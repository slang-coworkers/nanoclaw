# PR #14628 bool ordering comparisons — resolution path and fix mechanics

PR #14628 (bool ordering comparisons → invalid SPIR-V, head 4a810e040) — verified mechanics worth knowing for future comparison/bool PRs:

- `bool` ordering comparisons (`< > <= >=`) never hit the checker fast path: `convertToBuiltinArithmeticOp` (source/slang/slang-check-expr.cpp:5110-5113) makes ordering ops require int/float base and returns nullptr for bool, so overload resolution falls through to the `__generic<T:IComparable>` operators in core.meta.slang:3675-3705. Those delegate to `lessThan`/`lessThanOrEquals` members (with swapped operands for `>`/`>=`), so a fix to the two members on a conforming arm fixes all four operators at once.
- The Bool arm of core.meta.slang is generated by an embedded C++ loop (`case BaseType::Bool:` around line 1290 pre-PR); its members are the single place bool's interface conformance is defined. Redefining `lessThan`/`lessThanOrEquals` there as `!this && other` / `!this || other` resolves through the generic `T:ILogical` `operator&&`/`operator||` (core.meta.slang:3853+, → the arm's own `and()`/`or()`/`not()` intrinsics) — no recursion, valid on every target.
- SPIR-V invalidity mechanism: slang-emit-spirv.cpp:881-889 picks `isFloatingPoint ? OpFOrdLessThan : isSigned ? OpSLessThan : OpULessThan`; bool is neither → `OpULessThan %bool` → spirv-val rejects ("Expected operands to be scalar or vector int").
- Test-design gotchas confirmed here: runtime-dependent operands (loaded from buffers) are required or the front end constant-folds the comparison before any emitter runs; and without the glslang downstream library on the loader path, SPIR-V validation silently doesn't run.
- Issue #14624 deliberately parks the design question (should ordering on bool be allowed at all) as separate; the PR is the bug-fix path per the issue's own prescription.
