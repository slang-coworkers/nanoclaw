# slang-rhi cross-repo fix is a forced patch-handoff: bot has push:false + clone has no git identity

When a slang triage handoff's primary fix lands in **shader-slang/slang-rhi** (off-repo), the slang-fixer/triager container **cannot open the slang-rhi PR itself** — deliver a build-verified patch + draft PR body for the operator/maintainer to commit+push+open. Two independent hard blockers, both verified on slang#11519 (2026-06-09):

1. `gh api repos/shader-slang/slang-rhi --jq .permissions` → `{"admin":false,"maintain":false,"pull":false,"push":false,"triage":false}`. `nv-slang-bot[bot]` has **no push** on slang-rhi (the "origin push allowed" memory covers `shader-slang/slang` ONLY; slang-rhi is a different repo). Run this `gh api .../permissions` check to settle push-rights definitively — don't infer from `git push --dry-run` (false-positive for the GitHub App) or from the remote URL.
2. The slang-rhi clone has **no git user identity** (local + global empty), so you can't even create a commit there; safety rules forbid `git config` / `--author` / fabricated IDs. (The slang *core* clones DO carry the bot identity on-disk; slang-rhi does NOT.)

So a HOLD framed as "awaiting permission to do the unowned half" is wrong — the patch-handoff is *mechanically forced*, and the patch IS the deliverable (a real handoff, not a do-nothing hold). Build feasibility is fine: slang-rhi compiles headless via CMake FetchContent (Vulkan-Headers pinned v1.4.318 ≥ 1.3.280 → newer NV/EXT feature structs are defined; no GPU/Vulkan-SDK needed). Use `-DSLANG_RHI_ENABLE_CUDA=OFF -DSLANG_RHI_ENABLE_WGPU=OFF -DSLANG_RHI_BUILD_TESTS=OFF -DSLANG_RHI_BUILD_EXAMPLES=OFF`, target `slang-rhi`.

Also: slang-rhi's `rhi::Feature` enum (the `SLANG_RHI_FEATURES` X-macro in `include/slang-rhi.h`) is **public API** (`DeviceDesc::requiredFeatures`, `IDevice::getFeatures`/`hasFeature`, `getFeatureName`) — APPEND new entries at the END of the macro, never insert mid-list (mid-list renumbers every later enumerator = ABI break). The X-macro line is the single name table: one `x(EnumName, "kebab-name")` line generates both the enum entry AND the valid `-render-feature` string for slang-test.
