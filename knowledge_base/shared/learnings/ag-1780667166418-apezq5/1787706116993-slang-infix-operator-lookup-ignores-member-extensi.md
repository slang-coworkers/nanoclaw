# Slang infix operator lookup ignores member/extension-declared operators (only free functions resolve)

**Finding (verified at source master @ 8fe3df827 + empirically reproduced, issue #12761):** In Slang, an infix operator expression `a OP b` (`+ - * / == < ...`) resolves its candidate set via **pure lexical scope-chain lookup of the operator name** — the operand types play NO role in *finding* candidates (no member lookup on operands, no argument-dependent lookup). Path: `visitInvokeExpr` (`slang-check-expr.cpp:5123`) → `CheckTerm` → `visitVarExpr` (`:5324`) → `lookUp(..., expr->scope, ...)` (`:5334`) → `_lookUpInScopes` (`slang-lookup.cpp:786`) which walks `scope->parent` only.

**Consequence:** NO member-declared binary/unary operator is reachable via `a OP b` — this includes a plain `struct V { V operator+(V) }`, a non-generic `extension`, and both unconstrained and constrained generic extensions (`extension<T:IAdd> Box<T> { Box<T> operator+(Box<T>) }`). They compile at the declaration with NO diagnostic but can never be invoked. Only **free functions** `operator +<T:IAdd>(Box<T>,Box<T>)` resolve. Even if a member operator were found, the implicit `this` isn't counted as a call argument, so arity would reject it (`TryCheckOverloadCandidateArity`).

**The two exceptions that DO use member lookup:** `operator()` (`slang-check-expr.cpp:5138`) and `__subscript`/`operator[]` (`:3649`) call `lookUpMember` on the operand/callee type. So any declaration-site diagnostic for "member operator won't be found" MUST exclude these two (34 legitimate member definitions in-tree depend on them, incl. core-module `IFunc`/`IBwdCallable`/`_Texture`/`InputPatch`).

**This is currently documented + test-pinned as intentional** (both AUTO-GENERATED by claude-opus-5, not human spec): `docs/generated/design/name-resolution/overload-resolution.md:961-973` and `operator-member-declaration-not-in-scope-diagnostic.slang`. Convention corroborates: EVERY operator in `core.meta.slang` and EVERY user-operator test is a free function.

**Fix pattern (maintainer-preferred):** declaration-site diagnostic in `checkCallableDeclCommon` (`slang-check-decl.cpp:15582`), keyed off `getParentAggTypeDeclBase(decl) != nullptr && !isEffectivelyStatic(decl)` + operator-name. Prior art: sibling PR #11879 ("make the user's builtin operator win") was CLOSED UNMERGED — maintainer jkwak-work rejected the "make it work" alternative and fixed the sibling gap with a declaration-site diagnostic instead. Traps: `isPrefixOperatorName` matches only `-+~!` (too narrow); diagnostics live in `slang-diagnostics.lua` — there is NO `slang-diagnostic-defs.h`. Making member operators actually resolvable ("ADL for operators") is a language-DESIGN change (precedence/commutativity/ambiguity) above a fixer's authority.
