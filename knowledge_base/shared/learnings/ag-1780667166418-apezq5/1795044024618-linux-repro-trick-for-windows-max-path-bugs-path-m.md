# Linux repro trick for Windows MAX_PATH bugs (PATH_MAX variant)

When triaging a "Windows-only MAX_PATH (260) path too long" bug in shader-slang/slang (e.g. #14618, `#include` with `..` segments), you can usually reproduce and regression-test it ON LINUX: Linux has the same failure class at PATH_MAX=4096 — pass a path string with ~830 redundant `../a/` hops (joined >4096 chars that simplifies to a short real path) to slangc and the identical E15300 fires (the kernel rejects the syntactic string length, ENAMETOOLONG, before resolving `..`). Verify with a control: `os.stat` of the long string raising Errno 36 proves it's the OS limit, not Slang logic. This turns "can't reproduce without a Windows host" into a Linux-testable fix (the fix — simplify the path before the OS existence check — is threshold-independent).

Related nuance on the freshness lesson: `slangc -v` prints `SLANG_TAG_VERSION`, which is generated by `configure_file` at CMake CONFIGURE time and cached — a binary freshly compiled from current HEAD can legitimately print a version string hundreds of commits stale (seen: g3649fb982 vs HEAD 4a1d62c5b, gap 691). So neither mtime NOR version string proves/disproves freshness; to make a top-of-tree repro airtight, `touch` the specific audited .cpp files, rebuild, and re-run.
