# Slang AST ASTNodeType IDs are positional with NO serialization version gate (unlike IR modules)

**Context:** Triaging shader-slang/slang#12856 (refactor `bool isEqualityConstraint` → `EqualityConstraintDecl` subclass). The load-bearing risk for ANY refactor that adds/splits/reorders AST node classes.

**Fact (verified on master + fixer corroboration):**
- `ASTNodeType` enum members are **generated by `slang-fiddle`** (not hand-written): `tools/slang-fiddle/slang-fiddle-scrape.cpp` `getAllSubclasses` orders them as a **pre-order DFS of the class hierarchy in declaration order**. IDs are **purely positional, no explicit numbers**.
- Serialized AST tags each node by that `ASTNodeType` as a **raw uint** (`SLANG_DECLARE_FOSSILIZED_AS(ASTNodeType, FossilUInt)`; read path in `slang-serialize-ast.cpp:~990/1265/1413` indexes the SyntaxClass by the integer **directly**), with **NO stable-name remap**.
- **Contrast with IR:** IR ops DO have stable names (`slang-ir-insts-stable-names.lua`) + an IR module version gate (`IRModuleInfo::serializationVersion`, `k_min/k_maxSupportedModuleVersion` in `slang-ir.h`). **There is no analogous AST-format version gate.**

**Consequence / trap:** Inserting or reordering an AST node class mid-hierarchy shifts the positional IDs of every node type after it in the DFS → old `.slang-module` files deserialize to the WRONG AST class (silent corruption, not a clean rejection). Do NOT assume module-version gating will force a clean recompile of old modules the way it does for IR — that assumption is likely wrong for AST. Appending a new class at the very end of the DFS avoids shifting existing IDs; a mid-hierarchy insert does not.

**Also (FIDDLE non-regenerated sites):** adding a concrete Decl subclass auto-regenerates reflection/visitor/`as<>`/enum, but hand-written `switch(ASTNodeType)` statements are NOT touched — audit `slang-parser.cpp` (~5345/5417/5512), `slang-syntax.cpp` (~331), and `slang.natvis`. An explicit `case ASTNodeType::GenericTypeConstraintDecl` will NOT match a new subclass of it (though `as<Base>()` casts do catch subclasses).

**Takeaway for triage:** any "add/split an AST node class" refactor must resolve serialized-module compat with maintainers as a hard prerequisite, not a formality.
