## TL;DR

Operational gotchas from running the Slang coworker fleet: git/shallow-clone traps, software-Vulkan test gating, FileCheck authoring, CI rerun/flake mechanics, GitHub-app permission limits, multi-issue coordination, and source edits that silently break serialized-module compat.

- **Shallow clones lie about ancestry.** `git merge-base <branch> origin/master` returns empty when the common ancestor is below the `--depth` horizon; `git rebase origin/master` then replays from the *initial commit*. `git fetch --unshallow` first; use the GitHub compare API to characterize remote ancestry.
- **Software Vulkan:** gate GPU-semantics tests with `-render-feature hardware-device` (lavapipe reports software-device → the test is *Ignored*, not Failed). But the *fleet's* lavapipe is Mesa 22.3.6 — too old for slang-rhi to even create a device; always `slang-rhi-tests -check-devices` first.
- **FileCheck `-NOT` must match a syntax token** (`switch(`), never a bare keyword — the emitted CUDA/HLSL carries `#line "…file.slang"` that collides; prove non-vacuity with a positive control.
- **Reruns:** `gh run rerun --failed` on a run >~20h old is doomed by artifact expiry (~24h TTL) — only a full rerun rebuilds. SIGILL(4) vs SIGABRT(6) discriminates the AVX-512-JIT mechanism from a var-masked different bug.
- **The coworker GitHub App lacks the `workflows` scope** — origin push of `.github/workflows/**` is rejected; push to the `slang-coworkers` fork and open a cross-fork draft PR (with `maintainer_can_modify=false`), which does NOT auto-run CI. This *corrects* an earlier "patch-only" note.
- **Multi-issue single-PR "un-authored" bot commits are coworker collisions** under one shared identity, not intruders; **track a fix by the ISSUE**, not by a PR number that can go stale.
- **`capdef` append-only means after the LAST Normal `def` in the whole file**, and a hand-picked diagnostic error code can collide with an upstream one after a stale-branch rebase — re-check before trusting.

## Git and shallow-clone mechanics

The `/workspace/agent/slang` base clone is shallow (`--depth N`), and a `git worktree` inherits that shallowness. Two traps follow. `git rebase origin/master` when master is more than N commits ahead can't find the true merge-base and **replays your branch from the repository's initial commit** — the tell is a rebase mentioning "Initial commit" or conflicts in files you never touched (README/LICENSE); abort, `git fetch --unshallow`, retry [git rebase in a --depth shallow clone replays from the initial commit — unshallow first](../learnings/1787842174421-git-rebase-in-a-depth-shallow-clone-replays-from-t.md). Separately, `git merge-base <branch> origin/master` returns empty/rc=1 when the common ancestor is below the shallow horizon — this is NOT evidence of a non-linear/ephemeral base; use `gh api repos/O/R/compare/BASE...HEAD --jq '{status,ahead_by,behind_by}'` (`behind_by:0, status:ahead` ⇒ clean linear ancestor), and `git rebase --onto origin/master <old-base> <branch>` still works locally; verify a rebase changed only the base with `git patch-id --stable` / `git range-diff` [on a shallow clone, git merge-base lies about remote ancestry — use the GitHub compare API](../learnings/1787862114697-on-a-shallow-clone-git-merge-base-lies-about-remot.md).

## Software-Vulkan test gating and FileCheck authoring

To gate a test that needs real GPU semantics on a software-Vulkan host, append `-render-feature hardware-device` to the failing `-vk` line: lavapipe (`VK_PHYSICAL_DEVICE_TYPE_CPU`) reports software-device, so the requirement yields `Ignored` (skipped), not Fail. There are three distinct skip mechanisms — `-render-feature` (runtime skip on missing capability), `-expected-failure-list` (reclassifies a clean Fail→ExpectedFail, can't suppress a SIGSEGV), `-skip-list` (excludes before dispatch, the only thing that contains a crasher) — and a *present* feature doesn't mean safe (lavapipe reports Bindless supported yet faults on a never-bound descriptor = UB) [gating slang-test on a software rasterizer (lavapipe): -render-feature hardware-device](../learnings/1787840918556-gating-slang-test-on-a-software-rasterizer-lavapip.md). But do NOT assume "container has lavapipe ⇒ can reproduce software-Vulkan failures": the fleet's lavapipe is Mesa 22.3.6 / LLVM 15, too old for slang-rhi to create a Vulkan device (`-check-devices` → "not supported"), so `slang-test` Ignores every `-vk` subtest and you reproduce nothing — those reports were measured on Mesa ≳25; always verify device availability with `slang-rhi-tests -check-devices` first [slang fleet lavapipe is too old (Mesa 22.3.6) for slang-rhi Vulkan device creation](../learnings/1787843098338-slang-fleet-lavapipe-is-too-old-mesa-22-3-6-for-sl.md).

For an emit `-NOT` FileCheck, match a *syntax token* that only appears in a real statement (`switch(` with the paren), never a bare keyword — the emitted CUDA/HLSL carries `#line N "tests/.../thread-switch-....slang"` directives that FileCheck matches anywhere, so `-NOT: switch` false-matches the filename; always prove non-vacuity with a positive control that keeps the construct [CUDA/HLSL emit FileCheck -NOT must match a syntax token, not a bare keyword](../learnings/1787846790793-cuda-hlsl-emit-filecheck-not-must-match-a-syntax-t.md).

## CI reruns, flake mechanics, and crash-signal triage

`slang-tests-*` build artifacts expire ~24h after `created_at`; a `gh run rerun <id> --failed` fired >~20h after the original re-requests the now-expired artifact (which `--failed` never rebuilds) and is guaranteed to fail with "Artifact not found" — check `run_started_at` age first; only a full workflow rerun or a fresh push produces a new result. This also makes a stale "DepfileOutput.internal-flake"-looking classification unsafe without checking log freshness [artifact-expiry-before-rerun: a --failed rerun of an old test can hit a different, unfixable failure](../learnings/1787985585815-artifact-expiry-before-rerun-a-failed-rerun-of-an-.md). When a `-cpu`/LLVM-JIT crash is blamed on the AVX-512 mis-report class, check the signal number: **signal 4 = SIGILL** is the AVX-512 signature (illegal instruction the host can't decode); **signal 6 = SIGABRT** is an assert/abort where `SLANG_DISABLE_AVX512` may only *incidentally* mask a different bug — keep the mechanism labeled unproven and audit only workflows that run `-cpu`/JIT tests on x86 without the var [SIGILL (signal 4) vs SIGABRT (signal 6) discriminates the AVX-512-JIT mechanism](../learnings/1787912607368-sigill-signal-4-vs-sigabrt-signal-6-discriminates-.md). A local review-runner `INTEGRITY-FAIL` can be a false positive from a shared-`tmp/` race: two concurrent review runs against `/workspace/agent/slang` overwrite `tmp/pr-files.txt` between clear and guard-sample — adjudicate by comparing the run's own immutable `pr-diff.reference` (sha256) against `gh pr diff`, not the contaminated shared tmp [INTEGRITY-FAIL can be a false positive from the shared slang/tmp race](../learnings/1787845328421-integrity-fail-can-be-a-false-positive-from-the-sh.md).

## GitHub-app limits and coworker coordination

The slang coworker GitHub App credential does **not** hold the `workflows` scope, so any origin push of `.github/workflows/**` is rejected — the workaround is to push to the `slang-coworkers` fork and open a cross-fork draft PR, which then has a hidden human-in-the-loop step before CI runs and won't match `fix/issue-<n>` webhook routing [slang coworker GitHub App lacks workflows scope](../learnings/1787914861084-slang-coworker-github-app-lacks-workflows-scope.md). A **correction** refines the delivery mechanics: the fork *accepts* the workflow push (patch-only fallback is NOT required), and opening the cross-fork PR needs `-F maintainer_can_modify=false` on the `gh api POST .../pulls` call to avoid HTTP 422 `fork_collab`; amend with `git push --force-with-lease coworkers <branch>` [CORRECTION: bot CAN ship .github/workflows PRs via the coworkers fork](../learnings/1787748419987-correction-bot-can-ship-github-workflows-prs-via-t.md).

When one draft PR closes several issues, multiple fixer sessions commit to the single branch under the shared `nv-slang-bot[bot]` identity — so a chain will observe commits it "did not author," which reads like a fleet-safety incident but is a benign collision; diagnose via `gh api commits/<sha>` matching author+message+files against the *sibling* issue chains before escalating [multi-issue single-PR "un-authored" bot commits are coworker collisions, not intruders](../learnings/1787780061590-multi-issue-single-pr-un-authored-bot-commits-are-.md). And track a fix by the **issue**, not a PR number: an issue can be closed by an entirely different PR than the one you're polling, silently making "watch PR #N" a true-rule-welded-to-false-instance [tracking a fix by PR number goes stale if a different PR closes the issue first](../learnings/1787851633628-tracking-a-fix-by-pr-number-goes-stale-if-a-differ.md). A related recovery skill: a prototype pulled out of a focused PR during review is still recoverable from the squash-merged PR's pre-squash commit history (`gh api .../pulls/<N>/commits`), though you should re-classify against current HEAD since the source enum may have grown [recovering a deferred reference-impl from a squash-merged PR's history](../learnings/1787777686026-recovering-a-deferred-reference-impl-from-a-squash.md).

## Source edits that silently break serialized-module compat

Two Slang source files carry enum-ordering compat hazards. `capdef` "append-only" means append after the **last Normal `def` in the entire file**, not after the topical block — enum values are assigned in pure declaration order and `.slang-module` files serialize capability sets as bit positions indexed by that value, so inserting a `def` mid-file renumbers every later def and invalidates compiled modules; aliases are exempt (separate later pass). This is a `.slang-module` format-compat concern, so `pr: non-breaking` [capdef append-only means append after the last Normal def in the whole file](../learnings/1788071111340-capdef-append-only-means-append-after-the-last-nor.md). Similarly, a hand-picked diagnostic error code in `slang-diagnostics.lua` is only free as of the moment you picked it — a stale branch can collide with an upstream code taken meanwhile; re-check with `git grep <code> origin/master` on rebase, and the renumber surface is wider than the `.cpp` (the lua def+comment, every `//CHECK: E<code>`, the commit message, AND the PR body) [rebasing a stale branch can collide a hand-picked diagnostic code with an upstream one](../learnings/1787950830117-rebasing-a-stale-branch-can-collide-a-hand-picked-.md).
