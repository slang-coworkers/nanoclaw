# Slang Compiler: C/COM API Ownership & Front-End Guard/Cast Bugs

This page covers the C/COM API's ownership conventions and threading contract, an aarch64-only host-VM `PathInfo::type` bug, front-end guard-and-cast bugs ("the check is one layer off / too narrow"), canonical immutable-location/opaque-type predicates, an IR positional-accessor trap, and a `defer` scope leak.

## TL;DR
- When a crash disagrees with a stated ownership model or a guard premise, read the call-site source, not DeepWiki or a generic rule. Fix the producer of a bad shape, not the consumer.
- The COM-lite API has two conventions. `ISession::loadModule`/`loadModuleFromSource`/`loadModuleFromBlob`/`getLoadedModule` return a BORROWED `IModule*` (releasing it → double-free at teardown); `T**` out-params (`link`, `getTargetCode`, entry-point/composite creation) are OWNED, release once. Teardown ends in `slang_shutdown()`.
- The session caches a module whose IR lowering (not semantic checking) failed; a second `loadModule` returns it silently and codegen asserts in `slang-ir-link.cpp`. slangc never loads twice, so test session-cache claims through the C++ API.
- Threading: specialization and `link()` need external sync; only codegen methods are concurrent, and even they write unlocked state (DXC/FXC includes → `SourceManager`; LLVM `getPointerSize` → `InitializeAll*`, needs a leaf lock). The op mutex can't be split front/back (shared ASTBuilder hash-cons cache). Measure races standalone, not in slang-test (it preloads slang-llvm).
- `getCurrentASTBuilder()` is thread_local; new front-end code reached from `ComponentType::specialize` needs its own `SLANG_AST_BUILDER_RAII`. Probe with a GENERIC instantiation (`S<float4>`) on a `std::thread`; a non-generic struct is a false negative.
- Moving per-object state to `thread_local`: key it per object (not one scratch per thread), give exit-time-destructor paths a trivially-destructible late path, RSS-measure retention vs master, and check identity (pointer+size), not just the key.
- An aarch64-only wrong result in a `//TEST:INTERPRET` autodiff test is uninitialized `PathInfo::type` in host-VM serialization, not the op in the CHECK; determinism across aarch64 jobs is expected (cold zero-pages).
- `DeclRef::as<U>()` does NOT validate (returns non-null); use `as<U>(rawDecl)` or `declRef.is<U>()`. For "X isn't diagnosed," check whether the low-level utility already rejects X and the gap is a guard one layer up.
- Reuse `isPointerToImmutableLocation` / `isOpaqueType` rather than hand-rolling a narrow switch.
- A struct copy left after `transformParamsToConstRef` is the `updateCallSites` temp; it is required when the source is also written through `inout`.
- Adding/splitting a `ParamPassingMode`: grep every raw `hasModifier<Out|InOut|Ref|Const>` read and route it through `getParamPassingMode` (mesh outputs excepted).
- Verify how the builder emits an IR op before trusting a FIDDLE positional accessor (`MakeVectorFromScalar`: the scalar is `getOperand(0)`).
- `defer <bare-decl>;` leaks scope because the parser opens none; fix it in the parser.

## Slang C/COM API Has TWO Ownership Conventions — `loadModule` Returns a BORROWED Pointer

Which `SLANG_NO_THROW` methods leak exceptions across the boundary, and the `link()`-style guard, are on [slang-compiler-api-exception-boundary-guards](slang-compiler-api-exception-boundary-guards.md).

**(a) BORROWED — do NOT release:** `ISession::loadModule`/`loadModuleFromSource`/`loadModuleFromBlob`/`getLoadedModule` return a `slang::IModule*` with refcount unchanged; the session/`Linkage` holds the only strong refs (`asExternal(Module*)` is a plain `static_cast`, no `addRef`, despite DeepWiki). An FFI caller that releases it causes double-free/heap corruption at teardown. **(b) OWNED `T**` out-params — release once:** `link()`, `getTargetCode()`, `getEntryPointCode()`, `createCompositeComponentType()`, `findEntryPointByName()`, `getDefinedEntryPoint()` transfer via `.detach()`; blobs are per-call. Teardown: leave `loadModule` handles → release blobs/entry-points/composites → session → global session → `slang_shutdown()` (frees process-global SPIR-V grammar/RTTI/capability tables) [loadModule returns a BORROWED IModule*](../learnings/1785172765216-slang-c-com-api-loadmodule-returns-a-borrowed-imod.md).

`Linkage::loadParsedModule` (`slang-session.cpp:1173-1188`) evicts from `mapPathToLoadedModule`/`mapNameToLoadedModules` only when *semantic checking* added errors. A `generateIRForTranslationUnit` diagnostic (E40008 `invalid-l-value-for-ref-parameter`, e.g. `float g(__ref float2 x)` called as `g(v.zx)`) leaves the module cached: the first `loadModule("m")` returns null with the error, the second returns it silently, `link()` succeeds, and `getEntryPointCode` fails E99997 `slang-ir-link.cpp(399): c->value.ptrVal == nullptr`. Pre-existing on master (predates #13809). Test session-cache claims with a ~40-line C++ probe that loads twice (it also refuted a reviewer's "silent OpUndef" prediction). For note→error escalation PRs, a message-only `//CHECK: ^^^ <message>` matches any severity — pin with `error E<code>` [loadModule caches modules whose IR lowering failed](../learnings/1792579806821-session-loadmodule-caches-modules-whose-ir-lowerin.md).

## The API's Threading Contract: Linkage Op-Mutex Sites and the Front/Back Split (#13455)

docs/user-guide/08-compiling.md:1035-1046: specialization and `link()` require external synchronization; only the five codegen methods are concurrent. At master 5cb03fa5f, `Linkage::m_componentTypeOperationMutex` (slang-session.h:246) is taken at six sites (getSemanticsForReflection, createCompositeComponentType, COM specialize, link, getTargetProgram, getOrCreateLayout); `Linkage::specializeType` takes none, and getSemanticsForReflection locks only the swap of its cached context, then runs SemanticsVisitor unlocked. A front/back split races (not deadlocks): the linkage ASTBuilder's hash-cons `m_cachedNodes` is a plain Dictionary (ast-builder.h:238) that both specialize and layout (getType/substitute, getTupleType, mangling, createIRModuleForLayout) insert into. The real contention: getOrCreateLayout locks even when cached, so every getEntryPointCode/getTargetCode result-cache miss serializes via getOrCreateIRModuleForLayout (lower-to-ir.cpp:16584); an unlocked fast path is wrong because `m_layout` is published before `m_irModuleForLayout` ([op-mutex front/back split races on ASTBuilder](../learnings/1791314287042-slang-linkage-op-mutex-front-back-split-races-on-a.md)).

**The "concurrent" codegen methods still write shared, unlocked state.** DXIL: `CodeGenContext` passes `linkage->getSourceManager()` and the file system to the downstream compiler (slang-code-gen.cpp:628-629); on an include miss DXC/FXC's `IncludeSystem::loadFile` calls `createSourceFileWithBlob` + `addSourceFile` (slang-include-system.cpp:162-163) on the lock-free `SourceManager`, and generated HLSL can `#include "dx/linalg.h"` (slang-emit-hlsl.cpp:728). The #14441 triage (master 4f66408b) left it unreproduced, with `Session::getOrLoadSlangLLVM` (slang-global-session.cpp:1290) as the same unlocked check-then-load ([codegen writes the shared SourceManager](../learnings/1794327612666-slang-backend-codegen-writes-the-shared-sourcemana.md)); a later TSan run filed a DXIL-include race as #14444 ([[wiki/concepts/ci-b-build-tooling-local-testing.md]]). LLVM targets (#14443, draft PR #14446): every `getPointerSize` → `getLLVMBuiltinTypeLayoutInfo` (slang-type-layout.cpp ~3400) calls the uncached slang-llvm export `getLLVMTargetBuiltinTypeLayoutInfo_V2`, which runs `llvm::InitializeAll{TargetInfos,Targets,TargetMCs}` (slang-llvm.cpp:1100), so IR-pass workers race LLVM's global init, besides `createLLVMBuilder_V3`'s `cl::ParseCommandLineOptions`. Revert drill (8 threads): builder lock only → hangs/SEGVs 5/60; layout lock only → `Option 'h' registered more than once` 1-5/60; both → 0/260. The lock must be a leaf: `TargetProgram::getOrCreateLayout` (slang-parameter-binding.cpp:4846) holds the op mutex when it reaches the query. TSan misses the layout race because prebuilt slang-llvm is uninstrumented ([getPointerSize re-runs InitializeAll*](../learnings/1794336213875-slang-llvm-targets-getpointersize-calls-a-slang-ll.md)).

**Measure these races with a standalone repro run 60+ times under `timeout`, not a slang-test unit test.** slang-test's startup `checkPassThroughSupport` (slang-test-main.cpp ~7526) dlopens slang-llvm first, pre-empting first-use races: #14446's `parallelFirstLLVMCodegen` caught master 0-1/60 in slang-test (abort only) vs 9/60 hangs/segfaults standalone; preloading slang-llvm standalone dropped master to 2/120; two fresh global sessions per iteration raised it to 27/180 (head 0/240), cause unknown. No-rebuild A/B: put each variant's `libslang*.so*` (or master's `libslang-compiler.so.0.<ver>`) in its own dir and run with `LD_LIBRARY_PATH=<dir>[:<head lib>]` (overrides RUNPATH); for `slangc`/`slang-test` copy `bin/` beside a `lib/` (RUNPATH is `$ORIGIN/../lib`). CI's `sanitizer-linux-clang-x86_64` leg is ASan/UBSan; TSan is #13120 ([slang-test preloads slang-llvm](../learnings/1794339896347-slang-test-preloads-slang-llvm-at-startup-which-ma.md), [the A/B trick](../learnings/1794336213875-slang-llvm-targets-getpointersize-calls-a-slang-ll.md)).

## Worker-Thread AST Builder: `SLANG_AST_BUILDER_RAII` in Code Reached from `specialize` (#13538)

`getCurrentASTBuilder()` is thread_local; only the thread that created the global session has a default (slang-global-session.cpp:70). Front-end entry points scope it with `SLANG_AST_BUILDER_RAII`, but `EndToEndCompileRequest::executeActionsInner` → `createSpecializedGlobalAndEntryPointsComponentType` → internal `ComponentType::specialize(args, count, sink)` runs outside that scope. A new check there reaching `getCurrentASTBuilder()` (#13538: `getTrailingUnsizedArrayElement` → `_getMemberDeclRef`) gets null on a worker thread and segfaults in `ASTBuilder::_getOrCreateImpl(this=0x0)`. Fix: `SLANG_AST_BUILDER_RAII(linkage->getASTBuilder())` at the top of the new function (as in `EntryPoint::_validateSpecializationArgsImpl`); the regression is a unit test compiling on a `std::thread` (deprecated calls in `SLANG_ALLOW_DEPRECATED_BEGIN/END`) [code reached from ComponentType::specialize needs its own SLANG_AST_BUILDER_RAII](../learnings/1792060186315-slang-new-front-end-code-reached-from-componenttyp.md).

The repro shape decides whether it crashes: `getMemberDeclRef` short-circuits on a `DirectDeclRef` parent, so non-generic `struct S { float4 a; float4 x[]; }` passes; only a generic instantiation builds a `MemberDeclRef` needing the builder — `struct S<T> { float4 a; T x[]; }` with `-specialize S<float4>` gave rc 139 at 1ce058b, rc 0 on master. Same-thread runs and slangc never show it; drive `ICompileRequest::compile` on a `std::thread` with `addEntryPointEx(..., {"S<float4>"})` or `setGlobalGenericArgs`. A #13538 r4 reviewer dismissed the Security finding from one non-generic probe; when a claim names a code path, check which `DeclRef` subclass the probe takes before refuting [null-AST-builder repros need a GENERIC struct](../learnings/1792061760327-null-ast-builder-repros-need-a-generic-struct-non-.md).

## Moving Per-Object State to `thread_local`: Keying, Exit-Time Teardown, and Retention (#13786 / PR #13818)

`AppendBufferWriter` (`source/core/slang-writer.cpp`) had a per-writer mutex and append buffer; slang#13786 reported the mutex as misused, and PR #13818 replaced both with thread-local scratch. Every reviewer pass (A, Devin, clarity, codex) missed at least one of three lifetime regressions; peer review and measurement found them.

**Key the thread-local state by object.** "One active append buffer" is per writer, so `begin(A); begin(B); end(B); end(A)` on one thread is legal; with one per-thread scratch, B's `setCount` reallocates A's live buffer. Fix: a `thread_local` list of `{writer, buffer}` entries, each its own allocation, detached before `write()` so a re-entrant append gets a fresh buffer (revert drill confirmed the test). `find(this)` is not proof of ownership: it matched the calling thread's own abandoned entry, so a wrong-thread `end` wrote another thread's buffer — a "wrong thread → error" contract needs a pointer+size identity check. In Release `SLANG_ASSERT` is `SLANG_ASSUME`/`[[assume]]`, so `SLANG_ASSERT(!"msg"); return err;` is UB for reachable misuse; return a plain error ([keyed by writer](../learnings/1792583953497-thread-local-append-buffer-must-be-keyed-by-writer.md), [thread_local changes memory lifetime](../learnings/1792600018777-moving-per-object-storage-to-thread-local-changes-.md), [object→thread ownership changes lifetime](../learnings/1792602883492-moving-buffer-ownership-from-object-to-thread-chan.md)).

**A `thread_local` with a destructor is unsafe for code reachable from exit-time destructors.** Destructors still run after a thread's function-local `thread_local`s die (static objects at process exit, earlier-constructed `thread_local`s at thread exit). If a function-static writer like `_getDefaultWriter` prints from its destructor, `beginAppendBuffer` runs `List::add` on destroyed storage (PR head segfaulted, master OK). A writer destructor can't simply clean up its entry either, since that may create thread-local state during teardown. The ASan/LSan-clean shape: a holder destructor sets a trivially-destructible `thread_local bool destroyed`; later calls use a heap instance via a trivially-destructible `thread_local T*`, freed when idle; re-look-up the table after any callback (`write()`), since a re-entrant late call can free the late instance (an ASan UAF). A never-freed per-thread allocation trips CI LSan (`ci-slang-sanitizer.yml`, `detect_leaks=1`). A 20-line probe against `build/Release/lib/libcore.a` (`-isystem external/unordered_dense/include`) checks both: a static whose destructor prints through a static `NullWriter`, plus one print in `main`; and a `thread_local` whose destructor prints, constructed before the thread's first print ([unsafe from exit-time destructors](../learnings/1792591120086-a-thread-local-with-a-destructor-is-unsafe-for-cod.md), [object→thread ownership changes lifetime](../learnings/1792602883492-moving-buffer-ownership-from-object-to-thread-chan.md)).

**Retention moves from the object's lifetime to the thread's.** R2 kept a `thread_local` table keyed by writer address plus a reused `spare`; Reviewers A and C passed it, Devin flagged retention, a VmRSS probe confirmed: 200 writers each abandoning 1 MiB then destroyed cost +205 MB (master +20 KB), and one 64 MiB append left the spare holding 64 MB for the thread's life (master 0). When storage moves to `thread_local`/static scope, RSS-probe the object-destroyed and large-one-off cases against master, clean up from the destructor only via a find-without-create accessor, and cap any spare (4 KiB). Build the master baseline with master's header (mixing gives a bogus stack-buffer-overflow). ~10% of ASan `std::thread` probe runs hang at exit on master too (exit 124); judge hangs from non-ASan runs. The libcore.a probe technique is also on [Build tooling: testing a PR's effect locally](ci-b-build-tooling-local-testing.md) ([measure RSS vs master](../learnings/1792600018777-moving-per-object-storage-to-thread-local-changes-.md), [measure retention and teardown](../learnings/1792602883492-moving-buffer-ownership-from-object-to-thread-chan.md)).

## Host-VM PathInfo::type Is Uninitialized — an aarch64-only `0 0` in an INTERPRET Autodiff Test (#12871)

For an aarch64-only wrong result in a `//TEST:INTERPRET` autodiff test (`9 6 0 0 9 6` vs x86_64 `9 6 -9 -6 9 6` in `tests/autodiff/unary-plus-diff.slang`), don't anchor on the op in the CHECK. The cause is uninitialized `PathInfo::type` (`enum class Type : uint8_t`, no default, `slang-source-loc.h:125`, read by `hasFoundPath()` ~l.77) during host-VM module serialization: `emitHostVMCode` does `new Module(linkage)` (`slang-emit.cpp:3728`) and never sets a PathInfo before `serialize()`. The read happens once per slangi invocation whatever op the shader uses, so #12871's builtin-scalar mirror does not sidestep it; any complex enough INTERPRET autodiff program can trip it on aarch64, and #12879 (`Type type = Type::Unknown;`) greens them all. Which value is zeroed is a downstream artifact [#12871 PathInfo::type UB is not neg()-specific](../learnings/1788537147888-12871-host-vm-pathinfo-type-ub-is-not-neg-specific.md).

## Front-End Guard/Cast Bugs: Property Accessors, #language, and the Lexer Continuation Byte

Three bugs share the "check is one layer off / too narrow" shape. **(1)** `[Differentiable]`/`[TreatAsDifferentiable]` on a struct **property** accessor segfaults slangc with no diagnostic (#12210), while a subscript accessor is fine — front-end header checking, not autodiff. `getFuncType` (`slang-syntax.cpp:1122`) branches `if (as<SubscriptDecl>(parent) || as<PropertyDecl>(parent))` then casts `parent.as<CallableDecl>()`, but `SubscriptDecl : CallableDecl` while `PropertyDecl : ContainerDecl` is not. **`DeclRef::as<U>()` does NOT validate the target type** — it rewraps the same `declRefBase` and returns non-null, so `if (declRef.as<CallableDecl>())` is a no-op guard; use `as<U>(rawDecl)` or `declRef.is<U>()`. PR #5922's `|| as<PropertyDecl>` arm regressed it; the fix restricts the prepend to `SubscriptDecl` ([PropertyDecl is not a CallableDecl](../learnings/1784883686572-differentiable-property-accessor-segfaults-getfunc.md)). **(2)** `#language glsl <n>` (`HandleLanguageDirective`, `slang-preprocessor.cpp`) validates the version only via `isValidSlangLanguageVersion`, never `isValidGLSLVersion`, so `#language glsl 460` errors E15207 while `#language glsl 2025` passes and silently re-overrides the language to Slang; the GLSL selector is `#version <n>`. The issue's "PR #X will take care of this" was a dedup gate (the PR's diff satisfied it; no dispatch) ([#language glsl mis-validates against Slang versions](../learnings/1784916319659-language-glsl-version-mis-validates-against-slang-.md)). **(3)** The lexer accepts a lone UTF-8 continuation byte (0x80–0xBF, #12222), but `getUnicodePointFromUTF8` already rejects it; the branch guard `isUtf8LeadingByte` (`0xC0–0xFF` only, `slang-lexer.cpp:267/:350`) is too narrow, so the byte falls through to identifier lexing. Broadening to `isUtf8LeadingByte(c) || isUtf8ContinuationByte(c)` lets existing E10006 fire ([lone-continuation-byte gap is a guard-narrowness bug](../learnings/1784917194691-slang-lexer-lone-continuation-byte-gap-is-a-guard-.md)).

## Reuse Canonical Immutable-Location / Opaque-Type Predicates, Don't Hand-Roll

For the whole address-only / immutable-location class (ParameterBlock, ConstantBuffer, read-only StructuredBuffer/ByteAddressBuffer/textures, samplers, structs transitively containing them), reuse `isPointerToImmutableLocation(IRInst*)` (`slang-ir-util.cpp:3105`; walks element-access chains, excludes RW-alias and the OptiX-SBT case #10188) and `isOpaqueType(IRType*, IRType**)` (`slang-legalize-types.cpp:257`; recursive, cycle-safe). On slang#8002, `isLoadFromImmutableAddress` (`slang-ir-transform-params-to-constref.cpp:186`) hand-rolls a narrow switch duplicating `isPointerToImmutableLocation`; swapping it in gives full coverage. Related: `lowerGlobalShaderParam` wraps a global param as `LoweredValInfo::simple(irParam)` though the SSA value is a pointer, and `tryGetAddress` has no `Flavor::Simple` case, so a global resource/PB param forces the by-ref temp path, emitting a bare `store(v, %g)` that `undoParameterCopy` (matching `store(v, load(orig))`) misses [reuse isPointerToImmutableLocation / isOpaqueType](../learnings/1785194352818-slang-reuse-ispointertoimmutablelocation-isopaquet.md).

A whole-struct copy surviving `transformParamsToConstRef` is usually not a missed elision: the callee already takes `T*`, and the copy is the call-site temp `updateCallSites` (`:243-246`) makes for any argument that isn't a load from a ConstantBuffer/ParameterBlock/BorrowIn root. SSA often folds `T copy = orig;` into `load(%orig)`, so if `orig` is also passed `inout` and written by the callee, the temp is a required snapshot; it is merely conservative for a distinct, unmodified, non-escaping local (dropping it there removed 3 KB of spills on #13108). Inspect with `-dump-ir-before transformParamsToConstRef` [the leftover copy is its own call-site temp](../learnings/1791924437877-transformparamstoconstref-leftover-copy-is-its-own.md).

## Changing a ParamPassingMode: Route Every Direction Decision Through `getParamPassingMode`

When a `ParamPassingMode` is added or split (e.g. `RefWriteOnly` for `__ref_writeonly`), overload resolution, coercion and lowering are not the only consumers: `validateEntryPoint` (`slang-check-shader.cpp`) picked semantic direction from `hasModifier<InOutModifier|OutModifier|RefModifier>()` at four sites (SV semantic validation, depth-output collection, varying-type direction labels, SV_Position output scan). So `__ref_writeonly uint : SV_GroupIndex` was accepted and `SV_StencilRef` rejected (the reverse of `out`), suite green; only codex CODE_REVIEW caught it. The fix (#13406) queries `getParamPassingMode(param)`, with one exception: the effective mode maps `MeshOutputType` (`out vertices V v[3]`, `OutputVertices<V,3>`) to `In`, so a direction helper must treat mesh outputs as outputs. A `__ref` entry-point parameter to SPIR-V/GLSL hits a pre-existing `slang-ir-glsl-legalize.cpp` assert, so such tests need `-no-codegen`. Before declaring done, run `rg 'hasModifier<(Out|InOut|Ref|Const)Modifier>|findModifier<(Out|InOut|Ref|Const)Modifier>' source/slang` and route each decision through `getParamPassingMode` ([grep every direct Out/InOut/Ref modifier read](../learnings/1791611645970-changing-a-parampassingmode-grep-every-direct-out-.md)). The witness-synthesis clone loop and `ParameterDirectionInfo` are the other re-derivation sites; see [[wiki/concepts/slang-language-core-requirement-witness-synthesis.md]].

## IR Trap: Trust the Builder's Operand Count, Not a Generated Positional Accessor

`IRMakeVectorFromScalar`'s Lua schema (`slang-ir-insts.lua:1373`) declares three operands `{elementType, elementCount, scalarValue}`, so FIDDLE emits `getScalarValue() → getOperand(2)`; but every builder emits one operand (`emitMakeVectorFromScalar` → `emitIntrinsicInst(..., 1, &scalarValue)`, `slang-ir.cpp:4758`, also `slang-ir-spirv-legalize.cpp:1771`), and every consumer reads `getOperand(0)` (`slang-emit-spirv.cpp`, `slang-ir-peephole.cpp:946`). `getScalarValue()` reads two `IRUse` slots past the array (Debug assert `slang-ir.h:711`, Release wild pointer), reachable from a module-scope splat `static const uint3 g = (uint3)float3(3.0);`. PR #12263 (slang#12219) hit it in a new SCCP helper; the two-arg `makeVector` test missed the splat path. Reviewer A called it a bug because its checkout had `build/source/slang/fiddle/`; Reviewer C, lacking generated headers, said "please confirm" — for a "cannot confirm from source" finding, check whether fiddle headers exist and resolve it yourself ([getScalarValue reads getOperand(2), builder emits 1](../learnings/1785334765218-makevectorfromscalar-getscalarvalue-reads-getopera.md), [scalar is getOperand(0)](../learnings/1785335653192-makevectorfromscalar-scalar-is-getoperand-0-not-ge.md)).

## defer Bare Non-Block Decl Leaks Scope → IR-Lowering Segfault (#12266)

`Parser::ParseDeferStatement()` calls `ParseStatement()` without `pushScopeAndSetParent()`, so `defer uint i = 1;` leaks `i` into the enclosing scope (lookup resolves it, suppressing E30015); IR lowering puts the `IRVar` in the defer block, which `lowerDefer` relocates to scope-exit, so an earlier reference derefs a stale value → segfault. `if(c) uint i=1;`/`while` bodies leak identically but only `defer` crashes (the relocation). Fix: open a nested scope in the parser (mirror `parseBlockStatement`); the working block form `defer { uint i=1; }` is the proof ([defer bare decl leaks scope](../learnings/1785345383314-slang-defer-bare-non-block-decl-leaks-scope-ir-low.md)).
