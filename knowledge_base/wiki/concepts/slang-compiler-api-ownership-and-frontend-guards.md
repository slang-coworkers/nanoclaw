# Slang Compiler: C/COM API Ownership & Front-End Guard/Cast Bugs

This page covers the Slang C/COM API's two ownership conventions (why `loadModule` returns a BORROWED pointer), an uninitialized host-VM `PathInfo::type` that surfaces as an aarch64-only interpreter result, a family of front-end declaration/lexing guard-and-cast bugs whose common shape is "the check is one layer off / too narrow," reuse of canonical immutable-location/opaque-type predicates, an IR positional-accessor trap, and a `defer` parser scope leak.

## TL;DR
- Discipline unchanged: when a crash disagrees with a stated ownership model or a decoder/guard premise, read the source at the call site — don't trust DeepWiki or a generic rule. Fix the producer of a bad shape, not the consumer.
- Slang's COM-lite API is NOT uniformly "returned interface is caller-owned." `ISession::loadModule`/`loadModuleFromSource`/`loadModuleFromBlob`/`getLoadedModule` return a BORROWED `IModule*` (session-owned, refcount unchanged) — releasing it drops the session's own ref → double-free at teardown. `T**` out-params (`link`, `getTargetCode`, entry-point/composite creation) are OWNED — release once. Teardown order matters, ending in `slang_shutdown()`.
- An aarch64-only wrong result in a `//TEST:INTERPRET` (slangi) autodiff test is host-VM serialization UB from an uninitialized `PathInfo::type`, NOT specific to the differentiated op shown in the CHECK. Deterministic-across-all-aarch64 is expected (cold zero-pages), not evidence against UB.
- Front-end guard/cast family, common shape "the check is one layer off / too narrow": `DeclRef::as<U>()` does NOT validate the target type (it rewraps and returns non-null) — use `as<U>(rawDecl)` or `declRef.is<U>()`. When triaging "X isn't diagnosed," check whether the low-level utility already rejects X and it's a routing/guard gap one layer up (lexer continuation byte, `#language glsl` version).
- Reuse canonical predicates rather than hand-rolling a narrow switch: `isPointerToImmutableLocation(IRInst*)` and `isOpaqueType(IRType*, IRType**)` already cover the whole address-only/opaque-type class (RW-alias exclusions, OptiX-SBT case, transitively-containing structs).
- For any IR op, verify how the *builder* emits it before trusting a FIDDLE positional accessor — schema and builder can diverge (`MakeVectorFromScalar` declares 3 operands but is built with 1, so `getScalarValue()` reads OOB; the scalar is `getOperand(0)`).
- `defer <bare-decl>;` leaks scope because the parser opens none; single-statement `if`/`while` bodies leak identically but only `defer` crashes (scope-exit relocation of the `IRVar`). Fix in the parser (open a nested scope), not downstream.

## Slang C/COM API Has TWO Ownership Conventions — `loadModule` Returns a BORROWED Pointer

Slang's COM-lite API is NOT uniformly "returned interface is caller-owned / release it." **(a) BORROWED bare-pointer returns — do NOT release:** `ISession::loadModule`/`loadModuleFromSource`/`loadModuleFromBlob`/`getLoadedModule` return a bare `slang::IModule*` whose refcount is *unchanged* for the caller — the `Linkage`/session owns the only strong references and frees the module when the *session* is released (proof: `asExternal(Module*)` is a plain `static_cast` with no `addRef`; DeepWiki wrongly claims it increments). An FFI caller that releases a `loadModule` result drops the session's own ref → double-free / heap corruption at teardown. **(b) OWNED `T**` out-params — release once:** `link()`, `getTargetCode()`, `getEntryPointCode()`, `createCompositeComponentType()`, `findEntryPointByName()`, `getDefinedEntryPoint()` transfer ownership via `.detach()`; blobs are per-call allocations. Teardown recipe: don't release `loadModule` handles → release blobs/entry-points/composites you created → release session → release global session → `slang_shutdown()` (frees process-global SPIR-V grammar/RTTI/capability tables). Meta-lesson: when a crash disagrees with a stated ownership model, read the source at the call site — don't trust DeepWiki or the generic "COM caller owns returns" rule [Slang C/COM API: loadModule returns a BORROWED IModule*, not caller-owned](../learnings/1785172765216-slang-c-com-api-loadmodule-returns-a-borrowed-imod.md).

## Host-VM PathInfo::type Is Uninitialized — an aarch64-only `0 0` in an INTERPRET Autodiff Test (#12871)

For an aarch64-only wrong result in a `//TEST:INTERPRET` (slangi) autodiff test — e.g. `9 6 0 0 9 6` vs x86_64's `9 6 -9 -6 9 6` in `tests/autodiff/unary-plus-diff.slang`, where the zeroed values are the primal+tangent of `fwd_diff` through unary `-` — do NOT anchor on the specific differentiated op shown in the CHECK. The root cause is uninitialized `PathInfo::type` (`enum class Type : uint8_t`, no default init, `source/compiler-core/slang-source-loc.h:125`, read by `hasFoundPath()` ~l.77) during host-VM module serialization: `emitHostVMCode` does `new Module(linkage)` (`source/slang/slang-emit.cpp:3728`) and never sets a PathInfo before `serialize()`. That read happens ONCE PER slangi/INTERPRET invocation at module-serialization level, entirely upstream of and independent from whether the shader used a user `IFloat.neg()` or a builtin-scalar `-`. So the earlier #12871 assumption — that a builtin-scalar `-` mirror sidesteps the bug (it was filed against user `IFloat.neg()`) — is WRONG: ANY sufficiently-complex INTERPRET autodiff program can trip it on aarch64, and #12879 (`Type type = Type::Unknown;`) greens all of them, not just the neg() repro. Deterministic-across-all-aarch64-jobs is expected (cold zero-pages), not evidence against UB; which value gets zeroed is a downstream artifact of the corrupted serialization [#12871 host-VM PathInfo::type UB is not neg()-specific — hits builtin-scalar autodiff too](../learnings/1788537147888-12871-host-vm-pathinfo-type-ub-is-not-neg-specific.md).

## Front-End Guard/Cast Bugs: Property Accessors, #language, and the Lexer Continuation Byte

Three front-end declaration/lexing bugs triaged this day share a "the check is one layer off / too narrow" shape. A `[Differentiable]` (or `[TreatAsDifferentiable]`) on a struct **property** accessor segfaults slangc with no diagnostic (`#12210`), while a `[Differentiable]` *subscript* accessor is fine — so it's purely front-end header checking, not autodiff/IR. Root cause: `getFuncType` (`slang-syntax.cpp:1122`) branches `if (as<SubscriptDecl>(parent) || as<PropertyDecl>(parent))` then casts `parent.as<CallableDecl>()`, but `SubscriptDecl : CallableDecl` (has index params — the reason the branch exists) whereas `PropertyDecl : ContainerDecl` is NOT a CallableDecl. The load-bearing lesson: **`DeclRef::as<U>()` does NOT validate the target type** — it rewraps the same `declRefBase` and returns a non-null DeclRef even when the underlying decl isn't a `U`, so `if (declRef.as<CallableDecl>())` is a no-op guard; use `as<U>(rawDecl)` or `declRef.is<U>()` to actually test. Regression from PR #5922 which added the `|| as<PropertyDecl>` arm; fix restricts the param-prepend to `SubscriptDecl` only ([Differentiable property accessor segfaults getFuncType — PropertyDecl is not a CallableDecl](../learnings/1784883686572-differentiable-property-accessor-segfaults-getfunc.md)). Similarly, `#language glsl <n>` (`slang-preprocessor.cpp` `HandleLanguageDirective`) validates the version token only via `isValidSlangLanguageVersion`, never `isValidGLSLVersion`, so `#language glsl 460` errors E15207 while `#language glsl 2025` passes and then silently re-overrides the language back to Slang — the correct GLSL selector is `#version <n>`; the issue body's "PR #X will take care of this" was a **dedup gate**: checking the referenced PR's diff confirmed it net-satisfied the complaint (verdict = tracked-by-PR, no separate dispatch) ([#language glsl version mis-validates against Slang versions (not isValidGLSLVersion)](../learnings/1784916319659-language-glsl-version-mis-validates-against-slang-.md)). And the lexer silently accepts a lone UTF-8 **continuation byte** (0x80–0xBF, no lead byte, `#12222`) — but the instinct "the decoder doesn't handle it" is wrong: `getUnicodePointFromUTF8` already rejects a leading continuation byte; the bug is the branch guard `isUtf8LeadingByte` (`0xC0–0xFF` only) at `slang-lexer.cpp:267/:350` being too narrow, so the byte never enters the (correct) decode branch and falls through to identifier lexing. Fix at the guard (the producer of the branch decision), not the already-correct decoder nor the consumer; broadening to `isUtf8LeadingByte(c) || isUtf8ContinuationByte(c)` lets the existing E10006 emission fire — the general method being "when triaging 'X isn't diagnosed', check whether the low-level utility already rejects X and it's a routing/guard gap one layer up" ([Slang lexer lone-continuation-byte gap is a guard-narrowness bug, not a decoder gap](../learnings/1784917194691-slang-lexer-lone-continuation-byte-gap-is-a-guard-.md)).

## Reuse Canonical Immutable-Location / Opaque-Type Predicates, Don't Hand-Roll

When a fix must recognize "address-only / non-copyable / immutable-location" types across the whole class (ParameterBlock, ConstantBuffer, read-only StructuredBuffer/ByteAddressBuffer, read-only textures, samplers, and structs transitively containing them), reuse the existing canonical predicates rather than writing a new switch: `isPointerToImmutableLocation(IRInst*)` (`slang-ir-util.cpp:3105`, walks element-access chains and correctly excludes RW-alias + the OptiX-SBT case #10188) and `isOpaqueType(IRType*, IRType**)` (`slang-legalize-types.cpp:257`, recursive/cycle-safe, covers structs transitively containing resources). On slang#8002, `slang-ir-transform-params-to-constref.cpp:186 isLoadFromImmutableAddress` hand-rolls a narrow switch (ConstantBuffer/BorrowInParam/ParameterBlock only) that predates/duplicates `isPointerToImmutableLocation` — swapping it in gets full coverage in one source of truth. A subtle related mechanic: `lowerGlobalShaderParam` wraps a global param as `LoweredValInfo::simple(irParam)` even though the comment says the SSA value is a *pointer*; `tryGetAddress` has no `Flavor::Simple` case, so a global resource/PB param never presents as a Ptr and forces the by-ref temp path, emitting a bare `store(v, %g)` that `undoParameterCopy` (which matches `store(v, load(orig))`) misses [slang: reuse isPointerToImmutableLocation / isOpaqueType for constref copy-elision (do not hand-roll)](../learnings/1785194352818-slang-reuse-ispointertoimmutablelocation-isopaquet.md).

## IR Trap: Trust the Builder's Operand Count, Not a Generated Positional Accessor

**Trust the builder's operand count, not a generated positional accessor.** `kIROp_MakeVectorFromScalar` declares a THREE-operand Lua schema `{elementType, elementCount, scalarValue}`, so FIDDLE emits `getScalarValue() → getOperand(2)`; but every builder creates it with a SINGLE operand (`emitIntrinsicInst(..., 1, &scalarValue)`), and every existing consumer reads the scalar via `getOperand(0)`. Calling `getScalarValue()` therefore reads two `IRUse` slots past the array — asserts in Debug, wild pointer in Release — reachable from a module-scope splat like `static const uint3 g = (uint3)float3(3.0);` ([MakeVectorFromScalar getScalarValue reads getOperand(2) but builder emits 1 operand](../learnings/1785334765218-makevectorfromscalar-getscalarvalue-reads-getopera.md), [scalar is getOperand(0), NOT getScalarValue()](../learnings/1785335653192-makevectorfromscalar-scalar-is-getoperand-0-not-ge.md)). General rule: for any IR op, verify how the *builder* emits it before trusting a positional accessor — schema and builder can diverge.

## defer Bare Non-Block Decl Leaks Scope → IR-Lowering Segfault (#12266)

**Single-statement-body scope leak → defer-specific crash (#12266).** `Parser::ParseDeferStatement()` calls `ParseStatement()` without `pushScopeAndSetParent()`, so `defer uint i = 1;` leaks `i` into the enclosing function scope (name lookup then resolves it, suppressing `E30015`); IR lowering places the `IRVar` in the defer block, which `lowerDefer` relocates to scope-exit, so a reference before scope-exit derefs a stale value → segfault. `if(c) uint i=1;` / `while(...)` bodies leak identically but only `defer` crashes (the relocation). Fix = open a nested scope in the parser (mirror `parseBlockStatement`); the already-correct block form `defer { uint i=1; }` is the proof ([defer bare non-block decl leaks scope → IR-lowering segfault](../learnings/1785345383314-slang-defer-bare-non-block-decl-leaks-scope-ir-low.md)).
