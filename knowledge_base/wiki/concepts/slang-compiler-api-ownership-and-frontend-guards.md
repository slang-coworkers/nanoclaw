# Slang Compiler: C/COM API Ownership & Front-End Guard/Cast Bugs

This page covers the Slang C/COM API's two ownership conventions (why `loadModule` returns a BORROWED pointer), an uninitialized host-VM `PathInfo::type` that surfaces as an aarch64-only interpreter result, a family of front-end declaration/lexing guard-and-cast bugs whose common shape is "the check is one layer off / too narrow," reuse of canonical immutable-location/opaque-type predicates, an IR positional-accessor trap, and a `defer` parser scope leak.

## TL;DR
- Discipline unchanged: when a crash disagrees with a stated ownership model or a decoder/guard premise, read the source at the call site — don't trust DeepWiki or a generic rule. Fix the producer of a bad shape, not the consumer.
- Slang's COM-lite API is NOT uniformly "returned interface is caller-owned." `ISession::loadModule`/`loadModuleFromSource`/`loadModuleFromBlob`/`getLoadedModule` return a BORROWED `IModule*` (session-owned, refcount unchanged) — releasing it drops the session's own ref → double-free at teardown. `T**` out-params (`link`, `getTargetCode`, entry-point/composite creation) are OWNED — release once. Teardown order matters, ending in `slang_shutdown()`.
- The session caches a module whose IR lowering (not semantic checking) failed. A second `loadModule` of the same name returns it with no diagnostic, and codegen then asserts in `slang-ir-link.cpp`. slangc never loads twice, so test session-cache claims through the C++ API.
- Slang API threading: specialization and `link()` need external synchronization; only the codegen methods are concurrent. The Linkage op-mutex cannot simply be split front/back, because both halves insert into the shared ASTBuilder hash-cons cache.
- `getCurrentASTBuilder()` is thread_local and only the global-session thread has a default. New front-end code reached from `ComponentType::specialize` runs outside the `SLANG_AST_BUILDER_RAII` scope, so it needs its own RAII or it segfaults on a worker thread. Probe such a claim with a GENERIC instantiation (`S<float4>`) on a `std::thread`; a non-generic struct takes the `DirectDeclRef` path and is a false negative.
- Moving per-object state (a lock, a buffer) to `thread_local` changes three things. (1) Keying: a "one active buffer" rule that is per object needs a per-thread list keyed by object, not one scratch per thread. (2) Teardown: a `thread_local` with a destructor is gone before static destructors and earlier-constructed thread_locals run, so code reachable from them needs a trivially-destructible late path. (3) Retention: memory abandoned by destroyed objects now lives as long as the thread. Measure RSS against master, and check identity (pointer and size), not just the key.
- An aarch64-only wrong result in a `//TEST:INTERPRET` (slangi) autodiff test is host-VM serialization UB from an uninitialized `PathInfo::type`, NOT specific to the differentiated op shown in the CHECK. Deterministic-across-all-aarch64 is expected (cold zero-pages), not evidence against UB.
- Front-end guard/cast family, common shape "the check is one layer off / too narrow": `DeclRef::as<U>()` does NOT validate the target type (it rewraps and returns non-null) — use `as<U>(rawDecl)` or `declRef.is<U>()`. When triaging "X isn't diagnosed," check whether the low-level utility already rejects X and it's a routing/guard gap one layer up (lexer continuation byte, `#language glsl` version).
- Reuse canonical predicates rather than hand-rolling a narrow switch: `isPointerToImmutableLocation(IRInst*)` and `isOpaqueType(IRType*, IRType**)` already cover the whole address-only/opaque-type class (RW-alias exclusions, OptiX-SBT case, transitively-containing structs).
- A by-value struct copy left after `transformParamsToConstRef` is the `updateCallSites` temp, not the callee's copy. It is required when SSA folded the copy into a load of a variable the callee also writes through `inout`; it is only waste for a distinct, unmodified, non-escaping local.
- Adding/splitting a `ParamPassingMode` (e.g. `RefWriteOnly`): grep every raw `hasModifier<Out|InOut|Ref|Const>` read — `validateEntryPoint` picked SV-semantic direction from raw modifiers at four sites — and route through `getParamPassingMode` (mesh output types are an explicit exception).
- For any IR op, verify how the *builder* emits it before trusting a FIDDLE positional accessor — schema and builder can diverge (`MakeVectorFromScalar` declares 3 operands but is built with 1, so `getScalarValue()` reads OOB; the scalar is `getOperand(0)`).
- `defer <bare-decl>;` leaks scope because the parser opens none; single-statement `if`/`while` bodies leak identically but only `defer` crashes (scope-exit relocation of the `IRVar`). Fix in the parser (open a nested scope), not downstream.

## Slang C/COM API Has TWO Ownership Conventions — `loadModule` Returns a BORROWED Pointer

**(a) BORROWED bare-pointer returns — do NOT release:** `ISession::loadModule`/`loadModuleFromSource`/`loadModuleFromBlob`/`getLoadedModule` return a `slang::IModule*` whose refcount is unchanged; the `Linkage`/session owns the only strong refs and frees the module with the session (`asExternal(Module*)` is a plain `static_cast` with no `addRef`; DeepWiki wrongly claims it increments). An FFI caller that releases it drops the session's ref → double-free / heap corruption at teardown. **(b) OWNED `T**` out-params — release once:** `link()`, `getTargetCode()`, `getEntryPointCode()`, `createCompositeComponentType()`, `findEntryPointByName()`, `getDefinedEntryPoint()` transfer ownership via `.detach()`; blobs are per-call. Teardown: don't release `loadModule` handles → release blobs/entry-points/composites you created → session → global session → `slang_shutdown()` (frees process-global SPIR-V grammar/RTTI/capability tables). When a crash disagrees with a stated ownership model, read the call site, not DeepWiki or the generic COM rule [Slang C/COM API: loadModule returns a BORROWED IModule*, not caller-owned](../learnings/1785172765216-slang-c-com-api-loadmodule-returns-a-borrowed-imod.md).

The session cache keeps a module whose IR lowering failed: `Linkage::loadParsedModule` (`slang-session.cpp:1173-1188`) evicts from `mapPathToLoadedModule`/`mapNameToLoadedModules` only when *semantic checking* added errors. A diagnostic from `generateIRForTranslationUnit` (E40008 `invalid-l-value-for-ref-parameter`, e.g. `float g(__ref float2 x)` called as `g(v.zx)`) leaves it cached, so the first `loadModule("m")` returns null with the error and the second returns the module silently: `link()` succeeds and `getEntryPointCode` fails E99997 `slang-ir-link.cpp(399): c->value.ptrVal == nullptr`. Pre-existing on master (predates #13809). slangc never reloads, so test session-cache claims via a ~40-line C++ probe calling loadModule twice (link `build/Release/lib/libslang.so` with `-Wl,-rpath`); it also refuted a reviewer's "compiles silently with OpUndef" prediction. For note→error escalation PRs, a message-only `//CHECK: ^^^ <message>` matches any severity — pin with `error E<code>` [loadModule caches modules whose IR lowering failed](../learnings/1792579806821-session-loadmodule-caches-modules-whose-ir-lowerin.md).

## The API's Threading Contract: Linkage Op-Mutex Sites and the Front/Back Split (#13455)

docs/user-guide/08-compiling.md:1035-1046: specialization and `link()` require external synchronization; only the five codegen methods are concurrent. At master 5cb03fa5f, `Linkage::m_componentTypeOperationMutex` (slang-session.h:246) is taken at six sites (getSemanticsForReflection, createCompositeComponentType, COM specialize, link, getTargetProgram, getOrCreateLayout); `Linkage::specializeType` takes none, and getSemanticsForReflection locks only the swap of its cached context, then runs SemanticsVisitor unlocked. A front/back split races rather than deadlocks: the linkage ASTBuilder's hash-cons `m_cachedNodes` is a plain Dictionary (ast-builder.h:238) that both specialize and layout (getType/substitute, getTupleType, mangling, createIRModuleForLayout) insert into. Real contention is in getOrCreateLayout, which locks even when cached, so every getEntryPointCode/getTargetCode result-cache miss serializes via getOrCreateIRModuleForLayout (lower-to-ir.cpp:16584); an unlocked fast path is wrong because `m_layout` is published before `m_irModuleForLayout` ([Linkage op-mutex: front/back split races on ASTBuilder; getOrCreateLayout locks even when cached](../learnings/1791314287042-slang-linkage-op-mutex-front-back-split-races-on-a.md)). The race evidence to cite is layout→ASTBuilder, re-verified at 653bfdee: `TargetProgram::getOrCreateLayout` (slang-parameter-binding.cpp:~4841) reaches `ASTBuilder::getTupleType` (:2703) and `getOrCreate<>`, writing unlocked `m_cachedNodes`, while `ComponentType::specialize` (slang-linkable.cpp:~470) runs `SemanticsVisitor::CheckTerm` on the same builder. link → fillRequirements loops over the same `CompositeComponentType::create` as createComposite, but a direct ASTBuilder write there is unconfirmed — read slang-linkable-impls.cpp before claiming it ([cite layout→ASTBuilder, not link(), as the race evidence](../learnings/1792660287709-slang-13455-lock-split-cite-layout-astbuilder-not-.md)).

## Worker-Thread AST Builder: `SLANG_AST_BUILDER_RAII` in Code Reached from `specialize` (#13538)

`getCurrentASTBuilder()` is thread_local; only the thread that created the global session has a default (slang-global-session.cpp:70). Front-end entry points scope it with `SLANG_AST_BUILDER_RAII`, but `EndToEndCompileRequest::executeActionsInner` → `createSpecializedGlobalAndEntryPointsComponentType` → internal `ComponentType::specialize(args, count, sink)` runs outside that scope. A new check there reaching `getCurrentASTBuilder()` (#13538: `getTrailingUnsizedArrayElement` → `_getMemberDeclRef`) gets null on a worker thread and segfaults in `ASTBuilder::_getOrCreateImpl(this=0x0)`. Fix: `SLANG_AST_BUILDER_RAII(linkage->getASTBuilder())` at the top of the new function (as in `EntryPoint::_validateSpecializationArgsImpl`); regression test is a unit test compiling on a `std::thread` (deprecated `ICompileRequest` calls in `SLANG_ALLOW_DEPRECATED_BEGIN/END`) [new front-end code reached from ComponentType::specialize needs its own SLANG_AST_BUILDER_RAII](../learnings/1792060186315-slang-new-front-end-code-reached-from-componenttyp.md).

The repro shape decides whether it crashes: `getMemberDeclRef` short-circuits on a `DirectDeclRef` parent, so non-generic `struct S { float4 a; float4 x[]; }` passes; only a generic instantiation builds a `MemberDeclRef` needing the builder — `struct S<T> { float4 a; T x[]; }` with `-specialize S<float4>` gave rc 139 at 1ce058b, rc 0 on master. Same-thread runs and slangc never show it; drive `ICompileRequest::compile` on a `std::thread` with `addEntryPointEx(..., {"S<float4>"})` or `setGlobalGenericArgs`. A #13538 r4 reviewer dismissed the Security finding from one non-generic probe; when a claim names a code path, check which `DeclRef` subclass the probe takes before refuting [null-AST-builder repros need a GENERIC struct](../learnings/1792061760327-null-ast-builder-repros-need-a-generic-struct-non-.md).

## Moving Per-Object State to `thread_local`: Keying, Exit-Time Teardown, and Retention (#13786 / PR #13818)

`AppendBufferWriter` (`source/core/slang-writer.cpp`) had a per-writer mutex and append buffer; slang#13786 reported the mutex as misused, and PR #13818 replaced both with thread-local scratch. Every reviewer pass (Reviewer A with 6 subagents, Devin, clarity, codex) missed at least one of three lifetime regressions; peer review and measurement found them.

**Key the thread-local state by object.** "One active append buffer" is per writer, so `begin(A); begin(B); end(B); end(A)` on one thread is legal; with one per-thread scratch, B's `setCount` reallocates A's live buffer. Fix: a `thread_local` list of `{writer, buffer}` entries, each its own allocation, detached before `write()` so a re-entrant append gets a fresh buffer (revert drill confirmed the test). `find(this)` is not proof of ownership: it matched the calling thread's own abandoned entry, so a wrong-thread `end` wrote another thread's buffer — a "wrong thread → error" contract needs a pointer+size identity check. In Release `SLANG_ASSERT` is `SLANG_ASSUME`/`[[assume]]`, so `SLANG_ASSERT(!"msg"); return err;` is UB for reachable misuse; return a plain error ([thread-local append buffer must be keyed by writer](../learnings/1792583953497-thread-local-append-buffer-must-be-keyed-by-writer.md), [moving per-object storage to thread_local changes memory lifetime](../learnings/1792600018777-moving-per-object-storage-to-thread-local-changes-.md), [moving buffer ownership from object to thread changes lifetime](../learnings/1792602883492-moving-buffer-ownership-from-object-to-thread-chan.md)).

**A `thread_local` with a destructor is unsafe for code reachable from exit-time destructors.** On a thread, destructors still run after its function-local `thread_local`s die: static objects at process exit on the main thread, earlier-constructed `thread_local`s at thread exit. Function-static writers like `_getDefaultWriter` die after the main thread's thread_locals; if such a destructor prints, `beginAppendBuffer` runs `List::add` on destroyed storage (PR head segfaulted, master OK). A writer destructor can't simply clean up its entry either, since that may create thread-local state during teardown. The ASan/LSan-clean shape: a holder destructor sets a trivially-destructible `thread_local bool destroyed`; afterwards calls use a heap instance via a trivially-destructible `thread_local T*`, freed when idle; and the table is re-looked-up after any callback (`write()`), since a re-entrant late call can free the late instance (ASan caught that UAF). A never-freed per-thread allocation trips CI LSan (`ci-slang-sanitizer.yml`, `detect_leaks=1`). A 20-line probe linked against `build/Release/lib/libcore.a` (add `-isystem external/unordered_dense/include`, or use `compile_commands.json` flags) checks both: `static struct X { ~X(){ static NullWriter w(IsStatic); WriterHelper(&w).print("x"); } } g;` plus one print in `main`, and a `thread_local` whose destructor prints, constructed before the thread's first print ([a thread_local with a destructor is unsafe for code that may run from exit-time destructors](../learnings/1792591120086-a-thread-local-with-a-destructor-is-unsafe-for-cod.md), [moving buffer ownership from object to thread changes lifetime](../learnings/1792602883492-moving-buffer-ownership-from-object-to-thread-chan.md)).

**Retention moves from the object's lifetime to the thread's.** R2 kept buffers in a `thread_local` table keyed by writer address plus a reused `spare`; Reviewers A and C passed it, Devin flagged retention, and a VmRSS probe confirmed: 200 writers each abandoning 1 MiB then destroyed cost +205 MB (master +20 KB), and one 64 MiB append left the spare holding 64 MB for the thread's life (master 0). When storage moves from an object to `thread_local`/static scope, RSS-probe the object-destroyed and large-one-off cases against master; clean up from the destructor only through a find-without-create accessor; cap any spare (4 KiB). Build a master baseline probe with master's header (mixing headers gives a bogus stack-buffer-overflow). ~10% of ASan `std::thread` probe runs here hang at exit (exit 124, DEADLYSIGNAL) on master too — a toolchain artifact; judge hangs from non-ASan runs. The libcore.a probe technique is also on [Build tooling: testing a PR's effect locally](ci-b-build-tooling-local-testing.md) ([moving per-object storage to thread_local changes memory lifetime: measure RSS vs master](../learnings/1792600018777-moving-per-object-storage-to-thread-local-changes-.md), [moving buffer ownership from object to thread changes lifetime — measure retention and teardown](../learnings/1792602883492-moving-buffer-ownership-from-object-to-thread-chan.md)).

## Host-VM PathInfo::type Is Uninitialized — an aarch64-only `0 0` in an INTERPRET Autodiff Test (#12871)

For an aarch64-only wrong result in a `//TEST:INTERPRET` autodiff test — e.g. `9 6 0 0 9 6` vs x86_64 `9 6 -9 -6 9 6` in `tests/autodiff/unary-plus-diff.slang`, the zeroed values being `fwd_diff` through unary `-` — don't anchor on the op in the CHECK. The cause is uninitialized `PathInfo::type` (`enum class Type : uint8_t`, no default, `slang-source-loc.h:125`, read by `hasFoundPath()` ~l.77) during host-VM module serialization: `emitHostVMCode` does `new Module(linkage)` (`slang-emit.cpp:3728`) and never sets a PathInfo before `serialize()`. That read happens once per slangi invocation, independent of whether the shader used user `IFloat.neg()` or builtin-scalar `-`, so the #12871 assumption that a builtin-scalar mirror sidesteps it is wrong: any sufficiently complex INTERPRET autodiff program can trip it on aarch64, and #12879 (`Type type = Type::Unknown;`) greens them all. Determinism across aarch64 jobs is expected (cold zero-pages); which value is zeroed is a downstream artifact [#12871 host-VM PathInfo::type UB is not neg()-specific — hits builtin-scalar autodiff too](../learnings/1788537147888-12871-host-vm-pathinfo-type-ub-is-not-neg-specific.md).

## Front-End Guard/Cast Bugs: Property Accessors, #language, and the Lexer Continuation Byte

Three bugs share the "check is one layer off / too narrow" shape. **(1)** `[Differentiable]`/`[TreatAsDifferentiable]` on a struct **property** accessor segfaults slangc with no diagnostic (#12210), while a subscript accessor is fine — front-end header checking, not autodiff. `getFuncType` (`slang-syntax.cpp:1122`) branches `if (as<SubscriptDecl>(parent) || as<PropertyDecl>(parent))` then casts `parent.as<CallableDecl>()`, but `SubscriptDecl : CallableDecl` while `PropertyDecl : ContainerDecl` is not. **`DeclRef::as<U>()` does NOT validate the target type** — it rewraps the same `declRefBase` and returns non-null, so `if (declRef.as<CallableDecl>())` is a no-op guard; use `as<U>(rawDecl)` or `declRef.is<U>()`. Regression from PR #5922's `|| as<PropertyDecl>` arm; the fix restricts the param-prepend to `SubscriptDecl` ([Differentiable property accessor segfaults getFuncType — PropertyDecl is not a CallableDecl](../learnings/1784883686572-differentiable-property-accessor-segfaults-getfunc.md)). **(2)** `#language glsl <n>` (`HandleLanguageDirective`, `slang-preprocessor.cpp`) validates the version only via `isValidSlangLanguageVersion`, never `isValidGLSLVersion`, so `#language glsl 460` errors E15207 while `#language glsl 2025` passes and silently re-overrides the language to Slang; the GLSL selector is `#version <n>`. The issue's "PR #X will take care of this" was a dedup gate: the referenced PR's diff net-satisfied the complaint (tracked-by-PR, no dispatch) ([#language glsl version mis-validates against Slang versions (not isValidGLSLVersion)](../learnings/1784916319659-language-glsl-version-mis-validates-against-slang-.md)). **(3)** The lexer accepts a lone UTF-8 continuation byte (0x80–0xBF, #12222), but the decoder is not the gap: `getUnicodePointFromUTF8` already rejects it. The branch guard `isUtf8LeadingByte` (`0xC0–0xFF` only, `slang-lexer.cpp:267/:350`) is too narrow, so the byte falls through to identifier lexing; broadening to `isUtf8LeadingByte(c) || isUtf8ContinuationByte(c)` lets existing E10006 fire. Method: when triaging "X isn't diagnosed", check whether the low-level utility already rejects X and the gap is routing one layer up ([Slang lexer lone-continuation-byte gap is a guard-narrowness bug, not a decoder gap](../learnings/1784917194691-slang-lexer-lone-continuation-byte-gap-is-a-guard-.md)).

## Reuse Canonical Immutable-Location / Opaque-Type Predicates, Don't Hand-Roll

To recognize the whole address-only / immutable-location class (ParameterBlock, ConstantBuffer, read-only StructuredBuffer/ByteAddressBuffer/textures, samplers, structs transitively containing them), reuse `isPointerToImmutableLocation(IRInst*)` (`slang-ir-util.cpp:3105`; walks element-access chains, excludes RW-alias and the OptiX-SBT case #10188) and `isOpaqueType(IRType*, IRType**)` (`slang-legalize-types.cpp:257`; recursive, cycle-safe). On slang#8002, `isLoadFromImmutableAddress` (`slang-ir-transform-params-to-constref.cpp:186`) hand-rolls a narrow ConstantBuffer/BorrowInParam/ParameterBlock switch duplicating `isPointerToImmutableLocation`; swapping it in gives full coverage from one source of truth. Related mechanic: `lowerGlobalShaderParam` wraps a global param as `LoweredValInfo::simple(irParam)` though the SSA value is a pointer, and `tryGetAddress` has no `Flavor::Simple` case, so a global resource/PB param forces the by-ref temp path, emitting a bare `store(v, %g)` that `undoParameterCopy` (matching `store(v, load(orig))`) misses [slang: reuse isPointerToImmutableLocation / isOpaqueType for constref copy-elision (do not hand-roll)](../learnings/1785194352818-slang-reuse-ispointertoimmutablelocation-isopaquet.md).

A whole-struct copy surviving `transformParamsToConstRef` is usually not a missed elision: the callee already takes `T*`, and the copy is the call-site temp `updateCallSites` (`:243-246`) makes for any argument that isn't a load from a ConstantBuffer/ParameterBlock/BorrowIn root. SSA often folds `T copy = orig;` into `load(%orig)`, so if `orig` is also passed `inout` and written by the callee, the temp is a required snapshot; it is merely conservative only for a distinct, unmodified, non-escaping local (dropping it there removed 3 KB of spills on #13108). Inspect with `-dump-ir-before transformParamsToConstRef` [the leftover copy is its own call-site temp and is often required](../learnings/1791924437877-transformparamstoconstref-leftover-copy-is-its-own.md). On master 653bfdeef (2026-10-22) the #13108 repro still emits `State_0 _S7 = original_1; readFields_0(&_S7, &original_1);` for `-target cuda`; the argument is `load(%original1)` and the callee writes `original.a`, so a snapshot is required. A standalone nvcc harness on the L40S gives 16,18 for inputs 11,5 — correct, perf-only (the eval container lacks slang-test; recipe on [slangc target output](slangc-target-output-and-obfuscation.md)). The reply named the pass, confirmed correct values, planned copying only the fields the callee reads, and invited the reporter's PR [#13108 copy is a call-site temp; GPU result verified 16,18](../learnings/1792650204812-13108-reply-eval-copy-is-a-call-site-temp-from-tra.md).

## Changing a ParamPassingMode: Route Every Direction Decision Through `getParamPassingMode`

When a `ParamPassingMode` is added or split (e.g. `RefWriteOnly` for `__ref_writeonly`), overload resolution, coercion and lowering are not the only consumers: `validateEntryPoint` (`slang-check-shader.cpp`) picked semantic direction from `hasModifier<InOutModifier|OutModifier|RefModifier>()` at four sites (SV semantic validation, depth-output collection, varying-type direction labels, SV_Position output scan). So `__ref_writeonly uint : SV_GroupIndex` in compute was accepted and `SV_StencilRef` rejected — the reverse of `out` — with the suite green; only a codex CODE_REVIEW caught it. The fix (#13406) queries `getParamPassingMode(param)`, with one exception: the effective mode maps `MeshOutputType` (`out vertices V v[3]`, `OutputVertices<V,3>`) to `In`, so a direction helper must treat mesh outputs as outputs. Any `__ref` entry-point parameter to SPIR-V/GLSL hits a pre-existing `slang-ir-glsl-legalize.cpp` assert, so semantic-direction tests need `-no-codegen`. Before declaring done, run `rg 'hasModifier<(Out|InOut|Ref|Const)Modifier>|findModifier<(Out|InOut|Ref|Const)Modifier>' source/slang` and route each decision through `getParamPassingMode` ([grep every direct Out/InOut/Ref modifier read, incl. entry-point validation](../learnings/1791611645970-changing-a-parampassingmode-grep-every-direct-out-.md)). The witness-synthesis clone loop and `ParameterDirectionInfo` are the other re-derivation sites; see [[wiki/concepts/slang-language-core-requirement-witness-synthesis.md]].

## IR Trap: Trust the Builder's Operand Count, Not a Generated Positional Accessor

`IRMakeVectorFromScalar`'s Lua schema (`slang-ir-insts.lua:1373`) declares three operands `{elementType, elementCount, scalarValue}`, so FIDDLE emits `getScalarValue() → getOperand(2)`; but every builder emits one operand (`emitMakeVectorFromScalar` → `emitIntrinsicInst(..., 1, &scalarValue)`, `slang-ir.cpp:4758`, also `slang-ir-spirv-legalize.cpp:1771`), and every consumer reads `getOperand(0)` (`slang-emit-spirv.cpp`, `slang-ir-peephole.cpp:946`). `getScalarValue()` reads two `IRUse` slots past the array — asserts `index < getOperandCount()` (`slang-ir.h:711`) in Debug, wild pointer in Release — reachable from a module-scope splat `static const uint3 g = (uint3)float3(3.0);`. Found when PR #12263 (slang#12219) used `getScalarValue()` in a new SCCP helper; the plain two-arg `makeVector` test didn't cover the splat path. Reviewer lesson: Reviewer A called it a bug (confidence 90) because its checkout had `build/source/slang/fiddle/`; Reviewer C, lacking the generated headers, could only say "please confirm" — when adjudicating a "cannot confirm from source" finding, check whether fiddle headers exist and resolve it yourself ([MakeVectorFromScalar getScalarValue reads getOperand(2) but builder emits 1 operand](../learnings/1785334765218-makevectorfromscalar-getscalarvalue-reads-getopera.md), [scalar is getOperand(0), NOT getScalarValue()](../learnings/1785335653192-makevectorfromscalar-scalar-is-getoperand-0-not-ge.md)). For any IR op, verify how the builder emits it before trusting a positional accessor.

## defer Bare Non-Block Decl Leaks Scope → IR-Lowering Segfault (#12266)

`Parser::ParseDeferStatement()` calls `ParseStatement()` without `pushScopeAndSetParent()`, so `defer uint i = 1;` leaks `i` into the enclosing scope (lookup resolves it, suppressing E30015); IR lowering puts the `IRVar` in the defer block, which `lowerDefer` relocates to scope-exit, so an earlier reference derefs a stale value → segfault. `if(c) uint i=1;`/`while` bodies leak identically but only `defer` crashes (the relocation). Fix: open a nested scope in the parser (mirror `parseBlockStatement`); the working block form `defer { uint i=1; }` is the proof ([defer bare non-block decl leaks scope → IR-lowering segfault](../learnings/1785345383314-slang-defer-bare-non-block-decl-leaks-scope-ir-low.md)).
