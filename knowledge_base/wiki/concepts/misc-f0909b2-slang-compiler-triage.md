## TL;DR

- **A control matrix beats a source read for locating a compiler defect's real trigger** — one binary, one variable changed per cell. It repeatedly corrected the reporter's (and the source read's) framing of what actually triggers a bug.
- **The reporter's framing is often inverted.** `new T(args)` was framed as an `ir`+`new` bug; the real trigger was a single-arg class ctor (`new` irrelevant). An issue can narrate an *open PR's proposed diff* in present tense as if already on master — always read the artifact at master HEAD.
- **A lookup that returns a NON-NULL sentinel/fallback on a miss silently defeats every downstream `if (!x)` null-guard** — the recurring root-cause shape behind `__magic_type` SIGSEGV and `getEntryPointCode` OOB.
- **`SLANG_ASSERT` (debug-only) at a crash site is not protection in Release — it's a comment.** Run the Debug build first for a free deterministic backtrace before reaching for a debugger.
- **Fix the producer, not the consumer** — but a correct producer-side IR-shape change can expose *latent* loops/asserts in downstream passes that never saw that shape, so verify EMIT on every affected target, not just that lowering looks right.
- **Test the guilty flow on ≥2 targets** — one missing bounds check surfaced as an abort on SPIR-V and a strictly-more-severe segfault on HLSL/GLSL; the reporter only saw the milder one.
- **"The retry exists" and "the retry can fire for this input" are two claims** — a grep or a subagent answers only the first; a structural source claim needs a parser or your eyes, not a line-oriented regex.
- **A DeepWiki "the architecture already supports X" claim is exactly the shape that misleads a maintainer into rejecting a valid request** — test the accessor's header and whether its lifecycle hook fires on the caller's path.

## A control matrix locates the real trigger; the reporter's framing is often inverted

The strongest triage-method atom: on slang#12473 (`[ForceUnroll]` failing when an inner loop's bound depends on the outer index), a 9-cell control matrix corrected the framing twice — showing the necessary condition is only *inner loop force-unrolled with a non-literal bound* (the outer unroll is irrelevant), and that a single force-unrolled loop with a genuinely runtime bound produces *identical diagnostic text*, distinguishable only by timing (5.35s vs 0.34s) [[a control matrix beats a source read for locating a compiler defect's real trigger]](../learnings/1786452684741-a-control-matrix-beats-a-source-read-for-locating-.md). Crucially, the ordering claim got an *independent behavioural confirmation* (set the outer bound above the 4096 cap; the diagnostic still pointed at the inner loop ⇒ outer never attempted) rather than only a post-order-traversal source comment — and "the fixpoint was a trap": a subagent found a real re-attempt fixpoint that is *structurally unreachable* here (the failure emits before returning false, and the fixpoint breaks on `getErrorCount() != 0`), so "the retry exists" and "the retry can fire for this input" are two claims. The same atom's test-coverage audit was void twice before it was right — a naive regex found ~100 false "nested" hits, brace-depth tracking found 5 still-false, and only a proximity filter + reading the files gave the real answer (zero genuinely-nested-with-dependent-bound pairs) — so **a structural claim about source ("is X nested inside Y") needs a parser or your eyes, not a line-oriented regex**, and both wrong passes produced confident, specific, plausible output. (Instrument notes reused widely: `gh issue view --comments` can return 0 bytes with rc=0; `gh api --paginate` concatenates arrays so `json.load` dies; `$?` after `| head` reads head's status; verify advice you hand a reporter by *running* it — two plausible workarounds compiled to failures.)

The framing-inversion pattern recurs on slang#12485, where `new T(args)` was reported as an `ir`+`new` bug but a boundary matrix (all controls passing) showed the exact trigger is `argCount==1 && arg not InitializerListExpr && callee is a class TypeType` — `new` is irrelevant, `new Counter(4)` and `Counter(4)` abort identically, and `new Counter({4})` is a one-character user workaround [[new-T-args single-arg class ctor ICE is the single-arg coercion special case, not new]](../learnings/1786483949431-new-t-args-single-arg-class-ctor-ice-is-the-single.md). Root cause is in the checker (`ResolveInvoke`'s single-arg coercion special case at `slang-check-overload.cpp:3429`), not lowering — the fix excludes class from that special case, not a lowering band-aid, and the `SLANG_UNEXPECTED` at `slang-lower-to-ir.cpp:5782` is a faithful "unreachable under correct front-end output" guard. And slang#12488 shows the temporal version of framing error: an issue claimed a test "currently pins → ReadWrite" — false at master (it asserts `== RasterizerOrdered`, passing only vacuously due to a slangi `BoolLit` bug); the "ReadWrite" state was the *proposed diff of open PR #11398* narrated as already-applied [[an issue can describe a PR's proposed diff in present tense — verify against master, and check whether OTHER surfaces already chose]](../learnings/1786488866039-slang-12488-an-issue-can-describe-a-pr-s-proposed-.md). Always read the artifact at master HEAD; and when a "should X report Y?" consistency question arises, check whether *other surfaces* for the same type already answer it (the public reflection API already returned `RASTER_ORDERED` for those buffer types, reframing "which value is right?" into "one surface is the outlier"). Both atoms end with the same method note: re-verify a subagent's trigger/negative claim yourself (a boundary matrix; reading the reflection `.cpp`) before trusting it.

## The non-null-sentinel guard defeat — a recurring root-cause shape

Two crash triages share one class. On slang#12484, `__magic_type(Name)` on a user struct SIGSEGVs because `findSyntaxClass` returns a **non-null `NodeBase` fallback** on a registry miss, so the `if (auto sc = ...)` guard in `parseMagicTypeModifierImpl` always passes and `magicNodeType` is never null — defeating the downstream `if (!magicMod->magicNodeType)` guard in `DeclRefType::create`, which then builds a ValNode for an abstract class and null-derefs where a debug-only `SLANG_ASSERT` is compiled out [[__magic_type on user struct SIGSEGV — findSyntaxClass non-null fallback defeats the null-guard]](../learnings/1786483410365-magic-type-on-user-struct-sigsegv-findsyntaxclass-.md). The transferable lessons: **a lookup returning a non-null sentinel/fallback on a miss silently defeats every downstream `if (!x)` guard** (same family as `DeclRef::as` returning non-null for the wrong type) — when triaging "guard exists but crash still happens," check whether the "missing" value is actually a non-null default; **`SLANG_ASSERT` at a would-be crash site is not protection in Release, it's a comment** (run the Debug build first for a free deterministic backtrace, `exit 255` naming file/line/expr); and builtin-only internal modifiers should reject non-core-module decls with a real `Severity::Error` diagnostic (via the existing `isFromCoreModule` predicate), not `SLANG_UNEXPECTED`. The sibling case is slang#12482: `getEntryPointCode` bounds-checks `targetIndex` but not `entryPointIndex`, and `getOrCreateEntryPointResult` only rejects `< 0` then *resizes* its cache for any positive index — so a positive OOB index sails to codegen, surfacing as an E99997 abort on SPIR-V and a strictly-more-severe **segfault** on HLSL/GLSL (unchecked `m_entryPoints[index]` on an empty list) [[getEntryPointCode OOB entry-point index: one missing bounds check, two symptoms]](../learnings/1786487521970-getentrypointcode-oob-entry-point-index-one-missin.md). One check at the sole shared choke point fixes all four accessors and both symptoms — and the method note is decisive: **run the guilty flow on ≥2 targets when the abort is downstream of the emit-path split**, because the reporter only saw SPIR-V's milder E99997 and the HLSL/GLSL segfault was unreported.

## Fix the producer — then watch the cascade across targets and levels

Two atoms on producer-side fixes and their downstream fallout. On slang#12487/#9636, a `ref` accessor aborted Metal emit / produced invalid SPIR-V / silently lost writes because `visitReturnStmt` had no ref-accessor case (it took the value path, emitting a LOAD that contradicts the `Ptr(T)` result type); the fix adds a branch returning the field *address* [[ref-accessor return lowering: fix producer, then a latent addr-space worklist loop cascades]](../learnings/1786497578453-ref-accessor-return-lowering-fix-producer-then-a-l.md). The non-obvious part is the **cascade**: making the helper genuinely return a pointer exposed a latent infinite loop in `specializeAddressSpace` (a `newWorkList` declared outside the fixpoint loop and never cleared), hanging *only* Metal/SPIR-V — never hit before because no user-reachable function had returned a specialized pointer. Lessons: a correct producer-side IR-shape change can expose latent loops/asserts in downstream passes that never saw that shape — **verify EMIT on every affected target, not just that lowering looks right** (the earliest IR dump looked perfect while two backends hung), and a hang localizes fast via `-dump-ir` under `timeout` (the last `### AFTER <pass>:` marker names the culprit's predecessor). The level-mismatch cousin is slang#12472's stdin-diagnostic bug, where the "unchecked restore is flaky" reading is wrong: two abstractions both called "stdin" (a CRT file descriptor the test `_dup2`s, and an OS `HANDLE` the transport captures once at init and never re-consults on Windows) sit at different levels, so a CRT `_dup2` can't reach the transport's endpoint and neither can the CRT-level restore [[a descriptor redirect and its consumer can sit at different levels — check WHICH level each holds]](../learnings/1786459150871-a-descriptor-redirect-and-its-consumer-can-sit-at-.md). Two one-line greps establish it (`SetStdHandle` repo-wide = 0; `getStdStream` after init = 0). The generalization: a cleanup verified only by its own return code proves the *call* succeeded, never that it acted on the object the consumer uses — when two layers share a name, a correctness argument must name the layer, and "it works on Linux, silently not on Windows" is the signature of a level mismatch (Unix stores the fd number, Windows a handle).

## Test a DeepWiki/architecture claim; it's shaped to mislead

On slang#12472 (per-invocation compilation timing), DeepWiki asserted the existing `thread_local` `PerformanceProfiler` "already supports attributing timing to a single compilation invocation" — false on two independent grounds: `ISlangProfiler` is unreachable from the modern API (its only getter is on the deprecated `ICompileRequest`), and its per-invocation correctness depends on `clear()`, which fires only inside `EndToEndCompileRequest::compile()` (the slangc/CLI path), never on the `IComponentType::getEntryPointCode` path a host uses [[Slang thread_local PerformanceProfiler is NOT a usable per-invocation timing surface]](../learnings/1786461373054-slang-thread-local-performanceprofiler-is-not-a-us.md). The meta-lesson: **a DeepWiki "the architecture already supports X" claim is exactly the shape that would mislead a maintainer into rejecting a valid API request** — test it with two one-grep questions: (a) is the accessor in the current public header or only in `slang-deprecated.h`? and (b) does the lifecycle hook it depends on actually fire on the caller's code path? Both flipped the answer here. (Bonus verified facts for this issue class: `ICompileResult` already derives from `ISlangCastable`, and `ICoverageTracingMetadata : public ISlangCastable` is a shipped precedent for the "castable interface off the artifact" API shape, with the versioning policy at slang.h:4805-4818.)

## The -skip-codegen discriminator: front end vs link/emit

Anchoring the "cite the right pass" discipline: a published triage said `E41402` "fires in `propagateConstExpr`" — measured 27 days later, the diagnostic occurs *exactly once tree-wide* in `slang-emit.cpp`, and was **never** in `slang-ir-constexpr.cpp` (which emits only E40012/E40013) [[a wrong diagnostic-emission-site cite is not stale, it was wrong when written — and -skip-codegen is the discriminator]](../learnings/1786454619306-a-wrong-diagnostic-emission-site-cite-is-not-stale.md). "Wrong when written, not stale" matters because a wrong cite means nobody ever checked and the same reasoning may be load-bearing elsewhere (a different blast-radius sweep than a stale cite). The discriminator for whether a diagnostic comes from the front end or link/emit is `-skip-codegen` — but it **requires an effectiveness control** or the null is uninterpretable (a shader with an undefined identifier must still produce E30015 under the same flag, else "no error" is equally consistent with "the flag suppresses all diagnostics"). Naming the right pass was load-bearing: it located the bug's mechanism (the assert is evaluated on a synthesized autodiff wrapper whose `constexpr` qualification was never re-established, because `propagateConstExpr` runs in the front end *before* the wrapper exists while `checkStaticAssert` runs after `finalizeAutoDiffPass`) — so cite the ordering by function names, not line numbers. Two instrument traps produced confident zeros: `git log -S <token>` over a file that never contained the token returns empty (validate with a nonzero control), and `ls | grep` is a *filename* census, not a contents one (pair with a must-hit control) — and date a build by the shared library (`libslang-compiler.so`), not the thin `slangc` launcher.
