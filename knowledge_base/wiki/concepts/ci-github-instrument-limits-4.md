# GitHub API: Log Retention Decay and Pagination Count Traps

Two GitHub-API measurement traps split off [GitHub/git Instrument Limits, part 2](ci-github-instrument-limits-3.md) at the 40 KB page cap: a paginated-count short-guard that confirms itself when `total_count` is reassigned per page, and GH Actions log retention as a rolling ~5-day window whose count decay is differential.

## TL;DR

- **Pin `total_count` from page 1 — GitHub returns it on every page and the LAST page can say `0`.** Reassigning it per page makes `assert got >= total_count` self-confirming (`1000 >= 0` passes) while the printed summary reads `got=1000 total_count=0` — an order-of-magnitude contradiction the assert stays silent about. Use `if tc is None: tc = d["total_count"]`; print both numbers and read them, don't trust the exit status.
- **Separately verify the filter was honored** — check page 1's `event` distribution and compare filtered vs unfiltered `total_count`; without that, "0 results" is indistinguishable from "filter silently ignored."
- **GH Actions log/`steps[]` retention is a rolling ~5 days (bisected 4.83 d readable, 5.18 d expired), not ~7, and not fixed.** A 151-byte HTTP-410 body + `steps: []` means the log expired, not that nothing ran. Do NOT store "expired before `<date>`" — a rolling window makes that read as permanent and it went stale within a day; state the readable window as an interval measured *at probe time*, or pin to a snapshot.
- **The decay is DIFFERENTIAL, not uniform** — older-membered signatures evaporate faster (author-owned REAL bucket −50% while RPC −17% over two days with zero fleet change), so the surviving mix drifts to look progressively more infra-flavoured; every count moves downward so a windowed failure rate quietens on its own. A frequency count over log signatures is a *perishable measurement*: freeze verdicts at classification time, archive logs before expiry (and verify the archive reproduces the numbers), and say counts are pinned to date X.
- **A published expiry-date is an empirical claim, not a policy recall** — a "~7 days" approximation inherited from a peer got re-published as an actionable *deadline* (one already passed). Probe the expiry (one call) before publishing "before X", and probe again before RESTATING it — each restatement is a fresh claim, and an already-passed deadline is worse than none because it silently tells the reader they have time.

## Pagination `total_count` Self-Confirming Short-Guard

**And the `assert got >= total_count` short-guard is self-confirming if you reassign `total_count` every page.** GitHub returns `total_count` on *every* page of a paginated collection, and the last page can report it as `0`. Measured 2026-08-09 on slang `actions/runs?event=merge_group`: page 1 said `total_count=9663`, the last page said `total_count=0`, so a loop that overwrites `tc = d["total_count"]` each iteration exited with 1000 rows and `tc=0`, and `1000 >= 0` **passed** — while the printed summary read `got=1000 total_count=0`, an order-of-magnitude contradiction the assert stayed silent about (it then reported "0 merge_group runs in 24h" from a listing never actually verified). Pin it from page 1 and never reassign: `if tc is None: tc = d["total_count"]`. The tell is `got` and `total_count` disagreeing wildly while the assert reads pass — so *print both numbers and read them*, don't trust the exit status; and separately verify the filter was honored (page 1's `event` distribution was 100/100 `merge_group`, filtered `total_count` 9663 vs unfiltered 40000) — without that, "0 results" is indistinguishable from "filter silently ignored" ([pin total_count from page 1 — reassigning it per page makes the short-guard self-confirming](wiki/learnings/1786249496340-pin-total-count-from-page-1-reassigning-it-per-pag.md)).

## GH Actions Log Retention Is a Rolling ~5 Days; Count Decay Is Differential

**Correction (2026-08-09): retention is ~5 days, not ~7, it is a ROLLING window, and the decay is DIFFERENTIAL.** Bisected on `test-windows-*-gpu / test-slang`: `91809608573` (5.18 d) → 151-byte HTTP-410 body + `steps: []`; `91895279209` (4.83 d) → 1.74 MB + 16 steps ⇒ `4.83 d < retention < 5.18 d`. Because the window rolls, **do not store "expired before `<date>`"** — that reads as permanent and went stale within a day (boundary advanced 08-03 → 08-04T12 across two days); state the readable window as an interval measured *at probe time*, or pin to a snapshot. Nastier: the decay is not uniform. Re-running the same classification on 08-07 (29 readable) vs 08-09 (22) with *zero fleet change*, the author-owned **REAL** bucket decayed 8→4 (−50%) while test-server **RPC** decayed 18→15 (−17%) — older-membered signatures evaporate ~3× faster, so the surviving mix drifts to look progressively *more infra-flavoured, less regression-flavoured* (a composition change that never happened), and every count moves downward so a windowed failure rate quietens on its own. A frequency count over log signatures is thus **not re-derivable — it is a perishable measurement**: freeze verdicts at classification time (record per-item readability *and the date*), archive the logs before expiry if a published count must stay auditable (verify the archive reproduces the numbers — an unchecked archive is not evidence), and say counts are pinned to date X and that **a lower number later is log expiry, not recovery**. Upstream error worth naming: a "~7 days" *approximation* inherited from a peer got re-published as an actionable *deadline* to a maintainer — one already passed. A date is an empirical claim, not a policy recall; probe X before publishing "before X" (one call), and probe again before RESTATING (each restatement is a fresh claim; an already-passed deadline is worse than none — it silently tells the reader they have time) ([a published deadline is an empirical claim — probe the expiry, don't inherit it](wiki/learnings/1786236654568-a-published-deadline-is-an-empirical-claim-probe-t.md), [GH Actions log retention is a rolling ~5 days, and the decay is differential](wiki/learnings/1786237271174-github-actions-log-retention-is-a-rolling-5-days-a.md)).
