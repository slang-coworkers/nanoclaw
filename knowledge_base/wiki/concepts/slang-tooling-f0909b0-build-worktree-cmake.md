# Slang build in worktrees: submodule init, A/B baselines, stale binaries

## TL;DR

Per-issue `git worktree` builds over a shared base clone have setup traps (10–40 min each unhandled), and the CMake graph can go stale after a rebase.

- **`git worktree add` does NOT populate submodules** (nor nested ones): configure fails with `non-existent target "SPIRV-Headers::SPIRV-Headers"` or `external/<x> does not contain a CMakeLists.txt`. A missing `::` target is almost always an uninitialised nested submodule (usually `external/spirv-tools/external/spirv-headers`).
- **Before the first configure run `git -c protocol.file.allow=always submodule update --init --recursive --jobs 16`.** The shared `.git/config` points every submodule at the base clone's local checkout, which git ≥2.38 blocks ("transport 'file' not allowed"); `--depth`/`--reference` don't help. Never rewrite the shared URLs; fallback: `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=protocol.file.allow GIT_CONFIG_VALUE_0=always`.
- **Init is offline and fast** (seconds to ~1 min; slang-rhi's nested ones use https). Clear a half-written cache before reconfiguring. Copying `external/` from a same-pin worktree also works. Submodule `origin` is the shared clone: fetch upstream from the GitHub URL.
- **On this GLIBC 2.36 host add `-DSLANG_ENABLE_DXIL=OFF`** (or `-DSLANG_DXC_BUILD_FROM_SOURCE=OFF`) unless you need DXIL, or configure source-builds DXC (10–30 min). A `slangc slang-test`-only worktree also needs `libslang-llvm.so` in `build/<cfg>/lib`, or FileCheck rows report ignored.
- **Quick PR-head `slangc`:** detached worktree at `pull/<N>/head`, init (or symlink `external/<sub>`), tests/examples/gfx/rhi off, and build `slang-glslang` too or every `-target spirv`/`-O1` compile fails with E00100 (~5 min). A clean `SLANG_RUN_SPIRV_VALIDATION=1` does not prove debug info is sane.
- **Old (2025-era) commits fail with "not our ref"**: fetch each pinned SHA from upstream into `.git/modules/external/<p>`, `foreach 'git checkout -f HEAD'`, skip WindowsToolchain; add `-DSLANG_ENABLE_GFX=ON` and `slang-glslang`.
- **After merging master: `git submodule update --init` (pins may move), then build the FULL preset.** A targeted `slangc slang-test` build leaves serialized std modules stale (`E00131`) and never builds `slang/functional.slang`, `slang` or `slangi` (~15 false failures).
- **The prebuilt `slangc` in the mounted checkout can be many commits behind HEAD** — check `slangc -v`'s `-g<sha>`. It prints the configure-time describe, and a clean `git status` proves only the source: rebuild after every revert-drill restore.
- **A slangc/slang-test copied out of `build/Debug` is a different instrument**: prelude and OptiX headers resolve relative to the exe (~31 CUDA/OptiX tests fail from a `-bindir` copy). Compare like-for-like plus a no-change control.
- **Never run baseline and candidate full suites concurrently** (or beside a build); ~91 environmental failures remain on a quiet no-GPU box. **Don't background the build in a subagent** — a detached ninja dies with its shell.
- **A corpus A/B diff needs equal-length bindirs, a stripped new-pass dump and a null control, and covers only shapes the corpus contains.** Never share one `.slang-module`-writing worktree between two binaries or rebuild one mid-sweep; strip `#line`/absolute `#include` lines.
- **Configure flags, DXC-from-source, sanitizers and build costs: [Slang build configuration](slang-tooling-build-configure-dxc-sanitizers.md).**

## Worktree submodule init

`git worktree add` checks out tracked files but not submodules, so `external/*` starts empty: `cmake --preset default` fails (usually `non-existent target "SPIRV-Headers::SPIRV-Headers"`), `cmake --build` dies with `ninja: error: loading 'build-Debug.ninja'`, and `git submodule status` shows a leading `-` per entry. The base clone is `git clone --depth 50` without `--recursive`, so every new worktree starts this way ([cascade](../learnings/1787176235982-git-worktrees-do-not-inherit-submodule-checkouts-i.md), [init + DXIL off](../learnings/1787824391934-slang-worktree-build-needs-submodule-init-disable-.md), [#13017](../learnings/1789394522873-fresh-slang-worktree-submodule-init-clang-format-1.md)). In the worktree, before the first configure:

```bash
git -c protocol.file.allow=always submodule update --init --recursive --jobs 16
rm -f build/CMakeCache.txt && rm -rf build/CMakeFiles   # only if a configure already ran on the empty external/
cmake --preset default
```

**Why the override.** The shared `.git/config` maps each `submodule.<path>.url` to the base clone's checkout (`/workspace/agent/slang/external/<name>`) and git ≥ 2.38 blocks the file transport, so a plain init fails with `fatal: transport 'file' not allowed`, first on `external/WindowsToolchain` or `external/unordered_dense` ([WindowsToolchain](../learnings/1791581040071-new-git-worktree-of-workspace-agent-slang-submodul.md), [#13410](../learnings/1792241165412-new-slang-worktrees-from-the-local-clone-need-git-.md)). `--reference` fails too ([`--reference`](../learnings/1793323215178-slang-worktree-submodules-proving-a-slang-test-gpu.md)), sometimes as "reference repository ... is shallow" ([shallow](../learnings/1792088805773-slang-worktree-submodules-reference-to-the-shallow.md)); `--depth 1` is ignored for local clones. The `-c` form is reconfirmed in every report since 2026-10-29 (PR-head, #14307 and 2026-11-05 builds below); once only the `GIT_CONFIG_COUNT` env form worked, hence the fallback ([env form](../learnings/1793312277621-fresh-slang-worktree-submodule-init-fails-with-tra.md)). Never rewrite the shared URLs: the base clone and sibling worktrees read them ([shared refs](../learnings/1793301770175-worktree-refs-are-shared-reset-soft-origin-master-.md)).

**Offline and fast.** Top-level submodules clone from the local module store in ~10 s (`--jobs 16`) to ~1 min ([offline](../learnings/1792661987044-slang-worktrees-submodule-init-is-offline-because-.md), [`-c`, ~1 min, `--depth` ignored](../learnings/1793335182089-slang-worktree-submodule-init-fails-with-transport.md), [~10 s](../learnings/1792436239104-core-module-bootstrap-aborts-on-any-warning-worktr.md), [`--jobs 16`](../learnings/1792823537201-new-slang-worktree-build-submodules-need-protocol-.md), [~13 s](../learnings/1790636604671-fresh-slang-git-worktree-init-submodules-before-cm.md)); unmapped nested ones such as slang-rhi's come over https ([nested](../learnings/1793296016142-submodule-init-in-slang-worktrees-needs-protocol-f.md)). Each worktree submodule's `origin` is the shared local clone, so fetch a newer upstream commit from GitHub: `git fetch https://github.com/shader-slang/slang-rhi.git main` ([origin = shared clone](../learnings/1793879645962-slang-worktree-submodule-init-needs-protocol-file-.md)).

**Partial init and stale caches.** A top-level-only init (no `--recursive`) also builds, skipping slang-rhi's nested submodules and dxc/llvm. Shallow flags are harmless only because the objects are already local; a real shallow fetch gets branch tips, not pins (see [CI Build: Git Checkout Depth & Submodule Pins](ci-build-git-checkout-and-submodule-pins.md)). If a configure already ran on the empty `external/` ("Configuring incomplete"), clear the cache as above or `rm -rf build`, also for a worktree recreated on an existing `fix/issue-*` branch ([top-level only](../learnings/1787677680988-slang-git-worktree-needs-per-worktree-submodule-in.md)). A configure `&&`-chained behind a failed submodule step exits 1 silently; read the submodule log.

**Alternatives.** Copy a populated `external/` from another worktree when the pins match (`git diff --quiet <base> HEAD -- external .gitmodules`; ~10 min to a build on #13429) ([copy external/](../learnings/1791151479459-slang-pr-review-runner-scripts-may-lose-exec-bit-r.md)), e.g. `cp -a slang/external/. wt/external/` (no rsync) ([`cp -a`](../learnings/1792666503891-two-prs-that-add-the-same-lines-can-merge-cleanly-.md)).

**Old commits add dead pins.** Bisecting 2025-era commits (e.g. v2025.12..v2025.13), `git submodule update` fails with "not our ref" for lz4, miniz, unordered_dense and glslang: the local mirrors lack the old SHAs, and WindowsToolchain's pin is gone upstream. Fetch each pinned SHA into the shared module store from the `.gitmodules` upstream URL, then check the dirs out (until then they hold only `.git` files), skipping WindowsToolchain:

```bash
git --git-dir=/workspace/agent/slang/.git/modules/external/<p> fetch <upstream-url> <sha>
git submodule foreach 'git checkout -f HEAD'
```

Old trees also need `-DSLANG_ENABLE_GFX=ON` (render-test) and the `slang-glslang` target, or `-target spirv` fails to load spirv-opt; Release `slangc` ~6 min at `-j20`. (Aside: master `-vk` misreads `column_major int` matrix buffer fields, #13446; use float matrices.) ([2025-era](../learnings/1792191559147-building-2025-era-slang-commits-dead-submodule-pin.md))

## Building after the init

**Build cost.** On this GLIBC 2.36 host the first configure builds DXC from source (~500 MB, 10–30 min); pass `-DSLANG_ENABLE_DXIL=OFF` unless the task needs DXIL ([build configuration](slang-tooling-build-configure-dxc-sanitizers.md)), or `-DSLANG_DXC_BUILD_FROM_SOURCE=OFF`, which takes the prebuilt without the GLIBC check. On 60–64 cores, no sccache: Release `slangc` + `slang-test` (+ `render-test`) ~5–10 min, two in parallel fine ([#14307](../learnings/1793809802346-worktree-submodules-need-protocol-file-allow-rebui.md)); full Release `-j 60` with DXIL off ~6 min; five Release targets (`slangc`, `slang-test`, `slang-unit-test`, `slang-reflection-test`, `test-server`) ~10 min, where `SLANG_ENABLE_TESTS` requires `SLANG_ENABLE_SLANG_RHI` and a re-configure needs `=ON` passed explicitly ([#13535](../learnings/1791499534921-slang-worktree-build-slang-enable-tests-requires-s.md)); outlier: ~30 min and 5.3 GB on #13858. A clean debug build is ~1510 steps in under 10 min; CUDA is auto-detected from `/usr/local/cuda-12.6`. Configure's `FETCH_BINARY_IF_POSSIBLE` normally downloads `build/Release/lib/libslang-llvm.so` (possibly an old release); if missing, copy it in ([Test instruments](slang-tooling-test-instruments.md)).

**Two-commit build bisect.** To confirm a code-trace regressor, put a worktree at `<sha>^`, init, configure Release with LLVM/tests/examples/gfx/rhi/slangd/slangi/DXIL off, build `--target slangc` (~15 min on 64 cores), probe, then `git checkout <sha>` and rebuild: only the touched TU recompiles (13 steps, <1 min), giving a built counterfactual instead of "by code trace" ([bisect](../learnings/1792065111999-two-commit-build-bisect-is-cheap-when-the-suspect-.md)).

**Quick PR-head build, without touching the shared checkout.** `git fetch origin pull/<N>/head:refs/remotes/pr/<N>`, `git worktree add --detach <dir> pr/<N>`, then the `-c` init, or (PR base = main checkout's HEAD) symlink each empty `external/<sub>` to the main checkout's copy. Configure with `-DSLANG_ENABLE_TESTS=OFF -DSLANG_ENABLE_EXAMPLES=OFF -DSLANG_ENABLE_GFX=OFF -DSLANG_ENABLE_SLANG_RHI=OFF -DSLANG_DXC_BUILD_FROM_SOURCE=OFF` and build `--preset release` for `slangc` **and** `slang-glslang`: spirv-opt/spirv-dis live in slang-glslang, so without it every `-target spirv`/`spirv-asm` or `-O1` compile fails with E00100 "failed to load downstream compiler 'spirv-opt'", which looks like the fix broke everything. ~5 min, ~4.2 GB; `git worktree remove --force` and delete the ref afterwards ([quick build](../learnings/1792365932155-quick-pr-head-slangc-verify-build-symlink-submodul.md), [private worktree](../learnings/1793434873472-build-a-pr-head-in-a-private-worktree-init-submodu.md), [SPIR-V build](../learnings/1793463061545-fast-slangc-build-in-a-fresh-slang-pr-worktree-for.md)). Caveats: `SLANG_RUN_SPIRV_VALIDATION=1` passes bad debug info (`OpUndef`-pointer DebugValues, or ones before `DebugFunctionDefinition`, on #13842/#14114), so count `DebugDeclare`/`DebugValue` per `DebugLocalVariable` yourself; if a shared build's freshness is unknown, probe with the newest compiler commit's test (shared Release was once stale while Debug was current), and `SLANG_ASSERT=release-assert-only` lets Debug pass a debug-only assert (e.g. #13272) to show what Release emits.

**Build-subagent hazard and formatters.** A subagent that launches ninja with `&`/`nohup` and returns leaves a detached build that dies with its shell (on #13017 one returned in ~25 s and kept launching background ops). Build in the foreground or as a Bash `run_in_background` grandchild; check liveness with `pgrep -x ninja` + `readlink /proc/<pid>/cwd` (never `pgrep -f`, which matches your own argv). A Monitor on `build.log` mis-fires when *configure* failed (no `build.log`). Formatters in the slang-fixer container: `/workspace/agent/bin/shfmt`, gersemi 0.21 at `/workspace/agent/tools/gersemi-venv/bin/gersemi` (the `bin/gersemi` shim is broken), `/usr/bin/clang-format-17`; symlink them into one PATH dir, or `pip install --user clang-format==17.0.6`. The script skips Lua diagnostics (`slang-diagnostics.lua`); match their style by hand.

## A/B baselines must be like-for-like

**Relocated copies.** A `build/Debug/{bin,lib}` snapshot used as a master baseline differs on CUDA/PTX paths: `TestToolUtil::setSessionDefaultPreludeFromExePath` resolves `prelude/` relative to the executable (else inlines the embedded prelude, changing the `.cu`), and nvrtc's `_findOptixIncludePath` looks for `<instance>/../../../external/optix-dev/include`, so a copy fails every OptiX/PTX compile ("Failed to locate OptiX headers"). Under `-bindir <copy>/bin` ~31 tests (`tests/cuda/*`, `tests/optix/*`, header-generation, some SER) fail that pass in-tree ([~31 tests](../learnings/1790714053699-slang-test-from-a-bindir-binary-copy-fails-31-cuda.md)). Run both from the same kind of location with a no-change control, or recreate the tree shape around the copy ([`<bin>/../../..`](../learnings/1790719029887-slang-binary-copies-prelude-optix-headers-resolve-.md)):

```bash
mkdir -p X/build/Debug X/external
cp -al copy/bin copy/lib X/build/Debug/
ln -s <tree>/external/optix-dev X/external/optix-dev
ln -s <tree>/prelude X/prelude
```

That setup exposed master's own PTX failure for slang#13329. Keep scratch under `/workspace/agent/` (`/tmp` is wiped).

**Missing CUDA driver.** With no NVIDIA driver the link fails on a missing `/usr/lib/x86_64-linux-gnu/libcuda.so`; reconfigure with `-DCUDA_cuda_driver_LIBRARY=/usr/local/cuda-12.6/lib64/stubs/libcuda.so` ([stub](../learnings/1790802490676-slangc-o-dev-null-fails-with-e00004-in-the-fixer-c.md)). At run time it shows as `tests/cpu-program/gfx-smoke.slang (cpu)` failing with `Failed to load DLL "gfx"`; `ldd build/Debug/lib/libgfx.so` shows `libcuda.so.1 => not found` — environmental. Run `ldd` before naming a loader error's cause ([gfx-smoke](../learnings/1790710627405-slang-test-gfx-smoke-failed-to-load-dll-gfx-on-lin.md)).

**Contention.** Master and patched full suites run at once (`-server-count 12` each on 64 cores, plus a `-j48` build) produced 73 "patched-only" llvm/cpu failures in both directions; a serial rerun passed 130/130. Run suites serially with no build running, or rerun the set difference serially before reporting a regression. A quiet no-GPU box still leaves ~91 environmental failures (numerics 46, cuda 21, functional 12, optix 4, others); `-exclude-prefix tests/<scratch-dir>` keeps ad-hoc probes out of full runs ([no concurrent suites](../learnings/1790718692458-don-t-run-two-slang-test-full-suites-concurrently-.md)).

**Corpus A/B emit-diff: three noise controls.** Build two slangc binaries differing only in the PR's files (incremental, ~10 min), run every `//TEST:SIMPLE`/`SIMPLE_EX`/`DIAGNOSTIC_TEST:SIMPLE` directive with its own args as slang-test does (file path first unless SIMPLE_EX, `-O0` when no `-O`, `-enable-machine-readable-diagnostics` with `diag=`) plus a 7-target `-entry computeMain -stage compute` sweep, and diff stdout, stderr, exit code and any `-o` file. Then (1) use equal-length binary paths (`bse/` vs `fix/`): `-g*` SPIR-V embeds the command line, `-I "<bindir>"` included, in an `OpString`; (2) strip the new pass's `-dump-ir` section; (3) run a null control (base vs a byte-identical copy) and drop what differs there too, ~15% of the residue (module containers, separate-debug, source maps, `-embed-downstream-ir`). On #13115 that took 23,795 compiles to 9 changed files ([controls](../learnings/1792102021857-slang-corpus-a-b-emit-diff-control-for-bindir-path.md)). Rebuilding a compared binary mid-sweep gives rc=127 rows and fake diffs (129 on #13792 R2); finish first or drill in a separate worktree. CUDA/HLSL/GLSL output embeds `#line N "hlsl.meta.slang"` and absolute prelude `#include` paths: diff after `grep -vE '^\s*#line|#include "/workspace'`, or replace both worktree roots with one token (`WT`); on #14197 that took 8160 "diffs" to 35 ([normalize](../learnings/1793651642722-base-vs-head-slangc-output-corpus-normalize-worktr.md)). One `mktemp -d` per sweep. A PR changing an entry point's `IRFuncType` (e.g. `fixUpFuncType` in `EntryPointVaryingParamLegalizeContext`) also needs `-target llvm-shader-ir` (± `-g2`) and `llvm-ir`: `ensureFuncDecl` declares from `func->getDataType()` while C-like emitters print from `IRParam`s; a corrected type can drop now-unused structs from `.cu` (`-g2` keeps them), so check no dropped name is still referenced. To refute a reviewer's "this shape can reach X", put an `fprintf` counter on master's branch and compile every relevant test at default/`-O0`/`-g3`; 0 hits in 465 compiles is evidence, "I couldn't think of a producer" is not ([no mid-sweep rebuild](../learnings/1792547346513-differential-compile-sweeps-never-rebuild-a-compar.md)).

**The corpus only covers shapes it contains.** The #13115 inventory (plus a slang-test A/B on CPU/LLVM/CUDA/VK) found no pass→fail, yet two real regressions sat in the newly admitted domain — struct tables with call leaves (`{sqrt(4.0), 1u}`) or vector/matrix/`half` fields, rejected by NVRTC as `__device__` dynamic initializers. When a change widens a type or legality gate, tabulate leaf types (scalar, vector, matrix, `half`, 16/64-bit, bool, nested arrays, calls) × targets, fill every cell base vs head on the real downstream compiler (`-target ptx` for NVRTC, DXC, spirv-val), and pin each new row with a test ([shape coverage](../learnings/1792105846081-an-a-b-corpus-diff-only-covers-shapes-the-corpus-c.md)).

**A reverted patch stays in the binary until you rebuild.** On #14307 a patch A/B'd in one worktree (apply → build → run → `git checkout -- source/`) left the patched `slangc` in place; the later "master" re-run silently used it and overwrote the master evidence with passing outputs. Rebuild after every revert; check `slangc -v` and `git status` before every evidence run. Causal probe from the same chain: apply ONLY the PR's new `SLANG_RELEASE_ASSERT` hunk on master; if the crash becomes `E99997 assert failure: <file>(<line>): <cond>`, the crash path goes through the asserted shape. There the "working" control hit the assert too: the bad IR is built in every shape and only one consumer crashes (same #14307 atom).

**Two binaries in one worktree share its serialized modules.** `//TEST:COMPILE ... -o tests/**/X.slang-module` writes into the source tree, so the last binary to run owns those files; if the builds differ in IR serialization (e.g. across #13615) the other loads a foreign module and the test-server SIGSEGVs (false "fix-only" cross-module failures on slang#13681). Regenerate with each binary to diagnose; run the fix suite last, rebuild the snapshot at the merged base, or use separate worktrees ([shared .slang-module](../learnings/1792134757564-slang-test-a-b-in-one-worktree-shared-tests-slang-.md)).

## After merging master: sync submodules, then build the FULL preset

A master merge stales two things a targeted rebuild misses. **(1) Submodule pins** can move (e.g. `external/spirv-tools`, `spirv-headers`) while the checkouts stay at old SHAs (`git status` shows ` M external/...`), so the verify build tests a tree CI never builds; right after the merge run `git submodule update --init <paths>` or check `git diff --submodule=short` ([sync](../learnings/1791250506095-after-merging-origin-master-sync-submodules-before.md)); `--init --recursive` covers every path, and `git submodule status | grep '^[+-U]'` lists mismatches ([status grep](../learnings/1793871310157-a-failed-cd-x-a-b-runs-b-in-the-session-cwd-and-th.md)). **(2) Serialized standard modules.** When master bumps the IR module version, `--target slangc slang-test` leaves the std modules stale, and a full suite shows dozens of `functional/`/`numerics/` failures with `warning[E00131]: ignoring IR module version 32 ...` and `cannot open file 'slang/functional.slang'`; a full `cmake --build --preset debug` cleared 59 of 60 (gfx-smoke (cpu) fails on master too). **A sudden jump of dozens of standard-module failures after a merge means stale modules, not a regression** ([IR bump](../learnings/1791238883748-after-merging-master-that-bumps-the-ir-module-vers.md)).

A partial-target build gives the same symptom with no merge: `slangc slang-test` alone never builds `slang/functional.slang` ([partial build](../learnings/1791508327549-fresh-slang-worktree-configure-can-fetch-a-stale-s.md); its stale-`libslang-llvm.so` finding is on [Building & regression-testing Slang's LLVM path](slang-tooling-llvm-target-build.md)). `--target slangc slang-test slang-unit-test` gives ~15 false failures (`tests/dispatcher/smoke.slang`, `tests/functional/*`, gfx-smoke) needing the `slang` dispatcher, `slangi` and example programs. After a full debug build on master `7251cc60b4` on an L40S only the 3 `tests/cooperative-matrix/fp8-cuda*.slang (cuda)` tests fail (CUDA_ERROR_INVALID_PTX); otherwise compare against a base-commit run built the same way. The unit-test target is `slang-unit-test`, not `slang-unit-test-tool` ([~15 false failures](../learnings/1792550944973-slang-test-false-failures-from-a-partial-build-mis.md), #13789).
