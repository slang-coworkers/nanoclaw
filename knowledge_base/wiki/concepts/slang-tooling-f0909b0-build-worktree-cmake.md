# Slang build in worktrees: submodule init, A/B baselines, stale binaries

## TL;DR

Per-issue `git worktree` builds over a shared base clone have setup traps (10–40 min each unhandled); the CMake graph goes stale after a rebase.

- **`git worktree add` does NOT populate submodules** (nor nested ones): a missing `::` target (`SPIRV-Headers::SPIRV-Headers`) or `external/<x>` without `CMakeLists.txt` means an uninitialised submodule.
- **Before the first configure: `git -c protocol.file.allow=always submodule update --init --recursive --jobs 16`** (shared `.git/config` uses file transport, blocked by git ≥2.38; `--depth`/`--reference` don't help; fallback `GIT_CONFIG_COUNT`). Never rewrite shared URLs. Init is offline, seconds to ~1 min; submodule `origin` is the shared clone, so fetch upstream from GitHub.
- **FetchDXC 504: copy the base clone's `build/_dxc_probe/` tarball in** (SHA256-verified). **Add `-DSLANG_ENABLE_DXIL=OFF`** (or `-DSLANG_DXC_BUILD_FROM_SOURCE=OFF`) on this GLIBC 2.36 host, or configure source-builds DXC (10–30 min). More: [Slang build configuration](slang-tooling-build-configure-dxc-sanitizers.md).
- **Quick PR-head `slangc` (~5 min):** detached worktree at `pull/<N>/head`, tests/examples/gfx/rhi off, and build `slang-glslang` too or `-target spirv`/`-O1` fails rc 255 E00100 (`spirv-asm` may pass, so a target matrix lies). Works for external PRs whose fork CI isn't approved.
- **2025-era commits fail "not our ref"**: fetch each pinned SHA into `.git/modules/external/<p>`, skip WindowsToolchain.
- **After merging master: `git submodule update --init`, then build the FULL preset**; a targeted `slangc slang-test` build leaves std modules stale (`E00131`) and skips `slang/functional.slang`, `slang`, `slangi` (~15 false failures).
- **The prebuilt `slangc` can be far behind HEAD**: check `slangc -v` (configure-time); rebuild after every revert-drill — clean `git status` proves only the source.
- **A slangc/slang-test copied out of `build/Debug` is a different instrument** (prelude/OptiX resolve relative to the exe; ~31 CUDA/OptiX tests fail). Compare like-for-like with a no-change control.
- **Never run two full suites concurrently** (or beside a build), nor two cmake builds in one build dir (bogus `cc1plus` "Bus error"); separate worktrees build in parallel fine. **Don't background a build in a subagent** — detached ninja dies with its shell.
- **Corpus A/B diffs need equal-length bindirs, a stripped new-pass dump, a null control, stripped `#line`/absolute `#include`, and cover only shapes present.** Never share a `.slang-module`-writing worktree between two binaries or rebuild one mid-sweep.

## Worktree submodule init

`git worktree add` skips submodules and the base clone is `--depth 50` without `--recursive`, so every new worktree starts with empty `external/*`: configure fails (usually `non-existent target "SPIRV-Headers::SPIRV-Headers"`, plus `could not find TARGET miniz`), `cmake --build` dies `ninja: error: loading 'build-Debug.ninja'`, and `git submodule status` shows a leading `-` ([cascade](../learnings/1787176235982-git-worktrees-do-not-inherit-submodule-checkouts-i.md), [init + DXIL off](../learnings/1787824391934-slang-worktree-build-needs-submodule-init-disable-.md), [#13017](../learnings/1789394522873-fresh-slang-worktree-submodule-init-clang-format-1.md)). In the worktree, before the first configure:

```bash
git -c protocol.file.allow=always submodule update --init --recursive --jobs 16
rm -f build/CMakeCache.txt && rm -rf build/CMakeFiles   # only if a configure already ran on the empty external/
cmake --preset default
```

**Why the override.** The shared `.git/config` maps each `submodule.<path>.url` to `/workspace/agent/slang/external/<name>`, and git ≥ 2.38 blocks the file transport: a plain init fails `fatal: transport 'file' not allowed`, first on `external/WindowsToolchain` or `external/unordered_dense` ([WindowsToolchain](../learnings/1791581040071-new-git-worktree-of-workspace-agent-slang-submodul.md), [#13410](../learnings/1792241165412-new-slang-worktrees-from-the-local-clone-need-git-.md)). `--reference /workspace/agent/slang` fails "reference repository ... is shallow" ([`--reference`](../learnings/1793323215178-slang-worktree-submodules-proving-a-slang-test-gpu.md), [#14391](../learnings/1794017216504-building-a-pr-head-next-to-master-in-a-worktree-su.md), [shallow](../learnings/1792088805773-slang-worktree-submodules-reference-to-the-shallow.md)); `--depth` is ignored for local clones ([`--depth` ignored](../learnings/1793335182089-slang-worktree-submodule-init-fails-with-transport.md)). The `-c` form changes no config; reconfirmed in every report since 2026-10-29 ([reconfirmed](../learnings/1793960596905-fresh-slang-worktree-submodule-init-needs-protocol.md)); once only the `GIT_CONFIG_COUNT` env form worked, hence the fallback ([env form](../learnings/1793312277621-fresh-slang-worktree-submodule-init-fails-with-tra.md)). Never rewrite the shared URLs — the base clone and sibling worktrees read them ([shared refs](../learnings/1793301770175-worktree-refs-are-shared-reset-soft-origin-master-.md)).

**Offline and fast.** Top-level submodules clone from the local module store with no network, ~2 s to ~1 min ([~2 s](../learnings/1791200391884-slang-verify-worktrees-submodule-init-needs-protoc.md), [~5 s](../learnings/1794036034182-git-worktree-of-shared-slang-clone-submodule-file-.md), [offline](../learnings/1792661987044-slang-worktrees-submodule-init-is-offline-because-.md), [~1 min](../learnings/1793335182089-slang-worktree-submodule-init-fails-with-transport.md), [~10 s](../learnings/1792436239104-core-module-bootstrap-aborts-on-any-warning-worktr.md), [`--jobs 16`](../learnings/1792823537201-new-slang-worktree-build-submodules-need-protocol-.md), [~13 s](../learnings/1790636604671-fresh-slang-git-worktree-init-submodules-before-cm.md)); unmapped nested ones (slang-rhi's) come over https ([nested](../learnings/1793296016142-submodule-init-in-slang-worktrees-needs-protocol-f.md)). A worktree submodule's `origin` is the shared clone, so fetch upstream from GitHub: `git fetch https://github.com/shader-slang/slang-rhi.git main` ([origin = shared clone](../learnings/1793879645962-slang-worktree-submodule-init-needs-protocol-file-.md)). In one container a plain `git submodule update --init --recursive` worked (~50 s, #14407); the `-c` form costs nothing where unneeded ([plain init; seed DXC](../learnings/1794135375190-fresh-slang-worktree-init-submodules-seed-dxc-tarb.md)).

**Seed the DXC tarball when its download fails.** If configure fails in `cmake/FetchDXC.cmake` with an HTTP error (GitHub release 504), copy the tarball from the base clone's `build/_dxc_probe/` into the worktree's: FetchDXC checks its SHA256 and skips the download. Full Release then took 8 min on 64 cores (#14407) ([seed `build/_dxc_probe/`](../learnings/1794135375190-fresh-slang-worktree-init-submodules-seed-dxc-tarb.md)).

**Partial init, stale caches, alternatives.** A top-level-only init also builds (skips slang-rhi's nested submodules, dxc/llvm); shallow flags are harmless only because objects are local (a real shallow fetch gets branch tips, not pins: [CI Build: Git Checkout Depth & Submodule Pins](ci-build-git-checkout-and-submodule-pins.md)). If configure already ran on the empty `external/` ("Configuring incomplete"), clear the cache as above or `rm -rf build` — also for a worktree recreated on an existing `fix/issue-*` branch ([top-level only](../learnings/1787677680988-slang-git-worktree-needs-per-worktree-submodule-in.md)). A configure `&&`-chained behind a failed submodule step exits 1 silently with no configure.log — read the submodule log ([silent exit](../learnings/1791581040071-new-git-worktree-of-workspace-agent-slang-submodul.md)). When pins match (`git diff --quiet <base> HEAD -- external .gitmodules`), copying a populated `external/` from another worktree works (~10 min to a build, #13429) ([copy external/](../learnings/1791151479459-slang-pr-review-runner-scripts-may-lose-exec-bit-r.md)): `cp -a slang/external/. wt/external/` (no rsync) ([`cp -a`](../learnings/1792666503891-two-prs-that-add-the-same-lines-can-merge-cleanly-.md)).

**Old commits add dead pins.** On 2025-era commits (e.g. v2025.12..v2025.13), `git submodule update` fails "not our ref" for lz4, miniz, unordered_dense and glslang (local mirrors lack the SHAs; WindowsToolchain's pin is gone upstream). Fetch each pinned SHA into the shared module store from the `.gitmodules` URL, then check the dirs out (only `.git` files until then), skipping WindowsToolchain:

```bash
git --git-dir=/workspace/agent/slang/.git/modules/external/<p> fetch <upstream-url> <sha>
git submodule foreach 'git checkout -f HEAD'
```

Old trees also need `-DSLANG_ENABLE_GFX=ON` (render-test) and `slang-glslang` (else `-target spirv` can't load spirv-opt); Release `slangc` ~6 min at `-j20`. (Aside: master `-vk` misreads `column_major int` matrix buffer fields, #13446 — use float matrices.) ([2025-era](../learnings/1792191559147-building-2025-era-slang-commits-dead-submodule-pin.md))

## Building after the init

**Build cost.** On this GLIBC 2.36 host the first configure builds DXC from source (~500 MB, 10–30 min); pass `-DSLANG_ENABLE_DXIL=OFF` unless the task needs DXIL ([build configuration](slang-tooling-build-configure-dxc-sanitizers.md)), or `-DSLANG_DXC_BUILD_FROM_SOURCE=OFF` (prebuilt, no GLIBC check). On 60–64 cores, no sccache: Release `slangc` + `slang-test` (+ `render-test`) ~5–10 min (6m20s from scratch); full Release, DXIL off, ~6 min; on the L40S box `cmake --preset default` ~36 s and full Release `all` at `-j48` 288 s ([timings](../learnings/1794036034182-git-worktree-of-shared-slang-clone-submodule-file-.md)); clean debug ~1510 steps, <10 min; outlier ~30 min / 5.3 GB (#13858). **Separate** worktrees build fine in parallel (two Release `slangc` at `-j32` each ~8 min; [#14307](../learnings/1793809802346-worktree-submodules-need-protocol-file-allow-rebui.md)); two cmake builds in **one** build dir fail with a misleading `cc1plus: internal compiler error: Bus error` ([one build dir](../learnings/1793982195717-check-overlapping-in-flight-prs-by-building-them-a.md)). Five Release targets (`slangc`, `slang-test`, `slang-unit-test`, `slang-reflection-test`, `test-server`): ~10 min; `SLANG_ENABLE_TESTS` requires `SLANG_ENABLE_SLANG_RHI` (pass `=ON` explicitly on re-configure) ([#13535](../learnings/1791499534921-slang-worktree-build-slang-enable-tests-requires-s.md)). CUDA is auto-detected from `/usr/local/cuda-12.6`. `FETCH_BINARY_IF_POSSIBLE` fetches `build/Release/lib/libslang-llvm.so` (maybe an old release) — a `slangc slang-test`-only worktree needs it in `build/<cfg>/lib`; else copy it in ([Test instruments](slang-tooling-test-instruments.md)).

**Two-commit build bisect.** To confirm a code-trace regressor, build `--target slangc` at `<sha>^` (Release, LLVM/tests/examples/gfx/rhi/slangd/slangi/DXIL off; ~15 min on 64 cores), probe, then `git checkout <sha>` and rebuild: only the touched TU recompiles (13 steps, <1 min) — a built counterfactual, not "by code trace" ([bisect](../learnings/1792065111999-two-commit-build-bisect-is-cheap-when-the-suspect-.md)).

**Quick PR-head build, never on the shared checkout.** Verify a PR head (or master beside it) in its own worktree, never as a patch on the shared checkout whose `build/Release/bin/slangc` siblings use ([6 min from scratch](../learnings/1793960596905-fresh-slang-worktree-submodule-init-needs-protocol.md)). At ~5 min for init + configure + build, an external PR gets a real build and GPU slang-test while its fork CI still shows `action_required` ([external PRs](../learnings/1794036034182-git-worktree-of-shared-slang-clone-submodule-file-.md)). Recipe: `git fetch origin pull/<N>/head:refs/remotes/pr/<N>`, `git worktree add --detach <dir> pr/<N>` (one worktree per side for PR-vs-master), then the `-c` init or (PR base = main checkout's HEAD) symlink each empty `external/<sub>` to the main checkout's. Configure `-DSLANG_ENABLE_TESTS=OFF -DSLANG_ENABLE_EXAMPLES=OFF -DSLANG_ENABLE_GFX=OFF -DSLANG_ENABLE_SLANG_RHI=OFF -DSLANG_DXC_BUILD_FROM_SOURCE=OFF`; build `--preset release` for `slangc` **and** `slang-glslang` (spirv-opt/spirv-dis live there; bare `--target slangc` skips `libslang-glslang-<ver>.so`). Without it `-target spirv` (and `-O1`) exits rc 255 with E00100 "failed to load downstream compiler 'spirv-opt'" / "failed to load dynamic library 'slang-glslang-<ver>'", while `-target spirv-asm` may still succeed — a false "spirv broken on the PR head" (#12721) ([rc 255 on spirv](../learnings/1794239598486-fresh-worktree-target-slangc-alone-gives-rc-255-on.md)). ~5 min, ~4.2 GB; then `git worktree remove --force` and delete the ref ([quick build](../learnings/1792365932155-quick-pr-head-slangc-verify-build-symlink-submodul.md), [private worktree](../learnings/1793434873472-build-a-pr-head-in-a-private-worktree-init-submodu.md), [SPIR-V build](../learnings/1793463061545-fast-slangc-build-in-a-fresh-slang-pr-worktree-for.md)). Caveats: `SLANG_RUN_SPIRV_VALIDATION=1` passes bad debug info (`OpUndef`-pointer DebugValues, or ones before `DebugFunctionDefinition`; #13842/#14114) — count `DebugDeclare`/`DebugValue` per `DebugLocalVariable`; probe a shared build of unknown freshness with the newest compiler commit's test (shared Release was once stale while Debug was current); `SLANG_ASSERT=release-assert-only` lets Debug pass a debug-only assert (#13272) to show what Release emits.

**Build-subagent hazard; formatters.** A subagent that launches ninja with `&`/`nohup` and returns leaves a build that dies with its shell (#13017: returned in ~25 s). Build in the foreground or as a Bash `run_in_background` grandchild; check liveness with `pgrep -x ninja` + `readlink /proc/<pid>/cwd` (never `pgrep -f` — it matches your own argv). A `build.log` Monitor mis-fires when *configure* failed. slang-fixer formatters: `/workspace/agent/bin/shfmt`, gersemi 0.21 at `/workspace/agent/tools/gersemi-venv/bin/gersemi` (`bin/gersemi` shim broken), `/usr/bin/clang-format-17`; symlink into one PATH dir, or `pip install --user clang-format==17.0.6`. The script skips `slang-diagnostics.lua`; match its style by hand.

## A/B baselines must be like-for-like

**Relocated copies.** A `build/Debug/{bin,lib}` snapshot as master baseline differs on CUDA/PTX paths: `TestToolUtil::setSessionDefaultPreludeFromExePath` resolves `prelude/` relative to the executable (else inlines the embedded prelude, changing the `.cu`), and nvrtc's `_findOptixIncludePath` looks for `<instance>/../../../external/optix-dev/include` ("Failed to locate OptiX headers"). Under `-bindir <copy>/bin` ~31 in-tree-passing tests fail (`tests/cuda/*`, `tests/optix/*`, header-generation, some SER) ([~31 tests](../learnings/1790714053699-slang-test-from-a-bindir-binary-copy-fails-31-cuda.md)). Run both from the same kind of location with a no-change control, or rebuild the tree shape around the copy ( [`<bin>/../../..`](../learnings/1790719029887-slang-binary-copies-prelude-optix-headers-resolve-.md)) — that exposed master's own PTX failure for slang#13329. Keep scratch under `/workspace/agent/` (`/tmp` gets wiped).

```bash
mkdir -p X/build/Debug X/external
cp -al copy/bin copy/lib X/build/Debug/
ln -s <tree>/external/optix-dev X/external/optix-dev
ln -s <tree>/prelude X/prelude
```

**Missing CUDA driver.** Without an NVIDIA driver the link fails on missing `/usr/lib/x86_64-linux-gnu/libcuda.so`; reconfigure with `-DCUDA_cuda_driver_LIBRARY=/usr/local/cuda-12.6/lib64/stubs/libcuda.so` ([stub](../learnings/1790802490676-slangc-o-dev-null-fails-with-e00004-in-the-fixer-c.md)). At run time: `tests/cpu-program/gfx-smoke.slang (cpu)` fails `Failed to load DLL "gfx"` and `ldd build/Debug/lib/libgfx.so` shows `libcuda.so.1 => not found` (environmental) — run `ldd` before naming a loader error's cause ([gfx-smoke](../learnings/1790710627405-slang-test-gfx-smoke-failed-to-load-dll-gfx-on-lin.md)).

**Contention.** Master and patched full suites at once (`-server-count 12` each on 64 cores, plus a `-j48` build) gave 73 "patched-only" llvm/cpu failures both ways; a serial rerun passed 130/130. Run suites serially with no build running, or rerun the set difference serially. A quiet no-GPU box still has ~91 environmental failures (numerics 46, cuda 21, functional 12, optix 4, others); `-exclude-prefix tests/<scratch-dir>` keeps probes out ([no concurrent suites](../learnings/1790718692458-don-t-run-two-slang-test-full-suites-concurrently-.md)).

**Corpus A/B emit-diff: noise controls.** Build two slangc binaries differing only in the PR's files (incremental, ~10 min); run every `//TEST:SIMPLE`/`SIMPLE_EX`/`DIAGNOSTIC_TEST:SIMPLE` directive as slang-test does (file path first unless SIMPLE_EX, `-O0` when no `-O`, `-enable-machine-readable-diagnostics` with `diag=`) plus a 7-target compute sweep; diff stdout, stderr, exit code and `-o` files. Controls: (1) equal-length binary paths (`bse/` vs `fix/`) — `-g*` SPIR-V embeds the command line, `-I "<bindir>"` included, in an `OpString`; (2) strip the new pass's `-dump-ir` section; (3) drop what also differs in a null control (base vs byte-identical copy), ~15% of residue (module containers, separate-debug, source maps, `-embed-downstream-ir`); #13115: 23,795 compiles → 9 changed files ([controls](../learnings/1792102021857-slang-corpus-a-b-emit-diff-control-for-bindir-path.md)); (4) CUDA/HLSL/GLSL embed `#line N "hlsl.meta.slang"` and absolute prelude `#include` paths — diff after `grep -vE '^\s*#line|#include "/workspace'` or replace both worktree roots with one token (`WT`); #14197: 8160 "diffs" → 35 ([normalize](../learnings/1793651642722-base-vs-head-slangc-output-corpus-normalize-worktr.md)). Rebuilding a compared binary mid-sweep gives rc=127 rows and fake diffs (129 on #13792 R2): finish first or drill in a separate worktree, one `mktemp -d` per sweep. A PR changing an entry point's `IRFuncType` (e.g. `fixUpFuncType` in `EntryPointVaryingParamLegalizeContext`) also needs `-target llvm-shader-ir` (± `-g2`) and `llvm-ir`: `ensureFuncDecl` declares from `func->getDataType()` while C-like emitters print from `IRParam`s; a corrected type can drop now-unused structs from `.cu` (`-g2` keeps them), so check no dropped name is still referenced. To refute "this shape can reach X", add an `fprintf` counter on master and compile each relevant test at default/`-O0`/`-g3`: 0 hits in 465 compiles is evidence; "I couldn't think of a producer" is not ([no mid-sweep rebuild](../learnings/1792547346513-differential-compile-sweeps-never-rebuild-a-compar.md)).

**The corpus only covers shapes it contains.** The #13115 inventory (plus slang-test A/B on CPU/LLVM/CUDA/VK) found no pass→fail, yet two regressions sat in the newly admitted domain: struct tables with call leaves (`{sqrt(4.0), 1u}`) or vector/matrix/`half` fields, rejected by NVRTC as `__device__` dynamic initializers. When a change widens a type or legality gate, tabulate leaf types (scalar, vector, matrix, `half`, 16/64-bit, bool, nested arrays, calls) × targets, fill each cell base vs head on the real downstream compiler (`-target ptx` for NVRTC, DXC, spirv-val), and pin new rows with tests ([shape coverage](../learnings/1792105846081-an-a-b-corpus-diff-only-covers-shapes-the-corpus-c.md)).

**A reverted patch stays in the binary until you rebuild.** On #14307 a patch A/B'd in one worktree (apply → build → run → `git checkout -- source/`) left the patched `slangc`, silently used by the later "master" re-run, overwriting the master evidence. Rebuild after every revert and check `slangc -v` and `git status` before every evidence run; the version string is stamped at configure time, so a stale configure shows an old tag even after a fresh build ([PR head beside master](../learnings/1794017216504-building-a-pr-head-next-to-master-in-a-worktree-su.md)). Causal probe: apply ONLY the PR's new `SLANG_RELEASE_ASSERT` hunk on master; if the crash becomes `E99997 assert failure: <file>(<line>): <cond>`, the crash path goes through the asserted shape (there the "working" control hit it too: every shape builds the bad IR, one consumer crashes).

**Two binaries in one worktree share its serialized modules.** `//TEST:COMPILE ... -o tests/**/X.slang-module` writes into the source tree, so the last binary run owns those files; if IR serialization differs (e.g. across #13615) the other loads a foreign one and the test-server SIGSEGVs (false "fix-only" failures, slang#13681). Regenerate per binary to diagnose; run the fix suite last, rebuild the snapshot at the merged base, or use separate worktrees ([shared .slang-module](../learnings/1792134757564-slang-test-a-b-in-one-worktree-shared-tests-slang-.md)).

## After merging master: sync submodules, then build the FULL preset

A master merge stales two things a targeted rebuild misses. **(1) Submodule pins** can move (e.g. `external/spirv-tools`, `spirv-headers`) while checkouts stay at old SHAs (`git status`: ` M external/...`), so the verify build tests a tree CI never builds: `git submodule update --init <paths>` right after the merge, or check `git diff --submodule=short` ([sync](../learnings/1791250506095-after-merging-origin-master-sync-submodules-before.md)); `--init --recursive` covers every path, and `git submodule status | grep '^[+-U]'` lists mismatches ([status grep](../learnings/1793871310157-a-failed-cd-x-a-b-runs-b-in-the-session-cwd-and-th.md)). **(2) Serialized standard modules.** When master bumps the IR module version, `--target slangc slang-test` leaves std modules stale: dozens of `functional/`/`numerics/` failures with `warning[E00131]: ignoring IR module version 32 ...` and `cannot open file 'slang/functional.slang'`; a full `cmake --build --preset debug` cleared 59 of 60 (gfx-smoke (cpu) fails on master too). **Dozens of new std-module failures after a merge mean stale modules, not a regression** ([IR bump](../learnings/1791238883748-after-merging-master-that-bumps-the-ir-module-vers.md)).

A partial-target build gives the same symptom without a merge: `slangc slang-test` never builds `slang/functional.slang` ([partial build](../learnings/1791508327549-fresh-slang-worktree-configure-can-fetch-a-stale-s.md); its stale-`libslang-llvm.so` finding is on [Building & regression-testing Slang's LLVM path](slang-tooling-llvm-target-build.md)), and `--target slangc slang-test slang-unit-test` gives ~15 false failures (`tests/dispatcher/smoke.slang`, `tests/functional/*`, gfx-smoke) needing the `slang` dispatcher, `slangi` and examples. A full debug build of master `7251cc60b4` on an L40S fails only the 3 `tests/cooperative-matrix/fp8-cuda*.slang (cuda)` tests (CUDA_ERROR_INVALID_PTX); otherwise compare against a same-built base-commit run. The unit-test target is `slang-unit-test`, not `slang-unit-test-tool` ([~15 false failures](../learnings/1792550944973-slang-test-false-failures-from-a-partial-build-mis.md), #13789).
