# Slang build in worktrees: submodule init, A/B baselines, stale binaries

## TL;DR

Per-issue `git worktree` builds over a shared base clone have a few setup traps, each costing 10–40 min unhandled, and the CMake graph can go stale after a rebase.

- **`git worktree add` does NOT populate submodules** (nor nested ones): configure fails with `non-existent target "SPIRV-Headers::SPIRV-Headers"` or `external/<x> does not contain a CMakeLists.txt`.
- **Before the first configure run `git -c protocol.file.allow=always submodule update --init --recursive --jobs 16`.** The shared `.git/config` points every submodule at the base clone's local checkout, which git ≥2.38 blocks ("transport 'file' not allowed"); `--depth`/`--reference` don't help. Never rewrite the shared URLs; fallback: `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=protocol.file.allow GIT_CONFIG_VALUE_0=always`.
- **Init is offline and fast** (seconds to ~1 min; slang-rhi's nested submodules come over https). Clear a half-written cache before reconfiguring; a `&&`-chained configure stops silently. Copying `external/` from a same-pin worktree also works.
- **On this GLIBC 2.36 host add `-DSLANG_ENABLE_DXIL=OFF`** (or `-DSLANG_DXC_BUILD_FROM_SOURCE=OFF`) unless you need DXIL, or configure source-builds DXC (10–30 min). A `slangc slang-test`-only worktree also needs `libslang-llvm.so` in `build/<cfg>/lib`, or FileCheck rows report ignored.
- **A missing `::` target at configure is almost always an uninitialised nested submodule** (usually `external/spirv-tools/external/spirv-headers`).
- **Quick PR-head `slangc`:** fetch `pull/<N>/head`, `worktree add --detach`, init (or symlink empty `external/<sub>` dirs when the base is the main checkout's HEAD), configure tests/examples/gfx/rhi off, and build `slang-glslang` too, or every `-target spirv`/`-O1` compile fails with E00100 (~5 min). A clean `SLANG_RUN_SPIRV_VALIDATION=1` does not prove debug info is sane.
- **Old (2025-era) commits fail with "not our ref"**: fetch each pinned SHA from upstream into `.git/modules/external/<p>`, `foreach 'git checkout -f HEAD'`, skip WindowsToolchain; add `-DSLANG_ENABLE_GFX=ON` and `slang-glslang`.
- **After merging master: `git submodule update --init` (pins may move), then build the FULL preset.** A targeted `slangc slang-test` build leaves serialized std modules stale (`E00131`) and never builds `slang/functional.slang`, `slang` or `slangi` (~15 false failures).
- **The prebuilt `slangc` in the mounted checkout can be many commits behind HEAD** — check `slangc -v`'s `-g<sha>`. In a reused tree `-v` prints the configure-time describe and a clean `git status` proves only the source: rebuild after every revert-drill restore.
- **A slangc/slang-test copied out of `build/Debug` is a different instrument**: prelude and OptiX headers resolve relative to the exe (~31 CUDA/OptiX tests fail from a `-bindir` copy). Compare like-for-like plus a no-change control.
- **Never run baseline and candidate full suites concurrently** (or beside a build); ~91 environmental failures remain on a quiet no-GPU box. **Don't background the build in a subagent** — a detached ninja dies with its shell.
- **A corpus A/B diff needs equal-length bindirs, a stripped new-pass dump and a null control, and covers only shapes the corpus contains.** Never A/B two binaries in one worktree that writes `.slang-module` files or rebuild a compared binary mid-sweep; strip `#line`/absolute `#include` lines.
- **Configure flags, DXC-from-source, sanitizers and build costs are on [Slang build configuration](slang-tooling-build-configure-dxc-sanitizers.md).**

## Worktree submodule init: one rule, many reports

`git worktree add` checks out tracked files but not submodules, so `external/*` starts empty: `cmake --preset default` fails (most often `get_target_property() called with non-existent target "SPIRV-Headers::SPIRV-Headers"`), `cmake --build` dies with `ninja: error: loading 'build-Debug.ninja'`, and `git submodule status` shows a leading `-` per entry. The base clone is `git clone --depth 50` without `--recursive`, so every new worktree starts this way ([full external cascade](../learnings/1787176235982-git-worktrees-do-not-inherit-submodule-checkouts-i.md), [worktree init + DXIL disable](../learnings/1787824391934-slang-worktree-build-needs-submodule-init-disable-.md), [#13017 fresh worktree](../learnings/1789394522873-fresh-slang-worktree-submodule-init-clang-format-1.md)).

The current recipe, run in the worktree before the first configure:

```bash
git -c protocol.file.allow=always submodule update --init --recursive --jobs 16
rm -f build/CMakeCache.txt && rm -rf build/CMakeFiles   # only if a configure already ran on the empty external/
cmake --preset default
```

The shared `.git/config` maps each `submodule.<path>.url` to the base clone's checkout (`/workspace/agent/slang/external/<name>`), and git ≥ 2.38 blocks the file transport, so a plain init fails with `fatal: transport 'file' not allowed`, first on `external/WindowsToolchain` or `external/unordered_dense` ([WindowsToolchain first](../learnings/1791581040071-new-git-worktree-of-workspace-agent-slang-submodul.md), [#13410: unordered_dense](../learnings/1792241165412-new-slang-worktrees-from-the-local-clone-need-git-.md)); so does `--reference` ([`--reference` fails too](../learnings/1793323215178-slang-worktree-submodules-proving-a-slang-test-gpu.md)), which can also fail with "reference repository ... is shallow" ([shallow --reference](../learnings/1792088805773-slang-worktree-submodules-reference-to-the-shallow.md)). The one-command override was reconfirmed on 2026-10-31 in two PR-head worktrees ([private PR-head worktree](../learnings/1793434873472-build-a-pr-head-in-a-private-worktree-init-submodu.md), [PR-head SPIR-V worktree](../learnings/1793463061545-fast-slangc-build-in-a-fresh-slang-pr-worktree-for.md)). Never rewrite the shared URLs; the base clone and sibling worktrees read them too ([commit-split session](../learnings/1793301770175-worktree-refs-are-shared-reset-soft-origin-master-.md)). `--depth 1` is ignored for these local clones. Top-level submodules clone offline in seconds (`--jobs 16`) to ~1 min ([`-c` works, ~1 min](../learnings/1793335182089-slang-worktree-submodule-init-fails-with-transport.md), [offline](../learnings/1792661987044-slang-worktrees-submodule-init-is-offline-because-.md), [init ~10 s](../learnings/1792436239104-core-module-bootstrap-aborts-on-any-warning-worktr.md), [`--jobs 16`](../learnings/1792823537201-new-slang-worktree-build-submodules-need-protocol-.md), [init ~13 s](../learnings/1790636604671-fresh-slang-git-worktree-init-submodules-before-cm.md)); nested ones the config does not map, such as slang-rhi's, come over https ([nested over https](../learnings/1793296016142-submodule-init-in-slang-worktrees-needs-protocol-f.md)). In one 2026-10-29 session `-c` failed and the `GIT_CONFIG_COUNT` environment form (TL;DR) worked ([env form worked](../learnings/1793312277621-fresh-slang-worktree-submodule-init-fails-with-tra.md)); every later report succeeded with `-c`, so that form is the fallback.

A top-level-only init (no `--recursive`) also builds, skipping slang-rhi's nested submodules and dxc/llvm. Shallow flags are harmless only because the objects already sit in the base clone's module store; a real shallow submodule fetch gets branch tips, not pinned SHAs (see [CI Build: Git Checkout Depth & Submodule Pins](ci-build-git-checkout-and-submodule-pins.md)). A missing `::` target (e.g. `external/spirv-tools` has a SHA but its nested `external/spirv-headers` is absent) is an uninitialised submodule. If a configure already ran on the empty `external/` ("Configuring incomplete"), clear the cache as above or `rm -rf build`, also for a worktree recreated on an existing `fix/issue-*` branch ([top-level-only init](../learnings/1787677680988-slang-git-worktree-needs-per-worktree-submodule-in.md)). A configure `&&`-chained behind the submodule step exits 1 with no `configure.log`; read the submodule log first.

**Two-commit build bisect.** To confirm a code-trace regressor, put a worktree at `<sha>^`, init, configure Release with LLVM/tests/examples/gfx/rhi/slangd/slangi/DXIL off, build `--target slangc` (~15 min on 64 cores), probe, then `git checkout <sha>` and rebuild: only the touched TU recompiles (13 steps, <1 min), giving a built counterfactual instead of "by code trace" ([two-commit build bisect](../learnings/1792065111999-two-commit-build-bisect-is-cheap-when-the-suspect-.md)).

**Build cost after the init.** On this GLIBC 2.36 host the first configure builds DXC from source (~500 MB, 10–30 min) because `FetchDXC.cmake` finds the prebuilt unusable; pass `-DSLANG_ENABLE_DXIL=OFF` unless the task needs DXIL ([build configuration](slang-tooling-build-configure-dxc-sanitizers.md)), or `-DSLANG_DXC_BUILD_FROM_SOURCE=OFF`, which takes the prebuilt without the GLIBC check ([PR-head SPIR-V build](../learnings/1793463061545-fast-slangc-build-in-a-fresh-slang-pr-worktree-for.md)). On 60–64 cores: Release `slangc` + `slang-test` ~10 min; a full Release `-j 60` build with DXIL off ~6 min; five Release targets (`slangc`, `slang-test`, `slang-unit-test`, `slang-reflection-test`, `test-server`) ~10 min, where `SLANG_ENABLE_TESTS` requires `SLANG_ENABLE_SLANG_RHI` and a re-configure needs `=ON` passed explicitly ([#13535](../learnings/1791499534921-slang-worktree-build-slang-enable-tests-requires-s.md)); but a from-scratch Release `slangc` + `slang-test` on #13858 took ~30 min and 5.3 GB. A clean debug build is 1508–1511 steps in under 10 min (~1242 for `slangc` + `slang-test`, then 269 more), with `SLANG_ENABLE_CUDA=TRUE` and `SLANG_RHI_ENABLE_CUDA=ON` auto-detected from `/usr/local/cuda-12.6`. Configure's `FETCH_BINARY_IF_POSSIBLE` normally downloads `build/Release/lib/libslang-llvm.so` (possibly an old release); if missing, copy it in ([Test instruments](slang-tooling-test-instruments.md)).

**Old commits add dead pins.** Bisecting 2025-era commits (e.g. v2025.12..v2025.13), `git submodule update` fails with "not our ref" for lz4, miniz, unordered_dense and glslang: the local-mirror URLs lack the old SHAs, and WindowsToolchain's pin is gone upstream. Fetch each pinned SHA into the shared module store from the upstream URL in `.gitmodules`, then check the worktree dirs out (until then they hold only `.git` files), skipping WindowsToolchain:

```bash
git --git-dir=/workspace/agent/slang/.git/modules/external/<p> fetch <upstream-url> <sha>
git submodule foreach 'git checkout -f HEAD'
```

Old trees also need `-DSLANG_ENABLE_GFX=ON` to configure with tests (render-test) and the `slang-glslang` target for `-target spirv`, or slangc fails with "failed to load downstream compiler spirv-opt"; a Release `slangc` took ~6 min at `-j20`. (Aside: on master `-vk` reads `column_major int` matrix buffer fields incorrectly, #13446, so Vulkan layout value tests use float matrices.) ([building 2025-era commits](../learnings/1792191559147-building-2025-era-slang-commits-dead-submodule-pin.md))

**Alternatives to the init.** Copying a populated `external/` from another worktree works when its pins match (`git diff --quiet <base> HEAD -- external .gitmodules`; ~10 min to a build on #13429) ([copy external/ from a same-base worktree](../learnings/1791151479459-slang-pr-review-runner-scripts-may-lose-exec-bit-r.md)); so does `cp -a slang/external/. wt/external/` (rsync is not installed) ([`cp -a` external](../learnings/1792666503891-two-prs-that-add-the-same-lines-can-merge-cleanly-.md)).

**Quick PR-head build, without touching the shared checkout.** `git fetch origin pull/<N>/head:refs/remotes/pr/<N>`, `git worktree add --detach <dir> pr/<N>`, then the `-c` init, or, when the PR base equals the main checkout's HEAD, symlink each empty `external/<sub>` to the main checkout's copy. Configure with `-DSLANG_ENABLE_TESTS=OFF -DSLANG_ENABLE_EXAMPLES=OFF -DSLANG_ENABLE_GFX=OFF -DSLANG_ENABLE_SLANG_RHI=OFF` (plus `-DSLANG_DXC_BUILD_FROM_SOURCE=OFF` here) and build `--preset release` for `--target slangc` **and** `--target slang-glslang`: spirv-opt and spirv-dis live in slang-glslang, so without it every `-target spirv`/`spirv-asm` or `-O1` compile fails with E00100 "failed to load downstream compiler 'spirv-opt'", which looks like the fix broke everything; ~5 min and ~4.2 GB on 64 cores; `git worktree remove --force` and delete the ref afterwards ([quick PR-head build](../learnings/1792365932155-quick-pr-head-slangc-verify-build-symlink-submodul.md), [private PR-head worktree](../learnings/1793434873472-build-a-pr-head-in-a-private-worktree-init-submodu.md), [slang-glslang needed](../learnings/1793463061545-fast-slangc-build-in-a-fresh-slang-pr-worktree-for.md)). Two measurement caveats. A passing `SLANG_RUN_SPIRV_VALIDATION=1` does not catch bad debug info: DebugValues with an `OpUndef` pointer plus Deref, or placed before `DebugFunctionDefinition`, validated clean on #13842/#14114, so count `DebugDeclare`/`DebugValue` per `DebugLocalVariable` yourself ([spirv-val misses bad debug info](../learnings/1793463061545-fast-slangc-build-in-a-fresh-slang-pr-worktree-for.md)). When a shared build's freshness is unknown, run a test added by the newest compiler commit as a probe (on 2026-10-31 the shared Release build was stale while Debug was current); `SLANG_ASSERT=release-assert-only` then lets the current Debug build pass a debug-only assert, such as #13272's legalize-types assert, to show what Release would emit ([freshness probe](../learnings/1793434873472-build-a-pr-head-in-a-private-worktree-init-submodu.md)).

**Build-subagent hazard.** A subagent that launches ninja with `&`/`nohup` and returns leaves a detached build that dies with its shell; on #13017 one returned in ~25 s and kept launching background ops, risking two builds in one dir. Run the build in the foreground or as a Bash `run_in_background` grandchild, and check liveness with `pgrep -x ninja` + `readlink /proc/<pid>/cwd` (never `pgrep -f`, which matches your own argv). A Monitor grepping `build.log` mis-fires when *configure* failed, because `build.log` is never created. Incremental rebuilds take ~2–4 min. Formatter PATH gap in the slang-fixer container: shfmt `/workspace/agent/bin/shfmt`, gersemi 0.21 `/workspace/agent/tools/gersemi-venv/bin/gersemi` (the `/workspace/agent/bin/gersemi` shim is broken), clang-format `/usr/bin/clang-format-17`; symlink all three into one PATH dir, or install without admin (`python3 -m pip install --user clang-format==17.0.6`, `export PATH="$HOME/.local/bin:$PATH"`). The script skips Lua diagnostics such as `slang-diagnostics.lua`; match their style by hand.

## A/B baselines must be like-for-like: relocated copies, concurrent suites, and the missing CUDA driver

A `build/Debug/{bin,lib}` snapshot used as a master baseline behaves differently on CUDA/PTX paths. `TestToolUtil::setSessionDefaultPreludeFromExePath` resolves `prelude/` relative to the executable and otherwise inlines the embedded prelude, so the emitted `.cu` differs (`#include <optix...>` lines, `optixGet` counts); nvrtc's `_findOptixIncludePath` (`slang-nvrtc-compiler.cpp`) looks for `<instance>/../../../external/optix-dev/include`, so a copy fails every OptiX/PTX compile with "Failed to locate OptiX headers (optix.h)". Under `slang-test -bindir <copy>/bin`, ~31 tests (`tests/cuda/*`, `tests/optix/*`, header-generation, a few SER tests) fail from the copy while passing in-tree, so a copy-run baseline vs in-tree candidate diff is an artifact ([bindir copy fails ~31 tests](../learnings/1790714053699-slang-test-from-a-bindir-binary-copy-fails-31-cuda.md)). Run both from the same kind of location, add a no-change control (if it differs too, it is environmental), or recreate the tree shape around the copy ([resolve relative to `<bin>/../../..`](../learnings/1790719029887-slang-binary-copies-prelude-optix-headers-resolve-.md)):

```bash
mkdir -p X/build/Debug X/external
cp -al copy/bin copy/lib X/build/Debug/
ln -s <tree>/external/optix-dev X/external/optix-dev
ln -s <tree>/prelude X/prelude
```

That setup showed master's own PTX nvrtc failure for slang#13329. Keep scratch under `/workspace/agent/`, not `/tmp` (wiped on restart). A container with no NVIDIA driver fails the link against a missing `/usr/lib/x86_64-linux-gnu/libcuda.so`; reconfigure with `-DCUDA_cuda_driver_LIBRARY=/usr/local/cuda-12.6/lib64/stubs/libcuda.so` ([CUDA driver stub](../learnings/1790802490676-slangc-o-dev-null-fails-with-e00004-in-the-fixer-c.md)). At run time the same missing driver shows as `tests/cpu-program/gfx-smoke.slang (cpu)` failing with `Failed to load DLL "gfx"`: `libgfx.so` is built in `build/Debug/lib/`, and `ldd` on it shows `libcuda.so.1 => not found` — environmental. Run `ldd` before naming the cause of a loader error ([gfx-smoke = missing libcuda.so.1](../learnings/1790710627405-slang-test-gfx-smoke-failed-to-load-dll-gfx-on-lin.md)).

Contention also lies: master and patched full suites run at once (`-use-test-server -server-count 12` each, 64 cores, plus a `-j48` build) produced 73 "patched-only" failures across llvm/cpu tests in both directions; a serial rerun passed 130/130. Run suites serially with no build running, or rerun the set difference serially before reporting a regression. A clean serial suite on a quiet no-GPU box still leaves ~91 environmental failures (numerics 46, cuda 21, functional 12, optix 4, others), and `slang-test -exclude-prefix tests/<scratch-dir>` keeps ad-hoc probes out of full-suite runs ([no concurrent suites](../learnings/1790718692458-don-t-run-two-slang-test-full-suites-concurrently-.md)).

**A corpus A/B emit-diff needs three noise controls.** To inventory a change's side effects, build two slangc binaries differing only in the PR's files (incremental rebuild, ~10 min), run every `//TEST:SIMPLE`/`SIMPLE_EX`/`DIAGNOSTIC_TEST:SIMPLE` directive with its own args as slang-test does (file path first unless SIMPLE_EX, `-O0` when no `-O`, `-enable-machine-readable-diagnostics` with `diag=`), add a 7-target `-entry computeMain -stage compute` sweep, and diff stdout, stderr, exit code and any `-o` file. Then (1) put the binaries at equal-length paths (`bse/` vs `fix/`), because `-g*` SPIR-V embeds the command line, `-I "<bindir>"` included, in an `OpString`; (2) strip the new pass's section from `-dump-ir`; (3) run a null control (base binary vs a byte-identical copy) and drop everything differing there too, ~15% of the residue (module containers, separate-debug, source maps, `-embed-downstream-ir`). On PR #13115 that took 23,795 compiles to 9 genuinely changed files ([corpus A/B controls](../learnings/1792102021857-slang-corpus-a-b-emit-diff-control-for-bindir-path.md)). Rebuilding a compared binary mid-sweep (mutation drill, probe) gives rc=127 rows and fake diffs (129 on #13792 R2); finish first or drill in a separate worktree. CUDA/HLSL/GLSL output embeds `#line N "hlsl.meta.slang"` and absolute prelude `#include` paths, so diff after `grep -vE '^\s*#line|#include "/workspace'`, or replace both worktree roots with one token (`WT`) in the prelude includes and `-g` paths; on #14197 that took 8160 "diffs" to 35 ([normalize worktree paths](../learnings/1793651642722-base-vs-head-slangc-output-corpus-normalize-worktr.md)). One `mktemp -d` per sweep. A PR changing an entry point's `IRFuncType` (e.g. `fixUpFuncType` in the shared CUDA/CPU `EntryPointVaryingParamLegalizeContext`) also needs `-target llvm-shader-ir` (with and without `-g2`) and `llvm-ir`, since `slang-emit-llvm.cpp` `ensureFuncDecl` declares from `func->getDataType()` while C-like emitters print from `IRParam`s. A corrected func type can drop unused structs from `.cu` output (the stale type kept them alive through DCE; `-g2`'s `IRDebugFunction` keeps them), so check no dropped struct name is still referenced ([same](../learnings/1793651642722-base-vs-head-slangc-output-corpus-normalize-worktr.md)). The harness also refutes a reviewer's "this shape can reach X": put an `fprintf` counter on master's handling branch and compile every relevant test at default/`-O0`/`-g3` plus probes; 0 hits in 465 compiles is evidence, "I couldn't think of a producer" is not ([never rebuild mid-sweep](../learnings/1792547346513-differential-compile-sweeps-never-rebuild-a-compar.md)).

**The corpus only covers shapes it contains.** The #13115 inventory (~23,800 null-controlled compiles plus a slang-test A/B on CPU/LLVM/CUDA/VK) found no pass→fail, yet two real regressions sat in the newly admitted domain — struct tables with call leaves (`{sqrt(4.0), 1u}`) or vector/matrix/`half` fields, rejected by NVRTC as `__device__` dynamic initializers — which the corpus never tested. When a change widens a type or legality gate, tabulate leaf types (scalar, vector, matrix, `half`, 16/64-bit, bool, nested arrays, calls) × targets, fill every cell base vs head on the real downstream compiler (`-target ptx` for NVRTC, DXC, spirv-val), and pin each new row with a test ([corpus covers only its shapes](../learnings/1792105846081-an-a-b-corpus-diff-only-covers-shapes-the-corpus-c.md)).

**Two binaries sharing one worktree share its serialized modules.** `//TEST:COMPILE ... -o tests/**/X.slang-module` writes into the source tree, so whichever binary ran last owns those files; when the builds differ in IR serialization (after merging a master commit such as #13615), the other binary loads a foreign module and the test-server SIGSEGVs. On slang#13681 that gave false "fix-only" failures in `module-prelink-keeps-autodiff.slang.3` and `dispatch-cross-module.slang.3` (cpu). Diagnose by regenerating with each binary; fix by running the fix suite last, rebuilding the snapshot at the merged base, or separate worktrees ([shared .slang-module artifacts](../learnings/1792134757564-slang-test-a-b-in-one-worktree-shared-tests-slang-.md)).

## After merging master: sync submodules, then build the FULL preset

A master merge stales two things a targeted rebuild misses. **(1) Submodule pins.** The merge can move pins (e.g. `external/spirv-tools`, `spirv-headers`) while the checked-out submodules stay at old SHAs (`git status` shows ` M external/...`), so the verify build tests a tree CI never builds; run `git submodule update --init <paths>` (or check `git diff --submodule=short`) right after the merge ([sync submodules after merge](../learnings/1791250506095-after-merging-origin-master-sync-submodules-before.md)). (Aside from that atom: the critique gate counts only fresh `mcp__codex__codex` calls with the canonical `/codex-critique` developer-instructions; a `codex-reply` is never a round.) **(2) Serialized standard modules.** When master bumps the serialized IR module version, `--target slangc slang-test` leaves the std modules stale, and a full suite shows dozens of `functional/`/`numerics/` failures with `warning[E00131]: ignoring IR module version 32 ...` and `cannot open file 'slang/functional.slang'`; a full `cmake --build --preset debug` cleared 59 of 60 (gfx-smoke (cpu) fails on master too). **After any master merge, build the full preset before the suite; a sudden jump of dozens of standard-module failures means stale modules, not a regression** ([full build after IR version bump](../learnings/1791238883748-after-merging-master-that-bumps-the-ir-module-vers.md)).

A partial-target build gives the same symptom with no merge: building only `slangc slang-test` in a fresh worktree never builds `slang/functional.slang` ([partial build skips functional.slang](../learnings/1791508327549-fresh-slang-worktree-configure-can-fetch-a-stale-s.md); its stale-`libslang-llvm.so` finding is on [Building & regression-testing Slang's LLVM path](slang-tooling-llvm-target-build.md)). A `--target slangc slang-test slang-unit-test` build gives ~15 false failures — `tests/dispatcher/smoke.slang` ("failed to run test"), `tests/functional/*` (codegen, unsized-array, runtime-values, …) and `tests/cpu-program/gfx-smoke.slang` — which need the `slang` dispatcher, `slangi` and the example programs. After a full `cmake --build --preset debug` on master `7251cc60b4` on an L40S only the 3 `tests/cooperative-matrix/fp8-cuda*.slang (cuda)` tests fail (CUDA_ERROR_INVALID_PTX); otherwise compare against a base-commit run built the same way. The unit-test target is `slang-unit-test`, not `slang-unit-test-tool` ([~15 partial-build false failures](../learnings/1792550944973-slang-test-false-failures-from-a-partial-build-mis.md), #13789).
