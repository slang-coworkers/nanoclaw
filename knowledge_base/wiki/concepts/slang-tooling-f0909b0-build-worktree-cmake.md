# Slang build in worktrees: submodule init, A/B baselines, stale binaries

## TL;DR

Building Slang in a per-issue `git worktree` over a shared base clone has a small set of
setup traps that, unhandled, each cost 10–40 minutes — and the CMake build graph can go stale
under you after a rebase.

- **`git worktree add` does NOT populate submodules** (nor *nested* ones), so configure fails with `non-existent target "SPIRV-Headers::SPIRV-Headers"` or `external/<x> does not contain a CMakeLists.txt`. Before the first configure run `git -c protocol.file.allow=always submodule update --init --recursive --jobs 16`: the inherited shared `.git/config` points every submodule at the base clone's local checkout, which git ≥2.38 blocks ("transport 'file' not allowed"; `--depth`/`--reference` don't help). It is a one-command override, so never rewrite the shared URLs; if `-c` still fails, set `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=protocol.file.allow GIT_CONFIG_VALUE_0=always`. Top-level submodules clone offline in seconds to a minute (slang-rhi's nested ones come over https). Clear any half-written cache before reconfiguring; a `&&`-chained configure stops silently (exit 1, no configure log). Copying `external/` from a worktree with matching pins is the fallback. A worktree built with only `slangc slang-test` also needs `libslang-llvm.so` in `build/<cfg>/lib`, or its FileCheck rows report ignored. On a GLIBC 2.36 host add `-DSLANG_ENABLE_DXIL=OFF` unless you need DXIL, or the first configure source-builds DXC (10–30 min).
- **For a quick PR-head `slangc` check whose base equals the main checkout's HEAD, symlink each empty `external/<sub>` to the main checkout's copy** (or copy it: `cp -a slang/external/. wt/external/`; rsync is not installed), and build `slang-glslang` with `slangc`, or every `-target spirv` compile fails with E00100 (spirv-opt not loaded).
- **Building an old (2025-era) commit fails `git submodule update` with "not our ref"**: the local-mirror URLs lack the old SHAs and some pins are gone upstream. Fetch each pinned SHA from the `.gitmodules` upstream URL into the shared `.git/modules/external/<p>` store, `git submodule foreach 'git checkout -f HEAD'`, and skip WindowsToolchain. Old trees also need `-DSLANG_ENABLE_GFX=ON` and the `slang-glslang` target.
- **A configure that dies on a missing `::` target is almost always an uninitialised nested
  submodule, not a code error** — the nested `external/spirv-tools/external/spirv-headers` is
  the usual culprit even when the top-level shows a SHA.
- **After merging master: `git submodule update --init` (pins may have moved), then build the FULL preset** — a targeted `slangc slang-test` build leaves serialized std modules stale after an IR-module-version bump (`E00131 ignoring IR module version`, dozens of `functional/` failures that are not regressions). Even without a merge, a partial `slangc slang-test` build never builds `slang/functional.slang`, `slang` or `slangi`, so about 15 dispatcher/functional/gfx-smoke tests fail falsely.
- **The prebuilt `slangc` in the mounted checkout can be many commits behind HEAD** — check
  `slangc -v`'s `-g<sha>` and `git merge-base --is-ancestor` before trusting its emit. In a
  *reused* build tree `-v` prints the configure-time describe, and a clean `git status` proves
  only the source: a revert drill restored without a rebuild leaves the REVERTED binary. Rebuild
  after every drill restore, and before citing an old worktree's binary rebuild it or check
  the binary is newer than the last source change.
- **A slangc/slang-test copied out of `build/Debug` is a different instrument.** The prelude resolves relative to the exe (missing → the embedded prelude is inlined, changing `.cu` text) and nvrtc looks for OptiX headers at `<bin>/../../../external/optix-dev/include` (missing → every OptiX/PTX compile fails), so ~31 CUDA/OptiX/header tests fail from a `-bindir` copy. Run baseline and candidate from the same kind of location plus a no-change control, or rebuild the tree shape with hardlinks + symlinks.
- **Never run baseline and candidate full suites concurrently** (or alongside a build): contention fabricates "patched-only" failures. Run serially, or rerun the set difference serially; ~91 environmental failures remain on a quiet no-GPU box.
- **Don't background the build in a subagent** — a detached ninja dies when the subagent's
  shell exits; run in the foreground, or a `run_in_background` grandchild that survives.
- **Configure flags, DXC-from-source on old glibc, sanitizers, CMake flag scope and measured build costs are on [Slang build configuration](slang-tooling-build-configure-dxc-sanitizers.md).**
- **A corpus A/B diff needs equal-length bindirs, a stripped new-pass dump and a null control, and still only covers shapes the corpus contains** — probe a widened gate's leaf types per target directly, and never A/B two binaries in one worktree that writes `.slang-module` files. Never rebuild a compared binary mid-sweep (rc=127 rows), and strip `#line`/absolute `#include` lines before diffing.

## Worktree submodule init: one rule, many reports

`git worktree add` checks out tracked files but does **not** populate submodules: worktrees share `.git` objects, yet each needs its own submodule working tree, so a new worktree's `external/*` is empty. `cmake --preset default` then fails at configure, most often with `get_target_property() called with non-existent target "SPIRV-Headers::SPIRV-Headers"`, and `cmake --build` dies with `ninja: error: loading 'build-Debug.ninja'` because configure never generated; `git submodule status` shows a leading `-` on each uninitialized entry. The base clone is `git clone --depth 50` *without* `--recursive`, so every new worktree starts this way ([full external cascade](../learnings/1787176235982-git-worktrees-do-not-inherit-submodule-checkouts-i.md), [per-worktree init, top-level only](../learnings/1787677680988-slang-git-worktree-needs-per-worktree-submodule-in.md), [worktree init + DXIL disable](../learnings/1787824391934-slang-worktree-build-needs-submodule-init-disable-.md), [#13017 fresh worktree](../learnings/1789394522873-fresh-slang-worktree-submodule-init-clang-format-1.md)).

The current recipe, run in the worktree before the first configure:

```bash
git -c protocol.file.allow=always submodule update --init --recursive --jobs 16
rm -f build/CMakeCache.txt && rm -rf build/CMakeFiles   # only if a configure already ran on the empty external/
cmake --preset default
```

`-c protocol.file.allow=always` is needed because the base clone's shared `.git/config`, which every `git worktree add` worktree inherits, maps each `submodule.<path>.url` to the base clone's local checkout (`/workspace/agent/slang/external/<name>`), and git ≥ 2.38 blocks the file transport by default. A plain init, or one with `--reference`, fails with `fatal: transport 'file' not allowed`, first on `external/WindowsToolchain` or `external/unordered_dense`. The override lasts one command; never rewrite the shared submodule URLs, which the base clone and sibling worktrees also read. `--depth 1` is ignored for these local clones. Top-level submodules then clone offline from the base clone's checkouts, in seconds (`--jobs 16`) to about a minute; nested ones the shared config does not map, such as slang-rhi's, still come over https ([newest report: ~1 min, then a clean debug build](../learnings/1793335182089-slang-worktree-submodule-init-fails-with-transport.md), [nested slang-rhi submodules over https](../learnings/1793296016142-submodule-init-in-slang-worktrees-needs-protocol-f.md), [`--reference` fails the same way](../learnings/1793323215178-slang-worktree-submodules-proving-a-slang-test-gpu.md), [same rule from a commit-split session](../learnings/1793301770175-worktree-refs-are-shared-reset-soft-origin-master-.md), [#13410: unordered_dense](../learnings/1792241165412-new-slang-worktrees-from-the-local-clone-need-git-.md), [init ~10 s](../learnings/1792436239104-core-module-bootstrap-aborts-on-any-warning-worktr.md), [`--jobs 16`, seconds](../learnings/1792823537201-new-slang-worktree-build-submodules-need-protocol-.md), [offline via inherited URLs](../learnings/1792661987044-slang-worktrees-submodule-init-is-offline-because-.md), [WindowsToolchain first](../learnings/1791581040071-new-git-worktree-of-workspace-agent-slang-submodul.md), [init ~13 s](../learnings/1790636604671-fresh-slang-git-worktree-init-submodules-before-cm.md)). In one 2026-10-29 session the `-c` form still failed and the environment form worked: `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=protocol.file.allow GIT_CONFIG_VALUE_0=always git submodule update --init --recursive` ([`-c` failed, GIT_CONFIG_COUNT worked](../learnings/1793312277621-fresh-slang-worktree-submodule-init-fails-with-tra.md)). `--reference /workspace/agent/slang` fails for every submodule with "reference repository ... is shallow" ([--reference to the shallow base clone fails](../learnings/1792088805773-slang-worktree-submodules-reference-to-the-shallow.md)).

A top-level-only init (no `--recursive`, same override) also builds, skipping slang-rhi's nested submodules and dxc/llvm. Shallow flags are harmless here only because the objects already sit in the base clone's module store; a real shallow submodule fetch gets branch tips, not pinned SHAs (see [CI Build: Git Checkout Depth & Submodule Pins](ci-build-git-checkout-and-submodule-pins.md)). A configure that dies on a missing `::` target, e.g. `SPIRV-Headers::SPIRV-Headers` when `external/spirv-tools` shows a SHA but its nested `external/spirv-tools/external/spirv-headers` is absent, is almost always an uninitialised submodule, not a code error. If a configure already ran against the empty `external/` ("Configuring incomplete"), clear the cache as above or `rm -rf build`; the same applies to a worktree recreated on an existing `fix/issue-*` branch ([per-worktree init, top-level only](../learnings/1787677680988-slang-git-worktree-needs-per-worktree-submodule-in.md), [two-commit build bisect](../learnings/1792065111999-two-commit-build-bisect-is-cheap-when-the-suspect-.md)). A script that chains configure behind the submodule step with `&&` just exits 1 with no `configure.log`, so read the submodule log first ([silent `&&` stop](../learnings/1791581040071-new-git-worktree-of-workspace-agent-slang-submodul.md)).

**Build cost after the init.** On this GLIBC 2.36 host the first default configure still clones and builds DXC from source (~500 MB, 10–30 min), because `FetchDXC.cmake` finds the prebuilt unusable; pass `-DSLANG_ENABLE_DXIL=OFF` unless the task needs DXIL ([build configuration](slang-tooling-build-configure-dxc-sanitizers.md)). Measured on 60–64 cores: Release `slangc` + `slang-test` ~10 min, even while configure logs "building DXC from source" ([init and build times](../learnings/1790636604671-fresh-slang-git-worktree-init-submodules-before-cm.md), [#13410](../learnings/1792241165412-new-slang-worktrees-from-the-local-clone-need-git-.md)); a full Release `-j 60` build with DXIL off in about 6 min ([DXIL off, 6 min](../learnings/1792823537201-new-slang-worktree-build-submodules-need-protocol-.md)); five Release targets (`slangc`, `slang-test`, `slang-unit-test`, `slang-reflection-test`, `test-server`) in ~10 min ([#13535](../learnings/1791499534921-slang-worktree-build-slang-enable-tests-requires-s.md)); but a from-scratch Release `slangc` + `slang-test` on #13858 in about 30 min and 5.3 GB ([#13858](../learnings/1792661987044-slang-worktrees-submodule-init-is-offline-because-.md)). A clean debug build is 1508–1511 steps (about 1242 for `slangc` + `slang-test`, then 269 more for the full set), with `SLANG_ENABLE_CUDA=TRUE` and `SLANG_RHI_ENABLE_CUDA=ON` auto-detected from `/usr/local/cuda-12.6` ([1242 + 269 steps](../learnings/1793335182089-slang-worktree-submodule-init-fails-with-transport.md), [CUDA detected](../learnings/1793296016142-submodule-init-in-slang-worktrees-needs-protocol-f.md)). Configure's `FETCH_BINARY_IF_POSSIBLE` normally downloads `build/Release/lib/libslang-llvm.so`; if it is missing, copy it in or every FileCheck row reports ignored ([#13410](../learnings/1792241165412-new-slang-worktrees-from-the-local-clone-need-git-.md), [core-module bootstrap; worktree init](../learnings/1792436239104-core-module-bootstrap-aborts-on-any-warning-worktr.md)). The download can itself be an old release ([Test instruments](slang-tooling-test-instruments.md)).

**Old commits add a second submodule failure: dead pins.** When bisecting 2025-era commits (e.g. v2025.12..v2025.13), `git submodule update` fails with "not our ref" for lz4, miniz, unordered_dense and glslang, because the main clone's local-mirror URLs lack the old SHAs and WindowsToolchain's pin is gone upstream. Fetch each pinned SHA into the shared module store from the upstream URL in `.gitmodules`, then check the worktree dirs out (until then they contain only `.git` files), skipping WindowsToolchain:

```bash
git --git-dir=/workspace/agent/slang/.git/modules/external/<p> fetch <upstream-url> <sha>
git submodule foreach 'git checkout -f HEAD'
```

Old trees also need `-DSLANG_ENABLE_GFX=ON` to configure with tests (render-test), and the `slang-glslang` target for `-target spirv`, or slangc fails with "failed to load downstream compiler spirv-opt"; a Release `slangc` took about 6 min at `-j20`. (Aside from the same bisect: on master `-vk` reads `column_major int` matrix buffer fields incorrectly, #13446, so Vulkan layout value tests use float matrices.) ([building 2025-era commits: dead pins + local-mirror URLs](../learnings/1792191559147-building-2025-era-slang-commits-dead-submodule-pin.md))

**Alternatives to the init.** Copying a populated `external/` from another worktree still works when its pins match (`git diff --quiet <base> HEAD -- external .gitmodules`; ~10 min to a build on #13429) ([copy external/ from a same-base worktree](../learnings/1791151479459-slang-pr-review-runner-scripts-may-lose-exec-bit-r.md)); so does `cp -a slang/external/. wt/external/` (rsync is not installed) ([two PRs that add the same lines can merge cleanly](../learnings/1792666503891-two-prs-that-add-the-same-lines-can-merge-cleanly-.md)). **Quick PR-head verify build:** `git fetch origin pull/N/head:refs/remotes/origin/pr-N`, `git worktree add --detach`, and when the PR base equals the main checkout's HEAD, symlink each empty `external/<sub>` to the main checkout's copy instead of initializing it. Configure with `-DSLANG_ENABLE_TESTS=OFF` and build `--target slangc` **and** `--target slang-glslang`: without slang-glslang every `-target spirv` compile fails with E00100 "failed to load downstream compiler 'spirv-opt'", which looks like the fix broke everything. It takes about 5 min on 64 cores; remove the worktree and the `pr-N` ref afterwards ([quick PR-head slangc verify build](../learnings/1792365932155-quick-pr-head-slangc-verify-build-symlink-submodul.md)).

**Build-subagent hazard:** a subagent that launches ninja with `&`/`nohup` and returns leaves a *detached* build that dies when its shell exits; on #13017 one returned in ~25 s and kept launching background ops, risking two concurrent builds in one dir. Run the build yourself in the foreground or as a Bash `run_in_background` grandchild, and check liveness with `pgrep -x ninja` + `readlink /proc/<pid>/cwd` (never `pgrep -f`, which matches your own argv). A Monitor grepping `build.log` mis-fires when *configure* failed, because `build.log` is never created. An incremental rebuild after the first full build is ~2–4 min ([foreground/block the build](../learnings/1787176235982-git-worktrees-do-not-inherit-submodule-checkouts-i.md), [detached ninja dies; check pgrep -x](../learnings/1787824391934-slang-worktree-build-needs-submodule-init-disable-.md), [monitor mis-fires when configure failed](../learnings/1787677680988-slang-git-worktree-needs-per-worktree-submodule-in.md)). Formatting hits a PATH gap too: in the slang-fixer container shfmt is at `/workspace/agent/bin/shfmt`, gersemi 0.21 at `/workspace/agent/tools/gersemi-venv/bin/gersemi` (the `/workspace/agent/bin/gersemi` shim is broken) and clang-format at `/usr/bin/clang-format-17`, so symlink all three into one PATH dir ([formatter tool paths](../learnings/1792088805773-slang-worktree-submodules-reference-to-the-shallow.md)). Where they are absent, install the pinned version without admin (`python3 -m pip install --user clang-format==17.0.6`, then `export PATH="$HOME/.local/bin:$PATH"`); Lua diagnostics such as `slang-diagnostics.lua` are not formatted by the script, so match their style by hand ([fresh-worktree submodule init + clang-format-17 via pip](../learnings/1789394522873-fresh-slang-worktree-submodule-init-clang-format-1.md)).

## A/B baselines must be like-for-like: relocated copies, concurrent suites, and the missing CUDA driver

Keeping a master baseline by snapshotting `build/Debug/{bin,lib}` into a scratch directory produces a binary that behaves differently from the in-tree one on the CUDA/PTX paths. slangc's `TestToolUtil::setSessionDefaultPreludeFromExePath` resolves `prelude/` relative to the executable, and when it is not found the embedded prelude is inlined, so the emitted `.cu` text differs (including the `#include <optix...>` lines and `optixGet` counts); and nvrtc's `_findOptixIncludePath` (`slang-nvrtc-compiler.cpp`) looks for `<instance>/../../../external/optix-dev/include`, so a copy fails every OptiX/PTX compile with "Failed to locate OptiX headers (optix.h)". Run as `slang-test -bindir <copy>/bin`, about 31 tests (`tests/cuda/*`, `tests/optix/*`, `tests/headers/generate-cuh`/`hpp-header`, a few hlsl-intrinsic SER tests) fail from the copy while passing in-tree, so a "fixed vs master" diff between a copy-run baseline and an in-tree candidate is an artifact [bindir copy fails ~31 CUDA/OptiX tests](../learnings/1790714053699-slang-test-from-a-bindir-binary-copy-fails-31-cuda.md). Run baseline and candidate from the same kind of location, add a no-change control program (if it differs too, the difference is environmental), or recreate the tree shape around the copy [prelude + OptiX resolve relative to `<bin>/../../..`](../learnings/1790719029887-slang-binary-copies-prelude-optix-headers-resolve-.md):

```bash
mkdir -p X/build/Debug X/external
cp -al copy/bin copy/lib X/build/Debug/
ln -s <tree>/external/optix-dev X/external/optix-dev
ln -s <tree>/prelude X/prelude
```

That like-for-like setup showed master's own PTX nvrtc failure for slang#13329. Keep test lists
and scratch under `/workspace/agent/`, not `/tmp`, which a container restart wipes. Separately, a
container with no NVIDIA driver fails the link against a missing
`/usr/lib/x86_64-linux-gnu/libcuda.so`; reconfigure with
`-DCUDA_cuda_driver_LIBRARY=/usr/local/cuda-12.6/lib64/stubs/libcuda.so`
[CUDA driver stub](../learnings/1790802490676-slangc-o-dev-null-fails-with-e00004-in-the-fixer-c.md).

At run time the same missing driver shows up as `tests/cpu-program/gfx-smoke.slang (cpu)` failing
with `Failed to load DLL "gfx"`. `libgfx.so` is built, but it lives in `build/Debug/lib/`, not
`bin/`, and `ldd build/Debug/lib/libgfx.so` shows `libcuda.so.1 => not found`; that is an
environmental failure unrelated to any compiler change, not "no libgfx in this build". Run `ldd` on
the library before naming the cause of a loader error
[gfx-smoke = missing libcuda.so.1](../learnings/1790710627405-slang-test-gfx-smoke-failed-to-load-dll-gfx-on-lin.md).

Contention is the other way an A/B comparison lies. Running the master and patched full suites at the same time (`-use-test-server -server-count 12` each, 64 cores, with a `-j48` build also running) produced 73 "patched-only" failures across llvm/cpu tests in both directions; a serial rerun of those files passed 130/130. Run baseline and candidate suites one after another with no build running, or rerun the set difference serially before reporting any regression. A clean serial suite on a quiet no-GPU Linux box still leaves about 91 environmental failures (numerics 46, cuda 21, functional 12, optix 4, a few others), and `slang-test -exclude-prefix tests/<scratch-dir>` keeps ad-hoc probes under `tests/` out of full-suite runs [don't run two full suites concurrently](../learnings/1790718692458-don-t-run-two-slang-test-full-suites-concurrently-.md).

**A corpus A/B emit-diff needs three noise controls before its diff means anything.** To inventory a compiler change's side effects, build two slangc binaries that differ only in the PR's files (merge-base versions, incremental rebuild, ~10 min), run every `//TEST:SIMPLE`/`SIMPLE_EX`/`DIAGNOSTIC_TEST:SIMPLE` directive with its own args the way slang-test does (file path first unless SIMPLE_EX, `-O0` when no `-O`, `-enable-machine-readable-diagnostics` with `diag=`), add a 7-target `-entry computeMain -stage compute` sweep, and diff stdout, stderr, exit code and any `-o` file. Then (1) put the binaries at equal-length paths (`bse/` vs `fix/`) and normalize them, because `-g*` SPIR-V embeds the command line, `-I "<bindir>"` included, in an `OpString`; (2) strip the new pass's section from `-dump-ir` output; and (3) run a null control (the base binary against a byte-identical copy of itself) and drop everything that differs there too, about 15% of the residue (module containers, separate-debug, source maps, `-embed-downstream-ir`). On PR #13115 this took 23,795 compiles down to 9 genuinely changed files [corpus A/B emit-diff controls](../learnings/1792102021857-slang-corpus-a-b-emit-diff-control-for-bindir-path.md). The sweep adds two noise sources of its own: rebuilding a compared binary mid-sweep (a mutation drill, an instrumentation probe) gives rc=127 "missing binary" rows and fake diffs (129 on #13792 R2), so finish the sweep first or drill in a separate worktree; and CUDA/HLSL/GLSL output embeds `#line N "hlsl.meta.slang"` and absolute prelude `#include` paths, so diff after `grep -vE '^\s*#line|#include "/workspace'`. Give each sweep its own `mktemp -d` dir. The same harness refutes a reviewer's "this shape can reach X" claim: add an `fprintf` counter on master's branch that would handle the shape and compile every relevant test at default/`-O0`/`-g3` plus your probes; 0 hits in 465 compiles is evidence, "I couldn't think of a producer" is not ([differential sweeps: never rebuild mid-sweep, normalize #line](../learnings/1792547346513-differential-compile-sweeps-never-rebuild-a-compar.md)).

**The corpus only covers shapes it contains.** The same #13115 inventory (4,475 directive runs plus 19,320 runs over 2,760 files × 7 targets, null-controlled, plus a slang-test A/B on CPU/LLVM/CUDA/VK) found no pass→fail and no compile→fail, while two real regressions sat in the newly admitted domain: struct tables with call leaves (`{sqrt(4.0), 1u}`) and with vector/matrix/`half` fields, both rejected by NVRTC as `__device__` dynamic initializers, and the corpus had zero such tests. When a change widens a type or legality gate, tabulate leaf types × targets (scalar, vector, matrix, `half`, 16/64-bit, bool, nested arrays, calls), fill every cell base vs head on the real downstream compiler (`-target ptx` for NVRTC, DXC, spirv-val), and pin each new row with a test [an A/B corpus diff only covers shapes the corpus contains](../learnings/1792105846081-an-a-b-corpus-diff-only-covers-shapes-the-corpus-c.md).

**Two binaries sharing one worktree share its serialized modules.** `//TEST:COMPILE ... -o tests/**/X.slang-module` writes into the source tree, so whichever binary ran last owns those files; when the builds differ in IR serialization (after merging a master commit such as #13615), the other binary loads a foreign module and the test-server SIGSEGVs. On slang#13681 that produced false "fix-only" failures in `module-prelink-keeps-autodiff.slang.3` and `dispatch-cross-module.slang.3` (cpu). Diagnose by regenerating with each binary; fix by running the fix suite last, rebuilding the snapshot at the merged base, or using separate worktrees [shared .slang-module artifacts in one worktree](../learnings/1792134757564-slang-test-a-b-in-one-worktree-shared-tests-slang-.md).

## After merging master: sync submodules, then build the FULL preset

A `git merge origin/master` stales two things a targeted rebuild does not refresh. **(1) Submodule pins.** The merge can move pins (e.g. `external/spirv-tools`, `spirv-headers`) while the checked-out submodules stay at the old SHAs (`git status` shows ` M external/...`), so the verify build tests a tree CI will never build; run `git submodule update --init <paths>` (or check `git diff --submodule=short`) right after the merge [sync submodules after merging master](../learnings/1791250506095-after-merging-origin-master-sync-submodules-before.md). (That atom also reconfirms that the critique gate records only fresh `mcp__codex__codex` calls carrying the canonical `/codex-critique` developer-instructions; a `codex-reply` is never a round.) **(2) Serialized standard modules.** When master bumps the serialized IR module version, `--target slangc slang-test` leaves the std modules stale, and a full suite shows dozens of `functional/`/`numerics/` failures with `warning[E00131]: ignoring IR module version 32 because this compiler supports IR module versions 33 through 33` and `cannot open file 'slang/functional.slang'`; a full `cmake --build --preset debug` cleared 59 of 60 (gfx-smoke (cpu) fails on master too). **Rule: after any master merge, build the full preset before running the suite; a sudden jump of dozens of standard-module failures means stale modules, not a regression** [full build after an IR module version bump](../learnings/1791238883748-after-merging-master-that-bumps-the-ir-module-vers.md). A partial-target build gives the same symptom with no merge: building only `slangc slang-test` in a fresh worktree never builds `slang/functional.slang` ([partial-target build skips functional.slang](../learnings/1791508327549-fresh-slang-worktree-configure-can-fetch-a-stale-s.md); its stale-`libslang-llvm.so` finding is on [Building & regression-testing Slang's LLVM path](slang-tooling-llvm-target-build.md)). A `--target slangc slang-test slang-unit-test` build gives about 15 false failures: `tests/dispatcher/smoke.slang` ("failed to run test"), `tests/functional/*` (codegen, unsized-array, runtime-values, numerics-interoperability, experimental-feature-required) and `tests/cpu-program/gfx-smoke.slang`, which need the `slang` dispatcher, `slangi` and the example programs.
