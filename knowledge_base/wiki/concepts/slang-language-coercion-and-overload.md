# Slang Coercion & Overload Resolution

Coercion into generic containers and `vector<T,N>` init-lists, conversion-cost caching, and operator overload resolution (shifts, `==`, compound assignment). (Witnesses: [[wiki/concepts/slang-language-witness-and-conformance.md]]; visibility/layout/codegen: [[wiki/concepts/slang-language-visibility-and-layout.md]]; generics and inference: [[wiki/concepts/slang-language-generics-and-type-system.md]].)

## TL;DR

- **No generic type's arguments convert covariantly** (`Optional<Derived>`↛`Optional<Base>`, arrays, tuples, user generics): `_coerce` has no type-arg recursion. `Optional<opaque>` via a generic member escapes the E30902 guard (T abstract at check time, concrete only at IR specialization).
- **`canCoerce`'s two conversion-cost caches must key on every cost-relevant input.** The global `BasicTypeKey` cache drops matrix layout (layout-only overloads always ambiguous) and visible user `__implicit_conversion`s (an import or an earlier test-server test changes later picks); the per-module `TypePair` cache dropped l-value-ness (#13394). Shapes the fast-path key can't encode hit the slow path, so check that key too.
- **The core vector splat `__init<FromType>(FromType) where ToType(FromType) implicit` leaves `FromType` unbounded**, so a user `__implicit_conversion` (`float ← float3`) makes `float4 r = p3;` build `vector<float3,4>` (late E38203/E55200, #14100). Enums, `float1` and `bool` use it too, so a bound must be at least `__BuiltinScalarType`, listed directly on each base type (transitive conformance costs 1 per hop, cost precedes the prefer-implicit tie-break, and the explicit-only `__init(int)` then wins).
- **Init-list coercion into `vector<T,N>` tries ctor overload resolution FIRST**, falling back to the tail-padding reader only when no ctor matches the arg count (`{1,2,3}`→`{1,2,3,0}` vs `{1,int2(2,3)}`→`{1,1,2,3}`).
- **Coherence is per-access; heap resources cannot spell `globallycoherent`** (E31201/E30076; heap lowering attaches no `IRMemoryQualifierSetDecoration`). On SPIR-V use `loadCoherent`/`storeCoherent<4, MemoryScope::Device>(&buf[i])` with `-capability vk_mem_model` (without it E99997; other targets E36107).
- **Coherence and alignment are attributes on each load**, so a pass splitting `load(p)` into per-field loads must copy `IRAlignedAttr`/`IRMemoryScopeAttr` or refuse (as `deferBufferLoad` does); otherwise `loadCoherent(ptr).field` silently becomes a plain load.
- **Shift operands may differ in type by design**, so C-like targets must convert them. On CPU/CUDA `unifyBinaryExprOperands` splats a scalar to the OTHER operand's type (`int s >> uint3` becomes a logical shift; `int3 >> uint3` fails NVRTC/gcc). Convert to the RESULT type (#13553, PR #13562).
- **Generic `vector<T,N> ==` with `T : __BuiltinFloatingPointType`/`__BuiltinIntegerType` bound core's `IComparable` `operator==` and returned scalar `bool`** (fewer witness-upcast hops beat `OverloadRank`); since #13969 infix is per-component, but explicit `operator==(a, b)` still binds IComparable. glsl.meta.slang overloads need `import glsl` or GLSL source.
- **When a result changes from `bool` to `vector<bool,N>`, test `any(a == b)` and `all(a != b)`**: they flip, while `all(a == b)` and `any(a != b)` keep their value. Vector `?:` becomes per-component (E30056; E30055 in `[Differentiable]` code).
- **Compound assignment `x -= y` calls a function named `-=` found by lookup, never derived from `operator-`** (E39999). Only a free `T operator-=(inout T l, T r)` works (member/static/extension: E30073); `IArithmetic`/`IFloat` get no compound ops (`ILogical` gets `&= |= ^=`). The intended route is `slang.numerics`' `IAdditive` (under `-experimental-feature`).
- **An `out`/`inout` argument may differ from the parameter type only between same-size integers** (`_canLValueCoerceScalarType`); DXC converts `int` → `out float` on copy-out. IR lowering handles any pair, so relaxing it is check-side.
- **`==`/`!=` take the built-in `bool` overload whenever both operands convert implicitly to `bool`, and there is no condition-only coercion context** (`CoercionSite` has no Condition). So `Ptr` `==` across different `Ptr` parameters silently compares nullness (cost 400 < the 500 warning threshold) and structs with a cheap user `bool` conversion compare equal. Compare addresses with `uint64_t(a) == uint64_t(b)`.

## Optional<T> and Generic-Container Coercion

**`Optional<T>` covariance is unsupported**, as is covariance of any generic type's arguments, though single-value `Derived → Base` existential boxing works. `tryGetSubtypeWitness(Optional<Derived>, Optional<Base>)` is null (`T` is invariant/opaque to the facet system), and `_coerce`'s one generic-app path is an equality-modulo-witness fallback that never recurses into args (a TODO in `slang-check-inheritance.cpp`). Fixes: a bespoke `_coerce` branch for `Optional<A> → Optional<B>` gated on `tryGetSubtypeWitness(A,B)`, or a general variance model (a language-design project); csyonghe wants it, jkwak sees sugar: a maintainer decision, draft-only ([slang generic-container covariance unsupported — _coerce has no type-arg recursion (Optional Derived to Base, #7406)](../learnings/1783523269992-slang-generic-container-covariance-unsupported-coe.md)). **`Optional<opaque>` via a generic member escapes E30902**: returning `none` as `Optional<T>` from a generic struct member with T = Texture2D ICEs at SPIR-V emit (`E99997: Unhandled local inst: defaultConstruct`); a generic free function gets E30902. The three front-end sites gate on `typeTransitivelyContainsOpaqueHandle` at AST-check time, while T is abstract, and nothing re-checks after IR specialization. #9932 (DescriptorHandle, which has a representable zero) is not a dup; a bare resource has no default, so maintainers want a DIAGNOSTIC in `checkForOptionalNoneUsage` or `processMakeOptionalNone` ([slang#7878 Optional-of-opaque via generic member escapes the E30902 front-end guard](../learnings/1783523243524-slang-7878-optional-of-opaque-via-generic-member-e.md)).

## Initializer-List → Vector Coercion Routes Through Ctor Overload Resolution First

`vector<T,N>` is a core `DeclRefType<StructDecl>` with EXPLICIT composition ctors (`core.meta.slang:2777-2805`; for `vector<T,4>`: `(T,T,T,T)`, `(vec2,T,T)`, `(T,vec2,T)`, `(T,T,vec2)`, `(vec2,vec2)`, `(vec3,T)`, `(T,vec3)`, no 3-parameter ctor). `_coerceInitializerList` (`slang-check-conversion.cpp:1378`) tries ctor overload resolution first (`createInvokeExprForExplicitCtor`, :1403) and falls back to `_readAggregateValueFromInitializerList` (:998-1053, left-to-right, tail-pads with 0) only when no ctor matches the arg count (#12093): `int4 v={1,2,3}` → `{1,2,3,0}`, but `int4 v={1,int2(2,3)}` → only `(vec2,vec2)` applies and `1` splats to `int2(1,1)` (`kConversionCost_ScalarToVector=2`) → `{1,1,2,3}`. Verify GPU-free with `slangi`. Design-gated (skiminki-nv asked a semantics question; every fix changes behavior): (A) suppress the splat when a composition ctor is chosen from an init-list, (B) flatten by component count first, (C) disallow implicit under-fill. Same area as #11730 ([init-list→vector (vec2,vec2) composition ctor splats scalars, diverges from tail-pad](../learnings/1784025263407-slang-init-list-vector-vec2-vec2-composition-ctor-.md)).

## Type-modifier add/drop policy lives in `coerce`; coherence is access-based (proposal 031)

For "may modifier X be added/dropped in conversion?" (e.g. #13084, `globallycoherent` as a type modifier) the machinery exists. Type modifiers are `ModifiedType` (`slang-ast-type.h:1364`) over `TypeModifierVal`s (`UNorm`/`SNorm`/`NoDiffModifierVal`), lowered to `IRAttributedType` and peeled by reflection (no ABI surface). **`coerce` owns the policy**: its modifier block (`slang-check-conversion.cpp:1940-2036`) calls `_canModifierBeAddedDuringCoercion` (:1572) / `_canModifierBeDroppedDuringCoercion` (:1596) then `createModifierCast`; neither consults `CoercionSite`, so "explicit-only drop" is a ~1-param thread. But **coherence is access-based**: `globallycoherent` → `IRMemoryQualifierSetDecoration` on the var, which `NeedToUseCoherentLoadOrStore` walks back to at emit; for pointers the team chose per-operation `loadCoherent`/`storeCoherent` (carrying `IRMemoryScopeAttr`) and BANNED `Ptr<coherent T>` (`external/spec/proposals/031-coherent-pointer-operations-and-access.md`; type-modifier alternatives §2/§4/§5 rejected). Coherence is declaration-based on HLSL/GLSL/SPIR-V-GLSL450, per-access only on SPIR-V+VMM, and **silently dropped on Metal/WGSL/CUDA** (worth a diagnostic); a type-modifier model adds no expressiveness, and implicit "add coherence" is honorable only on SPIR-V+VMM ([Slang type-modifier coercion is the reusable hook for add/drop policy; coherence is access-based (proposal 031)](../learnings/1789753912256-slang-type-modifier-coercion-is-the-reusable-hook-.md)).

The access-based model is the only route for descriptor-heap resources (e6be8dcdd, #13440). `globallycoherent` is unspellable there: a local gives E31201 (`isModifierAllowedOnDecl`), `DescriptorHandle<globallycoherent T>` E31201 (`checkTypeModifier`; #10852 parked), a `static` global E30076. Neither `lowerDynamicResourceHeap` nor `emitDescriptorHeapLoad` attaches `IRMemoryQualifierSetDecoration`. On SPIR-V use `loadCoherent<4, MemoryScope::Device>(&buf[i])` / `storeCoherent<4, MemoryScope::Device>(&buf[j], v)` (or `__getAddress(buf[i])`) with `-capability vk_mem_model`: MakePointerVisible/Available|NonPrivatePointer, spirv-val clean on the default heap, spvDescriptorHeapEXT and DescriptorHandle fields. Without `vk_mem_model` it asserts (E99997, `slang-emit-spirv.cpp:8962`); other targets give E36107. DXC accepts the local heap form for DXIL but drops it in SPIR-V even under `-fspv-use-vulkan-memory-model` ([coherent access on a ResourceDescriptorHeap/DescriptorHandle buffer: loadCoherent/storeCoherent(&buf[i]) + vk_mem_model](../learnings/1791217879185-coherent-access-on-a-resourcedescriptorheap-descri.md)).

Since coherence and alignment live on each load (`IRMemoryScopeAttr`, `IRAlignedAttr`), a pass replacing `load(p)` + field extracts with per-member `load(fieldAddr(p, k))` must copy them or refuse; otherwise `loadCoherent<..>(ptr).field` loses `MakePointerVisible|NonPrivatePointer`. `deferBufferLoad` refuses on either (slang-ir-defer-buffer-load.cpp ~230-244). Found verifying PR #13734 (#13732); probe `uniform Big* gPtr; outb[t.x] = loadCoherent<16, MemoryScope::Device>(gPtr).b.other;` under `-target spirv-asm -capability vk_mem_model -skip-spirv-validation` and grep the `OpLoad`s. A `-DSLANG_SLANG_LLVM_FLAVOR=DISABLE` worktree silently skips FileCheck tests; copy in `libslang-llvm.so` first (see [[wiki/concepts/misc-f0909b5-verification-discipline-and-tooling.md]]) [partial-load rewrites must carry load attributes](../learnings/1792252301146-partial-load-rewrites-must-carry-load-attributes-a.md).

## Conversion-cost caches: both keys must carry every cost-relevant bit

`SemanticsVisitor::canCoerce` (slang-check-conversion.cpp ~3200) returns a cached cost *before* `toType->equals(fromType)`, so a key omitting any input `_coerce` prices reuses the first cost, exact matches included. The **linkage-global `conversionCostCache`** keys on `BasicTypeKey` (`makeBasicTypeKey`, slang-check-impl.h:171-185) for constant-shape scalars/vectors/matrices; it has an `isLValue` bit but omits `MatrixExpressionType::getLayout()`, so the first matrix cost for a shape serves every layout pair, and `pick(row_major float2x3)` + `pick(column_major float2x3)` is E39999 "ambiguous" even for an exact argument (both print as `func pick(float2x3)`). Prototype fix: `BasicTypeKey::invalid()` for a matrix with non-Unknown layout ([global conversion-cost cache key ignores matrix layout](../learnings/1790917787458-slang-s-global-conversion-cost-cache-key-ignores-m.md)). Everything else (e.g. generic `vector<…,N>`) uses the **per-module `m_typeConversionCostCache`**, keyed `TypePair{to, from}` with NO l-value bit, while `_coerce` adds `kConversionCost_LValueCast` (800) for an l-value source (flag from the *parameter*, `coerceArgToParam`), so an earlier `inout` call caches an inflated cost for later by-value calls. Regressed in v2026.1.2 (45774a4486, #9780); #13394 keys `ConversionCostKey{toType, fromType, fromIsLValue}` ([per-module key must include l-value-ness](../learnings/1790942037348-slang-conversion-cost-cache-per-module-key-must-in.md)). When a reviewer proposes "encode X into the fast-path key", check shapes it can't encode (generic params): they hit the slow path, whose key is usually the bug. Mangling (slang-mangle.cpp:217-224, #13383: layout-only overloads link to one body) and the type printer drop layout too, while `Type::equals` keeps it; check all three (redeclaration matching: [[wiki/concepts/slang-compiler-frontend-and-checking.md]]). `./extras/formatting.sh` silently skips C++ without clang-format on PATH (`PATH=/usr/lib/llvm-17/bin:$PATH`).

**A third omission: the global key ignores which user `__implicit_conversion`s are visible.** `_coerce` also prices user conversions like `extension float { __implicit_conversion(500) __init(float3 v) {…} }`, visible only to some modules, and the first cost for a pair wins for all sharing the cache, within a linkage (imports included) and across linkages, since a `Linkage` seeds from the global session (slang-global-session.cpp ~838) and `Linkage::~Linkage` (slang-session.cpp:132) replaces the global cache if its own is larger. With that extension, `h(p)` (`p : float3`; `h` on `float`/`int2`) compiles alone but fails E39999 after `import a;` brings in a module that cached `float ← float3` as Impossible, and `float4(p)` becomes `(p.x,0,0,0)` + E30081 (e8adec895, #14110) ([conversion-cost cache leaks across imported modules](../learnings/1793406048784-slang-conversion-cost-cache-leaks-across-imported-.md)). Under `-use-test-server` it crosses tests: a COMPARE_COMPUTE test relying on a user conversion between builtin basic types passes alone and fails in the suite; reproduce by copying a seeding test to a name that sorts first, `-server-count 1` (pre-existing, unfiled at 2026-10-30) ([canCoerce's basic-type cache leaks across compiles](../learnings/1793398579081-slang-cancoerce-s-basic-type-conversion-cost-cache.md)). For an order-dependent user-conversion result, try one `import` exercising the same pair before blaming the harness. The type-only `ImplicitCastMethodKey` breaks under an `if (T is I)` guard; see [[wiki/concepts/slang-language-core-f0909b0-interfaces-witness-conformance.md]].

See also [Slang core vector splat init: user implicit conversions, element-type bounds and witness-cost ranking (#14100)](../concepts/slang-language-vector-splat-init-and-generic-init-bounds.md) — the unbounded `__init<FromType>` splat, and why a transitive bound loses to an explicit-only init.

## Out-argument type mismatch: DXC converts on copy-out, Slang allows only same-size int↔int (#14112)

DXC accepts an `int` lvalue for an `out float` parameter, intrinsic or user (`int ip; modf(x, ip)`; `void g(out float)`), converting on copy-out (DXIL `fptosi`, SPIR-V `OpConvertFToS`); its table declares only `modf(float_like x, out $type1 ip)`, so this is general conversion, not an overload. Slang's `_canLValueCoerceScalarType` (`slang-check-expr.cpp` ~3910) allows `Out`/`InOutImplicitCastExpr` only between same-size integers (E39999 for generics; E30047 + E30063 with explicit type args). The limit is check-side only: `slang-ir-lower-l-value-cast.cpp` handles any pair (temp + `emitCast` copy-back). Inference leans to the OUT argument (`TryJoinTypes` uses `getConversionCost`, +800 for an l-value source), so `T f<T>(T x, out T y)` with `(float, int)` infers `T = int` [HLSL out-arg type mismatch: DXC converts on copy-out](../learnings/1793404049449-hlsl-out-arg-type-mismatch-dxc-converts-on-copy-ou.md).

## Mixed-type shift operands: unify to the result type, not the other operand (#13553)

core.meta.slang (:3309-3343) declares `vector<L,N> op(vector<L,N>, vector<R,N>)` and `op(L, vector<R,N>)`, so mixed-type `kIROp_Lsh`/`kIROp_Rsh` reach IR on purpose, with the left element type as result. Metal/WGSL adjust operands in `legalizeBinaryOp`; CPU/CUDA (preludes define only `T op(T,T)`) use `unifyBinaryExprOperands` (slang-ir-simplify-for-emit.cpp:344-406). At f6238cee3 it skips vector-by-vector shifts (`int3 >> uint3` fails NVRTC and gcc) and splats a scalar to the OTHER operand's type (:381-383): `int s = -8; s >> uint3(1)` becomes a logical `uint3` shift, so CPU returns 2147483644 and CUDA finds no matching `operator=`. C-like targets must convert both operands to the RESULT type (a two-type prelude template would not fix scalar-left). Same-type matrix shifts also fail on CPU/CUDA (no prelude matrix shift) ([mixed-type shift operands: unifyBinaryExprOperands splats to the wrong type](../learnings/1791589674979-cpu-cuda-mixed-type-shift-operands-unifybinaryexpr.md), [vector shifts must use the RESULT type (PR #13562)](../learnings/1791604848695-cpu-cuda-vector-shifts-unifybinaryexproperands-mus.md)). Side findings: `simplifyForEmit` visits only `IRFunc` bodies, so a module-scope `static const int3 K = int(-8) + V;` fails on CPU/CUDA for any op; `int8_t3(...)` of three `int8_t`s is an NVRTC "more than one make_char3" ambiguity; a narrow-type `<<` (`uint16_t3 << n`) warns E41034, breaking COMPARE_COMPUTE stderr matching, so tests use `>>` ([same](../learnings/1791604848695-cpu-cuda-vector-shifts-unifybinaryexproperands-mus.md)).

## Generic `vector<T,N> ==` binds `IComparable` and returns a scalar `bool` (#13969, #13970)

```slang
bool3 eq<T : __BuiltinFloatingPointType>(vector<T,3> a, vector<T,3> b) { return a == b; }
```

Before #13969 the fast path (`convertToBuiltinArithmeticOp`, `slang-check-expr.cpp` ~L5062) declined generic vector equality, so overload resolution chose core's `__generic<T:IComparable> [OverloadRank(-10)] bool operator==(T,T)` via vector's `IFloat`/`IInteger` → `IArithmetic` → `IComparable` witness, giving a scalar `all(__vectorEql(..))` silently splatted to `bool3`. The component-wise `[OverloadRank(10)] vector<bool,N> operator==` lost because `CompareOverloadCandidates` compares `conversionCostSum` (+1 per witness upcast hop) before `OverloadRank`: `T:__BuiltinFloatingPointType → __BuiltinType` is 5 hops vs `vector : IComparable` 2 (general rule on [[wiki/concepts/slang-language-core-f0909b0-generics-overload-inference.md]]). `T : __BuiltinArithmeticType` was already component-wise. The fast-path comment that glsl.meta.slang's vec==vec is "visible regardless of scope" is false (it needs `import glsl` or GLSL source). Bisect: broke at v2023.4.10 (#3317, `vector : IFloat`), via `gh release download <tag> -p '*linux-x86_64*'` and `-target hlsl`. To see what bound, find `lookupWitness(... IComparable ...)` + `MakeVectorFromScalar` in the first `### LOWER-TO-IR:` section of `-dump-ir`. On older releases build `bool3` per component [generic vector == binds IComparable scalar bool (witness cost beats OverloadRank)](../learnings/1793188707381-generic-vector-t-n-binds-icomparable-scalar-bool-w.md) [fast path vs overload resolution: generic vector == binds IComparable](../learnings/1793191333102-slang-fast-path-vs-overload-resolution-generic-vec.md).

**Testing the scalar-`bool` → `vector<bool,N>` change (#13970).** Uses as `bool` now error, but reductions compile and only `all(a == b)` and `any(a != b)` agree under both; `any(a == b)` (master 0 → head 1 for a=(0.1,0,0.3), b=0) and `all(a != b)` (1 → 0) silently flip, so a repro testing only the stable forms can't tell old from new. Vector `?:` now selects per component (warning E30056; error E30055 in `[Differentiable]` code). Probe each form on master and head first [test any(a==b) and all(a!=b), not all(a==b)/any(a!=b)](../learnings/1793194698608-bool-to-vector-bool-result-change-test-any-a-b-and.md).

## Compound assignment is looked up by name, never derived from the binary operator (#14038)

`x -= y` is an `InfixExpr` calling a function named `-=` found by scope lookup, never rewritten to `x = x - y`, so a type with only `operator-` gets E39999 (9b3ac252d). The only working user spelling is a free `T operator-=(inout T l, T r)`; member, static and extension operators get E30073 (#12781). `core.meta.slang` generates binary but no compound ops for `IArithmetic`/`IFloat` (open PR #12765), while `ILogical` gets `&= |= ^=`. DeepWiki's "core has `+=` for IAdditive" is only the experimental slang.numerics module (`wrappers.slang:332`). The local `external/spec` clone was stale; read upstream shader-slang/spec `expressions-operators.md` [Slang compound assignment: never derived from binary op; member operators E30073; IArithmetic has no op=](../learnings/1793296003069-slang-compound-assignment-never-derived-from-binar.md).

That module is the supported route. On master 3da6f63c0 a user `struct S3 : IAdditive` (`import slang.numerics;`) needs only `typealias Scalar = float; typealias Mask = bool3; static S3 fromScalar(float); static S3 zero(); S3 plus(S3); S3 minus(S3);`; then `x + y`, `x - y`, `x += y`, `x -= y` and prefix `+x` compile for SPIR-V (validated) and HLSL (`+=` lowers to `plus`, `-=` to `minus`), also in a generic `T : IAdditive` body. Without `-experimental-feature` the import gives E00104. `*`/`*=` need `INumeric` (`one()`, `multipliedBy`, integer construction) with one type on both sides; nothing multiplies a shaped value by a scalar. tangent-vector (maintainer) calls this interface-plus-generic-operator pattern the intended design, not compound-operator synthesis [slang.numerics IAdditive gives user structs + - += -=](../learnings/1793820752682-slang-numerics-iadditive-gives-user-structs-needs-.md).

## `==`/`!=` fall back to `bool == bool`; there is no condition coercion context (#14268, #14086)

The `Ptr` comparison operators (`core.meta.slang:1672-1694`) share one `Ptr<T, access, addrSpace, L>` for both operands. If any parameter differs (pointee, `Access`, `AddressSpace`, layout, `Ptr<void>`), inference fails and `==`/`!=` resolve to `bool == bool` via implicit `bool.__init(Ptr)` at cost 400, testing only nullness with no warning (30081 starts at 500; f1cd35ff8, L40S vk and cuda, #14268). Ordering operators give an error, since `bool` has none. The same init makes `int(p)` 0 or 1 (#14086). The declared implicit `Ptr<T>` → `Ptr<void>` (`core.meta.slang:2251-2254`) does not apply even with a known target (`Ptr<void> v = p;` is E30019), so a fix cannot use `Ptr<void>` as common type. Compare different pointers with `uint64_t(a) == uint64_t(b)`. GPU repro: `//TEST_INPUT: set ptr = ubuffer(...)` with `uniform uint* ptr;` gives a device address, and `(uint64_t)ptr` and `+16` two distinct non-null ones for COMPARE_COMPUTE on `-vk`/`-cuda` (the file must be under `tests/`; use a temporary dir and delete it) [Ptr ==/!= with mismatched Ptr params silently compares nullness](../learnings/1793744628906-slang-ptr-with-mismatched-ptr-params-silently-comp.md).

The general rule: built-in `bool operator==(bool, bool)` and `!=` are ordinary candidates, so `a == b` compiles as a `bool` comparison whenever both operands convert implicitly to `bool`: a `Ptr` at cost 400 with no warning, `uint64_t` at 900 with only E30081, and a user `extension bool { __implicit_conversion(N) __init(T) }` silently when N < 500, so two unrelated structs compare equal (`p == number` gave `1 0 1 0 0 0` on vk and cuda at 3da6f63c0, #14268). Slang has no condition-only conversion like C++ `explicit operator bool`: `checkPredicateExpr` (`slang-check-stmt.cpp:302`) uses `CoercionSite::General`; `!`, `&&`, `||` and `?:` conditions coerce as ordinary arguments (`&&`/`||` short-circuit only for `BasicExpressionType`, `convertToLogicOperatorExpr`, `slang-check-expr.cpp:5217`); `CoercionSite` (`slang-check-impl.h:498`) has no Condition value, and `ImplicitConversionModifier` stores only a cost and `builtinKind`. Without `__implicit_conversion`, `bool(x)` works but `if (x)`, `!x`, `x && y`, `x ? a : b` give E30019. A site-aware conversion must extend both cache keys: `canCoerce` (`slang-check-conversion.cpp:3228`) always passes `General` and caches by type pair, and `ImplicitCastMethodKey` has no site [no condition coercion context; == / != take the bool overload](../learnings/1793811149195-slang-has-no-condition-coercion-context-take-the-b.md).
