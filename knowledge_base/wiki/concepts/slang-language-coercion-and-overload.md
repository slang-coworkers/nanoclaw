# Slang Coercion & Overload Resolution

How Slang coerces values into generic containers (`Optional<T>` and friends) and how initializer-list coercion into a `vector<T,N>` routes through constructor overload resolution before the legacy component reader. (Witness tables and conformance live in [[wiki/concepts/slang-language-witness-and-conformance.md]]; visibility/layout/codegen surfaces live in [[wiki/concepts/slang-language-visibility-and-layout.md]]; generic specialization and inference live in [[wiki/concepts/slang-language-generics-and-type-system.md]].)

## TL;DR

- No covariant conversion of ANY generic type's arguments (`Optional<Derived>`↛`Optional<Base>`, arrays, tuples, user generics) — `_coerce` has no type-arg recursion. `Optional<opaque>` via a generic member escapes the E30902 front-end guard (T abstract at check time, concrete only at IR specialization).
- **`canCoerce`'s two conversion-cost caches must key on every cost-relevant input.** The linkage-global `BasicTypeKey` cache drops matrix layout (layout-only overloads always ambiguous); the per-module `TypePair` cache dropped l-value-ness (#13394: an earlier `inout` call poisons later by-value overload picks). Shapes the fast-path key can't encode (generic params) fall to the slow path, so check that key too. The global key also ignores which user `__implicit_conversion`s are visible, so an imported module, or an earlier test in the same test-server process, changes later overload picks.
- **The core vector splat `__init<FromType>(FromType) where ToType(FromType) implicit` leaves `FromType` unbounded**, so a user `__implicit_conversion` (`float ← float3`) makes `float4 r = p3;` build `vector<float3,4>` (late E38203/E55200, #14100). Enums, `float1` and `bool` use the same splat, so a bound must be at least `__BuiltinScalarType`, listed directly on each base type: a transitive conformance costs 1 per hop, cost is compared before the prefer-implicit tie-break, and the explicit-only `__init(int)` then wins.
- `vector<T,N>` is a struct with explicit composition ctors; init-list coercion tries ctor overload resolution FIRST, falls back to the tail-padding component reader only when no ctor matches the arg count — element count decides the path (`{1,2,3}`→`{1,2,3,0}` vs `{1,int2(2,3)}`→`{1,1,2,3}`).
- **Coherence is per-access, and heap resources cannot spell `globallycoherent`.** A `ResourceDescriptorHeap[i]`/`DescriptorHandle<T>` buffer rejects the modifier (E31201/E30076), and heap lowering never attaches `IRMemoryQualifierSetDecoration`. On SPIR-V use `loadCoherent`/`storeCoherent<4, MemoryScope::Device>(&buf[i])` with `-capability vk_mem_model` (without it: an E99997 assert; other targets: E36107).
- **An array-typed `BuiltinCast` (arrays of matrices that differ only in layout) is lowered by a dedicated pass right after `finalizeSpecialization`, not in the peephole.** The peephole runs before linking (layouts still `Unknown`) and inside generics, and handles only literal lengths, so a spec-constant-sized array ICEs at emit. Use a `MakeArray` of per-element casts for length ≤16 or at global scope, and a cached loop helper otherwise.
- **Coherence and alignment are attributes on each load, so a pass that splits `load(p)` into per-field loads must copy `IRAlignedAttr`/`IRMemoryScopeAttr` or refuse.** Otherwise `loadCoherent(ptr).field` silently becomes a plain SPIR-V load. `deferBufferLoad` refuses.
- **Shift operands may differ in type by design** (`vector<L,N> op(vector<L,N>, vector<R,N>)`, `op(L, vector<R,N>)`), so each C-like target must convert them for its output language. On CPU/CUDA, `unifyBinaryExprOperands` splats a scalar to the OTHER operand's type: `int s >> uint3` becomes a logical shift (-8>>1 = 2147483644 on CPU) and `int3 >> uint3` fails NVRTC/gcc. Convert shift operands to the RESULT type (#13553, PR #13562).
- **Generic `vector<T,N> == vector<T,N>` with `T : __BuiltinFloatingPointType`/`__BuiltinIntegerType` bound core's `IComparable` `operator==` and returned a scalar `bool`** (fewer witness-upcast hops beat `OverloadRank`); #13969 removed the fast-path decline, so infix is per-component, while explicit `operator==(a, b)` still binds IComparable. glsl.meta.slang's overloads are in scope only under `import glsl` or GLSL source.
- **When a result changes from scalar `bool` to `vector<bool,N>`, test `any(a == b)` and `all(a != b)`**: they flip, while `all(a == b)` and `any(a != b)` keep their value. Vector `?:` also changes (per-component, E30056; E30055 in `[Differentiable]` code).
- **Compound assignment `x -= y` calls a function named `-=` found by lookup; it is never derived from `operator-`.** A user type with only `operator-` gets E39999, and the only working user spelling is a free `T operator-=(inout T l, T r)`, because member, static and extension operators are rejected (E30073). `IArithmetic`/`IFloat` get no compound ops in core, while `ILogical` gets `&= |= ^=` (#14038).
- **An `out`/`inout` argument may differ from the parameter type only between same-size integers** (`_canLValueCoerceScalarType`); DXC accepts `int` → `out float` and converts on copy-out. The IR l-value-cast lowering already handles any pair, so relaxing it is a check-side change.

## Optional<T> and Generic-Container Coercion

**`Optional<T>` covariance is unsupported**, and more generally no generic type's arguments convert covariantly (Optional, arrays, tuples, user generics), even though single-value `Derived → Base` existential boxing works. `tryGetSubtypeWitness(Optional<Derived>, Optional<Base>)` returns null because `T` is invariant/opaque to the facet system, and `_coerce`'s one generic-app path is an equality-modulo-witness fallback that never recurses into the args (an acknowledged TODO in `slang-check-inheritance.cpp`). Fix menu: a bespoke `_coerce` branch for `Optional<A> → Optional<B>` gated on `tryGetSubtypeWitness(A,B)` (reuses MakeOptional/existential-boxing IR, mirrors other container coercions) vs a general per-parameter variance model (a language-design project). csyonghe wants it, jkwak sees nice-to-have sugar → maintainer-owned decision, draft-only ([slang generic-container covariance unsupported — _coerce has no type-arg recursion (Optional Derived to Base, #7406)](../learnings/1783523269992-slang-generic-container-covariance-unsupported-coe.md)). **`Optional<opaque>` via a generic member escapes E30902**: returning `none` for `Optional<T>` from a generic struct's member with T = Texture2D ICEs at SPIR-V emit (`E99997: Unhandled local inst: defaultConstruct`), while a generic free function gets E30902 cleanly. The three front-end sites are gated on `typeTransitivelyContainsOpaqueHandle`, evaluated at AST-check time while T is still *abstract*; concrete `Optional<Texture2D>` appears only at IR specialization, and nothing re-runs the check. #9932 (DescriptorHandle) is not a dup — that type has a representable zero, so its fix made it compile, whereas a bare resource has no default and maintainers want a DIAGNOSTIC; homes are `checkForOptionalNoneUsage` or `processMakeOptionalNone` (both have a sink) ([slang#7878 Optional-of-opaque via generic member escapes the E30902 front-end guard](../learnings/1783523243524-slang-7878-optional-of-opaque-via-generic-member-e.md)).

## Initializer-List → Vector Coercion Routes Through Ctor Overload Resolution First

`vector<T,N>` is a core-module `DeclRefType<StructDecl>` with EXPLICIT composition ctors (`core.meta.slang:2777-2805`; for `vector<T,4>`: `(T,T,T,T)`, `(vec2,T,T)`, `(T,vec2,T)`, `(T,T,vec2)`, `(vec2,vec2)`, `(vec3,T)`, `(T,vec3)` — NO 3-parameter ctor). `_coerceInitializerList` (`slang-check-conversion.cpp:1378`) tries ctor overload resolution FIRST (`createInvokeExprForExplicitCtor`, :1403) and falls back to `_readAggregateValueFromInitializerList` (:998-1053, left-to-right, tail-pads with 0) only when no ctor matches the arg count. So element count picks the path (#12093): `int4 v={1,2,3}` → legacy → `{1,2,3,0}`, but `int4 v={1,int2(2,3)}` → only `(vec2,vec2)` applies → `1` splats to `int2(1,1)` at `kConversionCost_ScalarToVector=2` (`slang-ast-support-types.h:172`) → `{1,1,2,3}`. Verify GPU-free with `build/Debug/bin/slangi`. Design-gated (maintainer skiminki-nv asked a semantics question; every fix changes compiling behavior): (A) suppress the splat when a composition ctor is chosen from an init-list, (B) flatten by component count before ctor resolution, (C) disallow implicit under-fill. Same area as #11730 ([init-list→vector (vec2,vec2) composition ctor splats scalars, diverges from tail-pad](../learnings/1784025263407-slang-init-list-vector-vec2-vec2-composition-ctor-.md)).

## Type-modifier add/drop policy already lives in `coerce`; coherence is access-based (proposal 031)

For "should modifier X be add/droppable during conversion?" (e.g. #13084, `globallycoherent` as a type modifier), the machinery exists. Type modifiers are `ModifiedType` (`slang-ast-type.h:1364`) wrapping a base + `TypeModifierVal` subclasses (`UNorm`/`SNorm`/`NoDiffModifierVal`, `slang-ast-val.h:1185-1213`); `_moveTypeModifiersToTypeExpr` routes them onto the type, they reach IR as `IRAttributedType` (`visitModifiedType`), and reflection peels them (`unwrapModifiedType`) — no ABI surface. **`coerce` owns the policy**: the `_coerce` modifier block (`slang-check-conversion.cpp:1940-2036`) calls `_canModifierBeAddedDuringCoercion` (:1572) / `_canModifierBeDroppedDuringCoercion` (:1596) then `createModifierCast` (unorm/snorm: freely both ways); neither consults `CoercionSite` yet, so "explicit-only drop" is a ~1-param thread. But **coherence is access-based today** for pointers and resources: `globallycoherent` → `MemoryQualifierSetModifier` → `IRMemoryQualifierSetDecoration` on the var, and each access's coherence is decided at emit by `NeedToUseCoherentLoadOrStore` walking back to it; for pointers the team deliberately chose per-operation `loadCoherent`/`storeCoherent` (carrying `IRMemoryScopeAttr`) and BANNED `Ptr<coherent T>` (`external/spec/proposals/031-coherent-pointer-operations-and-access.md`; alternatives §2/§4/§5, all type-modifier variants, rejected), so coherence-as-type-modifier runs opposite to that decision. Fulfillability is declaration-based on HLSL/GLSL/SPIR-V-GLSL450, per-access only on SPIR-V+VMM, and **silently dropped on Metal/WGSL/CUDA** (worth a diagnostic); a type-modifier model changes policy (could close that leak at coerce) but adds no expressiveness, and implicit "add coherence" is honorable only on SPIR-V+VMM ([Slang type-modifier coercion is the reusable hook for add/drop policy; coherence is access-based (proposal 031)](../learnings/1789753912256-slang-type-modifier-coercion-is-the-reusable-hook-.md)).

The access-based model is the only route for descriptor-heap resources (master e6be8dcdd, #13440). `globallycoherent` is unspellable there: a local gives E31201 (`isModifierAllowedOnDecl`), `DescriptorHandle<globallycoherent T>` E31201 (`checkTypeModifier`; #10852 parked on the resource-type refactor), a `static` global E30076. Neither `lowerDynamicResourceHeap` (default `__slang_resource_heap`) nor `emitDescriptorHeapLoad` (spvDescriptorHeapEXT) attaches `IRMemoryQualifierSetDecoration`, so `NeedToUseCoherentLoadOrStore` never fires. On SPIR-V use `loadCoherent<4, MemoryScope::Device>(&buf[i])` / `storeCoherent<4, MemoryScope::Device>(&buf[j], v)` (or `__getAddress(buf[i])`) with `-capability vk_mem_model`: MakePointerVisible/Available|NonPrivatePointer, spirv-val clean on the default heap, spvDescriptorHeapEXT and a DescriptorHandle field. Without `vk_mem_model` it hits the E99997 assert at `slang-emit-spirv.cpp:8962`; other targets give E36107. DXC accepts the local heap form and annotates DXIL, but drops it in SPIR-V even with `-fspv-use-vulkan-memory-model` ([coherent access on a ResourceDescriptorHeap/DescriptorHandle buffer: loadCoherent/storeCoherent(&buf[i]) + vk_mem_model](../learnings/1791217879185-coherent-access-on-a-resourcedescriptorheap-descri.md)).

Because coherence and alignment live on each load (`IRMemoryScopeAttr`, `IRAlignedAttr`), a pass replacing `load(p)` + field extracts with per-member `load(fieldAddr(p, k))` must copy them to every new load or refuse; otherwise `loadCoherent<..>(ptr).field` silently loses `MakePointerVisible|NonPrivatePointer`. `deferBufferLoad` refuses on either attribute (slang-ir-defer-buffer-load.cpp ~230-244). Found verifying PR #13734 (slang#13732); probe with `uniform Big* gPtr; outb[t.x] = loadCoherent<16, MemoryScope::Device>(gPtr).b.other;` under `-target spirv-asm -capability vk_mem_model -skip-spirv-validation` and grep the `OpLoad`s. A `-DSLANG_SLANG_LLVM_FLAVOR=DISABLE` worktree silently skips every FileCheck test ("FileCheck is not available") — copy `libslang-llvm.so` into `build/Release/lib` first; the general trap is on [[wiki/concepts/misc-f0909b5-verification-discipline-and-tooling.md]] [partial-load rewrites must carry load attributes](../learnings/1792252301146-partial-load-rewrites-must-carry-load-attributes-a.md).

## Conversion-cost caches: both keys must carry every cost-relevant bit (matrix layout, #13394 l-value-ness)

`SemanticsVisitor::canCoerce` (slang-check-conversion.cpp ~3200) returns a cached cost *before* reaching `toType->equals(fromType)`, so a key omitting any input `_coerce` prices on reuses the first cost computed for it, exact matches included. The **linkage-global `conversionCostCache`** keys on `BasicTypeKey` (`makeBasicTypeKey`, slang-check-impl.h:171-185) for constant-shape scalars/vectors/matrices: it has an `isLValue` bit but omits `MatrixExpressionType::getLayout()`, so the first matrix→matrix cost for a shape (e.g. `kConversionCost_MatrixLayout = 5`) serves every layout pair, and `pick(row_major float2x3)` + `pick(column_major float2x3)` is E39999 "ambiguous" even for an exact argument (both print as `func pick(float2x3)`, since `_toTextOverride` omits layout). Prototype fix: `BasicTypeKey::invalid()` for a matrix with non-Unknown layout, no regressions in the subsets run ([global conversion-cost cache key ignores matrix layout](../learnings/1790917787458-slang-s-global-conversion-cost-cache-key-ignores-m.md)). Everything else (e.g. generic `vector<…,N>`) uses the **per-module `m_typeConversionCostCache`**, keyed `TypePair{to, from}` with NO l-value bit; `_coerce` adds `kConversionCost_LValueCast` (800) for an l-value source (flag from the *parameter*, `coerceArgToParam`), so an earlier `inout` call caches an inflated cost and a later by-value call picks the wrong overload. Regressed in v2026.1.2 (45774a4486, #9780); #13394 keys on `ConversionCostKey{toType, fromType, fromIsLValue}` ([per-module key must include l-value-ness](../learnings/1790942037348-slang-conversion-cost-cache-per-module-key-must-in.md)). Two distinct omissions, not one bug. When a reviewer proposes "encode X into the fast-path key", check the shapes that *can't* be encoded (generic params) — they hit the slow path, whose key is usually the bug. Layout is also dropped by mangling (slang-mangle.cpp:217-224, #13383: layout-only overloads link to one body) and the type printer, while `Type::equals` distinguishes it — check all three; redeclaration matching is on [[wiki/concepts/slang-compiler-frontend-and-checking.md]]. `./extras/formatting.sh` silently skips C++ without clang-format on PATH (`PATH=/usr/lib/llvm-17/bin:$PATH`).

**A third omission: the global key ignores which user `__implicit_conversion`s are visible.** `_coerce` also prices user conversions such as `extension float { __implicit_conversion(500) __init(float3 v) {…} }`, visible only to some modules, and the first cost for a pair wins for everyone sharing the cache — within a linkage (imports included) and across linkages, since a `Linkage` seeds from the global session (slang-global-session.cpp ~838) and `Linkage::~Linkage` (slang-session.cpp:132) replaces the global cache if its own is larger. With that extension, `h(p)` (`p : float3`; `h` on `float`/`int2`) compiles alone but fails E39999 after `import a;` brings in a module that resolved `g(float)` vs `g(float3)` and cached `float ← float3` as Impossible; `float4(p)` becomes `(p.x,0,0,0)` + E30081 (master e8adec895, reviewing #14110) ([conversion-cost cache leaks across imported modules](../learnings/1793406048784-slang-conversion-cost-cache-leaks-across-imported-.md)). Under `slang-test -use-test-server` it crosses tests: a COMPARE_COMPUTE test relying on a user conversion between builtin basic types passes alone and fails in the suite — reproduce by copying a seeding test under a name that sorts first, `-server-count 1`; pre-existing, unfiled as of 2026-10-30 ([canCoerce's basic-type cache leaks across compiles](../learnings/1793398579081-slang-cancoerce-s-basic-type-conversion-cost-cache.md)). When a user-conversion result depends on order, try one `import` exercising the same pair before blaming the harness. The type-only `ImplicitCastMethodKey` breaks under an `if (T is I)` guard; see [[wiki/concepts/slang-language-core-f0909b0-interfaces-witness-conformance.md]].

See also [Slang core vector splat init: user implicit conversions, element-type bounds and witness-cost ranking (#14100)](../concepts/slang-language-vector-splat-init-and-generic-init-bounds.md) — the unbounded `__init<FromType>` splat, and why a transitive bound loses to an explicit-only init.

## Out-argument type mismatch: DXC converts on copy-out, Slang allows only same-size int↔int (#14112)

DXC accepts an `int` lvalue for an `out float` parameter, intrinsic or user (`int ip; modf(x, ip)`; `void g(out float)`), silently binding the float signature and converting on copy-out (DXIL `fptosi`, SPIR-V `OpConvertFToS`); its intrinsic table declares only `modf(float_like x, out $type1 ip)`, so this is general conversion, not an overload. Slang's `_canLValueCoerceScalarType` (`slang-check-expr.cpp` ~3910) allows `Out`/`InOutImplicitCastExpr` only between same-size integers: E39999 "no overload" for generics, or E30047 + E30063 with explicit type args. The restriction is check-side only — `slang-ir-lower-l-value-cast.cpp` handles any pair (temp + `emitCast` copy-back). Inference also leans to the OUT argument: `TryJoinTypes` uses `getConversionCost` (+800 for an l-value source), so `T f<T>(T x, out T y)` with `(float, int)` infers `T = int` [HLSL out-arg type mismatch: DXC converts on copy-out](../learnings/1793404049449-hlsl-out-arg-type-mismatch-dxc-converts-on-copy-ou.md).

## Array-of-matrix layout conversions are lowered after specialization (#13376)

Passing `row_major float4x4 src[N]` where `float4x4[N]` is expected yields an array-typed `kIROp_BuiltinCast`. Expanding it in `slang-ir-peephole.cpp` is the wrong layer: the peephole runs before linking (layouts `Unknown`, so identity casts become copies), runs inside generics, and expands only literal lengths, so a spec-constant-sized array ICEs at emit ("Unhandled local inst in spirv-emit"); full unrolling also bloats (`bones[256]` → 233 KB HLSL). What worked (slang-13376 eval trial, slang-eval PR #11): a pass right after `finalizeSpecialization` in `linkAndOptimizeIR`, gated by a `requiredLoweringPassSet` flag, that drops identity casts and emits a `MakeArray` of per-element `emitCast`s for length ≤16 or global scope, else a per-type-pair cached loop helper (`emitLoopBlocks`, bounded by `getElementCount()`). Details: constant-folded casts are `@ConstExpr`-rate-qualified, so read `getDataType()` not `getFullType()`; a spec-constant length is a separate `load` per array type, so length operands can't be compared by identity; `canCoerce` probing uses `CoercionSite::General`, so Argument-only rules (sized→unsized) never rank overloads; slangc defaults to column-major. Shader-slang PR #13378's `lowerArrayBuiltinCasts` hit a release assert on a 17-element module-scope `static const`; that probe lesson is on [[wiki/concepts/slang-test-false-greens-and-verification-traps.md]] [array-typed BuiltinCast must be lowered after specialization](../learnings/1792202454473-slang-array-typed-builtincast-must-be-lowered-afte.md).

## Mixed-type shift operands: unify to the result type, not the other operand (#13553)

core.meta.slang (:3309-3343) declares `vector<L,N> op(vector<L,N>, vector<R,N>)` and `op(L, vector<R,N>)`, so mixed-type `kIROp_Lsh`/`kIROp_Rsh` reach IR on purpose, with the left operand's element type as result. Metal/WGSL adjust operands in `legalizeBinaryOp`; CPU/CUDA, whose preludes define only `T op(T,T)`, use `unifyBinaryExprOperands` (slang-ir-simplify-for-emit.cpp:344-406, run at slang-emit.cpp:3051). At f6238cee3 it skips vector-by-vector shifts (`int3 >> uint3` fails NVRTC and gcc) and splats a scalar into the OTHER operand's type (:381-383): `int s = -8; s >> uint3(1)` becomes a logical `uint3` shift, so CPU returns 2147483644 and CUDA finds no matching `operator=`. Rule for C-like targets: convert both operands to the RESULT type (a two-type prelude template would not fix scalar-left). Same-type matrix shifts also fail on CPU/CUDA — no prelude matrix shift ([mixed-type shift operands: unifyBinaryExprOperands splats to the wrong type](../learnings/1791589674979-cpu-cuda-mixed-type-shift-operands-unifybinaryexpr.md), [vector shifts must use the RESULT type (PR #13562)](../learnings/1791604848695-cpu-cuda-vector-shifts-unifybinaryexproperands-mus.md)). Side findings: `simplifyForEmit` visits only `IRFunc` bodies, so a module-scope `static const int3 K = int(-8) + V;` fails on CPU/CUDA for any binary op (pre-existing); `int8_t3(int8_t(x), int8_t(y), int8_t(100))` is an NVRTC "more than one make_char3" ambiguity on master; a narrow-type `<<` (`uint16_t3 << n`) emits warning E41034, breaking COMPARE_COMPUTE stderr matching, so regression tests use `>>` ([same](../learnings/1791604848695-cpu-cuda-vector-shifts-unifybinaryexproperands-mus.md)).

## Generic `vector<T,N> ==` binds `IComparable` and returns a scalar `bool` (#13969, #13970)

```slang
bool3 eq<T : __BuiltinFloatingPointType>(vector<T,3> a, vector<T,3> b) { return a == b; }
```

Before #13969 the builtin-operator fast path (`convertToBuiltinArithmeticOp`, `slang-check-expr.cpp` ~L5062) declined generic vector equality, so `==`/`!=` went to overload resolution, where core's `__generic<T:IComparable> [OverloadRank(-10)] bool operator==(T,T)` (~:3650) won via vector's `IFloat`/`IInteger` → `IArithmetic` → `IComparable` witness, giving a scalar `all(__vectorEql(..))` silently splatted to `bool3`. The component-wise `[OverloadRank(10)] vector<bool,N> operator==` lost because `CompareOverloadCandidates` compares `conversionCostSum` (+1 per witness upcast hop) before `OverloadRank`: `T:__BuiltinFloatingPointType → __BuiltinType` is 5 hops vs `vector : IComparable` 2 (general rule on [[wiki/concepts/slang-language-core-f0909b0-generics-overload-inference.md]]). `T : __BuiltinArithmeticType` was already component-wise. The fast-path comment that glsl.meta.slang's vec==vec overload is "visible regardless of scope" is false — it loads only via `import glsl` or GLSL source (where `all(equal(..))` binds). Bisect: broke at v2023.4.10 (#3317, `vector : IFloat`), via `gh release download <tag> -R shader-slang/slang -p '*linux-x86_64*'` and `-target hlsl`. To see what bound, read the first `### LOWER-TO-IR:` section of `slangc -dump-ir` for `lookupWitness(... IComparable ...)` + `MakeVectorFromScalar`. Since #13969 infix `a == b` is per-component; explicit `operator==(a, b)` still takes IComparable; on older releases build `bool3` per component [generic vector == binds IComparable scalar bool (witness cost beats OverloadRank)](../learnings/1793188707381-generic-vector-t-n-binds-icomparable-scalar-bool-w.md) [fast path vs overload resolution: generic vector == binds IComparable](../learnings/1793191333102-slang-fast-path-vs-overload-resolution-generic-vec.md).

**Testing the scalar-`bool` → `vector<bool,N>` change (#13970).** Uses as `bool` now error, but reductions still compile and only two keep their value: `all(a == b)` and `any(a != b)` agree under both meanings, while `any(a == b)` (master 0 → head 1 for a=(0.1,0,0.3), b=0) and `all(a != b)` (1 → 0) silently flip — a repro testing only the stable forms can't tell old from new. Vector `?:` now selects per component with warning E30056, a hard E30055 in `[Differentiable]` code. Probe each form on master and head builds before calling the break "documented" [test any(a==b) and all(a!=b), not all(a==b)/any(a!=b)](../learnings/1793194698608-bool-to-vector-bool-result-change-test-any-a-b-and.md).

## Compound assignment is looked up by name, never derived from the binary operator (#14038)

`x -= y` is an `InfixExpr` calling a function named `-=` found by scope lookup; the checker never rewrites it to `x = x - y`, so a type with only `operator-` gets E39999 (master 9b3ac252d). The only working user spelling is a free `T operator-=(inout T l, T r)`; member, static and extension operators get E30073 (#12781). `IArithmetic` doesn't help: `core.meta.slang` generates binary but no compound ops for `IArithmetic`/`IFloat` (open PR #12765), while `ILogical` gets `&= |= ^=`. DeepWiki's "core has `+=` for IAdditive" is only the experimental slang.numerics module (`wrappers.slang:332`). The local `external/spec` clone was stale (June 2026) — read operator rules from upstream shader-slang/spec `expressions-operators.md` [Slang compound assignment: never derived from binary op; member operators E30073; IArithmetic has no op=](../learnings/1793296003069-slang-compound-assignment-never-derived-from-binar.md).
