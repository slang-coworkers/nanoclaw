# Slang Parameter Binding and Layout

## TL;DR
- `vk::binding` entry-point predicates must match the binder's layout-kind contract (#11861/#11857); use one **shared predicate**, not single-kind guards.
- `validateEntryPoint` checks each SV in isolation; #6319 (exact duplicate) and #11863 (overlap) are complementary. A duplicate-SV key needs the output binding space (classic empty, mesh CATEGORY, geometry STREAM).
- E38052 (VS without SV_Position) is an **intentional false-positive** (`-warnings-disable 38052`); `SV_Target<N>`'s `index` is set in **TWO** places.
- GLSL varying layout gives 64-bit 3/4-vectors one Location instead of two (#13427); fix `GetVectorLayout` AND the hull patch-constant IR layout.
- WGSL/Metal varying-location bugs are one family fixed by open PR #13736 (+ umbrella #13892) — check it before dispatching a fixer; the WGSL emitter reads semantic indices, not layout offsets.
- Layout POLICY is written **twice** (`slang-type-layout.cpp`, `slang-ir-layout.cpp`; no shared code, not 1:1). SPIR-V decorations use the **IR path**, not reflection `IRTypeLayout`. A reflection-affecting layout attribute needs one target gate in both engines: `[vk::offset]` was IR-only and applied off-Vulkan; PR #14108 gates it to `isKhronosTarget`.
- Type-level alignment: `alignas` on CUDA/C++/Metal, explicit offsets on SPIR-V, `@align` on WGSL; GLSL `align` block-only; HLSL none.
- Each entry point's `uniform` params form a PushConstant block at Offset 0 (#9643), aliasing under VK_EXT_descriptor_heap; share one `[[vk::push_constant]]` struct, or `[vk::offset]` a struct param's first field.
- IR rule `Natural` shares user `ScalarDataLayout`'s op, so a per-target scalar change hits natural buffers unless a separate op is added; concrete `sizeof`/`alignof` are target-independent.
- Natural layout is computed twice (concrete `sizeof` in `ASTNaturalLayoutContext`, generic `sizeof(T)` in IR); they disagree on `bool` (1 vs 4) and, before #13864, statics (use `MemberFilterStyle::Instance`). Compare `sizeof(S)` with `gsz<S>()`. Buffer `bool` is 4 bytes on HLSL/SPIR-V/GLSL/WGSL, 1 on Metal/CUDA/CPU/C layout; CPU/CUDA byte-address bools: 4-byte stride, 1-byte `Load<bool>`.
- `static_assert` is IR-evaluated: it accepts `sizeof(X, Std430DataLayout)` but cannot prove a front-end fold; pin that with `SizeTag<sizeof(S)>` (E30019).
- Natural layout already rounds array strides; only a nested struct shifting later fields tests rounding. `LoadAligned` promises must be powers of two (E41301).
- On CPU/CUDA varying rules ARE uniform rules: a global `in`/`out` takes uniform bytes and `GlobalParams` must collect it. A global's layout field key is the var, not a load.
- E31215 checks only EXPLICIT `ConstantBuffer`/`ParameterBlock`: unsized `uniform T x[]` in implicit Global/EntryPointParams gets infinite size (VUID-04680, #13530); no classifier answers "carries uniform bytes?" `GLSLBufferModifier` has no producer; guards on it are dead code.
- Bitfield packing is fixed at check time and baked into modules; zero-width fields open the next backing (MSB-first getter reads -1). Oracle: `-target cpp` + g++ `ms_struct`.
- Reflection lays pointer POINTEES out with scalar rules on every target (`_createTypeLayout`'s PtrTypeBase branch), so `-reflection-json` contradicts CUDA native-vector emit — one JSON, two layouts for the same struct (#14040).

## `vk::binding` Parameter-Binding Predicates

Regressions from #11712 cluster in `slang-parameter-binding`: the `vk::binding` entry-point predicate keys off an AST type that must match the binder's layout-kind contract ([predicate must match the layout-kind contract](../learnings/1782864612564-vk-binding-entry-point-diagnostic-predicate-ast-ty.md)); it misfires on a struct-of-resources entry param (#11861, mirroring #11857) ([#11861 mirrors #11857](../learnings/1782871594193-slang-11861-vk-binding-on-struct-of-resources-entr.md)). Single-kind exclusion guards (e.g. `InputAttachmentIndex` falsely reserving set 0) are correct but fragile; reviewers ask for one predicate covering all non-descriptor-set kinds ([single-kind guards are fragile](../learnings/1782879563848-single-kind-exclusion-guards-in-slang-parameter-bi.md)).

## `validateEntryPoint` System-Value Validation

`validateEntryPoint`/`validateSystemValueSemantic` (`slang-check-shader.cpp`) check each SV in isolation; neither duplicate check subsumes the other: #6319 is an **exact duplicate** (same SV name+index+direction on 2+ params); PR #11863 handles **overlap** (distinct depth-output names lowering to one builtin). A #6319 PR textually conflicts with #11863's aggregation block — coordinate the diagnostic code ([#6319 vs #11863 complementary](../learnings/1782900707997-slang-6319-dedup-pr-11863-is-related-not-duplicate.md)).

A duplicate-SV diagnostic is for **system values only** (post-linking `fixFieldSemanticsOfFlatStruct` legitimately re-indexes overlapping *user* semantics). The hard part is the key's **output binding space**: empty for classic stages, output CATEGORY for mesh, STREAM PARAMETER for geometry. Landmine: `inout TriangleStream<T>` is double-collected → spurious self-collision unless the InOut branch skips output-only-by-type params ([output-binding-space keying + inout-stream hazard](../learnings/1782911038880-entry-point-duplicate-system-value-check-output-bi.md)).

E38052 "vertex shader has no output with SV_Position" (PR #10971) is an **intentional heuristic false-positive**: gated only on `stage == Vertex`, its comment names VS→GS/tess/mesh as legitimate-but-undetected and `-warnings-disable 38052` is documented ([E38052 intentional false-positive](../learnings/1782910937014-e38052-vs-missing-sv-position-is-an-intentional-he.md)).

**An outer (function-level) semantic silently clobbers a result-struct's field semantics (#14489).** `processEntryPointVaryingParameterDecl` (`slang-parameter-binding.cpp` ~2174) implements "outer-most semantic wins"; for an entry-point RESULT, `decl` is the *function*, so a function-level `: SV_Target` becomes `state.optSemanticName` and the guard at ~2221 skips EVERY struct field's own semantic — `depth : SV_Depth` ends up laid out as `systemValueSemantic("SV_Target", 1)` with no diagnostic; neither validator checks for a redundant return-level `SV_Target` when a field already carries one. Triage gotcha: the IR struct KEY decorations still say `SV_Depth` in `-dump-ir` at every stage — the loss is in the final LAYOUT only (read the `AFTER checkUnsupportedInst` `structFieldLayout` block); SPIR-V shows `Location 1` instead of `BuiltIn FragDepth` ([outer semantic clobbers entry fields — check final layout, not key decorations](../learnings/1794815615771-slang-14489-outer-semantic-silently-clobbers-entry.md); [redundant SV_Target on a struct return is silently accepted](../learnings/1794815315476-slang-14489-redundant-sv-target-on-a-struct-return.md)). Workaround: omit the function-level `: SV_Target`. Repro notes: rebuild slangc first (`-v` is configure-time stale — use `git describe`); text targets need `-entry main` before `-o` (E00070).

## Varying Locations

Deriving a fragment `SV_Target<N>`'s `layout(location=N)` from the render-target index (#11944) means patching **both** places in `slang-parameter-binding.cpp` that set the VarLayout resource `index` ([SV_Target fix in TWO places](../learnings/1783263604045-sv-target-location-fix-lives-in-two-places-in-slan.md)).

64-bit vectors get too few Locations (#13427). `DefaultVaryingLayoutRulesImpl::GetVectorLayout` (`slang-type-layout.cpp:1035-1045`), inherited by `GLSLVaryingLayoutRulesImpl`, ignores the element type: every vector is one Location. Vulkan needs two for `double3/4`, `int64_t3`, `uint64_t4`; arrays and matrices inherit the undercount (`double4x4` gets 4, not 8). Overriding `GetVectorLayout` in the GLSL varying rules (>16 bytes → 2) fixes every front-end shape and reflection, leaves HLSL unchanged, but misses the hull patch-constant OUTPUT path: `createPatchConstantFuncResultTypeLayout` (`slang-ir-glsl-legalize.cpp`) builds its own IR layout, so hull and domain disagree. Oracle: DXC `-spirv` [64-bit varying Location counts](../learnings/1791134194001-vulkan-64-bit-varying-location-counts-slang-glsl-v.md).

WGSL/Metal varying-location bugs are one family: before dispatching a fixer chain, check open PR #13736 (plus umbrella #13892) — its branch (94c49ee97, verified 2026-11-18) fixes the whole set: WGSL `@location` reordering, ignored `[vk::location]`, nested-varying layout drops, and Metal `lowerOutParameters` layout staleness. Root cause: the WGSL legalizer collapses all user semantics to one name `user_semantic` (`slang-ir-legalize-varying-params.cpp:5433`), so suffix-derived indices collide and get first-fit renumbered, while the WGSL emitter reads semantic indices (`slang-emit-wgsl.cpp:325`), not layout offsets. #9693 was triaged as a member of this family and parked — a duplicate-collision avoided by building the PR branch locally [WGSL/Metal varying-location bugs: check PR #13736 first](../learnings/1795043376789-wgsl-metal-varying-location-bugs-check-pr-13736-be.md).

## Layout POLICY Is Written Twice: type-layout vs ir-layout

At `53b76e6d3` (#12316) the files share no header or policy helper. Duplicated rules include D3D cbuffer 16-byte straddling, std140 composite align, and vec3 (`GetVectorLayout` vs `getVectorSizeAndAlignment`). They are **not 1:1**, capping the value of unifying: the front end has 9 `LayoutRulesFamilyImpl` families / 28+ rule structs and also tracks slots, unbounded `LayoutSize`, existentials, matrix MODES and target-category remapping; the IR side has 7 bytes-only singletons with 3 virtuals — only uniform bytes are common.

**The path a consumer reads decides where a stride/offset bug is fixed.** SPIR-V layout decorations use the **IR path** (member `Offset` via `getOffset(...)` in `slang-emit-spirv.cpp:7014`, `MatrixStride` :7036-7043, `ArrayStride` :2007/:2032); so do emit-llvm/vm/wgsl and the byte-address, buffer-element and varying legalizers. `IRTypeLayout` (`_lowerTypeLayoutCommon`) feeds reflection and parameter binding/legalization. The IR path deliberately skips C tail padding; a differential check must whitelist that, matrix modes and resource kinds. The IR path memo-caches on the type (`kIROp_SizeAndAlignmentDecoration`, `kIROp_OffsetDecoration`) and is indispensable: AST layout runs before IR exists and cannot see `RWByteAddressBuffer.Load<T>()`'s concrete `T` ([layout policy written twice](../learnings/1785761211846-slang-layout-policy-is-written-twice-verified-dupl.md)).

**Changing "scalar layout" per target hits three traps** (#12714's `-layout-rules-version 202c` rounding, PR #13300): (1) `getOpFromTypeLayoutRuleName(Natural)` returns `kIROp_ScalarBufferLayoutType`, which user `ScalarDataLayout` also lowers to, so a version-aware decoder also rounds natural buffers — PR #13300 adds an internal `NaturalBufferLayoutType` emitted only on rounding targets; (2) the DX-layout block in `getTypeLayoutRuleNameForBuffer` returns `Natural` for pointers while reflection lays pointees out as scalar (consistent only because natural == scalar; tell user vs StorageBuffer element pointers apart by `AddressSpace::UserPointer`); (3) `sizeof`/`alignof` fold to target-independent AST constants, so cannot follow a per-target rule; neither does ByteAddressBuffer `Load<T>` (natural rules).

Tooling: `-reflection-json` prints REFLECTION-test format; keep `command-line-slangc-reference.md` trailing spaces (CI byte-compares) ([Natural doubles as ScalarDataLayout's op](../learnings/1790635577609-slang-layout-ir-rule-natural-doubles-as-user-scala.md)).

**The reflection pointer branch forces scalar pointee layout on every target (slang#14040).** `_createTypeLayout`'s `PtrTypeBase` branch (`slang-type-layout.cpp:5735-5743`) applies `kScalarLayoutRulesImpl_` to the pointee regardless of target, while buffer layouts go through the per-target IR layout path. For `uniform S* src` where `struct S { uint a; float2 b; uint c; }`, `-target cuda` emits native `float2 b_0;` (b@8, c@16, size 24) but `-reflection-json` expands the pointee with the SCALAR layout (a@0, b@4, c@12) — one JSON, two layouts for the same struct. Fix direction: making CUDA pointees scalar fixes emit+reflection+CPU agreement in one move; CUDA-aligned also requires changing the reflection pointer branch. `-reflection-json` needs an output filename [CUDA reflection-JSON reports scalar pointee layout while emitting native vectors](../learnings/1794947921393-cuda-reflection-json-reports-scalar-pointee-layout.md).

Testing a rounding change needs a type whose layout differs: `IRTypeLayoutRules::getNatural()` already gives array stride alignUp(size, align) (`S{double x; int y;}`: size 12, stride 16), so only a nested struct moving later fields distinguishes — `U{S z; float w;}` (`w`@12 vs @16) or `T{S a; float b[3];}` (stride 24 vs 32). The aligned-array byte-address path needs `promisedAlignment % (stride*count) == 0`; E41301 demands a power-of-two promise. Oracle: DXC HLSL `sizeof(T)` (`-HV 2021`) includes struct rounding, run locally by an `IDxcCompiler3` driver against `build/Debug/lib/libdxcompiler.so` ([natural layout already rounds array strides](../learnings/1790769300394-slang-ir-natural-layout-already-rounds-array-strid.md)).

**Natural layout is computed twice, and concrete and generic `sizeof` disagree.** Concrete `sizeof`/`alignof` fold through `ASTNaturalLayoutContext::_calcSizeImpl`; generic `sizeof(T)`, IR layout and reflection use the lowered IR struct after specialization, as does any struct AST layout cannot size (a field or static of `Ptr<T>`, `uintptr_t`, `SamplerState` or its own type).

1. **Statics.** `AggTypeDecl::getFields()` (`slang-ast-decl.h:448`) is `getMembersOfType<VarDecl>()` and includes `static` members; instance-only is `getFields(astBuilder, declRef, MemberFilterStyle::Instance)` (`slang-syntax.h:383`). `_calcSizeImpl` counted statics (#13858); PR #13864 filters them (base structs too) ([AST natural layout counts statics](../learnings/1792661288757-slang-ast-natural-layout-counts-static-struct-memb.md)). Three other instance-storage callers had it: `doStructFieldsHaveSemanticImpl` (E38040), `_typeTransitivelyContainsOpaqueHandleImpl` (E30902 with a `static SamplerState`) and `_astTypeIncludesDynamicDispatch` (E52012 with a static interface member) ([getFields() includes statics — 4 callers](../learnings/1792669589818-aggtypedecl-getfields-includes-static-members-4-fr.md)). (2) **`bool`.** The front end sizes `bool` from `BaseTypeInfo` (1 byte); IR natural layout uses `BASE(Bool, 4)` (`slang-ir-layout.cpp:129`). So `struct B { bool b; }` has concrete `sizeof` 1 but generic 4, and a change letting more structs fold in the front end flips bool-field answers: #13864 moves `{static S shared; bool flag;}` from 4 to 1 — probe a bool variant when reviewing natural-layout changes. Changing the front-end value isn't drop-in (`align-of-generic.slang` expects `alignof(bool)` = 1) ([front-end bool 1 byte, IR 4](../learnings/1792687332003-slang-front-end-natural-layout-sizes-bool-as-1-byt.md)). Per target: buffer `bool` is 4 bytes on HLSL, DXIL, SPIR-V/GLSL, WGSL, LLVM std140/std430; 1 byte on Metal, CUDA, CPU/C++, slangvm and C layout — byte-address legalization takes field offsets from IR natural layout, hence the CPU/CUDA 4-byte bool stride vs 1-byte `Load<bool>`. Print a target's real size via `int targetSizeof<T>(T v) { __target_switch { case cpp: case cuda: __intrinsic_asm "int(sizeof($0))"; } }` ([bool size is context-dependent](../learnings/1793830159570-slang-bool-size-is-context-dependent-sizeof-bool-1.md)).

Oracle: `sizeof(S)` vs `uint gsz<T>() { return sizeof(T); }` called as `gsz<S>()` (IR layout). `static_assert(sizeof(X, Std430DataLayout) == N)` works: the natural/scalar-only check at `slang-check-expr.cpp:3010` limits only checker folding, while `static_assert` lowers to an IR inst that `checkStaticAssert` (`slang-emit.cpp:2173`) evaluates after IR `SizeOf` folds with real rules — so it cannot prove a front-end fold: `struct S { static S shared; float x; }` passes `static_assert(sizeof(S) == 4)` unpatched; pin it with `SizeTag<sizeof(S)> t; takesSizeTag4(t);` where `void takesSizeTag4(SizeTag<4>)` gives E30019 when unfolded ([static_assert is evaluated in IR](../learnings/1792680419848-correction-static-assert-sizeof-x-std430datalayout.md)).

**`[vk::offset(N)]` is read by the IR engine only.** `IRVkStructOffsetDecoration` is consumed by `IRTypeLayoutRules::calcSizeAndAlignment` (`slang-ir-layout.cpp:161`) and GLSL emit; front-end layout handles only `packoffset`, so reflection reports the natural offset (often 0) while SPIR-V carries `Offset N` ([vk::offset reaches SPIR-V but not reflection](../learnings/1793388961985-vk-offset-reaches-spir-v-but-not-reflection-a-per-.md)). IR layout also applied it on *every* target (docs say none): for `struct S { int a; [vk::offset(16)] int b; }`, HLSL/Metal/CUDA/C++ `ByteAddressBuffer.Load<S>` read `b` at 16 but native `ConstantBuffer<S>` at 4, and `sizeof(S)` folds to 8. PR #14108 (#9643) makes reflection honour it and gates IR layout to `isKhronosTarget`; Khronos output stays byte-identical ([IR vk::offset honoured off-Vulkan](../learnings/1793400225781-ir-layout-vk-offset-was-honoured-off-vulkan-while-.md)). A layout attribute that starts affecting reflection needs the same gate in both engines. A `-vk` COMPARE_COMPUTE test checks reflection vs SPIR-V: render-test writes entry-point `uniform`s at reflection offsets into a reflected-size block. `//TEST_INPUT:` must start at column 0, and `CHECK: 3` matches inside `type: int32_t` — anchor on the type line ([one target gate for both engines](../learnings/1793397649663-slang-layout-attributes-reflection-and-ir-layout-m.md)).

**Type-level alignment per target (`[Align(N)]`/`alignas` designs, #14032).** CUDA has `__align__(N)`/`alignas`; C++ and Metal (per MSL spec) have struct `alignas`. SPIR-V carries explicit `Offset`/`ArrayStride` from Slang's layout. WGSL puts `@align(k)` per member from the IR offset. GLSL mostly leaves block layout to glslang (ARB_enhanced_layouts `align`/`offset` are std140/std430-block-only, and `align` leaves array stride alone). HLSL has no type-alignment specifier; `packoffset` is top-level cbuffer only ([per-target alignment expressibility](../learnings/1793644718087-per-target-struct-alignment-expressibility-for-ali.md)).

## Entry-Point Push Constants Alias at Offset 0 (#9643)

Each entry point's `uniform` params form their own `PushConstant` block at `Offset 0`; VK_EXT_descriptor_heap's `vkCmdPushDataEXT` has only `offset` + `data` (no stageFlags), so stages alias. #9643 has no maintainer design (advice: keep push constants in one place). Workarounds (positive control: global push block + entry-point `uniform` fires VUID-06674):
- one `struct PushData { ...; DescriptorHandle<Sampler2D> tex; }` as `[[vk::push_constant]] ConstantBuffer<PushData> pd;` in both entry points ([entry-point push constants alias](../learnings/1793349219262-entry-point-push-constants-all-start-at-offset-0-w.md));
- a struct param whose first field has `[vk::offset]` (`struct FragPC { [vk::offset(8)] uint a; uint b; };` lands at 8/12) — on the param itself it is E31002 (`slang-check-modifier.cpp:1541-1544` accepts only struct members);
- one global `[[vk::push_constant]]` block per stage (E39033 does not fire).

The last two lose the nested offset in GLSL output; reflection reports 0 until PR #14108 ([same](../learnings/1793388961985-vk-offset-reaches-spir-v-but-not-reflection-a-per-.md)).

## Global-Scope Varyings on CPU/CUDA (#9078, PR #13467)

A GLSL global `out vec4 f;` aborted Metal/CPU/CUDA in `introduceExplicitGlobalContext` ("no outer func at use site", #9078): `lowerTypeLayout` keyed the struct-field layout on `getSimpleVal(ensureDecl(decl))`, which for a `Flavor::Ptr` global emits a module-scope `load(%f)`, while `createIRModuleForLayout` keys on the var itself — so the two layouts disagreed and `collectGlobalUniformParameters` missed the load. After the key fix both `structFieldLayout(%var, L)` insts dedupe as hoistables; dropping the stray loads reorders GLSL/HLSL/WGSL globals and can break order-checking tests ([getSimpleVal on a global emits a module-scope load](../learnings/1791330554022-slang-ir-layout-field-keys-getsimpleval-on-a-globa.md)).

The fix exposes a second disagreement: on CPU and CUDA, `getVaryingInputRules()`/`getVaryingOutputRules()` return the uniform rules (`slang-type-layout.cpp` ~2278, ~2545), so a global `in`/`out` gets Uniform bytes in `ScopeLayoutBuilder::_addParameter`, shifting every later global in reflection; if `collectGlobalUniformParameters` skips the varying, `GlobalParams` silently mismatches. Repro: `COMPARE_COMPUTE(filecheck-buffer=CHECK):-cpu -compute -entry computeMain -source-language glsl -output-using-type` over `RWStructuredBuffer; out vec4 o; uniform vec4 u;` reads 0.0 for `u`; on master these SEGFAULT in Release (`SLANG_ASSERT(globalParam)` is only `SLANG_ASSUME`) ([global in/out on CPU/CUDA gets uniform bytes](../learnings/1791335346005-glsl-global-in-out-on-cpu-cuda-layout-gives-unifor.md)).

## Unsized Arrays in Implicit Uniform Buffers (E31215, #13530, PR #13538)

At f6238cee3 E31215 (`slang-check-decl.cpp:3805-3824`) is gated on `getConstantBufferElementType`, matching only explicit `ConstantBuffer`/`ParameterBlock`. So a global or entry-point `uniform float4 x[]` is never checked: it packs into implicit GlobalParams/EntryPointParams with infinite size, the next field lands at Offset 0 ("unbounded" in reflection), SPIR-V fails VUID-04680 ([E31215 skips implicit uniform buffers](../learnings/1791490940298-slang-e31215-unsized-type-in-constant-buffer-skips.md)).

Extending it needs a "holds ordinary uniform bytes?" predicate no classifier provides: `isOpaqueHandleType` misses `__DynamicResource[]`/`SubpassInput[]`; `isUniformParameterType(elem) || doesTypeHaveTag(elem, TypeTag::Opaque)` errs both ways (`Opaque` is set if ANY field is a resource; `isUniformParameterType` is true for `PtrType`, but `float4* ps[]` is an unsized address array); interface elements are existentials; a generic `T` is classifiable only after specialization. The PR also fixed two `getTrailingUnsizedArrayElement` crashes: a null-deref on an all-static struct, and an infinite loop on an error-typed last field ([classifiers misclassify; getTrailingUnsizedArrayElement crashes](../learnings/1791508227251-slang-unsized-array-classifiers-opaque-tag-and-isu.md)).

Review of #13538 found a dead guard: nothing creates `GLSLBufferModifier` (`slang-ast-modifier.h`). GLSL `buffer` goes through `parseGLSLShaderStorageBufferDecl` to a `GLSLShaderStorageBuffer<…>` variable, which `getConstantBufferElementType` already excludes. Dropping the `hasModifier<GLSLBufferModifier>` conjunct passed 378/378; older checks at `slang-check-decl.cpp:3051` and `slang-lower-to-ir.cpp:12507` are equally unreachable. Such a guard needs a reaching test, or removal ([GLSLBufferModifier has no producer](../learnings/1791516340522-glslbuffermodifier-has-no-producer-guards-that-tes.md)).

## Bitfields: Packing Fixed at Check Time, Baked Into Modules

Bitfield offsets are decided at semantic check, not per target: `SemanticsDeclAttributesVisitor::visitStructDecl` (`slang-check-decl.cpp` ~20922) reads the packing rule from *linkage* options into `BitFieldModifier::offset` → `IRBitFieldAccessorDecoration`. So a `.slang-module` built with `-msvc-style-bitfield-packing` (MSB-first, though MSVC is LSB-first; #13296) stays MSB-first when imported without it; option changes reach only its builder. A new `CompilerOptionName` also needs a case in `writeCommandLineArgs` (`slang-compiler-options.cpp`) ([bitfield packing baked into modules](../learnings/1790625408306-slang-bitfield-packing-is-baked-into-precompiled-m.md)).

Zero-width fields (`T x : 0`; `slang-check-decl.cpp` ~21088-21111, #13299) close the current group and become the FIRST member of the next, so their type sizes the next `$bit_field_backing_N`. Default mode shares that backing with the next bitfield; MSVC mode gives an empty backing when the next type size differs. No spelling is portable: Slang rejects unnamed `uint32_t : 0;` (E20001); C/C++ reject named zero-width fields. Under legacy MSB-first packing the field's offset == backingWidth, so its getter `int32_t(backing) >> 31` reads -1 when the next field is negative (LSB-first reads 0). The checker picks only backing types and bit offsets, so a storage-less alignment barrier is unrepresentable ([zero-width bitfields; MSB-first readback bug](../learnings/1790631718776-slang-zero-width-bitfields-layout-vs-native-and-a-.md)).

**GPU-free, MSVC-free layout oracle:** `-target cpp` (emitted `struct S_0` backings and setter masks give the layout; `g++ -I prelude` runs it). To compare with MSVC host layout, compile `struct __attribute__((ms_struct)) S {...}` with g++/clang. Backing-word init rules are on [[wiki/concepts/slang-compiler-frontend-and-checking.md]].
