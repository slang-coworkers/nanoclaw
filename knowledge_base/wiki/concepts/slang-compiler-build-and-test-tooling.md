# Slang build, test, and verification tooling: freshness, exit codes, DIAGNOSTIC_TEST traps, harnesses

Practical traps in building slangc/slangd, running slang-test, authoring tests, verifying backends, and driving a fix session — the tooling layer around the Slang compiler (CI noise classification lives on [CI failure classification](slang-compiler-ci-failure-classification.md)).

## TL;DR

- A preflight rebuild can silently NO-OP on a stale binary: `git pull` sets source mtimes to commit dates, which can precede build-output mtimes, so ninja deems everything fresh. The `-version` string is a configure-time CMake cache value and stays stale even after a genuine rebuild — tie a binary to a commit with checkout state + build-step counts, never `-version`.
- Since #14573 (2026-11-18) slangc exit codes are positive: 2 = failed compile, 3 = ICE; old notes saying "returns -1 (255)" read as "returns 2" on current master.
- DIAGNOSTIC_TEST `diag=` annotations match the parsed message text only, parsed as `//PREFIX:` with NO space; `.wgsl`/`.spv`/`.glsl`/`.hlsl`/`.metal` under `tests/` are gitignored; pass-through gates belong in `executeActionsInner`, not `OptionsParser`.
- Metal render tests compile-check anywhere but only render-verify on macOS; slang-rhi CPU-device bugs can be verified headless by linking a small driver against `libslang-rhi.a`.
- A gate change that activates a previously-dormant table weaponizes every stale entry — audit all entries against what the downstream compiler actually consumes.
- Session tooling: `plan-tracker.sh` records only Write-tool plans; every critique round needs a fresh codex call; verify formatting per tool (the script's exit code is masked); `/tmp/opencode` is root-owned — scratch in `/tmp/<subdir>`.

## Build freshness: the silent no-op preflight and the stale version string

In the slang base clone, the "rebuild before citing a master repro" preflight (`cmake --build --preset release --target slangc`) can itself silently NO-OP while the binary is stale: `git pull` sets source mtimes to commit dates, which can precede the build outputs' mtimes (written later by a sibling session), so ninja deems everything fresh and rebuilds nothing (seen 2026-11-18 on #14603: no-op preflight, slangc still the v2026.13.1+50 binary, checkout at v2026.22-37). Cures: run with `--clean-first` (~4.5 min), or only trust a preflight that actually compiled steps. The version string is NOT a post-check — it's a configure-time CMake cache value and stays stale even after a genuine rebuild; to tie a binary to a commit use the checkout state (git status + `git describe HEAD`) plus build-step counts, not `-version` [slangc preflight rebuild can silently no-op on a stale binary (mtime inversion)](../learnings/1795025333675-slangc-preflight-rebuild-can-silently-no-op-on-a-s.md).

Slang master commit 8df5bc214 ("Return positive exit codes from slangc", #14573, 2026-11-18) changed slangc exit codes: failed compilation now returns 2 (was -1/255) and internal compiler error 3 (was -2/254); old Ignored/FailedToRun moved to 4/5. slang-test now expects exit-code=2 where tests expected -1, and .expected files use the new values. Any issue body or comparison note written before 2026-11-18 saying "returns -1 (255)" reads as "returns 2" on current master — recheck exit-code claims when re-verifying old repros (encountered re-verifying #14439) [slangc exit codes are positive since #14573 (2 = failed compile, 3 = ICE)](../learnings/1795027136177-slangc-exit-codes-are-positive-since-14573-2-faile.md).

## DIAGNOSTIC_TEST authoring traps (each costs a build; #14603 / PR #14606)

1. `diag=<PREFIX>` annotation matching parses `//<PREFIX>:` with **no space** between `//` and the prefix, and matches the parsed **message text only** — never the `error[E...]` prefix. Use `filecheck=` if you need raw-output matching. clang-format inserts `// ` in `.c` test files → wrap directive/annotation blocks in `// clang-format off/on`.
2. `.wgsl`, `.spv`, `.glsl`, `.hlsl`, `.metal` under `tests/` are **gitignored as generated outputs** — a tracked test input in those extensions is impossible (and slang-test's `endsWithAllowedExtension` has no `.wgsl`). To test an explicit-language TU: SIMPLE tests always put the input file first, so `-lang <x>` in directive args can't retag it; instead pass `-lang wgsl $dirname/<self>.slang` — the `-lang` option consumes the following path at that language, self-referencing the test file.
3. Pass-through constraint checks belong in `EndToEndCompileRequest::executeActionsInner` (the E45104 coverage check there documents this: covers `setPassThrough()` API callers too), NOT in `OptionsParser` — an options-level gate fires before E45104 and breaks the recorded diagnostics of `trace-*-pass-through.slang` tests.
4. Triage briefs about environment-dependent failure modes can be wrong: on this container slang-llvm **loads** (llvm spelling crashes like clang/gcc, does not stop at E52002), and sharedlib+pass-through pre-fix was **silent exit 0**, not a crash. Re-measure each spelling before writing it into a report [slang DIAGNOSTIC_TEST authoring traps: no-space annotations, gitignored .wgsl, -lang self-reference, pass-through gate layering](../learnings/1795030486309-slang-diagnostic-test-authoring-traps-no-space-ann.md).

## Backend verification: headless slang-rhi CPU harness, and Metal's macOS-only render path

**Headless verification of slang-rhi's CPU backend** works without building a test harness around the device: link a small driver directly against `libslang-rhi.a` (+ `libslang-rhi-resources.a`, the local slang build's `-lslang -lcompiler-core -lcore`, and `liblz4.a` from `slang/build/external/lz4/build/cmake/<Config>/`), and construct `rhi::cpu::TextureImpl`/`TextureViewImpl` directly (they implement `slang_prelude::ITexture` — the exact interface compiled CPU-target shaders call). Gotchas: do NOT put `slang-rhi/src/core` on the include path (its `string.h` shadows the system header and breaks `<cstring>`); use `-std=c++20` (std::span); a prebuilt `build-*/libslang-rhi.a` from a prior chain is valid evidence for "main" if its mtime postdates the last commit touching the file (check `git log -1 -- <file>`). Used to verify slang-rhi#976 (cube array @arrayLength=1 always reads face 0 — `isArray = arrayLength > 1` at cpu-texture.cpp:328/:380 ignores TextureType's explicit array-ness). Also: slang-rhi has NO `reproduced` label (unlike slang) — accepted CPU bugs like #960 carry no labels, only Issue Type [headless slang-rhi CPU-backend verification harness (+#976 cube-array finding)](../learnings/1795022024831-headless-slang-rhi-cpu-backend-verification-harnes.md).

On shader-slang/slang#5667 ("metal: Investigate rendering tests"): PR #5666 was closed unmerged, but its fix landed anyway via #6063 (merged 2025-01-15), which moved Metal entry-point legalization onto the shared WGSL/Metal path — `fixFieldSemanticsOfFlatStruct` runs unconditionally at slang-ir-legalize-varying-params.cpp:3339. When a closed-unmerged PR looks unfixed, grep the current source for the fix shape before calling it "still broken" — unification refactors often land closed PRs' changes under different numbers. But the ask of #5667 is NOT resolved: the Metal render comparison (render0.hlsl, multiple-stage-io-locations.slang, nointerpolation.hlsl) is still `DISABLE_TEST ... -mtl` and listed in tests/expected-failure-github.txt; compile-for-metal succeeds, but end-to-end render validation needs macOS hardware — Linux containers cannot run the Metal render path. Metal render tests can be compile-checked anywhere but only render-verified on macOS [Issue #5667 Metal render tests: PR #5666 fix landed via #6063, render rows still disabled](../learnings/1795035417817-issue-5667-metal-render-tests-pr-5666-fix-landed-v.md).

## Fix-session tooling traps (#14603/PR #14606)

1. **A decline of a reviewer finding can itself be wrong — verify the "bug" at the consumer, not the table.** A "spirv-opt regression" was declined claiming a SPIR-V TU passes `canCompile(SPIRV_OPT, SPIRV)`; the reviewer then verified the REAL pre-PR flow was `-pass-through spirv-opt` with **GLSL** input (both glslang spellings share the slang-glslang wrapper, which compiles GLSL and optimizes SPIR-V, slang-glslang-compiler.cpp:268-278), so enforcing the pre-existing SPIRV-only table entry regressed it. When a gate starts enforcing a previously-dormant table, audit EVERY entry against what the downstream compiler actually consumes; "the entry was pre-existing" is no defense — the change weaponizes it.
2. **plan-tracker.sh records a plan only on the Write tool** (PostToolUse matcher is Write); editing the plan file with Edit leaves `plan_written=false` and the gate keeps firing. Each new inbound message mints a fresh workflow-state — re-Write the plan after every inbound-driven round.
3. **track-critique does not record codex-reply rounds** — every critique stage needs a fresh `mcp__codex__codex` call to count toward the delivery gate.
4. **formatting.sh exit code is masked by `| tail` and the script exits 1 in this container anyway** (broken gersemi shim); verify per tool: `clang-format-17 <file> | diff <file> -` must be empty, and keep new files under the 100-column limit before committing.
5. **upsert_pr_body.py quiz positions change with every head** — re-run `--quiz-positions <new head>` and re-order both the option letters and the per-question answer-restatement letters after each push.
6. GitHub CLI quirks in this container: `gh issue view <n> --comments` can print empty — `gh api repos/.../issues/<n>` works; and GraphQL `updateIssue` for Issue Type needs the issue `node_id`, not issueNumber ([#14613 triage](../learnings/1795040516111-slang-14613-missing-scalar-any-all-were-a-numerics.md)).
[Slang fix-session traps: dormant-table weaponization (spirv-opt), Write-tool-only plan tracker, fresh-call-only critique recording, quiz positions per head](../learnings/1795039978926-slang-fix-session-traps-dormant-table-weaponizatio.md). Environment note from the same sweep: in the slang-triager container `/tmp/opencode` is root-owned and NOT writable by the agent user ("Permission denied" on mkdir subdirs) — use `/tmp/<your-subdir>` for scratch repro files [/tmp/opencode is root-owned; use /tmp/<subdir> for scratch](../learnings/1795042603036-tmp-opencode-is-root-owned-use-tmp-subdir-for-scra.md).

## SlangPy worktree builds: submodules, missing SHAs, torch repros

Recurring SlangPy worktree-build setup gotchas (hit on wt-518, 2026-11-18, building origin/main):

1. Submodules cloned from a live sibling worktree can end up "inited" but with an EMPTY working tree — `git submodule status` shows them inited yet the files are missing (CMake then fails with confusing cascade errors like "unable to find a build program" or "missing Inconsolata-Regular.ttf"). Fix per-submodule with `git submodule update --force -- <path>`.
2. When the source worktree predates the superproject's latest submodule bump, the recorded submodule SHA isn't in the local clone (e.g. slang-rhi at 314584012, bumped in slangpy#1275, wasn't reachable from the local fetch URL). Fetch the missing SHA directly from GitHub: `git -C external/slang-rhi fetch https://github.com/shader-slang/slang-rhi.git main`, checkout the recorded SHA, then `git -C external/slang-rhi submodule update --init --recursive`.
3. nanobind v2.10.2 and nanothread still have nested submodules (ext/robin_map, ext/cmake-defaults) — init them from INSIDE the parent repo (`git -C external/nanobind -c protocol.file.allow=always -c submodule.ext/robin_map.url=<live-worktree-path> submodule update --init ext/robin_map`); superproject-level pathspecs fail.
4. For torch repros: torch 2.15.0+cu132 installs into the tmp venv via `uv pip install --python .../venv/bin/python torch` (the venv has no pip binary). Create the spy device with torch CUDA interop via `slangpy.testing.helpers.get_torch_device(DeviceType.cuda|vulkan)`, and if the native slangpy_torch extension isn't built, enable the pure-Python bridge with `spy.set_torch_bridge_python_fallback(True)` + `spy.set_allow_torch_fallback(True)` (same calls as the `torch_bridge_mode` pytest fixture).
