# Slang Test — Output Assertions and Truncated Runs

This page covers the ways a slang-test run goes **green while asserting nothing about a failing compile or a curtailed run**: output-path and exit-status assertions, `OpString` self-match counting, SIMPLE lanes that ignore the result code, inert DIAGNOSTIC_TEST annotations, and the `100% of tests passed` fake-pass on a truncated run. FileCheck authoring, `CHECK-NOT` regions, and opt-level plumbing live in [Slang Test — FileCheck Authoring and Opt-Levels](slang-test-filecheck-authoring-and-opt-levels.md). Directive authoring is in [part 1](slang-misc-test-harness.md); running the harness and its false greens are in [slang-test False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md).

## TL;DR

- **Never write a dump-based FileCheck test to `-o /dev/null`.** It is Windows-invalid (`E00004`, exit 255), yet `-dump-ir` already printed the matched text, so the test stays green. Use `-o -` plus a status assertion. Reproduce on Linux with `-o /nonexistent-dir/out.spv`; that is the negative control.
- **`-o -` and dropping `-o` differ: with `-g`, dropping `-o` switches to `-whole-program` mode.** Prefer `-o -`.
- **Bugs that need several entry points in one module hide from slangc-to-stdout and plain `//TEST:SIMPLE`**, which compile one entry point at a time; `-o <file>` or `-whole-program` emits one module. render-test compiles `computeMain` only and ignores `-entry`, so a COMPARE_COMPUTE leg needs an entry named `computeMain` (else E38000).
- **Write `result code = {{0}}`, not `result code = 0`.** Under `-g` the IR dump embeds the source, so the literal matches its own echoed comment. `{{N}}` is a regex; `{N}` is inert.
- **The `OpString` self-match is the same family**: a `CHECK-NOT` or `CHECK-DAG` can match its own echoed comment. Break the literal and anchor on the opcode; count with `grep -cE 'OpExtInst.*<Op>'`, never a bare `grep -c '<Op>'`.
- **`//TEST:SIMPLE(filecheck=…)` never checks the result code.** Error output echoes the source line, so `X: computeMain` matches a failed compile. Use a success-only pattern (`define void @computeMain`, `__global__ void computeMain(`) or `result code = {{0}}`. A bare `X-NOT: error` matches the `standard error = {` header, and a NOT-only lane gates on nothing: anchor it first (`X: OpEntryPoint` or `result code = {{0}}`) and re-run the revert drill after adding any row.
- **COMPARE_COMPUTE compares stderr: any compile warning fails the lane even with a correct buffer** (`EXPECTED standard error = {}`). Fix the warning, or for deliberately deprecated syntax add `-xslang -Wno-<code>` to each COMPARE_COMPUTE line.
- **A `CHECK: <decl-name>` on a spirv/glsl lane passes on a failed compile.** Check the lowered op, put `result code = 0` first, and run with `SLANG_RUN_SPIRV_VALIDATION=1` (CI sets it).
- **A `-NOT` after a stdout match never sees stderr** (buffer order: result code, stderr, stdout). Assert "no diagnostics" with an annotation-free `//DIAGNOSTIC_TEST:SIMPLE(diag=X):`, or put the NOT before the first stdout match.
- **DIAGNOSTIC_TEST has no `-NOT` directive, and `// CHECK:` with a space is inert.** The marker is `"//" << prefix << ":"`. Assert absence with an exhaustive, annotation-free test; pin codes in a caret annotation (`^^^^ error E39033`) and mutate the code to prove the row is live.
- **`100% of tests passed (264/264)` can be a run TRUNCATED by the consecutive-failure breaker.** `PendingRetry` failures never enter the total, and the bail notice goes to stderr, so `2>/dev/null | grep '% of tests passed'` hides it.
- **Grep `2>&1` for `% of tests passed|Stopped scheduling|Skipping retries|failed\(pending retry\)|failing tests`.** `failed(pending retry)` is the load-bearing term, validated both ways.
- **Never store a per-directory total as a constant, and never use `$?`** (slang-test exits 0 with failures). Derive counts in-session or run a neuter→run→restore→run drill. A positive control that returns zero means the control is wrong.
- **Under `-output-using-type`, anchor on the `type:` header and pin each value line**: `// BUF: type: uint32_t`, then `// BUF-NEXT: {{^}}2{{$}}`, or compute a distinctive value (`207`, not `2`). A bare `BUF: 2` matches inside `uint32_t`/`int32_t`; a comma-joined line never matches. Read `<test>.actual.txt` first.
- **`-bindir <other>/bin` is not an A/B**; slang-test loads its own libslang. Run master's own slang-test from its root, with one known-fails-on-master control.
- **Ask of every new test: what would have to break for this to stay green?** If "the compile fails" is an answer, add a status assertion.

## Output paths and status assertions: `-o /dev/null`, `-o -`, and `result code = {{0}}`

**Never write a dump-based FileCheck test to `-o /dev/null`.** It is an anti-pattern, fixed repo-wide in #12333 / PR #12334, and it supersedes an older note that called it idiomatic. On Windows `/dev/null` is not a valid output path, so slangc reports `error[E00004]: cannot write output file` and exits 255. The test still passes: `-dump-ir` prints the matched IR before codegen reaches the failing write, and FileCheck sees no nonzero result code unless one is asserted. pdeayton-nv caught it on #12281; CI did not ([dump-based FileCheck tests need `-o -` and an explicit `result code = 0`](../learnings/1785775051459-dump-based-filecheck-tests-need-o-and-an-explicit-.md)). Use `-o -` and pin the exit status. `-o -` and dropping `-o` both make the backend run and are byte-identical for plain tests, but with `-g`, dropping `-o` flips the driver into `-whole-program` mode (visible in the `-g` debug string).

**The status assertion has an inert spelling.** The FileCheck buffer is `result code = <N>` / `standard error = {…}` / `standard output = {…}` (`slang-test-main.cpp:1876`). Under `-g` the IR dump embeds the whole source in `DebugSource("<path>", "<file text>")`, so `// PREFIX: result code = 0` matches its own echoed comment and passes when the real line is `result code = 255`. Measured: `result code = {{0}}` passes the healthy compile and fails the forced-failing one. `{{N}}` is evaluated as a regex (`{{1}}` fails on an exit-0 compile); `{0}` is the inert spelling, whatever a reviewer claims. The `-g2` `OpString` trap is the same family: the source, including `//CHECK` lines, lands in an `OpString`, so `CHECK-NOT: DebugGlobalVariable` matches its own comment and a positive `CHECK-DAG: DebugGlobalVariable {{.*}} %payload` can pass with no real instruction. Confirm the hazard with `slangc … | grep -o 'CHECK-DAG: <your text>'` returning your own line; fix it by breaking the literal and anchoring on the opcode (`OpExtInst {{.*}} Debug{{Global}}Variable`). To count, use `grep -cE 'OpExtInst.*<Op>'`; a bare `grep -c '<Op>'` counts the echoed comment lines and once inflated a figure sent to a maintainer (3 debug records claimed, 1 real) ([FileCheck tests that pass without testing anything](../learnings/1785779116844-filecheck-tests-that-pass-without-testing-anything.md), [never use `-o /dev/null`; `-g` makes `result code` self-match](../learnings/1785787436624-never-use-o-dev-null-in-slang-tests-and-g-makes-re.md)).

The negative control on Linux is `-dump-ir -o /nonexistent-dir/out.spv`: same `E00004`, exit 255, full IR dump, green test. A known latent instance is `tests/autodiff/func-extension/subscript-accessor.slang`, still on `-o /dev/null` (out of scope on #12281). Under all of this sits the ambient inert mode: without the `slang-llvm` library, `filecheck=` tests report `TestResult::Ignored`, not failed (`slang-test-main.cpp:815-822`). slang-test loads FileCheck in-process from `libslang-llvm.so`, which the shared full build has in `build/Debug/lib/`; a fresh worktree that built only `slangc`/`slang-test` lacks it, and its filecheck lanes all go `ignored` until the lib is copied in (details on [Verification discipline](misc-f0909b5-verification-discipline-and-tooling.md); [SIMPLE(filecheck=) lanes ignored without libslang-llvm.so](../learnings/1791609372518-slang-test-silently-ignores-simple-filecheck-lanes.md)). Either way, break one assertion on purpose and confirm RED before trusting a green run.

**A bug that needs several entry points in one module needs a one-module compile.** On #13687 (global `in`/`out` varyings shared by two entry points), slangc writing to stdout and a plain `//TEST:SIMPLE` both generate code one entry point at a time, so both hide the bug; `-o <file>` or `-whole-program` emits one module, as Metal SIMPLE lanes already do. render-test (COMPARE_COMPUTE) always compiles `computeMain` alone (`-entry` is parsed and ignored; `-no-default-entry-point` asserts), so no GPU runtime test can cover two-entry-point emission. In a test that mixes SIMPLE legs with a `//TEST(compute, vulkan):COMPARE_COMPUTE(...)` leg, an entry named `main` fails that leg with E38000 "no function found matching entry point name 'computeMain'" even with `-entry main`; name the entry `computeMain` ([COMPARE_COMPUTE ignores -entry](../learnings/1792488875310-slang-test-compare-compute-ignores-entry-codex-cri.md), [vk leg fails E38000 without `computeMain`](../learnings/1793207048530-slang-formatting-sh-full-run-can-leave-a-committed.md)). On the compiler side, `translateGlobalVaryingVar` emits `GlobalVariableShadowingGlobalParameterDecoration(param, global, key)`, which lets `slang-ir-glsl-legalize.cpp` rewrite every use of the global, module-wide, to one entry point's Input var. That is correct only when exactly one entry point reaches the global; otherwise a shared struct `in` gives VUID-08721 and a scalar silently reads the wrong location, and none of the 3,158 SPIR-V-validated tests covered it ([multi-entry-point bugs: stdout and SIMPLE compile one entry point at a time](../learnings/1792198835891-slang-multi-entry-point-bugs-slangc-stdout-and-sla.md)).

## `100% of tests passed` on a truncated run: the `failed(pending retry)` grep

`slang-test` reports `100% of tests passed (264/264)` on a run truncated by its consecutive-failure breaker, because the disqualifying failures never enter the total. In source (master `0864e60e6`), `slang-test-main.cpp:5121` returns early while `stopSchedulingTests` is set, so later tests are never scheduled. A `PendingRetry` result prints `failed(pending retry) '<name>'` and returns before `m_totalTestCount++` (`test-reporter.cpp:368-372`, increment at `:378`), and once the breaker fires retries are skipped, so those failures are counted nowhere. Only `ignoredCount` is subtracted (`runTotal = rawTotal - ignoredCount`, `:694`; printed at `:713`). The number is arithmetically true, which makes it harder to distrust than a lopsided ratio. The percentage prints to stdout while the bail notice uses `fprintf(stderr, …)` (`slang-test-main.cpp:6131-6137`), so `cmd 2>/dev/null | grep '% of tests passed'` discards the disqualifying fact by construction. Watch both numbers in `100% of tests passed (264/264), 94 tests ignored`, since the ignored path and the breaker path are independent, and never use `$?`: `slang-test` exits 0 even with failing tests ([`100% of tests passed` on a truncated run: the exact accounting](../learnings/1785837790090-correction-slang-test-denominator-check-measure-th.md)).

The pattern validated on real output in both directions is `slang-test ... 2>&1 | grep -E '% of tests passed|Stopped scheduling|Skipping retries|failed\(pending retry\)|failing tests'`. `failed(pending retry)` is the load-bearing term: it prints to stdout (`test-reporter.cpp:371`), so it survives a stderr-dropping pipeline, and it fired 265 times on a real truncated run against one bail-notice line. On a healthy run the pattern shows only the pass line (`689/689`), so it does not false-alarm. The first validation attempt returned zero matches because it was pointed at a build log with no test output; a positive control that returns zero means the control is wrong, not that the world is clean ([the `failed(pending retry)` grep, proven both directions](../learnings/1785838168354-validated-grep-for-the-slang-test-fake-pass-failed.md)). Never store a per-directory total (`dynamic-dispatch=689`) as a constant: it silently ages into a phantom regression or an accepted truncation. Derive the expected value in the same session (baseline before, again after), or run a neuter → run → restore → run drill, which needs only that the two runs differ.

## `-output-using-type` buffer checks and `-bindir`

With `-output-using-type`, the COMPARE_COMPUTE buffer dump (written to `<test>.actual.txt`) opens with a type header such as `type: uint32_t` and then prints one value per line (`type: float`, `3.000000`, `1.000000`). Two failure modes follow. A comma-joined `// CHECK: 3.0, 1.0` never matches and FAILS correct values; #13611 triage nearly misreported an open PR this way ([filecheck-buffer prints one value per line](../learnings/1791922190410-slang-test-filecheck-buffer-prints-one-value-per-l.md)). A bare `// BUF: 2` matches the `2` inside `uint32_t` and passes whatever the kernel wrote (slang#13412, where master's real output was `1`); the signed header does the same (`// CHECK: 2` inside `type: int32_t`, PR #13503) ([caret blocks; int32_t header matches bare CHECK digits](../learnings/1791411328355-diagnostic-test-caret-columns-use-check-blocks-for.md)), and again on slang#13966 R2, where a reviewer's probe of a 1-vs-2 behavior change "passed" on the broken build. Besides anchoring, a probe can compute a distinctive value (`x * 100 + 7`, then check `207` against `107`) so that no result digit can match the header ([small-digit CHECKs are vacuous under -output-using-type](../learnings/1793153753122-filecheck-buffer-with-output-using-type-small-digi.md)). With `X-NEXT` value lines after it, the same mis-anchor shifts every check by one line and FAILS correct output, which reads as a codegen bug: #13363's dynamic-index test hit it on its first L40S run, and a GPU-less container ignores the `(vk)` row so it never fails there ([anchor the first BUF check on `type:`](../learnings/1792570875618-slang-test-output-using-type-anchor-the-first-buf-.md)). Anchor past the header and pin each whole value line: `// BUF: type: uint32_t`, then one `// BUF-NEXT: {{^}}2{{$}}` per value, as the `tests/compute/half-*.slang` tests do. Read `.actual.txt` before trusting either verdict. (#13611's compiler finding: an existential `DifferentialPair` through dynamic dispatch gets a wrong tangent offset when conformer sizes differ, since typeflow's `makeInfoForConcreteType` has no `DifferentialPair` case; a regression from #9808.)

**`-bindir` is not an A/B.** `slang-test -bindir <other-build>/bin tests/x.slang` still runs the invoking tree's compiler for SIMPLE and COMPARE_COMPUTE tests, because the invoked slang-test loads its own libslang through RUNPATH. Seen on #13412 (master "passed" a test it fails) and #13700 R4; #13687 confirmed the reason ([`-bindir` does not switch COMPARE_COMPUTE tests](../learnings/1792215112632-slang-test-bindir-does-not-switch-compare-compute-.md); [`-bindir` loads the caller's libslang](../learnings/1792198835891-slang-multi-entry-point-bugs-slangc-stdout-and-sla.md); mechanism on [Release-Build Divergences](slang-build-release-divergences-and-sanitizers.md)). Run the baseline's own slang-test from its root and include one test known to fail on master as a control. A lane fact from #13412: a CPU lane loads the whole module, so one barrier entry point anywhere in the file fails it with E36107 ([`BUF: 2` matches `uint32_t`; `-bindir` is not an A/B](../learnings/1791162065748-slang-test-filecheck-buf-2-vacuously-matches-type-.md)); the stderr-warning rule from the same run is below. (#13700 R4's IR finding: a value that dominates a `LoadFromUninitializedMemory` (freeze) can still be poison, e.g. `select(c, 1, poison)`, so refining all uses of a frozen value to `d` needs a `d` with an established non-poison guarantee, such as an IR literal outside any function or an `IRGlobalParam` without `IRDefaultValueDecoration`; dominance alone is not enough.)

**COMPARE_COMPUTE compares stderr, so any compile warning fails the lane.** The expected output includes an empty stderr, so a lane whose compile prints a warning fails with `EXPECTED standard error = {}` beside the warning, on cpu, vk and cuda alike, even when the buffer matches. It has been measured with E41016 (uninitialized variable) on #13412 ([`BUF: 2` matches `uint32_t`](../learnings/1791162065748-slang-test-filecheck-buf-2-vacuously-matches-type-.md)) and with the front-end E30514 ("loop runs zero times") on #13985 / PR #13993, where a runtime test needed a warning fix as well as the codegen fix ([COMPARE_COMPUTE fails on any stderr warning; E30514 is not what removes the loop](../learnings/1793220323154-slang-compare-compute-fails-on-any-stderr-warning-.md)). A test that uses deprecated syntax on purpose, such as vector `?:` (warning 30056), passes `-xslang -Wno-30056` on each COMPARE_COMPUTE line, as `tests/language-feature/scalar-ternary-op-short-and-non-short-circuit.slang` does ([COMPARE_COMPUTE fails on any stderr warning](../learnings/1793197057690-compare-compute-fails-on-any-stderr-warning-critiq.md)).

## Contradictions / supersessions

- **`slang-test`'s process exit code as a pass/fail signal** — it returned **0 on a FAILED test**, and exits 0 even with failing tests in a truncated run. Parse the `FAILED test:` / `% of tests passed` / `failed(pending retry)` lines, never `$?`.
- **"6 tests committed" as a coverage figure** — narrowed in place under *Counting Assertion-Bearing Tests* in [slang-test False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md): count assertion-bearing tests only (3 of the 6 files), and name the single discriminating case rather than letting a file count stand in for power.

## SIMPLE+filecheck never gates on the result code

A `//TEST:SIMPLE(filecheck=X):` test passes whenever its pattern matches anywhere in the buffer, whatever the compile returned: `runSimpleTest` calls `_validateOutput(..., forceFailure=false, ...)`, and the FileCheck branch returns `_fileCheckTest(...)` without reading `result code` (`tools/slang-test/slang-test-main.cpp` ~989-991, 3234-3238). Pair every FileCheck with positive evidence of success, either a success-only pattern or `result code = {{0}}`, the same rule as the `CHECK-NOT`-only case on [slang-b-test-harness](slang-b-test-harness.md). Measured shapes:

- **Errors echo the source line.** Downstream Metal errors go through the GCC-style diagnostic parser and quote the offending line, so `// LIB: computeMain` on `-target metallib` matches a rejected kernel signature (#12294 R2, where the R1 report had relayed it as proof) ([SIMPLE+filecheck never gates on the result code](../learnings/1790702677475-slang-test-simple-filecheck-never-gates-on-the-res.md), [SIMPLE+FileCheck ignores the compile result](../learnings/1790704590796-slang-test-simple-filecheck-ignores-the-compile-re.md)). Use `// METALLIB: define void @computeMain` (`tests/metal/simple-compute.slang:22`, `barrier.slang:8`) or a lowered intrinsic such as `sample_compare_depth_2d`; a green macOS "metallib passed" line is not proof otherwise. On #13413 R1, `// X: <entryName>` passed after Apple's compiler rejected the MSL; gate with `// X: result code = 0` (`{{0}}` under `-g`) plus `// X: define {{.*}} @<entry>` ([SIMPLE filecheck lanes ignore slangc's exit code](../learnings/1790977463190-slang-test-simple-filecheck-lanes-ignore-slangc-s-.md)). Slang's own located diagnostics do the same: on #13843 a Metal compile with two E41014 errors passed a `//X: computeMain` control lane. Match the emitted kernel signature (`//X: __global__ void computeMain(` for CUDA, `//X: {{\[\[kernel\]\]}} void computeMain(` for Metal, since `[[` is FileCheck syntax and must be escaped inside `{{ }}`) and add `//X-NOT: error[E`. A bare `error` matches the `standard error = {` header, and legacy rows such as `internal error 99999:` lack the `[E`, so the positive signature is the load-bearing half ([`computeMain` control lanes pass on a failed compile](../learnings/1792629381882-slang-test-simple-filecheck-computemain-control-la.md)). That atom's caret-column note is the `/*X:` … `*/` caret-block rule on [slang-b-test-harness](slang-b-test-harness.md).
- **A NOT-only lane gates on nothing.** `// PREFIX-NOT: error :` alone passed on a throwaway test where `-entry doesNotExist` made slangc fail, while a NOT that did match failed, so FileCheck was running. Slang's own diagnostics print `error[E38000]: …`; only downstream-compiler errors use `<file>(<line>): error <code>:`, and the `failed to load downstream compiler` path is ignored, not failed. Pair the NOT with `// PREFIX: result code = 0` (as `tests/metal/mesh-index-expression.slang:13` does) or a positive anchor such as `METALLIB: @entryName`. It was seen on #12294 R2, #13413 R1, and #13421 G2, so check every new `-target metallib` lane ([a NOT-only `X-NOT: error :` lane passes when slangc itself fails](../learnings/1791009233810-a-not-only-x-not-error-filecheck-lane-passes-when-.md)). SPIR-V lanes fail the same way. On #13988 an `-emit-spirv-via-glsl` row with only `SPV-NOT: … SAbs` passed on master because glslang rejected `abs(uint)`, so the buffer held no `OpExtInst` at all. The fixer had reported those rows as failing without the fix, because the revert drill ran before the rows were added; the peer reviewer caught it by running the new tests on a base binary. Put a positive anchor before the NOT (`// X: OpEntryPoint`, used by 229 tests, or `// X: result code = 0`, used by 212), and after adding or changing any row, re-run the revert drill on a pre-fix binary and confirm each claimed regression row fails there ([SIMPLE filecheck with only CHECK-NOT passes when compilation fails](../learnings/1793216878744-slang-test-simple-filecheck-with-only-check-not-pa.md), [a FileCheck block of only -NOT lines passes when the compile fails](../learnings/1793220332838-a-filecheck-block-of-only-not-lines-passes-when-th.md)).
- **A declaration name proves nothing on SPIR-V/GLSL.** On #13507, `bit-cast-resource-array.slang` (`-target spirv`, one `// CHECK: bitsBuffer`) passed 22/22 locally but fails under `SLANG_RUN_SPIRV_VALIDATION=1`, which CI exports (`ci-slang-test.yml:152`): stderr is in the buffer, and the module dumped on a validation failure still has `OpName %bitsBuffer`. The `Texture2D[2]`→`uint64_t[2]` cast was invalid on every target (an `OpBitcast` of an image, GLSL `uint64_t(texture2D)`, HLSL E99999). Check the lowered operation, put `CHECK: result code = 0` first (it precedes the emitted source in the buffer), or add `CHECK-NOT: error` without the colon, since a validation failure prints `internal error 99999:` and `CHECK-NOT: error:` never fires on it ([false-greens page](slang-test-false-greens-and-verification-traps.md)). Re-run spirv/glsl SIMPLE lanes with `SLANG_RUN_SPIRV_VALIDATION=1 slang-test <dir>`, and try `-emit-spirv-via-glsl` for glslang's view of the GLSL row ([CHECK on a decl name passes on failed compiles](../learnings/1791426372496-slang-test-simple-check-decl-name-passes-on-failed.md); [filecheck=A,B is one prefix; `result code = 0` first](../learnings/1791427324960-slang-test-filecheck-a-b-is-one-prefix-the-second-.md)).

CI coverage gap: the macOS runners do not report the `ray-query` render feature, so every `//TEST(compute, metal):COMPARE_COMPUTE_EX … -render-feature ray-query` lane is IGNORED there (e.g. `tests/metal/ray-query-intrinsics.slang.2 (mtl)`, run 37043131359). For Metal ray-query the metallib compile is the only check against Apple's toolchain, so do not describe the runtime lane as a CI hardware check. Confirm a lane's CI status with `gh run view <run> -R shader-slang/slang --job <id> --log | grep <test>` (`gh api …/jobs/<id>/logs` returned 410 through the proxy).

**A `-NOT` after a stdout match never sees stderr.** The buffer is built as `result code`, then `standard error = {…}`, then `standard output = {…}` (`slang-test-main.cpp:2222-2230`), and a `-NOT` scans only the region after the preceding positive match. Consider this pair from a CUDA texture test:

```
//FLOAT: tex2DLod<float4
//FLOAT-NOT: static assertion failed
```

The positive match lands in stdout, so the `-NOT` never reaches the stderr above it, where the diagnostic would print; and a real `static_assert` failure would also suppress the positive match, so the pair can never fail on the NOT. The pattern sits in `tests/diagnostics/cuda-half-texture-sample-level.slang` and was copied into #13559's SampleGrad test. That sibling also cites "#12185", an unrelated spvBindlessTextureNV issue, so check a citation with `gh api` before copying it. To assert "no diagnostics", use an annotation-free `//DIAGNOSTIC_TEST:SIMPLE(diag=X):` on the same entry point (exhaustive mode fails on any unannotated diagnostic), or move the `-NOT` above the first stdout match. A leading `-NOT` scans only up to the first positive match, so a whole-file negative needs its own `filecheck=` prefix ([`[noRefInline]` test: whole-file negatives need their own prefix](../learnings/1791604550352-slang-noinline-does-not-keep-a-ref-helper-use-nore.md)). On #13559 the Reviewer A CLI died three runs in a row (it ends its turn with background subagents still running); running the read-only cross-backend, documentation-accuracy, and test-coverage reviewers on a saved diff was a workable stand-in ([a `-NOT` after a stdout match never checks stderr](../learnings/1791607903034-slang-test-simple-a-not-on-a-diagnostic-placed-aft.md); [verify copied citations](../learnings/1791608967955-slang-test-not-checks-after-a-stdout-match-never-s.md)).

## DIAGNOSTIC_TEST annotations the parser never sees: `-NOT` lines and `// CHECK:` with a space

`parseAnnotations` in `tools/slang-test/diagnostic-annotation-util.cpp` looks only for `//PREFIX:` and `/*PREFIX:` markers (the colon is required) and has no negative-check handling. A line like `//SCOPE-NOT: E36107` is ignored, and under `non-exhaustive` the test passes even when the diagnostic fires: `tests/diagnostics/capability-generic-struct-entrypoint-param.slang` passes its SCOPE case on master although slangc emits E36107 for `mainScope` (via `Foo.init`), and the #13579 triage found 17 test files with inert `-NOT` lines under DIAGNOSTIC_TEST prefixes. To assert absence, use an exhaustive DIAGNOSTIC_TEST with no annotations (any diagnostic then fails it) or a filecheck-based test ([DIAGNOSTIC_TEST has no -NOT directive](../learnings/1791842377952-diagnostic-test-has-no-not-directive-prefix-not-li.md)). The capability-propagation finding from the same triage is on [[wiki/concepts/slangc-target-coverage-and-capabilities.md]].

The same marker rule makes a spaced annotation inert. The parser builds the marker as `"//" << prefix << ":"`, so only `//CHECK:` or `/*CHECK:` with no space after the comment opener matches. `// CHECK: error[E39033]` asserts nothing: on shader-slang/slang#13724 R1 the test still passed after the code was changed to `E12345` or to bogus text. Put an error code in a caret annotation such as `^^^^ error E39033` (see `docs/diagnostics.md`), and in review, mutate the code and re-run ([`// CHECK:` with a space is silently ignored](../learnings/1792198981359-slang-test-diagnostic-test-check-with-a-space-is-s.md)). A space AFTER the colon (`//CHECK: ^^^`) is a different trap that shifts the caret columns; it is on [slang-test False Greens](slang-test-false-greens-and-verification-traps.md).
