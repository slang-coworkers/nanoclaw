# Slang Test — Output Assertions and Truncated Runs

How a slang-test run goes **green while asserting nothing about a failing compile or a curtailed run**: output-path and exit-status assertions, `OpString` self-match, SIMPLE lanes that ignore the result code, inert DIAGNOSTIC_TEST annotations, and the `100% of tests passed` fake-pass on a truncated run. FileCheck authoring, `CHECK-NOT` regions and opt-levels: [Slang Test — FileCheck Authoring and Opt-Levels](slang-test-filecheck-authoring-and-opt-levels.md). Directive authoring: [part 1](slang-misc-test-harness.md). Running the harness and its false greens: [slang-test False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md).

## TL;DR

- **Never write a dump-based FileCheck test to `-o /dev/null`.** It is Windows-invalid (`E00004`, exit 255), yet `-dump-ir` already printed the matched text, so the test stays green. Use `-o -` plus a status assertion. Linux negative control: `-o /nonexistent-dir/out.spv`.
- **Prefer `-o -` to dropping `-o`: with `-g`, dropping `-o` switches to `-whole-program` mode.**
- **Bugs that need several entry points in one module hide from slangc-to-stdout and plain `//TEST:SIMPLE`** (one entry point at a time); only `-o <file>` or `-whole-program` emits one module and fires link-time checks. A binary target such as `slangvm` on a SIMPLE lane needs `filecheck=` with a positive `CHECK: --START--`. render-test compiles `computeMain` only and ignores `-entry` (else E38000).
- **Write `result code = {{0}}`, not `result code = 0`.** Under `-g` the IR dump embeds the source, so the literal matches its own echoed comment. `{{N}}` is a regex; `{N}` is inert.
- **The `OpString` self-match is the same family**: a `CHECK-NOT` or `CHECK-DAG` can match its own echoed comment. Break the literal and anchor on the opcode; count with `grep -cE 'OpExtInst.*<Op>'`, never a bare `grep -c '<Op>'`.
- **Before #14269 (2026-11-04) `//TEST:SIMPLE(filecheck=…)` never checked the result code; since then a non-zero exit fails unless the lane says `exit-code=N`** (`diag=` lanes still unchecked, #14266). On older branches error output echoes the source line, so `X: computeMain` matches a failed compile: use a success-only pattern (`define void @computeMain`, `__global__ void computeMain(`) or `result code = {{0}}`. A bare `X-NOT: error` matches the `standard error = {` header, and a NOT-only lane gates on nothing: anchor it first (`X: OpEntryPoint` or `result code = {{0}}`) and re-run the revert drill after adding any row.
- **COMPARE_COMPUTE compares stderr: any compile warning fails the lane even with a correct buffer.** Fix the warning, or for deliberately deprecated syntax add `-xslang -Wno-<code>` to each COMPARE_COMPUTE line.
- **A `CHECK: <decl-name>` on a spirv/glsl lane passes on a failed compile.** Check the lowered op, put `result code = 0` first, and run with `SLANG_RUN_SPIRV_VALIDATION=1` (CI sets it).
- **A `-NOT` after a stdout match never sees stderr** (buffer order: result code, stderr, stdout). Assert "no diagnostics" with an annotation-free `//DIAGNOSTIC_TEST:SIMPLE(diag=X):`, or put the NOT before the first stdout match.
- **DIAGNOSTIC_TEST has no `-NOT` directive, and `// CHECK:` with a space is inert** (the marker is `"//" << prefix << ":"`). Assert absence with an exhaustive, annotation-free test; pin codes in a caret annotation (`^^^^ error E39033`) and mutate the code to prove the row is live.
- **`100% of tests passed (264/264)` can be a run TRUNCATED by the consecutive-failure breaker.** `PendingRetry` failures never enter the total, and the bail notice goes to stderr, so `2>/dev/null | grep '% of tests passed'` hides it.
- **Grep `2>&1` for `% of tests passed|Stopped scheduling|Skipping retries|failed\(pending retry\)|failing tests`.** `failed(pending retry)` is the load-bearing term, validated both ways.
- **Never store a per-directory total as a constant, and never use `$?`** (slang-test exits 0 with failures). Derive counts in-session or run a neuter→run→restore→run drill. A positive control that returns zero means the control is wrong.
- **Under `-output-using-type`, anchor on the `type:` header and pin each value line** (`// BUF: type: uint32_t`, then `// BUF-NEXT: {{^}}2{{$}}`), or compute a distinctive value (`207`, not `2`). A bare `BUF: 2` matches inside `uint32_t`/`int32_t`; a comma-joined line never matches. Read `<test>.actual.txt` first.
- **`-bindir <other>/bin` is not an A/B**; slang-test loads its own libslang. Run master's own slang-test from its root, with one known-fails-on-master control.
- **Ask of every new test: what would have to break for this to stay green?** If "the compile fails" is an answer, add a status assertion.

## Output paths and status assertions: `-o /dev/null`, `-o -`, `result code = {{0}}`

**`-o /dev/null` is an anti-pattern**, fixed repo-wide in #12333 / PR #12334 (superseding an older note that called it idiomatic). On Windows slangc reports `error[E00004]: cannot write output file` and exits 255, but `-dump-ir` prints the matched IR before codegen reaches the failing write, and FileCheck sees no nonzero result code unless one is asserted; a reviewer caught it on #12281, CI did not ([`-o -` + `result code`](../learnings/1785775051459-dump-based-filecheck-tests-need-o-and-an-explicit-.md)). `-o -` and dropping `-o` are byte-identical for plain tests, but with `-g` dropping `-o` flips the driver into `-whole-program` mode (visible in the `-g` debug string).

**The status assertion has an inert spelling.** The buffer is `result code = <N>` / `standard error = {…}` / `standard output = {…}` (`slang-test-main.cpp:1876`). Under `-g` the IR dump embeds the source in `DebugSource("<path>", "<file text>")`, so `// PREFIX: result code = 0` matches its own echoed comment when the real line is `result code = 255`. `result code = {{0}}` passes a healthy compile and fails a forced failure; `{{N}}` is a regex, `{0}` is inert. The `-g2` `OpString` trap is the same family: `CHECK-NOT: DebugGlobalVariable` matches its own comment, and `CHECK-DAG: DebugGlobalVariable {{.*}} %payload` can pass with no real instruction. Confirm with `slangc … | grep -o 'CHECK-DAG: <your text>'` returning your own line; break the literal and anchor on the opcode (`OpExtInst {{.*}} Debug{{Global}}Variable`). Count with `grep -cE 'OpExtInst.*<Op>'`; a bare `grep -c '<Op>'` counts echoed comments (once 3 claimed to a maintainer, 1 real) ([pass without testing](../learnings/1785779116844-filecheck-tests-that-pass-without-testing-anything.md), [`-g` self-match](../learnings/1785787436624-never-use-o-dev-null-in-slang-tests-and-g-makes-re.md)).

The Linux negative control is `-dump-ir -o /nonexistent-dir/out.spv`: same `E00004`, exit 255, full dump, green test (e.g. `tests/autodiff/func-extension/subscript-accessor.slang`). Beneath this sits an ambient inert mode: without `libslang-llvm.so` (slang-test loads FileCheck from it in-process), `filecheck=` tests report `TestResult::Ignored`, not failed (`slang-test-main.cpp:815-822`). The shared full build has it in `build/Debug/lib/`; a fresh worktree that built only `slangc`/`slang-test` does not, and all its filecheck lanes go `ignored` until the lib is copied in ([ignored without libslang-llvm.so](../learnings/1791609372518-slang-test-silently-ignores-simple-filecheck-lanes.md); see [Verification discipline](misc-f0909b5-verification-discipline-and-tooling.md)). Either way, break one assertion and confirm RED before trusting green.

**A bug that needs several entry points in one module needs a one-module compile.** On #13687 (global `in`/`out` varyings shared by two entry points), slangc to stdout and plain `//TEST:SIMPLE` generate one entry point at a time and hide the bug; `-o <file>` or `-whole-program` emits one module. render-test always compiles `computeMain` alone (`-entry` is ignored; `-no-default-entry-point` asserts), so no GPU runtime test covers two-entry-point emission, and a `//TEST(compute, vulkan):COMPARE_COMPUTE` leg fails with E38000 "no function found matching entry point name 'computeMain'" if the entry is `main`, even with `-entry main` ([ignores -entry](../learnings/1792488875310-slang-test-compare-compute-ignores-entry-codex-cri.md), [vk leg E38000](../learnings/1793207048530-slang-formatting-sh-full-run-can-leave-a-committed.md)). Compiler side: `translateGlobalVaryingVar`'s `GlobalVariableShadowingGlobalParameterDecoration` lets `slang-ir-glsl-legalize.cpp` rewrite every use of the global, module-wide, to one entry point's Input var — correct only when one entry point reaches it; otherwise a shared struct `in` gives VUID-08721 and a scalar reads the wrong location, untested by 3,158 SPIR-V-validated tests ([one entry point at a time](../learnings/1792198835891-slang-multi-entry-point-bugs-slangc-stdout-and-sla.md)). The switch is `rawOutput.isWholeProgram` (`slang-options.cpp` ~4945), set by `-o <file>` or `-whole-program`; without it link-time checks over `irEntryPoints` never fire (on #14221 `-target slangvm` passed with no `-o` and failed the duplicate-name E38016 with `-o x.vm`). A plain `//TEST:SIMPLE:-target slangvm` fails even a clean compile (slangc dumps the binary as hex from `--START--` against an empty expectation); write `//TEST:SIMPLE(filecheck=CHECK):-target slangvm -whole-program` with a positive `// CHECK: --START--`. slangc drops a repeated `-entry X` only when it directly follows the same `-entry X` (`slang-options.cpp:3597`), so a "requested twice" test needs another `-entry` between ([whole-program depends on -o](../learnings/1793674479483-slangc-whole-program-depends-on-o-simple-tests-wit.md)).

## `100% of tests passed` on a truncated run: the `failed(pending retry)` grep

`slang-test` reports `100% of tests passed (264/264)` on a run truncated by its consecutive-failure breaker, because the disqualifying failures never enter the total. At `0864e60e6`, `slang-test-main.cpp:5121` returns early while `stopSchedulingTests` is set, so later tests never run; a `PendingRetry` result prints `failed(pending retry) '<name>'` and returns before `m_totalTestCount++` (`test-reporter.cpp:368-372`, increment `:378`), and once the breaker fires retries are skipped. Only `ignoredCount` is subtracted (`runTotal = rawTotal - ignoredCount`, `:694`). The percentage goes to stdout but the bail notice to `fprintf(stderr, …)` (`slang-test-main.cpp:6131-6137`), so `2>/dev/null | grep '% of tests passed'` discards the disqualifying fact by construction. Watch both numbers in `100% of tests passed (264/264), 94 tests ignored` (ignored and breaker paths are independent), and never use `$?` ([exact accounting](../learnings/1785837790090-correction-slang-test-denominator-check-measure-th.md)).

The pattern validated in both directions is `slang-test ... 2>&1 | grep -E '% of tests passed|Stopped scheduling|Skipping retries|failed\(pending retry\)|failing tests'`. `failed(pending retry)` is load-bearing: it prints to stdout (`test-reporter.cpp:371`), survives a stderr-dropping pipeline, and fired 265 times on a real truncated run against one bail-notice line; a healthy run shows only the pass line (`689/689`). Its first validation, pointed at a build log, returned zero matches: a zero-match positive control means the control is wrong ([grep proven both ways](../learnings/1785838168354-validated-grep-for-the-slang-test-fake-pass-failed.md)). Never store a per-directory total (`dynamic-dispatch=689`) as a constant (it ages into a phantom regression or an accepted truncation); derive it in-session, or run a neuter → run → restore → run drill.

## `-output-using-type` buffer checks, `-bindir`, and stderr warnings

With `-output-using-type`, the COMPARE_COMPUTE dump (`<test>.actual.txt`) opens with a type header (`type: uint32_t`) and prints one value per line, so a comma-joined `// CHECK: 3.0, 1.0` never matches and FAILS correct values (#13611 triage nearly misreported a PR) ([one value per line](../learnings/1791922190410-slang-test-filecheck-buffer-prints-one-value-per-l.md)). A bare `// BUF: 2` matches the `2` inside `uint32_t` and passes whatever the kernel wrote (slang#13412, where master really wrote `1`); `// CHECK: 2` matches inside `type: int32_t` the same way (PR #13503) ([int32_t header](../learnings/1791411328355-diagnostic-test-caret-columns-use-check-blocks-for.md)), and on slang#13966 R2 a reviewer's probe of a 1-vs-2 change "passed" on the broken build; a probe can instead compute a distinctive value (`x * 100 + 7`, check `207` vs `107`) ([small digits vacuous](../learnings/1793153753122-filecheck-buffer-with-output-using-type-small-digi.md)). With `X-NEXT` lines after it, the mis-anchor shifts every check by one line and FAILS correct output, which reads as a codegen bug (#13363, first L40S run) ([anchor on `type:`](../learnings/1792570875618-slang-test-output-using-type-anchor-the-first-buf-.md)). Anchor past the header and pin each whole line — `// BUF: type: uint32_t`, then `// BUF-NEXT: {{^}}2{{$}}` per value, as `tests/compute/half-*.slang` do — and read `.actual.txt` before trusting either verdict.

**`-bindir` is not an A/B.** `slang-test -bindir <other-build>/bin tests/x.slang` still runs the invoking tree's compiler for SIMPLE and COMPARE_COMPUTE, because slang-test loads its own libslang through RUNPATH (seen on #13412, where master "passed" a test it fails, and #13700 R4; reason confirmed on #13687) ([`-bindir` doesn't switch](../learnings/1792215112632-slang-test-bindir-does-not-switch-compare-compute-.md); mechanism on [Release-Build Divergences](slang-build-release-divergences-and-sanitizers.md)). Run the baseline's own slang-test from its root with one known-fails-on-master control. Also from #13412: a CPU lane loads the whole module, so one barrier entry point anywhere in the file fails it with E36107 ([`BUF: 2`; `-bindir`](../learnings/1791162065748-slang-test-filecheck-buf-2-vacuously-matches-type-.md)).

**COMPARE_COMPUTE compares stderr, so any compile warning fails the lane** with `EXPECTED standard error = {}` beside the warning, on cpu, vk and cuda alike, even when the buffer matches — measured with E41016 (uninitialized variable) on #13412 and front-end E30514 ("loop runs zero times") on #13985 / PR #13993, where a runtime test needed a warning fix as well as the codegen fix ([E30514](../learnings/1793220323154-slang-compare-compute-fails-on-any-stderr-warning-.md)). A test using deprecated syntax on purpose, such as vector `?:` (warning 30056), passes `-xslang -Wno-30056` on each COMPARE_COMPUTE line, as `tests/language-feature/scalar-ternary-op-short-and-non-short-circuit.slang` does ([`-Wno-30056`](../learnings/1793197057690-compare-compute-fails-on-any-stderr-warning-critiq.md)).

## SIMPLE+filecheck did not gate on the result code before #14269

Since #14269 (2026-11-04) slang-test fails a `SIMPLE(filecheck=X)` lane whose slangc exit code differs from `exit-code=N` (default 0), so an intended-error lane needs `(filecheck=X,exit-code=-1)`; REFLECTION/INTERPRET got the check in #14299, `diag=` lanes not yet (#14266) ([#14269 rule](../learnings/1793897749447-slang-test-now-fails-filecheck-simple-tests-on-non.md); fallout on [the nightly triage page](slang-tooling-docs-generated-nightly-triage.md)). The rest of this section describes older branches, where a `//TEST:SIMPLE(filecheck=X):` test passed whenever its pattern matched anywhere in the buffer: `runSimpleTest` calls `_validateOutput(..., forceFailure=false, ...)`, and the FileCheck branch returns `_fileCheckTest(...)` without reading `result code` (`tools/slang-test/slang-test-main.cpp` ~989-991, 3234-3238). Pair every FileCheck with positive evidence of success (a success-only pattern or `result code = {{0}}`) (same rule as the `CHECK-NOT`-only case on [slang-b-test-harness](slang-b-test-harness.md)).

- **Errors echo the source line.** Downstream Metal errors quote the offending line, so `// LIB: computeMain` on `-target metallib` matched a rejected kernel signature on #12294 R2 (R1 had relayed it as proof) ([never gates](../learnings/1790702677475-slang-test-simple-filecheck-never-gates-on-the-res.md), [ignores the result](../learnings/1790704590796-slang-test-simple-filecheck-ignores-the-compile-re.md)). Use `// METALLIB: define void @computeMain` (`tests/metal/simple-compute.slang:22`) or a lowered intrinsic such as `sample_compare_depth_2d`. On #13413 R1, `// X: <entryName>` passed after Apple's compiler rejected the MSL; gate with `// X: result code = 0` (`{{0}}` under `-g`) plus `// X: define {{.*}} @<entry>` ([exit code ignored](../learnings/1790977463190-slang-test-simple-filecheck-lanes-ignore-slangc-s-.md)). Slang's own located diagnostics do too (#13843: two E41014 errors passed a `//X: computeMain` control lane). Match the emitted signature (`//X: __global__ void computeMain(` for CUDA, `//X: {{\[\[kernel\]\]}} void computeMain(` for Metal, since `[[` is FileCheck syntax) and add `//X-NOT: error[E`. A bare `error` matches the `standard error = {` header (so a leading `X-NOT: error` fails even a clean compile, #14221), and legacy `internal error 99999:` lacks the `[E`, so the positive signature is the load-bearing half ([control lanes](../learnings/1792629381882-slang-test-simple-filecheck-computemain-control-la.md), ["error" matches the wrapper](../learnings/1793686330054-filecheck-traps-in-slang-test-simple-lanes-error-m.md)). That atom's caret-column note is the `/*X:` … `*/` block rule on [slang-b-test-harness](slang-b-test-harness.md).
- **A NOT-only lane gates on nothing.** `// PREFIX-NOT: error :` alone passed a throwaway test where `-entry doesNotExist` made slangc fail. Slang's diagnostics print `error[E38000]: …` (only downstream ones use `<file>(<line>): error <code>:`), and `failed to load downstream compiler` is ignored, not failed. Pair the NOT with `// PREFIX: result code = 0` (as `tests/metal/mesh-index-expression.slang:13` does) or `METALLIB: @entryName`; seen on #12294 R2, #13413 R1 and #13421 G2, so check every new `-target metallib` lane ([NOT-only lane](../learnings/1791009233810-a-not-only-x-not-error-filecheck-lane-passes-when-.md)). SPIR-V lanes fail the same way: on #13988 an `-emit-spirv-via-glsl` row with only `SPV-NOT: … SAbs` passed on master because glslang rejected `abs(uint)` and the buffer held no `OpExtInst` at all (the revert drill predated those rows; a peer caught it on a base binary). Put a positive anchor first (`// X: OpEntryPoint`, used by 229 tests, or `// X: result code = 0`, used by 212), and after adding or changing any row re-run the revert drill on a pre-fix binary ([only CHECK-NOT](../learnings/1793216878744-slang-test-simple-filecheck-with-only-check-not-pa.md), [only -NOT lines](../learnings/1793220332838-a-filecheck-block-of-only-not-lines-passes-when-th.md)).
- **A declaration name proves nothing on SPIR-V/GLSL.** On #13507, `bit-cast-resource-array.slang` (`-target spirv`, one `// CHECK: bitsBuffer`) passed 22/22 locally but fails under `SLANG_RUN_SPIRV_VALIDATION=1`, which CI exports: the module dumped on a validation failure still has `OpName %bitsBuffer`. Check the lowered operation, put `CHECK: result code = 0` first (it precedes the emitted source), or use `CHECK-NOT: error` without the colon, since a validation failure prints `internal error 99999:`. Re-run spirv/glsl lanes with `SLANG_RUN_SPIRV_VALIDATION=1`; `-emit-spirv-via-glsl` gives glslang's view ([decl name](../learnings/1791426372496-slang-test-simple-check-decl-name-passes-on-failed.md); [filecheck=A,B is one prefix](../learnings/1791427324960-slang-test-filecheck-a-b-is-one-prefix-the-second-.md)).

CI gap: macOS runners lack the `ray-query` render feature, so every metal `COMPARE_COMPUTE_EX … -render-feature ray-query` lane is IGNORED there; the metallib compile is the only check against Apple's toolchain. Confirm a lane's CI status with `gh run view <run> -R shader-slang/slang --job <id> --log | grep <test>` (`gh api …/logs` returns 410 via the proxy).

**A `-NOT` after a stdout match never sees stderr.** The buffer is `result code`, then `standard error = {…}`, then `standard output = {…}` (`slang-test-main.cpp:2222-2230`), and a `-NOT` scans only the region after the preceding positive match. Consider this pair from a CUDA texture test:

```
//FLOAT: tex2DLod<float4
//FLOAT-NOT: static assertion failed
```

The positive match lands in stdout, so the `-NOT` never reaches the stderr above it (and a real `static_assert` failure would suppress the positive match anyway). It sits in `tests/diagnostics/cuda-half-texture-sample-level.slang` and was copied into #13559's test, along with a wrong "#12185" citation — check citations with `gh api` before copying ([never sees stderr](../learnings/1791607903034-slang-test-simple-a-not-on-a-diagnostic-placed-aft.md); [verify citations](../learnings/1791608967955-slang-test-not-checks-after-a-stdout-match-never-s.md)). To assert "no diagnostics", use an annotation-free `//DIAGNOSTIC_TEST:SIMPLE(diag=X):` on the same entry point, or move the `-NOT` above the first stdout match. A leading `-NOT` scans only up to the first positive match, so a whole-file negative needs its own `filecheck=` prefix ([own prefix](../learnings/1791604550352-slang-noinline-does-not-keep-a-ref-helper-use-nore.md)).

## DIAGNOSTIC_TEST annotations the parser never sees: `-NOT` lines and `// CHECK:` with a space

`parseAnnotations` (`tools/slang-test/diagnostic-annotation-util.cpp`) looks only for `//PREFIX:` and `/*PREFIX:` markers, with no negative-check handling. `//SCOPE-NOT: E36107` is ignored, and under `non-exhaustive` the test passes even when the diagnostic fires (`tests/diagnostics/capability-generic-struct-entrypoint-param.slang` on master); the #13579 triage found 17 files with inert `-NOT` lines under DIAGNOSTIC_TEST prefixes. Assert absence with an exhaustive DIAGNOSTIC_TEST with no annotations, or a filecheck test ([no -NOT directive](../learnings/1791842377952-diagnostic-test-has-no-not-directive-prefix-not-li.md)). The capability-propagation finding from that triage is on [[wiki/concepts/slangc-target-coverage-and-capabilities.md]].

The marker is built as `"//" << prefix << ":"`, so only `//CHECK:` or `/*CHECK:` with no space after the comment opener matches. `// CHECK: error[E39033]` asserts nothing: on #13724 R1 the test still passed with the code changed to `E12345`. Put an error code in a caret annotation such as `^^^^ error E39033` (see `docs/diagnostics.md`), and in review mutate the code and re-run ([space ignored](../learnings/1792198981359-slang-test-diagnostic-test-check-with-a-space-is-s.md)). A space AFTER the colon (`//CHECK: ^^^`) shifts the caret columns instead; see [slang-test False Greens](slang-test-false-greens-and-verification-traps.md).

## Contradictions / supersessions

- **`slang-test`'s process exit code as a pass/fail signal** — it returned **0 on a FAILED test**, and exits 0 even with failing tests in a truncated run. Parse the `FAILED test:` / `% of tests passed` / `failed(pending retry)` lines, never `$?`.
- **"6 tests committed" as a coverage figure** — narrowed in place under *Count assertion-bearing tests* in [slang-test False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md): count assertion-bearing tests only (3 of the 6 files), and name the single discriminating case.
