# Slang Test — Output Assertions and Truncated Runs

How a slang-test run goes **green while asserting nothing about a failing compile or a curtailed run**. FileCheck authoring, `CHECK-NOT` regions and opt-levels: [Slang Test — FileCheck Authoring and Opt-Levels](slang-test-filecheck-authoring-and-opt-levels.md). Directive authoring: [part 1](slang-misc-test-harness.md). Running the harness and its false greens: [slang-test False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md).

## TL;DR

- **Never write a dump-based FileCheck test to `-o /dev/null`**: Windows-invalid (`E00004`, exit 255), yet `-dump-ir` already printed the matched text, so it stays green. Use `-o -` plus a status assertion. Linux negative control: `-o /nonexistent-dir/out.spv`.
- **Bugs that need several entry points in one module hide from slangc-to-stdout and plain `//TEST:SIMPLE`**; only `-o <file>` or `-whole-program` emits one module and fires link-time checks. render-test compiles `computeMain` only and ignores `-entry` (else E38000).
- **An ownership/scoping change can pass the suite and a corpus diff yet break the issue's own repro** (#14395, E58001). Compile the repro per stage with `-entry`, as a whole module, AND as several `.slang` files on one slangc command line (they form ONE module), against master.
- **Write `result code = {{0}}`, not `result code = 0`**: under `-g` the dump embeds the source, so the literal matches its own echoed comment. `CHECK-NOT`/`CHECK-DAG` on `OpString` self-match the same way: break the literal, anchor on the opcode, count with `grep -cE 'OpExtInst.*<Op>'`.
- **Since #14269 (2026-11-04) a `SIMPLE(filecheck=…)` lane fails on a non-zero exit unless it says `exit-code=N`** (`diag=` lanes and `.expected` tests since #14422, default -1); intended-error `DIAGNOSTIC_TEST:SIMPLE(filecheck=X)` rows need `exit-code=-1`, and since #14355 `filecheck=`+`diag=` together and unused `.expected` files are errors. On older branches the lane passed on a failed compile (errors echo the source line): use a success-only pattern (`define void @computeMain`) or `result code = {{0}}`.
- **A bare `X-NOT: error` matches the `standard error = {` header, and a NOT-only lane gates on nothing**: anchor first (`X: OpEntryPoint` or `result code = {{0}}`) and re-run the revert drill after any row change. A `CHECK: <decl-name>` on spirv/glsl passes on a failed compile: check the lowered op. Old-format NOT text (`E39999: …`, `error 39999`, `warning 41020`) never matches `error[E39999]:`; warnings also escape the exit-code backstop, so sweep with `-NOT:.*\b(error|warning|note) [0-9]|-NOT:.*\bE[0-9]{5}:`.
- **COMPARE_COMPUTE compares stderr: any warning fails the lane** despite a correct buffer; fix it, or add `-xslang -Wno-<code>` per line.
- **A `-NOT` after a stdout match never sees stderr** (order: result code, stderr, stdout): put the NOT first, or use an annotation-free `//DIAGNOSTIC_TEST:SIMPLE(diag=X):`.
- **DIAGNOSTIC_TEST has no `-NOT` directive, and `// CHECK:` with a space is inert.** Assert absence with an exhaustive, annotation-free test; pin codes in a caret annotation (`^^^^ error E39033`) and mutate the code to prove the row is live.
- **`100% of tests passed (264/264)` can be a run truncated by the consecutive-failure breaker**: `PendingRetry` failures never enter the total and the bail notice goes to stderr. Grep `2>&1` for `% of tests passed|Stopped scheduling|Skipping retries|failed\(pending retry\)|failing tests`.
- **Never store a per-directory total as a constant or use `$?`** (exit 0 with failures); derive counts in-session or run a neuter→run→restore→run drill. A zero-match positive control is itself wrong.
- **Under `-output-using-type`, anchor on the `type:` header and pin each value line** (`// BUF: type: uint32_t`, then `// BUF-NEXT: {{^}}2{{$}}`), or compute a distinctive value (`207`, not `2`). A bare `BUF: 2` matches inside `uint32_t`/`int32_t`; a comma-joined line never matches. Read `<test>.actual.txt` first.
- **`-bindir <other>/bin` is not an A/B** (slang-test loads its own libslang): run master's own slang-test, with a known-fails-on-master control.
- **Ask what would have to break for a new test to stay green**; if "the compile fails", add a status assertion.

## Output paths and status assertions: `-o /dev/null`, `-o -`, `result code = {{0}}`

**`-o /dev/null` is an anti-pattern**, fixed repo-wide in #12333 / PR #12334. On Windows slangc reports `error[E00004]: cannot write output file` and exits 255, but `-dump-ir` prints the matched IR before the failing write, and FileCheck sees no nonzero result code unless one is asserted; a reviewer caught it on #12281, CI did not ([`-o -` + `result code`](../learnings/1785775051459-dump-based-filecheck-tests-need-o-and-an-explicit-.md)). `-o -` and no `-o` are byte-identical for plain tests, but with `-g` dropping `-o` flips the driver into `-whole-program` mode.

**The status assertion has an inert spelling.** The buffer is `result code = <N>` / `standard error = {…}` / `standard output = {…}` (`slang-test-main.cpp:1876`). Under `-g` the dump embeds the source in `DebugSource(…)`, so `// PREFIX: result code = 0` matches its own comment when the real line is `result code = 255`; `result code = {{0}}` (`{{N}}` is a regex; `{N}` is inert) passes a healthy compile and fails a forced failure. The `-g2` `OpString` trap is the same: `CHECK-NOT: DebugGlobalVariable` matches its own comment and `CHECK-DAG: DebugGlobalVariable {{.*}} %payload` can pass with no real instruction. Confirm with `slangc … | grep -o 'CHECK-DAG: <text>'`; anchor on the opcode (`OpExtInst {{.*}} Debug{{Global}}Variable`). A bare `grep -c '<Op>'` counts echoed comments (3 claimed, 1 real) ([pass without testing](../learnings/1785779116844-filecheck-tests-that-pass-without-testing-anything.md), [`-g` self-match](../learnings/1785787436624-never-use-o-dev-null-in-slang-tests-and-g-makes-re.md)).

The Linux negative control `-dump-ir -o /nonexistent-dir/out.spv` reproduces it (`tests/autodiff/func-extension/subscript-accessor.slang`). An ambient inert mode sits beneath: without `libslang-llvm.so` (slang-test loads FileCheck from it in-process), `filecheck=` tests report `TestResult::Ignored`, not failed (`slang-test-main.cpp:815-822`); a fresh worktree that built only `slangc`/`slang-test` goes all-`ignored` until it is copied in from the full build's `build/Debug/lib/` ([ignored without libslang-llvm.so](../learnings/1791609372518-slang-test-silently-ignores-simple-filecheck-lanes.md); see [Verification discipline](misc-f0909b5-verification-discipline-and-tooling.md)). Either way, break one assertion and confirm RED before trusting green.

**A bug that needs several entry points in one module needs a one-module compile.** On #13687 (global `in`/`out` varyings shared by two entry points), slangc to stdout and plain `//TEST:SIMPLE` generate one entry point at a time and hide the bug. render-test compiles only `computeMain` (`-entry` ignored; `-no-default-entry-point` asserts), so no GPU test covers two-entry-point emission; a vulkan leg with entry `main` fails E38000 even with `-entry main` ([ignores -entry](../learnings/1792488875310-slang-test-compare-compute-ignores-entry-codex-cri.md), [vk leg E38000](../learnings/1793207048530-slang-formatting-sh-full-run-can-leave-a-committed.md)). Compiler side: `GlobalVariableShadowingGlobalParameterDecoration` (from `translateGlobalVaryingVar`) lets `slang-ir-glsl-legalize.cpp` rewrite every use of the global, module-wide, to one entry point's Input var; with two entry points a shared struct `in` gives VUID-08721 and a scalar reads the wrong location ([one entry point at a time](../learnings/1792198835891-slang-multi-entry-point-bugs-slangc-stdout-and-sla.md)). The switch is `rawOutput.isWholeProgram` (`slang-options.cpp` ~4945), set by `-o <file>` or `-whole-program`; without it link-time checks over `irEntryPoints` never fire (#14221: `-target slangvm` passed with no `-o` and failed duplicate-name E38016 with `-o x.vm`). A plain `//TEST:SIMPLE:-target slangvm` fails a clean compile (hex dump vs empty expectation); write `//TEST:SIMPLE(filecheck=CHECK):-target slangvm -whole-program` with `// CHECK: --START--`. slangc drops a repeated `-entry X` only when it directly follows the same `-entry X` (`slang-options.cpp:3597`), so a "requested twice" test needs another `-entry` between ([whole-program depends on -o](../learnings/1793674479483-slangc-whole-program-depends-on-o-simple-tests-wit.md)).

**An ownership or scoping redesign can be green on its suite and still break the issue's repro.** On #14395 (stage 1 of #14375: each entry point owns all module-scope varyings) the suite and a 91-file corpus diff were clean, yet the issue's repro (vertex + fragment shader in one module, global `out float4 gPos : SV_Position`) failed the fragment entry point with E58001 and E30702 on a global it never uses; master compiles it, and `loadModule` fails too since it validates every `[shader]` entry point. Existing multi-stage tests use `-entry`, so none sees the whole-module shape. `slangc vs.slang fs.slang -entry vsMain ... -entry fsMain ...` is the same shape: all Slang source files form one translation unit and so one module (HLSL gets one TU per file), and #14395 gave E30702 there too. So any per-module rule (ownership, a marker, a "module has X" warning) needs that probe, plus a binary import: a FIDDLE `Modifier` on `ModuleDecl` is serialized into `.slang-module`, and since binary modules skip semantic checking, a test proves it takes the binary path by relying on a warning only source checking would emit [several .slang files form one module](../learnings/1794271641326-slang-several-slang-files-on-one-slangc-command-li.md). Side trap: a `LANG_SERVER` test with a `//DIAGNOSTICS` line hangs in `waitForResponse` even on master; use `//HOVER:` ([compile the issue's own repro first](../learnings/1794019004705-ownership-semantics-redesign-prs-compile-the-issue.md)).

## `100% of tests passed` on a truncated run: the `failed(pending retry)` grep

The disqualifying failures never enter the total. At `0864e60e6`, `slang-test-main.cpp:5121` returns early once `stopSchedulingTests` is set; a `PendingRetry` result prints `failed(pending retry) '<name>'` and returns before `m_totalTestCount++` (`test-reporter.cpp:368-372`, increment `:378`), and once the breaker fires retries are skipped. Only `ignoredCount` is subtracted (`runTotal = rawTotal - ignoredCount`, `:694`). The bail notice goes to `fprintf(stderr, …)` (`slang-test-main.cpp:6131-6137`), so `2>/dev/null | grep '% of tests passed'` discards it. Ignored and breaker paths are independent (`100% … (264/264), 94 tests ignored`) ([exact accounting](../learnings/1785837790090-correction-slang-test-denominator-check-measure-th.md)).

`failed(pending retry)` prints to stdout (`test-reporter.cpp:371`), survives a stderr-dropping pipeline, and fired 265 times on a real truncated run against one bail-notice line; a healthy run shows only the pass line (`689/689`) ([grep proven both ways](../learnings/1785838168354-validated-grep-for-the-slang-test-fake-pass-failed.md)). A stored per-directory total ages into a phantom regression or accepted truncation.

## `-output-using-type` buffer checks, `-bindir`, and stderr warnings

The COMPARE_COMPUTE dump (`<test>.actual.txt`) opens with a type header (`type: uint32_t`) and prints one value per line, so a comma-joined `// CHECK: 3.0, 1.0` FAILS correct values (#13611) ([one value per line](../learnings/1791922190410-slang-test-filecheck-buffer-prints-one-value-per-l.md)). A bare `// BUF: 2` matches the `2` inside `uint32_t` and passes whatever the kernel wrote (slang#13412); `// CHECK: 2` matches inside `type: int32_t` the same way: PR #13503 ([int32_t header](../learnings/1791411328355-diagnostic-test-caret-columns-use-check-blocks-for.md)), #14380 ("passed" while the buffer held 1) ([`CHECK: 2` vs `type: int32_t`](../learnings/1793951018748-slang-test-filecheck-buffer-check-2-passes-falsely.md)), and #13966 R2 (a 1-vs-2 probe "passed" on the broken build); a probe can compute a distinctive value (`x * 100 + 7`, check `207` vs `107`) ([small digits vacuous](../learnings/1793153753122-filecheck-buffer-with-output-using-type-small-digi.md)). With `X-NEXT` lines after it, the mis-anchor shifts every check by a line and FAILS correct output (#13363) ([anchor on `type:`](../learnings/1792570875618-slang-test-output-using-type-anchor-the-first-buf-.md)). Pin whole lines (`tests/compute/half-*.slang`).

**`-bindir <other-build>/bin` still runs the invoking tree's compiler** for SIMPLE and COMPARE_COMPUTE, because slang-test loads its own libslang through RUNPATH (#13412, where master "passed" a test it fails; #13700; #13687) ([`-bindir` doesn't switch](../learnings/1792215112632-slang-test-bindir-does-not-switch-compare-compute-.md); see [Release-Build Divergences](slang-build-release-divergences-and-sanitizers.md)). Also from #13412: a CPU lane loads the whole module, so one barrier entry point anywhere in the file fails it with E36107 ([`BUF: 2`; `-bindir`](../learnings/1791162065748-slang-test-filecheck-buf-2-vacuously-matches-type-.md)).

**COMPARE_COMPUTE fails on any compile warning** with `EXPECTED standard error = {}`, on cpu, vk and cuda, even when the buffer matches: E41016 (uninitialized variable) on #13412, E30514 ("loop runs zero times") on #13985 ([E30514](../learnings/1793220323154-slang-compare-compute-fails-on-any-stderr-warning-.md)). Deliberately deprecated syntax such as vector `?:` (warning 30056) passes `-xslang -Wno-30056` per line (see `tests/language-feature/scalar-ternary-op-short-and-non-short-circuit.slang`) ([`-Wno-30056`](../learnings/1793197057690-compare-compute-fails-on-any-stderr-warning-critiq.md)); `-Xslang -warnings-disable -Xslang <code>` also works, and a PR adding a new warning must update every lane that now emits it (#14395) ([new warnings](../learnings/1794014892301-slang-a-legacy-slang-file-silently-becomes-languag.md)).

## SIMPLE+filecheck did not gate on the result code before #14269

Since #14269 (2026-11-04) slang-test fails a `SIMPLE(filecheck=X)` lane whose exit code differs from `exit-code=N` (default 0), so an intended-error lane needs `(filecheck=X,exit-code=-1)`; REFLECTION/INTERPRET got the check in #14299, and `diag=` lanes and `.expected` tests in #14422 (2026-11-10, default -1; pick N by the whole run's outcome: warnings/notes only → 0, option-parser error → 1 [diag= exit codes](../learnings/1794331397967-diag-exit-codes-decide-by-the-whole-run-s-outcome-.md)) ([#14269 rule](../learnings/1793897749447-slang-test-now-fails-filecheck-simple-tests-on-non.md); fallout on [the nightly triage page](slang-tooling-docs-generated-nightly-triage.md)). `//DIAGNOSTIC_TEST:SIMPLE(filecheck=X)` rows checking an intended error (e.g. error[E36107]) need it too, else "expected exit code 0, but the exit code is -1" with every CHECK matching; copy the bulk-updated tests' directive form. #14355 made `filecheck=` with `diag=` an error, and unused `.expected` files too ([exit-code=-1 rows](../learnings/1793988645605-slang-test-simple-diagnostic-test-rows-that-are-ex.md)). This supersedes the "never gates" atoms; the rest of this section holds on older branches, where `runSimpleTest` calls `_validateOutput(..., forceFailure=false, ...)` and the FileCheck branch returns `_fileCheckTest(...)` without reading `result code` (`tools/slang-test/slang-test-main.cpp` ~989-991, 3234-3238). Pair every FileCheck with positive evidence of success (as for the `CHECK-NOT`-only case on [slang-b-test-harness](slang-b-test-harness.md)).

- **Errors echo the source line.** Downstream Metal errors quote the offending line, so `// LIB: computeMain` on `-target metallib` matched a rejected kernel signature on #12294 R2 ([never gates](../learnings/1790702677475-slang-test-simple-filecheck-never-gates-on-the-res.md), [ignores the result](../learnings/1790704590796-slang-test-simple-filecheck-ignores-the-compile-re.md)). Use `// METALLIB: define void @computeMain` (`tests/metal/simple-compute.slang:22`) or a lowered intrinsic; on #13413 R1 `// X: <entryName>` passed after Apple's compiler rejected the MSL, so gate with `// X: result code = 0` (`{{0}}` under `-g`) plus `// X: define {{.*}} @<entry>` ([exit code ignored](../learnings/1790977463190-slang-test-simple-filecheck-lanes-ignore-slangc-s-.md)). Slang's own located diagnostics echo too (#13843: two E41014 errors passed a `//X: computeMain` lane). Match the emitted signature (`//X: __global__ void computeMain(` for CUDA, `//X: {{\[\[kernel\]\]}} void computeMain(` for Metal, since `[[` is FileCheck syntax) and add `//X-NOT: error[E`. A bare `error` matches the `standard error = {` header (a leading `X-NOT: error` fails even a clean compile, #14221), and legacy `internal error 99999:` lacks the `[E`, so the positive signature is the load-bearing half ([control lanes](../learnings/1792629381882-slang-test-simple-filecheck-computemain-control-la.md), ["error" matches the wrapper](../learnings/1793686330054-filecheck-traps-in-slang-test-simple-lanes-error-m.md)). Its caret-column note is the `/*X:` … `*/` block rule on [slang-b-test-harness](slang-b-test-harness.md).
- **A NOT-only lane gates on nothing.** `// PREFIX-NOT: error :` alone passed when `-entry doesNotExist` made slangc fail: Slang prints `error[E38000]: …` (only downstream compilers print `error <code>:`), and `failed to load downstream compiler` is ignored, not failed. Pair it with `// PREFIX: result code = 0` (`tests/metal/mesh-index-expression.slang:13`) or `METALLIB: @entryName` (#12294, #13413, #13421) ([NOT-only lane](../learnings/1791009233810-a-not-only-x-not-error-filecheck-lane-passes-when-.md)). On #13988 an `-emit-spirv-via-glsl` row with only `SPV-NOT: … SAbs` passed on master because glslang rejected `abs(uint)`; the revert drill predated the row. Put a positive anchor first (`// X: OpEntryPoint`, 229 tests, or `// X: result code = 0`, 212) and re-run the revert drill on a pre-fix binary after any row change ([only CHECK-NOT](../learnings/1793216878744-slang-test-simple-filecheck-with-only-check-not-pa.md), [only -NOT lines](../learnings/1793220332838-a-filecheck-block-of-only-not-lines-passes-when-th.md)).
- **Old-format diagnostic text in a `-NOT` line is vacuous.** The #14258 triage (2026-11-08) found three forms still in `tests/` that a `-NOT: error [1-9]` sweep misses: (1) `CHECK-NOT: E39999: …` never matches the real `error[E39999]: …` (the #14269 rewrite itself produced this form); (2) `CHK-NOT:error 39999`, no space after the colon; (3) `warning 41020`-style warnings, the dangerous ones, because a warning leaves the exit code unchanged and escapes the #14269 backstop. Sweep with `grep -rnE -- '-NOT:.*\b(error|warning|note) [0-9]|-NOT:.*\bE[0-9]{5}:' tests/`. Prove a pattern vacuous with a temp SIMPLE test that emits the diagnostic, NOT line BEFORE any positive anchor (a NOT scans only after the previous match; stderr precedes stdout): the old pattern passes, a bare `E<code>` fails ([old-format diagnostic sweeps](../learnings/1794140453890-old-format-diagnostic-sweeps-grep-for-e-code-and-w.md)).
- **A declaration name proves nothing on SPIR-V/GLSL.** On #13507 `bit-cast-resource-array.slang` (one `// CHECK: bitsBuffer`) passed locally but fails under CI's `SLANG_RUN_SPIRV_VALIDATION=1`: the module dumped on a validation failure still has `OpName %bitsBuffer`. Check the lowered operation, put `CHECK: result code = 0` first (it precedes the emitted source), or use `CHECK-NOT: error` without the colon, since a validation failure prints `internal error 99999:`; `-emit-spirv-via-glsl` gives glslang's view ([decl name](../learnings/1791426372496-slang-test-simple-check-decl-name-passes-on-failed.md); [filecheck=A,B is one prefix](../learnings/1791427324960-slang-test-filecheck-a-b-is-one-prefix-the-second-.md)).

CI gap: macOS runners lack `ray-query`, so metal `-render-feature ray-query` lanes are IGNORED there and the metallib compile is the only Apple-toolchain check. Confirm a lane's CI status with `gh run view <run> -R shader-slang/slang --job <id> --log | grep <test>` (not `gh api`).

**A `-NOT` after a stdout match never sees stderr.** The buffer is `result code`, then `standard error = {…}`, then `standard output = {…}` (`slang-test-main.cpp:2222-2230`), and a `-NOT` scans only the region after the preceding positive match. Consider this CUDA texture pair:

```
//FLOAT: tex2DLod<float4
//FLOAT-NOT: static assertion failed
```

The positive match lands in stdout, so the `-NOT` never reaches stderr. It sits in `tests/diagnostics/cuda-half-texture-sample-level.slang` and was copied into #13559 with a wrong "#12185" citation; check citations with `gh api` before copying ([never sees stderr](../learnings/1791607903034-slang-test-simple-a-not-on-a-diagnostic-placed-aft.md); [verify citations](../learnings/1791608967955-slang-test-not-checks-after-a-stdout-match-never-s.md)). A leading `-NOT` scans only up to the first positive match, so a whole-file negative needs its own `filecheck=` prefix ([own prefix](../learnings/1791604550352-slang-noinline-does-not-keep-a-ref-helper-use-nore.md)).

## DIAGNOSTIC_TEST annotations the parser never sees: `-NOT` lines and `// CHECK:` with a space

`parseAnnotations` (`tools/slang-test/diagnostic-annotation-util.cpp`) looks only for `//PREFIX:` and `/*PREFIX:` markers, with no negative checks: `//SCOPE-NOT: E36107` is ignored, and under `non-exhaustive` the test passes even when the diagnostic fires (`tests/diagnostics/capability-generic-struct-entrypoint-param.slang` on master); the #13579 triage found 17 files with inert `-NOT` lines ([no -NOT directive](../learnings/1791842377952-diagnostic-test-has-no-not-directive-prefix-not-li.md)). The capability-propagation finding from that triage is on [[wiki/concepts/slangc-target-coverage-and-capabilities.md]].

The marker is built as `"//" << prefix << ":"`, so `// CHECK: error[E39033]` asserts nothing: on #13724 R1 the test still passed with the code changed to `E12345`. Put the code in a caret annotation (`^^^^ error E39033`); in review mutate it and re-run ([space ignored](../learnings/1792198981359-slang-test-diagnostic-test-check-with-a-space-is-s.md)). A space AFTER the colon (`//CHECK: ^^^`) shifts the caret columns instead; see [slang-test False Greens](slang-test-false-greens-and-verification-traps.md).

## Contradictions / supersessions

- **slang-test's exit code**: **0 on a FAILED test** and on a truncated run. Parse `FAILED test:` / `% of tests passed` / `failed(pending retry)`.
- **"6 tests committed" as a coverage figure**: narrowed in [slang-test False Greens](slang-test-false-greens-and-verification-traps.md) to assertion-bearing tests (3 of 6), naming the discriminating case.
