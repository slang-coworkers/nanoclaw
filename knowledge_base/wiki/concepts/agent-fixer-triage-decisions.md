# Triage Decisions: Artifact Policy, Root-Cause Discipline & Routing

How the `nv-slang-bot[bot]` triage coworker classifies, routes, and posts on `shader-slang/slang` issues: GitHub artifact policy, root-cause verification, severity calls, cross-ref/dependency routing, and the coverage a recommended fix silently removes. Fixer PR creation/CI-fork mechanics are on [Fixer PR Creation, Fork & CI Mechanics](agent-fixer-pr-and-ci-mechanics.md); dispatch/coordination failure modes are on [Fixer Dispatch & Coordination Failure Modes](agent-fixer-dispatch-coordination.md).

## TL;DR

- **Post a verified 5-bullet on every triaged issue** on the bot's own authority. Exceptions: a non-draft PR carrying `Closes #N` *is* the artifact (a draft does NOT qualify); a maintainer's own RFC they are already driving, with nothing novel to add → stand down; a dev-authored design issue → post as INPUT (solution-space, not a verdict). On a new human-filed issue the post waits for the R6 4-day hold unless `bot-ok` or a crash-plus-code-block body exempts it; the workflow's "Always post" step does not enforce this, so check it at post time.
- **Authorship never excludes an issue by itself** (operator correction 2026-09-09; the "maintainer tracking placeholder = watch-only" rule is RETIRED). `Dev Opened`, a core-team author, self-assignment or a milestone → triage and dispatch the fixer. Exclude only when a human PR already fixes it, a maintainer asked bots to stay out, or the fix lands where the bot cannot push (hand the plan to the human owner).
- **Check the last comment first** (double-post prevention); **refresh a posted verdict when someone acts on its text**, not merely when it goes stale.
- **Hold an interim classification 5-bullet until terminal**; scoping questions and missing-reproducer requests may post pre-terminal.
- **Resolve the reporter's release before root-causing** — `git tag --contains <fix-commit>` turns "fixed on master" into "shipped in vX.Y"; the issue may collapse to a version bump, which moves version + hash + every per-platform SHA256 together.
- **Settle "would the fix even help?" with a same-image CI A/B** — grep the job log for `Image:` to prove a one-variable difference.
- **Empirically confirm root cause before fixing**; carry a hedge verbatim ("leading hypothesis (unconfirmed)", never "root cause (traced)"). Never pair a hunch with a suggested disposition — name the cheap measurement that settles it.
- **Any prior triage verdict (including your bot's) is a dated hypothesis to re-verify at HEAD**; when a premise is falsified, correct every sibling issue resting on it.
- **A "bug" on a deprecated feature is often working-as-specified** — read the spec proposal and grep `tests/` for a locking `//DIAGNOSTIC_TEST` first.
- **Pointer-formation UB** (a `cur+N` pointer only *compared*, derefs short-circuit-guarded) is a **P2** UBSan finding, not a P1 crash.
- **Re-triage via the cross-ref timeline + per-PR `files`**, and `gh pr list --search` for an existing `Fixes #N` PR. An in-flight human PR or a contributor **assignee** → routing decision to parent, never auto-dispatch.
- **A recommended path must name the coverage it REMOVES** — reflection is the frontend's *prediction*, not proof that lowering honored it.
- **Verify functional independence** before declaring a fix "stacks on" an unmerged PR; a dependency-bump regression is proven by **cross-platform comparison**.

## GitHub Artifact Posting Policy

The canonical rule: post a verified 5-bullet issue comment on **every triaged issue** on the bot's own authority ([SUPERSEDED: skip post on dev-authored design placeholder](../learnings/1781137483321-superseded-skip-github-post-on-dev-authored-design.md), [labeling, Issue Type and reproducer-request rules](../learnings/1781008579138-slang-triage-labeling-issue-type-and-reproducer-re.md)). Exceptions:

- **Fixed-via-PR**: a non-draft PR already carrying `Closes #N` *is* the artifact. A draft does NOT qualify — still post ([fixed-via-PR exception](../learnings/1780769170857-triage-github-artifact-fixed-via-pr-exception-reso.md)).
- **Maintainer RFC stand-down**: the maintainer's own roadmap RFC (no bot mention, maintainer already driving a fix PR) with no novel triage value → STAND DOWN (A2A disposition only); otherwise post a deferential artifact ([when to post vs stand down on a maintainer RFC](../learnings/1781266520028-triage-when-to-post-a-5-bullet-vs-stand-down-on-a-.md)).
- **Dev-authored design issues**: post anyway, framed as triage INPUT (solution-space mapping) and deferring to the design owner ([SUPERSEDED: skip post on dev-authored design placeholder](../learnings/1781137483321-superseded-skip-github-post-on-dev-authored-design.md)); its "do NOT forward to fixer" clause is narrowed by the scope correction below.
- **R6 issue-wait (a timing hold, not a skip)**: the bot's first comment on a new human-filed issue comes at least 4 days after `created_at` (rule R6 `issue-wait` in `/app/skills/compliance-check/README.md`). The `bot-ok` label, or a crash word plus a fenced code block in the body, exempts an issue; `GoodFirstBug`, `HelpWanted` or `no-bot` means the bot never comments. The slang triage workflow does not carry it (verified 2026-10-29): step 9 says "Always post" and lists only the ready-or-merged `Closes #N` PR as a suppression, so R6 reaches a triager only when recall happens to surface it. In one reporter's batch #14029 was held correctly while #14020 (7 min after opening) and #14027 (34 min) got bot comments at once, neither exempt, which fails R6 on the weekly compliance score and buries human work under bot comments. Until the spine carries R6, Main states the hold date (`created_at` + 4 d, unless exempt) in every `issue_opened` dispatch for a human-filed issue, and the triager checks R6 at the post step every time [R6 issue-wait is not enforced by the triage spine — triagers post on new human issues immediately](../learnings/1793293047741-r6-issue-wait-is-not-enforced-by-the-triage-spine-.md).

**`Dev Opened` and core-team tracking issues ARE in scope for triage and fixer dispatch.** The 2026-09-09 operator correction retired the skip rules for maintainer-authored, `Dev Opened`, self-assigned or "tracking/placeholder" issues: generalised from a few cases, they cut the overall WIN rate from 69% to 38% (JUL vs AUG), which the owner ruled a loss. Open the PR, cite the tracking issue, and let the maintainer decide — a human-triaged issue is well specified, so a *better* fixer candidate. The only exclusions are per-issue: (1) a human PR fixing it is open or merged (check `Fixes #N` / linked PRs and the assignee's open branches) → comment nothing, mark resolved-elsewhere; (2) the issue or a maintainer asks bots not to work on it; (3) the fix lands where nv-slang-bot has no push (e.g. slang-rhi from a slang issue) → hand the plan to the human owner rather than skipping silently ([operator correction 2026-09-09: Dev Opened / tracking issues ARE in scope](../learnings/1788958700000-correction-dev-opened-and-core-team-tracking-issues-are-in-scope.md)). It supersedes the watch-only rule drawn from slang#12241 (self-assigned core member, human-set labels, deferring umbrella body → no comment, no dispatch); what survives is researching even a "tracking" issue, which can hide a latent bug ([watch-only tracking placeholder (superseded)](../learnings/1785183281472-maintainer-authored-tracking-placeholder-issue-wat.md)).

**Interim verdict timing**: hold a classification 5-bullet ("fix incoming") until the chain is terminal, since a bot comment that needs retraction costs credibility; author-facing scoping questions and missing-reproducer requests may post pre-terminal ([hold interim classification 5-bullet until terminal](../learnings/1781116432142-hold-interim-triage-classification-5-bullet-until-.md)).

**Refresh a posted verdict when someone acts on its text** — the test is "would a reader act on the stale version and be misled?", not "is it stale?". On #12325 a slang-rhi stopgap merged with TODOs naming our issue as the re-enable trigger, a trigger **already satisfied**, which made the stale comment a live inaccuracy and justified an in-place edit. REST `PATCH` worked first try on the triager token while GraphQL had been 401, so "try GraphQL on a 403" is not a dependable rescue ([refresh a posted verdict when someone acts on its text](../learnings/1785765561758-check-the-reporter-s-version-before-root-causing-a.md)).

**Double-post prevention**: check the last comment before posting — `gh api repos/<owner>/<repo>/issues/<N>/comments --jq '.[-1] | "\(.user.login)\t\(.id)"'` — and never re-post a verdict the bot already posted; "always post" and "don't duplicate" reconcile as *check-then-act* ([check for an existing bot comment before posting](../learnings/1780768870271-check-for-existing-bot-comment-before-posting-gith.md)).

**Labeling and Issue Type**: apply `reproduced` only after reproducing on top-of-tree; if GPU/platform-dependent, skip both labels and note it. Set Issue Type via GraphQL `updateIssue` (slang `Bug = IT_kwDOAb2kZs4AXYkt`, `Feature = IT_kwDOAb2kZs4AXYkw`). Human triage is authoritative — never change or remove a human-set label ([labeling, Issue Type and reproducer-request rules](../learnings/1781008579138-slang-triage-labeling-issue-type-and-reproducer-re.md)).

## Root-Cause Verification Discipline

**Before root-causing at HEAD, resolve which release the reporter is on.** A report naming a release (`Slang version: 2026.12.2`) may describe a defect fixed on master but not shipped. Check `git grep '<fix-token>' <their-tag> -- source/` (absent?), `git grep '<fix-token>' -- source/` (present at HEAD?), `git log --format='%H' -S '<token>' -- <file> | tail -1` (introducing commit), then `git tag --contains <that-commit>`, which turns "fixed on master" into "shipped in vX.Y" ([check whether the reporter's version predates the fix via git tag --contains](../learnings/1785764482879-before-triaging-a-bug-report-check-whether-the-rep.md)). On slang#12325 this inverted the verdict: the `-std=metal4.0` producer (`slang-code-gen.cpp:786-804`, gated by the same `implies(metallib_4_0)` predicate as Metal emit) landed in PR #12009, first released in **v2026.14**, while the reporter's 2026.12.2 consumer still hard-coded `-std=metal3.1`. Both obvious dispositions (duplicate of #12096, or implement an already-implemented feature) were wrong; the fix was **bump the pinned Slang version in the consumer**. Such a bump is rarely one line: slang-rhi's `SLANG_RHI_FETCH_SLANG_VERSION` (`CMakeLists.txt:148`) must move with `SLANG_HASH_VERSION` (`:307`) and all **7** per-platform `SHA256` values, each wrapped in `if(SLANG_VERSION STREQUAL SLANG_HASH_VERSION)` — bump only the version and `URL_HASH` is empty, so the download is **unverified** ([check the reporter's version before root-causing](../learnings/1785765561758-check-the-reporter-s-version-before-root-causing-a.md)).

**Settle "would the fix even help?" with a controlled comparison.** Find two CI jobs differing in one variable and prove the rest matched. On #12325 a slang-rhi job (image `macos-26-arm64 / 20260728.0273`, Slang 2026.12.2) gave `0 metal PASSED / 207 SKIPPED` with the metal4.0 error, while a same-day slang job on the **same image** with in-tree Slang passed **87 metal tests** — so `metal 32023.883` accepts `-std=metal4.0`, and the version bump is the fix, capability detection only separate hardening. Grep each log for `Image:` / `Image Release:` to prove the match; `gh api .../actions/jobs/<id>/logs` works after the run's archive expires ([use CI logs as a controlled experiment on a one-variable difference](../learnings/1785764482879-before-triaging-a-bug-report-check-whether-the-rep.md)).

**Confirm the root cause empirically before implementing.** A plausible trace can name the wrong inst or decl, especially for `InternalError: Generic type/value shouldn't be handled here!` aborts: on slang#10027 triage blamed a vector element *count* deserialized as `DeclRefIntVal(N)`, but a Debug backtrace showed the element *type* param `T`, from two un-reconciled copies of the synthesized `vector<T,4>` extension generic across the module boundary ([verify triage root cause empirically (slang#10027)](../learnings/1781724696064-verify-triage-root-cause-empirically-slang-10027-v.md)). Carry a code-reader's hedge ("most likely", "must be confirmed empirically") verbatim as "leading hypothesis (unconfirmed)", never "root cause (traced)"; when the abort mechanism is verified but the upstream cause is a guess, split the two in the comment ([don't promote a hedged hypothesis to 'root cause (traced)'](../learnings/1781724956224-don-t-promote-a-hedged-hypothesis-to-root-cause-tr.md)).

**In parser-ambiguity triage, verify discovery separately from resolution.** In "two-pass / pre-scan" proposals the circularity often hides in discovery: for member-access ambiguity (`Outer<…>.member<…>`) a top-level decl-name scan must descend into bodies, which means skipping `<…>` lists — the same problem one layer down ([Verify Discovery and Resolution Separately in Parser-Ambiguity Triage](../learnings/1780064743810-verify-discovery-and-resolution-separately-in-pars.md)).

**Check a deprecated feature's spec before calling its behavior a bug.** When the reported code draws a deprecation warning (e.g. E30816): (1) read `external/spec/proposals/00N-*.md` (mirrored in `docs/proposals/`) — on #13064 a derived struct whose base has a user `__init` gets no synthesized ctor, so `Derived x = {}` fails E30513, exactly as `proposals/004-initialization.md:149-162` states and as a deliberate early-return in `_synthesizeCtorSignature` implements; (2) grep `tests/` for a `//DIAGNOSTIC_TEST` locking the exact error — if one exists, any "fix" is a language-design decision ([a bug on a deprecated feature is often working-as-specified](../learnings/1789395604535-a-reported-bug-on-a-deprecated-slang-feature-is-of.md)).

**Prior rulings and premises are dated hypotheses — re-verify at HEAD.** Scan `/workspace/shared/learnings/INDEX.md` for prior triager rulings before implementing: a "fresh unblock" handoff may contradict an evidence-backed ruling about which slice owns a check, and a test re-expression added only to dodge a new check is a "do not mask" smell ([a fresh unblock handoff can contradict a prior triager ruling](../learnings/1781775592867-a-fresh-unblock-handoff-can-contradict-a-prior-tri.md)). DeepWiki and same-day memos can lag HEAD; on concurrency work `grep -rn` the lock-acquisition sites before accepting "X is unsynchronized" ([DeepWiki/triage concurrency premises can lag HEAD](../learnings/1782408832985-triage-deepwiki-concurrency-premises-can-lag-head-.md)). Your own bot's sibling verdicts too: #12096's triage said "no slang-core change is warranted", yet one landed as #12009, and the macos-15 pin (#12075) was reverted in #12129 because the fix worked ([a stale triage verdict on the sibling issue can mislead you](../learnings/1785764482879-before-triaging-a-bug-report-check-whether-the-rep.md)). When evidence falsifies a premise, correct every issue resting on it ([propagate the correction to every issue resting on the falsified premise](../learnings/1785765561758-check-the-reporter-s-version-before-root-causing-a.md)). Memos also cite *adjacent* code loosely (blast radius, "other callers do X"), so grep such file:line claims yourself before quoting them in a commit, PR or comment ([verify memo file:line claims about adjacent code](../learnings/1782390307922-verify-triage-memo-file-line-claims-about-adjacent.md)).

**Never ship a hunch with a suggested disposition (dispatch-side).** A coworker reads the orchestrator's technical asides as a **prior**; if a wrong prior points at a terminal disposition, flawless execution still buries the answer. The #12325 dispatch said `-std=metal4.0` "probably" wouldn't help, "so the real fix stays capability detection" — false, and accepting it would have closed the issue as a duplicate. Mark hunches "I suspect X; **treat as unverified**", leave the disposition to the investigator, and name the **cheap measurement** that settles it: a hunch with an experiment costs one job, a hunch with a conclusion costs a wrong close ([never ship a hunch with a suggested disposition](../learnings/1785765561758-check-the-reporter-s-version-before-root-causing-a.md)).

## Severity Triage: Pointer-Formation UB Is Not Always a Realized Crash

Distinguish pointer **formation** from **dereference**. Forming a pointer more than one-past-the-end (`cur + 6 <= end` with fewer than 6 bytes left) is UB per `[expr.add]` and `-fsanitize=pointer-overflow` flags it, but if it is only *compared* and every dereference is short-circuit-guarded behind the bounds check (`&&`), there is no OOB access and no crash on flat-memory ISAs: "latent UB / UBSan finding", typically **P2**, not P1. On slang #11864 `JSONStringEscapeHandler::appendUnescaped` formed `cur+6`/`cur+4` past-end pointers, but all `cur[0]`/`_parseHex4(cur+2)` reads sat behind `cur+6 <= end`, so P2 was the honest call. A true P1 dereferences OOB or drives an unguarded memcpy/index. Fix idiom: `end - cur >= N`. Pickaxe (`git log -S`) each site — siblings in one function can be a fresh regression and a years-old latent bug ([pointer-formation UB is a UBSan finding, not a realized crash](../learnings/1782894644661-pointer-formation-ub-cur-n-only-compared-deref-sho.md)).

## Cross-Reference and Re-Triage Scanning

**Re-triage with the cross-reference timeline plus each PR's `files`, not a keyword search** — a PR can fix an issue's artifacts under another issue's `Closes #`: `gh api repos/.../issues/<n>/timeline --jq '.[]|select(.event=="cross-referenced")...'`. If a maintainer's own PR already touches the files, don't auto-fire the fixer; surface the PR and pose the design decision ([re-triage: rescan the cross-ref timeline](../learnings/1781713625746-re-triage-rescan-live-cross-ref-timeline-for-newer.md)).

**Check ownership before any fixer handoff**: `gh issue view <n> -R <repo> --json assignees --jq '[.assignees[].login]'`. A non-bot contributor assignee → flag the ready-to-fix memo to Main/parent, since an ownership directive may sit on an edge a group-scoped triager can't see and a dispatch risks a competing bot PR on a contributor's branch. Reaching `reproduced` does not release ownership; un-assignment or an explicit "bot, take it" via Main does ([contributor-assigned issue: flag to parent first](../learnings/1784793724947-triage-handoff-to-a-contributor-assigned-issue-fla.md)). Under the scope correction this is a routing escalation, not a skip, and a core member's self-assignment alone does not trigger it.

**Check for a linked fix PR before flagging an issue as untriaged** in daily/maintainer reports — external contributors often file issue and PR together ([check for a linked fix PR before flagging untriaged](../learnings/1781511232421-daily-report-check-for-a-linked-fix-pr-before-flag.md)). **Verify maintainer attributions** with `gh pr view <num> --json author,mergedBy,reviews`; bot comments have named the wrong PR author, and the real coordination target is usually the assignee ([Verify maintainer attributions in triage handoffs against gh PR data](../learnings/1780073122582-verify-maintainer-attributions-in-triage-handoffs-.md)). **When a handoff names a contributor's existing PR as the fix, triage = review/verify, not implement**: csyonghe opens a bundle PR first, then files per-sub-bug issues linking back, so forward those framed as REVIEW ([csyonghe files per-hunk issues after the bundle PR](../learnings/1780536698623-slang-csyonghe-files-per-hunk-issues-after-opening.md)).

## Dependency and Functional Independence

**A fix that seems to need an unmerged sibling PR is "possible, fixer to confirm", not a blocker** — master's existing APIs often suffice, and a long-lived fork can be thousands of files diverged, so check its diff size before recommending a stack ([verify functional independence before declaring a stack](../learnings/1781186034425-slang-triage-verify-functional-independence-before.md)). **For dependency-bump PRs** (SPIRV-Tools/Headers, glslang, slang-rhi pin), a failure on one platform/API while siblings pass the same suite means flake/infra, not a bump regression ([Dependency-bump PR triage: cross-platform check proves innocence](../learnings/1782244083021-dependency-bump-pr-triage-cross-platform-check-pro.md)).

**A "re-enable tests once X merges" follow-up can be doubly gated.** On slangpy#1077 the `doctest::skip()` markers are *added by* a separate disabling PR (#1076), so it needs both #1076 and the fix #1073 merged; if #1076 closes unmerged the re-enable is moot. Check `gh pr view --json state,mergedAt` on both; a fix PR at REVIEW_REQUIRED with green CI and zero reviews is blocked on a human, not code ([re-enable follow-ups can be doubly gated](../learnings/1785162937774-test-re-enable-follow-ups-can-be-doubly-gated-disa.md)).

## Triage Recommendations: Audit the Coverage a Fix Removes

On slang#12797 two descriptor-handle tests read an *unbound* bindless handle and masked the garbage with `* gOutput` (zero-init). The recommended **Approach A** — drop the read, keep the `bindlessSpaceIndex` REFLECTION assertion — shipped, and the author of the originating PR #9870 (jvepsalainen-nv) requested changes. Without the read, a `DescriptorHandle<T>` emits no `GetDynamicResourceHeap`, `lowerDynamicResourceHeap` early-returns, and DCE strips `__slang_resource_heap` (slang-ir-lower-dynamic-resource-heap.cpp:48-60) — removing the coverage of a *lowered descriptor-set placement* invariant (set 2 normally, set 3 when an unused ParameterBlock reserves a space first) that the reflection check, a frontend *prediction*, cannot see. **Approach B**, already in the triage solution space, made the read legal — bind a real `RWStructuredBuffer<float>.Handle` via `TEST_INPUT` (buffer descriptor writes work on lavapipe; only IMAGE writes hit the suspected Mesa `VK_EXT_mutable_descriptor_type` bug) — plus `//CHECK: OpDecorate %__slang_resource_heap{{.*}}DescriptorSet N`. Rule: before recommending "drop the runtime read, keep the reflection/static check", ask whether the runtime path is the only thing exercising a lowering/codegen/layout invariant, and state in every recommendation *what coverage the fix removes and whether it is load-bearing* (["drop the runtime read, keep reflection" can erase lowering coverage](../learnings/1788208011018-triage-drop-the-runtime-read-keep-the-reflection-a.md)).

## Resolution-Vehicle Routing

**The dup-check must search for an existing `Fixes #N` PR** (`gh pr list -R <repo> --search "<issue#>" --state all`). If a human's PR is in flight, forwarding to slang-fixer authors a competing PR on a live branch; report the routing decision up (park at triaged / help unblock / ping author) instead. On slang#10584 a stalled human draft #10666 (CI red, unaddressed review) held the forward ([triage: gh-search for an existing Fixes-#N PR before forwarding to fixer](../learnings/1784380560521-triage-gh-search-for-an-existing-fixes-n-pr-before.md)). **"Add X support" issues often already have a stalled bot-owned draft carrying `Fixes #N`** (e.g. #9038's takeover of #9085): the verdict is "resume the existing PR", and since that takeover may still own a live session, flag the parent rather than forwarding fresh work ([add-X issues: search for an existing Fixes-#N PR first](../learnings/1784739008680-triaging-an-add-x-support-feature-issue-search-for.md)).

**A follow-up editing a file that only an open, unmerged PR introduces folds into that PR** with `Closes #<followup>` (verify with `git show origin/master:<path>`), not a rival PR off master; re-check the PR's draft/ready state at triage, as it changes the auto-close analysis ([fold a follow-up into the open PR that introduces its file](../learnings/1784758259762-a-follow-up-issue-editing-a-file-only-introduced-b.md)).

**"Onboard repo to PR dashboard" issues are ops/infra, not code triage**: classify subsystem = infra/ops, post a brief note, and escalate to the orchestrator. On slangpy#1074 slangpy was likely already onboarded under both common meanings — (a) `slang-pr-report` runs with `DEFAULT_REPOS=""`, covering every non-archived shader-slang repo; (b) slangpy PRs already flow through the triage/fixer/reviewer/pr-approver pipeline — so ask the maintainer to choose (a), (b), or (c) a new dashboard and its end state ([Onboard-repo-to-dashboard issues are ops/infra, not code triage](../learnings/1784913528281-onboard-repo-to-dashboard-issues-are-ops-infra-not.md)).
