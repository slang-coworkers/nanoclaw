# PR-Approver: Merge-Join Calibration — Empirical Re-Verify, Design-Scope ABSTAINs & Coverage Gaps

How a shadow verdict is scored against the human outcome once a PR merges, and the disciplines that keep the join honest: re-verifying an empirical repro when the code moves; recognizing a design/scope question that CI-green can never settle; proving substance-equivalence across master-merge syncs; and reading the coverage a green status actually delivered (opaque submodule bumps, whole-`TEST_CASE` skips, no-runner Metal skips).

## TL;DR

- **A prior empirical repro does NOT transfer across a change to the same code region.** When a synchronize touches the code your gap depends on, build and reproduce at the new head; don't reason about the new form, and don't relay a peer's "unaffected."
- **Empirical confirmation moves the *evidence* axis (inspection < reproduction < independent re-reproduction), never the *class* axis.** A proven-but-intended, opt-in, fail-safe behavior on an unresolved maintainer design fork stays `ABSTAIN_POLICY:OPEN_GAP` — not BLOCK; owner COMMENT-state "looks good" does not make it WOULD_APPROVE.
- **CI-green never resolves a design/scope objection.** "Matches GLSL/shaderc" is evidence about another tool's design; a fix that makes class A inherit class B's latent bug is a design-scope flag; a live maintainer scope objection caps at `ABSTAIN_POLICY:CHALLENGER_CONCERN`.
- **Score each revision on its own commit.** Prove substance-equivalence by checksumming each head's three-dot PR diff (master-merge syncs move the head, not the contribution); `mergedBy ≠ author` + an independent APPROVED is genuine agreement; a CLA/rebase force-push does NOT clear a standing CHANGES_REQUESTED (read the aggregate `reviewDecision`); `closed-unmerged` is not REJECTED when a superseding PR merged the same change.
- **Withholds resolved by a human are agreements, not conservative misses** — ABSTAIN on a standing CR later cleared by APPROVED, a size-cap ABSTAIN on a large test-only consolidation merged with known nits, an OPEN_GAP whose named one-liner the author lands.
- **A merge with the flagged gap unfilled ratifies acceptance of the gap, not its absence** (per-arm coverage gaps, acknowledged temporary fixes, additive tooling-output gaps). These are expected false-abstains; don't round the next one up.
- **A submodule bump is reviewable content** — `gh api .../compare/<A>...<B>` and read the added lines; verify `policy_version` in clauses.json.
- **Green CI can mean the path never executed** — a whole-`TEST_CASE` skip drops deterministic coverage bundled with flaky assertions; a paravirtual Metal device SKIPs `.metal` cases while status is green. Grep the job log; a SKIP is not a pass. **Timestamp or re-probe every observation** — a runner-capability premise silently ages into a false one.

## Re-verifying evidence when the code moves

**When a `synchronize` touches the exact code your open gap depends on, build and reproduce at the new head.** On slang#12151 (public-by-default struct members, #9153) the E30604 `UseOfLessVisibleType` gap was empirically proven at head `044c1e1b09`; the code owner then simplified that exact `getDeclVisibility` branch and pushed a new head. A prior repro does not transfer across a change to the same region: re-read the changed source at the new head, don't relay a peer's "unaffected," and separate "empirical at old head" from "source-predicted at new head; fresh build = ground truth" ([re-verify at the new head](../learnings/1784657247208-a-prior-empirical-repro-doesn-t-transfer-across-a-.md)). Apply exactly that one change to a local clone, build slangc, and run the gap's trigger shape plus controls (pre-feature language version; the workaround); a background subagent absorbs the ~15-min build and keeps it out of the decision session ([build and reproduce, don't reason about the new form](../learnings/1784658867738-approver-calibration-when-a-synchronize-changes-th.md)). Empirical confirmation moves the *evidence* axis, never the *class* axis: a proven-but-**intended**, opt-in, fail-safe behavior whose desirability is an unresolved maintainer design fork stays `ABSTAIN_POLICY:OPEN_GAP` — BLOCK is reserved for a verified 🔴 defect, and owner COMMENT-state "looks good" does not promote it to WOULD_APPROVE ([evidence, not decision class](../learnings/1784658882005-approver-calibration-empirical-confirmation-of-a-f.md)).

**Verify a claimed fix in SOURCE at the settled head.** A fixer's later push can resolve a withhold, and a standing bot/Devin flag pointing at the now-fixed lines is then REFUTED, not confirmed; the BLOCK→ABSTAIN→WOULD_APPROVE chain on #12125 was normal convergence, decided fresh each revision ([verify a claimed fix in source](../learnings/1784724233457-approver-challenger-verify-a-claimed-fix-in-source.md)).

## Design and scope questions CI cannot settle

**A PR that relaxes or removes a diagnostic poses a desirability question that cross-toolchain precedent cannot settle.** On #12138 the challenger judged a `verifyComputeDerivativeGroupModifiers` relaxation "correct + principled" because it matched GLSL `local_size_*_id`/shaderc, and every bot agreed the code was sound — but maintainers CLOSED it unmerged: an error on the compile-time DEFAULT of an overridable spec constant is a deliberate safety/ergonomic choice (the default is what ships if nobody overrides). Correct code does not establish a correct decision to relax. Any of these flags makes it a maintainer design call: the change deletes an error path (vs fixing wrong codegen); the justification is "tool X accepts it"; the rejected input is a compile-time default of a runtime-overridable value — lean ABSTAIN (CHALLENGER_CONCERN/OPEN_GAP) on the design question and say so. Here the ABSTAIN agreed in direction but was withheld for the WRONG reason (CI/test, not design), which would have become a false-safe had CI been green ([matches GLSL/shaderc ≠ desired Slang behavior](../learnings/1784845286053-approver-challenger-miss-matches-glsl-shaderc-desi.md)).

**A target-neutral fix for a target-specific problem is a first-class design-risk axis (#12156 hpp-export chain).** When a fix makes input-class A behave identically to a class B that carries a known-latent bug, "A now inherits B's quirk, so benign" silently answers a design question with an approve. Separate "is the equivalence a FACT?" (verifiable) from "is inheriting B's bug ACCEPTABLE?" (a maintainer scope call); a live maintainer objection on scope (target-neutral vs host-target rooting) caps the decision at `ABSTAIN_POLICY:CHALLENGER_CONCERN`, because green CI answers the regression hinge, not the scope question ([class A inheriting class B's latent bug](../learnings/1784665766341-approver-calibration-fix-making-classa-inherit-cla.md)). #12156 rooted `__extern_cpp` exports at target-neutral IR lowering although the motivating issue was host-C++-only; the R3 ABSTAIN on pdeayton-nv's scope objection, despite fully-green CI, was vindicated when jkwak-work closed it unmerged in favor of the host-scoped `isCPUTarget()` replacement #12242 ([R3 target-neutral-rooting ABSTAIN vindicated](../learnings/1785201460764-approver-human-agreement-r3-abstain-on-target-neut.md)).

**Construct the adversarial input for a "retain + must-link" change.** On the same chain a "clear it as a benign dedup/plausibility" reflex missed a REAL regression: an `as<CallableDecl>(decl)` gate that added `HLSLExport`+`KeepAlive` did not exclude imported/bodyless `[__extern] __extern_cpp` decls, so a definition-less function became a keep-alive export root demanding a nonexistent symbol → `E45001 unresolved external symbol`. When such a decoration is added on a path that also runs for imported/extern/bodyless decls, ask whether it now demands a symbol with no local definition, and prefer build/repro over deepwiki plausibility for any linking/DCE outcome; the correct gate is `as<CallableDecl>(decl) && !isImported` ([as-CallableDecl gate missed the imported bodyless fn](../learnings/1784665748345-approver-challenger-miss-as-callabledecl-gate-did-.md)).

## Merge-join scoring mechanics

**Establish who agreed, on what content.** When the merged head ≠ your recorded SHA, prove substance-equivalence by checksumming each head's own three-dot PR diff — master-merge commits move the head with zero change to the contribution, so the decision still holds; `mergedBy ≠ author` + an independent APPROVED review = genuine agreement, not a self-merge ([merged head byte-identical via master-merge syncs](../learnings/1784725443219-approver-human-agreement-would-approve-vindicated-.md)). Always pull `mergedBy`/`author`/`reviewDecision`/`reviews[]` (`gh pr view --json` has no `merged` field — use `state`/`mergedAt`/`mergedBy`). shader-slang.github.io#209's `ABSTAIN_POLICY:OUT_OF_SCOPE:website-content` merged at the exact decision SHA, APPROVED by csyonghe (not the author) and merged by a third actor (bmillsNV) — the 2nd vindication of the #207 pattern; rounding up to WOULD_APPROVE would have been wrong even though the PR was fine, because there was no code-review signal to approve on ([website-content ABSTAIN vindicated](../learnings/1784650403339-approver-human-agreement-website-content-abstain-v.md)). An author self-merge alone is a *weak* signal (the #12859 trap); slang#12993's counted because an independent MEMBER APPROVE sat at the same commit ([spvdb cleanup merged verbatim](../learnings/1789061586539-approver-calibration-spvdb-test-only-warning-clean.md)).

**Score each revision on its OWN commit.** A mechanical CLA/rebase/re-author force-push does NOT auto-dismiss a standing `CHANGES_REQUESTED` — read the aggregate `reviewDecision`, not the individual review's `.commit_id` ([CLA force-push does not clear a CR](../learnings/1784731375990-approver-challenger-cla-mechanical-force-push-does.md)). Because `record_human_verdict` maps the terminal APPROVED onto EVERY decided revision row, a BLOCK the fixer resolves with exactly your predicted fix before an APPROVED merge is a clean hit, but an earlier buggy WOULD_APPROVE row on the same PR is coincidental noise ([guard the multi-revision false-safe](../learnings/1784765736898-approver-human-agreement-block-fixer-applies-my-fi.md)). Never write a calibration learning from a partial revision view — check the ledger for other revision rows first. The first #12119 join note called its `+kIROp_PtrCast` change a "safe-direction refinement"; the correction established it was LOAD-BEARING, because a walker-miss's failure direction is **per-chain, set by the address space the un-peeled op carries** (UserPointer → safe/mutable; Uniform/ConstantBuffer → dangerous/immutable → `__ldg` → stale read) ([CORRECTION — PtrCast was load-bearing](../learnings/1784672721537-approver-calibration-correction-to-12119-merged-jo.md)).

**`closed-unmerged` is NOT reliably a REJECTED verdict.** slang#12840 (fork, "Fix matrix specialization") was ABSTAIN_POLICY:CLAUSE_FAIL:head_provenance across all 5 heads, then closed with "closing because #12986 is merged" — the same change, authored same-repo by maintainer jkwak-work, merged that day; the change was ACCEPTED and only the vehicle changed. The fork-head ABSTAIN *predicted the real completion blocker*: the breaking change needed secret-gated cross-repo cherry-pick CI (companion slangpy#1135) that a fork PR structurally cannot run ([#12840 superseded by #12986](../learnings/1789072509032-pr-closed-unmerged-rejected-when-a-superseding-sam.md)). `closed-unmerged` has ≥3 meanings (rejected-on-merit / superseded-dedup / abandoned): read the closing comments and check for a superseding merged PR before mapping to a verdict. No `record_human_verdict` tool exists agent-side; terminal outcomes join via the host webhook path only ([closed-unmerged ≠ rejected](../learnings/1789072509032-pr-closed-unmerged-rejected-when-a-superseding-sam.md)).

## Withholds and blocks the human outcome vindicated

**An OPEN_GAP that names the exact one-liner (#12119 OptiX SBT `__ldg` exclusion).** The arc ran R1/R2 WOULD_APPROVE → R3 ABSTAIN_POLICY(OPEN_GAP) → R4 WOULD_APPROVE → merged APPROVED (jkwak-work, independent). R3 abstained because the SBT walker `isAddressIntoOptiXShaderBindingTable` omitted `kIROp_PtrCast`; the author landed precisely `+kIROp_PtrCast` — a real correctness catch that shaped the shipped code, not over-caution ([OPEN_GAP → named one-liner → APPROVED](../learnings/1784672675326-approver-human-agreement-abstain-open-gap-on-a-loa.md)). The advisory bar also held: a 🟡 "the test might not catch a regression," on a fix whose correctness is independently provable and whose guarded regression has no current trigger, is correctly cleared as advisory even when a diligent author later tightens it ([advisory 🟡 gaps were the author's follow-ups](../learnings/1784672659958-approver-human-agreement-12119-shape-independent-o.md)).

**The canonical end-to-end BLOCK vindication (#12111).** The descriptor-reuse coalescing PR (#12051) ran R1 WOULD_APPROVE → R2 BLOCK(RED_BUG: an `isMovableInst`-on-`UniformConstant`-alone over-fire that regressed unmodified `intrinsic-texture` SPIR-V tests; Devin missed it, the challenger's CI-vs-master probe caught it) → R3 WOULD_APPROVE on the narrowed `kIROp_GetElementPtr` predicate → MERGED APPROVED by jkwak at the exact R3 head. On any "move the fix to a more generic predicate" revision the blast radius widens *within* the target even when cross-target is dead-code-safe: enumerate every other IR shape matching the new predicate and diff live test-slang legs vs master. A `kIROp_<Op>` direct-immediate-pointer check is safer than a `getRootAddr` walk (it sidesteps the op-set false-safe class; failure direction is safe). Never record on an unsettled head — this PR's head moved three times near the record step ([R2 BLOCK vindicated end-to-end](../learnings/1784675820614-approver-human-agreement-r2-block-narrowed-fix-mer.md)).

**Policy withholds a human later resolves are the withhold working as designed.** ABSTAIN_POLICY on a standing `CHANGES_REQUESTED` that the maintainer clears with a fresh APPROVED ([standing CR → APPROVED](../learnings/1784732395517-approver-human-agreement-abstain-policy-on-standin.md)); ABSTAIN(OPEN_GAP) on an intended-but-design-undecided behavior that merges at your exact head with a formal Approve ([design fork → formal Approve](../learnings/1784756558331-approver-human-agreement-abstain-open-gap-on-a-mai.md)); and slangpy#1085 (~3200 test-only lines), ABSTAIN_POLICY:CLAUSE_FAIL:tier_eligible across R1/R2, merged at the exact R2 head with the maintainer merging over known non-blocking nits ("probably better just to get it in"). The size cap is a routing decision ("a human must weigh this"), not a code judgment — "enough coverage now vs perfect-but-delayed" is a trade-off a bot cannot make; record the plain ABSTAIN_POLICY, don't round a clean-looking test diff toward WOULD_APPROVE, and don't mislabel it ABSTAIN_INFRA ([size-cap ABSTAIN vindicated](../learnings/1785514761596-approver-calibration-large-test-only-consolidation.md)). Two tier calibrations belong here: a `head_provenance` ABSTAIN on a trusted member's fork-head PR (slangpy#918) that merged unchanged is defer-to-human and a second data point to relax `allow_fork_head` for trusted members ([fork-head abstain, slangpy#918](../learnings/1784752014622-approver-human-disagreement-fork-head-abstain-on-s.md)); and a Devin-only ABSTAIN later corroborated by the delayed primary production review on the identical head shows the fallback tier is trustworthy for the no-bug/gaps distinction ([Devin-only ABSTAIN corroborated](../learnings/1784723580509-approver-calibration-devin-only-abstain-on-slang-1.md)).

## Gaps maintainers accept, and clears that held

**A merge with the flagged gap unfilled ratifies acceptance of the gap, not its absence.** Two in-group instances, both merged by MEMBER jkwak-work at exactly the decision commit with 0 follow-up. slang#12892 (external fork, "Fix node discard in tryParseGenericApp") was ABSTAIN_POLICY:OPEN_GAP at R2 (critique-gate-enforced down from WOULD_APPROVE: the single-overload `DeclRefExpr` arm untested) and shipped both 🟡 gaps (missing rationale comment, untested arm) — for this shape maintainers treat a per-arm coverage gap as non-blocking ([#12892 single-arm gap shipped unfilled](../learnings/1789072146151-approver-human-disagreement-merge-join-confirms-a-.md)). slang#12885 (Metal mesh user-semantic) merged at the R2 ABSTAIN_POLICY/OPEN_GAP commit `dd42b964bffd` with the nested mesh-output indexed user semantic still bypassing `maybeFlattenNestedStructs`, and proper-fix issue #12998 was filed. Its shape — external-fork PR + senior-maintainer "wrong-layer / band-aid" objection + shepherd approval "as a temporary fix" + a proper-fix design issue — expects ABSTAIN_POLICY/OPEN_GAP citing the acknowledged gap and an unchanged merge; a false gap would have drawn a corrective commit, so the unchanged merge confirms the gap was real-but-accepted ([temporary fix merges with OPEN_GAP unfilled](../learnings/1789118224461-approver-human-disagreement-merge-join-a-maintaine.md)). Both are expected shadow-mode false-abstains (excluded from scoring), not a procedure change; don't let "it merged" pull the next such PR toward WOULD_APPROVE.

**Ask additive-vs-regressive before leaning OPEN_GAP on tooling output.** slang#12850 (`-reflection-json`: reflect through pointers into the pointee struct) drew 🟡 with 0 bugs and 3 gaps (a never-popped global `ReflectionTracker` making `valueType` order-dependently polymorphic; the type-info path expands any pointee while the layout path expands only struct pointees; thin new-test coverage), and `jkwak-work` merged it AS-IS at the reviewed commit. It was safe because the change is to developer-tooling JSON *output* (not an ABI/correctness contract) and is **strictly additive** — every "collapsed to a name" branch is byte-identical to pre-PR behavior, so no existing consumer regresses. Weigh additive-vs-regressive and tooling-output-vs-load-bearing-contract: an additive tooling-output gap with no regression/crash/malformed-output/purpose-defeat clears as advisory; OPEN_GAP is reserved for regressions, crashes, and purpose-defeating gaps ([reflection-JSON additive gaps merge as-is](../learnings/1789079564809-approver-challenger-calibration-reflection-json-ad.md)).

**Mechanism-based clears and safe shapes that shipped verbatim.** On the SPIRV-{Headers,Tools} bump slang#12996 the bot predicted `debug-break-spirv-direct.slang` (matching `NonSemantic.DebugBreak` by numeric opcode) would break like the updated `DebugPrintf` tests — a false alarm, because NonSemantic ext-inst disassembly is per-set explicit, not generic ([per-set explicit ext-inst disassembly](../learnings/1789085984956-approver-challenger-calibration-spirv-tools-bump-n.md)); the WOULD_APPROVE merged at the exact decided commit with no follow-up, so the clear held ([confirmed by clean merge](../learnings/1789088953885-approver-challenger-calibration-confirmed-spirv-bu.md)). slang#12993 ("tests/spvdb/lib: Clean up warnings") merged verbatim at the decided WOULD_APPROVE commit `3bbeab30d875` (n_commits=1, no post-decision churn to mine): a diff confined to `tests/spvdb/lib/` (a standalone SPIR-V debug helper, nothing under `source/`/`include/`/`prelude/`) of `= {}` designated-init no-ops on already-empty-default members plus dead-code removal verified unreferenced at head is a reliably safe shape when all clauses pass and primary review + Devin are clean — the second spvdb/test-only datapoint after #12896 ([spvdb cleanup merged verbatim](../learnings/1789061586539-approver-calibration-spvdb-test-only-warning-clean.md)).

## Reading the coverage a green status delivered

**A submodule bump is reviewable content, not an opaque pointer.** On slangpy#1075 (`external/slang-rhi` bump + a per-batch `device->wait()`), `gh api .../compare/<A>...<B>` showed the added lines (a debug `fprintf` on the descriptor-heap failure path). Verify `policy_version` in clauses.json: copying the *bundled* `v0-shadow` policy (which lists `external/**` as protected) into the workspace shadows the authoritative mounted `v0-shadow-relaxed` policy and wrongly short-circuits to CLAUSE_FAIL. A resource-bounding sync with an open maintainer question is OPEN_GAP, never rounded up from a clean Devin ([submodule bump is reviewable content](../learnings/1785150368583-approver-challenger-slangpy-external-slang-rhi-sub.md)). **Approval timing is decision-relevant:** on #1075 R3 a maintainer APPROVED at head `e65086`, then CodeRabbit posted a Major finding ~3 min later at the *same* head; `submittedAt` for both proved the human never weighed the off-by-one, so the approval is recorded via `record_human_verdict` (the calibration join) but never flips the independent shadow decision, which stays ABSTAIN on the verified-real-but-low-severity gap ([approval predating a head-current bot finding](../learnings/1785151870935-approver-human-agreement-a-human-approved-commit-c.md)).

**A whole-`TEST_CASE` skip is all-or-nothing.** slangpy#1076's `doctest::skip()` silenced deterministic cross-thread frame-rejection assertions bundled with the flaky drain-ordering ones. Read the full test body, separate deterministic from flaky, and grep BOTH the C++ and Python suites for equivalent live coverage before scoring; uniquely-covered deterministic loss ⇒ OPEN_GAP, with the claim narrowed precisely (the same-thread path was covered by a Python sibling) ([whole-TEST_CASE skip drops deterministic coverage](../learnings/1785165216238-approver-challenger-miss-whole-test-case-skip-can-.md)).

**Green CI can mean the path never executed — and that observation ages.** GitHub-hosted `macos-latest` exposed only an "Apple Paravirtual device" with non-functional Metal, so a slang-rhi Metal-only-feature PR's `.metal` cases all resolved to `SKIPPED (device not available)` while status was green; grep the `-check-devices` job log for the feature's test lines before treating the runtime path as verified — a SKIP is not a pass. At that time slang-rhi had NO runner that could execute Metal (#800/#801/#802 all held on this) ([Metal tests SKIP on macos-latest](../learnings/1785193552208-approver-challenger-slang-rhi-metal-tests-skip-on-.md)). ⚠️ slang-rhi#807 then restored Metal device init, after which the paravirtual runner *does* execute Metal cases, so "Metal always skips" is a dated reading. Report the last occurrence plus the clean run after it, and re-probe a runner-capability premise before reusing it: a present-tense claim in a durable record silently ages into a false one, and unlike a wrong number nothing ever flags it ([timestamp or re-probe every observation](../learnings/1785822559259-approver-calibration-report-the-last-occurrence-pl.md)).

## Contradictions / supersessions

- The #12119 merged-join note calling the PtrCast change a "safe-direction refinement" is **superseded** by the correction: it was LOAD-BEARING, and a walker-miss's failure direction is chain-address-space-dependent, not universally safe.
- "Metal always skips on paravirtual macos-latest" is a **dated reading, superseded** by slang-rhi#807 restoring Metal device init.
- Not a contradiction but a standing rule: green CI never clears a design/scope objection (#12138 diagnostic relaxation, #12156 target-neutral rooting); CI answers only the regression hinge.
