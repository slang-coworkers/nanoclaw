## TL;DR

- **WGSL emit has two type paths**: `_emitType` routes, `emitSimpleTypeImpl` emits the name; a new IR type usually needs a case in the latter. A router grep hit is not coverage.
- **GLSL and Core are separate builtin modules**: a core decl marked `internal` is invisible to `glsl.meta.slang` callers and breaks the core-module build.
- **Default Vulkan/SPIR-V buffer layout is std430 (structured buffers, push constants) / std140 (ConstantBuffer)**; no auto-scalar at Vulkan 1.4; `scalar ≠ C`.
- **A GLSL SSBO reflects as a simple type layout**: element and container var-layout accessors both return nullptr.
- **On `-target wgsl-spirv(-asm)` (WGSL via Tint) the sub-context format is WGSL but `getTarget()` reports `WGSLSPIRV*`.** Exact `== CodeGenTarget::WGSL` checks are the bug class; use `isWGPUTarget()` (it also changes matrix storage).
- **Tint rows run only on Windows x64 CI and skip WGSL buffer lowering.** Capture Tint's input GPU-free with a stub `slang-tint` or a fake library loader; validate with naga, wgpu-py or Dawn null.
- **A bindless storage-buffer heap with a dynamic index emits GLSL without `GL_EXT_nonuniform_qualifier`**; the next error is a glslang cascade. Test buffer-only: a texture heap masks the gap.
- **`-vk` bindless tests that dynamically index a heap need `-emit-spirv-directly`**, or they fail the "Test Slang via glsl" step in every GPU job.
- **Shader-visible `DescriptorHandle` `uint2`: ordinary handle = `.x` index, `.y` = 0, not a 64-bit split.** Only an acceleration structure is 64-bit; `.x`/`.y` = texture/sampler only in the split combined-sampler lowering.
- **`early_fragment_tests` needed only front-end recognition**: the backend already exists via `[earlydepthstencil]`.
- **`globallycoherent` on a parameter is rejected in default mode** (`isModifierAllowedOnDecl` omits `ParamDecl`; a second gate hides behind). `-allow-glsl` ≠ "source is GLSL".
- **DXC duplicate semantics are backend-split** (DXIL errors on `TEXCOORD`+`TEXCOORD0`, DXC SPIR-V does not); Slang's silent re-index is Metal/WGSL-only.
- **A 202c GLSL-operator ambiguity comes from redundant equal-rank glsl spellings, not unreachable `OverloadRank`.** Capture surviving candidates and ranks first.
- **`import glsl;` on WGSL/Metal hits E36107 from `glsl.meta.slang` `[require]` gates that predate WGSL** (634 of 698 omit wgsl). Widening a gate suffices only if the body's callee has metal/wgsl cases.
- **On WGSL, `ConstantBuffer<T, ScalarDataLayout>` reflects std140 but lowers Natural** (#13904); naga rejects it, Dawn/Chrome 144+ silently mis-reads it. PR #13935 maps Scalar→Std430 and emits `requires uniform_buffer_standard_layout;`, but for every explicit CB.
- **GLSL interface blocks never compile for Metal/WGSL**: `Std140DataLayout` is spirv/glsl-only and uniform blocks default to std140.
- **GLSL combined-sampler calls parenthesize every argument**: CHECK `texture({{.*}}name`. Profiles/`-capability` never emit `#extension`; only per-use `__requireCapability`/`__glsl_extension` does.
- **Re-verify DeepWiki-sourced facts on your own instrument** (source, vendored DXC, a rebuild), and check a local build's commit before using it as a baseline (`build/Release` can be hundreds of commits old; `slangc -v` can show a stale tag).

## Two type paths in the C-like emitters (WGSL example)

The C-like emitters split type handling into `_emitType` (declarator, routing) and `emitSimpleTypeImpl` (type name). During slang#12535 a claim that WGSL "already handles `AttributedType`" rested on a grep hit (`slang-emit-wgsl.cpp:933`) in `_emitType` that only routed onward; `emitSimpleTypeImpl` had no case, so a `unorm float` emitted an empty type and invalid WGSL. After a grep hit, confirm the enclosing function is on your path ([WGSL emit has TWO type paths](../learnings/1786706500522-wgsl-emit-has-two-type-paths-emittype-routing-vs-e.md)).

## Cross-module visibility: GLSL is a separate builtin module

`internal` is same-module only, and GLSL (`glslLanguageScope`) is a separate module from Core (`core`/`hlsl`/`diff.meta.slang`). Adding `internal` to `__getLegalizedSPIRVGlobalParamAddr`, which 8 `case spirv:` arms in glsl.meta.slang call, fails the core-module rebuild with 360× `E30600 declaration not accessible`, invisible to source reading; grep `glsl.meta.slang` for callers and measure with a rebuild. Alternatives: `[require(spirv)]` rejects non-spirv user calls at check time but a spirv-targeting user still reaches the emit ICE (necessary, not sufficient); or move the declaration into `glsl.meta.slang` beside its callers (precedent: `__imageTexelPointer`) ([internal breaks cross-builtin-module calls](../learnings/1786522969053-internal-modifier-breaks-cross-builtin-module-call.md)).

## Buffer layout defaults and reflection

With no option given, Slang's Vulkan/SPIR-V layout is **std430** for (RW)StructuredBuffer elements and push constants and **std140** for ConstantBuffer. Nothing auto-enables scalar at Vulkan 1.4 (the 1.4 spirv-legalize code is about storage class; the Vulkan tutorial is wrong). Scalar, C and DX layouts come only from `-fvk-use-{scalar,c,dx}-layout` or a per-buffer `StructuredBuffer<T, ScalarDataLayout|...>`. Tightness: scalar/natural ⊂ C ⊂ std430 ⊂ std140; scalar packs a trailing field into a prior struct field's tail padding, so it is not C-compatible for nested structs ([default layout is std430/std140; scalar≠C](../learnings/1787601323178-slang-default-vulkan-spir-v-buffer-layout-is-std43.md)).

A `GLSLShaderStorageBuffer<T>` reflects as a plain `SimpleLayoutInfo` (the standalone `GetObjectLayout` branch), not a `ParameterGroupTypeLayout`, so `spReflectionTypeLayout_GetElementVarLayout()` and `spReflectionTypeLayout_getContainerVarLayout()` both return `nullptr`; only ConstantBuffer/TextureBuffer/ParameterBlock reach the `as<ParameterGroupTypeLayout>` branch. DeepWiki claimed the opposite with "high confidence" ([SSBO reflection: null element and container](../learnings/1787660189955-glsl-ssbo-reflection-layout-has-null-element-and-n.md)).

On WGSL an explicit per-buffer layout splits reflection from the shader (#13904). For `ConstantBuffer<T, ScalarDataLayout>`, reflection uses `WGSLLayoutRulesFamilyImpl::getConstantBufferRules` (always std140), but `getTypeLayoutRuleNameForBuffer` maps the explicit Scalar op to Natural and skips the std140 vec4 wrapper: a `float[4]` field becomes `array<f32,4>` (stride 4) in `var<uniform>` while `-reflection-json` reports stride 16. naga rejects the module; Dawn/Chrome 144+ silently mis-reads the buffer, because it supports `uniform_buffer_standard_layout` and by WGSL §4.1.2 a supported language extension needs no `requires X;`. `StructuredBuffer<S, ScalarDataLayout>` matches reflection only by luck. `ScalarDataLayout` has no `[require]`, while `Std140DataLayout`/`Std430DataLayout` give E36107 (see `import glsl;` below) ([ScalarDataLayout CB: reflection std140, IR Natural](../learnings/1792913060489-wgsl-scalardatalayout-constant-buffers-reflection-.md)). PR #13935 (open) adds `[require(wgsl)]` to both layouts, maps Scalar to Std430 on WebGPU targets, emits `requires uniform_buffer_standard_layout;` and makes reflection use std430; offsets agreed in every probe and default output stayed byte-identical. But it emits `requires` for every explicit std430/scalar CB, even one already valid std140, so naga and Safari reject those for no layout reason. Check a local build's commit before using it as a baseline: `build/Release` was hundreds of commits behind master on 2026-10-25, and `slangc -v` can print a stale configure-time tag (g3649fb982 on a build of 52e29ab43), so confirm top-of-tree with a recently merged behavior (#13708's `binding_array` output). In a fresh worktree, `git -c protocol.file.allow=always submodule update --init --recursive` takes ~12 s (local submodule URLs) ([ConstantBuffer explicit layout: master vs PR #13935](../learnings/1792930635926-wgsl-constantbuffer-explicit-layout-master-vs-pr-1.md), [check gpuweb before a chromium_* atom](../learnings/1792916916093-wgsl-chromium-experimental-features-check-gpuweb-b.md)).

## WGSL via Tint (`-target wgsl-spirv(-asm)`): requested target vs. sub-context format

On `-target wgsl-spirv(-asm)`, Slang emits WGSL in a sub-CodeGenContext whose format is `_getDefaultSourceForTarget(WGSLSPIRV) == WGSL` (slang-code-gen.cpp:278) and hands it to Tint. The sub-context shares `m_shared`, so `getTarget()` still reports `WGSLSPIRV*`. Code switching on `codeGenContext->getTargetFormat()` (`linkAndOptimizeIR`, the C-like emitter) is correct; the bugs are exact comparisons against `getTarget()` or the outer format. `getTypeLayoutRuleNameForBuffer` (slang-ir-lower-buffer-element-type.cpp) checks `== CodeGenTarget::WGSL`, then `isKhronosTarget`, and returns Natural, so the WGSL std140 vec4 packing of cbuffer scalar arrays never runs although the front end applies WGSL layout rules (#13381/#13391). The others are `emitEntryPoints` (the #8323 abort) and `doesTargetAllowUnresolvedFuncSymbol` (an `-incomplete-library` extern gives E45001 on the Tint path only). The fix is `isWGPUTarget()` ([WGSL-via-tint: check the REQUESTED target](../learnings/1790934790391-wgsl-via-tint-bugs-check-the-requested-target-not-.md)). Coverage is thin: slang-tint is fetched only on Windows x64 (elsewhere the rows report as ignored), and a `-target wgsl-spirv-asm` row never covers WGSL buffer-element lowering; only `-target wgsl` rows do ([wgsl-spirv-asm rows skip WGSL std140](../learnings/1790915313396-wgsl-spirv-asm-test-rows-do-not-exercise-wgsl-std1.md)).

A layout-rule fix there changes matrices. With `isWGPUTarget` (PR #13402) Tint storage buffers move from Natural to Std430, so matrices go through `shouldLowerMatrixType`: `RWStructuredBuffer<float2x2>` went from native `mat2x2` (bytes 1,2,3,4) to `_MatrixStorage_*ColMajorstd430` (1,3,2,4), and `float2x3` from 32 to 24 bytes, now matching reflection. Review layout-rule changes for matrices too ([Tint-path layout fixes change matrix storage](../learnings/1790962008492-tint-path-layout-fixes-also-change-matrix-storage-.md)).

Capturing the WGSL that Slang hands to Tint, on any platform, without a GPU:

- **CLI stub.** A ~10-line `libslang-tint.so` exporting `tint_compile` (write `req->wgslCode` to a file, return 1) and `tint_free_result`, per `slang-tint.h`. Run `slangc … -target wgsl-spirv-asm -tint-path <dir>` (a directory) and diff against `-target wgsl`. A stub returning real SPIR-V, copied into `build/Release/lib`, makes `-target wgsl-spirv` SIMPLE rows run and FileCheckable ([stub slang-tint](../learnings/1790932425083-slang-to-see-the-wgsl-that-target-wgsl-spirv-asm-p.md), [Tint-path layout fixes change matrix storage](../learnings/1790962008492-tint-path-layout-fixes-also-change-matrix-storage-.md)).
- **In-process unit test.** `IGlobalSession::setSharedLibraryLoader` with a loader that answers "slang-tint" with a fake `ISlangSharedLibrary` and forwards the rest to `DefaultSharedLibraryLoader::getSingleton()` (unit-test-wgsl-spirv-tint-input.cpp, PR #13402). An `SLANG_UNEXPECTED` in getEntryPointCode comes back as SLANG_FAIL + E99997, so assert the diagnostic text; `IComponentType` holds a raw `Linkage*`, so keep the ISession alive ([capture the WGSL Slang hands to Tint](../learnings/1790957231882-capture-the-wgsl-slang-hands-to-tint-without-tint-.md)).
- **Validate the capture.** `pip install --target /tmp/x wgpu` (bundles naga; llvmpipe adapter; `create_shader_module` raises naga's error) ([stub slang-tint](../learnings/1790932425083-slang-to-see-the-wgsl-that-target-wgsl-spirv-asm-p.md)), or node-only `npm install naga-wasm@30.2.0` + `validate(parseWgsl(src))` ([GPU-free WGSL check via naga-wasm](../learnings/1791663423398-gpu-free-wgsl-parse-validate-check-naga-wasm-via-n.md); [[wiki/concepts/slang-backends-wgsl-matrix-and-validation.md]]). For real Tint diagnostics use Dawn's null backend (`npm install webgpu@0.6.2`); naga rejects spec-valid f16 bitcasts and `enable subgroups;`. See [WGSL emit and GPU-free validation](slang-backends-wgsl-matrix-and-validation.md).

Metal's cbuffer path through `getTypeLayoutRuleNameForBuffer` is on [Metal buffer element lowering](../concepts/slang-backends-metal-buffer-lowering-and-layout-rules.md).

## Bindless descriptor heaps and the "Test Slang via glsl" CI leg

See also [DescriptorHandle emit on bindless and non-bindless targets](slang-backends-descriptor-handle-emit-and-bindless-targets.md) for the WGSL handle-spelling bug, `bit_cast` out of a handle, and WGSL resource tables (`getResource<T>`).

A bindless storage-buffer heap (`DescriptorHandle<RWStructuredBuffer<T>>`) read with a dynamic index emits GLSL that glslang rejects with `'variable index' : required extension not requested: GL_EXT_nonuniform_qualifier`, then `'+' : wrong operand types ... block{...}`. The second error is a glslang recovery cascade (`_slang_resource_heap[idx]._data[j]` is fine); a constant index compiles clean, proving one defect ([phantom "second bug"](../learnings/1788442267382-glsl-bindless-variable-descriptor-array-index-reje.md)). Root cause: `GLSLSourceEmitter::tryEmitGlobalParamImpl` requests the extension for an unsized resource array only after the buffer/param-group early-returns, so only textures reach it; the fix hoists the request. A texture heap requests the extension file-wide, masking the gap, so the regression test must be buffer-only. Do not add `nonuniformEXT(...)` wrapping; decoration propagation is the separate #12161 ([buffer heap misses the extension; texture heap masks it](../learnings/1788445078995-slang-glsl-bindless-buffer-heap-misses-gl-ext-nonu.md)). #12051, sometimes cited with it, is the unrelated closed "re-use loaded descriptors" issue; check an issue's title before citing it ([correction: #12051 is descriptor-load reuse](../learnings/1793829368223-correction-slang-12051-is-descriptor-load-reuse-no.md)).

CI consequence (PR #12800, gap #12897): a `-vk` bindless test that dynamically indexes a heap must add `-emit-spirv-directly` to its `COMPARE_COMPUTE` directive, or it fails the shared "Test Slang via glsl" step that re-runs `-vk` tests through glslang in every GPU `test-slang` job (dx, vk and cuda alike). The per-directive flag overrides the injected `-emit-spirv-via-glsl` (precedent `desc-handle-test-input.slang:1`). Reproduce GPU-free: `slangc <test> -emit-spirv-via-glsl -target spirv-asm -stage compute -entry <e>`. Read the job log before accepting "backend-agnostic": three runners failing one step deterministically, or `result code = 1` plus glslang errors, is real; bot-PR reds with every real job `skipped` are the priority-yield ([bindless -vk tests need -emit-spirv-directly](../learnings/1788440528410-bindless-vk-tests-need-emit-spirv-directly-via-gls.md), [RWStructuredBuffer.Handle -vk tests hard-fail via glsl](../learnings/1788441444776-bindless-rwstructuredbuffer-handle-vk-tests-must-u.md)).

**Shader-visible `DescriptorHandle` `uint2` has three cases** (`hlsl.meta.slang` HEAD, Sep 2026, docs PR #12938; distinct from host `uint64` packing, D3D12 2×32-into-64, Metal 128b):

- **Ordinary handle** (texture, sampler, buffer, CBV): `.x` = resource- or sampler-heap index, `.y` unused. Construction is `uint2(index, 0)` (`:27568`/`:27853`) and every lookup (GLSL, HLSL, WGSL, `spvDescriptorHeapEXT`; `:27970`–`:28056`) reads only `.x`. Not a 64-bit low/high split (the #12937 misconception).
- **Acceleration structure**: a 64-bit GPU address on the default SPIR-V/GLSL path (`__asuint64((uint2)handleValue)`, `:28000`); HLSL loads it from the resource heap by `.x`.
- **Combined texture-sampler**: `.x` = texture, `.y` = sampler only in the split lowering (HLSL/`spvDescriptorHeapEXT`); native SPIR-V combined-image-sampler (VkMutable) uses `.x` alone.

The `defaultGetDescriptorFromHandle` / `getDescriptorFromDynamicResourceHeap` target switches are the source of truth ([DescriptorHandle uint2 semantics](../learnings/1788849400575-descriptorhandle-uint2-component-semantics-shader-.md)).

## Front-end recognition gaps and language-mode subtleties

`layout(early_fragment_tests) in;` under `-allow-glsl` failed with E31217 because `parseLayoutModifier`'s hardcoded list of bare GLSL layout qualifiers lacked it. `[earlydepthstencil]` already emits it on all targets, so the fix is front-end recognition only, as `local_size_*` synthesizes a `NumThreadsAttribute` ([early_fragment_tests: backend already exists](../learnings/1787245492858-glsl-early-fragment-tests-input-qualifier-rejected.md)).

`globallycoherent RWByteAddressBuffer buffer` as a function parameter is rejected in default mode (E31201) but accepted with `-allow-glsl`: `isModifierAllowedOnDecl`'s `isGLSLInput` branch allows `ParamDecl` and the non-GLSL fall-through omits it. The stripped modifier then trips a call-site check (E30048; fix the gate, not it), and a second gate in `slang-check-decl.cpp` rejects memory qualifiers on non-`TextureType` params; both must widen ([globallycoherent on params](../learnings/1787705000586-globallycoherent-on-function-params-rejected-in-de.md)). When converting the option-derived `bool isGLSLInput` to a `SourceLanguage`, do not prefer the TU's `sourceLanguage`: a `.slang` file with `-allow-glsl` keeps `sourceLanguage == Slang`. AllowGLSL is not "the source is GLSL" (collapsing them is a maintainer decision), and the `GLSLModuleModifier` fallback is load-bearing since `m_translationUnitRequest` is nullptr on reflection/language-server paths ([prefer-TU-first drops -allow-glsl](../learnings/1787774464819-converting-option-derived-glsl-bool-to-sourcelangu.md)).

DXC duplicate-semantic behavior is backend-split (vendored DXC, `build/_deps/dxc_source-src/`). For `TEXCOORD`+`TEXCOORD0`, DXIL errors (both normalize to `(TEXCOORD,0)`); DXC SPIR-V does not (`getSemanticStr()` returns the raw string, so the dup-check sees two names). Slang's silent re-index (`fixFieldSemanticsOfFlatStruct`) is Metal/WGSL-only; HLSL passes semantics through. Read DXC's source, not DeepWiki ([CORRECTION: DXC duplicate semantics backend-split](../learnings/1788388950993-correction-dxc-duplicate-semantic-behavior-is-back.md)).

## A GLSL-operator overload regression: equal-rank spellings, not unreachable rank

Gating off the generic-parameter-count tie-breaker in `compareOverloadCandidateSpecificity` for 202c (#12829) regresses `builtin-operator-fastpath-glsl.slang`: `mat*mat`, `vec==vec`, `vec!=vec` become E39999 ambiguous under `-std 202c -allow-glsl`. The first diagnosis ("the generic early-return at :2420-2426 skips `OverloadRank`") was wrong: both survivors are same-operator `glsl.meta.slang` overloads with identical `[OverloadRank(15)]`, differing only in generic-param count (`operator*<let N>(matrix<float,N,N>,…)` vs `operator*<T,let L,C,R>(…)`). Both are fully specialized at the compare step, so rank is reached (ranks 5 vs 9 resolve, 15 vs 15 is ambiguous); the core operators drop out earlier on conversion cost. The root cause is redundant glsl spellings only the count heuristic separated, so the fix needs a core-module/language-design change (distinct ranks, merged spellings, or a structural-specificity rule); the maintainer moved spike PR #12830 back to draft. Capture survivors with ranks, flavors and conversion-cost ties before theorizing ([#12829 regresses glsl operators](../learnings/1787965868058-slang-12829-removing-generic-param-count-tie-break.md), [CORRECTION: equal-rank redundant spellings](../learnings/1787966040183-correction-slang-12829-glsl-regression-is-equal-ra.md)).

## `import glsl;` on WGSL/Metal: `glsl.meta.slang` require gates and std140 blocks

`import glsl;` (or `-lang glsl`, which imports it implicitly) with a matrix `a * b` on `-target wgsl` or `-target metal` fails E36107 (#13350). `glsl.meta.slang:226-287` gates the `operator*` / `operator*=` overloads with `[require(cpp_cuda_glsl_hlsl_spirv_llvm, sm_4_0_version)]`, a set that predates WGSL (#3912 before #5006); the sibling `==`/`!=` include metal and wgsl. Unlike the fwidth trap, which also needs a `__target_switch` case (see [WGSL/Metal cross-target emission](../concepts/slang-backends-wgsl-metal.md)), widening the gate alone suffices: the bodies forward to `mul`, which has metal/wgsl cases. Workaround: `mul(b, a)`. Rebuild `slang-glsl-module slangc` after touching `glsl.meta.slang` ([matrix `*` E36107 is an operator gate](../learnings/1790793913411-e36107-on-wgsl-metal-with-import-glsl-matrix-glsl-.md)). The class is large: 634 of 698 `glsl.meta.slang` `[require]` gates omit wgsl, and after PR #13356, 62 declarations (`mix`, `mod`, `atan(y,x)`, …) are still gated (#13355); before widening one, check its callees have metal/wgsl cases.

A second gate sits on the layout types. `Std140DataLayout` is spirv/glsl-only (`hlsl.meta.slang:41-45`) and `Std430DataLayout` spirv/glsl/llvm, so any GLSL `layout(std140) uniform {…}` or `buffer {…}` block gives E36107 on metal and wgsl (PR #13935 would add wgsl to both); dropping `std140` does not help, since uniform blocks default to it. `tests/glsl/matrix-mul.slang`'s METAL lane has never compiled; it passes only because its regex matches the diagnostic's quoted source (see [test authoring](../concepts/slang-tooling-f0909b0-test-authoring-filecheck.md)) ([GLSL interface blocks never compile for Metal](../learnings/1790798404070-glsl-interface-blocks-never-compile-for-metal-std1.md)).

## GLSL emit shape: combined-sampler parens and where `#extension` comes from

From reviewing #13333: a combined-sampler call such as `SamplerCubeArrayShadow.SampleCmpBias(...)` on `-target glsl` emits `texture((combinedShadowCubeArray_0), (_S1), (0.5), (0.25))`, so `CHECK: texture(name` never matches; use `texture({{.*}}name`. A separate Texture + `SamplerComparisonState` emits `texture(samplerCubeArrayShadow(tex_0,samp_0), …)`. A reviewer bot's untested CHECK had this bug; run a suggested CHECK first. `-profile glsl_460+GL_EXT_X` and `-capability GL_EXT_X` do not emit `#extension GL_EXT_X`; only a per-use `__requireCapability` / `__glsl_extension` (`IRRequireTargetExtension`) does, so such a profile does not make an `#extension` CHECK vacuous. To drill failability, break the compiler, not the test: remove the wrapper's `__glsl_extension` + `__requireCapability`, or revert `SampleCmpBias`→`SampleCmp` in the `glsl.meta.slang` `default:` branch, and rebuild the core module (~3 min). Under that drill the older `sample-cmp.slang` / `intrinsic-texture.slang` still passed; only the new per-form tests failed ([combined-sampler parens; profile caps don't emit `#extension`](../learnings/1790724590745-glsl-emit-combined-sampler-calls-are-texture-name-.md)).
