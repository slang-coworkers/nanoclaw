## Standing-Bot 🔴 Refutation and Codegen-Fix Verification Without Running the Compiler (2026-07-20 fold)

Three challenger-stage calibrations from the slang#11803 and #12142 chains. **(1) A standing bot 🔴 is REFUTED, not honored, when the flagged text/code no longer exists at the pinned head.** Devin's bug list can LAG the latest commit (re-renders slowly / keys off a cached analysis), so a bug persists in the list after the code is fixed. The sole discriminator is whether the defect actually exists in source at the pinned head — re-fetch the exact file:line and grep the named phrase. This is NOT the "downgrade a CONFIRMED 🔴 by severity" error: refuting an ABSENT 🔴 is legitimate and required; honoring a label for a defect that no longer exists is a false-BLOCK ([a standing bot 🔴 is REFUTED when the flagged text no longer exists at the pinned head](../learnings/1784442969985-approver-challenger-a-standing-bot-is-refuted-not-.md)). **(2) A codegen fix whose only validating test never executed = OPEN_GAP, not WOULD_APPROVE.** External-fork PRs have their `CI` workflow maintainer-gated (`conclusion=action_required`, 0 jobs); the green *combined* status covers only CLA/CodeRabbit/trigger, not slang's build/test matrix. Pull `/actions/runs?head_sha=<sha>` and check the `CI` run's conclusion + job count — codegen change + unrun validating test + no local run path ⇒ ABSTAIN_POLICY/OPEN_GAP, never round up ([fork-PR codegen fix with unrun validating test → OPEN_GAP](../learnings/1784446531911-approver-challenger-fork-pr-codegen-fix-with-unrun.md)). **(3) But you CAN establish correctness-by-inspection** when the target can't run locally: align the change with pre-existing hand-written siblings as ground truth, prove before/after byte-identity to bound the blast radius, grep every use of a role-changed variable for completeness, and confirm the test corpus has no pre-existing test asserting the old form. This separates "is the code right?" (yes) from "has it been validated?" (no) — two axes driving different reason_codes ([verify a codegen fix by aligning with siblings + before/after byte-identity](../learnings/1784446552079-approver-challenger-verify-a-codegen-fix-by-aligni.md)).


## Confirmed-by-Merge: DDS Subresource-Math Fix (WOULD_APPROVE = APPROVED = MERGED) (2026-07-21 fold)

A calibration vindication worth recording as a *class*, not an instance. slangpy#1049 (DDS loader mipmap-pitch / 3D-depth fix): shadow decision WOULD_APPROVE @ 6fd917aa; human jhelferty-nv APPROVED the same head, then MERGED it 4 min later (7e8c09cb) with no follow-up commits between the decision head and the merged head — the strongest calibration signal (approve/approve/merge, zero diff between the read and the shipped change). The safely-approvable *class*: a small (~180-line) bug-fix to binary-asset subresource/offset/size math in an image/texture loader, where risk is silent wrong offsets rather than a crash. What made it approvable (probe these on similar changes): (1) **hand-verify every arithmetic test literal against the new code** — recompute expected offsets from the formula, don't trust "tests pass" (here mip clamp `max(1u,dim>>mip)` had to be on BOTH width and height or high mips give slice_pitch 0); (2) **the removed code was the bug** — deleting an override that recomputes *worse* (a rounding-buggy manual pitch calc that truncates for block-compressed) is a strong positive signal; (3) **verify the test-data git-submodule bump is merged to the data repo's default branch and contains the referenced files** (`gh api …/compare/main...<sha>` identical) — a human's CHANGES_REQUESTED here was exactly "use the merged data files"; (4) **3D `layer_count==1`** with depth folded into one subresource's `.size = slice_pitch*mip_depth`, not iterated as layers. Two process meta-lessons: a `synchronize` that is a pure "Merge branch 'main'" produces a new head SHA but a byte-identical PR-authored diff (`base...head`) — re-pin and record against the new SHA but the code investigation carries over; and the OUTPUT_REVIEW critique gate re-hashes attested artifacts at delivery, so ANY post-approve edit re-trips it (this PR took 5 rounds) — resolve the human-verdict commit alignment from review `commit` oids BEFORE drafting (never assume the human approved an earlier commit), write time-sensitive cautions as record-time-scoped ("CI was not green AT RECORD TIME; policy did not require it"), and batch all edits before the first OUTPUT_REVIEW ([[approver/human-disagreement] CONFIRMED agreement — DDS/texture subresource-math fix with exact-offset tests + merged data submodule](../learnings/1784561186392-approver-human-disagreement-confirmed-agreement-dd.md), [[approver/human-disagreement] CONFIRMED-by-merge — DDS subresource-math fix WOULD_APPROVE matched merge outcome](../learnings/1784561550592-approver-human-disagreement-confirmed-by-merge-dds.md)).


## Empirical Re-Verification, Design-Scope ABSTAINs, and Merged-Join Corrections (2026-07-22 fold)

**When a `synchronize` touches the exact code your open gap depends on, build and reproduce — don't reason about the new form, and don't relay a peer's "unaffected."** On slang#12151 (public-by-default struct members, #9153) the E30604 `UseOfLessVisibleType` gap was empirically proven at head `044c1e1b09`; the code owner then simplified that very `getDeclVisibility` branch and pushed a new head. A prior empirical repro does NOT transfer across a change to the same region — re-read the changed source at the new head and separate "empirical at old head" from "source-predicted at new head; fresh build = ground truth" ([a prior empirical repro doesn't transfer across a change to the same code region — re-verify at the new head](../learnings/1784657247208-a-prior-empirical-repro-doesn-t-transfer-across-a-.md)). The reliable move is to apply exactly that one change to a local clone, build slangc, and run the gap's trigger shape plus controls (pre-feature language version; the workaround) — a ~15-min build absorbed by a background subagent keeps it out of the decision session ([when a synchronize changes the exact code your open gap concerns, build and reproduce — don't reason about the new form](../learnings/1784658867738-approver-calibration-when-a-synchronize-changes-th.md)). Crucially, empirical confirmation moves the *evidence* axis (inspection < reproduction < independent re-reproduction), never the *class* axis: a proven-but-**intended**, opt-in, fail-safe behavior whose desirability is an unresolved maintainer design fork stays `ABSTAIN_POLICY:OPEN_GAP` — proving it occurs does not promote it to BLOCK (reserved for a verified 🔴 defect), and owner COMMENT-state "looks good" does not promote it to WOULD_APPROVE ([empirical confirmation strengthens the evidence, not the decision class — intended-but-design-undecided stays OPEN_GAP, not BLOCK](../learnings/1784658882005-approver-calibration-empirical-confirmation-of-a-f.md)).

**Design-scope objections and imported-decl gates on the #12156 hpp-export chain.** Two challenger lessons: (1) a "clear it as a benign dedup/plausibility" reflex missed a REAL regression — an `as<CallableDecl>(decl)` gate that added `HLSLExport`+`KeepAlive` did NOT exclude imported/bodyless `[__extern] __extern_cpp` decls, so a definition-less function became a keep-alive export root demanding a symbol that doesn't exist → `E45001 unresolved external symbol`. When a change adds a "retain + must-link" decoration in a path that also runs for imported/extern/bodyless decls, construct the concrete adversarial input (does this now demand a symbol with no local definition?) and prefer build/repro over deepwiki plausibility for any linking/DCE outcome; the correct gate is `as<CallableDecl>(decl) && !isImported` ([challenger miss — as-CallableDecl gate did not exclude imported bodyless fn → E45001](../learnings/1784665748345-approver-challenger-miss-as-callabledecl-gate-did-.md)). (2) When a fix makes input-class A behave identically to a class B that carries a known-latent bug, "A now inherits B's quirk, so benign" silently answers a DESIGN question with an approve — separate "is the equivalence a FACT?" (verifiable) from "is inheriting B's bug ACCEPTABLE?" (a maintainer scope call). A live maintainer objection on scope (target-neutral vs host-target rooting) caps the decision at `ABSTAIN_POLICY:CHALLENGER_CONCERN`; green CI answers the regression hinge, not the design/scope question ([fix making class A inherit class B's latent bug is design-scope ABSTAIN, not benign equivalence](../learnings/1784665766341-approver-calibration-fix-making-classa-inherit-cla.md)).

**A PR that RELAXES or REMOVES a diagnostic poses a DESIRABILITY question the challenger cannot settle by cross-toolchain precedent — "matches GLSL/shaderc" ≠ desired Slang behavior.** On #12138 the challenger judged a `verifyComputeDerivativeGroupModifiers` relaxation "correct + principled" because it matched GLSL `local_size_*_id`/shaderc, and every bot agreed the code was sound — but maintainers CLOSED it unmerged: firing an error on the compile-time DEFAULT of an overridable spec constant is a deliberate safety/ergonomic choice (the default is what ships if nobody overrides), so "shaderc allows it" is evidence about GLSL's design, not Slang's. Correctness of the CODE does not establish correctness of the DECISION to relax. Flags that make it a maintainer design call, not a challenger call: the change deletes an error path (vs fixing wrong codegen); the justification is "tool X accepts it"; the rejected input is a compile-time-known default of a runtime-overridable value — any of these ⇒ lean ABSTAIN (CHALLENGER_CONCERN/OPEN_GAP) on the design question and say so in the notes, don't let a clean bot review + toolchain precedent round the challenger up (here the ABSTAIN agreed in direction but was withheld for the WRONG reason — CI/test, not design — which would have become a false-safe had CI been green) [[approver/challenger-miss] "matches GLSL/shaderc" ≠ desired Slang behavior — a compile-time diagnostic relaxation is a DESIGN call maintainers may reject even when the code is correct](../learnings/1784845286053-approver-challenger-miss-matches-glsl-shaderc-desi.md).

**#12119 OptiX SBT `__ldg` exclusion — an ABSTAIN(OPEN_GAP) that named the exact one-liner was vindicated end-to-end, and the merged-join calibration itself needed a correction.** The 4-revision arc ran R1/R2 WOULD_APPROVE → R3 ABSTAIN_POLICY(OPEN_GAP) → R4 WOULD_APPROVE → merged APPROVED (jkwak-work, independent). R3 correctly ABSTAINed because the SBT walker `isAddressIntoOptiXShaderBindingTable` omitted `kIROp_PtrCast`; the author then landed precisely `+kIROp_PtrCast` and it merged — a real correctness catch that shaped the shipped code, not over-caution ([ABSTAIN(OPEN_GAP) on a load-bearing peel-set gap → author lands the named one-liner → merged APPROVED](../learnings/1784672675326-approver-human-agreement-abstain-open-gap-on-a-loa.md)). The advisory-bar half also calibrated cleanly: a 🟡 "the test might not catch a regression" on a fix whose correctness is independently provable and whose guarded regression has no current trigger is correctly CLEARED-as-advisory even though a diligent author later tightens it ([#12119 shape-independent SBT exclusion MERGED — the advisory 🟡 gaps I cleared were exactly the author's later follow-ups](../learnings/1784672659958-approver-human-agreement-12119-shape-independent-o.md)). But an initial merged-join note mischaracterized that same PtrCast change as a "safe-direction refinement" — a CORRECTION established it was LOAD-BEARING: a walker-miss's failure direction is **per-chain, set by the address space the un-peeled op carries** (UserPointer→safe/mutable; Uniform/ConstantBuffer→dangerous/immutable→`__ldg`→stale read). Never write calibration learnings from a partial revision view — check the ledger for other revision rows on the same PR before generalizing a merge outcome ([CORRECTION — the PtrCast peel-set change was load-bearing; "walker miss is failure-direction-safe" is chain-AS-dependent, not universal](../learnings/1784672721537-approver-calibration-correction-to-12119-merged-jo.md)).

**#12111 is the canonical end-to-end BLOCK vindication.** The descriptor-reuse coalescing PR (#12051) ran R1 WOULD_APPROVE → R2 BLOCK(RED_BUG, an `isMovableInst`-on-`UniformConstant`-alone over-fire that regressed unmodified `intrinsic-texture` SPIR-V tests, which Devin missed and the challenger's CI-vs-master probe caught) → R3 WOULD_APPROVE on the narrowed `kIROp_GetElementPtr` predicate → MERGED APPROVED by jkwak at the exact R3 head. Transferable: on any "move the fix to a more generic predicate" revision the blast radius widens *within* the target even when cross-target is dead-code-safe — enumerate every other IR shape matching the new predicate and diff live test-slang legs vs master; a `kIROp_<Op>` direct-immediate-pointer check is stronger/safer than a `getRootAddr` walk (sidesteps the op-set false-safe class, failure direction is safe); and never record on a non-settled head — this PR's head moved three times near the record step ([R2 BLOCK → narrowed fix → merge-APPROVED = shadow BLOCK vindicated end-to-end (#12111)](../learnings/1784675820614-approver-human-agreement-r2-block-narrowed-fix-mer.md)).

**Website-content ABSTAIN vindicated a 2nd time (shader-slang.github.io#209).** A `ABSTAIN_POLICY:OUT_OF_SCOPE:website-content` merged at the exact decision SHA, APPROVED by a maintainer (csyonghe, not the author) and merged by a third actor (bmillsNV) — genuine non-self approval + non-author merge = vindication/AGREEMENT, the 2nd exemplar of the #207 pattern. Rounding up to WOULD_APPROVE would have been wrong even though the PR was fine, because there was no code-review signal to approve on. On the join, always pull `mergedBy`/`author`/`reviewDecision`/`reviews[]` to distinguish genuine approval from an author self-merge (`gh pr view --json` has no `merged` field — use `state`/`mergedAt`/`mergedBy`) ([website-content ABSTAIN vindicated by genuine non-self maintainer approval + non-author merge](../learnings/1784650403339-approver-human-agreement-website-content-abstain-v.md)).


## Merge-Join Calibration: Source-Verify Fixes, Substance-Equivalence, and the Multi-Revision False-Safe Guard (2026-07-23 fold)

Several merge-join calibrations sharpened how a shadow verdict is scored against the human outcome. The dominant rule: **verify a claimed fix in SOURCE at the settled head** — a fixer's later push can resolve a withhold, and a standing bot/Devin flag pointing at the now-fixed lines is REFUTED, not confirmed (the BLOCK→ABSTAIN→WOULD_APPROVE chain on #12125 was normal convergence, decided fresh each revision) ([verify a claimed fix in source at the settled head — a stale flag on fixed lines is refuted](../learnings/1784724233457-approver-challenger-verify-a-claimed-fix-in-source.md)). On merge joins where the merged head ≠ your recorded SHA, prove **substance-equivalence** by checksumming each head's own three-dot PR diff — master-merge commits move the head with zero change to the contribution, so the decision still holds; and `mergedBy ≠ author` + an independent APPROVED review = genuine agreement, not a self-merge ([WOULD_APPROVE vindicated — merged head byte-identical via master-merge syncs](../learnings/1784725443219-approver-human-agreement-would-approve-vindicated-.md)).

Withholds resolved by a human are **agreements, not conservative misses**: an ABSTAIN_POLICY on a standing `CHANGES_REQUESTED` that the maintainer later clears with a fresh APPROVED is the withhold working as designed ([ABSTAIN_POLICY on standing CR → human APPROVED = clean withhold resolution](../learnings/1784732395517-approver-human-agreement-abstain-policy-on-standin.md)), as is an ABSTAIN(OPEN_GAP) on an intended-but-design-undecided behavior that merges at your exact head with a formal Approve ([ABSTAIN(OPEN_GAP) on a maintainer-flagged design fork, then merged with a formal Approve = clean resolution](../learnings/1784756558331-approver-human-agreement-abstain-open-gap-on-a-mai.md)). A `tier_eligible` size-cap ABSTAIN on a large test-only consolidation is the same working-as-designed shape: slangpy#1085 (~3200 test-only lines) was ABSTAIN_POLICY:CLAUSE_FAIL:tier_eligible across R1/R2 and merged at the exact R2 head, the maintainer explicitly merging over known non-blocking nits ("fine for it to go ahead in… probably better just to get it in") — the size-cap abstain is a routing decision ("a human must weigh this"), not a code judgment, and the "enough coverage now vs perfect-but-delayed" call is exactly the trade-off a bot cannot make; record the plain ABSTAIN_POLICY, don't round a clean-looking test diff toward WOULD_APPROVE and don't mislabel it ABSTAIN_INFRA ([[approver/calibration] Large test-only consolidation abstained on size cap → human APPROVE-with-known-nits (cap vindicated)](../learnings/1785514761596-approver-calibration-large-test-only-consolidation.md)). Two mechanics guard the scoring: a mechanical CLA/rebase/re-author force-push does NOT auto-dismiss a standing `CHANGES_REQUESTED` — read the aggregate `reviewDecision`, not the individual review's `.commit_id` ([CLA/mechanical force-push does not clear a standing CHANGES_REQUESTED](../learnings/1784731375990-approver-challenger-cla-mechanical-force-push-does.md)); and because `record_human_verdict` maps the terminal APPROVED onto EVERY decided revision row, a BLOCK that the fixer resolves with *exactly your predicted fix* before an APPROVED merge is a clean hit, but the earlier buggy WOULD_APPROVE row on the same PR is coincidental noise — score each revision on its OWN commit's correctness ([BLOCK→fixer-applies-my-fix→APPROVED is vindication; guard the multi-revision false-safe](../learnings/1784765736898-approver-human-agreement-block-fixer-applies-my-fi.md)). Related fork-head calibration also lands here: an ABSTAIN on `head_provenance` for a trusted member's fork-head PR that merges unchanged is defer-to-human, and a second such data point ([fork-head abstain on slangpy#918 merged unchanged — evidence to relax allow_fork_head for trusted members](../learnings/1784752014622-approver-human-disagreement-fork-head-abstain-on-s.md)); and a Devin-only ABSTAIN later corroborated by the delayed primary production review on the identical head confirms the fallback tier is trustworthy for the no-bug/gaps distinction ([Devin-only ABSTAIN corroborated by the delayed primary review of the same head](../learnings/1784723580509-approver-calibration-devin-only-abstain-on-slang-1.md)).


## Reading opaque content, approval timing, coverage-collapse & no-runner gaps (2026-07-27 fold)

Four challenger disciplines sharpened on the slangpy#1075 / #1076 / rhi Metal / slang#12156 cluster. **A submodule bump is reviewable content, not an opaque pointer.** On slangpy#1075 (`external/slang-rhi` bump + a per-batch `device->wait()`), the correct move was to `gh api .../compare/<A>...<B>` and read the added lines (a debug `fprintf` on the descriptor-heap failure path) — and to verify `policy_version` in clauses.json, because copying the *bundled* `v0-shadow` policy (which lists `external/**` as protected) into the workspace shadows the authoritative mounted `v0-shadow-relaxed` policy and would wrongly short-circuit to CLAUSE_FAIL; a resource-bounding sync with an open maintainer question is OPEN_GAP, never rounded up from a clean Devin [[approver/challenger] slangpy external/slang-rhi submodule bump is reviewable content; fold live maintainer gaps in on the Devin-only tier](../learnings/1785150368583-approver-challenger-slangpy-external-slang-rhi-sub.md). **Approval timing is decision-relevant:** on #1075 R3 a maintainer APPROVED at head `e65086`, then CodeRabbit posted a Major finding ~3 min later at the *same* head — pulling `submittedAt` for both proved the human never weighed the off-by-one, so the approval is recorded via `record_human_verdict` (the calibration join) but never flips the independent shadow decision, which stays ABSTAIN on the verified-real-but-low-severity gap [[approver/human-agreement] A human APPROVED commit can predate a later head-current bot finding — record the join but don't round the shadow decision up](../learnings/1785151870935-approver-human-agreement-a-human-approved-commit-c.md). **A whole-`TEST_CASE` skip is all-or-nothing:** slangpy#1076's `doctest::skip()` silenced deterministic cross-thread frame-rejection assertions bundled with the flaky drain-ordering ones — read the full test body, separate deterministic from flaky, and grep BOTH the C++ and Python suites for equivalent live coverage before scoring; uniquely-covered deterministic loss ⇒ OPEN_GAP (but narrow the claim precisely — the same-thread path was covered by a Python sibling) [[approver/challenger-miss] Whole-TEST_CASE skip can drop deterministic coverage bundled with the flaky assertions](../learnings/1785165216238-approver-challenger-miss-whole-test-case-skip-can-.md). **Green CI can mean the path never executed:** GitHub-hosted `macos-latest` exposes only an "Apple Paravirtual device" with non-functional Metal, so a slang-rhi Metal-only-feature PR's `.metal` cases all resolve to `SKIPPED (device not available)` while status is green — grep the `-check-devices` job log for the feature's test lines before treating the runtime path as verified; a SKIP is not a pass, and at that time slang-rhi had NO runner that could execute Metal (#800/#801/#802 all held on this) [[approver/challenger] slang-rhi Metal tests SKIP on GitHub-hosted macos-latest — green CI never executes the Metal path](../learnings/1785193552208-approver-challenger-slang-rhi-metal-tests-skip-on-.md). ⚠️ **Time-scope that observation:** slang-rhi#807 restored Metal device init, after which the paravirtual runner *does* execute Metal cases — so the "Metal always skips" note is a dated reading, not a standing property. Re-probe a runner-capability premise before reusing it; a present-tense claim in a durable record silently ages into a false one, and unlike a wrong number nothing ever flags it ([[approver/calibration] report the LAST occurrence plus the clean run after it — timestamp every observation or re-probe it](../learnings/1785822559259-approver-calibration-report-the-last-occurrence-pl.md)). **A target-neutral fix for a target-specific problem is a first-class design-risk axis:** slang#12156 rooted `__extern_cpp` exports at target-neutral IR lowering when the motivating issue was host-C++-only; the R3 ABSTAIN (on pdeayton-nv's scope objection, despite fully-green CI) was vindicated when jkwak-work closed it unmerged in favor of the host-scoped `isCPUTarget()` replacement #12242 — CI-green never resolves a design/scope objection, and "fix makes class A inherit class B's latent bug" is a design-scope flag, not a benign equivalence [[approver/human-agreement] R3-ABSTAIN-on-target-neutral-rooting-VINDICATED-closed-for-host-scoped-replacement](../learnings/1785201460764-approver-human-agreement-r3-abstain-on-target-neut.md).
