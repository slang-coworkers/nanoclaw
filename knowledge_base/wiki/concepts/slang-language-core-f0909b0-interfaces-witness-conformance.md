# Interfaces, witness tables, and conformance resolution in Slang

## TL;DR

Conformance bugs in Slang cluster around a few mechanisms:

- **Interface self-conformance (`isSubtype(IFoo, IFoo)`) is load-bearing**: `Optional<IFoo>`, `IFoo[]` and autodiff materials rely on it. Removing it for a `dyn IFoo` split breaks 68+ base files; limit the existential to explicit generic-arg sites with required conformance constraints.
- **Witness tables can legitimately hold duplicate requirement keys** (the autodiff DiffPair path relies on first-match in `findWitnessTableEntry`). Do not assert uniqueness.
- **Associated-type resolution reads the conforming type's CANONICAL witness table.** Conformance-check order and canonical-witness *ownership* (not the inheritance DAG) produce spurious `E38029`/`E38106`. `_getInheritanceInfo` caches only frames with nothing skipped, so an `isBeingChecked()` skip leaves a partial frame that recomputes wrong. When a check fails because an entry "is not checked yet", let lookup compute that one entry on demand (#12835), not force-check the whole type and retry.
- **Inherited DEFAULT methods calling sibling `this` methods** crash (`_replaceInstUsesWith(null)`) because a stale `conformingWitness` field bakes the derived table into `specialize(defaultImpl, ...)`. One producer fix covers static (#12814) and dynamic (#11487); consumer null-guards are the "do not mask" anti-pattern.
- **Un-named requirement keys collide on the empty mangled name** in witness-table clone deferral (equality-constraint keys are a second un-named class beyond `IRBuiltinRequirementKey`).
- **`tryLookUpRequirementWitness` handles only the `InheritanceDecl` declRef arm**; there is no natural `.slang` repro because normal compilation resolves via `getUnspecializedLookupRec`.
- A **shadowed inherited interface member** gives a 2-candidate overload that the member-base filter empties → ErrorType, no diagnostic → E99997 ICE.
- An existential as a generic argument is E33180 only under `#lang slang 2025`+; legacy mode specializes it via type-flow dispatch. Show both modes before calling it a known limitation.
- A lazily-synthesized conformance (enum `__EnumType`) plus a cache invalidated by a *different* event (extension epochs) is an order-dependent false-negative trap.
- A **function-local** type conforming to a *constrained* generic-method requirement crashes in `doesGenericSignatureMatchRequirement` (null `getSub`, constraint not `SignatureChecked`); fix with `ensureDecl(constraintDecl, SignatureChecked)`. `SLANG_ASSERT` is UB in release; use `SLANG_RELEASE_ASSERT` for a real guard.
- The **optional-constraint gap through inherited requirements** silently accepts operators and members (`where optional T : __BuiltinIntegerType { return a+b; }` has zero diagnostics) and ICEs elsewhere (#13011). The optional marker is lost at the inheritance step (a plain `$inheritance` witness, not a `TransitiveSubtypeWitness`); maintainer direction is a front-end lookup filter. Workaround: `if (T is X)`. Test ROOT interface vs sub-interface to localize.
- **Requirement enumeration and method-requirement witness synthesis** (E38100 deny-list gap, #13349 single-candidate `OverloadedExpr` ICE, #13260 non-static-satisfies-static) are on [[wiki/concepts/slang-language-core-requirement-witness-synthesis.md]].

## Self-conformance and the `dyn IFoo` split

Passing an interface type as a generic argument (`Optional<IFoo>`, structured buffers of interfaces, autodiff materials) works only because `isSubtype(IFoo, IFoo)` succeeds [interface self-conformance is load-bearing](../learnings/1786772419196-interface-self-conformance-is-load-bearing-for-sla.md). Tim Foley's AST-level `ExistentialType` makes `ExistentialType(IFoo)` not conform to `IFoo`; forming it at all explicit generic-arg sites and removing self-conformance broke 68 base files (dynamic-dispatch 51, autodiff 11, interfaces 5, generics 1). The low-churn slice: form the existential only at explicit generic-type-argument sites and only for required conformance-constrained params (skip equality and `where optional`). `ExistentialType` must canonicalize to a distinct node, because `Val::equals` compares resolved-pointer identity and collapsing it re-enables self-conformance.

The front-end chokepoint is `CoerceToProperTypeImpl`, the single funnel for var/field/param/return/generic-arg/element positions ("an interface is not a proper type, an existential is"). Exempt the constraint supertype re-entry (use the resolved `constraintParam->sup.type`), or `ITexelElement`→`dyn ITexelElement` breaks the core-module build [forming dyn IFoo needs auto-unboxing](../learnings/1786781226502-slang-forming-dyn-ifoo-everywhere-needs-auto-unbox.md). The breakage buckets are the deferred existential machinery: `maybeOpenExistential` must recognize `ExistentialType`; make-existential coercion (`X → dyn IFoo`) is unimplemented; per-operand conjunctions yield `(dyn IFoo)&(dyn IBar)`; autodiff mangling and `tryGetDifferentialType` have no `ExistentialType` case. E38029 (front-end reflexive-conformance reject) is distinct from IR-pass E33180, whose `isExistentialDerived` already covers bare and extracted existentials.

Whether an existential may be a generic argument depends on language version: `#lang slang 2025`+ rejects it (E33180), while legacy mode specializes it through type-flow dynamic dispatch (`tests/language-feature/dynamic-dispatch/dynamic-specialization-1.slang` passes as written, fails with `#lang slang 2025` prepended). So for a repro with no `#lang` line (#13817), "known limitation" and "legacy-mode bug" are both arguable: compile both modes (`( echo '#lang slang 2025'; cat repro.slang ) > r25.slang`), show both, and leave the call to the maintainer [check the language version before "known limitation"](../learnings/1792604336895-before-replying-known-limitation-on-dynamic-dispat.md).

## Duplicate requirement keys are legitimate

While fixing generic enum-extension conformance merging with int's (#12540), a guard asserting one entry per key in `findWitnessTableEntry` was wrong: the autodiff differential-pair path produces duplicate keys and relies on first-match (`matrix-row-major-dedup.slang` fired it) [duplicate requirement keys are legitimate](../learnings/1786802981602-witness-tables-can-legitimately-have-duplicate-req.md). The #12540 fix instead gives each conformance witness table an identity operand (its mangled name) so distinct conformances don't dedup. Method: when an advisory guard fires on an untouched suite, check the invariant on pristine master first.

## Order-dependent associated-type resolution: the #12659 / #12822 / #12874 family

The shared root: resolving an inherited requirement's associated type reads the conforming type's **canonical** witness table, which is null or partial if built in the wrong order.

**#12659.** With sibling `associatedtype ... : IFirst<Context>` bounds, the second use of `Context` as a generic arg fails: `tryAddConstraintBase` skips a constraint when `checkState.isBeingChecked()` (a cycle-breaker), so the unrelated `Context : IContext` is skipped mid-check, and `_getInheritanceInfo` refuses to cache the partial facet list → recomputed wrong → E38029 [assoc-type as generic arg loses witness](../learnings/1787248050437-assoc-type-as-generic-arg-loses-conformance-witnes.md). Direction: scope the skip to the constraint's own subject. A related pre-existing re-entrancy: `tryResolveConstraintTypes` resolves equality endpoints eagerly and defers only a `MemberExpr`, not a `GenericAppExpr`, so a sup like `Wrapper<Context>` re-enters an in-progress `_calcInheritanceInfo(Context)` → spurious E38029 [equality-constraint generic-app re-entrancy](../learnings/1788291891545-slang-inheritance-equality-constraint-generic-app-.md). An interface-typed equality sup is independently rejected E30404, so demonstrate with a generic-app struct sup.

**#12822.** `R<Container> value;` with `where T.Element == ConcreteElement` is E38029 at module scope but passes as a local var. The equality-blind linear pass is only the emission site; the root cause is that the projection `Container.Element` is not reduced at module-scope validation (in a function body the worklist solver reduces it) [assoc-type projection not reduced at module scope](../learnings/1787950486759-slang-12822-assoc-type-projection-not-reduced-at-m.md). Run the pass/fail isolation matrix even when a learning names an "obvious" emission-site defect. It was fixed by #12835 (merged 2026-09-14), not our closed draft #12827, which force-checked the whole concrete type and its extensions to `ReadyForConformances`, bumped the epoch and retried (an earlier form crashed the core-module bootstrap). #12835 splits requirement lookup into passive and forceful paths with per-requirement checking state (adds `InterfaceRequirementKey`), and `ensureAndResolveRequirementProjection` / `checkRequirementProjectionForConstraint` force only the one missing entry, so it is order-independent and re-entrant; its 11 `gh-12822-*` tests cover recursive cycles, multistep inheritance, extern, chained, typealias and negative-mismatch shapes [postmortem: #12822 superseded by #12835 — force one entry inside lookup, not the whole type at the failure site](../learnings/1792461690850-postmortem-shader-slang-slang-12822-superseded-by-.md).

**#12874.** A struct conforming to `IProvider & IShape & ISelfShape` (IShape redundant) leaves `Item` as `Value.Item` → E38106. The first hypothesis, a storage↔resolution asymmetry (`_mergeFacetLists` prefers the lowest-directness facet; non-canonical paths store a bare `Flavor::val` witness that `getUnspecializedLookupRec` rejects), was **superseded** [redundant interface base breaks assoc-type witness (superseded)](../learnings/1788298656584-slang-conformance-redundant-interface-base-breaks-.md). The root cause is conformance-check **order**: bases are checked in declaration order (`checkAggTypeConformance`/`checkExtensionConformance`), and if the canonical-path owner is checked after the requirement, its `witnessTable` is null [correction: #12874 is conformance-check ordering](../learnings/1788307346729-correction-to-12874-root-cause-it-is-conformance-c.md). A base-first topological sort is **unsound**: it regresses the diamond `IDerived & ICanonical & INeedsShape` by demoting the canonical owner, because the dependency is canonical-witness ownership (directness plus declaration-order tie-break), not the DAG. Prefer phased/targeted per-conformance witness construction; a whole-type `ensureDecl(self)` mid-check gives `CyclicReference` [conformance-order bugs assoc-type E38106](../learnings/1788307210066-slang-conformance-order-bugs-assoc-type-e38106-reo.md).

Minimal shape: `interface IBase { associatedtype T; } interface IDerived : IBase { void f(T value); } struct Impl : IDerived, IBase { struct T {} void f(T value) {} }` gives E38105 (E38106 with `T` in return position); `IBase, IDerived` or `IDerived` alone compiles. #12835's on-demand resolution has one external caller, generic constraint solving (slang-check-constraint.cpp:2922), so it does **not** fix conformance member-signature matching. In a regression test, `typealias T = int` in parameter position compiles in both orders, so use a nested type, user-struct alias, or return position [#12874 minimal shape; #12835 on-demand resolution doesn't cover conformance member matching](../learnings/1792093093563-12874-minimal-shape-12835-on-demand-resolution-doe.md). Still E38106 on master 653bfdeef (2026-10-22). Workaround for reporters: list the base interface first, or declare a nominal `interface IScalarProvider : IShape, IProvider, ISelfShape {}`. The non-canonical path in `ensureInheritedInterfaceRequirement` (slang-check-decl.cpp ~10492) stores only a redirect to the unfilled canonical table, and LookupDeclRef resolution is passive. A `where T.Item==int` constraint forces resolution through the solver and hides the bug, so keep it out of repros [#12874 minimal repro and workaround verified on 653bfde](../learnings/1792649429150-12874-reply-minimal-repro-and-workaround-verified-.md).

## Function-local conformance crashes on a constrained generic-method requirement

A function-local `struct Op : IOp` whose requirement is `int apply<T:__BuiltinArithmeticType>(T)` SIGSEGVs the front end on every target with no diagnostic; module-scope `Op`, no `: IOp`, or no constraint each compile [function-local conformance with a constrained generic method crashes (null getSub)](../learnings/1789014792514-function-local-interface-conformance-with-constrai.md). Same read-before-checked hazard as above: `doesGenericSignatureMatchRequirement` (`slang-check-decl.cpp` ~6152) calls `getSub` on a `GenericTypeConstraintDecl`, which is non-null only after `DeclCheckState::SignatureChecked`. Module-scope members get that before `ReadyForConformances`; function-local types do not, and `Val::equals` (`slang-ast-base.h:436`) guards only the argument, so `satisfyingSubType->resolve()` segfaults. Fix: `ensureDecl(satisfyingConstraintDecl, SignatureChecked)` first, as the And-type-flattening path already does.

Two invariants generalize [SLANG_ASSERT is SLANG_ASSUME (UB) in release; ensureDecl-before-enumeration for constraint flattening](../learnings/1789019735283-slang-assert-is-slang-assume-ub-in-release-ensured.md). (1) `SLANG_ASSERT` maps to `SLANG_ASSUME` in release (`source/core/slang-common.h` ~L371), so asserting something that can be false is UB; use `SLANG_RELEASE_ASSERT` for a real guard. (2) `SignatureChecked` both populates sub/sup and flattens `T : A & B` into per-conjunct members, so consumers of `getSub`/`getSup`/`getFromType`/`getToType` must advance the **constraint decls only** (the enclosing type re-enters the conformance check → `CyclicReference`) and do so **before enumerating** the generic's members; a stale snapshot can silently accept an over-constrained impl (a soundness bug). Diagnostic tests that also emit a `note:` need `//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK,non-exhaustive):`.

## The `tryLookUpRequirementWitness` LookupDeclRef gap has no natural repro

`tryLookUpRequirementWitness` returns `Flavor::none` when a `DeclaredSubtypeWitness`'s declRef base is a `LookupDeclRef`, because it handles only `.as<InheritanceDecl>()` [tryLookUpRequirementWitness LookupDeclRef gap](../learnings/1787675479061-trylookuprequirementwitness-lookupdeclref-gap-has-.md). Twelve natural `.slang` shapes compile on unfixed master because `_resolveImplOverride → tryResolve → getUnspecializedLookupRec` handles all three declRef shapes; only an internal resolver on a still-symbolic chain (the #12691 draft) hits it. Don't hunt a repro for such gaps; delegate the arm to `getUnspecializedLookupRec`/`specializeLookedUpRec`, closing the drift where `syntax.cpp` knew 1 of 3 shapes.

## The optional-constraint gap through inherited requirements

`isWitnessUncheckedOptional` (`slang-check-expr.cpp` ~1344) backs three gates: `filterLookupResultByCheckedOptional` (members), `slang-check-overload.cpp:1280` (operators) and `slang-check-constraint.cpp:2954` (solver). The gap ICEs in typeflow-specialize (#13011, E99997 "Unexpected context type for parameter info retrieval") and is also a front-end soundness leak: `where optional T : __BuiltinIntegerType { return a+b; }` (or `a%b`, `a.add(b)`) type-checks with zero diagnostics and no `if (T is I)` guard (#13061). The control `where optional T : IArithmetic`, which declares the operator, declines correctly (E39999 / E30403), so the bug fires whenever the requirement lives on a *super*-interface [Optional-constraint gap also silently accepts operators/members, not just ICE](../learnings/1789383448186-optional-constraint-transitive-witness-gap-also-si.md).

Builtin-free minimal regression test (master 653bfdeef): `interface IA { This plus(This o); } interface IB : IA {} struct S{int x;} T f<T>(T a,T b) where optional T : IB { return a.plus(b); }` called as `f<S>(s,s)` gives E99997, `optional T : IA` gives E30403; an uncalled `f` compiles, so instantiate it. Builtin matrix: `__BuiltinFloatingPointType`, `__BuiltinArithmeticType`, `IFloat`, `IInteger` ICE; `__BuiltinIntegerType` compiles silently (#13061); `IArithmetic`, `__BuiltinLogicalType` give E39999 [#13011 ICE reproduces with user interfaces only](../learnings/1792649521700-slang-13011-ice-reproduces-with-user-interfaces-on.md).

**Mechanism (corrected by instrumentation).** The first triage blamed a `TransitiveSubtypeWitness` not recursed via `getSubToMid()`. Instrumenting `where optional T : IFloat { a + b }` shows none: the helper sees a `DeclaredSubtypeWitness` on the optional constraint (T:IFloat) and a plain one on IFloat's own `$inheritance` decl (T:IArithmetic, no `OptionalConstraintModifier`). The marker is lost where lookup records the linearized facet witness as the SuperType breadcrumb (slang-lookup.cpp ~:494); fix by carrying optional-ness through `_getInheritanceInfo` or recovering it in the filter [optional-constraint filter: inherited requirement arrives as a plain InheritanceDecl witness](../learnings/1790788025222-slang-optional-constraint-filter-inherited-require.md). saipraveenb25's direction on #13011: "properly filter lookup items if they are reached through optional constraints", the front-end filter, not a typeflow guard [#13011 maintainer direction](../learnings/1792424334332-slang-13011-maintainer-direction-filter-lookups-re.md). Workaround until then: `if (T is __BuiltinFloatingPointType) return a + b; return a;` compiles on v2026.20 for float and struct; per-release status is on [[wiki/concepts/slang-tooling-release-tarball-repro-and-version-bisect.md]] [#13011 `if (T is X)` workaround](../learnings/1792403257595-slang-13011-optional-constraint-ice-if-t-is-x-guar.md).

Triage tips: test the ROOT interface against a sub-interface or builtin marker to localize the gap; check sibling issues' bot comments before restating a mechanism (#13061's trace corrected #13011's); a throwaway `fprintf` plus incremental Release `slangc` rebuild (~1.5 min) settles witness-kind questions (`Decl` has `parentDecl`, not `getParent()`).

## Inherited-default-method crash: one producer root cause

A static generic `combine<Value>` calling DEFAULT method `combineInPlace` on base `IBase`, with `Value : IDerived : IBase`, aborts `slang-ir.cpp(9011)` (`_replaceInstUsesWith(null)`) [inherited default-method static specialization crash](../learnings/1787932414310-inherited-default-method-static-specialization-cra.md). `-dump-ir` shows the `Value:IBase` entry as `specialize(defaultImplGeneric, Value, <Value:IDerived table>)`, so its inner `lookupWitness(IBase.combine)` misses. Cause: `slang-check-decl.cpp:11298` sets `context.conformingWitness` once and never refreshes it, while `findDefaultInterfaceImpl` reads that stale field instead of the per-table `subIsReqWitness` parameter. Fixing the producer resolves both static (#12814) and dynamic (#11487) variants; #11487's unmerged consumer patch (`findWitnessTableEntryInInheritanceClosure`) is the do-not-mask anti-pattern [inherited default-method: static and dynamic share one root cause](../learnings/1787937170959-inherited-default-method-witness-assert-static-128.md). `specializeWitnessLookup` (`slang-ir-translate.cpp:348`) is not null-guarded (unlike `maybeSpecializeWitnessLookup`), so check which is on the crash path. Leave `SLANG_ASSERT` unset; `release-assert-only` yields silently wrong IR.

## Witness-table clone deferral collides on the empty mangled name

`slang-dictionary.h(325): The key already exists` on generic code with associated-type **equality** constraints in a diamond is a back-end IR bug (#12817) [witness-table clone deferral collides on empty name](../learnings/1787936873954-slang-witness-table-clone-deferral-collides-on-emp.md). Triage tricks: the assert line names the container (`:325` = plain `Dictionary`, not the checker's `OrderedDictionary` at `:576`), and `-dump-ir` of the whole module localizes the crash to `linkIR`. `cloneWitnessTableImpl` defers entries by `getMangledName(requirementKey)`, empty for un-named keys; equality-constraint keys have no mangled name, so two defer under `""`. The eager-clone guard already exempts `IRBuiltinRequirementKey` for this reason. Fix: broaden that guard (no serialized-IR change), or give equality-constraint keys a distinct mangled name (touches linkage).

## Shadowed inherited members and lazily-synthesized conformances

When a derived interface re-declares an inherited member, lookup on a constrained type param returns a valid 2-candidate overload that `CompareLookupResultItems` can rank [shadowed inherited interface member ICE](../learnings/1786585128863-shadowed-inherited-interface-member-member-base-ov.md). In #12513 the member-access base path (`maybeInsertImplicitOpForMemberBase`) only filters out interface-parented candidates; with all candidates being requirements the set empties → ErrorType, no diagnostic → E99997. Discriminator: a shadowed non-member ICEs silently, the unshadowed one gives E30027. Fix: when the filter empties the set, rank the original with `resolveOverloadedLookup(refineLookup(..., LookupMask::Default))` (not `maybeResolveOverloadedExpr`, not `LookupMask::type`).

An enum failing `T : __EnumType` (E38029) only while checking the multi-file `__include` module that declares it (#12926) points to a **stale negative cache** [enum __EnumType conformance stale cache](../learnings/1788776018731-enum-enumtype-conformance-failing-in-multi-file-in.md): the conformance is synthesized late (`ReadyForLookup`), inheritance info caches negatives, and the cache is validated only against extension epochs, which the synthesized conformance does not bump. Any earlier query (extensions are driven `ReadyForLookup`-first) caches the poison. Fix where the facet list is built (`ensureDecl(subject, ReadyForLookup)`) or invalidate on the late `addMember`; guarding only `isSubtype` is insufficient.

See also [[wiki/concepts/slang-language-core-requirement-witness-synthesis.md]] for the #13260/#13269 non-static-method-satisfies-static-requirement adaptation.
