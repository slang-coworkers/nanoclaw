## TL;DR

- **A green `slang-test` run is not proof when FileCheck is absent** — `filecheck-buffer=CHECK` comparison is silently *skipped*, not failed, so an all-zeros output "passes." But `slang-test` actually runs FileCheck *internally* (links `createLLVMFileCheck_V1` from `libslang-llvm.so`), so build `slang-test` and the absence is a false blocker.
- **Every regression test needs a proven negative control:** copy the test to the pre-fix source, run it, and confirm it FAILS there for the RIGHT reason. A COUNT-N/`CHECK-NOT` test can pass vacuously on both builds.
- **Validate a must-fail repro against CURRENT source, not a stale prebuilt binary** — lowering of even trivial shapes drifts between builds, so a stale binary is not a valid oracle for what the current pre-fix path emits. Run the revert drill in YOUR build tree (`git show <base>:<path> > <path>`, rebuild, run, restore), never against a base clone's binary of unverified commit, and log the output. When a predicate gains several cases, drill each case alone.
- **rc 0 on an old release is not correct output.** When bisecting "old compiles, master crashes", compile the old release's `-target cpp` output with g++ and a small `main()` harness and check the values. Checking adjacent commits directly (~2 min Release `slangc` rebuild in a warm worktree) is cheaper than more tarballs.
- **Review a generated-test retarget PR by running master's test copies on the PR-head compiler:** master copies must fail exactly the nightly variants, PR copies must pass. `regenerate.py list-stale` must be unchanged for a hand-edit; re-stamped `//META` provenance needs explicit hand-edit disclosure in the PR body.
- **Verify "this test covers path X" claims with `-dump-ir`, not the source shape** — an uncalled helper is DCE'd before a post-specialization walker runs, so it tests DCE, not the gate.
- **IR FileCheck false-passes when the repro shares a function with control cases** — FileCheck binds a capture to the FIRST match; isolate the repro in its own entry point and anchor on `func %<name>` first.
- **DIAGNOSTIC_TEST carets align to the immediately-preceding non-annotation line** — never insert a comment between a source line and its `//CHECK:^` block. `DIAGNOSTIC_TEST` matches message text only and ignores the result code — assert `error E<code>` so a future downgrade fails.
- **A crash-realization bug only fires when the type is referenced** — an unreferenced decl is never realized; force realization when probing.
- **A change to a pass keyed on a suite-wide attribute needs the FULL suite**, not a chosen subdirectory subset — the attribute's blast radius can't be enumerated by directory name.
- Binding directives matter: `//TEST_INPUT:uniform(data=...)` binds a module-scope `uniform`; `cbuffer(...)`/`ubuffer(...)` do NOT (they read as zeros). A FileCheck prefix must not be a leading substring of another prefix in the same file (`CUDA`/`CUDA_EMPTY` collide).

## The vacuous-pass family: green ≠ verified

The most dangerous test failure mode is a test that passes while proving nothing, and several atoms document distinct mechanisms. When FileCheck is unavailable on the fixer/reviewer edge, a `//TEST:COMPARE_COMPUTE(filecheck-buffer=CHECK):-cpu` test runs the shader but *silently skips* the output-vs-CHECK comparison — `slang-test` reports `passed test:` regardless — so a `unorm`/`snorm` regression test "passed" 3/3 on cpu+cuda while every output was `0.000000`; only reading the generated `.slang.<n>.actual.txt` files revealed it [COMPARE_COMPUTE passes vacuously](../learnings/1786686310812-compare-compute-test-can-pass-vacuously-when-filec.md). This "FileCheck absent" blocker is often false: `slang-test` does **not** shell out to an external FileCheck binary — it links `createLLVMFileCheck_V1` from `libslang-llvm.so`, so any edge with a built `slang-test` + that lib can run FileCheck directives directly even when `which FileCheck` is empty [slang-test runs FileCheck internally](../learnings/1786715257186-slang-test-runs-filecheck-internally-no-external-f.md). The atoms give the same countermeasure two ways: when FileCheck truly can't run, `cat` the `.actual.txt` files and eyeball values by hand; otherwise build `slang-test` and run it. A companion trap: on an edge without FileCheck, `slang-test` marks `//TEST:SIMPLE(filecheck=...)` tests `ignored` (0 passed/0 failed) — indistinguishable from "passed" at a glance, so verify codegen-shape fixes by direct `slangc` emit + `grep -c` [dedup guard ray payload](../learnings/1786663782456-a-dedup-guard-keyed-on-an-entry-point-global-count.md) (cross-referenced from the crash-triage page).

**The negative control is the only proof a regression test discriminates.** The canonical drill (verified on OptiX payload #12537): fetch the PR head, run `slang-test` → pass; then `git checkout <base-sha> -- <the-one-source-file>` (revert ONLY the fix, keep the PR's test), rebuild, re-run → the test MUST fail; restore. A COUNT-N + `CHECK-NOT` test can pass vacuously, and the revert drill is the only proof [slang-test runs FileCheck internally](../learnings/1786715257186-slang-test-runs-filecheck-internally-no-external-f.md). Skipping this bit twice: an IR FileCheck false-passed because the repro and control cases lived in the same function — FileCheck binds a capture variable to the FIRST match, which was a *control* case's `load`, satisfying the sequence even on the buggy compiler; the fix is to isolate the repro in its own entry point and anchor on `func %<name>` first, then always validate the SIMPLE directive alone against the UNFIXED compiler [IR FileCheck false-passes](../learnings/1786617901622-ir-filecheck-false-passes-when-repro-shares-a-func.md). The drill's granularity matters too. When a fix adds several cases to one predicate, revert each case alone: on the #13321 autodiff fix, deleting only one of four new `BuiltinRequirementKind` cases (`case BwdApplyFunc:`) left every new test passing while `__apply(fwd_diff(f))` inside a `[Differentiable]` function went back to compiling silently, so that load-bearing branch had no test [drill each case of a multi-case predicate alone](../learnings/1790702192345-before-accepting-a-code-traced-new-crash-finding-r.md).

## Stale oracles and drifting lowering

Validating a must-fail control against a **stale prebuilt binary** is a trap because lowering drifts. On #12525, a stale base-clone binary lowered a by-value-parameter field access to `var`+`get_field_addr` (Ptr flavor), making a `CHECK: load` look like a proper must-fail control — but on current master the same shape lowers directly to `get_field` (a Simple value), so the fix was a no-op passthrough and the `load` CHECK would never match even post-fix. A stale binary is fine for *confirming the pre-fix bug existed historically*, but is NOT a valid oracle for *what the current pre-fix path emits* [validate must-fail repro against current source](../learnings/1786636025197-validate-must-fail-repro-against-current-source-no.md). The same trap bit a revert drill on slang#13313 / PR #13315: "new tests 0/12 on pre-fix master" came from running the shared base clone's `build/Release/bin/slang-test` against the worktree's tests, but the reviewer measured 1/12 on real master. One FileCheck variant (a lib_6_7 PAQ check that matched only the TraceRay wrapper master already emits) was vacuous, and the base binary's source commit had never been verified, so it was probably built before a recent merge. The reliable drill resets the changed source files to the base sha in *your own* worktree (`git show <base>:<path> > <path>`), rebuilds the same build tree, runs the tests, then restores the files and rebuilds; that gave a verified 0/12 → 12/12. Capture the output in a log file so a reviewer can check it. A related gotcha from the same session: `/tmp` symlinks can vanish mid-session, and `./extras/formatting.sh --cpp >/dev/null` then prints "needs clang-format" into the discarded output and formats nothing, so check the exit code of `--cpp --check-only` [revert drills must run in the same build tree, not a base-clone binary](../learnings/1790688100687-revert-drills-must-run-in-the-same-build-tree-not-.md). Related: verifying a coverage *claim* also needs `-dump-ir`, not the source shape — an "uncalled helper verifies the reachability-gate exclusion" comment was wrong because a zero-caller function is DCE'd before the diagnostic walker runs, so it tests plain DCE; the inclusion path is genuinely tested only where a *called* helper survives to the walker's pass [verify coverage claims with -dump-ir](../learnings/1786586906469-verify-test-coverage-claims-with-dump-ir-not-prose.md). The same "references matter" principle governs *probing* a crash: a type-realization crash (a bad modifier that only bites when the builtin-type accessor runs) never fires for a declaration that is never referenced — a first scope table tested unreferenced structs and wrongly concluded "does not reproduce"; always reference the decl (local var, param, field) so its type is realized before calling a case benign [type-realization crashes only fire when referenced](../learnings/1786671818928-type-realization-crashes-only-fire-when-the-type-i.md).

**The mirror image: an old release's rc 0 is not proof its output was right.** When bisecting a "regression" where an old release compiles and master crashes, check the old output's values before calling it a regression. A cheap check needs no slang-test: compile the old release's `-target cpp -stage compute -entry computeMain` output with g++. The emitted .cpp already `#include`s the release's own `include/slang-cpp-prelude.h`; append a small `main()` that fills `GlobalParams_0` (a `RWStructuredBuffer<float>` is `{T* data; size_t count;}`), sets `ComputeVaryingInput{startGroupID={0,0,0}, endGroupID={1,1,1}}`, calls `computeMain(&vi, nullptr, &gp)`, and prints the buffer: `(cat out.cpp; cat harness_main.cpp) > t.cpp && g++ -std=c++17 -w t.cpp && ./a.out`. On #13327 this showed that v2026.5.2 computed the right third-order derivative (`6 6 12`). In a warm worktree on the 64-core box, a Release `--target slangc` rebuild at an adjacent commit takes about 2 minutes, so checking parent-vs-suspect commits directly is cheaper than downloading more release tarballs [prove an old release -target cpp output is correct with a g++ host harness](../learnings/1790705791676-prove-an-old-slang-release-s-target-cpp-output-is-.md).

## Directive mechanics and suite scope

Several bite-sized directive facts recur. **Removing a test's explicit `-cuda` line can *add* a CUDA run:** any `-cpu` `COMPARE_COMPUTE` directive gets a synthesized CUDA run unless some directive in the file names `-cuda`, and `DISABLE_TEST` directives count because requirement collection runs over disabled directives too (`slang-test-main.cpp:6149-6199`); confirm with `slang-test -dry-run -api vk+cuda+...` and look for `syn (cuda)` ([re-run ls-remote right before citing a branch author's WIP](../learnings/1790952109142-re-run-ls-remote-right-before-citing-a-branch-auth.md)). `//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK)` matches message *text* by default and does NOT validate the process result/severity — assert `error E<code>` on the caret row so a future downgrade to a warning fails rather than silently passing [type-realization](../learnings/1786671818928-type-realization-crashes-only-fire-when-the-type-i.md). Position-based `//CHECK:^` carets align to the *immediately-preceding non-annotation source line*, so inserting an explanatory comment between the source line and its caret block shifts the reference and the whole block fails "columns don't match" — put explanatory comments *above* the checked line [DIAGNOSTIC_TEST carets align](../learnings/1786606749394-diagnostic-test-carets-align-to-the-immediately-pr.md). Binding directives: a module-scope `uniform Foo n;` is bound by `//TEST_INPUT:uniform(data=[...]):name=n`, NOT `cbuffer(...)`/`ubuffer(...)` (those are for constant/structured buffers) — the wrong binder leaves the uniform zero-initialized [COMPARE_COMPUTE passes vacuously](../learnings/1786686310812-compare-compute-test-can-pass-vacuously-when-filec.md). And no FileCheck *prefix* may be a leading substring of another prefix's check-line token in the same file: `CUDA` + `CUDA_EMPTY` collide (`error: misspelled directive 'CUDA_EMPTY:'`, reported as a code failure), while `GLSL_EXT` + `GLSL_NV` are fine — rename to `EMPTYCUDA` [FileCheck prefix superstring collision](../learnings/1786800115346-slang-test-filecheck-prefix-must-not-be-a-superstr.md).

Two atoms cover **test surface** rather than a single test. A behavior-changing emit/codegen PR's own new tests are not the whole surface: `docs/generated/tests/**` holds COMMITTED generated FileCheck tests that may assert the OLD behavior and regress silently on the next generated-suite run — grep the generated tree for the affected symbol and cross-check `expected-failures.txt`; the fix is to regenerate or add expected-failures entries [behavior-changing PR must reconcile generated tests](../learnings/1786531994900-a-behavior-changing-slang-pr-must-reconcile-commit.md). The reverse case, a PR that *only* retargets `docs/generated/tests` CHECKs with no compiler change, can be reviewed without building master. Build once at the PR head, copy master's versions of the edited .slang files into a scratch dir under `docs/generated/tests/`, and run slang-test on both sets: the master copies should fail exactly the nightly variants (`.3`/`.4` etc.) and the PR copies should pass; delete the scratch dir afterwards. `regenerate.py lint <bundle>` gives per-bundle errors; the whole-suite lint currently has 2 pre-existing errors in unrelated `_meta/findings` YAML, so compare against master rather than trusting a bare "0 errors". `regenerate.py list-stale` should be unchanged vs master for a hand-edit that doesn't regenerate docs, because mark-fresh would be a lie. `_meta/regenerate.md`'s "Hand-edit policy" forbids hand-editing bundle .slang/README; the accepted precedent (#12841) is to disclose the hand-edit explicitly in the PR body, so flag re-stamped `//META` provenance that has no such disclosure. Devin also timed out after 30 minutes on a *draft* PR (#13312), probably because it doesn't analyze drafts [verify generated-test retargets by running master test files on the PR-head compiler](../learnings/1790675891064-verify-agentic-test-retargets-by-running-master-s-.md). And a change to a pass keyed on a *suite-wide* attribute (`[ForceUnroll]`, `[unroll]`) must be verified against the ENTIRE `slang-test` suite, not a hand-picked "relevant directories" subset — a two-pass `[ForceUnroll]` rewrite passed a local sweep of 3 directories but failed the full CI suite on every platform including CPU, because the attribute is used across `tests/compute`/`tests/hlsl`/etc.; "relevant directories" is a trap because the attribute's blast radius is every test that uses it [pass touching suite-wide attribute needs full suite](../learnings/1786895359208-a-pass-that-touches-a-suite-wide-attribute-needs-t.md).
