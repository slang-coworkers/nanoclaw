# Slang Generics & Type System

Generic specialization, inference, overload resolution and checker recursion. Witness tables, extensions, coercion, visibility and codegen live in [[wiki/concepts/slang-language-witness-and-conformance.md]].

## TL;DR

- Generic params are solved from call/index arguments only; a return-position-only param cannot be inferred (E39999). Use a non-generic proxy plus a per-target `__init(proxy)` instead.
- E39999 has an extensible tagged-union failure reason; E30438 (arity), E30439 (unsolved param), E38029 (conformance) reuse it. Arity checks range-check against defaulted trailing params.
- The generic-arg comparison fence is half-built: `>`/`>=` are gated via `genericDepth`, `<`/`<=` are not, and `genericDepth` never resets inside `( )`.
- `hasModifier` on a generic/static method resolves via `getDecl()` to the inner `FuncDecl`.
- The any-value-inference recursion guard (#10686) covers only pointers; the `IRSpecialize`-operand path still overflows.
- An "unlowered X survives to emit" ICE with a concrete operand at the pass boundary is usually the pass's own produce/consume ordering (#11782). Dump IR at the boundary before blaming the producer.
- Literal coercion into a constrained generic param resolves against the INTERFACE's ctors before specialization: `(T)0.25` for `T:IArithmetic` floors to 0 (no `__init(float)`).
- Interface `__init` requirements cannot have default bodies (E30317). Add a conversion init as a BARE requirement: per-conformer, witness-synthesized, source-non-breaking.
- The #11493 builtin-operator fast path runs BEFORE overload resolution and silently ignores in-scope user overloads on builtin types.
- Overload diagnostics reuse #7857's machinery (type-coercion reason only). `AddOverloadCandidateInner` prunes losers early, so "X chosen over Y" diagnostics must capture there and suppress `isFromCoreModule`.
- Entry-point `-specialize` conformance context = `getModule()` + `getModuleDependencies()` (#12052).
- `static_assert(false)` in a `switch(T.kind)` arm of generically compiled code fires at generic check; diagnose unsupported kinds at IR emit.
- A new `TryJoinTypes` arm is gated off the constraint solver (on only at `mergeTypeConstraint`); `_coerce` arbitrates legality.
- Recursion that builds a NEW type per level defeats identity guards: skip the converse join for interface subjects (except concrete equalities), carry a budget across the extension candidate search, cap type walkers at `kMaxTypeNestingDepth`, key seen-sets on instantiated `Type*`.
- `where X == Concrete` reduces a fresh `X.A` but not a substituted one (no congruence). Workaround: state the nested equality.
- Through `where X : I`, `X.Assoc` stays symbolic; `where X.Assoc == Y` feeds coercion, not member lookup. Do not route public aliases through associated types.

## Generic Specialization and Inference

**Return-position-only params are unsolvable.** The checker specializes a generic (including a `__subscript`) from the index or call arguments only; it does not thread the assignment/coercion target in. A core-module `__generic<T:IOpaqueDescriptor> __subscript(uint) -> DescriptorHandle<T>` compiles, but `Texture2D t = ResourceDescriptorHeap[i];` fails with `E39999 could not specialize generic for arguments of type (uint)`. That killed Approach A for #11568; viable paths are a non-generic proxy with a per-resource `T.__init(proxy)` or a checker change. Spike gotchas: `__subscript` attributes go on the accessor (else E31002); a `static const` struct global needs `= {}` (else E31225) ([Slang generic __subscript cannot infer a return-position-only type param from coercion target (E39999)](../learnings/1781222181614-slang-generic-subscript-cannot-infer-a-return-posi.md), [CORRECTION: ResourceDescriptorHeap Approach A (return-position generic subscript) is a dead end — E39999](../learnings/1781222607198-correction-resourcedescriptorheap-approach-a-retur.md)).

**Failure reasons.** E39999 carries a tagged union `GenericArgumentInferenceFailure` (PR #11571); PR #11656 added the focused codes E30438 (arity), E30439 (unsolved param) and E38029 (conformance not satisfied), covering 3 of ~9 sites ([slang E39999 'could not specialize generic' has an extensible failure-reason mechanism (PR #11571)](../learnings/1781684668464-slang-e39999-could-not-specialize-generic-has-an-e.md), [slang #11643 RESOLVED — focused generic-specialization diagnostics landed (PR #11656), 3 of ~9 sites done](../learnings/1781729215980-slang-11643-resolved-focused-generic-specializatio.md)). Arity diagnostics must range-check against defaulted trailing parameters, not compare against the total count ([Slang generic-arg arity diagnostics must range-check against defaulted params](../learnings/1781753229607-slang-generic-arg-arity-diagnostics-must-range-che.md)).

**Parser fence.** In `GetOpLevel`, `>` and `>=` inside a generic argument list are gated via `genericDepth`, but `<` and `<=` are not, and `genericDepth` is never reset inside `( )`, so parenthesizing an already-banned operator does not work today ([Slang generic-arg comparison fence is half-built; parens escape hatch is broken](../learnings/1780512896132-slang-generic-arg-comparison-fence-is-half-built-p.md)).

**Attributes on generic methods.** `hasModifier` resolves via `getDecl()` to the inner `FuncDecl`, not the wrapping `GenericDecl`; verify GPU-only attribute cases with a CPU generic proxy ([Slang: hasModifier on generic/static methods resolves via getDecl() to inner FuncDecl; verify GPU-only attribute cases with a CPU generic proxy](../learnings/1780497220869-slang-hasmodifier-on-generic-static-methods-resolv.md)).

**Any-value inference.** `_findDependenciesOfTypeInSet` has only the #10686 pointer-case guard, not a general visited-set, so a self-referencing generic used through an interface still overflows via `IRSpecialize` operands ([Slang any-value-inference recursion: #10686 pointer guard is partial; IRSpecialize-operand path bypasses it](../learnings/1780353989621-slang-any-value-inference-recursion-10686-pointer-.md)).

**`makeConditionalValue` ICE (#11782).** The repro needs nothing more exotic than a plain generic `outer<T>`, never monomorphized in the single-compile AOT path, that calls an inner `<let flag:bool>` with a literal bool ([Conditional-flag ICE #11782 needs only a plain un-monomorphized enclosing generic](../learnings/1784793304583-conditional-flag-ice-11782-repros-need-only-a-plai.md)). **Correction (IR dump, PR #13043):** the flag is not symbolic; specialization already made it `Conditional(Int, true)`. The cause is ordering inside `slang-ir-lower-conditional-type.cpp`: `processModule` uses one LIFO worklist for the producer (`processConditionalType`, which records `loweredConditionalTypes[condType]`) and the consumers (`processMakeConditionalValue`/`processGetConditionalValue`). A consumer visited first hits `if (!info) return;`, gets re-typed to `Int`, and reaches `SLANG_UNIMPLEMENTED_X` in `slang-emit-spirv.cpp` (tell: a still-present `makeConditionalValue` after the pass). The fix resolves the type on demand via an idempotent helper and emits a once-per-type `Diagnostics::Unimplemented` ([#11782 conditional ICE root cause is an intra-pass ordering bug in lowerConditionalType, not a symbolic flag](../learnings/1789302491936-11782-conditional-ice-root-cause-is-an-intra-pass-.md)).

**Literal coercion into a constrained param (#12311).** `(T)0.25` in `T f<T:IArithmetic>()` returns `0.0` for `T=float`. `IArithmetic` (core.meta.slang) declares only `__init(int)`/`__init(This)`, unlike `IFloat`, so the front-end path `visitTypeCastExpr`→`_coerce`→`lookupConstructorsInType` converts float→int at generic-check time (warning E30081 always names `int`), and the folded `0` is baked into the generalized IR. Specialization and emit are victims; `(T)0.25f` and `T(0.25)` fail alike. Design fork for maintainers: (A) add `__init(float)` to `IArithmetic`, or (B) defer literal conversion for a constrained param to specialization (non-breaking but delicate) ([Generic (T)float-literal cast floors to 0 — IArithmetic lacks __init(float)](../learnings/1785559222590-generic-t-float-literal-cast-floors-to-0-iarithmet.md)).

**Fork (A) must use a bare requirement.** An interface may give a METHOD requirement a default body (`tests/language-feature/interfaces/default-method.slang`), but a defaulted `__init` inside an `interface` fails core-module compile with `error[E30317]: interface requirement has body`. The bare `__init(float val);` is also the only value-preserving form: each conformer binds its own `__init(float)` (a default body would route through `int(val)`), and builtin `int`/`vector<int,N>`/CoopVec/CoopMat and a user `struct : IArithmetic` with only `__init(int)` auto-satisfy it via witness synthesis (verified). Serialized-module ABI of an added requirement is a separate question ([Slang interface: __init requirements cannot have default bodies (E30317)](../learnings/1785565100286-slang-interface-init-requirements-cannot-have-defa.md)).

## Builtin-operator fast path silently bypasses user overloads (#11493)

PR #11493 (`61ad43dbc`, first in v2026.11) added `SemanticsExprVisitor::convertToBuiltinArithmeticOp` (`slang-check-expr.cpp:4605`), called from `visitInvokeExpr` at :5007 and returning before `CheckTerm`/`ResolveInvoke` (:5044). For builtin arithmetic/comparison/bitwise/shift/unary operators on builtin scalar/vector/matrix operands it builds a `BuiltinOperatorExpr` and skips overload resolution, so a user overload such as a global `operator*(float4x4,float4x4)` is ignored with no diagnostic (discussion #11840, regressed 2026.9→2026.11). The path already defers matrix operators in GLSL operator scope (:4634-4637, :4723-4730); the fix direction is a cheap "non-core user `operator OP` in scope" check that keeps the common fast path. Same class as the earlier float-bitwise → E39999 decline ([Slang #11493 builtin-operator fast path silently bypasses user operator overloads on builtin scalar/vector/matrix types](../learnings/1782894605011-slang-11493-builtin-operator-fast-path-silently-by.md)).

## Overload-failure diagnostics and candidate pruning (#12035, #12284)

The #12035 "explain why each candidate was rejected" ask reuses #7857's machinery. `OverloadCandidate` (`slang-check-impl.h:377-456`) has a coarse `Status` (Unchecked → ArityChecked → FixityChecked → TypeChecked → DirectionChecked → VisibilityChecked → Applicable, plus GenericArgumentInferenceFailed), the first un-coercible arg (`argMismatchArgIndex/ExpectedType/ActualType`, set in `recordArgMismatch` at `slang-check-overload.cpp:877-886` only when bare types differ), `conversionCostSum`, and `genericInferenceFailure`. The no-applicable emitter (:3520-3611) sorts `bestCandidates` by status and prints `argument N does not match: expected 'X', got 'Y'`. Gaps: arity (not stored), inaccessibility (E40014 only in the ambiguous branch, :3692), failed generic constraints and direction mismatches show only the signature. Split: (A) fix-ready, emit the remaining reasons on the #7857 pattern; (B) design-gated, true proximity ranking, which needs candidate retention on the hot path because `bestCandidates` keeps only the tied furthest-progressing set ([slang#12035 overload-failure diagnostics — #7857 already built most of the per-candidate machinery](../learnings/1783656901958-slang-12035-overload-failure-diagnostics-7857-alre.md)).

The same pruning gates #12284 (warn when an imported module's better overload silently rebinds a call). `AddOverloadCandidateInner` (:2461-2540) `fastRemoveAt`s worse existing candidates and drops a strictly-worse new one, and the winner is finalized later at `CompleteOverloadCandidate`. With local `fn(int)` (uint→int cost) vs imported `fn(uint)` (cost 0), the local loser is gone before the decision point, so the feature must record contributing modules at the choke-point and suppress `isFromCoreModule()` (else it fires on `lerp`, texture ops, and most implicit-conversion stdlib calls). Rule: for any "diagnose when X was chosen over Y" feature, first check whether the loser survives to the decision point ([slang-12284-overload-pruning-discards-beaten-local-candidate](../learnings/1785405718177-slang-12284-overload-pruning-discards-beaten-local.md)).

## Generic entry-point -specialize and primary-file extensions (#12049)

`slangc file.slang -entry g -specialize float` on `void g<T:IDenorm>(...)` gave E38029 when `float:IDenorm` came from an `extension` in the same command-line file. `EntryPoint::_validateSpecializationArgsImpl` built its context with `m_module = nullptr`, so `getCandidateExtensionsForTypeDecl` enumerated only `m_linkage->loadedModulesList`, and the primary TU lives in the request-local `loadedModules` dict instead. Moving the interface and extension into an imported module made the error vanish. Adding the primary TU to `loadedModulesList` was rejected (broad reflection/import blast radius) ([slang#12049 -- generic entry-point -specialize can't see primary-file extension conformances](../learnings/1783701731376-slang-12049-generic-entry-point-specialize-can-t-s.md)). PR #12052 (merged 2026-07-16) shipped that approach: the context is scoped to `getModule()` + `getModuleDependencies()` ([slang#12049 SHIPPED — Approach A confirmed: entry-point -specialize conformance scoped to getModule()+getModuleDependencies()](../learnings/1784167461042-slang-12049-shipped-approach-a-confirmed-entry-poi.md)).

## static_assert(false) in a switch(T.kind) arm fires eagerly (#12185)

In `defaultGetDescriptorFromHandle` (hlsl.meta.slang), a `static_assert(false, ...)` in a `switch(T.kind)` case of a generic `[ForceInline]` function worked at a concrete call site but broke a test's own `export T getDescriptorFromHandle<T:IOpaqueDescriptor>(...)`: an `export` generic is type-checked with `T` symbolic, so the switch cannot fold and E41400 fires for every kind. The existing `static_assert(false)` at :27778 is safe because it is in `default:` of `switch(bindlessOptions)`, a `constexpr` param. Emit "unsupported kind on this target" at the IR-emit consumer; a plain `if (T.kind == X) return ...; else ...` is safe. Always run the reporter's exact repro (`desc-handle-default.slang`) ([static_assert(false) in a switch(T.kind) arm fires EAGERLY for generic export functions](../learnings/1784691233062-static-assert-false-in-a-switch-t-kind-arm-fires-e.md)).

## TryJoinTypes: a new join arm must be gated off the constraint solver

`SemanticsVisitor::TryJoinTypes` (`slang-check-constraint.cpp`) is shared by ordinary-argument common-type inference (`mergeTypeConstraint`, ~:2019) and the witness/subtype/equality solver for optional `where` clauses (~:1772). The enum⊕scalar arm of slang#13160 (fix #13158) decays an enum to its tag type so `cond ? Enum::Case : 0` and `select(...)` infer a scalar instead of falling to the deprecated `vector<T,1>` overload (opaque E30019 plus spurious E30056). It sits behind a defaulted `allowEnumScalarJoin` enabled only at `mergeTypeConstraint`; in the solver it would fabricate `T == int` and break `where optional T == int`. The join only nominates; `_coerce` (`slang-check-conversion.cpp:2201-2220`, `if (tagType == toType)`) stays the sole arbiter, so an inapplicable arm still gets a clean per-arm error. This follows #12753's lesson that "fixing the join" is usually wrong because the join is solver-shared ([extending TryJoinTypes with a new join arm — gate it off the solver](../learnings/1789678492053-extending-tryjointypes-with-a-new-join-arm-gate-it.md)).

The flag alone does not keep widening out of the solver: `TryJoinVectorAndScalarType` already runs unconditionally, so `struct S : IA<float>, IB<float3>` passed to `pick<T,U>(T) where optional T:IA<U> where optional T:IB<U>` solves `U=float3`, while unrelated `IA<Foo>, IB<Bar>` fails E30442. Verify scope with an `IA<X>, IB<Y>` optional-`where` probe, not by reading the flag's call site ([TryJoinTypes vector/scalar join already feeds optional-constraint solving](../learnings/1789690773518-tryjointypes-vector-scalar-join-already-feeds-opti.md)). Residual review gaps: the flag broadens every generic call (`f<T>(T,T)` with `(enum, scalar)` now infers `T=tagType`), so add a user generic-overload regression; the arm's recursion is inert (tag is always a `BasicExpressionType`), worth asserting.

## Unbounded checker recursion: each level is a NEW type, so identity guards never fire

**Witness-shape inference on an interface subject (#13461, PR #13468).** `tryInferOrdinaryArgsFromWitnessConstraint` (~:1807) calls the symmetric `TryJoinTypes(sub, sup)`, which swaps operands when `sub` is an interface (:404) and so asks whether `sup` conforms to `sub`. With `extension<T> T : IRec<T> where T : IOther<T> {}` and any `struct Z : IOther<Z>`, the join becomes `isSubtype(IOther<IOther<Z>>, IOther<Z>)`, re-applying the extension to ever larger types until a SIGSEGV with no diagnostic (regression from #11210, 79ac457f0). Each level is a new `Type*`, so `isComputing`, extension circularity and the subtype cache never fire. A second leg, `cacheSubtypeWitness`, linearizes the sup's inheritance before checking whether the sub is in progress; each leg alone still overflows, so both are cut (check the sub first). The fix that held skips the join only when `isInterfaceType(sub) && !(isEqualityConstraint && !isInterfaceType(sup))`: a directional `_tryJoinTypeWithInterface` turned a rejected program into an E99997 ICE, and a blanket skip broke `f<T = IGet>() where T == G`, whose swapped join IS the solution. Tests reach the path only through array arguments (`IFoo<int> arr[2]` for a `T[2]` param); `f<IFoo<int>>(a)` is a separate E99997 (#13469). An A/B against the last-good release binary (`gh release download`) caught both regressions the suite missed ([witness-shape inference on interface subjects: skip the join but exempt concrete equalities](../learnings/1791336953861-slang-witness-shape-inference-on-interface-subject.md), [unbounded checker recursion where each level is a NEW type defeats identity guards](../learnings/1791316435617-unbounded-checker-recursion-where-each-level-is-a-.md)).

**The inheritance circularity guard is decl-identity only and resets per nested query (#13470).** `extension<X> Wrap<X> : I where Wrap<Wrap<X>> : I {}` overflows on every release since v2024.14, even unused. `checkAndConstructSubtypeWitness` calls `getInheritanceInfo(subType)` with `circularityInfo = nullptr` (slang-check-conformance.cpp:269); the extension's `InheritanceCircularityInfo` frame is pushed only after `applyExtensionToType` succeeds (slang-check-inheritance.cpp:855 → :866 → :228); and `_checkForCircularityInExtensionTargetType` cannot tell this from well-founded `where X : I` recursion. A per-`GenericInferenceContext` cap fails because each application makes a fresh context (slang-check-decl.cpp:17722); the budget must carry across the candidate search, on the `_checkForCircularityInConstantFolding`/`kMaxTypeNestingDepth` (E39997) pattern. That budget is principled only for this non-terminating shape, not for #13461, which terminated before #11210. Diagnosing without gdb: run at `ulimit -s` 2/8/64 MB (always crashes, time grows ⇒ unbounded); an LD_PRELOAD SIGSEGV handler (`sigaltstack` + `backtrace()`) plus `addr2line -e libslang-compiler.so.<ver>.dwarf` symbolizes frames; print `type->toString()` at `_getInheritanceInfo` entry; skip the innermost ~400 `collectDependentDeclsInVal` frames; a two-state Release build of suspect vs parent (~10 min) pins the regression ([inheritance circularity guard is decl-identity only and is reset at checkAndConstructSubtypeWitness](../learnings/1791331579789-slang-inheritance-circularity-guard-is-decl-identi.md), [unbounded checker recursion: two-state + growing-stack test](../learnings/1791316435617-unbounded-checker-recursion-where-each-level-is-a-.md)).

**A type walker's seen-set needs a depth cap too (#13538).** `struct LoopTail<each T> { float4 x[]; LoopTail<T, int> next; }` builds a new type each step (`LoopTail<int,int>`, `LoopTail<int,int,int>`, ...), so a walk that stops on a repeated `Type*` hangs or segfaults; master's `getTrailingUnsizedArrayElement` already did so for `ConstantBuffer<LoopTail<int>>`. Bound every walker with `for (UInt depth = 0; depth < kMaxTypeNestingDepth; depth++) { ... } return nullptr;` so validation reports fatal E39997, pinned by a `DIAGNOSTIC_TEST:SIMPLE(diag=CHECK,non-exhaustive)` test in its own file. Key the seen-set on the instantiated `Type*` (as `TypeTagContext` does), not the `Decl*`: `Box<Box<float4>>` instantiates one decl twice and is not a cycle. Related: after `IComponentType::specialize`, validate only the composite's entry points (fall back to `module->getEntryPoints()` only when it has none), or `{module, b}` fails on an uncompiled `a` ([a seen-types cycle guard does not terminate a generic struct that grows its own arguments](../learnings/1791547431780-slang-a-seen-types-cycle-guard-does-not-terminate-.md), [key recursion guards on the instantiated Type*](../learnings/1791528614678-new-front-end-errors-can-break-the-nightly-agentic.md)).

## Associated types through constraints: what lookup can and cannot reduce (#13509, #13537)

**No congruence for equality constraints.** With `where C.Primitive == TrianglePrimitive`, a freshly spelled `C.Primitive.Attributes` resolves to `TrianglePrimitive.Attributes` because member lookup sees the equality base added by the generic-parameter scan (slang-check-inheritance.cpp:1334-1433). The same type arriving through substitution (a field of `Input<C>`, a `let`, the return type of `g<C>()`, `Input<C>.A`) stays unreduced: substitution yields `LookupDeclRef(Attributes, witness C.Primitive : IPrimitive)` and `resolve()` is context-free. Its inheritance then has no base, since the lookup-derived scan (:1057-1331) matches only constraint endpoints canonically equal to `selfType` (:1200-1211) and the generic-parameter scan needs an exact subject (:1419). So there is no `X == Y ⇒ X.A == Y.A` rule, on every release back to v2025.1. A 36-line congruence base at the end of the lookup-derived block fixes it with the full suite green: take the lookup source's equality facets, project `Y.A` via `isSubtype(Y, interface)` + `getLookupDeclRef`, `resolve()` it, and add it under the existing depth guard and in-progress skip. Workaround: state `where C.Primitive.Attributes == TriangleAttributes` directly (placing the prefix constraint before it gives E30405). Debug tip: print facets in `getInheritanceInfo(Type*)` (:139), not `_calcInheritanceInfo` [equality constraints lack congruence: substituted X.A never reduces](../learnings/1791443571566-slang-equality-constraints-lack-congruence-substit.md). The related module-scope projection gap of #12822 is on [[wiki/concepts/slang-language-core-f0909b0-interfaces-witness-conformance.md]].

**Member lookup through a generic constraint is weaker still.** `_tryLookUpExistingRequirementWitnessRec` (slang-ast-decl-ref.cpp ~407) resolves `X.Assoc` from a concrete conformance's `InheritanceDecl::witnessTable`, which has associated-type entries; for `where X : I` it reads `GenericTypeConstraintDecl::pathResolutionTable`, which holds only inherited-interface paths (slang-check-decl.cpp ~12350), so `X.Assoc` stays opaque. The checker does not search for a more concrete conformance either: a core-module `extension<int N> vector<float,N> : I` cannot match `vector<T,1>` while `T` is abstract. `where X.Assoc == Y` is consumed by coercion (slang-check-conversion.cpp), not lookup: `Y v = x; v.m` compiles but `x.m` fails "not a member of 'X.Assoc'", on master too (`where T.A == float2` with `a.x`). Routing a public alias through an associated type (`_Texture<T.DataType, …>`) therefore broke SlangPy's generic code on slang #13537 [associated types through a generic constraint stay symbolic](../learnings/1791916553178-slang-associated-types-through-a-generic-constrain.md). The same alias defeats inference of `f<T>(Texture2D<T>)`; see [[wiki/concepts/slang-language-core-f0909b0-generics-overload-inference.md]].
