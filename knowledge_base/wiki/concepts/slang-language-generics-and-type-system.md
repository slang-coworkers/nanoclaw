# Slang Generics & Type System

Generic specialization, inference, overload resolution, checker recursion, and two IR type-shape facts. Witness tables, extensions, coercion, visibility and codegen live in [[wiki/concepts/slang-language-witness-and-conformance.md]].

## TL;DR

- Generic params are solved from call/index arguments only; a return-position-only param cannot be inferred (E39999). Use a non-generic proxy plus a per-target `__init(proxy)` instead.
- E39999 has an extensible tagged-union failure reason; E30438 (arity), E30439 (unsolved param), E38029 (conformance) reuse it. Arity checks range-check against defaulted trailing params.
- The generic-arg comparison fence is half-built: `>`/`>=` are gated via `genericDepth`, `<`/`<=` are not, and `genericDepth` never resets inside `( )`.
- `hasModifier` on a generic/static method resolves via `getDecl()` to the inner `FuncDecl`.
- The any-value-inference recursion guard (#10686) covers only pointers; the `IRSpecialize`-operand path still overflows.
- An "unlowered X survives to emit" ICE with a concrete operand at the pass boundary is usually the pass's own produce/consume ordering (#11782). Dump IR at the boundary before blaming the producer.
- Literal coercion into a constrained generic param resolves against the INTERFACE's ctors before specialization: `(T)0.25` for `T:IArithmetic` floors to 0 (no `__init(float)`).
- Interface `__init` requirements cannot have default bodies (E30317). Add a conversion init as a BARE requirement: per-conformer, witness-synthesized, source-non-breaking.
- The #11493 builtin-operator fast path runs BEFORE overload resolution and silently ignores in-scope user overloads on builtin types.
- Overload diagnostics reuse #7857's machinery (type-coercion reason only). `AddOverloadCandidateInner` prunes losers early, so "X chosen over Y" diagnostics must capture there and suppress `isFromCoreModule`.
- Entry-point `-specialize` conformance context = `getModule()` + `getModuleDependencies()` (#12052).
- `static_assert(false)` in a `switch(T.kind)` arm of generically compiled code fires at generic check; diagnose unsupported kinds at IR emit.
- A new `TryJoinTypes` arm is gated off the constraint solver (on only at `mergeTypeConstraint`); `_coerce` arbitrates legality. The join has no Ptr⊕NullPtr or Optional⊕None arm, so `c ? p : nullptr` and `c ? opt : none` fail E39999 before `_coerce` runs (#14059); the fix is the same gated nominate-and-let-`_coerce`-decide pattern.
- Recursion that builds a NEW type per level defeats identity guards: skip the converse join for interface subjects (except concrete equalities), carry a budget across the extension candidate search, cap type walkers at `kMaxTypeNestingDepth`, key seen-sets on instantiated `Type*`.
- `where X == Concrete` reduces a fresh `X.A` but not a substituted one (no congruence). Workaround: state the nested equality.
- An `==` constraint's sides are sorted by declaration order (only behind the non-essential-validations gate) but checked one way (`isSubtype(sub, sup)`), so a false E38029 that disappears when two interface declarations swap places, or under `-disable-non-essential-validations`, is this orientation bug (#14075), not missing congruence.
- Through `where X : I`, `X.Assoc` stays symbolic; `where X.Assoc == Y` feeds coercion, not member lookup. Do not route public aliases through associated types.
- IR `as<T>`/`dynamicCast<T>` look through `IRAttributedType` by default; type-pointer equality does not, so unwrap before comparing.
- Every backend lowers `vector<T,1>` to a scalar, so only an IR-dump check, not an emitted-code FileCheck, can pin whether it survived.

## Generic Specialization and Inference

**Return-position-only params are unsolvable.** The checker specializes a generic (including a `__subscript`) from the index or call arguments only; it does not thread the assignment/coercion target in. A core-module `__generic<T:IOpaqueDescriptor> __subscript(uint) -> DescriptorHandle<T>` compiles, but `Texture2D t = ResourceDescriptorHeap[i];` fails with `E39999 could not specialize generic for arguments of type (uint)`. Spike gotchas: `__subscript` attributes go on the accessor (else E31002); a `static const` struct global needs `= {}` (else E31225) [return-position param unsolvable](../learnings/1781222181614-slang-generic-subscript-cannot-infer-a-return-posi.md). That killed Approach A for #11568 (correcting an earlier "front-end-only" recommendation); the backend stays reusable, and the viable paths — handed to jkwak-work as design decisions — are a non-generic proxy with a per-resource `T.__init(proxy)` or a checker change [Approach A dead end](../learnings/1781222607198-correction-resourcedescriptorheap-approach-a-retur.md).

**Failure reasons.** E39999 carries a tagged union `GenericArgumentInferenceFailure` (PR #11571) [extensible failure reason](../learnings/1781684668464-slang-e39999-could-not-specialize-generic-has-an-e.md); PR #11656 added focused codes E30438 (arity), E30439 (unsolved param) and E38029 (conformance not satisfied), covering 3 of ~9 sites [#11643 resolved](../learnings/1781729215980-slang-11643-resolved-focused-generic-specializatio.md). Arity diagnostics must range-check against defaulted trailing parameters, not compare against the total count [arity range-check](../learnings/1781753229607-slang-generic-arg-arity-diagnostics-must-range-che.md).

**Parser fence.** In `GetOpLevel`, `>` and `>=` inside a generic argument list are gated via `genericDepth`, but `<` and `<=` are not, and `genericDepth` is never reset inside `( )`, so parenthesizing an already-banned operator does not work today [half-built fence](../learnings/1780512896132-slang-generic-arg-comparison-fence-is-half-built-p.md).

**Attributes on generic methods.** `hasModifier` resolves via `getDecl()` to the inner `FuncDecl`, not the wrapping `GenericDecl`; verify GPU-only attribute cases with a CPU generic proxy [hasModifier via getDecl()](../learnings/1780497220869-slang-hasmodifier-on-generic-static-methods-resolv.md).

**Any-value inference.** `_findDependenciesOfTypeInSet` has only the #10686 pointer-case guard, not a general visited-set, so a self-referencing generic used through an interface still overflows via `IRSpecialize` operands [#10686 guard is partial](../learnings/1780353989621-slang-any-value-inference-recursion-10686-pointer-.md).

**`makeConditionalValue` ICE (#11782).** The repro needs only a plain generic `outer<T>`, never monomorphized in the single-compile AOT path, that calls an inner `<let flag:bool>` with a literal bool [plain generic repro](../learnings/1784793304583-conditional-flag-ice-11782-repros-need-only-a-plai.md). **Correction (IR dump, PR #13043):** the flag is not symbolic; specialization already made it `Conditional(Int, true)`. The cause is ordering inside `slang-ir-lower-conditional-type.cpp`: `processModule` uses one LIFO worklist for the producer (`processConditionalType`, which records `loweredConditionalTypes[condType]`) and the consumers (`processMakeConditionalValue`/`processGetConditionalValue`). A consumer visited first hits `if (!info) return;`, is re-typed to `Int`, and reaches `SLANG_UNIMPLEMENTED_X` in `slang-emit-spirv.cpp` (tell: `makeConditionalValue` survives the pass). The fix resolves the type on demand via an idempotent helper and emits a once-per-type `Diagnostics::Unimplemented` [intra-pass ordering](../learnings/1789302491936-11782-conditional-ice-root-cause-is-an-intra-pass-.md).

**Literal coercion into a constrained param (#12311).** `(T)0.25` in `T f<T:IArithmetic>()` returns `0.0` for `T=float`. `IArithmetic` (core.meta.slang) declares only `__init(int)`/`__init(This)`, unlike `IFloat`, so `visitTypeCastExpr`→`_coerce`→`lookupConstructorsInType` converts float→int at generic-check time (warning E30081 names `int`) and the folded `0` is baked into the generalized IR; specialization and emit are victims; `(T)0.25f` and `T(0.25)` fail alike. Fork: (A) add `__init(float)` to `IArithmetic`, or (B) defer literal conversion for a constrained param to specialization (non-breaking, delicate) [(T)0.25 floors to 0](../learnings/1785559222590-generic-t-float-literal-cast-floors-to-0-iarithmet.md).

**Fork (A) must use a bare requirement.** A METHOD requirement may have a default body (`tests/language-feature/interfaces/default-method.slang`), but a defaulted `__init` in an `interface` fails core-module compile with `error[E30317]: interface requirement has body`. The bare `__init(float val);` is also the only value-preserving form: each conformer binds its own `__init(float)` (a default body would go through `int(val)`), and builtin `int`/`vector<int,N>`/CoopVec/CoopMat and a user `struct : IArithmetic` with only `__init(int)` auto-satisfy it via witness synthesis (verified). Serialized-module ABI of a new requirement is separate [no default __init bodies](../learnings/1785565100286-slang-interface-init-requirements-cannot-have-defa.md).

## Builtin-operator fast path silently bypasses user overloads (#11493)

PR #11493 (`61ad43dbc`, first in v2026.11) added `SemanticsExprVisitor::convertToBuiltinArithmeticOp` (`slang-check-expr.cpp:4605`), called from `visitInvokeExpr` at :5007, returning before `CheckTerm`/`ResolveInvoke` (:5044). For builtin operators on builtin scalar/vector/matrix operands it builds a `BuiltinOperatorExpr` and skips overload resolution, so a user overload such as a global `operator*(float4x4,float4x4)` is ignored with no diagnostic (discussion #11840, regressed 2026.9→2026.11). The path already defers matrix operators in GLSL operator scope (:4634-4637, :4723-4730); the fix direction is a cheap "non-core user `operator OP` in scope" check that keeps the fast path. Same class as the earlier float-bitwise → E39999 decline [fast path bypasses overloads](../learnings/1782894605011-slang-11493-builtin-operator-fast-path-silently-by.md).

## Overload-failure diagnostics and candidate pruning (#12035, #12284)

The #12035 "explain why each candidate was rejected" ask reuses #7857's machinery. `OverloadCandidate` (`slang-check-impl.h:377-456`) has a coarse `Status` (Unchecked → … → Applicable, plus GenericArgumentInferenceFailed), the first un-coercible arg (`argMismatchArgIndex/ExpectedType/ActualType`, set in `recordArgMismatch` at `slang-check-overload.cpp:877-886` only when bare types differ), `conversionCostSum`, and `genericInferenceFailure`. The no-applicable emitter (:3520-3611) sorts `bestCandidates` by status and prints `argument N does not match: expected 'X', got 'Y'`. Gaps: arity (not stored), inaccessibility (E40014 only in the ambiguous branch, :3692), failed generic constraints and direction mismatches show only the signature. Split: (A) fix-ready, emit the remaining reasons on the #7857 pattern; (B) design-gated proximity ranking, needing candidate retention on the hot path since `bestCandidates` keeps only the tied furthest-progressing set [#7857 machinery](../learnings/1783656901958-slang-12035-overload-failure-diagnostics-7857-alre.md).

The same pruning gates #12284 (warn when an imported module's better overload silently rebinds a call). `AddOverloadCandidateInner` (:2461-2540) `fastRemoveAt`s worse existing candidates and drops a strictly-worse new one; the winner is finalized later at `CompleteOverloadCandidate`. With local `fn(int)` (uint→int cost) vs imported `fn(uint)` (cost 0), the local loser is gone before the decision point, so record contributing modules at the choke-point and suppress `isFromCoreModule()` (else it fires on `lerp`, texture ops, most implicit-conversion stdlib calls). For any "diagnose when X was chosen over Y" feature, first check whether the loser survives to the decision point [pruning discards the loser](../learnings/1785405718177-slang-12284-overload-pruning-discards-beaten-local.md).

## Generic entry-point -specialize and primary-file extensions (#12049)

`slangc file.slang -entry g -specialize float` on `void g<T:IDenorm>(...)` gave E38029 when `float:IDenorm` came from an `extension` in the same command-line file. `EntryPoint::_validateSpecializationArgsImpl` built its context with `m_module = nullptr`, so `getCandidateExtensionsForTypeDecl` enumerated only `m_linkage->loadedModulesList`, while the primary TU lives in the request-local `loadedModules` dict (moving both into an imported module made the error vanish). Adding the primary TU to `loadedModulesList` was rejected (broad blast radius) [#12049 diagnosis](../learnings/1783701731376-slang-12049-generic-entry-point-specialize-can-t-s.md). PR #12052 shipped the scoped approach: the context is `getModule()` + `getModuleDependencies()` [#12049 shipped](../learnings/1784167461042-slang-12049-shipped-approach-a-confirmed-entry-poi.md).

## static_assert(false) in a switch(T.kind) arm fires eagerly (#12185)

In `defaultGetDescriptorFromHandle` (hlsl.meta.slang), a `static_assert(false, ...)` in a `switch(T.kind)` case of a generic `[ForceInline]` function worked at a concrete call site but broke an `export T getDescriptorFromHandle<T:IOpaqueDescriptor>(...)`: an `export` generic is checked with `T` symbolic, so the switch cannot fold and E41400 fires for every kind. The existing `static_assert(false)` at :27778 is safe because it is in `default:` of `switch(bindlessOptions)`, a `constexpr` param. Emit "unsupported kind on this target" at the IR-emit consumer; a plain `if (T.kind == X) return ...; else ...` is safe. Always run the reporter's exact repro (`desc-handle-default.slang`) [static_assert fires eagerly](../learnings/1784691233062-static-assert-false-in-a-switch-t-kind-arm-fires-e.md).

## TryJoinTypes: a new join arm must be gated off the constraint solver

`SemanticsVisitor::TryJoinTypes` (`slang-check-constraint.cpp`) is shared by ordinary-argument common-type inference (`mergeTypeConstraint`, ~:2019) and the witness/subtype/equality solver for optional `where` clauses (~:1772). The enum⊕scalar arm of slang#13160 (fix #13158) decays an enum to its tag type so `cond ? Enum::Case : 0` and `select(...)` infer a scalar instead of falling to the deprecated `vector<T,1>` overload (opaque E30019 plus spurious E30056). It sits behind a defaulted `allowEnumScalarJoin` enabled only at `mergeTypeConstraint`; in the solver it would fabricate `T == int` and break `where optional T == int`. The join only nominates; `_coerce` (`slang-check-conversion.cpp:2201-2220`, `if (tagType == toType)`) stays the sole arbiter, so an inapplicable arm still gets a clean per-arm error — #12753's lesson that "fixing the join" is usually wrong because the join is solver-shared [gate new arms off the solver](../learnings/1789678492053-extending-tryjointypes-with-a-new-join-arm-gate-it.md).

The flag alone does not keep widening out of the solver: `TryJoinVectorAndScalarType` already runs unconditionally, so `struct S : IA<float>, IB<float3>` passed to `pick<T,U>(T) where optional T:IA<U> where optional T:IB<U>` solves `U=float3`, while unrelated `IA<Foo>, IB<Bar>` fails E30442. Verify scope with an `IA<X>, IB<Y>` optional-`where` probe, not by reading the flag's call site [vector/scalar join feeds the solver](../learnings/1789690773518-tryjointypes-vector-scalar-join-already-feeds-opti.md). Review gaps: the flag broadens every generic call (`f<T>(T,T)` with `(enum, scalar)` infers `T=tagType`) — add a user generic-overload regression; the arm's recursion is inert (tag is always a `BasicExpressionType`) — assert it.

**No Ptr⊕NullPtr or Optional⊕None arm: `c ? p : nullptr` and `c ? opt : none` fail (#14059).** `?:`, `select` and any user generic `f<T>(T,T)` infer `T` by joining operand types in `TryJoinTypes` (~:302). When the join returns nullptr, `mergeTypeConstraint` (~:2031) rejects the candidate before the `_coerce` rules that make `float3* p = nullptr` and `Optional<T> o = none` work (`slang-check-conversion.cpp` ~:2115/:2130) ever run → E39999 "no overload for '?:'", or E30442 for a single user-generic candidate. Fix on the #13160 pattern: nominate the Ptr/Optional type in the join, gated to the common-type path, and let `_coerce` decide. Traps: PR #6022's `select(bool, T, __none_t) -> Optional<T>` overloads bind `T=Optional<X>` for an Optional operand (E30019 "got Optional<Optional<X>>"); a mixed-type `?:` overload would also lower badly, since scalar `SelectExpr` lowering is an if/else on the coerced arguments and ignores the callee body. Not a regression (2026.13.1 behaves the same), and independent of the #13632 HLSL/WGSL PtrLit emit bug [nullptr/none join gap](../learnings/1793311739945-c-p-nullptr-c-opt-none-fail-in-tryjointypes-not-in.md).

## Unbounded checker recursion: each level is a NEW type, so identity guards never fire

**Witness-shape inference on an interface subject (#13461, PR #13468).** `tryInferOrdinaryArgsFromWitnessConstraint` (~:1807) calls the symmetric `TryJoinTypes(sub, sup)`, which swaps operands when `sub` is an interface (:404) and so asks whether `sup` conforms to `sub`. With `extension<T> T : IRec<T> where T : IOther<T> {}` and any `struct Z : IOther<Z>`, the join becomes `isSubtype(IOther<IOther<Z>>, IOther<Z>)`, re-applying the extension to ever larger types until SIGSEGV with no diagnostic (regression from #11210, 79ac457f0). Each level is a new `Type*`, so `isComputing`, extension circularity and the subtype cache never fire. A second leg, `cacheSubtypeWitness`, linearizes the sup's inheritance before checking whether the sub is in progress; each leg alone still overflows, so both are cut (check the sub first) [new type per level](../learnings/1791316435617-unbounded-checker-recursion-where-each-level-is-a-.md). The fix that held skips the join only when `isInterfaceType(sub) && !(isEqualityConstraint && !isInterfaceType(sup))`: a directional `_tryJoinTypeWithInterface` turned a rejected program into an E99997 ICE, and a blanket skip broke `f<T = IGet>() where T == G`, whose swapped join IS the solution. Tests reach the path only via array arguments (`IFoo<int> arr[2]` for a `T[2]` param); `f<IFoo<int>>(a)` is a separate E99997 (#13469). An A/B against the last-good release binary (`gh release download`) caught both regressions the suite missed [skip join, exempt concrete equalities](../learnings/1791336953861-slang-witness-shape-inference-on-interface-subject.md).

**The inheritance circularity guard is decl-identity only and resets per nested query (#13470).** `extension<X> Wrap<X> : I where Wrap<Wrap<X>> : I {}` overflows on every release since v2024.14, even unused. `checkAndConstructSubtypeWitness` calls `getInheritanceInfo(subType)` with `circularityInfo = nullptr` (slang-check-conformance.cpp:269); the extension's `InheritanceCircularityInfo` frame is pushed only after `applyExtensionToType` succeeds (slang-check-inheritance.cpp:855 → :866 → :228); and `_checkForCircularityInExtensionTargetType` cannot tell this from well-founded `where X : I` recursion. A per-`GenericInferenceContext` cap fails because each application makes a fresh context (slang-check-decl.cpp:17722); the budget must carry across the candidate search, on the `_checkForCircularityInConstantFolding`/`kMaxTypeNestingDepth` (E39997) pattern — principled only for this non-terminating shape, not for #13461, which terminated before #11210 [circularity guard is decl-identity](../learnings/1791331579789-slang-inheritance-circularity-guard-is-decl-identi.md). Without gdb: run at `ulimit -s` 2/8/64 MB (always crashes, time grows ⇒ unbounded); an LD_PRELOAD SIGSEGV handler (`sigaltstack` + `backtrace()`) plus `addr2line -e libslang-compiler.so.<ver>.dwarf` symbolizes frames; print `type->toString()` at `_getInheritanceInfo` entry; skip the innermost ~400 `collectDependentDeclsInVal` frames; a two-state Release build of suspect vs parent (~10 min) pins the regression.

**A type walker's seen-set needs a depth cap too (#13538).** `struct LoopTail<each T> { float4 x[]; LoopTail<T, int> next; }` builds a new type each step (`LoopTail<int,int>`, `LoopTail<int,int,int>`, ...), so a walk that stops on a repeated `Type*` hangs or segfaults; master's `getTrailingUnsizedArrayElement` already did so for `ConstantBuffer<LoopTail<int>>`. Bound every walker with `for (UInt depth = 0; depth < kMaxTypeNestingDepth; depth++) { ... } return nullptr;` so validation reports fatal E39997, pinned by a `DIAGNOSTIC_TEST:SIMPLE(diag=CHECK,non-exhaustive)` test in its own file [seen-set needs a depth cap](../learnings/1791547431780-slang-a-seen-types-cycle-guard-does-not-terminate-.md). Key the seen-set on the instantiated `Type*` (as `TypeTagContext` does), not the `Decl*`: `Box<Box<float4>>` instantiates one decl twice and is not a cycle. After `IComponentType::specialize`, validate only the composite's entry points (fall back to `module->getEntryPoints()` only when it has none), or `{module, b}` fails on an uncompiled `a`; new front-end errors can also break the nightly agentic suite, so run docs/generated/tests too [key guards on Type*](../learnings/1791528614678-new-front-end-errors-can-break-the-nightly-agentic.md).

## Associated types through constraints: what lookup can and cannot reduce (#13509, #13537)

**No congruence for equality constraints.** With `where C.Primitive == TrianglePrimitive`, a freshly spelled `C.Primitive.Attributes` resolves to `TrianglePrimitive.Attributes` because member lookup sees the equality base added by the generic-parameter scan (slang-check-inheritance.cpp:1334-1433). The same type arriving through substitution (a field of `Input<C>`, a `let`, the return type of `g<C>()`, `Input<C>.A`) stays unreduced: substitution yields `LookupDeclRef(Attributes, witness C.Primitive : IPrimitive)` and `resolve()` is context-free. Its inheritance then has no base, since the lookup-derived scan (:1057-1331) matches only constraint endpoints canonically equal to `selfType` (:1200-1211) and the generic-parameter scan needs an exact subject (:1419). There is no `X == Y ⇒ X.A == Y.A` rule, on every release back to v2025.1. A 36-line congruence base at the end of the lookup-derived block fixes it (full suite green): take the lookup source's equality facets, project `Y.A` via `isSubtype(Y, interface)` + `getLookupDeclRef`, `resolve()` it, add it under the existing depth guard and in-progress skip. Workaround: state `where C.Primitive.Attributes == TriangleAttributes` directly (placing the prefix constraint before it gives E30405). Debug tip: print facets in `getInheritanceInfo(Type*)` (:139), not `_calcInheritanceInfo` [no congruence](../learnings/1791443571566-slang-equality-constraints-lack-congruence-substit.md). The module-scope projection gap of #12822 is on [[wiki/concepts/slang-language-core-f0909b0-interfaces-witness-conformance.md]].

**Member lookup through a generic constraint is weaker still.** `_tryLookUpExistingRequirementWitnessRec` (slang-ast-decl-ref.cpp ~407) resolves `X.Assoc` from a concrete conformance's `InheritanceDecl::witnessTable`, which has associated-type entries; for `where X : I` it reads `GenericTypeConstraintDecl::pathResolutionTable`, which holds only inherited-interface paths (slang-check-decl.cpp ~12350), so `X.Assoc` stays opaque. Nor does the checker search for a more concrete conformance: a core-module `extension<int N> vector<float,N> : I` cannot match `vector<T,1>` while `T` is abstract. `where X.Assoc == Y` is consumed by coercion (slang-check-conversion.cpp), not lookup: `Y v = x; v.m` compiles but `x.m` fails "not a member of 'X.Assoc'", on master too (`where T.A == float2` with `a.x`). Routing a public alias through an associated type (`_Texture<T.DataType, …>`) therefore broke SlangPy's generic code on slang #13537 [assoc types stay symbolic](../learnings/1791916553178-slang-associated-types-through-a-generic-constrain.md). The same alias defeats inference of `f<T>(Texture2D<T>)`; see [[wiki/concepts/slang-language-core-f0909b0-generics-overload-inference.md]].

**A distinct `==` failure: constraint orientation depends on declaration order (#14075).** `checkGenericTypeEqualityConstraintSubType` (`slang-check-decl.cpp` ~:4908-4964, from #8445/#8851) sorts the two sides of an `==` constraint when both are valid subjects, by the member index of each side's owning decl under their lowest common ancestor, then swaps sub and sup. Consumers check one way only: `isSubtype(sub, sup)` in `findWitnessForInterfaceRequirement` (~:10751) and in the generic solver (`slang-check-constraint.cpp` ~:3007). When the stored sub is the concrete side, the check scans only that type's facets and misses the where-clause equality on the abstract side → false E38029 (ToT 1f0b33b86). Tells: swapping the two interface declarations removes the error, and so does `-disable-non-essential-validations`, because the sort runs only behind that gate (~:4850) — that flag changes semantics. The #13509 congruence repros ignore the flag, and the congruence prototype does not fix this. The generic-call sibling `need<A,B>() where A.Context == B` called as `need<S, Concrete>()` regressed between v2025.17.2 and v2025.18, the first release with #8445 [orientation depends on decl order](../learnings/1793320533848-slang-equality-constraint-orientation-depends-on-d.md).

## IR type casts look through `IRAttributedType`; `vector<T,1>` is erased at emit

`as<T>` and `dynamicCast<T>` default to `IRDynamicCastBehavior::Unwrap` (`slang-ir.h:822-836`) and look through `kIROp_AttributedType`, so `as<IRVectorType>(unorm float2)` succeeds with no `unwrapAttributedType` call. Type-pointer equality still needs the unwrap, because `getDataType()` strips only the rate qualifier (a #13342 review, R3, wrongly flagged a "release-assert asymmetry" by missing this). User code reaches a `vector<T,1>` swizzle via `__vectorReshape<1>(uint3(...))`; hlsl, cpp, cuda, metal and spirv all legalize `vector<T,1>` to a scalar and emit `return x_0;`, so only an IR-dump check, not an emitted-code FileCheck, can tell whether the type survived. In a verify worktree, `git submodule update --reference /workspace/agent/slang` fails because that clone is shallow and `file` transport is blocked; use `git -c protocol.file.allow=always submodule update --init --recursive` [as<T> unwraps; vector<T,1> erased](../learnings/1792750703434-slang-ir-as-t-unwraps-irattributedtype-vector-t-1-.md).
