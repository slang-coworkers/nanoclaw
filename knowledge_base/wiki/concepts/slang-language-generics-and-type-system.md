# Slang Generics & Type System

Generic specialization, inference, overload resolution, checker recursion, and two IR type-shape facts. Witness tables, extensions, coercion, visibility and codegen live in [[wiki/concepts/slang-language-witness-and-conformance.md]].

## TL;DR

- Generics are solved from call/index arguments only; a return-position-only param cannot be inferred (E39999). Use a non-generic proxy plus a per-target `__init(proxy)`.
- E39999's tagged-union failure reason backs E30438/E30439/E38029; arity checks count defaulted trailing params.
- The generic-arg comparison fence gates `>`/`>=` but not `<`/`<=`; `hasModifier` on a generic method sees the inner `FuncDecl`; #10686's recursion guard covers only pointers.
- "Unlowered X survives to emit" with a concrete operand is usually the pass's own produce/consume ordering (#11782).
- `Conditional<T,false>` elides storage, not arity: pass any `T` or default it `= 0` (`= {}` fails).
- `(T)0.25` for `T:IArithmetic` floors to 0 (no `__init(float)`); interface `__init` requirements cannot have default bodies (E30317), so add a bare one.
- The #11493 builtin-operator fast path skips overload resolution and ignores user overloads on builtin types.
- `AddOverloadCandidateInner` prunes losers early, so "X chosen over Y" diagnostics capture there; #12035 reuses #7857's machinery.
- Entry-point `-specialize` conformance context = `getModule()` + `getModuleDependencies()` (#12052).
- `static_assert(false)` in a `switch(T.kind)` arm of a generically checked function fires at check time; diagnose at IR emit.
- New `TryJoinTypes` arms stay off the constraint solver (on only at `mergeTypeConstraint`); `_coerce` arbitrates. Missing Ptr⊕NullPtr/Optional⊕None arms break `c ? p : nullptr` (#14059). Pin any new arm with a negative test, proven by widening it in a drill.
- Recursion that builds a new type per level defeats identity guards: skip the converse join for interface subjects (except concrete equalities), budget across extension search, cap walkers at `kMaxTypeNestingDepth`, key seen-sets on `Type*`.
- Field-recursing checker predicates run before E39997 and need their own seen-set; `getFields(..., Instance)` omits base-struct fields.
- `where X == Concrete` reduces a fresh `X.A`, not a substituted one (no congruence). A false E38029 that vanishes when two interface decls swap is the `==` orientation bug (#14075).
- Through `where X : I`, `X.Assoc` stays symbolic; do not route public aliases through associated types.
- IR `as<T>` looks through `IRAttributedType`, pointer equality does not; backends scalarize `vector<T,1>`, so only an IR dump shows it.
## Generic Specialization and Inference

**Return-position-only params are unsolvable.** Generics (including `__subscript`) specialize from index/call arguments, never the assignment target: `__generic<T:IOpaqueDescriptor> __subscript(uint) -> DescriptorHandle<T>` compiles, but `Texture2D t = ResourceDescriptorHeap[i];` fails E39999 "could not specialize generic for arguments of type (uint)". (spike: `__subscript` attributes go on the accessor, E31002; `static const` struct globals need `= {}`, E31225) [return-position](../learnings/1781222181614-slang-generic-subscript-cannot-infer-a-return-posi.md). That killed #11568 Approach A; viable paths (handed to jkwak-work): a non-generic proxy with per-resource `T.__init(proxy)`, or a checker change [Approach A dead](../learnings/1781222607198-correction-resourcedescriptorheap-approach-a-retur.md).

**Failure reasons.** E39999 carries tagged union `GenericArgumentInferenceFailure` (PR #11571) [failure reason](../learnings/1781684668464-slang-e39999-could-not-specialize-generic-has-an-e.md); PR #11656 added E30438, E30439 and E38029, covering 3 of ~9 sites [#11643](../learnings/1781729215980-slang-11643-resolved-focused-generic-specializatio.md). Arity diagnostics range-check against defaulted trailing params [arity](../learnings/1781753229607-slang-generic-arg-arity-diagnostics-must-range-che.md).

**Small facts.** In `GetOpLevel`, `>`/`>=` inside generic args are gated via `genericDepth` but `<`/`<=` are not, and `genericDepth` never resets inside `( )`, so parenthesizing a banned operator fails [half-built fence](../learnings/1780512896132-slang-generic-arg-comparison-fence-is-half-built-p.md). `hasModifier` resolves via `getDecl()` to the inner `FuncDecl`, not the `GenericDecl`; test GPU-only attributes via a CPU generic proxy [hasModifier](../learnings/1780497220869-slang-hasmodifier-on-generic-static-methods-resolv.md). `_findDependenciesOfTypeInSet` has only #10686's pointer guard, no general visited-set, so a self-referencing generic used through an interface still overflows via `IRSpecialize` operands [#10686 partial](../learnings/1780353989621-slang-any-value-inference-recursion-10686-pointer-.md).

**`makeConditionalValue` ICE (#11782).** The repro needs only a plain generic `outer<T>` (un-monomorphized in single-compile AOT) calling an inner `<let flag:bool>` with a literal bool [repro](../learnings/1784793304583-conditional-flag-ice-11782-repros-need-only-a-plai.md). The flag is not symbolic; specialization already made it `Conditional(Int, true)`. In `slang-ir-lower-conditional-type.cpp`, `processModule` shares one LIFO worklist between producer `processConditionalType` (records `loweredConditionalTypes`) and consumers `processMakeConditionalValue`/`processGetConditionalValue`; a consumer visited first hits `if (!info) return;`, is re-typed to `Int`, and reaches `SLANG_UNIMPLEMENTED_X` in SPIR-V emit. PR #13043 resolves the type on demand via an idempotent helper [pass ordering](../learnings/1789302491936-11782-conditional-ice-root-cause-is-an-intra-pass-.md); the repro compiles on v2026.21 [#11782 fixed](../learnings/1794126186966-conditional-t-hasvalue-params-arity-is-not-elided-.md).

**`Conditional<T,false>` removes storage, not arity.** `Conditional<T, bool hasValue>` (`core.meta.slang`) drops the value from emitted code, but the call keeps the parameter: for `f<let c:bool>(Conditional<int,c> v, int x, out int r)`, `f<false>(2, r)` fails E39999 "not enough arguments (got 2, expected 3)". Valid: any `int` (`__init(T)` discards it), a `= 0` default on a trailing parameter (spirv-val clean), or an uninitialized local (warns E41016). `Conditional<int,false>()` and `= {}` fail: the only ctor is `__init(T val)`. The user guide covers it only for struct fields. For another arity, use overloads [arity kept](../learnings/1794126186966-conditional-t-hasvalue-params-arity-is-not-elided-.md) [needs arg](../learnings/1794126489690-slang-conditional-t-false-function-parameter-still.md).

**Literal coercion into a constrained param (#12311).** `(T)0.25` in `T f<T:IArithmetic>()` returns `0.0` for `T=float`: `IArithmetic` declares only `__init(int)`/`__init(This)` (unlike `IFloat`), so `visitTypeCastExpr`→`_coerce`→`lookupConstructorsInType` converts float→int at generic-check time and bakes `0` into the generalized IR; `(T)0.25f`/`T(0.25)` too. Fork: (A) add `__init(float)` to `IArithmetic`, or (B) defer literal conversion for constrained params to specialization (non-breaking, delicate) [floors to 0](../learnings/1785559222590-generic-t-float-literal-cast-floors-to-0-iarithmet.md).

**Fork (A) must use a bare requirement.** A defaulted `__init` in an `interface` fails core-module compile with E30317 "interface requirement has body" (method requirements may have defaults). Bare `__init(float val);` is also the only value-preserving form (a default body would go through `int(val)`); builtin conformers and a user `struct : IArithmetic` with only `__init(int)` satisfy it via witness synthesis (verified) [no default bodies](../learnings/1785565100286-slang-interface-init-requirements-cannot-have-defa.md).

## Builtin-operator fast path silently bypasses user overloads (#11493)

PR #11493 (v2026.11) added `convertToBuiltinArithmeticOp` (`slang-check-expr.cpp`), run from `visitInvokeExpr` before `ResolveInvoke`: builtin operators on builtin scalar/vector/matrix operands become a `BuiltinOperatorExpr` without overload resolution, so a user `operator*(float4x4,float4x4)` is ignored silently (#11840). GLSL-scope matrix operators are already deferred; the fix direction is a cheap "non-core user `operator OP` in scope" check that keeps the fast path [fast path](../learnings/1782894605011-slang-11493-builtin-operator-fast-path-silently-by.md).

## Overload-failure diagnostics and candidate pruning (#12035, #12284)

#12035 ("explain why each candidate was rejected") reuses #7857's machinery. `OverloadCandidate` (`slang-check-impl.h`) holds a coarse `Status`, the first un-coercible arg (`argMismatch*`, set only when bare types differ), `conversionCostSum` and `genericInferenceFailure`, from which `slang-check-overload.cpp` prints `argument N does not match: expected 'X', got 'Y'`. Arity, inaccessibility (E40014 only when ambiguous), failed constraints and direction mismatches show only the signature. Split: (A) fix-ready, emit those on the #7857 pattern; (B) design-gated proximity ranking, needing hot-path candidate retention (`bestCandidates` keeps only the tied furthest set) [#7857](../learnings/1783656901958-slang-12035-overload-failure-diagnostics-7857-alre.md).

The same pruning gates #12284 (warn when an imported better overload rebinds a call). `AddOverloadCandidateInner` `fastRemoveAt`s worse candidates and drops a strictly-worse new one before `CompleteOverloadCandidate`: with local `fn(int)` (uint→int cost) vs imported `fn(uint)` (cost 0), the local loser is gone before the decision point. Record contributing modules there and suppress `isFromCoreModule()` (else it fires on `lerp` and most stdlib calls). For any "X chosen over Y" diagnostic, check first that the loser reaches the decision point [pruning](../learnings/1785405718177-slang-12284-overload-pruning-discards-beaten-local.md).

## Generic entry-point -specialize and primary-file extensions (#12049)

`slangc file.slang -entry g -specialize float` on `void g<T:IDenorm>(...)` gave E38029 when `float:IDenorm` came from an `extension` in the same file: `EntryPoint::_validateSpecializationArgsImpl` used `m_module = nullptr`, so `getCandidateExtensionsForTypeDecl` saw only `m_linkage->loadedModulesList`, not the request-local `loadedModules` holding the primary TU. Adding the TU to `loadedModulesList` was too broad [#12049](../learnings/1783701731376-slang-12049-generic-entry-point-specialize-can-t-s.md); PR #12052 shipped the scoped context `getModule()` + `getModuleDependencies()` [#12052](../learnings/1784167461042-slang-12049-shipped-approach-a-confirmed-entry-poi.md).

## static_assert(false) in a switch(T.kind) arm fires eagerly (#12185)

`static_assert(false, ...)` in a `switch(T.kind)` case of `defaultGetDescriptorFromHandle` (hlsl.meta.slang) worked at concrete call sites but broke `export T getDescriptorFromHandle<T:IOpaqueDescriptor>(...)`: an `export` generic is checked with `T` symbolic, the switch cannot fold, and E41400 fires for every kind. One under `default:` of a switch on a `constexpr` param is safe. Emit "unsupported kind on this target" at the IR-emit consumer (a plain `if (T.kind == X) return ...; else ...` is safe), and run the reporter's exact repro [fires eagerly](../learnings/1784691233062-static-assert-false-in-a-switch-t-kind-arm-fires-e.md).

## TryJoinTypes: a new join arm must be gated off the constraint solver

`TryJoinTypes` (`slang-check-constraint.cpp`) serves both common-type inference (`mergeTypeConstraint`) and the solver for optional `where` clauses. slang#13160's enum⊕scalar arm (fix #13158) decays an enum to its tag type so `cond ? Enum::Case : 0` and `select(...)` infer a scalar instead of the deprecated `vector<T,1>` overload (E30019 plus spurious E30056). It sits behind a defaulted `allowEnumScalarJoin` enabled only at `mergeTypeConstraint`; in the solver it would fabricate `T == int` and break `where optional T == int`. The join only nominates; `_coerce` (`slang-check-conversion.cpp`, `if (tagType == toType)`) stays the sole arbiter, so an inapplicable arm still gets a clean per-arm error. #12753's lesson: "fixing the join" is usually wrong because the join is solver-shared [gate off solver](../learnings/1789678492053-extending-tryjointypes-with-a-new-join-arm-gate-it.md).

The flag alone does not keep widening out of the solver: `TryJoinVectorAndScalarType` runs unconditionally, so `struct S : IA<float>, IB<float3>` passed to `pick<T,U>(T) where optional T:IA<U> where optional T:IB<U>` solves `U=float3` (unrelated `IA<Foo>, IB<Bar>` fails E30442); probe scope that way [vec/scalar join](../learnings/1789690773518-tryjointypes-vector-scalar-join-already-feeds-opti.md). The flag also broadens every generic call (`f<T>(T,T)` with `(enum, scalar)` infers `T=tagType`), so add a user generic-overload regression and assert the arm's inert recursion.

**No Ptr⊕NullPtr or Optional⊕None arm (#14059).** `?:`, `select` and user `f<T>(T,T)` infer `T` by joining operand types; when the join returns nullptr, `mergeTypeConstraint` rejects the candidate before the `_coerce` rules behind `float3* p = nullptr` and `Optional<T> o = none` run → E39999 "no overload for '?:'" (E30442 for one user-generic candidate). Fix on the #13160 pattern: nominate Ptr/Optional on the common-type path only; `_coerce` decides. Traps: PR #6022's `select(bool, T, __none_t) -> Optional<T>` overloads bind `T=Optional<X>` for an Optional operand (E30019); a mixed-type `?:` overload would lower badly (scalar `SelectExpr` is if/else on coerced arguments). Not a regression [nullptr/none](../learnings/1793311739945-c-p-nullptr-c-opt-none-fail-in-tryjointypes-not-in.md).

**A new join arm needs a negative companion test (PR #14219).** PR #14219 added `Ptr ⊕ NullPtr → Ptr` under `allowCommonTypeJoins` with positive-only tests; a drill widening it to `if (as<NullPtrType>(right)) return left;` still passed all nine rows. Only a negative diagnostic test caught it (e.g. `c ? 1 : nullptr`, `c ? s : nullptr` for a struct, `pickFoo<T : IFoo>(c, ip, nullptr)`): widened, the struct case moves from E39999 to E30019 and the int case the reverse. Ship a negative test with any new join or coercion arm (as #13160 did), proven by a widening drill. Once `c ? p : nullptr` passes the front end, HLSL/WGSL hit #13632's E99999 and SPIR-V `groupshared` nulls hit #14207 [negative test](../learnings/1793673507370-positive-only-tests-don-t-pin-a-new-tryjointypes-a.md).

## Unbounded checker recursion: a NEW type per level defeats identity guards

**Witness-shape inference on interface subjects (#13461, PR #13468).** `tryInferOrdinaryArgsFromWitnessConstraint` calls the symmetric `TryJoinTypes(sub, sup)`, which swaps operands when `sub` is an interface. With `extension<T> T : IRec<T> where T : IOther<T> {}` and any `struct Z : IOther<Z>`, the join becomes `isSubtype(IOther<IOther<Z>>, IOther<Z>)`, re-applying the extension to ever larger types until SIGSEGV (regression from #11210). Each level is a new `Type*`, so `isComputing`, circularity checks and the subtype cache never fire; `cacheSubtypeWitness` overflows alone too, so both legs are cut [new type/level](../learnings/1791316435617-unbounded-checker-recursion-where-each-level-is-a-.md). The fix skips the join only when `isInterfaceType(sub) && !(isEqualityConstraint && !isInterfaceType(sup))`: a directional `_tryJoinTypeWithInterface` turned a rejected program into an E99997 ICE, and a blanket skip broke `f<T = IGet>() where T == G`, whose swapped join IS the solution. Tests reach it only via array arguments (`IFoo<int> arr[2]` for `T[2]`); an A/B vs the last-good release caught both regressions [skip join](../learnings/1791336953861-slang-witness-shape-inference-on-interface-subject.md).

**The circularity guard is decl-identity only, reset per nested query (#13470).** `extension<X> Wrap<X> : I where Wrap<Wrap<X>> : I {}` overflows on every release since v2024.14, even unused, because `checkAndConstructSubtypeWitness` calls `getInheritanceInfo(subType)` with `circularityInfo = nullptr`, the extension's `InheritanceCircularityInfo` frame is pushed only after `applyExtensionToType` succeeds, and `_checkForCircularityInExtensionTargetType` cannot tell this from well-founded `where X : I` recursion. A per-`GenericInferenceContext` cap fails (each application makes a fresh context); the budget must span the candidate search, like `kMaxTypeNestingDepth` (E39997) [decl-identity](../learnings/1791331579789-slang-inheritance-circularity-guard-is-decl-identi.md). Without gdb: crashes at `ulimit -s` 2/8/64 MB mean unbounded recursion; an LD_PRELOAD SIGSEGV handler (`sigaltstack` + `backtrace()`) + `addr2line` symbolizes frames.

**A type walker's seen-set needs a depth cap too (#13538).** `struct LoopTail<each T> { float4 x[]; LoopTail<T, int> next; }` builds a new type each step, so a walk stopping on a repeated `Type*` hangs or segfaults (`getTrailingUnsizedArrayElement` on `ConstantBuffer<LoopTail<int>>`). Bound every walker with `for (UInt depth = 0; depth < kMaxTypeNestingDepth; depth++) { ... } return nullptr;` so validation reports fatal E39997, pinned by a `diag=CHECK,non-exhaustive` test in its own file [depth cap](../learnings/1791547431780-slang-a-seen-types-cycle-guard-does-not-terminate-.md). Key the seen-set on the instantiated `Type*`, not the `Decl*` (`Box<Box<float4>>` instantiates one decl twice, no cycle). After `IComponentType::specialize`, validate only the composite's entry points. New front-end errors may break the nightly agentic suite, so run docs/generated/tests too [key on Type*](../learnings/1791528614678-new-front-end-errors-can-break-the-nightly-agentic.md).

**Field predicates need their own cycle guard; `getFields` skips base fields (#14379).** A by-value recursive struct (`struct R { Texture2D t; R r; }`) reaches `checkVarDeclCommon` and the static-const initializer checks *before* fatal E39997, so an unguarded field-recursing predicate segfaults there (exit 139 on PR #14379). Copy the guard in `_typeTransitivelyContainsOpaqueHandleImpl` (`slang-check-decl.cpp`, `HashSet<Decl*> seen`; key generic structs on `Type*`). Separately, `getFields(..., MemberFilterStyle::Instance)` returns only the struct's own fields, not a base struct's (`struct D : B`, deprecated E30816 but compiled), so an "only resources" test accepts `struct B { float k; } struct D : B { Texture2D t; }`, which HLSL emits with a `base_0` member. [recursive/inherited](../learnings/1794036031168-slang-type-predicates-recursive-structs-and-inheri.md).

## Associated types through constraints (#13509, #13537)

**No congruence for equality constraints.** With `where C.Primitive == TrianglePrimitive`, a freshly spelled `C.Primitive.Attributes` resolves to `TrianglePrimitive.Attributes`, because lookup sees the equality base added by the generic-parameter scan (slang-check-inheritance.cpp). The same type arriving through substitution (a field of `Input<C>`, a `let`, a return type) stays unreduced: substitution yields `LookupDeclRef(Attributes, witness C.Primitive : IPrimitive)`, `resolve()` is context-free, and neither inheritance scan matches it. No release since v2025.1 has an `X == Y ⇒ X.A == Y.A` rule. A 36-line congruence base (project `Y.A` from the equality facets via `isSubtype` + `getLookupDeclRef`, then `resolve()`) fixes it, suite green. Workaround: state `where C.Primitive.Attributes == TriangleAttributes` directly (the prefix constraint before it gives E30405) [no congruence](../learnings/1791443571566-slang-equality-constraints-lack-congruence-substit.md). The module-scope projection gap of #12822 is on [[wiki/concepts/slang-language-core-f0909b0-interfaces-witness-conformance.md]].

**Lookup through a generic constraint is weaker still.** `_tryLookUpExistingRequirementWitnessRec` (slang-ast-decl-ref.cpp) resolves `X.Assoc` from a concrete conformance's `InheritanceDecl::witnessTable`, but for `where X : I` reads `GenericTypeConstraintDecl::pathResolutionTable`, which holds only inherited-interface paths, so `X.Assoc` stays opaque. Nor does the checker seek a more concrete conformance: `extension<int N> vector<float,N> : I` cannot match `vector<T,1>` while `T` is abstract. `where X.Assoc == Y` feeds coercion, not lookup: `Y v = x; v.m` compiles but `x.m` fails "not a member of 'X.Assoc'". Routing a public alias through an associated type (`_Texture<T.DataType, …>`) therefore broke SlangPy's generic code on slang #13537 [assoc symbolic](../learnings/1791916553178-slang-associated-types-through-a-generic-constrain.md). The alias also defeats `f<T>(Texture2D<T>)` inference; see [[wiki/concepts/slang-language-core-f0909b0-generics-overload-inference.md]].

**`==` orientation depends on declaration order (#14075).** When both sides of `==` are valid subjects, `checkGenericTypeEqualityConstraintSubType` (`slang-check-decl.cpp`, from #8445/#8851) sorts them by the member index of each side's owning decl under their lowest common ancestor and swaps sub and sup. Consumers check one way (`isSubtype(sub, sup)` in `findWitnessForInterfaceRequirement` and the solver), so when the stored sub is the concrete side, the abstract side's where-clause equality is missed → false E38029. Tells: swapping the two interface declarations removes the error, and so does `-disable-non-essential-validations` (the sort runs only behind that gate, so the flag changes semantics). Congruence does not fix it. The sibling `need<A,B>() where A.Context == B` called as `need<S, Concrete>()` regressed in v2025.18, the first release with #8445 [orientation](../learnings/1793320533848-slang-equality-constraint-orientation-depends-on-d.md).

## IR type casts look through `IRAttributedType`; `vector<T,1>` is erased at emit

`as<T>`/`dynamicCast<T>` default to `IRDynamicCastBehavior::Unwrap` and look through `kIROp_AttributedType`, so `as<IRVectorType>(unorm float2)` succeeds; type-pointer equality still needs `unwrapAttributedType`, since `getDataType()` strips only the rate qualifier (a #13342 review missed this). User code reaches a `vector<T,1>` swizzle via `__vectorReshape<1>(uint3(...))`; hlsl, cpp, cuda, metal and spirv all scalarize it, so only an IR dump shows if it survived. (Verify worktrees: `git -c protocol.file.allow=always submodule update --init --recursive`.) [as<T> unwraps](../learnings/1792750703434-slang-ir-as-t-unwraps-irattributedtype-vector-t-1-.md).
