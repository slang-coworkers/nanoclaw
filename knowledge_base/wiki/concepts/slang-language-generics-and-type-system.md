# Slang Generics & Type System

Generic specialization, inference, overload resolution, checker recursion, and two IR type-shape facts. Witness tables, extensions, coercion, visibility and codegen live in [[wiki/concepts/slang-language-witness-and-conformance.md]].

## TL;DR

- Generic params are solved from call/index arguments only; a return-position-only param cannot be inferred (E39999). Use a non-generic proxy plus a per-target `__init(proxy)` instead.
- E39999 has an extensible tagged-union failure reason; E30438 (arity), E30439 (unsolved param), E38029 (conformance) reuse it. Arity checks range-check against defaulted trailing params.
- The generic-arg comparison fence is half-built: `>`/`>=` are gated via `genericDepth`, `<`/`<=` are not, and `genericDepth` never resets inside `( )`.
- `hasModifier` on a generic/static method resolves via `getDecl()` to the inner `FuncDecl`.
- The any-value-inference recursion guard (#10686) covers only pointers; the `IRSpecialize`-operand path still overflows.
- An "unlowered X survives to emit" ICE with a concrete operand at the pass boundary is usually the pass's own produce/consume ordering (#11782).
- Literal coercion into a constrained generic param resolves against the INTERFACE's ctors before specialization: `(T)0.25` for `T:IArithmetic` floors to 0 (no `__init(float)`).
- Interface `__init` requirements cannot have default bodies (E30317); add a conversion init as a BARE requirement (witness-synthesized, non-breaking).
- The #11493 builtin-operator fast path runs BEFORE overload resolution and silently ignores in-scope user overloads on builtin types.
- Overload diagnostics reuse #7857's machinery; `AddOverloadCandidateInner` prunes losers early, so "X chosen over Y" diagnostics capture there.
- Entry-point `-specialize` conformance context = `getModule()` + `getModuleDependencies()` (#12052).
- `static_assert(false)` in a `switch(T.kind)` arm of generically compiled code fires at generic check; diagnose unsupported kinds at IR emit.
- A new `TryJoinTypes` arm is gated off the constraint solver (on only at `mergeTypeConstraint`); `_coerce` arbitrates. Missing Ptr⊕NullPtr/Optional⊕None arms make `c ? p : nullptr` and `c ? opt : none` fail E39999 (#14059); PR #14219 adds Ptr⊕NullPtr.
- Positive-only tests do not pin a new join or coercion arm. Ship a negative companion diagnostic test and prove it by widening the predicate in a drill worktree.
- Recursion that builds a NEW type per level defeats identity guards: skip the converse join for interface subjects (except concrete equalities), carry a budget across the extension candidate search, cap type walkers at `kMaxTypeNestingDepth`, key seen-sets on instantiated `Type*`.
- A field-recursing checker predicate can run before E39997 (`checkVarDeclCommon`, static-const checks), so it needs its own seen-set; `getFields(..., MemberFilterStyle::Instance)` omits base-struct fields.
- `where X == Concrete` reduces a fresh `X.A` but not a substituted one (no congruence). Workaround: state the nested equality.
- A false E38029 that disappears when two interface declarations swap places, or under `-disable-non-essential-validations`, is the `==` orientation bug (#14075), not missing congruence.
- Through `where X : I`, `X.Assoc` stays symbolic; `where X.Assoc == Y` feeds coercion, not member lookup. Do not route public aliases through associated types.
- IR `as<T>`/`dynamicCast<T>` look through `IRAttributedType` by default; type-pointer equality does not, so unwrap before comparing.
- Every backend lowers `vector<T,1>` to a scalar, so only an IR-dump check can pin whether it survived.

## Generic Specialization and Inference

**Return-position-only params are unsolvable.** The checker specializes a generic (including a `__subscript`) from index or call arguments only, not the assignment target: `__generic<T:IOpaqueDescriptor> __subscript(uint) -> DescriptorHandle<T>` compiles, but `Texture2D t = ResourceDescriptorHeap[i];` fails `E39999 could not specialize generic for arguments of type (uint)`. Spike gotchas: `__subscript` attributes go on the accessor (else E31002); a `static const` struct global needs `= {}` (else E31225) [return-position param unsolvable](../learnings/1781222181614-slang-generic-subscript-cannot-infer-a-return-posi.md). That killed Approach A for #11568; the viable paths, handed to jkwak-work, are a non-generic proxy with a per-resource `T.__init(proxy)` or a checker change [Approach A dead end](../learnings/1781222607198-correction-resourcedescriptorheap-approach-a-retur.md).

**Failure reasons.** E39999 carries a tagged union `GenericArgumentInferenceFailure` (PR #11571) [extensible failure reason](../learnings/1781684668464-slang-e39999-could-not-specialize-generic-has-an-e.md); PR #11656 added E30438 (arity), E30439 (unsolved param) and E38029 (conformance not satisfied), covering 3 of ~9 sites [#11643 resolved](../learnings/1781729215980-slang-11643-resolved-focused-generic-specializatio.md). Arity diagnostics must range-check against defaulted trailing parameters, not the total count [arity range-check](../learnings/1781753229607-slang-generic-arg-arity-diagnostics-must-range-che.md).

**Parser fence.** In `GetOpLevel`, `>` and `>=` inside a generic argument list are gated via `genericDepth`, but `<` and `<=` are not, and `genericDepth` is never reset inside `( )`, so parenthesizing a banned operator does not work today [half-built fence](../learnings/1780512896132-slang-generic-arg-comparison-fence-is-half-built-p.md).

**Attributes on generic methods.** `hasModifier` resolves via `getDecl()` to the inner `FuncDecl`, not the wrapping `GenericDecl`; verify GPU-only attribute cases with a CPU generic proxy [hasModifier via getDecl()](../learnings/1780497220869-slang-hasmodifier-on-generic-static-methods-resolv.md).

**Any-value inference.** `_findDependenciesOfTypeInSet` has only the #10686 pointer-case guard, not a general visited-set, so a self-referencing generic used through an interface still overflows via `IRSpecialize` operands [#10686 guard is partial](../learnings/1780353989621-slang-any-value-inference-recursion-10686-pointer-.md).

**`makeConditionalValue` ICE (#11782).** The repro needs only a plain generic `outer<T>`, never monomorphized in the single-compile AOT path, that calls an inner `<let flag:bool>` with a literal bool [plain generic repro](../learnings/1784793304583-conditional-flag-ice-11782-repros-need-only-a-plai.md). The flag is not symbolic (PR #13043): specialization already made it `Conditional(Int, true)`. In `slang-ir-lower-conditional-type.cpp`, `processModule` uses one LIFO worklist for the producer (`processConditionalType`, which records `loweredConditionalTypes`) and the consumers (`processMakeConditionalValue`/`processGetConditionalValue`); a consumer visited first hits `if (!info) return;`, is re-typed to `Int`, and reaches `SLANG_UNIMPLEMENTED_X` in SPIR-V emit. The fix resolves the type on demand via an idempotent helper and emits a once-per-type `Diagnostics::Unimplemented` [intra-pass ordering](../learnings/1789302491936-11782-conditional-ice-root-cause-is-an-intra-pass-.md).

**Literal coercion into a constrained param (#12311).** `(T)0.25` in `T f<T:IArithmetic>()` returns `0.0` for `T=float`. `IArithmetic` (core.meta.slang) declares only `__init(int)`/`__init(This)`, unlike `IFloat`, so `visitTypeCastExpr`→`_coerce`→`lookupConstructorsInType` converts float→int at generic-check time and the folded `0` is baked into the generalized IR; specialization and emit are victims, and `(T)0.25f` and `T(0.25)` fail alike. Fork: (A) add `__init(float)` to `IArithmetic`, or (B) defer literal conversion for a constrained param to specialization (non-breaking, delicate) [(T)0.25 floors to 0](../learnings/1785559222590-generic-t-float-literal-cast-floors-to-0-iarithmet.md).

**Fork (A) must use a bare requirement.** A METHOD requirement may have a default body, but a defaulted `__init` in an `interface` fails core-module compile with `error[E30317]: interface requirement has body`. The bare `__init(float val);` is also the only value-preserving form: each conformer binds its own `__init(float)` (a default body would go through `int(val)`), and builtin conformers and a user `struct : IArithmetic` with only `__init(int)` auto-satisfy it via witness synthesis (verified). [no default __init bodies](../learnings/1785565100286-slang-interface-init-requirements-cannot-have-defa.md).

## Builtin-operator fast path silently bypasses user overloads (#11493)

PR #11493 (first in v2026.11) added `SemanticsExprVisitor::convertToBuiltinArithmeticOp` (`slang-check-expr.cpp`), called from `visitInvokeExpr` before `CheckTerm`/`ResolveInvoke`. For builtin operators on builtin scalar/vector/matrix operands it builds a `BuiltinOperatorExpr` and skips overload resolution, so a user overload such as a global `operator*(float4x4,float4x4)` is ignored with no diagnostic (#11840, regressed in 2026.11). The path already defers matrix operators in GLSL operator scope; the fix direction is a cheap "non-core user `operator OP` in scope" check that keeps the fast path. [fast path bypasses overloads](../learnings/1782894605011-slang-11493-builtin-operator-fast-path-silently-by.md).

## Overload-failure diagnostics and candidate pruning (#12035, #12284)

The #12035 "explain why each candidate was rejected" ask reuses #7857's machinery. `OverloadCandidate` (`slang-check-impl.h:377-456`) has a coarse `Status`, the first un-coercible arg (`argMismatchArgIndex/ExpectedType/ActualType`, set only when bare types differ), `conversionCostSum`, and `genericInferenceFailure`; the no-applicable emitter (`slang-check-overload.cpp` :3520-3611) prints `argument N does not match: expected 'X', got 'Y'`. Gaps: arity, inaccessibility (E40014 only when ambiguous), failed generic constraints and direction mismatches show only the signature. Split: (A) fix-ready, emit the remaining reasons on the #7857 pattern; (B) design-gated proximity ranking, needing candidate retention on the hot path, since `bestCandidates` keeps only the tied furthest-progressing set [#7857 machinery](../learnings/1783656901958-slang-12035-overload-failure-diagnostics-7857-alre.md).

The same pruning gates #12284 (warn when an imported module's better overload silently rebinds a call). `AddOverloadCandidateInner` (:2461-2540) `fastRemoveAt`s worse candidates and drops a strictly-worse new one before `CompleteOverloadCandidate` finalizes the winner. With local `fn(int)` (uint→int cost) vs imported `fn(uint)` (cost 0), the local loser is gone before the decision point, so record contributing modules at the choke-point and suppress `isFromCoreModule()` (else it fires on `lerp` and most stdlib calls). For any "X chosen over Y" diagnostic, first check whether the loser survives to the decision point [pruning discards the loser](../learnings/1785405718177-slang-12284-overload-pruning-discards-beaten-local.md).

## Generic entry-point -specialize and primary-file extensions (#12049)

`slangc file.slang -entry g -specialize float` on `void g<T:IDenorm>(...)` gave E38029 when `float:IDenorm` came from an `extension` in the same command-line file. `EntryPoint::_validateSpecializationArgsImpl` built its context with `m_module = nullptr`, so `getCandidateExtensionsForTypeDecl` enumerated only `m_linkage->loadedModulesList`, while the primary TU lives in the request-local `loadedModules` dict. Adding the primary TU to `loadedModulesList` was rejected as too broad [#12049 diagnosis](../learnings/1783701731376-slang-12049-generic-entry-point-specialize-can-t-s.md); PR #12052 shipped the scoped context `getModule()` + `getModuleDependencies()` [#12049 shipped](../learnings/1784167461042-slang-12049-shipped-approach-a-confirmed-entry-poi.md).

## static_assert(false) in a switch(T.kind) arm fires eagerly (#12185)

In `defaultGetDescriptorFromHandle` (hlsl.meta.slang), a `static_assert(false, ...)` in a `switch(T.kind)` case of a generic `[ForceInline]` function worked at a concrete call site but broke an `export T getDescriptorFromHandle<T:IOpaqueDescriptor>(...)`: an `export` generic is checked with `T` symbolic, so the switch cannot fold and E41400 fires for every kind. The `static_assert(false)` at :27778 is safe because it sits in `default:` of `switch(bindlessOptions)`, a `constexpr` param. Emit "unsupported kind on this target" at the IR-emit consumer; a plain `if (T.kind == X) return ...; else ...` is safe. Run the reporter's exact repro [static_assert fires eagerly](../learnings/1784691233062-static-assert-false-in-a-switch-t-kind-arm-fires-e.md).

## TryJoinTypes: a new join arm must be gated off the constraint solver

`SemanticsVisitor::TryJoinTypes` (`slang-check-constraint.cpp`) is shared by ordinary-argument common-type inference (`mergeTypeConstraint`) and the witness/subtype/equality solver for optional `where` clauses. The enum⊕scalar arm of slang#13160 (fix #13158) decays an enum to its tag type so `cond ? Enum::Case : 0` and `select(...)` infer a scalar instead of falling to the deprecated `vector<T,1>` overload (E30019 plus spurious E30056). It sits behind a defaulted `allowEnumScalarJoin` enabled only at `mergeTypeConstraint`; in the solver it would fabricate `T == int` and break `where optional T == int`. The join only nominates; `_coerce` (`slang-check-conversion.cpp`, `if (tagType == toType)`) stays the sole arbiter, so an inapplicable arm still gets a clean per-arm error. That is #12753's lesson: "fixing the join" is usually wrong because the join is solver-shared [gate new arms off the solver](../learnings/1789678492053-extending-tryjointypes-with-a-new-join-arm-gate-it.md).

The flag alone does not keep widening out of the solver: `TryJoinVectorAndScalarType` already runs unconditionally, so `struct S : IA<float>, IB<float3>` passed to `pick<T,U>(T) where optional T:IA<U> where optional T:IB<U>` solves `U=float3`, while unrelated `IA<Foo>, IB<Bar>` fails E30442. Verify scope with an `IA<X>, IB<Y>` optional-`where` probe [vector/scalar join feeds the solver](../learnings/1789690773518-tryjointypes-vector-scalar-join-already-feeds-opti.md). Review gaps: the flag broadens every generic call (`f<T>(T,T)` with `(enum, scalar)` infers `T=tagType`), so add a user generic-overload regression, and assert the arm's inert recursion.

**No Ptr⊕NullPtr or Optional⊕None arm: `c ? p : nullptr` and `c ? opt : none` fail (#14059).** `?:`, `select` and any user generic `f<T>(T,T)` infer `T` by joining operand types. When the join returns nullptr, `mergeTypeConstraint` rejects the candidate before the `_coerce` rules that make `float3* p = nullptr` and `Optional<T> o = none` work ever run → E39999 "no overload for '?:'", or E30442 for a single user-generic candidate. Fix on the #13160 pattern: nominate the Ptr/Optional type in the join, gated to the common-type path, and let `_coerce` decide. Traps: PR #6022's `select(bool, T, __none_t) -> Optional<T>` overloads bind `T=Optional<X>` for an Optional operand (E30019), and a mixed-type `?:` overload would lower badly (scalar `SelectExpr` lowering is an if/else on coerced arguments). Not a regression [nullptr/none join gap](../learnings/1793311739945-c-p-nullptr-c-opt-none-fail-in-tryjointypes-not-in.md).

**A new join arm needs a negative companion test (PR #14219).** PR #14219 added the `Ptr ⊕ NullPtr → Ptr` arm under `allowCommonTypeJoins` with three tests that checked only shapes that should compile. As a drill, widening the arm to `if (as<NullPtrType>(right)) return left;` (and the reverse) still passed all nine PR test rows. Only a negative diagnostic test caught it (`c ? 1 : nullptr`, `select(c, 1.0f, nullptr)`, `c ? s : nullptr` for a struct, `c ? ip : fp`, `pickFoo<T : IFoo>(c, ip, nullptr)`): with the widened arm the struct case moves from E39999 to E30019 and the int case the other way. Ship a negative companion test with any new join or coercion arm, as #13160 did with `enum-int-ternary-negative-13158`, and prove it by widening the predicate in a drill worktree. Once the front end accepts `c ? p : nullptr`, HLSL/WGSL fail later with #13632's E99999 and SPIR-V `groupshared` nulls hit #14207 [positive-only tests don't pin a new TryJoinTypes arm](../learnings/1793673507370-positive-only-tests-don-t-pin-a-new-tryjointypes-a.md).

## Unbounded checker recursion: each level is a NEW type, so identity guards never fire

**Witness-shape inference on an interface subject (#13461, PR #13468).** `tryInferOrdinaryArgsFromWitnessConstraint` calls the symmetric `TryJoinTypes(sub, sup)`, which swaps operands when `sub` is an interface. With `extension<T> T : IRec<T> where T : IOther<T> {}` and any `struct Z : IOther<Z>`, the join becomes `isSubtype(IOther<IOther<Z>>, IOther<Z>)`, re-applying the extension to ever larger types until SIGSEGV with no diagnostic (regression from #11210). Each level is a new `Type*`, so `isComputing`, extension circularity and the subtype cache never fire; a second leg, `cacheSubtypeWitness`, also overflows alone, so both are cut [new type per level](../learnings/1791316435617-unbounded-checker-recursion-where-each-level-is-a-.md). The fix that held skips the join only when `isInterfaceType(sub) && !(isEqualityConstraint && !isInterfaceType(sup))`: a directional `_tryJoinTypeWithInterface` turned a rejected program into an E99997 ICE, and a blanket skip broke `f<T = IGet>() where T == G`, whose swapped join IS the solution. Tests reach it only via array arguments (`IFoo<int> arr[2]` for `T[2]`); an A/B against the last-good release binary (`gh release download`) caught both regressions the suite missed [skip join, exempt concrete equalities](../learnings/1791336953861-slang-witness-shape-inference-on-interface-subject.md).

**The inheritance circularity guard is decl-identity only and resets per nested query (#13470).** `extension<X> Wrap<X> : I where Wrap<Wrap<X>> : I {}` overflows on every release since v2024.14, even unused. `checkAndConstructSubtypeWitness` calls `getInheritanceInfo(subType)` with `circularityInfo = nullptr`; the extension's `InheritanceCircularityInfo` frame is pushed only after `applyExtensionToType` succeeds; and `_checkForCircularityInExtensionTargetType` cannot tell this from well-founded `where X : I` recursion. A per-`GenericInferenceContext` cap fails because each application makes a fresh context, so the budget must carry across the candidate search, on the `kMaxTypeNestingDepth` (E39997) pattern [circularity guard is decl-identity](../learnings/1791331579789-slang-inheritance-circularity-guard-is-decl-identi.md). Without gdb: crashes at `ulimit -s` 2/8/64 MB with growing time mean unbounded recursion; an LD_PRELOAD SIGSEGV handler (`sigaltstack` + `backtrace()`) plus `addr2line` on the `.dwarf` symbolizes frames; a two-state Release build of suspect vs parent pins the regression.

**A type walker's seen-set needs a depth cap too (#13538).** `struct LoopTail<each T> { float4 x[]; LoopTail<T, int> next; }` builds a new type each step, so a walk that stops on a repeated `Type*` hangs or segfaults, as master's `getTrailingUnsizedArrayElement` did for `ConstantBuffer<LoopTail<int>>`. Bound every walker with `for (UInt depth = 0; depth < kMaxTypeNestingDepth; depth++) { ... } return nullptr;` so validation reports fatal E39997, pinned by a `diag=CHECK,non-exhaustive` test in its own file [seen-set needs a depth cap](../learnings/1791547431780-slang-a-seen-types-cycle-guard-does-not-terminate-.md). Key the seen-set on the instantiated `Type*`, not the `Decl*`: `Box<Box<float4>>` instantiates one decl twice and is not a cycle. After `IComponentType::specialize`, validate only the composite's entry points. New front-end errors can also break the nightly agentic suite, so run docs/generated/tests too [key guards on Type*](../learnings/1791528614678-new-front-end-errors-can-break-the-nightly-agentic.md).

**A recursive field predicate needs its own cycle guard, and `getFields` skips base-struct fields (#14379).** A by-value recursive struct (`struct R { Texture2D t; R r; }`) reaches `checkVarDeclCommon` and the static-const initializer checks *before* the fatal E39997 "maximum type nesting level exceeded", so a field-recursing "is this struct made only of X" predicate in `slang-check-*.cpp` without a guard segfaults there (exit 139 on PR #14379): E39997 protects only the walkers that run after it. `_typeTransitivelyContainsOpaqueHandleImpl` in `slang-check-decl.cpp` shows the guard pattern (`HashSet<Decl*> seen`); for generic structs, key it on the instantiated `Type*` as above. Separately, `getFields(astBuilder, structDeclRef, MemberFilterStyle::Instance)` returns only the fields the struct itself declares, not those of a struct base (`struct D : B`, deprecated with warning E30816 but still compiled), so an "only resources" test accepts `struct B { float k; } struct D : B { Texture2D t; }`, which HLSL emits with a `base_0` member. A probe loop over targets that prints exit codes and E-codes, run against the old build too, shows both problems in about a minute [Slang type predicates: recursive structs and inherited fields](../learnings/1794036031168-slang-type-predicates-recursive-structs-and-inheri.md).

## Associated types through constraints: what lookup can and cannot reduce (#13509, #13537)

**No congruence for equality constraints.** With `where C.Primitive == TrianglePrimitive`, a freshly spelled `C.Primitive.Attributes` resolves to `TrianglePrimitive.Attributes`, because member lookup sees the equality base added by the generic-parameter scan (slang-check-inheritance.cpp). The same type arriving through substitution (a field of `Input<C>`, a `let`, the return type of `g<C>()`) stays unreduced: substitution yields `LookupDeclRef(Attributes, witness C.Primitive : IPrimitive)`, `resolve()` is context-free, and neither inheritance scan matches it. There is no `X == Y ⇒ X.A == Y.A` rule, on every release back to v2025.1. A 36-line congruence base at the end of the lookup-derived block fixes it (full suite green): project `Y.A` from the lookup source's equality facets via `isSubtype(Y, interface)` + `getLookupDeclRef` and `resolve()` it. Workaround: state `where C.Primitive.Attributes == TriangleAttributes` directly (the prefix constraint before it gives E30405) [no congruence](../learnings/1791443571566-slang-equality-constraints-lack-congruence-substit.md). The module-scope projection gap of #12822 is on [[wiki/concepts/slang-language-core-f0909b0-interfaces-witness-conformance.md]].

**Member lookup through a generic constraint is weaker still.** `_tryLookUpExistingRequirementWitnessRec` (slang-ast-decl-ref.cpp) resolves `X.Assoc` from a concrete conformance's `InheritanceDecl::witnessTable`, which has associated-type entries; for `where X : I` it reads `GenericTypeConstraintDecl::pathResolutionTable`, which holds only inherited-interface paths, so `X.Assoc` stays opaque. Nor does the checker search for a more concrete conformance: `extension<int N> vector<float,N> : I` cannot match `vector<T,1>` while `T` is abstract. `where X.Assoc == Y` is consumed by coercion, not lookup: `Y v = x; v.m` compiles but `x.m` fails "not a member of 'X.Assoc'", on master too. Routing a public alias through an associated type (`_Texture<T.DataType, …>`) therefore broke SlangPy's generic code on slang #13537 [assoc types stay symbolic](../learnings/1791916553178-slang-associated-types-through-a-generic-constrain.md). The same alias defeats inference of `f<T>(Texture2D<T>)`; see [[wiki/concepts/slang-language-core-f0909b0-generics-overload-inference.md]].

**A distinct `==` failure: constraint orientation depends on declaration order (#14075).** `checkGenericTypeEqualityConstraintSubType` (`slang-check-decl.cpp` ~:4908-4964, from #8445/#8851) sorts the two sides of an `==` constraint, when both are valid subjects, by the member index of each side's owning decl under their lowest common ancestor, then swaps sub and sup. Consumers check one way only (`isSubtype(sub, sup)` in `findWitnessForInterfaceRequirement` and in the generic solver), so when the stored sub is the concrete side, the check scans only its facets and misses the abstract side's where-clause equality → false E38029. Tells: swapping the two interface declarations removes the error, and so does `-disable-non-essential-validations`, because the sort runs only behind that gate (so that flag changes semantics). The congruence prototype does not fix this. The sibling `need<A,B>() where A.Context == B` called as `need<S, Concrete>()` regressed in v2025.18, the first release with #8445 [orientation depends on decl order](../learnings/1793320533848-slang-equality-constraint-orientation-depends-on-d.md).

## IR type casts look through `IRAttributedType`; `vector<T,1>` is erased at emit

`as<T>` and `dynamicCast<T>` default to `IRDynamicCastBehavior::Unwrap` (`slang-ir.h`) and look through `kIROp_AttributedType`, so `as<IRVectorType>(unorm float2)` succeeds without `unwrapAttributedType`. Type-pointer equality still needs the unwrap, because `getDataType()` strips only the rate qualifier (a #13342 review missed this). User code reaches a `vector<T,1>` swizzle via `__vectorReshape<1>(uint3(...))`; hlsl, cpp, cuda, metal and spirv all legalize it to a scalar and emit `return x_0;`, so only an IR-dump check can tell whether the type survived. In a verify worktree use `git -c protocol.file.allow=always submodule update --init --recursive` (`--reference` to the shallow clone fails) [as<T> unwraps; vector<T,1> erased](../learnings/1792750703434-slang-ir-as-t-unwraps-irattributedtype-vector-t-1-.md).
