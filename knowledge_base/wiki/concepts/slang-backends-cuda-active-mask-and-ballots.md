# Slang CUDA: active-mask synthesis and its exit ballots

CUDA has no implicit "active lanes" for wave operations, so `slang-ir-synthesize-active-mask.cpp` threads an explicit mask through the control flow of every function that uses a wave op, computing it with `__ballot_sync`. This page records how those ballots group into collectives, the deadlock that a missing group member causes, how to prune dead ballots without breaking the group, what an unused ballot costs after nvcc, and how to review and test a change to the pass. The rest of the CUDA emitter is on [[wiki/concepts/slang-backends-cuda-cpp.md]].

## TL;DR

- **Exit ballots of one structured region form ONE collective.** The pass emits `ballot(entryMask, true)` on each normal exit and `ballot(entryMask, false)` on each abnormal exit (`break`, `return`) of a region; together they are one `__ballot_sync` spread over several call sites, and every lane in `entryMask` must reach one of them.
- **An arm that skips its exit ballot deadlocks when a barrier follows.** Lanes that did ballot wait in `vote.sync`; lanes that skipped it wait in `bar.sync`. Without a later barrier the skipping lanes simply exit and the kernel finishes, which is why barrier-free tests miss the bug.
- **Never mark `waveMaskBallot` side-effect-free or delete an "unused" ballot on its own.** Prune per region group: keep the whole group if any member's result is live. Liveness roots are uses outside the pass's own mask insts and outside mask-parameter phi args.
- **A pass that rebuilds a terminator must call `transferDecorationsTo` and copy `sourceLoc`.** The active-mask pass rebuilt branches without them, so a `[unroll]` loop containing a wave op lost `#pragma unroll` on CUDA.
- **nvcc does not delete unused `__ballot_sync`.** Each one survives in SASS as `REDUX.OR` + `R2UR` + a convergence branch (plus a `WARPSYNC`/`VOTE` slow path). Count `REDUX.OR`, not `VOTE`. Ballots inside a loop also block unrolling and load batching; in #14016 they made a kernel about 10x slower.
- **A deadlock regression test must keep a LIVE ballot group plus a wave-op-free abnormal exit** (a `break` out of the loop, a `return` from a helper). Once pruning exists, a test whose group is entirely dead no longer guards the marking fix. Revert-drill each test against the final state, not only master.
- **Assert-on-skip walks must exempt unreachable blocks** (`m_dominatorTree->isUnreachable(block)`), for example the 0-predecessor continue block of a loop that never continues.
- **Corpus check for any pass that adds or removes warp collectives:** compile every wave-op test with base and head slangc `-target cuda`, count `__ballot_sync|__match_any_sync` per file, compare exit codes, and read the files whose count goes up.
- **Hang or slow?** Under container load a single CUDA COMPARE_COMPUTE test can take over 100 s to pass. Allow at least 200 s per file before calling a deadlock, and check every CUDA call for a transient `cudaMalloc` out-of-memory on the shared L40S, which can make a later launch fail and a sync look hung.
- **`CUDA-LABEL: __global__ void computeMain(` skips helper functions emitted before the kernel**, such as `static __device__ ... WaveActiveBallot_0(...)`, so ballots inside them do not count toward the kernel's. Compile the test and grep the emitted `.cu`, whole-file and from `__global__` onward, before disputing a FileCheck count.
- **Before reporting an ICE on internal syntax, check master's output for the same shape.** A divergent arm that ends in an `__intrinsic_asm` statement ICEs after #14025, but master already miscompiled it silently.
- **Hardware reconverges at the merge.** Intrinsics that read `__activemask()` directly (matrix `WaveReadLaneAt`, `WaveGetConvergedMask`) gave results identical to Vulkan on the L40S after pruning removed ballots.
- **Benchmark with `cudaEvent` timing plus static SASS.** `ncu` performance counters are blocked in coworker containers (`ERR_NVGPUCTRPERM`), and the GPU is shared, so medians move 10-20%; report the minimum as well as the median.

## How the pass builds ballot groups

On CUDA, each structured region (an `if`, a loop, a `switch`) that contains a mask use gets its own entry mask. When control leaves the region, the pass emits `ballot(entryMask, true)` on a normal exit (`slang-ir-synthesize-active-mask.cpp:1796` at 01dcd3568) and `ballot(entryMask, false)` on an abnormal exit (`:1833`). The lanes that reach the normal-exit ballot form the mask for the code after the region. Because every lane of `entryMask` reaches exactly one of these call sites, they behave as a single `__ballot_sync` collective, even though they are separate instructions in the IR [Slang CUDA synthesizeActiveMask: exit ballots are one collective per region; unpaired ones deadlock with a barrier](../learnings/1793280013857-slang-cuda-synthesizeactivemask-exit-ballots-are-o.md), [CUDA active-mask pass: rebuilt branches dropped [unroll]; prune ballots by region group; drill tests against the final state](../learnings/1793290583175-cuda-active-mask-pass-rebuilt-branches-dropped-unr.md).

## The deadlock: an arm that skips its exit ballot

`transformChildRegion` returns early (`:2032`) for an arm that cannot reach a mask use, and that arm then never emits its exit ballot, so the group is incomplete. Consider this example from #14016:

```hlsl
if (tid.x < 5) acc = WaveActiveSum(v); else acc = 1;
GroupMemoryBarrierWithGroupSync();
```

It hangs on the GPU: lanes 0-4 wait in `vote.sync` for lanes that will never ballot, while lanes 5-31 wait in `bar.sync`. Remove the barrier and the lanes in the `else` arm exit, and the kernel finishes. That is why the existing tests, which have no barrier after the divergent region, never caught it [Slang CUDA synthesizeActiveMask: exit ballots are one collective per region; unpaired ones deadlock with a barrier](../learnings/1793280013857-slang-cuda-synthesizeactivemask-exit-ballots-are-o.md).

The reviewer's corpus check on PR #14025 found the same gap on `break` arms: all six test files whose ballot count went up gained master's missing exit ballots there, for example `tests/hlsl-intrinsic/wave-read-lane-at.slang`. Each is a latent deadlock that no test catches until a barrier follows the loop [CUDA active-mask review: corpus ballot diff, hang timeouts under load, and __intrinsic_asm arms](../learnings/1793295534316-cuda-active-mask-review-corpus-ballot-diff-hang-ti.md).

## Pruning dead ballots: by group, never singly

Because a ballot group is one collective, a single member cannot be deleted just because its result is unused; the other lanes still wait on it. Marking `waveMaskBallot` side-effect-free, which lets DCE remove members one at a time, is therefore unsound. PR #14025 prunes by group instead: it keeps the whole group if any member's result is live, and it counts as live only uses outside the pass's own mask instructions and outside the mask-parameter phi arguments. A group may be deleted only as a whole, and only once it is complete [CUDA active-mask pass: rebuilt branches dropped [unroll]; prune ballots by region group; drill tests against the final state](../learnings/1793290583175-cuda-active-mask-pass-rebuilt-branches-dropped-unr.md), [Slang CUDA synthesizeActiveMask: exit ballots are one collective per region; unpaired ones deadlock with a barrier](../learnings/1793280013857-slang-cuda-synthesizeactivemask-exit-ballots-are-o.md).

The same PR found that `transformUnconditionalEdge` rebuilt a branch (`emitIntrinsicInst` + `removeAndDeallocate`) to append the mask phi argument and dropped the old branch's decorations, so a `[unroll]` loop containing a wave op lost `#pragma unroll` on CUDA. A pass that rebuilds a terminator must `transferDecorationsTo` the new one and copy its `sourceLoc`, as `slang-ir-ssa.cpp` does. A new assert, "the walk never skips a block inside a structured region", fired in `tests/neural` on unreachable blocks such as the continue block of a loop that never continues (0 predecessors), so it exempts `m_dominatorTree->isUnreachable(block)` [CUDA active-mask pass: rebuilt branches dropped [unroll]; prune ballots by region group; drill tests against the final state](../learnings/1793290583175-cuda-active-mask-pass-rebuilt-branches-dropped-unr.md).

## What unused ballots cost after nvcc

nvcc 12.6 on sm_89 keeps every `__ballot_sync`, used or not. Each one appears in SASS as `REDUX.OR` + `R2UR` + a `BRA.CONV`/`BRA.DIV` convergence check, plus a `CALL` to a `WARPSYNC` + `VOTE` slow path, so `grep -c VOTE` undercounts them; count `REDUX.OR`. A ballot inside a loop also stops nvcc from unrolling the loop and batching its loads. In #14016 the synthesized ballots made the kernel about 10x slower: 7.4 ms against 0.73-0.78 ms with one block, and 11 ms against 1.05-1.14 ms with 512 blocks [Benchmarking Slang-generated CUDA kernels with a native nvcc harness (L40S)](../learnings/1793278728292-benchmarking-slang-generated-cuda-kernels-with-a-n.md). With group pruning, the repro went from 16 to 5 ballots and from 7.3-7.8 ms to 0.74 ms on the L40S (1 block x 256 threads, n = 1<<20) [CUDA active-mask pass: rebuilt branches dropped [unroll]; prune ballots by region group; drill tests against the final state](../learnings/1793290583175-cuda-active-mask-pass-rebuilt-branches-dropped-unr.md).

Removing ballots did not change results that depend on reconvergence. CUDA intrinsics that read `__activemask()` directly, such as matrix `WaveReadLaneAt` and `WaveGetConvergedMask`, still matched Vulkan on the L40S after pruning took one test from 13 to 5 ballots, because the hardware reconverges at the merge without them [CUDA active-mask review: corpus ballot diff, hang timeouts under load, and __intrinsic_asm arms](../learnings/1793295534316-cuda-active-mask-review-corpus-ballot-diff-hang-ti.md).

## Reviewing and testing an active-mask change

**Regression tests must survive the pruning.** Once pruning exists, a deadlock test whose region group is entirely dead (an if/else with nothing after it that needs the mask) no longer guards the marking fix, because pruning removes the whole group and hides the bug. Only shapes with a LIVE group plus a wave-op-free abnormal exit, such as a `break` out of a loop or a `return` from a helper, still deadlock without the fix. Revert-drill each test against the final state of the PR, not only against master [CUDA active-mask pass: rebuilt branches dropped [unroll]; prune ballots by region group; drill tests against the final state](../learnings/1793290583175-cuda-active-mask-pass-rebuilt-branches-dropped-unr.md).

**Corpus ballot diff.** Compile every test that uses wave ops and has a `computeMain` with `-target cuda`, once with the base slangc and once with the head slangc; for each file, count `__ballot_sync|__match_any_sync` and compare exit codes. Files whose count goes up are where to look first. The scan takes about a minute at `-P 24` [CUDA active-mask review: corpus ballot diff, hang timeouts under load, and __intrinsic_asm arms](../learnings/1793295534316-cuda-active-mask-review-corpus-ballot-diff-hang-ti.md).

**Telling a hang from slowness.** With a container load average of 170-220, one CUDA COMPARE_COMPUTE test took 103 s to pass, so a 100 s cap would have reported a hang. Use at least 200 s per file before calling a CUDA test a deadlock. slang-test output piped into `grep` is block-buffered, so a timeout kill can also drop the lines of tests that already passed [CUDA active-mask review: corpus ballot diff, hang timeouts under load, and __intrinsic_asm arms](../learnings/1793295534316-cuda-active-mask-review-corpus-ballot-diff-hang-ti.md). In a hand-written harness, a transient `cudaMalloc` out-of-memory on the shared L40S makes a later launch fail with "invalid argument" and can make a sync appear to hang; check every CUDA call and retry before concluding that a kernel deadlocks [Slang CUDA synthesizeActiveMask: exit ballots are one collective per region; unpaired ones deadlock with a barrier](../learnings/1793280013857-slang-cuda-synthesizeactivemask-exit-ballots-are-o.md).

**FileCheck counts and `CUDA-LABEL`.** When a CUDA FileCheck counts `__ballot_sync(` after `CUDA-LABEL: __global__ void computeMain(`, the label skips every device function emitted before the kernel. A user's `WaveActiveBallot(...)` is emitted in its own `static __device__ ... WaveActiveBallot_0(...)` helper ahead of `__global__`, so its ballot is not one of the kernel's. On #14050 a reviewer who did not compile the test claimed that a SpMV test's "1 + 4 ballots" header left out the user's ballot; the emitted code showed the header was exactly right. Compile the test and grep the emitted `.cu`, both whole-file and from `__global__` onward, before passing on such a claim. The CUDA emitter may also reuse a dead local's name for a mask phi (`j_0 = _S7` was the loop mask in that test); that is cosmetic [FileCheck CUDA-LABEL on __global__ excludes ballots in stdlib helper functions](../learnings/1793305986589-filecheck-cuda-label-on-global-excludes-ballots-in.md).

**`__intrinsic_asm` statement arms are not a regression.** A divergent arm that ends in an `__intrinsic_asm` statement (a GenericAsm terminator inside `__target_switch`) is reached by the walk after #14025 and hits `SLANG_UNEXPECTED("unhandled terminator op")`. Master already miscompiles that shape: the whole helper becomes the asm and the other arm is dropped. The ICE replaces a silent miscompile and breaks no working code, so check master's emitted code for a shape before reporting an ICE on internal syntax [CUDA active-mask review: corpus ballot diff, hang timeouts under load, and __intrinsic_asm arms](../learnings/1793295534316-cuda-active-mask-review-corpus-ballot-diff-hang-ti.md).

## Benchmarking a Slang CUDA kernel on the shared L40S

A native nvcc harness runs `slangc -target cuda` output directly; the `extern "C" __constant__ SLANG_globalParams` fix it needs is on [[wiki/concepts/slangc-target-output-and-obfuscation.md]]. To compare several variants in one binary, include each `.cu` in a wrapper translation unit that `#define`s `computeMain`, `SLANG_globalParams` and the groupshared variables (`partial_0`) to per-variant names. `ncu` is installed, but performance counters are blocked in coworker containers (`ERR_NVGPUCTRPERM`), so time with `cudaEvent` and read static SASS (`cuobjdump -sass`) instead. The GPU is shared with other tenants: `cudaMalloc` can transiently fail and medians move by about 10-20%, so report the minimum as well as the median [Benchmarking Slang-generated CUDA kernels with a native nvcc harness (L40S)](../learnings/1793278728292-benchmarking-slang-generated-cuda-kernels-with-a-n.md).
