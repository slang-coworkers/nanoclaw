## TL;DR
- **A read of a live artifact is a MEASUREMENT WITH A TIMESTAMP, not a fact.** PR state, CI conclusion, draft/ready, review state, infra capability — all mutate. Re-probe before citing; a saved memo is a claim about a past instant.
- **A dispatch, a webhook, a nudge, and a timeout are all claims ABOUT state, never state.** Resolve live before acting on any of them. A timeout in particular describes a past instant and is not a decision.
- **Correcting the EXTENT of a claim about a mutable condition, while still stating it as a standing property, leaves the claim wrong.** Fix the tense too.
- **A matching sha does not establish a current reading.** Same-head is necessary, not sufficient — a check can have been re-run, evicted, or superseded since.
- **Verify the CI *conclusion*, not just draft+HEAD, before calling a chain terminal** — and check whether the "last activity" you are clocking is actually a terminal close.
- **A commit date is not a version, and not an edit time.** Read submodule pins by version, not by date; use `merged_at`, never a merge commit's `committer.date`, for when a PR landed.
- **Bot-filed and stale issues rot silently.** Re-verify every `file:line` against current main before relaying; a static-analysis pointer goes stale when the branch is gone, not just when the file changes.
- **A grep hit is a line, not a scope, and `grep -c` counts lines, not events.** A member cite names file, line **and** owner; a published count names the invocation that produced it — or is deleted.
- **A PR's changed-file list does not prove "not a regression."** Verify control-flow invariants against SOURCE, not against a triage memo or a reviewer's assertion.
- **Check ownership before driving anything.** Read issue comments and `head.repo.full_name`: a contributor-owned fork PR is not yours to park, close, or push. Stand down when a maintainer or contributor is driving.
- **Verify @-mention identity against the actual PR/commit author before posting** — a wrong mention is a public, unrecoverable error.
- **A corrupted tool-result turn taints its own verifications**; redo them in a clean turn rather than reasoning off the residue.
- **Post-compaction drift is real**: re-read state before autonomous action in a compacted session, because your premise may have been summarized away.
- **Recurring trackers must carry DISPOSITION, not just items**, and a daily report must carry open ship-stoppers — an item list with no disposition reads as handled.
- **Recurrence only advances on completion**, so a host event can orphan an overdue occurrence and freeze a whole daily series until a human notices. Watchdog the scheduler.
- **A verdict you already published is a past position, not a reason to skip re-checking.** A substantive new human comment re-opens a chain you closed.
- **Control the instrument, not the reasoning.** Re-reading an argument has no access to a measurement defect. `grep -n` for anything you intend to cite, never a range-printer; verify an instrument can return a non-zero answer at all before believing a zero.

## Controls, discrimination, and proxy verification — part 1 — part 2/3**Executed ≠ observed.** A code path can run in an environment where its effect is invisible: a guard's false arm *did* execute locally (`SGL_HAS_NVAPI: OFF` ⇒ predicate always false) but against a Slang pin where the diagnostic under test was unreachable, so it ran without being able to discriminate patched from unpatched. That learning also fixes **which arm owes verification**: when a fix narrows an unconditional action behind a predicate, the true arm restores the pre-patch path verbatim and is *inert by construction*, so "the `P == true` path is unverified" points at the arm needing no verification and stays silent on the real question — did anything on the newly-skipped path depend on the side effect that no longer happens? Over-correcting into "the inert arm is unverifiable, weight it accordingly" is its own inaccuracy; and "can't test configuration X" is usually too coarse — a diagnostic raised in `TargetRequest::checkCapabilities()` keyed on the *target* is testable with no D3D12 device at all, so split what needs the hardware from what only looked like it did ([which arm of a compatibility guard carries the risk](../learnings/1785750665244-which-arm-of-a-compatibility-guard-carries-the-ris.md)). Relatedly, **a pin-independent fix's risk baseline is the pinned dependency, not the unreleased upstream change that motivated it** — the pin-independence that makes it safe to land early is exactly what makes the post-merge world the wrong comparison; fetch the dependency at the pinned ref (`gh api repos/<o>/<r>/contents/<path>?ref=<tag>`) and ask which configurations behave differently *under the pin*, and note that a green CI matrix lacking the exposed configuration cannot see the flip. Its corollary on two-clause predicates inverts a grep: `hasOption(Profile)` was unconditionally true because the *upstream* session code calls `setProfile()`, so grepping the downstream repo for the option name "confirms" no profile is requested — exactly backwards ([a pin-independent fix's risk baseline is the pinned dependency](../learnings/1785751904901-a-pin-independent-fix-s-risk-baseline-is-the-pinne.md)). **Never ship a hedge for an environment failure you did not personally hit**: a dispatch handed down a specific `E00100` link failure to state publicly, but that belonged to the upstream tier's container — relaying it would have laundered another agent's failure under our bot identity and destroyed the best evidence in the review, *because if you believe you can't compile, you don't try*. With a working compiler the code comment's own premise ("valid programs cannot have by-value struct cycles") was testable and didn't carry: a 143-level acyclic chain compiles clean via `groupshared` and trips `E39997` only behind a `RWStructuredBuffer`. Watch for **DCE faking a pass** — a 200-deep type "compiled" only because the value was never stored, output byte-identical to an empty shader; compare artifact sizes against a trivial baseline before believing a negative ([never ship a hedge for an environment failure you didn't personally hit — prove the premise, hedge the inference](../learnings/1785748057767-never-ship-a-hedge-for-an-environment-failure-you-.md)). Two Slang-specific proxies worth naming: in slang-rhi's Vulkan backend, `areDefined()` deliberately excludes `VK_API_DEVICE_OPT_PROCS` and `addFeatureExtension` does not clear the feature bool it rejects, so a gate written `if (!api.m_extendedFeatures.X.y) bypass;` **tests a stale feature bit and never the proc pointer** and can jump through null with no C++/Python exception — gate on the proc pointer ([optional Vulkan proc pointers are loaded unchecked and feature bits survive a rejected extension](../learnings/1785774873723-slang-rhi-vulkan-optional-proc-pointers-are-loaded.md)). But that clean mechanism was then *refuted by call ordering*: the enclosing function called the proc **twice** and the reported fault was the second call — a null function pointer faults at the **first** call site, so reaching the second proves it was non-null, no matter how well the rest fits. Same logic for a suspect `this`/context pointer successfully dereferenced earlier in the frame; and don't invoke "optimized builds are imprecise" as a blanket licence to move a fault 8 lines to where your hypothesis needs it — weigh how big a misattribution you are asking for ([a null function pointer faults at the FIRST call site](../learnings/1785775592426-a-null-function-pointer-faults-at-the-first-call-s.md)). Finally, **breadth-of-mechanism is the author's job and no gate will do it**: rejecting a whole approach after one failed spelling (`set(... CACHE STRING "" FORCE)`) led to building the more complex detection-based fix, which every codex gate passed — because gates validate *the shape you chose*, not whether a simpler mechanism existed (`*_FLAGS_DEBUG_INIT` seeding before `enable_language()`, which the maintainer used in the superseding PR). Its second-order half is the same error with the sign flipped: endorsing that superseding fix by **repeating its PR body** rather than running it — env `CXXFLAGS='-O0 -g3'` still yields `-Og` winning, so the described env-var case is not fixed. A PR body is a claim, not evidence ([review gates validate the shape you chose, not whether a better mechanism exists](../learnings/1785769682134-review-gates-validate-the-shape-you-chose-not-whet.md)).


**Control the instrument, not the reasoning — ten measurement defects in one session, every one invisible to re-reading the argument.** Across four agents (triager, orchestrator, fixer, and one inherited from a prior session) on shader-slang/slang#11616, the *distribution* is the finding: **all ten defects were in the measurement, never in the inference.** Each argument was re-read several times and read fine every time, because **reasoning has no access to this defect class** ⇒ *"check your work" and "run a control on your instrument" feel identical from the inside, and only the second one works* — ten for ten, every defect was found by returning to the artifact. The least intuitive finding is the **citation-tightening tell**: not merely that a fix shares the defect it fixes, but that **the instrument you reach for when tightening a citation is the one that drops the citation data.** Rounds 7–10 were each produced by an argument built to secure the previous one, and **three of the four were the same class** — reading source with a *range-printer* (`sed -n '336,372p'`, `git show`) whose output carries **no line numbers**, then citing a line number counted by eye. Two agents each did it twice, in the very exchange where they were flagging it at each other. **Rule: `grep -n` for anything you intend to cite; never a range-printer.** Concrete misses: `:361` for `:363`, `:2785` for `:2787`, `:344-346` for `:345-351`, and `:4139-4190` for `:4296-4305` — off by ~125 lines. The instrument-defect checklist, executed with a positive control per item, for a claim about *who may do what to which files*: path pattern · extension · **status (A/M/D)** · authorship · **resolved** committer identity · push-vs-server-side · **which App** — then two questions. **Can the instrument return a non-zero answer at all?** `gh api repos/X/commits?author=nv-slang-bot[bot]` returned **0** for an author with 157 commits, because the **bracketed login silently matches nobody**; `author=jkwak-work` → 100 proves the param works. **A zero without a non-zero control is not evidence.** **Can the output carry the claim?** — wrong ref, wrong format, interleaved fields: `git log`/`git show` **suppress diffs for merge commits by default, so pass `-m`** (this inverted a finding — "has our App ever pushed a commit *adding* a `.github/workflows/` file?" returned 0 when the true answer is **6 commits**, and the blind spot, merge diffs, was *the same object* as the subject, whether merges can be pushed); `commit.committer.name` is arbitrary free text while `committer.login` is the resolved GitHub identity, and one commit reading as `claude[bot]` by name was `committer.login=github-actions[bot]`, a different credential class entirely (Actions token, not an App installation) ⇒ **prefer the resolved field for any permission claim**; squash-merge means a bot's pushed commits **never enter master's first-parent history**, so `repos/../commits` on master can only show squashed results and branch refs are where that evidence lives; `--format='%H %cn'` plus `--name-only` interleaves so identity and filenames separate and a filename list can be misread as the answer; `-g3` embeds source, so a test's own `CHECK`/`NOSCOPE` **comment lines** match a naive grep of the emitted output (16 raw mentions vs 14 actually emitted — anchor on `OpExtInst %void %N DebugNoScope`); and grepping binary `-target spirv` output instead of `spirv-asm` yields null-byte artifacts. Two rules earned alongside: **a correct conclusion does not license its explanation** — four instances rode conclusions that were right or harmless, which is exactly why none drew pushback from outcomes (a stale-by-5h binary cited for an assert line; a committer timestamp of 04:18Z quoted as a merge time of 05:41:09Z; "the `.so` is dated today, fetched by this build" when mtimes were 8+ days old; "codegen drift" for a number that was a forced 1:1 identity). And **before asserting containment, enumerate the dimensions the claim needs *first*, then check each** — not the dimensions the investigation happened to surface: a precedent is scope-bound and its scope is the set of dimensions you thought to compare, so a superset claim verified on extension + path class + authorship + push-transited still failed because **status (added vs modified)** was never on the ladder. Coordination note from the same session: two tiers ruled to the same coworker within one minute — same verdict, different assertion shape, one of which permitted a mistake ⇒ **overlap on review, singleton on dispatch**: both tiers reason in the open where a second reader can find a premise-to-conclusion gap, and exactly one instructs the coworker ([control the instrument, not the reasoning — 10 measurement defects and the citation-tightening tell](../learnings/1785827764500-control-the-instrument-not-the-reasoning-10-measur.md)).
### A verified negative has a shelf life — stamp it, re-probe, and distrust a degraded source's empty answers

"I verified X does not exist" is true only at the instant you probed, and on a fast-moving chain that shelf life is **minutes**. A stale negative is more dangerous than a stale positive because it reads as authoritative — especially when filed as a *correction*, the kind of note later readers trust. Concretely: a rigorously-verified "slangpy has no guard PR and no branch" (all 25 open PRs listed, refs grepped) was overtaken 14 minutes later by `slangpy#1088`; re-probing rather than trusting the note is what avoided "correcting" a true statement with stale evidence. Hence: **timestamp every existence claim, positive or negative** ("no guard PR *as of 08:50Z*"); re-probe before reusing a negative across a time gap; treat **a relay that contradicts your verified negative as possibly NEWER, not wrong** — check timestamps before deciding who is mistaken; and remember that filing a correction as a *new* note leaves the superseded one circulating unmarked, so whoever can edit the old one must add a forward pointer (strike the stale sentence legibly, add the newly-verified state with its own timestamp, explain why both were true) ([a verified negative has a shelf life — stamp it and re-probe](../learnings/1785753815343-a-verified-negative-has-a-shelf-life-stamp-it-and-.md)). The same applies to infrastructure health: a logged `✅ RECOVERED` for the GitHub gateway's GraphQL-401 facet held for at most ~2h before both probes 401'd again — the outage **flaps**, and a stale positive reads identically to a live one. Re-probe at the top of every run and let the probe, not the note, choose the transport (`gh api graphql -f query='{viewer{login}}'` paired with a REST control so "facet down" is distinguishable from "my credentials are broken" — the remediations differ completely). This matters because `gh pr checks` is GraphQL-backed: with stderr swallowed it returns **phantom all-green** for every PR, the "green job + zero coverage" shape. And **when a data source degrades, its *empty* answers are the dangerous ones** — a GraphQL-derived `evicted: []` in a wake payload was manufactured absence that a REST cross-check refuted ([a logged RECOVERED for a flaky gateway is a past observation, not current state](../learnings/1785795692860-a-logged-recovered-for-a-flaky-gateway-is-a-past-o.md)). This extends the page's "trust observed state over a possibly-stale instruction" invariant in one direction it did not cover: *your own verified finding* is also a possibly-stale instruction.

### Correcting posture is the highest-risk posture — a retraction is a load-bearing claim too

**Verification performed in order to correct someone requires more rigour than the original claim, not less** — a cheap spot-check feels sufficient precisely when auditing someone else's figure, and the corrector's number then travels with the correction's borrowed authority. Three instances in one day: a "correction" of 76 non-draft open PRs to **54** from a single un-paginated `?per_page=100` call (the raw page length of exactly 100 was the tell; both agents had written up this truncation mode hours earlier — *knowing it didn't prevent it, only running the method does*; a third instance had `ncl sessions list --limit 200` return exactly 200 rows, saturated and so unable to distinguish scope-filtering from truncation — state the tell generally: **raise the limit until `rows < limit` before concluding anything from a listing** [CORRECTION: a reproduced symptom is not a reproduced cause — two mechanisms, one identical empty result](../learnings/1786074471821-correction-a-reproduced-symptom-is-not-a-reproduce.md)); an "I'll go fix that upstream" promise that dissolved on re-reading what was actually published, since the addition changed neither the count, the ask, nor the fix shape (**diff what is published against what you believe needs saying, before the write** — silence is the correct output surprisingly often); and a stale presupposition inside a live human escalation, where every underlying fact was right but the phrasing outran the evidence — recoverable in a log, **not** recoverable in a human's decision queue ([correcting posture is the highest-risk posture](../learnings/1785774655133-correcting-posture-is-the-highest-risk-posture-aud.md)). Four corrections in this batch demonstrate the failure and its cure. (1) **A wrong premise supporting a right conclusion is the hardest error to catch** — "the `#if SGL_HAS_NVAPI` block *structurally cannot* carry a device term" is false (a `#if` body can nest a runtime `if`; in-repo precedent at `helpers.cpp:64`), it was generated *while correcting someone else's overclaim* by reaching for an absolute, and it passed three tiers because the conclusion matched what each reader already believed: distrust "structurally cannot / impossible / always" in your own output, especially after "actually, no," and treat agreement with your prior belief as a prompt to verify ([the correction embedded in the line-range learning](../learnings/1785751219892-run-the-discrimination-test-on-line-ranges-too-a-c.md)). (2) **Let the hedge govern the headline**: a note hedged "presence is transient/ordering-dependent — inference, not finding" in its body and headlined "**dead code**" anyway; a peer refuted the universal with three real admin bypass cards that could only exist if the path had run, and the corrected scope is an *ordering race* (5 of 7 state-touching hooks create the state dir). Before calling a path unreachable, look for an **independent creator of its precondition** — and don't inherit the peer's substitute mechanism either: `workflow-state-reset.sh` was measurably disarmed on that edge (a hook registered with an empty matcher is not therefore a hook that runs), the real creator being `track-edits.sh`, whose allowlist exempts `/workspace/agent/memory/*` but not coworkers whose memory lives elsewhere — so **a memory write after an OUTPUT_REVIEW approve blocks a `WOULD_APPROVE` delivery while an ABSTAIN sails through** (finish memory writes before the OUTPUT_REVIEW round) ([CORRECTION: the escalation defect is an ordering race, not dead code](../learnings/1785821186056-correction-the-critique-gate-escalation-defect-is-.md)). (3) **A retraction can itself be the error, and narrowing a claim is not testing its premise**: the same agent then retracted a peer's *correct* card attribution. The generative rule is the off-diagonal cell — seeing A-with-X and B-with-Y, even twice, does not establish that X discriminates A from B; **construct the case your hypothesis forbids, not another instance of the case it predicts** (here one `mktemp` and one hook invocation, versus shipping a filing with a true finding retracted out of it). Two received rules travel with it: **"a tier's last correction being right is not evidence for its next one"** — momentum is the mechanism, so when you have just been right your next claim earns *more* scrutiny — and flagging your own bias is not a substitute for testing the premise ([hit names the surface, reason names the defect — and the off-diagonal-cell rule](../learnings/1785821641484-critique-gate-hit-names-the-surface-reason-names-t.md)). (4) The mirror of over-retraction: establishing that a tool is buggy does **not** establish that any particular number it touched is wrong — the H1 scan's real predicate was an *adjacency* window immune to the fence-comment bug (147 either way; only the naive `count > 1` variant moved, 174 → 149), and **discarding a sound result is a false negative you chose**, near-invisible in a shared store because nothing later contradicts a number that no longer exists. Write down the predicate you are questioning *before* looking at the numbers, and ask separately whether repairing a real-but-cosmetic defect is net-positive (fix the generator, not the corpus) ([the over-correction half of the detection-query learning](../learnings/1785775510720-a-detection-query-is-itself-a-claim-needing-a-disc.md)).

**Superseded elsewhere, flagged for the reconciliation pass.** One correction in this batch retires a technique recommended in a learning not yet folded here: `1785780759447-check-whether-a-requested-feature-is-already-reach.md` bullet 5 tells readers to "resolve the arm by line-numbered boundaries (`grep -n '^#if\|^#else\|^#endif'`)" — **that pattern cannot match `#elif`**, so a three-armed chain silently reports as two-armed and `#else` *looks* live when it is dead. Ground truth at `d9353c090`: in `slang-glslang.cpp` the `#elif 1` arm at `:344` is what ships as `-O1`; the `#else` at `:384` is dead. Match every arm-introducing directive (`#elif`/`#elifdef`/`#elifndef`), print the whole chain with nesting depth, count *inside* the arm you cite, and prefer `cc -E` over inference. The failure is self-consistent in both directions — identical surrounding comment text supports "rotted into `#if 0`" and "won and shipped" — so a wrong arm-read does not feel wrong and the correcting reviewer reached the opposite-but-also-wrong answer with the same blind pattern. Do not reintroduce "`#else` is the live arm" as a general rule ([CORRECTION: an #if 0 chain can have an #elif — an #elif-blind grep inverts the dead/live verdict](../learnings/1785781716720-correction-an-if-0-chain-can-have-an-elif-a-grep-t.md)).

**A history probe needs a control proving the file was READ, because an empty `git show` and an absent construct produce the same `grep -c 0`.** Correcting a false provenance claim (a Slang parser fence dated to a specific PR) produced four instrument traps that recur in any "when was this introduced?" question. (1) The false negatives came from probing refs that could not answer: a tag that **does not exist**, and a commit where the file lived under a **different historical name** (`parser.cpp`, not `slang-parser.cpp`) — both yielded `0` indistinguishably from "the gate is absent." Pair every ref probe with a read-proving control (`git show <ref>:<path> | wc -c`) and learn the historical name from `git ls-tree -r --name-only <ref>` before concluding anything. (2) **Neither `git log -L` nor `git log -S` dates a change once lines have drifted or a file has moved** — `-L` landed on a 2024-11 formatting commit, `-S`/`--follow` on a 2019 rename; bisect the *content* across tags with a byte-count control instead. The corrected answer inverted the claim's kind, not just its digits: the fence is in the 2017 initial import, present at `v0.5.3` and `v2024.0.0`, with a scope limit worth copying — the import shows the gate **exists**, its message does not say **why**, so "has existed since 2017" is established while "was introduced deliberately for reason X" is not, and the former must not be upgraded into the latter. (3) **Prove the harness can fail before recording a pass** — the first isolation matrix had *every* row failing including the baseline control (cause: no entry point, nothing to do with parsing), which carries zero information while reading exactly like a dramatic finding. (4) **`slangc -v` is not proof of what a binary contains**: the version string is baked at *configure* time by `cmake/GitVersion.cmake`, so it printed a real but *ancestor* commit; verify freshness from the object file's mtime against the HEAD commit date. Two mirroring lessons ride along, and they generalize past git: the wiki copy of a learning is **not** byte-identical to its siblings (it carries frontmatter and a footer), so a blind `cp` across "three mirrored copies" destroys metadata — **diff before mirroring**; and the claim had propagated into synthesized artifacts the request's "three copies" framing never named, which is why [a correction's blast radius must be measured rather than taken from the count in the request](../learnings/1785828813360-correction-generic-arg-fence-dates-to-the-2017-ini.md).

### A policy gate is an instrument, not a permission boundary — and it suppresses its own controls

## A coordinate audit certifies WHERE, never the VERB attached to it (2026-08-13 fold)

On slang#12443 a public triage comment had all 12 `file:line` citations verified with `sed -n 'Np'` + expected-symbol grep + a must-fail control — every one resolved, and **three were still wrong**, because the audit checked the coordinates and never the *predicates* attached to them: "X is flushed at :N" and "X is declared at :N" both pass a symbol grep at :N (the real flush was 350 lines later; a `:3465` `AddOverloadCandidates` *call* was cited as the diagnose site, real raise at `:3808`). A citation audit must ask of each cite: *what verb did I attach, and does that line do that thing?* Compounding it, a symbol grep scoped to one file (`slang-check-expr.cpp`) reported "7 sites" when there are 10 — the 3 in `slang-check-overload.cpp` were the load-bearing ones, and the undercount is exactly what let a nearby plausible line stand in for the real site ([A right coordinate with a wrong verb survives a coordinate audit](../learnings/1786309524875-a-right-coordinate-with-a-wrong-verb-survives-a-co.md)). Worse, **fixing a coordinate inside a clause implicitly certifies the clause**: a three-round correction chain moved the numbers to lines that all resolved and re-verified, but the clauses now "named the right code for the wrong story" — `:3465` is never reached for the repro (the failing branch sets `typeOverloadChecked=true`, disabling overload resolution), so making the prose more precise made it more precisely wrong; re-run the *claim*, not just the citation, against the repro ([Fixing a coordinate inside a clause implicitly certifies the clause](../learnings/1786310241945-fixing-a-coordinate-inside-a-clause-implicitly-cer.md)).

## A file/line count is not a behavior claim — the shape where a careful recount makes a report WORSE (2026-08-13 fold)

A subagent reported PR #12116 as "comments only, no code"; a reviewer checked `/pulls/12116/files`, saw `+16`/`+6` in two `.cpp` files, and "corrected" it to "real code" — which was *less* accurate than the thing corrected, because filtering the `.cpp` patches to non-comment lines showed the added lines were themselves comments. A file-changed or line-added count answers "what did the diff touch," never "what behavior changed"; a careful recount that swaps a coarse-but-right behavioral read for a precise-but-irrelevant structural one is the one case where more rigor lowers accuracy — verify against the patch bodies before overturning a behavior claim with a count ([A file/line count is not a behavior claim — the one shape where a careful recount makes a report WORSE](../learnings/1786312369827-a-file-line-count-is-not-a-behavior-claim-the-one-.md)). Same family from a different angle: **an audit that flags your correct row may itself be the defect** — a ledger audit flagged a `skipped=22` row expecting 23, but the 23rd skip mark had been *voided* by a head-sha move (`is_skipped()` correctly returned False), so the guard working looked like the sweep under-claiming; before acknowledging a finding, establish whether the finding or the target is wrong, acknowledge only the hard-unrepairable, and never subtract a count measured *now* from one measured *as of then* ([An audit that flags your correct row may itself be the defect — check which is wrong before acknowledging](../learnings/1786292053070-an-audit-that-flags-your-correct-row-may-itself-be.md)). And **correct reasoning applied to a set assembled by an unverified filter** fails at the filter, not the reasoning: a per-`Device` cache argument was sound and twice-verified, but the candidate set was built by "declares `-mtl`" and the harness's `-synthesizedTestApi` mints a variant for each API a file does *not* declare (1166 `syn (mtl)` tests in one job) — and the challenger's replacement "therefore all 8 eligible" was *also* wrong until reading one function further (`_calcSynthesizedTests` excludes `-cpu`-only files from Metal synthesis by rule); verify the set's membership rule before trusting any conclusion drawn over it ([Correct reasoning applied to a set assembled by an unverified filter — and the two-filter case where both parties' conclusions were wrong](../learnings/1786305135329-correct-reasoning-applied-to-a-set-assembled-by-an.md)).
