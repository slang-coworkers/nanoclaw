## TL;DR

- **Picking a diagnostic code:** don't argue "max in the band + 1" — uniqueness is **build-enforced** across five catalogs sharing one code space (`slang-diagnostics-helpers.lua` `error()`s on a clash), so two in-flight PRs claiming adjacent codes merge safely in either order.
- **Enumerating occupancy is where every method fails:** codes are declared multi-line, via six constructors (`err`/`warning`/`standalone_note`/`internal`/`fatal`/`note`), and one catalog stores codes as *strings* (`code = "E30019"`). A single-line / integer-only / one-constructor regex silently under-reports. Enumerate by *registration*, not by syntax; control on a code you know is occupied.
- **Diagnostic rendering pins severity:** the rich renderer emits `error[E00116]` (zero-padded, severity-prefixed) — asserting on that form pins the ID *and* the severity. `internal(` sorts above `Fatal` and aborts the compile immediately.
- **Slang reflection deliberately reports push-constant ranges as descriptor ranges** — consumers must filter, or they mint a phantom empty descriptor set. You can triage at the reporter's exact release version — just download it. `-reflection-json` is not the surface a runtime consumes; write a ~100-line harness against `libslang.so`.
- **`VariableReflection::getDefaultValueBlob` is the only `SLANG_API` non-free-function** in the public headers — no flat C export, so non-C++ FFI (C#, Rust, Python ctypes) cannot bind it. A deliberate `sp*` deprecation with an unexamined C-ABI-reachability side effect.
- **Spec-grounded review:** the governing Vulkan section for a foreign-API ownership release is §12.10.1 (External Resource Sharing), *not* the generic §7.7.6 inter-queue QFOT text. The asciidoc `undefined:` macro renders identically for "undefined contents" and "undefined behavior" — quoting one true sentence from the wrong section produces a confident, well-cited, wrong must-fix.

## Diagnostic codes: build-enforced uniqueness, and the enumeration traps

The safety argument for a new diagnostic code is **structural, not arithmetic**. `slang-diagnostics-helpers.lua` sets `allow_duplicate_diagnostic_codes = false` and `error()`s out at generation time on a clash, spanning **five catalogs that share one code space**: `slang-diagnostics.lua`, `source/slang/diagnostics/type-errors.lua`, and three C++ `*-diagnostic-defs.h` files folded in via `cpp_diagnostic_defs_files`. A new `*-diagnostic-defs.h` joining the compiler code space must be added to that list or its codes stop participating in the check; the `tools/` variants are deliberately excluded (each numbers from ~0). Duplicates are legal for an allow-listed set (`is_intentional_shared`: all negatives plus 20002–20012), which is why 39999 appears 27× without failing. Consequence: two in-flight PRs claiming adjacent codes are safe to merge in either order, independent of anyone's enumeration being complete. [Slang diagnostic codes: uniqueness is build-enforced across five catalogs, not just conventional](../learnings/1785982868763-slang-diagnostic-codes-uniqueness-is-build-enforce.md)

Enumerating *occupancy* is where confidently-wrong answers come from, and the same defect bit three actors independently on #12342. Three compounding traps:

- **Multi-line declarations.** Most diagnostics are declared across three lines (`err(\n "name",\n 114,\n ...)`), so any matcher requiring name-and-code on one line returns zero for them and reads the code as free. Use a DOTALL matcher, or a form-agnostic own-line check (`grep -c '^\s*114,$'`). Cheapest check of all: look at your own insertion point — a code cannot be free if you are writing the new block three lines beneath it. [slang-diagnostics.lua declares codes across 3 lines — single-line matchers silently under-report occupancy](../learnings/1785895810117-slang-diagnostics-lua-declares-codes-across-3-line.md)
- **Six constructors funnel into one registration.** `add_diagnostic` is fed by `err`/`warning`/`standalone_note`/`internal`/`fatal`/`note`. A regex omitting `standalone_note`/`internal` produced a large, authoritative-feeling count (779) while missing codes 102/103 — reported as free, they are occupied. Correct parse: 837 diagnostics, 100–114 contiguous, first free 115. **Enumerate by registration, not by syntax:** find the one function that registers an entry and enumerate its callers. A positive control proves you are reading the right *file*; it cannot detect an *incomplete enumeration*. [Slang diagnostic codes: enumerate via add_diagnostic's six constructors, not an err/warning regex (100-114 all occupied, first free 115)](../learnings/1785895873723-slang-diagnostic-codes-enumerate-via-add-diagnosti.md)
- **String-coded catalog.** `type-errors.lua` uses `diagnostic "name" { code = "E30019", ... }` and contains zero integer tokens — an integer-anchored scan returns a clean, meaningless 0. Re-run for `E116`/`E0116`/`E00116`/`"116"` with a string positive control. The helper's own doc comment (`warning("my-warning", 123, ...)`) is a commented example a call-shape regex counts as real.

Cross-check findings *inside* one message: a build-enforcement finding *predicts* that any occupancy claim about a shipping code is wrong — those two facts sitting two paragraphs apart went unreconciled until a reviewer caught it. **Rendering:** the rich renderer emits `error[E00116]` (severity + zero-padded bracketed code), so asserting on that form pins severity as well as the ID (a `err(`→`warning(` downgrade breaks the assertion); the older plain sink emits `error 116:`. `internal(` maps to `Severity::Internal`, which sorts *above* `Fatal` and triggers `SLANG_ABORT_COMPILATION` immediately — an `internal(` diagnostic can abort the compile before it reaches the code a test targets.

## Reflection API: push-constant ranges, and the FFI-unreachable member

Slang reflection **intentionally** enumerates a push-constant range as a "descriptor range" inside a descriptor set, even though push constants are not descriptor-bound on Vulkan/D3D12 — the source (`slang-reflection-api.cpp:2582-2590`) says an application layer "will need to filter/translate." Measured: a compute entry point with `uniform uint width` makes the entry-point type layout report `getDescriptorSetCount() == 1` whose only range is `PushConstant`; without the uniform it reports 0. So a host looping `getDescriptorSetCount()` and minting one API set per reflected set **must** skip sets whose ranges are all `PushConstant`, or it creates a phantom empty set that steals set index 0 (insertion-order assignment) and pushes a real `ParameterBlock`'s set to the wrong index → `VUID-VkComputePipelineCreateInfo-layout-07988`. This is a defect *class* (slang#8958 was the same interaction, closed by a fix that touched only an example). When you see push-constant + ParameterBlock, suspect the consumer, not the compiler. Two reusable methods: you can **triage at the reporter's exact release version** — `gh release download v2026.12 ...` ships `slangc` + `libslang.so` + headers, so a version claim is a one-minute measurement, not an inference from "the files changed a lot"; and `-reflection-json` does not expose the per-set/per-range surface a runtime like slang-rhi reads, so write a ~100-line harness linked against `libslang.so`. (`getBindingRangeDescriptorSetIndex()` returning −1 = "sub-object, contributes no range to the parent" — a `ParameterBlock` always does this.) [Slang reflection deliberately reports push-constant ranges as descriptor ranges — consumers must filter, and a version-matched release binary is downloadable for triage](../learnings/1785880794321-slang-reflection-deliberately-reports-push-constan.md)

`VariableReflection::getDefaultValueBlob` is the **only `SLANG_API`-marked non-free-function in the entire public header set** — every other reflection method is a header-inline wrapper forwarding to an `spReflection*` flat C function. `VariableReflection` is not COM (no vtable, no `ISlangUnknown`), just an opaque handle whose C++ methods cast `this`; so there is no `extern "C"` symbol and no vtable, and non-C++ FFI consumers (C#, Rust, Python ctypes) cannot bind it the way they bind every sibling. It got there via PR #11471: a maintainer asked to drop the deprecated `sp*_*()` name and inline the body, but the body needs internal AST types so it could not be header-inlined — what shipped is an out-of-line `SLANG_API` member with no header precedent. **Dropping the `sp*` name was deliberate; losing C-ABI reachability was an unexamined side effect** — no reviewer comment mentions bindings/FFI/mangling. When a reflection method is reported "unbindable," check for an `spReflection*` counterpart in `include/slang-deprecated.h` (which still holds the *active* reflection C-API); `include/slang-reflection.h` does not exist on master. [slang VariableReflection::getDefaultValueBlob is the only SLANG_API member — no flat C export (C# binding blocker)](../learnings/1785899132762-slang-variablereflection-getdefaultvalueblob-is-th.md)

## Spec-grounded review: cite the governing section, not the plausible one

Reviewing a Vulkan→foreign-API (CUDA) ownership release, a lens returned REQUEST_CHANGES quoting a real §7.7.6 Queue Family Ownership Transfer sentence ("after a release... contents are undefined until a matching acquire") — and was still wrong, because that sentence governs *inter-queue* transfers inside one Vulkan instance. For an external consumer importing `VkDeviceMemory`, the governing text is **§12.10.1 External Resource Sharing**, and there is no Vulkan-side acquire (the foreign API's own sync is the acquire half). The undefined-contents hazard attaches to *omitting* the release (the pre-fix status quo), and the release itself performs the availability operation, so the barrier is load-bearing, not decorative. **Root trap:** the spec's asciidoc `undefined:` macro renders identically for "undefined contents" and "undefined behavior" — seeing `undefined` near a release tells you nothing about which is meant or whose fault it is. Quoting one true sentence from the wrong section produces a confident, well-cited, wrong must-fix. Method notes: `registry.khronos.org` returns 403 to WebFetch but 200 to `curl`; the asciidoc source on GitHub is the better citable source since VUIDs live in `commonvalidity/`; and controls cleared two red herrings (`dstStageMask=BOTTOM_OF_PIPE` on a release is ignored, no VUID; `VK_ACCESS_MEMORY_WRITE_BIT` is always valid and subsumes `TRANSFER_WRITE_BIT`).
