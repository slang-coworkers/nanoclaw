# PR-Approver: Decision Procedure, Clauses, Infra-Abstain & Critique-Gate (part 7)

> **This page is part 7 of 7** of the PR-Approver: Decision Procedure, Clauses, Infra-Abstain & Critique-Gate synthesis (split 2026-08-07 to stay under the 40 KB read cap). Siblings: [part 1](review-approver-decision-procedure.md), [part 2](review-approver-decision-procedure-2.md), [part 3](review-approver-decision-procedure-3.md), [part 4](review-approver-decision-procedure-4.md), [part 5](review-approver-decision-procedure-5.md), [part 6](review-approver-decision-procedure-6.md). The TL;DR below is shared across all parts.

## TL;DR

- Step 1 is data, Step 3 is judgment. A clause is a mechanical predicate over PR metadata and changed paths at the pinned commit; anything needing a diff read belongs in the challenger.
- Never encode an adequacy judgment as a clause. It evaluates `unevaluable` and produces a spurious `ABSTAIN_INFRA` on every PR, corrupting the abstain rate it was meant to protect.
- Route "the reviewer should ask X" to Step 3 no matter how the request was framed upstream.
- Treat a writable skill file as ephemeral. Grep `.external-skills.json` for the skill name before editing under `/home/node/.claude/skills/`; if listed, the edit is re-synced away silently.
- Put per-agent behavior in the group overlay `.instructions.md`; put anything that must reach every consumer of a skill in an upstream PR to the skill repo, not in N drifting overlays.
- Confirm durability by grepping the recomposed `CLAUDE.md` after a restart. Writability is not durability.
- Demand a both-directions control for any conditional change: condition false → path skipped, and condition true → path taken and observably did its job.
- Per new flag, check cheapest-first: a setter exists anywhere in the tree; the scan runs before the gated work; every job in the pass is accounted for, not just the guarded one; a trigger-present control exists per job.
- Read an uninitialized flag aggregate as indeterminate, not false, before its reset point.
- Search for a pre-existing present-direction test before calling a control missing. A missing trigger-present control is `ABSTAIN_POLICY:OPEN_GAP`, not a nit.
- Exempt widening-only changes from the dead-flag probe. Broadening an existing flag false→true is monotone and cannot create a dead flag; a probe that fires on the safe direction of a change class is a false-abstain generator.
- Treat inbound findings as hypotheses, never conclusions. A correct prospective hazard is routinely mis-stated as a shipped defect; verify before adopting wording.
- Enumerate every feedback endpoint in the instruction itself. GitHub splits PR feedback across `pulls/N/reviews`, `pulls/N/comments`, and `issues/N/comments`; an instrument silent about the channel list will be written blind.
- Scope a source-model defect to the consumer SET, then to every copy of the pattern. Copies live outside the surface you are auditing and are invisible from inside any one of them.
- Report per-endpoint counts and timestamps including empty channels, and apply any addressee or relevance test per channel. A union verdict hides which member carried the evidence.
- Mark a consumer N/A rather than clean only after reading its call sites; a zero grep hit is equally consistent with "does not read it" and "reads it by another spelling."
- Call a consumer that defers channel selection to the reader UNDER-SPECIFIED, not clean.

## Devin Subagent Returns Before devin-fetch.sh Completes — Watch the Artifact, Not the Subagent (2026-07-21 fold)

In `/slangpy-pr-approve` (and slang) Step 1b, driving Devin via a background `Agent` subagent, the subagent repeatedly reports completion while `devin-fetch.sh` is still running: its final message gets clobbered by its own polling ("I'll wait for the notification…"), and `review/devin-flags.md` is absent on disk for 15-25+ min because the script (agent-browser + Chromium) is long-running, silent, and writes its result ONLY at the very end. The devin-fetch process SURVIVES the subagent's exit and keeps running under the parent session, so the artifact does eventually land — but the subagent's returned text is not a completion signal. How to catch it: after the subagent "completes," check the actual artifact (`ls review/devin-flags.md`) and process liveness (`pgrep -af devin-fetch.sh`); if the process is alive, wait on the artifact, not the subagent. Fix: drive Devin with a `Monitor` (or background Bash `until` loop) watching for the artifact to appear OR the script to exit (covering both success and no-artifact failure), instruct the subagent to run in the FOREGROUND and report once with an explicit ~15-min self-timeout returning `DEVIN_TIMEOUT`. If Devin never produces a head-current signal AND the harvested bot review is stale/absent, that is `ABSTAIN_INFRA:NO_REVIEW_SIGNAL` — do NOT substitute your own code read for the missing review doc. Gotcha: `pkill -f chromium` from a Bash tool can take down the calling shell (exit 144) — kill in a throwaway shell or SIGTERM the top `devin-fetch.sh` pid only ([[approver/infra-abstain] Devin subagent returns before devin-fetch.sh completes; artifact writes at end](wiki/learnings/1784560636178-approver-infra-abstain-devin-subagent-returns-befo.md)). A sibling race hits even when `devin-fetch.sh` exits 0 with a populated rollup: on slangpy#1084 rev-3 the artifact carried "0 Bugs, 3 Flags" but the per-flag DETAIL lines (title/severity/file:line) were **absent** because the done-detector fired while the diff pane still read "Loading diffs…" — the right-rail flag COUNT settles before the center pane hydrates the detail. So after the subagent returns, cross-check the `## Flags` section against the AI-analysis rollup: an empty/"(none captured)" Flags list while the rollup says "N Flags" (N>0) means the detail was lost to the race — do NOT report "no flags"; when the decision does not short-circuit at a Step-1 clause, re-run/re-scrape before deciding, and when it does (e.g. all files under `.github/**`) record the decision but set a `devin_flag_detail_captured: false` marker rather than present the incomplete list as exhaustive (still `reviewers_complete=true` — a capture-completeness gap, not a NO_REVIEW_SIGNAL) ([[approver/infra-abstain] Devin done-detector also races the "Loading diffs…" state — flag COUNT renders but per-flag DETAIL lines stay empty](wiki/learnings/1785517182047-approver-infra-abstain-devin-done-detector-also-ra.md)).


## Repo-Class Predicate Overrides Co-Occurring INFRA Symptoms; Devin-Timeout on Bot PRs = NO_REVIEW_SIGNAL (2026-07-22 fold)

**Two independent INFRA-looking signals on a website-content PR still resolve to ABSTAIN_POLICY, not INFRA.** On shader-slang.github.io#209 both `collect-reviews.sh` exit 20 (`{found:false}` — no bot review to harvest) and `commit_match` unevaluable (because `eval-clauses.py` was run before `review-doc.md` was synthesized) co-occurred and could double-mislead toward ABSTAIN_INFRA. Both are structural out-of-domain symptoms of the website repo, not pipeline failures: production `claude-pr-review.yml` never runs on the Jekyll site (→ harvest-20), and `commit_match` parses the synthesized doc, not `harvest.json` (→ unevaluable purely because the doc isn't written yet). The **repo-class predicate fires FIRST and overrides the mechanical review-signal → INFRA mapping** — verify the diff is content-only (no `_config`/CI/build code) and record `ABSTAIN_POLICY:OUT_OF_SCOPE:website-content`, never ABSTAIN_INFRA. Re-running `eval-clauses.py` after synthesizing the doc with the pinned `commit_id` flips `commit_match` to a clean 6/6-pass whose abstain rests purely on the class predicate ([website-content PR shows BOTH harvest-20 and commit_match-unevaluable — both out-of-domain, still ABSTAIN_POLICY not INFRA](wiki/learnings/1784618140917-approver-clause-gap-website-content-pr-shows-both-.md)).

**On the Devin-only tier, a Devin timeout + exit-20 harvest = the one fragile signal failing = ABSTAIN_INFRA:NO_REVIEW_SIGNAL — never round up from your own investigation.** slangpy#1071 (bot-authored rebased takeover, tiny diff, fully green CI) abstained because production `claude-pr-review.yml`/claude-code-action genuinely SKIPS bot-authored branches (exit-20, expected for this class) AND `devin-fetch.sh` hung past the URL-rewrite step for >12 min with no `devin-flags.md`. Exit-20 alone is not an abstain (Devin-only tier decides); exit-20 AND a Devin failure is the `reviewers_complete=false` harness-integrity case. This is the dominant infra-abstain driver for bot-authored PRs — the fix is devin-fetch fail-fast (a ~5-min internal cap), and whether trivially-safe bot test-only PRs should keep abstaining is a human policy question, never a license to substitute the approver's own code read for the missing review verdict ([Devin timeout + bot-authored PR = NO_REVIEW_SIGNAL despite clean CI](wiki/learnings/1784695299892-approver-infra-abstain-devin-timeout-bot-authored-.md)).


## Late-Primary Refresh, Bounded Devin Retry, Class-Override, and the ABSTAIN-Token Gate Trap (2026-07-23 fold)

Refinements to the deterministic order and its infra/gate mechanics. A Devin-only fallback decision is **provisional** against a late primary review on an unchanged head: when a supervisor nudge or later event lands, re-check live state and REFRESH the ledger row on the primary tier if `github-actions[bot]` has since posted at your decided commit — the fallback row's "review never posted" blocker becomes factually false minutes later ([a primary review that posts after you decide (unchanged head) → refresh the row on the primary tier](wiki/learnings/1784723964060-approver-infra-abstain-a-primary-review-that-posts.md)). To keep ABSTAIN_INFRA near zero, wrap `devin-fetch.sh` in a hard shell `timeout` and do ONE bounded retry before recording NO_REVIEW_SIGNAL — an agent-browser hang is a transient wedge, not a real "Devin can't review" outcome ([Devin agent-browser hang recovered by bounded-timeout retry — avoid false ABSTAIN_INFRA](wiki/learnings/1784735780656-approver-infra-abstain-devin-agent-browser-hang-re.md)).

Two class/clause interactions: `head_provenance` fails any cross-repo (fork) head under `allow_fork_head=false` **independently of author trust**, so a clean member PR from a personal fork is a foregone ABSTAIN_POLICY:CLAUSE_FAIL — check `isCrossRepository` early and don't burn a challenger pass ([fork-head PRs from trusted MEMBERs abstain on head_provenance under v0-shadow](wiki/learnings/1784735771677-approver-clause-gap-fork-head-prs-from-trusted-mem.md)); and the `tier_eligible` size cap is another Step-1 FAIL that short-circuits before the challenger with no carve-out for change *class* — a purely test-only consolidation PR (slangpy#1085, 24 files all under `tests/`, +3141/−59 ≈ 3200 lines, zero runtime/binding/build changes) resolves to ABSTAIN_POLICY:CLAUSE_FAIL:tier_eligible (3200 > 2000-line cap) even though it touches no shipped code, because `eval-clauses.py` computes eligibility from raw `additions+deletions` churn. When a PR is test-only AND the only failing clause is `tier_eligible`, recognize the benign expected abstain, don't spend challenger effort (the challenger cannot upgrade a Step-1 FAIL), and note that the only lever that would change the outcome is a policy tier scaling `max_total_lines` by change class — not a challenger override ([[approver/clause-gap] Large test-only consolidation PRs abstain on tier_eligible size cap](wiki/learnings/1785510473677-approver-clause-gap-large-test-only-consolidation-.md)); and class determination fires FIRST — a non-compiler infra/docs PR (e.g. a `slang-coworkers/nanoclaw` changelog) sails through all six eligibility clauses as PASS and its harvest-20 mimics the INFRA trigger, but the correct verdict is ABSTAIN_POLICY:OUT_OF_SCOPE, never WOULD_APPROVE or ABSTAIN_INFRA — and a bot self-merge is not a human verdict ([nanoclaw changelog docs PR: 6/6 clauses pass, still OUT_OF_SCOPE not INFRA](wiki/learnings/1784745354331-approver-clause-gap-nanoclaw-changelog-docs-pr-6of.md)). The confirming shape for infra-abstain: a bot-authored rebased-takeover that is test-only, cites a CLOSED blocker, and whose target CI job actually *runs* the enabled tests is a repeatedly-safe class — but that still does not license rounding up from ABSTAIN_INFRA ([merge confirms bot-authored test-only device-enablement takeover is a repeatedly-safe shape](wiki/learnings/1784726873588-approver-infra-abstain-merge-confirms-bot-authored.md)). Finally a gate trap: the critique-gate ABSTAIN fast-path allows the message only if it matches `ABSTAIN_*` AND does NOT match `WOULD_APPROVE|BLOCK` as bare words — so writing "→ OPEN_GAP, not WOULD_APPROVE" in an abstain rationale trips the exclusion and forces the full (skippable) gate; keep those enum tokens out of the delivered `[Approval Decision]` text entirely ([ABSTAIN [Approval Decision] message must not contain the literal tokens WOULD_APPROVE/BLOCK](wiki/learnings/1784769386692-approver-critique-mustfix-abstain-approval-decisio.md)). The exclusion grep is a plain whole-word, case-sensitive ERE over the ENTIRE message body — it does not care whether `BLOCK`/`WOULD_APPROVE` is the decision state or just prose, so an innocuous `**Blocker:**` bullet that explains *why* you held a 🔴 "rather than a BLOCK verdict" defeats the fast-path and gets the abstain treated as a gated decision (observed on slangpy#1075 @4415159, where it consumed denial-cap strikes and escalated to a human admin before it was noticed) — reword to "a hard-fail verdict" / "round up to approve", and scan the whole message for the bare uppercase tokens before sending ([[approver/infra-abstain] Critique-gate abstain fast-path breaks if the message text contains the tokens BLOCK or WOULD_APPROVE](wiki/learnings/1785450575710-approver-infra-abstain-critique-gate-abstain-fast-.md)).

Two more critique-gate mechanics that cost round-trips under the `critique-gate` overlay (observed on slang#12220): **PLAN_REVIEW is a REQUIRED stage, not optional** — even a well-scoped triage-handed fix has `gh pr create` DENIED until a `STAGE: PLAN_REVIEW` codex round is recorded, so run all three (PLAN_REVIEW → CODE_REVIEW → OUTPUT_REVIEW) as fresh `mcp__codex__codex` calls carrying the canonical developer-instructions verbatim (a `codex-reply` is NOT counted unless its instructions match). And **any edit after an OUTPUT_REVIEW approve re-arms the gate — including edits to non-deliverable files** (writing a local `memory/fix-<n>.md` re-armed it even though the PR body/code/test were byte-identical), so do all side-artifact writes BEFORE the final OUTPUT_REVIEW and send the deliverable immediately after the approve with no intervening edits [critique-gate: PLAN_REVIEW is required + any side-artifact edit re-arms the OUTPUT gate](wiki/learnings/1785191965028-critique-gate-plan-review-is-required-any-side-art.md).

A `synchronize` webhook does not always mean new work to re-decide: GitHub fires it on **any** head move, including a `git merge main` that pulls base content into the branch, so the raw commit-to-commit diff shows base churn (e.g. an unrelated test file) that a naive read mistakes for new PR footprint. Decide from the **net footprint** (`gh pr diff` = merge-base…head): if it is byte-identical to the prior revision the push is a no-op merge and the challenger findings transfer — but every open gap must still be **re-verified against LIVE source at the new head** (contents API `?ref=<head>`), because byte-identical net diff proves the *change* is unchanged, not that a maintainer didn't separately edit the flagged lines; a stale-by-commit-id harvest (CodeRabbit exit 10) is not the same as an obsolete finding ([a no-op merge synchronize leaves footprint byte-identical — decide from net diff, re-verify gaps against live source](wiki/learnings/1785319523865-approver-clause-gap-a-synchronize-on-a-no-op-merge.md)). This also sharpens the ABSTAIN delivery-gate rule already on this page: in an `[Approval Decision]` ABSTAIN message, never write the uppercase tokens `BLOCK`/`WOULD_APPROVE` even negated — phrase as "not a blocking defect".

## Adequacy Judgments Are Step-3, Never Step-1 — And the Writable Skill File Is Not the Durable One (2026-08-04 fold)

**No deterministic clause covers test-plan adequacy and none *can*; route any "the reviewer should ask X" request to Step 3 regardless of how it was framed upstream.** `eval-clauses.py` is data-only by construction (`eval-clauses.py:5-6`: it never judges the code and never reasons) — each of its six clauses (`author_trust`, `head_provenance`, `commit_match`, `ci_green_on_sha`, `no_protected_paths`, `tier_eligible`, plus size caps) is a mechanical predicate over PR metadata and changed paths at the pinned commit. "Does this PR's test plan contain a trigger-present control?" needs a diff read to find each new flag and locate its setter — judgment over code. Encoded as a clause it lands `unevaluable` ⇒ a spurious **ABSTAIN_INFRA on every PR**, corrupting the infra-abstain rate that is a quality gate driven to ~0; the advice would have degraded every decision, not merely missed its target. The Step-1/Step-3 boundary is **data vs judgment**, and an inbound framing ("file this against whatever clause covers adequacy") does not move it. The second half of the same correction is about *where the fix lives*: **the writable skill file is the obvious target and the wrong one.** `/home/node/.claude/skills/{slang,slangpy}-pr-approver/SKILL.md` is writable, but `.external-skills.json` lists both (and 17 siblings) as synced from `shader-slang/slang-skills@main`, so local edits are re-synced away silently, with no error — the same cost recorded when a `supervise-issues` `scan.py` fix had to be re-derived by hand across six ticks because it reverted on every re-sync. The durable home is the group overlay **`/workspace/agent/.instructions.md`**, which composes verbatim into `CLAUDE.md`'s `## Additional Instructions` (headers demoted `##`→`####`); verified unchanged mtime across ~26 days of restarts, with the adopted probe block reappearing at `CLAUDE.md:559-579` after the restart that applied it. Guards: before editing anything under `/home/node/.claude/skills/`, grep `.external-skills.json` for that skill name — present ⇒ the edit is ephemeral; confirm durability the honest way by grepping the *recomposed* `CLAUDE.md` for your text after a restart, because **writability is not durability**; and anything that must reach *every* consumer of the skill is an upstream PR to `shader-slang/slang-skills`, not N drifting overlays ([adequacy has no deterministic clause — the both-directions control is a Step-3 probe, and its durable home is `.instructions.md`, not the synced `SKILL.md`](wiki/learnings/1785828782431-approver-clause-gap-test-plan-adequacy-has-no-dete.md), [the dead-flag probe belongs in Step 3, not Step 1 — same layer + durability errors, self-corrected in 20 min](wiki/learnings/1785829409706-approver-clause-gap-a-gate-pr-probe-belongs-in-ste.md)).

**The probe that replaces the impossible clause is scoped to NEW flag + NEW gate, and must exempt widening-only changes or it becomes a false-abstain generator.** The defect shape: a flag declared and gated on but never set, so the guarded work never happens on any input while every artifact an approval pipeline consumes stays green — byte-identical output is green *by construction* (skipped work changes nothing), tests pass (none asserted the work happened), no reviewer objects (nobody looks for an unsatisfiable condition). `tests/hlsl/lower-lvalue-cast-skip.slang` (slang#12088) says it in its own comment: skip-vs-run "is a compile-time-only property that is not observable in emitted output," so the skip-direction test and the revert drill both stay green *more* easily when the flag is dead. The Step-3 form is a **both-directions control** — condition false → path skipped, *and* condition true → path taken and observably did its job — backed by four checks, cheapest first, per new flag: (1) **setter exists** — grep the whole tree for the identifier, not just the scan switch; a write anywhere refutes "dead"; (2) **order** — the scan must run before the gated work (in slang the flag struct is a plain aggregate of *uninitialized* bools, `slang-code-gen.h:52-88`, verified 34 bools with zero member initializers, reset only at `slang-emit.cpp:1047`, so a read before that is **indeterminate**, not false); (3) **jobs, not passes** — read the whole `processModule` (`lowerUntaggedUnionTypes::processModule`, `slang-ir-lower-dynamic-dispatch-insts.cpp:745-756`, carries a second unconditional job at `:755`, `replaceNoneTypeElementWithVoidType()`); (4) **a trigger-present control per job**, but check for a pre-existing one before calling it missing (`late-capability-requirement-{bad,missing,conditional,conditional-fail}.slang` are already the present-direction control for `lateRequireCapability`; #12088 added only the skip baseline). Missing ⇒ `ABSTAIN_POLICY:OPEN_GAP`, explicitly not a nit; diagnostic-bearing passes are the worst case, because the loss is a **missing error**, invisible to any codegen byte-comparison. The exemption: **widening-only changes** — no new flag, only new `case` labels broadening an existing flag false→true — are monotone, cannot create a dead flag and cannot skip a needed pass (precedent slang#12050 @`4c507cb94ca3`: WOULD_APPROVE, merged unchanged by a maintainer). Finally, treat inbound findings as hypotheses: verification at `0864e60e635ef39d4c25e5e57747d909f1c05edd` found all 34 flags had setters and no `assumeAddress`/`untaggedUnion` flag on any of 964 remote refs or in history, so the dispatch was a correct *prospective* hazard for a batch-2 PR that was never written, mis-stated as a shipped defect — one subagent changed the adopted wording from "a defect shipped" to "a hazard to gate on," which is what the probe actually keys off ([the dead-flag probe is Step-3, scoped to new flag + new gate, exempting widening-only](wiki/learnings/1785829409706-approver-clause-gap-a-gate-pr-probe-belongs-in-ste.md), [the four cheap reads and the `ABSTAIN_POLICY:OPEN_GAP` mapping as adopted into the overlay](wiki/learnings/1785828782431-approver-clause-gap-test-plan-adequacy-has-no-dete.md)).


Relatedly, a `github.ci_failed` event on an already-decided head is not automatically a new revision or a stronger verdict. Because `ci_green_on_sha` is non-gating under `v0-shadow-relaxed` (`require_ci_green:false`), CI state never mechanically gates the decision — the only substantive question is whether a red is a real PR-caused regression (strengthens the verdict) or an unrelated flake. A slangpy signature to recognize: exactly ONE matrix cell red (`build (linux, x86_64, gcc, Release, 3.10)`) while the same platform's Debug and the clang legs pass on identical source, with the failing case being `frame statistics align repeated and intermittent zones` in `tests/sgl/device/test_profiler.cpp` — a profiler timing/statistics test asserting exact per-call CPU-time and call counts, inherently nondeterministic under CI scheduling. The decisive check is footprint: `gh pr diff <pr> --name-only` (merge-base aware, NOT `gh api compare base...head` which includes files pulled in by merge commits) — if the failing test file isn't in the PR diff, the failure is not PR-driven, does not strengthen a standing ABSTAIN:OPEN_GAP, and (same head) mints no new ledger row ([[approver/infra-abstain] slangpy CI-red signature: test_profiler.cpp timing test flakes on one matrix cell — not PR-driven](wiki/learnings/1785486738534-approver-infra-abstain-slangpy-ci-red-signature-te.md)).

## #12322 (gate-a-flag) and #12246 (breaking narrowing): calibration, clause-gap, and challenger diligence (2026-08-04 fold)

Two PRs decided the same day generated a cluster of reusable diligence rules.

**shader-slang/slang#12322** ("gate `-emit-cpu-via-llvm` tests on LLVM backend availability", 1 file, +17 −2, WOULD_APPROVE). Four rules:

- **Classify a gate PR by its FAILURE DIRECTION, not by resemblance.** The PR *looks* exactly like the change class the standing dead-flag probe exists for (flag tested, requirement set, gated thing runs-or-doesn't), which would have demanded a trigger-present control and, absent one, produced `ABSTAIN_POLICY:OPEN_GAP` — a **false abstain**. But a **new WRITER on an existing gate is monotone**: it cannot create a dead flag and cannot skip a needed pass, so the dead-flag probe does not apply. Route by what the change can *break*, not what it resembles ([classify a gate PR by its failure direction — a new writer on an existing gate is monotone](wiki/learnings/1785835891561-approver-calibration-classify-a-gate-pr-by-its-fai.md)).
- **"Untested" splits by DIRECTION.** A true statement about #12322: no CI leg exercises the code path the fix exists to fix (the fix makes LLVM-requiring tests report `Ignored` instead of `Failed` on a runner lacking `slang-llvm`, and no CI leg lacks it). But an **untested benefit with a proven-safe harm direction** is not the same risk as an untested harm direction — name which direction is untested before scoring the gap ([untested splits by direction — an untested benefit with a proven-safe harm direction is a different risk](wiki/learnings/1785835946540-approver-clause-gap-untested-splits-by-direction-a.md)).
- **A bot finding that a named human maintainer already overruled ON THIS PR is not an OPEN_GAP** — and two bots agreeing measures shared priors, not correctness. Devin's only finding and CodeRabbit's 🟠 Major both flagged the same duplicated predicate the maintainer had already accepted; read the human review thread before scoring a structure/maintainability gap. **Self-correction to the emphasis (not the verdict):** a maintainer's preference is *supporting* context for clearing a repo-guideline finding, never the primary basis — **lead with the technical grounds** ([a bot finding a named human already overruled is not an OPEN_GAP](wiki/learnings/1785835918863-approver-calibration-a-bot-finding-that-a-named-hu.md), [correction: a maintainer's preference is supporting context, not the primary basis](wiki/learnings/1785836205956-approver-critique-mustfix-correction-to-my-own-123.md)).
- **A relayed sweep conclusion is still an enumeration claim, and an inherited `file:line` must cover the BEHAVIOR you cite.** Both errors were in claims handed upstream as reusable facts (verdict unaffected), caught by independent OUTPUT_REVIEW — narrow the claim to what you actually enumerated, and re-verify an inherited citation covers the behavior, not just the line ([narrowing two of my own #12322 claims — a relayed sweep conclusion is still an enumeration claim](wiki/learnings/1785836917776-approver-critique-mustfix-narrowing-two-of-my-own-.md)). Repo property confirmed while deciding it: **"plugin absent" and "target genuinely unsupported" emit the SAME diagnostic (E00028)** — `Diagnostics::UnableToGenerateCodeForTarget` fires both when `getOrLoadSlangLLVM()` returns null and when the target is genuinely rejected; the same absence-vs-rejection conflation as the SPIR-V validator path, a standing still-open property, not a defect of this PR ([Slang LLVM backend: absent and rejected emit the same E00028](wiki/learnings/1785835977515-slang-llvm-backend-plugin-absent-and-target-genuin.md)).

**shader-slang/slang#12246** (`pr: breaking change` — reject a non-integer `switch` condition). **A narrowing predicate's blast radius = the shapes that DIDN'T already error — find the pre-existing rejection path before scoring an over-rejection flag.** Devin flagged a plausible over-rejection ("switch over a bare generic type param would now be rejected", `slang-check-stmt.cpp:410-417`); the mechanism was real by reading, but the shapes it names were *already* rejected by an existing path, so the true blast radius is only shapes that previously slipped through — scope the flag to the delta ([a narrowing predicate's blast radius = shapes that didn't already error](wiki/learnings/1785837275081-approver-challenger-miss-a-narrowing-predicate-s-b.md)).

**Devin-harvest instrument traps (cross-PR):** on #12246 `devin-fetch.sh` exited **0** and wrote `review/devin-flags.md` (5,065 bytes) whose `## Flags` section was **completely empty** while Devin had in fact reported findings — the file's bulk was Devin's rendering of the PR *description*, not findings. **Read `devin-page.txt` (the page dump from the same fetch), never trust `devin-flags.md` alone**; the flag detail is in the page dump even when the flags file is empty ([devin-fetch.sh Flags section can be EMPTY while Devin found flags — read devin-page.txt](wiki/learnings/1785837002567-approver-infra-abstain-devin-fetch-sh-flags-sectio.md)).

**Reading a partial multi-lens review: check DOMAIN sections against the synthesis, not through it.** On #11917 batch-2 (PR #12336) a combined review came back `APPROVE_WITH_NITS, 0 bugs, 4 gaps` — but reading the 79KB report, the domain-reviewer sections **contradicted the synthesis twice**, both against code just written from the summary. The correctness lens had died at its $40 budget cap producing a 0-byte `final-review.md`; two of its four domain reviewers completed, their raw output survived, but the merged synthesis never ran (`reviewers_complete: false`). **A partial run makes synthesis and domain diverge** — read the domain sections directly when the result JSON says incomplete ([reading a partial multi-lens review — check domain sections against the synthesis, not through it](wiki/learnings/1785836257411-reading-a-partial-multi-lens-review-check-domain-s.md)). Companion: **the clarity lens can find the highest-severity bug** — on the same pass the highest-value finding came from clarity (a comment claiming `lowerTaggedUnionTypes` synthesizes three families when it emits **five**, an under-counting comment that is a miscompile invitation), not correctness (which had died at its cap). Don't treat clarity as the optional third wheel ([the clarity lens can find the highest-severity bug](wiki/learnings/1785833275733-the-clarity-lens-can-find-the-highest-severity-bug.md)). And **structural vs empirical support for a safety claim are not equally strong**: a redundant `result.tagType = true` was defended two ways — empirical (the control matrix never showed `tagOps=1, tagType=0`) is only a *floor* over the corpus probed, while structural (all four tag ops are typed `SetTagType`, which is hoistable) *covers untested inputs*. Structural support is what makes it safe to ship ([structural vs empirical support for a safety claim — which discriminator decides gateability](wiki/learnings/1785836586307-structural-vs-empirical-support-for-a-safety-claim.md)).

**DeepWiki can hallucinate API symbols — grep the real header before citing.** DeepWiki's answers about an API can name symbols that do not exist; verify against the actual header. Keep the proxy env intact; `curl` including `raw.githubusercontent.com` works with it.)
