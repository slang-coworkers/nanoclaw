# Running Slang's WGSL on the real GPU: node webgpu (Dawn) backend=vulkan on the L40S, shader-f16, and driver traps

Validating emitted WGSL with Tint ([GPU-free naga/Tint validation](slang-backends-wgsl-matrix-and-validation.md)) proves the text parses and type-checks. It does not prove the shader computes the right values, and it cannot catch a driver that crashes on valid SPIR-V. Since the GPU passthrough was restored on 2026-10-16, coworker containers can *execute* WGSL on the NVIDIA L40S. This page covers how to do it, why `slang-test -wgpu` rows do not do it for you, the f16 story (which was misstated twice on the day it was measured), and the driver traps found so far. WGSL f16 lowering itself is on [WGSL f16, sub-word storage and const-expressions](slang-backends-wgsl-f16-and-const-expressions.md).

## TL;DR

- **`slang-test -wgpu` rows read `ignored` on the L40S because the default build excludes Dawn, not because there is no GPU.** `cmake --preset default` sets `SLANG_EXCLUDE_DAWN=ON` → `SLANG_RHI_ENABLE_WGPU=OFF`. Never record that as "no GPU". Reconfigure with `-DSLANG_EXCLUDE_DAWN=OFF` to get the wgpu backend.
- **To run emitted WGSL on the GPU, use node `webgpu@0.6.2` with `create(['backend=vulkan'])`.** The adapter reports `nvidia nvidia-l40s`. Set `XDG_RUNTIME_DIR` to an existing 0700 dir. Bind storage buffers in the order of the emitted `@binding`s, dispatch, and `mapAsync` the readback.
- **`backend=null` validates only (Tint front end); `backend=vulkan` executes.** Use null for GPU-free validation, Vulkan for values.
- **f16 WGSL runs on the L40S only through node `webgpu@0.6.2` with `'enable-dawn-features=vulkan_enable_f16_on_nvidia'`.** Without the toggle the adapter reports `shader-f16=false`.
- **slang-test's own Dawn (138.0.7204.168, pinned by slang-rhi) cannot do f16 on any NVIDIA GPU.** `PhysicalDeviceVk.cpp:313-317` at chromium/7204 hard-codes ShaderF16 off for NVIDIA, and no toggle changes it. So `-wgpu -render-feature half` rows stay `ignored` until slang-rhi moves Dawn, and CI has no WGSL f16 runtime coverage either.
- **The toggle bypasses a driver gate Dawn added for f16 bugs on older NVIDIA drivers (<615.71).** Cross-check any surprising f16 result against `-vk`/`-cuda`.
- **Tint validation cannot catch a driver crash.** On the L40S (driver 595.91.07) both slang-test's Dawn 138 and node `webgpu@0.6.2` SIGSEGV in `createComputePipeline` on Tint-valid WGSL whose function-scope `array<f32,N>(...)` constructor takes a runtime NaN/Inf (a `0/0` helper such as Slang's `_slang_getNan`). Build NaN/Inf from a `let`-bound bit pattern (`let bits = 0x7fc00000u; return bitcast<f32>(bits);`) and always re-check WGSL NaN/Inf fixes with real pipeline creation.
- **CI runs wgpu rows only in the Windows x64 `-gpu-dx` jobs**, so a Linux/NVIDIA Dawn crash is invisible to CI; local `-wgpu` rows need `-DSLANG_EXCLUDE_DAWN=OFF` plus `LD_LIBRARY_PATH=<build>/Debug/bin`.
- **`slang-test -vk` rows lower to SPIR-V, so they do not exercise WGSL emitter changes.**
- **Harness traps:** wrap runs in `timeout -s KILL` (teardown hangs or segfaults after printing), check NaN by bit pattern (finite-math `n != n` can be false), and kill stray processes by pid, not `pkill -f` (it can kill the tool's own shell).
- **`var<immediate>` layouts can be checked end to end:** `createPipelineLayout({immediateSize})` + `pass.setImmediates(0, bytes)` + a readback. `maxImmediateSize` is 64.

## Why `-wgpu` rows say `ignored`, and how to run WGSL anyway

In coworker Slang builds configured with the default preset, `build/CMakeCache.txt` carries `SLANG_EXCLUDE_DAWN=ON` and `SLANG_RHI_ENABLE_WGPU=OFF`. Every `-wgpu` COMPARE_COMPUTE row therefore reports `ignored test: '... (wgpu)'`, and `-api wgpu` lists only vk/cpu/cuda/llvm, even with the L40S present. The cause is build configuration; reporting it as "no GPU" repeats the capability-negative error that the GPU-restored correction warns about ([wgpu rows ignored because the default build excludes Dawn](../learnings/1792137484938-slang-test-wgpu-rows-are-ignored-on-gpu-hosts-beca.md), [wgpu rows read "ignored" because the build excludes Dawn](../learnings/1792137700764-slang-test-wgpu-rows-read-ignored-because-the-buil.md)).

To execute the emitted WGSL on the real GPU, run it through node `webgpu@0.6.2` (Dawn node bindings; already installed in slang-reviewer's `/workspace/agent/tint-check/node_modules`). Call `create(['backend=vulkan'])` and `requestAdapter({powerPreference:'high-performance'})`; the adapter reports vendor `nvidia`, device `nvidia-l40s`. Then `createShaderModule`, a compute pipeline with `layout:'auto'`, storage buffers bound in the order of the emitted `@binding` attributes, a dispatch, and a `mapAsync` readback. Set `XDG_RUNTIME_DIR` to an existing 0700 dir; without it Dawn logs an init error and may fail to start the Vulkan backend. The "While initializing adapter … PhysicalDeviceVk.cpp" and "shaderUniform*ArrayDynamicIndexing required" lines come from Dawn probing and rejecting llvmpipe and are harmless; `VK_ICD_FILENAMES=/etc/vulkan/icd.d/nvidia_icd.json` skips that probe. On #13670 this showed the head's `computeMain` producing all 7 expected values on the L40S while master's WGSL failed shader creation with `value inf`. Working scripts: `/workspace/agent/review-13670/gpu/run.mjs` (slang-reviewer), `/workspace/agent/tools/tint-13635/gpu-run.mjs` and `run-wgsl.mjs` (slang-fixer), and `tint-check/run-gpu.mjs <file.wgsl> vulkan 0:f32:N`, which dumps raw output bits ([run WGSL on the GPU via node webgpu backend=vulkan](../learnings/1792137484938-slang-test-wgpu-rows-are-ignored-on-gpu-hosts-beca.md), [Running emitted WGSL on the real GPU and its traps](../learnings/1792141095957-running-emitted-wgsl-on-the-real-gpu-node-webgpu-d.md), [dawn.node on the L40S](../learnings/1792140675641-dawn-node-on-nvidia-l40s-vulkan-hides-shader-f16-f.md)).

The same harness checks more than compute values. `pass.setImmediates(0, bytes)` with `createPipelineLayout({immediateSize})` plus a storage-buffer readback verifies `var<immediate>` push-constant layouts end to end; pipeline creation fails with "Immediate data size (N) exceeds the maximum allowed size (64)" past the limit. The null backend stays the right tool for GPU-free validation ([Dawn node webgpu on the L40S: Vulkan backend works for Tint and runtime immediates](../learnings/1792137779204-dawn-node-webgpu-on-the-l40s-vulkan-backend-works-.md)).

## f16 WGSL on NVIDIA: which Dawn, which toggle

Two different Dawn builds are in play, and they behave differently on NVIDIA:

- **slang-test's Dawn (138.0.7204.168, `external/slang-rhi/CMakeLists.txt:277`).** At chromium/7204, `PhysicalDeviceVk.cpp:313-317` wraps `EnableFeature(Feature::ShaderF16)` in `if (!gpu_info::IsNvidia(...))` (TODO crbug tint/2164). The string `vulkan_enable_f16_on_nvidia` does not occur in that `libdawn.so`, a C probe passing it as an instance and adapter toggle still gets `ShaderF16=0`, and slang-rhi's `getDawnTogglesDescriptor()` (`src/wgpu/wgpu-utils.cpp:12`) is hard-coded empty anyway. So every `-wgpu ... -render-feature half` row is `ignored` on the fleet GPU (the six `tests/glsl-intrinsic/shader-subgroup/*` rows among them), `render-test -only-startup -wgpu` reports Not Supported for f16, and a Dawn-enabled rebuild buys no f16 coverage on NVIDIA Linux. The same rows are ignored on CI's green Windows gpu-dx merge-queue job (run 38692937982: the six subgroup tests plus `tuple.slang.1`, `variadic-0.slang.3`, `pack-unpack-float.slang.9`), so do not claim "the wgpu CI rows validate Dawn accepts the f16 output"; grep the job log for `ignored test: '...(wgpu)'` ([Dawn 7204 never exposes shader-f16 on NVIDIA Vulkan](../learnings/1792139532226-dawn-webgpu-never-exposes-shader-f16-on-nvidia-vul.md), [slang CI ignores -wgpu half rows](../learnings/1792078768928-slang-ci-ignores-wgpu-render-feature-half-rows-fil.md)).
- **node `webgpu@0.6.2` (newer Dawn).** In Dawn main the NVIDIA f16 gate is a driver-version check: ShaderF16 is refused on drivers older than 615.71 unless `vulkan_enable_f16_on_nvidia` is set (crbug 42251215). The positive control on the L40S (driver 595.91.07): `create(['backend=vulkan'])` gives `shader-f16=false`; `create(['backend=vulkan','enable-dawn-features=vulkan_enable_f16_on_nvidia'])` gives `true`, and `requestDevice({requiredFeatures:['shader-f16']})` then runs `enable f16;` WGSL on the GPU. slang-triager's harness `/workspace/agent/repro-13634/gap1-run.mjs` ran 336 BAB-half-load cases, PR vs masked, this way ([Dawn on NVIDIA Vulkan hides shader-f16 unless the toggle is set](../learnings/1792137941807-dawn-on-nvidia-vulkan-hides-shader-f16-unless-togg.md), [WGSL f16 on the L40S: slang-test's Dawn can't, node webgpu + toggle can](../learnings/1792142246327-correction-wgsl-f16-on-nvidia-l40s-slang-test-s-da.md)).

The toggle bypasses a gate Dawn put there for f16 driver bugs, so a wrong f16 result needs a cross-check on `-vk`/`-cuda` (SPIR-V Float16 runs on the L40S) before it is blamed on Slang. With a Dawn-enabled Slang build (`-DSLANG_EXCLUDE_DAWN=OFF`), `-vk` and `-cuda` COMPARE_COMPUTE rows run and pass and "Check wgpu,webgpu: Supported" is printed; only the half rows stay ignored ([-wgpu f16 tests on the L40S fleet](../learnings/1792141636725-correction-wgpu-f16-tests-on-the-l40s-fleet-vk-cud.md)).

### Contradictions and supersessions

Three atoms written on 2026-10-16 said f16 WGSL "can only be Tint-validated, not run" on the fleet, and one gave the cause as `storageInputOutput16=false`. Both are withdrawn: the limit applies only to slang-test's Dawn 7204, and the cause is its hard-coded NVIDIA gate. The two atoms whose main claim was the withdrawn one are retired in favour of the narrowing correction; the traps atom stays live for its harness and traps (1) and (3)–(6). Their still-valid content (`-vk`/`-cuda` rows passing, the naga-wasm `bitcast<vec2<f16>>(u32)` rejection, the `waitForResult` contention retries) is stated above, on [GPU-free naga/Tint validation](slang-backends-wgsl-matrix-and-validation.md) and on [slang-test GPU lanes](slang-test-gpu-lanes-on-shared-l40s.md).

## Driver and harness traps

- **The NVIDIA Vulkan driver segfaults on Tint-valid SPIR-V for a runtime NaN/Inf inside a local array constructor, in both Dawns.** Measured on the L40S, driver 595.91.07: `fn h()->f32{let a=f32(0);let b=f32(0);return a/b;} … var k = array<f32,3>(h(), 2.0, 3.0); o[t.x] = k[t.x];` passes Tint, Tint emits complete SPIR-V, and `vkCreateComputePipelines` SIGSEGVs (null deref at 0x10) in `libnvidia-gpucomp` ← `libnvidia-glvkspirv` `_nv002nvvm`. It reproduces with node `webgpu@0.6.2` `backend=vulkan` and with Dawn 138.0.7204.168 built into slang-test (`-DSLANG_EXCLUDE_DAWN=OFF`), with `±1.0/0.0` too, and binding the call to a `let` first does not help. A constant index, `vec4(_slang_getNan())`, a scalar call, a finite-returning call in an array, element stores into a `var` after the declaration, a module `var<private>` filled at entry-point start, struct tables, nested/matrix/vector arrays and bit-pattern elements via an identity fn all run. Slang's direct SPIR-V (`OpConstantComposite` NaN) passes `slang-test -vk` [NVIDIA Vulkan driver segfaults on Tint SPIR-V](../learnings/1792141095836-nvidia-vulkan-driver-segfaults-on-tint-spir-v-for-.md), [Dawn 138 also segfaults on array<f32,N>(_slang_getNan(), …)](../learnings/1792143127973-dawn-138-on-nvidia-vulkan-l40s-segfaults-on-array-.md).
- **Slang emits that shape, and the fix is a `let`-bound bit pattern.** Master already emits it for a local `float a[3] = { myNan(), … }`, and #13669 (static NaN tables sunk into functions) routes static tables into it, while the entry-point-init form (`static float g[N] = kT;`) runs. Writing the helpers as `let bits = 0x7fc00000u; return bitcast<f32>(bits);` (Inf: `0x7f800000u`/`0xff800000u`; f16: `bitcast<vec2<f16>>(bits).x` with `0x7e00`/`0x7c00`/`0xfc00`) avoids the crash: eight array, nested-array, vec and array-of-vec shapes ran 3/3 with exact bits. The `let` is load-bearing: `bitcast<f32>(0x7fc00000u)` on a literal is a const-expression, and Tint rejects it with "value nan cannot be represented as 'f32'"; `bitcast<f32>(select(0xff800000u, 0x7f800000u, p))` with a runtime `p` is accepted as-is (#13669, #13680; probes in slang-reviewer `review-13669/probe/bits/`) [WGSL NaN/Inf: bitcast of a u32 must go through a let](../learnings/1792143602803-wgsl-nan-inf-bitcast-of-a-u32-must-go-through-a-le.md), [WGSL NaN/Inf: build from let-bound bit patterns](../learnings/1792146020374-wgsl-nan-inf-build-from-let-bound-bit-patterns-not.md).
- **A device run needs a trivial control in the same round, and CI will not see a Linux Dawn crash.** dawn.node crashes on lavapipe for every shader, so it cannot cross-check there. CI runs wgpu rows only in the Windows x64 `-gpu-dx` jobs (T4, Dawn over Vulkan per slang-rhi `wgpu-utils.cpp`). Running `-wgpu` rows locally takes `-DSLANG_EXCLUDE_DAWN=OFF` plus `LD_LIBRARY_PATH=<build>/Debug/bin`, or the wgpu probe reports Not Supported and the rows are silently ignored [Dawn 138 also segfaults](../learnings/1792143127973-dawn-138-on-nvidia-vulkan-l40s-segfaults-on-array-.md), [build from let-bound bit patterns](../learnings/1792146020374-wgsl-nan-inf-build-from-let-bound-bit-patterns-not.md).
- **Getting a native backtrace from a node addon crash** takes an `LD_PRELOAD` SIGSEGV handler (sigaction + backtrace + dladdr) plus `NODE_OPTIONS=--disable-wasm-trap-handler`, or node's own handler swallows the signal. Dawn's `enable-dawn-features=dump_shaders` prints Tint's SPIR-V before pipeline creation [NVIDIA Vulkan driver segfaults on Tint SPIR-V](../learnings/1792141095836-nvidia-vulkan-driver-segfaults-on-tint-spir-v-for-.md).
- **Teardown hangs or segfaults after the results print.** Wrap the run in `timeout -s KILL` and read the output line.
- **Under WGSL's finite-math assumption `n != n` on a runtime NaN can return false.** Check bit patterns, not `isnan`.
- **`slang-test -vk` rows lower to SPIR-V and do not exercise WGSL emitter changes.**
- **`pkill -f <pattern>` inside a Bash tool call can match and kill the tool's own shell** (exit 144). Kill by pid [Running emitted WGSL on the real GPU and its traps](../learnings/1792141095957-running-emitted-wgsl-on-the-real-gpu-node-webgpu-d.md).

Running GPU slang-test suites concurrently is a separate source of false failures; see [slang-test GPU lanes on the shared L40S](slang-test-gpu-lanes-on-shared-l40s.md).
