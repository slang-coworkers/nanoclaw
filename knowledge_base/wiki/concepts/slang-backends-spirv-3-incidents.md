# Slang Backends Spirv 3 Incidents

## TL;DR
- SPIR-V symptoms usually trace upstream (IR pass, capability set, core-module producer, downstream tool), not to emit. Verify a triage premise at HEAD with a freshly REBUILT binary before fixing on it.
- `[require]` atoms and capdef atoms never emit `OpCapability`/`OpExtension`. They model floors and dependencies only. Emission is always explicit emitter C++ (`ensureExtensionDeclaration`) or an inline `spirv_asm` declaration.
- Entry-point `[require]` never reaches `getTargetCaps()`, the codegen cap set, or `specializeTargetSwitch` (#11631). It silently diverges on codegen-decision paths; honoring it needs per-entry-point specialization, not an emit patch.
- Emitted SPIR-V version = max over target format + explicit `-profile`/`-capability` + public `spirv_1_x` require-decorations; a used function's `[require]` chain never raises it, and a GLSL-family profile implies a floor, not a pin.
- A SPIR-V validation fix needs a `-target spirv` test so spirv-val runs. A spec saying "requires X" does not mean bundled spirv-val enforces X; run the counterfactual.
- A NEW capdef atom (not a floor edit) triggers `check-cmdline-ref` and `check-capability-atoms-ref`. Wait for both to go green.
- A capability that depends on operand constness → a new backend IR op. Slang does not iterate inside `spirv_asm` blocks.
- Signature-derived capabilities (VariablePointers) gate on `[noinline]`, not `hasUses()`.
- Direct SPIR-V emits `NoContraction` only for `-fp-mode precise` (v2026.13+). In default mode the `precise` qualifier is still ignored (#12198); a full fix must propagate precise-ness to compiler temps.
- For `precise`, the reference compilers (DXC→DXIL, DXC→SPIR-V, glslang) disagree at call boundaries, so name the backend you match. Slang's `computePreciseInsts` walk stops at `spirv_asm` intrinsics (`dot`, `mul`, `mad`), loses the decoration in CSE, and over-marks stores sharing a buffer root. Count `OpDecorate .* NoContraction`, not a bare grep.
- Stale-version triage: count the symptom on the reporter's version and on HEAD, then run `git merge-base --is-ancestor <fix> <release-tag>`. If it is already fixed, resolve without a PR.
- Internal `spirv_asm` registers get an auto-`OpName`; prefix them `__` with a brace-tracked, block-scoped rename that also covers `slang-core-module-textures.cpp`.
- In `spirv_asm`, `__entryPoint` is special-cased only for `OpExecutionMode` (emitted once per referencing entry point). `OpExecutionModeId __entryPoint` ICEs (E99997); write `OpExecutionModeId $main <Mode> $specConst` inside each entry point. Direct SPIR-V only.
- `-dump-ir` misses early-lowering insts and all SPIR-V legalize/emit mutations. Disassemble for late questions; check the specific operand, not a whole-dump grep.
- The per-use descriptor `OpLoad` (#12051) is emit strategy, not a SPIR-V rule. Coalescing a dominating read-only `UniformConstant` load is safe even for a divergent index: per-lane divergence is not per-iteration variance (#12111).
- Inlined and `[noinline]` shapes answer cross-call questions differently, so test the exact shape. Label SPIR-V operands from `OpTypeFunction`, never by source position.
- The NonUniform mark is lost through the DescriptorHandle Cast round-trip and through arithmetic into a callee (`findNonuniformIndexInst` owns call args; the float pass, same-function). Keep one shared propagating-op predicate; walk with a worklist + visited set.
- The float pass's SPIR-V-only cases are by design. Textual targets treat NonUniform as a hint; SPIR-V needs it on the exact index.
- `spirv-opt` never CSEs `OpGroupNonUniform*`. Dedup wave ops in Slang IR with a participation-fenced block-local pass, never via `isMovableInst`.
- A logical-address-space pointer may not be a composite operand, and VariablePointers does not help. Only physical pointers are legal in a struct.
- spirv-opt / `-O0` behaviour (the #11805 default, `-O3` asserts, #12160 reassociation): see [slang-backends-spirv-4-incidents](slang-backends-spirv-4-incidents.md).

## Capabilities, extensions, and the version header

**Inline capability for `spirv_asm` builtin loads.** `RayCurrentTime()` emitted `BuiltIn CurrentRayTimeNV` with no `OpCapability RayTracingMotionBlurNV`, so spirv-val rejected the module. Declare the capability inline in the `spirv_asm` block ([[require] doesn't emit OpCapability](../learnings/1782828754941-require-capability-atom-does-not-auto-emit-opcapab.md)). Test such a validation fix with a real `-target spirv` directive, because a `spirv-asm`-only check can pass without validating ([validation fixes need -target spirv](../learnings/1782833127380-spir-v-capability-validation-fixes-need-a-target-s.md)).

**Capdef atoms never emit.** `determineSpirvVersion()` reads atoms only for the version floor and a few flags; every `OpExtension` comes from a hand-written `ensureExtensionDeclaration("SPV_...")`, and `-capability SPV_EXT_physical_storage_buffer` alone emits nothing. `SPV_KHR_physical_storage_buffer` is only an emit string, not a capdef atom ([capdef atoms never auto-emit an OpExtension](../learnings/1784120354355-slang-capdef-atoms-never-auto-emit-an-opextension-.md)).

**SER at SPIR-V 1.4 (#12097 → PR #12115).** Bundled spirv-val ACCEPTS 1.4 SER without PSB (the triage claim was false); PSB is still declared, for spec-correctness. The shipped fix has two parts: the capdef floor `_spirv_1_5`→`_spirv_1_4`, and `SPV_KHR_physical_storage_buffer` declared centrally in `requireSPIRVCapability` ([SER at 1.4 without PSB: spirv-val accepts it](../learnings/1784102979347-correction-spir-v-ser-at-1-4-without-psb-bundled-s.md)). Capability-floor PR checklist: added atom floors ≤ target; the guard reads effective `m_spvVersion`, not the profile; `ensureExtensionDeclaration` is idempotent; memory model stays `Logical GLSL450`; a spirv-val test ships ([SER 1.4 fix #12115: floor + PSB OpExtension both required](../learnings/1784139502358-approver-confirmed-safe-ser-spir-v-1-4-fix-12115-c.md)). A NEW atom changes `slangc -h` and the a4-02 reference, so query both ref check-runs at the pinned head ([new capdef ATOM trips both ref checks](../learnings/1784139517684-approver-clause-gap-new-capdef-atom-not-just-floor.md)).

**Emitted version.** `determineSpirvVersion` (slang-ir-spirv-legalize.cpp ~2482) takes a max over `getTargetCaps()` (format + explicit profile/capability) plus public `spirv_1_x` require-decorations. SER's internal `_spirv_1_5` is not matched, so a TraceRay shader under `-profile spirv_1_4` still emits 1.4. Build and run; don't infer ([[require] doesn't drive the version header](../learnings/1784157894453-entry-point-require-caps-do-not-drive-the-emitted-.md)). A `-profile` pins a version only when its family matches the target: use `profile.getFamily()`/`getVersion()` gated by `isSPIRV(format)`, not `isKhronosTarget`. `glsl_450` implies a 1.3 floor, not a pin ([GLSL-family -profile doesn't pin](../learnings/1784157903315-a-glsl-family-profile-does-not-pin-a-spir-v-output.md)).

**`[require]` never reaches codegen (#11631).** Entry-point `[require(...)]` atoms never update the SPIR-V codegen cap set; the version path partly compensates, bindless does not ([[require] never reaches codegen cap set](../learnings/1781638061693-slang-require-capabilities-never-reach-codegen-cap.md)). Severity: a silent SS-class runtime divergence on codegen-DECISION caps only, never invalid SPIR-V ([#11631 severity](../learnings/1781686744418-slang-11631-severity-require-drop-is-a-silent-runt.md)). The bindless half: `specializeTargetSwitch` selects the bindless-vs-descriptor-heap accessor from *global* `getTargetCaps()` at module-link scope. The `implies(spvBindlessTextureNV)` gates in spirv-legalize/emit are downstream consumers ([bindless path is selected at specializeTargetSwitch](../learnings/1784780629812-slang-bindless-descriptor-heap-path-is-selected-at.md)). `[require]` lowers to an `IRRequireCapabilityAtomDecoration` that is never unioned into target caps. A version-scan-style emit fix would produce incoherent `uint64`-typed/`uint2`-accessed SPIR-V, so the fix is per-entry-point reachability specialization (#12196) ([entry-point [require] never reaches specializeTargetSwitch](../learnings/1784782055293-slang-12196-entry-point-require-never-reaches-spec.md)).

**Constness-conditional capability (#9382).** A constant `Gather` offset must use `ConstOffset` with no capability, while a runtime offset needs `Offset` + `ImageGatherExtended`. Maintainer rule: replace the `*.meta.slang` body with a new backend IR op that decides constness and capability; never iterate inside `spirv_asm` ([constness-conditional capability → new backend IR op](../learnings/1784164953340-conditional-spir-v-capability-by-operand-constness.md)).

**Signature-derived VariablePointers.** A capability derived from a signature type must gate on the function surviving inlining: check `[noinline]` via `findDecoration`, not `hasUses()`, or VariablePointers is over-declared (driver bug #9061) ([VariablePointers must gate on [noinline]](../learnings/1781023718622-signature-derived-spir-v-variablepointers-must-gat.md)).

**Builtin-var Flat gate (#12064).** Prove else-branch reachability from the callers' asserts. `getBuiltinGlobalVar` asserts a pointer type, so the non-pointer branch is reachable only for `SPIRVAsmOperandBuiltinVar` (always BuiltinInput). An `IRGlobalParam` CAN be non-pointer; only `IRGlobalVar` is always a pointer ([Flat gate reachability](../learnings/1783767618309-approver-challenger-spir-v-builtin-var-flat-gate-p.md)).

## HitObject SM6.9+NVAPI (#11903): verify the premise at HEAD

The triage claimed PR #11889's `implies(hlsl_nvapi)` guard is inert on sm_6_9; an instrumented, rebuilt slangc showed `implies(nvapi)=1`, so the fix was a no-op. Revert-drill the predicate, print the actual value, and don't repeat a triage's sub-claims ([verify a triage premise at HEAD](../learnings/1782991917563-verify-a-triage-s-predicate-premise-at-head-revert.md)). The wrong read came from a prebuilt pre-#11889 binary. Rebuild after any source refresh; don't trust `slangc -v` on incremental builds. The real bug is an ABI gap: the native-only 2-arg `HitObject::Invoke` binds `dx::HitObject::Invoke(NvHitObject)`, while NVAPI's Invoke takes 3 args ([CORRECTION: real bug is 2-arg Invoke ABI gap](../learnings/1782992753685-correction-slang-hitobject-sm6-9-nvapi-refutes-my-.md)).

## NoContraction and `precise` on direct SPIR-V

`slang-emit-spirv.cpp` never emitted `NoContraction`, so `-fp-mode precise` did nothing on `-target spirv` (#11933) ([direct SPIR-V emitter never emits NoContraction](../learnings/1783064216848-slang-direct-spir-v-emitter-never-emits-nocontract.md)). PR #11935 fixed this by emitting it at the `emitArithmetic` choke point ([emit NoContraction at emitArithmetic](../learnings/1783067747847-slang-direct-spir-v-emit-nocontraction-for-fp-mode.md)).

**Stale-version dup (#12285).** A report that "precise compensated summation is wrong unless the helper is `[noinline]`" on v2026.12 is a dup of #11933: fix commit `33f9ed0c` first shipped in v2026.13. Method: count the symptom on the exact repro (`grep -c NoContraction`: 0 on 2026.12, 32 at HEAD); run `git merge-base --is-ancestor <fix> <tag>`; refute the per-function theory (fp-mode is target-scoped; `[noinline]` "worked" only because `OpFunctionCall` is a driver optimization barrier). Resolve without a PR. `NoContraction` belongs on the surrounding `OpFAdd`s, not on a fused `Fma` ([#12285 = stale-version dup of #11933](../learnings/1785415514440-12285-stale-version-dup-of-11933-spir-v-precise-no.md)).

**`precise` qualifier in default fp-mode (#12198, still open, distinct from #12285).** It produces 0 `NoContraction` and spirv-opt reassociates, because `isFloatingPointModePrecise` reads only the global `-fp-mode` and never reads `IRPreciseDecoration`. `-O0` preserves order and `-fp-mode precise` yields 16 `NoContraction`, so that is the lever. `IRPreciseDecoration` sits only on directly qualified insts, not compiler temps, so a complete fix propagates precise-ness backward through the FP fan-in before `maybeEmitNoContraction` ([precise ignored in default fp-mode](../learnings/1784785437426-precise-qualifier-ignored-on-direct-spir-v-in-defa.md)). For the downstream reassociation itself (#12160), see [slang-backends-spirv-4-incidents](slang-backends-spirv-4-incidents.md).

**Reference compilers disagree on `precise`, and Slang's `computePreciseInsts` walk has three gaps (#13324).** Measured 2026-09-29 with the in-tree compilers: DXC→SPIR-V by dlopen-ing `build/Release/lib/libdxcompiler.so` (it has SPIR-V CodeGen) and calling `IDxcCompiler3` with `-spirv -O0 -fcgl`; DXC→DXIL via `slangc -pass-through dxc -target dxil-asm`; glslang via `glslang_compile_1_2` in `libslang-glslang` (harnesses `dxcspv.cpp`/`gl2.cpp` in `/workspace/agent/scratch-13324`). At call boundaries the references disagree. When a caller's `precise` result comes from a non-inlined callee, only DXC→DXIL marks the callee's math (it has inlined by then); glslang and DXC→SPIR-V leave it unmarked. A callee's `precise` local marks the caller's argument math in both DXC backends but not in glslang. DXC→DXIL also ignores `precise` on static/groupshared globals, a helper's `out precise` param, a helper's `precise` return type, and a reassigned `precise in` param, all of which DXC→SPIR-V and glslang honor. So "match DXC" is not one target; name the backend. In Slang (master 214064dd1) the backward walk `computePreciseInsts` dead-ends at intrinsics lowered via `spirv_asm` (`dot`, `mul`, `abs`, `mad`→Fma), so `dot(a*b+c, d)` gets 0 `NoContraction` where DXC gets 3, and its op filter also excludes `OpDot`, `OpMatrixTimes*` and `OpVectorTimesMatrix`. CSE drops the decoration (`removeAndDeallocate` in `slang-ir-redundancy-removal.cpp` does not transfer it). And the walk goes from a load to the buffer root and then to every store into that buffer, so unrelated outputs in the same `RWBuffer` get marked; tests need separate in/out buffers. Counting pitfall: spirv-asm output also comments `; NoContraction` on instruction lines, so count `OpDecorate .* NoContraction`, not a bare grep ([precise/NoContraction: reference compilers disagree at call boundaries; Slang's walk dead-ends at spirv_asm intrinsics](../learnings/1790706758785-precise-nocontraction-reference-compilers-disagree.md)). For `precise` lost on entry-point out params and struct fields (#13287), see [slang-backends-glsl](slang-backends-glsl.md).

## `spirv_asm` register names leak as OpName (#12002, #12108)

**#12002 (PR #12053).** A "misattributed OpName" turned out to be a stdlib register name collision. The fix renamed the internal register `%sampled`→`%__sampled` at 94 sites and added a `CHECK-NOT: "sampled"` test. Rename-drill decides such claims: rename the user's variable; if the OpName follows it propagates, if it stays it is intrinsic-baked. Lead a public verdict with the refutation, then give the real defect. Gating the auto-OpName loop is maintainer scope ([#12002 refute-then-fix](../learnings/1783746988745-slang-12002-shipped-refute-then-fix-triage-of-a-mi.md)).

**#12108 generalization.** Scope covers `hlsl.meta.slang` and also `glsl.meta.slang` (53 un-prefixed sites), plus a build assert. Re-pin stale line numbers; it is maintainer-driven, so stand down ([#12108 scope spans hlsl AND glsl](../learnings/1784248363961-slang-12108-triage-spirv-asm-prefix-cleanup-scope-.md)). A file-wide sed is unsafe because the same `%result`/`%6` tokens live in `__intrinsic_asm` LLVM/Metal strings. Rename only inside brace-tracked `spirv_asm{}` ranges, and skip `$name`, integer ids, and already-prefixed names. `slang-core-module-textures.cpp` (`writeGetDimensionFunctions`) is a second generator ([renaming spirv_asm registers: block-scoped only](../learnings/1784760040459-renaming-spirv-asm-registers-in-meta-slang-block-s.md)).

## `spirv_asm` execution modes: `__entryPoint` works only for `OpExecutionMode`

In `spirv_asm`, `OpExecutionMode __entryPoint <Mode> ...` is special-cased (`slang-emit-spirv.cpp` ~11924): it is emitted once for EVERY entry point that references the enclosing function, so it works from a shared helper. `OpExecutionModeId` is not special-cased. It takes the generic path, where `__entryPoint` hits `SLANG_UNREACHABLE` "Unhandled case in emitSPIRVAsm" (E99997). For Id modes such as `OpacityMicromapIdKHR`, write `OpExecutionModeId $main <Mode> $specConst` inside each entry point: `$main` is an ordinary function-value reference emitted verbatim, and a `[vk::constant_id(N)] const bool` referenced as `$name` becomes an `OpSpecConstant` with SpecId that spirv-val accepts as the Id operand. This works on direct SPIR-V only; `-target glsl` and `-emit-spirv-via-glsl` ICE on these blocks ("unexpected IR opcode" / "circularity during codegen"). DeepWiki says `__entryPoint` works for execution modes and is tested; that is wrong for `OpExecutionModeId`, and `tests/` has no such test (#13438, master 6ba151dcf) ([spirv_asm OpExecutionModeId: $entryName works, __entryPoint ICEs](../learnings/1791207151155-spirv-asm-opexecutionmodeid-entryname-works-entryp.md)).

## #12051 / PR #12111: DescriptorHandle descriptor-load coalescing

**Reload is an emit artifact.** With `Texture2D tex = texH;` sampled 3×, HLSL loads once but SPIR-V emits 3 `OpLoad` from one `OpAccessChain`; `pinDescriptor()` (`OpCopyObject`) collapses them to 1, which proves a single load is valid. Tooling: with a bare Debug build, `-target spirv-asm` needs a RELEASE `libslang-glslang-*.so` on `LD_LIBRARY_PATH` ([descriptor reload is an emit-time artifact](../learnings/1783759451138-slang-12051-spir-v-descriptor-reload-is-an-emit-ti.md)). On the default path the generic IR holds one shared `getElement(__slang_resource_heap, index)`. The per-use `OpLoad` comes from `legalizeIRForSPIRV` + the emit walk after the last `-dump-ir` snapshot, not from `shouldDuplicateInstAtUseSite`. The lever is therefore emit/legalize: materialize one load when its def dominates the uses ([CORRECTION: emit-time OpLoad-per-use](../learnings/1784075115135-correction-slang-12051-spir-v-descriptor-reload-is.md)).

**Why the existing redundancy pass misses it.** `legalizeIRForSPIRV` runs `legalizeSPIRV` first (which inserts the loads) and then `simplifyIRForSpirvLegalization` → `removeRedundancyInFunc`. Ordering is not the reason; `isMovableInst`'s `kIROp_Load` case accepts only CB/ParameterBlock pointers. `CastDescriptorHandleToResource` (the lowering only for `spvBindlessTextureNV`) is not movable; `CastDynamicResource` is ([legalize pass ordering](../learnings/1784269362740-slang-12111-spir-v-legalize-pass-ordering-removere.md)).

**The NonUniform guard was unnecessary.** At `insertLoadAtLatestLocation` uniform and divergent IR are identical: the heap index has no `NonUniformResourceIndex` and no `IRSPIRVNonUniformResourceDecoration`, and the `isNonUniform` at `:690` belongs to the plain resource-array path. A plain `Texture2D t[16]` keeps its decorations; only the heap path loses them ([divergent NonUniform marker stripped before legalize](../learnings/1784081063099-slang-12051-descriptorhandle-divergent-nonuniform-.md)). Coalescing is correct: per-lane divergence is not per-iteration variance, `spvDescriptorHeapEXT` already emits 2 loads with 0 NonUniform and validates, and the missing hint is a documented gap (`desc-heap-nonuniform.slang:8-12`). So Option A drops the guard, and NonUniform preservation is a separate follow-up (#12110). Before calling a plan's guard mandatory, verify that the signal it reads exists at the fix site ([option-a: the invariance guard was over-specified](../learnings/1784081353064-slang-12051-option-a-the-invariance-guard-was-over.md)). The precise mechanism: the mark exists early (`%34 = nonUniformResourceIndex(%33)`). `makeVector` → `CastUInt2ToDescriptorHandle` → `CastDescriptorHandleToUInt2` → `swizzle` then re-extracts the index unmarked. A whole-dump `grep -c` is inflated by the capability-atom name ([CORRECTION: the Cast round-trip drops the mark](../learnings/1784083614756-slang-12051-correction-descriptorhandle-nonuniform.md)). `-dump-ir`'s first snapshot (`AFTER validateAndRemoveAssumeAddress`) is already past early lowering, so the dump is blind at both ends ([REFINEMENT: -dump-ir starts too late](../learnings/1784083913871-refinement-slang-12051-the-nonuniform-marker-exist.md)).

**Safe shape for SPIR-V-legalize CSE/coalesce PRs:** the shared load dominates by construction (`setInsertAfter(subAddr)`), the change is decoration-neutral, and scope follows the read-only `UniformConstant` invariant, not a builtin-name gate ([UniformConstant load-coalescing is a safe shape](../learnings/1784126649253-approver-confirmed-spir-v-uniformconstant-load-coa.md)).

**`[noinline]` and the #12027 workaround.** Inlined and `[noinline]` helpers answer differently. With `[noinline]`, a resource passed as a loaded descriptor value is loaded caller-side, and #12111 coalesces those loads N→1 across the call. #12027 passes an IMAGE across a call as a `%uint` bindless index and a SAMPLER as a real descriptor. A change is a regression only if the image parameter flips from `%uint` to `OpTypeImage` ([load-coalescing vs [noinline] + #12027 workaround](../learnings/1784128384354-slang-12051-12111-descriptorhandle-load-coalescing.md)). After two mislabeled public answers: resolve operand roles from the raw `OpTypeFunction` / `OpFunctionParameter` / type-def lines, never from source position ([image passes as uint INDEX, sampler as real descriptor](../learnings/1784128407283-slang-bindless-noinline-image-passes-as-uint-index.md)).

## NonUniformResourceIndex propagation

**DescriptorHandle round-trip (PR #12116, #12161).** The float pass (`slang-ir-float-non-uniform-resource-index.cpp`) adds SPIR-V-gated `kIROp_CastUInt2ToDescriptorHandle` and `kIROp_MakeVector` cases. They float the wrapper to the heap index, fixing VUID-RuntimeSpirv-None-10148 on the default heap path. The flagged `if (floatMode != SPIRV) break;` asymmetry follows the file-header contract (textual = hint; SPIR-V `OpDecorate NonUniform` is position-specific). Verdict: APPROVE_WITH_NITS ([#12116 guard asymmetry is a nit](../learnings/1784536684181-slang-12116-nonuniform-float-pass-guard-asymmetry-.md)). On HLSL/GLSL the mark lands nested in `uint2(...).x`. Whether DXC/glslang honour it is GPU-only: hold for hardware verification and gate any textual fix on a failing downstream test ([textual targets: nested in uint2(...).x by design](../learnings/1784539603707-nonuniform-on-descriptorhandle-round-trip-lands-ne.md)).

**Through arithmetic (#13072).** The spelling `buffers[NUR(i)*i][0]` / `.Load(...)` lowers to a CALL. The float pass floats the mark through `mul`, but the mark dead-ends at the call argument. The real gate is `findNonuniformIndexInst` in `slang-ir-specialize-function-call.cpp`, which walked only `IntCast`. The float pass's arithmetic path runs only for same-function access (e.g. `arr[NUR(i)*i][0] = v`). Dump IR to find the real layer; use a worklist + visited set (naive recursion took >10 s on a 29-node `v=v+v` chain); re-insert the mark with `newParam->getFullType()`; keep one `isNonUniformIndexArithmeticOp` predicate ([NUR through arithmetic: fix is in the specializer](../learnings/1789465468604-nonuniformresourceindex-through-arithmetic-fix-is-.md)).

## spirv-opt will not CSE `OpGroupNonUniform*`

Both CSE passes use `ValueNumberTable`, which gives every non-combinator a fresh value number; `AddCombinatorsForCapability` lists no group/subgroup/ballot op. A group op depends on the active-lane set, so CSE/hoist would be unsound. Dedup ops such as `WaveActiveCountBits` + `WavePrefixCountBits` (both emit `OpGroupNonUniformBallot`) in Slang IR with a participation-fenced block-local pass (PR #12848). Do not add them to `isMovableInst` ([spirv-opt won't CSE OpGroupNonUniform*](../learnings/1789578103315-spirv-opt-won-t-cse-opgroupnonuniform-they-re-non-.md)).

## Logical-address-space pointer as a struct field (#13206)

A struct whose field is a `Ptr<T, Access, GroupShared/Function/Private>` emits an `OpCompositeConstruct` that carries a logical pointer. slangc is silent (rc=0); only spirv-val rejects it. VariablePointers is already declared and doesn't help; only `PhysicalStorageBuffer` pointers are legal in a composite. Path: a partial field write → SSA aggregate → `emitMakeStruct`. No SROA pass or diagnostic exists; `specialize-address-space` only re-types slots (#13039). Same class as #9062. A fix needs a recursive "contains-a-logical-pointer" predicate covering copies, returns, and phis, with a front-end diagnostic as the fallback ([logical Ptr as struct field](../learnings/1790017243652-logical-address-space-ptr-as-a-struct-field-invali.md)).
