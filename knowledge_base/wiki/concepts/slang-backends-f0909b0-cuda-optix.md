# CUDA / OptiX backend

CUDA/OptiX backend facts, mostly around ray tracing, the NVRTC-compiled prelude, and GPU-free verification.

## TL;DR

- **OptiX payload register count is the separate `payloadSize` operand, NOT the `_optix_trace_typed_32` name**, which is emitted for every payload size; grep the `payloadSize` immediate. The prelude's `optix*WithRegs` fixed-width `N<=16`/`N<=32` catch-alls over-read/over-write for N in [9,15] AND [17,31].
- **An `inout` ray payload is legalized TWICE** (VaryingInput + VaryingOutput) and a direction-agnostic `case RayPayload:` double-reads the registers; the reads survive DCE because `kIROp_GetOptiXPayloadRegister` is side-effecting. Fix the producer; don't mark it pure.
- **Hit attributes are field-wise (one 32-bit register per scalar leaf), not byte-packed.** `ReportHit` must gather leaves into ONE `optixReportIntersection` call and emit `__float_as_uint` explicitly (CUDA `kIROp_BitCast` is a numeric cast).
- **HLSL ray flags pass verbatim into `optixTrace`.** Only `SKIP_TRIANGLES`(0x100) and `SKIP_PROCEDURAL_PRIMITIVES`(0x200) lack an OptiX equivalent (0x400 maps); key a diagnostic off the named `OptixRayFlags` set (supported = 0x4FF), not `>=0x100`.
- **`OptixRayFlags` bits 0–7 are identical in OptiX 7.0–9.1; the 0x400 OMM flag first appears in 7.6.0**, so named emission needs `#if OPTIX_VERSION >= 70600`. A long-lived draft adding a `slang-diagnostics.lua` entry must re-check its code against master before rebasing.
- **Lower shader-record (SBT) globals to an opaque intrinsic only after `specializeResourceUsage` and the global-init move.** Earlier, a `ConstantBuffer<T>` helper param stays unspecialized and gets `__ldg` (#10188), `expand` bodies crash, and reference graphs miss generic calls and the static initializers CUDA injects into EVERY entry point.
- **On CUDA, GeometryIndex is the OptiX SBT GAS index** (HitObject since SER; pipeline `GeometryIndex()` since PR #13437 via `optixGetSbtGASIndex()`, OptiX >= 7.1). It equals the DXR ordinal only under slang-rhi's one-record-per-input layout.
- **All of `slang-cuda-prelude.h` goes to NVRTC verbatim**, so an OptiX helper using an SDK-N symbol without `#if (OPTIX_VERSION >= NNNNN)` breaks ALL RT shaders on older SDKs. Resolve thresholds from `external/optix-dev` tags (7.x decls in `optix_7_device.h`), verify with nvcc. The OptiX block is compiled only for RT-stage entry points, so a type compute can name (e.g. `RayDesc`) must live outside it.
- **NVRTC `-pch` (12.8+) is requested only when the emitted source starts with `#include`**, so any CUDA front matter ahead of the prelude include silently disables it.
- **Slang never forwards `-O<n>` to NVRTC** (switch commented out since 2019) and NVRTC optimizes by default, so `-target ptx -O0` and `-O3` PTX are byte-identical.
- **A slang-rhi 1D CUtexObject is array-backed, so an integer 1D texel Load must use `tex.level.2d … [x,0]`**; integer `tex.level.1d` is the linear-memory `TLD … 1D` and reads zeros. Decide PTX texture forms from SASS (`cuobjdump -sass`). Linear-memory texture objects have no built-in Slang target (#14064); an `__intrinsic_asm "tex1Dfetch<float>(...)"` over a `uniform uint64_t` handle works.
- **CUDA `noinline` policy must be target-gated**: SPIR-V/LLVM/HLSL emitters already consume `IRNoInlineDecoration`.
- **`inout` subobject copy-in/out is design-gated on CUDA** by `undoParameterCopy` abort safety (OptiX aborts can skip writeback); WGSL already copies unconditionally.
- **`case cuda: __intrinsic_asm "name"` forwards ALL the function's args positionally** (spirv/glsl pass explicit operands), so mirroring a case across overloads of different arity needs a matching-arity prelude wrapper. Gate CUDA codegen on `-target ptx -Xnvrtc`: a bare `-target cuda` EXIT 0 can be a silent drop, and E41009 is OFF for CUDA/DXIL.

## OptiX payloads: register count is `payloadSize`, and `inout` is legalized twice

`_optix_trace_typed_32` is OptiX's single register-trace transport: it always emits 32 inline-asm slots, and the real word count travels only in the separate `payloadSize = (int)sizeof...(Payload)` operand. To triage "traced as N registers", grep the `payloadSize` immediate before the call, not the symbol; the bug is Slang passing the wrong number of `pr.regs[i]`. `optixTraceWithRegs`/`optixTraverseWithRegs`/`optixInvokeWithRegs` have `if constexpr (N==0..8)` branches then fixed-width catch-alls (`N<=16` passes regs[0..15], `N<=32` regs[0..31]), so `PayloadRegisters<T,N>` is over-read and over-written for N in [9,15] and [17,31] — when a report cites one window, check the sibling. NVRTC scalarizes the struct, so PTX shows undefined extra register operands, not stack OOB; scope the verdict to the codegen defect (a hang is "consistent with, not proven"). Repro GPU-free via `-target ptx` ([Slang CUDA/OptiX payload register count is carried by payloadSize](../learnings/1786644040522-slang-cuda-optix-payload-register-count-is-carried.md)).

`processMutableParam` calls `createLegalVaryingVal` once as `VaryingInput` and once as `VaryingOutput`, and the CUDA `case LayoutResourceKind::RayPayload:` keys off `getLayoutResourceKind` (always `RayPayload`) ignoring `info.kind`, so `emitOptiXPayloadRead` fires twice; writeback stays correct only via a `getCount()==0` registration dedup. The dead reads survive DCE because `kIROp_GetOptiXPayloadRegister` has `mightHaveSideEffects()` true. Fix the producer (don't emit the second read), not by marking the op pure — a mutable payload register can legitimately be re-read. Repro GPU-free with text CUDA emit plus `-dump-ir` ([OptiX inout ray-payload legalized twice: direction-agnostic RayPayload branch double-reads](../learnings/1786656384074-optix-inout-ray-payload-legalized-twice-direction-.md)).

## Hit attributes, ray flags, and RT intrinsics

**Hit attributes.** `emitOptiXAttributeFetch` recurses fields, elements and lanes, takes one 32-bit register per scalar `IRBasicType` leaf, and wraps float leaves in `__int_as_float`; the 8-register cap and its diagnostic live in the legalize pass. That reader is the contract, so a `ReportHit` writer must flatten field-wise too — a whole-struct `bit_cast<uint[N]>` desyncs on padding, sub-dword fields and float bits ([OptiX hit-attribute lowering is field-wise, not byte-packed](../learnings/1787174981538-optix-hit-attribute-lowering-is-field-wise-not-byt.md)). The write path (slang#12637): no per-attribute setter, so all leaves go into ONE `optixReportIntersection(hitT, hitKind, a0..a7)`; CUDA lowers `kIROp_BitCast` as a numeric C cast, so floats need explicit `__float_as_uint(x)` (PTX must show `0.5f` as `1056964608`, not 0); a target marker op with an aggregate operand is flattened after post-inline DCE and before empty-type/resource legalization; FileCheck slang-tests pass vacuously `0/0` without slang-llvm, so check with direct `slangc -target cuda` and a per-leaf grep ([OptiX ReportHit write path: no attribute setter, non-bit-preserving CUDA BitCast, pass ordering](../learnings/1787792439688-optix-reporthit-write-path-no-attribute-setter-non.md)). Releases without PR #12783 (e.g. v2026.14.1) reject portable `ReportHit(t, kind, attrs)` on `-target cuda`/`ptx` with E36107; the workaround `ReportHitOptix(1.0f, 1u, a.id, asuint(a.weight))` becomes `optixReportIntersection(1.0f, 1U, id, F32_asuint(weight))`, matching the reader (`optixGetAttribute_0()`, `__int_as_float(optixGetAttribute_1())`) ([pre-fix ReportHit workaround: ReportHitOptix with asuint per field](../learnings/1792400325654-pre-fix-reporthit-workaround-for-cuda-optix-report.md)).

**Ray flags.** `TraceRay`'s CUDA arm is `case cuda: __intrinsic_asm "optixTrace";`, which writes the flags operand verbatim, so flags with no OptiX equivalent silently miscompile (exit 0, then a GPU fault resembling a null deref). Fix with a compile-time diagnostic, not bit translation (OptiX skips triangles/AABBs per pipeline, not per ray). Any bare `case cuda: __intrinsic_asm` pass-through whose value space differs between DXR and OptiX is the same class ([CUDA/OptiX TraceRay ray-flags are a bare intrinsic-asm pass-through](../learnings/1787172018498-cuda-optix-traceray-ray-flags-are-a-bare-intrinsic.md)). Per `external/optix-dev/include/optix_types.h`, `OptixRayFlags` has bits 0–7 plus `FORCE_OPACITY_MICROMAP_2_STATE=1<<10` (0x400), nothing at bits 8–9. HLSL bits 0–7 map identically (`CULL_OPAQUE(0x40)↔CULL_DISABLED_ANYHIT` matches in value and semantics) and `RAY_FLAG_FORCE_OMM_2_STATE(0x400)` coincides. Only `SKIP_TRIANGLES=0x100`/`SKIP_PROCEDURAL_PRIMITIVES=0x200` are unsupported: unsupported = `flags & ~0x4FF`; a `>=0x100` threshold wrongly flags 0x400 ([HLSL RAY_FLAG vs OptiX OptixRayFlags — only 0x100/0x200 lack an equivalent](../learnings/1787173053502-hlsl-ray-flag-vs-optix-optixrayflags-only-0x100-0x.md)). All 12 NVIDIA/optix-dev tags (v7.0.0–v9.1.0) define bits 0–7 identically and nothing at 8/9; the OMM flag first appears in v7.6.0 (`OPTIX_VERSION` 70600; header was `optix_7_types.h` before 7.7). Emitting flags by name (jkwak-work's direction on slang#12629, following his #11437 HLSL barrier-flag pattern) needs `#if OPTIX_VERSION >= 70600` around OMM. Check a tag with a sparse `git clone --depth 1 --branch vX` (`include` only). While slang#12644 sat as a draft for six weeks, master reused its diagnostic code (55215) — re-check a long-lived draft's `slang-diagnostics.lua` code before rebasing ([OptiX ray-flag names are stable 7.0–9.1; the OMM flag needs OPTIX_VERSION >= 70600](../learnings/1790820168701-optix-ray-flag-names-are-stable-7-0-9-1-omm-flag-n.md)).

**Intrinsic-asm arity.** The CUDA arm forwards ALL the function's args positionally, while spirv/glsl arms pass explicit operands (`__spirvExecuteShaderEXT(HitOrMiss, p)`, `__glslInvoke(HitOrMiss, __rayPayloadLocation(p))`). Copying the 3-arg `"optixInvoke"` case into a 2-arg overload (slang#12553) emits `optixInvoke(hit, payload)` and NVRTC fails with `no instance of overloaded function "optixInvoke" matches the argument list`. Fix with a matching-arity prelude wrapper forwarding `(OptixTraversableHandle)0` (exact, since the 3-arg wrapper ignores handles). `-target cuda` exit 0 was a silent drop, so gate on `-target ptx -Xnvrtc -I external/optix-dev/include/`; missing-return E41009 is target-gated (`doesTargetAllowMissingReturns`, `slang-ir-missing-return.cpp:18-26`, false only for Khronos/WGPU), so one core-module gap is E41009 on SPIR-V/GLSL, a silent drop on CUDA and nothing on DXIL ([case cuda __intrinsic_asm forwards args positionally — dropping an arg breaks NVRTC arity](../learnings/1786786566207-case-cuda-intrinsic-asm-forwards-args-positionally.md)).

**E36107 on an RT built-in:** check the FIRST argument of its `[require(<target-atom-set>, <capability>)]`, not the capability. `TraceMotionRay`/`RayCurrentTime` are `[require(glsl_spirv, raytracing_motionblur_…)]`; the capability already has a `cuda` conjunct, so narrow `glsl_spirv` blocks (sibling `HitObject.TraceMotionRay` uses `cuda_glsl_spirv`). E36107's two `note:` lines give use site and `[require]` decl. Fix lock-step: widen the first arg, add the `case <target>: __intrinsic_asm` arm, add a matching-arity prelude overload if needed; repro `slangc repro.slang -target <t> -entry … -stage …` ([E36107 on a CUDA RT intrinsic: check the `[require]` FIRST-arg target set, not the capability compound](../learnings/1789186196430-e36107-for-an-rt-intrinsic-on-cuda-check-the-requi.md)).

**GeometryIndex.** On `-target cuda`, `HitObject.GetGeometryIndex()` lowers to `optixHitObjectGetSbtGASIndex()`, `HitObject.MakeHit`'s `GeometryIndex` arg is passed as `sbtGASIdx`, and since PR #13437 (2026-10-06) pipeline `GeometryIndex()` calls `optixGetSbtGASIndex()` (E36107 before). OptiX (through 9.0) has no build-input-ordinal query; the SBT GAS index is the sum of `numSbtRecords` over earlier inputs plus `sbtIndexOffset` in [0, numSbtRecords-1] (`optix_types.h:717`), so slang-rhi's one-record-per-input layout makes it the DXR ordinal (DeepWiki conflates pipeline and HitObject forms) ([CUDA SER path already treats GeometryIndex as the OptiX SBT GAS index](../learnings/1790318608424-slang-cuda-ser-path-already-treats-geometryindex-a.md)). `optixGetSbtGASIndex()` first appears in OptiX 7.1.0, so CUDA `GeometryIndex()` needs >= 7.1 (NVRTC reports it undefined against 7.0) ([optixGetSbtGASIndex needs OptiX >= 7.1](../learnings/1791203817991-optixgetsbtgasindex-needs-optix-7-1-reviewer-a-bac.md)). The OptiX 9 prelude `optixMakeHitObject` overloads build from `optixHitObjectGetTraverseData` and ignore `MakeHit`/`MakeMotionHit`'s explicit hit args — a known gap in docs/cuda-target.md ([property-getter `[require]` is not enforced](../learnings/1791199099928-slang-property-getter-require-is-not-enforced-a-mi.md)).

## The NVRTC-compiled prelude and version gating

All of `prelude/slang-cuda-prelude.h` is prepended to the NVRTC translation unit, so every helper must compile against the user's OptiX SDK whether called or not. Intrinsics are version-tiered (`optixTrace` 7.x, `optixTraverse` 8.0+, full `optixMakeHitObject` 9.0 with an 8.1 `#elif`), so a helper missing `#if (OPTIX_VERSION >= NNNNN)` breaks ALL RT shaders on older SDKs; a trivial shader failing `-target ptx` with `no instance of overloaded function "optixXxx"` points at an ungated helper. Dropping lower-SDK support is a maintainer call. It recurs because filecheck tests compile only against bundled 9.0 headers (the #10503 gap) ([OptiX version-gating bugs in slang-cuda-prelude.h recur — the whole prelude is NVRTC-compiled](../learnings/1787175488691-optix-version-gating-bugs-in-slang-cuda-prelude-h-.md)). Read thresholds from `external/optix-dev` tags (`git show v8.0.0:include/optix_device.h | grep -c 'void optixTraverse('`). In 7.x declarations live in `optix_7_device.h` (`optix_device.h` is a 47-line wrapper → false "absent"), and stock 7.0.0 headers fail under NVRTC 12.x (unguarded `#include <stddef.h>`), so put a stub `stddef.h` on `-Xnvrtc -I` ([same](../learnings/1791203817991-optixgetsbtgasindex-needs-optix-7-1-reviewer-a-bac.md)). Use one `#if` unless the signature changes across tiers and verify with an nvcc prelude probe against old headers; a testless PR documenting that check is often correct, since no in-tree-9.0 CI test can fail before and pass after ([resolve OptiX prelude version-gate thresholds from optix-dev git tags, verify GPU-free with nvcc](../learnings/1787227776278-resolve-optix-prelude-version-gate-thresholds-from.md)).

The OptiX block is compiled only for RT entry points: `slang-code-gen.cpp` (~:960-970) sets `PipelineType::RayTracing` for raygen/intersection/anyhit/closesthit/miss/callable, and `slang-nvrtc-compiler.cpp` (~:1341) `_maybeAddOptixSupport` — the only place adding `-DSLANG_CUDA_ENABLE_OPTIX` — runs only then. A plain data type a compute shader can name, such as `RayDesc` (#12638), must be defined outside `#ifdef SLANG_CUDA_ENABLE_OPTIX` (v2026.14.1). GPU-free testing of such a patch: [[wiki/concepts/slang-backends-cuda-ptx-surface-asm-verification.md]] ([SLANG_CUDA_ENABLE_OPTIX is set by entry-point stage, not by feature use](../learnings/1792400439374-cuda-slang-cuda-enable-optix-is-set-by-entry-point.md)).

**NVRTC `-pch`** shipped in PR #12880, gated on NVRTC ≥12.8, the leading-`#include` prelude form, and amortization (one-shot `-pch` is a net regression); the 256 MB default heap is managed reactively. `nvrtcGetPCHCreateStatus` is an optional symbol (init() works below 12.8); a `slang-nvrtc-pch-status: created|not-created|create-failed` token exposes the outcome to tests. Review gotchas: empty `IArtifactDiagnostics::getRaw()` returned a `nullptr`-backed slice that `SLANG_ASSERT(in[0]==0)` dereferenced (back it with `""`); `getDownstreamCompilerVersion` was removed from master (use `getDesc()`/`SemanticVersion`) — rebase before trusting "builds locally"; DRAFT PRs skip Slang CI ([empty-diagnostics null-deref + removed getDownstreamCompilerVersion](../learnings/1789272763883-nvrtc-pch-review-slang-12880-empty-diagnostics-nul.md), [NVRTC -pch for the CUDA prelude SHIPPED (#12880)](../learnings/1789272870056-nvrtc-pch-for-cuda-prelude-shipped-pr-12880-findin.md)). Slang's gate is stricter than NVRTC: `pchRequested` (`source/compiler-core/slang-nvrtc-compiler.cpp`, ~line 1430) requires the emitted source to `trimStart().startsWith("#include")`, so anything `CUDASourceEmitter::emitFrontMatterImpl` writes first — `#define SLANG_CUDA_ENABLE_FAST_MATH 1` under `-fp-mode fast` (PR #12872), the `#ifndef`-guarded `SLANG_CUDA_ENABLE_{HALF,BF16,FP8}` from #14037 — silently drops `-pch`. NVRTC itself stops at the first non-directive token, so the check could skip leading directives; NVRTC 12.6 containers can't show the effect. Why the front matter exists: [[wiki/concepts/slang-backends-cuda-nvrtc-vs-offline-nvcc.md]] [CUDA front-matter defines turn off NVRTC -pch on -target ptx](../learnings/1793299799398-cuda-front-matter-defines-turn-off-nvrtc-pch-on-ta.md).

**downstreamCompile super-linearity** on a matrix-heavy kernel is NVRTC's cost, not Slang emit size: Slang emits O(N) CUDA for an N-multiply chain (`targetLegalizesMatrixTypes()` is false, matrices stay prelude `Matrix<T,ROWS,COLS>`, `[__readNone]` `mul` emitted once with N call sites). The timer (PR #13050) wraps only `compiler->compile(...)` (`slang-code-gen.cpp:1028`), excluding Slang IR passes (e.g. #13010/#13059's O(n²) redundancy removal), so report it to NVIDIA; the reporter's workloads aren't in `tools/compile-perf/` ([a downstreamCompile-timer super-linearity on a matrix kernel is nvrtc-intrinsic, not a Slang emit-size artifact](../learnings/1789389982745-a-downstreamcompile-timer-super-linearity-on-a-mat.md)).

## Optimization level, noinline policy, and inout subobject lowering

CUDA `__noinline__` splits into mechanism and policy: PR #12419 made CUDA the 4th backend to emit it from `IRNoInlineDecoration`, which recovers nothing alone (generated code has no `[noinline]`); #12620 is the marking heuristic. The decoration has no consumers in `slang-ir-inline.cpp`, but the SPIR-V (`DontInline`), LLVM (`noinline`) and HLSL (`[noinline]`) emitters already emit from it, so an ungated pass would regress them. Shape: opt-in `-cuda-noinline-threshold=<n>` (default OFF) driving a CUDA-gated pass after `performForceInlining`, before emit ([CUDA noinline: a heuristic pass must be target-gated](../learnings/1787146175748-cuda-noinline-a-heuristic-pass-must-be-target-gate.md)).

`slang-code-gen.cpp:796-812` maps `-O<n>` into `DownstreamCompileOptions::optimizationLevel`, but the NVRTC switch at `slang-nvrtc-compiler.cpp:1234-1238` is commented out since #1151 (2019); NVRTC has no `-O` (`-Xnvrtc -O3` is "unrecognized option") and optimizes by default, so `-O0`/`-O3` PTX are byte-identical (CUDA 12.6). Per `ptxas -v`, NVVM promotes a pointer-to-struct param to scalars across `__noinline__` only when aliasing is ruled out (`__restrict__`, or read-before-write through another pointer) and ≤3 fields are read (observed; LLVM ArgumentPromotion defaults 3 in LLVM 14, 2 in 15). For signature rewrites (#13108 / #13177), `&s.a` still escapes the struct, and copy-in/write-back is abort-unsafe on OptiX (`slang-ir-undo-param-copy.cpp:9`, below). `slangc -target ptx` output ends with a NUL byte — grep with `-a` or `tr -d '\000'` ([Slang never forwards -O<n> to NVRTC; NVVM argpromotion across __noinline__ is narrow](../learnings/1790961575284-slang-never-forwards-o-n-to-nvrtc-nvrtc-optimizes-.md)).

`inout` uses copy-in/copy-out wrappers, but `addArg` materializes a temp only for a NON-addressable l-value; `path.sg` is passed as `&path.sg`. On CUDA/CPP `inout T` emits as `T*`, and `undoParameterCopy` (CUDA/Metal/CPP) removes copy temps precisely because OptiX aborts (`IgnoreHit`/`TerminateRay`) can skip a copy-back and drop the payload mutation. WGSL's `legalizeCall` always makes a `function`-space temp (no pointers to struct fields). So the requested copy-in/out exists on WGSL but is design-gated on CUDA: restrict to provably abort-free callees or write back on all exit paths. Green SPIR-V/HLSL never clears a CUDA param-passing change; the CUDA emitter inherits `CPPSourceEmitter`, and `-target cuda` emit is GPU-free FileCheck-able ([CUDA vs WGSL inout-subobject lowering divergence (and the undoParameterCopy abort-safety constraint)](../learnings/1788636814094-cuda-vs-wgsl-inout-subobject-lowering-divergence-a.md)).

## 1D texture integer Load: array-backed textures need the 2D form (#12630)

Pick the PTX texture form from SASS (no GPU needed): `nvcc -arch=sm_XX -cubin x.cu && cuobjdump -sass x.cubin | grep -E 'TLD|TEX'`, reading the trailing dimension token. For slang#12630 (nvcc 12.6, sm_52–sm_90): integer `tex.level.1d.v4.f32.s32` → `TLD … 1D` (like `tex1Dfetch`, linear memory); CUDA's `tex1DLod<float4>` on a 1D object → `TEX … 2D`; `tex.level.2d…s32 [t,{x,0}]` → `TLD … 2D`; `tex.level.a1d…s32` → `TLD … ARRAY_1D`. slang-rhi's 1D CUtexObjects are all array-backed, so the integer fetch is 2D at row 0 (on the L40S `tex.level.1d…s32` returned zeros). Fix: PR #13377 (T4 CUDA test checks values). Gotchas: GPU-less containers with a stale CMake cache fail to link on `libcuda.so` (use `-DCUDA_cuda_driver_LIBRARY=/usr/local/cuda/lib64/stubs/libcuda.so`); the render-test CPU backend lacks `Texture1D` subscript and unpacks only RGBA32Uint/R32Uint/R16Uint, so Sint coverage is CUDA-only; a bot ci.yml dispatch can park on `wait-for-human-priority`/`falcor-ci` approval, which `ci-retry-yielded-bot` never retries ([CUDA 1D texture Load: integer tex.level.1d = linear-memory TLD.1D](../learnings/1790894433645-cuda-1d-texture-load-integer-tex-level-1d-linear-m.md)).

Linear memory has no built-in Slang target (#14064): on CUDA/PTX read-only `Buffer<T>` is E36107 (note `__ShapeBuffer`; `[require(cpp_glsl_hlsl_metal_spirv)]` at `hlsl.meta.slang:590` since #12289) and `Texture1D` is the CUDA-array path. Workaround: `float fetchLinear(uint64_t tex, int i) { __target_switch { case cuda: __intrinsic_asm "tex1Dfetch<float>((cudaTextureObject_t)$0, $1)"; } }` with the `CUtexObject` as a `uniform uint64_t`; it emits `tex.1d.v4.f32.s32 [t, {i}]` and returned 1000/1000 correct values on the L40S (2026-10-29, CUDA 12.6, driver-API host, `CU_RESOURCE_TYPE_LINEAR` 1-channel float). Compute uniforms become plain kernel params (`k(ulonglong, float*, uint)`), so a small `cuModuleLoadData` + `cuLaunchKernel` host suffices. slang-rhi makes texture objects only over CUDA arrays, and TypedBuffer binds a device pointer [CUDA linear-memory texture objects from Slang today: __intrinsic_asm tex1Dfetch over a uint64_t handle](../learnings/1793312171013-cuda-linear-memory-texture-objects-from-slang-toda.md).

## Shader-record (SBT) globals: lower after specialization and the global-init move

PR #12646 (slang#12628) maps a global `shaderRecordEXT` `ConstantBuffer` to the OptiX SBT on CUDA by rewriting the `IRGlobalParam` into opaque `GetOptiXSbtDataPtr`. Placed early in `linkAndOptimizeIR` beside `collectOptiXEntryPointUniformParams` (`slang-emit.cpp` ~:1391) it broke three things: (1) `specializeResourceUsage` (~:2097) specializes a callee's ConstantBuffer/resource param only when the argument is a `kIROp_GlobalParam` (`slang-ir-specialize-resources.cpp` ~:740; else `ThisFuncFailed`), so `float4 readIt(ConstantBuffer<T> cb)` stayed unspecialized, `isPointerToImmutableLocation` couldn't see the root through the param, and the callee emitted `__ldg(&cb->field)` — the #10188 stale-SBT-read bug; (2) a use inside an `expand` body crashed slangc (`IRExpand` owns a block but isn't an `IRGlobalValueWithCode`; `specializeModule` ~:1552 hadn't run); (3) a reference-graph diagnostic missed interface/generic calls, which don't follow witness tables before specialization. Moving the rewrite just after `specializeResourceUsage` fixed all three; review probe: `readIt(gSbt)` then grep the callee for `__ldg` [rewriting a global param into an opaque intrinsic before specializeResourceUsage](../learnings/1790827641249-cuda-optix-rewriting-a-global-param-into-an-opaque.md), [lower shader-record globals after specialization](../learnings/1790831529525-cuda-optix-lower-shader-record-globals-after-speci.md).

Second constraint: `moveGlobalVarInitializationToEntryPoints` (`slang-ir-explicit-global-init.cpp` ~:107-114, 187-240) injects EVERY global initializer into EVERY entry point, late on CUDA/CPU (~:2483). A per-entry-point diagnostic from `buildEntryPointReferenceGraph` before it is unsound for `static` initializers: with an RT and a compute entry point plus `static uint x = gSbt.id;`, the compute kernel calls `optixGetSbtDataPointer()` unflagged (SPIR-V's spirv-val catches the analog, VUID-07119; CUDA has nothing). Run such lowering after the move (~:2490) [every static initializer reaches every entry point](../learnings/1790827641249-cuda-optix-rewriting-a-global-param-into-an-opaque.md). Provenance is still lost when a handle is stored in a struct field, returned, or `select`ed (`isPointerToImmutableLocation` then calls it immutable by type), so `lowerImmutableBufferLoadForCUDA` needs a module-level guard, keyed in PR #12646 on `GetOptiXSbtDataPtr`'s deduplicated IR types [module-level `__ldg` guard](../learnings/1790831529525-cuda-optix-lower-shader-record-globals-after-speci.md).
