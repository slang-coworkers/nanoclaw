# Slang SPIR-V: slang-glslang, spirv-opt, and optimization levels

How Slang's SPIR-V passes through the bundled `slang-glslang` module (SPIRV-Tools/spirv-opt), what each `-O` level runs, and the downstream folding, unrolling and CSE limits that look like "Slang bugs". Floating-point reassociation and `NoContraction` live on [[wiki/concepts/slang-backends-spirv-precise-and-nocontraction.md]]; the core emitter is on [[wiki/concepts/slang-backends-spirv.md]].

## TL;DR

- `slang-glslang` IS the SPIR-V backend (it bundles SPIRV-Tools/spirv-opt; unrelated to GLSL), always runtime-loaded: a missing module is a packaging fix, never a reason to make the load optional. Opt out of one pass via a dedicated CMake escape hatch.
- SPIR-V emit loads spirv-opt only when it needs it (link, `-O1+` or `-Xspirv-opt`, validation, `-separate-debug-info`). A plain `-O0` compile loads nothing locally, but CI exports `SLANG_RUN_SPIRV_VALIDATION=1`; a test that must avoid slang-glslang sets `SkipSPIRVValidation`.
- A missing library reports E00100: the CLI fails, the API returns the unoptimized module (slang-wasm depends on that), so never add an unconditional fail. Absence is unit-testable via `setSharedLibraryLoader`.
- `-separate-debug-info` is Slang's own word filter, yet master still loads spirv-opt for it and crashes when the library is missing (fix: PR #13801). Split output from two builds always differs in `DebugBuildIdentifier` and paths; prove byte-identity by swapping only `libslang-compiler.so`.
- Pre-existing: linking a precompiled `-embed-downstream-ir` SPIR-V module with `-g2 -separate-debug-info` and any spirv-opt pass segfaults in libslang-glslang; at `-g0`/`-g1` spirv-opt reports a dangling `OpExtInst` set id.
- slangc has no build-graph edge to the dlopen'd `slang-glslang`, so a FetchContent consumer's SPIR-V custom command needs `DEPENDS slang-glslang`. Trace its calls with a logging shim `libslang-glslang-<ver>.so` in a directory passed as `-spirv-opt-path <dir>` (never the `.so` path).
- Default optimization runs spirv-opt, `-target spirv-asm` included; only `-O0` runs zero passes, so it is a faithful "no spirv-opt" proxy. `legalizeIRForSPIRV` always runs.
- `-O<n>` changes only the downstream level, never Slang IR passes; `-minimum-slang-optimization` is the switch that alters Slang's own pipeline.
- `-O0` does not stop Slang SCCP/DCE dropping an unused shader parameter. `-preserve-params` keeps it, on SPIR-V only at `-O0` (spirv-opt strips it at every other level; GLSL/HLSL keep it). `-reflection-json` still lists it, so prefer Slang reflection over spirv-reflect/SPIRV-Cross.
- spirv-opt is size/perf only, not correctness; binary size is not GPU runtime, and no size/perf harness exists. Granular pass control goes through `RegisterPassesFromFlags`, not a hand-maintained flag→pass table.
- `CreatePrivateToLocalPass` (default preset) demotes a single-function `Private` var to `Function` storage and breaks function-`static` persistence.
- Default-opt SPIR-V is exhaustively inlined into one `OpFunction`; WGSL/HLSL keep the call graph and Slang has no inlining heuristic or flag, so deep single-call wrapper chains cost DXC time unless `[ForceInline]`. Inspect shapes at `-O0`.
- An assert inside `external/spirv-tools` is an upstream bug: file it upstream, mark the test expected-failure. slang-test's `-O0` default (PR #11805) MASKS such aborts; `-O1+` users still hit them and suite-wide `-O3` (#12247) revives them. Triage on Debug with the real `-entry`/`-stage`: exit 0 = benign drift, 134 = real abort.
- spirv-opt segfaults on body-less imported `OpFunction`s (from `-incomplete-library` externs and precompiled-import chains); upstream is still affected. `//TEST:COMPILE:` runs `-O0`, so it pins nothing unless it names `-O1`+.
- Invalid SPIR-V only at `-O1+`, with the op intact in `-dump-ir` and `-O0` correct ⇒ spirv-opt. #12104's vec3 `OpConstantComposite` with 4 constituents is spirv-opt's IEEE-unsafe `x/x→1` fold, not Slang emit.
- LoopUnroll does not fire on Slang's `[unroll]` loops at -O2/-O3 because a trampoline block precedes the merge; DXC and NVRTC fold them. A `[ForceUnroll]` bound built from integer `abs`/`min`/`max` gives E40020.
- spirv-opt never CSEs `OpGroupNonUniform*`; dedup wave ops in Slang IR with a participation-fenced block-local pass, never via `isMovableInst`.
- SlangPy's generated-kernel abstraction folds to zero overhead at `-O3`; measure codegen quality GPU-free with a SPIR-V opcode census.

## slang-glslang is the SPIR-V backend

`slang-glslang` is always runtime-loaded, never static-linked; a build missing it needs a build-system fix, not a non-fatal load ([don't mask its load](../learnings/1782152994624-slang-glslang-is-the-spir-v-backend-don-t-mask-its.md)). To opt out of one pass, follow `SLANG_ENABLE_SPIRV_OPT_MERGE_RETURN`: an `advanced_option`, a compile definition via `CompilerFlags.cmake`, and `#if` around ALL registrations, dead `#if 0` blocks included ([CMake escape hatch](../learnings/1781975592365-slang-glslang-add-an-opt-out-via-dedicated-cmake-e.md)).

**When spirv-opt loads.** `createArtifactFromIR` calls `getOrLoadDownstreamCompiler(SpirvOpt, getSink())`, so a missing `slang-glslang` puts E00100 in the real sink; optional callers pass a `nullptr` sink, and absence is unit-testable via `setSharedLibraryLoader` ([fatal via real sink](../learnings/1781799089141-slang-downstream-compiler-load-optional-spirv-opt-.md), [absence is unit-testable](../learnings/1781804734767-slang-downstream-compiler-absence-spirv-opt-slang-.md)). On master (f96c0d829, 2026-10-21) it loads only when `needsDownstreamCompiler` is true: a link, `needsOptimization` (`-O1`+ or any `-Xspirv-opt`), validation, or `-separate-debug-info` (`slang-emit.cpp:3600-3623`); `spirv-asm` also loads it for spirv-dis. Plain `-O0` thus works without slang-glslang locally, but not in CI: `.github/workflows/ci-slang-test.yml:149` exports `SLANG_RUN_SPIRV_VALIDATION=1` for the whole "Test Slang" step (unit tests included), and `shouldRunSPIRVValidation` (slang-emit.cpp ~3486) then sets `needsDownstreamCompiler` even at `Optimization=None` (LD_DEBUG load counts at `-O0`: 0 unset, 1 set, 0 with `-skip-spirv-validation`). A unit test that must avoid slang-glslang sets `CompilerOptionName::SkipSPIRVValidation = 1`, checked before the env var (PR #13867) ([CI validation loads slang-glslang at -O0](../learnings/1792682583662-slang-test-ci-exports-slang-run-spirv-validation-1.md)).

**A missing spirv-opt must not become an unconditional failure (#13795, PR #13801).** The CLI already fails (`generateOutput` checks the sink's error count); the API returns the unoptimized module from `getEntryPointCode`/`getTargetCode` with E00100 in diagnostics. slang-wasm ships no slang-glslang and its smoke test (`tests/wasm/smoke/smoke-test.js`) compiles SPIR-V through the API at default `-O1`, so a `needsDownstreamCompiler && !compiler → SLANG_FAIL` in `createArtifactFromIR` breaks it. `-separate-debug-info` is where a missing optimizer changed the result: `stripDbgSpirvFromArtifact` (Slang's own filter) ran only inside a successful spirv-opt `compile()`, so `dbgArtifact` stays null and `emitSPIRVForEntryPointsDirectly` crashes (Debug E99997 at `slang-artifact-impl.cpp(244)`, Release segfault; still so on f96c0d829). PR #13801 strips after the downstream block and gates `compile()` on `needsOptimization`. Test notes: the split still *opens* slang-glslang (`Linkage::buildHash` probes `SpirvDis` for a version string), so assert on E00100 or "optimizer called", not a fake loader's "requested" flag; `-spirv-opt-path` changes the global session, so the test must be `COMMAND_LINE_SIMPLE`; the fixer container has gdb (analysis does not), and a break on `*DownstreamCompilerUtil::locateCompilers` shows who loads a library ([split is independent of spirv-opt](../learnings/1792555787908-slang-spir-v-separate-debug-info-split-is-independ.md)). The Release segfault comes *after* the diagnostic, so a `COMMAND_LINE_SIMPLE` "E00xxx and not E99997" test misses it; see the result-code trap on [[wiki/concepts/misc-f0909b3-slang-test-verification.md]].

**Byte-comparing `-separate-debug-info` output across builds.** Two builds always differ in the 40-hex `DebugBuildIdentifier`, even at one tag (`Linkage::buildHash` → `getEntryPointHash` folds in the build tag and slang-glslang's file timestamp), and the `.dbg.spv` embeds the source path and `-I <bin dir>`. So swap one library: build a "drill" tree (head with only the changed file reverted), copy its `libslang-compiler.so.0.<ver>` over a backed-up HEAD build's, run from the same cwd and file names, restore; #13801 was byte-identical at O0/O1/O3, `-g0`..`-g3`, validate and link ([swap only libslang-compiler.so](../learnings/1792564291274-byte-compare-spir-v-separate-debug-info-across-bui.md)). That review also found a crash master 2e145635a already has: compile `lib.slang -target spirv -embed-downstream-ir -incomplete-library -g2`, then `import lib` from `main.slang` with `-target spirv -O1 -g2 -skip-spirv-validation -separate-debug-info`, and slangc segfaults entirely inside libslang-glslang (also `-O0 -Xspirv-opt <pass>`, not plain `-O0`). At `-g0`/`-g1` without the split, `-O1` fails with `OpExtInst set Id N does not reference an OpExtInstImport result Id`: probably a dangling ext-inst set id (hypothesis; no issue filed as of 2026-10-21). An `LD_PRELOAD` SIGSEGV handler with `backtrace()` + `dladdr` gives frames without gdb ([pre-existing link segfault](../learnings/1792564295285-pre-existing-precompiled-spir-v-link-g2-separate-d.md)).

**Nothing in the build graph orders `slang-glslang` before a SPIR-V compile.** `slangc` REQUIRES `slang-glsl-module`, `generate_core_module_cache` and the DXC copy targets (`CMakeLists.txt:736-743`) but not the dlopen'd `slang-glslang` MODULE, so a FetchContent consumer whose custom command runs `$<TARGET_FILE:slangc> -target spirv` can race ahead of `libslang-glslang-<ver>.so` and fail with E00100 "failed to load downstream compiler 'spirv-opt'" (the adjacent 'pthread' load failure is a harmless probe). Proof without a race: `ninja -t inputs <output> | grep libslang-glslang` gives 0 hits, and a clean `ninja <output>` reproduces. Fix: `DEPENDS slang-glslang` or `add_dependencies(<tgt> slang-glslang)`. DeepWiki wrongly gives slangc `OPTIONAL_REQUIRES slang-glslang`; that is slang-test (`tools/CMakeLists.txt:352`) ([no build dep on slang-glslang](../learnings/1792402895620-slang-cmake-slangc-has-no-build-dep-on-runtime-loa.md), shader-slang/slang#13746).

**Tracing slangc → slang-glslang calls without a debugger** (the analysis container has no gdb/lldb/ltrace/strace; #13795). A forwarding `shim.cpp` exports `glslang_compile_1_3`, `glslang_validateSPIRV`, `glslang_disassembleSPIRV`, `glslang_linkSPIRV`, includes `source/slang-glslang/slang-glslang.h`, dlopens `$REAL_GLSLANG`, logs `r->action`/`r->optimizationLevel`/`r->spirvOptimizationFlagCount`, and forwards. Name it `libslang-glslang-<SLANG_VERSION_NUMERIC>.so` (e.g. `libslang-glslang-2026.13.1.so`) in a directory passed as `-spirv-opt-path <dir>`. A `.so` path fails with E00100 (the loader appends the library name), so `-spirv-opt-path nonexistent.so` is a CLI repro of "slang-glslang missing". `LD_DEBUG=libs slangc … 2>&1 | grep slang-glslang` checks whether it loads ([logging shim](../learnings/1792539973371-trace-slang-glslang-calls-without-a-debugger-loggi.md)).

**Granular pass selection (#12204):** `-OX` levels are hand-unrolled presets (~40 `RegisterPass` calls, `slang-glslang.cpp:316`). Use the bundled `spvtools::Optimizer::RegisterPassesFromFlags(flags)` (`optimizer.hpp:140`), passing the string across the C ABI in a new `glslang_CompileRequest_1_3`; no correctness risk, but it ties the CLI to the bundled SPIRV-Tools version ([RegisterPassesFromFlags](../learnings/1784829679560-granular-spvopt-pass-selection-registerpassesfromf.md)).

## What each optimization level runs

**Default optimization runs spirv-opt**, even for plain `-target spirv-asm` with no `-O`: the level is Default, so `glslang_optimizeSPIRV` runs the `#elif 1` DEFAULT preset, `CreatePrivateToLocalPass` included ([default opt runs spirv-opt](../learnings/1781714495665-slangc-target-spirv-asm-at-default-opt-does-run-sp.md)). That pass moves a `Private` var used in one function to per-call `Function` storage without checking the function runs once per invocation, breaking function-`static` persistence; the fix removes both live registrations ([private-to-local](../learnings/1781713084820-spir-v-function-static-state-loss-spirv-tools-priv.md)).

**`-O0` is a faithful no-spirv-opt proxy.** `needsOptimization = getOptimizationLevel() != None` maps None → downstream None and `glslang_optimizeSPIRV` early-returns; the always-on `legalizeIRForSPIRV` does not depend on `-O`. A study of what spirv-opt buys must state that binary size ≠ GPU runtime (the driver re-optimizes), that only large real shaders show the 50-70% size win, and that no size/perf harness exists ([-O0 proxy](../learnings/1784653425624-o0-is-a-faithful-no-spirv-opt-proxy-spirv-opt-is-s.md)).

**`-O<n>` never changes the Slang IR pipeline.** It only sets `CompilerOptionName::Optimization`, read only by downstream compilers: IR dumps match at `-O0`/`-O1`, and WGSL is byte-identical at every level. `-minimum-slang-optimization` does change Slang's passes (skips the late `simplifyIR` after `lowerBitCast`, runs SCCP once), so test IR-fold fixes under it ([-O<n> is downstream-only](../learnings/1792593053197-slang-o-n-does-not-change-ir-passes-test-ir-fold-f.md); WGSL detail on [[wiki/concepts/slang-backends-wgsl-f16-and-const-expressions.md]]). Any `-O0`/`-O1` SPIR-V difference thus comes from spirv-opt; the `-g2` case (ADCE deleting `_dbgvar_` shadows with their `DebugDeclare`) is on [[wiki/concepts/slang-backends-spirv-debug-info-emission.md]] ([`_dbgvar_` at -O0 vs -O1](../learnings/1792627978559-spir-v-g2-dbgvar-helper-vars-o0-duplicates-real-st.md)).

**Unused shader parameters: `-O0` does not keep them, and `-preserve-params` holds on SPIR-V only at `-O0`.** A `cbuffer` used only inside `if (false)` is dropped at `-O0` (slangc 2026.20), even with `-minimum-slang-optimization`, because Slang's `simplifyIR` SCCP/DCE always runs. `-O0 -preserve-params` keeps it (`slang-ir-link.cpp` ~L2340 clones global params with KeepAlive, `slang-ir-ssa-simplification.cpp` ~L30 reads `keepGlobalParamsAlive`, `slang-emit-spirv.cpp` ~L12214 calls `ensureInst`). `-reflection-json` still lists a dropped parameter with set and index, so tools needing the full binding list should use Slang reflection, not spirv-reflect/SPIRV-Cross. `isParameterLocationUsed` is on `slang::IMetadata`, not `ProgramLayout`, and is wrong for some entry-point parameters (#13789, draft fix #13811) ([-O0 does not stop Slang DCE](../learnings/1792894686825-o0-does-not-stop-slang-dce-of-unused-params-preser.md)). Every SPIR-V level above `-O0`, default `-O1` included, drops it again, since spirv-opt runs whenever the level is not None (`slang-emit.cpp:3620-3623`) and strips unused variables; GLSL and HLSL keep it. Issue #6947 (open) tracks this and the help text still promises "even if they are not used", so advise "`-O0 -preserve-params`", not just "avoid `-O3`" ([-preserve-params only at -O0](../learnings/1792916425472-preserve-params-keeps-unused-globals-in-spir-v-onl.md)).

**Default opt inlines the whole SPIR-V call graph; other targets keep it.** At `-O1`+ `-target spirv` runs `CreateInlineExhaustivePass`, leaving one `OpFunction` (a 4-wrapper repro: 1 by default, 7 at `-O0`). `source/slang-glslang/slang-glslang.cpp` holds three DEFAULT preset copies behind `#if 0` / `#elif 1` / `#else`; only `#elif 1` is live, inline pass at :367 (verified at 98ea350615), so do not cite the dead :343 and :422; HIGH/MAXIMAL registers it at :470. To see Slang's own function and parameter shapes (#13703), compile at `-O0` or use `-dump-ir-after transformParamsToConstRef` (SPIR-V/Metal/CUDA/CPU only, `slang-emit.cpp:2496-2534`); WGSL, HLSL and GLSL keep struct `in` params by value ([SPIR-V -O1 fully inlined](../learnings/1792160953423-slang-spir-v-default-o1-is-fully-inlined-by-spirv-.md)). WGSL and HLSL keep every non-`[ForceInline]` function (`slang-ir-wgsl-legalize.cpp:230-234`), leaving inlining to Tint/DXC and the driver; Slang's IR inliners (`slang-ir-inline.cpp`) act only on decorations or legality rules, with no call-count or size heuristic and no slangc option. On non-lib DXIL the cost lands in DXC: each single-call wrapper level adds inliner time for byte-identical DXIL (#13960: depth 0/4/8 takes 7.1/8.6/10.4 s; `[ForceInline]` restores about 7.0 s). That atom's own line map swaps the live and dead copies ([#13960 inlining cost](../learnings/1793108645180-slang-spir-v-output-is-fully-inlined-by-spirv-opt-.md)).

**SlangPy kernel abstraction:** at `-O3` it collapses to 0 `OpFunctionCall`, byte-identical to a hand-rolled kernel; the runtime index arithmetic (1 sdiv + 1 srem + strided loads) is design-inherent ([folds at -O3, deferred to nvrtc for CUDA](../learnings/1781017004302-slangpy-generated-kernel-abstraction-fully-folds-i.md), [SPIR-V opcode census](../learnings/1781050949927-measure-slangpy-generated-kernel-codegen-quality-g.md)).

## spirv-opt aborts and the `-O0` default

**fp8 constants abort in spirv-tools:** `GetWordsFromScalarFloatConstant` (`opt/folding_rules.cpp`) asserts width 16/32/64 (the integer sibling handles 8); upstream fix #11766, Slang expected-failure #11744 ([fp8 width-8 gap](../learnings/1782449605671-fp8-scalar-float-constants-abort-in-spirv-tools-co.md)). **The slang-test `-O0` default (PR #11805) hides such aborts rather than fixing them**: suppressions for tests aborting in spirv-opt (fp8 #11766/#11767) can be dropped without the upstream fix, but `-O1+` users still hit the bug. GPU-free repro: Debug slangc exits 134, 0 with `-O0`; Release compiles the assert out. Render-test checks device features BEFORE compiling, so a `(vk)` test compiles only where a Vulkan device (e.g. lavapipe) exists ([suppressions droppable via -O0](../learnings/1783036168133-spirv-opt-crash-suppressed-via-expected-failure-li.md)). Suite-wide `-O3` (#12247) revives the asserts, so a "resolved" #11805-era issue may be dormant. Live sites: fp8/CoopVec constants (`folding_rules.cpp:156/:3539`), `spirv_asm` `OpMemberDecorateIdEXT` (ADCE `:1000 assert(false)`). A debug `assert()` bypasses `messageConsumer`/`SLANG_FAIL` and on Windows surfaces as "exit 3 / hang / lost JSON-RPC worker" in a sibling test, so verify each suspect standalone; about 77 of 79 failures were benign drift ([-O3 revives dormant asserts](../learnings/1785203893114-suite-wide-spirv-opt-o3-revives-dormant-spirv-tool.md)).

**spirv-opt also crashes on body-less imported functions, and slang-test COMPILE lines never run it.** A body-less `OpFunction` declaration reaches spirv-opt via `slangc -incomplete-library -target spirv` with an unresolved `extern`, or by precompiling (`-target spirv -embed-downstream-ir`) a module that imports an already precompiled one (its SPIR-V carries `LinkageAttributes … Import`). At -O1 `DeadBranchElimPass::FixBlockOrder` → `ReorderBasicBlocksInStructuredOrder` reads the declaration's `blocks_[0]` (only when DBE changed something); at -O2/-O3 `LocalSingleStoreElim` dereferences `func->begin()`. Both segfault silently; upstream main (efadd8a7) is still affected even with valid Linkage/Import SPIR-V, and `-O0` avoids it. If `-dump-ir` shows the last pass (`checkUnsupportedInst`) completed yet it crashes, suspect emit or the downstream optimizer first; without gdb, an `LD_PRELOAD` SIGSEGV handler printing `backtrace()` + `dladdr` offsets plus `addr2line -f -C -e <Debug .so>` gives the stack, and `build/external/spirv-tools/tools/Debug/spirv-opt` reruns single passes ([-incomplete-library SPIR-V crashes come from spirv-opt](../learnings/1793663616584-incomplete-library-spir-v-with-an-unresolved-exter.md)). No `tests/library/precompiled-*` test caught the chain crash on master 7f506f4c9, because slang-test runs `//TEST:COMPILE:` as `slangc -O0 <args>` (see `slang-test -v`). PR #14220 fixes it as a side effect by skipping the `-O` preset for unlinked modules that still import symbols. Put `-O1`+ on a COMPILE line meant to pin optimizer behaviour, and when reviewing an optimizer gate also test a libA→libB precompile chain ([slang-test COMPILE injects -O0, hiding spirv-opt crashes](../learnings/1793673393737-slang-test-compile-injects-o0-hiding-spirv-opt-cra.md)).

## Folding, unrolling and CSE limits

**spirv-opt's LoopUnroll skips Slang's `[unroll]` loops at -O2/-O3.** Slang lowers `[unroll]` to `OpLoopMerge … Unroll`, yet a constant-trip loop such as `for (i = 0; i < 10; ++i) sum += i` survives the bundled preset (`slang-glslang.cpp:493`). `Loop::FindConditionBlock` (spirv-tools `loop_descriptor.cpp:619`) requires the merge block's single in-loop predecessor to be the `OpBranchConditional`, but Slang's output still has a trampoline `%x: OpBranch %merge` from the breakable-region wrap, and BlockMerge runs only later; `spirv-opt -O` twice, or BlockMerge before LoopUnroll, folds it. DXC and NVRTC fold such loops unhinted, so "loop not folded at -O3" is SPIR-V-specific. Related: spirv-opt has no GLSL.std.450 `SAbs` fold rule (`SMin`/`SMax`/`SClamp` exist), and Slang IR keeps integer `abs`/`min`/`max`/`clamp`/`sign` as opaque intrinsic calls, so a `[ForceUnroll]` bound built from them gives E40020 while the ternary form folds (#13424) ([LoopUnroll skips `[unroll]`](../learnings/1791074922027-spirv-opt-loopunroll-silently-skips-slang-s-unroll.md)).

**Invalid SPIR-V only at optimization levels points at spirv-opt (#12104).** `output[0] = (value<eps) ? 0 : (value/value)` for a runtime `float3` emits `OpConstantComposite %v3float %float_1 ×4`, which spirv-val rejects; the maintainer's Slang-side leads (`processConstructor`/`emitCompositeConstruct`/`MakeVector`) are wrong. The layer-isolation drill: (1) `-dump-ir` shows `div(%value,%value)` intact through every pass; (2) `-O0` emits a correct `OpFDiv`, every other level the bad constant (the only delta is routing through `PassThroughMode::SpirvOpt`, vendored spirv-tools v2026.3); (3) `-fp-mode precise` keeps `OpFDiv ; NoContraction`, `fast` gives the bad constant, an IEEE-unsafe `x/x→1` fold (0/0 = NaN); (4) float2/3/4 all get 4 constituents, a hardcoded 4. Slang's peephole folds `v-v` correctly and leaves `v*v`; only `v/v` reaches the downstream fold. Fixes: (A, root) `external/spirv-tools/source/opt/folding_rules.cpp` uses the result type's component count (upstream + submodule bump); (B, in-tree now) a fast-math-gated `x/x→1` Slang peephole producing a correctly sized ones vector ([#12104 is spirv-opt's x/x fold](../learnings/1784072018251-slang-12104-vec3-opconstantcomposite-4-constituent.md)). An earlier repro-blocked triage (~11 minimal shapes, all 3 constituents) rightly ruled out the sub-vector UNDER-count path that `processConstructor` flattens (`slang-ir-spirv-legalize.cpp:1795-1810`); its post-legalize-fold suspect is superseded. Its net still holds: `emitOpConstantComposite` (`slang-emit-spirv-ops.h:1417-1425`) has no constituent-count check, and an assert there makes silent invalid output loud, though not #12104's, minted after emit ([#12104 repro-blocked triage](../learnings/1784069141044-slang-spir-v-vec3-opconstantcomposite-over-count-r.md)).

**spirv-opt will not CSE `OpGroupNonUniform*`.** Both CSE passes use `ValueNumberTable`, which gives every non-combinator a fresh value number, and `AddCombinatorsForCapability` lists no group/ballot op; a group op depends on the active-lane set, so CSE or hoisting is unsound. Dedup ops such as `WaveActiveCountBits` + `WavePrefixCountBits` (both emit `OpGroupNonUniformBallot`) in Slang IR with a participation-fenced block-local pass (PR #12848), never via `isMovableInst` ([no CSE of group ops](../learnings/1789578103315-spirv-opt-won-t-cse-opgroupnonuniform-they-re-non-.md)).

Float reassociation under default fp-mode (#12160) is also a spirv-opt fold, gated on `NoContraction`; see [[wiki/concepts/slang-backends-spirv-precise-and-nocontraction.md]].
