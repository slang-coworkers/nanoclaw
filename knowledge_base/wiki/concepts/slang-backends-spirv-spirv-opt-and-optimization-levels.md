# Slang SPIR-V: slang-glslang, spirv-opt, and optimization levels

How Slang's directly emitted SPIR-V passes through the bundled `slang-glslang` module (SPIRV-Tools/spirv-opt), what each `-O` level actually runs, and the downstream folding, unrolling and CSE limits that show up as "Slang bugs". Floating-point reassociation and `NoContraction` live on [[wiki/concepts/slang-backends-spirv-precise-and-nocontraction.md]]; the core emitter is on [[wiki/concepts/slang-backends-spirv.md]].

## TL;DR

- `slang-glslang` IS the SPIR-V backend: it bundles SPIRV-Tools/spirv-opt and has nothing to do with GLSL. It is always runtime-loaded; a missing module is a build/packaging fix, never a reason to make its load optional. Opt out of one pass through a dedicated CMake escape hatch, not by deleting it.
- SPIR-V emit loads spirv-opt with the real sink only when it needs it (link, `-O1+` or `-Xspirv-opt`, validation, `-separate-debug-info`). A plain `-O0` compile loads nothing locally, but CI exports `SLANG_RUN_SPIRV_VALIDATION=1`, so there it loads; a test that must avoid slang-glslang sets `SkipSPIRVValidation`. When the library is absent, the load reports E00100. The CLI fails on that error, but the API returns the unoptimized module, and slang-wasm (which ships no slang-glslang) depends on that, so do not add an unconditional fail. Optional callers pass a `nullptr` sink, and absence is unit-testable via `setSharedLibraryLoader`.
- `-separate-debug-info` is Slang's own word filter and does not need spirv-opt, but on master it still loads it, and a missing library crashes the compile (fix: PR #13801).
- `-separate-debug-info` output from two builds always differs in `DebugBuildIdentifier` (build tag, glslang file timestamp) and path strings. To prove an emit change byte-identical, swap only `libslang-compiler.so` between builds and run from the same cwd.
- Pre-existing on master: linking a precompiled `-embed-downstream-ir` SPIR-V module with `-g2 -separate-debug-info` and any spirv-opt pass segfaults inside libslang-glslang; at `-g0`/`-g1` spirv-opt reports a dangling `OpExtInst` set id.
- slangc has no build-graph dependency on the dlopen'd `slang-glslang`, so a FetchContent consumer's SPIR-V custom command needs `DEPENDS slang-glslang`. To trace its calls without a debugger, put a logging shim named `libslang-glslang-<ver>.so` in a directory and pass `-spirv-opt-path <dir>` (a directory, never the `.so` path).
- Default optimization runs spirv-opt, `-target spirv-asm` included; only `-O0` runs zero passes, so `-O0` is a faithful "no spirv-opt" proxy. `legalizeIRForSPIRV` always runs, independent of `-O`.
- `-O<n>` changes only the downstream level, never Slang IR passes; `-minimum-slang-optimization` is the switch that alters Slang's own pipeline.
- spirv-opt is size/perf only, not correctness; binary size is not GPU runtime, and no size/perf harness exists.
- `CreatePrivateToLocalPass` (default preset) demotes a single-function `Private` var to `Function` storage and breaks function-`static` persistence.
- Default-opt SPIR-V is exhaustively inlined into one `OpFunction`; WGSL/HLSL keep the call graph. Compare per-target function/param shapes at `-O0` or with `-dump-ir-after transformParamsToConstRef`.
- Granular pass control goes through `spvtools::Optimizer::RegisterPassesFromFlags`, not a hand-maintained flag→pass table.
- An assert inside `external/spirv-tools` is an upstream bug: file it upstream and mark the Slang test expected-failure.
- The slang-test `-O0` default (PR #11805) MASKS spirv-opt aborts, it does not fix them; users at `-O1+` still hit them and a suite-wide `-O3` (#12247) revives them.
- Triaging an `-O3` failure list: compile with the test's real `-entry`/`-stage` on a Debug build. Exit 0 = benign FileCheck drift; exit 134 = real abort (about 77 of 79 were benign).
- Invalid SPIR-V only at `-O1+` with `-dump-ir` intact and `-O0` correct ⇒ spirv-opt. The #12104 vec3 `OpConstantComposite` with 4 constituents is spirv-opt's IEEE-unsafe `x/x→1` fold, not Slang emit.
- spirv-opt's LoopUnroll does not fire on Slang's `[unroll]` loops at -O2/-O3, because a trampoline block still precedes the merge; DXC and NVRTC fold the same loops. A `[ForceUnroll]` bound built from integer `abs`/`min`/`max` gives E40020.
- spirv-opt never CSEs `OpGroupNonUniform*`; dedup wave ops in Slang IR with a participation-fenced block-local pass, never via `isMovableInst`.
- SlangPy's generated-kernel abstraction folds to zero overhead at `-O3`; measure codegen quality GPU-free with a SPIR-V opcode census.

## slang-glslang is the SPIR-V backend

`slang-glslang` is always runtime-loaded, never static-linked. A static build missing it needs a build-system fix, not a non-fatal load ([slang-glslang: don't mask its load as optional](../learnings/1782152994624-slang-glslang-is-the-spir-v-backend-don-t-mask-its.md)). Pass opt-out follows `SLANG_ENABLE_SPIRV_OPT_MERGE_RETURN`: `advanced_option` + compile definition via `CompilerFlags.cmake` + `#if` around ALL registrations, dead `#if 0` blocks included ([CMake escape-hatch opt-out](../learnings/1781975592365-slang-glslang-add-an-opt-out-via-dedicated-cmake-e.md)).

**The spirv-opt load uses the real sink, so a missing library is an error.** `createArtifactFromIR` calls `getOrLoadDownstreamCompiler(SpirvOpt, getSink())`, so a missing `slang-glslang` puts E00100 in the sink before any output guard. Optional callers pass a `nullptr` sink, and absence is unit-testable via `setSharedLibraryLoader` ([optional spirv-opt is fatal via real sink](../learnings/1781799089141-slang-downstream-compiler-load-optional-spirv-opt-.md), [absence IS unit-testable](../learnings/1781804734767-slang-downstream-compiler-absence-spirv-opt-slang-.md)). On master (f96c0d829, 2026-10-21) the load happens only when `needsDownstreamCompiler` is true: a link, `needsOptimization` (`-O1`+ or any `-Xspirv-opt` flag), validation, or `-separate-debug-info` (`slang-emit.cpp:3600-3623`). A plain `-O0` compile loads nothing, which is why `-target spirv -O0` works with a build that has no slang-glslang. `spirv-asm` still loads it for 'spirv-dis'. **CI turns validation on, so there a `-O0` compile still loads slang-glslang.** `.github/workflows/ci-slang-test.yml:149` exports `SLANG_RUN_SPIRV_VALIDATION=1` for the whole "Test Slang" step, which also runs `slang-unit-test-tool`; `shouldRunSPIRVValidation` (slang-emit.cpp ~3486, read via `_dupenv_s`) then sets `needsDownstreamCompiler`, and `getOrLoadDownstreamCompiler(SpirvOpt)` runs even with `Optimization=None`. LD_DEBUG counts for `slangc -target spirv -O0`: slang-glslang is loaded 0 times with the variable at 0, once at 1, and 0 times with `-skip-spirv-validation`. So a unit test that must not touch slang-glslang (for example one that measures only slang-compiler) passes locally and fails in CI unless it also sets `CompilerOptionName::SkipSPIRVValidation = 1`, which is checked before the env var (found on PR #13867) [slang-test CI exports SLANG_RUN_SPIRV_VALIDATION=1, so -O0 SPIR-V compiles still load slang-glslang](../learnings/1792682583662-slang-test-ci-exports-slang-run-spirv-validation-1.md).

**Do not turn a missing spirv-opt into an unconditional failure (#13795, PR #13801).** The CLI already fails, because `generateOutput` checks the sink's error count. The API does not: `getEntryPointCode`/`getTargetCode` return the unoptimized module with E00100 in the diagnostics. The Emscripten slang-wasm build ships no slang-glslang, and its CI smoke test (`tests/wasm/smoke/smoke-test.js`) compiles SPIR-V through the API at the default `-O1`, so a `needsDownstreamCompiler && !compiler → SLANG_FAIL` in `createArtifactFromIR` breaks it. `-separate-debug-info` is the case where a missing optimizer did change the result. `stripDbgSpirvFromArtifact` is Slang's own word filter, but it runs only inside a successful spirv-opt `compile()`. So the split loads slang-glslang even at `-O0` (an empty identity pass), and when the library is missing `dbgArtifact` stays null and `emitSPIRVForEntryPointsDirectly` crashes (Debug E99997 at `slang-artifact-impl.cpp(244)`, Release segfault; still true on master f96c0d829). PR #13801 strips after the downstream block and gates `compile()` on `needsOptimization`. Three test notes from that PR: even with the fix, the split still *opens* slang-glslang, because `Linkage::buildHash` probes `getOrLoadDownstreamCompiler(SpirvDis, nullptr)` for its version string, so a fake loader's "was slang-glslang requested" flag proves nothing; assert on E00100 or on "optimizer called" instead. `-spirv-opt-path` changes the global session, so a `.slang` test that uses it must be `COMMAND_LINE_SIMPLE` (a fresh slangc process), not `SIMPLE` (a shared session). The fixer container has gdb (the analysis container does not); break on the `*DownstreamCompilerUtil::locateCompilers` functions to find who loads a library ([-separate-debug-info split is independent of spirv-opt; a missing optimizer must not change the API result](../learnings/1792555787908-slang-spir-v-separate-debug-info-split-is-independ.md)). Because the Release failure is a segfault *after* the diagnostic, a `COMMAND_LINE_SIMPLE` "E00xxx and not E99997" test does not catch it on Release; see the result-code trap on [[wiki/concepts/misc-f0909b3-slang-test-verification.md]].

**Proving a `-separate-debug-info` emit change byte-identical, and a pre-existing crash found doing it (#13801 review).** Outputs from two separate builds always differ in the 40-hex `DebugBuildIdentifier`, even at the same git tag. The hash (`Linkage::buildHash` → `getEntryPointHash`) folds in the build tag and the slang-glslang library's file timestamp (`GlslangDownstreamCompiler::getVersionString` uses the `SharedLibraryUtils` timestamp), and the `.dbg.spv` also embeds the source path and `-I <bin dir>`. So `cmp` across builds is evidence of a regression only when the difference extends past the identifier and the path strings. The reliable method swaps one library: build a "drill" tree (head with only the changed file reverted), back up the HEAD build's `libslang-compiler.so.0.<ver>`, copy the drill's copy over it, run from the same cwd with the same file names, then restore. That way #13801 was byte-identical at O0/O1/O3, `-g0`..`-g3`, validate and link ([byte-compare -separate-debug-info by swapping only libslang-compiler.so](../learnings/1792564291274-byte-compare-spir-v-separate-debug-info-across-bui.md)). The same review found a crash that master 2e145635a also has, so it is not the PR's: compile `lib.slang -o lib.slang-module -target spirv -embed-downstream-ir -incomplete-library -g2`, then `main.slang` (which does `import lib`) with `-target spirv -O1 -g2 -skip-spirv-validation -separate-debug-info`, and slangc gets SIGSEGV with every crashing frame inside libslang-glslang. `-O0 -Xspirv-opt <pass>` crashes too; plain `-O0` is fine. At `-g0`/`-g1` without the split, the same link fails at `-O1` with `spirv-opt: error : OpExtInst set Id N does not reference an OpExtInstImport result Id`, so the linked module probably carries a dangling ext-inst set id (a hypothesis; no issue filed as of 2026-10-21). An `LD_PRELOAD` SIGSEGV handler that calls `backtrace()` + `dladdr` gives the frames without gdb ([precompiled SPIR-V link + -g2 -separate-debug-info + optimizer segfaults in libslang-glslang](../learnings/1792564295285-pre-existing-precompiled-spir-v-link-g2-separate-d.md)).

**Because it is dlopen'd, nothing in the build graph orders `slang-glslang` before a SPIR-V compile.** `slangc` (`source/slangc/CMakeLists.txt`) REQUIRES `slang-glsl-module`, `generate_core_module_cache` and the DXC copy targets (`CMakeLists.txt:736-743`), but not the `slang-glslang` MODULE. So a consumer that pulls Slang in through FetchContent/`add_subdirectory` and runs `$<TARGET_FILE:slangc> -target spirv` in a custom command (default `-O1`) can race ahead of `libslang-glslang-<ver>.so` and fail with E00100 "failed to load downstream compiler 'spirv-opt'"; the "failed to load dynamic library 'pthread'" note beside it is a harmless first probe. Prove the missing edge without a race: `ninja -t inputs <output> | grep libslang-glslang` gives 0 hits, and a clean `ninja <output>` reproduces it in about 4 minutes on 64 cores, while a full `ninja` may pass by job order. The consumer fix is `DEPENDS slang-glslang` on the custom command or `add_dependencies(<tgt> slang-glslang)`. DeepWiki wrongly says slangc has `OPTIONAL_REQUIRES slang-glslang`; that is slang-test (`tools/CMakeLists.txt:352`) ([slangc has no build dep on runtime-loaded slang-glslang](../learnings/1792402895620-slang-cmake-slangc-has-no-build-dep-on-runtime-loa.md), shader-slang/slang#13746).

**Tracing what slangc sends to slang-glslang, with no debugger.** The container has no gdb, lldb, ltrace or strace. A forwarding shim answers "does slangc call `glslang_compile_1_3`, and with what request" (#13795): a `shim.cpp` that exports `glslang_compile_1_3`, `glslang_validateSPIRV`, `glslang_disassembleSPIRV` and `glslang_linkSPIRV`, includes `source/slang-glslang/slang-glslang.h` for the structs, dlopens `$REAL_GLSLANG`, logs `r->action`, `r->optimizationLevel` and `r->spirvOptimizationFlagCount`, and forwards. Copy it into a directory under the versioned Linux name `libslang-glslang-<SLANG_VERSION_NUMERIC>.so` (e.g. `libslang-glslang-2026.13.1.so`) and pass the directory with `-spirv-opt-path <dir>`. Passing the `.so` path itself fails with E00100, because the loader treats the value as a directory and appends `/pthread` and the library name. That same behaviour makes `-spirv-opt-path nonexistent.so` a command-line repro of the "slang-glslang missing" path, and `LD_DEBUG=libs slangc … 2>&1 | grep slang-glslang` is a quicker check of whether the library loads at all ([logging shim via -spirv-opt-path <dir>](../learnings/1792539973371-trace-slang-glslang-calls-without-a-debugger-loggi.md)).

**Granular pass selection (#12204):** `-OX` levels are hand-unrolled presets (~40 `RegisterPass` calls, `slang-glslang.cpp:316`). Use bundled `spvtools::Optimizer::RegisterPassesFromFlags(flags)` (`optimizer.hpp:140`); the pass string crosses the C ABI as a new `glslang_CompileRequest_1_3`. No correctness risk (spirv-opt is size/perf only), but it ties the CLI to the bundled SPIRV-Tools version ([RegisterPassesFromFlags is the clean primitive](../learnings/1784829679560-granular-spvopt-pass-selection-registerpassesfromf.md)).

## What each optimization level runs

**Default optimization runs spirv-opt**, including `CreatePrivateToLocalPass`, even for plain `-target spirv-asm` ([default opt DOES run spirv-opt](../learnings/1781714495665-slangc-target-spirv-asm-at-default-opt-does-run-sp.md)). It demotes a `Private` var used in one function to `Function` storage, breaking function-`static` persistence; the fix removes both live registrations ([function-static state loss = private-to-local](../learnings/1781713084820-spir-v-function-static-state-loss-spirv-tools-priv.md)).

**`-O0` is a faithful no-spirv-opt proxy.** `needsOptimization = getOptimizationLevel() != None` maps None → downstream None, and `glslang_optimizeSPIRV` early-returns. The always-on `legalizeIRForSPIRV` does not depend on `-O`. When studying what spirv-opt buys, state these caveats: binary size ≠ GPU runtime (the driver re-optimizes), the corpus must include large real shaders (the 50-70% size win doesn't show on tests/), and no size/perf harness exists ([-O0 is a faithful no-spirv-opt proxy](../learnings/1784653425624-o0-is-a-faithful-no-spirv-opt-proxy-spirv-opt-is-s.md)).

**`-O<n>` never changes the Slang IR pipeline.** It only sets `CompilerOptionName::Optimization`, which only downstream compilers read; Slang IR dumps are identical at `-O0` and `-O1`, and on a target with no downstream compiler (WGSL) the output is byte-identical at every level. The switch that does change Slang's own passes is `-minimum-slang-optimization`, which skips the late `simplifyIR` after `lowerBitCast` and runs SCCP only once, so an IR-fold fix must be tested under it ([-O<n> does not change IR passes](../learnings/1792593053197-slang-o-n-does-not-change-ir-passes-test-ir-fold-f.md); WGSL detail on [[wiki/concepts/slang-backends-wgsl-f16-and-const-expressions.md]]). Any `-O0`/`-O1` SPIR-V difference therefore comes from spirv-opt; the `-g2` debug-variable case (ADCE duplicating `DebugValue`s and deleting `_dbgvar_` shadows with their `DebugDeclare`) is on [[wiki/concepts/slang-backends-spirv-debug-info-emission.md]] ([`_dbgvar_` helper vars: -O0 vs -O1](../learnings/1792627978559-spir-v-g2-dbgvar-helper-vars-o0-duplicates-real-st.md)).

**Default opt inlines the whole SPIR-V call graph; other targets keep it.** At the default level, `-target spirv` runs spirv-opt with `CreateInlineExhaustivePass` (the `#elif 1` default preset, `source/slang-glslang/slang-glslang.cpp:366`), so the final module has a single `OpFunction`. To see the function and parameter shapes that Slang's IR produces for SPIR-V (for example by-value vs pointer params, #13703), compile with `-O0` or use `-dump-ir-after transformParamsToConstRef`. WGSL and HLSL output keeps every non-`[ForceInline]` function (WGSL legalize does "no extra inlining", `slang-ir-wgsl-legalize.cpp:230-234`), so Tint/DXC and the driver decide inlining there. `transformParamsToConstRef` runs only for SPIR-V/Metal/CUDA/CPU (`slang-emit.cpp:2496-2534`); WGSL, HLSL and GLSL keep struct `in` params by value ([SPIR-V -O1 is fully inlined; WGSL/HLSL keep the call graph](../learnings/1792160953423-slang-spir-v-default-o1-is-fully-inlined-by-spirv-.md)).

**SlangPy kernel abstraction:** Fully collapses to zero overhead in Slang SPIR-V at `-O3` — 0 `OpFunctionCall`, byte-identical to a hand-rolled kernel. Runtime index arithmetic (1 sdiv + 1 srem + strided loads) is design-inherent, not a codegen defect ([SlangPy generated-kernel abstraction fully folds in slang SPIR-V (-O3), but is deferred to nvrtc for CUDA target](../learnings/1781017004302-slangpy-generated-kernel-abstraction-fully-folds-i.md), [Measure SlangPy generated-kernel codegen quality GPU-free via slangc SPIR-V opcode census](../learnings/1781050949927-measure-slangpy-generated-kernel-codegen-quality-g.md)).

## spirv-opt aborts and the `-O0` default

**fp8 constants abort in spirv-tools:** `GetWordsFromScalarFloatConstant` (`opt/folding_rules.cpp`) asserts width 16/32/64 (the integer sibling handles 8). Upstream fix #11766; Slang expected-failure #11744 ([fp8 width-8 gap](../learnings/1782449605671-fp8-scalar-float-constants-abort-in-spirv-tools-co.md)). The same fp8 case shows how the slang-test `-O0` default hides such aborts: tests suppressed for aborting inside spirv-opt, such as fp8 #11766/#11767 at `folding_rules.cpp:156`, stop aborting once PR #11805 defaults slang-test to `-O0`. The suppression can be dropped without the upstream SPIRV-Tools fix, but users at `-O1+` still hit the upstream bug. GPU-free repro: a Debug slangc aborts with exit 134, and adding `-O0` exits 0. Release builds compile the assert out. Render-test creates the device and checks features BEFORE compiling, so a `(vk)` test compiles only where a Vulkan device (e.g. lavapipe) exists ([spirv-opt crash suppressions droppable via the -O0 default](../learnings/1783036168133-spirv-opt-crash-suppressed-via-expected-failure-li.md)). Suite-wide `-O3` (#12247) revives such asserts. A "resolved" #11805-era issue may just be dormant. Live sites: fp8/CoopVec constants hit `folding_rules.cpp:156/:3539` (the float folder rejects width 8), and `spirv_asm` `OpMemberDecorateIdEXT` hits ADCE `:1000 assert(false)`. A debug `assert()` bypasses the `messageConsumer`/`SLANG_FAIL` path. On Windows it shows up as "exit 3 / hang / lost JSON-RPC worker" in a sibling test, so verify each suspect standalone. About 77 of 79 failures were benign drift ([suite-wide -O3 revives dormant SPIRV-Tools asserts](../learnings/1785203893114-suite-wide-spirv-opt-o3-revives-dormant-spirv-tool.md)).

## Folding, unrolling and CSE limits

**spirv-opt's LoopUnroll skips Slang's `[unroll]` loops at -O2/-O3.** Slang lowers `[unroll]` to `OpLoopMerge … Unroll`, yet a constant-trip loop such as `for (i = 0; i < 10; ++i) sum += i` survives the bundled preset (`slang-glslang.cpp:493`, the same order as upstream `RegisterPerformancePasses`). `Loop::FindConditionBlock` (spirv-tools `loop_descriptor.cpp:619`) requires the merge block's single in-loop predecessor to be the `OpBranchConditional`, but at that point in the preset Slang's output still has a trampoline `%x: OpBranch %merge` left by the breakable-region wrap, and BlockMerge runs only later. Running `spirv-opt -O` twice, or adding BlockMerge just before LoopUnroll, unrolls and folds the loop to a constant. DXIL (DXC) and PTX (NVRTC) fold such loops with no hint, so "loop not folded at -O3" reports are SPIR-V-specific. Two related folding limits: spirv-opt has no GLSL.std.450 `SAbs` constant-fold rule (`SMin`/`SMax`/`SClamp` exist), and in Slang IR integer `abs`/`min`/`max`/`clamp`/`sign` are opaque target-intrinsic calls, so a `[ForceUnroll]` bound built from them gives E40020 while the ternary form folds (#13424) ([spirv-opt LoopUnroll silently skips Slang's [unroll] loops at -O3](../learnings/1791074922027-spirv-opt-loopunroll-silently-skips-slang-s-unroll.md)).

**vec3 `OpConstantComposite` over-count is a downstream spirv-opt fold, NOT Slang emit (#12104):** `output[0] = (value<eps) ? 0 : (value/value)` for a runtime `float3` emits `OpConstantComposite %v3float %float_1 ×4` (4 constituents on a vec3 → spirv-val rejects). The maintainer's (jkwak) leads pointed at Slang's own `processConstructor`/`emitCompositeConstruct`/`MakeVector` — those are WRONG. Layer-isolation drill (reusable for any "invalid SPIR-V only at optimization" bug): (1) `-dump-ir` shows `div(%value,%value)` surviving intact through every pass → Slang IR isn't folding it; (2) `-O0` emits correct `OpFDiv` while default/`-O1/2/3` emits the malformed constant — the only pipeline delta is `slang-emit.cpp` routing SPIR-V through `PassThroughMode::SpirvOpt` (vendored `external/spirv-tools` spirv-opt @ v2026.3); (3) `-fp-mode precise` → clean `OpFDiv ; NoContraction`, `-fp-mode fast` → malformed, confirming an IEEE-unsafe `x/x→1` fold (0/0=NaN); (4) width sweep shows a HARDCODED 4 constituents (float2→4, float3→4, float4→4), NOT a vec4→vec3 result-type shrink — the vec2-with-4 case is the smoking gun. Slang's own peephole folds `v-v` correctly to a 3-constituent zero-vector and leaves `v*v` as `OpFMul`; only `v/v` (no `x/x→1` rule in slang-ir-peephole/sccp) reaches the vulnerable downstream fold. Fix options: (A, true root) fix `external/spirv-tools/source/opt/folding_rules.cpp` to use the result type's component count (upstream + submodule bump); (B, in-tree actionable now) add a fast-math-gated `x/x→1` Slang peephole fold producing a correctly-sized ones vector so spirv-opt never sees the vulnerable `OpFDiv %a %a`. An emit-time constituent-count assert in `emitOpConstantComposite` (which has no `constituent-count==element-count` check today, `slang-emit-spirv-ops.h:1417-1425`) is a useful general net that converts silent-invalid-output into a loud failure, but does NOT catch this bug — the malformed constant is minted post-emit in spirv-opt ([#12104 vec3 OpConstantComposite 4-constituent bug is in downstream spirv-opt, not Slang (x/x fold)](../learnings/1784072018251-slang-12104-vec3-opconstantcomposite-4-constituent.md)). An earlier repro-blocked triage of the same issue (jkwak's `float3(float2(1,1),1)` minimal case validates fine; ~11 minimal shapes on near-HEAD all emit a correct 3-constituent composite) correctly ruled out the sub-vector UNDER-count path (`processConstructor`'s flatten at `slang-ir-spirv-legalize.cpp:1795-1810` already handles that) and flagged a post-legalize fold (`simplifyIRForSpirvLegalization`) as the suspect — since superseded by the spirv-opt root cause above, but the standing `emitOpConstantComposite` count-assert recommendation still holds ([vec3 OpConstantComposite over-count — repro-blocked, post-legalize fold suspect (#12104)](../learnings/1784069141044-slang-spir-v-vec3-opconstantcomposite-over-count-r.md)).

**spirv-opt will not CSE `OpGroupNonUniform*`.** Both CSE passes use `ValueNumberTable`, which gives every non-combinator a fresh value number; `AddCombinatorsForCapability` lists no group/subgroup/ballot op. A group op depends on the active-lane set, so CSE/hoist would be unsound. Dedup ops such as `WaveActiveCountBits` + `WavePrefixCountBits` (both emit `OpGroupNonUniformBallot`) in Slang IR with a participation-fenced block-local pass (PR #12848). Do not add them to `isMovableInst` ([spirv-opt won't CSE OpGroupNonUniform*](../learnings/1789578103315-spirv-opt-won-t-cse-opgroupnonuniform-they-re-non-.md)). PR #12848 is not merged. On 2026-10-19 it was an open draft (last updated 2026-10-02); on 2026-09-17 the maintainer said they were "considering NOT to proceed" with it and asked for the spirv-opt/SPIRV-Tools layer to be checked. Run `gh pr view 12848 --json isDraft,state` before citing it ([#12848 is still a draft](../learnings/1792423080231-slang-12847-pr-12848-is-still-a-draft-local-master.md)).

Float reassociation under default fp-mode (#12160) is also a spirv-opt fold, gated on `NoContraction`; see [[wiki/concepts/slang-backends-spirv-precise-and-nocontraction.md]].
