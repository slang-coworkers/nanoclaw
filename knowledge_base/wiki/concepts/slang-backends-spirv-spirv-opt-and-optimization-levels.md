# Slang SPIR-V: slang-glslang, spirv-opt, and optimization levels

How Slang's directly emitted SPIR-V passes through the bundled `slang-glslang` module (SPIRV-Tools/spirv-opt), what each `-O` level actually runs, and the downstream folding, unrolling and CSE limits that show up as "Slang bugs". Floating-point reassociation and `NoContraction` live on [[wiki/concepts/slang-backends-spirv-precise-and-nocontraction.md]]; the core emitter is on [[wiki/concepts/slang-backends-spirv.md]].

## TL;DR

- `slang-glslang` IS the SPIR-V backend (it bundles SPIRV-Tools/spirv-opt; nothing to do with GLSL) and is always runtime-loaded: a missing module is a build/packaging fix, never a reason to make its load optional. Opt out of one pass through a dedicated CMake escape hatch, not by deleting it.
- SPIR-V emit loads spirv-opt with the real sink only when it needs it (link, `-O1+` or `-Xspirv-opt`, validation, `-separate-debug-info`). A plain `-O0` compile loads nothing locally, but CI exports `SLANG_RUN_SPIRV_VALIDATION=1`, so there it loads; a test that must avoid slang-glslang sets `SkipSPIRVValidation`.
- A missing library reports E00100. The CLI fails on it; the API returns the unoptimized module, and slang-wasm (no slang-glslang) depends on that, so never add an unconditional fail. Optional callers pass a `nullptr` sink; absence is unit-testable via `setSharedLibraryLoader`.
- `-separate-debug-info` is Slang's own word filter and needs no spirv-opt, but on master it still loads it and crashes when the library is missing (fix: PR #13801). Two builds' split output always differs in `DebugBuildIdentifier` and paths; prove byte-identity by swapping only `libslang-compiler.so`.
- Pre-existing on master: linking a precompiled `-embed-downstream-ir` SPIR-V module with `-g2 -separate-debug-info` and any spirv-opt pass segfaults inside libslang-glslang; at `-g0`/`-g1` spirv-opt reports a dangling `OpExtInst` set id.
- slangc has no build-graph edge to the dlopen'd `slang-glslang`, so a FetchContent consumer's SPIR-V custom command needs `DEPENDS slang-glslang`. Trace its calls with a logging shim named `libslang-glslang-<ver>.so` in a directory passed as `-spirv-opt-path <dir>` (never the `.so` path).
- Default optimization runs spirv-opt, `-target spirv-asm` included; only `-O0` runs zero passes, so `-O0` is a faithful "no spirv-opt" proxy. `legalizeIRForSPIRV` always runs.
- `-O<n>` changes only the downstream level, never Slang IR passes; `-minimum-slang-optimization` is the switch that alters Slang's own pipeline.
- `-O0` does not stop Slang's SCCP/DCE from dropping an unused shader parameter. `-preserve-params` keeps it, but on SPIR-V only at `-O0`: at every other level spirv-opt strips it again (GLSL/HLSL keep it). `-reflection-json` still lists it, so prefer Slang reflection over spirv-reflect/SPIRV-Cross.
- spirv-opt is size/perf only, not correctness; binary size is not GPU runtime, and no size/perf harness exists. Granular pass control goes through `RegisterPassesFromFlags`, not a hand-maintained flag→pass table.
- `CreatePrivateToLocalPass` (default preset) demotes a single-function `Private` var to `Function` storage and breaks function-`static` persistence.
- Default-opt SPIR-V is exhaustively inlined into one `OpFunction`; WGSL/HLSL keep the call graph, and Slang has no inlining heuristic or flag, so deep single-call wrapper chains cost DXC compile time unless marked `[ForceInline]`. Inspect per-target function/param shapes at `-O0` or with `-dump-ir-after transformParamsToConstRef`.
- An assert inside `external/spirv-tools` is an upstream bug: file it upstream and mark the Slang test expected-failure. The slang-test `-O0` default (PR #11805) MASKS such aborts; users at `-O1+` still hit them, and a suite-wide `-O3` (#12247) revives them. Triage such a list with the test's real `-entry`/`-stage` on a Debug build: exit 0 = benign FileCheck drift, exit 134 = real abort (about 77 of 79 were benign).
- Invalid SPIR-V only at `-O1+`, with the op intact in `-dump-ir` and `-O0` correct ⇒ spirv-opt. The #12104 vec3 `OpConstantComposite` with 4 constituents is spirv-opt's IEEE-unsafe `x/x→1` fold, not Slang emit.
- spirv-opt's LoopUnroll does not fire on Slang's `[unroll]` loops at -O2/-O3, because a trampoline block still precedes the merge; DXC and NVRTC fold the same loops. A `[ForceUnroll]` bound built from integer `abs`/`min`/`max` gives E40020.
- spirv-opt never CSEs `OpGroupNonUniform*`; dedup wave ops in Slang IR with a participation-fenced block-local pass, never via `isMovableInst`.
- SlangPy's generated-kernel abstraction folds to zero overhead at `-O3`; measure codegen quality GPU-free with a SPIR-V opcode census.

## slang-glslang is the SPIR-V backend

`slang-glslang` is always runtime-loaded, never static-linked; a static build missing it needs a build-system fix, not a non-fatal load ([don't mask its load](../learnings/1782152994624-slang-glslang-is-the-spir-v-backend-don-t-mask-its.md)). To opt out of one pass, follow `SLANG_ENABLE_SPIRV_OPT_MERGE_RETURN`: an `advanced_option`, a compile definition via `CompilerFlags.cmake`, and `#if` around ALL registrations, dead `#if 0` blocks included ([CMake escape hatch](../learnings/1781975592365-slang-glslang-add-an-opt-out-via-dedicated-cmake-e.md)).

**When spirv-opt loads.** `createArtifactFromIR` calls `getOrLoadDownstreamCompiler(SpirvOpt, getSink())`, so a missing `slang-glslang` puts E00100 in the real sink before any output guard; optional callers pass a `nullptr` sink, and absence is unit-testable via `setSharedLibraryLoader` ([fatal via real sink](../learnings/1781799089141-slang-downstream-compiler-load-optional-spirv-opt-.md), [absence is unit-testable](../learnings/1781804734767-slang-downstream-compiler-absence-spirv-opt-slang-.md)). On master (f96c0d829, 2026-10-21) it loads only when `needsDownstreamCompiler` is true: a link, `needsOptimization` (`-O1`+ or any `-Xspirv-opt`), validation, or `-separate-debug-info` (`slang-emit.cpp:3600-3623`); `spirv-asm` also loads it for spirv-dis. So a plain `-O0` compile works without slang-glslang locally, but not in CI: `.github/workflows/ci-slang-test.yml:149` exports `SLANG_RUN_SPIRV_VALIDATION=1` for the whole "Test Slang" step (`slang-unit-test-tool` included), and `shouldRunSPIRVValidation` (slang-emit.cpp ~3486) then sets `needsDownstreamCompiler` even at `Optimization=None`. LD_DEBUG counts slang-glslang loads for `slangc -target spirv -O0` as 0 (variable 0), 1 (variable 1), 0 (`-skip-spirv-validation`). A unit test that must avoid slang-glslang therefore sets `CompilerOptionName::SkipSPIRVValidation = 1` (checked before the env var; PR #13867) ([CI validation loads slang-glslang at -O0](../learnings/1792682583662-slang-test-ci-exports-slang-run-spirv-validation-1.md)).

**A missing spirv-opt must not become an unconditional failure (#13795, PR #13801).** The CLI already fails (`generateOutput` checks the sink's error count); the API returns the unoptimized module from `getEntryPointCode`/`getTargetCode` with E00100 in the diagnostics. slang-wasm ships no slang-glslang and its CI smoke test (`tests/wasm/smoke/smoke-test.js`) compiles SPIR-V through the API at the default `-O1`, so a `needsDownstreamCompiler && !compiler → SLANG_FAIL` in `createArtifactFromIR` breaks it. `-separate-debug-info` is where a missing optimizer did change the result: `stripDbgSpirvFromArtifact` is Slang's own word filter but ran only inside a successful spirv-opt `compile()`, so without the library `dbgArtifact` stays null and `emitSPIRVForEntryPointsDirectly` crashes (Debug E99997 at `slang-artifact-impl.cpp(244)`, Release segfault; still so on f96c0d829). PR #13801 strips after the downstream block and gates `compile()` on `needsOptimization`. Test notes: the split still *opens* slang-glslang because `Linkage::buildHash` probes `getOrLoadDownstreamCompiler(SpirvDis, nullptr)` for a version string, so assert on E00100 or "optimizer called", not a fake loader's "requested" flag; `-spirv-opt-path` changes the global session, so its `.slang` test must be `COMMAND_LINE_SIMPLE`, not `SIMPLE`; the fixer container has gdb (the analysis container does not), and a break on `*DownstreamCompilerUtil::locateCompilers` shows who loads a library ([split is independent of spirv-opt](../learnings/1792555787908-slang-spir-v-separate-debug-info-split-is-independ.md)). The Release segfault comes *after* the diagnostic, so a `COMMAND_LINE_SIMPLE` "E00xxx and not E99997" test misses it; see the result-code trap on [[wiki/concepts/misc-f0909b3-slang-test-verification.md]].

**Byte-comparing `-separate-debug-info` output across builds.** Two builds always differ in the 40-hex `DebugBuildIdentifier`, even at one tag: `Linkage::buildHash` → `getEntryPointHash` folds in the build tag and the slang-glslang file timestamp (`GlslangDownstreamCompiler::getVersionString`), and the `.dbg.spv` embeds the source path and `-I <bin dir>`. A `cmp` difference means a regression only beyond those; instead swap one library: build a "drill" tree (head with only the changed file reverted), copy its `libslang-compiler.so.0.<ver>` over the backed-up HEAD build's, run from the same cwd with the same file names, then restore; #13801 was byte-identical at O0/O1/O3, `-g0`..`-g3`, validate and link ([swap only libslang-compiler.so](../learnings/1792564291274-byte-compare-spir-v-separate-debug-info-across-bui.md)). That review also found a crash master 2e145635a already has: compile `lib.slang -o lib.slang-module -target spirv -embed-downstream-ir -incomplete-library -g2`, then a `main.slang` doing `import lib` with `-target spirv -O1 -g2 -skip-spirv-validation -separate-debug-info`, and slangc segfaults with every frame inside libslang-glslang (also `-O0 -Xspirv-opt <pass>`, not plain `-O0`). At `-g0`/`-g1` without the split the link fails at `-O1` with `OpExtInst set Id N does not reference an OpExtInstImport result Id`, so the linked module probably carries a dangling ext-inst set id (hypothesis; no issue filed as of 2026-10-21). An `LD_PRELOAD` SIGSEGV handler calling `backtrace()` + `dladdr` gives frames without gdb ([pre-existing link segfault](../learnings/1792564295285-pre-existing-precompiled-spir-v-link-g2-separate-d.md)).

**Nothing in the build graph orders `slang-glslang` before a SPIR-V compile.** `slangc` REQUIRES `slang-glsl-module`, `generate_core_module_cache` and the DXC copy targets (`CMakeLists.txt:736-743`) but not the dlopen'd `slang-glslang` MODULE, so a FetchContent/`add_subdirectory` consumer whose custom command runs `$<TARGET_FILE:slangc> -target spirv` can race ahead of `libslang-glslang-<ver>.so` and fail with E00100 "failed to load downstream compiler 'spirv-opt'" (the "failed to load dynamic library 'pthread'" beside it is a harmless first probe). Prove the missing edge without a race: `ninja -t inputs <output> | grep libslang-glslang` gives 0 hits, and a clean `ninja <output>` reproduces (about 4 minutes on 64 cores) where a full `ninja` may pass by job order. The consumer fix is `DEPENDS slang-glslang` or `add_dependencies(<tgt> slang-glslang)`. DeepWiki wrongly says slangc has `OPTIONAL_REQUIRES slang-glslang`; that is slang-test (`tools/CMakeLists.txt:352`) ([no build dep on slang-glslang](../learnings/1792402895620-slang-cmake-slangc-has-no-build-dep-on-runtime-loa.md), shader-slang/slang#13746).

**Tracing slangc → slang-glslang calls without a debugger** (the analysis container has no gdb, lldb, ltrace or strace; #13795). A forwarding `shim.cpp` exports `glslang_compile_1_3`, `glslang_validateSPIRV`, `glslang_disassembleSPIRV` and `glslang_linkSPIRV`, includes `source/slang-glslang/slang-glslang.h`, dlopens `$REAL_GLSLANG`, logs `r->action`, `r->optimizationLevel` and `r->spirvOptimizationFlagCount`, and forwards. Name it `libslang-glslang-<SLANG_VERSION_NUMERIC>.so` (e.g. `libslang-glslang-2026.13.1.so`) inside a directory and pass `-spirv-opt-path <dir>`. The `.so` path itself fails with E00100 (the loader appends `/pthread` and the library name), so `-spirv-opt-path nonexistent.so` is a command-line repro of "slang-glslang missing". `LD_DEBUG=libs slangc … 2>&1 | grep slang-glslang` quickly checks whether it loads at all ([logging shim](../learnings/1792539973371-trace-slang-glslang-calls-without-a-debugger-loggi.md)).

**Granular pass selection (#12204):** `-OX` levels are hand-unrolled presets (~40 `RegisterPass` calls, `slang-glslang.cpp:316`). Use the bundled `spvtools::Optimizer::RegisterPassesFromFlags(flags)` (`optimizer.hpp:140`), passing the string across the C ABI as a new `glslang_CompileRequest_1_3`. No correctness risk (spirv-opt is size/perf only), but it ties the CLI to the bundled SPIRV-Tools version ([RegisterPassesFromFlags](../learnings/1784829679560-granular-spvopt-pass-selection-registerpassesfromf.md)).

## What each optimization level runs

**Default optimization runs spirv-opt**, even for plain `-target spirv-asm` with no `-O`: the level is Default, so `glslang_optimizeSPIRV` runs the `#elif 1` DEFAULT preset, `CreatePrivateToLocalPass` included ([default opt runs spirv-opt](../learnings/1781714495665-slangc-target-spirv-asm-at-default-opt-does-run-sp.md)). That pass moves a `Private` var used in one function to per-call `Function` storage without checking that the function runs once per invocation, breaking function-`static` persistence; the fix removes both live registrations ([private-to-local](../learnings/1781713084820-spir-v-function-static-state-loss-spirv-tools-priv.md)).

**`-O0` is a faithful no-spirv-opt proxy.** `needsOptimization = getOptimizationLevel() != None` maps None → downstream None and `glslang_optimizeSPIRV` early-returns; the always-on `legalizeIRForSPIRV` does not depend on `-O`. A study of what spirv-opt buys must state that binary size ≠ GPU runtime (the driver re-optimizes), that only large real shaders show the 50-70% size win (tests/ do not), and that no size/perf harness exists ([-O0 proxy](../learnings/1784653425624-o0-is-a-faithful-no-spirv-opt-proxy-spirv-opt-is-s.md)).

**`-O<n>` never changes the Slang IR pipeline.** It only sets `CompilerOptionName::Optimization`, which only downstream compilers read: IR dumps match at `-O0` and `-O1`, and WGSL (no downstream compiler) is byte-identical at every level. `-minimum-slang-optimization` does change Slang's passes (it skips the late `simplifyIR` after `lowerBitCast` and runs SCCP once), so test IR-fold fixes under it ([-O<n> is downstream-only](../learnings/1792593053197-slang-o-n-does-not-change-ir-passes-test-ir-fold-f.md); WGSL detail on [[wiki/concepts/slang-backends-wgsl-f16-and-const-expressions.md]]). Any `-O0`/`-O1` SPIR-V difference therefore comes from spirv-opt; the `-g2` case (ADCE duplicating `DebugValue`s and deleting `_dbgvar_` shadows with their `DebugDeclare`) is on [[wiki/concepts/slang-backends-spirv-debug-info-emission.md]] ([`_dbgvar_` at -O0 vs -O1](../learnings/1792627978559-spir-v-g2-dbgvar-helper-vars-o0-duplicates-real-st.md)).

**Unused shader parameters: `-O0` does not keep them, and `-preserve-params` holds on SPIR-V only at `-O0`.** Consider a `cbuffer` used only inside `if (false)`. With slangc 2026.20 and `-target spirv-asm` it is dropped at `-O0`, even with `-minimum-slang-optimization`, because Slang's `simplifyIR` SCCP/DCE always runs. `-O0 -preserve-params` keeps it (`slang-ir-link.cpp` ~L2340 clones the global params with KeepAlive, `slang-ir-ssa-simplification.cpp` ~L30 reads `keepGlobalParamsAlive`, `slang-emit-spirv.cpp` ~L12214 calls `ensureInst`). `-reflection-json` still lists a dropped parameter with its set and index, so tools needing the full binding list should use Slang reflection, not spirv-reflect or SPIRV-Cross. `isParameterLocationUsed` is on `slang::IMetadata`, not `ProgramLayout`, and is wrong for some entry-point parameters (#13789, draft fix #13811) ([-O0 does not stop Slang DCE](../learnings/1792894686825-o0-does-not-stop-slang-dce-of-unused-params-preser.md)). Every SPIR-V level above `-O0`, the default `-O1` included, drops the parameter again, because spirv-opt runs whenever the level is not None (`slang-emit.cpp:3620-3623`) and strips unused variables; GLSL and HLSL keep it at every level. Issue #6947 (open) tracks this and the help text still promises "even if they are not used", so advise "`-O0 -preserve-params`", not just "avoid `-O3`" ([-preserve-params only at -O0](../learnings/1792916425472-preserve-params-keeps-unused-globals-in-spir-v-onl.md)).

**Default opt inlines the whole SPIR-V call graph; other targets keep it.** At `-O1`+ `-target spirv` runs `CreateInlineExhaustivePass`, leaving a single `OpFunction` (a 4-wrapper repro gives 1 by default, 7 at `-O0`). `source/slang-glslang/slang-glslang.cpp` holds three DEFAULT preset copies behind `#if 0` / `#elif 1` / `#else`; only `#elif 1` is live, with its inline pass at :367 (verified at 98ea350615), so do not cite the dead :343 and :422; HIGH/MAXIMAL registers it at :470. To see Slang's own SPIR-V function and parameter shapes (by-value vs pointer params, #13703), compile at `-O0` or use `-dump-ir-after transformParamsToConstRef`, which runs only for SPIR-V/Metal/CUDA/CPU (`slang-emit.cpp:2496-2534`); WGSL, HLSL and GLSL keep struct `in` params by value ([SPIR-V -O1 fully inlined](../learnings/1792160953423-slang-spir-v-default-o1-is-fully-inlined-by-spirv-.md)). WGSL and HLSL keep every non-`[ForceInline]` function (WGSL legalize does "no extra inlining", `slang-ir-wgsl-legalize.cpp:230-234`), leaving inlining to Tint/DXC and the driver; Slang's own IR inliners (`slang-ir-inline.cpp`) act only on decorations or legality rules with no call-count or size heuristic, and no slangc option controls inlining. On non-lib DXIL the cost lands in DXC, each single-call wrapper level adding inliner time for byte-identical DXIL (#13960: depth 0/4/8 takes 7.1/8.6/10.4 s; `[ForceInline]` brings 4 and 8 back to about 7.0 s). That atom's own line map swaps the live and dead copies ([#13960 inlining cost](../learnings/1793108645180-slang-spir-v-output-is-fully-inlined-by-spirv-opt-.md)).

**SlangPy kernel abstraction:** at `-O3` it collapses to 0 `OpFunctionCall`, byte-identical to a hand-rolled kernel. Runtime index arithmetic (1 sdiv + 1 srem + strided loads) is design-inherent, not a codegen defect ([folds at -O3, deferred to nvrtc for CUDA](../learnings/1781017004302-slangpy-generated-kernel-abstraction-fully-folds-i.md), [SPIR-V opcode census](../learnings/1781050949927-measure-slangpy-generated-kernel-codegen-quality-g.md)).

## spirv-opt aborts and the `-O0` default

**fp8 constants abort in spirv-tools:** `GetWordsFromScalarFloatConstant` (`opt/folding_rules.cpp`) asserts width 16/32/64, though the integer sibling handles 8; upstream fix #11766, Slang expected-failure #11744 ([fp8 width-8 gap](../learnings/1782449605671-fp8-scalar-float-constants-abort-in-spirv-tools-co.md)). **The slang-test `-O0` default (PR #11805) hides such aborts rather than fixing them**: suppressions for tests aborting inside spirv-opt (fp8 #11766/#11767 at `folding_rules.cpp:156`) can be dropped without the upstream fix, but users at `-O1+` still hit the bug. GPU-free repro: a Debug slangc exits 134, and 0 with `-O0`; Release compiles the assert out. Render-test checks device features BEFORE compiling, so a `(vk)` test compiles only where a Vulkan device (e.g. lavapipe) exists ([suppressions droppable via -O0](../learnings/1783036168133-spirv-opt-crash-suppressed-via-expected-failure-li.md)). Suite-wide `-O3` (#12247) revives the asserts, so a "resolved" #11805-era issue may just be dormant. Live sites: fp8/CoopVec constants (`folding_rules.cpp:156/:3539`) and `spirv_asm` `OpMemberDecorateIdEXT` (ADCE `:1000 assert(false)`). A debug `assert()` bypasses the `messageConsumer`/`SLANG_FAIL` path and on Windows shows up as "exit 3 / hang / lost JSON-RPC worker" in a sibling test, so verify each suspect standalone; about 77 of 79 failures were benign drift ([-O3 revives dormant asserts](../learnings/1785203893114-suite-wide-spirv-opt-o3-revives-dormant-spirv-tool.md)).

## Folding, unrolling and CSE limits

**spirv-opt's LoopUnroll skips Slang's `[unroll]` loops at -O2/-O3.** Slang lowers `[unroll]` to `OpLoopMerge … Unroll`, yet a constant-trip loop such as `for (i = 0; i < 10; ++i) sum += i` survives the bundled preset (`slang-glslang.cpp:493`, upstream `RegisterPerformancePasses` order). `Loop::FindConditionBlock` (spirv-tools `loop_descriptor.cpp:619`) requires the merge block's single in-loop predecessor to be the `OpBranchConditional`, but Slang's output still has a trampoline `%x: OpBranch %merge` from the breakable-region wrap, and BlockMerge runs only later; running `spirv-opt -O` twice, or BlockMerge just before LoopUnroll, unrolls and folds it to a constant. DXC and NVRTC fold such loops with no hint, so "loop not folded at -O3" is SPIR-V-specific. Related: spirv-opt has no GLSL.std.450 `SAbs` constant-fold rule (`SMin`/`SMax`/`SClamp` exist), and Slang IR keeps integer `abs`/`min`/`max`/`clamp`/`sign` as opaque target-intrinsic calls, so a `[ForceUnroll]` bound built from them gives E40020 while the ternary form folds (#13424) ([LoopUnroll skips `[unroll]`](../learnings/1791074922027-spirv-opt-loopunroll-silently-skips-slang-s-unroll.md)).

**Invalid SPIR-V only at optimization levels points at spirv-opt (#12104).** `output[0] = (value<eps) ? 0 : (value/value)` for a runtime `float3` emits `OpConstantComposite %v3float %float_1 ×4`, which spirv-val rejects. The maintainer's leads (Slang's `processConstructor`/`emitCompositeConstruct`/`MakeVector`) are wrong; the reusable layer-isolation drill: (1) `-dump-ir` shows `div(%value,%value)` intact through every pass, so Slang IR does not fold it; (2) `-O0` emits a correct `OpFDiv` and every other level the bad constant, and the only delta is `slang-emit.cpp` routing SPIR-V through `PassThroughMode::SpirvOpt` (vendored spirv-tools v2026.3); (3) `-fp-mode precise` gives `OpFDiv ; NoContraction` and `-fp-mode fast` the bad constant, an IEEE-unsafe `x/x→1` fold (0/0 = NaN); (4) float2, float3 and float4 all get 4 constituents, a hardcoded 4 rather than a vec4→vec3 shrink. Slang's peephole folds `v-v` to a correct zero vector and leaves `v*v` as `OpFMul`; only `v/v` (no `x/x→1` rule in slang-ir-peephole/sccp) reaches the downstream fold. Fixes: (A, root) make `external/spirv-tools/source/opt/folding_rules.cpp` use the result type's component count (upstream + submodule bump); (B, in-tree now) a fast-math-gated `x/x→1` Slang peephole producing a correctly sized ones vector, so spirv-opt never sees `OpFDiv %a %a` ([#12104 is spirv-opt's x/x fold](../learnings/1784072018251-slang-12104-vec3-opconstantcomposite-4-constituent.md)). An earlier repro-blocked triage (jkwak's `float3(float2(1,1),1)` and ~11 minimal shapes all emit 3 constituents) rightly ruled out the sub-vector UNDER-count path, which `processConstructor` flattens (`slang-ir-spirv-legalize.cpp:1795-1810`); its post-legalize-fold suspect is superseded. Its standing net still holds: `emitOpConstantComposite` (`slang-emit-spirv-ops.h:1417-1425`) has no constituent-count == element-count check, and an assert there makes silent invalid output loud, though it cannot catch #12104, whose constant is minted after emit ([#12104 repro-blocked triage](../learnings/1784069141044-slang-spir-v-vec3-opconstantcomposite-over-count-r.md)).

**spirv-opt will not CSE `OpGroupNonUniform*`.** Both CSE passes use `ValueNumberTable`, which gives every non-combinator a fresh value number, and `AddCombinatorsForCapability` lists no group/subgroup/ballot op; a group op depends on the active-lane set, so CSE or hoisting would be unsound. Dedup ops such as `WaveActiveCountBits` + `WavePrefixCountBits` (both emit `OpGroupNonUniformBallot`) in Slang IR with a participation-fenced block-local pass (PR #12848), never via `isMovableInst` ([no CSE of group ops](../learnings/1789578103315-spirv-opt-won-t-cse-opgroupnonuniform-they-re-non-.md)). PR #12848 is unmerged: an open draft on 2026-10-19 (last updated 10-02), and on 09-17 the maintainer was "considering NOT to proceed" and asked for the SPIRV-Tools layer to be checked. Run `gh pr view 12848 --json isDraft,state` before citing it ([#12848 is a draft](../learnings/1792423080231-slang-12847-pr-12848-is-still-a-draft-local-master.md)).

Float reassociation under default fp-mode (#12160) is also a spirv-opt fold, gated on `NoContraction`; see [[wiki/concepts/slang-backends-spirv-precise-and-nocontraction.md]].
