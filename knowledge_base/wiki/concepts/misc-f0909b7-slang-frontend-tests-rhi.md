## TL;DR

Firsthand facts about the Slang front-end/test-tool surface and the slang-rhi runtime, plus two triage-methodology rules.

- **slang-test conventions:** surface per-test problems through `context->getTestReporter()` (assert it on the runtime path, don't stderr-fallback); a rich diagnostic with a differing `span { message }` emits a *second* machine-readable row that exhaustive `DIAGNOSTIC_TEST` mode fails unless annotated.
- **Core exception rule:** `source/core` and `source/compiler-core` compile with exceptions disabled — never bare `throw`; route through the signal mechanism (`SLANG_UNEXPECTED`), but preserve a real catch site.
- **"Single source of truth" is per-COLUMN.** A unified descriptor table can still have a hand-maintained name-drift seam when two consumers key on different columns.
- **CPU value-check harness trap:** `createDynamicObject`+`type_conformance` doesn't feed distinct tags on `-cpu` — use a plain factory returning concrete types when asserting numeric output.
- **Bindless / DescriptorHandle (a correction chain):** slang-rhi's Vulkan combined-texture-sampler uses a *self-consistent fused* `COMBINED_IMAGE_SAMPLER` single-index (`.x`) model — this is a **valid design choice, NOT a bug**. The earlier "VK is missing a `.y` sampler-heap slot" framing was wrong; the two-heap `SamplerHeapEXT[.y]` contract only applies under the `spvDescriptorHeapEXT` capability. SPIR-V passing validation rules out a *structural* defect, not runtime/semantic correctness.
- **slang-rhi runtime facts:** `ConstantBufferPool` is per-command-buffer, duplicated across 5 backends, and `reset()` frees pages only on CUDA (a permanent high-water leak on D3D12/Vulkan). But trace the *caller lifecycle* — only D3D12/Vulkan cache command buffers, so a free-on-reset fix is dead code on D3D11/WGPU.
- **Triage rules:** a "test over-specifies" claim is usually true AND hides a separate latent producer gap — recommend both, block neither; an anticipatory-guard's zero-invariant is a *future* state gated on an unmerged PR — verify against ToT, not the issue's premise.
- **DeepWiki is for architecture/flow, not line-level behavior** — a source-grounded subagent overrules it on specific code behavior.

## slang-test, diagnostics, and core-library rules

On the runtime test-execution path (`processFile → _runTestsOnFile → _gatherTestsForFile`) the reporter is *guaranteed* present (set at the thread scheduler / non-threaded entry before dispatch, and a sibling failure path derefs it unconditionally) — so the maintainer convention is `SLANG_ASSERT(context && context->getTestReporter())` and delete the `fprintf(stderr,…)` branch as dead code; the caveat is that `TestReporter*` *is* nullable elsewhere in the file, so trace the actual call graph to the specific site before converting a null-check to an assert [slang-test reporter is guaranteed at the processFile path — assert, don't stderr-fallback](../learnings/1787779570701-slang-test-reporter-is-guaranteed-at-processfile-p.md). A diagnostic defined with both a top-level message and a `span { message }` emits *two* machine-readable records; the span row is deduplicated against the primary only when their text is identical, so a differing span survives and an exhaustive `//DIAGNOSTIC_TEST` annotating only the error code FAILS — annotate both rows or add `non-exhaustive` (diagnostic tests need no GPU, so run them) [rich diagnostics emit a separate span row; exhaustive DIAGNOSTIC_TEST must annotate it](../learnings/1787794172021-rich-diagnostics-emit-a-separate-span-row-exhausti.md). And in `source/core`/`source/compiler-core`, a bare `throw` is a hard compile error under `-fno-exceptions -DSLANG_DISABLE_EXCEPTIONS=1` — route through the signal mechanism (`SLANG_UNEXPECTED`), but watch for a genuine catch site (e.g. `TextFormatException` is caught for recovery) that must keep its throw path when exceptions are on; you can prove a header-only fix compiles under both configs against `/dev/null` without touching the repo [core/compiler-core must compile with C++ exceptions disabled](../learnings/1787782198291-slang-core-compiler-core-must-compile-with-c-excep.md).

Two more front-end/test facts. A refactor advertising "the two consumers cannot drift" via one descriptor table can still have a hand-maintained seam: `kOperatorNameInfos[]` is read by `tokenType` (parser) and by `name` (checker), and `operator()`/`operator?:` have names produced from *hardcoded literals* not the table — "single source of truth" claims are per-column, and a fix is an assertion at the production point [a single source of truth table can still have a hand-maintained name-drift seam](../learnings/1787783984271-a-single-source-of-truth-table-can-still-have-a-ha.md). When a dynamic-dispatch `.slang` test must validate *computed values* for two conformances on `-cpu`, do not use `createDynamicObject<IFace>(type_id,0)` with a `type_conformance` wiring — on CPU both existentials resolved to the same concrete type (a test-harness artifact that looks like a compiler bug); use a plain factory returning concrete types and reserve `createDynamicObject` for compile-only crash-coverage [createDynamicObject + type_id mis-wires on CPU COMPARE_COMPUTE value-checks](../learnings/1787937181861-createdynamicobject-type-id-mis-wires-on-cpu-compa.md).

## Bindless DescriptorHandle: a triage that corrected itself

This is a contradiction resolved within the batch. An initial triage of the Vulkan combined texture+sampler crash (#12784) reasoned that Slang's SPIR-V emission for a combined-sampler `DescriptorHandle` reads the texture from `ResourceHeapEXT[.x]` and the sampler from a *separate* `SamplerHeapEXT[.y]`, while the sampler-less path emits `OpImageFetch` and never touches the sampler heap [DescriptorHandle combined-sampler heap access reads a separate sampler-heap descriptor](../learnings/1787794830441-descriptorhandle-combined-sampler-heap-access-read.md) — and concluded slang-rhi's Vulkan backend is buggy because it leaves `handle.y` uninitialized [slang-rhi Vulkan bindless combined-texture-sampler handle has no .y sampler-heap slot](../learnings/1787794960161-slang-rhi-vulkan-bindless-combined-texture-sampler.md). **The CORRECTION supersedes both**: slang-rhi's VK backend writes a *real fused* `VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER` descriptor and stores a single 32-bit slot in `.x` — a self-consistent single-index model that never reads `.y`; it simply doesn't implement the `spvDescriptorHeapEXT` two-heap model, which is a valid design choice, not a defect (do NOT file a slang-rhi "fix `.y`" PR). The two-heap `SamplerHeapEXT[.y]` contract only applies under the `spvDescriptorHeapEXT` capability [CORRECTION: slang-rhi Vulkan bindless uses a fused COMBINED_IMAGE_SAMPLER model](../learnings/1787796424823-correction-slang-rhi-vulkan-bindless-uses-a-fused-.md). The durable process lesson: SPIR-V passing `SLANG_RUN_SPIRV_VALIDATION=1` rules out a *structural* defect but not runtime/semantic correctness — state such a verdict as a hypothesis pending a GPU capture, and always re-read cross-repo source before asserting one backend is "buggy" relative to another.

## slang-rhi ConstantBufferPool leak and build gotchas

`ConstantBufferPool` is a direct member of each backend's `CommandBufferImpl` (per-command-buffer, no shared base class) — fully duplicated across D3D12/Vulkan/D3D11/CUDA/WGPU, so a behavior fix is per-backend. On D3D12/Vulkan/D3D11 `reset()` only rewinds cursors and does NOT free `m_pages`; CUDA (the correct model) frees every page. Free-on-reset is GPU-safe because `reset()` is reached only via fence-gated retirement [slang-rhi ConstantBufferPool is per-command-buffer, reset() frees pages only on CUDA](../learnings/1787809893009-slang-rhi-constantbufferpool-is-per-command-buffer.md). But not every duplicated copy has the leak: only D3D12/Vulkan cache command buffers (`CommandQueueImpl::m_commandBuffersPool` + call `reset()` at retirement), while D3D11/WGPU new a fresh command buffer per encode — so a free-on-reset change there would be dead code; trace the caller lifecycle, don't assume all 5 copies need the same fix. This atom also carries the slang-rhi build divergences from the compiler repo: default branch `main`, CI auto-runs on draft PRs, `-DSLANG_RHI_BUILD_TESTS_WITH_GLFW=OFF` for headless builds, `pre-commit` formatting with clang-format v20.1.7 + an ASCII hook, and the `dynamic_cast<DebugDevice*>->baseObject` white-box unwrap idiom [slang-rhi build + backend-cache gotchas (issue 844)](../learnings/1787815902770-slang-rhi-build-backend-cache-gotchas-issue-844.md).

## Two triage-methodology rules

A "this CI failure is test-only over-specification, no compiler fix needed" claim should be verified structurally, and the answer is usually **both layers at once**: pull the exact failing assertion line (not just the job name), see which *sibling* assertion passed (the passing sibling is the real contract, the failing one pinned incidental behavior), and trace the producer — recommend the test fix now PLUS a separate low-priority issue for the latent producer gap; block neither on the other [triaging a "test over-specifies" claim: find the exact failing assertion, check which sibling passed](../learnings/1787815901109-triaging-a-test-over-specifies-claim-find-the-exac.md). And an anticipatory-guard issue ("add a grep-asserts-zero guard so X never regresses") whose premise is "the repo now contains zero occurrences of X" must be verified against current master — the zero-invariant is a *future* state gated on an unmerged PR, so confirm the gating PR's merge status and prove the post-merge count by grepping the PR-head blob; the guard must NOT land before the fix or it red-fails CI on the existing occurrences [anticipatory-guard issues: verify the invariant against ToT, not the issue's premise](../learnings/1787818183441-anticipatory-guard-issues-verify-the-invariant-aga.md).
