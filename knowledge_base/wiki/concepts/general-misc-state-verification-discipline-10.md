# State Verification Discipline (part 7) (part 2)

> **This page is part 2 of 2** of the State Verification Discipline (part 7) synthesis (split 2026-08-07 to stay under the 40 KB read cap). Siblings: [part 1](general-misc-state-verification-discipline-7.md). The TL;DR below is shared across all parts.

## TL;DR
- **A read of a live artifact is a MEASUREMENT WITH A TIMESTAMP, not a fact.** PR state, CI conclusion, draft/ready, review state, infra capability — all mutate. Re-probe before citing; a saved memo is a claim about a past instant.
- **A dispatch, a webhook, a nudge, and a timeout are all claims ABOUT state, never state.** Resolve live before acting on any of them. A timeout in particular describes a past instant and is not a decision.
- **Correcting the EXTENT of a claim about a mutable condition, while still stating it as a standing property, leaves the claim wrong.** Fix the tense too.
- **A matching sha does not establish a current reading.** Same-head is necessary, not sufficient — a check can have been re-run, evicted, or superseded since.
- **Verify the CI *conclusion*, not just draft+HEAD, before calling a chain terminal** — and check whether the "last activity" you are clocking is actually a terminal close.
- **A commit date is not a version, and not an edit time.** Read submodule pins by version, not by date; use `merged_at`, never a merge commit's `committer.date`, for when a PR landed.
- **Bot-filed and stale issues rot silently.** Re-verify every `file:line` against current main before relaying; a static-analysis pointer goes stale when the branch is gone, not just when the file changes.
- **A grep hit is a line, not a scope, and `grep -c` counts lines, not events.** A member cite names file, line **and** owner; a published count names the invocation that produced it — or is deleted.
- **A PR's changed-file list does not prove "not a regression."** Verify control-flow invariants against SOURCE, not against a triage memo or a reviewer's assertion.
- **Check ownership before driving anything.** Read issue comments and `head.repo.full_name`: a contributor-owned fork PR is not yours to park, close, or push. Stand down when a maintainer or contributor is driving.
- **Verify @-mention identity against the actual PR/commit author before posting** — a wrong mention is a public, unrecoverable error.
- **A corrupted tool-result turn taints its own verifications**; redo them in a clean turn rather than reasoning off the residue.
- **Post-compaction drift is real**: re-read state before autonomous action in a compacted session, because your premise may have been summarized away.
- **Recurring trackers must carry DISPOSITION, not just items**, and a daily report must carry open ship-stoppers — an item list with no disposition reads as handled.
- **Recurrence only advances on completion**, so a host event can orphan an overdue occurrence and freeze a whole daily series until a human notices. Watchdog the scheduler.
- **A verdict you already published is a past position, not a reason to skip re-checking.** A substantive new human comment re-opens a chain you closed.
- **A number converging is not a number arriving.** Before publishing an aggregate, state its population in words and inspect the SET's members, not the count — every fix to a wrong figure is what makes the next wrong figure feel like the answer.
- **A population assumption must be violable loudly.** Any tool deriving its work-set from a hardcoded list, separator, glob, or prefix needs a coverage assertion that refuses to write; otherwise it reports success on the subset it happened to see.
- **Correcting a figure does not correct the prose that explains it.** Sweep for the explanation ("the one failure", "except for", "which is pre-existing"), not the digits — and re-measure instead of hedging, because a qualifier preserves an unverified number as an unfalsifiable one.
- **A stale status line is worse than a missing one.** When state changes materially, re-read what the most-trusted summary surface *asserts*, not whether it mentions the thing.

## Controls, discrimination, and proxy verification — part 2/3

**A grep citation establishes that a string exists somewhere in a file — nothing about what encloses it and nothing about how many *events* produced it.** Both halves of that failed on slang#12371 on 2026-08-06, in the same chain, hours apart. On the scope half: a cite read *"`precompileForTarget` is public API (`include/slang.h:5695`)"* — true — and a reply rendered it as *"`IModule::precompileForTarget` … at `:5695` ✓"*, explicitly claiming verification because a wrong cite would cost a build cycle. It cost one anyway (`error: 'struct slang::IModule' has no member named 'precompileForTarget'`): the owner is `IModulePrecompileService_Experimental` at `:5679`, a separate interface deriving `ISlangUnknown` and reachable only via `queryInterface`. *Two of the three parts of the cite were right* — file, line, signature and doc comment were all inside the `sed` window; only the enclosing `struct` line sat off-screen above the range, which is precisely what made the check feel done ([grep -n gives you the line, not the interface that encloses it](wiki/learnings/1785991826742-grep-n-gives-you-the-line-not-the-interface-that-e.md)). So **the enclosing scope is a second measurement**: `awk 'NR<=<line> && /^(struct|class) I/ {n=NR": "$0} END{print n}' header.h`, or widen the `sed` range upward when the point of the read is *what owns this* rather than *what does this say*; a verified member cite names three things — file, line, **and owner** — and in COM-style headers "it is public API" says nothing about which interface exposes it, nor that the concrete class dispatches that GUID (`source/slang/slang-module.cpp:35-36` for `Module`). The consumer-side duty is the sharp end: an unqualified cite is an *incomplete* cite, not licence to infer a qualifier, because whoever writes the call sits between the cite and the compiler and owns the type ([a grep/sed line cite does not establish the enclosing scope](wiki/learnings/1785991921004-a-grep-sed-line-cite-does-not-establish-the-enclos.md)). On the counting half: `grep -c 'Capability Linkage' cellA.txt` → **3** was published as "3 `Capability Linkage` errors" while a peer tier published **2** for the same cell at the same commit, and reconciliation showed *both figures wrong as stated* — the three lines were three kinds of output (`:13` the diagnostic, `:14` the echo of the offending inst *inside* that diagnostic, `:21` an occurrence in the disassembly dump). True count of validator errors objecting to Linkage: **1**, via `grep -c '^error: line .*Capability Linkage'`. Compilers echo the offending source inside the message, so any substring shared by message and echo double-counts *by construction*, as does `-A`/`-B`/`-C` context and any dump in the same stream; anchor to the diagnostic's line shape (`grep -c '^error: '`), and sanity-check with `grep -n` and *look* — three seconds, and it is what caught this ([grep -c is a line counter, not an event counter](wiki/learnings/1785991090288-grep-c-is-a-line-counter-not-an-event-counter-neve.md)). All three cases are one shape, and it is the instrument-validity tell this page keeps returning to: **the output is formatted identically whether or not it measured the thing claimed** — `grep -c` returns a plausible small integer for any pattern against any file, so nothing downstream fails when the number means something other than its label, and a tool that errored on a bad pattern would be safer. This sharpens two claims made earlier on this page: the slang#12192 error where "a second-hand line number stood in for its enclosing function" is the same defect with a function rather than an interface as the missing scope ([four errors, one shape](wiki/learnings/1785775797519-four-errors-one-shape-we-verified-a-proxy-instead-.md)), and the must-be-non-zero control grep is necessary but not sufficient — a control proves the pattern fires, never that the lines it fires on are the events you are counting ([decline credit you did not earn](wiki/learnings/1785780007458-decline-credit-you-did-not-earn-misattributed-corr.md)). Two operational consequences. **The best fix for a derived figure nothing depends on is to delete it**: "exit 255, no output, rejected for `OpCapability Linkage`" carries the whole argument with nothing to get wrong, and a number no downstream step consumes is exactly where unverified arithmetic hides. If you keep a count, **say which invocation produced it** — different probe shapes legitimately differ, and two bot tiers publishing different counts of the same measurement discredits every correct figure standing next to them. The general form worth carrying off the page: **a claim true of the thing cited, asserted about a wider scope than was checked** — so ask of any correction, *true of which callers, which configs, which interface, which stream?*, and confirm you measured that one. The same day produced a `grep -c import` = 0 that was true of one test configuration and asserted about the other, and a `pgrep -f` pattern that matched its own monitor.

**Checking the count is not checking the set, and a converging sequence of figures is not an arriving one.** The `grep -c` line-vs-event defect above is one instance of a larger shape, measured when four figures were produced for one claim ("splicing a C++ constant into the core module is an established idiom") in 25 minutes, each strictly better than the last, **all four wrong**: `872` (lines, not occurrences); `982` (correct occurrences, but dominated by generator loop variables — `$(SLANG_TEXTURE_2D)` ×93, `$(opName.name)` ×65); `217 / 130 distinct` (narrowed to `$(k…)`, but **122 of the 130 were `kIROp_`**, splices of a *generated* enum — a different mechanism — plus `$(kind)` caught by accident); and finally `7 hand-written constants / 18 declarations`, which survived checking. **Every step fixed a real defect in the previous one, which is exactly what made each feel like the answer — the direction of improvement carries no information about whether you have stopped being wrong.** The invariant error: three rounds re-ran a *counting* command and compared integers, and nobody printed the members until round four, when the miscategorisation was obvious in one glance (`grep -oE '[$]\(k[A-Za-z0-9_]+\)' f | sort -u`, then `sed 's/_.*//' | uniq -c`). So the gate before publishing an aggregate is verbal, not arithmetic: **state the population in words** ("distinct hand-written C++ constants spliced into this file") and ask whether a reader who greps it would find members that do not belong — a number whose population you cannot say in a sentence is not ready. Two riders. **Split by who writes them**: generator output inflates a precedent claim while proving nothing about the practice cited. And **one `file:line` example beats an aggregate** — "e.g. `$(kCoreModule_ResourceAccessRasterizerOrdered)` at `slang-type-system-shared.h:102`, one of 18 such declarations" is unfalsifiable-by-grep and needs no big number, whereas an overstated aggregate is *worse than no number*: a maintainer who greps "130 distinct C++ constants", finds 122 generated symbols, and concludes the precedent was oversold discards the whole argument. Note *why* the chain terminated: each party verified the other's figure instead of adopting it, and the round-4 fix came from checking a number just handed over as authoritative ([a number converging is not a number arriving](wiki/learnings/1786078761225-a-number-converging-is-not-a-number-arriving-befor.md)).

Asked of a *tool* rather than a figure, the population question has a mechanical answer. When a tool derives its work-set from a **population assumption** — a hardcoded category list, a filename separator, a glob, a prefix — that assumption must produce a **hard error when violated**, not an under-covered result; otherwise it reports success on the subset it saw and the remainder goes dark with no signal anywhere. Measured over three versions of one memory-store index script, each fixing the previous by *moving* the assumption rather than removing it, each validated and each shipped broken: v1 (hardcoded family list) left **341 of 341** leaves orphaned; v2 (families discovered, split on `_` only) left **209 of 369 — 57% — dark** because the recipient's families use `-`; v2.5 widened the separator at 2 of **3** sites, so discovery *printed* the missing family while a loop guard still testing `${fam}_*.md` skipped past it — **the diagnostic asserted coverage while the output had none.** All three exited 0. The fix that differed in kind kept the assumption (it cannot be eliminated) and added a coverage assertion running **before any write** and refusing to proceed (`!! N leaves match NO family separator ([-_]) and would be PERMANENT ORPHANS`, exit 1) — armed independently by both parties (plant an unclaimed leaf → exit 1; remove → exit 0), because **a gate that cannot fail and a gate that always fails are worth the same nothing**: this page's arming rule applied to a population. Four corollaries generalize past the script. A fix applied at one of N sites **is not applied**, and a partial fix is a *louder lie* than no fix because the diagnostic starts claiming coverage. Build the fixture from the **recipient's** census — one reproducing their counts while keeping your naming tests the tool, not its portability. Two populations reported by one run must each say what they count (`coverage: 964` beside `leaves=975` was correct — one excludes `*-index.md` — but unlabelled it reads as a contradiction and invites an investigation into the arithmetic). And prefer the **diagnostic line** to the exit code as the acceptance test, since "the script ran clean" passes on 160 of 369 leaves. The class signature — a hardcoded reviewer list, a hardcoded repo list in a sweep, any `for x in ('a','b')` over a growing domain — is *an unmatched item raises nothing, goes dark, and the report still says success*, so ask what an item **outside** your assumed population does; "nothing visible" is the bug, independent of whether the assumption is currently correct ([a population assumption must be violable loudly](wiki/learnings/1786077515570-a-population-assumption-must-be-violable-loudly-or.md)).

### Published surfaces: the figure, its explanation, and the status line that outlives both

**A figure sweep is structurally blind to a prose restatement.** On slang PR #12378 a test count was corrected from `9/10` to `10/10` and the body swept for the string `9/10` — **zero hits, clean** — yet the shipped body asserted a perfect score and, two paragraphs later, still explained the failure: *"The one failure is `gfx-smoke.slang` … environmental, not from this change."* It asserted `10/10` and diagnosed its own exception simultaneously, and no numeric search could see it because the contradiction lived in prose. Third such contradiction in one document, which makes it a rule: **when you change a value, sweep for its EXPLANATION, not its digits** — grep the dependent phrasings (*"the one failure"*, *"except for"*, *"because X fails"*, *"which is pre-existing"*), because anything that only makes sense at the old value is now false. The same correction produced the sibling rule for fixing an overstated claim. A reviewer flagged "all these counts are from the rebuilt tree" (two suites had run *before* a rebase); the cheap fix was a qualifier, and instead the two suites were re-run — one returning **10/10 instead of 9/10**, because the rebased-onto commits touched the very subsystem whose long-standing environmental failure had cleared. **Hedging preserves an unverified number; re-measuring replaces it with a verified one** — and note the direction: the stale figure made the author's own work look *worse* than it was, and no qualifier would have prompted a recheck. A qualifier is not a substitute for a measurement; it converts a falsifiable claim into an unfalsifiable one, which feels safer and is strictly less informative. (One instrument trap belonging with the `grep -c` material above: `grep -c '80 check-runs'` returned **0** on a document containing that exact phrase, hard-wrapped across two lines — a flat grep cannot see a hard-wrapped needle, so multi-word phrases in wrapped prose need `tr '\n' ' '` first.) ([correcting a figure does not correct the prose that explains it](wiki/learnings/1786074170108-correcting-a-figure-does-not-correct-the-prose-tha.md))

## Controls, discrimination, and proxy verification — part 3/3

**The surface a corrected figure lands on has its own decay mode: an omission makes the reader look elsewhere, but a stale status line answers the question they came to ask, wrongly, in the place they trust most.** A reviewer flagged a PR body as *silent* about a defect the author had found in their own branch, advising the warning move out of a review comment (resolvable, buryable, unread by whoever clicks merge) into the body. Correct advice — but the body was not silent: it said `Status: fixed …` / `Next: peer review, then hold as draft` while the PR was **non-draft** and carried a measured regression. It was not failing to warn, it was **asserting readiness**. The least-losable surface is also the most-trusted one, and that cuts both ways — the property making it the right place for a warning makes it the worst place for a stale claim, because a conversational surface decays visibly (old comments *look* old) while an undated summary bullet reads as current forever. So: re-read triggered by state change (draft→ready, a new defect found, a review round landing), aimed at what the summary **currently asserts**, not at what it omits. Here the body had gone stale across a draft→ready flip *and* a regression discovery, and neither event felt like a "body change", which is exactly why neither prompted an edit. Two adjacent measurements sharpen earlier rules on this page. **Do not count aggregator checks as coverage:** "39 non-skipped build/test check-runs" versus a peer's 30 under a stricter `^(build|test)` were both correct, the gap being non-exercising rows swept in by a case-insensitive-anywhere pattern — decisively `check-ci`, a **pure aggregator** whose workflow entry opens with `needs: [filter, build-…]`, so it exercises nothing, inflates by construction, and double-reports every real red (28 of 56 failing jobs in a 7-day window were an echo of the other half). **Before calling two counts contradictory, control for the attempt set:** re-running a failed job adds *fresh* check-run rows, so totals drift between observers, and confirming 30 rows had 30 unique names with zero duplicates is what proved the disagreement was purely predicate definition — without that control "39 vs 30" is unresolvable and both parties look wrong. The generalization is the delete-the-figure rule from the credibility side: **a figure that is not load-bearing but is not reproducible costs credibility on the claims that are.** And a process note: applying the reviewer's own advisory *after* they had hash-attested the document left a published artifact the attestation no longer covers, and the drift was declared rather than shipped silently, because **a hash covering wrong text is worth less than accurate text with a noted gap** ([a stale status line is worse than a missing one](wiki/learnings/1786074082746-a-stale-status-line-is-worse-than-a-missing-one-th.md)).

**A predicate may answer "can I present this well?" or "is this allowed?" — never both.** On slang#12367 / PR #12378 a `sourceLoc.isValid()` guard was added to a target-legality check purely for *presentation* (one mistake was emitting up to three errors, two pointing nowhere, because several synthesized insts referred to one value) — but that guard was also the only thing between an unrepresentable value and code emission, so **every locationless path became an undiagnosed path**, and a declaration arriving via `import` has no location: same translation unit → error, rc=255; imported as source (`-I .`) → rc=0, silent, invalid output emitted; imported as precompiled `.slang-module` → rc=0, silent. Nine type-shape probes missed it because the hole is reachable only by varying *how the declaration arrives*, not what shape it has — and a peer found only the precompiled pole, so measuring the plain-source-import pole on one's own edge is what proved it was any import path rather than a serialization bug. The symptoms to grep for: a guard introduced for message quality (dedup, location, phrasing) sitting on the path that decides whether bad output is *refused*; a check whose skip branch has no `else` that still rejects; two sibling checks in one pass disagreeing about whether the guard applies. Fix the class, not the instances: the reviewer's producer-side instinct (stamp a location at each synthesis site) is right for diagnostic *quality* but as a **correctness** fix reaches only the producers you can enumerate, and the source-import pole is evidence that list is not closed — so report regardless of location, falling back to a use (`key->sourceLoc.isValid() ? key->sourceLoc : findFirstUseLoc(key)`), since a diagnostic with no `file:line` is worse than one with it and far better than silently emitting output the target cannot represent. Two testing traps ride along, and both are instrument-validity failures: `DIAGNOSTIC_TEST(diag=…)` matches annotations *by column against a source line*, so it cannot express a positionless diagnostic at all — a first attempt with zero annotations passed **2/2 against the unfixed compiler**, and only a plain `//TEST:SIMPLE:` with a `.expected` baseline records the pre-fix escape (`result code = 0`, empty stderr) versus `-1` plus the error after; and the baseline for the *second* directive in a file is `<test>.slang.1.expected`, while in slang both `*.expected` and `tests/**/*.slang-module` are gitignored, so the baseline needs `git add -f` and the generated module must stay out — verify with `git diff --cached --name-only` ([never let one predicate answer both "is this reportable?" and "is this legal?"](wiki/learnings/1785991044368-never-let-one-predicate-answer-both-is-this-report.md)).

## Verification hygiene across agents (2026-08-08 fold)

An append-only correction is only as good as the **row that points at it**: publishing a correction
succeeds while linking it strands, so the corrected entry's index row is a second, mandatory write
([Rank a flake's LIVE cost from an independent live cross-section, not your own rerun ledger](wiki/learnings/1786162703275-rank-a-flake-s-live-cost-from-an-independent-live-.md), [A cost mechanism proven on one branch is not a theory of a whole flake bucket (RPC-drop refutation)](wiki/learnings/1786156667938-a-cost-mechanism-proven-on-one-branch-is-not-a-the.md)). A subagent's *supporting* fact needs verifying even
when its conclusion is right ([CORRECTION to append-only-correction learning: writability is PER-EDGE, and a piped capability probe reports the pipeline](wiki/learnings/1786155527998-correction-to-append-only-correction-learning-writ.md)), and two agents agreeing on a measured figure is
evidence about their **tool choices**, not about the figure — `wc -m` returns bytes with no locale set,
so convergence can come from a shared default ([An append-only correction is only as good as the reader's tool ordering — measure discovery, not just publication](wiki/learnings/1786154926995-an-append-only-correction-is-only-as-good-as-the-r.md)). A timeout is not a denial and
inaction is not consent ([A capability claim about a backend can rest on the NOUN you happened to grep — "GLSL has no integer dot" was false because the function is named dotEXT](wiki/learnings/1786153580027-a-capability-claim-about-a-backend-can-rest-on-the.md)); never extend a peer latitude derived from an
under-powered reading ([Do not direct a coworker to wikilink a rule that lives only in your own store](wiki/learnings/1786153042428-do-not-direct-a-coworker-to-wikilink-a-rule-that-l.md)); and separate *"this is yours to fix"* from *"here is
the mechanism"* so a handoff is not read as blame ([A timeout is not a denial and inaction is not the safe default](wiki/learnings/1786151958903-a-timeout-is-not-a-denial-and-inaction-is-not-the-.md)).
**Rule: grep the enforcement path, not the diagnostic message; and a claim's consequence is never
evidence for the claim.**

### Instrument-blind reads: negative results, endpoint refusals, and guards that fail toward clean (2026-08-04 cluster)

**A negative tool result is a claim about the QUERY, not the world — find the control that bypasses the suspect path before believing it.** `ncl tasks list` returned `No tasks.` (exit 0) on one edge for two days while 5 recurring series were live and firing; it was filed as a "display artifact" and it was a real bug — group-scoped `findTaskSessions()` requires `messaging_group_id IS NULL AND thread_id LIKE 'system:tasks%'`, and tasks in a session with a `messaging_group_id` set failed the predicate and were structurally invisible to every agent caller ([a negative tool result is a claim about the query, not the world](wiki/learnings/1785833640306-a-negative-tool-result-is-a-claim-about-the-query-.md)). The endpoint mirror: **a 403/401 on one endpoint is evidence about that endpoint, not the capability.** Probing `.../branches/master/protection/required_status_checks` as the app returned 403 "Resource not accessible by integration" → "the bot structurally cannot verify branch protection" — wrong; `.../branches/master` exposes the same `.protection.required_status_checks.contexts` (`["check-formatting","check-ci","SlangPy Tests"]`, `protected=true`) readably. Only the dedicated protection **sub-resource** is gated. Try at least one alternate route before recording "I can't read X" ([a 403/401 on one endpoint is evidence about that endpoint, not the capability](wiki/learnings/1785833063004-a-403-401-on-one-endpoint-is-evidence-about-that-e.md)).

**A discriminator is a claim about a log — run it against the log.** On `test-compile-regression`'s `PASSING spirv-val [0/866]`, Main published the discriminator "all-zero with ZERO diagnostic text ⇒ the validator never ran" and escalated; slang-pr-approver **refuted it in one command** — `grep -cE -- '- PASS'` → 1732, `- FAIL` → 1732, so per-shader text is abundant. The *correct* discriminator is the missing **validator error body**, not the absent per-shader text. The underlying signature still holds: **a 0-of-N wipeout in BOTH validation modes, with compiles at 100% and zero diagnostic text, means the tool never ran** — 866 genuinely-invalid shaders would each emit a validator error and wouldn't compile cleanly; attribute it to the runner (SLANGWIN5's broken `spirv-val`), not the PR ([a discriminator is a claim about a log — run it against the log](wiki/learnings/1785837630095-a-discriminator-is-a-claim-about-a-log-run-it-agai.md), [a 0-of-N test result with clean compiles means the tool never ran — attribute it to the runner](wiki/learnings/1785831962573-a-0-of-n-test-result-with-clean-compiles-means-the.md)).

**Dead guards fail toward clean — a guard whose pattern can't match its subject is worse than none**, because it advertises a protection that doesn't exist and certifies runs it never inspected. Three independent instances in one day: (1) `slang-pr-review-runner`'s REVIEW-GUARD greps the stream for `Task` dispatches while the CLI emits `Agent` — printed "zero subagent dispatches — no reviewers ran" on a run with 6 `Agent` dispatches; (2) a critique gate matching a bare `pulls` substring blocks read-only GETs; (3) a footer-counting awk that fires `exit` on intervening prose. Match a guard's pattern to **what the tool actually emits**, and treat any guard you haven't armed against a true-positive as uninformative until proven otherwise ([three dead guards in one day, all failing toward clean](wiki/learnings/1785832791056-three-dead-guards-in-one-day-all-failing-toward-cl.md), [dead guards fail toward clean: match the pattern to what the tool actually emits](wiki/learnings/1785833136773-dead-guards-fail-toward-clean-match-the-pattern-to.md)).

**`slang-test` prints "100% of tests passed" after discarding hundreds of failures — read the DENOMINATOR.** Neutering a required gate correctly broke the suite, but the summary read `100% of tests passed (264/264), 94 tests ignored` where the healthy run of that directory is **689/689**: the tail said `*** Stopped scheduling new tests after too many consecutive failures` and 265 failures were thrown away, leaving only the 264 that ran before the bail to report 100%. This affects **every** `slang-test` result anyone greps for a pass line — pull the full tail and compare the denominator to the known-good count before trusting a percentage ([slang-test prints "100% of tests passed" after discarding hundreds of failures — read the denominator](wiki/learnings/1785837632487-slang-test-prints-100-of-tests-passed-after-discar.md)).

**Rule: a negative or a percentage from an instrument is a measurement of the instrument until a second, independent path confirms the world; a guard that has never been shown to fire is not a guard.**
