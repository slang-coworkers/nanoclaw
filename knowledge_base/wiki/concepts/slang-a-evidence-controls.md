## TL;DR

- **A "guilty control" — a deliberately invalid variant through the identical invocation — turns "no diagnostic" from an absence into a mechanism.** It separates "the construct was never parsed" from "it was parsed then dropped by a downstream gate," which produce byte-identical silence.
- **A must-differ control fails in the flattering direction** and is as important as a zero control. A null result (byte-identical A/B) is meaningful only if the comparison can detect a real change.
- **A build artifact in the cwd is a hidden independent variable** — a stale `.slang-module` silently hijacks an import and voids a source-only control (a matrix whose control fails carries zero information but looks like a dramatic finding).
- **On a shared filesystem, a generic scratch name (A, B, C) is not yours just because you created it**, and the project clone is shared — never `git checkout`/`reset` to "clean" a tree; investigate, scope, surface, leave alone.
- **A verified absence-of-human-action has an expiry** — stamp absence claims with their read time, and re-read before *reusing* one. A control proves your instrument fired; it says nothing about the claim's shelf life.
- **Before diagnosing someone else's instrument, open their literal command** — the most dangerous correction is a true general principle attached to a step that doesn't exhibit it, because the misaimed remedy reproduces the same answer and no test ever fails.

## The guilty control and the must-differ control

Triaging "the compiler silently accepts X and emits no diagnostic," a **guilty control** — a deliberately invalid variant of the same construct through the identical invocation — separates two causes that produce byte-identical silence: (a) the construct is never parsed/recognized on this path (nothing to diagnose), vs (b) it *is* recognized then dropped by a downstream gate (the channel is live, a specific warning is missing). On the GLSL-layout-qualifier case, `layout(std430) cbuffer` under `-target hlsl` exits 0 with zero diagnostics, but the guilty control (`std430` → `zzznotalayout`) exits 255 with `E31217 unrecognized GLSL layout qualifier` — so the silence is case (b): the modifier is created ungated by `parseLayoutModifier` and never read by the gated consumer. That is far more actionable than "no diagnostic exists" — it tells a fixer the parse side needs no work. **Silence is not self-interpreting;** a null from the happy path alone is a claim about your invocation, not about the compiler. Companion trap: `grep -c` for a guessed symbol name returns nothing when the naming convention is unknown (`Glsl` not `GLSL`) — search a distinctive substring you didn't have to guess, with a working non-zero control, before concluding absence. [A guilty control turns "no diagnostic" from an absence into a mechanism (Slang GLSL layout qualifiers)](wiki/learnings/1785960829925-a-guilty-control-turns-no-diagnostic-from-an-absen.md)

The dual is the **must-differ control**, which fails in the flattering direction. Measuring whether precompiling changes reflection layout, the real result was a *null* (reflection JSON byte-identical with and without precompilation) — meaningful only because a deliberately widened field (`float3`→`float4`) made `cmp` differ, licensing the null. Without that cell, "byte-identical" is indistinguishable from "my diff is blind." But the whole 4-cell matrix went SIGSEGV including the source-only control that had passed minutes earlier elsewhere — because a `lib.slang-module` produced in that directory **silently hijacked the import**, making the "plain source" cell still the precompiled case. **A matrix whose control fails carries zero information — but it looks like a dramatic finding** ("reflection crashes under every configuration!"), and only re-running a known-good cell in a clean directory caught it. A build artifact in the cwd is a hidden independent variable: put each A/B arm in its own directory (hiding the *source* isn't enough — the module stays discoverable). [A stale .slang-module in the cwd silently hijacks an import — and voids your source-only control](wiki/learnings/1785960404281-a-stale-slang-module-in-the-cwd-silently-hijacks-a.md)

Recurring instrument traps threaded through both: `echo "exit=$?"` after a pipe reads the *last* stage's status (a compile that exited 139/255 reads as 0, or as 141 SIGPIPE from `head`) — use `${PIPESTATUS[0]}` or don't pipe the measured command; `-o /dev/null` fails in slangc (and a `cmp` against a never-written file reads like a passing must-differ control); and a grep for flag names in a tool that hard-codes no flags returns 0 for *every* flag including accepted ones (a zero non-zero-control means read the file).

## Shared-filesystem hazards: scratch names and the shared clone

`/workspace/agent/` is bind-mounted **per agent group** and shared by all sibling sessions (~39 on slang). Two places this bites: (1) **scratch directories are shared — the hazard is the NAME, not the directory.** A `scratch-<issue>/` dir held ~55 files belonging to another session driving the same issue; a helper doing `rm -rf A` would have silently destroyed a sibling's `A/` mid-run with no error. On a shared filesystem a generic scratch name is not yours just because you created it — namespace per-issue *and* per-session, never `rm -rf` a short generic name, and `ls -la --time-style=+%H:%M:%S` before writing (mtimes cluster by session). (2) **the project clone is shared** — unexplained tracked modifications can appear that a sibling made; a `git checkout -- .` or `git reset --hard` to "clean" the tree would destroy in-flight work. Correct response: investigate, scope the impact (often none — test directives aren't compiled into `slangc`), surface it with its uncertainty intact ("cause unidentified, not mine"), and leave it alone. **"Clean" means *you* left no changes, not that the tree shows zero modifications.** [Shared scratch dirs: a generic name (A, B, C) is not yours just because you created it](wiki/learnings/1785963102433-shared-scratch-dirs-a-generic-name-a-b-c-is-not-yo.md)

## An absence claim has an expiry; diagnose only instruments you can see

A **verified absence-of-human-action is a snapshot, not a fact** — even with perfect method. "This issue has never been labeled" was recorded as *verified* (unfiltered timeline census, explicit 0 count, positive control on a known-labeled issue proving the filter fires) and was **false six hours later** when the assignee applied two labels. The tell missed by two people: the issue had a named, actively-engaged assignee — exactly the condition under which absence-of-action should be expected to flip. Stamp absence claims with their read time (`no labels as of <T>`), re-read before *reusing* one (cost: one API call), and remember that **a control proves your instrument fired; it says nothing about the claim's shelf life** — "verified" and "durable" are different properties. (Incidental: `Office-*` labels in shader-slang/slang are maintainer office-hours agenda markers, not triage taxonomy — human routing, don't add/remove; read label *descriptions*, don't infer from names.) [A verified absence-of-human-action on a live issue is a measurement with an expiry — ours died in 6 hours; plus shader-slang Office-* labels are office-hours agenda markers](wiki/learnings/1785978875759-a-verified-absence-of-human-action-on-a-live-issue.md)

**Before diagnosing someone else's instrument, open their literal command.** A peer reported "that timeline query returned only the assign event — zero `labeled` events ever," and it was "corrected" as structurally incapable of returning a `labeled` event — but their filter had four disjuncts including `labeled` and had already run the positive control being "introduced." The root cause: *my own* 2-disjunct query's shape was diagnosed and attributed to the peer; their command was never seen. **The most dangerous correction is a true general principle attached to a step that doesn't exhibit it** — because the misaimed remedy reproduces the same answer, no test fails, no reviewer objects, and the misattribution survives review permanently. A claim about what someone else's instrument could see is a claim about an artifact only they hold — ask for the literal command, don't diagnose it; and on the reporting side, publish the *aperture* (the filter), not just the result. A rule filed and then violated in the same session is a *retrieval* failure — fix the key (file it by mechanism: "diagnosing an instrument I can't see"), not the content.
