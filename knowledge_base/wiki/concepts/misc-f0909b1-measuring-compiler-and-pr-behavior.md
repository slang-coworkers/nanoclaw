## TL;DR

- A claim about what the compiler emits is measurable in minutes — measure it. Reasoning from the language standard tells you what *should* happen; the symbol table (`readelf -sW` binding column, not `nm` case) tells you what *did*.
- "This pattern already exists elsewhere" is a claim about a *specific input*, not the code's structure. Two diagnostic sites both being reachable does not mean both *fire* on your example — run the precedent case and count.
- A public header's consumers are **not enumerable**; a repo-scoped grep answers "does *this project* take the address," never "does *any caller*." Internal linkage changes address *identity* for out-of-tree code, which a symbol-emission table does not show. When your evidence's scope is narrower than your claim's, abstain and route to a human.
- A submodule bump's diffstat describes the *pointer*, never the content — `+1 -1` can hide the removal of a safety guard. Resolve both SHAs and read the upstream commit; for each removed condition, read the base-class contract it enforced.
- A hot symbol in a profile is not a fix site: open F and bound its complexity before "optimize F." An O(1) function at 27% self-time is a call-*volume* signal; the fix is at the caller. Measure scaling before naming a fix class (a large constant factor is not a quadratic).
- A "we removed feature X" closure is scoped to the versions that removed it — check the DEFAULT path before treating it as a dedup, because the removal often lands behind a version gate whose default is the old, still-crashing behavior.
- Stop reading at the end of the *function*, not the end of the branch that confirms your hypothesis. A guard that explains your observation is the most dangerous place to stop.
- Before abstaining on an unenforced documented precondition, run the **sibling-API check**: is the gap an outlier or the house style? One cheap enumeration decides opposite verdicts.
- For a layout/codegen crash, "exit 0" is the weakest pass condition — assert the *value* produced against a working analog, and print `rc` next to every timing cell.

## Measure emission, don't reason it — and run the precedent case

[Measure a linkage/ODR claim by symbol BINDING (readelf -sW), not by the language rule](../learnings/1786389287112-approver-challenger-method-measure-a-linkage-odr-c.md) builds the header two ways and compares symbol tables, showing that a naive `nm`-presence check makes a correct `inline constexpr → static constexpr` fix look *backwards* (0 symbols "before," 2 "after") while the real transition is `WEAK`/`UNIQUE` → `LOCAL`, visible only in `readelf -sW`'s binding column. The clang+ASan row reproduces the PR's stated mechanism end to end (a `WEAK` size-4 symbol inflated by a 28-byte redzone). Write two TUs (value-read-only and address-taken); the safety predicate is a one-line grep *for this repo*. The measurement-over-reasoning discipline recurs in [A "warns in both cases" premise can be false even when the pattern genuinely pre-exists](../learnings/1786388561579-a-warns-in-both-cases-premise-can-be-false-even-wh.md): an author's "master already emits 2 warnings for this analogue, so the pattern pre-exists" was refuted by compiling one function per unit and counting (master emits 1, not 2) — reachability of a diagnostic site and its firing on a chosen input are different properties gated by conditions like `currentCaseLabel`. Before repeating a precedent defense, run the precedent case and count; and when an author volunteers a concern *and* a defense, the defense is where to aim.

## Scope of evidence: a public header's consumers are unbounded

The linkage lesson has a hard limit made explicit in [A public header's consumers are not enumerable](../learnings/1786390562483-approver-false-safe-a-public-header-s-consumers-ar.md): a `grep -rn '&<name>'` returning 0 answers "does *slang* take the address," not "does *any caller*," so it cannot settle SOURCE compatibility for `include/slang.h`. Internal linkage makes the entity per-TU, changing *address identity* (`same=1 → same=0` across TUs; a non-type template argument becomes distinct types per TU; an IFNDR test that "passed" by linker luck carried zero bits). "I proved a claim over the scope I could reach, then reported it as the claim" is the transferable error — audit your own wording for coverage promotions ("*the whole* ABI check," "0 hits ⇒ answered"), because coverage is exactly what a grep cannot attest. Read the invariant *section*, not the invariant *named*. This is why the decision became `ABSTAIN_POLICY:CHALLENGER_CONCERN`: risk low ≠ risk nil, and an undiagnosed break on a long-lived public header satisfies the abstain bar.

## Small diffs, hot symbols, and the scope of what you read

[A submodule bump's line count hides the change: +2-6 can be the removal of a safety guard](../learnings/1786399884300-approver-challenger-probe-a-submodule-bump-s-line-.md): a `+1 -1` submodule pointer bump concealed the deletion of a guard (`return pipeline->getType() != PipelineType::RayTracing;` → `return true;`) that a prior abstain depended on — the smaller the visible delta, the more content hides behind it. Resolve both SHAs, read the upstream commit's actual changes, and for each removed condition read the *base-class* contract it enforced (that is where the "must return false" rule lives). [A hot symbol in a profile is not a fix site](../learnings/1786405024024-a-hot-symbol-in-a-profile-is-not-a-fix-site-check-.md): `isSubClassOf` at ~27% self-time and ~400M calls was already O(1), so the fix belongs at the caller (`getClass()` constructs a fresh `SyntaxClass` per `as<>` cast); measure scaling before naming a fix class (a 10× gap that fit `2.47ms/site + 363ms fixed, R²=0.9967` was a constant factor, not quadratic); discard a number whose derivation contains an assumed factor; and print `rc` next to every timing cell (two cells returned rc=255 with 9–10MB of diagnostics but *plausible* timings).

The most instructive scope-of-reading atom is [Stopping at the branch that confirms your hypothesis](../learnings/1786420900027-stopping-at-the-branch-that-confirms-your-hypothes.md): a confident root cause ("a generic `T` bypasses the only cache") was false — the fallback cache sat four lines below where the reading stopped. Read to the end of the *function*, not the end of the branch that confirms the hypothesis (a guard that explains your observation is the most dangerous place to stop). Its other four failures each generalize: a diagnostic dismissed as noise *was* the measurement (suppressing 3,062 conversion warnings suppressed the evidence the control was contaminated); provenance of an entry point says nothing about its callees; a hazard warning was built on an unread commit (the removed cache was redundant, not unsafe — the history *lowered* the barrier); and absolute timings were inflated ~1.8× by the author's own concurrent build (ratios survived, absolutes did not). Hitting a reviewer round-limit is a signal to escalate, not to stop.

## Dedup, sibling APIs, and value-not-exit-code

[A closure that cites feature removal is scoped to the versions that removed it — check the DEFAULT path](../learnings/1786412442845-a-closure-that-cites-feature-removal-is-scoped-to-.md): a SIGSEGV closed as "we removed struct inheritance" still crashes on every non-2026 std because the hard-error gates on `isSlang2026OrLater` while the default emits a warning and proceeds into the crashing path (139 exit on `-std 2025/2018/default`). A "we removed X" closure records the maintainer's *policy*, not the defect's *reachability*; find the version gate, measure the default, quote the closure verbatim, and surface both dispositions rather than picking one. That atom's companion trap: a crash-fix validated by exit code can certify a still-wrong result — the fix took all four targets 139→0 but emitted two members both at `location = 0`, so for a layout/codegen crash "exit 0" only certifies nothing read out of bounds; assert the *value* against a working analog. Finally, [The sibling-API check: before abstaining on an unenforced documented precondition, test whether it is the house style](../learnings/1786433684643-approver-challenger-the-sibling-api-check-before-a.md): enumerating every `create*From*Handle` showed Metal validates, Vulkan doesn't, D3D12 sits between — uniformly across the family — reframing "inconsistent with siblings" (a real `OPEN_GAP`) into "the layer treats size as a caller precondition" (advisory). House style downgrades inconsistency but says nothing about blast radius. A method note that nearly bit: a `/tmp` clone had been garbage-collected, so every backend returned `0 size-validation hits` — a clean, plausible, fictitious result; a control (body line count, an `ls` probe) caught it. When a sweep returns all-zeros, verify the corpus exists before believing the zeros.
