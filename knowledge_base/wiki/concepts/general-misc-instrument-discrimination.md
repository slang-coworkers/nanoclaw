# Instrument Discrimination — a signal that cannot separate states carries zero bits

## TL;DR
- The discrimination test: a signal that cannot separate the states you care about carries zero bits.
- Diagnose an instrument's blindness from its shape, BEFORE running it — a green result can be structurally incapable of red.
- A check that could not come out differently is a proxy, not a measurement.
- Match the instrument to the claim — membership, completeness, identity, or currency. Verify the deliverable, not the machinery.
- Control the instrument, not the reasoning. An audit can itself be the defect — a conclusion is only as sound as the set's membership rule.
- A common-mode defect is invisible to per-item review — ask one question over the whole SET.

## The discrimination test — a signal that cannot separate the states you care about carries zero bits

Provenance discipline (*is my source live and primary?*) and method discipline (*could this observation have come out differently if I were wrong?*) are separate checks and you need both — the worst offenders are all read from correct primary sources. Before an observation carries a conclusion, ask whether it would have looked different had the opposite been true; if not, no amount of careful sourcing rescues it ([the unifying diagnosis: a signal that cannot distinguish the states you care about](../learnings/1785750713482-the-unifying-diagnosis-a-signal-that-cannot-distin.md)). **Absence claims need a positive control; presence claims mostly don't.** The canonical miss: `grep -c "DEEPEST SUBCASE: d3d12"` → 0 cited as "no d3d12 failures," when the same pattern on `vulkan` — where all 28 failures were — also returns 0, because doctest emits the subcase name on the *following indented line*; the pattern matched nothing and the zero was unfalsifiable ([a grep returning 0 is only evidence if the same pattern returns non-zero for a known-present case](../learnings/1785749557692-a-grep-returning-0-is-only-evidence-if-the-same-pa.md), [same rule, reviewer-side: run the positive control first](../learnings/1785750137847-a-grep-returning-0-is-only-evidence-if-the-positiv.md); a third near-identical filing survives only as a [dedup pointer](../learnings/1785749767697-a-grep-returning-0-is-only-evidence-if-the-same-pa.md)). Companion traps: **Windows runner logs are CRLF**, so `$`-anchored patterns silently return nothing on `windows.log` (`tr -d '\r'` first); **a log absence tells you WHAT, never WHY** (a correctly-derived zero cannot separate *ran-and-exited-early* from *never-a-step* from *excluded-by-an-`if:`* — resolve the cause at the workflow/build **definition**); **a count can be topically right and semantically empty** (`grep -c pytest` = 22 was entirely `pip install` chatter, 1 after filtering); and **a claim you have had to weaken twice** is telling you the property is not verifiable in your environment — say that outright (`passed` → `no observed failure` → `consistent with…` is the tell). The test applies to citation *shapes*: a **line range** straddling two constructs cannot discriminate "drifted guard" from "adjacent construct that needs none" ([run the discrimination test on line ranges too — plus the "structurally cannot" correction](../learnings/1785751219892-run-the-discrimination-test-on-line-ranges-too-a-c.md)); and one level out, **a correct probe pointed at the wrong observable** — corroboration needs a *causal path*, not an overlapping target set (a capability-set mutation and three layout branches at one call site read as one mechanism, but no branch reads the promoted capability, so an A/B on layout would find no difference either way) ([two mechanisms at one call site are not one mechanism — derive the measurement from what the mechanism mutates](../learnings/1785752093299-two-mechanisms-at-one-call-site-are-not-one-mechan.md)). Finally, **the detector is itself a claim**: a duplicate-H1 scan using `grep -c "^# "` counted `#` bash comments inside fenced code as headings — when a count surprises you on an artifact you believe is clean, suspect the counter first, because a tool bug does not invalidate every number it touched and discarding a sound result is a false negative you chose ([a detection query is itself a claim needing a discrimination test](../learnings/1785775510720-a-detection-query-is-itself-a-claim-needing-a-disc.md)). Two practices make all of this reviewable: prefer **two independent extraction methods** for any load-bearing claim, and **publish the extraction command alongside the finding** — a command gets run against inputs its author never had, which is how the vacuous grep was caught at all.


## Diagnose an instrument's blindness from its shape, before running it — a green result can be structurally incapable of red

A revert-drill proves a test *can* fail; these are the checks that cannot, and which therefore manufacture their own supporting evidence. **When a check reads one element of an unordered or arbitrarily-ordered set, its passing carries no information.** `[ "$(git rev-parse HEAD)" = "$(cat .git/shallow | head -1)" ]` as a shallow-clone discriminator coincides whenever HEAD happens to sort first (`.git/shallow` is SHA-sorted); measured false-agreement was ~1/6 on a 6-entry fixture and a **coin flip** on a 2-entry one, and *the smallest, most natural fixture is the one most likely to lie to you* ([a check that reads one element of an unordered set cannot be validated by running it](../learnings/1785768953168-a-check-that-reads-one-element-of-an-unordered-set.md)). Those rates were themselves an instance of the failure: `--depth` implies `--single-branch`, so the modal real shape (`clone --depth 1 --branch <pr-head>`) writes exactly one shallow entry and the bad check agrees **~always** — and a second smell, **a check whose verdict an unrelated later operation can flip was never measuring its subject** (an extra `git fetch --depth 1` flipped it in 4 of 12 fixtures with HEAD untouched); the stable form is `--is-shallow-repository` plus empty `git log -1 --format=%P` ([the false-agreement rates were measured on a configuration nobody reaches by accident](../learnings/1785769120004-correction-to-the-false-agreement-rates-depth-impl.md)). The same blindness appears in the artifacts we *demand as proof*: a `sourceLoc`-propagation fix asked to prove itself with a `-g2` SPIR-V golden gave byte-identical output at `-g1/-g2/-g3`, read as "no observable effect" — but `OpLine`/`DebugLine` are emitted only from explicit `kIROp_DebugLine` markers at statement granularity, so the test **could not fail before it was run**; when you specify the unsatisfiable test, the miss is yours, not the implementer's — match the assertion layer to the *contract* layer ([byte-identical output is not proof a patch is effectless — check the layer](../learnings/1785775152713-byte-identical-output-is-not-proof-a-patch-is-effe.md)).


## Verify the thing, not a convenient proxy — measure the deliverable, not the machinery

**Measure the deliverable — artifact mtime plus a string the new code introduces — never the machinery.** `until ! pgrep -f '<pattern>'; do sleep 20; done` as a wait-for-build primitive is broken by construction: `pgrep -f` matches full argv and the pattern is literally an argument of the shell running the loop, so the monitor finds *itself* and the wait never terminates. On slang#12371 a monitor armed on `pgrep -f 'ninja -f build-Debug.ninja'` reported "still building" for ~20 minutes after the build finished, and a `pkill -f` on the same pattern killed my own monitor and shell (exit 144). Match the **binary** (`pgrep -x ninja`, or an anchored path); never `pkill -f` a pattern in your own supervisor's argv; and pair any process-liveness reading with an artifact reading, since an mtime plus a behavioural probe cannot both be wrong the same way ([a self-matching pgrep pattern is a liveness check that can never go false](../learnings/1785988965980-a-self-matching-pgrep-pattern-is-a-liveness-check-.md)). The positive-control rule for absence claims has a *timing* form: **hand-verify at least one case you know must appear in the output BEFORE running the population probe, then require the probe to find it.** A sweep for stale-`failure`-behind-same-named-pass printed **nothing across 79 PRs** while the population provably contained **17** — a `details_url` split index off by one made `split("/")[6]` the literal constant `"runs"` for every row, silently defeating every downstream `unique`/`group_by`; it read as broken only because two hand-verified positives (#11389, #9809) contradicted it. Corollary: **print the split once and count the fields**, never infer an index by eyeballing a URL ([hand-verify one positive case before running a population probe](../learnings/1785990863211-hand-verify-one-positive-case-before-running-a-pop.md)). And the *scope* form: **a must-hit control proves LIVENESS ("did my instrument read anything?"), never COVERAGE ("did the run reach the thing whose absence I'm citing?").** Arguing a red nightly was unrelated to a Metal-4 issue, I cited "zero occurrences of `required_threads_per_threadgroup` and zero failing `*Metal.internal` tests" — both counts literally true and both worthless, because the harness segfaulted (`exit 139`) before reaching those tests while my liveness control (`passed test:` = **8,737**) stayed non-zero. The coverage counter separates them: `gfx-unit-test-tool` appeared **220** times in the green log and **1** (a *build* line) in the red. **A zero is evidence only over a population that was actually visited** — pick the noun from your own claim, count it in the run under test and a known-good run, and sweep the defect *class*, not the instance ([before believing a zero, prove the run reached the target — a coverage counter, not a liveness control](../learnings/1785984244886-before-believing-a-zero-prove-the-run-reached-the-.md)). The worst-behaved claim has no failure signature at all: **never write "X is impossible / there is no hook / nothing can catch this" — write "declining on scope", or name what you actually searched.** A wrong *capability-negative* is self-sealing: readers comply by *not attempting*, so it is never tested and it propagates because it reads as diligence. On slang#9146 / PR #12379 I shipped a PR body saying the repo "has no automated export check of any kind," and a reviewer disproved it in one grep (an existing `release.yml:352` `File check` step). Before publishing any "no way to do X": state the search that would have found it, check whether your grep **presupposes the tool you'd use**, distinguish "no facility exists" (checkable) from "no facility could exist" (unsupportable), and prefer *scope* as the reason to decline. (Same task, same-shape trap: `git diff --stat origin/master..HEAD` showed 9 files / 461 deletions on a 3-file change because **two-dot** diff renders advanced-upstream additions as your deletions — use three-dot `origin/master...HEAD`, what GitHub's PR view uses) ([a capability-negative has no failure signature](../learnings/1785988766801-a-capability-negative-no-test-is-possible-there-s-.md)).


## Control the instrument, not the reasoning — ten measurement defects, every one invisible to re-reading

Across four agents on shader-slang/slang#11616, the *distribution* is the finding: **all ten defects were in the measurement, never in the inference.** Each argument re-read fine every time, because **reasoning has no access to this defect class** ⇒ *"check your work" and "run a control on your instrument" feel identical from the inside, and only the second one works.* The least intuitive finding is the **citation-tightening tell**: the instrument you reach for when tightening a citation is the one that drops the citation data — three of four late rounds read source with a *range-printer* (`sed -n '336,372p'`, `git show`) whose output carries **no line numbers**, then cited a line counted by eye (`:361` for `:363`, `:2785` for `:2787`, `:4139-4190` for `:4296-4305`, off by ~125). **Rule: `grep -n` for anything you intend to cite; never a range-printer.** The instrument-defect checklist for a "who may do what to which files" claim, each item with a positive control: path pattern · extension · **status (A/M/D)** · authorship · **resolved** committer identity · push-vs-server-side · **which App** — then two questions. **Can the instrument return a non-zero answer at all?** `gh api …/commits?author=nv-slang-bot[bot]` returned **0** for an author with 157 commits (the bracketed login silently matches nobody); `author=jkwak-work` → 100 proves the param works — **a zero without a non-zero control is not evidence.** **Can the output carry the claim?** `git log`/`git show` **suppress merge-commit diffs by default, so pass `-m`** (this inverted a finding — "has our App pushed a commit *adding* a `.github/workflows/` file?" returned 0 when the true answer is **6**); `commit.committer.name` is free text while `committer.login` is the resolved identity (**prefer the resolved field for any permission claim**); squash-merge means a bot's commits never enter master's first-parent history; `-g3` embeds source so a test's own `CHECK` comment lines match a naive grep of the emitted output (anchor on `OpExtInst %void %N DebugNoScope`). Two rules earned alongside: **a correct conclusion does not license its explanation** (four instances rode conclusions that were right, so none drew pushback), and **before asserting containment, enumerate the dimensions the claim needs *first*, then check each** (a superset claim verified on extension + path + authorship + push-transited still failed because **status (added vs modified)** was never on the ladder). Coordination note: two tiers ruled to the same coworker within one minute ⇒ **overlap on review, singleton on dispatch** ([control the instrument, not the reasoning — 10 measurement defects and the citation-tightening tell](../learnings/1785827764500-control-the-instrument-not-the-reasoning-10-measur.md)).


## An audit can be the defect, and a conclusion is only as sound as the set's membership rule

**An audit that flags your correct row may itself be the defect.** A ledger audit flagged a `skipped=22` row expecting 23, but the 23rd skip mark had been *voided* by a head-sha move (`is_skipped()` correctly returned False), so the guard working looked like the sweep under-claiming. Before acknowledging a finding, establish whether the finding or the target is wrong, acknowledge only the hard-unrepairable, and **never subtract a count measured *now* from one measured *as of then*** ([an audit that flags your correct row may itself be the defect](../learnings/1786292053070-an-audit-that-flags-your-correct-row-may-itself-be.md)). And **correct reasoning applied to a set assembled by an unverified filter** fails at the filter, not the reasoning: a per-`Device` cache argument was sound and twice-verified, but the candidate set was built by "declares `-mtl`" and the harness's `-synthesizedTestApi` mints a variant for each API a file does *not* declare (1166 `syn (mtl)` tests in one job) — and the challenger's replacement "therefore all 8 eligible" was *also* wrong until reading one function further (`_calcSynthesizedTests` excludes `-cpu`-only files from Metal synthesis by rule); **verify the set's membership rule before trusting any conclusion drawn over it** ([correct reasoning applied to a set assembled by an unverified filter](../learnings/1786305135329-correct-reasoning-applied-to-a-set-assembled-by-an.md)).


## Match the instrument to the claim — membership, completeness, identity, currency

Different claim shapes need structurally different checks, and substituting one for another produces luck reported as verification. Two tiers disagreed on a session count; the approver backed its 17 with a "second independent path" (`sessions get <id>` per session), but **a membership check is structurally incapable of revealing an 18th item a capped list omitted** — it validated the items it already held and gave zero completeness coverage. `ncl sessions list` returned 200 rows both bare and `--agent-group`-filtered (the identical count *is* the tell), 2096 at `--limit 5000`, and only the stable reruns at 10000/20000 make 2096 a total rather than a fourth page: **membership → `get`, completeness → BOUND test, identity → hash**, and an unbounded count is a FLOOR ([match the check to the claim — membership, completeness, identity](../learnings/1785820665177-match-the-check-to-the-claim-membership-get-comple.md)).


## A check that could not come out differently is a proxy, not a measurement

Four independent slang#12192 errors shared one shape: each check ran green but could not have failed if the claim were false (a grep proving presence not reachability; a byte-identical SPIR-V diff `OpLine` can't move; a line number standing for its enclosing function; an aggregate `total > 0` standing for per-site coverage). The installable reflex is one question — *if the claim were false, would this specific check have told me?* — and if you cannot describe the failing output, you hold a proxy ([four errors, one shape — verifying a proxy instead of the thing](../learnings/1785775797519-four-errors-one-shape-we-verified-a-proxy-instead-.md)).


## A common-mode defect is invisible to per-item review — ask one question over the SET

When the shared model carries the defect, every item passes for the same wrong reason, so N truthful self-reports sum to a false coverage claim (7 agents each reported matching counts, 5 were wrong, 19 of 47 pages affected; three fixtures inert from one root cause). Ask "what would be true of ALL of these if my premise were wrong?" and test that once; a cross-cutting audit must include items nobody edited, and agreement among reports sharing a method is one observation, not N ([a common-mode defect is invisible to per-item review](../learnings/1785826374214-a-common-mode-defect-is-invisible-to-per-item-revi.md)).


## Controls that cannot discriminate

The single most reusable failure of this whole page: a control runs, produces output, and looks like an answer while being **incapable of separating the hypotheses it was offered to settle**. The canonical instance — `ncl tasks list --agent-group-id <bogus>` returned `No tasks.`, identical to the bare call, and was promoted to a "measured reproduction" of *flag-silently-ignored* — collapses the moment you write predictions first: the caller's true task set was **empty**, so "flag inert → returns my own (empty) tasks" and "flag filters → bogus group has no tasks" both predict `No tasks`, and no observation on that edge could tell them apart; only a reviewer whose true value was non-empty could measure it (bare → 19 rows, bogus → still 19 ⇒ inert) ([a control whose hypotheses predict the same output is not a control — state the predictions before running it](../learnings/1786240939835-a-control-whose-hypotheses-predict-the-same-output.md)). The fix is procedural: **before running a control, write down what each hypothesis predicts; if they match, don't run it, build a different one** — and pair every "bogus value → empty" with a "known-good value → non-empty," bounding the baseline first because a default row cap makes two different totals look equal. The trap deepens one step further when the control is sound but the **hypothesis set is incomplete**: at group scope, bare `ncl sessions list` → 5 rows and `--agent-group-id <nonexistent>` → also 5 was read as "flag ignored," but a third hypothesis — *scope enforcement overwrites the value with the caller's own group before the query runs* — predicts the identical 5, so "ignored" was unmeasurable rather than measured; a `global`-scope reviewer settled it (bogus → 0, own-group → 5) and the flag filters correctly ([enumerate hypotheses, not just two: "flag ignored" vs "flag overwritten by scope enforcement" predict identical output to the caller](../learnings/1786241272517-enumerate-hypotheses-not-just-two-flag-ignored-vs-.md)). Two rules carry: for any "my filter didn't change the output," always include *"the value was rewritten/defaulted before use"* alongside *"the flag was ignored"* — they are opposite verdicts (a bug to file vs. security working) with one symptom — and **test sibling flags on the same verb first** (if `--status` and `--thread-id` demonstrably filter, "flags are inert here" is not viable; look for why *this* value is special). The same night produced three more instances of the identical shape — a `2>/dev/null` that let a true-but-wrong-cause sentence send two agents chasing timing for an hour, a bogus-term grep where *absent* and *truncated* both yield 0 hits (needing a positive control), and a cross-group read one message from inverting a colleague's correct report.
