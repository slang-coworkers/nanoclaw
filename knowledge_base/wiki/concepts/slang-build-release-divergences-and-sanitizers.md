# Slang Release-Build Divergences & Sanitizer Suppressions

This page covers the ways a locally-green Slang build diverges from CI or ships stale logic — LTO symbol leaks, `LD_LIBRARY_PATH` lib shadowing, and the `-Og`/`SLANG_ASSERT` debug-flag traps — plus sanitizer-suppression paired removal and the `external/` dependency kinds. The build-workflow hazards you hit while iterating (detached build subagents, disk-full on shared volumes, `slangc -v`/submodule staleness, concurrent-build corruption) live on the sibling page [Slang Build Subagent & Worktree Hygiene](slang-build-subagent-and-worktree-hygiene.md). The dependency and CMake-option surface (DXC, slang-llvm, FindDXC, Falcor) lives on [Build System, Prebuilt Deps (DXC/LLVM) & CMake Options](slang-tooling-build-runtime-libs.md).

## TL;DR

- **Release-ZIP symptom absent from a local `--preset release` → LTO.** CI's `release.yml` adds `-DSLANG_ENABLE_RELEASE_LTO=ON` (default OFF), which bypasses `-Wl,--exclude-libs,ALL`.
- **The wrong library loads silently.** Keep the staging dir `build/slang-<ver>-<arch>/lib/` off `LD_LIBRARY_PATH` (rpath already points at `build/Debug/lib`); for DXC expose ONLY `libdxcompiler.so`/`libdxil.so`. `slang-test -bindir` does not switch the compiler under test: A/B with each tree's own binaries. A harness rc 139 with no output is not a pass.
- **A sanitizer fix removes its `expected-sanitizer-findings.txt` entry in the same PR.** Match modes: SUMMARY-substring (`in <fn>`) vs LEAK-prefix (`LEAK:`).
- **Leak checks without ASan:** preload `liblsan.so` plus the `libslang-glslang` shim into a plain RelWithDebInfo slangc (gcc ASan stalls, `setarch -R` is EPERM here). rc=139 under it is a flake: count only rc=23 or a clean rc=0. For a quick glslang count use a `dladdr`-filtered `new[]`/`delete[]` interposer, never `LD_PRELOAD=libasan`. CI-nightly visibility of glslang leaks is unverified.
- **Sanitizer Summary classifies whole log files:** on a PR a log touching no changed file only warns, the nightly fails on it, so a new test hitting old buggy code reds the next nightly. Verify a nightly fix by grepping the job log for the `FOUND N SANITIZER LOG(S)` line and `<file>.cpp:<line>:<col>: runtime error`, never a bare filename.
- **Local UBSan:** gcc + `-fsanitize=float-cast-overflow` (clang 14 can't build master; gcc's `-fsanitize=undefined` lacks it), whole tree or one render-test file; the fails-before signal is `halt_on_error=1`.
- **`external/` has four content kinds;** lua IS consumed (slang-fiddle via `tools/`), mimalloc is a real submodule. Verify at HEAD.
- **`-Og` Debug (#12140/#12223) breaks debugging;** gate it behind a new option, default is a maintainer design gate.
- **`SLANG_ASSERT` is `__builtin_assume` outside `_DEBUG`, and the `debug` preset here builds Release.** Never assert what you also runtime-guard, never swap a reachable guard for an assert; verify new asserts on `-DCMAKE_BUILD_TYPE=Debug`.
- **All-Windows-fail, all-else-pass → MSVC `/W4 /WX`** (e.g. C4458 local hides member): rename the local.
- **Metal-only:** `createTexture`'s forced `mipCount = 1` reads the wrong slice for Texture1D array layers ≥ 1.

## Release-Build Divergences: LTO Symbol Leaks and LD_LIBRARY_PATH Shadowing

**CI release LTO defeats symbol-hiding.** When a symptom is in the release ZIPs but not a local `cmake --workflow --preset release` (slang#9146: `libslang-glslang` re-exports C++ stdlib symbols), diff `release.yml`'s configure line against the preset: CI adds `-DSLANG_ENABLE_RELEASE_LTO=ON` (default **OFF**, no preset sets it). LTO merges and re-emits statically-linked archive symbols at link time, bypassing `-Wl,--exclude-libs,ALL` archive-name matching; it is the usual culprit for visibility regressions ([CI release LTO defeats symbol-hiding that local --preset release keeps](../learnings/1784380337015-ci-release-lto-defeats-symbol-hiding-that-local-pr.md)).

**The wrong library loads silently,** via three triggers that each look like a real result:

- **Stale package lib.** Beside fresh `build/Debug/lib/` sits a days-old staging dir `build/slang-<ver>-<arch>/lib/`; with the latter first on `LD_LIBRARY_PATH`, slangc runs stale logic (~30 min lost on slang#11803 to a retired diagnostic). Use NO `LD_LIBRARY_PATH` (rpath points at `build/Debug/lib`) or list `build/Debug/lib` first, and check that a recently changed diagnostic prints its NEW message ([local slangc can silently run stale logic via LD_LIBRARY_PATH lib shadowing](../learnings/1784435219287-local-slangc-can-silently-run-stale-logic-via-ld-l.md)).
- **Local DXC checks.** A directory holding `libdxcompiler.so` and also a `libslang-compiler.so` (e.g. an old build's `lib/`) makes slangc load the stale Slang library and segfault on `-target dxil`, even `-target hlsl -profile cs_6_0`. Put only `libdxcompiler.so` + `libdxil.so` in a dedicated `LD_LIBRARY_PATH` dir; keep a trivial `RWStructuredBuffer` store as a control. (HLSL skips `lowerAppendConsumeStructuredBuffers` (`slang-emit.cpp:~1919`), so Append/Consume buffers reach the HLSL-only `lower-buffer-element-type`/`wrapStructuredBuffersOfMatrices` paths, #13385) ([local DXC check: LD_LIBRARY_PATH must contain only libdxcompiler/libdxil](../learnings/1790921619098-local-dxc-check-ld-library-path-must-contain-only-.md)). The scratch harness `/workspace/agent/scratch-13440/dxcdxil` dlopens `getenv("DXCLIB")` and without it segfaults (rc 139) silently, reading as "DXC accepted the HLSL". Run `DXCLIB=/workspace/agent/scratch-13385/dxc/libdxcompiler.so LD_LIBRARY_PATH=/workspace/agent/scratch-13385/dxc dxcdxil file.hlsl main cs_6_0` and check rc and stdout length. Master `c8e02397a` still emits combined-sampler HLSL as `tex.GetDimensions(sampler, …)` / `tex.Load(sampler, …)`, which DXC rejects (#10522 family) ([DXC harness scratch-13440/dxcdxil needs the DXCLIB env var](../learnings/1791315511105-dxc-harness-scratch-13440-dxcdxil-needs-dxclib-env.md)).
- **A/B runs.** `slang-test -bindir <master>/build/Debug/bin` does **not** switch the compiler under test: RUNPATH loads the `libslang-compiler.so` beside the invoked slang-test, so repro tests "pass on master" (#13409: 11/11 passed via `-bindir`; master's own slang-test failed all 11). Run master's own `build/Debug/bin/slang-test` from the fixed worktree root, or diff each tree's `slangc` output, and build slang-test in the patch's worktree ([slang-test -bindir does not switch the compiler under test](../learnings/1790998251754-slang-test-bindir-does-not-switch-the-compiler-und.md); RUNPATH mechanism on [Build System, Prebuilt Deps](slang-tooling-build-runtime-libs.md)). A copied master build needs `<root>/build/Debug/{bin,lib}` + `<root>/prelude` + `<root>/external/optix-dev`: slang-test finds the prelude by walking up from the exe (`TestToolUtil::getRootPath`) and nvrtc finds OptiX at `<exe>/../../../external/optix-dev`; copying only `bin/`+`lib/` gives ~24 bogus CUDA/OptiX failures ([CPU COMPARE_COMPUTE tests can hide IR optimisation bugs unless -g0](../learnings/1790982231204-slang-cpu-compare-compute-tests-can-hide-ir-optimi.md)).

## Sanitizer suppression files: paired removal required on fix

A fix for a previously suppressed sanitizer finding MUST remove the matching entry in `cmake/expected-sanitizer-findings.txt` (and related `lsan-suppressions.txt` / `sanitizer-ignorelist.txt`) in the same PR, or the stale entry produces CI warnings (a "never matched" warning can also be spurious, see below). Suppressions often come from an earlier PR, so grep by issue number or function name. Two match modes: **SUMMARY-mode**, a plain `in <function_name>` line substring-matched against the ASan alloc-dealloc-mismatch summary, and **LEAK-mode**, a `LEAK:` prefix matched against Direct-leak stack frames. Removing a SUMMARY-mode entry does NOT unmask a co-located leak on another path; the file header documents the modes, so read it before calling a removal premature ([Sanitizer-finding fixes must remove the matching expected-sanitizer-findings.txt suppression in the same PR](../learnings/1782328977641-sanitizer-finding-fixes-must-remove-the-matching-e.md), [expected-sanitizer-findings.txt has two match modes — SUMMARY-substring vs LEAK-prefix](../learnings/1782330515490-expected-sanitizer-findings-txt-has-two-match-mode.md)).

## Leak Checks Without an ASan Build: Preloaded liblsan, rc=139 Flakes, and a new[]/delete[] Interposer

A full ASan build is often unavailable here: gcc `-DSLANG_ENABLE_ASAN=ON` stalls in the build-time generators (slang-embed, slang-generate, slang-spirv-embed-generator spin at ~97% CPU printing `AddressSanitizer:DEADLYSIGNAL`), the usual `setarch $(uname -m) -R` cure (see [CI Flake — ASan, Merge-Group & Receipts-Level Root-Cause Cases](ci-flake-asan-and-merge-group-cases.md)) fails with `Operation not permitted`, and clang-14 ships no ASan runtime. What reproduced the reporter's nightly leak and stack for #13830 is an uninstrumented build plus a preloaded LSan: configure `cmake --preset default -B build-rel -DSLANG_SLANG_LLVM_FLAVOR=DISABLE -DSLANG_ENABLE_TESTS=OFF -DSLANG_ENABLE_GFX=OFF -DSLANG_ENABLE_SLANG_RHI=OFF -DSLANG_ENABLE_EXAMPLES=OFF` (RelWithDebInfo), build `slangc slang-glslang` (~10 min on 48 cores), and run `LSAN_OPTIONS=fast_unwind_on_malloc=0:malloc_context_size=30 LD_PRELOAD="$(gcc -print-file-name=liblsan.so) <lib>/libslang-glslang-<ver>.so" slangc ...`. Preloading the shim keeps it mapped at exit so its frames symbolize (otherwise frame #1 shows a wrong module path from a mapping reused after dlclose) ([Slang leak repro without ASan: preload liblsan into an uninstrumented build](../learnings/1792625160079-slang-leak-repro-without-asan-preload-liblsan-into.md)).

**rc=139 under a preloaded liblsan is an intermittent flake, not a result.** RelWithDebInfo crashed 1/3 at the default 8 MB stack, 0/3 with `ulimit -s unlimited`, 2/3 with unlimited plus `print_suppressions=1`; Debug 1/6 at 8 MB, 2/6 unlimited. Neither `ulimit -s unlimited` nor dropping the suppressions file fixes it (the "stack overflow" diagnosis was an n=1 coincidence); re-run and count only rc=23 (LSan's leak exit code) or rc=0 with no LSan output ([LSan-preload slangc runs segfault intermittently (rc=139)](../learnings/1792629855978-lsan-preload-slangc-runs-segfault-intermittently-r.md), [CORRECTION: liblsan-preload slangc rc=139 is an intermittent flake, not a stack overflow](../learnings/1792629887235-correction-liblsan-preload-slangc-rc-139-is-an-int.md)).

**Do not LD_PRELOAD libasan into a non-sanitizer build:** the slang-glslang dlopen fails (E00100 "failed to load downstream compiler 'spirv-opt'") and `-spirv-opt-path` then hangs. For a yes/no on a glslang leak fix, a ~30-line `operator new[]`/`operator delete[]` interposer is faster: it records only allocations whose `__builtin_return_address(0)` resolves through `dladdr` to a file containing `libslang-glslang` (which imports `_Znam`/`_ZdaPv` from libstdc++) and prints blocks still live at exit from a destructor. Build `g++ -O1 -shared -fPIC -o newtrack.so newtrack.cpp -ldl`, run `LD_PRELOAD=newtrack.so slangc ...`; on #13849 it showed in ~1 s 1 live block of 1784 B on master (tests/library/precompiled-spirv-generics.slang) and 0 with the fix, matching LSan. An optional export that both callers null-guard can also vanish from the version script with every test passing; pin it with a `findSymbolAddressByName` check in `tools/slang-unit-test/unit-test-downstream-compiler-path.cpp` (it reloads the real library) ([Measure slang-glslang leaks with a new[]/delete[] interposer, not LD_PRELOAD libasan](../learnings/1792633682579-measure-slang-glslang-leaks-with-a-new-delete-inte.md)).

**Whether the CI LSan nightly sees slang-glslang leaks is unverified.** An earlier learning says `SKIP_ASAN` and a broad `leak:<unknown module>` suppression blind it (see [GLSL backend](slang-backends-glsl.md)), yet locally, with `suppressions=cmake/lsan-suppressions.txt` and no shim preloaded, the #13830 leak (1784 B from `glslang_linkSPIRV`) was still reported on both triager and fixer builds. Local gcc liblsan is not CI's clang ASan with `-shared-libsan`, so read a nightly log before claiming either way ([LSan-preload slangc runs segfault intermittently; suppressions file does NOT hide the #13830 glslang leak](../learnings/1792629855978-lsan-preload-slangc-runs-segfault-intermittently-r.md), [CORRECTION: liblsan-preload slangc rc=139 is an intermittent flake](../learnings/1792629887235-correction-liblsan-preload-slangc-rc-139-is-an-int.md)).

## UBSan Findings From CI: Log-File Classification, PR vs Nightly, and Local Repro (#14121)

**The Sanitizer Summary step classifies whole log files, and only the nightly fails on "pre-existing" ones.** `ci.yml` runs `sanitizer-linux-clang-x86_64` (`ci-slang-sanitizer.yml`) on every PR. Each log file (one `ubsan.<pid>` per process) is sorted into expected / PR-related / pre-existing: on a PR, a log whose frames touch no file in the diff is pre-existing and only warns; the scheduled nightly has no changed-files list and fails on every unexpected finding. So #13999's new cpu-lane `content=gradient` test, hitting the old 0/0 at the 1x1 mip (`x/(float)(size-1)` → `-nan` cast to `unsigned char`, `tools/render-test/shader-input-layout.cpp:1564-1566`), went green and turned the next nightly red (slang#14121); before saying "PR CI couldn't catch it", grep the PR log for `FOUND N SANITIZER LOG(S): 0 PR-related, 1 pre-existing`. Per file, a known expected entry (e.g. `LEAK: getPathInfoFromFile`, #11938) sharing a log with a new finding counts as unexpected and draws a spurious "Stale expected-finding pattern never matched" warning. Diagnose from `runtime error:` / `PR-RELATED:` lines in the full job log (`gh api --allow-escape-sequences repos/<r>/actions/jobs/<id>/logs | sed 's/\x1b\[[0-9;]*m//g'`; `gh run view --log-failed` prints only the tail) ([PR jobs only warn outside the diff; the nightly fails](../learnings/1793420179456-slang-sanitizer-pr-jobs-only-warn-on-findings-outs.md)). The file-attribution side of "PR-related" is on [[wiki/concepts/ci-flake-asan-and-merge-group-cases.md]]. To check that a fix cleared a finding on the `Nightly Slang Sanitizer Test` run, fetch the sanitizer job's log (`gh run view <run> --job <job> --log`) and grep two things: `FOUND N SANITIZER LOG(S): a PR-related, b pre-existing, c expected`, and `<file>.cpp:<line>:<col>: runtime error`. A bare filename grep (`shader-input-layout`) also matches the compile and link lines, so it gives false hits. A run that concludes `success` can still carry findings that match `cmake/expected-sanitizer-findings.txt`, such as the known `slang-repro.cpp` leak, and on a schedule run every unexpected finding counts as PR-related and fails the job. Run the same grep on the last pre-fix nightly as the control that proves it catches the finding when present ([verify a sanitizer fix on the nightly: grep the report line](../learnings/1793707333227-verifying-a-sanitizer-fix-on-the-slang-nightly-gre.md)).

**A UB-only harness bug has no plain "fails before" signal.** NaN → `unsigned char` gives 0 in practice (gcc 12 -O0/-O2, clang -O2), so the #14121 test passes in a plain build before and after the fix. The signal is a UBSan render-test run with `UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1` (exit 1 pre-fix, 0 post-fix; use 0 to list every site). CI runs `halt_on_error=0`, so there it shows only in the Sanitizer Summary step; say so in the test header and PR. The CPU lane supports RGBA32Uint textures, and `TEST_INPUT` `content=<unknown word>` parses as Gradient (`shader-input-layout.cpp:124`) ([UB-only harness bugs](../learnings/1793421938615-ub-only-harness-bugs-the-failing-repro-is-a-ubsan-.md)).

**Local UBSan repro in the coworker container (Debian 12, gcc 12.2, clang 14.0.6).** clang 14 cannot compile master (`source/core/slang-internally-linked-list.h:122` needs C++20 relaxed `typename`, clang ≥16; CI uses clang-18), and gcc's `-fsanitize=undefined` omits `float-cast-overflow`, so gcc ASan misses NaN/inf→int findings. Two routes work:
- **Whole tree (~10 min at -j60):** `CC=gcc CXX=g++ cmake --preset default -B build-ub -DSLANG_ENABLE_DXIL=OFF -DSLANG_ENABLE_EXAMPLES=OFF -DCMAKE_{C,CXX,EXE_LINKER,SHARED_LINKER,MODULE_LINKER}_FLAGS=-fsanitize=float-cast-overflow`, then `cmake --build build-ub --config Release --target slangc slang-test render-test test-server` (`render-test` produces `librender-test-tool.so`); run with `UBSAN_OPTIONS=print_stacktrace=1:halt_on_error=0:log_path=/tmp/x/ubsan`. A clean run writes no files, so prove instrumentation with a revert drill (revert, rebuild `render-test`, rerun), and copy `libslang-llvm.so` into `build-ub/Release/lib` or filecheck rows are ignored ([local UBSan repro](../learnings/1793424217444-local-ubsan-repro-of-slang-ci-sanitizer-findings-u.md)).
- **One instrumented file, shared build untouched:** slang-test dlopens `librender-test-tool.so` via RUNPATH `$ORIGIN/../lib`. Make a symlink tree (`cp -as /workspace/agent/slang/build/Debug/. /tmp/ubsan-rt/Debug/`; `cp -al` fails across filesystems) with `slang-test` replaced by a real copy (glibc resolves its `$ORIGIN` via `/proc/self/exe`). Take commands from `ninja -C build -f build-Debug.ninja -t commands -s <target>`: for the `.o`, replace `-MD -MT .. -MF .. -o ..` with `-fsanitize=float-cast-overflow -o /tmp/x.o`; for the `.so`, append the flag, retarget `-o`, swap the `.o` path, drop the objcopy/strip chain (PCH mismatch harmless). The link target `Debug/lib/librender-test-tool.so` lives in `build/CMakeFiles/impl-Debug.ninja`; `... -t commands -s Debug/lib/librender-test-tool.so | tail -1` prints it, the link command is the text between `: && ` and the first ` && cd .../Debug && objcopy`, run from `/workspace/agent/slang/build`. The recipe also instruments `tools/render-test/shader-renderer-util.cpp` ([link target + second file](../learnings/1793437666271-render-test-createtexture-forced-mipcount-1-picks-.md)). gcc 12's libubsan.so.1 arrives as a NEEDED of the dlopened `.so`, so no LD_PRELOAD is needed. gcc's columns differ from CI's clang (1564:85 vs 1564:62), and UBSan prints each location once per process ([instrument one render-test file](../learnings/1793420006232-instrument-one-render-test-file-with-ubsan-without.md)).

**A latent Metal-only harness bug: forced `mipCount = 1` reads the wrong slice.** `ShaderRendererUtil::createTexture` forces `textureDesc.mipCount = 1` for Metal Texture1D/1DArray (`shader-renderer-util.cpp:144-150`, HEAD c959b561), but its upload loop still takes `m_slices[subResourceCounter++]`, while `generateTextureDataRGB8` lays slices out layer-major over the full mip chain (`a*m_mipLevels + m`). Forced on Vulkan for `Texture1D(size=4, content=gradient, format=RGBA32Float, arrayLength=2)`, layer 1 reads slice 1 (layer 0, mip 1) instead of slice 3, returning `0, 1, 0, 1814516` (heap over-read), not `0, .333, .667, 1`. Without Linux Metal CI it shows only via a gradient Texture1DArray test with arrayLength > 1 or by forcing the branch on Vulkan ([forced mipCount=1 picks the wrong m_slices](../learnings/1793437666271-render-test-createtexture-forced-mipcount-1-picks-.md)).

## external/ Dependency Kinds at HEAD

**`external/` has FOUR content kinds, and a submodule's option is not always in `external/CMakeLists.txt` — verify at HEAD.** Triaging #12176 corrected two stale beliefs: **lua IS consumed** (backs `slang-fiddle` via `SLANG_OVERRIDE_LUA_PATH`, `tools/CMakeLists.txt:59`; glm and tinyobjloader likewise feed graphics examples from outside `external/`), and **mimalloc is a real SHA-pinned submodule** (`.gitmodules:67`), not a configure-time download. Kinds: git submodules (18 at HEAD), vendored headers (dxc/, stb/, spirv/), build-time generated (glslang-generated/), fetched prebuilts (DXC, slang-tint, webgpu_dawn, slang-llvm). Knobs: `SLANG_ENABLE_*`, `SLANG_USE_SYSTEM_*` (→ find_package), `SLANG_OVERRIDE_*_PATH`, `.gitmodules` pin-policy overrides ([external/ deps at HEAD: lua IS consumed (slang-fiddle), mimalloc is now a real submodule](../learnings/1784655012400-external-deps-at-head-lua-is-consumed-slang-fiddle.md)).

## -Og Debug Builds (#12140) Break Debugging → Gate Behind a CMake Option

`#12223` (regression/P2): since PR #12140 (skiminki-nv), GCC/Clang **Debug** builds compile at `-Og`, giving `<optimized out>` locals and erratic single-stepping: `cmake/CompilerFlags.cmake:195` appends `target_compile_options(... $<$<CONFIG:Debug>:-Og>)` *after* `CMAKE_CXX_FLAGS_DEBUG` (`-O0 -g`), the last `-O` wins, and there is no opt-out short of editing source. The settled fix gates `-Og` behind a new `option(SLANG_ENABLE_DEBUG_OPTIMIZATION ...)` AND-ed into the guard (like `SLANG_ENABLE_RELEASE_LTO`). The **default is a maintainer design gate** (ON keeps #12140's ~4× Debug-build speedup for CI; OFF makes "Debug" debuggable, as `RelWithDebInfo` already gives fast + debug info); a straight revert discards a benchmarked win. With the reporter and PR author (both core) on opposite sides, PARK at triaged and forward the fixer handoff as **HELD/do-not-implement**. The flag change is verifiable from source (→ `regression`), but severity scales with optimizer aggressiveness (GCC 15) and code size, so without the reporter's GCC or a full Debug build withhold `reproduced` and call severity a hypothesis ([-Og Debug builds (#12140) break debugging → gate behind SLANG_ENABLE_* option; default is a design gate (#12223)](../learnings/1784925326386-og-debug-builds-12140-break-debugging-gate-behind-.md)).

## Inert SLANG_ASSERT and MSVC-only build errors

**`SLANG_ASSERT` is inert in this container's default build, and in release it is an optimizer assumption.** Outside `_DEBUG` it expands to `SLANG_ASSUME` (`[[assume]]`/`__builtin_assume(cond)`, `source/core/slang-common.h:364-371`), letting the optimizer delete code that runs only when `cond` is false. The stock `debug` preset here produces `CMAKE_BUILD_TYPE=Release` (check `build/CMakeCache.txt`), so a new assert never fires locally while a real `_DEBUG`/CI build aborts (PR #12263 lost a review round to an inert `getConstant` shape-assert) ([local Debug preset builds Release → SLANG_ASSERT is inert](../learnings/1785342311498-local-slang-debug-preset-builds-cmake-build-type-r.md)). **Never assert a precondition you also runtime-guard on**: `SLANG_ASSERT(x); if(!x) return fallback;` lets release delete the fallback as dead. Use `if/else` (with a rationale comment) for a real discriminant, `SLANG_ASSERT` for impossible states, `SLANG_RELEASE_ASSERT` to crash loudly in release ([SLANG_ASSERT becomes __builtin_assume in release — never assert a precondition you also guard on](../learnings/1785335639560-slang-assert-becomes-builtin-assume-in-release-nev.md)). Conversely, **don't replace a reachable `if (!cond) return false;` guard with `SLANG_ASSERT(cond)`**: out-of-contract input becomes release UB instead of a no-op ([SLANG_ASSERT is an optimizer assumption in release builds](../learnings/1791173083128-slang-assert-is-an-optimizer-assumption-in-release.md)). The same rule applies to the remedies a reviewer proposes: on #14202 R1 a tested remedy read `SLANG_ASSERT(linkage); use(linkage->...)`, and the next round caught it, because a null `linkage` is release UB rather than a crash. An out-of-contract shape that is dereferenced right after the check takes `SLANG_RELEASE_ASSERT`, which does fire in Release slangc (the linker's `SLANG_RELEASE_ASSERT(c->value.ptrVal == nullptr)` `IRPtrLit` check is one), matching the repo rule "fail loudly on out-of-contract input". An aside from the same round: a C++ raw string `R"( ... )"` in a unit test ends early on Slang source containing `("...")]` (for example `[DllImport("lib")]`), so use a delimiter such as `R"slang( ... )slang"` ([SLANG_ASSERT is SLANG_ASSUME in Release: not in front of a dereference in a remedy](../learnings/1793672675596-slang-assert-is-slang-assume-in-release-don-t-put-.md)).

To exercise asserts, configure `-DCMAKE_BUILD_TYPE=Debug` and run the affected tests before committing any new `SLANG_ASSERT`. Example: `SLANG_ASSERT(iface->getRequirementCount() == 5)`, written from the 5 declared members of `IBackwardDifferentiable` in core.meta.slang, is false — the `BwdCallable : IBwdCallable` conformance is its own entry (kind 29, BwdCallableContextWitness), making 6. Release passed every test on a false assumption; only Debug showed E99997. Count IR requirement entries by instrumenting (`cast<IRInterfaceRequirementEntry>(iface->getOperand(i))` + `BuiltinRequirementDecoration` kind), not from `.meta.slang` ([verify a count assert on a Debug build](../learnings/1791585758023-verify-a-count-assert-on-a-debug-build-slang-asser.md)).

**A pure-C++ change where ALL Windows (MSVC) builds fail but ALL Linux/macOS pass is almost always an MSVC-only warning-as-error.** On #13089 every Windows build failed with `error C2220 … warning C4458: declaration of 'workList' hides class member` (a local shadowing a struct member). Windows builds use `/W4 /WX`, so C4458 and siblings (C4456 local shadow, C4245/C4244 signed/unsigned, C4189 unused local) are hard errors GCC/Clang don't emit by default. Check new locals in methods against member names (`workList`, `builder`, `module`, `context`), grep failed Windows logs for `error C2220` plus the `warning Cxxxx`, and fix with a behavior-neutral rename ([MSVC /WX rejects C4458 (local hides class member) that GCC/Clang pass silently — local Linux build won't catch it](../learnings/1789579281328-msvc-wx-rejects-c4458-local-hides-class-member-tha.md)).
