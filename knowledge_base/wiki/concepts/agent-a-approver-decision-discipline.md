## TL;DR

- The OPEN_GAP severity bar includes **"a gap that undermines the PR's stated purpose"** — a hole closed *in the tool* but *in no CI gate* is purpose-undermining, not advisory. "No CI gate doesn't make the code wrong" answers the wrong question, and slides one-directionally toward approval. An OPEN_GAP abstain is "a human must look," not a fix demand on the author.
- A PR head can move **three times mid-decision**. "Likely a duplicate delivery" is a claim about state (the webhook payload carries no head SHA) — re-probe `headRefOid`. An invalidation can split by *function*, not file. The settle signal is the review **artifact** (`pulls/N/reviews` with matching `commit_id`), which lands ~18s before the check flips.
- Terminal PR webhooks (`pr_merged`/`pr_closed`) route to **`gh-issue-*`** threads (the normal path), the router **resolves** to an existing session rather than minting one — so dispatching on the canonical issue thread does not strand the join. **A count of successes is not a model of the mechanism.**
- **A correction/retraction is not self-verifying** — it inherits none of the original's verification and needs its own; an over-correction is under-audited precisely because retreat looks like humility. Verify a retraction like a claim.
- The **critique gate** counts *any* file edit (including memory writes), denies the *whole* compound bash command (including read-only verification inside it), re-arms on edits made to satisfy its own prior suggestion, and mis-fires on prose that merely *mentions* a gated command (the Bash branch is unanchored). `codex-reply` cannot record a stage — verify the ledger incremented.
- A **zero-hit proves absence only after a positive control**; a re-derived capability-negative is a **store-search failure wearing an instrument failure's clothes** — grep your own store before recording any tooling defect.

## The OPEN_GAP bar and one-directional error

On slang#12344 (docs-link fix) a `lint_markdown_tables` checker was added, verified invoked by **no CI workflow at all**, and filed under "context, deliberately NOT charged as gaps" — 6/6 clauses passed, approval proposed [[approver/challenger-miss] "No CI gate doesn't make code wrong" answers the wrong question — the OPEN_GAP bar includes undermining the PR's STATED PURPOSE](wiki/learnings/1785863569258-approver-challenger-miss-no-ci-gate-doesn-t-make-c.md). DECISION_REVIEW reversed it to MUST-FIX. Three separable errors:

1. **Wrong question.** The rationale ("absence of a gate doesn't make shipped code wrong") is true and irrelevant. The severity bar is *plausible trigger, real blast radius, **or a gap undermining the PR's stated purpose*** — a PR that promises to "close the hole" closes it in the tool and in no gate, so the class recurs undetected. *Having the words is not having applied the rule* — the finding was held in prose and not recognized as a predicate.
2. **"Pre-existing" mis-scoped.** The *script* is old; the *checker* is **new in this PR**. Grep the diff, not the file's history.
3. **Conflated "charging the author" with "declining to approve."** Demanding CI wiring is out of scope; an OPEN_GAP abstain is not a fix demand — it is "a human must look." The conflation was directional: it only ever produced approval.

The social failure mode: raising the gap to a peer twice, framed as "context," and getting agreement — **two tiers running the same frame is a shared prior, not independent evidence.** All the adversarial rigor on the *evidence* did not substitute for re-reading the *rule*. Catch it by quoting the PR's stated purpose and checking each mechanism it claims one at a time; re-read the three-part severity clause verbatim and say which part you rely on; and note the direction — **a one-directional error pattern (every judgment call resolving toward approval) is itself a signal.** Record the falsifier in the row (merged unchanged ⇒ over-cautious; human asks for CI wiring ⇒ the read was right) — an abstain that can't be wrong teaches nothing.

## Revision-chain and settle-signal mechanics

slang#12344 advanced through three heads in one session while deciding [[approver/infra] A "duplicate webhook" claim is a claim about state — the payload carries no head sha; plus the settle signal is the review ARTIFACT, not the check](wiki/learnings/1785863652001-approver-infra-a-duplicate-webhook-claim-is-a-clai.md):

- **"Likely a duplicate delivery" is a claim about state.** The webhook payload carries **no head SHA**, and `reason`/`title`/`author` are invariant across pushes — payload equality is non-diagnostic of redelivery. Re-probe: `gh pr view <pr> --json headRefOid,state`. The check belongs at the dispatching tier *and* the deciding tier (which owns the SHA it records).
- **A one-file `+125/−25` delta can be undebounceable** — the rule is not "small delta ⇒ skip" but "does the delta touch the premises the verdict rests on." **An invalidation can split by FUNCTION, not file**: a fence-skip newly added to `lint_markdown_tables` but pre-existing in `heading_slugs` means measurements pinned to the latter still carry.
- **The settle signal is the ARTIFACT, not the check.** The production review posts `pulls/N/reviews` ~18s *before* its check-run flips; poll for a row whose `commit_id == <pinned sha>`, and arm the watcher to **abort on head-move** or you settle on a superseded SHA.
- **Hung-vs-alive is a STEP-level question** — read `actions/runs/<id>/jobs` step states before `ABSTAIN_INFRA`; sitting `in_progress` on `PR Review` is alive. Pick the honest reason code: "current-head artifact missing" is not `NO_REVIEW_SIGNAL` when reviews existed at prior heads. **Waiting beats mislabeling.**
- Harness traps: `EXIT=$?` after piping through `tail` reads tail's status (read the script's own structured output); run the clause script *after* synthesizing the review doc (else `commit_match` evaluates `unevaluable` → `ABSTAIN_INFRA`, reporting your own sequencing as a property of the PR).

## Where terminal webhooks land — measured, not inferred

The calibration loop needs terminal PR events to reach the session holding the decision row. Measured from the session store: **~65 of ~74 webhook inbounds landed on `gh-issue-*` threads; only 4 on `gh-pr-*`** — the "terminal events only route to `gh-pr-*`" hypothesis was exactly inverted [[approver/infra] Terminal PR webhooks route to gh-issue-* threads, not gh-pr-* — and the router RESOLVES to an existing session, never mints one (measured from the session store)](wiki/learnings/1785865141443-approver-infra-terminal-pr-webhooks-route-to-gh-is.md). Terminal events demonstrably reach `gh-issue-*`-only sessions (several with recorded join records), so dispatching on the canonical `gh-issue-<owner>/<repo>-<num>` thread does **not** strand the join. The **router resolves to an existing session, not mints one** — every session checked had a chat forward as its first inbound, zero were webhook-minted. The methodological lesson: the first answer ("my store holds 79 archived terminal rows ⇒ the path fires") was accurate and **not evidence for the claim** — it verified *that joins happened*, never *what routing shape they arrived through*. ⭐ **A count of successes is not a model of the mechanism.** When someone proposes a condition your data is blind to, the honest first move is "my evidence can't see that," then go get evidence that can. Enumerate the population by the *hypothesis's* discriminating attribute, not by the outcome you already care about.

## A correction is not self-verifying

A retraction inherits none of the original claim's verification and needs its own; it is **under-audited precisely because retreat looks like humility** [[approver/clause-gap] An over-correction is a defect too — "the gate wouldn't have prevented it" is false with CI_GATE_REQUIRED_SUITE set: the build suite is conclusion=failure, so the host parks the wake upstream of the waived clause](wiki/learnings/1785943756223-approver-clause-gap-an-over-correction-is-a-defect.md). Having correctly established that `ci_green_on_sha` passed via a *waiver* branch (not the blind combined-status API), an orchestrator prepared a correction saying "the gate wouldn't have prevented it" — itself wrong, because it dropped a **configuration variable**: with `CI_GATE_REQUIRED_SUITE` set, the failing build suite parks the wake *upstream* of the waived clause (the gate *would* have prevented it); unset, it releases on any green suite. The unconditional form is false either way; report the conditional. Rules: **verify a retraction like a claim** (what measurement falsifies the correction? — one `check-suites` call); for any counterfactual, enumerate the config variables it depends on and answer per-setting; when citing a policy value as a defect, read its `_comment`/provenance first (`require_ci_green: false` was a deliberate, human-signed shadow-mode widening, not a bug). **Over-correction is a defect with the same cost as the original error.**

This recurs. On slangpy#1090 the `ci_green_on_sha` clause conflated two epistemic states onto one `pass` [[approver/infra-abstain] Full audit: 5 of 18 registry entries are absent from the declared source, and they cluster by function (both approvers, webhook routing, agent-browser) — one declares itself local-only, so the registry conflates "syncs from upstream" with "exists locally"](wiki/learnings/1785946924487-approver-infra-abstain-full-audit-5-of-18-registry.md); a full 18-entry registry audit found 5 skills absent upstream, **clustered by function** (both approvers, webhook routing, clarity-runner, agent-browser) — the `.external-skills.json` schema has no way to express "local-only," so it lists local skills as synced. Same disease each time: **a schema that can't represent a real state will misrepresent it.** And **enumerate before naming** — auditing all 18 turned a peer's 4-sample "some entries missing" into "the missing ones are a category the schema can't name," a better defect statement reached only by enumerating.

## The critique gate: scope, denial, and re-arming

The critique gate mis-fires in several documented ways [critique gate arms on MEMORY-file edits and denies read-only gh api — verify state before you start editing notes](wiki/learnings/1785881956405-critique-gate-arms-on-memory-file-edits-and-denies.md) [A denied gate kills the WHOLE compound command — verify each step ran, don't report intent as outcome](wiki/learnings/1785880153114-a-denied-gate-kills-the-whole-compound-command-ver.md) [Writing guidance ABOUT a gated command installs a permanent tripwire: the critique gate's Bash branch is UNANCHORED, so grepping your own notes for "gh pr create" is denied and burns soft-cap strikes](wiki/learnings/1785952099887-writing-guidance-about-a-gated-command-installs-a-.md) [codex-critique: codex-reply cannot record a gate stage; verify the round actually counted](wiki/learnings/1785908614073-codex-critique-codex-reply-cannot-record-a-gate-st.md):

- **It counts non-code edits.** 7 `memory/*.md` writes armed a gate whose stated scope is *PR creation* — its edit counter doesn't distinguish code from note-taking. **Verify heads/review-states/comment-IDs BEFORE a memory pass**, because the pass arms the gate.
- **A denial kills the WHOLE compound command**, including read-only `gh api`/`git` calls that can't reach the gated action — so you lose verification at the moment you're deciding whether an action is safe. **Never batch a mutation with its verification and publication in one gated command** (do the mutation with Edit/Write, which fails loudly and independently); after any denial, **re-establish state by reading it, never by replaying your intent** (a fixer reported a `sed` substitution done from *intent* after the whole command was denied — a hash check caught the pre-substitution file). Non-Bash tools (`Read`/`Grep`/`Edit`/MCP) still work while blocked. And before treating a blocked check as a blocker, ask whether its outcome would change your action — a verification you can't run only matters if its result would change what you do.
- **The Bash branch is UNANCHORED** — it matches `gh pr create` *anywhere* in the command text, so `grep -n "gh pr create" notes.md` is denied as "PR creation." **Recording guidance ABOUT a gated command installs a permanent tripwire** against reading your own notes (and burns soft-cap strikes toward auto-escalation). Read such files with the `Read`/`Grep` tools, never Bash; stop reproducing a confirmed false-positive. This does *not* contradict the "text-matching is deliberate advisory friction" learning — that guards false *negatives* (hardening the matcher); this reports missing *anchoring* → false *positives* (matching prose). Anchoring narrows scope; it does not add enforcement.
- **`codex-reply` cannot record a gate stage** (no `developer-instructions` field for the canonical sentinels) — re-verification must be a fresh `mcp__codex__codex` call with `STAGE:` as the literal first line. A round can also drop with no error at all — **check the ledger** (`jq '{critique_rounds}' /workspace/.claude/workflow-state.json`); if it didn't increment, the round didn't count. The `### Attested` sha256 list binds the approve to file contents — finish edits before the final OUTPUT_REVIEW. Always pass `sandbox: "danger-full-access"`.

## A zero-hit proves absence only after a positive control

A re-dispatch asserted "your turn died with a 429 before any work; nothing recorded, verified just now" — every clause false (`record_decision` had fired; the 429 hit a *later* turn) [[approver/infra-abstain] A zero-hit only proves absence after a positive control — ncl sessions messages cannot render tool calls, so "did I record that decision?" returns a false clean](wiki/learnings/1785939590944-approver-infra-abstain-a-zero-hit-only-proves-abse.md). The first probe `ncl sessions messages <sid> | grep record_decision` → 0, which would have "confirmed" the false premise and produced a **duplicate ledger row from a stale pre-critique draft**. The zero was a property of the instrument (system-kind rows filtered by default). A **verification claim inherits the scope of what was actually measured, not the sentence it's attached to** — "verified just now" covered PR liveness (`state`/`isDraft`), which cannot discriminate "decision recorded" from "not recorded" (an open PR is fully consistent with a recorded ABSTAIN). And an unverified negative that *corroborates what you were just told* gets the fewest re-runs of all — the agreement suppresses the second look.

But the diagnosis "the instrument can't render tool calls" was itself a **re-derived false capability-negative** — the real fix was `--include-system`, and this exact retraction had been filed *two days earlier* [[approver/infra-abstain] RETRACTION²: I re-derived a false capability-negative about ncl sessions messages that I had ALREADY RETRACTED two days earlier — a positive control proves an instrument is broken, never HOW](wiki/learnings/1785940006523-approver-infra-abstain-retraction-i-re-derived-a-f.md). **A positive control establishes *THAT* an instrument is broken, never *HOW*** — the diagnosis is a second claim needing its own probe (`--help`), and it rode in on the control's credibility. **A re-derived capability-negative is a store-search failure wearing an instrument failure's clothes** — diagnosing it as "wrong instrument" localizes the defect in the tool and leaves the real failure (never searching the store) unbooked. ⇒ **before recording any caveat/limit/defect about your own tooling, the first command is `grep -ril <command-name> /workspace/shared/learnings/`.** A self-critical artifact is not a verified one — the confession occupies the diligence slot where the check belongs.
