# slang-rhi backend runtime internals

`slang-rhi` is the graphics-abstraction runtime library (Vulkan / D3D12 / CUDA / Metal / WGPU backends), vendored as a submodule and exercised by slang-test's `render-test`. This page collects source-verified facts about its **runtime** internals — buffer/queue lifetime, the CUDA constant-buffer pool and heap, CUDA entry-point lookup, staging-heap pooling, and Vulkan device creation (software Vulkan, extension gating) — as distinct from the compiler's target emit (the `slang-backends-*` pages) and from slang-rhi test/build authoring ([Slang & slang-rhi test harness](slang-a-test-harness.md)). Facts were source-verified at HEAD `e17f6d7` unless noted.

## TL;DR

- **A null deref pinned at one site usually has a symmetric twin; grep every deref of the pointer before endorsing a one-site fix.** An imported Vulkan buffer's null `m_buffer.m_api` crashes both `~BufferImpl` (`:169`) and `getView()` (`:333`).
- **A pointer that doubles as an ownership flag cannot be fixed by populating it** (setting `m_api` on an import double-frees). Take the dispatch table from `getDevice<DeviceImpl>()->m_api`; the landed fix (#945) added explicit `m_ownsBuffer`/`m_ownsMemory`, so name the conflation and offer that refactor.
- **The Vulkan `VkQueue` is shared de-facto and guarded nowhere** (never imported, re-fetched at index 0; mutexes guard only the command-buffer pool). A per-wrapper mutex cannot serialize it; that needs an app-supplied shared object or a per-native-queue registry.
- **Before guarding a public getter, grep its internal callers.** `getDeviceAddress()` is called ~20× during command recording; split a public guarded entry from an internal unchecked accessor, and keep `base ? base + offset : 0`.
- **`string_view` keys into a bump allocator's pages survive `vector<Page>` growth**; a byte-content intern map is lifetime-safe iff cleared before the pool frees pages and read only during build.
- **Before slang-rhi#923 (2026-10-22), a destroyed CUDA device leaks its 256 MiB pinned heap page while another device holds the primary context.** Measure with VmRSS plus `device.report_heaps()`; a CI OOM at `cuda-heap.cpp:395` means pre-#923.
- **On main before PR #929, ReadBack staging pages are `HOST_VISIBLE | HOST_COHERENT`, not `HOST_CACHED`** (~0.15 vs 4.7 GB/s on the L40S); #869's pooled `readBuffer` inherits #929's cached type (verified at runtime). `StagingHeap::map` returns an offset-advanced pointer.
- **Prove pooling on a fresh device (`DontCacheDevice`):** a fresh heap goes `0→1` pages on the first read.
- **Tie a pooled staging allocation's lifetime to GPU completion:** `retainResource` holds a `RefPtr<StagingHeap::Handle>` from `allocHandle` until command-buffer retirement; never bare alloc/free.
- **Do not route WebGPU `readBuffer` through the shared `StagingHeap`:** it adds a queue-wide wait `mapAsync` already covers, and each map maps a whole 16 MiB page; use a small dedicated reused buffer.
- **Overflow-safe range check:** check `offset > desc.size`, then `size > desc.size - offset`; never form `offset + size`.
- **A Vulkan VUID fix in Slang examples is not CI-gated** (surface tests skip headless, examples run with validation off); say it is verified by construction.
- **D3D11/D3D12 `clearTextureUint`/`Sint` silently do nothing on a RenderTarget-only texture**; a new integer-RT clear test fails on D3D only.
- **A CUDA `cuModuleGetFunction … NOT_FOUND` at pipeline creation: grep for E40100 first** (`main` → `main_0`). slang-rhi squash-merges, so re-pin a submodule pointing at a PR head after merge.
- **Run `-vk` on the L40S first; lavapipe is only the fallback** (`nvidia-smi -L` each session; report failure as infra). Lavapipe-only device creation fails on the unconditional `VK_KHR_shader_non_semantic_info`; a local-only guard + `VK_ICD_FILENAMES=…lvp_icd…` gives real readbacks (never commit).
- **`VK_EXT_shader_atomic_float2` is enabled only when float16 atomics exist**, and the L40S has none, so a `-vk` float32 atomic min/max loses the device; cover min/max with compile tests.
- **slang-rhi Metal orders encoders only through one queue `MTLFence`, and `memoryBarrier` runs before every dispatch after the first**; `clearTexture` and `executeCallback` bypass encoder boundaries, so any encoder-coalescing change must fix both.
- **slang-rhi Metal (and WGPU) never advertise `Feature::TimestampQuery`.** Apple silicon samples only at stage boundaries; use Dawn's empty-blit trick (`sampleBufferAttachments` + 1-byte fill).
- **Thread-group size: slang-rhi CUDA and Metal always launch the reflected `[numthreads]` size;** a host-chosen size is on [[wiki/concepts/slang-backends-compute-thread-group-size-and-dispatch-override.md]].
- **slang-rhi guarantees no ABI (and no source) compatibility between revisions since #895 (2026-10-08)**, so a pre-October "ABI break" objection is stale; still keep an inline wrapper for an old signature, because render-test and sgl call it.
- **Shader-object binding is on [[wiki/concepts/slang-rhi-shader-object-binding-and-root-layout.md]]:** per-dispatch binding data, D3D12 root CBVs, Vulkan push-constant ranges, the global `$Globals` constant buffer.

## Vulkan buffer and queue lifetime

**A null deref pinned at one site has a create-site twin (slang-rhi#860).** `DeviceImpl::createBufferFromNativeHandle` (`src/vulkan/vk-buffer.cpp:475`) imports a borrowed `VkBuffer` without `VKBufferHandleRAII::init()`, leaving `m_buffer.m_api` null, so `~BufferImpl()` crashes destroying cached `VkBufferView`s (`:169`). The reporter's destructor-only fix misses that `BufferImpl::getView()` creates views through the same pointer (`:333`), so a texel SRV/UAV import crashes there first. Route both through the always-valid `getDevice<DeviceImpl>()->m_api` (mirror `:157-163`). Populating `m_api` double-frees, because the destructor (`vk-buffer.h:30-34`) frees buffer and memory iff `m_api != null`. Vulkan-specific ([create site shares the deref](../learnings/1789372389751-slang-rhi-imported-buffer-null-m-api-the-create-si.md)). The bot's PR #868 kept `m_api` as the implicit ownership flag and scoped out the uninitialized `m_memory`; skallweitNV closed it and landed #945 with explicit `m_ownsBuffer`/`m_ownsMemory` (null-default handles, copy disabled, ownership set after each allocation), fixing `m_memory` too. When a fix routes around a field that means two things, name the conflation and offer the refactor; a reviewer calling the root issue "out of scope" is not the maintainer agreeing ([explicit ownership](../learnings/1793091793971-slang-rhi-maintainer-prefers-explicit-ownership-ov.md)).

**One `VkQueue`, guarded nowhere (slang-rhi#863).** `DeviceNativeHandles` has only instance/physicalDevice/device slots (`include/slang-rhi.h:3431-3433`), and the queue always comes from `vkGetDeviceQueue(m_device, m_queueFamilyIndex, 0, &queue)` (`vk-device.cpp:1857-1858`), so two `DeviceImpl` over one `VkDevice` share it. `CommandQueueImpl::submit` (`vk-command.cpp:2131`), `VulkanDeviceQueue::flushStepA` (`vk-device-queue.cpp:124`), `SurfaceImpl::present`/`destroySwapchain` and both `vkQueueWaitIdle` sites use it unlocked; `m_mutex` and `m_deferredDeleteQueueMutex` guard only the command-buffer pool. d3d12 and cuda follow the same pattern, with no cross-device sync or registry. Serializing needs an app-supplied shared object (which also covers the app's raw calls) or a library per-native-queue registry behind one choke point ([one VkQueue](../learnings/1789373034879-slang-rhi-vulkan-shares-one-vkqueue-de-facto-and-g.md)).

## Guarding a public getter that the RHI also calls internally

For slang-rhi#787 (forbid `getDeviceAddress`/bindless handles on `Shared` resources on Vulkan), `IBuffer::getDeviceAddress()` is also called ~20× during recording (AS/micromap inputs and scratch, cluster ops, cooperative-vector src/dst). A guard returning 0 corrupts those (codex flagged HIGH), and `BufferOffsetPair::getDeviceAddress()` computing `base + offset` turns a 0 sentinel into a plausible address; keep `base ? base + offset : 0`. Split a public guarded entry from `getDeviceAddressUnchecked()` plus a `getBufferDeviceAddress(BufferOffsetPair)` helper, rerouting internal sites whose operand is app-provided (could be `Shared`) but not RHI-owned buffers (SBT, AS/micromap backing); internal operands stay in `m_trackedObjects` and are reacquired normally ([split public/internal](../learnings/1790032907874-guarding-a-public-getter-that-rhi-calls-internally.md)).

## Public API compatibility: no ABI guarantee since slang-rhi#895

Since slang-rhi#895 (2026-10-08), README.md "Project status and compatibility" (lines 35-41) and CONTRIBUTING.md:15-19 say that neither source nor binary (ABI) compatibility is guaranteed between revisions, and that headers and binaries must come from the same revision. Maintainer PR #940 (2026-10-27) then inserted `createResourceHeap` and its siblings in the middle of `IDevice`. So an "this would be an ABI break" objection written before October 2026 is no longer a hard blocker; #811 (passing a session or `IComponentType` to `createShaderObjectFromTypeLayout`) is one such stale objection. Source compatibility still matters to downstream callers (slang render-test, sgl): keep an inline wrapper for the old signature, as `createShaderObject` does, whose virtual takes `ISession*` first and whose inline session-less overloads keep old call sites compiling. This differs from Slang's own `include/` rules, which still forbid vtable reordering ([slang-rhi no longer guarantees ABI (README policy since #895)](../learnings/1793622511423-slang-rhi-no-longer-guarantees-abi-readme-policy-s.md)).

## CUDA constant-buffer pool: interning by byte-content is lifetime-safe

slang-rhi#861's `std::unordered_map<std::string_view, CUdeviceptr>` keyed into `objectData.host` looks like a dangling-key hazard but is not: `ConstantBufferPool::Pool::allocate` (`src/cuda/cuda-constant-buffer-pool.cpp:96`) is a bump allocator whose `HeapAlloc` pages (`include/slang-rhi.h:3135/3138`) live outside the `std::vector<Page>`, so `push_back` moves Page structs, not bytes, and the pool is append-only during a build. `BindingCache` and `ConstantBufferPool` are both `CommandBufferImpl` members (`cuda-command.h:116-117`); `reset()` clears the map (`:1465`) before freeing pages (`:1466`), and the map is read only via `try_emplace` while building. The execution-side copy-skip (`m_globalParamsState` in `cmdDispatchCompute`) is correct: `CommandExecutor` is per-command-buffer, `m_globalParams` is a stable per-pipeline symbol written only by that copy, the stream is FIFO, and `cmdExecuteCallback` clears the cache. The halves are coupled (pointer identity proxies byte equality only because interning canonicalizes addresses). Label such an optimization `enhancement` ([intern map lifetime-safe](../learnings/1789372807192-slang-rhi-cuda-string-view-keyed-intern-map-into-c.md)).

## CUDA heap: a destroyed device leaks 256 MiB pinned pages before slang-rhi#923

Up to 57018e3 (#923, merged 2026-10-22), `HeapImpl::~HeapImpl` (`src/cuda/cuda-heap.cpp:306-310`) frees only the page cache and `Heap::~Heap` (`src/heap.cpp:18-24`) deletes resident pages without `cuMemFree`/`cuMemFreeHost`. Devices share the primary context, and any request ≤64 MiB gets a 256 MiB page (`heap.cpp:45-48`), so in slangpy pytest (session-cached devices hold the context) every uncached device that uploads or reads back strands 256 MiB. Repro (L40S, slangpy 0.43.1): keep one CUDA device open, loop creating a second, uploading a texture, closing; VmRSS +256 MiB per cycle, 0 without the upload or the other device (`/workspace/agent/repro-13890/variants2.py`; shader-slang/slang#13891). `/proc/self/smaps` attributes it to no mapping, so use VmRSS + `device.report_heaps()`. `Heap::allocate`'s OOM retry (`heap.cpp:77-82`) never runs on CUDA because `SLANG_CUDA_RETURN_ON_FAIL_REPORT` returns `SLANG_FAIL` (-2147467259) for every `CUresult` (`cuda-utils.h:83`). A CI OOM at `cuda-heap.cpp:395` is pre-#923 (`:406` after). Don't name repro modes as substrings of each other ("noupload" matched "upload") ([pinned page leak](../learnings/1792770237658-slang-rhi-cuda-heap-leaks-256-mib-pinned-page-per-.md)).

## Staging-heap pooling for readback

For Vulkan `readBuffer` via the pooled `m_readbackHeap` (slang-rhi#862): **ReadBack pages are not `HOST_CACHED` on main before #929** — `StagingHeap::allocPage` calls `createBuffer` with `memoryType=ReadBack`, which requests `HOST_VISIBLE | HOST_COHERENT` (`vk-buffer.cpp:414-416`); the `HOST_CACHED` flags at `vk-heap.cpp:38-40` belong to the separate `IHeap` path (a "faster CPU reads" claim was caught by OUTPUT_REVIEW). `StagingHeap::map(alloc, &ptr)` returns `page->getMapped() + offset` (`staging-heap.cpp:181`); `getOffset()` is only the `copyBuffer` destination. `free()` keeps one empty 16 MiB standard page and frees oversized pages, so after a read `getUsed()==0` but `getNumPages()>=1`; prove pooling with `GPU_TEST_CASE(name, Vulkan | DontCacheDevice)`, where `initialize()` pre-allocates nothing and `0→1` pages is definitive. Range-check `offset > desc.size`, then `size > desc.size - offset` ([HOST_CACHED myth](../learnings/1789440138998-slang-rhi-vulkan-readbuffer-pooling-host-cached-my.md)).

**L40S memory types** (2026-10-20, TRANSFER_DST): type 1 DEVICE_LOCAL, type 2 HOST_VISIBLE|HOST_COHERENT (~0.15 GB/s CPU read), type 3 adds HOST_CACHED (~4.7 GB/s at 256 MiB). Main picks type 2 for ReadBack buffers, the `readBuffer` staging buffer and readback pages; PR #929 (7577eea, slang-rhi#928) picks type 3 for all three, so "not HOST_CACHED" describes pre-#929 main, not an invariant ([L40S memory types](../learnings/1792502963862-slang-rhi-tests-tc-needs-a-device-suffix-wildcard.md)). Resolving #869 (pooled `readBuffer`) against #929 kept #869's body and dropped #929's hunk on the claim the pooled path inherits it (`device.cpp:436` ReadBack heap → `staging-heap.cpp:234-238` `createBuffer` → HOST_CACHED preference); a temporary `fprintf` in `allocateVkMemory` (reverted) confirmed type 3, flags `0xe`, for the readback page. Check claimed inheritance at runtime, not only by reading ([verify inheritance](../learnings/1793106992385-merging-a-pr-whose-code-path-an-upstream-pr-edited.md)).

**Free on GPU completion, not RAII scope exit** — a scope-exit free can return an in-flight page when `waitOnHost` fails. Mirror `uploadBufferData`/`uploadTextureData` (`src/command-buffer.cpp:616,688`): after `copyBuffer`, `checked_cast<CommandEncoder*>(commandEncoder.get())->m_commandList->retainResource(staging)`, then `submit`/`waitOnHost`/`map`. `retainResource` (`command-list.h:473`) inserts into `m_trackedObjects` (`command-buffer.h:422`), cleared by `CommandBuffer::reset()` at retirement (not `CommandList::reset()`), so a failed wait leaves the page owned by the un-retired buffer. Hold `RefPtr<StagingHeap::Handle>` from `allocHandle`: success-only frees leak on any `SLANG_RETURN_ON_FAIL` and trip `StagingHeap::release()`'s `m_totalUsed==0` assert (`Device::readTexture` has this latent leak). Follow-up, not blocker: `~DeviceImpl` (`vk-device.cpp:147`) ignores `m_queue->waitOnHost()`'s result before releasing the heaps; only a cross-backend teardown reorder fixes it. `checked_cast` is a `static_cast` in release ([retainResource](../learnings/1789448569968-slang-rhi-fix-pattern-tie-pooled-staging-lifetime-.md)).

**The shared heap is wrong for WebGPU readback (slang-rhi#953, #956).** `Device::readTexture`'s path (`src/device.cpp:887`) submits, `waitOnHost`s (a queue-wide `wgpuQueueOnSubmittedWorkDone`, `wgpu-command.cpp:1221` — the round trip #953 removes since `mapAsync` waits), then maps; and `m_keepPagesMapped=false` on WGPU/Metal (`staging-heap.cpp:20`) makes each map call `mapBuffer` on the WHOLE buffer (`wgpu-buffer.cpp:168`), a 16 MiB page (`stagingHeapPageSize`) for a 4-byte read. #956's dedicated small reused buffer avoids both. Check a sibling PR's diff before repeating "same design": #869 uses the shared heap (#862's Approach B), not a bounded slot + mutex [WebGPU double-wait](../learnings/1793260323330-slang-rhi-webgpu-shared-stagingheap-readback-path-.md).

## Vulkan VUIDs in Slang examples are not CI-gated

A Slang examples fix for a dynamic-rendering format-mismatch VUID (PR #13127, `colorTarget.format` vs attachment) is checked by no CI gate: slang-rhi surface/swapchain tests skip headless at `hasMonitor()`, the examples' test path disables validation (`enableValidation = !isTestMode()`), and examples skip on Vulkan platforms. State "verified by construction plus compile/link"; for format bugs follow the value to the real `VkImageCreateInfo`/`VkSwapchainCreateInfoKHR`/`ColorTargetDesc.format` field ([validation OFF in CI](../learnings/1789564810840-vulkan-vuid-in-slang-examples-left-to-ci-is-not-a-.md)).

## D3D11/D3D12 integer texture clears are no-ops on RenderTarget-only textures

In main f0c50c7 (and PR #899 head f76fb50), `cmdClearTextureUint` (`d3d11-command.cpp:340`, `d3d12-command.cpp:505`) handles only `TextureUsage::UnorderedAccess`, and `clearTextureSint` shares `commands::ClearTextureUint`, so integer clears on an RT-only texture do nothing silently; `cmdClearTextureFloat` has an RT branch, and Vulkan (`vkCmdClearColorImage`), Metal and WGPU are fine. Fix: an RT branch converting int→float for `ClearRenderTargetView` (exact ≤2^24); Dawn uses a draw (`apply_clear_big_integer_color_value_with_draw`) for larger values ([D3D integer RT clears](../learnings/1792518561170-slang-rhi-d3d11-d3d12-cleartextureuint-sint-are-no.md)). Side facts elsewhere: a green slang-rhi `build (windows, aarch64, msvc, Debug)` skips its `Unit Tests` step ([[wiki/concepts/slang-a-test-harness.md]]); backtick-wrapped `### Attested` hashes break the critique gate ([[wiki/concepts/agent-routing-f0909b1-critique-gate-mechanics.md]]).

## CUDA pipeline creation: an entry point named `main` is renamed `main_0` (E40100)

In slangpy#1189 CI (2026-09-29) a `[shader("compute")] void main()` kernel failed at pipeline creation with `cuModuleGetFunction … CUDA_ERROR_NOT_FOUND named symbol not found` (`src/cuda/cuda-pipeline.cpp:89`), and `warning[E40100]: entry point 'main' has been renamed to 'main_0'` matched all nine failures. Working hypothesis (unverified with coverage off): the RHI looks up the original name. Existing `void main` tests only load modules, so they miss it. slang-rhi squash-merges, so a submodule pinned to an open PR head must be re-pinned to the squash commit ([`main` → `main_0`](../learnings/1790685200036-cuda-entry-point-named-main-is-renamed-to-main-0-e.md)).

## Vulkan device creation on lavapipe: `VK_KHR_shader_non_semantic_info` is not optional

Containers run `-vk` on the L40S with the NVIDIA ICD; measure with `nvidia-smi -L` each session and report failures as infra ([containers have an L40S](../learnings/1792133264162-coworker-containers-have-an-nvidia-l40s-gpu-cuda-vulkan.md)). This section applies only when lavapipe is the sole ICD, as in the 2026-09-28→10-16 passthrough outage ([passthrough restored](../learnings/1792142517350-correction-gpu-passthrough-restored-2026-10-16-con.md)); never record that as "no GPU". Then `slang-test ... -vk` reports `Check vk,vulkan: Not Supported` despite `/usr/share/vulkan/icd.d/lvp_icd.x86_64.json`, because `external/slang-rhi/src/vulkan/vk-device.cpp` (~:595) pushes `VK_KHR_shader_non_semantic_info` unconditionally, Mesa 22.3.6 lavapipe lacks it, and `vkCreateDevice` fails (`VK_LOADER_DEBUG=error,warn`). This names the extension behind failed device creates on [[wiki/concepts/misc-f0909b7-ci-build-git-coworker-ops.md]] and [[wiki/concepts/slangpy-build-and-infra-operations.md]].

For observed Vulkan values, a local-only workaround: guard the push with `extensionNames.count(...)`, rebuild only `render-test`, run with `VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.x86_64.json`:

```bash
slang-test -bindir build/Release/bin render-test <file> -vk -compute -output-using-type -shaderobj -o out.txt
```

Real readbacks, also with `-emit-spirv-via-glsl`; revert and rebuild afterwards, never commit. Neighbouring traps (slang#13446): `slangc -target host-callable -o x` fails with E00098 "cannot access as a blob" (use `-reflection-json` without `-o`); render-test's LLVM path uses `host-callable` (+ `emit-cpu-via-llvm`), whose reflection differs from `shader-sharedlib` ([lavapipe non_semantic_info](../learnings/1792028852820-observed-vulkan-runs-on-lavapipe-in-agent-containe.md)).

## Vulkan device creation: `VK_EXT_shader_atomic_float2` is gated on float16 atomics

`external/slang-rhi/src/vulkan/vk-device.cpp:832-840` enables `VK_EXT_shader_atomic_float2` (and `SPV_EXT_shader_atomic_float_min_max`) only when `shaderBufferFloat16Atomics` is reported. The L40S has `shaderBufferFloat32AtomicMinMax = true` but `shaderBufferFloat16Atomics = false`, so any `-vk` run executing `OpAtomicFMinEXT` loses the device (`api.vkQueueWaitIdle(m_queue) call failed`) on both `-emit-spirv-directly` and `-emit-spirv-via-glsl`; float atomic add is unaffected. Until slang-rhi gates per feature, test float32 min/max by compiling through glslang and direct SPIR-V. Found on shader-slang/slang#14026 (2026-10-29), not yet filed [float16-gated atomic_float2](../learnings/1793302322039-slang-rhi-enables-vk-ext-shader-atomic-float2-only.md).

## Metal encoders, barriers, fences and timestamps (rhi#962, rhi#964)

Apple says untracked resources need "barriers, fences, or events"; within a pass that means an intrapass barrier (fences sync only between passes), and a plain `computeCommandEncoder()` dispatches serially. slang-rhi Metal (main 30250fa): every encoder waits on and updates one queue `MTLFence` (from PR #713, which made all resources untracked for GPU pointers) — the only inter-encoder ordering. The core layer writes `SetComputeState` before every dispatch (`src/command-buffer.cpp:245-268`) with fresh binding data, so the `memoryBarrier` at `metal-command.cpp:881` runs before every dispatch after the first, not "on rebind" (the comment at :894-899 misleads). `clearTexture` reuses an open compute encoder without a barrier and `executeCallback` hands out the command buffer without ending the encoder, so encoder coalescing must fix both. Apple docs need the DocC JSON endpoint, on [[wiki/concepts/slang-backends-metal-atomics-fences-and-coherence.md]] ([DocC JSON; Metal barrier facts](../learnings/1793570718425-apple-metal-docs-are-readable-via-the-docc-json-en.md)).

Metal timestamps have been disabled since rhi#307, so `Feature::TimestampQuery` is never advertised and timestamp tests SKIP (WGPU likewise). On Apple silicon (M1–M4, macOS 26) `supportsCounterSampling` is true only for `AtStageBoundary`; blit/compute `sampleCountersInBuffer` errors. Use the pass descriptor's `sampleBufferAttachments` (start/endOfEncoderSampleIndex for compute/blit, start/endOfVertex and start/endOfFragment for render, ≤4 per pass). Dawn's `EncodeEmptyBlitEncoderForWriteTimestamp` (`CommandBufferMTL.mm`) encodes a blit pass with endOfEncoderSampleIndex = query index plus a 1-byte fill, since empty encoders store no samples (dawn:1473). Samples are GPU ticks; calibrate with `sampleTimestamps:gpuTimestamp:`. Zeros on macOS 26 when the GPU resolve commits before sampling completes (gfx-rs/wgpu#9414) are avoided by a CPU `resolveCounterRange` after completion. Triage memo: slang-triager `memory/issues/triage-slang-rhi-962.md` ([Metal stage-boundary timestamps](../learnings/1793565036279-metal-gpu-timestamps-apple-silicon-samples-only-at.md)).
