## TL;DR

- `record_decision` returns `"Decision recorded: …"` **before** the writer gate — the ack is emission-only. The writer-capability check runs host-side, out of band, and denies asymmetrically (some calls draw the deny a second later, some draw none). A missing denial carries no information. Say **"emitted to the ledger"**, never **"recorded."**
- When `APPROVAL_LEDGER_WRITERS` is unset the ledger is empty fleet-wide; the only fix is the operator setting that host env var (no restart needed). Do not read an empty `approval_decisions` table as "the approvers aren't deciding" — the rows are being dropped.
- A per-session ordinal ("this is the 2nd") is a LOWER BOUND that reads as a TOTAL — N sessions each count privately behind one capability defect. Write "≥N, own-session only" or grep the shared store for the union. Escalate the **rate** (dropped decisions/hour), not the cumulative count or the file count.
- Before reporting "X breaks Y", ask what Y would do if X were fixed. `record_human_verdict` is deliberately withdrawn (the host self-stamps human outcomes from the webhook); the join breaks because there is no *row*, not because the tool is gone. Discovery order is not causal order.
- When a durable-store write is denied, some weaker-durability copy is silently promoted to primary. Ask "what is now the only copy, and who can read it?" A file path in prose is a dead pointer to a peer — `send_file` the artifact, don't name its path.
- Do not `record_decision` until the decision *class* is FINAL. The ledger is append-only / first-write-wins; an early ABSTAIN skips the gate that would have caught a mis-classification AND burns the one slot for that commit.
- Before debating an infra mechanism, grep your OWN `work/`+`logs/` tree first — the verbatim host denial is usually already captured there. "You were wrong" and "your claim was false" are different findings.
- A silent log is not a clean run. Before reading absence-in-a-log as evidence, run a known-positive case through the same instrument; if it's also silent, the instrument is blind to that class.
- Never write a parse of an artifact that hasn't returned. "The run is in flight" is not a value; a citation to a file path is a claim the file exists — verify it. A real call chain proves reachability, not ordering — an order claim needs the caller's statement sequence.
- Harvest tools drop signal silently: `collect-reviews.sh` exit 20 hides CodeRabbit's **issue-comment** summary; `devin-fetch.sh` drops `Investigate`-severity flags as "none reported." Always read the raw page (`devin-page.txt`) and the CodeRabbit issue comment before trusting the synthesized doc.
- For a submodule bump, attribute hunks by **per-commit** file list (`gh api .../commits/<sha>`), never the aggregate `compare/.files`. Cite file:line from the pinned commit via the contents API, never from a local checkout on an unknown branch.
- A confirming probe cannot establish a limit — to find a ceiling you must probe above it and observe a failure. A measured FLOOR read as a CEILING is an invented bound. A row of zeros is both the most likely instrument failure and the one that feels most like a clean bill of health; plant a positive control in the same tree.
- WebFetch silently follows same-host 302s and reports only the final page. A route/redirect claim ("URL X serves page Y") needs a no-follow header fetch (`curl -sS -o /dev/null -D -`), not WebFetch.

## Emission is not persistence: the record_decision ack

The single most re-discovered infra fact: `record_decision`'s handler validates its args, emits a `system` message row, and returns `ok("Decision recorded: …")` **unconditionally** — there is no writer-capability check anywhere in the container; `APPROVAL_LEDGER_WRITERS` appears nowhere in `/app`. The gate is enforced by the host *after* consuming the emitted row, so the success string is emitted before and independently of the write it claims ([record_decision returns "Decision recorded" before the writer gate](../learnings/1786361652051-approver-infra-abstain-record-decision-returns-dec.md)). Denial is **asymmetric** — of two identical calls for the same commit, one drew a deny message a second later and one drew nothing ever — so a missing denial carries zero information, and a denial that names one call does not exonerate earlier calls: infer the environment-level fact ("no writers configured") and apply it to every call. Report **"emitted to the ledger (host-side persistence is not container-verifiable)"**, never "recorded."

Main's canonical union leaf ties this together: `approval_decisions` is empty fleet-wide, shadow-mode scoring has zero data, and the defect accrues ~2–3 dropped decisions per hour of approver activity ([approval-ledger denial — canonical union leaf](../learnings/1786385767660-approval-ledger-denial-canonical-union-leaf-read-t.md)). Two transferable rules crystallize there. **A per-session ordinal is a lower bound that reads as a total** — approvers reported "2nd" then "3rd+" and both were ~4× low, because N sessions each count privately behind one capability defect and no approver edge can see the union. And **discovery order is not causal order**: `record_human_verdict` is deliberately withdrawn (the host self-stamps the human outcome from the webhook, keyed by delivery id), so on a PR *with a row* the join happens without the approver — "the join is broken because the tool is gone" is the wrong causal chain; the join breaks because there is no row, and only the env fix addresses it. Before reporting "X breaks Y", ask what Y would do if X were fixed.

When the append is denied the only copy of the decision is a file on the deciding agent's container filesystem, which no peer can open — a report that *describes* the record does not *deliver* it ([a denied ledger append leaves the record only on your disk](../learnings/1786409670355-approver-infra-abstain-a-denied-ledger-append-leav.md)). The transferable shape: **a write that fails silently promotes some other copy to primary, and that copy usually has weaker durability** — so on any denied persist, `send_file` the decision record + `clauses.json` on the reporting thread, copy it outside the per-PR workspace, banner the file, and say "emitted, not recorded." Naming an inaccessible artifact is not disclosing it. And do not `record_decision` until the decision *class* is final: the append-only / first-write-wins ledger will lock in a wrong verdict — one approver recorded `ABSTAIN_POLICY` then OUTPUT_REVIEW established the correct call was BLOCK, but the slot was already burned ([don't record_decision until the class is FINAL](../learnings/1786482505015-approver-infra-don-t-record-decision-until-the-dec.md)). The ABSTAIN gate-relaxation is a license to skip DECISION/OUTPUT review of a hand-to-human, not a license to record before you're certain it *is* an abstain.

## Calibrate the instrument before reasoning from its silence

Two tiers once spent two full round-trips arguing whether an append succeeded, reasoning entirely from *absences* in their own containers — when the cheapest query, `grep -rn APPROVAL_LEDGER_WRITERS` over the approver's own `/workspace/agent` tree, returns the verbatim host denial captured by past sessions ([grep your own work tree; a silent log is not a clean run](../learnings/1786454516285-approver-infra-abstain-before-debating-an-infra-me.md)). Two lessons: *"you were wrong" and "your claim was false" are different findings* (a correct conclusion from invalid evidence still needs its real evidence located); and *a silent log is not a clean run* — before reading absence as evidence, run a known-positive case through the same instrument, and if the known-positive is also silent the instrument is blind to that class and your absence carries zero bits. The general form of that discipline: a **confirming probe cannot establish a limit**. One approver treated "24,400 chars" as a hard `Read` truncation bound for days and paid real cost against it, because its original probe only ever showed a canary *rendering* — that establishes a floor, never a ceiling; to find a ceiling you must probe above it and observe a failure ([a measured FLOOR enforced as a CEILING; inert detectors](../learnings/1786407780165-approver-challenger-miss-the-24-400-char-read-boun.md)). A row of zeros is simultaneously the output most likely to be instrument failure and the one that feels most like a clean bill of health — a grep sweep needs a planted positive in the *same tree*, and "verified two independent ways" is itself a claim to audit.

The same "verify your own tool" discipline extends to WebFetch, which silently follows same-host 302s and reports only the final page — so a claim that `/pull/N/changes` "is a valid direct/canonical route" was materially wrong (it 302-aliases to `/files`), caught only when codex fetched with headers ([WebFetch silently follows same-host 302s](../learnings/1786990448164-approver-challenger-webfetch-silently-follows-same.md)). Any route/redirect/canonical-path/404-vs-200 claim needs a no-follow header fetch (`curl -sS -o /dev/null -D -`) and a bogus-sibling control; WebFetch reads content but collapses the redirect chain. And never write a parse of an artifact that hasn't returned: one approver wrote a Devin `verdict: APPROVE, bugs:0` while the run was still in flight, citing a `devin-result.md` that never existed — "the run is in flight" is not a value, and a citation to a file path is a claim the file exists ([never parse an unreturned artifact; a call chain is not an order proof](../learnings/1786411189713-approver-critique-mustfix-never-write-a-parse-of-a.md)). The companion: a real call chain proves A can *reach* B, not that A happens *before* B — an order claim needs the caller's statement sequence, and you must name the event the invariant precedes (before first *teardown*, not vague "before first use").

## Harvest fidelity: the tools drop signal quietly

The synthesized review doc is only as good as the harvesters that build it, and two drop head-current signal silently. `collect-reviews.sh` returns exit **20** ("no harvestable bot review → Devin-only") on slang-rhi PRs that CodeRabbit *has* reviewed cleanly — because CodeRabbit posts its walkthrough as an **issue comment** (`issues/N/comments`, body starts `<!-- summarize by coderabbit.ai -->`), not a formal PR review, so it never becomes a candidate and the exit collapses to 20 while `commits/<sha>/status` still shows `CodeRabbit=success` ([collect-reviews.sh exit 20 hides CodeRabbit's issue-comment summary](../learnings/1787054813237-approver-infra-abstain-collect-reviews-sh-exit-20-.md)). Treat exit 20 as "no *formal* bot review", not "no signal": harvest the CodeRabbit issue comment yourself and confirm its base→head range equals the pinned head. Likewise `devin-fetch.sh` synthesizes `devin-flags.md` but drops `Investigate`-severity flags (keeping only Bugs+Informational) — on one PR the raw `devin-page.txt` said "2 Flags" with a real gap directly on the changed line, and the decision went WOULD_APPROVE off "none reported" ([devin-fetch.sh drops Investigate flags](../learnings/1787137975816-approver-infra-abstain-devin-fetch-sh-drops-invest.md)). Always read the raw page, grep the count line (`[0-9]+ (Bugs|Flags)`), and confirm `devin-flags.md`'s count == the raw page's before writing the doc.

Finally, attribution precision on submodule bumps: the GitHub `compare/<A>...<B>` `.files` array is **aggregated across the whole range** — it tells you what changed, not which commit changed each file. Narrating per-commit attributions from that aggregate plus commit messages is guessing; fetch the per-commit file list (`gh api repos/<owner>/<sub>/commits/<sha> --jq '[.files[].filename]'`) to bind hunks→commit, or describe the range in aggregate only ([attribute submodule-range hunks by per-commit file list](../learnings/1786634617136-approver-critique-mustfix-attribute-submodule-rang.md)). The same PR taught a companion cite-hygiene rule: always cite file:line from the pinned commit (contents API), never from a local `/workspace/agent/<repo>/` checkout that tracks whatever branch is checked out.
