## TL;DR

A cross-cutting discipline: a control (test, assertion, grep, self-check, classifier) that stays green no matter what the code does certifies nothing — it must be PROVEN to discriminate the thing it guards.

- **Arm-test your controls.** Deliberately reintroduce the regression a control guards in a `/tmp` throwaway and confirm it goes RED. Green on first run is also the state you'd see if the control were inert. For Slang bug fixes, a Debug pass does NOT verify the Release path (`SLANG_ASSERT`→`SLANG_ASSUME`/UB); use a four-leg control (fix passes, revert-drill confirms the bug, base binary crashes, restore). "Executable-code-unchanged ≠ fresh build" — prove binding with `nm | grep <new-symbol>`.
- **FileCheck traps:** `//TEST:SIMPLE(filecheck=...)` is silently IGNORED (`0/0`, exit 0; or `100% passed (1/3), 3 ignored`) when `libslang-llvm.so` is missing from `build/<cfg>/lib/`, which is the default for a minimal-target worktree build. That is a vacuous null, not a pass: confirm `llvm` is in Supported backends, or copy the lib in from another build and re-run. A `CHECK-NOT` only discriminates relative to its bounding positive `CHECK`s — re-run the must-fail control after ANY layout change. `CHECK-NOT: for(` is whitespace-sensitive; prefer `for{{[[:space:]]*}}(`.
- **Test-input gotchas:** Slang `L` literals are 32-bit (`7L << 32` = 0); use `LL` to build a nonzero high word or the split/reassembly test passes vacuously.
- **Baselines & inventories are claims:** re-grep a quoted code inventory against current source before republishing; a "current-master" grep is the wrong baseline for a cleanup that follows an open PR; state provenance precisely (PR-head vs squash-merge commit). A whole-file grep for a status token matches inner streaming content — parse the terminal `type==result` event.
- **Blockers are often surmountable:** a "disk-full, can't build" is usually an incremental build on a cached-deps checkout; a docs-only prose edit must skip the auto-formatter (it churns unrelated lines on non-conformant `.md`).
- **Crashpad** captures faults/aborts, not graceful nonzero exits — a null minidump is informative, not a failure.
- **okf-synthesis:** most reported backlog is a frontmatter-convention mismatch, not rot; run a proposed classifier change yourself (a reclass pushes files into another class); frontmatter regexes must be line-anchored and must not cross newlines.

## Make every control actually discriminate

The core principle: a control that stays green regardless of the code is a "dark control" — it certifies the ABSENCE of the mechanism it mimics, and the cheap decisive proof is to deliberately reintroduce the exact regression it guards in a `/tmp` throwaway copy and confirm it goes RED, then delete the copy ([Prove a control arms by breaking the logic in a throwaway copy](../learnings/1787226695062-prove-a-control-arms-by-breaking-the-logic-in-a-th.md)). This applies with force to Slang fixes whose pre-fix failure is `SLANG_ASSERT` in Debug but SIGSEGV in Release: a Debug-only run does NOT verify the shipping config, so the decisive verification is a four-leg control — build at head with `SLANG_ASSERT=release-assert-only` and observe the ACTUAL printed values, revert only the fixed file and grep-confirm the fix is gone, run the input on the base binary and confirm SIGSEGV (which also defeats the stale-binary false pass), then restore — overlaying the single changed `.cpp` into the WARM shared Release build is far cheaper than a cold worktree ([Release crash-reproduction is a distinct control from a Debug pass](../learnings/1787500349746-release-crash-reproduction-is-a-distinct-control-f.md)). And a Monitor/grep control whose timing is impossible for the real event is itself the tell: greping a `stream.jsonl` for `"is_error":true` fired within seconds (the real crash took 120s) because a raw whole-file grep matches an `is_error` field in some inner streaming payload, NOT the run's terminal `{"type":"result",...}` event — parse the LAST `type==result` event, or key on a terminal-artifact floor ([A whole-file grep for a status token matches inner streaming content](../learnings/1787323802416-a-whole-file-grep-for-a-status-token-matches-inner.md)).

## FileCheck and build-environment traps

`slang-test tests/foo.slang` on a `//TEST:SIMPLE(filecheck=CHECK):` test can print `0% of tests passed (0/0), N tests ignored` and exit 0. That is a vacuous null, not a pass. FileCheck (`IFileCheck`) is loaded in-process from `build/<cfg>/lib/libslang-llvm.so`; when the lib is absent `_fileCheckTest` returns `TestResult::Ignored` ("Ignore if FileCheck is not available", `slang-test-main.cpp` ~:816-819) and `slang-test -v` prints `FileCheck is not available`. Three routes lead there, all common on verify worktrees: a build configured without LLVM (missing git tags in a shallow/worktree clone, so no prebuilt slang-llvm is selected), an explicit `-DSLANG_SLANG_LLVM_FLAVOR=DISABLE` or failed fetch, and a minimal `--target slangc slang-test test-server` build, which never builds or fetches the lib. The trap is the summary line. `100% of tests passed (1/3), 3 ignored` reads green while the CUDA/PTX or `-target wgsl` lanes never ran, so a reviewer concludes "tests pass" from skipped rows. Check the environment before reading the result: `Supported backends` in the slang-test output must list `llvm`, and a shipping FileCheck test from the tree (e.g. `tests/cuda/sampler-comparison-state-unused.slang`) must actually pass. The fix is to copy a matching `libslang-llvm.so` from another build into `build/<cfg>/lib/` (or build the `slang-llvm` target) and re-run; on PR 13562 that turned 1 pass + 3 ignored into 3 pass + 1 ignored. If no lib is available, verify the CHECK patterns by hand against the directive's `slangc` emit, report that explicitly, and leave the FileCheck lanes to CI ([FileCheck SIMPLE tests are silently ignored locally when slang-llvm is not built](../learnings/1787276807546-filecheck-simple-tests-are-silently-ignored-locall.md), [SIMPLE(filecheck=) lanes ignored in a fresh worktree build](../learnings/1791609372518-slang-test-silently-ignores-simple-filecheck-lanes.md), [wgsl SIMPLE rows ignored without libslang-llvm.so](../learnings/1791679248387-slang-verify-worktree-simple-wgsl-tests-silently-i.md), [filecheck tests ignored under `SLANG_LLVM_FLAVOR=DISABLE`](../learnings/1791758791152-slang-test-silently-ignores-filecheck-tests-withou.md)).

The same worktree atoms carry setup traps. A new worktree's submodules need `git -c protocol.file.allow=always submodule update --init --recursive`, because file-transport clones are blocked by default and configure then fails on a missing `external/miniz`. `submodule update --init --reference /workspace/agent/slang` fails with "reference repository is shallow"; copying `external/` from an already-populated verify worktree (`cp -a --no-clobber wt-old/external/. wt-new/external/`) works, after diffing submodule SHAs with `git ls-tree -r HEAD | awk '$2=="commit"'`. Skill runner scripts under `~/.claude/skills/*/scripts` may lack the exec bit, so invoke them as `bash <script>` (direct execution exits 126). For a revert drill, master's own `slang-test` run from another worktree's root uses its own bin dir as `-bindir`, so it runs a PR's test files against the master compiler. For a GPU-free WGSL emit regression sweep, `npm install naga-wasm@30.2.0` and run parseWgsl+validate over old and new emits of every compute test with `xargs -P 48`; on #13569 that found 0 regressions across 1654 emits in about 2 minutes. clang-format 17 installs in about 10 s with `python3 -m venv /tmp/x && /tmp/x/bin/pip install clang-format==17.0.6` (the install recipe and its caveats are on [the formatting page](slang-tooling-f0909b0-formatting.md)).

A `CHECK-NOT` only means something relative to its bounding positive `CHECK`s: restructuring to a leading `CHECK-NOT` + `CHECK-DAG` changed the scan region so the leaked token escaped and the test passed on the BUGGY binary too — after ANY layout change re-run the must-fail control against a known-buggy binary; "passes on the fixed build" is necessary but never sufficient ([FileCheck CHECK-NOT layout: re-run the must-fail control after restructuring](../learnings/1787368063094-filecheck-check-not-layout-re-run-the-must-fail-co.md)). Whitespace matters too: `CHECK-NOT: for(` does NOT match `for (` (with space, as Slang's CPU emitter formats grid loops), so prefer the whitespace-insensitive `for{{[[:space:]]*}}(` idiom and verify it stays non-vacuous ([Reducing a PR to test-only: rebase mechanic + FileCheck whitespace trap](../learnings/1787552911744-reducing-a-pr-to-test-only-after-the-source-fix-me.md)). This last atom also carries a rebase mechanic: `git reset --soft origin/master` is the WRONG tool to rebase an old-based branch (it stages the entire old→new master delta) — back up the file(s) outside the tree, `git reset --hard origin/master`, `git submodule update` any moved pointer, then restore and commit. A pure test-input gotcha in the same family: Slang treats an `L`-suffixed literal as 32-bit, so `(7L << 32)` overflows to 0 and an AnyValue 64-bit split/reassembly test passes vacuously — use `LL` to build a nonzero high word ([Slang int64 shift literals need LL suffix, not L](../learnings/1787337737957-slang-int64-shift-literals-need-ll-suffix-not-l-l-.md)).

## Baselines, inventories, and surmountable blockers

An inventory (file:line lists, "N producers", "doc is stale") is a claim carrying the same staleness risk as memory even when it's your own — re-grep it against current master before republishing a tracking issue, since a quoted PublicDecoration inventory was materially wrong (missed a second producer, "refuted" correct prose, ±1–46 line drift) ([Re-verify a quoted code inventory against source before republishing it](../learnings/1787264346872-re-verify-a-quoted-code-inventory-against-source-b.md)). For a cleanup that follows an open PR, a raw "current-master" grep is the wrong baseline: verify the footprint against the state the cleanup STARTS from (`gh pr diff <N>` to see what the PR itself deletes), watch the decoration-spelling trap (`[export("...")]` = ExportDecoration ≠ `[hlslExport]`), and state provenance precisely — a built worktree at a PR head is NOT the squash-merge commit ([A "current-master" grep is the wrong baseline for a cleanup that follows an open PR](../learnings/1787269228520-a-current-master-grep-is-the-wrong-baseline-for-a-.md)). A "can't build — disk full" blocker is often surmountable: the obstacle is a *from-scratch* build in a *fresh* worktree, but a shared checkout with `external/` already fetched and a populated `build/` needs only an incremental rebuild that fits in a few GB — and prove-of-binding (`nm -C ... | grep <new-symbol>`) plus a non-vacuity control (run the compiler on a NEGATIVE input) defeats the stale-binary false pass; give a concurrent read-only Reviewer A its own worktree so a mid-read edit doesn't desync its line citations ([Disk-full "can't build" is often surmountable via incremental build on a cached-deps checkout](../learnings/1787318166939-disk-full-can-t-build-is-often-surmountable-via-in.md)). For a docs-only prose edit, NEVER run `./extras/formatting.sh --md`: the pristine `docs/*.md` are not prettier-conformant even under the CI-pinned version (CI skips draft PRs), so the formatter reflows ~40 unrelated lines — instead restore pristine (`git checkout HEAD~1 -- docs/file.md`), re-apply only your prose paragraphs, and verify your specific lines are clean without reformatting the whole file ([Docs-only edit: never run the auto-formatter on docs/*.md](../learnings/1787236112272-docs-only-edit-never-run-the-auto-formatter-on-doc.md)). And Crashpad only produces a minidump on a hardware fault or `abort()` — it does NOT capture a graceful nonzero exit, so a null minidump on a "nonzero exit after green summary" flake is informative (the teardown fault is a clean return, needing exit-code/stdout analysis), not a sign the arming failed ([Crashpad in sgl_tests captures faults/aborts, not graceful nonzero exits](../learnings/1787174413870-crashpad-in-sgl-tests-captures-faults-aborts-not-g.md)).

## okf-synthesis memory-scanner tooling

Running `/okf-synthesis` on a slang-fixer-style OKF tree, most reported backlog is NOT foldable rot: NO-FRONTMATTER is over-counted because the scanner only recognizes a top-level `type:` while the NanoClaw auto-memory writer emits nested `metadata:\n  type:` (263 of ~503 files), live operational aggregates (`active-holds.md`) legitimately ESCALATE, per-issue `fix-<n>.md` logs are one concept each, and the one clean win is deleting stale generated index monoliths — verify before fragmenting anything ([okf-synthesis backlog is inflated by frontmatter-convention mismatch, not rot](../learnings/1787373318278-okf-synthesis-backlog-is-inflated-by-frontmatter-c.md)). The fixes shipped three heuristic changes — anchor `_has_type` to `^\s*type:\s*\S` (recognizing the nested dialect, with a `node_type:`-only negative test), gate the DOSSIER heuristics on `not _has_type`, and add an `okf_synth: exempt` flag for genuinely-live aggregates — but SKILL.md is the source of truth (the container rewrites the tool each run) and there is NO repo source-of-truth, so a local edit doesn't propagate ([okf-synthesis: nested metadata.type recognition + self-declared exempt flag](../learnings/1787375075036-okf-synthesis-nested-metadata-type-recognition-sel.md)). Two follow-on discipline lessons: a codex critique found the round-1 regexes cross newlines (`\s` in `re.M` matches `\n`, so `type:\n<nextkey>` reads as typed and a block-scalar body can silence an arbitrarily large file) — for "value on the SAME line as the key" always use `[ \t]`, never `\s`, and walk block-scalars as YAML keys ([okf-synthesis round-2: frontmatter regexes must not cross newlines](../learnings/1787376438827-okf-synthesis-round-2-frontmatter-regexes-must-not.md)). And, from the authorizing side: before signing off on a heuristic/classifier change, RUN the proposed logic yourself against real data — a change that clears one offender class frequently pushes the same files into another (here DOSSIER→OVERSIZE, ESCALATE unchanged), so the fix's headline outcome can be false even when its stated mechanism is true; reproduce the baseline first, simulate the proposed classifier end-to-end, dump the full top-N offender list, and distrust aggregate "phantom→real" headlines ([Run a proposed classifier change yourself — a reclassification is not an exemption](../learnings/1787374271043-run-a-proposed-classifier-change-yourself-a-reclas.md)). On a group whose `memory/` was bulk-migrated from native memory the NO-FRONTMATTER pile is almost entirely this same artifact — the migration emits a *nested* `metadata:\n  node_type: memory\n  type: project` block that `_has_type()`'s top-level `^type:` match can't see (~150 of ~160 offenders in one slang-reviewer store) — so rather than hand-edit the tool-bounded 4-offenders/run forever (~40 daily runs to drain the flat pile), propose an owner-approved one-time mechanical promotion of `metadata.type` → a top-level `type:` line; but stamping that line on a file already >16000B flips it DOSSIER→OVERSIZE, so trim or split it under the budget in the same edit rather than just adding frontmatter, and consolidate any duplicate migration hook-indexes (`MEMORY.md`/`MEMORY-2.md`) into the size-exempt folder `index.md` for one source of truth ([NO-FRONTMATTER pile is often a nested metadata.type migration artifact](../learnings/1790061935849-okf-no-frontmatter-pile-is-often-a-nested-metadata.md)). A separate scanner false-positive class: the `MDLINK`/`WIKILINK` regexes don't strip fenced or inline code before extracting links, so a file that *documents* link syntax — illustrative `](file.md)` written inside inline code spans as examples — has those examples counted as *uses* and reported DANGLING-LINK; do NOT mangle a correct file to silence a broken instrument, treat it as a small fixed backlog floor, and act only if it's the LAST thing keeping the gate awake (backlog otherwise < GATE_MIN_BACKLOG 2000), at which point the fix belongs in the SKILL.md scanner (strip code spans first), escalated to the owner, not in the memory files ([DANGLING-LINK false-positives on code-span link syntax](../learnings/1790224601208-okf-synth-py-dangling-link-regex-false-positives-o.md)).
