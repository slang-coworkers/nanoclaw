# Slang Compiler: IR Type-Legalization, Empty Structs, Half, and Enum-Cast Lowering

IR-level type legalization and lowering-gate mechanics: empty structs, the legalization quadratic and attr contiguity, specialization worklist discipline (address-space specialization is on [its own page](slang-compiler-ir-address-space-specialization.md)), CPU `half` rounding, the enum-cast gate, pass-order hazards, and split "special" types.

## TL;DR
- **Confine the empty-struct fix to `IREmptyTypeLegalizationContext` / consumer-side `isSimpleType`.** A global `removeEmptyStructFields` pass is CI-rejected (it strips the zero-size empties that `Conditional<T,false>`/`Optional` need in dynamic-dispatch payloads); producer-side `addPublicDecoration` removal is the wrong layer (plain `public` functions then emit `static` and `findFuncByName` returns null). Make `isSimpleType` return false for a zero-field struct regardless of linkage decoration.
- **When a change deletes a decoration at its producer, inventory EVERY consumer** — a "minimal" producer deletion can carry compiler-wide blast radius.
- **#7612 is the canonical original of the empty-CUDA-struct dup pair; #8125 is the slangpy instance** — route #7612 as a DEDUP, never a fresh fixer dispatch that double-implements the change.
- **Empty-struct legalization erases a whole parameter**, taking any decoration read off it at emit (GS input topology, #13195); record such decorations on the entry-point `IRFunc` too.
- **`IRTypeLegalizationPass` is O(N^2) on straight-line code** via a per-round full-module scratch-bit reset inside the round loop and re-queue gated on worklist-presence rather than on an actual operand-value change. The "changed" predicate MUST treat inst replacement and struct→tuple splitting as a change.
- **`findAttrs<T>()` returns only the FIRST CONTIGUOUS RUN of `T` operands.** A new `IRAttr` subtype emitted inside the per-kind size loop truncates `getSizeAttrs()` (→ `slotCount=0`, miscompiled existential binding) — emit new attr types in a SEPARATE pass after all size attrs.
- **For CPU/C++ `half`, arithmetic (+ - * /) via `float` is provably benign for normalized results; the hazard is CONVERSIONS and LITERALS.** The literal path rounds `double`→half directly (`_truncateDouble`); the runtime prelude `struct half` (float-intermediate) is the genuine double-rounding site.
- **Any pass gated on a TYPE opcode is fragile: const-folding can delete the type while leaving an op that still needs the pass.** A stranded `CastEnumToInt` reached emit as E99999 because `calcRequiredLoweringPassSet` flagged only `kIROp_EnumType`. Gate `lowerEnumType` on the cast opcodes too; the `Constexpr*` enum casts stay excluded because they are produced only in IntVal contexts.
- **In `slang-ir-specialize.cpp`, a mutation-site requeue is `enqueue(x)` then `addUsersToWorkList(x)`**, and the "dead" re-drain loop stays — it keeps output byte-identical.
- **Address-space specialization (`slang-ir-specialize-address-space.cpp`: clone keys, cycle detection, the `newWorkList` hang, export roots) lives on [IR address-space specialization](slang-compiler-ir-address-space-specialization.md).**
- **Before reordering a lowering pass, list every pass between the old and new positions and check what each assumes about the type's shape.** `legalizeMatrixTypes` running before buffer lowering is why `column_major` int/bool matrices lose their buffer layout (#13446); moving it later crashes passes that expect arrays.
- **Matrix legalization must accept a scalar operand:** Metal/WGSL splat `op(matrix, scalar)` before `legalizeMatrixTypes`, SPIR-V/GLSL do not, so "works on Metal/WGSL, crashes on SPIR-V/GLSL" points at `slang-ir-legalize-matrix-types.cpp` (#14018).
- **`bit_cast` between structs holding resources ICEs because resource legalization splits the struct before `lowerBitCast` runs.** Fix it in a structural pre-pass ahead of the `shouldLegalizeExistentialAndResourceTypes` block, gated on that same flag: CUDA/C++/LLVM handles are real bytes and already compile.
- **In `lowerBufferElementTypeToStorageType`, a replacement inst takes `user->getDataType()`, never a builder-deduced type.** Values are retyped to storage types up front while field/element/func types stay logical until the end, so a deduced type swaps storage for logical; an identity `CastStorageToLogical` is always that bug.
- **Making a new type "special" for type legalization (e.g. logical pointers) exposes consumers that assumed only resources split.** Debug vars must keep the legal type's pair/tuple structure or be dropped whole; split `IRGlobalVar`s lose their initializer unless the unfiltered `moveGlobalVarInitializationToEntryPoints` runs before legalization (a filtered move reorders initializers).

See also [Slang IR: phi block parameters and where inlined global values land](slang-compiler-ir-phis-and-global-value-placement.md) for the all-undefined opaque phi behind E56004 after `legalizeResourceTypes`, and where `GlobalInstInlining` places sunk module-scope tables.

## Empty-Struct Legalization: Fix It in the Legalization Layer (#8125 / #7612)

An empty `struct` used as a **member** of a public/layout-decorated struct (e.g. a `ParameterBlock<CallData>` element) crashes on CUDA/CPU. `IREmptyTypeLegalizationContext::isSimpleType` deliberately RETAINS an empty type carrying `LayoutDecoration`/`PublicDecoration`/`ExternCpp`/`HLSLExport`. The C-like emitter (`slang-emit-c-like.cpp`, which skips only `IRVoidType`) emits it as a 1-byte C++ member while type-layout gives it size 0, so slangpy binds per reflection (offset 0) and the device reads per emit (offset 8) → `CUDA_ERROR_ILLEGAL_ADDRESS`. The fix home is Slang codegen, not slangpy.

**Provenance.** #7612 ("Properly handle empty CUDA structs") is the canonical original; @bmillsNV tagged #8125 (the slangpy-surfaced instance) as its dup. Route #7612 as a DEDUP (`Fixes #7612` on the active PR, or close at merge), never as a fresh fixer dispatch ([slang#7612 is the canonical original of the empty-CUDA-struct dup pair (#8125 is the slangpy instance)](../learnings/1785507093198-slang-7612-is-the-canonical-original-of-the-empty-.md)).

**Rejected: a global field-removal pass.** PR #11657 (`removeEmptyStructFields` on the C-like emit path) was CI-rejected and closed: global removal also strips the zero-size empties that `Conditional<T,false>`/`Optional` rely on in dynamic-dispatch AnyValue/existential payloads (`layout-conditional-field.slang.4 (cpu)` aborts `non-simple operand(s)!`). jkwak's steer: fix it inside `IREmptyTypeLegalizationContext` without touching interface empties; `layout-conditional-field.slang` must stay green ([slang#8125 empty-struct fix — global field-removal pass is CI-rejected, fix belongs in empty-type legalization](../learnings/1783473465864-slang-8125-empty-struct-fix-global-field-removal-p.md)).

**Rejected: producer-side decoration removal.** jkwak's dictated draft PR #12304 deleted the `addPublicDecoration` block in `addLinkageDecoration` (`slang-lower-to-ir.cpp`) so a `public` empty struct is dropped like a non-`public` one ([#8125 empty-struct fix — decoration-removal, not the rejected global pass](../learnings/1785467126768-8125-empty-struct-fix-decoration-removal-not-the-r.md)). Review returned REQUEST_CHANGES (wrong layer): it erases `IRPublicDecoration` for EVERY plain-`public` decl, and three CPU/CUDA emit consumers (`isPublicOrExportedFunc`, `_isExported`, `_getExportStyle`) key on `PublicDecoration || HLSLExportDecoration`, not plain `ExportDecoration`, so a plain `public` function emits `static` and `ISlangSharedLibrary::findFuncByName` returns null. It also leaves `export`/`[DllExport]`/`__extern_cpp` empties leaking. The converged fix is consumer-side: `isSimpleType` returns false for a zero-field struct regardless of linkage decoration, which covers every spelling with no visibility regression ([PR #12304 empty-struct public-decoration removal review — REQUEST_CHANGES (wrong layer)](../learnings/1785468944911-pr-12304-empty-struct-public-decoration-removal-re.md)). Rule: when a change deletes a decoration at its producer, inventory ALL consumers.

**Empty-struct legalization erases a whole PARAMETER (#13195).** A geometry shader with `struct Input {}` used as `point Input v[1]` emitted `OpExecutionMode … Triangles` on SPIR-V+GLSL. Topology is lowered onto the input `IRParam` as `IRGeometryInputPrimitiveTypeDecoration`; the empty struct legalizes to `LegalType::none`, so `legalizeResourceTypes`/`legalizeParam` erases the param before `legalizeEntryPointParameterForGLSL` can lift the decoration to the func, and a post-loop default stamps `Triangles` (silent miscompile). `shouldLegalizeExistentialAndResourceTypes` is off only for CPP/C/CUDA, so the param is erased for HLSL too, and keeping the param copy does not rescue HLSL's empty-struct case (a separate limitation). Topology has 3 consumers / 2 homes — SPIR-V and GLSL read it off the FUNC, HLSL off the PARAM (`slang-emit-hlsl.cpp`, as a param qualifier) — so a blind move regresses HLSL. The fix records the decoration on the entry-point `IRFunc` at lowering (as `[maxvertexcount]`/`[instance]` do), keeps the param copy, and makes the glsl-legalize lift idempotent (assert op-consistency instead of `SLANG_UNEXPECTED`, as for `IRStreamOutputTypeDecoration`) ([geometry input primitive topology has 3 consumers / 2 homes; empty input struct erases the param before glsl-legalize lifts it](../learnings/1789985294662-geometry-input-primitive-topology-has-3-consumers-.md), [empty input struct erases the whole GS input param on ALL non-CPP targets, not just SPIR-V/GLSL](../learnings/1789987486527-empty-input-struct-erases-the-whole-gs-input-param.md)).

## IR Type-Legalization Quadratic (#12040) and `IRTypeLayout` Attr Contiguity

`IRTypeLegalizationPass` (`slang-ir-legalize-types.cpp`) is O(N^2) on straight-line functions through two compounding mechanisms. The per-round `resetScratchDataBit(module->getModuleInst(), ...)` sits INSIDE the round loop and walks the whole module each round; and re-queueing is gated only on worklist presence, never on whether an operand's legalized value changed, with no already-processed early-out, so on a dependence chain the ready frontier advances ~O(1) per round (O(N) rounds × O(N)). One fix in `legalizeTypes`→`processModule` covers all three lowering variants: re-queue only on a real operand-value change and drop the per-round full-module reset. The load-bearing correctness point is that the "changed" predicate MUST count inst replacement and struct→tuple splitting ([slang#12040 IR type-legalization O(N^2) root cause](../learnings/1783674869932-slang-12040-ir-type-legalization-o-n-root-cause-is.md)).

`findAttrs<T>()` (`slang-ir.h`) skips to the first operand of type `T` and STOPS at the first non-`T` operand, returning only the first contiguous run — a documented invariant. PR #12306 emitted the new `IRTypeAlignmentAttr` inside the per-kind size loop, giving `size(Uniform), TypeAlignment, size(Existential…)`; `getSizeAttrs()` stopped at the alignment attr, dropped the existential sizes, and `bind-existentials.cpp` got `slotCount=0`, miscompiling interface slot binding. Fix: emit the new attr type in a separate loop after all size attrs. Verify by dumping `structTypeLayout(...)` operands from the PR-head binary with `-dump-ir` ([Slang IRTypeLayout attr contiguity — new attr types interleaved into a mixed operand run break findAttrs](../learnings/1785536484666-slang-irtypelayout-attr-contiguity-new-attr-types-.md)).

## Specialization Worklist Discipline (`slang-ir-specialize.cpp`, #12604/#12608)

The same worklist rule recurs in `SpecializationContext`. `expandUseClosure(seed, forceSeed)` has two modes over `workListSet` (queued) and a per-drain `expanded` memo. The **seeding** walk descends into a user only if it is newly added to `expanded`; the **forced** (mutation) walk descends only if the user is **newly queued** (`workListSet.add` returns true) and does not consult `expanded` to stop. So a plain `addToWorkList(x)` at a mutation site queues x's users, and a following `addUsersToWorkList(x)` finds them queued and stops, defeating transitive re-notification. The idiom is `enqueue(x)` (seed only, no walk) then `addUsersToWorkList(x)`, at `maybeSpecializeFoldableInst` (gated on an actual fold, `instChanged`) and `maybeSpecializePackBranch`. Do NOT delete the `specializeChildInsts` re-drain loop as dead (it never fired across 4087 tests): the iterative work-stack changed enqueue order, single-drain completeness is order-sensitive, and the loop keeps output byte-identical to master ([expanded-memo requires the re-drain loop; mutation requeues must enqueue-then-force](../learnings/1789220236579-slang-specialize-cpp-expanded-memo-requires-the-re.md), [the forced walk stops on workListSet, not the `expanded` memo](../learnings/1789224857022-slang-specialization-work-list-forced-mutation-wal.md)).

## Half Double-Rounding: Conversions Are the Hazard, Not Arithmetic (#12042)

For CPU/C++ `half`, + - * / via `float` is provably benign for normalized results (Figueroa's 2q+2 bound: q=11 needs exactly float's 24 bits), so don't over-scope a fix into arithmetic. The front-end literal path rounds `double` directly to half via `_truncateDouble` (round-to-even, `slang-lexer.cpp`), not through `float`; the real float-intermediate double rounding is the runtime prelude `struct half` (only `explicit half(float)`, no `half(double)`). `struct half` is only the fallback behind the native-fp16 path (`FLT16_MIN`/`__STDCPP_FLOAT16_T__`); a `std::float16_t` route risks cross-host non-determinism unless the fallback is bit-identical ([slang#12042 half double-rounding -- arithmetic benign, conversions are the hazard](../learnings/1783677064766-slang-12042-half-double-rounding-arithmetic-benign.md)).

## Enum-Cast Lowering Gate: Gate on Ops, Not Just the Type (#12048/#12050)

`enum : uint -> int` casts abort at emit with E99999 on all targets because `calcRequiredLoweringPassSet` (`slang-emit.cpp`) sets `enumType=true` only for `kIROp_EnumType`. An enum-typed local holding a constant gets const-folded away with the last `IREnumType` reference, leaving a `CastEnumToInt` on tag-typed operands and nothing to trigger `lowerEnumType` ([slang enum->int cast E99999: lowerEnumType gated only on EnumType, not cast ops](../learnings/1783700480198-slang-enum-int-cast-e99999-lowerenumtype-gated-onl.md)). The fix adds the enum-cast opcodes to the gate. Gating on {EnumType + 3 casts} is complete because a live enum-typed value keeps the hoistable `IREnumType` alive as a module child. The `Constexpr*` casts are excluded because they are produced only in IntVal contexts (`emitConstexprCast` from `visitTypeCastIntVal`) and `lowerEnumType` has no case for them; the correct argument is "IntVal-context-only production", not "SCCP folds them" ([enum-cast lowering gate -- completeness reasoning](../learnings/1783706489119-slang-enum-cast-lowering-gate-calcrequiredlowering.md)).

## Static-Const POD-Struct Arrays as Global Constants (#13107/#13115)

PR #13115 extends the #12688/#11628 static-const-array-as-global-constant family to POD structs in `slang-ir-legalize-global-values.cpp`: `isSimpleConstantType` recurses through struct fields (resource/pointer fields → false → conservative inline), and a pre-pass `legalizeConstantConstructorCallsForGlobalScope` folds module-scope synthesized `$init` calls to `IRMakeStruct` before `inlineGlobalConstantsForLegalization`, (unfoldable ctors still inline). Three reviewers found no correctness bug; recurring findings were renaming the misnamed `tryReplaceSynthesizedConstructorCallWithMakeStruct` → `tryBuildMakeStructForSynthesizedConstructorCall`, and whether symbolically walking the `$init` body at module scope is the right layer ([Slang #13107/#13115 static-const POD-struct-array global-constant fold: 3-reviewer consensus + recurring findings](../learnings/1789525381949-slang-13107-13115-static-const-pod-struct-array-gl.md)).

## Split ("Special") Types: Debug Vars and Initialized Globals (#13305)

Type legalization splits a value of a "special" type into a pair/tuple `LegalVal`. Resource-bearing types were long the only special types, and two consumers in `slang-ir-legalize-types.cpp` quietly depend on that; making logical pointers special on SPIR-V exposed both.

**Debug vars.** `legalizeDebugVar`/`legalizeDebugValue` "discarded the special part", so a split debug var came back simple and `legalizeGetElementPtr`/`legalizeFieldAddress` asserted `flavor == Flavor::simple`. It was latent because resource structs are not debuggable (`isDebuggableType`); pointers are. The fix emits the debug var with its legal type's pair/tuple structure when every leaf is debuggable, and drops it whole otherwise. A partial drop is impossible (`void` placeholder fields are non-debuggable; `LegalVal::pair` collapses when one side is none). Limits: legalization cannot split memory it does not own (SB/CB elements, groupshared, physical-pointer pointees), so a new special criterion needs a pre-legalization validator; and arrays of special leaves stay array values, resources included (the #9062 class) ([type legalization: debug vars assume no special type reaches them; logical ptrs as special break it](../learnings/1790645510789-slang-type-legalization-debug-vars-assume-no-speci.md)).

**Initialized globals.** `legalizeGlobalVar`'s split path uses `declareVars`, which creates body-less globals and discards the original, so an initializer is silently lost. Resource statics never hit this (front end rejects them, E30076). The working fix runs the existing unfiltered `moveGlobalVarInitializationToEntryPoints(module, target)` before `legalizeResourceTypes`, only when such an initialized global exists; SPIR-V/GLSL run it right after legalization anyway, so only timing changes. Traps: a filtered move REORDERS initializers (later stores go before `firstOrdinaryInst`, now the early store, so `static float b = t.tag;` would run before `t`); `SLANG_ASSERT(!globalVar->getFirstBlock())` is wrong because empty-type legalization splits initialized empty-struct statics (`tests/bugs/generic-initializer-inlining.slang`, cpu); and the move skips `IRActualGlobalRate` (`__global`) vars, so those holding a special type are rejected instead. (`tests/**/*.glsl` is gitignored: write GLSL-input tests as `.slang` with `#version 450` and `-Wno-120`) ([type legalization: split globals lose initializers; move them early without reordering](../learnings/1790660162174-slang-type-legalization-split-globals-lose-initial.md)). The same "initializer block has no parent function" shape trips coverage-marker collection; see [[wiki/concepts/slang-a-compiler-internals.md]].

## Matrix Legalization Pass Order: Int/Bool Matrices Lose Their Buffer Layout (#13446)

On SPIR-V, GLSL, WGSL and Metal, `legalizeMatrixTypes` (`linkAndOptimizeIR` in `slang-emit.cpp`) rewrites int/uint/bool `matrix<T,R,C>` into `vector<T,C>[R]` BEFORE `lowerBufferElementTypeToStorageType`. Buffer lowering already stores column-major matrices (`_MatrixStorage_*_ColMajor` = `vector<T,R>[C]` with transposing pack/unpack) but never sees an int `IRMatrixType`, while reflection honours the layout, so a `column_major` int matrix in a buffer silently gets the wrong offset or element order (square `int3x3`: matching offsets, transposed elements, so offset-only checks miss it). LLVM already runs buffer lowering first. A prototype moving `legalizeMatrixTypes` after buffer lowering, with the Khronos `shouldLowerMatrixType` wrapping non-float matrices on direct SPIR-V, matched reflection; an extra LLVM-style early buffer-lowering run broke 7 tests ([int/bool matrix buffer layout lost by pass order](../learnings/1791310149747-int-bool-matrix-buffer-layout-lost-by-pass-order.md)).

Passes between the two positions assume the array shape: `legalizeIRForMetal`/`legalizeIRForWGSL` call `legalizeScalarOperandsToMatchComposite` (`slang-ir-legalize-binary-operator.cpp`), which for Lsh/Rsh with a matrix operand calls `as<IRVectorType>(matrix)->getElementCount()` on null (likely the SIGSEGV in `tests/metal/matrix-integer-lowering.slang`); `validateVectorsAndMatrices` (`slang-ir-validate.cpp`) would reject int matrices with a dimension of 1; and `shouldLowerMatrixType`'s override is direct-SPIR-V-only while GLSL's Default policy skips default-layout matrices under the Natural rule, so a non-float wrap must precede that gate. bool→int storage inside `_MatrixStorage` also remains ([moving legalizeMatrixTypes later exposes passes that assume arrays](../learnings/1791313692068-moving-legalizematrixtypes-later-exposes-passes-th.md)).

**Matrix-vs-scalar ops reach `legalizeMatrixTypes` raw on SPIR-V/GLSL, already splatted on Metal/WGSL (#14018).** The core module emits `cmp(matrix, scalar)` / `op(matrix, scalar)` as a direct `__intrinsic_op` with the scalar left unsplatted (`core.meta.slang` ~3229-3283). On Metal and WGSL, `legalizeIRForMetal`/`legalizeIRForWGSL` call `legalizeBinaryOp` → `legalizeScalarOperandsToMatchComposite` (`slang-ir-legalize-binary-operator.cpp:64`), which splats the scalar to a matrix BEFORE `legalizeMatrixTypes` (`slang-emit.cpp:2669`). SPIR-V, GLSL and LLVM have no such step, so there `legalizeMatrixTypes` sees the matrix-scalar shape. "Works on Metal/WGSL, crashes on SPIR-V/GLSL" in matrix legalization therefore usually means a function in `slang-ir-legalize-matrix-types.cpp` does not handle a scalar operand; in #14018 `legalizeComparisonOperation` asserted that both operands were matrices. The SPIR-V emitter (`emitSplat`) and the GLSL emitter (`_maybeEmitGLSLCast` inside `greaterThan(...)`) already accept vector-op-scalar, so the fix belongs in the matrix pass. Quick repro: `float2x2 m; all(m > 0.0)` or `clip(float4x4)` in a fragment shader with `-target spirv`. `-target llvm-ir` hits the same assert but is not a usable check, since even `m + m` in a compute shader fails there with "Unsupported instruction for LLVM target!" [Matrix-vs-scalar ops: Metal/WGSL splat the scalar before legalizeMatrixTypes, SPIR-V/GLSL don't](../learnings/1793284670342-matrix-vs-scalar-ops-metal-wgsl-splat-the-scalar-b.md).

## `bit_cast` of Resource-Holding Structs: a Pre-Legalization Pass, Gated on the Legalization Flag (#13480)

`bit_cast<B,A>(a)` where both structs hold a resource field (e.g. slangpy's `Tensor`/`PrimalTensor`) ICEs with E99997 on every release since 2024.1.1 — not a regression — at two sites. On SPIR-V/HLSL/GLSL/Metal/WGSL, `legalizeResourceTypes` runs long before `lowerBitCast`, splits the struct, and `legalizeInst` has no `kIROp_BitCast` case ("non-simple operand(s)!"). On CUDA/C++, `lowerBitCast`'s `readObject` has no resource leaf ("Unable to generate bit_cast code"). A check inside `lowerBitCast` is too late, so the fix is a structural pre-pass before the `shouldLegalizeExistentialAndResourceTypes` block: opaque leaves must match type-for-type and are copied as-is, opaque-free subtrees stay ordinary `BitCast`, and a mismatch gets a user diagnostic. Workaround: copy field by field; `reinterpret<>` is not one (invalid SPIR-V "may not return a logical pointer", E99999 on HLSL/GLSL). Repro on master with slangpy main's module (v0.43.1's `staticarray.slang` no longer parses) ([bit_cast of resource-holding structs ICEs on every target](../learnings/1791383550283-bit-cast-between-structs-that-contain-resource-fie.md)).

The pre-pass must not diagnose every target. On CUDA/C++/LLVM a handle is a real value (`CUtexObject`; a structured buffer is ptr+count; LLVM lowers handles in `lowerCPUResourceTypes` before `lowerBitCast`), so master already compiles `bit_cast<uint2>(struct{Texture2D})` as `slang_bit_cast<ulonglong>`, and diagnosing it regressed PR #13507. Gate on `options.shouldLegalizeExistentialAndResourceTypes`, not a target list. A positional field matcher must require equal natural size AND alignment per position (and equal effective `[[vk::offset]]`, which natural layout honours), or it changes the meaning of casts master rejects with E41202; only structs holding handles are split, so bare handle arrays stay whole and must not trigger it. Before claiming no regression, diff every master-compiling probe's output on every target (strip the prelude include line that embeds the worktree path) ([CUDA/CPU/LLVM give handles real bytes: gate on shouldLegalizeExistentialAndResourceTypes](../learnings/1791423071938-slang-bit-cast-of-resource-holding-structs-cuda-cp.md)).

## Buffer-Element-Type Lowering: a Replacement Keeps the Replaced Inst's Type (#13948, PR #13951)

In the middle of `lowerBufferElementTypeToStorageType` (`slang-ir-lower-buffer-element-type.cpp`), `Ptr(T)` means two different things. `processModule` retypes every existing VALUE of type `Ptr(T, UserPointer)` (or a buffer type) to the storage type `Ptr(T_natural)` up front, but struct field types, array element types and func types keep the logical `Ptr(T)` until the final `bufferType->replaceUsesWith` near the end of the pass. A rewrite in `deferStorageToLogicalCasts` that builds its replacement with a builder-DEDUCED type, such as `emitLoad(gep)` from a logical struct field in the FieldExtract handler, therefore swaps a storage-typed value for a logical one without any error. After `replaceUsesWith`, the downstream cast is an identity cast, and call specialization then inserts an inverted cast on the callee's parameter: an array pointee asserts `structType` in `emitFieldAddress`, and a bool pointee gives an invalid `OpLoad %bool`. The rule is that a replacement inst takes `user->getDataType()`. An identity `CastStorageToLogical` is a reliable detector: `emitCastStorageToLogical` folds same-type casts (`slang-ir.cpp:6733`), so one can only appear after an operand was replaced, and it is always this bug ([lower-buffer-element-type rewrites must keep the replaced inst's type](../learnings/1792965326774-lower-buffer-element-type-rewrites-must-keep-the-r.md); [#13948 root-cause pattern](../learnings/1792961894220-dump-ir-after-pass-can-be-printed-during-exception.md)). To confirm the fix is at the right layer, compile both `f(root.view)` (the FieldAddress path) and `f(r.view)` (the FieldExtract path from a local copy) and count `OpFunction` in `spirv-asm`. One specialization of `f` means the fixed path now builds the same IR shape as the path that already worked ([pointer data on vk vs cuda; right-layer check](../learnings/1792966623515-slang-test-pointer-data-on-vk-uses-scalar-offsets-.md)). The test-input facts from the same fix (pointer data layout per lane, `-cuda` not reproducing it) are on [[wiki/concepts/slang-test-harness-internals-and-unit-tests.md]].
