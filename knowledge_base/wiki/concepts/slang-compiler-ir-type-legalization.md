# Slang Compiler: IR Type-Legalization, Empty Structs, Half, and Enum-Cast Lowering

IR-level type legalization and lowering-gate mechanics: empty structs, the legalization quadratic and attr contiguity, specialization worklist discipline (address-space specialization is on [its own page](slang-compiler-ir-address-space-specialization.md)), CPU `half` rounding, the enum-cast gate, pass-order hazards, and split "special" types.

## TL;DR
- **Confine the empty-struct fix to `IREmptyTypeLegalizationContext` / consumer-side `isSimpleType`**, which returns false for a zero-field struct regardless of linkage decoration. A global `removeEmptyStructFields` pass is CI-rejected (it strips the zero-size empties `Conditional<T,false>`/`Optional` need in dynamic-dispatch payloads); producer-side `addPublicDecoration` removal is the wrong layer (plain `public` functions then emit `static`).
- **When a change deletes a decoration at its producer, inventory EVERY consumer.**
- **#7612 is the canonical original of the empty-CUDA-struct dup pair; #8125 is the slangpy instance** — route #7612 as a DEDUP, never a fresh fixer dispatch.
- **Empty-struct legalization erases a whole parameter**, with any decoration read off it at emit (GS input topology, #13195); record such decorations on the entry-point `IRFunc` too.
- **`IRTypeLegalizationPass` is O(N^2) on straight-line code** (per-round full-module scratch reset, re-queue gated on worklist presence instead of an operand-value change); the "changed" predicate must count inst replacement and struct→tuple splitting.
- **`findAttrs<T>()` returns only the FIRST CONTIGUOUS RUN of `T` operands**; emit a new `IRAttr` type in a separate pass after all size attrs, or `getSizeAttrs()` truncates.
- **For CPU/C++ `half`, arithmetic via `float` is benign for normalized results; conversions and literals are the hazard**, and the runtime prelude `struct half` is the real double-rounding site.
- **A pass gated on a TYPE opcode is fragile**: const-folding can delete the type and strand an op that needs the pass. Gate `lowerEnumType` on the cast opcodes too (not the IntVal-only `Constexpr*` casts).
- **In `slang-ir-specialize.cpp`, a mutation-site requeue is `enqueue(x)` then `addUsersToWorkList(x)`**, and the "dead" re-drain loop stays (it keeps output byte-identical).
- **Before reordering a lowering pass, check what every pass between the old and new positions assumes about the type's shape.** `legalizeMatrixTypes` before buffer lowering loses `column_major` int/bool matrix layout (#13446); moving it later crashes array-assuming passes.
- **Matrix legalization must accept a scalar operand:** Metal/WGSL splat `op(matrix, scalar)` first, SPIR-V/GLSL do not (#14018).
- **`bit_cast` between resource-holding structs ICEs because resource legalization splits the struct before `lowerBitCast`**; fix it in a structural pre-pass gated on `shouldLegalizeExistentialAndResourceTypes` (CUDA/C++/LLVM handles are real bytes and already compile).
- **In `lowerBufferElementTypeToStorageType`, a replacement inst takes `user->getDataType()`, never a builder-deduced type**; an identity `CastStorageToLogical` is always that bug.
- **A new "special" (split) type exposes consumers that assumed only resources split:** debug vars keep the pair/tuple shape or drop whole; split `IRGlobalVar`s need the unfiltered `moveGlobalVarInitializationToEntryPoints` before legalization.

See also [Slang IR: phi block parameters and where inlined global values land](slang-compiler-ir-phis-and-global-value-placement.md) for the all-undefined opaque phi behind E56004 after `legalizeResourceTypes`, and where `GlobalInstInlining` places sunk module-scope tables.

## Empty-Struct Legalization: Fix It in the Legalization Layer (#8125 / #7612)

An empty `struct` used as a **member** of a public/layout-decorated struct (e.g. a `ParameterBlock<CallData>` element) crashes on CUDA/CPU. `IREmptyTypeLegalizationContext::isSimpleType` deliberately RETAINS an empty type carrying `LayoutDecoration`/`PublicDecoration`/`ExternCpp`/`HLSLExport`; the C-like emitter (`slang-emit-c-like.cpp`, which skips only `IRVoidType`) emits it as a 1-byte member while type-layout gives size 0, so slangpy binds at offset 0 and the device reads at offset 8 → `CUDA_ERROR_ILLEGAL_ADDRESS`. The fix home is Slang codegen, not slangpy. #7612 ("Properly handle empty CUDA structs") is the canonical original and @bmillsNV tagged #8125 as its dup, so route #7612 as a DEDUP (`Fixes #7612` on the active PR, or close at merge) ([slang#7612 is the canonical original of the empty-CUDA-struct dup pair (#8125 is the slangpy instance)](../learnings/1785507093198-slang-7612-is-the-canonical-original-of-the-empty-.md)).

**Two layers were rejected.** PR #11657 (a global `removeEmptyStructFields` on the C-like emit path) was CI-rejected: it also strips the zero-size empties `Conditional<T,false>`/`Optional` rely on in AnyValue/existential payloads (`layout-conditional-field.slang.4 (cpu)` aborts `non-simple operand(s)!`); jkwak's steer was to fix it inside `IREmptyTypeLegalizationContext` with `layout-conditional-field.slang` green ([slang#8125 empty-struct fix — global field-removal pass is CI-rejected, fix belongs in empty-type legalization](../learnings/1783473465864-slang-8125-empty-struct-fix-global-field-removal-p.md)). jkwak's dictated draft PR #12304 then deleted the `addPublicDecoration` block in `addLinkageDecoration` (`slang-lower-to-ir.cpp`) so a `public` empty struct drops like a non-`public` one ([#8125 empty-struct fix — decoration-removal, not the rejected global pass](../learnings/1785467126768-8125-empty-struct-fix-decoration-removal-not-the-r.md)). Review returned REQUEST_CHANGES: it erases `IRPublicDecoration` for every plain-`public` decl, and `isPublicOrExportedFunc`, `_isExported` and `_getExportStyle` key on `PublicDecoration || HLSLExportDecoration`, so a plain `public` function emits `static` and `ISlangSharedLibrary::findFuncByName` returns null; `export`/`[DllExport]`/`__extern_cpp` empties still leak. The converged fix is consumer-side: `isSimpleType` returns false for a zero-field struct regardless of linkage decoration, covering every spelling with no visibility regression ([PR #12304 empty-struct public-decoration removal review — REQUEST_CHANGES (wrong layer)](../learnings/1785468944911-pr-12304-empty-struct-public-decoration-removal-re.md)).

**Empty-struct legalization erases a whole PARAMETER (#13195).** A geometry shader with `struct Input {}` used as `point Input v[1]` emitted `OpExecutionMode … Triangles` on SPIR-V+GLSL. Topology lives on the input `IRParam` as `IRGeometryInputPrimitiveTypeDecoration`; the empty struct legalizes to `LegalType::none`, so `legalizeResourceTypes`/`legalizeParam` erases the param before `legalizeEntryPointParameterForGLSL` lifts the decoration to the func, and a post-loop default stamps `Triangles` (silent miscompile). `shouldLegalizeExistentialAndResourceTypes` is off only for CPP/C/CUDA, so HLSL loses the param too, and keeping the param copy does not rescue HLSL's empty-struct case. Topology has 3 consumers / 2 homes (SPIR-V and GLSL read the FUNC, HLSL the PARAM as a qualifier in `slang-emit-hlsl.cpp`), so a blind move regresses HLSL. The fix records the decoration on the entry-point `IRFunc` at lowering (as `[maxvertexcount]`/`[instance]` do), keeps the param copy, and makes the glsl-legalize lift idempotent (assert op-consistency instead of `SLANG_UNEXPECTED`, as for `IRStreamOutputTypeDecoration`) ([geometry input primitive topology has 3 consumers / 2 homes; empty input struct erases the param before glsl-legalize lifts it](../learnings/1789985294662-geometry-input-primitive-topology-has-3-consumers-.md), [empty input struct erases the whole GS input param on ALL non-CPP targets, not just SPIR-V/GLSL](../learnings/1789987486527-empty-input-struct-erases-the-whole-gs-input-param.md)).

## IR Type-Legalization Quadratic (#12040) and `IRTypeLayout` Attr Contiguity

`IRTypeLegalizationPass` (`slang-ir-legalize-types.cpp`) is O(N^2) on straight-line functions: `resetScratchDataBit(module->getModuleInst(), ...)` sits inside the round loop and walks the whole module each round, and re-queueing is gated only on worklist presence, not on whether an operand's legalized value changed, with no already-processed early-out, so a dependence chain advances ~O(1) per round. One fix in `legalizeTypes`→`processModule` covers all three lowering variants: re-queue only on a real operand-value change and drop the per-round reset; the "changed" predicate must count inst replacement and struct→tuple splitting ([slang#12040 IR type-legalization O(N^2) root cause](../learnings/1783674869932-slang-12040-ir-type-legalization-o-n-root-cause-is.md)).

`findAttrs<T>()` (`slang-ir.h`) skips to the first `T` operand and stops at the first non-`T`, returning only the first contiguous run (a documented invariant). PR #12306 emitted `IRTypeAlignmentAttr` inside the per-kind size loop (`size(Uniform), TypeAlignment, size(Existential…)`), so `getSizeAttrs()` dropped the existential sizes and `bind-existentials.cpp` got `slotCount=0`, miscompiling interface slot binding. Emit the new attr in a separate loop after all size attrs, and verify by dumping `structTypeLayout(...)` operands with `-dump-ir` from the PR-head binary ([Slang IRTypeLayout attr contiguity — new attr types interleaved into a mixed operand run break findAttrs](../learnings/1785536484666-slang-irtypelayout-attr-contiguity-new-attr-types-.md)).

## Specialization Worklist Discipline (`slang-ir-specialize.cpp`, #12604/#12608)

`SpecializationContext::expandUseClosure(seed, forceSeed)` has two modes over `workListSet` (queued) and a per-drain `expanded` memo: the **seeding** walk descends into a user only if newly added to `expanded`; the **forced** (mutation) walk descends only if the user is **newly queued** (`workListSet.add` returns true). So a plain `addToWorkList(x)` at a mutation site queues x's users, and a following `addUsersToWorkList(x)` finds them queued and stops, defeating transitive re-notification. The idiom is `enqueue(x)` (seed only) then `addUsersToWorkList(x)`, at `maybeSpecializeFoldableInst` (gated on an actual fold, `instChanged`) and `maybeSpecializePackBranch`. Keep the `specializeChildInsts` re-drain loop even though it never fired across 4087 tests: the iterative work-stack changed enqueue order, single-drain completeness is order-sensitive, and the loop keeps output byte-identical to master ([expanded-memo requires the re-drain loop; mutation requeues must enqueue-then-force](../learnings/1789220236579-slang-specialize-cpp-expanded-memo-requires-the-re.md), [the forced walk stops on workListSet, not the `expanded` memo](../learnings/1789224857022-slang-specialization-work-list-forced-mutation-wal.md)).

## Half Double-Rounding: Conversions Are the Hazard, Not Arithmetic (#12042)

For CPU/C++ `half`, + - * / via `float` is provably benign for normalized results (Figueroa's 2q+2 bound: q=11 needs exactly float's 24 bits), so don't scope a fix into arithmetic. The front-end literal path rounds `double` directly to half via `_truncateDouble` (round-to-even, `slang-lexer.cpp`); the real float-intermediate double rounding is the runtime prelude `struct half` (only `explicit half(float)`, no `half(double)`), the fallback behind the native-fp16 path (`FLT16_MIN`/`__STDCPP_FLOAT16_T__`). A `std::float16_t` route risks cross-host non-determinism unless the fallback is bit-identical ([slang#12042 half double-rounding -- arithmetic benign, conversions are the hazard](../learnings/1783677064766-slang-12042-half-double-rounding-arithmetic-benign.md)).

## Enum-Cast Lowering Gate: Gate on Ops, Not Just the Type (#12048/#12050)

`enum : uint -> int` casts abort at emit with E99999 on all targets because `calcRequiredLoweringPassSet` (`slang-emit.cpp`) sets `enumType=true` only for `kIROp_EnumType`: const-folding an enum-typed constant local removes the last `IREnumType` reference and leaves a `CastEnumToInt` with nothing to trigger `lowerEnumType` ([slang enum->int cast E99999: lowerEnumType gated only on EnumType, not cast ops](../learnings/1783700480198-slang-enum-int-cast-e99999-lowerenumtype-gated-onl.md)). The fix adds the enum-cast opcodes to the gate; {EnumType + 3 casts} is complete because a live enum-typed value keeps the hoistable `IREnumType` alive as a module child. The `Constexpr*` casts are excluded because they are produced only in IntVal contexts (`emitConstexprCast` from `visitTypeCastIntVal`) and `lowerEnumType` has no case for them; the argument is "IntVal-context-only production", not "SCCP folds them" ([enum-cast lowering gate -- completeness reasoning](../learnings/1783706489119-slang-enum-cast-lowering-gate-calcrequiredlowering.md)).

## Static-Const POD-Struct Arrays as Global Constants (#13107/#13115)

PR #13115 extends the #12688/#11628 static-const-array-as-global-constant family to POD structs in `slang-ir-legalize-global-values.cpp`: `isSimpleConstantType` recurses through struct fields (resource/pointer fields → false → conservative inline), and a pre-pass `legalizeConstantConstructorCallsForGlobalScope` folds module-scope synthesized `$init` calls to `IRMakeStruct` before `inlineGlobalConstantsForLegalization` (unfoldable ctors still inline). Three reviewers found no correctness bug; recurring findings were renaming `tryReplaceSynthesizedConstructorCallWithMakeStruct` → `tryBuildMakeStructForSynthesizedConstructorCall`, and whether walking the `$init` body at module scope is the right layer ([Slang #13107/#13115 static-const POD-struct-array global-constant fold: 3-reviewer consensus + recurring findings](../learnings/1789525381949-slang-13107-13115-static-const-pod-struct-array-gl.md)).

## Split ("Special") Types: Debug Vars and Initialized Globals (#13305)

Type legalization splits a value of a "special" type into a pair/tuple `LegalVal`. Resource-bearing types were long the only special types, and two consumers in `slang-ir-legalize-types.cpp` depend on that; making logical pointers special on SPIR-V exposed both.

**Debug vars.** `legalizeDebugVar`/`legalizeDebugValue` discarded the special part, so a split debug var came back simple and `legalizeGetElementPtr`/`legalizeFieldAddress` asserted `flavor == Flavor::simple`; latent because resource structs are not debuggable (`isDebuggableType`) but pointers are. The fix emits the debug var with its legal type's pair/tuple structure when every leaf is debuggable, and drops it whole otherwise (a partial drop is impossible: `void` placeholder fields are non-debuggable, and `LegalVal::pair` collapses when one side is none). Legalization cannot split memory it does not own (SB/CB elements, groupshared, physical-pointer pointees), so a new special criterion needs a pre-legalization validator; arrays of special leaves stay array values, resources included (the #9062 class) ([type legalization: debug vars assume no special type reaches them; logical ptrs as special break it](../learnings/1790645510789-slang-type-legalization-debug-vars-assume-no-speci.md)).

**Initialized globals.** `legalizeGlobalVar`'s split path uses `declareVars`, which creates body-less globals and discards the original, silently losing the initializer (resource statics never hit this: the front end rejects them, E30076). The fix runs the existing unfiltered `moveGlobalVarInitializationToEntryPoints(module, target)` before `legalizeResourceTypes` when such a global exists; SPIR-V/GLSL run it right after legalization anyway, so only timing changes. Traps: a filtered move REORDERS initializers (later stores go before `firstOrdinaryInst`, now the early store, so `static float b = t.tag;` would run before `t`); `SLANG_ASSERT(!globalVar->getFirstBlock())` is wrong because empty-type legalization splits initialized empty-struct statics (`tests/bugs/generic-initializer-inlining.slang`, cpu); and the move skips `IRActualGlobalRate` (`__global`) vars, so those holding a special type are rejected. `tests/**/*.glsl` is gitignored, so write GLSL-input tests as `.slang` with `#version 450` and `-Wno-120` ([type legalization: split globals lose initializers; move them early without reordering](../learnings/1790660162174-slang-type-legalization-split-globals-lose-initial.md)). The same "initializer block has no parent function" shape trips coverage-marker collection; see [[wiki/concepts/slang-a-compiler-internals.md]]. The `printf`/`abort` consumers of split values (an all-resource pack argument becomes a `tuple` that `legalizePrintf` ICEs on; a `pair` keeps only `ordinaryVal`) are on [[wiki/concepts/slang-compiler-printf-and-abort-variadic-arguments.md]].

## Matrix Legalization Pass Order: Int/Bool Matrices Lose Their Buffer Layout (#13446)

On SPIR-V, GLSL, WGSL and Metal, `legalizeMatrixTypes` (`linkAndOptimizeIR` in `slang-emit.cpp`) rewrites int/uint/bool `matrix<T,R,C>` into `vector<T,C>[R]` BEFORE `lowerBufferElementTypeToStorageType`. Buffer lowering already stores column-major matrices (`_MatrixStorage_*_ColMajor` = `vector<T,R>[C]` with transposing pack/unpack) but never sees an int `IRMatrixType`, while reflection honours the layout, so a `column_major` int matrix in a buffer silently gets the wrong offset or element order (square `int3x3`: matching offsets, transposed elements, so offset-only checks miss it). LLVM already runs buffer lowering first. A prototype moving `legalizeMatrixTypes` after buffer lowering, with the Khronos `shouldLowerMatrixType` wrapping non-float matrices on direct SPIR-V, matched reflection; an extra LLVM-style early buffer-lowering run broke 7 tests ([int/bool matrix buffer layout lost by pass order](../learnings/1791310149747-int-bool-matrix-buffer-layout-lost-by-pass-order.md)). Passes between the two positions assume the array shape: Metal/WGSL `legalizeScalarOperandsToMatchComposite` (`slang-ir-legalize-binary-operator.cpp`) calls `as<IRVectorType>(matrix)->getElementCount()` on null for Lsh/Rsh (likely the SIGSEGV in `tests/metal/matrix-integer-lowering.slang`); `validateVectorsAndMatrices` (`slang-ir-validate.cpp`) would reject int matrices with a dimension of 1; and `shouldLowerMatrixType`'s override is direct-SPIR-V-only while GLSL's Default policy skips default-layout matrices under the Natural rule, so a non-float wrap must precede that gate. bool→int storage inside `_MatrixStorage` also remains ([moving legalizeMatrixTypes later exposes passes that assume arrays](../learnings/1791313692068-moving-legalizematrixtypes-later-exposes-passes-th.md)).

**Matrix-vs-scalar ops reach `legalizeMatrixTypes` raw on SPIR-V/GLSL, already splatted on Metal/WGSL (#14018).** The core module emits `cmp(matrix, scalar)` / `op(matrix, scalar)` as a direct `__intrinsic_op` with the scalar unsplatted (`core.meta.slang` ~3229-3283). Metal and WGSL call `legalizeBinaryOp` → `legalizeScalarOperandsToMatchComposite` (`slang-ir-legalize-binary-operator.cpp:64`), splatting before `legalizeMatrixTypes` (`slang-emit.cpp:2669`); SPIR-V, GLSL and LLVM do not. So "works on Metal/WGSL, crashes on SPIR-V/GLSL" usually means a function in `slang-ir-legalize-matrix-types.cpp` mishandles a scalar operand; in #14018 `legalizeComparisonOperation` asserted both operands were matrices. The SPIR-V (`emitSplat`) and GLSL (`_maybeEmitGLSLCast` in `greaterThan(...)`) emitters already accept vector-op-scalar, so the fix belongs in the matrix pass. Repro: `float2x2 m; all(m > 0.0)` or `clip(float4x4)` in a fragment shader with `-target spirv`; `-target llvm-ir` hits the same assert but is unusable as a check, since even `m + m` in compute fails there with "Unsupported instruction for LLVM target!" [Matrix-vs-scalar ops: Metal/WGSL splat the scalar before legalizeMatrixTypes, SPIR-V/GLSL don't](../learnings/1793284670342-matrix-vs-scalar-ops-metal-wgsl-splat-the-scalar-b.md).

## `bit_cast` of Resource-Holding Structs: a Pre-Legalization Pass, Gated on the Legalization Flag (#13480)

`bit_cast<B,A>(a)` where both structs hold a resource field (e.g. slangpy's `Tensor`/`PrimalTensor`) ICEs with E99997 on every release since 2024.1.1 (not a regression) at two sites: on SPIR-V/HLSL/GLSL/Metal/WGSL `legalizeResourceTypes` splits the struct long before `lowerBitCast` and `legalizeInst` has no `kIROp_BitCast` case ("non-simple operand(s)!"); on CUDA/C++ `lowerBitCast`'s `readObject` has no resource leaf ("Unable to generate bit_cast code"). A check inside `lowerBitCast` is too late, so the fix is a structural pre-pass before the `shouldLegalizeExistentialAndResourceTypes` block: opaque leaves must match type-for-type and are copied as-is, opaque-free subtrees stay ordinary `BitCast`, and a mismatch gets a user diagnostic. Workaround: copy field by field; `reinterpret<>` is not one (invalid SPIR-V "may not return a logical pointer", E99999 on HLSL/GLSL). Repro on master with slangpy main's module (v0.43.1's `staticarray.slang` no longer parses) ([bit_cast of resource-holding structs ICEs on every target](../learnings/1791383550283-bit-cast-between-structs-that-contain-resource-fie.md)).

The pre-pass must not diagnose every target. On CUDA/C++/LLVM a handle is a real value (`CUtexObject`; a structured buffer is ptr+count; LLVM lowers handles in `lowerCPUResourceTypes` before `lowerBitCast`), so master already compiles `bit_cast<uint2>(struct{Texture2D})` as `slang_bit_cast<ulonglong>`, and diagnosing it regressed PR #13507: gate on `options.shouldLegalizeExistentialAndResourceTypes`, not a target list. A positional field matcher must require equal natural size AND alignment per position (and equal effective `[[vk::offset]]`), or it changes the meaning of casts master rejects with E41202; only handle-holding structs are split, so bare handle arrays stay whole and must not trigger it. Before claiming no regression, diff every master-compiling probe's output on every target (strip the prelude include line embedding the worktree path) ([CUDA/CPU/LLVM give handles real bytes: gate on shouldLegalizeExistentialAndResourceTypes](../learnings/1791423071938-slang-bit-cast-of-resource-holding-structs-cuda-cp.md)).

## Buffer-Element-Type Lowering: a Replacement Keeps the Replaced Inst's Type (#13948, PR #13951)

Mid-`lowerBufferElementTypeToStorageType` (`slang-ir-lower-buffer-element-type.cpp`), `Ptr(T)` means two things: `processModule` retypes every existing VALUE of type `Ptr(T, UserPointer)` (or a buffer type) to the storage `Ptr(T_natural)` up front, but struct field, array element and func types keep the logical `Ptr(T)` until the final `bufferType->replaceUsesWith`. A rewrite in `deferStorageToLogicalCasts` that builds its replacement with a builder-DEDUCED type (e.g. `emitLoad(gep)` from a logical struct field in the FieldExtract handler) silently swaps a storage-typed value for a logical one. After `replaceUsesWith` the downstream cast is identity, and call specialization inserts an inverted cast on the callee's parameter: an array pointee asserts `structType` in `emitFieldAddress`, a bool pointee gives invalid `OpLoad %bool`. A replacement inst takes `user->getDataType()`. An identity `CastStorageToLogical` is a reliable detector, since `emitCastStorageToLogical` folds same-type casts (`slang-ir.cpp:6733`), so one appears only after an operand was replaced ([lower-buffer-element-type rewrites must keep the replaced inst's type](../learnings/1792965326774-lower-buffer-element-type-rewrites-must-keep-the-r.md); [#13948 root-cause pattern](../learnings/1792961894220-dump-ir-after-pass-can-be-printed-during-exception.md)). To confirm the layer, compile both `f(root.view)` (FieldAddress path) and `f(r.view)` (FieldExtract from a local copy) and count `OpFunction` in `spirv-asm`: one specialization of `f` means the fixed path builds the same IR shape as the working one ([pointer data on vk vs cuda; right-layer check](../learnings/1792966623515-slang-test-pointer-data-on-vk-uses-scalar-offsets-.md)). The test-input facts from the same fix (pointer data layout per lane, `-cuda` not reproducing it) are on [[wiki/concepts/slang-test-harness-internals-and-unit-tests.md]].
