# PR-Approver: Challenger CI-Gate, Verdict Calibration & Human Agreement

Once the deterministic clauses ([[wiki/concepts/review-approver-decision-procedure.md]]) pass and the review-doc verdict is parsed, Step 3, the **adversarial challenger**, is where WOULD_APPROVE / ABSTAIN_POLICY(OPEN_GAP) / BLOCK are actually distinguished. The automated reviewers (production `github-actions[bot]`, CodeRabbit, Devin) do not build or run the test suites, so the challenger pulls the live CI check-runs, traces each red to cause, and reads the source at the pinned head. This page collects the verified-BLOCK catches, the middle-rung ABSTAIN discriminators, the coverage traps, and the human-agreement calibration behind the bar.

## TL;DR

- A green review-doc verdict is blind to golden regressions, downstream-submodule breaks and reachable release-asserts. Harvest individual check-runs at head, per lane, read the failing step, and read the source at the pinned head.
- A verified, deterministic, PR-caused break of a pre-existing CI-gated test is BLOCK even under an APPROVE-with-nits doc: downstream `test-slang-rhi` shaders, previously-swallowed warnings hitting empty-stderr tests, a sanitizer-only link break, the same fix moved to a more generic predicate.
- Classify a core-module edit by direction first: narrowing/removing edits carry the downstream-break risk; purely additive edits and identity folds do not.
- A data-submodule pointer bump can turn untouched tests red: diff the submodule tree across refs; tied-red CI with no code 🔴 is OPEN_GAP. A main-merge push that leaves the flagged file byte-identical cannot clear a prior 🔴: diff the two heads.
- A PR that exposes a pre-existing defect by changing global behavior (a default-type flip) owns it: BLOCK. Enumerate every method on the affected type.
- A RELEASE_ASSERT reachable on valid input is a RED_BUG; prove the trigger at the producer. Convergent reviewers are not proof.
- Green CI that silences the symptom without scoping the root change is ABSTAIN_POLICY:OPEN_GAP. Track the residual across revisions.
- A gap clears when the worst realistic failure is a build break CI would show (green affected legs suffice) or the change is false-negative-safe by construction; codegen/logic PRs can miscompile while green.
- A new suppression or path-blocking predicate needs a vacuous-truth probe and a trigger-present negative control: CI and codegen diffs cannot see a missing diagnostic.
- Real-hardware CI substitutes for a missing Devin only if the PR's test executed on a hardware device. A test mask is not execution: grep the `GPU_TEST_CASE` mask for the target backend, resolve `runs-on`, open a log. Compile-out behind an unmerged companion ABI is a third zero-coverage mode; verify "compiles out" per file and symbol.
- Combined status is not causal in either direction: classify from individual check-runs traced to cause.
- A secondary reviewer's flag on a fresh push is a hypothesis: verify it at the pinned head by construct name. On docs PRs Devin's doc-accuracy "bugs" are low-confidence; the source-reading production review is the arbiter, and uncertainty means ABSTAIN, never BLOCK.
- Join each verdict to the commit it was submitted against; an early COMMENTED/LGTM is not a formal APPROVED.

## The core CI-gate class: a green review-doc is blind to test regressions

A repeating BLOCK class, vindicated across #11595, #12130, #12106-R1 and #12141, is a **verified, deterministic, PR-caused break of a pre-existing CI-gated test** that the review-doc rated only nits. Harvest **check-runs at head** (not the combined-status glance) and read the failing job's failing step.

- **Downstream submodule shaders test-slang never compiles.** slang#12141 disabled the `vector<T,4>` `(vec2,T)`/`(T,vec2)` initializers via `static_assert(false)`; the primary review was 🟡 APPROVE_WITH_NITS, Devin clean, all `test-slang` legs green, but the bundled `external/slang-rhi` submodule's `test-ray-tracing-clusters.slang` uses `float4(attribs.barycentrics, 1.f)`, which now hits E41400, and only `test-slang-rhi` compiles it; that job was RED ([disabling a core-module init overload breaks bundled slang-rhi shaders](../learnings/1784270927259-approver-challenger-miss-averted-disabling-a-core-.md)).
- **Diagnostic forwarding surfaces previously-swallowed warnings.** slang#12141 R2's `forwardDiagnostics()` on the constructor success path re-emitted a long-standing `warning[E30081]` and broke pre-existing `tests/glsl/integer_pack.slang (vk)`; the blast radius is every input that already triggered the swallowed diagnostic, in tests asserting empty stderr. A `.slang (vk)` test shows `conclusion=success` on a GPU-less runner because it is skipped, not passed: only a completed leg with the GPU counts ([a diagnostic-forwarding refactor breaks empty-stderr tests](../learnings/1784304367382-approver-challenger-miss-averted-a-diagnostic-forw.md)).
- **A sanitizer-only link break.** slang#12136's new unit test touched the polymorphic internal `Slang::Session` via `asInternal()`; under `-fno-rtti` + the sanitizer's `-Wl,--no-undefined` the lazy-undefined `typeinfo for Slang::Session` became a hard link failure, RED on one of ~12 lanes. Scan per lane; the leading `DWARF error: FORM value: 0x23` is noise (grep `undefined reference|typeinfo`) ([a Slang::Session unit test fails to link only in the sanitizer job](../learnings/1784271192351-approver-challenger-miss-averted-a-new-unit-test-t.md)).
- **Moving the same fix to a more generic layer widens blast radius.** slang#12111 R1 approved a Layer-B fix (coalesce descriptor-heap loads in the SPIR-V legalizer). The `synchronize` re-implemented it as Layer A (make any `UniformConstant` load movable in the generic `isMovableInst`, so CSE collapses them), reviewer-directed and Devin-clean, but it regressed unmodified `intrinsic-texture.slang.6/.7/.8` goldens because the predicate also fires on plain sampler globals. Such a revision is a different change: run a full fresh challenger and a live CI diff-vs-master ([same-fix Layer-A revision needs a fresh CI probe](../learnings/1784328018356-approver-challenger-same-fix-layer-a-generic-cse-r.md)).
- **A data-submodule bump can turn untouched tests red.** slangpy#1082 had a near-clean review doc but 6/12 build jobs red: unchanged `test_dds_file.cpp` threw "No such file" for `bc7-unorm-{nonsquare,3d}.dds` because the PR bumped `data` `4c24c797`→`6ecdf7c` and the new commit removed those fixtures. Treat any `160000`-mode / `Subproject commit` hunk as a review surface: `require_ci_green=false` passes the clause over red CI, so pull a failed job log and diff the submodule tree across refs (`gh api repos/<data-repo>/contents/<dir>?ref=<old>` vs `?ref=<new>`, or 404-probe the file). A real trigger with no verified code 🔴 is ABSTAIN_POLICY:OPEN_GAP; never approve over red CI tied to the PR's own change ([data-submodule bump can turn CI red on unchanged tests](../learnings/1785426143619-approver-challenger-ci-gate-data-submodule-bump-ca.md)). The fix was confirmable: the author's "Restore data submodule" commit made `compare old...new` show exactly one changed file (`data`), the fixtures returned, and CI settled 12/12 green, which retires that OPEN_GAP once CI fully settles ([reverting the bump restores fixtures and greens CI](../learnings/1785495128502-approver-challenger-ci-gate-confirmed-reverting-a-.md)). Conversely, a later main-merge `synchronize` touched only unrelated files and left the flagged `torch_bridge_impl.cpp` byte-identical, so the prior Devin 🔴 recurred verbatim. "New push" ≠ "concern addressed": compute `gh api compare/<prevhead>...<newhead>`; if the flagged path is not in the delta the prior disposition stands, and name what would move it (a change to that file, or a human sign-off) ([a main-merge synchronize can't clear a code-level 🔴](../learnings/1785496402847-approver-challenger-ci-gate-a-main-merge-synchroni.md)).

**Classify a core-module edit by direction first.** The #12141 rule (a change to `core.meta.slang`/`hlsl.meta.slang`/prelude that narrows what compiles is assumed to break downstream code until CI proves otherwise) is a narrowing rule, and applying it to an additive edit inverts it. slang#12651 added a new `operator+` beside `operator-` in `core.meta.slang` and folded unary `+` in `tryConstantFoldExpr`; it merged unchanged at the decided commit with zero follow-ups. A **narrowing / removing / constraining** edit (disable an overload, tighten a `static_assert`, drop an atom) needs check-runs at head including `test-slang-rhi`, and a downstream break is BLOCK-class even under APPROVE-with-nits. A **purely additive** edit (a new overload, a new capability atom, a flag broadened false→true) cannot break callers that never referenced the new symbol, so the only residual probe is overload ambiguity. Likewise an **identity** fold (unary `+`) is safe by construction, while **value-changing** folds (unary `-`, `~`, binary arithmetic) need the source-width / no-intermediate-wrap / `ParenExpr`-peel probe ([widening core-module additions are not the #12141 class](../learnings/1788943725016-approver-challenger-calibration-widening-core-meta.md)).

## Attribution: a PR that EXPOSES a pre-existing defect by changing global behavior owns it

On slang#12089 rev6 a capability-narrowing PR flipped the default HitObject type on `sm_6_9+hlsl_nvapi` from NVAPI to native `dx::HitObject`, but four LSS accessors keyed on a different capability were not re-gated, producing mixed-ABI HLSL, the defect class the PR exists to eliminate. The lines are pre-existing and untouched, which tempts an ABSTAIN "latent", but the PR is the proximate cause: changing the type-selection predicate turned them from matched-at-base to mixed-at-head, so BLOCK ([a capability-narrowing PR can expose pre-existing mixed-ABI on unedited sites](../learnings/1784310133019-approver-challenger-a-capability-narrowing-pr-can-.md)). On any capability-narrowing or default-flipping PR, enumerate all methods on the affected type, not just the diff's arms: a method whose `case hlsl:` emits a vendor intrinsic but is callable regardless of the resolved ABI is a mixed-ABI candidate.

## Reachable RELEASE_ASSERT is a RED_BUG — prove reachability at the producer

slang#12147's `SLANG_RELEASE_ASSERT(debugArtifactCount == 1)` aborts slangc on valid multi-entry-point input, while its sibling validator `_validateCoverageManifestOutputPaths` handles `>1` with a graceful diagnostic; the asymmetry between sibling validators is the smell ([RELEASE_ASSERT on a reachable multi-artifact count is a RED_BUG](../learnings/1784316403221-approver-challenger-release-assert-on-a-reachable-.md)). The trigger is subtle: for a single SPIR-V target slang forces whole-program (count==1) on every path (no-`-o` synthesizes a stdout output gated on `m_rawTargets==1`), so the assert is reachable only via multi-target + ≥2 entry points + no per-target `-o` ([multi-target demotes SPIRV out of whole-program](../learnings/1784336687356-slang-separate-debug-info-multi-target-demotes-spi.md) on the compiler-internals page). The recall subagents and the production bot all converged on a wrong single-target trigger; a DECISION_REVIEW critique adversarially hunting the gate the finders missed caught it. Convergence is not correctness: run that critique whenever the challenger overrides a lenient doc verdict on a reachability argument ([single-vs-multi-target whole-program forcing hides the trigger](../learnings/1784333455962-approver-challenger-miss-single-vs-multi-target-wh.md)).

## The middle rung: green CI can still be a hold (ABSTAIN / OPEN_GAP)

A green-CI revision that fixes the symptom without scoping the root change is a hold, not a WOULD_APPROVE. slang#12141 R3 added explicit casts to the one test E30081 broke but left the over-broad `forwardDiagnostics()`, so the latent surface remains for every other consumer, and a `diagnoseRaw` re-emission bypasses per-id `-Wno-*`/`#pragma warning` suppression by construction. Both checks are CI-invisible; verified over-broad + plausible trigger + real blast radius + not false-negative-safe is `ABSTAIN_POLICY:OPEN_GAP`, the rung between BLOCK (no reproduced 🔴) and WOULD_APPROVE ([a test-cast workaround fixes the test, not the over-broad change](../learnings/1784309271831-approver-challenger-miss-averted-a-test-cast-worka.md)). Across that PR's three revisions (BLOCK for the rhi break → BLOCK for E30081 → OPEN_GAP for one latent scope gap) the job is tracking the residual, not confirming "the last thing I flagged is fixed".

## When a gap CLEARS: is the worst realistic failure a build break CI catches, or a silent miscompile it wouldn't?

The discriminator is the failure class. For a **build-flag / optimization-level PR** whose only risk is a CI-visible `-Werror` break, complete green CI on the affected config legs clears the gap. slang#12140 (`-Og` for GCC/Clang debug) cleared a "`-Wmaybe-uninitialized` might break `-Werror`" gap because the debug legs were green at head, the warning is GCC-only (the "macOS Clang" framing was misdirected), and the blast radius is Debug+GCC/Clang only ([build-flag PR: clear a -Werror gap by checking the affected config is green](../learnings/1784270606102-approver-calibration-build-flag-pr-clear-a-werror-.md)). A **subtractive guard** (`AND NOT MSVC`) relative to a prior CLEAN head can only remove a flag, so the verdict is ≥ prior without re-derivation, and a warning-coverage gap on a pure-cmake PR adding zero C++ clears as future-proofing ([subtractive NOT-MSVC guard can't regress prior-green](../learnings/1784288671711-approver-calibration-og-debug-build-guard-subtract.md)). Codegen/logic PRs differ: a miscompile passes all tests.

**False-negative-safe-by-construction exemptions approve.** For a diagnostic-suppression PR, trace the diagnostic's fire conditions instead of asking abstractly "could this hide a bug?". slang#12011's E41017 `__extern_cpp` exemption is safe because `checkUninitializedGlobals` fires only when a global has no in-module init and no store, the predicate (`IRExternCppDecoration` + external linkage) is a strict subset of the documented host-provided-global pattern, and a discriminator test proves it narrow ([E41017 __extern_cpp exemption is false-negative-safe by construction](../learnings/1784288118508-approver-calibration-e41017-extern-cpp-exemption-i.md)).

**A new path-blocking predicate needs a vacuous-truth probe.** When a PR adds a guard or coverage predicate to must-init / uninitialized / uniformity analysis (`isEveryPathFromBlockedByStore`, `cancelLoadsByDefiniteAssignment`), check whether it can be vacuously true, which would silently suppress real warnings. On slang#12894 (the E41035 false positive on `WaveIsFirstLane`-guarded stores read via `WaveReadLaneFirst`) the author self-caught exactly this ("Fix vacuous-true soundness gap in `isEveryPathFromBlockedByStore`"); the correct fix keys on the specific guard↔read correlation, since a blanket "blocked" would suppress a genuinely uninitialized store guarded by `if(!WaveIsFirstLane())`. CI-green and byte-identical codegen cannot see a missing diagnostic, so demand a **trigger-present negative control**: a test without the correlation where E41035 still fires, the same rule as the flag-chain control ([uninit-analysis guard predicates: probe for vacuous truth](../learnings/1788947202230-approver-challenger-miss-uninit-analysis-guard-cor.md)).

**A CUDA guard on one entry of a shared test module.** Wrapping one `[shader]` entry of a multi-entry Slang test module in `#ifndef __TARGET_CUDA__` keeps the module loadable on CUDA for its siblings, since Slang capability-checks all entry points at load and one unsupported `Buffer<T>`/`RWBuffer<T>` entry (E36107) takes the module down. Two probes make it airtight: **structural containment** (read the full file at head; the guard wraps only the target entry) and **skip-before-load ordering** (the `pytest.skip` must fire before `load_program(..., ["copy_"+type])`, or stripping the entry turns a clean skip into "entry point not found"). On slangpy#1083 the skip at `test_buffer.py:76-77` precedes the load at L118-120 and the macro has in-repo precedent → WOULD_APPROVE on the Devin-only tier (production skips bot fixer branches → harvest exit 20) ([CUDA preprocessor-guard: verify skip-before-load ordering](../learnings/1785453364629-approver-challenger-clean-cuda-preprocessor-guard-.md)). Confirmed by merge: jkwak-work APPROVED and merged the exact R2 head `a31e8af8` with zero follow-ups. The human signal evolved (R1 COMMENTED "Looks good to me." + a nit → R2 APPROVED), and only the final state is calibration truth: an early COMMENTED/LGTM is not a formal approve, so join each verdict to its commit and re-check reviews at the merged head ([confirmed by merge (slangpy#1083)](../learnings/1785462075111-approver-challenger-clean-confirmed-by-merge-cuda-.md)).

**Constness-selected SPIR-V operands: trace the emitted form.** slang#12133's Gather const-offset fix emits `ConstOffset`, legal only for an `OpConstant`/`OpConstantComposite`. "The helper detects constants" is not enough: verify that `maybeHoistConstructInstToGlobalScope` moves the accepted shapes to global scope and that the classifier's accepted set ⊆ the hoister's set. When the PR's test is spirv-asm-only (no real `spirv-val`), that inspection is the validation gate ([ConstOffset safety hinges on constant-MakeVector hoisting](../learnings/1784334175709-approver-challenger-constoffset-safety-hinges-on-c.md)).

## Real-hardware CI can substitute for a missing Devin — but only if it actually EXERCISED the code

slang-rhi runs its full test suite inline in the build matrix on real GPU adapters, so on the fallback tier a timed-out Devin on a behavior-changing PR (#797 D3D12 timestamp resolve) need not force ABSTAIN: grep the CI job logs for the PR's new test executing and passing on a real adapter (`hardware-device`, not `software-device`/`SKIPPED`) ([slang-rhi real-hardware CI substitutes for a timed-out Devin](../learnings/1784271405834-approver-human-agreement-slang-rhi-real-hardware-c.md)). CI green in a decoupled component (a standalone Go tool in `extras/scaler` that no CMake/CI job builds) is orthogonal and substitutes for nothing. Three zero-coverage modes defeat the substitution:

- **Masked-out test.** slang-rhi#800 flipped `docs/api.md`'s Metal `dispatchComputeIndirect` cell to `yes` and added real Metal code with green CI, but the test's `GPU_TEST_CASE(..., D3D12 | Vulkan | CUDA)` excludes Metal: compile-only, never executed, a genuine `OPEN_GAP` for a support-claiming PR ([backend-support PR with a masked-out test is compile-only](../learnings/1784338875078-approver-clause-gap-backend-support-pr-that-flips-.md)). It recurs when the PR ships a test: slang-rhi#801 (native Metal buffer import) masked its test `D3D12 | Vulkan`, so `GPU_TEST_CASE` registered no Metal case, and `checkNoSilentGpuSkips()` flags only a device with registered-but-zero-running tests. Grep the mask for the PR's target backend; a Metal-only change tested under `D3D12 | Vulkan` is OPEN_GAP even if source-verified correct; next action is to add `Metal` or consciously accept the risk ([Metal-only feature with test masked to D3D12|Vulkan = OPEN_GAP](../learnings/1784816143760-approver-challenger-slang-rhi-metal-only-feature-w.md)).
- **The runner cannot run it.** A mask declares intent; the runner the job lands on decides execution. The #801 write-up's claim that the macOS runner runs `-check-devices` on Metal hardware is withdrawn: hosted `macos-latest`/`macos-26-arm64` is an `Apple Paravirtual device` that, until slang-rhi#807 restored Metal device init, reported Metal unsupported and skipped every Metal case. Resolve the job's `runs-on` and open a log ([test-mask registration is not test execution](../learnings/1785787084796-approver-challenger-miss-test-mask-registration-is.md)).
- **Compiled out behind an unmerged companion ABI.** slang-rhi#803 (CPU ray query: 1120-line impl, dedicated CPU tests, 30 CTS cases) is gated behind `SLANG_RHI_ENABLE_CPU_RAY_QUERY`, whose default hinges on the fetched Slang package shipping `prelude/slang-cpp-ray-query.h`, a header that existed only in the open companion slang#12282, not the pinned `v2026.12.2`. ABI_AVAILABLE=OFF, so the test file was `target_sources`-gated out and the CTS mask degraded `CPU|D3D12`→`D3D12`. For any `cmake_dependent_option` keyed on a Slang-package header, check the pinned `SLANG_RHI_FETCH_SLANG_VERSION`; compiled-out code is OPEN_GAP and "CPU runs headlessly" must not round it up (fork-PR CI also sat at `action_required`) ([feature gated on an unmerged companion PR compiles out](../learnings/1785395617012-approver-challenger-slang-rhi-feature-gated-on-unm.md)). Verify "compiles out" per file and symbol: on #803 R2 only `cpu-acceleration-structure.cpp` was whole-file excluded, while `cpu-command.cpp`'s flagged `cmdQueryAccelerationStructureProperties` compiled regardless of the toggle. `grep -n <file> CMakeLists.txt`, open the flagged line to confirm it is inside the guard (a macro-occurrence count is not enough), and say "compiled and registered", not "would exercise", unless the device is confirmed to run it; a false "it all compiles out" can make a human dismiss a live finding ([verify "compiles out" per file/symbol](../learnings/1785416472140-approver-challenger-miss-compiles-out-on-a-partial.md)).

## Combined-status ≠ causal: classify from individual check-runs traced to cause

The combined commit status aggregates all contexts, including non-causal cross-repo jobs. On the clean front-end PR #12131 it was `failure` from a `test-falcor` image-diff flake (a prior draft run) and a Linux-only `SlangPy Tests` `test_profiler.cpp` CPU-timing assertion, neither reachable from the PR ([combined-status failure from non-causal downstream flakes](../learnings/1784329341037-approver-calibration-combined-status-failure-from-.md)). When `require_ci_green:false` defers, enumerate check-runs `--paginate`, confirm the repo's own core legs (especially the one running the PR's new tests) are `success`, and trace each red; platform-asymmetric, timing, image-diff and downstream-renderer failures signal non-causal flakes, and `test_profiler.cpp` recurs for slang PRs. The rule is symmetric: a green combined status is equally untrustworthy (#12130's metal-fmod miss).

## A stale secondary reviewer flags the pre-fix state — verify at head

On slang#12147 R4 (the fix revision) Devin ran ~5 min after the push and flagged the R1–R3 bug verbatim at `:766`, but the assert was gone: Devin analyzed a stale snapshot, and `:766` was now a harmless guard, with the graceful diagnostic at `:798` ([Devin reviews the pre-fix state on a fresh push](../learnings/1784343479716-approver-stale-secondary-devin-secondary-reviews-t.md)). On a fresh-push revision the primary tier harvested at the pinned head (matching `diff_hash`) is the verdict source; open the flagged construct at the head by name, not line number. A secondary flag is a hypothesis to verify, never a standalone reason to hold a BLOCK.

On **docs PRs**, Devin's confident "the documentation is factually wrong about X" findings are usually prose misreadings: Devin browses the rendered PR page and does not read compiler source the way the production `github-actions[bot]` reviewer does. Across two revisions of slang#12039 (language-reference conversion expressions) Devin kept reporting "Bugs" ("supported numeric promotions appear unavailable"), while the source-reading production review of near-identical content reported "5 documentation consistency/clarity gaps — NO correctness or behavioral errors". Treat a Devin-only doc-accuracy bug as low-confidence unless a source-reading reviewer or your own check against compiler behavior corroborates it; that reviewer's explicit "no correctness errors" outweighs it. If clauses pass and you cannot verify the claim, ABSTAIN, never BLOCK. On a code PR, by contrast, a Devin bug pointing at a specific inst/line is often worth escalating ([on docs PRs Devin's doc-accuracy "bugs" are prose misreadings](../learnings/1788947298987-approver-challenger-calibration-on-docs-prs-devin-.md)).
