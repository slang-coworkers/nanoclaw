# Formatting & Lint Tooling (clang-format, prettier, gersemi)

How Slang's `extras/formatting.sh` works, what CI pins for each tool, and the traps that cost CI round-trips on formatting, ASCII, license-lint and clang-only warning failures.

## TL;DR

- **Verify a tool version against the script that gates it, never against the tool's own `--version` or a README range.** `extras/formatting.sh:203` calls `require_bin "clang-format" "17" "18"`, a half-open `[17, 18)`, so **18.x is REJECTED as too new**, although the repo prose says "clang-format 17-18".
- **Pin clang-format 17.0.6** (the PyPI default 18.1.8 is rejected). gersemi `0.21-0.22`, prettier `3+`, shfmt `3+`.
- **`formatting.sh` with no args prints USAGE and exits**; pass at least `--modified` plus a type flag (`--cpp`, `--md`, …).
- **A bare `--modified` ABORTS EARLY if any required tool is missing, even under `--check-only`**, so markdown goes unchecked. Type flags narrow the requirement checks: `--modified --cpp` runs cleanly with gersemi/shfmt absent. An unrelated missing tool never means "formatting is impossible here".
- **`--cpp` with clang-format absent from `$PATH` prints "Formatting cpp files..." and exits 0 having formatted nothing.** Confirm `which clang-format` first, especially after a container restart drops an ephemeral install.
- **`--since HEAD` is a false-pass for uncommitted work** (it sees only files changed in commits after the rev). CI runs `./extras/formatting.sh --check-only` with no `--since`; run that before any push.
- **`--modified` covers only git-TRACKED, uncommitted files**: a new untracked file is skipped at exit 0 (`clang-format -i <newfile>` or `git add -N` first), and a committed file needs clang-format pointed at it directly.
- **Never point clang-format at a `.meta.slang` file**: it is Slang source, and one `clang-format -i` reformatted all 43k lines of `hlsl.meta.slang`. Recover with `git checkout HEAD -- <file>`. No tool in `formatting.sh` formats `.slang`.
- **`export PATH=` does not survive between Bash tool calls**: prefix inline, `PATH="$HOME/.local/bin:$PATH" ./extras/formatting.sh --cpp -- <file>`.
- **"clang-format is missing here" is no reason to punt to the author.** The PyPI wheel ships a native binary; `pip download clang-format==17.0.6 --no-deps`, `python3 -m zipfile -e`, `chmod +x`, prepend to `PATH` (~10 s, no apt or approval).
- **A `pip install --user` binary lands in `~/.local/bin`, off PATH; a `pip install --target DIR` shim needs `PYTHONPATH=DIR`** or every call throws a Traceback.
- **CI's prettier check covers the six top-level `*.md` files, not `docs/`.** Since #12600 a default `--check-only` reaches markdown, but the unquoted `git ls-files $@` glob-expands `*.md` at the repo root (`AGENTS`, `CLAUDE`, `CODE_OF_CONDUCT`, `CONTRIBUTING`, `README`, `REVIEW`). Keep those prettier@3.3.3-clean; `docs/**` is effectively unenforced.
- **Never `prettier --write` repo markdown.** Design and user-guide docs use setext headings, `*` bullets and `*emphasis*`; local prettier 3.8/3.9 rewrites them (50-130 lines of churn per file), and even prettier@3.3.3 flags them. If `origin/master`'s file already fails your prettier, the divergence is the tool version: match conventions by eye and prove format-neutrality with a normalized diff (`/pnpm/prettier`).
- **Never run prettier on the generated capability-atoms doc**; it is regenerated from capdef `///` comments.
- **A DRAFT PR can run functional CI but not the format check.** `gh workflow run ci.yml --ref <branch>` bypasses the `draft != true` filter; `check-formatting.yml` has no `workflow_dispatch`, so verify locally with `clang-format --dry-run --Werror <file>`. `/format` works again (since 2026-10-29) but pushes a `format/pr-<N>` branch you merge back.
- **Every file under `include/` AND `prelude/` must be pure ASCII** (MSVC C4819 → C2220 under `/WX` on CP932). Sweep with `grep -rP '[^\x00-\x7F]' include/ prelude/`; watch arrows too. C4819 cannot be `reproduced` from Linux.
- **`reuse lint` does not recurse into submodules**, so BSD notices of statically-linked `external/` deps never ship; and a bare `LICENSES/BSD-*.txt` turns `reuse lint` RED (unused license). Install each dep's own notice via the CMake install `metadata` component.
- **clang `-Werror -Wformat-security` rejects an argless `printf(fmt)`; gcc does not**, so Linux is green while macOS CI fails. Route through `"%s"`.
- **shader-slang/slang-rhi's gates are NOT slang's:** clang-format **v20.1.7**, an ASCII-only hook, `-Werror`. Run the pinned version from a venv; control-test on an untouched file.

## formatting.sh: tool requirements and invocation

`extras/formatting.sh` runs clang-format (C++), gersemi (CMake), prettier (YAML/JSON/MD) and shfmt (shell) over `.cpp/.h/.cmake/.sh/.md/.yaml/.json`, never `.slang`. With no arguments it prints USAGE. A bare `--modified` aborts early if any required tool is missing, even under `--check-only`; a type flag narrows the requirement checks too, so a C++-only change formats cleanly with gersemi and shfmt absent. `--modified` covers only git-tracked files and skips a new untracked file at exit 0. CI pins clang-format **17.x**: `require_bin "clang-format" "17" "18"` is half-open, so 18.1.8 fails with `found clang-format 18.1.8, required [17, 18)` / `version 18.1.8 is too new` and `FMT_EXIT=1`, though `.github/copilot-instructions.md` says "clang-format 17-18". Verify a version by running the consumer that gates it and reading its exit code ([CORRECTION: formatting.sh needs 17.x; 18.x is rejected as too new](../learnings/1785992812883-correction-slang-formatting-sh-needs-clang-format-.md); [formatting.sh requires clang-format 17.x exactly](../learnings/1778742529214-slang-formatting-sh-requires-clang-format-17-x-exa.md), [CI pins clang-format 17; never prettier-write docs/design/*.md](../learnings/1780938587077-slang-ci-pins-clang-format-17-never-prettier-write.md)).

**`clang-format -i` on a `.meta.slang` is destructive.** `.meta.slang` is Slang source and `formatting.sh` never formats it; `clang-format -i --style=file source/slang/hlsl.meta.slang` reformatted the whole 43k-line file (~22877 ins / ~21003 del). Point clang-format only at `.cpp`/`.h`, hand-edit `.meta.slang` comments, and recover with `git checkout HEAD -- <file>`. The script needs clang-format on `$PATH` **inline in the same bash call**, since the shell env resets between Bash tool invocations; reinstall the pip wheel each fresh session (`pip install clang-format==17.0.6 --break-system-packages`; binary at `~/.local/lib/python3.11/site-packages/clang_format/data/bin/clang-format`) ([never point clang-format at .meta.slang; PATH inline in the same call](../learnings/1784332011128-clang-format-via-pip-wheel-never-point-it-at-meta-.md)).

**The scoped `--cpp` path has a silent false-clean.** With clang-format absent from `$PATH`, `./extras/formatting.sh --cpp` prints "Formatting cpp files..." and **exits 0 without formatting anything**, distinct from the early abort; a `--cpp` run that passed earlier can be a no-op after a restart drops the ephemeral install. Confirm the binary (`which clang-format` or `~/.local/bin/clang-format --version`). `--modified` also finds nothing once you have committed, so format a committed file by running clang-format on it ([formatting.sh --cpp silently no-ops when clang-format is absent](../learnings/1784826314203-formatting-sh-silently-no-ops-when-clang-format-is.md)).

**`--since HEAD` is a false-pass for uncommitted changes.** `--check-only --cpp --since HEAD` exits 0 with edits uncommitted, because `--since <rev>` formats only files changed in commits after `<rev>`. CI's `check-formatting` runs the full `./extras/formatting.sh --check-only`; run that (or `--check-only --cpp` without `--since`) before any push ([--since HEAD is a false-pass for uncommitted changes](../learnings/1782456154502-formatting-sh-since-head-is-a-false-pass-for-uncom.md)).

## clang-format 17: installation, PATH, PYTHONPATH, wheel extraction

CI pins **17.0.6**. clang-format 18 makes different wrapping decisions on borderline (~99-char) lines, and Debian 12's apt version is too old. `pip install --user --break-system-packages clang-format==17.0.6` puts the binary in `~/.local/bin`, NOT on PATH (`export PATH="$HOME/.local/bin:$PATH"` in the same call). `pip install --target ~/.cf17 clang-format==17.0.6` gives a `bin/clang-format` Python launcher that needs `PYTHONPATH=~/.cf17` or every call throws a Traceback (`PYTHONPATH=~/.cf17 ~/.cf17/bin/clang-format --version` → 17.0.6). Check a file against the repo `.clang-format` with `diff -q <file> <(clang-format --style=file <file>)`. When `git fetch` of a PR ref is blocked, fetch PR-head files with `gh api repos/<o>/<r>/contents/<path>?ref=<headRef> --jq .content | base64 -d` ([formatting.sh requires clang-format 17.x exactly](../learnings/1778742529214-slang-formatting-sh-requires-clang-format-17-x-exa.md), [clang-format-17 via pip --target needs PYTHONPATH](../learnings/1782156721731-clang-format-17-via-pip-target-needs-pythonpath-se.md)).

**Extract the wheel; do not punt.** clang-format is often absent in coworker containers, and that absence has been handed downstream as "the PR author must run formatting.sh". The PyPI wheel ships a prebuilt native binary under `clang_format/data/bin/`, so extracting it is enough: no `pip install` (which can hit `externally-managed-environment`), no apt, no `install_packages`, ~10 seconds ([extract the clang-format PyPI wheel](../learnings/1785989277743-clang-format-for-slang-formatting-sh-extract-the-p.md)):

```bash
pip download clang-format==17.0.6 -d /tmp/cf17 --no-deps -q
cd /tmp/cf17 && python3 -m zipfile -e clang_format-17.0.6-*.whl /workspace/agent/tools-cf17/
chmod +x /workspace/agent/tools-cf17/clang_format/data/bin/clang-format
export PATH="/workspace/agent/tools-cf17/clang_format/data/bin:$PATH"
./extras/formatting.sh --modified --cpp   # → found clang-format 17.0.6, required [17, 18) ✓ exit 0
```

Pin 17.0.6, not the pip default 18.1.8: extracting the 18.x wheel and reasoning "the docs say 17-18" is a failure mode recorded twice ([CORRECTION: 17.x required](../learnings/1785992812883-correction-slang-formatting-sh-needs-clang-format-.md)). Measured in the `slang-fixer` container (2026-08-06): `prettier` was already on PATH (its `UNDICI-EHPA` stderr warning is not a failure); `gersemi` and `shfmt` were absent, irrelevant for a C++-only change. The extraction persists for the session only, so re-run it each fresh session.

**When the local build is disk-blocked**, pull CI's own binary from slang-binaries: `curl -fsSL "https://github.com/shader-slang/slang-binaries/raw/<SHA>/clang-format/x86_64-linux/bin/clang-format" -o /tmp/cf && chmod +x /tmp/cf`, confirm `--version` is 17.0.6, and run `/tmp/cf -i <file>` from the repo root so it reads `.clang-format`. A failed `check-formatting` job log prints the download URL; as of 2026-06 the SHA was `306d22efc0f5f72c7230b0b6b7c99f03c46995bd` ([run CI-pinned clang-format when disk-blocked](../learnings/1782507462588-run-ci-pinned-clang-format-locally-when-the-build-.md)).

## Draft PRs: ci.yml is workflow_dispatch-able, check-formatting is NOT

shader-slang/slang gates `pull_request` CI on `draft != true`, so a DRAFT PR shows every check as "skipping". `ci.yml` (functional CI) CAN run on a draft via `gh workflow run ci.yml -R shader-slang/slang --ref <branch>`, because `workflow_dispatch` is not subject to the filter (verify with `gh run view <id> --json jobs`). `check-formatting.yml` is `pull_request`-only with no `workflow_dispatch`, so formatting must be verified locally against clang-format 17: `clang-format --dry-run --Werror <changed_file.cpp>` (empty output + rc 0 = clean), rather than the script's overall exit code when gersemi/shfmt are absent ([Draft PRs: ci.yml IS workflow_dispatch-able, check-formatting.yml is NOT](../learnings/1782440063963-draft-prs-ci-yml-is-workflow-dispatch-able-but-che.md), [workflow_dispatch bypasses the draft filter](../learnings/1782440084006-draft-pr-ci-on-shader-slang-slang-workflow-dispatc.md)).

The `/format` PR comment (Regenerate Format workflow) is a fallback with a different shape. Its 2026-10-19 failure, `remote: You must verify your email address` / 403 on `github.com/slangbot/slang` from the `slangbot` account's lapsed e-mail verification ([CI sweep notes: `/format` 403](../learnings/1792486355939-ci-sweep-snapshot-misses-jobs-in-waiting-runs-only.md)), was fixed by moving to an App token and `GITHUB_TOKEN` (history in [Agent GitHub Token Boundaries](agent-github-token-boundaries-and-write-blocks.md)). Since 2026-10-29 it works, but it pushes a separate `format/pr-<N>` branch and comments a compare link instead of committing to your branch, so you merge a `format: PR #N` PR back; a PR that touches workflows gets only the patch ([/format push path works](../learnings/1793262748456-slang-format-push-path-works-format-pr-n-branch-me.md)).

## prettier: never --write repo markdown; top-level files are enforced

The design docs use **setext headings** (`Title\n=====`) and **`*emphasis*`**, which the project's pinned prettier preserves; a local prettier (e.g. 3.8.3) converts setext→ATX and `*x*`→`_x_`, so `prettier --write` on repo markdown introduces massive churn. For a targeted docs edit, match the file's style, and prove **format-neutrality**: `prettier <orig> > /tmp/orig-norm; prettier <edited> > /tmp/edited-norm; diff /tmp/orig-norm /tmp/edited-norm` should show only your semantic lines. The local binary is `/pnpm/prettier` (not resolvable via `npx --no-install`). If `origin/master`'s version already fails your local prettier, the divergence is the tool version, not your edit ([docs .md whose baseline fails local prettier: verify format-neutrality](../learnings/1780345737111-editing-a-docs-md-whose-baseline-already-fails-loc.md), [never prettier-write docs/design/*.md](../learnings/1780938587077-slang-ci-pins-clang-format-17-never-prettier-write.md)).

The user-guide docs (`docs/*/09-reflection.md`, `08-compiling.md`, `README.md`) use setext headings, `*` bullets and `*emphasis*` too, and pnpm prettier 3.9.x rewrites them to ATX `#`, `-` and `_emphasis_` (50-130 lines per file). CI stays green on master for these "non-conforming" docs (3+ merged PRs, #11436, #11280, #10594, added to `09-reflection.md`), so trust merged-PR precedent over any local checker, even the CI-pinned prettier@3.3.3, which also flags them ([never run local prettier on whole user-guide docs](../learnings/1785550531048-slang-formatting-sh-markdown-never-run-local-prett.md)). Never run prettier (`formatting.sh --md`) on `docs/user-guide/a4-02-reference-capability-atoms.md`: editing a capdef `///` comment regenerates it via `slang-capability-generator` (slang#12097) ([never prettier the generated capability-atoms doc](../learnings/1784101129985-never-run-prettier-formatting-sh-md-on-the-generat.md)).

**The top-level markdown files are the exception, and they are enforced.** The older aside that `CLAUDE.md`/`CONTRIBUTING.md`/`README.md` are prettier-dirty on master (in [the --cpp no-op atom](../learnings/1784826314203-formatting-sh-silently-no-ops-when-clang-format-is.md)) is stale. #12600 (2026-09-01) changed the dispatch to `((run_all || run_markdown)) && markdown_formatting` (`extras/formatting.sh:444`) with the reformat, so CI's `--check-only` runs prettier, and `npx -y prettier@3 --check CONTRIBUTING.md` passes at master a801f2685 ([correction: CONTRIBUTING.md now passes prettier (#13822)](../learnings/1792607515728-correction-contributing-md-now-passes-prettier-on-.md)). Re-measured 2026-10-22 at `653bfdeef4` with a logging stub `prettier`: a default `--check-only` handed prettier exactly `AGENTS.md`, `CLAUDE.md`, `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `README.md` and `REVIEW.md`, all passing prettier@3.3.3, while 427 of 594 other tracked `.md` files fail it. The six-file scope comes from `list_files`' unquoted `git ls-files $@`, which lets the shell expand `*.md` at the repo root ([git ls-files $@ unquoted narrows a repo-wide pathspec](../learnings/1786023595379-git-ls-files-unquoted-silently-narrows-a-repo-wide.md)). Keep top-level `.md` edits clean with `npx -y prettier@3.3.3 --check <file>`, or Check Formatting fails on a non-draft PR.

## Public headers must be ASCII-only (MSVC C4819); sweep prelude/ too

MSVC emits **C4819** ("character cannot be represented in the current code page") when a consumer compiles a TU that `#include`s a non-ASCII header under a non-UTF-8 charset (`/source-charset:.932`), and `/WX` makes it error C2220, so doc-comment bytes break downstream CP932/Shift-JIS builds (#12016: 3 U+2014 em-dashes in `include/slang.h`, regressed twice, once via the bot's own PR). Detect with `grep -rP '[^\x00-\x7F]'` (must be empty); C4819 needs Windows+MSVC+CP932, so never label it `reproduced` from Linux. Replace with the file's ASCII convention (in slang.h, a spaced ` - `) ([public headers must be ASCII-only](../learnings/1783579004581-slang-public-headers-must-be-ascii-only-msvc-c4819.md)). The shipped #12016 fix extends this: sweep `prelude/` too, since preludes install into `include/` (the fix touched 3 files incl. `slang-cuda-prelude.h`, with em-dashes AND U+2192 arrows); canonical sweep `grep -rP '[^\x00-\x7F]' include/ prelude/`; widen scope when the reporter asks to "review all public headers". A CI guard for this lives in `.github/workflows/**`, policy-rejected for coworker bots, so flag it for maintainers ([ASCII sweep must include prelude/ and arrows](../learnings/1783596951560-slang-non-ascii-header-sweep-must-include-prelude-.md)).

## REUSE license lint: submodule notices and the unused-license trap

Slang uses **REUSE** (`REUSE.toml` + `LICENSES/` + a `reuse-compliance.yml` job running `fsfe/reuse-action`). `reuse lint` does NOT recurse into git submodules, so statically-linked `external/` deps (`cmark` BSD-2, `lz4` BSD-2, `glslang` BSD-3) are outside Slang's annotation and their binary-redistribution notices reach neither `LICENSES/` (no BSD text at HEAD) nor the shipped artifact. Find which deps ship by grepping `source/*/CMakeLists.txt` for `LINK_WITH_PRIVATE`, then read each dep's `COPYING`/`LICENSE` ([REUSE doesn't cover statically-linked submodules](../learnings/1785460293333-slang-third-party-license-attribution-reuse-doesn-.md)). Dropping bare `LICENSES/BSD-2-Clause.txt`/`BSD-3-Clause.txt` in turns `reuse lint` RED: spec 3.3 forbids a license text no *tracked* file references, and the CI checkout has no `submodules:` key, so the submodule's own SPDX tag cannot be that reference (reproduced: exit 1 "unused licenses", exit 0 once a tracked carrier references it) ([bare LICENSES/BSD-*.txt breaks reuse lint](../learnings/1785460805646-slang-12302-bsd-notice-fix-bare-licenses-bsd-txt-b.md), [don't add bare LICENSES/ SPDX texts](../learnings/1785461480820-don-t-add-bare-licenses-spdx-texts-in-a-reuse-repo.md)). Correct pattern (A1): install each dep's OWN notice file via the CMake install `metadata` component, which satisfies the redistribution clause and carries the copyright line a bare SPDX template lacks; add SPDX text to `LICENSES/` (A2) only with a real tracked carrier. `external/cmark/COPYING` is compound (BSD-2 + embedded MIT notices), so shipping its own file covers all of them. Verify the unused-license rule empirically before recommending any `LICENSES/` edit (the `reuse` CLI needs `charset-normalizer`).

## clang -Wformat-security rejects argless printf(fmt); Linux gcc won't catch it

A `printf`-family call with a **non-literal** format and **zero** variadic args (e.g. `reportError("literal\n")` where `reportError(fmt, args...)` forwards to `printf`) is a hard error under clang `-Werror -Wformat-security`, but gcc does not enforce it, so a Linux build is green while macOS/clang CI fails (Slang examples build `-Werror` everywhere). A literal passed through a variadic wrapper counts as non-literal at the inner call, since `fmt` is a runtime `const char*`. Fix: `reportError("%s", "error: ...\n")`. A gcc-only build is blind to clang-only `-Werror` flags (`-Wformat-security`, `-Wreturn-local-addr`), so grep the diff for argless wrapper-`printf` calls; `build-macos-*-clang-aarch64` is the real gate (#12009 lost a round-trip to this) ([clang -Wformat-security rejects argless printf(fmt)](../learnings/1783560312328-clang-wformat-security-rejects-argless-printf-fmt-.md)).

## slang-rhi lint gates differ from the slang compiler

**shader-slang/slang-rhi** gates on **clang-format v20**, an ASCII-only hook and `-Werror`; verify against those, not slang's toolchain ([slang-rhi gates differ](../learnings/1783022365578-slang-rhi-formatting-lint-gates-differ-from-the-sl.md)). The pin is **`v20.1.7`** (`.pre-commit-config.yaml`, `mirrors-clang-format rev: v20.1.7`). The container ships only `clang-format-17`, which reflows pre-existing, untouched signatures (collapses multi-line param lists, moves `override`), churn the pre-commit CI rejects. Install the pin in a venv (`python3 -m venv /tmp/cf-venv; /tmp/cf-venv/bin/pip install clang-format==20.1.7`; system pip is PEP-668-blocked), run `/tmp/cf-venv/bin/clang-format -i <files>`, and verify with `--dry-run --Werror` (exit 0 = clean). Confirm the version from `.pre-commit-config.yaml` first; the control is `--dry-run --Werror` on a file you did NOT touch, which wants changes if your version differs from the one that produced the tree ([slang-rhi pins clang-format v20.1.7](../learnings/1790032890420-slang-rhi-pins-clang-format-v20-1-7-mirrors-clang-.md)).
