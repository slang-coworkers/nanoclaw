# SlangPy AppWindow Presentation: Surface Invalidation, Present-Suppression, and Recovery

The SGL windowing layer that SlangPy ships (`src/sgl/app/app.cpp` + `src/sgl/device/surface.cpp` + `src/sgl/core/window.cpp`, with the RHI boundary in `external/slang-rhi`) has a cluster of subtle behaviors around swapchain invalidation, minimized-window present-suppression, and recovery. A 2026-09 body of work — triage of #1152, the present-suppression gap #1154, and delivery of the recovery fixes #1157/#1160 — mapped where recovery is possible in SGL alone vs. blocked on an upstream slang-rhi change, and captured the app-loop, GLFW-callback, and critique-gate mechanics you need to ship a windowing fix.

## TL;DR

- SGL `Surface::acquire_next_image()` / `present()` THROW via `SLANG_RHI_CALL` on any failure — the `if (!texture) return;` guard in `AppWindow::_run_frame` is DEAD code; acquire never returns null.
- `VK_ERROR_OUT_OF_DATE_KHR` is NOT a typed RHI status — it is debug-logger text folded into the thrown exception message; the underlying RHI `Result` is a bare `SLANG_FAIL`.
- slang-rhi's Vulkan backend collapses recoverable out-of-date AND fatal device-loss into the SAME `SLANG_FAIL` (and treats `VK_SUBOPTIMAL_KHR` as success), so "recover from surface invalidation while PRESERVING device loss" is IMPOSSIBLE in SGL alone — it needs a typed SurfaceStatus / `SLANG_E_*` plumbed through every backend upstream in slang-rhi (NOT the slang compiler; escalate-to-slang-rhi).
- On Vulkan, invalidation is detected on the NEXT `acquireNextImage()`, not on `present()` (present ignores the `vkQueuePresentKHR` return) — drive SGL recovery off the acquire failure (guard present too for D3D/WGPU/CUDA).
- RHI `getConfig()` stays non-null across an out-of-date, so SGL's `config()` guard CANNOT detect invalidation — an SGL dirty flag is required.
- `SGL_THROW` calls `log_fatal` + `platform::debug_break()` BEFORE throwing a plain `std::runtime_error` (no typed SGL exception), so a try/catch around acquire/present for a routine resize emits a fatal log + debugger break every frame — add non-throwing `try_*` Surface variants that return the `Result` instead.
- There is no device-lost query on `rhi::IDevice`; the principled interim is "recovery-as-test" — soften only acquire/present, and rely on the throwing `configure()`/`submit()` paths (NOT `wait()`, which discards `waitOnHost()`'s result and throws nothing on device loss) so real device loss still propagates at reconfigure, plus a bounded consecutive-failure ceiling so a persistent non-throwing failure isn't silently swallowed.
- `AppWindow::_run_frame` gates rendering SOLELY on `if (!m_surface->config()) return;`, and `process_events()` runs first — events stay responsive while minimized with no change. Minimization is handled today only via the zero-extent resize → `unconfigure()` path (PR #331).
- The #1154 gap: on WMs where an iconified window keeps a NONZERO framebuffer extent, the surface stays configured and the loop acquires/presents invisible frames forever — distinct from #331. Fix with a cached `Window::is_minimized()` + `on_iconify(bool)` callback.
- Present-suppression via early-return introduces a 100%-CPU busy-loop (it removes acquire/present's natural pacing) — make `_run_frame` / `App::run_frame` return `bool rendered` (non-short-circuit `rendered |= window->_run_frame()` so every window still pumps events) and `sleep_for(10ms)` in `App::run()` when nothing rendered.
- Minimize detection: `glfwGetFramebufferSize` is NOT reliably 0 while iconified (X11 keeps the retained window size) — use `glfwGetWindowAttrib(GLFW_ICONIFIED)` as the authoritative suspend signal; framebuffer size is for swapchain sizing (and fixes HiDPI under-sizing vs. logical window size).
- `m_width` / `m_height` are the GLFW WINDOW size, not the framebuffer extent — a latent hi-DPI mismatch.
- Adding a Window callback = 6 edits mirroring `on_refresh` (#1133) across window.h, window.cpp, and `slangpy_ext/core/window.cpp` (including the `visitor("on_*")` line in `GcHelper<Window>::traverse` for GC-cycle correctness) + hand-added py_doc.h entries.
- GLFW C trampolines have NO exception boundary — a raising Python callback unwinds through C frames → `std::terminate`; the maintainer accepts this (no try/catch), so keep new callbacks consistent with siblings.
- Window/GLFW APIs can't be unit-tested headlessly (GLFW is X11-forced on Linux, `glfwInit` throws a catchable `RuntimeError` with empty `DISPLAY`) — ship a `hasattr(spy.Window, "is_minimized")` binding-surface test (always runs) + a `@pytest.mark.skipif(not DISPLAY)` construction test (the guard skips BEFORE construction, avoiding the `init_glfw` refcount-corruption path).
- `init_glfw()` has a latent refcount bug: `glfw_ref_count.fetch_add(1)` runs BEFORE `glfwInit()` can throw, so a failed init leaves the counter at 1 with GLFW uninitialized → later window creation skips init.
- Don't make a shared, Python-bound core method throw to fix a narrow case: making `Device::wait_for_idle()` throw cascaded through `~App` (noexcept) → `close()` → `wait()` → `std::terminate` and regressed explicit `close()`. Rest device-loss propagation on the already-throwing `configure()`/`submit()`.
- Delivery: the critique gate needs PLAN_REVIEW + CODE_REVIEW + OUTPUT_REVIEW all recorded before `gh pr create`, and OUTPUT_REVIEW must be `approve` (PLAN_REVIEW must-fix does NOT block). OUTPUT/PLAN_REVIEW read `git diff origin/main..HEAD` (committed state), so COMMIT before reviewing; do NOT edit an attested file after the approve (codex re-hashes at PR-create → stale-deny).
- Read the PINNED submodule (`external/slang-rhi` after `git submodule update --init`), not the differing main-checkout copy, when verifying RHI behavior.
- Surface/GPU behavior is unverifiable headless (slang-rhi surface tests skip without a monitor) — say "no headless end-to-end surface test is available" and gate the draft on a human display checklist; don't claim a test is absolutely impossible.

## The SGL / slang-rhi surface boundary has no typed status

Any surface-recovery work founders on the same fact: recoverable and fatal failures are indistinguishable at the SGL boundary. SGL's `Surface::acquire_next_image()` and `Surface::present()` (`src/sgl/device/surface.cpp:79,96`) both **throw** via the `SLANG_RHI_CALL` macro (`helpers.h:27-34`) on any `SLANG_FAILED` — they never return null gracefully, so the `if (!texture) return;` guard in `AppWindow::_run_frame()` (`app.cpp:146`) is effectively **dead code**. The `VK_ERROR_OUT_OF_DATE_KHR` substring that ad-hoc workarounds grep for is NOT a typed RHI code — it is debug-logger text folded into the thrown message by `build_slang_rhi_error_message` (`helpers.cpp:104-121`); the underlying RHI `Result` is a bare `SLANG_FAIL`. And slang-rhi's `ISurface::acquireNextImage/present` (`external/slang-rhi/include/slang-rhi.h:2968-2969`) return only a `Result` with no typed status — the Vulkan backend (`src/vulkan/vk-surface.cpp:514-526,578-583`) collapses recoverable `VK_ERROR_OUT_OF_DATE_KHR` AND fatal device-loss into the same `SLANG_FAIL` and silently treats `VK_SUBOPTIMAL_KHR` as success. The load-bearing implication: "recover from surface invalidation while PRESERVING device loss" is **impossible in SGL alone** — it requires an **upstream slang-rhi** change (a typed `SurfaceStatus` / `SLANG_E_*` code plumbed through every backend; note each backend has its OWN `ISurface` impl, and CUDA uses a separate VK swapchain+interop, not `vk-surface.cpp`). This is slang-rhi, NOT the slang compiler — so it is escalate-to-slang-rhi, not escalate-to-slang ([VK_ERROR_OUT_OF_DATE is not a typed status; recovery is blocked on slang-rhi](../learnings/1789373197415-slangpy-appwindow-surface-invalidation-vk-error-ou.md)).

A recovery design must NOT rely on `Device::wait()` to catch device loss — it is a no-op on the error path. `Device::wait()` → `wait_for_idle()` calls `m_rhi_graphics_queue->waitOnHost()` and **discards the return value** (`device.cpp` ~1074-1080/1158-1161, not wrapped in `SLANG_RHI_CALL`); since `waitOnHost()` is `SLANG_NO_THROW Result`, a device-lost queue wait returns an error `Result` that is dropped, so `wait()` throws nothing on device loss. In the `reconfigure_surface()` pattern (#1160), the synchronous device-loss surfacing therefore comes ONLY from the throwing `SLANG_RHI_CALL` paths — `Surface::configure()`/`unconfigure()` (`surface.cpp:56,71`) and `submit_command_buffer()` — never from the `wait()` that precedes them (this is why the fix leaves `wait_for_idle` non-throwing). Combined with the untyped `SLANG_FAIL` above, recoverable-out-of-date vs fatal device-loss still cannot be distinguished at the API boundary; the typed fix is the same Phase-2 slang-rhi change ([sgl Device::wait() swallows the RHI result — not a device-loss backstop](../learnings/1789382110721-sgl-device-wait-swallows-the-rhi-result-not-a-devi.md)).

Two further boundary facts sharpen where the SGL-side hook must sit. First, **invalidation is detected on the NEXT `acquireNextImage()`, not on `present()`**: `vk-surface.cpp` `present()` (~395-434) IGNORES the `vkQueuePresentKHR` return value (~line 427) and returns `SLANG_OK` unless the current texture index is -1, while `acquireNextImage()` (~352-393) checks `vkAcquireNextImageKHR` manually (`VK_SUBOPTIMAL_KHR`→success; `VK_ERROR_OUT_OF_DATE_KHR` AND `VK_ERROR_DEVICE_LOST` both → a silent bare `SLANG_FAIL`). So any SGL-side recovery must be driven off the acquire failure, not present — but still guard present for D3D/WGPU/CUDA which may surface it there. Second, RHI base `getConfig()` returns non-null across an out-of-date (only `unconfigure`/failed-configure clears `m_configured`), so **SGL's `config()` guard cannot detect invalidation — an SGL dirty flag is required** ([recovery trigger is the next acquire, and RHI `getConfig()` can't detect invalidation](../learnings/1789373831179-slangpy-appwindow-swapchain-recovery-trigger-is-ne.md)).

## Recovery-as-test: what SGL can do without the upstream change

Because there is no device-lost query on `rhi::IDevice` (`getInfo()`→`DeviceInfo`, `slang-rhi.h ~3143-3168`, is static descriptor data with no health field; the only device-loss signal is `IDebugCallback::handleMessage`, unreliable in release; a Vulkan fence-path device loss trips `SLANG_RHI_ASSERT_FAILURE("Vulkan device lost")` inside RHI), you cannot probe device health directly. The principled interim is **"recovery-as-test"**: soften ONLY acquire/present, and keep `configure()` / `wait()` / `submit()` throwing so a real device loss still propagates at the reconfigure step, plus a bounded consecutive-failure ceiling so a persistent non-throwing failure isn't silently swallowed. Crucially, do NOT wrap acquire/present in a plain try/catch to recover from a routine recoverable resize: `SGL_THROW` throws a plain `std::runtime_error` AND calls `log_fatal(...)` + `platform::debug_break()` BEFORE throwing (`src/sgl/core/error.cpp:30-36`; macro at `error.h:93`), and there is no typed SGL exception subclass — so a catch would emit a fatal log and a debugger break on every routine resize. Prefer adding non-throwing `try_*` variants on `Surface` that call the RHI method directly (skip `SLANG_RHI_CALL`) and return the `Result`, checked with `SLANG_FAILED` in the caller ([`SGL_THROW` is noisy — use non-throwing `try_*` variants; no device-health probe exists](../learnings/1789373831179-slangpy-appwindow-swapchain-recovery-trigger-is-ne.md)).

A related trap: **don't make a shared, Python-bound core method throw to fix a narrow case.** Making `Device::wait_for_idle()` propagate (throw) to guarantee device-loss surfacing cascaded — `App::~App` is `noexcept` → `close()` → `wait()` → `std::terminate` — and regressed explicit `close()`. It was reverted; device-loss propagation rests on the already-throwing `configure()`/`submit()`. Prefer the narrowest change ([don't make `wait_for_idle()` throw to fix a narrow case](../learnings/1789381460302-slangpy-fix-delivery-codex-output-review-reads-ori.md)). The full fix still needs a typed `SurfaceStatus` upstream across all backends.

## Present-suppression: the config() gate, the iconify gap, and the busy-loop

`AppWindow::_run_frame` (`app.cpp ~139-174`) decides whether to render **solely** by `if (!m_surface->config()) return;`, and `m_window->process_events()` is the FIRST statement (~141) — so event pumping is already decoupled from acquire/present, and "keep events responsive while minimized" needs no change. Minimization is handled today ONLY via the zero-extent resize path from PR #331 (merged 2025-07-07): `handle_resize` (~181-192) calls `m_surface->unconfigure()` when width/height == 0, which nulls `config()` and short-circuits the loop. **The gap (#1154):** on platforms/WMs where an iconified window keeps a **nonzero** framebuffer extent, `handle_resize` never sees (0,0), the surface stays configured, and the loop acquires/presents invisible frames forever — which is why #1154 is distinct from #331. As of HEAD `4bf28e5` there was NO `Window::is_minimized()`, NO `glfwSetWindowIconifyCallback`, NO cached iconify state, and NO `glfwGetFramebufferSize` use; `m_width`/`m_height` are the GLFW WINDOW size, not the framebuffer extent — a latent hi-DPI mismatch ([config() gate vs the iconified-nonzero-extent gap (#1154)](../learnings/1789373439634-slangpy-appwindow-present-suppression-config-gate-.md)).

The fix implemented in **PR #1157** (peer-approved, full CI matrix green) added a cached `Window::is_minimized()` + `on_iconify(bool)` via `glfwSetWindowIconifyCallback` plus a native present-suppression guard in `_run_frame` — but naïvely adding `if (is_minimized() || !config()) return;` **introduces a 100%-CPU busy-loop**: the early return removes the natural pacing that `acquire_next_image()`/`present()` provided, so `App::run()` + non-blocking `glfwPollEvents()` spins while minimized. Fix it at the app-loop level: make `_run_frame()` and `App::run_frame()` return `bool` (rendered?) using a non-short-circuit `rendered |= window->_run_frame()` (so every window still pumps events), and have `App::run()` `std::this_thread::sleep_for(10ms)` when nothing rendered. A short sleep beats `glfwWaitEventsTimeout` here because `app.cpp` otherwise has no GLFW dependency (layering), and this also fixes the pre-existing unconfigured-surface spin. For the suspend signal itself, prefer `glfwGetWindowAttrib(GLFW_ICONIFIED)`: **`glfwGetFramebufferSize` is NOT reliably 0 while iconified** (X11 delegates to the retained window size); framebuffer size is for swapchain sizing (and fixes HiDPI under-sizing vs. the logical window size) ([busy-loop trap + minimize-detection](../learnings/1789447175147-slangpy-appwindow-iconify-present-suppression-busy.md), [`glfwGetWindowAttrib(GLFW_ICONIFIED)` is the authoritative iconify signal](../learnings/1789381460302-slangpy-fix-delivery-codex-output-review-reads-ori.md)).

## Adding a Window callback + testing headlessly

The idiomatic way to add a window event/state is to mirror the `on_refresh` addition (slangpy#1133), which copied `on_resize` byte-for-byte — a **6-edit pattern**: `window.h` (typedef + accessor pair + private `handle_*` decl + `m_on_*` member), `window.cpp` (`EventHandlers::handle_*` static C trampoline + `glfwSet*Callback` in the ctor ~`window.cpp:390-399` + `Window::handle_*` dispatcher), and `slangpy_ext/core/window.cpp` (`def_prop_rw` + a matching `visitor("on_*")` line in `GcHelper<Window>::traverse` for GC-cycle correctness), plus hand-added `py_doc.h` entries (the `slangpy_pydoc` mkdoc target is manual and not in the default build; `py_doc.h` is pre-commit-excluded — see the py_doc.h note on the build-and-infra page). **Hazard:** GLFW C trampolines have no exception boundary, so a raising Python callback can unwind through C frames → `std::terminate`; the maintainer accepted this pattern (didn't require try/catch), so keep new callbacks consistent with siblings ([add a callback by mirroring on_refresh; GLFW-trampoline exception hazard](../learnings/1789373439634-slangpy-appwindow-present-suppression-config-gate-.md), [callback = 6 edits + GLFW/refcount/test gotchas](../learnings/1789447175147-slangpy-appwindow-iconify-present-suppression-busy.md)).

Window/GLFW APIs **can't be unit-tested headlessly** — GLFW is X11-forced on Linux (no Null platform) and `glfwInit` fails with a catchable `RuntimeError` when `DISPLAY` is empty. The pattern that satisfies "new Python API needs a test" without flakiness: (1) a binding-surface test that only does `hasattr(spy.Window, "is_minimized")` (always runs, no construction); and (2) a `@pytest.mark.skipif(not os.environ.get("DISPLAY"))` test that constructs a `Window` — the DISPLAY guard skips BEFORE construction on headless CI, so it never drives the `init_glfw` failure/refcount-corruption path. (#1133's `on_refresh` shipped with NO test and was accepted, but codex/reviewers still expect at least the surface test.) Separately, `init_glfw()` (`src/sgl/core/window.cpp`) has a **latent refcount bug**: `glfw_ref_count.fetch_add(1)` runs BEFORE `glfwInit()` throws on failure, so a failed init leaves the counter at 1 with GLFW uninitialized → later window creation skips init and misbehaves (out of scope for a windowing fix, worth a separate issue). Tooling: `pre-commit` isn't on PATH but exists at `/workspace/agent/venv-1130/bin/pre-commit`; clang-format 20.1.7 / black 24.4.2 install cleanly into a venv; and `git push --force-with-lease` fails with "stale info" when the remote-tracking ref wasn't materialized (an explicit-refspec fetch only updates `FETCH_HEAD`) — verify the real remote tip with `git ls-remote origin <branch>`, confirm no third-party pushes, then push with an explicit `--force-with-lease=<branch>:<verified-sha>` ([headless test pattern, init_glfw refcount bug, force-with-lease gotcha](../learnings/1789447175147-slangpy-appwindow-iconify-present-suppression-busy.md)).

## Delivering the fix through the codex critique gate (#1160)

Delivering #1160 (AppWindow surface-invalidation recovery) through the critique gate took 14 codex rounds; the reusable delivery mechanics:

- **The gate requires PLAN_REVIEW + CODE_REVIEW + OUTPUT_REVIEW before `gh pr create`**, not just CODE_REVIEW. The delivery condition is: every required stage recorded (count ≥ 1) AND OUTPUT_REVIEW verdict == `approve`. A must-fix PLAN_REVIEW does NOT block PR creation — only OUTPUT_REVIEW must be `approve`. Run all three (PLAN early, CODE after edits, OUTPUT on the final deliverable) to avoid a late surprise at `gh pr create`.
- **OUTPUT_REVIEW / PLAN_REVIEW read `git diff origin/main..HEAD` (committed state), not your working tree.** Edit after committing and codex reviews the STALE commit and (correctly) flags "the diff still uses X". COMMIT (or amend) your latest edits BEFORE invoking OUTPUT_REVIEW. And codex re-hashes the attested files at PR-create time — do NOT edit an attested file after the approve or the gate denies as stale.
- **Read the PINNED submodule, not the main checkout.** #1160's device-loss facts were mistakenly read from `/workspace/agent/slangpy/external/slang-rhi` (the main checkout, a different commit) while the worktree's pinned submodule differed; the submodule isn't populated in a fresh `git worktree` until `git submodule update --init` (which the build agent runs). Verify RHI behavior against the EXACT pinned commit that builds.
- **Surface/GPU behavior is unverifiable headless** (no Window/Surface without a display; slang-rhi surface tests skip on headless CI — `test-surface.cpp:325 hasMonitor`). State plainly in the PR that device-loss preservation is heuristic + locally unverified and gate the draft on a human display checklist. Don't claim an automated test is "impossible" absolutely — say "no headless end-to-end surface test is available."
- **Meta:** when codex keeps surfacing deeper platform edges in unverifiable territory, it converges if you fix the real ones and correct over-claiming comments/PR wording; the last few rounds here were pure comment/wording accuracy ([codex OUTPUT_REVIEW reads committed state; commit before reviewing; read the pinned submodule](../learnings/1789381460302-slangpy-fix-delivery-codex-output-review-reads-ori.md)).
