# Reviewer-Run Survival & Review-Tool Operational Infra

Keeping reviewer and Devin runs alive, invoking them without false skips, posting, and the critique gate. Related: [approver decision & shadow-mode](review-pr-approver-decision-and-shadow-mode.md), [harvest tiers & verdict reporting](review-pr-harvest-tiers-and-verdict-reporting.md), [runner reliability](agent-infra-f0909b0-codex-and-pr-review-runners.md).

## TL;DR
- **Reviewers fail toward CLEAN** — a dead run can fake success (0/0/0, exit 0); check size/heading/REVIEW-GUARD/per-subagent tool uses/`stream.jsonl` kills before trusting "no findings".
- **The outer turn must outlive its jobs** — turn end/interrupt/restart kills background runs (even `setsid`); re-armed bounded foreground polls; a verdict can ship with `reviewers_complete:false`.
- **Inner-lead orphaning fixed by default** (`CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`); always pass `--max-budget-usd`; on a stub run the missing `.claude/agents/*` lenses yourself; version is not the trigger; re-run `install.sh` after restarts.
- **Teardown (`"killed"` + `[Request interrupted by user]`, `parent_tool_use_id` set) vs budget cut (`error_max_budget_usd`)**; $30 too little for ~700–900 lines: give 45–60, re-dispatch only missing lenses.
- **Recover a stub from `stream.jsonl`/`reviewerA.log` before re-running** (merge can drop a verified crash).
- **Isolate and identify:** private `REPO_ROOT` worktree, run dir from the echo (never newest-mtime); INTEGRITY-FAIL/REVIEW-GUARD false-trips → adjudicate by sha and content.
- **Run scripts from `/home/node/.claude/skills/` via `bash`** (read-only `/app/skills` + missing exec bit fail yet look like success).
- **First Devin exit 3 = "not done yet."** Devin-only tier: retry once; B runs once ungated by `isDraft`; no outer `timeout`; reconcile `devin-page.txt`/`devin-flags.md`; never pre-fill `reviewers_complete:true`.
- **Gate counts only exact `/codex-critique` calls**; DECISION_REVIEW/OUTPUT_REVIEW separate; read PRs via `gh pr view --json`/`gh graphql`, never `gh api .../pulls`.
- **`post-review.sh` has no bot disclaimer** (append first, edit via GraphQL); **fast self-merge is normal** — no escalation on the first silent reping.

## Outer turn: keeping background jobs alive

Background runs die at teardown (`stopped`, run_dir gone, or a <500 B "0 findings" stub) ([#12023](../learnings/1783969636640-approver-reviewer-runs-are-session-teardown-fragil.md); [#12060](../learnings/1783964822172-approver-infra-abstain-pr-merged-undecided-while-r.md) merged undecided). Persist the run-dir path; the deliverable must be ≥500 B and cover the current head ([verify](../learnings/1783971373048-slang-pr-review-verify-reviewer-runs-survived-clea.md)). A terminal event with empty `review/` and no `tmp/decided` is a coverage miss, not an APPROVED join. Escalating on the first silent reping was overruled (2026-07-13) — fast self-merges trip it ([ruling](../learnings/1783965620899-approver-clause-gap-operator-ruling-do-not-escalat.md)).

**Ending your own turn triggers teardown**, so "end your turn after dispatching" is unsafe: the host stops the idle container minutes later (`oom=0`), killing `nohup` jobs — 7 h silent ([#13283](../learnings/1790619062342-slang-reviewer-ending-the-turn-after-dispatching-b.md)), 2× in a row ([#13315](../learnings/1790686802018-container-stops-when-the-turn-ends-keep-long-revie.md)), ~90 s in ([#13328](../learnings/1790712733292-reviewer-background-jobs-die-at-turn-end-keep-the-.md)), an 11 h background wait ([#13541](../learnings/1791764268124-never-end-a-reviewer-turn-on-a-background-wait-for.md)). Dead tasks don't resume. So:
1. Launch with `setsid nohup … < /dev/null &`; stay in the turn doing your own build/drills.
2. Block in bounded foreground loops (600000 ms timeout, polls ≤5 min) or a Monitor, re-armed until every job exits: `end=$((SECONDS+570)); while [ $SECONDS -lt $end ] && ps -p $PID >/dev/null; do sleep 15; done`.
3. Merge in the same turn; remove the orphaned `wt-clarity-*` worktree.
4. If your verification supports a verdict, send it naming reviewers still running; else give an ETA (the verify `build/` survives restarts).

**User interrupts kill `setsid` jobs too** (#13333 R2) ([interrupts](../learnings/1790727232799-user-turn-interrupts-kill-setsid-d-reviewer-jobs-k.md)). Write `review-<N>-my-verification.md` as you go so the verdict can ship with dead reviewers `_skipped: killed by session interrupt_`; afterwards `git status` the verify worktree and rerun the restore build (an interrupted `generate_core_module_headers` leaves a stale module).

**Container restarts also SIGKILL detached A/C runs** — `setsid` doesn't protect across a restart (#14525: rc=125, no exit-status; only B's finished artifacts survived). Tell: `ps` shows your own runtime (opencode/bun) at ~1 min. Recovery is cheap — clones, the master pin, finished run dirs persist — re-dispatch A/C into fresh run dirs (`…-r1-retry1`), keep the dead dirs for forensics [detached reviewer runs die with container restarts](../learnings/1794901762492-detached-reviewer-runs-die-with-container-restarts.md). Dispatch mechanics: `setsid nohup … &` inside a bash tool call hangs that call until its timeout, but the setsid'd process survives the kill — let the call time out, then poll artifacts (#14539) [setsid job survives bash tool timeout](../learnings/1794915713884-detached-setsid-job-survives-bash-tool-timeout-dev.md). The printed `$!` dies with the tool kill; the real detached child is `$!+2` — check `ps -eo pid,args | grep <script-name>` [gh auth status false negative; setsid child PID](../learnings/1794908670329-gh-auth-status-false-negative-under-onecli-proxy-p.md).

## Reviewer A: the inner lead ends its turn

**History.** The inner `claude --print` lead backgrounded 5–7 subagents and ended its turn; print mode has no next turn, so after a 600 s ceiling it killed them, leaving an interim sentence as `final-review.md` (exit 1, `REVIEW-GUARD FAIL: <500 bytes`; signatures: `task_notification` `status: stopped`, `[Request interrupted by user]`, `[RESULT] end_turn`, false 0/0/0). Any diff size — [#12782](../learnings/1789468288728-reviewer-a-empty-final-review-md-on-large-diffs-60.md) 332 B while ~$20 of subagents had found REQUEST_CHANGES, [#13305](../learnings/1790649618844-slang-pr-review-reviewer-a-can-die-silently-set-cl.md), [#13322](../learnings/1790707975468-reviewer-a-patch-mode-inner-orchestrator-can-end-t.md), [#13283](../learnings/1790757776971-reviewer-a-inner-claude-print-kills-background-sub.md), [#12646](../learnings/1790837192079-slang-pr-review-runner-export-claude-code-print-bg.md). The ceiling variable helped but was never baked in ([#13429](../learnings/1791151479459-slang-pr-review-runner-scripts-may-lose-exec-bit-r.md)); on [#13431](../learnings/1791168330129-reviewer-a-inner-cli-can-end-its-turn-with-backgro.md) (2.1.289) the lead still ended its turn — `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` ran the subagents in the foreground, all `completed`.

**Now the default.** `repro.sh` and `run-clarity.sh` both `export CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` (check `grep -n DISABLE_BACKGROUND_TASKS scripts/*.sh`). No wall-clock bound → always pass `--max-budget-usd`.

**Variants.**
- **Silent (exit 0).** #13377's `Run state: success` 1.5 KB `final-review.md` (passing REVIEW-GUARD) was a subagent fragment, all six `killed`: grep `stream.jsonl` for `"status": "killed"`, check for a review heading ([#13377](../learnings/1790895880915-reviewer-a-exit-0-can-still-be-a-silent-kill-check.md)).
- **Late.** Two #13356 runs lost all subagents 17–22 min in: salvage `task_notification`/`result` summaries, report `reviewers_complete=false`; on a small delta use your verification plus the prior review, not a third retry ([#13356](../learnings/1790803785855-reviewer-a-inner-cli-can-be-interrupted-mid-run-17.md)).
- **Early.** A permission denial on a compound `gh pr diff … ; echo …` ends the inner CLI before any subagent (~400 B, exit 0).
- **Orphan.** On 2.1.285 #13284 failed 2× (`killed.system=7`) ([2.1.285](../learnings/1790765591537-reviewer-a-slang-pr-review-runner-breaks-on-claude.md)); #13345 orphaned 3/3 runs (no `"run_in_background":true` in `tool-uses.jsonl`) ([3/3](../learnings/1790792204414-reviewer-a-orphan-is-now-3-3-on-claude-cli-2-1-285.md)). Diagnose: `grep -o '"subagent_stats":{[^}]*}[^}]*}[^}]*}' <run>/stream.jsonl | tail -1`, `"claude_code_version"`. Last parent text saying reviewers "are running in the background" = nothing recoverable: `mv` the dir to `*-INCOMPLETE`, re-run at most once (#13378) ([#13378](../learnings/1790901257688-reviewer-a-background-subagent-orphan-recurs-subag.md)). The version is not the trigger: #13432's early exit recurred on a restored 2.1.289 that had passed that day; restarts wipe `~/.local/bin/claude` (fallback `/pnpm/claude` is 2.1.280). Keep the `claude --version` vs `stream.jsonl` preflight; stop after one early exit ([correction: not the version](../learnings/1791209006651-correction-reviewer-a-early-exit-is-not-caused-by-.md)).
- **Narration-only (guard passes).** The <500 B byte-floor guard is bypassed by narration-only truncation: #14502 r2 completed all subagents and the editorial table, then ended its turn after "Now producing the final review." — 679 B passed. The minimum also passes a message that is only the editorial-table PREAMBLE (#14525-r1-retry1), and compose-and-run's infra guard `grep -qiE 'API Error|socket|rate.?limit'` false-positives on prose mentioning "rate-limit failures" while a complete 11 KB review sits in the dir (#14522-r1). Always `head`-check `final-review.md` for a `**Verdict**` line before merging (re-dispatch ≈ $8–10) ([narration-only truncation passes the 500B guard; rc=125 mid-stream = infra kill, retry once](../learnings/1794845153917-reviewer-a-narration-only-truncation-passes-the-50.md); [detached runs die with restarts; two guard blind spots](../learnings/1794901762492-detached-reviewer-runs-die-with-container-restarts.md)). A small-but-nonzero file is a review only if it starts with the review shape (verdict line / "The complete final review:" / "All reviewer dispatches complete"); otherwise re-run once. Same PR r3: `wait-run` rc=125 with `stream.jsonl` stopping mid-tool-event (no OOM) = infra kill at minute 9 — one re-dispatch worked ([narration-only truncation passes the 500B guard; rc=125 mid-stream = infra kill, retry once](../learnings/1794845153917-reviewer-a-narration-only-truncation-passes-the-50.md)).

**Substitute instead.** Run the `.claude/agents/*` lenses (security, ir-correctness, test-coverage, code-quality) as Agent calls on the head worktree with the diff and REVIEW.md, apply its Step 3 filter, label it "Reviewer A (substitute)", quote A's partial notes, set `reviewers_complete=false`; C plus your verification carry the verdict. A delta re-review needs one code-quality lens (~$3).

## Reviewer A: budget cutoffs on large PRs

**Success can be empty.** On #13363 R2 (~900 lines) all 7 subagents had 0 tool uses and `final-review.md` said "still running", yet `summarize.py` said `Run state: success`: check per-row tool uses and an "incomplete" header ([#13363](../learnings/1791081955973-reviewer-a-on-large-slang-prs-the-30-budget-can-cu.md)). (Its finished lenses still found a real bug.)

**$30 does not cover a large diff; with no wait ceiling the cut moves to the budget.** #13363 and #13541 ended 3/7 short; #13425 (725 lines) lost two to the ceiling then two to the cap; #13564 (heavy IR) stopped 6/7 at ~$25. `final-review.md` then says "Review incomplete" (draft: `slang/tmp/review-candidates/pr-<N>/partial-findings-NOT-FOR-POSTING.md`); finished lenses survive in `task_notification` `<result>`. Give large/heavy-IR PRs 45–60 ([#13425](../learnings/1791132067717-reviewer-a-slang-pr-review-runner-runs-out-of-budg.md), [#13564](../learnings/1792060963846-slang-pr-review-reviewer-a-30-budget-can-stop-6-7-.md)); the [fleet budget table](review-pr-workflow-and-issue-hygiene.md) goes to 120–150 above ~15 files/~2k lines. Close the gap with the missing lenses only (`Agent` with each unreturned `subagent_type`, e.g. `ir-correctness-reviewer`, on a PR-head worktree with the saved diff); keep `reviewers_complete=false`.

## Reviewer A: recovering a stub from stream.jsonl

Under ~1.5 KB is a stub. `<run_dir>/stream.jsonl` is the source of truth (subagent transcripts are deleted, leaving `.meta.json` id→agentType). Recoverable causes:
- **Synthesis never flushed.** Take the last top-level (`subagent_type is None`) `**Verdict**` block; group by `subagent_type` to see finished lenses. Before writing it with a provenance note, confirm no `INTEGRITY-FAIL.txt`, `pr-diff.reference` sha == footer, no review writes, head unchanged ([unflushed](../learnings/1783983883017-slang-pr-review-reviewer-a-600s-bg-wait-ceiling-tr.md)).
- **Subagents finished, lead did not** (also when one dies with "Agent terminated early due to an API error"). Recover lenses from `{"subtype":"task_notification"}` records with `len(summary)>200`, matched by `tool_use_id`; `status:"stopped"` without output is a ceiling hit ([dead lens](../learnings/1789483811315-reviewer-a-final-review-md-can-be-a-truncated-stub.md)). Disclose they are unfiltered; name the missing lens. `reviewerA.log` holds the text untruncated; C's is in `C-<pr>.log` (strip `N\t`); a hand-made #13425 extract cut summaries at 4000 chars — check `awk '{print length}'` ([reviewerA.log](../learnings/1791094754719-reviewer-a-subagent-outputs-recover-full-text-from.md)).
- **Trailing heartbeat.** A Monitor heartbeat read as input can stub a finished review to ~200 B. Recover the earlier top-level turn (`parent_tool_use_id == null`) containing "Here is the complete final review", from `**Verdict**` on, recomputing counts (#13244: 7.4 KB, saved a ~$13 re-run) ([heartbeat](../learnings/1790181801645-reviewer-a-final-review-md-can-be-a-stub-recover-t.md)).

**The merge step can drop a verified crash.** On #11709 R2 a subagent's null-deref SIGSEGV, absent from A's 0-bug review, reproduced (rc=139; E30015 on master): grep summaries and result text for bug/crash/null/SIGSEGV and reproduce hits ([merge](../learnings/1790744483226-reviewer-a-s-merge-step-can-drop-a-subagent-s-veri.md)).

## Concurrent runs on the shared checkout

**Find your run dir** from the runner's echo (A: `>>> final review: <path>`, C: `>>> output → <path>`), never `ls -dt`/`-newermt` (a concurrent or stale run wins). A's `pr-<ts>` lacks the SHA: grep a head-unique token in `pr-diff.reference`. A `bash … ; echo "exit: $?"` wrapper masks exits (Devin's 3 showed 0); read `devin-error.txt` ([echo](../learnings/1790159323514-resolving-a-slang-pr-review-runner-run-dir-under-c.md), [ls -dt](../learnings/1789507730747-slang-pr-review-runner-identify-a-run-dir-from-the.md)).

**False INTEGRITY-FAIL.** With the default `REPO_ROOT=/workspace/agent/slang` the guard re-reads the shared `tmp/pr-diff.patch`/`tmp/context.json`, which concurrent runs overwrite (full recipe: [Reviewer-A integrity & concurrency](review-process-f0909b0-reviewer-a-integrity-concurrency.md)). Launch A with `REPO_ROOT=/workspace/agent/wt-<pr>-revA`, a detached head worktree ([isolate](../learnings/1789053876664-slang-pr-review-runner-concurrent-runs-race-on-sha.md)). If it fires anyway: footer `<sha>` == `headRefOid`, footer `diff sha256` == `sha256sum <run_dir>/pr-diff.reference`, findings cite the PR's files, `summarize.py` drift==0; never delete another run's `tmp/pr-diff.patch` ([four checks](../learnings/1789518412257-concurrent-slang-pr-review-runner-sessions-collide.md)). The CLI often self-heals into `tmp/iso-<pr>-review/pr-diff.patch` while `context.json` stays polluted: use the verified `pr-diff.reference` sha as `diff_hash`, disclose the race ([self-heal](../learnings/1789506920553-slang-pr-review-runner-integrity-fail-can-be-a-fal.md); round-2 probes and bare-repo re-pinning on [concurrent reviewer dispatch limits](review-concurrent-reviewer-dispatch-limits.md))

**Mid-review PR head moves: prestage pins the head.** `prestage.sh` writes `tmp/pr-diff.patch`/`tmp/context.json` (`head_sha`) once at first dispatch; C's later dispatch reuses them, so a head pushed between the A and C dispatches does NOT split the review targets — verify via `sha256sum tmp/pr-diff.patch` vs the A run's `pr-diff.reference` and `context.json`'s `head_sha`. Before re-running reviewers over a mid-review push, verify the delta (`git fetch origin pull/<n>/head` + `git diff <requested-head>..<new-head>`): a comment-only delta leaves every finding applicable — say so in the report header instead of re-running. Reviewer A may `edit` files, but only its own scratch candidates under `<checkout>/tmp/review-candidates/` — check `tool-uses.jsonl` targets before suspecting contamination ([mid-review PR head moves: prestage pins the head](../learnings/1795000278066-mid-review-pr-head-moves-prestage-pins-the-head-ve.md)).

**False REVIEW-GUARD FAIL.** Its `looks like an infrastructure error` check trips on infra wording ("transient API errors", an `exit(-1)` finding): a full Verdict + Findings review is a false trip; a <500 B verdict-less stub is real ([wording](../learnings/1789512038521-slang-pr-review-runner-review-guard-fail-can-false.md)). It also false-positives on "rate-limit failures" in a COMPLETED review's opening sentence (#14522 attempt 3: 11.3 KB real review). Adjudicate, don't re-dispatch: (1) `summarize.py` — authoritative parsed verdict + drift==0 proves completion; (2) verify the provenance line at the bottom of `final-review.md` ("reviewed: <head_sha> · diff sha256 <12>") against a live `gh pr diff | sha256sum` and the prestage `tmp/context.json`; (3) use the review, noting the incident in the header. In an API 429 storm detached runs die three ways: (a) inner subagents killed mid-run — run completes but `summarize.py` shows 0-token agents → partial, re-dispatch; (b) abrupt kill, dead pid, NO exit-status — the launcher was killed → re-dispatch; (c) 429-exhaustion (`api_retry` lines + tiny output) → CLARITY-INCOMPLETE guard → re-dispatch. Setsid runs survive outer-session 429 interruptions but not (b) — re-check `pid`+`exit-status` after any interruption ([REVIEW-GUARD false-positive on rate-limit prose; 429-storm kill shapes](../learnings/1794897242707-review-guard-false-positive-on-rate-limit-prose-42.md)).

**Reviewer C mis-capture.** `clarity-review.md` <2 KB lacking `### `/`## Kept`/`## Review Body` headers (rc=0): the review went to `tmp/` ([tmp/](../learnings/1789573892015-clarity-runner-reviewer-c-can-lose-its-output-to-a.md)) or a trailing meta-message was captured. Recover the largest `## Review Body`/`## Kept` text from `stream.jsonl`; scope the drift grep to command fields (`gh api|--method (POST|PUT|…)|post-github|pulls/[0-9]+/reviews`); a bare `PATCH` matches prompts ([meta](../learnings/1789517911038-slang-clarity-review-runner-can-capture-a-trailing.md)).

**Refute reviewer "harness behavior" claims against the PR's CI tree, not your worktree's base.** GitHub CI builds the merge of the PR branch with CURRENT master, so a local refutation can pass just because your branch predates the master commit that changed the harness (slang#14248 r2: master's #14573 added the slang-test exit-code check the older worktree lacked — the reviewer was right for CI). Before refuting: `git log --oneline HEAD..origin/master`, merge master if nonempty, re-run, prefer the corpus's post-change convention (`TEST:SIMPLE(filecheck=CHECK,exit-code=2)`); master can move under a long-lived PR — re-merge before claiming what CI will see. Post-#14573 slangc returns positive exit codes (CompilationFailed=2); slang-test's `exit-code` accepts only 0/1/2 (`slang-test-main.cpp:3581-3625`) ([refute reviewer harness claims against the CI merge tree](../learnings/1794993700461-refute-reviewer-harness-claims-against-the-ci-merg.md)).

## Runner setup, cited files and posting

- **Where and how.** From read-only `/app/skills` the scripts fail `mkdir -p "$SKILL_DIR/transcripts/..."` in seconds, looking complete: use `/home/node/.claude/skills/<runner>/scripts/` ([writable](../learnings/1789621947264-slang-pr-review-runner-scripts-must-run-from-home-.md)). `gh auth status` 401 ("GitHub is not connected in OneCLI" + connect URL) is a **false negative under the OneCLI proxy**: real `gh` API calls succeed because the proxy replaces the placeholder credential at request time — don't block a preflight or escalate on `gh auth status` alone; probe with one real read (`gh pr view <N> -R <owner>/<repo> --json headRefOid`) first ([gh auth status false negative](../learnings/1794908670329-gh-auth-status-false-negative-under-onecli-proxy-p.md); [Devin fetch via detach.sh](../learnings/1794900109239-devin-fetch-via-detach-sh-gh-auth-status-red-herri.md)).
- **slang-rhi PRs.** Keep `REPO_ROOT` on the slang checkout, pass `--repo shader-slang/slang-rhi --pr <N>`; vendored `external/slang-rhi/` may lag the head, so verify hunks with `gh pr diff` ([slang-rhi](../learnings/1789438594576-slang-pr-review-runner-reviews-slang-rhi-prs-with-.md)).
- **Artifacts and cited files.** Copy `final-review.md`, `clarity-review.md`, `tool-uses.jsonl` to `/workspace/agent/review-<pr>/` at once (`transcripts/` is shared). B via agent-browser can't launch Chrome here (dbus): a deterministic skip. Drop A's findings on files absent from `gh pr view <N> --json files`, keeping any true kernel ([cited](../learnings/1783681518930-verify-reviewer-a-s-cited-files-against-the-author.md)).
- **Posting.** `post-review.sh` POSTs the body verbatim (event=COMMENT) with no bot-transparency disclaimer: append it first ([disclaimer](../learnings/1783665412901-post-review-sh-posts-body-verbatim-no-bot-transpar.md)). REST `PUT /pulls/N/reviews/{id}` 404s under the App token; edit via GraphQL `updatePullRequestReview`, which keeps COMMENTED ([GraphQL](../learnings/1783669185294-slang-pr-review-rest-review-body-edit-404s-under-a.md)).

## Devin infra

**Devin-only tier: retry once.** A first exit 3 usually means Devin is still cold-starting. On the Devin-only tier (bot-authored, harvest exit 20): confirm the head is unchanged, reap Chromium (`pkill -f agent-browser`, clear `/tmp/agent-browser-chrome-*`, delete the stale `devin-error.txt`), retry once wider (`--max-minutes 18 --poll-seconds 45`, #12107) ([#12107](../learnings/1784074357103-approver-infra-abstain-devin-timeout-on-the-sole-s.md), [reap](../learnings/1783993723797-approver-infra-abstain-devin-only-tier-retry-a-tim.md)). Never retry past a `synchronize`; exits 2 (auth wall) and 4 (browser, self-retried) differ. Checkpoint pinned commit and clause/challenger state to `tmp/STATE.md` early. #13425 still timed out thrice ([#13425](../learnings/1791132067717-reviewer-a-slang-pr-review-runner-runs-out-of-budg.md)). On the primary harvest tier Devin is best-effort, a URL-rewrite stall non-blocking: start early, wait ≤~3 min after the primary lands, record `devin: skipped_stall` ([stall](../learnings/1784042688985-approver-infra-abstain-devin-devin-fetch-sh-stall-.md)).

**In `/slang-pr-review`, B runs once** (15-min cap), never retried or gated on `isDraft`: Devin renders for anonymous viewers, drafts included. B runs 2026-09-17..10-13 all failed on a `devin-fetch.sh` done-check defect (fixed in slang-skills #62): on exit 3 read `devin-error.txt` before blaming the PR ([B runs once](../learnings/1791964273446-correction-devin-review-renders-for-anonymous-view.md)). Dispatch B through the runner's `detach.sh` wrapper (`detach.sh /workspace/agent/runs/B-<pr>-r1 -- bash …/devin-fetch.sh --url <devin-url> --out <dir> --max-minutes 15`), poll with `wait-run.sh` — B becomes wait-run-compatible with A and C (rc=0, fresh analysis, #14526) [Devin fetch via detach.sh](../learnings/1794900109239-devin-fetch-via-detach-sh-gh-auth-status-red-herri.md). When re-fetching Devin into the same run dir, `rm` the stale `exit-status` first — completion checks keep reading the previous fetch's code: fetch once (harvests the stale analysis, triggers re-analysis), wait ~9-10 min, `rm exit-status`, re-fetch, then check `devin-commit-status.txt` equals the reviewed head ([mid-review PR head moves; Devin refetch mechanics](../learnings/1795000278066-mid-review-pr-head-moves-prestage-pins-the-head-ve.md)).

## Critique-gate hygiene

The gate records a round only for the exact `/codex-critique` format ([format](../learnings/1783939165247-approver-critique-mustfix-critique-gate-only-recor.md)) keyed to the first stage token, so DECISION_REVIEW and OUTPUT_REVIEW are separate calls; use `reason_code=CLEAN` for WOULD_APPROVE ([separate calls](../learnings/1783978376082-approver-critique-mustfix-output-review-must-be-it.md)). Per-revision `[Approval Decision]` delivery to the dashboard is mandatory, separate from the materiality-gated `[Report]` ([per-revision](../learnings/1783958368120-approver-critique-mustfix-per-revision-approval-de.md)).

`/app/hooks/gate-critique-on-deliver.sh` matches `gh api [^|]*pulls\b`, so read-only GETs trip it; with `edits_since_critique>0` or a stale OUTPUT_REVIEW it denies, and 3 denials hard-block. Diff R2/R1 `review-doc.md` locally, read PR data via `gh pr view <n> --json ...` or `gh graphql`, and never write a file inside a read command (it bumps `edits_since_critique`) ([GET trips](../learnings/1783913716215-approver-critique-mustfix-critique-gate-false-posi.md)).

`reviewers_complete:true` is checked against disk: true only once `devin-flags.md` exists or a bot review was harvested, never before Devin is terminal ([pre-fill](../learnings/1784049951184-approver-critique-mustfix-never-set-reviewers-comp.md)).
