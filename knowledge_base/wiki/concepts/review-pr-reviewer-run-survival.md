# Reviewer-Run Survival & Review-Tool Operational Infra

Keeping reviewer and Devin runs alive, invoking them without false skips, posting, and clearing the critique gate. Decision framework: [approver decision & shadow-mode](review-pr-approver-decision-and-shadow-mode.md); harvested signal: [harvest tiers & verdict reporting](review-pr-harvest-tiers-and-verdict-reporting.md).

## TL;DR
- **Every reviewer fails toward CLEAN.** Check each artifact (size, verdict, exit marker) before reading "no findings" as a result. `summarize.py` reports `Run state: success` and 0/0/0 on an empty or stub file.
- **Background reviewer runs die at session teardown** and look like "0 findings." Ending your turn right after dispatching them is enough (the host stops the idle container; `nohup` does not help, and it is not OOM). Keep the turn alive with re-armed foreground polling loops and merge in the same turn; a relaunched build resumes incrementally from the surviving `build/`.
- **A user interrupt or turn end kills `setsid nohup` jobs too.** Keep your own verification complete and on disk as you go, so a verdict can ship with `reviewers_complete:false` when A/B/C die.
- **Reviewer A's inner `claude --print` lead ends its turn while its subagents run in the background, and print mode kills them** (at the 600 s background-wait ceiling, or silently). The scripts do not set the fix: export `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0` on every `compose-and-run.sh` (and `run-clarity.sh`) launch.
- **Exit 0 is not success.** A silently killed run can leave a >500 B fragment that clears REVIEW-GUARD: grep `stream.jsonl` for `"status": "killed"`/`stopped` and check `final-review.md` opens with a review heading. Also grep per-subagent summaries for crashes the merge step dropped.
- **On claude CLI 2.1.285 the orphan is a broken pipeline (3/3), not a flake.** `install.sh` does not pin the CLI. Re-run at most once with the variable, then substitute direct `.claude/agents/*` lenses with `reviewers_complete=false`; durable fix is pinning 2.1.280.
- **A `final-review.md` of a few hundred bytes to ~1 KB is a stub** (timeout, dead subagent, or a misread trailing heartbeat). Recover from `stream.jsonl` instead of re-running, and set `reviewers_complete=false` when lenses are missing.
- **Resolve your run dir from the runner's own echo, never newest-mtime.** Concurrent runs on the shared checkout race on `tmp/pr-diff.patch` and cause false INTEGRITY-FAIL: confirm by sha matching, and launch every A run in a private `REPO_ROOT` worktree. REVIEW-GUARD FAIL can false-trip on infra wording inside a valid review.
- **Run the runner scripts from the writable `/home/node/.claude/skills/` copy**, not the read-only `/app/skills`, and invoke every one via `bash` (they have lost their exec bit; a by-path call exits 126).
- **A first Devin timeout (exit 3) means "not done yet."** Retry once (clean browser state, delete stale `devin-error.txt`, wider `--max-minutes`) before NO_REVIEW_SIGNAL, and abstain only when Devin is the sole signal.
- **Invoke `devin-fetch.sh` via `bash`** (no exec bit, so a by-path call exits 126) and never inside an outer `timeout` shorter than its `--max-minutes` (exit 124/137 is a false NO_REVIEW_SIGNAL).
- **Reconcile Devin's raw `devin-page.txt` tally against `devin-flags.md`** (the extractor drops Flags). A `devin-commit-status.txt` of "unknown" means verify findings on the pinned head, not abstain.
- **Never pre-fill `reviewers_complete:true`** before Devin reaches a terminal state.
- **The critique gate counts only exact `/codex-critique` calls.** DECISION_REVIEW and OUTPUT_REVIEW are separate calls. Read PR data with `gh pr view --json` or `gh graphql`, not `gh api .../pulls`.
- **`post-review.sh` adds no bot-transparency disclaimer**: append it to `final-review.md` before posting.
- **A fast maintainer self-merge is normal.** Do NOT escalate on the first silent reping (operator ruling).

## Run survival: session teardown

`compose-and-run.sh` and `run-clarity.sh` launched with `run_in_background` are killed at session teardown and come back as `status: stopped` with a possibly-deleted run_dir, which is indistinguishable from "0 findings." Verify the run survived AND cleared its permission guard before trusting its output ([verify reviewer runs survived + cleared the guard before trusting output](../learnings/1783971373048-slang-pr-review-verify-reviewer-runs-survived-clea.md)). A synchronize burst can cost whole review rounds this way (R3 of slang#12023 died with no doc), and a PR can merge undecided while the reviewer doc never returns ([reviewer runs are session-teardown-fragile — a synchronize burst can cost whole review rounds](../learnings/1783969636640-approver-reviewer-runs-are-session-teardown-fragil.md), [PR merged undecided while reviewer doc never returned (slang#12060)](../learnings/1783964822172-approver-infra-abstain-pr-merged-undecided-while-r.md)).

The reviewer's own turn end is a teardown trigger, so the `/slang-pr-review` step "end your turn after dispatching" is unsafe. On slang#13283 the reviewer background-dispatched A, B, C and a build `Agent`, then ended its turn; about 3 minutes later the host stopped the idle container, everything died at once, and no verdict appeared for 7 hours. The dead tasks cannot be resumed, so only a fresh run recovers. Keep the turn alive with a foreground wait chained over several calls (e.g. `timeout 580 bash -c 'until grep -q "A exit=" /tmp/revA.log; do sleep 15; done'`), merge in the same turn, and remove the orphaned `wt-clarity-*` worktree whose cleanup trap never ran ([ending the turn after dispatching background reviewers lets the container get reaped](../learnings/1790619062342-slang-reviewer-ending-the-turn-after-dispatching-b.md)). It recurred twice in a row on PR #13315 (2026-09-29): each time the reviewer ended its turn while A/B/C and a cmake build ran under `nohup`, the container stopped and every job died. It was not memory pressure (`memory.events` showed `oom=0`). Stay in the turn and block in foreground polling loops (e.g. `for i in $(seq 1 28); do <done-check> && break; sleep 20; done` under a 600000 ms Bash timeout), re-armed until every job is done. One mitigating fact: the verify worktree's `build/` directory survives a container restart, so a relaunched `cmake --build` resumes incrementally ([container stops when the turn ends — keep long review jobs in-turn with foreground polling](../learnings/1790686802018-container-stops-when-the-turn-ends-keep-long-revie.md)).

**`nohup` and `setsid` do not protect a job from a turn end or a user interrupt.** On #13328, reviewer jobs started with `nohup … &` died about 90 s in and left only `prompt.txt` and `stream.jsonl`. The relaunch that worked was `setsid nohup … < /dev/null &` with the turn kept open: run your own build and drills meanwhile, then wait in the foreground with a bounded loop (`end=$((SECONDS+570)); while [ $SECONDS -lt $end ] && ps -p $PID >/dev/null; do sleep 15; done`) repeated until the jobs exit. After a re-delivered request, no runner pids in `ps` and no `final-review.md`/`tool-uses.jsonl` in the run dir is the tell ([turn end kills nohup jobs; setsid + keep the turn open](../learnings/1790712733292-reviewer-background-jobs-die-at-turn-end-keep-the-.md)). A user interrupt (`[Request interrupted by user for tool use]`) killed setsid'd A, B and C and an in-flight cmake core-module rebuild, and on #13333 R2 three relaunches under repeated interrupts produced nothing salvageable. Keep your own verification complete and on disk as you go (`review-<N>-my-verification.md` with drill results), so the verdict can ship with `reviewers_complete:false` and each reviewer section marked `_skipped: killed by session interrupt_`; compiler-side drills are stronger evidence anyway. After an interrupt, check `git status` in the verify worktree (drill edits may still be applied) and rerun the restore build, because an interrupted `generate_core_module_headers` can leave a stale core module. Wait in short polls (≤5 min) rather than one 10-minute blocking call ([user interrupts kill setsid jobs; keep verification independent of A/B/C](../learnings/1790727232799-user-turn-interrupts-kill-setsid-d-reviewer-jobs-k.md)).

**Operator ruling.** The slang#12060 learning recommended escalating on the first silent reping. The operator overruled it (2026-07-13): it would fire on every healthy fast self-merge. The failure is real; reping-escalation is not the fix ([operator ruling: do NOT escalate on 1st silent reping (fast self-merge is acceptable)](../learnings/1783965620899-approver-clause-gap-operator-ruling-do-not-escalat.md)).

## Reviewer A stubs and recovery from stream.jsonl

**The background-wait kill.** REVIEW.md tells the inner `claude --print` lead to dispatch its five to seven subagents with `run_in_background` and wait to be notified, so the lead ends its turn with a line like "Waiting for the five background reviewers…". Print mode has no next turn. It waits up to its default 600 s ceiling, logs `Background tasks still running after 600s; terminating. Set CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0 to wait indefinitely.`, and kills the subagents. `final-review.md` is then the lead's last interim sentence and the runner exits 1 with `REVIEW-GUARD FAIL: final review is <500 bytes`. It is an infra kill, not a 0-findings verdict, on ordinary reviews as well as large diffs. On slang#12782 (43 files) a 332-byte file read as 0/0/0 while the subagents (~$20) had found a REQUEST_CHANGES ([empty final-review.md on a large diff is a 600s bg-wait timeout — recover subagents from stream.jsonl](../learnings/1789468288728-reviewer-a-empty-final-review-md-on-large-diffs-60.md)). On slang#13305 a 63-byte stub cost $16 ([Reviewer A can die silently at the 600 s bg-wait ceiling — set CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0](../learnings/1790649618844-slang-pr-review-reviewer-a-can-die-silently-set-cl.md)). On #13322 it hit both pr and patch mode (62–168 bytes, 2/2 patch runs), while a same-day run whose lead kept a Monitor keepalive succeeded ([inner CLI ends before its subagents finish (#13322)](../learnings/1790706807027-slang-pr-review-runner-inner-cli-can-end-before-it.md), [patch-mode lead can end_turn while background subagents run](../learnings/1790707975468-reviewer-a-patch-mode-inner-orchestrator-can-end-t.md)); #13283 on CLI 2.1.283 left 159 bytes ([inner claude --print kills background subagents after 600 s (#13283)](../learnings/1790757776971-reviewer-a-inner-claude-print-kills-background-sub.md)). On #12646 R2 the first run lost all 7 subagents ($18) and the re-run with the variable completed in about 55 min ($24) ([export the variable on every launch; it is not baked into the scripts](../learnings/1790837192079-slang-pr-review-runner-export-claude-code-print-bg.md)).

The runner scripts do not set the variable, and `repro.sh` passes the environment through to the inner CLI, so export it on every launch: `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0 REPO_ROOT=<own worktree> setsid nohup bash …/compose-and-run.sh …` (the #13305 re-run wrote 20 KB). Set it for `run-clarity.sh` too; making it a `repro.sh` default is the durable fix. Signatures in `stream.jsonl`: every `{"subtype":"task_notification"}` record `status: stopped`, `[Request interrupted by user]` on every subagent, a `[RESULT] end_turn` line, and a summarizer report of 0/0/0 that is false. Usually nothing is salvageable. On 2.1.283/2.1.284 the kill is intermittent (same-day runs on the same version succeeded), so it comes from the lead's choice to end its turn, not from a version regression. Detect it with `wc -c final-review.md` plus the REVIEW-GUARD line, and pair the variable with `--max-budget-usd` (no wall-clock bound).

**Exit 0 can still be a silent kill.** On #13377 `compose-and-run.sh` exited 0 with `Run state: success` and no "Background tasks still running" line, yet `final-review.md` (1.5 KB) held a cross-backend subagent's mid-thought fragment. All six subagents were `task_updated status: killed` / `task_notification status: stopped`, and the lead's final `result` said they were "still running in the background". It clears REVIEW-GUARD's byte floor, so after every A run grep `stream.jsonl` for `"status": "killed"` and check that `final-review.md` opens with a review heading ([exit 0 can still be a silent kill: check final-review.md content](../learnings/1790895880915-reviewer-a-exit-0-can-still-be-a-silent-kill-check.md)). The kill can also land late. Two consecutive #13356 runs had every subagent hit `[Request interrupted by user]` 17–22 min in (27 and 221 bytes), while the round-1 run of the same PR completed in about 20.5 min; there is no timeout in `repro.sh`, and the signature matches the background-wait kill above. Salvage the finished subagents' summaries from `task_notification` events and the main-thread `result` events (each narrates which reviewer finished with what), report `reviewers_complete=false`, and on a small delta lean on independent verification plus the previous round's complete review instead of a third retry ([inner CLI interrupted mid-run (~17-22 min); the guard catches it](../learnings/1790803785855-reviewer-a-inner-cli-can-be-interrupted-mid-run-17.md)).

**On claude CLI 2.1.285 the orphan is a broken pipeline, not a flake.** `install.sh` does not pin the CLI. On 2026-09-30 it moved `~/.local/bin/claude` from 2.1.280, where all six subagents completed, to 2.1.285, where #13284 failed twice in a row: `subagent_stats` showed `killed.system=7` (and `killed.parent=4, system=7`), and the 167–427-byte stubs tripped REVIEW-GUARD and INTEGRITY-FAIL ([runner breaks on claude CLI 2.1.285: subagents killed, review is a stub](../learnings/1790765591537-reviewer-a-slang-pr-review-runner-breaks-on-claude.md)). On #13345 three runs out of three orphaned (~$14 each). The third had **zero** `"run_in_background":true` in `tool-uses.jsonl`, so Agent dispatch is effectively asynchronous on this version and prompting the lead to block does not help ([orphan is 3/3 on 2.1.285 even without run_in_background — treat as broken](../learnings/1790792204414-reviewer-a-orphan-is-now-3-3-on-claude-cli-2-1-285.md)). Diagnose with `grep -o '"subagent_stats":{[^}]*}[^}]*}[^}]*}' <run>/stream.jsonl | tail -1` and `grep -o '"claude_code_version":"[^"]*"' <run>/stream.jsonl`. When the final parent text says the reviewers "are running in the background", there is nothing to recover: the `/tmp/claude-*/tasks/*.output` symlinks point at `~/.claude/projects/-workspace-agent-slang/<sid>/subagents/agent-*.jsonl`, which hold only `.meta.json` stubs, and each subagent's last text is a one-line "Let me check…". `mv` the run dir to `*-INCOMPLETE` and re-run at most once with the variable set (#13378: 6 killed, $17.49, 14 min) ([orphan recurs; subagent jsonl absent; quarantine + one re-run](../learnings/1790901257688-reviewer-a-background-subagent-orphan-recurs-subag.md)). If that also orphans, stop rerunning. Run the `.claude/agents/*` lenses (security, ir-correctness, test-coverage, code-quality) directly from the coordinator as ordinary Agent calls on the head worktree plus the full diff and REVIEW.md, apply REVIEW.md Step 3's filter yourself, label the section "Reviewer A (substitute, not the byte-equivalent pipeline)", and set `reviewers_complete=false`. A delta re-review needed only one delta-scoped code-quality lens (~$3) ([orphan recurs back-to-back on 2.1.285 — substitute direct lenses](../learnings/1790786024623-reviewer-a-background-subagent-orphan-recurs-back-.md), [orphan is 3/3 on 2.1.285](../learnings/1790792204414-reviewer-a-orphan-is-now-3-3-on-claude-cli-2-1-285.md), [patch-mode workaround: dispatch REVIEW.md lenses from the outer session](../learnings/1790707975468-reviewer-a-patch-mode-inner-orchestrator-can-end-t.md)). Durable fixes: pin the CLI (2.1.280) in `install.sh`, or have `repro.sh` wait for task notifications before extracting.

Three stub causes share one source of truth, `<run_dir>/stream.jsonl`:
- **Timeout.** The main agent's synthesis is often in the stream, never flushed: take the last top-level (`subagent_type is None`) block containing `**Verdict**`, and group by `subagent_type` to see which lenses finished. Check no `INTEGRITY-FAIL.txt`, `pr-diff.reference` sha matches the footer, zero review writes, head unchanged; then write it out with a provenance note and `reviewers_complete:false` ([Reviewer A 600s bg-wait ceiling truncates final-review.md — recover from stream.jsonl](../learnings/1783983883017-slang-pr-review-reviewer-a-600s-bg-wait-ceiling-tr.md)).
- **Dead subagent.** A subagent dying mid-run ("Agent terminated early due to an API error", 0 tools/0 tokens) can end the run without synthesis, leaving a ~1 KB intermediate turn ("Waiting for the final reviewer (code-quality)") while summarizer and artifact monitor report done; a normal file is ~8-12 KB. With at least 5/6 lenses done, recover each from `{"subtype":"task_notification"}` records with `len(summary)>200` (a dead lens has `status:"stopped"`). The reports are unfiltered, so set `reviewers_complete=false`, disclose the truncation and name the missing lens ([final-review.md can be a truncated stub — verify size, recover lenses from stream.jsonl task_notifications](../learnings/1789483811315-reviewer-a-final-review-md-can-be-a-truncated-stub.md)).
- **Trailing heartbeat.** A completed review can stub to ~200 bytes when the CLI reads a trailing Monitor heartbeat as leftover input and ends with "The final review is already complete and delivered above…", which becomes the artifact (the last top-level turn). Recover the earlier top-level turn (`parent_tool_use_id == null`) containing "Here is the complete final review", from `**Verdict**` onward, and recompute the counts; #13244 recovered 7.4 KB from turn 26 of 28 instead of a ~$13 re-run [Reviewer A final-review.md can be a stub — recover the real review from stream.jsonl](../learnings/1790181801645-reviewer-a-final-review-md-can-be-a-stub-recover-t.md).

**The merge step can drop a verified crash.** `final-review.md` can report 0 bugs while a domain subagent reported a crash at the confidence bar. On #11709 R2 the IR/security subagent reported a null-deref SIGSEGV that A's merge left out, and it reproduced (rc=139 on the PR, clean E30015 on master). After `summarize.py`, grep the per-subagent summary column and the subagent result text in `stream.jsonl` for "bug", "crash", "null" and "SIGSEGV", and reproduce any hit before trusting A's counts ([Reviewer A's merge step can drop a subagent's verified crash](../learnings/1790744483226-reviewer-a-s-merge-step-can-drop-a-subagent-s-veri.md)).

## Concurrent runs on the shared checkout

**Find your own run dir** from the runner's echo, not `ls -dt` (a stale dir with a leftover `final-review.md` wins newest-mtime): A prints `>>> final review: <path>`, C prints `>>> output → <path>`. A dir with `stream.jsonl` but no `final-review.md` is still running or not yours. The outer `bash … ; echo "exit: $?"` wrapper masks the real exit (a Devin exit 3 showed as 0), so read `devin-error.txt` [Resolving a slang-pr-review-runner run_dir under concurrent reviews — use the script's own echo, not newest-mtime](../learnings/1790159323514-resolving-a-slang-pr-review-runner-run-dir-under-c.md). C's dir name embeds the head SHA (`pr-pr<N>-<headsha>-<bundlehash>-…`) and self-disambiguates; A's `pr-<ts>` does not, so check a head-unique token in `<dir>/pr-diff.reference` ([identify a run dir from the bg log's "output →" line, not ls -dt](../learnings/1789507730747-slang-pr-review-runner-identify-a-run-dir-from-the.md)).

**False INTEGRITY-FAIL.** `compose-and-run.sh` defaults `REPO_ROOT=/workspace/agent/slang`, and its end-of-run guard re-reads the shared `$REPO_ROOT/tmp/pr-diff.patch` and `tmp/context.json`, which a concurrent run overwrites; the guard then exits 1 naming a different PR although the review is correct. The full adjudication and isolation recipe lives on [Reviewer-A integrity & concurrency](review-process-f0909b0-reviewer-a-integrity-concurrency.md). In short: launch every A run with `REPO_ROOT=/workspace/agent/wt-<pr>-revA` (a `git worktree add --detach` of the head or origin/master; the `wt-<pr>-<tag>` name lets supervise-issues GC reap it) ([concurrent runs race on shared REPO_ROOT tmp/pr-diff.patch → false INTEGRITY-FAIL; isolate in a worktree](../learnings/1789053876664-slang-pr-review-runner-concurrent-runs-race-on-sha.md)). When it fires anyway, run the four checks: footer `<sha>` == `headRefOid`, footer `diff sha256` == `sha256sum <run_dir>/pr-diff.reference`, findings cite the PR's files, `summarize.py` drift==0. The CLI often self-heals into `tmp/iso-<pr>-review/pr-diff.patch` while `context.json` stays polluted, so use the verified `pr-diff.reference` sha as `diff_hash` and disclose the race ([INTEGRITY-FAIL confirmation recipe + tmp/iso-<pr>/ self-heal](../learnings/1789506920553-slang-pr-review-runner-integrity-fail-can-be-a-fal.md)). Never delete a concurrent run's `tmp/pr-diff.patch` ([concurrent A-sessions collide on tmp/pr-diff.patch → false integrity guard; confirm via four checks, don't delete the other's file](../learnings/1789518412257-concurrent-slang-pr-review-runner-sessions-collide.md)).

**False REVIEW-GUARD FAIL.** `final review looks like an infrastructure error` trips on infra wording inside a valid review (a note that passes "terminated on transient API errors", findings about `exit(-1)`). A full Verdict + Findings review is a false trip; a <500-byte stub with no verdict is real ([REVIEW-GUARD FAIL false-trips on infra-error wording inside a valid review](../learnings/1789512038521-slang-pr-review-runner-review-guard-fail-can-false.md)).

**Reviewer C mis-capture.** `clarity-review.md` can come out tiny (<2 KB, no `### `/`## Kept`/`## Review Body` headers, rc=0) because the model wrote the real review to a `tmp/` path ([clarity-runner can lose its output to a tmp/ file — recover the Write tool_use from stream.jsonl](../learnings/1789573892015-clarity-runner-reviewer-c-can-lose-its-output-to-a.md)) or because a trailing meta-message was captured. Recover from `stream.jsonl` (the largest assistant text with `## Review Body`/`## Kept`, or the candidates-file `Write` tool_use) and note the provenance. A bare `(POST|PUT|PATCH|DELETE)` drift grep hits "PATCH" in dispatch prompts; scope it to command/name fields (`gh api|--method (POST|PUT|…)|post-github|pulls/[0-9]+/reviews`) ([clarity-review.md can capture a trailing meta-message — recover the real body from stream.jsonl](../learnings/1789517911038-slang-clarity-review-runner-can-capture-a-trailing.md)).

## Runner setup, cited files and posting

- **Where to run from.** Use `/home/node/.claude/skills/<runner>/scripts/`. From read-only `/app/skills` both scripts fail `mkdir -p "$SKILL_DIR/transcripts/..."` and exit 1 within seconds, which looks like a fast completion; read the log tail. `gh pr view/diff` on a public repo works read-only even when `gh auth status` calls the token invalid ([slang-pr-review runner scripts must run from /home/node/.claude/skills (not /app/skills — read-only)](../learnings/1789621947264-slang-pr-review-runner-scripts-must-run-from-home-.md)). The runner scripts (`slang-pr-review-runner/scripts/*.sh`, `run-clarity.sh`) have lost their exec bit (mode 664 after an edit), so a by-path call exits 126 with `Permission denied`; invoke them as `bash <script>` ([patch-mode lead can end_turn; scripts lost exec bit](../learnings/1790707975468-reviewer-a-patch-mode-inner-orchestrator-can-end-t.md), [orphan recurs; runner scripts exit 126 without bash](../learnings/1790901257688-reviewer-a-background-subagent-orphan-recurs-subag.md)).
- **slang-rhi PRs.** Keep `REPO_ROOT=/workspace/agent/slang` (REVIEW.md, the six subagents, the clarity skills) and pass `--repo shader-slang/slang-rhi --pr <N>`. The vendored `external/slang-rhi/` gives the subagents real source; the pinned submodule may lag the PR head, so verify hunks against `gh pr diff` ([reviews slang-rhi PRs with real source via vendored external/slang-rhi](../learnings/1789438594576-slang-pr-review-runner-reviews-slang-rhi-prs-with-.md)).
- **Artifacts and cited files.** Copy `final-review.md`, `clarity-review.md` and `tool-uses.jsonl` into `/workspace/agent/review-<pr>/` at once; the shared `transcripts/` dir gets clobbered. Reviewer B via agent-browser cannot launch Chrome here (dbus), a deterministic skip. Reviewer A can cite test files not in the PR: check the authoritative file list (`gh pr view <N> --json files`, per the gate rule below), drop findings on absent files, keep the true kernel (e.g. "no regression test" on a 0-test PR) ([verify Reviewer A's cited files against the authoritative PR file list](../learnings/1783681518930-verify-reviewer-a-s-cited-files-against-the-author.md)).
- **Posting.** `post-review.sh` POSTs the body verbatim (event=COMMENT) and neither it nor `final-review.md` adds the bot-transparency disclaimer ([post-review.sh posts body verbatim — no bot-transparency disclaimer](../learnings/1783665412901-post-review-sh-posts-body-verbatim-no-bot-transpar.md)). Append it to `final-review.md` before posting. REST `PUT /pulls/N/reviews/{id}` returns 404 under the App token, so a later edit needs the GraphQL `updatePullRequestReview` mutation, which keeps the state COMMENTED ([REST review-body edit 404s under App token; use GraphQL updatePullRequestReview](../learnings/1783669185294-slang-pr-review-rest-review-body-edit-404s-under-a.md)).

## Devin infra

**Retry once before abstaining.** A first exit-3 timeout usually means Devin is not finished (often a fresh PR racing cold start). On the Devin-only tier (bot-authored, harvest exit 20), confirm the head has not moved, delete the stale `devin-error.txt`, and retry once with `--max-minutes 18 --poll-seconds 45`; on #12107 that returned a full analysis. Never retry past a `synchronize`. Exit 2 (auth wall) and exit 4 (browser launch, self-retried) differ ([Devin timeout on the sole-signal Devin-only tier: retry once](../learnings/1784074357103-approver-infra-abstain-devin-timeout-on-the-sole-s.md)). Reap an orphaned Chromium (`pkill -f agent-browser`) and clear `/tmp/agent-browser-chrome-*` before retrying; on the primary harvest tier Devin is best-effort and needs no retry. **Invocation.** `devin-fetch.sh` ships without its exec bit, so a by-path call dies with exit 126, a false Devin-skip; invoke it as `bash devin-fetch.sh` ([devin-fetch.sh missing exec bit false-skips Devin](../learnings/1783997801258-approver-devin-fetch-sh-missing-exec-bit-false-ski.md)). ## Critique-gate hygiene

The gate records a round only when the codex call uses the exact `/codex-critique` format ([critique gate only records a round when the codex call uses the exact /codex-critique format](../learnings/1783939165247-approver-critique-mustfix-critique-gate-only-recor.md)). DECISION_REVIEW and OUTPUT_REVIEW must be separate calls because the tracker keys each round to the first stage token; use `reason_code=CLEAN` for WOULD_APPROVE ([OUTPUT_REVIEW must be its own codex call; reason_code=CLEAN for WOULD_APPROVE](../learnings/1783978376082-approver-critique-mustfix-output-review-must-be-it.md)). Per-revision `[Approval Decision]` delivery to the dashboard is mandatory and separate from the materiality-gated upstream `[Report]` ([per-revision [Approval Decision] delivery is mandatory (dashboard)](../learnings/1783958368120-approver-critique-mustfix-per-revision-approval-de.md)).

`/app/hooks/gate-critique-on-deliver.sh` matches `gh api [^|]*pulls\b`, so it fires on read-only GETs too, and denies when that coincides with `edits_since_critique>0` or a stale OUTPUT_REVIEW; 3 denials hard-block. Answer "did the review change" from local artifacts (R2 vs R1 `review-doc.md`), read PR data with `gh pr view <n> --json ...`, and never write a file in the same command as a read (it bumps `edits_since_critique`) ([critique gate false-positives on read-only gh api .../pulls GETs — don't burn denial strikes](../learnings/1783913716215-approver-critique-mustfix-critique-gate-false-posi.md)). `reviewers_complete:true` is a harness-integrity assertion the gate checks against disk, true only when `devin-flags.md` exists or a bot review was harvested, so never pre-fill it before Devin reaches a terminal state ([never set reviewers_complete:true before Devin reaches a terminal state](../learnings/1784049951184-approver-critique-mustfix-never-set-reviewers-comp.md)).
