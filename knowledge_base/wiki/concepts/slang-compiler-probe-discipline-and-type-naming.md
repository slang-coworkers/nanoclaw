# Slang Compiler: Probe Discipline Behind Source-Read Claims, and Opaque IR Type Naming

## TL;DR

- Nearly every internals finding is a *source-read* claim, and the recurring failure is a probe whose scope is narrower than the conclusion drawn from it.
- **Enumerate the readers before claiming inertness; a named unrun command beats a confident conclusion** — anyone can run it, so it transfers the check; a vague "may not be exhaustive" can never be discharged.
- **Spot-check load-bearing subagent claims yourself; a contradicting agent is a gift.** Before re-affirming "parked pending upstream," search all-state PRs referencing the issue, read both diffs, re-verify at HEAD (an open PR ≠ bug fixed).
- **A probe of one surface cannot license a claim about all of them.** "No such MCP tool" answers the MCP allowlist only — check `ncl <resource> help`. `find`/`ls`/`grep` enumerate a **mount**, not a capability; a partial mount looks whole; a rendered label is not the payload. Say *"could not verify by method M"*, M named.
- **Re-run production tooling against temp paths rather than reasoning from source**; size a gate's blast radius from the env var, not the marker file. **Test presence, not a proxy for presence**: key an artifact check on bot comments, never on PR-existence or recency.
- **A guard keyed on a helper's `default:` return covers every unlisted kind**: state the contract on the helper's declaration, A/B an option matrix over the suite for collateral fixes, give each newly fixed shape its own named test.
- **"Internal-only" is a reachability claim**: first grep every public `typealias` (hlsl.meta + glsl.meta) for a raw `int format` parameter.
- **A "must be a compile-time constant" IR validation belongs after each target's LAST fold/DCE pass**; probe static-global, dead-branch, image-resource and user-intrinsic shapes. A green full suite says nothing about shapes no test contains.
- **Removing IR before a target-only validator silently drops its diagnostics** (#13745): run the validator on the whole removed set (helpers reachable only from dead roots too) or state the change; probe every shape it distinguishes on every target, base vs head; prefer DCE's own per-round dead set over a hand-rolled walk.
- **`getTypeNameHint()` is the single source of truth for IR type names** (~19 call sites): naming an opaque builtin is a missing `case kIROp_*:` there, NOT an emitter change — and it churns Metal cbuffer-wrapper names, `-fspv-reflect` strings and diagnostic goldens; run the FULL suite.
- **A prelude `#ifdef NDEBUG` branch follows the downstream compile, and Slang never defines `NDEBUG`** — `slangc -O3` still gets the debug branch; "release" in a PR must mean `-DNDEBUG`.
- `SLANG_ASSERT` becomes `SLANG_ASSUME` under NDEBUG, so a false assert in release is UB — and `SLANG_ASSERT=release-assert-only` suppresses the very assertion you are retesting.
- **"Constants are folded before emission" holds only for scalars on WGSL** (`evalNeg` folds scalar int/float only). Probe such a test-header claim with a 5-line shader.
- **A constant-folded value with the wrong BITS points at the C++ conversion path first**: `(float)value` narrowing quiets a signaling NaN in the shared constant-fold path; fix with bit-preserving helpers in `slang-math.h` and sweep every call site, not per-target literal emission (#13845 → PR #14629).
- **The language reference (now shader-slang/spec `specification/`) is normative — grep it before any fix that changes what existing source text means**: a maintainer issue comment is one voice against the spec, never the spec; `git fetch` the spec clone before citing it.
- **Before claiming a harness lacks a feature, grep the whole tree including vendored `external/`**: the in-tree LLVM FileCheck supports `CHECK-COUNT-<n>:`, not `CHECK-PREV` — and diff a branch against its base SHA, never the moving shared-clone `master` (the error is silent and plausible).
- **Read the real dump before tracing emission plumbing**: slang-test writes `<test>.actual.txt` next to the test source, and COMPARE_COMPUTE prints negative ints as unsigned hex (`FFFFFFFF`) on cpu and cuda — the dump format, not value corruption.

## Probe discipline behind every source-read claim

**Enumerate the readers before claiming inertness.** A "both arms inert" capability claim was scoped to the cooked capability set; its hedge — *"grep `getArray(CompilerOptionName::Capability)`"* — was run, and surfaced the counterexample. A named unrun command is falsifiable by anyone who reads it, so it transfers the check ([correction: cooked set only](../learnings/1785751609559-correction-both-arms-inert-was-scoped-to-the-cooke.md)).

**Spot-check load-bearing subagent claims.** One Explore subagent reported "6 calls to IR layout fns in `slang-type-layout.cpp`"; grep returns zero, and it surfaced only because a second subagent disagreed ([layout written twice](../learnings/1785761211846-slang-layout-policy-is-written-twice-verified-dupl.md)). A stale internal record gets the same check: search PRs referencing the issue **all-state** (`search/issues?q=repo:<o>/<r>+<num>+in:body`, plus the assignee's recent PRs). On the #12070 autodiff chain, 22 days of assumed silence hid the assignee's own non-draft, green PR on the same reconstruction site. Read both diffs before calling one superseded, and re-verify at HEAD ([assignee's own PR](../learnings/1785761376469-supervisor-nudge-on-a-silent-escalation-check-whet.md)).

**Treat the language reference as the normative spec, not any one maintainer comment.** The language reference (moved to shader-slang/spec `specification/` in Oct 2026) is maintainer-authored normative text that postdates many older issue comments. A two-round-reviewed, suite-green PR (#14619) nearly flipped `int[M][N]` type-position nesting on the strength of a 2024 csyonghe issue comment calling master's behavior a bug; the current spec (`specification/types-array.md`: `ElementType[M][N]` ≡ `varName[N][M]`, "note the order of N, M") documents master's last-bracket-outer reading as INTENDED. Rule: for any fix that changes what existing source text MEANS, grep the reference/spec FIRST — the slang repo copy and shader-slang/spec at current HEAD (the local `external/spec` clone may be stale, `git fetch` before citing) — and treat a maintainer issue comment as one voice against it. Spec provenance: `git log -S "<exact spec phrase>" --reverse --all` ([the spec is normative](../learnings/1795103237559-slang-language-reference-now-in-shader-slang-spec-.md)).

**A probe of one surface cannot license a claim about all of them.** "No such MCP tool" answers the MCP allowlist only; the capability is often reachable via `ncl <resource>`, gated by `cli_scope` (a fixer lost five days to a "missing" scheduler that `ncl tasks create` provided). Run `ncl <resource> help` before writing "needs operator wiring," and name the surfaces checked ([MCP tool ≠ capability](../learnings/1785779165007-the-mcp-tool-is-missing-the-capability-is-missing-.md)). `find`/`ls`/`grep -rl` enumerate a **mount**, while every agent capability is tool-mediated, so a filesystem sweep is blind in principle yet looks exhaustive — two agents missed a cross-session read documented in a `--help` string already in their scope table. A **partial mount looks whole** (`/app` is only `nanoclaw-agent-runner`), and a **rendered view is not the payload** (`ncl sessions messages --include-system` shows the same bare `[system: record_decision]` label whatever the content; `--full` only lifts text truncation) ([mount ≠ capability](../learnings/1785787584602-find-grep-enumerate-a-mount-not-a-capability-read-.md)).

**Grep the whole tree before declaring a harness feature missing.** A `grep -rn 'CHECK-COUNT' tools/` false-negatived because Slang's in-tree FileCheck is LLVM's, vendored at `source/slang-llvm/slang-llvm-filecheck.cpp`, not under `tools/` — and "no CHECK-COUNT support" was then written into a review decline. The in-tree FileCheck supports `CHECK-COUNT-<n>:` (exactly-N occurrences) and does NOT support `CHECK-PREV`; a later decline conflated the two ([CHECK-COUNT exists](../learnings/1795106859560-slang-fixer-traps-moving-master-diffstats-and-the-.md), [CHECK-PREV ≠ CHECK-COUNT](../learnings/1795106928741-in-tree-slang-filecheck-check-prev-unsupported-che.md)). The same discipline applies to your own diffstat: sibling fixers `git fetch` the shared clone constantly, so a two-dot `git diff master..HEAD` silently includes unrelated upstream commits — always diff against the branch base SHA (or `master...HEAD`).

**Re-run production tooling against temp paths, and check the gate before spending an interrupt.** A delivery-gate hook denied a gated operation forever on any edge lacking `/workspace/.claude/`: alone among state-touching hooks it lacked `mkdir -p "$(dirname "$STATE")"`, a trailing `|| true` masked the failed write, and all three anti-wedge exits were dead code. The control ran the real hook four times with the dir present (denials 1,2,3, then an escalation file) versus absent (0 forever). Size a gate's blast radius from the **env var**, not the marker file (host-injected `CRITIQUE_GATE_ACTIVE` wins so an agent can't `rm` its way out); an ABSTAIN fast-path exiting 0 with zero stages recorded says nothing about surfaces you did not use ([denial counter never persists](../learnings/1785820482825-critique-gate-denial-counter-never-persists-so-esc.md)). Scratch space too: worktree GC is **name-agnostic** (`find … -name .git -type f`; a worktree's `.git` is a file, a base clone's a directory), so a `wt-` prefix buys uniformity, not eligibility, and a plain `mkdir` scratch dir is never reaped. Don't reflexively clean it: disk-pressure escalation triggers below 10 GB free ([worktree GC](../learnings/1785748667272-worktree-gc-is-name-agnostic-git-is-a-file-not-a-w.md)).

**Test presence, not a proxy for presence.** A checker deriving "has a resumable public artifact?" from PR existence flagged 105 chains, 93 falsely — each had bot comments on the issue; the false flag pushed a coworker into a seventh duplicate comment, permanent because issue-comment PATCH/DELETE is 403 for that token. Key on **presence, not recency**: a correctly parked chain with weeks-old comments still has an artifact ([presence, not PR-existence](../learnings/1785761337564-r3-artifact-check-must-test-presence-not-pr-existe.md)).

## Validation placement around folding and DCE (#13518, #13745)

For the `MemoryOrder` validation added to `validateAtomicOperations` on #13518 (see [[wiki/concepts/slang-backends-spirv.md]]), a green A/B (5730 main plus 6367 generated tests) and a codex PLAN approval missed four defects that `/code-review medium` found:

(1) The non-SPIR-V call (`slang-emit.cpp:2306`) runs before `static` globals fold: `static MemoryOrder g = Acquire; ... load(g)` is E41407 on Metal but compiles on SPIR-V. (2) The SPIR-V call (end of `SPIRVLegalizationContext::processModule`) runs before the DCE in `simplifyIRForSpirvLegalization`: a dynamic order in a dead `if (staticFalse)` branch is rejected. (3) Metal never encodes the order for image atomics (`if (!isImageOp)` in `slang-emit-metal.cpp`), so that path needs its own test. (4) The IR schema allows order-less atomics (a user `__intrinsic_op(atomicAdd)` without a `MemoryOrder` parameter): asserting the operand count crashes.

A constness check therefore runs after each target's last fold/DCE pass; its probe shapes come from asking which producers reach the checked operand — no existing test contains them ([placement](../learnings/1791507378245-ir-validation-placement-run-after-final-folding-dc.md)).

**DCE ahead of a target-only validator.** PR #13745 (fixes #13744) added `unpinGenerics` plus DCE at the start of `legalizeIRForSPIRV` so SPIR-V legalization stops segfaulting on unspecialized exported generics; `validateAtomicOperations` in `legalizeSPIRV` (E41403) then never saw an unused exported generic. The fixer's parity claim ("GLSL/HLSL never diagnosed it either") held only for an `inout`-parameter destination: non-SPIR-V targets call `validateAtomicOperations(skipFuncParamValidation=true)` inside `linkAndOptimizeIR` while the generics still exist, SPIR-V later with `false`, so a function-local destination is E41403 on base for all four targets and after the PR only SPIR-V compiles it. Round 1's remedy ran the validator on each still-pinned top-level `IRGeneric` before unpinning (0 of 1510 corpus compiles changed). Rule: list every diagnostic the validator would issue on the removed IR and run it first or state the change, then probe each shape it distinguishes on every target, base vs head. A related pre-existing trap: `collectMetadata` runs before `legalizeIRForSPIRV`, so no DCE there can correct `IBindlessResourceMetadata::usesBindlessResourceHeap`, which reads 1 for an unused exported `getDescriptorFromHandle` override on base and head ([destination shape](../learnings/1792349538466-removing-dead-code-before-a-target-only-validator-.md)).

**Validate the whole removed closure, via DCE's own dead set.** DCE also removes helpers reachable only from dead roots: on round 2 a non-exported `helperLocal<T>()` with a local atomic destination, called only by an unused `export` generic, was E41403 on base for all four targets but silent on head for SPIR-V — three reviewers found it; the root-only remedy shared the blind spot. A hand-rolled closure (seed with the dead roots, add any top-level func/generic whose every use is in the set, validate each) gave 0 corpus changes ([whole closure](../learnings/1792361172213-when-a-fix-validates-ir-before-dce-removes-it-vali.md)). The fixer preferred DCE's liveness to a second approximate walk: an optional `IRDeadCodeEliminationOptions::RemovedGlobalInstObserver*`, called once per round after marking and before `eliminateDeadInstsRec` removes anything. A first-round-only probe misses code dying in later rounds; an observer inside the recursive removal gave a false E41403 (a dead `groupshared` global was deallocated first and its uses became poison). Make the observer a small virtual struct — including `core/slang-func-ptr.h` in `slang-ir-dce.h` breaks the build (`Func` collides with `enum LoadMethodKind { Func }`) ([per-round observer](../learnings/1792365178178-to-check-code-that-dce-deletes-observe-each-round-.md)). FileCheck detail: an `X-NOT:` after the last positive match scans only the tail, and SPIR-V asm puts `OpName` before bodies — place the NOT between `OpEntryPoint` and the first body match, and check its sensitivity with a must-exist pattern that should fail [same](../learnings/1792361172213-when-a-fix-validates-ir-before-dce-removes-it-vali.md).

## A guard keyed on a helper's default return covers every unlisted kind (#13096 / PR #13610)

The slang#13096 fix makes `getGlobalParamAddressSpace` skip any resource kind for which `getAddressSpaceFromGlobalParamResourceKind` returns `AddressSpace::Generic`. Keyed on the `default:` arm, that `continue` covers every unlisted kind, not only `InputAttachmentIndex`, so it also fixed a `ParameterBlock` in space ≥1 under `-fvk-*-shift` (E99997 on master). The peer reviewer found it by compiling ~4k SPIR-V test invocations with both builds under combined shifts — a cheap collateral-fix search. Put the contract on the helper's declaration ("`Generic` means no storage class and is ignored during inference"), give each newly fixed shape a regression test named in the PR body, and pin odd pre-existing behavior rather than assert it away: `-fvk-*-shift` changes layout rules for entry-point parameters but never shifts their bindings. CI note: a bot draft's `ci.yml` run can yield and sit `waiting` at the `falcor-ci` environment gate; `retry-yielded-bot-ci` skips waiting runs, so a human approves or cancels ([default-return guard](../learnings/1791926289453-a-guard-keyed-on-a-helper-s-default-return-needs-t.md)).

## An "internal-only" repro claim needs a grep of every public alias (#13629)

Filing #13629, the `-target glsl` segfault in `_emitGLSLImageFormatModifier` looked reachable only via internal `_Texture<..., 44>`, since public `Texture*`/`RWTexture*` take their format from `T.format`. But the GLSL module's `image2D<int format>` (`glsl.meta.slang` ~4637), `DepthTexture*<int format>` and `Sampler*Shadow<int format>` take a raw integer, so `uniform image2D<44> img;` in a `.glsl` file crashes. Before calling an out-of-range-input bug "internal-only", grep `typealias` in both `hlsl.meta.slang` and `glsl.meta.slang` for a raw `int format`. The defect predates the crash: `getImageFormatInfo` (`slang-syntax.cpp`) never bounds-checked ([integer-format aliases](../learnings/1792045881495-slang-internal-only-texture-repro-may-be-public-vi.md)).

## Prelude "debug vs release" means downstream `NDEBUG`, which Slang never sets

A prelude macro keyed on `#ifdef NDEBUG` (`prelude/slang-cuda-prelude.h`, `prelude/slang-cpp-types-core.h`) takes its branch from the downstream compile (NVRTC, gcc, clang, MSVC), not Slang's `-O` level; nothing under `source/` defines `NDEBUG`, so the debug branch is the default even at `slangc -O3` — verify by comparing `slangc x.slang -target ptx -O3` with and without `-DNDEBUG` and grepping the PTX. Maintainers and OUTPUT_REVIEW read "release" as `-O3`, so "UB in release" or "trap in debug" must say release means `-DNDEBUG`. On #13228 the `SLANG_PRELUDE_UNREACHABLE()` none-unwrap arm traps by default and is UB only with `-DNDEBUG`; when framing "defined vs UB" for a maintainer, include the third answer, "must trap deterministically" ([downstream NDEBUG](../learnings/1791233726995-slang-prelude-debug-vs-release-downstream-ndebug-w.md)).

## Naming an opaque IR type lives in getTypeNameHint, and churns far more than debug info (#12920/#12858)

When SPIR-V NonSemantic debug info names a type `DebugTypeComposite` "unnamed"/"@unnamed", the fix is a missing `case kIROp_*:` in `getTypeNameHint()` (`slang-ir-util.cpp:566-934`), not an emitter change: `emitDebugTypeImpl` → `getName()` uses NameHint/Linkage decorations, else `getTypeNameHint()`, else the literal "unnamed". Hoistable builtins (`DescriptorHandle<T>`, RayQuery, CoopVec/Mat, TensorLayout/View) carry no NameHint. Mirror the `ParameterBlock<…>`/`StructuredBuffer<…>` cases: emit `Name<`, recurse on the resource type, `>` ([getTypeNameHint, not the emitter](../learnings/1788756352102-naming-descriptorhandle-t-and-other-opaque-types-i.md)).

**Blast radius.** The ~19 call sites include `printDiagnosticArg` and buffer/CUDA/optional/clone/autodiff/glsl-block name synthesis, so a new case can shift diagnostic goldens. `slang-ir-wrap-cbuffer-element.cpp:23` builds `"wrapper_" + getTypeNameHint(elementType)`, so `ParameterBlock<DescriptorHandle<Buffer>>` now emits `wrapper_DescriptorHandlex3C…x3E`, breaking `tests/metal/test_descriptor_handle.slang`'s `// METAL-NOT: DescriptorHandle` — green only because of the bug; replace such negatives with a positive lowering assertion. `addUserTypeHintDecorations` gives any `IRGlobalParam` whose type now has a name a `-fspv-reflect` UserTypeGOOGLE string. Run the FULL suite (`slang-test -use-test-server -server-count 8`); CUDA-PTX-JIT / "Failed to load DLL gfx" reds are pre-existing GPU-less-runner failures. Test GPU-free via `slangc -target spirv-asm -g2 -emit-spirv-directly` ([shared blast radius](../learnings/1788774792668-gettypenamehint-is-shared-naming-an-opaque-ir-type.md)).

## Probe "constants are folded" test claims: SCCP folds only scalar `Neg`

On WGSL, "negated constants are folded before emission" holds only for scalars: `static const float S; -S` emits `-5.0f`, but `static const float3 V; -V` emits `(vec3<f32>(0) - …)`, because `evalNeg` in `slang-ir-sccp.cpp` handles only scalar int/float. When a PR narrows such a claim, run a 5-line probe rather than trust the comment. For round-N reviews, snapshot the previous round's `bin/` and `lib/` (`cp -a`) before rebuilding the verify worktree: it is a revert-drill baseline. `/tmp` can be wiped overnight, taking naga-wasm setups with it ([SCCP scalar Neg](../learnings/1791812377155-probe-constants-are-folded-test-claims-sccp-folds-.md)).

**Consume the outputs or DCE deletes the call you are probing.** A repro of `tex.GetDimensions(x, y)` with `x,y` never read emits nothing and looks mysteriously "fixed" — any opaque-resource call whose outputs are unused is DCE'd before emission. Always consume the results (e.g. `return a + float4(x,y,0,1)`) so the call survives to emit ([GetDimensions vanishes under DCE](../learnings/1794819536412-slang-repro-gotcha-getdimensions-vanishes-under-dc.md)).

**When a constant-folded value has the wrong BITS, suspect the C++ conversion path before any emitter.** #13845: folding `asfloat` of an sNaN bit pattern ran the bits through a C++ `double→float` hardware conversion, which quiets the signaling NaN before it reaches any emitter — so a WGSL-centric patch (PR #13816) could not have fixed SPIR-V/VM. The merged fix (PR #14629) added bit-preserving `FloatBitsToDouble`/`DoubleToFloatBits` to `source/core/slang-math.h` and swept every constant-fold narrowing site, fixing all targets at once. Rule: `(float)value` / `FloatAsInt(float(...))` in an emitter silently normalizes NaN patterns — fix at the core-math helper layer and sweep the call sites ([#13845 postmortem](../learnings/1795115705677-postmortem-shader-slang-slang-13845-superseded-by-.md)).

## Read the real harness output before blaming your diff (#14641/#14643)

slang-test writes `<test>.actual.txt` next to the test source (one per leg), and it shows the real buffer dump — read it FIRST when a filecheck fails: thirty minutes went into tracing emission plumbing for a "wrong" `-1` that was correct all along; the `.actual.txt` had the answer immediately. COMPARE_COMPUTE buffer dumps print negative ints as UNSIGNED HEX on both cpu and cuda legs (`-1` appears as `FFFFFFFF`), so a `// CHECK-NEXT: -1` never matches and looks like a value-corruption bug — CHECK the hex, with precedent in `tests/language-feature/switch-fallthrough/fallthrough-only-some-vars.slang`. In a shared-clone worktree, a later build step can destroy the base-clone submodule symlinks; the symptom is every optix test failing NVRTC "Failed to locate OptiX headers" — re-run the symlink loop and the suite before treating it as a code regression ([hex dumps and .actual.txt](../learnings/1795118342270-slang-test-compare-compute-dumps-negatives-as-hex-.md)).

To reproduce a cpu-target compile failure, don't fight slang-test directives: emit the C++ directly (`slangc -target cpp -entry <e> -stage compute -O3 t.slang -o out.cpp`; pass `-O3` bare) and compile `out.cpp` with BOTH g++ and clang++ (g++ misses clang-only `-Warray-bounds` warnings). That repro found the latent `SLANG_MATRIX_UNARY_OP` typo in `prelude/slang-cpp-types-core.h` (`result[i].rows[i][j]`): no test ever instantiated a matrix unary op, so `!someMatrix` has never compiled on cpu/cpp for ANY element type ([cpu-target dual-compile repro](../learnings/1795109819596-repro-cpu-target-failures-by-emitting-cpp-dual-com.md); the same learning also records a host-side routing guard — fresh `[Triage handoff]` delegations to a fixer now require `in_reply_to` even with explicit `to` + `thread_id`).

## Exit-code verification: −2 internal vs −1 compile-failed

To verify a PR's "clean failure" vs "internal error" claim: slangc exit −2 (internal) is `SLANG_E_ABORT` → `InternalCompilerError`, set after `CompilationAbortedDueToException` E99997 is diagnosed. Exit −1 (ordinary failed compile) is the naming trap: non-abort failures are converted to `SLANG_E_INTERNAL_FAIL` in `slangc/main.cpp`. So `SLANG_E_INTERNAL_FAIL` = −1 user-facing failure, `SLANG_E_ABORT` = −2 compiler bug (verified on #14519) ([exit −2 internal vs −1 compile-failed](../learnings/1794889169435-slang-exit-code-mapping-2-internal-vs-1-compile-fa.md)).
