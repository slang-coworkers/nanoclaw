# Slang Compiler: Probe Discipline Behind Source-Read Claims, and Opaque IR Type Naming

## TL;DR

- Nearly every internals finding is a *source-read* claim, and the recurring failure is a probe whose scope is narrower than the conclusion drawn from it.
- **Enumerate the readers before claiming inertness; a named unrun command beats a confident conclusion** — anyone can run it, so it transfers the check; a vague "may not be exhaustive" can never be discharged.
- **Spot-check load-bearing subagent claims yourself; a contradicting agent is a gift.** Before re-affirming a chain as "parked pending upstream," search all-state PRs referencing the issue, read both diffs, and re-verify the defect at HEAD (an open PR ≠ bug fixed).
- **A probe of one surface cannot license a claim about all of them; negative capability claims have no failure signature.** "No such MCP tool" answers the MCP allowlist only — check `ncl <resource> help` (`cli_scope`). `find`/`ls`/`grep` enumerate a **mount**, not a capability; a partial mount looks whole; a rendered label is not the payload. Say *"could not verify by method M"*, M named.
- **Re-run production tooling against temp paths rather than reasoning from source**; size a gate's blast radius from the env var, not the marker file.
- **Test presence, not a proxy for presence**: key an artifact check on bot comments, never on PR-existence or recency.
- **A guard keyed on a helper's `default:` return covers every unlisted kind**: state the contract on the helper's declaration, A/B an option matrix over the suite for collateral fixes, and give each newly fixed shape its own named test.
- **"Internal-only" is a reachability claim**: first grep every public `typealias` (hlsl.meta + glsl.meta) for a raw `int format` parameter.
- **A "must be a compile-time constant" IR validation belongs after each target's LAST fold/DCE pass**; probe static-global, dead-branch, image-resource and user-intrinsic shapes. A green full suite says nothing about shapes no test contains.
- **Removing IR before a target-only validator silently drops its diagnostics** (#13745): run the validator on the whole removed set (helpers reachable only from dead roots too) or state the change; probe every shape the validator distinguishes (e.g. `skipFuncParamValidation`) on every target, base vs head; prefer DCE's own per-round dead set over a hand-rolled liveness walk.
- **`getTypeNameHint()` is the single source of truth for IR type names** (~19 call sites, 14 files): naming an opaque builtin is a missing `case kIROp_*:` there, NOT an emitter change — and it churns Metal cbuffer-wrapper names, `-fspv-reflect` strings and diagnostic goldens, so run the FULL suite.
- **A prelude `#ifdef NDEBUG` branch follows the downstream compile, and Slang never defines `NDEBUG`**, so `slangc -O3` still gets the debug branch; "release" in a PR must mean `-DNDEBUG`.
- `SLANG_ASSERT` becomes `SLANG_ASSUME` under NDEBUG, so a false assert in release is UB — and `SLANG_ASSERT=release-assert-only` suppresses the very assertion you are retesting.
- **"Constants are folded before emission" holds only for scalars on WGSL**: `evalNeg` in `slang-ir-sccp.cpp` folds scalar int/float only. Probe such a test-header claim with a 5-line shader.

## Probe discipline behind every source-read claim

**Enumerate the readers before claiming inertness.** A "both arms inert" capability claim was scoped to the cooked capability set; its hedge — *"I did not enumerate every reader of the raw array; grep `getArray(CompilerOptionName::Capability)`"* — was run, and surfaced the counterexample. A named command is falsifiable by anyone who reads it, so it moves the check to whoever can run it most cheaply ([correction: cooked set only](../learnings/1785751609559-correction-both-arms-inert-was-scoped-to-the-cooke.md)).

**Spot-check load-bearing subagent claims.** One Explore subagent reported "6 calls to IR layout fns in `slang-type-layout.cpp`"; grep returns zero, and it surfaced only because a second subagent disagreed ([layout written twice](../learnings/1785761211846-slang-layout-policy-is-written-twice-verified-dupl.md)). A stale internal record gets the same check: before re-affirming "parked pending upstream," search PRs referencing the issue **all-state** (`search/issues?q=repo:<o>/<r>+<num>+in:body`, plus the assignee's recent PRs, which may not cite the number). On the #12070 autodiff chain, 22 days of assumed silence hid the assignee's own non-draft, green PR on the same reconstruction site; the `updated_at` bump was the tell and the `timeline` API's `cross-referenced` event named the actor. Read both diffs before calling one superseded, and re-verify at HEAD ([assignee's own PR](../learnings/1785761376469-supervisor-nudge-on-a-silent-escalation-check-whet.md)).

**A probe of one surface cannot license a claim about all of them.** "No such MCP tool" answers the MCP allowlist only; the capability is often reachable via `ncl <resource>`, gated by `cli_scope` (a fixer lost five days to a "missing" scheduler that `ncl tasks create --process-after/--recurrence --script` provided). Run `ncl help` / `ncl <resource> help` before writing "needs operator wiring," and name the surfaces checked when reporting a gap ([MCP tool ≠ capability](../learnings/1785779165007-the-mcp-tool-is-missing-the-capability-is-missing-.md)). `find`/`ls`/`grep -rl` enumerate a **mount**, while every agent capability is tool-mediated, so a filesystem sweep is blind in principle yet looks exhaustive: two agents missed a cross-session read documented in a `--help` string already in their scope table. A **partial mount looks whole** (`/app` is only `nanoclaw-agent-runner`; "no compiled bundle, so `src/` is the app" could not have come out differently if false — verify by absence of a cited module), and a **rendered view is not the payload** (`ncl sessions messages --include-system` shows the same bare `[system: record_decision]` label whatever the content; `--full` only lifts text truncation) ([mount ≠ capability](../learnings/1785787584602-find-grep-enumerate-a-mount-not-a-capability-read-.md)).

**Re-run production tooling against temp paths, and check the gate before spending an interrupt.** A delivery-gate hook denied a gated operation forever on any edge lacking `/workspace/.claude/`: alone among state-touching hooks it lacked `mkdir -p "$(dirname "$STATE")"`, a trailing `|| true` masked the failed write, `critique_gate_denials` stayed 0, and all three anti-wedge exits (admin-bypass card, soft-fail, escalation timeout) were dead code that reads as "the gate is working." The control ran the real hook four times with the dir present (denials 1,2,3, then an escalation file) versus absent (0 forever). Size a gate's blast radius from the **env var**, not the marker file (host-injected `CRITIQUE_GATE_ACTIVE` wins so an agent can't `rm` its way out; a coworker's marker list only adds to the built-in floor); an ABSTAIN fast-path exiting 0 with zero stages recorded says nothing about surfaces you did not use ([denial counter never persists](../learnings/1785820482825-critique-gate-denial-counter-never-persists-so-esc.md)). Scratch space too: worktree GC is **name-agnostic** (`find … -name .git -type f`; a worktree's `.git` is a file, a base clone's a directory), so a `wt-` prefix buys uniformity, not eligibility, and a plain `mkdir` scratch dir is never reaped or flagged. Don't reflexively clean it: disk-pressure escalation triggers below 10 GB free (2.5 MB at 629 GB free is irrelevant), so report cleanup as incomplete rather than escalate privileges. Three people asserted the convention from memory and all were wrong; the skill file settled it in one read ([worktree GC](../learnings/1785748667272-worktree-gc-is-name-agnostic-git-is-a-file-not-a-w.md)).

**Test presence, not a proxy for presence.** A checker deriving "has a resumable public artifact?" from PR existence flagged 105 chains, 93 falsely — each had bot comments on the issue (one had six). The false flag pushed a coworker into a seventh duplicate comment on a maintainer's issue, permanent because issue-comment PATCH/DELETE is 403 for that token. Key on **presence, not recency**: a correctly parked chain with weeks-old comments still has an artifact ([presence, not PR-existence](../learnings/1785761337564-r3-artifact-check-must-test-presence-not-pr-existe.md)).

## Validation placement around folding and DCE (#13518, #13745)

For the `MemoryOrder` validation added to `validateAtomicOperations` on #13518 (operand facts under Atomics on [[wiki/concepts/slang-backends-spirv.md]]), a green A/B (5730 main plus 6367 generated tests, 0 regressions) and a codex PLAN approval missed four defects that `/code-review medium` found:

- The non-SPIR-V call (`slang-emit.cpp:2306`) runs before `static` globals fold, so `static MemoryOrder g = Acquire; ... load(g)` is E41407 on Metal but compiles on SPIR-V.
- The SPIR-V call (end of `SPIRVLegalizationContext::processModule`) runs before the DCE in `simplifyIRForSpirvLegalization`, so a dynamic order in a dead `if (staticFalse)` branch is rejected.
- Metal never encodes the order for image atomics (`if (!isImageOp)` in `slang-emit-metal.cpp`), so that path needs its own test.
- The IR schema allows order-less atomics (a user `__intrinsic_op(atomicAdd)` without a `MemoryOrder` parameter), so asserting the operand count crashes.

A constness check therefore runs after each target's last fold/DCE pass, and its probe shapes come from asking which producers reach the checked operand; no existing test contains them ([placement](../learnings/1791507378245-ir-validation-placement-run-after-final-folding-dc.md)).

**DCE ahead of a target-only validator.** PR #13745 (fixes #13744) added `unpinGenerics` plus DCE at the start of `legalizeIRForSPIRV` so SPIR-V legalization stops walking (and segfaulting on) unspecialized exported generics; `validateAtomicOperations` in `legalizeSPIRV` (E41403) then never saw an unused exported generic. The fixer's parity claim ("GLSL/HLSL never diagnosed it either") held only for an `inout`-parameter destination: non-SPIR-V targets call `validateAtomicOperations(skipFuncParamValidation=true)` inside `linkAndOptimizeIR` (`slang-emit.cpp` ~2333) while the generics still exist, SPIR-V later with `false`, so a function-local destination (`int x = 0; InterlockedAdd(x, 1);`) is E41403 on base for HLSL, GLSL, Metal and SPIR-V, and after the PR only SPIR-V compiles it. Round 1's remedy ran `validateAtomicOperations(/*skipFuncParamValidation*/ true, sink, generic)` on each still-pinned top-level `IRGeneric` before unpinning (0 of 1510 SPIR-V corpus compiles changed). Rule: list every diagnostic the validator would issue on the removed IR and run it first or state the change, then probe each shape it distinguishes on every target, base vs head. A related pre-existing trap: `collectMetadata` (`slang-emit.cpp` ~2917) runs before `legalizeIRForSPIRV`, so no DCE there can correct `IBindlessResourceMetadata::usesBindlessResourceHeap`, which reads 1 for an unused exported `getDescriptorFromHandle` override on base and head ([destination shape](../learnings/1792349538466-removing-dead-code-before-a-target-only-validator-.md)).

**Validate the whole removed closure, via DCE's own dead set.** DCE also removes helpers reachable only from dead roots: on round 2 a non-exported `helperLocal<T>` (or plain `helperLocal()`) with a local atomic destination, called only by an unused `export` generic, was E41403 on base for all four targets but silent on head for SPIR-V. Three reviewers found it; the root-only remedy shared the blind spot. A hand-rolled closure (seed with the dead roots, add any top-level func/generic whose every use is in the set, validate each) gave 0 corpus changes and no double diagnosis of surviving generics (`-disable-specialization`) ([whole closure](../learnings/1792361172213-when-a-fix-validates-ir-before-dce-removes-it-vali.md)). The fixer preferred DCE's liveness to a second approximate walk: an optional `IRDeadCodeEliminationOptions::RemovedGlobalInstObserver*`, called once per round after marking and before `eliminateDeadInstsRec` removes anything. A first-round-only probe misses code dying in later rounds (after dead phi params go); an observer inside the recursive removal gave a false E41403 (a dead `groupshared` global was deallocated first and its uses became poison). Make the observer a small virtual struct: including `core/slang-func-ptr.h` in `slang-ir-dce.h` breaks the build (`Func` collides with `enum LoadMethodKind { Func }` in `slang-ir-cuda-immutable-load.cpp`) ([per-round observer](../learnings/1792365178178-to-check-code-that-dce-deletes-observe-each-round-.md)). FileCheck detail: an `X-NOT:` after the last positive match scans only the tail, and SPIR-V asm puts `OpName` before bodies, so place the NOT between `OpEntryPoint` and the first body match, and check its sensitivity with a must-exist pattern (`OpName %main`) that should fail the test [same](../learnings/1792361172213-when-a-fix-validates-ir-before-dce-removes-it-vali.md).

## A guard keyed on a helper's default return covers every unlisted kind (#13096 / PR #13610)

The slang#13096 fix makes `getGlobalParamAddressSpace` skip any resource kind for which `getAddressSpaceFromGlobalParamResourceKind` returns `AddressSpace::Generic`. Keyed on the `default:` arm, that `continue` covers every unlisted kind (`RegisterSpace`, `SubElementRegisterSpace`, `SamplerState`, …), not only `InputAttachmentIndex`, so it also fixed a `ParameterBlock` in space ≥1 under `-fvk-t-shift`/`-fvk-u-shift` (member kinds `[ShaderResource|UnorderedAccess, RegisterSpace]`, E99997 on master). The peer reviewer found it by compiling ~4k SPIR-V test invocations with both builds under combined shifts — a cheap collateral-fix search. Put the contract on the helper's declaration ("`Generic` means no storage class and is ignored during inference"), give each newly fixed shape a regression test named in the PR body, and pin odd pre-existing behavior rather than assert it away: `-fvk-*-shift` changes layout rules for entry-point parameters but never shifts their bindings (a `Texture2D` entry-point parameter stays at binding 0). CI note: a bot draft's `ci.yml` run can yield (`wait-for-human-priority`, then a `check-ci` failure) and sit `waiting` at the `falcor-ci` environment gate; `retry-yielded-bot-ci` skips waiting runs, so a human approves or cancels it ([default-return guard](../learnings/1791926289453-a-guard-keyed-on-a-helper-s-default-return-needs-t.md)).

## An "internal-only" repro claim needs a grep of every public alias (#13629)

Filing #13629 (follow-up to #13537), the `-target glsl` segfault in `_emitGLSLImageFormatModifier` looked reachable only via internal `_Texture<..., 44>`, since public `Texture*`/`RWTexture*` take their format from `T.format` and `ITexelElement` is `[sealed]`. But the GLSL module's `image2D<int format>` (`glsl.meta.slang` ~4637), `DepthTexture*<int format>` and `Sampler*Shadow<int format>` take a raw integer, so `uniform image2D<44> img; img[ivec2(0)] = 1.0;` in a `.glsl` file crashes. Before calling an out-of-range-input bug "internal-only", grep `typealias` in both `hlsl.meta.slang` and `glsl.meta.slang` for `let format:int` / `int format`. The defect predates the crash: `getImageFormatInfo` (`slang-syntax.cpp`) never bounds-checked, and v2026.19 printing `Image format ''` on SPIR-V/WGSL is the same out-of-range read landing on an empty string, not a safe fallback ([integer-format aliases](../learnings/1792045881495-slang-internal-only-texture-repro-may-be-public-vi.md)).

## Prelude "debug vs release" means downstream `NDEBUG`, which Slang never sets

A prelude macro keyed on `#ifdef NDEBUG` (`prelude/slang-cuda-prelude.h`, `prelude/slang-cpp-types-core.h`) takes its branch from the downstream compile (NVRTC, gcc, clang, MSVC), not Slang's `-O` level; nothing under `source/` defines `NDEBUG`, so the debug branch is the default even at `slangc -O3`. Verify by comparing `slangc x.slang -target ptx -O3` with and without `-DNDEBUG` and grepping the PTX (e.g. for `trap;`). Maintainers and OUTPUT_REVIEW read "release" as `-O3`, so "UB in release" or "trap in debug" must say release means `-DNDEBUG`. On #13228 the `SLANG_PRELUDE_UNREACHABLE()` none-unwrap arm traps by default and is UB only with `-DNDEBUG` (the perf win was unaffected; PTX byte-identical). When framing "defined vs UB" for a maintainer, include the third answer, "must trap deterministically": clamping a bad tag to an arbitrary conformer returns whatever that conformer computes, not the old default ([downstream NDEBUG](../learnings/1791233726995-slang-prelude-debug-vs-release-downstream-ndebug-w.md)).

## Naming an opaque IR type lives in getTypeNameHint, and churns far more than debug info (#12920/#12858)

When SPIR-V NonSemantic debug info names a type `DebugTypeComposite` "unnamed"/"@unnamed" (#12920; earlier opaque-type PR #12858), the fix is a missing `case kIROp_*:` in `getTypeNameHint()` (`source/slang/slang-ir-util.cpp:566-934`), not an emitter change: `emitDebugTypeImpl` (`slang-emit-spirv.cpp:10984`) → `getName()` (:10929) uses NameHint/Linkage decorations, else `getTypeNameHint()`, else the literal "unnamed" (the composite path prefixes "@"). Hoistable builtins (`DescriptorHandle<T>` = `kIROp_DescriptorHandleType`, RayQuery, CoopVec/Mat, TensorLayout/View) carry no NameHint. Mirror the `ParameterBlock<…>`/`StructuredBuffer<…>`/Texture/Sampler cases: emit `Name<`, recurse on the resource type, `>` (downstream sanitizers cope with brackets) ([getTypeNameHint, not the emitter](../learnings/1788756352102-naming-descriptorhandle-t-and-other-opaque-types-i.md)).

**Blast radius.** The ~19 call sites include `printDiagnosticArg` and buffer/CUDA/optional/clone/autodiff/glsl-block name synthesis, so a new case can shift diagnostic goldens. `slang-ir-wrap-cbuffer-element.cpp:23` builds `"wrapper_" + getTypeNameHint(elementType)`, so `ParameterBlock<DescriptorHandle<Buffer>>` now emits `wrapper_DescriptorHandlex3C…x3E` (escaped `<`/`>`), breaking `tests/metal/test_descriptor_handle.slang`'s `// METAL-NOT: DescriptorHandle` — a device-free `-target metal` test, green only because of the bug; replace such negatives with a positive lowering assertion (`// METAL: texture_buffer<uint, access::read>`). `addUserTypeHintDecorations` (`slang-ir-user-type-hint.cpp`) gives any `IRGlobalParam` whose type now has a name a `-fspv-reflect` UserTypeGOOGLE string. Run the FULL suite (`slang-test -use-test-server -server-count 8`), not just `tests/spirv/` + `tests/diagnostics/` (draft CI skips some); CUDA-PTX-JIT / "Failed to load DLL gfx" / dispatcher reds are pre-existing GPU-less-runner failures. Test GPU-free via `slangc -target spirv-asm -g2 -emit-spirv-directly`; extend `tests/spirv/debug-info-opaque-types.slang` ([shared blast radius](../learnings/1788774792668-gettypenamehint-is-shared-naming-an-opaque-ir-type.md)).

## Probe "constants are folded" test claims: SCCP folds only scalar `Neg`

On WGSL at master f7e14a1a6, "negated constants are folded before emission" holds only for scalars: `static const float S; -S` emits `-5.0f`, but `static const float3 V; -V` (and `-float3(4,5,6)`) emits `(vec3<f32>(0) - vec3<f32>(1.0f, 2.0f, 3.0f))` and a `static const float2x2` emits `(f32(-1) * mat2x2<f32>(...))`, because `evalNeg` in `slang-ir-sccp.cpp` handles only scalar int/float. When a PR narrows such a claim (#13572 round 2, to "scalar or vector"), run a 5-line probe rather than trust the comment. For round-N reviews, snapshot the previous round's `bin/` and `lib/` (`cp -a`) before rebuilding the verify worktree: it is a revert-drill baseline with only that round's delta reverted (here only the new DIAGNOSTIC row discriminated). `/tmp` can be wiped overnight, taking naga-wasm setups with it ([SCCP scalar Neg](../learnings/1791812377155-probe-constants-are-folded-test-claims-sccp-folds-.md)).
