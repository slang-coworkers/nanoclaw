# Generics, overload resolution, and type inference in Slang

## TL;DR

Slang's generic/overload machinery has several structural traps that recur across bugs:

- **Two constraint-discharge paths exist and disagree.** The fixpoint worklist solver (`trySolveGenericArguments`) serves only the *outermost* generic; nested generics use a **linear, declaration-order** pass that cannot see witnesses from a later constraint, so `where` order is load-bearing there.
- **`CompareOverloadCandidates` compares conversion cost BEFORE `OverloadRank`, and skips rank entirely for `Generic`/`UnspecializedGeneric`-flavored candidates.** For inferred generic calls (the PR #12249 min/max tiers) rank decides only cost ties. Each constraint-upcast hop costs 1, so a directly named constraint beats an overload over a refined interface whatever the ranks; a failed optional constraint costs 150, a matrix layout conversion 5.
- **Specialization never re-runs overload resolution**; only `lookup_witness_method` folding re-targets. To reach a concrete builtin overload (e.g. vector `min`) from abstract `T`, route through an interface requirement whose builtin witness body is checked against the concrete shape; a direct call to the same name recurses.
- **No core-module dispatcher shape serves every constraint spelling.** A hidden refined interface (`<T : __IMinMax>`) loses to a directly named coarser base; public interfaces (`IFloat`, `IInteger`) break `T : __IMinMax` callers. The real fix is a refinement check before cost (global). Sibling entry points need DIFFERENT ranks (equal-rank zero-cost is E39999). Probe every spelling with a tiny `-target cpp` file; verify rank moves with a revert drill.
- **Slang does not rank overloads by constraint specificity** (`compareOverloadCandidateSpecificity` only counts generic params). Overloads differing *only* in a bound are ambiguous whenever the discriminating param is explicit rather than inferred. Always test the **fully-explicit-generic-args** call; prefer a single widened bound.
- **Unsuffixed int literals commit to `int` at parse time.** In generic inference the literal-sourced `Element=int` is solved *before* the conformance witness runs, so a conformer's `uint` is never offered: an **ordering / eager-commit** defect, not a type-join tie-break (`TryJoinTypes(int,uint)` already returns `uint`).
- **Inference never sees a `typealias`, and inverting an associated-type projection is unsound** (`TryUnifyTypes` gets canonical types; `T.A == X` has many solutions, #13537). Optional hints are order-dependent (`mergeTypeConstraint` joins before comparing priority). Its `fst->equals(snd)` early return records no `T = T` (E30027 inside `extension Foo<T, C>`); recording it causes E55201, so forward through a free generic function instead.
- **`[ForwardDerivativeOf]` resolution routes through ordinary overload resolution** over imaginary args and inherits both blind spots above, so a shaped derivative + a catch-all primal → ambiguous → E31148.
- **`__func_extension` cannot name one overload of a generic set that contains a `vector<T,N>`/`matrix` overload** (E33070, explicit `<T>` or not), and a resolving extension only helps callers that bind that exact overload.
- **Constraint-failed generic candidates are status-pruned** (status 0 = worst) before the multi-candidate note loop, so E39999 omits their reason (which *is* captured per-candidate in `genericInferenceFailure`).
- **ABI-additive claims for implied-constraint synthesis need two conditions** (exclude optional constraints; skip already-satisfiable) and three cache invalidations.
- **A later constraint that needs a non-first part of an inline conjunction ICEs at lowering** (`void f<R : IA & IB, T : IFoo<R>>()` with `IFoo<R : IB>`: E99997 "generic type constraint during lowering", even uncalled). Split it into separate `where` clauses.
- HLSL `template<...>` reuses ~90% of the generics machinery; net-new risk is the duck-typed-at-instantiation decl, the instance registry, and same-module rejection. A **base-class split** (`GenericDecl → ParameterizedDecl`) breaks invariants the derived class silently held (never-null `inner`).

## Two constraint-discharge paths and declaration-order sensitivity

When the declaration order of `where` constraints decides whether code compiles, suspect the split in `TryCheckOverloadCandidateConstraints` (`slang-check-overload.cpp:1157`). The fixpoint worklist solver `trySolveGenericArguments` runs only when `genericIsOutermost`, blocking each witness constraint until its dependencies are ready (`hasUnreadyDependenciesForWitnessConstraint`); **nested** generics fall through to a **linear pass** (`:1260`) over `getMembers()` in declaration order that cannot see witnesses established later [order sensitivity](../learnings/1787226105001-generic-where-constraint-declaration-order-sensiti.md). PR #11210 consolidated solving into the worklist and #11368 made it order-agnostic, but only on the outermost path. The "does not conform" diagnostic is `TypeArgumentDoesNotConformToInterface` (`diagnostics/type-errors.lua`), emitted at `:1303` (linear reject) and `:1598` (solver).

A #11210 side effect (#13464): an omitted variadic pack now starts empty, so `isSubtype` returns an empty `Pack()` witness for `() : (int,float)` (the `ConcreteTypePack` branch "vacuously satisfies") and `isTypeEqualityWitness` accepts it for having zero elements. `where U == T` then holds with `countof(U)=0` vs `countof(T)=2`, and forwarding through `U` silently drops arguments (b6ca5682d rejects, 79ac457f0 accepts) [empty-pack witness (#13464)](../learnings/1791318189564-a-rebuilt-scratch-worktree-can-be-stale-after-git-.md).

## Overload ranking gaps: OverloadRank, specificity, constraint-only splits

Two independent facts make constraint-based disambiguation of generics unreliable. First, **`[OverloadRank]` is unreachable for generic-vs-generic candidates**: `CompareOverloadCandidates` early-returns 0 (lines 2420–2426) when either flavor is `Generic`/`UnspecializedGeneric`, skipping `getScopeRank` and `getOverloadRank` [OverloadRank unreachable for generics](../learnings/1787965552599-slang-generic-overload-overloadrank-is-unreachable.md). So "glsl beats core" (`[OverloadRank(15)]` vs negative core rank) never applies between generic operator overloads; only the generic-param-count block (`:2214-2219`) separates them, which is why removing that tie-breaker (proposed for `-std 202c`) makes core/GLSL builtin operator calls ambiguous.

Second, **Slang does not rank by constraint specificity** (`slang-check-overload.cpp:2201`), so overloads differing only in a type param's bound are distinguished only by argument matching [constraint-only split needs an inferable param](../learnings/1787359986220-slang-overload-split-by-constraint-only-disambigua.md). An inferable discriminating param resolves; an explicit-only one (`coopVecLoad<4,half>(byteAddressBuffer)`) is E39999; and even an inferable one goes ambiguous once the caller spells **all** generic args (`coopVecLoad<4,float,DefaultDataLayout>(sbuf)`, #12411), because argument matching no longer discriminates [fully-explicit callers regress (#12411)](../learnings/1787395523470-coopvecload-two-overload-split-regresses-fully-exp.md). Before such a split, test the fully-explicit call and prefer a single widened bound; `[OverloadRank]` helps only inferred calls, after conversion cost ties.

## Reaching concrete builtin overloads from abstract-`T` generics; conversion cost before rank (#11075 / PR #12249)

Generic `min<T : IComparable>` over vectors ICEs on cpp/cuda via `$P` (#11075). In a generic body `min(x, y)` binds once against abstract `T`; `specializeGeneric` only substitutes, and the only post-specialization re-targeting is `lookup_witness_method` folding (`maybeSpecializeWitnessLookup`, slang-ir-specialize.cpp:1233). A direct call therefore never picks the concrete `vector<T,N>` overload (e.g. `VECTOR_MAP_BINARY` on cpp/cuda), and calling the same name recurses. Reach it through an interface requirement whose builtin witness body is checked against the concrete shape: the slang.numerics pattern (`IRealOrderingFunctions.minimum` → `__numericsBuiltinMinimum` → `::min`, #12859) became a hidden core `__IMinMax` requirement refined by IFloat/IInteger and implemented in the builtin `extension vector<T,N> : IFloat` as `min(this, other)`, where the concrete overload wins by `OverloadRank` (0 vs −10) at equal cost [witness dispatch reaches concrete overloads](../learnings/1790730458349-slang-reaching-concrete-builtin-overloads-from-abs.md) [hidden `__IMinMax` witness](../learnings/1790777947628-generic-min-max-on-vectors-reach-concrete-overload.md). `where optional T : IFoo` plus `if (T is IFoo)` does NOT help from an abstract caller: the optional witness resolves at the call site at check time (slang-check-overload.cpp:1276-1294), a `NoneWitness` survives specialization, and a failed optional constraint adds conversion cost 150, ranked before `OverloadRank`. Rank budget: slang.numerics pins its min/max at −9 against core IComparable `min` at −10 (numerics/wrappers.slang:14-16), so a new core generic `min` must avoid tying −9 [witness dispatch](../learnings/1790730458349-slang-reaching-concrete-builtin-overloads-from-abs.md).

**Conversion cost beats rank.** `CompareOverloadCandidates` (:2288) compares `conversionCostSum` before `OverloadRank` (:2394) and before `compareOverloadCandidateSpecificity`. For generic-constrained arguments the cost counts constraint-upcast hops (`kConversionCost_GenericParamUpcast = 1`, via `TransitiveSubtypeWitness` / `DeclaredSubtypeWitness::_getOverloadResolutionCostOverride`, slang-ast-val.cpp ~820/960), so the cost-0 candidate wins even when the refined interface (`__IMinMax : IComparable`) is the more specific choice. With PR #12249's `min<T : __IMinMax>` at −10 and `min<T : IComparable>` at −11: `T : IFloat` binds `__IMinMax` (1 hop vs 2); `T : IFloat & IComparable` binds IComparable (0 vs 1) and still hits the #11075 E99997 on cpp/cuda; only `T : IFloat & IArithmetic` ties (1 vs 1), so only there does rank decide (reverting −11 to −10 gives E39999). A revert drill of the rank move passed all 7 of the PR's own tests, so it had no covering test [constraint hops beat rank: the #12249 tiers](../learnings/1790781329960-slang-overload-resolution-conversion-cost-constrai.md).

Constraining the entry points by user-facing interfaces (`<T : IFloat>`, `<T : IInteger>`, with DIFFERENT sibling ranks, since two zero-cost candidates at equal rank are ambiguous for a type satisfying both) fixes callers that name a coarser interface [constrain entry points by user-facing interfaces](../learnings/1790786101749-slang-overload-resolution-conversion-cost-beats-ov.md), but callers constrained by `T : __IMinMax` itself then break. Neither dispatcher shape serves every spelling; the general fix is an applicability-subset or refinement check before cost (the TODO at slang-check-overload.cpp ~2177), a global change. First probe every spelling (single, compound `&`, `where`, the hidden interface) with a 6-line `slangc -target cpp` file; user-level `[OverloadRank(n)]` overloads check rank moves without rebuilding the core module [refined hidden dispatcher loses to a named base](../learnings/1790967236160-slang-overload-conversion-cost-beats-overloadrank-.md).

**Matrix trap.** Inside `extension matrix<T,N,M,L>`, a concrete `matrix<T,N,M>` overload needs a layout conversion (`kConversionCost_MatrixLayout = 5`), so a cost-0 self-dispatching generic wins and the call recurses forever. Override per row, `min(this[i], other[i])`, since rows are exactly `vector<T,M>` [witness dispatch](../learnings/1790730458349-slang-reaching-concrete-builtin-overloads-from-abs.md) [hidden `__IMinMax` witness](../learnings/1790777947628-generic-min-max-on-vectors-reach-concrete-overload.md). Interface default methods are supported (re-parsed into `InterfaceDefaultImplDecl`), overriders MUST say `override` (E30853 is an error), and a default on a base reached via a derived interface works on master (#12814 test `default-method-inherited-static.slang`) [witness dispatch](../learnings/1790730458349-slang-reaching-concrete-builtin-overloads-from-abs.md).

**Probe which overload a generic bound:** `slangc f.slang -target hlsl -entry computeMain -stage compute -dump-ir -o x.hlsl 2>&1 | awk '/^###/{n++} n==1'`, then read the callee's mangled name, which encodes the constraint (`[import("_S4core3ming2TCGP04core11IComparable...")]`). Side finding: `docs/generated/tests/.../is-vector-folds-false.slang` passes vacuously (`CHECK: 0` matches a padding slot) [constraint hops beat rank](../learnings/1790781329960-slang-overload-resolution-conversion-cost-constrai.md). `docs/generated/**` is never hand-edited (`docs/generated/design/_meta/regenerate.md`); when a change makes it stale, ask the maintainer whether to regenerate in the PR or defer [user-facing interfaces](../learnings/1790786101749-slang-overload-resolution-conversion-cost-beats-ov.md). A struct field named like a defaulted interface method requirement segfaults slangc (the #13349 single-candidate `OverloadedExpr` family on [[wiki/concepts/slang-language-core-requirement-witness-synthesis.md]]).

## `[ForwardDerivativeOf]` inherits the overload blind spots

A `[ForwardDerivativeOf(f)]` whose derivative has a *shaped* generic signature (`vector<T,N>`) fails E31148 when the primal `f` also has an applicable *catch-all* generic overload, through two coupled gaps [shaped vs catch-all E31148](../learnings/1787954897660-slang-forwardderivativeof-shaped-vs-catchall-gener.md): (1) `checkDerivativeOfAttributeImpl` cannot bind a derivative whose signature is a constrained subset of a catch-all primal's ("inverse generic argument solving" is unimplemented, `:19082`); (2) derivative resolution uses ordinary overload resolution, where specificity ignores constraint tightness and generic flavors tie, so the two `pow` overloads tie or attach to the catch-all and gap (1) fails the rebind. **Decisive probe:** narrow the catch-all so it no longer applies to `vector<T,N>` (`<T:IFloat>` → `<T:__BuiltinFloatingPointType>`; `float3` conforms to `IFloat` but not to the builtin scalar interface); if it then compiles clean, the cause is gap (2), not a typo. Adding a public generic wrapper beside a scalar/vector/matrix builtin breaks the generated shaped derivative registrations in `diff.meta.slang` at core-module load.

**`__func_extension` cannot target one overload of an overloaded generic builtin either.** On master 9f31ffcfd, `__func_extension<T : X> fwd_diff(min)(...)` fails E33070 "expected a function, got 'overload group'" (even in core-module bootstrap), and `fwd_diff(min<T>)` or a concrete `min<float2>` fail E33070 "got '<unknown type>'". Explicit specialization breaks once the set contains a generic with an extra `let N` parameter (the `vector<T,N>`/`matrix<T,N,M>` overloads); a set of only `T : IFloat`/`T : IComparable` generics resolves, as does a non-overloaded generic with explicit `<T>` (diff.meta.slang:1959 records the same limit for CoopVec). A bare-name target on a single generic (`fwd_diff(mymin)`) gives E30855/E30850, then segfaults slangc. A resolving extension fixes only callers that bind that exact overload (generic `T : IFloat` code binds `min<T:IFloat>` at −11, PR #12249, not `min<T:IComparable>`), and a derivative rule selecting by IFloat `lessThan` is wrong per lane, because on vectors and matrices `lessThan` compares only lane 0 (core.meta.slang:2460/:2530). User code gets W30131 (a warning, but the declaration is rejected); core-module source is exempt via `isFromCoreModule` (slang-check-decl.cpp:17031) [`__func_extension` E33070 on sets with a vector overload](../learnings/1791389931461-func-extension-cannot-target-an-overloaded-generic.md).

## Literal inference is an ordering defect, not a tie-break defect

`acceptBox(box, 3)` fails `UIntBox does not conform to IBox<int>` for `struct UIntBox : IBox<uint>` because unsuffixed decimal literals commit to `BaseType::Int` at parse time (`_determineIntegerLiteralType`; there is no contextual literal type) [literals commit to int](../learnings/1787674982285-slang-generic-inference-unsuffixed-int-literal-com.md). The `GenericArgumentSolver` collects and solves the ordinary constraint (`Element=int`) *before* the witness constraint, then substitutes it into the witness supertype, so `_tryJoinTypeWithInterface(UIntBox, IBox<int>)` unifies `IBox<uint>` vs `IBox<int>` with no generic param to bind, and `Element=uint` is never discovered. It is not a type-join tie-break: `TryJoinTypes(int,uint)` already returns `uint` (conversion costs 300>250), but the two facts are never co-live [#12753 is ordering, not type-join](../learnings/1787675243000-slang-12753-literal-vs-conformance-generic-inferen.md). Fix: deprioritize literal-sourced ordinary constraints below witness inference (keep the arg a `DefaultSubstitutionArg` until the witness runs), or add a real deferred-representability literal type. Before "fixing the join", check that both constraints are even co-live.

## Inferring through an alias over an associated-type projection (#13537)

The public `Texture2D<T:ITexelElement>` alias expands to `_Texture<T.DataType, …, T.format>`, which broke `f<T>(Texture2D<T>)` called as `f(tex)` with E39999 (#13537). Unifying at the alias level is unavailable: `dynamicCast<NamedExpressionType>` on both `TryUnifyTypes` operands (not `as<>`, which canonicalizes the sugar away) shows neither side carries the alias, so measure whether sugar survives before designing around it. Recovering `T` from `T.A == X` inverts a projection that is non-injective when conformers share `A` (`float4`, `RGBA32F` and `RGBA16F` all have `DataType = float4`); even with an `X.A == X` guard it is a choice, not a proof. Three solver details in slang-check-constraint.cpp matter for any hint-based design: `mergeTypeConstraint` (~1988-2040) joins TypeJoin constraints before comparing priority, so an Optional+Exact hint is order-dependent against a Required TypeJoin and an Optional TypeJoin hint can widen a required binding; `canCoerce` checks convertibility, not uniqueness of the inferred `T`, so post-inference checking misses a wrong pick; and caller-provided generic args are fixed (`ArgState::CallerProvidedOrdinaryArg`, ~1889) [typealias never reaches `TryUnifyTypes`](../learnings/1791984562834-slang-inference-a-typealias-doesn-t-survive-to-try.md). Member access through such a projection is on [[wiki/concepts/slang-language-generics-and-type-system.md]].

`TryUnifyTypes` also returns early when `fst->equals(snd)` and records nothing, so inside `extension Foo<T, C>` a member call through a value whose type reuses the extension's own parameters fails lookup with E30027 (no `T = T` binding). The core-module case is `return __extractImage(this).Load(location);` inside `extension _Texture<T,Shape,…,isCombined,format>`, where `__extractImage` yields `_Texture<T,…,0,…>`; a typed local fails the same way. Making the solver record that binding lets a constrained generic pick itself elsewhere (E55201) [`equals` early return → E30027](../learnings/1792284128530-q-intrinsic-strings-must-also-be-understood-by-the.md). No type-checker change is needed, because a free generic function taking the plain texture resolves normally: `T __loadTexture(_Texture<T,Shape,isArray,0,sampleCount,0,isShadow,0,format> t, vector<int,…> loc) { return t.Load(loc); }`, called as `if (isCombined != 0) return __loadTexture(__extractImage(this), location);`, in the style of `__texture_gather`. The peer reviewer's drill on PR #13741 disproved the fixer's "cannot compile at all", so try a free-function trampoline before declaring a forward inside a generic extension impossible [free-function trampoline](../learnings/1792289884493-core-module-e30027-on-self-forward-inside-a-generi.md) [try a free function first](../learnings/1792301433983-e30027-on-a-forward-inside-a-generic-extension-try.md) [combined-sampler forwarder](../learnings/1792308956799-core-module-combined-sampler-forward-member-call-o.md). Its per-target output, and why WGSL keeps `$q`, is on [[wiki/concepts/slang-backends-hlsl-combined-sampler-texture-ops.md]].

## Constraint-failed candidates are status-pruned out of diagnostics

When an overload set has a generic candidate with an unsatisfied conformance constraint, E39999 omits it and its constraint and lists only the concrete overloads; remove the concretes and the useful E38029 appears [status-pruning drops the note (#12965)](../learnings/1788895654799-slang-overload-notes-drop-constraint-failed-generi.md). The reason *is* captured per candidate (`OverloadCandidate::genericInferenceFailure`, a tagged union), correcting the older #12035/#7857 learning. The gap has two parts: (1) the candidate gets `Status::GenericArgumentInferenceFailed` = enum 0 = worst, so `CompareOverloadCandidates` ranks it below concrete arg-mismatch candidates and `AddOverloadCandidateInner` drops it before `bestCandidates`; (2) the multi-candidate note loop reads only `bestCandidates` and never `genericInferenceFailure` (the single-candidate `CompleteOverloadCandidate` path does, which is why removing the concretes surfaces it). Low-risk fix: keep dropped candidates in a diagnostics-only side list and reuse `CompleteOverloadCandidate`'s switch; do **not** raise the candidate status, which is the first selection tiebreak everywhere.

## Implied-constraint synthesis: additive is necessary-but-not-sufficient

An "additive ⇒ non-breaking" ABI claim for implied-constraint synthesis needs two conditions, or a currently compiling program's mangle changes [two conditions, three cache invalidations](../learnings/1787958848031-implied-constraint-abi-additive-claim-needs-two-co.md). (1) Exclude OPTIONAL constraints: an optional bound already compiles via `NoneWitness`, so inferring a required `T:IFoo` from it strengthens a valid signature. (2) Skip constraints already satisfiable by existing/transitive evidence, using `isSubtype(...NoCaching)` then `isTypeEqualityWitness` (a bare identity test misses `T==V, V==U`). An `addDirectMemberDecl` of a synthesized `GenericTypeConstraintDecl` must invalidate three caches: the subtype-witness negative cache (avoid poisoning via `NoCaching`), the default-substitution-args cache (`_cachedArgsForDefaultSubstitution.clear()`), and the inheritance-info cache, which is epoch-gated on *extension* registration and so needs an explicit `.remove()`. Discovery must be structural, not a `JustTrying` resolve (which returns false and only suppresses the diagnostic).

## HLSL templates: reuse the generics machinery; watch the base-class split

For the deliberately limited HLSL `template<...>` feature (#12550, spec#61), the hard pieces already exist: argument inference / fixpoint solver (`inferGenericArguments`, `trySolveGenericArguments`), SFINAE-like silent rejection (`OverloadResolveContext::Mode::JustTrying` + discardable `DiagnosticSink`), instance dedup (ASTBuilder hash-consing via `getGenericAppDeclRef`), and a parser that is ~70% there (`ParseGenericDeclImpl`; `template` is not reserved) [templates reuse map (#12550)](../learnings/1786742192588-slang-limited-hlsl-templates-12550-reuse-map-the-h.md). The net-new risk: a template decl distinct from `GenericDecl` (out of ordinary lookup, duck-typed at instantiation), a durable instance registry preserving the lexical parent chain (`ASTCloner::cloneSyntaxNode` does *not*), a specialization-time expansion budget, and the same-module rejection point.

STEP 1 reparents the node onto a new base and generalizes consumers from `as<GenericDecl>` to `as<ParameterizedDecl>`; the highest-yield bug is an **invariant the derived class silently held that the new sibling does not** [`TemplateDecl` null `inner`](../learnings/1786869369727-base-class-split-genericdecl-parameterizeddecl-sur.md). `GenericDecl::inner` is never null, but a `TemplateDecl` can have `inner==null` (EOF parse), and two generalized consumers then crash slangc or the language server. Fix it producer-side by restoring the invariant (synthesize `EmptyDecl`), not with per-consumer null guards. A `//CHECK-NOT: error` template parse test is shallow, because step 1 keeps a `TemplateDecl`'s inner out of the member list and never checks it.

## Two-phase constraint-parameter emission leaks placeholder types

Fixing an order dependency in `emitGenericDecl` by splitting constraint-parameter emission into a predeclare pass (placeholder type + `setValue`) and a finalize pass (`setFullType`) leaks the placeholder into composite witnesses: lowering a sibling's `TypePackSubtypeWitness` reads each element witness param's *current* `getFullType()` into a permanent `IRTypePack`, which a later `setFullType` does not update [placeholder leaks into pack witnesses](../learnings/1787268164470-two-phase-ir-param-predeclare-leaks-placeholder-ty.md). Scalar witnesses are safe (the caller supplies the witness-table type). Fix: derive composite-witness element types from the semantic witness supertype, not the param's stored IR type. `isGenericConstraintParameterDecl` is true for equality constraints too, so `T == A & B` reaches the finalizer with a conjunction supertype under `-disable-non-essential-validations`, and a `SLANG_RELEASE_ASSERT(!conjunction)` there is unsafe (equality conjunctions are not flattened at header checking).

Inline conjunctions also break plain lowering: `void f<R : IA & IB, T : IFoo<R>>() {}` with `interface IFoo<R : IB>` aborts with E99997 "generic type constraint during lowering" (the `SLANG_UNEXPECTED` ending `visitGenericTypeConstraintDecl`, `slang-lower-to-ir.cpp:10598` at 4fb416a7; v2026.11–v2026.21, SPIR-V and HLSL), even if `f` is never called. Only a LATER constraint needing a NON-FIRST conjunct triggers it: `IFoo<R : IA>` and `R : IB & IA` compile, `R : IA & IB & IC` with `IFoo<R : IC>` fails, and a call `g<R>()` to `g<R : IB>` compiles. Workaround: `where R : IA where R : IB where T : IFoo<R>`. Related but distinct: #9334 (constraint order, same ICE text), #9197 (closed), #12873 (existential `AndType`); unfiled as of 2026-11-04 [inline-conjunction ICE](../learnings/1793781619588-slang-ice-inline-conjunction-constraint-used-by-a-.md).
