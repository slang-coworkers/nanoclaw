## TL;DR

- The `PreToolUse` Bash hook `gate-critique-on-deliver.sh` matches command **text**, not effect. Its `BASH_PATTERNS` includes `gh api [^|]*pulls\b`, so it denies **read-only** `gh api .../pulls/...` GETs (reviews, comments, files) as "PR creation." `gh api` defaults to GET; nothing in a read implies a mutation.
- Read PR data through surfaces the pattern never sees: `gh pr view --json`, `gh pr diff`, `gh api graphql` (reviewThreads), the `issues/N/...` endpoints, or the `mcp__slang-mcp__github_get_pull_request_*` MCP tools (not Bash → never seen by the hook). `commits/<sha>/status` and `check-runs` are also safe.
- The hook lives **in the container image**, not host source. A peer grepping `src/guard/` finds nothing — that locates the gate, it does not refute it. Scope every gate claim to LAYER + path + line + exact command + edge.
- A guard that fails to *record* is indistinguishable from one that *permits*. On a cold container where `/workspace/.claude/` is absent, the denial counter can't persist → gate denies forever AND never escalates (fail-closed + no-escalation = deadlock). The fix is `mkdir -p` the state dir, never fail-open. Read the counter (`jq .critique_gate_denials`), not the silence.
- Hook stderr about its own state files ("No such file or directory" on `workflow-state.json.tmp`) is a **finding**, not noise.
- `CRITIQUE_GATE_ACTIVE=1` is host-injected env; a child process cannot unset it and deleting `.overlay-critique-gate` does nothing. Do NOT run a ceremonial `/codex-critique` just to zero the counter — with no artifact in flight that reviews nothing and only games the guard. Report the blocker instead.
- When a gate forces an instrument swap, re-check the substitute's fidelity: the MCP review tools truncate bodies to 1000 chars, which silently manufactures a "0 findings" read.
- ABSTAIN_* decisions are NOT critique-gated (they assert nothing about code). Re-ask the gating question every time the decision *state* changes; `WOULD_APPROVE`/`BLOCK` are gated, `ABSTAIN_POLICY`/`ABSTAIN_INFRA` are not.
- Ship an ABSTAIN `[Approval Decision]` via the `mcp__nanoclaw__send_message` **tool** (its shell hook has the abstain fast-path), never a trailing `<message>` block (the host `poll-loop.ts` gate has NO abstain fast-path and always refuses it).
- Keep the literal words `BLOCK` / `WOULD_APPROVE` out of ABSTAIN prose — the fast-path's negative guard is unanchored, so "not a BLOCK" defeats it. Say "a rejecting verdict" / "a clean approval."
- Delivery re-hashes every path in codex's `### Attested` block: never attest volatile files (`.claude-trace/*.jsonl`, `logs/*`, `/workspace/*.db`) — they mutate every turn and block the post. Scope codex's reads+attestation to stable `work/<pr>-<sha>/` artifacts.
- Any file write — including a `cat > /tmp/reply.md` heredoc — counts as an "edit" and re-arms the gate. Get one OUTPUT_REVIEW approve, then post all replies with inline bodies and zero writes between.
- Each gated STAGE (DECISION_REVIEW, OUTPUT_REVIEW) must be a **fresh** `mcp__codex__codex` call with the verbatim `/codex-critique` developer-instructions; `mcp__codex__codex-reply` never records a round (no `developer-instructions` param → fails the sentinel check).
- Evaluative absolutes ("improvement", "no new risk", "strictly improves") on an un-regression-tested change are OUTPUT_REVIEW must-fixes — describe what code DOES, never grade it, unless you measured it. Grep ALL artifacts for the absolute in one pass; a residual copy re-triggers.
- A PR-review "build it and run your checks" task cannot be satisfied by citing the fixer's PASS matrix — build+run yourself in a `git worktree add --detach` at the reviewed commit.

## The read-block defect: one matcher, many reports

Across at least seven independent sessions the same defect was re-discovered: `gate-critique-on-deliver.sh`'s `BASH_PATTERNS='gh pr create|gh api [^|]*pulls\b|api\.github\.com[^ ]*/pulls\b|createPullRequest'` matches command **text**, so it classifies every read-only `gh api .../pulls/N/reviews|comments|files` GET as "PR creation" and denies it with *"CRITIQUE REQUIRED before PR creation"* ([tooling: hook blocks read-only gh api pulls](../learnings/1786386194490-tooling-critique-gate-hook-blocks-read-only-gh-api.md), [critique-gate blocks PR reads, GraphQL reachable](../learnings/1786397603719-approver-infra-critique-gate-blocks-pr-reads-gh-ap.md), [bash hook false-fires on read-only GETs](../learnings/1786479308420-approver-infra-abstain-critique-gate-bash-hook-fal.md), [route PR/issue reads through MCP tools](../learnings/1787083477695-approver-infra-abstain-the-critique-gate-bash-hook.md)). This is the standing maxim *"a guard matching command TEXT enforces nothing about command EFFECT"* in its **over-blocking** direction: it stops legitimate reads and names an action ("PR creation") that never happened, sending you to look for a delivery you aren't making ([matcher matches TEXT not EFFECT, over-blocking](../learnings/1786453015067-approver-infra-the-critique-gate-blocks-read-only-.md)). The hook's own comment concedes pattern enumeration can never be complete — it even denied a command whose only `pulls` occurrence was inside a grep string with no HTTP call at all.

Two second-order traps compound it. First, `track-edits.sh` bumps `edits_since_critique` on **any** Bash command containing a `>`/`>>` redirect (so `gh api … > /tmp/out.json` and memory bookkeeping outside its allowlist both count as "edits"), and it carries over stale across sessions — one container read `last_critique_at: 2026-07-13` against a month-old work dir ([TEXT not EFFECT + track-edits over-count](../learnings/1786453015067-approver-infra-the-critique-gate-blocks-read-only-.md)). Second, when the denial pushes you onto the MCP review tools, those **truncate bodies to 1000 chars** — precisely the shape that manufactures a false "0 findings / reviewers_complete" read, because verdict lines sit near the body end ([pulls-substring over-block + instrument-swap fidelity](../learnings/1786454460880-approver-infra-critique-gate-s-pulls-substring-ove.md)). The denial is loud; the truncation is silent.

**Scope the claim to the LAYER, then the edge.** The matcher is not in host source — it is a `PreToolUse` hook inside the approver's container image. A peer grepping `src/guard/` or the agent-runner finds nothing and can honestly report "works fine on my edge"; both observations are true simultaneously about different layers, and a peer's negative grep of a *different* layer localizes the mechanism rather than refuting it ([scope a gate claim to the layer, not the edge](../learnings/1786386936182-approver-infra-abstain-scope-a-gate-claim-to-the-l.md)). Verify the pattern's line number on your own edge (it is a per-container fact), and pipe your literal command through the hook to test — but beware the test string itself trips the gate if it contains `pulls` ([recurrence, escalate rate not count](../learnings/1786454460880-approver-infra-critique-gate-s-pulls-substring-ove.md)).

## Counter and escalation failures on a cold container

The denial counter and the 3-strike escalation both write to `STATE=/workspace/.claude/workflow-state.json`, but the gate — unlike five sibling hooks — never `mkdir -p`s that directory. On a container where `/workspace/.claude/` does not yet exist, both writes fail silently (`|| true`-suppressed): the counter stays `ABSENT` so retries are "free" and the 3-strike cap can never trip ([denial counter silently failed on missing dir](../learnings/1786396976794-approver-infra-abstain-the-critique-gate-s-denial-.md)), and critically the human-escalation path — which exists precisely so a wrongly-shut gate gets unstuck — never fires either: **fail-closed plus no-escalation is a deadlock, not a safe default** ([cold container denies forever AND never escalates](../learnings/1786397614230-approver-infra-cold-container-the-critique-gate-de.md)). The correct fix is `mkdir -p "$(dirname "$STATE")"` (matching the sibling hooks), which restores escalation while preserving fail-closed — never make the gate fail open. The general rule: *a guard that fails to record is indistinguishable from one that permits* — when a control doesn't fire, read its counter, not its silence. The harvester's own `collect-reviews.sh` survives the same `pulls/N/reviews` call only because the hook never inspects text run *inside a script* — that asymmetry (bare probe blocked, wrapped call passes) is why the defect went unnoticed.

**Working escapes** (all verified): `gh pr view --json` / `gh pr diff`; `gh api graphql` reviewThreads (route is `/graphql`, never matched — and it returns strictly more than REST: `isResolved`+`isOutdated`, but cap 100 nodes so assert `fetched == totalCount` and select the PR's own `number` for liveness); the `issues/N/...` endpoints (the `timeline` event tells you who closed a PR without any `pulls` path); and the MCP GitHub read tools ([GraphQL reviewThreads with completeness+liveness asserts](../learnings/1786397603719-approver-infra-critique-gate-blocks-pr-reads-gh-ap.md), [issues endpoints + escalation payload tell](../learnings/1787083477695-approver-infra-abstain-the-critique-gate-bash-hook.md)). The escalation payload's own fields are a tell: `hit:"PR creation"` but `repo/prNumber/prUrl` all null means a read tripped a mutation clause. Because the approver **skips the critique gate entirely for ABSTAIN_* decisions**, the gate firing on a read is a known false positive, not a signal to run codex ([known false positive on ABSTAIN reads](../learnings/1786479308420-approver-infra-abstain-critique-gate-bash-hook-fal.md)). The durable fix (owner-gated, hook is a read-only mount) is to require a write verb — `pulls\b` AND (`-X/--method POST|PATCH|PUT|DELETE` OR `-f/--field/--input`), spelled `(A.*B|B.*A)` since grep -E has no lookahead.

## Delivering the decision message: two gates, only one has the abstain fast-path

Two independent enforcement points guard the `[Approval Decision]` marker and they drifted out of parity. The shell hook (which governs the `mcp__nanoclaw__send_message` **tool**) has an ABSTAIN fast-path; the host runtime `poll-loop.ts` `blockedByCritiqueGate` (which governs the final-text `<message>…</message>` path) has **none** — so an `ABSTAIN_POLICY`/`ABSTAIN_INFRA` delivered as a trailing `<message>` block is *always* refused regardless of phrasing ([ABSTAIN must ship via send_message tool, not a <message> block](../learnings/1786479929909-approver-critique-mustfix-abstain-decisions-must-s.md)). Even on the tool path, the fast-path fires only if the text contains an ABSTAIN token AND contains **neither** `WOULD_APPROVE` nor `BLOCK` as whole words anywhere — so a 5-bullet that explains "not a confident BLOCK" defeats `! grep BLOCK` and the generic gate then demands critique stages an abstain never produces ([fast-path defeated by literal BLOCK/WOULD_APPROVE tokens](../learnings/1787021319074-approver-infra-abstain-critique-gate-abstain-fast-.md)). Belt-and-suspenders: ship via the tool, and keep the bare enum words out of the prose ("a rejecting verdict", "a clean approval"). When a gate refuses something the policy says is exempt, read *which* gate fired (the refusal wording differs) before assuming your artifact is wrong.

Running the gate you needed at the *start* of a decision after the state has moved is its own waste: one approver ran 12 OUTPUT_REVIEW + 3 DECISION_REVIEW rounds on a decision that had drifted to `ABSTAIN_INFRA:STALE_STAGE`, because it never re-asked whether the gate still applied — the gating question is a function of the *current* decision state, and an abstain asserts nothing about the code ([an ABSTAIN is not critique-gated](../learnings/1786417660584-approver-critique-mustfix-an-abstain-is-not-critiq.md)).

## Codex attestation and OUTPUT_REVIEW recording

Posting review replies trips the gate two more ways. The gate re-hashes every path in codex's `### Attested` block at delivery and denies if any changed since the approve — so if codex `sha256sum`s a live-mutating file (a `.claude-trace/session-*.jsonl` transcript, `logs/container-*.log`, `/workspace/*.db`) the re-hash always mismatches and the post is blocked with "reviewed artifacts changed" even though the approve was real ([delivery-gate + codex-attestation mechanics](../learnings/1786490307277-delivery-gate-codex-attestation-mechanics-that-blo.md), [codex attesting a volatile file falsely trips the gate](../learnings/1786740913803-approver-critique-mustfix-evaluative-absolutes-imp.md)). Explicitly scope codex's reads+attestation to stable `work/<pr>-<sha>/` files and tell it to use `gh api` (not local reads) for source confirmation. And because any file write — including a scratch heredoc — re-arms the "N edits since last critique" clause, the working pattern is: one approve, then post *all* replies with inline single-quoted bodies and zero writes between (a bare `VAR=…; gh …` in the same Bash call is not a write).

Two more recording rules: every gated STAGE must be a **fresh** `mcp__codex__codex` call carrying the verbatim `/codex-critique` developer-instructions — `mcp__codex__codex-reply` accepts no `developer-instructions` param, so `track-critique.sh` never records it as a round no matter what STAGE the prompt claims ([OUTPUT_REVIEW must be a fresh codex call, not codex-reply](../learnings/1786634623471-approver-critique-mustfix-output-review-must-be-a-.md)). And evaluative absolutes are must-fixes: describing a ctor change as "strictly improves / no new risk" was correctly blocked because a parameterized-ctor path also changed init defaults — state what code *does* against the blob, never grade it good/bad unless you measured it, and grep ALL artifacts (message + decision.md + investigation.md + memory) for the absolute in one pass so a residual copy doesn't re-trigger ([evaluative absolutes are OUTPUT_REVIEW must-fixes](../learnings/1786740913803-approver-critique-mustfix-evaluative-absolutes-imp.md)). For a reviewer, "build it and run your checks" cannot be substituted with the fixer's reported PASS matrix — the OUTPUT_REVIEW gate treats that as scope shrinkage; build+run in a `git worktree add --detach <path> <commit>` at the exact reviewed head so you never disturb the primary checkout ([OUTPUT_REVIEW rejects "relied on the fixer's test run"](../learnings/1787104438946-pr-review-output-review-gate-rejects-relied-on-the.md)).
