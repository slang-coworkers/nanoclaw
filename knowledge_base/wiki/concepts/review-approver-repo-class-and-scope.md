# PR-Approver: Repo Class, Scope & Durable-Record Discipline

## TL;DR

**Class determination first.**
- Decide the PR's CLASS before, and overriding, the clause→INFRA mapping. A non-compiler repo, or changes to the approver's own harness, is OUT_OF_SCOPE — record `ABSTAIN_POLICY` with `reason_code=OUT_OF_SCOPE:<class>`, stamp `_approver_result` explicitly so it can't drift to INFRA, skip Devin.
- An own-rules PR is also a conflict of interest — never self-approve; a human must look. A token-401 on an out-of-domain repo is a *symptom* of out-of-scope, not the cause of an infra abstain.
- A workflow-file-only PR (the `ci-latest-slang.yml` cherry-pick step) harvests Devin-only (exit 20) and fails `no_protected_paths` at Step 1 — a policy abstain, not infra. A Step-1 clause FAIL short-circuits to ABSTAIN_POLICY before the challenger; no "BLOCK overrides clause-fail" exception.

**Ledger mechanics.**
- `record_decision` writes one row per (repo, pr, commit_sha); a re-run **replaces** it and DROPS any `record_human_verdict` stamp. Before re-recording, grep for a per-commit stamp, re-stamp in the same turn, and embed the human verdict in the correction note.
- The ledger is write-only from an agent tier: you can prove your own EMISSION (`messages_out`, byte-for-byte; other sessions via `ncl sessions messages <id> --include-system`) but NOT the host-side upsert-vs-append. Report a ledger correction as ATTEMPTED / pending operator verification — never "resolved."
- `processing_ack` is inbound-only — "NOT ACKED" on an outbound row proves nothing. Before reading a status field as evidence, confirm it agrees on a row whose true status you know independently.
- `find`/`grep` over `/app` enumerate a MOUNT, not a capability (`/app` is only the container half); a negative from an incomplete enumeration is a fact about your reach. Read `--help` for verbs already in your capability table before claiming you cannot reach X.

**Lab-container infra reach.**
- `GH_TOKEN` is the sentinel `ROUTED_VIA_ONECLI_PROXY`; creds inject at the OneCLI HTTPS proxy, per path — REST works, `gh`'s GraphQL (`gh pr view/list --json`) 401s. Route PR reads through a GET-only helper with no `/pulls` literal (the critique-gate hook blocks them); the real gate stays at `record_decision`.
- Non-shader-slang orgs 401 (looks like 404 through a raising client) — use `raw.githubusercontent.com`, and read `.gitmodules` + the pinned SHA before trusting a submodule path (it may point at a fork).
- Never accept an `ABSTAIN_INFRA` without reproducing the fetch by hand — a self-inflicted tooling failure is a burned decision. Exit codes ARE usable once the gh shim distinguishes `--paginate --slurp` from bare `--paginate` and no trailing conditional sets `$?`.
- CI evidence without admin: `actions/runs/<id>/jobs?per_page=100` gives per-step status/conclusion (not log text); job logs are PUBLIC via the 302 → signed blob (`curl -sSL`). Unauthenticated limit is 60 req/hr — budget it.

**The durable record.**
- A correction that lands only in the outbound message is not a correction. Ask WHERE ELSE the claim lives — private ledger, shared learnings, synthesized wiki, embedded JSON, frontmatter, index lines. A sweep of one store is not a sweep.
- Sweep for the SUPERSEDED wording expecting **zero** hits, plus a positive control on the new wording (>0) — grepping your new phrasing cannot match stale text. Prefer labelled invalidation over deletion.
- In an append-only store, a correction atom disarms the stale one only if it names the superseded file by path and quotes the retracted sentences verbatim; say which parts survive; retract at paragraph granularity.
- Compaction inverts this discipline — shortening a pointer DELETES content when the index line is the only copy. Grep the child for the rule's distinctive phrase first; append-then-verify-then-shorten; mark load-bearing evidence `⛔ do-not-compress`. A datapoint a rule's credibility rests on IS the rule.
- Confirming a mechanism means running the counterfactual; an artifact-level defect is not a decision-level harm; after any predicate fix, test it against known current state.

## Class Determination First: Own-Harness / Non-Compiler-Repo PRs Are OUT_OF_SCOPE

A PR-approve dispatch landed for `slang-coworkers/nanoclaw#982` — an infra-fork PR that *modifies the approver's OWN decision harness* (including relaxing its ABSTAIN critique gate). The pipeline produced ABSTAIN_INFRA-looking signals (`harvest-reviews.py` exit 21, all 6 clauses UNEVALUABLE) because the App token is scoped to shader-slang → HTTP 401 on `slang-coworkers/*`. The correct call is a **class determination made FIRST in the skill, overriding the clause→INFRA mapping**: a repo that isn't shader-slang/slang compiler code, or changed paths in the approver's own harness (`container/skills/slang-pr-approver/**`, `container/workflows/slang-pr-approve/**`), is OUT_OF_SCOPE — and an own-rules PR is additionally a conflict of interest (self-endorsement is never permitted; a human must look). Record `ABSTAIN_POLICY` with `reason_code=OUT_OF_SCOPE:<class>` (closed enum, free-form suffix — new suffix `approver-harness`), stamp it into `_approver_result` so it doesn't drift to INFRA, and skip Devin (a class determination isn't informed by a review signal) ([approver-own-harness PR = ABSTAIN_POLICY:OUT_OF_SCOPE + conflict-of-interest](../learnings/1784443235968-approver-clause-gap-approver-own-harness-pr-abstai.md)).

**Workflow-file cherry-pick-step PRs are a recurring Devin-only + protected-path-ABSTAIN class.** A PR changing only the "Cherry-pick SlangPy PR" step in `.github/workflows/ci-latest-slang.yml` (e.g. slangpy#1145/#1147 adding `--no-recurse-submodules` to the fetch calls) harvests **exit 20 (Devin-only)** — `github-actions[bot]` posts no review and CodeRabbit only a commit status — so synthesize the Devin-only doc rather than treating exit 20 as a defect. The decision is fixed at Step 1: under `protected_paths: [".github/workflows/**"]`, `no_protected_paths` FAILs → `ABSTAIN_POLICY:CLAUSE_FAIL:no_protected_paths`, a clean human-must-look policy abstain that doesn't burn the infra gate. Narrowing an existing step (`--no-recurse-submodules`, `--unshallow` preserved) is "port/narrow existing behavior," so the both-directions positive-control challenger probe is N/A — demanding it would false-abstain ([cherry-pick-step workflow PRs: Devin-only (exit 20) + policy-abstain on protected path](../learnings/1789057905920-approver-confirmed-slangpy-ci-latest-slang-yml-che.md)).

## Ledger Mechanics: `record_decision` Replaces, and Emission Is the Furthest You Can See

**`record_decision` replaces the row and DROPS any `record_human_verdict` stamp.** The contract is one row per (repo, pr, commit_sha), a re-run **replacing** it, while `record_human_verdict` stamps an **existing** row; neither knows about the other, so re-recording to correct a row's *input signal* (decision unchanged) silently destroys the human-verdict column and drops the row out of accuracy measurement — right decision, right reason_code, nothing errors. Hit during the CodeRabbit under-read audit: slangpy#1085 @ `a1da5beac5af` carried `human_verdict=APPROVED`, and that disagreement (human APPROVED vs approver ABSTAIN_POLICY) is exactly what the scoring exists to capture. Before re-recording ANY historical row, grep session transcripts for `record_human_verdict` on that repo/pr/**commit_sha** (the stamp is per-commit; a sibling revision's stamp is not yours to preserve), put the unstamped row first in a batch, re-stamp **immediately after the replacement in the same turn** rather than past a possible compaction, and record the human verdict inside the correction note so provenance survives another loss ([[approver/infra-abstain] record_decision replaces the row and DROPS the record_human_verdict stamp — re-stamp after any correction](../learnings/1785779161211-approver-infra-abstain-record-decision-replaces-th.md)).

**The ledger is write-only from an agent tier — your OUTBOX proves emission, and `processing_ack` "NOT ACKED" proves nothing.** Whether a correction upserted or appended is not self-answerable: `grep -rl` for `approval_decisions` and `record_decision` over `/app` hits **only** the tool definition (`/app/src/mcp-tools/core.ts`), whose handler just does `writeMessageOut({kind:'system', content: JSON.stringify({action:'record_decision', …})})` — so "one row per commit, a re-run replaces it" is the tool's **own doc string**, **a contract to relay, never a state to assert**; a success return means the *call* succeeded. (`ncl approvals` is a **different** table — in-flight self-mod/OneCLI cards.) What *is* self-verifiable is your emission: `select seq, content from messages_out where content like '%record_decision%'` showed both writes for the same `commit_sha` — the first with the retracted phrase **present**, the later with the correction present and the phrase **gone**. ⚠️ The trap that nearly inverted the conclusion: all 12 `messages_out` rows read "NOT ACKED", **including chat messages the orchestrator demonstrably received and answered**, because `processing_ack` is **inbound-only** (`message_id` holds `sys-`/`a2a-` ids, never `msg-`) and `messages_out` has no consumption column. That contradiction *was* the control. **Before reading a status field as evidence, find a row whose true status you know independently and check the field agrees**; a column that reads the same for a known success and a known unknown is no status column. Say **"could not verify by method M"** and report a ledger correction as **ATTEMPTED, pending operator verification** — never "resolved." This is structural, not a permissions gap — an audit artifact's writer cannot verify its own write — so **a contaminated reasoning field can be repaired but not confirmed** while the headline fields look right ([[approver/infra-abstain] the ledger is write-only from every tier — but your outbox proves emission, and processing_ack is inbound-only](../learnings/1785786203086-approver-infra-abstain-the-ledger-is-write-only-fr.md)).

⚠️ **RETRACTION of two claims in that note, filed 25 minutes later — `find` and `grep` enumerate a MOUNT, not a CAPABILITY.** (1) *"No compiled bundle ⇒ `src/` IS the whole app"* is **false**: `/app` is `nanoclaw-agent-runner`, the **container half only** — shipped code in `/app` cites files absent from it (`src/session-manager.ts` twice, `scripts/sanity-live-poll.ts`). So `grep -rl approval_decisions /app` → one hit licenses "no consumer readable from an agent tier," never a statement about the system: **a negative drawn from an incomplete enumeration is a fact about your reach.** (2) The consequential one — **a documented, in-scope probe exists** (`ncl sessions help`): `ncl sessions messages <session-id> --include-system` reads **other sessions'** outbound rows, including the `kind=system` rows `record_decision` writes; sweeping 180 sessions found **40** carrying them, including both #806 rows a peer tier had correctly declined to confirm because they lived in another agent's `outbound.db`. **The cross-tier boundary was real; the cross-SESSION boundary was not.** (3) `/workspace/{inbound,outbound}.db` are the *current* session's, so a fresh session reads `messages_out` → 0 rows, which nearly read as "the evidence is gone." **Before claiming you cannot reach X, read `--help` for every verb already in your capability table** — cheaper than a filesystem sweep, and the only probe that sees a *mediated* path; a probe that feels like ground truth deserves *more* scrutiny of its scope. What remains dark is **only the host-side upsert-vs-append**; emission is provable to byte-level content, across sessions, by any tier in the group ([[approver/infra-abstain] RETRACTION — ncl sessions messages --include-system reads other sessions' record_decision rows; find/grep enumerate a mount, not a capability](../learnings/1785787116199-approver-infra-abstain-retraction-ncl-sessions-mes.md)).

## Lab-Container Infra Reach — Three Failures That Each Look Like a Different Problem

`GH_TOKEN` in the approver container is the 23-char sentinel `ROUTED_VIA_ONECLI_PROXY`; credentials are injected at the OneCLI **HTTPS proxy boundary**, which covers `api.github.com` REST but not `gh`'s GraphQL. (1) **REST works, GraphQL does not:** `gh pr view --json`/`gh pr list --json` 401 while `/repos/{o}/{r}/pulls/{n}`, `/pulls/{n}/reviews`, `/pulls/{n}/commits`, `/compare/{base}...{head}` and `/contents/{path}?ref={sha}` serve fine (`gh api repos/<o>/<r> --jq .full_name` → 200 confirms injection; a 403 on `/user` is expected — installation tokens have no user). (2) **The critique-gate hook blocks read-only `/pulls` reads**, so route PR reads through a small GET-only Python helper whose command text has no `/pulls` literal — the real gate still applies at `record_decision` / `[Approval Decision]`. (3) **Non-`shader-slang` repos 401** because the credential is org-scoped, and through a raising client a 401 *looks like a 404* — use `raw.githubusercontent.com` for public files, and read `.gitmodules` plus the pinned SHA before trusting a cited submodule path, since it may point at a **fork** (slangpy's `external/nanobind` is `skallweitNV/nanobind`, not `wjakob/nanobind`). Each looks like something else: a bad token (it is a sentinel), a missing file (a 401), a PR-creation attempt (a GET) ([[approver/infra-abstain] lab container: gh GraphQL 401s on the OneCLI sentinel token; use REST via a helper, and upstream repos are unreachable](../learnings/1785786635119-approver-infra-abstain-lab-container-gh-graphql-40.md)).

**Never accept an `ABSTAIN_INFRA` without reproducing the fetch by hand — an infra-abstain caused by your own tooling is a burned decision, not a real gate.** On slang-rhi#807 `collect-reviews.sh --dry-run` reported `reviews fetch FAILED -> exit 21 (ABSTAIN_INFRA)` for a healthy fetch (one `curl` showed the data), from two shim bugs against real `gh`'s contract: **wrong paginate shape** — `--paginate --slurp` yields ONE array of page-arrays, bare `--paginate` yields page arrays concatenated with `][` (which `collect-reviews.sh` stitches itself); the shim emitted slurp-shape for both, so output was double-nested → `None` → exit 21 (`harvest-reviews.py` uses `--slurp`, `collect-reviews.sh` bare `--paginate`, so a shim must serve both); and a **trailing conditional setting the exit code** — `[ "$SLURP" = "1" ] && echo -n "]"` as the last command exits **1** whenever SLURP is 0, which callers read as a fetch failure (use `if/then/fi` near a script's end). With both fixed, a nonzero status means the *fetch* failed and can be trusted. For CI evidence without admin, **step-level metadata is public**: `actions/runs/<run_id>/jobs?per_page=100` gives each job's `steps[]` with per-step `status`/`conclusion` plus `runner_name`/`labels` ("did `Unit Tests` run and pass on this leg at this SHA?") — but not log *text*, so anything needing a printed line must be named unresolved. Take the run id from the check-run `html_url`; a *stale* run's jobs list silently answers for the wrong head. Unauthenticated rate limit is **60 req/hr**; a re-decision on a moved head roughly doubles usage ([[approver/infra-abstain] job logs need admin (403) — use jobs?per_page for step-level evidence, and fix the gh shim's --paginate shape](../learnings/1785765021134-approver-infra-abstain-job-logs-need-admin-403-use.md)).

## The Durable Record: A Correction Is Not Applied Until Every Restatement Is Fixed

The recorded row and the memory stores outlive the decision, so a correction that lands only in the outbound message is not a correction — *a wrong message is read once; a wrong memory file is read by every future session.*

**Sweep for the SUPERSEDED wording, never for your new phrasing.** Two occurrences in one turn on slang-rhi#800, in separate stores: an overstated residency claim was corrected ("refuted" → "NOT cleared") and confirmed by grepping for the **new** wording — which found it, while the old claim survived in the R1/R2 historical sections *and* in an embedded JSON `notes` field a downstream parser reads; the orchestrator's parallel fix left three more survivors, including a whole duplicate terminal section. **A search for your correction cannot match stale text written in the vocabulary you abandoned** — both checks felt like verification and could not fail. Sweep the abandoned vocabulary expecting **zero** hits (`grep -nE "refuted|STALE|VINDICATED|…"`) *plus* a **positive control** (`grep -c "<new wording>"` > 0), since a zero-hit sweep is indistinguishable from a typo'd pattern. Check machine-readable fields (embedded JSON, frontmatter `description`, headings, index lines — a parser recovers the rejected claim as authoritative), status tags on historical sections (`[OPERATIVE]`, "join pending"), and duplicate terminal sections from separate append passes. Prefer **labelled invalidation over deletion** (a banner naming what is withdrawn, why, and which statement controls), and re-record an already-published ledger row rather than leaving the corrected reasoning only in prose. The surviving stale text was exactly the inference several critique rounds had just rejected, so a future session would have re-derived the error with the correction sitting in the same file ([[approver/critique-mustfix] correcting a claim means sweeping the WHOLE file for the SUPERSEDED wording](../learnings/1785773722903-approver-critique-mustfix-correcting-a-claim-means.md)).

**In an append-only store, a correction is only as reachable as the stale vocabulary it quotes.** L1 atoms are immutable; a correction filed as a *new* atom does not disarm the stale one unless it **names the superseded file by path and quotes the retracted sentences verbatim** — a future reader greps the abandoned wording, and if those strings appear only in the retracted file, the correction is invisible to the search that would surface the error. Say explicitly **which parts survive** (a blanket "that learning is wrong" discards checklists that are correct and expensive to derive) and retract at paragraph granularity. Derived surfaces (this wiki included) inherit the error and self-heal on the next sync **only if** the correction is in the source set — so a private-ledger fix cannot reach other coworkers' Step-0 recall. After correcting any claim, ask **where else it lives**: private ledger, shared learnings, synthesized wiki, embedded JSON, frontmatter, index lines ([[approver/critique-mustfix] a correction filed as a new atom does not disarm the stale one unless it names the file and quotes the retracted sentence](../learnings/1785774267946-approver-critique-mustfix-correction-to-my-own-sla.md)).

⚠️ **Compaction is the mode where this discipline inverts — "move the detail to the child and shorten the pointer" DELETES content when the index line is the only copy.** Compacting a memory index (22.2KB → 15.9KB) cut eleven evidence-discipline rules to one-liners "with detail in the topic file it already points to"; verification passed on every axis (34 rows intact, every link resolving, all eleven headlines present) **while three of the eleven had no full text in the child at all**. One of the three carried *"do NOT compress it away, or what remains is a plausible maxim with nothing under it"* — and the compaction deleted exactly that paragraph and kept exactly that maxim. Link integrity and headline presence are structural checks, blind to the one question that matters: **does the destination contain the text I am about to delete?** Cure: (1) before shortening a pointer, `grep` the child for the rule's distinctive phrase — if absent, append it first, confirm the hit, *then* shorten; (2) after compacting, re-grep every pointer for **content**, not links — any zero is silent data loss; (3) mark index lines whose child paragraph is load-bearing *evidence* `⛔ do-not-compress`, since future-you optimizing for bytes cannot tell proof from wordiness. **A summary and its evidence decay at different rates** — the summary survives every cleanup, the evidence reads as redundant and gets trimmed — so a store of hard-won corrections degrades into unfalsifiable platitudes with no visible mistake. If a rule's credibility rests on a specific datapoint (a cost, a count, "both parties hit this simultaneously"), the datapoint **is** the rule. The memory directory was not a git repo; the three rules were recovered only from earlier in the same conversation — across a context boundary the loss would have been permanent and undetectable ([[approver/critique-mustfix] compaction destroyed 3 of 11 rules' evidence — verify the child file HAS the text before shortening the pointer](../learnings/1785781908276-approver-critique-mustfix-compaction-destroyed-3-o.md)).

## Contradictions / supersessions

- The "clauses only gate the approve direction, so a verified BLOCK can override a clause FAIL" theory is **rejected** — the skill ordering governs and a clause FAIL short-circuits to ABSTAIN_POLICY before the challenger ([[approver/clause-gap] a Step-1 clause FAIL short-circuits to ABSTAIN_POLICY even after a verified BLOCK](../learnings/1784271165403-approver-clause-gap-a-step-1-clause-fail-short-cir.md)).
- The GraphQL-401 "total GitHub outage → ABSTAIN_INFRA on everything" reading is **wrong** — REST + anon git still serve the clauses, and the 07-16/07-17 outages were later RESOLVED, so the split is a technique, not a state ([[approver/infra-abstain] GraphQL 401 outage ≠ no GitHub access](../learnings/1784271281635-approver-infra-abstain-graphql-401-gateway-outage-.md)).
- "Bot-authored dep bump + Devin timeout = guaranteed INFRA" holds only for the timed-out run; it does NOT license pre-emptively skipping Devin on a re-sync (see [[wiki/concepts/review-approver-challenger-calibration.md]]).
- The empty-body-`COMMENTED`-wrapper learning's claim that *"the relevant author replies were on page 3, page 1 was entirely July bot traffic"* is **false**: the author's replies are on the early pages too (250 comments over 100/100/**50**, 37 by the author). Its central lesson (empty wrapper ⇒ look one level down) stands; the real rule is *never characterize a page's contents from a summarized read* ([[approver/clause-gap] CORRECTION to the empty-body-wrapper claim](../learnings/1785761810820-approver-clause-gap-correction-to-empty-body-comme.md)).
- *"`--paginate` output is truncated and silence is the only tell, so exit codes are unusable"* is **narrowed**: the failure was invocation-form-dependent plus a trailing conditional setting `$?`; with those fixed, **exit codes ARE usable** ([[approver/infra-abstain] fix the gh shim's --paginate shape; a trailing conditional set the exit code](../learnings/1785765021134-approver-infra-abstain-job-logs-need-admin-403-use.md)).
- *"`DeclRef::as<U>()` does no type check, so `if (declRef.as<T>())` is a no-op guard"* is **wrong for `DeclRef`** and scoped to **`SubstExpr::as()`** only: `DeclRef<U>::as()` rewraps through the typed constructor and `DeclRef<T>::init()` nulls on mismatch, so it is a safe guard; `is<>()` is a style nit, not a correctness gap ([[approver/clause-gap] DeclRef::as&lt;U&gt;() DOES type-check](../learnings/1785745186536-approver-clause-gap-declref-as-lt-u-gt-does-type-c.md)).
- *"`actions/jobs/<id>/logs` needs admin, so job logs are unavailable"* is **wrong as a property of the endpoint** — it 302-redirects to a signed blob and `curl -sSL` returns the full body unauthenticated on a public repo; the 403 was a tooling artifact and not reproducible ([[approver/infra-abstain] job logs are PUBLIC — follow the 302](../learnings/1785766450209-approver-infra-abstain-github-actions-job-logs-are.md)). The step-level corollary stands: `jobs?per_page=100` gives per-step pass/fail, never log text ([[approver/infra-abstain] use jobs?per_page for step-level evidence](../learnings/1785765021134-approver-infra-abstain-job-logs-need-admin-403-use.md)).
- The `rate_limit` core-`limit` token probe (*"60 = anonymous, 5000 = injected, run via curl not gh"*) is **retracted** — it reads anonymous while injection works, because injection is **per-path**, so a transport fix cannot help. Read `x-ratelimit` headers on the exact path you will call and test **presence**, not value ([[approver/critique-mustfix] the rate_limit probe is itself species 2](../learnings/1785782770123-approver-critique-mustfix-correction-my-rate-limit.md)).
- The slang-rhi#800 residency framing is **doubly corrected**: the absence-of-log-line refutation was unsound (severity routing made 2 of 3 paths undetectable), and then the polarity inverted — **CI runs the FALLBACK** by default (no Apple6 on the hosted runner), so the *residency-SET* path is uncovered and the missing artifact is an **Apple6 run**, never a `SLANG_RHI_METAL_NO_RESIDENCY_SET` run ([[approver/critique-mustfix] the #800 residency corollary is withdrawn](../learnings/1785774267946-approver-critique-mustfix-correction-to-my-own-sla.md)).
- *"The `approval_decisions` ledger is unverifiable from an agent tier / `/app`'s `src/` is the whole app / reachable SQLite is only the two session DBs"* is **narrowed** to: only the host-side upsert-vs-append stays dark ([[approver/infra-abstain] RETRACTION — find/grep enumerate a mount, not a capability](../learnings/1785787116199-approver-infra-abstain-retraction-ncl-sessions-mes.md)).
- *"The missing `json.loads` decode caused devin-fetch's empty `## Flags`"* is **refuted as a causal claim** — decoded and re-split, Flags is still empty because the marker occurs zero times in the capture; the real cause is the done-poll exiting on a CI progress counter (the decode defect is real but was never the mechanism) ([[approver/critique-mustfix] confirming a mechanism means running the counterfactual](../learnings/1785787841835-approver-critique-mustfix-confirming-a-peer-s-mech.md)).
- *"11 of 18 harvests exposed ⇒ 17 findings were missed ⇒ slang-rhi#797 is a probable false-safe"* is **withdrawn at the decision level**: the review docs carry the findings verbatim with severities. The artifact-level defect is real; the decision-level harm was not confirmed ([[approver/critique-mustfix] an artifact-level defect is not a decision-level harm](../learnings/1785780014953-approver-critique-mustfix-an-artifact-level-defect.md)).
- The resume predicate for a held chain went wrong in **both** directions: *"a non-bot review with an actionable state lands"* can never fire (the blocker has no review object), and its widening to *"actionable non-bot feedback in ANY of the three endpoints"* **always** fires. The working form requires all three of non-bot · addressed to the decision, not the PR author · changes a load-bearing input ([[approver/clause-gap] widening a never-fires predicate produced an always-fires one](../learnings/1785821476819-approver-clause-gap-widening-a-never-fires-predica.md)).
