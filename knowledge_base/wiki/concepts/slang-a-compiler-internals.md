## TL;DR

- **Model an absent IR operand as fewer operands, never a null operand**; the call-graph walk dereferences every operand unguarded. Gate accessors on operand count (`IRDebugInlinedAt` builds 4 or 5); `min_operands` is not validator-enforced.
- **An IR op *mentioned* in a consumer is not *handled*.** Read each branch body for the property you care about; sibling `case` labels mislead most.
- **A best-effort specialization/legalization pass is not a reachability guarantee.** Check whether it errors or silently skips (a ternary func value reaches CUDA emit at exit 0, then `nvcc` fails).
- **A fix can create an exposure master never had** (simplifyCFG two-walk block-merge). Prefer structurally immune iteration (walk params, not filtered children).
- Global-var initializer blocks have no parent function until `moveGlobalVarInitializationToEntryPoints`; passes walking only `IRFunc` bodies miss or assert on them.
- A named profiler bucket can be empty on your path (spirv-direct skips `emitEntryPointsSourceFromIR`); empty reads like "cheap".
- C-like emitter fold legality must follow every force-folded (Always-policy) user to its final use, in one cached linear pass. `fixValueScoping` sees only direct uses: clone a cross-block folded def before the user and re-scope its operands.
- **slangc's exit code is the DiagnosticSink error count, not the `SlangResult`.** An undiagnosed `SLANG_FAIL` exits 0; a local sink + `nullptr outDiagnostics` is a black hole; `-o /dev/null` fails for binary targets on Linux too.
- Making a step fail on emitter errors can expose tests relying on ignored errors: move the test to supported targets (no target guard); compare error counts before/after, not against 0.
- HostVM: guard unrepresentable types at storage-defining sites, keyed on the layout query failing, never on size==0.
- Confirm a source-traced symptom at HEAD; a prebuilt's different symptom is often the truth.
- **Per-frame size is a stack budget in recursive checker/emitter paths** (#13514). A crash threshold that moves with `ulimit -s` proves recursion; invariance proves nothing. A C-like-vs-SPIR-V differential localizes the stage.
- **Localize a hang with no debugger:** LD_PRELOAD SIGPROF sampler + `addr2line` on the split-dwarf `.dwarf`; the sample distribution is the finding. `-dump-ir` is useless for a hang.
- The `.slang-module` embed path is nondeterministic (heap pointers); size and hash are unsound equality tests (use `cmp -l`).
- Precompiled-code provenance needs a guilty control (corrupt an embedded blob → link fails), not "exit 0 + same op counts".
- **Two option sets:** `TargetProgram` vs `TargetRequest`, inheritance request→program only. Name which set each side reads/writes.
- `__include` + `implementing` is ONE module; audit graph depth by resolving imports, not counting files.
- A value computed only for a `SLANG_ASSERT` is `#ifdef _DEBUG`-guarded with the assertion; GCC's `SLANG_ASSUME` fallback evaluates its operand. A usage contract is not a statement of fact.

## Modeling IR: operands, ops, and the "present ≠ handled" trap

Build an inst with an optional trailing operand with **fewer operands** and gate the accessor on the count; never construct a fixed-arity inst with a `nullptr` operand. `buildEntryPointReferenceGraph` (`slang-ir-call-graph.cpp:85-88`) dereferences every operand's `getOp()` with no null check before SPIR-V emit, so a null crashes far from where it was built. The precedent is `IRDebugInlinedAt`: it declares 5 operands but builds 4 or 5 (`if (outerInlinedAt)`), with `getOuterInlinedAt()` gated on `operandCount == 5`; `min_operands` feeds `IROpInfo::fixedArgCount` and is never checked against the actual count. The lurking hazard is `IRDebugNoScope::getScope()`, a bare `getOperand(0)` on a 0-operand inst: the `SLANG_ASSERT` trips in debug but reads garbage in release. A shipped precedent beats "no validator forbids it" [absent operand = fewer operands (IRDebugInlinedAt precedent)](../learnings/1785897823903-slang-ir-model-an-absent-operand-as-fewer-operands.md).

Grepping that a destination op is *mentioned* in every consumer proves only that control reaches the code, not that the handling is equivalent. On PR #11709 all three param-mode ops sat on consecutive `case` lines in `slang-ir-inline.cpp`, but `kIROp_RefParamType` force-inlines regardless of `[noinline]` (honoring only `IRNoRefInlineDecoration`), while the Borrow ops bail out when the arg roots at a var/global, which is why `[noinline]` works for them. Moving `groupshared` from `BorrowInOut` to `Ref` would have destroyed the `[noinline]` boundaries that three new diagnostics were shipped to protect. Name the property, read the branch body, and use a two-sided control (`__ref` destroys the boundary, `__constref` keeps it; either alone proves nothing) [an op MENTIONED is not HANDLED](../learnings/1785857072008-an-ir-op-being-mentioned-in-a-consumer-is-not-the-.md).

## simplifyCFG block-merge: a fix that introduces its own exposure

On #12343 a `throw` of an existential-typed value in `do{}catch{}` hangs `slangc`. Block-merge in `processFunc` walked `successor`'s child list while `replaceUsesWith` re-parented hoistable insts (`lookupWitness`/`extractExistential*`), rotating the list forever. The obvious two-walk fix ("move non-params first, then replace params") introduces an exposure master lacks. In master a hoistable user moves only while it still shares `successor` as parent, so `tryHoistInst`'s guard fires; after walk 1 the user lives in `block`, the guard no longer fires, and `mergeCandidateParentsForHoistableInst` can hoist it back into the list a child-filtering second walk is traversing. Iterating params is structurally immune: `getNextParam()` returns null at the first non-param, so a re-hoisted user never becomes the cursor. Calling it "pre-existing" was wrong: the guard was evaluated against the pre-walk-1 state. A two-param regression test would be vacuous (0 merges with ≥2 params across 7,429, with a firing nested control) [two-walk block-merge creates a new hoist exposure](../learnings/1785873979004-slang-simplifycfg-block-merge-splitting-the-walk-i.md).

## Codegen reachability: passes that skip, buckets that are empty

Finding the pass that eliminates construct X does not answer "can X reach emit?"; check whether the pass errors or silently skips. `specializeHigherOrderParameters` runs for CUDA, but `slang-ir-specialize-function-call.cpp` silently skips an unspecializable call, so a func value from a ternary or struct field emits `Slang_FuncType<int,int>` into CUDA at exit 0 and `nvcc` fails. The same input breaks 4 targets with 3 spellings from 2 producers (Metal has no `kIROp_FuncType` case and falls through to an op-name fallback emitting `Func<...>`), so a CPP-emitter fix alone does not close the class [best-effort specialization is not reachability](../learnings/1785940519756-a-best-effort-specialization-pass-is-not-a-reachab.md).

**Code in a global-variable initializer has no parent function until `moveGlobalVarInitializationToEntryPoints` runs**, so passes that walk only `IRFunc` bodies miss it or assert on it. Branch coverage is the worked example (#13278 triage). `-trace-branch-coverage` markers are emitted during lowering by `StmtLoweringVisitor::emitBranchCoverageMarker`/`allocateCoverageBranchSiteID` (`slang-lower-to-ir.cpp` ~:8209), not by an IR pass, and `?:`/`&&`/`||` get none only because their visitors never call these helpers. `collectCoverageMarkerOps` (`slang-ir-coverage-instrument.cpp` ~:1097) walks only `IRFunc` (and generic-inner) bodies, and `getRemappedBranchSiteID` release-asserts `getParentFunc(marker)` (~:1265). The pass runs in `linkAndOptimizeIR` before the initializer move, and `static bool g = a && b;` lowers its short-circuit diamond into the `IRGlobalVar` initializer (a scalar `?:` bails to `select`). So a new marker site must gate on `getParentFunc(insertLoc)` as `visitSelectExpr` does [coverage markers are lowering-time, collected only from IRFunc](../learnings/1790588585622-slang-branch-coverage-markers-are-lowering-time-an.md). Type legalization loses such initializers the same way; see [[wiki/concepts/slang-compiler-ir-type-legalization.md]].

**A named profiler bucket can be empty on the path you care about, and empty reads like "low cost."** For `-target spirv`, `CodeGenContext::_emitEntryPoints` (`slang-code-gen.cpp:1169-1175`) routes to `emitSPIRVForEntryPointsDirectly` (definition `slang-emit.cpp:3670`) → `createArtifactFromIR` → `emitSPIRVFromIR` (`slang-emit-spirv.cpp:12161`), none carrying `SLANG_PROFILE`; the text path's `emitEntryPointsSourceFromIR` (`slang-emit.cpp:2891`) is bypassed and spirv-opt is untimed, so both costs land in the `generateOutput (self)` residual. Verify the path reaches the instrumented function before citing a timer; hedge "unattributed, not invisible". A bare `slangc` vs `glslangValidator` timing compares ~16 spirv-opt passes to zero (glslang defaults `disableOptimizer=true` for GLSL) [a named profiler bucket can be EMPTY](../learnings/1785954775731-a-named-profiler-bucket-can-be-empty-on-the-path-y.md). Filed as #13016; the fix is the symmetric `SLANG_PROFILE` mirror on `emitSPIRVForEntryPointsDirectly`, which `tools/compile-perf/breakdown.py` already nests. Prove it GPU-free with `-report-detailed-perf-benchmark`: spirv-direct shows `generateOutput` with only `linkAndOptimizeIR` and a ~6 ms residual; an HLSL control shows `generateOutput == emitEntryPointsSourceFromIR`. The issue's line numbers point at forward declarations; cite definitions. For reporter-owned perf issues (#12941 initiative), triage and recommend but hold the bot fixer so the reporter folds the fix into their branch [SPIR-V direct emit is unprofiled (#13016)](../learnings/1789157504641-spir-v-direct-emit-path-is-unprofiled-fix-is-the-s.md).

`-Xspirv-opt` is **structurally unreachable for text targets**: its one call site (`slang-emit.cpp:3385`) is reached only from `case CodeGenTarget::SPIRV` + `shouldEmitSPIRVDirectly()`. The guilty control is dispositive: `-target spirv -Xspirv-opt <bogus-pass>` errors, `-target hlsl -Xspirv-opt <bogus>` exits 0 (silently discarded). spirv-opt pass names need the double dash. `--strip-debug` keeps Slang reflection working (served from Slang's layout data, not the blob). Check the stage an option operates at against the stage the use case reaches [-Xspirv-opt is SPIR-V-only](../learnings/1785954407063-xspirv-opt-is-structurally-unreachable-for-text-ta.md).

## C-like emitter folding: legality must follow force-folded users (#13273)

Consider `s.a[s.top] = bump(s);`, or a `pop` that reads `s.a[s.top]` after `s.top -= 1`. `CLikeSourceEmitter::shouldFoldInstIntoUseSites` (`slang-emit-c-like.cpp`) force-folds `getElementPtr`, `FieldAddress` and pointer- or resource-typed values, but its side-effect scan covered only the instructions between an operand and its DIRECT user. The index load folds into the GEP, the GEP is re-materialized at its later use, and the index is re-read after the store or call. Triggers: simplifyForEmit's `processLoadUse` legally defers `load(gep)` past a non-aliasing store, and `s.a[s.top] = f(s)` needs no deferral (the IR computes the address first; the text evaluates the index after the call). All textual backends are wrong; SPIR-V is right. `-dump-ir` looks correct, `-g` masks only the deferral variant, and slang-test's `-cpu`/`-cuda` runtime paths returned correct values while `slangc -target cuda` text was wrong, so regressions belong in text FileCheck [fold scan is not transitive through force-folded GEPs](../learnings/1790497097531-c-like-emitter-fold-scan-is-not-transitive-through.md).

The fix (`fix/issue-13273`, 1817cc19ac) splits the predicate into `getFoldPolicy` (Never / Always / WhenSafe) and a use-position check recursing only into Always users (a WhenSafe user validated its own use). Two performance traps: calling `shouldFoldInstIntoUseSites(user)` per level is O(depth²), and an uncached per-use rescan makes a many-use GEP (unrolled `gs[idx]`) cubic. One forward scan to the last use, cached during `emitRegionTree`, is safe because body IR is stable and `fixValueScoping` has run (benchmarks: a 3000-deep folded chain, an N=800 `[ForceUnroll]` loop). Extra temporaries churned three goldens under the coarse `mightHaveSideEffects` model: `metal/atomic-intrinsics`, `compute/unbounded-array-of-array-syntax` (CUDA), `cross-compile/geometry-shader-global-array-12169` (GLSL) [fold legality must follow Always users, linearly](../learnings/1790504140643-slang-c-like-emitter-fold-legality-must-follow-alw.md).

**Any fold change also interacts with `fixValueScoping`, which sees only DIRECT uses.** Consider `if (c) { x = s.a[t*2]; } else { return 0; } s.a[t*2] = x + 7;`. Dominance-scoped `removeRedundancy` lets the store reuse the then-block's GEP, since the other branch returns. `fixValueScoping` (`slang-ir-restructure-scoping.cpp`) hoists the out-of-region always-folded GEP with `addHoistableInst` only to just after its last operand, still inside the branch, and never revisits that operand. A folded inst's operands are emitted at its use sites, so once `t*2` stops folding into the GEP its temporary is declared inside the branch and used after it: glslang/dxc report `'_S2' : undeclared identifier` on GLSL/HLSL/WGSL/Metal/CUDA. PR #13283 hit this; it was already a silent master miscompile for a multi-use index. The fix: if the use is still out of scope after hoisting, `cloneInst` the folded def before the user and re-run `fixValueScopingForInst` on its (already visited) operands. GPU-free repros that make scoping bugs hard errors: `-target spirv -emit-spirv-via-glsl` (runs glslang; test form `//TEST:SIMPLE(filecheck=SPV): -target spirv-asm -emit-spirv-via-glsl` + `// SPV: OpEntryPoint`), `-target dxil -profile cs_6_0` (runs dxc), or a `-cpu` runtime test ([emit CSE creates cross-block folded GEP uses](../learnings/1790620041750-slang-emit-cse-creates-cross-block-always-folded-g.md), [folded insts' operands are emitted at the uses](../learnings/1790626574492-slang-fixvaluescoping-folded-insts-operands-are-em.md)).

## Localizing a compiler hang with no debugger

The container has no `gdb`/`lldb`/`perf`/`pstack`, and `-dump-ir` is useless for a hang (`DiagnosticSinkWriter` is never flushed: a 0-line file even under `stdbuf`). Build a ~30-line `LD_PRELOAD` shim whose constructor installs a `SIGPROF` handler (`backtrace` + `backtrace_symbols_fd` to a raw fd, no `printf`) and arms `setitimer(ITIMER_PROF, ...)`, which fires on CPU time and so samples only while spinning. Call `backtrace()` once in the constructor first; lazy init inside the handler can deadlock. The **distribution is the finding**: 80/80 (#12343) or 203/203 (#12362, `findErrorHandler`) samples on one line-range, with zero in sibling sub-transforms, kills competing theories that a single stack cannot. The Debug build has split debug info, so `backtrace_symbols_fd` prints only `lib(+0xOFFSET)`; resolve the library-relative offset with `addr2line -f -C -e <lib>.dwarf`, not the `.so`, and histogram the innermost slang frame. Cheap discriminators first: RSS flat but utime climbing ⇒ spinning, RSS growing ⇒ runaway allocation; narrow the phase with `-skip-codegen` plus a control proving the flag takes effect. Confirm the mechanism with a counter that `abort()`s at N, printing both data structures' before/after state. `auto next = inst->getNextInst()` is safe against removing the current node, not against a callee re-parenting other nodes [LD_PRELOAD SIGPROF sampler + addr2line](../learnings/1785862700777-localize-a-compiler-hang-with-no-debugger-ld-prelo.md) [split-dwarf addr2line recipe](../learnings/1785920959839-locating-a-slang-compiler-hang-with-no-debugger-ld.md).

## Localizing a stack overflow: stack-size sweep + differential-target test

A Debug-only `STATUS_STACK_OVERFLOW`/SIGSEGV suspected to be input-linear recursion can be confirmed and localized GPU-free (#13018). **A stack-size sweep is a positive recursion signature.** slangc compiles on the caller's main thread with the OS-default stack (no large-stack worker thread exists in the compiler), so `ulimit -s <KB>` constrains it directly. If the crashing input size N moves monotonically with the stack, that is linear-depth recursion (`ulimit -s 512`: N≤260 ok, ≥280 → rc=139); rc=139 invariant under a growing stack proves nothing (an out-of-bounds pointer faults regardless). **A differential-target test localizes the stage.** The C-like source emitter (`slang-emit-c-like.cpp`) recurses `emitInstExpr(:2381)→emitOperand(:2656)→emitOperandImpl(:2019)→shouldFoldInstIntoUseSites(:1495)→emitInstExpr` while folding single-use chains; SPIR-V does not use it, so C-like targets crashing while `-target spirv` compiles at a tiny stack puts the recursion in source emit, not an IR pass. In #13018 an N-texture accumulator (`acc += tex_i.SampleLevel(...)`) folds into one left-leaning expression (a ~22 KB `.cu` line). The fix caps fold-chain depth at the `shouldFoldInstIntoUseSites`/schedule layer so deep chains materialize bounded temporaries, not a mid-recursion `getName` bailout in `emitOperandImpl` (which would name an inst never given its own statement). No emit-path recursion guard exists; `kMaxTypeNestingDepth`=128 is front-end-only ([stack-size sweep + differential-target test (#13018)](../learnings/1789158062330-localizing-a-compiler-stack-overflow-stack-size-sw.md)).

The front-end checker has the same budget. #13514 passed PR CI and then failed the merge queue: Windows Debug `test-slang` died with 0xC00000FD on `tests/glsl-intrinsic/intrinsic-texture.slang`, whose 294-operator `&&` chain recurses once per operator through `visitInvokeExpr` → `CheckExpr` → `_CheckTerm` → `dispatchExpr`. The PR built a `SemanticsVisitor sub(withX(...))` copy in `visitInvokeExpr`, `visitIndexExpr` and `visitTypeCastExpr` (~544 B per level at -O0), and a pointer field placed after a 4-byte enum grew `SemanticsContext` from 168 to 184 B, which `dispatchExpr` and `_CheckTerm` also copy per level. The fix is an in-place RAII save/restore of the fields (like `OuterScopeContextRAII`) and padding-free field placement (`ptype /o Slang::SemanticsContext`). Reproduce on Linux with a `( ulimit -s N; slang-test <test>.0 )` bisection (master 399 KB vs PR 559 KB) plus a gdb walk of `$sp` between `visitInvokeExpr` frames ([a SemanticsVisitor copy per recursive frame overflows Windows Debug](../learnings/1792079649552-slang-checker-a-semanticsvisitor-copy-per-recursiv.md)).

## Silent-failure plumbing — where a real error becomes a quiet exit

**slangc's exit code comes from the DiagnosticSink error count, not the `SlangResult`.** When a failure path is silent, trace whether anything calls `diagnose()`, not the `SlangResult` chain. A failed SPIR-V downstream link returns `SLANG_FAIL` with no `diagnose()` (no link-failure diagnostic exists), the value is discarded up the chain, and every end-to-end gate reads `getErrorCount() != 0` ⇒ exit 0 with no output file. Reproduce with a duplicate entry point via `-embed-downstream-ir` (no GPU); count the SPIR-V magic `03 02 23 07` in the `.slang-module` as a provenance A/B (1 with embed, 0 without) [a SlangResult nobody diagnoses is invisible](../learnings/1785962770674-a-slangresult-nobody-diagnoses-is-invisible-slangc.md).

**A local `DiagnosticSink` plus a `nullptr` `outDiagnostics` is a diagnostic black hole.** `Module::precompileForTarget` builds a local sink with no writer; diagnostics accumulate in `outputBuffer`, and `getBlobIfNeeded(outDiagnostics)` returns `SLANG_OK` immediately for a null blob, which the CLI passes. Result: exit 255, no output, a real `E50100` discarded. Grep for `nullptr` at `API(..., ISlangBlob** outDiagnostics)` call sites when a tool exits nonzero silently, and recover the message with a ~30-line probe passing a real blob. `SLANG_ASSERT=system` does nothing on Linux (the branch is inside `#if _WIN32`), and exit 255 is nonspecific (every failed `spCompile` → `SLANG_E_INTERNAL_FAIL`), so never infer a failure kind from it [local sink + nullptr outDiagnostics](../learnings/1785959064285-a-local-diagnosticsink-plus-a-nullptr-outdiagnosti.md).

`-o /dev/null` fails on **Linux too**, for binary targets only. `ArtifactOutputUtil::writeToFile` branches on `isText(desc)`: text targets take a path that works, while binary targets hit `FileStream::_init`, where `Path::getPathType` rejects anything not `S_IFREG` (a character device) before `fopen`. A "Windows-only" fix for a path-shape check is the wrong shape. A null-path guard must not swallow real failures (test `-o /nonexistent-dir/out.spv`), and there are two `CannotWriteOutputFile` sites [-o /dev/null fails on Linux for binary targets](../learnings/1785967936973-o-dev-null-fails-on-linux-too-for-binary-targets-s.md).

Closing a silent-failure path can surface tests that relied on it. On PR #13724 the maintainer (jkwak-work) asked for `emitEntryPointsSourceFromIR` to return `SLANG_FAIL` whenever the source emitter adds an error, on every target, with no target condition. That broke `slang-unit-test-tool/cooperativeVectorTypeMetadata`, whose `cuda_optix` row compiled coop-vector ops that OptiX reports as E55204 and `getTargetMetadata` had been ignoring. The fix moved the test onto supporting targets (SPIR-V + HLSL; other tests still cover `cuda_optix`) instead of adding a target guard. Compare the sink's error count before and after `emitModule`, since it can already hold earlier errors; slang-test shows only `res == SLANG_OK` failing, so print the test's `diagnostics` blob temporarily ([failing on errors surfaces tests that relied on ignored errors](../learnings/1792463767876-making-a-compile-step-fail-on-errors-can-surface-t.md)).

The HostVM (slangi) version of the trap is a **crash**: a runtime value with no HostVM byte layout (a runtime `String`, aggregates containing it, the varargs `Tuple`) reaches a value-slot allocation, `getNaturalSizeAndAlignment` fails for `kIROp_StringType`, `ensureWorkingsetMemory` ignored the failure and returned a 0-byte slot, and `%s` dereferenced garbage → SIGSEGV 139 with no diagnostic (#13017). The fix diagnoses rather than adding VM String support: `getRepresentableSizeAndAlignment` records a fail-loud E52014 (deduped per `IRType*`) and returns a placeholder `(0,1)`, so `emitVMByteCodeForEntryPoints` returns `SLANG_FAIL`. Route the guard only at **storage-defining sites** (value slots, `kIROp_Var`/`kIROp_Store` dest pointees, the function-result slot); raw stride/offset queries are covered by the enclosing aggregate's guarded slot. Key on the query failing, never on size==0 (void/empty aggregates are legitimately zero-size) ([HostVM guard at storage-defining sites](../learnings/1789402835980-hostvm-slangi-unrepresentable-type-guard-check-at-.md)).

**A source trace can predict the wrong symptom; confirm the exact claim at HEAD.** #13093 claimed `countof` on a truly-unsized array ICEs at emit (`E99999 unexpected IR opcode`). At HEAD it compiles clean on every target and silently folds `countof(gArr)` to `4` (`sizeof(int)`), the `#11317`-class wrong-value miscompile (even `int fixed[8]` folds to 4). Source-only reasoning ("un-foldable `kIROp_CountOf` → emit ICE") missed that the wrong-value fold runs first. When a memo says a symptom "needs a HEAD build" and the prebuilt showed a different one, treat the claim as unverified. A checker fix rejecting `countof(unsized)` with E56002 is still valid, but the PR must frame it as fixing a miscompile, not an ICE ([#13093 ICE does not reproduce at HEAD](../learnings/1789485829159-slang-13093-countof-unsized-ice-does-not-reproduce.md)).

## Precompilation, module determinism, and truncated instrument output

A truncated `-dump-ir` on the precompile path reads as "no passes ran", but the ICE message refutes it: it names a `_std140` struct variant created by a late pass, so `-dump-ir` is simply not wired through that path. **When an instrument's output is unexpectedly small, ask whether the output itself contradicts the reading.** Also: `-embed-downstream-ir -o out.mod` writes nothing and exits 0 (extension must be `.slang-module`), and a `kIROp_ConstantBufferType` grep zero was a false absence (the file uses `as<IRConstantBufferType>`). The real asymmetry was `wrapRemainingConstantBufferElementTypes()` having no `ParameterBlockType` twin, which is why nested `ConstantBuffer` compiles and nested `ParameterBlock` ICEs [truncated -dump-ir on the precompile path](../learnings/1785959056296-a-truncated-dump-ir-on-the-precompile-path-reads-a.md).

Proving that precompiled target code was *used* needs discriminators, not "exit 0 + same op counts" (similarity, not provenance): disassemble the pre-link module (`OpFMul = 0` + `LinkageAttributes Import`), or corrupt ~24 bytes inside an embedded blob, confirm the link fails, then restore as the control. Slang also **validates the wrong buffer**: with `SLANG_RUN_SPIRV_VALIDATION=1` a precompiled-link compile fails on "Capability Linkage" though the shipped artifact is valid, because `slang-emit.cpp` validates the pre-link `spirv` buffer, never `linkedArtifact`. Every `tests/library/precompiled-*` test passes `-skip-spirv-validation`, corroborating a long-standing defect [precompiled-SPIRV provenance; wrong buffer validated](../learnings/1785957170037-precompiled-spirv-link-proving-target-code-provena.md).

The `.slang-module` **embed path is nondeterministic**: 3 identical runs give identical sizes but distinct MD5s, with exactly 12 bytes differing in three 8-byte slots holding raw `void*` heap pointers. It is embed-specific (a plain front-end module is bit-identical) and functionally harmless, because `isBinaryModuleUpToDate` hashes source+options, never the module bytes; only external content-addressing is exposed. Size and `md5sum` are both unsound equality tests: size is blind to the in-place change, and padded string fields make equal sizes expected across real differences (72 B vs 69 B paths, same 80-byte field). Use `cmp -l`. The module also embeds a cwd-derived source path, so enumerate what differs between edges before attributing a cross-edge delta to a mechanism [.slang-module embed path is nondeterministic](../learnings/1785968956916-slang-slang-module-nondeterministic-on-the-embed-p.md).

Precompilation limits are quotable from `slang-compiler-tu.cpp` ("no target languages allow generics to be precompiled"; DXIL rejects `StructuredBuffer`/`Matrix` in a library interface); `IModulePrecompileService_Experimental` is "experimental and not thread-safe since it mutates the module."

## Two option sets, module graphs, and `__include`

Slang has **two option sets that are not interchangeable**: `TargetRequest::getOptionSet()` (from the session) and `TargetProgram::getOptionSet()` (program override, then request inherit). Inheritance runs request→program only. `shouldRunSPIRVValidation` reads the TargetProgram, `doesTargetAllowUnresolvedFuncSymbol` reads the TargetRequest, and `precompileForTarget` adds options to a local TargetProgram. So `IncompleteLibrary` set in the precompile path never reaches the request-level unresolved-symbol gate, while a session-level `SkipSPIRVValidation` is honored. Grepping the option name distinguishes neither set [two option sets, one-way inheritance](../learnings/1786000309982-slang-option-gates-read-two-different-option-sets-.md).

A module split via `module "a"; __include "a-part.slang";` + `implementing "a";` is **one module**, but reads as a separate module in any file listing or `grep -l` census, so an A→B→C graph can really be A→B. Audit depth by resolving each `import "X"` to `X.slang` and counting that file's imports; `implementing` in the resolved file means depth does not increase. Measure the directives rather than carry the shape by analogy [__include + implementing is ONE module](../learnings/1785961765627-slang-include-implementing-is-one-module-that-read.md).

## `SLANG_ASSUME` / `SLANG_ASSERT`: a usage contract is not a statement of fact

Outside `_DEBUG`, `SLANG_ASSERT(X)` expands to `SLANG_ASSUME(X)`, whose branches differ in whether they evaluate the operand: `[[assume]]` and `__builtin_assume` do not, but the **GCC fallback** (`do { if (!(X)) __builtin_unreachable(); } while (0)`) does, and on the GCC 12 container `__cpp_assume` is undefined, so that branch is live (verified with a call counter). The header's "Do not rely on side effects of the condition being performed" is a usage contract (some expansions skip evaluation), not a claim that a given expansion skips it. Two agents published "SLANG_ASSERT never evaluates its argument" beside a correct measurement (a counting loop surviving `-O2`) that survives precisely because the operand IS evaluated; a correct measurement beside an inverted mechanism is worse than either alone. Rule: **a value computed solely for a `SLANG_ASSERT` is `#ifdef _DEBUG`-guarded together with the assertion**; guarding only the computation leaves the variable undeclared in release, so build release whenever you add such a guard. The justification needs no performance claim, and "release paid an O(n) walk" is unmeasured anyway (`SLANG_ENABLE_RELEASE_LTO` defaults OFF, so `-O2`-without-LTO evidence does not describe shipped artifacts). "Do not rely on X" means X is not guaranteed, not that X does not happen; find the code path and measure it if cheap [SLANG_ASSUME evaluates its operand on GCC](../learnings/1785883273838-slang-assume-evaluates-its-operand-on-gcc-and-the-.md).
