## TL;DR

- **Model an absent IR operand as fewer operands, never a null operand**; the call-graph walk dereferences every operand unguarded. Gate accessors on operand count; `min_operands` is not validator-enforced.
- **An IR op *mentioned* in a consumer is not *handled*.** Read each branch body for the property you care about; sibling `case` labels mislead most.
- **A best-effort specialization pass is not a reachability guarantee.** Check whether it errors or silently skips (a ternary func value reaches CUDA emit at exit 0, then `nvcc` fails).
- **Whole-program `linkIR` is a reachability clone, not a merge** — an unreferenced `static` global and its initializer are never cloned, before any validation or DCE pass. For "silently missing global/init", diff the LOWER-TO-IR dump vs the first emit-pipeline pass before blaming the optimizer (#14578).
- **`kIROp_*` enums are GENERATED from `slang-ir-insts.lua`** into the build-time fiddle header; never conclude "op X doesn't exist" from the handwritten `slang-ir-insts.h` alone.
- **A fix can create an exposure master never had** (simplifyCFG two-walk block-merge). Prefer structurally immune iteration (walk params, not filtered children).
- Global-var initializer blocks have no parent function until `moveGlobalVarInitializationToEntryPoints`; passes walking only `IRFunc` bodies miss or assert on them.
- A named profiler bucket can be empty on your path (spirv-direct skips `emitEntryPointsSourceFromIR`); empty reads like "cheap."
- C-like fold legality must follow every force-folded (Always-policy) user to its final use, in one cached linear pass. `fixValueScoping` sees only direct uses: clone a cross-block folded def before the user and re-scope its operands.
- **slangc's exit code is the DiagnosticSink error count, not the `SlangResult`.** An undiagnosed `SLANG_FAIL` exits 0; a local sink + `nullptr outDiagnostics` is a black hole; `-o /dev/null` fails for binary targets on Linux.
- Making a step fail on emitter errors can expose tests relying on ignored errors: move the test to supported targets; compare error counts before/after, not against 0.
- HostVM: guard unrepresentable types at storage-defining sites, keyed on the layout query failing, never on size==0.
- Confirm a source-traced symptom at HEAD; a prebuilt's different symptom is often the truth.
- **Per-frame size is a stack budget in recursive checker/emitter paths** (#13514). A crash threshold that moves with `ulimit -s` proves recursion; a C-like-vs-SPIR-V differential localizes the stage.
- **Localize a hang with no debugger:** LD_PRELOAD SIGPROF sampler + `addr2line` on the split-dwarf `.dwarf`; the distribution is the finding. `-dump-ir` is useless for a hang.
- The `.slang-module` embed path is nondeterministic (heap pointers); size and hash are unsound equality tests — use `cmp -l`.
- Precompiled-code provenance needs a guilty control (corrupt an embedded blob → link fails), not "exit 0 + same op counts".
- **Two option sets:** `TargetProgram` vs `TargetRequest`, inheritance request→program only; name which set each side reads/writes.
- `__include` + `implementing` is ONE module; audit graph depth by resolving imports, not counting files.
- A value computed only for a `SLANG_ASSERT` is `#ifdef _DEBUG`-guarded with the assertion; GCC's `SLANG_ASSUME` fallback evaluates its operand. A usage contract is not a fact.

## Modeling IR: operands, ops, and the "present ≠ handled" trap

Build an inst with an optional trailing operand as **fewer operands** and gate the accessor on the count; never construct a fixed-arity inst with a `nullptr` operand — `buildEntryPointReferenceGraph` (`slang-ir-call-graph.cpp:85-88`) dereferences every operand's `getOp()` unguarded, so a null crashes far from where it was built. The precedent is `IRDebugInlinedAt`: it declares 5 operands but builds 4 or 5, with `getOuterInlinedAt()` gated on `operandCount == 5`; `min_operands` feeds `IROpInfo::fixedArgCount` and is never checked. The lurking hazard is `IRDebugNoScope::getScope()`, a bare `getOperand(0)` on a 0-operand inst: the `SLANG_ASSERT` trips in debug but reads garbage in release. A shipped precedent beats "no validator forbids it" [absent operand = fewer operands (IRDebugInlinedAt precedent)](../learnings/1785897823903-slang-ir-model-an-absent-operand-as-fewer-operands.md).

Grepping that a destination op is *mentioned* in every consumer proves only that control reaches the code, not that the handling is equivalent. On PR #11709 all three param-mode ops sat on consecutive `case` lines in `slang-ir-inline.cpp`, but `kIROp_RefParamType` force-inlines regardless of `[noinline]` (honoring only `IRNoRefInlineDecoration`), while the Borrow ops bail out when the arg roots at a var/global — which is why `[noinline]` works for them. Moving `groupshared` from `BorrowInOut` to `Ref` would have destroyed the `[noinline]` boundaries three new diagnostics were shipped to protect. Name the property, read the branch body, and use a two-sided control (`__ref` destroys the boundary, `__constref` keeps it) [an op MENTIONED is not HANDLED](../learnings/1785857072008-an-ir-op-being-mentioned-in-a-consumer-is-not-the-.md).

Slang IR ops are **generated, not handwritten**: `slang-ir-insts.lua` is the source of truth and the `kIROp_*` enum lands in the generated fiddle header at build time. Grepping only the handwritten `slang-ir-insts.h` to decide "op X doesn't exist" is wrong — `kIROp_CharType` looked absent that way yet exists (`insts.lua:37`) and is used in `slang-ir-util.cpp`, `slang-ir.cpp` and the emitters. When an exclusion is genuinely needed, give the semantic reason, not op non-existence: `CharType` has no entry in the natural-layout scalar table (`slang-ir-layout.cpp:108-131`), so char has no target-independent size at lowering time, and bool is size-variable too (4 B natural/GPU, 1 B under `CLikeLayoutRules`/`LLVMLayoutRules`) [IR ops are generated from slang-ir-insts.lua](../learnings/1794988255632-slang-ir-ops-are-generated-from-slang-ir-insts-lua.md).

## simplifyCFG block-merge: a fix that introduces its own exposure

On #12343 a `throw` of an existential-typed value in `do{}catch{}` hangs `slangc`: block-merge in `processFunc` walked `successor`'s child list while `replaceUsesWith` re-parented hoistable insts (`lookupWitness`/`extractExistential*`), rotating the list forever. The obvious two-walk fix ("move non-params first, then replace params") introduces an exposure master lacks: in master a hoistable user moves only while it still shares `successor` as parent, so `tryHoistInst`'s guard fires; after walk 1 the guard no longer fires, and `mergeCandidateParentsForHoistableInst` can hoist the user back into the list a child-filtering second walk is traversing. Iterating params is structurally immune: `getNextParam()` returns null at the first non-param. [two-walk block-merge creates a new hoist exposure](../learnings/1785873979004-slang-simplifycfg-block-merge-splitting-the-walk-i.md).

## Codegen reachability: passes that skip, buckets that are empty

Finding the pass that eliminates construct X does not answer "can X reach emit?"; check whether the pass errors or silently skips. `specializeHigherOrderParameters` runs for CUDA, but `slang-ir-specialize-function-call.cpp` silently skips an unspecializable call, so a func value from a ternary or struct field emits `Slang_FuncType<int,int>` into CUDA at exit 0 and `nvcc` fails. The same input breaks 4 targets with 3 spellings from 2 producers (Metal falls through to an op-name fallback emitting `Func<...>`), so a CPP-emitter fix alone does not close the class [best-effort specialization is not reachability](../learnings/1785940519756-a-best-effort-specialization-pass-is-not-a-reachab.md).

**Code in a global-variable initializer has no parent function until `moveGlobalVarInitializationToEntryPoints` runs**, so passes that walk only `IRFunc` bodies miss it or assert on it. Branch coverage is the worked example (#13278 triage): `-trace-branch-coverage` markers are emitted during lowering (`StmtLoweringVisitor::emitBranchCoverageMarker`/`allocateCoverageBranchSiteID`), not by an IR pass, and `?:`/`&&`/`||` get none only because their visitors never call these helpers. `collectCoverageMarkerOps` walks only `IRFunc` bodies, `getRemappedBranchSiteID` release-asserts `getParentFunc(marker)`, the pass runs in `linkAndOptimizeIR` before the initializer move, and `static bool g = a && b;` lowers its short-circuit diamond into the `IRGlobalVar` initializer. A new marker site must gate on `getParentFunc(insertLoc)` as `visitSelectExpr` does [coverage markers are lowering-time, collected only from IRFunc](../learnings/1790588585622-slang-branch-coverage-markers-are-lowering-time-an.md). Type legalization loses such initializers the same way; see [[wiki/concepts/slang-compiler-ir-type-legalization.md]].

**A named profiler bucket can be empty on the path you care about, and empty reads like "low cost."** For `-target spirv`, `CodeGenContext::_emitEntryPoints` routes to `emitSPIRVForEntryPointsDirectly` → `createArtifactFromIR` → `emitSPIRVFromIR`, none carrying `SLANG_PROFILE`; the text path's `emitEntryPointsSourceFromIR` is bypassed and spirv-opt is untimed, so both costs land in the `generateOutput (self)` residual. Verify the path reaches the instrumented function before citing a timer; hedge "unattributed, not invisible" [a named profiler bucket can be EMPTY](../learnings/1785954775731-a-named-profiler-bucket-can-be-empty-on-the-path-y.md). Filed as #13016; the fix is the symmetric `SLANG_PROFILE` mirror on `emitSPIRVForEntryPointsDirectly`. Prove it GPU-free with `-report-detailed-perf-benchmark`: spirv-direct shows `generateOutput` with only `linkAndOptimizeIR` and a ~6 ms residual; an HLSL control shows `generateOutput == emitEntryPointsSourceFromIR`. For reporter-owned perf issues, hold the bot fixer so the reporter folds the fix into their branch [SPIR-V direct emit is unprofiled (#13016)](../learnings/1789157504641-spir-v-direct-emit-path-is-unprofiled-fix-is-the-s.md).

`-Xspirv-opt` is **structurally unreachable for text targets**: its one call site is reached only from `case CodeGenTarget::SPIRV` + `shouldEmitSPIRVDirectly()`. The guilty control is dispositive: `-target spirv -Xspirv-opt <bogus-pass>` errors; `-target hlsl -Xspirv-opt <bogus>` exits 0 (silently discarded). spirv-opt pass names need the double dash; `--strip-debug` keeps Slang reflection working (served from layout data, not the blob) [-Xspirv-opt is SPIR-V-only](../learnings/1785954407063-xspirv-opt-is-structurally-unreachable-for-text-ta.md).

**Whole-program `linkIR` is a reachability clone, not a merge** (`slang-ir-link.cpp:2209`, called from `linkAndOptimizeIR`): it clones only what is reachable from entry points plus a small allowlist; roots are `HLSLExport`/`DownstreamModuleExport` decorations only. A plain `static` global carries just a linkage `ExportDecoration` name — not an export root — so an unreferenced global and its init block are never cloned, before any validation or DCE pass runs (the in-code TODO at `slang-ir-link.cpp:2499-2511` admits as much). DCE is a second layer that also drops unreferenced `IRGlobalVar` (`KeepAliveDecoration` is the escape hatch). Triage shortcut for "silently missing global/init": diff the LOWER-TO-IR dump section against the first emit-pipeline pass section — if it is gone there, suspect linkIR, not the optimizer. Found in #14578 (unreferenced static-init atomics silently dropped on LLVM CPU) [linkIR is a reachability clone](../learnings/1794984620723-slang-whole-program-linkir-is-a-reachability-clone.md).

## C-like emitter folding: legality must follow force-folded users (#13273)

Consider `s.a[s.top] = bump(s);`, or a `pop` that reads `s.a[s.top]` after `s.top -= 1`. `CLikeSourceEmitter::shouldFoldInstIntoUseSites` force-folds `getElementPtr`, `FieldAddress` and pointer- or resource-typed values, but its side-effect scan covered only the instructions between an operand and its DIRECT user: the index load folds into the GEP, the GEP is re-materialized at its later use, and the index is re-read after the store or call. Triggers: simplifyForEmit's `processLoadUse` legally defers `load(gep)` past a non-aliasing store, and `s.a[s.top] = f(s)` needs no deferral (the IR computes the address first; the text evaluates the index after the call). All textual backends are wrong; SPIR-V is right. `-dump-ir` looks correct, and slang-test's `-cpu`/`-cuda` runtime paths returned correct values while `slangc -target cuda` text was wrong — regressions belong in text FileCheck [fold scan is not transitive through force-folded GEPs](../learnings/1790497097531-c-like-emitter-fold-scan-is-not-transitive-through.md).

The fix (`fix/issue-13273`, 1817cc19ac) splits the predicate into `getFoldPolicy` (Never / Always / WhenSafe) and a use-position check recursing only into Always users (a WhenSafe user validated its own use). Two performance traps: calling `shouldFoldInstIntoUseSites(user)` per level is O(depth²), and an uncached per-use rescan makes a many-use GEP cubic; one forward scan to the last use, cached during `emitRegionTree`, is safe because body IR is stable and `fixValueScoping` has run. Extra temporaries churned three goldens (`metal/atomic-intrinsics`, `compute/unbounded-array-of-array-syntax`, `cross-compile/geometry-shader-global-array-12169`) [fold legality must follow Always users, linearly](../learnings/1790504140643-slang-c-like-emitter-fold-legality-must-follow-alw.md).

**The store that invalidates a folded index need not be the user's.** Consider #14445, `items[items[index].left].right` on WGSL/HLSL/GLSL: SSA register allocation coalesces `index` and the ternary phi results into one `var`; a deferBufferLoad'd struct (over 16 B, containing an array) gets an always-folded GEP with users in later blocks, after `store(var, …)`, so the text re-reads the index after the store. Metal and CUDA snapshot a pointer and were never affected. The same fix covers it (PR #13283, 60a7c8c88, first in v2026.21; the v2026.20/v2026.21 release tarballs bracket the fix with no source build — see [[wiki/concepts/slang-tooling-release-tarball-repro-and-version-bisect.md]]). A temporary slang-test file must live under `tests/`; delete it and its `.actual.txt` files afterwards ([#13283 fold fix also covers register-coalesced index vars](../learnings/1794332130849-13283-fold-fix-also-covers-register-coalesced-inde.md)).

**Any fold change also interacts with `fixValueScoping`, which sees only DIRECT uses.** Consider `if (c) { x = s.a[t*2]; } else { return 0; } s.a[t*2] = x + 7;`. Dominance-scoped `removeRedundancy` lets the store reuse the then-block's GEP; `fixValueScoping` hoists the out-of-region always-folded GEP only to just after its last operand, still inside the branch, and never revisits that operand. A folded inst's operands are emitted at its use sites, so once `t*2` stops folding into the GEP its temporary is declared inside the branch and used after it: glslang/dxc report `'_S2' : undeclared identifier` on GLSL/HLSL/WGSL/Metal/CUDA. PR #13283 hit this; it was already a silent master miscompile. The fix: if the use is still out of scope after hoisting, `cloneInst` the folded def before the user and re-run `fixValueScopingForInst` on its operands. GPU-free repros that make scoping bugs hard errors: `-target spirv -emit-spirv-via-glsl`, `-target dxil -profile cs_6_0`, or a `-cpu` runtime test ([emit CSE creates cross-block folded GEP uses](../learnings/1790620041750-slang-emit-cse-creates-cross-block-always-folded-g.md), [folded insts' operands are emitted at the uses](../learnings/1790626574492-slang-fixvaluescoping-folded-insts-operands-are-em.md)).

## Localizing a compiler hang with no debugger

No `gdb`/`lldb`/`perf`/`pstack`, and `-dump-ir` is useless for a hang (`DiagnosticSinkWriter` is never flushed). Build a ~30-line `LD_PRELOAD` shim whose constructor installs a `SIGPROF` handler (`backtrace` + `backtrace_symbols_fd` to a raw fd, no `printf`; call `backtrace()` once in the constructor first — lazy init inside the handler can deadlock) and arms `setitimer(ITIMER_PROF, ...)`, which samples only while spinning. The **distribution is the finding**: 80/80 (#12343) or 203/203 (#12362, `findErrorHandler`) samples on one line-range, with zero in sibling sub-transforms, kills competing theories that a single stack cannot. The Debug build has split debug info: resolve offsets with `addr2line -f -C -e <lib>.dwarf`, not the `.so`. Cheap discriminators: RSS flat but utime climbing ⇒ spinning, RSS growing ⇒ runaway allocation. `auto next = inst->getNextInst()` is safe against removing the current node, not against a callee re-parenting others [LD_PRELOAD SIGPROF sampler + addr2line](../learnings/1785862700777-localize-a-compiler-hang-with-no-debugger-ld-prelo.md) [split-dwarf addr2line recipe](../learnings/1785920959839-locating-a-slang-compiler-hang-with-no-debugger-ld.md).

## Localizing a stack overflow: stack-size sweep + differential-target test

A Debug-only stack overflow suspected to be input-linear recursion can be confirmed and localized GPU-free (#13018). **A stack-size sweep is a positive recursion signature:** slangc compiles on the caller's main thread with the OS-default stack, so `ulimit -s <KB>` constrains it directly: if the crashing input size N moves monotonically with the stack, that is linear-depth recursion; rc=139 invariant under a growing stack proves nothing (an out-of-bounds pointer faults regardless). **A differential-target test localizes the stage.** The C-like source emitter recurses `emitInstExpr→emitOperand→emitOperandImpl→shouldFoldInstIntoUseSites→emitInstExpr` while folding single-use chains; SPIR-V does not use it, so C-like targets crashing while `-target spirv` compiles at a tiny stack puts the recursion in source emit, not an IR pass. In #13018 an N-texture accumulator folds into one left-leaning expression; the fix caps fold-chain depth at the `shouldFoldInstIntoUseSites`/schedule layer so deep chains materialize bounded temporaries. No emit-path recursion guard exists (`kMaxTypeNestingDepth`=128 is front-end-only) ([stack-size sweep + differential-target test (#13018)](../learnings/1789158062330-localizing-a-compiler-stack-overflow-stack-size-sw.md)).

The front-end checker has the same budget. #13514 passed PR CI then failed the merge queue: Windows Debug `test-slang` died with 0xC00000FD on a 294-operator `&&` chain recursing once per operator through `visitInvokeExpr` → `CheckExpr` → `_CheckTerm` → `dispatchExpr`. The PR built a `SemanticsVisitor sub(withX(...))` copy in `visitInvokeExpr`/`visitIndexExpr`/`visitTypeCastExpr` (~544 B per level at -O0), and a 8-B `SemanticsContext` growth that `dispatchExpr` and `_CheckTerm` also copy per level. The fix is an in-place RAII save/restore of the fields (like `OuterScopeContextRAII`) and padding-free field placement (`ptype /o Slang::SemanticsContext`) ([a SemanticsVisitor copy per recursive frame overflows Windows Debug](../learnings/1792079649552-slang-checker-a-semanticsvisitor-copy-per-recursiv.md)).

## Silent-failure plumbing — where a real error becomes a quiet exit

**slangc's exit code comes from the DiagnosticSink error count, not the `SlangResult`.** When a failure path is silent, trace whether anything calls `diagnose()`, not the `SlangResult` chain. A failed SPIR-V downstream link returns `SLANG_FAIL` with no `diagnose()` (no link-failure diagnostic exists), and every end-to-end gate reads `getErrorCount() != 0` ⇒ exit 0 with no output file. [a SlangResult nobody diagnoses is invisible](../learnings/1785962770674-a-slangresult-nobody-diagnoses-is-invisible-slangc.md).

**`SlangResult` also inverts C truthiness: `SLANG_OK == 0` is FALSY.** A condition like `if (parseInt(a, x) && parseInt(b, y))` takes the failure branch exactly when parsing SUCCEEDS — silent wrong-way logic with no error anywhere (slang#14518: a location parser used `StringUtil::parseInt`'s `SlangResult` as a bool and emitted line 0 for every valid `path:line:col`). Always wrap `SlangResult` conditions in `SLANG_SUCCEEDED(...)`; treat any HRESULT-style Slang API the same way [SlangResult SLANG_OK==0 is falsy — never use parseInt as a boolean](../learnings/1794898063634-slangresult-slang-ok-0-is-falsy-never-use-parseint.md).

**A local `DiagnosticSink` plus a `nullptr` `outDiagnostics` is a diagnostic black hole.** `Module::precompileForTarget` builds a local sink with no writer; `getBlobIfNeeded(outDiagnostics)` returns `SLANG_OK` immediately for a null blob, which the CLI passes. Result: exit 255, no output, a real `E50100` discarded. Grep for `nullptr` at `API(..., ISlangBlob** outDiagnostics)` call sites when a tool exits nonzero silently, and recover the message with a probe passing a real blob. `SLANG_ASSERT=system` does nothing on Linux (the branch is inside `#if _WIN32`); exit 255 is nonspecific [local sink + nullptr outDiagnostics](../learnings/1785959064285-a-local-diagnosticsink-plus-a-nullptr-outdiagnosti.md).

`-o /dev/null` fails on **Linux too**, for binary targets only. `ArtifactOutputUtil::writeToFile` branches on `isText(desc)`: text targets take a path that works, while binary targets hit `FileStream::_init`, where `Path::getPathType` rejects anything not `S_IFREG` (a character device) before `fopen`. A "Windows-only" fix for a path-shape check is the wrong shape. A null-path guard must not swallow real failures (test `-o /nonexistent-dir/out.spv`), and there are two `CannotWriteOutputFile` sites [-o /dev/null fails on Linux for binary targets](../learnings/1785967936973-o-dev-null-fails-on-linux-too-for-binary-targets-s.md).

Closing a silent-failure path can surface tests that relied on it. On PR #13724 the maintainer asked for `emitEntryPointsSourceFromIR` to return `SLANG_FAIL` whenever the source emitter adds an error, on every target. That broke `slang-unit-test-tool/cooperativeVectorTypeMetadata`, whose `cuda_optix` row compiled coop-vector ops that OptiX reports as E55204 and `getTargetMetadata` had been ignoring. The fix moved the test onto supporting targets (SPIR-V + HLSL) instead of adding a target guard. Compare the sink's error count before and after `emitModule`; slang-test shows only `res == SLANG_OK` failing, so print the test's `diagnostics` blob temporarily ([failing on errors surfaces tests that relied on ignored errors](../learnings/1792463767876-making-a-compile-step-fail-on-errors-can-surface-t.md)).

The HostVM (slangi) version of the trap is a **crash**: a runtime value with no HostVM byte layout reaches a value-slot allocation, `getNaturalSizeAndAlignment` fails for `kIROp_StringType`, `ensureWorkingsetMemory` ignored the failure and returned a 0-byte slot, and `%s` dereferenced garbage → SIGSEGV 139 with no diagnostic (#13017). The fix diagnoses rather than adding VM String support: `getRepresentableSizeAndAlignment` records a fail-loud E52014 and returns a placeholder `(0,1)`, so `emitVMByteCodeForEntryPoints` returns `SLANG_FAIL`. Route the guard only at **storage-defining sites** (value slots, `kIROp_Var`/`kIROp_Store` dest pointees, the function-result slot); raw stride/offset queries are covered by the enclosing aggregate's guarded slot. Key on the query failing, never on size==0 ([HostVM guard at storage-defining sites](../learnings/1789402835980-hostvm-slangi-unrepresentable-type-guard-check-at-.md)).

**A source trace can predict the wrong symptom; confirm the exact claim at HEAD.** #13093 claimed `countof` on a truly-unsized array ICEs at emit. At HEAD it compiles clean on every target and silently folds `countof(gArr)` to `4` (`sizeof(int)`), the `#11317`-class wrong-value miscompile — source-only reasoning ("un-foldable `kIROp_CountOf` → emit ICE") missed that the wrong-value fold runs first. When a memo says a symptom "needs a HEAD build" and the prebuilt showed a different one, treat the claim as unverified. A checker fix rejecting `countof(unsized)` with E56002 is still valid, but the PR must frame it as fixing a miscompile, not an ICE ([#13093 ICE does not reproduce at HEAD](../learnings/1789485829159-slang-13093-countof-unsized-ice-does-not-reproduce.md)).

## Precompilation, module determinism, and truncated instrument output

A truncated `-dump-ir` on the precompile path reads as "no passes ran", but the ICE message refutes it: it names a `_std140` struct variant created by a late pass, so `-dump-ir` is simply not wired through that path. **When an instrument's output is unexpectedly small, ask whether the output itself contradicts the reading.** The real asymmetry: `wrapRemainingConstantBufferElementTypes()` has no `ParameterBlockType` twin, which is why nested `ConstantBuffer` compiles and nested `ParameterBlock` ICEs [truncated -dump-ir on the precompile path](../learnings/1785959056296-a-truncated-dump-ir-on-the-precompile-path-reads-a.md).

Proving that precompiled target code was *used* needs discriminators, not "exit 0 + same op counts": corrupt ~24 bytes inside an embedded blob, confirm the link fails, then restore as the control. Slang also **validates the wrong buffer**: with `SLANG_RUN_SPIRV_VALIDATION=1` a precompiled-link compile fails on "Capability Linkage" though the shipped artifact is valid — `slang-emit.cpp` validates the pre-link `spirv` buffer, never `linkedArtifact`; every `tests/library/precompiled-*` test passes `-skip-spirv-validation` [precompiled-SPIRV provenance; wrong buffer validated](../learnings/1785957170037-precompiled-spirv-link-proving-target-code-provena.md).

The `.slang-module` **embed path is nondeterministic**: 3 identical runs give identical sizes but distinct MD5s, with exactly 12 bytes differing in three 8-byte slots holding raw `void*` heap pointers. It is embed-specific (a plain front-end module is bit-identical) and functionally harmless, because `isBinaryModuleUpToDate` hashes source+options, never the module bytes; only external content-addressing is exposed. Size and `md5sum` are both unsound equality tests — use `cmp -l`. [.slang-module embed path is nondeterministic](../learnings/1785968956916-slang-slang-module-nondeterministic-on-the-embed-p.md).

Precompilation limits are quotable from `slang-compiler-tu.cpp` ("no target languages allow generics to be precompiled"; DXIL rejects `StructuredBuffer`/`Matrix` in a library interface); `IModulePrecompileService_Experimental` is "not thread-safe — it mutates the module."

## Two option sets, module graphs, and `__include`

Slang has **two option sets that are not interchangeable**: `TargetRequest::getOptionSet()` (from the session) and `TargetProgram::getOptionSet()` (program override, then request inherit); inheritance runs request→program only. `shouldRunSPIRVValidation` reads the TargetProgram, `doesTargetAllowUnresolvedFuncSymbol` reads the TargetRequest, and `precompileForTarget` adds options to a local TargetProgram — so `IncompleteLibrary` set in the precompile path never reaches the request-level unresolved-symbol gate, while a session-level `SkipSPIRVValidation` is honored. Grepping the option name distinguishes neither set [two option sets, one-way inheritance](../learnings/1786000309982-slang-option-gates-read-two-different-option-sets-.md).

A module split via `module "a"; __include "a-part.slang";` + `implementing "a";` is **one module**, but reads as a separate module in any file listing, so an A→B→C graph can really be A→B. Audit depth by resolving each `import "X"` to `X.slang` and counting that file's imports; `implementing` in the resolved file means depth does not increase [__include + implementing is ONE module](../learnings/1785961765627-slang-include-implementing-is-one-module-that-read.md).

## `SLANG_ASSUME` / `SLANG_ASSERT`: a usage contract is not a statement of fact

Outside `_DEBUG`, `SLANG_ASSERT(X)` expands to `SLANG_ASSUME(X)`, whose branches differ in whether they evaluate the operand: `[[assume]]` and `__builtin_assume` do not, but the **GCC fallback** (`do { if (!(X)) __builtin_unreachable(); } while (0)`) does, and on the GCC 12 container `__cpp_assume` is undefined, so that branch is live (verified with a call counter). The header's "Do not rely on side effects" is a usage contract (some expansions skip evaluation), not a claim that a given expansion skips it. Rule: **a value computed solely for a `SLANG_ASSERT` is `#ifdef _DEBUG`-guarded together with the assertion**; guarding only the computation leaves the variable undeclared in release, so build release whenever you add such a guard. "Do not rely on X" means X is not guaranteed, not that X does not happen [SLANG_ASSUME evaluates its operand on GCC](../learnings/1785883273838-slang-assume-evaluates-its-operand-on-gcc-and-the-.md).

The `as<>`/`cast<>` trap also bites *suggested-fix snippets* (#14746 r3): a round-2 verdict suggesting `SLANG_RELEASE_ASSERT(as<IRConditionalType>(paramType));` got applied followed by `cast<IRConditionalType>(paramType)` — a release-build type confusion, because `as<T>` unwraps `IRAttributedType` chains (slang-ir.h:833) while `cast<T>` only debug-asserts via that `as<>` and is a raw static cast in release (slang-ir.h:859-864). An attributed Conditional param (memberwise-ctor params are attributed — a shape the PR itself documents in-contract) passed the assert while the cast reinterpreted an `IRAttributedType` as an `IRConditionalType` (operand layouts `{baseType, attr}` vs `{valueType, hasValue}`, slang-ir-insts.lua:132/147); flat payloads read coincidentally correct and tests passed. Rule for any suggested fix on Slang IR: bind the unwrapped pointer first (`auto p = as<T>(x); SLANG_RELEASE_ASSERT(p);`) and use `p` — never assert on a temporary `as<>` where the fixer will naturally follow with `cast<>`. Corollary: `SLANG_ASSERT` is debug-only and expands to `SLANG_ASSUME` (UB license) in release, so invariants that must abort in shipped slangc use `SLANG_RELEASE_ASSERT` [Slang IR as&lt;&gt; vs cast&lt;&gt; — suggested-fix snippets must bind the as&lt;&gt; pointer](../learnings/1795808314302-slang-ir-as-vs-cast-suggested-fix-snippets-must-bi.md).
