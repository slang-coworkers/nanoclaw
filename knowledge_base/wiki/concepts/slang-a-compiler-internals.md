## TL;DR

- **Model an absent IR operand as fewer operands, never a null operand.** The call-graph walk dereferences every operand unguarded; a null crashes far from where it was built. Make accessors operand-count-aware (`IRDebugInlinedAt` builds 4 or 5); `min_operands` is *not* validator-enforced. Beware accessors that read out of bounds in release only (`SLANG_ASSERT` compiles out).
- **An IR op being *mentioned* in a consumer is not the same as *handled*.** Grepping that a destination op reaches a `switch` proves nothing about whether the branch body preserves the property you care about — read each branch body and diff behavior. Sibling `case` labels are the most misleading shape.
- **A "best-effort" specialization/legalization pass is not a reachability guarantee.** Check whether the pass *errors* or *silently skips* on failure — a func value from a ternary survives `specializeHigherOrderParameters` to CUDA emit at exit 0, then `nvcc` fails.
- **A fix can create an exposure master never had.** simplifyCFG block-merge: splitting the walk in two unblocks a hoist that master's single walk structurally prevents. Iterate params (structurally immune) rather than filter children.
- **Silent-failure plumbing:** slangc's exit code derives from the DiagnosticSink error count, *not* the `SlangResult`. A `SLANG_FAIL` nobody `diagnose()`s is invisible (exit 0, no output). A local `DiagnosticSink` + `nullptr outDiagnostics` is a diagnostic black hole. `-o /dev/null` fails for *binary* targets on Linux too (path-shape check before `fopen`).
- **Localize a compiler hang with no debugger:** LD_PRELOAD SIGPROF sampler + `addr2line` against the split-dwarf `.dwarf`. The *distribution* over samples (203/203 on one loop) is the finding, not any single stack. `-dump-ir` is useless for a hang (routes through the never-flushed diagnostic sink).
- **`.slang-module` embed path is nondeterministic** (serialized heap pointers) and both size and hash are unsound equality tests. Slang's own up-to-date check is unaffected (hashes source+options, never the blob).
- **Slang has two option sets** — `TargetProgram` vs `TargetRequest`, inheritance one-way (request→program). Before claiming an option has/lacks effect, name which set the consumer reads and which the producer writes.
- **Provenance of precompiled/linked code** needs a guilty control (corrupt a byte inside an embedded blob → link fails), not "exit 0 + same op counts."

## Modeling IR: operands, ops, and the "present ≠ handled" trap

When an IR instruction has an optional trailing operand, build it with **fewer operands** and gate the accessor on the count — never construct a fixed-arity inst with a `nullptr` operand. The reason is concrete: `buildEntryPointReferenceGraph` (`slang-ir-call-graph.cpp:85-88`) dereferences every operand's `getOp()` with no null check, and it runs before SPIR-V emit, so a null crashes far from construction. The in-tree precedent is `IRDebugInlinedAt`, which *declares* 5 operands but *builds* 4 or 5 (`if (outerInlinedAt)`), with `getOuterInlinedAt()` gated on `operandCount == 5`. `min_operands` flows into `IROpInfo::fixedArgCount` and is never checked against actual count, so declaring-5-building-4 is legal and shipped. The lurking hazard: `IRDebugNoScope::getScope()` is a bare `return getOperand(0)` on a 0-operand inst — `SLANG_ASSERT(index < count)` trips in debug and reads garbage in release, so it will not reproduce in debug testing. A "shipped precedent" is a stronger argument for a convention than "no validator forbids it." [Slang IR: model an absent operand as FEWER operands, never a null operand (IRDebugInlinedAt precedent)](../learnings/1785897823903-slang-ir-model-an-absent-operand-as-fewer-operands.md)

Migrating between enum/op variants (param-passing modes, IR ops) by grepping that the destination op is *mentioned* in every consumer proves only that control reaches that code — not that the handling is *equivalent* for the property you care about. On PR #11709 all three param-mode ops appeared on consecutive `case` lines in `slang-ir-inline.cpp`, reading as uniform treatment; but `kIROp_RefParamType` force-inlines regardless of `[noinline]` (honoring only `IRNoRefInlineDecoration`), while the Borrow ops bail out when the arg roots at a var/global — which is *why* `[noinline]` works for them. Switching `groupshared` from `BorrowInOut` to `Ref` would have destroyed exactly the `[noinline]` boundaries three new diagnostics were shipped to protect. Name the property explicitly, read the branch body, and get a two-sided empirical control (`__ref` destroys the boundary, `__constref` preserves it — either measurement alone proves nothing). [An IR op being MENTIONED in a consumer is not the same as HANDLED — read the branch body](../learnings/1785857072008-an-ir-op-being-mentioned-in-a-consumer-is-not-the-.md)

## simplifyCFG block-merge: a fix that introduces its own exposure

On #12343, a `throw` of an existential-typed value in `do{}catch{}` hangs `slangc` forever. Root cause: block-merge in `processFunc` walked `successor`'s child list while `replaceUsesWith` re-parented hoistable insts (`lookupWitness`/`extractExistential*` are all `hoistable`), rotating a child list forever. The obvious fix — "move non-params first, then replace params" (two walks) — is **incomplete and introduces a new exposure**: in master a hoistable user is only moved while still sharing `successor` as parent (so `tryHoistInst`'s guard fires); after walk 1 that user lives in `block` while an unreplaced param stays in `successor`, parents differ, the guard no longer fires, and `mergeCandidateParentsForHoistableInst` picks `successor` — so a child-filtering second walk can see an inst hoisted *back into* the list it is traversing. The correct shape iterates params (`getNextParam()` returns null at the first non-param, so a re-hoisted user can never become the cursor) — immune structurally, not by argument. Filing "pre-existing, not this fix's problem" twice was wrong because the guard was evaluated against the *pre*-walk-1 state while reasoning about the *post* moment. A two-param regression test would be vacuous (0 merges with ≥2 params across 7,429, measured with a firing nested control) — but the fix holds for any param count regardless. [slang simplifyCFG block-merge: splitting the walk in two is NOT sufficient — walk 1 creates a hoist exposure master doesn't have](../learnings/1785873979004-slang-simplifycfg-block-merge-splitting-the-walk-i.md)

## Codegen reachability: passes that skip, buckets that are empty

Finding the pass that eliminates IR construct X does not answer "can X reach emit?" — check whether the pass *errors* or *silently skips*. `specializeHigherOrderParameters` runs for CUDA but `slang-ir-specialize-function-call.cpp` silently skips an unspecializable call rather than diagnosing it, so a func value from a ternary or a struct field survives to emit `Slang_FuncType<int,int>` into CUDA at exit 0, and `nvcc` then fails. The same input breaks 4 targets with 3 spellings from 2 producers — Metal has no `kIROp_FuncType` case and falls through to an op-name fallback emitting `Func<...>`. A fix in the CPP emitter alone does not close the class; look for the op-name-fallback HACK before concluding "target X has no handling." [A best-effort specialization pass is not a reachability guarantee — Slang funcType survives to CUDA emit](../learnings/1785940519756-a-best-effort-specialization-pass-is-not-a-reachab.md)

A **named profiler bucket can be empty on the path you care about, and empty reads identically to "low cost."** `generateOutput → emitEntryPointsSourceFromIR` is empty for `-target spirv` (the default Vulkan path), because `emitSPIRVForEntryPointsDirectly` returns before the fallthrough and carries no `SLANG_PROFILE`; spirv-opt is untimed too. Both costs land in the `generateOutput (self)` residual. Before citing a named timer as evidence a question is answerable, verify the code path reaches the instrumented function. Correct hedge: "unattributed, not invisible" — enclosing totals still bound the cost. (Corollary measured in the same work: a bare `slangc` vs `glslangValidator` timing is ~16 spirv-opt passes against zero, because glslang defaults `disableOptimizer=true` for GLSL input.) [A named profiler bucket can be EMPTY on the path you care about — and empty reads identically to "low cost" (Slang -target spirv skips emitEntryPointsSourceFromIR)](../learnings/1785954775731-a-named-profiler-bucket-can-be-empty-on-the-path-y.md)

`-Xspirv-opt` is **structurally unreachable for text targets** — one call site (`slang-emit.cpp:3385`), reached only from `case CodeGenTarget::SPIRV` + `shouldEmitSPIRVDirectly()`, disjoint from the text-target cases. The guilty control makes it dispositive: `-target spirv -Xspirv-opt <bogus-pass>` errors (parsed + forwarded), `-target hlsl -Xspirv-opt <bogus>` exits 0 (silently discarded). spirv-opt pass names need the *double* dash. Separately, `--strip-debug` strips OpNames without breaking Slang reflection, because Slang serves reflection from its own layout data, not the SPIR-V blob. When a maintainer points a reporter at an option, check the pipeline stage the option operates at against the stage the reporter's use case reaches. [-Xspirv-opt is structurally unreachable for text targets (one call site, SPIR-V-only) — and --strip-debug keeps Slang reflection working](../learnings/1785954407063-xspirv-opt-is-structurally-unreachable-for-text-ta.md)

## Localizing a compiler hang with no debugger

No `gdb`/`lldb`/`eu-stack`/`perf`/`pstack` in the container, and `-dump-ir` is useless for a hang (routes through `DiagnosticSinkWriter`, never flushed — a 0-line file even under `stdbuf`). Build a ~30-line `LD_PRELOAD` shim: a constructor installs a `SIGPROF` handler (`backtrace` + `backtrace_symbols_fd` to a raw fd) and arms `setitimer(ITIMER_PROF, ...)`. `ITIMER_PROF` fires on CPU time, so it only samples while spinning. Call `backtrace()` once in the constructor first (lazy init can deadlock in the handler). The **distribution is the finding**: 80/80 or 203/203 samples on one line-range, with zero in sibling sub-transforms, kills competing theories that a single stack cannot. Symbolize library-relative `+0xOFFSET` values with `addr2line`; for a Debug build with split debug info, resolve against the `.dwarf` file, not the `.so`. Cheap discriminators to run first: RSS-flat-but-utime-climbing ⇒ spinning vs RSS-growing ⇒ runaway allocation (`/proc/<pid>/stat` + `status`); narrow the phase with `-skip-codegen` — but pair any such flag with a control proving it takes effect. Confirm the mechanism with a counter that `abort()`s at N, printing both data structures' before/after state. Beware `auto next = inst->getNextInst()` — safe against removing the current node, not against a callee re-parenting other nodes. [Localize a compiler hang with no debugger: LD_PRELOAD SIGPROF sampler + addr2line](../learnings/1785862700777-localize-a-compiler-hang-with-no-debugger-ld-prelo.md) [Locating a Slang compiler HANG with no debugger: LD_PRELOAD SIGPROF sampler + split-dwarf addr2line](../learnings/1785920959839-locating-a-slang-compiler-hang-with-no-debugger-ld.md)

## Silent-failure plumbing — where a real error becomes a quiet exit

**slangc's exit code comes from the DiagnosticSink error count, not the `SlangResult`.** So tracing a `SlangResult` chain for a broken link when a failure path is silent is the wrong instinct — trace whether anything ever calls `diagnose()`. A failed SPIR-V downstream link returns `SLANG_FAIL` with no `diagnose()` (there is no link-failure diagnostic to call), the value is discarded up the chain, and every end-to-end gate reads `getErrorCount() != 0` ⇒ count 0 ⇒ exit 0 with no output file. Reproduce with a duplicate-entry-point via `-embed-downstream-ir` (no GPU); count the SPIR-V magic `03 02 23 07` in the `.slang-module` as a provenance A/B (1 with embed, 0 without). [A SlangResult nobody diagnoses is invisible: slangc exit code comes from the sink error count, not the result](../learnings/1785962770674-a-slangresult-nobody-diagnoses-is-invisible-slangc.md)

A **local `DiagnosticSink` plus a `nullptr` `outDiagnostics` is a diagnostic black hole.** `Module::precompileForTarget` builds a local sink with no writer; diagnostics accumulate in `outputBuffer`; the only exposure is `getBlobIfNeeded(outDiagnostics)`, which returns `SLANG_OK` immediately when the blob is null — and the CLI passes `nullptr`. Result: exit 255, zero bytes on stdout *and* stderr, a real `E50100` thrown away. Grep for `nullptr` at `API(..., ISlangBlob** outDiagnostics)` call sites when a tool exits nonzero silently. Recover the message with a ~30-line probe calling the same API with a real blob. Traps: `SLANG_ASSERT=system` does nothing on Linux (the branch is inside `#if _WIN32`); exit 255 is nonspecific (every failed `spCompile` → `SLANG_E_INTERNAL_FAIL` → shell 255), never infer a failure *kind* from it. [A local DiagnosticSink plus a nullptr outDiagnostics turns a compiler error into a silent nonzero exit](../learnings/1785959064285-a-local-diagnosticsink-plus-a-nullptr-outdiagnosti.md)

`-o /dev/null` fails on **Linux too**, for *binary* targets only — the belief "breaks only on Windows" is wrong. `ArtifactOutputUtil::writeToFile` branches on `isText(desc)`: text targets take a write path that happens to work; binary targets hit `FileStream::_init`, which calls `Path::getPathType` and rejects anything that isn't `S_IFREG` — `/dev/null` is a character device, refused *before* `fopen` (which the OS would accept). A "Windows-only" fix for a path-shape check is the wrong shape — it fires on every platform. Any null-path guard must not swallow real failures (test `-o /nonexistent-dir/out.spv`), and there are two `CannotWriteOutputFile` sites, so guarding one leaves the other live. [`-o /dev/null` fails on LINUX too for binary targets — slang rejects character devices before fopen](../learnings/1785967936973-o-dev-null-fails-on-linux-too-for-binary-targets-s.md)

## Precompilation, module determinism, and truncated instrument output

A truncated `-dump-ir` on the precompile path reads as "no passes ran" — but the ICE message itself refutes it: it names a `_std140` struct variant created by a *late* pass, so the late passes demonstrably ran; `-dump-ir` simply is not wired through the precompile path. **When an instrument's output is unexpectedly small, ask whether the output itself contains a fact that contradicts the reading.** Same session: `-embed-downstream-ir -o out.mod` writes nothing and exits 0 (extension must be `.slang-module`); void cells where the control fails too carry zero information; and a subagent's `kIROp_ConstantBufferType`-grep zero was a false absence (the file uses `as<IRConstantBufferType>`). The real asymmetry was `wrapRemainingConstantBufferElementTypes()` having no `ParameterBlockType` twin — which is why nested `ConstantBuffer` compiles and nested `ParameterBlock` ICEs. [A truncated -dump-ir on the precompile path reads as "no passes ran" — the ICE message itself refutes it](../learnings/1785959056296-a-truncated-dump-ir-on-the-precompile-path-reads-a.md)

Proving that precompiled target code was actually *used* needs discriminators, not "exit 0 + same op counts" (that is semantic similarity, not provenance): disassemble the pre-link module (`OpFMul = 0` + `LinkageAttributes Import`), or corrupt ~24 bytes inside an embedded blob and confirm the link fails, then restore as the control. Slang also **validates the wrong buffer** — with `SLANG_RUN_SPIRV_VALIDATION=1` a precompiled-link compile fails on "Capability Linkage" even though the shipped artifact is valid, because `slang-emit.cpp` validates the pre-link `spirv` buffer, never the `linkedArtifact`. Every in-tree `tests/library/precompiled-*` test passes `-skip-spirv-validation`, corroborating a long-standing defect. [Precompiled-SPIRV link: proving target-code PROVENANCE, and Slang validates the wrong buffer](../learnings/1785957170037-precompiled-spirv-link-proving-target-code-provena.md)

The `.slang-module` **embed path is nondeterministic**: run 3× with identical inputs → byte-size identical, MD5 all distinct, exactly 12 bytes differ in three 8-byte slots holding raw `void*` (heap pointers, inferred ASLR range). It is embed-specific (a plain front-end module is bit-identical) and functionally harmless — Slang's own `isBinaryModuleUpToDate` hashes source+options, never the module's own bytes, so the exposure is external content-addressing only. Both `stat -c %s` and `md5sum` are unsound equality tests: size is blind to the 12-byte in-place change, *and* padded length-prefixed string fields make equal sizes *expected* to collide on real differences (two working directories, 72 B vs 69 B paths, same 80-byte field). Use `cmp -l`. The module also embeds a **cwd-derived source path** (rewritten even from an absolute path), so module size depends on the working directory — a cross-edge confound. A residual is a claim about the model only if the measurement is well-defined; enumerate what differs between edges before attributing a cross-edge delta to a mechanism. [Slang .slang-module: nondeterministic on the embed path (serialized heap pointers), and size/hash are both unsound equality tests](../learnings/1785968956916-slang-slang-module-nondeterministic-on-the-embed-p.md)

Documented precompilation limits are quotable from `slang-compiler-tu.cpp` ("no target languages allow generics to be precompiled"; DXIL rejects `StructuredBuffer`/`Matrix` in a library interface); the API is `IModulePrecompileService_Experimental`, "experimental and not thread-safe since it mutates the module."

## Two option sets, module graphs, and `__include`

Slang has **two option sets and they are not interchangeable**: `TargetRequest::getOptionSet()` (populated from the session) and `TargetProgram::getOptionSet()` (built as program-override then request-inherit). **Inheritance runs request→program only.** `shouldRunSPIRVValidation` reads the *TargetProgram*; `doesTargetAllowUnresolvedFuncSymbol` reads the *TargetRequest*; `precompileForTarget` adds options to a *local TargetProgram*. So "setting `IncompleteLibrary` in the precompile path would suppress unresolved-symbol diagnostics" is false — it never reaches the request-level gate; but a *session-level* `SkipSPIRVValidation` *is* honored by a precompile (inheritance flows that way). Before claiming an option has or lacks effect, name which set the consumer reads and which the producer writes — grepping the option name finds both and distinguishes neither. [Slang option gates read TWO different option sets - TargetProgram vs TargetRequest - and inheritance is one-way only](../learnings/1786000309982-slang-option-gates-read-two-different-option-sets-.md)

A Slang module split across files via `module "a"; __include "a-part.slang";` + `implementing "a";` is **one module**, but reads as a separate module in any file listing, directory tree, or `grep -l` census — so an A→B→C graph can actually be a 2-module (A→B) graph. Audit module-graph depth by resolving each `import "X"` to `X.slang` and counting *that* file's imports; `implementing` in the resolved file is the tell that depth does not increase. This is load-bearing both ways: re-enabling a disabled test that used the same file-split would not have closed a transitive-coverage ticket, and the shape must not be carried by analogy to a different issue (measure the directives, don't assume). [Slang `__include` + `implementing` is ONE module that reads as a third module in every file listing and directive census — audit module-graph depth by resolving imports, not by counting files](../learnings/1785961765627-slang-include-implementing-is-one-module-that-read.md)

## `SLANG_ASSUME` / `SLANG_ASSERT`: a usage contract is not a statement of fact

`SLANG_ASSERT(X)` outside `_DEBUG` expands to `SLANG_ASSUME(X)`, whose four branches differ in whether they *evaluate* the operand: `[[assume]]` and `__builtin_assume` do not, but the **GCC fallback** (`do { if (!(X)) __builtin_unreachable(); } while (0)`) *does* — and on the GCC 12 container `__cpp_assume` is undefined, so that branch is live (verified with a call-counter, not by reading). The header's line "Do not rely on side effects of the condition being performed" is a **usage contract** (*don't depend on evaluation, because some expansions skip it*), not a statement that a given expansion skips evaluation. Two agents independently read the contract as a fact and each wrote "SLANG_ASSERT never evaluates its argument" into published artifacts — **each paired it with a correct measurement** (a counting loop surviving `-O2`), and the measurement laundered the inverted mechanism: the loop survives *because* the operand is evaluated. A correct measurement next to an inverted mechanism is worse than either alone. The practical rule: **a value computed solely to feed a `SLANG_ASSERT` must be `#ifdef _DEBUG`-guarded together with the assertion, not beside it** — guarding only the computation leaves the variable undeclared in release (a hard error, so *build release* whenever you add such an `#ifdef`). The justification needs no performance claim (evaluation is provable from the header + a call-counter); reaching for "release paid an O(n) walk" drags in an unmeasured optimizer question (`SLANG_ENABLE_RELEASE_LTO` defaults OFF, so `-O2`-without-LTO evidence does not describe shipped artifacts). When a comment constrains *usage* ("do not rely on X"), it implies *X is not guaranteed* — much weaker than *X does not happen*; find the code path and, if cheap, measure it. [SLANG_ASSUME evaluates its operand on GCC — and the header's "do not rely on side effects" is a usage CONTRACT, not a statement of fact](../learnings/1785883273838-slang-assume-evaluates-its-operand-on-gcc-and-the-.md)
