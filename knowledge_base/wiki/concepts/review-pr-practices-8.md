Siblings: [part 1](review-pr-practices.md), [part 2](review-pr-practices-2.md), [part 3](review-pr-practices-3.md), [part 4](review-pr-practices-4.md), [part 5](review-pr-practices-5.md), [part 6](review-pr-practices-6.md), [part 7](review-pr-practices-7.md), [part 9](review-pr-practices-9.md). ## TL;DR
- **Every reviewer fails toward CLEAN.** Devin exit 0 is not a signal; Reviewer A can emit a 0-byte or budget-capped output; Reviewer C can skip environmentally. **Verify each reviewer produced findings before treating "no findings" as a result** — an absent reviewer and a clean reviewer are byte-identical downstream.
- **Watch the ARTIFACT, not the subagent.** A Devin subagent returns before `devin-fetch.sh` finishes; a detached reviewer's completion is proven by its exit marker, never by streamed JSON. Anchor monitors to exit markers.
- **Read the full page dump, not the summary file.** `devin-flags.md` can have an EMPTY `## Flags` section while `devin-page.txt` from the same run shows real findings — synthesizing from the summary records a false "0 findings" and carries a false-clean prior into the challenger.
- **Reviewer A needs an isolated checkout.** Fleet contention on a shared repo root corrupts runs; `$30` is too low a budget cap and produces silent truncation. Use fresh per-run out-dirs to avoid `/tmp` collisions.
- **Two bots agreeing measures shared priors, not correctness.** Independent bots flagging the same item is weak corroboration; read the human review thread before scoring any structure/maintainability gap.
- **A bot finding a named maintainer already overruled ON THIS PR is not an open gap** — but **lead with the technical grounds**, never the maintainer's preference. Maintainer preference is supporting context; a repo guideline is not cleared by taste alone.
- **A refuted 🔴 does not become WOULD_APPROVE**, and a standing human `CHANGES_REQUESTED` caps the verdict at ABSTAIN. Never round up.
- **A mid-iteration `diff_hash` mismatch is expected under debounce**, not a bug. Pin the head, byte-prove reviews against it, and re-verify a stale secondary reviewer's flags at the current head.
- **Re-review scope: redesign gaps and self-recommended nits do not reset the pipeline.** Additive nit rounds are fine; a full re-run is not.
- **The review signal is endpoint-split across three surfaces** (`pulls/N/reviews`, `pulls/N/comments`, `issues/N/comments`) and the harvest reads one. That split is a property of GitHub's data model, so **every consumer inherits the blind spot independently — fixing one instance is not fixing the class.**
- **A GitHub post gates on the literal marker, not on prose.** Post only in COMMENT state; never APPROVE/REQUEST_CHANGES from a runner.
- **Empirical probes can test the wrong sub-case.** A probe that varies the intended factor while holding the confound constant reads as decisive and proves nothing — name the factor and the confound before citing a control.
- **In an artifact where claims cite `file:line`, the UNCITED SENTENCE IS THE DEFECT** — in a document whose norm is citation, the citation outlier is where an inference got restated as an observation. Run that self-check mechanically over your own draft.
- **Recording is not routing.** Documenting a blocking infra defect any number of times never reaches a file only an operator can edit. The record serves the next agent; the escalation serves the fix — do both.
- **A stale webhook dispatch on an already-decided PR is a no-op plus a report, never a re-decision.** `record_decision` is idempotent per `(repo, pr, sha)`, so re-deciding CLOBBERS a human-joined calibration row with a verdict contaminated by post-hoc information.

## Approver Deep-Dive: Head-Pinning Races, Devin Infra, Challenger Probes, and Human Calibration (2026-07-15 fold) — part 2/3The critique gate records a round **only from a fresh `mcp__codex__codex` call carrying the canonical `/codex-critique` `developer-instructions` block verbatim** — a `mcp__codex__codex-reply` reuses the thread's original instructions, carries no `developer-instructions`, and never records regardless of its verdict; run DECISION_REVIEW and OUTPUT_REVIEW as SEPARATE fresh calls, reserving `codex-reply` for must-fix re-verification within an already-recorded stage ([critique gate records only codex calls, never codex-reply — OUTPUT_REVIEW must be a fresh call](wiki/learnings/1784020599916-approver-critique-mustfix-critique-gate-records-on.md), [OUTPUT_REVIEW must be a FRESH codex call with the canonical reviewer developer-instructions](wiki/learnings/1784095230054-approver-critique-mustfix-output-review-must-be-a-.md)). The gate's `gate-critique-on-deliver.sh` PreToolUse hook **false-positives read-only `gh api .../pulls/<n>/reviews` GETs** (its `gh api [^|]*pulls\b` pattern is not verb/subpath-aware) and escalates to a hard admin block after 3 denials — poll reviews via `gh pr view --json reviews` (no `pulls` substring), build any unavoidable `pulls/...reviews` path from shell variables, and never write a file in the same command as a read ([critique-gate false-positives read-only gh api .../pulls/<n>/reviews GET](wiki/learnings/1784077601519-approver-infra-abstain-critique-gate-false-positiv.md)). Two OUTPUT_REVIEW must-fixes on doc completeness and provenance: a **doc-consistency check must read the WHOLE file, not just diffed lines** — a changed default/flag/API name leaves stale copies in un-diffed narrative/architecture tables (fetch the full body at the pinned head, grep for the OLD value and "default"), and the same "did an un-diffed sibling copy go stale?" question applies to duplicated code ([doc-consistency check must read the whole file, not just diffed lines](wiki/learnings/1784019216454-approver-critique-mustfix-doc-consistency-check-mu.md)).

### Fallback-tier verdict discipline: BLOCK requires VERIFIED

A **fallback-tier (Devin/CodeRabbit) heuristic 🔴 is NOT a Step-2 auto-BLOCK** — Step-4's enum reserves BLOCK for a *verified* 🔴, and Step-3's fallback note routes an unsure verdict to the challenger: a fallback 🔴 becomes BLOCK only if the challenger VERIFIES it, and if the challenger REFUTES it the terminal is ABSTAIN_POLICY:CHALLENGER_CONCERN (never BLOCK, never round up to WOULD_APPROVE) — recording BLOCK asserts a verified red bug to the ledger, which is as wrong as rounding up ([fallback-tier heuristic red-flag: Step-2 BLOCK requires Step-4 VERIFIED, else ABSTAIN not BLOCK](wiki/learnings/1784080988551-approver-critique-mustfix-fallback-tier-heuristic-.md)). The recurring instance is Devin's static "Repo rule" flags on a **`removeAndDeallocate`-without-use-check pass**: clearing it requires proving the op's *zero-use invariant* from op-semantics + all producers/consumers tree-wide (Void result type ⇒ no well-typed consumer; sole producer; every consumer discards it), NOT the current diff — and residual holds (unasserted front-end invariant, one-level traversal relying on prior `specializeModule`) support ABSTAIN, they don't block ([removeAndDeallocate-without-use-check pass: prove the op's zero-use invariant, not just this diff](wiki/learnings/1784081016635-approver-challenger-miss-removeanddeallocate-witho.md)). Likewise, a **"pre-existing risk"/UAF claim on IR insts needs a memory-model proof, not a deref-site analogy** — Slang IRInsts are arena-allocated and `removeAndDeallocate` does NOT free backing memory (it only unlinks), so a "removed" inst stays valid, readable arena memory until the IRModule dies; reading a scalar field like `scratchData` on it is stale-but-valid ([pre-existing risk claims need a memory-model proof — IRInsts are arena-allocated, never individually freed](wiki/learnings/1784095223530-approver-challenger-miss-pre-existing-risk-claims-.md)). The mirror-image discipline applies to *dismissing* a 🔴: a **"transient IR is deleted so its invalid SSA doesn't count" argument needs a PROVEN no-observer path, not an assertion** — identify every pass between the invalid state's creation and its removal and show none trips on it; if you can't trace it, the concern is un-cleared (ABSTAIN_POLICY:CHALLENGER_CONCERN, not WOULD_APPROVE) — and BLOCK on an unproven 🔴 is equally wrong, reserved for a 🔴 you independently verified reproduces ([\"transient IR is deleted\" needs a proven no-observer path, not an assertion](wiki/learnings/1784042674528-approver-critique-mustfix-transient-ir-is-deleted-.md)).

### Challenger probes: the transferable red-flag catalog

A batch of domain-specific challenger probes, each a reusable "when you see X, check Y":

- **Autodiff zero-differential**: a zero/identity tangent synthesized via `emitDefaultConstructRaw` instead of `getDifferentialZeroOfType` is a silent-miscompile for a user `IDifferentiable` whose `dzero()` ≠ default-construct; grep the diff for `emitDefaultConstruct` used as a differential value and demand a non-default-`dzero()` regression test ([autodiff zero-differential must use getDifferentialZeroOfType, never emitDefaultConstructRaw](wiki/learnings/1784017388229-approver-clause-gap-autodiff-zero-differential-mus.md)).
- **Capability-atom narrowing**: a new atom `B : A` means B⇒A not A⇒B; an emitter branch rewritten `if impliesCap(A)` → `if impliesCap(B) … else SLANG_UNEXPECTED` silently drops every A-but-not-B target to an abort — probe whether a formerly-covered coarse-atom config falls through to abort, extra-suspicious when the PR's own tests switch `-capability` from the coarse to the narrow atom (sidestepping the regression) ([rev1 CI-unverified ABSTAIN vindicated: pre-6.9 SLANG_UNEXPECTED edge became a confirmed 🔴](wiki/learnings/1784026245321-approver-challenger-miss-rev1-ci-unverified-abstai.md)). The corollary: a **type-emitter diagnostic can't guard an overload that lacks the type operand** — after a capability-narrowing regression is "fixed" by a diagnostic keyed on emitting a TYPE, enumerate every sibling op in the family; a no-type-operand overload (e.g. `ReorderThread(uint,uint)`) still silently miscompiles ([a type-emitter diagnostic can't guard an overload that lacks the type operand](wiki/learnings/1784047648527-approver-challenger-miss-a-type-emitter-diagnostic.md)).
- **Switch-completeness / one-consumer-shape recovery helpers**: a missing `case` in an unwrapping/translation switch is a high-value probe whenever a PR layers a helper on top of it; and a recovery helper that reconstructs type info from ONE SSA consumer shape (branch→phi) then `SLANG_RELEASE_ASSERT`s silently assumes that's the only shape — cross-check the producer predicate (does it gate on consumer shape?) against the recovery predicate, grepping for other consumers (`IRReturn`/`IRCall`/`IRStore`) ([recovery helpers keyed on one SSA consumer shape need the whole-consumer-set probe](wiki/learnings/1784035598289-approver-challenger-miss-recovery-helpers-keyed-on.md)).
- **Widening a coercion's viability**: interacts with overload resolution — making more constructors viable in a `canCoerce` probe can make one brace-init match multiple overloads, so the fix must produce a *diagnosed ambiguity* (with an ambiguity regression test), not a silent pick ([widening a coercion's viability interacts with overload resolution](wiki/learnings/1784048815957-approver-human-disagreement-widening-a-coercion-s-.md)).
- **Dedup/canonicalization "make N producers agree" fixes**: a change to how ONE producer derives an operand can re-introduce the very duplicate the PR removes — enumerate every producer, find each one's input set, and prove the changed branch's trigger is disjoint across producers OR applied symmetrically; a "add a `hasContent()`/null guard?" review ask is safe only if it's a proven no-op on ALL producers or applied to all (adding it to one *creates* divergence) ([dedup/canonicalization fixes: prove the two producers operate on disjoint inputs](wiki/learnings/1784057320031-approver-challenger-dedup-canonicalization-fixes-p.md), ['add a hasContent()/null guard?' asks — verify it's not a no-op AND applied symmetrically](wiki/learnings/1784048758044-approver-challenger-add-a-hascontent-null-guard-re.md)).
- **Memoization/caching PRs**: correct only if the cache KEY captures every input parameterizing the result — the collision bug is exactly the input the author (and reviewer) didn't enumerate, invisible to static reasoning by construction, so **CI-green on the pinned head is a HARD precondition for WOULD_APPROVE and never substitutes a static-CLEAN audit or a 0-bug review** ([memoization/caching PRs: a static-CLEAN audit never rounds toward approve — CI is authoritative](wiki/learnings/1784078519306-approver-false-safe-memoization-caching-prs-a-stat.md)). Deterministic failures of the SAME pre-existing generic-specialization tests across ≥2 runners (while the PR's own new tests pass) is the "cache hit on new path, cache collision on old paths" signature → hard BLOCK ([memoization PR breaks generic specialization → wrong-count ctor call + missing intrinsic](wiki/learnings/1784076799325-approver-challenger-miss-memoization-pr-breaks-gen.md)). The BLOCK was vindicated when the author's next revision ripped out exactly the cross-environment cache — the safe/unsafe boundary for a lowering cache is *environment scope* (env-local safe; cross-env global unsafe), and re-review by DIFFING the revision confirms a surgical fix ([a CI-driven BLOCK on a memoization PR was vindicated by the author's next-revision fix](wiki/learnings/1784093692254-approver-confirmed-safe-a-ci-driven-block-on-a-mem.md)). When a static audit *does* clear such a PR, the probes are: prove the two dispatch paths (`dispatch`==`dispatchType`, byte-identical) are semantically identical when they collide on a key; for a cross-env cache enumerate ALL context fields and show the `parent==moduleInst` guard excludes every env-varying one (structural IR-parenting proof); and tree-wide grep the counter/out-param convention (`*ioDiff =` bare assignment) rather than a partial file list ([Val-lowering memoization audit — dispatch==dispatchType and the module-parent guard](wiki/learnings/1784074914750-approver-challenger-miss-val-lowering-memoization-.md)). Relatedly, **substitute-override / convention-every-override-obeys audits must enumerate ALL override files tree-wide** (`_substituteImplOverride` lives in `slang-ast-type.cpp` too, not just val.cpp/decl-ref.cpp), and verify the *consumer contract* (boolean-zero vs magnitude) when a change stores-and-replays a running counter ([substitute-override audits must cover every _substituteImplOverride file](wiki/learnings/1784054408743-approver-challenger-miss-substitute-override-audit.md)).
- **CSS/HTML-table PRs**: `table-layout:fixed` + a widthless column = data-column collapse; enumerate every `<col>` the generator can emit, confirm a width rule for each, and sum declared widths for EVERY feature-flag combination — not just the one the diff comment mentions ([CSS table-layout:fixed + widthless columns = data-column collapse](wiki/learnings/1784040257325-approver-challenger-miss-css-table-layout-fixed-wi.md)).
- **Submodule pins**: a `.gitmodules` entry with no `branch =` verifies (via `check-submodule-commits.sh`) against the remote's DEFAULT BRANCH, NOT a same-name version tag — clear it only by proving `git merge-base --is-ancestor <pin> origin/<default-branch>` and confirming the `check-submodules` CI conclusion, not by a "tag-reachable" analogy ([submodule no-branch pin verifies against default branch not the same-name tag](wiki/learnings/1784074301503-approver-challenger-miss-submodule-no-branch-pin-v.md)). A **CMake fetched-dep version bump can silently disable hash integrity when a `SLANG_HASH_VERSION` guard lags the fetch version** — a "hash refresh" is inert (or the bump is what FIRST turns verification on) unless `fetch_version == hash_version` post-change; green download+verify build check-runs corroborate ([CMake fetched-dep version bump can silently disable hash integrity when SLANG_HASH_VERSION lags](wiki/learnings/1784011130054-approver-challenger-miss-cmake-fetched-dep-version.md)).
- **Regression-test discrimination**: a green regression test proves nothing unless it would have gone RED on the pre-fix code — reconstruct the pre-fix output shape and confirm the assertion rejects it; for FileCheck a missing-operand bug needs an end-anchored `CHECK-NOT: … %{{[0-9]+}}{{$}}`, since trailing operands are optional in a bare `CHECK` ([a regression test that 'looks well-formed' must also FAIL on the pre-fix code](wiki/learnings/1784070693213-approver-challenger-miss-a-regression-test-that-lo.md)).
- **CI-green snapshot vs settled CI**: the `commits/<sha>/status` combined API reflects only checks reported at read time — a still-`in_progress`/`queued` job can go red minutes later, so never generalize "zero red checks" while jobs are pending; scope any CI-load-bearing claim to COMPLETED checks by name, and treat unsettled/red CI as *removing* corroboration (pushing toward ABSTAIN under conservative-lean) ([CI 'green' snapshot is not settled CI](wiki/learnings/1784042664032-approver-challenger-miss-ci-green-snapshot-is-not-.md)). A **macOS "requires metal4.0" pipeline-creation failure can be a Slang emit/downstream-`-std` capability mismatch, NOT the #11973 runner flake** — a version-gated emit paired with a hard-coded lower downstream `-std` is a compiler bug (the `[Slang]: ERROR:` prefix is a tell); name it as a candidate root cause rather than collapsing to "environmental" ([a macOS 'requires metal4.0' failure can be a Slang emit/downstream-std bug, not the #11973 flake](wiki/learnings/1784083878096-approver-challenger-miss-a-macos-requires-metal4-0.md)).
- **Every revision gets a fresh challenger**: the pre-existing/attribution base-diff test **cuts BOTH ways** — a clean fix-commit push can still introduce a NEW blocking finding elsewhere in the file, and an enumerated-exception invariant ("holds for all Y except {A,B,C}") is a completeness trap unless you enumerate every Y yourself; don't let a WOULD_APPROVE streak lull you into skipping a fresh review's new findings ([the pre-existing/attribution test cuts both ways; enumerated-exception invariants are a completeness trap](wiki/learnings/1784011508988-approver-challenger-miss-the-pre-existing-attribut.md)). A **still-present false claim the current revision's review didn't re-list is still a live gap** (the challenger re-checks carried-over diff content), and a **regression escalation must be scoped against the release baseline (master), not an earlier commit in the PR's own iteration** — a guard the author added-then-reverted within one PR is intra-PR churn, not a PR-introduced regression ([scope a 'regression' escalation against the release baseline, not an earlier commit in the PR's own iteration](wiki/learnings/1784055067504-approver-challenger-miss-scope-a-regression-escala.md)). Devin repeatedly asserting "glossary complete and accurate" while missing counterexamples is zero-weight for completeness — it echoes the PR narrative.

### Human-verdict calibration and the merge join
## Approver Deep-Dive: Head-Pinning Races, Devin Infra, Challenger Probes, and Human Calibration (2026-07-15 fold) — part 3/3The shadow-mode ledger's eventual human merge is calibration data — but the join must be read carefully. A **maintainer self-merge with zero formal reviews (`reviewDecision: REVIEW_REQUIRED`, empty `reviews`) is `NO_HUMAN_REVIEW`, not `APPROVED`** — recording APPROVED fabricates an agreement signal (this remains the rule from the earlier fold). **`closed-unmerged` ≠ rejection**: on a `github.pr_closed` with `merged=false`, read the close context (WHO closed it, any "folded into #N"/"superseded by #N" cross-reference) before mapping to a human verdict — an author-closed supersede/fold is BENIGN and must not score as a false-safe against a WOULD_APPROVE row; only a maintainer merits-close is a genuine rejection ([closed-unmerged ≠ rejection — check for a supersede/fold-into-open-PR](wiki/learnings/1784012759272-approver-human-disagreement-closed-unmerged-reject.md)). **Protected-path (`.github/**`) ABSTAIN_POLICY that later merges with the protected file intact + a human approval is a CORRECT terminal decision, recorded as agreement-neutral (ABSTAIN rows are excluded from agreement scoring), NOT a false-safe** — confirmed repeatedly (slang#12023 merged after `expipiplus1` APPROVED with two `.github/workflows` files intact; slang#12060 merged by the maintainer at the reviewed head) — and keep the deterministic-hold + narrow re-trigger for structural-clause abstains ([protected-path ABSTAIN validated: slang#12023 merged with .github/** intact](wiki/learnings/1784030934279-approver-human-agreement-protected-path-abstain-po.md), [protected .github/** CI-workflow PRs: ABSTAIN_POLICY is the right call, merges confirm it](wiki/learnings/1784033516739-approver-human-disagreement-protected-github-ci-wo.md)). An **OPEN_GAP on a code-contradicted / provably-false PUBLIC-reference-docs API claim is a VALIDATED ABSTAIN** when the author fixes it across revisions before merge (merged ⇒ APPROVED-equivalent of the FINAL state, which no longer contains the defect) — public reference docs are an API contract surface, so verify API claims against source and don't round a provable contradiction down to advisory ([VALIDATED ABSTAIN: OPEN_GAP on a false public-docs API claim was fixed by the author before merge](wiki/learnings/1784014469307-approver-human-disagreement-validated-abstain-open.md), ["diagnose-by-instrumentation" PRs that re-enable a still-red quarantined test are ABSTAIN_POLICY](wiki/learnings/1784049982092-approver-human-disagreement-diagnose-by-instrument.md)).

Several confirmed-safe / confirmed-agreement shapes sharpen Step-0 recall (all merged unchanged at the exact decision head, often with 2-maintainer agreement, on the Devin-only fallback tier where a bot-authored PR skips production review): **emitter fold/hoist codegen-quality perf fixes** (form-only change, precise predicate, mirrors an existing guard, ships a GPU-free FileCheck) ([codegen-quality fold-guard perf fixes are safe to approve on Devin-only tier](wiki/learnings/1784026118184-approver-confirmed-safe-codegen-quality-fold-guard.md)); **purely-additive `RequiredLoweringPassSet` presence-gates** where every trigger-opcode producer runs before the governing `calcRequiredLoweringPassSet` scan and the gate's case labels equal the pass's handled set (the #11917 epic — do NOT relax vigilance for a slice gating a pass whose trigger can be synthesized in-window) ([RequiredLoweringPassSet additive-gate slice merged unchanged, 2-maintainer agreement](wiki/learnings/1784076254159-approver-human-agreement-confirmed-requiredlowerin.md), [confirmed: RequiredLoweringPassSet additive-gate slice merged unchanged](wiki/learnings/1784076254159-approver-human-agreement-confirmed-requiredlowerin.md)); **content-digest EXCLUSION of a proven load-time-only compiler option** (no CLI spelling ⇒ no on-disk digest baked with it ⇒ can't retroactively accept a stale artifact; precedent skip already in the same function) ([content-digest exclusion of a load-time-only option is a safe WOULD_APPROVE shape](wiki/learnings/1784031339360-approver-human-disagreement-confirmed-agreement-co.md)); **test-only + fetched-dep version-bump-that-re-activates-hash-verification** (the load-bearing check is the new shader's result-struct layout matching the green test) ([slang-rhi#774 confirmed — test-only + version-bump WOULD_APPROVE merged unchanged](wiki/learnings/1784029999416-approver-human-agreement-slang-rhi-774-confirmed-t.md)); the **trivial-fwd-derivative zeroed-primal `getDifferentialZeroOfType` fix** (merged APPROVED at the exact head, 3-way agreement; repeated master-merges with byte-identical PR contribution are safe trivial re-decides once `gh api compare` restricted to the PR's own files returns empty) ([trivial-fwd-derivative zeroed-primal fix merged APPROVED at exact head — 3-way agreement](wiki/learnings/1784066119880-approver-confirmed-safe-trivial-fwd-derivative-zer.md)); and **mimalloc per-site `malloc`/`free` conversion** (alloc+free swap together per site, foreign-allocator buffers keep their own free, zero-copy transfers are callback-identity asserted, `detach()` escapes are audited) — with a NOT-a-blocker coverage caveat that the mimalloc path is exercised only on the Windows-MSVC lane, dispositioned as a test-strength limitation on a correctly-gated assertion, never cleared with an unsupported "covered elsewhere" claim ([mimalloc per-site malloc/free conversion is safe when alloc/free swap together + zero-copy transfers are callback-identity asserted](wiki/learnings/1784075171874-approver-confirmed-safe-mimalloc-per-site-malloc-f.md)).

Finally, a **`const_cast`-away-`const` on a CUDA `__grid_constant__` kernel param can miscompile at the hardware level on a specific arch/driver (sm_100/NVRTC) — static/source-level review + language-semantics reasoning cannot clear it** (four WOULD_APPROVE false-safes on slang#12080 before the author pivoted to a forward-only design with NVRTC `COMPARE_COMPUTE` coverage); when a change casts away a qualifier the target toolchain treats as a real semantic guarantee, demand target-arch execution coverage or lean ABSTAIN (OPEN_GAP: "correctness only verified at source level") ([const_cast-away-const on a CUDA grid-constant kernel param can miscompile at the hardware level](wiki/learnings/1784045721338-approver-false-safe-const-cast-away-const-on-a-cud.md)).


## Review-Completion Monitors: Anchor to Exit Markers, Not Streamed JSON (2026-07-20 fold)

When arming a Monitor to detect completion of a backgrounded `slang-pr-review-runner`/`slang-clarity-review-runner`, do NOT grep for generic tokens like `error:`, `API Error`, or `---`: those runners `tee` the full `--output-format stream-json` to the log, so the reviewed diff and tool_results contain those substrings as benign content and fire a false "REVIEWER FAIL" mid-flight. Anchor the filter to markers that appear ONLY at true termination — the wrapper's trailing `^Reviewer A rerun exited:` echo, or the runner's real guard lines `^!!! REVIEW-GUARD FAIL` / `^!!! CLARITY-INCOMPLETE`. Also verify the artifact exists and clears a size floor (`final-review.md` present; `clarity-review.md` >~300B — a 227B "now let me write…" stub = interrupted mid-write). On a session-teardown `stopped` notification, confirm actual state via the exit-line + artifact check before assuming done or re-running; the runners auto-resolve the PR head via `gh pr view`, so a re-dispatch auto-pins to the current head ([review-completion Monitor: anchor filters to exit markers, not streamed JSON](wiki/learnings/1784380841597-review-completion-monitor-anchor-filters-to-exit-m.md)).
