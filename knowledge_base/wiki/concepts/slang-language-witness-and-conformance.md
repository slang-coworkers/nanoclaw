# Slang Witness Tables, Conformance & Extensions

How Slang represents interface conformance (witness tables and subtype-witness `Val` classes) and how `extension` declarations resolve names across namespace fragments. (Container coercion and overload resolution live in [[wiki/concepts/slang-language-coercion-and-overload.md]]; visibility, layout, and codegen surfaces live in [[wiki/concepts/slang-language-visibility-and-layout.md]]; generic specialization and inference live in [[wiki/concepts/slang-language-generics-and-type-system.md]].)

## TL;DR

- Inherited witness-table requirements live on nested base-interface tables, not the flat top-level table; a flat `findWitnessTableEntry` returns null for inherited keys — use the inheritance-closure walk.
- On a partial witness-table-set miss (N-of-M found), return `none()` (keep the lookup dynamic), never a partial result — a surviving entry misdispatches to tags whose tables missed. Producer/analyzer sites return `none()`; consumer sites hard-assert.
- `DeclaredSubtypeWitness` vs `ExtractExistentialSubtypeWitness` differ only in Val class, and that class drives codegen (static table vs runtime extraction). Swapping witness class to fix type identity silently changes codegen.
- Pack-query `__first`/`__last` produce a `First`/`Last SubtypeWitness` that two lowering consumers (`isTypeEqualityWitness`, `emitCastToConcreteSuperTypeRec`) omit, so a `where`-clause cast of the result SIGSEGVs (#12494); a new SubtypeWitness subclass must be taught to BOTH lowering layers.
- Associated constants fold only via `DeclaredSubtypeWitness`. A concrete-witness fold can still return symbolic because the conformance table isn't built yet — fix with `ensureDecl(sub, ReadyForConformances)`, not `resolve()`/normalize.
- `override = 0` on `createTypeConformanceComponentType` always duplicates the `(T,I)` entry — auto-ID assignment never picks 0.
- Widening a builtin *interface requirement* (not a concrete method) re-matches every conformer — far larger blast radius than a concrete member. Adding an explicit member *to* Array/vector/matrix has zero blast radius on `arr[i]` (hard-routed to `CheckSimpleSubscriptExpr`).
- Adding a requirement to a non-`[sealed]` interface breaks the OPEN user-conformer set; an in-tree differential proves nothing, and successful synthesis can be silently wrong. Prefer an `extension` that diagnoses.
- A requirement reached through an `optional` constraint's super-interface escapes `isWitnessUncheckedOptional` (ICE or silent leak). Witness shapes drift between HEADs, so re-verify a triaged root cause by instrumentation, and print the decl-ref kind and its lookup witness, not only the leaf decl (the optional proof hides in a `LookupDeclRef` base).
- Witness search is single-point (`isSubtype` returns null, never diagnoses); strict-vs-query lives at the caller (`OverloadResolveContext::Mode`).
- Two `Val`s that print identically can still be unequal: `toString` hides witness generic args and `Val::equals` compares resolved pointers. When `isSubtype` misses a facet that "looks" right, dump and diff the operand trees.
- Equality constraints resolve both endpoints eagerly in inheritance matching — a re-entrancy surface a directed-constraint fix misses.
- Function-local interface conformance crashes at two stages (front-end for a constrained generic requirement, IR lowering for a generic local struct). Phase-ordering fixes often belong at the shared consumer, after enumerating its entry paths.
- Extension headers resolve names before namespace fragments reach `ScopesWired` (E30015). Fix: pre-pass wiring ALL module-level `NamespaceDecl`s to `ScopesWired` — not enclosing-only, not whole-module `ensureAllDeclsRec`.
- The core module DOES contain namespace-enclosed extensions (`namespace linalg` in `hlsl.meta.slang`). "No namespaced core extensions" is factually false.
- Struct-vs-extension same-name member: direct access prefers the non-extension decl; interface dispatch front-loads the extension's member. Design-gated (undefined); `override` already exists. `InterfaceDecl : AggTypeDecl`, so a "just assert it" guard can abort on interface extensions.
- #13387's per-conformance copies cover only the `extension<G:I> G` method spelling (value-generic variants included); a free generic `f<G:I>(G g)` keeps one shared body, and a signature that depends on `T` stays E33180 in Slang 2025 by design.

## Witness Tables and Conformance

Inherited witness-table requirements live on nested base-interface tables, not the flat top-level table. `findWitnessTableEntry` in `slang-ir-util.cpp` is flat and returns null for inherited keys, so a caller that does not null-guard crashes or silently misdispatches; `findWitnessTableEntryInInheritanceClosure` recurses into inheritance entries ([Slang inherited witness-table requirements live on nested base-interface tables](../learnings/1780677948078-slang-inherited-witness-table-requirements-live-on.md)).

When a witness-table-set filtering walk partially misses (N-of-M tables found), a partial result misdispatches: the surviving entry is applied to all runtime tags, including those whose tables missed. Free the partial result and return `none()` so the lookup stays dynamic. Miss handling follows each site's pipeline role: analyzer/producer sites return `false`/`none()`, consumer/downstream sites hard-assert ([Witness-table-set filtering: partial-miss is a silent-misdispatch trap](../learnings/1780769309511-witness-table-set-filtering-partial-miss-is-a-sile.md)).

**The witness Val class is load-bearing at lowering.** `DeclaredSubtypeWitness` and `ExtractExistentialSubtypeWitness` carry identical operands, but the class drives codegen: a static witness table versus a runtime `emitExtractExistentialWitnessTable`. Swapping the witness class to fix type identity silently changes codegen ([Slang: subtype-witness Val-class is load-bearing at lowering](../learnings/1780530677473-slang-subtype-witness-val-class-is-load-bearing-at.md)). A new SubtypeWitness subclass that a lowering consumer does not handle crashes. Consider #12494: `__first(args)`/`__last(args)` over `expand each T args`, cast to a concrete type through a `where`-clause witness (`where T == int`), SIGSEGVs slangc; Debug asserts `!"unhandled"` in `emitCastToConcreteSuperTypeRec` (`slang-lower-to-ir.cpp:7252`), Release derefs the returned nullptr. `__first`/`__last` produce a `FirstSubtypeWitness`/`LastSubtypeWitness` (`slang-check-inheritance.cpp:2197-2205`). `isTypeEqualityWitness` (`slang-ast-val.h:1352`) recurses through Each/TypePack/Expand/TrimFirst/TrimLast but omits First/Last, so the no-op `where T==int` cast is not recognized (`:7288`) and falls into `emitCastToConcreteSuperTypeRec` (`:7214`), which handles only Declared/Transitive witnesses. The fix spans both layers: add First/Last to `isTypeEqualityWitness` (precedent: PR #8736 added `ExpandSubtypeWitness` there and also fixed the identical #6856; the cast is representation-only because `__first` already lowers to `kIROp_ExtractFirstFromPack`), and handle the sibling genuine upcast (a `__first` result upcast to a real struct base through a Declared inheritance witness) in `emitCastToConcreteSuperTypeRec`. On the Release SIGSEGV `addr2line` mis-hit an inlined return address; the Debug assert line is authoritative for which function crashed ([Pack-query __first/__last cast crash: two-layer witness gap](../learnings/1786529197320-pack-query-first-last-cast-crash-two-layer-witness.md)).

`ISession::createTypeConformanceComponentType` always allocates a new conformance entry instead of looking up the source-declared one, and `override = 0` always breaks `is`/`as` because auto-ID assignment never picks 0, guaranteeing a duplicate entry ([slang type-conformance override=0 always duplicates the (T,I) entry](../learnings/1780414379429-slang-type-conformance-override-0-always-duplicate.md)).

Associated constants fold only via `DeclaredSubtypeWitness`; `getUnspecializedLookupRec` returns nothing for other witness subclasses. A fold in a declaration/signature-type position can still return symbolic over a concrete `DeclaredSubtypeWitness`, not because the witness has the wrong class but because the conformance witness table is not built yet at fold time. The fix is `ensureDecl(sub, ReadyForConformances)` before re-folding, not `resolve()`/normalize ([slang associated-constant fold gated on DeclaredSubtypeWitness](../learnings/1782215625162-slang-associated-constant-fold-gated-on-declaredsu.md), [a fold over a concrete DeclaredSubtypeWitness can return symbolic because the table isn't built yet](../learnings/1782224910624-slang-a-fold-over-a-concrete-declaredsubtypewitnes.md)).

**Widening an interface requirement re-matches every conformer.** Widening `IArray`/`IRWArray`'s `__subscript(int index)` (core.meta.slang) to `__generic<TIndex : __BuiltinIntegerType> __subscript(TIndex index)` (#11990) cascaded in three stages, even with the conforming method declared directly on Array/vector/matrix: (1) a core-module bootstrap crash, `SLANG_ASSERT(foundParent)` at `slang-ast-builder.h:430`, because RWStructuredBuffer's synthesized get/set wrapper for its bare generic `ref` subscript forms a bad decl-ref under the `GenericDecl`-wrapped subscript (fixed by a `case ASTNodeType::GenericDecl:` in the decl-ref normalization at `:396` that unwraps `Member(Lookup(w, GenericDecl[SubscriptDecl]), get/set/ref)`, accepting `RefAccessorDecl`); (2) E38105 on every explicit non-generic conformer (CoopMat/CoopVec `__subscript(int)`, and E30019 on their `__indexRead`/`__indexRef` helpers); (3) a terminal E39999, because CoopVec's autodiff `fwd_diff/bwd_diff(CoopVec<T,N>::__subscript::get/set)` registrations become ambiguous between two identical generic candidates, its own and the inherited one — an autodiff-design decision. By contrast, adding an explicit `__subscript` *to* Array/vector/matrix has no blast radius on `arr[i]`: `visitIndexExpr` (`slang-check-expr.cpp:3579-3594`) hard-routes those types to `CheckSimpleSubscriptExpr`, so the member participates only in conformance. Debug `slang-bootstrap` has no try/catch (`main.cpp #ifndef _DEBUG`), so an uncaught `InternalError` from a core-module check terminates without a message; flip `if(false)`→`if(true)` at `slang-signal.cpp:~119` to print `g_lastSignalMessage`, and iterate with the ~1-3 min incremental `--target slang-bootstrap` relink instead of a full build ([Widening a Slang interface subscript requirement to generic cascades beyond stdlib (#11990)](../learnings/1784276750681-widening-a-slang-interface-subscript-requirement-t.md)).

**Adding a requirement to a non-`[sealed]` interface is breaking over the OPEN user-conformer set.** On slang#12311, `(T)0.25` in a `T:IArithmetic` body floors to 0 because `IArithmetic` declares `__init(int)` and no `__init(float)`. A new `__init(float)` requirement passed a differential slangi run over every in-tree conformer, and the maintainer still rejected it, correctly: `IArithmetic`/`IFloat`/`IComparable` are not `[sealed]` (only `IArithmeticAtomicable` is), so the conformers include user types no suite can exercise. Synthesis succeeding can be worse than failing: for a user fixed-point `struct : IArithmetic` with only `__init(int)`, synthesizing `__init(float)` through it makes `(T)0.25` silently truncate to 0, so "it compiles" is not "it is correct". Check `[sealed]` before changing a public interface's requirements. The preferred remedy for such a footgun is an `extension<T> where T:IArithmetic { __init(float){…} }` that diagnoses a compile error (an extension member is not a requirement, so no user conformance changes); real interface evolution belongs in the experimental `slang.numerics` module ([a 'non-breaking' check on a non-`[sealed]` interface must cover the open user-conformer set](../learnings/1789159225247-a-non-breaking-check-on-a-non-sealed-interface-mus.md)).

**An optional-constraint requirement reached through interface inheritance escapes the optional-witness guard.** Consider `T compute<T>(T a,T b) where optional T : I { return a+b; }` called with a non-conforming `T`. If `I` directly declares the used requirement, behavior is clean (`a+b` → "no overload for '+'"; `a.add(b)` → E30403 "must be checked with an 'is' statement"). If the requirement lives on a super-interface (`optional T : IFloat | IInteger | __BuiltinFloatingPointType`, all inheriting `IArithmetic`), the guard `isWitnessUncheckedOptional` (`slang-check-expr.cpp:1315`), which recognizes only a bare `DeclaredSubtypeWitness` carrying `OptionalConstraintModifier`, returns false; IR emits `call(lookupWitness(optionalWitness, …→Super.add))`, and specialization ICEs with `SLANG_UNEXPECTED("Unexpected context type for parameter info retrieval")` in `slang-ir-typeflow-specialize.cpp`. Plain `IFloat`/`IInteger` reproduce it; the builtin markers merely sit several inheritance hops above their requirements ([optional-constraint ICE: a requirement reached through interface inheritance escapes the optional-witness guard](../learnings/1789135806162-slang-optional-constraint-ice-requirement-reached-.md)). The witness shape behind this differs by HEAD. At `d3a113484` the super-interface case composed a transitive witness, and the sibling soundness leak #13061 (`where optional T : __BuiltinIntegerType { return a+b; }` type-checks silently) was triaged as "descend `TransitiveSubtypeWitness::getSubToMid()`". At `8d763dd390`, instrumenting `isWitnessUncheckedOptional` shows a bare `DeclaredSubtypeWitness` whose `declRef` is the interface's `$inheritance` `InheritanceDecl`: the super-interface conformance is flattened and drops the optional-ness, which lives only on the user function's `T : __BuiltinIntegerType` `GenericTypeConstraintDecl`, so the descent is a no-op. That reading saw only the leaf decl: the witness's decl-ref is a `LookupDeclRef` whose `getWitness()` is the optional root, which PR #14096 follows (details on [[wiki/concepts/slang-language-core-f0909b0-interfaces-witness-conformance.md]]) [the optional proof is in the witness's LookupDeclRef base](../learnings/1793382125314-slang-optional-constraint-inherited-requirement-th.md). Re-verify a triaged root cause against the current checkout by instrumentation. The real fix needs a layer decision: preserve optionality when inheritance linearization flattens a generic param's indirect-base conformances (producer), or recurse `isWitnessUncheckedOptional` through the flattened witness's provenance (consumer, a graph-walk red flag). The prebuilt master `slangc` reproduces both the leak (exit 0) and the sibling ICE #13011 (`E99997 ... Unexpected context type for parameter info retrieval`, `-target spirv`) GPU-free; `SLANG_ASSERT=release-assert-only` avoids the abort dialog ([slang#13061: optional-constraint super-interface conformance is a flattened InheritanceDecl witness at HEAD](../learnings/1789651782494-slang-13061-optional-constraint-super-interface-co.md)).

Link-time `export`/`extern` wrapper associated-type resolution (the #9580 / #12131 / #12134 cluster) has **two requirement-resolution entry points that behave differently on transitivity** (`TransitiveSubtypeWitness`), which matters for any base-interface or transitive fix ([slang link-time assoc-type resolution: two resolvers differ on TransitiveSubtypeWitness (#12134)](../learnings/1784248435373-slang-link-time-assoc-type-resolution-two-resolver.md)).

**Reference map: conformance-witness core (master `928f4010f`, from the #12995 promise-witness feasibility work).** Witness search and creation is a single point: `SemanticsVisitor::isSubtype(Type*, Type*, IsSubTypeOptions)` (`slang-check-conformance.cpp:51`) returns a `SubtypeWitness*` or null and never diagnoses, and its builder `checkAndConstructSubtypeWitness` (`:220`) scans `getInheritanceInfo(subType).facets` and constructs via `getDeclaredSubtypeWitness`/`getOrCreate<DynamicSubtypeWitness>`. `IsSubTypeOptions` (`None`/`NoCaching`) is cache control, not strictness: `NoCaching` avoids caching provisional results that create circular dependencies. Strict-vs-query lives at the caller layer, in `OverloadResolveContext::Mode {JustTrying, ForReal}` plus the diagnose-on-null versus return-bool convention: `TryCheckOverloadCandidateConstraints` (`slang-check-overload.cpp:1157`) applies `TypeArgumentDoesNotConformToInterface` after a null witness at `:1300`, while the solver at `slang-check-constraint.cpp:2939` demands `isSubtype` with no diagnostic. Per-call-site strictness at the witness core therefore means plumbing the mode down a widely-called signature. The global Val epoch (`Session::m_epochId`, `ASTBuilder::getEpoch()/incrementEpoch()`) has three `incrementEpoch()` callers (the ASTBuilder dtor, after folding a defaulted-assoc-type witness, and after conformance checking creates new witness tables), meaning "a new witness table exists, so cached `Val::resolve()` results are stale"; the finer per-decl `bumpDeclExtensionEpoch` governs inheritance-info caching. `getInheritanceInfo` marks `isComputing` and rolls the cache entry back on a partial (`frameSkipped`) result, the precedent for deferred checking. Subtype witnesses are hash-consed Vals consumed at IR lowering, so a provisional witness must `resolve()` to a concrete form before lowering ([conformance-witness core, strict-vs-query mode, and Val-epoch map @ master 928f4010f](../learnings/1789068321840-slang-conformance-witness-core-strict-vs-query-mod.md)).

**When `isSubtype` returns null although a facet prints identically, diff operand trees, not strings.** `toString` skips witness generic arguments and `Val::equals` compares resolved pointers, so two different `DiffTypeInfoWitness` shapes can print the same. On slang#13322, `isSubtype(X, IForwardDifferentiable<X>)` returned null although X's facets listed a type printing exactly as `IForwardDifferentiable<X>`. Instrumenting `isSubtype` with a recursive operand dump (class name, pointer and decl name per DeclRef; walk `m_operands` by kind, printing NULL for empty operands) and diffing facet against query found the cause: `HigherOrderDiffTypeTranslationWitness::_resolveImplOverride` kept a method's `this` as the DTI's `this`, but the forward derivative is a static function taking `this` as its first parameter (`FwdDiffFuncType::_resolveImplOverride` pairs parameters by position), so the declared optional conformance `V.m.fwd_diff : IForwardDifferentiable` never equals its use-site query. `DiffTypeInfoWitness::_toTextOverride` dereferences operand 0 (`thisParamType`), which is null for static functions, so `toString` on such a value segfaults ([isSubtype fails although the facet prints identical: dump operand trees](../learnings/1790705562977-slang-issubtype-fails-although-the-facet-type-prin.md)).

**Inheritance constraint-matching resolves equality constraints eagerly on both endpoints, a re-entrancy surface a directed-constraint fix does not cover.** slang#12690 fixes a false E38029 caused by eagerly `ensureDecl`-ing an unrelated sibling constraint whose dependent super-type re-enters the in-progress `_calcInheritanceInfo` query; it moves the subject-relevance filter before `ensureDecl` (`resolveConstraintTypesForInheritanceMatch` → {Resolved, Deferred, Invalid}). A directed `S : B` resolves only `S` and defers `B` (the tested #12659 path). An equality `L == R` must resolve both endpoints, since either can match `selfType`: a multi-level `MemberExpr` endpoint returns `Deferred`, but a generic-app leaf (`__constraint Alias == G<Context>`) is force-resolved via `TranslateTypeNodeForced` and can re-enter the query. The shape is unusual and possibly unreachable, but when reviewing a directed-vs-equality special case, ask whether the equality branch eagerly resolves what the directed branch defers; two review sources disagreeing on one line (production ✅ Clean vs Devin 🔴 at :1163) is the signal to dig, not to average. Under error recovery that replaces endpoints with `ErrorType`, a graceful `NoBase` return beats `SLANG_RELEASE_ASSERT(selfIsSub||selfIsSup)` ([inheritance constraint-matching: equality constraints resolve both endpoints eagerly](../learnings/1789071218256-approver-challenger-miss-inheritance-constraint-ma.md)).

**A function-local struct that implements an interface has two independent crash bugs, at different stages.** The front-end crash (#12987, fixed by #12988) needs a *constrained* generic requirement (`int apply<T:__BuiltinArithmeticType>(T)`): `doesGenericSignatureMatchRequirement` (`slang-check-decl.cpp`) calls `getSub(satisfyingConstraintDecl)`, which is null because a function-nested type's constraint decl was never advanced to `DeclCheckState::SignatureChecked`, so `Val::equals`/`resolve()` null-derefs. The IR-lowering crash (#13092, not fixed by #12988) needs a *generic* local struct (`Op<U>`) with conformance and lowered witness content (e.g. a field), even with an unconstrained method: it passes the front end and crashes in `DeclLoweringVisitor::lowerWitnessTable` (`slang-lower-to-ir.cpp:11181`) on a null `OrderedDictionary<Decl*,RequirementWitness>::begin()` via `visitInheritanceDecl:11536`. Boundary controls that all compile cleanly — module-scope, non-generic local + unconstrained, empty generic local, unconstrained method — tell the two apart; a generic local struct with a constrained method can hit the front-end bug first and mask the lowering one ([function-local interface conformance crashes at TWO compiler stages](../learnings/1789483742996-function-local-interface-conformance-crashes-at-tw.md)). The #12988 fix belongs at the consumer choke point, `ensureDecl(constraintDecl, SignatureChecked)` in `doesGenericSignatureMatchRequirement` (constraint decls only; advancing the enclosing type mid-conformance is a CyclicReference), not at the producer (`visitBlockStmt`) the maintainer first preferred, because other paths reach the matcher without `visitBlockStmt`: a module-scope type checked on demand via `tryConstantFoldDeclRef → ensureDecl(..., ReadyForConformances)`, and a generic local `struct Op<T>` whose `GenericDecl` wrapper `getDirectMemberDeclsOfType<AggTypeDeclBase>()` skips. Before adopting a producer-side alternative to a consumer-side fix, enumerate every entry path into the consumer (codex CODE_REVIEW is good at finding the missed ones). Before blaming your change for a full-suite regression, diff the failure set against a clean baseline: a "47 failures in tests/numerics/" scare was pre-existing container breakage (`slang.numerics` does not resolve there). `SLANG_ASSERT` becomes UB `SLANG_ASSUME` in release, so a fail-loud guard needs `SLANG_RELEASE_ASSERT` ([phase-ordering fixes: the shared consumer/choke point often beats the producer](../learnings/1789483453715-phase-ordering-fixes-the-shared-consumer-choke-poi.md)).

## Extensions and Namespace Scoping

Cross-fragment namespace lookup inside `extension` headers fails with E30015 (unqualified name) because the extension-first pass in `checkModule` resolves headers before `ensureAllDeclsRec` wires namespace sibling scopes ([#11531 root cause: extension headers resolve names before namespace fragments reach ScopesWired](../learnings/1781071107223-slang-11531-root-cause-extension-headers-resolve-n.md)). The fix (maintainer PR #11577) is a `discoverNamespaceDecls` pre-pass that drives ALL module-level `NamespaceDecl`s to `ScopesWired` before the extension loop — not enclosing-only (too narrow, misses #11532) and not whole-module `ensureAllDeclsRec` (regresses core-library texture extensions) ([#11531/#11532 fix: wire ALL module-level NamespaceDecls before the extension-first pass](../learnings/1781244954865-slang-11531-11532-fix-wire-all-module-level-namesp.md)). Its core-module safety rests on the `as<NamespaceDecl>` filter, not on an absence of namespaced core extensions ([#11531 Approach B core-module safety rests on the as&lt;NamespaceDecl&gt; filter](../learnings/1781086844343-slang-11531-approach-b-core-module-safety-rests-on.md)): the core module DOES contain one (`namespace linalg { extension ... }` in `hlsl.meta.slang`), and the opposite claim has shipped in a PR description. Verify the mechanism a scope-wiring change touches, not the supposed absence of the risky construct ([core module HAS a namespace-enclosed extension (namespace linalg)](../learnings/1781088865270-slang-core-module-has-a-namespace-enclosed-extensi.md)).

Extension method name hints drop the type qualifier because `getNameForNameHint` has no `ExtensionDecl` case, producing unqualified SPIR-V debug names. The fix redirects to the extension's target type via `as<DeclRefType>(extensionDecl->targetType)->getDeclRef().getDecl()`. Every legal extension target (builtins, vectors, typedefs, generic structs) is a nominal `DeclRefType<ContainerDecl>`, so an unqualified fallback is unreachable by construction: the checker rejects non-nominal targets ([extension-method name hints drop the Type. qualifier](../learnings/1781199860108-slang-extension-method-name-hints-drop-the-type-qu.md), [extension name-hint qualification has no reachable unqualified fallback](../learnings/1781269392733-slang-extension-name-hint-qualification-has-no-rea.md)).

When a struct and an extension both declare the same member name, two independent policies apply: direct member access prefers the non-extension decl (the base silently wins via `CompareLookupResultItems`), while interface dispatch front-loads the extension's member as the witness. A nested-type static member inside an extension hard-errors on ambiguity because `getParentDeclRef` checks only the immediate parent ([extension same-name member resolution — dual policy + immediate-parent tie-break gap (#9660)](../learnings/1782215352976-slang-extension-same-name-member-resolution-dual-p.md)). The behavior is documented as undefined and design-gated, and the `override` keyword already exists ([slang#9660 extension shadowing — design-gated](../learnings/1782216036396-slang-9660-extension-shadowing-design-gated-overri.md)). A "just assert it" clarity suggestion for the `AggTypeDecl` guard is unsafe because `InterfaceDecl : AggTypeDecl`: interface extensions pass the guard but are absent from `getCandidateExtensions` (registered before being diagnosed-and-returned), so `indexOf` returns -1 and the assert aborts ([#9660: a 'just assert it' clarity suggestion can introduce an abort regression](../learnings/1782745012175-slang-9660-a-just-assert-it-clarity-suggestion-can.md)).

Which extensions count as conformance candidates at a call site depends on the caller's own imports (direct or through `__exported import`), not the callee's; the E38029 consequence for libraries over slang.numerics is on [[wiki/concepts/slang-language-core-f0909b0-fp-interface-tower-conformance.md]].

**Per-conformance extension methods (#13387): only the extension spelling is covered.** The #13387 rework gives an `extension<T : I> T` method called on a dynamic object one copy per conformer plus a dispatcher; its specialize-pass mechanics are on [[wiki/concepts/slang-compiler-type-flow-set-specialization-diamonds.md]]. Measured on the #13268 RayQuery compact repro (DXIL commit/phi counts at -O3, SPIR-V validated; `-std 2025` selects Slang 2025 mode), master 52e29ab43 vs fixer head 8c5bb99eb: (1) `extension<G:IGeometry> G { void m(inout Handler, inout RayQuery<0>) }` called on `createDynamicObject` goes from 1/18 with one shared body in legacy mode and E33180 in 2025 mode to 2/13 in both modes, the same shape as a default-method callback. (2) The same method with `<let FLAGS:uint>` and `RayQuery<FLAGS>` goes from E99997 "unexpected set kind" in both modes to 2/13. (3) A FREE generic `f<G:IGeometry>(G g, …)` is NOT covered (still 1/18, and E33180 in 2025). (4) An extension method that returns `G` and has its own value generic goes from legacy E99997 to compiling in legacy mode, but stays E33180 in 2025 by design, because its signature depends on `T`. (5) A blanket `extension<G:I> G : J` with `-conformance` in the primary TU is still E00073. To build the fixer worktree, run `git -c protocol.file.allow=always submodule update --init --recursive`, and build the `slang-glslang` target for SPIR-V output (otherwise E00100, a spirv-opt load failure) ([#13387 per-conformance extension methods: what is and isn't covered](../learnings/1792919629099-13387-per-conformance-extension-methods-what-is-an.md)).
