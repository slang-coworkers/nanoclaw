# Slang Witness Tables, Conformance & Extensions

How Slang represents interface conformance (witness tables and subtype-witness `Val` classes) and how `extension` declarations resolve names across namespace fragments. (Container coercion and overload resolution live in [[wiki/concepts/slang-language-coercion-and-overload.md]]; visibility, layout, and codegen surfaces live in [[wiki/concepts/slang-language-visibility-and-layout.md]]; generic specialization and inference live in [[wiki/concepts/slang-language-generics-and-type-system.md]].)

## TL;DR

- Inherited witness-table requirements live on nested base-interface tables, not the flat top-level table; a flat `findWitnessTableEntry` returns null for inherited keys — use the inheritance-closure walk.
- On a partial witness-table-set miss (N-of-M found), return `none()` (keep the lookup dynamic), never a partial result — a surviving entry misdispatches to tags whose tables missed. Producer/analyzer sites return `none()`; consumer sites hard-assert.
- `DeclaredSubtypeWitness` vs `ExtractExistentialSubtypeWitness` differ only in Val class, and that class drives codegen (static table vs runtime extraction). Swapping witness class to fix type identity silently changes codegen.
- Widening a builtin *interface requirement* (not a concrete method) re-matches every conformer — far larger blast radius than a concrete member. Adding an explicit member *to* Array/vector/matrix has zero blast radius on `arr[i]` (hard-routed to `CheckSimpleSubscriptExpr`).
- Associated constants fold only via `DeclaredSubtypeWitness`. A concrete-witness fold can still return symbolic because the conformance table isn't built yet — fix with `ensureDecl(sub, ReadyForConformances)`, not `resolve()`/normalize.
- `override = 0` on `createTypeConformanceComponentType` always duplicates the `(T,I)` entry — auto-ID assignment never picks 0.
- Extension headers resolve names before namespace fragments reach `ScopesWired` (E30015). Fix: pre-pass wiring ALL module-level `NamespaceDecl`s to `ScopesWired` — not enclosing-only, not whole-module `ensureAllDeclsRec`.
- The core module DOES contain namespace-enclosed extensions (`namespace linalg` in `hlsl.meta.slang`). "No namespaced core extensions" is factually false.
- Struct-vs-extension same-name member: direct access prefers the non-extension decl; interface dispatch front-loads the extension's member. Design-gated (undefined); `override` already exists. `InterfaceDecl : AggTypeDecl`, so a "just assert it" guard can abort on interface extensions.
- Pack-query `__first`/`__last` produce a `First`/`Last SubtypeWitness` — a witness Val subclass two lowering consumers (`isTypeEqualityWitness`, `emitCastToConcreteSuperTypeRec`) omit, so a `where`-clause cast of the result SIGSEGVs (#12494); a new SubtypeWitness subclass must be taught to BOTH lowering layers.

## Witness Tables and Conformance

Inherited witness-table requirements live on nested tables, not the flat top-level table. `findWitnessTableEntry` in `slang-ir-util.cpp` is flat and returns null for inherited keys, causing crashes or silent misdispatch if callers do not null-guard ([Slang inherited witness-table requirements live on nested base-interface tables](../learnings/1780677948078-slang-inherited-witness-table-requirements-live-on.md)). The fix is `findWitnessTableEntryInInheritanceClosure` which recurses into inheritance entries.

When a witness-table-set filtering walk can partially miss (N-of-M tables found), returning a partial result causes singleton-misdispatch: a surviving entry is applied to all runtime tags, including ones whose tables missed. The correct policy is to free the partial result and return `none()` so the lookup stays dynamic. Miss-handling policy differs by pipeline role: analyzer/producer sites return `false`/`none()` on miss; consumer/downstream sites must hard-assert ([Witness-table-set filtering: partial-miss is a silent-misdispatch trap, and miss-handling policy must match each site's role](../learnings/1780769309511-witness-table-set-filtering-partial-miss-is-a-sile.md)).

Widening a builtin *interface requirement* (as opposed to a concrete method) has a far larger blast radius than widening a concrete member, because every conformer must be re-matched against the new signature. Widening `IArray`/`IRWArray`'s `__subscript(int index)` requirement (core.meta.slang) to `__generic<TIndex : __BuiltinIntegerType> __subscript(TIndex index)` (#11990) cascades in three stages even after following csyonghe's advice to declare the conforming method directly on Array/vector/matrix rather than relying on witness synthesis: (1) core-module bootstrap CRASH — `SLANG_ASSERT(foundParent)` at `slang-ast-builder.h:430` on a malformed `Member(RWStructuredBuffer, get)`, because RWStructuredBuffer satisfies IRWArray via a bare generic `ref` subscript and its synthesized get/set wrapper forms a bad decl-ref for the accessor nested under the `GenericDecl`-wrapped subscript (fix: add a `case ASTNodeType::GenericDecl:` to the decl-ref normalization special-case at `:396` that unwraps `Member(Lookup(w, GenericDecl[SubscriptDecl]), get/set/ref)`, accepting `RefAccessorDecl` too); (2) E38105 on every other explicit non-generic conformer — CoopMat/CoopVec have explicit `__subscript(int)` and `: IArray<T>` and must be widened to match (plus their `__indexRead`/`__indexRef` helpers → E30019); (3) TERMINAL E39999 — CoopVec's autodiff `fwd_diff/bwd_diff(CoopVec<T,N>::__subscript::get/set)` registrations become ambiguous because resolution now finds two identical generic candidates (CoopVec's own subscript + the inherited IArray generic subscript), where the old identical `int` signatures resolved fine — an autodiff-design call (own-member-shadows-identically-signatured-inherited disambiguation). Contrast: adding an explicit `__subscript` *to* Array/vector/matrix has NO blast radius on direct `arr[i]` indexing, because `visitIndexExpr` (`slang-check-expr.cpp:3579-3594`) hard-routes those base types to `CheckSimpleSubscriptExpr` and never consults `__subscript` members — the explicit member participates only in interface conformance. Reusable debug technique for core-module bootstrap crashes: Debug `slang-bootstrap` has NO try/catch (`main.cpp #ifndef _DEBUG`), so an uncaught `InternalError` from a core-module check hits `terminate` with no message — flip `if(false)`→`if(true)` at `slang-signal.cpp:~119` to fprintf `g_lastSignalMessage`, then iterate with the ~1-3 min incremental `cmake --build --preset debug --target slang-bootstrap` relink rather than a full 20-min build ([Widening a Slang interface subscript requirement to generic cascades beyond stdlib (#11990)](../learnings/1784276750681-widening-a-slang-interface-subscript-requirement-t.md)).

`DeclaredSubtypeWitness` and `ExtractExistentialSubtypeWitness` carry identical operands but differ in Val class, and that class drives codegen: `DeclaredSubtypeWitness` → static witness table; `ExtractExistentialSubtypeWitness` → runtime `emitExtractExistentialWitnessTable`. Swapping witness class to fix type identity silently changes codegen ([Slang: subtype-witness Val-class is load-bearing at lowering (not just type identity)](../learnings/1780530677473-slang-subtype-witness-val-class-is-load-bearing-at.md)).

`ISession::createTypeConformanceComponentType` unconditionally allocates a new conformance entry rather than looking up the existing source-declared one. `override = 0` always breaks `is`/`as` because Slang's auto-ID assignment never picks 0, guaranteeing a duplicate entry ([slang type-conformance override=0 always duplicates the (T,I) entry](../learnings/1780414379429-slang-type-conformance-override-0-always-duplicate.md)).

Associated constants fold only via `DeclaredSubtypeWitness`; other witness subclasses are not processed by `getUnspecializedLookupRec`. The declaration/signature-type access path can fail to fold not because the witness is the wrong class, but because the conformance witness table is not yet built at fold time — the fix is `ensureDecl(sub, ReadyForConformances)` before re-folding, not `resolve()`/normalize ([slang associated-constant fold gated on DeclaredSubtypeWitness; eager tryConstantFoldDeclRef skips normalize](../learnings/1782215625162-slang-associated-constant-fold-gated-on-declaredsu.md), [Slang: a fold over a concrete DeclaredSubtypeWitness can return symbolic purely because the conformance witness table isn't built yet — fix with ensureDecl(ReadyForConformances), not resolve()/normalize](../learnings/1782224910624-slang-a-fold-over-a-concrete-declaredsubtypewitnes.md)).

Link-time `export`/`extern` wrapper associated-type resolution (the #9580 / #12131 / #12134 cluster) has **two distinct requirement-resolution entry points that behave differently on transitivity** (`TransitiveSubtypeWitness`) — load-bearing for any base-interface / transitive fix ([slang link-time assoc-type resolution: two resolvers differ on TransitiveSubtypeWitness (#12134)](../learnings/1784248435373-slang-link-time-assoc-type-resolution-two-resolver.md)).

The witness-Val-class-drives-lowering hazard has a pack-expansion instance: a pack-query `__first(args)`/`__last(args)` over `expand each T args`, when its result is cast to a concrete type via a `where`-clause witness (e.g. `where T == int`), SIGSEGVs slangc (#12494) — Debug asserts `!"unhandled"` in `emitCastToConcreteSuperTypeRec` (`slang-lower-to-ir.cpp:7252`), Release derefs the returned nullptr. It is a two-layer gap: `__first`/`__last` produce a `FirstSubtypeWitness`/`LastSubtypeWitness` (`slang-check-inheritance.cpp:2197-2205`) that two lowering consumers don't recognize — (1) `isTypeEqualityWitness` (`slang-ast-val.h:1352`) recurses through Each/TypePack/Expand/TrimFirst/TrimLast but omits First/Last, so the `where T==int` no-op cast isn't seen as type-equality (checked at `:7288`); (2) it then falls into `emitCastToConcreteSuperTypeRec` (`:7214`) which handles only Declared/Transitive witnesses → unhandled else → nullptr. Both sub-cases need fixing at BOTH layers: the type-equality flavor by adding First/Last to `isTypeEqualityWitness` — the blessed, precedented mechanism (PR #8736 added the `ExpandSubtypeWitness` case there and that also fixed the identical crash in #6856, whose closing PR was test-only; the no-op reasoning holds because `__first` already lowers to `kIROp_ExtractFirstFromPack`, selecting element 0 BEFORE the cast, so the cast is representation-only) — plus a SIBLING genuine field-extraction upcast (`__first` result upcast to a real struct base via a Declared inheritance witness) that needs handling IN `emitCastToConcreteSuperTypeRec`. This is the same principle as `DeclaredSubtypeWitness` vs `ExtractExistentialSubtypeWitness` above: the witness Val-class is load-bearing at lowering, and a new SubtypeWitness subclass silently unhandled by a lowering consumer crashes. Method note: on the Release SIGSEGV, `addr2line` gave an inlined-return-address MIS-HIT — discard it in favor of the stale-but-source-matching Debug assert line, which is authoritative for "which function" in inlined C++ ([Pack-query __first/__last cast crash: two-layer witness gap (First/Last SubtypeWitness)](../learnings/1786529197320-pack-query-first-last-cast-crash-two-layer-witness.md)).

**Reference map (as of master `928f4010f`, surfaced during the #12995 promise-witness feasibility work).** Conformance-witness search/creation is a *single point*: `SemanticsVisitor::isSubtype(Type*, Type*, IsSubTypeOptions)` (`slang-check-conformance.cpp:51`) returns a `SubtypeWitness*` or **null, and never diagnoses**; the builder `checkAndConstructSubtypeWitness` (`:220`) scans `getInheritanceInfo(subType).facets` and constructs via `getDeclaredSubtypeWitness`/`getOrCreate<DynamicSubtypeWitness>`. `IsSubTypeOptions` is `None`/`NoCaching` only — **cache control, NOT strictness** (`NoCaching` exists to avoid caching *provisional* results that create circular deps). The strict-validation-vs-query distinction **exists but at the caller layer, not threaded into the witness core**: the discriminator is `OverloadResolveContext::Mode {JustTrying, ForReal}` plus the diagnose-on-null-vs-return-bool convention (`TryCheckOverloadCandidateConstraints`, `slang-check-overload.cpp:1157`, applies the strict `TypeArgumentDoesNotConformToInterface` gate AFTER a null witness at `:1300`; the solver path at `slang-check-constraint.cpp:2939` demands `isSubtype` with no diagnostic) — so any design needing per-call-site strictness at the witness core must **plumb the mode down** a widely-called signature. The global **Val epoch** (`Session::m_epochId`, `ASTBuilder::getEpoch()/incrementEpoch()`) has only THREE `incrementEpoch()` callers — ASTBuilder dtor, after folding a defaulted-assoc-type witness, and after conformance checking creates new witness tables — with semantics "a witness table we didn't have now exists ⇒ stale cached `Val::resolve()` results"; a separate, finer per-decl epoch (`bumpDeclExtensionEpoch`) governs inheritance-info caching. Deferred/lazy-checking precedent: `getInheritanceInfo` marks `isComputing` and rolls the cache entry back on a partial (`frameSkipped`) result so a later root query recomputes. Subtype witnesses are hash-consed Vals **consumed at IR lowering**, not just type identity — a provisional/placeholder witness must `resolve()` to a concrete form and never reach lowering unresolved ([conformance-witness core, strict-vs-query mode, and Val-epoch map @ master 928f4010f](../learnings/1789068321840-slang-conformance-witness-core-strict-vs-query-mod.md)).

**Inheritance constraint-matching resolves equality constraints eagerly on BOTH endpoints — a re-entrancy surface a directed-constraint fix doesn't cover.** slang#12690 fixes a false E38029 from eagerly `ensureDecl`-ing an unrelated sibling constraint whose dependent super-type re-enters the in-progress `_calcInheritanceInfo` query (the fix moves the subject-relevance filter before `ensureDecl`, extracting `resolveConstraintTypesForInheritanceMatch` → {Resolved,Deferred,Invalid}). It is asymmetric: a **directed** `S : B` resolves only the subject `S` for the relevance test and defers the super-type `B`, so an unrelated dependent `B` never re-enters (the tested #12659 path); an **equality** `L == R` resolves BOTH endpoints eagerly (it must, since either can match `selfType`) — a multi-level `MemberExpr` endpoint returns `Deferred` (safe) but a generic-app-leaf endpoint (`__constraint Alias == G<Context>`) is force-resolved via `TranslateTypeNodeForced`, which can re-enter the in-progress query, the same failure mode the directed branch now avoids. Plausibly pre-existing and the triggering shape is unusual, so possibly unreachable — but it is a distinct surface. When reviewing inheritance/constraint-matching changes that special-case directed vs equality, ask "does the equality branch resolve endpoints eagerly on a path the directed branch defers?" — and two review sources disagreeing on a specific line (production ✅ Clean vs Devin 🔴 at :1163) is itself the signal to dig, not average away. (Good pattern from the same PR: prefer a graceful `NoBase` return over `SLANG_RELEASE_ASSERT(selfIsSub||selfIsSup)` when error recovery can replace endpoints with `ErrorType`) ([inheritance constraint-matching: equality constraints resolve both endpoints eagerly](../learnings/1789071218256-approver-challenger-miss-inheritance-constraint-ma.md)).

## Extensions and Namespace Scoping

Cross-fragment namespace lookup inside `extension` headers fails with E30015 (unqualified name) because the extension-first pass in `checkModule` resolves headers before `ensureAllDeclsRec` wires namespace sibling scopes. The correct fix is a `discoverNamespaceDecls` pre-pass that drives ALL module-level `NamespaceDecl`s to `ScopesWired` before the extension loop — not enclosing-only (too narrow, misses #11532) and not the full-module ensureAllDeclsRec (regresses core library texture extensions) ([slang #11531 root cause: extension headers resolve names before namespace fragments reach ScopesWired](../learnings/1781071107223-slang-11531-root-cause-extension-headers-resolve-n.md), [slang #11531 Approach B core-module safety rests on as&lt;NamespaceDecl&gt; filter, not 'no namespaced core extensions](../learnings/1781086844343-slang-11531-approach-b-core-module-safety-rests-on.md), [slang core module HAS a namespace-enclosed extension (namespace linalg) — verify before claiming user-namespace-only](../learnings/1781088865270-slang-core-module-has-a-namespace-enclosed-extensi.md), [Slang #11531/#11532 fix: wire ALL module-level NamespaceDecls before the extension-first pass (not enclosing-only, not whole-module) — landed via maintainer PR #11577](../learnings/1781244954865-slang-11531-11532-fix-wire-all-module-level-namesp.md)).

The core module DOES contain namespace-enclosed extensions (`namespace linalg { extension ... }` in `hlsl.meta.slang`). Claims that the core module has no namespace-enclosed extensions are factually false and have shipped in PR descriptions ([slang core module HAS a namespace-enclosed extension (namespace linalg) — verify before claiming user-namespace-only](../learnings/1781088865270-slang-core-module-has-a-namespace-enclosed-extensi.md)).

Extension method name hints drop the type qualifier because `getNameForNameHint` has no `ExtensionDecl` case, causing unqualified SPIR-V debug names. The fix redirects to the extension's target type via `as<DeclRefType>(extensionDecl->targetType)->getDeclRef().getDecl()`. All legal extension targets (builtins, vectors, typedefs, generic structs) are nominal `DeclRefType<ContainerDecl>` — the unqualified fallback is unreachable by construction since the checker rejects non-nominal targets ([Slang extension-method name hints drop the Type. qualifier (getNameForNameHint)](../learnings/1781199860108-slang-extension-method-name-hints-drop-the-type-qu.md), [Slang extension name-hint qualification has no reachable unqualified fallback (extension targets are always nominal)](../learnings/1781269392733-slang-extension-name-hint-qualification-has-no-rea.md)).

When a struct and an extension both declare the same member name, two independent policies govern resolution: direct member access prefers the non-extension decl (base silently wins via `CompareLookupResultItems`); interface dispatch front-loads the extension's member as the witness. A nested-type static member inside an extension hard-errors on ambiguity because `getParentDeclRef` checks only the immediate parent ([slang extension same-name member resolution — dual policy + immediate-parent tie-break gap (#9660)](../learnings/1782215352976-slang-extension-same-name-member-resolution-dual-p.md), [slang#9660 extension shadowing — design-gated; override keyword already exists](../learnings/1782216036396-slang-9660-extension-shadowing-design-gated-overri.md), [slang #9660: a 'just assert it' clarity suggestion can introduce an abort regression (InterfaceDecl is an AggTypeDecl)](../learnings/1782745012175-slang-9660-a-just-assert-it-clarity-suggestion-can.md)). This behavior is documented as undefined and design-gated ([slang#9660 extension shadowing — design-gated; override keyword already exists](../learnings/1782216036396-slang-9660-extension-shadowing-design-gated-overri.md)).

A "just assert it" clarity suggestion for an `AggTypeDecl` guard is unsafe because `InterfaceDecl : AggTypeDecl` — interface extensions pass the guard but are absent from `getCandidateExtensions` (registered before they are diagnosed-and-returned), so `indexOf` returns -1 and the assert aborts ([slang #9660: a 'just assert it' clarity suggestion can introduce an abort regression (InterfaceDecl is an AggTypeDecl)](../learnings/1782745012175-slang-9660-a-just-assert-it-clarity-suggestion-can.md)).
