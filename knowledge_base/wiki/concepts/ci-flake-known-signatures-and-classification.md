# CI Flake Triage — Classification and Known Signatures

Deciding whether a red Slang CI job is a flake or a legitimate author-owned failure, and the catalogue of recurring signatures with their per-signature disposition. The fleet these run on is [runner pools and infrastructure](ci-flake-runner-pools-and-infrastructure.md); *when a rerun helps at all* is [rerun decision rules](ci-flake-rerun-decision-rules.md).

## TL;DR

- **The rollup never carries the reason.** Read each check-run's `conclusion`, then each failure's log (`actions/jobs/<job_id>/logs`; `output.summary` is often `null`). The skip pattern alone cannot tell you WHY a check went red.
- **A CPU-job failure pins legitimacy**: `test-linux-release-gcc-x86_64-cpu / test-slang` never touches the GPU fleet, so the same test failing there *and* on GPU/macOS/Windows is a deterministic regression.
- **Deterministic build/link errors are never rerunnable**: grep `undefined reference`, `undefined symbol`, `typeinfo`, `error C####`, `LNK####`, `linker command failed`, `ninja: build stopped`, `FAILED:`, and never classify off the first "error" line (a benign `ld: DWARF error ... FORM value: 0x23` can precede the real cause).
- **A stale-base break (unrelated to the diff; current main builds that job clean) needs a new head, not a rerun**: a re-run reuses the original merge sha. Rebase/merge main. Measure the base against the fix-introducing commit, not "behind master"; read the tested base from the log's `+<sha>:refs/remotes/pull/N/merge` parents.
- **Author-owned deterministic failures:** XPASS still listed in `expected-failure*.txt`; `check-cmdline-ref`; a merge-group `duplicate case value` collision with a green head; an aarch64-only `OpSource Slang` CHECK failure (relax to `{{Slang|Unknown}}`).
- **Auto-rerun-eligible** (sole failure on an otherwise-green PR): slang-rhi cmd-query timing; Falcor single image-comparison diff; "Common Test Setup" pre-test (head checks); `texture-shared-cuda.vulkan` numeric; macOS-release `metal4.0` per-runner; macOS-debug `debug-do-while-locals.slang` SPIRV-Tools assert.
- **Do-NOT-rerun / escalate:** Falcor "Unknown VCS root" (systemic infra); cooperative-vector hlsl-codegen DXC mismatch; `.slang-module` gen with `E99997`/SIGABRT (real assert); base-branch WASM `LanguageServerCore`/`WorkspaceVersion` link regression.
- **Bot-CI `ci_failed` with everything `skipped` and only `wait-for-human-priority`/`check-ci` failing is a priority-yield**: `retry-yielded-bot-ci.yml` self-heals it, narrowly (`--lookback-hours 16`, `--max-attempts 30`, skips superseded dispatches, `--max-reruns 1` oldest first). Do NOT rerun.
- **A JSON-RPC (`waitForResult()`/`hasMessage()`) failure is a test-server child crash**: dedup by run id; separate harness flake from the PR's own crashing test and GPU device-loss.
- **slang-rhi OMM `VUID-10904` on a submodule-bump PR is likely a Vulkan SDK 1.4.341.1 validation-layer false positive** (lavapipe SKIPs OMM in slang-rhi's CI). Fix CI-side (pin/suppress the VUID) or report upstream; not rerun-clearable.
- **Nightly Coverage reds:** a `merge-and-deploy` red can be slang-coverage-reports' 950 MB Pages budget (the bytes are in `reports/latest`, so pruning history does not help; file it there); a `coverage-windows` red on a Chocolatey 503 is infra unless it fails two nights running.
- **The nightly `agentic-tests` job is advisory doc-bundle drift**: the non-blocking `docs/generated/tests` corpus drifts with breaking-change PRs; regenerate periodically, no issue per drift.

## Classifying Failures: Flake vs. Legitimate

**Test duration is a fast signal:** a Windows GPU test job finishing in under ~60 s ran no tests (disk-space preflight or artifact download; see [runner pools and infrastructure](ci-flake-runner-pools-and-infrastructure.md) and [rerun decision rules](ci-flake-rerun-decision-rules.md)).

**A CPU-job failure pins legitimacy:** the CPU runner never touches the GPU fleet, so the same test failing identically there and on GPU/macOS/Windows is a deterministic regression for the author, not a rerun ([CPU tell](../learnings/1782296288354-ci-babysitter-cpu-job-failure-is-the-tell-for-real.md)).

**A pure-Python `extras/` change cannot break C++ build/GPU-test jobs.** If those fail while `Check Python Scripts (Core Python Only)` and `Check Formatting` pass, check `--log-failed`: HTTP 504 downloads (sccache/OptiX), OOM, timeouts and cancellations are infra (do nothing); real compile/link errors or unit-test asserts are master breakage via a `BEHIND` branch (rebase once master is green, never mid-run: that cancels the matrix and can dismiss a fresh approval). A `nv-slang-bot[bot]` `workflow_dispatch` on a DRAFT bypasses the draft-skip but priority-yields at once (matrix skipped, parked on `falcor-build-approval-gate`), so don't re-dispatch to "force" a matrix; a human marking the PR ready gives the reliable run ([pure-Python PR](../learnings/1790019959011-slang-bot-ci-priority-yield-classifying-ci-failure.md)).

**Deterministic build/link errors are never rerunnable.** Grep the failed log for `undefined symbol`, `error C####`, `LNK####`, `FAILED:` (ninja) before calling a build failure flaky ([wasm linker errors](../learnings/1780920419175-slang-ci-wasm-build-failures-are-usually-real-link.md)). **Don't classify off the first "error" line:** on PR #12136 a classify-only subagent stopped at `/usr/bin/ld: DWARF error: invalid or unhandled FORM value: 0x23` and recommended a futile rerun; two lines later were 4× `undefined reference to typeinfo for Slang::Session` from the PR's own new `-fno-rtti` file → `linker command failed` → `ninja: build stopped`. Grep `undefined reference`/`typeinfo`/`linker command failed`/`ninja: build stopped` and read around them (the `linker command failed` line names the unit, the lines above say why), and verify a subagent's rerun candidate against the raw log before firing ([DWARF note](../learnings/1784347920752-a-benign-dwarf-ld-note-can-mask-the-real-undefined.md)).

**A stale-base failure needs a new head, not a rerun.** A build failure clearly unrelated to the diff (e.g. C++ linker errors on a pure CI-YAML PR) while current main builds that job clean is against a stale base; a recent green run of the same job on another PR rules out an active base break ([stale base](../learnings/1780985285213-ci-babysitter-stale-base-build-link-failures-are-r.md)). That 2026-06 atom held that `gh run rerun --failed` recomputes `refs/pull/N/merge` against current main; the 2026-11 receipt supersedes it: a re-run (`run_attempt` 2+, including a maintainer approving an `action_required` fork run) reuses the original run's merge sha. slangpy#1234's run 40987499432, created 10-30 and re-run 11-04, still checked out `ae2d31b3` (head + main `10311ca8` from 10-29), leaving four days of main untested. To read the tested base, grep the job log for `+<sha>:refs/remotes/pull/N/merge`, take `commits/<sha> --jq '.parents'`, and check `compare/<base>...main` before calling a PR "CI-verified against main". The `pull_request_review`-triggered bot workflows (assistant/bridge/maintenance) that show `action_required` after approval are not merge checks; don't count them as pending CI ([old merge ref](../learnings/1793890233966-fork-pr-ci-re-run-tests-the-old-merge-ref-not-curr.md)).

**Measure base distance to the fix-introducing commit, not the tip, and re-run the cheap git probe before acting on a memory conclusion.** #12783, #13078 and #12992 shared `undefined identifier 'MatrixLayoutMode'` → E30624 → E30855. A verdict calling #13078 a real regression because `gh api compare` reported its base `ahead_by:24` of #12986 (which added the enum) was **retracted**: `git merge-base --is-ancestor <pr-base> <fix-commit>` returned 1 and `git rev-list --left-right --count <pr-base>...<fix>` showed `17 3`, so all three were base-skewed needs-rebase (likely swapped compare arguments). When a memory conclusion feeds an action, re-run the probe yourself; detailed prose with run ids is no proxy for correctness. A **single, explicitly authorized one-off rerun to classify flake vs deterministic** for a genuine anomaly doesn't violate "only rerun infra" (get sign-off; it spends CI), and touching a PR can surface a live `@nv-slang-bot` mention in `issues/<n>/comments` you weren't webhook-wired for ([retraction](../learnings/1789460715976-retraction-pr-13078-was-not-ahead-of-12986-it-was-.md)).

**Merge-group collisions are legitimate, not flakes.** A merge-group build error (e.g. `duplicate case value`) with green head checks means two queued PRs introduced the same enum value: do NOT requeue; the author rebases and renumbers ([collision](../learnings/1782533107353-merge-group-build-break-with-green-head-merge-time.md)).

**XPASS (unexpected pass) is author-owned.** A fixed test still listed in an `expected-failure*.txt` reports XPASS as a failure on every platform; don't rerun, the author removes it ([XPASS](../learnings/1782360530038-xpass-is-a-deterministic-author-owned-ci-failure-n.md)). The lists differ per workflow: "Test Slang via glsl" in `ci-slang-test.yml` (Windows GPU) reads only `tests/expected-failure-via-glsl.txt`, while `ci-slang-test-container.yml` (Linux T4) also reads expected-failure-github/linux/linux-gpu, so a test failing in both the direct-SPIR-V and via-GLSL passes needs its key in both `expected-failure-github.txt` and `expected-failure-via-glsl.txt` ([via-GLSL lists](../learnings/1791247356003-gh-api-job-logs-silently-empty-without-allow-escap.md)).

**check-cmdline-ref failures are always deterministic** and almost always the PR's own (`slang-options.cpp` changed without regenerating docs, or a wrong doc edit), not master-wide staleness ([cmdline-ref](../learnings/1782324937326-attributing-check-cmdline-ref-ci-failures-not-mast.md)).

**An aarch64-ONLY test-slang CHECK failure** (x86_64 green) is likely an env-dependent SPIR-V disassembly token: aarch64 `test-slang` jobs export `SLANG_USE_SPV_SOURCE_LANGUAGE_UNKNOWN=1` (a swiftshader workaround), so `OpSource` disassembles as `OpSource Unknown 1 …` there vs `OpSource Slang 1 …` on x86_64. Author-owned, not rerun-clearable; the fix is a test-only relax to `OpSource {{Slang|Unknown}} 1 …`, not a golden-shift (the emit is correct) ([aarch64 token](../learnings/1784830954472-aarch64-only-test-slang-check-fails-env-token-not-.md)).

**The nightly `agentic-tests` job is advisory doc-bundle drift.** "Nightly Slang Test"'s sole job runs `slang-test -test-dir docs/generated/tests`, an LLM-generated doc-anchored corpus (not `tests/`) that never blocks PRs and drifts whenever a breaking-change PR lands without regenerating its golden snapshots. Pull `--log-failed` for the `N failing tests:` block, diff each `// CHECK:` line against its "possible intended match here" line (usually one token, `0 : Int` vs `0 : Enum(Int)`), and map each to a breaking-change PR via `compare/<last-green-sha>...<red-sha>`. If every failure maps to a disclosed PR and is snapshot-shaped (no crash/assert), it is bundle drift: regenerate periodically, no tracking issue per instance (precedent #12351) ([agentic-tests](../learnings/1789142798536-slang-nightly-agentic-tests-failures-are-advisory-.md)).

## Known Flake Signatures

**slang-rhi cmd-query timing flake** (`test-cmd-query.cpp:183: CHECK(durationGPU < durationCPU) is NOT correct!`, macOS aarch64): both durations can round equal (`7e-06 < 7e-06`), failing strict `<`. Auto-rerun eligible as the sole failure on an otherwise-green PR ([WASM + timing signatures](../learnings/1780891496263-slang-ci-wasm-link-regression-slang-rhi-timing-fla.md), [mac-aarch64 timing assert](../learnings/1781679288468-slang-11641-mac-aarch64-rhi-flake-cmd-query-timing.md)). The fix (slang-rhi#775, `<=` + tolerance) helps only once slang's pin includes it: `gh api repos/shader-slang/slang-rhi/compare/<fix-sha>...<pin-sha> --jq '{status,behind_by}'`. The sibling WASM signature (`build-linux-release-gcc-wasm / build` undefined symbols for `LanguageServerCore::*` / `WorkspaceVersion::*`) is a known base-branch break: do NOT rerun.

**Falcor image-test flake** (a single isolated image-comparison diff, e.g. `renderpasses/test_GBufferRTTexGrads_d3d12 : FAILED` on `build (windows, release, cl, x86_64)`): if the PR doesn't touch rendering, rerun with `gh run rerun <id> --failed` ([Falcor image](../learnings/1780762074181-slang-ci-falcor-image-test-flakes-vs-artifact-not-.md)).

**Falcor `Unknown VCS root`** (exit 1, "Error. Unknown VCS root") hitting many independent PRs in one window is systemic infra: do NOT rerun; record and surface to maintainers ([VCS root](../learnings/1781136348152-slang-ci-falcor-unit-test-unknown-vcs-root-is-syst.md)).

**"Common Test Setup" pre-test failure** on Windows GPU runners (SLANG-WINDOWS-*) dies before any test runs and evicts PRs from the merge queue. Auto-rerun eligible for head checks; use Merge Queue Recovery for merge-group evictions. The bot cannot requeue fork PRs ("You're not authorized to push to this branch") ([Common Test Setup](../learnings/1781626237709-slang-ci-common-test-setup-pre-test-flake-evicts-p.md)).

**Nightly Coverage `coverage-windows` red on a Chocolatey 503** (run 41375586658, 2026-11-02): only `coverage-windows / coverage` failed, ~8 s into installing `opencppcoverage` 0.9.9 via `choco` (HTTP 503 from `community.chocolatey.org/api/v2`, "choco install exited 1") before any Slang build. Read the first failing step with `gh run view <run> --job <id> --log-failed`; a feed 503 leaves nothing to bisect. The install step has no retry, so treat it as a flake unless it fails two nights in a row ([Chocolatey 503](../learnings/1793592113911-nightly-coverage-coverage-windows-red-on-chocolate.md)).

**Nightly Coverage `merge-and-deploy` red on the Pages size budget** (from 2026-11-05): `Verify coverage Pages publication` goes red when shader-slang/slang-coverage-reports fails `pages.yml` at `Stage published reports` (`tools/stage-pages.py`: `MAX_CONTENT_BYTES` = 950,000,000, tar bound `MAX_ARCHIVE_BYTES` = 1e9, warning at 800 MB; first trip 950.55 MB, filed as slang-coverage-reports#5). Not code, and it will not self-clear. 950.4 MB of the staged bytes are the 8 `reports/latest/{linux,macos,windows}/new/{full,slangc}` and `merged/{full,slangc}` views; history adds ~0.4 MB, so retention pruning (`cleanup-old-reports.sh`) shrinks the Git repo but not the Pages number. Growth is ~0.8 MB/day. Measure without a checkout by summing blob sizes per view from `gh api repos/shader-slang/slang-coverage-reports/git/trees/<reports/latest sha>?recursive=1`; per-night staged sizes are the `Pages content:` lines of `gh run view <id> --log` on pages.yml runs, and the served marker is https://shader-slang.org/slang-coverage-reports/reports/publication.json [Pages budget](../learnings/1793953073465-slang-coverage-reports-pages-budget-only-reports-l.md).

**JSON-RPC failure** (`waitForResult()`/`hasMessage()`): the test-server child died mid-test (stdio EOF), a crash symptom, not an RPC-infra bug; since PR #11753 fixed the `runUnitTestModule()` stale-pass bug, crashing unit tests record failure instead of silently passing ([JSON-RPC crash](../learnings/1782407732117-slang-ci-json-rpc-failure-on-a-unit-test-test-serv.md)). The surface conflates (a) a genuine harness flake (CPU concurrency on aarch64), (b) GPU device-loss/faulty ICD killing the worker, and (c) the PR's own consistently failing test; dedup by run id and exclude (b) and (c) from the harness-flake count ([dedup by run id](../learnings/1782598546890-flaky-ci-evidence-dedup-by-run-id-json-rpc-and-fal.md)).

**Bot-CI priority-yield** (`ci_failed`, every build/test job `skipped`, only `wait-for-human-priority` + `check-ci` failing): the bot CI yielded to higher-priority human CI and `retry-yielded-bot-ci.yml` self-heals it. Do NOT rerun; it re-enters the same gate ([priority-yield](../learnings/1781571803229-slang-bot-ci-ci-failed-is-often-a-priority-yield-s.md)).

⚠️ **The skip pattern cannot tell you why, and the self-heal is narrow** (both learned on a maintainer-facing report). Draft filtering explained a draft PR's 74 `skipped` check-runs, but its two `failure`s were the priority gate yielding; the skip pattern is identical under both explanations and both had `output.summary: null`, so only `gh api repos/<o>/<r>/actions/jobs/<job_id>/logs` gave the reason (`##[error]priority-gate-yielded: higher-priority CI is active; ci-retry-yielded-bot will rerun this bot CI when quiet`). And `ci-retry-yielded-bot` considers only runs within `--lookback-hours` (16), under `--max-attempts` (30, age-independent: `workflow_run: [completed]` triggers can burn attempts faster than hourly, hitting the cap before the 12 h `--max-yield-hours` escalation), skips runs superseded by a newer dispatch on the branch, and reruns `--max-reruns` (1) candidate per invocation, the **oldest** by `run_number`. The wrong mechanism leaves a maintainer waiting on nothing ([read job logs](../learnings/1785784732188-read-ci-conclusions-and-failing-job-logs-the-skip-.md)).

**Cooperative-vector HLSL codegen** (`tests/cooperative-vector/matrix-mul-hlsl-codegen.slang.1` and `training-hlsl-codegen.slang.1` failing deterministically on `test-windows-release-cl-x86_64-gpu` across 8+ unrelated PRs) is a DXC version mismatch on that runner: do NOT rerun; classify "blocked on fix PR" ([cooperative-vector](../learnings/1780157118768-slang-ci-cooperative-vector-tests-fail-on-windows-.md)).

**`.slang-module` gen failure with `E99997` / SIGABRT** on debug builds is a deterministic compiler assert, a real PR bug: do NOT rerun. A silent exit 1 with no diagnostic is a transient bootstrap crash, rerun-eligible ([E99997](../learnings/1781720061070-slang-ci-slang-module-gen-failure-with-e99997-asse.md)).

**`texture-shared-cuda.vulkan` numeric flake** on `test-windows-release-cl-x86_64-gpu-rhi / test-slang-rhi`: a CUDA↔Vulkan interop tolerance failure (`CHECK_GE(result[i], expectedResult[i] - 0.01f)`, `external/slang-rhi/tests/testing.h:228`) while ~965/966 rhi cases pass and the suite is green elsewhere. PR-agnostic (#11693, #11735, #11812): rerun `--failed` under the daily cap; the `check-ci` red is cascade. Systemic fix (maintainer): widen the tolerance or quarantine ([interop flake](../learnings/1782936358409-texture-shared-cuda-vulkan-is-a-recurring-slang-rh.md)).

**slang-rhi OMM `VUID-10904` on a submodule-bump PR is likely a validation-layer false positive.** When slang bumps `external/slang-rhi` onto an opacity-micromap commit (slang-rhi #853/#852), `test-linux-debug-gcc-x86_64-rhi / test-slang-rhi` can fail `opacity-micromap-build.vulkan` / `-trace.vulkan` with **VUID-vkCmdBuildAccelerationStructuresKHR-pInfos-10904** (`indexType` `NONE` requires `indexBuffer.deviceAddress == 0`). The converter complies: `AccelerationStructureBuildDescConverter::convert` (`src/vulkan/vk-acceleration-structure.cpp`) sets `indexType` and `indexBuffer` together in exclusive branches and `NONE` leaves the value-initialized 0, so the naive `ommData.indexBuffer = {};` "fix" is a byte-level no-op. slang-rhi's Linux CI runs on **lavapipe**, which lacks `VK_EXT_opacity_micromap`, so the tests SKIP; slang's runs on real OMM hardware with validation on (and master often pins a pre-OMM slang-rhi, so it surfaces only on a bump). Best hypothesis: a **Vulkan SDK 1.4.341.1** layer false positive on the new VUID-10904/10905 case; fix CI-side (pin/bump the layer or suppress the VUID) or report upstream. Method: when a VUID won't reproduce on your VVL, don't install an SDK that rebuilds a shared container; **capture the exact struct bytes handed to Vulkan on real hardware**, and never hand a maintainer a second guessed fix-site ([OMM VUID](../learnings/1789600998422-slang-rhi-omm-vuid-10904-ci-red-is-likely-a-vvl-1-.md)).

**macOS-release `test-slang` metal4.0 flake is per-runner infra.** `test-macos-release-clang-aarch64 / test-slang` fails with `'required_threads_per_threadgroup' attribute requires Metal language standard metal4.0 or higher` (often with `slang-unit-test-tool/replayStream*`) because some macos-release runners' Metal toolchain is too old. Confirm your tests passed on that runner, macos-**debug** passes, and the same head both passed and failed; then rerun (≤3×) ([metal4.0](../learnings/1783448021238-macos-release-test-slang-metal4-0-flake-is-infra-n.md)). If it is deterministic across runners, or an example step exits 255 with `gpu-printing` swallowing the error, it can be a real emit-vs-target capability bug (#11985): grep for the masked `metal ...: error:` line first.

**`gpu-printing` macOS example flake (#11999): verify the step, don't trust bot conflation.** On hosted macOS aarch64 the red step is often "Run Slang examples", where `gpu-printing` exits 255 with no output (silent `SLANG_FAIL`, likely an RHI null-return), while "Test Slang" in the same job is GREEN; the bot conflated it with a non-fatal metal4.0 gfx-unit-test message in the green step. Map the red to a step and example before accepting a cause, test determinism (pass and fail within an hour on static master = intermittent), and note "debug passes / release fails" is CI config (examples run only on `config==release && event==pull_request`) ([gpu-printing](../learnings/1783548983571-slang-11999-gpu-printing-macos-flake-verify-ci-sig.md)).

**`static-const-matrix-array.slang.3 syn (llvm)` RPC drop / SIGSEGV is env-specific and intermittent; harness retry is not a fix.** The synthesized LLVM-JIT variant crashes the test-server child (a JSON-RPC drop on GPU jobs, a SIGSEGV core dump on the CPU job), so there is nothing to reconnect to. In merge_group runs it drops on both the initial pass and the harness retry, a hard FAILED that evicts the queue, while head runs stay green ("clears on rerun" yet evicts). Root-causing needs a Windows-debug, server-count-8 repro, so label it neither `reproduced` nor `not reproduced` ([RPC drop](../learnings/1783340384337-static-const-matrix-array-3-syn-llvm-rpc-drop-harn.md)). #11951 Sig-B (GPU RPC drop) and #11955 (CPU SIGSEGV) converge on this test+variant and may be one bug in two process topologies; track them separately until a backtrace confirms, since CI uploads no symbolic core dump and the evidence places the crash *at* this test, not its fault frame ([#11951/#11955 converge](../learnings/1783527380806-11951-sig-b-and-11955-cpu-sigsegv-converge-on-stat.md)).

**`debug-do-while-locals.slang` on macOS-debug-aarch64 is a SPIRV-Tools assert flake.** It fails only on `test-macos-debug-clang-aarch64 / test-slang` with `Assertion failed: (unique_id_ != 0), function unique_id, file instruction.h, line 251` (SPIRV-Tools, via debug-info SPIR-V emission); slang-test's auto-retry doesn't always clear it. If it is the only failure and the PR doesn't touch debuginfo/SPIR-V emit, rerun `--failed` (≤3×); if it reproduces across reruns, report a pre-existing platform issue rather than block (PR #12504, run 34891043815) ([do-while flake](../learnings/1789420993765-known-flaky-ci-test-tests-debuginfo-debug-do-while.md)).
