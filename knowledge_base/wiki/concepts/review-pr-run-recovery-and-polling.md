# PR Review Run Recovery and In-Turn Polling

Operational rules for driving the three-reviewer Slang PR-review pipeline (A = correctness `compose-and-run.sh`, B = Devin, C = clarity `run-clarity.sh`): detecting true completion, recovering a stranded or truncated pass without a ~25-min re-run, polling in-turn, avoiding stale or cross-PR artifacts, patch-mode and stacked-PR traps, and off-repo adaptation. Sibling pages carry the approver challenger catalog and the branch-delivery/diff-reading disciplines.

## TL;DR
- **Anchor completion detection to true exit markers plus an artifact-size floor**, never generic tokens (`error:`, `API Error`, `---`): the runners `tee` the full stream-json, so those appear as benign diff content.
- **On a teardown-prone cluster, poll in-turn with bounded blocking Bash calls**, never a background `Monitor` or `run_in_background` waiter. The completion signal must be a tool result you are holding.
- **`pgrep -f '<reviewer cmd>'` matches your own polling shell** — confirm exit via the script's log epilogue; call `wait-run.sh` with `--tail 0 >/dev/null 2>&1` and branch on `rc`, since its timeout dumps ~136 KB of stream-JSON.
- **Recover before re-running.** Completed run-dir outputs survive teardown; a capped or truncated Reviewer A review lives in `stream.jsonl`; a dead Reviewer C's candidates survive in `stream.jsonl` Write inputs or its `wt-clarity-*/tmp/review-candidates/`. Re-run only the missing dimensions, in-turn, as direct `Agent()` calls.
- **A failing guard on a job that exited 0, or a tiny / 0-count `final-review.md`, warrants a stream check** before you report failure or a clean result.
- **Raising the dollar cap is the wrong lever on a fan-out pipeline** — report spend-at-death and which passes completed. Do not starve Reviewer A's inner cap (~24; 35–40 for large diffs).
- **Reviewer B: fresh unique out-dir per run, or verify `devin-flags.md` mtime**; a wrapper's exit 0 reflects a trailing `echo`, so check `devin-error.txt`. Devin times out on draft and stacked PRs: an expected skip with `reviewers_complete:false`.
- **The runner scripts take flags, not the skill verb** (`bash scripts/run-clarity.sh --mode pr --pr N …`).
- **A wrong-PR INTEGRITY-FAIL is usually a shared-`tmp/` race on the shared checkout** — trust the per-run `pr-diff.reference` hash, find the run dir by `PR NUMBER:` in `prompt.txt` (not mtime), run Reviewer A in an isolated `wt-<pr>-<tag>` worktree, and never read `FETCH_HEAD` while reviewers run.
- **Reuse completed outputs when the head-delta is non-code-only** — compare at content level (strip `index` lines); findings on removed files are moot.
- **Scope from `gh pr diff -R <repo>`**, never a stale-local `git diff main...head`; enumerate feedback across `reviews` + `reviewThreads` + issue `comments`.
- **Patch mode applies onto master, not the PR head, and drops untracked new files** (`git commit -am`): verify "no producer" / "no test" findings against the head before relaying. To review a patch built on a PR head, point the runner's `origin` at a shared bare clone whose `master` is that head. Deliver patches only as `git apply --check`-verified exact bytes.
- **Stacked PRs: a diverged base makes `gh pr diff` cumulative, and subagents verify against local master** — scope the verdict to the top delta and check where a "doesn't exist" claim was verified.
- **Off-repo PRs (e.g. slang-rhi): run Devin natively; the A/C runners hard-target the compiler repo**, so use general-domain Agents for A and C.

## Completion Detection: Exit Markers and In-Turn Polling

**Anchor filters to termination-only markers.** The runners `tee` the full `--output-format stream-json` to the log, so a filter on `error:` / `API Error` / `---` fires a false "REVIEWER FAIL" mid-flight. Use the wrapper's trailing `^Reviewer A … exited:` echo or the guard lines `^!!! REVIEW-GUARD FAIL` / `^!!! CLARITY-INCOMPLETE`, and require the artifact to clear a size floor (`clarity-review.md` > ~300 B; a 227 B "now let me write…" stub means it was interrupted mid-write). After a teardown `stopped` notification, check the exit line and artifact before assuming done or re-running; a re-dispatch auto-pins to the current head because the runners resolve it via `gh pr view` ([anchor Monitor filters to exit markers](../learnings/1784380841597-review-completion-monitor-anchor-filters-to-exit-m.md)).

**Poll in-turn, not through a background waiter.** A Monitor or `run_in_background` `until`-loop dies on container teardown and the verdict never reaches the parent; this stranded reviews 5× on one cluster (#12116 ×2, #12162, #12200-first, #12231-first), while the workflow's "end turn after dispatch" step assumed the waiter survives. What works (#12200, #12231): launch A/B/C detached (`nohup` / `setsid … &`; they run 20–40 min), record run dirs in a stable `run-dirs.env`, then stay in the turn with consecutive bounded blocking Bash loops (`while [ $(date +%s) -lt $end ]; do pgrep -f <reviewer>; sleep 25; done`, ~8–9 min, tool `timeout` ~560000 ms) that return as tool results. `pgrep -f 'compose-and-run.sh --mode pr --pr N'` matches the polling shell's own command line, so confirm exit by the log epilogue (`>>> final review:` for A, `>>> run-clarity.sh: done` for C, `devin-fetch: …md (N lines)` for B). Before re-driving a stranded review, re-confirm the PR head and each reviewer's reviewed-diff hash: teardown plus a fixer re-push can make it stale twice over ([in-turn polling beats background Monitor](../learnings/1784625017836-slang-pr-review-in-turn-polling-beats-background-m.md); [bounded blocking Bash calls, never an armed waiter](../learnings/1785143391944-in-turn-pr-review-polling-bounded-blocking-bash-ca.md)). The runner's own blocking waiter, `wait-run.sh`, has one output trap: on its timeout (exit 124) it prints the last lines of `run.log`, which are stream-JSON with large thinking signatures, and one such call returned about 136 KB into the context. Call it as `bash wait-run.sh <run_dir> --timeout 540 --tail 0 >/dev/null 2>&1; echo rc=$?` and read the review artifacts only after `rc=0` ([wait-run.sh: use --tail 0 and discard output](../learnings/1792932360994-wait-run-sh-use-tail-0-and-discard-output.md)).

## Recovering a Stranded or Truncated Pass

**Recover in layers before any ~25-min re-run.** (1) Salvage finished reviewers: Devin artifacts persist at `/workspace/agent/review-<pr>/devin/devin-flags.md`; a Clarity run dir may be GC'd after days, but a `clarity-review.md` already read into context can be reconstructed into a file. (2) Extract partial Reviewer A verdicts from the dead run's `stream.jsonl` — the 600 s inner background-wait ceiling often truncates aggregation after the subagents already reported. (3) Re-run only the missing dimensions as direct in-turn `Agent()` calls, which have no teardown window. Root-cause the infra failures: **REVIEW-GUARD FAIL (<500 B `final-review.md`)** means inner `claude --print` hit the 600 s ceiling, so re-run with `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0`; **INTEGRITY-FAIL "reviewed WRONG diff"** can be a stale `tmp/pr-diff.patch` the model never overwrote (its `gh pr diff >` was permission-denied), so `rm -f slang/tmp/pr-diff.patch` (concurrent-run races: see below). The shared `/workspace/agent/slang` usually sits on base master: fetch the head into a ref you own (`git fetch origin pull/<n>/head:refs/pr/<n>`) and read with `git show refs/pr/<n>:<path>`, never via `FETCH_HEAD`, which a sibling session can move (the branch-delivery page covers this mutable-ref trap) ([recover a stranded pass without a full re-run](../learnings/1784536666918-recovering-a-teardown-stranded-pr-review-pass-with.md)).

**Per-subagent extraction is verbatim.** Each of the six `.claude/agents/*` subagents writes its final text into `stream.jsonl` before the parent finishes: group assistant `content[].type=="text"` blocks by `subagent_type` and keep the last >200-char block per subagent (typically 4/6 survive; resolve the cut-off one from source). Run dirs are named `pr-<UTC-timestamp>Z/`, not by PR number — identify yours with `grep "PR NUMBER" <dir>/prompt.txt` (or the `pr-diff.reference` head), or a concurrent review of a different PR gets mis-attributed to yours ([recover torn-down Reviewer A findings](../learnings/1784828278697-slang-pr-review-recover-torn-down-reviewer-a-findi.md)).

**Budget squeeze and wrap-up turns hide a complete review.** Three shapes share one recovery. (a) A writes its full review, then hits `error_max_budget_usd` on the file-write turn: `final-review.md` is absent, the guard says "0 bytes / no substantive review", and the summarizer parses 0/0/0, yet the review is the last top-level assistant message in `stream.jsonl` ([0-byte guard lies at the budget cap](../learnings/1785186988820-slang-pr-review-reviewer-a-0-bytes-no-review-produ.md)). (b) Near the cap, A delivers the review as an earlier turn and Writes only a 1–2 KB meta-note ("the review delivered in my previous message stands…"), giving a false 🔴0/🟡0/🔵0 clean ([truncated meta-note](../learnings/1789244336644-slang-pr-review-runner-final-review-md-can-be-a-tr.md)). (c) The inner CLI ends on an ~8-line wrap-up turn, which `compose-and-run.sh` captures as `final-review.md` ([wrap-up-turn extraction](../learnings/1789733573227-slang-pr-review-stacked-pr-review-final-review-md-.md)). Recovery: take the largest substantive `type=="assistant"` text turn in `<run_dir>/stream.jsonl` (the one with `**Verdict**` / `reviewed:`), slice from `**Verdict**`, cross-check against the top-level `result`, overwrite `final-review.md`, and keep the stub as `final-review.meta-note.md` — not a ~$30 / 20-min re-run. The inner `--max-budget-usd` is separate from the outer session meter: give A a near-full cap (~24), 35–40 for large diffs. Confirm drift==0 by counting actual POST `tool_use` calls, not by grepping the model's quoted REVIEW.md protocol prose.

**Reviewer C (clarity) can exhaust its turn budget right before the canonical write.** A plain re-run fails the same way and GCs the worktree, and a bigger cap does not help (investigation depth is the cost): recover the raw candidates from the `stream.jsonl` Write-tool inputs (`tmp/review-candidates/pr-<N>-*clarity.md`) and set `reviewers_complete:false` ([C exhausts turn budget before canonical write](../learnings/1785339114704-clarity-reviewer-c-exhausts-turn-budget-before-can.md)). If the run died outright (pid gone, no exit status, no `clarity-review.md`), the per-pass files usually survive at `/workspace/agent/wt-clarity-pr-pr<N>-<head>-<hash>-<pid>/tmp/review-candidates/pr-<N>-{clarity,fine-grained-clarity}.md`; ship them verbatim, labelled PARTIAL (unconsolidated, unfiltered, every candidate `Status: Proposed`), with `reviewers_complete=false` instead of a 60–90 min re-run — #13681 R2 shipped this way ([recover a dead C run from its wt-clarity worktree](../learnings/1792132307982-recover-a-dead-reviewer-c-run-from-its-wt-clarity-.md)).

**Reuse completed outputs on resume when the head-delta is non-code-only.** Stranded-but-finished runs leave `final-review.md` / `clarity-review.md` / `devin-flags.md` intact. Compare what was reviewed with the current head at content level: a rebase or amend changes blob hashes and `compare` shows a misleading "ahead=1 behind=1", so extract file-blocks from A's `pr-diff.reference`, strip `index <hash>` lines, and diff against a normalized `gh pr diff`. An empty diff on code and test files means the review stands (#12200: reviewed `fcfcc00` vs shipping `e7dc2ba`, 9 files identical, only a scratch file removed → all three outputs reused, ~25 min saved). A finding about a removed file is moot on the shipping head — subtract it from the live count and say so. Run any needed re-review in-turn, never under a re-armed Monitor ([reuse outputs when head-delta is non-code-only](../learnings/1784882724986-reuse-completed-reviewer-outputs-when-head-delta-i.md)).

## Reviewer B (Devin) Hygiene

On a timeout `devin-fetch.sh` writes only `devin-error.txt` and leaves any earlier `devin-flags.md` / `devin-page.txt` untouched, so a reused out-dir can smuggle flags from a different PR into `combined-review.md` (reviewing #12186, the dir held Jul-2 flags about an unrelated glsl struct-initializer PR). Use `/workspace/agent/devin-out-<pr>-<ts>`, confirm the flags file's mtime is from this run, and mark B skipped if only `devin-error.txt` is fresh; a `run_in_background` wrapper's exit 0 is a trailing `echo`, not the script's status ([Devin out-dir reuse smuggles stale flags](../learnings/1784697016109-devin-out-dir-reuse-can-smuggle-stale-flags-from-a.md)). Devin reliably times out / exits 3 on draft or stacked PRs (the anonymous scrape does not converge): treat it as an expected best-effort skip, note it, set `reviewers_complete:false`, and let A+C carry the verdict ([stacked-PR review notes](../learnings/1789733573227-slang-pr-review-stacked-pr-review-final-review-md-.md)).

## Shared-Checkout Races: INTEGRITY-FAIL and `tmp/` Collisions

`compose-and-run.sh` stages `context.json`, `pr-diff.patch` and `pr-files.txt` into a fixed `$REPO_ROOT/tmp/` (default `/workspace/agent/slang`). Two concurrent runs — or another session's patch-mode review — on the same checkout clobber each other: the inner model reviews the wrong PR and the integrity net refuses to emit `final-review.md`, leaving `INTEGRITY-FAIL.txt` that lists the other PR's files ([shared tmp/ staging collision](../learnings/1785209892572-reviewer-a-wrong-pr-integrity-fail-shared-tmp-stag.md)). The guard can also false-alarm on a good run, because its post-run check reads that same shared `tmp/pr-diff.patch` ([INTEGRITY-FAIL false alarm, #13538](../learnings/1791530998165-reviewer-a-integrity-fail-can-be-a-false-alarm-fro.md)). The run-start `rm -f tmp/pr-diff.patch` guard does not stop a concurrent writer that re-creates the file mid-run (#13027 R2: the checkout was parked on an abandoned `patch-review-<ts>` branch with a stale #12766/#12608 patch) ([isolated worktree for Reviewer A](../learnings/1789222069725-slang-pr-review-runner-shared-checkout-workspace-a.md)).

Diagnose with per-run evidence, which is never shared: `sha256sum <run_dir>/pr-diff.reference` against `gh pr diff <N> -R <repo> | sha256sum`, the `final-review.md` footer `reviewed: <sha> · diff sha256`, the shared `tmp/pr-diff.patch` mtime against your run's start, and `tool-uses.jsonl` `gh pr diff|view` commands naming only your PR while `tmp/context.json` names the other. Cross-check Reviewer C's diff-hash marker — C isolates itself in `wt-clarity-*` and Devin scrapes the live page, so only A is exposed. Subagent inputs are not preserved (`summarize.py`: "Preserved subagent outputs: 0"), so you cannot prove a subagent avoided the clobbered file; do not reason around a tripped guard. Confirm no active run (`ps -eo pid,args | grep -E 'compose-and-run|run-clarity'`), `rm -f slang/tmp/{context.json,pr-diff.patch}`, re-run A once (preferably isolated, below), and set `reviewers_complete:true` only after a guard-clean run ([concurrent reviews race on tmp/](../learnings/1789165950252-slang-pr-review-runner-concurrent-reviews-of-diffe.md)):

```
git worktree add --detach /workspace/agent/wt-<pr>-<tag> origin/master
REPO_ROOT=/workspace/agent/wt-<pr>-<tag> bash …/compose-and-run.sh --mode pr --pr <N> --repo <owner/repo>
```

A base worktree suffices because `REVIEW.md` and `.claude/agents/*` are git-tracked and pr mode reviews the `gh pr diff` text; `RUN_DIR` still lands under the skill's `transcripts/`. Name it `wt-<pr>-<tag>` so the supervisor GC reaps it, remove only worktrees you created, and when dispatching several PRs at once give each its own `REPO_ROOT` from the start; the durable fix is per-run diff/context under `$RUN_DIR`. Current recipe and the 2026-09/10 recurrences: [Reviewer-A integrity & concurrency](review-process-f0909b0-reviewer-a-integrity-concurrency.md). The same race hits `FETCH_HEAD` (A and C each `git fetch` concurrently), so verify deltas against a diff you captured (`gh pr diff > /tmp/x.diff`) or an immutable SHA ([FETCH_HEAD race](../learnings/1789733573227-slang-pr-review-stacked-pr-review-final-review-md-.md)).

## Invocation, Auth Fallback, and Patch Mode

**Runner scripts parse flags only.** `slang-clarity-review-runner`'s `argument-hint` shows `run-clarity --mode pr …`, but `run-clarity.sh` exits 1 on the leading verb; invoke `bash scripts/run-clarity.sh --mode pr --pr <N> --repo <owner/repo> …`. `compose-and-run.sh` behaves the same ([run-clarity.sh takes flags](../learnings/1787167494708-slang-clarity-review-runner-run-clarity-sh-takes-m.md)).

**Dead gh auth on a public repo: shim gh and keep pr mode.** Put a read-only `gh` shim over local git first on `PATH` (`gh pr diff` → `git diff merge-base..head`, `gh pr view` → prebuilt JSON) and run production pr mode unchanged; Devin scrapes the public URL anonymously regardless ([gh-shim fallback](../learnings/1785339099440-gh-shim-fallback-for-dead-token-on-public-repo-pr-.md)). Patch mode is the wrong fallback: it aborts on stale untracked files, and its `git commit -am` stages only modified tracked files, so a brand-new `tests/*.slang` hunk is silently dropped and A reports a false 🟡 "no regression test ships with the patch". The tell: A's footer `diff sha256` differs from the patch file's, while isolated Reviewer C saw the test. Evaluate the untracked test yourself instead of relaying the gap; the skill fix is `git add -A && git commit` ([patch mode drops untracked new files](../learnings/1789333359114-patch-mode-pr-review-git-commit-am-drops-new-test-.md)).

**Patch mode applies onto master, not the PR head.** When a fix is split between a pushable head and a separately delivered patch (typical when the App token lacks the `workflows` scope, so `.github/workflows/*` changes go to a maintainer as a `git apply` patch), patch-mode review flags anything that depends on head changes as broken. On slang#13021, A reported a 🔴 "no install rule produces `install-metadata/third-party-notices/{cmark-COPYING,lz4-LICENSE,glslang-LICENSE.txt}`", but the `install(FILES … RENAME …)` rules were on the head (815525c225, CMakeLists 691–714). Before relaying such a 🔴, check whether the head produces the referenced artifacts (`gh api repos/O/R/contents/<file>?ref=<head>` or `gh pr diff`); if it does, reframe it as an apply-order dependency — the patch goes on top of the PR branch or lands with it, never onto bare master — and state that order in the maintainer instruction ([off-head patch: false "no producer"](../learnings/1789174390977-patch-mode-review-of-an-off-head-patch-flags-false.md)).

To review such a patch *with* the PR's code as context, make the runner's `origin/master` be the PR head. Both `compose-and-run.sh` and `run-clarity.sh` patch modes always run `git checkout -b tmp origin/master && git apply`, so a fixer patch built on someone's PR head either fails to apply or is reviewed without that code. The recipe used for slang#13387 (2026-10-24) gives each reviewer a clone whose `origin` is a shared bare repo with the PR head as `master`:

```bash
git -C slang update-ref refs/review/prN-head <sha>   # a bare clone skips commits reachable only from FETCH_HEAD
git clone --bare --shared slang runs/N-base.git
git -C runs/N-base.git fetch slang +refs/review/prN-head:refs/heads/master   # '+' or the non-fast-forward update is rejected quietly
git clone --shared runs/N-base.git wt-N-revA
git clone --shared runs/N-base.git wt-N-revC
```

Run A with `REPO_ROOT=wt-N-revA` and C with `REPO_ROOT=wt-N-revC`; their `git fetch --depth 50 origin master` then fetches the PR head, and `--mode patch --patch <git diff base..head>` applies cleanly. Before dispatching, check that the applied tree matches the branch head (`git diff HEAD <head> --stat` is empty) ([Reviewing a patch whose base is a PR head, not master](../learnings/1792835526086-reviewing-a-patch-whose-base-is-a-pr-head-not-mast.md)).

**Deliver patches as verified exact bytes.** The #13021 inline patch in the PR body was corrupt (hand-retyped hunk counts and trimmed `index` lines → `corrupt patch at line 54`) though the generated `.patch` file was valid, so the maintainer rebuilt the changes by hand. Generate patches from a real `git diff` / `format-patch`, run `git apply --check` against the exact target branch before inlining or handing off, paste byte-identical bytes, and prefer attaching the `.patch` as the single source of truth. A codex semantic-equivalence review that calls an inline block "matches" does not validate patch format. If permission-blocked deliveries recur, the structural fix is granting the App the `workflows` scope ([validate with git apply --check](../learnings/1789174030552-validate-bot-delivered-git-apply-patches-with-git-.md); [never inline a hand-retyped patch](../learnings/1789174287841-never-inline-a-hand-retyped-patch-in-a-pr-body-git.md)).

## Scoping the Diff and the Feedback

Enumerate PR feedback across the union of `reviews`, `reviewThreads` and issue-level `comments`: blocking feedback (szihs on #996) often lives in issue comments that per-node review filters drop ([enumerate all comment types](../learnings/1785353452935-pr-review-feedback-enumeration-must-query-all-comm.md)). Scope a diff from `gh pr diff <n> -R <repo>`, which diffs against the remote base, never from a local `git diff main...head` — a stale local `main` inflated a 1-file PR to 40 files. The `gh pr diff` sha256 is also the review's `diff_hash` ([gh pr diff, not local git diff](../learnings/1785357368357-slangpy-pr-review-use-gh-pr-diff-not-local-git-dif.md)).

**Stacked PRs.** For a PR based on another fix branch, `gh pr diff` already returns only the author's delta, so pr mode is right as-is. When the head has diverged from its unmerged base (the PR shows CONFLICTING/DIRTY), `gh pr diff` returns the cumulative whole-stack diff (#13176: "1 file, +12" per the fixer, 11 files/+332 from `gh pr diff`, because base `fix/issue-13168` predated deps #13171/#13173). Review the superset, but scope the verdict to findings on the top-commit delta versus ancestor code, and note that a rebase fixes it. Reviewer A's subagents verify against the local `origin/master` checkout, which misses whatever a stacked dependency introduced: 3 of 6 subagents on #13176 falsely claimed no `emitSPIRVFromIR` error-count gate existed, though it is at the head (`slang-emit-spirv.cpp:12220`). Before relaying a "the fix doesn't work / X doesn't exist" finding on a stacked PR, check whether it was verified against the PR head, and tell the fixer not to chase master-vs-head false alarms ([stacked PR: whole-stack diff + master-vs-head false alarms](../learnings/1789735770801-reviewing-a-stacked-slang-pr-in-pr-mode-expect-the.md)). When the delta is reviewed as a patch, the shared-bare-clone recipe above makes the runners' `origin/master` the base PR head, which removes this class of false alarm at the source. The two-round pattern held there: round 1 REQUEST_CHANGES on a reachable `%a=OpNop %a` self-reference that the validator's `default:break` skipped, the fixer applied the exact `content >= i` guard, round 2 APPROVE_WITH_NITS ([stacked-PR review notes](../learnings/1789733573227-slang-pr-review-stacked-pr-review-final-review-md-.md)).

**Additive nit rounds keep full rigor.** Even on an approved fix, a test's prose claim needs a `CHECK` / `CHECK-NOT` behind it, or the prose must be narrowed (an unbacked "no whole-handle copy" claim was must-fix; the fix was a scoped `CHECK-NOT: OpVariable ... Function` + `CHECK-NOT: OpCopyMemory` between two CHECKs). Re-run codex OUTPUT_REVIEW after comment edits — it catches false claims in comments you wrote yourself, which are the hardest to self-catch. When one mechanism covers N sibling types (`isNonCopyableOpaqueType`: RayQuery and HitObject), add a positive test per sibling ([additive nit rounds need CHECK-NOT backing](../learnings/1784884204062-additive-review-nit-rounds-still-need-check-not-ba.md)).

## Off-Repo PRs (slang-rhi)

On a repo that is not the compiler (e.g. `shader-slang/slang-rhi`), the Reviewer A and C runners hard-default `REPO_ROOT=/workspace/agent/slang` and `git checkout origin/master` (slang-rhi's default is `main`), `compose-and-run.sh` requires a `REVIEW.md` that slang-rhi lacks, and the compiler-domain `.claude/agents/*` / `slang-review-*` subagents produce mismatched noise. What worked (slang-rhi#802): fetch the PR head into a `wt-<pr>-review` worktree of the real slang-rhi checkout, run Devin natively (it reviews any public PR by URL), dispatch general-domain `Agent`s with repo-appropriate correctness and clarity lenses, personally verify load-bearing claims, and merge into `combined-review.md` with the usual 5-bullet + JSON block plus a header note on the adaptation ([slang-rhi: adapt the A/C runners](../learnings/1784929061497-slang-rhi-pr-review-a-c-runner-skills-hard-target-.md)).
