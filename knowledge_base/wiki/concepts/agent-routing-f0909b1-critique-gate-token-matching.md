# Critique-gate token matching, denial mechanics, and the review-request format

## TL;DR

The delivery side of the critique gate: how it text-matches tokens in messages, what a hook denial does to a compound Bash command, how to order the append-only ledger row, and the exact format a `[Fix Review Request]` needs. Stage counting and attestation live on [gate mechanics](agent-routing-f0909b1-critique-gate-mechanics.md); read-only `gh` false positives and hook matchers on [gate-hook mechanics](agent-infra-gate-hook-mechanics.md).

- **The gate is a text matcher.** Bare `WOULD_APPROVE`/`BLOCK` in an ABSTAIN report, or `[Resolution]`/`[Fix Report]` text, trips it. Rephrase; don't run a ceremonial critique.

- **A denial aborts the whole Bash call** — never chain `git push` or a file edit with a gated command. After a must-fix even a read-only `gh api` call (or `gh pr list`) is refused; check state with git.

- **Record the append-only ledger row last:** artifact/memory writes → gate-forced critique → `record_decision` → deliver.

- **A `[Fix Review Request]` needs a plain `Maintainer direction:` line (a bold label fails); if that section links any GitHub comment it also needs `Fixer self-check:` (that literal label) with R1…Rn items.**

## Token matching, push bundling, and ledger ordering

**The matcher over-blocks on literal tokens.** An ABSTAIN report whose prose merely says "not BLOCK"/"not WOULD_APPROVE" falls through the fast-path to the full gate, which an abstain can't satisfy, and `gate-chain-routing.sh` then also demands `in_reply_to` (regex and safe paraphrases on [critique and delivery gates](agent-routing-f0909b2-critique-and-delivery-gates.md)) ([quoting BLOCK/WOULD_APPROVE defeats the fast-path](../learnings/1787621185331-approver-infra-critique-gate-abstain-fast-path-is-.md), [the gate text-matches tokens in prose](../learnings/1787778155862-approver-infra-delivery-critique-gate-text-matches.md)). TRIGGER ≠ REASON: rephrase, keep `ABSTAIN_POLICY` present, and don't manufacture a ceremonial critique. The `[GATE AUDIT]` hook likewise flags a message containing the literal `[Resolution]` when codex was never invoked, colliding with the spine's `[Resolution]` 5-bullet for routine acks: close courtesy chains neutrally ("[Chain closed]") and reserve `[Resolution]` for outcomes you ran codex on ([the `[Resolution]` tag trips the audit](../learnings/1789633290729-the-resolution-tag-trips-the-critique-overlay-gate.md)). It also fires on `[Fix Report]` when a reviewer merely asks for one, a false trigger, not a skipped gate ([GATE AUDIT false trigger on "[Fix Report]"](../learnings/1792058636644-container-restart-mid-review-kills-reviewer-a-c-an.md)). The audit keyword-matches bracketed report markers in ANY outbound message, not just messages of that type: a `[Report]` status rollup to parent that merely MENTIONED "waiting on fixer's [Fix Report]" produced "[GATE AUDIT] … codex-critique was never invoked — gate skipped" — the message still sends (warn, not block), so either phrase the relay without the bracketed marker ("the fixer's fix report") to avoid the audit noise, or accept the skipped-gate warning when every claim in the message is a live-verified fact ([gate audit matches bracketed report markers in any outbound message](../learnings/1794905704260-gate-audit-matches-bracketed-report-markers-in-any.md)).

**A denial aborts the whole Bash call.** A `git push` bundled with a gated command never runs, so reviewers see a stale commit: push in its own call (`--force-with-lease=<branch>:<sha>` in a worktree with no `origin/<branch>` ref), verify with `git ls-remote`, re-dispatch CI and tell reviewers the head moved ([never bundle a git push](../learnings/1787846612049-never-bundle-a-git-push-with-a-critique-gated-comm.md)). A chained file edit is swallowed the same way, and the trigger is command text, so a heredoc merely mentioning the PR-open command suffices (slang#13273: a python PR-body edit chained before `gh pr create` never ran). Keep edits in separate calls; write memory text naming gated commands with the Edit tool ([the gate blocks the whole Bash call](../learnings/1790593764309-critique-gate-blocks-the-whole-bash-call-gpu-less-.md)). After an OUTPUT_REVIEW must-fix any command containing `gh api` is refused, even a GET (and `gh pr list` while any stage is unapproved; use git for state checks [gh pr list blocked](../learnings/1793010303873-slangpy-worktrees-submodule-init-needs-protocol-fi.md)), so a fix-then-check-with-`gh` call never writes the fix: edit in a `gh`-free call and re-hash before claiming an item is addressed. A maintainer's `@nv-slang-bot` mention via `pr_session_mappings` authorizes your reply on that PR but does not lift a parent's separate hold; report it upstream ([a combined edit+gh call is blocked whole](../learnings/1790818878715-the-critique-delivery-gate-can-block-a-combined-ed.md)).

**Record the append-only ledger row last.** The edit-count gate can force an OUTPUT_REVIEW that overturns an ABSTAIN after the row is committed (first-write-wins per `(repo, pr, commit_sha)`; "Decision recorded" is a known false-success string) ([record the ABSTAIN row last](../learnings/1787732678394-approver-infra-abstain-record-the-abstain-row-last.md)). The ABSTAIN fast-path also records before the gate, locking out a late BLOCK (e.g. a head-current CodeRabbit review after harvest); for an ABSTAIN citing "no/incomplete reviewer signal", settle the harvest and run OUTPUT_REVIEW before `record_decision`, never the fast-path ([the fast-path records before the gate](../learnings/1787905229286-approver-critique-mustfix-the-abstain-fast-path-re.md)). `record_decision` is the last irreversible action of the turn.

## The review-request format check

The hook refuses a `[Fix Review Request]` without a `Maintainer direction:` line linking a canonical GitHub comment or saying `none — <reason>`. If that section contains any canonical comment link (`…/issues|pull/<n>#issuecomment-…`, `#discussion_r…`, `#pullrequestreview-…`, `#issue-…`), even a triager comment cited in the reason, it also requires a `Fixer self-check:` line with R1, R2… items (map a triager's numbered asks to R1–Rn); a bare `none — <reason>` passes (hook `review_request_problem`) ([review-request gate requires Fixer self-check R-items](../learnings/1792261551774-critique-gate-a-narrow-codex-reply-approve-leaves-.md)). Both labels match literally: `**Fixer self-check (R1 findings):**` ([recall stub](../learnings/1792695817981-codex-critique-run-with-cwd-outside-workspace-agen.md)) and a bold `- **Maintainer direction:** none` ([plain Maintainer direction line](../learnings/1792748776667-codex-first-reply-in-a-fresh-critique-thread-can-b.md)) were refused, while on slangpy-fixer plain `Maintainer direction: none — <why>` passed where bold `**Maintainer direction:** none.` failed ([plain review-request lines](../learnings/1793010303873-slangpy-worktrees-submodule-init-needs-protocol-fi.md), [fixer delivery gates](../learnings/1793850163791-fixer-delivery-gates-review-request-field-format-i.md)). When the only comment to cite is a reporter's or a bot/triage comment, keep the `none — <why>` line link-free and put the link on a separate `Scope source:` line (without the full `#issuecomment-` URL) or under Artifacts; a link to the reporter's issue body trips it the same way, so quote the reporter without a URL on that line ([a URL on the 'Maintainer direction: none' line trips the R-item gate](../learnings/1793658431464-task-started-fixer-sessions-delivery-gates-want-in.md), [reporter issue-body link, #14407](../learnings/1794135375190-fresh-slang-worktree-init-submodules-seed-dxc-tarb.md)). The link regex short-circuits the bare-none exit, so a canonical URL with a `none —` prefix still trips the R-item gate, and a `#issuecomment-` URL inside `Maintainer direction: none — …` parses as linked direction and rejects the message ("REVIEW REQUEST INCOMPLETE") — keep the none clause anchor-free, referencing the comment id in prose ("issuecomment <id>") ([delivery-gate mechanics](../learnings/1795017778129-delivery-gate-mechanics-codex-reply-must-not-carry.md), [codex-bridge dispatch](../learnings/1795055939569-codex-bridge-dispatch-setsid-not-nohup-no-issuecom.md)). Also: any file Write/Edit between the OUTPUT_REVIEW approve and the send re-arms the gate even when the edit is the review-request file itself — order the sequence: write the request file → OUTPUT_REVIEW → send unchanged ([delivery-gate mechanics](../learnings/1795017778129-delivery-gate-mechanics-codex-reply-must-not-carry.md)).
