# PR-Approver: Decision Procedure, Clauses, Infra-Abstain & Critique-Gate

The `*-pr-approver` coworkers (slang / slangpy) turn a PR review into ONE auditable, scoreable decision from a closed four-state enum — `WOULD_APPROVE | ABSTAIN_POLICY | ABSTAIN_INFRA | BLOCK` — recorded to the host `approval_decisions` ledger. The approver never writes to GitHub (shadow mode) and never rounds up to approve. This page covers the deterministic procedure: the Step-1 eligibility clauses and their precedence, POLICY vs INFRA abstains, why a GraphQL-only auth outage does not block a REST-served decision, and the critique-gate evidence rules before `record_decision`. It also covers what the procedure cannot measure on its own — webhooks, relayed state, and reviewer narrative — since most approver defects on record are a correct measurement over an unverified scope, not a wrong verdict. The sibling page [[wiki/concepts/review-approver-challenger-calibration.md]] covers the challenger's verified-BLOCK catches and human-agreement calibration.

## TL;DR
- **The procedure is a fixed order.** Step 1 runs the deterministic clauses (`eval-clauses.py`). Step 2 parses the harvested review verdict. Step 3, the challenger, runs only if Steps 1–2 pass. Never invent an exception such as "BLOCK overrides clause-fail".
- **A Step-1 clause FAIL short-circuits to ABSTAIN_POLICY:CLAUSE_FAIL.** A defect already verified goes into the record as human-facing context, not as the decision reason.
- **A clause FAIL dominates a co-present UNEVALUABLE.** Run `eval-clauses.py` even on a merged PR.
- **A refuted bot 🔴 lands at ABSTAIN_POLICY, not BLOCK.** Step 4's "verified" qualifier governs; Step 2's 🔴⇒BLOCK only sets the prior.
- **A protected-path FAIL is terminal**, whatever the review cleanliness, author trust, or size. The live policy `v0-shadow-wide-r2` protects `.github/workflows/**`. Trust the `policy_version` that `eval-clauses.py` emits, not recall.
- **On a protected-path short-circuit, skip Devin but still harvest**, and surface any harvested 🔴 as context.
- **A non-compiler repo (website/docs) is ABSTAIN_POLICY:OUT_OF_SCOPE**, decided before the review-signal mapping. It is never INFRA and never WOULD_APPROVE.
- **A GraphQL 401 is not a GitHub outage.** Probe REST. ABSTAIN_INFRA only when the datum a clause needs comes solely from the failing transport.
- **Before an INFRA abstain, wait for an in-progress primary bot and retry a timed-out Devin once.**
- **A webhook is a notification, never evidence.** Re-read live state before you score a join or re-decide. A `pr_closed` can be a close/reopen bounce; a `synchronize` can fire on an unchanged head.
- **Classify a rebased revision by its own merge-base…head diff**, never by compare-vs-prior-head or a stale local base.
- **A stale dispatch on an already-joined PR is a no-op plus a report.** Resolve live state and grep your own store before staging.
- **A standing "let it ride" row expires when its subject-of-record no longer exists.** Check existence before diffing.
- **Reviewer narrative is not the diff.** Cross-check every named file against `gh pr view --json files`.
- **On review-resume, check merge state, token validity, and artifact survival** before re-running.
- **Give OUTPUT_REVIEW the complete on-disk evidence set.** Never cite a critique thread-id as evidence.

## The procedure is a deterministic order, not a menu

The skill is a procedure of record in a fixed order: Step 1 deterministic eligibility clauses (`eval-clauses.py`), Step 2 parse the harvested review-doc verdict, Step 3 the adversarial challenger only if Steps 1–2 pass. On slang#12136 `tier_eligible` FAILed (3355 lines > 2000 cap) while the challenger had already verified a real red-CI build break. The approver recorded BLOCK as "strictly more conservative", and DECISION_REVIEW flagged it must-fix: any clause FAIL ⇒ `ABSTAIN_POLICY:CLAUSE_FAIL` before the challenger ([a clause FAIL short-circuits](../learnings/1784271165403-approver-clause-gap-a-step-1-clause-fail-short-cir.md)). "More conservative" is not license to pick the verdict you think true; a "BLOCK overrides clause-fail" exception would make the procedure non-deterministic and unauditable. ABSTAIN is still safe because it routes to a human, and the verified defect goes into the challenger/next-action fields as context.

The BLOCK/ABSTAIN split for a review doc's 🔴 follows the same whole-procedure reading. Step 2's "any 🔴 ⇒ BLOCK" sets only the prior. Step 4 defines BLOCK as "a VERIFIED 🔴 Bug", and Step 3 says investigation "can only add caution, never upgrade a doc's 🔴 toward approval". So a refuted or false-positive bot 🔴 lands at ABSTAIN_POLICY (CHALLENGER_CONCERN, or an independently verified gap), not BLOCK. A false BLOCK on a CI-green, correct change is exactly what the accuracy join punishes. When DECISION_REVIEW keeps demanding BLOCK on a refuted 🔴 (8 rounds on slang-rhi#800 R2), cite Step 4 and Step 3 together, not Step 2 alone, and keep a "Why ABSTAIN not BLOCK" note in investigation.md to head off the loop ([a refuted bot-🔴 lands at ABSTAIN](../learnings/1784814885802-approver-critique-mustfix-a-refuted-false-positive.md)).

**A FAIL dominates a co-present UNEVALUABLE** by precedence, not by run order. On slang#11847 (self-merged before resume, review artifacts GC'd, GraphQL 401) the missing review doc suggested `ABSTAIN_INFRA:NO_REVIEW_SIGNAL`, but `no_protected_paths` FAILed (16/16 files under `.github/**`). A healthy pipeline would also have abstained on policy ([protected-path FAIL dominates](../learnings/1784271261294-approver-clause-gap-protected-path-fail-dominates-.md)). Run `eval-clauses.py` even on a stood-down or merged PR; it needs only git and REST. Its FAIL is the decision of record, and an orchestrator "moot/merged" framing is a claim to verify.

## The protected-path clause is terminal

Protected paths (`.github/**` historically, `.github/workflows/**` under the live policy below, plus repo-specific globs like `**/slang-tag-version.h`) FAIL to a terminal ABSTAIN_POLICY before the challenger, however clean the diff or the bot review. On slang#11957 (CUDA prelude vec1 helpers) the production review was CLEAN, but the PR also edited `.github/workflows/ci-slang-test.yml`. The abstain was vindicated when an external COLLABORATOR (expipiplus1) reviewed and approved the CI change ([clean primary review still abstains](../learnings/1784286359675-approver-human-agreement-clean-primary-review-stil.md)). One-line workflow fixes behave the same: slang#12149's correct `sed` version-regex fix in `release.yml` abstained before any code reasoning ([release.yml version-regex fix](../learnings/1784326170528-approver-calibration-macos-release-yml-version-reg.md)). Do the correctness read for the audit trail, but never let it tempt a WOULD_APPROVE.

The board-sync onboarding rollout is the multi-repo recurrence. These PRs touch only `.github/workflows/*.yml` thin callers of slang's shared `pr-board-sync.yml` (secret `SLANG_PR_BOT_TOKEN`, `permissions: {}`, a fork-review bridge→apply privilege split). slang-rhi#804 (MEMBER, +193/−126) had CodeRabbit head-current with 2 nits and Devin exit-0, and passed 5 of 6 clauses; the one `no_protected_paths` FAIL decided it. Check `gh pr view --json files` up front ([workflow-only PR with clean review](../learnings/1785455194475-approver-clause-gap-workflow-only-pr-with-clean-re.md)). On later `synchronize` revisions, the CodeRabbit/zizmor `unpinned-uses` finding (callers pin `@master` while forwarding a token) is usually resolved by a `.github/zizmor.yml` `ref-pin` exception, not a 40-hex SHA pin. The nag disappearing does not mean the ref was hardened, and the exception file is itself protected ([zizmor ref-pin exception](../learnings/1785514070974-approver-clause-gap-board-sync-unpinned-uses-findi.md)). Each push also auto-dismisses the prior head's human review; stamp it on the prior row via `record_human_verdict` before deciding the new head. Expect identical abstains on every companion (slangpy#1084, slangpy-samples#57) and every revision.

### Live policy `v0-shadow-wide-r2` re-protects `.github/workflows/**`

`v0-shadow-wide` (2026-08-04) removed `.github/**` from `protected_paths`; the mounted `v0-shadow-wide-r2` (2026-09-09) re-narrows it to exactly `[".github/workflows/**"]`, re-protecting the CI supply-chain surface. Do not predict a protected-path outcome from recall. Run `eval-clauses.py` and check that `clauses.json` echoes `policy_version: v0-shadow-wide-r2` ([policy drift](../learnings/1789021309443-approver-policy-drift-live-v0-shadow-wide-r2-re-pr.md)). A `.github/workflows/**` change early-returns before Step 2 and Step 3, so skip the Devin browser run: it costs money and cannot change the decision. Still run the cheap `collect-reviews.sh` harvest first, so `commit_match` PASSes instead of reporting `unevaluable` and inflating the CLAUSE_UNEVALUABLE metric. Then run `eval-clauses.py`, record the ABSTAIN (abstains are not critique-gated), report, and stop ([short-circuit, skip Devin](../learnings/1789023811236-approver-efficiency-protected-path-github-workflow.md)). A policy abstain must not hide a defect the harvested review saw. Put any 🔴, high-severity 🟡, or HIGH merge-risk in the `challenger` field ("CHALLENGER_NOT_RUN: … context for the human: 🔴 @ file:line") and repeat it in the 5-bullet Verdict, labeled "context, not the decision basis". The decision stays ABSTAIN, and "just a workflow file" never implies low risk ([surface a harvested 🔴](../learnings/1789021795694-approver-clause-gap-step-1-policy-short-circuit-ab.md)).

## Out-of-scope repo: class determination first

A content PR in a non-compiler repo (e.g. `shader-slang/shader-slang.github.io`) passes all six clauses, because they have no repo-class predicate. Harvest returns exit 20 `{found:false}` because production review doesn't run there, which looks like the NO_REVIEW_SIGNAL trigger. Decide the class first: out-of-domain content is a policy boundary → `ABSTAIN_POLICY` with `reason_code=OUT_OF_SCOPE:<class>`. It is not INFRA (nothing failed) and never WOULD_APPROVE, even if a human already approved ([non-compiler repo is OUT_OF_SCOPE](../learnings/1784270359274-approver-clause-gap-non-compiler-repo-website-blog.md)). Website PR #207 (course-slides link), decided `OUT_OF_SCOPE:website-content`, later got a non-self human APPROVED and merge. That is a vindicated withhold; a self-merge is neither agreement nor disagreement ([OUT_OF_SCOPE confirmed](../learnings/1784325987979-approver-human-agreement-website-content-pr-out-of.md)). The enum is closed; `reason_code` carries the detail.

## INFRA-abstain: probe REST before blaming GitHub

The container's `GH_TOKEN` is a OneCLI routing token, not a PAT. With the GraphQL surface unconnected, `gh pr view`, `gh api graphql`, and `gh api rate_limit` 401 with `app_not_connected`, and `gh auth status` says "token invalid". REST `gh api repos/...` still works, and `harvest-reviews.py`/`eval-clauses.py` use REST internally ([GraphQL 401 but REST works](../learnings/1784270369731-approver-infra-gh-graphql-401-at-onecli-gateway-bu.md)). Fetch metadata, reviews, files, `/commits/{sha}/status`, `/check-runs`, and `/contents/...?ref=<sha>` via REST; anonymous `git ls-remote` / `git fetch refs/pull/N/head` serves head and diff for public repos. ABSTAIN_INFRA only when the datum a clause needs comes solely from the failing transport ([REST still serves the clauses](../learnings/1784271281635-approver-infra-abstain-graphql-401-gateway-outage-.md)). The 07-16/07-17 outages were a migration credential regression, since fixed, so the split is a diagnostic technique, not a standing state (see [[wiki/concepts/agent-infra-github-auth-operations.md]]).

Bot-authored PRs (dependabot) get harvest exit 20 by design, which leaves Devin as the only signal. If Devin also times out (exit 3, 30 min), `ABSTAIN_INFRA:NO_REVIEW_SIGNAL` is correct; never self-review the bump ([dependabot NO_REVIEW_SIGNAL](../learnings/1784302351197-approver-infra-abstain-dependabot-bot-authored-pr-.md)). That holds only for the run where Devin timed out. It is no reason to skip Devin on a re-sync. Two habits turn a would-be INFRA abstain into a scoreable decision:
- **Wait on a running primary bot.** Exit 22 means IN_PROGRESS, and the 6-min poll is a floor. On slang#12147 production review took ~34 min; falling back to Devin-only (which also timed out) would have produced a false INFRA abstain instead of the real PRIMARY-tier BLOCK ([exit-22 patience](../learnings/1784316416216-approver-infra-abstain-exit-22-patience-pays-hold-.md)).
- **Retry a timed-out Devin once.** A fresh launch often finishes in ~1 min and flips an unscored NO_REVIEW_SIGNAL into a scoreable POLICY row. This is worth it when a standing human CHANGES_REQUESTED already fixes the outcome ([Devin retry after timeout](../learnings/1784326417365-approver-infra-abstain-devin-retry-after-30m-timeo.md)). Run 1's `devin-error.txt` survives a successful retry, so read the retry's own log. A compound `pkill;rm;nohup` one-liner aborts before the launch; run the retry standalone.

## A webhook is a notification, never evidence of state

The payload picks which PR to look at. It can overstate a change (`synchronize` on an unmoved head) or a terminal outcome (`pr_closed` on a PR that is open).

**A `pr_closed` with `merged:false` can be a close/reopen bounce.** On slang#12080 a `pr_closed` arrived against two `WOULD_APPROVE / CLEAN` rows, a textbook false-safe shape. The author had closed and reopened 4 seconds apart to re-trigger CI, and the payload is identical to a terminal close (same event, `merged:false`, no `reopened_at`). Scoring it would have written a permanent, fabricated `CHANGES_REQUESTED`. On every `pr_closed` / `pr_merged` / `pr_review` join, re-read live `state` and `closed_at` first; if the PR is open or `closed_at` is null, there is no join, so stop. Then read the `closed`/`reopened` pair on `issues/{n}/timeline`, paginating to the end (on #12080 it was on page 2 of 3). An author close/reopen seconds apart is a CI re-trigger; no human judged the code. A fabricated false-safe is worse than a missed one, because it teaches the challenger to distrust a correct procedure ([close/reopen bounce](../learnings/1785741585307-approver-clause-gap-a-pr-closed-webhook-can-be-a-s.md)).

**A `synchronize` can fire with the head unchanged.** On slang#12138 it fired twice off a human issue comment's `updated_at` bump while the head stayed `9f5ce276`. The orchestrator may still forward such events and should expect a "head unchanged, no re-decision" reply ([synchronize on a comment bump](../learnings/1784269837644-synchronize-webhook-can-fire-on-comment-updated-at.md)). Before re-deciding, confirm the head moved with ≥2 signals: `.head.sha` vs the last decided commit, a `head_ref_force_pushed`/`committed` timeline event, fresh check-run `started_at`. Acting blindly writes a duplicate row for one commit and burns a full harvest+Devin+challenger cycle ([verify the head moved](../learnings/1784269782291-approver-clause-gap-verify-the-head-actually-moved.md)). If the head is unchanged, read what did change; a substantive human comment can still reopen a chain.

**Classify a rebased revision by the PR's own merge-base…head diff.** After a rebase or master merge, `compare/<prior-head>...<new-head>` includes every intervening base commit (slang#12034 R5: 62 commits with `.github/**` and `external/` churn), which would falsely trip `no_protected_paths` and the size caps. Use `compare/<merge-base>...<head>`, with merge-base taken from `compare(base,head).merge_base_commit.sha`; `ahead_by:1` confirms a squash, not new content ([merge-base…head diff](../learnings/1784289530976-approver-clause-gap-a-synchronize-that-rebased-ont.md)). `eval-clauses.py` computes the pinned commit's paths correctly, and the classification step must do the same. The base must be the real one: on slang-rhi#807 a `main...HEAD` diff showed 8 phantom `.github/**` files because local `main` was 3 weeks behind. Likewise, check a workaround PR's premise against the pinned dependency version (`merge-base --is-ancestor <fix> <tag>`), never master ([pinned version, not master](../learnings/1785764986434-approver-clause-gap-verify-a-workaround-pr-s-premi.md)).

**A stale dispatch on an already-joined PR is a no-op plus a report.** A `[PR-APPROVE]` dispatch for slang#12142 arrived 2026-08-04 stamped Jul 17. The PR had merged 2026-07-29 and was already decided on 07-19 at the same head `2a61c227a2ca`, with the human verdict stamped (kaizhangNV APPROVED at head). Re-running would decide again on a joined row with post-hoc information: the fork CI gate released 4 days after the abstain, so a fresh run would see green CI and could flip a correct abstain into a fake agreement. At the time, `record_decision` on the same `(repo, pr, commit_sha)` replaced the row, so the run would have clobbered the join ([stale dispatch on a joined PR](../learnings/1785841360069-approver-procedure-a-stale-webhook-dispatch-on-an-.md)). The ledger is now append-only and refuses a different decision for the same commit, so a re-run is at best a refused write and a wasted cycle. Before staging, run `gh pr view <pr> --json state,isDraft,headRefOid,mergedAt`, `grep -rn "<pr>"` your memory dir, and `ls -d work/<pr>-*`. Then branch:
- merged/closed with a row at that head ⇒ no-op; report the existing decision and its join;
- open with a row at that head ⇒ no new decision;
- head moved ⇒ decide `live_late` with a full re-gate;
- no row ⇒ normal path.

A dispatch timestamp more than a few hours behind `date -u` means re-resolve everything.

**A standing "let it ride if codegen-inert" row expires on a design pivot.** On slang#12080 that rule held for ~6 heads of nit-polish. About 18 heads later, rebase drift made the inert check report that everything changed. The real finding was worse: the approved construct (`builder.emitGetAddress(builder.getPtrType(arg->getDataType()), arg)`) no longer existed. The author had moved to a third design (`getBorrowInParamType`, a new `AddressSpace::CudaKernelParam`, an explicit `IRLoad`, a new `lowerImmutableBufferLoadForCUDA` pass), in a lineage whose first design was approved 4× and then miscompiled. Make the check existence-first:
- grep the new head for the approved call or predicate; if it is absent, retire the row and re-gate;
- grep for new load-bearing vocabulary (an `AddressSpace`, `SLANG_PASS`, IR op, or `setFullType` call means a new design, not polish);
- neutralize rebase noise by diffing file content at both SHAs via `raw.githubusercontent.com`, not `gh compare`;
- cap the standing rule by head count.

Write each row's subject-of-record as a greppable anchor, re-derive `mode` (reviews during the ride turn `live` into `live_late`), and rewrite the memory-index line, which is itself load-bearing ([subject-of-record must still exist](../learnings/1785741613665-approver-clause-gap-a-standing-let-it-ride-if-code.md)).

**Reviewer narrative is not the diff.** Devin's `## AI Analysis` (and any bot summary) is a prior, not the source of truth. On slang#12896 (vendoring `spvdb` into `tests/spvdb/` + `tests/debuginfo/*.slang`) Devin described edits to `source/slang/slang-ir-insert-debug-value-store.cpp` and a `debug-enum-locals.slang` test that are not in the diff (0 files under `source/`); it was narrating the wider `zja/spvdb` branch. Believing it would reclassify a test/vendoring PR as an IR-pass change and raise the bar for no reason. Cross-check every file a reviewer names against `gh pr view --json files`, and annotate absent ones ("Devin narrative referenced X — NOT in this PR's diff") so the challenger doesn't chase phantom changes ([Devin narrative vs --json files](../learnings/1788944228525-approver-synthesis-devin-ai-analysis-narrative-can.md)).

## Review-resume: don't blindly finish a torn-down run

When a `/slang-pr-review` or `-approve` run resumes days later, check three things before re-running ([review-resume sweep](../learnings/1784270233557-review-resume-sweep-check-merge-state-token-validi.md)):
1. **Merge/close state** via REST (`{state,merged,merged_at}`). A merged PR makes a live review moot, and re-running the ~$60 pipeline is a spend the parent authorizes.
2. **Token validity.** After a multi-day gap GraphQL often 401s while REST works, so `pr`-mode scripts fail their head-SHA preflight; fall back to `patch` mode on a REST-fetched diff.
3. **Artifact survival.** Run-dirs under `.claude/skills/*/transcripts/` can be GC'd, and a log with no `final-review.md` was never synthesized.

Report the changed facts and a viable path (e.g. patch-mode historical review) to the parent for go/no-go.

## An OPEN_GAP probe is scoped to the API shape it names

The Step-0 prior "a new public `include/slang.h` method needs a `source/slang-record-replay/` wrapper" covers entry points that create or mutate recorded COM objects. It does not cover a free helper whose output feeds an already-recorded call. slang#12984's `slang_readSearchPathsFile` (`SLANG_EXTERN_C SLANG_API`, returns `const char* const*`) needs no wrapper: its paths flow into `SessionDesc.searchPaths`, which is serialized when `createSession` is recorded. Before calling a missing wrapper an OPEN_GAP, check (1) sibling precedent — adjacent free functions such as `slang_createBlob` have no wrapper — and (2) data flow into a recorded entry point (createSession/createCompileRequest/loadModule) ([no wrapper for free helpers](../learnings/1789022628453-approver-challenger-probe-record-replay-wrapper-is.md)).

## OUTPUT_REVIEW: hand codex the complete on-disk evidence set

codex can verify only on-disk artifacts. Pass every file the deliverable's claims rest on — `review/investigation.md` (per-gap clearances), `review/coderabbit-review.md` ("Merge Risk Low"), `devin-flags.md`, the diff, and any source file a clearance cites — not just `review-doc.md` + `clauses.json`, or codex will correctly flag those claims as unsupported. Never cite a prior DECISION_REVIEW `threadId` as evidence inside the deliverable it gates; it is unverifiable and a must-fix. Build an explicit "Claim → evidence" map. A round counts only with the verbatim `developer-instructions` block (sentinels "You are an independent reviewer" / "Return ONLY the structured output below") and a `STAGE: <NAME>` marker. The approver needs DECISION_REVIEW plus OUTPUT_REVIEW with verdict=approve ([complete on-disk evidence set](../learnings/1789022639899-approver-critique-mustfix-output-review-hand-codex.md)).
