# Slang WGSL emit: matrix-operator validity and storage orientation, template-list ambiguity, buffer-element gaps, enable/requires directives, push constants, and GPU-free naga/Tint validation

Slang's WGSL emitter (`slang-emit-wgsl.cpp`) can produce text that compiles with rc 0 but is rejected by wgpu/naga or Tint. The recurring families are shapes legal in the Metal/HLSL forms the emitter mirrors but not in WGSL (matrix negation, non-float matrices), comma lists that WGSL's template-list grammar mis-parses, buffer-element lowering that leaves non-host-shareable or untyped values, and built-ins whose `enable` is never requested. All can be checked without a GPU, with naga-wasm or with real Tint through Dawn's null backend. The broader WGSL backend is on [[wiki/concepts/slang-backends-wgsl-metal.md]]; WGSL via Tint is on [[wiki/concepts/slang-backends-f0909b0-glsl-wgsl-bindless.md]]. WGSL f16, `half`→`u16` producers and const-expression NaN/Inf are on [WGSL f16, sub-word storage and const-expressions](slang-backends-wgsl-f16-and-const-expressions.md); `DescriptorHandle` spelling and WGSL resource tables are on [DescriptorHandle emit and bindless targets](slang-backends-descriptor-handle-emit-and-bindless-targets.md).

## TL;DR

- **GPU-free WGSL check: `npm install naga-wasm@30.2.0`, then `validate(parseWgsl(src))`.** It throws on parse or validation errors, needs no Rust toolchain, and works on node 22 despite a node >=24.12 warning.
- **naga and Tint have different blind spots; use Tint for any verdict on f16, subgroups, uniformity, const-expressions or new directives.** naga-wasm rejects spec-valid `bitcast<vec2<f16>>(u32)`, every `enable subgroups;` and `requires immediate_address_space;`, and runs no uniformity analysis.
- **Real Tint without a GPU: `npm install webgpu@0.6.2`, `create(['backend=null'])`, then `createShaderModule({code}).getCompilationInfo()`.** Request `shader-f16` (and `subgroups`) in `requestDevice`, or every `enable f16;` is a harness false negative. Set `XDG_RUNTIME_DIR=/tmp` and end with `process.exit(0)`.
- **wgpu-py is the pip-only naga validator and GPU runner**; its pipelines catch `var<uniform>` alignment and vertex `@location` errors, a dispatch checks values, and naga enforces §11.4 pointer-argument address spaces. A slang-tint stub library only captures WGSL; it validates nothing.
- **`subgroups_f16` no longer exists** (removed from Dawn/Tint in Apr 2025). f16 subgroup ops need only `enable f16; enable subgroups;`, yet Slang still emits `enable subgroups_f16;` whenever `half` and any subgroup op meet (#13636).
- **Tint's own lowering (`src/tint/lang/wgsl/reader/lower/lower.cc`) is the cross-target reference for a WGSL built-in's meaning**: `workgroupUniformLoad(p)` is barrier; load; barrier, which Slang's non-WGSL arms drop (#13631). DeepWiki describes current code, not design intent.
- **WGSL push constants are `var<immediate>`** (module scope, no `@group/@binding`, no arrays, at most one per entry point). Slang emits it since #13646 (2026-10-21), but a block with an array, matrix or `bool` member still fails Tint: every buffer matrix, int matrices included since #13715, becomes a `_MatrixStorage_*` array. The lowering choice is open design question #13666.
- **A native WGSL `matRxC` in a buffer equals Slang `row_major` storage byte for byte**; Slang `column_major` (the slangc CLI default) is its transpose and needs `matCxR` plus `transpose()`.
- **Directive order is checked by Tint**: a `__requirePrelude("diagnostic(...)")` can land after a helper `fn` in the shared insertion-ordered prelude set ("directives must come before all global declarations").
- **WGSL template-list ambiguity (§3.9):** in `f(a < b, a > b)` the `a <` opens a candidate template list, commas do not clear it, and a later `>` (or `>=`) closes it. `<=` and `<<` never open one. Slang emits call/constructor args at `EmitOp::General`, where `maybeEmitParens` does not parenthesize relational operators (#13566).
- **To exercise WGSL `select(...)` argument lists, use vector `&&`/`||`**; a `{a, b}` struct initializer lowers to a synthesized-ctor call, not `kIROp_MakeStruct`.
- **For a "wrap this op in parens" emit fix, reuse the shared printer**: `emit("("); defaultEmitInstExpr(inst, getInfo(EmitOp::General)); emit(")");`.
- **WGSL has no unary `-` on matrices and no single-scalar matrix constructor.** Emit `T(-1) * m` (keeps IEEE -0) or `matCxR<T>() - m`, not `matCxR<T>(0) - m`. Scalar `uint` `- x` is also naga-rejected (#13571).
- **int64/uint64 matrices survived `legalizeMatrixTypes` on WGSL** (only 32-bit int/uint/bool were lowered) and emitted `mat2x2<i64>`. A WGSL emitter `SLANG_ASSERT(isFloatingType(matrixElt))` is reachable from user code, and in Release it is `[[assume]]` UB.
- **The #13572 fix lowers every non-float matrix on WGPU**, so E38203 fires. A test built from int64 *scalars* is vacuous (E38203 fires on the old build too); build the matrix from a float-matrix cast, with location-less annotations.
- **Probe more than one source spelling before calling a shape unreachable** — `int64_t2x2(...)` gave E38203 where `matrix<int64_t,2,2>(...)` compiled.
- **`bool` inside `var<uniform>`/`var<storage>` is emitted with rc 0 but is not host-shareable (#13590).** Three gaps in `slang-ir-lower-buffer-element-type.cpp` must be fixed together: Khronos-only bool→int leaf mapping, std140 widening that replaces the leaf cast with `VectorReshape`, and `needsElementLowering` skipping top-level `vector<bool,N>`.
- **A bare WGSL expression statement (`x.data_0[i32(N)].x;`) usually means an IR inst with a null type, not an emitter bug.** The `VectorReshape`→scalar peephole built its swizzle with a null `resultType`; fix with `emitSwizzle(inst->getDataType(), …)` (#13607).
- **When a PR turns an ICE into rc 0, validate the new output with naga or spirv-val**, on shapes beyond the PR's own type.
- **On WGSL, `-force-glsl-scalar-layout`/`-fvk-use-c-layout` change the entry-point uniform buffer's IR layout while reflection stays std140 (#13704).** A per-buffer `ScalarDataLayout` CB splits the same way (#13904; [GLSL/WGSL buffer layout](slang-backends-f0909b0-glsl-wgsl-bindless.md)).
- **An undefined resource value (`LoadFromUninitializedMemory`/`Poison` of a `Texture2D`) gives rc 0 and invalid GLSL and WGSL**; validate with `-emit-spirv-via-glsl` and Tint.
- **`@builtin(primitive_index)` needs `enable primitive_index;` (naga ≥29, Tint/Chrome 142), and the WGSL varying legalizer cannot request enables.** Hook: a required-extension field on `SystemValueInfo` plus `addRequireWGSLExtensionDecoration`. A raw `SV_WaveLaneIndex` parameter likewise omits `enable subgroups;`. Draft PR #13619 adds `SystemValueInfo.requiredWGSLExtension`; stack other system-value enables on it.
- **Check gpuweb and Dawn before adding a WGSL capability atom.** Multisampled array textures are now a core language extension (no `enable`); static samplers are API-side bind-group layout; compat mode is device validation and limits, with no directive. capdef has no subtraction: model a restricted profile as a base atom that the full profile implies.
- **A lone WGSL `sample`/`centroid` qualifier is silently dropped**; `emitInterpolationModifiersImpl` emits `@interpolate` only with an interpolation type.

## Validating WGSL in-container: naga-wasm, wgpu-py and real Tint

**naga-wasm** (`npm install naga-wasm@30.2.0`) is the cheapest oracle and the source of every naga message quoted on this page ([GPU-free WGSL parse/validate check: naga-wasm](../learnings/1791663423398-gpu-free-wgsl-parse-validate-check-naga-wasm-via-n.md)):

```js
import { parseWgsl, validate } from "naga-wasm";
const m = parseWgsl(src); validate(m);  // throws on parse/validation error
```

**wgpu-py** is the pip-only naga route and adds pipeline- and value-level checks on the GPU: `python3 -m venv /tmp/wgpu-venv && /tmp/wgpu-venv/bin/pip install wgpu numpy` (system pip is PEP-668 locked), then `request_adapter_sync()` → `request_device_sync()` → `create_shader_module(code=src)` in a `try` (raises the naga error with a span) → `create_compute_pipeline(layout="auto", ...)` or `create_render_pipeline`, where a bad `var<uniform>` layout fails with "Alignment requirements for address space Uniform"; a dispatch plus `read_buffer` checks values. On the L40S fleet it picks Vulkan; `XDG_RUNTIME_DIR` warnings are harmless. A vertex-only render pipeline needs a `depth_stencil` target, and its vertex buffers must match the emitted `@location`s, which exposes the dropped-explicit-locations bug (GLSL 0/3 → WGSL 1/0, ~#9693); `var<storage, read_write>` in a vertex stage (VERTEX_WRITABLE_STORAGE) is the negative control ([validate emitted WGSL on the GPU with wgpu-py](../learnings/1793222265902-validate-emitted-wgsl-on-the-gpu-with-wgpu-py-naga.md)). naga enforces WGSL §11.4 (a pointer argument must match the parameter's address space; `ptr<workgroup,T>` params are rejected), which confirmed the explicit-`__constref` bugs #13703/#13709: a `static` global argument emits `&(var<private>)` into a `ptr<function>` parameter (the #12173 family on [[wiki/concepts/slang-backends-wgsl-metal.md]]), and a `groupshared` argument makes a `ptr<workgroup>` parameter. A slang-tint stub library (`scratch-13391/libslang-tint.so`) only captures the WGSL handed to Tint, so feed the capture to a real validator ([validate WGSL locally with naga via wgpu-py](../learnings/1792441518888-validate-slang-wgsl-output-locally-with-naga-via-w.md)). The case that prompted the recipe (#13704): `slang-ir-entry-point-uniforms.cpp:559` sets the synthesized entry-point constant buffer's layout op from `-force-glsl-scalar-layout`/`-fvk-use-c-layout` with no target check; WGSL lowering honours it while reflection stays std140, so host offsets and shader disagree, and `-fvk-use-dx-layout` also breaks WGSL uniforms ([wgpu-py (naga) is a pip-installable real WGSL validator](../learnings/1792162080215-wgpu-py-naga-is-a-pip-installable-real-wgsl-valida.md)).

**naga is wrong in both directions on recent WGSL.** It rejects the spec-listed f16 bitcasts `bitcast<vec2<f16>>(u32)` and `bitcast<u32>(vec2<f16>)` ([naga-wasm rejects spec-valid f16 bitcasts](../learnings/1792085330619-naga-wasm-rejects-spec-valid-wgsl-f16-bitcasts-val.md)), every `enable subgroups;` ([naga-wasm cannot validate `enable subgroups;`](../learnings/1792070896998-wgsl-subgroups-f16-is-dead-naga-wasm-30-cannot-val.md)), and `requires immediate_address_space;` while accepting `var<immediate>` itself ([naga 30.2 `var<immediate>` support gap](../learnings/1792071495705-wgsl-var-immediate-push-constants-spec-rules-naga-.md)). It skips uniformity analysis and misses Tint-only errors (NaN/Inf const-expressions, user-function calls at module scope). A report names the validator that ran.

**Real Tint runs in the container through Dawn's null backend** (`npm install webgpu@0.6.2`, ~137 MB):

```js
import { create, globals } from "webgpu"; Object.assign(globalThis, globals);
const gpu = create(["backend=null"]);
const dev = await (await gpu.requestAdapter()).requestDevice({ requiredFeatures: ["shader-f16", "subgroups"] });
const m = dev.createShaderModule({ code });
console.log((await m.getCompilationInfo()).messages); process.exit(0);
```

Messages match the `tint` CLI text. The null adapter reports `subgroups`, `shader-f16`, the wgslLanguageFeatures (including `immediate_address_space`) and limits (`maxImmediateSize=64`), matching Chrome. The default Vulkan backend rejects lavapipe for missing `shaderUniform*ArrayDynamicIndexing`; without `process.exit(0)` the process may hang ([dawn.node null backend catches uniformity errors](../learnings/1792071853801-gpu-free-tint-wgsl-validation-uniformity-errors-in.md), [real-Tint validation via node webgpu](../learnings/1792074422249-gpu-free-real-tint-wgsl-validation-via-node-webgpu.md), [null adapter reports language features and limits](../learnings/1792086855977-gpu-free-tint-wgsl-validation-dawn-node-webgpu-nul.md)). The triager's `/workspace/agent/tools/tint-validate/tint-validate.mjs` calls `requestDevice()` with no features, so every `enable f16;` fails with "extension 'f16' is not allowed in the current environment"; `var x : u16` is a good negative control ([tint-validate.mjs rejects all f16 unless shader-f16 is requested](../learnings/1792085503561-tint-validate-mjs-rejects-all-f16-wgsl-unless-the-.md)). The same Null backend is reachable from C via slang-rhi's prebuilt Dawn (`<rhi-build>/_deps/dawn-src/{include,lib64/libdawn.so}`, `timedWaitAnyEnable=1`, `WGPUBackendType_Null`, `WGPUFeatureName_ShaderF16`; harness slang-fixer `reports/tint-wgsl-validator.c`); `-wgpu` COMPARE_COMPUTE rows still report "Not Supported" on llvmpipe. In-tree `wgsl-spirv-asm` (Tint) rows are ignored on Linux because slang-tint is fetched only for Windows x64, so this harness is the local Tint oracle ([PackedFloat types never reach the WGSL FloatLit switch](../learnings/1792099072974-slang-packedfloat-types-bf16-fp8-never-reach-the-w.md)).

Tint facts measured this way: a function `@diagnostic` attribute does not cover callees; conflicting severities for one rule are an error; an unknown rule only warns; `derivative_uniformity` and `subgroup_uniformity` are independent rules; directives must precede every global declaration, which Slang can violate because WGSL helper preludes share an insertion-ordered set ([dawn.node null backend catches uniformity errors](../learnings/1792071853801-gpu-free-tint-wgsl-validation-uniformity-errors-in.md)).

**Spec and Tint sources without a browser.** Tint's extension list is the `enum extension` block of `https://raw.githubusercontent.com/google/dawn/main/src/tint/lang/wgsl/wgsl.def`. Other Dawn files: `curl -sL "https://dawn.googlesource.com/dawn/+/refs/heads/main/<path>?format=TEXT" | base64 -d`; commit messages via `+/<sha>?format=JSON` with the `)]}'` prefix stripped (`gh api repos/google/dawn` returns 401 through the gateway). The WGSL spec: `curl -sL https://gpuweb.github.io/gpuweb/wgsl/` and strip tags (WebFetch to w3.org returned 429) ([subgroups_f16 is dead](../learnings/1792070896998-wgsl-subgroups-f16-is-dead-naga-wasm-30-cannot-val.md), [Tint's lowering is the cross-target reference](../learnings/1792071135841-wgsl-built-in-semantics-use-tint-s-lowering-as-the.md)).

## Template-list ambiguity in comma-separated argument lists (#13566)

`vec2<bool>(a_0 < b_0, a_0 > b_0)` fails naga with "expected `)`, found b_0" because of the §3.9 rule in the TL;DR. Slang emits call and constructor arguments at `EmitOp::General`, where `maybeEmitParens` leaves relational operators bare. User workarounds mostly fail (source parens are dropped, locals are folded back); only rewriting so no `<` is followed by `>` in the same list works [same](../learnings/1791663423398-gpu-free-wgsl-parse-validate-check-naga-wasm-via-n.md).

Testing the fix (PR #13569) needs inputs that reach each comma-list path. `Flags f = { a < b, a > b };` lowers to the synthesized constructor call `Flags_x24init_0(...)`, not WGSL `kIROp_MakeStruct` (see [[wiki/concepts/slang-language-core-struct-construction-lowering.md]]). Vector `&&`/`||` such as `(u <= v) && (u >= v)` on `float2` lowers to `select(vec2<bool>(false), rhs, lhs)`. On the emit side, wrap `defaultEmitInstExpr(inst, getInfo(EmitOp::General))` in parens rather than copying the printer, as Metal's MakeArray does [a `{a, b}` initializer list on WGSL lowers to a synthesized ctor call](../learnings/1791675327416-slang-a-b-initializer-list-on-wgsl-lowers-to-a-syn.md).

## Matrix negation: `T(0) - m` is not WGSL (#13571)

`WGSLSourceEmitter::tryEmitInstExprImpl`'s `kIROp_Neg` case lowered vectors and matrices to `(T(0) - x)`. `vecN<T>(0)` is a valid splat but `matCxR<T>(0)` is not ("cannot cast a {AbstractInt} to a mat2x2<f32>"). The form came from #7936 mirroring Metal, where `matrix<…>(0)` is valid MSL; #12909 fixed only the operand parens and its test pins the invalid form. Releases up to 2025.12 emitted `- mat2x2(...)`, also invalid, so this is not a regression. Use `(f32(-1) * m)` (keeps -0) or `mat2x2<f32>() - m`. 32-bit int/uint/bool matrices are unaffected (`legalizeMatrixTypes` makes them arrays of row vectors), and matrix-plus-scalar is fine (`legalizeBinaryOp` splats via `MakeMatrixFromScalar`). Scalar `uint` negation emits `- x`, also rejected ("Operation Negate can't work") [WGSL matrix negation `T(0) - m` is invalid; use `T(-1) * m`](../learnings/1791749878369-wgsl-emitter-matrix-negation-t-0-m-is-invalid-use-.md).

## 64-bit integer matrices reach the emitter as `IRMatrixType` (#13572)

`shouldLowerMatrixType` (slang-ir-legalize-matrix-types.cpp) lowered only `IRBoolType`, `IRIntType` and `IRUIntType` for WGSL, so `matrix<int64_t,2,2>`/`matrix<uint64_t,2,2>` compiled with rc 0 to `mat2x2<i64>(...)` ("matrix scalar type must be floating-point"), even for `m + m`. int16/uint16 give E56103; int8 and double ICE. Emitter code that asserts `isFloatingType(matrixElt)` on the grounds that integer matrices are lowered is therefore reachable, and Release `SLANG_ASSERT` is `SLANG_ASSUME`, so a violation is UB. Probe several spellings: `int64_t2x2(buf[0],...)` gave E38203 while `matrix<int64_t,2,2>(b[0],b[1],b[2],b[3])` with a `float2x2(-m)` consumer compiled [int64/uint64 matrices survive legalizeMatrixTypes on WGSL](../learnings/1791763584478-wgsl-int64-uint64-matrices-survive-legalizematrixt.md).

The fix makes WGPU lower every non-float matrix (`return !isFloatingType(elementType)`), so the 32-bit vector-width check in `slang-ir-validate.cpp` reports E38203. Building the test matrix from int64 scalars is vacuous: AST lowering already creates an int64 vector, so E38203 fires on the unfixed build. `matrix<int64_t,2,2>(floatMat)` has no 64-bit vector until matrix lowering; its diagnostic has no source location, so annotations must be caret-less. Run every new negative row against the unfixed build before trusting it [a diagnostic test for WGSL matrix lowering can be vacuous](../learnings/1791809366702-slang-wgsl-a-diagnostic-test-for-matrix-lowering-c.md).

## Buffer-element lowering: `bool` is not host-shareable (#13590)

`struct P { bool b; bool a[2]; }; ConstantBuffer<P> gC;` or `StructuredBuffer<bool2>` on `-target wgsl` emits `bool` in `var<uniform>`/`var<storage>` with rc 0 (since at least v2025.1); naga says "The type is not host-shareable" and Tint agrees. Three coupled gaps in `slang-ir-lower-buffer-element-type.cpp`, none sufficient alone:

1. The only bool→int leaf mapping is in `KhronosTargetBufferElementTypeLoweringPolicy::lowerLeafLogicalType` (behind `shouldEmitSPIRVDirectly`); every WGSL target, Tint ones included, uses `WGSLBufferElementTypeLoweringPolicy`.
2. WGSL std140 array-element widening in `getLoweredTypeInfoImpl` overwrites the leaf's `convertLoweredToOriginal` with `VectorReshape`, so `bool[N]` and bool matrices then use a `u32` as an `if` condition; reshape and cast must be composed.
3. `needsElementLowering` accepts scalar `bool` but not top-level `vector<bool,N>` (on SPIR-V that shape fails spirv-val, `OpTypeBool` in StorageBuffer).

An 88-line prototype of all three made 14/16 shapes pass naga with reflection unchanged; the rest are `ByteAddressBuffer` (#10207) and push constants (no `@binding` on WGSL) [WGSL bool in uniform/storage buffers: 3 coupled gaps](../learnings/1791890303067-wgsl-bool-in-uniform-storage-buffers-3-coupled-gap.md).

## A null-typed `VectorReshape` swizzle prints as a dangling statement (#13607)

The same widening leads to the next silent failure:

```slang
struct S { float a[3]; };
ConstantBuffer<S> gC;
RWStructuredBuffer<S> gOut;
gOut[0].a = gC.a;   // invalid WGSL on master
// gOut[0] = gC;    // invalid WGSL once #13607 fixes the CopyLogical ICE
```

Unpacking a std140-widened scalar-array element uses `kIROp_VectorReshape`. The `slang-ir-peephole.cpp` case folds vector→scalar reshape into `builder.emitSwizzle(resultType, …)` with `resultType = as<IRVectorType>(inst->getDataType())`, null for a scalar result. The untyped swizzle prints as `gC_0.a_0.data_0[i32(N)].x;` and a later use names an undeclared `_S1`; naga: "expected assignment or increment/decrement, found ';'". Fix: `emitSwizzle(inst->getDataType(), …)`; test `tests/wgsl/uniform-array-copy-to-storage.slang` [VectorReshape→scalar peephole emits a typeless swizzle](../learnings/1791921698811-vectorreshape-scalar-peephole-emits-a-typeless-swi.md), [VectorReshape-to-scalar swizzle was built with a null result type](../learnings/1791924339218-slang-peephole-vectorreshape-to-scalar-swizzle-was.md). #13607 turned a master ICE (the cross-layout `CopyLogical` on [[wiki/concepts/slang-backends-f0909b0-spirv-legalization-crashes.md]]) into rc 0; probing only `bool` missed the float arrays that then reached the broken peephole.

## Undefined resource values: rc 0 with invalid GLSL and WGSL (#13700)

For a `LoadFromUninitializedMemory`/`Poison` of resource type (an undefined `Texture2D` local read on some path), GLSL prints an undeclared identifier, because `shouldFoldInstIntoUseSites` folds resource values before the never-fold-undefined check; WGSL declares a function-scope `var t : texture_2d<f32>`, which Tint rejects ("must have constructible type"). `checkUnsupportedInst` (slang-ir-check-unsupported-inst.cpp) rejects only an opaque `DefaultConstruct`, so neither gets a diagnostic, with or without #13700. Validate with `slangc -target spirv -emit-spirv-via-glsl` (glslang) and the Tint harness, using `int` cbuffer conditions so #13590 does not fail first. A related hang with no texture: a `{undef, self}` phi or loop swap cycle (`int t; for(..){ if(c==i){int r; t=r;} o[i]=t; }`) hangs slangc on SPIR-V and HLSL; #13700's `arg == inst` skip fixes it ([Slang GLSL/WGSL 'compiles' checks hide invalid output for undefined resources](../learnings/1792155974717-slang-glsl-wgsl-compiles-checks-hide-invalid-outpu.md)).

## Required `enable`/`requires` directives: missing, stale, and misplaced (#13617, #13636)

`@builtin(primitive_index)` is a fragment-only `u32` input that since naga 29 / Tint/Chrome 142 needs `enable primitive_index;` and the "primitive-index" device feature (naga 30.0.1: no enable is a parse error, `i32` a validation error). Slang marks `SV_PrimitiveID` unsupported on WGSL (E55202) in `LegalizeWGSLEntryPointContext::getSystemValueInfo` (slang-ir-legalize-varying-params.cpp), and `SystemValueInfo` on master has no required-extension field. The producer-side hook is that field plus `legalizeSystemValue` calling `addRequireWGSLExtensionDecoration(entryPointFunc, ext)`; the emitter already consumes it (`handleRequiredCapabilitiesImpl` feeds the tracker, and `emitFrontMatterImpl`, emitted after the body, writes `enable X;`). A prototype validated under naga, and draft PR #13619 (`SV_PrimitiveID` → `enable primitive_index;`) adds the field as `SystemValueInfo.requiredWGSLExtension`, so other system-value enables (`barycentric_coord`, `view_index`) should stack on #13619 ([check gpuweb before a chromium_* atom](../learnings/1792916916093-wgsl-chromium-experimental-features-check-gpuweb-b.md)). Similarly, a raw `uint l : SV_WaveLaneIndex` parameter emits `@builtin(subgroup_invocation_id)` without `enable subgroups;`, since only Wave* intrinsics call `__requireTargetExtension("subgroups")`; the spec requires it though naga accepts its absence [WGSL primitive_index needs `enable primitive_index;`](../learnings/1791954062918-wgsl-primitive-index-needs-enable-primitive-index-.md).

The stale case: Dawn/Tint removed the `subgroups_f16` enable and SubgroupsF16 feature in April 2025 (dawn e2c7a2a0b8); it is in neither WGSL §4.1.1 nor `wgsl.def`. Slang's `handleRequiredCapabilitiesImpl` (from #6213) still hard-codes it, so any `half` use plus any subgroup op, even on `uint`, yields a module Tint rejects (#13636) [WGSL `subgroups_f16` is dead](../learnings/1792070896998-wgsl-subgroups-f16-is-dead-naga-wasm-30-cannot-val.md). WGSL's `requires X;` language-extension directive must also precede all declarations; `ShaderExtensionTracker::appendExtensionRequireLinesForWGSL` emits only `enable X;` today [WGSL `var<immediate>` spec rules](../learnings/1792071495705-wgsl-var-immediate-push-constants-spec-rules-naga-.md).

Before modeling a Dawn or WebGPU feature as a directive or capability atom, check where it lives. A Dawn-experimental WGSL feature may already be standardized: gpuweb#6283 (June 2026) put `texture_multisampled_2d_array` into core as a WGSL language extension with no `enable`, so Slang's only blocker is the `static_assert` in `__wgsl_check_texture_type` (hlsl.meta.slang:1339) and the emitter can already print the type; barycentrics are only a discussion (gpuweb#5566) with no standard name. Check this before adding an opt-in `wgsl_chromium_experimental_*` atom in the PR #13707 pattern (#13932) ([check gpuweb before a chromium_* atom](../learnings/1792916916093-wgsl-chromium-experimental-features-check-gpuweb-b.md)). Dawn "static samplers" are API-side: a `StaticSamplerBindingLayout` chained into a bind-group-layout entry, while the shader still declares a normal `sampler`, which Slang already emits. `wgsl.def` has no static-sampler extension, and shader-declared samplers are only gpuweb issue 4687. WebGPU compatibility mode has no `enable`/`requires` either; it is device validation (featureLevel "compatibility", feature "core-features-and-limits"), and some of its rules are device limits (`maxStorageBuffersInVertexStage` defaults to 0) that no capability atom can express. The capdef algebra is only `+`/`|`, so a restricted profile is modeled by inverting the chain, as the `_spirv_1_x`/`_GLSL_xxx` version chains do: a compat base atom, a core atom that implies it, and features gated on core. Compat accepts only `@interpolate(flat, either)`, but Slang's `nointerpolation` emits `@interpolate(flat)`. A side bug, not filed: a lone `sample` or `centroid` qualifier with no `linear`/`nointerpolation` is silently dropped, because `emitInterpolationModifiersImpl` (slang-emit-wgsl.cpp ~1883) emits `@interpolate` only when an interpolation type is set (#13933, master 52e29ab) ([Dawn static samplers are API-side; compat has no directive](../learnings/1792917188690-webgpu-dawn-static-samplers-are-api-side-compat-mo.md)).

## WGSL built-in semantics: Tint's lowering is the cross-target reference (#13631)

When a Slang intrinsic mirrors a WGSL built-in, Tint's `src/tint/lang/wgsl/reader/lower/lower.cc` defines its meaning on other backends: `workgroupUniformLoad(p)` becomes `workgroupBarrier(); load (or atomicLoad); workgroupBarrier()`. Slang's `hlsl.meta.slang` version has `default: return v;`, dropping both barriers on SPIR-V, HLSL, GLSL, Metal and CUDA. DeepWiki echoed the buggy code as design ("does not implicitly include a barrier") [Tint's lowering is the cross-target reference](../learnings/1792071135841-wgsl-built-in-semantics-use-tint-s-lowering-as-the.md).

## Push constants: WGSL `var<immediate>` (#13639, #13646)

Before #13646, `emitParameterGroupImpl` in slang-emit-wgsl.cpp had no `PushConstantBuffer` case and hard-coded `var<uniform>`, so push constants came out binding-less and invalid (#13639). The `immediate_address_space` extension's `var<immediate>` is module-scope, binding-less, storage-layout (std430-compatible), with a host-shareable constructible store type containing no arrays (nor structs with arrays), at most one statically accessed per entry point, set by the API's `setImmediates` [WGSL `var<immediate>` spec rules](../learnings/1792071495705-wgsl-var-immediate-push-constants-spec-rules-naga-.md). That collides with buffer matrix lowering: `shouldLowerMatrixType` (slang-ir-lower-buffer-element-type.cpp) keeps a matrix native only under the Natural layout rule, which WGSL never uses, so every WGSL buffer matrix becomes a `_MatrixStorage_*` array struct. Push constants reach buffer lowering as `AddressSpace::Uniform`; the PushConstant address space is unused there [WGSL matrix storage orientation](../learnings/1792086860208-wgsl-matrix-storage-native-matrxc-slang-row-major-.md). Since #13715 (2026-10-20) that wrapper covers int/uint/bool matrices too: `lowerBufferElementTypeToStorageType` wraps them (`isMatrixTypeLegalizedToVectorArray`) and runs before `legalizeMatrixTypes`, so notes saying int matrices become bare `vector<T,C>[R]` arrays with no wrapper are out of date. #13646 (merged 2026-10-21) now emits push constants as `var<immediate>`, but re-checked on master 0bd71cd70 (2026-10-22), any block with an array, a matrix or a `bool` member still fails Tint with "arrays cannot be used in the <immediate> address space"; blocks of only scalars and vectors pass. The lowering choice is tracked as design question #13666 (waiting on maintainers; the reporter will implement) [WGSL var<immediate> still rejects arrays/matrices after #13646](../learnings/1792685555616-wgsl-var-immediate-still-rejects-arrays-matrices-a.md).

## Matrix storage orientation: native `matRxC` is Slang row-major (#13666)

Slang emits an HLSL-semantics `floatRxC` as WGSL `matRxC` (the "terminology reversal" in slang-emit-wgsl.cpp), so each WGSL column holds one Slang row. A native WGSL matrix in a std430/storage/immediate buffer therefore matches Slang `row_major` byte for byte (row-major `float4x3` is 64 bytes, like `mat4x3<f32>`). `column_major` is the transpose, needing `matCxR` plus `transpose()`, with different sizes (column-major `float3x4` is 64 bytes vs 48 row-major). Column-major is the slangc CLI default (slang-end-to-end-request.cpp) and row-major the API default, so a keep-matrices-native fix must handle both [WGSL matrix storage orientation](../learnings/1792086860208-wgsl-matrix-storage-native-matrxc-slang-row-major-.md). The default also applies to GLSL input: a GLSL `mat4` in a std430 SSBO is read row-major on SPIR-V (`RowMajor`) and WGSL alike, the GLSL target emits `layout(row_major) buffer;`, and `-matrix-layout-row-major` gives GLSL column-major semantics [same wgpu-py run](../learnings/1793222265902-validate-emitted-wgsl-on-the-gpu-with-wgpu-py-naga.md).
