## TL;DR

- **`[[vk::binding]]` is silently dropped when a matching `-fvk-*-shift` is active** on a non-combined resource: the layout reports an HLSL kind; the binding reader only reads `DescriptorTableSlot`. The same flip crashes `SubpassInput` under any `-fvk-t-shift` on SPIR-V 1.4+.
- **Reflection JSON's `"binding".index` IS `getOffset(category)`** (on Vulkan index = binding, space = set), but `include/slang.h` never says so. Header silence is not falsity; find the producer/consumer.
- **A `//TEST:SIMPLE(filecheck=...)` on a source target verifies what Slang EMITS, never what DXC/Metal ACCEPT.** `-target dxil`/`metallib` invoke the toolchain; `webgpu@0.6.2` `backend=null` gives Tint diagnostics GPU-free.
- **Prelude-vs-emitter drift**: before calling a prelude inefficient, check whether the emitter already made the better decision years ago.
- **A capability-negative keyed on one identifier survives every widening of the search.** Search the concept or operand shape, not the name (GLSL has integer dot as `dotEXT`).
- **`ByteAddressBuffer.Load<T>()` feeding a call (method `this` counts) with a struct >16 B SIGSEGVs**: `specializeFuncsForBufferLoadArgs` rebuilt the 3-operand load with 2 operands. Fix copies all trailing operands plus a loud `operandCount==3` release assert (#13130).
- **Pre-link `peepholeOptimize` runs before matrix layouts and buffer-load specialization are resolved**: don't expand type-dependent casts there. `//TEST:SIMPLE` slangc runs get `-O0`, so pin `-O2` in a DXIL load-count test.
- **The shared `CLikeSourceEmitter` fails silently or late.** An always-fold `return true` above the side-effect checks deletes side effects; Always-policy users (GEP, `NonUniformResourceIndex`) re-read operands after a store until PR #13283 (master 2026-10-17, not v2026.20). A null data type means void. Self-referential pointer structs: forward-declare the pointer, never the struct.
- **C-like emit: a pointer type used only by a null literal is never declared** (`ensureGlobalInst` skips `IRPtrLit`, #14088), **and 0-use atomic results and discarded non-void calls get named temps** (#14058): gate atomic paths on non-debug uses and calls in `_emitInst`'s default branch, never generically in `emitInstResultDecl`; keep WGSL's binding.
- **A `switch` case label prints through `emitSimpleValue`, so a literal spelling that only warns in an expression is a hard error as a label** (INT64_MIN as `-9223372036854775808LL`, #14155). Add a `switch` repro when triaging a literal-emission bug.
- **The E30048 memory-qualifier-drop diagnostic needs a positive destination-type check**, not an error-count delta (an ill-formed destination errors in the header phase).

## `[[vk::binding]]` silently dropped under an active `-fvk-*-shift`

On a Vulkan/GLSL/SPIR-V target with `-fvk-t-`/`-s-`/`-u-`/`-b-shift`, an explicit `[[vk::binding(b,set)]]` on a **non-combined** resource of that register class is neither honoured nor diagnosed. When `options.hlslToVulkanKindFlags` has the kind's bit, `GetObjectLayout` (`slang-type-layout.cpp:1135`) returns an HLSL kind (`ShaderResource` etc.) instead of `DescriptorTableSlot` ("Later we will do shifting as necessary"), but `addExplicitParameterBindings_GLSL` (`slang-parameter-binding.cpp:1247`) reads the `GLSLBindingAttribute` only inside `if (FindResourceInfo(DescriptorTableSlot))`. The explicit binding is never recorded; the parameter is auto-allocated plus shifted. `_maybeDiagnoseMissingVulkanLayout` warns only for `register` without `vk::binding`, so "attribute present but unusable" is the one unguarded combination. Combined texture-samplers keep `DescriptorTableSlot` and still work; `tests/bindings/hlsl-to-vulkan-combined.hlsl`'s `.expected` (kind stays `descriptorTableSlot`, no shift) is the discriminating control. Coverage gap: none of the five shift tests uses `vk::binding`. Until fixed, don't mix the two on one register class for non-combined resources. Mechanism verified at source; wrong-binding outcome inferred. [Slang: [[vk::binding]] appears to be silently dropped when a matching -fvk-*-shift is active (mechanism verified, outcome inferred)](../learnings/1786010843554-slang-vk-binding-appears-to-be-silently-dropped-wh.md)

The same flip crashes `SubpassInput` (#13096): any `-fvk-t-shift` throws `E99997 "Var layout contains conflicting resource uses"` (`SLANG_UNEXPECTED`, `slang-ir-spirv-legalize.cpp:822`). A `SubpassInput` fills a texture `t` slot and an `InputAttachmentIndex` slot (`slang-type-layout.cpp:5393-5401`). The shift reclassifies the texture slot to `ShaderResource`, which `getGlobalParamAddressSpace` (`:806-825`) maps to `StorageBuffer` on SPIR-V ≥1.4, while `InputAttachmentIndex` defaults to Generic; the pair does not reconcile (only `result==Uniform` escapes). Controls: only the `t`-shift triggers, and both `-fvk-t-shift 0 0` and `128 1` trigger, so it is layout-rule selection, not binding arithmetic. On ≤1.3 `getStorageBufferAddressSpace()` returns Uniform ({Uniform, Generic} works); the default target (1.5) reproduces, so a test should note the version gate. Narrowest fix: treat `InputAttachmentIndex` as non-storage-class-bearing in `getGlobalParamAddressSpace` (it lowers only to a decoration), validated under the shift; else stop reclassifying the slot at the producer. [SubpassInput + -fvk-t-shift → E99997 is a layout-rule flip, SPIR-V-1.4+-only](../learnings/1789489702879-subpassinput-fvk-t-shift-e99997-is-a-layout-rule-f.md)

## Reflection JSON's `"binding".index` is `getOffset(category)`: undocumented but exact

`slang-reflection-json.cpp:222` shows what the header never states: `{"binding": {"kind": "descriptorTableSlot", "index": 2}}` is literally `var->getOffset(DescriptorTableSlot)`, and `space` is `getBindingSpace(category)`; on Vulkan index = `binding`, space = `set`. `include/slang.h` documents only `getOffset`'s `SLANG_UNKNOWN_SIZE` failure. **Header silence is not falsity**: find an in-repo producer or consumer (a dumper, serializer or test oracle is a behavioural spec that outranks absent prose). Adjacent traps: there is no `struct ProgramLayout` (it is `typedef ShaderReflection`); `getBindingIndex` has no category overload (use `getOffset(category)`); `SLANG_BINDING_TYPE_MUTABLE_TETURE` is a public-ABI typo that cannot be silently fixed. [Reflection JSON's "binding".index IS getOffset(category) — behaviourally exact, but include/slang.h never documents it](../learnings/1786011267097-reflection-json-s-binding-index-is-getoffset-categ.md)

## A filecheck SIMPLE test asserts what Slang EMITS, never what a downstream toolchain ACCEPTS

`//TEST:SIMPLE(filecheck=...):-target hlsl|cpp|cuda|metal` checks emitted text and never runs a downstream compiler. The toolchain-invoking directives are **`-target dxil`** (~123 tests) and **`-target metallib`** (~97). If a PR says "downstream acceptance routed to CI" and every added directive is a source-target `SIMPLE(filecheck=...)`, green Windows/macOS jobs confirmed nothing: add a `dxil`/`metallib` directive or say "unverified." Whether DXC rejected the old output also decides the characterization ("canonical-form cleanup" versus "we emitted invalid HLSL `int8_t(1)`"). Instrument traps: a duplicate webhook is a redrive (does the outward artifact exist?); re-verify state at the point of action; two-dot `git diff A..B -- <files>` shows your additions as deletions (use three-dot); compile-regression prints each file as PASS and FAIL (dual config). [A filecheck SIMPLE test asserts what Slang EMITS, never what DXC/MSL ACCEPT — -target dxil/metallib are the toolchain-invoking directives](../learnings/1786013814276-a-filecheck-simple-test-asserts-what-slang-emits-n.md)

WGSL has a GPU-free acceptance check: `npm i webgpu@0.6.2`, then `create(['backend=null'])` → `requestAdapter` → `requestDevice` → `device.createShaderModule({code}).getCompilationInfo()` returns real Tint diagnostics, e.g. "value -nan cannot be represented as 'f32'" for a const-expression NaN bitcast (slang#13635; script `tools/tint-13635/tint-validate.mjs` in the slang-fixer workspace) ([check the issue timeline for cross-referenced PRs; GPU-free Tint validator](../learnings/1792076007832-check-issue-timeline-for-cross-referenced-prs-befo.md)).

## Prelude-vs-emitter drift: the emitter may already do the better thing

When triaging "the prelude does X inefficiently" for a C-family target, check whether the emitter already decided better and the hand-written prelude was never brought along. On #12401 (CUDA vector macros use `for(i)` plus an accessor), `slang-emit-cpp.cpp:1567/1608` already emit `.x/.y/.z/.w` for a literal index since PR #2770 (2023-04-03), which touched `prelude/` zero times, so the fix is prelude-only, non-breaking, with no IR pass. Cheap checks: `git grep -l <MACRO_NAME>` and `git show --name-only <sha> | grep -c '^prelude/'`; `nvcc` allows GPU-free PTX diffs. Traps: "byte-identical PTX" from a narrow TU is a claim about the TU (a wide instantiation matrix showed 7/33 kernels differing); an opcode difference is not a semantic one, so measure values; order-balance timing runs. The accessor form is less well-defined (`char*` cast vs `signed char` members), so claim "better defined and measurably same-valued," not "formally equivalent." [Prelude-vs-emitter drift: check whether the emitter already made the decision (slang#12401)](../learnings/1786037659152-prelude-vs-emitter-drift-check-whether-the-emitter.md) The same drift can be a correctness bug: CUDA `WaveMatch` used `__match_all_sync` in the prelude while `kIROp_WaveMaskMatch` in `slang-emit-cuda.cpp` already emitted the right `__match_any_sync` (#14263; [[wiki/concepts/slang-backends-wave-ops-element-types-and-cross-target-probes.md]]) [CUDA WaveMatch: only the prelude disagreed](../learnings/1793745788116-cuda-wavematch-test-with-non-uniform-values-and-ch.md).

## A capability-negative keyed on one identifier survives every widening of the search

Before publishing "API X has no operation Y," search the **capability or concept**, not the **name**, and never carry a vendor tag across ecosystems. On #12403, "GLSL has no integer `dot`" decided the design fork. In-tree grep, the GLSL 4.60 §8.5 spec and a live `glslang` `dlopen` with a working guilty control all agreed, but they were one probe sharing the key `dot`. GLSL has integer dot as **`dotEXT`** (`GL_EXT_integer_dot_product`); codex found it. **Independence is measured over the search key, not the source**; the strongest evidence (§8.5 excludes `genIType`) was a consequence of the positive, and "verify against the spec" only digs deeper into the same key. Apply: grep the builtin table for the operand shape (`ivec3`) or concept (`integer_dot`); try vendor suffixes (`EXT`/`KHR`/`ARB`/`NV`/`OES`); attack hardest the negative that collapses a fork. Slang specifics: `GL_EXT_integer_dot_product` has 0 capability atoms (`__glsl_extension(<NAME>)` exists); the `#version 450` floor satisfies `dotEXT`; its 8/16-bit overloads return 32-bit, which `__intrinsic_asm` would surface as a compile error. [A capability-negative keyed on one identifier survives every widening of the search (GLSL dot vs dotEXT)](../learnings/1786039700634-a-capability-negative-keyed-on-one-identifier-surv.md)

## ByteAddressBuffer.Load<T> + method/call-arg crash = specialization dropping the alignment operand

`slangc` SIGSEGVs on all targets for `input.Load<S>(0).get()` with `S { float values[5]; float get(){...} }` and a `ByteAddressBuffer input` (#13126, PR #13130): it needs a struct big enough to specialize, passed into a call (method `this` counts). `byteAddressBufferLoad` is `(buffer, offset, alignment)` (`slang-ir-insts.lua:1322-1328`; `Load` emits 0, `LoadAligned` the stride). `specializeFuncsForBufferLoadArgs` → `getSpecializedValueForArg` (`slang-ir-specialize-function-call.cpp` ~:911, mirror :933) rebuilt access insts with a hardcoded operand count of 2; `processLoad` (`slang-ir-byte-address-legalize.cpp` ~:140) then read `getOperand(2)` out of bounds and `validateExplicitAlignment` dereferenced it via `as<IRIntLit>(...)->getOp()` before its `SLANG_RELEASE_ASSERT` (Release SIGSEGV; Debug asserts `index < getOperandCount()`). `isTypePreferrableToDeferLoad` (`slang-ir-defer-buffer-load.cpp`) specializes only composites with arrays over 16 B (`{float[5]}` qualifies, `{float[4]}` not). The producer fix copies all trailing operands via `oldArg->getOperandCount()` and keys the specialization cache on them (else `LoadAligned` miscompiles by source order), plus a loud `SLANG_RELEASE_ASSERT(operandCount==3)` at the legalizer, not a tolerant guard: the legalizer's own 2-operand loads at `:999` are terminal output never re-fed to `processLoad`. #8547 introduced the drop; #11595's alignment check made it fatal ([ByteAddressBuffer.Load<T>() + method/call-arg crash = specialization dropping the alignment operand](../learnings/1789577999587-byteaddressbuffer-load-lt-t-gt-method-call-arg-cra.md)).

A module-scope assert on the preserved operand (`SLANG_RELEASE_ASSERT(!getParentFunc(trailingOperand))`) looked unsafe for single-arg `T LoadAligned<T>(uint location)` (`hlsl.meta.slang:490-492`), which forwards `__naturalAlignmentOf<T>()` → `kIROp_GetNaturalAlignment`, a function-local, non-hoistable inst (`slang-ir-insts.lua:1377`) that peephole skips inside a generic (`slang-ir-peephole.cpp:1841`), with no peephole before this pass at `-O0` ([ByteAddressBufferLoad alignment operand: natural-alignment overload is function-local until peephole](../learnings/1789579501578-byteaddressbufferload-alignment-operand-natural-al.md)). False alarm: generic specialization and type legalization resolve it on the concrete type to a module-scope literal first, even at `-O0` inside a user generic (`-O0 -dump-ir-after specializeFuncsForBufferLoadArgs` shows `4 : UInt`). Keep the loud assert (a fallback would be dead code); prove non-reachability with `-dump-ir-after` plus an `-O0` regression arm ([Natural-alignment LoadAligned's alignment is folded to a literal before buffer-load-arg specialization](../learnings/1789580976960-natural-alignment-loadaligned-s-alignment-is-folde.md)). Triage rule: for "buffer `Load<T>`/`Store<T>` + method or call-arg → crash", suspect a specialization/clone pass dropping a trailing operand and check counts with `-dump-ir-after specializeFuncsForBufferLoadArgs`. DeepWiki wrongly says the load has no alignment operand; the lua definition and `hlsl.meta.slang` are authoritative.

**Pre-link peephole runs before buffer-load specialization can see the shape.** `peepholeOptimize` also runs in lower-to-IR (`PeepholeOptimizationOptions::getPrelinking()`), before `specializeMatrixLayout` resolves `Unknown` matrix layouts. PR #13378 round 1 expanded an array `BuiltinCast` per element there, copying arrays whose layouts later proved identical and blocking `specializeFuncsForBufferLoadArgs` (a 64-bone cbuffer went from 4 to 256 `cbufferLoadLegacy`). The fix keeps the cast as one inst, lowers it late after buffer-load specialization, and lets the specializer see through value-preserving wrappers such as `CastDynamicResource`. Measuring traps: slang-test passes `-O0` to `//TEST:SIMPLE` slangc runs and DXC `-O0` emits ~3× the loads of `-O2`, so pin `-O2`; count `call` lines, not `grep -c cbufferLoadLegacy` (it counts the `declare`); an exhaustive `DIAGNOSTIC_TEST` must annotate the second labelled diagnostic E30019/E30047 emit on the same span ([peephole runs pre-link: don't expand type-dependent casts there; SIMPLE uses -O0](../learnings/1790926336121-slang-peephole-runs-pre-link-don-t-expand-type-dep.md)).

## C-like emitter hazards: silent folds, null types, declaration cycles, and unused temps

Each hazard in the shared `CLikeSourceEmitter` (`slang-emit-c-like.cpp`) hits every text target while direct SPIR-V usually escapes; one text-target probe does not cover the others.

**An always-fold rule above the side-effect checks deletes side effects.** In `shouldFoldInstIntoUseSites` the pointer-type early `return true` precedes `!inst->hasUses()`. On a target without pointer types (GLSL), an unused pointer-typed inst is folded into zero use sites: never emitted, side effects lost, no diagnostic. Examples (#13414, fixed by #13410's `canHoldPtrTypeInTemporary`): an ignored `[noinline] int* f()` call, and `RWByteAddressBuffer.Store(off, ptr)` (its legalized store takes the value's type as result type). Any early `return true` above those checks shares the hazard; probe an unused side-effecting inst of the affected type, and sweep GLSL output master vs head over `tests/**/*.slang` (~2.8k compile) to find behaviour changes ([always-fold of pointer types drops unused side-effecting insts](../learnings/1790980787322-c-like-emitter-always-fold-of-pointer-types-also-d.md)).

**`NonUniformResourceIndex` is an always-folded user too, so it had the #13273 fold-order bug (#13548).** `shouldFoldInstIntoUseSites` (`:1556`) always folds `kIROp_NonUniformResourceIndex`, and the side-effect scan (:1869-1881) reached only the operand's direct user, so `load(%a)` folded into the NURI emitted at a later `store` and re-read `a` after `store(%a)`: in `a = NonUniformResourceIndex(b); b = NonUniformResourceIndex(a);` the second assignment reads the new `a`. HLSL, GLSL, CUDA and C++ were wrong since at least 2025.1 (direct SPIR-V right); a `-cpu` COMPARE_COMPUTE test reproduces (1,1 vs 1,0). #13539's narrow `user->getOp() == kIROp_NonUniformResourceIndex` early-out would fix it but changes three CUDA goldens and covers one op ([NonUniformResourceIndex is an always-folded user too: #13273 fold-order bug class](../learnings/1791574480804-nonuniformresourceindex-is-an-always-folded-user-t.md)). What merged is PR #13283's transitive fold legality (the `getFoldPolicy` split on [[wiki/concepts/slang-a-compiler-internals.md]]) on 2026-10-17, after v2026.20 was tagged; it closes #13548 and adds `tests/bugs/gh-13548.slang`. Master 68438b5e1 emits `uint _S1 = b_0; uint _S2 = a_0; ...` and fixes the #13273 `s.top` repro on GLSL, HLSL, Metal and WGSL; `isSafeToFoldIntoUseSites` now recurses into `FoldPolicy::Always` users ([#13273 master build confirms fix](../learnings/1792426436559-13273-master-build-confirms-fix-emits-int-s1-s-top.md)). On v2026.20 and earlier, apply NURI at the resource index (`t[NonUniformResourceIndex(a)]`); copying into new locals (`uint na = NURI(a); a = na;`) does not help, as SSA collapses the copies ([#13548 fixed by #13283, index-site workaround](../learnings/1792406922339-13548-nonuniformresourceindex-swap-miscompile-fixe.md)). Per-release status: [[wiki/concepts/slang-tooling-release-tarball-repro-and-version-bisect.md]].

**A null data type means void.** `emitInstResultDecl` returns early when `inst->getDataType()` is null, the legitimate void marker (`emitStore`/`emitReturn` build insts with nullptr type). A value-producing inst built with a null type makes every text emitter print `expr;` with uses of an undeclared `_Sn`, undiagnosed (`-validate-ir` checks a type only when present). In #13380 / PR #13381 the VectorReshape peephole passed `as<IRVectorType>(scalarType)` (null) to `emitSwizzle`; only WGSL broke (only its std140 policy packs scalar arrays into `vec4` and reads back via `vectorReshape`). `-dump-ir` tell: `let %N : _ = ...`. The fix is `SLANG_RELEASE_ASSERT(type)` in `IRBuilder::emitSwizzle` (`SLANG_ASSERT` becomes `SLANG_ASSUME` in Release); for vector→scalar reuse `emitVectorReshape` ([a null data type means void to the C-like emitters](../learnings/1790912037059-slang-ir-a-null-data-type-means-void-to-the-c-like.md)).

**Self-referential pointer structs: break the cycle at the pointer.** `struct N { float v; N* next; }` reached through a pointer first (`cbuffer C { N* p; }`) aborts with E99997 `circularity during codegen` on every source target since at least v2025.1; direct SPIR-V uses `OpTypeForwardPointer` (#13396). `computeEmitActions` orders declarations by DFS; the `kIROp_PtrType` arm of `ensureInstOperandsRec` relaxes to ForwardDeclaration only when the pointee is already open (N→Ptr(N), not Ptr(N)→N→Ptr(N)). When it fires it downgrades all the pointer's operands, so an IntLit reaches `SLANG_UNREACHABLE` in `emitForwardDeclaration` (the symptom when the struct is reached first). The prototyped fix forward-declares the pointer on the cycle and schedules its definition after the pointee closes. Deferring the pointee is wrong: GLSL rejects `struct N;` (that variant broke 11 via-GLSL tests), whereas `layout(buffer_reference) buffer BufferPointer_N;` is legal. `CPPSourceEmitter::_emitForwardDeclarations` filters by op and must allow any new case; WGSL (no forward declarations) needs separate handling. To dump the cycle without gdb, add a temporary `openStack` to `ComputeEmitActionsContext` and print op names at the circularity check ([self-referential pointer structs crash every source target](../learnings/1790943808591-c-like-emit-ordering-self-referential-pointer-stru.md)).

**A literal's type is never scheduled for declaration.** The early `if (as<IRPtrLit>(inst)) return;` in `ensureGlobalInst` (#3561) skips the literal and its type. Harmless while the literal never named its type, but GLSL now spells it `BufferPointer_X(0UL)`, so a pointer type reachable only through a null literal is undeclared and glslang fails "no matching overloaded function". Consider `float4* f = nullptr; out = int(uint64_t(f));` with nothing else of type `float4*`. The fix (#14088) calls `ensureInstOperand(ctx, inst->getFullType())` there, gated to `SourceLanguage::GLSL` so other targets are unchanged. To catch the class, test a literal whose type has no other user [CLikeSourceEmitter::ensureGlobalInst skips an IRPtrLit's type — a pointer type used only by a null literal is never declared](../learnings/1793335984103-clikesourceemitter-ensureglobalinst-skips-an-irptr.md).

**A discarded atomic result still gets a named temp, and a generic skip in `emitInstResultDecl` is unsafe (#14058).** A discarded atomic RMW result has 0 uses at emit, but the atomic branch of `tryEmitInstStmtImpl` on Metal, GLSL, CUDA and WGSL still calls `emitInstResultDecl`; HLSL hand-rolls `T name; InterlockedX(dst, v, name)`. Metal flags the temp `-Wunused-variable`; nvcc is silent. Skipping the decl for every 0-use inst is wrong: SwizzleSet (~3453) and UpdateElement (~3530) write to `name` after the decl; GetDimensions, the AtomicLoad deref, the Metal image `….x` and WGSL `atomicCompareExchangeWeak(...).old_value` would leave non-call expression statements (clang `-Wunused-value`; hard errors in WGSL); and it never reaches the HLSL atomics. Gate each atomic path on non-debug uses and drop the texture `.x` too. The fix later added `hasNonDebugUse` to `slang-ir-util` (see [emitter result-unused checks](slang-compiler-unsupported-shape-checks-and-emitter-use-checks.md)); PR #14044 adds a Metal `emitAtomicCall(…, bool returnsValue)` with this skip path. DeepWiki wrongly claims `emitInstStmt` already skips the temp; check emitted text [C-like emit: 0-use atomic results still get a named temp; a generic skip in emitInstResultDecl is unsafe](../learnings/1793312005041-c-like-emit-0-use-atomic-results-still-get-a-named.md).

**Discarded non-void calls get the same never-read temp (#14058 rescope).** Every C-like target binds a 0-use `IRCall` (`int _S2 = setA_0(...)`), which Metal flags. `(void)f()` does not help: `CastToVoid` is dropped in lowering (`slang-lower-to-ir.cpp` ~1008), leaving 0 uses. The safe shape skips `emitInstResultDecl` in `_emitInst`'s default branch for an `IRCall` with no non-debug use, not inside `emitInstResultDecl`. Traps: intrinsic template expansions (`slang-intrinsic-expand.cpp`) are wrapped in `( … )` and can be casts, `.x` swizzles or derefs, so C-family targets need `(void)(…)` to avoid clang `-Wunused-value` (ordinary-name and `.name` intrinsics and user callees are plain calls); WGSL accepts only a bare call_phrase as a statement and `subgroup*`, `textureLoad`, `frexp`, `modf`, `bitcast` are `@must_use`, so keep the binding there or emit `_ = …;`. `RWTexture.Load` is `[__readNone]` but keeps 0 uses because RW resources are not value types (`areCallArgumentsSideEffectFree`) [discarded non-void calls: gate in _emitInst's default branch, keep WGSL's binding](../learnings/1793616502734-discarded-non-void-calls-gate-in-emitinst-s-defaul.md).

**Switch case labels share `emitSimpleValueImpl`, so an out-of-range literal spelling becomes a hard error.** `CLikeSourceEmitter::emitSwitchCaseSelectorsImpl` (~3697) prints each case value via `emitOperand` → IntLit `FoldPolicy::Always` → `emitSimpleValue`. INT64_MIN as `-9223372036854775808LL` (#14155) only warns in an assignment (clang `-Wimplicitly-unsigned-literal`, Metal `-Wconstant-conversion`), but `case -9223372036854775808LL:` fails in nvrtc (narrowing), dxc ("case value is not a constant expression"), LLVM host-callable (narrowing) and glslang via the GLSL override (`...L`). Add a `switch` repro to see a literal bug's real severity. GPU-free downstream checks: `-target ptx` (nvrtc), `-target dxil -profile cs_6_0` (dxc), `-target spirv -emit-spirv-via-glsl` (glslang), `-target host-callable` (LLVM), `-target shader-sharedlib` (gcc) [switch case labels share emitSimpleValueImpl](../learnings/1793614607788-slang-c-like-emit-switch-case-labels-share-emitsim.md).

## Memory-qualifier-drop diagnostic (E30048): a positive destination-type check is required

A checker diagnostic at a binding/copy boundary (E30048, #13084) cannot be gated only on "no new error after `coerce`". An ill-formed destination (`UndefinedType x = coherentBuf;`) emits its resolution error in the header phase, already in the body-phase baseline; `coerce()` accepts the `ErrorType` target silently, so E30048 fires spuriously (verified for `int x = coherentBuf;` and `UndefinedType x = coherentBuf;`). The fix also requires the destination type to be a resource handle. `isOpaqueHandleType(Type*)` is broader than "read/write memory resource" (samplers, parameter groups, acceleration structures, patch/stream/mesh I/O), so use a dedicated predicate listing exactly the coherent read/write handle types. The three var-init/assignment paths are asymmetric: `checkVarDeclCommon` (explicit init) and `checkAssignWithCheckedOperands` carry the `isWriteOnly` → `ReadingFromWriteOnly` (E30119) check, but `deriveVarTypeFromInitExpr` (type-inferred `var x = ...`) does not, so a `writeonly` source gives E30119 on two paths but E30048 (or nothing) on the third; it also assigns `varDecl->type.type` late, so a destination-type check there must follow that. Codex CODE_REVIEW caught all of these after a peer APPROVE_WITH_NITS, so run codex even after peer approval, on the full small file (a truncated excerpt caused a false must-fix) ([Memory-qualifier-drop diagnostic: destination-type check needed beyond an error-count gate](../learnings/1789543242916-memory-qualifier-drop-diagnostic-destination-type-.md)).
