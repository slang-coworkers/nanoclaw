# Slang Compiler: Type-Flow ExtractExistential, Gate-Relaxation Discipline, and 2026-07-17 Operational Fold

Covers the dynamic-dispatch type-flow specialization pass (`slang-ir-typeflow-specialize.cpp`), relaxing a diagnostic gate, and folded approver/operational notes. Set-specialized generics, the #13817 E33180 diamond and `analyzeCall` callee lifetime are on [Type-Flow Set-Specialization Diamonds](slang-compiler-type-flow-set-specialization-diamonds.md).

## TL;DR
- **Type-flow `ExtractExistential` ICEs (#12934/#13046/#13259) are fixed at the PRODUCER (merged PR #12935):** lowered info written back onto data types was read as concrete and re-wrapped by `makeInfoForConcreteType`; the fix is `if (isRefinedInfoType(type)) return type;` at its TOP. Consumer-side acceptance emits ill-typed code.
- **Put a "don't re-wrap" guard at the single construction chokepoint**, not at a caller and not as an entry assert.
- **A producer fix can SUPERSEDE a consumer PR for a whole crash family**; run the sibling issue's own regression on your build first.
- **Build an "already refined" predicate from what `getLoweredType` writes onto data types**, not from `tryGetInfo`'s info set.
- **Simulate a candidate typeflow fix with gdb before rebuilding; find the shapes that really occur by instrumenting, not reading.**
- **"Emission succeeded" is not "valid":** verify typeflow changes with `-target dxil` and `SLANG_RUN_SPIRV_VALIDATION=1 -target spirv` (CI sets it; set it locally too).
- **An assert-backed invariant is no soundness proof:** interrogate the shape a guard ACCEPTS, not only the one it rejects.
- **Before dispatching a fix for an ICE in a known crash family, apply the open sibling PR's real diff, re-run the repro, and re-fetch its review state**; never write "green once #N lands" without applying #N.
- **A freshly built slangc's `-v` is a stale git-describe tag**; identify a master binary by crash-site line numbers.
- **No-GPU container: CUDA/VK runtime tests flake under a high `-server-count`**; exclude CUDA and rerun VK serially.
- **`s_dispatch_*` and `*_wtwrapper*` are force-inlined only from v2026.18.2 (#12924)**; the ID→tag mapping function never is. DeepWiki is stale on both.
- **`[__specializePerConformance]` (open PR #13387) helps only when the whole consumer of the dynamic object is inside the attributed helper**; compare SASS counts, not timings.
- **A CPU-bound compile "hang" in `bwd_diff` on a non-unrollable interface-typed loop is a target-specialization fixpoint (#13169), not autodiff**; make the lowering idempotent, don't cap iterations.
- **Before relaxing a diagnostic gate, git-blame it AND grep the tests for one that PINS it**; gate on entry-point reachability.
- **`SLANG_ASSERT` becomes `SLANG_ASSUME` under NDEBUG, so a false release assert is UB**; read internals at a named ref before citing them.
- **Peel-walker guards: probe the peel-set against ALL later passes, then prove the failure direction from the FALLTHROUGH root's real type.**
- **Clear a new `SLANG_RELEASE_ASSERT` when an unguarded sibling arm already relies on the same helper and the failure is a loud abort**; abstain only with a shown producer.
- **capdef `def` accepts a top-level `|` disjunction but NOT a parenthesized `(b|c)` inside a conjunction.**
- **A `meta.slang` `$(kIROp_X)` splice uses the CAPITALIZED enum name, not the lua key.**
- **`analyzeMakeStruct` positional OOB is LATENT** (producers keep operand==field parity); assert it, don't min-bound.
- **Prove a witness `substitute()` is load-bearing with a revert-drill**, on a case whose resolved value varies with the generic argument.
- **`createGlobalSession` RSS ≈ `g_coreModule` blob size**; measure it via `nm` on libslang.

## Type-flow ExtractExistential ICEs: the merged fix is at the producer (PR #12935)

The pass (PR #7968) has three sibling analyzers that extract components from an existential's propagated "info": `analyzeExtractExistentialType` (~:3781) and `analyzeExtractExistentialWitnessTable` (~:3746) accept only COM-interface and `IRTaggedUnionType` info and `SLANG_UNEXPECTED` otherwise, while `analyzeExtractExistentialValue` (~:3817) returns `none()`. Reaching an existential-returning helper through dynamic dispatch over ≥2 conformances (`createDynamicObject` + two `-conformance`, often via the autodiff `IRDifferentialPairType` union) throws `E99997 Unhandled info type in analyzeExtractExistentialType` (#12934, Falcor2 `scene_test`; either conformance alone compiles). `-dump-ir` goes to stderr; prior pass: `specializeModule` [ExtractExistential Type/WitnessTable analyzers crash where the Value sibling tolerates the info](../learnings/1788817368144-slang-type-flow-extractexistential-type-witnesstab.md).

Mirroring the Value sibling in the consumers removed the crash but emitted code DXC, spirv-val and nvcc rejected; the cause is upstream. Each `specializeDynamicInsts` run writes lowered info (`TaggedUnionType`, multi-element `UntaggedUnionType`, `SetTagType`) back onto data types and declared result types, and `isConcreteType` (~:585-602 @ a90dfa311) has no union case, so it returns true through `default`. From fixpoint iteration 2, `updateFuncReturnInfo` skips recording the callee's return info and the FuncToCall fallback in `propagateInterproceduralEdge` (~:2158-2176) calls `makeInfoForConcreteType(TaggedUnion, Interface)`. Its entry `SLANG_ASSERT(isConcreteType(type))` wrongly passes, its bottom fallthrough (~:704-706) builds `UntaggedUnion(TypeSet(TaggedUnion(...)))`, and `analyzeExtractExistentialType`'s happy path (~:3778) matches only a bare `IRTaggedUnionType`, so it hits `SLANG_UNEXPECTED`. #13046 is an autodiff-free trigger of the same root; `[__unsafeForceInlineEarly]` is a user-side workaround ([producer-side root: isConcreteType lacks a union case](../learnings/1789325428139-analyzeextractexistentialtype-ice-has-a-producer-s.md)). Merged PR #12935 (e6be8dcdd7, 2026-10-05) makes `makeInfoForConcreteType` return refined info unchanged via `isRefinedInfoType` before any structural matching; `tryGetInfo` uses the same predicate. Repro: call the interface-returning function from the entry point and reach a second call site only via an `IGeometry.intersectAndAccept`-style default method over 2 conformances; for an A/B swap only this .cpp (~1 min rebuild) and gate on DXC, SPIR-V validation and `nvcc -c` [info re-read as a concrete declared type; merged producer fix](../learnings/1791210427063-type-flow-fixpoint-info-re-read-as-a-concrete-decl.md).

The guard belongs at the construction chokepoint. A guarded fallback plus an entry `SLANG_ASSERT(!isRefinedInfoType(type))` is incomplete: a nested refined return (`IAccessor[1]`, tuple) passes `isConcreteType` at the top level and the structural recursion then hard-aborts on the refined element. Because the structural cases recurse through `makeInfoForConcreteType`, one guard at its top covers both, matching `tryGetInfo`'s "refinement occurred in a previous phase; reuse directly" rule. This producer fix superseded #12935's consumer-guard revision for the whole family: that guard only relocated #13046 (its singleton branch re-asserted at `slang-ir-specialize-function-call.cpp:246`), while the producer fix passes #12934's own regression with no consumer guard. If the sibling test passes on your build, recommend supersede and carry the test forward. Codex CODE/PLAN critique caught both, so run it on IR-pass fixes even when tests are green ([fix the double-wrap at the construction chokepoint (#13046)](../learnings/1789331744961-typeflow-refined-info-double-wrap-fix-at-the-const.md)).

The data-type predicate is not `tryGetInfo`'s info op set ({TaggedUnion, UntaggedUnion, ElementOfSet}): `getLoweredType` rewrites `ElementOfSetType` to `SetTagType` and a singleton `UntaggedUnionType` to its bare element, and keeps `TaggedUnionType` and multi-element `UntaggedUnionType`. It must precede the structural cases: `Optional<Interface>` lowers to a bare `TaggedUnionType` return while call sites keep `Optional<I>` ([what getLoweredType writes](../learnings/1790416309401-typeflow-re-wrap-12935-what-getloweredtype-actuall.md)).

## Debugging the pass: gdb simulation, instrumentation, local verification

Try a candidate fix under gdb on the Debug build instead of a 20-minute rebuild: `set breakpoint pending on` (libslang-compiler.so loads late), `break slang-ir-typeflow-specialize.cpp:705 if type->m_op == Slang::kIROp_TaggedUnionType` with `commands` `return (Slang::IRInst*)type` / `continue`, then `printf "EXITCODE=%d\n", $_exitcode` after `run`. `call ((Slang::IRInst*)$f)->dump()` at `Slang::specializeDynamicInsts` entry shows each iteration; operand i is `((Slang::IRUse*)((Slang::IRInst*)x + 1))[i].usedValue`. `slang-test tests/language-feature/dynamic-dispatch` runs with the override in ~2 min ([gdb-simulate note](../learnings/1790408655536-slang-typeflow-simulate-a-candidate-fix-with-gdb-i.md)). A `thread_local` caller tag + depth counter logging which shapes reach `makeInfoForConcreteType` over a `slang-test -use-test-server` run exposed an undocumented `UntaggedUnionType` pass-through in three existing tests. CUDA/VK runtime tests flake under `-server-count 48` here (identical runs: 294 vs 101 failures); numerics tests need the standard-module targets built ([local verification note](../learnings/1790416309401-typeflow-re-wrap-12935-what-getloweredtype-actuall.md)).

DXC is bundled at `build/<cfg>/lib/libdxcompiler.so`, so `-target dxil` runs in the container. `//TEST:SIMPLE -target spirv-asm` + `CHECK: OpEntryPoint` tests catch ill-typed codegen only with `SLANG_RUN_SPIRV_VALIDATION=1`, which `ci-slang-test.yml` exports and local runs usually lack ([gdb-simulate note](../learnings/1790408655536-slang-typeflow-simulate-a-candidate-fix-with-gdb-i.md); [local verification note](../learnings/1790416309401-typeflow-re-wrap-12935-what-getloweredtype-actuall.md)).

## The #13259/#13261 follow-ons: apply the open sibling PR, then test what the guard accepts

#13259 (`...WitnessTable`) looked like a new trigger. Applying open PR #12935 (`gh pr diff 12935 > p; git apply -3 p`), rebuilding and re-running the repro gave rc=0 on spirv/hlsl/cuda with SPIR-V validation clean: "covered by #12935; add the regression", not a fresh dispatch. The HEAD-built slangc reported `-v` 2026.13.1-50-g… ([apply the open sibling PR and re-run the repro](../learnings/1790318063820-before-dispatching-a-fix-for-an-ice-in-a-known-cra.md)).

#12935 was not idle and mergeable but in CHANGES_REQUESTED: the reviewer feared the WitnessTable arm's `none()` relocates the crash for a concrete-struct payload. #13259's untagged-arm hit sat on a dead (DCE'd) path with an inner TaggedUnion payload, the side the existing test already covered, so offering it as the resolving test would have overclaimed; distinguish *removed before lowering* from *survived but lowered*, and live from dead extractions. Ops: the `--depth 50` base clone gives an empty `git merge-base origin/master HEAD` until `--unshallow`; fast-forward rather than force-push over live review threads; bare `extras/formatting.sh` is a no-op ([untagged-union witness-table arm](../learnings/1790319855433-untagged-union-witness-table-arm-assert-the-emerge.md)). The fixer then encoded an emergent invariant (the only `UntaggedUnionType` reaching the arm is a singleton wrapping a `TaggedUnionType`) as `SLANG_RELEASE_ASSERT(isSingleton() && as<IRTaggedUnionType>(getElement(0)))`. A human's repro compiled with rc=0 to HLSL, SPIR-V and CUDA without firing it, yet DXC rejected the HLSL, SPIR-V validation failed, and the CUDA dispatcher took the tagged-union tuple as its receiver instead of the AnyValue payload: `none()` had turned an ICE into invalid codegen, and `UntaggedUnion(singleton(TaggedUnion))` is the double wrap the producer fix removes ([emission succeeded is not valid](../learnings/1790404907441-emission-succeeded-is-not-valid-run-spirv-val-and-.md)). Nobody had asked whether untagged-wrapping-tagged is principled. Before approving a public soundness reply to a CHANGES_REQUESTED review, require validated DXIL/SPIR-V for constructed nearby shapes (callbacks, two-consumer factories, dispatch receivers) and a fresh read of the PR comments (the counterexample's webhook went to a sibling session) ([assert-backed invariant needs validated nearby shapes and a PR re-read](../learnings/1790405042503-an-assert-backed-invariant-must-be-tested-on-valid.md)).

#13261 shows where that revision stopped. `let v = createDynamicObject<IFactory>(k,0).make(n)` returns an associated type, and `v is T` / `v as T` fold to false: the checker opens an existential only when the static type is literally an `InterfaceDecl` (`isInterfaceType`, slang-check-decl.cpp:2145; `visitIsTypeExpr`/`visitAsTypeExpr`), so an interface-bound `AssocTypeDecl` falls through to a static `kIROp_TypeEquals` and `_isTypeParametric` suppresses the diagnostic. Fixing the checker reaches type-flow and #12934's ICE; #12935's diff on top still ICEs at `slang-ir.h(861): !inst || as<T>(inst)` via `GetTypeTagFromTaggedUnion`, because `none()` expects refinement to a singleton and two distinct runtime types never refine. The miscompile needs ≥2 concrete types, so the front-end half has no ICE-free regression test on master (single-conformance shapes were never wrong). A same-file, same-mechanism PR can be necessary but insufficient ([verify a "green once PR X lands" dependency by applying X's diff](../learnings/1790318063842-verify-a-green-once-pr-x-lands-dependency-by-apply.md)).

## What dynamic-dispatch lowering inlines (#12924) and what `[__specializePerConformance]` changes (#13387)

On the 2026.17.1/2026.18.2 Linux binaries and master 6eb89786c: before 2026.18.2, `s_dispatch_*` and `*_wtwrapper*` carry no inline marking and stay as calls; `[ForceInline]` on the user's default implementation only inlines it into the wrapper. From 2026.18.2 (PR #12924, 76d3f1416), `addForceInlineDecoration` marks the wrapper (`slang-ir-lower-dynamic-dispatch-insts.cpp:195`) and dispatcher (`:303`) except on CPU-via-LLVM, and `performForceInlining` (`slang-emit.cpp:1839`) runs before `eliminatePhis` and `simplifyForEmit`, so the concrete MakeStruct reaches the caller per field. The ID→tag mapping function from `createIntegerMappingFunc` (`:409`, GetTagFromSequentialID at `:942`) is still not inlined on master: `createDynamicObject<I>(constId, …)` inside `[ForceUnroll]` emits `uint t = _S16(0U); switch (t) {…all arms…}` per iteration. Check: `gh release download vX -R shader-slang/slang -p 'slang-X-linux-x86_64.tar.gz'`, then `grep -c 's_dispatch.*('` the `-target cuda` output ([s_dispatch_*/wtwrapper survive as calls before v2026.18.2](../learnings/1790405268841-dynamic-dispatch-s-dispatch-wtwrapper-survive-as-c.md)).

Open PR #13387's `[__specializePerConformance]` (head b379e75, #13245 repros, ptxas 12.6 sm_75) emits one dispatch switch to per-conformer copies of the attributed generic helper and drops the associated-result `AnyValue` box, but only when the whole consumer is inside that helper. A helper returning the interface (`IHit`/`IProperties`) is byte-identical to the existing "IHit return" mode, direct `createDynamicObject<I>(id,0).method(p)` is byte-identical with and without the PR, and the public-ID→tag remap switch survives everywhere (#13220). The larger #13245 Gist files give the compact repro's cubins, so their timing gaps come from compiler version or the SlangPy route. Count SASS with `slangc -target ptx -O3` → `ptxas -arch=sm_75 -O3 -v` → `cuobjdump -sass | grep -cE '^\s+/\*[0-9a-f]{4}\*/'`; render-test ignores `-entry`, so CPU value checks need the entry named `computeMain` ([`[__specializePerConformance]` helps only when the whole consumer is inside the helper](../learnings/1791193003985-slang-specializeperconformance-pr-13387-helps-only.md)).

## A `bwd_diff` ".bwds() hang" is a target-specialization fixpoint, not autodiff (#13169)

A reverse-mode `bwd_diff`/`.bwds()` hang on a `[Differentiable]` runtime-bound loop reading an interface-typed differentiable view (`IDiffTensor`/`DiffTensorView`; SlangPy #1167 → slang#13169) was blamed by four agents on the reverse-loop counter in `slang-ir-autodiff-primal-hoist.cpp`. gdb on the live, CPU-bound (GPU 0%) compile pinned it after autodiff, in `linkAndOptimizeIR`: `SpecializationContext::processModule`'s `for(;;)` (`slang-ir-specialize.cpp:1832`, exit `:1904` on `!iterChanged`) never converges because `performDynamicInstLowering` re-reports a change every round on a loop-carried phi typed `TagType(IRWitnessTableSet)` feeding a set-specialized `IRSpecialize`, a shape `_resolveInstRec` excludes from `resolvedStructuralFixedPoints` as non-monotonic (`slang-ir-translate.cpp:514-517`). Owner is typeflow (jvepsalainen-nv). The hot frames (`performInformationPropagation`/`_resolveInstRec`/`getIntValue`) are the time sink, not the change driver ([#13169: an autodiff 'hang' was a type-flow fixpoint](../learnings/1789722972530-slang-13169-a-reverse-mode-autodiff-hang-was-actua.md)).

Discriminators: the hang is compile-time and CPU-bound; an unrollable loop (`i<5`, `[ForceUnroll]`; `unrollLoopsInModule` warns E30519) converges into finite concrete witness tables while a `[MaxIters]`-only runtime loop over an interface never idempotents; the forward pass is fine, with no ICE and no wrong gradient. The GPU-free repro (~55 lines, no `import slangpy`) is `slangc -target cuda` on an `interface ITensorView { [Differentiable] float read(...); }` read in a `[MaxIters(n)]` `[Differentiable]` loop under `bwd_diff`; earlier failed repros modeled the autodiff shape, so check you model the right pass. Make the set-specialized `Specialize`/witness-table-set lowering idempotent; a bare iteration cap masks and risks miscompile. Have gdb LAUNCH slangc (`ptrace_scope=1`) and `kill -INT` the gdb pid so a queued `-ex bt` fires. `import "slangpy"` + `bwd_diff` hangs bare slangc earlier at `diagnoseCircularConformances`, a separate confound. Check "window straddles X" claims with `git merge-base --is-ancestor`. Not #13000 (wrong gradient) ([discriminators and repro](../learnings/1789723591195-a-bwd-diff-bwds-hang-on-an-interface-typed-non-unr.md)).

## Before relaxing a compiler gate, grep the tests that PIN it (#12486)

Fixing "empty existential passed to a helper ICEs instead of a clean E50100" (#12486) by deleting the entry-point-only gate in `diagnoseUnresolvedLookupWitnesses` (`slang-ir-typeflow-specialize.cpp:3477`) and keeping only the zero-conformance gate (`collectExistentialTables(...).getCount()==0`, :3502) breaks `tests/diagnostics/no-type-conformance-nested-interface.slang:46-63`, whose never-called, zero-conformance `unusedHelper(IUnused)` must get no E50100. The fix also gates on entry-point reachability through resolvable direct calls: reachable + zero-conformance (the `useDyn` repro) → diagnose (was ICE); unreachable + zero-conformance → skip; reachable + ≥1 conformance (slangpy `write_arg(IPrintable)`) → skip via the count gate. Reachability is a valid proxy for "reaches codegen" because `eliminateDeadCode` (`slang-ir-specialize.cpp:1729`) runs before `specializeDynamicInsts`→`diagnoseUnresolvedLookupWitnesses` (:1760); reuse the `getResolvedCalleeFunc` BFS in `slang-ir-legalize-varying-params.cpp`. A triage's "just delete the gate" fix can be provably wrong [#12486: the E50100 entry-point gate is pinned by a test](../learnings/1786495950035-slang-12486-the-e50100-entry-point-gate-is-pinned-.md).

## Approver and operational learnings (fold 2026-07-17)

**Peel-walker guards (#11152 → #12119).** #11152 guarded the CUDA immutable→`__ldg` rewrite with `getRootAddr(load->getPtr())->getOp() != kIROp_GetOptiXSbtDataPtr`. `getRootAddr` (slang-ir-util.cpp:936) peels only {GetElementPtr, FieldAddress, NodeOutputRecordGetElementPtr}, and buffer element-type legalization (`lowerBufferElementTypeToStorageType`, e.g. bool or 16-bit SBT members) inserts `BitCast`/`GetOffsetPtr` before the root, so the approver's WOULD_APPROVE was a false-safe; the author superseded it with #12119. A root-op guard is complete only if the walker covers every pointer-forwarding op ANY later pass can splice in, not just the tested shapes ([false-safe: probe the peel-set against ALL later passes](../learnings/1784120041393-approver-false-safe-guard-keyed-on-getrootaddr-s-o.md)). Completeness is necessary but not sufficient; the second probe is what the fallthrough returns for each op the walker does not peel. On #12119 the SBT walker peels a superset of `getRootAddr` and a UserPointer `BitCast` falls through to "mutable" (no `__ldg`); record which axis carried the decision ([challenger-miss: op-set completeness AND failure direction](../learnings/1784123729267-approver-challenger-miss-for-a-peel-walker-guard-v.md)). The failure-direction proof must use the fallthrough root's actual type: a missed `kIROp_PtrCast` leaves the `ConstantBuffer<>`-typed `GetOptiXSbtDataPtr` root, which lowers to `AddressSpace::Uniform`, which `isPointerToImmutableLocation` calls immutable, the unsafe answer. The decision moved WOULD_APPROVE → ABSTAIN_POLICY (OPEN_GAP), not BLOCK, because `git grep` found no source producer of `PtrCast` ([critique-mustfix: check the FALLTHROUGH type](../learnings/1784180537337-approver-critique-mustfix-failure-direction-proof-.md)).

**Clearing a new `SLANG_RELEASE_ASSERT` (#12127).** A new `SLANG_RELEASE_ASSERT(storedType)` on `tryGetPointedToType(getPtr())` in the HostVM `kIROp_Store` arm was flagged as a possible abort on ComPtr/NativePtr. Clear it as advisory when unguarded sibling arms in the file (`kIROp_Var`, `GetElementPtr`, `FieldAddress`, `GetOffsetPtr`) already rely on the same helper over the same operands AND the failure is a loud abort. Abstain only when you can show the op that produces the flagged shape; in #11152 the missed op was reachable and the failure silent ([challenger-win: sibling-arm precedent + failure direction](../learnings/1784148942373-approver-challenger-win-clearing-a-new-slang-relea.md)).

**`analyzeMakeStruct` OOB is latent (#12132).** `analyzeMakeStruct` (~L2260-2283) reads `makeStruct->getOperand(i)` bounded by `structType->getFields()`, unchecked against `getOperandCount()` (`slang-ir.h:711` asserts). No producer under-supplies it: DCE `trimMakeStructOperands` (`slang-ir-dce.cpp:404-433, 472-483`) removes field and operand together, varying-params legalization (`slang-ir-legalize-varying-params.cpp:3989, 4002`) builds a fresh one-field struct, and autodiff `translateMakeStruct` already release-asserts the same pattern (`slang-ir-autodiff-fwd.cpp:907`). Assert operand==field count at the consumer rather than bound with `min`. DeepWiki found the paths, not that they preserve parity ([analyzeMakeStruct OOB is LATENT](../learnings/1784171101845-slang-analyzemakestruct-positional-oob-is-latent-m.md)).

**Revert-drill for a witness `substitute()` (slang#9580 / PR #12131).** Neuter `val->substitute(astBuilder, SubstitutionSet(declRef))` to `SubstitutionSet()`, rebuild, and check the target case breaks; if it still passes, a coverage test overclaims. A value-generic wrapper (`struct SolidMode<let N:int> : IShaderMode { typedef ColorOutput FragOut; }`) does not exercise it: the resolved type ignores `N` ([revert-drill for a witness substitute()](../learnings/1784176407848-revert-drill-to-prove-a-witness-substitute-is-load.md)).

**capdef disjunctions (#12097).** `def` and `alias` inheritance both go through `parseExpr()`, which accepts DNF top-level `|` (`def X : a + b | a + c;`); `parseConjunction()` joins only bare identifiers, so `def X : a + (b | c);` fails with `error 20001: unexpected (, expected identifier`, and you distribute it by hand. Verify with `slang-capability-generator <capdef> --target-directory <dir>`; test the exact spelling you claim fails before telling a maintainer ([capdef: top-level | yes, parenthesized (b|c) no](../learnings/1784126862980-capdef-def-inheritance-accepts-top-level-disjuncti.md)).

**meta.slang op splices.** A new op with a lowercase lua key (`imageGatherOffset`) generates `kIROp_ImageGatherOffset`. `__intrinsic_op($(kIROp_...))` splices and C++ `case kIROp_...:` use the capitalized enum, while `slang-ir-insts-stable-names.lua` uses the lua key; the lua-key spelling breaks the core-module embedding compile. Check `build/source/slang/fiddle/slang-ir-insts-enum.h.fiddle` ([meta.slang splice uses the CAPITALIZED enum name](../learnings/1784168350681-meta-slang-kirop-x-splice-must-use-the-capitalized.md)).

**createGlobalSession RSS (#12113).** `createGlobalSession()` eagerly deserializes the embedded core module, so baseline RSS tracks the `.rodata` symbol `g_coreModule` in libslang.so nearly 1:1 (v2026.5→v2026.7: 4.73→9.29 MiB, peak RSS 96.7→187.1 MiB). Compare release tarballs with `nm --print-size --size-sort --radix=d`. If `*.meta.slang` is flat and the serializer files are unchanged, the compiler synthesizes more core-module IR (suspect: autodiff refactor #9808); bisect by building only the bootstrap at in-window commits ([createGlobalSession RSS ≈ g_coreModule size](../learnings/1784096601212-slang-createglobalsession-rss-g-coremodule-blob-si.md)).
