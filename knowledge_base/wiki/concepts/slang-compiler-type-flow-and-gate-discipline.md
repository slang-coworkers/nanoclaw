# Slang Compiler: Type-Flow ExtractExistential, Gate-Relaxation Discipline, and 2026-07-17 Operational Fold

Covers the dynamic-dispatch type-flow specialization pass (`slang-ir-typeflow-specialize.cpp`), relaxing a diagnostic gate, and folded approver/operational notes. Set-specialized generics, the #13817 E33180 diamond, `analyzeCall` callee lifetime, and the specialize-pass mechanics of the #13387 extension-method rework are on [Type-Flow Set-Specialization Diamonds](slang-compiler-type-flow-set-specialization-diamonds.md).

## TL;DR
- **Type-flow `ExtractExistential` ICEs (#12934/#13046/#13259) are fixed at the PRODUCER (merged PR #12935):** lowered info on data types was re-wrapped by `makeInfoForConcreteType`; the fix is `if (isRefinedInfoType(type)) return type;` at its TOP. Consumer-side acceptance emits ill-typed code.
- **Put a "don't re-wrap" guard at the single construction chokepoint**, not at a caller and not as an entry assert.
- **A producer fix can SUPERSEDE a consumer PR for a whole crash family**; run the sibling's regression on your build first.
- **Build an "already refined" predicate from what `getLoweredType` writes onto data types**, not from `tryGetInfo`'s info set.
- **Simulate a candidate typeflow fix with gdb before rebuilding; find the shapes that really occur by instrumenting, not reading.**
- **"Emission succeeded" is not "valid":** verify typeflow changes with `-target dxil` and `SLANG_RUN_SPIRV_VALIDATION=1 -target spirv` (CI sets it).
- **An assert-backed invariant is no soundness proof:** interrogate the shape a guard ACCEPTS, not only the one it rejects.
- **Before dispatching a fix for an ICE in a known crash family, apply the open sibling PR's diff, re-run the repro, and re-fetch its review state**; "green once #N lands" needs #N applied.
- **A freshly built slangc's `-v` is a stale git-describe tag**; identify a master binary by crash-site line numbers.
- **No-GPU container: CUDA/VK runtime tests flake under a high `-server-count`**; exclude CUDA and rerun VK serially.
- **`s_dispatch_*` and `*_wtwrapper*` are force-inlined only from v2026.18.2 (#12924)**; the ID→tag mapping function never is. DeepWiki is stale on both.
- **Passing an interface-typed field by address (`inout`/`out`/borrow/ref) mixes existential layouts (#14152):** typeflow retypes the address but not the storage. slangc exits 0 with invalid code; verify with dxc/glslang/nvrtc/spirv-val; copy into a local.
- **`[__specializePerConformance]` (open PR #13387) helps only when the whole consumer is inside the attributed helper**; compare SASS counts, not timings.
- **A CPU-bound `bwd_diff` compile "hang" on a non-unrollable interface-typed loop is a target-specialization fixpoint (#13169), not autodiff**; make the lowering idempotent, don't cap iterations.
- **Before relaxing a diagnostic gate, git-blame it AND grep for a test that PINS it**; gate on entry-point reachability.
- **`SLANG_ASSERT` is `SLANG_ASSUME` under NDEBUG, so a false release assert is UB**; cite internals at a named ref.
- **Peel-walker guards: probe the peel-set against ALL later passes, then prove the failure direction from the FALLTHROUGH root's real type.**
- **Clear a new `SLANG_RELEASE_ASSERT` when unguarded sibling arms rely on the same helper and the failure is a loud abort**; abstain only with a shown producer.
- **capdef `def` accepts a top-level `|` disjunction but NOT a parenthesized `(b|c)` inside a conjunction.**
- **A `meta.slang` `$(kIROp_X)` splice uses the CAPITALIZED enum name, not the lua key.**
- **`analyzeMakeStruct` positional OOB is LATENT** (producers keep operand==field parity); assert it, don't min-bound.
- **Prove a witness `substitute()` is load-bearing with a revert-drill**, on a case whose resolved value varies with the generic argument.
- **`createGlobalSession` RSS ≈ `g_coreModule` blob size**; measure it via `nm` on libslang.

## Type-flow ExtractExistential ICEs: the merged fix is at the producer (PR #12935)

The pass (PR #7968) has three sibling analyzers of an existential's propagated "info": the Type and WitnessTable ones accept only COM-interface and `IRTaggedUnionType` info and `SLANG_UNEXPECTED` otherwise, while `analyzeExtractExistentialValue` returns `none()`. Reaching an existential-returning helper through dynamic dispatch over ≥2 conformances (often via the autodiff `IRDifferentialPairType` union) throws `E99997 Unhandled info type in analyzeExtractExistentialType` (#12934, Falcor2 `scene_test`; either conformance alone compiles). `-dump-ir` goes to stderr [ExtractExistential Type/WitnessTable analyzers crash where the Value sibling tolerates the info](../learnings/1788817368144-slang-type-flow-extractexistential-type-witnesstab.md).

Mirroring the Value sibling in the consumers removed the crash but emitted code DXC, spirv-val and nvcc rejected. Each `specializeDynamicInsts` run writes lowered info (`TaggedUnionType`, multi-element `UntaggedUnionType`, `SetTagType`) back onto data types, and `isConcreteType` has no union case, so it returns true. From fixpoint iteration 2, the FuncToCall fallback in `propagateInterproceduralEdge` calls `makeInfoForConcreteType(TaggedUnion, Interface)`, whose entry assert wrongly passes and whose fallthrough builds `UntaggedUnion(TypeSet(TaggedUnion(...)))`, which `analyzeExtractExistentialType` does not match. #13046 is an autodiff-free trigger of the same root; `[__unsafeForceInlineEarly]` is a user-side workaround ([producer-side root: isConcreteType lacks a union case](../learnings/1789325428139-analyzeextractexistentialtype-ice-has-a-producer-s.md)). Merged PR #12935 (2026-10-05) makes `makeInfoForConcreteType` return refined info unchanged via `isRefinedInfoType` before any structural matching, the predicate `tryGetInfo` also uses. Repro: call the interface-returning function from the entry point and from a default method over 2 conformances; A/B by rebuilding only this .cpp (~1 min), gating on DXC, SPIR-V validation and `nvcc -c` [info re-read as a concrete declared type; merged producer fix](../learnings/1791210427063-type-flow-fixpoint-info-re-read-as-a-concrete-decl.md).

The guard belongs at the construction chokepoint. A guarded fallback plus an entry `SLANG_ASSERT(!isRefinedInfoType(type))` is incomplete: a nested refined return (`IAccessor[1]`, tuple) passes at the top level and the structural recursion aborts on the refined element. One guard at the top of `makeInfoForConcreteType` covers both, matching `tryGetInfo`'s "reuse refined info directly" rule. This producer fix superseded #12935's consumer-guard revision for the whole family: that guard only relocated #13046 (re-asserting in `slang-ir-specialize-function-call.cpp`), while the producer fix passes #12934's own regression. If the sibling test passes on your build, recommend supersede and carry the test forward. Codex critique caught both; run it on IR-pass fixes even when green ([fix the double-wrap at the construction chokepoint (#13046)](../learnings/1789331744961-typeflow-refined-info-double-wrap-fix-at-the-const.md)).

The data-type predicate is not `tryGetInfo`'s info op set: `getLoweredType` rewrites `ElementOfSetType` to `SetTagType` and a singleton `UntaggedUnionType` to its bare element, and keeps `TaggedUnionType` and multi-element `UntaggedUnionType`. It must precede the structural cases, since `Optional<Interface>` lowers to a bare `TaggedUnionType` return while call sites keep `Optional<I>` ([what getLoweredType writes](../learnings/1790416309401-typeflow-re-wrap-12935-what-getloweredtype-actuall.md)).

## Debugging the pass: gdb simulation, instrumentation, local verification

Try a candidate fix under gdb on the Debug build instead of a 20-minute rebuild: `set breakpoint pending on` (libslang-compiler.so loads late), `break slang-ir-typeflow-specialize.cpp:705 if type->m_op == Slang::kIROp_TaggedUnionType` with `commands` `return (Slang::IRInst*)type` / `continue`, and print `$_exitcode` after `run`. `call ((Slang::IRInst*)$f)->dump()` at `specializeDynamicInsts` entry shows each iteration; operand i is `((Slang::IRUse*)((Slang::IRInst*)x + 1))[i].usedValue`. The dynamic-dispatch test dir runs with the override in ~2 min ([gdb-simulate note](../learnings/1790408655536-slang-typeflow-simulate-a-candidate-fix-with-gdb-i.md)). Logging which shapes reach `makeInfoForConcreteType` (a `thread_local` caller tag) over a full slang-test run exposed an undocumented `UntaggedUnionType` pass-through in three tests. CUDA/VK runtime tests flake under `-server-count 48` here (identical runs: 294 vs 101 failures) ([local verification note](../learnings/1790416309401-typeflow-re-wrap-12935-what-getloweredtype-actuall.md)).

DXC is bundled at `build/<cfg>/lib/libdxcompiler.so`, so `-target dxil` runs in the container. `-target spirv-asm` + `CHECK: OpEntryPoint` tests catch ill-typed codegen only with `SLANG_RUN_SPIRV_VALIDATION=1`, which CI exports and local runs usually lack ([gdb-simulate note](../learnings/1790408655536-slang-typeflow-simulate-a-candidate-fix-with-gdb-i.md); [local verification note](../learnings/1790416309401-typeflow-re-wrap-12935-what-getloweredtype-actuall.md)).

## The #13259/#13261 follow-ons: apply the open sibling PR, then test what the guard accepts

#13259 (`...WitnessTable`) looked like a new trigger. Applying open PR #12935 (`gh pr diff 12935 > p; git apply -3 p`) and re-running the repro gave rc=0 on spirv/hlsl/cuda with SPIR-V validation clean: "covered by #12935; add the regression", not a fresh dispatch. The HEAD-built slangc reported a stale `-v` 2026.13.1-50-g… ([apply the open sibling PR and re-run the repro](../learnings/1790318063820-before-dispatching-a-fix-for-an-ice-in-a-known-cra.md)).

#12935 was then in CHANGES_REQUESTED: the reviewer feared the WitnessTable arm's `none()` relocates the crash for a concrete-struct payload. #13259's untagged-arm hit sat on a dead (DCE'd) path with an inner TaggedUnion payload, already covered, so offering it as the resolving test would have overclaimed; distinguish live from dead extractions. Ops: a `--depth 50` clone gives an empty `git merge-base` until `--unshallow`; fast-forward rather than force-push over live review threads ([untagged-union witness-table arm](../learnings/1790319855433-untagged-union-witness-table-arm-assert-the-emerge.md)). The fixer then release-asserted an emergent invariant: the only `UntaggedUnionType` reaching the arm is a singleton wrapping a `TaggedUnionType`. A human's repro compiled rc=0 to HLSL, SPIR-V and CUDA without firing it, yet DXC and SPIR-V validation rejected the output and the CUDA dispatcher took the wrong receiver: `none()` had turned an ICE into invalid codegen, and `UntaggedUnion(singleton(TaggedUnion))` is the double wrap the producer fix removes ([emission succeeded is not valid](../learnings/1790404907441-emission-succeeded-is-not-valid-run-spirv-val-and-.md)). Before approving a public soundness reply, require validated DXIL/SPIR-V for constructed nearby shapes (callbacks, two-consumer factories, dispatch receivers) and re-read the PR comments (the counterexample's webhook went to a sibling session) ([assert-backed invariant needs validated nearby shapes and a PR re-read](../learnings/1790405042503-an-assert-backed-invariant-must-be-tested-on-valid.md)).

#13261 shows where that revision stopped. `let v = createDynamicObject<IFactory>(k,0).make(n)` returns an associated type, and `v is T` / `v as T` fold to false: the checker opens an existential only when the static type is literally an `InterfaceDecl` (`isInterfaceType`), so an interface-bound `AssocTypeDecl` falls through to a static `kIROp_TypeEquals` and `_isTypeParametric` suppresses the diagnostic. Fixing the checker reaches #12934's ICE; #12935's diff on top still ICEs (`!inst || as<T>(inst)` via `GetTypeTagFromTaggedUnion`) because `none()` expects refinement to a singleton and two runtime types never refine. The miscompile needs ≥2 concrete types, so the front-end half has no ICE-free regression test. A same-file, same-mechanism PR can be necessary but insufficient ([verify a "green once PR X lands" dependency by applying X's diff](../learnings/1790318063842-verify-a-green-once-pr-x-lands-dependency-by-apply.md)).

## What dynamic-dispatch lowering inlines (#12924) and what `[__specializePerConformance]` changes (#13387)

Before 2026.18.2, `s_dispatch_*` and `*_wtwrapper*` carry no inline marking and stay calls; `[ForceInline]` on the user's default implementation only inlines it into the wrapper. From 2026.18.2 (PR #12924), `addForceInlineDecoration` marks wrapper and dispatcher except on CPU-via-LLVM, and `performForceInlining` runs before `eliminatePhis`, so the concrete MakeStruct reaches the caller per field. The ID→tag mapping function from `createIntegerMappingFunc` is still not inlined on master: `createDynamicObject<I>(constId, …)` inside `[ForceUnroll]` emits `uint t = _S16(0U); switch (t) {…all arms…}` per iteration. Check a release binary (`gh release download vX -R shader-slang/slang`) with `grep -c 's_dispatch.*('` on `-target cuda` output ([s_dispatch_*/wtwrapper survive as calls before v2026.18.2](../learnings/1790405268841-dynamic-dispatch-s-dispatch-wtwrapper-survive-as-c.md)).

Open PR #13387's `[__specializePerConformance]` (#13245 repros, sm_75) emits one dispatch switch to per-conformer copies of the attributed generic helper and drops the associated-result `AnyValue` box, but only when the whole consumer is inside that helper. A helper returning the interface (`IHit`) and direct `createDynamicObject<I>(id,0).method(p)` are byte-identical with and without the PR, and the ID→tag remap switch survives everywhere (#13220). The larger #13245 Gist files give the compact repro's cubins, so their timing gaps come from compiler version or the SlangPy route. Count SASS (`slangc -target ptx -O3` → `ptxas -arch=sm_75 -O3 -v` → `cuobjdump -sass | grep -cE '^\s+/\*[0-9a-f]{4}\*/'`); render-test ignores `-entry`, so name the entry `computeMain` ([`[__specializePerConformance]` helps only when the whole consumer is inside the helper](../learnings/1791193003985-slang-specializeperconformance-pr-13387-helps-only.md)). The `extension<T : I> T` rework is on [Type-Flow Set-Specialization Diamonds](slang-compiler-type-flow-set-specialization-diamonds.md#per-conformance-extension-methods-13387-specialize-pass-mechanics-and-adjacent-bugs).

## Addresses into interface-typed storage are retyped without their storage (#14152)

Consider `takeRef(p.foo)`, an `inout IFoo` helper called on an interface-typed field of a uniform, cbuffer or buffer struct. `analyzeFieldAddress` falls back to `Ptr(TaggedUnion(all tables))` for an interface-typed field with no `fieldInfo`, and `specializeInst` has no FieldAddress/GetElementPtr case, so `replaceType` retypes the address to `{uint,AnyValueM}` while the field stays `IFoo` (`{uint2,uint2,AnyValueN}`). `specializeCall` upcasts only `In` arguments; `Out`, `BorrowInOut`, `BorrowIn` and `Ref` pointers pass through unchanged, so the call produces invalid code on every target while slangc exits 0, and a by-value read through an address (`takeVal(pBuf[0].foo)`) fails the same way. Bridges exist only for Load, Store and FieldExtract (`CastInterfaceToTaggedUnionPtr`). FileCheck-only tests hide the bug; check with dxc (`-target dxil -profile cs_6_5`), glslang (`-emit-spirv-via-glsl`), nvrtc (`-target ptx`) and spirv-val. Workaround: copy into a local first (`IFoo x = p.foo; takeRef(x);`) ([type-flow addresses into interface-typed storage are retyped without their storage](../learnings/1793615402549-type-flow-dynamic-dispatch-addresses-into-interfac.md)).

## A `bwd_diff` ".bwds() hang" is a target-specialization fixpoint, not autodiff (#13169)

A reverse-mode `bwd_diff`/`.bwds()` hang on a `[Differentiable]` runtime-bound loop reading an interface-typed differentiable view (`IDiffTensor`/`DiffTensorView`; SlangPy #1167 → slang#13169) was blamed by four agents on the autodiff reverse-loop counter. gdb on the live, CPU-bound compile pinned it after autodiff, in `linkAndOptimizeIR`: `SpecializationContext::processModule`'s `for(;;)` never converges because `performDynamicInstLowering` re-reports a change every round on a loop-carried phi typed `TagType(IRWitnessTableSet)` feeding a set-specialized `IRSpecialize`, a shape `_resolveInstRec` excludes from `resolvedStructuralFixedPoints` as non-monotonic (`slang-ir-translate.cpp:514-517`). Owner: typeflow (jvepsalainen-nv). The hot frames (`performInformationPropagation`/`_resolveInstRec`) are the time sink, not the change driver ([#13169: an autodiff 'hang' was a type-flow fixpoint](../learnings/1789722972530-slang-13169-a-reverse-mode-autodiff-hang-was-actua.md)).

Discriminators: the hang is compile-time and CPU-bound; an unrollable loop (`i<5`, `[ForceUnroll]`) converges while a `[MaxIters]`-only runtime loop over an interface never does; the forward pass is fine. The GPU-free repro (~55 lines) is `slangc -target cuda` on an `interface ITensorView { [Differentiable] float read(...); }` read in a `[MaxIters(n)]` loop under `bwd_diff`; earlier repros modeled the autodiff shape and failed. Make the set-specialized `Specialize`/witness-table-set lowering idempotent; a bare iteration cap masks and risks miscompile. Have gdb LAUNCH slangc (`ptrace_scope=1`) and `kill -INT` it so a queued `-ex bt` fires. `import "slangpy"` + `bwd_diff` hangs bare slangc earlier at `diagnoseCircularConformances`, a separate confound. Not #13000 (wrong gradient) ([discriminators and repro](../learnings/1789723591195-a-bwd-diff-bwds-hang-on-an-interface-typed-non-unr.md)).

## Before relaxing a compiler gate, grep the tests that PIN it (#12486)

Fixing "empty existential passed to a helper ICEs instead of a clean E50100" (#12486) by deleting the entry-point-only gate in `diagnoseUnresolvedLookupWitnesses` and keeping only the zero-conformance count gate breaks `tests/diagnostics/no-type-conformance-nested-interface.slang:46-63`, whose never-called, zero-conformance `unusedHelper(IUnused)` must get no E50100. The fix gates on entry-point reachability through resolvable direct calls: reachable + zero-conformance → diagnose (was ICE); unreachable + zero-conformance → skip; reachable + ≥1 conformance (slangpy `write_arg(IPrintable)`) → skip via the count gate. Reachability is a valid proxy for "reaches codegen" because `eliminateDeadCode` runs before `specializeDynamicInsts`; reuse the `getResolvedCalleeFunc` BFS in `slang-ir-legalize-varying-params.cpp`. A triage's "just delete the gate" can be provably wrong [#12486: the E50100 entry-point gate is pinned by a test](../learnings/1786495950035-slang-12486-the-e50100-entry-point-gate-is-pinned-.md).

## Approver and operational learnings (fold 2026-07-17)

**Peel-walker guards (#11152 → #12119).** #11152 guarded the CUDA immutable→`__ldg` rewrite on `getRootAddr(ptr)` not being `GetOptiXSbtDataPtr`. `getRootAddr` peels only {GetElementPtr, FieldAddress, NodeOutputRecordGetElementPtr}, and buffer element-type legalization (bool or 16-bit SBT members) inserts `BitCast`/`GetOffsetPtr` before the root, so the approver's WOULD_APPROVE was a false-safe (superseded by #12119). A root-op guard is complete only if the walker covers every pointer-forwarding op ANY later pass can splice in ([false-safe: probe the peel-set against ALL later passes](../learnings/1784120041393-approver-false-safe-guard-keyed-on-getrootaddr-s-o.md)). Completeness is necessary but not sufficient; the second probe is what the fallthrough returns for each unpeeled op. On #12119 a UserPointer `BitCast` falls through to "mutable" (no `__ldg`, safe); record which axis carried the decision ([challenger-miss: op-set completeness AND failure direction](../learnings/1784123729267-approver-challenger-miss-for-a-peel-walker-guard-v.md)). The failure-direction proof must use the fallthrough root's actual type: a missed `kIROp_PtrCast` leaves the `ConstantBuffer<>`-typed root, which lowers to `AddressSpace::Uniform`, which `isPointerToImmutableLocation` calls immutable, the unsafe answer. The decision moved WOULD_APPROVE → ABSTAIN_POLICY (OPEN_GAP), not BLOCK, because `git grep` found no source producer of `PtrCast` ([critique-mustfix: check the FALLTHROUGH type](../learnings/1784180537337-approver-critique-mustfix-failure-direction-proof-.md)).

**Clearing a new `SLANG_RELEASE_ASSERT` (#12127).** A new `SLANG_RELEASE_ASSERT(storedType)` on `tryGetPointedToType(getPtr())` in the HostVM `kIROp_Store` arm was flagged as a possible abort on ComPtr/NativePtr. Clear it as advisory when unguarded sibling arms (`kIROp_Var`, `GetElementPtr`, `FieldAddress`, `GetOffsetPtr`) already rely on the same helper AND the failure is a loud abort. Abstain only when you can show the op producing the flagged shape; in #11152 the missed op was reachable and the failure silent ([challenger-win: sibling-arm precedent + failure direction](../learnings/1784148942373-approver-challenger-win-clearing-a-new-slang-relea.md)).

**`analyzeMakeStruct` OOB is latent (#12132).** `analyzeMakeStruct` reads `makeStruct->getOperand(i)` bounded by `structType->getFields()`, unchecked against `getOperandCount()` (`slang-ir.h:711` asserts). No producer under-supplies it: DCE `trimMakeStructOperands` (`slang-ir-dce.cpp`) removes field and operand together, varying-params legalization builds a fresh one-field struct, and autodiff `translateMakeStruct` already release-asserts the same pattern (`slang-ir-autodiff-fwd.cpp:907`). Assert operand==field count at the consumer rather than bound with `min`. DeepWiki found the paths, not that they preserve parity ([analyzeMakeStruct OOB is LATENT](../learnings/1784171101845-slang-analyzemakestruct-positional-oob-is-latent-m.md)).

**Revert-drill for a witness `substitute()` (slang#9580 / PR #12131).** Neuter `val->substitute(astBuilder, SubstitutionSet(declRef))` to `SubstitutionSet()`, rebuild, and check the target case breaks; if it still passes, the test overclaims. A value-generic wrapper whose resolved type ignores `N` (`struct SolidMode<let N:int> : IShaderMode { typedef ColorOutput FragOut; }`) does not exercise it ([revert-drill for a witness substitute()](../learnings/1784176407848-revert-drill-to-prove-a-witness-substitute-is-load.md)).

**capdef disjunctions (#12097).** `def` and `alias` inheritance both go through `parseExpr()`, which accepts DNF top-level `|` (`def X : a + b | a + c;`); `parseConjunction()` joins only bare identifiers, so `def X : a + (b | c);` fails with `error 20001` and must be distributed by hand. Verify with `slang-capability-generator <capdef> --target-directory <dir>` before telling a maintainer ([capdef: top-level | yes, parenthesized (b|c) no](../learnings/1784126862980-capdef-def-inheritance-accepts-top-level-disjuncti.md)).

**meta.slang op splices.** A lua key `imageGatherOffset` generates `kIROp_ImageGatherOffset`; `__intrinsic_op($(kIROp_...))` splices and C++ `case`s use the capitalized enum, `slang-ir-insts-stable-names.lua` the lua key, and the lua-key spelling in a splice breaks the core-module compile. Check `build/source/slang/fiddle/slang-ir-insts-enum.h.fiddle` ([meta.slang splice uses the CAPITALIZED enum name](../learnings/1784168350681-meta-slang-kirop-x-splice-must-use-the-capitalized.md)).

**createGlobalSession RSS (#12113).** `createGlobalSession()` eagerly deserializes the embedded core module, so baseline RSS tracks the `g_coreModule` symbol in libslang.so nearly 1:1 (v2026.5→v2026.7: 4.73→9.29 MiB, peak RSS 96.7→187.1 MiB). Compare release tarballs with `nm --print-size --size-sort --radix=d`. If `*.meta.slang` and the serializer are unchanged, the compiler synthesizes more core-module IR (suspect: #9808); bisect by building only the bootstrap ([createGlobalSession RSS ≈ g_coreModule size](../learnings/1784096601212-slang-createglobalsession-rss-g-coremodule-blob-si.md)).
