# Slang Compiler: Type-Flow ExtractExistential, Gate-Relaxation Discipline, and 2026-07-17 Operational Fold

This page covers the dynamic-dispatch type-flow specialization pass (`slang-ir-typeflow-specialize.cpp`), the discipline for relaxing a compiler diagnostic gate, and a fold of dated operational learnings (approver false-safe/challenger notes, capdef, meta.slang splice, revert-drill, analyzeMakeStruct, createGlobalSession RSS).

## TL;DR
- **Type-flow `ExtractExistential` analyzers must tolerate coarsened untagged-union info, but only the *singleton* case may refine to a concrete type.** A blanket mirror of the Value sibling relocates the ICE — the Type analyzer must guard `untaggedUnion->getSet()->isSingleton()` before refining to `makeElementOfSetType`; WitnessTable returns `none()` for any untagged union; keep `SLANG_UNEXPECTED` for all other shapes. A later `SLANG_RELEASE_ASSERT(isSingleton() && as<IRTaggedUnionType>(getElement(0)))` on that arm proved nothing: a repro that passed it still emitted DXC-rejected HLSL and spirv-val-failing SPIR-V, and the singleton-wrapped tagged union it accepts is plausibly the malformed #13046 shape itself. This is the correct layer for #12934's consumer PR #12935.
- **But the same crash family has a PRODUCER-side root (#13046):** `isConcreteType` lacks a tagged/untagged-union case → `makeInfoForConcreteType` re-wraps an already-lowered union into `UntaggedUnion(TypeSet(TaggedUnion(...)))`. Fix at the construction chokepoint with `if (isRefinedInfoType(type)) return type;` at the TOP of `makeInfoForConcreteType` (covers nested cases; NOT an entry assert, which hard-aborts on `IAccessor[1]`-style nesting). A producer fix can SUPERSEDE the consumer PR for the whole family — verify by running the sibling issue's own regression on your build before recommending a companion PR.
- **Before dispatching a fix for an ICE in a known crash family, apply the open sibling PR's real diff and re-run the repro** (`gh pr diff N > p; git apply -3 p`, incremental rebuild), and re-fetch that PR's review state. #12935 covered #13259 but sat in CHANGES_REQUESTED, and it was necessary but insufficient for #13261, whose ≥2 distinct runtime types never refine to a singleton. Never write "green once #N lands" without applying #N.
- **Interrogate the shape a guard ACCEPTS, not only the one it rejects**, and treat "assert never fired" as no evidence of soundness.
- **"Emission succeeded" is not "valid" for a typeflow/dynamic-dispatch change:** verify with `-target dxil` (DXC is bundled) and `SLANG_RUN_SPIRV_VALIDATION=1 -target spirv`; `-target hlsl`/`spirv-asm`/`cuda` rc=0 and `CHECK: OpEntryPoint` tests do not catch ill-typed codegen.
- **A freshly built slangc's `-v` is a stale baked git-describe tag**; tell a master binary by crash-site line numbers, not the version string.
- **Before relaxing a compiler diagnostic gate, git-blame it AND grep the tests for a case that PINS the exact behaviour you are relaxing** — a "just delete the gate" fix a triage recommends can be provably wrong against an existing regression test. Gate on entry-point reachability (a valid proxy for "reaches codegen" since `eliminateDeadCode` runs before the diagnostic pass).
- **`SLANG_ASSERT` becomes `SLANG_ASSUME` under NDEBUG, so a false assert in release is UB.** Before citing an internals behaviour, read it at a named ref — several folded entries here record a premise that was false.
- **capdef `def` inheritance accepts a top-level `|` disjunction but NOT a parenthesized `(b|c)` inside a conjunction.**
- **A `meta.slang` `$(kIROp_X)` splice must use the CAPITALIZED enum name, not the lua key.**
- **For a peel-walker / `getRootAddr` op-set guard, probe the peel-set against ALL later passes (not the test shapes), and verify BOTH op-set completeness AND the fallthrough's failure direction** — an incomplete peel is safe iff the miss returns the conservative value; the failure-direction proof must check the FALLTHROUGH type, not assume miss=safe.
- **`analyzeMakeStruct` positional OOB is LATENT** — MakeStruct producers preserve operand==field parity.
- **Prove a witness `substitute()` is load-bearing with a revert-drill** — neuter the call to `SubstitutionSet()` (empty), rebuild, check whether the target case breaks.
- **`createGlobalSession` RSS ≈ `g_coreModule` blob size** — measure it via `nm` on libslang.

## Type-flow ExtractExistential analyzers: tolerate untagged-union info, but guard the singleton case (#12934/#12935)

`source/slang/slang-ir-typeflow-specialize.cpp` (the dynamic-dispatch type-flow specialization pass, PR #7968) has three sibling analyzers that extract components from an existential's propagated "info": `analyzeExtractExistentialType` (~:3781) and `analyzeExtractExistentialWitnessTable` (~:3746) handle only COM-interface and `IRTaggedUnionType` info and `SLANG_UNEXPECTED` on anything else, while `analyzeExtractExistentialValue` (~:3817) already `return none()`s on the non-tagged-union fall-through. On *valid* code that reaches an existential-returning helper through a real dynamic dispatch over ≥2 registered conformances (`createDynamicObject` + two `-conformance`), especially threaded through the autodiff `IRDifferentialPairType` union, the merge (`unionPropagationInfo`/`flatUnionPropagationInfo`/`analyzeSpecialize`) coarsens the operand info to `UntaggedUnionType` or a non-singleton `ElementOfSetType` — not a `TaggedUnionType` — so the Type/WitnessTable analyzers throw `E99997 Unhandled info type in analyzeExtractExistentialType` (issue #12934, reduced from a Falcor2 `scene_test`; either conformance alone stays concrete and compiles) [slang type-flow ExtractExistential Type/WitnessTable analyzers crash where the Value sibling tolerates non-tagged-union info](../learnings/1788817368144-slang-type-flow-extractexistential-type-witnesstab.md). The fix is NOT a blanket mirror of the Value sibling: the Type analyzer must guard `untaggedUnion->getSet()->isSingleton()` and only then refine to `makeElementOfSetType(getSet())` (a statically-known concrete type); accepting *every* untagged union unconditionally lets a multi-element union flow into `specializeExtractExistentialType`'s multi-element path (~:6109), which calls `emitGetTypeTagFromTaggedUnion` on a tagless operand and merely RELOCATES the ICE to the tag-extraction path. WitnessTable returns `none()` for any untagged union (no witness-table-set to recover; see the #13259 section below for why a later assert on this arm is not proof of safety); keep `SLANG_UNEXPECTED` for all other shapes. This is the correct layer (consumer, not producer): `makeInfoForConcreteType()` (~:704) intentionally wraps a concrete value at a non-structural merge point as a singleton `UntaggedUnionType` (tag dropped — a concrete value has no runtime witness-table tag). Gate per the #12873 discipline — a temporary `fprintf(stderr, "...op=%s", ...)` in the fall-through pins the arriving op + `isSingleton()`/`getOperandCount()`, and `SLANG_RUN_SPIRV_VALIDATION=1` confirms downstream lowering accepts the coarser shape rather than just moving the crash. `-dump-ir` writes to **stderr**; the pass just before is `specializeModule`. Fixed in PR #12935 [slang typeflow ExtractExistential singleton guard: mirroring Value sibling naively relocates the crash](../learnings/1788821533041-slang-typeflow-extractexistential-singleton-guard-.md).

## Same crash family has a PRODUCER-side root (#13046): fix the double-wrap at the construction chokepoint

The consumer-side singleton guard above (PR #12935) fixes #12934, but the `E99997 Unhandled info
type in analyzeExtractExistentialType` family also has a **distinct producer-side trigger**
(#13046, autodiff-free, no nested hit-info) that the consumer guard merely *relocates*. Mechanism,
all in `slang-ir-typeflow-specialize.cpp` (@ a90dfa311): `isConcreteType` (~:585-602) has NO case
for `kIROp_TaggedUnionType`/`kIROp_UntaggedUnionType` → falls through `default: return true`, so an
already-lowered `IRTaggedUnionType` return is mis-classified "concrete"; `propagateInterproceduralEdge`'s
FuncToCall fallback (~:2158-2176) passes it to `makeInfoForConcreteType`, whose entry
`SLANG_ASSERT(isConcreteType(type))` wrongly passes (same misclassification) and whose bottom
fallthrough (~:704-706) RE-WRAPS it into the malformed `UntaggedUnion(TypeSet(TaggedUnion(...)))`;
`analyzeExtractExistentialType`'s happy path (~:3778) only matches a BARE `IRTaggedUnionType`, so the
doubly-wrapped shape hits `SLANG_UNEXPECTED` at ~:3781 ([analyzeExtractExistentialType ICE has a producer-side root (isConcreteType lacks a union case), not just the consumer gate](../learnings/1789325428139-analyzeextractexistentialtype-ice-has-a-producer-s.md)).
Two transferable lessons: **(1) put the "don't re-wrap an already-refined X" guard at the single
CONSTRUCTION CHOKEPOINT, not the caller — and NOT as an assert.** Guarding only the
`propagateInterproceduralEdge` fallback + `SLANG_ASSERT(!isRefinedInfoType(type))` at
`makeInfoForConcreteType`'s entry is INCOMPLETE: a structurally-nested refined return (`IAccessor[1]`,
tuple, `DifferentialPair<...>`) passes `isConcreteType` at the top level, enters the function, and the
structural recursion hits the refined element → the assert HARD-ABORTS. Correct fix:
`if (isRefinedInfoType(type)) return type;` at the TOP of `makeInfoForConcreteType` — because the
structural cases recurse back through it, one chokepoint guard covers top-level AND arbitrarily-nested
cases, matching the existing `tryGetInfo` "refinement occurred in a previous phase; reuse directly"
rule (`isRefinedInfoType` = {TaggedUnionType, UntaggedUnionType, ElementOfSetType}, the op set
`tryGetInfo`/`isSingletonInfo` already use — consolidate to one predicate). **(2) A producer-side fix
can SUPERSEDE a consumer-side PR for a whole crash family — verify by running the sibling issue's own
regression on your fix.** #12935's consumer guard relocates #13046 (its singleton branch fires on the
malformed singleton and re-asserts at `slang-ir-specialize-function-call.cpp:246`), whereas the
producer fix compiles+passes #12934's OWN regression test with NO consumer guard present → it fixes
both at the root. Before recommending a "companion PR", run the related issue's test on your build; if
it passes, recommend supersede and carry that test forward (no path collision — only one PR lands).
Both the incomplete-assert gap and the supersede opportunity were caught by the codex CODE/PLAN
critique before delivery, so run the critique gate on IR-pass fixes even when local tests are green — a
top-level-only repro misses the structural-nesting variant ([Typeflow refined-info double-wrap: fix at the construction chokepoint, and producer can supersede a consumer PR (slang#13046 vs #12934/#12935)](../learnings/1789331744961-typeflow-refined-info-double-wrap-fix-at-the-const.md)).

## The #13259/#13261 follow-ons: apply the open sibling PR, then assert the emergent invariant

Two 2026-09-25 reports in the `E99997 Unhandled info type in analyzeExtractExistential*` family looked new and were not. #13259 (`...WitnessTable`) was said to have a trigger distinct from #12934/#13046, both still open. Applying the open bot PR #12935 (`gh pr diff 12935 > p; git apply -3 p`), an incremental Release rebuild of slangc (~1 min) and re-running the repro gave rc=0 on spirv/hlsl/cuda with SPIR-V validation clean, so the verdict became "covered by #12935; add the regression" instead of a fresh fix dispatch. A trap on the way: a slangc freshly built from HEAD still reports a stale baked git-describe `-v` (2026.13.1-50-g…), so tell a master binary by the source line numbers at the crash site, not the version string ([apply the open sibling PR and re-run the repro before dispatching a fix for an ICE in a known crash family](../learnings/1790318063820-before-dispatching-a-fix-for-an-ice-in-a-known-cra.md)).

"Just add a regression test" was still not the whole job. #12935 had been described as idle and mergeable but was actually in CHANGES_REQUESTED: the reviewer feared that the WitnessTable arm's `none()` relocates the crash for a concrete-struct payload. IR dumps plus instrumentation showed that #13259's untagged-arm hit sat on a dead (DCE'd) path with an inner TaggedUnion payload, the same safe side the existing test already covered, so offering it as "the test that resolves the concern" would have overclaimed. Distinguish *removed before lowering* from *survived but lowered*, and live from dead extractions. The fixer argued that an emergent invariant makes `none()` safe. An `ExtractExistentialWitnessTable` operand is always a frontend existential, so its refined info should be a `TaggedUnionType` (`analyzeMakeExistential` never yields untagged, and `flatUnionPropagationInfo` rejects tagged/untagged mixing), and the only `UntaggedUnionType` reaching the arm would be a singleton wrapping that tagged union, made by `makeInfoForConcreteType` at a merge. It encoded that with `SLANG_RELEASE_ASSERT(isSingleton() && as<IRTaggedUnionType>(getElement(0)))` and gated it on the full `dynamic-dispatch` and `autodiff` suites. That assert did not settle the question. A human's standalone repro on #12935 compiled to HLSL, SPIR-V and CUDA with rc=0 and did not fire the assert, yet DXC rejected the HLSL, `SLANG_RUN_SPIRV_VALIDATION=1` failed the SPIR-V, and the CUDA source was ill-typed: a dispatcher took the lowered tagged-union tuple as its receiver instead of the AnyValue payload. An assert that encodes "the shape I traced as safe" can be satisfied by the malformed shape, and `UntaggedUnion(singleton(TaggedUnion))` is plausibly the same double-wrap the #13046 producer fix above removes at `makeInfoForConcreteType`. The owning session called #12935 a band-aid and escalated for a decision (["emission succeeded" is not "valid": run spirv-val and DXC before claiming a typeflow fix is safe](../learnings/1790404907441-emission-succeeded-is-not-valid-run-spirv-val-and-.md)). `none()` had in fact relocated the failure from an internal error to invalid codegen, which was the reviewer's exact concern. The proof and the adversarial critique had both aimed at the feared bare-struct payload, and nobody asked whether untagged-wrapping-tagged is a principled representation, so the input-shape check applies to the shape a guard *accepts* as much as to the shape it rejects. The orchestrator-side lesson: before approving a public soundness reply to a CHANGES_REQUESTED review, require the adversarial pass to produce validated target output (DXC-compiled DXIL, validated SPIR-V) for constructed nearby shapes such as callbacks, factories with two consumers and dispatch receivers, and require a fresh read of the PR's comments, because the counterexample's webhook had gone to a sibling session ([an assert-backed invariant must be tested on validated output of nearby shapes, and the PR re-read before any public claim](../learnings/1790405042503-an-assert-backed-invariant-must-be-tested-on-valid.md)). So for any dynamic-dispatch or typeflow change, verify with `-target dxil` (DXC is bundled at `build/<cfg>/lib/libdxcompiler.so`, so it runs in the container) and `SLANG_RUN_SPIRV_VALIDATION=1 -target spirv`, never with emit rc alone; existing `//TEST:SIMPLE -target spirv-asm` + `CHECK: OpEntryPoint` tests do not catch ill-typed codegen. Ops notes from the same PR: the base clone is `--depth 50`, so `git merge-base origin/master HEAD` is empty until `--unshallow`; land a fast-forward commit rather than force-pushing a rebase over live review threads; and `extras/formatting.sh` with no arguments is a no-op ([untagged-union witness-table arm: assert the emergent invariant, and don't add a safe-side regression test](../learnings/1790319855433-untagged-union-witness-table-arm-assert-the-emerge.md)).

#13261 shows where #12935 stops. `let v = createDynamicObject<IFactory>(k,0).make(n)` returns an associated type, and `v is T` / `v as T` fold to constant false. The is/as checker opens an existential only when the static type is literally an `InterfaceDecl` (`isInterfaceType`, slang-check-decl.cpp:2145; `visitIsTypeExpr`/`visitAsTypeExpr` in slang-check-expr.cpp), so an interface-bound `AssocTypeDecl` falls through to a static `kIROp_TypeEquals`, and `_isTypeParametric` suppresses the diagnostic. Fixing the checker makes is/as reach type-flow and hit #12934's ICE. Applying #12935's actual diff on top still ICEs, relocated to `slang-ir.h(861): !inst || as<T>(inst)` via `GetTypeTagFromTaggedUnion`, because #12935's `none()` expects later refinement to a singleton and two genuinely distinct runtime types never refine. The miscompile appears iff the opened existential has ≥2 concrete types, which is exactly the multi-element untagged-union condition that ICEs downstream (the #13046 family), so the front-end half has no ICE-free green-on-master regression test; single-conformance shapes and `this is/as T` in a default method were never wrong. The rule: before writing "fully green once #N lands" into a PR body or merge gate, apply #N's real diff and run the repro, because a same-file, same-mechanism PR can be necessary but insufficient ([verify a "green once PR X lands" dependency by applying X's actual diff; #12935 is insufficient for multi-type is/as (#13261)](../learnings/1790318063842-verify-a-green-once-pr-x-lands-dependency-by-apply.md)).

## A `bwd_diff` '.bwds() hang' is a target-specialization fixpoint, NOT an autodiff bug (slang#13169)

A reverse-mode `bwd_diff`/`.bwds()` "hang" on a `[Differentiable]` runtime-bound loop reading through an interface-typed differentiable view (`IDiffTensor`/`DiffTensorView`; SlangPy #1167 → slang#13169, bot-filed and labeled `Autodiff`+`regression`) was hypothesized by the issue, the triager, and two fixers to be an autodiff reverse-loop-counter bug in `slang-ir-autodiff-primal-hoist.cpp` (`collectLoopExitConditions` / `lowerIndexedRegion` `diffCountParam`). **All were the wrong subsystem.** gdb on the live (CPU-bound, GPU 0%) compile pinned it, triple-corroborated, to a **non-terminating TARGET-SPECIALIZATION fixpoint in `linkAndOptimizeIR`, AFTER autodiff**: `SpecializationContext::processModule`'s `for(;;)` (`slang-ir-specialize.cpp:1832`, exit `:1904` on `!iterChanged`) never converges because `performDynamicInstLowering` (`slang-ir-typeflow-specialize.cpp`) re-reports a change every round on a **loop-carried phi typed `TagType(IRWitnessTableSet)` feeding a set-specialized `IRSpecialize`** — a shape `_resolveInstRec` classifies as **non-monotonic** and deliberately excludes from `resolvedStructuralFixedPoints` (`slang-ir-translate.cpp:514-517`; only `IRSetBase` records fixed points). Owner is typeflow/target-specialization (jvepsalainen-nv), NOT autodiff/saipraveenb25, and #12299 (the autodiff-start fix) is fully refuted as suspect ([slang#13169: a reverse-mode autodiff 'hang' was actually a type-flow specialization fixpoint](../learnings/1789722972530-slang-13169-a-reverse-mode-autodiff-hang-was-actua.md)). The gdb "hot" frames (`performInformationPropagation`/`_resolveInstRec`/`getIntValue`) are the TIME-SINK (context rebuilt each round → empty fixed-point set → full re-walk), NOT the change driver — don't confuse the two. Fast discriminators to route this class next time: (1) the hang is **compile-time / CPU-bound (GPU 0%)** — a non-terminating fixpoint, not a runtime GPU kernel loop, so "compile-time vs GPU-dispatch?" is the key early question; (2) **unrollable ⇒ converges, non-unrollable ⇒ hangs** — a literal `i<5`/`[ForceUnroll]` loop unrolls (`unrollLoopsInModule`, warns E30519) into finite concrete witness tables and converges, while a `[MaxIters]`-only runtime loop over an interface type keeps a live witness-table-set and never idempotents; (3) forward pass ok, no ICE, no wrong gradient. The minimal GPU-free repro is `slangc -target cuda` on an `interface ITensorView { [Differentiable] float read(...); }` with a `[MaxIters(n)] for(i<n)` `[Differentiable]` loop reading through the interface-typed value + `bwd_diff` — ~55 lines, NO `import slangpy` (prior "no minimal repro" failures modeled the *autodiff* shape — value arrays / scatter-add — which all compile fine; re-check you're modeling the RIGHT pass) ([a bwd_diff .bwds() hang on an interface-typed non-unrollable loop is a target-specialization fixpoint](../learnings/1789723591195-a-bwd-diff-bwds-hang-on-an-interface-typed-non-unr.md)). Candidate fix = make the set-specialized `Specialize`/witness-table-set lowering idempotent (structural/set-equivalence fixed point), NOT a bare iteration cap (which masks and risks miscompile). Technique notes: gdb on a live compile beats pass-bisection for a CPU-side hang (have gdb LAUNCH slangc so it is an ancestor under `ptrace_scope=1`; `kill -INT` the gdb pid to break the inferior so a queued `-ex bt` fires); `import "slangpy"` + a `bwd_diff` wrapper hangs bare slangc EARLIER at `diagnoseCircularConformances` (a SEPARATE confound hitting both runtime and fixed bounds, before specialization), so capture kernels through SlangPy's own linked session or use a slangpy-free repro; and verify any "regression window straddles commit X" claim with `git merge-base --is-ancestor` + tag commit DATES (release-tag dates ≠ version-number intuition). Distinct from #13000 (nested-`[MaxIters]` *wrong gradient*).

## Before relaxing a compiler gate, grep the tests that PIN it (#12486)

Fixing "empty existential passed to a helper ICEs instead of a clean E50100" (#12486) by deleting the entry-point-only gate in `diagnoseUnresolvedLookupWitnesses` (`slang-ir-typeflow-specialize.cpp:3477`) and relying only on the existing zero-conformance gate (`collectExistentialTables(...).getCount()==0`, :3502) **breaks an existing test**: `tests/diagnostics/no-type-conformance-nested-interface.slang:46-63` deliberately declares a NON-entry, zero-conformance, never-called `unusedHelper(IUnused)` and its exhaustive-CHECK asserts that broadening the walker to non-entry funcs would emit an unannotated E50100. The correct fix additionally gates on **entry-point reachability** (diagnose a non-entry helper only if it is reachable from an entry point through resolvable direct calls), splitting three cases: reachable + zero-conformance (the `useDyn` repro) → diagnose (was ICE); unreachable + zero-conformance (`unusedHelper`) → skip (test stays green); reachable + ≥1 conformance (slangpy `write_arg(IPrintable)`) → skip via the count-gate. Reachability is a valid proxy for "reaches codegen" because `eliminateDeadCode` (`slang-ir-specialize.cpp:1729`) runs BEFORE `specializeDynamicInsts`→`diagnoseUnresolvedLookupWitnesses` (:1760), so genuinely-dead helpers are already gone; reuse the `getResolvedCalleeFunc` BFS pattern from `slang-ir-legalize-varying-params.cpp`. Lesson: before relaxing a gate, git-blame it AND grep the tests for a case that pins the exact behaviour you're relaxing — a minimal "just delete the gate" fix a triage recommends can be provably wrong against an existing regression test [slang#12486: the E50100 entry-point gate is pinned by an existing test — zero-conformance-only fix regresses it](../learnings/1786495950035-slang-12486-the-e50100-entry-point-gate-is-pinned-.md).
