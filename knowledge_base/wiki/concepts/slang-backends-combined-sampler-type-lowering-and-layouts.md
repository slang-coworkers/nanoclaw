# lowerCombinedTextureSamplers: which combined types get lowered, the nested layout rebuild, and deduplicated IR layouts

On HLSL, Metal, WGSL and CPU, `lowerCombinedTextureSamplers` (`slang-ir-lower-combined-texture-sampler.cpp`) turns a combined `Sampler2D<T>` into a `{texture, sampler}` struct, and `legalizeResourceTypes` later splits that struct into two resources with their own bindings. This page covers the pass's type and layout side: which combined types it decides to lower, how it rebuilds layouts for samplers nested in containers, and why it must never free a layout inst. The intrinsic-string side (the injected sampler operand, `$q`, member-form HLSL intrinsics, and the `__getTexture()` forward) is on [[wiki/concepts/slang-backends-hlsl-combined-sampler-texture-ops.md]]; general parameter binding is on [[wiki/concepts/slang-compiler-parameter-binding-and-layout.md]].

## TL;DR

- **Lowering is lazy and decided per type inst.** `mapTypeToLoweredInfo` is filled only from top-level global params whose (array-unwrapped) type is combined, and from use sites: `CombinedTextureSamplerGetTexture`/`GetSampler` (`__getTexture()`, `__extractImage(this)`) and handle insts. A combined type with neither survives the pass unlowered.
- **Because type insts are hoisted, one use lowers every field of that type, and no use lowers none.** An unaccessed `Sampler2D` field in a Metal `ParameterBlock` stays a bare 8-byte `texture2d` while reflection reports 16 bytes, so every later field shifts by 8. A `ParameterBlock` used only through `Load`/`GetDimensions` emits a bare `texture2d` and drops the sampler.
- **Through ce23b34 the pass rebuilt layouts only for top-level params.** Any change that makes an op lower the type in more places (forwarding `Load`/`[]`/`GetDimensions` through `__extractImage`, as #13741 does for HLSL/CPU and #14017 for Metal) exposes every nested shape: `cbuffer`, `ConstantBuffer<S>`, `ParameterBlock<S>`, a `uniform S` global, a plain struct, and an entry-point `uniform` param.
- **The nested failure is loud in Debug and silent in Release.** Debug asserts `SLANG_ASSERT(fieldLayout || !typeLayout)` in `slang-ir-legalize-types.cpp` (~3504, E99997). Release emits the split texture and sampler with no `register(...)`; DXC then auto-binds the texture to t0 while reflection says t1, so the shader reads the wrong texture.
- **`Sample` on those nested shapes always failed this way.** `Load`-only use "worked" on master only because the type was never lowered, which silently dropped the sampler (`Texture2D C_t_0 : register(t0) : register(s0)`).
- **Fix of record: rebuild layouts along the type path in the producer pass** (PR #14017, commit ca41b168a, cherry-picked into #13741). Walk each global param's type and layout together through arrays, structs and uniform parameter groups; give each lowered leaf a struct layout made of the lowered field layouts plus the leaf's original sizes; re-derive the parameter-group offset element with `applyOffsetToTypeLayout`.
- **A struct layout can list a field that an earlier pass already moved out of the IR struct** (resources of `GlobalParams`), so the walk must not assert that the field exists.
- **IR layout insts (`IRVarLayout`, `IRTypeLayout`, layout attrs) are hoistable and deduplicated.** A top-level `Sampler2D x` at t0/s0 and the field `a` of `cbuffer C { Sampler2D a; }` at relative t0/s0 are one inst. Never call `removeAndDeallocate()` on a layout: remove only the layout decoration and let DCE collect the old layout (fix c1b407836).
- **Registering every combined type inst in the driver loop fixes the unused-field Metal case only together with the nested-layout rebuild.** Alone, it makes Debug assert on HLSL/WGSL `cbuffer`/`ParameterBlock` with an unused field; and #14017's walk alone does not fix the unused field, because the walk is gated on `containsKey`.
- **Probe checklist for any change to this pass or to an op that reaches it:** `Sample` and `Load`; Debug and Release (`SLANG_ASSERT` is compiled out of Release); a combined sampler inside every container kind; two samplers so the register index is non-zero; a top-level and a nested sampler with identical relative offsets. Compare bindings against `-reflection-json` and the DXIL binding table, because DXC accepts register-less HLSL.

## Which combined types the pass lowers

`mapTypeToLoweredInfo` is populated from two places only: top-level global params whose type, after unwrapping arrays, is a combined texture-sampler, and use sites that need the parts (`CombinedTextureSamplerGetTexture`, `CombinedTextureSamplerGetSampler`, and handle insts). The type inst is hoisted, so the lowering decision is made once per type, not per field. Consider a Metal `ParameterBlock` whose struct holds a `Sampler2D<float4>` field that the shader never touches. The type is never registered, so the field survives the pass, and Metal emits a bare 8-byte `texture2d` inside the argument-buffer struct, while tier-2 reflection reports 16 bytes for it, so every later field is read at the wrong offset. If another field of the same type is sampled anywhere, both fields are lowered and the layout is consistent again ([lowerCombinedTextureSamplers never lowers an unused combined type](../learnings/1793297505956-lowercombinedtexturesamplers-never-lowers-an-unuse.md)). The same registration rule explains a second Metal symptom: a `ParameterBlock` that uses a combined sampler only through `Load` or `GetDimensions` registers nothing, so it emits a bare `texture2d` and silently drops the sampler, while reflection still reports 16 bytes per element ([Metal ParameterBlock keeps the combined-sampler struct whole](../learnings/1793266751909-metal-parameterblock-keeps-the-combined-sampler-st.md)).

The obvious fix, registering every combined type inst in the driver loop (three lines), is a trap on its own. Verified on 2026-10-29, it fixes Metal, but on bare master it makes Debug slangc assert at `slang-ir-legalize-types.cpp:3508` (`fieldLayout || !typeLayout`) on HLSL and WGSL `cbuffer`/`ParameterBlock` shapes with an unused field: the newly lowered field takes the split path with a flat nested layout (the mechanism of #13272). It is clean only together with the nested-layout rebuild below. The reverse also holds: #14017's walk alone does not fix the unused field, because the walk runs only for types that `containsKey` already finds in the map ([same](../learnings/1793297505956-lowercombinedtexturesamplers-never-lowers-an-unuse.md)).

## Nested containers: the layout rebuild (#13741, #14017)

Forwarding a texture-only op through `__extractImage(this)` adds a `CombinedTextureSamplerGetTexture` op, and that op makes the pass lower the combined type wherever it is used. Through ce23b34 the pass rebuilt the *layout* only for the top-level case (a bare `Sampler2D` global or an array of them). For a sampler nested in a `cbuffer`, `ConstantBuffer<S>`, `ParameterBlock<S>`, a plain struct, a `uniform S` global, or an entry-point `uniform` param (which is collected into a global struct or constant buffer), the lowered struct had no field layouts, so `legalizeResourceTypes` found nothing to split. Debug asserts `SLANG_ASSERT(fieldLayout || !typeLayout)` (`slang-ir-legalize-types.cpp` ~3504, reported as E99997). Release compiles and emits the split texture and sampler with no `register(...)`, so DXC rebinds the texture to t0 while reflection says t1, and the shader reads the wrong texture ([forwarding a combined-sampler op through `__extractImage` lowers the type in nested containers](../learnings/1793279115432-slang-forwarding-a-combined-sampler-op-through-ext.md)) ([a forward that adds CombinedTextureSamplerGetTexture exposes nested layouts](../learnings/1793280887943-a-forward-that-adds-combinedtexturesamplergettextu.md)).

The forwards did not create this bug; they exposed it. On master the same nested shapes already fail when they use `Sample`, which always forwards through `__getTexture()`. `Load`-only use "worked" only because the type was never lowered, and the cost was a silently dropped sampler (`Texture2D C_t_0 : register(t0) : register(s0)`) ([moving a combined-sampler op onto `__extractImage`/`__getTexture`](../learnings/1793294161029-moving-a-combined-sampler-op-onto-extractimage-get.md)).

The fix sits in the producer pass, shipped as a standalone commit (PR #14017, commit ca41b168a, cherry-picked into #13741). For every global param other than the top-level combined ones, the pass walks the type and its layout together through arrays, structs, and uniform parameter groups. It gives each lowered combined leaf a struct layout that uses the lowered field layouts plus the leaf's original sizes, and it re-derives the parameter-group offset element with `applyOffsetToTypeLayout`. The walk must not assert that each layout field exists in the IR struct: a struct layout can still list a field that an earlier pass already moved out (the resource fields of `GlobalParams`) ([same](../learnings/1793279115432-slang-forwarding-a-combined-sampler-op-through-ext.md)).

## Deduplicated layouts: never deallocate a layout inst

The first version of the #14017 walk segfaulted (rc 139) on HLSL, WGSL and Metal, in Release and Debug, for this program, and for the same shape with `ConstantBuffer<S>`, `uniform S`, and `ParameterBlock<S>`:

```hlsl
Sampler2D x;
cbuffer C { Sampler2D a; float4 c; }
```

The cause is that IR layout insts (`IRVarLayout`, `IRTypeLayout`, and their attrs) are hoistable, so two layouts with the same operands are one instruction. `x` at t0/s0 and the field `C.a` at relative t0/s0 share one `IRVarLayout`. The existing top-level loop called `varLayout->removeAndDeallocate()` after re-decorating `x`, which cleared the operands of the shared inst; the nested walk then read `C.a`'s field layout, found a null type layout, and dereferenced it. The fix is to remove only the layout decoration and let DCE collect the old layout (c1b407836) ([nested layout rebuild PRs: probe a top-level and a nested sampler with the same offsets](../learnings/1793284649930-nested-layout-rebuild-prs-probe-a-top-level-combin.md)) ([IR layout insts are hoisted and deduplicated, never remove-and-deallocate them](../learnings/1793285464040-ir-layout-insts-are-hoisted-deduplicated-never-rem.md)) ([Slang IR layouts are deduplicated](../learnings/1793288360465-slang-ir-layouts-are-deduplicated-removeanddealloc.md)). The rule generalizes to any pass that rewrites layouts: when you replace a layout decoration, never free the layout it pointed to, because some other parameter or field may be the same inst.

## Testing this pass

Each regression above passed a green suite. The nested-layout bug passed the full suite because no test covered `Load`-only nested shapes; `/code-review medium` caught it ([same](../learnings/1793279115432-slang-forwarding-a-combined-sampler-op-through-ext.md)). The dedup segfault passed the PR's tests, the full suite, and a 1258-compile corpus, because no case paired a top-level combined global with a nested one at the same relative offset (the nested test led with a separate `Texture2D` and `SamplerState`, whose layout differs). Reviewer A found it by reading the code, and a one-minute probe confirmed it ([same](../learnings/1793284649930-nested-layout-rebuild-prs-probe-a-top-level-combin.md)). The probe set that covers these cases:

- `Sample` and `Load` on a combined sampler inside each container kind (`cbuffer`, `ConstantBuffer<S>`, `ParameterBlock<S>`, struct, `uniform S`, entry-point `uniform`), with at least two samplers so the register index is non-zero ([same](../learnings/1793280887943-a-forward-that-adds-combinedtexturesamplergettextu.md)).
- A top-level parameter and a nested field whose relative offsets are identical, so two positions produce one deduplicated layout ([same](../learnings/1793288360465-slang-ir-layouts-are-deduplicated-removeanddealloc.md)).
- Debug and Release builds. `SLANG_ASSERT` is compiled out of Release, so a Release-only diff can look byte-identical while Debug asserts, and a Release rc=0 can hide a lost binding ([same](../learnings/1793297505956-lowercombinedtexturesamplers-never-lowers-an-unuse.md)) ([same](../learnings/1793294161029-moving-a-combined-sampler-op-onto-extractimage-get.md)).
- Bindings checked against `-reflection-json`. "DXC accepts it" proves nothing, because HLSL with no `register()` still compiles (DXC auto-binds); compare the DXIL binding table (`-pass-through dxc ... -target dxil-assembly`, the `; Name ... HLSL Bind` rows) with reflection ([same](../learnings/1793285464040-ir-layout-insts-are-hoisted-deduplicated-never-rem.md)).

One run-environment note from the same PR: a parallel `slang-test -server-count 24` on a shared GPU produced 42 spurious CUDA failures, which a serial rerun cleared ([same](../learnings/1793280887943-a-forward-that-adds-combinedtexturesamplergettextu.md)).
