# Slang Intrinsics & Builtins

Slang exposes GPU intrinsics and builtin types as core-module declarations (`core.meta.slang`, `hlsl.meta.slang`, `glsl.meta.slang`). Most bugs here come from how they map to each target at emit time and from their capability atoms.

## TL;DR

- **`$TR` in an `__intrinsic_asm` string emits the call's RETURN type; `$T<n>` emits operand n's type and unwraps a texture to its element type.** Use `$TR` when the result type must be spelled.
- **`__intrinsic_type` and `__intrinsic_op` are legal in user code** (E31229 covers only `__magic_type`, `__builtin_type`, `__builtin_requirement`); DeepWiki's "core-only" is wrong. A bogus `__intrinsic_op(1000)` is not range-checked and ICEs.
- **An emitter rule keyed on `intrinsicDefinition.startsWith(...)` also matches user `__intrinsic_asm` text**, so arity and operand type are filters (`return nullptr`), never asserts. "Fail loudly" applies only to compiler-produced shapes.
- **A marker that remaps `$N` (`$q` skips a combined sampler's split-out sampler) must also be applied in `shouldFoldInstIntoUseSites`**, or multiply-used arguments are folded into every use and chained calls grow exponentially.
- **`float(sign(x))` on SPIR-V is an unfolded `FSign; FToS; SToF` chain.** Folding to bare `FSign` changes the sign of zero; the exact rewrite is `FSign(x) + 0.0`, and a peephole needs the casts outside the `spirv_asm`.
- **Dot-form `__intrinsic_asm ".Method"` on a `void` method discards a value-returning target op**; capture it (`this = __hlslSplat(t);`, precedent `__hlslLoadBAB`).
- **The `$P` prefix expander has no vector case**, so generic `min`/`max` on a vector or matrix hits E99997; a `default:`-arm diagnostic misses prefixed element types lacking a vector helper (`intptr_t`, `int16_t`).
- **Overload resolution in a generic body is not redone after specialization**, so a scalar-decomposition fallback overload costs generic callers the native vector/matrix op. Use one shared target-aware `[ForceInline]` worker.
- **Builtin vector/matrix types ARE `DeclRefType<StructDecl>`**; init-list coercion goes through `createInvokeExprForExplicitCtor`, whose viability must not depend on `outExpr`.
- **`float4(float2 xy, 1.f)` is `(x,y,1,1)` (scalar splat), not `(x,y,1,0)`**; the preserving rewrite is `float4(xy, 1.f, 1.f)`.
- **`|`/`&`/`^` work on `[Flags]` enums (via `ILogical`) but `|=`/`&=`/`^=` do not**; add generic compound operators over `T : ILogical` with `[OverloadRank(-10)]`.
- **The builtin-operator fast path shadows a user operator on builtin operands; the maintainer wants an ERROR.** A check mirroring another site SHARES the predicate, hardened with explicit cases plus `SLANG_UNEXPECTED`.
- **`static_assert` is a builtin function, valid only in a function body**; at global scope any `ident(...)` mis-parses as a declaration.
- **A gather offset branches on CONSTNESS** (`ConstOffset` vs `Offset`+`ImageGatherExtended`); a negated constant folds to a constant.
- **A `groupshared T[N]` PARAMETER lowered by-value loses TGSM on DXIL.** Fix at parameter lowering (`BorrowInOut`); detect GPU-free with `slangc -target dxil-asm`.
- **Only the (GroupShared, parameter) arm of the variable-pointers signature walk is fail-without-fix**; document the untested arms.
- **An instantiation-dependent capability cannot be a static `[require]`**; gate `__requireTargetExtension(...)` at emit time with a base atom in `[require]` (precedent `GetDimensions`).
- **E41012 for a `[require]` attribute comes from the AST check in `slang-check-shader.cpp`, not `LateRequireCapability`.** Also audit the `glsl.meta.slang` `texelFetch` wrappers' own `[require]`.
- **Renaming a shared capability atom is not behavior-neutral: ADD a new atom and RE-POINT**; public aliases need `///` docs and a doc regen. The shadow-LOD BIAS boundary is narrower than the LOD boundary.
- **A family's latest-version atom is `getElements()[count-2]`** (`-1` is the stage atom). Capability predicates lack `SLANG_API`; test via `.slang`.
- **`__requireCapability` and compound `alias` exist; no generic `IRRequireTargetCapability` op; generic-dependent `[require]` is unsupported.** A capability RFC under owner debate is not fix-eligible.
- **A single-struct SSBO works today as `typealias RWStorageBuffer<T> = GLSLShaderStorageBuffer<T>;`** (hidden core type, all targets); omit the layout argument, since an explicit `Std430DataLayout` fails with E36107 off SPIR-V/GLSL.
- **On CPU/LLVM `half` is the fallback `struct half` with only `explicit operator float()`**; add explicit scalar conversions, not native `_Float16`.
- **A new texture access kind needs a case in EVERY emitter** (GLSL/WGSL fall to sampled; SPIR-V has no default). GLSL `image2D` IS `RWTexture2D<float>`, so key alias diagnostics on the spelling; `readonly RWTexture*` is not enforced.

## `__intrinsic_asm` markers and dot-form methods

`$TR` emits the call's return type (`m_callInst->getDataType()`); `$T<n>` emits operand n's type and unwraps an `IRTextureType` to its element type, the usual source of element-vs-vector texture bugs. On #12276, CUDA `Texture2D<float>.Gather` emitted `tex2Dgather<$T0>` = `tex2Dgather<float>` into a promised `float4` (NVRTC error); `tex2Dgather<$TR>` yields exactly `vector<T.Element,4>` (precedent: `llvm bitcast`). Repro: `slangc -target ptx` ([$TR marker emits the call return type](../learnings/1785372605179-intrinsic-asm-tr-marker-emits-the-call-return-type.md)).

A dot-prefix `__intrinsic_asm ".Method"` on a `[mutating] void` method emits `receiver.Method(args)` as a bare statement and drops its value. On #12059 HLSL `Matrix::Splat(T)` returns a value, so `CoopMat.fill(t)` left the destination uninitialized (PSO-creation crash). The fix follows `__hlslLoadBAB`: an `internal static This` helper wrapping `$TR::Splat($0)`, used as `this = __hlslSplat(t);`; editing `hlsl.meta.slang` needs the core-module-header regen ([HLSL CoopMat fill/Splat dot-form discards value](../learnings/1783725139961-slang-12059-hlsl-coopmat-fill-splat-dot-form-intri.md)).

## Intrinsic modifiers in user code, and emitter rules keyed on intrinsic text

User code may use `__intrinsic_type` and `__intrinsic_op`. E31229 (#12538) rejects only `__magic_type`, `__builtin_type` and `__builtin_requirement` outside the core module. Standard modules use both without `FromCoreModuleModifier`, so an `isFromCoreModule`-only gate would break them; DeepWiki's "core-only" claim is wrong. `parseIROp` does not range-check numeric opcodes: `__intrinsic_op(1000)` gives E99997 in Debug and "Unhandled local inst in spirv-emit" in Release. The "never used by an application" spec sentence lives in shader-slang/spec (`introduction-language-evolution.md:83-84`), so changing it needs a spec-repo PR [__intrinsic_type/__intrinsic_op are accepted in user code](../learnings/1792065241922-intrinsic-type-intrinsic-op-are-accepted-in-user-c.md).

So an emitter hook such as `emitIntrinsicCallExprImpl(inst, intrinsicDefinition, ...)` also sees user text, and a rule keyed on `intrinsicDefinition.startsWith("<builtin>")` matches it. On #13670 a reviewer turned the filter `&& inst->getArgCount() == 1` into `SLANG_RELEASE_ASSERT`; a valid two-argument user `__intrinsic_asm "unpack2x16float(($0) | (($1) << 16u))"` then hit E99997, and a one-argument `int` user intrinsic was wrapped in a `u32`-only WGSL helper that Tint rejects. Arity and operand type are preconditions (`if (argCount != 1) return nullptr;` plus e.g. `getDataType()->getOp() == kIROp_UIntType`); exact-string matching narrows the trigger but still needs the filter. Pin with a revert-drilled test row of same-prefix user intrinsics. User-writable text is never out of contract [emitter rules keyed on an intrinsic-string prefix must filter](../learnings/1792104381131-emitter-rules-keyed-on-an-intrinsic-string-prefix-.md).

`CLikeSourceEmitter::shouldFoldInstIntoUseSites` also reads intrinsic text: it counts `$N` uses by raw operand index to decide inlining. A remapping marker like `$q` (skips the split-out sampler at operand 1 of a combined texture-sampler) must be honored there, or a multiply-used argument looks unused and is folded into every use: 5 chained combined-sampler `Load`s on Metal/WGSL produced 121 texture reads. #13741 adds one shared `getIntrinsicArgOperandIndex()` in slang-intrinsic-expand.cpp for both readers [$q intrinsic strings must also be understood by the emitter's fold heuristic](../learnings/1792284128530-q-intrinsic-strings-must-also-be-understood-by-the.md).

## `sign()` round-trip on SPIR-V (#13676)

HLSL `sign()` returns `int`, so float `sign` lowers to one opaque `spirv_asm { FSign; OpConvertFToS }`; `float(sign(x))` adds `OpConvertSToF`, which neither Slang IR nor spirv-opt folds. The round-trip yields only {-1, +0, +1}, while bare `FSign` returns -0.0 for -0.0 and anything in ±1/±0 for NaN, so folding to `FSign` changes the sign of zero (fast-math-only, #12405). The exact rewrite is `FSign(x) + 0.0`, which spirv-opt drops at -O1+ unless `NoContraction` (precise mode) or float-controls apply; `FSign` never returns NaN, so `OpConvertFToS` is always defined. DXC gives 0 for NaN and -0; cpp/cuda `F32_sign` gives 1 for NaN. For an IR peephole to see the casts, split out a `[__readNone]` FSign-only asm helper plus `__float_to_int_cast`, ForceInline the wrapper, and recognize the helper via `KnownBuiltinDeclName` + `getBuiltinFuncEnum`. Separately, GLSL-language mode has no float `sign`, so GLSL `sign(x)/2` becomes integer `OpSDiv`, a correctness bug [float(int(FSign(x))) == FSign(x)+0.0 exactly](../learnings/1792095513009-float-int-fsign-x-fsign-x-0-0-exactly-spirv-opt-fo.md).

## The `$P` prefix expander and generic vector/matrix `min`/`max` (#11075, PR #12249)

A generic `T:IFloat`/`IComparable` `min`/`max` specialized on a vector ICEs (E99997) on `-target cpp`/`cuda` (regression from #9593). Concrete overloads decompose via `VECTOR_MAP_BINARY`; the generic path emits one whole-vector `$P_min`, and `case 'P'` in `slang-intrinsic-expand.cpp` has no vector case. A meta.slang-only fix fails; the authorized fix unwraps `IRVectorType` before the switch, adds vector-arity prelude helpers (CPU `template<int N>`, CUDA explicit 2/3/4), and folds the `kIROp_IsVector` peephole on the pre-unwrap type. Gotchas: `slang-embed` follows `#include` (prelude edits need a fresh worktree); include order forces a `Vector<T,N>` forward-decl; a draft-PR `gh workflow run ci.yml` shows a benign priority-yield "failure" ([$P prefix + vector min/max fix layer](../learnings/1785207760204-slang-p-prefix-vector-min-max-fix-layer-prelude-em.md)).

The matrix sibling crashes the same way (`$P_max` on a matrix falls to `default:`); it is pre-existing and outside vector scope, so blocking on it is a scope call ([matrix sibling crash left by vector fix](../learnings/1785210150352-slang-p-vector-min-max-fix-leaves-matrix-sibling-c.md)). The round-2 `E55215` diagnostic in `default:` catches only element types with no prefix; prefixed types without a vector helper (`intptr_t`→IPTR, `int16_t`→I16, via `vector<intptr_t,N>:IInteger`) slip to "undeclared identifier". Verdict: APPROVE_WITH_NITS ([E55215 misses prefix-having element types](../learnings/1785214611295-slang-12249-round-2-e55215-diagnostic-misses-prefi.md)).

**A scalar-decomposition fallback overload costs generic callers the native aggregate op.** A low-rank broad `min<T:__BuiltinArithmeticType, let N:int>(vector<T,N>, vector<T,N>)` with a `VECTOR_MAP_BINARY` body leaves concrete callers fine (the narrow overload wins on rank), but overload resolution in a generic body is not redone after specialization, so every generic caller gets per-element scalar ops (no SPIR-V `FMin`/`SMin`, no HLSL `min`). The maintainer's #13139 (closing #13114) routes the int, float and broad families through shared target-aware `[ForceInline]` workers (`__vectorMinImpl`, `__matrixMinImpl`), so all get native ops and matrices keep their `MatrixLayoutMode`; cover matrices as well as vectors ([core-module: a broad generic overload that decomposes to scalars loses aggregate intrinsics for generic callers](../learnings/1790642295187-slang-core-module-a-broad-generic-overload-that-de.md)).

## Builtin vector types and constructor resolution

Builtin vector/matrix types are `DeclRefType<StructDecl>`, so init-list coercion goes through `createInvokeExprForExplicitCtor` (the struct branch of `_coerceInitializerList`), not `createCtorInvokeExprForAbstractType`. On #11730 its viability `return true` was nested under `if (outExpr)`; the `canCoerce` probe passes null, so `{float2, float}` failed as an argument but worked in a declaration. The fix reports viability independently of `outExpr` ([builtin vector is a DeclRefType&lt;StructDecl&gt;](../learnings/1782733705823-slang-11730-builtin-vector-is-a-declreftype-lt-str.md)).

`float4(float2 barycentrics, 1.f)` splats `1.f` to `float2(1,1)` and resolves `__init(vector<T,2> xy, vector<T,2> zw)` → `(x,y,1,1)`, not a tail-pad. The slang-rhi#798 fix `float4(barycentrics, 1.f, 1.f)` resolves `__init(vector<T,2> xy, T z, T w)` to the identical value, keeping the ray-tracing test unchanged. It unblocks #12141, whose `static_assert(false)` on the `(vec2,T)` ctors for `vector<T,4>` would otherwise make the call E41400 ([float4(float2,1.f) splat vs tail-pad](../learnings/1784281175141-slang-rhi-798-float4-float2-1-f-splat-vs-tail-pad-.md)). The same design-gated divergence is #12093; see [[wiki/concepts/slang-language-generics-and-type-system.md]].

## A single-struct SSBO today: `typealias` over the hidden `GLSLShaderStorageBuffer<T>` (#11028)

Users keep asking for `RWStorageBuffer<T>` / `StorageBuffer<T>` as a single-struct SSBO (#11028: open, assigned to jkwak-work, no milestone). The core module already has a hidden type for it, `GLSLShaderStorageBuffer<T, L = DefaultDataLayout>` (`hlsl.meta.slang:73-77`, `//@hidden`), and `typealias RWStorageBuffer<T> = GLSLShaderStorageBuffer<T>;` lets user code write `buf.field` with no `[0]`. Checked compile-only on v2026.20: SPIR-V gets a StorageBuffer `Block` with std430 offsets and no runtime array, which passes spirv-val; GLSL gets a `layout(std430) buffer` block; HLSL gets a `RWStructuredBuffer<T>` indexed `[0]`, WGSL a storage `array<T>` indexed `[0]`, Metal a `device*`, and CUDA compiles too. Omit the layout argument: with an explicit `Std430DataLayout` only SPIR-V and GLSL compile, and the other targets fail with E36107. There is no read-only variant; the plan in #11028 is to rename the type to `RWStorageBuffer<T,L>` and add `StorageBuffer<T,L>` ([non-array storage buffer today: typealias over GLSLShaderStorageBuffer<T>](../learnings/1792916435475-non-array-storage-buffer-today-typealias-over-hidd.md)).

## Builtin operators: fast path, shared predicates, and flag enums

Since #11493, `convertToBuiltinArithmeticOp` (`slang-check-expr.cpp`) rewrites `a OP b` on builtin scalar/vector/matrix operands to a `BuiltinOperatorExpr` before overload resolution, silently dropping a user `operator*(float4x4,float4x4)` (#11877); the maintainer wants that declaration to be an error ([fast path: maintainer wants ERROR not honor](../learnings/1784156401458-slang-11493-fast-path-user-operator-on-builtin-ope.md)).

PR #12162 (`pr: breaking change`) adds the declaration-site diagnostic, which must reject exactly what the fast path shadows. Reviewers gated it on collapsing the per-operator element-eligibility ladder (bitwise/shift→int; equality→int|float|bool; logical-not→bool; arithmetic→int|float), written three times, into one predicate `isBuiltinOperationKindEligibleForBaseType(BuiltinOperationKind, BaseType)` beside `getBuiltinOperationKindFromString`. A "// matches X" comment is the signal to extract; harden with explicit cases plus `[[noreturn]]` `SLANG_UNEXPECTED`, not a plausible `default:`. Tests matter most on the new `this`-receiver branch; a widely included header means a broad recompile and regression sweep ([share the mirrored predicate](../learnings/1784627727954-slang-when-a-check-must-mirror-the-fast-path-share.md)).

Binary `|`, `&`, `^` work on `[Flags]` enums because they are generic over `T : ILogical`, which enums conform to; the compound forms come from `kCompoundBinaryOps`, constrained on `__BuiltinLogicalType`, which enums do not. The fix adds generic `operator|=/&=/^=` over `T : ILogical` in `core.meta.slang` with `[OverloadRank(-10)]` to avoid ambiguity for builtin integers. `a |= b` resolves by named-function overload lookup, not a checker desugar ([flag-enum compound-assign gap](../learnings/1781621242788-slang-flag-enum-compound-assign-gap-ilogical-vs-bu.md)).

## `static_assert` is function-body only (#13208)

`static_assert(cond, msg)` is a builtin intrinsic function (`__intrinsic_op(kIROp_StaticAssert)`), not a keyword, so it is valid only as an expression-statement in a function body. At module scope (`parseDecls`→`ParseDeclWithModifiers`) it is consumed as a type name, `(` commits to a function declarator, and the arguments fail with a misleading `unexpected '(', expected ')'`; module scope has no decl→expr backtrack, so any global `ident(...)` mis-parses (a usable signal for a tailored diagnostic). Any-scope support is #6136 (a syntax-decl plus module-level `kIROp_StaticAssert`; the emit-time checker already recurses the module) ([static_assert is function-body only](../learnings/1790019025315-slang-static-assert-is-a-builtin-intrinsic-fn-func.md)).

## Texture access kinds: every emitter, and aliases that share a type (#13536)

Texture access is `kCoreModule_ResourceAccess*` 0-4. Emitters do not reject unhandled values: GLSL and WGSL fall into sampled `texture`, and the SPIR-V `Sampled` switch has no default, its `SLANG_ASSERT` becoming `SLANG_ASSUME` in Release. A new kind (#13536's `RTexture*`) needs an explicit case in each. GLSL `image2D` is the same type as `RWTexture2D<float>` (`_Texture`, access 1), so a `readonly RWTexture*` diagnostic must key on the spelled alias. `readonly` on `RWTexture2D` only emits `NonWritable`; stores still compile everywhere. `WTexture2DMS` is missing because the alias generator (`hlsl.meta.slang:6130`) compares access against a shape constant. Re-read an issue before posting a triage (#13536 was retitled after its webhook) ([texture access kinds: adding one needs every emitter; image2D == RWTexture2D](../learnings/1791500273983-slang-texture-access-kinds-adding-one-needs-every-.md)).

## Texture gather: `ConstOffset` vs `Offset` (#9382)

`Texture2D.Gather(s, uv, int2(2,1))` emits SPIR-V `Offset` plus `ImageGatherExtended` instead of `ConstOffset`. Switching wholesale is unsafe because GLSL `textureGatherOffset` can pass a runtime offset through the same intrinsic; branch on constness. Two stale draft PRs exist ([naive ConstOffset fix unsafe](../learnings/1781713033202-slang-9382-gather-constoffset-naive-fix-unsafe-two.md)). A negated constant (`-int2(2,1)`) is `Neg(MakeVector(...))` at spirv-legalize but later folds to `int2(-2,-1)` and takes `ConstOffset`, with the capability lingering as a pre-existing limitation; asserting `Offset`+capability for it would lock in the bug ([negated constant offset folds](../learnings/1781731175811-slang-9382-negated-constant-gather-offset-int2-2-1.md)).

## GroupShared / TGSM on DXIL (#10641)

A `groupshared T scratch[N]` parameter, unlike a global, was lowered by-value (`In`) in `getExplicitlyDeclaredParamPassingMode`, giving a per-thread `alloca` without `addrspace(3)` on DXIL, so sharing silently failed; SPIR-V keeps a `Workgroup` pointer and was fine ([groupshared param lowered by-value](../learnings/1782228288994-groupshared-array-parameter-lowered-by-value-loses.md)). PR #11709 lowers bare `groupshared` params (`HLSLGroupSharedModifier`, no `InModifier`) to `BorrowInOut`; the HLSL emitter strips the DXC-illegal `groupshared inout` except for mesh payload params, which carry `IRGroupSharedRate` but need `in payload`. Extending `specializeAddressSpace` to DXIL was falsified as the fix layer ([fix is by-reference lowering](../learnings/1782228568362-slang-10641-groupshared-array-param-bug-fix-is-by-.md)). GPU-free repro: `slangc -target dxil-asm`, where zero `addrspace(3)` globals plus `alloca [N x ...]` proves the bug, with a plain groupshared global as positive control ([detect TGSM bugs without a GPU](../learnings/1782216962036-detect-groupshared-tgsm-codegen-bugs-on-dxil-witho.md)).

## Variable pointers (SPIR-V, PR #11521)

`requireFunctionTypeCapabilitiesIfNeeded(IRFuncType*)`, called from `emitFunc`, sends the result and parameter types to `requireVariableBufferCapabilityIfNeeded`, declaring `SPV_KHR_variable_pointers`/`VariablePointers` for a `Workgroup`/`StorageBuffer` pointer that survives only in a non-inlined signature. Only (GroupShared, parameter) fails without the fix: the result-type arm is covered by `emitCall` and `StorageBuffer` by `emitGetOffsetPtr`/`emitGetElement`, so document that rather than add passing tests ([only (GroupShared, parameter) is fail-without-fix](../learnings/1780972705906-slang-variable-pointers-signature-walk-fix-only-gr.md)).

## Capability atoms on texture methods and E41012

An instantiation-dependent capability (bare vs. combined sampler) cannot be a static `[require]`, which cannot reference a generic `let isCombined`. Gate `__requireTargetExtension(...)` on the generic at emit time and keep a non-extension base atom (`texture_sm_4_1`) in `[require]`, as `GetDimensions` does. `Texture.Load`'s unconditional `[require(..., texture_sm_4_1_samplerless)]` disagreed with its gated `if(isCombined==0)` GLSL emission, firing spurious `warning E41012 (ProfileImplicitlyUpgraded)` on combined samplers under `-profile` ([spurious E41012 from static require](../learnings/1782889962730-spurious-e41012-profile-upgrade-warning-static-req.md)). The warning comes from the AST check in `slang-check-shader.cpp` (gated on an explicit capability/profile request), not the IR `LateRequireCapability` pass (only the `__requireCapability` statement), and the AST path cannot see generic lets ([E41012 comes from slang-check-shader.cpp](../learnings/1782895560951-e41012-from-a-require-attribute-comes-from-slang-c.md)).

That check fires for any `[require]`-annotated inlined FuncDecl, so editing only `.Load`/subscript in `hlsl.meta.slang` is incomplete: the `[ForceInline]` `texelFetch(...)` wrappers in `glsl.meta.slang` carry their own samplerless `[require]`, several hardcoded-combined. `grep texture_sm_4_1_samplerless source/slang/glsl.meta.slang` and decide explicitly. Dropping a stdlib atom can flip generated "DO NOT EDIT" `-restrictive-capability-check` negative tests red→green; fix the generator and regenerate ([also check glsl.meta texelFetch wrappers](../learnings/1782898835005-fixing-a-capability-require-atom-on-a-texture-meth.md)).

## Shadow-texture capability atoms (#12244)

The `GL_EXT_texture_shadow_lod` bias boundary is narrower than its explicit-LOD boundary, so do not reuse the `texture_shadowlod_ext` LOD shape list for bias. Bias `texture`/`textureOffset` is core GLSL 1.50 for `sampler1D/1DArray/2DShadow` and `samplerCubeShadow`; the extension adds only `sampler2DArrayShadow`/`samplerCubeArrayShadow` bias, and `textureGrad*` on shadow samplers is core. `SampleCmpLevel` is SM6.7, `SampleCmpBias`/`SampleCmpGrad` SM6.8 ([bias boundary ≠ LOD boundary](../learnings/1785190567550-gl-ext-texture-shadow-lod-bias-form-boundary-expli.md)). Renaming `texture_shadowlod`→`texture_shadow` is wrong because the atom is shared (~14 `SampleCmp*` sites plus ~57 GLSL `textureLod`/`texture` overloads). Add `texture_shadow`/`texture_shadowbias` equal to the current expansions and re-point only the SampleCmp methods; atom names are user-exposed, so a new public alias needs `///` docs and a doc regen ([rename = re-point](../learnings/1785192528373-samplecmp-capability-atom-rename-re-point-not-rena.md)).

## Capability system internals

To derive a family's latest version atom from a `_*_latest` alias, mirror `getLatestSpirvAtom()`/`getLatestMetalAtom()`: `elements[elements.getCount() - 2]`, because a version alias's `CapabilitySet` includes a stage atom that sorts above all version atoms. Max-atom scans grab the stage atom; gap-walk scans segfault. `isSpirvExtensionAtom` and the family predicates lack `SLANG_API`, so a `slang-unit-test` caller fails to link; test via `.slang` ([latest-version atom = count-2](../learnings/1784424625402-slang-capability-latest-version-atom-helper-must-u.md)).

Current-system facts for capability RFC triage (#9210): statement-level `__requireCapability(...)` → `RequireCapabilityStmt` exists; there is no generic `IRRequireTargetCapability` op (only GLSL/WGSL-extension decorations plus `LateRequireCapability`); `[require]` is `RequireCapabilityAttribute`, propagated by `_propagateRequirement` with the caller-⊇-callee check `CapabilitySet::checkCapabilityRequirement`; `CapabilitySet` is a disjunction of conjunctions (`CapabilityTargetSets → CapabilityStageSets → CapabilityAtomSet`); compound capabilities exist as `alias` in `slang-capabilities.capdef`. Defects #11631 and #11903 corroborate the RFC; generic-parameter-dependent `[require]` is unsupported. While owners debate, park it with a neutral 5-bullet recording both directions and no fixer dispatch ([capability RFC #9210 facts](../learnings/1783523347890-slang-capability-rfc-9210-current-system-facts-tha.md)).

## CPU/LLVM `half`: no half→integer conversion (#11996)

`SLANG_LLVM` gates out the native `_Float16` block in `prelude/slang-cpp-scalar-intrinsics.h`, so CPU/LLVM `half` is the fallback `struct half` with only `explicit operator float()`. `(int8_t)half` lowers to one `kIROp_CastFloatToInt` emitted as `int8_t(halfValue)`, which fails, because an explicit `operator float()` does not chain through one cast; `(int8_t)(float)h` compiles. Approach A adds `explicit` operators (int8-64 signed/unsigned, double, bool) via `load()`; native `_Float16` on LLVM is rejected (unsupported on some host triples, high blast radius) ([CPU half has only operator float](../learnings/1783511746989-slang-cpu-half-struct-has-only-operator-float-half.md)).
