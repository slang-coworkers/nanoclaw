# Slang Compiler Crash & Legalization Probes

## TL;DR

Verified root-cause traces for Slang compiler crashes/miscompiles, all resolved at the producer/IR layer rather than by masking in emit. Common shape: an early classifier or lowering pass mishandles an input shape, and the crash surfaces far downstream in codegen or the linker.

- **`if(decoration){ if(sv_){...} }` with the real work in the sibling `else` silently drops the middle case**: the tess patch-constant Location-0 collision is a fall-through, NOT a shared-counter race; `kIROp_PatchDecoration` gives per-patch vars a separate location set. Verify by IR dump.
- **A zero-size/void struct field has no byte-address skip**, so `.Load<void>` is emitted; add a natural-size-0 skip in the `emitLegalLoad`/`emitLegalStore` field loops.
- **`getDefaultVal` on an `AssocTypeDecl` built a zero-operand `IRMakeStruct`** (positional OOB after type-flow specialization). Fix producer-side with `emitDefaultConstruct`; assert the consumer with EXACT `==`.
- **Collect only bracketed attributes where a decl name can be a bareword modifier keyword** (`ParseModifiers` broke `enum FilterMode { point, linear }`).
- **Array + ConstantBuffer + resource element** crashes type-legalization: `legalizeGetElement` (value path) has no `implicitDeref` case. The trigger is the resource, not "zero-size."
- **A non-null `IRPtrLit` reaching the linker** is a `HighLevelDecl` decoration on a late-synthesized inst that escaped `stripFrontEndOnlyInstructions` (front-end lowering only). Fix the producer; don't relax the linker assert.
- **`IREntryPointDecoration` relocation** has two seductive-but-wrong companion fixes; `SLANG_ASSERT(x); if(!x)…` is DEAD in Release (`SLANG_ASSERT` is an assume there).
- **An entry point with a `uniform` param, called by another compiled entry point, segfaults on every target** (open on master): before `fixEntryPointCallsites` only the borrow pass updates callers; the uniform-param hoist and `translateGlobalVaryingVar` change arity silently.
- **Before turning a fallback into a `SLANG_RELEASE_ASSERT` on a closed set of IR layout shapes, list the `IRTypeLayout` subclasses and probe each** (existential via `slangc -specialize`, pointer, combined-sampler, DescriptorHandle); run the full suite after adding it.
- **Zero coverage-drill hits show the suite does not reach a branch, not that no input does**: they justify deleting dead guards, not asserting (#13872's 0-hit release assert ICEd dynamic-dispatch generics at `-g2`). Audit the producer class first, or keep a graceful fallback plus a `-validate-ir` rule.
- **A last `-dump-ir` "AFTER X" does not mean X finished**: `PassHooksRAII` prints it during exception unwind; `-dump-ir-before <next pass>` printing nothing confirms the crash is inside X.
- **"Guard A subsumes guard B" is a claim about the FULL consumer set of each**: a `static_assert` reachability walk and `isFromCoreModule` cover disjoint consumers; keep both.
- **Inherited-field access through a BoundMember/BoundStorage base (#13348) needs `InheritanceDecl` at all three `BoundMemberInfo` consumers**, not just `materialize`.
- **`CoerceToProperTypeImpl` has THREE failure representations**: normalize at the wrapper.
- **CUDA surface-stride-through-a-param** is a documented structural limitation (`_findImageFormat` can't see `[format]` through an `IRParam`), NOT a regression.
- **A partial-init struct's spurious varying store is `fieldExtract(load(var))`, not `IRUndefined`**; handle both shapes in glsl-legalize's `assign`.
- **Nested swizzle-of-swizzle vector lvalue** miscompiles from `.add(count)` (should be `.setCount`) plus a by-value lambda output param (should be `auto&`).
- **A full-coverage texture swizzle store (`t[i].xyzw = v`) is lowered as read-modify-write**: fix in `legalizeStore`, measuring coverage against the image op's texel (4-wide on Metal/GLSL/SPIR-V, `T` on CUDA). Plain `t[i] = v` lowers through the `set` accessor, so test both spellings.
- **On HLSL/CPU/CUDA a spec-const `[numthreads]` operand is a removed inst with a null type**; any pass reading its type before emit segfaults (see [[wiki/concepts/slang-compiler-specialization-constants-across-targets.md]]).

## Front-end / classifier fall-throughs that crash downstream

The tess patch-constant Location-0 collision is a classifier fall-through, correcting an earlier "shared counter race" framing. In `createPatchConstantFuncResultTypeLayout` (`slang-ir-glsl-legalize.cpp:1181-1199`) a field with any `IRSemanticDecoration` enters the outer `if`, only `sv_`-prefixed names do work there, and the `getLSBZero()` VaryingOutput allocator lives in the sibling `else` (no-semantic fields only). A *user* semantic like `PATCH_LINE` reaches neither branch, gets no offset, and defaults to Location 0, colliding with per-control-point output. The shared `usedBindingIndex` counter is untouched, so adding `kIROp_PatchDecoration` (→ `SpvDecorationPatch`) alone clears the standalone-validation failure, since Patch-decorated vars occupy a separate location set ([3-way classification gap](../learnings/1787640266798-slang-tess-patch-constant-user-output-location-bug.md), [CORRECTION: fall-through](../learnings/1787641994236-correction-user-patch-constant-field-misses-locati.md)). Check for an `if(decoration){ if(sv_){} }` with no inner `else` before blaming a shared allocator, and disambiguate with `-dump-ir`.

`getDefaultVal(Type*)` is the producer for a latent positional OOB (#12132). `AssocTypeDecl` derives from `AggTypeDecl`, so `T.Assoc x = {}` built a zero-operand `IRMakeStruct` over the opaque associated type; once type-flow specialization resolves it to a real struct, `analyzeMakeStruct` reads `getOperand(i)` positionally → OOB. Add an `AssocTypeDecl` branch calling `emitDefaultConstruct` (mirroring the `InterfaceDecl` case) and assert the consumer with EXACT `==`, not `min()`, which would mask a future under-supplying producer ([empty IRMakeStruct](../learnings/1787585281811-slang-getdefaultval-on-assoctypedecl-built-an-empt.md)).

`ParseModifiers` on a name-first decl position is source-breaking. On slang#12551 (attributes on enum members) it accepted bareword modifier keywords, so the long-valid `enum FilterMode { point, linear }` started erroring. Collect ONLY bracketed `[...]` attributes via `ParseSquareBracketAttributes` wherever the identifier can be a bareword modifier, which also closes the silent-accept gap where `isModifierAllowedOnDecl` has no policy for the new decl kind; test with a case named `point`/`linear` ([ParseModifiers breaks valid code](../learnings/1787558855449-parsemodifiers-on-a-decl-whose-name-can-be-a-barew.md)).

## Type legalization, linking, and Release-guard traps

`ByteAddressBuffer.Load<Item>` with `Item { float a; Empty b; }` emits `.Load<void>` for the empty field (DXIL "external function", SPIRV divide-by-zero from stride 0). Add a zero-size skip (`getNaturalSizeAndAlignment`) in the `emitLegalLoad`/`emitLegalStore` field loops, mirroring buffer-element-type lowering's void-field skip ([Load<void>](../learnings/1787580105549-byteaddressbuffer-load-of-struct-with-empty-zero-s.md)). Separately, `ConstantBuffer<Foo> arr[N]` where `Foo` contains a resource crashes type-legalization on all targets: `Foo` legalizes to a non-simple `LegalType`, array-wrapping distributes it, and `legalizeGetElement` handles none/simple/pair/tuple but not `implicitDeref` (unlike `legalizeGetElementPtr`). The mixed bytes+resource case crashes too ([array of ConstantBuffer](../learnings/1787601573078-array-of-constantbuffer-with-resource-element-cras.md)).

A non-null `IRPtrLit` at the linker asserts because a raw front-end `Decl*` is meaningless in a fresh target module. Its common producer is `addHighLevelDeclDecoration`, stripped by `stripFrontEndOnlyInstructions`, which runs ONLY during front-end module IR generation, not inside `linkAndOptimizeIR`; a late-synthesized entry point that attaches one survives to trip the assert. Don't attach it late, or re-strip after late synthesis ([IRPtrLit at linker](../learnings/1787644362954-non-null-irptrlit-at-linker-a-highleveldecl-escapi.md)). The related `IREntryPointDecoration` relocation (stop attaching at module lowering; link-time `specializeIRForEntryPoint` is the single producer) has two regressive companions: moving `fixEntryPointCallsites` earlier (it asserts on un-specialized higher-order shapes), and hardening the constref pass's null-check to a RELEASE_ASSERT (a precompiled `-r` module from an older compiler bakes the decoration into serialized IR). `SLANG_ASSERT(x); if(!x) return false;` is DEAD in Release because `SLANG_ASSERT`→`__builtin_assume` licenses deleting the check ([two wrong companion fixes](../learnings/1787615422745-slang-entry-point-decoration-relocation-two-seduct.md)).

An entry point with a `uniform` parameter compiled together with another entry point that *calls* it segfaults (rc 139) on SPIR-V, CUDA and Metal: `[shader("compute")][numthreads(1,1,1)] void inner(int id : SV_DispatchThreadID, uniform int k)` called as `inner(id, 3)` from a second `[shader("compute")] outer`, with `slangc x.slang -target spirv-asm`. `-entry outer` alone works; master (8d763dd39) crashes too ([uniform-param entry point segfaults](../learnings/1790767202448-slang-compiling-a-uniform-param-entry-point-togeth.md)). **Why: in `linkAndOptimizeIR`, only the borrow pass updates callers.** Several passes change an entry point's signature in place before `fixEntryPointCallsites` (slang-emit.cpp:2079 at 837ab4c34) clones it into an ordinary function. `translateEntryPointInParamToBorrow` (:1100) fixes its call sites (`updateCallSites`, transform-params-to-constref.cpp:213); `collectEntryPointUniformParams`/`moveEntryPointUniformParamsToGlobalScope` (:1406/:1415) remove params, the crash above (Debug asserts `index < getParamCount()` at slang-ir.cpp:3168), and `translateGlobalVaryingVar` (:2073) adds a `BorrowInParam` for a global `in` (#13730 asserts at specialize-function-call.cpp:246, or segfaults in Release). The arg fix-up in fix-entrypoint-callsite.cpp:96-97 returns silently on a count mismatch. When a maintainer blames "in→constref in place", check which pass changed the arity with `-dump-ir-after fixEntryPointCallsites`. Design history: #8739 (the "Preferred Solution" trampoline; closed by #9869, which never built it) and #12392's comments (clone or forwarding wrapper at one split point after linking); no tracking issue as of 2026-10-19 ([only the borrow pass updates callers](../learnings/1792432625744-slang-entry-point-called-as-a-function-only-the-bo.md)).

**Turning a silent fallback into a `SLANG_RELEASE_ASSERT` needs every input shape probed, not a corpus run.** On #13811 (for #13789) R2 replaced the `return typeLayout;` fallback in `_createOrdinaryPartTypeLayout` (slang-ir-legalize-types.cpp) with `SLANG_RELEASE_ASSERT(as<IRPointerTypeLayout>(typeLayout))` because a probe saw only pointer layouts and 12k corpus compiles never reached it. But an `IRExistentialTypeLayout` arrives when an interface-typed parameter is specialized to a concrete type mixing data and resources, so Release reported E99997 on code master compiled; the existential+resource tests (tests/compute/interface-shader-param*.slang) are DISABLED or report "no tests run". Hand repro: `interface IFoo{float4 get();} struct Impl:IFoo{float4 v; Texture2D t; ...}` with `void main(uniform IFoo f, uniform float4 tint, ...)` and `slangc ... -specialize Impl`; a global `uniform IFoo` or an `IFoo` field in a CB/PB needs the API (`IComponentType::specialize` with `SpecializationArg::fromType(layout->findTypeByName("Impl"))`). Instrument the fallback to log which subclass reaches it (test `as<IRExistentialTypeLayout>` etc.; raw `getOp()` numbers do not match a naive parse of the fiddle enum) ([existential layouts reach it](../learnings/1792594670567-release-assert-catch-all-in-ir-layout-code-existen.md)). Start from the `IRTypeLayout` subclasses (struct, array, parameterGroup, pointer, existential, structuredBuffer, streamOutput, ...). Pre-legalization passes rebuild layouts, so AST-layout invariants may not hold: an earlier assert in the same PR ("every kind of the new element is in the old element") broke 3 combined-sampler tests, because `lowerCombinedTextureSamplers` builds `Sampler2D` struct layouts with field layouts but no size attributes. CI runs Debug jobs too, and some shapes (existentials with resources, a `Ptr<Struct-with-resource>` field) already hit the Debug-only `SLANG_ASSERT(fieldLayout || !typeLayout)` in the declareVars tuple case on master, so a `.slang` regression test fails Debug CI; use a unit test guarded by `#ifdef _DEBUG SLANG_IGNORE_TEST` ([enumerate the subclasses](../learnings/1792599445713-before-release-asserting-a-closed-set-of-ir-layout.md)).

**Zero coverage-drill hits do not license an assert.** The drill puts `{ FILE* f = fopen("/tmp/drill<pr>.txt","a"); if (f) { fputs("<tag>\n", f); fclose(f); } }` in each guard, rebuilds slangc and slang-test, runs `slang-test -use-test-server -server-count 16`, and counts tags with `sort | uniq -c` (test-server processes write to the same /tmp). On #13872 it showed in ~25 minutes that 4 of 8 new guards had 0 hits across 11k tests, concrete evidence for CLAUDE.md's "silent impossible-shape handling" rule ([coverage drill](../learnings/1792692531156-coverage-drill-log-each-defensive-branch-to-a-file.md)). The fixer then turned the SPIR-V emitter's graceful fallback for a stale `DebugVarStorage` decoration into a `SLANG_RELEASE_ASSERT`, and an audit of passes that clone a function's params before its body found `specializeGenericWithSetArgs`, which crashes ordinary user code at `-g2` (a dynamic-dispatch generic with an `inout` param) and which a `-g2` sweep of all 5310 tests also missed; mechanism on [[wiki/concepts/slang-backends-spirv-debug-info-emission.md]]. Audit the producer class first (grep `transferDecorationsTo|cloneDecoration|cloneInstDecorationsAndChildren`, look for clones that copy params ahead of the body); unless every producer is covered, prefer a `-validate-ir` rule plus a graceful fallback. `SLANG_ASSERT` expands to `[[assume]]` in release (`slang-common.h:371`), so a failed one is undefined behaviour, not a skipped check ([release assert creates user ICEs](../learnings/1792709180643-turning-a-silent-emitter-fallback-into-a-release-a.md)). A worktree's `git submodule update` from the local clone needs `git -c protocol.file.allow=always`, or it fails with "transport 'file' not allowed" ([same](../learnings/1792692531156-coverage-drill-log-each-defensive-branch-to-a-file.md), [corroborated](../learnings/1793331730063-glsl-extension-tracking-regression-tests-can-pass-.md)).

The `[numthreads]` spec-constant dangling-operand trap (#13767, PR #13826) is on [[wiki/concepts/slang-compiler-specialization-constants-across-targets.md]].

## Subsumption, wrappers, and value-shape completeness

"Guard A subsumes guard B" is a claim about the full consumer set each protects. On #12623 a transitive "never defer a func reachable from a static_assert" gate was claimed to subsume the producer-side `!isFromCoreModule` guard; the broad `tests/cuda` suite falsified it: core-module `[ForceInline]` helpers fold into consumers OTHER than static_assert (an intrinsic operand IR validation requires be an integer literal), which the use-site walk can't see. Keep both, and let the broad suite, not the one motivating test, expose a false subsumption ([does NOT subsume](../learnings/1787658437191-reachability-from-static-assert-does-not-subsume-a.md)).

The same question decides an inherited-field ICE (#13348). `h.p.baseField`, where `p` is a get/set or `ref` property/subscript returning `struct Derived : Base`, crashes lowering with E99997 "unexpected member flavor": `emitCastToConcreteSuperTypeRec` (`slang-lower-to-ir.cpp:7330`) calls `extractField` with an `InheritanceDecl`, which for a BoundMember/BoundStorage base defers into `BoundMemberInfo` (:1153-1167), and all THREE consumers of `BoundMemberInfo::declRef` accept `VarDecl` only: `materialize` (:1263 → abort :1278), `tryGetAddress` (:10288, silent fall-through) and `assign` (:10720 → :10741). A prototype accepting `InheritanceDecl` at all three, narrowed to struct bases (interface inheritance lowers to a requirement key at :11434), fixes every shape. `RWStructuredBuffer<Derived> buf; buf[0].baseField` fails too, read and write; get-only properties and `StructuredBuffer` reads are fine. Not a regression (2025.23.2 fails too). Validate with get/set or buffer shapes, since a user-written `ref` accessor still emits invalid HLSL/SPIR-V/CPU for the independent #9636. Under `-std 2026` user struct→struct inheritance is E30811, but core-module decls are exempt ([three consumers](../learnings/1790788517757-inherited-field-access-through-boundstorage-boundm.md)).

`CoerceToProperTypeImpl` fails three ways: null out-param, `getErrorType()` (only inside `if(diagSink)`), and `return false` leaving a stale non-null type. Normalize at the `CoerceToProperType` wrapper on the bool the Impl already returns; `tryCoerceToProperType` must keep returning null (overload resolution reads null as "candidate not viable") ([fix the wrapper](../learnings/1787657808750-coercetopropertype-null-vs-errortype-fix-the-wrapp.md)).

The CUDA surface-stride-through-a-param bug (#12737) is a documented structural limitation, reproducible from a plain `-target cuda` compile: `_findImageFormatDecoration` recovers `[format]` only from the resource's own inst or a load-of-global-field, never through an `IRParam`; the principled fix is producer-side specialization of formatted resource params, so DON'T label it `regression` ([structurally documented](../learnings/1787665524776-cuda-surface-stride-format-through-param-is-compil.md)). The partial-init struct-return spurious varying store (#12756) reaches emit as `fieldExtract(load(unpromoted var))` (per-field stores plus a whole-struct load defeat mem2reg), so an `as<IRUndefined>` guard is incomplete; skip a provably-uninitialized store in glsl-legalize's `assign` (`address ← value`) for both shapes ([fieldExtract, not IRUndefined](../learnings/1787708099936-partial-init-struct-return-undef-varying-store-is-.md)). The nested swizzle-of-swizzle vector lvalue (#12768) has two compounding defects in `LValueExprLoweringVisitor::visitSwizzleExpr`: `.add((uint32_t)elementCount)` pushes the count as one index (should `.setCount`), and the `backpermute` lambda takes its output by value (should `auto&`); the matrix sibling worked only because its output is a raw C-array decaying to a pointer ([backpermute + add-count](../learnings/1787736858261-slang-nested-swizzle-of-swizzle-vector-lvalue-misc.md)).

Texture swizzle stores have their own gap. `assign()` in `slang-lower-to-ir.cpp` emits `swizzledStore` for every multi-element swizzle, including full-coverage ones such as `t[i].xyzw = v` (or `.xy` on a `float2` texel), so `legalizeImageSubscript` lowers them as read-modify-write: a needless image load on every target, a CUDA-only false E56006 warning since PR #13363, and a hard CUDA E55204 on a format-converted `[format("rgba8")] RWTexture2D<float4>` (no converting read exists) though `t[i] = v` compiles. In `legalizeStore`, when the swizzle indices permute all of the texel's components, emit a plain imageStore of the reordered source. `RWBuffer` never reaches CUDA surface emit (E36107 rejects it first); `tests/bugs/gh-4411.slang` (scalar-texel `.x =`) is the canonical scalar whole-texel store through `ref` ([full-coverage swizzle RMW](../learnings/1790832459014-full-coverage-swizzle-on-rwtexture-goes-through-th.md)). "Full coverage" is measured against the texel the image op writes, not the element type: on Metal, GLSL and SPIR-V it is always a 4-vector, so treating `t[i].yx = v` on `[format("rgba32f")] RWTexture2D<float2>` as full would zero `.zw`; on CUDA the texel is the element type (`surf*write<T>` writes `sizeof(T)` bytes). Pin both directions with GLSL, Metal and SPIR-V CHECKs and test a non-self-inverse swizzle (`.yzwx` must become `v.wxyz`; `.wzyx` and `.yx` pass even with the mapping reversed); don't rebuild during an A/B run (exit 127) ([compare against the texel width](../learnings/1791084184485-image-subscript-rmw-shortcut-compare-a-swizzle-aga.md)). Both fixes live in the image-subscript pass, which sees only some stores: assignment through a bound subscript tries `set` before `ref`, so `t[i] = v` or `t.Store(i, v)` becomes the `Store` intrinsic (on CUDA via `$C`/`$E` in hlsl.meta.slang), and only swizzle or member writes produce the `kIROp_ImageSubscript` + `Store`/`SwizzledStore` that `legalizeImageSubscript` rewrites. A rule there, such as #13363's E56007 conversion check, never sees plain stores, so the spellings can diverge. Before claiming a pass "rejects store X", run master slangc with `-dump-ir`, count `imageSubscript` insts, and compare `t[i] = v` with `t[i].x = v` ([plain store via the setter](../learnings/1792030315427-slang-plain-tex-i-v-lowers-via-the-setter-not-kiro.md)).

**A last `### AFTER <pass>` dump does not mean that pass finished.** `SLANG_PASS` wraps each pass in `PassHooksRAII` (`source/slang/slang-pass-wrapper.h`), whose destructor runs `postPassHooks`, including the `-dump-ir` "AFTER" dump. When a pass throws (e.g. a `SLANG_RELEASE_ASSERT` InternalError) that dump still prints during unwinding, showing the PARTIALLY transformed IR, with no "BEFORE <next pass>" after it. Confirm with `-dump-ir-before <next pass>`, which prints nothing if X threw; the partial IR shows the half-rewritten state at the throw. Triage of #13948 placed its crash inside `lowerBufferElementTypeToStorageType` this way; root cause on [[wiki/concepts/slang-compiler-ir-type-legalization.md]] ([printed during unwind](../learnings/1792961894220-dump-ir-after-pass-can-be-printed-during-exception.md)).
