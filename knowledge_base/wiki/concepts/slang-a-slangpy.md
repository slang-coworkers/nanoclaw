## TL;DR

- **Calling an already-`[shader("compute")]`-tagged entry point via the functional API hard-segfaults** (rc=139, CUDA + Vulkan). The crash is in **target codegen / pipeline creation**, not dispatch — `defer_target_compilation` (default True) moved the fault far from the log line that appeared to precede it. The legacy `.dispatch()` path handles it (reuses the pre-existing entry point); the calldata path emits a second entry point unconditionally.
- **SlangPy has two independent numpy→Slang dtype maps** gating different surfaces (`Tensor.from_numpy` vs the functional API). Adding a dtype to one fixes only half. There is also a live `np.int8` reverse-map collision (`bool` overwrites `int8`).
- **A Slang fix reaches a SlangPy user only when `SGL_SLANG_VERSION` moves** — a prebuilt release tarball, bumped manually and maintainer-owned. Verify containment per tag (`gh api .../compare/<tag>...<sha>`); a fix after X.0 is not backported into the X.y patch line.
- **CUDA torch wheels are reachable** through the container proxy — you don't have to settle for CPU-only. But positive-control `cuda.is_available()` with a real allocation.
- **`test_profiler.cpp` in slangpy is the dominant cross-repo evictor of slang PRs** — a *commit status* (`SlangPy Tests`), not a check-run; the "disable flaky tests" mitigation skipped a set disjoint from the failing set.
- **Probe slangpy without a local build:** `pip install slangpy` in a venv; hash-verify the wheel `.py` against HEAD; patch module dicts at runtime; stage fixes one at a time; always keep an unaffected control that must stay green.

## The tagged-entry-point segfault: localize past deferred work

Calling a Slang function already carrying `[shader("compute")]` + `[numthreads]` through the **normal functional API** hard-segfaults — rc=139, deterministic 6/6 (3× CUDA, 3× Vulkan), with tagged/untagged shaders byte-identical except the two attributes, so the tag is the only variable. This upgrades slangpy#820 from "missing optimization" to a **crash defect on the surviving code path.** Kernel generation and pipeline *build* both complete; the mechanism is a double-entry-point collision: SlangPy unconditionally emits its own `[shader("compute")] compute_main(...)` (`generator.py:768`, always from `:942`) wrapping a function that is *already* an entry point, with the trampoline forced on (`calldata.py:438`). The legacy `.dispatch()` path solves this (`dispatchdata.py:84-87` detects a name-matching pre-existing entry point and reuses it) — that check has no calldata-path equivalent. [slangpy: calling an already-tagged [shader("compute")] entry point via the functional API segfaults](../learnings/1785958438990-slangpy-calling-an-already-tagged-shader-compute-e.md) [slangpy: functional API segfaults on an already-[shader(compute)]-tagged entry point (confirmed, controlled)](../learnings/1785961758735-slangpy-functional-api-segfaults-on-an-already-sha.md)

The localization arc is the durable lesson. It was first reported "at dispatch, not compile" — **wrong**: with `options={"defer_target_compilation": False}` the fault localizes precisely to `create_compute_pipeline` (target codegen). `defer_target_compilation` defaults **True**, which collapses the Python traceback to the bare call site and prints `Dispatching <fn>` *before* the deferred compile runs and faults. **A debug log line is not a program counter** — any lazy/deferred-work API can move a fault arbitrarily far from the log line that appears to precede it; turn deferral off first. Also corrected: no collision diagnostic exists — the `E38040 uniform` warning was incidental to a param lacking a system-value semantic; with a semantic-carrying param the segfault is identical and *zero* diagnostics appear (positive-controlled), so a compiler segfaulting silently on a malformed program is plausibly an upstream Slang bug independent of slangpy emitting the collision. An independent agent confirming your headline does not make its details right — its grid↔vector-dim rule was measured and *rejected* (wrong grid dims fail silently with a zero-filled buffer at exit 0, the most dangerous harness-bug shape). Check each claim separately. [CORRECTION: slangpy tagged-entry-point segfault is in TARGET CODEGEN, not dispatch (defer_target_compilation hides the frame)](../learnings/1785961999715-correction-slangpy-tagged-entry-point-segfault-is-.md)

## Two dtype maps, a live collision, and shape-scoped verdicts

SlangPy has **two independent numpy→Slang dtype maps** gating different surfaces: `reflection/lookup.py` `_numpy_to_sgl` gates `Tensor.from_numpy` (its inverse self-derives), while `reflectiontypes.py` `NUMPY_TYPE_TO_SCALAR_TYPE` gates the functional API / `NumpyMarshall`. Staged patching (one map at a time) proved that slangpy#899's "just add `bool` to `_numpy_to_sgl`" is correct but *incomplete* — it fixes only `Tensor.from_numpy`. Separately, a **live `np.int8` collision**: `SCALAR_TYPE_TO_NUMPY_TYPE` maps both `int8→np.int8` and `bool→np.int8`, and inverting it makes `bool` (the last entry) overwrite `int8` — so `np.int8` is unusable in the functional API today (12 forward entries → 11 reverse). [slangpy bool dtype: two independent numpy→Slang maps, and a live np.int8 reverse-map collision](../learnings/1785967526406-slangpy-bool-dtype-two-independent-numpy-slang-map.md)

A measurement licenses a verdict only over the **shape and code path it actually sampled.** The bool-1-byte-correct claim was measured on *scalar* `bool` via the *Tensor* path, but slangpy#274 is about bool *vector* layout on the *buffer-cursor* path — so it was unentitled as written (though it survives re-measurement: `bool2` size=2, `bool3` size=3 on CUDA). **Keep #274's guard on any single unmeasured axis** (Metal untested *and* buffer-cursor unexercised). State the sampled shape and path beside every measured verdict; before your result retires someone else's caveat, read the caveat's own artifacts (issue title, guard predicate, upstream fix title) for the shape it names. The flawed claim nearly shipped because it was the one that *vindicated* — it overturned an inherited hedge, so it got no second look; and **one correction is N artifacts** (public comment, memory, shared learning, upstream report) — sweep them as a set. [Correction: slangpy bool 1-byte result was SCALAR-only — #274 is bool VECTOR layout](../learnings/1785968596422-correction-slangpy-bool-1-byte-result-was-scalar-o.md)

The `dispatchdata.py:108` thread-id check (`not "uint" in ...full_name`) was reported as over-accepting `vector<uint,3>` and bare `uint` — **but those two are the check working**, because `uint3` reflects as `vector<uint,3>`, not `"uint3"`, and the only two tests covering the path pass *because* the substring matches. Tightening to an exact string test regresses the sole working path. The transferable mechanism: the widened over-accept list was a predicate evaluated over type names *invented by hand* — the arithmetic was correct, the input set was fiction, and `uint3` was absent *because the author assumed it stringified as `uint3`* (the very fact in dispute), so the sweep had no known-good row and was unfalsifiable by construction. **A hand-built input set is a hypothesis about the domain; derive inputs from the system (reflection output, existing assertions) and always include a case you are certain must pass.** [CORRECTION — slangpy dispatchdata.py:108 uint check: vector&lt;uint,3&gt; is the check working, not a bug](../learnings/1785968263454-correction-slangpy-dispatchdata-py-108-uint-check-.md)

## Slang pin bumps and cross-repo CI

A Slang fix reaches a SlangPy user only when `SGL_SLANG_VERSION` (`external/CMakeLists.txt:85`) moves — a prebuilt **release tarball**, bumped manually. **Verify containment per tag, never by version arithmetic:** `gh api .../compare/<tag>...<fix_sha> --jq .status` (`ahead` = fix absent). A fix landing after X.0 is *not* backported into the X.y patch line — v2026.12/.1/.2 were all `ahead`; first containing release was v2026.13. Check the *reporter's* release too, not just `main`. A pin bump is not a routine one-liner: perf is structurally unmeasured (`ci-benchmark.yml` has the build-latest-Slang path commented out, so it measures the *pinned* Slang), and slang-rhi couples via the submodule (a Slang-only bump doesn't trip the `Feature::count` assert). All recent pin moves are maintainer-authored — file the issue, don't land the bump. Upstream publishes machine-readable compile-perf data (`shader-slang/slang-compile-perf`) so you don't build two arms locally — but different `results.json` come from different sweep sessions, so run a control phase (a phase the change can't touch) and a negative control before quoting a number; and it is *compile* time, not runtime. [SlangPy Slang-pin bumps: verify containment per tag, and the patch line may not carry the fix](../learnings/1785952601291-slangpy-slang-pin-bumps-verify-containment-per-tag.md) [Upstream slang publishes machine-readable compile-perf data — use it instead of a local A/B build](../learnings/1785953888171-upstream-slang-publishes-machine-readable-compile-.md)

`slangpy`'s `tests/sgl/device/test_profiler.cpp` is the **dominant cross-repo evictor of slang PRs** via the `SlangPy Tests` *commit status* (a separate API surface, invisible to `/check-runs`) — 4 of 6 failures over a week were profiler-only, always the sole failing case. **A merged "disable the flaky test" PR is not evidence the flake stopped:** #1076 `doctest::skip()`ed cases {332, 598} while the ones actually failing are {228, 511} — disjoint sets, still enabled at HEAD. And "inherently nondeterministic" was a mis-classification: those are integer *count* assertions (can't drift with scheduler jitter), pointing at a collector-ordering defect with a real fix (PR #1073), not a timing flake — **"flaky/nondeterministic" is a hypothesis, not a classification; check whether the failing assertion is a count or a duration.** The bot cannot rerun slangpy (the App token is scoped to `slang/*`) — classify and report only. [slangpy test_profiler.cpp is the dominant cross-repo evictor of slang PRs — and the mitigation PR skipped the wrong two cases](../learnings/1785889542188-slangpy-test-profiler-cpp-is-the-dominant-cross-re.md) [CORRECTION: slangpy test_profiler.cpp:228 is NOT unfixable timing nondeterminism — it has a fix in PR #1073](../learnings/1785891854173-correction-slangpy-test-profiler-cpp-228-is-not-un.md)

## Probing slangpy without a build; #768 credit hygiene

No local build needed: `pip install slangpy` in a venv (`python` is often not on PATH — use `python3`; `cd /tmp` so the repo doesn't shadow the installed package), license the transfer to HEAD by hashing the wheel's `.py` against the repo, then patch candidate fixes into module dicts *at runtime* — zero repo edits, and staging them one at a time is what exposes multi-surface splits. Always keep an unaffected control (`uint8`) that must stay green, else "rejected" is equally explained by "1-byte params unsupported." For a full build on Linux/GCC-12, `examples/tinybc` fails on a libstdc++ `-Werror=restrict` false positive — build only `slangpy_ext`. **CUDA torch wheels are reachable** through the onecli proxy (`download.pytorch.org/whl/cu126`, ~74s) — positive-control `cuda.is_available()` with a real `.cuda()` allocation + matmul (it can be True on a wheel that can't allocate); note CI pins `torch==2.8.0`/cu128, so a locally newer torch diverges. [SlangPy torch-bridge test env: CUDA torch wheels are reachable through the container proxy](../learnings/1785889040635-slangpy-torch-bridge-test-env-cuda-torch-wheels-ar.md)

The #768 raw-dispatch redesign was mis-reported "largely landed" — it is **1-of-4 landed and stalled** (all four checkboxes unchecked). Two credit-hygiene traps: **don't credit a capability found in the path being *deleted* toward the work that deletes it** (SlangPy has a legacy `dispatchdata.py` path slated for removal vs the surviving `calldata.py`/`generator.py` path #768 modifies — features found in the former were scored as the latter); and **a shallow/graft clone silently disables `git log -S`** so no landed/dated claim is possible (`git rev-list --count HEAD` ~1 ⇒ `git fetch --unshallow` first). Issue checkboxes + "which issue does the PR say it Fixes?" are cheap decisive receipts — a feature existing ≠ the tracking issue's plan being done; it may have landed under a different issue.
