## TL;DR

- GitHub's closing-keyword parser (`close/closes/closed/fix/fixes/fixed/resolve/resolves/resolved` immediately followed by `#N`) has **no notion of sentence meaning**. A sentence that *denies* a link still creates it; a sentence with words between the keyword and the number creates no link at all.
- Both failure modes are invisible in the text and opposite in polarity: `Fixes half of #N` **looks linked and is not**; "neither PR **resolves #12441**" **looks unlinked and would link**. Only GitHub's *parsed* result settles it.
- Only `closingIssuesReferences` answers "is this linked *by the PR body*." Query it against a **control PR known to link** in the same call, or an empty array is uninterpretable (reads identically to a broken query).
- Under **squash-only** repos the squash commit is **title + body**, so a closing keyword in the PR *title* fires at merge and never appears in `closingIssuesReferences`. The load-bearing check is a simulated-squash scan of title+body; `closingIssuesReferences` is only corroboration.
- **Draft status suppresses nothing** — the link is populated while a PR is a draft and fires on merge. Draft affects CI triggering and review requests, not issue closure.
- The instrument is **merge-settings-dependent**: on merge-commit/rebase repos the source commit subjects also reach the default branch and must be scanned. Read `allow_squash_merge`/`allow_merge_commit`/`allow_rebase_merge` first.
- When one issue is fixed by N PRs, an auto-close on first merge shuts a live remainder — demote to a non-keyword reference (`Refs #N`), say the absence is a decision not an omission, and record the manual-close obligation where a future session reads it.

## The parser reads meaning nowhere — so both polarities bite

The foundational atom, [A sentence denying a GitHub closing link can create one](../learnings/1786417655060-a-sentence-denying-a-github-closing-link-can-creat.md), documents a replacement paragraph titled "Deliberately no closing keyword" whose first sentence — "Neither PR alone **resolves #12441**…" — was a live closing sequence that would have created exactly the auto-close link it declared absent. The fix is to keep the number nowhere near a keyword ("#N has two halves", "is not a complete answer to #N"). Its mirror, `Fixes half of #N`, links *nothing* because the intervening words break the parse, so prose reads to a human as a link that does not exist. [GitHub issue-linkage is a false-appearance trap in BOTH directions](../learnings/1786417868727-github-issue-linkage-is-a-false-appearance-trap-in.md) states the general rule: **prose that merely describes machine-parsed metadata is never evidence about that metadata** — applies to `//TEST:` directives, expected-failure entries, label names in prose, and CODEOWNERS globs alike. Query the parsed artifact; and when writing *about* a parser's trigger, remember the parser will read your explanation too.

## The check needs a control, and the control catches instrument defects too

Both linkage atoms insist the query is uninterpretable without a control PR known to link in the same invocation set — a `[]` reads identically to "the query is wrong." The false-appearance atom records two instrument defects hit while verifying: `gh api --jq -r` is invalid (jq output is already raw) and printed an empty value that looked like a legitimate `[]`; and scanning target PRs *before* fetching the control body left the target rows printing a confident `0` while the control row crashed. "Both zeros were void until the control fired" — the same lesson as any grep-zero needing a positive control. A second, independent regex instrument (`(?:close[sd]?|fix(?:e[sd])?|resolve[sd]?)\s*:?\s*(#\d+|…)`) catches the negation-links-anyway case *before upload*, verified firing on the control.

## Squash-only: the title is the closing artifact

The most consequential extension is that `closingIssuesReferences` is *not* the whole answer. [Issue-closing linkage under squash-only: the PR TITLE closes issues](../learnings/1786426115544-issue-closing-linkage-under-squash-only-the-pr-tit.md) and its companion [The squash commit is title+body — scan that, not just closingIssuesReferences](../learnings/1786426257720-the-squash-commit-is-title-body-scan-that-not-just.md) record the same discovery: `shader-slang/slang` is squash-only with `squash_merge_commit_title=PR_TITLE`, `squash_merge_commit_message=PR_BODY`, so the squash commit *is* title + "\n\n" + body. A title of `Fix #9999: …` fires at merge regardless of the body, and a commit-message closure does not appear in `closingIssuesReferences` at all — making that field corroboration, and a simulated-squash scan of title+body the load-bearing check (all nine keyword spellings × three reference forms). The instrument is merge-settings-dependent: on merge-commit/rebase repos the source commit subjects reach master too, so read the merge settings first to decide what to scan. Two reasoning errors from that chain recur: the keyword must *precede* the reference (`PR #12236 fixes…` is not closing syntax — verified with `totalCount=0` on the live quote, so bracketing the number would have made a maintainer quotation less faithful for nothing), and "my fix didn't work" is itself a claim — a stale `totalCount=2` read of a successful edit manufactured a phantom second cause and a wasted hunt. Re-measure a failure before hunting a deeper one.

## Draft is not dormant; and when absent linkage is correct

[Draft status does not suppress a closing keyword — only closingIssuesReferences answers "is this linked"](../learnings/1786425268271-draft-status-does-not-suppress-a-closing-keyword-o.md) refutes "held as a draft, so it won't auto-close": the link was populated while the PR was a draft and would fire on merge, and it also linked a *second, already-closed* issue that merging would have re-closed. Worse, that PR's evidence was Linux-debug-only with 37 build/test jobs skipped on both CI dispatches — "an issue closing on evidence that never compiled on two of three platforms." When a fix's verification is incomplete or one issue is fixed by N PRs, demote to `Refs #N` and let a human close (prefer leaving all unlinked — it cannot misfire), document the absent link as a *decision* not an omission, and record the manual-close obligation somewhere a future session reads, because nothing monitors it. That atom's adjacent findings are worth carrying: a surviving mutant proves a test suite decorative (reducing a `SeqStmt` walk to `stmts[0]` passed every case), and one should count reviewer *independence*, not reviewers (a clean-looking 3-of-3 was really 1-of-3 — one reviewer died on an API 400 while its wrapper reported success, another's "no findings" was the PR body reflected back verbatim).
