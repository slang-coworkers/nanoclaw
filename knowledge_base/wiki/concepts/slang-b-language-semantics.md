## TL;DR

- **A bare unparenthesized function name as a statement (`GroupMemoryBarrierWithGroupSync;`) is silently accepted and dropped**: exit 0, no diagnostic, even under `-warnings-as-errors all`, so a one-character typo removes a barrier. Only *overloaded* names error (E39999 ambiguous). Root: the `// TODO` stub in `CheckExpr` (`slang-check-expr.cpp:3849`); filed **#12428**.
- **`import a.b` reaches subdirectories via a PARSER dot→slash rewrite**, but `-I` search is non-recursive and quoted imports get no sugar. One `-I` root serves a hierarchy *only* with dotted names.
- **Parallel compilation needs one `IGlobalSession` PER THREAD.** A mutex around `createSession` cannot help, because every `Linkage` copies the global session's by-value `NamePool`.
- **`slang` is a dispatcher** routing `slang foo` to a sibling `slang-foo` binary: sibling-dir only, no PATH search, no abbreviation.
- **Scalar `SV_DispatchThreadID` is component `.x`, not a flattened index**, and silently collides across a column. Use `SV_GroupIndex` for a flat id.
- **The front-end SV stage check (E30702) sees only entry-point parameters and returns, and is silent under `-ignore-capabilities`.** A target legalizer that newly maps a semantic must reject non-fragment stages itself.
- **`WorkgroupSize()` folds to a compile-time constant pre-emit** and returns signed `int3`; spec-constant `[numthreads]` works on SPIR-V/GLSL only. The splice adds no casts, so a `uint` spec-constant axis makes `int3 w = WorkgroupSize();` invalid SPIR-V.
- **`WorkgroupCount()` works on GLSL/SPIR-V and on WGSL since #13920; Metal/CUDA need one `SV_WorkgroupCount` case in their system-value legalizer** (`__intrinsic_asm` cannot add a Metal kernel attribute). `: SV_WorkgroupCount` on a user parameter is E49999 everywhere.
- Matrix truncation `(float3x3)m3x4` is explicit-cast-only and yields the upper-left submatrix.
- **HLSL-dialect methods take `this` as `inout` by default since #13615 (2026-10-16, breaking, no compat flag; first release v2026.20)**; a trailing `const` or `[nonmutating]` selects `in`, and `.slang` files keep the old default. Calls on immutable receivers (cbuffer members, `StructuredBuffer` elements, rvalues) now give E30050 (#13964). See [[wiki/concepts/slang-language-hlsl-receiver-mutability.md]].
- **`getSourceLanguage()` is the dialect of the translation unit being checked.** Declaration semantics read the defining unit; call-site legality rules read the calling unit, never a property of the callee.
- A `__target_switch` with no case for the target is a hard E41009 on SPIR-V/GLSL/WGSL and a silent drop on CUDA; the most specific case wins the whole function.
- In `*.meta.slang`, a zero-hit grep on a user-facing spelling means "wrong query" (types/methods are meta-generated), not "absent."
- **In `*.meta.slang`, `__isFloat<T>()` means "any floating type", double included.** Branch on an exact type with `__type_equals<T, double>()`; do not change `__isFloat`.

## The bare-function-name silent drop (#12428)

`GroupMemoryBarrierWithGroupSync;` (no parens, as an expression-statement) compiles clean and emits **nothing**: HLSL 0 barriers vs 1 with parens, SPIR-V `OpControlBarrier` 0 vs 1, 0 vs ~380 barrier mentions in `-dump-ir`, still silent under `-warnings-as-errors all` and `-validate-ir`. For a barrier that is a silent data race (measured on release `slangc 2026.14.1`; filed **shader-slang/slang#12428**). The behavior is broad. It hits **all six targets** (`controlBarrier`/`threadgroup_barrier`/`workgroupBarrier`/`__syncthreads` go 0→1 too) and any **user function** (`void sideEffect()`), and **`[NoDiscard]` is blind to it** (`f();` gives `error[E30059] result discarded`, `f;` exits 0). The discriminating control is a bare *overloaded* name (`max;`), which gives `error[E39999] ambiguous reference`, because `maybeResolveOverloadedExpr` reaches `diagnoseAmbiguousReference` only for `OverloadedExpr`; so testing with a random overloaded intrinsic gives a false all-clear.

Mechanism (master `716ec597`): `CheckExpr` (`slang-check-expr.cpp:3843-3849`) runs `maybeResolveOverloadedExpr`, and the value check after it is a literal `// TODO: Implement this step.` stub, which is the missing check. A `CallableDecl` declRef legitimately yields a `FuncType` (`slang-check-decl.cpp:1773-1787`; needed for `IFunc`, lambdas and `__fwd_diff(f)`), so nothing downstream objects, and a fix must keep those legal; warning vs error at the TODO is a maintainer choice. No unused/no-effect diagnostic exists at all: of 695 codes only `30058 dangling-equality-expr` is in that family.

**Method: "0 mentions in a `-dump-ir` body dump" does not mean lowering never ran.** `visitExpressionStmt` (`slang-lower-to-ir.cpp:8783`) calls `lowerLValueExpr`, and `ensureDecl` (`:14866`) puts the `IRFunc` at module scope, where the uncalled global is DCE'd. The decisive positive probe was `[deprecated(...)]`: the bare use fires `warning[E31200]` at `bar;` col 5, so lookup resolved the declRef and nothing objected. Release binaries are one curl away: "no compiler on PATH" is a claim about PATH, and source-reading cannot settle an absence claim, so measure. Pair each run with controls (a typo at the same line:col must diagnose; the parenthesized form must emit). [Slang: a bare unapplied func ref as an expression-statement is silently accepted (and why no IR appears)](../learnings/1786181574992-slang-a-bare-unapplied-func-ref-as-an-expression-s.md) [Slang silently drops a bare (unparenthesized) non-overloaded function name statement](../learnings/1786181926904-slang-silently-drops-a-bare-unparenthesized-non-ov.md) [Slang silently drops a bare unparenthesized function name — and "no compiler on PATH" is not "no compiler available"](../learnings/1786182172919-slang-silently-drops-a-bare-unparenthesized-functi.md) [A bare function name is a valid Slang statement that silently emits nothing](../learnings/1786182513293-a-bare-function-name-is-a-valid-slang-statement-th.md)

## Module resolution: `import a.b` is parser sugar; `-I` is non-recursive

`-I` search is **non-recursive**: `import mylib;` with the file at `packages/mylib/src/mylib.slang` fails under `-I packages` (`E00001 cannot open file 'mylib.slang'`) and works only with `-I packages/mylib/src`. **Dotted names do reach subdirectories**: `import mylib.core;` finds `<root>/mylib/core.slang` with one `-I <root>`. The rewrite is in the **parser**: `parseFileReferenceDeclBase` (`slang-parser.cpp:1341-1352`) appends `/` for each `Dot` token ("as sugar"), so the name has slashes before file lookup. `getFileNameFromModuleName` (`slang-session.cpp:1468`) does only underscore→dash and `.slang` append, so grepping there reads as "feature doesn't exist". A guilty control settles it: delete the target and the error becomes `cannot open file 'mylib/core.slang'`, with a slash.

Sharp edges: quoted imports get NO sugar (`import "mylib.core";` opens `mylib.core.slang`); nothing makes a `module` decl match its import path; `module mylib.core;` is invalid syntax (one identifier or one string literal). Outside the language server, `.slang-module` (IR) is tried *before* source (`slang-session.cpp:1583`), so a stale binary module can shadow fresher source; freshness validation rejects stale IR only when the source is reachable. [Slang `import a.b` reaches subdirectories via a PARSER dot→slash rewrite; `-I` itself is non-recursive and quoted imports get no sugar](../learnings/1786040130872-slang-import-a-b-reaches-subdirectories-via-a-pars.md)

## Parallel compilation: one `IGlobalSession` per thread

For `STATUS_ACCESS_VIOLATION` in parallel compilation "even with a mutex on the global session", the answer is **a distinct `IGlobalSession` per thread**, not finer locking. `docs/user-guide/08-compiling.md:720` and `slang.h:4071` state the global session is not thread-safe, and `:1011` rules out N sessions on one global session: front-end operations "require external synchronization when multiple threads share a global session, a session, **or objects created from them**." A lock around `createSession` cannot help because the shared state is touched after it returns: `slang-session.cpp:71` does `namePool = session->getNamePool();`, so every `Linkage` (`ISession`) uses the global session's **by-value** `NamePool`, and concurrent `loadModule`/checking on separate sessions interns into one unsynchronized pool (maintainer-confirmed on #8581). Only backend emission is parallel-safe, and only after full specialize+link. There is **no module-unload API by design** (#4645 closed not_planned); recreate the session, which is cheap because the core module amortizes on the global session. Method: for "I added the obvious lock and it still crashes", compare the window the lock covers with where the shared state is touched (here one copy line). [Slang: parallel compilation needs one IGlobalSession PER THREAD — a mutex around createSession cannot work](../learnings/1786088362639-slang-parallel-compilation-needs-one-iglobalsessio.md)

## The `slang` dispatcher

`source/slang-dispatcher/` builds `slang` with a builtin subcommand table (compile→slangc, interpret→slangi, help, version) and sends any unknown subcommand to a sibling `slang-<subcommand>` (`main.cpp:484`), so a tool named `slang-foo` becomes `slang foo` with no dispatcher change (PR #10621, first release v2026.5.1). Measured gotchas: **PATH is NOT searched**, only the running `slang`'s directory (contradicting #10621's prose); no abbreviation (`slang pkg` looks for `slang-pkg`); `looksLikeFilePath()` is just "contains a dot", so a dotted subcommand is a file. The binary is in the packaged tree `build/slang-<ver>-linux-x86_64/bin/slang`, not `build/{Debug,Release}/bin`; reporting it absent was a false capability-negative. Only one `//TEST:DISPATCHER` case exists, and the delegation path is untested. [Slang already has a `slang` dispatcher that routes unknown subcommands to sibling `slang-<name>` binaries — sibling-dir ONLY, no PATH](../learnings/1786040102016-slang-already-has-a-slang-dispatcher-that-routes-u.md)

## System-value semantics and workgroup intrinsics

**Scalar `SV_DispatchThreadID` narrows by SWIZZLE, not linearization.** Slang allows `uint`/`uint2`/`int`/`int2` besides HLSL's `uint3`, and `tryConvertValue` (`slang-ir-legalize-varying-params.cpp:293`) emits a swizzle with `index=0`, i.e. `.x`. So `void main(uint tid : SV_DispatchThreadID)` under `[numthreads(8,8,1)]` compiles clean and every thread in a column sees the same `tid`; the scalar form is correct only for 1D dispatch. For a flat index use `SV_GroupIndex` (group-local) or flatten yourself. Without the builtins: `dispatchThreadID = groupID*extents + groupThreadID`, `groupIndex = (z*Ny+y)*Nx+x` (x fastest); `emitCalcGroupExtents` bails on a non-literal extent. Metal/WGSL diagnose `SystemValueTypeIncompatible` instead of converting, so `uint2` is safest on SPIR-V/GLSL/CUDA. [Slang scalar SV_DispatchThreadID is component .x, not a flattened index](../learnings/1786115913613-slang-scalar-sv-dispatchthreadid-is-component-x-no.md)

**`WorkgroupSize()` is a compile-time constant** returning signed **`int3`** (`hlsl.meta.slang:7837`; DeepWiki's `uint3` is wrong, see `tests/spirv/spec-constant-numthreads.slang`). `materializeGetWorkGroupSize` (`slang-ir-translate-global-varying-var.cpp:438`) splices the `IRNumThreadsDecoration` operands into each use (not limited to literal extents, unlike `emitCalcGroupExtents`), inside `linkAndOptimizeIR` outside any `switch(target)`, so the op is gone before emit everywhere. So zero `GetWorkGroupSize` hits across the seven emitters means portability, not a missing arm (WGSL is untested, not unsupported). Spec constants in `[numthreads]` work on SPIR-V/GLSL and hard-error at the attribute on HLSL/Metal/WGSL/CPU (`slang-emit-c-like.cpp:294`). Do not confuse it with `uint3 WorkgroupCount()` (groups dispatched; GLSL/SPIR-V, plus WGSL since #13920, below). [Slang WorkgroupSize() folds to a constant pre-emit; WorkgroupCount() is GLSL/SPIR-V only](../learnings/1786117126710-slang-workgroupsize-folds-to-a-constant-pre-emit-w.md) The splice adds no casts: `materializeGetWorkGroupSize` (`:463-471, 510-516` at master 7251cc6) builds `makeVector(Vec(Int,3), numthreads operands)`, so a `[SpecializationConstant] const uint` axis with `int3 w = WorkgroupSize();` fails SPIR-V validation (`OpCompositeConstruct %v3int %kX ...`) while `WorkgroupSize().x` is fine (pre-existing, found triaging #13767; the WGSL `@workgroup_size` type rule is on [[wiki/concepts/slang-backends-wgsl-on-gpu-execution.md]]) [WGSL @workgroup_size override args must share one int type; WorkgroupSize() makeVector lacks casts](../learnings/1792502196007-wgsl-workgroup-size-override-args-must-share-one-i.md).

**`WorkgroupCount()` now works on WGSL; Metal, CUDA, PTX and HLSL still give E36107 (#14034).** The older "GLSL/SPIR-V only" note predates #13920 (fc02240aa, 2026-10-29): `hlsl.meta.slang:18` now declares `in uint3 __builtinWorkgroupCount : SV_WorkgroupCount;`, and WGSL maps it to `num_workgroups` (`slang-ir-legalize-varying-params.cpp:5197`). `translateGlobalVaryingVar` (`slang-emit.cpp:2074`) turns a core-module global `in` with an SV_ semantic into an entry-point parameter before `legalizeIRForMetal` / `legalizeEntryPointVaryingParamsForCUDA` run, so a Metal or CUDA arm is one new case in that target's system-value switch: Metal `getSystemValueInfo`, or the CUDA switch at :2497 together with a global like `blockDim` at :2419. `WaveGetLaneCount()` on Metal already works this way. `SV_WorkgroupCount` is internal only: a user entry parameter `: SV_WorkgroupCount` gives E49999 on every target, WGSL included, because `core.meta.slang` has no `semantic sv_workgroupcount` decl. On Metal, `__intrinsic_asm "threadgroups_per_grid"` compiles (exit 0) but emits `threadgroups_per_grid()` as a call and no `[[...]]` parameter, so a value that exists only as a Metal kernel attribute must go through the legalizer. The CUDA `gridDim` workaround runs correctly on the L40S (slang-test `-compute-dispatch 3,2,1`) [Slang WorkgroupCount(): WGSL works since #13920; Metal/CUDA need SV_WorkgroupCount mappings; __intrinsic_asm can't supply Metal entry-point attributes](../learnings/1793295609658-slang-workgroupcount-wgsl-works-since-13920-metal-.md).

**The front-end SV stage check (E30702) misses global varyings and `-ignore-capabilities`.** `validateSystemValueSemantic` (slang-check-shader.cpp ~2020-2073) checks only entry-point **parameters and the return value**, so a global `in uint g : SV_PrimitiveID;` is never checked, and it reports through `diagnoseCapabilityErrors`, which `-ignore-capabilities` silences. Both paths still reach `legalizeSystemValue` / `ensureStructHasUserSemantic`. While a legalizer leaves a semantic unmapped the user gets a clean E55202; once a PR maps it (WGSL `SV_PrimitiveID` → `@builtin(primitive_index)`, slang#13619), these paths emit the builtin in the wrong stage, or an output without its `enable`, and naga rejects the WGSL. So "the front end restricts it to fragment input" is not a sufficient review answer. Probe it as a global `in` in vertex/compute shaders and, under `-ignore-capabilities`, as vertex input, vertex output and fragment output, validating with naga-wasm (`node naga-check/val.mjs`). Master already leaks a global `in SV_SampleIndex` / `SV_IsFrontFace` in a vertex shader into invalid WGSL, so the class is pre-existing. A working remedy: the legalizer rejects the semantic for non-fragment stages, including on the VaryingOutput path in `ensureStructHasUserSemantic` [the E30702 stage check skips global varyings and -ignore-capabilities](../learnings/1791965980843-slang-sv-front-end-stage-check-e30702-skips-global.md).

## Matrix truncation is explicit-cast-only and yields the upper-left submatrix

`(float3x3)someFloat3x4` is legal and yields the upper-left 3×3, but only as an explicit cast. The truncating ctor is *generated*: `core.meta.slang:2857-2867` loops `rr` from R..4 and `cc` from C..4, emitting `__intrinsic_op(kIROp_MatrixReshape) __init(matrix<T,rr,cc,L>)` for larger-or-equal sources only. Implicit assignment (`float3x3 m = my3x4;`) is rejected: the builtin matrix→matrix coercion (`slang-check-conversion.cpp:2237`) requires equal rows AND columns, and the ctor has no `__implicit_conversion` marker. Upper-left is provable: `slang-ir-peephole.cpp:1575` truncates rows, `slang-ir.cpp:4643` swizzles each row to `[0..toCount)`, and `tests/bugs/matrix-reshape.slang` asserts a diagonal sum only the upper-left produces. Growing zero-pads.

Method lesson: `grep 'float3x3'` on `hlsl.meta.slang` returns **ZERO**, because concrete spellings are typedefs from a C++ meta-generator (`core.meta.slang:2601`) and the ctor is loop-generated. **In `*.meta.slang`, grep the generator, not the spelling users type, and treat a zero-hit grep as "wrong query", not "absent."** The same trap fired on `$(ccName)`-generated RayQuery methods and on `operator ++` written with a space. [Slang truncates matrices via an explicit-only generated ctor — verify at the generator, not the grep](../learnings/1786134501113-slang-truncates-matrices-via-an-explicit-only-gene.md)

## Generics: independent axes and full-contract checks

On BFloat16 for cooperative vectors (#12411) a maintainer chained three blockers, and measurement showed two sit on **independent axes**: `CoopVecComponentType` (an `enum` passed as `constexpr`) is the *memory interpretation*, while `CoopVec<T,N>`'s `T : __BuiltinArithmeticType` is the *register element type*, and nothing makes them agree. The decisive cell fails one axis, passes the other: `CoopVec<FloatE4M3,4>` fails E38029, yet `coopVecMatMul<float,4,4>(..., ::FloatE4M3, ...)` compiles. But `coopVecLoad` takes no interpretation parameter, so for that API the constraint *is* the only gate. Rules: test whether chained blockers gate each other; "not on the critical path" is a claim about every API named, so enumerate them; a precedent is evidence about the interface, not proof a swap works, so check the *whole* contract (`CoopVec` inherits `IComparable`, whose `equals`/`lessThan` need per-element scalar ops BFloat16 lacks → E39999). A hand-written core-module struct outside `FOREACH_BASE_TYPE` cannot inherit conformance through the generated loop, so "just add the conformance" is never a one-liner there. [A generic constraint and a runtime enum parameter can be two independent axes — measure both before calling one a blocker](../learnings/1786049811729-a-generic-constraint-and-a-runtime-enum-parameter-.md)

## Constant folding: an all-literal probe never touches the backend

Slang folds all-literal arithmetic before the backend, so a "real hardware" measurement on constant inputs may measure only the folder: `dot(float2(-0.0,-0.0), float2(1,1))` on `-target spirv` emitted **0** `OpDot`. Control: require the op under test to appear (count ≥ 1) in the emitted code. Fix: read operands from a buffer (`RWStructuredBuffer` + `//TEST_INPUT:ubuffer(data=[0x80000000 ...])`, hex for exact bits like `-0.0`). Second trap: `slang-test` inserts `-O0` into any directive lacking `-OX` while `slangc` uses the default, so `OpDot` survives at `-O0` and folds at `-O1`; record the opt level. Unrolling an accumulator loop drops the `T(0) +` seed, an observable signed-zero change (`0.0 + (-0.0) == +0.0`), so "just unroll it" needs an identity-element-absorption check. [Slang folds all-literal arithmetic before it reaches the backend — a "real hardware" measurement on constant inputs may never touch the driver](../learnings/1786037229044-slang-folds-all-literal-arithmetic-before-it-reach.md) [Slang: [ForceUnroll] on a core-module __target_switch default arm — measure the arm set per overload, the FP and integer twins differ](../learnings/1786035420979-slang-forceunroll-on-a-core-module-target-switch-d.md)

**Measure the `__target_switch` arm set per overload, not per function name.** `hlsl.meta.slang`'s two `dot` fallbacks differ: FP has `glsl`/`metal` arms and integer does not, so the same `default:` loop is reached on glsl/metal for integers only. A blast-radius measurement on a float shader concluded "C-like targets only" and was wrong for the integer twin. `[ForceUnroll]` failure is a hard error (E40020 `CannotUnrollLoop`), but `vector<T,N>` bounds the trip count to 1..4 (`N>=5` is E38206), so the risk is structurally bounded there.

## The "core module counts as imported" trap

"No `import` line ⇒ cross-module logic cannot fire" is **FALSE**. A file with zero imports that redefines a core name (`int max(int,int)`) trips `warning[E38208]: ... overriding a candidate declared in this module ... chose ... from imported module 'core'`, because the implicit modules (`core`, plus `glsl` under `-allow-glsl`) report as imported (`getModuleDecl()`) without an `import` statement. A structural exclusion beats a statistical one *only when the enumeration is complete*; otherwise it licenses skipping the checks that would catch it. Grep for the *behavior*, not the syntax that usually accompanies it. ["No import ⇒ cross-module logic cannot fire" is FALSE in Slang — the core module reports as `imported module 'core'`, so stdlib shadowing needs zero import lines](../learnings/1786044404247-no-import-cross-module-logic-cannot-fire-is-false-.md)

## `__target_switch`: whole-function case selection, missing-return gating, and capability hoisting

`specializeTargetSwitch` (`slang-ir-specialize-target-switch.cpp`) selects EXACTLY ONE case for the whole function by capability specificity ("larger implied atom set wins", `slang-capability.cpp:1417-1420`), reading GLOBAL target caps. It is the producer-side selection layer, upstream of the `targetCaps.implies(...)` gates in `slang-ir-spirv-legalize.cpp`/`slang-emit-spirv.cpp`; editing those does not move selection and regresses (slang#11631), so fix the meta-source producer.

**A missing case does not fall back.** `specializeTargetSwitch` injects `emitMissingReturn()`, a sentinel terminator, and `doesTargetAllowMissingReturns` (`slang-ir-missing-return.cpp:18-26`) gates the result: `false` for `isKhronosTarget || isWGPUTarget` gives a hard `E41009 "non-void function must return"` (SPIR-V/GLSL/WGPU), even on a `void` method because the pass keys on the sentinel; elsewhere it is at most an `E41010` warning, and on CUDA the call is SILENTLY DROPPED. This hit HitObject/SER methods with only `case hlsl:` (#12553 2-arg `HitObject::Invoke`, #10307 `HitObject.FromRayQuery`). Fix: mirror a sibling overload's `spirv`/`glsl`/`cuda` cases and widen `[require(...)]`. The SPIR-V/GLSL SER ops (`OpHitObjectExecuteShaderEXT/NV`) never take an AccelerationStructure (it is baked into the `HitObject`; the explicit TLAS is an NVAPI/DXIL artifact), so a no-TLAS form maps to identical ops, but `case cuda: __intrinsic_asm "optixInvoke"` forwards args positionally, so dropping the TLAS needs matching 2-arg wrappers in `slang-cuda-prelude.h`. (`hlsl.meta.slang` is >1 MB, so the `gh api` contents call returns `content:""`; use `git show <ref>:... | grep`.) [HitObject/SER core-module method missing a `__target_switch` case → E41009](../learnings/1789454795235-hitobject-ser-core-module-method-missing-a-spirv-g.md)

**With two capabilities enabled, the more specialized arm captures the WHOLE function**, so a less specialized arm's per-kind carve-out is never reached (#13070: `spvBindlessTextureNV` = 1 atom vs `spvDescriptorHeapEXT` = 2 atoms routed texture/sampler handles to the EXT heap instead of native `OpConvertUTo{Image,Sampler}NV`). Rather than a compound `case A + B:` with unverified ranking, HOIST a second `__target_switch` ahead of the main one that names ONLY the weaker capability, so the specialized cap cannot out-rank it. It MUST end in `default: break`: a `break;` compiles to a branch to the after-switch continuation, while a hoisted switch with no `default` traps (missing-return) on every target lacking the cap. [__target_switch: hoist a less-specialized capability's per-kind case ahead of the main switch](../learnings/1789460740871-slang-target-switch-hoist-a-less-specialized-capab.md)

**A case-less `__target_switch` is not always removed by DCE** before a "no case for this target" check sees it. `export`/`[DllExport]` functions and methods reachable through dynamic dispatch (`createDynamicObject` with `-conformance`) survive DCE, so a post-DCE no-case diagnostic (E41037 on PR #13564's head; not on master as of 2026-10-16) fires for them even without `-ignore-capabilities`. A dispatch repro must call through the interface from the entry point, or DCE drops the method. HostVM is not a silent hole: its empty target caps take the `failedImplies` path, reporting E41011 "`__target_switch` has no compatible target" ([#13564: export and dynamic-dispatch methods survive DCE](../learnings/1792060963846-slang-pr-review-reviewer-a-30-budget-can-stop-6-7-.md)).

## meta.slang type predicates: `__isFloat<T>()` is true for double (#13773)

`__isFloat<T>()` lowers to `kIROp_IsFloat`, which peephole (`slang-ir-peephole.cpp` ~:1934) folds through `isFloatingType` (`slang-ir.cpp` ~:8714), true for Half, Float and Double. So over `T : __BuiltinFloatingPointType`, `if (__isFloat<T>() || __isHalf<T>()) mad(...) else fma(...)` never takes the else branch. The scalar `fma` `case hlsl:` (`hlsl.meta.slang` ~:11862) has been written that way since 2024-02: `fma(double)` emits `mad`, so DXIL gets FMad (op 46) instead of Fma (op 47), and no test checked HLSL fma output. Branch on an exact type with `__type_equals<T, double>()` (folds via `kIROp_TypeEquals` once `T` is concrete; idiom at `glsl.meta.slang:9402`), and leave `__isFloat` alone because other callers rely on it. HLSL `fma` is double-only, so float/half vector and matrix `fma` must still emit `mad` or DXC errors "no matching function for call to 'fma'". GPU-free check: `slangc -target dxil-assembly -profile cs_6_5`, grep `dx.op.tertiary.f64(i32 47` vs `46` after `define void @main()`; fix PR #13779 (open 2026-10-21). Related: a capability-specific case (`case spvXxx:` before `case spirv:`) is taken only when `-capability`/`-profile` caps imply the atom; an entry-point `[require(...)]` does not select it (`slang-ir-specialize-target-switch.cpp:52-64`) [__isFloat<T>() is true for double](../learnings/1792503417674-slang-core-module-isfloat-t-is-true-for-double-use.md) [__isFloat<T>() means any floating type; use __type_equals](../learnings/1792507691855-slang-core-module-isfloat-t-means-any-floating-typ.md).

## meta.slang `static_assert` is the only compile-time diagnostic: error-only, per-instantiation

`static_assert(constexpr bool, NativeString msg)` (`core.meta.slang:483`) is the ONLY compile-time diagnostic primitive in the meta language; there is no `static_warn` or `__diagnostic`. So a REJECT keyed on a generic parameter lives in `*.meta.slang`, but a WARNING keyed on one needs a checker-side path (a `slang-diagnostics.lua` entry plus a hook at the conversion site). In a generic member body `static_assert` fires per-instantiation, only when the offending specialization is used, giving a targeted error at the call site; precedent is pervasive in `_Texture` bodies keyed on generic `let` ints/`Shape` (`hlsl.meta.slang:1791/1894/1937`, the `isShadow`/`isArray`/`isMS`/`access` family at `:1135-1161`). When the flag rides on an interface-bound `T`, read the interface's `static const` (`_Texture`'s `static const DescriptorKind kind`, readable through `DescriptorHandle<T>` as `T.kind`; the core module already does `switch(T.kind)` at `hlsl.meta.slang:28023`). Prefer `static_assert` to *omitting* a member, which gives only a generic "cannot convert X to Y" (context #13085: ResourceDescriptorHeap single-index → combined texture/sampler silently defaults sampler slot 0, via the zero-fill `__init`s at `:27622` and `:27905`). [meta.slang can reject (not warn) a member per-instantiation via `static_assert` on a generic `let`/`T.kind`](../learnings/1789457618247-meta-slang-can-reject-not-warn-a-member-per-instan.md)

## How the checker learns the dialect: no SourceLanguage path before #13615, `getSourceLanguage()` after

Before #13615 the semantic checker never branched on the translation-unit source language. At master `c0e27bc0e7` (investigating #13073), a sweep of `slang-check*.{cpp,h}` finds the raw `SourceLanguage` enum consulted exactly once, and that use is in the *parser* (`slang-parser.cpp:10022`), deciding whether to stamp a `GLSLModuleModifier` on the `ModuleDecl`. Only that marker survives parse; `TranslationUnitRequest::sourceLanguage` is never copied onto the `ModuleDecl`, so the checker reads `GLSLModuleModifier` + the `AllowGLSL` option (via `isGLSLOperatorScope`) for "is this GLSL-flavored". At that point a dialect-scoped feature seemed to need a module-AST hook: a bare `HLSLModuleModifier`, or the maintainer-preferred single `ModuleSourceLanguageModifier` carrying a `SourceLanguage`, both reachable via `getModuleDecl(decl)` at check and lowering. Baking the dialect onto the *defining* module keeps semantics stable across modules; a use-site option read answers differently for definer and importer (witness/ABI divergence) ([Slang checker has no Decl→SourceLanguage path — HLSL-dialect scoping needs net-new module-AST plumbing](../learnings/1789502791946-slang-checker-has-no-decl-sourcelanguage-path-hlsl.md)).

#13615 (e49310561) instead added `SemanticsContext::getSourceLanguage()` (slang-check-impl.h), which returns the `sourceLanguage` of the translation unit being checked, or `SourceLanguage::Unknown` in reflection and specialization contexts that have no translation unit. There is one shared context per translation unit (`checkTranslationUnit`) and imported modules are checked in their own, so the value is the dialect of the code being checked, never the dialect of a callee's module; witness wrappers inherit the conforming type's translation unit. The definer-vs-importer concern above becomes a rule about which code a dialect rule reads. A declaration's semantics, such as the default receiver mode that `getDefaultReceiverParamMode` computes during signature checking, are fixed by the defining translation unit and are the same for every importer. A call-site legality rule, such as accepting an immutable receiver for an `inout` method, reads the calling translation unit [Slang checker: getSourceLanguage() is the call site's dialect, including witness wrappers](../learnings/1793151491149-slang-checker-getsourcelanguage-is-the-call-site-s.md). The HLSL default-`inout` receiver (#13073 → #13615, first released in v2026.20), its #13964 fallout on immutable receivers, and the call-site fix direction are on [[wiki/concepts/slang-language-hlsl-receiver-mutability.md]].
