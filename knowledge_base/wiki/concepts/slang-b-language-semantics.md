## TL;DR

- **A bare unparenthesized function name as a statement (`GroupMemoryBarrierWithGroupSync;`) is silently accepted and dropped**: exit 0, no diagnostic, even under `-warnings-as-errors all`, so a one-character typo removes a barrier. Only *overloaded* names error (E39999 ambiguous). Root: the `// TODO` stub in `CheckExpr` (`slang-check-expr.cpp:3849`); filed **#12428**.
- **`import a.b` reaches subdirectories via a PARSER dot→slash rewrite**, but `-I` search is non-recursive and quoted imports get no sugar. One `-I` root serves a hierarchy *only* with dotted names.
- **Parallel compilation needs one `IGlobalSession` PER THREAD.** A mutex around `createSession` cannot help, because every `Linkage` copies the global session's by-value `NamePool`.
- **`slang` is a dispatcher** routing `slang foo` to a sibling `slang-foo` binary: sibling-dir only, no PATH search, no abbreviation.
- **Scalar `SV_DispatchThreadID` is component `.x`, not a flattened index**, and silently collides across a column. Use `SV_GroupIndex` for a flat id.
- **The front-end SV stage check (E30702) sees only entry-point parameters and returns, and is silent under `-ignore-capabilities`.** A target legalizer that newly maps a semantic must reject non-fragment stages itself.
- **`WorkgroupSize()` folds to a compile-time constant pre-emit** and returns signed `int3`; spec-constant `[numthreads]` works on SPIR-V/GLSL only. The splice adds no casts, so a `uint` spec-constant axis makes `int3 w = WorkgroupSize();` invalid SPIR-V.
- **`WorkgroupCount()` works on GLSL/SPIR-V and on WGSL since #13920; Metal/CUDA need one `SV_WorkgroupCount` case in their system-value legalizer** (`__intrinsic_asm` cannot add a Metal kernel attribute). `: SV_WorkgroupCount` on a user parameter is E49999 everywhere.
- Matrix truncation `(float3x3)m3x4` is explicit-cast-only and yields the upper-left submatrix.
- **HLSL-dialect methods take `this` as `inout` by default since #13615 (2026-10-16, breaking, no compat flag; first release v2026.20)**; a trailing `const` or `[nonmutating]` selects `in`, and `.slang` files keep the old default. Calls on immutable receivers (cbuffer members, `StructuredBuffer` elements, rvalues) now give E30050 (#13964). See [[wiki/concepts/slang-language-hlsl-receiver-mutability.md]].
- **`getSourceLanguage()` is the dialect of the translation unit being checked.** Declaration semantics read the defining unit; call-site legality rules read the calling unit, never a property of the callee.
- A `__target_switch` with no case for the target is a hard E41009 on SPIR-V/GLSL/WGSL and a silent drop on CUDA; the most specific case wins the whole function.
- In `*.meta.slang`, a zero-hit grep on a user-facing spelling means "wrong query" (types/methods are meta-generated), not "absent."
- **In `*.meta.slang`, `__isFloat<T>()` means "any floating type", double included.** Branch on an exact type with `__type_equals<T, double>()`; do not change `__isFloat`.

## The bare-function-name silent drop (#12428)

`GroupMemoryBarrierWithGroupSync;` (no parens, as an expression-statement) compiles clean and emits **nothing** (0 HLSL barriers, 0 `OpControlBarrier`, 0 vs ~380 mentions in `-dump-ir`), still silent under `-warnings-as-errors all` and `-validate-ir` (release 2026.14.1; filed **#12428**): for a barrier, a silent data race. It hits **all six targets** and any **user function**; **`[NoDiscard]` is blind to it** (`f();` gives E30059, `f;` exits 0). Only a bare *overloaded* name (`max;`) errors (E39999 ambiguous), because `maybeResolveOverloadedExpr` reaches `diagnoseAmbiguousReference` only for `OverloadedExpr`; testing with an overloaded intrinsic gives a false all-clear.

Mechanism (master `716ec597`): in `CheckExpr` (`slang-check-expr.cpp:3843-3849`) the value check after `maybeResolveOverloadedExpr` is a `// TODO: Implement this step.` stub. A `CallableDecl` declRef legitimately yields a `FuncType` (`slang-check-decl.cpp:1773-1787`; needed for `IFunc`, lambdas, `__fwd_diff(f)`), so a fix must keep those legal; warning vs error is a maintainer choice. No unused/no-effect diagnostic family exists (of 695 codes only `30058 dangling-equality-expr`).

**Method: "0 mentions in a `-dump-ir` body" does not mean lowering never ran.** `visitExpressionStmt` (`slang-lower-to-ir.cpp:8783`) calls `lowerLValueExpr`, `ensureDecl` (`:14866`) puts the `IRFunc` at module scope, and DCE removes it. The decisive positive probe was `[deprecated(...)]`: the bare use fires `warning[E31200]` at `bar;`, proving lookup resolved it. "No compiler on PATH" is a claim about PATH (release binaries are one curl away), and source-reading cannot settle an absence claim: measure, with controls (a typo at the same line:col must diagnose; the parenthesized form must emit). [Slang: a bare unapplied func ref as an expression-statement is silently accepted (and why no IR appears)](../learnings/1786181574992-slang-a-bare-unapplied-func-ref-as-an-expression-s.md) [Slang silently drops a bare (unparenthesized) non-overloaded function name statement](../learnings/1786181926904-slang-silently-drops-a-bare-unparenthesized-non-ov.md) [Slang silently drops a bare unparenthesized function name — and "no compiler on PATH" is not "no compiler available"](../learnings/1786182172919-slang-silently-drops-a-bare-unparenthesized-functi.md) [A bare function name is a valid Slang statement that silently emits nothing](../learnings/1786182513293-a-bare-function-name-is-a-valid-slang-statement-th.md)

## Module resolution: `import a.b` is parser sugar; `-I` is non-recursive

`-I` search is **non-recursive**: `import mylib;` with the file at `packages/mylib/src/mylib.slang` fails under `-I packages` (E00001) and works only with `-I packages/mylib/src`. **Dotted names do reach subdirectories**: `import mylib.core;` finds `<root>/mylib/core.slang` with one `-I <root>`, because `parseFileReferenceDeclBase` (`slang-parser.cpp:1341-1352`) appends `/` per `Dot` token. `getFileNameFromModuleName` (`slang-session.cpp:1468`) only does underscore→dash and `.slang`, so grepping there reads as "feature doesn't exist"; the guilty control (delete the target → `cannot open file 'mylib/core.slang'`) settles it.

Sharp edges: quoted imports get NO sugar (`import "mylib.core";` opens `mylib.core.slang`); nothing ties a `module` decl to its import path; `module mylib.core;` is invalid syntax. Outside the language server, `.slang-module` (IR) is tried *before* source (`slang-session.cpp:1583`), so a stale binary module can shadow fresher source when the source is unreachable for freshness validation. [Slang `import a.b` reaches subdirectories via a PARSER dot→slash rewrite; `-I` itself is non-recursive and quoted imports get no sugar](../learnings/1786040130872-slang-import-a-b-reaches-subdirectories-via-a-pars.md)

## Parallel compilation: one `IGlobalSession` per thread

For `STATUS_ACCESS_VIOLATION` in parallel compilation "even with a mutex on the global session", the answer is **a distinct `IGlobalSession` per thread**. `docs/user-guide/08-compiling.md:720` and `slang.h:4071` say the global session is not thread-safe, and `:1011` requires external synchronization for threads sharing a global session, a session, **or objects created from them**. A lock around `createSession` cannot help: `slang-session.cpp:71` does `namePool = session->getNamePool();`, so every `Linkage` uses the global session's **by-value** `NamePool`, and concurrent `loadModule`/checking interns into one unsynchronized pool (maintainer-confirmed on #8581). Only backend emission after full specialize+link is parallel-safe. There is **no module-unload API by design** (#4645); recreating a session is cheap since the core module amortizes on the global session. [Slang: parallel compilation needs one IGlobalSession PER THREAD — a mutex around createSession cannot work](../learnings/1786088362639-slang-parallel-compilation-needs-one-iglobalsessio.md)

## The `slang` dispatcher

`source/slang-dispatcher/` builds `slang` with builtin subcommands (compile→slangc, interpret→slangi, help, version) and sends any unknown subcommand to a sibling `slang-<subcommand>` (`main.cpp:484`), so `slang-foo` becomes `slang foo` with no dispatcher change (PR #10621, v2026.5.1). Gotchas: **PATH is NOT searched**, only the binary's own directory (contrary to #10621's prose); no abbreviation; a dotted subcommand is treated as a file (`looksLikeFilePath()`). The binary lives in `build/slang-<ver>-linux-x86_64/bin/slang`, not `build/{Debug,Release}/bin` (reporting it absent was a false capability-negative). The delegation path is untested (one `//TEST:DISPATCHER` case). [Slang already has a `slang` dispatcher that routes unknown subcommands to sibling `slang-<name>` binaries — sibling-dir ONLY, no PATH](../learnings/1786040102016-slang-already-has-a-slang-dispatcher-that-routes-u.md)

## System-value semantics and workgroup intrinsics

**Scalar `SV_DispatchThreadID` narrows by SWIZZLE, not linearization.** Slang allows `uint`/`uint2`/`int`/`int2` besides `uint3`, and `tryConvertValue` (`slang-ir-legalize-varying-params.cpp:293`) emits `.x`, so `uint tid : SV_DispatchThreadID` under `[numthreads(8,8,1)]` compiles clean and a whole column shares `tid`; scalar is correct only for 1D dispatch. For a flat index use `SV_GroupIndex` or flatten: `dispatchThreadID = groupID*extents + groupThreadID`, `groupIndex = (z*Ny+y)*Nx+x`; `emitCalcGroupExtents` bails on a non-literal extent. Metal/WGSL diagnose `SystemValueTypeIncompatible` instead of converting, so `uint2` is safest on SPIR-V/GLSL/CUDA. [Slang scalar SV_DispatchThreadID is component .x, not a flattened index](../learnings/1786115913613-slang-scalar-sv-dispatchthreadid-is-component-x-no.md)

**`WorkgroupSize()` is a compile-time constant** returning signed **`int3`** (`hlsl.meta.slang:7837`; DeepWiki's `uint3` is wrong). `materializeGetWorkGroupSize` (`slang-ir-translate-global-varying-var.cpp:438`) splices the `IRNumThreadsDecoration` operands into each use inside `linkAndOptimizeIR`, outside any `switch(target)`, so zero `GetWorkGroupSize` hits across the emitters means portability, not a missing arm. Spec-constant `[numthreads]` hard-errors on HLSL/Metal/WGSL/CPU (`slang-emit-c-like.cpp:294`). Because it is folded, a CUDA/Metal kernel launched with another block size still sees the declared size, while CUDA `blockDim` and `SV_GroupIndex` follow the real launch; see [[wiki/concepts/slang-backends-compute-thread-group-size-and-dispatch-override.md]]. [Slang WorkgroupSize() folds to a constant pre-emit; WorkgroupCount() is GLSL/SPIR-V only](../learnings/1786117126710-slang-workgroupsize-folds-to-a-constant-pre-emit-w.md) The splice adds no casts (`:463-471, 510-516` at master 7251cc6 builds `makeVector(Vec(Int,3), operands)`), so a `[SpecializationConstant] const uint` axis with `int3 w = WorkgroupSize();` fails SPIR-V validation while `WorkgroupSize().x` is fine (pre-existing, found triaging #13767; the WGSL `@workgroup_size` type rule is on [[wiki/concepts/slang-backends-wgsl-on-gpu-execution.md]]) [WGSL @workgroup_size override args must share one int type; WorkgroupSize() makeVector lacks casts](../learnings/1792502196007-wgsl-workgroup-size-override-args-must-share-one-i.md).

**`uint3 WorkgroupCount()` works on GLSL/SPIR-V and on WGSL since #13920 (fc02240aa, 2026-10-29); Metal, CUDA, PTX and HLSL still give E36107 (#14034).** `hlsl.meta.slang:18` declares `in uint3 __builtinWorkgroupCount : SV_WorkgroupCount;` and WGSL maps it to `num_workgroups` (`slang-ir-legalize-varying-params.cpp:5197`). `translateGlobalVaryingVar` (`slang-emit.cpp:2074`) turns that global into an entry-point parameter before `legalizeIRForMetal` / `legalizeEntryPointVaryingParamsForCUDA` run, so each missing arm is one case in that target's system-value switch (Metal `getSystemValueInfo`; CUDA switch at :2497 plus a global like `blockDim` at :2419), as `WaveGetLaneCount()` on Metal already does. A user parameter `: SV_WorkgroupCount` is E49999 on every target (no `semantic sv_workgroupcount` decl in `core.meta.slang`). On Metal, `__intrinsic_asm "threadgroups_per_grid"` exits 0 but emits a call and no `[[...]]` parameter, so a value that exists only as a kernel attribute must go through the legalizer. The CUDA `gridDim` workaround runs correctly on the L40S [Slang WorkgroupCount(): WGSL works since #13920; Metal/CUDA need SV_WorkgroupCount mappings; __intrinsic_asm can't supply Metal entry-point attributes](../learnings/1793295609658-slang-workgroupcount-wgsl-works-since-13920-metal-.md).

**The front-end SV stage check (E30702) misses global varyings and `-ignore-capabilities`.** `validateSystemValueSemantic` (slang-check-shader.cpp ~2020-2073) checks only entry-point **parameters and return**, so a global `in uint g : SV_PrimitiveID;` is unchecked, and it reports through `diagnoseCapabilityErrors`, which `-ignore-capabilities` silences. Both paths reach `legalizeSystemValue` / `ensureStructHasUserSemantic`: while the semantic is unmapped the user gets a clean E55202, but once a PR maps it (WGSL `SV_PrimitiveID` → `@builtin(primitive_index)`, slang#13619) they emit the builtin in the wrong stage or without its `enable`, and naga rejects it. So "the front end restricts it to fragment input" is not a sufficient review answer. Probe a global `in` in vertex/compute and, under `-ignore-capabilities`, vertex I/O and fragment output; validate with naga-wasm (`node naga-check/val.mjs`). Master already leaks vertex-shader global `in SV_SampleIndex`/`SV_IsFrontFace` into invalid WGSL. Remedy: the legalizer rejects non-fragment stages, including the VaryingOutput path in `ensureStructHasUserSemantic` [the E30702 stage check skips global varyings and -ignore-capabilities](../learnings/1791965980843-slang-sv-front-end-stage-check-e30702-skips-global.md).

## Matrix truncation is explicit-cast-only and yields the upper-left submatrix

`(float3x3)someFloat3x4` yields the upper-left 3×3, only as an explicit cast. The ctor is *generated*: `core.meta.slang:2857-2867` loops `rr`/`cc` from R/C..4, emitting `__intrinsic_op(kIROp_MatrixReshape) __init(matrix<T,rr,cc,L>)` for larger-or-equal sources. Implicit assignment is rejected: matrix→matrix coercion (`slang-check-conversion.cpp:2237`) requires equal shape and the ctor has no `__implicit_conversion`. Upper-left is provable: `slang-ir-peephole.cpp:1575` truncates rows, `slang-ir.cpp:4643` swizzles each row to `[0..toCount)`, and `tests/bugs/matrix-reshape.slang` checks it. Growing zero-pads.

Method lesson: `grep 'float3x3'` on `hlsl.meta.slang` returns **ZERO**; concrete spellings are meta-generated typedefs (`core.meta.slang:2601`). **In `*.meta.slang`, grep the generator, not the user spelling, and treat a zero-hit grep as "wrong query", not "absent"**; the same trap fired on `$(ccName)`-generated RayQuery methods and on `operator ++` written with a space. [Slang truncates matrices via an explicit-only generated ctor — verify at the generator, not the grep](../learnings/1786134501113-slang-truncates-matrices-via-an-explicit-only-gene.md)

## Generics: independent axes and full-contract checks

On BFloat16 for cooperative vectors (#12411) a maintainer chained three blockers, and measurement showed two sit on **independent axes**: `CoopVecComponentType` (a `constexpr` enum) is the *memory interpretation*, while `CoopVec<T,N>`'s `T : __BuiltinArithmeticType` is the *register element type*, and nothing makes them agree (`CoopVec<FloatE4M3,4>` fails E38029, yet `coopVecMatMul<float,4,4>(..., ::FloatE4M3, ...)` compiles). But `coopVecLoad` takes no interpretation parameter, so there the constraint *is* the only gate. Rules: test whether chained blockers gate each other; enumerate every API a "not on the critical path" claim covers; check the *whole* contract (`CoopVec` inherits `IComparable`, whose `equals`/`lessThan` need scalar ops BFloat16 lacks → E39999). A hand-written core-module struct outside `FOREACH_BASE_TYPE` cannot inherit conformance through the generated loop, so "just add the conformance" is never a one-liner there. [A generic constraint and a runtime enum parameter can be two independent axes — measure both before calling one a blocker](../learnings/1786049811729-a-generic-constraint-and-a-runtime-enum-parameter-.md)

## Constant folding: an all-literal probe never touches the backend

Slang folds all-literal arithmetic before the backend: `dot(float2(-0.0,-0.0), float2(1,1))` on `-target spirv` emitted **0** `OpDot`. Control: require the op under test in the emitted code; read operands from a buffer (`RWStructuredBuffer` + `//TEST_INPUT:ubuffer(data=[0x80000000 ...])`, hex for exact bits). `slang-test` inserts `-O0` into any directive lacking `-OX` while `slangc` uses the default (`OpDot` survives at `-O0`, folds at `-O1`), so record the opt level. Unrolling an accumulator loop drops the `T(0) +` seed, an observable signed-zero change (`0.0 + (-0.0) == +0.0`), so "just unroll it" needs an identity-element check. [Slang folds all-literal arithmetic before it reaches the backend — a "real hardware" measurement on constant inputs may never touch the driver](../learnings/1786037229044-slang-folds-all-literal-arithmetic-before-it-reach.md) [Slang: [ForceUnroll] on a core-module __target_switch default arm — measure the arm set per overload, the FP and integer twins differ](../learnings/1786035420979-slang-forceunroll-on-a-core-module-target-switch-d.md)

**Measure the `__target_switch` arm set per overload, not per function name.** `hlsl.meta.slang`'s FP `dot` fallback has `glsl`/`metal` arms and the integer one does not, so a float-shader blast-radius result ("C-like only") was wrong for integers. `[ForceUnroll]` failure is a hard E40020, but `vector<T,N>` bounds the trip count to 1..4 (`N>=5` is E38206).

## The "core module counts as imported" trap

"No `import` line ⇒ cross-module logic cannot fire" is **FALSE**. A file with zero imports that redefines `int max(int,int)` trips `warning[E38208]: ... chose ... from imported module 'core'`, because the implicit modules (`core`, plus `glsl` under `-allow-glsl`) report as imported without an `import` statement. A structural exclusion holds *only when the enumeration is complete*; grep for the *behavior*, not its usual syntax. ["No import ⇒ cross-module logic cannot fire" is FALSE in Slang — the core module reports as `imported module 'core'`, so stdlib shadowing needs zero import lines](../learnings/1786044404247-no-import-cross-module-logic-cannot-fire-is-false-.md)

## `__target_switch`: whole-function case selection, missing-return gating, and capability hoisting

`specializeTargetSwitch` (`slang-ir-specialize-target-switch.cpp`) selects EXACTLY ONE case for the whole function by capability specificity ("larger implied atom set wins", `slang-capability.cpp:1417-1420`), reading GLOBAL target caps. It is the producer-side selection layer upstream of the `targetCaps.implies(...)` gates in `slang-ir-spirv-legalize.cpp`/`slang-emit-spirv.cpp`; editing those does not move selection and regresses (slang#11631), so fix the meta-source.

**A missing case does not fall back.** `specializeTargetSwitch` injects an `emitMissingReturn()` sentinel and `doesTargetAllowMissingReturns` (`slang-ir-missing-return.cpp:18-26`) gates it: hard `E41009 "non-void function must return"` on SPIR-V/GLSL/WGPU (even for `void`, since the pass keys on the sentinel), at most an `E41010` warning elsewhere, and on CUDA the call is SILENTLY DROPPED — in a `[CudaKernel]`, force-inlining moves the `missingReturn` terminator into the kernel, so DCE also deletes every later statement [A no-cuda intrinsic in a [CudaKernel] deletes every later statement, not just its own store](../learnings/1793990067393-a-no-cuda-intrinsic-in-a-cudakernel-deletes-every-.md). This hit HitObject/SER methods with only `case hlsl:` (#12553 2-arg `HitObject::Invoke`, #10307 `HitObject.FromRayQuery`). Fix: mirror a sibling overload's `spirv`/`glsl`/`cuda` cases and widen `[require(...)]`. SPIR-V/GLSL SER ops never take an AccelerationStructure (it is baked into the `HitObject`), so a no-TLAS form maps to identical ops, but `case cuda: __intrinsic_asm "optixInvoke"` forwards args positionally, so it needs matching 2-arg wrappers in `slang-cuda-prelude.h`. (`hlsl.meta.slang` is >1 MB: `gh api` contents returns `content:""`; use `git show`.) [HitObject/SER core-module method missing a `__target_switch` case → E41009](../learnings/1789454795235-hitobject-ser-core-module-method-missing-a-spirv-g.md)

**With two capabilities enabled, the more specialized arm captures the WHOLE function**, so a less specialized arm's per-kind carve-out is never reached (#13070: `spvDescriptorHeapEXT` (2 atoms) out-ranked `spvBindlessTextureNV` (1 atom), routing texture/sampler handles to the EXT heap instead of `OpConvertUTo{Image,Sampler}NV`). Rather than a compound `case A + B:` with unverified ranking, HOIST a second `__target_switch` ahead of the main one naming ONLY the weaker capability. It MUST end in `default: break` (compiles to a branch to the continuation); without `default` it traps (missing-return) on every target lacking the cap. [__target_switch: hoist a less-specialized capability's per-kind case ahead of the main switch](../learnings/1789460740871-slang-target-switch-hoist-a-less-specialized-capab.md)

**A case-less `__target_switch` is not always removed by DCE** before a no-case check. `export`/`[DllExport]` functions and methods reachable through dynamic dispatch (`createDynamicObject` with `-conformance`) survive DCE, so a post-DCE no-case diagnostic (E41037 on PR #13564's head; not on master as of 2026-10-16) fires for them even without `-ignore-capabilities`. A dispatch repro must call through the interface from the entry point. HostVM is not a silent hole: empty target caps report E41011 "`__target_switch` has no compatible target" ([#13564: export and dynamic-dispatch methods survive DCE](../learnings/1792060963846-slang-pr-review-reviewer-a-30-budget-can-stop-6-7-.md)).

## meta.slang type predicates: `__isFloat<T>()` is true for double (#13773)

`__isFloat<T>()` lowers to `kIROp_IsFloat`, which peephole (`slang-ir-peephole.cpp` ~:1934) folds through `isFloatingType` (`slang-ir.cpp` ~:8714), true for Half, Float and Double. So `if (__isFloat<T>() || __isHalf<T>()) mad(...) else fma(...)` never takes the else branch: the scalar `fma` `case hlsl:` (`hlsl.meta.slang` ~:11862) has emitted `mad` for double since 2024-02, giving DXIL FMad (op 46) instead of Fma (op 47), and no test checked HLSL fma output. Branch on an exact type with `__type_equals<T, double>()` (folds via `kIROp_TypeEquals`; idiom at `glsl.meta.slang:9402`) and leave `__isFloat` alone, since other callers rely on it. HLSL `fma` is double-only, so float/half `fma` must still emit `mad` or DXC errors. GPU-free check: `slangc -target dxil-assembly -profile cs_6_5`, grep `dx.op.tertiary.f64(i32 47` vs `46`; fix PR #13779 (open 2026-10-21). Related: a capability-specific case (`case spvXxx:` before `case spirv:`) is taken only when `-capability`/`-profile` imply the atom; an entry-point `[require(...)]` does not select it (`slang-ir-specialize-target-switch.cpp:52-64`) [__isFloat<T>() is true for double](../learnings/1792503417674-slang-core-module-isfloat-t-is-true-for-double-use.md) [__isFloat<T>() means any floating type; use __type_equals](../learnings/1792507691855-slang-core-module-isfloat-t-means-any-floating-typ.md).

## meta.slang `static_assert` is the only compile-time diagnostic: error-only, per-instantiation

`static_assert(constexpr bool, NativeString msg)` (`core.meta.slang:483`) is the ONLY compile-time diagnostic in the meta language (no `static_warn`/`__diagnostic`). So a REJECT keyed on a generic parameter lives in `*.meta.slang`, but a WARNING needs a checker-side path (a `slang-diagnostics.lua` entry plus a hook at the conversion site). In a generic member body it fires per-instantiation, only when the offending specialization is used, as in `_Texture` bodies keyed on generic `let`s (`hlsl.meta.slang:1791/1894/1937`, `isShadow`/`isArray`/`isMS`/`access` at `:1135-1161`). For an interface-bound `T`, read the interface's `static const` (`_Texture`'s `static const DescriptorKind kind`, readable as `T.kind` through `DescriptorHandle<T>`; `switch(T.kind)` at `hlsl.meta.slang:28023`). Prefer `static_assert` to *omitting* a member, which gives only "cannot convert X to Y" (context #13085: single-index ResourceDescriptorHeap → combined texture/sampler silently uses sampler slot 0 via zero-fill `__init`s, `:27622`/`:27905`). [meta.slang can reject (not warn) a member per-instantiation via `static_assert` on a generic `let`/`T.kind`](../learnings/1789457618247-meta-slang-can-reject-not-warn-a-member-per-instan.md)

## How the checker learns the dialect: no SourceLanguage path before #13615, `getSourceLanguage()` after

Before #13615 the checker never branched on source language: at master `c0e27bc0e7` (#13073), `SourceLanguage` was read once, in the *parser* (`slang-parser.cpp:10022`), to stamp a `GLSLModuleModifier` on the `ModuleDecl`; `TranslationUnitRequest::sourceLanguage` was never copied onto the `ModuleDecl`, so the checker used `GLSLModuleModifier` + `AllowGLSL` (via `isGLSLOperatorScope`). A dialect-scoped feature then seemed to need a module-AST hook (an `HLSLModuleModifier`, or the maintainer-preferred `ModuleSourceLanguageModifier` carrying a `SourceLanguage`, reachable via `getModuleDecl(decl)`), since baking the dialect onto the *defining* module keeps semantics stable while a use-site read answers differently for definer and importer (witness/ABI divergence) ([Slang checker has no Decl→SourceLanguage path — HLSL-dialect scoping needs net-new module-AST plumbing](../learnings/1789502791946-slang-checker-has-no-decl-sourcelanguage-path-hlsl.md)).

#13615 (e49310561) instead added `SemanticsContext::getSourceLanguage()` (slang-check-impl.h): the `sourceLanguage` of the translation unit being checked, or `Unknown` in reflection/specialization contexts. There is one shared context per translation unit (`checkTranslationUnit`), imported modules are checked in their own, and witness wrappers inherit the conforming type's unit, so the value is never a callee's dialect. The definer-vs-importer concern becomes a rule about which code a dialect rule reads: declaration semantics (e.g. the default receiver mode `getDefaultReceiverParamMode` computes during signature checking) are fixed by the defining unit for every importer; a call-site legality rule (e.g. accepting an immutable receiver for an `inout` method) reads the calling unit [Slang checker: getSourceLanguage() is the call site's dialect, including witness wrappers](../learnings/1793151491149-slang-checker-getsourcelanguage-is-the-call-site-s.md). The HLSL default-`inout` receiver (#13073 → #13615, v2026.20), its #13964 fallout and the call-site fix are on [[wiki/concepts/slang-language-hlsl-receiver-mutability.md]].
