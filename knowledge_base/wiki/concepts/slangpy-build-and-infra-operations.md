# SlangPy Build from Source, Infra/Ops, downstream_args, and slangpy-samples Review

Building and locally verifying SlangPy (native extension and C++ `sgl` layer) in coworker containers; GPU and prod-infra facts; `downstream_args` plumbing (#1058 / PR #1061), and slangpy-samples review (PR #53).

## TL;DR
- **Building slangpy needs `python3-dev` and `--break-system-packages` on every pip call (PEP-668)**; `tools/ci.py install-slangpy-torch` omits the flag; nvcc is not required. An ENOSPC-broken submodule needs `--init --force --recursive`.
- **No root?** `apt-get download` + `dpkg -x` the headers into `/tmp` (re-extract after every restart) and build only `--target slangpy_ext` (~90 s).
- **One worktree and build dir per PR** (a group's sessions share `/workspace/agent/slangpy`); seed submodules locally and copy the main checkout's vcpkg state.
- **GCC 12 Release `all` dies in `examples/tinybc` (`-Werror=restrict` false positive)**: build explicit targets; install `requirements-dev.txt` (libcst) first.
- **The full C++ `sgl` build needs the `data` submodule's two git-LFS fonts** (verify byte sizes; stubs are ~131 B). **A stubgen failure aborts ninja before the `sgl_tests` link — a false green**: require `sgl_tests` and `libsgl.so` mtimes newer than a pre-build stamp.
- **Verify cheaply:** single-TU C++ via its `compile_commands.json` entry + `-fsyntax-only`; pure Python on `DeviceType.cpu` with the checkout first on `PYTHONPATH` and the `.so` copied in (from an unbuilt worktree add `-o pythonpath=<built wt>`).
- **A local full `pytest slangpy/tests` has ~50 git-lfs failures, and the main checkout's `.so` is often stale** (compare `git_version.h` with `git log -1`).
- **Autodiff `.bwds()` repros run on `DeviceType.cpu`** (after #1136) with a private `atomics.slang` `InterlockedAddF32` patch, single-thread only.
- **Re-probe the GPU every session before writing "CPU only"**: containers have an NVIDIA L40S; a really missing GPU is an infra report; bookworm lavapipe is not a fallback. CoopVec kernels compiled but did not run on driver 565.x (no `VK_NV_cooperative_vector`).
- **`downstream_args` reach only DXC (d3d12) and NVRTC (cuda)**, silently dropped elsewhere; NVRTC runs at the first `kernel.dispatch(...)`, so tests must dispatch and expect `RuntimeError`.
- **Python docstrings come from the checked-in generated `src/slangpy_ext/py_doc.h`**; a bound symbol missing from it breaks the build (hand-add it or use `D_NA`).
- **slangpy-samples:** skip generated MDL `.slang`, verify LFS objects resolve and renames keep coverage; bot comment `PATCH` 403s, so post fresh ones.
- **Prod's 6 slang/slangpy group dirs are symlinks into `/ephemeral`**; symlink only untracked, gitignored dirs, moved only with containers stopped.

## Building SlangPy from Source

**Dependencies and PEP-668.** CMake's `find_package(Python ... Development.Module)` needs `python3-dev`/`python3.11-dev` (admin `install_packages` apt); nvcc is not needed (the CUDA backend uses the driver API). Every `pip install` needs `--break-system-packages`, so install the torch bridge by hand: `pip install --break-system-packages wheel && pip install --break-system-packages --no-build-isolation ./src/slangpy_torch`. A container rebuild resets pip site-packages (reinstall `requirements-dev.txt`); the `/workspace` worktree persists. An ENOSPC-interrupted submodule checkout leaves an empty-tree gitlink that `git submodule update --init` skips; use `--init --force --recursive`. Build only `--target slangpy_ext` (~304 steps) to skip C++ test/example binaries; `build/buildtrees` (~765 MB vcpkg intermediates) can be deleted after configure [fixer-container build](../learnings/1782324519820-building-slangpy-from-source-in-the-fixer-containe.md).

**Without root or `python3-dev`.** With no `Python.h`, X11 dev headers or sudo, `apt-get download` + `dpkg -x` still work unprivileged. Point apt state at `/tmp` (`-o Dir::State::Lists=/tmp/apt/lists -o Dir::Cache=/tmp/apt/cache -o Debug::NoLocking=1 update`) and `download` `libpython3.11-dev` and the X11 `-dev` debs one at a time (a list holding an installed package fails). Extract them to `/tmp/pyheaders` and `/tmp/x11prefix`; symlink the runtime libs in `/tmp/x11prefix/usr/lib/x86_64-linux-gnu` (`libXcursor.so.1.0.2`, `libXfixes.so.3.1.0`, `libXi.so.6.1.0`, `libXinerama.so.1.0.0`, `libxkbcommon.so.0`) to the system copies; make `pyconfig.h` resolvable with `CPATH=/tmp/pyheaders/usr/include:/tmp/x11prefix/usr/include` or by copying `usr/include/x86_64-linux-gnu/python3.11/pyconfig.h` into `usr/include/python3.11/`. Configure `cmake --preset linux-gcc -DPython_EXECUTABLE=<venv>/bin/python -DPython_INCLUDE_DIR=/tmp/pyheaders/usr/include/python3.11 -DCMAKE_INCLUDE_PATH=/tmp/x11prefix/usr/include -DCMAKE_LIBRARY_PATH=/tmp/x11prefix/usr/lib/x86_64-linux-gnu`; a clean Release `slangpy_ext` build takes ~90 s on 64 cores [non-root build](../learnings/1792142268329-building-slangpy-in-a-non-root-coworker-container-.md). `/tmp` is wiped on restart while the cache still points there, so the next incremental build dies in glfw (`X11/Xcursor/Xcursor.h: No such file`), then nanobind (`Python.h`), until you re-extract ([re-extract after restart](../learnings/1793850554382-slangpy-debug-build-restore-tmp-x11prefix-and-tmp-.md)).

**Fresh worktree, fast.** Use one worktree and build dir per PR: a group's sessions share `/workspace/agent/slangpy`, and a `git checkout` there moved the branch under another session's build (#1263/#1264) ([per-PR worktrees](../learnings/1793850554382-slangpy-debug-build-restore-tmp-x11prefix-and-tmp-.md)). Init submodules offline, including `data` (cmrc embeds `data/fonts`) and the nested `nanobind/ext/robin_map` and `nanothread/ext/cmake-defaults`, by one of: (a) `git -c protocol.file.allow=always -c submodule.<path>.url=/workspace/agent/slangpy/.git/modules/<path> submodule update --init` (the `url` override can be omitted if the shared config already points there, except for the nested two); (b) `git -C <wt> submodule update --init --reference <main>/.git/modules/<path> -- <path>` ([reuse main vcpkg state](../learnings/1793850765246-slangpy-fast-isolated-worktree-build-by-reusing-ma.md)); (c) when `git ls-tree <sha> external/ samples data` matches a built scratch worktree's SHAs, point each `submodule.<name>.url` at `/workspace/agent/tmp/wt-<old>/<path>` and run `git -c protocol.file.allow=always submodule update --init --recursive` (~2 s; without `-c`: `transport 'file' not allowed`) ([sibling-worktree submodules](../learnings/1793838656591-fast-slangpy-scratch-worktree-clone-submodules-fro.md)). Then `cp -a` the gitignored `external/vcpkg/vcpkg`, `external/vcpkg/downloads` and `build/linux-gcc/vcpkg_installed` from the main checkout (configure ~13 s, `vcpkg install` a no-op) and reuse the main cache's options incl. `-DPython_EXECUTABLE=<main>/.venv/bin/python` (no `python` on PATH). A full Debug build takes ~10 min on 64 cores (Slang tarball via the proxy); the `.so` lands in `<worktree>/slangpy/`, so `PYTHONPATH=<worktree>` suffices.

**GCC 12 Release.** `--preset linux-gcc-release --target slangpy_ext` works, but Release `all` fails in `examples/tinybc` on an `-O3` `-Werror=restrict` false positive in `external/include/argparse/argparse.hpp` (Debug is fine). For the C++ tests, build explicit targets `sgl_data copy_binary_files slang-rhi-copy-files sgl slangpy_ext slangpy_stubs sgl_tests`; `slangpy_stubs` runs `tools/postprocess_stub.py`, which imports `libcst`, so install `requirements-dev.txt` first or it fails after `slangpy_ext*.so` links [fresh-main build](../learnings/1792064521058-slangpy-fast-fresh-main-build-repro-in-the-triage-.md), [non-root build](../learnings/1792142268329-building-slangpy-in-a-non-root-coworker-container-.md), [tinybc `-Werror=restrict`](../learnings/1793367272672-slangpy-linux-gcc-release-build-tinybc-werror-rest.md). (The fresh-main atom's "only `DeviceType.cpu` works" reflects the 09-28→10-16 outage.)

### The full C++ `sgl` layer: LFS fonts, stubgen false green

The full `sgl` layer (linux-gcc-debug, for the doctest `sgl_tests` / profiler suite) needs the `data` submodule (`slangpy-data.git`): `cmrc_add_resource_library(sgl_data ...)` is an unconditional PUBLIC link dep. Its two fonts are git-LFS; without git-lfs they are ~131-byte pointer stubs and ninja fails on `Inconsolata-Regular.ttf` before any source compiles (an infra gap, not your code). Init without the smudge filter (`git -c filter.lfs.smudge= submodule update --init data`), fetch the binaries via GitHub's LFS batch API, and verify by `file *.ttf` or byte sizes (Montserrat 197624 B, Inconsolata 101752 B) [LFS fonts](../learnings/1784867803689-slangpy-c-build-needs-data-submodule-lfs-fonts-git.md). The `.pyi` stubgen targets (nanobind stubgen + `tools/postprocess_stub.py`) import the built module, needing `numpy` and `libcst` (`pip install --user --break-system-packages numpy libcst`) [stubgen deps](../learnings/1784868284126-slangpy-c-build-needs-the-data-lfs-submodule-numpy.md).

**A stubgen failure is a false green for `sgl_tests`.** `libsgl.so` links before stubgen but the test binary does not, so a missing `numpy`/`libcst` aborts ninja before the `sgl_tests` link and the old binary "passes" against pre-change code. Build `--target sgl_tests` explicitly and check the dynamically linked `libsgl.so` relinked too: stamp `date '+%F %T'` first, then require `ls -l --time-style=full-iso build/linux-gcc/Debug/sgl_tests build/linux-gcc/Debug/libsgl.so` mtimes newer than the stamp. A fresh `.o` is not enough. Baseline failures: the 5 Git-LFS fixture cases (3 in `test_dds_file.cpp`, 2 in `test_texture_loader.cpp`); `platform/environment` in doctest output is just a `MESSAGE` header ([stubgen false green](../learnings/1785774319630-slangpy-stubgen-failure-aborts-ninja-before-linkin.md)).

**Single-TU C++ compile-verify.** In the main checkout's `build/pip/compile_commands.json`, take the entry whose `file` is your source and whose `output` is under the intended library's `.dir` (`sgl.dir`, not `slangpy_ext.dir`; a source compiles into several targets). Reuse its `command` with your worktree copy as input, drop `-c`/`-o`, add `-fsyntax-only`, and run it from the entry's `directory`. That is real compiler proof (full `-std=gnu++20 -Werror` flags) in seconds, missing only link errors. GLFW/AppWindow code cannot be unit-tested here (`glfwInit` fails with empty `DISPLAY`): cursor/window fixes get compile-only plus manual verification ([single-TU compile-verify](../learnings/1789819901846-fast-compile-verify-a-single-tu-c-change-via-compi.md)).

### Pure-Python changes without a native rebuild

Use the prebuilt venv `/workspace/agent/slangpy-main-build-venv/bin/python` (has `numpy`; ephemeral `pip install -q pytest` is fine) with your checkout first on `PYTHONPATH` (its own `slangpy` is in site-packages; confirm `spy.__file__`) and the gitignored `slangpy_ext.cpython-311-*.so` copied from `/workspace/agent/slangpy/slangpy/` into `<worktree>/slangpy/`. `spy.DeviceType.cpu` runs the functional API headless and `spy.Device(type=vulkan/cuda)` constructs, enough for tests failing at module resolution; tests parametrize over `helpers.DEFAULT_DEVICE_TYPES` (linux → `[vulkan, cuda]`; none use `cpu`). slangpy#1177's `SHADER_PATH` fix (PR #1178) was verified this way ([pure-Python on CPU](../learnings/1790023108329-test-pure-python-slangpy-changes-locally-without-a.md)). Running a PR's tests from an unbuilt worktree with `PYTHONPATH=<built wt>` fails: `pyproject.toml`'s `pythonpath = ["."]` makes pytest prepend the test file's rootdir, so `import slangpy` finds no `.so`. Pass `-o pythonpath=<built wt>` and print `slangpy.__file__` after `pytest.main([...])`; even then only test and fixture edits run, because the built extension loads sgl shaders (`src/sgl/device/*.slang`) from `<built wt>/build/linux-gcc/Release/shaders` (slangpy#1258 / PR #1257; [`pythonpath` shadowing](../learnings/1793687165666-slangpy-pytest-pythonpath-shadows-pythonpath-when-.md)).

### Local full-suite pytest traps

Before calling a local `pytest slangpy/tests` failure a regression:

1. **Missing dev deps.** The venv lacks `deepdiff` (and pytest-timeout, pytest-xdist, imageio), so collection aborts on `test_declrefs.py` and `test_shapes.py`: `pip install --target /tmp/deps deepdiff imageio`, delete the numpy it pulls in (it shadows the venv's), add `/tmp/deps` to `PYTHONPATH`. xdist is unnecessary (as of 2026-11-09 the xdist venv `tmp/venv-1258` is gone; venv-1189/1260/126 lack it): serial L40S runs from `/tmp` with `-o pythonpath=<worktree>` take ~83 s for `slangpy/tests/device --device-types vulkan,cuda`, ~84 s / ~121 s for `slangpy_tests` on Vulkan / CUDA, and two suites run side by side cleanly. The build interpreter is CMakeCache `Python_EXECUTABLE` (venv-1189). Absolute-path node ids with parametrize brackets (`...::test_x[...-DeviceType.cuda]`) are "not found" from `/tmp`; select with `--device-types cuda -k "<name> and <substr>"` ([serial L40S sweeps](../learnings/1794236077554-slangpy-local-l40s-test-sweeps-are-fast-serially-v.md)).
2. **~50 failures are git-lfs pointers.** 51 of 53 `data/test_images/` files are 130-byte pointers, so `test_bitmap.py` (png_read_bit_depth, dds_read, dds_detect_format), `test_bc_codec.py::test_load_and_decode_dds` and every `test_texture_loader.py` variant fail ("Unknown file format!", "DDS file has invalid header"). Expected L40S vulkan+cuda tally: ~3633 passed / 50 failed / 599 skipped. In a worktree, copy real files from the main checkout's `data/`; 11 C++ `sgl_tests` fail the same way ([LFS pointers in fixer containers](../learnings/1793842659420-slangpy-torch-fallback-bridge-bf16-copy-path-only-.md)).
3. **The main checkout's native `.so` is often older than its Python sources.** A Sep 22 fixer `.so` under e7bb2242 lacked `_set_default_slang_include_paths` (conftest NameError); a reviewer `.so` from da8844f under pr-1182 (13f50dc) made `spy.create_device` raise `TypeError: DeviceDesc.__init__`. Compare `build/linux-gcc/git_version/git_version.h` with `git log -1` before trusting a run; to test without touching the checkout, `git archive <built sha> slangpy | tar -x -C /tmp/x`, symlink the `.so` into `/tmp/x/slangpy/`, copy `slangpy/.build_dir`, and run with `PYTHONPATH=/tmp/x` ([local pytest](../learnings/1792466857244-slangpy-local-pytest-50-bitmap-dds-texture-failure.md), [stale reviewer `.so`](../learnings/1792484603209-slangpy-reviewer-main-checkout-native-so-is-stale-.md), [worktree LFS-pointer failures](../learnings/1792466654227-slangpy-tests-no-device-type-param-skipped-under-d.md)).

### Autodiff `.bwds()` repros on the CPU device

Functional-API autodiff repros run on `spy.Device(DeviceType.cpu)` given the #1136 zero-dispatch-groups fix (4bf28e5b or later). The cpp target cannot emit `InterlockedAddF32`, so every DiffTensor gradient kernel dies with E99999 "unexpected IR opcode" at `atomics.slang:37`; in a private package copy (tar `slangpy/`, put it on `PYTHONPATH`) replace that line with `__target_switch { case cpp: buf.Store(addr, asuint(asfloat(buf.Load(addr)) + value)); default: buf.InterlockedAddF32(addr, value); }` — not atomic, so single-thread repros only. To check another Slang pin without rebuilding, set `SLANGPY_PRINT_GENERATED_SHADERS=1`, save kernel and user module as `.slang`, run `slangc k.slang -I . -I <that version's slangpy/slang> -target hlsl -entry compute_main -stage compute`, and grep for `InterlockedAdd` and `_grad_in` reads. Sources must match the `slangc` version (4bf28e5b sources fail on 2026.18.3 with E30019); wrap each call in `timeout` (some combinations hang). Used for slangpy#1204, downstream of slang#13301 ([autodiff on CPU](../learnings/1791189869324-slangpy-autodiff-repros-run-gpu-free-on-devicetype.md)).

### Prod Coworker Group Dirs Symlinked to /ephemeral
On prod, the 6 coworker group dirs `groups/slang{,py}-{fixer,triager,reviewer}` are symlinks into `/ephemeral/prod-groups/<name>` (the 251G `/dev/vdb`); `initGroupFilesystem` follows them via `fs.existsSync`, so they are not re-created on wake. Only untracked, gitignored coworker dirs are safe to symlink (`groups/main/` has a git-tracked file and stays a real dir); move a dir only while its group's containers are stopped [group dirs on /ephemeral](../learnings/1780720000000-prod-coworker-groups-symlinked-to-ephemeral.md).

### Bot Cannot Edit Issue Comments on slangpy-samples
`PATCH` of any issue comment on `shader-slang/slangpy-samples`, even the bot's own, returns HTTP 403 "Must have admin rights to Repository"; `POST` works. Post a fresh delta comment instead, and assume the same for other shader-slang repos with this token scope until proven otherwise [samples PATCH 403](../learnings/1781603959329-slangpy-samples-editing-bot-issue-comments-403s-ad.md).

### Re-probe the GPU every session; lavapipe is no fallback
Fleet containers have an NVIDIA L40S with CUDA and NVIDIA Vulkan ([L40S](../learnings/1792133264162-coworker-containers-have-an-nvidia-l40s-gpu-cuda-vulkan.md)). From 2026-09-28 to 10-16 a host passthrough bug removed it (nanoclaw's `detectGpuMode`, `src/drivers/index.ts`, adds `--gpus` only when the host has `ENABLE_GPU=1` or `/usr/bin/nvidia-smi`), leaving the slangpy fixer and triager without `/dev/nvidia*` or `libcuda` (slangpy#1181; [historical outage](../learnings/1792089571497-agent-containers-have-no-gpu-since-2026-09-28-host.md)). A carried "no GPU" note goes stale and damages public verdicts (#126 needed a next-day edit). Before writing "CPU only", run `nvidia-smi -L` and try `spy.Device(type=spy.DeviceType.vulkan / cpu / cuda)`; to re-verify an old CPU repro, `sed s/DeviceType.cpu/DeviceType.vulkan/` and rerun with `PYTHONPATH=<built worktree>`. A GPU that is really missing is an infra report ([re-probe the GPU](../learnings/1792136253471-slangpy-triage-re-probe-the-gpu-every-session-a-no.md)).

Debian bookworm's lavapipe (Mesa 22.3.6) cannot stand in: slang-rhi requests `VK_KHR_shader_non_semantic_info` unconditionally (`vk-device.cpp:596`, pin `82c03494`; see [[wiki/concepts/slang-rhi-backend-runtime.md]]), so `spy.Device(type=vulkan)` raises "Failed to create device!" though `enumerate_adapters` lists llvmpipe; patching slang-rhi would change the tested binary. On substitute hardware, run a positive control (the known-bad build must still reproduce) before trusting a negative. A Slang build dir configured with the GPU caches `CUDA_cuda_driver_LIBRARY` (`libcuda.so`); without the driver ninja dies on it: clear that entry or reconfigure. To confirm a fix resolved a CI failure, check the job log shows the test PASSED (a skip is invisible at run level) via `gh run view <run> --job <id> --log` (`gh api .../jobs/<id>/logs` refuses output with escape sequences) ([bookworm lavapipe](../learnings/1790628362287-slangpy-vulkan-tests-can-t-use-debian-bookworm-lav.md), [lavapipe is no substitute](../learnings/1790628523920-lavapipe-can-t-substitute-for-a-gpu-in-slangpy-vul.md)).

## slangpy-samples review (PR #53)

MDL material `.slang` files (e.g. `mdl_ceramic_material.slang`, 3492 lines of Itanium-mangled generated code) are vendored: review only the trailing hand-written `IMaterialInstance` wrapper (~190 lines). Verify LFS objects resolve (a dangling pointer means a non-runnable sample): POST each ~130-byte pointer's `oid`/`size` to the repo's `info/lfs/objects/batch` endpoint; `actions.download` means it exists. `experiments/` has zero CI (only `examples/` entries in `test_examples.py` run), so an examples→experiments rename loses coverage only if the demo was a test entry; check `git show main:tests/examples/test_examples.py` ([samples PR #53](../learnings/1783721228354-slangpy-samples-utracer-experiment-pr-53-mdl-files.md)).

Measure the GPU when such PRs need one. On the L40S with driver 565.57.01 (CUDA 12.7, measured ≤09-22), compute and Vulkan `cooperative_matrix` ran, but the driver advertises `VK_NV_cooperative_matrix` and not `VK_NV_cooperative_vector`, so `has_feature(cooperative_vector)` is False on Vulkan and CUDA and all 45 `test_coopvec.py` cases skip, while CoopVec kernels still compile (slangc exit 0). Say "the driver doesn't expose VK_NV_cooperative_vector", not "GPU-less" [coop-vec not runnable](../learnings/1784831657952-this-env-has-a-gpu-nvidia-l40s-but-coop-vec-is-not.md).

## downstream_args Plumbing to Downstream Compilers (#1058, PR #1061)

`SlangCompilerOptions.downstream_args` (and `link_options.downstream_args`) are forwarded via `session_options.add(CompilerOptionName::DownstreamArgs, "<tag>", arg)` (`<tag>` = SlangPassThrough name). Only DXC (`"dxc"`, d3d12) and NVRTC (`"nvrtc"`, cuda) consume them; Vulkan/Metal/WGPU/CPU have no downstream compiler. Before PR #1061 both `create_session` (`src/sgl/device/shader.cpp:322`) and `ShaderProgram::link` (~:1540) hardcoded d3d12/`"dxc"`, so on CUDA `downstream_args=["--use_fast_math"]` was silently dropped, while `floating_point_mode=fast` always worked because it is a first-class per-target Slang option (`shader.cpp:397`). The fix adds a CUDA branch with `add(DownstreamArgs, "nvrtc", arg)` (CLI `-Xnvrtc`), a tag already used in-tree for OptiX includes ([downstream_args D3D12-only](../learnings/1783910132054-slangpy-downstream-args-only-forwarded-for-d3d12-d.md)).

**Testing it requires a dispatch.** On CUDA (SLANG_PTX), NVRTC runs neither at `session.link_program()` nor at `device.create_compute_kernel()` (reflection only); `ComputeKernel::pipeline()` (`kernel.cpp:35-40`) creates the pipeline lazily on the first `kernel.dispatch(...)`. A test that an arg reaches NVRTC (or a bogus one is rejected) must create an output buffer and dispatch; PR #1061's first version asserted a raise at create time and CI failed "DID NOT RAISE". A pipeline-time NVRTC/RHI failure surfaces as `RuntimeError` (`SLANG_RHI_CALL`→`SGL_THROW`), not `spy.SlangCompileError`; `pytest.raises(RuntimeError)` covers both ([NVRTC deferred to dispatch](../learnings/1783912568549-slangpy-cuda-nvrtc-codegen-is-deferred-to-first-di.md)).

### `py_doc.h`: Generated Python Docstrings

**Editing a `///` docstring in `src/sgl/device/shader.h` does not reach Python.** Docstrings come from the checked-in `src/slangpy_ext/py_doc.h`, generated by pybind11_mkdoc via the `slangpy_pydoc` target (`src/slangpy_ext/CMakeLists.txt:227`, needs a full build and the vcpkg include dir). Otherwise hand-edit `py_doc.h` to match: `static const char *__doc_sgl_SlangCompilerOptions_<field> = R"doc(...)doc";`, ~70-col reflow, ASCII, no trailing whitespace (pre-commit excludes it from clang-format) (#1058 / PR #1061; [py_doc.h desync](../learnings/1783909847856-slangpy-py-doc-h-must-be-updated-when-editing-slan.md)).

**A newly bound method or class breaks the build if its symbol is missing from `py_doc.h`**: `D(Device, new_method)` expands to `DOC(sgl, ...)` → `__doc_sgl_Device_new_method`. The mkdoc target needs `pybind11_mkdoc` + clang ≥ 20.1.5 + libc++, usually absent in coworker containers, so hand-add the entry in the exact generated format (mirror a neighbor; fields are alphabetical) or use `D_NA(Device, new_method)` (expands to `"N/A"`); prefer hand-adding for user-facing APIs (PR #1158 / issue #1155) ([hand-add or `D_NA`](../learnings/1789376759049-slangpy-py-doc-h-is-committed-generated-hand-add-d.md)). The same hand-apply rule holds for `docs/generated/api.rst`, stale on main: `docs/generate_api.py` rewrites ~700 unrelated lines, including platform object addresses, so add only your own entries ([api.rst is stale on main](../learnings/1793842659420-slangpy-torch-fallback-bridge-bf16-copy-path-only-.md)).

**mkdoc strips the leading underscore from underscore-prefixed names**: private `Device::_notify_command_recording_submitted` becomes `__doc_sgl_Device_notify_command_recording_submitted`, so grepping `__doc_sgl_Device__...` wrongly suggests it is undocumented. mkdoc emits empty entries (`R"doc()doc"`) for private data members and underscore-prefixed internal methods (not uniformly for every private method); omitting them is cosmetic but churns the next regeneration, so for a callback mirroring siblings prefer regenerating. Related: `CommandEncoder::finish()` sets `m_open=false` only on success (a failed finish leaves the encoder open and retryable); before-finish is not 1:1 with a recording; `discarded` fires only on destruction ([mkdoc strips underscores](../learnings/1789378366162-slangpy-py-doc-h-mkdoc-strips-leading-underscore-f.md)).
