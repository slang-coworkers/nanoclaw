# SlangPy Build from Source, Infra/Ops, downstream_args, and slangpy-samples Review

Building and locally verifying SlangPy (native extension and C++ `sgl` layer) in coworker containers, GPU and prod-infra facts, `downstream_args` plumbing (#1058 / PR #1061), and slangpy-samples review (PR #53).

## TL;DR
- **Building slangpy needs `python3-dev` and `--break-system-packages` on every pip call (PEP-668).** `tools/ci.py install-slangpy-torch` fails because its internal `pip install wheel` omits the flag. nvcc is not required. pip site-packages reset on container rebuild. An ENOSPC-interrupted submodule needs `git submodule update --init --force --recursive`.
- **No root and no `python3-dev`?** `apt-get download` + `dpkg -x` into `/tmp`, point `CPATH`/`Python_INCLUDE_DIR` at it, build only `--target slangpy_ext` (~90 s), and copy the vcpkg binary into fresh worktrees.
- **With GCC 12 the linux-gcc Release `all` build dies in `examples/tinybc` (`-Werror=restrict` false positive; Debug is fine).** Build explicit targets (`slangpy_ext`, plus `sgl sgl_tests slangpy_stubs …` for C++ tests) and install `requirements-dev.txt` (libcst) before building.
- **The full C++ `sgl` build needs the `data` submodule, whose two fonts are git-LFS.** Without git-lfs you get ~131-byte pointer stubs and ninja dies on `Inconsolata-Regular.ttf` before any source compiles. Verify byte sizes, not existence.
- **A stubgen (`numpy`/`libcst`) failure aborts ninja before the `sgl_tests` link — a false green.** A stale binary "passes" against pre-change code. Build `--target sgl_tests` and require both `sgl_tests` and `libsgl.so` mtimes newer than a pre-build `date` stamp. A fresh `.o` is not proof.
- **Verify cheaply:** a single-TU C++ change via its `compile_commands.json` entry with `-fsyntax-only`; a pure-Python change on `DeviceType.cpu` with the checkout first on `PYTHONPATH` and the `slangpy_ext` `.so` copied into the worktree.
- **A local full `pytest slangpy/tests` has ~50 environmental failures** (git-lfs pointer images), and the main checkout's native `.so` is often older than its Python sources. Compare `git_version.h` with `git log -1` before using it as a baseline.
- **Autodiff `.bwds()` repros run GPU-free on `DeviceType.cpu`** once the #1136 fix is in, with a private `atomics.slang` patch for `InterlockedAddF32` (single-thread repros only).
- **Re-probe the GPU every session before writing "CPU only".** Containers have an NVIDIA L40S (CUDA + NVIDIA Vulkan). The 2026-09-28→10-16 no-GPU window was a host passthrough outage. A carried "no GPU" note goes stale; a GPU that is really missing is an infra report. Bookworm lavapipe is not a fallback.
- **Cooperative-vector kernels compile (slangc exit 0) but did not run on driver 565.x**, which lacks `VK_NV_cooperative_vector`. Compile-only checks give false confidence.
- **`downstream_args` reach only DXC (d3d12) and NVRTC (cuda)**; elsewhere they are dropped silently. `floating_point_mode` is a first-class Slang option and a different mechanism.
- **NVRTC compilation is deferred to the first `kernel.dispatch(...)`.** A test that stops at `create_compute_kernel` never runs NVRTC; dispatch with a real buffer and expect `RuntimeError`.
- **Python docstrings come from the checked-in generated `src/slangpy_ext/py_doc.h`, not `shader.h`.** A newly bound symbol missing from `py_doc.h` breaks the build; hand-add the entry or use `D_NA`.
- **On slangpy-samples, do not hand-review generated MDL `.slang` files.** Verify LFS objects resolve and that examples→experiments renames lose no test coverage. `PATCH` of a bot comment 403s there; post fresh comments.
- **On prod, the 6 slang/slangpy coworker group dirs are symlinks into `/ephemeral`.** Symlink only untracked, gitignored dirs, and move them only while containers are stopped.

## Building SlangPy from Source

On a linux-gcc Ninja Multi-Config box (no GPU needed):

- **Dependencies.** `python3-dev`/`python3.11-dev` (admin `install_packages` apt); without it CMake `find_package(Python ... Development.Module)` fails. nvcc is not required, because the CUDA backend uses the driver API at runtime.
- **PEP-668.** Every `pip install` needs `--break-system-packages`. Install the torch bridge by hand, since `tools/ci.py install-slangpy-torch` omits the flag: `pip install --break-system-packages wheel && pip install --break-system-packages --no-build-isolation ./src/slangpy_torch`. A container rebuild resets pip site-packages (reinstall `requirements-dev.txt`); the `/workspace` worktree persists.
- **ENOSPC-interrupted submodule checkout** leaves a gitlink with an empty tree that `git submodule update --init` skips. Use `git submodule update --init --force --recursive`.
- **Build only `slangpy_ext`** (`cmake --build build/linux-gcc --config Release --target slangpy_ext`, ~304 steps) to skip the C++ test/example binaries. `build/buildtrees` (vcpkg intermediates, ~765 MB) is regenerable and safe to delete after configure [Building slangpy from source in the fixer container: python3-dev, PEP-668, torch bridge, submodule/ENOSPC gotchas](../learnings/1782324519820-building-slangpy-from-source-in-the-fixer-containe.md).

**Without root and without `python3-dev`.** The coworker container lacks `Python.h` and the libxinerama/libxcursor/libxi dev headers and has no sudo, but `apt-get download` plus `dpkg -x` works unprivileged. Point apt at `/tmp` state (`-o Dir::State::Lists=/tmp/apt/lists -o Dir::Cache=/tmp/apt/cache -o Debug::NoLocking=1 update`, then `download libpython3.11-dev python3.11-dev libxinerama-dev libxcursor-dev libxi-dev libxinerama1 libxcursor1 libxi6 libxfixes-dev libxrender-dev`). Extract the python debs to `/tmp/pyheaders` and the X11 ones to `/tmp/x11prefix`, export `CPATH=/tmp/pyheaders/usr/include:/tmp/x11prefix/usr/include` (pyconfig.h includes `<x86_64-linux-gnu/python3.11/pyconfig.h>`), and configure `cmake --preset linux-gcc -DPython_EXECUTABLE=<venv>/bin/python -DPython_INCLUDE_DIR=/tmp/pyheaders/usr/include/python3.11 -DCMAKE_INCLUDE_PATH=/tmp/x11prefix/usr/include -DCMAKE_LIBRARY_PATH=/tmp/x11prefix/usr/lib/x86_64-linux-gnu`. `/tmp` is wiped between sessions, so redo the extraction each time. A clean Release `slangpy_ext` build takes about 90 s on 64 cores [building SlangPy in a non-root container](../learnings/1792142268329-building-slangpy-in-a-non-root-coworker-container-.md).

**Fresh worktree, fast.** Init submodules offline with `git -c protocol.file.allow=always -c submodule.<path>.url=/workspace/agent/slangpy/.git/modules/<path> submodule update --init`, repeating for the nested `nanobind/ext/robin_map` and `nanothread/ext/cmake-defaults`. Where the shared config already points submodule URLs at `/workspace/agent/slangpy/<path>`, plain `git -c protocol.file.allow=always submodule update --init` suffices (the nested two still need their URL set in the nested repo config). `cp -a` the gitignored `external/vcpkg/vcpkg` bootstrap binary, `external/vcpkg/downloads` and `build/linux-gcc/vcpkg_installed` from the main checkout: vcpkg then reports "already installed" and configure takes ~13 s; the pinned Slang tarball downloads from GitHub through the proxy. Build `cmake --build --preset linux-gcc-release --target slangpy_ext`. The full **Release** `all` build fails in `examples/tinybc` on a GCC 12 `-O3` `-Werror=restrict` false positive inside `external/include/argparse/argparse.hpp` (Debug is unaffected); to get the C++ tests too, build explicit targets `sgl_data copy_binary_files slang-rhi-copy-files sgl slangpy_ext slangpy_stubs sgl_tests`. `slangpy_stubs` runs `tools/postprocess_stub.py`, which imports `libcst`, so a venv with only numpy/pytest fails there after `slangpy_ext*.so` has linked — install `requirements-dev.txt` first. The `.so` lands in `<worktree>/slangpy/`, so `PYTHONPATH=<worktree>` is all a run needs [fast fresh-main build in the triage container](../learnings/1792064521058-slangpy-fast-fresh-main-build-repro-in-the-triage-.md), [non-root build](../learnings/1792142268329-building-slangpy-in-a-non-root-coworker-container-.md), [linux-gcc Release: tinybc `-Werror=restrict`, stubs need libcst](../learnings/1793367272672-slangpy-linux-gcc-release-build-tinybc-werror-rest.md). (That atom's "only `DeviceType.cpu` works" describes the 09-28→10-16 outage, not the fleet.)

### The Full C++ `sgl` Layer: LFS Fonts and the Stubgen False Green

Building the full C++ `sgl` layer (linux-gcc-debug, for the doctest `sgl_tests` / profiler suite) needs the `data` submodule (`slangpy-data.git`): `cmrc_add_resource_library(sgl_data ...)` makes it an unconditional PUBLIC link dep. Its two fonts are git-LFS files. With git-lfs absent the checkout holds ~131-byte pointer stubs, so ninja fails on `Inconsolata-Regular.ttf` before any source compiles. That is an infra gap, not your code. Init without the smudge filter (`git -c filter.lfs.smudge= submodule update --init data`), fetch the real binaries through GitHub's LFS batch API, and verify with `file *.ttf` or byte sizes (Montserrat 197624 B, Inconsolata 101752 B) [SlangPy C++ build needs data submodule + LFS fonts (git-lfs absent)](../learnings/1784867803689-slangpy-c-build-needs-data-submodule-lfs-fonts-git.md). The final `.pyi` stubgen targets (nanobind stubgen + `tools/postprocess_stub.py`) import the built module and need `numpy` and `libcst` (`pip install --user --break-system-packages numpy libcst`) [SlangPy C++ build needs the `data` LFS submodule + numpy/libcst for stubgen](../learnings/1784868284126-slangpy-c-build-needs-the-data-lfs-submodule-numpy.md).

**A stubgen failure is a false green for `sgl_tests`.** `libsgl.so` links before stubgen runs, but the test binary does not: without `numpy`/`libcst`, `cmake --build --preset linux-gcc-debug` fails at the stub step and aborts ninja before the `sgl_tests` link. Your objects compile fresh, the old `sgl_tests` stays on disk, and it "passes" against pre-change code. This was observed with a binary 10 days older than HEAD passing the tests a fix was meant to change. Build `--target sgl_tests` explicitly, and make sure `sgl` relinked too, because `sgl_tests` links `libsgl.so` dynamically. Before trusting any test number, stamp `date '+%F %T'` before the build, then run `ls -l --time-style=full-iso build/linux-gcc/Debug/sgl_tests build/linux-gcc/Debug/libsgl.so` and require both mtimes newer than the stamp. A fresh `.o` is not sufficient. Expected baseline failures are the 5 Git-LFS fixture cases (3 in `test_dds_file.cpp`, 2 in `test_texture_loader.cpp`). `platform/environment` in grepped doctest output only prints a `MESSAGE` header and passes in isolation ([stubgen failure aborts ninja before linking `sgl_tests` — use `--target sgl_tests` and verify mtimes](../learnings/1785774319630-slangpy-stubgen-failure-aborts-ninja-before-linkin.md)).

**Single-TU C++ change: compile-verify without a rebuild.** The main checkout already has `build/pip/compile_commands.json`. Find the entry whose `file` ends with your source and whose `output` is under the intended library's `.dir` (`sgl.dir`, not `slangpy_ext.dir`; one source compiles into several targets). Reuse its `command`, swap the input to your worktree copy, drop `-c`/`-o`, add `-fsyntax-only`, and `cd` to the entry's `directory` so relative `-I` resolve. This is real compiler proof (full `-std=gnu++20 -Werror` flags) in seconds; delegate it to a subagent. It cannot catch link errors, but it is conclusive for adding a defaulted arg to an existing overload. GLFW/AppWindow code cannot be unit-tested here (`glfwInit` fails with empty `DISPLAY`), so cursor/window fixes are compile-only plus manual verification ([fast compile-verify a single-TU C++ change via compile_commands.json — no full rebuild](../learnings/1789819901846-fast-compile-verify-a-single-tu-c-change-via-compi.md)).

### Verifying a Pure-Python Change Without a GPU or Native Rebuild

Use the prebuilt venv `/workspace/agent/slangpy-main-build-venv/bin/python` (has `numpy`; an ephemeral `pip install -q pytest` is fine). Its `slangpy` lives in site-packages, so put your checkout first on `PYTHONPATH` and confirm `spy.__file__`. `spy.DeviceType.cpu` works headless and exercises the functional API (`Tensor.from_numpy`, dispatch). `spy.Device(type=vulkan/cuda)` also constructs, which is enough for tests that fail at Slang-session module resolution before any dispatch. A worktree lacks build artifacts, so copy the gitignored native module across (`cp /workspace/agent/slangpy/slangpy/*.so <worktree>/slangpy/`; it is `slangpy_ext.cpython-311-*.so`) and run `PYTHONPATH=<worktree> <venv>/python -m pytest ...`. Tests parametrize over `helpers.DEFAULT_DEVICE_TYPES` (linux → `[vulkan, cuda]`; none use `cpu`). slangpy#1177's `SHADER_PATH` fix (PR #1178) was verified this way with zero native builds ([test pure-Python SlangPy changes locally without a GPU (CPU backend + worktree .so)](../learnings/1790023108329-test-pure-python-slangpy-changes-locally-without-a.md)).

### Local Full-Suite pytest: Environmental Failures and the Stale Main-Checkout `.so`

Three environment facts apply before you call a local `pytest slangpy/tests` result a regression.

1. **Missing dev deps.** The venv lacks `deepdiff` (and pytest-timeout, pytest-xdist, imageio), so collection aborts on `test_declrefs.py` and `test_shapes.py`. Run `pip install --target /tmp/deps deepdiff imageio`, delete the numpy it pulls into `/tmp/deps` (it would shadow the venv's), and add `/tmp/deps` to `PYTHONPATH`.
2. **About 50 failures are git-lfs pointers.** 51 of 53 files in `data/test_images/` are 130-byte pointers, so `test_bitmap.py` (png_read_bit_depth, dds_read, dds_detect_format), `test_bc_codec.py::test_load_and_decode_dds` and every `test_texture_loader.py` variant fail with errors such as "Unknown file format!" or "DDS file has invalid header". The expected tally on an L40S with vulkan+cuda is about 3633 passed / 50 failed / 599 skipped. In a worktree, copy real files from the main checkout's `data/` if you need them.
3. **The main checkout's native module is often older than its Python sources.** In the fixer container, `/workspace/agent/slangpy` sat at e7bb2242 with a `.so` built Sep 22 from older source; HEAD's `slangpy/__init__.py` calls `_set_default_slang_include_paths`, which that `.so` lacks, so conftest dies with a NameError. In the reviewer container, pr-1182 (13f50dc) was checked out over a `.so` built from da8844f, and `spy.create_device` failed with `TypeError: DeviceDesc.__init__ ...`. Compare `build/linux-gcc/git_version/git_version.h` with `git log -1` before trusting a run. To test without touching the checkout, `git archive <built sha> slangpy | tar -x -C /tmp/x`, symlink the `.so` into `/tmp/x/slangpy/`, copy `slangpy/.build_dir`, and run with `PYTHONPATH=/tmp/x` ([local pytest: 50 LFS failures, missing dev deps, stale main-checkout .so](../learnings/1792466857244-slangpy-local-pytest-50-bitmap-dds-texture-failure.md), [reviewer main checkout .so is stale vs Python sources](../learnings/1792484603209-slangpy-reviewer-main-checkout-native-so-is-stale-.md), [worktree LFS-pointer failures](../learnings/1792466654227-slangpy-tests-no-device-type-param-skipped-under-d.md)).

### Running Autodiff `.bwds()` Repros GPU-Free on the CPU Device

Functional-API autodiff repros run on `spy.Device(DeviceType.cpu)` if the build carries the #1136 zero-dispatch-groups fix (4bf28e5b or later). The cpp target cannot emit `InterlockedAddF32`, so every DiffTensor gradient kernel dies with E99999 "unexpected IR opcode" at `atomics.slang:37`. Patch a private copy of the package (tar `slangpy/`, put the copy on `PYTHONPATH`), replacing that line with `__target_switch { case cpp: buf.Store(addr, asuint(asfloat(buf.Load(addr)) + value)); default: buf.InterlockedAddF32(addr, value); }`. It is not atomic: single-thread repros only. To check the kernel against another Slang pin without rebuilding, set `SLANGPY_PRINT_GENERATED_SHADERS=1`, save the kernel and user module as `.slang` files, run `slangc k.slang -I . -I <that version's slangpy/slang> -target hlsl -entry compute_main -stage compute`, and grep for `InterlockedAdd` and `_grad_in` reads. Sources must match the `slangc` version (4bf28e5b sources fail on 2026.18.3 with E30019), and wrap each call in `timeout` because some combinations hang. Used for slangpy#1204, downstream of slang#13301 ([SlangPy autodiff repros run GPU-free on DeviceType.cpu with one atomics.slang patch; static slangc HLSL check for other Slang pins](../learnings/1791189869324-slangpy-autodiff-repros-run-gpu-free-on-devicetype.md)).

## Infra / Operations

### Prod Coworker Group Dirs Symlinked to /ephemeral
On prod, the 6 slang/slangpy coworker group dirs (`groups/slang-{fixer,triager,reviewer}`, `groups/slangpy-{fixer,triager,reviewer}`) are symlinks into `/ephemeral/prod-groups/<name>` (the 251G `/dev/vdb`), not real dirs on the OS disk. `initGroupFilesystem` follows symlinks via `fs.existsSync`, so they are not re-created on wake. Only untracked, gitignored coworker dirs are safe to symlink; `groups/main/` has a git-tracked file and must stay a real dir. ### Bot Cannot Edit Issue Comments on slangpy-samples
`PATCH` of an existing issue comment on `shader-slang/slangpy-samples`, even one the bot wrote, returns HTTP 403 "Must have admin rights to Repository." `POST` works. Refresh a status comment by posting a fresh comment with only the delta. Assume the same for other shader-slang repos with the same token scope until proven otherwise [slangpy-samples: editing bot issue comments 403s ('admin rights') — use fresh comments, not PATCH-in-place](../learnings/1781603959329-slangpy-samples-editing-bot-issue-comments-403s-ad.md).

### Re-Probe the GPU Every Session; Lavapipe Is Not a Fallback
Fleet containers have an NVIDIA L40S with CUDA and NVIDIA Vulkan ([containers have an NVIDIA L40S](../learnings/1792133264162-coworker-containers-have-an-nvidia-l40s-gpu-cuda-vulkan.md)). From 2026-09-28 to 10-16 a host passthrough bug removed it (nanoclaw's `detectGpuMode` in `src/drivers/index.ts` adds `--gpus` only when the host has `ENABLE_GPU=1` or `/usr/bin/nvidia-smi`), leaving the slangpy fixer and triager with no `/dev/nvidia*` or `libcuda` (slangpy#1181; [Agent containers have no GPU since ~2026-09-28 (historical: 09-28→10-16 outage)](../learnings/1792089571497-agent-containers-have-no-gpu-since-2026-09-28-host.md)).

A carried "no GPU" note goes stale and damages public verdicts: the #163 and #126 memos said "only CPU was verified", the next day `nvidia-smi -L` showed the L40S, and the #126 public comment had to be edited. Before writing "CPU only", run `nvidia-smi -L` and a probe that loops `spy.Device(type=spy.DeviceType.vulkan / cpu / cuda)` (`create_device` does not exist on current main). To re-verify an old CPU repro, `sed s/DeviceType.cpu/DeviceType.vulkan/` over the script and rerun it with `PYTHONPATH=<built worktree>`. A GPU that is really missing is an infra problem to report, not a property of the environment ([slangpy triage: re-probe the GPU every session](../learnings/1792136253471-slangpy-triage-re-probe-the-gpu-every-session-a-no.md)).

Debian bookworm's Mesa lavapipe (`mesa-vulkan-drivers` 22.3.6, llvmpipe on LLVM 15) cannot stand in. slang-rhi requests `VK_KHR_SHADER_NON_SEMANTIC_INFO_EXTENSION_NAME` unconditionally (`src/vulkan/vk-device.cpp:596`, pin `82c03494`) and this lavapipe lacks it, so `vkCreateDevice` is rejected and `spy.Device(type=vulkan)` raises "Failed to create device!" even though `enumerate_adapters` lists llvmpipe. A slang-rhi patch would change the tested binary. On any substitute hardware, run a positive control (the known-bad build must still reproduce) before trusting a negative. A Slang build dir configured with the GPU present caches `CUDA_cuda_driver_LIBRARY` (`libcuda.so`); without the driver ninja dies on it, so clear that entry or reconfigure. When verifying that a fix resolved a CI failure, check the job log shows the test PASSED, since a skip is invisible at run level; use `gh run view <run> --job <id> --log`, because `gh api .../jobs/<id>/logs` refuses output with escape sequences ([slangpy Vulkan tests can't use bookworm lavapipe; fleet GPU can vanish](../learnings/1790628362287-slangpy-vulkan-tests-can-t-use-debian-bookworm-lav.md), [lavapipe can't substitute for a GPU in SlangPy Vulkan tests](../learnings/1790628523920-lavapipe-can-t-substitute-for-a-gpu-in-slangpy-vul.md)).

## slangpy-samples Review: Vendored MDL, LFS Resolution, Zero-CI Experiments (PR #53)

MDL material `.slang` files (e.g. `mdl_ceramic_material.slang`, 3492 lines of Itanium-mangled generated MDL target code) are vendored. Do not hand-review them; only the trailing hand-written `IMaterialInstance` wrapper (~190 lines) is glue. Verify LFS objects resolve, because a dangling pointer means a non-runnable sample: take `oid`/`size` from the ~130-byte pointer files and POST to the repo's `info/lfs/objects/batch` endpoint; `actions.download` present means the object exists. `experiments/` has zero CI (only `examples/` entries in `test_examples.py` are tested), so an examples→experiments rename loses coverage only if the demo was a test entry; check `git show main:tests/examples/test_examples.py` ([slangpy-samples utracer experiment (PR #53): MDL files are generated/vendored; verify LFS + rename cleanliness](../learnings/1783721228354-slangpy-samples-utracer-experiment-pr-53-mdl-files.md)).

When such PRs need a GPU, measure it. With the L40S on driver 565.57.01 (CUDA 12.7), regular compute and Vulkan `cooperative_matrix` ran, but cooperative-vector code could not: the driver advertises `VK_NV_cooperative_matrix` but not `VK_NV_cooperative_vector`, so `has_feature(cooperative_vector)` is False on Vulkan and CUDA and all 45 `test_coopvec.py` cases skip. CoopVec kernels still compile (slangc exit 0), so a compile-only check gives false confidence. Say "the installed driver doesn't expose VK_NV_cooperative_vector", not "GPU-less" [This env HAS a GPU (NVIDIA L40S) — but coop-vec is NOT runnable (driver lacks VK_NV_cooperative_vector)](../learnings/1784831657952-this-env-has-a-gpu-nvidia-l40s-but-coop-vec-is-not.md).

## downstream_args Plumbing to Downstream Compilers (#1058, PR #1061)

`SlangCompilerOptions.downstream_args` (and `link_options.downstream_args`) are forwarded via `session_options.add(CompilerOptionName::DownstreamArgs, "<tag>", arg)`, where `<tag>` is the SlangPassThrough name. Only DXC (`"dxc"`, d3d12) and NVRTC (`"nvrtc"`, cuda) accept pass-through args; Vulkan/Metal/WGPU/CPU have no consuming downstream compiler. Before PR #1061 the forwarding was hardcoded to d3d12/`"dxc"` in both `create_session` (`src/sgl/device/shader.cpp:322`) and `ShaderProgram::link` (~:1540), so on CUDA `downstream_args=["--use_fast_math"]` passed the unvalidated Python layer and was dropped. `floating_point_mode` is a first-class Slang option applied per-target (`shader.cpp:397`), which is why `floating_point_mode=fast` always worked on CUDA. The fix adds a CUDA branch with `add(DownstreamArgs, "nvrtc", arg)` (CLI `-Xnvrtc`); the `"nvrtc"` tag was already proven in-tree by the OptiX-include forwarding ([slangpy downstream_args only forwarded for D3D12 (dropped on CUDA/NVRTC)](../learnings/1783910132054-slangpy-downstream-args-only-forwarded-for-d3d12-d.md)).

**Testing it requires a dispatch.** For a CUDA device (SLANG_PTX target), NVRTC does not run at `session.link_program()` or `device.create_compute_kernel()`, which only reads reflection. The pipeline is created lazily in `ComputeKernel::pipeline()` (`kernel.cpp:35-40`) on the first `kernel.dispatch(...)`. A test that checks an arg reaches NVRTC, or that a bogus arg is rejected, must create an output buffer and dispatch. PR #1061's first version asserted a raise at create time and CI failed "DID NOT RAISE". A pipeline-time NVRTC/RHI failure surfaces as `RuntimeError` (via `SLANG_RHI_CALL`→`SGL_THROW`), not `spy.SlangCompileError`; `pytest.raises(RuntimeError)` covers both ([SlangPy CUDA/NVRTC codegen is deferred to first dispatch — tests must dispatch to catch downstream-arg errors](../learnings/1783912568549-slangpy-cuda-nvrtc-codegen-is-deferred-to-first-di.md)).

### `py_doc.h`: Generated Python Docstrings

**Editing a `///` docstring on a field in `src/sgl/device/shader.h` does not reach Python users.** Python docstrings come from `src/slangpy_ext/py_doc.h`, a checked-in file generated by pybind11_mkdoc through the `slangpy_pydoc` CMake target (`src/slangpy_ext/CMakeLists.txt:227`), which needs a full build and the vcpkg include dir. Without it, hand-edit `py_doc.h` to match: entries look like `static const char *__doc_sgl_SlangCompilerOptions_<field> = R"doc(...)doc";`, ~70-col reflow, ASCII, no trailing whitespace. Pre-commit excludes it from clang-format. Review caught the desync on #1058 / PR #1061 ([SlangPy py_doc.h must be updated when editing SlangCompilerOptions docstrings](../learnings/1783909847856-slangpy-py-doc-h-must-be-updated-when-editing-slan.md)).

**A newly bound method or class breaks the build if its symbol is missing from `py_doc.h`.** `D(Device, new_method)` expands to `DOC(sgl, ...)` → `__doc_sgl_Device_new_method`; an absent symbol fails compilation. The mkdoc target needs `pybind11_mkdoc` + clang ≥ 20.1.5 + libc++, usually absent in coworker containers. Either hand-add the entry in the exact generated format (mirror an adjacent entry; fields are alphabetical), or use `D_NA(Device, new_method)`, which expands to `"N/A"`. Prefer hand-adding for user-facing APIs (PR #1158 / issue #1155) ([py_doc.h is committed+generated: hand-add DOC symbols or use D_NA when mkdoc is unavailable](../learnings/1789376759049-slangpy-py-doc-h-is-committed-generated-hand-add-d.md)).

**mkdoc strips the leading underscore from underscore-prefixed names.** Private `Device::_notify_command_recording_submitted` becomes `__doc_sgl_Device_notify_command_recording_submitted`, not `__doc_sgl_Device__notify_...`; grepping the double-underscore form finds nothing and suggests, wrongly, that the method is undocumented. mkdoc emits empty entries (`R"doc()doc"`) for private data members and underscore-prefixed internal methods, but not uniformly for every private method. Omitting those is cosmetic (no binding references them) but churns the next regeneration, so for a callback that mirrors siblings, prefer regenerating. Related: `CommandEncoder::finish()` sets `m_open=false` only on success, so a failed finish leaves the encoder open and retryable, before-finish is not 1:1 with a recording, and `discarded` fires only on destruction ([mkdoc strips the leading underscore from private symbol names in py_doc.h](../learnings/1789378366162-slangpy-py-doc-h-mkdoc-strips-leading-underscore-f.md)).
