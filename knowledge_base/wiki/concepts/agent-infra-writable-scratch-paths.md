# Writable Scratch Paths: /tmp/opencode Is Not Writable in Coworker Containers

## TL;DR

- `/tmp/opencode`, despite being advertised by the bash tool docs as a pre-approved temp dir, is **root-owned and NOT writable** in the coworker containers (confirmed across the slang-triager container and others, 2026-11-16..17). `mkdir`, heredoc redirects, and `>` redirections there fail with "Permission denied".
- The failure mode is dangerous because it is **silent and downstream**: a redirected `gh api ... > file` never executes; a failed heredoc leaves the file missing, so a follow-up `gh api --input` posts an empty body and returns a confusing HTTP 422 "Body cannot be blank" instead of a file-write error. A `mkdir && cd && cat >file` chain drops the first file and later heredocs land in the default workdir — check for strays.
- **Always re-verify state after a redirection error** — a failed redirect can make it look like a GitHub POST went through when it hadn't.
- Use scratch paths under `/workspace/agent/` instead: `/workspace/agent/scratch/`, `/workspace/agent/.gh-comments/`, `/workspace/agent/runs/probe-<n>/` (per-PR workflow scratch), or `/tmp/<name>` (e.g. `/tmp/rt14207`, or `TD=$(mktemp -d)`) for plain temp dirs outside the advertised path. The dir can exist yet still be root-owned (another container recreated it as root, mode 755, while you run as uid 1000) — check `ls -ld /tmp/opencode` before relying on it and fall back at once instead of burning a retry.
- Confirmed beyond the triager in the **slang-ci-babysitter** container (2026-11-20: both bash heredoc writes and the Write tool fail with PermissionDenied there) and the **slang-discord-support** container (2026-11-21: `curl -o /tmp/opencode/...` fails with "Failure writing output to destination" — use `TD=$(mktemp -d)` for temp fetches). It is a fleet-wide property, not a per-group accident.
- A `curl -o /tmp/opencode/...` failure masquerades as a network fetch failure: an `&&`-chained pipeline produces nothing, so check whether the failing step is the write (`ls -ld /tmp/opencode`), not the network, before reporting `fetch_failed`. When the fetch output only feeds jq, pipe inline and skip the file entirely.

## The one rule, measured repeatedly

`/tmp/opencode` is root-owned (drwxr-xr-x root:root) and unwritable by the agent user, so every flavor of temp-file work that the tool docs steer toward it fails: output redirection (a redirected `gh api` silently never runs, making a POST look like it may have gone through when it hadn't — always re-verify state after a redirection error) [[wiki/learnings/1794837758803-tmp-opencode-not-writable-use-workspace-paths-for-]], heredoc draft files for GitHub comment bodies (the missing file then feeds `gh api` a blank body → HTTP 422 "Body cannot be blank") [[wiki/learnings/1794846275046-tmp-opencode-is-root-owned-and-unwritable-in-this-]] [[wiki/learnings/1794892919226-tmp-opencode-not-writable-in-this-container-use-wo]], `mkdir` for scratch dirs (use `/tmp/<name>` instead; a failed `mkdir && cd && cat >file` chain silently drops the first file and leaves later heredocs writing into the default workdir) [[wiki/learnings/1794853595354-tmp-opencode-is-not-writable-in-this-container-use]], `jq --rawfile` / `gh api --input` payloads (confirmed 2026-11-17 on the #14481 and #13596 triages; the retry from a workspace scratch dir posted cleanly) [[wiki/learnings/1794888613914-tmp-opencode-not-writable-use-workspace-scratch-fo]] [[wiki/learnings/1794891626479-use-workspace-agent-scratch-for-temp-files-tmp-ope]], PATCH bodies for GitHub comment edits (heredoc to `/workspace/agent/scratch/tmp/` after `mkdir -p`; `jq --rawfile` reads it fine, hit 2026-11-17 while PATCHing a comment body) [[wiki/learnings/1794897371584-tmp-opencode-is-root-owned-use-workspace-scratch-f]], and repro files / build logs (use `/workspace/agent/scratch/`) [[wiki/learnings/1794890485568-triager-env-tmp-opencode-unwritable-handoff-needs-]]. The working substitute in every case is a path under `/workspace/agent/` — `/workspace/agent/scratch/`, `/workspace/agent/.gh-comments/`, or another workspace dir — or a plain `/tmp/<name>` dir [[wiki/learnings/1794889274555-tmp-opencode-unwritable-in-triager-container-use-w]]. The base `/tmp` itself is also ephemeral (wiped between sessions and restarts), so `/workspace/agent/` scratch is the durable choice for anything a later session must find. The trap recurs container-to-container even when the directory exists: on 2026-11-17 `/tmp/opencode` was present but owned root:root mode 755 while the agent ran as uid 1000 (node), so writes failed with Permission denied — likely another container recreated it as root; don't burn a retry on it, check `ls -ld /tmp/opencode` before relying on it and fall back to a workspace dir (`/workspace/agent/scratch/` for heredoc bodies and `jq --rawfile` inputs, or `/workspace/agent/tmp/`) at once ([tmp/opencode unwritable, use workspace scratch](../learnings/1794899718821-tmp-opencode-unwritable-use-workspace-scratch.md), [/tmp/opencode can be root-owned and unwritable (uid 1000 node)](../learnings/1794910955939-tmp-opencode-can-be-root-owned-and-unwritable-uid-.md)).

Re-confirmed in the slang-reviewer container (2026-11-19, #14636 round): redirects to `/tmp/opencode/*` fail with "Permission denied" there too — the block is fleet-wide, not triager-specific. For per-PR scratch that the review workflows themselves consume (maintainer-direction JSON, PR diff copies), use `/workspace/agent/runs/probe-<n>/` — those are the dirs the workflows want probes in, and unlike `/tmp` they survive worktree GC retention ([/tmp/opencode is read-only in this container — use runs/ dirs for scratch files](../learnings/1795094690652-tmp-opencode-is-read-only-in-this-container-use-ru.md)). The 2026-11-20..21 sweeps extended the same fact to two more containers: in the **slang-ci-babysitter** container `/tmp/opencode` is root-owned `drwxr-xr-x root:root` while the agent runs as uid 1000 (node), and *both* bash heredoc writes and the Write tool fail with PermissionDenied even though the tool docs describe the dir as pre-approved — use `/workspace/agent/scratch/` (rw) for scratch scripts and downloaded job logs instead [tmp-opencode-root-owned-use-workspace-scratch](../learnings/1795162136197-tmp-opencode-root-owned-use-workspace-scratch.md); in the **slang-discord-support** container `curl -o /tmp/opencode/...` fails with "Failure writing output to destination", so temp fetches there want `TD=$(mktemp -d)` [Container quirks: /tmp/opencode unwritable; Discord REST via gateway needs NO auth header](../learnings/1795273578813-container-quirks-tmp-opencode-unwritable-discord-r.md). The same CI-babysitter session reconfirmed a sibling validator quirk: `touch_tracker_verdict` rejects hand-typed future timestamps — `at` must be `$(date -u +%FT%TZ)`, passed as the command substitution, never a literal [tmp-opencode-root-owned-use-workspace-scratch](../learnings/1795162136197-tmp-opencode-root-owned-use-workspace-scratch.md). And re-confirmed in the slang-triager container on 2026-11-21 (the #14691 handoff): `/tmp/opencode` is still NOT writable there despite being described as scratch — use `/workspace/agent/.gh-comments/` or `memory/scratch/` for gh-post output files ([chain handoff gate: [Triage handoff] needs in_reply_to, not just thread_id](../learnings/1795266283017-chain-handoff-gate-triage-handoff-to-a-peer-needs-.md)).

The 11-22..23 discord-support heartbeats re-confirmed the same fact from another angle and pinned the fetch-side trap: `curl -sf <url> -o /tmp/opencode/file` dies on the OUTPUT file (a permission error the instruction layer's "pre-approved temp dir" claim turns into a silent failure) while looking exactly like a network fetch failure — an `&&`-chained pipeline then produces nothing, so before reporting `fetch_failed`, check whether the failing step is the write, not the network (`ls -ld /tmp/opencode`). When a fetch's output is only needed as jq input, skip the file entirely: pipe `curl` straight into `jq` (or a `while read` loop) and the unwritable dir never enters the picture ([curl -o to /tmp/opencode masquerades as a fetch failure](../learnings/1795348043514-tmp-opencode-root-owned-temp-dir-unwritable-by-nod.md), [pipe curl output inline instead](../learnings/1795398391647-tmp-opencode-writes-permission-denied-in-support-b.md)). Re-confirmed twice more on 2026-11-23: a 17.7 MB fetch returned HTTP 200 in 0.13 s to `/dev/null` yet `curl -sf <url> -o /tmp/opencode/file` exited **23 (Failure writing output)** and created nothing — so the "pre-approved" scratch dir's ownership turns a healthy network path into what looks like a retry-worthy fetch failure; pipe curl output or write under a workspace path you own, and check `ls -ld` on any documented temp dir before using it as a `curl -o` target ([/tmp/opencode is root-owned and unwritable — curl -o fails with error 23, pipe instead](../learnings/1795444560221-tmp-opencode-is-root-owned-and-unwritable-curl-o-f.md), [tmp-opencode not writable; use workspace .tmp](../learnings/1795442571638-tmp-opencode-not-writable-use-workspace-tmp.md)). Discord-REST egress quirks measured in that same discord-support container live on [Discord REST via the OneCLI gateway](agent-infra-discord-rest-gateway-egress.md).
Re-confirmed on 2026-11-24..25 in two more containers and one more failure mask: in the slang-fixer-side container the redirect failure masqueraded as a CI-snapshot fetch failing twice when the fetch was fine and only the `>` target was unwritable ([/tmp/opencode is root-owned and read-only in coworker containers](../learnings/1795540614355-tmp-opencode-is-root-owned-and-read-only-in-cowork.md)); the slang-triager container hit it again the same day on a heredoc write, with `/workspace/agent/.scratch/` as the working fallback for comment-body staging ([Issue-Type IDs work across shader-slang org repos; /tmp/opencode may be unwritable](../learnings/1795547148000-issue-type-ids-work-across-shader-slang-org-repos-.md)). The standing recipe is unchanged: verify with a trivial write before relying on any documented temp path, and use `/workspace/agent/` subpaths (or `mktemp -d` under `/tmp` proper) for scratch.

Re-confirmed fleet-wide again on 2026-11-25 in three more containers, with the same masquerade each time: in **slang-discord-support** `curl -sf URL -o /tmp/opencode/...` fails instantly and silently as user `node` and a healthy health_snapshots.jsonl fetch was misread as a Fastly outage for a whole diagnostic cycle — pipe inline (`curl -s URL | tail -1`) or write under `/workspace/agent/` ([/tmp/opencode is root-owned: curl -o there fails silently as user node](../learnings/1795610868367-tmp-opencode-is-root-owned-curl-o-there-fails-sile.md)), and again hours later as exit 23 CURLE_WRITE_ERROR ([/tmp/opencode is root-owned — curl exit 23 on temp writes](../learnings/1795646053380-tmp-opencode-is-root-owned-curl-exit-23-on-temp-wr.md)); in **slang-triager** `mkdir /tmp/opencode/...` still hits Permission denied even when the tool call "pre-approves" it — use a fresh `/tmp/slang-i<N>/` dir for scratch repro files ([/tmp/opencode is root-owned in triager container — use /tmp/slang-* for scratch](../learnings/1795631211604-tmp-opencode-is-root-owned-in-triager-container-us.md)); in **slang-reviewer** both heredoc `>` and `gh pr diff >` failed during the #14725 review — `/workspace/agent/runs/` is the writable, GC-safe substitute there ([/tmp/opencode write permission broken — use /workspace/agent/runs for scratch](../learnings/1795639185174-tmp-opencode-write-permission-broken-use-workspace.md)).
