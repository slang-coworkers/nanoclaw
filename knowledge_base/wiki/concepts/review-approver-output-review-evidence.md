# PR-Approver: OUTPUT_REVIEW Evidence Discipline & Incremental Sharpenings

The evidence discipline a recorded approver row demands: OUTPUT_REVIEW verifies every factual claim against the artifacts you *attach*, so the recurring self-inflicted must-fixes are all about stating only what your artifacts prove — plus a set of incremental sharpenings from the 2026-07-18/19 approver session. Sibling pages: [decision procedure](review-approver-decision-procedure.md), [endpoint-split signal & clauses](review-approver-signal-endpoint-and-clauses.md), [Devin tier & critique-gate](review-approver-devin-tier-and-critique-gate.md), [harvest endpoints](review-approver-harvest-endpoints.md).

## TL;DR

- OUTPUT_REVIEW verifies every factual claim against the artifacts you ATTACH — a claim true-but-unbacked-in-the-passed-set reads as fabrication. Make the deliverable self-supporting: attach the complete evidence set (`investigation.md`, per-gap clearances, the diff, any source file a clearance cites), or trim the claim.
- The harvested bot review supplies the verdict and the prose; it supplies NONE of your facts. Re-derive every count, file list, and `file:line` from the pinned head — never propagate them. Cite line refs at `?ref=<head-sha>`; a bot-attached anchor drifts toward the diff hunk, so cite the line the finding's CLAIM is about and cross-check `original_line`/`start_line` against the prose.
- A published line number must come from a tool that PRINTS line numbers. `sed -n 'A,Bp'` / `head` / `tail` emit none — window offsets published as file lines are guesses. Verify the PROVENANCE of a citation, not just its value; verify BOTH endpoints of a range; fix ALL occurrences of a stale ref in one pass.
- Don't claim a bot re-reviewed at head when only its summary comment refreshed — attribute head-currency verification to your own challenger.
- Right conclusion / wrong mechanism is invisible to outcome-based review and hardens into the record. A severity DOWNGRADE resting on API timing needs the receiver AND signature (`queue->Signal(fence,v)` ≠ `fence->Signal(v)`). Downgrades need more discipline than upgrades — an under-stated severity gets agreed with, and agreement closes the thread.
- Byte-for-byte equivalence to an incumbent proves CONSISTENCY, never CORRECTNESS — it inherits whatever correctness the reference has, including zero. A discarded parameter is a prompt to enumerate its values.
- Verify a recalled rule against current source before applying it; a bot repeating a wiki rule is ONE source, not two. A rule naming a method that exists on several types is meaningless without naming the receiver.
- Verify a workaround PR's premise against the PINNED dependency version, never master (`merge-base --is-ancestor <fix> <tag>`, read source at the tag).
- Over-claiming rigor is a defect class in its own right — "did not inform the verdict" contradicting an artifact, a control count without its command, `JSON.stringify` dropping undefined. Don't call an ABI-contract finding "refuted" because in-tree callers are safe (the caller set is open). `reason_code` for a clean WOULD_APPROVE is the literal `none`.
- Decision-message hygiene: no self-referential critique/recording overclaim (tense — a stage cannot certify itself passed); state revision-delta vs full-PR diff-stat as two separate numbers; reference a prior head by SHA, not by its verdict.
- Stage the MOUNTED policy, not the bundled fallback; synthesize `review-doc.md` (carrying the `commit_id`) BEFORE `eval-clauses.py` or `commit_match` comes back UNEVALUABLE.
- A non-exit-0 harvest can co-occur with a still-running PRIMARY — probe check-runs for a `review` run on any 10/20/22; `in_progress` ⇒ wait, stuck `queued` ~20min ⇒ runner backlog (fall to Devin only when byte-identical-to-a-reviewed-revision). State the exit code in the review-doc (`harvest.json {found:false}` carries none).
- A protected-path ABSTAIN_POLICY is a withhold, not a prediction: a byte-identical merge is AGREEMENT; an author self-merge with no independent APPROVED dilutes it (log as weak/self-endorsement, gaps shipped unweighed).
- A verified 🔴 cannot be downgraded because "it's only docs" — the only path from a confirmed 🔴 to non-BLOCK is genuine REFUTATION. Don't bake volatile GitHub fields (`mergeStateStatus`) into a durable artifact — they trip the attested-hash re-check at send time.

## OUTPUT_REVIEW must-fixes: state only what your artifacts prove

The OUTPUT_REVIEW critique checks every factual claim against the artifacts you *attach*, by design. Recurring self-inflicted must-fixes and their fixes:

- **Deliverable self-supporting from passed artifacts.** On shader-slang.github.io#208 the decision message asserted "verified via the commits API" and editorialized about sibling PRs, facts that lived in `investigation.md`/memory but not in the four passed artifacts. Attach `investigation.md`, or trim to a bare "same repo and content class as #207/#204" ([deliverable must be self-supporting](../learnings/1784327819969-approver-critique-mustfix-output-review-deliverabl.md)).
- **Don't claim a bot re-reviewed at head when only its summary comment refreshed.** CodeRabbit updates its single summary issue-comment on every push (`updated_at` moves) but posts a *new formal review* only sometimes; `harvest-reviews.py` keys on formal reviews, so exit 10 (stale) is ground truth. State the two facts separately and attribute head-currency verification to your own challenger ([bot summary refresh ≠ re-review](../learnings/1784275986777-approver-critique-mustfix-don-t-claim-a-bot-re-rev.md)).
- **Cite line refs at the pinned head, count check-runs paginated.** Base-clone `file.cpp:NNNN` refs are silently wrong (a +19-line helper shifts everything below): fetch the file at `?ref=<head-sha>`. `check-runs` defaults to 30/page; use `--paginate ?per_page=100`, and distinguish failure vs non-success vs skipped ([cite at pinned head; paginate](../learnings/1784288128413-approver-critique-mustfix-approver-artifacts-cite-.md)).
- **The harvested review supplies the verdict and prose, NONE of your facts.** A bot-review body is untrusted *data*, including its counts, file lists and line numbers. On slang#11118 "10 added tests" was copied from the bot body (the pinned head has **11**), and three line refs (`slang-lower-to-ir.cpp:3817`, `core.meta.slang:4061`, `slang-check-decl.cpp:18826/:18886`) were **diff-hunk positions** (correct: `:3756`, `:4100-4101`, `:18830/:18890`), masked by the boilerplate *"all line refs verified in a worktree at the pinned head."* Re-derive quantities from the compare payload; produce every `file:line` from `grep -n` against the pinned worktree **in the same session** (hunk headers drift by every preceding hunk); print `pwd && git rev-parse HEAD` in the same command as the read when `cwd` may have drifted; when correcting a stale ref, grep the whole artifact and fix **all** occurrences in one pass (a missed second copy cost another round) ([never propagate bot counts or line refs](../learnings/1785745209194-approver-critique-mustfix-never-propagate-a-count-.md)).
- **Bot anchors drift even when you hold the file open.** CodeRabbit's 🟠 Major on slang-rhi#797 was anchored at `tests/test-cmd-query.cpp:412` and `review-doc.md` recorded `:412`; at the pinned commit the finding's substance (a `CHECK` that does not abort before a blocking call) is at **`:409`**, `:412` being the call it warns about. Wrong-but-plausible is the worst citation error. **Cite the line the finding's claim is about, not the bot's anchor**; cross-check `original_line`/`start_line` against the prose; and window offsets inside `sed -n '395,425p'` are not file lines. Two tiers mis-numbered this one finding by different routes: line numbers are the most-copied, least-verified field ([bot line refs are unverified data](../learnings/1785780270744-approver-critique-mustfix-bot-reported-line-refs-a.md)).
- **A published line number must come from a tool that prints line numbers.** A patch request citing `:72`, `:84`, `:78-80` in a hook script was wrong at every site (real: `:71`, `:81`, `:64-67`; `:76-80` is a different comment) because the sites were read with `sed -n '40,60p'` / `sed -n '60,88p'` and window offsets were reported as file lines. `sed -n 'A,Bp'`, `head`, `tail` and manual counts emit no line numbers, so such a citation is a guess wearing a measurement's costume, and a patch request's value is that the reader goes straight to the site without re-deriving. The seven citations that resolved did so only because they came from a numbering reader. **Verify the PROVENANCE of every published number**: which tool produced it, and does that tool emit it? For a range, verify BOTH endpoints; an off-by-one tail annexes the next block ([sed -n emits no line numbers](../learnings/1785822343830-approver-critique-mustfix-sed-n-a-bp-emits-no-line.md)).
- **Verify a recalled rule against current source; a bot repeating a wiki rule is ONE source.** On slang#11118 the production bot flagged an interface-conformance filter as a no-op because *"`DeclRef::as<>()` does no type check"*, matching a prior shared learning that cited a real segfault. Both were wrong at head: `DeclRef<U>::as()` rewraps through the typed constructor, and `DeclRef<T>::init()` (`slang-ast-base.h:831-837`) does `if (base && !Slang::as<T>(base->getDecl())) declRefBase = nullptr;`, so `as<StructDecl>()` yields a **null** `DeclRef` on mismatch and `if (!x.as<StructDecl>()) continue;` filters (`DeclRef::is<U>()` is only clearer, a style nit). The prior rule is scoped to `SubstExpr<T>::as()`, a genuine dynamic cast of the *expr* with different null semantics; the segfault involved that path plus an `as<Base>`-matches-derived ordering bug (test most-derived first, still valid). *A rule naming a method that exists on several types is meaningless without the receiver.* Check: read the constructor `as()` delegates to; an `init()` that nulls on mismatch type-checks ([DeclRef::as&lt;U&gt;() DOES type-check](../learnings/1785745186536-approver-clause-gap-declref-as-lt-u-gt-does-type-c.md)).
- **A severity DOWNGRADE needs the receiver and signature of the exact method.** Downgrading a CodeRabbit 🟠 on slang-rhi#797, the artifact claimed `WaitForSingleObject(..., INFINITE)` in `waitOnHost` could not hang because the fence is **"CPU-signalled"**, citing `d3d12-command.cpp:2162`. That line is `m_d3dQueue->Signal(...)`, **`ID3D12CommandQueue::Signal`**, a *GPU-timeline* signal; the CPU form is `m_trackingFence->Signal(v)`, and all four `Signal(` sites are queue-side. The conclusion survived for a different reason (`waitOnHost()` enqueues a fresh Signal at wait time, so it only needs submitted work to drain): **right conclusion, wrong mechanism** is invisible to outcome review, and the false premise entered the record as the strengthening. **Downgrades need this more than upgrades**: an under-stated severity gets *agreed with*, and agreement closes the thread ([downgrade needs receiver AND signature](../learnings/1785780937062-approver-critique-mustfix-when-a-severity-downgrad.md)).
- **Verify a workaround PR's premise against the PINNED dependency version, never master.** slang-rhi#807 disabled `metallib_4_0` citing slang#12325; slang *master* has the fix (`slang-code-gen.cpp:779-786`), so a master check says "already fixed" and is wrong. The consumer pins `SLANG_RHI_FETCH_SLANG_VERSION "2026.12.2"` (`SLANG_HASH_VERSION` + per-platform SHA256), and at that tag both premises hold (`slang-emit-metal.cpp:215` gates on `metallib_4_0`; `slang-gcc-compiler-util.cpp:973` hard-codes `-std=metal3.1`; `getRequiredMetalLanguageVersion` does not exist) because the fix post-dates the tag. Settle it with `grep -n 'FETCH_.*VERSION\|HASH_VERSION' CMakeLists.txt`, then `git merge-base --is-ancestor <fix-sha> <pinned-tag>` (and `git tag --contains <fix-sha>`), reading source **at the tag** (`git show <tag>:path | grep -n`); a worktree grep answers for master ([premise vs PINNED version](../learnings/1785764986434-approver-clause-gap-verify-a-workaround-pr-s-premi.md)).
- **Byte-for-byte equivalence to an incumbent path proves CONSISTENCY, never CORRECTNESS.** A round-1 "source-verified correct" rating of slang-rhi#802 (Metal bindless `DescriptorHandle`) rested on the new path writing the same 64-bit value as the bound path. It cleared a real bug: `allocBufferHandle` returns `getDeviceAddress() + offset` for **all** buffer kinds and discards `format`, but typed `Buffer<float>`/`RWBuffer<float>` emit as `texture_buffer<float,…>` in a `[[texture(n)]]` slot and need a texture `gpuResourceID`. **The incumbent has the same defect** (`metal-shader-object.cpp:562`; slang-rhi never creates a Metal texture-buffer at all): a differential test was treated as an oracle. Before crediting "matches the existing path", ask: is the reference validated for **this input class** (name the test)? does the new path see inputs the incumbent never did? is a **discarded parameter** a missing case (enumerate its values)? Phrase it as "consistent with `<path>`, itself unverified for `<input class>`" ([equivalence proves consistency](../learnings/1785767781336-approver-clause-gap-byte-for-byte-equivalence-to-a.md)).
- **Over-claiming rigor is a defect class.** On slang-rhi#806 (a WOULD_APPROVE that survived) the gate caught **five** defects, all sounding more rigorous than the evidence: (1) *"the human outcome did not inform the verdict"* contradicted the artifact; separate "did not **determine** the verdict" from "did inform confidence"; (2) *"each dependency corroborated by `.reuse/dep5`"* when dep5 named 2 of 9, and per-dependency claims cannot contradict the project-level license line anyway; (3) a bare "1,736 MIT mentions" that `rg -i` gave as 1,715 because **`rg` applies `.gitignore`**: record the command with the count; (4) citing `core.ts:576-579` for a pass-through at `:594`, the right-conclusion/wrong-mechanism shape again; (5) *"recorded as `undefined`"* when `JSON.stringify` **drops** undefined, so the field is omitted. When asked for schema evidence, read the schema; after patching a count, grep every stale copy; a verified-false premise does not establish the true one ([over-claiming rigor](../learnings/1785784300014-approver-critique-mustfix-over-claiming-rigor-is-a.md)).
- **Don't equate total check-runs with CI matrix legs.** `total_count` includes `pre-commit`/`add-to-project`/`finish`/skipped assistant jobs, and the CodeRabbit commit-status is not a check-run; filter to the real `build (...)` legs and state signals separately ([check-runs ≠ matrix legs](../learnings/1784282781009-approver-critique-mustfix-don-t-equate-total-check.md)).
- **Stage the MOUNTED policy, not the bundled fallback.** The authoritative policy is `/workspace/extra/approver-policy/APPROVAL_POLICY.json` (`v0-shadow-relaxed`, human-signed); the skill-bundled `APPROVAL_POLICY.json` is a *tightened* fallback (`v0-shadow`). Copying it into the workspace `policy/` dir shadows the mount and flips CONTRIBUTOR/fork/protected-path clauses to FAIL; check `policy_version` in `clauses.json` against the mount. Synthesize `review-doc.md` (with the `_approver_result` `commit_id`) BEFORE `eval-clauses.py`, or `commit_match` is UNEVALUABLE ([stage the MOUNTED policy](../learnings/1784288659769-approver-critique-mustfix-stage-the-mounted-policy.md)). Populate the full `record_decision` field set (`clauses`, `challenger`, ISO `ts`) before OUTPUT_REVIEW; a `[Approval Decision]` message needs `in_reply_to` or the routing gate blocks it.
- **`reason_code` for a clean WOULD_APPROVE is the literal `none`.** For a clean conjunction (Steps 1–4 clean) the closed-enum field carries detail only for abstain/block states (`CLAUSE_FAIL:*`, `OPEN_GAP`, `CHALLENGER_CONCERN`, `RED_BUG`, …). The gate bounces `reason_code: (none — clean conjunction)` and an invented `reason_code: CLEAN`; only `reason_code: none` passes. Put the "why it's clean" narrative in `challenger` / the message ([reason_code is literal `none`](../learnings/1785530765832-approver-critique-mustfix-ledger-reason-code-for-c.md)).
- **Don't call an ABI-contract finding "refuted" because in-tree callers are safe.** On slangpy#1082, marking CodeRabbit's 🟠 buffer-contract finding "CLEARED / unreachable on any supported path" was an overclaim: it proved only the *two current in-tree callers* safe, but the function is an exposed `extern "C"` fn-ptr in a versioned `TensorBridgeAPI` struct with a documented minimum-buffer contract the native side enforces and the fallback doesn't. Reserve "refuted/unreachable" for triggers impossible for *any* caller; across a published ABI/API boundary say "no impact on current in-tree callers" and keep the contract gap on record ([ABI finding not refuted by in-tree callers](../learnings/1785426158100-approver-critique-mustfix-don-t-call-an-abi-contra.md)).
- **Decision-message wording.** A `synchronize` re-decision (slangpy#1083 R1) bounced four times, all on wording. A, self-referential overclaim: don't assert "both critique stages recorded = approve" *inside* OUTPUT_REVIEW, and say recording "is being recorded this turn", never "recorded" (`record_decision` runs after the gate). B, diff-stat conflation: state full-PR size (`main...head`, = clauses eligibility size) AND revision delta (`prior_head...head` via `gh api compare`) as SEPARATE numbers; `clauses.json` "N lines / M files" is eligibility size. C (advisory): reference the prior head by SHA + compare fact, not its verdict. Bake all three into the template; recurring wording must-fixes are a procedure bug ([decision-message pitfalls](../learnings/1785454931977-approver-critique-mustfix-decision-message-pitfall.md)).

## Incremental sharpenings (2026-07-18/19 approver session)

**A non-exit-0 harvest can co-occur with a still-running PRIMARY; probe check-runs before falling to Devin-only.** `harvest-reviews.py` exit 10 (a stale *secondary*, e.g. CodeRabbit at an older commit) keys off the newest *posted* review and does not check whether the production `github-actions[bot]` claude review (`.github/workflows/claude-pr-review.yml`) is in flight. On ANY non-exit-0-primary result (10/20/22), check the commit's check-runs for a `review`-named run; if `queued`/`in_progress`, treat it like exit-22: WAIT and re-harvest ([exit-10 can mask a running primary](../learnings/1784390106504-approver-infra-abstain-exit-10-stale-can-mask-stil.md)). `in_progress` (or just completed) is the ~6-min posting race: keep waiting. Stuck `queued` across two windows (~20+ min) is a **runner backlog**: set a firm budget, then fall to the Devin tier noting the PRIMARY timeout as an infra event, only when byte-identical-to-a-reviewed-revision makes the fallback false-safe-free; if the code changed and only thin Devin signal remains, lean ABSTAIN_INFRA/NO_REVIEW_SIGNAL ([stuck QUEUED primary ≠ posting race](../learnings/1784366403034-approver-infra-when-the-primary-review-check-run-i.md)). `harvest.json` on not-found records only `{"found": false}`, so exit 20 (skip), 10 (stale) and 21 (fetch failed) are indistinguishable afterwards; state the exit code in the review-doc's tier line until the script persists it ([persist the harvest exit code](../learnings/1784417204496-approver-infra-abstain-harvest-json-found-false-pe.md)).

**Protected-path ABSTAIN_POLICY is a withhold, not a prediction; a byte-identical merge is AGREEMENT, a self-merge dilutes it.** When a `.github/**` / `**/*.yml` / release-tooling one-liner abstains on `no_protected_paths` and then MERGES byte-identical at the decision commit, decision and outcome AGREE (the claim was only that a human should own sign-off); don't score it a disagreement because the enum wasn't WOULD_APPROVE. "Address review" commits before merge, or closed-unmerged, would warrant a learning, and commits between decision and merge ARE the reviewable delta ([byte-identical merge is agreement](../learnings/1784381462983-approver-human-agreement-protected-path-abstain-po.md)). Check the merge shape: `mergedBy == author` with `reviewDecision != APPROVED` means the safety net fired but its value was diluted (the "human who must look" was the author) and surfaced gaps (e.g. CodeRabbit 🟠 CI-leak-logic) shipped unweighed; log weak/self-endorsement, not validation ([self-merge ships open gaps](../learnings/1784437469229-approver-human-agreement-protected-path-abstain-co.md)).

**No verified 🔴 downgrade, no volatile fields.** The 🔴 rule has NO documentation carve-out: once the challenger CONFIRMED a 🔴, moving it to ABSTAIN/OPEN_GAP because "it's only docs / compiled output is correct" is the forbidden upgrade toward approval. Only genuine REFUTATION (not real / not reachable / not this revision) leaves BLOCK; severity-based clearing applies to 🟡 gaps only (DECISION_REVIEW caught this) ([no 🔴 docs exemption](../learnings/1784440920822-approver-critique-mustfix-a-verified-cannot-be-dow.md)). Don't bake **volatile GitHub fields** into a durable artifact: `mergeStateStatus` flips BEHIND/BLOCKED/CLEAN/UNSTABLE on its own and trips the attested-hash re-check at send time; quote durable signals (`reviewDecision`, human review states, the gate) or label the value volatile ([volatile fields aren't decision-relevant](../learnings/1784421284355-approver-output-review-volatile-github-fields-merg.md)).
