# SlangPy CI, Triage, Build, and Runtime (part 2)

> **This page is part 2 of 3** of the SlangPy CI, Triage, Build, and Runtime synthesis (split 2026-08-11 to stay under the 40 KB read cap). Siblings: [part 1](slangpy-ci-triage.md), [part 3](slangpy-ci-triage-3.md). The TL;DR below is shared across all parts.

## TL;DR
- **SUPERSEDED (2026-08-03): cross-repo `gh run rerun <id> --repo shader-slang/slangpy --failed` now WORKS** — the old "Must have admin rights to Repository" block no longer reproduces, so rerun slangpy reds yourself under the normal 3/PR/day cap.
- **Exit 0 is NOT proof a rerun fired — the `run_attempt` increment is.** Re-read `gh api repos/shader-slang/slangpy/actions/runs/<id> --jq '{status,conclusion,attempt:.run_attempt}'`; piped forms (`gh … | jq`) report jq's status and launder gh failures into exit 0.
- **Classify a slangpy red by its signature's determinism, not by permissions** — intermittent (dep-fetch 5xx, DXC prebuilt fetch 500 at CMake configure from `FetchDXC.cmake`) → rerun; deterministic/author-owned (setup-python toolcache, `E36121`, code break) → no rerun, because a rerun cannot fix a deterministic failure.
- **All-false `.permissions` on `shader-slang/slangpy` does NOT mean you cannot act or read** — log reads always worked. **Probe the actual operation instead of introspecting permissions.**
- **RETRACTED framing: the old rerun 403 was the OneCLI gateway PAT-routing collision, not a missing scope** — a read-only user PAT shadowed the App token, which already has `actions:write`. Never ask an operator to "grant slangpy actions:write"; ask only to extend the scoped secret.
- **RETRACTED GPU-leak claims: #115/#608/#827 do not reproduce at HEAD.** The CUDA-OOM cascade is peak concurrent VRAM (`pytest -n auto --maxprocesses=4` × ~5 GB per worker), not a leak — distinguish a monotonic climb (leak) from a step function that plateaus (working set).
- **When A/B-ing against a local Slang build, `SGL_LOCAL_SLANG_BUILD_DIR` must point at `build/Release`, never the downloaded `build/slang-<ver>-linux-x86_64/` release artifact** — that artifact lacks the PR and makes BOTH arms come back clean, a false negative that looks like a real result. Prove it with `strings <dir>/libslang*.so | grep -c 'is incompatible with compilation target'` (2 = real, 0 = invalid) plus `ldd build/linux-gcc/Debug/sgl_tests | grep slang`.
- **Slang's `default` CMake preset is Ninja Multi-Config, so `-DCMAKE_BUILD_TYPE=Release` is inert** — `--config Release` is what selects the config.
- **Establish the pinned-Slang baseline control BEFORE any A/B or you will misattribute pre-existing failures** — the 5 residual `sgl_tests` failures are LFS-fixture cases (3 `test_dds_file.cpp` + 2 `test_texture_loader.cpp`); the arithmetic `33 = 28 + 5` is what falsified a monitor reporting 0 diagnostics.
- **`git checkout <commit> -- <path>` STAGES as well as writing the worktree, so a plain `git diff` is empty and the revert looks like a no-op** — use `git diff HEAD` / `git status --porcelain`, and prove a PR is unmerged with `git merge-base --is-ancestor <pr-head> origin/master`.
- **Doctest name filters can silently select nothing** (`-tc=formats` / `-sc=vulkan` matched 0, 203 skipped) — run the whole binary and grep the log.
- **A stubgen (`numpy`/`libcst`) failure aborts ninja BEFORE the `sgl_tests` link — a FALSE GREEN where a stale binary "passes" against pre-change code** (observed 10 days older than HEAD). Build `--target sgl_tests` explicitly and require both `sgl_tests` and `libsgl.so` mtimes newer than a pre-build `date` stamp; a fresh `.o` is not sufficient.
- **Building slangpy needs `python3-dev`/`python3.11-dev` and `--break-system-packages` on every pip call (PEP-668)** — `tools/ci.py install-slangpy-torch` fails because its internal `pip install wheel` omits the flag; nvcc is NOT required; pip site-packages reset on container rebuild; an ENOSPC-interrupted submodule needs `git submodule update --init --force --recursive`.
- **The full C++ `sgl` build requires the `data` submodule whose two fonts are git-LFS** — without git-lfs you get ~131-byte pointer stubs and ninja dies on `Inconsolata-Regular.ttf` before any source compiles. Verify byte sizes (Montserrat 197624 B, Inconsolata 101752 B), not mere existence.
- **`device.create_buffer(element_count=n, struct_size=K)` allocates `n*K` bytes and NEVER reconciles `K` against Slang's per-target device-side stride — silent out-of-bounds the debug layer will not catch.** Pass `resource_type_layout=program.reflection.<bufferParam>` so the reflected stride is used.
- **Python `id(m)` differing across `session.load_module(...)` calls is NOT evidence of an `IModule*` identity bug** — slangpy mints a fresh wrapper proxy per call; compare `IModule*` pointers in a standalone C++ program.
- **`device.load_program("mod.slang", ["one_ep"])` capability-checks EVERY `[shader]` entry point in the module at load time, not lazily per function** — one illegal EP sinks its clean siblings; guard the offending declaration with the SGL-injected `#ifndef __TARGET_CUDA__`.
- **`E36121` fires only on API-level requested capabilities** (`targetOptionSet.getArray(CompilerOptionName::Capability)`), never by walking declarations — so `[__requiresNVAPI]` is not a second fix site. Read a diagnostic's emission loop, not its wording.
- **`0 assertions failed` alongside N failed test cases is the signature of a module-load/compile break, not a logic regression** — go read the compiler diagnostic instead of hunting behavior.
- **`ci-latest-slang.yml`'s `build-pr` job runs `actions/checkout@v6` with no `ref:`, so slangpy always builds its DEFAULT branch** — a required `SlangPy Tests` check on a slang PR cannot go green until the slangpy-side fix is **merged to slangpy main**; a draft PR changes nothing.
- **"Deferred until the upstream Slang fix ships" gates on the `SGL_SLANG_VERSION` pin (`external/CMakeLists.txt:85`), not on a wheel release** — check three stages: merge, a tag CONTAINING the commit (`compare/<tag>...<sha> --jq '.status'` must be `behind`/`identical`, never `ahead`), then the pin bump. The pin lagged five releases.
- **The cheapest proof a slang fix works with slangpy is an existing cross-repo `ci-latest-slang` run** (nightly 01:00 UTC, `workflow_dispatch` with `slang_branch`, `repository_dispatch` per slang PR) — but `build-pr` is a reduced Linux+Windows Release matrix: real evidence, not full-matrix evidence.
- **`updatedAt - createdAt` from `gh run list` is NOT job duration** — a re-run keeps the original `created_at` while jobs start at `run_started_at`, so a `success` run can show 1255 min. Confirm with per-job durations.
- **Never call this environment "GPU-less" — an NVIDIA L40S is present and compute/Vulkan `cooperative_matrix` run.** Cooperative-VECTOR does not (driver 565.x lacks `VK_NV_cooperative_vector`), and **coop-vec kernels still COMPILE (slangc exit 0), so compile-only checks give false confidence** — dispatch is where it dies.
- **NVRTC/CUDA downstream compilation is deferred to the first `kernel.dispatch(...)`, so a test stopping at `create_compute_kernel` never runs NVRTC** — dispatch with a real output buffer and expect `RuntimeError`; `downstream_args` reach only DXC and NVRTC, silently dropped elsewhere.
- **A test that deliberately crashes (SIGSEGV/SIGABRT) HANGS the "Unit Tests (Python)" step for hours** because Crashpad intercepts it, while passing locally where crashpad is off — hard-guard on the CI env.
- **On slangpy-samples, `pre-commit run --all-files` means one pre-existing violation anywhere reds the `pre-commit` job on EVERY PR**, and **`PATCH` of an existing bot issue comment 403s while `POST` works** — design status updates as append-only fresh comments.
- **A single test can remove the shared D3D12 device and cascade into hundreds of "Failed to create device!" failures** indistinguishable from infra flake — grep for `Device removal has been triggered` and find the first-emitting test per xdist worker; "my tests passed" is meaningless if they ran before the poisoner.
- **Before mapping a solution space, grep HEAD for the feature's named symbols and check merged PRs** (stale line-refs are the staleness tell); for any GPU-codegen gap search `shader-slang/slang` PRs first — the fix often already lives in core.

## Building SlangPy from Source (Fixer Container)

Building the slangpy native extension on an L40S linux-gcc Ninja Multi-Config box:

- **Needs `python3-dev`/`python3.11-dev`** (admin `install_packages` apt). Without it, CMake `find_package(Python ... Development.Module)` fails. nvcc is NOT required (CUDA backend uses the driver API at runtime).
- **PEP-668:** every `pip install` needs `--break-system-packages`. `python3 tools/ci.py install-slangpy-torch` fails because its internal `pip install wheel` omits the flag — install the torch bridge manually: `pip install --break-system-packages wheel && pip install --break-system-packages --no-build-isolation ./src/slangpy_torch`.
- **After a container rebuild**, the image's pip site-packages reset — reinstall `requirements-dev.txt` with `--break-system-packages`. The `/workspace` worktree persists across rebuild; pip packages do not.
- **Interrupted (ENOSPC) submodule checkout** leaves a gitlink with an empty working tree that `git submodule update --init` skips. Fix: `git submodule update --init --force --recursive`.
- **Build only `slangpy_ext`** (`cmake --build build/linux-gcc --config Release --target slangpy_ext`, ~304 steps) to skip heavy C++ test/example binaries. `build/buildtrees` (vcpkg intermediates) is regenerable — safe to `rm -rf` after configure to reclaim ~765MB. [Building slangpy from source in the fixer container: python3-dev, PEP-668, torch bridge, submodule/ENOSPC gotchas](wiki/learnings/1782324519820-building-slangpy-from-source-in-the-fixer-containe.md)

Building the full C++ `sgl` layer (linux-gcc-debug, e.g. for the doctest `sgl_tests` / profiler suite) adds two non-obvious deps: the `data` git submodule (`slangpy-data.git`) is a REQUIRED unconditional PUBLIC link dep via `cmrc_add_resource_library(sgl_data ...)`, and its two fonts are git-LFS files — with git-lfs absent the checkout holds only ~131-byte pointer stubs, so ninja fails on `Inconsolata-Regular.ttf` BEFORE any source compiles (an INFRA gap, not your code); init without the smudge filter (`git -c filter.lfs.smudge= submodule update --init data`) then fetch the real binaries via GitHub's LFS batch API and verify with `file *.ttf` / byte sizes (Montserrat 197624 B, Inconsolata 101752 B), not mere existence [SlangPy C++ build needs data submodule + LFS fonts (git-lfs absent)](wiki/learnings/1784867803689-slangpy-c-build-needs-data-submodule-lfs-fonts-git.md). The final `.pyi` stubgen targets (nanobind stubgen + `tools/postprocess_stub.py`) then import the built module and need `numpy`+`libcst` (`pip install --user --break-system-packages numpy libcst`) — but they run AFTER all C++ link succeeds, so a `ModuleNotFoundError` there means the binaries (libsgl.so + sgl_tests) are already built [SlangPy C++ build needs the `data` LFS submodule + numpy/libcst for stubgen](wiki/learnings/1784868284126-slangpy-c-build-needs-the-data-lfs-submodule-numpy.md).

**CORRECTION to that reassurance — the stubgen failure is a FALSE-GREEN trap for `sgl_tests`.** "It runs after all C++ link succeeds" holds for `libsgl.so`, but **not** for the test binary: without `numpy`/`libcst`, `cmake --build --preset linux-gcc-debug` fails at the `.pyi` stub step and **aborts ninja BEFORE the `sgl_tests` link**. So your changes compile (`profiler.cpp.o` is fresh), `sgl_tests` is never relinked, the *old* binary stays on disk, and running it "passes" — against pre-change code. That is worse than a plain build failure, because the build looks like it hit only the known-ignorable error while the tests silently exercise stale code (observed concretely: an `sgl_tests` binary **10 days older than HEAD** still passing the very tests a fix was supposed to change). Fix: build the test target explicitly so the link happens before the stub step can abort the graph — `cmake --build --preset linux-gcc-debug --target sgl_tests` — and since `sgl_tests` links `libsgl.so` dynamically, make sure the `sgl` target relinked too. **Mandatory check before trusting ANY test number:** stamp `date '+%F %T'` before the build, then `ls -l --time-style=full-iso build/linux-gcc/Debug/sgl_tests build/linux-gcc/Debug/libsgl.so` and require **both** mtimes newer than the baseline; if not, you have no valid binary and must not report results. Checking the `.o` is not sufficient — the object can be fresh while the executable is stale. (Companion facts: the pre-existing full-suite failures in this environment are the 5 Git-LFS fixture cases — 3 in `test_dds_file.cpp`, 2 in `test_texture_loader.cpp` — from unmaterialized LFS pointer stubs, not regressions; and grepping doctest output for failing test names can surface `platform/environment`, which merely prints a `MESSAGE` header and passes in isolation.) ([stubgen failure aborts ninja before linking `sgl_tests` — use `--target sgl_tests` and verify mtimes](wiki/learnings/1785774319630-slangpy-stubgen-failure-aborts-ninja-before-linkin.md))

## Crashing Regression Tests, Native-SIGSEGV Testing & CI Flake (2026-07-13 fold)

**A deliberately-crashing test hangs CI even when it passes locally.** If a SlangPy Python test intentionally triggers a native crash (SIGSEGV/SIGABRT) — e.g. a regression tripwire for a known-crashing GPU path — it will HANG the "Unit Tests (Python)" CI step for hours (2h+ linux/windows, 6h macOS), not crash cleanly. SlangPy's CI unit-test lanes build with the `crashpad` flag and `slangpy/testing/plugin.py` starts the Crashpad handler at `pytest_sessionstart` (gated on `spy.crashpad.is_supported()`); Crashpad intercepts the crash to capture a minidump and wedges the run. It does NOT reproduce on a local dev build where crashpad is disabled — so "passes locally, hangs in CI" is the signature. Diagnosis tell: Build + C++ tests pass, only "Unit Tests (Python)" is stuck `in_progress` with a multi-hour duration. Fix: guard the test with `if spy.crashpad.is_supported(): pytest.skip(...)` so it only runs on non-Crashpad builds; keep non-crashing controls always-on. Subprocess isolation stops a SIGSEGV from killing the pytest worker but does NOT stop a process-level crash handler from intercepting it ([a test that deliberately crashes (SIGSEGV) hangs SlangPy CI because Crashpad intercepts it](wiki/learnings/1783909321657-a-test-that-deliberately-crashes-sigsegv-hangs-sla.md)).

**The pattern to regression-test a native SIGSEGV under pytest** (used for slangpy#1051 / slang#12070, `test_diff_loop_runtime_start.py`): run the crashing call in an ISOLATED SUBPROCESS (the test file doubles as the worker via `if __name__ == "__main__": os._exit(_child_main(...))`; `os._exit` avoids teardown perturbing the exit code); the parent asserts on returncode (a signal death is a NEGATIVE returncode, `-signal.SIGSEGV == -11`, not shell 139); use TARGETED `@pytest.mark.xfail(raises=_KnownCrash, strict=True)` so a clean exit (fix landed) becomes an XPASS hard-failure forcing marker removal; bracket the crash with FLUSHED `PHASE:begin`/`PHASE:end` prints so a crash in setup/teardown is surfaced not masked; compute the "fixed but wrong" oracle in numpy with a NON-SQUARE shape; gate to POSIX. A SIGSEGV discards block-buffered stdout — capture generated shaders with `python -u` or `SLANGPY_PRINT_GENERATED_SHADERS=1` ([regression-testing a native SIGSEGV under pytest (subprocess + strict xfail + phase bracket)](wiki/learnings/1783875908806-regression-testing-a-native-sigsegv-under-pytest-s.md)).

**Matrix-vector grad tests flake on GFX pipelines.** `test_pytorch.py::test_tensor_interfaces[DeviceType.d3d12]` fails intermittently in Windows CI (`AssertionError: Tensor deviates by <large N>`) while 5120+ tests pass and the build succeeds — it is flaky, not a real regression. Confirm fast: the same test's `[cuda]`/`[vulkan]` variants PASS in the same run, and the sibling `test_tensor_arguments` (same helper, same grad assertion) is explicitly `pytest.skip("Test currently unreliable on GFX pipelines")` — maintainer-documented unreliability. `nv-slang-bot` CANNOT `gh run rerun --failed` (`Must have admin rights`), so a human must re-run or push a no-op. Triage rule: a single-test Python failure on ONE backend, where other backends of that test pass + it's green on the PR base + your change is backend-agnostic, is flaky CI — report, don't hunt ([slangpy CI: test_tensor_interfaces[d3d12] and matrix-vector grad tests are flaky on GFX pipelines](wiki/learnings/1783887861915-slangpy-ci-test-tensor-interfaces-d3d12-and-matrix.md)).


## downstream_args Plumbing to Downstream Compilers (#1058, PR #1061)

`SlangCompilerOptions.downstream_args` (and `link_options.downstream_args`) are forwarded to Slang via `session_options.add(CompilerOptionName::DownstreamArgs, "<tag>", arg)` where `<tag>` is the SlangPassThrough name of the downstream compiler. Only **DXC** (`"dxc"`, d3d12) and **NVRTC** (`"nvrtc"`, cuda) accept pass-through args; Vulkan/Metal/WGPU/CPU have no consuming downstream compiler. Before PR #1061 the forwarding was hardcoded `if (device_type == DeviceType::d3d12)` with the `"dxc"` tag in BOTH the compile path (`create_session`, `src/sgl/device/shader.cpp:322`) and link path (`ShaderProgram::link`, ~:1540), so on CUDA the args were accepted at the Python dict→struct layer (`src/slangpy_ext/device/shader.cpp:27`, no validation) then **silently dropped** — e.g. `downstream_args=["--use_fast_math"]` had zero effect. Key distinction: `floating_point_mode` is a FIRST-CLASS Slang option applied unconditionally per-target (`shader.cpp:397`), which is why `floating_point_mode=fast` always worked on CUDA — a different mechanism. Fix = add a CUDA branch forwarding via `add(DownstreamArgs, "nvrtc", arg)` (CLI `-Xnvrtc`); the `"nvrtc"` tag was already proven in-tree by the auto OptiX-include forwarding ([SlangPy downstream_args forwarded only to DXC (d3d12) and NVRTC (cuda)](wiki/learnings/1783909862147-slangpy-downstream-args-forwarded-only-to-dxc-d3d1.md), [slangpy downstream_args only forwarded for D3D12 (dropped on CUDA/NVRTC)](wiki/learnings/1783910132054-slangpy-downstream-args-only-forwarded-for-d3d12-d.md)).

**Testing the fix requires an actual dispatch — NVRTC codegen is deferred to first dispatch.** For a CUDA device (SLANG_PTX target), NVRTC downstream compilation does NOT run at `session.link_program()` or `device.create_compute_kernel()` (which only reads reflection). The compute pipeline is created lazily in `ComputeKernel::pipeline()` (`kernel.cpp:35-40`), invoked only on the first `kernel.dispatch(...)`. So a test that verifies a downstream arg reaches NVRTC — or that a bogus arg is rejected — MUST create an output buffer and call `dispatch`; a test that stops at `create_compute_kernel` silently never runs NVRTC (this bit PR #1061: first version asserted a bogus flag raised at create and CI failed "DID NOT RAISE"). A pipeline-time NVRTC/RHI failure surfaces as Python `RuntimeError` (via `SLANG_RHI_CALL`→`SGL_THROW`), NOT `spy.SlangCompileError`; `pytest.raises(RuntimeError)` covers both ([SlangPy CUDA/NVRTC codegen is deferred to first dispatch — tests must dispatch to catch downstream-arg errors](wiki/learnings/1783912568549-slangpy-cuda-nvrtc-codegen-is-deferred-to-first-di.md)).

**Editing a `///` docstring on a struct field in `src/sgl/device/shader.h` does NOT reach Python users automatically.** Python docstrings come from `src/slangpy_ext/py_doc.h`, a checked-in generated file (pybind11_mkdoc), regenerated by the `slangpy_pydoc` CMake target (`src/slangpy_ext/CMakeLists.txt:227`) which needs a full build + vcpkg include dir. If you can't run that target, hand-edit `py_doc.h` to match (entries look like `static const char *__doc_sgl_SlangCompilerOptions_<field> = R"doc(...)doc";`, ~70-col reflow, ASCII, no trailing whitespace — it's in the pre-commit `exclude:` list so clang-format won't touch it). A review WILL catch the desync if you only edit `shader.h` (found on #1058 / PR #1061) ([SlangPy py_doc.h must be updated when editing SlangCompilerOptions docstrings](wiki/learnings/1783909847856-slangpy-py-doc-h-must-be-updated-when-editing-slan.md)).

## sgl_tests Teardown Exit-Code Flake and CI-Hang Corrections (2026-07-14 fold)

The `sgl_tests` teardown exit-code flake (#1062) is a distinct class: doctest prints a green `[doctest] Status: SUCCESS!` then the *process* exits nonzero during post-`main` teardown (`static_shutdown`/`close_all_devices` GPU-resource destruction), which `tools/ci.py`'s `run_command` turns into a `RuntimeError` reddening the cross-repo *SlangPy Tests* check on unrelated slang PRs ([sgl_tests exit-code flake root cause + tracking issue #1062](wiki/learnings/1783930954720-sgl-tests-exit-code-flake-root-cause-tracking-issu.md)). The candidate fix is `std::fflush(nullptr); std::_Exit(result)` to bypass teardown ([#1062: no minidump, post-main teardown, fix with std::_Exit](wiki/learnings/1783932346816-sgl-tests-exit-code-flake-1062-no-minidump-exists-.md)), but two evidence legs need correcting: crashpad is neither producing a minidump NOR armed in the C++ binary, so an empty `.crashpad/reports/` says nothing about fault location ([CORRECTION: crashpad is not armed; empty reports/ uninformative](wiki/learnings/1783932949420-correction-to-1062-learning-crashpad-is-not-armed-.md)), and `_Exit` suppresses the (CI-disabled, non-blocking) LeakSanitizer end-of-run report ([_Exit fix #1064 suppresses LeakSanitizer report](wiki/learnings/1783932699675-sgl-tests-exit-fix-1064-suppresses-leaksanitizer-e.md)). Maintainer @skallweitNV **rejected exit-code masking** — a teardown flake needs a root-cause fix, not `_Exit(result)` ([maintainer rejected exit-code masking](wiki/learnings/1783937217747-sgl-tests-exit-code-flake-maintainer-rejected-exit.md)). Two related CI-hang corrections: a deliberately-crashing GPU test lands in an unkillable D-state process, so hard-guard on the CI env instead of probing crashpad ([CORRECTION: crashing GPU test wedges CI (unkillable)](wiki/learnings/1783931282447-correction-a-deliberately-crashing-gpu-test-wedges.md)); and the separate slangpy#1051/#1053 6-hour hang was ultimately the known **CUDA-OOM cascade** from `pytest -n auto` opening 4 concurrent GPU contexts, NOT the crash-test ([CORRECTION #2: 6h hang was CUDA-OOM cascade](wiki/learnings/1783974986070-correction-2-slangpy-1051-pr-1053-the-6h-ci-hang-w.md)). The same PR #1063 (self-merged, CodeRabbit Major findings unresolved) also carried a `ProfilerImpl::drain()` snapshot-ordering race (#1072): the async collector snapshotted the per-thread CPU event queues BEFORE `sealed_frame_events` under separate mutex scopes, so a producer could publish a zone and seal its frame in the unlocked window → the marker was consumed ahead of its zone and the frame finalized with zones missing — thread-count-INDEPENDENT (both the macOS cross-thread and Windows single-thread GPU tests fail on it) [SlangPy profiler PR #1063 also had a drain() snapshot-ordering race (#1072)](wiki/learnings/1784869755509-slangpy-profiler-pr-1063-also-had-a-drain-snapshot.md). The #1072 fix (PR #1073, +14/−5) reorders the two snapshots — `sealed_frame_events` under `sealed_frame_mutex` FIRST, then acquire-load `write_index` — and its soundness rests on a C++ happens-before / release-sequence argument (the acq-rel RMW chain on `global_frame` synchronizes each zone-releaser with the sealer); the two cited regression guards PRE-EXIST on main and are probabilistic (they only catch #1072 if the collector drains in the exact race window), so a green run corroborates but does not prove — the memory-model argument is the real proof and the PR added NO deterministic test (verdict: APPROVE_WITH_NITS, nit = coverage) [SGL profiler drain() #1072 fix — snapshot reorder + why its guard tests are probabilistic](wiki/learnings/1784870556172-sgl-profiler-drain-1072-fix-snapshot-reorder-why-i.md).

**And the reorder does NOT make `flush()` deterministic — a separate barrier gap covers only 1 of the collector's 3 input channels.** `Profiler::flush()` documents (`src/sgl/utils/profiler.h:476`) that it blocks "until the collector consumes events published before this call and publishes both snapshot products," but the implementation snapshots watermarks only from each thread's ring `write_index` (`profiler.cpp:~1710`) and `flush_targets_satisfied()` checks only `read_index >= flush_targets[i]` (`~1616-1629`). `drain()` has **three** independent inputs: the per-thread lock-free CPU/zone ring queues (*the only one in the barrier*), `sealed_frame_events` (frame markers, under `sealed_frame_mutex`), and `pending_gpu_results` (pushed at `~1046`/`~1289` under `gpu_result_mutex`). Channels 2 and 3 don't participate, so a frame marker or GPU result published before `flush()` returns can be missed — the collector snapshots a side queue, the event is published, and `flush()` still returns once the CPU watermark is met, leaving frame statistics incomplete until some later collector iteration. Consequence: `tests/sgl/device/test_profiler.cpp` *"device close settles pending frame statistics"* stays timing-dependent **even after** the #1072/#1073 fix — the reorder guarantees ordering only *within* one drain pass and cannot force another pass for a side-channel publication a pass already missed. Two constraints for anyone fixing it: the **GPU watermark must cover already-*published* results only** (waiting on *unresolved* queries exceeds the documented "published before this call" contract and can block indefinitely when a query never resolves; `tick()` is what moves resolved results into `pending_gpu_results` and is documented as not waiting — `profiler.h:471-474`), and an **"expected zone count" scheme must count `push()` successes, not zone attachments** (`ThreadData::push()` returns false and bumps `drop_count` when the ring is full, `~326-328`, but `end_zone` **discards that return value** at `~2186` and unconditionally calls `release_zone_from_global_frame` at `~2188`, so a dropped zone still decrements the frame's live-zone count and an attachment-based count would wait forever for an event never published). Diagnosed by skallweitNV, the profiler's author, on PR #1073 and verified first-hand against source ([profiler `flush()` barrier covers only 1 of 3 collector input channels](wiki/learnings/1785769306938-slangpy-profiler-flush-barrier-covers-only-1-of-3-.md)).
