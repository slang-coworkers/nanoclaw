# Slang Serialization, Module Cache, Link/Output Order, and Enum/Sentinel Discipline

## TL;DR
- The record/replay stream is **fixed-schema per call**: `executeNextCall` replays the same call shape, so **never conditionally skip `RECORD_OUTPUT`**.
- Pass an **interface-typed** pointer to record-replay `wrapObject`/`unwrapObject`. A concrete-impl `T` is bad-downcast UB that a green Debug build and passing tests hide; only UBSan catches it.
- `ReplayContext` registries are raw/non-owning, so the replay path leaks (DeepWiki says they own — wrong).
- Free a miniz `mz_zip_writer_finalize_heap_archive` buffer with the archive's own `archive.m_pFree`, not global `mz_free`.
- For a big retained blob, separate retention (lazy decode needs it) from decompression into private heap (a policy choice).
- The binary-module up-to-date check is **digest-based, not mtime-based**. #11918 (Windows cross-drive cache miss): `getRelativePath` returns empty across volumes, so save writes an empty dep; fixed by PR #11921.
- Keep terminal `CountOf`/`Count`/`NUM_*` sentinels **implicit**, with textual order == value order. `static_assert(CountOf == Named + 1)` is not a uniqueness guard.
- An exception from a destructor-time flush goes to `std::terminate`; a typed `catch` across macOS hidden-visibility dylibs silently misses. "Just throw" fixes neither.
- An inline template's `__FILE__` names the header (the path prefix names the instantiating TU). A switch's `default: break;` admits every unlisted case.
- Prefer an existing decoration on a single-producer type over a new stable IR opcode. Prove it safe from the readers' argument types, not from pass order.
- A new AST `FIDDLE()` field shifts the positional layout of its class and every subclass: bump BOTH `k_min` and `k_max`, because the reader's field-count check is only an assert and an old module segfaults. Since #12905 the loader rejects an out-of-range module version cleanly (E00130).
- Any new AST class, even an internal attribute, renumbers the positional `ASTNodeType` tags and needs the same bump. CI does not catch a missing one (`check-inst-version-changes.sh` tracks only IR insts), so test it with a cross-build `.slang-module` load in both directions.
- An added optional IR operand is a **max-only** module-version bump. Changing operand shape (value → type, reorder) is byte-stable: stable-names freeze only opcode ↔ integer.
- Changing an IR inst's meaning is a max-only bump with an `IRModule::getVersion()` branch. Drill the gate by removing the operands it exists for, and run `git merge-tree` against other open PRs that claim the same version number.
- A module-scope `static_assert` needs a carrier `IRFunc` (`[export]` + `[keepAlive]`), deleted after the emit check. A condition that must be constant at emit must fold in specialization, not only in peephole (`-minimum-slang-optimization` skips peephole; #13537).
- `-emit-ir` with no `-target` skips `linkAndOptimizeIR`, so no emit-time check runs on a serialized `.slang-module`.
- Two modules exporting one link-time symbol link silently; the winner depends on module order relative to the extern-declaring module. Do not call it "last wins". A tie can be TRUE both ways, and selection re-runs per alias and per target, so a conflict diagnostic needs a symmetric tie test and a per-link dedupe.
- `IRBuilder::getSet` order depends on the host C++ compiler; never FileCheck two conformers' generated functions in one sequence.
- `Dictionary` iterates in insertion order only because of `unordered_dense`; pointer-keyed loops that reach output would go nondeterministic under a hash-order map. Byte-compare repeated runs to check.
- `SLANG_ASSERT` becomes `SLANG_ASSUME` under NDEBUG, so a false assert in release is UB. Read an internals behaviour at a named ref before citing it — several premises recorded here were false.

## Record/Replay Layer

The stream in `source/slang-record-replay/` is fixed-schema at the call level even though each value carries a TypeId tag. Playback's `executeNextCall` re-invokes the same call shape, so a conditionally skipped `RECORD_OUTPUT` desynchronizes every later call ([Record/replay stream is fixed-schema at the call level](../learnings/1782866674061-record-replay-stream-is-fixed-schema-at-the-call-l.md)).

**`wrapObject<T>` needs a COM interface `T`.** There are two `wrapObject`s: the free `ISlangUnknown* wrapObject(ISlangUnknown*)` (`proxy-base.h`, does the real `tryWrap`) and the template `T* wrapObject(T*)` (`replay-context.h`), which QIs the proxy back to `T` via `T::getTypeGuid()`. Overload resolution prefers the template, so `wrapObject(new ReplayNullFileSystem())` deduces a concrete impl `T`. Its inherited `getTypeGuid()` compiles and runs, but `toSlangInterface<ReplayNullFileSystem>` calls through a pointer of the wrong dynamic type. UBSan reports a bad-downcast (`replay-shared.h:105`) while Debug and all 85 unit tests were green (PR #12863). Fix: `ISlangMutableFileSystem* standIn = new ReplayNullFileSystem(); desc.fileSystem = wrapObject(standIn);`, as the working arms already do. When a sanitizer job fails and local Debug is green, suspect static-vs-dynamic-type UB. Dead code a new test runs first can carry several latent bugs (a leak and this downcast both lived in the never-run `new NULLFileSystem()` arm) ([wrapObject<T> must use a COM interface type](../learnings/1788352568307-slang-record-replay-wrapobject-t-must-be-instantia.md)).

**The replay path leaks** (LSan direct leaks, #11936) because `ReplayContext` registries are raw/non-owning. DeepWiki describes them as owning, so check the source ([replay path leaks](../learnings/1783073842766-slang-record-replay-the-replay-path-leaks-because-.md)).

## Archive Buffers: miniz Ownership and RiffFileSystem Decompression

A buffer from `mz_zip_writer_finalize_heap_archive(&archive, &buf, &size)` belongs to the archive's allocator. Free it with `archive.m_pFree`, which can differ from global `mz_free` ([miniz heap-archive buffers](../learnings/1783064260282-miniz-heap-archive-buffers-are-owned-by-per-archiv.md)).

For the ~41.5 MB session-lifetime core-module blob (slang#12530), retention is required (fossil/on-demand deserialization, `readSerializedModuleAST` and #12446 deferred IR bodies, keeps spans into it), but the buffer is a decompressed private-heap copy, not a view into the mapped `g_coreModule[]` `.rodata`, only because the embedded archive ships compressed. In `source/core/slang-riff-file-system.cpp`, `RiffFileSystem::loadFile` with `m_compressionSystem` set allocates a full `ScopedAllocation` and decompresses into it; the uncompressed branch is `contents->addRef(); *outBlob = contents;` (zero-copy). `loadArchive` picks Deflate/LZ4/null from the header and `RawBlob::tryCreate`-copies each entry, so a `malloc_history` rooted at `loadFile` proves the archive is compressed. Rules: (1) separate the retention (backs lazy decode) from decompression-on-load (a binary-size vs load-RSS tradeoff); (2) build a lifetime-safe slice from existing parts — `ScopeBlob::create(UnownedRawBlob::create(base+offset,len), parentBlob)` — scoped to `loadArchive`, because `RiffFileSystem` is also the mutable `saveFile` path; (3) shipping the archive uncompressed makes the zero-copy branch fire (~0 private heap) for a bigger binary; measure first (depends on #12446/#12136) ([a retained blob's cost can be its decompression](../learnings/1789649564786-a-retained-blob-s-cost-can-be-its-decompression-no.md)).

## Terminal Count/Sentinel Enums

In #11852, `CompilerOptionName::CountOf == SPIRVUnifiedDescriptorHeapStride == 154`. The durable fix restores textual order == value order and keeps the sentinel implicit instead of pinning it explicitly ([keep sentinels IMPLICIT](../learnings/1782859187073-terminal-count-sentinel-enums-prefer-keeping-them-.md)). The hazard comes back when a concurrent PR's renumber breaks textual value order: the implicit `CountOf` then aliases an option again ([implicit CountOf aliases after a concurrent renumber](../learnings/1782853815255-implicit-countof-sentinel-aliases-an-option-when-a.md)). ## Binary-Module Up-to-Date Check and the #11918 Correction Chain

The up-to-date check compares digests, not mtimes, and the path layer has no cross-drive handling ([digest-based up-to-date check](../learnings/1783028515295-slang-binary-module-up-to-date-check-is-digest-bas.md)). The Windows-only #11918 cross-drive cache MISS is a model correction chain. The reproducer refuted the naive path-layer hypothesis ([reproducer refutes path-layer hypothesis](../learnings/1783029316997-slang-11918-cross-drive-module-cache-miss-reproduc.md)). A later atom placed the root cause at SAVE, not load: `getRelativePath` returns empty across volumes, save writes an empty dep, and load consumes it ([SUPERSEDES: empty-dep is the root cause](../learnings/1783031868902-supersedes-prior-11918-correction-the-getrelativep.md)). PR #11921 resolved it ([#11918 RESOLVED](../learnings/1783038802019-slang-11918-resolved-getrelativepath-returns-empty.md)).

## A Thrown Exception That Never Reaches Its `catch`

On macOS, hidden visibility duplicates RTTI, and libc++abi matches exceptions by RTTI identity. A typed `catch` of `Slang::Exception`/`InternalError` in another dylib therefore silently misses ([macOS hidden visibility breaks cross-dylib typed catch](../learnings/1783011716114-macos-hidden-visibility-breaks-cross-dylib-typed-c.md)).

The fossil deserializer had a second route to the same symptom (#13343, fixed by PR #13345). Before that PR, `Fossil::SerialReader` drained its deferred-action queue (object contents, e.g. a WitnessTable's requirement dictionary) in its destructor (`slang-serialize-fossil.cpp` ~1213). Destructors are implicitly `noexcept`, so any exception during a deferred read (`SLANG_ASSERT`/`InternalError`, `SLANG_UNEXPECTED`, `SLANG_ABORT_COMPILATION`) called `std::terminate`. A stale `.slang-module` aborted with `terminate called after throwing ... 'Slang::InternalError'`, rc 134 (0xC0000409 on Windows), so throwing instead of returning nullptr from `_readImportedDecl` did not help by itself. Confirm with `gdb -batch -ex run -ex 'bt 40' --args slangc ...`: frames show `~SerialReader` → `_flush`. The PR moves the drain into an explicit outermost-only `flush()` at both construction sites (`readFossilizedDecl`, `readSerializedModuleIR_`). To pin a clean failure, use `CHECK: result code = -1` (SIMPLE(filecheck) output starts with `result code = N`); an in-process terminate kills slang-test itself ([fossil deferred-read exception calls std::terminate](../learnings/1790783529890-slang-fossil-deserializer-an-exception-from-a-defe.md)).

## Reading a C++ Crash Path: Inline-Template `__FILE__` and a Switch's Default Arm

Two reading errors from the slang-rhi#818 triage. **An inline template's `__FILE__` names the header, not the data owner.** The assert path `src/metal/../core/short_vector.h:187` was read as "a metal TU indexed metal-owned data". But `short_vector::operator[]` is an inline template, so the `src/metal/../core/` prefix is only the include path of the TU that instantiated it. One grep disproved it at the pinned commit: `src/metal/` declared two `short_vector`s and never used either, and no file under `src/metal/` includes `../core/` (must-hit control: that TU has 7 includes) ([an inline template's __FILE__ names the header](../learnings/1786303967402-an-inline-template-s-file-names-the-header-so-a-cr.md)). **A switch's `default: break;` admits every case.** A claim that a call "fires exactly on `ConstantBuffer`/`ParameterBlock` cursors" (the two labels above it) turned a guard into a no-op, because the `default: break;` arm lets the call run for every other kind. Read the default arm before saying a switch restricts to its labels ([a switch's default arm admits every case](../learnings/1786304686679-a-switch-s-default-break-admits-every-case-reading.md)).

## IR Additions and Serialized-Module Compatibility

**Prefer an existing decoration over a new stable opcode.** slang#12875 first added `AnyValueMarshalCastDecoration` (new opcode, stable-name entry, generated builder, `k_maxSupportedModuleVersion` bump, per-cast decorations). The maintainer asked instead to attach the existing `IRAnyValueSizeDecoration` to the `AnyValueN` storage struct (produced only in `ensureAnyValueType()`) and gate on `as<IRStructType>(result) && result->findDecoration<IRAnyValueSizeDecoration>()`. That removed the opcode, stable name, builder and version bump (~13 fewer lines). Safety is a type-specific argument: check that every reader of the decoration passes a type that is never the newly marked type. A pass-ordering argument was wrong here — `getInterfaceAnyValueSize` is called inside the marshalling file itself, and codex OUTPUT_REVIEW caught it; all four reader sites pass an interface type ([prefer reusing an existing IR decoration](../learnings/1789475350340-prefer-reusing-an-existing-ir-decoration-over-a-ne.md)).

**An added optional operand is a max-only bump** (`k_maxSupportedModuleVersion` 28→29; `k_min` unchanged). `docs/design/ir-instruction-definition.md` calls new optional operands minor; changed minimum operand counts/types are major. Serialization is self-describing for operand count: `InstAllocInfo{IROp op; uint32_t operandCount}` is written per inst (`slang-serialize-ir.cpp`) and read back with the stored count, so an old 1-operand `IRWitnessTable` reads as `operandCount==1`. Since #12905 (2026-09-17) the loader rejects a module whose version is outside `[k_min, k_max]` (`IRModule::isModuleVersionSupported` in `slang-session.cpp` and `slang-serialize-ir.cpp`, E00130 `unsupported-serialized-module-version`); before that it checked only the serialization format version. A max-only bump keeps old modules in range, so they still reach the reader: guard the accessor on count (`getOperandCount() > 1 ? getOperand(1) : nullptr`), null-guard every call site, and state that the repo has no old-module → new-reader load test, only same-version round-trips. Flag, don't dismiss: `IRInstKey` compares operand counts, so a legacy 1-operand table and a new 2-operand table for the same conformance do not GVN-merge ([module-version bump for an additive optional operand](../learnings/1789476647852-slang-ir-module-version-bump-for-an-additive-optio.md)).

**A new AST `FIDDLE()` field is a min+max bump.** The AST serializer lays out fields by position, base-class fields first and then each class's own fields in order, so a field added to an AST class shifts the layout of that class and of every subclass: `Attribute::floatArgVals` in #13953 shifts every builtin attribute too (a new `Decl` subclass likewise shifts the positional `ASTNodeType` tags; see the `static_assert` section). The reader's field-count check is only a `SLANG_ASSERT`, so a module written by the previous compiler is decoded one field off and crashes: in #13953 a `.slang-module` built at base 52e29ab43 segfaulted the PR's compiler (rc=139) under both `slangc m.slang-module -reflection-json` and `import m`, while the base compiler loaded it. Bump both `IRModule::k_minSupportedModuleVersion` and `k_maxSupportedModuleVersion` in `source/slang/slang-ir.h` and add a line to the comment above them (precedent #13756, bumped to 37 for a new serialized field); the old module then fails cleanly with E00130. `tools/slang-static-unit-test/unit-test-module-version.cpp` compares against the constants symbolically, so the bump does not break it. To check, build a module with the base compiler (`slangc m.slang -o m.slang-module`), move `m.slang` away, and load the module with the head compiler [Adding a FIDDLE() field to an AST node needs a module-version bump (old .slang-module segfaults)](../learnings/1793002822043-adding-a-fiddle-field-to-an-ast-node-needs-a-modul.md) [Slang checker: fold quietly with a scratch sink; coerce() already folds int→half](../learnings/1793009488997-slang-checker-fold-quietly-with-a-scratch-sink-coe.md). A `List<std::optional<T>>` field also needs a `dump(const std::optional<T>&)` overload in `slang-ast-dump.cpp`; clone and serialization already handle the type [Slang front-end float folding for user-attribute args: gotchas (#13952)](../learnings/1793000621319-slang-front-end-float-folding-for-user-attribute-a.md).

**A new AST class is a min+max bump too, and CI does not catch a missing one.** `ASTNodeType` is a sequential pre-order numbering of every `NodeBase` subclass, and a serialized `.slang-module` stores it (`Fossilized<ASTNodeType>` in `slang-serialize-ast.cpp`). So inserting any class, even an internal attribute such as #13975's `ConstantFoldAsAttribute`, renumbers the tags. Without a `k_min`/`k_max` bump, a master-built module imported by the PR build segfaulted (rc 139), and so did the reverse. Precedent: #13406 bumped 36→37 for the same reason. `extras/check-inst-version-changes.sh` tracks only IR insts. A check takes under a minute with two Release builds: write a tiny `module m;` with a public struct, function and `static const`, run `slangc m.slang -o m.slang-module` with build X, move `m.slang` away, then run `slangi main.slang` (which does `import m;`) with build Y. As a control, two masters that differ in no `slang-ast-*.h` load each other's modules. After the bump an old module gets a clean `warning[E00131]: ignoring IR module version 37…` and the loader falls back to source [adding any AST class requires a module-version bump](../learnings/1793210446543-adding-any-ast-class-requires-a-module-version-bum.md).

**Changing an IR instruction's meaning, and drilling the gate.** Per `docs/design/backwards-compat-for-ir-modules.md`, bump `k_maxSupportedModuleVersion`, keep `k_min`, and branch on `IRModule::getVersion()`. Test the legacy path by rewriting a serialized blob's version, as `irBlobRejectsVersion36` in `unit-test-ir-blob.cpp` does; that file is CRLF, so preserve it with `newline=''` in Python [linker DebugSource ownership needs the producer](../learnings/1793220067281-slang-linker-a-module-s-debugsource-list-includes-.md). On #13992, `DebugCompilationUnit` gained variadic `includedSources` operands (bump to 38 with a v37 fallback) whose only job is to keep #7203's "list a header that has no line rows" behavior. Emitting the CU with an empty operand list still passed all 277 `-g` tests plus `irBlob`, because #7203 itself had no test and every include test calls into its header, so the header is reached through `DebugLine` anyway. When a PR adds IR operands only to keep records alive through linking, drill by removing them. The guarding test needs a header that defines only a macro, both in the entry file and in an imported module that is used. A real v37 module for cross-version checks comes from the base compiler (`slangc -g2 -o X.slang-module`), loaded into head with `-r`. Before approving a module-version bump, run `git merge-tree --write-tree` against the other open PRs that bump it: that day 4 PRs claimed version 38 [module version gate: drill the IR operand the gate exists for](../learnings/1793223587899-slang-module-version-gate-drill-the-ir-operand-tha.md). The linker side of #13992 is on [[wiki/concepts/slang-backends-spirv-debug-info-emission.md]].

**Changing operand shape is byte-stable** (value operand → type operand, reorder): no major bump and no stable-name rename. `slang-ir-insts-stable-names.lua` freezes only opcode ↔ integer (e.g. TypeEquals=582). Operands serialize positionally as inst references, and the `"value"`/`"type"` operand names in `slang-ir-insts.lua` are unserialized C++ accessor sugar (`slang-serialize-ir.cpp:314-332`). For legacy modules whose op references a value inst, keep consumers dual-tolerant (peephole `getTypeFromOperand` already accepts either) or add a small IR upgrade. A DeepWiki "must major-bump" answer was refuted by these two files ([IR operand-shape migration is byte-stable](../learnings/1789601900070-ir-operand-shape-migration-is-byte-stable-stable-n.md)).

## `static_assert` as a Declaration (#13229) and Where It Is Checked

A `static_assert` usable at global/namespace/aggregate scope (#13229 / #6136) must be lowered where there is no active IR block. Emitting the condition under the module inst is malformed IR: a condition needing inlining or `||`/`&&` control flow aborts (a global `static_assert(__targetHasImplicitDerivatives(), ...)` hit `SLANG_ASSERT(as<IRBlock>(callerBlock))` at `slang-ir-inline.cpp:767`), while simple `sizeof`/arithmetic conditions survive and hide the bug. The fix synthesizes a `void()` **carrier `IRFunc`** and lowers condition + message + assert into its block (reusing function-body lowering). `[export]` (so `linkIR` clones it as a root) and `[keepAlive]` (blocks DCE) keep it through linking — the pattern at `slang-lower-to-ir.cpp:14117`. `slang-emit.cpp` deletes the emptied carrier right after the check; otherwise `void s_N(){}` leaks into `-target cpp` output. A new IR decoration must have an explicit `slang-ir-insts-stable-names.lua` entry (fiddle fails with an opaque "internal error in 'fiddle' tool" and does not auto-append), and a stateless one must join `isSimpleDecoration` (`slang-ir.cpp`); a duplicate diagnostic code fails the same fiddle step the same way. `checkStaticAssert` does not fold the condition: the specialization/simplification passes fold it to a bool literal, and the check reads, diagnoses and removes it ([static_assert as a decl needs a carrier IRFunc](../learnings/1790123003621-static-assert-as-a-decl-module-scope-conditions-ne.md)).

**The folding pass matters under `-minimum-slang-optimization`, which skips peephole.** On slang#13537, `_Texture` changed `T` to `typealias T = Texel.DataType` (an associated-type projection). HLSL `Sample`/`SampleLevel` then failed with E41402 (condition not compile-time constant), only for `hlsl`/`dxil` at min-opt. `T` lowers to `lookup_witness_method`, which `specializeModule` resolves to the concrete type, but `maybeSpecializeInst` (slang-ir-specialize.cpp) had no `kIROp_TypeEquals` case. The `T is float || …` chain therefore folded only in peephole (slang-ir-peephole.cpp ~1810), and `checkStaticAssert` saw a non-constant condition. Adding `case kIROp_TypeEquals:` to the `maybeSpecializeFoldableInst` group fixes it; test core-module `static_assert`s under min-opt. Process: a trivial master merge can still break CI, so run master's new tests on the merged tree before pushing to an auto-merge PR. To bisect without rebuilding, download each PR head's `slang-tests-linux-x86_64-gcc-release` CI artifact (`gh api repos/.../actions/artifacts/<id>/zip`) and run its `Release/bin/slangc` with `LD_LIBRARY_PATH=Release/lib` ([associated-type alias breaks static_assert at min-opt](../learnings/1792025326251-associated-type-alias-in-core-module-breaks-static.md)).

**Surviving linking also means escaping the check.** `checkStaticAssert` / `checkAndRemoveStaticAsserts` live in `linkAndOptimizeIR`, which runs only inside `for (auto targetReq : linkage->targets)`. With `-emit-ir` / `ContainerFormat::SlangModule` and no `-target`, that list is empty, so no pass or diagnostic in `linkAndOptimizeIR` runs and `maybeCreateContainer` serializes the raw front-end IR. The carrier lands unchecked in the `.slang-module`; failure is deferred to the consumer's `import` + real-target codegen. For an emit-time check said to run "on every target", ask whether `slangc lib.slang -o lib.slang-module -emit-ir` runs it (HostVM/interpreter skips it via an early return in `linkAndOptimizeIR`). Also, a new **user-writable** `Decl` subclass needs both a `k_min`/`k_maxSupportedModuleVersion` bump (inserting an AST node shifts positional `ASTNodeType` tags; precedent #13175) and a case in `classifyDeclForNesting` (`slang-check-decl.cpp`). An unclassified `Decl` takes `Unknown` → skip validation and bypasses the nesting table ([-emit-ir with no -target skips linkAndOptimizeIR](../learnings/1790140301023-slang-module-serialization-emit-ir-no-target-skips.md)).

## Order-Dependent Output: Link Symbol Choice, Dictionary Iteration, IR Set Order

**Conflicting link-time exports resolve silently by module order.** Two modules `export` the same link-time symbol (an `extern struct`, `static const`, or function), and a third declares it `extern`: linking succeeds and prints nothing. `isBetterForTarget` (`slang-ir-link.cpp:1294`) returns false on a full tie, so the selection loop (:1610-1615) keeps its current best. `insertGlobalValueSymbol` (:1671-1701) keeps the first-inserted candidate at the head of the list and splices each later one right after it. Extern module first → the last export wins; exporters first → the first wins. Neither is a rule; don't say "last wins" (#13319). Traps for a conflict diagnostic: IR `[export]` is on every non-imported definition (`slang-lower-to-ir.cpp:1428-1437`), not only source `export`; `[hlslExport]` (the user `export` keyword) is also put on sub-witness tables of exported types (`:11182`); enum witnesses share mangled names on purpose (`slang-mangle.cpp:1052-1080`). slangc binds `-entry` to the file before it, so a permutation test keeps the extern module just before `-entry` ([IR-link conflicting exports pick silently](../learnings/1790691097788-ir-link-conflicting-exports-pick-silently-and-the-.md)).

**A tie can be TRUE both ways, and selection runs more than once per link** (E45002 export-conflict diagnostic, #13319/PR #13471). Two `__specialized_for_target(hlsl)` definitions in different modules, compiled for hlsl, make `CapabilitySet::isBetterForTarget` true in both directions (the `thisStageSet == shaderStageSetWeNeed` early return), so the loop replaces `bestVal` on every visit and the last visited wins. Test a tie as `isBetterForTarget(a,b) == isBetterForTarget(b,a)`. Members of `export struct R : I {...}` have their own mangled symbols, so `R` can come from module A and `R.value()` from module B. For a generic extension, `[hlslExport]` is on the inner witness_table and the linkage decoration on the outer `IRGeneric`. A source TU and its own precompiled `.slang-module` reach `linkIR` as two IRModules with one Name (other same-name modules are deduped earlier by `Linkage::loadModuleFromBlob`). Use `standalone_note` for IR-level notes (as E45001 does); a `variadic_note` with an invalid SourceLoc prints a stray `--- :0:0`. Census every tie (env-gated fprintf) across the suite before choosing a predicate: 186 ties ruled out three naive ones ([isBetterForTarget can return TRUE both ways](../learnings/1791333125522-slang-ir-linker-isbetterfortarget-can-return-true-.md)). Selection also re-runs for one mangled name. `cloneInst`'s `kIROp_SymbolAlias` case clones the aliased value but never calls `registerClonedValue` for the alias, and `linkIR`'s keep-alive loop (`cloneAndKeepAlive` over each module's `getHLSLExports()`) clones every `export struct R : I = X;` alias. A per-symbol diagnostic after the loop therefore needs a per-link dedupe set (`IRSharedSpecContext::reportedExportConflicts`). Two entry points share one IRSpecEnv, but a multi-target compile runs `linkIR` once per target, so the diagnostic repeats per target. In gdb break on the function name; line breakpoints on an early `return` landed on wrong statements in the optimized Debug build ([a SymbolAlias re-runs selection](../learnings/1791352109049-slang-linker-a-symbolalias-re-runs-cloneglobalvalu.md)).

**Dictionary iteration order reaches output through pointer-keyed loops.** At master b9199bdaa, `Dictionary`/`HashSet` wrap `ankerl::unordered_dense`, which iterates in insertion order (erase swaps the last entry into the hole), so output is deterministic today. Plain (non-`Ordered`) loops whose order reaches output: `slang-ir-lower-dynamic-dispatch-insts.cpp:338`, over an `IRInst*`-keyed map (:276), sets the wrapper/switch-case order of the dispatch function; `slang-serialize-source-loc.cpp:128`, over a `SourceFile*`-keyed map, sets `m_sourceInfos` order in serialized modules (the reader is a linear search, :170-176, so only bytes change); `slang-ir-link.cpp:1939`, int-keyed, sets the atomic struct's order. A hash-order map (e.g. `boost::unordered_flat_map`, #13309, branch expipiplus1 3c87126) would make pointer-keyed output vary between runs of one binary, because pointers hash by address and ASLR moves addresses. Byte-compare repeated runs; FileCheck won't catch it. Related: master `getHashCode(const char*, len)` (`slang-hash.h:136-139`) calls the private `ankerl::unordered_dense::detail::wyhash::hash`, gone from Homebrew's unordered_dense; PR #13293 uses public `hash<std::string_view>`, and #13309's WYHASH path re-adds the private call ([Dictionary iteration order leaks into output](../learnings/1790673419809-slang-dictionary-iteration-order-leaks-into-output.md)).

**IR set order differs by host compiler.** `IRBuilder::getSet` (slang-ir.cpp ~7587) sorts with `getUniqueID(a) < getUniqueID(b)`, but `getUniqueID` assigns IDs lazily on first call and C++ leaves the order of the two calls unspecified. MSVC builds (Windows x86_64 Debug, aarch64 Debug and Release) therefore order sets differently from GCC/Clang. Set order drives dispatch order and the order of generated functions (e.g. AnyValue pack/unpack per conformer), so FileChecking two conformers' functions in one sequence can fail only on Windows. Give each conformer its own prefix (separate `//TEST:SIMPLE(filecheck=X)` runs). Reproduce on Linux by swapping the comparator's call order (`auto ib = getUniqueID(b); auto ia = getUniqueID(a); return ia < ib;`) ([IR set order is host-compiler dependent](../learnings/1791336133684-slang-ir-set-order-is-host-compiler-dependent-lazy.md)).
