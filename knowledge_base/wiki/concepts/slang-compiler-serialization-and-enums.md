# Slang Serialization, Module Cache, Link/Output Order, and Enum/Sentinel Discipline

## TL;DR
- The record/replay stream is **fixed-schema per call**: **never conditionally skip `RECORD_OUTPUT`**. Pass an **interface-typed** pointer to `wrapObject`/`unwrapObject`; a concrete-impl `T` is bad-downcast UB only UBSan catches. `ReplayContext` registries are non-owning, so replay leaks.
- Free a miniz heap-archive buffer with `archive.m_pFree`, not `mz_free`. For a big retained blob, retention (lazy decode) and decompression into private heap are separate decisions.
- The binary-module up-to-date check is **digest-based, not mtime-based**. #11918 (Windows cross-drive cache miss): `getRelativePath` returns empty across volumes, so save writes an empty dep; fixed by PR #11921.
- Keep terminal `CountOf`/`Count`/`NUM_*` sentinels **implicit**, with textual order == value order. `static_assert(CountOf == Named + 1)` is not a uniqueness guard.
- An exception from a destructor-time flush goes to `std::terminate`; a typed `catch` across macOS hidden-visibility dylibs silently misses.
- An inline template's `__FILE__` names the header, not the data owner. A switch's `default: break;` admits every unlisted case.
- Prefer an existing decoration on a single-producer type over a new stable IR opcode. Prove it safe from the readers' argument types, not from pass order.
- A new AST `FIDDLE()` field or any new AST class shifts the positional serialized layout: bump BOTH `k_min` and `k_max` (the field-count check is only an assert; an old module segfaults). Since #12905 an out-of-range module is rejected cleanly (E00130). CI does not catch a missing bump; test with a cross-build `.slang-module` load in both directions.
- An added optional IR operand is a **max-only** module-version bump. Changing operand shape (value → type, reorder) is byte-stable: stable-names freeze only opcode ↔ integer.
- Changing an IR inst's meaning is a max-only bump with an `IRModule::getVersion()` branch. Drill the gate by removing the operands it exists for, and run `git merge-tree` against other open PRs that claim the same version number.
- A module-scope `static_assert` needs a carrier `IRFunc` (`[export]` + `[keepAlive]`), deleted after the emit check. A condition that must be constant at emit must fold in specialization, not only in peephole (`-minimum-slang-optimization` skips peephole; #13537).
- `-emit-ir` with no `-target` skips `linkAndOptimizeIR`, so no emit-time check runs on a serialized `.slang-module`.
- Two modules exporting one link-time symbol link silently; the winner depends on module order relative to the extern-declaring module. Do not call it "last wins". A tie can be TRUE both ways, and selection re-runs per alias and per target, so a conflict diagnostic needs a symmetric tie test and a per-link dedupe.
- `IRBuilder::getSet` order depends on the host C++ compiler; never FileCheck two conformers' generated functions in one sequence.
- `Dictionary` iterates in insertion order only because of `unordered_dense`; pointer-keyed loops that reach output would go nondeterministic under a hash-order map. Byte-compare repeated runs to check.
- `SLANG_ASSERT` becomes `SLANG_ASSUME` under NDEBUG (a false assert in release is UB). Read an internals behaviour at a named ref before citing it.

## Record/Replay Layer

The stream in `source/slang-record-replay/` is fixed-schema at the call level even though each value carries a TypeId tag. Playback's `executeNextCall` re-invokes the same call shape, so a conditionally skipped `RECORD_OUTPUT` desynchronizes every later call ([Record/replay stream is fixed-schema at the call level](../learnings/1782866674061-record-replay-stream-is-fixed-schema-at-the-call-l.md)).

**`wrapObject<T>` needs a COM interface `T`.** The free `ISlangUnknown* wrapObject(ISlangUnknown*)` (`proxy-base.h`) does the real `tryWrap`; the template `T* wrapObject(T*)` (`replay-context.h`) QIs the proxy back via `T::getTypeGuid()`. Overload resolution prefers the template, so `wrapObject(new ReplayNullFileSystem())` deduces a concrete `T`; it compiles and runs, but `toSlangInterface<ReplayNullFileSystem>` calls through a pointer of the wrong dynamic type. UBSan reports a bad-downcast (`replay-shared.h:105`) while Debug and all 85 unit tests were green (PR #12863). Fix: `ISlangMutableFileSystem* standIn = new ReplayNullFileSystem(); desc.fileSystem = wrapObject(standIn);`. When a sanitizer job fails and local Debug is green, suspect static-vs-dynamic-type UB; never-run code that a new test reaches first can carry several latent bugs ([wrapObject<T> must use a COM interface type](../learnings/1788352568307-slang-record-replay-wrapobject-t-must-be-instantia.md)).

**The replay path leaks** (LSan direct leaks, #11936) because `ReplayContext` registries are raw/non-owning. DeepWiki describes them as owning, so check the source ([replay path leaks](../learnings/1783073842766-slang-record-replay-the-replay-path-leaks-because-.md)).

## Archive Buffers: miniz Ownership and RiffFileSystem Decompression

A buffer from `mz_zip_writer_finalize_heap_archive(&archive, &buf, &size)` belongs to the archive's allocator; free it with `archive.m_pFree`, which can differ from global `mz_free` ([miniz heap-archive buffers](../learnings/1783064260282-miniz-heap-archive-buffers-are-owned-by-per-archiv.md)).

The ~41.5 MB session-lifetime core-module blob (slang#12530) must be retained (fossil on-demand deserialization, `readSerializedModuleAST` and #12446 deferred IR bodies keep spans into it), but it is a private-heap copy rather than a view into the mapped `g_coreModule[]` `.rodata` only because the embedded archive ships compressed. In `source/core/slang-riff-file-system.cpp`, `RiffFileSystem::loadFile` with `m_compressionSystem` set decompresses into a full `ScopedAllocation`; the uncompressed branch is zero-copy (`contents->addRef(); *outBlob = contents;`). A `malloc_history` rooted at `loadFile` proves compression. Rules: (1) treat retention (backs lazy decode) and decompression-on-load (binary size vs load RSS) as separate decisions; (2) build a lifetime-safe slice from existing parts — `ScopeBlob::create(UnownedRawBlob::create(base+offset,len), parentBlob)` — scoped to `loadArchive`, because `RiffFileSystem` is also the mutable `saveFile` path; (3) shipping uncompressed makes the zero-copy branch fire (~0 private heap) for a bigger binary; measure first (depends on #12446/#12136) ([a retained blob's cost can be its decompression](../learnings/1789649564786-a-retained-blob-s-cost-can-be-its-decompression-no.md)).

## Terminal Count/Sentinel Enums

In #11852, `CompilerOptionName::CountOf == SPIRVUnifiedDescriptorHeapStride == 154`. The durable fix restores textual order == value order and keeps the sentinel implicit instead of pinning it explicitly ([keep sentinels IMPLICIT](../learnings/1782859187073-terminal-count-sentinel-enums-prefer-keeping-them-.md)). The hazard returns when a concurrent PR's renumber breaks textual value order: the implicit `CountOf` then aliases an option again ([implicit CountOf aliases after a concurrent renumber](../learnings/1782853815255-implicit-countof-sentinel-aliases-an-option-when-a.md)). A `static_assert(CountOf == SomeNamedOption + 1)` checks adjacency to one enumerator, not that `CountOf` is unique ([sentinel static_assert is not a uniqueness guard](../learnings/1782858072079-sentinel-static-assert-pinned-to-a-named-option-is.md)).

## Binary-Module Up-to-Date Check and #11918

The up-to-date check compares digests, not mtimes ([digest-based up-to-date check](../learnings/1783028515295-slang-binary-module-up-to-date-check-is-digest-bas.md)). For the Windows-only #11918 cross-drive cache miss, the reporter's reproducer ruled out "different directory" (a same-drive, different-dir control HITs) and "source dir missing from search path" ([reproducer refutes path-layer hypothesis](../learnings/1783029316997-slang-11918-cross-drive-module-cache-miss-reproduc.md)). The root cause is at SAVE: `Path::getRelativePath` (`std::filesystem::relative`) returns an empty path across volumes; `encodeModuleDependencyPaths` accepts a cross-volume search dir as `linkageRoot` because `hasRelativeElement("") == false`, then serializes the module's dep as an empty string; on load `isBinaryModuleUpToDate` cannot resolve it. A clean read of the consumer exonerated the load layer while the producer it received input from was the bug — trace producer → consumer end to end, and treat "save-side only" as a reason to inspect what the helper writes ([SUPERSEDES: empty-dep is the root cause](../learnings/1783031868902-supersedes-prior-11918-correction-the-getrelativep.md)). PR #11921 makes `getRelativePath` fall back to the absolute path when the result is empty; the exact-value regression asserts are `#if SLANG_WINDOWS_FAMILY`-gated, since only Windows drive letters produce the empty result ([#11918 RESOLVED](../learnings/1783038802019-slang-11918-resolved-getrelativepath-returns-empty.md)).

## A Thrown Exception That Never Reaches Its `catch`

On macOS, hidden visibility duplicates RTTI, and libc++abi matches exceptions by RTTI identity, so a typed `catch` of `Slang::Exception`/`InternalError` in another dylib silently misses ([macOS hidden visibility breaks cross-dylib typed catch](../learnings/1783011716114-macos-hidden-visibility-breaks-cross-dylib-typed-c.md)).

The fossil deserializer had a second route to the same symptom (#13343, fixed by PR #13345). `Fossil::SerialReader` drained its deferred-action queue (object contents, e.g. a WitnessTable's requirement dictionary) in its destructor (`slang-serialize-fossil.cpp` ~1213). Destructors are implicitly `noexcept`, so any exception during a deferred read (`SLANG_ASSERT`/`InternalError`, `SLANG_UNEXPECTED`, `SLANG_ABORT_COMPILATION`) called `std::terminate`: a stale `.slang-module` aborted with rc 134 (0xC0000409 on Windows), and throwing instead of returning nullptr from `_readImportedDecl` did not help by itself. A gdb backtrace shows `~SerialReader` → `_flush`. The PR moves the drain into an explicit outermost-only `flush()` at both construction sites (`readFossilizedDecl`, `readSerializedModuleIR_`). Pin a clean failure with `CHECK: result code = -1`; an in-process terminate kills slang-test itself ([fossil deferred-read exception calls std::terminate](../learnings/1790783529890-slang-fossil-deserializer-an-exception-from-a-defe.md)).

## Reading a C++ Crash Path: Inline-Template `__FILE__` and a Switch's Default Arm

**An inline template's `__FILE__` names the header, not the data owner.** The assert path `src/metal/../core/short_vector.h:187` was read as "a metal TU indexed metal-owned data", but `short_vector::operator[]` is an inline template, so the prefix is only the include path of the instantiating TU. One grep disproved it: `src/metal/` declared two `short_vector`s and never used either, and no file there includes `../core/` (must-hit control: that TU has 7 includes) ([an inline template's __FILE__ names the header](../learnings/1786303967402-an-inline-template-s-file-names-the-header-so-a-cr.md)). **A switch's `default: break;` admits every case.** A claim that a call "fires exactly on `ConstantBuffer`/`ParameterBlock` cursors" (the two labels above it) turned a guard into a no-op, because the default arm lets the call run for every other kind. Read the default arm before saying a switch restricts to its labels ([a switch's default arm admits every case](../learnings/1786304686679-a-switch-s-default-break-admits-every-case-reading.md)).

## IR Additions and Serialized-Module Compatibility

**Prefer an existing decoration over a new stable opcode.** slang#12875 first added `AnyValueMarshalCastDecoration` (new opcode, stable-name entry, builder, `k_maxSupportedModuleVersion` bump). The maintainer asked instead to attach the existing `IRAnyValueSizeDecoration` to the `AnyValueN` storage struct (produced only in `ensureAnyValueType()`) and gate on `as<IRStructType>` + that decoration, removing the opcode, stable name, builder and bump. Prove safety by checking that every reader of the decoration passes a type that is never the newly marked type; a pass-ordering argument was wrong here (`getInterfaceAnyValueSize` is called inside the marshalling file itself; codex OUTPUT_REVIEW caught it), while all four reader sites pass an interface type ([prefer reusing an existing IR decoration](../learnings/1789475350340-prefer-reusing-an-existing-ir-decoration-over-a-ne.md)).

**An added optional operand is a max-only bump** (`k_maxSupportedModuleVersion` 28→29; `k_min` unchanged; `docs/design/ir-instruction-definition.md` calls new optional operands minor and changed minimum counts/types major). Serialization is self-describing for operand count: `InstAllocInfo{IROp op; uint32_t operandCount}` is written per inst (`slang-serialize-ir.cpp`), so an old 1-operand `IRWitnessTable` reads as `operandCount==1`. Since #12905 (2026-09-17) the loader rejects a module outside `[k_min, k_max]` (`IRModule::isModuleVersionSupported` in `slang-session.cpp` and `slang-serialize-ir.cpp`, E00130 `unsupported-serialized-module-version`); before that it checked only the serialization format version. A max-only bump keeps old modules in range, so guard the accessor on count (`getOperandCount() > 1 ? getOperand(1) : nullptr`), null-guard every call site, and note that the repo has no old-module → new-reader load test, only same-version round-trips. `IRInstKey` compares operand counts, so a legacy 1-operand and a new 2-operand table for one conformance do not GVN-merge — flag it ([module-version bump for an additive optional operand](../learnings/1789476647852-slang-ir-module-version-bump-for-an-additive-optio.md)).

**A new AST `FIDDLE()` field is a min+max bump.** The AST serializer lays out fields by position (base-class fields first, then each class's own), so a new field shifts the layout of that class and every subclass: `Attribute::floatArgVals` in #13953 shifts every builtin attribute. The reader's field-count check is only a `SLANG_ASSERT`, so an old module is decoded one field off: a base-built `.slang-module` segfaulted the PR's compiler (rc=139) under both `-reflection-json` and `import m`. Bump both `IRModule::k_minSupportedModuleVersion` and `k_maxSupportedModuleVersion` in `source/slang/slang-ir.h` with a comment line (precedent #13756, bumped to 37); the old module then fails cleanly with E00130. `unit-test-module-version.cpp` compares the constants symbolically, so the bump does not break it. To check, build a module with the base compiler (`slangc m.slang -o m.slang-module`), move `m.slang` away, and load it with the head compiler [Adding a FIDDLE() field to an AST node needs a module-version bump (old .slang-module segfaults)](../learnings/1793002822043-adding-a-fiddle-field-to-an-ast-node-needs-a-modul.md) [Slang checker: fold quietly with a scratch sink; coerce() already folds int→half](../learnings/1793009488997-slang-checker-fold-quietly-with-a-scratch-sink-coe.md). A `List<std::optional<T>>` field also needs a `dump(const std::optional<T>&)` overload in `slang-ast-dump.cpp`; clone and serialization already handle the type [Slang front-end float folding for user-attribute args: gotchas (#13952)](../learnings/1793000621319-slang-front-end-float-folding-for-user-attribute-a.md).

**A new AST class is a min+max bump too, and CI does not catch a missing one.** `ASTNodeType` is a sequential pre-order numbering of every `NodeBase` subclass, stored in a serialized module (`Fossilized<ASTNodeType>` in `slang-serialize-ast.cpp`), so inserting any class — even an internal attribute such as #13975's `ConstantFoldAsAttribute` — renumbers the tags. Without a bump, a master-built module imported by the PR build segfaulted (rc 139), and so did the reverse (precedent #13406, 36→37). `extras/check-inst-version-changes.sh` tracks only IR insts. Check with two Release builds: compile a tiny public `module m;` with build X, move `m.slang` away, and `import m;` from `slangi main.slang` with build Y (control: two masters differing in no `slang-ast-*.h` load each other's modules). After the bump an old module gets `warning[E00131]: ignoring IR module version 37…` and the loader falls back to source [adding any AST class requires a module-version bump](../learnings/1793210446543-adding-any-ast-class-requires-a-module-version-bum.md).

**Changing an IR instruction's meaning, and drilling the gate.** Per `docs/design/backwards-compat-for-ir-modules.md`, bump `k_maxSupportedModuleVersion`, keep `k_min`, and branch on `IRModule::getVersion()`. Test the legacy path by rewriting a serialized blob's version, as `irBlobRejectsVersion36` in `unit-test-ir-blob.cpp` does (the file is CRLF; preserve with `newline=''` in Python) [linker DebugSource ownership needs the producer](../learnings/1793220067281-slang-linker-a-module-s-debugsource-list-includes-.md). On #13992, `DebugCompilationUnit` gained variadic `includedSources` operands (bump to 38 with a v37 fallback) whose only job is #7203's "list a header that has no line rows" behavior. Emitting the CU with an empty operand list still passed all 277 `-g` tests, because #7203 had no test and every include test reaches its header through `DebugLine` anyway. When a PR adds IR operands only to keep records alive through linking, drill by removing them; the guarding test needs a macro-only header, both in the entry file and in a used imported module. Get a real v37 module from the base compiler (`slangc -g2 -o X.slang-module`) and load it into head with `-r`. Before approving a version bump, run `git merge-tree --write-tree` against other open PRs that bump it (that day 4 PRs claimed 38) [module version gate: drill the IR operand the gate exists for](../learnings/1793223587899-slang-module-version-gate-drill-the-ir-operand-tha.md). The linker side of #13992 is on [[wiki/concepts/slang-backends-spirv-debug-info-emission.md]].

**Changing operand shape is byte-stable** (value operand → type operand, reorder): no major bump, no stable-name rename. `slang-ir-insts-stable-names.lua` freezes only opcode ↔ integer (e.g. TypeEquals=582); operands serialize positionally as inst references, and the `"value"`/`"type"` names in `slang-ir-insts.lua` are unserialized accessor sugar (`slang-serialize-ir.cpp:314-332`). For legacy modules whose op references a value inst, keep consumers dual-tolerant (peephole `getTypeFromOperand` already accepts either) or add a small IR upgrade. A DeepWiki "must major-bump" answer was refuted by these two files ([IR operand-shape migration is byte-stable](../learnings/1789601900070-ir-operand-shape-migration-is-byte-stable-stable-n.md)).

## `static_assert` as a Declaration (#13229) and Where It Is Checked

A `static_assert` at global/namespace/aggregate scope (#13229 / #6136) has no active IR block, and emitting its condition under the module inst is malformed IR: a condition needing inlining or `||`/`&&` control flow aborts (`SLANG_ASSERT(as<IRBlock>(callerBlock))`, `slang-ir-inline.cpp:767`), while simple `sizeof`/arithmetic conditions hide the bug. The fix synthesizes a `void()` **carrier `IRFunc`** holding condition + message + assert (reusing function-body lowering), kept through linking by `[export]` (`linkIR` clones it as a root) and `[keepAlive]` (blocks DCE) — the pattern at `slang-lower-to-ir.cpp:14117`. `slang-emit.cpp` deletes the emptied carrier after the check, or `void s_N(){}` leaks into `-target cpp` output. A new IR decoration needs an explicit `slang-ir-insts-stable-names.lua` entry (otherwise fiddle fails with an opaque internal error, as a duplicate diagnostic code also does), and a stateless one must join `isSimpleDecoration`. `checkStaticAssert` does not fold the condition: specialization/simplification fold it to a bool literal, and the check reads, diagnoses and removes it ([static_assert as a decl needs a carrier IRFunc](../learnings/1790123003621-static-assert-as-a-decl-module-scope-conditions-ne.md)).

**The folding must happen in specialization, because `-minimum-slang-optimization` skips peephole.** On slang#13537, `_Texture`'s `typealias T = Texel.DataType` made HLSL `Sample`/`SampleLevel` fail with E41402 (not compile-time constant) only for `hlsl`/`dxil` at min-opt. `T` lowers to `lookup_witness_method`, which `specializeModule` resolves, but `maybeSpecializeInst` (slang-ir-specialize.cpp) had no `kIROp_TypeEquals` case, so the `T is float || …` chain folded only in peephole (~1810). Adding `case kIROp_TypeEquals:` to the `maybeSpecializeFoldableInst` group fixes it; test core-module `static_assert`s under min-opt. A trivial master merge can still break CI, so run master's new tests on the merged tree before pushing to an auto-merge PR. To bisect without rebuilding, run each PR head's `slang-tests-linux-x86_64-gcc-release` CI artifact (`Release/bin/slangc`, `LD_LIBRARY_PATH=Release/lib`) ([associated-type alias breaks static_assert at min-opt](../learnings/1792025326251-associated-type-alias-in-core-module-breaks-static.md)).

**Surviving linking also means escaping the check.** `checkStaticAssert` / `checkAndRemoveStaticAsserts` live in `linkAndOptimizeIR`, which runs only inside `for (auto targetReq : linkage->targets)`. With `-emit-ir` / `ContainerFormat::SlangModule` and no `-target` that list is empty, so `maybeCreateContainer` serializes the raw front-end IR and the carrier lands unchecked in the `.slang-module`; failure is deferred to the consumer's `import` + real-target codegen (HostVM/interpreter also skips it via an early return). For an emit-time check said to run "on every target", ask whether `slangc lib.slang -o lib.slang-module -emit-ir` runs it. A new **user-writable** `Decl` subclass needs both a `k_min`/`k_max` bump (positional `ASTNodeType` tags; precedent #13175) and a case in `classifyDeclForNesting` (`slang-check-decl.cpp`); an unclassified `Decl` takes `Unknown`, skipping nesting validation ([-emit-ir with no -target skips linkAndOptimizeIR](../learnings/1790140301023-slang-module-serialization-emit-ir-no-target-skips.md)).

## Order-Dependent Output: Link Symbol Choice, Dictionary Iteration, IR Set Order

**Conflicting link-time exports resolve silently by module order.** When two modules `export` the same link-time symbol (an `extern struct`, `static const`, or function) and a third declares it `extern`, linking succeeds silently. `isBetterForTarget` (`slang-ir-link.cpp:1294`) returns false on a full tie, so the selection loop (:1610-1615) keeps its current best, and `insertGlobalValueSymbol` (:1671-1701) keeps the first-inserted candidate at the head and splices later ones after it. Extern module first → the last export wins; exporters first → the first wins; don't say "last wins" (#13319). Traps for a conflict diagnostic: IR `[export]` is on every non-imported definition; `[hlslExport]` (the user `export` keyword) is also on sub-witness tables of exported types; enum witnesses share mangled names on purpose. slangc binds `-entry` to the file before it, so a permutation test keeps the extern module just before `-entry` ([IR-link conflicting exports pick silently](../learnings/1790691097788-ir-link-conflicting-exports-pick-silently-and-the-.md)).

**A tie can be TRUE both ways, and selection runs more than once per link** (E45002 export-conflict diagnostic, #13319/PR #13471). Two `__specialized_for_target(hlsl)` definitions compiled for hlsl make `CapabilitySet::isBetterForTarget` true in both directions (the `thisStageSet == shaderStageSetWeNeed` early return), so the loop replaces `bestVal` on every visit and the last visited wins; test a tie as `isBetterForTarget(a,b) == isBetterForTarget(b,a)`. Members of `export struct R : I {...}` have their own mangled symbols, so `R` can come from module A and `R.value()` from module B. A source TU and its own precompiled `.slang-module` reach `linkIR` as two IRModules with one Name. Use `standalone_note` for IR-level notes (a `variadic_note` with an invalid SourceLoc prints a stray `--- :0:0`). Census every tie (env-gated fprintf) across the suite before choosing a predicate: 186 ties ruled out three naive ones ([isBetterForTarget can return TRUE both ways](../learnings/1791333125522-slang-ir-linker-isbetterfortarget-can-return-true-.md)). `cloneInst`'s `kIROp_SymbolAlias` case clones the aliased value without `registerClonedValue` for the alias, and `linkIR`'s keep-alive loop (`cloneAndKeepAlive` over `getHLSLExports()`) clones every `export struct R : I = X;` alias, so selection re-runs for one mangled name and a per-symbol diagnostic needs a per-link dedupe set (`IRSharedSpecContext::reportedExportConflicts`). Two entry points share one IRSpecEnv, but a multi-target compile runs `linkIR` once per target, so the diagnostic repeats per target. ([a SymbolAlias re-runs selection](../learnings/1791352109049-slang-linker-a-symbolalias-re-runs-cloneglobalvalu.md)).

**Dictionary iteration order reaches output through pointer-keyed loops.** At master b9199bdaa, `Dictionary`/`HashSet` wrap `ankerl::unordered_dense`, which iterates in insertion order (erase swaps the last entry into the hole), so output is deterministic today. Plain loops whose order reaches output include `slang-ir-lower-dynamic-dispatch-insts.cpp:338` (`IRInst*`-keyed; dispatch switch-case order), `slang-serialize-source-loc.cpp:128` (`SourceFile*`-keyed; serialized `m_sourceInfos` bytes) and `slang-ir-link.cpp:1939` (int-keyed; atomic struct order). A hash-order map (e.g. `boost::unordered_flat_map`, #13309) would make pointer-keyed output vary between runs because ASLR moves addresses; byte-compare repeated runs, since FileCheck won't catch it. Master `getHashCode(const char*, len)` calls the private `unordered_dense::detail::wyhash::hash` (gone from Homebrew's build); PR #13293 uses public `hash<std::string_view>` ([Dictionary iteration order leaks into output](../learnings/1790673419809-slang-dictionary-iteration-order-leaks-into-output.md)).

**IR set order differs by host compiler.** `IRBuilder::getSet` (slang-ir.cpp ~7587) sorts with `getUniqueID(a) < getUniqueID(b)`, but `getUniqueID` assigns IDs lazily and C++ leaves the order of the two calls unspecified, so MSVC builds order sets differently from GCC/Clang. Set order drives dispatch order and the order of generated functions (e.g. AnyValue pack/unpack per conformer), so FileChecking two conformers' functions in one sequence can fail only on Windows. Give each conformer its own prefix (separate `//TEST:SIMPLE(filecheck=X)` runs). Reproduce on Linux by swapping the comparator's call order ([IR set order is host-compiler dependent](../learnings/1791336133684-slang-ir-set-order-is-host-compiler-dependent-lazy.md)).
