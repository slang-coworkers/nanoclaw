# Slang Serialization, Module Cache, Link/Output Order, and Enum/Sentinel Discipline

## TL;DR
- Record/replay is **fixed-schema per call**: **never conditionally skip `RECORD_OUTPUT`**; pass **interface-typed** pointers to `wrapObject`/`unwrapObject` (a concrete `T` is UB only UBSan catches). `ReplayContext` registries are non-owning, so replay leaks.
- Free miniz heap-archive buffers with `archive.m_pFree`, not `mz_free`. Retaining a big blob and decompressing it into private heap are separate decisions.
- The binary-module up-to-date check is **digest-based**, not mtime. #11918: cross-volume `getRelativePath` returned empty, so save wrote an empty dep (PR #11921).
- Keep `CountOf`/`Count`/`NUM_*` sentinels **implicit**, with textual order == value order; `static_assert(CountOf == Named + 1)` is no uniqueness guard.
- A destructor-time exception hits `std::terminate`; a typed `catch` across macOS hidden-visibility dylibs silently misses.
- An inline template's `__FILE__` names the header, not the data owner; a switch's `default: break;` admits every unlisted case.
- Prefer an existing decoration on a single-producer type over a new stable IR opcode; prove safety from the readers' argument types, not pass order.
- A new AST `FIDDLE()` field or AST class needs a `k_min` + `k_max` bump, else old modules segfault (E00130 after the bump); CI misses it, so test a cross-build `.slang-module` load both ways.
- An added optional IR operand or a changed inst meaning (branch on `IRModule::getVersion()`) is a **max-only** bump; operand-shape changes are byte-stable. Drill a gate by removing the operands it exists for; `git merge-tree` against open PRs claiming the same version.
- A module-scope `static_assert` needs a carrier `IRFunc` (`[export]` + `[keepAlive]`) and must fold in specialization (`-minimum-slang-optimization` skips peephole). `-emit-ir` without `-target` skips every emit-time check.
- Duplicate link-time exports link silently, the winner set by module order relative to the extern declarer (not "last wins"); ties can be TRUE both ways and selection re-runs per alias and target, so a conflict diagnostic needs a symmetric tie test and a per-link dedupe.
- `IRBuilder::getSet` order is host-compiler dependent (never FileCheck two conformers' functions in one sequence); `Dictionary` is insertion-ordered only via `unordered_dense` (byte-compare repeated runs).
- `SLANG_ASSERT` becomes `SLANG_ASSUME` under NDEBUG (a false assert in release is UB). Read an internals behaviour at a named ref before citing it.

## Record/Replay Layer

The stream in `source/slang-record-replay/` is fixed-schema per call even though each value carries a TypeId tag: playback's `executeNextCall` re-invokes the same call shape, so a conditionally skipped `RECORD_OUTPUT` desynchronizes every later call ([fixed-schema](../learnings/1782866674061-record-replay-stream-is-fixed-schema-at-the-call-l.md)).

**`wrapObject<T>` needs a COM interface `T`.** The template `T* wrapObject(T*)` (`replay-context.h`; QIs back via `T::getTypeGuid()`) beats the free `ISlangUnknown*` overload (`proxy-base.h`, the real `tryWrap`), so `wrapObject(new ReplayNullFileSystem())` deduces a concrete `T` and `toSlangInterface<ReplayNullFileSystem>` calls through a pointer of the wrong dynamic type. UBSan reports a bad-downcast (`replay-shared.h:105`) while Debug and all unit tests were green (PR #12863). Fix: `ISlangMutableFileSystem* standIn = new ReplayNullFileSystem(); desc.fileSystem = wrapObject(standIn);`. When a sanitizer job fails with local Debug green, suspect static-vs-dynamic-type UB; code a new test reaches first can hide several latent bugs ([COM T](../learnings/1788352568307-slang-record-replay-wrapobject-t-must-be-instantia.md)).

**The replay path leaks** (LSan direct leaks, #11936) because `ReplayContext` registries are raw/non-owning; DeepWiki calls them owning; check the source ([replay leaks](../learnings/1783073842766-slang-record-replay-the-replay-path-leaks-because-.md)).

## Archive Buffers: miniz Ownership and Decompression

A buffer from `mz_zip_writer_finalize_heap_archive(&archive, &buf, &size)` belongs to the archive's allocator: free it with `archive.m_pFree`, which can differ from global `mz_free` ([miniz](../learnings/1783064260282-miniz-heap-archive-buffers-are-owned-by-per-archiv.md)).

The ~41.5 MB session-lifetime core-module blob (slang#12530) must be retained (fossil lazy decode, `readSerializedModuleAST` and #12446 deferred IR bodies keep spans into it), but is a private-heap copy, not a view into `g_coreModule[]` `.rodata`, only because the archive ships compressed: `RiffFileSystem::loadFile` (`source/core/slang-riff-file-system.cpp`) with `m_compressionSystem` set decompresses into a full `ScopedAllocation`, while the uncompressed branch is zero-copy (`contents->addRef(); *outBlob = contents;`). A `malloc_history` rooted at `loadFile` proves it. Retention and decompression-on-load (binary size vs load RSS) are separate decisions; a lifetime-safe slice (`ScopeBlob::create(UnownedRawBlob::create(base+offset,len), parentBlob)`) belongs scoped to `loadArchive`, since `RiffFileSystem` is also the mutable `saveFile` path. Shipping uncompressed gets ~0 private heap for a bigger binary; measure first (depends on #12446/#12136) ([decompression](../learnings/1789649564786-a-retained-blob-s-cost-can-be-its-decompression-no.md)).

## Terminal Count/Sentinel Enums

In #11852, `CompilerOptionName::CountOf == SPIRVUnifiedDescriptorHeapStride == 154`. The fix restores textual order == value order and keeps the sentinel implicit, not pinned ([keep implicit](../learnings/1782859187073-terminal-count-sentinel-enums-prefer-keeping-them-.md)). It aliases again when a concurrent PR's renumber breaks textual order ([concurrent renumber](../learnings/1782853815255-implicit-countof-sentinel-aliases-an-option-when-a.md)), and `static_assert(CountOf == SomeNamedOption + 1)` checks adjacency to one enumerator, not uniqueness ([not a guard](../learnings/1782858072079-sentinel-static-assert-pinned-to-a-named-option-is.md)).

## Binary-Module Up-to-Date Check and #11918

The up-to-date check compares digests, not mtimes ([digest-based](../learnings/1783028515295-slang-binary-module-up-to-date-check-is-digest-bas.md)). The Windows-only #11918 cross-drive cache-miss reproducer ruled out "different directory" (a same-drive control HITs) and "source dir missing from search path" ([reproducer](../learnings/1783029316997-slang-11918-cross-drive-module-cache-miss-reproduc.md)). The cause is at SAVE: `Path::getRelativePath` (`std::filesystem::relative`) returns empty across volumes; `encodeModuleDependencyPaths` accepts a cross-volume `linkageRoot` (`hasRelativeElement("") == false`) and serializes the dep as an empty string that `isBinaryModuleUpToDate` cannot resolve. A clean consumer read had exonerated the load layer while its producer was the bug: trace producer → consumer, treating "save-side only" as a cue to inspect what the helper writes ([empty dep](../learnings/1783031868902-supersedes-prior-11918-correction-the-getrelativep.md)). PR #11921 falls back to the absolute path on an empty result; its exact-value asserts are `#if SLANG_WINDOWS_FAMILY`-gated, since only drive letters produce it ([resolved](../learnings/1783038802019-slang-11918-resolved-getrelativepath-returns-empty.md)).

## A Thrown Exception That Never Reaches Its `catch`

On macOS, hidden visibility duplicates RTTI and libc++abi matches exceptions by RTTI identity, so a typed `catch` of `Slang::Exception`/`InternalError` in another dylib silently misses ([macOS](../learnings/1783011716114-macos-hidden-visibility-breaks-cross-dylib-typed-c.md)).

The fossil deserializer had a second route to the same symptom (#13343, fixed by PR #13345): `Fossil::SerialReader` drained its deferred-action queue in its implicitly `noexcept` destructor (`slang-serialize-fossil.cpp` ~1213), so any exception in a deferred read (`SLANG_ASSERT`/`InternalError`, `SLANG_UNEXPECTED`, `SLANG_ABORT_COMPILATION`) called `std::terminate`: a stale `.slang-module` aborted with rc 134 (0xC0000409 on Windows). gdb shows `~SerialReader` → `_flush`; the PR moves the drain into an explicit outermost-only `flush()` at both construction sites (`readFossilizedDecl`, `readSerializedModuleIR_`). Pin a clean failure with `CHECK: result code = -1` (an in-process terminate kills slang-test itself) ([std::terminate](../learnings/1790783529890-slang-fossil-deserializer-an-exception-from-a-defe.md)).

## Reading a C++ Crash Path: `__FILE__` and `default:`

**An inline template's `__FILE__` names the header, not the data owner.** `src/metal/../core/short_vector.h:187` was read as "a metal TU indexed metal-owned data", but `short_vector::operator[]` is an inline template, so the prefix is just the instantiating TU's include path; one grep disproved it (`src/metal/` used neither of its two `short_vector`s and never includes `../core/`; must-hit control: that TU has 7 includes) ([__FILE__](../learnings/1786303967402-an-inline-template-s-file-names-the-header-so-a-cr.md)). **A switch's `default: break;` admits every case:** a claim that a call "fires exactly on `ConstantBuffer`/`ParameterBlock` cursors" (the two labels above it) made a guard a no-op, since the default arm runs it for every other kind; read the default arm before saying a switch restricts to its labels ([default arm](../learnings/1786304686679-a-switch-s-default-break-admits-every-case-reading.md)).

## IR Additions and Serialized-Module Compatibility

**Prefer an existing decoration over a new stable opcode.** slang#12875 first added `AnyValueMarshalCastDecoration` (new opcode, stable name, builder, version bump); the maintainer asked instead to attach the existing `IRAnyValueSizeDecoration` to the `AnyValueN` storage struct (produced only in `ensureAnyValueType()`) and gate on `as<IRStructType>` + that decoration, dropping all four. Prove safety by checking that no reader of the decoration ever passes the newly marked type: a pass-ordering argument was wrong here (`getInterfaceAnyValueSize` is called inside the marshalling file itself), while all four reader sites pass an interface type ([reuse](../learnings/1789475350340-prefer-reusing-an-existing-ir-decoration-over-a-ne.md)).

**An added optional operand is a max-only bump** (28→29, `k_min` unchanged; `docs/design/ir-instruction-definition.md` calls new optional operands minor, changed minimum counts/types major). Operand count is self-describing (`InstAllocInfo{IROp op; uint32_t operandCount}` per inst in `slang-serialize-ir.cpp`), so an old 1-operand `IRWitnessTable` reads as `operandCount==1`. Since #12905 (2026-09-17) the loader rejects a module outside `[k_min, k_max]` (`IRModule::isModuleVersionSupported` in `slang-session.cpp` and `slang-serialize-ir.cpp`, E00130 `unsupported-serialized-module-version`). Old modules stay in range, so guard the accessor on count (`getOperandCount() > 1 ? getOperand(1) : nullptr`) and null-guard every call site; the repo has no old-module → new-reader load test. `IRInstKey` compares operand counts, so legacy 1-operand and new 2-operand tables for one conformance do not GVN-merge; flag it ([operand](../learnings/1789476647852-slang-ir-module-version-bump-for-an-additive-optio.md)).

**A new AST `FIDDLE()` field is a min+max bump.** The AST serializer lays out fields by position (base-class fields first), so a new field shifts that class and every subclass (`Attribute::floatArgVals` in #13953 shifts every builtin attribute), and the field-count check is only a `SLANG_ASSERT`: a base-built `.slang-module` segfaulted the PR's compiler (rc=139) under `-reflection-json` and `import m`. Bump `IRModule::k_minSupportedModuleVersion` and `k_maxSupportedModuleVersion` in `source/slang/slang-ir.h` (precedent #13756, to 37); the old module then fails cleanly with E00130 (`unit-test-module-version.cpp` compares the constants symbolically, so it still passes). Check: build `slangc m.slang -o m.slang-module` with base, move `m.slang` away, load it with head [FIDDLE field](../learnings/1793002822043-adding-a-fiddle-field-to-an-ast-node-needs-a-modul.md) [E00130](../learnings/1793009488997-slang-checker-fold-quietly-with-a-scratch-sink-coe.md). A `List<std::optional<T>>` field also needs a `dump(const std::optional<T>&)` overload in `slang-ast-dump.cpp`; clone and serialization handle it [ast-dump](../learnings/1793000621319-slang-front-end-float-folding-for-user-attribute-a.md).

**A new AST class is a min+max bump too, and CI does not catch a missing one.** `ASTNodeType` numbers every `NodeBase` subclass in pre-order and is stored in serialized modules (`Fossilized<ASTNodeType>` in `slang-serialize-ast.cpp`), so inserting any class (even an internal attribute such as #13975's `ConstantFoldAsAttribute`) renumbers the tags. Without a bump, cross-loading master and PR modules segfaulted (rc 139) in both directions (precedent #13406, 36→37); `extras/check-inst-version-changes.sh` tracks only IR insts. Check with two Release builds: compile a tiny public `module m;` with X, move `m.slang` away, `import m;` from `slangi main.slang` with Y (control: two masters differing in no `slang-ast-*.h` load each other's modules). After the bump an old module gets `warning[E00131]: ignoring IR module version 37…` and the loader falls back to source [any AST class](../learnings/1793210446543-adding-any-ast-class-requires-a-module-version-bum.md).

**Changing an IR instruction's meaning, and drilling the gate.** Per `docs/design/backwards-compat-for-ir-modules.md`, bump `k_max` only and branch on `IRModule::getVersion()`; test the legacy path by rewriting a serialized blob's version, as `irBlobRejectsVersion36` in `unit-test-ir-blob.cpp` does (the file is CRLF; preserve with `newline=''` in Python) [legacy test](../learnings/1793220067281-slang-linker-a-module-s-debugsource-list-includes-.md). On #13992, `DebugCompilationUnit` gained variadic `includedSources` operands (bump to 38, v37 fallback) whose only job is #7203's "list a header with no line rows"; an empty operand list still passed all 277 `-g` tests (#7203 had no test; every include test reaches its header via `DebugLine`). When a PR adds IR operands only to keep records alive through linking, drill by removing them: the guarding test needs a macro-only header, in the entry file and in a used imported module. Load a real v37 module from the base compiler (`slangc -g2 -o X.slang-module`) into head with `-r`. Before approving a bump, run `git merge-tree --write-tree` against other open PRs that bump it (that day 4 PRs claimed 38) [drill](../learnings/1793223587899-slang-module-version-gate-drill-the-ir-operand-tha.md). The linker side of #13992 is on [[wiki/concepts/slang-backends-spirv-debug-info-emission.md]].

**Changing operand shape is byte-stable** (value operand → type operand, reorder): no major bump, no stable-name rename. `slang-ir-insts-stable-names.lua` freezes only opcode ↔ integer (e.g. TypeEquals=582); operands serialize positionally, and the `"value"`/`"type"` names in `slang-ir-insts.lua` are unserialized accessor sugar (`slang-serialize-ir.cpp:314-332`). For legacy modules whose op references a value inst, keep consumers dual-tolerant (peephole `getTypeFromOperand` accepts either) or add an IR upgrade (this refuted a DeepWiki "must major-bump" answer) ([byte-stable](../learnings/1789601900070-ir-operand-shape-migration-is-byte-stable-stable-n.md)).

## `static_assert` as a Declaration (#13229) and Where It Is Checked

A `static_assert` at global/namespace/aggregate scope (#13229 / #6136) has no active IR block, so emitting its condition under the module inst is malformed: a condition needing inlining or `||`/`&&` control flow aborts (`SLANG_ASSERT(as<IRBlock>(callerBlock))`, `slang-ir-inline.cpp:767`), while simple `sizeof`/arithmetic conditions hide the bug. The fix synthesizes a `void()` **carrier `IRFunc`** (condition + message + assert) kept through linking by `[export]` (`linkIR` clones it as a root) and `[keepAlive]` (blocks DCE), as at `slang-lower-to-ir.cpp:14117`; `slang-emit.cpp` deletes the emptied carrier after the check, or `void s_N(){}` leaks into `-target cpp`. A new IR decoration needs an explicit `slang-ir-insts-stable-names.lua` entry (else fiddle fails with an opaque internal error, as a duplicate diagnostic code also does), and a stateless one must join `isSimpleDecoration`. `checkStaticAssert` does not fold: specialization/simplification produce a bool literal that the check reads, diagnoses and removes ([carrier IRFunc](../learnings/1790123003621-static-assert-as-a-decl-module-scope-conditions-ne.md)).

**The folding must happen in specialization, because `-minimum-slang-optimization` skips peephole.** On slang#13537, `_Texture`'s `typealias T = Texel.DataType` made HLSL `Sample`/`SampleLevel` fail E41402 (not compile-time constant) only for `hlsl`/`dxil` at min-opt: `T` lowers to `lookup_witness_method` (resolved by `specializeModule`), but `maybeSpecializeInst` (slang-ir-specialize.cpp) had no `kIROp_TypeEquals` case, so the `T is float || …` chain folded only in peephole (~1810). Adding `case kIROp_TypeEquals:` to the `maybeSpecializeFoldableInst` group fixes it; test core-module `static_assert`s under min-opt. A trivial master merge can still break CI: run master's new tests on the merged tree before pushing to an auto-merge PR. To bisect without rebuilding, run each PR head's `slang-tests-linux-x86_64-gcc-release` CI artifact (`Release/bin/slangc`, `LD_LIBRARY_PATH=Release/lib`) ([min-opt fold](../learnings/1792025326251-associated-type-alias-in-core-module-breaks-static.md)).

**Surviving linking also means escaping the check.** `checkStaticAssert` / `checkAndRemoveStaticAsserts` live in `linkAndOptimizeIR`, which runs only inside `for (auto targetReq : linkage->targets)`. With `-emit-ir` / `ContainerFormat::SlangModule` and no `-target` the list is empty, so `maybeCreateContainer` serializes raw front-end IR with the carrier unchecked; failure waits for the consumer's `import` + real-target codegen (HostVM/interpreter also skips it via an early return). For a check said to run "on every target", ask whether `slangc lib.slang -o lib.slang-module -emit-ir` runs it. A new **user-writable** `Decl` subclass needs a `k_min`/`k_max` bump (positional `ASTNodeType` tags; precedent #13175) and a case in `classifyDeclForNesting` (`slang-check-decl.cpp`); an unclassified `Decl` takes `Unknown`, skipping nesting validation ([-emit-ir](../learnings/1790140301023-slang-module-serialization-emit-ir-no-target-skips.md)).

## Order-Dependent Output: Link Choice, Dictionary, IR Sets

**Conflicting link-time exports resolve silently by module order.** If two modules `export` one link-time symbol (`extern struct`, `static const`, function) that a third declares `extern`, linking succeeds silently: `isBetterForTarget` (`slang-ir-link.cpp:1294`) returns false on a full tie, the selection loop (:1610-1615) keeps its current best, and `insertGlobalValueSymbol` (:1671-1701) keeps the first-inserted candidate at the head. Extern module first → the last export wins; exporters first → the first wins (#13319). Conflict-diagnostic traps: IR `[export]` is on every non-imported definition; `[hlslExport]` (the user `export` keyword) is also on sub-witness tables of exported types; enum witnesses share mangled names on purpose. slangc binds `-entry` to the file before it, so a permutation test keeps the extern module just before `-entry` ([silent pick](../learnings/1790691097788-ir-link-conflicting-exports-pick-silently-and-the-.md)).

**A tie can be TRUE both ways, and selection runs more than once per link** (E45002 export-conflict diagnostic, #13319/PR #13471). Two `__specialized_for_target(hlsl)` definitions compiled for hlsl make `CapabilitySet::isBetterForTarget` true both ways (its `thisStageSet == shaderStageSetWeNeed` early return), so the last visited wins; test a tie as `isBetterForTarget(a,b) == isBetterForTarget(b,a)`, and census every tie (env-gated fprintf) across the suite before choosing a predicate (186 ties ruled out three naive ones). Members of `export struct R : I {...}` have their own mangled symbols (`R` can come from module A, `R.value()` from B), and a source TU plus its own precompiled `.slang-module` reach `linkIR` as two IRModules with one Name. Use `standalone_note` for IR-level notes (a `variadic_note` with an invalid SourceLoc prints a stray `--- :0:0`) ([TRUE both ways](../learnings/1791333125522-slang-ir-linker-isbetterfortarget-can-return-true-.md)). `cloneInst`'s `kIROp_SymbolAlias` case clones the aliased value but skips `registerClonedValue` for the alias, and `linkIR`'s keep-alive loop (`cloneAndKeepAlive` over `getHLSLExports()`) clones every `export struct R : I = X;` alias, so selection re-runs for one mangled name: a per-symbol diagnostic needs a per-link dedupe set (`IRSharedSpecContext::reportedExportConflicts`). Two entry points share one IRSpecEnv, but a multi-target compile runs `linkIR` once per target, so it repeats per target ([SymbolAlias](../learnings/1791352109049-slang-linker-a-symbolalias-re-runs-cloneglobalvalu.md)).

**Dictionary iteration order reaches output through pointer-keyed loops.** At master b9199bdaa, `Dictionary`/`HashSet` wrap `ankerl::unordered_dense`, which iterates in insertion order, so output is deterministic today. Loops whose order reaches output: `slang-ir-lower-dynamic-dispatch-insts.cpp:338` (`IRInst*`-keyed; dispatch switch-case order), `slang-serialize-source-loc.cpp:128` (`SourceFile*`-keyed; serialized `m_sourceInfos` bytes) and `slang-ir-link.cpp:1939` (int-keyed; atomic struct order). A hash-order map (e.g. `boost::unordered_flat_map`, #13309) would make pointer-keyed output vary run to run (ASLR); byte-compare repeated runs, since FileCheck won't catch it. Master `getHashCode(const char*, len)` calls the private `unordered_dense::detail::wyhash::hash` (gone from Homebrew's build); PR #13293 uses public `hash<std::string_view>` ([Dictionary](../learnings/1790673419809-slang-dictionary-iteration-order-leaks-into-output.md)).

**IR set order differs by host compiler.** `IRBuilder::getSet` (slang-ir.cpp ~7587) sorts with `getUniqueID(a) < getUniqueID(b)`, but `getUniqueID` assigns IDs lazily and C++ leaves the two calls' order unspecified, so MSVC orders sets differently from GCC/Clang. Set order drives dispatch and generated-function order (e.g. AnyValue pack/unpack per conformer), so FileChecking two conformers' functions in one sequence fails only on Windows; give each its own prefix (separate `//TEST:SIMPLE(filecheck=X)` runs). Reproduce on Linux by swapping the comparator's call order ([set order](../learnings/1791336133684-slang-ir-set-order-is-host-compiler-dependent-lazy.md)).
