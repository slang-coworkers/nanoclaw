# PR Review Practices (part 6)

> **This page is part 6 of 9** of the PR Review Practices synthesis (split 2026-08-06 to stay under the 40 KB read cap). Siblings: [part 1](review-pr-practices.md), [part 2](review-pr-practices-2.md), [part 3](review-pr-practices-3.md), [part 4](review-pr-practices-4.md), [part 5](review-pr-practices-5.md), [part 7](review-pr-practices-7.md), [part 8](review-pr-practices-8.md), [part 9](review-pr-practices-9.md). ## TL;DR
- **Every reviewer fails toward CLEAN.** Devin exit 0 is not a signal; Reviewer A can emit a 0-byte or budget-capped output; Reviewer C can skip environmentally. **Verify each reviewer produced findings before treating "no findings" as a result** — an absent reviewer and a clean reviewer are byte-identical downstream.
- **Watch the ARTIFACT, not the subagent.** A Devin subagent returns before `devin-fetch.sh` finishes; a detached reviewer's completion is proven by its exit marker, never by streamed JSON. Anchor monitors to exit markers.
- **Read the full page dump, not the summary file.** `devin-flags.md` can have an EMPTY `## Flags` section while `devin-page.txt` from the same run shows real findings — synthesizing from the summary records a false "0 findings" and carries a false-clean prior into the challenger.
- **Reviewer A needs an isolated checkout.** Fleet contention on a shared repo root corrupts runs; `$30` is too low a budget cap and produces silent truncation. Use fresh per-run out-dirs to avoid `/tmp` collisions.
- **Two bots agreeing measures shared priors, not correctness.** Independent bots flagging the same item is weak corroboration; read the human review thread before scoring any structure/maintainability gap.
- **A bot finding a named maintainer already overruled ON THIS PR is not an open gap** — but **lead with the technical grounds**, never the maintainer's preference. Maintainer preference is supporting context; a repo guideline is not cleared by taste alone.
- **A refuted 🔴 does not become WOULD_APPROVE**, and a standing human `CHANGES_REQUESTED` caps the verdict at ABSTAIN. Never round up.
- **A mid-iteration `diff_hash` mismatch is expected under debounce**, not a bug. Pin the head, byte-prove reviews against it, and re-verify a stale secondary reviewer's flags at the current head.
- **Re-review scope: redesign gaps and self-recommended nits do not reset the pipeline.** Additive nit rounds are fine; a full re-run is not.
- **The review signal is endpoint-split across three surfaces** (`pulls/N/reviews`, `pulls/N/comments`, `issues/N/comments`) and the harvest reads one. That split is a property of GitHub's data model, so **every consumer inherits the blind spot independently — fixing one instance is not fixing the class.**
- **A GitHub post gates on the literal marker, not on prose.** Post only in COMMENT state; never APPROVE/REQUEST_CHANGES from a runner.
- **Empirical probes can test the wrong sub-case.** A probe that varies the intended factor while holding the confound constant reads as decisive and proves nothing — name the factor and the confound before citing a control.
- **In an artifact where claims cite `file:line`, the UNCITED SENTENCE IS THE DEFECT** — in a document whose norm is citation, the citation outlier is where an inference got restated as an observation. Run that self-check mechanically over your own draft.
- **Recording is not routing.** Documenting a blocking infra defect any number of times never reaches a file only an operator can edit. The record serves the next agent; the escalation serves the fix — do both.
- **A stale webhook dispatch on an already-decided PR is a no-op plus a report, never a re-decision.** `record_decision` is idempotent per `(repo, pr, sha)`, so re-deciding CLOBBERS a human-joined calibration row with a verdict contaminated by post-hoc information.

## Approver Decision Workflow: Head-Pinning, Tiers, and Calibration (2026-07-14 fold)

This section consolidates a large batch of PR-approver operational lessons. The approver runs in shadow mode (posts nothing to GitHub), so the eventual human merge becomes calibration data against the recorded ledger verdict.

**Pin the settled head, then re-pin it — twice.** The single most recurring failure is deciding against a stale commit. On a fresh, actively-iterated PR the opening commit's diff is a poor predictor of the settled diff — a clean single-file fix grew into a `.github/**` protected-path edit within ~20 min, flipping WOULD_APPROVE to ABSTAIN_POLICY ([[approver/clause-gap] Debounced settled head can expand scope into a protected path — never decide on the opening commit](wiki/learnings/1783927363514-approver-clause-gap-debounced-settled-head-can-exp.md)). The debounce window must outlast the burst; a 90-second poll desyncs the pinned SHA from live-head Devin/`gh pr diff` ([[approver/critique-mustfix] Debounce window must outlast the burst — a too-short window desyncs the pinned SHA from live-head Devin/gh pr diff](wiki/learnings/1783960363272-approver-critique-mustfix-debounce-window-must-out.md)), and the head must be re-pinned *after* the slow harvest/Devin phase, not just at debounce start ([[approver/critique-mustfix] Re-pin head AFTER slow harvest/Devin, not just at debounce start](wiki/learnings/1783930401148-approver-critique-mustfix-re-pin-head-after-slow-h.md)). A sustained force-push burst (6 heads in ~85 min) starves every head-current decision — after a hard bound that is correctly ABSTAIN_INFRA, not an endless chase ([[approver/infra-abstain] Sustained force-push burst starves head-current decisions → ABSTAIN_INFRA](wiki/learnings/1783958614926-approver-infra-abstain-sustained-force-push-burst-.md)). On a synchronize you already decided, classify the delta cheaply with `gh api compare/<last_approved>...<new_head>` and a `gh pr diff | sha256sum` match rather than re-deriving ([Reviewing a PR whose head keeps moving (synchronize/merge churn)](wiki/learnings/1784006371550-reviewing-a-pr-whose-head-keeps-moving-synchronize.md), [[approver/clause-gap] Re-decide a synchronize by diffing head vs your LAST-APPROVED SHA (gh api compare) — and pre-existing exemption covers factual (not just cosmetic) findings the PR didn't touch](wiki/learnings/1783970228393-approver-clause-gap-re-decide-a-synchronize-by-dif.md)); for a master-merge-only branch, pin the PR-diff hash and re-verify structural claims when the base moves ([[approver/human-agreement] master-merge churn: pin the PR-diff hash, re-verify structural claims when the base moves, treat pipeline-incompleteness as an explicit judgment](wiki/learnings/1784008035954-approver-human-agreement-master-merge-churn-pin-th.md)).

**Reading the review tiers — harvest exit codes and the late-post race.** harvest exit 20 means "no bot review AND no bot still working" — it does NOT license asserting a *cause* ("production skips X"); encoding an unevidenced causal claim is an OUTPUT_REVIEW must-fix ([[approver/critique-mustfix] Don't assert a CAUSE for harvest exit 20 — it means "no review + no pending bot", not "production skips X"](wiki/learnings/1783961748935-approver-critique-mustfix-don-t-assert-a-cause-for.md)), and it is the "absent bot review is not an abstain" Devin-only skip-class ([[approver/human-disagreement] confirmed agreement — Devin-only WOULD_APPROVE matched human APPROVE on bot-authored test-only PR](wiki/learnings/1783963594230-approver-human-disagreement-confirmed-agreement-de.md)). harvest exit 10 (stale-only) can hide an in-flight bot re-review — check the commit-status API before falling to Devin ([[approver/clause-gap] harvest exit 10 (stale-only) can hide an in-flight bot re-review on a synchronize](wiki/learnings/1783949042869-approver-clause-gap-harvest-exit-10-stale-only-can.md)); a stale-but-recent bot review on a prior head is weak as a verdict source but strong corroboration ([[approver/challenger-miss] On a live multi-revision PR, a production bot review that lands on a PRIOR head is stale-as-verdict-source but strong corroboration — harvest still surfaces it, use it as an independent agreement signal](wiki/learnings/1783959025798-approver-challenger-miss-on-a-live-multi-revision-.md)). The dominant timing hazard is the late-post race: a slow production review can post seconds-to-minutes after your harvest window closes, so re-harvest again right before `record_decision`, and treat a "hung" in-progress review as merely slow ([[approver/critique-mustfix] Re-harvest AGAIN right before record_decision — slow prod reviews post seconds after your window](wiki/learnings/1783962571176-approver-critique-mustfix-re-harvest-again-right-b.md), [[approver/critique-mustfix] A "hung" production review may just be slow — re-harvest before falling to Devin-only](wiki/learnings/1783958635135-approver-critique-mustfix-a-hung-production-review.md), [[approver/clause-gap] Harvest timing-race on fresh reviewable PRs — re-harvest at the settled head, never freeze the first-second result](wiki/learnings/1783957917061-approver-clause-gap-harvest-timing-race-on-fresh-r.md), [[approver/infra-abstain] Confirmed: wait out the IN_PROGRESS production review before Devin-only; and debounce a head that moves mid-decision](wiki/learnings/1783935971762-approver-infra-abstain-confirmed-wait-out-the-in-p.md)). A human APPROVE can likewise race in during harvest/Devin — re-check reviews before finalizing `mode` (live vs live_late) ([[approver/clause-gap] re-check PR reviews before finalizing mode — a human APPROVE can race in during harvest/Devin](wiki/learnings/1783963597891-approver-clause-gap-re-check-pr-reviews-before-fin.md)).

**Devin as challenger — infra timeouts, exec bits, false positives.** A first-attempt Devin timeout is not proof of unavailability; the head-started session frequently completes clean on a re-poll, so retry once before NO_REVIEW_SIGNAL/ABSTAIN_INFRA ([[approver/infra-abstain] Devin-only tier: retry a timed-out Devin before NO_REVIEW_SIGNAL abstain](wiki/learnings/1783946313392-approver-infra-abstain-devin-only-tier-retry-a-tim.md), [[approver/infra-abstain] Devin-only tier: retry a timed-out Devin before ABSTAIN_INFRA](wiki/learnings/1783993723797-approver-infra-abstain-devin-only-tier-retry-a-tim.md), [[approver/infra-abstain] Devin timeout (exit 3) on a just-opened PR: re-poll once before ABSTAIN_INFRA — the head-started session often completes clean](wiki/learnings/1783961759956-approver-infra-abstain-devin-timeout-exit-3-on-a-j.md)). `devin-fetch.sh` ships without its exec bit in approver containers, so a by-path call dies exit 126 (a false Devin-skip) — always invoke via `bash devin-fetch.sh` ([approver devin-fetch.sh missing exec bit false-skips Devin](wiki/learnings/1783997801258-approver-devin-fetch-sh-missing-exec-bit-false-ski.md), [[approver/infra] devin-fetch.sh needs bash prefix + tolerate first-run timeout](wiki/learnings/1783949034225-approver-infra-devin-fetch-sh-needs-bash-prefix-to.md), [[approver/ops] Invoke approver scripts via python3/bash; use gh graphql (not gh api pulls) for read-only fetches](wiki/learnings/1783960724921-approver-ops-invoke-approver-scripts-via-python3-b.md)), and never wrap it in an outer `timeout` shorter than its own `--max-minutes` deadline ([[approver/infra-abstain] devin-fetch.sh: never wrap in an outer `timeout` shorter than its --max-minutes — bound it with the flag](wiki/learnings/1783934997171-approver-infra-abstain-devin-fetch-sh-never-wrap-i.md)). Devin false-positive classes to challenge, not defer to: cross-platform filename bugs on tutorial run-scripts ([[approver/challenger-miss] Devin cross-platform filename bugs on tutorial run-scripts are often false positives — verify the tool's actual naming convention in source](wiki/learnings/1783935960085-approver-challenger-miss-devin-cross-platform-file.md)) and narrative that merely echoes the PR description while citing superseded locations ([[approver/challenger-miss] Devin narrative echoes PR description and cites superseded locations — do not treat as coverage](wiki/learnings/1783957900263-approver-challenger-miss-devin-narrative-echoes-pr.md)). Conversely, a still-present false claim the current revision didn't re-list is still a live gap ([[approver/challenger-miss] A still-present false claim the current revision's review didn't re-list is still a live gap — challenger re-checks carried-over diff content, doesn't defer to "not re-flagged"](wiki/learnings/1783937211976-approver-challenger-miss-a-still-present-false-cla.md)).

**Drawing the abstain lines.** A terminal Step-1 clause FAIL dominates a co-occurring UNEVALUABLE and no-review-signal — record ABSTAIN_POLICY, not ABSTAIN_INFRA ([[approver/clause-gap] Terminal Step-1 clause FAIL dominates a co-occurring UNEVALUABLE and no-review-signal — record ABSTAIN_POLICY, not ABSTAIN_INFRA](wiki/learnings/1783932935934-approver-clause-gap-terminal-step-1-clause-fail-do.md)). Protected-path (`.github/**`) ABSTAIN_POLICY is well-calibrated even for trivial CI runner-pins — these changes reliably draw real multi-round human review ([[approver/calibration] Protected-path ABSTAIN_POLICY on trivial CI runner-pins is correctly drawn — merged unchanged](wiki/learnings/1783942538159-approver-calibration-protected-path-abstain-policy.md), [[approver/human-disagreement] Confirmed: protected-path (.github/**) ABSTAIN_POLICY is well-calibrated — these changes draw real, multi-round human review](wiki/learnings/1783949231509-approver-human-disagreement-confirmed-protected-pa.md), [[approver/human-disagreement] Small release-packaging PRs touching .github/**: ABSTAIN_POLICY confirmed correct; CodeRabbit "Major" packaging-robustness nits are non-blocking 🟡, not 🔴](wiki/learnings/1783964691555-approver-human-disagreement-small-release-packagin.md)); when the protected-path edit is structural/invariant across revisions the ABSTAIN is deterministic — do NOT re-run every synchronize ([Deterministic-ABSTAIN PRs — stop re-running on churn](wiki/learnings/1783972579606-deterministic-abstain-prs-stop-re-running-on-churn.md)). The size-cap ABSTAIN (`tier_eligible`) is confirmed correct: a ~6700-line PR self-merged past unresolved CodeRabbit Major findings ([[approver/calibration] Large author-authored PR self-merged past unresolved static-analysis Major findings — size-cap ABSTAIN confirmed correct](wiki/learnings/1783962279436-approver-calibration-large-author-authored-pr-self.md)). On a reformatting PR, base-diff a flagged 🟡 before treating it as an OPEN_GAP — pre-existing artifacts the PR only re-whitespaces do not block ([[approver/clause-gap] On a reformatting PR, always base-diff a flagged 🟡 before treating it as an OPEN_GAP — pre-existing artifacts the PR only re-whitespaces do not block](wiki/learnings/1783960153742-approver-clause-gap-on-a-reformatting-pr-always-ba.md)).

**Clearing the critique gate.** The gate only records a round when the codex call uses the exact `/codex-critique` format ([[approver/critique-mustfix] Critique gate only records a round when the codex call uses the exact /codex-critique format — freeform codex calls don't count toward delivery](wiki/learnings/1783939165247-approver-critique-mustfix-critique-gate-only-recor.md)), and DECISION_REVIEW / OUTPUT_REVIEW must be *separate* calls (the tracker keys each round to the first stage token; use `reason_code=CLEAN` for WOULD_APPROVE) ([[approver/critique-mustfix] OUTPUT_REVIEW must be its own codex call; reason_code=CLEAN for WOULD_APPROVE](wiki/learnings/1783978376082-approver-critique-mustfix-output-review-must-be-it.md)). Per-revision `[Approval Decision]` delivery to the dashboard is mandatory and distinct from the materiality-gated upstream `[Report]` ([[approver/critique-mustfix] Per-revision [Approval Decision] delivery is mandatory (dashboard) — distinct from the materiality-gated upstream [Report]](wiki/learnings/1783958368120-approver-critique-mustfix-per-revision-approval-de.md)). Ops: invoke approver scripts via `python3`/`bash` and use `gh graphql` (not `gh api pulls`, which the critique gate denies) for read-only fetches ([[approver/ops] Invoke approver scripts via python3/bash; use gh graphql (not gh api pulls) for read-only fetches](wiki/learnings/1783960724921-approver-ops-invoke-approver-scripts-via-python3-b.md)).

**Session-teardown fragility.** Approver and the reviewer runs it consumes are session-teardown-fragile — a synchronize burst can cost whole review rounds, and a PR can merge undecided while the reviewer doc never returns; verify the run survived before trusting output ([approver: reviewer runs are session-teardown-fragile — a synchronize burst can cost whole review rounds (R3 of slang#12023 died with no doc)](wiki/learnings/1783969636640-approver-reviewer-runs-are-session-teardown-fragil.md), [[approver/infra-abstain] PR merged undecided while reviewer doc never returned (slang#12060)](wiki/learnings/1783964822172-approver-infra-abstain-pr-merged-undecided-while-r.md)).

**Calibration — the human-outcome join.** Confirmed-safe classes: purely-additive `calcRequiredLoweringPassSet` "gate = pass handled-set" lowering fixes (the #11917 epic — a stale-false gate reduces to a producer-vs-governing-scan check, skip predicate must be a safe superset of every mutation site) ([[approver/human-agreement] Purely-additive "gate = pass handled-set" lowering fixes ship unchanged](wiki/learnings/1783957287484-approver-human-agreement-purely-additive-gate-pass.md), [[approver/human-agreement] RequiredLoweringPassSet gates: stale-false reduces to a producer-vs-governing-scan check](wiki/learnings/1784006091575-approver-human-agreement-requiredloweringpassset-g.md), [[approver/challenger-miss] #11917 pass-gating early-outs: verify the skip predicate is a safe superset of every mutation site, and that any scan blind-spot is matched by the pass's own bail](wiki/learnings/1783997718788-approver-challenger-miss-11917-pass-gating-early-o.md)); bot-authored test-only PRs on the Devin-only tier merged unchanged ([[approver/human-disagreement] confirmed-at-merge — slang#12081 merged unchanged, zero follow-up commits after WOULD_APPROVE](wiki/learnings/1783972123031-approver-human-disagreement-confirmed-at-merge-sla.md)); and mid-cycle ABSTAINs that defer to a maintainer who then APPROVES the exact decision commit ([[approver/calibration] Confirmed-correct ABSTAIN: deferred to a mid-cycle maintainer who then APPROVED the exact decision commit (#12065)](wiki/learnings/1783960819826-approver-calibration-confirmed-correct-abstain-def.md)).

**Operator ruling (contradiction).** An earlier learning (slang#12060, PR merged undecided while the reviewer doc never returned) recommended escalating on the 1st silent reping. The operator **overruled** this (2026-07-13): it would fire on every fast maintainer self-merge, a normal healthy pattern — the reviewer-doc-never-returned failure is real but the fix is NOT reping-escalation ([[approver/clause-gap] Operator ruling: do NOT escalate on 1st silent reping (fast self-merge is acceptable, not a gap to close)](wiki/learnings/1783965620899-approver-clause-gap-operator-ruling-do-not-escalat.md)).


## Reviewer-Run Survival: Session Teardown and the 600s Background-Wait Ceiling (2026-07-14 fold)

`compose-and-run.sh`/`run-clarity.sh` launched with `run_in_background` are killed at session teardown, arriving as `status: stopped` with a possibly-deleted run_dir — indistinguishable from a "0 findings" verdict; always verify the run survived AND cleared its permission guard before trusting output ([slang-pr-review: verify reviewer runs survived + cleared the guard](wiki/learnings/1783971373048-slang-pr-review-verify-reviewer-runs-survived-clea.md)). Reviewer A additionally has a **600s background-wait ceiling** in the inner `claude --print` CLI that kills the six subagents before `final-review.md` is written (`REVIEW-GUARD FAIL: final review is <500 bytes`) — this is an infra timeout, not a 0-findings result; recover the analysis from `stream.jsonl` rather than reporting empty ([Reviewer A 600s bg-wait ceiling truncates final-review.md](wiki/learnings/1783983883017-slang-pr-review-reviewer-a-600s-bg-wait-ceiling-tr.md)).
