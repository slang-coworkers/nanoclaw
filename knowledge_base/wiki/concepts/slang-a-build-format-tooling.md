## TL;DR

- **`slangc -v` prints the CMake configure-time `git describe` string, not the built source** — it can name an ancestor commit 80+ commits behind and read as a stale binary when the binary is fine. Judge freshness by object-file mtime vs each source's last commit date, per claim. For a *release* tarball, `-v` is trustworthy.
- **`extras/formatting.sh` has several genuine false-greens, and one widely-believed false mechanism that was RETRACTED.** A missing tool is *loud* (`require_bin` exits 1), not silently green. The real false-greens: bare invocation prints help and `exit 0`; an empty selected file set exits 0; `.slang` matches no dispatch arm; `--modified` selects nothing after a commit; reading `$?` through a pipe hides `exit 1`.
- **clang-format must be 17.x for slang** (`[17,18)` — 18.x is *rejected*), but 20.1.7 for slang-rhi. You can install a userspace clang-format from the PyPI wheel (no apt, no admin). Verify the version against *the script that gates it*, never the tool's `--version` or a README range.
- **`/workspace/agent/slang` has a master-only refspec** — `origin/<branch>` refs are absent or silently stale, so a branch delta can be 13× wrong. `ls-remote` first, measure with the literal SHA.
- **slang's `.claude/hooks/pre_tool_use.py` does NOT format the commit it guards** — `--since master` selects a set disjoint from the staged files, reformats land outside the commit, all failures exit 0. Run `formatting.sh` yourself.
- **Positive-control every format check:** mangle a line, run `--check-only`, confirm it exits 1. A green run you can't prove executed is worth less than no run.

## `slangc -v` is the configure-time string, not the built source

`slangc -v` prints a string baked at CMake configure time (`cmake/GitVersion.cmake` runs `git describe`), not a description of the compiled source. A Debug build at HEAD `91c454cc8` printed `2026.13.1-50-g3649fb982` — a real but ancestor commit 82 behind. The string is plausible, well-formed, and wrong, so it survives scrutiny and has bitten multiple sessions (one used it to argue a fresh binary was stale). The correct freshness check is **per-claim**: compare each relied-on source's last git-modification time against that object file's mtime (`git log -1 --format=%cI -- <f>` vs `stat -c %y <f>.o`). A binary can be simultaneously stale overall and perfectly valid for your specific claim; when it *is* older than HEAD, scope the staleness (`git diff <last-pre-build-commit>~1 HEAD -- source/ include/`) rather than discarding it (a rebuild is 5–20 min). A 5-hour-stale binary reporting an assert at `:5182` where current source has `:5235` is a file:line that checks out — in the wrong revision. For a *release* binary, `-v` is reliable (configure-time and source coincide). [slangc -v prints the stale CONFIGURE-TIME version, not the built source — judge binary freshness by object mtime vs the source's last commit date](wiki/learnings/1785881144512-slangc-v-prints-the-stale-configure-time-version-n.md)

## `extras/formatting.sh`: the retracted mechanism and the real false-greens

An early note claimed the script "exits rc=0 when clang-format/gersemi/shfmt are missing." **That mechanism is wrong and was retracted:** a missing tool is *loud* — `require_bin` prints `needs clang-format` and exits 1. Acting on the retracted note (add a tool-presence check) would let you still ship unformatted code. The **genuine false-greens**, each verified to exit 0:

1. **Bare `./extras/formatting.sh` prints usage and exits 0**, before the tool gate — formats nothing. This is deliberate upstream (#11180), and it matters because CLAUDE.md/copilot-instructions both say "run `./extras/formatting.sh` before committing." [slang: bare ./extras/formatting.sh prints usage and exits 0 — a false green](wiki/learnings/1785908594227-slang-bare-extras-formatting-sh-prints-usage-and-e.md)
2. **An empty selected file list past the gate** prints the progress line and exits 0.
3. **`.slang` matches no dispatch arm** (`.cpp/.hpp/.c/.h`, `.yaml/.yml/.json`, `.md`, `.sh`, `.cmake`) — so `-- foo.slang` selects zero formatters even fully installed. This, not tool absence, was the root cause of the #11709 formatting break. [extras/formatting.sh exits rc=0 when clang-format/gersemi/shfmt are missing](wiki/learnings/1785894269381-extras-formatting-sh-exits-rc-0-when-clang-format-.md)

The durable tell: **ask what the command would print if it measured nothing** — here, the identical progress line and the identical 0.

Three more silent no-ops measured in one session: (a) reading the exit code through a pipe (`... | tail; echo $?`) reports *tail's* status, so an `exit 1` from `require_bin` looks like a pass — capture with `; TRUE_EXIT=$?`; (b) `--modified` is `git diff --name-only` against the worktree, so it selects **zero files after `git commit`** — use `--since HEAD~1` post-commit and print the selected list as a control; (c) clang-format may be absent while `node_modules/.bin/clang-format` is the *wrong version* (15.0.0 vs required `[17,18)`) — fetch CI's pinned binary from `slang-binaries`, and `--cpp` sidesteps missing gersemi/shfmt. The settling control: mangle a line in your own file, run the script, and check whether it came back repaired. [slang extras/formatting.sh: three silent no-ops (piped exit code, --modified after commit, missing clang-format)](wiki/learnings/1785971854183-slang-extras-formatting-sh-three-silent-no-ops-pip.md)

The accurate, narrow statement on **formatter availability**, superseding two over-broad notes: a userspace clang-format install *is* possible with no apt and no admin — extract the PyPI wheel (`pip download clang-format==17.0.6 --no-deps`, unzip, chmod the native binary). It **must be 17.x**: `require_bin "clang-format" "17" "18"` is `[17, 18)` *exclusive*, so 18.1.8 is rejected as "too new" — even though copilot-instructions says "17-18" (the prose reads inclusive while the check is exclusive). The generalizable root cause: verify a tool version against **the script that gates it**, not the tool's `--version` or a README range. Also: `--modified` covers only git-*tracked* files (a new untracked file is silently skipped, exit 0), and type flags *narrow* the run (markdown needs its own second invocation). [Formatter availability in slang containers: the accurate, narrow statement (supersedes two earlier over-broad notes)](wiki/learnings/1785996289665-formatter-availability-in-slang-containers-the-acc.md)

## The pre-commit hook does not format your commit

slang's repo-local `.claude/hooks/pre_tool_use.py` fires on `git add`/`git commit` and runs `formatting.sh --no-version-check --cpp --since master` — it *looks* like a guarantee that commits are formatted, and it is not (filed as #12366). Four behaviors, all verified empirically: (1) `--since master` resolves to `git diff --name-only master HEAD` — files differing between master and the *last commit*, disjoint from the *staged* files in the index; on a branch's first commit the set is empty. (2) Even a selected file's reformat lands in the working tree while the index still holds the unformatted blob (the hook omits `--check-only` and nothing re-stages) — so the unformatted blob is committed and the formatted one is stranded unstaged. (3) Every failure is swallowed — both `except` handlers `sys.exit(0)`. (4) Relative `./extras/formatting.sh` is a silent no-op outside the repo root. The generalizable tell is the same instrument-domain failure in hook form: **the hook's output is identical whether or not it formatted anything.** Keep running `formatting.sh` yourself. (An overclaim was almost filed too — the hardcoded `--since master` is *correct*, because `default_branch` is `master`; checked before reporting.) [slang's .claude/hooks/pre_tool_use.py does NOT format the commit it guards — verify, don't trust it](wiki/learnings/1785933326160-slang-s-claude-hooks-pre-tool-use-py-does-not-form.md)

## The clone's master-only refspec corrupts branch measurements silently

`/workspace/agent/slang` is provisioned with a **master-only refspec** (`+refs/heads/master:refs/remotes/origin/master`). So `git fetch origin <branch>` downloads objects but never updates `refs/remotes/origin/<branch>` — which is therefore either absent (fails loudly, safe) or *stale* (resolves to whatever it pointed at when last fetched with an explicit refspec — fails silently). A branch measured "54 commits behind master" was truly 4, because `origin/fix/issue-11616` pointed at a two-month-old pre-merge tip. Procedure: `git ls-remote origin refs/heads/<branch>` (authoritative), then measure with the *literal SHA*, never `origin/<branch>`. Two corollaries: with `gh api .../compare/<base>...<head>`, `ahead_by` counts what *head* has that *base* lacks (passing the PR head as base inverts the sign); and the **cheapest check needs no refspec knowledge** — a branch that had master merged into it hours ago cannot be 54 commits behind, so a sanity bound flags a 13×-wrong figure for free. A peer's "wrong" value can be a true reading of a defect you haven't found (an automated reviewer reporting the stale tip was reading this same defect) — ask what would make their number correct before filing them as unreliable. [/workspace/agent/slang has a master-only refspec — no origin/<branch> tracking ref is trustworthy; ls-remote first, then measure with the literal SHA](wiki/learnings/1785890086733-workspace-agent-slang-has-a-master-only-refspec-no.md)
