# Slang Compiler Internals: Parser, IR, Types, and Language Semantics

This page covers internal compiler mechanics: lexer and parser gaps, IR builder source-location stamping, type interning and dual-representation bugs, module import/re-export and debug-info semantics, autodiff conventions, release-build assert behavior, platform macros, and runtime data-structure gotchas.

## TL;DR

- **`SLANG_ASSERT` compiles to `SLANG_ASSUME` (a UB license) in release, not a runtime check.** Never pair `SLANG_ASSERT(x)` with a runtime `if (x)` on the same `x`: the optimizer may delete the guard. Use `SLANG_RELEASE_ASSERT` to fail loudly, or keep only the `if`. Retesting an assert ICE under `SLANG_ASSERT=release-assert-only` suppresses that assert and gives a false "fixed".
- **`getStringLiteralTokenValue` has its own hex decoder missing `+10` for a–f/A–F**; char literals use the correct `CharUtil::getHexDigitValue`. Replace the inline ladder with the shared util, do not add a third decoder.
- **Each statement parser owns its terminator.** `ParseThrowStatement` never reads `;`, so `if (c) throw 1; else return 2;` is REJECTED (the `else` is orphaned). Always test the unbraced if/else shape, and prove a parse by reading emitted code, not error text. Requiring `;` does not tighten greedy expression absorption.
- **`ParseDeclName` is shared by function and variable declarators** (`int operator+ = 10;` parses); fix at `CompleteVarDecl`. `parseTypeDef` lacks trailing-array form; fix with shared declarator machinery.
- **`IRBuilderSourceLocRAII` may already stamp new insts** — check explicit `sourceLoc =` assignments by deleting them, not by assumption.
- **`ASTBuilder::getOrCreate<T>` keys on syntax class AND operands**, so `ThisType` and `DeclRefType` for one base are distinct `Type*`. When one logical type interns differently by access path, fix the representation canonicalization, not the divergence site.
- **Module import:** `using namespace N;` is lookup-local and never re-exported; the `parentDecl == moduleDecl` re-export conjunct is load-bearing via plain transitive `import`; global `type_param` names are NOT merged across imports.
- **`#include`'d files get an `IRDebugSource` but NO `IRDebugCompilationUnit`** (imported modules do get one). A `DebugSource → CU` map therefore misses include-defined functions. Verify every X in scope HAS a Y before recommending an X→Y lookup.
- **For an old serialization bug with a precise line pointer, `git log -S` the symbol first** — #6557 was already removed by the RIFF rewrite (#7041); the deliverable is the missing cross-module regression test.
- **Post-link entry-point result layouts are not refreshed** for the associated type of an `export` struct (#9580) — fix producer-side, not with a null-guard.
- **Reverse-mode autodiff shapes a differentiable `out T y` as a bare `in T.Differential` with no primal writeback**; forward-mode `DifferentialPair` intuition does not transfer. A fix that registers a checkpoint dependency beats one that forces a store past checkpoint policy.
- **Scope NRVO for by-value opaque returns to genuinely-opaque handles, not all `[__NonCopyableType]`** — bit-copyable tagged structs regress `defer`, `x = f(x)` and throwing partial writes.
- **Scalar `?:` short-circuits by design; vector `?:` does not** and is deprecated in favor of `select`.
- **Default optimization level is `Default` (1), not `None`** — detect explicit `-O` with `hasOption(CompilerOptionName::Optimization)`.
- **Slang platform macros are value-style and always defined (0 when inactive)**, so `#ifdef SLANG_OSX` is always true; a presence→value conversion drops iOS — use `SLANG_APPLE_FAMILY`.
- **`Slang::String` is copy-on-write with a shallow copy ctor** — to share across threads, deep-copy with `String(x.getUnownedSlice())` under the producer's lock.
- **`canCoerce` probes call with `outExpr == nullptr`**, so a `return true` nested in `if (outExpr)` makes init-lists fail as arguments; the error path can still leak real-sink diagnostics during probes.
- **`#language slang <ver>` unconditionally overrides the default version for that file**; files without a directive keep the default. It does not cross an `import` boundary.
- **Before re-reporting a silent chain as parked, search all-state PRs referencing the issue** and re-verify the defect at HEAD — the assignee may have shipped their own fix.

## Lexer: Hex-Digit Decoder Bug

Slang has two hex-digit decoders. The shared, correct one is `CharUtil::getHexDigitValue` (`source/core/slang-char-util.h`), which char literals use through `CppStringEscapeHandler::appendUnescaped`. String literals use an inline if/else ladder in `getStringLiteralTokenValue` (`slang-lexer.cpp`) that omits `+ 10` for a–f/A–F, so letter digits decode to 0–5 and `"\xff"` silently becomes `0x55` ('U'). No test covers hex escapes. Char literals have a different bug in the same family: `getCharLiteralValue` re-decodes a single `0xff` byte as UTF-8 and reads past the buffer. The fix replaces the inline ladder with `CharUtil::getHexDigitValue`; both decoders also lack overflow checks and truncate unbounded digits ([slang-lexer.cpp has a duplicate hex-digit decoder with an off-by-ten bug](../learnings/1779805764133-slang-lexer-cpp-has-a-duplicate-hex-digit-decoder-.md)).

## Parser: ParseDeclName Shared by Func and Var

`ParseDeclName` is shared by function and variable declarators, so `int operator+ = 10;` is silently accepted as a variable named `operator+`. Function-vs-variable disambiguation happens later, at the commit point, so the fix belongs in `CompleteVarDecl`, not in the shared name reader ([slang ParseDeclName shared by func and var declarators accepts operator names](../learnings/1781823315708-slang-parsedeclname-shared-by-func-and-var-declara.md)).

`parseTypeDef` handles only the leading-array form, so the C/HLSL trailing-array form `typedef int arr[2];` fails with an unexpected-integer-literal error. The principled fix routes typedef through the shared declarator machinery instead of patching the typedef-specific path ([Slang typedef trailing-array parse gap (parseTypeDef vs declarator machinery)](../learnings/1781218629168-slang-typedef-trailing-array-parse-gap-parsetypede.md)).

**A missing terminator in one statement parser also makes the compiler REJECT valid code (#12326).** The dispatch framework never consumes semicolons; each statement parser reads its own. `ParseThrowStatement` (`slang-parser.cpp:7580-7587` @`53b76e6d3`) returns right after `ParseExpression()` with no `ReadToken(TokenType::Semicolon)`, unlike `return`, `break`, `continue`, `discard` and expression statements (`defer` also omits it, correctly, because its nested Stmt carries the terminator). Consider `if (n < 0) throw 1; else return 2;`: `parseIfStatement` gets the ThrowStmt back with `;` unconsumed, `LookAheadToken("else")` sees `;`, and the leftover `;` becomes an EmptyStmt that orphans the `else` — HEAD reports `E20001` + `E30015 undefined identifier 'else'`. So when triaging any missing-terminator issue, test the unbraced `if/else` shape.

Keep two claims separate: requiring `;` does **not** tighten the expression bound. Greedy line absorption is generic to Slang's newline-insensitive grammar (`return x` ⏎ `- 5;` emits `x_0 - int(5)` even though `return` requires `;`); the requirement only turns a silent misparse into an honest diagnostic. After a semicolon-less `throw x`, `- 5;`/`-n;`/`+ 5;`/`* 2;` absorb silently, `--n;`/`++n;` absorb as postfix (so a detector keyed on the thrown value under-counts), `(n);` becomes a call (`E30016`), and `g(n);`/`int y=1;`/`return 5;`/`if(...)` are unaffected. Prove a parse by reading emitted code (HLSL `packAnyValue4_0(x_0 - int(5))` vs the control `packAnyValue4_0(x_0)`), not error text. A prebuilt binary can probe an older path when `git diff <old> HEAD -- <file>` shows that function untouched; after restoring a patched file, verify behaviorally, since the binary keeps the patch until rebuilt. Fallout is one semicolon-less `throw` tree-wide (a generated doc test) plus two generated doc lines. A language-version gate is wrong: `SLANG_LANGUAGE_VERSION_202C` does not exist at HEAD (unmerged #12179), and gating a fix that un-rejects valid code keeps the bug on the default version. A prior doc review logged the `;` question as `rejected-bogus`; `docs/generated/design/_meta/{reviews,remediations}/` records already-litigated questions ([semicolon-less `throw` orphans a following `else` — a parser omission has an un-obvious rejection side](../learnings/1785766261707-slang-semicolon-less-throw-orphans-a-following-els.md)).

## IRBuilder Source Location RAII

`IRBuilderSourceLocRAII` in `lowerDecl` already stamps the source location of new instructions from the builder stack when `createStructKey()` runs, so an explicit `irFieldKey->sourceLoc = fieldDecl->loc` right after is likely redundant for in-source paths. Verify by deleting it, not by assuming it is necessary ([Slang: IRBuilder source-loc RAII may already stamp struct keys — explicit sourceLoc= can be redundant](../learnings/1780416359939-slang-irbuilder-source-loc-raii-may-already-stamp-.md)).

## Type Interning: DeclRefType vs ThisType Dual-Representation

`ASTBuilder::getOrCreate<T>` keys on both the syntax class and the operands, so `getOrCreate<ThisType>(base)` and `getOrCreate<DeclRefType>(base)` produce **distinct** `Type*` for the same base. `DeclRefType::create` falls through to a plain `DeclRefType` for `MemberDeclRef` bases, so one interface `This` exists as two types ([Slang getOrCreate interns on syntax class — DeclRefType vs ThisType dual-representation bugs](../learnings/1780529958264-slang-getorcreate-interns-on-syntax-class-declreft.md)). A narrow 2-file fix for this was superseded by a 44-file maintainer PR (#11368) that canonicalized the underlying `associatedtype` constraint representation. When one logical type interns differently by access path, suspect a canonicalization gap instead of patching the divergence site ([postmortem: shader-slang/slang#11465 superseded by PR #11368](../learnings/1781114755243-postmortem-shader-slang-slang-11465-superseded-by-.md)).

## Module Import: Re-Export Semantics and Scope Chain

`using namespace N;` is lookup-local to the declaring module and is **never re-exported** through `import`. The primary-file leak that used to work was a bug, fixed as `pr: breaking`; reconciled tests add `using ns;` to the importer instead of deleting the test ([slang #11443 verdict: using namespace is lookup-local, primary-file leak is a breaking bug-fix](../learnings/1780477032580-slang-11443-verdict-using-namespace-is-lookup-loca.md)). The `parentDecl == moduleDecl` conjunct in the re-export filter is load-bearing via plain transitive `import`, not only `using namespace`: imported module scopes are spliced onto the importer's scope chain, so weakening it to bare `as<FileDecl>` leaks transitive imports ([Slang import re-export: parentDecl==moduleDecl conjunct is load-bearing via transitive import, not using-namespace](../learnings/1780493659932-slang-import-re-export-parentdecl-moduledecl-conju.md)). Global `type_param` declarations merge within one module's global scope but **not** across imported modules; each module's param is its own `SpecializationParam` ([Slang global type_param names are NOT merged across module imports](../learnings/1781372887205-slang-global-type-param-names-are-not-merged-acros.md)).

Importing a precompiled `.slang-module` produces location-less diagnostics, because IR-pass diagnostics lose file:line when the struct/field key is deserialized. See the regression verification note in [[wiki/concepts/slang-misc-pr-process-and-maintainer-workflow.md]].

**Before investigating an old serialization bug, `git log -S` the symbol to see whether a rewrite removed the cited code.** The `loadModuleFromIRBlob` "returns nullptr when A imports B" bug (#6557, a `containerData.modules.getCount() != 1` gate) is already fixed on ToT: PR #7041's RIFF rewrite removed the gate. `ModuleEncodingContext::encode` now stores only the module's own IR/AST and records imported deps as file-dependency paths, so `A.slang-module` has one `smod` chunk, and `ModuleChunk::find` resolves dep paths at load. Prove the disposition with an on-ToT repro (`slangc -dump-module A.slang-module`), not the vanished line numbers (the code moved to `slang-session.cpp`). The deliverable for an already-fixed bug is the coverage gap: all 8 subtests of `unit-test-ir-blob.cpp` are self-contained, so the regression test registers B's blob and then loads A's blob in a fresh session ([slang#6557 loadModuleFromIRBlob-imports-module already fixed by RIFF rewrite (#7041)](../learnings/1783463091677-slang-6557-loadmodulefromirblob-imports-module-alr.md)). Serialized-module loading already works in slang-wasm, because the embedded core module goes through `loadCoreModule` (`slang-api.cpp:186-196`), so a wasm IR-blob feature needs only bindings; imports inside an IR module resolve by name against modules already loaded in the session (`slang-serialize-ast.cpp:1515`), since wasm `createSession` sets no search paths. Dedup such reports with 2-3 phrasings — "loadModuleFromIRBlob" misses the older "IR binary modules" issue (#8744) ([wasm IR-blob loading needs only bindings](../learnings/1792084496275-batch-external-reporter-files-issue-pr-together-al.md)).

**An entry point returning the associated type of an `export`/`extern` struct crashes SPIR-V codegen (#9580, a PR #8603 regression).** After #8603, `extern struct Foo : IFoo = Impl;` resolves at link time via `IRSymbolAlias`, so the return type IS the concrete struct, but the result VarLayout keeps its pre-link opaque associated-type layout. `as<IRStructTypeLayout>` returns null and `createGLSLGlobalVaryingsImpl` asserts or segfaults. The post-link refresh (`processEntryPointVaryingParameter` → `lookupExternDeclRefType`) fires when the result is directly the extern struct, not its associated type. The principled fix rebuilds entry-point result layouts post-link, not a null-guard; the reporter (@h3r2tic) already prototyped it, so help land that branch instead of a parallel fix ([slang#9580 assoc-type-of-export-struct entry-point return crashes — stale post-link result layout (PR #8603 regression)](../learnings/1783557222885-slang-9580-assoc-type-of-export-struct-entry-point.md)).

**Debug info distinguishes `import` from `#include`.** `emitDebugSource` (`slang-lower-to-ir.cpp:15407`) runs for every source file, but `emitDebugCompilationUnit` (:15418) requires `debugInfoLevel >= Standard && !source->isIncludedFile()`, and `SourceFile::setIncludedFile()` is called only from the preprocessor `#include` path (`addIncludedSourceFileIfNotExist`, `slang-translation-unit.cpp:132`). So an `#include`'d file has an `IRDebugSource` but no `IRDebugCompilationUnit`, while an imported module's primary source has its own CU. For the #11983 DebugFunction-scope fix, a `DebugSource → CU` map keyed on `debugFunc->getFile()` would fix imported functions but miss include-defined ones; the correct fix (Approach B) stores the scope/CU on `IRDebugFunction` at IR generation instead of reconstructing it at SPIR-V emit after modules flatten. "Every DebugFunction has a source file" was true; "every source file has a CU" was false by design — verify every X in scope has a Y before recommending an X→Y lookup ([slang #include'd file gets a DebugSource but NO DebugCompilationUnit — defeats any DebugSource→CU map (#11983)](../learnings/1784282376505-slang-include-d-file-gets-a-debugsource-but-no-deb.md)).

## Autodiff: Backward Diff Out-Parameter Convention

In reverse-mode autodiff, a differentiable `out T y` becomes a **bare `in T.Differential`** in the synthesized backward function, and `bwd_diff` writes back no primal values. Forward mode shapes `out` as `out DifferentialPair<T>` with primal and tangent, so forward-mode intuitions do not transfer ([slang bwd_diff out-param convention — bare in-differential seed, no primal writeback](../learnings/1780332708129-slang-bwd-diff-out-param-convention-bare-in-differ.md)).

**Loop-start / induction-counter reconstruction (#12070, via slangpy#1051)** is still unfixed at master `53b76e6d3`: `counterOffset = loopInst->getArg(paramIndex)` (:1034) feeds a raw `emitAdd(..., counterOffset)` (:1355-1361) with no remap or guard, while the sibling site at :1154 is guarded, and `tests/autodiff/` has no induction-runtime-start coverage. Of two candidate fixes, an unconditional `hoistInfo->storeSet.add(counterOffset)` at the reconstruction site forces a store and bypasses checkpoint policy's recompute-vs-store choice (15 lines, 1 test). Registering the offset as a **synthetic checkpoint dependency in `processFunc`** lets the policy decide and consumes the decision at reconstruction (clone mapping if recomputed, `ensurePrimalAvailability` if stored), and it also catches a second defect: the synthetic reverse count is always `int`, so an `int16_t`/`int64_t` induction variable produces a mixed-width add and invalid SPIR-V. That fix was the assignee's own PR (#12299), found only after 22 days of silence. Before re-affirming a park, search all-state PRs referencing the issue plus the assignee's recent PRs, read the timeline's `cross-referenced` events, compare both diffs before calling one superseded, re-verify the defect at HEAD, and recommend (never perform) closing the superseded draft ([supervisor nudge on a silent escalation — check whether the assignee shipped their OWN PR before re-reporting "parked"](../learnings/1785761376469-supervisor-nudge-on-a-silent-escalation-check-whet.md)).

**NRVO for opaque non-copyable returns (#12197, `slang-lower-to-ir.cpp`).** Returning `RayQuery<...>` by value miscompiles because the callee value-copies the opaque handle into the return destination (a no-op OpLoad+OpStore); the fix aliases the single named-return local to the return-destination parameter. Gating that on `isNonCopyableType` is too broad: `[__NonCopyableType]` also marks bit-copyable tagged structs whose by-value return already works, and aliasing them regresses `defer`, `inout` aliasing (`x = f(x)`) and throwing-path partial writes. A shared `isNonCopyableOpaqueType` (RayQuery/HitObject, where whole-value load/store really is a no-op) makes those regressions impossible by construction. Adversarial codex CODE_REVIEW caught both regressions; a green 2113-test suite with no defer/aliasing/throws+RayQuery coverage did not ([NRVO for opaque non-copyable returns must be scoped to opaque HANDLES, not all [__NonCopyableType] (#12197)](../learnings/1784798335581-nrvo-for-opaque-non-copyable-returns-must-be-scope.md)).

## Scalar vs Vector Ternary Short-Circuit Semantics

A scalar-condition `?:` short-circuits by lowering to if-else control flow (design intent, target-independent). A vector-condition `?:` does **not** short-circuit and is deprecated in favor of `select`. The language-reference doc was stale and was corrected (#11403) ([Slang `?:` short-circuit semantics + #11403 disposition (scalar short-circuits by design; vector does not)](../learnings/1780345715837-slang-scalar-short-circuits-by-design-vector-does-.md)).

## SLANG_ASSERT and Release Build Behavior

`SLANG_ASSERT` compiles to `SLANG_ASSUME` (an undefined-behavior license) in release builds — `#define SLANG_ASSERT(VALUE) SLANG_ASSUME(VALUE)` under `#else` in `slang-common.h:372` — so it is not a runtime check, and narrowing an existing predicate can introduce release-only UB right before a dereference. Use `SLANG_RELEASE_ASSERT` to fail loudly in release ([Slang: SLANG_ASSERT is a no-op (SLANG_ASSUME/UB-license) in release builds — use SLANG_RELEASE_ASSERT to actually fail loudly](../learnings/1781807946287-slang-slang-assert-is-a-no-op-slang-assume-ub-lice.md)). Unlike libc `assert()` under `NDEBUG`, it is not a no-op: **never pair `SLANG_ASSERT(x)` with a runtime `if (x)` on the same `x`**, because the optimizer may prove `x` true and delete the null-guard, reintroducing the dereference the guard prevented. To document an invariant but stay null-safe, drop the assert and keep the `if`; for a hard abort in release, use `SLANG_RELEASE_ASSERT`. Codex CODE_REVIEW caught exactly this on PR #12206, where `SLANG_ASSERT(diagnosticFunc)` before `if (diagnosticFunc) emit;` undercut the claimed best-effort emit ([SLANG_ASSERT(x); if(x)... is a release-build UB trap](../learnings/1784847485639-slang-assert-x-if-x-is-a-release-build-ub-trap-ass.md)).

Retesting an assert-failure ICE with `SLANG_ASSERT=release-assert-only` **suppresses the exact assertion** under test and gives a false "fixed" result ([SLANG_ASSERT=release-assert-only gives FALSE 'fixed' when triaging assert-failure ICEs](../learnings/1781712984955-slang-assert-release-assert-only-gives-false-fixed.md)).

## Optimization Level Default

The default optimization level is `OptimizationLevel::Default` (1), not `None` (0), so a `level != None` test over-warns on every ordinary compile. Detect an explicit `-O` with `CompilerOptionSet::hasOption(CompilerOptionName::Optimization)` ([Slang opt-level default is Default not None — use hasOption to detect explicit -O](../learnings/1781810067410-slang-opt-level-default-is-default-not-none-use-ha.md)).

## Platform Macros: Value-Style, Always Defined

Slang platform macros such as `SLANG_OSX`, `SLANG_LINUX` and `SLANG_VC` are **always defined** by `slang.h` (to 0 on inactive platforms), so `#ifdef SLANG_OSX` is always true wherever `slang.h` is included; prelude headers without `slang.h` are the exception ([Slang platform macros are value-style (always defined) — defined()/#ifdef on them is an always-true bug](../learnings/1782281850149-slang-platform-macros-are-value-style-always-defin.md)). Converting `defined(SLANG_OSX)` to the value test `SLANG_OSX` silently drops iOS from the dlfcn branch, since `SLANG_OSX` is 0 on iOS; use the `SLANG_APPLE_FAMILY` aggregate, which mirrors `SLANG_LINUX_FAMILY` ([Presence→value SLANG_* macro conversions can silently narrow the active-platform side (iOS dropped from dlfcn)](../learnings/1782327804698-presence-value-slang-macro-conversions-can-silentl.md)).

## Slang::String Is Copy-On-Write

`Slang::String` is copy-on-write with a shallow copy constructor, so sharing one across threads needs a forced deep copy: `String(x.getUnownedSlice())` under the producer's lock yields a uniquely-owned buffer ([Slang::String is COW — deep-copy via String(x.getUnownedSlice()) to share across threads](../learnings/1782731516993-slang-string-is-cow-deep-copy-via-string-x-getunow.md)).

## Initializer List Coercion: canCoerce Probe Divergence

When brace initializers work in var-decl/return/assignment but fail as function arguments, check the `canCoerce` viability probe: it calls with `outExpr == nullptr`, so a `return true` nested inside `if (outExpr)` in a coercion helper reports a false negative. Un-nest the `return true` so viability does not depend on whether an output AST was requested ([Slang init-list-as-argument bugs: check canCoerce viability-probe (outExpr==null) divergence](../learnings/1782736932170-slang-init-list-as-argument-bugs-check-cancoerce-v.md)). PR #11818 (issue #11730) fixed the success return, but the error return in `createInvokeExprForExplicitCtor` still calls `diagnoseRaw` on the real sink during probes, leaking hard diagnostics before overload ranking completes ([slang init-list arg coercion: #11730 fixed the success return's probe-safety but the ERROR return still leaks a real-sink diagnostic during canCoerce](../learnings/1782739042356-slang-init-list-arg-coercion-11730-fixed-the-succe.md)).

## #language Directive Precedence

The precedence is well-defined. Each file starts at `optionSet.getLanguageVersion()` (`slang-compile-request.cpp:324`); `HandleLanguageDirective` (`slang-preprocessor.cpp:4568`) assigns the directive's version unconditionally, so it overrides the default in either direction; and the value is written back only if a directive was seen (`!= UNKNOWN`), so directive-less files keep the default. `slangc -std`/`-lang` already sets `CompilerOptionName::LanguageVersion`, so a "default version for files without a directive" feature (slangd) only needs to feed that option per file. Valid versions are `legacy`/2018, 2025 and 2026; `maybeUpgradeLanguageVersionFromLegacy` bumps LEGACY→2025 when a visibility modifier is parsed. A directive in a shared file propagates only through textual `#include`, not across an `import` boundary, because each module has its own `languageVersion` ([Slang #language directive precedence: unconditional per-file override of the option-set default](../learnings/1782153228750-slang-language-directive-precedence-unconditional-.md)).
