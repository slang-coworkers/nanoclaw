# Slang Compiler Internals: Parser, IR, Types, and Language Semantics

This page covers internal compiler mechanics: parsing, IR builder source location stamping, type interning and dual-representation bugs, module import/re-export semantics, autodiff parameter conventions, platform macros, and runtime data structure gotchas.

⚠️ **This page is over the 40 KB page cap (~121 KB) and its tail may be truncated on read.** The TL;DR below carries the durable rules so they survive a bounded read; a subtopic split is pending.

## TL;DR

- **`SLANG_ASSERT` compiles to `SLANG_ASSUME` (a UB license) in release, not a runtime check** — never pair `SLANG_ASSERT(x)` with a runtime `if (x)` fallback on the same `x` (the optimizer may delete the guard); use `SLANG_RELEASE_ASSERT` to fail loudly, or keep only the `if`. And **`SLANG_ASSERT=release-assert-only` suppresses the very assertion you are retesting**, giving a false "fixed" verdict.
- **In `include/slang.h` endianness fails loudly (`#error`) but pointer size fails SILENTLY** — `SLANG_PTR_IS_32 = (SLANG_PTR_IS_64 ^ 1)`, so any non-whitelisted 64-bit arch (rv64, LoongArch64, s390x, MIPS64) silently gets a 32-bit `SlangInt` and corrupts the public ABI. Add the symmetric guard; don't delete the whitelist.
- **`ISession::loadModule`/`loadModuleFromSource`/`loadModuleFromBlob`/`getLoadedModule` return a BORROWED `IModule*` — never release it** (`asExternal` is a plain `static_cast`, no addRef; DeepWiki is wrong). `link()`, `getTargetCode()`, `getEntryPointCode()`, `createCompositeComponentType()`, `findEntryPointByName()` transfer ownership via `.detach()` and must be released once.
- **Appending fields to a versioned public struct via inheritance makes it non-standard-layout, so `offsetof` is only conditionally-supported** — `is_trivially_copyable` + `sizeof(D) > sizeof(B)` do NOT prove B is a byte-prefix of D.
- **Keep terminal `CountOf`/`Count`/`NUM_*` sentinels IMPLICIT and restore textual-order == value-order** — a `static_assert(CountOf == SomeOption + 1)` checks adjacency to one enumerator, **not uniqueness** (observed: `CompilerOptionName::CountOf == SPIRVUnifiedDescriptorHeapStride == 154`).
- **`kIROp_MakeVectorFromScalar`'s generated `getScalarValue()` reads `getOperand(2)` but every builder emits ONE operand** — read the scalar via `getOperand(0)`. Generally: **verify how the BUILDER emits an op before trusting a positional accessor**; schema and builder diverge.
- **`findAttrs<T>()` returns only the FIRST CONTIGUOUS RUN of `T` operands**, so a new `IRAttr` subtype emitted inside the per-kind size loop truncates `getSizeAttrs()` (→ `slotCount=0`, miscompiled existential binding) — emit new attr types in a separate pass after all size attrs.
- **Order `as<derived>` before `as<base>` in any AST classification cascade** — `VarExpr`/`MemberExpr`/`StaticMemberExpr` all derive from `DeclRefExpr`, so a leading `as<DeclRefExpr>` makes the MemberExpr branch dead code. **`DeclRef::as<U>()` does NOT validate the target type** (it rewraps the same `declRefBase` and returns non-null for the wrong decl) — use `as<U>(rawDecl)` or `declRef.is<U>()`.
- **Slang builds modifier lists in REVERSE declaration order, so `findModifier<T>()` returns the LAST-written attribute** — verify "which duplicate modifier wins" empirically, never from source order. `-dump-ast` is unmaintained.
- **`ASTBuilder::getOrCreate<T>` keys on syntax class AND operands**, so `getOrCreate<ThisType>(base)` and `getOrCreate<DeclRefType>(base)` are distinct `Type*` for one base — when a logical type interns differently by access path, **fix the representation canonicalization, not the divergence site** (a 2-file fix was superseded by a 44-file canonicalization).
- **Any pass gated on a TYPE opcode is fragile: const-folding can delete the type while leaving an op that still needs the pass** — a stranded `CastEnumToInt` reached emit as E99999 because `calcRequiredLoweringPassSet` flagged only `kIROp_EnumType`. Gate on the cast opcodes too.
- **The requested-capability array has five readers OUTSIDE `getTargetCaps()`**, so "the cooked set is identical ⇒ inert" is false — removing an entry can flip `descriptor_handle` auto-promotion on metal/cuda/wgpu/cpu. **Derive an A/B from what the mechanism actually mutates (accept/reject + diagnostics), not layout/size, or you get a false null.**
- **`-capability` affects only target-compatibility checking, never per-function self-consistency** — public functions must declare `[require(...)]`; a dropped `[require]` is a silent runtime divergence that bites only codegen-decision capabilities.
- **Confine the empty-struct fix to `IREmptyTypeLegalizationContext` / consumer-side `isSimpleType`** — a global `removeEmptyStructFields` pass is CI-rejected (it strips zero-size empties that `Conditional<T,false>`/`Optional` need), and producer-side `addPublicDecoration` removal is the wrong layer (plain `public` functions then emit `static`). **When a change deletes a decoration at its producer, inventory every consumer.**
- **Entry-point / varying-parameter / reflection layout fixes belong in the front-end AST before layout generation, not a back-end post-link rebuild** — and don't hand-roll recursion; the layout walk re-enters per-node resolution and `Val::resolve()` already recurses.
- **Escape VALIDATION must ride the decode layer, not the token scan pass** — `getFileNameTokenValue` deliberately never decodes escapes (`\` is a Windows separator), so scan-pass `\u`/`\U` validation broke `#include "dir\utility\f.slangh"`. Separately, `getStringLiteralTokenValue`'s inline hex decoder is **missing `+10` for a–f/A–F**; fix the too-narrow guard, not the already-correct utility.
- **Never conditionally skip `RECORD_OUTPUT` in `source/slang-record-replay/`** — the stream is fixed-schema at the call level, so one skipped output desynchronizes every subsequent call on playback. `ReplayContext` registries are raw/**non-owning** (DeepWiki says otherwise), so the replay path leaks by construction.
- **`canCoerce` viability probes call with `outExpr == nullptr`**, so a `return true` nested inside `if (outExpr)` yields false negatives (init-lists work in var-decls but fail as arguments).
- **Slang platform macros are value-style and always defined (0 on inactive platforms), so `#ifdef SLANG_OSX` is unconditionally true** — and a presence→value conversion silently narrows (iOS dropped since `SLANG_OSX==0` there); use `SLANG_APPLE_FAMILY`. **The default optimization level is `Default` (1), not `None`** — detect an explicit `-O` via `hasOption(CompilerOptionName::Optimization)`.
- **`CompilerOptionSet::buildHash`'s `Int` branch drops `v.intValue2`**, so `-fvk-bind-globals`, `VulkanBindShift(All)` and `-trace-coverage-binding` collide on the key feeding BOTH the shader cache and `.slang-module` freshness. The binary-module up-to-date check is **digest-based, not mtime-based**.
- **Flipping the default `-g` level silently changes TEXTUAL codegen, not just SPIR-V** — `IRDebugLine` has side effects so `shouldFoldInstIntoUseSites` refuses to fold across it; sweep non-SPIR-V goldens, and note **a `SLANG_UNIMPLEMENTED` default arm weaponizes any newly-surviving inst class into a hard crash**.
- **A missing statement terminator makes the compiler REJECT valid code too, not just over-accept** — `ParseThrowStatement` omits `ReadToken(Semicolon)`, so `if (c) throw 1; else return 2;` fails with E20001+E30015. **Always test the unbraced if/else shape, and prove a parse by reading EMITTED CODE, not error text.** Same class: `ParseDeferStatement` opens no scope, so `defer uint i = 1;` leaks `i` and IR relocation turns it into a segfault.
- **Layout POLICY is coded twice with ZERO shared code** — SPIR-V `Offset`/`MatrixStride`/`ArrayStride` use the IR path (`slang-ir-layout.cpp`), reflection uses `IRTypeLayout`, so **which path the consumer reads decides where the bug is fixed**. The IR path deliberately omits C tail padding (whitelist it in differential checks), and an `SV_Target<N>` VarLayout `index` must be patched in **two** places in `slang-parameter-binding.cpp`.
- **Module import semantics:** `using namespace N;` is lookup-local and never re-exported; the `parentDecl == moduleDecl` conjunct is load-bearing via plain transitive `import`; global `type_param` names are NOT merged across imports. **`#include`'d files get an `IRDebugSource` but NO `IRDebugCompilationUnit`** (only the preprocessor sets `setIncludedFile()`), which kills any `DebugSource → CU` map — **verify every X in scope actually HAS a Y before recommending an X→Y lookup**.
- **Reverse-mode autodiff shapes a differentiable `out T y` as a bare `in T.Differential` with no primal writeback** — forward mode's `out DifferentialPair<T>` intuition does not transfer. NRVO for by-value opaque returns must be scoped to genuinely-opaque handles, **not all `[__NonCopyableType]`** (that also covers bit-copyable tagged structs; aliasing them regresses `defer`, `x = f(x)`, and throwing partial writes).
- **`validateEntryPoint` validates each param in isolation with no cross-param aggregation** — a duplicate-SV check must fire for system values only and skip output-only-by-type params in the InOut branch or `inout TriangleStream<T>` self-collides. **E38052 "VS has no SV_Position" is an intentional heuristic false positive** (VS→GS is known-legit; escape hatch `-warnings-disable 38052`).
- **Reuse the canonical predicates instead of hand-rolling** — `isPointerToImmutableLocation` (excludes RW-alias and the OptiX-SBT case) and `isOpaqueType` (recursive/cycle-safe) predate the narrow hand-rolled switches that duplicate them.
- **`Slang::String` is copy-on-write with a shallow copy ctor** — to share across threads force a deep copy with `String(x.getUnownedSlice())` under the producer's lock. On macOS, **hidden visibility silently breaks catching `Slang::Exception` BY TYPE across dylibs** (libc++abi keys on RTTI identity).
- **A probe's scope, not your confidence, bounds the claim** — enumerate readers with a named runnable grep before declaring anything inert; spot-check load-bearing subagent claims (one reported "6 calls" where grep returns zero); **EMIT AND GREP before any cross-target codegen claim**; check whether an intervening rewrite deleted the cited lines (`git log -S`) before investigating a stale pointer; and prefer *"could not verify by method M"* over any capability-negative — `find`/`grep` enumerate a MOUNT, not a capability.
- **Test presence, not a proxy for presence** — an artifact checker keyed on PR-existence flagged 105 chains of which 93 were false (they had issue comments), and keying on *recency* instead re-breaks exactly the correctly-parked chains. Before re-reporting a chain as parked, search all-state PRs referencing the issue and re-verify at HEAD.

## Lexer: Hex-Digit Decoder Bug

`getStringLiteralTokenValue` in `slang-lexer.cpp` has an inline hex-digit decoder that is missing `+10` for letter hex digits (a–f, A–F), causing string literals with hex escape letters to silently produce wrong byte values. Char literals use a separate correct utility ([slang-lexer.cpp has a duplicate hex-digit decoder with an off-by-ten bug](wiki/learnings/1779805764133-slang-lexer-cpp-has-a-duplicate-hex-digit-decoder-.md)).

## Parser: ParseDeclName Shared by Func and Var

`ParseDeclName` is shared between function and variable declarators, so `int operator+ = 10;` is silently accepted as a variable named `operator+`. Function-vs-variable disambiguation happens later at the commit point; the fix belongs at `CompleteVarDecl`, not the shared name reader ([slang ParseDeclName shared by func and var declarators accepts operator names](wiki/learnings/1781823315708-slang-parsedeclname-shared-by-func-and-var-declara.md)).

The `parseTypeDef` function only handles the leading-array form, causing `typedef int arr[2];` (C/HLSL trailing-array form) to fail with an unexpected-integer-literal error. The principled fix is shared declarator machinery rather than patching the typedef-specific path ([Slang typedef trailing-array parse gap (parseTypeDef vs declarator machinery)](wiki/learnings/1781218629168-slang-typedef-trailing-array-parse-gap-parsetypede.md)).

**A missing terminator in one statement parser also makes the compiler REJECT valid code.** Each statement parse fn owns its own terminator — the dispatch framework never consumes semicolons — and `ParseThrowStatement` (`slang-parser.cpp:7580-7587`, #12326 @`53b76e6d3`) returns straight after `ParseExpression()` with no `ReadToken(TokenType::Semicolon)`, unlike every sibling (`return` :7567, `break` :7547, `continue` :7556, `discard` :6949, expression stmt :7596; `defer` :7571 also omits it but *correctly*, since it parses a nested Stmt carrying its own terminator). The framing everyone reaches for is "the compiler accepts too much," and it is only half the story: `if (n < 0) throw 1; else return 2;` is **rejected** at HEAD (`E20001` + `E30015 undefined identifier 'else'`), because `parseIfStatement` (:7381-7386) gets the ThrowStmt back with the `;` unconsumed, so the following `LookAheadToken("else")` sees `;` and the else never attaches — the leftover `;` becomes a sibling EmptyStmt that orphans trailing clauses. So when triaging any missing-terminator issue, always test the unbraced `if/else` shape. Two claims must also stay separate: requiring the `;` does **not** tighten the expression bound — greedy `ParseExpression()` line absorption is generic to Slang's newline-insensitive grammar, and `return`, which already requires `;`, absorbs identically (`return x` ⏎ `- 5;` emits `x_0 - int(5)`); the `;` requirement converts a *silent* misparse into an honest diagnostic and nothing more. Sweep of the line after a semicolon-less `throw x`: `- 5;` / `-n;` / `+ 5;` / `* 2;` absorb **silently** (wrong thrown value, zero diagnostics), `--n;` / `++n;` absorb as postfix, `(n);` becomes a call (`E30016`), while `g(n);` / `buf[0]=1;` / `int y=1;` / `return 5;` / `if(...)` are unaffected — and a detector keyed on the *thrown value* under-counts, because postfix returns the original value. Method notes that generalize: **read emitted code, not error text, to prove a parse** (the decisive evidence was HLSL emission `packAnyValue4_0(x_0 - int(5))` vs the control `packAnyValue4_0(x_0)`); a prebuilt binary is valid for probing an older path when `git diff <old> HEAD -- <file>` shows the specific function untouched (check the function, not the version string), and after restoring a patched file verify **behaviorally** — the binary still carries the patch until you rebuild. Fix fallout is tiny: exactly one semicolon-less `throw` exists tree-wide (`docs/generated/tests/design/syntax-reference/grammar/stmt-throw-no-semicolon.slang:30`, `//META: generated=true` — a behavior mirror, not an independent requirement) out of 18 throw statements, and two generated doc lines document the omission (`grammar.md:342-344`, `ast-reference/statements.md:112`). Do **not** reach for a language-version gate here: `SLANG_LANGUAGE_VERSION_202C` does not exist at HEAD (it arrives with unmerged PR #12179; the enum at `include/slang.h:5758-5765` is UNKNOWN/LEGACY=2018/2025/2026), and a langver gate is a bad fit for a fix that *un-rejects* valid code — it would preserve the bug on the default version for no compat gain. Also: the grammar doc (`grammar.md:342-344`) says `'throw' Expr` with an explicit note that the `;` is not consumed, and a prior doc review logged that exact question as `rejected-bogus`, so "the grammar doc already requires it" is not an available argument — `docs/generated/design/_meta/{reviews,remediations}/` is the place to check whether a question was already litigated ([semicolon-less `throw` orphans a following `else` — a parser omission has an un-obvious rejection side](wiki/learnings/1785766261707-slang-semicolon-less-throw-orphans-a-following-els.md)).

## Type Interning: DeclRefType vs ThisType Dual-Representation

`ASTBuilder::getOrCreate<T>` keys on both the syntax class and operands, so `getOrCreate<ThisType>(base)` and `getOrCreate<DeclRefType>(base)` produce **distinct** `Type*` even for the same base. `DeclRefType::create` falls through to a plain `DeclRefType` for `MemberDeclRef` bases, causing the same interface `This` to exist as two distinct types ([Slang getOrCreate interns on syntax class — DeclRefType vs ThisType dual-representation bugs](wiki/learnings/1780529958264-slang-getorcreate-interns-on-syntax-class-declreft.md)).

A narrow 2-file fix for this dual-representation bug was superseded by a 44-file maintainer PR that canonicalized the underlying `associatedtype` constraint representation. When the same logical type interns differently based on access path, suspect a representation-canonicalization gap rather than patching the single divergence site ([postmortem: shader-slang/slang#11465 superseded by PR #11368](wiki/learnings/1781114755243-postmortem-shader-slang-slang-11465-superseded-by-.md)).

## Module Import: Re-Export Semantics and Scope Chain

`using namespace N;` is lookup-local to the declaring module and is **never re-exported** through `import`; the primary-file leak that previously worked was a bug (now fixed via `pr: breaking`). Reconciled tests must add `using ns;` to the importer rather than deleting the test ([slang #11443 verdict: using namespace is lookup-local, primary-file leak is a breaking bug-fix](wiki/learnings/1780477032580-slang-11443-verdict-using-namespace-is-lookup-loca.md)).

The `parentDecl == moduleDecl` conjunct in the module re-export filter is load-bearing via plain transitive `import` (not only `using namespace`). Imported module scopes are spliced onto the importing module's scope chain; weakening it to bare `as<FileDecl>` would cause unintended transitive import leakage ([Slang import re-export: parentDecl==moduleDecl conjunct is load-bearing via transitive import, not using-namespace](wiki/learnings/1780493659932-slang-import-re-export-parentdecl-moduledecl-conju.md)).

Global `type_param` declarations are merged within a single module's global scope but are **not** merged across imported modules — each module's param becomes its own distinct `SpecializationParam` ([Slang global type_param names are NOT merged across module imports](wiki/learnings/1781372887205-slang-global-type-param-names-are-not-merged-acros.md)).

Precompiled `.slang-module` import triggers location-less diagnostics because IR-pass diagnostics lose file:line source location when the struct/field key is deserialized from a precompiled module. See also the regression verification note in [[wiki/concepts/slang-misc-pr-process-and-maintainer-workflow.md]].

The old `loadModuleFromIRBlob` "returns nullptr when A imports B" bug (#6557, `containerData.modules.getCount() != 1` gate) is **already fixed on ToT** — PR #7041's RIFF rewrite removed that gate entirely. Now write (`ModuleEncodingContext::encode`) stores ONLY the module's own IR/AST with imported deps recorded as file-dependency PATH references, so `A.slang-module` has ONE `smod` chunk (not two), and load (`ModuleChunk::find` = first chunk, never fails on count>1) resolves the recorded dep paths dynamically. Prove disposition with an on-ToT repro (`slangc -dump-module A.slang-module` is exactly the reporter's `loadModuleFromIRBlob` path), NOT by reading the cited (vanished) line numbers — the file moved from slang.cpp to slang-session.cpp. The actionable deliverable for a PR request on an already-fixed bug is the coverage gap: `unit-test-ir-blob.cpp`'s 8 subtests are all self-contained, so hand the fixer a regression test that registers B's blob then loads A's blob in a fresh session. General lesson: for an old module/serialization bug with a precise line pointer, check whether an intervening rewrite (`git log -S` the symbol) removed the code before investigating the cited layer ([slang#6557 loadModuleFromIRBlob-imports-module already fixed by RIFF rewrite (#7041)](wiki/learnings/1783463091677-slang-6557-loadmodulefromirblob-imports-module-alr.md)).

An entry point returning the **associated type of an `export`/`extern` struct** crashes SPIR-V codegen (#9580, a PR #8603 regression): post-#8603 `extern struct Foo : IFoo = Impl;` resolves at link time via `IRSymbolAlias` so the entry-point return type IS the concrete struct, but the entry-point result VarLayout's type-layout is never refreshed post-link — it stays the pre-link opaque associated-type layout, so `as<IRStructTypeLayout>` returns null → assert/segfault in `createGLSLGlobalVaryingsImpl`. The intended post-link refresh (`processEntryPointVaryingParameter` → `lookupExternDeclRefType`) fires when the result is *directly* the extern struct (VARIANT 1, works) but NOT the *associated type of* an export struct (VARIANT 0, crashes). Principled fix is producer-side (rebuild entry-point result layouts post-link), not a null-guard; the reporter (@h3r2tic) already prototyped exactly this on a branch — corroborate and help land it rather than build a parallel fix ([slang#9580 assoc-type-of-export-struct entry-point return crashes — stale post-link result layout (PR #8603 regression)](wiki/learnings/1783557222885-slang-9580-assoc-type-of-export-struct-entry-point.md)).

A related producer-side subtlety in debug-info lowering distinguishes `import` from `#include`: `emitDebugSource` (`slang-lower-to-ir.cpp:15407`) runs for EVERY source file, but `emitDebugCompilationUnit` (:15418) is gated by `debugInfoLevel >= Standard && !source->isIncludedFile()` — so an `#include`'d file gets an `IRDebugSource` but NO `IRDebugCompilationUnit`. `SourceFile::setIncludedFile()` is called ONLY from the preprocessor `#include` path (`TranslationUnitRequest::addIncludedSourceFileIfNotExist`, `slang-translation-unit.cpp:132`), NOT for `import`ed modules — an imported module's primary source is non-included and DOES get its own CU. This is why the #11983 DebugFunction-scope fix cannot use the tempting "build a `DebugSource → DebugCompilationUnit` map and resolve scope by `debugFunc->getFile()`" approach: it would fix the reported imported-function symptom (imported source has a CU) yet MISS include-defined functions (their `getFile()` DebugSource has no CU → lookup misses). The correct fix is producer-side (Approach B): store the scope/compilation-unit explicitly on `IRDebugFunction` at IR-generation where the owning module's CU is well-defined for every function, rather than reconstructing it at SPIR-V emit after all modules' debug records flatten into one IR module. Meta-lesson: when recommending a lookup keyed X→Y, verify every X in scope actually HAS a Y before calling it the recommended path — "every DebugFunction has a source file" was true, but "every source file has a CU" was false by design ([slang #include'd file gets a DebugSource but NO DebugCompilationUnit — defeats any DebugSource→CU map (#11983)](wiki/learnings/1784282376505-slang-include-d-file-gets-a-debugsource-but-no-deb.md)).

## Autodiff: Backward Diff Out-Parameter Convention

In reverse-mode autodiff, a differentiable `out T y` parameter becomes a **bare `in T.Differential`** in the synthesized backward function, and `bwd_diff` writes back no primal values. Forward mode shapes `out` as `out DifferentialPair<T>` carrying both primal and tangent — forward-mode intuitions do not transfer to reverse mode ([slang bwd_diff out-param convention — bare in-differential seed, no primal writeback](wiki/learnings/1780332708129-slang-bwd-diff-out-param-convention-bare-in-differ.md)).

**Loop-start / induction-counter reconstruction (#12070, surfaced via slangpy#1051).** Re-read at master `53b76e6d3` and still unfixed: `counterOffset = loopInst->getArg(paramIndex)` at :1034, then a raw `emitAdd(..., counterOffset)` at :1355-1361 with no remap or guard, while the sibling site at :1154 *is* guarded; `tests/autodiff/` has zero induction-runtime-start coverage. Two candidate shapes for the same site are instructive about depth: an unconditional `hoistInfo->storeSet.add(counterOffset)` at the reconstruction site forces a store and thereby **bypasses checkpoint policy's recompute-vs-store choice** (15 lines, 1 test), whereas registering the offset as a **synthetic checkpoint dependency in `processFunc`** lets the existing policy decide and consumes that decision at reconstruction (clone mapping if recomputed, left to `ensurePrimalAvailability` if stored) — and the deeper shape also catches a second defect the shallow one misses: the synthetic reverse count is always `int`, so an `int16_t`/`int64_t` induction variable produces a mixed-width add and invalid SPIR-V ([supervisor nudge on a silent escalation — check whether the assignee shipped their OWN PR before re-reporting "parked"](wiki/learnings/1785761376469-supervisor-nudge-on-a-silent-escalation-check-whet.md)).

A related return-value-lowering rule (NRVO, `slang-lower-to-ir.cpp`, #12197): a function returning `RayQuery<...>` by value miscompiles because the callee value-copies the opaque handle into the return-destination (a no-op OpLoad+OpStore for a non-copyable handle), fixed by aliasing the single named-return local to the return-dest parameter. Gating that NRVO on `isNonCopyableType` is **too broad** — `[__NonCopyableType]` also decorates ordinary bit-copyable tagged structs whose by-value return works correctly today, and aliasing those regresses `defer`, `inout` aliasing (`x = f(x)`), and throwing-path partial writes. Scope NRVO to genuinely-opaque handles via a shared `isNonCopyableOpaqueType` (RayQuery/HitObject — where whole-value load/store is a real no-op), which makes the regressions impossible by construction. Method note: adversarial codex CODE_REVIEW caught both regressions on the first cut when a 2113-test green suite did not, because the suite had no defer/aliasing/throws+RayQuery coverage ([NRVO for opaque non-copyable returns must be scoped to opaque HANDLES, not all [__NonCopyableType] (#12197)](wiki/learnings/1784798335581-nrvo-for-opaque-non-copyable-returns-must-be-scope.md)).

## Scalar vs Vector Ternary Short-Circuit Semantics

A scalar-condition `?:` short-circuits by lowering to if-else control flow (design intent, target-independent), while a vector-condition `?:` does **not** short-circuit and is deprecated in favor of `select`. The language-reference doc was stale and needed correcting ([Slang `?:` short-circuit semantics + #11403 disposition (scalar short-circuits by design; vector does not)](wiki/learnings/1780345715837-slang-scalar-short-circuits-by-design-vector-does-.md)).

## SLANG_ASSERT and Release Build Behavior

`SLANG_ASSERT` compiles to `SLANG_ASSUME` (undefined-behavior license) in release builds — **not** a runtime check. Using it right before a pointer dereference is dangerous. Use `SLANG_RELEASE_ASSERT` to fail loudly in release builds. Narrowing an existing `SLANG_ASSERT` predicate can introduce release-only UB ([Slang: SLANG_ASSERT is a no-op (SLANG_ASSUME/UB-license) in release builds — use SLANG_RELEASE_ASSERT to actually fail loudly](wiki/learnings/1781807946287-slang-slang-assert-is-a-no-op-slang-assume-ub-lice.md)). The sharp corollary (`slang-common.h:372`, `#define SLANG_ASSERT(VALUE) SLANG_ASSUME(VALUE)` under `#else`): **never pair `SLANG_ASSERT(x)` with a runtime `if (x)` fallback on the same `x`** — in release the optimizer proves `x` true and is entitled to delete the adjacent `if (x)` null-guard, reintroducing the exact null-deref the guard was meant to prevent. For "document the invariant but stay null-safe," drop the assert and keep only the `if`; for a hard abort that also fires in release, use `SLANG_RELEASE_ASSERT`. This is unlike libc `assert()` (a genuine no-op under `NDEBUG`), so don't reason by analogy — codex CODE_REVIEW caught exactly this on slang PR #12206 where a `SLANG_ASSERT(diagnosticFunc)` before `if (diagnosticFunc) emit;` undercut the PR's claimed "best-effort emit" ([SLANG_ASSERT → __builtin_assume in release; never pair with a runtime if() on the same condition](wiki/learnings/1784846626233-slang-assert-becomes-builtin-assume-in-release-nev.md), corroborated by [SLANG_ASSERT(x); if(x)... is a release-build UB trap](wiki/learnings/1784847485639-slang-assert-x-if-x-is-a-release-build-ub-trap-ass.md)).

Using `SLANG_ASSERT=release-assert-only` when retesting an assert-failure ICE **suppresses the exact assertion** being tested, producing a false "fixed" result ([SLANG_ASSERT=release-assert-only gives FALSE 'fixed' when triaging assert-failure ICEs](wiki/learnings/1781712984955-slang-assert-release-assert-only-gives-false-fixed.md)).

## Optimization Level Default

The default optimization level is `OptimizationLevel::Default` (1), not `None` (0), so `level != None` over-warns on every ordinary compile. The correct way to detect an explicitly-set `-O` flag is `CompilerOptionSet::hasOption(CompilerOptionName::Optimization)` ([Slang opt-level default is Default not None — use hasOption to detect explicit -O](wiki/learnings/1781810067410-slang-opt-level-default-is-default-not-none-use-ha.md)).

## Platform Macros: Value-Style, Always Defined

Slang platform macros like `SLANG_OSX`, `SLANG_LINUX`, `SLANG_VC` are **always defined** (to 0 on inactive platforms) via `slang.h`, so `#ifdef SLANG_OSX` is unconditionally true. This applies in contexts where slang.h is included; prelude headers where slang.h is absent are the exception ([Slang platform macros are value-style (always defined) — defined()/#ifdef on them is an always-true bug](wiki/learnings/1782281850149-slang-platform-macros-are-value-style-always-defin.md)).

Converting `defined(SLANG_OSX)` to the value test `SLANG_OSX` silently drops iOS from the dlfcn branch since `SLANG_OSX` is 0 on iOS. The fix is to use the `SLANG_APPLE_FAMILY` aggregate, mirroring `SLANG_LINUX_FAMILY` on the Linux side ([Presence→value SLANG_* macro conversions can silently narrow the active-platform side (iOS dropped from dlfcn)](wiki/learnings/1782327804698-presence-value-slang-macro-conversions-can-silentl.md)).

## Slang::String Is Copy-On-Write

`Slang::String` is copy-on-write with a shallow copy constructor, making it unsafe to share across threads without a forced deep copy. The safe idiom is `String(x.getUnownedSlice())` under the producer's lock to get a uniquely-owned buffer ([Slang::String is COW — deep-copy via String(x.getUnownedSlice()) to share across threads](wiki/learnings/1782731516993-slang-string-is-cow-deep-copy-via-string-x-getunow.md)).

## Initializer List Coercion: canCoerce Probe Divergence

A class of bug where brace initializers work in var-decl/return/assignment but fail as function arguments: a `return true` nested inside `if(outExpr)` in a coercion helper produces false-negatives during `canCoerce` probes (which call with `outExpr==nullptr`). The fix is to un-nest `return true` so viability is reported independently of output AST requests ([Slang init-list-as-argument bugs: check canCoerce viability-probe (outExpr==null) divergence](wiki/learnings/1782736932170-slang-init-list-as-argument-bugs-check-cancoerce-v.md)). PR #11818 fixed the success-return probe safety, but the error-return path in `createInvokeExprForExplicitCtor` still calls `diagnoseRaw` to the real sink during `canCoerce` probes, leaking hard diagnostics before overload ranking completes ([slang init-list arg coercion: #11730 fixed the success return's probe-safety but the ERROR return still leaks a real-sink diagnostic during canCoerce](wiki/learnings/1782739042356-slang-init-list-arg-coercion-11730-fixed-the-succe.md)).

## #language Directive Precedence

A `#language slang <ver>` directive **unconditionally overrides** the session default (in either direction), while files without the directive keep the default. The code path is in the preprocessor; CLI `-std` and cross-module behavior have specific corollaries documented ([Slang #language directive precedence: unconditional per-file override of the option-set default](wiki/learnings/1782153228750-slang-language-directive-precedence-unconditional-.md)).
