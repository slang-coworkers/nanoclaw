## TL;DR

- **A critique-endpoint 429 is retryable transport, NOT a review outcome.** Back off (60s→180s→300s via a *background* sleep loop; foreground sleep is blocked) and retry the SAME critique call — do not record `ABSTAIN_INFRA:CRITIQUE_UNAVAILABLE` on a passing endpoint's bad minute.
- **Sequence ALL mutations before the final OUTPUT_REVIEW.** The delivery gate's freshness check counts edits since the critique — including native auto-memory writes, `work/<pr>/` artifacts, and even a scratch `> /tmp/foo`. A post-review edit forces a re-run. Freeze artifacts after the review.
- **Each `mcp__codex__codex` call is a FRESH session with no memory of prior rounds.** A thin "nothing changed, re-confirm" prompt strips the framing and codex reverts to a naive reading. Restate the decider's hard constraints (read-only; deliverable = the decision message, NOT the author's diff; severity governed ONLY by the skill's Step-3 rubric) IN THE PROMPT every round. Re-running with the SAME complete framing is legitimate; thinning framing until it agrees is the anti-pattern.
- **Codex is authoritative on FACTS but not on the REMIT of an approval decision.** When its only surviving must-fix lints the AUTHOR's code (a change-history comment, verbose prose) or proposes a remedy you cannot perform (amend the PR, push a commit), it has mis-scoped — those rules govern a diff *you* author, not a third-party PR you decide on read-only. Do NOT round a style opinion up to BLOCK (needs a verified 🔴 bug) or down to a false ABSTAIN.
- **Two different gates share the word "critique."** The skill's abstain relaxation applies to the `record_decision` host append (abstain rows record without recorded verdicts). The `gate-critique-on-deliver.sh` **overlay hook** is separate, does NOT honor the abstain exemption, and pattern-matches PR-creation-shaped strings — including read-only `gh api .../pulls`/`compare` bash. Don't argue exemption; just run `/codex-critique` once per stage. Route GitHub reads through the slang-mcp tools or a python subprocess wrapper to avoid tripping it.
- **`record_human_verdict` is NOT an exposed tool** — the host joins the human outcome automatically from the GitHub webhook (keyed by delivery id). Never claim you "recorded the human verdict." On a merge/close join your only actions are the calibration `append_learning` and mining the decision→merged-head diff.
- **On a bot-fixer branch, production Claude review + CodeRabbit are skipped, leaving Devin the SOLE review signal** — and Devin's cache can lag a fresh push. A head-stale Devin means no head-current review tier ⇒ correct infra-abstain. The fix is a head-pinned review signal, not a challenger override. Score such infra-abstains against the pipeline gap, never as code disagreement or false-safe.
- **Scope a recall/helper subagent with a hard negative boundary** ("Do ONLY X. Do NOT run scripts, synthesize docs, or make/record any decision"). A capable subagent will expand fuzzy scope and run the whole pipeline; a decision it reaches was NOT made through the procedure and must be re-derived, never adopted on trust.

## The critique gate and its transport failures

The approver's `gate-critique-on-deliver.sh` hook is fail-closed: it blocks `record_decision` / the `[Approval Decision]` marker until DECISION_REVIEW and OUTPUT_REVIEW are recorded with verdict=approve. That makes the codex MCP endpoint a delivery dependency, and its transient failures masquerade as review outcomes. A 429 rate-limit is CRITIQUE_UNAVAILABLE-shaped but transient; recording `ABSTAIN_INFRA` on it abstains a sound decision over a passing endpoint's bad minute. The correct move is a background backoff-and-retry of the same call (it cleared on the ~5th attempt), and because the 429 fails at the codex call itself it never reaches a `record_decision` attempt, so retrying is free of the 3-denial soft-cap ([OUTPUT_REVIEW 429 backoff](../learnings/1786764325591-approver-critique-infra-output-review-codex-429s-b.md)).

The freshness half of the gate is unforgiving: `track-edits.sh` bumps `edits_since_critique` for any file write outside its allowlist — the native auto-memory tree, `work/<pr>/` artifacts, even a scratch `> /tmp/foo` — and the byte-identical sha256 of the deliverable does not save you. Finish ALL memory/learning writes and scratch/clause-extraction writes BEFORE the final OUTPUT_REVIEW, then freeze ([429 backoff, ordering rule](../learnings/1786764325591-approver-critique-infra-output-review-codex-429s-b.md); [oscillation, scratch-write bump](../learnings/1787738196820-approver-critique-mustfix-output-review-oscillates.md)).

## Codex scope errors: facts vs. remit

The most expensive recurring failure is codex applying its own developer-instruction comment-hygiene rule — written for reviewing *your own code diff* — to the third-party PR the approver is only DECIDING on read-only. It surfaced on CI-tuning PRs where the author added a verbose change-history comment: codex demanded BLOCK, then ABSTAIN_POLICY/CRITIQUE_MUSTFIX, across 3+ rounds, even while conceding the change was functionally sound and a MEMBER had cleared it ([codex escalates author comment-hygiene](../learnings/1787317426535-approver-critique-mustfix-codex-escalates-author-c.md)). The clean discriminator that ends the round early: **which artifact does the must-fix point at?** On slang#12968 codex's DECISION_REVIEW returned must-fix on `source/standard-modules/CMakeLists.txt:54` (a `# Build the experimental functional module` comment restating the following `add_subdirectory(functional)`) while its own Notes said the derivation was sound and no evidence gap required ABSTAIN — a line in the **PR-under-review's diff**, not in one of *your* synthesized artifacts (`clauses.json`, `review-doc.md`, `investigation.md`, `decision.md`) [comment-hygiene must-fix on the author's diff is an out-of-scope misfire](../learnings/1788983445996-approver-critique-mustfix-codex-comment-hygiene-ru.md). That is definitionally out of scope: DECISION/OUTPUT review governs the *decision derivation and deliverable*, not the author's code style, and the approver is read-only against GitHub and never edits the PR. It was also false on the merits (every `add_subdirectory(X)` in that file carries a matching `# Build the … module` comment, so removing this one introduces inconsistency). Do NOT abstain or "fix" author code; reply on the same codex thread re-scoping the review to the derivation + deliverable (and, if apt, that the flagged line matches the file's own convention), then ask codex to re-verify — it approved immediately, ~1 extra round. Author-side style nits map at most to an APPROVE_WITH_NITS-class advisory and never block the decision. Because each codex call is a fresh session, a bare "re-confirm" prompt lets it revert to this naive reading, producing OUTPUT_REVIEW oscillation (must-fix → approve → must-fix) — the APPROVE rounds were exactly the ones where the read-only invariant, "deliverable = the decision message," and the Step-3 severity rubric were restated in the prompt ([OUTPUT_REVIEW oscillates without framing](../learnings/1787738196820-approver-critique-mustfix-output-review-oscillates.md)).

The disposition rule: separate accuracy from style. Fix every factual issue in your own artifacts (codex's factual catches are reliably correct — GA-not-preview, a real SAST finding, caller-set enumeration), but a residual must-fix that lints the author's file or proposes a remedy you cannot perform (amend/push) has mis-scoped the review. Do not round a style opinion into BLOCK (which requires a verified 🔴 bug) — that is a scored false-block against the human approve — nor cave to a false ABSTAIN. When the churn cannot be resolved and every revision you *can* make is made, the correct terminal state is ABSTAIN_POLICY/CRITIQUE_MUSTFIX (policy family, excluded from agreement scoring by state, still joined against the human outcome). The escalation path is a genuine hazard: an `ask_user_question` tiebreaker on a low-stakes author-facing nit will usually time out, and the timeout DETERMINISTICALLY produces an ESCALATED false-abstain ([escalated, tiebreaker timed out](../learnings/1787753889540-approver-infra-abstain-escalated-codex-applied-aut.md)). Prefer an escalation that resolves to the merits verdict, not to ABSTAIN, when the code is already human-approved. Class rule: ESCALATED reason_codes that originate from a *scope disagreement with the critique tool* are process false-abstains — distinguish them from genuine escalations (real unresolved gap, real harness fail); only the latter should consume a human tiebreaker.

## Two gates named "critique"; the record_human_verdict phantom

A subtle infra trap: the skill's statement that "ABSTAIN_POLICY is NOT critique-gated" applies to the host `record_decision` *append* — but the `gate-critique-on-deliver.sh` **overlay hook** is a separate mechanism that guards delivery-marker / PR-creation-shaped tool calls and does NOT honor the abstain exemption ([deliver-gate hook is separate](../learnings/1788865668481-approver-infra-abstain-the-deliver-gate-critique-h.md)). It even pattern-matches read-only `gh api .../pulls/<n>/reviews|comments` and `.../compare/...` bash as "PR creation." Arguing exemption gets a bypass request admin-rejected and burns the denial cap; the fix is to run `/codex-critique` once per named stage (for an abstain, DECISION_REVIEW just confirms "clause FAIL → ABSTAIN per skill" and OUTPUT_REVIEW checks the 5-bullet shape), and to route GitHub reads through the slang-mcp `github_get_pull_request_reviews`/`_comments` tools or a python subprocess wrapper (`gh pr view`/`gh pr diff` as direct commands are also fine).

`record_human_verdict` is a documented-but-nonexistent tool: SKILL.md instructs calling it on `pr_review`/`pr_merged`/`pr_closed`, but it is not in the approver's MCP set, because the host stamps human verdicts itself from the webhook (`notifyApproverOfTerminalPr`, keyed by delivery id) and the guard denies the container-originated action unconditionally ([record_human_verdict not exposed](../learnings/1787049708429-approver-clause-gap-skill-md-tells-you-to-call-rec.md); [correction — missing ROW not missing tool](../learnings/1786377397682-approver-infra-abstain-correction-to-the-record-hu.md)). Never claim you recorded the human verdict — OUTPUT_REVIEW will correctly flag it as unsupported. On a join your only real actions are the calibration `append_learning` (merged ⇒ APPROVED-equivalent; closed-unmerged ⇒ CHANGES_REQUESTED-equivalent) and mining the diff. The correction atom also carries a sharp same-symptom/different-cause lesson: a join can still fail on a PR with NO recorded row (a denied ledger append from an unset `APPROVAL_LEDGER_WRITERS`), which looks identical to the missing-tool symptom but only the ledger-writer fix addresses it — discovery order is not causal order, so before reporting "X breaks Y," ask what Y would do if X were fixed. It also pins a measurement-scope rule: one measurement covers one scope (the stale instruction sits at different line numbers per skill — `:180/:190` slangpy vs `:182/:192` slang), so a claim of "both A and B" from measuring only A is an unmeasured claim wearing verified clothes.

## The single-review-tier gap and subagent overrun

On bot-fixer branches, production's claude-code-action review and CodeRabbit are both skipped by design (harvest exit 20), leaving Devin as the sole automated signal — and Devin's cache can lag a fresh push, describing a prior revision. When that happens there is no demonstrably head-current review tier, and the approver correctly abstains rather than substitute its own code read ([Devin-only tier forces infra-abstain](../learnings/1787361513735-approver-infra-abstain-confirmed-by-merge-the-devi.md)). Confirmed by #12417 merging clean at the exact decided head: the abstain was neither over-caution on substance nor a false-safe — it was driven entirely by review-signal integrity. The lever that closes the gap is a *head-pinned* Devin (verify the returned commit-status equals the pinned SHA; re-trigger and poll if stale, like the harvest tier waits on `pending_bot`/exit 22), NOT a challenger override. Score this shape as an infra miss against the pipeline gap, never as code disagreement.

Finally, subagent discipline: a Step-0 recall subagent, dispatched ONLY to "return ≤5 bullets," instead ran the entire decision pipeline (synthesized review-doc.md, ran eval-clauses, wrote investigation.md, reached a verdict, and was mid-critique) because the recall prompt named the PR richly enough to let a capable general-purpose agent expand the fuzzy scope ([recall subagent overran](../learnings/1787049658061-approver-infra-recall-subagent-overran-its-task-an.md)). A decision reached by an unscoped subagent was NOT made through the procedure and must not be adopted on trust — even if it lands on the right verdict. Scope helper subagents with an explicit negative boundary, and when any subagent returns more than its remit, re-derive the extra work yourself; its coherent decision narrative is exactly the coherent-and-false failure mode ("read the artifact, not the framing," applied to a subagent).
