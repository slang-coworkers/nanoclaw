# Slang Backends Spirv 2 Pipeline

## TL;DR
- `slang-glslang` IS the SPIR-V backend (it bundles SPIRV-Tools/spirv-opt and has nothing to do with GLSL). It is always a runtime-loaded module: a missing module is a build/packaging fix, never a reason to make its load optional. Opt out of one pass through a dedicated CMake escape hatch, not by deleting it.
- Default optimization runs spirv-opt, `-target spirv-asm` included; only `-O0` skips it. Reproduce at `-O0` before blaming the emitter. `private-to-local` breaks function-`static` persistence.
- spirv-opt's LoopUnroll does not fire on Slang's `[unroll]` loops at -O2/-O3, because a trampoline block still precedes the merge when it runs; DXC and NVRTC fold the same loops. A `[ForceUnroll]` bound built from integer `abs`/`min`/`max` gives E40020, since those are opaque intrinsics in Slang IR.
- An assert/crash inside `external/spirv-tools` is an upstream bug: file it upstream and mark the Slang test expected-failure.
- Granular pass control goes through `spvtools::Optimizer::RegisterPassesFromFlags`, not a hand-maintained flag→pass table.
- A clean `slangc` exit proves nothing about validity. Validate with `SLANG_RUN_SPIRV_VALIDATION=1` (CI always sets it; `//TEST:SIMPLE` FileCheck never validates); never use the system `spirv-val`; `-skip-spirv-validation` only to inspect output.
- Validator silence proves nothing in either direction. Any "is this valid SPIR-V?" claim that gates a diagnostic or a test change must cite the Khronos spec text, not DeepWiki.
- A VUID that fires only in a system Vulkan validation layer newer than the embedded spirv-tools is version skew, not a regression.
- `-emit-spirv-via-glsl` is the A/B reference. The direct and GLSL paths diverge (e.g. depth execution modes), so check both.
- SPIR-V debug-info defects are almost always producer-side (lowering, IR type gates). `slang-emit-spirv.cpp` is usually innocent, except for debug composites, which the emitter builds itself and therefore owns.
- `-g0` still emits `OpSource`/`OpName`/`OpMemberName` by design (SPIR-V only; documented in help text).
- `-g2` embeds the whole source, CHECK lines included, as an `OpString`: anchor patterns on `%id = OpString "name"` and on real instruction lines, or they self-match.
- A hoistable IR inst dedups only if every producer builds byte-identical operands; path strings are the classic divergence.
- `IRDebugScope` is variable-arity (1 or 2 operands); never build it with a null operand.
- A matrix's debug type is layout-independent: `OpTypeMatrix` is the same for all layouts, and packing rides the member decoration plus `MatrixStride`.
- Opaque-handle locals: the emitter already handles them (`OpDebugLocalVariable` + `OpDebugValue`, no backing `OpVariable`). Admit them at the leaf/creation type gates with a narrow texture/sampler predicate, never inside recursive `isDebuggableType`, and cover both `let` and `var`.
- DebugVar type-eligibility and DebugValue value-representability are separate checks. Drop only a value shape confirmed illegal by a test, never arrays wholesale.
- DebugVar `ArgNumber` remapping across param-removing passes is cross-cutting: flag it to the maintainer instead of patching locally.
- `SV_Target<N>` is the only varying semantic whose suffix is an absolute location. User-defined suffixes are names, so GLSL/SPIR-V locations follow declaration order; never genericize suffix→location.
- Gate capability emission on `targetCaps.implies(CapabilityAtom::spvFooEXT)`, never `isSPIRV()`. A capdef atom alone is inert.
- Check that a decoration is produced on the same IR module (codegen vs layout/reflection) that its consumer reads.
- A runtime test for a new Vulkan extension needs a slang-rhi `SLANG_RHI_FEATURES` entry first. The order is: slang-rhi PR → pin bump → slang test PR.
- Local verification: put `build/Debug/lib` first in `LD_LIBRARY_PATH`, and write binary SPIR-V to a real temp path (not `/dev/null`).
- Containers have an NVIDIA GPU for compute only: installing `libvulkan1` gives software llvmpipe, so Vulkan execution belongs in CI. RHI builds need `libx11-dev`.

## spirv-opt / slang-glslang Integration

`slang-glslang` is always runtime-loaded, never static-linked. A static build missing it needs a build-system fix, not a non-fatal load ([slang-glslang: don't mask its load as optional](../learnings/1782152994624-slang-glslang-is-the-spir-v-backend-don-t-mask-its.md)). Pass opt-out follows `SLANG_ENABLE_SPIRV_OPT_MERGE_RETURN`: `advanced_option` + compile definition via `CompilerFlags.cmake` + `#if` around ALL registrations, dead `#if 0` blocks included ([CMake escape-hatch opt-out](../learnings/1781975592365-slang-glslang-add-an-opt-out-via-dedicated-cmake-e.md)).

**The spirv-opt load is fatal via the real sink:** `createArtifactFromIR` always calls `getOrLoadDownstreamCompiler(SpirvOpt, getSink())`, so a missing `slang-glslang` poisons the sink with E00100 before any output guard. Optional callers pass a `nullptr` sink; absence is unit-testable via `setSharedLibraryLoader` ([optional spirv-opt is fatal via real sink](../learnings/1781799089141-slang-downstream-compiler-load-optional-spirv-opt-.md), [absence IS unit-testable](../learnings/1781804734767-slang-downstream-compiler-absence-spirv-opt-slang-.md)).

**Default optimization runs spirv-opt**, including `CreatePrivateToLocalPass`, even for plain `-target spirv-asm` ([default opt DOES run spirv-opt](../learnings/1781714495665-slangc-target-spirv-asm-at-default-opt-does-run-sp.md)). It demotes a `Private` var used in one function to `Function` storage, breaking function-`static` persistence; the fix removes both live registrations ([function-static state loss = private-to-local](../learnings/1781713084820-spir-v-function-static-state-loss-spirv-tools-priv.md)).

**Granular pass selection (#12204):** `-OX` levels are hand-unrolled presets (~40 `RegisterPass` calls, `slang-glslang.cpp:316`). Use bundled `spvtools::Optimizer::RegisterPassesFromFlags(flags)` (`optimizer.hpp:140`); the pass string crosses the C ABI as a new `glslang_CompileRequest_1_3`. No correctness risk (spirv-opt is size/perf only), but it ties the CLI to the bundled SPIRV-Tools version ([RegisterPassesFromFlags is the clean primitive](../learnings/1784829679560-granular-spvopt-pass-selection-registerpassesfromf.md)).

**fp8 constants abort in spirv-tools:** `GetWordsFromScalarFloatConstant` (`opt/folding_rules.cpp`) asserts width 16/32/64 (the integer sibling handles 8). Upstream fix #11766; Slang expected-failure #11744 ([fp8 width-8 gap](../learnings/1782449605671-fp8-scalar-float-constants-abort-in-spirv-tools-co.md)).

**spirv-opt's LoopUnroll skips Slang's `[unroll]` loops at -O2/-O3.** Slang lowers `[unroll]` to `OpLoopMerge … Unroll`, yet a constant-trip loop such as `for (i = 0; i < 10; ++i) sum += i` survives the bundled preset (`slang-glslang.cpp:493`, the same order as upstream `RegisterPerformancePasses`). `Loop::FindConditionBlock` (spirv-tools `loop_descriptor.cpp:619`) requires the merge block's single in-loop predecessor to be the `OpBranchConditional`, but at that point in the preset Slang's output still has a trampoline `%x: OpBranch %merge` left by the breakable-region wrap, and BlockMerge runs only later. Running `spirv-opt -O` twice, or adding BlockMerge just before LoopUnroll, unrolls and folds the loop to a constant. DXIL (DXC) and PTX (NVRTC) fold such loops with no hint, so "loop not folded at -O3" reports are SPIR-V-specific. Two related folding limits: spirv-opt has no GLSL.std.450 `SAbs` constant-fold rule (`SMin`/`SMax`/`SClamp` exist), and in Slang IR integer `abs`/`min`/`max`/`clamp`/`sign` are opaque target-intrinsic calls, so a `[ForceUnroll]` bound built from them gives E40020 while the ternary form folds (#13424) ([spirv-opt LoopUnroll silently skips Slang's [unroll] loops at -O3](../learnings/1791074922027-spirv-opt-loopunroll-silently-skips-slang-s-unroll.md)).

## Debug Information

**`-g0` (DebugInfoLevel::None) emits exactly `OpSource`, `OpName`, and `OpMemberName`.** `OpSource` is unconditional; names come from `IRNameHintDecoration`, which `stripDebugInfo` (removes only `IRDebug*`) keeps. `OpLine` and the `DebugSource` `OpString` are g1+; `OpModuleProcessed` is never emitted. SPIR-V-specific (DXIL/HLSL/Metal `-g0` emits nothing). Help text documents this (#11682/#12201). For "g0 still emits X", check whether X is a direct `emitInst` or a surviving decoration ([-g0 doesn't zero debug info](../learnings/1782145409789-slang-g0-doesn-t-zero-spir-v-debug-info-opsource-o.md), [-g0 emits EXACTLY these three](../learnings/1784828289031-g0-debuginfolevel-none-emits-exactly-opsource-opna.md)).

**Constructors.** Synthesized `$init` ctors (#11550) are lowered like user functions, so they get `DebugFunction`/`DebugScope`. Suppressing only the function scope leaves body `DebugLine`s behind and produces invalid NonSemantic SPIR-V, so gate on AST flavor (`SynthesizedDefault | SynthesizedMemberInit`) during lowering ([synthesized $init ctors](../learnings/1781168370965-slang-synthesized-init-ctors-get-full-source-level.md)). A user `__init`'s `this` (#11565) is a synthesized local, not an `IRParam`. After `thisVar` is emitted (`slang-lower-to-ir.cpp:13839`), add a "this" name hint and an `IRDebugLocationDecoration` ([__init lacks `this`](../learnings/1781206942083-slang-user-defined-init-lacks-this-in-spir-v-debug.md)).

**Name hints.** `ExtensionDecl` is anonymous, so redirect `getNameForNameHint` through the extended type's decl. Name hints also feed C-like emitter identifiers (HLSL/CUDA) ([getNameForNameHint](../learnings/1781267563910-getnamefornamehint-feeds-c-like-emitter-identifier.md)).

**`IRDebugScope` arity.** Use 1 operand when `inlinedAt` is absent, otherwise 2. A null operand crashes `buildEntryPointReferenceGraph` (`slang-ir-call-graph.cpp:~85`) ([DebugScope variable-arity](../learnings/1781568128097-spir-v-debugscope-must-be-variable-arity-null-ir-o.md)).

**`-g2` FileCheck self-match.** Because the embedded source contains the CHECK directives, a bare-word `CHECK-NOT` falsely fails. Anchor on `%id = OpString "name"` (closing quote right after the name), and bind `DebugValue`→`DebugLocalVariable` through a captured id ([embedded-source self-match trap](../learnings/1781176200581-slang-g2-spirv-asm-filecheck-tests-embedded-source.md)).

**`-g2` + `import`/`#line` cluster (#11982/#11983/#11984, not dups).** All three are producer-side bugs in `slang-lower-to-ir.cpp`; the consumer (`slang-emit-spirv.cpp` ~:2136) is innocent. (1) DebugFunction scope is now carried in IR (`IRDebugFunction` `parentScope`, operand 5), so an imported function resolves to its own module's CU; see [[wiki/concepts/slang-backends-spirv-debug-function-info.md]]. (2) A duplicate `DebugSource` for one file comes from two producers spelling the path differently (`getMostUniqueIdentity()` relative vs `getName()` absolute), which defeats `hoistable=true` dedup ([#11982](../learnings/1783466061131-slang-11982-duplicate-spir-v-debugsource-from-dive.md)). (3) A BOM in `DebugSource` for a `#line` file appears because the fresh-read fallback `getOrEmitDebugSource` bypasses `SourceFile::setContents`'s BOM strip; decode in the fallback ([#11984](../learnings/1783468265984-slang-11984-g2-debugsource-for-line-files-bypasses.md)). `-dump-ir` is authoritative on whether dedup happens; DeepWiki got this one wrong.

**`DebugTypeMatrix`, col-major constant-buffer member (#12757):** emits `(vec2, 3, false)` instead of `(vec3, 2, true)`. The emit site (`slang-emit-spirv.cpp:11108-11138`) keys off the source `getLayout()`, and `normalizeMatrixDebugType` (:10899) returns early for buffer types, so only these members are wrong. The fix is the layout-independent `(vec(getColumnCount()), getRowCount(), true)`; packing stays on the member decoration (:7054-7078, where Slang's naming is reversed relative to SPIR-V). Not a regression: PR #9708 (Fixes #9325, by the reporter) made it deliberate, so get sign-off. Update `tests/spirv/debug-matrix-layout.slang` (lines 54/63) and re-check `debug-matrix-layout-non-buffer.slang`. Reproduces with `-target spirv-asm -g2` ([DebugTypeMatrix keys off source layout](../learnings/1787695833712-spir-v-debugtypematrix-keys-off-source-matrix-layo.md)).

**Opaque `DebugTypeComposite` (#12807):** the fallback (`:11241-11255`) emits `Size` as integer 0 (:11253); it should be `DebugInfoNone` (ext-inst op 0), using a cached `getDebugInfoNone()` that mirrors `getDwarfExpr()` (:10552-10563). It also reuses `name` as the LinkageName (:11252). The requested `"@Texture2D"` is a literal `"@"+Name`, not IR mangling (`getMangledTypeName` gives `_ST…`): check a helper's output against the reporter's expected text. The emitter builds composites itself, so it is the producer. The struct branch (:11069/:11075) has the same LinkageName defect; whether to fix it there is the maintainer's call ([`"@"+Name` is not IR mangling](../learnings/1787878146168-spir-v-debug-composite-issue-requested-name-linkag.md)).

**Opaque resource/sampler locals get no debug info (#12918, PR #12919).** Two upstream type gates cause it: `isDebuggableType` (`slang-ir-insert-debug-value-store.cpp` ~L22-104; defaults true only for `IRBasicType`; the pass runs before `constructSSA`) and spirv-legalize's `isSimpleDataType` (`slang-ir-util.cpp:356`) strip. The emitter is already correct: `emitDebugVarDeclaration` (`slang-emit-spirv.cpp:4676`) emits `OpDebugLocalVariable`, skips `OpDebugDeclare` when there is no backing var, and binds through `OpDebugValue`. Fix rules:
- Admit texture/sampler leaves with a narrow predicate, not broad `isResourceType` (which unwraps arrays and matches buffers). Do it at the leaf/creation sites, never inside recursive `isDebuggableType`: `isAllowedDebugVarType` accepts structs, so a struct holding a handle would become an illegal Function `OpVariable`.
- `processDebugVar`'s strip is dead code here, because `emitDebugVar` (`slang-ir.cpp:3614/3619`) always builds a pointer-typed DebugVar. Relax `processDebugValue` instead.
- `let x = t;` creates no `IRVar` (its debug info comes from the LetDecl case in `visitVarDecl`), so test both `let` and `var`.
- Drop combined texture-sampler DebugValues (`isCombined()` → `OpTypeSampledImage`, not a legal operand). Keep arrays: `InputPatch`/`OutputPatch` are legal (`tests/spirv/tessellation`).
- `cleanUpVoidType`'s `argIndexRemap` uses all-params positions, but earlier legalization strips empty params without remapping, so advancing the index for every param breaks `debug-var-void-argument.slang`. Flag this to the maintainer.

Sources: [root cause = two type gates](../learnings/1788744414687-slang-spir-v-opaque-resource-sampler-function-loca.md), [leaf/creation gates, let-path, dead processDebugVar](../learnings/1788748635093-slang-spir-v-opaque-handle-local-debug-info-fix-at.md), [value-operand limits & ArgNumber remap](../learnings/1789468940215-slang-spir-v-debug-var-value-operand-limits-param-.md).

## Depth Output and Topology Execution Modes

**Depth.** For `SV_DepthGreaterEqual`/`SV_DepthLessEqual`, the direct SPIR-V path emits `DepthReplacing` plus `DepthGreater`/`DepthLess`, while the GLSL/via-GLSL path drops the directional mode. On the direct path, when two depth-affecting builtins coexist (e.g. `SV_Depth` + `SV_DepthGreaterEqual`), `maybeEmitEntryPointDepthReplacingExecutionMode` collapses to `DepthReplacing` only, through its `else if (mode != thisMode)` conflict branch ([GLSL drops directional mode](../learnings/1782165817624-slang-sv-depth-greater-less-equal-direct-spir-v-co.md), [direct path also drops via conflict branch](../learnings/1782211031715-slang-direct-spir-v-depth-mode-also-dropped-via-co.md)). In `slang-ir-glsl-legalize.cpp`, gate a new entry-point system-value decoration on `kind == LayoutResourceKind::VaryingOutput`, as `sv_position` does (~478-498), and add the op to `isSimpleDecoration` (`slang-ir.cpp` ~86) so duplicates collapse. For depth this is only defense-in-depth: depth semantics are setter-only in `core.meta.slang` (E30702), so the inout double-attach can't happen ([VaryingOutput gating](../learnings/1782175454099-glsl-legalize-per-entry-point-system-value-decorat.md)).

**Output topology (hull/domain).** The `kIROp_OutputTopologyDecoration` hull/domain arm handles only TriangleCW/TriangleCCW/Point. `Line` falls through to the mesh arm and emits `OutputLinesEXT`, which is invalid on tessellation stages. For isoline, `Line` should be a no-op because `OpExecutionMode Isolines` already implies it, and the fallback needs a stage guard ([hull/domain topology subset](../learnings/1780253722562-slang-spir-v-output-topology-hull-domain-arm-only-.md)).

## Varying-Parameter Location Assignment

`SV_Target<N>` is the only varying semantic that both consumes a GLSL/SPIR-V location and carries a suffix naming an absolute slot. In `processEntryPointVaryingParameter` (`slang-parameter-binding.cpp` ~:2064), it alone takes the `Output` layout; every other `SV_`/`NV_` semantic is a builtin with direction mask 0. In #11944, `systemValueSemanticIndex` is stored but never read, so an out-of-order `SV_TargetN` gets its location from declaration order. User-defined suffixes (TEXCOORD0, COLOR1) are name disambiguators: GLSL/SPIR-V assign those locations in declaration order, and HLSL matches stages by name. Deriving locations from those suffixes would break inter-stage matching, so the fix applies to SV_Target only. The `SV_TARGET<N>→LOCATION_<N>` translation in `fixFieldSemanticsOfFlatStruct` (`slang-ir-legalize-varying-params.cpp:3730`) runs only for Metal and WGSL. GLSL/SPIR-V read the VarLayout `index` in emit (`slang-emit-spirv.cpp:3445-3465`) ([SV_Target-N is the only absolute-location semantic](../learnings/1784321038825-slang-sv-target-n-is-the-only-varying-semantic-enc.md)).

## Capability and Version Gating

Triaging "add a SPIR-V capability bit" (#11538): grep `external/spirv-headers/include/spirv/unified1/spirv.h` first, because the operand is often already vendored and needs no submodule bump. A capdef atom (`def SPV_EXT_xxx` + `def spvXxxEXT`, each with `///` doc and an `[EXT]` tag) is inert until something consumes it. Adding one is `pr: non-breaking` ([capability-bit triage](../learnings/1781116222932-triaging-an-quot-add-a-spir-v-capability-bit-quot-.md)). Gate emission on `targetCaps.implies(CapabilityAtom::spvFooEXT)`, following `slang-emit-spirv.cpp:1692`, and add the extension string inside the block with `ensureExtensionDeclaration`. Never gate on `isSPIRV()`, which emits unconditionally ([use implies(), NOT isSPIRV()](../learnings/1781123971590-correction-spir-v-capability-emit-gating-use-impli.md)). `[require(spirv_1_5)]` failed to raise the version (#11631) because `IRRequireCapabilityAtomDecoration` reached only the layout IR module and never the codegen module that `determineSpirvVersion()` scans. The fix calls `addEntryPointRequireCapabilityDecorations()` from codegen lowering and maps internal `_spirv_1_x` atoms ([#11631 correction](../learnings/1781643037138-correction-to-11631-version-root-cause-require-ato.md)).

## Validation, Testing and Environment

**Validate explicitly:** `slangc` can exit cleanly on invalid SPIR-V ([require spirv-val](../learnings/dashboard_slang-triage-1776263007885.md)). CI sets `SLANG_RUN_SPIRV_VALIDATION=1`, so tests assuming validation is off fail there ([CI validation on](../learnings/1781825083619-ci-runs-slang-test-with-slang-run-spirv-validation.md)). `//TEST:SIMPLE` doesn't validate: making the `SPIRVLoadDescriptorFromHeap` heap operand (a pointer global at emit) a `uint` param passes FileCheck but yields an invalid access-chain base. Never parameterize it; pin the base in FileCheck ([heap operand is a pointer global](../learnings/1780769340224-spirvloaddescriptorfromheap-heap-operand-is-a-poin.md)). Binary `-o /dev/null` fails (E00004); use a real temp path.

**Cite the spec:** `external/spirv-tools/source/val/` has no operand-type rule for `OpConvertUTo*NV`, so validator behavior is uninformative. Read `raw.githubusercontent.com/KhronosGroup/SPIRV-Registry/main/extensions/<VENDOR>/<EXT>.asciidoc`; a self-hedging DeepWiki answer is not a citation ([cite the SPEC](../learnings/1785776557998-cite-the-spec-not-a-summarizer-spv-nv-bindless-tex.md)).

**Version skew.** The embedded spirv-tools is v2026.2 (HEAD ~2026-06). A VUID that fires only in a maintainer's Vulkan SDK 1.4.328+ layer is skew ([embedded vs system validator](../learnings/1782267495019-triage-discriminator-slang-embedded-spirv-tools-vs.md)).

**Local verify:** `build/Debug/lib` first in `LD_LIBRARY_PATH`; the staging `build/slang-<ver>-linux-x86_64/lib/` has a stale `libslang-compiler.so`, and disassembly needs its slang-glslang ([LD_LIBRARY_PATH trap](../learnings/1782733787106-slang-local-spirv-asm-verify-put-build-debug-lib-f.md)).

**Containers.** Building RHI targets on Linux needs `libx11-dev`, even headless, because the fetched Vulkan-Headers include `X11/Xlib.h` ([libx11-dev](../learnings/1780330247261-CONSOLIDATED-slang-rhi-vulkan-build-needs-libx11-dev.md)). `nvidia-smi` shows a GPU, so don't claim "no GPU". The container is provisioned for compute only (`NVIDIA_VISIBLE_DEVICES=void`), and CUDA is still Not Supported in slang-test because nvrtc is missing ([GPU present, no Vulkan loader](../learnings/1781698311286-this-environment-has-an-nvidia-gpu-nvidia-smi-work.md)). Installing `libvulkan1` gives software llvmpipe only, and the NVIDIA ICD fails with `ERROR_INCOMPATIBLE_DRIVER`, so `vk` stays Not Supported. Real-GPU Vulkan needs host-side device injection ([libvulkan1 does NOT enable NVIDIA Vulkan](../learnings/1781699613539-correction-installing-libvulkan1-does-not-enable-n.md)).

**Runtime tests for a new Vulkan extension:** slang-rhi's `SLANG_RHI_FEATURES` X-macro (`include/slang-rhi.h`) must have the feature: it generates the `rhi::Feature` entry and makes `-render-feature <name>` valid (render-test skips with `SLANG_E_NOT_AVAILABLE` if absent). The feature must also fit dispatch→readback→compare; `abort` (#11790) causes device loss and can't ([X-macro bridge](../learnings/1780969782467-slang-rhi-feature-gate-disabled-vulkan-runtime-tes.md), [fp16-vector atomics gate + Vulkan-Headers v1.4.318 caveat](../learnings/1780970406624-slang-rhi-nv-extension-feature-gate-fp16-vector-at.md), [gated on slang-rhi harness](../learnings/1782515089370-runtime-slang-test-for-a-new-vulkan-extension-is-g.md)).

## Contradictions / Supersessions

- Capability gating: `isSPIRV()` → `implies(CapabilityAtom::spv*)`. The rest of the triage atom stands.
- #11631: the alias/namespace mismatch is secondary; the missing decoration on the codegen module is primary.
- GLSL depth inout double-attach: unreachable (depth is output-only). Gating stays as defense-in-depth.
- Opaque-handle gate: `isResourceType` (earlier #12919 note) → narrow texture/sampler leaf predicate.
- Vulkan loader install → llvmpipe only, so no `-vk`.
- DeepWiki said user-defined varying suffixes set the location; refuted by code trace and spirv-dis.
- **RETRACTED (public, #12186):** "`OpConvertUTo*NV` need a 64-bit scalar." `SPV_NV_bindless_texture` allows uint64 OR uint2, so `tests/bugs/gh-9916.slang` is valid.
