# Slang Backends Spirv 2 Pipeline

## TL;DR
- spirv-opt runs as a downstream pass; a crash there is not a Slang IR bug — reproduce with `-O0` before blaming the emitter.
- Validation: set `SLANG_RUN_SPIRV_VALIDATION=1`; never trust the system `spirv-val` (often outdated). Use `-skip-spirv-validation` only to see output.
- Debug info (`-g2`) is marker-driven: `DebugLine`/`DebugSource` come from decorations, so a missing marker looks like a backend bug.
- `-emit-spirv-via-glsl` gives a reference SPIR-V for A/B comparison against the direct emitter.
- Direct-emitter gaps are real: features present on the GLSL path are not automatically present on the direct path — check both.

## spirv-opt / slang-glslang Integration

`slang-glslang` is Slang's SPIR-V backend library (bundles SPIRV-Tools including `spirv-opt`) — the name is misleading; it has nothing to do with GLSL. It is always a runtime-loaded MODULE, never static-linked. The correct fix for "missing slang-glslang in a static build" is a build-system change (provide the module), not making its load non-fatal ([slang-glslang/spirv-opt: gate the emit-path load to only-when-needed (masking vs. principled gating)](../learnings/1782152994624-slang-glslang-is-the-spir-v-backend-don-t-mask-its.md)).

`slangc -target spirv-asm` at default optimization (`OptimizationLevel::Default`) DOES run `spirv-opt` (specifically `CreatePrivateToLocalPass` et al.) — this is not the same as `-O0` ([slangc -target spirv-asm at default opt DOES run spirv-opt (private-to-local)](../learnings/1781714495665-slangc-target-spirv-asm-at-default-opt-does-run-sp.md)). The `-OX` levels are hand-unrolled pass *presets* (a `switch (optimizationLevel)` with ~40 `RegisterPass` calls in `slang-glslang.cpp:316`); to expose granular per-pass selection (#12204) the clean primitive is the bundled `spvtools::Optimizer::RegisterPassesFromFlags(flags)` (`external/spirv-tools/include/spirv-tools/optimizer.hpp:140`), which maps spirv-opt CLI-style flags to passes so no hand-maintained string→`Create*Pass` table is needed — the level crosses the slang↔slang-glslang C ABI as a versioned-request field, so a custom-pass string just adds a new `glslang_CompileRequest_1_3`. This safely exposes pass control without correctness risk (spirv-opt is size/perf-only), at the cost of tying the CLI surface to the bundled SPIRV-Tools version ([granular SpvOpt pass selection — RegisterPassesFromFlags is the clean primitive (#12204)](../learnings/1784829679560-granular-spvopt-pass-selection-registerpassesfromf.md)). The `private-to-local` pass demotes any `Private` variable used in exactly one function to `Function` storage, which breaks cross-call persistence for function-`static` locals. Fix: remove the two live registrations of `CreatePrivateToLocalPass` ([SPIR-V function-static state loss = SPIRV-Tools private-to-local (and how to CLI-repro)](../learnings/1781713084820-spir-v-function-static-state-loss-spirv-tools-priv.md)).

**spirv-opt load is fatal via real sink:** `createArtifactFromIR` unconditionally calls `getOrLoadDownstreamCompiler(SpirvOpt, getSink())`. If `slang-glslang` is absent, the sink is poisoned with E00100 before any output guard. Deliberately-optional callers pass `nullptr` sink ([slang downstream-compiler load: optional spirv-opt is fatal via real sink + half-wired GLSLANG gate](../learnings/1781799089141-slang-downstream-compiler-load-optional-spirv-opt-.md), [Slang downstream-compiler absence (spirv-opt/slang-glslang) IS unit-testable via setSharedLibraryLoader](../learnings/1781804734767-slang-downstream-compiler-absence-spirv-opt-slang-.md)). For opt-out via CMake escape-hatch, follow the `SLANG_ENABLE_SPIRV_OPT_MERGE_RETURN` pattern: `advanced_option`, compile definition wired through `CompilerFlags.cmake`, and `#if ... #endif` guards around ALL registrations including dead `#if 0` blocks ([slang-glslang: add an opt-out via dedicated CMake escape-hatch, not by deleting the pass](../learnings/1781975592365-slang-glslang-add-an-opt-out-via-dedicated-cmake-e.md)).

**fp8 scalar float constants abort in spirv-tools:** `GetWordsFromScalarFloatConstant` in `external/spirv-tools/source/opt/folding_rules.cpp` asserts `width == 16 || 32 || 64`; width-8 (fp8) is missing. The integer sibling handles width-8 correctly. Tracked as issue #11766 for an upstream fix; Slang-side workaround is expected-failure (#11744) ([fp8 scalar float constants abort in spirv-tools constant folding (width-8 gap)](../learnings/1782449605671-fp8-scalar-float-constants-abort-in-spirv-tools-co.md)).

## Debug Information

**-g0 does not zero all debug info:** `OpSource` is emitted unconditionally at `slang-emit-spirv.cpp:11838` without consulting the debug level. `OpName`/`OpMemberName` are emitted from `kIROp_NameHintDecoration` which also survives at g0. Neither is gated on `m_targetProgram->getOptionSet().getDebugInfoLevel()` ([slang -g0 doesn't zero SPIR-V debug info: OpSource/OpName bypass the IRDebug gating path](../learnings/1782145409789-slang-g0-doesn-t-zero-spir-v-debug-info-opsource-o.md)). Verified exhaustively for PR #11682/#12201, `-g0` (DebugInfoLevel::None) emits **exactly** three debug-adjacent instructions and nothing more: `OpSource`, `OpName`, and `OpMemberName` — while `OpLine`, the `OpString` from `DebugSource`, and `OpModuleProcessed` are all correctly absent (`OpLine` is gated to g1+, the IRDebug* insts only exist at g1+, `stripDebugInfo` removes only IRDebug* not name hints). This is SPIR-V-specific: DXIL/HLSL/Metal `-g0` genuinely emits nothing, so the help text "For SPIR-V, OpSource, OpName and OpMemberName are still emitted" is factually complete ([-g0/DebugInfoLevel::None emits exactly OpSource/OpName/OpMemberName in SPIR-V](../learnings/1784828289031-g0-debuginfolevel-none-emits-exactly-opsource-opna.md)).

**Synthesized `$init` constructors get full debug info** (issue #11550): synthesized ctors inherit the struct's source loc and their member-store stmts inherit field locs — both are lowered like user functions, giving them `DebugFunction`/`DebugScope` entries. Suppressing the function-level scope without also suppressing body `DebugLine`s leaves invalid NonSemantic debug SPIR-V. Gate on AST flavor (`SynthesizedDefault | SynthesizedMemberInit`) during lowering ([Slang: synthesized $init ctors get full source-level SPIR-V debug info (no synthesized-func filter)](../learnings/1781168370965-slang-synthesized-init-ctors-get-full-source-level.md)).

**User-defined `__init` lacks `this` in debug info** (issue #11565): a constructor's `this` is a synthesized local var (not an IRParam), so the debug-var pass doesn't pick it up. Fix: after emitting `thisVar` at `slang-lower-to-ir.cpp:13839`, add a "this" name hint + `IRDebugLocationDecoration` so the local-var loop emits it ([Slang: user-defined __init lacks `this` in SPIR-V debug info — root cause + fix site](../learnings/1781206942083-slang-user-defined-init-lacks-this-in-spir-v-debug.md)).

**Extension method debug names:** `ExtensionDecl` is anonymous (`getName()` returns null), so extension method name hints are emitted unqualified. Fix: redirect the `getNameForNameHint` recursion through the extended type's decl. Note: the name hint also feeds C-like emitter identifiers (HLSL/CUDA), not just SPIR-V debug names ([getNameForNameHint feeds C-like emitter identifiers (not just SPIR-V debug); ExtensionDecl is anonymous](../learnings/1781267563910-getnamefornamehint-feeds-c-like-emitter-identifier.md)).

**DebugScope variable-arity rule:** `IRDebugScope` must be built with 1 or 2 operands (1 when `inlinedAt` is absent) — never with 2 operands where operand 1 is null. A null operand crashes `buildEntryPointReferenceGraph` at `slang-ir-call-graph.cpp:~85` which iterates operands unguarded ([SPIR-V DebugScope must be variable-arity (null IR operand crashes buildEntryPointReferenceGraph)](../learnings/1781568128097-spir-v-debugscope-must-be-variable-arity-null-ir-o.md)).

**`-g2` test self-match trap:** At `-g2`, the full source is embedded as an `OpString`. A `CHECK-NOT` pattern whose text appears in a `//CHECK` directive line will falsely fail by matching the embedded copy. Use real quotes or `@LINE`-relative patterns to avoid this ([slang -g2 spirv-asm FileCheck tests: embedded-source self-match trap + local env gotchas](../learnings/1781176200581-slang-g2-spirv-asm-filecheck-tests-embedded-source.md)).

**`-g2` + `import`/`#line` debug-info cluster (all producer-side, all in `slang-lower-to-ir.cpp`):** three distinct 2026-07 defects (#11982/#11983/#11984, same reporter/subsystem, not dups) share a debug-info emission surface where the *consumer* (`slang-emit-spirv.cpp` around :2136) is innocent — fix the producer. (1) **DebugFunction scope** for imported functions gets pinned to the entry-point's `DebugCompilationUnit` because `IRDebugFunction` carries no scope operand and a post-pass (PR #10907) unconditionally forces the one module-global scope slot to the entry-point source; fix builds a `DebugSource → CU` map at emit and resolves scope per-file ([SPIR-V DebugFunction scope uses one module-global slot pinned to entry-point CU (#11983)](../learnings/1783465931766-slang-spir-v-debugfunction-scope-uses-one-module-g.md)). (2) **Duplicate DebugSource** for one physical file arises because two producers spell the filename operand differently (`getMostUniqueIdentity()` relative vs `getName()` absolute for `PathInfo::Type::Normal`), defeating the `hoistable=true` auto-dedup — for a hoistable IR inst, two producers MUST construct identical operands or dedup silently fails, a string/path operand being the classic divergence point ([duplicate SPIR-V DebugSource from divergent path spelling defeating hoistable-dedup (#11982)](../learnings/1783466061131-slang-11982-duplicate-spir-v-debugsource-from-dive.md)). (3) **BOM in DebugSource** for a `#line`-named file: the fresh-read fallback `getOrEmitDebugSource` wraps the raw blob bytes as content, bypassing `SourceFile::setContents`'s canonical BOM strip (`CharEncoding::determineEncoding`), so a UTF-8 BOM lands in the `OpString` while line/col data stays BOM-free — decode/BOM-strip in the fallback ([-g2 DebugSource for #line files bypasses canonical BOM strip (fresh-read fallback) (#11984)](../learnings/1783468265984-slang-11984-g2-debugsource-for-line-files-bypasses.md)). Repro note for all three: the disassembly path needs slang-glslang, present only in `build/Debug/lib`, so use `LD_LIBRARY_PATH=build/Debug/lib ... -target spirv-asm` or emit binary `-emit-spirv-directly -o out.spv` and grep raw bytes; `-dump-ir` is authoritative for "does dedup actually happen" (DeepWiki reasons from symbol names and confidently got the DebugSource dedup wrong).

## Depth Output Execution Modes

**Direct SPIR-V path** emits both `DepthReplacing` AND `DepthGreater`/`DepthLess` for `SV_DepthGreaterEqual`/`SV_DepthLessEqual`. When two depth-affecting builtins coexist (e.g. `SV_Depth` + `SV_DepthGreaterEqual`), `maybeEmitEntryPointDepthReplacingExecutionMode` collapses to `DepthReplacing` only via the `else if (mode != thisMode)` conflict branch ([Slang SV_Depth{Greater,Less}Equal: direct SPIR-V correct, GLSL/via-GLSL drops directional mode](../learnings/1782165817624-slang-sv-depth-greater-less-equal-direct-spir-v-co.md), [Slang direct-SPIR-V depth mode ALSO dropped via conflict-branch (dual depth-affecting vars) — not just GLSL](../learnings/1782211031715-slang-direct-spir-v-depth-mode-also-dropped-via-co.md)).

**Output topology (hull/domain):** The `case kIROp_OutputTopologyDecoration:` hull/domain arm handles only TriangleCW/TriangleCCW/Point; `Line` falls through to the mesh-shader fallback arm emitting `OutputLinesEXT` — invalid on tess stages. For isoline, `Line` should be a no-op (the `OpExecutionMode Isolines` from `[domain("isoline")]` already implies it). The fallback must be stage-guarded ([Slang SPIR-V output-topology: hull/domain arm only handles a subset of OutputTopologyType — Line falls through to mesh OutputLinesEXT](../learnings/1780253722562-slang-spir-v-output-topology-hull-domain-arm-only-.md)).

## Varying-Parameter Location Assignment

`SV_Target<N>` is the ONLY varying semantic that both consumes a GLSL/SPIR-V `location` AND carries a numeric suffix that is an ABSOLUTE hardware slot which must equal that location. In `slang-parameter-binding.cpp` `processEntryPointVaryingParameter`, SV_Target takes `getSimpleVaryingParameterTypeLayout(...Output)` (:~2064) while all other `SV_`/`NV_` semantics take direction mask 0 → consume NO location (SV_Position/SV_Depth→`BuiltIn FragDepth`/SV_Coverage/SV_ClipDistance are builtins). The #11944 bug is that `systemValueSemanticIndex` is stored but never read into location allocation, so out-of-order `SV_TargetN` gets a declaration-order location ignoring N. User-defined semantics (TEXCOORD0/1, COLOR0/1) are the opposite: the suffix is a name disambiguator, not a slot — GLSL/SPIR-V assign their locations by DECLARATION ORDER and HLSL matches inter-stage by NAME, so the same varying struct used as VS-out and FS-in gets identical declaration-order locations on both sides. Genericizing suffix→location (as a PR reviewer proposed) would REGRESS user-defined varyings by desyncing inter-stage matching and inventing locations HLSL never assigns — the correct fix axis is "semantic encodes an absolute slot," i.e. SV_Target only. The `SV_TARGET<N>→LOCATION_<N>` by-index translation in `fixFieldSemanticsOfFlatStruct` (`slang-ir-legalize-varying-params.cpp:3730`) runs ONLY inside `LegalizeShaderEntryPointContext`, subclassed only by Metal + WGSL; GLSL/SPIR-V never use it and instead read the VarLayout resource `index` directly in emit (`slang-emit-spirv.cpp:3445-3465`) — so the suffix→location path is a WGSL/Metal-only concern ([slang SV_Target-N is the only varying semantic encoding an absolute GLSL/SPIR-V location](../learnings/1784321038825-slang-sv-target-n-is-the-only-varying-semantic-enc.md)).

## Validation and Testing

**spirv-val must be run explicitly:** A clean `slangc` exit is not sufficient. The compiler can emit structurally invalid SPIR-V that only `spirv-val` detects ([SPIR-V issues require spirv-val, not just slangc exit code](../learnings/dashboard_slang-triage-1776263007885.md)). Under CI, `SLANG_RUN_SPIRV_VALIDATION=1` is set — a unit test asserting the absence of a validation-related diagnostic will pass locally and fail in CI ([CI runs slang-test with SLANG_RUN_SPIRV_VALIDATION enabled — unit tests must not assume validation is off](../learnings/1781825083619-ci-runs-slang-test-with-slang-run-spirv-validation.md)).

**Text FileCheck cannot catch malformed access-chain bases:** `//TEST:SIMPLE` does NOT run SPIR-V validation. For descriptor-heap / access-chain fixes, run `SLANG_RUN_SPIRV_VALIDATION=1` out-of-band or write FileCheck that pins the base to the heap builtin global ([SPIRVLoadDescriptorFromHeap heap operand is a pointer global at emit — never parameterize it in call-spec](../learnings/1780769340224-spirvloaddescriptorfromheap-heap-operand-is-a-poin.md)).

**spirv-val silence proves nothing in EITHER direction.** A construct that passes the bundled validator is not thereby legal, and a construct it accepts is not thereby illegal — for the `OpConvertUTo{Image,Sampler,SampledImage}NV` operand width there is simply **no operand-type rule anywhere in `external/spirv-tools/source/val/`**, so validator behaviour is uninformative and must not be read as "validator gap confirming my theory." For any "is this valid SPIR-V?" claim that gates a *diagnostic* or a *test change*, read the primary spec text — fetch `raw.githubusercontent.com/KhronosGroup/SPIRV-Registry/main/extensions/<VENDOR>/<EXT>.asciidoc`. A DeepWiki summary that caveats itself ("headers do not explicitly state… however, typically") is an inference, not a citation; using it publicly on a maintainer's PR is how a valid repo test gets accused of a latent miscompile ([cite the SPEC, not a summarizer: SPV_NV_bindless_texture accepts uint2 OR uint64](../learnings/1785776557998-cite-the-spec-not-a-summarizer-spv-nv-bindless-tex.md)).

**Triage discriminator — embedded spirv-tools vs system validation layer:** At HEAD ~2026-06 the embedded spirv-tools is v2026.2. A VUID that fires only in a maintainer's system layer (Vulkan SDK 1.4.328+) is validator version-skew, not a master regression ([Triage discriminator: Slang embedded spirv-tools vs system Vulkan validation layer (version-skew)](../learnings/1782267495019-triage-discriminator-slang-embedded-spirv-tools-vs.md)).

**Local verify LD_LIBRARY_PATH trap:** Always put `build/Debug/lib` FIRST in `LD_LIBRARY_PATH` when verifying fixes locally. The package-staging dir (`build/slang-<ver>-linux-x86_64/lib/`) holds a stale `libslang-compiler.so` that silently overrides the fresh build ([slang local spirv-asm verify: put build/Debug/lib FIRST in LD_LIBRARY_PATH or you test a stale compiler](../learnings/1782733787106-slang-local-spirv-asm-verify-put-build-debug-lib-f.md)).

**Vulkan build dependencies:** Building any RHI-dependent target on Linux requires `libx11-dev` (header `X11/Xlib.h`), even headless. `slang-rhi` CMakeLists.txt fetches Vulkan-Headers via FetchContent; the bundled headers unconditionally include `X11/Xlib.h` ([CONSOLIDATED: slang-rhi Vulkan build needs libx11-dev (X11/Xlib.h)](../learnings/1780330247261-CONSOLIDATED-slang-rhi-vulkan-build-needs-libx11-dev.md)). The GPU environment may have NVIDIA hardware but no Vulkan loader — installing `libvulkan1` gives only software llvmpipe; real-GPU Vulkan needs the container to be provisioned with graphics device injection ([This environment HAS an NVIDIA GPU (nvidia-smi works) despite CLAUDE.md saying 'no GPU' — but no Vulkan loader, so Vulkan execution still unavailable](../learnings/1781698311286-this-environment-has-an-nvidia-gpu-nvidia-smi-work.md), [Correction: installing libvulkan1 does NOT enable NVIDIA-GPU Vulkan in these containers — only software llvmpipe; NVIDIA Vulkan ICD fails (ERROR_INCOMPATIBLE_DRIVER, NVIDIA_VISIBLE_DEVICES=void)](../learnings/1781699613539-correction-installing-libvulkan1-does-not-enable-n.md)).

**Runtime tests for new extensions:** A `COMPARE_COMPUTE` slang-test for a Vulkan extension requires a `SLANG_RHI_FEATURES` entry in slang-rhi. The `SLANG_RHI_FEATURES` X-macro is the bridge: one line auto-generates the `rhi::Feature` enum entry AND makes `-render-feature <name>` valid in slang-test. Cross-repo sequence: slang-rhi gate PR → bump slang-rhi pin → slang test-re-enable PR ([Slang RHI feature gate + disabled Vulkan runtime test: the SLANG_RHI_FEATURES X-macro is the cross-repo bridge](../learnings/1780969782467-slang-rhi-feature-gate-disabled-vulkan-runtime-tes.md), [slang-rhi NV-extension feature gate (fp16-vector atomics) + Vulkan-Headers v1.4.318 retires bump caveat](../learnings/1780970406624-slang-rhi-nv-extension-feature-gate-fp16-vector-at.md), [Runtime slang-test for a new Vulkan extension is gated on slang-rhi harness support (abort/VK_KHR_shader_abort #11790)](../learnings/1782515089370-runtime-slang-test-for-a-new-vulkan-extension-is-g.md)).
