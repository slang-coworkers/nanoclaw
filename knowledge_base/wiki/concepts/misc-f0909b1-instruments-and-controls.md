## TL;DR

- A negative result — a zero, an "absent", a green test — is worthless until you have proven the instrument that produced it *can* return the other answer. Validate the instrument first, then read its output.
- Every polarity of control matters: a **positive/must-hit control** proves your grep read the file; a **must-miss control** proves it discriminates; a **must-fail control** (the revert drill) proves a test detects the bug — *and it must fail on the assertion that encodes the property, from a start state the bug cannot produce.*
- A control can itself be inert. `GH_TOKEN=bogus` breaks nothing in a proxy-credentialed container; `env`-overriding a credential is not failure-injection. Inject failure at a layer the code actually consults (a bad PR number, a nonexistent file).
- A **plausible-negative** is a check that returns a believable answer in exactly the state where it is blind (`formatting.sh --check-only` exits 0 when its formatters are absent; a size-only diff "matches" while contents differ). Ask: *what does this command print in the state where it cannot work?*
- A must-hit control proves the instrument *fired* — never that the file is the right **authority**. A grep of a vendored/pinned copy that predates a fact returns an uninformative zero. Compare artifact provenance date to the fact's origin date.
- A number you measured yourself is still a claim you must read: re-read the table against the sentence, column by column, before publishing "mechanism observed."
- Vacuous tests hide behind good reasoning. "State X unchanged after Y" is trivially true if Y never ran; assert that Y ran. A relaxed assertion with a principled-sounding comment survives review precisely because the comment defends the hole.
- `CHECK-NOT` after positive matches scans only the tail — a negative/absence assertion needs its own prefix (or its own control) or it silently checks nothing.
- A symbolic ref (`FETCH_HEAD`, `HEAD`) is not an identity; in a shared/shallow clone a range diff can fail **open and huge**. Pin to explicit SHAs, assert the merge-base, treat output size as a signal.
- A measurement that *succeeded* can measure the wrong thing: a partial revert produces a correct, reproducible reading of a different cell, labelled as the baseline. Derive the revert set from `git diff --name-only`, then `git diff --stat` must be empty.

## The core failure mode: a check indistinguishable from success in its blind state

Across a dozen review sessions the same shape recurs: an instrument returns a plausible answer while measuring nothing, and nothing downstream can tell. The unifying discipline is **prove variation before trusting a reading**.

The sharpest single framing is the *plausible-negative* — "a check that returns a believable answer in exactly the state where it is blind" [Plausible-negative: ask what a check prints where it cannot run](../learnings/1786424971755-plausible-negative-ask-what-a-check-prints-in-the-.md). Three instances in one chain shared it: `formatting.sh --check-only` exits 0 when its four formatters are missing from PATH (reads as "clean"); a `tail | xxd` pipeline reported "no trailing newline" for every ref because `xxd` was absent; a priority-yielded CI run read `conclusion: failure` for skipped jobs. Directions differ (one reassures, one alarms, one misattributes) but each reading is indistinguishable from a real measurement at the point of use. The habit that catches all three: *what does this command print in the state where it cannot work?* — and if the answer is any plausible verdict, pair it with a tool-presence assertion and a positive control that must fire. A tool-dependent green also **expires with its tooling**: a `clang-format 17.0.6` green went stale when the pip install vanished on a container restart.

## Controls of every polarity — and controls that are themselves inert

The revert/must-fail drill is necessary but not sufficient: a test can go red for a reason unrelated to the property it claims to check. [A must-fail control has to fail for the reason under test](../learnings/1786431455474-a-must-fail-control-has-to-fail-for-the-reason-und.md) makes the two obligations explicit — the test fails when the fix is removed **and** it fails on the assertion encoding the property, from a starting state the bug cannot produce. Two vacuous passes from one regression test illustrate it: one where the subject never ran (an unrecognized option bailed before the code under test, giving `100% (1/1)`), and one where the expected value equalled the bug's output (asserting "empty" when the defect blanks the value — start from a one-character sentinel instead). The related [A relaxed assertion defended by good reasoning is the most dangerous kind](../learnings/1786405384375-a-relaxed-assertion-defended-by-good-reasoning-is-.md) shows why: a deliberately-relaxed check ("don't check the result code, we're testing a different property") reads as the *more* rigorous choice, so its principled-sounding comment defends the hole. The catch came not from re-reading the test but from an **independent signal beside the verdict** — a `error 1004: unknown command-line option` line sitting next to `100% of tests passed`.

Controls must themselves be capable of failing. [My own negative control was inert too](../learnings/1786397650491-approver-critique-miss-my-own-negative-control-was.md): `GH_TOKEN=bogus ./probe.sh` returned a clean result because auth is injected at the OneCLI HTTPS proxy — `GH_TOKEN` is a literal sentinel nothing reads, so the "negative control" broke nothing. `env`-var overrides are not valid failure-injection in a proxy-credentialed container; inject at a layer the code consults (a bad PR number genuinely fails). And a detector can return the "blind" value for a known-true input: in [I read my own measurement table backwards](../learnings/1786405416519-approver-challenger-miss-i-read-my-own-measurement.md), counting `asan_globals` ELF sections returned 0 even for a plainly-instrumentable `int gArr[16]`, so its zeros carried no information — the size-delta signal only became usable once a positive control proved it fired. That same atom carries a distinct lesson: *a number I measured myself is still a claim I have to read* — the author quoted a size-4 (unchanged) offender as "its recorded size grows by the redzone," inverting the direction of a table three lines above the sentence. Re-read each numeric claim by pointing at the cell it came from.

## A firing control proves the instrument fired — not that it is the right authority

The subtler trap is that both controls pass and the answer is still wrong because the *artifact* cannot know the fact. [A must-hit control proves the instrument fires, not that the file is the right AUTHORITY](../learnings/1786403788895-a-must-hit-control-proves-the-instrument-fires-not.md): grepping a vendored `spirv.core.grammar.json` pinned at a 2026-07-08 commit for opcodes ratified 2026-07-31 returns a true zero about a stale artifact — both must-hit and must-miss controls behaved perfectly. The discriminating question is answerable by no control: *could this artifact possibly know about the thing I'm asking, given when it was produced?* Compare the artifact's provenance date (`git -C <submodule> log -1 --format=%ci`) to the fact's origin date; a version field can fail to discriminate (vendored and upstream both reported `1.6 rev 7` while contents differed). That atom also collects reusable grep defects: `grep -oF -c` is a line count (`-c` overrides `-o`); a flag-shaped needle is eaten as an option (use `-oFe`); a case-mismatched symbol looks identical to an absent one.

## Empty inputs, masked failures, and sentinels

An instrument fed an empty input fabricates a failure. [An empty probe file reports a good patch as broken](../learnings/1786408962743-an-empty-probe-file-reports-a-good-patch-as-broken.md): `git show origin/master:<path> > probe/<path>` run from a non-repo cwd created a 0-byte file, and `git apply` then failed against emptiness with a plausible "patch does not apply" — nearly retracting a correct diff. Two compounding reading errors: an `&&` chain masked the failure (`... | head -4 && echo "applies cleanly"` fires on `head`'s exit 0, not git's) and a true observation ("does not apply") was attributed to the target, not the instrument. Guard: after materializing any probe file, assert it is non-empty and hash-matches the expected blob; `set -o pipefail`; `cd` into the real repo and `git rev-parse --is-inside-work-tree` first. (A Main correction on that atom notes the *artifact* it cited was later superseded — cite `18203c9588` — but the probe lesson stands.)

A field's "absence" has more than one spelling. [A sentinel is not a null](../learnings/1786422510763-a-sentinel-is-not-a-null-enumerate-a-field-s-value.md): GitHub Actions `runner_id` is `null` for skipped, `0` for queued, and a real integer for a job that ran — so a `runner_id != null` filter passes queued jobs and reported an 11.3h outage as ~30 minutes old (biasing *away* from the alarm, which gets filed rather than investigated). Enumerate a field's actual values across every state before using absence as a discriminator; print the value distribution instead of applying a predicate you already believe. The correct discriminator there was `runner_name` non-empty.

## Absence assertions need their own scope

[CHECK-NOT after a block of CHECK-DAGs scans only the tail of the output](../learnings/1786412733571-check-not-after-a-block-of-check-dags-scans-only-t.md): FileCheck scopes a `CHECK-NOT` to the span between surrounding positive matches, so negatives placed after the DAG block never scan the module's head — a green test and a scope-limited test are byte-identical. Give negative assertions their own prefix and `//TEST` directive so their scan starts at the beginning, *type* the negative lines (`OpIAdd %float`, not bare `OpIAdd`), and verify the new form actually catches things by naming a present opcode. This is the same rule as grep zeros: an absence claim needs a mutation that makes it fire.

## Even a successful measurement can measure the wrong thing

Two instrument defects come from git itself. [A shallow clone + re-pointed FETCH_HEAD makes `git diff A..B` fail OPEN](../learnings/1786387943319-shallow-clone-a-re-pointed-fetch-head-makes-git-di.md): a shared clone's `FETCH_HEAD` was re-pointed mid-session and `--depth=1` left an empty merge-base, so `$MB..$HEAD` became `..$HEAD` and a 32-line PR's diff ballooned to 9.2 MB of unrelated history that read like a supply-chain red flag. This is the *opposite polarity* of the known shallow-clone trap (which fails **closed** at a graft boundary) — when you store a trap, store its polarity. Pin every `git show`/diff to an explicit SHA, assert the merge-base is non-empty, prefer the forge's `compare` endpoint, and treat implausible output size as self-refuting.

And [A partial revert produces a correct measurement with the wrong label](../learnings/1786404998429-a-partial-revert-produces-a-correct-measurement-wi.md): reverting the two files thought of as "the fix" (of six) produced a real, reproducible measurement of the *emitter-only* cell, labelled "pre-fix." A failed measurement announces itself; a mislabel does not. Derive the revert set from `git diff --name-only <base>..HEAD`, confirm `git diff --stat` is empty before trusting the build, label every A/B cell by its file set, and add a checkable discriminator when two cells could produce the same output. What caught it was an *unexpected value* against a strong prior — "the surprise was the instrument," which is exactly why the mechanical `git diff --stat` check earns its one command.

## Practical checklist

- Never report a zero/absent/green from a probe you have not seen fire, in the same idiom, on a known-positive.
- Pair every absence with a positive control (must fire) and, where discrimination matters, a negative control (must stay zero).
- For a revert drill: record *which assertion at which line* failed; if it failed in setup, you measured scaffolding.
- Ask of any dependency (tool, credential, file, network): what does the check print when it is missing? Assert presence and version bounds.
- Compare artifact provenance date to fact origin date before trusting a vendored/pinned copy's zero.
- Pin git reads to explicit SHAs; assert merge-base; `set -o pipefail`; verify cwd is inside the repo.
- Re-read your own measurement table against the sentence you wrote from it, column by column.
