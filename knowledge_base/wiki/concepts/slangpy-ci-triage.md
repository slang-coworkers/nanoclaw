# SlangPy CI, Triage, Build, and Runtime

Operational knowledge for slangpy's CI, GitHub issue triage, runtime/API behavior, and builds: flake patterns, rerun authority, the slang bundling model, and buffer layout gotchas.

> Related pages: [Crashing Tests & CI Flake](slangpy-test-crashes-and-ci-flake.md) · [Build from Source & Infra/Ops](slangpy-build-and-infra-operations.md) · [Build, CI Structure & Toolchain](slangpy-f0909b0-build-ci-toolchain.md) · [GPU Validation & Cross-Repo Guards](slangpy-gpu-validation-and-cross-repo-guards.md) · [Bug Investigations](slangpy-f0909b0-bug-investigations.md).

## TL;DR
- **Cross-repo `gh run rerun <id> --repo shader-slang/slangpy --failed` WORKS** — rerun slangpy reds yourself under the 3/PR/day cap. The old "Must have admin rights" 403 was the OneCLI gateway PAT-routing collision, never a missing scope.
- **Exit 0 is not proof a rerun fired; the `run_attempt` increment is.**
- **Classify a slangpy red by determinism, not permissions** — intermittent (dep-fetch 5xx, DXC fetch 500) → rerun; deterministic/author-owned (setup-python toolcache, `E36121`, code break) → no rerun.
- **Probe the operation; don't introspect permissions** — grep the action ledger (`rerun-log.jsonl`) before repeating a "bot cannot do X" line.
- **Self-hosted runners' cached toolcache never upgrades unpinned or transitive deps.** For a pyright Node-bootstrap break propose `pyright[nodejs]` first (merged as #1253 over the nodeenv floor #1251). GitHub-hosted green proves nothing there.
- **The GPU-leak claims (#115/#608/#827) are retracted** — CI CUDA-OOM is peak concurrent VRAM (4 xdist workers × ~5 GB), not a monotonic leak.
- **The pyright, OOM, cpu-shader-llvm and D3D12 device-removal cascades all look like infra flake;** read the signature before rerunning.
- **`ci-latest-slang.yml`'s `build-pr` checks out slangpy's DEFAULT branch** — a required `SlangPy Tests` check on a slang PR goes green only once the slangpy fix is merged to main.
- **"Deferred until the upstream Slang fix ships" gates on the `SGL_SLANG_VERSION` pin, not a wheel** — check merge, a tag CONTAINING the commit, then the pin bump; the pin lags and moves under parked requests.
- **Measure GPU presence each session** (L40S since 2026-10-16); cooperative-VECTOR compiles but cannot dispatch.
- **Read cross-backend (incl. Metal) results from each CI job's log;** mid-run, `gh run view --log --job` is empty — use the jobs logs API.
- **Re-symbolize the crashpad `.dmp` locally** before designing a flake fix.
- **slangpy-samples `pre-commit run --all-files` lets one pre-existing violation red every PR.**
- **Before mapping a solution space, grep HEAD for the feature's symbols and check merged PRs**; for GPU-codegen gaps search `shader-slang/slang` PRs first.
- **`create_buffer(struct_size=K)` never checks `K` against Slang's per-target stride (silent OOB)** — pass `resource_type_layout=`.
- **Python `id(m)` differing per `load_module` is not an `IModule*` bug** — slangpy mints a fresh wrapper per call.
- **No-GPU CUDA check: `ParameterBlock` lowers to `__constant__`, entry-point args to `.param`.**
- **Detailed on the related pages** (validation / build / crash pages above): an A/B's `SGL_LOCAL_SLANG_BUILD_DIR` must be `build/Release`, not the downloaded release artifact (both arms come back clean); Slang's `default` preset is Ninja Multi-Config, so `-DCMAKE_BUILD_TYPE` is inert; establish the pinned-Slang baseline first (5 LFS-fixture `sgl_tests` failures).
- `git checkout <commit> -- <path>` also STAGES, so plain `git diff` is empty (use `git diff HEAD`); doctest name filters can select nothing; a stubgen failure aborts ninja before the `sgl_tests` link (stale-binary false green — check mtimes).
- Builds need `python3-dev` and `--break-system-packages` (PEP-668) plus the `data` submodule's real LFS fonts; `load_program` capability-checks EVERY `[shader]` EP; `E36121` fires only on API-requested capabilities; `0 assertions failed` with N failed cases = module-load break.
- `gh run list` `updatedAt - createdAt` is not job duration; NVRTC runs only at the first `dispatch`; a deliberately crashing test HANGS CI under Crashpad; one test can remove the shared D3D12 device and cascade; `PATCH` of a bot issue comment 403s while `POST` works.

## CI flakes and infra failures

### Crash dump re-symbolization
When a slangpy CI abort is buried under crashpad symbolizer noise (`elf_dynamic_array_reader.h:64 tag not found` spam), download the run's `crash-reports-${os}-${platform}-${compiler}-${config}` artifact and re-symbolize the `.dmp` locally with full symbols (e.g. `minidump-stackwalk` against a debug build of the same sha). `Upload Crashpad Reports` (`.github/workflows/ci.yml:228-234`) uploads `.dmp` + `.txt` + `.json` only when `matrix.flags` contains `crashpad`; the on-the-fly stackwalk in `slangpy/testing/crashpad.py:_postprocess_reports` is shallow, and the aborting worker's stderr gets buried ([slangpy CI flake triage: re-symbolize the existing .dmp before designing fixes](../learnings/1779545587070-slangpy-ci-flake-triage-re-symbolize-the-existing-.md)).

### GPU OOM on the shared nvrgfx runner (not a leak)
**Signature:** `SlangPy Tests` fails with `cuMemAlloc ... CUDA_ERROR_OUT_OF_MEMORY`, `RuntimeError: Failed to create device!` and pytest-xdist `replacing crashed worker gwN`; hundreds of tests fail across unrelated files while thousands pass. `pytest slangpy/tests -vra -n auto --maxprocesses=4` puts up to 4 workers, each with CUDA + Vulkan(+D3D12)+torch contexts, on ONE shared `nvrgfx` Linux GPU; reruns re-contend and often re-fail ([SlangPy CI flake: shared nvrgfx GPU runner CUDA OOM](../learnings/1781122096821-slangpy-ci-flake-shared-nvrgfx-gpu-runner-cuda-oom.md)).

On an L40S (46 GB, debug layers on), single-process micro-repros of leaks #115 (functional API), #608 (command encoder) and #827 (torch interop) were flat after warm-up (0 growth over 5k–20k iterations), while a real CUDA suite slice showed a step function plateauing at ~5 GB per CUDA-only worker ([slangpy GPU mem-leak #115/#608 don't reproduce at HEAD](../learnings/1782324497848-slangpy-gpu-mem-leak-115-608-don-t-reproduce-at-he.md)). The cascade (e.g. #1024) is **peak concurrent VRAM = workers × per-worker high-water mark**; the first failed alloc cascades to every worker. Tell a leak (monotonic climb on a repeated op) from a high-water-mark working set by sampling both a micro-loop and the real suite; probe at `/workspace/agent/leak_probe.py`. The fix is maintainer-side: right-size runner VRAM to ≥ `maxprocesses × per-worker peak` + headroom, lower the per-worker peak, cap GPU-job concurrency, or add a per-job GPU-memory budget. Maintainers rejected a `--maxprocesses` cut as a wall-clock-costly stopgap, so measure per-worker high-water first ([CI GPU-OOM that passes on rerun is usually peak concurrent VRAM, not a leak](../learnings/1782896626067-ci-gpu-oom-that-passes-on-rerun-is-usually-peak-co.md)). Side finding: Vulkan + CUDA interop (`enable_cuda_interop`) throws `SLANG_FAIL` on `command_encoder->finish()` on L40S (adjacent to #929/#823).

### cpu-shader-llvm shader.o build failure
On slang PR #11424, `ci-latest-slang` `build-pr` failed on Linux and Windows building the `cpu-shader-llvm` example: `shader.o` is never marked `FAILED:` but is absent at link. Commit `bbc4b0278`'s `GENERATED TRUE` Ninja-race fix is insufficient in slangpy's high-parallelism build. It looks PR-specific only because PRs on older master don't build the example. Reruns won't help and the fix does not belong in an unrelated PR: such a PR is "blocked by infra", not unmergeable ([SlangPy Tests red = cpu-shader-llvm shader.o build failure](../learnings/1781008254667-slangpy-tests-red-cpu-shader-llvm-shader-o-build-f.md)).

### slangpy-samples pre-commit: the --all-files trap
`.github/workflows/pre-commit.yml` runs `pre-commit run --all-files`, so one pre-existing violation (e.g. a missing trailing newline) reds `pre-commit` on every PR. Fix with a standalone 1-byte EOF-newline PR off `main`; verify with `python3 -m venv /tmp/pcvenv && /tmp/pcvenv/bin/pip install pre-commit`, then `/tmp/pcvenv/bin/pre-commit run end-of-file-fixer --files <f>` ([slangpy-samples CI pre-commit runs --all-files](../learnings/1781609083456-slangpy-samples-ci-pre-commit-runs-all-files-a-sin.md)).

### Reading cross-backend (incl. Metal) test outcomes from CI
Without local macOS/GPU, read per-test PASS/FAIL from each job's "Unit Tests (Python)" step: linux gcc Debug runs vulkan + cuda, windows msvc Debug d3d12 + vulkan + cuda, and `build (macos, aarch64, clang, …)` the full suite on metal. `gh run view --job <id> -R shader-slang/slangpy --log | grep -iE "<test_name>|DeviceType.metal"` closes a "platform X unverified" gap. A PASS cannot prove which of two string-match arms fired ([SlangPy CI macOS build jobs run the full pytest suite incl. Metal](../learnings/1790024857395-slangpy-ci-macos-build-jobs-run-the-full-pytest-su.md)). **While any job in the run is still going, `gh run view --log --job` returns nothing** — use `gh api --allow-escape-sequences repos/shader-slang/slangpy/actions/jobs/<id>/logs` (ids from `detailsUrl` in `statusCheckRollup`), strip ANSI, and grep `(PASSED|FAILED|SKIPPED).*<test_file>`. Static A/B for an autodiff fix in `slangpy/slang/*.slang`: `git archive` both arms, compile an `import slangpy;` probe calling `bwd_diff(f)` with `slangc -I <arm>/slangpy/slang -target hlsl`, and count `Interlocked` / `Tensor_read_buffer.*_grad_in`. A raw `spy.Device()` has empty include paths; only `spy.create_device()` prepends `SHADER_PATH`, else `cannot open file 'slangpy.slang'` (PR #1178) ([SlangPy CI: per-job test logs mid-run](../learnings/1791194997507-slangpy-ci-per-job-test-logs-while-a-workflow-run-.md)).

GPU presence is not stable across restarts; check `ls /dev/nvidia*; nvidia-smi -L` each session. Containers have an NVIDIA L40S (CUDA + NVIDIA Vulkan) since 2026-10-16, and compute/Vulkan `cooperative_matrix` runs on it; 2026-09-28→10-16 was a passthrough outage (lavapipe CPU Vulkan only; GPU repros needed a CI runner) ([no GPU since ~09-28](../learnings/1792089571497-agent-containers-have-no-gpu-since-2026-09-28-host.md)). ### pyright/nodeenv crash on the self-hosted runners (slangpy#1250)
**Signature:** every pyright (typing) step on the self-hosted `nvrgfx-kernelvm-bridge` runners (slangpy `ci.yml`, `ci-latest-slang`, `ci-gcp`) fails with `int('0-alpha')` from nodeenv's `parse_version`, while GitHub-hosted jobs stay green. Three facts combine. (1) Those runners have no `node` on PATH, so pyright-python (`pyright/node.py::_resolve_strategy`: the `nodejs_wheel` package from the `pyright[nodejs]` extra, then a global `node`, then nodeenv) runs `python -m nodeenv ~/.cache/pyright-python/nodeenv` with the default `--node latest`. (2) Their `actions/setup-python` toolcache (`_work/_tool/Python/<ver>`) persists, so `pip install -r requirements-dev.txt` never upgrades unpinned or transitive deps (pyright 1.1.411 and nodeenv 1.10.0 stayed while PyPI had 1.1.414 and 1.11.1) ([pyright installs Node via nodeenv; toolcache never upgrades](../learnings/1793320345251-slangpy-ci-pyright-installs-node-via-nodeenv-on-se.md)). (3) nodejs.org listed `v27.0.0-alpha.0.0.0` first in `index.json`, and nodeenv takes `index.json[0]` with no prerelease filter. Only nodeenv **1.11.1** fixes it: 1.11.0 has the same unfiltered `_get_last_node_version` and `+`-only `parse_version`, so `>=1.11` is not enough. Because `SlangPy Tests` is required on slang merge-queue groups, the break also evicted slang PRs and froze slang master ([GitHub CI Status-Surface Traps](ci-github-status-surface-traps.md)).

**Fix: maintainers chose `pyright[nodejs]` over a version floor.** On persistent runners, waiting for an upstream release or leaving a name unpinned changes nothing; only a new requirement forces pip to act. The bot's draft #1251 (`nodeenv >= 1.11.1` in requirements-dev.txt; no workflow edit, since the bot token has no `workflows` scope) was green on every self-hosted runner and approved, but maintainers closed it for jkwak-work's #1253: `pyright` → `pyright[nodejs]`, which bundles Node via `nodejs-wheel-binaries`, so pyright never touches nodeenv or the mutable nodejs.org index. They accept the extra dev dependency to drop the runtime nodejs.org dependency that a floor leaves in place ([maintainers prefer pyright[nodejs] over nodeenv pins](../learnings/1793368291147-slangpy-maintainers-prefer-pyright-nodejs-over-nod.md)). It works on frozen toolcaches because pip installs the extra's dependency even when pyright is already satisfied. Avoid `PYRIGHT_PYTHON_NODE_VERSION=<ver>`: pyright-python then passes `--force` and reinstalls node every run ([unpinned dev deps freeze; nodeenv fallback](../learnings/1793319226571-slangpy-ci-unpinned-dev-deps-freeze-on-self-hosted.md)).

**Verifying the fix.** A green typing check on GitHub-hosted runners (ubuntu-24.04*, macos-latest) proves nothing: they have `node` on PATH and never call nodeenv; only the self-hosted linux-gcc and windows-msvc jobs exercise that path. To reproduce locally, hide the container's `/usr/local/bin` node: build a venv with `nodeenv==1.10.0` and pyright, then run `env -i HOME=$HOME PATH=venv/bin:/usr/bin:/bin XDG_CACHE_HOME=$(mktemp -d) venv/bin/pyright --version` ([GitHub-hosted green proves nothing; 1.11.0 still buggy](../learnings/1793320675908-slangpy-ci-green-github-hosted-jobs-don-t-prove-a-.md)).

## Rerun authority

### Current rule: rerun slangpy reds yourself, verify via `run_attempt`
A slang PR's cross-repo **SlangPy Tests** run lives in `shader-slang/slangpy` (`repository_dispatch`); find the run id there. Its rerun once returned "Must have admin rights to Repository", which was read as an admin-only rule for `repository_dispatch` runs ([SlangPy Tests failures on slang PRs are not bot-rerunnable — superseded](../learnings/1782166177663-slangpy-tests-failures-on-slang-prs-are-not-bot-re.md)). Re-probed 2026-08-03 on slang PR #12116: exit 0, `run_attempt` **1 → 2**. It has held: `rerun-log.jsonl` records reruns on #11709, #13078 and #13357, and `--job <job-id>` on #12766 flipped the run to `queued`. Yet a stale "App token is scoped to `slang/*`" memory line was re-asserted while `grep -i slangpy rerun-log.jsonl` refuted it. A "cannot do X" line is a claim that rots: grep the action ledger before repeating one, and correct it in place with a dated note ([stale "bot cannot rerun slangpy" claim contradicted by the rerun-log.jsonl precedent](../learnings/1790907793442-stale-bot-cannot-rerun-slangpy-claim-contradicted-.md)). All-false `permissions` on slangpy never blocked action.

Under the gateway a failed call can still exit 0 (`gh … | jq` reports jq's status), so after any rerun confirm the counter moved:

```bash
gh api repos/shader-slang/slangpy/actions/runs/<id> --jq '{status,conclusion,attempt:.run_attempt}'
```

Intermittent signatures (dep-fetch 5xx, network, single-platform transient) → rerun under the 3/PR/day cap. Deterministic or owned ones (setup-python toolcache, slang#11225's E36121, an author code break) → no rerun. A DXC prebuilt fetch 500 (`downloading '.../dxc_2026_02_20.zip' failed … CMake Error at download-dxc-populate.cmake:163`, then `ninja: error: loading 'build-Release.ninja'`) fails at CMake configure, so zero tests run; it comes from `FetchDXC.cmake`, a different call site from the `FetchedSharedLibrary.cmake` that slang PR #12323 fixes — one root cause, two call sites ([cross-repo `gh run rerun` on slangpy now works — verify via `run_attempt`](../learnings/1785773902337-cross-repo-gh-run-rerun-on-shader-slang-slangpy-no.md)).

## Issue triage patterns

### Check HEAD and merged PRs before mapping a solution
When a slangpy feature request cites file:line pointers, grep HEAD for its named symbols first: sub-task issues under an umbrella effort lag the code, because the umbrella PR closes the substance but not the issue. Already wired and tested → needs-decision, not ready-for-fix ([SlangPy triage: grep the issue's named symbols in HEAD first](../learnings/1781015340808-slangpy-triage-grep-the-issue-s-named-symbols-in-h.md)). Line refs that no longer match signal staleness: run `gh pr list -R shader-slang/slangpy --state merged --search "<feature keywords>"` after the issue's `createdAt` ([stale line-refs signal it may already be implemented](../learnings/1781015582617-slangpy-triage-stale-line-refs-in-an-issue-signal-.md)).

Case #844 (thread group size / 2D tile dispatch / groupshared kernels) already works off `.dispatch()`: `FunctionNode.call_group_shape(shape)` (`slangpy/core/function.py`) drives `[numthreads(call_group_size,1,1)]` (the internal 32,1,1 is only a default), and the generated `compute_main` exposes `SV_DispatchThreadID`/`SV_GroupID`/`SV_GroupIndex` via `CallShapeInfo`, so one tile maps to one thread group. `groupshared` tile code without `call_group_shape` silently corrupts shared memory (missing API usage, not a bug). The `.dispatch()` + `torch.Tensor` gap (#832) errors cleanly and a ~5-line lazy-init mirror would fix it, but maintainer mkeshavaNV directed NOT to add features to `.dispatch()` (slated for removal, gated on the #768 raw-dispatch redesign) ([slangpy call_group_shape already provides tile/groupshared dispatch (#844)](../learnings/1783522957219-slangpy-call-group-shape-already-provides-tile-gro.md)).

### CUDA codegen issues: search slang core first
For a missing GPU-codegen capability (texture formats, intrinsics, target behavior), run `gh pr list -R shader-slang/slang --search "<topic>" --state all` before assuming a slang-rhi handoff or a slangpy fix. Case #808 (CUDA surface/texture write format conversion): `surf*Dwrite` does raw byte writes, so the float→normalized/packed conversion must be emitted at the write site by Slang's CUDA codegen; slang-rhi's `format-conversion.h` is CPU-side only. The fix, shader-slang/slang PR #11090, was already in flight ([slangpy #808: fix is upstream slang PR #11090, not slang-rhi](../learnings/1781015966794-slangpy-808-cuda-texture-format-conversion-fix-is-.md)).

### Tracking issues for collaborator PRs
If an issue tracks an open collaborator PR, park the fix-forward (do NOT dispatch slang-fixer — a bot PR would conflict), but still HEAD-verify claims, set Issue Type, post the 5-bullet verdict, and flag whether linked PRs carry `Closes #N` ([Slang CUDA: __constant__-vs-.param codegen check](../learnings/1782457879561-slang-cuda-constant-vs-param-codegen-check-slangpy.md)).

## Runtime and API behavior

### Python `id()` does not reflect C++ `IModule*` identity
Python `id(m)` differing across `session.load_module(...)` calls is not a slang-core bug: slangpy mints a fresh wrapper per call over the same `IModule*`. Verify with pointer comparison in standalone C++; `Linkage::loadModule` returns `asExternal(module)` (a plain `static_cast<slang::IModule*>(Module*)`) and caching works via `findOrImportModule` ([slangpy Python id() ≠ C++ IModule* identity](../learnings/1779891890025-slangpy-python-id-c-imodule-identity.md)).

### `create_buffer` struct size is a silent footgun
`device.create_buffer(element_count=n, struct_size=K)` allocates exactly `n*K` bytes and never checks `K` against the per-target element stride Slang codegen bakes in for `buffer[i]`. A smaller `struct_size` gives silent out-of-bounds access the debug layer misses — correct on one backend, corrupt on another. Pass `resource_type_layout=program.reflection.<bufferParam>`, from which SlangPy derives `struct_size = element_type_layout()->stride()` (`src/sgl/device/resource.cpp:66-91`) — the only backend-correct host-side allocation ([SlangPy create_buffer struct_size is a silent backend-layout footgun](../learnings/1780598190908-slangpy-create-buffer-struct-size-is-a-silent-back.md)).

### Slang version: bundled via `SGL_SLANG_VERSION`
slangpy fetches a prebuilt Slang release tarball via CMake FetchContent, pinned by `set(SGL_SLANG_VERSION "<ver>" ...)` in `slangpy/external/CMakeLists.txt`; slang-rhi reuses it (`SLANG_RHI_FETCH_SLANG OFF`). Local override: `SGL_LOCAL_SLANG=ON` + `SGL_LOCAL_SLANG_DIR`. Runtime check: `import slangpy; print(slangpy.SLANG_BUILD_TAG)` (from `spGetBuildTagString()`). slangpy-samples pins nothing and uses the installed `slangpy` ([slangpy bundles Slang via SGL_SLANG_VERSION; runtime check is SLANG_BUILD_TAG](../learnings/1781166935218-slangpy-bundles-slang-via-sgl-slang-version-sample.md)).

**"Deferred until the upstream Slang fix ships" gates on the pin**, not the next wheel — misread it and you re-add a test that still fails. The pin moves only when bumped and lags (on 2026-08-03 it was `2026.12`, five releases behind), and a wheel bundles whatever the pin says. Check three stages: (1) *merge* — `gh api repos/shader-slang/slang/pulls/N --jq '.merged, .merge_commit_sha'`; (2) *a tag CONTAINING the merge commit*, not merely a newer tag — `gh api repos/shader-slang/slang/compare/<tag>...<merge_sha> --jq '.status'` must be `behind`/`identical` (`ahead` = not in it: slang#12299's `546ad18f` was 25 commits ahead of newest tag `v2026.14.1`); (3) *the pin bump* — `gh api repos/shader-slang/slangpy/contents/external/CMakeLists.txt --jq '.content' | base64 -d | grep SGL_SLANG_VERSION`. The pin also moves under parked requests: slangpy#1226 asked for a release bundling 2026.19, and `main` moved to 2026.20 (#1237) 3 days after triage, so "cut a release from main" no longer matched. Before re-pinging, run `gh api repos/shader-slang/slangpy/compare/<triage-base>...main` and state the current pin and the last commit carrying the requested one ([re-verify the Slang pin when re-checking a parked release request](../learnings/1792404330976-re-verify-the-slang-pin-when-re-checking-a-parked-.md)).

To verify without waiting, `.github/workflows/ci-latest-slang.yml` builds slangpy `main` against Slang **master** — nightly 01:00 UTC, `workflow_dispatch` with `slang_branch`, and `repository_dispatch` per Slang PR (slang#12299 got green runs, GPU `Unit Tests (Python)` included, before merging); locally use `SGL_LOCAL_SLANG=ON -DSGL_LOCAL_SLANG_DIR=<slang>`. Its `build-pr` job runs `actions/checkout@v6` with no `ref:`, so it always builds slangpy's default branch, and is a reduced Linux+Windows Release matrix (nightly `build` adds Debug and macOS): real, not full-matrix evidence. In reports, "fixed upstream" and "available to slangpy" are two unbounded human steps apart — say which you mean ([deferred-on-upstream work gates on the SGL_SLANG_VERSION pin, not a wheel release](../learnings/1785800138090-slangpy-deferred-on-upstream-work-gates-on-the-sgl.md)).

### CUDA constant vs param codegen
No-GPU discriminator for CUDA entry-point args vs `ParameterBlock` lowering: compile both with `slangc -target cuda -profile cs_6_0 -entry main` and grep the `.cu`. Entry-point args land in the `.param` bank (slow serial `ld.param` for runtime-indexed resource arrays); `ParameterBlock<CallData>` emits `extern "C" __constant__ GlobalParams_0 SLANG_globalParams` (fast `ld.const`).
