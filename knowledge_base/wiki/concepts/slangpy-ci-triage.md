# SlangPy CI, Triage, Build, and Runtime

Operational knowledge for working with slangpy's CI system, triaging GitHub issues, understanding runtime/API behavior, and building from source. Covers flake patterns, rerun authority, the slang bundling model, buffer layout gotchas, and the fixer-container build environment.

> Related pages: [Crashing Tests & CI Flake](slangpy-test-crashes-and-ci-flake.md) · [Build from Source & Infra/Ops](slangpy-build-and-infra-operations.md) · [Build, CI Structure & Toolchain](slangpy-f0909b0-build-ci-toolchain.md) · [GPU Validation & Cross-Repo Guards](slangpy-gpu-validation-and-cross-repo-guards.md) · [Bug Investigations](slangpy-f0909b0-bug-investigations.md).
## TL;DR
- **Cross-repo `gh run rerun <id> --repo shader-slang/slangpy --failed` WORKS (since 2026-08-03)** — rerun slangpy reds yourself under the 3/PR/day cap. The old "Must have admin rights" 403 was the OneCLI gateway PAT-routing collision, never a missing scope: never ask to "grant slangpy actions:write".
- **Exit 0 is NOT proof a rerun fired — the `run_attempt` increment is** (`gh … | jq` reports jq's status and launders gh failures).
- **Classify a slangpy red by determinism, not permissions** — intermittent (dep-fetch 5xx, DXC fetch 500 at CMake configure) → rerun; deterministic/author-owned (setup-python toolcache, `E36121`, code break) → no rerun.
- **Probe the operation; don't introspect permissions** — before repeating a "bot cannot do X" memory line, grep the action ledger (`rerun-log.jsonl`) for a counterexample.
- **RETRACTED GPU-leak claims (#115/#608/#827 don't reproduce at HEAD)** — CI CUDA-OOM is peak concurrent VRAM (4 xdist workers × ~5 GB), a plateauing step function, not a monotonic leak.
- **When A/B-ing against a local Slang build, `SGL_LOCAL_SLANG_BUILD_DIR` must point at `build/Release`, never the downloaded `build/slang-<ver>-linux-x86_64/` release artifact** — it lacks the PR and makes BOTH arms come back clean, a false negative. Prove it with `strings <dir>/libslang*.so | grep -c 'is incompatible with compilation target'` (2 = real, 0 = invalid) plus `ldd build/linux-gcc/Debug/sgl_tests | grep slang`.
- **Slang's `default` CMake preset is Ninja Multi-Config, so `-DCMAKE_BUILD_TYPE=Release` is inert** — `--config Release` selects the config.
- **Establish the pinned-Slang baseline control BEFORE any A/B** — the 5 residual `sgl_tests` failures are LFS-fixture cases (3 `test_dds_file.cpp` + 2 `test_texture_loader.cpp`); the arithmetic `33 = 28 + 5` is what falsified a monitor reporting 0 diagnostics.
- **`git checkout <commit> -- <path>` STAGES as well as writing the worktree, so plain `git diff` is empty and a revert looks like a no-op** — use `git diff HEAD` / `git status --porcelain`; prove a PR is unmerged with `git merge-base --is-ancestor <pr-head> origin/master`.
- **Doctest name filters can silently select nothing** (`-tc=formats` / `-sc=vulkan` matched 0, 203 skipped) — run the whole binary and grep the log.
- **A stubgen (`numpy`/`libcst`) failure aborts ninja BEFORE the `sgl_tests` link — a FALSE GREEN where a stale binary (once 10 days older than HEAD) "passes"** — build `--target sgl_tests` explicitly and require both `sgl_tests` and `libsgl.so` mtimes newer than a pre-build `date` stamp; a fresh `.o` is not sufficient.
- **Building slangpy needs `python3-dev`/`python3.11-dev` and `--break-system-packages` on every pip call (PEP-668)** — `tools/ci.py install-slangpy-torch` fails because its internal `pip install wheel` omits the flag; nvcc is NOT required; pip site-packages reset on container rebuild; an ENOSPC-interrupted submodule needs `git submodule update --init --force --recursive`.
- **The full C++ `sgl` build needs the `data` submodule's two git-LFS fonts** — without git-lfs you get ~131-byte pointer stubs and ninja dies on `Inconsolata-Regular.ttf` before any source compiles. Verify byte sizes (Montserrat 197624 B, Inconsolata 101752 B), not existence.
- **`create_buffer(struct_size=K)` never reconciles `K` with Slang's per-target stride (silent OOB)** — pass `resource_type_layout=program.reflection.<bufferParam>`. **Python `id(m)` differing per `load_module` is not an `IModule*` bug** — slangpy mints a fresh wrapper per call.
- **`device.load_program("mod.slang", ["one_ep"])` capability-checks EVERY `[shader]` entry point in the module at load time** — one illegal EP sinks its clean siblings; guard it with the SGL-injected `#ifndef __TARGET_CUDA__`. **`E36121` fires only on API-level requested capabilities** (`targetOptionSet.getArray(CompilerOptionName::Capability)`), never by walking declarations, so `[__requiresNVAPI]` is not a second fix site — read a diagnostic's emission loop, not its wording.
- **`0 assertions failed` alongside N failed test cases signals a module-load/compile break, not a logic regression** — read the compiler diagnostic.
- **`ci-latest-slang.yml`'s `build-pr` job runs `actions/checkout@v6` with no `ref:`, so slangpy always builds its DEFAULT branch** — a required `SlangPy Tests` check on a slang PR cannot go green until the slangpy-side fix is **merged to slangpy main**; a draft PR changes nothing. An existing `ci-latest-slang` run is the cheapest proof a slang fix works with slangpy (reduced matrix).
- **"Deferred until the upstream Slang fix ships" gates on the `SGL_SLANG_VERSION` pin, not a wheel release** — check merge, a tag CONTAINING the commit, then the pin bump; the pin lags and moves while requests are parked.
- **`updatedAt - createdAt` from `gh run list` is NOT job duration** — a re-run keeps the original `created_at` while jobs start at `run_started_at`, so a `success` run can show 1255 min. Use per-job durations.
- **Measure GPU presence each session** (L40S since 2026-10-16 after a passthrough outage); coop-VECTOR compiles but cannot dispatch, so compile-only checks give false confidence.
- **NVRTC/CUDA downstream compilation is deferred to the first `kernel.dispatch(...)`** — a test stopping at `create_compute_kernel` never runs NVRTC; dispatch with a real output buffer and expect `RuntimeError`. `downstream_args` reach only DXC and NVRTC, silently dropped elsewhere.
- **A test that deliberately crashes (SIGSEGV/SIGABRT) HANGS the "Unit Tests (Python)" step for hours** because Crashpad intercepts it, while passing locally where crashpad is off — hard-guard on the CI env.
- **One test can remove the shared D3D12 device and cascade into hundreds of "Failed to create device!" failures** that look like infra flake — grep `Device removal has been triggered` and find the first-emitting test per xdist worker; "my tests passed" is meaningless if they ran before the poisoner.
- **slangpy-samples `pre-commit run --all-files` lets one pre-existing violation red EVERY PR**, and **`PATCH` of an existing bot issue comment 403s while `POST` works** — make status updates append-only fresh comments.
- **Before mapping a solution space, grep HEAD for the feature's symbols and check merged PRs**; for GPU-codegen gaps search `shader-slang/slang` PRs first.

## CI Flakes and Infra Failures

### Crash Dump Re-symbolization
When a slangpy CI abort is buried under crashpad symbolizer noise (`elf_dynamic_array_reader.h:64 tag not found` spam), first download the run's `crash-reports-${os}-${platform}-${compiler}-${config}` artifact and re-symbolize the `.dmp` locally with full symbols (e.g. `minidump-stackwalk` against a debug build of the same sha). `Upload Crashpad Reports` (`.github/workflows/ci.yml:228-234`) uploads `.dmp` + `.txt` + `.json` only when `matrix.flags` contains `crashpad`; the on-the-fly stackwalk in `slangpy/testing/crashpad.py:_postprocess_reports` (~lines 105-145) is shallow and the aborting worker's stderr gets buried. [slangpy CI flake triage: re-symbolize the existing .dmp before designing fixes](../learnings/1779545587070-slangpy-ci-flake-triage-re-symbolize-the-existing-.md)

### GPU OOM on the Shared nvrgfx Runner (not a leak)
**Signature:** `SlangPy Tests` fails with `cuMemAlloc ... CUDA_ERROR_OUT_OF_MEMORY`, `RuntimeError: Failed to create device!` and pytest-xdist `replacing crashed worker gwN`; hundreds of tests fail across unrelated files (test_dtypes, test_buffer, test_reflection2, test_torchintegration) while thousands pass — GPU contention, not a regression. `pytest slangpy/tests -vra -n auto --maxprocesses=4` puts up to 4 workers, each with CUDA + Vulkan(+D3D12)+torch contexts, on ONE shared `nvrgfx` Linux GPU; reruns re-contend and often re-fail. [SlangPy CI flake: shared nvrgfx GPU runner CUDA OOM](../learnings/1781122096821-slangpy-ci-flake-shared-nvrgfx-gpu-runner-cuda-oom.md)

On an L40S (46GB, debug layers on), single-process micro-repros of leaks #115 (functional API), #608 (command-encoder) and #827 (torch-interop) were **flat after warm-up** (0 growth over 5k–20k iters, `nvidia-smi` per iteration), while a real CUDA suite slice showed a **step function** that plateaus at ~5 GB for one CUDA-only worker. The cascade (e.g. #1024) is **peak concurrent VRAM = workers × per-worker high-water mark**; the first failed alloc cascades to every worker. Tell a LEAK (monotonic climb on a repeated op) from a HIGH-WATER-MARK working set by sampling both a micro-loop and the real suite; probe at `/workspace/agent/leak_probe.py`. Fix is maintainer-side: right-size runner VRAM to ≥ `maxprocesses × per-worker peak` + headroom, lower per-worker peak, cap GPU-job concurrency, or add a per-job GPU-memory budget; maintainers rejected a `--maxprocesses` cut as a wall-clock-costly stopgap, so measure per-worker high-water first. Side finding: Vulkan + CUDA-interop (`enable_cuda_interop`) throws `SLANG_FAIL` on `command_encoder->finish()` on L40S — functional, adjacent to #929/#823. [slangpy GPU mem-leak #115/#608 don't reproduce at HEAD; CI OOM is concurrent-peak high-water-mark, not a leak](../learnings/1782324497848-slangpy-gpu-mem-leak-115-608-don-t-reproduce-at-he.md) ([CI GPU-OOM that passes on rerun is usually peak concurrent VRAM, not a leak](../learnings/1782896626067-ci-gpu-oom-that-passes-on-rerun-is-usually-peak-co.md))

### Reading Cross-Backend (incl. Metal) Test Outcomes from CI
Without local macOS/GPU, read per-test PASS/FAIL from each job's "Unit Tests (Python)" step: linux gcc Debug runs vulkan + cuda, windows msvc Debug runs d3d12 + vulkan + cuda, and `build (macos, aarch64, clang, Debug/Release, 3.10)` runs the FULL suite on metal. `gh run view --job <job-id> -R shader-slang/slangpy --log | grep -iE "<test_name>|DeviceType.metal"` (job id from the `/job/<id>` URL in `gh pr checks`) retires a "platform X unverified" gap, e.g. `test_missing_shader_path_error[DeviceType.metal] PASSED`. **While any job in the run is still going, `gh run view --log --job` returns nothing** — use `gh api --allow-escape-sequences repos/shader-slang/slangpy/actions/jobs/<id>/logs`, strip ANSI, grep `(PASSED|FAILED|SKIPPED).*<test_file>` (ids from `detailsUrl` in `gh pr view --json statusCheckRollup`). A PASS cannot prove which of two string-match arms fired. Static A/B for an autodiff fix in `slangpy/slang/*.slang`: `git archive` both arms, compile an `import slangpy;` probe calling `bwd_diff(f)` with the bundled `slangc -I <arm>/slangpy/slang -target hlsl`, and count `Interlocked` / `Tensor_read_buffer.*_grad_in`. From PR #1178: a raw `spy.Device()` has EMPTY `slang_session.desc.compiler_options.include_paths`; only `spy.create_device()` prepends `SHADER_PATH` = `slangpy/slang`, and the failure reads exactly `cannot open file 'slangpy.slang'` (Slang single-quotes the bare filename). ([SlangPy CI: per-job test logs mid-run](../learnings/1791194997507-slangpy-ci-per-job-test-logs-while-a-workflow-run-.md)) ([SlangPy CI macOS build jobs run the full pytest suite incl. ## Rerun Authority

### Current rule: rerun slangpy reds yourself, verify via `run_attempt`
A slang PR's cross-repo **SlangPy Tests** run lives in `shader-slang/slangpy` (`repository_dispatch`); find the run id there. Its rerun once returned "Must have admin rights to Repository," read as a structural admin-only rule for `repository_dispatch` runs [SlangPy Tests failures on slang PRs are not bot-rerunnable (admin-rights boundary — superseded)](../learnings/1782166177663-slangpy-tests-failures-on-slang-prs-are-not-bot-re.md). Re-probed 2026-08-03 on slang PR #12116 (slangpy run `30808650114`): exit 0, `run_attempt` **1 → 2**. It has held: `rerun-log.jsonl` records reruns on #11709, #13078 (2026-09-29) and #13357 (10-01), and `--job <job-id>` on #12766 (10-02) flipped the run to `queued`. Yet a stale "App token is scoped to `slang/*`" memory line was re-asserted while `grep -i slangpy rerun-log.jsonl` refuted it. A "cannot do X" line is a claim that rots: grep the durable action ledger before repeating one, and correct it in place with a dated note rather than deleting it ([stale "bot cannot rerun slangpy" claim contradicted by the rerun-log.jsonl precedent](../learnings/1790907793442-stale-bot-cannot-rerun-slangpy-claim-contradicted-.md)). All-false `permissions` on slangpy never blocked action (log reads always worked).

Under the gateway a failed call can still exit 0 (the phantom-green laundering), so after any rerun confirm the counter moved:

```bash
gh api repos/shader-slang/slangpy/actions/runs/<id> --jq '{status,conclusion,attempt:.run_attempt}'
```

Intermittent signatures (dep-fetch 5xx, network, single-platform transient) → rerun under the 3/PR/day cap. Deterministic or owned ones (setup-python toolcache, slang#11225's E36121, an author code break) → no rerun, because a rerun cannot fix them. A DXC prebuilt fetch 500 (`downloading '.../dxc_2026_02_20.zip' failed … CMake Error at download-dxc-populate.cmake:163`, then `ninja: error: loading 'build-Release.ninja'`) fails at CMake configure, so zero tests run; it comes from `FetchDXC.cmake`, a different call site from the `FetchedSharedLibrary.cmake` that slang PR #12323 fixes — one root cause, two call sites ([cross-repo `gh run rerun` on slangpy now works — verify via `run_attempt`, not exit code](../learnings/1785773902337-cross-repo-gh-run-rerun-on-shader-slang-slangpy-no.md)).

### Check HEAD and Merged PRs Before Mapping a Solution
When a slangpy feature request cites file:line pointers, grep HEAD for its named symbols first: sub-task issues under an umbrella effort lag the code, because the umbrella PR closes the substance but not the issue. Already wired and tested → needs-decision, not ready-for-fix. Case #844 (thread group size / 2D tile dispatch / groupshared kernels) already works off `.dispatch()`: `FunctionNode.call_group_shape(shape)` (`slangpy/core/function.py`) drives `[numthreads(call_group_size,1,1)]` (the internal 32,1,1 is only a default), and generated `compute_main` exposes `SV_DispatchThreadID`/`SV_GroupID`/`SV_GroupIndex` via `CallShapeInfo`, so one tile maps to one thread group. `groupshared` tile code without `call_group_shape` silently corrupts shared memory (missing API usage, not a bug). ## Runtime and API Behavior

### Python `id()` Does Not Reflect C++ IModule* Identity
Python `id(m)` differing across `session.load_module(...)` calls is not a slang-core bug: slangpy mints a fresh wrapper per call over the same `IModule*`. Verify with pointer comparison in standalone C++; `Linkage::loadModule` returns `asExternal(module)` (a plain `static_cast<slang::IModule*>(Module*)`) and caching works via `findOrImportModule`. [slangpy Python id() ≠ C++ IModule* identity](../learnings/1779891890025-slangpy-python-id-c-imodule-identity.md)

### `create_buffer` Struct Size is a Silent Footgun
`device.create_buffer(element_count=n, struct_size=K)` allocates exactly `n*K` bytes and never checks `K` against the per-target element stride Slang codegen bakes in for `buffer[i]`. A smaller `struct_size` gives silent out-of-bounds the debug layer misses — correct on one backend, corrupt on another. Pass `resource_type_layout=program.reflection.<bufferParam>`, from which SlangPy derives `struct_size = element_type_layout()->stride()` (`src/sgl/device/resource.cpp:66-91`) — the only backend-correct host-side allocation. [SlangPy create_buffer struct_size is a silent backend-layout footgun — use resource_type_layout](../learnings/1780598190908-slangpy-create-buffer-struct-size-is-a-silent-back.md)

### Slang Version: Bundled via SGL_SLANG_VERSION
slangpy fetches a prebuilt Slang release tarball via CMake FetchContent, pinned by `set(SGL_SLANG_VERSION "<ver>" ...)` in `slangpy/external/CMakeLists.txt` (line 85); slang-rhi reuses it (`SLANG_RHI_FETCH_SLANG OFF`). Local override: `SGL_LOCAL_SLANG=ON` + `SGL_LOCAL_SLANG_DIR`. Runtime check: `import slangpy; print(slangpy.SLANG_BUILD_TAG)` (bound in `src/slangpy_ext/slangpy_ext.cpp:114` from `spGetBuildTagString()`). slangpy-samples pins nothing and uses the installed `slangpy`. [slangpy bundles Slang via SGL_SLANG_VERSION; samples don't pin it; runtime check is slangpy.SLANG_BUILD_TAG](../learnings/1781166935218-slangpy-bundles-slang-via-sgl-slang-version-sample.md)

**"Deferred until the upstream Slang fix ships" gates on the pin**, not the next wheel — misread it and you re-add a test that still fails. The pin moves only when bumped and lags: on 2026-08-03 it was `2026.12` (last bumped 2026-06-30, #1037), five releases behind, and a wheel bundles whatever the pin says. Check three stages: (1) *merge* — `gh api repos/shader-slang/slang/pulls/N --jq '.merged, .merge_commit_sha'`; (2) *a tag CONTAINING the merge commit*, not merely a newer tag — `gh api repos/shader-slang/slang/compare/<tag>...<merge_sha> --jq '.status'` must be `behind`/`identical` (`ahead` = not in it: slang#12299's `546ad18f`, merged 08-03T21:28Z, was 25 commits ahead of newest tag `v2026.14.1`); (3) *the pin bump* — `gh api repos/shader-slang/slangpy/contents/external/CMakeLists.txt --jq '.content' | base64 -d | grep SGL_SLANG_VERSION`. The pin also moves under parked requests: slangpy#1226 asked for a release bundling 2026.19, and `main` moved to 2026.20 (#1237) 3 days after triage, so "cut a release from main" no longer matched. Before re-pinging, run `gh api repos/shader-slang/slangpy/compare/<triage-base>...main` and state the current pin and the last commit carrying the requested one ([re-verify the Slang pin when re-checking a parked release request](../learnings/1792404330976-re-verify-the-slang-pin-when-re-checking-a-parked-.md)).

To verify without waiting, `.github/workflows/ci-latest-slang.yml` builds slangpy `main` against Slang **master** — nightly 01:00 UTC, `workflow_dispatch` with `slang_branch`, and `repository_dispatch` per Slang PR (slang#12299 got green runs `30836651948` and `30848628629`, GPU `Unit Tests (Python)` included, before merging); locally use `SGL_LOCAL_SLANG=ON -DSGL_LOCAL_SLANG_DIR=<slang>`. `build-pr` is a reduced Linux+Windows Release matrix (nightly `build` adds Debug and macOS): real, not full-matrix evidence. In reports, "fixed upstream" and "available to slangpy" are two unbounded human steps apart — say which you mean ([deferred-on-upstream work gates on the SGL_SLANG_VERSION pin, not on a wheel release](../learnings/1785800138090-slangpy-deferred-on-upstream-work-gates-on-the-sgl.md)).

### CUDA Constant vs Param Codegen
No-GPU discriminator for CUDA entry-point-args vs `ParameterBlock` lowering: compile both with `slangc -target cuda -profile cs_6_0 -entry main` and grep the `.cu`. Entry-point args land in the `.param` bank (slow serial `ld.param` for runtime-indexed resource arrays); `ParameterBlock<CallData>` emits `extern "C" __constant__ GlobalParams_0 SLANG_globalParams` (fast `ld.const`).
