# Slang Test — FileCheck Authoring and Opt-Levels

This page covers **FileCheck itself** as slang-test runs it: where the checker comes from, how to prove it ran, fallbacks when it is absent, `CHECK-NOT`/`-DAG` region and vacuity traps, golden-diffing, and the `-O0` / pre-opt-validation harness defaults. Siblings: output-path/status assertions and truncated runs on [Slang Test — Output Assertions and Truncated Runs](slang-test-output-assertions-and-truncated-runs.md); directive authoring on [part 1](slang-misc-test-harness.md); false greens on [slang-test False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md); `#line`/location checks and mutation drills on [slang-test #line directive and source-location checks](slang-test-line-directive-and-location-checks.md).

## TL;DR

- **`slang-test` never runs a `FileCheck` binary from `PATH`.** It loads FileCheck in-process from the `slang-llvm` library (`test-context.cpp:95-113`, gated at `slang-test-main.cpp:5915` on `hasLlvm`).
- **The library is `build/Debug/lib/libslang-llvm.so` (not `bin/`) and is present in the standard build** — probe with `find build -iname '*slang-llvm*'`, never `ls bin/` or `which FileCheck`.
- **Only a failable control proves FileCheck ran:** inject a broken CHECK, require RED (parse `FAILED test:`; the exit code is 0), restore, and `diff` that each edit landed.
- **With the library missing, `SIMPLE(filecheck=)` reports `Ignored` but `COMPARE_COMPUTE(filecheck-buffer=)` reports `passed`.** Copy a prebuilt `libslang-llvm.so` into the worktree's `build/Debug/lib/`, or check `<test>.slang.actual.txt` by hand.
- **A Python FileCheck emulator is a different implementation.** Validate it both ways and report "passes under an emulator; LLVM FileCheck in CI is authoritative."
- **Hand-verify CHECK lines with an ORDERED matcher** (each CHECK at or after the previous match's end), never by counting matches.
- **A `CHECK-NOT` scans only between its adjacent positive matches, and never between the matches of a `-DAG` group.** Moving it to the top does not help; the only whole-output negative is a lone `-NOT` under its own `filecheck=` prefix.
- **A correctly-scoped `-NOT` is still vacuous if DCE removed its subject** — grep for the instruction with the decoration stripped, fence every negative with a positive, and flip it to a known-present pattern to confirm RED.
- **`-DAG` lines do not bind a value to its function, and a bare `1` matches `10`.** One prefix per helper with `-NEXT`, anchor values as `{{^}}1{{$}}`, and mutant-drill every new pin test.
- **When an intentional change breaks a CHECK only through an incidental token, loosen the line to the claim** (`if{{[(]+}}a_N > ...`); don't re-pin the new spelling.
- **`PREFIX:` anywhere in a line — prose, backticks — is a live directive.** Never write the active prefix plus colon in explanatory text; a fix can be verified statically with a regex.
- **Diff emit/lowering changes against goldens whenever you have not PROVED FileCheck ran.** Uniform failure across arches = real regression; one platform only = drift or flake.
- **slang-test front-inserts `-O0`**, so a fold-dependent CHECK needs explicit `-O1`; a suite-wide override plumbs through `context->options` and both `addDefault*` helpers.
- **render-test compiles every COMPARE_COMPUTE row with debug info ON unless the row passes `-g0`.** Debug insts block IR optimizations, so an optimization-dependent row can fail where plain `slangc` passes; reproduce with `slangc -g2`.
- **Place a negative by EMISSION order:** direct SPIR-V emits `OpDecorate %v NonReadable` before `OpDecorate %v Binding`, so a `-NOT` after a Binding anchor never sees it.
- **`SLANG_RUN_SPIRV_VALIDATION=1` validates PRE-optimization SPIR-V** — pin an optimizer-introduced defect with a `-target spirv-asm` operand-count check anchored by `{{$}}`.
- **A `-target spirv` SIMPLE test with no `[shader("compute")]`/`-entry`/`-stage` has NO entry point** and silently exercises only the fallback path.
- **The `OpSource` token is env-dependent** (`Slang`, or `Unknown` where aarch64 CI sets `SLANG_USE_SPV_SOURCE_LANGUAGE_UNKNOWN=1`) — match `OpSource {{Slang|Unknown}} 1`.
- **At `-g2` the source, comments included, is an `OpString`, so FileCheck matches your own `//CHECK` lines.** Drop `-g2` or anchor with `{{^}}`.
- **A byte-offset fixture needs `text eol=lf` in `.gitattributes`**, or Windows CRLF shifts the byte.
- **Attempt a crafted minimal reproducer before concluding a sanitizer witness is un-addable.**
- **Ask of every new test: what would have to break for this to stay green?** If the answer includes "the compile fails," add a status assertion.
- **A textual-emitter miscompile needs `-vk -emit-spirv-via-glsl` to show at runtime**; `-cpu`/`-cuda` can mask it, so pair runtime tests with per-target text FileChecks ordered by emission order.

## Where FileCheck comes from, and proving it ran

`slang-test` **never** invokes a `FileCheck` executable. `TestContext::locateLLVMFileCheck()` (`tools/slang-test/test-context.cpp:95-113`) calls `loader->loadSharedLibrary("slang-llvm", …)` then `findFuncByName("createLLVMFileCheck_V1")`; it is invoked from `slang-test-main.cpp:5917` and **gated at `:5915` on `if (hasLlvm)`** (`checkPassThroughSupport(SLANG_PASS_THROUGH_LLVM)`). A `pip install filecheck` on `~/.local/bin`, an `apt` LLVM `FileCheck`, or anything else on `PATH` **cannot influence slang-test at all** — the library is the dependency ([slang-test `filecheck=` tests need the slang-llvm library, not a FileCheck binary on PATH](../learnings/1785824518254-slang-test-filecheck-tests-need-the-slang-llvm-lib.md)).

**In the standard container build, LLVM FileCheck does run locally.** The library is at **`build/Debug/lib/libslang-llvm.so`** (152 MB) and `DefaultSharedLibraryLoader` searches library paths, so an empty `ls build/Debug/bin/ | grep slang-llvm` establishes nothing; `find build -iname '*slang-llvm*'` settles it. A retracted note made exactly that mistake (see *Contradictions*). Settle the question with a failable control, because a skipped test and a passing test are the same colour in the summary:

```
# 1. baseline
./build/Debug/bin/slang-test tests/language-feature/function-calls/forceinline-basic-block.slang
  → "Supported backends: … llvm …" ; "passed test:" ; 100% (1/1)
# 2. CONTROL — inject a deliberately broken CHECK pattern into the same file
  → "FAILED test:" ; 0% of tests passed (0/1)
# 3. restore → passes again
```

⚠️ `slang-test`'s **process exit code was 0 even on the FAILED test** — parse the `FAILED test:` / `% of tests passed` lines, never `$?`. A bundled DXC-tree FileCheck (`build/_deps/dxc_source-src/utils/FileCheck`) may also exist; infer availability from neither path — run the control ([CORRECTION — the "slang-llvm absent / filecheck= tests skip" claim was FALSE; LLVM FileCheck runs locally, proved with a failable control](../learnings/1785824734935-correction-slang-llvm-filecheck-my-library-absent-.md)). False capability-negatives are the worst class to leave in shared prose: readers act on them by *not trying*.

## When the library is genuinely missing

The usual cause is a worktree configured `-DSLANG_SLANG_LLVM_FLAVOR=DISABLE` for a fast build. `_fileCheckTest` then logs `FileCheck is not available` (visible only with `-v`) and returns `TestResult::Ignored` (`slang-test-main.cpp:843-848`). A `SIMPLE(filecheck=…)` test reports *ignored* (0/0). **The buffer form is the dangerous one:** `runComputeComparisonImpl` returns `TestReporter::combine(compileResult, bufferResult)` (`:4687`), and `combine` keeps the larger value (`test-reporter.h:194`; `Ignored = 0 < Pass = 1`), so a `COMPARE_COMPUTE(filecheck-buffer=…)` test reports **passed** with no CHECK line evaluated. Measured twice: a value test passed with 16 wrong outputs, and changing an expected value from 3 to 99 still passed ([filecheck-buffer tests pass vacuously when slang-llvm is disabled](../learnings/1790896856276-slang-test-filecheck-buffer-tests-pass-vacuously-w.md), [slang-test passes filecheck-buffer tests without enforcing CHECKs when FileCheck is absent](../learnings/1790913402068-slang-test-passes-filecheck-buffer-tests-without-e.md)). The `-output-using-type` header trap both atoms mention (`CHECK: 3` matching `int32_t`) is on [Slang test authoring: FileCheck efficacy](slang-tooling-f0909b0-test-authoring-filecheck.md).

**Fix: copy a prebuilt `libslang-llvm.so` from the shared base clone into the worktree's `build/Debug/lib/`** — FileCheck V1 is target-independent, so version drift is fine. Remove it, or caveat `tests/llvm/*` failures, before quoting full-suite numbers. A Python simulator that passed for #12170 later FAILED under real FileCheck because backreference and scan semantics differ ([run filecheck .slang tests through real slang-test (copy libslang-llvm.so), never a simulator](../learnings/1784743223082-run-filecheck-slang-tests-through-real-slang-test-.md)). If you cannot, read the `<test>.slang.actual.txt` slang-test writes beside the test, match the CHECK/CHECK-NEXT chain against it, and tell reviewers CI is the first real FileCheck run.

A `pip install filecheck` emulator is acceptable only as a **parallel** harness for local iteration. Validate it bidirectionally first (satisfiable input → exit 0; the real defect reintroduced → exit 1, including the anchors you rely on, such as `{{$}}` rejecting an extra operand), derive compile options from each file's own `//TEST:` directive so it cannot drift from the test, and report "passes under a FileCheck-compatible emulator; **LLVM FileCheck in CI is authoritative**."

To hand-verify, use an **ordered matcher**: each CHECK matches at or after the previous match's end; translate `{{...}}` to regex and `re.escape` the literal spans. Global count-the-matches approximations cannot express FileCheck's ordered `CHECK` / windowed `CHECK-NOT` semantics and report spurious failures on a file that legitimately repeats a pattern. It caught a real coverage gap — a test exercising every texture shape but asserting only on the 1D arm ([verify FileCheck CHECK directives by ordered-matching emitted output when FileCheck is absent locally](../learnings/1784751927211-verify-filecheck-check-directives-by-ordered-match.md)).

## Harness defaults: `-O0`, pre-opt validation, suite-wide opt level

slang-test **prepends `-O0`** to any directive without an explicit `-OX`, so a fold-dependent CHECK can never match unless you add `-O1`; a manual `slangc` uses the compiler's optimizing default and misleads you. `SLANG_RUN_SPIRV_VALIDATION=1` validates the **pre-optimization** SPIR-V, so an optimizer-introduced defect passes validation; the real signal is a `-target spirv-asm` (post-opt) operand-count assertion with a `{{$}}` end-of-line anchor to tell correct-3 from buggy-4 ([slang-test injects -O0 by default; SPIRV validation runs pre-opt](../learnings/1784762873836-slang-test-injects-o0-by-default-spirv-validation-.md)).

A suite-wide opt-level override plumbs through `context->options`. The `-O0` default is `kTestOptimizationOption` in `slang-test-optimization-options.h`, front-inserted deliberately. Add a `defaultOptimizationLevel` to `Options`, thread an override parameter into `addDefaultSlangOptimization`/`addDefaultRenderTestSlangOptimization`, and pass `context->options.defaultOptimizationLevel` at the call sites (`TestContext::options` is public). `-O0` is the sole spirv-opt early-out, so "force max SpvOpt suite-wide" means `-O3`/maximal ([slang-test suite-wide opt-level override: plumb via context->options](../learnings/1784440518963-slang-test-suite-wide-opt-level-override-plumb-via.md)).

**render-test compiles with debug info ON by default.** Unless a row passes `-g0`, render-test sets `DebugInformation = STANDARD` for every compile (`tools/render-test/options.h:89` defaults `generateSPIRVDirectly=true`; `slang-support.cpp:273-282`; `options.cpp:293`), for every target in the session, `-wgpu` included. `DebugLine`/`DebugScope` then sit between instructions and block passes such as store-to-load forwarding (they fall to the default case of `canInstHaveSideEffectAtAddress`). So a `-wgpu`/`-vk` COMPARE_COMPUTE_EX row can fail while `slangc` without `-g` emits correct code. On PR #13883 the `-wgpu` row failed Tint uniformity on Windows CI while `slangc -target wgsl` passed. Reproduce with `slangc -g2`, and fix the row with `-g0` (precedent: `tests/autodiff/reverse-checkpoint-4.slang`). It showed up only in Windows GPU CI because a default-preset Linux build reports wgpu rows `ignored` (`SLANG_EXCLUDE_DAWN=ON`); a fresh Dawn-ON configure runs them locally ([false greens](slang-test-false-greens-and-verification-traps.md)) ([COMPARE_COMPUTE rows compile with debug info ON; IR-optimization tests need -g0](../learnings/1792768846741-slang-test-compare-compute-rows-compile-with-debug.md)).

## SPIR-V debug-test authoring traps (PR #12202/#12204/#12206)

- **No entry point.** A `-target spirv` SIMPLE test with a bare `[numthreads(1,1,1)] void computeMain(...)` and no `[shader("compute")]`/`-entry`/`-stage` compiles a module with NO entry point — auto-deduction keys on `[shader(...)]`. Anything keyed on entry-point context (e.g. the emitter's `m_defaultDebugSource` primary debug-source path) then exercises only the module-scan fallback, and a primary-path regression stays green. Add `[shader("compute")]` (template: `tests/spirv/debug-info-line-function.slang`), and add a `#include` multi-source test for any "pick the main/non-included source" branch ([SPIR-V debug tests need [shader("compute")]/-entry or they silently test the fallback path](../learnings/1784822694362-slang-spir-v-debug-tests-need-shader-compute-entry.md)).
- **`OpSource` token.** Default `Slang`, but the aarch64 `test-slang` CI jobs export `SLANG_USE_SPV_SOURCE_LANGUAGE_UNKNOWN=1` (a swiftshader workaround), so it disassembles as `Unknown` and a hardcoded `OpSource Slang 1` fails deterministically aarch64-only. Match `OpSource {{Slang|Unknown}} 1`; reproduce without an aarch64 box by running the test normally AND with that env var set ([OpSource language token is env-dependent Slang vs Unknown; FileCheck must use {{Slang|Unknown}} — aarch64 trap](../learnings/1784830837048-spir-v-opsource-language-token-is-env-dependent-sl.md)).
- **`-g2` self-match.** At `-g2` Slang embeds the entire `.slang` source, comments included, as an `OpString`, so a `-NOT` or mnemonic CHECK matches the text of your own directive comments (false positives and vacuous passes). Drop `-g2` if you don't need embedded source (`OpName` is emitted regardless), or anchor with line-start forms like `{{^}}OpName %` ([-g2 embeds source-as-OpString and FileCheck matches your own directive comments](../learnings/1784838497425-slang-test-spirv-filecheck-g2-embeds-source-as-ops.md)).
- **CRLF byte shift.** A fixture whose correctness depends on an EXACT byte offset needs `text eol=lf` in `.gitattributes`; otherwise Windows CI checks it out as CRLF, each `\n`→`\r\n` above the marker shifts the target byte, and it fails Windows-CL-only (reproduce with `sed 's/$/\r/'`). Prefer content-anchored matches; a test that only needs to EXCEED a threshold is CRLF-safe ([byte-exact .slang fixtures need `text eol=lf` in .gitattributes or fail on Windows CRLF](../learnings/1784845596400-byte-exact-slang-test-fixtures-need-text-eol-lf-in.md)).

## `CHECK-NOT` regions, `-DAG` blind spots, and vacuous negatives

A `CHECK-NOT` (likewise `SPV-NOT`, `GLSL-NOT`) scans only the region between its preceding and following positive matches, so a forbidden token emitted *earlier* — a GLSL buffer block or a SPIR-V type decl before `main`/`OpEntryPoint` — is silently missed. Moving the negative to the *top* of the prefix does not fix it; it is then bounded by the next positive. **The only reliable whole-output negative is a lone `-NOT` under its own `filecheck=` prefix with no positive directives to bound it.** On `desc-heap-nonuniform-spirv.slang` a trailing `SPVNONCONST-NOT` after two positive CHECKs was scanning 6 lines, and a `%uint` pattern could not fire against the one `OpCompositeExtract %float` left in that window. The fix costs one extra `//TEST:` line (same entry point, same flags):

```
//TEST:SIMPLE(filecheck=SPVNONCONST):        -target spirv-asm -entry mainNonConstSibling
//TEST:SIMPLE(filecheck=SPVNONCONSTSIBLING): -target spirv-asm -entry mainNonConstSibling
// SPVNONCONST: %[[IDX:[0-9]+]] = OpCompositeExtract %uint %{{.*}} 0 {{.*}}; NonUniform
// lone -NOT under its own prefix -> scans the entire disassembly
// SPVNONCONSTSIBLING-NOT: OpCompositeExtract %uint %{{.*}} 1 {{.*}}; NonUniform
```

Prove the negative is live by flipping it to a pattern you *know* is present and confirming RED — and verify the control itself: two controls tried on this file were themselves vacuous, so `diff` that the edit landed and confirm the flipped pattern really is in the output ([CHECK-NOT is bounded by surrounding positive CHECKs — a lone-prefix negative is the only whole-output assertion](../learnings/1785748572125-filecheck-check-not-is-bounded-by-surrounding-posi.md)). Independently re-derived on #10918: flipping `CHECK-NOT: OpExtInst {{.*}} Debug{{Global}}Variable` to `CHECK-NOT: OpEntryPoint`, which is definitely present, still passed 1/1.

**A `-DAG` group widens the blind spot.** `-NOT` lines before and after a block of `-DAG` lines check only the text before the group's *earliest* match and after its *latest*, never text between DAG matches. On PR #13471 (conflicting-export E45002, the `conflicting-export-13319.slang` WITNESS run), disabling the witness-dedup rule put a duplicate `'Renderer : IRenderer'` warning between the `Thing : IValue` and `Renderer` DAG matches and the test still passed 28/28. Fix it with a separate `//TEST:SIMPLE_EX(filecheck=X-ONCE)` run whose only checks are `X-ONCE-NOT:` lines, then revert-drill the guarded code. In review, revert-drill any `-NOT` next to a `-DAG` group ([FileCheck -NOT around a -DAG group does not guard text between DAG matches](../learnings/1791336888864-filecheck-not-around-a-dag-group-does-not-guard-te.md)).

**Place a negative by emission order, not source order.** Slang's direct SPIR-V emitter writes `OpDecorate %v NonReadable` BEFORE `OpDecorate %v Binding N`, because `maybeEmitWriteOnlyImageDecoration` runs before `emitVarLayout` (seen on #13896). So `RW: OpDecorate %v Binding` followed by `RW-NOT: NonReadable` scans only after the Binding line and skips the real decoration. That test still catches a stray `NonReadable`, but only because the spirv-asm disassembler appends the comment `; NonReadable, Binding 2, …` to the `OpVariable` line further down. Robust forms: a separate prefix run whose only checks are `-NOT` lines, or `X-NOT: NonReadable` followed by `X: %v = OpVariable` (variables come after the annotations section). Confirm with a mutation drill: feed output that has the decoration to the NOT prefix and expect RED. A related lowering fact: `lowerDynamicResourceHeap` gives each `DescriptorHandle<T>` heap element type its own unsized-array `IRGlobalParam` named `__slang_resource_heap` at the shared bindless binding. A per-type decoration (`NonReadable` for WTexture) therefore lands only on that type's `OpVariable`, the RW heap at the same binding is unaffected, and the GLSL path already emits `writeonly` on the WTexture heap ([a NOT check after a Binding anchor misses NonReadable](../learnings/1792783665896-spir-v-filecheck-a-not-check-after-a-binding-ancho.md)).

**Even a correctly-scoped negative is worthless if its subject is never emitted.** On #12116 the negative had its own prefix but asserted `-NOT: OpCompositeExtract %uint %{{.*}} 1 {{.*}}; NonUniform` on a shader whose `.y` lane fed only a `makeVector` that upstream peephole folds delete, so DCE removed the lane-1 extract (`grep -cE 'OpCompositeExtract %uint %[0-9]+ 1' out.spvasm` → **0**). It passed unconditionally, even with the decoration logic inverted. Vacuity test: grep the output for the forbidden instruction with the decoration stripped; zero hits ⇒ vacuous. Then make the subject live (adding `uint2 raw = (uint2)th; … + float(raw.y);` produced an undecorated `OpCompositeExtract %uint %11 1`, confirming the property while indicting the test). Put a positive "so the test is not vacuous" fence next to every negative (in-tree idiom: `tests/spirv/nonuniform-constant-index-no-leak.slang`); and when a clarity reviewer flags a directive/comment contradiction but says "no build in this checkout, cannot resolve," that is precisely the finding a build resolves ([a CHECK-NOT can be vacuous because DCE removed its subject](../learnings/1785754047907-a-filecheck-check-not-can-be-vacuous-because-dce-r.md)).

## Positive pins and refreshing stale CHECK lines

**`-DAG` pins prove each line exists, not which function it is in.** Pinning two WGSL helpers as `WGSL-DAG: fn A`, `WGSL-DAG: let bits = X`, `WGSL-DAG: fn B`, `WGSL-DAG: let bits = Y` still passes if X and Y swap between the helpers. Give each helper its own prefix (`//TEST:SIMPLE(filecheck=HNAN)` with `HNAN: fn …` followed by `HNAN-NEXT:` lines): that binds each body to its function without depending on emission order (a single `WGSL`/`WGSL-NEXT` chain binds them too, but locks the order). **Small integers match larger ones:** a filecheck-buffer test expecting `1`, `2`, `3` passes on `10`, `12`, `13`, worst when an encoding uses 1..3 for NaN/Inf and 10+v for finite values. Write `// CHECK: {{^}}1{{$}}`, or choose codes that cannot overlap (the `-output-using-type` header variant is on [Output Assertions](slang-test-output-assertions-and-truncated-runs.md)). A mutant drill caught both on #13669/#13680, so drill every new runtime or pin test: change the expected value at the source and confirm FAIL ([unanchored small integers and -DAG pins](../learnings/1792149954051-filecheck-unanchored-small-integer-check-lines-mat.md)).

**Refreshing a stale CHECK: pin the claim, not the token that broke it.** Re-pinning the new spelling just moves the brittleness. On #13569 WGSL began wrapping comparisons in parentheses (`if(a > b)` → `if((a > b))`); the robust refresh is `if{{[(]+}}a_N > ...`, which states only what the claim depends on (docs/generated `_meta/prompts/_common.md` rule 8: "Pin only what the claim depends on"). The same review (PR #13731) applied the region rule above: a `WGSL-NOT: break;` placed after `default :` scans only between its neighbouring positives, so it never covered case 0's tail. Prove a refreshed block non-vacuous by compiling a scratch copy whose source violates the claim and confirming RED ([refreshing a stale FileCheck line](../learnings/1792230758914-refreshing-a-stale-filecheck-line-don-t-re-pin-the.md)).

## Goldens and directive collisions

**Diff emit/lowering changes against FileCheck goldens whenever you have not *proved* FileCheck ran** — where the library is missing, a green "no compile error" run is not a pass. Grep every golden touching the modifier/inst you changed and compare slangc output to the ordered `//CHECK:` lines. Uniform failure across all arches = deterministic real regression; one platform only = golden drift or flake. A decoration arm shared by several decl kinds (func vs struct vs field) is the classic over-broad trap: it cost a maintainer-approved PR a 7-platform RED on a `.cuh` golden ([diff emit/header changes against FileCheck goldens even when FileCheck is absent](../learnings/1784421575539-emit-header-changes-diff-against-filecheck-goldens.md)).

**`PREFIX:` anywhere in a line is a live directive.** Stock FileCheck scans every line for the active prefix (optionally followed by `-SUFFIX`) then `:`, ignoring comments, backticks and markdown, so a literal `CHECK:` in an explanatory comment registers a real, failing directive that stops the intended assertion below it ([LLVM FileCheck parses a stray CHECK: token in prose as a live directive](../learnings/1784435207146-llvm-filecheck-parses-a-stray-check-token-inside-p.md)). It recurred with a custom prefix on `tests/cuda/texture1d-load.slang` (PR #13377): ``// The `PTX:` lines check ...`` registered a `PTX:` directive and failed with "expected string not found"; write "the PTX checks below" instead ([FileCheck parses `PREFIX:` inside ordinary test comments](../learnings/1790909785789-filecheck-parses-prefix-inside-ordinary-test-comme.md)).

The fix can be confirmed statically, without slangc or FileCheck (often the reviewer-container case). The prefix is whatever `filecheck=<PREFIX>` names, so `// CUDA: the payload survives…` becomes a required literal match. Enumerate every directive token per file with `re.compile(r'\b(HLSL|DXIL|SPIRV|GLSL|CUDA|CHECK)(-[A-Z]+(?:-\d+)?)?:')`; a hit is OK only if the stripped line starts with `// <PREFIX>...:`. Fetch PR-head files via `gh api repos/<o>/<r>/contents/<path>?ref=<sha> --jq .content | base64 -d`. Author dodges: hyphenate `SPIR-V` (≠ prefix `SPIRV`) and keep the colon off the prefix boundary (`GLSL compiles`, `CUDA behaves the same way:`). **Scope honesty:** this proves only that the parse collision is gone; whether each CHECK matches emitted output still needs slangc + FileCheck in CI ([verify a FileCheck directive-collision fix statically](../learnings/1790108085939-verify-a-filecheck-directive-collision-fix-statica.md)).

## Crafted minimal repros

Before concluding a sanitizer witness (ASan/LSan/UB) is un-addable, attempt a **crafted minimal reproducer** that forces the exact failing condition — don't stop at "the natural repro needs a GPU / an >8GB buffer"; on slang#12058 a maintainer landed the very test called impossible ([attempt a crafted minimal repro before concluding a witness is un-addable](../learnings/1783977754690-attempt-a-crafted-minimal-repro-before-concluding-.md)). For every new test, ask what would have to break for it to stay green; if the answer includes "the compile fails," it needs a status assertion (see [Output Assertions](slang-test-output-assertions-and-truncated-runs.md)).

## Runtime-testing a textual-emitter miscompile

For a bug in the GLSL/HLSL text emitters, `//TEST:COMPARE_COMPUTE(filecheck-buffer=CHECK):-vk -compute -shaderobj -output-using-type -emit-spirv-via-glsl` reproduces the miscompile at runtime on a GPU; plain `-vk` goes through direct SPIR-V and passes. Check `nvidia-smi -L` first: slang-fixer containers have an L40S with NVIDIA Vulkan, so this runs locally (it needed a CI GPU runner only during the 2026-09-28→10-16 host passthrough outage, [no GPU since ~09-28 (historical: 09-28→10-16 outage)](../learnings/1792089571497-agent-containers-have-no-gpu-since-2026-09-28-host.md)). The CPU and CUDA harness paths are not a substitute: on slang#13273 slang-test's `-cpu` and `-cuda` runs did not reproduce the `pop` shape even though `slangc -target cuda` text was wrong (they did reproduce `push`). The cause is unexplained (not `-O` or line-directive mode). `-g` was ruled out on the premise that render-test sets DebugInformation only when `generateSPIRVDirectly` (`tools/render-test/slang-support.cpp:273`), but that flag defaults to true, so every row carries debug info unless it passes `-g0` and `-g` is still a candidate ([debug info ON by default](../learnings/1792768846741-slang-test-compare-compute-rows-compile-with-debug.md)). Pair any runtime test with per-target `//TEST:SIMPLE(filecheck=...)` text checks, and order `CHECK-LABEL`s by EMISSION order, which follows the entry point's call order rather than source order [Runtime-testing textual-emitter miscompiles: use -vk -emit-spirv-via-glsl; CPU/CUDA harness may mask them](../learnings/1790504140710-runtime-testing-textual-emitter-miscompiles-use-vk.md).

## Contradictions / supersessions

- **"`slang-llvm` is absent locally, so `filecheck=` tests skip"** — **retracted** (2026-08-04): it came from listing only `build/Debug/bin/`, and it contradicted an already-correct 2026-07-02 learning (a contradiction is a signal to re-verify, not to overwrite). The load path survives.
- **"FileCheck is usually missing in-container"** — corrected. The *conditional* still holds (no library ⇒ `TestResult::Ignored`, vacuous green), but the default state is FileCheck **live**. Never infer which case you are in from `bin/`, `which FileCheck`, or a `passed` line — break an assertion and require RED.
- **"Whole-file negatives need a top anchor"** — superseded: a top-placed `-NOT` is still bounded by the next positive; use a lone-prefix negative.
