# Slang Test — FileCheck Authoring and Opt-Levels

How slang-test runs FileCheck, its region and vacuity traps, goldens, and harness defaults. Siblings: [Output Assertions and Truncated Runs](slang-test-output-assertions-and-truncated-runs.md), [directive authoring](slang-misc-test-harness.md), [False Greens](slang-test-false-greens-and-verification-traps.md), [#line and location checks](slang-test-line-directive-and-location-checks.md).

## TL;DR

- **`slang-test` loads FileCheck in-process from `build/Debug/lib/libslang-llvm.so`** (gated on `hasLlvm`), never from `PATH`; the standard build has it. Probe with `find build -iname '*slang-llvm*'`, never `ls bin/` or `which FileCheck`.
- **Only a failable control proves FileCheck ran:** inject a broken CHECK, require RED (parse `FAILED test:`; the exit code is 0), restore, `diff` that each edit landed.
- **Without the library, `SIMPLE(filecheck=)` is `Ignored` but `COMPARE_COMPUTE(filecheck-buffer=)` is `passed`.** Copy a prebuilt `libslang-llvm.so` into `build/Debug/lib/` (and any `LD_LIBRARY_PATH` swap dir), or ORDERED-match `<test>.slang.actual.txt`, never count. Emulators must be validated both ways; LLVM FileCheck in CI is authoritative.
- **A `CHECK-NOT` scans only between its adjacent positive matches, never between a `-DAG` group's matches.** The only whole-output negative is a lone `-NOT` under its own prefix, which also passes on a crash — bracket it `P-NOT` / `P: <surely-emitted line>` / `P-NOT`.
- **A scoped `-NOT` is still vacuous if DCE removed its subject**: grep for the instruction minus the decoration, fence every negative with a positive, flip it to a known-present pattern to confirm RED.
- **Place a negative by EMISSION order** (SPIR-V emits `NonReadable` before `Binding`).
- **Mutation-drill every `-NOT` guard on the base build**; back up fixture edits first (`git checkout -- <file>` restores pre-edit HEAD).
- **`-DAG` lines do not bind a value to its function, and a bare `1` matches `10` or `AAAAAA01`**: one prefix per helper with `-NEXT`, anchor `{{^}}1{{$}}`, mutant-drill new pins.
- **An order-only failure with equal counts means an emitter fold/inline change**; `CHECK-DAG` accepts both forms. Refresh a stale CHECK by pinning the claim (`if{{[(]+}}a_N > ...`).
- **`PREFIX:` anywhere in a line — prose, backticks — is a live directive**; verify a fix statically with a regex.
- **Diff emit/lowering changes against goldens unless you PROVED FileCheck ran.** Uniform failure across arches = regression; one platform = drift or flake.
- **slang-test front-inserts `-O0`** (fold CHECKs need `-O1`; suite-wide override via `context->options`). **`SLANG_RUN_SPIRV_VALIDATION=1` validates PRE-opt SPIR-V**; pin optimizer defects on `-target spirv-asm` with `{{$}}`.
- **render-test compiles COMPARE_COMPUTE rows with debug info ON unless `-g0`**, which blocks IR optimizations; reproduce with `slangc -g2`.
- **SPIR-V debug tests:** without `[shader("compute")]`/`-entry`/`-stage` there is NO entry point; match `OpSource {{Slang|Unknown}} 1`; at `-g2` source is an `OpString`, so anchor `{{^}}`; byte-offset fixtures need `text eol=lf`.
- **Try a crafted minimal reproducer before calling a sanitizer witness un-addable**; if a test would stay green when "the compile fails," add a status assertion.
- **Textual-emitter miscompiles show at runtime only with `-vk -emit-spirv-via-glsl`**; pair with per-target text FileChecks.

## Where FileCheck comes from, and proving it ran

`slang-test` never runs a `FileCheck` executable: `TestContext::locateLLVMFileCheck()` (`tools/slang-test/test-context.cpp:95-113`) loads the `slang-llvm` shared library and looks up `createLLVMFileCheck_V1`, called from `slang-test-main.cpp:5917` and gated at `:5915` on `if (hasLlvm)` (`checkPassThroughSupport(SLANG_PASS_THROUGH_LLVM)`). Nothing on `PATH` (`pip install filecheck`, an apt LLVM `FileCheck`) influences it ([library, not PATH](../learnings/1785824518254-slang-test-filecheck-tests-need-the-slang-llvm-lib.md)).

The standard container build has `build/Debug/lib/libslang-llvm.so` (152 MB, on `DefaultSharedLibraryLoader`'s path), so FileCheck runs locally; an empty `ls build/Debug/bin/ | grep slang-llvm` proves nothing. Skipped and passing look alike, so use a failable control: baseline `Supported backends: … llvm …` and `passed test:`; a broken CHECK gives `FAILED test:` and `0% of tests passed (0/1)`. The **exit code is 0 even on FAILED**: parse lines, never `$?`. A DXC-tree FileCheck (`build/_deps/dxc_source-src/utils/FileCheck`) proves nothing either way ([CORRECTION: FileCheck runs locally](../learnings/1785824734935-correction-slang-llvm-filecheck-my-library-absent-.md)). A false capability-negative is the worst claim to leave in shared prose: readers stop trying.

## When the library is genuinely missing

Causes: `-DSLANG_SLANG_LLVM_FLAVOR=DISABLE`, or a lib swap — under `LD_LIBRARY_PATH=/tmp/somelib ./build/Release/bin/slang-test ...` the compiler seeks `libslang-llvm.so` in its own directory (on the #14231 bisect the parent showed 26/26 until the commit-independent master lib was copied in, then 13/26). Check `slang-test <test> -v | grep -E 'Supported backends|FileCheck'` ([swapped lib](../learnings/1793683015448-slang-test-filecheck-tests-pass-vacuously-when-lib.md)). `_fileCheckTest` then logs `FileCheck is not available` (only with `-v`) and returns `TestResult::Ignored` (`slang-test-main.cpp:843-848`): `SIMPLE(filecheck=…)` reports ignored, but **`COMPARE_COMPUTE(filecheck-buffer=…)` reports passed**, because `TestReporter::combine(compileResult, bufferResult)` in `runComputeComparisonImpl` (`:4687`) keeps the larger value (`test-reporter.h:194`; `Ignored = 0 < Pass = 1`). A test passed with 16 wrong outputs, and an expected 3→99 still passed ([vacuous pass](../learnings/1790896856276-slang-test-filecheck-buffer-tests-pass-vacuously-w.md), [CHECKs unenforced](../learnings/1790913402068-slang-test-passes-filecheck-buffer-tests-without-e.md)). Input traps: `TEST_INPUT:ubuffer(data=[1 2 3])` stores int bits for float fields (write `1.0 2.0 3.0`), and the `-output-using-type` header lets `CHECK: 3` match `int32_t` (see [Slang test authoring: FileCheck efficacy](slang-tooling-f0909b0-test-authoring-filecheck.md)).

Fix: copy a prebuilt `libslang-llvm.so` from the shared base clone into the worktree's `build/Debug/lib/` (FileCheck V1 is target-independent, so drift is fine); remove it, or caveat `tests/llvm/*` failures, before quoting full-suite numbers. A Python simulator passed a #12170 test real FileCheck failed (backreference and scan semantics differ) ([real slang-test, never a simulator](../learnings/1784743223082-run-filecheck-slang-tests-through-real-slang-test-.md)). Otherwise match the chain against `<test>.slang.actual.txt` and tell reviewers CI is the first real run. A `pip install filecheck` emulator is only a local harness: validate it both ways (satisfiable input exits 0; the reintroduced defect exits 1, `{{$}}` anchors included), take options from each `//TEST:` line, and report "passes under a FileCheck-compatible emulator; **LLVM FileCheck in CI is authoritative**."

Hand-verify with an **ordered matcher** (each CHECK at or after the previous match's end, `{{...}}` as regex, literals `re.escape`d); counting cannot express ordered `CHECK` or windowed `CHECK-NOT`. It caught a test exercising every texture shape but asserting only on the 1D arm ([ordered match](../learnings/1784751927211-verify-filecheck-check-directives-by-ordered-match.md)).

## Harness defaults: `-O0`, debug info, pre-opt validation

slang-test **front-inserts `-O0`** (`kTestOptimizationOption` in `slang-test-optimization-options.h`) into any directive without an explicit `-OX`, so a fold-dependent CHECK needs `-O1` (manual `slangc` optimizes by default). `SLANG_RUN_SPIRV_VALIDATION=1` validates **pre-optimization** SPIR-V, so optimizer defects pass; assert on `-target spirv-asm` with a `{{$}}` anchor telling correct-3 from buggy-4 operands ([-O0; pre-opt validation](../learnings/1784762873836-slang-test-injects-o0-by-default-spirv-validation-.md)). A suite-wide override adds `defaultOptimizationLevel` to `Options`, threads it into `addDefaultSlangOptimization`/`addDefaultRenderTestSlangOptimization`, and passes `context->options.defaultOptimizationLevel` (`TestContext::options` is public); `-O0` is the sole spirv-opt early-out, so "max SpvOpt" means `-O3` ([override via context->options](../learnings/1784440518963-slang-test-suite-wide-opt-level-override-plumb-via.md)).

**render-test compiles with debug info ON**: unless a row passes `-g0`, every target gets `DebugInformation = STANDARD` (`tools/render-test/options.h:89` defaults `generateSPIRVDirectly=true`; `slang-support.cpp:273-282`; `options.cpp:293`). `DebugLine`/`DebugScope` block passes such as store-to-load forwarding (default case of `canInstHaveSideEffectAtAddress`), so a COMPARE_COMPUTE_EX row can fail where `slangc` without `-g` is correct: on PR #13883 the `-wgpu` row failed Tint uniformity on Windows CI only, since Linux reports wgpu rows `ignored` (`SLANG_EXCLUDE_DAWN=ON`; [false greens](slang-test-false-greens-and-verification-traps.md)). Reproduce with `slangc -g2`; fix the row with `-g0` (precedent: `tests/autodiff/reverse-checkpoint-4.slang`) ([debug info ON](../learnings/1792768846741-slang-test-compare-compute-rows-compile-with-debug.md)).

## SPIR-V debug-test authoring traps (PR #12202/#12204/#12206)

- **No entry point.** A `-target spirv` SIMPLE test with a bare `[numthreads(1,1,1)] void computeMain(...)` and no `[shader("compute")]`/`-entry`/`-stage` has NO entry point, so entry-point-keyed code (`m_defaultDebugSource`) runs only the module-scan fallback and a primary-path regression stays green. Add `[shader("compute")]` (template: `tests/spirv/debug-info-line-function.slang`) and a `#include` multi-source test for any "pick the main source" branch ([need an entry point](../learnings/1784822694362-slang-spir-v-debug-tests-need-shader-compute-entry.md)).
- **`OpSource` token.** aarch64 `test-slang` CI exports `SLANG_USE_SPV_SOURCE_LANGUAGE_UNKNOWN=1` (swiftshader workaround), so hardcoded `OpSource Slang 1` fails there; match `OpSource {{Slang|Unknown}} 1` and test with and without the var ([OpSource token](../learnings/1784830837048-spir-v-opsource-language-token-is-env-dependent-sl.md)).
- **`-g2` self-match.** At `-g2` the whole source, comments included, is an `OpString`, so a `-NOT` or mnemonic CHECK matches your own directive comments. Drop `-g2` if you don't need embedded source (`OpName` is emitted regardless), or anchor `{{^}}OpName %` ([-g2 embeds source](../learnings/1784838497425-slang-test-spirv-filecheck-g2-embeds-source-as-ops.md)).
- **CRLF byte shift.** A byte-offset fixture needs `text eol=lf` in `.gitattributes`, or Windows CRLF checkout shifts the offset (reproduce with `sed 's/$/\r/'`). Content-anchored and threshold tests are CRLF-safe ([`text eol=lf`](../learnings/1784845596400-byte-exact-slang-test-fixtures-need-text-eol-lf-in.md)).

## `CHECK-NOT` regions, `-DAG` blind spots, and vacuous negatives

**A `CHECK-NOT` (any `X-NOT`) scans only between its preceding and following positive matches**, so a forbidden token emitted earlier (a SPIR-V type decl before `OpEntryPoint`) is missed, and a negative at the top is bounded by the next positive. The only whole-output negative is a lone `-NOT` under its own `filecheck=` prefix (one extra `//TEST:` line, same entry point and flags). On `desc-heap-nonuniform-spirv.slang` a trailing `SPVNONCONST-NOT` was scanning 6 lines; the fix:

```
//TEST:SIMPLE(filecheck=SPVNONCONST):        -target spirv-asm -entry mainNonConstSibling
//TEST:SIMPLE(filecheck=SPVNONCONSTSIBLING): -target spirv-asm -entry mainNonConstSibling
// SPVNONCONST: %[[IDX:[0-9]+]] = OpCompositeExtract %uint %{{.*}} 0 {{.*}}; NonUniform
// SPVNONCONSTSIBLING-NOT: OpCompositeExtract %uint %{{.*}} 1 {{.*}}; NonUniform
```

Prove a negative live by flipping it to a known-present pattern (require RED) and `diff` that the control edit landed: two controls on this file were vacuous, and on #10918 a bounded `CHECK-NOT` flipped to `OpEntryPoint` still passed ([bounded by positives](../learnings/1785748572125-filecheck-check-not-is-bounded-by-surrounding-posi.md)).

**A `-DAG` group widens the blind spot**: `-NOT` lines around it check only before the group's earliest match and after its latest. On PR #13471 (`conflicting-export-13319.slang`) a duplicate `'Renderer : IRenderer'` warning between two DAG matches still passed 28/28. Use a separate `//TEST:SIMPLE_EX(filecheck=X-ONCE)` run whose only checks are `X-ONCE-NOT:` lines, and revert-drill any `-NOT` beside a `-DAG` group ([-NOT around -DAG](../learnings/1791336888864-filecheck-not-around-a-dag-group-does-not-guard-te.md)). A `-DAG` lane taking every branch catches combination bugs: on #14194 an `if`→`else if` mutation passed every single-type lane and failed only the all-three-types lane ([all-branches lane](../learnings/1793648853326-the-slang-coworkers-github-app-cannot-push-github-.md)).

**Place a negative by emission order, not source order.** Direct SPIR-V writes `OpDecorate %v NonReadable` before `OpDecorate %v Binding N` (`maybeEmitWriteOnlyImageDecoration` runs before `emitVarLayout`, #13896), so `RW-NOT: NonReadable` after `RW: OpDecorate %v Binding` never sees it (the test caught a stray decoration only via the disassembler's `; NonReadable, Binding 2, …` suffix on `OpVariable`). Use a `-NOT`-only prefix run, or `X-NOT: NonReadable` then `X: %v = OpVariable`, and mutation-drill it. Each `DescriptorHandle<T>` element type gets its own `__slang_resource_heap` `IRGlobalParam` (`lowerDynamicResourceHeap`), so a per-type decoration lands only on its `OpVariable` ([emission order](../learnings/1792783665896-spir-v-filecheck-a-not-check-after-a-binding-ancho.md)).

**A scoped negative is worthless if its subject is never emitted.** On #12116 a lone-prefix `-NOT: OpCompositeExtract %uint %{{.*}} 1 {{.*}}; NonUniform` targeted a `.y` lane DCE removed (`grep -cE 'OpCompositeExtract %uint %[0-9]+ 1'` → 0) and the test passed with the decoration logic inverted. Grep for the instruction minus the decoration (zero hits = vacuous), make the subject live (`uint2 raw = (uint2)th; … + float(raw.y);`), and fence every negative with a positive (idiom: `tests/spirv/nonuniform-constant-index-no-leak.slang`). A reviewer's "no build, cannot resolve" is exactly what a build resolves ([DCE removed the subject](../learnings/1785754047907-a-filecheck-check-not-can-be-vacuous-because-dce-r.md)).

**A `-NOT`-only prefix passes when the compile crashes**: on #12014 the ORDER prefix passed on master, which crashes on that file. Use BUMP — `P-NOT: x`, `P: <surely emitted line>`, `P-NOT: x` — and check every prefix has a positive before counting a revert drill as proof ([NOT-only prefixes](../learnings/1793280831784-filecheck-prefixes-with-only-not-lines-pass-when-t.md)). **A revert drill shows the test can fail; a mutation drill on base shows the guard cannot be bypassed.** When `-NOT`s rule out other sources of an effect (an `#extension` request), add a line triggering another source and run on base (~1 min): on #14085 `{{int64_t [_a-zA-Z]|64vec|[0-9]U?L[^a-zA-Z0-9_]}}` missed `uint64_t(inputBuffer[7]) >> 40` (base 8/8); adding `int64_t\([^d]` failed the GLSL rows on base ([mutation run on base](../learnings/1793332792382-prove-a-filecheck-not-guard-is-not-vacuous-with-a-.md)).

## Positive pins and refreshing stale CHECK lines

**`-DAG` pins prove each line exists, not which function it is in**: `WGSL-DAG:` lines `fn A`, `let bits = X`, `fn B`, `let bits = Y` pass with X and Y swapped; give each helper its own prefix (`HNAN: fn …` then `HNAN-NEXT:`). **Small integers match larger ones**: `1`, `2`, `3` pass on `10`, `12`, `13` (worst when 1..3 code NaN/Inf and 10+v finite values); write `// CHECK: {{^}}1{{$}}` or use non-overlapping codes (header variant on [Output Assertions](slang-test-output-assertions-and-truncated-runs.md)). A mutant drill caught both on #13669/#13680 ([small integers, -DAG pins](../learnings/1792149954051-filecheck-unanchored-small-integer-check-lines-mat.md)). In a `filecheck-buffer` dump `// CHECK: 1` matches inside `AAAAAA01`, so a 1-byte write into a `0xAAAAAAAA` word passes (#14283): anchor it, and for partial writes read the per-backend `tests/<t>.slang[.N].actual.txt`. Scratch probes need no shared-checkout edit (slang-test only wants `tests/` under the cwd): `mkdir -p /tmp/x/tests && cp t.slang /tmp/x/tests/ && cd /tmp/x && <checkout>/build/Release/bin/slang-test tests/t.slang` ([out-of-tree runs](../learnings/1793752818996-slang-test-runs-out-of-tree-tests-anchor-filecheck.md)).

**Refresh a stale CHECK by pinning the claim, not the token that broke it.** When WGSL began parenthesizing comparisons (#13569, `if(a > b)` → `if((a > b))`), refresh to `if{{[(]+}}a_N > ...` (`_meta/prompts/_common.md` rule 8: "Pin only what the claim depends on"). PR #13731 also found a `WGSL-NOT: break;` after `default :` that never covered case 0's tail. Prove a refreshed block non-vacuous with a scratch copy that violates the claim ([refreshing a stale line](../learnings/1792230758914-refreshing-a-stale-filecheck-line-don-t-re-pin-the.md)).

**An emitter fold or inline change reorders text without changing counts.** The nightly `agentic-tests` job runs `docs/generated/tests` fixtures PR CI skips ([CI flake signatures](ci-flake-known-signatures-and-classification.md)). #13764 made `kIROp_ByteAddressBufferLoad` side-effect-free in `IRInst::mightHaveSideEffects()`, so a single-use load is emitted inside its use (HLSL `Load<int>(..)` inside `.Store(`) and ordered `CHECK:` pairs fail with equal counts; #13911 mapped WGSL `WaveGetNumWaves` to `@builtin(num_subgroups)`, breaking a `WGSL-DAG: @builtin(subgroup_size)` fixture. Triage: diff `FAILED test:` names against the prior nightly, read "possible intended match here" notes, then `compare/<green>...<red>` ([nightly reorder](../learnings/1793260989645-nightly-agentic-tests-ir-side-effect-free-changes-.md)). `CHECK-DAG` keeps both patterns required and accepts inlined and temporary forms (prove it with a throwaway two-use fixture). Back up a fixture edit before mutation drills, because `git checkout -- <file>` restores the pre-edit HEAD (on #13887, 3 of 6 drills ran on the old fixture) ([git checkout reverts the edit](../learnings/1793264358969-undoing-a-mutation-with-git-checkout-file-also-rev.md)).

## Goldens and directive collisions

**Diff emit/lowering changes against FileCheck goldens whenever you have not proved FileCheck ran**; with the library missing, "no compile error" is not a pass. Compare slangc output to the ordered `//CHECK:` lines of every golden touching the changed modifier/inst; uniform failure across arches is a deterministic regression, one platform only is drift or flake. A decoration arm shared by several decl kinds (func/struct/field) is the classic over-broad trap: it cost an approved PR a 7-platform RED on a `.cuh` golden ([diff against goldens](../learnings/1784421575539-emit-header-changes-diff-against-filecheck-goldens.md)).

**`PREFIX:` anywhere in a line is a live directive.** FileCheck scans every line for the active prefix (optionally `-SUFFIX`) then `:`, ignoring comments, backticks and markdown. A `CHECK:` in prose expects English, fails and stops, so the assertion below (a `CHECK-COUNT-2` on slang#11803) never runs; the tell is a CI error at a comment line ([stray CHECK:](../learnings/1784435207146-llvm-filecheck-parses-a-stray-check-token-inside-p.md)). Custom prefixes too: ``// The `PTX:` lines check ...`` in `tests/cuda/texture1d-load.slang` (PR #13377) failed with "expected string not found"; write "the PTX checks below" ([`PREFIX:` in comments](../learnings/1790909785789-filecheck-parses-prefix-inside-ordinary-test-comme.md)).

Confirm a collision fix statically: enumerate tokens per file with `re.compile(r'\b(HLSL|DXIL|SPIRV|GLSL|CUDA|CHECK)(-[A-Z]+(?:-\d+)?)?:')`; a hit is OK only if the stripped line starts with `// <PREFIX>...:`. Fetch PR-head files with `gh api repos/<o>/<r>/contents/<path>?ref=<sha> --jq .content | base64 -d`. Authors dodge by hyphenating `SPIR-V` or moving the colon (`CUDA behaves the same way:`). This proves only the parse collision is gone; matching needs CI ([static verification](../learnings/1790108085939-verify-a-filecheck-directive-collision-fix-statica.md)).

## Crafted repros and runtime-testing textual emitters

Before calling a sanitizer witness (ASan/LSan/UB) un-addable, attempt a **crafted minimal reproducer** forcing the exact failing condition (not "needs a GPU / >8GB buffer"); on slang#12058 a maintainer landed the test called impossible ([crafted repro first](../learnings/1783977754690-attempt-a-crafted-minimal-repro-before-concluding-.md)). For each new test, ask what would have to break for it to stay green; if "the compile fails," add a status assertion (see [Output Assertions](slang-test-output-assertions-and-truncated-runs.md)).

For a GLSL/HLSL text-emitter bug, `//TEST:COMPARE_COMPUTE(filecheck-buffer=CHECK):-vk -compute -shaderobj -output-using-type -emit-spirv-via-glsl` reproduces the miscompile at runtime; plain `-vk` goes through direct SPIR-V and passes. Coworker containers have an L40S with NVIDIA Vulkan (`nvidia-smi -L`; the 2026-09-28→10-16 outage is [historical](../learnings/1792089571497-agent-containers-have-no-gpu-since-2026-09-28-host.md)). `-cpu`/`-cuda` are no substitute: on slang#13273 they missed the `pop` shape though `slangc -target cuda` text was wrong (they caught `push`), cause unexplained (render-test's default debug info is a candidate) ([debug info ON](../learnings/1792768846741-slang-test-compare-compute-rows-compile-with-debug.md)). Pair a runtime test with per-target `//TEST:SIMPLE(filecheck=...)` text checks, `CHECK-LABEL`s in emission (call) order ([-vk -emit-spirv-via-glsl](../learnings/1790504140710-runtime-testing-textual-emitter-miscompiles-use-vk.md)).

## Superseded claims

- **"`slang-llvm` is absent locally, so `filecheck=` tests skip"** — retracted (it came from listing only `bin/`); FileCheck is live by default, and the no-library ⇒ `Ignored` conditional still holds.
- **"Whole-file negatives need a top anchor"** — superseded by the lone-prefix negative.
- **"Agent containers have no GPU"** (2026-09-28 passthrough outage) — historical; containers have an L40S again.
