# Slang Test — FileCheck Authoring and Opt-Levels

FileCheck as slang-test runs it: where the checker comes from and how to prove it ran, fallbacks when it is absent, `CHECK-NOT`/`-DAG` region and vacuity traps, goldens, and the `-O0` / debug-info / pre-opt-validation harness defaults. Siblings: [Output Assertions and Truncated Runs](slang-test-output-assertions-and-truncated-runs.md), [directive authoring](slang-misc-test-harness.md), [False Greens](slang-test-false-greens-and-verification-traps.md), [#line and location checks](slang-test-line-directive-and-location-checks.md).

## TL;DR

- **`slang-test` loads FileCheck in-process from `build/Debug/lib/libslang-llvm.so`** (`test-context.cpp:95-113`, gated on `hasLlvm`), never from `PATH`. The standard build has it; probe with `find build -iname '*slang-llvm*'`, never `ls bin/` or `which FileCheck`.
- **Only a failable control proves FileCheck ran:** inject a broken CHECK, require RED (parse `FAILED test:`; the exit code is 0), restore, and `diff` that each edit landed.
- **With the library missing, `SIMPLE(filecheck=)` reports `Ignored` but `COMPARE_COMPUTE(filecheck-buffer=)` reports `passed`.** Copy a prebuilt `libslang-llvm.so` into `build/Debug/lib/` (and any `LD_LIBRARY_PATH` lib-swap dir), or check `<test>.slang.actual.txt` with an ORDERED matcher, never by counting. A Python emulator is a different implementation: validate it both ways; LLVM FileCheck in CI is authoritative.
- **A `CHECK-NOT` scans only between its adjacent positive matches, and never between the matches of a `-DAG` group.** The only whole-output negative is a lone `-NOT` under its own `filecheck=` prefix, and even that passes when the compile crashes, so bracket it as `P-NOT` / `P: <surely-emitted line>` / `P-NOT`.
- **A correctly-scoped `-NOT` is still vacuous if DCE removed its subject** — grep for the instruction with the decoration stripped, fence every negative with a positive, and flip it to a known-present pattern to confirm RED.
- **Place a negative by EMISSION order:** direct SPIR-V emits `OpDecorate %v NonReadable` before `OpDecorate %v Binding`, so a `-NOT` after a Binding anchor never sees it.
- **Mutation-drill every `-NOT` guard on the base build** (inject another source of the forbidden effect; green there = a hole). Back up a fixture edit first: `git checkout -- <file>` restores the pre-edit HEAD.
- **`-DAG` lines do not bind a value to its function, and a bare `1` matches `10`.** One prefix per helper with `-NEXT`, anchor `{{^}}1{{$}}`, mutant-drill every new pin test.
- **An order-only CHECK failure with equal counts points at an emitter fold/inline change**; `CHECK-DAG` accepts both forms. Refresh a CHECK broken by an incidental token by pinning the claim (`if{{[(]+}}a_N > ...`).
- **`PREFIX:` anywhere in a line — prose, backticks — is a live directive**; a fix can be verified statically with a regex.
- **Diff emit/lowering changes against goldens whenever you have not PROVED FileCheck ran.** Uniform failure across arches = real regression; one platform only = drift or flake.
- **slang-test front-inserts `-O0`**, so a fold-dependent CHECK needs `-O1`; a suite-wide override plumbs through `context->options`. **`SLANG_RUN_SPIRV_VALIDATION=1` validates PRE-optimization SPIR-V**; pin optimizer defects with a `-target spirv-asm` check anchored by `{{$}}`.
- **render-test compiles every COMPARE_COMPUTE row with debug info ON unless it passes `-g0`**; debug insts block IR optimizations, so reproduce with `slangc -g2`.
- **SPIR-V debug tests:** no `[shader("compute")]`/`-entry`/`-stage` means NO entry point (fallback path only); match `OpSource {{Slang|Unknown}} 1` (aarch64 CI); at `-g2` the source is an `OpString`, so anchor `{{^}}` or FileCheck matches your own comments. A byte-offset fixture needs `text eol=lf` in `.gitattributes`.
- **Attempt a crafted minimal reproducer before calling a sanitizer witness un-addable**; if a new test stays green when "the compile fails," add a status assertion.
- **A textual-emitter miscompile needs `-vk -emit-spirv-via-glsl` to show at runtime**; `-cpu`/`-cuda` can mask it, so pair runtime tests with per-target text FileChecks.

## Where FileCheck comes from, and proving it ran

`slang-test` never invokes a `FileCheck` executable. `TestContext::locateLLVMFileCheck()` (`tools/slang-test/test-context.cpp:95-113`) loads the `slang-llvm` shared library and looks up `createLLVMFileCheck_V1`; it is called from `slang-test-main.cpp:5917`, gated at `:5915` on `if (hasLlvm)` (`checkPassThroughSupport(SLANG_PASS_THROUGH_LLVM)`). A `pip install filecheck`, an `apt` LLVM `FileCheck`, or anything on `PATH` cannot influence it ([filecheck= tests need the slang-llvm library, not a binary on PATH](../learnings/1785824518254-slang-test-filecheck-tests-need-the-slang-llvm-lib.md)).

The standard container build has `build/Debug/lib/libslang-llvm.so` (152 MB, found via `DefaultSharedLibraryLoader`'s search path), so LLVM FileCheck runs locally. An empty `ls build/Debug/bin/ | grep slang-llvm` establishes nothing; `find build -iname '*slang-llvm*'` does. Skipped and passing tests look alike, so use a failable control: the baseline lists `Supported backends: … llvm …` and `passed test:`; a broken CHECK gives `FAILED test:` and `0% of tests passed (0/1)`; restoring passes again. The **exit code is 0 even on FAILED**, so parse those lines, never `$?`. A DXC-tree FileCheck (`build/_deps/dxc_source-src/utils/FileCheck`) may exist; infer availability from neither path ([CORRECTION — LLVM FileCheck runs locally, proved with a failable control](../learnings/1785824734935-correction-slang-llvm-filecheck-my-library-absent-.md)). A false capability-negative is the worst claim to leave in shared prose: readers stop trying.

## When the library is genuinely missing

Causes: a worktree configured `-DSLANG_SLANG_LLVM_FLAVOR=DISABLE` for a fast build, or a compiler-lib swap: under `LD_LIBRARY_PATH=/tmp/somelib ./build/Release/bin/slang-test ...` the compiler looks for `libslang-llvm.so` in its own directory, so a swapped-in dir without it hides the `llvm` backend and every `filecheck-buffer=` test passes; on the #14231 bisect the parent commit showed 26/26 until the master build's (commit-independent) `libslang-llvm.so` was copied in, then the true 13/26. Check `slang-test <test> -v | grep -E 'Supported backends|FileCheck'`: `llvm` listed, no "not available" line ([vacuous pass when libslang-llvm is missing beside a swapped lib](../learnings/1793683015448-slang-test-filecheck-tests-pass-vacuously-when-lib.md)). `_fileCheckTest` then logs `FileCheck is not available` (only with `-v`) and returns `TestResult::Ignored` (`slang-test-main.cpp:843-848`). `SIMPLE(filecheck=…)` reports ignored (0/0), but **`COMPARE_COMPUTE(filecheck-buffer=…)` reports passed with no CHECK evaluated**: `runComputeComparisonImpl` returns `TestReporter::combine(compileResult, bufferResult)` (`:4687`), which keeps the larger value (`test-reporter.h:194`; `Ignored = 0 < Pass = 1`). A value test passed with 16 wrong outputs, and an expected value changed from 3 to 99 still passed ([filecheck-buffer passes vacuously with slang-llvm disabled](../learnings/1790896856276-slang-test-filecheck-buffer-tests-pass-vacuously-w.md), [CHECKs unenforced when FileCheck is absent](../learnings/1790913402068-slang-test-passes-filecheck-buffer-tests-without-e.md)). Input traps: `TEST_INPUT:ubuffer(data=[1 2 3])` stores int bits for float fields (write `1.0 2.0 3.0`), and the `-output-using-type` header lets `CHECK: 3` match `int32_t` (see [Slang test authoring: FileCheck efficacy](slang-tooling-f0909b0-test-authoring-filecheck.md)).

The fix is to copy a prebuilt `libslang-llvm.so` from the shared base clone into the worktree's `build/Debug/lib/`. FileCheck V1 is target-independent, so version drift is fine; remove the copy (or caveat `tests/llvm/*` failures) before quoting full-suite numbers. A simulator is no substitute: a Python one passed a #12170 test that real FileCheck failed, because backreference and scan semantics differ ([run through real slang-test, never a simulator](../learnings/1784743223082-run-filecheck-slang-tests-through-real-slang-test-.md)). If copying is impossible, match the CHECK/CHECK-NEXT chain against the `<test>.slang.actual.txt` beside the test, and tell reviewers CI is the first real FileCheck run.

A `pip install filecheck` emulator is only a parallel harness for local iteration: validate it both ways (satisfiable input exits 0; the reintroduced defect exits 1, including anchors such as `{{$}}` rejecting an extra operand), take compile options from each file's `//TEST:` directive, and report "passes under a FileCheck-compatible emulator; **LLVM FileCheck in CI is authoritative**."

To hand-verify, use an **ordered matcher**: each CHECK matches at or after the previous match's end, `{{...}}` becomes regex, literal spans are `re.escape`d. Counting matches cannot express ordered `CHECK` or windowed `CHECK-NOT`. The ordered matcher caught a test exercising every texture shape but asserting only on the 1D arm ([ordered-match CHECK lines when FileCheck is absent](../learnings/1784751927211-verify-filecheck-check-directives-by-ordered-match.md)).

## Harness defaults: `-O0`, debug info, pre-opt validation

slang-test **prepends `-O0`** to any directive without an explicit `-OX`, so a fold-dependent CHECK needs `-O1`; a manual `slangc` optimizes by default and misleads. `SLANG_RUN_SPIRV_VALIDATION=1` validates **pre-optimization** SPIR-V, so an optimizer-introduced defect passes; the real signal is a `-target spirv-asm` (post-opt) operand-count assertion with a `{{$}}` anchor that tells correct-3 from buggy-4 ([-O0 by default; SPIRV validation runs pre-opt](../learnings/1784762873836-slang-test-injects-o0-by-default-spirv-validation-.md)).

The `-O0` default is `kTestOptimizationOption` in `slang-test-optimization-options.h`, front-inserted deliberately. A suite-wide override adds `defaultOptimizationLevel` to `Options`, threads an override parameter into `addDefaultSlangOptimization` and `addDefaultRenderTestSlangOptimization`, and passes `context->options.defaultOptimizationLevel` at the call sites (`TestContext::options` is public). `-O0` is the sole spirv-opt early-out, so "force max SpvOpt suite-wide" means `-O3` ([suite-wide opt-level override via context->options](../learnings/1784440518963-slang-test-suite-wide-opt-level-override-plumb-via.md)).

**render-test compiles with debug info ON by default.** Unless a row passes `-g0`, it sets `DebugInformation = STANDARD` for every target, `-wgpu` included (`tools/render-test/options.h:89` defaults `generateSPIRVDirectly=true`; `slang-support.cpp:273-282`; `options.cpp:293`). `DebugLine`/`DebugScope` sit between instructions and block passes such as store-to-load forwarding (they fall to the default case of `canInstHaveSideEffectAtAddress`), so a COMPARE_COMPUTE_EX row can fail where `slangc` without `-g` is correct (PR #13883: the `-wgpu` row failed Tint uniformity on Windows CI; `slangc -target wgsl` passed). Reproduce with `slangc -g2`; fix the row with `-g0` (precedent: `tests/autodiff/reverse-checkpoint-4.slang`). It showed only on Windows GPU CI because a default Linux build reports wgpu rows `ignored` (`SLANG_EXCLUDE_DAWN=ON`) ([false greens](slang-test-false-greens-and-verification-traps.md)) ([COMPARE_COMPUTE rows compile with debug info ON](../learnings/1792768846741-slang-test-compare-compute-rows-compile-with-debug.md)).

## SPIR-V debug-test authoring traps (PR #12202/#12204/#12206)

- **No entry point.** A `-target spirv` SIMPLE test with a bare `[numthreads(1,1,1)] void computeMain(...)` and no `[shader("compute")]`/`-entry`/`-stage` has NO entry point (auto-deduction keys on `[shader(...)]`), so entry-point-keyed code (the emitter's `m_defaultDebugSource` path) runs only the module-scan fallback and a primary-path regression stays green. Add `[shader("compute")]` (template: `tests/spirv/debug-info-line-function.slang`) and a `#include` multi-source test for any "pick the main source" branch ([SPIR-V debug tests need [shader("compute")]/-entry](../learnings/1784822694362-slang-spir-v-debug-tests-need-shader-compute-entry.md)).
- **`OpSource` token.** Default `Slang`, but the aarch64 `test-slang` CI jobs export `SLANG_USE_SPV_SOURCE_LANGUAGE_UNKNOWN=1` (a swiftshader workaround), so a hardcoded `OpSource Slang 1` fails aarch64-only; match `OpSource {{Slang|Unknown}} 1` and test with and without the var ([OpSource token is env-dependent](../learnings/1784830837048-spir-v-opsource-language-token-is-env-dependent-sl.md)).
- **`-g2` self-match.** At `-g2` the whole `.slang` source, comments included, is an `OpString`, so a `-NOT` or mnemonic CHECK matches your own directive comments. Drop `-g2` if you don't need embedded source (`OpName` is emitted regardless), or anchor `{{^}}OpName %` ([-g2 embeds source-as-OpString](../learnings/1784838497425-slang-test-spirv-filecheck-g2-embeds-source-as-ops.md)).
- **CRLF byte shift.** A fixture depending on an exact byte offset needs `text eol=lf` in `.gitattributes`; otherwise Windows CI checks it out as CRLF, each `\n`→`\r\n` above the marker shifts the byte, and it fails Windows-only (reproduce with `sed 's/$/\r/'`). Content-anchored and threshold tests are CRLF-safe ([byte-exact fixtures need `text eol=lf`](../learnings/1784845596400-byte-exact-slang-test-fixtures-need-text-eol-lf-in.md)).

## `CHECK-NOT` regions, `-DAG` blind spots, and vacuous negatives

**A `CHECK-NOT` (likewise `SPV-NOT`, `GLSL-NOT`) scans only between its preceding and following positive matches**, so a forbidden token emitted earlier — a GLSL buffer block, a SPIR-V type decl before `OpEntryPoint` — is missed, and moving the negative to the top only bounds it by the next positive. The only whole-output negative is a lone `-NOT` under its own `filecheck=` prefix (one extra `//TEST:` line, same entry point and flags). On `desc-heap-nonuniform-spirv.slang` a trailing `SPVNONCONST-NOT` was scanning 6 lines; the fix:

```
//TEST:SIMPLE(filecheck=SPVNONCONST):        -target spirv-asm -entry mainNonConstSibling
//TEST:SIMPLE(filecheck=SPVNONCONSTSIBLING): -target spirv-asm -entry mainNonConstSibling
// SPVNONCONST: %[[IDX:[0-9]+]] = OpCompositeExtract %uint %{{.*}} 0 {{.*}}; NonUniform
// SPVNONCONSTSIBLING-NOT: OpCompositeExtract %uint %{{.*}} 1 {{.*}}; NonUniform
```

Prove a negative live by flipping it to a known-present pattern and requiring RED, and verify the control itself (`diff` that the edit landed): two controls on this file were vacuous, and on #10918 a bounded `CHECK-NOT` flipped to `OpEntryPoint` still passed ([CHECK-NOT is bounded by surrounding positives](../learnings/1785748572125-filecheck-check-not-is-bounded-by-surrounding-posi.md)).

**A `-DAG` group widens the blind spot**: `-NOT` lines around it check only before the group's earliest match and after its latest. On PR #13471 (`conflicting-export-13319.slang`), disabling witness dedup put a duplicate `'Renderer : IRenderer'` warning between two DAG matches and the test still passed 28/28. Use a separate `//TEST:SIMPLE_EX(filecheck=X-ONCE)` run whose only checks are `X-ONCE-NOT:` lines, and revert-drill any `-NOT` beside a `-DAG` group in review ([-NOT around a -DAG group](../learnings/1791336888864-filecheck-not-around-a-dag-group-does-not-guard-te.md)). A `-DAG` lane also catches combination bugs: on #14194 emitter logic under independent `if`s passed every single-type lane under an `if`→`else if` mutation, and only a `-DAG` lane using all three types failed, so mutation-drill independent-branch logic with one lane taking every branch ([`if`→`else if` mutation drill](../learnings/1793648853326-the-slang-coworkers-github-app-cannot-push-github-.md)).

**Place a negative by emission order, not source order.** Direct SPIR-V writes `OpDecorate %v NonReadable` before `OpDecorate %v Binding N` (`maybeEmitWriteOnlyImageDecoration` runs before `emitVarLayout`, #13896), so `RW: OpDecorate %v Binding` then `RW-NOT: NonReadable` never sees it; that test caught a stray decoration only because the disassembler appends `; NonReadable, Binding 2, …` to the later `OpVariable` line. Use a `-NOT`-only prefix run, or `X-NOT: NonReadable` then `X: %v = OpVariable`, and mutation-drill it. (`lowerDynamicResourceHeap` gives each `DescriptorHandle<T>` element type its own `__slang_resource_heap` `IRGlobalParam`, so a per-type decoration lands only on that type's `OpVariable`.) ([NOT after a Binding anchor misses NonReadable](../learnings/1792783665896-spir-v-filecheck-a-not-check-after-a-binding-ancho.md))

**A correctly-scoped negative is worthless if its subject is never emitted.** On #12116 a lone-prefix `-NOT: OpCompositeExtract %uint %{{.*}} 1 {{.*}}; NonUniform` targeted a `.y` lane feeding only a `makeVector` folded away upstream, so DCE removed the extract (`grep -cE 'OpCompositeExtract %uint %[0-9]+ 1'` → 0) and the test passed with the decoration logic inverted. Vacuity test: grep for the forbidden instruction with the decoration stripped; zero hits means vacuous. Make the subject live (`uint2 raw = (uint2)th; … + float(raw.y);`) and fence every negative with a positive (idiom: `tests/spirv/nonuniform-constant-index-no-leak.slang`). A reviewer's "no build, cannot resolve" is exactly what a build resolves ([CHECK-NOT vacuous because DCE removed its subject](../learnings/1785754047907-a-filecheck-check-not-can-be-vacuous-because-dce-r.md)).

**A prefix of only `-NOT` lines also passes when the compile crashes** (the abort text contains no forbidden pattern): on #12014 the ORDER prefix passed on master, which crashes on that file. Use the BUMP pattern — `P-NOT: x`, `P: <a line that is surely emitted>`, `P-NOT: x` — and check every prefix has a positive before counting a revert drill or master comparison as proof ([NOT-only prefixes pass on a crash](../learnings/1793280831784-filecheck-prefixes-with-only-not-lines-pass-when-t.md)). **A revert drill shows the test can fail; a mutation drill on base shows the guard cannot be bypassed.** When `-NOT` lines rule out other sources of a side effect (an `#extension` request), add one line triggering another source and run on base. On #14085 the guard `{{int64_t [_a-zA-Z]|64vec|[0-9]U?L[^a-zA-Z0-9_]}}` required a space after the type and missed `uint64_t(inputBuffer[7]) >> 40` (base passed 8/8); adding `int64_t\([^d]` made the GLSL rows fail on base while head passed. Each drill takes ~1 min ([mutation-drill a -NOT guard on base](../learnings/1793332792382-prove-a-filecheck-not-guard-is-not-vacuous-with-a-.md)).

## Positive pins and refreshing stale CHECK lines

**`-DAG` pins prove each line exists, not which function it is in**: `WGSL-DAG: fn A`, `WGSL-DAG: let bits = X`, `WGSL-DAG: fn B`, `WGSL-DAG: let bits = Y` passes with X and Y swapped. Give each helper its own prefix (`HNAN: fn …` then `HNAN-NEXT:` lines) to bind bodies without locking emission order. **Small integers match larger ones**: expecting `1`, `2`, `3` passes on `10`, `12`, `13`, worst when an encoding uses 1..3 for NaN/Inf and 10+v for finite values; write `// CHECK: {{^}}1{{$}}` or use non-overlapping codes (header variant on [Output Assertions](slang-test-output-assertions-and-truncated-runs.md)). A mutant drill (change the expected value at the source, confirm FAIL) caught both on #13669/#13680 ([unanchored small integers and -DAG pins](../learnings/1792149954051-filecheck-unanchored-small-integer-check-lines-mat.md)).

**Refresh a stale CHECK by pinning the claim, not the token that broke it.** When WGSL began wrapping comparisons in parentheses (#13569, `if(a > b)` → `if((a > b))`), the robust refresh is `if{{[(]+}}a_N > ...` (docs/generated `_meta/prompts/_common.md` rule 8: "Pin only what the claim depends on"). The same review (PR #13731) found a `WGSL-NOT: break;` after `default :` that never covered case 0's tail, per the region rule. Prove a refreshed block non-vacuous with a scratch copy that violates the claim ([refreshing a stale FileCheck line](../learnings/1792230758914-refreshing-a-stale-filecheck-line-don-t-re-pin-the.md)).

**An emitter fold or inline change reorders text without changing counts.** The nightly `agentic-tests` job runs `docs/generated/tests` fixtures PR CI never runs ([CI flake signatures](ci-flake-known-signatures-and-classification.md)). #13764 added `kIROp_ByteAddressBufferLoad` to the side-effect-free list in `IRInst::mightHaveSideEffects()`, so a single-use load is emitted inside its use (HLSL `Load<int>(..)` inside `.Store(`; Metal `as_type<uint>` nested in `as_type<uint32_t>`) and ordered `CHECK:` pairs fail with equal load/store counts; #13911 mapped WGSL `WaveGetNumWaves` to `@builtin(num_subgroups)`, breaking a `WGSL-DAG: @builtin(subgroup_size)` fixture. Triage: diff `FAILED test:` names against the previous nightly, read the "possible intended match here" notes, then `compare/<green>...<red>` ([side-effect-free loads reorder emitted text](../learnings/1793260989645-nightly-agentic-tests-ir-side-effect-free-changes-.md)). `CHECK-DAG` keeps both patterns required and accepts inlined and temporary forms; prove the second with a throwaway two-use fixture. Commit or `cp` a backup of a fixture edit before mutation drills, because `git checkout -- <file>` restores the pre-edit HEAD (on #13887, 3 of 6 drills ran on the old fixture) ([git checkout -- reverts an uncommitted fixture edit](../learnings/1793264358969-undoing-a-mutation-with-git-checkout-file-also-rev.md)).

## Goldens and directive collisions

**Diff emit/lowering changes against FileCheck goldens whenever you have not proved FileCheck ran**; with the library missing, "no compile error" is not a pass. Grep every golden touching the changed modifier/inst and compare slangc output to its ordered `//CHECK:` lines. Uniform failure across arches is a deterministic regression; one platform only is drift or flake. A decoration arm shared by several decl kinds (func/struct/field) is the classic over-broad trap: it cost an approved PR a 7-platform RED on a `.cuh` golden ([diff emit changes against goldens](../learnings/1784421575539-emit-header-changes-diff-against-filecheck-goldens.md)).

**`PREFIX:` anywhere in a line is a live directive.** FileCheck scans every line for the active prefix (optionally `-SUFFIX`) then `:`, ignoring comments, backticks and markdown. A literal `CHECK:` in prose becomes a directive expecting English; it fails and stops, so the assertion below (a `CHECK-COUNT-2` on slang#11803) never runs. The tell is a CI error at a comment line ([stray CHECK: token in prose is live](../learnings/1784435207146-llvm-filecheck-parses-a-stray-check-token-inside-p.md)). Likewise for a custom prefix: ``// The `PTX:` lines check ...`` in `tests/cuda/texture1d-load.slang` (PR #13377) failed with "expected string not found"; write "the PTX checks below" ([`PREFIX:` inside test comments](../learnings/1790909785789-filecheck-parses-prefix-inside-ordinary-test-comme.md)).

A collision fix can be confirmed statically. Enumerate directive tokens per file with `re.compile(r'\b(HLSL|DXIL|SPIRV|GLSL|CUDA|CHECK)(-[A-Z]+(?:-\d+)?)?:')`; a hit is OK only if the stripped line starts with `// <PREFIX>...:`. Fetch PR-head files with `gh api repos/<o>/<r>/contents/<path>?ref=<sha> --jq .content | base64 -d`. Authors dodge by hyphenating `SPIR-V` and keeping the colon off the prefix (`CUDA behaves the same way:`). This proves only the parse collision is gone; matching still needs CI ([verify a collision fix statically](../learnings/1790108085939-verify-a-filecheck-directive-collision-fix-statica.md)).

## Crafted repros and runtime-testing textual emitters

Before concluding a sanitizer witness (ASan/LSan/UB) is un-addable, attempt a **crafted minimal reproducer** forcing the exact failing condition (not "the natural repro needs a GPU / >8GB buffer"); on slang#12058 a maintainer landed the test called impossible ([crafted minimal repro first](../learnings/1783977754690-attempt-a-crafted-minimal-repro-before-concluding-.md)). For every new test, ask what would have to break for it to stay green; if the answer includes "the compile fails," add a status assertion (see [Output Assertions](slang-test-output-assertions-and-truncated-runs.md)).

For a bug in the GLSL/HLSL text emitters, `//TEST:COMPARE_COMPUTE(filecheck-buffer=CHECK):-vk -compute -shaderobj -output-using-type -emit-spirv-via-glsl` reproduces the miscompile at runtime; plain `-vk` goes through direct SPIR-V and passes. Coworker containers have an L40S with NVIDIA Vulkan (`nvidia-smi -L`; CI was needed only in the 2026-09-28→10-16 outage, [historical outage](../learnings/1792089571497-agent-containers-have-no-gpu-since-2026-09-28-host.md)). `-cpu` and `-cuda` are no substitute: on slang#13273 they did not reproduce the `pop` shape although `slangc -target cuda` text was wrong (they did reproduce `push`), cause unexplained; render-test's default debug info is a candidate ([debug info ON by default](../learnings/1792768846741-slang-test-compare-compute-rows-compile-with-debug.md)). Pair a runtime test with per-target `//TEST:SIMPLE(filecheck=...)` text checks, `CHECK-LABEL`s in emission (call) order ([-vk -emit-spirv-via-glsl for textual-emitter miscompiles](../learnings/1790504140710-runtime-testing-textual-emitter-miscompiles-use-vk.md)).

- **"`slang-llvm` is absent locally, so `filecheck=` tests skip"** — retracted (it came from listing only `bin/`); FileCheck is live by default, and the no-library ⇒ `Ignored` conditional still holds.
- **"Whole-file negatives need a top anchor"** — superseded by the lone-prefix negative.
- **"Agent containers have no GPU"** (2026-09-28 passthrough outage) — historical; containers have an L40S again.
