# slang-test Harness Internals and In-Process Unit Tests

slang-test reporter and discovery-output configuration (CI parses it), a replay-folder race between parallel test servers, COMPARE_COMPUTE lane synthesis and render-test input binding/layout, and putting harness or compiler internals under in-process `slang-unit-test` (unexported symbols, Windows per-DLL CRT environments). Whether a green run can be trusted is on [slang-test False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md).

## TL;DR

- **Main and per-worker `TestReporter`s configure through ONE path, `TestReporter::init(const Options&)`.** Before PR #12180 parallel workers kept ctor-default `Info` verbosity under `-v failure`. New reporter settings go inside `init`, or the worker/main drift (#11911, #12177) returns.
- **Check that a print runs AFTER the option it is gated on is parsed.** `Supported backends:` prints ~70 lines before `Options::parse`, so an in-place gate is a no-op; accumulate pre-parse, print gated after parse.
- **CI parses discovery output.** `common-test-setup/action.yml` greps `Supported backends: ` at default verbosity, so discovery is gated on `verbosity >= Info`, never suppressed unconditionally. `Check <api>: Not Supported` lines stay ungated.
- **Replay recording folders are not process-unique** (ms timestamp, no PID; `findLatestReplayFolder` has no ownership filter), so parallel test servers read each other's recordings (#12214). Fix both: a per-process test base dir (the flake) and PID-suffixed names with an atomic leaf create (the latent production collision).
- **On a GPU host every `-cpu` COMPARE_COMPUTE line also runs a synthesized `syn (cuda)` runtime lane.** Verify `-cpu` tests on a CUDA host. Only opt-in `-synthesize-compile-targets` rows are compile-only.
- **`TEST_INPUT` `data=[...]` counts 32-bit words, even with `stride=8`.** 64-bit values need 2 words and bit patterns or `l` literals; a short buffer corrupts the CPU heap (glibc abort) and silently drops GPU writes.
- **An unbound parameter (indented, missing or `#include`d `//TEST_INPUT:`) crashes slang-test itself on `-cpu` (139) and `-cuda` (134)** because render-test runs in-process (`UseSharedLibrary`); vk reads 0. Repro crashes under `-use-test-server`; check column-0 `//TEST_INPUT:` first; prove parser tests with rebuild-only-`render-test` mutants.
- **Bind pointer fields through `ConstantBuffer<S>`, not a global `uniform S`** (`new S{ubuffer…}` leaves them unbound: CPU segfault, CUDA misaligned address).
- **vk reads a `uniform T*` pointee with scalar layout, cuda with natural alignment.** Pick pointee structs whose two layouts agree.
- **render-test ignores `-entry`: every COMPARE_COMPUTE row dispatches `computeMain`**, so a `-entry otherMain` row can pass by coincidence. Give each runtime variant its own file (or `-DVARIANT` + `#if`); SIMPLE rows honor `-entry`.
- **CPU-lane `Texture.Load` ignores the mip coordinate (slang-rhi) and cuda `SampleLevel` returns level 0**, so no mip>0 read is checkable on every lane; check mip>0 on GPU lanes and run any mip-reading suggestion on each lane first.
- **Passes alone, fails after unrelated tests ⇒ a process-wide cache key misses an input** (render-test `DeviceCache` omitted the global session, #14103).
- **A slangc row's backend requirement comes from its FIRST `-target`.** `-target spirv ... -target dxil` fails rather than skips without DXC; gate with `//TEST(windows):` or put dxil first. Check precompiled-body reuse at `-O0`; `git clean -fdx tests` before a corpus A/B.
- **"The harness is monolithic, so no unit test is possible" is overstated.** A config-propagation fix with public fields and a plain-struct input can carry a `SLANG_UNIT_TEST`; only stdout/reporting-flow behavior needs behavioral verification.
- **To unit-test an unexported `namespace Slang` free function, put it in its own small TU compiled into both the DLL and `slang-unit-test`.** Don't export it (ABI creep) or add a heavy owning `.cpp`; `--no-undefined` linkage, not include paths, is the constraint.
- **On Windows a unit test cannot set an env var that `slang.dll` reads** (static CRT: per-DLL environment copied at load). Re-run the check in a child `slang-test <exact test name>` with the variable set and require the child's own `passed test:` line, not exit 0.

## Reporter configuration: one `init` path for main and parallel workers (#12177 / PR #12180)

Before the fix, `slang-test -v failure -use-test-server -server-count 8` printed every `passed test:` line plus the whole discovery block. The main reporter set its fields inline (`m_verbosity = options.verbosity`), while `runTestsInParallel`'s per-worker `TestReporter` only called `init(...)`, which carried no verbosity, so workers kept the ctor default `VerbosityLevel::Info` (the main/worker drift class of #11911). PR #12180 (7002bbe6, +79/−31 in `tools/slang-test`) folded all reporter configuration into `TestReporter::init(const Options&)` instead of a one-line patch, and the unit test `slangTestReporterInitFromOptions` pins the propagation.

The discovery half had two traps. **Timing:** the `Supported backends:` block in `slang-test-main.cpp` runs ~70 lines before `Options::parse`, so an in-place `>= Info` gate sees the ctor default. The block must still run there (it sets `availableBackendFlags`, registers pass-through categories), so names accumulate in place and print, gated, after parse; `_getAvailableRenderApiFlags`'s `Check <api>:` prints are post-parse and gate in place. **Scope:** only `Check <api>: Supported` and the `Supported backends:` aggregate are gated; `Not Supported` always prints, at the maintainer's request, because a missing backend is what a `-v failure` user needs. CI's `common-test-setup/action.yml` greps `Supported backends: ` at default `Info`, so default output stayed byte-identical; unconditional suppression would have broken CI backend detection ([#12177 close-out: verbosity fix merged; pre-parse timing + Not-Supported stays ungated](../learnings/1784683587359-12177-close-out-slang-test-verbosity-fix-merged-me.md)).

## Replay recording folders collide across parallel test-server processes (#12214)

`ReplayContext::generateTimestampFolderName()` (`source/slang-record-replay/replay-context.cpp`) is millisecond-precision with no process-unique part, and `setupRecordingMirror()` joins it to a shared base with non-exclusive `Path::createDirectoryRecursive`. **The CI flake:** replay unit tests share `.slang-replays-test`, and `findLatestReplayFolder(baseDir)` returns the last directory under the base with no ownership filter, so under `-use-test-server -server-count N` another server's newer folder wins and `unit-test-replay-integration.cpp`'s `secondPath.endsWith(latest)` fails intermittently (15 of 96 forced runs). **The latent production bug:** recorders starting in the same millisecond open the same `stream.bin`/`index.bin`, and `ReplayContext::loadLatestReplay()` over production `.slang-replays` assumes a single writer. Fix at two layers: (A) append `Process::getId()` (`source/core/slang-process.h`) and create atomically with retry (no `mkdtemp`/`O_EXCL` helper, but plain-`mkdir` `Path::createDirectory` gives atomic EEXIST on the leaf); (B) a per-process test base `.slang-replays-test-<pid>` with cleanup. B alone fixes the flake, A alone does not; ship A+B. The race dates to #9925 ([replay recording folders collide under parallel test-server processes](../learnings/1784895262564-slang-replay-recording-folders-collide-under-paral.md)). An explicit `SLANG_RECORD_PATH` is used verbatim, so parallel writers to one path collide the same way; see [Test Instruments That Lie Quietly](slang-tooling-test-instruments.md).

## COMPARE_COMPUTE lanes: synthesized CUDA lanes and pointer inputs

**A `-cpu` COMPARE_COMPUTE test also runs a CUDA lane on a GPU host.** slang-test synthesizes a `<test>.1 syn (cuda)` lane from every `-cpu` COMPARE_COMPUTE(_EX) line when CUDA is available (one directory went from 36 to 46 lanes), so a test checked only on a CPU-only host (e.g. Windows `-api cpu`) can fail on Linux GPU CI. PR #13927's `-cpu` NaN test put +inf in a `static const float[]` and the synthesized lane failed NVRTC ("dynamic initialization is not supported for a __device__ variable"; CUDA constant rules on [[wiki/concepts/slang-backends-cuda-cpp.md]]). Run new `-cpu` tests on a CUDA host (the L40S coworker containers) ([a -cpu test also runs a synthesized CUDA lane](../learnings/1792918374217-a-cpu-compare-compute-test-also-runs-a-synthesized.md); [render-test pointer fields](../learnings/1792958642303-render-test-pointer-fields-of-a-global-uniform-str.md)). That lane runs the kernel and compares the buffer. A note calling it compile-only ([syn (cuda) rows are compile-only](../learnings/1793663773741-slang-test-syn-cuda-rows-from-a-cpu-compare-comput.md)) read the wrong synthesizer: at 76a45e10c1 `_calcSynthesizedTests` (`slang-test-main.cpp` ~6148) copies a CPU-API test's `COMPARE_COMPUTE` options and adds `-cuda` (CUDA is in default `synthesizedTestApis`, `options.h:128`); `_calcSynthesizedCompileTargetTests` (~6282, `COMPILE_TARGET`) runs only under `-synthesize-compile-targets`/`-only-synthesized`. The runtime misaligned-address failure below confirms it.

**Pointer fields of a global `uniform` struct are not bound by `new S{ubuffer…}`.** `//TEST_INPUT: set pointers = new Pointers{ ubuffer(...), ubuffer(...) }` on `uniform Pointers pointers;` (a struct of `float2*`) leaves the fields unbound: the CPU lane segfaults the test server twice and the CUDA lane fails with CUDA_ERROR_MISALIGNED_ADDRESS. `ConstantBuffer<Pointers> cb;` with `set cb = new Pointers{...}` works, and `cb` can still be passed by value ([render-test pointer fields](../learnings/1792958642303-render-test-pointer-fields-of-a-global-uniform-str.md)). For a pointer stored inside a buffer, `data=[bufName ...]` embeds the 8-byte device address as two uint slots ([lower-buffer-element-type rewrites](../learnings/1792965326774-lower-buffer-element-type-rewrites-must-keep-the-r.md)).

**An unbound resource parameter crashes slang-test itself (#14407).** Causes: an indented `//TEST_INPUT:` (render-test's `shader-input-layout.cpp:1047` tests `startsWith("//")` on the raw line, while slang-test's `//TEST` scan, `slang-test-main.cpp:664-677`, first skips spaces, tabs and extra `/`), a missing TEST_INPUT, or one in an `#include`d file. `-cpu` segfaults (139), `-cuda` hits `CUDA_ERROR_ILLEGAL_ADDRESS` at slang-rhi `cuda-command.cpp:940` then an assert abort (134), Vulkan silently reads 0. Both kill slang-test because the default spawn type is `UseSharedLibrary` (`test-context.cpp:355`), running render-test in-process; under `-use-test-server` the server crashes and the test reports FAILED. A driver fault on an invalid module behaves the same; `-use-test-server -server-count 1` under `timeout -k 10 180` reports FAILED in ~5 s. When a CPU/CUDA repro crashes slang-test, check for a column-0 `//TEST_INPUT:` per parameter before blaming the compiler; a fail-loudly check is #14409 ([unbound param aborts slang-test](../learnings/1794132979479-unbound-render-test-param-cuda-aborts-slang-test-t.md), [driver fault SIGSEGVs in-process](../learnings/1794133299455-float-cas-on-spir-v-a-value-bitcast-is-not-enough-.md)). PR #14411 (draft, 2026-11-08) gives render-test the slang-test prefix rule. Mutation drills proved its test: per mutant rebuild only the `render-test` ninja target (`--target render-test`, not `render-test-tool` though the output is `librender-test-tool.so`; under a minute) and run the test under `-use-test-server`. Four mutants (no extra-`/` strip, no `trimStart`, `/` and spaces stripped in one loop, spaces-only indent) each failed 0/3, so the test pins every branch, including a `// //TEST_INPUT:` decoy. `UnownedStringSlice::trim()`/`trimStart()` strip only space and tab, so a CRLF line keeps its `\r` ([render-test parser mutation drills](../learnings/1794137071520-test-harness-parser-fixes-pin-each-branch-with-reb.md)).

**The vk and cuda lanes lay out a pointee differently.** A `uniform T*` filled with `ubuffer(data=[...])` is read with scalar layout on Vulkan (PhysicalStorageBuffer) and natural alignment on CUDA: `struct Inner { bool b; float4 x[2]; }` puts `x` at offset 4 vs 16, so `x[1].w` reads 14 vs 17 (also master 52e29ab43). Avoid a `float4` after a 4-byte field ([pointer data: vk scalar, cuda natural](../learnings/1792966623515-slang-test-pointer-data-on-vk-uses-scalar-offsets-.md)). A `-cuda` line does not replace a vk line for a SPIR-V lowering bug: #13948 reproduced only on vk/spirv ([lower-buffer-element-type rewrites](../learnings/1792965326774-lower-buffer-element-type-rewrites-must-keep-the-r.md)).

**`TEST_INPUT` `data=[...]` lists 32-bit words, not elements, whatever the `stride`.** `ubuffer(data=[2.0 10.0], stride=8)` packs 32-bit floats, so a `RWStructuredBuffer<double>` reads garbage; use `l`-suffixed literals in the shader or bit patterns, and size 64-bit buffers at 2 words per element (32 zeros for 16 doubles). A shader writing past a short buffer aborts `-cpu` with glibc heap corruption ("corrupted double-linked list", "free(): invalid next size") (looks like a harness bug), while CUDA/VK silently drop the writes and FileCheck reports a CHECK-NEXT mismatch at element N+1 (#14222). Read the whole `<file>.slang.actual.txt` before deleting a scratch dir ([TEST_INPUT data counts 32-bit words; a short buffer corrupts the CPU heap](../learnings/1793673491930-slang-test-test-input-data-counts-32-bit-words-so-.md), [TEST_INPUT floats are 32-bit; double transcendentals segfault on vk](../learnings/1793659067733-slang-test-gpu-double-checks-test-input-floats-are.md)). Also, on Vulkan `double` radians/degrees/exp/log/exp2/log2 (and their `fwd_diff`) emit GLSL.std.450 ops that take only 16/32-bit floats; slang-test segfaults (139) with no pass/fail line while the cuda row prints "passed". Check with `SLANG_RUN_SPIRV_VALIDATION=1 slangc -target spirv` (#14061; `double.getPi()` alone runs) ([same](../learnings/1793659067733-slang-test-gpu-double-checks-test-input-floats-are.md)).

**render-test ignores `-entry`.** `tools/render-test/options.cpp:301-303` parses `-entry` into `Options::entryPointName`, which nothing reads; `slang-support.cpp:22,802` hard-codes `computeMain`. A `COMPARE_COMPUTE_EX(...): ... -entry otherMain` row runs `computeMain` and passes whenever the expected value also appears in its output: on #14080 (2026-10-30) the `PACKED: 7.0` rows for `-entry packedMain` matched computeMain's `outputBuffer[1] = 7.0` (caught by slang-reviewer, not codex or /code-review). For a second runtime shader use its own file as `computeMain`, or `-Xslang... -DVARIANT -X.` with `#if`; `slangc`/`TEST:SIMPLE` rows honor `-entry` ([COMPARE_COMPUTE always dispatches computeMain](../learnings/1793329026502-slang-test-compare-compute-render-test-ignores-ent.md)).

**No `Load` or `SampleLevel` reads a specific mip on every lane.** At slang c959b561d (slang-rhi b856e635, L40S), on a size-4 `content=gradient` RGBA32Float texture `tex.Load(int3(1,1,1))` gives cpu 0.333333 (the mip-0 texel) but cuda/vk 1.0: slang-rhi `src/cpu/cpu-texture.cpp:396` inverts the test (`if (!hasMipLevels) mip = ...`, `hasMipLevels = !isMultisample`; still on main 30250fa). A CPU-lane CHECK on a mip>0 `Load` reads mip 0 and passes whenever levels agree (gradient texel (0,0) is 0 at every level). `tex.SampleLevel(pointSampler, uv, 2)` returns level 0 on cuda while cpu and vk honour it (cause unconfirmed; maybe `cuda-texture.cpp` default `maxMipmapLevelClamp` = 0). Check mip>0 values on the GPU lanes for `Load`, note in the test that the CPU lane only exercises host-side data generation, and run any mip-reading remedy on every lane before suggesting it (#14122's `SampleLevel` suggestion would have broken cuda) ([CPU-lane Texture.Load ignores the mip](../learnings/1793424223067-render-test-cpu-lane-texture-load-ignores-the-mip-.md)).

**render-test's `DeviceCache` key omitted the Slang global session (#14103).** `tools/render-test/slang-test-device-cache.cpp` keyed devices by type, profile and flags but not `desc.slang.slangGlobalSession`, and RenderTestApp compiles with `device->getSlangSession()->getGlobalSession()`. On a cache hit, a test given a fresh core-module-less session (`hasDeferredCoreModule`, e.g. `-compile-arg -load-core-module x.zip`) compiled against the previous test's session: `std-lib-serialize.slang.4 syn (llvm)` passed alone and failed after any earlier render-test test. It hid because `IGlobalSession::parseCommandLineArguments` returned SLANG_OK on parse failure; the #14103 PR adds the session to the key ([DeviceCache ignored the global session](../learnings/1793400319361-render-test-devicecache-ignored-the-slang-global-s.md)).

## Backend requirements come from the first `-target`; precompiled-module rows

**slang-test derives a slangc row's backend requirement from the FIRST `-target` only** (`_extractArg` / `cmdLine.findArgIndex("-target")`, `slang-test-main.cpp` ~1615). A precompile row `//TEST:COMPILE: ... -target spirv -embed-downstream-ir -target dxil -embed-downstream-ir` requires only glslang, so without DXC (Linux aarch64 CI, `-DSLANG_ENABLE_DXIL=OFF`) it FAILS instead of skipping. Gate with `//TEST(windows):` like `tests/library/precompiled-dxil*.slang`, or put `-target dxil` first — which is not neutral: `addDecoration` prepends, changing which `AvailableInDownstreamIR` decoration `findDecoration` sees first. A consumer row can pass vacuously, because `import` compiles from source when the precompiled artifact is absent ([backend requirement from the first -target](../learnings/1793285684044-slang-test-a-test-line-s-backend-requirement-comes.md), [precompiled-module review pitfalls, #14008](../learnings/1793279676378-precompiled-module-reviews-stripping-availableindo.md)).

**Check precompiled-body reuse at `-O0`, not only correctness.** On #14008 a remedy stripping `AvailableInDownstreamIR` from every address-space clone fixed wrong-signature imports but stopped reuse of the precompiled body in the common case (an `inout` param, `Generic`, emitted as SPIR-V `Function`, called with a local). Only `-O0` shows it (master 3 functions, the fix 4: a local copy plus the unused precompiled one); spirv-opt hides it at default optimization. To pin reuse by counting `OpName "f"`, use a library with no entry point (one with its own entry point adds its clones to the importer's `-O0` output). For corpus A/Bs over `tests/**/*.slang`, delete `tests/**/*.slang-module` first (`git clean -fdx tests`) and never run the full suite alongside, since it rewrites those modules ([precompiled-module review pitfalls](../learnings/1793279676378-precompiled-module-reviews-stripping-availableindo.md), [backend requirement from the first -target](../learnings/1793285684044-slang-test-a-test-line-s-backend-requirement-comes.md)).

## Putting harness and compiler internals under `slang-unit-test`

**slang-test internals are partially unit-testable.** An earlier rule held that `TestReporter` and `slang-test-main.cpp` build only into the `slang-test` executable, so every harness fix must be verified behaviorally ([harness false-green fixes: verify behaviorally](../learnings/1783013967417-slang-test-harness-false-green-fixes-verify-behavi.md)). That is overstated: `tools/CMakeLists.txt` already compiles `tools/slang-test/test-output-path-util.cpp` into `slang-unit-test` (precedents: `unit-test-slang-test-output-path.cpp`, `-optimization-options.cpp`). Stdout/reporting-flow behavior (parallel worker output, the test-server false-green cluster) has no clean unit form; verify it behaviorally. A harness internal with public fields and a plain-struct input, such as `TestReporter::init(const Options&)`, can carry a `SLANG_UNIT_TEST`: add the `.cpp` to `slang-unit-test`'s `target_sources`, build a non-default `Options`, call `init(options, /*isSubReporter*/ true)`, and assert propagation, as PR #12180 did ([slang-test harness IS partially unit-testable](../learnings/1784664553168-slang-test-harness-is-partially-unit-testable-corr.md)).

**An unexported compiler free function: own TU, dual compile.** A unit test calling an internal `namespace Slang` function with no `SLANG_API` export will not link, because `slang-unit-test` links `libslang-compiler.so` with `-Wl,--no-undefined` (slang#12220: `classifyCommandLineOption`, `writeCommandLineArgs`). Exporting is ABI creep maintainers avoid. Adding the owning `.cpp` to the test target is sanctioned ([`not exported so a test can't link it` is false for slang-unit-test](../learnings/1785976052762-correction-not-exported-so-a-test-can-t-link-it-is.md); the impossibility-versus-cost lesson is on [Slang & slang-rhi test harness](slang-a-test-harness.md)) only when that `.cpp` is light: `slang-compiler-options.cpp` pulls in unexported `Profile::getName`, `capabilityNameToString` and `TypeTextUtil`, which cascade. The pattern documented in `tools/CMakeLists.txt` beside `slang-repro-validator.cpp` is to move the function into a small TU depending only on the types it needs. It joins the slang DLL through the `slang_add_target(. ...)` glob in `source/slang/CMakeLists.txt`, and adding it to `slang-unit-test`'s `target_sources(... PRIVATE ...)` compiles it into the test too: one source, two binaries, no export. Includes are not the limit (`INCLUDE_DIRECTORIES_PRIVATE ${slang_SOURCE_DIR}/source` allows `#include "slang/..."`) ([unit-testing an unexported slang free function: own TU + dual compile](../learnings/1785203787876-unit-testing-an-internal-unexported-slang-free-fun.md)).

**Windows: the test DLL and slang.dll do not share an environment.** Windows builds use `CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded[Debug]` (static CRT, `CMakePresets.json`), so each DLL has its own CRT environment table copied at load. A `_putenv_s` or `ScopedEnvVar` inside `slang-unit-test-tool.dll` is invisible to `PlatformUtil::getEnvironmentVariable` in slang.dll (`_dupenv_s`, `slang-platform.cpp`), so a test setting e.g. `SLANG_RECORD_LAYER` in-process passes on Linux/macOS and fails on every Windows job. `SetEnvironmentVariableA` does not help (`_putenv_s` already updates the OS block; slang.dll's table is a load-time copy). Re-run the check in a child `slang-test <exact test name>` launched with the variable set, guarded by a sentinel env var, and require the child's own `passed test: '<name>` line, since exit 0 alone is vacuous. Env-driven tests like SPIR-V validation work only because CI exports the variable before launch (PR #12823; Microsoft: "potential errors passing CRT objects across DLL boundaries") ([Windows static CRT: a unit test can't set an env var that slang.dll reads](../learnings/1791936249295-windows-static-crt-a-unit-test-can-t-set-an-env-va.md)). That CI-exported `SLANG_RUN_SPIRV_VALIDATION=1` is itself a local-vs-CI difference; see [Slang & slang-rhi test harness](slang-a-test-harness.md).
