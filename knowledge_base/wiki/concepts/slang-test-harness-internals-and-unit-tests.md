# slang-test Harness Internals and In-Process Unit Tests

slang-test reporter and discovery-output configuration (CI parses it), a replay-folder race between parallel test servers, COMPARE_COMPUTE lane synthesis and render-test input binding/layout, and putting harness or compiler internals under in-process `slang-unit-test`. Whether a green run can be trusted is on [slang-test False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md).

## TL;DR

- **Main and per-worker `TestReporter`s configure through ONE path, `TestReporter::init(const Options&)`.** Before PR #12180 parallel workers kept ctor-default `Info` verbosity under `-v failure`. New reporter settings go inside `init`, or the worker/main drift (#11911, #12177) returns.
- **Check that a print runs AFTER the option it is gated on is parsed.** `Supported backends:` prints ~70 lines before `Options::parse`; accumulate pre-parse, print gated after parse.
- **CI parses discovery output.** `common-test-setup/action.yml` greps `Supported backends: ` at default verbosity, so discovery is gated on `verbosity >= Info`, never suppressed unconditionally. `Check <api>: Not Supported` lines stay ungated.
- **Replay recording folders are not process-unique** (ms timestamp, no PID; no ownership filter in `findLatestReplayFolder`), so parallel test servers read each other's recordings (#12214). Fix both: a per-process test base dir (the flake) and PID-suffixed names with an atomic leaf create (the latent production collision).
- **On a GPU host every `-cpu` COMPARE_COMPUTE line also runs a synthesized `syn (cuda)` runtime lane.** Verify `-cpu` tests on a CUDA host. Only opt-in `-synthesize-compile-targets` rows are compile-only.
- **`TEST_INPUT` `data=[...]` counts 32-bit words, even with `stride=8`.** 64-bit values need 2 words and bit patterns or `l` literals; a short buffer corrupts the CPU heap (glibc abort) and silently drops GPU writes.
- **An unbound parameter (indented, missing or `#include`d `//TEST_INPUT:`) crashes slang-test itself on `-cpu` (139) and `-cuda` (134)** because render-test runs in-process (`UseSharedLibrary`); vk reads 0. Check column-0 `//TEST_INPUT:` first. A COMPARE_COMPUTE kernel also needs an explicit `//TEST_INPUT:ubuffer(...):out,name=output` binding for its output buffer — otherwise empty FileCheck output or `CUDA_ERROR_ILLEGAL_ADDRESS` reads exactly like a compiler bug.
- **Bind pointer fields through `ConstantBuffer<S>`, not a global `uniform S`** (`new S{ubuffer…}` leaves them unbound: CPU segfault, CUDA misaligned address). Never take `&localVar` as a `Ptr` test value (vk device-lost; `Access.Immutable` loads emit `__ldg` on CUDA, which faults on non-global memory).
- **vk reads a `uniform T*` pointee with scalar layout, cuda with natural alignment.** Pick pointee structs whose two layouts agree.
- **render-test ignores `-entry`: every COMPARE_COMPUTE row dispatches `computeMain`**, so a `-entry otherMain` row can pass by coincidence. Give each runtime variant its own file (or `-DVARIANT` + `#if`); SIMPLE rows honor `-entry`.
- **CPU-lane `Texture.Load` ignores the mip coordinate (slang-rhi) and cuda `SampleLevel` returns level 0**, so no mip>0 read is checkable on every lane; check mip>0 on GPU lanes.
- **Passes alone, fails after unrelated tests ⇒ a process-wide cache key misses an input** (render-test `DeviceCache` omitted the global session, #14103).
- **A slangc row's backend requirement comes from its FIRST `-target`.** `-target spirv ... -target dxil` fails rather than skips without DXC; gate with `//TEST(windows):` or put dxil first. Check precompiled-body reuse at `-O0`; `git clean -fdx tests` before a corpus A/B.
- **"The harness is monolithic, so no unit test is possible" is overstated.** A config-propagation fix with public fields and a plain-struct input can carry a `SLANG_UNIT_TEST`; only stdout/reporting-flow behavior needs behavioral verification.
- **To unit-test an unexported `namespace Slang` free function, put it in its own small TU compiled into both the DLL and `slang-unit-test`.** Don't export it (ABI creep); `--no-undefined` linkage, not include paths, is the constraint.
- **`SLANG_UNIT_TEST` takes two args since #14674 (`name, usedApis`).** In-flight PRs adding 1-arg unit tests go red on the CI merge ref; fix = merge `origin/master` (never rebase/force-push a PR under review) and pass `NoRenderApi` for logic-only tests.
- **On Windows a unit test cannot set an env var that `slang.dll` reads** (static CRT: per-DLL environment copied at load). Re-run the check in a child `slang-test <exact test name>` with the variable set and require the child's own `passed test:` line, not exit 0.
- **slang-test defaults to direct SPIR-V (`emitSPIRVDirectly: true`)** — the `-emit-spirv-via-glsl` (glslang) path is opt-in and untested by render tests; a green COMPARE_COMPUTE file says nothing about via-glsl compilability.
- **CHECK values must render identically in hex and decimal legs** (render-test prints `%X`, `-cpu -output-using-type` legs print decimal), and SIMPLE-leg spirv-asm pins are written against `-O0` output. Compute bit-pattern constants, never recall them (1.5f = 0x3FC00000 = 1069547520).

## Reporter configuration: one `init` path for main and parallel workers (#12177 / PR #12180)

Before the fix, `slang-test -v failure -use-test-server -server-count 8` printed every `passed test:` line plus the whole discovery block: the main reporter set fields inline while `runTestsInParallel`'s per-worker `TestReporter` only called `init(...)`, which carried no verbosity — workers kept the ctor default (the #11911 drift class). PR #12180 folded all reporter configuration into `TestReporter::init(const Options&)`, pinned by the unit test `slangTestReporterInitFromOptions`.

Two traps in the discovery half. **Timing:** the `Supported backends:` block in `slang-test-main.cpp` runs ~70 lines before `Options::parse`, so an in-place gate sees the ctor default. The block must still run there (it sets `availableBackendFlags`, registers pass-through categories), so names accumulate in place and print, gated, after parse. **Scope:** only `Check <api>: Supported` and the aggregate are gated; `Not Supported` always prints, at the maintainer's request. CI's `common-test-setup/action.yml` greps `Supported backends: ` at default `Info`, so default output stayed byte-identical; unconditional suppression would have broken CI backend detection ([#12177 close-out](../learnings/1784683587359-12177-close-out-slang-test-verbosity-fix-merged-me.md)).

## Replay recording folders collide across parallel test-server processes (#12214)

`ReplayContext::generateTimestampFolderName()` is millisecond-precision with no process-unique part, and `setupRecordingMirror()` joins it to a shared base with non-exclusive `createDirectoryRecursive`. **The CI flake:** replay unit tests share `.slang-replays-test`, and `findLatestReplayFolder(baseDir)` returns the last directory under the base with no ownership filter, so another server's newer folder wins and the integration test fails intermittently (15 of 96 forced runs). **The latent production bug:** recorders starting in the same millisecond open the same `stream.bin`/`index.bin`. Fix at two layers: (A) append `Process::getId()` and create atomically with retry (plain-`mkdir` `Path::createDirectory` gives atomic EEXIST on the leaf); (B) a per-process test base `.slang-replays-test-<pid>` with cleanup. B alone fixes the flake, A alone does not; ship A+B. The race dates to #9925 ([replay recording folders collide under parallel test-server processes](../learnings/1784895262564-slang-replay-recording-folders-collide-under-paral.md)). An explicit `SLANG_RECORD_PATH` is used verbatim, so parallel writers to one path collide the same way; see [Test Instruments That Lie Quietly](slang-tooling-test-instruments.md).

## COMPARE_COMPUTE lanes: synthesized CUDA lanes and pointer inputs

**A `-cpu` COMPARE_COMPUTE test also runs a CUDA lane on a GPU host.** slang-test synthesizes a `<test>.1 syn (cuda)` lane from every `-cpu` COMPARE_COMPUTE(_EX) line when CUDA is available (one directory went 36→46 lanes), so a test checked only on a CPU-only host can fail on Linux GPU CI — PR #13927's NaN test put +inf in a `static const float[]` and the synthesized lane failed NVRTC ("dynamic initialization is not supported for a __device__ variable"). Run new `-cpu` tests on a CUDA host (the L40S containers) ([a -cpu test also runs a synthesized CUDA lane](../learnings/1792918374217-a-cpu-compare-compute-test-also-runs-a-synthesized.md); [render-test pointer fields](../learnings/1792958642303-render-test-pointer-fields-of-a-global-uniform-str.md)). An earlier note calling the lane compile-only was REFUTED by code reading at 76a45e10c1: `_calcSynthesizedTests` copies the CPU-API test's COMPARE_COMPUTE options and adds `-cuda` (CUDA is in default `synthesizedTestApis`); `_calcSynthesizedCompileTargetTests` (COMPILE_TARGET) runs only under `-synthesize-compile-targets` ([syn (cuda) rows are compile-only](../learnings/1793663773741-slang-test-syn-cuda-rows-from-a-cpu-compare-comput.md)).

**Pointer fields of a global `uniform` struct are not bound by `new S{ubuffer…}`.** `//TEST_INPUT: set pointers = new Pointers{ ubuffer(...), ... }` on `uniform Pointers pointers;` leaves the fields unbound: the CPU lane segfaults the test server, the CUDA lane fails with CUDA_ERROR_MISALIGNED_ADDRESS. `ConstantBuffer<Pointers> cb;` with `set cb = new Pointers{...}` works, and `cb` can still be passed by value ([render-test pointer fields](../learnings/1792958642303-render-test-pointer-fields-of-a-global-uniform-str.md)). For a pointer stored inside a buffer, `data=[bufName ...]` embeds the 8-byte device address as two uint slots ([lower-buffer-element-type rewrites](../learnings/1792965326774-lower-buffer-element-type-rewrites-must-keep-the-r.md)). Never take `&localVar` as a language `Ptr` test value: on Vulkan it is a PhysicalStorageBuffer bitcast of Function storage (a deterministic `VK_ERROR_DEVICE_LOST`), and `Access.Immutable` loads emit `__ldg` on CUDA, which faults on non-global memory ([hex buffer output; Ptr-to-local UB](../learnings/1794825279331-slang-test-harness-hex-buffer-output-output-using-.md)).

**CHECK values must survive both renderings, and SIMPLE legs pin against -O0 output.** render-test prints COMPARE_COMPUTE buffers in HEX (`%X`) while `-cpu -output-using-type` legs print decimal — a CHECK value must render identically in both (small values or float-derived ones like 3), or the decimal legs silently fail. SIMPLE legs run at `-O0`, so spirv-asm pins are written against `-O0` output: a direct constant bitcast stays param-based inside an un-inlined function (pin `OpBitcast %int %id`, not a constant); function emission order (computeMain before helpers) fixes pin ordering. The front end constant-folds a direct `__slang_noop_cast<float>(intLiteral)` chain (correct reinterpretation) but NOT a struct-getter chain — pin the getter path in asm, the noop_cast only at runtime; compute bit-pattern constants, don't recall them (bits of 1.5f are `0x3FC00000` = 1069547520) ([-O0 SIMPLE legs, hex vs decimal output, constant folding](../learnings/1794994061881-slang-test-harness-o0-simple-legs-hex-vs-decimal-c.md)).

**An unbound resource parameter crashes slang-test itself (#14407).** Causes: an indented `//TEST_INPUT:` (render-test's `shader-input-layout.cpp:1047` tests `startsWith("//")` on the raw line, while slang-test's `//TEST` scan first skips spaces, tabs and extra `/`), a missing TEST_INPUT, or one in an `#include`d file. `-cpu` segfaults (139), `-cuda` hits `CUDA_ERROR_ILLEGAL_ADDRESS` then an assert abort (134), Vulkan silently reads 0. Both kill slang-test because the default spawn type is `UseSharedLibrary`, running render-test in-process; under `-use-test-server` the server crashes and the test reports FAILED. A driver fault on an invalid module behaves the same; `-use-test-server -server-count 1` under `timeout -k 10 180` reports FAILED in ~5 s. When a CPU/CUDA repro crashes slang-test, check for a column-0 `//TEST_INPUT:` per parameter before blaming the compiler ([unbound param aborts slang-test](../learnings/1794132979479-unbound-render-test-param-cuda-aborts-slang-test-t.md), [driver fault SIGSEGVs in-process](../learnings/1794133299455-float-cas-on-spir-v-a-value-bitcast-is-not-enough-.md)). PR #14411 gives render-test the slang-test prefix rule; mutation drills proved its test — per mutant rebuild only the `render-test` ninja target (under a minute) and run the test under `-use-test-server`; four mutants each failed 0/3, so the test pins every branch, including a `// //TEST_INPUT:` decoy. `UnownedStringSlice::trim()` strips only space and tab, so a CRLF line keeps its `\r` ([render-test parser mutation drills](../learnings/1794137071520-test-harness-parser-fixes-pin-each-branch-with-reb.md)). The write-side face of the same gap: a COMPARE_COMPUTE test needs an explicit `//TEST_INPUT:ubuffer(data=[0 0], stride=4):out,name=output` line binding the output buffer, or the kernel writes to an unbound buffer — empty FileCheck results or `CUDA_ERROR_ILLEGAL_ADDRESS` that looks exactly like a compiler bug (cost ~1.5h of false root-causing on #13996) ([COMPARE_COMPUTE needs TEST_INPUT buffer binding](../learnings/1794905063627-slang-test-compare-compute-needs-test-input-buffer.md)).

**The vk and cuda lanes lay out a pointee differently.** A `uniform T*` filled with `ubuffer(data=[...])` is read with scalar layout on Vulkan (PhysicalStorageBuffer) and natural alignment on CUDA: `struct Inner { bool b; float4 x[2]; }` puts `x` at offset 4 vs 16, so `x[1].w` reads 14 vs 17. Avoid a `float4` after a 4-byte field ([pointer data: vk scalar, cuda natural](../learnings/1792966623515-slang-test-pointer-data-on-vk-uses-scalar-offsets-.md)). A `-cuda` line does not replace a vk line for a SPIR-V lowering bug: #13948 reproduced only on vk/spirv ([lower-buffer-element-type rewrites](../learnings/1792965326774-lower-buffer-element-type-rewrites-must-keep-the-r.md)).

**slang-test defaults to direct SPIR-V: the via-glsl (glslang) path is untested by render tests.** `emitSPIRVDirectly` defaults to **true** (`options.h:141`), so COMPARE_COMPUTE render tests always compile direct SPIR-V — `-emit-spirv-via-glsl` is opt-in only. A test file can contain code the via-glsl path cannot compile and still stay green in CI (the scalar>>vector shifts in `tests/wgsl/bitshifts.slang`, #14590). When triaging "glslang rejects X", reproduce manually with `slangc -target spirv -emit-spirv-via-glsl` (glslang is embedded; no external tool or GPU needed); the embedded glslang accepts mixed-signedness shifts — only scalar-left/vector-right is rejected ([slang-test defaults to direct SPIR-V](../learnings/1795015033026-slang-test-defaults-to-direct-spir-v-via-glsl-glsl.md)).

**`TEST_INPUT` `data=[...]` lists 32-bit words, not elements, whatever the `stride`.** `ubuffer(data=[2.0 10.0], stride=8)` packs 32-bit floats, so a `RWStructuredBuffer<double>` reads garbage; use `l`-suffixed literals or bit patterns and size 64-bit buffers at 2 words per element. A shader writing past a short buffer aborts `-cpu` with glibc heap corruption (looks like a harness bug), while CUDA/VK silently drop the writes and FileCheck reports a CHECK-NEXT mismatch at element N+1 (#14222). Read the whole `<file>.slang.actual.txt` before deleting a scratch dir ([TEST_INPUT data counts 32-bit words](../learnings/1793673491930-slang-test-test-input-data-counts-32-bit-words-so-.md), [TEST_INPUT floats are 32-bit; double transcendentals segfault on vk](../learnings/1793659067733-slang-test-gpu-double-checks-test-input-floats-are.md)). On Vulkan, `double` radians/degrees/exp/log/exp2/log2 (and `fwd_diff`) emit GLSL.std.450 ops that take only 16/32-bit floats; slang-test segfaults (139) with no pass/fail line while the cuda row prints "passed". Check with `SLANG_RUN_SPIRV_VALIDATION=1 slangc -target spirv` (#14061) ([same](../learnings/1793659067733-slang-test-gpu-double-checks-test-input-floats-are.md)).

**render-test ignores `-entry`.** `tools/render-test/options.cpp:301-303` parses `-entry` into `Options::entryPointName`, which nothing reads; `slang-support.cpp:22,802` hard-codes `computeMain`. A `COMPARE_COMPUTE_EX(...): ... -entry otherMain` row runs `computeMain` and passes whenever the expected value also appears in its output: #14080's `PACKED: 7.0` rows for `-entry packedMain` matched computeMain's `outputBuffer[1] = 7.0` (caught by slang-reviewer, not codex or /code-review). For a second runtime shader use its own file as `computeMain`, or `-Xslang... -DVARIANT -X.` with `#if`; `slangc`/`TEST:SIMPLE` rows honor `-entry` ([COMPARE_COMPUTE always dispatches computeMain](../learnings/1793329026502-slang-test-compare-compute-render-test-ignores-ent.md)). A lane that never ran anywhere passes everywhere it is skipped and fails on the first machine that can run it: #13408's two `-render-feature ray-query` lanes were skipped on the GPU-less dev container AND macOS CI, so a latent `-entry runtimeFlag` defect surfaced 6 weeks later on an L40S. Name compute test entries `computeMain`, and treat "runtime lane" claims from a GPU-less box as unexecuted until a capable device ran them ([render-test ignores -entry on compute lanes](../learnings/1794839621185-render-test-ignores-entry-on-compute-lanes-name-co.md)).

**No `Load` or `SampleLevel` reads a specific mip on every lane.** At slang c959b561d, `tex.Load(int3(1,1,1))` on a size-4 `content=gradient` texture gives cpu 0.333333 (the mip-0 texel) but cuda/vk 1.0: slang-rhi `cpu-texture.cpp:396` inverts the test (`if (!hasMipLevels) mip = ...`; still on main). `tex.SampleLevel(pointSampler, uv, 2)` returns level 0 on cuda while cpu and vk honour it (cause unconfirmed; maybe the cuda default `maxMipmapLevelClamp` = 0). Check mip>0 values on the GPU lanes, and run any mip-reading remedy on every lane before suggesting it (#14122's suggestion would have broken cuda) ([CPU-lane Texture.Load ignores the mip](../learnings/1793424223067-render-test-cpu-lane-texture-load-ignores-the-mip-.md)).

**render-test's `DeviceCache` key omitted the Slang global session (#14103).** Devices were keyed by type, profile and flags but not `desc.slang.slangGlobalSession`; on a cache hit a test given a fresh core-module-less session (`-load-core-module x.zip`) compiled against the previous test's session: `std-lib-serialize.slang.4 syn (llvm)` passed alone and failed after any earlier render-test test. It hid because `IGlobalSession::parseCommandLineArguments` returned SLANG_OK on parse failure ([DeviceCache ignored the global session](../learnings/1793400319361-render-test-devicecache-ignored-the-slang-global-s.md)).

## Backend requirements come from the first `-target`; precompiled-module rows

**slang-test derives a slangc row's backend requirement from the FIRST `-target` only** (`_extractArg`, `slang-test-main.cpp` ~1615). A precompile row `//TEST:COMPILE: ... -target spirv ... -target dxil ...` requires only glslang, so without DXC (Linux aarch64 CI) it FAILS instead of skipping. Gate with `//TEST(windows):`, or put `-target dxil` first — which is not neutral: `addDecoration` prepends, changing which `AvailableInDownstreamIR` decoration `findDecoration` sees first. A consumer row can pass vacuously because `import` compiles from source when the precompiled artifact is absent ([backend requirement from the first -target](../learnings/1793285684044-slang-test-a-test-line-s-backend-requirement-comes.md), [precompiled-module review pitfalls, #14008](../learnings/1793279676378-precompiled-module-reviews-stripping-availableindo.md)).

**Check precompiled-body reuse at `-O0`, not only correctness.** On #14008 a remedy stripping `AvailableInDownstreamIR` from every address-space clone fixed wrong-signature imports but stopped reuse of the precompiled body in the common case (an `inout` param emitted as SPIR-V `Function`, called with a local). Only `-O0` shows it (master 3 functions, the fix 4); spirv-opt hides it at default optimization. To pin reuse by counting `OpName "f"`, use a library with no entry point. For corpus A/Bs over `tests/**/*.slang`, delete `tests/**/*.slang-module` first (`git clean -fdx tests`) and never run the full suite alongside ([precompiled-module review pitfalls](../learnings/1793279676378-precompiled-module-reviews-stripping-availableindo.md), [backend requirement from the first -target](../learnings/1793285684044-slang-test-a-test-line-s-backend-requirement-comes.md)).

## TEST-line option lists and per-API display names

Design facts for adding a list-valued `//TEST:CMD(...)` option (verified while triaging #14559's proposed `targets=`). A new list-valued option must handle the comma-split in `_parseCommandArguments` (slang-test-main.cpp:368): `targets=vk,metal` arrives as `targets=vk` plus a bare no-`=` segment `metal`; "bare segment continues the list" is the minimal fix. On the display side, the `(<api>)` suffix is appended from used render-API flags for any test whose args name an explicit API, so a per-backend expanded test's `foo.slang.2 (metal)` name needs no new naming code; `_calcSynthesizedTests` skips tests that already name an explicit API, so `targets=` expansion and synthesized-variant synthesis do not interact ([slang-test option-list parsing and per-API display naming](../learnings/1794950105957-slang-test-option-list-parsing-and-per-api-display.md)).

## Putting harness and compiler internals under `slang-unit-test`

**slang-test internals are partially unit-testable.** An earlier rule held that `TestReporter` and `slang-test-main.cpp` build only into the `slang-test` executable, so every harness fix must be verified behaviorally ([harness false-green fixes: verify behaviorally](../learnings/1783013967417-slang-test-harness-false-green-fixes-verify-behavi.md)). That is overstated: `tools/CMakeLists.txt` already compiles `test-output-path-util.cpp` into `slang-unit-test`. Stdout/reporting-flow behavior (parallel worker output, the test-server false-green cluster) has no clean unit form; verify it behaviorally. A harness internal with public fields and a plain-struct input, such as `TestReporter::init(const Options&)`, can carry a `SLANG_UNIT_TEST`: add the `.cpp` to `slang-unit-test`'s `target_sources`, build a non-default `Options`, call `init(options, /*isSubReporter*/ true)`, and assert propagation ([slang-test harness IS partially unit-testable](../learnings/1784664553168-slang-test-harness-is-partially-unit-testable-corr.md)).

**An unexported compiler free function: own TU, dual compile.** A unit test calling an internal `namespace Slang` function with no `SLANG_API` export will not link, because `slang-unit-test` links `libslang-compiler.so` with `-Wl,--no-undefined` (slang#12220). Exporting is ABI creep maintainers avoid; adding the owning `.cpp` to the test target is sanctioned ([`not exported so a test can't link it` is false](../learnings/1785976052762-correction-not-exported-so-a-test-can-t-link-it-is.md)) only when that `.cpp` is light — `slang-compiler-options.cpp` pulls in unexported helpers that cascade. The pattern documented in `tools/CMakeLists.txt` beside `slang-repro-validator.cpp` is to move the function into a small TU depending only on the types it needs: it joins the slang DLL through the `slang_add_target` glob and also compiles into `slang-unit-test` via `target_sources(... PRIVATE ...)` — one source, two binaries, no export. Includes are not the limit (`INCLUDE_DIRECTORIES_PRIVATE ${slang_SOURCE_DIR}/source` allows `#include "slang/..."`) ([unit-testing an unexported slang free function: own TU + dual compile](../learnings/1785203787876-unit-testing-an-internal-unexported-slang-free-fun.md)).

**Windows: the test DLL and slang.dll do not share an environment.** Windows builds use `CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded[Debug]` (static CRT), so each DLL has its own CRT environment table copied at load. A `_putenv_s` or `ScopedEnvVar` inside `slang-unit-test-tool.dll` is invisible to `PlatformUtil::getEnvironmentVariable` in slang.dll, so a test setting e.g. `SLANG_RECORD_LAYER` passes on Linux/macOS and fails on every Windows job; `SetEnvironmentVariableA` does not help. Re-run the check in a child `slang-test <exact test name>` launched with the variable set, guarded by a sentinel env var, and require the child's own `passed test: '<name>` line, since exit 0 alone is vacuous. Env-driven tests like SPIR-V validation work only because CI exports the variable before launch (PR #12823) ([Windows static CRT: a unit test can't set an env var that slang.dll reads](../learnings/1791936249295-windows-static-crt-a-unit-test-can-t-set-an-env-va.md)). That CI-exported `SLANG_RUN_SPIRV_VALIDATION=1` is itself a local-vs-CI difference; see [Slang & slang-rhi test harness](slang-a-test-harness.md).

**`SLANG_UNIT_TEST` is 2-arg since #14674 (`name, usedApis`).** PR #14674 (merged 2026-11-21) changed `SLANG_UNIT_TEST(name)` to `SLANG_UNIT_TEST(name, usedApis)`, so any in-flight PR adding a 1-arg unit test against an older base goes 8-way build red the moment CI builds the merge ref. The fix: `git merge origin/master` into the branch (never rebase/force-push a PR under review), update submodule pointers after the merge, then pass `NoRenderApi` for logic-only tests (other tests pass their API flags). Triage note: the red shows on `pull_request`-event runs (merge ref) while a stale `workflow_dispatch` run may just be priority-yielded — check which run actually failed before diagnosing ([slang#14674 made SLANG_UNIT_TEST 2-arg — merge master + pass usedApis](../learnings/1795717299991-slang-14674-made-slang-unit-test-2-arg-merge-maste.md)).
