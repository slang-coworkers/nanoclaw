# slang-test Harness Internals and In-Process Unit Tests

How the slang-test harness configures itself (reporter verbosity across parallel workers, discovery output that CI parses), a shared-state race between parallel test-server processes (replay recording folders), how COMPARE_COMPUTE lanes are synthesized and how pointer inputs are bound and laid out, and how to put a slang-test or compiler internal under an in-process `slang-unit-test` — including the two boundaries (unexported symbols, Windows per-DLL CRT environments) that decide whether an in-process test can see what it tests. Whether a green run can be trusted is on the sibling page [slang-test False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md).

## TL;DR

- **The main and per-worker `TestReporter`s are configured through ONE path, `TestReporter::init(const Options&)`.** Before PR #12180, parallel workers kept the ctor-default `Info` verbosity, so `-v failure` still printed `passed test:` lines under `-use-test-server`. A new reporter setting belongs inside `init`, or the worker/main drift class (#11911, #12177) comes back.
- **Before gating a print on an option, check that the print runs AFTER the option is parsed.** The `Supported backends:` block prints about 70 lines before `Options::parse`, so an in-place verbosity gate there is a no-op. Accumulate the names pre-parse and print them, gated, after parse.
- **CI parses slang-test's discovery output.** `.github/actions/common-test-setup/action.yml` greps `Supported backends: ` at default verbosity, so discovery is gated on `verbosity >= Info` (suppressed only under `-v failure`), never unconditionally.
- **`Check <api>: Not Supported` lines stay ungated.** A missing backend is signal a `-v failure` user needs; only the positive `Supported` lines and the aggregate are gated.
- **Replay recording folders are not process-unique.** Folder names are millisecond timestamps with no PID, and `findLatestReplayFolder` returns the last folder in the base dir with no ownership filter. Parallel test-server processes sharing `.slang-replays-test` therefore read each other's recordings (#12214). A per-process test base dir fixes the flake; PID-suffixed names plus an atomic leaf create fix the latent production collision. Do both.
- **On a GPU host, every `-cpu` COMPARE_COMPUTE line also runs a synthesized `syn (cuda)` lane.** A test checked only on a CPU-only host is not verified; run it on a CUDA host before calling it green.
- **Bind pointer fields through `ConstantBuffer<S>`, not a global `uniform S`.** `new S{ubuffer…}` leaves a global uniform struct's pointer fields unbound (CPU segfault, CUDA misaligned address).
- **vk reads a `uniform T*` pointee with scalar layout, cuda with natural alignment.** Choose pointee structs whose two layouts agree, or one test's vk and cuda lines disagree.
- **"The harness is monolithic, so no unit test is possible" is overstated.** Some slang-test sources already compile into `slang-unit-test` (e.g. `test-output-path-util.cpp`). A config-propagation fix with public fields and a plain-struct input can carry a `SLANG_UNIT_TEST`. Only stdout/reporting-flow behavior (parallel worker output, the false-green cluster) still needs behavioral verification.
- **To unit-test an unexported `namespace Slang` free function, put it in its own small translation unit and compile that TU into both the DLL and `slang-unit-test`.** Do not export it (ABI creep), and do not add the whole owning `.cpp` if it drags in other unexported symbols. `slang-unit-test` links with `--no-undefined`, so linkage, not include paths, is the constraint.
- **On Windows a unit test cannot set an env var that `slang.dll` reads.** The static CRT gives each DLL its own environment table, copied at load, so `_putenv_s`/`ScopedEnvVar` in the test DLL is invisible to slang.dll. Such a test passes on Linux/macOS and fails on every Windows job. Re-run the check in a child `slang-test <exact test name>` launched with the variable set, and require the child's own `passed test:` line rather than exit 0.

## Reporter configuration: one `init` path for main and parallel workers (#12177 / PR #12180)

Consider `slang-test -v failure -use-test-server -server-count 8`. The user asked for failures only, yet before the fix the run printed every `passed test:` line plus the whole backend and render-API discovery block. The reporter half was configuration drift: the single-run main reporter set its fields inline (`m_verbosity = options.verbosity` and friends), while `runTestsInParallel`'s per-worker `TestReporter` only called `init(...)`, which carried no verbosity, so every worker kept the ctor default `VerbosityLevel::Info` and the passing-test gate never fired. It is the same main/worker drift class as #11911. PR #12180 (merged as 7002bbe6, closes #12177, +79/−31 entirely in `tools/slang-test`) took the principled route rather than a one-line `m_verbosity =` patch: all reporter configuration is folded into `TestReporter::init(const Options&)`, so single-run and per-worker reporters configure through one code path, and the unit test `slangTestReporterInitFromOptions` pins the propagation.

The discovery half carries two traps that the fix round surfaced. **Timing:** the `Supported backends:` block in `slang-test-main.cpp` runs before `Options::parse` (about 70 lines earlier), so at print time `context.options.verbosity` is still the ctor default and an in-place `>= Info` gate does nothing under `-v failure`. The block still has to run there, because it also sets `availableBackendFlags` and registers pass-through categories; the fix accumulates the names in place and prints them, gated, after parse. The `_getAvailableRenderApiFlags` `Check <api>:` prints can be gated in place, because every call site is post-parse. **Scope:** only the positive `Check <api>: Supported` lines and the `Supported backends:` aggregate are gated on `>= Info`; the `Not Supported` branches always print, at the maintainer's request, because a missing or failed backend is exactly what a `-v failure` user needs to see. **The CI contract held:** `common-test-setup/action.yml` greps `Supported backends: ` at the default `Info` level, so the output is byte-identical by default and "Common Test Setup" passed; an unconditional suppression would have silently broken CI backend detection ([#12177 close-out: verbosity fix merged; pre-parse timing + Not-Supported stays ungated](../learnings/1784683587359-12177-close-out-slang-test-verbosity-fix-merged-me.md)).

## Replay recording folders collide across parallel test-server processes (#12214)

The record-replay system names each recording folder with `ReplayContext::generateTimestampFolderName()` (`source/slang-record-replay/replay-context.cpp`), which is millisecond-precision with no process-unique component, and `setupRecordingMirror()` joins it to a shared base with a non-exclusive `Path::createDirectoryRecursive`. Two facets follow. **The observed CI flake:** every replay unit test shares the relative base `.slang-replays-test`, and `findLatestReplayFolder(baseDir)` sorts every directory under the base and returns the last one with no ownership filter. Under `slang-test -use-test-server -server-count N` another server process's newer folder can win, so `unit-test-replay-integration.cpp`'s `secondPath.endsWith(latest)` assertion fails intermittently (15 of 96 forced runs). **The latent production bug:** recorders that start in the same millisecond open the same `stream.bin`/`index.bin`, and `findLatestReplayFolder` also backs `ReplayContext::loadLatestReplay()` over the production `.slang-replays`, whose "latest folder = my recording" meaning is inherently single-writer. The fix has two halves at two layers: (A) collision-resistant names — append the existing `Process::getId()` (`source/core/slang-process.h`) and create atomically with retry (there is no `mkdtemp`/`O_EXCL` helper, but the plain-`mkdir` `Path::createDirectory` gives atomic EEXIST on the leaf); (B) a per-process test base `.slang-replays-test-<pid>` with cleanup. B alone fixes the CI flake and A alone does not, so the full fix is A+B. It is not a regression: the race dates to the initial replay system (#9925) ([replay recording folders collide under parallel test-server processes](../learnings/1784895262564-slang-replay-recording-folders-collide-under-paral.md)). An explicit `SLANG_RECORD_PATH` is used verbatim as the folder, so parallel writers to one path collide the same way; see [Test Instruments That Lie Quietly](slang-tooling-test-instruments.md).

## COMPARE_COMPUTE lanes: synthesized CUDA lanes and pointer inputs

**A `-cpu` COMPARE_COMPUTE test also runs a CUDA lane on a GPU host.** When CUDA is available, slang-test synthesizes a `<test>.1 syn (cuda)` lane from every `-cpu` COMPARE_COMPUTE(_EX) line, so the lane count grows on a GPU host (a gh-13412-style directory went from 36 to 46 lanes), and a test checked only on a CPU-only host (for example Windows `-api cpu`) can still fail on the Linux GPU CI runners. PR #13927 hit this: its `-cpu` NaN test put +inf in a `static const float[]`, and the synthesized lane failed NVRTC with "dynamic initialization is not supported for a __device__ variable"; the CUDA constant-expression rules are on [[wiki/concepts/slang-backends-cuda-cpp.md]]. Run a new `-cpu` test on a CUDA host (the L40S coworker containers) before calling it verified ([a -cpu test also runs a synthesized CUDA lane](../learnings/1792918374217-a-cpu-compare-compute-test-also-runs-a-synthesized.md); [render-test pointer fields](../learnings/1792958642303-render-test-pointer-fields-of-a-global-uniform-str.md)).

**Pointer fields of a global `uniform` struct are not bound by `new S{ubuffer…}`.** `//TEST_INPUT: set pointers = new Pointers{ ubuffer(...), ubuffer(...) }` on `uniform Pointers pointers;` (a struct of `float2*` fields at global scope) leaves the fields unbound. The CPU lane segfaults the test server twice ("crash caused by this input"), and the synthesized CUDA lane fails with CUDA_ERROR_MISALIGNED_ADDRESS. Declaring `ConstantBuffer<Pointers> cb;` with `set cb = new Pointers{...}` works, and the test can still pass `cb` to a function by value ([render-test pointer fields](../learnings/1792958642303-render-test-pointer-fields-of-a-global-uniform-str.md)). For a pointer stored inside a buffer, `data=[bufName ...]` embeds the 8-byte device address as two uint slots ([lower-buffer-element-type rewrites](../learnings/1792965326774-lower-buffer-element-type-rewrites-must-keep-the-r.md)).

**The vk and cuda lanes lay out a pointee differently.** A `uniform T*` filled with `ubuffer(data=[...])` is read with scalar layout on Vulkan (SPIR-V PhysicalStorageBuffer) and with natural alignment on CUDA. `struct Inner { bool b; float4 x[2]; }` puts `x` at offset 4 on vk and at 16 on cuda, so the same data gives `x[1].w` = 14 vs 17 (master 52e29ab43 too, so not a regression). Write pointee structs whose scalar and natural layouts agree (no `float4` after a 4-byte field) ([pointer data: vk scalar, cuda natural](../learnings/1792966623515-slang-test-pointer-data-on-vk-uses-scalar-offsets-.md)). A `-cuda` line is also no substitute for a vk line on a SPIR-V lowering bug: #13948 reproduced only on vk/spirv lines ([lower-buffer-element-type rewrites](../learnings/1792965326774-lower-buffer-element-type-rewrites-must-keep-the-r.md)).

## Putting harness and compiler internals under `slang-unit-test`

**slang-test internals are partially unit-testable.** An earlier rule held that `TestReporter` and `slang-test-main.cpp` compile only into the `slang-test` executable, so no `slang-unit-test` could cover the harness and every harness fix must be verified behaviorally ([harness false-green fixes: verify behaviorally](../learnings/1783013967417-slang-test-harness-false-green-fixes-verify-behavi.md)). That is overstated: `tools/CMakeLists.txt` already compiles `tools/slang-test/test-output-path-util.cpp` into the `slang-unit-test` module, with `unit-test-slang-test-output-path.cpp` and `unit-test-slang-test-optimization-options.cpp` as precedents. The current rule splits by shape. Stdout and reporting-flow behavior (parallel worker output, the test-server false-green cluster) still has no clean unit form, so verify it behaviorally. A harness internal with public fields and a plain-struct input, such as `TestReporter::init(const Options&)` with a default-constructible `Options`, can carry a `SLANG_UNIT_TEST`: add the `.cpp` to `slang-unit-test`'s `target_sources`, construct a non-default `Options`, call `init(options, /*isSubReporter*/ true)`, and assert the fields propagated. That is what PR #12180 shipped. So "the harness is monolithic" is not a blanket reason to skip a regression test on a config-propagation fix; check whether the specific unit is field-accessible and struct-driven first ([slang-test harness IS partially unit-testable](../learnings/1784664553168-slang-test-harness-is-partially-unit-testable-corr.md)).

**An unexported compiler free function: own TU, dual compile.** A unit test that calls an internal `namespace Slang` free function with no `SLANG_API` export will not link, because the `slang-unit-test` module links `libslang-compiler.so` with `-Wl,--no-undefined`; slang#12220 hit this for both `classifyCommandLineOption` and `writeCommandLineArgs`. Exporting the symbol is ABI-surface creep the maintainers avoid. Adding the whole owning `.cpp` to the test target is the sanctioned mechanism ([`not exported so a test can't link it` is false for slang-unit-test](../learnings/1785976052762-correction-not-exported-so-a-test-can-t-link-it-is.md); the impossibility-versus-cost framing lesson is on [Slang & slang-rhi test harness](slang-a-test-harness.md)), but only when that `.cpp` is light: `slang-compiler-options.cpp` pulls in `Profile::getName`, `capabilityNameToString`, and `TypeTextUtil`, all unexported, which cascade into their own undefined references. The established pattern, documented in `tools/CMakeLists.txt` beside `slang-repro-validator.cpp`, is to move the function into its own small translation unit that depends only on the types it needs. That TU joins the slang DLL automatically through the `slang_add_target(. ...)` glob in `source/slang/CMakeLists.txt`, and adding it to `slang-unit-test`'s `target_sources(... PRIVATE ...)` recompiles it into the test module too: one source, two binaries, no export and no cross-DLL call. Design the testable unit to be low-dependency from the start. Includes are not the limit — `slang-unit-test` has `INCLUDE_DIRECTORIES_PRIVATE ${slang_SOURCE_DIR}/source` and can `#include "slang/..."` ([unit-testing an unexported slang free function: own TU + dual compile](../learnings/1785203787876-unit-testing-an-internal-unexported-slang-free-fun.md)).

**Windows: the test DLL and slang.dll do not share an environment.** shader-slang/slang's Windows builds use `CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded[Debug]` (static CRT, `CMakePresets.json`), so each DLL has its own CRT environment table, copied when it loads. A `_putenv_s` or `ScopedEnvVar` inside `slang-unit-test-tool.dll` is invisible to `PlatformUtil::getEnvironmentVariable` in slang.dll, which reads with `_dupenv_s` (`slang-platform.cpp`). A unit test that sets, say, `SLANG_RECORD_LAYER` in-process therefore passes on Linux and macOS and fails on every Windows job. `SetEnvironmentVariableA` does not help: `_putenv_s` already updates the OS block, and slang.dll's table is a load-time copy. The fix pattern is to re-run the check in a child `slang-test <exact test name>` launched with the variable set and guarded by a sentinel env var, and to require the child's own `passed test: '<name>` line, since exit 0 alone is vacuous. Existing env-driven tests such as SPIR-V validation work only because CI exports the variable before launch (PR #12823; Microsoft's "potential errors passing CRT objects across DLL boundaries") ([Windows static CRT: a unit test can't set an env var that slang.dll reads](../learnings/1791936249295-windows-static-crt-a-unit-test-can-t-set-an-env-va.md)). The CI-exported `SLANG_RUN_SPIRV_VALIDATION=1` is itself an ambient difference between local and CI runs; see [Slang & slang-rhi test harness](slang-a-test-harness.md).
