## TL;DR

Deep-dive findings across the Slang frontend/IR/backend, most surfaced during triage or PR review:

- **Diagnostics** are now rich-diagnostic structs generated from `slang-diagnostics.lua` (`err(...)`/`warning(...)` with `span`/`loc`/typed `~field` tokens), invoked as brace-init `Diagnostics::Foo{.decl=...}` — not the old `sink->diagnose(loc, Diagnostics::Foo, args)`. `DisableWarning` treats an unknown **numeric** id as silently-ignored (intentional version-tolerance) but an unknown **name** as error E31111; a live severity-mismatch branch also errors even on a recognized id.
- **Type-system / conformance:** an assoc-type `where A.Member : IBar` constraint is definition-order-dependent (a deferred member-access constraint; principled fix is a per-interface fixpoint saturation pass). The #12659 witness-loss root cause was re-diagnosed by runtime trace to the `isComputing` empty-facet re-entry guard, NOT the `isBeingChecked` skip — a static read pinned a plausible-but-adjacent branch.
- **IR:** PR #12569 "fixed" a witness-table dedup collision by returning the GVN survivor, which drops a transforming forwarding entry → a landed silent miscompile (loud error → silent wrong answer). `IROpInfo` exposes only `name`/`fixedArgCount`/`flags`, dropping the rich per-operand schema in `slang-ir-insts.lua`, so arity/kind validation needs the generator extended first.
- **Emit/legalize:** out-param varying redirects need TWO guards (flavor==address AND pointee-type equality); a shared loader must fix at the site with guaranteed `(path,blob)` provenance; `PublicDecoration` can't be mechanically folded into export/HLSLExport (it's the sole `public`-visibility marker); `-cpu COMPARE_COMPUTE` defaults to CPP-host-callable (a real fast-path oracle), and a whole-object bitcast can be silently decomposed field-wise by `lowerBitCast`.
- **Language surface:** enum-case `ParseModifiers` swallows bareword modifier names (`point`, `linear`) — a source-breaking regression; `DescriptorKind` has zero C++/`include/` references so appending an atom is a core-module-API (not ABI) decision; a GLSL SPIRV-exemption narrows correctly only on the SIMPLIFIED-leaf atom set.
- **Platform:** Windows `_wstat64("NUL")` returns `_S_IFCHR`, so `File::exists`=true but `getPathType`=FAIL — verify CRT behavior against UCRT source, not MSDN prose.

## Diagnostics subsystem

Adding a diagnostic is a two-part codegen-backed process: define it in `slang-diagnostics.lua` with `err`/`warning` (the `loc` field names the struct member carrying the source location; `~field:Type` tokens become typed struct fields; kebab keys PascalCase into the C++ name with acronyms NOT preserved, e.g. `invalid-cuda-sm-version` → `InvalidCudaSmVersion`), then invoke as a brace-init `Diagnostics::MyDiag{.decl=varDecl}` — the location comes from the `loc` field, no separate location arg — and rebuild so fiddle regenerates the structs ([Slang diagnostics are rich-diagnostic structs generated from slang-diagnostics.lua](../learnings/1787194591603-slang-diagnostics-are-rich-diagnostic-structs-gene.md)). The `-Wno-<id>` disable path is asymmetric: an unknown **numeric** id is silently ignored (an explicit in-code comment calls this deliberate version-tolerance), while an unknown **name** errors as E31111 — the crux of issue #12661 ([DisableWarning: unknown numeric ids already silently ignored, unknown names error](../learnings/1787248265642-disablewarning-unknown-numeric-ids-already-silentl.md)). A third branch complicates any "ignore unknown" flag: when the id IS recognized but the passed `originalSeverity` mismatches the diagnostic's default, `overrideDiagnostic` still diagnoses E31111 and returns `SLANG_FAIL` — and this branch is LIVE for `-warnings-disable` (which passes `originalSeverity=Warning`), so a recognized non-Warning id hits the error path; an opt-in "ignore unknown" flag must gate ONLY the name-not-found branch ([overrideDiagnostic numeric-id silent-ignore has a live severity-mismatch error branch](../learnings/1787315204452-overridediagnostic-numeric-id-silent-ignore-has-a-.md)).

## Type-system, conformance, inheritance

An interface requirement `associatedtype A : IFoo<T> where A.Member : IBar` can spuriously fail conformance (E38105/E38029) with the result flipping when you swap the definition order of two conformers. Post-#11368 both bounds become sibling `GenericTypeConstraintDecl`s, but a multi-level member-access subject like `A.Member` is **deferred not force-resolved**, so the facet-introducing bound must be checked before the facet-consuming where-clause; the principled fix is a per-interface constraint-saturation fixpoint pass (a documented follow-up in #11368 §5.4) ([Slang assoc-type where-clause constraint is definition-order-dependent](../learnings/1787229323061-slang-assoc-type-where-clause-constraint-on-a-memb.md)). A closely related witness-loss bug (#12659) was mis-diagnosed by static read as the `isBeingChecked` skip; a runtime-instrumented Debug trace showed the actual mechanism is the `isComputing` in-progress re-entry guard returning an EMPTY seeded facet during interface header-checking — a process lesson that a static-read triage can pin a plausible-but-adjacent guard, and a runtime trace is what disambiguates re-entrancy bugs ([CORRECTION to slang #12659 root cause — isComputing empty-facet re-entry](../learnings/1787248653385-correction-to-slang-12659-root-cause-it-is-the-isc.md)).

## IR passes, dedup, and the operand schema

PR #12569 tried to fix a witness-table dedup collision (`IRInstKey::operator==` excludes witness-table entries from the dedup key) by having `cloneInst` return the GVN dedup survivor instead of grafting the generic's entry — but for a **transforming** forwarding extension the survivor is the WRONG table, so the fix turned a loud compile error into a SILENT wrong answer (emits 42 not 43), a landed correctness regression whose shipped regression test is non-transforming and passes vacuously ([PR #12569 fix picks GVN dedup survivor, drops transforming forwarding entry](../learnings/1787313119777-pr-12569-fix-picks-gvn-dedup-survivor-drops-transf.md)). On the validation side, `IROpInfo` drops most of the `slang-ir-insts.lua` operand schema: the generator emits only `name`, `fixedArgCount` (= total count including optionals, NOT a required-min), and `flags`, so an arity check false-positives on trailing optionals and a true min/max or operand-kind check requires extending the generator first — `validateIRModule` only checks SSA hygiene, never the schema, which is why arity mismatches survive validation ([IROpInfo drops most of the slang-ir-insts.lua operand schema](../learnings/1787329716091-iropinfo-drops-most-of-the-slang-ir-insts-lua-oper.md)).

## Emit, legalize, and lowering

Redirecting a partially-written `out` param's uses straight to the Output global (`legalizeEntryPointParameterForGLSL`) needs two non-obvious guards, each a real crash/miscompile: only dereference `globalOutputVal.irValue` when `flavor == address` (other flavors carry a null irValue → segfault), AND require `isTypeEqual(outputPtrType->getValueType(), valueType)` (a stage that reshapes its output yields an `Array<valueType>` pointee ≠ valueType, and `replaceUsesWith` does no type check) — plus exclude the `in out` borrow case ([slang out-param varying legalize: guard on flavor==address AND pointee-type equality](../learnings/1787247760690-slang-out-param-varying-legalize-guard-direct-outp.md)). When adding a file/dependency registration inside a shared loader/deserializer, fix at the site where `(path, blob)` provenance is guaranteed by construction — a shared deserializer is reached by callers (module-library loader, `loadModuleFromBlob`) whose path/blob pair is NOT the "this blob is the file at this path" relationship, and registering there poisons the content-digest freshness check ([A shared loader routine is reached by callers with different (path, blob) provenance](../learnings/1787260711213-a-shared-loader-routine-is-reached-by-callers-with.md)). `PublicDecoration` is the sole IR marker for the `public` visibility concept and cannot be mechanically folded into export/HLSLExport — all ~11 consumers OR Public with HLSLExport as an equivalent-but-broader signal, and once the op is gone no surviving IR signal distinguishes `public` from `internal`; removing it is a language-semantics decision, not a cleanup ([PublicDecoration cannot be mechanically folded into export/HLSLExport](../learnings/1787264954230-publicdecoration-cannot-be-mechanically-folded-int.md)). Finally, a `-cpu COMPARE_COMPUTE` test DOES exercise a `isCPUTarget && !isCPUTargetViaLLVM` fast path (the default `SLANG_EMIT_CPU_DEFAULT` compiles emitted C++ via the host compiler), making the CPU round-trip a genuine oracle — but note `SLANG_HOST_VM`/slangi also matches that predicate (no textual bitcast prelude), and a whole-object `kIROp_BitCast` can be silently decomposed field-wise by `lowerBitCast` if any unrelated bitcast set `requiredLoweringPassSet.bitcast` ([Slang -cpu COMPARE_COMPUTE default is CPP host-callable — a real fast-path oracle](../learnings/1787341661124-slang-cpu-compare-compute-default-is-cpp-host-call.md)).

## Parse, capability, and ABI surface

Adding `decl->modifiers = ParseModifiers(parser)` at the top of `parseEnumCaseDecl` is a source-breaking regression: `ParseModifiers` on an identifier token consumes a matched bareword, and many bareword modifier keywords (`point`, `line`, `linear`, `sample`, `centroid`, ...) are registered — because an enum case's name is the first identifier after the modifiers, `enum FilterMode { point, linear }` now has `point` eaten as `HLSLPointModifier` then errors E20001; the fix parses only `[...]` bracketed attributes ([Enum-case ParseModifiers swallows bareword-modifier case names](../learnings/1787344413642-enum-case-parsemodifiers-swallows-bareword-modifie.md)). On the ABI question for descriptors, `enum DescriptorKind` in `hlsl.meta.slang` has ZERO references in any C++ source or `include/` — it's compared only inside core-module Slang code — so appending an atom is a core-module-API (language-surface) decision, not a C++/COM-vtable ABI break; on the `spvDescriptorHeapEXT` path, `kind=Texture` is codegen-neutral for any non-sampler resource ([DescriptorKind is not C++-ABI-exposed — adding an atom is a core-module-API call](../learnings/1787309633712-descriptorkind-hlsl-meta-slang-is-not-c-abi-expose.md)). And narrowing the GLSL-target SPIRV exemption in `checkCapabilities()` (#12703/#11225): atom-closure tests all fail because a version alias's flattened closure CONTAINS extension atoms and a bare extension's closure includes its implied version — the only clean discriminator is the SIMPLIFIED leaf set (`newSetWithoutImpliedAtoms`), i.e. exempt iff the request's simplified spirv leaves contain an `isSpirvVersionAtom` ([Slang capability: version-vs-extension request needs SIMPLIFIED-leaf test](../learnings/1787548305717-slang-capability-version-vs-extension-request-need.md)).

## Platform CRT gotcha

On Windows, `File::exists("NUL")` returns true but `Path::getPathType("NUL")` returns `SLANG_FAIL` — both call `_wstat64`, but the modern UCRT (verified against source, contradicting MSDN's "file or a device" prose) opens `NUL` with `CreateFileW`, `GetFileType` returns `FILE_TYPE_CHAR` → `_S_IFCHR`, which is neither DIR nor REG. So a Windows `caseInsensitiveEquals("NUL")` null-device arm is load-bearing, not a mere safety net; verify CRT behavior against UCRT source when you can't run it locally ([Windows _wstat64/File::exists on NUL returns _S_IFCHR, not _S_IFREG](../learnings/1787277668063-windows-wstat64-file-exists-on-nul-returns-s-ifchr.md)).
