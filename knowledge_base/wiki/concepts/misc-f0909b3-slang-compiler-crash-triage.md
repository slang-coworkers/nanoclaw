# Slang Compiler Crash, Hang & Codegen Bug Triage

Localizing a slangc crash, hang or codegen bug without a debugger, and the recurring root-cause families found.

## TL;DR

- **A crash reproducing is not the reported defect reproducing.** A `slang-test -cpu` SIGSEGV can be a missing `//TEST_INPUT` binding; a negative control (strip the feature, same crash) exonerates the feature.
- **Localize a HANG by SIGPROF sampling, not the reporter's lead**; it is usually a fixpoint pass whose worklist isn't cleared.
- **A `slangi` segfault is often at bytecode-EMIT time** (real byte offsets), e.g. `FieldExtract` on a pointer base; textual emit hides it.
- **VM `Call` sizes args by callee param-slot stride, not operand `.size`** (a recorded source range); over-reads fire only when padding crosses a section edge.
- **`SLANG_ASSERT` is `_DEBUG`-only** (UB in release). A suggested "assert this invariant" is a probe: add it, run the suite. On Linux a Debug assert *throws* `InternalError` (E99997, no stack); `SLANG_ASSERT=system`/`debugbreak` are Windows-only.
- **Layout policy is coded twice** (AST `slang-type-layout.cpp`, IR `slang-ir-layout.cpp`, no shared code); fix and check both. Type-realization crashes fire only when the type is referenced.
- **E41035's must-init walk is path-insensitive** (`if (c) x = …; if (c) use(x);` warns) and runs before `extern static const` resolves, so folding cannot fix it; negative tests need a runtime condition.
- **An on-path `HashSet` cycle guard is exponential** on dense recursive-type graphs; probe with a complete pointer graph, memo finished nodes.
- **Verify pass ORDER before trusting "diagnostic X catches it first"** (loop-unroll runs before E38206).
- **ForceUnroll constant-folds the dead N+1 exit-test peel before removing dead blocks**, so a side-effecting fold misfires on code that never runs (`x / (N - i)` → `x / 0`, #13762).
- **No-gdb kit:** an `LD_PRELOAD` SIGSEGV shim or SIGPROF sampler capturing raw PCs (no `malloc`/`backtrace_symbols_fd` in a signal handler), a `__cxa_throw` hook for Debug asserts, offline `addr2line -f -C -i` at offset-1 on the matched `.dwarf`. Run Debug first for a release-only crash. A last `-dump-ir` header `AFTER checkUnsupportedInst` means emit; an earlier one does not name the failing pass, so trust the backtrace. For a wrong diagnostic, backtrace in a `fwrite`/`write` wrapper. Before any shim, `-no-codegen` (exit 0 → crash is after lowering) plus a `<null>` operand in the `LOWER-TO-IR` dump often names the cause.
- **Prove a prebuilt binary current with `find source include prelude -newer <lib>`**, not the version string. **A/B every traced crash on pristine master and a sibling form that skips the changed path.**

## Instrumentation kit (used by every crash below)

The fixer/reviewer container has **no gdb/lldb**; many atoms converged on this toolkit.

- **Two-minute localization, release binary, no symbols.** (1) Rerun with `-no-codegen`: exit 0 there plus a crash without it puts the crash after the checker (and, since `-no-codegen` still runs `generateIR()`, see below, in the IR passes or emit). (2) Rerun with `-dump-ir > x.ir`: the last `### AFTER <pass>` header shows how far it got, and a `<null>` operand in the `### LOWER-TO-IR` dump is usually the cause, even when the crash comes passes later. Diff against a close control that compiles. On v2026.21 a method call on the elements of an `expand IThing<each U>` pack segfaults slangc and slangi; its LOWER-TO-IR has `getTupleElement(%args, <null>)` (the expand index is missing), while an `each T : IThing` pack gets the index (see [[wiki/concepts/slang-language-variadic-packs-expand-and-each.md]]) [-no-codegen splits checker vs lowering; `<null>` operands are a lead](../learnings/1794213219752-slang-crash-triage-no-codegen-splits-checker-vs-lo.md).
- **SIGSEGV shim.** An `LD_PRELOAD` .so whose constructor installs a SIGSEGV/SIGBUS handler (`SA_SIGINFO|SA_ONSTACK`, `sigaltstack`) prints `si_addr`, `REG_RIP` and raw `backtrace()` PCs, each reduced with `dladdr()` to `(dli_fname, addr - dli_fbase)` [FieldExtract-on-pointer crash](../learnings/1786539532851-slangi-fieldextract-on-pointer-crashes-emit-vm-mak.md). Never call `backtrace_symbols_fd` (→ `malloc`) in a SIGPROF/SIGSEGV handler: interrupting an allocation aborts with a glibc malloc assertion. Resolve raw PCs offline against `/proc/<pid>/maps` [shader+export hang](../learnings/1786817508989-shader-export-imported-entry-point-with-params-han.md). `si_addr=0x38` (small nonzero) is a null-object *data* deref; `RIP=0x0`/empty backtrace is a call through a null fn-ptr [4-site bodyless crash class](../learnings/1786580792355-slang-pytorch-cpp-binding-pass-bodyless-kernel-dec.md).
- **Symbolize** with `addr2line -f -C -i -e build/<Cfg>/lib/libslang-compiler.so.0.<ver>.dwarf 0x<offset-1>`: offset-1 avoids bogus destructor frames, `-i` resolves inlining, and the `.dwarf` sidecar itself must be named (via the `.so` debuglink a Debug build printed `??:0`) [addr2line on the .dwarf sidecar (#10749)](../learnings/1792684568155-symbolize-slang-crashes-without-gdb-backtrace-hand.md). Match the sidecar to the *loaded* library; `head -1` on a glob gives `?? ??:0` [same](../learnings/1786580792355-slang-pytorch-cpp-binding-pass-bodyless-kernel-dec.md).
- **Debug asserts need a `__cxa_throw` hook, not a signal handler.** `handleAssert` (`source/core/slang-signal.cpp`) is `#if _WIN32`, so on Linux a Debug assert throws `InternalError` (`E99997 ... assert failure: slang-ir.h(861)`, no stack) whatever `SLANG_ASSERT` says. Interpose `__cxa_throw`: on the first throw print `backtrace()` (`backtrace_symbols_fd(..., 2)` is safe outside a signal), then forward to `dlsym(RTLD_NEXT, "__cxa_throw")` [SIGSEGV handler + __cxa_throw hook + addr2line](../learnings/1790693974366-getting-a-slang-crash-assert-backtrace-without-gdb.md) [__cxa_throw hook on Linux](../learnings/1790695170333-backtrace-a-slang-debug-slang-assert-on-linux-with.md). The ~10-line shim (`gcc -shared -fPIC -o hook.so hook.c -ldl`; `LD_PRELOAD=hook.so ./build/Debug/bin/slangc …`; `addr2line` on the `(+0xOFF)` offsets) also catches `SLANG_RELEASE_ASSERT`; copies in slang-triager's `scratch-14240/bt/` [backtrace a slangc InternalError with a __cxa_throw hook](../learnings/1793880831242-backtrace-a-slangc-internalerror-without-gdb-ld-pr.md).
- **SIGFPE**: the same preload with a SIGFPE handler (`backtrace()`, `backtrace_symbols_fd(b, n, 2)`, `_exit(99)`), ~2 minutes; on #13991 it put an int64-vector `INT64_MIN / -1` crash in spirv-opt's CCP, not Slang (see [[wiki/concepts/slang-language-core-integer-constant-folding.md]]) [Release slangc SIGFPE backtrace](../learnings/1793222408733-release-slangc-sigfpe-backtrace-without-gdb-ld-pre.md).
- **Wrong diagnostic, no crash**: wrap `write`/`fwrite`/`fputs` and `backtrace()` when the buffer holds the code (e.g. "E33180"); diagnostics print at diagnose time, so the stack is live. Resolve `addr - dli_fbase - 1` against the Release lib. That found E33180 on `[Differentiable]`/`no_diff T` generics called with a statically single-type existential: `as<IRElementOfSetType>` unwraps the `IRAttributedType` and drops `no_diff`; use `as<T, IRDynamicCastBehavior::NoUnwrap>` [backtrace-at-diagnostic shim](../learnings/1793683235612-debugging-slangc-without-gdb-backtrace-at-diagnost.md); see [[wiki/concepts/slang-autodiff-custom-derivatives-and-higher-order.md]].
- **Run Debug first for a release-only crash**: a compiled-out `SLANG_ASSERT` often names the `file:line` [ModifiedType type-layout crash](../learnings/1786650725225-modifiedtype-unorm-snorm-crashes-ast-side-type-lay.md). On #13320 Release showed a null deref in `getRootAddr`; Debug showed the first failure, `SLANG_ASSERT(diffVal)` at `slang-ir-autodiff-fwd.cpp:2098` [same](../learnings/1790693974366-getting-a-slang-crash-assert-backtrace-without-gdb.md). A Debug segfault right after `cast<IRFuncType>(x)` means `x` was null: `cast<>`'s `SLANG_ASSERT(!inst || as<T>(inst))` (`slang-ir.h:861`) passes null.

**Worked results**, each minutes from rc=139 to file:line: #13321, an unchecked `cast<IRFuncType>` at `slang-ir-typeflow-specialize.cpp:4795` [same](../learnings/1790695170333-backtrace-a-slang-debug-slang-assert-on-linux-with.md); #13817, a null callee func type in typeflow `analyzeCall` (:4831) [SIGSEGV backtrace (#13817)](../learnings/1792582829901-symbolized-sigsegv-backtrace-for-slangc-without-gd.md); #10749, a null `programLayout` in `buildExternTypeMap` (via `TargetRequest::getTypeLayout`), confirmed by a standalone C++-API repro (`-lslang-compiler -Wl,-rpath,…`) [same](../learnings/1792684568155-symbolize-slang-crashes-without-gdb-backtrace-hand.md); #14146, CUDA emit at `slang-emit-cpp.cpp:1615`, where `as<IRPtrTypeBase>` is null for the `ConstantBuffer` (`PointerLikeType`) base of a `GetElementPtr` (`ConstantBuffer<float3> sb; sb[1]`), placed in emit by a last `-dump-ir` header `AFTER checkUnsupportedInst` [segfault backtrace (#14146)](../learnings/1793566282072-backtrace-a-slangc-segfault-without-gdb-ld-preload.md); #14240, the opposite trap: "AFTER specializeModule" printed before an assert thrown INSIDE it, because typeflow (`specializeDynamicInsts`) transcribes autodiff derivatives on demand via `TranslationContext::resolveInst` from `analyzeCall`. Cause: `_getCalleeActualFuncType` (slang-ir-autodiff-fwd.cpp) calls 3-argument `maybeExpandConcreteFuncTypePacks`, which REWRITES the callee's type (`as<IRTypePack>` sees through `Attributed(…, no_diff)`), while call arguments are flattened only by `SpecializationContext` (`IRFunc` callee) or typeflow `expandPacksInFunc` (discovered contexts), so a primal differentiated before typeflow discovers it gets N+k params for N args [same (#14240)](../learnings/1793880831242-backtrace-a-slangc-internalerror-without-gdb-ld-pr.md); and #13433, `si_addr=0x10` at `SubtypeWitness::getSub()` inlined into `tryConstantFoldDeclRef` (`slang-check-expr.cpp:2841`), a null-witness read from `_validateCircularVarDefinition` self-folding an interface-requirement `static const` after E30623 (a `DirectDeclRef` has no `LookupDeclRef`, so `findThisTypeWitness` returns null), not from a reference to it: a decl's self-fold can take a different path than its uses [shim pins Release fault sites (#13433)](../learnings/1791310105655-no-gdb-in-container-an-ld-preload-sigsegv-cxa-thro.md).

**Hang and freshness gotchas.** In a hang, `-dump-ir`/`-dump-ir-before/after` emit **0 lines** (the buffered sink never flushes), so 0 lines is not a pass boundary, and `slangc -v` prints a stale configure-time version [shader+export hang](../learnings/1786817508989-shader-export-imported-entry-point-with-params-han.md); use `find source include prelude -newer build/Release/lib/libslang-compiler.so.*` [same](../learnings/1790693974366-getting-a-slang-crash-assert-backtrace-without-gdb.md). Shim copies: slang-triager's `scratch-p1a/segv-bt.c` + `throw-bt.c`, `/workspace/agent/scratch-p6/{throw.c,segv.c,bt.sh}`, `/workspace/agent/scratch-13433/shim.c`.

## Confound: the crash reproduces but the reported feature is innocent

The decisive move is a control that *isolates* the supposed cause. #12499 was filed as a `do/catch/throws` bug that "SIGSEGVs the CPU backend"; the repro exits 139, but a **negative control** (a bare buffer write, error handling stripped) crashes identically. The cause: a missing `//TEST_INPUT:ubuffer(...)` binding left the CPU launcher's root buffer null [slang-test -cpu SIGSEGV is a harness confound](../learnings/1786529531174-a-slang-test-cpu-sigsegv-is-a-harness-confound-unt.md). The reported defect does not reproduce, so do NOT apply `reproduced`: not-a-bug, with a one-line test fix. Indented or `#include`d `//TEST_INPUT:` lines abort slang-test on `-cuda` too (render-test runs in-process); see [[wiki/concepts/slang-test-harness-internals-and-unit-tests.md]].

The same discipline localized #12498, a `-target spirv-asm` infinite hang. The reporter pointed at `emitCastPtrToBool` (where they *found* the inst), but a SIGPROF sampler put 156/159 samples in `AddressSpaceContext::processModule`, and a plain `Node*` helper (no Optional) also hung. Root cause: `HashSet<IRFunc*> newWorkList` declared outside the `while` loop and never cleared, defeating the fixpoint's convergence [hang localized by SIGPROF sampling](../learnings/1786539248296-a-hang-localized-by-sigprof-sampling-not-by-the-re.md). Hang #12564 fires iff a precompiled `.slang-module` function is `[shader]` AND `export` AND has ≥1 parameter and is imported and re-emitted; a 9-cell matrix isolated it and refuted the "varying parameter" framing (uniform and no-semantic params hang too). Root cause **hedged**: the flat `IRInstListBase::Iterator` stack (shared across decorations/children/blocks/globals) fits a cyclic list, reorder churn or fixpoint re-processing [shader+export hang](../learnings/1786817508989-shader-export-imported-entry-point-with-params-han.md).

The same control applies to a *reviewer's* new-crash finding. In #13321's round-2 review, a code-traced null deref under `-disable-non-essential-validations` blamed on the patch's new witness entry crashed identically on pristine master and in the wrapper form that never reaches the entry, so it was pre-existing, and the suggested guard would have restored master's crash [run it on pristine master and in the sibling form](../learnings/1790702192345-before-accepting-a-code-traced-new-crash-finding-r.md). Drop extra repro features (custom `[ForwardDerivative]`, interfaces) one at a time (for #13321 none mattered) [drop repro features one at a time](../learnings/1790695170333-backtrace-a-slang-debug-slang-assert-on-linux-with.md). When a known crash shares the frame, restate the candidate: any `bwd_diff(fwd_diff(...))` repro lands on #13321's `:4795` cast, so re-test as `fwd_diff(fwd_diff(g))` beside a plain-`g` Debug control [isolate a higher-order repro from #13321](../learnings/1790704234870-a-higher-order-autodiff-crash-repro-can-be-confoun.md).

## slangi bytecode-VM crashes: emit-time, and the Call slot-size contract

#12495 (`Optional<A> o = b as A;`) SEGVs at bytecode *emit*: `visitMakeOptionalExpr` packed the payload with `val.val`, and a base-subobject upcast lowers to a `Ptr`-flavored l-value, so a raw pointer became the payload and reached `emitFieldExtract` on a pointer base. Fix at the r-value consumer: `val.val` → `getSimpleVal(context, val)` [FieldExtract-on-pointer crash](../learnings/1786539532851-slangi-fieldextract-on-pointer-crashes-emit-vm-mak.md). #12496 is distinct: VM `Call` reads each argument sized by the **callee's parameter-slot stride** (padded), not the operand's `.size`, unlike `Print`/`CallExt`. It is layout-dependent (`x*x` aborts, `x+x` runs) because over-read padding is inert unless it crosses a working-set section edge; `slangi -disasm` is a rebuild-free counterfactual [VM Call over-reads by callee param-slot stride](../learnings/1786539124882-slangi-vm-call-opcode-over-reads-args-by-callee-pa.md).

Three reviewers of the #12496 fix suggested `SLANG_ASSERT(size <= slotStride)`. Added as a **probe**, it SIGABRT'd on an existing passing test (`size=12 into an 8-byte slot`): a VM operand's `.size` is a *recorded source range* (`FieldExtract` advances `.offset` without narrowing `.size`) [a SLANG_ASSERT is a probe](../learnings/1786559479043-a-slang-assert-is-a-probe-it-can-falsify-a-plausib.md). Corrected mechanism: `SLANG_ASSERT` is `#ifdef _DEBUG` only (release turns the false condition into `SLANG_ASSUME`→UB), and this container's `debug` preset builds `CMAKE_BUILD_TYPE=Release`, so check which build you run [correction: debug-abort + release-UB](../learnings/1786561343746-correction-the-probed-slang-assert-was-debug-abort.md). Use `SLANG_RELEASE_ASSERT`/`SLANG_UNEXPECTED` for release invariants.

## Front-end error state, pass ordering, and use-before-init false positives

`-no-codegen` only sets `SkipCodeGen`; it does NOT skip `generateIR()`, and the `getErrorCount()` gate runs after it, so a *silent* front-end `ErrorType` (error count 0) hits `UNEXPECTED_CASE(ErrorType)` in lowering: a symptom of a missing upstream diagnostic, and tolerating ErrorType there is a mask [-no-codegen still runs generateIR](../learnings/1786573554629-no-codegen-still-runs-generateir-so-a-silent-front.md). On #12548 a PR omitted a loop guard claiming E38206 catches an over-wide vector first, but `specializeModule`/`unrollLoopsInModule` run *before* `validateVectorsAndMatrices` (`slang-emit.cpp`). The guard is unneeded anyway: the unroller succeeds for any constant bound below `kMaxIterationsToAttempt=4096`, and generics are specialized to a literal first [loop-unroll runs before E38206](../learnings/1786742313260-slang-specialization-loop-unroll-runs-before-e3820.md).

Inside the unroller, `_unrollLoop` (`slang-ir-loop-unroll.cpp`) clones one extra peel to prove the exit test false, and `_foldAndSimplifyLoopIteration` (:113-191) runs `tryConstantFoldInst` on every cloned inst *before* folding branches and `_eliminateDeadBlocks`. The dead N+1 peel is folded with `i == N`, so `for (int i = 0; i < N; i++) y += x / (N - i);` computes `x / 0` there, and because `tryConstantFoldInst` (`slang-ir-sccp.cpp:2008`) never set `SharedSCCPContext::sink` (uninitialized from #2911 until PR #13769), that fold dereferenced garbage (#13762). A real /0 on an executed step is still E30002 (module SCCP skips not-taken constant branches). In a new worktree `submodule update --reference /workspace/agent/slang` fails (shallow clone); use `git -c protocol.file.allow=always submodule update --init --recursive` (configure + Release slangc+slang-test ≈8 min on 64 cores) [ForceUnroll folds the dead N+1 exit-test peel](../learnings/1792502273587-forceunroll-folds-the-dead-n-1-exit-test-peel-via-.md).

E41035 "may be uninitialized" comes from `cancelLoadsByDefiniteAssignment` (`slang-ir-use-uninitialized-values.cpp`), a must-init walk over CFG edges with store blocks as barriers, otherwise **path-insensitive** (its only pruning: the short-circuit constant-phi case `getInfeasibleBranchFromPredecessor`, plus loop-exit and `WaveIsFirstLane` relaxations). So `if (c) x = ...; if (c) use(x);` warns for a runtime `c` (#13420). Folding cannot fix it: the check runs per module (`slang-lower-to-ir.cpp` ~16262), before linking resolves `extern static const`, so even `static const bool E = true` stays `ifElse(%E = globalConstant(true))`; only literal `if (true)` folds. A prototype tracking known-true/false bits for conditions tested by ≥2 `ifElse` terminators (reset at the condition's defining block, looking through `not`) fixed it without regressions. Workaround: initialize at declaration, or store and read in one `if`. Negative tests need a runtime condition (constant-`E` `if (E) store; if (!E) read;` has an unreachable read) [E41035 must-init walk is path-insensitive](../learnings/1790993123820-e41035-must-init-walk-is-path-insensitive-same-con.md).

The `WaveIsFirstLane` relaxation comes from #12545, a false positive on a `WaveIsFirstLane()`-guarded out-param store. The wave op is **essential**: with a plain read the warning is true (a non-first lane never took the `if`), so the fix keys on the `WaveIsFirstLane`-guard ↔ `WaveReadLaneFirst`-read correlation. A *direct* conditional store is clean only because SSA promotion + SCCP fold the evidence away; an out-param's address escapes, so it stays a memory var [E41035 must-init false positive](../learnings/1786747082828-e41035-must-init-false-positive-on-waveisfirstlane.md).

The same file's `canIgnoreType` shows a termination trap. #13416 replaces unbounded recursion over mutually recursive pointer structs with an on-path `HashSet` (add before recursing, remove after), which terminates but enumerates every simple path: K mutually-pointing structs take ≤0.5 s for K≤10, 2.3 s at K=11, 25 s at K=12. Probe with a complete pointer graph (`struct Si { float v; Sj* pj; ... }` for all j≠i, plus a local `S1 s;`), timed against the file without the local. For a path-independent answer ("is this struct ignorable"), a memo of finished nodes beside the in-progress set makes the walk linear. It is a nit when those inputs used to crash [path-set cycle guards can be exponential](../learnings/1790981687370-path-set-cycle-guards-in-recursive-type-walks-can-.md).

## Codegen bugs: legalization, dedup scope, and destructive overrides

Three codegen atoms share a "the fix is upstream" flavor. The CUDA `RWByteAddressBuffer`-param regression (#9824) was legalization leaving the *original* param behind after partially replacing its uses; the fix (#9742) removes unused byte-address types. `RWStructuredBuffer<uint>` in CUDA output is a bug only as a **parameter**; a body-local `x.asStructuredBuffer<uint>()` temporary is correct for atomics [CUDA RWByteAddressBuffer regression](../learnings/1786633506187-cuda-rwbyteaddressbuffer-param-regression-9824-was.md). #12532 (OptiX `inout` payload read twice) came from a dedup guard keyed on the **entry-point-global** `m_payloadWritebacks` count: with two payloads in one entry point, the second saw a non-zero count and dropped its store. The fix keys on identity (`hasRegisteredPayloadWriteback(info.type)`): scope "has X happened?" to the object, not a running count [dedup guard keyed on global counter](../learnings/1786663782456-a-dedup-guard-keyed-on-an-entry-point-global-count.md). #12462 (render-test blanks the HLSL prelude only in the non-NVAPI `else` branch) is a silent carry-forward: a 2020 reset-to-empty, from before any HLSL prelude existed, that the prelude-adding PR never revisited [render-test blanks HLSL prelude](../learnings/1786670359057-render-test-blanks-hlsl-prelude-only-in-the-non-nv.md).

The **two-parallel-layout-paths** hazard recurs in #12535: `unorm`/`snorm` (a `ModifiedType`) crashes AST-side `_createTypeLayout` (no `ModifiedType` case → catch-all assert/UB), while IR-side `slang-ir-layout.cpp` handles it (`ModifiedType` lowers to `IRAttributedType`). Check both files; the fix mirrors the transparent-unwrap precedents in the same function [ModifiedType type-layout crash](../learnings/1786650725225-modifiedtype-unorm-snorm-crashes-ast-side-type-lay.md). (The approver-side companion, checking `getSimpleVaryingParameterTypeLayout` too, is on the challenger page.)
