## TL;DR

- **A crash reproducing is not the reported defect reproducing.** A `slang-test -cpu` SIGSEGV can be a missing `//TEST_INPUT` binding (null root buffer), not the feature under test — the negative control (strip the feature, same crash) exonerates it in one step.
- **For a HANG, localize by SAMPLING, not by the reporter's found-inst lead.** A SIGPROF sampler + `addr2line` beats reading the reporter's browsing pointer; the loop is usually a fixpoint pass whose worklist/round-set isn't cleared, not where the inst was first noticed.
- **A `slangi` segfault is often at bytecode-EMIT time, not VM execution** — the emitter computes real byte offsets, so a malformed IR inst (e.g. `FieldExtract` on a pointer base) crashes there. HLSL/textual emit is tolerant and hides it.
- **VM `Call` sizes args by the callee param-slot stride, not operand `.size`** — an over-read fires only when padding lands at a section edge, so the bug is layout-dependent, not "on every call." A VM operand's `.size` is a recorded source range, not the natural size.
- **`SLANG_ASSERT` is `_DEBUG`-only** (→ `SLANG_ASSUME`/UB in release). A reviewer-suggested "assert this invariant" is a probe: add it, run the suite — an abort refutes the "impossible" claim. Don't call an assert firing a "release" behavior.
- **Layout policy is coded twice** (AST-side `slang-type-layout.cpp` reflection vs IR-side `slang-ir-layout.cpp`) with zero shared code — a fix on one path does NOT cover the other. Type-realization crashes only fire when the type is *referenced*.
- **Verify pass ORDER before trusting "diagnostic X catches it first"** — specialization/loop-unroll runs before E38206 vector-count validation, inverting a common "the width check preempts the unroll" claim.
- Instrument kit for a no-gdb container: `LD_PRELOAD` `SA_SIGINFO` SIGSEGV shim / SIGPROF sampler with **raw-PC capture** (never `malloc`/`backtrace_symbols_fd` in the handler), offline `addr2line` against the matched `.dwarf`; run the **Debug** binary first for a release-only crash (a compiled-in assert names the site).

## Instrumentation kit (recurs across every crash below)

The Slang fixer/reviewer container has **no gdb/lldb**, so several atoms independently converged on the same toolkit. Localize a SIGSEGV with an `LD_PRELOAD` `SA_SIGINFO` shim that captures `si_addr` + a backtrace, then resolve offsets with `addr2line` against the Debug shared library [FieldExtract-on-pointer crash](../learnings/1786539532851-slangi-fieldextract-on-pointer-crashes-emit-vm-mak.md). `si_addr=0x38` (a small nonzero offset) reads as a null-object *data* deref; `RIP=0x0`/empty backtrace is a call-through-null-fn-ptr — different bugs [4-site bodyless crash class instrument note](../learnings/1786580792355-slang-pytorch-cpp-binding-pass-bodyless-kernel-dec.md). Two hard-won gotchas: match the `.dwarf` sidecar to the *loaded* library by name (never `head -1` a glob, or every frame resolves to `?? ??:0`) [same](../learnings/1786580792355-slang-pytorch-cpp-binding-pass-bodyless-kernel-dec.md); and a SIGPROF/SIGSEGV handler that calls `backtrace_symbols_fd` (→ `malloc`) will itself abort the target with a glibc malloc-assertion when it interrupts an allocation — capture raw PCs in the handler and resolve offline against `/proc/<pid>/maps` [shader+export hang](../learnings/1786817508989-shader-export-imported-entry-point-with-params-han.md). For a **release-only** crash where a Debug binary exists, run the Debug binary FIRST: a compiled-out `SLANG_ASSERT` often names the exact `file:line` in one shot, far cheaper than resolving a release backtrace [ModifiedType type-layout crash](../learnings/1786650725225-modifiedtype-unorm-snorm-crashes-ast-side-type-lay.md). For a hang, `-dump-ir`/`-dump-ir-before/after` emit **0 lines** (buffered diagnostic sink never flushes) — 0 lines is not a pass boundary; and `slangc -v` prints a stale configure-time version string, so prove binary freshness *behaviorally* [shader+export hang](../learnings/1786817508989-shader-export-imported-entry-point-with-params-han.md).

## Confound: the crash reproduces but the reported feature is innocent

The decisive move on a crash report is a control that *isolates* the supposed cause. shader-slang/slang#12499 was filed as a `do/catch/throws` compiler bug that "SIGSEGVs the CPU backend"; the repro genuinely reproduces exit 139, but a **negative control** — a bare buffer write with all error-handling stripped — crashes identically, proving the crash is content-independent and the feature is exonerated. The true cause was a missing `//TEST_INPUT:ubuffer(...)` binding leaving the CPU launcher's root buffer null [slang-test -cpu SIGSEGV is a harness confound](../learnings/1786529531174-a-slang-test-cpu-sigsegv-is-a-harness-confound-unt.md). Label discipline: the crash reproduces but the *reported defect* does not, so do NOT apply `reproduced` (it implies a confirmed compiler bug) — verdict is not-a-bug/invalid, fix is a one-line test edit.

The same "isolate the supposed cause" discipline localized shader-slang/slang#12498, a `slangc -target spirv-asm` infinite hang. The reporter's lead pointed at `emitCastPtrToBool` (where they *found* the inst while browsing coverage), but a SIGPROF sampler put 156/159 samples in `AddressSpaceContext::processModule`, a totally different pass; a plain `Node*`-returning helper (no Optional, no `none`) *also* hung, killing the CastPtrToBool hypothesis independently of the profile. Root cause: `HashSet<IRFunc*> newWorkList` declared *outside* the `while` loop and never cleared, defeating the monotonic-convergence guarantee DeepWiki confirmed the fixpoint relies on [hang localized by SIGPROF sampling](../learnings/1786539248296-a-hang-localized-by-sigprof-sampling-not-by-the-re.md). A second target-independent hang, shader-slang/slang#12564, fires iff a precompiled `.slang-module` function is `[shader]` AND `export` AND has ≥1 parameter and is imported+re-emitted; a retained 9-cell matrix (each its own module rebuild) isolated the trigger and refuted the "varying parameter" framing (uniform and no-semantic params both hang — it's parameter *count* ≥1). The atom is careful to **hedge the root cause**: the flat `IRInstListBase::Iterator` stack fits a cyclic list OR a live-list-reorder churn OR a fixpoint re-processing, and that iterator is shared across decorations/children/blocks/globals, so the stack does not prove a specific walk [shader+export hang](../learnings/1786817508989-shader-export-imported-entry-point-with-params-han.md).

## slangi bytecode-VM crashes: emit-time, and the Call slot-size contract

Two atoms pin `slangi` crashes to bytecode *emit*, not VM execution. shader-slang/slang#12495 (`Optional<A> o = b as A;`) SEGVs because `visitMakeOptionalExpr` packed the payload with `val.val` directly; a base-subobject upcast lowers to a `Ptr`-flavored l-value, so a raw pointer became the Optional payload and reached `emitFieldExtract` on a pointer base → null deref in layout. Fix at the r-value consumer: `val.val` → `getSimpleVal(context, val)` [FieldExtract-on-pointer crash](../learnings/1786539532851-slangi-fieldextract-on-pointer-crashes-emit-vm-mak.md). shader-slang/slang#12496 is a distinct VM bug: the `Call` opcode reads each argument sized by the **callee's parameter-slot stride** (padded), not the operand's own `.size` — an outlier vs `Print`/`CallExt`. The crash is layout-dependent: `x*x` aborts but `x+x` runs correctly (the over-read bytes are inert alignment padding the callee never reads), faulting only when padding crosses a working-set section edge [VM Call over-reads by callee param-slot stride](../learnings/1786539124882-slangi-vm-call-opcode-over-reads-args-by-callee-pa.md).

The fix for #12496 exposed a subtle assertion lesson. Three reviewers suggested `SLANG_ASSERT(size <= slotStride)` on the theory that a well-typed operand can never exceed its slot. Adding the assert as a **probe** SIGABRT'd on an existing passing test at `size=12 into an 8-byte slot`, proving the "impossible" claim false — a VM operand's `.size` is a *recorded source range* (`FieldExtract` advances `.offset` without narrowing `.size`), not the natural size [a SLANG_ASSERT is a probe](../learnings/1786559479043-a-slang-assert-is-a-probe-it-can-falsify-a-plausib.md). A follow-up **corrected the mechanism**: `SLANG_ASSERT` is `#ifdef _DEBUG` only, so the abort was a debug-build event; in release the same false condition expands to `SLANG_ASSUME`→UB, not an abort. So the suggested assert was doubly wrong (debug abort + release UB), and — critically — this container's `debug` CMake preset builds `CMAKE_BUILD_TYPE=Release`, so an added `SLANG_ASSERT` won't even fire from that preset; verify which build you're running before concluding an assert does/doesn't fire [correction: debug-abort + release-UB](../learnings/1786561343746-correction-the-probed-slang-assert-was-debug-abort.md). Use `SLANG_RELEASE_ASSERT`/`SLANG_UNEXPECTED` when an invariant must hold in release.

## Front-end error state, pass ordering, and use-before-init false positives

`-no-codegen` only sets `SkipCodeGen`; it does NOT skip `generateIR()`, and the `getErrorCount()` gate is checked *after* generateIR. So a *silent* front-end `ErrorType` (error count stays 0) reaches lowering and hits `UNEXPECTED_CASE(ErrorType)` — the lowering abort is a symptom; the real defect is the missing diagnostic upstream, and a lowering-side tolerate-ErrorType change is a mask to reject [-no-codegen still runs generateIR](../learnings/1786573554629-no-codegen-still-runs-generateir-so-a-silent-front.md). Pass order is load-bearing elsewhere: on shader-slang/slang#12548 a PR justified omitting a loop guard by claiming E38206 vector-count validation catches an over-wide vector before the unroller — but `specializeModule`/`unrollLoopsInModule` runs *before* `validateVectorsAndMatrices` in `slang-emit.cpp`, so the ordering is inverted (the guard is still unneeded, but for a different reason: the unroller succeeds for any constant bound below `kMaxIterationsToAttempt=4096` and generics are specialized to a literal first) [loop-unroll runs before E38206](../learnings/1786742313260-slang-specialization-loop-unroll-runs-before-e3820.md).

shader-slang/slang#12545's E41035 "may be uninitialized" false positive on a `WaveIsFirstLane()`-guarded out-param store turns on a non-obvious fact: the wave op is **essential, not a red herring** — with a plain read the same warning is a genuine true positive (a non-first-active lane never took the `if`), so a fix must key on the specific `WaveIsFirstLane`-guard ↔ `WaveReadLaneFirst`-read correlation, not "any wave read." A *direct* conditional store is clean only because SSA promotion + SCCP fold the evidence away before the uninit check; an out-param store's address escapes, so it stays a memory var and is analyzed [E41035 must-init false positive](../learnings/1786747082828-e41035-must-init-false-positive-on-waveisfirstlane.md).

## Codegen bugs: legalization, dedup scope, and destructive overrides

Three codegen atoms share a "the fix is upstream, not in emit" flavor. The CUDA `RWByteAddressBuffer`-param regression (#9824) was a legalization pass leaving the *original* param behind after partially replacing its uses; the fix (#9742) explicitly removes unused byte-address types, not a target flag. Distinguishing trap: `RWStructuredBuffer<uint>` in CUDA output is only a bug when it is a **parameter** — a body-local `x.asStructuredBuffer<uint>()` temporary is the correct legalization for atomics [CUDA RWByteAddressBuffer regression](../learnings/1786633506187-cuda-rwbyteaddressbuffer-param-regression-9824-was.md). shader-slang/slang#12532 (OptiX `inout` ray payload read twice) came from a dedup guard keyed on the **entry-point-global** `m_payloadWritebacks` count; a single entry point can legally carry two payloads, so a second distinct payload saw a non-zero count from the first and silently dropped its own store — the fix keys the skip on object identity (`hasRegisteredPayloadWriteback(info.type)`), and the general rule is to scope a "has X already happened?" predicate to the object, not a bare accumulating count [dedup guard keyed on global counter drops work](../learnings/1786663782456-a-dedup-guard-keyed-on-an-entry-point-global-count.md). shader-slang/slang#12462 (render-test blanks the HLSL prelude only in the non-NVAPI `else` branch) is a silent carry-forward: the `else`-blank was a genuine reset-to-empty in 2020 when no HLSL prelude file existed; a later PR added the prelude without touching render-test, leaving a now-destructive override [render-test blanks HLSL prelude](../learnings/1786670359057-render-test-blanks-hlsl-prelude-only-in-the-non-nv.md).

The **two-parallel-layout-paths** hazard recurs sharply in shader-slang/slang#12535: `unorm`/`snorm` (a `ModifiedType`) crashes the AST-side `_createTypeLayout` (no `ModifiedType` case → catch-all assert/UB), while the IR-side `slang-ir-layout.cpp` already handles it transparently (`ModifiedType` lowers to `IRAttributedType`). The two layout paths share zero code, so a triager must check both `slang-ir-layout.cpp` and `slang-type-layout.cpp` independently; the fix mirrors the existing transparent-unwrap precedents in the same function [ModifiedType type-layout crash](../learnings/1786650725225-modifiedtype-unorm-snorm-crashes-ast-side-type-lay.md). (The approver-side companion — that a fix to one layout function must be checked against `getSimpleVaryingParameterTypeLayout` too — lives on the challenger page.)
