# Slang Compiler Crash, Hang & Codegen Bug Triage

How to localize a slangc crash, hang or codegen bug in a container without a debugger, and the recurring root-cause families those triages found.

## TL;DR

- **A crash reproducing is not the reported defect reproducing.** A `slang-test -cpu` SIGSEGV can be a missing `//TEST_INPUT` binding (null root buffer), not the feature under test — the negative control (strip the feature, same crash) exonerates it in one step.
- **For a HANG, localize by SAMPLING, not by the reporter's found-inst lead.** A SIGPROF sampler + `addr2line` beats the reporter's browsing pointer; the loop is usually a fixpoint pass whose worklist/round-set isn't cleared.
- **A `slangi` segfault is often at bytecode-EMIT time, not VM execution** — the emitter computes real byte offsets, so a malformed IR inst (e.g. `FieldExtract` on a pointer base) crashes there. HLSL/textual emit is tolerant and hides it.
- **VM `Call` sizes args by the callee param-slot stride, not operand `.size`** — an over-read fires only when padding lands at a section edge, so the bug is layout-dependent. A VM operand's `.size` is a recorded source range, not the natural size.
- **`SLANG_ASSERT` is `_DEBUG`-only** (→ `SLANG_ASSUME`/UB in release). A reviewer-suggested "assert this invariant" is a probe: add it, run the suite — a firing assert refutes the "impossible" claim. On Linux a Debug assert *throws* `InternalError` (`E99997 ... assert failure: <file>(<line>)`, no stack); `SLANG_ASSERT=system`/`debugbreak` are Windows-only.
- **Layout policy is coded twice** (AST-side `slang-type-layout.cpp` vs IR-side `slang-ir-layout.cpp`) with zero shared code — a fix on one path does NOT cover the other. Type-realization crashes only fire when the type is *referenced*.
- **E41035's must-init walk is path-insensitive**: a same-condition `if (c) x = …; if (c) use(x);` pair warns. The check runs per module, before `extern static const` resolves, so constant folding cannot fix it; negative tests need a runtime condition.
- **An on-path `HashSet` cycle guard terminates but is exponential** on dense recursive-type graphs. Probe it with a complete pointer graph; memo finished nodes when the result is path-independent.
- **Verify pass ORDER before trusting "diagnostic X catches it first"** — specialization/loop-unroll runs before E38206 vector-count validation.
- **ForceUnroll constant-folds the dead N+1 exit-test peel before it removes dead blocks**, so any side-effecting fold misfires on code that never runs (`x / (N - i)` becomes `x / 0`; #13762's segfault). Suspect this ordering first for an unroll crash or a false diagnostic.
- Instrument kit for a no-gdb container: `LD_PRELOAD` `SA_SIGINFO` SIGSEGV shim / SIGPROF sampler with **raw-PC capture** (never `malloc`/`backtrace_symbols_fd` in a signal handler), plus an `LD_PRELOAD` **`__cxa_throw` hook** that prints `backtrace()` for a Debug assert; offline `addr2line -f -C -i` at **offset-1** against the matched `.dwarf` sidecar itself. Run the **Debug** binary first for a release-only crash. A last `-dump-ir` header of `AFTER checkUnsupportedInst` puts a crash in emit, not a pass, but an earlier last header does not name the failing pass (typeflow transcribes derivatives inside `specializeModule`); trust the backtrace. For a wrong diagnostic, wrap `fwrite`/`write` and backtrace when the code is printed.
- **Prove a prebuilt binary is current with `find source include prelude -newer <lib>`**, not the version string. **A/B every traced crash on pristine master and in a sibling form that skips the changed path** before counting it against a patch.

## Instrumentation kit (recurs across every crash below)

The Slang fixer/reviewer container has **no gdb/lldb**, and many atoms independently converged on one toolkit.

- **SIGSEGV shim.** An `LD_PRELOAD` .so whose constructor installs a SIGSEGV/SIGBUS handler (`SA_SIGINFO|SA_ONSTACK` on a `sigaltstack`) prints `si_addr`, `uc_mcontext.gregs[REG_RIP]` and raw `backtrace()` PCs, reducing each frame with `dladdr()` to `(dli_fname, addr - dli_fbase)` [FieldExtract-on-pointer crash](../learnings/1786539532851-slangi-fieldextract-on-pointer-crashes-emit-vm-mak.md). Never call `backtrace_symbols_fd` (→ `malloc`) inside a SIGPROF/SIGSEGV handler: when it interrupts an allocation, the target aborts with a glibc malloc assertion — capture raw PCs and resolve offline against `/proc/<pid>/maps` [shader+export hang](../learnings/1786817508989-shader-export-imported-entry-point-with-params-han.md). `si_addr=0x38` (small nonzero offset) is a null-object *data* deref; `RIP=0x0`/empty backtrace is a call through a null fn-ptr — different bugs [4-site bodyless crash class](../learnings/1786580792355-slang-pytorch-cpp-binding-pass-bodyless-kernel-dec.md).
- **Symbolize** with `addr2line -f -C -i -e build/<Cfg>/lib/libslang-compiler.so.0.<ver>.dwarf 0x<offset-1>`. Subtracting 1 from return addresses stops misattribution (unadjusted Release offsets show bogus destructor frames); `-i` resolves inlined frames. Point at the `.dwarf` sidecar itself: via the `.so`'s debuglink a later Debug build printed only `??:0` [addr2line on the .dwarf sidecar (#10749)](../learnings/1792684568155-symbolize-slang-crashes-without-gdb-backtrace-hand.md). Match the sidecar to the *loaded* library by name — `head -1` on a glob makes every frame `?? ??:0` [same](../learnings/1786580792355-slang-pytorch-cpp-binding-pass-bodyless-kernel-dec.md).
- **Debug asserts need a `__cxa_throw` hook, not a signal handler.** On Linux `SLANG_ASSERT=system`/`debugbreak` are Windows-only (`handleAssert` in `source/core/slang-signal.cpp` is `#if _WIN32`), so a Debug assert throws `InternalError` and prints `E99997 ... assert failure: slang-ir.h(861)` with no stack; setting `SLANG_ASSERT=system` does not make it abort. Interpose `__cxa_throw`: on the first throw print `backtrace()` (`backtrace_symbols_fd(..., 2)` is safe in this non-signal context), then forward to `dlsym(RTLD_NEXT, "__cxa_throw")` [SIGSEGV handler + __cxa_throw hook + addr2line](../learnings/1790693974366-getting-a-slang-crash-assert-backtrace-without-gdb.md) [__cxa_throw hook on Linux](../learnings/1790695170333-backtrace-a-slang-debug-slang-assert-on-linux-with.md). The same ~10-line shim catches a `SLANG_RELEASE_ASSERT` / E99997 `InternalError`: `gcc -shared -fPIC -o hook.so hook.c -ldl`, `LD_PRELOAD=hook.so ./build/Debug/bin/slangc …`, then `addr2line -f -C -i -e build/Debug/lib/libslang-compiler.so.<ver> 0xOFF` on the `(+0xOFF)` offsets; copies are in slang-triager's `/workspace/agent/scratch-14240/bt/` [backtrace a slangc InternalError with a __cxa_throw hook](../learnings/1793880831242-backtrace-a-slangc-internalerror-without-gdb-ld-pr.md).
- **SIGFPE**: the same preload (`gcc -shared -fPIC -o /tmp/fpebt.so fpebt.c`) with a SIGFPE handler calling `backtrace()`, `backtrace_symbols_fd(b, n, 2)` and `_exit(99)` takes about 2 minutes. On #13991 it put an int64-vector `INT64_MIN / -1` crash in spirv-opt's CCP pass, not Slang (see [[wiki/concepts/slang-language-core-integer-constant-folding.md]]) [Release slangc SIGFPE backtrace](../learnings/1793222408733-release-slangc-sigfpe-backtrace-without-gdb-ld-pre.md).
- **Wrong diagnostic, no crash**: wrap `write`/`fwrite`/`fputs` and call `backtrace()` when the buffer contains the code (e.g. "E33180"); diagnostics print at diagnose time, so the stack is live. Log `addr - dli_fbase - 1` and resolve against the Release lib (it has `.symtab` and a `.dwarf` debuglink). That found E33180 on `[Differentiable]`/`no_diff T` generics called with a statically single-type existential: `as<IRElementOfSetType>` unwraps the `IRAttributedType` and drops `no_diff`, so use `as<T, IRDynamicCastBehavior::NoUnwrap>` [backtrace-at-diagnostic shim](../learnings/1793683235612-debugging-slangc-without-gdb-backtrace-at-diagnost.md); autodiff detail on [[wiki/concepts/slang-autodiff-custom-derivatives-and-higher-order.md]].
- **Run Debug first for a release-only crash**: a compiled-out `SLANG_ASSERT` often names the exact `file:line` in one shot [ModifiedType type-layout crash](../learnings/1786650725225-modifiedtype-unorm-snorm-crashes-ast-side-type-lay.md). On #13320 Release showed a null deref in `getRootAddr`; Debug showed the real first failure, `SLANG_ASSERT(diffVal)` at `slang-ir-autodiff-fwd.cpp:2098` [same](../learnings/1790693974366-getting-a-slang-crash-assert-backtrace-without-gdb.md). A Debug segfault right after `cast<IRFuncType>(x)` means `x` was null: `cast<>`'s `SLANG_ASSERT(!inst || as<T>(inst))` (`slang-ir.h:861`) lets null through.

**Worked results**, each minutes from rc=139 to file:line: #13321, the unchecked `cast<IRFuncType>` at `slang-ir-typeflow-specialize.cpp:4795` [same](../learnings/1790695170333-backtrace-a-slang-debug-slang-assert-on-linux-with.md); #13817, a null callee func type in typeflow `analyzeCall` (:4831) [SIGSEGV backtrace (#13817)](../learnings/1792582829901-symbolized-sigsegv-backtrace-for-slangc-without-gd.md); #10749, a null `programLayout` in `buildExternTypeMap` (via `TargetRequest::getTypeLayout`) on master 0bd71cd70, confirmed by a standalone C++-API repro linked `-I slang/include -L build/Debug/lib -lslang-compiler -Wl,-rpath,…` [same](../learnings/1792684568155-symbolize-slang-crashes-without-gdb-backtrace-hand.md); #14146, a CUDA emit SIGSEGV at `slang-emit-cpp.cpp:1615` where `as<IRPtrTypeBase>` returns null for the `ConstantBuffer` (`PointerLikeType`) base of a `GetElementPtr` (`ConstantBuffer<float3> sb; sb[1]`) — for a crash, a last `-dump-ir` header of `AFTER checkUnsupportedInst` means emit, not a pass [segfault backtrace (#14146)](../learnings/1793566282072-backtrace-a-slangc-segfault-without-gdb-ld-preload.md); #14240, where the opposite trap showed: an "AFTER specializeModule" section printed before an assert that was really thrown INSIDE `specializeModule`, because typeflow (`specializeDynamicInsts`) transcribes autodiff derivatives on demand through `TranslationContext::resolveInst` from `analyzeCall`, so the last dump header is not the failing pass and only the backtrace is. The cause was variadic + autodiff: `_getCalleeActualFuncType` (slang-ir-autodiff-fwd.cpp) calls the 3-argument `maybeExpandConcreteFuncTypePacks`, which REWRITES the callee's type (`as<IRTypePack>` sees through `Attributed(…, no_diff)`), while call arguments are flattened only by `SpecializationContext` for an `IRFunc` callee or by typeflow `expandPacksInFunc` on contexts it has discovered, so a primal body differentiated before typeflow discovers it gets N+k params against N args [same (#14240)](../learnings/1793880831242-backtrace-a-slangc-internalerror-without-gdb-ld-pr.md); and #13433, `si_addr=0x10` at `SubtypeWitness::getSub()` inlined into `tryConstantFoldDeclRef` (`slang-check-expr.cpp:2841`), a null-witness read. #13433's trace also moved the blame: the crash after E30623 came from `_validateCircularVarDefinition` self-folding an interface-requirement `static const` (a `DirectDeclRef` has no `LookupDeclRef`, so `findThisTypeWitness` returns null), not from a reference to it — a decl's circularity self-fold can take a different path than its uses, so check which fold crashes before blaming a referenced decl [shim pins Release fault sites (#13433)](../learnings/1791310105655-no-gdb-in-container-an-ld-preload-sigsegv-cxa-thro.md).

**Hang and freshness gotchas.** For a hang, `-dump-ir`/`-dump-ir-before/after` emit **0 lines** (the buffered diagnostic sink never flushes), so 0 lines is not a pass boundary; `slangc -v` prints a stale configure-time version string [shader+export hang](../learnings/1786817508989-shader-export-imported-entry-point-with-params-han.md). Prove a prebuilt binary is current with `find source include prelude -newer build/Release/lib/libslang-compiler.so.*` [same](../learnings/1790693974366-getting-a-slang-crash-assert-backtrace-without-gdb.md). Shim copies: slang-triager's `scratch-p1a/segv-bt.c` + `throw-bt.c`, `/workspace/agent/scratch-p6/{throw.c,segv.c,bt.sh}`, `/workspace/agent/scratch-13433/shim.c`.

## Confound: the crash reproduces but the reported feature is innocent

The decisive move on a crash report is a control that *isolates* the supposed cause. shader-slang/slang#12499 was filed as a `do/catch/throws` bug that "SIGSEGVs the CPU backend"; the repro genuinely exits 139, but a **negative control** — a bare buffer write with all error-handling stripped — crashes identically, so the crash is content-independent and the feature is exonerated. The true cause was a missing `//TEST_INPUT:ubuffer(...)` binding leaving the CPU launcher's root buffer null [slang-test -cpu SIGSEGV is a harness confound](../learnings/1786529531174-a-slang-test-cpu-sigsegv-is-a-harness-confound-unt.md). Since the *reported defect* does not reproduce, do NOT apply `reproduced`; the verdict is not-a-bug/invalid and the fix is a one-line test edit.

The same discipline localized #12498, a `slangc -target spirv-asm` infinite hang. The reporter pointed at `emitCastPtrToBool` (where they *found* the inst while browsing coverage), but a SIGPROF sampler put 156/159 samples in `AddressSpaceContext::processModule`, and a plain `Node*`-returning helper (no Optional) *also* hung, killing the CastPtrToBool hypothesis independently. Root cause: `HashSet<IRFunc*> newWorkList` declared *outside* the `while` loop and never cleared, defeating the monotonic convergence the fixpoint relies on [hang localized by SIGPROF sampling](../learnings/1786539248296-a-hang-localized-by-sigprof-sampling-not-by-the-re.md). A second target-independent hang, #12564, fires iff a precompiled `.slang-module` function is `[shader]` AND `export` AND has ≥1 parameter and is imported+re-emitted; a 9-cell matrix (each its own module rebuild) isolated the trigger and refuted the "varying parameter" framing (uniform and no-semantic params both hang). The root cause stays **hedged**: the flat `IRInstListBase::Iterator` stack fits a cyclic list, live-list-reorder churn or fixpoint re-processing, and that iterator is shared across decorations/children/blocks/globals [shader+export hang](../learnings/1786817508989-shader-export-imported-entry-point-with-params-han.md).

The same control applies when a *reviewer* reports a new crash against a patch. In the #13321 round-2 review, a code-traced finding blamed a null deref under `-disable-non-essential-validations` on the patch's new witness entry; the repro crashed (rc 139), but identically on pristine master and in the wrapper form that never reaches the new entry, so it was pre-existing, and the suggested guard would have restored master's crash. A/B every traced crash on a pristine build and in the sibling form that avoids the changed path [run it on pristine master and in the sibling form](../learnings/1790702192345-before-accepting-a-code-traced-new-crash-finding-r.md). When a repro carries extra features (custom `[ForwardDerivative]`, interfaces), drop them one at a time; for #13321 none mattered [drop repro features one at a time](../learnings/1790695170333-backtrace-a-slang-debug-slang-assert-on-linux-with.md). When a known crash shares the frame, restate the candidate to avoid it: any `bwd_diff(fwd_diff(...))` repro lands on #13321's `:4795` cast, so re-test as `fwd_diff(fwd_diff(g))` beside a plain-`g` control in Debug [isolate a higher-order repro from #13321](../learnings/1790704234870-a-higher-order-autodiff-crash-repro-can-be-confoun.md).

## slangi bytecode-VM crashes: emit-time, and the Call slot-size contract

#12495 (`Optional<A> o = b as A;`) SEGVs at bytecode *emit*: `visitMakeOptionalExpr` packed the payload with `val.val` directly, a base-subobject upcast lowers to a `Ptr`-flavored l-value, so a raw pointer became the Optional payload and reached `emitFieldExtract` on a pointer base → null deref in layout. Fix at the r-value consumer: `val.val` → `getSimpleVal(context, val)` [FieldExtract-on-pointer crash](../learnings/1786539532851-slangi-fieldextract-on-pointer-crashes-emit-vm-mak.md). #12496 is a distinct VM bug: `Call` reads each argument sized by the **callee's parameter-slot stride** (padded), not the operand's `.size` — an outlier vs `Print`/`CallExt`. It is layout-dependent: `x*x` aborts but `x+x` runs (the over-read bytes are inert padding), faulting only when padding crosses a working-set section edge; `slangi -disasm` is a rebuild-free counterfactual [VM Call over-reads by callee param-slot stride](../learnings/1786539124882-slangi-vm-call-opcode-over-reads-args-by-callee-pa.md).

Three reviewers of the #12496 fix suggested `SLANG_ASSERT(size <= slotStride)`. Added as a **probe**, it SIGABRT'd on an existing passing test at `size=12 into an 8-byte slot`, refuting the "impossible" claim — a VM operand's `.size` is a *recorded source range* (`FieldExtract` advances `.offset` without narrowing `.size`) [a SLANG_ASSERT is a probe](../learnings/1786559479043-a-slang-assert-is-a-probe-it-can-falsify-a-plausib.md). A follow-up **corrected the mechanism**: `SLANG_ASSERT` is `#ifdef _DEBUG` only, so the abort was a debug-build event; in release the false condition expands to `SLANG_ASSUME`→UB. And this container's `debug` CMake preset builds `CMAKE_BUILD_TYPE=Release`, so an added `SLANG_ASSERT` won't fire from that preset — verify which build you run [correction: debug-abort + release-UB](../learnings/1786561343746-correction-the-probed-slang-assert-was-debug-abort.md). Use `SLANG_RELEASE_ASSERT`/`SLANG_UNEXPECTED` when an invariant must hold in release.

## Front-end error state, pass ordering, and use-before-init false positives

`-no-codegen` only sets `SkipCodeGen`; it does NOT skip `generateIR()`, and the `getErrorCount()` gate runs *after* it. So a *silent* front-end `ErrorType` (error count 0) reaches lowering and hits `UNEXPECTED_CASE(ErrorType)` — the abort is a symptom of a missing upstream diagnostic, and a lowering-side tolerate-ErrorType change is a mask [-no-codegen still runs generateIR](../learnings/1786573554629-no-codegen-still-runs-generateir-so-a-silent-front.md). On #12548 a PR omitted a loop guard claiming E38206 vector-count validation catches an over-wide vector before the unroller — but `specializeModule`/`unrollLoopsInModule` runs *before* `validateVectorsAndMatrices` in `slang-emit.cpp`. The guard is still unneeded for a different reason: the unroller succeeds for any constant bound below `kMaxIterationsToAttempt=4096` and generics are specialized to a literal first [loop-unroll runs before E38206](../learnings/1786742313260-slang-specialization-loop-unroll-runs-before-e3820.md).

Inside the unroller, `_unrollLoop` (`slang-ir-loop-unroll.cpp`) clones one extra peel on purpose to prove the exit test false, and `_foldAndSimplifyLoopIteration` (:113-191) runs `tryReplaceInstUsesWithSimplifiedValue` → `tryConstantFoldInst` on every cloned inst *before* folding branches and running `_eliminateDeadBlocks`. So the dead N+1 peel is folded with `i == N`: `for (int i = 0; i < N; i++) y += x / (N - i);` computes `x / 0` there. `tryConstantFoldInst` (`slang-ir-sccp.cpp:2008`) never set `SharedSCCPContext::sink`, uninitialized from #2911 (2023) until PR #13769, so that fold dereferenced garbage (#13762). A real /0 on an executed step is still E30002 from the module SCCP, which skips the not-taken side of constant branches. In a new worktree, `git submodule update --init --recursive --reference /workspace/agent/slang` fails because that clone is shallow; use `git -c protocol.file.allow=always submodule update --init --recursive` (configure + Release slangc+slang-test ≈8 min on 64 cores) [ForceUnroll folds the dead N+1 exit-test peel](../learnings/1792502273587-forceunroll-folds-the-dead-n-1-exit-test-peel-via-.md).

E41035 "may be uninitialized" comes from `cancelLoadsByDefiniteAssignment` (`slang-ir-use-uninitialized-values.cpp`), a must-init walk over CFG edges with store blocks as barriers, otherwise **path-insensitive**: its only pruning is the short-circuit constant-phi case (`getInfeasibleBranchFromPredecessor`) plus the loop-exit and `WaveIsFirstLane` relaxations. So `if (c) x = ...; if (c) use(x);` warns for a runtime `c` (#13420). Constant folding is not the fix: the check runs per module (`slang-lower-to-ir.cpp` ~16262), before target linking resolves `extern static const`, so even `static const bool E = true` is still `ifElse(%E = globalConstant(true))`; only a literal `if (true)` folds. A prototype carrying known-true/false bits for conditions tested by two or more `ifElse` terminators (reset on entering the condition's defining block, looking through `not`) fixed it with no regressions in diagnostics/language-feature/bugs/autodiff. Workarounds: initialize at the declaration, or store and read inside one `if`. A negative test needs a runtime condition — a constant-`E` `if (E) store; if (!E) read;` has an unreachable read [E41035 must-init walk is path-insensitive](../learnings/1790993123820-e41035-must-init-walk-is-path-insensitive-same-con.md).

The `WaveIsFirstLane` relaxation comes from #12545, a false positive on a `WaveIsFirstLane()`-guarded out-param store. The wave op is **essential**: with a plain read the warning is a true positive (a non-first lane never took the `if`), so a fix must key on the `WaveIsFirstLane`-guard ↔ `WaveReadLaneFirst`-read correlation, not "any wave read." A *direct* conditional store is clean only because SSA promotion + SCCP fold the evidence away; an out-param store's address escapes, so it stays a memory var and is analyzed [E41035 must-init false positive](../learnings/1786747082828-e41035-must-init-false-positive-on-waveisfirstlane.md).

The same file's `canIgnoreType` shows a termination trap. #13416 replaces its unbounded recursion over mutually recursive pointer structs with an on-path `HashSet` (add before recursing, remove after); that terminates but enumerates every simple path: K structs each pointing to all others compile in ≤0.5 s for K≤10, 2.3 s at K=11, 25 s at K=12. Probe a path-set guard with a complete pointer graph (`struct Si { float v; Sj* pj; ... }` for all j≠i, plus one local `S1 s;`), timed against the same file without the local. When the answer is path-independent ("is this struct ignorable"), a memo of finished nodes beside the in-progress set makes the walk linear. Report it as a nit, not a blocker, when those inputs previously crashed [path-set cycle guards can be exponential](../learnings/1790981687370-path-set-cycle-guards-in-recursive-type-walks-can-.md).

## Codegen bugs: legalization, dedup scope, and destructive overrides

Three codegen atoms share a "the fix is upstream, not in emit" flavor. The CUDA `RWByteAddressBuffer`-param regression (#9824) was a legalization pass leaving the *original* param behind after partially replacing its uses; the fix (#9742) removes unused byte-address types. `RWStructuredBuffer<uint>` in CUDA output is a bug only as a **parameter** — a body-local `x.asStructuredBuffer<uint>()` temporary is the correct legalization for atomics [CUDA RWByteAddressBuffer regression](../learnings/1786633506187-cuda-rwbyteaddressbuffer-param-regression-9824-was.md). #12532 (OptiX `inout` ray payload read twice) came from a dedup guard keyed on the **entry-point-global** `m_payloadWritebacks` count; one entry point can carry two payloads, so the second saw a non-zero count and dropped its own store. The fix keys the skip on identity (`hasRegisteredPayloadWriteback(info.type)`): scope a "has X already happened?" predicate to the object, not an accumulating count [dedup guard keyed on global counter](../learnings/1786663782456-a-dedup-guard-keyed-on-an-entry-point-global-count.md). #12462 (render-test blanks the HLSL prelude only in the non-NVAPI `else` branch) is a silent carry-forward: the blank was a genuine reset-to-empty in 2020 when no HLSL prelude existed; a later PR added the prelude without touching render-test [render-test blanks HLSL prelude](../learnings/1786670359057-render-test-blanks-hlsl-prelude-only-in-the-non-nv.md).

The **two-parallel-layout-paths** hazard recurs in #12535: `unorm`/`snorm` (a `ModifiedType`) crashes the AST-side `_createTypeLayout` (no `ModifiedType` case → catch-all assert/UB), while IR-side `slang-ir-layout.cpp` handles it transparently (`ModifiedType` lowers to `IRAttributedType`). The paths share zero code, so check `slang-ir-layout.cpp` and `slang-type-layout.cpp` independently; the fix mirrors the existing transparent-unwrap precedents in the same function [ModifiedType type-layout crash](../learnings/1786650725225-modifiedtype-unorm-snorm-crashes-ast-side-type-lay.md). (The approver-side companion — check a layout fix against `getSimpleVaryingParameterTypeLayout` too — lives on the challenger page.)
