# Slang IR: phi block parameters and where inlined global values land

This page covers two IR shapes that downstream code often gets wrong. The first is SSA block parameters (phis): they are `IRParam`s just like function parameters, and a phi whose incoming values are all undefined is never folded, while a phi that merges a real resource with a `defaultConstruct` (the 2026.20 D3D E56019 autodiff regression) is a separate shape. The second is where `GlobalInstInlining` puts the clone of a module-scope value that is illegal at module scope for the target, which on WGSL can be inside a loop body. The third is a module-scope `static const` whose `[ForceInline]` user constructor the inliner expands at module scope (#14133), together with the dead constructor calls that `-g` leaves at module scope.

## TL;DR

- **Phi block parameters are `IRParam`s.** A walk that treats every `IRParam` as a function parameter also reports at phis, which take their source location from the promoted variable or the `?:` expression. To match only function parameters, test `as<IRParam>(user) && isFirstBlock(user->getParent())` (slang-ir-util.h).
- **Probe a user-walking diagnostic with a ternary and a loop-reassigned local**, not only a helper call. Those two shapes create phis.
- **When reviewing a "newly rejected shape" list, check what master emits, not only its exit code.** A shape master silently miscompiles (for example Metal `{ return; }`) is a fix when rejected, not a break.
- **No simplifier folds a phi whose incoming values are all undefined.** The peephole skips undefined args but needs one defined value, `tryRemoveTrivialPhi` has a TODO for the case, and `removeTrivialPhiParams` needs identical args. An opaque-typed phi of that shape survives to `eliminatePhis` and gives E56004 (E56019 on Metal).
- **E56004 triage:** dump IR after the `simplifyIR` that follows `legalizeResourceTypes`. If every incoming value of the opaque phi is `LoadFromUninitializedMemory` or `Poison`, the bug is the missing all-undefined fold, not the real-resource-selection family (#10526/#13248).
- **A phi that merges a real resource with a `defaultConstruct` is a different shape.** Slang 2026.20's new D3D storage check rejects slangpy `.bwds()` kernels with E56019 when an autodiff backward loop produces it. The all-undefined fold (#13700) does not cover it, because one incoming value is real.
- **A peephole rule that changes undefined values has two more traps.** The per-function peephole that runs after early inlining also runs before the uninitialized-value check, so it needs the prelinking flag too. A loop-header phi with incoming values {undef, itself} must skip the self argument, or `simplifyIR` never terminates.
- **In a slang-test `SIMPLE` filecheck, `CHECK-NOT: error` always matches the harness's own `standard error = {` header.** Match error codes instead.
- **`LoadFromUninitializedMemory` behaves like freeze(undef).** A phi of two such values may be refined to a fresh one, but never to `Poison`.
- **For phi(a, d) where `a` is a `LoadFromUninitializedMemory` used elsewhere too, refine `a` to d (replace every use of `a`) instead of keeping the phi "for correlation".** Keeping it gives E56004 and duplicate E41035. The refinement is sound only when one execution of `a` pairs with one d (d is global or constant, d dominates `a`, or d follows `a` in its block and dominates every use). It is not sound when d varies per loop iteration. Skip it in prelinking runs.
- **`GlobalInstInlining` inserts each clone at `getOutsideASM(user)`, and on WGSL that is the user itself.** A `static const` table used only inside a loop is rebuilt on every iteration at every -O level, and no later pass hoists it. Later uses in the same dominance region share the clone.
- **Placing the clone in the function entry block is safe only for side-effect-free values**, because `isInlinableGlobalInst` also sinks `Load` and `Call`.
- **Struct-typed tables reach WGSL legalization as `S_x24init` calls, not `MakeStruct`.** Check `-dump-ir-before legalizeIRForWGSL` before trusting an "untested arm" finding.
- **`performForceInlining` inlines module-scope calls too (#14133).** A `static const S k = S(0,0);` with a user `[ForceInline] __init` gets the constructor's `var`/`store`/`load` copied to file scope on every target (a branchy constructor segfaults Release slangc). Force-inlining runs before `inlineGlobalConstantsForLegalization`, so the fix belongs in the inliner, not in legalize-global-values.
- **"Legal at module scope" is not `!mightHaveSideEffects()`.** Debug insts under `-g` and an integer `Div`/`IRem` with a parameter divisor both count as side effects. Reject `IRVar`, `IRLoad` and unused side-effecting insts, and skip `isDebugInfoInst`; `IRStore` has a null type, not `Void`.
- **Under `-g`, a `static const` array of user-constructor structs leaves dead module-scope `$init` calls** that NVRTC, gcc and glslang reject. Debug insts block `[readNone]` inference (deliberate since #9860), so DCE keeps the element calls. slang-test cpu/cuda lanes need `-xslang -g0` for such array tests.

## Phis are `IRParam`s: filter with `isFirstBlock`

A diagnostic that walks an IR value's users to report at "declarations" (`IRGlobalParam`, `IRGlobalVar`, `IRParam`, `IRStructField`) also hits SSA block parameters, because a phi is an `IRParam` too. Consider `b = c ? m1 : m2`. SSA construction gives the merge block a parameter whose source location is the `?`, so the diagnostic reports there as well. On #13681 this produced 5 Metal E38204 reports where SPIR-V gave 2. The filter for function parameters only is `as<IRParam>(user) && isFirstBlock(user->getParent())`. Probe such a walk with a ternary and a loop-reassigned local, since a plain helper call creates no phi.

The same review produced a rule for "newly rejected shape" inventories: check what master actually emits, not only its exit code. On #13681, master's Metal output for `SB<ConstantBuffer<S{Tex}>>`, nested or static structured buffers, and mixed structs was `{ return; }`, a silent miscompile, so rejecting those shapes is a fix rather than a break [phi block params are IRParams: filter with isFirstBlock](../learnings/1792101219732-phi-block-params-are-irparams-filter-with-isfirstb.md).

## A phi whose incoming values are all undefined is never folded (#13685)

Consider a struct with a `Texture2D` field that is never written, where the struct is conditionally reassigned. `legalizeResourceTypes` splits the field into its own variable, and SSA gives each variable its own `LoadFromUninitializedMemory`. The merge block then gets a `Texture2D` parameter with incoming values (undef#1, undef#2). A plain `Texture2D t; if (c) { Texture2D r; t = r; }` reproduces it with no struct. Three simplifiers miss the shape:

- the peephole for `kIROp_Param` (slang-ir-peephole.cpp ~1665-1731) skips undefined args and folds to the one remaining value, so it does nothing when every arg is undefined;
- `tryRemoveTrivialPhi` (slang-ir-ssa.cpp ~795) has a TODO for exactly this case;
- `removeTrivialPhiParams` (simplify-cfg) requires identical args.

`eliminatePhis` then creates an opaque-typed variable, and `checkUnsupportedInst` reports E56004 (also on GLSL and WGSL; Metal gives E56019). The fix is semantic: `LoadFromUninitializedMemory` behaves like freeze(undef), so refining phi(freeze1, freeze2) to a fresh freeze is valid, while refining it to `Poison` is not.

For triage, when E56004 appears, look at the `-dump-ir` "AFTER simplifyIR" output right after `legalizeResourceTypes`. If every incoming value of the opaque parameter is `LoadFromUninitializedMemory` or `Poison`, this missing fold is the bug, not the real-resource selection case of #10526/#13248 [phi with all-undefined incoming args is never folded](../learnings/1792135170279-slang-ir-phi-with-all-undefined-incoming-args-is-n.md).

PR #13700, which adds the fold to the peephole, hit two more traps that apply to any peephole rule that changes undefined values. First, `PeepholeContext::isPrelinking` was set only by the module-wide `peepholeOptimize(target, module, options)`. In `generateIRForTranslationUnit`, the per-function `peepholeOptimize(nullptr, func)` that runs after `performMandatoryEarlyInlining` (slang-lower-to-ir.cpp ~15691) also runs before `checkForUsingUninitializedValues`. So a `!isPrelinking` gate does not protect the front-end uninitialized-value warnings in any function that calls an early-inlined core function, such as `bool((E)e)`. The PR adds a per-function overload that takes options and passes `getPrelinking()` there. Test this with a function that makes an early-inlined call, and do a revert drill.

Second, a loop-header parameter whose incoming values are {undefined, itself} made the existing single-defined-value rule in `case kIROp_Param` pick `argValue == inst`. Because `dominates(inst, inst)` is true, the rule replaced the parameter with itself, `changed` stayed true, and `simplifyIR` never terminated. Master already hangs this way on SPIR-V for `float4 t; for(..){ if(b){ float4 r; t = r; } } return t;`. The scan must skip `arg == inst`, as `tryRemoveTrivialPhi` does. The same PR found a detector trap: in a slang-test `SIMPLE` filecheck, `CHECK-NOT: error` always matches the harness's own `standard error = {` header, so a test must match error codes instead [peephole isPrelinking misses the per-function run after early inlining; loop-header {undef, self} params hang](../learnings/1792148210118-slang-peephole-isprelinking-misses-the-per-functio.md).

The same PR then had to decide what to do with phi(a, d) when `a` is a `LoadFromUninitializedMemory` that has other uses. Keeping the parameter so that it stays correlated with `a`'s other uses regressed code that master compiles: an opaque local gave E56004, the front end gave a duplicate E41035, and master's single-defined-value forwarding was lost. The version that keeps both behaviours forwards the parameter to d and also replaces every use of `a` with d. The `LoadFromUninitializedMemory` description in slang-ir-insts.lua permits this: "an optimization pass may freely decide on a particular value to use and replace all uses of the instruction with that value". The refinement is sound only when one execution of `a` pairs with exactly one d, which holds in three cases: d is outside every block (a constant or a global); d dominates `a`; or d follows `a` in the same block and dominates every use of `a`. It is not sound when d varies per loop iteration while `a` stays fixed. That case is a real conflict between correlation and forwarding, and PR #13700 asked the maintainer how to resolve it. The refinement is skipped in prelinking runs, so the uninitialized-use warnings do not change. Revert-drill each soundness guard (make it return true and check that some test fails), because a loop test can pass for an unrelated reason when the existing dominance check already keeps the parameter [refine an observed LoadFromUninitializedMemory to the forwarded value instead of keeping the phi](../learnings/1792200612138-slang-ir-refine-an-observed-loadfromuninitializedm.md).

## A real resource merged with `defaultConstruct` in an autodiff backward loop (2026.20 D3D E56019)

Slang 2026.20 added a D3D storage check, `checkUnsupportedResourceLocals` (slang#13116, c538debef). It rejects DXIL output for slangpy `.bwds()` through `IDiffTensor` in a runtime-bounded `[MaxIters]` loop with `error[E56019]: target cannot represent an opaque value in mutable local storage`. Slang 2026.19 compiled the same kernel, DXC 1.9 accepts the HLSL that 2026.20 emits, and Vulkan, CUDA and Metal are unaffected.

The IR shape is a phi again, but not the all-undefined one. The bwdProp loop body has `%x : RWByteAddressBuffer = defaultConstruct`, created at `legalizeResourceTypes`. A block parameter merges that `%x` with the real buffer parameter, so `eliminatePhis` turns it into a variable and the check fires. The #13685 fold in PR #13700 does not apply, because one incoming value is real.

Consider this minimal pure-Slang repro, compiled with `slangc -target dxil -entry main -stage compute -profile sm_6_6`: a struct holds `StructuredBuffer<float> primal; RWByteAddressBuffer grad;` and has `[BackwardDerivative(load_bwd)] float load(uint i)`, where `load_bwd` calls `grad.InterlockedAdd`. A `[Differentiable] f(no_diff DT t, no_diff int n)` loops `for (i < n)` under `[MaxIters(17)]`, and the entry point calls `bwd_diff(f)`. The files are in slangpy-fixer's group at `/workspace/agent/repro-1167/d3d12/min/d.slang`. For a local DXIL compile, pass `-dxc-path <dir with libdxcompiler.so>`. slangpy kernels include `nvHLSLExtns.h`, so to test them through `-pass-through dxc`, stub `NvInterlockedAddFp32` [2026.20 D3D E56019 regression: autodiff bwd loop merges a real resource with defaultConstruct](../learnings/1792492344596-slang-2026-20-d3d-e56019-regression-autodiff-bwd-l.md).

## Where `GlobalInstInlining` puts a sunk module-scope value

When `GlobalInstInliningContextGeneric::inlineGlobalValuesAndRemoveIfUnused` sinks a module-scope aggregate that is illegal at module scope for the target, such as a `static const` table on WGSL, it inserts each clone at `getOutsideASM(user)`. WGSL returns the user itself. A table used only inside a loop is therefore materialized as `var t = array<...>(...)` inside the `loop {}` and rebuilt on every iteration, at -O0 through -O3. No later pass hoists it, since `hoistLoopInvariantInsts` is autodiff-only. Uses after the first one in the same dominance region share the clone, so the behaviour is not strictly one clone per use site. Master's struct-typed tables already behave this way.

Placing the clone at the first ordinary instruction of the function's entry block fixes it for `Make*` values and constants (verified on #13669: tests/wgsl 64/64, corpus byte-identical). That placement is unsafe as written, because `isInlinableGlobalInst` also sinks `Load` and `Call`, so gate entry-block placement on side-effect-free ops.

A reviewer on #13669 claimed that a struct table with a NaN field reached WGSL legalization as a module-scope `makeStruct`. It does not: struct tables arrive as `S_x24init` calls, so the `MakeStruct` arm of WGSL `isLegalGlobalInstForTarget` is unreachable from user source. Check `-dump-ir-before legalizeIRForWGSL` before trusting an "untested arm" finding [GlobalInstInlining clones land at the first use, which can be inside a loop body](../learnings/1792094646121-globalinstinlining-clones-land-at-the-first-use-wh.md).

## Module-scope `[ForceInline]` constructor calls and dead global initializers (#14133)

Consider `static const S k = S(0, 0);`, where `S` has a user-written `[ForceInline] __init`. After `replaceGlobalConstants`, the initializer is a module-scope `call S.$init`. `InliningPassBase::considerAllCallSitesRec` (slang-ir-inline.cpp:80-98) visits module-scope `IRCall`s as well, and `inlineSingleBlockFuncBody` copies the constructor's `var`/`store`/`load` into module scope. Every textual emitter (HLSL, GLSL, Metal, WGSL, C++, CUDA) then prints file-scope statements, and SPIR-V fails spirv-val. A multi-block (branchy) `[ForceInline]` constructor segfaults Release slangc instead; the Debug build asserts at slang-ir-inline.cpp:767. The checker accepts the input because `_initExprIsRuntimeValue` treats every `ConstructorDecl` as pure, while a free `[ForceInline]` function gets E31226. To check, look for a module-scope `var` in the `-dump-ir` section "AFTER performForceInlining". The pass order in slang-emit.cpp decides the layer: force-inlining (:1864) runs before `inlineGlobalConstantsForLegalization` (:1973, which moves module-scope calls into each user), and runs again at :2724. A fix in legalize-global-values (such as PR #13115) therefore comes too late. The fix belongs in the inliner, which skips a module-scope call site whose callee body is not legal at global scope. The issue title said "CUDA:", but the bug hits every target, so run the `RWStructuredBuffer` variant on every target before scoping a fix [performForceInlining inlines module-scope calls](../learnings/1793515107207-slang-performforceinlining-inlines-module-scope-ca.md).

"Legal at module scope" is not the same as "no `mightHaveSideEffects()`". A first-draft guard that inlined at module scope only when no callee inst `mightHaveSideEffects()` regressed `static const` scalar arrays built from pure `[ForceInline]` helpers, which master folds to `{2.0, 4.0}`. Two shapes trip it. Under `-g`, every user function body carries `DebugLine`/`DebugValue`/`DebugVar`/`DebugScope`, which count as side effects. An integer `Div`/`IRem` whose divisor is not a non-zero literal counts as a possible trap, and in a callee body the divisor is a parameter. The leftover `call` initializers then failed on NVRTC ("dynamic initialization is not supported for a __device__ variable"), glslang ("global const initializers must be constant") and C++ ("undeclared identifier"). The rule that works rejects `IRVar`, `IRLoad` and statements (`mightHaveSideEffects() && !hasUses()`), and skips `isDebugInfoInst(inst)` (slang-ir-util.cpp). A statement test through `as<IRVoidType>(getDataType())` misses `IRStore`, whose type is null, not `Void`. To measure what a pass change does elsewhere, add temporary `fopen("/tmp/x/<pid>.log", "a")` logging inside the pass, run the full suite on master and on the fix (each test-server process writes its own pid file), and `sort | uniq -c` the logged shapes. On #14133 that showed that only `saturate`/`round`/`min` (SPIRVAsm) and `vector.$init` are inlined at module scope anywhere in the suite [mightHaveSideEffects() is not "legal at module scope"](../learnings/1793520147967-slang-ir-mighthavesideeffects-is-not-legal-at-modu.md).

A separate, older gap appears only under `-g` and is not specific to `[ForceInline]`. `static const S arr[2] = { S(0,0), S(1,1) }` with a user-written `__init` emits an unused `__device__ static const S_0 _S1 = S_x24init_0(...)`, which NVRTC, gcc and glslang reject. `inlineGlobalValuesAndRemoveIfUnused` (slang-ir-legalize-global-values.cpp) deletes only the root aggregate it inlined, so the element calls stay at module scope with no uses. Without `-g`, `S.$init` is inferred `[readNone]` and DCE removes them. With `-g`, the debug instructions in the callee body block `[readNone]` inference, deliberately since #9860 (e9cc1f671; v2026.1.1 good, v2026.1.2 broken), so DCE keeps the calls. Synthesized `$init` constructors (initializer lists) are clean, because #11555 drops their debug info. slang-test's cpu and cuda lanes behave as if debug info is on, so array tests there need `-xslang -g0` [same](../learnings/1793520147967-slang-ir-mighthavesideeffects-is-not-legal-at-modu.md). When a difference appears only under `-g`, compare `-dump-ir` with and without `-g` and find where `[readNone]` first appears on the callee: such a difference often comes from function-property inference, not from debug uses of the value [-g blocks readNone inference](../learnings/1793521071820-slang-g-blocks-readnone-inference-9860-orphaned-mo.md). The struct-table localization on CUDA (#13107) is a different bug; see [[wiki/concepts/misc-f0909b5-cuda-codegen-triage.md]].
