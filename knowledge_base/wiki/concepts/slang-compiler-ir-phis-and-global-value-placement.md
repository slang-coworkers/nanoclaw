# Slang IR: phi block parameters and where inlined global values land

Three IR shapes that downstream code often gets wrong: SSA block parameters (phis), including the all-undefined phi no simplifier folds and the real-resource-plus-`defaultConstruct` phi of the 2026.20 D3D E56019 regression; where `GlobalInstInlining` puts the clone of a module-scope value that is illegal for the target (on WGSL, possibly inside a loop); and module-scope `static const` initializers that the force-inliner expands at file scope (#14133), with the dead constructor calls `-g` leaves behind and the "outside any function" test (`getParentFunc` is not it).

## TL;DR

- **Phi block parameters are `IRParam`s.** A walk treating every `IRParam` as a function parameter also reports at phis (located at the promoted variable or the `?:`). Match only function parameters with `as<IRParam>(user) && isFirstBlock(user->getParent())`.
- **Probe a user-walking diagnostic with a ternary and a loop-reassigned local**, not only a helper call; those create phis.
- **For a "newly rejected shape" list, check what master emits, not only its exit code.** A shape master silently miscompiles (Metal `{ return; }`) is a fix when rejected.
- **No simplifier folds a phi whose incoming values are all undefined** (peephole needs one defined value, `tryRemoveTrivialPhi` has a TODO, `removeTrivialPhiParams` needs identical args). An opaque-typed phi of that shape reaches `eliminatePhis` and gives E56004 (E56019 on Metal).
- **E56004 triage:** dump IR after the `simplifyIR` following `legalizeResourceTypes`. All incoming values `LoadFromUninitializedMemory`/`Poison` → the missing fold, not the real-resource-selection family (#10526/#13248).
- **E56004 with a constant `?:` condition (#14214) is a folding gap:** the constant crosses a non-inlined call (SRU inlines only for resource outputs; SCCP is intraprocedural) or sits in a field-stored struct var (`constructSSA` skips partial stores). Check `-dump-ir-before specializeResourceUsage`.
- **A phi merging a real resource with a `defaultConstruct` is a different shape**: 2026.20's D3D storage check rejects slangpy `.bwds()` autodiff loops with E56019; the all-undefined fold (#13700) does not cover it.
- **Peephole rules that change undefined values:** the per-function peephole after early inlining also runs before the uninitialized-value check, so it needs the prelinking flag; a loop-header phi {undef, itself} must skip the self argument or `simplifyIR` never terminates.
- **In a slang-test `SIMPLE` filecheck, `CHECK-NOT: error` always matches the harness's `standard error = {` header.** Match error codes.
- **`LoadFromUninitializedMemory` behaves like freeze(undef):** phi of two may become a fresh one, never `Poison`.
- **For phi(a, d) with `a` a multi-use `LoadFromUninitializedMemory`, replace every use of `a` with d instead of keeping the phi.** Keeping it gives E56004 and duplicate E41035. Sound only when one execution of `a` pairs with one d (d global/constant, d dominates `a`, or d follows `a` in its block and dominates every use); not when d varies per loop iteration. Skip in prelinking runs.
- **`GlobalInstInlining` inserts each clone at `getOutsideASM(user)`, which on WGSL is the user.** A `static const` table used only in a loop is rebuilt every iteration at every -O level; nothing hoists it. Later uses in the same dominance region share the clone.
- **Entry-block placement of the clone is safe only for side-effect-free values**: `isInlinableGlobalInst` also sinks `Load` and `Call`.
- **Struct-typed tables reach WGSL legalization as `S_x24init` calls, not `MakeStruct`.** Check `-dump-ir-before legalizeIRForWGSL` before trusting an "untested arm" finding.
- **`performForceInlining` inlines module-scope calls (#14133):** `static const S k = S(0,0);` with a user `[ForceInline] __init` gets `var`/`store`/`load` at file scope on every target (branchy constructor segfaults Release slangc). It runs before `inlineGlobalConstantsForLegalization`, so the fix belongs in the inliner.
- **"Legal at module scope" is neither `!mightHaveSideEffects()` nor "no unused side effects".** `-g` debug insts and parameter-divisor `Div`/`IRem` count as side effects; refusing only unused ones still inlines used atomics and calls (#14238). At module scope treat the trap-only `Div`/`IRem` set as pure (gate on an `IRModuleInst` parent); `IRStore` has a null type, not `Void`.
- **"Outside any function" = nearest `IRGlobalValueWithCode` ancestor is an `IRGeneric` or absent.** `IRFunc` and `IRGlobalVar` ancestors are inside (`moveGlobalVarInitializationToEntryPoints` moves initializers into functions). `!as<IRBlock>(parent)` misses generics; `!getParentFunc(inst)` wrongly includes global-var initializers. Use the ancestor test for skipping inlined debug insts (#14321) and for choosing legalized-copy users (#14267).
- **Since #14204 (2026-11-04) `isLegalGlobalInstForTarget` rejects any `IRCall`,** so module-scope arrays with calls are copied into each kernel; before, only struct-rooted globals moved. Test scalar-array and struct roots, with and without `-g`; judge a competing PR by building master, PR and your fix from one merge-base.
- **Under `-g`, a `static const` array of user-constructor structs leaves dead module-scope `$init` calls** (NVRTC/gcc/glslang reject). Debug insts block `[readNone]` inference (deliberate since #9860). slang-test cpu/cuda lanes need `-xslang -g0` for such tests.

## Phis are `IRParam`s: filter with `isFirstBlock`

A diagnostic that walks a value's users to report at "declarations" (`IRGlobalParam`, `IRGlobalVar`, `IRParam`, `IRStructField`) also hits block parameters. For `b = c ? m1 : m2`, SSA gives the merge block a parameter located at the `?`; on #13681 this produced 5 Metal E38204 reports where SPIR-V gave 2. Filter with `as<IRParam>(user) && isFirstBlock(user->getParent())`, and probe with a ternary and a loop-reassigned local. The same review set the rule for "newly rejected shape" inventories: master's Metal output for `SB<ConstantBuffer<S{Tex}>>`, nested/static structured buffers and mixed structs was `{ return; }`, a silent miscompile, so rejecting them is a fix [phi block params are IRParams](../learnings/1792101219732-phi-block-params-are-irparams-filter-with-isfirstb.md).

## A phi whose incoming values are all undefined is never folded (#13685)

A struct with a never-written `Texture2D` field, conditionally reassigned: `legalizeResourceTypes` splits the field into its own variable, SSA gives each a `LoadFromUninitializedMemory`, and the merge block gets a `Texture2D` parameter with (undef#1, undef#2). `Texture2D t; if (c) { Texture2D r; t = r; }` reproduces it without a struct. Three simplifiers miss it: the `kIROp_Param` peephole (slang-ir-peephole.cpp ~1665-1731) skips undefined args and needs one remaining value; `tryRemoveTrivialPhi` (slang-ir-ssa.cpp ~795) has a TODO for the case; `removeTrivialPhiParams` (simplify-cfg) requires identical args. `eliminatePhis` then makes an opaque-typed variable and `checkUnsupportedInst` reports E56004 (also GLSL/WGSL; Metal E56019). Since `LoadFromUninitializedMemory` is freeze(undef), refining phi(freeze1, freeze2) to a fresh freeze is valid; refining to `Poison` is not. Triage: in the "AFTER simplifyIR" dump after `legalizeResourceTypes`, all-undefined incoming values mean this fold, not #10526/#13248 [all-undefined phi is never folded](../learnings/1792135170279-slang-ir-phi-with-all-undefined-incoming-args-is-n.md).

PR #13700 (adds the fold) hit two traps for any peephole rule that changes undefined values. First, `PeepholeContext::isPrelinking` was set only by the module-wide `peepholeOptimize(target, module, options)`; the per-function `peepholeOptimize(nullptr, func)` after `performMandatoryEarlyInlining` (slang-lower-to-ir.cpp ~15691) also runs before `checkForUsingUninitializedValues`, so a `!isPrelinking` gate did not protect warnings in functions calling an early-inlined core function such as `bool((E)e)`. The PR adds a per-function overload passing `getPrelinking()`; test with an early-inlined call and a revert drill. Second, a loop-header parameter with {undefined, itself} made the single-defined-value rule pick `argValue == inst`; `dominates(inst, inst)` is true, so it replaced the parameter with itself, `changed` stayed true and `simplifyIR` never terminated (master already hangs on SPIR-V for `float4 t; for(..){ if(b){ float4 r; t = r; } } return t;`). Skip `arg == inst`, as `tryRemoveTrivialPhi` does. Detector trap: `CHECK-NOT: error` in a `SIMPLE` filecheck always matches the harness's `standard error = {` header; match error codes [isPrelinking misses the per-function run; {undef, self} params hang](../learnings/1792148210118-slang-peephole-isprelinking-misses-the-per-functio.md).

For phi(a, d) where `a` is a `LoadFromUninitializedMemory` with other uses, keeping the parameter "for correlation" regressed code master compiles (opaque local E56004, duplicate front-end E41035, lost forwarding). The working version forwards the parameter to d and replaces every use of `a` with d, which slang-ir-insts.lua permits ("an optimization pass may freely decide on a particular value to use and replace all uses of the instruction with that value"). It is sound only when one execution of `a` pairs with one d: d is outside every block (constant/global), d dominates `a`, or d follows `a` in the same block and dominates every use of `a`. When d varies per loop iteration while `a` is fixed, correlation and forwarding genuinely conflict; #13700 asked the maintainer. Skip in prelinking runs so uninitialized-use warnings are unchanged. Revert-drill each soundness guard (make it return true, see a test fail), since a loop test can pass because the dominance check already keeps the parameter [refine an observed LoadFromUninitializedMemory](../learnings/1792200612138-slang-ir-refine-an-observed-loadfromuninitializedm.md).

## E56004 when the `?:` resource choice is a compile-time constant (#14214)

`cond ? texA : texB` with a constant `cond` still gives E56004 in two cases (ToT 96a728c85). (1) The constant arrives through an argument of a non-inlined helper: the `specializeResourceUsage` fixpoint (`slang-ir-specialize-resources.cpp` ~2019) inlines callers only for an unspecializable resource *output* (~2059-2073), not for an unresolved selection (rejected ~1845), and SCCP is intraprocedural; `[ForceInline]` works because `performForceInlining` (`slang-emit.cpp` ~1869) runs earlier. (2) The condition is a struct field written field-by-field (`Args a; a.f = false;`): `constructSSA` never promotes a var with a field-address *store* (`allUsesLeadToLoads` ~116, TODO ~503-512). A whole-value init (`(Args)0`) folds, a later field store does not, at any -O. Dump `-dump-ir-before specializeResourceUsage`: a leftover `call` or `store(get_field_addr(var))` before the phi names the gap. DeepWiki's "constructSSA promotes field-address chains" holds only for chains ending in loads [E56004 with a constant ?: resource choice](../learnings/1793665534261-slang-e56004-with-a-constant-resource-choice-two-f.md). Selection between genuinely different image globals is on [[wiki/concepts/slang-backends-spirv-emit-and-legalization-defects.md]].

## A real resource merged with `defaultConstruct` in an autodiff backward loop (2026.20 D3D E56019)

Slang 2026.20's D3D storage check `checkUnsupportedResourceLocals` (slang#13116, c538debef) rejects DXIL for slangpy `.bwds()` through `IDiffTensor` in a runtime-bounded `[MaxIters]` loop: `error[E56019]: target cannot represent an opaque value in mutable local storage`. 2026.19 compiled it, DXC 1.9 accepts the 2026.20 HLSL, and Vulkan/CUDA/Metal are unaffected. The bwdProp loop body has `%x : RWByteAddressBuffer = defaultConstruct` (from `legalizeResourceTypes`); a block parameter merges it with the real buffer parameter, `eliminatePhis` makes a variable, and the check fires. The #13700 fold does not apply because one incoming value is real.

Minimal repro (`slangc -target dxil -entry main -stage compute -profile sm_6_6`): a struct with `StructuredBuffer<float> primal; RWByteAddressBuffer grad;` and `[BackwardDerivative(load_bwd)] float load(uint i)` where `load_bwd` calls `grad.InterlockedAdd`; a `[Differentiable] f(no_diff DT t, no_diff int n)` looping `for (i < n)` under `[MaxIters(17)]`; the entry calls `bwd_diff(f)`. Files: slangpy-fixer's `/workspace/agent/repro-1167/d3d12/min/d.slang`. Local DXIL needs `-dxc-path <dir with libdxcompiler.so>`; to test slangpy kernels via `-pass-through dxc`, stub `NvInterlockedAddFp32` from `nvHLSLExtns.h` [2026.20 D3D E56019 regression](../learnings/1792492344596-slang-2026-20-d3d-e56019-regression-autodiff-bwd-l.md).

## Where `GlobalInstInlining` puts a sunk module-scope value

When `GlobalInstInliningContextGeneric::inlineGlobalValuesAndRemoveIfUnused` sinks a module-scope aggregate illegal for the target (a `static const` table on WGSL), it inserts each clone at `getOutsideASM(user)`, which WGSL returns as the user itself. A table used only in a loop becomes `var t = array<...>(...)` inside `loop {}`, rebuilt every iteration at -O0..-O3; `hoistLoopInvariantInsts` is autodiff-only, so nothing hoists it. Later uses in the same dominance region share the clone; master's struct tables already behave this way. Placing the clone at the first ordinary instruction of the entry block fixes it for `Make*` values and constants (#13669: tests/wgsl 64/64, corpus byte-identical), but must be gated on side-effect-free ops because `isInlinableGlobalInst` also sinks `Load` and `Call`. A #13669 reviewer claimed a NaN-field struct table reached WGSL legalization as a module-scope `makeStruct`; struct tables arrive as `S_x24init` calls, so that `MakeStruct` arm of `isLegalGlobalInstForTarget` is unreachable from user source. Check `-dump-ir-before legalizeIRForWGSL` first [GlobalInstInlining clones land at the first use](../learnings/1792094646121-globalinstinlining-clones-land-at-the-first-use-wh.md).

## Module-scope `[ForceInline]` constructor calls and dead global initializers (#14133, #14238)

For `static const S k = S(0, 0);` with a user `[ForceInline] __init`, the initializer after `replaceGlobalConstants` is a module-scope `call S.$init`. `InliningPassBase::considerAllCallSitesRec` (slang-ir-inline.cpp:80-98) visits module-scope `IRCall`s too, and `inlineSingleBlockFuncBody` copies the constructor's `var`/`store`/`load` into module scope: every textual emitter (HLSL, GLSL, Metal, WGSL, C++, CUDA) prints file-scope statements and SPIR-V fails spirv-val. A branchy constructor segfaults Release slangc (Debug asserts at slang-ir-inline.cpp:767). The checker accepts it because `_initExprIsRuntimeValue` treats every `ConstructorDecl` as pure (a free `[ForceInline]` function gets E31226). Look for a module-scope `var` in "AFTER performForceInlining". Pass order decides the layer: force-inlining (slang-emit.cpp:1864, again :2724) runs before `inlineGlobalConstantsForLegalization` (:1973), so a legalize-global-values fix (PR #13115) is too late; the inliner must skip a module-scope call site whose callee body is not legal at global scope. The issue said "CUDA:" but every target is hit; run the `RWStructuredBuffer` variant on all targets before scoping [performForceInlining inlines module-scope calls](../learnings/1793515107207-slang-performforceinlining-inlines-module-scope-ca.md).

"Legal at module scope" is not "no `mightHaveSideEffects()`". That guard (human PR #14150 and a local draft) regressed `static const` scalar arrays from pure `[ForceInline]` helpers, which master folds to `{2.0, 4.0}`, via two shapes: under `-g` every user body carries `DebugLine`/`DebugValue`/`DebugVar`/`DebugScope` (side effects), and an integer `Div`/`IRem` whose divisor is a parameter counts as a possible trap. The leftover `call` initializers failed on NVRTC ("dynamic initialization is not supported for a __device__ variable"), glslang ("global const initializers must be constant") and C++ ("undeclared identifier"). Rejecting `IRVar`, `IRLoad` and statements (`mightHaveSideEffects() && !hasUses()`) while skipping `isDebugInfoInst(inst)` fixes the #14133 shapes but is still too permissive (#14238 below); a statement test via `as<IRVoidType>(getDataType())` misses `IRStore`, whose type is null. To census a pass change, log shapes from inside the pass to `/tmp/x/<pid>.log` (one file per test-server process), run the suite on master and the fix, `sort | uniq -c`; on #14133 only `saturate`/`round`/`min` (SPIRVAsm) and `vector.$init` were inlined at module scope anywhere [mightHaveSideEffects() is not "legal at module scope"](../learnings/1793520147967-slang-ir-mighthavesideeffects-is-not-legal-at-modu.md).

"A later pass handles the leftover call" was only half true: `inlineGlobalConstantsForLegalization` moved a module-scope call into each user only when the enclosing global was itself illegal, which before #14204 meant a struct (`isSimpleConstantType` rejects structs). For an `int[]`/`float[]` `static const`, `makeArray` is legal, stays at module scope with the `call` operands, and emits `__device__ static const FixedArray<int,2> arr = {{ f(10,4), ... }}`, which NVRTC, glslang and C++ reject. So #14150 broke `static const int arr[] = { ceilDiv(10,4), ... }` and any pure helper under `-g`. Verify such fixes on scalar/array-of-scalar and struct roots, each with and without `-g` [legalization moves a module-scope call only when the global is illegal](../learnings/1793668121777-slang-global-constant-legalization-moves-a-module-.md). It surfaced through an A/B: when a human PR supersedes a local fix and the ask is "gaps only", build master, PR and fix as three Debug worktrees from one merge-base (`git worktree add --detach <path> <sha>`, ~6 min on 64 cores) and run one script over all three: a slangc target matrix (rc, spirv-val, file-scope-statement grep, nvcc/g++ on outputs) plus slang-test probes copied into each `tests/bugs/`. On #14150 only the slang-test probes caught it, because the default `-cuda` COMPARE_COMPUTE lane runs with debug info (script: `/workspace/agent/reports/slang-14133-repro/run.sh`) [diffing a competing PR on the same base](../learnings/1793668061204-diffing-a-competing-pr-build-master-pr-yours-on-th.md).

#14238 (PR #14267) settled module-scope "side effect". `mightHaveSideEffects` flags integer `Div`/`IRem`/`ConstexprDiv`/`ConstexprIRem` only because they might trap, and those four are the whole trap-only set. A module-scope inst has no execution point: emit's `getFoldPolicy` (emit-c-like:1695) folds a side-effect-free one into its uses and DCE drops it, so a division reporting a side effect became its own global with a dynamic initializer, which NVRTC rejects even for hand-written `static const int k = 10 / max(4,1);` on master and v2026.18. The fix gates the trap-only rule on `as<IRModuleInst>(getParent())`, leaving guarded `a / b` inside functions unchanged. "Refuse only unused side effects" inlines used atomics and calls at module scope and regresses master (GLSL/Metal fail on an atomic in a struct helper); under `-g` a `DebugValue` also counts as a use, so a call bound to an unused local passes. Inlining at module scope also cloned the callee's debug insts there (#14321; the skip and its "outside any function" test are on [[wiki/concepts/slangc-wave-vm-and-inliner.md]]). Test gotchas: `half(10)` is the type conversion, not a user helper; with `-output-using-type`, `BUF: 3` matches the '3' in "type: int32_t", so check `BUF: type: int32_t` then `BUF-NEXT:`; cpu/cuda COMPARE_COMPUTE lanes run with debug info by default [module-scope [ForceInline]: Div/IRem, debug insts, unused side effects](../learnings/1793744194001-slang-module-scope-forceinline-inlining-div-irem-d.md). Spec-constant operands in module-scope initializers (E31226, the #14278 WGSL hang) are on [[wiki/concepts/slang-compiler-specialization-constants-across-targets.md]].

#14238's repro was then fixed on master by an unrelated merge: #14204 (139f09f597, 2026-11-04 02:32Z) made `isLegalGlobalInstForTarget` (slang-ir-legalize-global-values.cpp) return false for any `IRCall`, so module-scope arrays with calls are copied into each kernel, and the repro passed without PR #14267. Re-run the repro on current master before a rework. The only variant still failing was a helper without `[__readNone]` in a struct static member array: `inlineGlobalValuesAndRemoveIfUnused` deletes only the top global, the operand calls stay at module scope unused, and DCE keeps them since the callee is not readNone, the same orphan as the `-g` gap below [re-run a regression repro on current master](../learnings/1793820509349-slang-re-run-a-regression-repro-on-current-master-.md).

An older gap, only under `-g` and not specific to `[ForceInline]`: `static const S arr[2] = { S(0,0), S(1,1) }` with a user `__init` emits an unused `__device__ static const S_0 _S1 = S_x24init_0(...)` that NVRTC, gcc and glslang reject. `inlineGlobalValuesAndRemoveIfUnused` deletes only the root it inlined, leaving element calls unused at module scope. Without `-g`, `S.$init` is inferred `[readNone]` and DCE removes them; with `-g`, callee debug insts block that inference, deliberately since #9860 (e9cc1f671; v2026.1.1 good, v2026.1.2 broken). Synthesized `$init` (initializer lists) is clean because #11555 drops its debug info. slang-test cpu/cuda lanes act as if debug info is on, so array tests need `-xslang -g0` [same](../learnings/1793520147967-slang-ir-mighthavesideeffects-is-not-legal-at-modu.md). For a `-g`-only difference, compare `-dump-ir` with and without `-g` and find where `[readNone]` first appears on the callee; such differences often come from function-property inference, not debug uses of the value [-g blocks readNone inference](../learnings/1793521071820-slang-g-blocks-readnone-inference-9860-orphaned-mo.md). The CUDA struct-table localization (#13107) is a different bug; see [[wiki/concepts/misc-f0909b5-cuda-codegen-triage.md]].

## Users under a `static` global's initializer are executable code (#14267 R2)

"Outside any function" is decided by the nearest `IRGlobalValueWithCode` ancestor, not `getParentFunc`: `IRGeneric` or none is outside; `IRFunc` or `IRGlobalVar` is inside, because `moveGlobalVarInitializationToEntryPoints` later moves a global-var initializer into a function. The inliner case that set this rule (#14321) is on [[wiki/concepts/slangc-wave-vm-and-inliner.md]]. Global-constant legalization had the same blind spot: `inlineGlobalValuesAndRemoveIfUnused` copied a module-scope value only into users with `getParentFunc(user)` set, skipping uses in a `static` global's initializer, so the root and its calls stayed at module scope. `moveGlobalVarInitializationToEntryPoints` (slang-emit.cpp:2102) runs after `inlineGlobalConstantsForLegalization` (:1989) and moved the initializer into the kernel still referencing those calls: `static int gv = Holder.arr[1];` broke on CUDA, GLSL and C++ ("dynamic initialization", "global const initializers must be constant"), and an effectful version gave E99997. Treating an `IRGlobalVar` ancestor as executable code fixes it with a clean suite. Probe runtime and effectful initializers with struct statics: E31226 ("static const global initializer must be a compile-time constant", #9404/#10925) applies only to namespace/file-scope declarations, and struct-member `static const` skips it (slang-check-decl.cpp:1597-1605, :3834) [legalization skips static-var initializer users](../learnings/1793831042175-slang-global-constant-legalization-skips-static-va.md).
