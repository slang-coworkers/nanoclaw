## TL;DR

A family of `InternalError`/`SLANG_UNEXPECTED` aborts on the SPIR-V path share one shape: a `LegalVal::none`, ErrorType, opaque or unspecialized value reaches a legalization/lowering switch with no case for it, and the `default:` arm asserts. Rules:

- **`non-simple operand(s)!`** (4-arg `legalizeInst`, `slang-ir-legalize-types.cpp`): an empty `struct{}` legalizes to `none`, but an inst whose *result type* is not `none` (a `spirv_asm` operand, a `copyLogical`) hits the shared `default:`. Add the specific case (assert operands `none`, return `LegalVal()`); safe because the inner switch runs only when `anyComplex==true`.
- **`unexpected: ErrorType`** past the error gate: a checker set an ErrorType (`CreateErrorExpr`) but backed it with only a WARNING, so `getErrorCount()==0` did not bail. Fix at the producer: a failed path raises an `err(...)`. Match on the message, not on E99997.
- **Malformed `__target_intrinsic(spirv,"…")` snippets** crash instead of diagnosing. Emit an err-level diagnostic and gate SPIR-V emit on the error count; an empty snippet parses non-null, so it needs an explicit zero-instruction reject.
- **Empty callable/ray payload on SPIR-V** crashes (passed by address into a `spirv_asm` operand); pad the empty struct on the SPIR-V path (spec-correct).
- **`getDefaultVal`**: gate the `IRMakeStruct` branch on a POSITIVE "concrete-field-owning" predicate (`StructDecl|ClassDecl|GLSLInterfaceBlockDecl` + `hasBody && !aliasedType`), defer all opaque kinds to `emitDefaultConstruct`, and assert operand↔field parity in the consumer. A fieldless BUILTIN struct (`CoopMat`) passes it yet under-counts (#12556) and needs its own guard.
- **A classification predicate that includes an opaque decl kind** without proof that its fields materialize there is an OPEN_GAP, even when no crash reaches the assert today.
- **`static` opaque/resource globals are rejected on every target (E30076)** and `static const` fails E31226, so support is none. #13116 still excludes several resource kinds, so features that desugar globals into `static` shadows must be type-aware.
- **Array-of-struct entry-point OUTPUTS on SPIR-V/GLSL store `void_constant` (E99997/E99999)**; PR #10283's per-element fix was dropped before merge. Read the merged diff, not the PR body.
- **`CopyLogical` is valid only between a storage type and its layout-free twin under the SAME lowering config**, and only SPIR-V emit / `lowerCopyLogical` handle it. Decide by comparing lowering configs, not by target. When a PR changes a storage lowering, probe whole-value buffer-to-buffer copies (`sb[i].field = cb.field`) on Metal/CUDA/C++/WGSL.
- **An unspecialized `export`ed generic is `[keepAlive]` and reaches `legalizeSPIRV`, whose worklist descends into generic bodies** (#13744). Keep the pin through `linkAndOptimizeIR`; unpin and DCE only at the start of `legalizeIRForSPIRV`.
- **Link-time entry-point stripping** (#12564) interacts with `unexportNonEmbeddableIR`: ordinary precompile is unchanged; a positional `.slang-module` changes output, untested.
- **GPU-free testing**: the GPU-less harness silently ignores `filecheck=` SIMPLE tests; use `diag=CHECK`, or check `slangc -target spirv-asm` output directly.

## The shared `default:` abort in `legalizeInst`

`InternalError ... unexpected: non-simple operand(s)!` comes from the 4-arg `legalizeInst` switch in `slang-ir-legalize-types.cpp`. An empty `struct{}` type-legalizes to the `none` flavor; an inst that carries such a value as a non-simple `LegalVal` while its result type is not `none` falls to the shared `default:` arm, which drops silently only for a `none` result type and otherwise asserts.

`CallShader(0, d)` with an empty `struct{}` `d` aborts on `-target spirv` but not on GLSL or for a non-empty payload. The `case spirv:` arm stores the payload into a `[__vulkanCallablePayload] static Payload p` global and passes `&p` directly as a `spirv_asm` operand; the `case glsl:` arm passes a location integer. The fix pads the empty callable-data struct on the SPIR-V path; `OpExecuteCallableKHR` requires a real Callable Data variable, so it cannot be dropped ([CallShader empty payload](../learnings/1787658226580-callshader-empty-payload-crashes-only-on-spir-v-be.md)).

The same abort comes from autodiff: a differential context struct holding a resource plus an empty nested struct, on SPIR-V ≥1.4 (which skips `lowerCopyLogical`), keeps an `emitCopyLogical` between two pointers to the empty struct. There is no `case kIROp_CopyLogical`, so the fix adds one to the inner switch, `SLANG_RELEASE_ASSERT`s both operands are `none`, and returns `LegalVal()`; a copy between non-empty structs never reaches the inner switch because it runs only when `anyComplex==true`. Cascade: the last `cleanUpVoidType` ran BEFORE the final `legalizeEmptyTypes` ("Required for AD 2.0"), which re-introduced `void_constant` placeholders into emission, so a second `cleanUpVoidType` runs after the late pass ([empty copyLogical + void_constant ordering](../learnings/1787256041815-empty-copylogical-void-constant-ordering-in-spir-v.md)).

## glsl-legalize `assign`: array outputs

For `out T result[N] : SV_Target` in a fragment shader (slang#12653), the whole-array `OpStore` (`OpCompositeConstruct` + `OpUndef` for unwritten slots) originates in `slang-ir-glsl-legalize.cpp`, not the emitter. The `out` param becomes an addressable local, the output is one array-typed global var, and `assign(globalOutputVal, localVal)` falls to the `default` `materializeValue` case, a whole-array load+store of the partially-written local. The arrayIndex path (mesh outputs, `SV_ClipDistance`) does per-element stores. Narrowest fix: a per-element `getElementAddress` + load/store loop when both sides are `Flavor::address` of an array type ([out-array whole-array store](../learnings/1787241644886-spir-v-out-array-param-whole-array-store-root-caus.md)).

The same path has an array-of-struct WRITE gap. PR #10283 (fixes #9428, merged 2026-03-03) says `extractField` "handles array types by extracting per element (getFieldTypeThroughArrays)", but that code (aa3217fa6) was dropped in f6e762fc2 ("Simplify ... to null guards only"); master has only `if (!fieldType) return ScalarizedVal();`. Any array-of-struct under an entry-point OUTPUT (struct field, `out` param, nesting) on SPIR-V/GLSL runs `assign()` tuple arm → `extractField(Array value)` → `none` → `materializeValue(none)` = `getVoidValue` → `store(var, void_constant)` → E99997 "Unhandled global inst in spirv-emit: void_constant" (SPIR-V) or E99999 (GLSL). Reads work (`materializeTupleValue` special-cases array tuples). Locations are also wrong: the SoA per-field arrays get the per-element field offset unscaled (`a[2]@0`, `b[2]@1` overlap, VUID 08721) while reflection is element-major; GS-input and hull control-point arrays share `Flavor::array` and must stay unscaled. Workaround: split the array into separate fields; the dropped commit is at `git fetch origin pull/10283/head` (#13330 triage) [#10283 fix dropped before merge](../learnings/1790714513390-pr-10283-s-extractfield-array-fix-was-dropped-befo.md).

## `CopyLogical` validity is a property of the lowering-config pair, not the target (#13379)

In `slang-ir-lower-buffer-element-type.cpp`, `CopyLogical` is meaningful only between a storage type and its layout-free twin (the same `TypeLoweringConfig` with `lowerToPhysicalType=false`). Only the SPIR-V emitter and `lowerCopyLogical` handle it, and `lowerCopyLogical` is called only from SPIR-V legalization (`slang-ir-spirv-legalize.cpp` ~:2993). Storage types are cached per `(type, TypeLoweringConfig)` and the config includes the address space, so since #9341 a ConstantBuffer (Uniform) and RWStructuredBuffer (StorageBuffer) of one struct get two storage structs (`Args_natural_0` / `Args_natural_1`) even with matching layouts. The store path sent every `CastStorageToLogicalDeref` source to `copyLogical` (plain store only for equal pointee types), so `outS[0] = cb;` produced `IRCopyLogical` and `E99999 unexpected IR opcode` on GLSL/HLSL/WGSL/Metal/CUDA/C++ ([CopyLogical config-pair rule](../learnings/1790920411937-copylogical-validity-is-a-property-of-the-lowering.md)).

Instances by target:

- **Metal**: master ICEs for a default CB with a column-major `float3x3` copied into an SB, and for `outS[0] = *p` through a `uniform Args*` pointer. PR #13425 (honoring `ScalarDataLayout` on Metal CBs) exposed it for any scalar CB containing a `float3` [Metal has no lowerCopyLogical](../learnings/1791096341904-metal-has-no-lowercopylogical-two-storage-lowering.md). #13425 then added `canCopyStorageValueDirectly`: copy storage-to-storage only when the types are equal or when emitting SPIR-V directly, otherwise unpack and repack [#13425 canCopyStorageValueDirectly](../learnings/1791124516519-slang-ir-copylogical-emits-spir-v-only-ircopylogic.md).
- **WGSL**, with no opt-in: wherever `canUseStorageTypeInLocalVar()` is true, `struct In {float a; int b; float2 c;}` copied as `sb[0].i = cb.i` (std140 → std430) fails with `internal error[E99999]: unexpected IR opcode during code emit`. PR #13607 applies the same types-match-or-SPIR-V rule. Removing the ICE exposed a silent null-typed `VectorReshape` swizzle miscompile ([[wiki/concepts/slang-backends-wgsl-matrix-and-validation.md]]). #13607's 28-shape corpus (loads, field and element stores) missed it because no shape copied a whole buffer-resident composite to another buffer; /code-review found it [WGSL cross-layout copy ICE](../learnings/1791914522081-slang-buffer-lowering-a-cross-layout-whole-value-c.md).

**Supersession.** The target gate `shouldEmitSPIRVDirectly() || isTypeEqual` used by #13425 and #13607 is insufficient: on direct SPIR-V, cbuffer → `S*` user pointer pairs `OpTypeMatrix` with a `_MatrixStorage` wrapper and spirv-val rejects the `OpCopyLogical`. The principled test (slang#13379 / PR #13386) is `getTypeLoweringConfigFromInst(castDeref->getLayoutConfig()) == getLogicalTypeLoweringConfig(destConfig)`; otherwise unpack/pack through `convertOriginalToLowered.applyDestinationDriven`. As of 2026-10-06 both open PRs need reconciling to it. `-vk` slang-test rows report "Not Supported" in the no-GPU container even with lavapipe, so are CI-only (cause and local workaround on [[wiki/concepts/slang-rhi-backend-runtime.md]]) ([same](../learnings/1790920411937-copylogical-validity-is-a-property-of-the-lowering.md)). Running `lowerCopyLogical` after buffer-element lowering on Metal fixes most cases experimentally but is unvetted: its structural walk cannot bridge Metal packed vectors (see [buffer-element storage-type lowering](../concepts/misc-f0909b4-slang-compiler-and-test-facts.md)).

## The error-count gate: a failed path must raise an error, not a warning

`error[E99997] ... unexpected: ErrorType` has one mechanism. `SemanticsExprVisitor::visitSPIRVAsmExpr` has ~7 `failed=true` sites, each returning `CreateErrorExpr(expr)`. The front-end gate `if (getSink()->getErrorCount() != 0) return SLANG_FAIL;` keys on the ERROR count, not on whether any expr is error-typed. Six sites emit `err(...)`; the zero-operand `spirv_asm { OpNop %x; }` branch diagnosed `E29106 too many operands` as a **warning**, so the gate did not bail, lowering ran `lowerType` on the ErrorType, and `UNEXPECTED_CASE(ErrorType)` aborted. Rule: **a checker that sets an ErrorType must also raise the error count**; audit every `failed=true`/`CreateErrorExpr` path for an `err(...)`. Fix the producer's severity; teaching lowering to tolerate ErrorType masks the defect. `E99997` is a generic wrapper, so match on the message; `SLANG_UNEXPECTED` fires in Release too ([spirv_asm ErrorType leak](../learnings/1786527874805-spirv-asm-errortype-leak-a-warning-backed-failed-p.md)).

The fix (slang#12506, new error `E29118`) is the model confirmed-safe shape. What makes it approvable: the new diagnostic is a genuine, unique `err(`; the replaced warning is NOT flipped globally (it stays a warning for its other producer, the parser's missing-semicolon recovery); the invariant was verified across all sites; the fix is scoped to the failing branch; and `pr: non-breaking` is correct, because warn→error on already-invalid code is non-breaking in Slang (see #6216) ([confirmed-safe warn→error escalation](../learnings/1786804994084-approver-confirmed-safe-warn-error-escalation-that.md)).

## `__target_intrinsic(spirv,"…")` snippet crashes: crash-vs-diagnose, the empty-snippet gap, GPU-free repro

slang#13166/#13168/#13174 are the same crash-vs-diagnose shape, all reproducible GPU-free. `__target_intrinsic` is a **bare modifier keyword**, not an attribute: `[__target_intrinsic(...)]` is rejected as `E31000 unknown attribute` and never reaches the parser. The reachable form is a bodyless intrinsic, `__target_intrinsic(spirv, "OpNop foobar") int f();`, ordinary user code because the keyword lives in `baseLanguageScope` (`-target spirv-asm`). Sites in `SpvSnippet::parse` (`slang-ir-spirv-snippet.cpp`): `"OpNop foobar"` → `SLANG_UNEXPECTED` (:305); `"OpReturnValue %undef"` → `SLANG_ASSERT` (:192); `"OpTotallyBogusOpcode"` → `TextFormatException` (:128, caught :318) → null → E29000. That one still crashes: emit re-calls `getParsedSpvSnippet` and hits `SLANG_ASSERT(snippet)` in `emitIntrinsicCallExpr`, because `emitSPIRVFromIR` never checks `sink->getErrorCount()` after `legalizeIRForSPIRV` (E29000 prints twice, then the assert). With `SLANG_ASSERT` unset, asserts **throw** an InternalError reported as `E99997 ... compilation aborted` with exit 255, not a segfault ([snippet crash-vs-diagnose repro](../learnings/1789712060899-reproducing-target-intrinsic-spirv-snippet-crash-v.md)). The fix for the class: route failed user input to an err-level diagnostic, make `emitSPIRVFromIR` bail on sink errors after legalize, and assert only truly impossible shapes.

The gate alone misses #13174. An empty or whitespace snippet (`__target_intrinsic(spirv, "")`) is not a parse failure: `SpvSnippet::parse` allocates the snippet up front and returns null only on `TextFormatException`, so it returns a **non-null** snippet with an empty `instructions` list. `processCall`'s `if(!snippet) return;` misses it, nothing raises an error, and `emitSpvSnippet`'s `emittedInsts.getLast()` (`slang-emit-spirv.cpp:8663`) reads an empty `ShortList` → assert (E99997 exit 255 by default; SIGSEGV 139 under `release-assert-only`). The fix rejects `instructions.getCount()==0` in `validateSpvSnippet` (introduced by #13173) with E29001; E29000 ("snippet parsing failed") is the wrong message because the snippet parsed. It is a stacked follow-up on #13173's branch `fix/issue-13168`, respecting the reviewer's scope. Lesson: confirm malformed input actually reaches a null or error-raising path; a valid-but-empty object passes both a null-check and an error-count gate ([empty snippet is a non-null parse](../learnings/1789731117975-empty-spir-v-target-intrinsic-snippet-is-a-non-nul.md)).

Testing GPU-free: the GPU-less harness silently IGNORES `filecheck=` SIMPLE tests (no external LLVM `FileCheck` → `0/0, 1 ignored`); `DIAGNOSTIC_TEST:SIMPLE(diag=CHECK)` uses the built-in matcher and runs. Verify positive spirv-asm expectations with `slangc -target spirv-asm`. The disassembler prints **half** constants in hex (`OpConstant %half 0x1p-1`) and **float** constants in decimal (`OpConstant %float 0.5`). No production source uses string-snippet `__target_intrinsic(spirv,"…")` (grep prelude/ + source/ → 0; shipped code uses `spirv_asm { … }`), so hardening it is regression-free ([snippet emit tests](../learnings/1789726457708-spir-v-snippet-emit-tests-filecheck-local-ignore-h.md)). Git gotcha: `git push --force-with-lease` fails "stale info" after `git fetch origin <branch>` (fetch updates FETCH_HEAD, not the tracking ref); use plain `--force` once `git ls-remote` shows the remote tip is yours.

## `getDefaultVal` opaque kinds and the positive-predicate fix

`getDefaultVal(Type*)` in `slang-lower-to-ir.cpp` dispatches `DeclRefType` through an `else if` chain (`EnumDecl` → `InterfaceDecl` → `AssocTypeDecl` → general `AggTypeDecl` building a member-wise `makeStruct`). An opaque type with no `VarDecl` members yields a ZERO-operand `makeStruct`; once specialization resolves it to a scalar, emit produces `OpConstantComposite %scalar` with no constituents and spirv-val rejects it. The first fix diverted `AssocTypeDecl` alone, but `InterfaceDecl`, `ThisTypeDecl` and `GlobalGenericParamDecl` are sibling `AggTypeDecl` subclasses that still fell through. Probe: when a fix adds an `else if (declRef.as<X>())` divert before a catch-all aggregate branch, enumerate X's undiverted sibling subclasses; each is a candidate for the same bug ([AggTypeDecl siblings probe](../learnings/1786479489048-approver-challenger-miss-probe-getdefaultval-opaqu.md)).

The maintainer-endorsed resolution (slang#12712, merged) inverts the logic: gate the `AggTypeDecl → IRMakeStruct` branch on a POSITIVE concrete-field-owning predicate (`StructDecl|ClassDecl|GLSLInterfaceBlockDecl` + `hasBody && !aliasedType`), let all opaque `AggTypeDecl` kinds fall through to a deferred `kIROp_DefaultConstruct`, and add an operand↔field parity `SLANG_RELEASE_ASSERT` in the consumer. Review bar: a classification predicate that INCLUDES an opaque decl kind (associated type, `This`, global generic param, `SynthesizedStructDecl`/autodiff-context types, bodyless/aliased link-time structs) whose fields do not demonstrably materialize there is an **OPEN_GAP worth abstaining on**, even if no crash reaches the assert today. The bar: "prove the fields materialize right here (producer-to-consumer trace + test), or exclude the kind"; the shipped answer was exclusion ([opaque-decl inclusion is an OPEN_GAP](../learnings/1788298131000-approver-challenger-miss-unjustified-opaque-decl-i.md)).

The positive predicate does NOT cover a fieldless builtin. `(CoopMat[N])0`, an array cast from literal zero of a `linalg.CoopMat` (slang#12556, verified @ master b4853080d), emits a coop-matrix `OpConstantComposite` with ZERO constituents (SPV_KHR_cooperative_matrix requires exactly one scalar-splat constituent), a reachable miscompile (stored into the elements), not dead constant noise. `CoopMat` is an AST `StructDecl` (`hlsl.meta.slang:28268`, conforming `IArray<T>`) with only `__init`/methods and no instance `VarDecl` fields, so it passes the predicate, takes `IRMakeStruct`, and emits `emitMakeStruct(irType, 0)`, never reaching `emitDefaultConstruct` (`slang-ir.cpp` ~:4291), whose `kIROp_CoopMatrixType` case calls `emitMakeCoopMatrixFromScalar`. Any builtin that lowers to a non-struct IR composite but presents as a fieldless AST struct shares the trap. A single `(CoopMat)0` is refused by E30513 (`cannot-use-initializer-list-for-type`), but the array case slips through the WAR array exemption in `createInvokeExprForSynthesizedCtor` (`slang-check-conversion.cpp` ~:876-880); `struct W{CoopMat m;} w={};` and `CoopMat y;` with `-zero-initialize` compile correctly (real `__init()` call), so a checker-only reject fixes the miscompile but leaves the getDefaultVal divergence latent. Proof needs no spirv-val: `-target spirv-asm` shows `%N = OpConstantComposite %coopmatType` with nothing after the type id; `-dump-ir` shows the zero-operand `makeStruct` typed `CoopMatrixType`. It mirrors closed over-count #12104 (vector-conditional, a four-constituent float3); on a constituent-count failure, check both directions ([CoopMat array zero-init under-count](../learnings/1786776911052-coop-matrix-and-no-instance-field-builtin-aggregat.md)).

## `static` opaque/resource globals: rejected in the front end, legalization in flight (#13074/#13116)

`static Texture2D t = tp;`, `static RWStructuredBuffer b = bp;`, or a `static` struct containing a Texture fail on master f3775b9a5 with `E30076 global-var-cannot-have-opaque-type` on hlsl/spirv/glsl/metal/wgsl/cuda. The check is in `checkVarDeclCommon` (`slang-check-decl.cpp:3635-3647`, from #6098), so IR legalization never sees them. The note's suggested `static const` fails with `E31226` because a resource value is not const-foldable, so no supported spelling exists. The fix for #13074 is draft PR #13116, whose `legalizeResourceGlobalVars` lifts the statics into entry-point locals plus `in`/`out`/`inout` params; it still excludes parameter groups, combined samplers, Append/Consume buffers, acceleration structures, `__DynamicResource`, and structs that contain resources. So a feature that desugars globals into `static` shadows type-blind, such as #13306 (HLSL `-Gec` writable uniforms), breaks valid read-only declarations of those types; it needs a type-aware checker fallback, or a step that forwards a never-written shadow back to the original parameter. Parser detail: `__transparent` is not surface syntax. `TransparentModifier` comes only from `ParseBufferBlockDecl`; with an empty wrapper (GLSL interface-block call, `slang-parser.cpp:5989`) it yields a transparent struct-typed non-buffer variable that lookup sees through ([static opaque globals: E30076/E31226](../learnings/1790646292417-slang-rejects-static-opaque-resource-globals-in-th.md)).

## Unspecialized exported generics reach SPIR-V legalization (#13744, PR #13745)

`export` adds `[hlslExport]` and `[keepAlive]` to the outer `IRGeneric` (`slang-lower-to-ir.cpp` ~1462), so an unspecialized exported generic stays in the final IR on every target. Emitters skip `IRGeneric` (`slang-emit-c-like.cpp` ~5419), but `SPIRVLegalizationContext::processWorkList` has no case for it and its `default:` arm descends into the generic body (`slang-ir-spirv-legalize.cpp` ~2508). A concrete-type handler then crashes on an operand of type `T`: `processMakeCombinedTextureSamplerFromHandle` null-derefs in `getTextureTypeFromCombinedTextureSampler` (#13744). Under `spvDescriptorHeapEXT`, even a `getDescriptorFromHandle` override that only returns `defaultGetDescriptorFromHandle(h)` crashes, because the heap path inlines the combined-sampler branch into the generic body. Isolation: if removing `export` stops the crash, it is this pattern. Without gdb, a 6-line `LD_PRELOAD` SIGSEGV handler (`backtrace_symbols_fd`) plus `addr2line -C -f -e build/Debug/lib/libslang-compiler.so.*.dwarf <offsets>` symbolizes a stack in a minute; omit `-i` (times out on the 260 MB dwarf) (full kit on [[wiki/concepts/misc-f0909b3-slang-compiler-crash-triage.md]]) [exported generics survive to SPIR-V legalize](../learnings/1792330928974-exported-generics-survive-to-spir-v-legalize-any-g.md).

The pin must survive all of `linkAndOptimizeIR` and be dropped only at target legalization. Stripping it early (e.g. beside `unpinWitnessTables`) breaks passes that inspect them on purpose: `legalizeResourceGlobalVars` (#13116, above) and `checkUnsupportedInst`; `tests/bugs/13074/13074-static-resource-exported-generic.slang` fails if the generic is removed before them. PR #13745 calls `unpinGenerics(module)` and then `eliminateDeadCode` at the start of `legalizeIRForSPIRV`. Unpin plus DCE beats a "remove unused generics" loop, which misses a non-exported helper referenced only by the dead export. Side effect: SPIR-V-only diagnostics such as E41403 stop firing on an unused exported generic body; restoring them (validate the removed set before DCE) is on [[wiki/concepts/slang-compiler-probe-discipline-and-type-naming.md]]. On the L40S fleet host, `tests/cooperative-matrix/fp8-cuda*.slang` fails on master with `CUDA_ERROR_INVALID_PTX`: environment, not a regression [exported generics must stay pinned through linkAndOptimizeIR](../learnings/1792342789360-exported-generics-must-stay-pinned-through-all-of-.md).

## Link-time entry-point stripping and the SPIR-V export path

slang#12564 strips `IREntryPointDecoration` from any global `IRFunc` not in the selected `irEntryPoints` at the end of `linkIR`. It interacts with `unexportNonEmbeddableIR`, which strips `IRPublicDecoration`/`IRDownstreamModuleExportDecoration` from SPIRV funcs carrying `IREntryPointDecoration`; that branch no longer fires for de-selected functions. `collectMetadata` keys on export/layout decorations, not `IREntryPointDecoration`, so exported-function reporting and binding metadata are unchanged for the ordinary precompile (which selects ALL of a module's entry points). The one real change, found by codex: a `.slang-module` passed positionally has its entry-point list CLEARED, so a `[shader]`+export func in it has zero selected entry points → its `IREntryPointDecoration` is stripped → `unexportNonEmbeddableIR` keeps the export → it emits as a SPIRV linkage Export and is recorded in metadata. That change is arguably more correct (an unselected func is not an entry point) and untested. Lesson: verify each link of a critique's chain against source before accepting OR dismissing it; here the chain was sound but the practical severity low ([#12564 entry-point strip](../learnings/1786823215627-fix-12564-link-time-entry-point-strip-interaction-.md)).
