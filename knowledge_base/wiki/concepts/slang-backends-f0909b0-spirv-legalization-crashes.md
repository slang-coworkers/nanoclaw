## TL;DR

A family of `InternalError`/`SLANG_UNEXPECTED` aborts on the SPIR-V path share one shape: a value with a `LegalVal::none` / ErrorType / opaque representation reaches a legalization or lowering switch that has no case for it, and the `default:` arm asserts instead of handling it. Recurring root causes and fixes:

- **`non-simple operand(s)!`** in the 4-arg `legalizeInst` switch (`slang-ir-legalize-types.cpp`): an empty `struct{}` legalizes to the `none` flavor, but an inst whose *result type* is not `none` (a `spirv_asm` operand, a `copyLogical`) hits the shared `default:` that only drops silently when the result type is `none`. Fix by adding the specific case (assert both operands are `none`, return `LegalVal()`), safe because the inner switch is only reached when `anyComplex==true`.
- **`unexpected: ErrorType`** past the error gate: a checker set an ErrorType (`CreateErrorExpr`) but backed it with only a WARNING, so `getErrorCount()==0` didn't bail and the error-typed node leaked into lowering. Fix at the producer: make the diagnostic an `err(...)`, not `warning(...)`, so a failed path raises the error count.
- **empty callable/ray payload on SPIR-V** crashes because the `case spirv:` arm passes the payload by value/address into a `spirv_asm` operand, while `case glsl:` passes a location integer. Pad the empty struct on the SPIR-V path (spec-correct — `OpExecuteCallableKHR` needs a real variable).
- **`getDefaultVal` opaque-kind divert** builds a zero-operand `makeStruct` for opaque `AggTypeDecl` kinds; the principled fix is a POSITIVE "concrete-field-owning" predicate (`StructDecl|ClassDecl|GLSLInterfaceBlockDecl` + `hasBody && !aliasedType`) that defers all opaque kinds to `emitDefaultConstruct`, plus a consumer parity assert. **Caveat:** a fieldless BUILTIN struct (`CoopMat`) PASSES that positive predicate yet still under-counts — `(CoopMat[N])0` emits a zero-constituent composite (#12556) — so the fieldless-builtin case needs its own guard on top of the opaque-kind exclusion.
- **Link-time entry-point stripping** interacts with `unexportNonEmbeddableIR`; the ordinary precompile path is unchanged, but a positionally-passed `.slang-module` with a cleared entry-point list is a real (arguably-more-correct) output change with no test coverage.

## The shared `default:` abort in `legalizeInst`

The recurring SPIR-V crash is `InternalError ... unexpected: non-simple operand(s)!`, produced by the 4-arg `legalizeInst` switch in `slang-ir-legalize-types.cpp`. The mechanism, seen in multiple issues, is that an empty `struct{}` type-legalizes to the `none` flavor ("get rid of empty structs that often trip up the downstream compiler"), so any inst that carries such a value as a non-simple `LegalVal` while its *result type* is NOT `none` falls through to the shared `default:` arm — which drops silently only when the result type is `none`, else asserts.

`CallShader(0, d)` with `d` an empty `struct{}` is the clean example: it aborts on `-target spirv` but compiles fine on GLSL and for any non-empty payload, because the `case spirv:` arm stores the payload into a `[__vulkanCallablePayload] static Payload p` global and passes `&p` *directly* as a `spirv_asm` operand, while the `case glsl:` arm routes through a location integer — so only the SPIR-V arm carries an empty-struct value/pointer into an asm operand. The recommended fix pads the empty callable-data struct on the SPIR-V path (spec-correct: `OpExecuteCallableKHR` requires a real Callable Data variable, so you can't drop it) ([CallShader empty payload crashes only on SPIR-V](../learnings/1787658226580-callshader-empty-payload-crashes-only-on-spir-v-be.md)).

The same abort surfaced from autodiff: a differential context struct holding a resource + an empty nested struct, on SPIR-V ≥1.4, keeps an `emitCopyLogical` between two pointers to the empty struct (SPIR-V ≥1.4 skips `lowerCopyLogical`), whose pointer operands legalize to `none` but whose result type stays non-`none` — no `case kIROp_CopyLogical` → the shared abort. The principled fix adds `case kIROp_CopyLogical` to the inner switch, `SLANG_RELEASE_ASSERT`s both operands are `none`, and returns `LegalVal()`; this is safe because the inner switch is only reached when `anyComplex==true`, so a `copyLogical` between non-empty structs never reaches it. A cascading second bug in the same fix: the last `cleanUpVoidType` runs BEFORE the final `legalizeEmptyTypes` ("Required for AD 2.0"), which re-introduces `void_constant` placeholders that reach emission — fixed by a second `cleanUpVoidType` after the late legalize pass ([empty copyLogical + void_constant ordering in SPIR-V empty-type legalization](../learnings/1787256041815-empty-copylogical-void-constant-ordering-in-spir-v.md)).

The out-array whole-array store (slang#12653) is a related legalization producer bug rather than an abort: for `out T result[N] : SV_Target` in a fragment shader, the whole-array `OpStore` (`OpCompositeConstruct` + `OpUndef` for unwritten slots) originates in `slang-ir-glsl-legalize.cpp`, not the emitter — an `out` param becomes an addressable local, the array output is a single array-typed global var, and `assign(globalOutputVal, localVal)` falls to the `default` `materializeValue` case doing a whole-array load+store of the partially-written local. Contrast the arrayIndex path (mesh outputs, `SV_ClipDistance`) which does per-element stores. Narrowest fix: emit a per-element `getElementAddress`+load/store loop when both sides are `Flavor::address` of an array type ([SPIR-V out-array param whole-array store root cause](../learnings/1787241644886-spir-v-out-array-param-whole-array-store-root-caus.md)).

## The error-count gate: a failed path must raise an error, not a warning

A distinct abort family is `error[E99997] ... unexpected: ErrorType`. The mechanism: `SemanticsExprVisitor::visitSPIRVAsmExpr` has ~7 `failed=true` sites, each returning `CreateErrorExpr(expr)` (an ErrorType). The front-end gate `if (getSink()->getErrorCount() != 0) return SLANG_FAIL;` is what stops an error-typed expr from reaching `generateIR()` — but it keys on the ERROR count, not on whether any expr is error-typed. Six of the seven failed sites emit an `err(...)` diagnostic, so the gate bails. The exception is the zero-operand `spirv_asm { OpNop %x; }` branch, which diagnoses `E29106 too many operands` as a **warning** — so error count stays 0, the gate does not bail, lowering does `lowerType` on the ErrorType, and `UNEXPECTED_CASE(ErrorType)` aborts. The rule: **when a checker sets an ErrorType it MUST also raise the sink's error count**, or the node leaks past the gate; audit every `failed=true`/`CreateErrorExpr` path to pair with an `err(...)`, not a `warning(...)`. Fix at the producer (make the diagnostic an error), NOT by teaching lowering to tolerate an ErrorType (that masks the defect). Also: `E99997` is a generic wrapper — match on the message ("unexpected: ErrorType"), not the code, and `SLANG_UNEXPECTED` fires in Release too ([spirv_asm ErrorType leak = a warning-backed failed path slips past the error-count gate](../learnings/1786527874805-spirv-asm-errortype-leak-a-warning-backed-failed-p.md)).

The fix for that (slang#12506) is the model "confirmed-safe" shape for this class: turn the mis-severitied warning into an error (`E29118`) to restore the invariant "a semantically-failed path must raise the error count." The checks that make it approvable: the new diagnostic is genuinely an `err(` and unique; the replaced warning is NOT flipped globally (it stays a warning for its other legitimate producer, the parser's missing-semicolon recovery); the invariant was verified across all sites; the fix is scoped to the failing branch; and `pr: non-breaking` is correct — a warn→error escalation on already-invalid code is non-breaking in Slang (precedent #6216) ([warn→error escalation that restores a "failed-path raises error-count" invariant](../learnings/1786804994084-approver-confirmed-safe-warn-error-escalation-that.md)).

## `getDefaultVal` opaque kinds and the positive-predicate fix

`getDefaultVal(Type*)` in `slang-lower-to-ir.cpp` handles `DeclRefType` with an `else if` chain (`EnumDecl` → `InterfaceDecl` → `AssocTypeDecl` → general `AggTypeDecl` building a member-wise `makeStruct`). An opaque type with no `VarDecl` members produces a ZERO-operand `makeStruct`; once specialization resolves it to a scalar, the emitter yields `OpConstantComposite %scalar` with no constituents → spirv-val rejects. The original fix diverted `AssocTypeDecl` to `emitDefaultConstruct` one opaque kind at a time — but `InterfaceDecl`, `AssocTypeDecl`, `ThisTypeDecl`, and `GlobalGenericParamDecl` are ALL `AggTypeDecl` subclasses, so fixing one leaves untreated siblings falling through to the same zero-operand `makeStruct`. The transferable probe: when a fix adds an `else if (declRef.as<X>())` divert inside a type-kind dispatch with a catch-all aggregate branch, pull X's base-class hierarchy and enumerate every SIBLING subclass not diverted before the catch-all — each is a candidate for the same bug ([getDefaultVal opaque-kind divert is incremental — check AggTypeDecl siblings](../learnings/1786479489048-approver-challenger-miss-probe-getdefaultval-opaqu.md)).

The maintainer-endorsed resolution (slang#12712, merged) inverts the logic: gate the `AggTypeDecl → IRMakeStruct` branch on a POSITIVE "concrete-field-owning" predicate (`StructDecl|ClassDecl|GLSLInterfaceBlockDecl` + `hasBody && !aliasedType`), letting all opaque `AggTypeDecl` kinds fall through to a deferred `kIROp_DefaultConstruct`, plus an operand↔field parity `SLANG_RELEASE_ASSERT` in the consumer.

A distinct UNDER-count instance the #12712 positive predicate does NOT cover: `(CoopMat[N])0` — an array cast-from-literal-zero of a `linalg.CoopMat` (slang#12556, verified @ master b4853080d) — emits an `OpConstantComposite` of coop-matrix type with ZERO constituents, invalid SPIR-V (SPV_KHR_cooperative_matrix requires exactly one scalar-splat constituent), a reachable miscompile (stored into the array elements) not dead constant noise. The reason it survives #12712: `CoopMat` is an AST `StructDecl` (`hlsl.meta.slang:28268`, conforming `IArray<T>`) with ONLY `__init`/methods and ZERO instance `VarDecl` fields, so it PASSES the positive `StructDecl + hasBody && !aliasedType` predicate, takes the `IRMakeStruct` branch, iterates zero instance fields, and emits `emitMakeStruct(irType, 0)` — never reaching the fallback `emitDefaultConstruct` (`slang-ir.cpp` ~:4291) whose `kIROp_CoopMatrixType` special-case calls `emitMakeCoopMatrixFromScalar` (the one-scalar splat). The same trap applies to ANY builtin type that lowers to a non-struct IR composite but presents as a fieldless AST struct — so the concrete-field-owning predicate needs a further guard for fieldless builtin structs, not just non-`StructDecl` opaque kinds. Two narrowing facts: the SINGLE `(CoopMat)0` is refused by E30513 (`cannot-use-initializer-list-for-type`), but the ARRAY case slips past it because `createInvokeExprForSynthesizedCtor` has a WAR exemption for array types (`slang-check-conversion.cpp` ~:876-880); and a struct wrapper `struct W{CoopMat m;} w={};` plus a single `CoopMat y;` with `-zero-initialize` BOTH compile correctly (real `__init()` call, not the empty makeStruct), so the misfire is specific to the `(T[N])0` array-cast path — a checker-only reject fixes the miscompile but leaves the getDefaultVal divergence latent. Proving it needs no spirv-val binary: `-target spirv-asm` shows the empty constituent list directly (`%N = OpConstantComposite %coopmatType` with nothing after the type id), and `-dump-ir` shows the culprit `makeStruct` with zero operands typed `CoopMatrixType`. Family: this is the under-count mirror of closed #12104 (SPIR-V vector-conditional over-count — a FOUR-constituent float3); when you see a constituent-count validation failure, check both directions ([Coop-matrix (and no-instance-field builtin aggregate) array zero-init: getDefaultVal emits a fieldless makeStruct instead of the type-aware splat](../learnings/1786776911052-coop-matrix-and-no-instance-field-builtin-aggregat.md)). The sharpened review lesson: if a classification predicate INCLUDES an opaque decl kind (associated type, `This`, global generic param, `SynthesizedStructDecl`/autodiff-context types, bodyless/aliased link-time structs) whose concrete fields do NOT demonstrably materialize there, treat it as an **OPEN_GAP worth abstaining on — NOT cleared merely because no crash reaches the assert today**. The maintainer's accepted bar is "prove the fields materialize right here (producer-to-consumer trace + test), or exclude the kind"; the shipped resolution was exclusion, not a downstream-guard argument ([unjustified opaque-decl inclusion in a classification predicate is an OPEN_GAP](../learnings/1788298131000-approver-challenger-miss-unjustified-opaque-decl-i.md)).

## Link-time entry-point stripping and the SPIR-V export path

Reviewing slang#12564 (strip `IREntryPointDecoration` from any global `IRFunc` not in the selected `irEntryPoints` at the end of `linkIR`): the interaction to verify is with `unexportNonEmbeddableIR` (which strips `IRPublicDecoration`/`IRDownstreamModuleExportDecoration` from SPIRV funcs carrying `IREntryPointDecoration`). After the fix strips the decoration earlier, that branch no longer fires for de-selected functions; `collectMetadata` keys on export/layout decorations (not `IREntryPointDecoration`), so exported-function reporting and binding metadata are unchanged for the ordinary precompile (which selects ALL of a module's entry points). The one real behavior change is an edge case found by codex: a `.slang-module` passed positionally has its entry-point list CLEARED, so a `[shader]`+export func in it now has zero selected entry points → the fix strips its `IREntryPointDecoration` → `unexportNonEmbeddableIR` no longer strips the export → it emits as a SPIRV linkage Export and is recorded in metadata. This is a real output/metadata change but arguably MORE correct (an unselected func is not an entry point), with no existing test coverage. The reusable lesson: verify each link of a critique's chain against source before accepting OR dismissing it — here the chain was mechanically sound but the practical severity low ([Fix #12564 link-time entry-point strip: interaction with unexportNonEmbeddableIR](../learnings/1786823215627-fix-12564-link-time-entry-point-strip-interaction-.md)).
