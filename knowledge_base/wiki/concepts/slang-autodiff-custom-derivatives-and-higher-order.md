# Slang Autodiff: Custom Derivatives Through Interfaces and Higher-Order Composition

Split from [[wiki/concepts/slang-autodiff-ir-autodiff-differentiation.md]] (internals and design rules) and a companion to [[wiki/concepts/slang-autodiff-diagnostics-and-testing.md]]. This page covers the September 2026 cluster in which a user-supplied derivative (`[BackwardDerivative]`, `[ForwardDerivative]`, `[*DerivativeOf]`, `[PrimalSubstitute]`) is silently replaced by the auto-derivative when it is called through an interface (#13301), together with the higher-order composition crashes that turned up while reviewing that fix (`fwd_diff(fwd_diff(f))`, `bwd_diff(fwd_diff(f))`: #13320, #13321, #13322, #13323, #13327). The no-gdb crash-localization tooling used throughout lives in [[wiki/concepts/misc-f0909b3-slang-compiler-crash-triage.md]].

## TL;DR

- **A call through an interface requirement (existential, generic `<T:I>`, dynamic dispatch) silently runs the AUTO-derivative instead of a custom `[BackwardDerivative]`/`[ForwardDerivative]`.** Side-effecting gradient scatters vanish, and once such a caller exists the direct concrete call in the same module can lose the override too.
- **Root cause (#13301): two conformances, one witness symbol, first wins.** `checkDifferentiableCallableCommon` synthesizes a default `IForward/IBackwardDifferentiable` extension at SignatureChecked; `translate{Fwd,Bwd}DerivativeAttributeToAD2` adds a second one for the user derivative at ReadyForLookup. Both lower to the same mangled witness name and the merged table keeps the default's entries. Tell: one witness table with two `[export]`s in `-dump-ir-before specializeModule`.
- **The attribute-on-primal fix (skip the default when the decl carries its own derivative attribute) does not cover `[BackwardDerivativeOf]` or `[Differentiable][PrimalSubstitute(g)]`.** `*DerivativeOf` needs a single extension whose members are bound before conformances, because its primal resolution looks up the default members.
- **Library workaround on released compilers:** make the requirement's witness a plain `[ForceInline][Differentiable]` forwarder and put `[BackwardDerivative]` on a private, statically dispatched helper. Removing `[Differentiable]` from the conformer instead gives E38110. Extension methods are not requirements and are unaffected, so a test suite that only uses them stays green.
- **To tell which derivative ran**, make the custom derivative deliberately wrong (d=10 where auto gives 3), add a call counter, and anchor FileCheck values with `{{^}}`.
- **`bwd_diff(fwd_diff(f))` crashes on master even for `f(s)=s*s` (#13321, since #9808 / AD 2.0).** Debug asserts at the unchecked `cast<IRFuncType>` in `TypeFlowSpecializationContext::analyzeCall` (`slang-ir-typeflow-specialize.cpp:4795`). Every repro that uses the bwd-of-fwd form lands on that frame, so restate a candidate bug as `fwd_diff(fwd_diff(g))` beside a plain-`g` control, and check it in a Debug build.
- **A `diffVal` assert at `slang-ir-autodiff-fwd.cpp:2098` means some callee took the silent `if (!diffCallee)` branch in `ForwardDiffTranslationContext::translateCall`.** Find which one with a temporary `fprintf` after `tryGetAssociationOfKind`, then fix the producer that should have registered the annotation, not the consumer.
- **Making a crashing callee resolvable can turn a neighboring crash into a silent wrong gradient.** After such a fix, also differentiate a function that CALLS the newly-resolvable form; E38037 is keyed on callee opcodes and misses `lookupWitness(Synthesized...WitnessTable, key)`.
- **Before counting a code-traced crash against a patch, run it on pristine master and in the sibling form that avoids the changed path.** When a predicate gains several cases, revert-drill each case alone.

## Symptom: custom derivatives bypassed through interface calls

Consider `struct V : I` implementing a `[Differentiable]` requirement with `[BackwardDerivative(f_bwd)]`. A call through the requirement (an existential `I` param, a generic `<T:I>`, or real dynamic dispatch) runs an AUTO-derivative of the primal body instead of `f_bwd`, with no diagnostic; once such a caller exists, the direct concrete call in the same module loses the custom bwd too. Side-effecting scatters (DiffTensor-style `grad += d`) vanish, so a body of all-`no_diff` reads yields an empty backward. Verified on master 68563d2f3 and 2026.13.1 with `slang-test -cpu`, so it predates #13234. The discriminator: make the custom bwd deliberately wrong (e.g. `d=10` for `f=3s`) and add a call counter; a result of 3 with counter 0 means the override was bypassed. SlangPy impact: `IDiffTensor` via `src[idx]` works, because the auto-diffed subscript getter calls the concrete load statically, but `src.load(idx)` directly on an `IDiffTensor` param gives zero gradients. SlangPy's `DiffTensor` is NOT `IDifferentiable` (`difftensor.slang:374`), so its gradients flow only through `load`'s custom bwd ([custom [BackwardDerivative] on an interface-requirement impl is silently ignored via interface/generic calls](../learnings/1790639544574-slang-custom-backwardderivative-on-an-interface-re.md)).

## Root cause (#13301): two conformances share one witness symbol

The root cause was verified with IR dumps on master 68563d2f3 [[Differentiable] + [Backward|Forward]Derivative creates two conformances; the default wins through interface calls (#13301)](../learnings/1790689225165-slang-autodiff-differentiable-backward-forward-der.md). Consider a method `[Differentiable][BackwardDerivative(read_bwd)] float read(float s)` on `struct V : I`. Two front-end passes each give `read` a differentiability conformance:

1. `checkDifferentiableCallableCommon` (`slang-check-decl.cpp:15624`) runs at `SignatureChecked` and unconditionally synthesizes default `extension f : IBackwardDifferentiable<f>` / `IForwardDifferentiable<f>` conformances whose members are auto ops (`BackwardDifferentiatePrimal`, `BackwardRemat`, `ForwardDifferentiate`).
2. `translate{Fwd,Bwd}DerivativeAttributeToAD2` runs later, at `ReadyForLookup`, and adds a second conformance for the user derivative. `extendContainerDecl` always creates a new extension rather than reusing the first one.

Both conformances lower to the same witness symbol (`getMangledNameForConformanceWitness`), and the merged table keeps the default's entries because the first one wins. A call through the interface requirement therefore runs the auto-derivative. The tell is in `-dump-ir-before specializeModule`: one witness table carrying two `[export]`s. Direct concrete calls look correct only because the caller's associations (annotation kinds 4/5/7/9) point at the custom members. A generic caller's `lookupWitness` folds to the concrete method after `specializeModule` and attaches a second `apply` annotation, and the default wins there too; that is how a generic caller elsewhere in the module breaks the concrete path.

The fix for the attribute-on-primal spelling is a producer-side one: skip the default synthesis when the decl carries its own `[ForwardDerivative]`/`[BackwardDerivative]`, so each role has exactly one conformance, instead of adding a preference rule at witness merge.

## Spellings the attribute-on-primal fix does not cover

With that patch applied (fix-13301.patch; CPU probes on 2026-09-29, master 4fe660083), existential, generic, and dynamic calls are correct for the attribute-on-primal spelling. Two other spellings still silently use the auto-derivative through an existential, while their concrete calls stay correct [the #13301 bug persists for *DerivativeOf and [Differentiable][PrimalSubstitute]; two pre-existing higher-order segfaults](../learnings/1790691457543-slang-autodiff-the-custom-derivative-through-inter.md):

- `[Differentiable] read` plus `[BackwardDerivativeOf(read)] read_bwd`: the existential call gives 3 where 10 is expected. The `DerivativeOf` path never adds the attribute to the primal's modifiers (the same inverse-placement asymmetry described on the internals page: `registerAssociatedDecl` without `addModifier`), so a skip keyed on the primal's attributes cannot see it. It also cannot be fixed at header time, because its primal resolution looks up the default members; it needs a single extension whose members are bound before conformances are formed [#13301 root cause](../learnings/1790689225165-slang-autodiff-differentiable-backward-forward-der.md).
- `[Differentiable][PrimalSubstitute(g)] read`, where `g` is `[Differentiable][BackwardDerivative]`: the existential call gives 3. A plain `[PrimalSubstitute(g)] read` without `[Differentiable]` is correct (10/10).

## Library-side workaround until the compiler fix ships

A library can avoid #13301 on released compilers by keeping `[BackwardDerivative]` off the requirement's witness. Consider SlangPy's `DiffTensor` `load` requirement. The witness becomes a plain forwarder, and the custom derivative moves to a private helper that is not a requirement:

```slang
[ForceInline][Differentiable]
T load(I idx[D]) { return _load_custom(idx); }        // the requirement's witness

[Differentiable][BackwardDerivative(_load_bwd)]
T _load_custom(I idx[D]) { ... }                      // private, statically dispatched
```

Default synthesis is now correct for the forwarder, because it has no custom derivative for a second conformance to lose. Its body calls the helper statically, so the helper's `[BackwardDerivative]` is used even when `load` is reached through an interface. The workaround was verified on Slang 2026.16.1 and 2026.18.3 for SlangPy's DiffTensor load/store via `IDiffTensor`/`IWDiffTensor`/`IRWDiffTensor`, including a generic `<T:IDiffTensor>` called from a concrete wrapper (gradients went from 0 to 3). Removing `[Differentiable]` from the conformer instead fails with E38110 "callable differentiability requirement not satisfied". Extension methods on `TensorType : IDiffTensor`, such as SlangPy's int-scalar `load(int i0)`, are not requirements and are unaffected. SlangPy's only interface-differentiation test (`test_tensor.slang:282`) goes through that extension path, which is why its CI stays green. Tracked as slangpy#1204 ([#13301 workaround: forwarder witness plus a private custom-derivative helper; dropping [Differentiable] gives E38110](../learnings/1791189874294-slang-13301-workaround-keep-backwardderivative-off.md)). The GPU-free CPU repro recipe used for it is on [[wiki/concepts/slangpy-build-and-infra-operations.md]].

## Higher-order composition crashes (#13320-#13323)

Probing the #13301 fix exposed pre-existing higher-order crashes on master (slangc rc 139) that are independent of the patch. The first probe listed two: `fwd_diff(fwd_diff(f))`, where `f` is a member `[ForwardDerivative(read_fwd)][Differentiable]` method and `read_fwd` is not `[Differentiable]` (the free-function version correctly gives E30027), and `bwd_diff(fwd_diff(f))` with a differentiable custom fwd on a member method [two pre-existing higher-order segfaults](../learnings/1790691457543-slang-autodiff-the-custom-derivative-through-inter.md). Dropping the repro's extra features one at a time showed that none of them mattered for the second crash: composed `bwd_diff(fwd_diff(f))` crashes even for `f(s)=s*s`, and has since #9808 (AD 2.0, v2026.7). It was filed as #13321. The failing site is the unchecked `cast<IRFuncType>(resolvedCallee->getDataType())` at `slang-ir-typeflow-specialize.cpp:4795`. No test covers the composed form; only the wrapper form is tested (`tests/autodiff/high-order-backward-diff-1/-2`) [backtrace a Debug SLANG_ASSERT without gdb; found #13321](../learnings/1790695170333-backtrace-a-slang-debug-slang-assert-on-linux-with.md).

**#13321 confounds other higher-order repros.** In Debug, the #13321 E99997 assert is that `cast<IRFuncType>` in `TypeFlowSpecializationContext::analyzeCall`. Any other bug whose repro uses the bwd-of-fwd composition lands on the same frame, so the symptom alone cannot separate the two. To isolate a candidate, restate it as `fwd_diff(fwd_diff(g))` beside a plain-`g` control that compiles (rc 0). Do this in a Debug build: Release segfaults only on the bwd-of-fwd form, and on fwd-of-fwd the unchecked cast happens not to crash. Example, #13323: with `-disable-non-essential-validations`, the forward-mode "differentiating a bwd_diff result" backstop (`slang-ir-autodiff-fwd.cpp:3561`) diagnoses E38037 and then returns the untranslated `ForwardDifferentiate`, so any higher-order use of it ICEs at the same `:4795` cast. The first-order case, which `tests/autodiff/high-order-backward-diff-3.slang` covers, is clean [a higher-order crash repro can be confounded by #13321; isolate with fwd_diff(fwd_diff(...))](../learnings/1790704234870-a-higher-order-autodiff-crash-repro-can-be-confoun.md).

**`diffVal` asserts: find the callee that lost its association.** #13320's Release build showed a null deref in `getRootAddr`; Debug showed the real first failure, `SLANG_ASSERT(diffVal)` at `slang-ir-autodiff-fwd.cpp:2098` (`translateDifferentialPairGetElement`) [crash/assert backtrace without gdb; #13320 worked example](../learnings/1790693974366-getting-a-slang-crash-assert-backtrace-without-gdb.md). The call feeding that assert almost always took the silent `if (!diffCallee)` branch in `ForwardDiffTranslationContext::translateCall` (fwd.cpp around line 1372), which returns a null differential with no diagnostic. To find which callee lost its association, put a temporary `fprintf(stderr, ...)` right after `tryGetAssociationOfKind(primalCallee, ForwardDerivative)` and print `getIROpInfo(primalCallee->getOp()).name`, the callee's `IRNameHintDecoration`, the op and name hint of operand(0), and whether `diffCallee` is null. Rebuild Release (about 2 minutes for one file on a warm tree) and compare against a working control. For #13322, the generic-calling-an-interface-method path printed `ForwardDifferentiate(PlainView.read) -> diffCallee=NULL`, while the concrete path printed `-> lookupWitness`. `tryGetAssociationOfKind` is an identity lookup over `IRAnnotation` uses (`tryLookupAnnotation` in slang-ir.cpp), so the fix belongs with the producer that should have registered the annotation. #13320 (invalid code that needs a diagnostic) and #13322 (valid code, a regression from #9808) end in the same consumer branch but have different producers. Workaround for #13322: an unused concrete `[Differentiable]` function that calls the same method registers the association module-wide [pin which association lookup fails with a one-line fprintf in translateCall (#13320/#13322)](../learnings/1790697944674-autodiff-higher-order-pin-which-association-lookup.md).

## Reviewing the #13321 fix: resolvable is not the same as correct

The #13321 patch replaced `poison(void)` in the IR-synthesized `fwd_diff(f) : IBackwardDifferentiable` witness with a real `LegacyBackwardDifferentiate` entry, which made `bwd_diff(fwd_diff(f))(...)` work. But a `[Differentiable]` function that *calls* the composed form, when it is itself `bwd_diff`'d or `fwd_diff`'d, went from a segfault to a **silently wrong gradient** instead of error E38037; the wrapper form still gets E38037. The reason is that E38037 is keyed on `isBackwardDerivativeValue(callee)` (slang-ir-autodiff.cpp), which checks callee opcodes. The composed callee is `lookupWitness(SynthesizedBackwardDerivativeWitnessTable(...), key)`, so it slips past both the front-end check and the translation backstops. Review rule: when a fix makes a previously-crashing callee resolvable, also probe "differentiate a function that calls it" [making a crashing autodiff call resolvable can turn an adjacent crash into a silent wrong gradient](../learnings/1790698803515-making-a-crashing-autodiff-call-resolvable-can-tur.md).

The same review chain produced two corrections to read-only, code-traced findings. First, examples that Reviewer A "worked out from code, not run" need running: its `__constref` ICE claim was unreachable because the front end rejects that code first with E38034 [same](../learnings/1790698803515-making-a-crashing-autodiff-call-resolvable-can-tur.md). Second, in round 2 A reported a null deref in the patch's new legacy bwd_diff witness entry under `-disable-non-essential-validations`. The repro did crash (rc 139), but it crashed identically on pristine master and in the wrapper form (`bwd_diff(wf)` with `wf` wrapping `fwd_diff(ggg)`), which never reaches the new entry. The crash was pre-existing, and A's suggested guard (keep the poison) would have restored master's crash as well. So A/B every traced crash on a pristine build, and in the equivalent form that avoids the changed code path, before counting it against a patch. Also, when a predicate gains several cases (here four `BuiltinRequirementKind` roles), drill each case alone: deleting only `case BwdApplyFunc:` left the new tests passing, but `__apply(fwd_diff(f))` inside a `[Differentiable]` function (which needs `-experimental-feature`) went back to compiling silently. That exposed a load-bearing but untested branch [before accepting a code-traced new-crash finding, run it on pristine master and in the sibling form](../learnings/1790702192345-before-accepting-a-code-traced-new-crash-finding-r.md).

## Probe, test, and build tips for this cluster

- One test file can cover several rows: `//TEST:COMPARE_COMPUTE(filecheck-buffer=ROW):-cpu -shaderobj -output-using-type -Xslang... -DROW -X.` [#13301 testing tips](../learnings/1790689225165-slang-autodiff-differentiable-backward-forward-der.md).
- Anchor values with `{{^}}10.0`, because `10.0` otherwise matches `110.0`. A deliberately wrong custom derivative plus a call counter shows which derivative ran (same atom).
- `slang-test` writes `<test>.actual.txt` next to a failing COMPARE_COMPUTE test; a deliberately failing `// CHECK: SHOW_ME` dumps the whole output buffer [probe-harness tip](../learnings/1790691457543-slang-autodiff-the-custom-derivative-through-inter.md).
- When an old release compiles a higher-order form and master crashes (#13327, a third-order derivative), prove the old output was *right*, not just rc 0, with a g++ host harness over its `-target cpp` output; v2026.5.2 computed `6 6 12`. Procedure on [[wiki/concepts/misc-f0909b3-slang-test-verification.md]] [prove an old release's -target cpp output is correct with a g++ host harness](../learnings/1790705791676-prove-an-old-slang-release-s-target-cpp-output-is-.md).
- Lean worktree builds: `SLANG_ENABLE_SLANGD=OFF` breaks configure because slang-test depends on slangd. Build `slang-numerics-modules`, `slang-functional-module`, `slang-neural-module`, `slang-workgraph-module`, and `slang-glsl-module` before running the full suite, otherwise about 60 tests fail with "cannot open file slang/numerics/...". `tests/dispatcher/smoke.slang` needs the `slang` dispatcher binary [#13301 build tips](../learnings/1790689225165-slang-autodiff-differentiable-backward-forward-der.md).
