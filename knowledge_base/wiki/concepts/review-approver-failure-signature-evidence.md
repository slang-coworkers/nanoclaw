# PR-Approver: Execution-Coverage Holds, Failure-Signature Discipline & Human-Agreement Joins

## TL;DR

**Execution coverage: reading is not running.**
- Source-verified-correct code can still fail once the backend executes. An execution-coverage hold is not pedantry: a composition bug is invisible to source review and appears only when the path runs.
- Test-mask *registration* (a backend listed in the `GPU_TEST_CASE` mask) is not *execution* (a real GPU runner ran it). Resolve job → `runs-on` → hardware and open a log. A mask reads as reassuring, so this error turns a live gap into a dismissed one.
- A coverage gap IS closable, but the proof is the job LOG plus a per-backend tally delta, never a green job (a fully-skipped backend still prints `SUCCESS`). Confirm the device initialized, grep case names with their backend suffix for `PASSED`, and require the delta to equal the number of newly-unmasked cases.
- Closing your prior gap does not mean the PR is covered. Re-derive the gap against *this* revision's new lines, tracing forward from the changed lines to an executing test.
- In a skip-based harness a removed or commented-out assertion is a silent-green regression. Ask "if the condition this asserted regressed, what would CI do?" Guards that skip *unavailable* devices are blind to bugs that *cause* unavailability.
- Wrapper/import APIs: validation lives in the backend (read it, for every backend; coverage is often uneven), and "CI green" on a wrapper PR usually means *compiles*, not *runs*.

**Failure signatures: parse the whole set, then choose the level of evidence.**
- Never characterize a multi-failure signature from a sample. Script-parse every row, assert the count matches the reported total, bucket, and cross-tab per case. Test a functional claim before writing it (group by index; several distinct actuals at one index kill a "`result[i] == i`" story).
- A heterogeneous signature does NOT imply a heterogeneous cause. Prefer one mechanism until excluded, and exclude it by checking observation points, not the distribution's shape.
- When the output resists explanation, read the INPUT CONTRACT: the test source and the interface the code actually receives.
- Compare Debug vs Release as ordered tuples, not counts. Only a byte-identical ordered tuple licenses "deterministic, not UB/race."
- A control proves nothing until its confounds are enumerated: print every attribution field of both arms. A rerun on a `runs-on` label-set pool is an independent draw, i.e. an experiment.

**Human-agreement joins: an approval is evidence about the axis the approver EXAMINED.**
- A human APPROVE is not a general safety certificate. Compare `submitted_at` before crediting an approval with a finding (same SHA is necessary, not sufficient), and score the join on byte content (sha256 the changed files), not line totals.
- "The push satisfies the ask" is the maintainer's call. Only the author of a blocking review can clear it. A cleanly-satisfied ask calls for a *narrow* withhold. A tasking message's framing is recorded, never decisive.
- A merge landing mid-decision must not retro-fit the verdict: decide on your own evidence, then join, and compare the human's objection axis with your withhold axis.
- Flagged code DELETED before it earned an approval scores CHANGES_REQUESTED. A consumer-side recovery helper is a producer-bug flag.
- OUT_OF_SCOPE is a repo-class / conflict-of-interest predicate, never "the diff is docs."
- "N sources agree" is a claim about PROVENANCE: state the shared-failure event you ruled out. A refuted premise is not a refuted conclusion; re-describe it, and carry any retraction into the recorded ledger field.

## Execution coverage

**Source-verified-correct code failed once the backend ran.** slang-rhi#802 (Metal bindless `DescriptorHandle`) was held at ABSTAIN_POLICY/`OPEN_GAP` purely on coverage: the source matched the slang#10842 fix-shape spec, but its two new Metal cases SKIPPED on macOS CI. After slang-rhi#807 fixed Metal device init, #802 went red on exactly those two cases (17 + 60 assertion failures). Every mechanism was individually right (`getDeviceAddress()+offset`, `gpuResourceID()._impl`, the `static_assert` on `sizeof(MTL::ResourceID)`); the composition was wrong, and only running it showed that. Attribute by counting `.metal` result rows per branch: main has 205 rows with `bindless-*.metal` absent, #802 has 207 with both FAILING, so the delta of 2 equals the cases #802 registers and the regression is introduced, not inherited. Check skip *reasons*, not the skip count: none of the 76 remaining `.metal` skips was `device not available` (ray tracing 59, timestamp 12, combined tex-sampler 2), which separates "feature-gated" from "not running at all" ([[approver/calibration] slang-rhi#802 — a source-verified-CORRECT implementation still FAILED once Metal executed: exec-coverage holds are not pedantry](../learnings/1785766869937-approver-calibration-slang-rhi-802-a-source-verifi.md)).

**Registration is not execution.** A #1090 report called a coverage gap "fixed upstream", citing `GPU_TEST_CASE("buffer-from-handle", D3D12 | Vulkan | Metal)` at `11eefdc6`. Registration was true; execution needs a runner with a real Metal GPU (`ci.yml:48-49` runs macos-aarch64 on `runs-on: macos-latest`), and nobody had checked. State coverage at the strength established, e.g. "registered for Metal at `<sha>`; execution unconfirmed, no rhi CI log opened", and never let a mask fix retire a gap on its own ([[approver/challenger-miss] test-mask registration is not test execution — resolve the job → `runs-on` → hardware, and prefer a run log over inference](../learnings/1785787084796-approver-challenger-miss-test-mask-registration-is.md)).

**Closing a gap: the job log plus a tally delta.** `slang-rhi-tests` prints one row per (test, backend), and a fully-skipped backend still prints `Status: SUCCESS!`, so the job conclusion says nothing about a backend. The checklist: (1) pin log provenance (`HEAD is now at` names your head); (2) confirm the device initialized (`Metal: supported` plus the `Features:`/`Capabilities:` block; an `Apple Paravirtual device` adapter is fine); (3) grep the case names with the backend suffix and require `PASSED`; (4) diff the tally against the baseline branch (Metal 129 PASSED/76 SKIPPED on main → 132/76 at head = +3, the three newly-unmasked cases; a mask edit that did not take shows +0); (5) check Debug and Release legs separately. Then name the load-bearing assertion: `compareComputeResult` against GPU-written `{16,32,32,64}` on zero-initialized buffers carries weight, while a `-zero` case expecting `{0}` would pass if the dispatch did nothing. Before honoring a bot finding, reconcile its rendered diffstat with the pinned head: Devin's stale 🔴 showed `2 files +8 −5` and `Loading diffs…` against the PR's `3 files +11 −8`, while CodeRabbit named its range explicitly. That atom's residency corollary is retracted; do not cite that part ([[approver/calibration] slang-rhi#800 — an execution-coverage OPEN_GAP is CLOSABLE; the job log plus a per-backend tally delta is the proof](../learnings/1785770830139-approver-calibration-slang-rhi-800-an-execution-co.md)).

**Re-scope the gap to the revision's own new code.** slang-rhi#801 R1 abstained on a Metal-only import API masked to `D3D12|Vulkan`. R2 widened the mask to Metal *and* rewrote the implementation as an intrusive linked list. `buffer-from-handle.metal` then PASSED on both legs (tally 132→133) while never touching the list. Do not diff the old withhold reason against the new evidence and stop; ask which lines are new here and what executes them. CodeRabbit independently flagged the same gap at the same head ("a regression in `insert` or `erase` for duplicate base addresses would still pass"). Record the old gap CLOSED and the new one re-scoped, so the ledger shows progress rather than a repeated withhold. That atom's claim that the map is dead code on Apple-Silicon runners is polarity-corrected: a feature-tier name is not a capability check ([[approver/calibration] closing a coverage gap can UNCOVER a new one — re-scope the gap to the revision's own new code](../learnings/1785776756858-approver-calibration-closing-a-coverage-gap-can-un.md)).

**A removed assertion in a skip-based harness is a silent-green regression.** slang-rhi#807 (`Temporarily disable metallib_4_0 capability`) moved its only assertion on that capability from `CHECK(hasCapability(metallib_4_0) == (macOSMajorVersion >= 26))` to `CHECK_FALSE(...)` in R1, then commented it out in R2. The harness turns probe failure into a skip: the availability probe compiles a trivial shader, and failure returns `RETURN_NOT_AVAILABLE` (`tests/testing.cpp:1002`), which is exactly what the upstream bug slang#12325 causes. Every Metal `GPU_TEST_CASE` then resolves to `SKIP("device not available")` (`:1124`), and the silent-skip guard exempts devices that were never available (`:1234-1240`). Re-enabling the capability before the fix therefore shows green CI with zero Metal coverage. Do not grade an assertion deletion on diff size or on a "temporary/maintainer/tracked" label. Severity can be LOW when the loss is confined to the workaround's self-pinning, but it is still a gap when the TODO anticipates the re-enable ([[approver/challenger] a skip-based test harness makes a removed assertion a SILENT-GREEN regression](../learnings/1785764961019-approver-challenger-a-skip-based-test-harness-make.md)).

**Wrapper and import APIs.** For slangpy#1090 `Device::create_buffer_from_native_handle`, two probes decide it. (1) Read the backend before accepting a missing-validation finding. Devin's "no size validation" was true at the slangpy layer and wrong as a finding: slang-rhi's Metal backend checks handle type, null value, device match and `desc.size > nativeBuffer->length()`, returning `SLANG_E_INVALID_ARG`, which `SLANG_RHI_CALL` raises in Python. Vulkan and D3D12 only type-check, so an oversized `desc` can cause OOB access; enumerate every backend plus the base-class default. (2) Check whether the path runs anywhere: does this PR add a test, does one exist, does any CI job execute the path on the target backend? Green CI with zero executing tests on a memory-corruption path is an OPEN_GAP. Cheap clears: byte-diff an extracted helper against the original body before treating it as new (that made CodeRabbit's 🟡 pre-existing); a documented lack of lifetime tie is the design of an import API, but confirm the retain/release side and that guards are `SGL_CHECK` (throws in release), not `SGL_ASSERT` (compiles to `{}`). Step-0 recall is a lead: a recalled learning describes the revision it was written against (#801's mask had since been widened), so re-verify its predicate at the pinned commit ([[approver/challenger] native-handle import APIs — probe the backend layer, and check the path actually executes](../learnings/1785786230423-approver-challenger-native-handle-import-apis-prob.md)).

## Failure-signature discipline

**Parse the whole failure set.** slang-rhi#802's red CI got three wrong characterizations from three reviewers. Reviewer A, expecting non-residency, said "the buffers read all zeros." The approver, expecting handle/slot plumbing, said "`result[i] == i` where `expected == i+1`." Across all 77 assertions the truth was a mixture: 56 zero and 21 shifted (10/7 on `bindless-buffers.metal`, 46/14 on `bindless-textures.metal`). The index claim was falsified outright, since at `logged: i := 0` the actuals were `0.0`, `1.0`, `3.0` and `5.0`. Each reviewer read the head of the list and matched it to the hypothesis they brought; 77 rows is long enough that nobody reads them all and short enough that it feels as if you did. Script-parse every row, assert the count, bucket and cross-tab per case, and group by index before claiming a function of the index. A wrong signature sends the fixer to the wrong subsystem ([[approver/challenger-miss] parse the WHOLE failure set before naming a signature — two reviewers read the same 77 assertions and each found the hypothesis they brought](../learnings/1785767276013-approver-challenger-miss-parse-the-whole-failure-s.md)).

**Read the input contract.** The third reading had complete, correct data and still concluded "a mixture, so no single cause." One mechanism explains both classes, and it was not in the output. On Metal a top-level `uniform ....Handle` is emitted as an ordinary directly-bound parameter with its own `[[buffer(n)]]`/`[[texture(n)]]` slot (a deliberate unwrap at `slang-emit-metal.cpp:148-152` in `v2026.12.2`, required by a #11066 regression test), so values written via `setDescriptorHandle` are never read. Grouping rows by assertion phase shows it: phase-1 reads return `0` because nothing is bound, and phase-2 read-backs return each RW resource's unmodified seed because the writes never landed (`rwTexture1DArray L1` seeds `{3,4}`, observed `3,4`, expected `4,5`, which is why every shifted row has `diff == 1.00`). The order is: group failures by phase or target (fresh read, or read-back of an earlier write?); read the test source; read the emitted interface (`slangc test.slang -target metal -entry computeMain -stage compute`, no GPU needed); only then name a cause. Refining the observation feels like progress while yielding ever more precise wrong answers ([[approver/challenger] when a failure signature resists explanation, stop refining the observation and read the INPUT CONTRACT](../learnings/1785767986973-approver-challenger-when-a-failure-signature-resis.md)).

**Enumerate a control's confounds.** On slang#12322's `test-compile-regression spirv-val [0/866]`, I cited a reproduction on the unrelated branch `fix/issue-12333` as proof that the failure was not runner-specific. I had varied branch and never read the runner field: both arms ran on `runner=SLANGWIN5`, so the control held the suspect constant and carried zero bits. For each arm, print `runner_name`, `head_sha`, `run_attempt`, `head_branch` and `conclusion` and read the columns; if the intended factor and a confound both differ, build the off-diagonal cell. Enumerated properly, 300 runs separated fully (SLANGWIN5 0/3, SLANGWIN4 1/0, SLANGWIN10X64-1 1/0), including a within-head pair on `ba156ebf5c90` (attempts 1-2 on SLANGWIN5 failed, attempt 3 on SLANGWIN4 passed). `runs-on: [Windows, self-hosted, regression-test]` is a label set, not a hostname, so a rerun on an unchanged head is an independent draw that manufactures the cross-runner control. Read `runs-on` before reasoning about routing, and never infer a dispatch property ("this job always lands here") from a defect property ("this failure looks environmental") ([a control that varied branch while silently holding runner constant read as decisive and proved nothing](../learnings/1785839459802-approver-clause-gap-a-control-that-varies-the-inte.md)).

## Human-agreement joins

- **Order the approval against the finding.** On slang-rhi#807 `ccummingsNV` APPROVED the pinned head at `13:29:00Z` and CodeRabbit posted the actionable comment at `13:29:19Z`: the approval predates the finding by 19 seconds, which GitHub's UI hides by showing both "on this commit." Sub-minute ordering is common when a bot re-reviews a fresh push. Prove identity with bytes: sha256 both changed files at the decided head and at the merge commit (`compare` alone showed `ahead_by 1 / behind_by 2`). When `pulls/<n>/reviews` is hook-blocked, `issues/<n>/timeline` has the same rows with `state`, `submitted_at` and `commit_id`. The row scored as conservative agreement, not a false-safe; the job log later showed `Image: macos-26-arm64`, proving the deleted `CHECK_FALSE` was load-bearing ([[approver/human-agreement] slang-rhi#807 — a fresh independent APPROVE that predated the finding by 19s; ABSTAIN scored as conservative agreement](../learnings/1785766473587-approver-human-agreement-slang-rhi-807-maintainer-.md)).
- **Only the blocking reviewer clears the block.** slang-rhi#800 R3 was clean on every axis (6/6 clauses, CodeRabbit clean, both Devin 🔴 resolved, coverage gap closed), leaving only skallweitNV's undismissed `CHANGES_REQUESTED`. The orchestrator framed it as "likely stale-but-unwithdrawn — factor it as a satisfied request." The approver held ABSTAIN_POLICY(CHALLENGER_CONCERN), narrowed to that review alone, at 15:26:00Z; skallweitNV APPROVED the same head at 15:26:51Z and merged 7 s later. A cleanly-satisfied ask predicts a fast resolution, so state that the substance is clean and the sole blocker is review state, without padding. Record the tasking framing, say you did not adopt it, and say why. Read the live aggregate `reviewDecision` via GraphQL; the individual review carries an old commit oid and looks stale ([[approver/human-agreement] second confirmation — holding at ABSTAIN over a standing undismissed CHANGES_REQUESTED resolved as clean agreement](../learnings/1785771033293-approver-human-agreement-second-confirmation-holdi.md)).
- **Decide first, join second.** slang-rhi#801 merged mid-decision: the reviewer holding the standing review APPROVED the head and merged 8 s later. Their objection was performance ("lots of heap allocations where previously there were none"), which the revision discharged; nobody examined the coverage gap on the rewritten structure. A withhold on a different axis from the human's is policy-consistent withholding, neither false-safe nor clean agreement. Note the timestamp order in the challenger field so an auditor can see the verdict was not back-fitted, and record per commit (R1 joined CHANGES_REQUESTED, R2 joined APPROVED). Never inherit a caveat without trying a second access path: `/branches/main/protection` 403s for an integration token while `/branches/main` returns the protection summary ([[approver/human-agreement] a merge landing mid-decision must not retro-fit the verdict](../learnings/1785776775891-approver-human-agreement-a-merge-landing-mid-decis.md)).
- **Deleted flagged code vindicates the flag.** On slang#11667 the ABSTAIN(OPEN_GAP) at `ad924934` flagged `findTargetOptionalType` (`slang-ir-lower-optional-type.cpp:185`) as a null-deref risk. Maintainer `saipraveenb25` rejected the approach ("compensating for an earlier regression in `isConcreteType()`, rather than fixing the producer"); as merged, `isConcreteType` returns `true` for `IRStructType` and the recovery helper was deleted. A consumer-side helper that recovers information that should already exist (walking phi args, users, substitution or witness chains) is evidence of a malformed upstream shape. Name the producer, check whether it changed (`git log -S<producerFn>`), and treat that regression as the leading hypothesis; slang's CLAUDE.md names this smell, so the methodology doc is a calibration oracle. Two joins share the shape (slang#12095, slang#11667): the head moved, flagged code was deleted, nobody approved the pinned commit, so the pinned row scores CHANGES_REQUESTED ([[approver/human-agreement] a consumer-side recovery helper is a producer-bug flag — vindicated on slang#11667](../learnings/1785782767710-approver-human-agreement-a-consumer-side-recovery-.md)).

**OUT_OF_SCOPE is a repo-class predicate.** slang-rhi#806 (one-line README license fix "MIT" → "Apache 2.0 with LLVM Exception", bot-authored, harvest exit 20, 6/6 clauses) looked like the PRs that fired `ABSTAIN_POLICY:OUT_OF_SCOPE:<docs-class>` on nanoclaw#1007, website #204/#207/#208/#209 and neural-shading#15. The precedent atoms show all of those fired on repo class (non-compiler repo) or conflict of interest, never on docs shape, and in-domain docs PRs were decided on merits both ways (#12082 → WOULD_APPROVE; #12090 → ABSTAIN on a merits OPEN_GAP). Grep precedent atoms for the predicate that fired, not the outcome. WOULD_APPROVE was earned, not rounded up: `LICENSE:1` and `.reuse/dep5` agree, `commits?path=LICENSE` shows MIT → Apache in #111 (so README was the stale artifact and docs→LICENSE is the right direction), the whole README was read, and manifests were grepped separately (`"license": "MIT"` escapes a prose grep). Join: merged at the head, skallweitNV APPROVED with `commit_id == head`. Keep the OUT_OF_SCOPE families repo/COI-scoped (`website-content`, `course-materials-docs`, `approver-harness`, `nanoclaw-changelog-docs`) and add no bare "docs" family ([[approver/human-agreement] in-domain docs PR decides on MERITS — OUT_OF_SCOPE is a REPO-class predicate, not a "diff is docs" predicate](../learnings/1785784245128-approver-human-agreement-in-domain-docs-pr-decides.md)).

**Independence is provenance, not count.** The #806 claim of "two independent authoritative sources" was wrong in the word doing the work: `bc7657abfac8` (#111) wrote both files in one commit. The one-call check (`commits?path=<B>` → length and oldest SHA) was run on `LICENSE` and never on `dep5`. Ask what single event could make both sources wrong: one commit writing two files, code and its own comment, a bot review and the PR body it summarized, two CI legs sharing a runner image or cache, a test asserting what the same commit implemented. State the shared-failure event you ruled out, not the number of sources. When caught, re-describe: shared origin in a REUSE-compliance commit is weak corroboration of the value but strong evidence of deliberate, repo-wide intent with README:14 the lone dissenter, so the corrected framing was stronger. The retraction must reach the recorded `approval_decisions` row ([[approver/challenger-miss] "N sources agree" is a claim about provenance, not count — and the retraction must reach the recorded ledger field](../learnings/1785785616042-approver-challenger-miss-n-sources-agree-is-a-clai.md)).
