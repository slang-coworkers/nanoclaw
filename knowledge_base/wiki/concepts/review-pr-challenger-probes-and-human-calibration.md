# PR Approver: Challenger Probes and Human-Verdict Calibration

The approver deep-dive (2026-07-15 fold, parts 2/3 and 3/3): how the critique gate records a review round, the fallback-tier verdict enum, the transferable catalog of challenger red-flag probes, and how the shadow-mode ledger's eventual human merge is read as calibration data. Sibling pages carry run-recovery/polling and branch-delivery/diff-reading.

## TL;DR
- **A fallback-tier (Devin/CodeRabbit) heuristic 🔴 is NOT an auto-BLOCK.** BLOCK is reserved for a 🔴 the challenger independently VERIFIED reproduces; a REFUTED fallback 🔴 terminates ABSTAIN_POLICY:CHALLENGER_CONCERN — never BLOCK, never round up to WOULD_APPROVE. Recording a BLOCK asserts a verified red bug to the ledger, as wrong as rounding up.
- **A refuted 🔴 does not become WOULD_APPROVE**, and a standing human `CHANGES_REQUESTED` caps the verdict at ABSTAIN. Never round up.
- **The critique gate records a round only from a FRESH `mcp__codex__codex` call** carrying the canonical `/codex-critique` `developer-instructions` verbatim. A `codex-reply` reuses the thread's original instructions, carries no `developer-instructions`, and never records. Run DECISION_REVIEW and OUTPUT_REVIEW as separate fresh calls.
- **Doc-consistency checks read the WHOLE file, not just diffed lines** — a changed default/flag/API name leaves stale copies in un-diffed narrative; the same applies to duplicated code.
- **Memoization/caching PRs: CI-green on the pinned head is a HARD precondition for WOULD_APPROVE.** A static-CLEAN audit never rounds toward approve — the collision bug is exactly the input nobody enumerated, invisible to static reasoning by construction.
- **When a change casts away a qualifier the target toolchain treats as a real semantic guarantee, demand target-arch execution coverage or lean ABSTAIN** — static/source review cannot clear a hardware-level miscompile.
- **`closed-unmerged` ≠ rejection.** On `pr_closed` with `merged=false`, read WHO closed it and any supersede/fold cross-reference before scoring a human verdict; an author-closed fold is benign and must not score as a false-safe.
- **Protected-path (`.github/**`) ABSTAIN_POLICY that later merges with the protected file intact + a human approval is a CORRECT terminal decision** — recorded agreement-neutral (ABSTAIN rows are excluded from agreement scoring), never a false-safe.
- **A maintainer self-merge with zero formal reviews is `NO_HUMAN_REVIEW`, not `APPROVED`** — recording APPROVED fabricates an agreement signal.
- **Every revision gets a fresh challenger.** The pre-existing/attribution base-diff test cuts BOTH ways: a clean fix-commit can introduce a NEW blocking finding; an enumerated-exception invariant is a completeness trap unless you enumerate every case yourself.
- **A green regression test proves nothing unless it would have gone RED on the pre-fix code.** Reconstruct the pre-fix output shape and confirm the assertion rejects it.
- **Scope a "regression" escalation against the release baseline (master), not an earlier commit in the PR's own iteration** — intra-PR add-then-revert churn is not a PR-introduced regression.

## Critique-Gate Recording: Only Fresh codex Calls; Doc-Consistency and the gh-api False-Positive

The critique gate records a round **only from a fresh `mcp__codex__codex` call carrying the canonical `/codex-critique` `developer-instructions` block verbatim** — a `mcp__codex__codex-reply` reuses the thread's original instructions, carries no `developer-instructions`, and never records regardless of its verdict; run DECISION_REVIEW and OUTPUT_REVIEW as SEPARATE fresh calls, reserving `codex-reply` for must-fix re-verification within an already-recorded stage ([critique gate records only codex calls, never codex-reply — OUTPUT_REVIEW must be a fresh call](../learnings/1784020599916-approver-critique-mustfix-critique-gate-records-on.md), [OUTPUT_REVIEW must be a FRESH codex call with the canonical reviewer developer-instructions](../learnings/1784095230054-approver-critique-mustfix-output-review-must-be-a-.md)).

The gate's `gate-critique-on-deliver.sh` PreToolUse hook **false-positives read-only `gh api .../pulls/<n>/reviews` GETs** (its `gh api [^|]*pulls\b` pattern is not verb/subpath-aware) and escalates to a hard admin block after 3 denials — poll reviews via `gh pr view --json reviews` (no `pulls` substring), build any unavoidable `pulls/...reviews` path from shell variables, and never write a file in the same command as a read ([critique-gate false-positives read-only gh api .../pulls/<n>/reviews GET](../learnings/1784077601519-approver-infra-abstain-critique-gate-false-positiv.md)).

Two OUTPUT_REVIEW must-fixes on doc completeness and provenance: a **doc-consistency check must read the WHOLE file, not just diffed lines** — a changed default/flag/API name leaves stale copies in un-diffed narrative/architecture tables (fetch the full body at the pinned head, grep for the OLD value and "default"), and the same "did an un-diffed sibling copy go stale?" question applies to duplicated code ([doc-consistency check must read the whole file, not just diffed lines](../learnings/1784019216454-approver-critique-mustfix-doc-consistency-check-mu.md)).

## Fallback-Tier Verdict Discipline: BLOCK Requires VERIFIED

A **fallback-tier (Devin/CodeRabbit) heuristic 🔴 is NOT a Step-2 auto-BLOCK** — Step-4's enum reserves BLOCK for a *verified* 🔴, and Step-3's fallback note routes an unsure verdict to the challenger: a fallback 🔴 becomes BLOCK only if the challenger VERIFIES it, and if the challenger REFUTES it the terminal is ABSTAIN_POLICY:CHALLENGER_CONCERN (never BLOCK, never round up to WOULD_APPROVE) — recording BLOCK asserts a verified red bug to the ledger, which is as wrong as rounding up ([fallback-tier heuristic red-flag: Step-2 BLOCK requires Step-4 VERIFIED, else ABSTAIN not BLOCK](../learnings/1784080988551-approver-critique-mustfix-fallback-tier-heuristic-.md)).

The recurring instance is Devin's static "Repo rule" flags on a **`removeAndDeallocate`-without-use-check pass**: clearing it requires proving the op's *zero-use invariant* from op-semantics + all producers/consumers tree-wide (Void result type ⇒ no well-typed consumer; sole producer; every consumer discards it), NOT the current diff — and residual holds (unasserted front-end invariant, one-level traversal relying on prior `specializeModule`) support ABSTAIN, they don't block ([removeAndDeallocate-without-use-check pass: prove the op's zero-use invariant, not just this diff](../learnings/1784081016635-approver-challenger-miss-removeanddeallocate-witho.md)).

Likewise, a **"pre-existing risk"/UAF claim on IR insts needs a memory-model proof, not a deref-site analogy** — Slang IRInsts are arena-allocated and `removeAndDeallocate` does NOT free backing memory (it only unlinks), so a "removed" inst stays valid, readable arena memory until the IRModule dies; reading a scalar field like `scratchData` on it is stale-but-valid ([pre-existing risk claims need a memory-model proof — IRInsts are arena-allocated, never individually freed](../learnings/1784095223530-approver-challenger-miss-pre-existing-risk-claims-.md)).

The mirror-image discipline applies to *dismissing* a 🔴: a **"transient IR is deleted so its invalid SSA doesn't count" argument needs a PROVEN no-observer path, not an assertion** — identify every pass between the invalid state's creation and its removal and show none trips on it; if you can't trace it, the concern is un-cleared (ABSTAIN_POLICY:CHALLENGER_CONCERN, not WOULD_APPROVE) — and BLOCK on an unproven 🔴 is equally wrong, reserved for a 🔴 you independently verified reproduces ([\"transient IR is deleted\" needs a proven no-observer path, not an assertion](../learnings/1784042674528-approver-critique-mustfix-transient-ir-is-deleted-.md)).

Finally, a **`const_cast`-away-`const` on a CUDA `__grid_constant__` kernel param can miscompile at the hardware level on a specific arch/driver (sm_100/NVRTC) — static/source-level review + language-semantics reasoning cannot clear it** (four WOULD_APPROVE false-safes on slang#12080 before the author pivoted to a forward-only design with NVRTC `COMPARE_COMPUTE` coverage); when a change casts away a qualifier the target toolchain treats as a real semantic guarantee, demand target-arch execution coverage or lean ABSTAIN (OPEN_GAP: "correctness only verified at source level") ([const_cast-away-const on a CUDA grid-constant kernel param can miscompile at the hardware level](../learnings/1784045721338-approver-false-safe-const-cast-away-const-on-a-cud.md)).

## Challenger Probes: the Transferable Red-Flag Catalog

A batch of domain-specific challenger probes, each a reusable "when you see X, check Y":

- **Autodiff zero-differential**: a zero/identity tangent synthesized via `emitDefaultConstructRaw` instead of `getDifferentialZeroOfType` is a silent-miscompile for a user `IDifferentiable` whose `dzero()` ≠ default-construct; grep the diff for `emitDefaultConstruct` used as a differential value and demand a non-default-`dzero()` regression test ([autodiff zero-differential must use getDifferentialZeroOfType, never emitDefaultConstructRaw](../learnings/1784017388229-approver-clause-gap-autodiff-zero-differential-mus.md)).
- **Capability-atom narrowing**: a new atom `B : A` means B⇒A not A⇒B; an emitter branch rewritten `if impliesCap(A)` → `if impliesCap(B) … else SLANG_UNEXPECTED` silently drops every A-but-not-B target to an abort — probe whether a formerly-covered coarse-atom config falls through to abort, extra-suspicious when the PR's own tests switch `-capability` from the coarse to the narrow atom (sidestepping the regression) ([rev1 CI-unverified ABSTAIN vindicated: pre-6.9 SLANG_UNEXPECTED edge became a confirmed 🔴](../learnings/1784026245321-approver-challenger-miss-rev1-ci-unverified-abstai.md)). The corollary: a **type-emitter diagnostic can't guard an overload that lacks the type operand** — after a capability-narrowing regression is "fixed" by a diagnostic keyed on emitting a TYPE, enumerate every sibling op in the family; a no-type-operand overload (e.g. `ReorderThread(uint,uint)`) still silently miscompiles ([a type-emitter diagnostic can't guard an overload that lacks the type operand](../learnings/1784047648527-approver-challenger-miss-a-type-emitter-diagnostic.md)).
- **Switch-completeness / one-consumer-shape recovery helpers**: a missing `case` in an unwrapping/translation switch is a high-value probe whenever a PR layers a helper on top of it; and a recovery helper that reconstructs type info from ONE SSA consumer shape (branch→phi) then `SLANG_RELEASE_ASSERT`s silently assumes that's the only shape — cross-check the producer predicate (does it gate on consumer shape?) against the recovery predicate, grepping for other consumers (`IRReturn`/`IRCall`/`IRStore`) ([recovery helpers keyed on one SSA consumer shape need the whole-consumer-set probe](../learnings/1784035598289-approver-challenger-miss-recovery-helpers-keyed-on.md)).
- **Widening a coercion's viability**: interacts with overload resolution — making more constructors viable in a `canCoerce` probe can make one brace-init match multiple overloads, so the fix must produce a *diagnosed ambiguity* (with an ambiguity regression test), not a silent pick ([widening a coercion's viability interacts with overload resolution](../learnings/1784048815957-approver-human-disagreement-widening-a-coercion-s-.md)).
- **Dedup/canonicalization "make N producers agree" fixes**: a change to how ONE producer derives an operand can re-introduce the very duplicate the PR removes — enumerate every producer, find each one's input set, and prove the changed branch's trigger is disjoint across producers OR applied symmetrically; a "add a `hasContent()`/null guard?" review ask is safe only if it's a proven no-op on ALL producers or applied to all (adding it to one *creates* divergence) ([dedup/canonicalization fixes: prove the two producers operate on disjoint inputs](../learnings/1784057320031-approver-challenger-dedup-canonicalization-fixes-p.md), ['add a hasContent()/null guard?' asks — verify it's not a no-op AND applied symmetrically](../learnings/1784048758044-approver-challenger-add-a-hascontent-null-guard-re.md)).
- **Memoization/caching PRs**: correct only if the cache KEY captures every input parameterizing the result — the collision bug is exactly the input the author (and reviewer) didn't enumerate, invisible to static reasoning by construction, so **CI-green on the pinned head is a HARD precondition for WOULD_APPROVE and never substitutes a static-CLEAN audit or a 0-bug review** ([memoization/caching PRs: a static-CLEAN audit never rounds toward approve — CI is authoritative](../learnings/1784078519306-approver-false-safe-memoization-caching-prs-a-stat.md)). Deterministic failures of the SAME pre-existing generic-specialization tests across ≥2 runners (while the PR's own new tests pass) is the "cache hit on new path, cache collision on old paths" signature → hard BLOCK ([memoization PR breaks generic specialization → wrong-count ctor call + missing intrinsic](../learnings/1784076799325-approver-challenger-miss-memoization-pr-breaks-gen.md)). The BLOCK was vindicated when the author's next revision ripped out exactly the cross-environment cache — the safe/unsafe boundary for a lowering cache is *environment scope* (env-local safe; cross-env global unsafe), and re-review by DIFFING the revision confirms a surgical fix ([a CI-driven BLOCK on a memoization PR was vindicated by the author's next-revision fix](../learnings/1784093692254-approver-confirmed-safe-a-ci-driven-block-on-a-mem.md)). When a static audit *does* clear such a PR, the probes are: prove the two dispatch paths (`dispatch`==`dispatchType`, byte-identical) are semantically identical when they collide on a key; for a cross-env cache enumerate ALL context fields and show the `parent==moduleInst` guard excludes every env-varying one (structural IR-parenting proof); and tree-wide grep the counter/out-param convention (`*ioDiff =` bare assignment) rather than a partial file list ([Val-lowering memoization audit — dispatch==dispatchType and the module-parent guard](../learnings/1784074914750-approver-challenger-miss-val-lowering-memoization-.md)). Relatedly, **substitute-override / convention-every-override-obeys audits must enumerate ALL override files tree-wide** (`_substituteImplOverride` lives in `slang-ast-type.cpp` too, not just val.cpp/decl-ref.cpp), and verify the *consumer contract* (boolean-zero vs magnitude) when a change stores-and-replays a running counter ([substitute-override audits must cover every _substituteImplOverride file](../learnings/1784054408743-approver-challenger-miss-substitute-override-audit.md)).
- **CSS/HTML-table PRs**: `table-layout:fixed` + a widthless column = data-column collapse; enumerate every `<col>` the generator can emit, confirm a width rule for each, and sum declared widths for EVERY feature-flag combination — not just the one the diff comment mentions ([CSS table-layout:fixed + widthless columns = data-column collapse](../learnings/1784040257325-approver-challenger-miss-css-table-layout-fixed-wi.md)).
- **Submodule pins**: a `.gitmodules` entry with no `branch =` verifies (via `check-submodule-commits.sh`) against the remote's DEFAULT BRANCH, NOT a same-name version tag — clear it only by proving `git merge-base --is-ancestor <pin> origin/<default-branch>` and confirming the `check-submodules` CI conclusion, not by a "tag-reachable" analogy ([submodule no-branch pin verifies against default branch not the same-name tag](../learnings/1784074301503-approver-challenger-miss-submodule-no-branch-pin-v.md)). A **CMake fetched-dep version bump can silently disable hash integrity when a `SLANG_HASH_VERSION` guard lags the fetch version** — a "hash refresh" is inert (or the bump is what FIRST turns verification on) unless `fetch_version == hash_version` post-change; green download+verify build check-runs corroborate ([CMake fetched-dep version bump can silently disable hash integrity when SLANG_HASH_VERSION lags](../learnings/1784011130054-approver-challenger-miss-cmake-fetched-dep-version.md)).
- **Regression-test discrimination**: a green regression test proves nothing unless it would have gone RED on the pre-fix code — reconstruct the pre-fix output shape and confirm the assertion rejects it; for FileCheck a missing-operand bug needs an end-anchored `CHECK-NOT: … %{{[0-9]+}}{{$}}`, since trailing operands are optional in a bare `CHECK` ([a regression test that 'looks well-formed' must also FAIL on the pre-fix code](../learnings/1784070693213-approver-challenger-miss-a-regression-test-that-lo.md)).
- **CI-green snapshot vs settled CI**: the `commits/<sha>/status` combined API reflects only checks reported at read time — a still-`in_progress`/`queued` job can go red minutes later, so never generalize "zero red checks" while jobs are pending; scope any CI-load-bearing claim to COMPLETED checks by name, and treat unsettled/red CI as *removing* corroboration (pushing toward ABSTAIN under conservative-lean) ([CI 'green' snapshot is not settled CI](../learnings/1784042664032-approver-challenger-miss-ci-green-snapshot-is-not-.md)). A **macOS "requires metal4.0" pipeline-creation failure can be a Slang emit/downstream-`-std` capability mismatch, NOT the #11973 runner flake** — a version-gated emit paired with a hard-coded lower downstream `-std` is a compiler bug (the `[Slang]: ERROR:` prefix is a tell); name it as a candidate root cause rather than collapsing to "environmental" ([a macOS 'requires metal4.0' failure can be a Slang emit/downstream-std bug, not the #11973 flake](../learnings/1784083878096-approver-challenger-miss-a-macos-requires-metal4-0.md)).
- **Every revision gets a fresh challenger**: the pre-existing/attribution base-diff test **cuts BOTH ways** — a clean fix-commit push can still introduce a NEW blocking finding elsewhere in the file, and an enumerated-exception invariant ("holds for all Y except {A,B,C}") is a completeness trap unless you enumerate every Y yourself; don't let a WOULD_APPROVE streak lull you into skipping a fresh review's new findings ([the pre-existing/attribution test cuts both ways; enumerated-exception invariants are a completeness trap](../learnings/1784011508988-approver-challenger-miss-the-pre-existing-attribut.md)). A **still-present false claim the current revision's review didn't re-list is still a live gap** (the challenger re-checks carried-over diff content), and a **regression escalation must be scoped against the release baseline (master), not an earlier commit in the PR's own iteration** — a guard the author added-then-reverted within one PR is intra-PR churn, not a PR-introduced regression ([scope a 'regression' escalation against the release baseline, not an earlier commit in the PR's own iteration](../learnings/1784055067504-approver-challenger-miss-scope-a-regression-escala.md)). Devin repeatedly asserting "glossary complete and accurate" while missing counterexamples is zero-weight for completeness — it echoes the PR narrative.

**Free revert-drill: use the prebuilt UNFIXED slangc to empirically test a FileCheck-coverage gap.** When a review flags a 🟡 of the form "this regression is only caught by the Apple-only METALLIB compile; the CI-runnable METAL *text* checks would still pass on the buggy emit" (slang#12887), whether a FileCheck pattern actually *rejects* the buggy emit is a precise, decidable property that depends on the exact emitted token shape — which the reviewer *estimated* rather than ran. The probe "could this observation have come out otherwise?" applies to the reviewer's own gap claim, not just to the test: if a prebuilt UNFIXED slangc is on hand (or the fix reverts cheaply), run the FileCheck against the buggy emit and see whether it fails — settle the gap empirically instead of parsing the reviewer's estimate at face value ([free revert-drill via the prebuilt unfixed slangc to test a FileCheck-coverage gap](../learnings/1789093222717-approver-challenger-technique-free-revert-drill-vi.md)).

## Human-Verdict Calibration and the Merge Join

The shadow-mode ledger's eventual human merge is calibration data — but the join must be read carefully.

A **maintainer self-merge with zero formal reviews (`reviewDecision: REVIEW_REQUIRED`, empty `reviews`) is `NO_HUMAN_REVIEW`, not `APPROVED`** — recording APPROVED fabricates an agreement signal (this remains the rule from the earlier fold).

**`closed-unmerged` ≠ rejection**: on a `github.pr_closed` with `merged=false`, read the close context (WHO closed it, any "folded into #N"/"superseded by #N" cross-reference) before mapping to a human verdict — an author-closed supersede/fold is BENIGN and must not score as a false-safe against a WOULD_APPROVE row; only a maintainer merits-close is a genuine rejection ([closed-unmerged ≠ rejection — check for a supersede/fold-into-open-PR](../learnings/1784012759272-approver-human-disagreement-closed-unmerged-reject.md)).

**Protected-path (`.github/**`) ABSTAIN_POLICY that later merges with the protected file intact + a human approval is a CORRECT terminal decision, recorded as agreement-neutral (ABSTAIN rows are excluded from agreement scoring), NOT a false-safe** — confirmed repeatedly (slang#12023 merged after `expipiplus1` APPROVED with two `.github/workflows` files intact; slang#12060 merged by the maintainer at the reviewed head) — and keep the deterministic-hold + narrow re-trigger for structural-clause abstains ([protected-path ABSTAIN validated: slang#12023 merged with .github/** intact](../learnings/1784030934279-approver-human-agreement-protected-path-abstain-po.md), [protected .github/** CI-workflow PRs: ABSTAIN_POLICY is the right call, merges confirm it](../learnings/1784033516739-approver-human-disagreement-protected-github-ci-wo.md)).

An **OPEN_GAP on a code-contradicted / provably-false PUBLIC-reference-docs API claim is a VALIDATED ABSTAIN** when the author fixes it across revisions before merge (merged ⇒ APPROVED-equivalent of the FINAL state, which no longer contains the defect) — public reference docs are an API contract surface, so verify API claims against source and don't round a provable contradiction down to advisory ([VALIDATED ABSTAIN: OPEN_GAP on a false public-docs API claim was fixed by the author before merge](../learnings/1784014469307-approver-human-disagreement-validated-abstain-open.md), ["diagnose-by-instrumentation" PRs that re-enable a still-red quarantined test are ABSTAIN_POLICY](../learnings/1784049982092-approver-human-disagreement-diagnose-by-instrument.md)).

### Confirmed-Safe / Confirmed-Agreement Shapes (sharpen Step-0 recall)

Several confirmed-safe / confirmed-agreement shapes sharpen Step-0 recall (all merged unchanged at the exact decision head, often with 2-maintainer agreement, on the Devin-only fallback tier where a bot-authored PR skips production review):

- **Emitter fold/hoist codegen-quality perf fixes** (form-only change, precise predicate, mirrors an existing guard, ships a GPU-free FileCheck) ([codegen-quality fold-guard perf fixes are safe to approve on Devin-only tier](../learnings/1784026118184-approver-confirmed-safe-codegen-quality-fold-guard.md)).
- **Purely-additive `RequiredLoweringPassSet` presence-gates** where every trigger-opcode producer runs before the governing `calcRequiredLoweringPassSet` scan and the gate's case labels equal the pass's handled set (the #11917 epic — do NOT relax vigilance for a slice gating a pass whose trigger can be synthesized in-window) ([RequiredLoweringPassSet additive-gate slice merged unchanged, 2-maintainer agreement](../learnings/1784076254159-approver-human-agreement-confirmed-requiredlowerin.md)).
- **Content-digest EXCLUSION of a proven load-time-only compiler option** (no CLI spelling ⇒ no on-disk digest baked with it ⇒ can't retroactively accept a stale artifact; precedent skip already in the same function) ([content-digest exclusion of a load-time-only option is a safe WOULD_APPROVE shape](../learnings/1784031339360-approver-human-disagreement-confirmed-agreement-co.md)).
- **Test-only + fetched-dep version-bump-that-re-activates-hash-verification** (the load-bearing check is the new shader's result-struct layout matching the green test) ([slang-rhi#774 confirmed — test-only + version-bump WOULD_APPROVE merged unchanged](../learnings/1784029999416-approver-human-agreement-slang-rhi-774-confirmed-t.md)).
- The **trivial-fwd-derivative zeroed-primal `getDifferentialZeroOfType` fix** (merged APPROVED at the exact head, 3-way agreement; repeated master-merges with byte-identical PR contribution are safe trivial re-decides once `gh api compare` restricted to the PR's own files returns empty) ([trivial-fwd-derivative zeroed-primal fix merged APPROVED at exact head — 3-way agreement](../learnings/1784066119880-approver-confirmed-safe-trivial-fwd-derivative-zer.md)).
- **mimalloc per-site `malloc`/`free` conversion** (alloc+free swap together per site, foreign-allocator buffers keep their own free, zero-copy transfers are callback-identity asserted, `detach()` escapes are audited) — with a NOT-a-blocker coverage caveat that the mimalloc path is exercised only on the Windows-MSVC lane, dispositioned as a test-strength limitation on a correctly-gated assertion, never cleared with an unsupported "covered elsewhere" claim ([mimalloc per-site malloc/free conversion is safe when alloc/free swap together + zero-copy transfers are callback-identity asserted](../learnings/1784075171874-approver-confirmed-safe-mimalloc-per-site-malloc-f.md)).
