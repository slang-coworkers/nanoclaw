# PR Approver: Challenger Probes and Human-Verdict Calibration

The approver deep-dive (2026-07-15 fold, parts 2/3 and 3/3): how the critique gate records a review round, the fallback-tier verdict enum, the transferable catalog of challenger red-flag probes, and how the shadow-mode ledger's eventual human merge is read as calibration data. Sibling pages carry run-recovery/polling and branch-delivery/diff-reading.

## TL;DR
- **A fallback-tier (Devin/CodeRabbit) 🔴 is not an auto-BLOCK.** BLOCK needs a 🔴 the challenger independently VERIFIED. A refuted fallback 🔴 ends at ABSTAIN_POLICY:CHALLENGER_CONCERN. It never becomes BLOCK and never rounds up to WOULD_APPROVE.
- **Never round up.** A standing human `CHANGES_REQUESTED` caps the verdict at ABSTAIN.
- **The critique gate records a round only from a FRESH `mcp__codex__codex` call** with the canonical `/codex-critique` `developer-instructions` verbatim. `codex-reply` never records. DECISION_REVIEW and OUTPUT_REVIEW are separate fresh calls.
- **Doc-consistency checks read the WHOLE file and the rest of the docs tree**, not just diffed lines. The same holds for duplicated code.
- **Memoization/caching PRs: CI-green on the pinned head is a hard precondition for WOULD_APPROVE.** A static-CLEAN audit never rounds toward approve.
- **A change that casts away a qualifier the target toolchain treats as a real guarantee needs target-arch execution coverage**, else lean ABSTAIN.
- **IR-lifetime claims need semantics, not analogy.** Prove zero-use invariants tree-wide; IRInsts are arena memory and are never individually freed.
- **Every revision gets a fresh challenger.** A clean fix-commit can add a new blocking finding. An enumerated-exception invariant is a completeness trap until you enumerate every case.
- **A green regression test proves nothing unless it goes RED on the pre-fix code.** When an unfixed binary is at hand, settle a coverage-gap claim by running it.
- **Scope a "regression" against master**, not an earlier commit in the PR's own iteration.
- **CI claims cover completed checks only.** A pending job can still go red.
- **`closed-unmerged` ≠ rejection.** Read who closed it and any supersede/fold reference before scoring.
- **Protected-path ABSTAIN that later merges with human approval is correct and agreement-neutral**, never a false-safe.
- **A maintainer self-merge with zero formal reviews is `NO_HUMAN_REVIEW`, not `APPROVED`.**

## Critique-Gate Recording and Doc Consistency

The critique gate records a round only from a fresh `mcp__codex__codex` call that carries the canonical `/codex-critique` `developer-instructions` block verbatim. A `mcp__codex__codex-reply` reuses the thread's original instructions, carries no `developer-instructions`, and never records, whatever its verdict. Run DECISION_REVIEW and OUTPUT_REVIEW as separate fresh calls. `codex-reply` is only for iteration inside a stage that is already recorded; a re-verify that must flip the gate to approve is itself a fresh call. Before `record_decision`, confirm the hook's "Critique round N recorded" message shows both stages with OUTPUT_REVIEW=approve ([codex-reply does not record a round](../learnings/1786634623471-approver-critique-mustfix-output-review-must-be-a-.md), [OUTPUT_REVIEW must be a fresh codex call](../learnings/1784095230054-approver-critique-mustfix-output-review-must-be-a-.md)).

The `gate-critique-on-deliver.sh` PreToolUse hook false-fires on read-only `gh api .../pulls/...` GETs (its `gh api [^|]*pulls\b` pattern ignores the verb) and escalates to an admin block after 3 denials. Read PRs through the MCP GitHub tools or `gh pr view --json reviews`; `commits/<sha>/check-runs` and `/status` never trip it. ABSTAIN_* skips the gate anyway, so a firing on a read is a known false positive, not a cue to run codex ([hook false-fires on gh api pulls GETs](../learnings/1786479308420-approver-infra-abstain-critique-gate-bash-hook-fal.md)).

A doc-consistency check reads the whole file at the pinned head, not just diffed lines. A changed default, flag, or API name leaves stale copies in un-diffed narrative and tables; grep for the OLD value and "default". Ask the same "did an un-diffed sibling copy go stale?" question of duplicated code ([read the whole file](../learnings/1784019216454-approver-critique-mustfix-doc-consistency-check-mu.md)). A docs PR whose purpose is to document a removal or behavior change (slang#13003) needs the same sweep across the docs tree, especially sibling `docs/user-guide/*.md` chapters: grep the removed feature's syntactic shape (e.g. `struct \w+ : \w+`). Accuracy of the new note and consistency of the rest are separate axes. Stale teaching that a reader on the affected version can still hit is an OPEN_GAP, not a clear ([document-a-change docs PR](../learnings/1789116584403-approver-challenger-miss-docs-pr-documenting-a-rem.md)).

## Fallback-Tier Verdict Discipline: BLOCK Requires VERIFIED

A fallback-tier (Devin/CodeRabbit) heuristic 🔴 is not a Step-2 auto-BLOCK. Step 4 reserves BLOCK for a verified 🔴, and Step 3 routes an unsure verdict to the challenger. If the challenger verifies the 🔴, the verdict is BLOCK; if it refutes it, ABSTAIN_POLICY:CHALLENGER_CONCERN. Recording BLOCK asserts a verified red bug to the ledger, which is as wrong as rounding up ([Step-2 BLOCK requires Step-4 VERIFIED](../learnings/1784080988551-approver-critique-mustfix-fallback-tier-heuristic-.md)). The same bar applies to dismissing a 🔴. "Transient IR is deleted, so its invalid SSA doesn't count" needs a proven no-observer path: name every pass between creation and removal and show that none trips on it. If you cannot trace it, the concern stays open — ABSTAIN, not WOULD_APPROVE, and not BLOCK either ([proven no-observer path](../learnings/1784042674528-approver-critique-mustfix-transient-ir-is-deleted-.md)).

Clearing or raising an IR-lifetime 🔴 needs semantics, not analogy:
- **`removeAndDeallocate` without a use check** (a recurring Devin "Repo rule" flag): prove the op's zero-use invariant tree-wide from op semantics and every producer and consumer (Void result ⇒ no well-typed consumer; sole producer; every consumer discards it), not from the current diff. Residual holds (an unasserted front-end invariant, a one-level traversal that relies on a prior `specializeModule`) support ABSTAIN, not BLOCK ([zero-use invariant](../learnings/1784081016635-approver-challenger-miss-removeanddeallocate-witho.md)).
- **"Pre-existing risk" or UAF claims on IR insts** need a memory-model proof, not a deref-site analogy. IRInsts are arena-allocated. `removeAndDeallocate` only unlinks and never frees, so a removed inst stays readable until the IRModule dies, and reading a scalar field like `scratchData` on it is stale but valid ([IRInsts are arena-allocated](../learnings/1784095223530-approver-challenger-miss-pre-existing-risk-claims-.md)).

Static review cannot clear a hardware-level miscompile. A `const_cast` away from `const` on a CUDA `__grid_constant__` kernel param miscompiled on sm_100/NVRTC. slang#12080 drew four WOULD_APPROVE false-safes before the author moved to a forward-only design with NVRTC `COMPARE_COMPUTE` coverage. When a change casts away a qualifier the target toolchain treats as a real guarantee, demand target-arch execution coverage or lean ABSTAIN (OPEN_GAP: "correctness only verified at source level") ([const_cast on a grid-constant param](../learnings/1784045721338-approver-false-safe-const-cast-away-const-on-a-cud.md)).

## Challenger Probes: the Transferable Red-Flag Catalog

Each probe is a reusable "when you see X, check Y".

### Codegen and semantics
- **Autodiff zero-differential**: a zero or identity tangent built with `emitDefaultConstructRaw` instead of `getDifferentialZeroOfType` silently miscompiles a user `IDifferentiable` whose `dzero()` differs from default construction. Grep the diff for `emitDefaultConstruct` used as a differential value and demand a non-default-`dzero()` regression test ([use getDifferentialZeroOfType](../learnings/1784017388229-approver-clause-gap-autodiff-zero-differential-mus.md)).
- **Capability-atom narrowing**: a new atom `B : A` means B⇒A, not A⇒B. Rewriting `if impliesCap(A)` as `if impliesCap(B) … else SLANG_UNEXPECTED` drops every A-but-not-B target to an abort. Probe whether a formerly covered coarse-atom config now aborts, and be extra suspicious when the PR's own tests switch `-capability` to the narrow atom ([pre-6.9 SLANG_UNEXPECTED edge](../learnings/1784026245321-approver-challenger-miss-rev1-ci-unverified-abstai.md)). After such a regression is "fixed" by a diagnostic keyed on emitting a TYPE, enumerate every sibling op in the family: an overload with no type operand (e.g. `ReorderThread(uint,uint)`) still miscompiles silently ([type-emitter diagnostic](../learnings/1784047648527-approver-challenger-miss-a-type-emitter-diagnostic.md)).
- **Switch completeness and one-shape recovery helpers**: a missing `case` in an unwrapping or translation switch is a high-value probe whenever a PR layers a helper on it. A recovery helper that rebuilds type info from ONE SSA consumer shape (branch→phi) and then `SLANG_RELEASE_ASSERT`s assumes that shape is the only one. Compare the producer predicate with the recovery predicate, and grep for other consumers (`IRReturn`/`IRCall`/`IRStore`) ([whole-consumer-set probe](../learnings/1784035598289-approver-challenger-miss-recovery-helpers-keyed-on.md)).
- **Widening a coercion's viability** interacts with overload resolution. More viable constructors in a `canCoerce` probe can make one brace-init match several overloads, so the fix must produce a diagnosed ambiguity with a regression test, not a silent pick ([coercion viability](../learnings/1784048815957-approver-human-disagreement-widening-a-coercion-s-.md)).
- **Dedup/canonicalization ("make N producers agree")**: changing how ONE producer derives an operand can re-introduce the duplicate the PR removes. Enumerate every producer and its input set, and prove the changed branch's trigger is disjoint across producers or applied symmetrically ([producers on disjoint inputs](../learnings/1784057320031-approver-challenger-dedup-canonicalization-fixes-p.md)). A review ask to "add a `hasContent()`/null guard" is safe only if it is a proven no-op on all producers or applied to all of them; adding it to one creates divergence ([hasContent guard asks](../learnings/1784048758044-approver-challenger-add-a-hascontent-null-guard-re.md)).

### Memoization and substitution
- **Cache-key completeness**: a memoization PR is correct only if the key captures every input that parameterizes the result. The collision is the input nobody enumerated, so static reasoning cannot see it. CI-green on the pinned head is a hard precondition for WOULD_APPROVE, and no static-CLEAN audit or 0-bug review substitutes for it ([CI is authoritative](../learnings/1784078519306-approver-false-safe-memoization-caching-prs-a-stat.md)). Deterministic failures of the same pre-existing generic-specialization tests on ≥2 runners, while the PR's new tests pass, is the collision signature → BLOCK ([memoization breaks generic specialization](../learnings/1784076799325-approver-challenger-miss-memoization-pr-breaks-gen.md)). That BLOCK was vindicated: the next revision removed exactly the cross-environment cache. Env-local lowering caches are safe; cross-env global ones are not. Diff the revision to confirm the fix is surgical ([BLOCK vindicated](../learnings/1784093692254-approver-confirmed-safe-a-ci-driven-block-on-a-mem.md)).
- **When a static audit does clear a cache PR**: prove the colliding dispatch paths are identical (`dispatch`==`dispatchType`, byte-identical). For a cross-env cache, enumerate every context field and show that the `parent==moduleInst` guard excludes each env-varying one (a structural IR-parenting proof). Grep the counter/out-param convention (`*ioDiff =`) tree-wide, not over a partial file list ([Val-lowering memoization audit](../learnings/1784074914750-approver-challenger-miss-val-lowering-memoization-.md)).
- **Substitute-override audits** cover every `_substituteImplOverride` file tree-wide, including `slang-ast-type.cpp`, not just val.cpp/decl-ref.cpp. When a change stores and replays a running counter, check the consumer contract (boolean-zero vs magnitude) ([every override file](../learnings/1784054408743-approver-challenger-miss-substitute-override-audit.md)).

### Build, CI, and tests
- **CSS/HTML tables**: `table-layout:fixed` plus a widthless column collapses data columns. Enumerate every `<col>` the generator can emit, confirm each has a width rule, and sum declared widths for every feature-flag combination, not just the one the diff mentions ([table-layout:fixed](../learnings/1784040257325-approver-challenger-miss-css-table-layout-fixed-wi.md)).
- **Submodule pins**: a `.gitmodules` entry with no `branch =` is checked by `check-submodule-commits.sh` against the remote's default branch, not a same-name version tag. Clear it with `git merge-base --is-ancestor <pin> origin/<default-branch>` and the `check-submodules` CI result, not a "tag-reachable" analogy ([default branch, not tag](../learnings/1784074301503-approver-challenger-miss-submodule-no-branch-pin-v.md)).
- **CMake fetched-dep bumps**: hash integrity is silently off when `SLANG_HASH_VERSION` lags the fetch version. A "hash refresh" is inert (or the bump is what first turns verification on) unless `fetch_version == hash_version` after the change; green download+verify check-runs corroborate ([SLANG_HASH_VERSION lags](../learnings/1784011130054-approver-challenger-miss-cmake-fetched-dep-version.md)).
- **Regression-test discrimination**: reconstruct the pre-fix output and confirm the assertion rejects it. For FileCheck, a missing-operand bug needs an end-anchored `CHECK-NOT: … %{{[0-9]+}}{{$}}`, because trailing operands are optional in a bare `CHECK` ([must FAIL on the pre-fix code](../learnings/1784070693213-approver-challenger-miss-a-regression-test-that-lo.md)). A reviewer's coverage-gap claim is decidable too. On slang#12887 a 🟡 said only the Apple-only METALLIB compile catches the bug and the CI-runnable METAL text checks would pass the buggy emit; that depends on the exact emitted tokens, which the reviewer estimated. Run the FileCheck against a prebuilt UNFIXED slangc (or a cheap revert) instead of trusting the estimate ([free revert-drill](../learnings/1789093222717-approver-challenger-technique-free-revert-drill-vi.md)).
- **CI snapshot vs settled CI**: `commits/<sha>/status` reflects only checks reported at read time, and an `in_progress`/`queued` job can still go red. Scope CI claims to completed checks by name. Unsettled or red CI removes corroboration and pushes toward ABSTAIN ([not settled CI](../learnings/1784042664032-approver-challenger-miss-ci-green-snapshot-is-not-.md)). A macOS "requires metal4.0" pipeline failure can be a Slang emit/downstream-`-std` mismatch, not the #11973 runner flake. A version-gated emit paired with a hard-coded lower `-std` is a compiler bug (the `[Slang]: ERROR:` prefix is a tell), so name it as a candidate cause instead of "environmental" ([metal4.0 is not always the flake](../learnings/1784083878096-approver-challenger-miss-a-macos-requires-metal4-0.md)).

### Revisions and attribution
- **Every revision gets a fresh challenger.** The pre-existing/attribution base-diff test cuts both ways: a clean fix-commit can add a new blocking finding elsewhere in the file, and an enumerated-exception invariant ("holds for all Y except {A,B,C}") is a completeness trap until you enumerate every Y yourself. A WOULD_APPROVE streak is no reason to skip a fresh review's new findings ([cuts both ways](../learnings/1784011508988-approver-challenger-miss-the-pre-existing-attribut.md)).
- **Carried-over content stays live.** A false claim that is still present but not re-listed by the current review is still a gap. Scope a regression escalation against master: a guard added and reverted within the PR is churn, not a PR-introduced regression ([release baseline](../learnings/1784055067504-approver-challenger-miss-scope-a-regression-escala.md)). Devin repeating "glossary complete and accurate" while missing counterexamples carries zero weight for completeness; it echoes the PR narrative.

## Human-Verdict Calibration and the Merge Join

The eventual human merge is calibration data, but the join needs a careful read.
- **A maintainer self-merge with zero formal reviews** (`reviewDecision: REVIEW_REQUIRED`, empty `reviews`) is `NO_HUMAN_REVIEW`, not `APPROVED`. Recording APPROVED fabricates an agreement signal.
- **`closed-unmerged` ≠ rejection.** On `github.pr_closed` with `merged=false`, read who closed it and any "folded into #N" or "superseded by #N" reference. An author-closed fold is benign and must not score as a false-safe against a WOULD_APPROVE row; only a maintainer merits-close is a rejection ([check for a supersede/fold](../learnings/1784012759272-approver-human-disagreement-closed-unmerged-reject.md)).
- **Protected-path (`.github/**`) ABSTAIN_POLICY that merges with the protected file intact and a human approval is correct**, recorded agreement-neutral (ABSTAIN rows are excluded from agreement scoring). slang#12023 merged after `expipiplus1` APPROVED with two `.github/workflows` files intact; slang#12060 merged at the reviewed head. Keep the deterministic hold and the narrow re-trigger for structural-clause abstains ([slang#12023 validated](../learnings/1784030934279-approver-human-agreement-protected-path-abstain-po.md), [merges confirm it](../learnings/1784033516739-approver-human-disagreement-protected-github-ci-wo.md)).
- **An OPEN_GAP on a provably false public-docs API claim is a validated ABSTAIN** when the author fixes it before merge; the merge approves the final state, which no longer has the defect. Public reference docs are an API contract: verify API claims against source and do not round a provable contradiction down to advisory ([VALIDATED ABSTAIN](../learnings/1784014469307-approver-human-disagreement-validated-abstain-open.md)). A "diagnose-by-instrumentation" PR that re-enables a still-red quarantined test is likewise ABSTAIN_POLICY ([diagnose-by-instrumentation](../learnings/1784049982092-approver-human-disagreement-diagnose-by-instrument.md)).

### Confirmed-Safe Shapes (Step-0 recall)

Each merged unchanged at the exact decision head, often with 2-maintainer agreement, on the Devin-only fallback tier (bot-authored PRs skip production review):
- **Emitter fold/hoist codegen-quality perf fixes**: form-only, precise predicate, mirrors an existing guard, ships a GPU-free FileCheck ([fold-guard perf fixes](../learnings/1784026118184-approver-confirmed-safe-codegen-quality-fold-guard.md)).
- **Purely additive `RequiredLoweringPassSet` presence-gates** (the #11917 epic) where every trigger-opcode producer runs before the governing `calcRequiredLoweringPassSet` scan and the gate's case labels equal the pass's handled set. Stay vigilant for a slice whose trigger can be synthesized in-window ([RequiredLoweringPassSet slice](../learnings/1784076254159-approver-human-agreement-confirmed-requiredlowerin.md)).
- **Content-digest exclusion of a proven load-time-only option**: no CLI spelling ⇒ no on-disk digest baked with it ⇒ no stale artifact can be accepted; a precedent skip already exists in the same function ([content-digest exclusion](../learnings/1784031339360-approver-human-disagreement-confirmed-agreement-co.md)).
- **Test-only change plus a fetched-dep bump that re-activates hash verification**: the load-bearing check is the new shader's result-struct layout matching the green test ([slang-rhi#774](../learnings/1784029999416-approver-human-agreement-slang-rhi-774-confirmed-t.md)).
- **Trivial-fwd-derivative zeroed-primal `getDifferentialZeroOfType` fix**: merged APPROVED at the exact head with 3-way agreement. Repeated master-merges with a byte-identical PR contribution are safe trivial re-decides once `gh api compare` restricted to the PR's own files is empty ([zeroed-primal fix](../learnings/1784066119880-approver-confirmed-safe-trivial-fwd-derivative-zer.md)).
- **mimalloc per-site `malloc`/`free` conversion**: alloc and free swap together per site, foreign-allocator buffers keep their own free, zero-copy transfers are callback-identity asserted, and `detach()` escapes are audited. Coverage only on the Windows-MSVC lane is a test-strength caveat on a correctly gated assertion, not a blocker, and is never cleared with an unsupported "covered elsewhere" ([mimalloc conversion](../learnings/1784075171874-approver-confirmed-safe-mimalloc-per-site-malloc-f.md)).
