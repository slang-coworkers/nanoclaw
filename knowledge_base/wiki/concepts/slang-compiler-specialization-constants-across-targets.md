# Slang specialization constants across targets

A `[SpecializationConstant]` / `[vk::constant_id]` global is native only on SPIR-V. Every other target has to emit it as something else: GLSL and SPIR-V-via-GLSL go through glslang's own spec-constant handling, WGSL uses `override`, and HLSL, CUDA and CPU fold it into the global-params struct in `collectGlobalUniformParameters`. This page collects what breaks when a spec constant is used as an array size, as a `[numthreads]` operand, or inside a module-scope `static const` initializer. WGSL `override` emission rules are on [[wiki/concepts/slang-backends-wgsl-f16-and-const-expressions.md]].

## TL;DR

- **An array sized by a spec constant works only on SPIR-V**, for groupshared, struct-field and function-local arrays alike. GLSL/WGSL/Metal fail with E99999 because `emitInstExpr` has no `kIROp_GlobalParam` case. HLSL/CUDA rewrite the size into a `globalParams` read: HLSL emits a VLA that DXC rejects (slangc exits 0), and CUDA aborts with E99997 or "circularity during codegen".
- **"HLSL works" claims about spec-constant array sizes are wrong.** Always compile to `-target dxil` for the downstream verdict.
- **glslang gives every spelling of a spec-constant size expression its own `OpSpecConstantOp`.** So `kN * 2` spelled at a caller and in a callee's `out` parameter are two array types, and the copy-out keeps only element 0: a silent wrong result through `-emit-spirv-via-glsl`. A bare `kN` size is fine. Emit each module-scope spec-constant value used by an `IRArrayType` once, as a named `const`.
- **Run an IR check for spec-constant array sizes on HLSL/CUDA after specialization, not before `collectGlobalUniformParameters`.** After the rewrite the size is still `isSpecConstRateType`, and running it earlier gives dead-code false positives and misses generic-argument arrays.
- **Arithmetic spec-constant sizes are hoistable constexpr ops that only the SPIR-V emitter handles.** For GLSL/WGSL, rewrite them to ordinary ops before target legalization, which reuses WGSL's shift/select legalization.
- **On HLSL/CPU/CUDA a spec-constant `[numthreads]` operand is a removed inst with a null type.** Never read its type between collect and emit. On SPIR-V, do not hoist a `makeVector` with a spec-constant constituent to an `OpConstantComposite`.
- **E55205 (numthreads spec constant) is the diagnostic precedent.** The collect pass already skips NumThreads users so they can be diagnosed later.
- **slangc returns 255 for every compile error**, so an acceptance criterion like "exit 1, not 255" cannot be met.
- **Since v2026.7 an op over spec constants is SpecConst-rate: hoisted to module scope, deduplicated, and never to be inlined into a function.** Cloning it can return the original inst, so code that clones the result's children or decorations must handle result == original. Spec-const-rate insts are legal globals on every target (PR #14285).
- **Keep spec-const operands literal or spec-const.** A pass that replaces a literal operand in place with a module-scope `intCast(lit)` (`legalizeBinaryOp`) silently drops the spec-const rate.
- **A spec-constant exemption must also require `isGlobalShaderParameter`.** `[vk::constant_id]` is accepted (and silently dropped) on `groupshared` globals, so `isSpecializationConstant` alone matches mutable workgroup variables.
- **E31226 folds only integer scalars.** Float, vector, array and struct `static const` initializers always reach `_initExprIsRuntimeValue`, so test those shapes when the walker changes. Struct `static const` members skip E31226 entirely, which makes them the probe shape for module-scope initializers.
- **Probe this area under `timeout` + `ulimit -v`, and record exit codes**: the #14278 hang eats memory at hundreds of MB/s, and rc >= 128 is a crash that a grep for "error" misses.

## Spec-constant array sizes fail on every non-SPIR-V target (#14030, #10214)

This was checked on master 9b3ac252d (2026-10-29, #14030 / #10214). An array sized by a `[SpecializationConstant]` works only on SPIR-V, and that holds for groupshared, struct-field and function-local arrays alike. The other targets fail through two different mechanisms [Slang: spec-constant array sizes fail on every non-SPIR-V target (two different mechanisms)](../learnings/1793292087744-slang-spec-constant-array-sizes-fail-on-every-non-.md):

- **GLSL, WGSL and Metal.** The final IR keeps `Array(T, %kTile)` with `%kTile = global_param`. `CLikeSourceEmitter::emitVal` (slang-emit-c-like.cpp:834) sends the size to `emitInstExpr`, which has no `kIROp_GlobalParam` case, so the compile fails with E99999 "unexpected IR opcode during code emit".
- **HLSL and CUDA.** These targets have no spec-constant layout rules, so `collectGlobalUniformParameters` (slang-emit.cpp:1363) rewrites the count into a `globalParams.kTile` read. HLSL then emits a VLA: slangc exits 0, but DXC rejects it. On the #10214 shape, CUDA aborts with E99997 "needed a known integer value" from `getIntVal` (slang-emit-cpp.cpp:1187), or with "circularity during codegen".

So a claim that "HLSL works" for this pattern is wrong until `-target dxil` has given the downstream verdict. E55205 (a spec constant in `[numthreads]`) is the diagnostic precedent: the collect pass already skips NumThreads users so they can be diagnosed later [Slang: spec-constant array sizes fail on every non-SPIR-V target (two different mechanisms)](../learnings/1793292087744-slang-spec-constant-array-sizes-fail-on-every-non-.md).

## glslang spellings, check placement, and arithmetic sizes (#14030, PR #14049)

glslang gives every *spelling* of a specialization-constant expression its own `OpSpecConstantOp`. Consider `float a[kN * 2]` at a caller and `out float b[kN * 2]` in the callee. They become two distinct `OpTypeArray` types, and the copy-out keeps only element 0, which is a silent wrong result through `-emit-spirv-via-glsl`. A bare `kN` size is fine. PR #14049 fixes this in Slang's GLSL emitter: it declares each module-scope spec-constant value used by an `IRArrayType` once, as a named `const` (`getFoldPolicy` → Never) [glslang miscompiles out-array copies when a spec-constant size expression is spelled twice; check spec-const arrays after specialization](../learnings/1793303171753-glslang-miscompiles-out-array-copies-when-a-spec-c.md).

An IR check that must see spec-constant array sizes on HLSL/CUDA does NOT need to run before `collectGlobalUniformParameters`. That pass runs before specialization and DCE, so a check there gives dead-code false positives and misses arrays sized by generic arguments. After the rewrite the size is `@SpecConst load(get_field_addr(globalParams, k))`, and `isSpecConstRateType` still holds, so run the check after specialization. Arithmetic spec-constant sizes are hoistable `constexpr*` IR ops that only the SPIR-V emitter handles; for GLSL/WGSL, rewriting them to ordinary ops before target legalization reuses WGSL's shift/select legalization. Finally, slangc returns 255 for every compile error, so an acceptance criterion like "exit 1, not 255" cannot be met [glslang miscompiles out-array copies when a spec-constant size expression is spelled twice; check spec-const arrays after specialization](../learnings/1793303171753-glslang-miscompiles-out-array-copies-when-a-spec-c.md).

## `[numthreads]` operands on targets without specialization constants

**`[numthreads]` operands are dangling on targets without specialization constants.** On HLSL/CPU/CUDA, `collectGlobalUniformParameters` (slang-ir-collect-global-uniforms.cpp:332-339) folds a `[vk::constant_id]` global into the global-params struct and `removeAndDeallocate`s it, but deliberately skips the `IRNumThreadsDecoration` use so E55205 can be diagnosed later. The decoration's operand is then a removed inst with a cleared type, and any pass between collect and emit that reads that type (e.g. `builder.emitCast(int, op)` in `materializeGetWorkGroupSize`) segfaults in `_getTypeStyleId(nullptr)`. Touch spec-const-rate operands only on targets that keep them (an `isSpecConstRateType(op->getFullType())` guard is itself a read of the dead type). The suite missed it because no test called `WorkgroupSize()` with a spec-const `[numthreads]` on HLSL/CPU; /code-review found it on #13767 (PR #13826). On SPIR-V, the cast of a `uint` spec const to `int` is an `OpSpecConstantOp`, and `maybeHoistConstructInstToGlobalScope` then hoists an all-module-scope `makeVector` to an `OpConstantComposite` with a spec-const constituent, which spirv-val rejects; skip the hoist when any operand is spec-const rate [[numthreads] operands on non-spec-const targets are dangling](../learnings/1792609336816-slang-numthreads-operands-on-non-spec-const-target.md). The missing casts in that splice are on [[wiki/concepts/slang-b-language-semantics.md]].

## Spec-const-rate values are module-scope globals (#14278, PR #14285)

Since f09c7e8f4 (#10694, v2026.7), `IRBuilder::_createInst` gives an eligible op (integer arithmetic, compares, casts, select) the SpecConst rate when every operand is a constant or a spec-const-rate value and at least one is a spec constant, and routes it through `_findOrEmitHoistableInst`. The op is hoisted to module scope and deduplicated. Consider `[vk::constant_id(0)] const int N = 4; static const int k = 64 + N;`. Cloning `k` at a use site with `cloneInstAndOperands` can return the ORIGINAL inst. `cloneInst` guards `newInst == oldInst` (slang-ir-clone.cpp:426-433), but `GlobalInstInliningContextGeneric::inlineInst` (slang-ir-legalize-global-values.cpp:192) did not: it cloned the decorations of `k` into `k` while iterating them, and because insert-into appends at the end, the loop never ended. On WGSL that hung `legalizeIRForWGSL` with unbounded memory growth. SPIR-V escaped only because `slang-ir-spirv-legalize.cpp:2057` already treated `isSpecConstRateType` insts as legal globals, an exemption WGSL's `isLegalGlobalInstForTarget` lacked [global-value inliner self-dedup loop (WGSL hang #14278)](../learnings/1793750179945-global-value-inliner-self-dedup-loop-a-specconst-c.md). PR #14285 moves that exemption into the shared `isLegalGlobalInst`, so a spec-const-rate inst is never inlined into a function [spec-const-rate insts can never be inlined into a function](../learnings/1793755067290-spec-const-rate-ir-insts-can-never-be-inlined-into.md). The general rule: any code that calls `cloneInstAndOperands` and then clones the children or decorations of the result must handle result == original.

Two neighbours keep the invariant fragile. WGSL emits module-scope aggregates (`MakeArray`/`MakeStruct`) as `const`, and a WGSL `const` cannot reference an `override`, so an aggregate with a spec-const element still has to be inlined at the use. And `legalizeBinaryOp` (WGSL/Metal) replaced a literal shift amount in place with a module-scope `intCast(lit)`, which is neither constant nor spec-const; the shift silently lost its spec-const rate and had to be inlined through `GlobalValueRef` temporaries. Keep literals literal. Note also that `IRBuilder::replaceOperand` re-keys only op-hoistable insts in the dedup map, not rate-hoisted spec-const ones [spec-const-rate insts can never be inlined](../learnings/1793755067290-spec-const-rate-ir-insts-can-never-be-inlined-into.md).

## Spec constants in `static const` initializers: E31226 (#14267, #14290)

A global `static const` initializer must be a compile-time constant (E31226). In `checkVarDeclCommon` (slang-check-decl.cpp) the check runs only when `varDecl->val` is null, and `_validateCircularVarDefinition` returns nullptr unless `isScalarIntegerType`, so only integer scalars constant-fold. Arrays, vectors, structs and float/half/double scalars always reach `_initExprIsRuntimeValue`. A claim that "the scalar case passes because it folds" therefore holds only for integer scalars. On #14290 (PR #14300), `[vk::constant_id] const float F; static const float s = F * 2.0;` failed with E31226 just like `static const int a[2] = {N, 3}`; the fix exempts spec constants in the walker's DeclRefExpr arm. That exemption must test `isSpecializationConstant(varDecl) && isGlobalShaderParameter(varDecl)`: `isSpecializationConstant` only scans for the `[vk::constant_id]`/`[SpecializationConstant]` attributes, and master accepts `[vk::constant_id(0)] groupshared int N;` silently (the attribute is dropped, no SpecId), so the bare check lets a mutable workgroup variable through. On PR #14300 that made `static const int arr[2] = {N, 3}` over a groupshared `N` crash Metal (`no outer func at use site for global`) and read uninitialized shared memory elsewhere. GLSL-mode `layout(constant_id)` constants stay shader parameters because the implicit-static pass excludes spec constants, but GLSL `const` arrays over them hit the same E31226 regression, so test with `-lang glsl` too [spec-constant attributes are accepted on groupshared globals](../learnings/1793773761003-slang-spec-constant-attributes-are-accepted-on-gro.md). Downstream, spec-const int arrays still emit invalid SPIR-V (#14279), WGSL (a `const` over an `override`) and GLSL (#14291), as on v2026.7, while float scalars and vectors are inlined at the use and run on Vulkan [E31226 walker: only integer scalars fold](../learnings/1793771061451-slang-e31226-walker-only-integer-scalars-constant-.md). Struct `static const` members are not checked for E31226 at all. So `struct H { static const int k = f(divisor); }` is the shape that probes uniform or spec-constant operands of module-scope initializers; a plain global stops at E31226 on every target and exercises nothing [probe scripts need timeout + ulimit; struct statics bypass E31226](../learnings/1793748082078-slang-probe-scripts-need-timeout-ulimit-struct-sta.md). The `[ForceInline]` side of module-scope initializers (#14133, #14238) is on [[wiki/concepts/slang-compiler-ir-phis-and-global-value-placement.md]].

## Probing hangs and crashes in this area

- **Bound every ad-hoc probe loop**, e.g. `timeout 40 bash -c 'ulimit -v 6000000; slangc ...'`. On master f1cd35ff8, `static const int k = 64 + N;` with `-target wgsl` grows memory at ~250-450 MB/s; one unguarded probe reached ~150 GB RSS on a shared box in 10 minutes [probe scripts need timeout + ulimit](../learnings/1793748082078-slang-probe-scripts-need-timeout-ulimit-struct-sta.md) [spec-const-rate insts](../learnings/1793755067290-spec-const-rate-ir-insts-can-never-be-inlined-into.md).
- **Record the exit code, not a grep for "error".** A pre-#14150 build segfaulted (rc 139) with no stderr, and a grep-only probe logged it as "ok". Treat rc >= 128 as a crash; slangc returns 255 on an ordinary error [probe scripts](../learnings/1793748082078-slang-probe-scripts-need-timeout-ulimit-struct-sta.md).
- **Keep a build from before the suspect PR** to tell a regression from restored behaviour (on #14267, `wt-14221-base` at 7f506f4c9, before #14150): some shapes "broken" by a fix had only compiled on master by accident of the regression [probe scripts](../learnings/1793748082078-slang-probe-scripts-need-timeout-ulimit-struct-sta.md). Release tarballs are a cheap alternative: `gh release download vX -R shader-slang/slang -p 'slang-X-linux-x86_64.tar.gz'`. There is no v2026.6 release; v2026.5.2 is the last before v2026.7 [global-value inliner self-dedup loop](../learnings/1793750179945-global-value-inliner-self-dedup-loop-a-specconst-c.md).
- **Never rebuild while a full slang-test run uses the same build directory** [spec-const-rate insts](../learnings/1793755067290-spec-const-rate-ir-insts-can-never-be-inlined-into.md).
