# State Verification Discipline (part 3) (part 2)

> **This page is part 2 of 2** of the State Verification Discipline (part 3) synthesis (split 2026-08-07 to stay under the 40 KB read cap). Siblings: [part 1](general-misc-state-verification-discipline-3.md). The TL;DR below is shared across all parts.

## TL;DR
- **A read of a live artifact is a MEASUREMENT WITH A TIMESTAMP, not a fact.** PR state, CI conclusion, draft/ready, review state, infra capability — all mutate. Re-probe before citing; a saved memo is a claim about a past instant.
- **A dispatch, a webhook, a nudge, and a timeout are all claims ABOUT state, never state.** Resolve live before acting on any of them. A timeout in particular describes a past instant and is not a decision.
- **Correcting the EXTENT of a claim about a mutable condition, while still stating it as a standing property, leaves the claim wrong.** Fix the tense too.
- **A matching sha does not establish a current reading.** Same-head is necessary, not sufficient — a check can have been re-run, evicted, or superseded since.
- **Verify the CI *conclusion*, not just draft+HEAD, before calling a chain terminal** — and check whether the "last activity" you are clocking is actually a terminal close.
- **A commit date is not a version, and not an edit time.** Read submodule pins by version, not by date; use `merged_at`, never a merge commit's `committer.date`, for when a PR landed.
- **Bot-filed and stale issues rot silently.** Re-verify every `file:line` against current main before relaying; a static-analysis pointer goes stale when the branch is gone, not just when the file changes.
- **A grep hit is a line, not a scope, and `grep -c` counts lines, not events.** A member cite names file, line **and** owner; a published count names the invocation that produced it — or is deleted.
- **A PR's changed-file list does not prove "not a regression."** Verify control-flow invariants against SOURCE, not against a triage memo or a reviewer's assertion.
- **Check ownership before driving anything.** Read issue comments and `head.repo.full_name`: a contributor-owned fork PR is not yours to park, close, or push. Stand down when a maintainer or contributor is driving.
- **Verify @-mention identity against the actual PR/commit author before posting** — a wrong mention is a public, unrecoverable error.
- **A corrupted tool-result turn taints its own verifications**; redo them in a clean turn rather than reasoning off the residue.
- **Post-compaction drift is real**: re-read state before autonomous action in a compacted session, because your premise may have been summarized away.
- **Recurring trackers must carry DISPOSITION, not just items**, and a daily report must carry open ship-stoppers — an item list with no disposition reads as handled.
- **Recurrence only advances on completion**, so a host event can orphan an overdue occurrence and freeze a whole daily series until a human notices. Watchdog the scheduler.
- **A verdict you already published is a past position, not a reason to skip re-checking.** A substantive new human comment re-opens a chain you closed.

## Fidelity of Transcription — Between a Source and Your Claim About It (2026-08-07 fold)

Sections above verify *state*. This one covers the failure on top: you verified the right thing, then **lost it in transit** — source→prose, instrument→message, log→conclusion, measurement→published rule. Shared signature: **the result reads fluently**, so nothing in the artifact prompts a re-check. A dropped disjunct still parses; an abbreviated label still tabulates; an echoed script line still looks like a log line.

**Prose about someone else's control flow must quote the source, not paraphrase it — and a paragraph wrong twice will be wrong a third time in a NEW way.** One PR paragraph explaining why CI showed no test results failed three times running, each fix opening the next: **stale mutable totals** ("81 check-runs, 74 skipped") read at a head a force-push superseded; a **self-falsified claim** ("no workflow ran") that dispatching CI myself refuted; a **false universal** introduced by the generalisation that fixed it ("each `ci.yml` dispatch on a draft yields to the priority gate" — `extras/ci/wait-for-priority.py` yields only if a contender exists, and `--max-yield-hours 12` anti-starvation lets a long-waiting run proceed anyway); then a **dropped disjunct** while paraphrasing that script — "an older bot run is still **queued**" where the source says "queued **or in progress**", also losing "for the same workflow." Rules by generality: **generalising to escape staleness is not free** — swapping a measured total for an invariant is right, but a universal cannot be confirmed by the single observation that prompted it, so you trade a stale fact for an unverified one; **a quoted line with a `file:line` cannot lose "or in progress"**, while every paraphrase is a fresh chance to drop one; **state the invariant, not the reading** ("non-skipped `test-*` check-runs = 0" survived all four rounds and was the only merge-relevant claim — everything corrected was scaffolding: counts that mutate, mechanisms restated, colours that change per dispatch); **count the rewrites — at three, stop rewriting and start quoting.** All four were caught by an adversarial reviewer reading the actual scripts, never by re-reading the prose: rereading is what produced the text, so it cannot audit it ([quote a mechanism's source instead of paraphrasing it](../learnings/1786080934191-quote-a-mechanism-s-source-instead-of-paraphrasing.md)).

**Paste instrument output; don't retype it — abbreviation is the move that destroys falsifiability, because it feels like tidying.** A relayed table showed `control  0  0`; I argued the row impossible (`control` appears in 150 of 378 files, so a corpus holding `transient` in 60 leaves cannot hold `control` in zero). Sound arithmetic, wrong conclusion, and the cause moved twice — my "their query is broken" wrong, then their own "the control searched a fabricated string, so `0` = passing; my *labelling* was the defect" also wrong. Settled: the tool printed `quokka-control  index=0  LEAVES=0 (control)` — fabricated string, correctly labelled — and the **relay** hand-retyped the label down to `control`, deleting the one token that made the row checkable. **The loss was invisible from both ends**: the sender knew what they meant, the reader read what arrived, neither view contained the discrepancy, so no party could detect it alone. Corollaries: **an impossible-looking number in a peer's relayed output has three live causes — broken instrument, bad label, lossy relay — and only the third is invisible from both ends**, so prefer causes needing no fault in their tooling until you have seen the command; **never diagnose a mechanism inside an instrument you cannot read, from a rendering of its output** — the honest verdict was available and skipped (*"this row is uninterpretable without knowing the searched string; which was it?"*); **an offered exoneration is a claim like any other** (declining theirs was right — the labelling wasn't the defect either, so accepting files a wrong cause for a real problem). Reach for this **first**: **establish which party can see which object before arguing about the object** — I am authoritative over what arrived on my edge, they over which string they searched ([paste instrument output, don't retype it](../learnings/1786082028729-paste-instrument-output-don-t-retype-it-hand-abbre.md)).

**A log contains the program's TEXT as well as its output — identify the decision line; don't grep the topic.** Three times in one task a correct-looking grep over a CI/test log returned source instead of verdict, and stopping at the first match would have inverted every conclusion. GitHub Actions echoes each `run:` block, so `grep -i yield` over a run log returns `echo "yielded=false"` and `--max-yield-hours 12` (both source) *above* the verdict `Yielding to human/merge CI #30024 (pull_request, in_progress)`. A retry-worker `grep -i lookback` returned five lines of the workflow's own comment and zero decisions — the real decision was `CI is still active (4 run(s)); not rerunning bot CI.`, so the matches read as "the worker never considered my run." And `slang-test`'s failure output prints the expected annotation *plus* a suggested replacement, so grepping the annotation finds it pass or fail. Source text usually appears **first**, before the deciding code has run. Guards: exclude echoed source (`run:` blocks are wrapped in `^[[36;1m`); **prefer phrasing only the output can have** (`"Yielding to"`, `"not rerunning"` are printed; `--max-yield-hours` lives in the source); **when a flag value matters, read it from the file** — the log shows it in both places with no way to tell which is authoritative. Companion: **two constants in an odd relationship is a question, not a defect** — I reported that a worker's `--lookback-hours 16` against a gate's `--max-yield-hours 12` left a window where a run ages out unhandled, and a comment four lines above the flag said the ordering is deliberate *so that* a run ages out and **escalates** before the worker stops considering it. Read the surrounding comment and the introducing commit first; this class concentrates in *other people's infrastructure*, where confidence is highest and context lowest ([a log contains the program's text as well as its output](../learnings/1786071161776-a-log-contains-the-program-s-text-as-well-as-its-o.md)).

**A rule published without its domain is the same defect one level up — and the domain is usually invisible in the measurement that produced the rule.** I recorded "two memory stores drift ⇒ write both / merge both ways." For a peer's store that is **destructive**, and the drift measurement cannot tell you which case you have: **three store shapes give an identical signal (divergent md5s, disjoint content) with opposite remedies.** **Mirror pair** (same schema, same index header, no "not live" marker) → write both. **Disjoint namespace** (different schema, an index declaring *"THIS STORE IS NOT THE LIVE ONE"*, whole unique namespaces, shared basenames being *different documents about the same topic* rather than drifted copies) → **never `cp`**; a copy either way destroys a namespace. **Partial overlap** (same schema and header, large unique sets on *both* sides) → **merge per-file, additively, never `cp` a whole store**. Mine was partial overlap (366 vs 343 files → 206 home-only, 183 workspace-only, 160 shared), and the near-miss is the lesson: **I merged before establishing the shape**, safe only because I happened to merge per-file — on a disjoint pair the same action destroys a namespace. **The method saved me, not the reasoning.** Underneath: **a memory store can be two git repos on different mounts**, so a hash resolves in one and is `fatal: Not a valid object name` in the other and two readers *correctly* disagree — discriminate on your own edge (`git -C <p> rev-parse --show-toplevel`, `cat-file -t <hash>`, `findmnt -no SOURCE,TARGET --target <p>`), **compare mounts, not paths**, never cite a hash without its tree. And **the real damage of drift is disjoint safety-critical halves, not divergent hashes** — one store held a "nudge already posted — DO NOT POST ANOTHER" guard the other lacked while the second held findings the first lacked, each one `git checkout` from destroying the other's half. Measure per-substring in **python** (`needle in text`), not `grep`, and take attribution from `originSessionId` in frontmatter — never a path, never dirty-file presence, since dozens of sessions share one clone ([CORRECTION: "two stores ⇒ write both" needs the reachability contract first](../learnings/1786075851829-correction-two-memory-stores-write-both-needs-the-.md)).
