> **This page is part 7 of 9** of the PR Review Practices synthesis (split 2026-08-06 to stay under the 40 KB read cap). Siblings: [part 1](review-pr-practices.md), [part 2](review-pr-practices-2.md), [part 3](review-pr-practices-3.md), [part 4](review-pr-practices-4.md), [part 5](review-pr-practices-5.md), [part 6](review-pr-practices-6.md), [part 8](review-pr-practices-8.md), [part 9](review-pr-practices-9.md). ## TL;DR
- **Every reviewer fails toward CLEAN.** Devin exit 0 is not a signal; Reviewer A can emit a 0-byte or budget-capped output; Reviewer C can skip environmentally. **Verify each reviewer produced findings before treating "no findings" as a result** — an absent reviewer and a clean reviewer are byte-identical downstream.
- **Watch the ARTIFACT, not the subagent.** A Devin subagent returns before `devin-fetch.sh` finishes; a detached reviewer's completion is proven by its exit marker, never by streamed JSON. Anchor monitors to exit markers.
- **Read the full page dump, not the summary file.** `devin-flags.md` can have an EMPTY `## Flags` section while `devin-page.txt` from the same run shows real findings — synthesizing from the summary records a false "0 findings" and carries a false-clean prior into the challenger.
- **Reviewer A needs an isolated checkout.** Fleet contention on a shared repo root corrupts runs; `$30` is too low a budget cap and produces silent truncation. Use fresh per-run out-dirs to avoid `/tmp` collisions.
- **Two bots agreeing measures shared priors, not correctness.** Independent bots flagging the same item is weak corroboration; read the human review thread before scoring any structure/maintainability gap.
- **A bot finding a named maintainer already overruled ON THIS PR is not an open gap** — but **lead with the technical grounds**, never the maintainer's preference. Maintainer preference is supporting context; a repo guideline is not cleared by taste alone.
- **A refuted 🔴 does not become WOULD_APPROVE**, and a standing human `CHANGES_REQUESTED` caps the verdict at ABSTAIN. Never round up.
- **A mid-iteration `diff_hash` mismatch is expected under debounce**, not a bug. Pin the head, byte-prove reviews against it, and re-verify a stale secondary reviewer's flags at the current head.
- **Re-review scope: redesign gaps and self-recommended nits do not reset the pipeline.** Additive nit rounds are fine; a full re-run is not.
- **The review signal is endpoint-split across three surfaces** (`pulls/N/reviews`, `pulls/N/comments`, `issues/N/comments`) and the harvest reads one. That split is a property of GitHub's data model, so **every consumer inherits the blind spot independently — fixing one instance is not fixing the class.**
- **A GitHub post gates on the literal marker, not on prose.** Post only in COMMENT state; never APPROVE/REQUEST_CHANGES from a runner.
- **Empirical probes can test the wrong sub-case.** A probe that varies the intended factor while holding the confound constant reads as decisive and proves nothing — name the factor and the confound before citing a control.
- **In an artifact where claims cite `file:line`, the UNCITED SENTENCE IS THE DEFECT** — in a document whose norm is citation, the citation outlier is where an inference got restated as an observation. Run that self-check mechanically over your own draft.
- **Recording is not routing.** Documenting a blocking infra defect any number of times never reaches a file only an operator can edit. The record serves the next agent; the escalation serves the fix — do both.
- **A stale webhook dispatch on an already-decided PR is a no-op plus a report, never a re-decision.** `record_decision` is idempotent per `(repo, pr, sha)`, so re-deciding CLOBBERS a human-joined calibration row with a verdict contaminated by post-hoc information.

## Approver Deep-Dive: Head-Pinning Races, Devin Infra, Challenger Probes, and Human Calibration (2026-07-15 fold) — part 1/3

This section consolidates a large batch of `slang-pr-approver` / `slangpy-pr-approver` operational lessons from the shadow-mode ledger — refining the head-pinning, harvest-tier, Devin-infra, clause-gap, challenger-probe, critique-gate, and human-calibration bodies above.

### Harvest tiers, the late-post race, and re-harvesting at record time

The dominant harvest hazard remains the **late-post race**: on slang the production `github-actions[bot]` claude-pr-review does not post promptly, and its **"Claude Code Assistant" check-run reaching `skipped`/`completed` is a red herring, not evidence the primary review was skipped** — the real formal review lands 25–45 min after the push, and the "review" workflow JOB stays `in_progress` long after its inner sub-check completes (a large post-review dismiss+submit lag). Key off the actual `github-actions[bot]` review appearing at the pinned SHA via `gh pr view --json reviews`, and **always re-harvest immediately before `record_decision`**, not just during the exit-22 window ([Claude Code Assistant skipped while real review posts 25-45min later](wiki/learnings/1784075137829-approver-infra-abstain-slang-claude-code-assistant.md), [claude-pr-review sub-check completion ≠ review body posted](wiki/learnings/1784078543250-approver-clause-gap-claude-pr-review-sub-check-com.md), [re-harvest before recording — primary can post mid-session after a Devin-only draft](wiki/learnings/1784032917245-approver-challenger-miss-re-harvest-before-recordi.md)). On a `synchronize` re-push whose head is a master-merge, **harvest exit 10 (stale-only) + a live `in_progress` "review" check-run is a timing race, not a Devin-only trigger — wait for the primary** ([stale-harvest + in_progress production review = wait, don't fall to Devin-only](wiki/learnings/1784042795116-approver-infra-abstain-stale-harvest-in-progress-p.md), [on synchronize the production 'review' check can still be in_progress at synthesis](wiki/learnings/1784049951158-approver-infra-abstain-on-synchronize-the-producti.md)). A `synchronize` burst can advance the head multiple times mid-wait: poll `headRefOid` on every re-harvest and **re-pin to the settled head before harvesting**, or you decide on a superseded SHA the primary never reviewed ([synchronize burst can advance head mid-wait — re-pin to settled head before harvest](wiki/learnings/1784034617985-approver-challenger-miss-synchronize-burst-can-adv.md)).

Two refinements on stale-review handling. **A stale bot review whose `<reviewed>...<head>` delta touches 0 `source/` files is source-current signal, not noise** — count source-touching files in the compare API; a 🟡/🔴 verdict on byte-identical source is a maintainer-proxy "do not auto-approve" prior that keeps the decision from rounding up ([a stale bot review whose head-delta touches 0 source files is source-current](wiki/learnings/1784035570681-approver-clause-gap-a-stale-bot-review-whose-head-.md)). And **`harvest.json` reports only the CHOSEN bot review** — when multiple CodeRabbit reviews coexist across commits (a large full review at an older SHA + a small incremental re-review at the head), provenance caveats must reflect the FULL live picture via a GraphQL per-review `commit{oid}` query, not the single harvest verdict ([harvest.json reports only the chosen bot review; verify per-commit via GraphQL](wiki/learnings/1784034639546-approver-critique-mustfix-harvest-json-reports-onl.md)). On **slang-rhi (and any repo lacking `claude-pr-review.yml`), harvest exit 20 is the expected Devin-only tier by design, not a missed harvest** — slang-rhi has only `claude.yml` (mention responder) and CodeRabbit auto-pauses to a walkthrough *issue comment*, so verify via the repo's `.github/workflows` + CodeRabbit's commit *status* (not its comments) before treating exit 20 as a skip ([slang-rhi Devin-only tier is legitimate, not a missed harvest](wiki/learnings/1784011099646-approver-clause-gap-slang-rhi-devin-only-tier-is-l.md)). A late human APPROVE can also race in during harvest/Devin: the `mode` ledger tag is derived at staging, so **re-check reviews at record time** — a maintainer APPROVE on the pinned SHA in the harvest+Devin window means the correct tag is `live_late`, and any late verdict (especially a `CHANGES_REQUESTED` that would invalidate a WOULD_APPROVE) must be joined onto the same ledger row via `record_human_verdict` ([mode=live can be stale on fast PRs — a human review may land between staging and decision](wiki/learnings/1784026123581-approver-clause-gap-mode-live-can-be-stale-on-fast.md), [re-fetch PR reviews at record time not just staging (confirmed live #11987 R2)](wiki/learnings/1784050296652-approver-clause-gap-re-fetch-pr-reviews-at-record-.md), [pr-approver must re-fetch reviews at record time not just staging](wiki/learnings/1784050376318-pr-approver-must-re-fetch-reviews-at-record-time-n.md)).

### Head-pinning discipline under active iteration

The subject of an approval decision is the **compiled behavior, not the commit SHA**. Re-pin the live head at BOTH critique stages, not just at build time — a rapidly-iterating author can push between build and record, and the codex gate re-verifies `headRefOid` at DECISION_REVIEW and OUTPUT_REVIEW, so a stale pin is a guaranteed must-fix ([re-pin live head at both critique stages](wiki/learnings/1784037974102-approver-critique-mustfix-re-pin-live-head-at-both.md)). But do not burn the full gated cycle on every push: when a run of heads is **codegen-inert** — the `source/slang/**` diff (excluding tests, stripping pure-comment/blank/`SLANG_ASSERT` lines) is empty — let the standing recorded decision RIDE, logging the head as "covered by \<recorded-sha\> (codegen-inert delta)" rather than losing a race against the author every ~45 min ([standing decision rides codegen-inert synchronizes](wiki/learnings/1784054163587-approver-clause-gap-standing-decision-rides-codege.md)). The guardrail is load-bearing: a push *labeled* doc-only that actually touches the emit path / IR-lowering / eligibility-predicate logic / target gating IS a codegen change and must re-trigger the full procedure (this is exactly where the `__grid_constant__` false-safe lived — verify behavior, never trust the commit message). The same shortcut applies at comment granularity — **a comment/whitespace-only delta proven by a FULL-file diff (not the compare summary) carries a prior CLEAN logic verdict to the new SHA** ([#11917 comment-only-delta re-verdict rode to merge with zero follow-up](wiki/learnings/1784063797593-approver-calibration-11917-comment-only-delta-re-v.md)). A **pure master-merge `synchronize` does NOT close a held coverage gap** — re-decide from the PR's own diff (`gh pr diff --name-only`; is the flagged file/test present at THIS head?), not from an orchestrator hint or a maintainer's approve; note that `diff_hash` legitimately differs across a master-merge even when the PR hunk is byte-identical because it hashes the full unified diff including context ([a pure master-merge synchronize does not close a held coverage gap](wiki/learnings/1784077537602-approver-challenger-a-synchronize-that-is-a-pure-m.md)). A **single `gh pr view --json changedFiles` read within seconds of a synchronize can be transient** (GitHub hasn't recomputed the merge base): read scope 2–3× back-to-back and require agreement — scope *shrinkage* below what a reviewer saw is the direction that produces false-safes, so a scope-larger critique finding is ground truth until you reproduce the smaller read ([a single gh pr view read of changedFiles can be transient during synchronize+force-push](wiki/learnings/1784021958594-approver-challenger-miss-a-single-gh-pr-view-read-.md)).

### Devin infra: retries, exec bits, drops, stalls, and cached snapshots

Devin failures on the sole-signal Devin-only tier are dominated by transient conditions that a single retry recovers, so **retry once (clear the chrome profile, delete stale `devin-error.txt`, widen `--max-minutes`) before recording NO_REVIEW_SIGNAL / ABSTAIN_INFRA** — a first-attempt exit-3 timeout is usually "not done yet," not a real failure ([devin-fetch.sh timeout (exit 3) on fresh PRs — retry once](wiki/learnings/1784019236976-approver-infra-abstain-devin-fetch-sh-timeout-exit.md), [Devin timeout on the sole-signal Devin-only tier: retry once](wiki/learnings/1784074357103-approver-infra-abstain-devin-timeout-on-the-sole-s.md)). A Devin **stall at the URL-rewrite handoff is non-blocking when the primary bot-review tier is already secured** — start Devin in the background early to overlap the harvest wait, cap its wait ~3 min after the primary lands, and note `devin: skipped_stall`; only escalate to ABSTAIN_INFRA when Devin is the SOLE signal ([Devin devin-fetch.sh stall at URL-rewrite is non-blocking when primary tier is secured](wiki/learnings/1784042688985-approver-infra-abstain-devin-devin-fetch-sh-stall-.md)). Two silent-data traps invalidate a Devin "clean" read: **`devin-fetch.sh` can drop the "N Flag" block from `devin-flags.md`** while the raw `devin-page.txt` shows `≥1 Flag` — always cross-check the raw page's tally (`grep -nE '[0-9]+ Bug|[0-9]+ Flag'`) before synthesizing, and treat "Loading diffs…"/commit-status `unknown` as "not fully settled" ([devin-fetch.sh drops the 'N Flag' block — cross-check raw devin-page.txt](wiki/learnings/1784017360003-approver-infra-abstain-devin-fetch-sh-drops-the-n-.md)); and a **`devin-commit-status.txt` reading `"unknown"` (not "up to date") on a `synchronize` signals a CACHED prior-revision analysis** — do NOT abstain and do NOT trust it blindly; verify each flagged finding directly against the pinned head's `compare` delta, since a byte-for-byte-verified finding stands regardless of Devin's cache state ([Devin commit-status 'unknown' ≠ ABSTAIN — verify the flagged finding on the pinned head](wiki/learnings/1784016854486-approver-infra-abstain-devin-commit-status-unknown.md)). For a **companion clang-format PR whose base is the feature branch, a maintainer force-push of that base makes Devin's commit-scoped review miss the parent PR's full merge-delta** — compare Devin's file count to the live `base...head` scope; a scope mismatch is ABSTAIN_INFRA (STALE_STAGE), and the substantive change lives in the parent PR ([companion clang-format PR — base force-pushed underneath ⇒ Devin misses merge-delta](wiki/learnings/1784021932868-approver-infra-abstain-companion-clang-format-pr-b.md)). Never optimistically pre-fill `reviewers_complete:true` before Devin reaches a terminal state — it is a harness-integrity assertion the critique gate checks against the artifact on disk, true only when `devin-flags.md` exists or a bot review was harvested ([never set reviewers_complete:true before Devin reaches a terminal state](wiki/learnings/1784049951184-approver-critique-mustfix-never-set-reviewers-comp.md)). When a **BLOCK-vs-not pivot needs a slow build+probe that could outlast the session, record ABSTAIN_INFRA:CHALLENGER_INCOMPLETE now and supersede later** — don't leave the pivot unrecorded; a `pr_merged` webhook waking a dormant decision no-ops `record_human_verdict` if no ledger row exists for the pinned commit ([a slow build+probe on a BLOCK-vs-not pivot can outrun the session — bound it or ABSTAIN promptly](wiki/learnings/1784055090518-approver-infra-abstain-a-slow-build-probe-on-a-blo.md)).

### Clause gaps: CI-green, size cap, protected paths, and merge-commit blind spots

Several clause gaps refine the Step-1 body above. **`ci_green_on_sha` passes on the legacy combined-status API even when the real build/slang-test CI never ran** — on a `CONFLICTING`/deeply-behind PR, `pull_request`-triggered CI silently doesn't dispatch, so combined-status green aggregates only trivial commit-status contexts (license/CLA/CodeRabbit); independently query `actions/runs?head_sha=` and `commits/<sha>/check-runs` and treat "no build/test check-run present" as UNEVALUABLE → ABSTAIN_POLICY:CHALLENGER_CONCERN ([ci_green_on_sha passes on legacy combined-status even when real CI never ran](wiki/learnings/1784017419889-approver-clause-gap-ci-green-on-sha-passes-on-lega.md)). The flip side: for **capdef/capability-atom PRs, `check-cmdline-ref` (regenerating `docs/command-line-slangc-reference.md`) fails if the second generated doc isn't refreshed** — combined-status red then correctly fails `ci_green_on_sha`, and even trivial-to-fix CI-red is not approvable ([capdef atom PRs: check-cmdline-ref fails if command-line-slangc-reference.md isn't regenerated](wiki/learnings/1784026216900-approver-clause-gap-capdef-atom-prs-check-cmdline-.md)). But under the **`v0-shadow-relaxed` policy `require_ci_green:false`, a red *required* check does NOT trip `ci_green_on_sha`** (the clause passes "policy does not require CI green") — the CI-red must be routed through the challenger as an OPEN_GAP, so read `clauses.json`/`policy_version` before naming a reason_code ([under v0-shadow-relaxed a red required check does NOT trip ci_green_on_sha](wiki/learnings/1784049960961-approver-clause-gap-under-v0-shadow-relaxed-a-red-.md)). **Eligibility is a property of each revision's cumulative diff, not the PR** — `tier_eligible` can flip pass→fail when a later push adds a large test/backend (re-score every settled head; the script computes `base...commit_sha` full-PR additions+deletions, not the incremental delta) ([a PR can cross the size cap mid-revision — re-score tier_eligible every revision](wiki/learnings/1784020764751-approver-clause-gap-a-pr-can-cross-the-size-cap-mi.md)). On protected paths: **never hand-judge from a recalled learning** — run `eval-clauses.py` and read the emitted `policy_version`; the relaxed mount narrows `protected_paths` to only `[".github/**", "**/slang-tag-version.h"]`, so a bot-authored CMake/submodule change passes `no_protected_paths` and is a correct Devin-only-tier WOULD_APPROVE, not the CLAUSE_FAIL a bundled-default recall would predict ([bot-authored CMake/submodule change is Devin-only tier; relaxed policy does NOT protect external/CMakeLists.txt](wiki/learnings/1784074325850-approver-clause-gap-bot-authored-cmake-submodule-c.md)). A **terminal Step-1 clause FAIL dominates a co-occurring `commit_match=unevaluable` / no-review-signal — record ABSTAIN_POLICY, not ABSTAIN_INFRA** (the unevaluable is subordinate to the FAIL, and clause FAIL short-circuits harvest/Devin/challenger) ([re-visited under size-cap: subordinate unevaluable does not make a clause FAIL into ABSTAIN_INFRA](wiki/learnings/1784020764751-approver-clause-gap-a-pr-can-cross-the-size-cap-mi.md)). Two ordering/blind-spot gaps: **`eval-clauses.py`'s `commit_match` clause parses the SYNTHESIZED `review-doc.md`, not `harvest.json`** — synthesize the doc first or you get a spurious `commit_match:unevaluable` → ABSTAIN_INFRA ([eval-clauses.py commit_match reads the synthesized review-doc, not harvest.json — synthesize first](wiki/learnings/1784038871000-approver-clause-gap-eval-clauses-py-commit-match-r.md)); and on a **master-merge-commit head, the `base...commit_sha` changed-path view surfaces only the second-parent delta** and can miss a PR-changed protected file — cross-check with `gh pr view --json files` ([under v0-shadow-relaxed: master-merge-head changed-path blind spot](wiki/learnings/1784049960961-approver-clause-gap-under-v0-shadow-relaxed-a-red-.md)).
