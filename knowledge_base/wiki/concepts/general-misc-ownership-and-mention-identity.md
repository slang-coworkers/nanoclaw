# Ownership and Mention Identity

## TL;DR

- Verify any person you name as author/owner in a public comment against the live source (`gh api .../pulls/<n> --jq .user.login`, commit `.author.login`; for a decision owner, `issues/<n>/events` assigned/unassigned), never memory. The PR number can be right while the person is wrong; `Office-<name>` labels and assignees are a cross-check, not proof.
- Confirm PR authorship via `pulls/<n>/commits`, never `commits?sha=<branch>` (ancestry drags in the bot's commits from other PRs after a master-merge). Before calling a design change "unapproved", list commit authors and assignees: the maintainer may have written it.
- Quote a maintainer authorization only when the words are in a real inbound and the comment id resolves; a relayer's judgment is "per the handoff / held pending maintainer review". "Verify it's clean" means re-reading the current bytes on GitHub. Fix your own comment in place; route a PR body you don't own to its owner; correct the flagger factually and fix internal notes with the same error.
- Stand down when a maintainer or external contributor drives the fix (maintainer assignee, "I'll take this", invited contributor, linked PR open): a competing bot PR is likely closed even when correct. Bias to advisory triage; any draft stays thin, parked, and closes with the issue. Re-engage only if the contributor abandons it AND a maintainer asks the bot.
- "Unassigned" is a live fact: re-check assignees at every GO, nudge, and status report. An assignee changes whom to ask: ask them on GitHub, keep the operator for what they cannot do. A "dropped promise, re-wake" nudge can resolve to STAND-DOWN; answer the parent's premise with the better-grounded outcome.
- Parked issues change silently. On every re-check read the timeline (`assigned`, `labeled`, `milestoned`, Issue Type, `cross-referenced`, `closed`) and every linking issue/PR; `updatedAt` later than the last comment is the trigger. An assignee owns the issue (hand off only on their ask); a moved direction means no handoff; Type and labels (`SPF:*`, `slang 202c`) are hints, not decisions. Check `state`/`closedAt` and the reporter's own PR list: a merged `Fixes #N` PR means a parent `[Report]` only.
- On re-checks post nothing new; edit the bot's own last comment in place to name the owner or new plan. Diff live state against a one-shot re-check prompt before following its branches.
- A maintainer self-assign or milestone, even with no comment, holds the issue: before any deferred post or push re-read assignee + milestone + timeline; post nothing, push nothing, cancel the one-shot, park prepared commits on a local-only branch.
- Look for a community/duplicate PR at every gate (orchestrator before dispatch; triager before routing and on each fixer status; fixer at setup, build start, and before `gh pr create`; reviewer at start) with the timeline `cross-referenced` query, not only `in:body` search; re-check siblings in a batch; dedup with 2–3 phrasings. Re-derive PR linkage from `gh pr list --author` + `Fixes #N`, not a memo.
- When a human PR exists: stand the fixer down, open no competing PR, validate it locally (build its head privately, full repro matrix; with your own fix built, report only-yours / only-theirs / conflicting) before claiming it "covers" anything, and report results to the parent only, never on their PR (2026-11-05 ruling; earlier chains posted on the issue). A defect that also reproduces on master is filed as its own deduped bug naming the PR in plain text only. `action_required` CI means a maintainer must approve the run.
- Answer a perf CHANGES_REQUESTED with the PR's own benchmark, main vs PR on our GPU, medians over two runs; post on the issue and name the blocking reviewer. An old-head CHANGES_REQUESTED still blocks.
- An isolated `gh api .../comments` read is authoritative; a batched `gh issue view --json comments,labels,...` can return stale empties.

## Verifying author, owner, and authorization identity

Verify a named author or owner against the live source (`gh api repos/<o>/<r>/pulls/<n> --jq .user.login`, commit `.author.login`): #11877's verdict credited "@skiminki-nv (author of #11493)"; csyonghe wrote it, and jkwak-work called it out publicly. `Office-<name>` labels and assignees show who a maintainer *thinks* owns a change. ⚠️ If caught, correct the bot's comment in place, reply factually to the flagger, and fix internal notes with the same error ([mention identity](../learnings/1783355490728-verify-mention-identity-against-pr-commit-author-b.md)). A decision owner goes stale too: on slang#13823 a delta was about to ping saipraveenb25 as "shepherd" from memory, but they had unassigned themselves and jkwak-work (reviewer of blocking PR #13755) had self-assigned. A self-assignment sends no webhook, so before a nudge or Next-action naming a person run `gh api .../issues/<n>/events --jq '.[]|select(.event=="assigned" or .event=="unassigned")'`; a maintainer who self-assigned holds the decision and is not chased ([decision owner](../learnings/1794006591876-before-naming-a-decision-owner-in-a-parked-chain-n.md)).

Authorization provenance needs the same check. On slang#12176 a draft-PR go was relayed as a verbatim jkwak-work quote whose comment id 404'd, and the false attribution reached an issue comment and the PR body. ⛔ The first audit said "clean" from memory; only re-reading the live bytes (`gh api …/comments/<id> --jq .body`, `gh pr view --json body`) exposed it. `PATCH` your own comment; route the PR body to the fixer ([relayed authorization](../learnings/1784656869644-a-relayed-authorization-can-carry-a-fabricated-mai.md)).

## Confirming PR authorship from the right endpoint

`commits?sha=<branch>` returns full ancestry: on slang#10788, after a maintainer master-merge, it showed 9 nv-slang-bot commits (relayed as "bot engaged") while `pulls/10788/commits` showed 5, none from the bot. ⚠️ Authorship decides stand-down vs re-drive, so a false positive inverts the action ([pulls/<n>/commits](../learnings/1783639312952-verify-pr-authorship-via-pulls-n-commits-never-com.md)). The same listing (`--jq '.[] | "\(.sha[0:10]) \(.author.login)"'`) plus assignees comes before calling a direction change unapproved: on #13406 a reviewer flagged commit `4752340d4c` as walking back jhelferty-nv's "every read is an error" request, but jhelferty-nv had self-assigned the PR and authored it and 13 later commits. Once a maintainer takes over the branch, fixer and reviewer stand down unless asked ([commit authors](../learnings/1792056812976-before-flagging-no-maintainer-approval-for-a-desig.md)).

## Standing down when someone else owns the fix

A competing bot PR on an issue a maintainer or external contributor drives is likely closed even when correct (seven postmortems). Signals: maintainer assignee, "I'll take this", a linked open PR, a maintainer inviting a contributor. On a handoff read comments and author intent *before* coding; if owned, stop at a read-only plan and offer advisory triage ([CONSOLIDATED stand-down](../learnings/1782648000000-CONSOLIDATED-stand-down-when-maintainer-or-contributor-drives-fix.md), [invited contributor](../learnings/1780473504394-don-t-auto-implement-issues-owned-by-an-invited-ex.md)).

The assignee is a live fact. On slang#11970 a supervisor's "dropped promise, re-wake the fixer" nudge was factually right (no PR, bug live at HEAD), but `jhelferty-nv`, author of the framework the fix extends, had since self-assigned. ✅ STAND-DOWN was right: no PR, the diff kept as a ready-to-apply advisory, the public triage comment turned maintainer-facing (strip "handed to fixer / fix incoming"), the corrected picture sent up. ⚠️ Don't conclude "my triage artifact vanished" from a batched `gh issue view` ([dropped-promise nudge](../learnings/1784033086075-a-supervisor-dropped-promise-nudge-can-resolve-to-.md)). On slang#13554 a bot auto-assigned jkwak-work 18 s after bot PR #13563 opened, yet for four days the Orchestrator called it "unassigned" and twice asked the operator about GPU CI; one triager comment to jkwak-work got it approved, GPU-verified and merged in ~25 h. Keep the operator for what the maintainer cannot do, such as a ci-approver gate nobody is releasing ([assignee before GO](../learnings/1792030832310-verify-assignee-live-before-an-orchestrator-go-tha.md)).

A parked issue changes owner or direction the same way, usually without a comment. Read `gh api .../issues/<n>/timeline` (plus GraphQL `IssueTypeAddedEvent` for the native Type) and open every linking issue or PR. The recurring outcomes:

- **A reporter PR makes a handoff a duplicate**, and may already have merged and closed the issue, which `--comments` does not show: #13641's reporter opened non-draft #13707 while a maintainer self-assigned and milestoned (nothing posted: the ready PR shows the trail); #14066's MEMBER reporter merged #14068 within ~20 h; #14069's invited reporter opened and merged #14072. Check `state`/`closedAt` and the timeline, then `gh pr view <pr> --json state,mergedAt,closingIssuesReferences`, before any post or label; a merged `Fixes`/`Closes #N` PR gets a parent `[Report]` only, no fixer and no issue post ([parked-on-reporter](../learnings/1793663874761-parked-on-reporter-re-checks-read-the-issue-timeli.md), [merged reporter PR](../learnings/1793661430992-r6-hold-re-checks-check-the-timeline-for-a-merged-.md)). The timeline shows only this issue's cross-references, so also run `gh pr list -R <o>/<r> --author <reporter> --state all`: batch reporters fix parked siblings (the #14029 re-check found #14149 fixing sibling #14135). `gh issue view --json authorAssociation` does not exist (the field is per-comment); it exits 1 and breaks a `| jq` pipe ([reporter's PR list](../learnings/1793637251147-parked-issue-re-check-scan-the-reporter-s-own-pr-l.md)).
- **An assignment is human ownership**, self-assigned or assigned to another human. Since 2026-10-22 (#13638) hand off to slang-fixer only if the owner asks for or agrees to a bot PR, otherwise close the chain to the parent ([self-assigned: handoff conditional](../learnings/1792674358775-parked-issue-self-assigned-by-a-maintainer-fixer-h.md)). On #13878 jkwak-work assigned kaizhangNV, labeled and milestoned without answering the bot's (a)/(b) question; a comments-only check would have said "still parked". #13900 was the same, and its reporter closed the dependent slang-rhi PR as blocked ([assigning a human](../learnings/1793030545714-parked-issue-re-check-a-maintainer-assigning-a-hum.md)). Ownership freezes our deferred work: on slang#14179 a scheduled triage comment and a fix held to fold into bot PR #13572 (both timed to the now-retired 4-day "R6 hold"; R6 is label-only, see [triage decisions](agent-fixer-triage-decisions.md)) were overtaken when jkwak-work silently self-assigned and milestoned. The parent ruled it held: no comment, labels, Type, commit or `Fixes #N`; cancel the one-shot; keep draft and memo; resume only on an @nv-slang-bot mention, the assignee's ask or an operator ask. So a deferred post or push first re-reads `gh api .../issues/<n> --jq '{a:[.assignees[].login],m:.milestone.title}'` and the `/timeline` actor, and a prepared commit goes on a local-only branch (`git branch local/issue-<n>-<slug> <sha>`, then `git reset --keep <pushed-head>`) so a routine PR push cannot carry it ([held post](../learnings/1793879399551-before-a-held-scheduled-issue-post-re-check-assign.md), [don't fold into a bot PR](../learnings/1793879440953-a-maintainer-assigned-issue-is-held-don-t-fold-its.md)).
- **A linked issue can move the direction.** On #13750 the assignee's overhaul issue #13956 picked option C over the tentative rule A and closed a sibling issue and its bot PR as will-not-fix; don't hand off an out-of-date brief ([timeline cross-references](../learnings/1793041485668-parked-issue-re-checks-read-the-timeline-cross-ref.md)).
- **Issue Type and labels are hints.** A human-set Type (Documentation on a design question, #13637/#13638) leans toward an option. On #13870 the maintainer silently reassigned to the decision owner, set a milestone, and added `SPF:*` (Slang Proposed Feature lifecycle: Proposal / Experimental / Stable / Proposing to Stabilize / Proposing to Deprecate / Deprecated / Rejected / Withdrawn) and `slang 202c` (the version-gated breaking-change gate `isSlang202cOrLater` in `slang-check-decl.cpp`). Record a routing hint; stay parked until a comment states the decision ([labels/assignee as direction](../learnings/1793286193023-maintainer-direction-can-arrive-as-labels-assignee.md)).

In every outcome the bot posts no new comment; if its last comment still promises a fixer or invites a PR on the old plan, edit it in place to name the assignee or new direction and offer the bot fix on request (#13878, #13750). If the newest nv-slang-bot comment is the fixer's and already carries live state, neither PATCH it nor post a duplicate 5-bullet. A one-shot re-check prompt is itself stale input: diff live head SHA, labels, draft state and comments since its date. On #13876 the maintainer reversed the decision four days after the prompt and the fixer reworked the PR via webhook without a `[Fix Report]`; the right move was one `[Report]` delta correcting the parent's `[Triage Resolution]`, with the new decision verbatim in the chain-state page ([overtaken prompts](../learnings/1793102591047-one-shot-re-check-prompts-can-be-overtaken-by-even.md); see [Scope, staleness, and missing side-effects](verification-e-scope-staleness-and-side-effects.md)). The close-out is `[Resolution]` when answering a live parent inbound; a `--process-after` re-check has no inbound and uses the ungated `[Report]` ([Message Routing & Gating](agent-routing-message-routing-and-gating.md)). A reporter's side-finding issue filed with their own PR (#13847/#13848) is not ours to triage; a sibling session may hold it on purpose.

## Checking for a community or duplicate PR before building, reviewing, or opening

A human PR can appear at any gate, and each miss cost real work: #13645 opened 23 min *before* the slang#13635 handoff and the fixer built ~6 min before noticing; #13646 opened ~25 min *after* slang#13639's triage, caught only by codex PLAN_REVIEW; #13644 preceded bot PR #13650 by 12 min and the peer reviewer found it by accident ([before opening](../learnings/1792079739619-search-for-a-community-pr-on-the-issue-before-open.md)). Batch reporters opened `Fixes #N` 16 s after the issue (#13662 → #13663) or hours after triage (#13642 → #13651) ([before building](../learnings/1792074164816-re-check-for-a-community-pr-right-before-building-.md), [timeline cross-refs](../learnings/1792076007832-check-issue-timeline-for-cross-referenced-prs-befo.md), [batch reporter](../learnings/1792084496275-batch-external-reporter-files-issue-pr-together-al.md)); slang#13766's #13775 landed mid-build ([after build start](../learnings/1792503223381-recheck-for-a-reporter-s-own-pr-right-after-the-bu.md)); slang#14019's #14022 opened 98 s before the triage comment and the "no duplicate" search missed it (also #13909/#13927) ([contributor PR before building](../learnings/1793284881331-check-the-issue-timeline-for-a-contributor-pr-befo.md)). So the check runs at every gate:

- **Orchestrator before dispatch; triager before routing and on each fixer status:** the timeline query below, plus *sibling* timelines in a batch. Keyword dedup needs 2–3 phrasings ("loadModuleFromIRBlob" missed an older "IR binary modules" duplicate, #8744).
- **Fixer at setup, before the first edit, as the build starts, and before `gh pr create`:** `gh api .../issues/<n>/timeline --jq '.[]|select(.event=="cross-referenced")|.source.issue.number'` plus `gh pr list -R <o>/<r> --search "<n> in:body" --state open`. A search is not the link graph; the timeline sees PRs linking from a comment or commit.
- **Reviewer at start:** `gh pr list -R <repo> --state all --search "<n> OR <key symbol>"` and `closingIssuesReferences` on open PRs.

(A recall subagent may report your own fresh `active-work/<target>` sentinel as a "peer collision"; compare its `started-at` with your claim.)

For a core-team, self-assigned, or self-fixing reporter the `cross-referenced` query is the only guard now that R6 is label-only ([triage decisions](agent-fixer-triage-decisions.md)): on slang#13793 a core-team MEMBER self-assigned, the timeline cross-referenced their fork PR a minute later, it was handed to slang-fixer anyway, and ~5 h later their #13798 made the fixer's design waste. Run it before dispatch, at handoff, on every fixer status, and before the fixer opens a PR. Recovery: stand the fixer down, open no competing PR, edit our issue comment to hand review to the human PR, and surface the fixer's measured regression shapes (master-compiles/PR-errors inputs, each with a parity twin), nothing on the human's PR; that chain posted the shapes on the issue, which the newer 2026-11-05 ruling below replaces with a report to the parent ([during a fixer handoff](../learnings/1792555065568-triage-re-check-the-issue-timeline-for-a-reporter-.md), [before dispatching](../learnings/1792555081581-check-the-issue-timeline-for-a-reporter-or-assigne.md)).

On slang#14153 the reporter's #14170 opened 45 min after filing while the bot built a stacked fix under a hold; the parent deferred to it and the branch was dropped. With your branch already built, build both heads, run the same probe matrix, report only-yours / only-theirs / conflicting hunks, and let the parent decide; call out semantic test conflicts (a capability-level E36107 made the human PR's emit-level E55204 test line unreachable) ([reporter-opened PR](../learnings/1793622493442-before-building-a-bot-fix-check-for-a-reporter-ope.md)). Before saying a human PR "covers" the findings, build its head privately and run the full matrix (#14133: #14150 tested only the simple case; we ran 4 repros × 7 targets × {default, `-O0`} plus NVRTC). Worktree reuse: `git checkout --detach refs/triage/prN-head`; per submodule `git -c protocol.file.allow=always -c submodule.<name>.url=/workspace/agent/slang/.git/modules/<name> submodule update --init -- <path>` (shared-clone submodules are shallow, so `--reference` fails); `cmake --preset default`, build `slangc` + `slang-glslang` (~3 min). A stale `-version` string is not a stale binary; confirm by behavior. `/tmp` is wiped on restart; keep repros in a memory bundle (`repro-<N>.md`) ([private worktree](../learnings/1793667471112-verify-a-human-fix-pr-on-a-private-worktree-before.md)).

Validate rather than compete: apply the PR on a throwaway branch (`gh pr diff N > x.diff && git apply x.diff`), run the triage acceptance matrix, report gaps up; if both PRs exist, post a coordination note on both. Since the 2026-11-05 parent ruling (precedents #13419/#13420/#13640/#13733) results go to the parent only, which relays them to maintainers; no findings on the human PR. A defect on it that also reproduces on master (surplus attribute arguments assert in Debug because `checkAttribute` never rejects `argCount > paramCount`) is deduped and filed as its own bug (Type=Bug, `reproduced`, no operator go-ahead needed), mentioning the PR in plain text only and never asking the contributor to fix it. No re-check is scheduled; the PR's webhooks and merge are the resumable artifact (#14135 → #14149 → spin-off #14349) ([report up, file master defects](../learnings/1793890745354-human-pr-validation-report-findings-up-file-master.md)). The 2026-11-06 slang#14156 ruling restated it for an unrequested reporter fix PR: gaps (e.g. a missing test lane) to the parent only, no suggestions on the PR, workflow approval, CLA and review left to maintainers; the PR is the resumable artifact and our chain closes. It re-confirmed the 4-day R6 hold is retired (nanoclaw #1993): a triage on a human-filed issue posts when ready unless a person asks the bot to stand down ([reporter-owned PR](../learnings/1793960241760-reporter-owned-fix-pr-verify-and-report-up-only-do.md)). Use `gh pr view N --json …` and `gh pr diff N`; even a read-only `gh api .../pulls/N` trips the critique gate's PR-creation arm.

On slangpy#1231 a scheduled "no reporter PR after 72 h → hand to fixer" became a review: the reporter had opened #1234 ten minutes after our invite, but our index recorded #1233 (hence linkage from `gh pr list --author` plus a `Fixes #N` body grep). Its CI sat at `action_required`, the real blocker, so the Next-action names the shepherd and requested reviewers. Building the head (`--target slangpy_ext`, new test, repro, vulkan/cuda/cpu sweep) turned "a PR exists" into evidence, which that pre-ruling chain posted as non-blocking notes on the issue ([reporter PR on GPU](../learnings/1792422129310-before-a-scheduled-fixer-handoff-on-a-reporter-pat.md)). ccummingsNV's CHANGES_REQUESTED ("doubles name lookups per dispatch") then moved on our GPU run of the PR's own benchmark, twice per device on main and on the locally merged PR (restore with `checkout --detach <base>`). The built-in 3-decimal ms table is too coarse for µs dispatches, so a pytest plugin outside the worktree logged per-iteration means; outliers moved a 10-sample mean ~25%, so compare medians. GitHub does not clear a CHANGES_REQUESTED on an old head when new commits land ([perf CHANGES_REQUESTED](../learnings/1792681690533-answer-a-maintainer-s-perf-changes-requested-on-a-.md)).
