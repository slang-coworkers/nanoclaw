# Slang WGSL Backend + Cross-Target Emission (WGSL/Metal Shared)

The WGSL backend (`slang-emit-wgsl.cpp`) is a textual target that needs constructor-syntax aggregate initializers and lacks native combined samplers. This page covers WGSL emission plus bugs that span WGSL/Metal/CUDA through shared `$N` intrinsic strings, value-indexability and entry-point legalization. Metal-only topics (address spaces, `DescriptorHandle`, MetalLib versioning, array-of-resource, CI) live on [[wiki/concepts/slang-backends-metal.md]]. Combined-sampler texture-only ops (`GetDimensions`, `Load`, subscript) on HLSL/Metal/WGSL are on [[wiki/concepts/slang-backends-hlsl-combined-sampler-texture-ops.md]].

## TL;DR

- Since #14132 every module-scope `static const`, arrays included, emits as a WGSL `const`; the old runtime-indexed-array `var<private>` fallback is gone. A runtime-indexed `const` array validates and runs correctly on Dawn, and a `const` does not count against the 8192-byte private-variable limit.
- `SV_TARGET` and `SV_TARGET0` both map to `@location(0)`, so a return-0 fallback can't be tested in one struct.
- WGSL trailing switch-case `break;` is a real bug (older naga rejects it): verify validator claims across toolchain VERSIONS. `!supportsSwitchFallThrough()` is the wrong gate. Unconditional loops emit `loop` since PR #13071.
- Tint's PreventInfiniteLoops counters every loop it cannot prove finite; only a `for` with a `var` init, a `±1` update and a constant-bound first `if … break` passes (#13733). After #13740, `VECTOR_MAP_*` loops and the `[ForceInline]` one-trip wrapper still get one (#13765).
- WGSL f16 floats work; "missing f16" is the 16-bit INTEGER path (E56103), except f16 subgroup builtins vs the `slang-tint-0` pin.
- WGSL strides: `StructuredBuffer<float3, ScalarDataLayout>` is 16 (12 elsewhere; use `RWByteAddressBuffer.Load<float3>`); a `var<uniform>` array needs stride 16·k, fixable only by widening the element.
- Pass each WGSL builtin as its own parameter; one non-uniform builtin taints a whole context struct.
- `uniform S s; s.member.method()` copies all of `S` unless `deferBufferLoad` sinks the load (> 16 B and (> 128 B or an array)) (#13732).
- Combined-sampler texture-only ops leak the injected sampler; `$q` (#11816) fixed only `GetDimensions` on Metal/WGSL (#13737).
- `CHECK-DAG: WaveActiveCountBits` on CUDA/Metal is false confidence; check `__ballot_sync`/`__popc` or `simd_ballot`/`popcount`.
- Look up layouts by KEY: a positional index into a pre-flatten layout segfaults Metal/WGSL (#8183).
- WGSL `inout` arg from a global `static` gives `ptr<private>` into `ptr<function>` (#12173); fix `legalizeCall`'s skip-list on IR op/scope.
- Metal alone omits FP-literal suffixes. For a `-target glsl` text bug, check whether the WGSL emitter already solved it.
- Widening `[require]` needs a matching `__target_switch` `case`/`default`, or E36107 becomes an emit gap (#12165).
- groupshared-by-ref (#10641) breaks Metal, WGSL and CUDA differently; a green vk/HLSL/SPIR-V run clears none.
- Pointer address space is TYPE-LEVEL on Metal/WGSL (E30019), PASS-INFERRED on SPIR-V (E58005/E58004). An "X can't reach Y" claim needs a named diagnostic + test or a repro.
- Metal `&` (E36107) is only a `[require]` gate; `__getAddress` works. Maintainers are deprecating `&`, so route such issues to them instead of widening the gate (#14035).
- Metal wrapper swaps leak decorations (#10675, #13271; cloned param layouts also break CUDA): strip at the producer. Callee-first `-entry vsB -entry vsA` hangs HLSL/GLSL/WGSL; use `timeout`.

Companion page [[wiki/concepts/slang-backends-wgsl-matrix-and-validation.md]] covers WGSL matrix-operator validity (negation, int64 matrices), the §3.9 template-list ambiguity in argument lists, and GPU-free naga-wasm validation. WGSL uniformity analysis (spec rules, which context shapes pass Tint, the `__builtinWaveLaneCount` shadow store; #8774) is on [[wiki/concepts/slang-backends-wgsl-uniformity-and-shadow-globals.md]].

## Static-Const Arrays Are WGSL `const` (since #14132)

Since #14132 (merged 2026-10-31, 6815ed82), `WGSLSourceEmitter::emitVarKeywordImpl` emits every module-scope `static const`, arrays included, as a WGSL `const`; the `var<private>` fallback (`emitModuleScopeArrayConstAsPrivateVar`) is removed. A runtime-indexed `const` array validates and returns correct values on Dawn (L40S) and does not count against the 8192-byte private-address-space limit. Nested arrays still fold inner rows inline (`getFoldPolicy` / `isInnerGlobalAggregate` in slang-emit-c-like.cpp), as emitter policy, not a validity requirement. `docs/generated/design/target-pipelines/wgsl.md:1202-1224` still describes the old rule (doc gap in #13887) [static const arrays are `const` since #14132](../learnings/1793523729686-wgsl-static-const-arrays-are-module-scope-const-si.md). Notes saying "runtime-indexed static const arrays need `var<private>`" are stale. Still true from that era's review: `replaceGlobalConstants` inlines GlobalConstant values and removes the `IRGlobalConstant` before `simplifyIR`, and peephole folds constant-index reads, so "the module-scope array is initialized from another module-scope array" is a false positive in post-link IR [replaceGlobalConstants false-positive](../learnings/1781639050403-wgsl-static-const-array-review-replaceglobalconsta.md).

## WGSL @location Return-0 Fallback Branch

A `resolveWGSLLocation`-style `return 0` fallback can't be covered with `: SV_TARGET` beside `: SV_TARGET2` in one struct: bare `SV_TARGET` and `SV_TARGET0` both resolve to `@location(0)`. It needs a separate struct; declining is reasonable when the fallback is pre-existing [return-0 fallback can't be tested in one struct](../learnings/1781663682498-wgsl-location-return-0-fallback-branch-can-t-be-un.md).

## Per-Target Buffer Stride and the var<uniform> Array Rule

`StructuredBuffer<float3, ScalarDataLayout>` has stride 12 on D3D/HLSL, Vulkan/SPIR-V (layout arg required), CUDA and Metal, but **WGSL hard-codes 16** in `slang-ir-lower-buffer-element-type.cpp`. For a tight WGSL stride use `RWByteAddressBuffer.Load<float3>`/`.Store<float3>` (three `f32` loads); `scalarizeVectorLoadStore` is set for WGSL, Metal and CPU-via-LLVM in `slang-emit.cpp` [WGSL is the stride outlier](../learnings/1780177237717-slang-per-target-stride-for-structuredbuffer-float.md).

**The `var<uniform>` 16-byte rule is on array STRIDE; only widening the element fixes it (#13704).** WGSL §14.4.5 requires StrideOf(array<T,N>) = 16·k, with stride = roundUp(AlignOf(E), SizeOf(E)), so `array<i32,N>` has stride 4. `@align(n)` moves only a member offset and cannot go below AlignOf(T) (naga rejects `@align(4)` on `array<vec4<i32>,N>`), and WGSL has no stride attribute. Widen via Slang's `_Array_std140` vec4 wrapper or the spec's `@size(16)` wrapper struct. `uniform_buffer_standard_layout` relaxes the rule but only Dawn has it (Chrome 144; naga/wgpu 0.32 rejects, Safari lacks), and Slang never emits `requires uniform_buffer_standard_layout;`. Check with pip wgpu `create_shader_module` + `create_compute_pipeline` (`scratch-13704/align-probe/val2.py`) [uniform rule is on array stride](../learnings/1792627107595-wgsl-uniform-16-byte-rule-is-on-array-stride-align.md).

## Uniform-Struct Member Access Copies the Whole Struct Unless deferBufferLoad Sinks It (#13732)

For `uniform S s; s.member.method()`, `collectGlobalUniformParameters` (`slang-ir-collect-global-uniforms.cpp:364-366`) emits `load(fieldAddr(globalParams, s))`, loading all of `S`. Only `deferBufferLoad` (`slang-ir-defer-buffer-load.cpp:240-245`) sinks it to `load(fieldAddr(.., member))`, when `isTypePreferrableToDeferLoad` (`:59-92`) holds: size > 16 B, and > 128 B or containing an array. Otherwise `deferStorageToLogicalCasts` (`slang-ir-lower-buffer-element-type.cpp:1351-1479`) builds a whole `S_std140` temp on WGSL (`copyLogical` on SPIR-V) and passes `&tmp.member` to a callee specialized to `BorrowInParam(Member_std140)` (`:1570-1578`). 128 B array-free keeps the copy; 132 B does not. The same heuristic gates `specializeFuncsForBufferLoadArgs` ([[wiki/concepts/slang-b-bindings-and-backends.md]]). To find which pass splits two variants, `-dump-ir` both, split with `extras/split-ir-dump.py`, diff; the first differing section names the pass [gated by deferBufferLoad's heuristic](../learnings/1792249776321-wgsl-whole-uniform-struct-copy-is-gated-by-deferbu.md).

## Wave Aggregate Intrinsics (CUDA/Metal FileCheck Trap)

`//CHECK-DAG: WaveActiveCountBits` on CUDA/Metal is false confidence: only `case hlsl:` emits it. CUDA lowers to `__popc(__ballot_sync(...))`, Metal to `_WaveCountBits(WaveActiveBallot(value))`; the token appears only as the force-kept `[KnownBuiltin]` definition name. Check `__ballot_sync`/`__popc` (CUDA) and `simd_ballot`/`popcount` (Metal; `simd_is_first` for `WaveIsFirstLane`) [FileCheck passes for the wrong reason](../learnings/1780935575501-coverage-wave-aggregate-tests-cuda-metal-filecheck.md).

## Textual-Emitter Parity: Constructor Syntax, FP Literal Suffixes, f16

WGSL, like GLSL, is a constructor-syntax, no-brace-init target, so a `-target glsl` text bug (e.g. array brace init) often has an override in `slang-emit-wgsl.cpp` to port [WGSL is the stride outlier](../learnings/1780177237717-slang-per-target-stride-for-structuredbuffer-float.md).

Metal is the **lone** C-like backend that prints FP literals without a type suffix: `MetalSourceEmitter::emitSimpleValueImpl` (`slang-emit-metal.cpp:1128-1164`) omits MSL `h`/`f`, so `61440.hf` becomes a bare double and breaks a size-sensitive `as_type<ushort>(...)`. The fix mirrors the WGSL/HLSL path (#11837) [Metal FP literals lack suffix (#11837)](../learnings/1782814984950-slang-metal-backend-emits-fp-literals-with-no-type.md), [Metal is the lone suffix-less backend](../learnings/1782832643994-metal-emitter-is-the-lone-backend-that-omits-fp-li.md).

WGSL has 16-bit floats: a "WGSL missing f16" report is almost always the 16-bit **integer** (`bit_cast<uint16_t>`) path surfacing E56103 (#11835; see [[wiki/concepts/slang-backends-wgsl-f16-and-const-expressions.md]]) [E56103 is the 16-bit-INTEGER path](../learnings/1782813507927-wgsl-f16-floats-already-work-e56103-is-the-16-bit-.md). Exception: f16-returning subgroup builtins. Dawn/Tint removed `subgroups_f16` in April 2025, but the Windows test-only `slang-tint-0` pin (shader-slang/dawn 9255f960, Sept 2024) still requires it, so f16 subgroup code through `-target wgsl-spirv*` cannot satisfy both [Tint pin still requires subgroups_f16](../learnings/1792074066723-codex-critique-cwd-workspace-agent-can-make-codex-.md).

## WGSL Control-Flow Emission: Switch-Case Break, Native `loop`, Tint's Loop Counter

The WGSL emitter ends every switch `case`/`default` with `break;`. A first read called it redundant and downgraded #11946 to cosmetic [first read: trailing break valid](../learnings/1783296818057-wgsl-trailing-break-in-switch-cases-is-valid-redun.md), but it **is** a real bug because **older naga rejects** it; verify validator claims across toolchain VERSIONS [CORRECTION: older naga rejects](../learnings/1783300097186-correction-wgsl-redundant-switch-case-break-is-a-r.md). `!supportsSwitchFallThrough()` is the **wrong** gate: HLSL/FXC also returns false yet requires the break [supportsSwitchFallThrough is not a proxy](../learnings/1783300771712-slang-supportsswitchfallthrough-is-not-a-proxy-for.md).

Until PR #13071 (merged 2026-09-28, for #13066), `CLikeSourceEmitter::emitRegion` hard-coded `for(;;)` for every `LoopRegion` and WGSL inherited it. The PR added a `getUnconditionalLoopHeader()` hook that `WGSLSourceEmitter` overrides to print `loop`; no `continuing {}` is needed because the restructurer folds the condition into the body. Test: tests/wgsl/loop.slang [native loop by PR #13071](../learnings/1792156297428-wgsl-loop-emission-for-changed-to-native-loop-by-p.md).

That shape costs a Tint counter that blocks unrolling (#13733): the restructurer copies the IR continue block to every `continue` and the body end (`slang-ir-restructure.cpp:424-451`) instead of emitting a region. PreventInfiniteLoops adds a `4294967295` counter to every loop Dawn's `loop_analysis.cc` cannot prove finite. Provably finite needs an i32/u32 `var` index in the `ir::Loop` Initializer (only a `for` init fills it), whose only store is `v = v ± 1` in Continuing, tested by the first body `if` (only loads/binaries before it) against a constant with `< > <= >=` and a `break` in one arm. So `for (var p = 0; ; p = p + 1) { if (p <= 3) {} else { break; } … }` passes; a `var` before `loop { … continuing { p = p + 1; } }`, `break if`, `while`, a body-computed store or a runtime bound keep the counter. Confirmed by 14 probes (node `webgpu` 0.6.2, `create(['backend=vulkan','enable-dawn-features=dump_shaders'])`, grep the dump for `4294967295`) [only a var-init ±1 `for` is provably finite](../learnings/1792251784378-tint-preventinfiniteloops-only-a-wgsl-for-with-var.md). Running WGSL through Dawn on the GPU is on [[wiki/concepts/slang-backends-wgsl-on-gpu-execution.md]].

Counted-`for` emission (PR #13740) cut the reporter's counters from 5 to 1; core-module loops remain (#13765). Vector overloads with no `case wgsl:` fall through to `VECTOR_MAP_*` (hlsl.meta.slang:7957), a plain `for` lacking the `[ForceUnroll]` of its `glsl.meta.slang` copy. The last survivor is the one-trip `loop { ...; break; }` that `inlineMultipleBlockFuncBody` (slang-ir-inline.cpp:821) wraps around a `[ForceInline]` callee whose body contains a `for`. For no loop, use per-target `case wgsl:` arms or `[ForceUnroll]`; a vector bit test like `(asuint(x) & 0x7fffffffu) > 0x7f800000u` compiles to a loop-free `bitcast<vec3<u32>>` compare. (A `--reference` worktree to a shallow clone failed on submodules; `cp -a` of each `external/<sub>` fixed it.) [VECTOR_MAP + one-trip wrapper keep a counter](../learnings/1792502293606-wgsl-vector-map-loops-the-inline-one-trip-wrapper-.md)

## Entry-Point Output-Struct Flatten Desyncs Var-Layout (Metal/WGSL Crash)

slang#8183: a vertex OUTPUT struct with a nested-struct member and a semantic-less field segfaults on Metal/WGSL (the two targets running this legalization). `wrapReturnValueInStruct` captures the original struct's layout, `maybeFlattenNestedStructs` adds leaf fields **without rebuilding it**, and `ensureStructHasUserSemantic` indexes the stale layout by POSITION, null-dereferencing `findOffsetAttr` past the original field count. Fix at the producer (rebuild/remap the layout) and/or look up by KEY with an assert; a null-check masks the desync and risks mis-assigned varyings. Debug slangc repro: EXIT=139; explicit semantic → EXIT=0. Sibling of the #9580 varying-layout crash [flatten desyncs var-layout](../learnings/1784382530471-slang-metal-wgsl-entry-point-output-struct-flatten.md).

## Metal fwidth E36107 and the `[require]` / `__target_switch` Pairing Rule

**`fwidth(float2)` on Metal fails E36107 from a stdlib annotation, not a Metal gap (#12165).** Only the SCALAR overload declares `metal`; the VECTOR (`glsl_hlsl_spirv_wgsl`) and MATRIX (`glsl_hlsl_spirv`) overloads omit it. The vector overload needs BOTH the `[require]` atom AND `case metal: __intrinsic_asm "fwidth($0)";` (no metal case or `default:`); the matrix overload needs only `[require]`, since `default: MATRIX_MAP_UNARY` recurses to the scalar. Do NOT add `metal` to `fwidth_coarse`/`fwidth_fine`: `fragmentprocessing_derivativecontrol` deliberately omits Metal. E36107 triage: read the atom def AND the `[require]`, and cross-check a supporting sibling (`ddx`/`ddy` carry `metal` on all three overloads; `fwidth ≡ abs(ddx) + abs(ddy)`; `fragmentprocessing` at `slang-capabilities.capdef:2344` lists `fragment + metal`) [fwidth needs require AND switch arm](../learnings/1784627957519-metal-fwidth-e36107-stdlib-require-clause-and-targ.md).

**The `[require]` edit and the body `case`/`default` are one atomic change.** Adding an atom when the `__target_switch` has neither `case <target>:` nor `default:` turns a clear E36107 into an obscure emit failure or empty body. Inverse of the case-less-switch mechanic (#12274): a method-level `[require]` with no arm is inert as a gate on REMOVE and an unhandled emit on ADD, so read the body, not just the clause [widening [require] needs the paired case](../learnings/1785840965047-widening-a-require-target-set-is-only-half-the-fix.md).

## WGSL inout/out Arg from a Global static: Address-Space Mismatch (#12173)

`legalizeCall` (`slang-ir-wgsl-legalize.cpp:14-72`) bridges by-ref args with copy-in/copy-out temps but skips `kIROp_Var/Param/GlobalParam/GlobalVar`. A global `static` is `kIROp_GlobalVar` (`private`), so it is passed as `ptr<private,…>` into a `ptr<function,…>` param, which naga/wgpu rejects (`slangc -target wgsl` reproduces). Skipping block-local `kIROp_Var` is correct; the global-scope entries are the bug. `legalizeCall` runs BEFORE `specializeAddressSpaceForWGSL`, so the fix keys on IR op/scope, not address space: global-scope pointer args take the temp path [legalizeCall skip-list gap](../learnings/1784636859545-wgsl-inout-out-arg-from-global-static-ptr-address-.md).

## Metal Entry-Point Wrapping and Decoration Repointing

**Uniform wrapping (#10675).** Metal wraps entry-point `uniform` params (including `uniform T*`) in a synthesized `EntryPointParams` cbuffer (one `constant*` `[[buffer(0)]]`), costing a pointer param an extra hop; SPIR-V uses a push constant. The split is `slang-parameter-binding.cpp:3420` (only `isKhronosTarget(...)` uses push-constant rules), so `needConstantBuffer` is true on Metal (`slang-ir-entry-point-uniforms.cpp:264`). Both fixes (a dedicated Metal buffer index for `uniform T*`, or no wrapping) shift the host binding layout and are breaking; parked for a future-year release, pinned by `tests/metal/entry-point-uniform-vertex-struct-output.slang` [Metal wraps uniforms in a cbuffer](../learnings/1784653655393-metal-wraps-entry-point-uniform-params-incl-pointe.md).

**The wrapper-swap family.** #7669 (a Metal `StructuredBuffer` param loses `[[buffer(0)]]`) does not reproduce at HEAD: PR #11607 fixed it for duplicate #11606. `lowerOutParameters` creates a new wrapper while the hoisted uniform's `IREntryPointParamDecoration` still names the old function, so `introduceExplicitGlobalContext` dropped the buffer; `retargetEntryPointParamDecorations()` fixes it. For any pre-2026.06 open issue, reproduce at a fresh HEAD first [#7669 already fixed by #11607](../learnings/1784753556178-slang-7669-metal-structuredbuffer-binding-loss-alr.md).

**`[[stage_in]]` on a non-entry helper (#13271).** `lowerOutParameters` (via `legalizeShaderOutputParamsForMetal`) inlines the original only if `useCount == 1` (slang-ir-lower-out-parameters.cpp:401), but the uniform's `IREntryPointParamDecoration` is a second use, retargeted only afterwards (legalize-varying-params.cpp:5450). The original survives as a helper whose params keep their VaryingInput `IRLayoutDecoration`, and `emitFuncParamLayoutImpl` (slang-emit-metal.cpp:185) prints invalid `[[stage_in]]`. `fixEntryPointCallsites` leaks the same way (its clone keeps each param's layout). SV_*-only tests cannot see it; use a user-semantic input (`float3 p : POSITION`). Three demotion lists (fix-entrypoint-callsite.cpp, autodiff-fwd.cpp, lower-out-parameters.cpp) argue for one producer-side "demote former entry point" helper [former entry point not demoted](../learnings/1790389765020-metal-stage-in-on-a-non-entry-helper-former-entry-.md).

The fix retargets inside `lowerOutParameters` before the decision, so the original is inlined and deleted. Cascade: `EntryPointInfo::entryPointDecor` still named the old `IREntryPointDecoration`, so `packStageInParameters` → `getProfile()` crashed on a null operand; re-read the decoration from the returned wrapper (`transferFunctionDecorations` clones it). FileCheck for an attribute-free helper signature: `{{^[^[]*}} vsB_0({{[^[]*}}){{$}}` [entryPointDecor goes stale](../learnings/1790394201978-metal-loweroutparameters-entrypointinfo-entrypoint.md).

The `fixEntryPointCallsites` leak is not Metal-only: the pass (`slang-emit.cpp:2364`) runs for every target, and CUDA's `emitSimpleFuncParamsImpl` (`slang-emit-cuda.cpp:1597`) drops system-value params from the declaration while the call site passes them (`tests/spirv/nested-entrypoint.slang -target cuda -entry outerMain -entry innerMain` declares `innerMain_0()` but calls `innerMain_0(&_S2)`). Stripping the clone's param layouts at the producer (`removeParamLayoutDecorations`, #13284) fixes both; when fixing an IR shape for one emitter, grep every `getVarLayout(param)` reader and test each target [stale param layouts break CUDA too](../learnings/1790761751687-stale-entry-point-param-layouts-on-a-cloned-ordina.md), [CUDA mismatch fixed by #13284](../learnings/1790758864251-slang-listing-the-callee-entry-point-first-hangs-h.md).

Separate master hang (unfiled): with `vsA` calling `vsB` (both returning an `SV_Position`/`TEXCOORD` struct), callee-first `-entry vsB -entry vsA` spins 6+ minutes on HLSL/GLSL/WGSL; Metal, SPIR-V and `-entry vsA` alone (0.3 s) are fine. Wrap slangc in `timeout 60` when cross-target diffing [callee-first order hangs](../learnings/1790758864251-slang-listing-the-callee-entry-point-first-hangs-h.md). Sibling worktree fetches move the shared clone's `origin/master`, so restore files from the pinned base SHA; each codex PLAN/CODE/OUTPUT critique round needs a `REQUIREMENTS:` line [stale param layouts](../learnings/1790761751687-stale-entry-point-param-layouts-on-a-cloned-ordina.md).

## groupshared-by-ref Multi-Backend Breakage (#10641)

A bare `groupshared` array param **by reference** (#10641 / PR #11709) breaks three backends differently; a green vk/HLSL/SPIR-V run clears NONE. Metal: a silent abort in the address-space pass, because the param type is `RateQualified(GroupShared, BorrowInOutParam(Array))` and `as<IRPtrTypeBase>(param->getFullType())` is null; unwrap the rate with `getDataType()`/`setDataType()`. WGSL: the callee MUST be inlined BEFORE `legalizeIRForWGSL`, or `legalizeCall` bridges a whole-array `var<workgroup>` copy, silently reintroducing the per-invocation copy #10641 removes; `WGSL-NOT: ptr<workgroup` misses it, so assert no whole-array copy and add a behavioral compute lane. Test the real downstream compiler via a `-target ptx`/NVRTC lane, not only emitted source [groupshared by-ref gotchas](../learnings/1784756124264-groupshared-by-ref-param-metal-addr-space-wgsl-inl.md).

## Pointer Address Space Is Type-Level on Metal/WGSL, Pass-Inferred on SPIR-V

On **SPIR-V** a source `int*` has no address space until `specializeAddressSpace` assigns a storage class, so returning pointers from two address spaces fails in or after that pass (E58005 `conflicting-return-pointer-storage-classes`; E58004 for non-returnable classes). On **Metal/WGSL** the address space is in the type (`Ptr<T, Access, AddressSpace.Device|GroupShared|…, Layout>`), so the same conflict (`uniform int*` vs `__getAddress(groupshared)`) is a type mismatch, **E30019**, in checking. Metal does allow returning pointers and `__getAddress` (`tests/metal/metal-pointer-params.slang`, `pointer-in-buffer-getaddress.slang`); E31160 on a function-local, failure on structured-buffer `buf[i]` on all targets (#10841), and a context-specific E36107 for `&gShared` in a compute entry point do not mean "no pointers". Maintainer rule: an "X cannot reach Y" claim names the enforcing diagnostic with a test or a failing repro, or weakens to "not attempted; covered by construction" [address space type-level vs pass-inferred](../learnings/1789546490977-pointer-address-space-is-type-level-on-metal-wgsl-.md).

**`&` on Metal is blocked only by its capability gate, and the gate should stay (#14035).** `operator&` (`core.meta.slang:3091`) is `[require(cpp_cuda_spirv_llvm)]` (no Metal since #4710), while `__getAddress` is `cpp_cuda_metal_spirv_llvm` (`slang-check-decl.cpp:22442`). So on Metal `&p[i]` gives E36107, but `__getAddress(p[i])` and `__getAddress(p->f)` compile (emit `p + i`), and `-ignore-capabilities` shows the Metal path already handles `&` for device, threadgroup and thread pointers. Do not widen the `&` gate: maintainers plan to deprecate `&` (#10280 commit b1505c6e5, jkwak-work on #9148, jhelferty-nv on #10619, draft #10206 `RemovedSince(2026)`, which leaves `__getAddress` out of its guidance), and under #10206 there is no public spelling for a field address. Route such issues to maintainers. `slangc -ignore-capabilities` probes "is the `[require]` gate the only blocker". WGSL has no device pointers: `uniform int*` silently emits invalid `ptr<, T>` (#13399) [`&` is gate-only; being deprecated](../learnings/1793295608390-e36107-on-operator-for-metal-gate-only-getaddress-.md).
