# Slang WGSL Backend + Cross-Target Emission (WGSL/Metal Shared)

The WGSL backend (`slang-emit-wgsl.cpp`) is a textual target that needs constructor-syntax aggregate initializers and lacks native combined samplers. This page covers WGSL emission plus bugs that span WGSL/Metal/CUDA through shared `$N` intrinsic strings, value-indexability and entry-point legalization. Metal-only topics (address spaces, `DescriptorHandle`, MetalLib versioning, array-of-resource, CI) live on [[wiki/concepts/slang-backends-metal.md]]. Combined-sampler texture-only ops (`GetDimensions`, `Load`, subscript) on HLSL/Metal/WGSL are on [[wiki/concepts/slang-backends-hlsl-combined-sampler-texture-ops.md]].

## TL;DR

- A runtime-indexed `static const` array emits as WGSL `var<private>` (`kIROp_ArrayType` only); safe because `replaceGlobalConstants` removes the GlobalConstant before emit.
- `SV_TARGET` and `SV_TARGET0` both map to `@location(0)`, so a return-0 fallback can't be tested in one struct.
- WGSL trailing switch-case `break;` is a real bug (older naga rejects it): verify validator claims across toolchain VERSIONS. `!supportsSwitchFallThrough()` is the wrong gate. Unconditional loops emit `loop` since PR #13071.
- Tint's PreventInfiniteLoops counters every loop it cannot prove finite; only a `for` with a `var` init, a `±1` update and a constant-bound first `if … break` passes (#13733). After #13740, `VECTOR_MAP_*` loops and the `[ForceInline]` one-trip wrapper still get one (#13765).
- WGSL f16 floats work; "missing f16" is the 16-bit INTEGER path (E56103), except f16 subgroup builtins vs the `slang-tint-0` pin.
- WGSL strides: `StructuredBuffer<float3, ScalarDataLayout>` is 16 (12 elsewhere; use `RWByteAddressBuffer.Load<float3>`); a `var<uniform>` array needs stride 16·k, fixable only by widening the element.
- Pass each WGSL builtin as its own parameter; one non-uniform builtin taints a whole context struct.
- `uniform S s; s.member.method()` copies all of `S` unless `deferBufferLoad` sinks the load (> 16 B and (> 128 B or an array)) (#13732).
- Combined-sampler texture-only ops leak the injected sampler; `$q` (#11816) fixed only `GetDimensions` on Metal/WGSL (#13737).
- `CHECK-DAG: WaveActiveCountBits` on CUDA/Metal is false confidence; check `__ballot_sync`/`__popc` or `simd_ballot`/`popcount`.
- Look up layouts by KEY: a positional index into a pre-flatten layout segfaults Metal/WGSL (#8183).
- WGSL `inout` arg from a global `static` gives `ptr<private>` into `ptr<function>` (#12173); fix `legalizeCall`'s skip-list on IR op/scope.
- Metal alone omits FP-literal suffixes. For a `-target glsl` text bug, check whether the WGSL emitter already solved it.
- Widening `[require]` needs a matching `__target_switch` `case`/`default`, or E36107 becomes an emit gap (#12165).
- groupshared-by-ref (#10641) breaks Metal, WGSL and CUDA differently; a green vk/HLSL/SPIR-V run clears none.
- Pointer address space is TYPE-LEVEL on Metal/WGSL (E30019), PASS-INFERRED on SPIR-V (E58005/E58004). An "X can't reach Y" claim needs a named diagnostic + test or a repro.
- Metal `&` (E36107) is only a `[require]` gate; `__getAddress` works. Maintainers are deprecating `&`, so route such issues to them instead of widening the gate (#14035).
- Metal wrapper swaps leak decorations (#10675, #13271; cloned param layouts also break CUDA): strip at the producer. Callee-first `-entry vsB -entry vsA` hangs HLSL/GLSL/WGSL; use `timeout`.

Companion page [[wiki/concepts/slang-backends-wgsl-matrix-and-validation.md]] covers WGSL matrix-operator validity (negation, int64 matrices), the §3.9 template-list ambiguity in argument lists, and GPU-free naga-wasm validation. WGSL uniformity analysis (spec rules, which context shapes pass Tint, the `__builtinWaveLaneCount` shadow store; #8774) is on [[wiki/concepts/slang-backends-wgsl-uniformity-and-shadow-globals.md]].

## Static-Const Arrays Must Be var<private> for Runtime Indexing

A WGSL `const` is a compile-time value (≈C++ constexpr), and the spec lets a *value* of array type be indexed only by a const-expression. So a `static const` array indexed at runtime (`positions[SV_VertexID]`) and emitted as `const` is rejected by naga/tint; `emitVarKeywordImpl` emits module-scope array constants as `var<private>` with a const-expression initializer ([WGSL emit: static-const arrays must be var<private> (not const) for runtime indexing](../learnings/1781624737396-wgsl-emit-static-const-arrays-must-be-var-private-.md)).

Only `kIROp_ArrayType` globals convert (vector/matrix values are runtime-indexable), and no use analysis is needed: `replaceGlobalConstants` inlines GlobalConstant values and removes the `IRGlobalConstant` before `simplifyIR`, and peephole folds constant-index reads. So the recurring review claim "the `var<private>` is initialized from another `var<private>`" is a false positive in post-link IR. Known limitation: a CSE-shared inner array that is both nested and independently runtime-indexed ([WGSL static-const-array review: replaceGlobalConstants false-positive + value-indexability rule](../learnings/1781639050403-wgsl-static-const-array-review-replaceglobalconsta.md)).

## WGSL @location Return-0 Fallback Branch

Covering a `resolveWGSLLocation`-style `return 0` fallback with `: SV_TARGET` beside `: SV_TARGET2` is impossible in one struct: bare `SV_TARGET` and `SV_TARGET0` both resolve to `@location(0)`. It needs a separate struct, and declining is reasonable when the fallback is pre-existing ([WGSL @location return-0 fallback branch can't be unit-tested in one struct](../learnings/1781663682498-wgsl-location-return-0-fallback-branch-can-t-be-un.md)).

## Per-Target Buffer Stride and the var<uniform> Array Rule

`StructuredBuffer<float3, ScalarDataLayout>` has a 12-byte stride on D3D/HLSL, Vulkan/SPIR-V (layout arg required), CUDA and Metal, but **WGSL hard-codes 16** in `slang-ir-lower-buffer-element-type.cpp` (an array of scalar/vector becomes a 16-byte-aligned vector). For a tight stride on WGSL use `RWByteAddressBuffer.Load<float3>`/`.Store<float3>` (three `f32` loads); `scalarizeVectorLoadStore` is set for WGSL, Metal and CPU-via-LLVM in `slang-emit.cpp` ([Slang per-target stride for `StructuredBuffer<float3, ScalarDataLayout>` — WGSL is the outlier](../learnings/1780177237717-slang-per-target-stride-for-structuredbuffer-float.md)).

**The `var<uniform>` 16-byte rule is on the array STRIDE; only widening the element fixes it (#13704).** WGSL §14.4.5 requires StrideOf(array<T,N>) = 16·k, and stride = roundUp(AlignOf(E), SizeOf(E)), so `array<i32,N>` has stride 4. `@align(n)` moves only a member's offset and cannot go below AlignOf(T) (naga: "struct member alignment must be at least 16" for `@align(4)` on `array<vec4<i32>,N>`), and WGSL has no stride attribute. So the element must widen: Slang's `_Array_std140` vec4 wrapper or the spec's `@size(16)` wrapper struct. The `uniform_buffer_standard_layout` extension relaxes the rule, but only Dawn has it (Chrome 144; naga/wgpu 0.32 rejects it, Safari lacks it), and Slang never emits `requires uniform_buffer_standard_layout;`. To check, pip-install wgpu and call `create_shader_module` + `create_compute_pipeline` (`scratch-13704/align-probe/val2.py`) [WGSL uniform 16-byte rule is on array stride](../learnings/1792627107595-wgsl-uniform-16-byte-rule-is-on-array-stride-align.md).

## Uniform-Struct Member Access Copies the Whole Struct Unless deferBufferLoad Sinks It (#13732)

For `uniform S s; s.member.method()`, `collectGlobalUniformParameters` (`slang-ir-collect-global-uniforms.cpp:364-366`) emits `load(fieldAddr(globalParams, s))`, loading all of `S`. Only `deferBufferLoad` (`slang-ir-defer-buffer-load.cpp:240-245`) sinks it to `load(fieldAddr(.., member))`, and only when `isTypePreferrableToDeferLoad` (`:59-92`) holds: natural size above 16 bytes, and above 128 bytes or containing an array. Otherwise `deferStorageToLogicalCasts`'s load case (`slang-ir-lower-buffer-element-type.cpp:1351-1479`) builds a whole `S_std140` temp on WGSL (a `copyLogical` on SPIR-V) and passes `&tmp.member` to a callee specialized to `BorrowInParam(Member_std140)` (`:1570-1578`). The boundary is exact: 128 bytes with no array keeps the copy, 132 bytes does not. The same heuristic gates `specializeFuncsForBufferLoadArgs` ([[wiki/concepts/slang-b-bindings-and-backends.md]]). To find which pass splits two variants, `-dump-ir` both, split with `extras/split-ir-dump.py`, and diff `main`; the first differing section names the pass ([WGSL whole-uniform-struct copy is gated by deferBufferLoad's size heuristic](../learnings/1792249776321-wgsl-whole-uniform-struct-copy-is-gated-by-deferbu.md)).

## Wave Aggregate Intrinsics (CUDA/Metal FileCheck Trap)

`//CHECK-DAG: WaveActiveCountBits` on CUDA/Metal output is false confidence: only `case hlsl:` emits it. CUDA lowers to `__popc(__ballot_sync(...))` and Metal to `_WaveCountBits(WaveActiveBallot(value))`; the token appears there only as the name of the force-kept `[KnownBuiltin]` definition. Check CUDA for `__ballot_sync`/`__popc` and Metal for `simd_ballot`/`popcount` (`simd_is_first` for `WaveIsFirstLane`) ([CUDA/Metal FileCheck on the `WaveActiveCountBits` literal passes for the wrong reason](../learnings/1780935575501-coverage-wave-aggregate-tests-cuda-metal-filecheck.md)).

## Textual-Emitter Parity: Constructor Syntax, FP Literal Suffixes, f16

WGSL, like GLSL, is a constructor-syntax, no-brace-init target, so a `-target glsl` text bug (e.g. array brace init) often has an override in `slang-emit-wgsl.cpp` to port ([Slang per-target stride for `StructuredBuffer<float3, ScalarDataLayout>` — WGSL is the outlier](../learnings/1780177237717-slang-per-target-stride-for-structuredbuffer-float.md)).

Metal is the **lone** C-like backend that prints FP literals with no type suffix: `MetalSourceEmitter::emitSimpleValueImpl` (`slang-emit-metal.cpp:1128-1164`) omits the MSL `h`/`f` suffix, so `61440.hf` becomes a bare double, which breaks a size-sensitive `as_type<ushort>(...)`. The fix mirrors the WGSL/HLSL path (#11837) ([Slang Metal backend emits FP literals with NO type suffix (issue #11837)](../learnings/1782814984950-slang-metal-backend-emits-fp-literals-with-no-type.md), [Metal emitter is the lone backend that omits FP literal type suffixes](../learnings/1782832643994-metal-emitter-is-the-lone-backend-that-omits-fp-li.md)).

WGSL is not missing 16-bit floats: a "WGSL missing f16" report is almost always the 16-bit **integer** (`bit_cast<uint16_t>`) path surfacing E56103 (#11835; see [[wiki/concepts/slang-backends-wgsl-f16-and-const-expressions.md]]) ([WGSL f16 floats already work; E56103 is the 16-bit-INTEGER path (slang #11835)](../learnings/1782813507927-wgsl-f16-floats-already-work-e56103-is-the-16-bit-.md)). The exception is f16-returning subgroup builtins: Dawn/Tint removed `subgroups_f16` in April 2025, but the Windows test-only `slang-tint-0` pin (shader-slang/dawn 9255f960, Sept 2024) still requires it, so f16 subgroup code through `-target wgsl-spirv*` cannot satisfy both ([Tint pin still requires subgroups_f16](../learnings/1792074066723-codex-critique-cwd-workspace-agent-can-make-codex-.md)).

## WGSL Control-Flow Emission: Trailing Switch-Case Break, Native `loop`, Tint's Loop Counter

Slang's WGSL emitter ends every switch `case`/`default` with `break;`. A first read called it redundant and downgraded #11946 to cosmetic ([WGSL trailing break in switch cases is VALID (redundant) — verify validator claims via DeepWiki](../learnings/1783296818057-wgsl-trailing-break-in-switch-cases-is-valid-redun.md)), but it **is** a real bug because **older naga rejects** it; verify validator claims across toolchain VERSIONS, not just current source ([CORRECTION: WGSL redundant switch-case break IS a real bug (older naga rejects)](../learnings/1783300097186-correction-wgsl-redundant-switch-case-break-is-a-r.md)). `!supportsSwitchFallThrough()` is the **wrong** gate: HLSL/FXC also returns false yet requires the break ([supportsSwitchFallThrough is not a proxy](../learnings/1783300771712-slang-supportsswitchfallthrough-is-not-a-proxy-for.md)).

Until PR #13071 (merged 2026-09-28, for #13066), `CLikeSourceEmitter::emitRegion` hard-coded `for(;;)` for every `LoopRegion` (slang-emit-c-like.cpp:3794 at a90dfa31) and WGSL inherited it. The PR added a `getUnconditionalLoopHeader()` hook that `WGSLSourceEmitter` overrides to print `loop`; no `continuing {}` block is needed because the restructurer folds the condition into the body. Test: tests/wgsl/loop.slang ([WGSL loop emission: for(;;) changed to native loop by PR #13071](../learnings/1792156297428-wgsl-loop-emission-for-changed-to-native-loop-by-p.md)).

That shape costs a Tint counter that blocks unrolling (#13733): the restructurer copies the IR continue block to every `continue` and the body end (`slang-ir-restructure.cpp:424-451`) instead of emitting a region. PreventInfiniteLoops adds a `4294967295` counter to every loop Dawn's `loop_analysis.cc` cannot prove finite, which needs an i32/u32 `var` index in the `ir::Loop` Initializer (only a `for` init fills it), whose only store is `v = v ± 1` in Continuing, tested by the first body `if` (only loads/binaries before it) against a constant with `< > <= >=` and a `break` in one arm. So `for (var p = 0; ; p = p + 1) { if (p <= 3) {} else { break; } … }` passes, with or without `continue`. A `var` before `loop { … continuing { p = p + 1; } }`, `break if`, `while`, a body-computed store or a runtime bound keep the counter. Confirmed by 14 probes (node `webgpu` 0.6.2, `create(['backend=vulkan','enable-dawn-features=dump_shaders'])`, grep the dump for `4294967295`) ([Tint PreventInfiniteLoops: only a `for` with var-in-init and a ±1 update is provably finite](../learnings/1792251784378-tint-preventinfiniteloops-only-a-wgsl-for-with-var.md)). Running WGSL through Dawn on the GPU is on [[wiki/concepts/slang-backends-wgsl-on-gpu-execution.md]].

Counted-`for` emission (PR #13740) cut the reporter's counters from 5 to 1; core-module loops remain (#13765). Vector overloads with no `case wgsl:` fall through to `VECTOR_MAP_*` (hlsl.meta.slang:7957), a plain `for` lacking the `[ForceUnroll]` of its `glsl.meta.slang` copy. The last survivor is the one-trip `loop { ...; break; }` that `inlineMultipleBlockFuncBody` (slang-ir-inline.cpp:821) wraps around a `[ForceInline]` callee whose body contains a `for` (an `if`-only body loses it). For no loop at all use per-target `case wgsl:` arms or `[ForceUnroll]`; a vector bit test like `(asuint(x) & 0x7fffffffu) > 0x7f800000u` compiles to a loop-free `bitcast<vec3<u32>>` compare. (A worktree made with `--reference` to a shallow clone failed on submodules; `cp -a` of each `external/<sub>` fixed it.) [VECTOR_MAP loops and the inline one-trip wrapper leave a Tint counter](../learnings/1792502293606-wgsl-vector-map-loops-the-inline-one-trip-wrapper-.md)

## Entry-Point Output-Struct Flatten Desyncs Var-Layout (Metal/WGSL Crash)

slang#8183: a vertex OUTPUT struct with a nested-struct member and a semantic-less field segfaults on Metal/WGSL, the two targets running this legalization. `wrapReturnValueInStruct` captures the layout for the original struct, `maybeFlattenNestedStructs` adds leaf fields **without rebuilding it**, and `ensureStructHasUserSemantic` indexes the stale layout by POSITION, null-dereferencing `findOffsetAttr` past the original field count (fields with a semantic `continue` first, hence the trigger). Fix at the producer (rebuild/remap the flattened layout) and/or look up by KEY with an assert; a null-check masks the desync and risks mis-assigned varyings. Host repro with Debug slangc: EXIT=139, explicit semantic → EXIT=0. Sibling to the #9580 varying-layout crash ([Metal/WGSL entry-point output-struct flatten desyncs var-layout](../learnings/1784382530471-slang-metal-wgsl-entry-point-output-struct-flatten.md)).

## Metal fwidth E36107 and the `[require]` / `__target_switch` Pairing Rule

**`fwidth(float2)` on Metal fails E36107 from a stdlib annotation, not a Metal gap (#12165).** Only the SCALAR overload declares `metal`; the VECTOR (`glsl_hlsl_spirv_wgsl`) and MATRIX (`glsl_hlsl_spirv`) overloads omit it. The vector overload needs BOTH the `[require]` atom AND `case metal: __intrinsic_asm "fwidth($0)";` (its `__target_switch` has no metal case or `default:`); the matrix overload needs only `[require]`, as `default: MATRIX_MAP_UNARY` recurses to the scalar. Do NOT add `metal` to `fwidth_coarse`/`fwidth_fine`: `fragmentprocessing_derivativecontrol` deliberately omits Metal. E36107 triage: read the atom def AND the `[require]` (genuine exclusion vs over-restrictive clause) and cross-check a supporting sibling (`ddx`/`ddy` carry `metal` on all three overloads, `fwidth ≡ abs(ddx) + abs(ddy)`, and `fragmentprocessing` at `slang-capabilities.capdef:2344` lists `fragment + metal`) ([Metal fwidth E36107 — stdlib require-clause AND target-switch body both need the metal atom](../learnings/1784627957519-metal-fwidth-e36107-stdlib-require-clause-and-targ.md)).

The transferable rule: **the `[require]` edit and the body `case`/`default` are one atomic change.** Adding an atom to `[require]` when the `__target_switch` has neither `case <target>:` nor `default:` turns a clear E36107 into an obscure emit failure or empty body. It is the inverse of the case-less-switch mechanic (#12274): a method-level `[require]` with no arm for the target is inert as a gate on REMOVE and an unhandled emit on ADD, so read the body, not just the clause ([widening a [require] set needs the paired __target_switch case](../learnings/1785840965047-widening-a-require-target-set-is-only-half-the-fix.md)).

## WGSL inout/out Arg from a Global static: Address-Space Mismatch (#12173)

`legalizeCall` (`slang-ir-wgsl-legalize.cpp:14-72`) is the copy-in/copy-out bridge for by-ref args, but it skips the temp for `kIROp_Var/Param/GlobalParam/GlobalVar`. A global `static` is `kIROp_GlobalVar` (`private`), so it is passed as `ptr<private,…>` into a `ptr<function,…>` param, which naga/wgpu rejects (emit-only; `slangc -target wgsl` reproduces). Skipping block-local `kIROp_Var` is correct; the global-scope entries are the bug. `legalizeCall` runs BEFORE `specializeAddressSpaceForWGSL`, so the fix keys on IR op/scope, not address space: narrow the skip-list so global-scope pointer args take the temp path ([WGSL inout/out arg from global static → ptr address-space mismatch (legalizeCall skip-list gap)](../learnings/1784636859545-wgsl-inout-out-arg-from-global-static-ptr-address-.md)).

## Metal Entry-Point Wrapping and Decoration Repointing

**Uniform wrapping (#10675).** Metal wraps entry-point `uniform` params (including `uniform T*`) in a synthesized `EntryPointParams` cbuffer (one `constant*` `[[buffer(0)]]`), costing a pointer param an extra hop; SPIR-V uses a push constant. The split is `slang-parameter-binding.cpp:3420` (only `isKhronosTarget(...)` swaps to push-constant rules), so `needConstantBuffer` is true on Metal (`slang-ir-entry-point-uniforms.cpp:264`). Both fixes, (A) a dedicated Metal buffer index for `uniform T*` or (B) no wrapping, shift the host binding layout and are breaking; parked as a future-year-release decision, pinned by `tests/metal/entry-point-uniform-vertex-struct-output.slang` ([Metal wraps entry-point uniform params (incl pointers) in cbuffer; SPIR-V routes them to push constants](../learnings/1784653655393-metal-wraps-entry-point-uniform-params-incl-pointe.md)).

**The wrapper-swap family.** #7669 (a Metal `StructuredBuffer` param loses `[[buffer(0)]]`, folded into an uninitialized `KernelContext`) does not reproduce at HEAD: PR #11607 fixed it for duplicate #11606. `lowerOutParameters` creates a new wrapper while the hoisted uniform's `IREntryPointParamDecoration` still names the old function, so `introduceExplicitGlobalContext` drops the buffer; `retargetEntryPointParamDecorations()` fixes it. For any pre-2026.06 open issue, reproduce at a fresh HEAD first ([slang #7669 Metal StructuredBuffer binding loss already fixed by #11607 — verify-at-HEAD caught it](../learnings/1784753556178-slang-7669-metal-structuredbuffer-binding-loss-alr.md)).

**`[[stage_in]]` on a non-entry helper (#13271).** `lowerOutParameters` (via `legalizeShaderOutputParamsForMetal`) inlines the original only if `useCount == 1` (slang-ir-lower-out-parameters.cpp:401), but the uniform's `IREntryPointParamDecoration` is a second use, retargeted only afterwards (legalize-varying-params.cpp:5450). The original survives as a helper whose params keep their VaryingInput `IRLayoutDecoration` (demotion strips only EntryPoint/KeepAlive), and `emitFuncParamLayoutImpl` (slang-emit-metal.cpp:185) prints invalid `[[stage_in]]`. `fixEntryPointCallsites` leaks the same way: its clone strips the function-level layout but `cloneInst` keeps each param's. SV_*-only tests (like #11607's) cannot see it; use a user-semantic input (`float3 p : POSITION`). Three demotion lists (fix-entrypoint-callsite.cpp, autodiff-fwd.cpp, lower-out-parameters.cpp) argue for one producer-side "demote former entry point" helper, not an emitter gate ([Metal [[stage_in]] on a non-entry helper = former entry point not demoted (lowerOutParameters useCount gate)](../learnings/1790389765020-metal-stage-in-on-a-non-entry-helper-former-entry-.md)).

The fix retargets inside `lowerOutParameters` before the decision, so the original is inlined and deleted. Cascade: `EntryPointInfo::entryPointDecor` still named the old `IREntryPointDecoration` (the old path survived only by detaching it with `removeFromParent()` first), so `packStageInParameters` → `getProfile()` crashed on a null operand. Re-read the decoration from the returned wrapper (`transferFunctionDecorations` clones it). FileCheck for an attribute-free helper signature: `{{^[^[]*}} vsB_0({{[^[]*}}){{$}}` ([lowerOutParameters: EntryPointInfo.entryPointDecor goes stale after the wrapper swap; retarget uniform decor before the inline decision](../learnings/1790394201978-metal-loweroutparameters-entrypointinfo-entrypoint.md)).

The `fixEntryPointCallsites` leak is not Metal-only: the pass (`slang-emit.cpp:2364`) runs for every target, and CUDA's `emitSimpleFuncParamsImpl` (`slang-emit-cuda.cpp:1597`) drops system-value params from the declaration while the call site passes them (`tests/spirv/nested-entrypoint.slang -target cuda -entry outerMain -entry innerMain` declares `innerMain_0()` but calls `innerMain_0(&_S2)`). Stripping the clone's param layouts at the producer (`removeParamLayoutDecorations`, #13284) fixes both. When fixing an IR shape for one emitter, grep every reader (`getVarLayout(param)`) and test each target [stale param layouts break CUDA too](../learnings/1790761751687-stale-entry-point-param-layouts-on-a-cloned-ordina.md), [CUDA signature mismatch fixed as a side effect of #13284](../learnings/1790758864251-slang-listing-the-callee-entry-point-first-hangs-h.md).

Same shape, separate master hang (unfiled): with `vsA` calling `vsB` (both returning an `SV_Position`/`TEXCOORD` struct), callee-first `-entry vsB -entry vsA` spins 6+ minutes on HLSL/GLSL/WGSL; Metal, SPIR-V and `-entry vsA` alone (0.3 s) are fine. Wrap slangc in `timeout 60` when cross-target diffing [callee-first entry-point order hangs HLSL/GLSL/WGSL](../learnings/1790758864251-slang-listing-the-callee-entry-point-first-hangs-h.md). Process: sibling worktree fetches move the shared clone's `origin/master`, so restore files from the pinned base SHA; each codex PLAN/CODE/OUTPUT critique round needs a `REQUIREMENTS:` line [stale param layouts](../learnings/1790761751687-stale-entry-point-param-layouts-on-a-cloned-ordina.md).

## groupshared-by-ref Multi-Backend Breakage (#10641)

A bare `groupshared` array param **by reference** (#10641 / PR #11709) breaks three backends differently; a green vk/HLSL/SPIR-V run clears NONE. Metal: a silent abort in the address-space pass, because the param type is `RateQualified(GroupShared, BorrowInOutParam(Array))`, so `as<IRPtrTypeBase>(param->getFullType())` is null; unwrap the rate with `getDataType()`/`setDataType()`. WGSL: the callee MUST be inlined BEFORE `legalizeIRForWGSL`, or `legalizeCall` bridges a whole-array `var<workgroup>` copy, silently reintroducing the per-invocation copy #10641 removes; `WGSL-NOT: ptr<workgroup` misses it, so assert no whole-array copy and add a behavioral compute lane. Test the real downstream compiler via a `-target ptx`/NVRTC lane, not only emitted source ([groupshared by-ref param: Metal addr-space + WGSL inline-ordering gotchas (#10641)](../learnings/1784756124264-groupshared-by-ref-param-metal-addr-space-wgsl-inl.md)).

## Pointer Address Space Is Type-Level on Metal/WGSL, Pass-Inferred on SPIR-V

On **SPIR-V** a source `int*` has no address space until `specializeAddressSpace` assigns a storage class, so returning pointers from two address spaces fails in or after that pass (E58005 `conflicting-return-pointer-storage-classes`; E58004 for non-returnable classes). On **Metal/WGSL** the address space is in the type (`Ptr<T, Access, AddressSpace.Device|GroupShared|…, Layout>`), so the same conflict (`uniform int*` vs `__getAddress(groupshared)`) is a type mismatch, **E30019**, in semantic checking. Metal does allow returning pointers and `__getAddress` (`tests/metal/metal-pointer-params.slang`, `pointer-in-buffer-getaddress.slang`); E31160 on a function-local, failure on structured-buffer `buf[i]` on all targets (#10841), and a context-specific E36107 for `&gShared` in a Metal/WGSL/GLSL compute entry point do not mean "no pointers". Maintainer rule: an "X cannot reach Y" claim names the enforcing diagnostic with a test or a failing repro, or weakens to "not attempted; covered by construction" ([Pointer address space is type-level on Metal/WGSL but pass-inferred on SPIR-V](../learnings/1789546490977-pointer-address-space-is-type-level-on-metal-wgsl-.md)).

**`&` on Metal is blocked only by its capability gate, and the gate should stay (#14035).** `operator&` (`core.meta.slang:3091`) is `[require(cpp_cuda_spirv_llvm)]`, which has never included Metal since #4710, while `__getAddress` is gated `cpp_cuda_metal_spirv_llvm` (`slang-check-decl.cpp:22442`). So on Metal `&p[i]` gives E36107, but `__getAddress(p[i])` and `__getAddress(p->f)` compile today (they emit `p + i`), and `-ignore-capabilities` shows the Metal IR/emit path already handles `&` for device, threadgroup and thread pointers. Do not just widen the `&` gate: maintainers plan to deprecate `&` (#10280 commit b1505c6e5, jkwak-work on #9148, jhelferty-nv on #10619, draft #10206 `RemovedSince(2026)`, which intentionally leaves `__getAddress` out of its guidance), and under #10206 there is no public spelling for a field address. Route such issues to maintainer direction. `slangc -ignore-capabilities` is a fast probe for "is the `[require]` gate the only blocker". WGSL has no device pointers at all: `uniform int*` silently emits invalid `ptr<, T>` (#13399) [E36107 on `&` (operator&) for Metal: gate-only; `__getAddress` works; maintainers are deprecating `&`](../learnings/1793295608390-e36107-on-operator-for-metal-gate-only-getaddress-.md).
