# Slang unsupported-shape diagnostics and emitter result-unused checks: where they run, what they must look through, and debug-info users

Two kinds of late decision in the Slang pipeline keep producing the same review findings. The first is an IR check that rejects a value or type the target cannot represent, such as the spec-constant-sized array diagnostics (E55222, E55223) added for HLSL, CUDA, Metal and WGSL in shader-slang/slang#14049 (#14030). The second is an emitter decision that depends on whether an instruction's result is used, such as Metal emitting the void form of a 64-bit atomic min/max (PR #14044, #14031) or skipping the temporary for an unused atomic result (#14058). Both decide on the IR as it exists at one point in the pipeline, so both depend on which optimizations ran before them and on what debug info added. Source-location loss in IR-pass diagnostics in general is on [[wiki/concepts/slang-autodiff-ir-passes-diagnostics.md]]; the MSL atomic rules themselves are on [[wiki/concepts/slang-backends-metal-atomics-fences-and-coherence.md]].

## TL;DR

- **Run a "this value cannot be emitted" check at the end of `linkAndOptimizeIR`, next to `checkUnsupportedResourceLocals`.** Run right after specialization and DCE, it rejects code that master compiles: in `float a[kTile] = {}; a[0] = 1; o[0] = a[0];` later passes forward the store and delete the array.
- **Late placement has two caveats.** Identical `makeArrayFromElement(0.0)` instances are CSE'd, so two zero-initialized arrays of the same type give one diagnostic (a test expecting two needs distinct element types). Under `-minimum-slang-optimization` the inst survives `linkAndOptimizeIR` while the SPIR-V emitter still drops the write-only local, so only an emit-time check matches master exactly in that mode.
- **A type-based check must look through every wrapper that can hold the type:** `IRPtrTypeBase` value types, array layers, `IRBuiltinGenericType` element types (operand 0, as in `RWStructuredBuffer<float[kN]>`), and `IRTupleType` elements (`lowerTuples` runs late). Record every looked-through layer of a reported type, or each element access is reported again.
- **It must also walk values that no declaration holds**, such as the result of `ByteAddressBuffer.Load<float[kN]>(0)` or a call returning an array, because the emitter declares a temporary of that type. Deduplicate per type and visit `IRCall` results first, so the location is the user's call and not the body of `Load` in core.meta.slang.
- **Fixing an emit ICE can turn the shapes the new check misses from an ICE into silently invalid output.** Widen the check in the same PR that removes the ICE.
- **`collectGlobalUniformParameters` creates the `globalParams` field key with `createStructKey()` and no `sourceLoc`.** A field-level diagnostic for a `uniform` global (and, on CUDA, for every resource-typed global) then reports line 0. Copy `globalParam->sourceLoc` onto the key after the existing `SLANG_ASSERT(globalParam)`; placed before it, the copy segfaults on non-uniform entries.
- **An emitter "result unused" check must ignore debug-info users.** With `-g`, an otherwise unused result keeps one user, `DebugValue(%var, %result)`, which the C-like emitters skip. Use `hasNonDebugUse` (`slang-ir-util`), or loop over uses and skip `isDebugInfoInst(use->getUser())`; never `hasUses()`. Pin it with a `-g` run line; a revert drill that swaps in `hasUses()` fails exactly the `-g` runs.
- **The same check depends on optimization level.** Under `-g -minimum-slang-optimization`, a never-read local survives as `store(%o, %atomicMin)`, which is a real use, so the check fires (E55204) where every other flag combination accepts the code. Probe that combination, pin the behavior with a DIAGNOSTIC_TEST, and document it; the fix is not in the emitter.
- **DIAGNOSTIC_TEST with a structured diagnostic:** each diagnostic gives two matchable entries at one position (the header and the span label), so exhaustive mode needs both caret lines for every site.
- **Run a reviewer's code-reading claim before acting on it.** A claimed silent drop of `{1,2,3,4}` on a spec-constant-sized array was false: every build reports E30523 "too many initializers".

## Where an unsupported-value check runs (#14049)

A new check for `makeArrayFromElement` with a spec-constant count (E55223) first ran right after specialization and DCE in `linkAndOptimizeIR`. That rejected a program master compiles to valid SPIR-V:

```hlsl
float a[kTile] = {};
a[0] = 1;
o[0] = a[0];
```

Later passes forward the store to the load and delete the array entirely, so the value the check objects to never reaches emission. A check of the form "this value cannot be emitted" belongs at the end of `linkAndOptimizeIR`, next to `checkUnsupportedResourceLocals`, which sits there for the same reason ([pre-optimization unsupported-value checks reject code master compiles](../learnings/1793318861659-pre-optimization-unsupported-value-checks-reject-c.md)) ([Slang IR diagnostics: run a check for an optimizable shape late](../learnings/1793321156877-slang-ir-diagnostics-run-a-check-for-an-optimizabl.md)). The `checkUnsupportedResourceLocals` check itself, and the E56019 regression it caused, are on [[wiki/concepts/slang-compiler-ir-phis-and-global-value-placement.md]].

The late position has two consequences that tests must account for. Late in the pipeline, identical `makeArrayFromElement(0.0)` instances have been CSE'd into one, so two zero-initialized declarations of the same type produce one diagnostic; a test that expects two needs distinct element types. And under `-minimum-slang-optimization` the instruction survives `linkAndOptimizeIR`, yet master still compiles, because the SPIR-V emitter drops a write-only local on its own. So even the late IR check differs from master in that mode; only an emit-time check would match it exactly ([same](../learnings/1793318861659-pre-optimization-unsupported-value-checks-reject-c.md)).

## What a type-based check must look through

The first version of the E55222 check (spec-constant-sized arrays on HLSL, CUDA, Metal and WGSL) walked declarations (`GlobalVar`, `GlobalParam`, `Var`, `StructField`, function params) and unwrapped only `IRPtrTypeBase` and array layers. It missed two families ([late IR unsupported-shape checks must look through wrappers](../learnings/1793309934870-late-ir-unsupported-shape-checks-must-look-through.md)):

- **Types held inside another type.** `RWStructuredBuffer<float[kN]>` is an `IRBuiltinGenericType` whose element type is operand 0, so the check must also look through `IRBuiltinGenericType::getElementType()`. `IRTupleType` elements need the same treatment, because `lowerTuples` runs late ([same](../learnings/1793321156877-slang-ir-diagnostics-run-a-check-for-an-optimizabl.md)).
- **Values that no declaration holds.** The result of `ByteAddressBuffer.Load<float[kN]>(0)`, or of a call that returns an array, has no declaration, but the emitter still declares a temporary of that type. The check therefore needs a value walk over block children too. Deduplicate it per type and visit `IRCall` results first; otherwise the first value found sits inside the core-module body of `Load`, and the diagnostic points into core.meta.slang instead of the user's call.

Record every looked-through layer of a reported type, or each element access of the same declaration is reported again ([same](../learnings/1793321156877-slang-ir-diagnostics-run-a-check-for-an-optimizabl.md)). The completeness of the check matters more than usual here, because the same PR fixed the `emitVal` ICE that used to stop these shapes: without the wider walk they went from an ICE to silently invalid Metal and WGSL output ([same](../learnings/1793309934870-late-ir-unsupported-shape-checks-must-look-through.md)).

## Diagnostic location for uniform globals: the `globalParams` key

On HLSL and CUDA, `collectGlobalUniformParameters` moves uniform globals into a `globalParams` struct, using a new field key from `createStructKey()` that has no `sourceLoc`. A struct-field diagnostic keyed on `field->getKey()->sourceLoc` then reports at line 0, and on CUDA this affects every resource-typed global as well. The producer-side fix is one line, `fieldKey->sourceLoc = globalParam->sourceLoc`, but its position matters: it must come after the existing `SLANG_ASSERT(globalParam)`, because `_getGlobalParamFromLayoutFieldKey` returns null for non-uniform entries that take the `continue` above it. Placed before the guard, the copy segfaulted `tests/glsl/global-uniform-with-varyings.slang` and `tests/diagnostics/glsl-global-const-with-init.slang` ([same](../learnings/1793309934870-late-ir-unsupported-shape-checks-must-look-through.md)) ([same](../learnings/1793321156877-slang-ir-diagnostics-run-a-check-for-an-optimizabl.md)).

## Emitter result-unused checks: debug users and optimization level (#14044, #14058)

An emitter that chooses a form by whether a result is used must not ask `inst->hasUses()`. With debug info, an otherwise unused result, such as the `original_value` out-param of `InterlockedMin`, keeps exactly one user: `DebugValue(%var, %result)`. The C-like emitters skip debug insts entirely (`slang-emit-c-like.cpp` returns early for `kIROp_DebugValue` and its kin), so the decision has to ignore uses whose user satisfies `isDebugInfoInst` (`slang-ir-util.h`). Otherwise `-g` turns valid code into an error: on PR #14044 (Metal 64-bit atomic min/max), the void-form selection failed only under `-g` ([emitter result-unused checks must ignore DebugValue users](../learnings/1793300205701-emitter-result-unused-checks-must-ignore-debugvalu.md)). The same bug appeared in the other direction on #14058: for `uint o; InterlockedAdd(b[i], 1u, o);` with `o` never read, the Metal emitter's "skip the temporary" check saw the `DebugValue` as a use, so the temporary stayed and `-Wunused-variable` persisted under `-g`. The fix added `hasNonDebugUse` to `slang-ir-util` and pinned it with a `-g` FileCheck run on a never-read out-param; a revert drill that swaps in `hasUses()` fails exactly the `-g` runs ([emitter result-unused fixes: -g leaves DebugValue as the only user](../learnings/1793316936930-emitter-result-unused-fixes-g-leaves-debugvalue-as.md)).

Ignoring debug users is not the whole story, because the check decides on the IR as it reaches emission. Consider `uint64_t o; InterlockedMin(buf[i], key, o);` with `o` never read. PR #14044 accepted it at default optimization, `-O0`, `-minimum-slang-optimization`, `-g`, `-g -O0`, and `-g3 -O0`. Under `-g -minimum-slang-optimization`, though, the never-read local survives as `store(%o1, %atomicMin)` in the final IR, which is a real use, so the check fires E55204. The 2-argument form and `var r = a.min(k)` are unaffected. When reviewing such a check, probe the `-g -minimum-slang-optimization` combination specifically, pin the behavior with a DIAGNOSTIC_TEST, and document it, since the fix is not in the emitter ([emitter result-unused checks depend on DCE: probe -g -minimum-slang-optimization](../learnings/1793303529967-emitter-result-unused-checks-depend-on-dce-g-minim.md)).

The MSL rules behind these two PRs (only void relaxed `atomic_ulong` min/max on device memory in MSL 4.1 §6.16.4.6, no `atomic_long`, and texture `atomic_min`/`atomic_max` on `ulong4`) are covered on the Metal atomics page linked above. Two points from these atoms matter for testing: for metallib output Slang passes `-std=metal3.1` unless something raises it (`slang-gcc-compiler-util.cpp` ~978, `slang-code-gen.cpp` ~770), so Metal 2.4/3.1-gated MSL features always compile; and the MSL spec PDF (over 10 MB) does not go through WebFetch, so `curl` it and extract text with `pip install --target /tmp/pyp pypdf` ([same](../learnings/1793303529967-emitter-result-unused-checks-depend-on-dce-g-minim.md)) ([same](../learnings/1793300205701-emitter-result-unused-checks-must-ignore-debugvalu.md)).

## Testing and review notes

- **Structured diagnostics give two matchable entries.** A diagnostic such as E55204 `UnsupportedTargetIntrinsic` yields a header ("unsupported intrinsic operation", matched by `^ E55204`) and a span label ("intrinsic operation '...' is not supported...") at the same position. In exhaustive mode a DIAGNOSTIC_TEST needs both caret lines per site; one alone fails with "N diagnostics without annotations". See `tests/diagnostics/unsupported-target-intrinsic.slang` ([same](../learnings/1793300205701-emitter-result-unused-checks-must-ignore-debugvalu.md)).
- **Downstream warnings can be pinned.** `-target metallib ... -Xmetal -Werror=unused-variable -Xmetal -Werror=unused-value` turns Metal compiler warnings into test failures (`slang-code-gen.cpp` forwards `-X<passthrough>` args); such runs execute on macOS CI only and are ignored on Linux ([same](../learnings/1793316936930-emitter-result-unused-fixes-g-leaves-debugvalue-as.md)).
- **Normalize `_S<n>` names in a master-vs-fix output diff.** A skipped temporary renumbers every later temporary, so a raw diff looks much larger than the change ([same](../learnings/1793316936930-emitter-result-unused-fixes-g-leaves-debugvalue-as.md)).
- **A corpus diff run while the full suite runs in the same worktree is noisy.** The suite writes `.slang-module` files into `tests/`, and slangc then loads them, so cross-module tests differ; rerun those files sequentially before calling a diff real ([same](../learnings/1793309934870-late-ir-unsupported-shape-checks-must-look-through.md)).
- **Run a reviewer's front-end claim before acting on it.** A reviewer claimed that `{1,2,3,4}` on a spec-constant-sized array "silently dropped to MakeArrayFromElement"; every build actually reports E30523 "too many initializers" ([same](../learnings/1793318861659-pre-optimization-unsupported-value-checks-reject-c.md)).
- **Do not re-split commits with `git reset --soft origin/master` in a worktree.** `origin/master` is shared with the base clone, and another session's `git fetch` moves it, so the reset silently "reverts" every new master commit in your index; reset to the recorded base SHA instead ([same](../learnings/1793300205701-emitter-result-unused-checks-must-ignore-debugvalu.md)). Worktree hygiene in general is on [[wiki/concepts/agent-infra-f0909b0-git-worktree-hygiene.md]].
