# Reasoning Traps and Evidence Fidelity

## TL;DR
- A wrong mechanism riding a right conclusion draws no pushback — no outcome, test, review, or CI can audit reasoning, so it propagates by relay, each hop adding authority without verification. A correct conclusion is not evidence of correct reasoning.
- A consequence of a claim cannot corroborate the claim — a real challenge owes a *different instrument*. "Impossible" must be a search's conclusion, never its premise.
- Order the questions: "is the implier ALWAYS PRODUCED?" (enumerate all producer paths) before "can it be ELIMINATED?" Skipping to elimination is the trap.
- A wrong-INSTANT measurement launders a reasoning error as data — a dump reads as data and data ends debate. Measure a claim about state at instant T *at* instant T; ask "could this probe have returned a different answer?" — if no, it carries no information.
- A plausible mechanism substituting for an observed fact is the tell you can state the mechanism but not the observation that distinguishes it from alternatives. Fix: state the observable and stop.
- A misreading that agrees with your hypothesis gets the least scrutiny. Before publishing a confirming finding, ask: *if this were false, would my instrument look any different?* — then re-derive from a second field.
- Quote a mechanism's source; don't paraphrase it. Paste instrument output; don't retype it. A paragraph wrong twice will be wrong a third time in a new way; count the rewrites — at three, stop rewriting and start quoting. State the invariant, not the reading.
- Two counts agreeing on a number is evidence about their TOOLS, not the figure (`wc -m` returns bytes with no locale set). A capability claim can rest on the NOUN you happened to grep. Grep the enforcement path, not the message table.
- An append-only correction is only as good as the row that points at it — the index row is a second, mandatory write. A subagent's supporting fact needs verifying even when its verdict is right.
- A rule published without its domain is a defect one level up; the domain is usually invisible in the measurement that produced the rule. Three memory-store shapes give an identical drift signal with opposite remedies — establish the store's shape before writing.

## A wrong mechanism riding a right conclusion draws no pushback from outcomes

This is the most durable error class, because following the note yields correct code and no outcome, test, review, or CI signal can ever push back — so it propagates by relay, each hop adding apparent authority without adding verification. On shader-slang/slang#11917 batch-2 a "safety-critical" note (enumerate all four tag insts *because* three are not covered by the tagged-union implication) had a TRUE premise, an INVALID inference, and a still-correct conclusion (a defense-in-depth superset, not load-bearing). Hence: **a correct conclusion is not evidence of correct reasoning** — when a claim's mechanism is load-bearing for *someone else's* decision, verify the mechanism directly; **an unsatisfiable test demand is evidence about the claim, not about the test** (the implementer stalling on "can't prove the safety-critical part" was the signal the premise was false). Two asymmetries govern the repair: **correcting toward *less* safety needs more evidence than correcting toward more** — keep the conservative behaviour while the mechanism is unsettled, retract the *reasoning* immediately, relax the *behaviour* only once the replacement proof is complete; and correct in public **once**, but fix every private restatement now, sweeping for the **superseded wording** ([a wrong mechanism riding a right conclusion draws no pushback from outcomes](../learnings/1785826139100-a-wrong-mechanism-riding-a-right-conclusion-draws-.md)).

## A consequence cannot corroborate its premise; order the questions

A consequence of a claim is not evidence for it, "impossible" must be a search's conclusion rather than its premise — and order the questions "is the implier always PRODUCED?" before "can it be ELIMINATED?" When a fixer reported a blocked must-fix ("can't isolate the direct scan arm"), the reply that co-emission "also explains the blocked test: no isolating test can exist" was **the same claim wearing a different hat**, inheriting the same open dependency; both flip together on one fact, so neither can audit the other. **Rule 1: a consequence of X cannot corroborate X** — a real challenge owes a *different instrument*. **Rule 2: "impossible" must be the conclusion of an exhausted search, never its premise** — telling an implementer "document the impossibility" makes them skip the exact construction that answers the open question. The reframe: **the search for the test and the answer to the open question were the SAME TASK** — a module reaching the governing scan with the consumer present and the implier eliminated simultaneously proves the guard load-bearing **and is** the regression test. Verified in source at HEAD `0864e60e6`: co-emission is **not universal** (`ElementOfSetType` is an independent producer via `specializeLookupWitnessMethod`), so the original strong claim was RIGHT. The transferable ordering: (1) **is the implier ALWAYS PRODUCED?** — enumerate *all* producer paths, because a sibling branch producing your trigger without your proxy defeats the gate at production; (2) only then, can it be **ELIMINATED** before the governing scan? Skipping to (2) is the trap. And **structural beats contingent evidence** — an argument requiring a contingent fact rots when an optimizer changes ([a consequence of a claim is not evidence for it](../learnings/1785826510128-a-consequence-of-a-claim-is-not-evidence-for-it-re.md), [CORRECTION: the co-emission example was FALSE — ask "is the implier always PRODUCED?" first](../learnings/1785826705506-correction-to-a-consequence-of-a-claim-is-not-evid.md)).

## A wrong-instant measurement launders a reasoning error as data

A wrong-INSTANT measurement is more dangerous than a wrong argument, because a dump reads as data and data ends debate. The implementer probed `-dump-ir-before lowerTagInsts` and got the hoped-for isolating shape (tag ops present, tagged-union opcodes **zero**, across three files) — but the pipeline order is governing scan **:1519** → `lowerTaggedUnionTypes` **:1607** (the *consumer* that removes the implier) → `lowerTagInsts` **:1617**, where the probe was taken. A probe after the consumer is **structurally incapable** of returning any other answer; re-probed in-window at `:1576`, tagged unions were present in every shape across ~80 files. Rules: **a claim about state at instant T must be measured AT instant T** — locate the probe point relative to every pass that produces or consumes what you count, choose it by pipeline position, then ask **"could this probe have returned a different answer?"** — if no, it carries no information. **Primed instruments fail in both directions with the same error** (a refute-framed agent "proved" all paths from 1 of 40+ sites; a confirm-framed agent authenticated a **location** and reported it as **scope**); a totality question needs an **enumeration**, not a sample, and **a citation authenticates the location, never the scope.** The alarm pattern: **when a conclusion survives the death of its own justification, repeatedly, that is evidence it is being reverse-justified** — hold it **UNSUPPORTED** while keeping the safe code. Two measurement traps: **`grep -c` counts MATCHING LINES, not occurrences** ("16 sites" was really 42 lines / 43 occurrences; use `grep -o PATTERN file | wc -l`), and **a bare 12-hex hash may be a BLOB** — `git cat-file -t <hash>` before treating a hash mismatch as a revision mismatch. And **a byte-identical revert-drill proves a gate does not BREAK things; it can never prove the gate WORKS** — gate tests need a control proving the gate FIRED ([a wrong-INSTANT measurement launders a reasoning error as data](../learnings/1785827639255-a-wrong-instant-measurement-is-more-dangerous-than.md), [the probe that cannot fail is the one that looks most convincing](../learnings/1785827665319-a-wrong-instant-measurement-is-more-dangerous-than.md)).

## A plausible mechanism substituting for an observed fact; state the observable and stop

The tell is that you can state the mechanism but not the observation that distinguishes it from its alternatives. Across #11917 batch-2, four wrong claims from three tiers shared that shape, none caught by tests: (1) "co-emission covers it" (checked at emission, gate reads at scan); (2) "`ElementOfSetType` is an independent producer" (contradicted by the dump at the governing scan); (3) "added by CODEOWNERS auto-assignment"; (4) "a human added them" — the corrected version of (3), still wrong, because an account name establishes the **actor**, not whether the action was manual or automated. The 3→4 progression shows **an unfounded mechanism was corrected with another unfounded mechanism.** **Fix: state the observable and stop** — "the timeline attributes the action to account X" is complete and cheap. Related: verify the *binary* before trusting any probe (a stale `.o`; or a mid-struct member insertion during an incremental build yielding a layout-split binary that links, runs, and produces garbage). Two asymmetries: **an instruction's confidence is not evidence** (a two-tiers-up "must-fix" had no evidence either time), and **report searches as searches** ("swept 60 modules, found none" ≠ "no such module exists"). Meta: **writing a section about honesty does not make its claims calibrated** — run the adversarial pass over careful prose too ([a plausible mechanism substituting for an observed fact — four wrong claims, one shape; state the observable and stop](../learnings/1785830249844-a-plausible-mechanism-substituting-for-an-observed.md)).

## A misreading that agrees with your hypothesis gets the least scrutiny

A bias term generalizes over the whole verification discipline: a misreading that **agrees with your current hypothesis** gets far less scrutiny than one that contradicts it, which is how a plausible-but-wrong finding survives into a report. Before publishing a finding that confirms what you set out to test, ask: *if this were false, would my instrument look any different?* — then re-derive from a second field. The corollary for causal stories: **a diagnosis that makes everyone look competent is the least audited artifact in a review** (each losing root-cause was quietly self-serving), and a second party finds what four self-checks miss because **they read your evidence without your hypothesis attached.** So adversarial cross-derivation must extend to **mechanisms**, not just figures — the mechanism drives the fix, so it is the least safe thing to leave unverified.

## Quote a mechanism's source; don't paraphrase it. Paste output; don't retype it.

Prose about someone else's control flow must quote the source, not paraphrase it — and a paragraph wrong twice will be wrong a third time in a NEW way. One PR paragraph explaining why CI showed no test results failed three times running: **stale mutable totals** ("81 check-runs, 74 skipped") read at a head a force-push superseded; a **self-falsified claim** ("no workflow ran") that dispatching CI refuted; a **false universal** ("each `ci.yml` dispatch on a draft yields to the priority gate" — `wait-for-priority.py` yields only if a contender exists, and `--max-yield-hours 12` lets a long-waiting run proceed anyway); then a **dropped disjunct** — "an older bot run is still **queued**" where the source says "queued **or in progress**". Rules: generalising to escape staleness is not free (a universal cannot be confirmed by the single observation that prompted it); **state the invariant, not the reading** ("non-skipped `test-*` check-runs = 0" survived all four rounds); and **count the rewrites — at three, stop rewriting and start quoting.** All four were caught by an adversarial reviewer reading the actual scripts, never by re-reading the prose, because rereading is what produced the text ([Quote a mechanism's source instead of paraphrasing it](../learnings/1786080934191-quote-a-mechanism-s-source-instead-of-paraphrasing.md)). The transcription mirror: **abbreviation destroys falsifiability, because it feels like tidying.** A relayed table showed `control  0  0`; the row looked impossible, and the cause moved twice before settling: the tool printed `quokka-control  index=0  LEAVES=0 (control)` — a fabricated string, correctly labelled — and the **relay** hand-retyped the label down to `control`, deleting the token that made the row checkable. **The loss was invisible from both ends**: the sender knew what they meant, the reader read what arrived. Corollaries: an impossible-looking number in relayed output has three live causes — broken instrument, bad label, lossy relay — and only the third is invisible from both ends; never diagnose a mechanism inside an instrument you cannot read, from a rendering of its output; and **establish which party can see which object before arguing about the object** ([Paste instrument output, don't retype it](../learnings/1786082028729-paste-instrument-output-don-t-retype-it-hand-abbre.md)).

## Verification hygiene across agents

An append-only correction is only as good as the **row that points at it**: publishing a correction succeeds while linking it strands, so the corrected entry's index row is a second, mandatory write ([Rank a flake's LIVE cost from an independent live cross-section, not your own rerun ledger](../learnings/1786162703275-rank-a-flake-s-live-cost-from-an-independent-live-.md), [A cost mechanism proven on one branch is not a theory of a whole flake bucket](../learnings/1786156667938-a-cost-mechanism-proven-on-one-branch-is-not-a-the.md)). A subagent's *supporting* fact needs verifying even when its conclusion is right ([CORRECTION to append-only-correction learning: writability is PER-EDGE, and a piped capability probe reports the pipeline](../learnings/1786155527998-correction-to-append-only-correction-learning-writ.md), [A subagent's supporting fact needs verifying even when its verdict is right](../learnings/1786148700669-a-subagent-s-supporting-fact-needs-verifying-even-.md)). Two agents agreeing on a measured figure is evidence about their **tool choices**, not about the figure — `wc -m` returns bytes with no locale set, so convergence can come from a shared default, and two counts agreeing on a number is not evidence they agree on a mechanism ([An append-only correction is only as good as the reader's tool ordering — measure discovery, not just publication](../learnings/1786154926995-an-append-only-correction-is-only-as-good-as-the-r.md), [wc -m returns BYTES with no locale set — two agents agreeing on a figure is evidence about their tools, not the figure](../learnings/1786143757509-wc-m-returns-bytes-with-no-locale-set-and-two-agen.md), [Two counts agreeing on a number is not evidence they agree on a mechanism](../learnings/1786154277446-two-counts-agreeing-on-a-number-is-not-evidence-th.md)). A capability claim about a backend can rest on the NOUN you happened to grep ("GLSL has no integer dot" was false because the function is named `dotEXT`) ([A capability claim about a backend can rest on the NOUN you happened to grep](../learnings/1786153580027-a-capability-claim-about-a-backend-can-rest-on-the.md)). Never extend a peer latitude derived from an under-powered reading ([Do not direct a coworker to wikilink a rule that lives only in your own store](../learnings/1786153042428-do-not-direct-a-coworker-to-wikilink-a-rule-that-l.md), [Never offer a peer latitude derived from an underpowered rate](../learnings/1786151532435-never-offer-a-peer-latitude-derived-from-an-underp.md)); separate *"this is yours to fix"* from *"here is the mechanism"* so a handoff is not read as blame. When enumerating a field's distinct values, enumerate them *in the window*, not once — a value vocabulary drifts over time ([A field's value vocabulary drifts over time — enumerate distinct values IN the window, not once](../learnings/1786141785236-a-field-s-value-vocabulary-drifts-over-time-enumer.md)). **Rule: grep the enforcement path, not the diagnostic message table (parameterized diagnostics are invisible); and a claim's consequence is never evidence for the claim** ([Grep the enforcement path, not the diagnostic message table](../learnings/1786142356467-grep-the-enforcement-path-not-the-diagnostic-messa.md)).

## A rule published without its domain; three memory-store shapes, one drift signal

A rule published without its domain is the same defect one level up — and the domain is usually invisible in the measurement that produced the rule. "Two memory stores drift ⇒ write both / merge both ways" is **destructive** for a peer's store, because **three store shapes give an identical signal (divergent md5s, disjoint content) with opposite remedies**: a **mirror pair** (same schema/header, no "not live" marker) → write both; a **disjoint namespace** (different schema, an index declaring *"THIS STORE IS NOT THE LIVE ONE"*, shared basenames that are *different documents about the same topic*) → **never `cp`**; a **partial overlap** (same schema, large unique sets on both sides) → **merge per-file, additively.** The near-miss: a merge before establishing the shape, safe only because it happened to be per-file — **the method saved me, not the reasoning.** Underneath: a memory store can be two git repos on different mounts, so a hash resolves in one and is `fatal: Not a valid object name` in the other and two readers *correctly* disagree — discriminate on your own edge (`git -C <p> rev-parse --show-toplevel`, `cat-file -t <hash>`, `findmnt`), **compare mounts, not paths**, never cite a hash without its tree. The real damage of drift is disjoint safety-critical halves (one store held a "nudge already posted — DO NOT POST ANOTHER" guard the other lacked), not divergent hashes ([CORRECTION: "two memory stores ⇒ write both" needs the reachability contract first](../learnings/1786075851829-correction-two-memory-stores-write-both-needs-the-.md)).
