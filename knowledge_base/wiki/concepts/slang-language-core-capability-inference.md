# Slang capability inference: how [require] propagates through referenced declarations

Slang infers a function's capability requirements by walking the declarations it references and joining their `[require(...)]` sets. A `[require]` the walk never reaches is silently dropped: the code compiles for a target the type or function was restricted away from, with no E36107. This page covers the decl-ref walk in `slang-check-decl.cpp`, the generic-struct gap (#13579, fixed by PR #13616), the stale-caps declaration-order bug (#14014), the traps in hooking a new reference path, the walks still missing, and how to verify and test such fixes. Related: target-family gating of IR passes on [slangc Target Coverage & Capability Gating](slangc-target-coverage-and-capabilities.md); derivative `[require]` threading on [[wiki/concepts/slang-autodiff-require-and-variants.md]]; descriptor-handle capability promotion on [[wiki/concepts/slang-language-core-descriptor-handle-capabilities-and-reflection.md]]; when E36100/E36107 fire and how a new barrier or `__stage_switch` in a core intrinsic breaks callers on [capability-check scope](slang-compiler-capability-check-scope-and-core-intrinsic-changes.md).

## TL;DR

- **Inference reaches a type's `[require]` only through the decl-refs it walks.** `SemanticsDeclReferenceVisitor::visitVal` skips Decl-kind operands, so before PR #13616 a `GenericAppDeclRef` (`Foo<3>`) or a member-of-generic decl-ref never contributed the struct's `[require]`; only `visitDirectDeclRef` did.
- **Hook a new path at the decl-ref level** (`visitGenericAppDeclRef` / `visitMemberDeclRef`), not at `visitDeclRefType`: a static member call `Foo<3>.make()` reaches the visitor as a `MemberDeclRef` with no type node.
- **Put capability policy in `CapabilityDeclReferenceVisitor`**, not the shared `SemanticsDeclReferenceVisitor`, which also drives `CollectReferencedDeclsVisitor` (forward-reference and extension generic-param checks).
- **Every `processReferencedDecl`/`processDeclModifiers` read of `inferredCapabilityRequirements` must follow `ensureDecl(decl, CapabilityChecked)`**, skipping decls whose check state `isBeingChecked()`. The caps argument is read before `_propagateRequirement` runs its own `ensureDecl`, so an unchecked decl contributes null caps. On master this makes inference declaration-order dependent (#14014: `StructuredBuffer.getCount` ends with `{}`); on a new path the requirement is lost for good because the decl-ref is marked visited.
- **Match `StructDecl || EnumDecl`.** `StructDecl` alone misses generic enums and enums nested in a generic struct; full `AggTypeDecl` also takes in interfaces and associated types.
- **Do not change the exclusion set by module or magic-ness.** Processing every `DeclRefBase` breaks the core-module bootstrap; skipping `__intrinsic_type`/`__magic_type` also skips standard-module types with their own `[require]`; scoping to `isFromCoreModule` pulls stage-restricted view types into helper inference.
- **The "~50 core-module E36104" cost of propagating intrinsic types comes only from checking core-module consumers**, so a consumer-keyed skip builds every builtin module clean. It still rejects valid user code, because many core-module type `[require]`s describe only the type's main stage (`OutputPatch` omits the domain stage). Before propagating a core type's `[require]`, check it covers every legal stage and target.
- **Two walks are still missing:** `visitFunctionDeclBase` never visits `returnType`, and the base `visitStaticMemberExpr` never calls `processDeclModifiers`. So a generic static member's `[require]` never joins a `__target_switch` case, and `T::m()` through a generic parameter drops even an annotated requirement's caps. Read the walk before writing "general inference already covers X".
- **An unannotated interface requirement can never constrain an implementation:** `checkCapabilityRequirement` treats an empty side as a superset. Probe static vs instance vs existential calls, each with annotated and unannotated requirements.
- **A struct's members never feed its own set:** there is no `visitTypeDefDecl`, so a member `typealias` (and a field's type) contributes nothing to the struct's `[require]`. Do not fold them into `inferredCapabilityRequirements`, which members, extensions and conformances also read (new E36100/E36108/E36118, a fatal E40002 cycle); charge member-typealias caps at the use site in `processReferencedDecl` (#13793).
- **Making a type's `[require]` visible mostly surfaces E36108** on public `[require(X)]` functions; E36104 appears only when the type's set is a superset of the declared target.
- **After any visitor change, run a full build with standard modules (`-- -k 0`) and grep every target's log for `(error|warning)[E…]`,** not only the core-module bootstrap: the `neural` module failed E36104 on #14014 after the core module was clean. Diff every SIMPLE directive's raw output with and without the change before claiming a test is re-enabled, and diff every declaration's inferred caps base vs head (env-gated dump); the test suite does not show which builtins changed.
- **Pin a parity fix with twin rows:** each generic row next to its non-generic twin in one exhaustive DIAGNOSTIC_TEST, master failing exactly the generic rows. Before calling a changed diagnostic a regression, run the non-generic twin on master.
- **A debug-only `SLANG_ASSERT` on a guard that a counting probe never hits beats a silent skip.**
- **Where the checks fire, and core-intrinsic body changes** (E36100 per function, `loadModule` E36107 per target, barrier/`__stage_switch` source breaks): [capability-check scope](slang-compiler-capability-check-scope-and-core-intrinsic-changes.md).

## The walk, and the generic decl-ref gap (#13579)

Inference visits each referenced declaration through `CapabilityDeclReferenceVisitor`, built on the shared `SemanticsDeclReferenceVisitor`, whose `visitVal` skips Decl-kind operands. A `GenericAppDeclRef` (inner `StructDecl` is operand 0) or a member-of-generic decl-ref therefore never contributes the struct's `[require]`; only `visitDirectDeclRef` does — why `[require]` on a generic struct was dropped in #13579 while a non-generic struct gave E36107. Processing every `DeclRefBase`'s `getDecl()` breaks the core-module bootstrap (57 errors); restricting it to user aggregates builds clean [visitVal skips Decl operands](../learnings/1791842377952-diagnostic-test-has-no-not-directive-prefix-not-li.md). PR #13616 adds `CapabilityDeclReferenceVisitor::visitGenericAppDeclRef` and `visitMemberDeclRef`, both routing to `referenceStructOfDeclRef`.

## Hooking a new reference path

PR #13616 produced three rules [new-path rules](../learnings/1791933462633-slang-capability-inference-a-new-processreferenced.md):

1. **ensureDecl first.** `processReferencedDecl` calls `handleProcessFunc(decl, decl->inferredCapabilityRequirements, loc)`, and that argument is evaluated before `_propagateRequirement` runs its own `ensureDecl`. A new path calls `ensureDecl(decl, CapabilityChecked)` itself; otherwise a struct declared later in the file contributes null caps and, its decl-ref now marked visited, the requirement never comes back (the extension check documents the same trap). Mirror `_propagateRequirement`'s skip of a decl whose `checkState.isBeingChecked()`, or a self-referencing type reports CyclicReference.
2. **Hook decl-refs, not types.** `Foo<3>.make()` reaches the visitor as `MemberDeclRef(make, GenericAppDeclRef(Foo, …))` with no type node, so a `visitDeclRefType` hook never sees it.
3. **Policy belongs in `CapabilityDeclReferenceVisitor`.** `SemanticsDeclReferenceVisitor` also drives `CollectReferencedDeclsVisitor` (forward-reference and extension generic-parameter checks), so a change there alters unrelated diagnostics.

## The existing path reads stale caps: inference depends on declaration order (#14014)

The ensureDecl-first rule applies to existing paths too. `CapabilityDeclReferenceVisitor::processReferencedDecl` (slang-check-decl.cpp ~:22154) and `processDeclModifiers` pass `decl->inferredCapabilityRequirements` as `nodeCaps` before `_propagateRequirement` (~:21989) runs `ensureDecl(CapabilityChecked)` (~:22005). For a not-yet-checked decl `nodeCaps` is null; ensureDecl computes the real set, but the stale null is what gets joined, so nothing is added and no provenance recorded. Instrumentation showed the `isBeingChecked()` early return never fired for the victims — not the cyclic skip [stale nodeCaps](../learnings/1793278807356-slang-capability-inference-stale-nodecaps-read-in-.md).

`StructuredBuffer.getCount` (hlsl.meta.slang ~:29629) and `Buffer<T>.getCount` (~:20753) both end with caps `{}`. They are checked early because `visitInheritanceDecl` (~:22954) ensureDecl's each top-level witness impl when the struct's first member, its `: IArray<T>` InheritanceDecl, is checked — before `GetDimensions` has caps. `RWStructuredBuffer.getCount` escapes: its `IRWArray<T>` witness table nests getCount under an `$inheritance` sub-table, which that loop skips. The user-visible result is a silent miscompile: base `Buffer<T>.getCount()` on `-target cpp` emitted an empty `GetDimensions` body [per-decl caps diff](../learnings/1793291900446-capability-checker-prs-diff-every-decl-s-inferred-.md).

Most user code escapes because the visitor reads a callee twice (the DeclRef in `processReferencedDecl`, then `processDeclModifiers`), and the second read sees the first `_propagateRequirement`'s ensureDecl. A `this.method()` member path reads once, so this is accepted on master 01dcd3568 although `second` is HLSL-only [verify with standard modules](../learnings/1793287326326-capability-inference-fixes-must-be-verified-with-s.md):

```slang
struct Box<T> { uint first() { return this.second(); } [require(hlsl)] uint second() { return 1; } }
// called from a Metal entry point: compiles
```

The fix (ensureDecl in the visitor before the read, skipped when `isBeingChecked()`) exposes conflicts the stale read hid. The core-module bootstrap, which aborts on any warning or error (`Session::addBuiltinSource`), reports E36108 twice (matrix `WaveMaskPrefixMin/Max` are `[require(cuda_glsl_spirv)]` but call matrix `WaveMultiPrefixExclusiveMin/Max`, `[require(glsl_spirv)]` only) and E36120 (in `HitObject::GetAttributes`' `__target_switch`, the `hlsl_nvapi` case calls the later-declared, stage-restricted `__hlslGetAttributesFromHitObject`; plain `case hlsl` is not stage-restricted). With those two meta edits the bootstrap is clean, and all 5375 SIMPLE/DIAGNOSTIC_TEST runs show one real delta, a new E41012 warning in `saturated-cooperation/fuse-product.slang` for glsl [decl-order dependent](../learnings/1793280440990-slang-capability-inference-is-decl-order-dependent.md). The full build then fails in the `neural` standard module: public `linearTransform` `[require(cuda_metal_spirv)]` reaches `CoopMat.__init<U,R1>` `[require(cooperative_matrix_conversion)]` on SPIR-V → E36104. Side finding: master's DXR 1.3 `HitObject::GetAttributes` emitted `attr = hit.GetAttributes();`, which DXC 1.9 rejects (hlsl-specs 0027: `template<attr_t> void GetAttributes(out attr_t)`); routing through `__hlslGetAttributesFromHitObject` emits `hit.GetAttributes(v)`.

## Which declarations to match: `StructDecl || EnumDecl`

PR #13616 first filtered `referenceStructOfDeclRef` on `as<StructDecl>`, leaving `[require(metal)] enum GE<let N:int>` and `Outer<3>.E` (enum in a generic struct) silent for HLSL while a non-generic `[require]` enum gives E36107. Widening to `StructDecl || EnumDecl` fixes both: core module builds with no diagnostics, metal still compiles, 2912/2912 tests pass, a 4770-invocation SIMPLE byte-compare is clean. Devin caught the enum gap; the in-house correctness reviewer filed only the member-function variant [StructDecl-only misses enums](../learnings/1791937885563-slang-capability-inference-a-structdecl-only-hook-.md).

Full `AggTypeDecl` was rejected because it covers interfaces and associated types: associated-type provenance notes move from the interface to `associatedtype A`, and `[require(hlsl)] struct S : IGen<int>` fires E36118. That E36118 is not a regression — master already emits it for the non-generic `[require(hlsl)] struct S : ING`, so the generic spelling now matches its twin [run the twin first](../learnings/1791941121185-before-calling-a-new-capability-diagnostic-a-regre.md).

## Excluding intrinsic types: the scoping traps

Copying `collectGenericStructTypeUses`'s rule (skip `__magic_type`/`__intrinsic_type` aggregates) also skips standard-module types declared `__intrinsic_type(...)` with their own `[require]`, e.g. slang.raytracing's `rt::MultiLevelAccelerationStructure<N>` (`[require(metal)] __intrinsic_type(RaytracingAccelerationStructure)`), so dependent tests keep passing silently. Limiting the exclusion to core-module decls (`isFromCoreModule`) propagates them but pulls stage-restricted view types (`[require(structural_raytracing_*)]` ClosestHitInput etc.) into helper inference: on fork kaizhangNV/slang@5dd28dd2e8 that moved/added E36100 and dropped one E36107 across 4 of 219 `tests/ray-tracing-2` directives. Fast fork build for `-no-codegen` checks: `-DSLANG_ENABLE_TESTS=OFF -DSLANG_ENABLE_DXIL=OFF -DSLANG_SLANG_LLVM_FLAVOR=DISABLE` (DXIL ON builds DXC from source; `SLANG_ENABLE_TESTS` requires `SLANG_ENABLE_SLANG_RHI`) [skipping __intrinsic_type](../learnings/1791852083392-capability-inference-fixes-that-skip-intrinsic-typ.md). Re-measured at cbd707f41 + #13616, the restriction changed raw output of only 1 of 261 `tests/ray-tracing-2` directives (`multilevel-acceleration-metal-only`, now E36107 as expected); the core module built clean and the 4/219 drift did not reproduce [1/261 re-measure](../learnings/1793230221963-slang-test-silently-ignores-filecheck-tests-withou.md).

PR #13616 keeps core-module `__magic_type`/`__intrinsic_type` generics out of inference, citing "~50 core-module E36104" otherwise. That cost comes only from checking core-module consumers. A consumer-keyed variant in `referenceAggTypeOfDeclRef` skips such a type only while the module being checked is core (`isFromCoreModule(getShared()->getModule()->getModuleDecl())`), so the types propagate into user code: core, glsl, neural, numerics, functional and workgraph build with 0 diagnostics, and `typeOnly<CoopVec<float,4>>()` now gets E36107 on metal and wgsl, where the type-keyed exclusion was silent. "Core module" means the compiler-embedded builtins (`m_isCoreModuleCode`, set in `slang-global-session.cpp`), not `source/standard-modules`; the only non-core `[require]` intrinsic types upstream are the 10 experimental workgraph types. Separately, an empty-body node entry taking `DispatchNodeInputRecord<T>` ICEs on spirv on master (E99997 "unhandled stage") [consumer-keyed skip](../learnings/1793236364757-slang-capability-exclusions-key-core-module-consum.md).

A full byte-compare of that variant (reviewer drill "N2" on #13579) showed it is not safe yet. Every module built clean, but 5 tests newly failed, 3 rejecting valid code with E36107: a domain shader taking `OutputPatch<…>` (`tests/bugs/gh-8920-domain-shaders.slang`), because `OutputPatch`'s `[require]` (hlsl.meta.slang ~6711) omits the domain stage, and compute code using `__SubpassImpl` (`tests/language-feature/descriptor-handle/gh-13070-handle-ordering-nonencodable.slang`). In the other 2, `stream-output-on-vertex` gains a second E36107 for `LineStream` beside its E38050, and in the domain/metal run of `tessellation-invalid-output-topology` an `OutputPatch` E36107 replaces the expected E50061; 4 more runs pass with notes moved from function to type. Many core type `[require]`s describe only the primary use, so check coverage of every legal stage and target before propagating. The "~50 E36104" is a separate problem: core functions taking these types do not redeclare their requirements [core type require = main stage](../learnings/1793240821420-core-module-type-require-s-describe-the-main-stage.md).

## Walks inference still does not make

`SemanticsDeclCapabilityVisitor::visitFunctionDeclBase` walks the parameters, body and parent aggregate, never `returnType`. A `[require(metal)] struct MN` named only by an entry point's return type (`MN main()`) compiles silently for HLSL; only `collectGenericStructTypeUses` in `validateEntryPoint` catches the generic `MG<3> main()`. The base `visitStaticMemberExpr` dispatches only the decl-ref and never calls `processDeclModifiers`, so a `[require]` on the member of `G<3>.make()` is dropped; non-generic `S.make()` folds to `DirectDeclRef(make)` and is caught. The PR #13616 reviewer caught a comment claiming "general inference already covers" the return-type case [return type never walked](../learnings/1791953844275-slang-capability-inference-never-walks-a-function-.md).

The member-level case resisted two quick fixes on PR #13616 — adding `processDeclModifiers` to the base `visitStaticMemberExpr`, and including `__intrinsic_type` generics in the new hook; both broke the core-module build (E36104 at `coopVecLoad`, E36120). Inside the core module, a GENERIC static member called as `Type::name` from a `__target_switch` case does not join its `[require]` into the case (a free function or non-generic static member does), because `visitStaticMemberExpr` never reaches `processDeclModifiers` for a `GenericAppDeclRef`; the E36120 consequence is on [capability-check scope](slang-compiler-capability-check-scope-and-core-intrinsic-changes.md) [generic static members](../learnings/1792523053545-slang-capability-checker-drops-require-only-for-ge.md).

The same gap drops an interface requirement's caps through a generic parameter (#13995, master dd307e436). `visitStaticMemberExpr` (:1205) never calls `processDeclModifiers`, which `visitDeclRefExpr` and `visitMemberExpr` (:1190/:1199) do, and inside `forward<T:IFoo>` the `T::invoke` decl-ref is a `LookupDeclRef`, so `visitDirectDeclRef` never fires either: `[require(anyhit)]` on `IFoo.invoke` is lost through `T::invoke()`, while `t.invoke()` and the existential form give E36107. Separately, an UNANNOTATED requirement can never constrain an implementation, because `CapabilitySet::checkCapabilityRequirement` returns "superset" when either side is empty (`slang-capability.cpp:1468`); removing the opt-in skip in `visitInheritanceDecl` (:22968) alone does not catch implementations whose requirements come only from inference. Probe static vs instance vs existential calls, each with annotated and unannotated requirements [T::m() drops caps](../learnings/1793227466477-slang-capability-inference-static-t-m-through-a-ge.md).

## A struct's members never contribute to its own capability set

`SemanticsDeclCapabilityVisitor` (slang-check-decl.cpp ~:1445, TOT 7251cc60b) has no `visitTypeDefDecl`, so a `typealias` falls to `visitDecl {}`: its aliased type is never walked and a `[require]` on it is ignored. A struct's `inferredCapabilityRequirements` comes from `visitContainerDecl` → `getDeclaredCapabilitySet` (~:22472-22532), reading only its own and parents' `[require]`. Members are never unioned in — not typealiases, not fields (`struct C { MetalOnly m; }` as `uniform C` compiles silently), not methods (charged at the call by design). `uniform Context.Element` still works, because type resolution canonicalizes the alias before capability checking, and `[require]` is enforced on member access through the type (`input.e.x`). Generic associated-type use is silent too: `Input<T:IC>{ T.Element e; }` as `Input<Context>`, and `use<Context>()` with `T.Element x` (#13793) [members never contribute](../learnings/1792534898622-slang-capability-inference-typealias-members-and-s.md).

Folding member-typealias caps into that field breaks code that compiles on master, because the field has four consumers: (a) users of the type (`processReferencedDecl`); (b) the struct's members, which inherit it as declared caps (the `getDeclaredCapabilitySet` AggTypeDecl shortcut plus the non-static parent join in `visitFunctionDeclBase`); (c) `visitExtensionDecl` / `_checkExtensionMemberCapConflict`; (d) `visitInheritanceDecl`'s subtype-vs-supertype check. Changing (b)-(d) gives new errors: `extension Context { [require(hlsl)] int get(); }` → E36100; `struct Context : IFoo` with a `[require(hlsl)][require(metal)] IFoo` → E36118; an unused struct with a metal alias and an hlsl alias → E36100; a `[require(hlsl)]` method → E36108. Walking `typealias L = List<Self>` (`List<T:I>`, `Self : I`) during the struct's own `CapabilityChecked` hits the InheritanceDecl→parent cycle → fatal E40002; the full 10.7k-test suite missed it (no test has `struct X : I { typealias A = G<X>; }` with `G<T:I>`), `/code-review medium` caught it. The approach that avoided all of these charges caps at the use site: when `processReferencedDecl` sees an AggTypeDecl, it also feeds each direct member `TypeDefDecl`'s caps (after `ensureDecl`) to `handleProcessFunc`, leaving the struct's own set untouched — keep "charged to users" and "inherited by members" separate. Run master and fix full suites serially: concurrent A/B runs gave ~460 spurious cuda/vk failures [charge at use site](../learnings/1792554070597-slang-capability-inference-folding-member-typealia.md).

## Breaking surface and verification

Making a type's `[require]` visible breaks user code mostly through E36108 (dependencies not compatible on target) on public `[require(X)]` functions; E36104 appears only when the type's set is a superset of the declared target, e.g. spirv plus an extension against plain spirv [StructDecl-only misses enums](../learnings/1791937885563-slang-capability-inference-a-structdecl-only-hook-.md).

**Build.** Visitor changes run against the core module first, so rebuild it and grep `build.log` for `(error|warning)[E…]` [new-path rules](../learnings/1791933462633-slang-capability-inference-a-new-processreferenced.md). That is not enough: on #14014 a scratch build with standard modules off missed the `neural` E36104. Run `cmake --build --preset debug -- -k 0` and grep `FAILED:` and `error[E` across all targets, including `slang-standard-module-*` [verify with standard modules](../learnings/1793287326326-capability-inference-fixes-must-be-verified-with-s.md).

**Byte-compare tests.** Before claiming a fix re-enables a test, diff every SIMPLE directive's raw output with and without the change [skipping __intrinsic_type](../learnings/1791852083392-capability-inference-fixes-that-skip-intrinsic-typ.md). For a whole-suite compare, run all ~5,160 SIMPLE/DIAGNOSTIC_TEST invocations with both slangc builds and diff only diagnostic lines (`error|warning|note`). Do not keep a drill binary by copying a Release `bin/`+`lib/` tree: OptiX header lookup breaks (`nvrtc: Failed to locate OptiX headers`) and `tests/cuda/optix-*` rows diverge spuriously [StructDecl-only misses enums](../learnings/1791937885563-slang-capability-inference-a-structdecl-only-hook-.md); a copied snapshot also changes prelude `#include` and debug-info paths, cannot load dxc, and changes debug-info hashes, so categorize every remaining difference before calling it noise [core type require = main stage](../learnings/1793240821420-core-module-type-require-s-describe-the-main-stage.md).

**Diff every declaration's inferred caps, base vs head.** Patch a review-only, env-gated dump into `_dispatchDeclCheckingVisitor` right after `SemanticsDeclCapabilityVisitor(shared).dispatch(decl)`. For each FunctionDeclBase, AggTypeDeclBase and PropertyDecl, write `ASTPrinter::getDeclSignatureString`, the parent chain, a loc and `printDiagnosticArg(CapabilitySet{decl->inferredCapabilityRequirements})`, printing EMPTY/NULL/INVALID explicitly (the printer shows `{}` for both empty and invalid). Build base and head with `SLANG_REVIEW_DUMP_CAPS=<file> cmake --build`; core, glsl, numerics and neural are capability-checked at build time, so the dump happens during the build (~19.5k decls). Diff by (signature, file). On #14024 this found 87 changed decls, including the `Buffer<T>.getCount()` cpp miscompile and a new E41012 on HLSL below sm_6_6 for DescriptorHandle deref (script: slang-reviewer `review-14024/dump-caps.py`). A capability test calling through a generic interface constraint (`input.linearTransform`, `input : IVector<T>`) passes on base and head because requirements are lost through interface calls (#13995), so test concrete-type calls [per-decl caps diff](../learnings/1793291900446-capability-checker-prs-diff-every-decl-s-inferred-.md).

**Scratch builds.** Copy with `tar --exclude=./build --exclude=./.git` (no rsync); configure `-DSLANG_VERSION_NUMERIC=2026.13.1 -DSLANG_SLANG_LLVM_FLAVOR=DISABLE` with tests, examples, GFX, RHI, slangd, replayer, CUDA and OptiX off; a 64-core release `slangc` build takes ~190 s (incremental ~77 s), and slang-bootstrap stderr shows in the build log [stale nodeCaps](../learnings/1793278807356-slang-capability-inference-stale-nodecaps-read-in-.md). Without libslang-glslang, `-target spirv` fails with E00100 'spirv-opt'; copy `libslang-glslang-<ver>.so` from a full build into `build/Release/lib` [decl-order dependent](../learnings/1793280440990-slang-capability-inference-is-decl-order-dependent.md). In-process slang-test can segfault on cooperative-matrix GPU tests, so use `-use-test-server`; SIMPLE rows with `-DNV_SHADER_EXTN_SLOT=u0` are silently ignored when external/nvapi is absent, so drop the define (slangc still emits `NvGetAttributesFromHitObject` with `-capability hlsl_nvapi`) [verify with standard modules](../learnings/1793287326326-capability-inference-fixes-must-be-verified-with-s.md).

## Testing a parity fix: twin rows, and the twin before a regression claim

A fix like #13616 removes a dependence on whether a type is spelled generically. Reviewers accept the tests as pinning it when each generic row sits next to its non-generic twin in one exhaustive DIAGNOSTIC_TEST and the master binary fails exactly the generic rows; on #13616 that was 18/33 on master, 33/33 with the fix [twin rows](../learnings/1791946199459-pin-a-generic-vs-non-generic-parity-fix-with-twin-.md).

The same framing decides whether a changed diagnostic is a regression: ask "does the generic spelling now match its non-generic twin on master?", not "is it new versus master?". On #13616 both the fixer and a reviewing approver reported E36118 on `[require(hlsl)] struct S : IGen<int>` as a regression, but master already gave it for `S : ING`. Put each probe shape in its own file: E36118 is reported per declaration for every struct in the file, so combined shapes mislead [run the twin first](../learnings/1791941121185-before-calling-a-new-capability-diagnostic-a-regre.md).

For a guard condition that should be impossible, a debug-only `SLANG_ASSERT` beats a silent skip once a counting probe shows it never fires (0 of 2,337 test files on #13616), and reviewers accept it [twin rows](../learnings/1791946199459-pin-a-generic-vs-non-generic-parity-fix-with-twin-.md).
