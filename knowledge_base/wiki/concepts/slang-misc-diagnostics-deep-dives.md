# Slang Diagnostics: Deep-Dive Incidents & Case Studies

Split from [Slang Diagnostics System: Catalog, Definitions, and Rendering](slang-misc-diagnostics-catalog-and-system.md) (over the 40 KB cap). The system-mechanics half (Lua definitions, the generated catalog + `regenerate.py`, rendering/FileCheck gotchas, warn→error escalation, API option plumbing, false-positive adjudication) stays there. This half collects the worked *incidents* — each a concrete case where a diagnostic's behavior, provenance, or severity had to be reasoned out end-to-end.

## TL;DR

- **A "new" diagnostic can report a discard that was always happening.** E36121 (#11225) didn't add a restriction — `getTargetCaps()` had silently dropped incompatible requested capabilities forever; a second walk now *reports* it. Before calling a diagnostic a new restriction, check whether the underlying discard predated it. An inertness claim covers *all* readers of an option — 5 files read the raw `Capability` array directly, bypassing `getTargetCaps()`.
- **Prove a one-site guard fix *complete* by enumerating the diagnostic's distinct variable values** (`grep -ohE "<msg>" *.log | sort | uniq -c`). One distinct pair → sufficient; ≥2 → the one-liner is only the first fix. Pull *raw* logs, not the triage digest. And **prove the negative arm reproduces first** — a version-pinned build cannot reproduce an *unreleased* upstream diagnostic, so a clean without-guard arm proves nothing.
- **A warning is not the end of a compile — run the reported snippet to codegen** before grading a permissiveness complaint docs-only. `| head` masks exit status (redirect + check `$?`); test a *release* binary too (`SLANG_ASSERT`→`SLANG_ASSUME` turns a clean debug error into a release crash); probe the matrix including the cell that removes your prime suspect; pin the breaking pass from the `-dump-ir` schedule, not `slang-emit.cpp` line order.
- **A severity DOWNGRADE resting on API semantics needs the receiver verified, not just the call site.** `queue->Signal` is GPU-timeline; `fence->Signal` is CPU — grep all call sites of the verb and confirm the receiver. Downgrades deserve *more* scrutiny than upgrades. Resolve every `file:line` against the pinned commit — inline anchors drift to the diff hunk.
- **Touching a shared type/name formatter** (`getTypeNameHint`, anything reached by `printDiagnosticArg`) silently regresses unrelated exhaustive `diag=` goldens — and **draft-PR CI hides it** (build/test jobs skip on drafts). Grep callers, run the broad diagnostic dirs locally, and confirm via merge-base your change is the reaching edit before touching a pre-existing golden.
- **A diagnostic with no Decl needs a direct `diagnose()`** — `[deprecated]`/`[RemovedSince]` work by `findModifier<>` on a Decl, so a synthetic special case like `(Struct)0` can't reuse the attribute path.
- **A loc-less diagnostic whose front-end clearly stamped the loc** points at a later pass that RE-SYNTHESIZES the access (std140 block-struct wrapping) without `IRBuilderSourceLocRAII`. Fix producer-side. Statement-granularity `OpLine` can mask the IR truth on master — re-run a subagent's `reproduced` claim against the user-visible observable before posting the label.
- **Missing-return severity is target-gated, not language-gated** (E41009 hard error on Khronos/WGPU vs E41010 warning on HLSL/Metal/CUDA/CPP). Verify a "depends on #N" claim by checking whether the symbols it adds exist on master, not just the PR state.
- **A late `linkAndOptimizeIR` diagnostic has three placement traps.** Before the final DCE it false-positives on dead-but-linked helpers (`__sincos_metal`); past an existing `getErrorCount()` bailout it lets later passes see IR the old error used to stop (segfault in `specializeResourceUsage`) — report at the same point as the error it replaces; and an IR backstop misses code `simplifyIR` already deleted (dead `__apply(f)(x)`, E38037) — test dead/pure forms.
- **A guard added to ONE emit pass rarely closes a "bodyless decl derefs `getFirstBlock()`" crash** — check the pass ORDER and the DECORATION the crashing pass keys on; verify with a cross-target control that disables the guarded pass entirely. The root-cause fix rejects the bodyless attr in the semantic checker.

## E36121: A New Diagnostic Can Report a Discard That Was Always Happening

`TargetRequest::getTargetCaps()` (`slang-target.cpp`) has long walked the requested-capability array, ending each iteration with `if (!targetCap.isIncompatibleWith(toAdd)) targetCap.join(toAdd);`. The incompatible case falls through with no join, no diagnostic and no trace, so an incompatible requested capability never entered `cookedCapabilities`. #11225 adds `checkCapabilities()` (called from `checkEntryPoints`), a *second* walk over the same `getArray(CompilerOptionName::Capability)` that **reports** what the first walk discarded — E36121 is a newly-visible pre-existing discard, not a new restriction. The cooked path is statically answerable: `hlsl_nvapi` is `def hlsl_nvapi : hlsl;`, `isIncompatibleWith` is true when zero target sets intersect, and non-d3d12 devices cook to non-hlsl atoms (vulkan→`spirv`, metal→`metal`, wgpu→`wgsl`, cuda→`cuda`, cpu→`cpp`/`llvm`), so every non-d3d12 target already dropped it. E36121 is keyed on the **target** with no device term, so a `dxil + hlsl_nvapi` pairing is verifiable with `slangc` alone; only device creation, runtime NVAPI linkage and Windows subcase execution need real CI ([getTargetCaps already silently drops incompatible requested capabilities — E36121 diagnoses a discard that was always happening](../learnings/1785751218246-slang-gettargetcaps-already-silently-drops-incompa.md)).

⚠️ **Correction: "both arms inert ⇒ pure diagnostic suppression" does NOT follow** — it verified only the **cooked** set. Five files read `getArray(CompilerOptionName::Capability)` directly, and one (`slang-type-layout.cpp:3549`, `maybePromoteDescriptorHandleCapability`) computes `specificCapabilityRequested` from the raw array, so removing an entry can flip `descriptor_handle` auto-promotion on metal/cuda/wgpu/cpu. The promotion's observable effect is accept/reject and diagnostics, not sizing, so measure diagnostics on a no-profile target, not layout. The E36121 emitter reads the **requested** array (`-capability`/API path), so an in-source `[__requiresNVAPI]`/`[require]` never enters it and is not a second fix site. Enumerate all readers of an option before claiming inertness. The full reader map lives on [[wiki/concepts/slang-compiler-frontend-and-checking.md]] (formerly on [[wiki/concepts/slang-misc-compiler-internals.md]]) ([CORRECTION — both-arms-inert was scoped to the cooked capability set only](../learnings/1785751609559-correction-both-arms-inert-was-scoped-to-the-cooke.md)).

## Prove a One-Site Guard Fix Complete by Enumerating the Diagnostic's Distinct Values

"Consistency with the other guarded sites" shows a one-site guard is *idiomatic*, never that it is *sufficient*, and only sufficiency justifies ruling a broader audit out of scope. The closing step is a uniqueness check on the diagnostic's **variable parts**:

```bash
grep -ohE "requested capability '[^']+' is incompatible with compilation target '[^']+'" *.log | sort | uniq -c
#   56 requested capability 'hlsl_nvapi' is incompatible with compilation target 'spirv'
```

One distinct pair → the single site is sufficient; two or more → the fix is only the first of several. On slangpy#1087/#1088 this returned one pair, 28× per platform, so run it **before** recommending the single site. Enumerate the other variable too (only `spirv` appeared, so metal/CUDA/CPU are covered-by-construction, not verified). Pull **raw** logs (`gh api repos/<o>/<r>/actions/jobs/<id>/logs`), not the triage digest, which keeps the failure shape but drops the cardinality that sets scope, and state counts per job ("28 failures" across two logs vs. 28 *per* log). Tell: **0 failed assertions with N failed test cases** is doctest's signature for an exception during setup (module-load failure), i.e. one root cause ([enumerate a diagnostic's distinct values to prove a one-site fix is complete](../learnings/1785748284485-enumerate-a-diagnostic-s-distinct-values-to-prove-.md)).

**Prove the negative arm reproduces first.** When the downstream project pins a released tarball (`SGL_SLANG_VERSION`, `external/CMakeLists.txt:85`) and the diagnostic comes from an *unreleased* upstream change, a build against the pin cannot reproduce it, so a green local test proves no-regression only. Run an A/B against a local build of the upstream PR (`SGL_LOCAL_SLANG=ON` + `SGL_LOCAL_SLANG_DIR` + `SGL_LOCAL_SLANG_BUILD_DIR`, as CI does): **without** the guard must show the error verbatim (captured in the PR body), **with** it must be clean. A clean without-guard arm means "locally unproven; rests on CI plus code inspection" — a negative result, not a pass. Confirm the harness creates real devices (a GPU-skipped run makes the A/B vacuous), and declare an arm you cannot exercise locally (e.g. `SGL_HAS_D3D12: OFF`) as a PR caveat. Sequencing for a downstream fix pinned to upstream releases is **merge → tag → bump**: check `merged`/`merged_at` via REST and list real tags; opening a draft is not gated by what gates promoting it ([verifying a guard fix: enumerate the diagnostic's distinct pairs, and prove the negative arm reproduces first](../learnings/1785746886431-verifying-a-guard-fix-enumerate-the-diagnostic-s-d.md)).

## A Warning Is Not the End of a Compile — Run the Reported Snippet to Codegen (#8785)

For any "the compiler accepts/permits X" report, run X **to codegen on the real targets** before ruling the compiler innocent. On slang#8785 the reporter quoted `warning 38040: parameter 'payload' is treated as 'uniform'` for the documented amplification form `out payload TaskData payload`. A first triage traced the front-end force-uniform + warn path (`slang-check-shader.cpp:2118-2155`) and graded it docs/medium/P2. Compiling at HEAD `546ad18f7` inverted that: `-target spirv` ICEs (`slang-ir-glsl-legalize.cpp(5235): call->getArgCount() == 4`), `-target metal` ICEs (`slang-ir-legalize-varying-params.cpp(4566)`), `hlsl` emits writes into a read-only `cbuffer` that `dxc 1.9` rejects, `glsl` silently writes a `push_constant` block, and released `slangc 2026.13.1` segfaults (exit 139). The real grade was bug/high/P1 `reproduced`. A warning means the front end had an opinion; reporters quote the first thing they see. Besides "does this permissiveness defect also REJECT valid code?", ask **"does it CRASH on the invalid code it accepts?"** ([a front-end warning is not the end of a compile run](../learnings/1785803987320-a-front-end-warning-is-not-the-end-of-a-compile-ru.md), [compile the reported snippet all the way to codegen — a quoted warning may be hiding an ICE](../learnings/1785803858075-compile-the-reported-snippet-all-the-way-to-codege.md)).

Four reusable method traps. **(1) `| head` masks exit status:** `slangc … 2>&1 | head -12` reported `EXIT=0` on a segfault; use `slangc … > log 2>&1; echo "EXIT=$?"`. **(2) Test a release binary:** `SLANG_ASSERT` becomes `SLANG_ASSUME` in release (`slang-common.h:364` vs `:371`), so debug gives a clean error and release gives a crash. **(3) Probe the matrix, including the cell that removes your prime suspect:** `out payload T`, `in payload T`, `inout payload T`, bare `payload T` **and plain `out T`** all ICE; `in T` compiles but emits a silently-wrong PushConstant; `uniform T`, a local, a `groupshared` global, a `groupshared` var passed to `DispatchMesh`, or no `DispatchMesh` call are clean. The trigger is "the value passed to `DispatchMesh` is an entry-point parameter", not the `payload` modifier, so a payload-only checker fix would leave `out T p` crashing. **(4) Pin the breaking pass from the dump, not `slang-emit.cpp` line order:**

```bash
awk '/^### AFTER/{pass=$3} /func %DispatchMesh/{print pass"\t"$0}' ir.dump \
  | sed 's/RefParam([^)]*)/REFPARAM/' | awk '{if($0!=prev)print; prev=$0}'
```

The call is 4-param through `specializeResourceUsage` and 3-param right after **`specializeFuncsForBufferLoadArgs`**; the same sweep on the working `groupshared` input never drops arity, ruling out "this pass always does that." An Explore subagent confidently blamed `legalizeEntryPointsForGLSL`, but the dump shows the drop complete before it runs — passes sit behind target conditionals, so adjudicate subagent attributions against the dump, not plausibility.

Two prose-discipline corollaries. **Scope your greps in prose:** a public claim that `taskPayloadSharedEXT` "returns nothing across this tree" was really a `--include=*.md --include=*.slang --include=*.rst` grep; the tree has 19 hits, including the emitter and legalize pass that implement the rate. Say "zero in markdown," never "zero tree-wide", and ask whether a non-empty result would have helped your argument before citing emptiness. The doc bug lived in `shader-slang/shader-slang.github.io` (`docs/coming-from-glsl.md:942-954`, found via `gh api "search/code?q=taskPayloadSharedEXT+org:shader-slang"`), so search the org when a cited `docs.shader-slang.org` page is absent from the compiler tree. **Re-read an artifact live immediately before editing it:** an in-flight `PATCH` nearly overwrote a superseding correction. Also, when a reporter says a test "works only because there is exactly one thread", check the thread count: both in-tree amplification tests dispatch one task thread (`task-simple.slang:37`, `task-groupshared.slang:34`), and at `[numthreads(32,1,1)]` the SPIR-V is an unsynchronized `OpStore` from all 32 threads with no `OpControlBarrier` — a coverage hole.

## A Severity DOWNGRADE Resting on API Semantics Needs the Receiver Verified, Not Just the Call Site

When a severity **downgrade** rests on an API's timing semantics, verify the exact method invoked — receiver *and* signature — not just that a call exists at the cited line. On slang-rhi#797 a CodeRabbit Major flagged a non-aborting `CHECK` followed by a call reaching `WaitForSingleObject(…, INFINITE)`. Two tiers correctly downgraded it to nit but recorded the reason as "the wait is on a CPU-signalled fence". At SHA `b34042ac`, `d3d12-command.cpp:2162` is `m_d3dQueue->Signal(...)` (`ID3D12CommandQueue::Signal`, GPU-timeline); the CPU form `m_trackingFence->Signal(value)` appears nowhere (all four `Signal(` sites are queue-side). The verdict held for a different reason (the Signal is enqueued at wait time and only needs submitted work to drain). **Right conclusion, wrong mechanism is the hardest class to catch**, because nothing prompts a re-check, and here the false premise was recorded as the strengthening. Downgrades deserve more scrutiny than upgrades: an over-stated severity gets argued down, an under-stated one is agreed with and closes the thread. Grep all call sites of the verb, confirm they share the assumed receiver, then walk the path — for the load-bearing claim only (two adjacent claims held under the same check). **Resolve every `file:line` against the pinned commit before it enters an artifact:** both tiers cited `:412` (a `sed -n '395,425p'` window offset; CodeRabbit's anchor copied verbatim) while the `CHECK` is at `:409`. Cite the line the claim is about and cross-check `original_line`/`start_line`, since inline anchors drift to the diff hunk. Having the rule (applied to bot counts, not line refs) isn't executing it ([a severity downgrade resting on API timeline semantics — verify the receiver, not just that the call site exists](../learnings/1785780844550-a-severity-downgrade-resting-on-api-timeline-seman.md)).

## Touching a Shared Type/Name Formatter Silently Regresses Unrelated `diag=` Goldens

Changing a shared formatter — `getTypeNameHint` (`slang-ir-util.cpp`) or anything reached by `printDiagnosticArg` (`slang-ir.cpp:36`, the generic `IRInst`/`IRType` argument renderer) — can alter the message text of unrelated diagnostics. On PR #12005 (#7878), adding `case kIROp_OptionalType` so E41037 could render `Optional<T>` also changed a pre-existing `__ref`/`__constref` dynamic-dispatch diagnostic from `''` to `'Optional<IFoo>'`, failing the exhaustive golden `tests/language-feature/dynamic-dispatch/diagnose-ref-interface-in-compound.slang` (+ `.1`). It bites because (1) **draft-PR CI skips build/test jobs**, so the failure appears only when the PR goes non-draft, often after approval; (2) `.slang` goldens are runtime-interpreted, so only running the test catches them; (3) goldens are scattered (`tests/diagnostics/`, `tests/language-feature/dynamic-dispatch/`, `tests/glsl-intrinsic/`, `tests/autodiff/`, `tests/compute/`, …), so a two-directory sweep does not bound the blast radius. When touching a shared render helper, `grep -rn getTypeNameHint source/slang/` for callers, run the broad diagnostic dirs locally, and say what you swept. The exhaustive-check output prints "Suggested annotations you can copy"; carets rarely move, so the fix is a message refresh. That is a genuine refresh (the message improved), but confirm via merge-base that your change is the reaching edit before touching a pre-existing test ([Shared diagnostic formatter changes silently regress unrelated exhaustive diag= goldens (masked on draft CI)](../learnings/1783657592434-shared-diagnostic-formatter-changes-silently-regre.md)).

## (Struct)0 Zero-Cast Has No Decl -- Deprecation Needs a Direct diagnose() (#12045)

The legacy HLSL `(Struct)0` cast (treated as `Struct s = {}`, default-init not zero-init) is a hardcoded special case in `SemanticsExprVisitor::visitTypeCastExpr` (`slang-check-expr.cpp:7389`), gated on a StructDecl target plus exactly one `IntegerLiteralExpr` arg equal to 0, and only for C-style cast syntax (not `T(0)`). `[deprecated]`/`[RemovedSince]` work by `findModifier<>` on a **Decl**, and the zero-cast has none, so a deprecation must be a direct version-gated `diagnose()` at the special-case site (:7404), reusing the `moduleDecl->languageVersion` comparison idiom plus a new diagnostic; the removal version is an ABI-relevant `SlangLanguageVersion` enum append ([slang (Struct)0 zero-cast is a synthetic special case, no Decl for [deprecated] attribute](../learnings/1783690411342-slang-struct-0-zero-cast-is-a-synthetic-special-ca.md)).

## Source-Loc Dropped by std140 Re-Synthesis (Real at IR Level, Masked by Statement-Granularity OpLine)

Under `spvBindlessTextureNV`, E55215 on a `ConstantBuffer<T>.Handle` prints with no source location while the same diagnostic on `StructuredBuffer`/`ByteAddressBuffer` has a real `line:col` (#12192). The front-end stamps the loc, but the CB element is wrapped into a std140 block-struct and its field access is **re-synthesized** in `slang-ir-lower-buffer-element-type.cpp` via `setInsertBefore(user)` + `emitFieldAddress`/`emitLoad` with no `IRBuilderSourceLocRAII`; a StructuredBuffer scalar load is not re-synthesized and keeps its loc. When a diagnostic is loc-less but the front-end clearly stamped it, suspect a later re-synthesizing pass and fix it producer-side ([diagnostic no-loc on ConstantBuffer descriptor-handle: loc dropped by std140 re-synthesis, not the frontend](../learnings/1784762842417-diagnostic-no-loc-on-constantbuffer-descriptor-han.md)).

The drop is real at the IR-instruction level but **masked on master** for debug info: Slang emits `OpLine`/`DebugLine` per *statement*, so the statement's `OpLine` covers the loc-less access and `-g2`/`-g1` output looks correct. A build+run subagent misread "the CB access has no OpLine of its own" as master-reproducible. Re-run a subagent's `reproduced` claim and read the output before posting the label; the clean observable here is the E55215 diagnostic (a direct `inst->sourceLoc` consumer), not the debug-info golden ([CB source-loc drop is IR-level real but MASKED on master by statement-granularity OpLine — verify observables yourself](../learnings/1784778798903-cb-source-loc-drop-is-ir-level-real-but-masked-on-.md)).

Missing-return severity is **target-gated, not language-gated** (a portability trap): `doesTargetAllowMissingReturns` is false for Khronos/WGPU (hard `E41009 MissingReturnError`) and true for HLSL/DXIL/Metal/CUDA/CPP (warning `E41010`). The check runs twice by design — at lowering (`CodeGenTarget::None`, warning) and at link/emit (real target, error on strict targets) — both gated by `shouldRunNonEssentialValidation()`. #12264 (skiminki-nv) proposes an unconditional `E41009` for language version 202c by gating on `module->languageVersion`; it is PARKED on unmerged #12179, which adds `SLANG_LANGUAGE_VERSION_202C`. Verify a "depends on #N" claim by checking whether its symbols exist on master, not just the PR state ([missing-return severity is target-gated; 202c proposal moves it to language-version gating](../learnings/1785336991633-missing-return-severity-is-target-gated-202c-propo.md)).

## Placing a Late Diagnostic in `linkAndOptimizeIR`: After the Final DCE, at the Bailout It Replaces (#13555, #13560)

Under `-ignore-capabilities` (#13555) E36107 is suppressed, so a `__target_switch` with no case for the target lowers to `missingReturn`, which C-like emitters print as nothing (empty kernels, or infinite loops on CUDA). `specializeTargetSwitch` is the wrong site: it runs over every linked function before DCE, and `sincos()` links the metal-only `__sincos_metal` on every target, so an error there breaks ~220 tests. Right after the post-link DCE (`slang-emit.cpp` ~:1595) is still early: torch keeps TensorView/cudaThreadIdx reachable until `removeTorchKernels`, and a Metal MS-texture test expects E41404 later from `legalizeImageSubscript`. What passed: decorate the emitted `missingReturn` (function name + switch sourceLoc) and report after the LAST DCE, next to `processLateRequireCapabilityInsts` (~:2563) ([case-less __target_switch must be diagnosed after the final DCE](../learnings/1791593675740-diagnosing-a-case-less-target-switch-must-happen-a.md)).

Moving an error later can remove a bailout. On SPIR-V/GLSL/WGSL the replaced E41009 stopped the compile at the `getErrorCount() != 0` check after `checkForMissingReturns` (~:1707); suppressing it let a case-less function returning `Texture2D` reach `specializeResourceUsage` and segfault (`ResourceOutputSpecializationPass::specializeCallSite`, this=0x0). PR #13564 reports the new error at the same point as the error it replaces (`diagnoseMissingReturnForTarget`) on targets that reject missing returns, and late only elsewhere. When you move or suppress a diagnostic, find the next `getErrorCount()` bailout, ask which later passes assume it stopped the compile, and test a resource-returning function — the full suite (7755/7756) missed this; `/code-review medium` with gdb found it ([moving a diagnostic later can remove an early bailout](../learnings/1791620162751-moving-a-slang-diagnostic-later-in-linkandoptimize.md)).

Conversely, a late IR backstop sees only what survives optimization. With `-disable-non-essential-validations`, the front-end `checkAutoDiffUsages` (`slang-lower-to-ir.cpp` ~:15673) is skipped, leaving E38037 to `diagnoseDifferentiatingBackwardDiffResult` (`slang-ir-autodiff.cpp:186`, in `specializeModule`). An unused `__apply(f)(x)` lowers to a pure `BackwardDifferentiatePrimal(f)` call that `simplifyIR` (`slang-emit.cpp:1492`) deletes before `checkAutodiffPatterns` (:1525) sees it, so it compiles silently (#13560); a dead `bwd_diff(f)(a, 1.0)` (inout write), a used result, or a side-effecting `f` are still diagnosed. Test an IR backstop with dead and pure forms, and capture `rc=$?` right after the command — a later `echo "$(...)"` reports the substitution's status ([E38037 IR backstop is optimization-sensitive](../learnings/1791594358621-slang-e38037-ir-backstop-is-optimization-sensitive.md)).

## A Guard on One Emit Pass Doesn't Close a Bodyless-Decl Crash — Check Pass Order + Keyed Decoration (#12514)

#12514 fixes a bodyless `[TorchEntryPoint]` SIGSEGV on `-target torch` by guarding `generateCppBindingForFunc` with `if (!func->isDefinition())`. But the torch pass order is `generateHostFunctionsForAutoBindCuda` → `lowerBuiltinTypesForKernelEntryPoints` (`slang-emit.cpp:1525`) → `generatePyTorchCppBinding` (:1526, the guard). `lowerBuiltinTypesForKernelEntryPoints` collects functions by `IRCudaKernelDecoration` with no body check and derefs `func->getFirstBlock()->getParams()` (:1122), so a bodyless `[CudaKernel]` (with or without `[TorchEntryPoint]`) still crashes before the guard; `generateCppBindingForFunc` sees only an `IRTorchEntryPointDecoration` worklist, and `checkCudaKernelAttribute` requires no body. The control that upgraded "plausible from the trace" to "verified": a bodyless `[CudaKernel]`-only decl crashes on both `-target torch` and `-target cuda`, and `generatePyTorchCppBinding` is not in the cuda pass list, so the crash is in the shared earlier pass. The root-cause fix rejects bodyless kernel attrs in the semantic checker, closing every emit site. Two Devin claims to refute on this PR class: no repo rule requires a doc update for a new error (the diagnostics catalog is auto-generated, and sibling torch codes E55101/E55102/E55200 are listed UNCOVERED); and the torch siblings (`tests/autodiff/autopybind-*.slang`) use `//TEST:SIMPLE(filecheck=TORCH): -target torch` pinning `result code = -1`, so not using `DIAGNOSTIC_TEST` is a low nit ([Torch bodyless-decl crash: guard in generatePyTorchCppBinding misses the earlier lowerBuiltinTypes pass](../learnings/1786579470704-torch-bodyless-decl-crash-guard-in-generatepytorch.md)).
