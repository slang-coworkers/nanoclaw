# Slang Backends Spirv 4 Incidents

## TL;DR
- SPIR-V symptoms usually trace upstream (IR pass, core-module producer, downstream tool), not to emit. Verify the premise against real output: compile, disassemble, and cite primary spec text, not a summarizer.
- `-O0` runs zero spirv-opt passes, so it is a faithful "no spirv-opt" proxy. Slang self-legalizes via `legalizeIRForSPIRV`; spirv-opt only affects size/perf, not correctness.
- The slang-test `-O0` default (PR #11805) MASKS spirv-opt aborts; it does not fix them. Users at `-O1+` still hit them, and a suite-wide `-O3` revives them.
- To triage an opt-level failure list, compile at `-O3` with the test's real `-entry`/`-stage` on a Debug build. Exit 0 = benign FileCheck drift (fix the test); exit 134 = real abort (file it).
- A float result that is wrong at default opt, correct at `-O0` or `-fp-mode precise`, with `-dump-ir` unchanged ⇒ spirv-opt reassociation, gated on `NoContraction`. Default mode emitting no `NoContraction` is intentional (#11933). Advise `-fp-mode precise`; do not flip the default.
- An emit-side `SLANG_UNEXPECTED` that fires only under one `-capability` ⇒ check the `.meta.slang` producer arm for that capability. Fix producer-side with kind-dispatch, and harden the emit `default` to a diagnostic.
- An emitter's accept-set and any legalization guard mirroring it share ONE predicate. Enumerate op families via `*TypeBase` classes, never leaf-op lists.
- `DescriptorHandle<T>` is `uint2` on plain spirv/glsl and `uint64` under `spvBindlessTextureNV`/cuda. To make a representation depend on a new discriminator, audit every width consumer (including constant-emit and the sizeof peephole). A module-scope `OpBitcast` is invalid.
- When the second consumer guard for one defect still misses a case, stop and fix the producer. Plausibly reachable from user code ⇒ diagnostic; unreachable ⇒ assert plus a written justification.
- spirv-val silence proves nothing either way. Compile a reviewer's proposed alternative before agreeing with it.
- A diagnostic that renders a resource type name must run before `lowerBufferElementTypeToStorageType`. Capture the name early and defer the emit so dead code is not flagged.
- When relaxing a rejection predicate, enumerate the discriminator's full range.
- Source-text embedding is gated at two layers (IR-gen producer and emit consumer), and there are two `IRDebugSource` producers. Gate SPIR-V-only flags on the target. A bare `OpSource` and file-carrying `OpSource` records must be mutually exclusive.
- `DebugLine`/`OpLine` come only from statement-level `IRDebugLine` markers. A value-inst `sourceLoc` fix produces byte-identical SPIR-V and has no writable golden, so surface that to the maintainer.
- A copy of a non-copyable opaque value (`__constref ParameterBlock`, `RayQuery` return) is fixed in IR copy-elision, not AST lowering.
- `DescriptorHandle<RaytracingAccelerationStructure>` + `spvDescriptorHeapEXT` is supported from v2026.11, so a crash there is usually host-side. The EXT heap is driver-managed: write the descriptor, don't memcpy the address.
- In std140, `float4[2]` is byte-identical to a row-major `float2x4`, and matrix-layout mode never touches arrays. If a heap-fetched CB has arrays, suspect #11483 (fixed by #11647).
- A typed buffer-data pointer to an array element needs a pointer `ArrayStride` (StorageBuffer only). glslang's untyped-Uniform path is legal, but it would be a non-local rework in Slang.
- `UIntPtr` is an emit-layer gap: add the type-decl case. `IntPtr` also needs signedness-classifier fixes.
- `[require]`/bindless accessor selection, NoContraction/`precise`, NonUniform, and `spirv_asm` register renames: see [slang-backends-spirv-3-incidents](slang-backends-spirv-3-incidents.md).

## spirv-opt and the optimization level

**`-O0` is a faithful no-spirv-opt proxy.** `needsOptimization = getOptimizationLevel() != None` maps None → downstream None, and `glslang_optimizeSPIRV` early-returns. The always-on `legalizeIRForSPIRV` does not depend on `-O`. When studying what spirv-opt buys, state these caveats: binary size ≠ GPU runtime (the driver re-optimizes), the corpus must include large real shaders (the 50-70% size win doesn't show on tests/), and no size/perf harness exists ([-O0 is a faithful no-spirv-opt proxy](../learnings/1784653425624-o0-is-a-faithful-no-spirv-opt-proxy-spirv-opt-is-s.md)).

**The `-O0` default masks aborts.** Tests suppressed for aborting inside spirv-opt, such as fp8 #11766/#11767 at `folding_rules.cpp:156`, stop aborting once PR #11805 defaults slang-test to `-O0`. The suppression can be dropped without the upstream SPIRV-Tools fix, but users at `-O1+` still hit the upstream bug. GPU-free repro: a Debug slangc aborts with exit 134, and adding `-O0` exits 0. Release builds compile the assert out. Render-test creates the device and checks features BEFORE compiling, so a `(vk)` test compiles only where a Vulkan device (e.g. lavapipe) exists ([spirv-opt crash suppressions droppable via the -O0 default](../learnings/1783036168133-spirv-opt-crash-suppressed-via-expected-failure-li.md)). Suite-wide `-O3` (#12247) revives such asserts. A "resolved" #11805-era issue may just be dormant. Live sites: fp8/CoopVec constants hit `folding_rules.cpp:156/:3539` (the float folder rejects width 8), and `spirv_asm` `OpMemberDecorateIdEXT` hits ADCE `:1000 assert(false)`. A debug `assert()` bypasses the `messageConsumer`/`SLANG_FAIL` path. On Windows it shows up as "exit 3 / hang / lost JSON-RPC worker" in a sibling test, so verify each suspect standalone. About 77 of 79 failures were benign drift ([suite-wide -O3 revives dormant SPIRV-Tools asserts](../learnings/1785203893114-suite-wide-spirv-opt-o3-revives-dormant-spirv-tool.md)).

**Float reassociation is spirv-opt, not Slang IR (#12160).** `[ForceUnroll]` + default opt folded `(xmax - xmin)` into an inexact constant. The add/sub folding rules regroup `(a-b)-(b-k)` → `(a-b)+C`, and every such rule is gated on `IsFloatingPointFoldingAllowed()`, which honours `NoContraction`. A regression test pins the default-mode absence of `NoContraction` (`//DEFAULT-NOT: NoContraction`, #11933). Treat this as "default is more permissive than users expect". Send an advisory with the `-fp-mode precise` workaround and escalate the design question ([float reassociation = downstream spirv-opt](../learnings/1784504993349-slang-spir-v-float-reassociation-precision-bug-dow.md)). The `precise` qualifier and `NoContraction` emission (#11933, #12198) are covered on [slang-backends-spirv-3-incidents](slang-backends-spirv-3-incidents.md).

## spvBindlessTextureNV and DescriptorHandle width (#12185, #12186)

**Over-broad producer.** A non-image/sampler `DescriptorHandle<T>` under `-capability spvBindlessTextureNV` aborts with `Unsupported result type for CastDescriptorHandleToResource` (E99997). The `case spvBindlessTextureNV:` arm in `hlsl.meta.slang` forwards every kind to `__castDescriptorHandleToResource<T>`, while sibling arms switch on `T.kind`. The emit switch in `slang-emit-spirv.cpp` handles only texture/sampler. Fix it on the producer side and turn the emit `default` into a diagnostic ([spvBindlessTextureNV abort: producer over-broadcasts](../learnings/1784687930584-slang-12185-spvbindlesstexturenv-descriptorhandle-.md)). The follow-up guard mirrored the emit accept-set by hand and omitted `kIROp_SamplerComparisonStateType` (encodable via `OpConvertUToSamplerNV`), which turned an abort into a wrong diagnostic. Extract `isBindlessTextureNVEncodableResourceType(IRType*)`, which matches `kIROp_TextureType || as<IRSamplerStateTypeBase>` on unwrapped types, and use it at both sites ([accept-set + mirroring guard share ONE predicate](../learnings/1784697407327-emit-switch-accept-set-a-legalization-guard-that-m.md)).

**Representation is capability-dependent.** The handle is a scalar `%ulong` under `spvBindlessTextureNV`/cuda, so the AS cast must be `RaytracingAccelerationStructure((uint64_t)handle)`. A maintainer's proposed `__asuint64((uint2)handle)` failed spirv-val once swapped in and compiled, which is how to settle such a suggestion ([DescriptorHandle is uint64-native under spvBindlessTextureNV](../learnings/1784762549887-descriptorhandle-is-uint64-native-under-spvbindles.md)). Making width *kind-dependent* touched 8 consumer sites: type emit, default-construct legalization, both byte-address cast selectors, IR layout, the sizeof/alignof peephole, AST layout, and reflection. Grep every `implies(CapabilityAtom::X)`/`getUInt64Type`, and keep classification as one IR predicate plus a mirrored AST predicate. In a block, a `uint2`↔`uint64` cast needs a real `OpBitcast`, but a module-scope `OpBitcast` is invalid ("must appear in a block"), so materialize the constant from its bits. Compare in the native representation ([kind-dependent representation: audit ALL width consumers](../learnings/1784859574140-kind-dependent-spir-v-representation-change-audit-.md)).

**Four consumer guards ⇒ one producer hole.** Four emit-time guards each caught a different subset, and the fourth had to walk the operand graph to recover width. The root cause: the handle read-back conversions in `hlsl.meta.slang` (`extension uint2 { __init<T>(DescriptorHandle<T>) }` and the `uint64_t` sibling) are capability-gated but not kind-gated. That one hole showed up at module scope (`OpIAdd %ulong` on `%v2uint`), in a function-scope cast, and in descriptor-heap lowering (a scalar `OpCompositeExtract` that trips spirv-opt `const_folding_rules.cpp:129`). Escalate the public `.meta.slang` fix instead of writing a fifth guard. Both integer constructors are public, so user code can reach the shape: use a diagnostic, not an assert. The spec lesson from the same work: SPV_NV_bindless_texture accepts `uint2` OR `uint64` at `OpSamplerImageAddressingModeNV 64`. A caveated DeepWiki answer said otherwise and cost a public retraction. Read the primary spec, and do not treat spirv-val silence as evidence ([cite the spec; four guards ⇒ upstream hole](../learnings/1785776557998-cite-the-spec-not-a-summarizer-spv-nv-bindless-tex.md)).

**Diagnostic placement in legalize.** E55215 renders the resource type name only because it runs before `lowerBufferElementTypeToStorageType`, and at that point dead-after-`discard` code (an un-inlined `[ForceInline]` helper) still exists. Running the diagnostic after DCE prints `of type ''`. An `IRUnreachable` block skip doesn't help. Use reachability, or capture the type-name string early and defer the emit ([diagnostic placement: type-name vs dead-code](../learnings/1784747930488-diagnostic-pass-placement-tradeoff-type-name-rende.md)). Triaging #12191: the diagnosed function existed only on PR #12186's branch, so there was no master repro. Verify "peer" codes before generalizing (E55210 was unrelated) ([#12191 E55215 triage](../learnings/1784762307830-slang-12191-e55215-post-opkill-dead-code-diagnosti.md)).

**Relaxing a rejection predicate.** PR #12195 (`-fvk-use-direct-resource-params`) gated on "any texture NOT rejected by GLSL" instead of "read-only texture". That silently admitted FEEDBACK/UNKNOWN access and, through `unwrapArray`, texture arrays. Enumerate the discriminator's full range ([direct-resource-param gate leaks feedback/unknown/array](../learnings/1784772370437-spir-v-direct-resource-param-gate-relaxing-isilleg.md)).

## Debug info: source embedding and line markers

**Two layers (#12181).** In the producer (`slang-lower-to-ir.cpp:15425`), `-g0` creates no `IRDebugSource`, `-g1` creates one with empty content, and `-g2/-g3` embed the source; `DebugCompilationUnit` exists only at `>= Standard`. In the consumer (`slang-emit-spirv.cpp:2164`), `Minimal` emits the filename `OpString` and nothing more. A flag that embeds source at a lower `-g` level must therefore thread through both layers, and at `-g0` it also needs a minimal `DebugCompilationUnit` + `SPV_KHR_non_semantic_info`. Append the flag as `CompilerOptionName::DebugInfoIncludeSource` before `CountOf` ([source-text embedding gated at two layers](../learnings/1784666850986-slang-spir-v-source-text-embedding-is-gated-at-two.md)). PR #12202 exposed two more producer traps:
- There are TWO `IRDebugSource` producers: the per-file loop (~15428) and `getOrEmitDebugSource` (~9717). Updating only one yields an `OpSource` with a File operand and an EMPTY Source.
- The producer ternary is target-agnostic, so `-target llvm -g1 -debug-info-include-source` embeds source too. Gate it on SPIR-V or warn per target, as `-separate-debug-info` does.

([two IRDebugSource producers; target-agnostic ternary](../learnings/1784822669473-slang-debug-info-include-source-12181-12202-second.md)). A bare fileless `OpSource` emitted alongside file-carrying `OpSource` records makes SPIRV-Tools' extractor create a spurious `unnamed-0.hlsl`. spirv-val passes, so this is invisible without a consumer-side check. Emit the bare record only in the no-embed branch ([bare fileless OpSource → spurious 'unnamed' source](../learnings/1784851566899-slang-spir-v-emitting-a-bare-fileless-opsource-alo.md)).

**Line markers (#12192).** `-g2 DebugLine` and `-g1 OpLine` come only from `IRDebugLine` markers, which `lowerStmt`→`maybeEmitDebugLine` places at statement granularity. Value insts fall under the last marker. So propagating `sourceLoc` onto re-synthesized value insts (`IRBuilderSourceLocRAII`) gives byte-identical output at `-g1/-g2/-g3`. Only diagnostics that read `inst->sourceLoc`/`findFirstUseLoc` see those locations. If no diagnostic fires, the fix has no test: tell the maintainer, and confirm the edit is actually in `libslang-compiler.so` ([DebugLine is statement-marker driven](../learnings/1785275556385-slang-g2-debugline-is-statement-marker-driven-not-.md)).

## Descriptor heap: acceleration structures, std140, heap ConstantBuffer

**AS through `spvDescriptorHeapEXT`.** The path is supported and regression-tested from v2026.11 (`tests/spirv/descriptor-heap-acceleration-structure*.slang`). Keep two values apart: the handle `uint2` (`.x` = heap index) and the slot contents (an 8-byte device address, not the opaque handle). Diagnosis order:
1. grep `-target spirv-asm` output for `OpConvertUToAccelerationStructureKHR` (missing = old build);
2. run VK GPU-assisted validation;
3. if slot 0 works but slot ≥1 crashes, suspect an AS stride mismatch (`-spirv-resource-heap-stride`, #11231/#11494).

([diagnosing DescriptorHandle<RaytracingAccelerationStructure> crashes](../learnings/1785051051163-diagnosing-descriptorhandle-lt-raytracingaccelerat.md)). The EXT `ResourceHeapEXT` is driver-managed (slang-rhi uses `VK_DESCRIPTOR_TYPE_MUTABLE_EXT`). Fill the AS slot with `vkUpdateDescriptorSets` + `VkWriteDescriptorSetAccelerationStructureKHR`, not a raw memcpy. The raw uint64 model holds only for an app buffer (`RaytracingAccelerationStructure(myBuffer[i])`). Tell: the AS fails at index 0 with a correct `.x` while textures work ⇒ the host is memcpy'ing. Escape hatch: override `getDescriptorFromHandle` ([AS heap is driver-managed](../learnings/1785056296611-spvdescriptorheapext-as-heap-is-driver-managed-des.md)).

**"`float4[N]` reads garbage, `float2x4` works."** In std140, `float4[2]` (32 B) is byte-identical to a row-major `float2x4`; column-major is 64 B. Matrix-layout mode changes only matrices. Without heap involvement, suspect host packing and check `spirv-dis | grep -E "Offset|ArrayStride|MatrixStride"` ([std140: row-major float2x4 == float4[2]](../learnings/1785073305394-std140-row-major-float2x4-and-float4-2-are-byte-id.md)). With a descriptor heap it is #11483: a heap-fetched `ConstantBuffer<T>` becomes a `Uniform` `OpBufferPointerEXT`, and `getPointerArrayStrideValue` emits no stride for Uniform. #11647 fixed it by retyping to StorageBuffer, so tell users to update forward. The #12226 regression follows below. Workaround: fetch through `StructuredBuffer<T>` ([float4[N] garbage + descriptor heap = #11483](../learnings/1785073991889-discord-float4-n-in-struct-reads-garbage-matrix-wo.md)).

**Typed vs untyped data pointer (#12226).** Slang's `emitDescriptorHeapLoad` returns a TYPED `IRPtrType`, so access goes through `OpAccessChain`. A typed pointer to an array element needs a pointer `ArrayStride`, which only exists for StorageBuffer/PhysicalStorageBuffer. glslang instead uses an untyped Uniform pointer + `OpUntypedAccessChainKHR`. Two framing corrections:
- Slang already emits valid typed Uniform access for scalar/vector/matrix CB elements, so the problem is specific to array elements.
- `processConstantBufferDescriptorHeapLoad` flips EVERY struct to StorageBuffer, which is broader than needed.

The untyped path would need ~5-8 new untyped-aware consumers, i.e. an emitter-architecture extension. `-spirv-unified-descriptor-heap-stride` fixes the stride, not the descriptor kind ([heap CB typed-vs-untyped OpBufferPointerEXT](../learnings/1785256702253-slang-descriptor-heap-constantbuffer-typed-vs-unty.md)).

## Non-copyable opaque value copies

`__constref ParameterBlock<T>` (or any opaque type) gets temp-copied in `addArg`, because `tryGetAddress` returns Simple, not Ptr, for a global. `processGlobalParam` only handles `IRGlobalParam`, so the copy survives to emit and ICEs. This is the same family as #7455/#8002. Fix it in IR copy-elision; PR #8008's AST-lowering approach was rejected 3× ([#8002 constref ParameterBlock ICE: fix in IR copy-elision](../learnings/1784754145569-slang-8002-constref-parameterblock-opaque-ice-copi.md)). Returning `RayQuery<...>` by value miscompiles because the callee value-copies the handle into the return-dest, and a bare `b = a` fails the same way. It is the general non-copyable value-copy defect. Disassembling the output refuted a confident source-only hypothesis ([RayQuery return-by-value = opaque value-copy](../learnings/1784785541306-rayquery-return-by-value-miscompile-opaque-value-c.md)).

## UIntPtr/IntPtr scalar emit (#8480)

"Unhandled global inst: UIntPtr" is a genuine emit-layer gap and an exception to the "unhandled inst ⇒ producer bug" heuristic. Pointer-sized integers get their width only at emit (`getPointerSize(targetReq)*8`), and no pass lowers them. The constant path already grouped `PtrType`+`UIntPtrType`, so only the type-decl switch in `emitGlobalInst` lacked `case kIROp_UIntPtrType:`. The existing body works as-is. `IntPtr` is not symmetric: `isSignedType` omits it, which trips `getUnsignedTypeFromSignedType`'s assert, and the value path emits a 32-bit constant under a 64-bit type. It needs `isSignedType(IntPtr)=true`, a `getUnsignedTypeFromSignedType` case, and a value-path arm ([UIntPtr/IntPtr: type-decl gap + signedness inconsistency](../learnings/1790007665223-spir-v-uintptr-intptr-scalar-emit-type-decl-gap-si.md)).
