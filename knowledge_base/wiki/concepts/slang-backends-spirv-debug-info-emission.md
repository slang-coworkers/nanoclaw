# Slang SPIR-V debug info: -g levels, DebugSource/DebugLine, debug types, debug variables, and OpName

Producer and consumer rules for SPIR-V debug information: what each `-g` level emits, where `DebugSource`/`DebugLine`/`DebugScope` come from, debug-type records, debug variables, and debug names. The `DebugFunction`/`DebugFunctionDefinition` layer has its own page, [[wiki/concepts/slang-backends-spirv-debug-function-info.md]].

## TL;DR

- SPIR-V debug-info defects are almost always producer-side (lowering, IR type gates); the emitter is innocent except for debug type records, which it builds itself.
- `-g0` emits exactly `OpSource`, `OpName` and `OpMemberName` by design (SPIR-V only; documented in help text). Check whether a "g0 still emits X" is a direct `emitInst` or a surviving decoration.
- Source-text embedding is gated at two layers (IR-gen producer, emit consumer) and has two `IRDebugSource` producers; update both, and gate SPIR-V-only flags on the target. A bare fileless `OpSource` beside file-carrying ones yields a spurious `unnamed-0` source.
- `-g1 OpLine` / `-g2 DebugLine` come only from statement-level `IRDebugLine` markers, so a value-inst `sourceLoc` fix changes the SPIR-V by zero bytes and has no writable golden test.
- `-g2` embeds the whole source, CHECK lines included, as an `OpString`: anchor patterns on `%id = OpString "name"` and on real instruction lines, or they self-match.
- A hoistable IR inst dedups only if every producer builds byte-identical operands; path strings are the classic divergence (#11982).
- `linkIR` keeps the `DebugSource`+CU of every imported module, used or not (#13982). Ownership must come from the producer (CU operands list the TU's `#include`d sources), because lazy foreign `DebugSource`s carry the owner's operands; reachability and `isIncludedFile` are not ownership tests.
- `IRDebugScope` is variable-arity (1 or 2 operands); never build it with a null operand.
- A matrix's debug type is layout-independent: `OpTypeMatrix` is the same for all layouts, and packing rides the member decoration plus `MatrixStride`.
- Opaque-handle locals: the emitter already handles them; admit them at the leaf/creation type gates with a narrow texture/sampler predicate, never inside recursive `isDebuggableType`, and cover both `let` and `var`.
- DebugVar type-eligibility and DebugValue value-representability are separate checks. DebugVar `ArgNumber` remapping across param-removing passes is cross-cutting: flag it to the maintainer.
- A decoration naming a function-local inst (#13872 `DebugVarStorage`) breaks where params move or are cloned: exclude entry points (varying legalization moves their params to globals), return `LegalVal()` in legalize-types, and remap with `findCloneForOperand` after params-first cloners (`specializeGenericWithSetArgs`, autodiff). A clean `-g2` suite sweep does not prove every cloner is covered.
- At `-g2 -O0` each local gets a `_dbgvar_*` shadow (`OpStore` + `OpDebugValue`); at `-O1` spirv-opt ADCE duplicates the DebugValues and deletes store-only shadows with their `DebugDeclare`. The `-O` difference is spirv-opt, not Slang IR; a `DebugDeclare` on real storage survives.
- Every named `%id` register in a `spirv_asm` block gets an `OpName`; stdlib registers are `__`-prefixed, renamed only inside brace-tracked `spirv_asm{}` ranges. Settle "debug name on the wrong inst" claims with a rename drill.
- spirv-opt's strip-debug passes delete `DebugBuildIdentifier`, so `-separate-debug-info` needs a Slang shim that keeps it.
- The `DebugEntryPoint` command-line string hardcodes `-g2` and silently drops un-cased options.
- NonSemantic debug info is not validated by spirv-val; these defects ship at rc=0.

## Debug levels and source embedding

**`-g0` (DebugInfoLevel::None) emits exactly `OpSource`, `OpName` and `OpMemberName`.** `OpSource` is a direct, unconditional `emitInst`; the names come from `IRNameHintDecoration`, which `stripDebugInfo` keeps because it removes only `IRDebug*` insts. `OpLine` and the `DebugSource` `OpString` are g1+, and `OpModuleProcessed` is never emitted. This is SPIR-V-specific (DXIL/HLSL/Metal `-g0` emits nothing) and documented in help text (#11682/#12201); for "g0 still emits X", check whether X is a direct `emitInst` or a surviving decoration ([-g0 doesn't zero debug info](../learnings/1782145409789-slang-g0-doesn-t-zero-spir-v-debug-info-opsource-o.md), [-g0 emits EXACTLY these three](../learnings/1784828289031-g0-debuginfolevel-none-emits-exactly-opsource-opna.md)).

**Source-text embedding is gated at two layers (#12181, PR #12202).** The producer (`slang-lower-to-ir.cpp:15425`) creates no `IRDebugSource` at `-g0`, an empty-content one at `-g1`, and embeds the source at `-g2/-g3`; `DebugCompilationUnit` exists only at `>= Standard`. The consumer (`slang-emit-spirv.cpp:2164`) emits only the filename `OpString` at `Minimal`. A flag that embeds source at a lower level (`CompilerOptionName::DebugInfoIncludeSource`, appended before `CountOf`) must thread both layers, and at `-g0` also needs a minimal CU plus `SPV_KHR_non_semantic_info` ([source-text embedding gated at two layers](../learnings/1784666850986-slang-spir-v-source-text-embedding-is-gated-at-two.md)). There are two `IRDebugSource` producers, the per-file loop (~15428) and `getOrEmitDebugSource` (~9717); updating only one yields an `OpSource` with a File operand and an empty Source. The producer ternary is target-agnostic (`-target llvm -g1 -debug-info-include-source` embeds too), so gate the flag on SPIR-V or warn per target, as `-separate-debug-info` does ([two IRDebugSource producers; target-agnostic ternary](../learnings/1784822669473-slang-debug-info-include-source-12181-12202-second.md)). A bare fileless `OpSource` next to file-carrying ones makes SPIRV-Tools' extractor create a spurious `unnamed-0.hlsl` while spirv-val passes, so emit the bare record only in the no-embed branch ([bare fileless OpSource → spurious 'unnamed' source](../learnings/1784851566899-slang-spir-v-emitting-a-bare-fileless-opsource-alo.md)).

**Line markers come from statements (#12192).** `-g2 DebugLine` and `-g1 OpLine` come only from `IRDebugLine` markers, which `lowerStmt`→`maybeEmitDebugLine` places per statement; value insts fall under the last marker. Propagating `sourceLoc` onto re-synthesized value insts (`IRBuilderSourceLocRAII`) leaves `-g1/-g2/-g3` output byte-identical; only diagnostics reading `inst->sourceLoc`/`findFirstUseLoc` see it, so with no such diagnostic the fix has no test. Tell the maintainer, and confirm the edit is in `libslang-compiler.so` ([DebugLine is statement-marker driven](../learnings/1785275556385-slang-g2-debugline-is-statement-marker-driven-not-.md)).

**`-g2` FileCheck self-match.** The embedded source contains the CHECK directives, so a bare-word `CHECK-NOT` fails on itself. Anchor on `%id = OpString "name"` (closing quote right after the name), and bind `DebugValue`→`DebugLocalVariable` through a captured id ([embedded-source self-match trap](../learnings/1781176200581-slang-g2-spirv-asm-filecheck-tests-embedded-source.md)).

## Producers of DebugSource, DebugFunction and DebugScope

**Constructors.** Synthesized `$init` ctors (#11550) lower like user functions, so they get `DebugFunction`/`DebugScope`. Suppressing only the scope leaves body `DebugLine`s and invalid NonSemantic SPIR-V, so gate on AST flavor (`SynthesizedDefault | SynthesizedMemberInit`) in lowering ([synthesized $init ctors](../learnings/1781168370965-slang-synthesized-init-ctors-get-full-source-level.md)). A user `__init`'s `this` (#11565) is a synthesized local, not an `IRParam`: after `thisVar` is emitted (`slang-lower-to-ir.cpp:13839`), add a "this" name hint and an `IRDebugLocationDecoration` ([__init lacks `this`](../learnings/1781206942083-slang-user-defined-init-lacks-this-in-spir-v-debug.md)).

**Name hints.** `ExtensionDecl` is anonymous, so `getNameForNameHint` redirects through the extended type's decl. Name hints also become C-like emitter identifiers (HLSL/CUDA) ([getNameForNameHint](../learnings/1781267563910-getnamefornamehint-feeds-c-like-emitter-identifier.md)).

**`IRDebugScope` arity.** It takes 1 operand when `inlinedAt` is absent and 2 otherwise; a null operand crashes `buildEntryPointReferenceGraph` (`slang-ir-call-graph.cpp:~85`) ([DebugScope variable-arity](../learnings/1781568128097-spir-v-debugscope-must-be-variable-arity-null-ir-o.md)).

**`-g2` + `import`/`#line` (#11982/#11983/#11984, distinct bugs)** are all producer-side in `slang-lower-to-ir.cpp` (the consumer ~:2136 is innocent); `-dump-ir`, not DeepWiki, settles whether dedup happens. (1) An imported function's DebugFunction scope is carried in IR (`IRDebugFunction` `parentScope`, operand 5) and resolves to its own module's CU; see [[wiki/concepts/slang-backends-spirv-debug-function-info.md]]. (2) A duplicate `DebugSource` for one file comes from two producers spelling the path differently (`getMostUniqueIdentity()` relative vs `getName()` absolute), which defeats `hoistable=true` dedup ([#11982](../learnings/1783466061131-slang-11982-duplicate-spir-v-debugsource-from-dive.md)). (3) A BOM in a `#line` file's `DebugSource` comes from the fresh-read fallback `getOrEmitDebugSource` bypassing `SourceFile::setContents`'s BOM strip; decode in the fallback ([#11984](../learnings/1783468265984-slang-11984-g2-debugsource-for-line-files-bypasses.md)).

**Which modules' `DebugSource` and CU survive linking (#13982, PR #13992).** At `-g2`/`-g3`, an imported module that contributes nothing (or only an inlined `static const`) still emits a full-text `DebugSource` and an unreferenced `DebugCompilationUnit`. `linkIR` (`slang-ir-link.cpp:2356-2395`) clones every global `DebugSource`/`DebugBuildIdentifier`/`DebugCompilationUnit` of every user module unconditionally, deliberately since PR #7203 ("list all source files … regardless of line table"); DCE keeps them (`mightHaveSideEffects` defaults to true) and the emitter (`:12538`) `ensureInst`s them all. `-separate-debug-info` does not make the stripped `.spv` byte-identical (the DBI hash and result ids shift). Check by counting references to each `DebugSource`/CU id in `-target spirv-asm` output [linker keeps DebugSource+CU of every imported module](../learnings/1793210647818-slang-spir-v-g-linker-keeps-debugsource-cu-of-ever.md).

Reachability is not ownership, so "clone every module the linked code reaches" is not a fix: `getOrEmitDebugSource` lazily creates in module M a `DebugSource` for any location M names, including other modules' files, with the owner's operands on purpose (hoistable dedup, PR #12034), and a foreign record for another module's `#include`d header even has `isIncludedFile=true`. The fix records ownership at the producer: `generateIRForTranslationUnit` gives each `DebugCompilationUnit` the TU's `#include`d DebugSources as variadic operands, the linker clones a used module's CUs (bringing its full file list, code-less headers included per #7203) and clones foreign records only by reference. The emitter reads only `getSource()`, so the extra operands are inert (`IROpInfo::fixedArgCount` has no readers), but the IR meaning change needs a module-version bump (legacy-path test and gate drill: [[wiki/concepts/slang-compiler-serialization-and-enums.md]]). SPIR-V-only work configures `-DSLANG_ENABLE_DXIL=OFF` (FetchDXC builds DXC from source here, GLIBC 2.36) [a module's DebugSource list includes lazy foreign records; ownership needs the producer](../learnings/1793220067281-slang-linker-a-module-s-debugsource-list-includes-.md).

## Debug type records

The emitter builds these records itself, so it is their producer.

**`DebugTypeMatrix` for a col-major constant-buffer member (#12757)** emits `(vec2, 3, false)` instead of `(vec3, 2, true)`. The emit site (`slang-emit-spirv.cpp:11108-11138`) keys off the source `getLayout()` and `normalizeMatrixDebugType` (:10899) returns early for buffer types, so only these members are wrong. The fix is the layout-independent `(vec(getColumnCount()), getRowCount(), true)`; packing stays on the member decoration (:7054-7078, Slang's naming reversed relative to SPIR-V). PR #9708 (Fixes #9325, by the reporter) made it deliberate, so get sign-off, update `tests/spirv/debug-matrix-layout.slang` (lines 54/63) and re-check `debug-matrix-layout-non-buffer.slang`. Repro: `-target spirv-asm -g2` ([DebugTypeMatrix keys off source layout](../learnings/1787695833712-spir-v-debugtypematrix-keys-off-source-matrix-layo.md)).

**Opaque `DebugTypeComposite` (#12807).** The fallback (`:11241-11255`) emits `Size` as integer 0 where it should be `DebugInfoNone` (ext-inst op 0, from a cached `getDebugInfoNone()` that mirrors `getDwarfExpr()` at :10552-10563), and reuses `name` as the LinkageName (:11252). The requested `"@Texture2D"` is a literal `"@"+Name`, not IR mangling (`getMangledTypeName` gives `_ST…`): check a helper's output against the expected text. The struct branch (:11069/:11075) has the same LinkageName defect; fixing it there is the maintainer's call ([`"@"+Name` is not IR mangling](../learnings/1787878146168-spir-v-debug-composite-issue-requested-name-linkag.md)).

## Debug variables for opaque handles (#12918, PR #12919)

Opaque resource/sampler locals get no debug info because of two upstream type gates: `isDebuggableType` (`slang-ir-insert-debug-value-store.cpp` ~L22-104, true by default only for `IRBasicType`, run before `constructSSA`) and spirv-legalize's `isSimpleDataType` strip (`slang-ir-util.cpp:356`). The emitter is already correct (`emitDebugVarDeclaration`, `slang-emit-spirv.cpp:4676`, emits `OpDebugLocalVariable`, skips `OpDebugDeclare` without a backing var, binds through `OpDebugValue`). Fix rules:
- Admit texture/sampler leaves with a narrow predicate (not `isResourceType`, which unwraps arrays and matches buffers) at the leaf/creation sites, never inside recursive `isDebuggableType`: `isAllowedDebugVarType` accepts structs, so a struct holding a handle would become an illegal Function `OpVariable`.
- `processDebugVar`'s strip is dead code here, because `emitDebugVar` (`slang-ir.cpp:3614/3619`) always builds a pointer-typed DebugVar; relax `processDebugValue` instead.
- `let x = t;` creates no `IRVar` (its debug info comes from the LetDecl case in `visitVarDecl`), so test both `let` and `var`.
- Type eligibility and value representability are separate checks: drop combined texture-sampler DebugValues (`isCombined()` → `OpTypeSampledImage`, not a legal operand) but keep arrays (`InputPatch`/`OutputPatch` are legal, `tests/spirv/tessellation`).
- `cleanUpVoidType`'s `argIndexRemap` uses all-params positions while earlier legalization strips empty params unremapped, so advancing per param breaks `debug-var-void-argument.slang`; ArgNumber remapping is cross-cutting, so flag it to the maintainer.

Sources: [root cause = two type gates](../learnings/1788744414687-slang-spir-v-opaque-resource-sampler-function-loca.md), [leaf/creation gates, let-path, dead processDebugVar](../learnings/1788748635093-slang-spir-v-opaque-handle-local-debug-info-fix-at.md), [value-operand limits & ArgNumber remap](../learnings/1789468940215-slang-spir-v-debug-var-value-operand-limits-param-.md).

## Debug variables across `-O` levels: `_dbgvar_` shadows and spirv-opt ADCE (#13841, #13842)

The `-O0`/`-O1` difference comes from spirv-opt, not a Slang IR pass: the emitter never checks the `-O` level, the IR dumps are identical, and spirv-opt runs only at `-O1`+ (slang-emit.cpp:3608) [`_dbgvar_` helper vars: -O0 duplicates real storage, -O1 loses DebugDeclare](../learnings/1792627978559-spir-v-g2-dbgvar-helper-vars-o0-duplicates-real-st.md). For a scalar local updated three times under `-g2`:

- **`-O0`:** every eligible local gets a `DebugDeclare` on a `_dbgvar_*` shadow `OpVariable` (`slang-emit-spirv.cpp:4781`) and each update emits an `OpDebugValue` plus an `OpStore` into it (`:11148-11185`), so a local with real storage is described twice.
- **`-O1`:** ADCE (`aggressive_dead_code_elim_pass.cpp` ~310, `AddDebugValueForVariable`) finds the shadow's storage dead and converts each whole-variable `OpStore` into another `DebugValue`, so 3 updates end as 6 (`spirv-opt --eliminate-dead-code-aggressive` on the `-O0` module reproduces it). `-O2`/`-O3` show no duplicates, and struct members are spared because their stores go through access chains.
- **Dynamically indexed updates** (`arr[tid] = v`) get no DebugValue (`translateIRAccessChain` rejects a non-constant index), so the shadow is store-only and ADCE deletes it with its `DebugDeclare`, leaving only a `DebugLocalVariable`. The same hits any local that keeps real storage, e.g. a struct or float passed `inout` to a `[noinline]` function.
- **A `DebugDeclare` on the real local storage survives** Slang's `-O1` pass list. Verify by pointing the `-O0` asm's `DebugDeclare` at the real var and running `spirv-as`, the `slang-glslang.cpp` pass list (or `spirv-opt -O`) and `spirv-dis` from `build/external/spirv-tools/tools/Debug/`.

spirv-val accepts all of these forms, so check by counting `DebugValue %var` per `DebugLocalVariable` [spirv-opt ADCE duplicates Slang's DebugValue](../learnings/1792627232349-spir-v-debug-vars-spirv-opt-adce-duplicates-slang-.md). A fix that points `DebugDeclare` at real storage matches on the original `IRVar` (its DebugLocation decoration), never the name, because `eliminatePhis` temporaries carry only a name hint (one `%i` served two loop `i`s); treats pointer-typed `inout`/`out` params as real storage; and links with a decoration on the `IRVar`, since a DebugVar operand is a non-load/store use that blocks `isPromotableVar` (slang-ir-ssa.cpp:513). "file too short" on a shared `build/Release`'s `libslang-compiler.so` means a sibling is relinking it: wait rather than fall back to a stale `build/Debug` [`_dbgvar_` helper vars](../learnings/1792627978559-spir-v-g2-dbgvar-helper-vars-o0-duplicates-real-st.md).

## The `DebugVarStorage` decoration and the passes that move or clone it (PR #13872)

PR #13872 (#13841) puts `[DebugVarStorage(%debugVar)]` on each `IRVar` and pointer-typed `out`/`inout` param. Unlike a DebugVar operand, a decoration does not block `isPromotableVar` and dies with the var under SSA promotion, so a surviving decoration proves the storage survived [decoration on an entry-point param migrates to globals](../learnings/1792688008753-slang-ir-a-decoration-on-an-entry-point-param-migr.md). A decoration that names a function-local inst breaks wherever params are moved or cloned:

- **Varying legalization moves entry-point params to globals.** `packStageInParameters` (slang-ir-legalize-varying-params.cpp, Metal/WGSL) and `lowerOutParameters` replace them and transfer their decorations, so the DebugVar dangles at global scope and `-validate-ir` fails. Exclude entry points at the producer (`func->findDecoration<IREntryPointDecoration>()`).
- **legalize-types legalizes decoration operands** through `legalizeInst`. An operand that legalizes to `none` (a zero-length array's DebugVar) hits `SLANG_UNEXPECTED("non-simple operand(s)!")`; add `case kIROp_<YourDecoration>: return LegalVal();` to the args switch [same](../learnings/1792688008753-slang-ir-a-decoration-on-an-entry-point-param-migr.md).
- **Params-first cloners leave the decoration naming the original function's inst.** `slang-ir-clone.cpp` clones a block's children before its decorations, so same-block references resolve; a cloner that clones params before the body gets the old operand back from `findCloneForOperand` (the behaviour that shares an `IRDebugFunction` on [[wiki/concepts/slang-backends-spirv-debug-function-info.md]]). Known producers: `specializeGenericWithSetArgs` (slang-ir-specialize.cpp ~3924, dynamic-dispatch generics); forward-mode autodiff (`translateFuncParam` clones params first, so remap through `cloneEnv.mapOldValToNew` after `translateFunc` and `generateTrivialFwdDiffFunc` [Vulkan COMPARE_COMPUTE tests compile at -g2](../learnings/1792702942408-slang-vulkan-compare-compute-tests-compile-at-g2-a.md)); and reverse mode's `splitApplyAndPropFuncs` and remat param-block clone (slang-ir-autodiff-unzip.cpp). Example: `void acc<T:IFoo>(T o, inout float a)` called with an existential at `-target spirv -g2` names the generic's DebugVar and trips `SLANG_RELEASE_ASSERT` at slang-emit-spirv.cpp:4845. The fix remaps each decoration operand with `findCloneForOperand(env, op)` after the clone and drops the decoration when no clone exists [params-first cloning leaves decorations naming the original insts](../learnings/1792708991560-cloning-a-function-s-params-before-its-first-block.md) [a decoration on a param that names a body inst goes stale](../learnings/1792712281969-slang-ir-a-decoration-on-a-param-that-names-a-body.md).
- **Auditing:** parse each pass section of `slangc -dump-ir` for `[DebugVarStorage(%x)]` against `%x = DebugVar(...)` (owning func, pointer and pointee types), and sweep `tests/**/*.slang` at `-g2` (also `-O0` and `-validate-ir-detailed`) with `xargs -P48`, about 2 minutes for 5310 files [same](../learnings/1792708991560-cloning-a-function-s-params-before-its-first-block.md). That sweep never hit dynamic dispatch, so suite coverage proves nothing about cloners; keep a consumer fallback with `-validate-ir` as the loud check rather than a release assert (general rule: [[wiki/concepts/slang-compiler-crash-and-legalization-probes.md]]) [same](../learnings/1792712281969-slang-ir-a-decoration-on-a-param-that-names-a-body.md). In-param proxy vars (`IRInParamProxyVarDecoration`) are a separate storage case that DebugVar/DebugDeclare changes tend to miss [coverage drill](../learnings/1792692531156-coverage-drill-log-each-defensive-branch-to-a-file.md).

Stable IR ids collide among drafts (three claimed 910 on 2026-10-22): check open PRs touching `slang-ir-insts-stable-names.lua` first and take the next free id after a rebase [same](../learnings/1792688008753-slang-ir-a-decoration-on-an-entry-point-param-migr.md).

## OpName and `spirv_asm` register names (#12002, #12108)

The emitter emits an `OpName` for every named `%id` register in a `spirv_asm` block regardless of debug level (the `idMap` loop in `slang-emit-spirv.cpp`). In #12002 a "misattributed OpName" was a stdlib register collision: the texture-sample intrinsics in `hlsl.meta.slang` named their raw-sample register `%sampled`, so every sample emitted `OpName ... "sampled"` whatever the caller's variable was called (a user call-result gets no `OpName`; it skips `maybeEmitName`). The defect is cosmetic; `slangc -target spirv-asm | grep OpName` reproduces it ([spirv_asm named registers leak into OpName; %sampled](../learnings/1783525064110-slang-12002-spirv-asm-named-registers-leak-into-op.md)). PR #12053 renamed the register to `%__sampled` at 94 sites and added a `CHECK-NOT: "sampled"` test. A rename drill decides such claims (an OpName that follows the renamed user variable is propagation; one that stays is intrinsic-baked); lead a public verdict with the refutation, then the real defect. Gating the auto-OpName loop is maintainer scope, because it is a documented, tested feature (`tests/language-feature/spirv-asm/opname.slang`) and plain user OpNames are ungated too ([#12002 refute-then-fix](../learnings/1783746988745-slang-12002-shipped-refute-then-fix-triage-of-a-mi.md)).

The #12108 generalization covers `hlsl.meta.slang` and `glsl.meta.slang` (53 un-prefixed sites) plus a build assert; it is maintainer-driven, so re-pin stale line numbers and stand down ([#12108 scope spans hlsl AND glsl](../learnings/1784248363961-slang-12108-triage-spirv-asm-prefix-cleanup-scope-.md)). A file-wide sed is unsafe because the same `%result`/`%6` tokens live in `__intrinsic_asm` LLVM/Metal strings: rename only inside brace-tracked `spirv_asm{}` ranges, skipping `$name`, integer ids and already-prefixed names. `slang-core-module-textures.cpp` (`writeGetDimensionFunctions`) is a second generator ([renaming spirv_asm registers: block-scoped only](../learnings/1784760040459-renaming-spirv-asm-registers-in-meta-slang-block-s.md)).

## Stripping and the DebugEntryPoint string

**`-separate-debug-info` needs a `DebugBuildIdentifier` shim (#8681).** `stripDbgSpirvFromArtifact`, the splitter, hand-rolls the strip to keep the DBI ext-inst, the hash linking the stripped module to its `.dbg.spv`. Both `CreateStripDebugInfoPass` and `CreateStripNonSemanticInfoPass` delete the DBI unconditionally, so the correct shape is a hybrid: spirv-opt owns the bulk strip and a thin Slang shim exempts or re-injects the DBI, its OpString and the NonSemantic import ([spirv-opt strip-debug deletes DebugBuildIdentifier — separate-debug-info needs a DBI shim](../learnings/1783556986544-slang-8681-spirv-opt-strip-debug-deletes-debugbuil.md)).

**`DebugEntryPoint` command-line string (#12220)** has two independent bugs. `getDebugInfoCommandLineArgumentForEntryPoint` ends with a literal `sb << " -g2"` that ignores the requested level (an unused `getDebugInfoLevel()` accessor exists), and `writeCommandLineArgs` is a `switch(option.key)` with no `default`, silently dropping un-cased options (`-lang`/`-profile`/`-gdwarf`/`-line-directive-mode` vanish while `-O0`/`-matrix-layout` survive). The string is stored verbatim (`strings x.spv | grep -- '-target spirv'`). `writeCommandLineArgs` also feeds the CPU/LLVM emit path but not the module-cache `buildHash` ([SPIR-V DebugEntryPoint command-line string: two roots (hardcoded -g2 + no-default serializer switch)](../learnings/1784915879616-spir-v-debugentrypoint-command-line-string-two-roo.md)).
