# Slang test authoring: FileCheck efficacy, ignored targets, and confounded lanes

## TL;DR

The theme is **test efficacy**: a locally green test (Linux, no DXC/Metal) often proves nothing, because its target is ignored, an independent flag produces the signal, or a `-NOT` sits on a target the code never runs on.

- **`slang-test` exits 0 when nothing matched** (filter typo, positional path arg, `-test-dir` plus a trailing filter). Gate on `[0-9]+% of tests passed (n/m)` appearing.
- **The failure marker is `FAILED test:` (uppercase)**; `grep -c '^failed test:'` reports 0 failures on a failing log.
- **A `-target hlsl` or `-mtl` subtest is "ignored" (0/0) without DXC/Metal**, and any `filecheck=` test is ignored without the FileCheck binary. That target is untested locally.
- **A cross-target `COMPARE_COMPUTE` listing `-mtl` must not use `double`**. Split F64 coverage into a no-Metal file.
- **CUDA diagnostic tests use `-target cuda`, not `-target ptx`**: ptx needs nvrtc (absent on CPU CI). A ptx `DIAGNOSTIC_TEST` still runs there (only `TEST:SIMPLE` is ignored), so check a no-backend CI log before calling it skipped.
- **A `-NOT` on a target the code under test never runs on is a tautology.** Put positive assertions on the target the pass runs on.
- **A target-path flag can mask a behavioral lane** (`-target ptx` adds NVRTC `--use_fast_math`). Remove every other cause of the signal.
- **Lifting a per-target emit predicate to the base class affects every sibling subclass.** Enumerate the concrete emitters first.
- **Retarget a stale emit test on the invariant, not the new spelling.** Capture names with `[[P:[A-Za-z_0-9]+]]`; don't pin incidental details that can flip.
- **A `__target_switch` arm nested under a non-implied capability is dead code.**
- **A textual `//CHECK: .GetX` ABI test proves only that Slang emits the call**, not that the target API has the member.
- **`non-exhaustive` is two-sided:** rejected when every diagnostic is annotated, required when an incidental extra (a profile-upgrade `warning[E41012]`) fires.
- **Never name a custom `filecheck=` prefix with a reserved suffix** (`-EMPTY`/`-NEXT`/`-SAME`/`-NOT`/`-DAG`/`-LABEL`/`-COUNT`); use `CHECK-ZERO`. A FileCheck variable named like another prefix becomes that lane's directive; name it `FN`.
- **`filecheck=CHECK,WGSL` activates only `CHECK`** (commas inside `(...)` separate options, #13359). Use one prefix per `//TEST` directive; a repeated key (`filecheck=A,filecheck=B`) crashes slang-test.
- **A lone `CHECK: 0` over a multi-slot buffer matches any unwritten zero, and `CHECK: 3` matches the `3` in `type: int32_t`.** Pin `CHECK: type: int32_t` then `CHECK-NEXT: {{^}}N{{$}}` per value, and mutation-check it.
- **Since #14269 (2026-11-04) SIMPLE+FileCheck fails a non-zero compiler exit unless the lane says `exit-code=N`** (`exit-code=-1` for an intended error). `diag=` lanes still ignore it (#14266).
- **A CHECK-DAG line that matches early text shrinks a CHECK-NOT placed before the DAG group.** Pin a code with a plain `PREFIX: [E30015]` ahead of the NOT; pin bare `[Exxxxx]` under SGR color.
- **Don't pin incidental output that is another open PR's bug.** Split a signature CHECK into `CHECK: void f(` plus one `CHECK-SAME:` per param.
- **`COMPARE_COMPUTE(-shaderobj)` loads the file as a module**, so a `sourceLanguage==HLSL` gate never fires (E30019). Value-check with a direct-compile `SIMPLE(filecheck=...):-target hlsl`. COMPARE_COMPUTE also rejects `-entry`/`-stage`.

## The slang-test harness: five instrument traps

Five traps from slang#12442 / PR #12465 [the five traps](../learnings/1786405416356-slang-test-harness-instrument-traps-failed-vs-fail.md). (1) The failure marker is `FAILED test:` (uppercase), the pass marker lowercase `passed test:`, so `grep -c '^failed test:'` reported 0 failures on a log with 4. `failed(pending retry)` is a retry, not a verdict; `failed(expected) test:` is a suppression match. Each `//TEST` directive is a cell (plus synthesized `... syn (cuda)` cells); quote the cell name. (2) `slang-test` exits 0 when nothing matched. A positional path arg is only a prefix filter (enumeration comes from `-test-dir`, default `tests/`), so `slang-test docs/generated/tests/<path>` runs nothing, as does `-test-dir` plus a trailing filter. Gate every run on `[0-9]+% of tests passed \([0-9]+/[1-9][0-9]*` appearing. (3) An ordering experiment needs `-explicit-test-order`. Subtests in one file run in order, so one `.slang` with `COMPARE_COMPUTE` then a `-target hlsl SIMPLE` directive can express an ordering dependency. (4) A red `workflow_dispatch` draft-PR check is usually a priority yield (`wait-for-human-priority: priority-gate-yielded`, GitHub conclusion `failure`); report it as "red by design; nothing was built", and count the job kinds before describing them. (5) The mutating and `--check-only` formatting paths use different file lists; a missing tool makes `--check-only` exit 1 with no formatting problem. Also: `git log --format=%B <sha>` without `-1` walks every ancestor, and `REQUIRED_BY` in `tools/render-test/CMakeLists.txt` is a broken way to depend on `slang-unit-test`; put `REQUIRES render-test` on the target and verify the edge with `ninja -t query` against a known-good positive control.

## Ignored targets: a locally green test that tested nothing

In the Linux sandbox (no DXC), `//TEST:SIMPLE(filecheck=CHECK):-target hlsl` reports **"ignored" (0/0)**, not pass or fail; a known-good sibling's hlsl variant is ignored too. Verify a parse- or compile-level fix locally as CPU compute (`//TEST(compute):COMPARE_COMPUTE(filecheck-buffer=CHECK):-cpu -output-using-type -shaderobj`) or `//TEST:INTERPRET` [bare -target hlsl SIMPLE ignored](../learnings/1787342748842-slang-test-bare-target-hlsl-simple-tests-are-ignor.md). The unit-test build target is `libslang-unit-test-tool.so`, and ninja aborts the whole multi-target build on one unknown target name.

Metal is the costliest case. A cross-target `COMPARE_COMPUTE` listing `-mtl` **must not contain `double` / `double2/3/4`**: Metal has no `double`, and emit correctly aborts (`error[E99997] ... unexpected: 'double' type emitted`), so the fix belongs in the test. The mtl subtest is ignored locally, so the file passes here while macOS CI fails [COMPARE_COMPUTE -mtl no double](../learnings/1787952374955-a-cross-target-compare-compute-test-that-targets-m.md). Verify device-free by emitting Metal (`slangc <test> -target metal -stage compute -entry <e> -o /tmp/out.metal`; exit 0 and `grep -c '\bdouble\b'` == 0) with a `git stash` must-fail control. Move `double` into its own `-cpu`/`-cuda`/`-vk` test; `float`, `int`, `uint`, and 64-bit ints are Metal-safe.

CUDA has the mirror rule: **diagnostic tests use `-target cuda`, not `-target ptx`.** `-target ptx` compiles through `nvrtc`, which CPU CI runners lack, so the compile aborts ("failed to load downstream compiler 'nvrtc'") before `checkUnsupportedInst`, and the expected diagnostic (E55215) never fires. `-target cuda` stops at CUDA source, still runs the pre-emit diagnostic pass, and needs no nvrtc (slang#12633 / PR #12671) [CUDA diagnostic tests use -target cuda](../learnings/1787351942939-cuda-diagnostic-tests-use-target-cuda-not-target-p.md). Prod containers ship CUDA 12.6 NVRTC and an L40S ([absent only in the 09-28→10-16 outage](../learnings/1792089571497-agent-containers-have-no-gpu-since-2026-09-28-host.md)). A `DIAGNOSTIC_TEST` is not skipped for a missing backend: `_extractSlangCTestRequirements` maps `-target ptx` to `PassThroughFlag::NVRTC`, which makes a `TEST:SIMPLE` lane ignored without nvrtc, yet on a macOS debug job the ptx `DIAGNOSTIC_TEST` `tests/diagnostics/command-line/x-arg-trailing-x.slang` passed (#13450). A ptx diagnostic that fires before the downstream load (command line, front end) is real CI coverage; one after it fails. Before calling a test "skipped", grep a no-backend job log (`gh run view --job <id> --log | sed 's/\x1b\[[0-9;]*m//g' | grep <file>`) for `passed test:` / `ignored test:` [DIAGNOSTIC_TEST -target ptx still runs without NVRTC](../learnings/1791410667785-diagnostic-test-with-target-ptx-still-runs-on-runn.md).

A third cause is independent of target and GPU: **any `filecheck=` test is ignored when the LLVM FileCheck binary is absent** (`slang-test-main.cpp:~842` returns `Ignored` when `getFileCheck()` is null), so a `//TEST:REFLECTION(filecheck=CHECK):-target spirv` subtest reports `ignored (0/0)`; REFLECTION tests against a `.expected` file still run. Verify by dumping reflection JSON (`slangc test.slang -target spirv -no-codegen -reflection-json out.json`), simulating the ordered CHECK / CHECK-LABEL matching yourself, and leaving the pass to CI (slang#13188 / PR #13189) [slang-test ignores spirv+filecheck reflection tests locally when FileCheck is absent](../learnings/1789941026991-slang-test-ignores-spirv-filecheck-reflection-test.md).

## Vacuous and confounded checks

A `-NOT` discriminates only if the code path under test can produce the forbidden token on that target. On slang#12718 / PR #12723, `// SPIRV-NOT: _slang_dummy` on a `-target spirv` lane could never fail: the fix is a D3D-only IR pass (`legalizeEmptyCallableDataPayloadsForHLSL`, gated by `isD3DTarget`). Put positive assertions where the pass runs (HLSL `int _slang_dummy`, DXIL `define void @`); on the unaffected target assert only correctness (`SPIRV: OpEntryPoint CallableKHR`). [-NOT on an unrun target is a tautology](../learnings/1787659385637-a-filecheck-not-on-a-target-the-code-under-test-ne.md).

**A loose regex can match the diagnostic instead of the output.** The METAL directive in `tests/glsl/matrix-mul.slang` (#4378) has never compiled, because GLSL `std140` blocks are gated off Metal with E36107 (see [GLSL / WGSL emit](../concepts/slang-backends-f0909b0-glsl-wgsl-bindless.md)). It passes anyway: `{{.*}}m1{{.*}}*{{.*}}m2{{.*}}*{{.*}}a_position{{.*}}` matches the source line E36107 quotes, and SIMPLE+FileCheck ignored the exit code. Anchor on tokens only real output contains [matrix-mul METAL lane is vacuous](../learnings/1790798404070-glsl-interface-blocks-never-compile-for-metal-std1.md). Since #14269 (2026-11-04) a SIMPLE+FileCheck lane fails with `expected exit code 0, but the exit code is -1` on a failed compile even if every CHECK matches, unless it declares `(filecheck=X,exit-code=-1)`; REFLECTION and INTERPRET followed in #14299, `diag=` lanes are not checked yet (#14266). A pre-11-04 branch that adds such a lane breaks on a clean merge with master, as the nightly-only `docs/generated/tests` tree did ([nightly triage](slang-tooling-docs-generated-nightly-triage.md)) [#14269 exit-code rule](../learnings/1793897749447-slang-test-now-fails-filecheck-simple-tests-on-non.md).

**An unanchored value check can match an unwritten slot or the type header.** `-output-using-type` prints every slot of a `COMPARE_COMPUTE` buffer, so with `data=[0 0 0 0]` and only slot 0 written, a lone `// CHECK: 0` matches any untouched zero and cannot tell 0 from 2: `docs/generated/tests/design/ir-reference/misc/is-vector-folds-false.slang` still passed after #13357 changed its value to 2. Size the buffer to the written slots, and run a test (`slang-test -test-dir docs/generated/tests <file>`) before accepting a reviewer's "will break" claim [a lone CHECK: 0 over a multi-slot buffer is vacuous](../learnings/1790799624727-a-lone-check-0-over-a-multi-slot-compare-compute-b.md). FileCheck also matches substrings: on #13410 a bare `// CHECK: 3` matched the `3` in the `type: int32_t` header, each later `CHECK: 0` matched any line with a 0, and a synthetic buggy buffer `[0,3,0]` passed on every leg; even `CHECK-NEXT: 3` accepts `13`. The robust form is `// CHECK: type: int32_t` then one `// CHECK-NEXT: {{^}}N{{$}}` per value. Validate it with a scratch `COMPARE_COMPUTE_EX ... -cpu -compute -shaderobj -output-using-type` test writing constant buggy and correct values; the buggy one must fail [value CHECKs can match the type header](../learnings/1790973538630-output-using-type-value-checks-can-match-the-type-.md), [`CHECK: 3` is vacuous; use `CHECK-NEXT: {{^}}N{{$}}`](../learnings/1790980781348-output-using-type-makes-check-3-vacuous-use-check-.md).

**A full-line CHECK can pin another open PR's bug.** On #13328 a one-line Metal kernel-signature check also pinned the missing `[[texture(n)]]` on resource arrays that open PR #12294 fixes; applying only #12294's `slang-emit-metal.cpp` hunk (`git apply --include=<path> pr.diff`) made the test fail on correct output. The fix, `MTL: void computeMain(` plus one `MTL-SAME:` per parameter, was verified with and without the other PR. The clarity reviewer caught this, not the correctness pass [full-signature CHECK pins another PR's bug](../learnings/1790712737290-a-full-signature-metal-check-can-pin-another-open-.md).

**A flag on the target path can mask the signal you attribute to your change.** To prove that the CUDA prelude's `#if SLANG_CUDA_ENABLE_FAST_MATH` redirect selects `__cosf` (slang#12619, #12872), the intuitive `-target ptx -fp-mode fast` lane checking `cos.approx.f32` is confounded: for `FloatingPointMode::Fast` Slang also passes NVRTC `--use_fast_math` (`slang-nvrtc-compiler.cpp`), which alone rewrites `sinf`→`__sinf`, so `.approx` appears even with the prelude gate deleted [ptx approx confounded by --use_fast_math](../learnings/1788296956279-testing-cuda-fp-mode-fast-redirect-target-ptx-appr.md), [a target-path flag masks the behavioral test](../learnings/1788297443087-a-target-path-flag-can-mask-what-a-behavioral-code.md). Such lanes catch an inverted gate but miss a deleted `#if` body. The robust test compiles the offline nvcc fixture with the macro on and off, without `--use_fast_math`, and checks the preprocessed source (`__cosf` vs `::cosf`) or the PTX; slangc's `-target cuda` text can't be checked directly because slang-test emits the prelude as an `#include`. OUTPUT_REVIEW caught the masking, not code review: when target X adds an independent optimization flag, check whether it confounds the test.

**Retarget a stale test on the invariant, not the new spelling.** For "an empty ray payload still has storage" (stale after #13256), capture the struct name with `[[P:[A-Za-z_0-9]+]]`, `CHECK-NEXT` exactly one member, then check `main(inout [[P]] …`. Don't pin the member type (`int` before, `uint` after). A stale base-clone binary gives a cheap before/after A/B without a bisect build [stale docs/generated/tests retarget](../learnings/1790673868800-stale-docs-generated-tests-retarget-prettier-3-3-3.md). For textual checks the coincidence worry runs the other way: MSL's runtime "first free index" fallback for an unattributed argument cannot make a missing-`[[texture(` textual check pass; only a runtime test could pass by coincidence, and pinning a nonzero register tests the index assignment [MSL first-free-index fallback in a textual check](../learnings/1790698191466-scope-narrowed-pr-check-closingissuesreferences-sq.md).

## Cross-target reach: emit predicates and capability nesting

**Lifting a per-target emit predicate to the shared base affects every sibling subclass.** On slang#12635, lifting WGSL's nested-static-const fold into `CLikeSourceEmitter` to fix CUDA also changed HLSL, GLSL, and Metal. Metal regressed: `metal::array<T,N>` is a struct wrapper like CUDA/C++ `FixedArray` and hit the same single-brace "too many initializers" mis-bind, but derives from `CLikeSourceEmitter`, not `CPPSourceEmitter`, so it lacked the double-brace fix. Enumerate the subclasses first (`grep "class .*SourceEmitter : public"`) and reason about each: struct-wrapper (CUDA/C++, Metal), native-array (HLSL), constructor-syntax (GLSL/WGSL). Pin Metal with `//TEST:SIMPLE(filecheck=METAL): -target metal` and check the aggregate-init shape through a `g++ -std=c++14` proxy [lifting a predicate to the base](../learnings/1787580446019-lifting-a-per-target-emit-predicate-to-the-shared-.md).

A `__target_switch` arm `case X:` is selected only if the compile's capabilities **imply** X (`slang-ir-specialize-target-switch.cpp:38-66`; the most specific eligible arm wins), so **nesting `case A:` inside `case B:` makes A's body dead whenever a compile enables A but not B.** On slang#12186, `spvBindlessTextureNV` and `spvDescriptorHeapEXT` are independent siblings under `_spirv_1_0`; nesting the NV arm inside the EXT arm would stop NV opcodes emitting under `-capability spvBindlessTextureNV`. Check the implication chain in `slang-capabilities.capdef` transitively [__target_switch arm nesting](../learnings/1787959548975-target-switch-arm-nesting-under-a-non-implied-capa.md).

**A textual ABI test can hide a DXC-only bug.** A `//CHECK: .GetX` test for NVAPI SER HitObject ops confirms only that Slang emits `nvHitObj.GetX()`. The NVAPI shim (`nvHLSLExtns.h`) is not in-tree, so only DXC with the NVAPI SDK reports "no member named X". On #9257 the `GetWorldToObject` / `GetObjectToWorld` mappings emit invalid HLSL because `NvHitObject` has no such getters; the fix is a `static_assert` on the NVAPI arm plus a diagnostic test. PR #12089 edits those lines but only re-gates the capability, with a textual CHECK-DAG test that never runs DXC, so it does not fix the bug [textual ABI test masks the DXC-only bug](../learnings/1787226505940-nvapi-hitobject-transform-getters-9257-textual-abi.md). A PR touching the exact lines is not evidence; check whether its test reaches the real failure path.

## Authoring diagnostic tests, FileCheck prefixes, and COMPARE_COMPUTE lanes

**`non-exhaustive` is rejected when redundant and required when a real extra fires.** When every diagnostic has a `//CHECK:`, `diag=CHECK,non-exhaustive` errors `Unnecessary 'non-exhaustive': All N diagnostic(s) were matched by annotations`; default to plain `diag=CHECK` [redundant non-exhaustive is rejected](../learnings/1789479929783-slang-test-rejects-redundant-non-exhaustive-place-.md). The mirror failure is an exhaustive `diag=CHECK` failing `Found N diagnostic(s) without annotations` on an incidental extra: core-module code (`hlsl.meta.slang`) referencing a capability inside a `__target_switch` (a `static_assert` in a `case spvDescriptorHeapEXT:` arm) emits `warning[E41012]: profile implicitly upgraded ...` at the entry point under a different requested capability. Then `non-exhaustive` is right [non-exhaustive for incidental profile-upgrade warnings](../learnings/1789572326133-slang-diagnostic-test-non-exhaustive-for-capabilit.md). slang-test prints the exact suggestion. Annotation matching is a substring match against the full message (E41400 is prefixed `static assertion failed, `, so quote the actionable tail), and the caret column is the error location. When narrowing a core-module conversion path, gate a capability bypass on both capabilities (nested `__target_switch`), not on a type property, or the single-capability config loses a user override.

**A custom `filecheck=` prefix must not collide with a reserved suffix.** FileCheck reserves `-NEXT`/`-SAME`/`-EMPTY`/`-NOT`/`-COUNT-<n>`/`-DAG`/`-LABEL` on every active prefix. With one directive `filecheck=CHECK` and another `filecheck=CHECK-EMPTY`, the `CHECK` run reads `// CHECK-EMPTY: <text>` as its own directive and errors `found non-empty check string for empty check with prefix 'CHECK:'`. Use a non-reserved suffix (`CHECK-ZERO`, `CHECK-PTX`, `CHECK_PTX`) [reserved-suffix prefix collision](../learnings/1789451228334-filecheck-custom-prefix-must-not-collide-with-rese.md). This hides locally (no FileCheck), and early `wait-for-human-priority` CI yields never ran test-slang, so "CI was green before" is not evidence. A FileCheck variable collides the same way: with prefixes OTHER and PICK, `// PICK: OpEntryPoint %[[OTHER:[A-Za-z0-9_]+]] "x"` contains `OTHER:` and the OTHER lanes read it as their own check and fail; name variables so they cannot spell a prefix (`FN`) ([FileCheck traps: `[[PREFIX:` vars become directives](../learnings/1793686330054-filecheck-traps-in-slang-test-simple-lanes-error-m.md)).

**slang-test supports exactly one FileCheck prefix per `//TEST` directive.** Text inside the parentheses is split on every `,` into options (`_parseCommandArguments`, `slang-test-main.cpp` :346/:367), so `//TEST:SIMPLE(filecheck=CHECK,WGSL):` is `filecheck=CHECK` plus a valueless `WGSL` nothing reads; `getFileCheckPrefix` (:96) reads only the `filecheck` key and `slang-llvm-filecheck.cpp:92` passes one prefix. On #13356 garbage in every `WGSL:`/`METAL:`/`GLSL:` line still passed 3/3, and #13507 re-found it (`filecheck=CHECK,BYTES`). The legitimate comma use joins two options (`filecheck=CHECK,diag=diag`). Write one `filecheck=` directive per target and mutation-test every new row (a false line under the second prefix, an injected compile error, the construct removed). Four master tests use the broken form (`tests/spirv/debug-matrix-layout.slang`, `tests/spirv/optional-vertex-output.slang`, `tests/bugs/gh-11021-dxil-default-profile.slang`, `tests/vkray/empty-payload-glsl-noinline-helper-chain.slang`; slang#13359; the splitting dates to #2747). Read the parser; an existing use is not proof. Activating dead lines surfaces two traps: `// METAL: [[kernel]]` parses as a FileCheck variable (escape as `{{\[\[}}kernel{{\]\]}}`), and prose such as `// ... only on GLSL: WGSL and Metal ...` becomes a `GLSL:` directive [comma prefixes are dead](../learnings/1790799835281-slang-test-filecheck-check-wgsl-silently-activates.md), [CORRECTION: one prefix per directive](../learnings/1790800525677-correction-slang-test-does-not-support-multiple-fi.md), [commas separate options](../learnings/1790805124373-slang-test-commas-inside-separate-options-so-filec.md), [filecheck=A,B is ONE prefix](../learnings/1791427324960-slang-test-filecheck-a-b-is-one-prefix-the-second-.md).

A real multi-prefix fix for #13359 has two constraints. A repeated key is no workaround: options live in a `Dictionary` via `Dictionary::add`, which asserts on a duplicate, so `filecheck=CHECK,filecheck=EXTRA` kills slang-test with an uncaught `Slang::InternalError`, in Release too. In-process LLVM FileCheck gives the unused-prefix guard for free (`readCheckFile`, `AllowUnusedPrefixes` defaults false), but `FileCheck::ValidateCheckPrefixes()` (empty, invalid, duplicate prefixes) runs only in the tool's `main`, so slang-llvm must call it itself [unused-prefix error lives in readCheckFile](../learnings/1790817962233-llvm-filecheck-unused-prefix-error-lives-in-readch.md).

**A CHECK-DAG pin can shrink a leading CHECK-NOT.** FileCheck checks a CHECK-NOT placed before a CHECK-DAG group only up to the group's earliest match, so a DAG line matching early output (an `[E30015]` pin on the diagnostic header) silently shrinks the NOT's region: on #14343, `ASCII-NOT: undefined identifier` FAILED at base and passed at head. Put a plain `PREFIX: [E30015]` line ahead of the NOT lines. Under `-diagnostic-color always` the severity word is SGR-wrapped (`^[[31merror^[[0m[E30015]`), so pin the bare `[Exxxxx]` [CHECK-DAG pin shrinks a leading CHECK-NOT](../learnings/1793872226026-docs-generated-fixture-sweeps-must-also-fix-the-ge.md).

**`COMPARE_COMPUTE(-shaderobj)` cannot verify a source-dialect-gated conversion.** When a feature is gated on `getShared()->getTranslationUnitRequest()->sourceLanguage == SourceLanguage::HLSL` (the #13075 HLSL-only unscoped-enum→scalar conversion), a `//TEST(compute):COMPARE_COMPUTE(...):-cpu -shaderobj` leg on a `.hlsl` file fails `error E30019: type mismatch`: `-shaderobj` loads the file as a module whose `sourceLanguage` is not HLSL. A direct `//TEST:SIMPLE:-target ...` compile does set HLSL for a `.hlsl` file, so value-check with `//TEST:SIMPLE(filecheck=HLSL): -target hlsl` (or `-target cpp`) and FileCheck the const-folded value (`Green = 7` → `outF{{.*}} = 7.0f;`), as in `tests/language-feature/enums/enum-to-int-cast-local.slang`. `COMPARE_COMPUTE(compute)` supplies its own `-compute` and entry, so `-entry`/`-stage` fail `error 1004: unknown command-line option '-stage'` [COMPARE_COMPUTE module-load defeats a source-dialect gate](../learnings/1789519401343-slang-test-compare-compute-can-t-verify-a-source-d.md).
