# Slang test authoring: FileCheck efficacy, ignored targets, and confounded lanes

## TL;DR

The theme is **test efficacy**: a green test in a local container (Linux, no DXC/Metal) often proves nothing, because its target is ignored, an independent flag produces the signal, or a `-NOT` sits on a target the code never runs on.

- **`slang-test` exits 0 when nothing matched** (filter typo, positional path arg, `-test-dir` plus a trailing filter). Gate on `[0-9]+% of tests passed (n/m)` appearing.
- **The failure marker is `FAILED test:` (uppercase)**; `grep -c '^failed test:'` reports 0 failures on a failing log.
- **A `-target hlsl` or `-mtl` subtest is "ignored" (0/0), not run,** in a sandbox without DXC/Metal; that target is untested, and macOS CI runs the mtl subtest. Any `filecheck=` test is also ignored when the FileCheck binary is absent.
- **A cross-target `COMPARE_COMPUTE` listing `-mtl` must not use `double`** (Metal has none; emit aborts). Split F64 coverage into a no-Metal file.
- **CUDA diagnostic tests use `-target cuda`, not `-target ptx`**: ptx needs nvrtc (absent on CPU CI), which aborts before the pre-emit diagnostic pass. A ptx `DIAGNOSTIC_TEST` still runs there (only `TEST:SIMPLE` is ignored), so check a no-backend CI log before calling it skipped.
- **A `-NOT` on a target the code under test never runs on is a tautology.** Put positive assertions on the target the pass runs on.
- **A target-path flag can mask a behavioral lane** (`-target ptx` adds NVRTC `--use_fast_math`). Remove every other cause of the signal.
- **Lifting a per-target emit predicate to the base class affects every sibling subclass.** Enumerate the concrete emitters first.
- **Retarget a stale emit test on the invariant, not the new spelling.** Capture names with `[[P:[A-Za-z_0-9]+]]`; don't pin incidental details (a padded member's type) that can flip.
- **A `__target_switch` arm nested under a non-implied capability is dead code.**
- **A textual `//CHECK: .GetX` ABI test proves only that Slang emits the call**, not that the target API has the member. Only DXC with the NVAPI SDK catches the gap.
- **`non-exhaustive` is a two-sided contract:** `diag=CHECK,non-exhaustive` is rejected when every diagnostic is annotated, and plain `diag=CHECK` fails when an incidental extra (a profile-upgrade `warning[E41012]`) fires. Add it only when a real extra exists.
- **Never name a custom `filecheck=` prefix with a reserved suffix** (`-EMPTY`/`-NEXT`/`-SAME`/`-NOT`/`-DAG`/`-LABEL`/`-COUNT`); `CHECK` reinterprets `CHECK-EMPTY:`. Use `CHECK-ZERO`.
- **`filecheck=CHECK,WGSL` activates only `CHECK`.** Commas inside `(...)` separate options, so every `WGSL:` line is skipped (#13359). Use one prefix per `//TEST` directive; a repeated key (`filecheck=A,filecheck=B`) crashes slang-test.
- **A lone `CHECK: 0` over a multi-slot `COMPARE_COMPUTE` buffer matches any unwritten zero slot, and `CHECK: 3` matches the `3` in `type: int32_t`.** Pin with `CHECK: type: int32_t` then `CHECK-NEXT: {{^}}N{{$}}` per value, and mutation-check it.
- **SIMPLE+FileCheck ignores the compiler's exit code**, so a loose `{{.*}}` regex can match the source line quoted in an error diagnostic.
- **Don't pin incidental output that is another open PR's bug.** Split a full-signature CHECK into `CHECK: void f(` plus one `CHECK-SAME:` per param, and run the test against that PR's diff.
- **`COMPARE_COMPUTE(-shaderobj)` loads the file as a module**, so a source-language-gated feature (`sourceLanguage==HLSL`) never fires (E30019). Value-check with a direct-compile `SIMPLE(filecheck=...):-target hlsl`. COMPARE_COMPUTE also rejects `-entry`/`-stage`.

## The slang-test harness: five instrument traps

`slang-test` gives believable answers where it is blind. Five traps from slang#12442 (PR #12465) [the five traps](../learnings/1786405416356-slang-test-harness-instrument-traps-failed-vs-fail.md). (1) The failure marker is `FAILED test:` (uppercase) and the pass marker is lowercase `passed test:`, so `grep -c '^failed test:'` reported 0 failures on a log with 4. `failed(pending retry)` is a retry, not a verdict; `failed(expected) test:` is a suppression match. A file yields one cell per `//TEST` directive plus synthesized `... syn (cuda)` cells, so always quote the cell name. (2) `slang-test` exits 0 when nothing matched. A positional path arg is only a prefix filter (enumeration comes from `-test-dir`, default `tests/`), so `slang-test docs/generated/tests/<path>` runs nothing, and `-test-dir` plus a trailing filter also runs nothing. Gate every run on `[0-9]+% of tests passed \([0-9]+/[1-9][0-9]*` appearing. (3) `-explicit-test-order` is mandatory for an ordering experiment, or the victim may run first and the drill reads "does not reproduce". Subtests within one file do run in order, so one `.slang` with `COMPARE_COMPUTE` then a `-target hlsl SIMPLE` directive can express an ordering dependency. (4) A red `workflow_dispatch` draft-PR CI check is usually a priority yield (`wait-for-human-priority: priority-gate-yielded`) whose GitHub conclusion is `failure`. Report it on the PR as "red by design; nothing was built", and count the job kinds before describing them. (5) The mutating and `--check-only` formatting paths use different file lists (see the formatting page); a missing tool makes `--check-only` exit 1 with no formatting problem. Also: `git log --format=%B <sha>` without `-1` walks every ancestor (a 6.7 MB message), and `REQUIRED_BY` in `tools/render-test/CMakeLists.txt` is a broken way to depend on `slang-unit-test`; put `REQUIRES render-test` on the target and verify the edge with `ninja -t query` against a known-good positive control.

## Ignored targets: a locally green test that tested nothing

In the Linux coworker sandbox (no DXC), a `//TEST:SIMPLE(filecheck=CHECK):-target hlsl` test is reported **"ignored" (0/0)**, not pass or fail. Ignored is not broken; a known-good sibling's hlsl variant is also ignored. To verify a parse- or compile-level fix locally, write the positive test as CPU compute (`//TEST(compute):COMPARE_COMPUTE(filecheck-buffer=CHECK):-cpu -output-using-type -shaderobj`) or for the `slangi` interpreter (`//TEST:INTERPRET`) [bare -target hlsl SIMPLE ignored](../learnings/1787342748842-slang-test-bare-target-hlsl-simple-tests-are-ignor.md). The same atom notes that the unit-test build target is `libslang-unit-test-tool.so`, that ninja aborts the whole multi-target build on one unknown target name, and the `clang-format-17` shim.

Metal is the costliest case. A cross-target `COMPARE_COMPUTE` test listing `-mtl` **must not contain `double` / `double2/3/4`**: Metal has no `double`, and the compiler correctly aborts at emit (`error[E99997] ... unexpected: 'double' type emitted`), so the fix belongs in the test. The container has no Metal toolchain, so the mtl subtest is ignored and the file passes locally while macOS CI fails [COMPARE_COMPUTE -mtl no double](../learnings/1787952374955-a-cross-target-compare-compute-test-that-targets-m.md). Verify device-free by emitting Metal source (`slangc <test> -target metal -stage compute -entry <e> -o /tmp/out.metal`; exit 0 and `grep -c '\bdouble\b'` == 0) with a `git stash` must-fail control. Keep F64 coverage by moving `double` into its own test for `-cpu`/`-cuda`/`-vk` only; `float`, `int`, `uint`, and 64-bit ints are Metal-safe.

CUDA has the mirror rule: **diagnostic tests use `-target cuda`, not `-target ptx`.** `-target ptx` compiles to PTX through the `nvrtc` downstream compiler, which CPU CI runners lack, so the compile aborts with "failed to load downstream compiler 'nvrtc'" before `checkUnsupportedInst`, and the expected diagnostic (e.g. E55215) never fires. `-target cuda` stops at CUDA source, still runs the pre-emit diagnostic pass, and needs no nvrtc. The ptx form passes on a box with nvrtc and fails in CI (slang#12633 / PR #12671) [CUDA diagnostic tests use -target cuda](../learnings/1787351942939-cuda-diagnostic-tests-use-target-cuda-not-target-p.md). The prod agent containers ship CUDA 12.6 NVRTC whether or not a GPU is passed through; they have an L40S, which was missing only during the 09-28→10-16 host outage ([no GPU since ~09-28 (historical: 09-28→10-16 outage)](../learnings/1792089571497-agent-containers-have-no-gpu-since-2026-09-28-host.md)). A `DIAGNOSTIC_TEST` is not skipped for a missing backend: `_extractSlangCTestRequirements` maps `-target ptx` to `PassThroughFlag::NVRTC`, which makes a `TEST:SIMPLE` lane ignored without nvrtc (`tests/cuda/nvrtc-architecture-override.slang` on the macOS debug job), yet on that same job the ptx `DIAGNOSTIC_TEST` `tests/diagnostics/command-line/x-arg-trailing-x.slang` passed (#13450). A ptx diagnostic that fires before the downstream load (command line, front end) is real CI coverage; one after it fails. Before calling a test "skipped", grep a no-backend job log: `gh run view --job <id> --log | sed 's/\x1b\[[0-9;]*m//g' | grep <file>` for `passed test:` / `ignored test:` [DIAGNOSTIC_TEST -target ptx still runs without NVRTC](../learnings/1791410667785-diagnostic-test-with-target-ptx-still-runs-on-runn.md).

A third cause is independent of target and GPU: **any `filecheck=` test is ignored when the LLVM FileCheck binary is absent.** `slang-test` returns `Ignored` ("FileCheck is not available") at `slang-test-main.cpp:~842` when `getFileCheck()` is null, so a `//TEST:REFLECTION(filecheck=CHECK):-target spirv` subtest reports `ignored (0/0)` even though the reflection tool produced correct output. REFLECTION tests that compare against a `.expected` file still run. Verify GPU-free by dumping reflection JSON (`slangc test.slang -target spirv -no-codegen -reflection-json out.json`), simulate the ordered CHECK / CHECK-LABEL matching yourself, and leave the pass to CI (slang#13188 / PR #13189) [slang-test ignores spirv+filecheck reflection tests locally when FileCheck is absent](../learnings/1789941026991-slang-test-ignores-spirv-filecheck-reflection-test.md).

## Vacuous and confounded checks

A `-NOT` assertion discriminates only if the code path under test can produce the forbidden token on that target. On slang#12718 / PR #12723 a regression test put `// SPIRV-NOT: _slang_dummy` on a `-target spirv` lane, but the fix is a D3D-only IR pass (`legalizeEmptyCallableDataPayloadsForHLSL`, gated by `isD3DTarget`) that never runs on SPIR-V, so the check cannot fail. Put positive assertions on the target the pass runs on (HLSL `int _slang_dummy`, DXIL `define void @`). On the unaffected target, assert only what proves correctness (`SPIRV: OpEntryPoint CallableKHR`); "documenting" non-leakage with a `-NOT` is a comment's job [-NOT on an unrun target is a tautology](../learnings/1787659385637-a-filecheck-not-on-a-target-the-code-under-test-ne.md).

**A loose regex can match the diagnostic instead of the output.** The METAL directive in `tests/glsl/matrix-mul.slang` (added by #4378) has never compiled, because GLSL `std140` blocks are gated off Metal with E36107 (see [GLSL / WGSL emit](../concepts/slang-backends-f0909b0-glsl-wgsl-bindless.md)). It passes anyway: `{{.*}}m1{{.*}}*{{.*}}m2{{.*}}*{{.*}}a_position{{.*}}` matches the source line that the E36107 diagnostic quotes, and SIMPLE+FileCheck ignores the exit code. Don't count such a lane as coverage; anchor on tokens only real output contains [matrix-mul METAL lane is vacuous](../learnings/1790798404070-glsl-interface-blocks-never-compile-for-metal-std1.md).

**An unanchored value check can match an unwritten slot or the type header.** `-output-using-type` prints every slot of a `COMPARE_COMPUTE` buffer, so a test that declares `data=[0 0 0 0]` but writes only slot 0 lets a lone `// CHECK: 0` match any untouched zero; it cannot tell 0 from 2. `docs/generated/tests/design/ir-reference/misc/is-vector-folds-false.slang` still passed after #13357 changed its value to 2. Size the buffer to the written slots. When a reviewer claims a change "will break" such a test, run it first (`slang-test -test-dir docs/generated/tests <file>`) [a lone CHECK: 0 over a multi-slot buffer is vacuous](../learnings/1790799624727-a-lone-check-0-over-a-multi-slot-compare-compute-b.md). FileCheck also matches substrings, so on #13410 a bare `// CHECK: 3` matched the `3` in the `type: int32_t` header, each following `CHECK: 0` matched any later line with a 0, and a synthetic buggy buffer `[0,3,0]` passed on every leg, vk via-GLSL included. Even `CHECK-NEXT: 3` accepts `13`. The robust form is `// CHECK: type: int32_t` then one `// CHECK-NEXT: {{^}}N{{$}}` per value. Validate it with a scratch `COMPARE_COMPUTE_EX ... -cpu -compute -shaderobj -output-using-type` test that writes constant buggy and correct values (copy a vk-only test's CHECK block into it), and confirm the buggy one fails [value CHECKs can match the type header](../learnings/1790973538630-output-using-type-value-checks-can-match-the-type-.md), [`CHECK: 3` is vacuous; use `CHECK-NEXT: {{^}}N{{$}}`](../learnings/1790980781348-output-using-type-makes-check-3-vacuous-use-check-.md).

**A full-line CHECK can pin another open PR's bug.** On #13328 a new test checked the whole Metal kernel signature on one line, which also pinned the missing `[[texture(n)]]` on resource arrays that open PR #12294 fixes. Applying only #12294's `slang-emit-metal.cpp` hunk (`git apply --include=<path> pr.diff`) made the test fail on correct output, so whichever PR landed second would break CI. The fix, `MTL: void computeMain(` plus one `MTL-SAME:` per parameter, was verified with and without the other PR. When a test matches output the PR body calls a separate known bug, run it against that bug's open PR; the clarity reviewer caught this, the correctness pass did not [full-signature CHECK pins another PR's bug](../learnings/1790712737290-a-full-signature-metal-check-can-pin-another-open-.md).

**A flag on the target path can mask the signal you attribute to your change.** To prove that the CUDA prelude's `#if SLANG_CUDA_ENABLE_FAST_MATH` redirect selects `__cosf` (slang#12619, R2/R3 of #12872), the intuitive test is a `-target ptx -fp-mode fast` lane that FileChecks `cos.approx.f32`. But `-target ptx` compiles with NVRTC, and for `FloatingPointMode::Fast` Slang also passes NVRTC `--use_fast_math` (`slang-nvrtc-compiler.cpp`), which by itself rewrites `sinf`→`__sinf`, so `.approx` appears even if the prelude gate is deleted [ptx approx confounded by --use_fast_math](../learnings/1788296956279-testing-cuda-fp-mode-fast-redirect-target-ptx-appr.md), [a target-path flag masks the behavioral test](../learnings/1788297443087-a-target-path-flag-can-mask-what-a-behavioral-code.md). Such lanes catch an inverted gate (the default lane gets no `--use_fast_math`, so its `-NOT` fails) but miss a deleted `#if` body. The robust test compiles the offline nvcc fixture with the macro on and off, without `--use_fast_math`, and FileChecks the preprocessed source (`__cosf` vs `::cosf`) or the PTX. slangc's `-target cuda` text cannot be checked directly, because slang-test emits the prelude as an `#include`. The critique gate's OUTPUT_REVIEW caught the masking, not the code review: when a review suggests a target-X test and notes that target X adds an independent optimization flag, check whether the flag confounds the test.

**Retarget a stale test on the invariant, not the new spelling.** For "an empty ray payload still has storage" (stale after #13256), capture the struct name with `[[P:[A-Za-z_0-9]+]]`, `CHECK-NEXT` exactly one member, then check `main(inout [[P]] …`. Don't pin the member type: the padded member was `int` before the change and `uint` after. A stale base-clone build (an older binary) gives a cheap before/after A/B without a bisect build [stale docs/generated/tests retarget](../learnings/1790673868800-stale-docs-generated-tests-retarget-prettier-3-3-3.md). The coincidence worry runs the other way for textual checks: MSL assigns an unattributed argument the runtime "first free index", but that fallback cannot make a missing-`[[texture(` textual check pass; only a runtime test could pass by coincidence. Pinning a nonzero register value tests the index assignment, not the fallback [MSL first-free-index fallback in a textual check](../learnings/1790698191466-scope-narrowed-pr-check-closingissuesreferences-sq.md).

## Cross-target reach: emit predicates and capability nesting

**Lifting a per-target emit predicate to the shared base affects every sibling subclass.** On slang#12635, lifting WGSL's nested-static-const fold into `CLikeSourceEmitter` to fix CUDA also changed HLSL, GLSL, and Metal. Metal regressed: `metal::array<T,N>` is a struct wrapper like CUDA/C++ `FixedArray` and hit the same single-brace "too many initializers" mis-bind, but Metal derives from `CLikeSourceEmitter`, not `CPPSourceEmitter`, so it lacked the double-brace fix. Before lifting, enumerate the concrete subclasses (`grep "class .*SourceEmitter : public"`) and reason about each: struct-wrapper (CUDA/C++, Metal), native-array (HLSL), constructor-syntax (GLSL/WGSL). Metal has no local toolchain, so pin its form with a `//TEST:SIMPLE(filecheck=METAL): -target metal` line and check the C++ aggregate-init shape through a `g++ -std=c++14` proxy [lifting a predicate to the base](../learnings/1787580446019-lifting-a-per-target-emit-predicate-to-the-shared-.md).

A `__target_switch` arm `case X:` is selected only if the compile's capabilities **imply** X (`slang-ir-specialize-target-switch.cpp:38-66`; the most specific eligible arm wins). **Nesting `case A:` inside `case B:` makes A's body dead whenever a compile enables A but not B.** On slang#12186, `spvBindlessTextureNV` and `spvDescriptorHeapEXT` are independent siblings under `_spirv_1_0`; nesting the NV arm inside the EXT arm would make NV tests (compiled with `-capability spvBindlessTextureNV` only) skip it, so the NV opcodes never emit. Check the implication chain in `slang-capabilities.capdef` transitively before nesting; for independent siblings, nesting is a latent regression, not a refactor [__target_switch arm nesting](../learnings/1787959548975-target-switch-arm-nesting-under-a-non-implied-capa.md).

**A textual ABI test can hide a DXC-only bug.** A `//CHECK: .GetX` test for NVAPI SER HitObject ops confirms only that Slang emits `nvHitObj.GetX()`, not that `NvHitObject` has `GetX`. The NVAPI shim (`nvHLSLExtns.h`) is not in-tree, so only DXC with the NVAPI SDK (absent here) reports "no member named X". On #9257 the `GetWorldToObject` / `GetObjectToWorld` mappings emit invalid HLSL because `NvHitObject` exposes none of those getters; the fix is a `static_assert` on the NVAPI arm plus a diagnostic test. PR #12089 edits those exact lines but only re-gates the capability and keeps the broken mapping, with a textual CHECK-DAG test that never runs DXC, so it does not fix the bug [textual ABI test masks the DXC-only bug](../learnings/1787226505940-nvapi-hitobject-transform-getters-9257-textual-abi.md). A PR touching the exact lines is not evidence the bug is handled; check whether its test reaches the real failure path.

## Authoring diagnostic tests, FileCheck prefixes, and COMPARE_COMPUTE lanes

**`non-exhaustive` is rejected when redundant and required when a real extra fires.** On `//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK,non-exhaustive)` where every diagnostic already has a `//CHECK:`, slang-test errors `Unnecessary 'non-exhaustive': All N diagnostic(s) were matched by annotations`, so adding it "to be safe" turns a green test red. Default to plain `diag=CHECK` [redundant non-exhaustive is rejected](../learnings/1789479929783-slang-test-rejects-redundant-non-exhaustive-place-.md). The mirror failure is an exhaustive `diag=CHECK` failing `Found N diagnostic(s) without annotations` because an incidental extra fires: core-module code (`hlsl.meta.slang`) that references a capability inside a `__target_switch` (a `static_assert` in a `case spvDescriptorHeapEXT:` arm) emits `warning[E41012]: profile implicitly upgraded ... 'spvDescriptorHeapEXT'` at the entry point under a different requested capability. Then `diag=CHECK,non-exhaustive` is right [non-exhaustive for incidental profile-upgrade warnings](../learnings/1789572326133-slang-diagnostic-test-non-exhaustive-for-capabilit.md). slang-test prints the exact suggestion in the failure. Annotation matching is a substring match against the full message (E41400 is prefixed `static assertion failed, `, so quote just the actionable tail), and the caret column is the error location, not the message length. When narrowing a core-module conversion path, gate a capability bypass on both capabilities at once (nested `__target_switch`), not on a type property, or the single-capability config loses a user override.

**A custom `filecheck=` prefix must not collide with a reserved suffix.** FileCheck reserves `-NEXT`/`-SAME`/`-EMPTY`/`-NOT`/`-COUNT-<n>`/`-DAG`/`-LABEL` on every active prefix. If one directive uses `filecheck=CHECK` and another uses `filecheck=CHECK-EMPTY`, the `CHECK` run reads `// CHECK-EMPTY: <text>` as its own CHECK-EMPTY directive (next line blank) and errors `found non-empty check string for empty check with prefix 'CHECK:'`, reported against `CHECK`, not your prefix. Use a non-reserved suffix (`CHECK-ZERO`, `CHECK-PTX`, `CHECK_PTX`); `CHECK-PTX` coexists with `CHECK` in tests/cuda/ because `PTX` is not reserved [reserved-suffix prefix collision](../learnings/1789451228334-filecheck-custom-prefix-must-not-collide-with-rese.md). This hides locally because `SIMPLE(filecheck=...)` is ignored without slang-llvm/FileCheck, and early `wait-for-human-priority` CI yields never run test-slang, so "CI was green before" is not evidence when the prior runs were yields.

**slang-test supports exactly one FileCheck prefix per `//TEST` directive.** The text inside the parentheses is split on every `,` into separate options (`_parseCommandArguments`, `slang-test-main.cpp` :346/:367), so `//TEST:SIMPLE(filecheck=CHECK,WGSL):` becomes `filecheck=CHECK` plus a valueless `WGSL` that nothing reads. `getFileCheckPrefix` (:96) reads only the `filecheck` key, and `slang-llvm-filecheck.cpp:92` passes one prefix (`fcReq.CheckPrefixes = {fileCheckPrefix};`). Every `// WGSL:` line is dead: on #13356 garbage in every `WGSL:`/`METAL:`/`GLSL:` line still passed 3/3 while breaking one `CHECK:` line failed, and #13507 re-found it (`filecheck=CHECK,BYTES`). The legitimate comma use is two different options (`filecheck=CHECK,diag=diag`). Write one `filecheck=` directive per target, and mutation-test every new row (a false line under the second prefix, an injected compile error, the construct under test removed) before trusting it. Four master tests use the broken form (`tests/spirv/debug-matrix-layout.slang`, `tests/spirv/optional-vertex-output.slang`, `tests/bugs/gh-11021-dxil-default-profile.slang`, `tests/vkray/empty-payload-glsl-noinline-helper-chain.slang`; shader-slang/slang#13359; the splitting dates to #2747). The wrong reading came from treating an existing use of the syntax as proof; read the parser. Activating dead lines surfaces two traps: `// METAL: [[kernel]]` parses as a FileCheck variable (escape it as `{{\[\[}}kernel{{\]\]}}`), and prose such as `// ... only on GLSL: WGSL and Metal ...` becomes a `GLSL:` directive [comma prefixes are dead](../learnings/1790799835281-slang-test-filecheck-check-wgsl-silently-activates.md), [CORRECTION: one prefix per directive](../learnings/1790800525677-correction-slang-test-does-not-support-multiple-fi.md), [commas separate options](../learnings/1790805124373-slang-test-commas-inside-separate-options-so-filec.md), [filecheck=A,B is ONE prefix](../learnings/1791427324960-slang-test-filecheck-a-b-is-one-prefix-the-second-.md).

A real multi-prefix fix for #13359 has two constraints. A repeated key is no workaround: options live in a `Dictionary` via `Dictionary::add`, which asserts on a duplicate, so `filecheck=CHECK,filecheck=EXTRA` kills slang-test with an uncaught `Slang::InternalError`, in Release too. In-process LLVM FileCheck gives the unused-prefix guard for free (`readCheckFile`, `AllowUnusedPrefixes` defaults false), but `FileCheck::ValidateCheckPrefixes()` (empty, invalid, and duplicate prefixes) runs only in the FileCheck tool's `main`, so slang-llvm must call it itself [unused-prefix error lives in readCheckFile](../learnings/1790817962233-llvm-filecheck-unused-prefix-error-lives-in-readch.md).

**`COMPARE_COMPUTE(-shaderobj)` cannot verify a source-dialect-gated conversion.** When a feature is gated on the translation unit's source language (`getShared()->getTranslationUnitRequest()->sourceLanguage == SourceLanguage::HLSL`, as in the #13075 HLSL-only unscoped-enum→scalar conversion), a `//TEST(compute):COMPARE_COMPUTE(...):-cpu -shaderobj` leg on a `.hlsl` file fails `error E30019: type mismatch`. The `-shaderobj` path loads the file as a module, where the TU's `sourceLanguage` is not HLSL, so the gate never fires; a plain `//TEST:SIMPLE:-target ...` direct compile does set HLSL for a `.hlsl` file. To value-check without a GPU, use a direct-compile `//TEST:SIMPLE(filecheck=HLSL): -target hlsl` (or `-target cpp`) and FileCheck the const-folded value (non-zero enumerator `Green = 7` → `outF{{.*}} = 7.0f;`), which pins the result against a wrong ordinal or truncated tag, like `tests/language-feature/enums/enum-to-int-cast-local.slang`. `COMPARE_COMPUTE(compute)` supplies its own `-compute` and entry, so passing `-entry`/`-stage` fails `error 1004: unknown command-line option '-stage'` [COMPARE_COMPUTE module-load defeats a source-dialect gate](../learnings/1789519401343-slang-test-compare-compute-can-t-verify-a-source-d.md).
