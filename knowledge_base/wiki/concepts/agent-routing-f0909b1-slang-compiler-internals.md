## TL;DR

Compiler-technical facts surfaced by fixer/approver sessions on shader-slang/slang. The recurring theme is that a change which *looks* like a one-line un-gate or fast-path is usually guarded by several independent invariants, each caught by a different check.

- **Don't un-gate a silently-broken instruction.** CUDA/PTX integer-coord 1D texture Load returns all zeros on real GPUs; a `#if 0` stub is disabled for a reason. Prove instruction support with a standalone `.cu` + positive controls, not a Slang rebuild.
- **A "prove byte-compatibility or corrupt silently" optimization needs multiple orthogonal gates** — whole-object bitcast needed 4 (ABI-not-Natural layout, reject matrices, reject empty aggregates, alignment ≤ payload), each found by a *different* verifier (code review, full regression suite, output review). Run the full neighboring suite, not just the targeted test.
- **Perf-only optimizations must gate conservatively** (safe by default, fast only when provably safe) and never rest on a *provenance proxy* (`loc`-validity, `!isFromCoreModule`) that merely correlates with the real reachability property.
- **Slang has two effect tiers:** `ReadNone` (no reads/writes → CSE + movable) vs `NoSideEffect` (no writes, may read → DCE only). Only `ReadNone` gates call CSE; resource-load wrappers are deliberately denied `ReadNone`.
- **GVN/dedup gates that depend on both insts need instruction-level dominance, not block-level** — block-level is reflexive within a block and rewrites backward pairs, silently miscompiling.
- **Fix at the producer, not the crash site.** IR-lowering ICEs usually root-cause in the checker; a guard at the crash site is a no-op under `SLANG_ASSERT→SLANG_ASSUME` in Release anyway.
- **Shadowable keywords can't be recognized by leading-token lookahead** — tentative-parse and commit on a token no existing grammar can produce (e.g. trailing `else`).
- **Platform traps:** `Path::isAbsolute` is platform-gated for drive/UNC (returns false for `C:\` on Linux); slang-test directive arg tokens keep their quotes; prefer `#if`-gating a platform-dependent test assert over deleting it; AST `ASTNodeType` IDs are positional with NO serialization version gate (unlike IR).
- **A many-to-one enum collision where routing keys on the coarse enum but the consumer keys on a finer property is a latent drift ICE** (DescriptorHandle: `TextureBuffer` and `Buffer` share `DescriptorKind.UniformTexelBuffer` but lower to different IR types).
- **A sentinel-gated helper needs a negative-invariant test** (assert out-of-domain inputs return the sentinel), not just positive-direction coverage.

## Optimizations that must "prove byte-compatibility or corrupt silently"

Two atoms establish the core discipline for aggressive lowering/codegen optimizations. Replacing field-wise AnyValue marshalling with a single whole-object `slang_bit_cast` needed [four independent predicate gates](../learnings/1787213800352-whole-object-bitcast-fast-path-four-independent-co.md), and no single verification step found them all: the box must compare against the emitted C/CUDA **ABI** layout (not Natural layout — CUDA `float4` is 16-byte aligned), must reject matrices (column-major walked vs row-contiguous stored), must reject empty aggregates (a zero-size aggregate legalizes to a non-simple tuple and `legalizeInstWithOperands` has no `kIROp_BitCast` case → `InternalError`), and must require emitted alignment ≤ payload alignment (a 16-aligned read from a 4-aligned box is UB). The lesson: for such an optimization the targeted FileCheck test proves little — the real bugs surfaced in an independent code reviewer reading layout/legalization source and in the **full neighboring regression suite (autodiff)**, so run both.

The companion rule for [perf-only optimizations](../learnings/1787595299942-a-perf-only-optimization-must-gate-conservatively-.md) (defer `[ForceInline]` to NVRTC): when one branch is "always correct, maybe slower" and the other is "faster, sometimes wrong," gate conservatively — do the safe thing by default and take the fast path only when *provably* safe, or you get a whack-a-mole stream of veto entries. Every *provenance/context proxy* (`loc`-validity, `!SetterDecl && !hasConstExprParam`, `!isFromCoreModule`) that merely *correlates* with the target property relocates the bug rather than closing it; the real invariant is usually a reachability property enforced at the consumer's requirement (a func reachable from a constant-required context must be inlined before that consumer runs). Test a predicate by asking "does this equal the property, or merely correlate?" then construct the divergence case.

## Effect tiers, CSE, and dominance

Slang's IR carries [two distinct function-effect decorations](../learnings/1787806415181-slang-has-two-effect-tiers-readnone-vs-nosideeffec.md): `IRReadNoneDecoration` (no reads AND no writes → safe to CSE and move/speculate) and `IRNoSideEffectDecoration` (no observable writes but may read → safe to DCE, not move). Call CSE gates ONLY on `ReadNone`; a read-only resource-load wrapper is deliberately denied `ReadNone` (moving it would OOB-read, pinned by `gh-3429.slang`) but still earns `NoSideEffect`. There is no intermediate "CSE-eligible-but-not-movable" tier — do not conflate "can be deduplicated" with "movable/speculatable."

Extending dedup for such a memory-reading call ([GVN with a per-both-insts gate](../learnings/1787828337427-gvn-dedup-with-a-per-both-insts-gate-needs-instruc.md)) must verify **instruction-level** dominance `dom->dominates(existingInst, candidateInst)`, not block-level: `deduplicate` records the most-recent representative per key and recurses over operands, so it can visit a *backward* pair (existing=later, candidate=earlier); block-level dominance is reflexive within a block and passes it, rewriting across a store and collapsing `a+b` to `b+b`. A call-COUNT FileCheck oracle misses this — add a VALUE-FLOW test (`before != after`).

## Producer-side fixes for crashes and cascades

The [IR-lowering default-arg crash fix](../learnings/1787412153690-fixing-ir-lowering-default-arg-crash-narrow-redire.md) shows three traps: a "read args from the requirement declRef" fix must be NARROW (an optional `defaultArgSource` only when it differs from the witness-resolved callee — a wholesale swap discards `.resolve()` substitutions and regresses the core module); a null-only per-parameter fallback is incoherent for mixed defaults (the selected declaration must be authoritative for all its omitted args); and This-dependent defaults are a separate pre-existing checker-side defect to scope OUT, not band-aid at lowering. The decisive tool is the **revert-control**: revert only your change on the same worktree, rebuild the minimal target, re-run the failing step.

Attribution matters when baselines churn: [peephole test-baseline churn from a gate fix](../learnings/1787586359149-peephole-test-baseline-churn-from-a-gate-fix-is-of.md) was tempting to blame on the headline stateful-mode leak (finding-2) but was actually the newly-added gate on a previously-*ungated* self-subtract arm (finding-1). `git show master:<file>` the pre-fix function and check which arm was gated before hand-waving to the leak. Confirmed-safe gate-batch PRs ([RequiredLoweringPassSet](../learnings/1787883589296-approver-confirmed-safe-requiredloweringpassset-ga.md), the #11917 epic) show the four standing source probes for gate PRs whose failure mode is silent always-skip = miscompile: no dead flag, correct scan order, jobs-not-passes (every unconditional job needs its own flag term), a trigger-present control for diagnostic-bearing gates, and a stale-FALSE producer trace.

## Parsing, tests, and layout/serialization traps

- [New statement keywords can't dispatch on leading tokens](../learnings/1787605380180-slang-a-new-statement-keyword-can-t-dispatch-on-le.md): Slang keywords are contextual/shadowable (`struct guard {}; guard let = e;` is a legal var-decl), so tentative-parse and commit on a unique discriminator (trailing `else`), or reserve the keyword as an intentional source-breaking change with a language-version gate.
- [`Path::isAbsolute` is platform-gated](../learnings/1787607368141-path-isabsolute-is-platform-gated-for-drive-unc-sl.md) — the drive/UNC check is `#if SLANG_WINDOWS_FAMILY`, so `Path::isAbsolute("C:\\out.spv")` is false on Linux; compose from `isDelimiter` + `isDriveSpecification` + `getFirstElement` for a cross-platform check. slang-test directive arg tokens PRESERVE their quotes (`_parseArg` uses `lexQuoted`); unescape with `unescapeShellLike` before a leading-char test. `isUnescapeShellLikeNeeded` returns a plain bool, not a `SlangResult`.
- [`globallycoherent` on resource params](../learnings/1787706145739-globallycoherent-on-resource-params-two-front-end-.md) needs widening TWO front-end gates in different files (`isModifierAllowedOnDecl`, `visitParamDecl`) plus an emit fix — `emitSimpleFuncParamImpl` does not emit memory-qualifier decorations, so a non-inlined HLSL helper drops the qualifier (moot on SPIR-V/GLSL/WGSL). Coherent-capable resource types span 3 disjoint AST bases.
- [Platform-dependent test asserts: `#if`-gate rather than delete](../learnings/1788159639075-platform-dependent-test-asserts-if-gate-rather-tha.md) — gating an assertion to platforms where behavior is guaranteed keeps the regression signal on the majority; deleting drops happy-path coverage everywhere (depfile folded-source case).
- [DescriptorHandle bindless drift ICE](../learnings/1788200982818-approver-challenger-miss-descriptorhandle-bindless.md): routing keys on `DescriptorKind` while encoding keys on the IR type class; `TextureBuffer<T>` and `Buffer<T>` both carry `DescriptorKind.UniformTexelBuffer` but lower to `IRTextureBufferType` vs `IRTextureType`, so one ICEs. Any many-to-one enum collision where the consumer keys on a finer property is a latent drift bug — reconcile by routing on the consumer's predicate or add a per-kind positive test.
- [AST `ASTNodeType` IDs are positional with NO serialization version gate](../learnings/1788214747973-slang-ast-astnodetype-ids-are-positional-with-no-s.md) — slang-fiddle orders them as a pre-order DFS of the class hierarchy; serialized AST tags nodes by raw uint with no stable-name remap. Inserting/reordering a class mid-hierarchy silently corrupts old `.slang-module` deserialization (contrast IR, which has stable names + a module-version gate). Any add/split-AST-node refactor must resolve module compat with maintainers.
- [CUDA/PTX 1D texture Load silently returns zero](../learnings/1787173148906-cuda-ptx-1d-texture-load-integer-coord-tex-level-1.md) — GPU-verified: the integer-coord `tex.level.1d.v4.f32.s32` fetch returns all zeros while float-coord and 2D controls work. Diagnose with a `static_assert(false)` in the 1D arm; do NOT un-gate the `#if 0` stub. The decisive experiment is a ~30-line `.cu` with positive controls, not a 20-min rebuild.
- [Sentinel-gated helpers need a negative-invariant test](../learnings/1788248579806-sentinel-gated-helper-needs-a-negative-invariant-t.md) — a guard reading `.isSet()`/null/empty silently depends on out-of-domain inputs returning the sentinel; a positive-only drift test that `continue`s past out-of-domain keys does not protect it. Also flag cross-enum index reuse (`CapabilityAtom(i)`/`CapabilityName(i)`) without a shared-integer-invariant comment.
