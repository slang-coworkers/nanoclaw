# Slang SPIR-V Backend: Emission, Capabilities, and Validation

The SPIR-V backend is Slang's primary Vulkan/Khronos target: a direct emitter (`slang-emit-spirv.cpp`), a legalization pass (`slang-ir-spirv-legalize.cpp`), and the bundled `slang-glslang` module for `spirv-opt`.

## TL;DR

- **`-fvk-use-entrypoint-name` auto-applies only when a module has >1 entry point** — a single-entry shader is still renamed `"main"` and fails `VUID-VkPipelineShaderStageCreateInfo-pName-00707` unless the flag is passed.
- **`[require(spirv_1_x)]` raises the emitted version only if the decoration reaches the CODEGEN IR module** (`addEntryPointRequireCapabilityDecorations()`) AND `determineSpirvVersion()` matches internal `_spirv_1_x` atoms, not the public alias — otherwise the header silently stays 1.0.
- **Gate capability-conditional emit on `targetCaps.implies(CapabilityAtom::spvFooEXT)`, never `isSPIRV(...)`** (fires for every SPIR-V target). Supersedes earlier advice.
- **Specify a capability through the API by STRING name** (`kind = String`, `stringValue0 = "spvGroupNonUniformArithmetic"`), never the generated `CapabilityName` int. Capdef atom adds/reorders are `pr: non-breaking` but trip BOTH `check-cmdline-ref` and `check-capability-atoms-ref`.
- **E36107 fires only on entry-point-reachable typed resources; a method-level `[require]` on a case-less `__target_switch` intrinsic is INERT** — the enforcing clause is the TYPE-level `[require]` on the shape struct (e.g. `__ShapeBuffer`).
- **`-capability` silently raises the SPIR-V version past an explicit `-profile`** (`-profile spirv_1_4 -capability spvShaderInvocationReorderNV` → `Version: 1.5`, exit 0): a version raise is a compatible `CapabilitySet` join and `requireSpirvVersion` takes `Math::Max`.
- **capdef atoms never auto-emit `OpExtension`/`OpCapability`** (emission is explicit C++), and **the emitted version comes from `getTargetCaps()`, NOT used functions' `[require]` caps** (RETRACTS "HitObject::TraceRay forces ≥1.5"; bundled spirv-val accepts SER at 1.4). Gate on `isSPIRV(format)`, not `isKhronosTarget`.
- **Entry-point `[require]` atoms never reach the codegen capability set and do NOT auto-emit `OpCapability` for `spirv_asm` builtin-loads** — declare the capability inline in the `spirv_asm` block, else VUID-…-pCode-08737.
- **Never mutate a hoistable `SPIRVAsmOperandEnum`/`Literal` in place** (asserts at `slang-ir.cpp:179`) — build a fresh operand and repoint the consumer; two producers must build byte-identical operands or dedup fails.
- **Parameterize only the INDEX of `SPIRVLoadDescriptorFromHeap`, never the `heap` global** (an `OpUntypedVariableKHR` in `UniformConstant`) — put the heap in the specialization cache key, not `newArgs`.
- **Descriptor-heap `ConstantBuffer` garbage is a WRONG STORAGE CLASS (Uniform vs StorageBuffer), not a missing `ArrayStride`.** Per spec the `OpTypeBufferEXT` and `OpBufferPointerEXT` storage classes are INDEPENDENT (DeepWiki was wrong).
- **SPIR-V atomic emit has FOUR address-space gates** — E30047, `isValidAtomicDest` (E41403), `isAtomicableAddressSpace` (**a miss silently falls back to non-atomic load/store**), `emitMemorySemanticMask` (miss → VUID-10870). `AtomicAdd/Inc/Dec/CompareExchange` bypass gate 3.
- **Atomic `MemoryOrder` has no per-op validation** — `load(Release)`, `store(Acquire)`, bad CAS pairs emit invalid SPIR-V with exit 0 (only VUID-10866 is Vulkan-gated). A non-constant order ICEs (E99997) on SPIR-V/Metal and is dropped on HLSL/GLSL/CUDA/WGSL.
- **Signature-derived `VariablePointers` must gate on `[noinline]`, not `hasUses()`** — over-declaring the cap triggers driver miscompile #9061.
- **`VariablePointers`/`VariablePointersStorageBuffer` lift "a variable may not hold a pointer" only for Workgroup/StorageBuffer pointees; `Uniform` is rejected regardless.** Pre-1.4 SSBOs are `Uniform`+`BufferBlock`, so `-profile spirv_1_3` is unfixable by capability.
- **Default optimization level still runs spirv-opt; only `-O0` runs ZERO passes** — but **`-O0` MASKS spirv-opt aborts** (#12247), and `CreatePrivateToLocalPass` breaks function-`static` persistence. "N tests fail under `-O3`": **EXIT 0 = benign FileCheck drift, EXIT 134 = real abort**.
- **`-g1 OpLine` / `-g2 DebugLine` come ONLY from statement-granularity `IRDebugLine` markers** — `sourceLoc` on value insts changes zero bytes. At `-g2` the source is embedded as `OpString`, so a `CHECK-NOT` matching your own `//CHECK` text falsely matches.
- **A clean `slangc` exit proves nothing: run `spirv-val`.** `//TEST:SIMPLE` and `-target spirv-asm` do NOT validate; CI sets `SLANG_RUN_SPIRV_VALIDATION=1`. A capability/validation regression test **must use a real `-target spirv` directive**.
- **spirv-val silence proves nothing in EITHER direction** — read the primary spec for validity claims. **RETRACTED on #12186:** `OpConvertUTo{Image,Sampler,SampledImage}NV` accept uint64 OR uint2 under addressing mode 64.
- **You are probably testing a stale compiler** — put `build/Debug/lib` FIRST in `LD_LIBRARY_PATH`, check `slangc -v`'s sha, and verify release claims with `git merge-base --is-ancestor <fix> <tag>`.
- **Revert-drill the triage predicate at HEAD before building on it** — "`implies()` is inert on disjunctive caps" was a stale-binary artifact.
- **`-dump-ir` is blind at BOTH ends** (after early lowering, before emit/legalize) — disassemble for late questions. `grep -c nonUniformResourceIndex` is inflated by the capability-atom name.
- **`NonUniformResourceIndex` is DROPPED by the `DescriptorHandle` Cast round-trip**, so a late `isNonUniform` coalescing guard is dead code.
- **A malformed `OpConstantComposite` (4 constituents on a vec3) comes from spirv-opt's IEEE-unsafe `x/x→1` fold, not Slang** — drill: `-dump-ir` intact + `-O0` correct vs `-O1+` broken ⇒ spirv-opt; `-fp-mode precise` correct ⇒ `NoContraction` lever.
- **Default fp-mode emitting NO `NoContraction` is INTENTIONAL** (#11933), so reassociation reports get `-fp-mode precise`, never a default flip. `precise` on a *variable* is ignored in default fp-mode.
- **The bindless-vs-descriptor-heap accessor is chosen at `specializeTargetSwitch` from GLOBAL `getTargetCaps()`** — no emit-side edit can honor a per-entry-point `[require]`.
- **`DescriptorHandle<T>`'s SPIR-V width is capability/kind-dependent (`uint2` plain, `uint64` under `spvBindlessTextureNV`/cuda)** — audit all ~8 width consumers; **a module-scope constant `OpBitcast` is INVALID SPIR-V**.
- **When the SECOND consumer-side guard for one defect still misses a case, fix the producer** — #12186's four emit guards traced to kind-UNGATED handle read-back conversions in `hlsl.meta.slang`. Reachable ⇒ diagnostic, else assert.
- **A module-scope `static const` repro compiles clean unless the constant is CONSUMED** (DCE). **Report static-const codegen per opt level:** `-O3` folds `$init` into a module-scope `OpConstantComposite`, hiding the reconstruction default opt and `-O0` show.
- **The `spvDescriptorHeapEXT` AS heap is DRIVER-managed** — populate via `vkUpdateDescriptorSets` + `VkWriteDescriptorSetAccelerationStructureKHR`, not memcpy. Slot-0-works-but-≥1-crashes ⇒ AS stride mismatch.
- **In std140 a row-major `float2x4` is byte-identical to `float4[2]`; `-matrix-layout-*` never touches arrays** — "array garbage, matrix fine" is host packing, EXCEPT with descriptor heap/bindless, where it is #11483 (update past #11647, or use `StructuredBuffer<T>`).
- **`SV_Target<N>` is the ONLY varying semantic whose suffix is an absolute SPIR-V location** — user varyings get locations by DECLARATION ORDER (DeepWiki's claim is REFUTED; WGSL/Metal-only).

## Entry Points and Module-Level Emission

Slang renames every SPIR-V entry point to `"main"` by default; `-fvk-use-entrypoint-name` (API `VulkanUseEntryPointName`) keeps the source name. Slang auto-applies the flag only when a module has more than one entry point (PR #6260), so a single-entry shader still fails VUID-VkPipelineShaderStageCreateInfo-pName-00707 unless the flag is passed uniformly ([Slang SPIR-V entry-point rename: auto-applies only with >1 entry point](../learnings/1779621920622-slang-spir-v-entry-point-rename-auto-applies-only-.md)).

The `[require(spirv_1_x)]` decoration that sets the emitted version must reach the **codegen IR module** (not only the layout/reflection module) via `addEntryPointRequireCapabilityDecorations()`, and `determineSpirvVersion()` must match internal `_spirv_1_x` atoms rather than the public alias. Without both, `[require(spirv_1_5)]` leaves the header at 1.0 ([CORRECTION to #11631 version root cause: require atom stamped only on layout IR module, not the codegen module determineSpirvVersion runs on](../learnings/1781643037138-correction-to-11631-version-root-cause-require-ato.md)).

**Adding a nullary entry-point attribute that maps to an execution mode** (e.g. `[postdepthcoverage]`, #12999/PR #13001): mirror `[earlydepthstencil]` across 9 sites (AST node, `attribute_syntax`, IR op + stable name, `isSimpleDecoration`, `addSimpleDecoration` lowering, SPIR-V `Stage::Fragment` funnel, GLSL `Stage::Pixel` chain). Rules: (1) `ASTNodeType` is FIDDLE-regenerated from declaration order, NOT append-only, so group the attribute with its siblings (a codex "renumbering" flag is a false positive). (2) A new IR instruction DOES bump `k_maxSupportedModuleVersion` (`slang-ir.h`). (3) `requireSPIRVCapability`/`requireSPIRVExecutionMode` are dedup'ing emission funnels with no capdef lookup, so skip capdef atoms unless you need front-end gating. PostDepthCoverage requires EarlyFragmentTests, so emit both. Test with `//TEST:SIMPLE(filecheck=CHECK): -target spirv`; "emitted exactly once" needs `COUNT-1:` **plus** a following `-NOT:` of the same pattern ([adding a nullary entry-point attribute + SPIR-V execution mode: mirror earlydepthstencil across 9 sites](../learnings/1789107867239-adding-a-nullary-entry-point-attribute-spir-v-exec.md)).

## Builtin Variables and Memory-Access Masks

`IRSPIRVAsmOperandBuiltinVar` is `hoistable=true`, so cross-stage uses of one builtin (e.g. compute + raygen `SubgroupLocalInvocationId`) collapse to one inst via `_findOrEmitHoistableInst`; a cache-key axis on `BuiltinSpvVarKey` is dead code ([slang-spirv-asm-operand-builtinvar-is-hoistable-collapses-cross-stage](../learnings/1779617050641-slang-spirv-asm-operand-builtinvar-is-hoistable-co.md)).

A side-table such as `m_volatileBuiltinGlobalVars` inside `getBuiltinGlobalVar` must be populated BEFORE the cache-hit early return, or later call sites miss it. `spirv_asm` blocks bypass `emitLoad`, so the `case SpvOpLoad:` branch of `emitSPIRVAsm` needs the same handling ([slang-emit-spirv builtin-var cache and the volatile-set cache-hit trap](../learnings/1779612967874-slang-emit-spirv-builtin-var-cache-and-the-volatil.md)). When injecting a mask (e.g. `Volatile`) into a `spirv_asm` OpLoad that already has a user mask, emit ONE combined mask word; the scan must cover both `kIROp_SPIRVAsmOperandLiteral` and `kIROp_SPIRVAsmOperandEnum` ([slang-emit-spirv-extra-memoryaccess-word-grammar-bug-pattern](../learnings/1779617068760-slang-emit-spirv-extra-memoryaccess-word-grammar-b.md)).

Hoistable `SPIRVAsmOperandEnum`/`Literal` operands are value-numbered; `setOperand` on them asserts at `slang-ir.cpp:179`. Build a fresh operand and repoint the non-hoistable consumer (`spvInst->setOperand(maskIndex+1, newOperand)`) ([Never mutate a hoistable SPIRVAsmOperand in place; repoint the consuming inst](../learnings/1781725591470-never-mutate-a-hoistable-spirvasmoperand-in-place-.md), [SPIR-V asm-operand legalization: hoistable operands + foldable≠constant pitfalls](../learnings/1781726667133-spir-v-asm-operand-legalization-hoistable-operands.md)).

## Descriptor Heap (spvDescriptorHeapEXT)

The heap path uses `kIROp_SPIRVLoadDescriptorFromHeap`, not `IRCastDescriptorHandleToResource`; four specialization allowlists in `slang-ir-specialize-function-call.cpp` and `slang-ir-specialize-buffer-load-arg.cpp` accepted only the cast, causing SIGSEGV #11498 — fix the allowlists, not the downstream pass ([spvDescriptorHeapEXT path uses kIROp_SPIRVLoadDescriptorFromHeap, not IRCastDescriptorHandleToResource](../learnings/1780729707220-spvdescriptorheapext-path-uses-kirop-spirvloaddesc.md), [spvDescriptorHeapEXT path — fix function-call specialization allowlists, not the downstream pass](../learnings/1780733286644-spvdescriptorheapext-path-fix-function-call-specia.md)). The `heap` operand is the module-scoped `kIROp_SPIRVResourceHeap` global, emitted as `OpUntypedVariableKHR` in `UniformConstant`; parameterizing it as a `uint` makes the cloned callee's access-chain base a scalar (invalid). Parameterize ONLY the index and keep the heap in the cache key, not `newArgs` ([spvDescriptorHeapEXT specialization fix: don't parameterize the heap global](../learnings/1780734760813-spvdescriptorheapext-specialization-fix-don-t-para.md), [SPIRVLoadDescriptorFromHeap heap operand is a pointer global at emit — never parameterize it in call-spec](../learnings/1780769340224-spirvloaddescriptorfromheap-heap-operand-is-a-poin.md)).

**`ConstantBuffer` via the heap (#11483) is a cluster of distinct defects; rebuild slangc at true HEAD before asserting any repro.** The `emitDescriptorHeapLoad` SIGSEGV reproduced only on builds predating #11211; on master the heap path emits layout byte-identical to a bound `ConstantBuffer` and validates, so that half closed as test-only PR #11484 ([CORRECTION: slang#11483 crash was a stale pre-#11211 build, not master](../learnings/1780648913125-correction-slang-11483-crash-was-a-stale-pre-11211.md)). The separate *miscompile* (nested-array members read garbage) is a wrong storage class: the fetch lowers to an `OpBufferPointerEXT` in **`Uniform`** instead of **`StorageBuffer`**, and the missing pointer-type `ArrayStride` is only the symptom. PR #11647's `processConstantBufferDescriptorHeapLoad` retypes it; the self-failing guard is a static spirv-asm FileCheck for `OpTypePointer StorageBuffer` + `ArrayStride` (a `StructuredBuffer.Handle` proxy is a false negative) ([Descriptor-heap ConstantBuffer miscompile = wrong storage class, not missing ArrayStride](../learnings/1783384030612-descriptor-heap-constantbuffer-miscompile-11483-wr.md)). #4472 (multidim-array assert) is still open; an old-release report on this surface (#11980) gets a ToT rebuild before any fixer dispatch ([Descriptor-heap ConstantBuffer<T> SPIR-V crash cluster — 3 fixes landed, verify at ToT](../learnings/1783459628122-descriptor-heap-constantbuffer-t-spir-v-crash-clus.md)).

**Strides.** For `DescriptorHandle<RaytracingAccelerationStructure>`, drive the runtime-array element type from the LOAD type (`uint64`) (AS size is opaque) ([spvDescriptorHeapEXT stride is opaque for AS — load-type must drive runtime-array base type](../learnings/1779962007180-spvdescriptorheapext-stride-is-opaque-for-as-load-.md)). The heap emits a distinct `OpTypeRuntimeArray` per `(descriptorElementType, arrayStride)`; a symbolic max stride via `OpSpecConstantOp Select(UGreaterThan(...))` over `OpConstantSizeOfEXT` passes the bundled spirv-val as an `ArrayStrideIdEXT` id ([spvDescriptorHeapEXT unified-stride: per-type arrays + symbolic-max construct (#11718)](../learnings/1782264945972-spvdescriptorheapext-unified-stride-per-type-array.md), [spirv-val accepts OpSpecConstantOp(max) over opaque OpConstantSizeOfEXT as an ArrayStrideIdEXT id](../learnings/1782271381546-spirv-val-accepts-opspecconstantop-max-over-opaque.md)).

**Texture atomics.** `processImageSubscript` rewrites the atomic dest into `IRSPIRVLoadTexelPointerFromHeap` (AddressSpace::Image) AFTER validation; `isValidAtomicDest` accepted `IRImageSubscript` but not the heap texel pointer (#11506, one-line fix). The `format=Unknown` spirv-val failure on bindless textures (#11130) is independent ([slang spvDescriptorHeapEXT: atomic-dest validator rejects heap texel pointers (E41403)](../learnings/1780865902537-slang-spvdescriptorheapext-atomic-dest-validator-r.md), [Descriptor-heap texture atomics: E41403 validator gap (#11506) is separate from format-Unknown spirv-val (#11130)](../learnings/1780869756318-descriptor-heap-texture-atomics-e41403-validator-g.md)).

## VariablePointers

`requireVariableBufferCapabilityIfNeeded` runs from value-materialization sites (var/phi/call/element-ptr/load), not signature emission, so a `Ptr<T, GroupShared>` surviving as a `[noinline]` parameter emits `OpTypeFunction %_ptr_Workgroup_T` with NO `OpCapability VariablePointers`. Fix: walk the function type in `emitFunc` gated on `IRNoInlineDecoration`, not `hasUses()` (inlined helpers keep uses, and a spurious cap triggers driver miscompile #9061). Isolate the repro so no value site self-declares the cap ([Slang SPIR-V variable-pointers cap is declared from value sites, not function signatures](../learnings/1780967438806-slang-spir-v-variable-pointers-cap-is-declared-fro.md), [Signature-derived SPIR-V VariablePointers must gate on [noinline], not hasUses() (driver bug #9061)](../learnings/1781023718622-signature-derived-spir-v-variablepointers-must-gat.md), [slang SPIR-V: isolating a signature-only VariablePointers cap repro (avoid value-site self-declare)](../learnings/1780970685981-slang-spir-v-isolating-a-signature-only-variablepo.md)).

**What the capability can lift.** Per `ValidateVariablePointer` in SPIRV-Tools `source/val/validate_memory.cpp`, a Function/Private OpVariable holding a pointer to **StorageBuffer** needs `VariablePointersStorageBuffer`, to **Workgroup** needs `VariablePointers`, and to **any other class, including `Uniform`**, is rejected whatever is declared. Slang lowers SSBOs to `Uniform`+`BufferBlock` before SPIR-V 1.4 and to `StorageBuffer`+`Block` from 1.4 (`getStorageBufferAddressSpace()`). On ≥1.4 VPSB is already declared and the module validates — on #13250 the default `Version: 1.5` passes, so the failure needs an explicit pre-1.4 profile and `-profile spirv_1_4` is a workaround ([default 1.5 validates](../learnings/1792404676930-slang-13250-default-spir-v-profile-1-5-validates-o.md)); on `-profile spirv_1_3` a `%_ptr_Function__ptr_Uniform_RWStructuredBuffer` slot cannot be fixed by any capability. Check "rejected approach" claims about spirv-val against the validator source or spec, not a citation into Slang's legalizer, and check which storage class the profile emits ([VP/VPSB lift the rule only for StorageBuffer/Workgroup pointees](../learnings/1790784612373-spir-v-function-var-holding-a-logical-pointer-vpsb.md), [pre-1.4 Slang SSBOs are Uniform](../learnings/1790785526520-spir-v-variable-pointers-cover-only-storagebuffer-.md)).

**groupshared by reference.** Lowering a `groupshared T arr[N]` parameter by reference (to fix D3D TGSM loss) creates a `Workgroup` pointer that cannot cross a SPIR-V function boundary without `VariablePointers`. Fix: extend the Khronos-gated `GLSLResourceReturnFunctionInliningPass::shouldInline` to inline callees with a groupshared-rate parameter, keyed on `as<IRGroupSharedRate>(param->getRate())`, not the value type ([groupshared by-reference param regresses Khronos SPIR-V; fix is Khronos-gated inlining keyed on param RATE](../learnings/1782237919713-groupshared-by-reference-param-regresses-khronos-s.md)).

## Atomics

Atomic emit has FOUR address-space gates, and a new `AddressSpace` case must touch all of them: (1) front-end l-value check E30047, (2) IR validator `isValidAtomicDest` E41403, (3) emitter `isAtomicableAddressSpace` (AtomicLoad/Store/Exchange only; a miss silently falls back to non-atomic `emitLoad`/`emitStore`), (4) `emitMemorySemanticMask` (a miss gives `memoryClass=0` → VUID-10870). `AtomicAdd`/`Inc`/`Dec`/`CompareExchange` bypass gate 3 ([SPIR-V atomic emit has TWO address-space gates — a per-address-space fix must touch both](../learnings/1782322436550-spir-v-atomic-emit-has-two-address-space-gates-a-p.md), [Slang SPIR-V atomic emission has 4 cross-layer gates keyed on address space — check all when reviewing atomic/VUID fixes](../learnings/1782346122322-slang-spir-v-atomic-emission-has-4-cross-layer-gat.md)).

**Memory order (#13518/#13519).** `Atomic<T>` methods and `__atomic_*` take `MemoryOrder` as a plain enum parameter; `emitMemorySemanticMask` maps it 1:1 with no per-op check, so `load(Release)`, `store(Acquire)` and invalid CAS pairs emit invalid SPIR-V with exit 0. Only VUID-10866 (SeqCst) is Vulkan/VulkanKHR-gated; 10867/10868/10875/10876 also fail under `--target-env spv1.5`. The order must be a compile-time constant: a non-inlined helper `uint ld(MemoryOrder o){ return a.load(o); }` gives E99997 (`getIntVal`) on SPIR-V/Metal while HLSL/GLSL/CUDA/WGSL drop the operand; `(MemoryOrder)7` hits `SLANG_UNEXPECTED` on SPIR-V and becomes `seq_cst` on Metal. The natural check site is `validateAtomicOperations` (`slang-ir-validate.cpp`, E41403), whose non-SPIR-V call is a `SLANG_PASS` in `slang-emit.cpp` that a grep for `validateAtomicOperations(` misses; both call sites run before final folding/DCE, so a constness check there misfires (see [[wiki/concepts/slang-compiler-probe-discipline-and-type-naming.md]]). `AllMemoryBarrier` emits AcquireRelease (0x948), not SeqCst as the docs say ([MemoryOrder: no per-op validation; non-constant order ICEs; only 10866 is Vulkan-gated](../learnings/1791462408563-slang-atomic-memoryorder-no-per-op-validation-non-.md)).

## Optimization-Level Effects

**Default opt is O1, so `-g2` runs spirv-opt.** `OptimizationLevel::Default` (`slang-compiler-options.cpp`) is not `None`; `glslang_optimizeSPIRV` early-returns only on explicit `-O0` with no `-Xspirv-opt`. The intermittent `SPVDB_DEBUGGER` failure — SPIRV-Tools `assert(unique_id_ != 0)` (`opt/instruction.h:251`) on macOS-aarch64 Debug — is therefore a latent slangc `-g2` debug-info emit/opt bug (introduced by #12896), not a spvdb integration problem: `libspvdb` never links SPIRV-Tools and the Step-1 compile runs in a fresh `UseExe` subprocess. It is a real bug with a flaky, Debug-only trigger, tracked as #13024 — cross-reference, don't re-file ([SPVDB_DEBUGGER failure is a slangc -g2 SPIR-V opt bug, not a spvdb-integration bug](../learnings/1789170739377-a-spvdb-debugger-debuginfo-slang-test-failure-is-a.md), [spvdb unique_id_ assertion is a real bug with a flaky trigger — tracked #13024](../learnings/1789179963682-spvdb-unique-id-assertion-on-macos-debug-aarch64-r.md)).

**Report static-const comparisons per opt level.** For a module-scope `static const` struct array (#13107), pre-fix master at `-O3` already emits a module-scope `OpConstantComposite` (spirv-opt folds the inlined `Record.$init`), so master and the fix look alike; the per-invocation reconstruction shows only at default opt (`OpCompositeConstruct` in the entry point) and `-O0` (`OpFunctionCall %Record__init`), while text targets show it even at `-O3`. The `Function`-var copy for dynamic indexing happens on both builds and is not evidence ([SPIR-V -O3 hides the static-const struct-table localization](../learnings/1790874683100-slang-spir-v-o3-hides-the-static-const-struct-tabl.md)).
