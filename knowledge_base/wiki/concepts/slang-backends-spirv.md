# Slang SPIR-V Backend: Emission, Capabilities, and Validation

The SPIR-V backend is Slang's primary Vulkan/Khronos target: a direct emitter (`slang-emit-spirv.cpp`), a legalization pass (`slang-ir-spirv-legalize.cpp`), and the bundled `slang-glslang` module for `spirv-opt`.

## TL;DR

- **Entry points:** `-fvk-use-entrypoint-name` auto-applies only with >1 entry point; a single-entry shader stays `"main"` and fails `pName-00707`. `[require(spirv_1_x)]` raises the version only if it reaches the CODEGEN IR module and `determineSpirvVersion()` matches internal `_spirv_1_x` atoms; else the header silently stays 1.0.
- **Capability gating:** gate capability-conditional emit on `targetCaps.implies(CapabilityAtom::spvFooEXT)`, never `isSPIRV(...)` (true for every SPIR-V target); `isSPIRV(format)`, not `isKhronosTarget` (matches GLSL text), is for format-family questions like profile version pinning. capdef atoms never auto-emit `OpExtension`/`OpCapability`.
- **Version:** comes from `getTargetCaps()`, not used functions' `[require]` (bundled spirv-val accepts SER at 1.4), and `-capability` silently raises it past `-profile` (a `CapabilitySet` join). Entry-point `[require]` never auto-emits `OpCapability` for `spirv_asm` builtin-loads; declare it inline (else VUID-…-08737).
- **API and enforcement:** name capabilities by STRING, never the `CapabilityName` int; capdef adds/reorders are non-breaking but trip `check-cmdline-ref` and `check-capability-atoms-ref`. E36107 enforcement is the type-level `[require]` on the shape struct (`__ShapeBuffer`); a method-level one on a case-less `__target_switch` is inert.
- **Never mutate a hoistable `SPIRVAsmOperandEnum`/`Literal`** (asserts, `slang-ir.cpp:179`); build a fresh, byte-identical one and repoint the consumer.
- **Descriptor heap:** parameterize only the INDEX of `SPIRVLoadDescriptorFromHeap`, never the `heap` global (it belongs in the cache key). `ConstantBuffer` garbage is a wrong storage class (Uniform vs StorageBuffer), not a missing `ArrayStride`. The AS heap is driver-managed (`vkUpdateDescriptorSets`, not memcpy). The bindless-vs-heap accessor is picked at `specializeTargetSwitch` from global caps; no emit edit honors a per-entry-point `[require]`.
- **Atomics:** four address-space gates (E30047, `isValidAtomicDest`/E41403, `isAtomicableAddressSpace` — a miss silently emits non-atomic load/store — and `emitMemorySemanticMask`, miss → VUID-10870). `MemoryOrder` has no per-op validation (invalid SPIR-V, exit 0); a non-constant one ICEs on SPIR-V/Metal. Float CAS cannot be lowered with Logical addressing (a logical pointer cannot be `OpBitcast`); only PSB and BAB work, so reject it on Vulkan (#14408).
- **VariablePointers:** signature-derived caps gate on `[noinline]`, not `hasUses()` (over-declaring → driver miscompile #9061). VP/VPSB help only Workgroup/StorageBuffer pointees; pre-1.4 SSBOs are `Uniform`, so `-profile spirv_1_3` is unfixable by capability.
- **Optimization:** default opt runs spirv-opt; only `-O0` runs none, but it masks spirv-opt aborts (#12247), and `CreatePrivateToLocalPass` breaks function-`static` persistence. Under `-O3`, exit 0 = FileCheck drift, 134 = real abort; `-O3` also folds a `static const` `$init` into a module-scope `OpConstantComposite`, so compare at default opt and `-O0` (consume the constant, or DCE hides it). A 4-constituent vec3 `OpConstantComposite` is spirv-opt's unsafe `x/x→1` fold. No `NoContraction` in default fp-mode is intentional (#11933): answer with `-fp-mode precise` (`precise` on a variable is ignored there).
- **Debug info:** `-g1 OpLine`/`-g2 DebugLine` come only from statement-granularity `IRDebugLine` markers; at `-g2` the source is embedded as `OpString`, so `CHECK-NOT` can match your own `//CHECK` text.
- **Validation:** a clean exit proves nothing; `//TEST:SIMPLE` and `spirv-asm` don't validate (CI sets `SLANG_RUN_SPIRV_VALIDATION=1`), so regression tests need real `-target spirv`. spirv-val silence proves nothing either way; read the spec (#12186: `OpConvertUTo*NV` accept uint64 or uint2).
- **Stale binaries, blind tools:** `build/Debug/lib` first in `LD_LIBRARY_PATH`, check `slangc -v`'s sha, `git merge-base --is-ancestor <fix> <tag>`, and revert-drill the triage predicate at HEAD ("`implies()` is inert on disjunctive caps" was a stale-binary artifact). `-dump-ir` is blind at both ends; disassemble for late questions. `grep -c nonUniformResourceIndex` also counts the capability-atom name.
- **DescriptorHandle:** `NonUniformResourceIndex` is dropped by the Cast round-trip. Width is `uint2` plain, `uint64` under `spvBindlessTextureNV`/cuda (audit ~8 consumers); a module-scope constant `OpBitcast` is invalid. When a second consumer guard still misses, fix the producer (#12186: kind-ungated read-back in `hlsl.meta.slang`).
- **Layout and varyings:** std140 row-major `float2x4` equals `float4[2]` and `-matrix-layout-*` skips arrays, so "array garbage, matrix fine" is host packing (except descriptor heap, #11483). Only `SV_Target<N>`'s suffix is an absolute location; user varyings go by declaration order.

## Entry Points and Module-Level Emission

Slang renames every SPIR-V entry point to `"main"`; `-fvk-use-entrypoint-name` (API `VulkanUseEntryPointName`) keeps the source name and auto-applies only with >1 entry point (PR #6260), so pass it uniformly or a single-entry shader fails VUID-VkPipelineShaderStageCreateInfo-pName-00707 ([Slang SPIR-V entry-point rename: auto-applies only with >1 entry point](../learnings/1779621920622-slang-spir-v-entry-point-rename-auto-applies-only-.md)).

`[require(spirv_1_x)]` sets the version only if `addEntryPointRequireCapabilityDecorations()` puts it on the **codegen IR module** (not just the layout module) and `determineSpirvVersion()` matches internal `_spirv_1_x` atoms, not the public alias; else `[require(spirv_1_5)]` leaves 1.0 ([CORRECTION to #11631 version root cause: require atom stamped only on layout IR module, not the codegen module determineSpirvVersion runs on](../learnings/1781643037138-correction-to-11631-version-root-cause-require-ato.md)).

**Adding a nullary entry-point attribute that maps to an execution mode** (`[postdepthcoverage]`, #12999/PR #13001): mirror `[earlydepthstencil]` across 9 sites (AST node, `attribute_syntax`, IR op + stable name, `isSimpleDecoration`, `addSimpleDecoration`, SPIR-V `Stage::Fragment` funnel, GLSL `Stage::Pixel` chain). `ASTNodeType` is FIDDLE-regenerated from declaration order, not append-only, so group the attribute with its siblings (a "renumbering" flag is a false positive). A new IR op bumps `k_maxSupportedModuleVersion` (`slang-ir.h`). `requireSPIRVCapability`/`requireSPIRVExecutionMode` are dedup'ing funnels with no capdef lookup; capdef atoms are needed only for front-end gating. PostDepthCoverage requires EarlyFragmentTests, so emit both. Test with `//TEST:SIMPLE(filecheck=CHECK): -target spirv`; "emitted exactly once" needs `COUNT-1:` plus a following same-pattern `-NOT:` ([adding a nullary entry-point attribute + SPIR-V execution mode: mirror earlydepthstencil across 9 sites](../learnings/1789107867239-adding-a-nullary-entry-point-attribute-spir-v-exec.md)).

## Builtin Variables and Memory-Access Masks

`IRSPIRVAsmOperandBuiltinVar` is `hoistable=true`, so cross-stage uses of one builtin (compute + raygen `SubgroupLocalInvocationId`) collapse to one inst via `_findOrEmitHoistableInst`; a cache-key axis on `BuiltinSpvVarKey` is dead code ([slang-spirv-asm-operand-builtinvar-is-hoistable-collapses-cross-stage](../learnings/1779617050641-slang-spirv-asm-operand-builtinvar-is-hoistable-co.md)). A side-table like `m_volatileBuiltinGlobalVars` in `getBuiltinGlobalVar` must be filled before the cache-hit early return, and `emitSPIRVAsm`'s `case SpvOpLoad:` needs the same handling because `spirv_asm` bypasses `emitLoad` ([slang-emit-spirv builtin-var cache and the volatile-set cache-hit trap](../learnings/1779612967874-slang-emit-spirv-builtin-var-cache-and-the-volatil.md)). Injecting a mask (e.g. `Volatile`) into a `spirv_asm` OpLoad with a user mask must emit ONE combined word, scanning both `kIROp_SPIRVAsmOperandLiteral` and `kIROp_SPIRVAsmOperandEnum` ([slang-emit-spirv-extra-memoryaccess-word-grammar-bug-pattern](../learnings/1779617068760-slang-emit-spirv-extra-memoryaccess-word-grammar-b.md)). Hoistable `SPIRVAsmOperandEnum`/`Literal` operands are value-numbered, so `setOperand` on them asserts at `slang-ir.cpp:179`; build a fresh operand and repoint the non-hoistable consumer (`spvInst->setOperand(maskIndex+1, newOperand)`) ([Never mutate a hoistable SPIRVAsmOperand in place; repoint the consuming inst](../learnings/1781725591470-never-mutate-a-hoistable-spirvasmoperand-in-place-.md), [SPIR-V asm-operand legalization: hoistable operands + foldable≠constant pitfalls](../learnings/1781726667133-spir-v-asm-operand-legalization-hoistable-operands.md)).

## Descriptor Heap (spvDescriptorHeapEXT)

The heap path uses `kIROp_SPIRVLoadDescriptorFromHeap`, not `IRCastDescriptorHandleToResource`; four specialization allowlists (`slang-ir-specialize-function-call.cpp`, `slang-ir-specialize-buffer-load-arg.cpp`) accepted only the cast (SIGSEGV #11498): fix the allowlists, not the downstream pass ([spvDescriptorHeapEXT path uses kIROp_SPIRVLoadDescriptorFromHeap, not IRCastDescriptorHandleToResource](../learnings/1780729707220-spvdescriptorheapext-path-uses-kirop-spirvloaddesc.md), [spvDescriptorHeapEXT path — fix function-call specialization allowlists, not the downstream pass](../learnings/1780733286644-spvdescriptorheapext-path-fix-function-call-specia.md)). The `heap` operand is the module-scoped `kIROp_SPIRVResourceHeap` global (`OpUntypedVariableKHR` in `UniformConstant`); parameterizing it as a `uint` makes the cloned callee's access-chain base a scalar, so parameterize only the index and key on the heap ([spvDescriptorHeapEXT specialization fix: don't parameterize the heap global](../learnings/1780734760813-spvdescriptorheapext-specialization-fix-don-t-para.md), [SPIRVLoadDescriptorFromHeap heap operand is a pointer global at emit — never parameterize it in call-spec](../learnings/1780769340224-spirvloaddescriptorfromheap-heap-operand-is-a-poin.md)).

**`ConstantBuffer` via the heap (#11483) is a cluster of distinct defects; rebuild at true HEAD before asserting a repro.** The `emitDescriptorHeapLoad` SIGSEGV reproduced only on pre-#11211 builds; master emits layout byte-identical to a bound `ConstantBuffer` and validates, so that half closed as test-only PR #11484 ([CORRECTION: slang#11483 crash was a stale pre-#11211 build, not master](../learnings/1780648913125-correction-slang-11483-crash-was-a-stale-pre-11211.md)). The separate miscompile (nested-array members read garbage) is a wrong storage class: the fetch lowers to an `OpBufferPointerEXT` in **`Uniform`**, not **`StorageBuffer`**; the missing `ArrayStride` is only the symptom. PR #11647's `processConstantBufferDescriptorHeapLoad` retypes it; the guard is a spirv-asm FileCheck for `OpTypePointer StorageBuffer` + `ArrayStride` (a `StructuredBuffer.Handle` proxy is a false negative) ([Descriptor-heap ConstantBuffer miscompile = wrong storage class, not missing ArrayStride](../learnings/1783384030612-descriptor-heap-constantbuffer-miscompile-11483-wr.md)). #4472 (multidim-array assert) is open; an old-release report (#11980) gets a ToT rebuild before fixer dispatch ([Descriptor-heap ConstantBuffer<T> SPIR-V crash cluster — 3 fixes landed, verify at ToT](../learnings/1783459628122-descriptor-heap-constantbuffer-t-spir-v-crash-clus.md)).

**Strides.** For `DescriptorHandle<RaytracingAccelerationStructure>` the AS size is opaque, so the LOAD type (`uint64`) drives the runtime-array element ([spvDescriptorHeapEXT stride is opaque for AS — load-type must drive runtime-array base type](../learnings/1779962007180-spvdescriptorheapext-stride-is-opaque-for-as-load-.md)). The heap emits one `OpTypeRuntimeArray` per `(descriptorElementType, arrayStride)`; a symbolic max stride via `OpSpecConstantOp Select(UGreaterThan(...))` over `OpConstantSizeOfEXT` passes spirv-val as an `ArrayStrideIdEXT` id ([spvDescriptorHeapEXT unified-stride: per-type arrays + symbolic-max construct (#11718)](../learnings/1782264945972-spvdescriptorheapext-unified-stride-per-type-array.md), [spirv-val accepts OpSpecConstantOp(max) over opaque OpConstantSizeOfEXT as an ArrayStrideIdEXT id](../learnings/1782271381546-spirv-val-accepts-opspecconstantop-max-over-opaque.md)).

**Texture atomics.** `processImageSubscript` rewrites the atomic dest into `IRSPIRVLoadTexelPointerFromHeap` (AddressSpace::Image) after validation, and `isValidAtomicDest` accepted `IRImageSubscript` but not the heap texel pointer (#11506, one-line fix). The bindless `format=Unknown` spirv-val failure (#11130) is independent ([slang spvDescriptorHeapEXT: atomic-dest validator rejects heap texel pointers (E41403)](../learnings/1780865902537-slang-spvdescriptorheapext-atomic-dest-validator-r.md), [Descriptor-heap texture atomics: E41403 validator gap (#11506) is separate from format-Unknown spirv-val (#11130)](../learnings/1780869756318-descriptor-heap-texture-atomics-e41403-validator-g.md)).

## VariablePointers

`requireVariableBufferCapabilityIfNeeded` runs from value-materialization sites (var/phi/call/element-ptr/load), not signature emission, so a `Ptr<T, GroupShared>` surviving as a `[noinline]` parameter emits `OpTypeFunction %_ptr_Workgroup_T` with no `OpCapability VariablePointers`. Fix: walk the function type in `emitFunc` gated on `IRNoInlineDecoration`, not `hasUses()` (inlined helpers keep uses; a spurious cap triggers driver miscompile #9061). Isolate the repro so no value site self-declares the cap ([Slang SPIR-V variable-pointers cap is declared from value sites, not function signatures](../learnings/1780967438806-slang-spir-v-variable-pointers-cap-is-declared-fro.md), [Signature-derived SPIR-V VariablePointers must gate on [noinline], not hasUses() (driver bug #9061)](../learnings/1781023718622-signature-derived-spir-v-variablepointers-must-gat.md), [slang SPIR-V: isolating a signature-only VariablePointers cap repro (avoid value-site self-declare)](../learnings/1780970685981-slang-spir-v-isolating-a-signature-only-variablepo.md)).

**What the capability can lift.** Per `ValidateVariablePointer` (SPIRV-Tools `source/val/validate_memory.cpp`), a Function/Private OpVariable holding a pointer to **StorageBuffer** needs `VariablePointersStorageBuffer`, to **Workgroup** `VariablePointers`, and to any other class (**including `Uniform`**) is rejected regardless. Slang lowers SSBOs to `Uniform`+`BufferBlock` before 1.4 and `StorageBuffer`+`Block` from 1.4 (`getStorageBufferAddressSpace()`), so ≥1.4 validates with VPSB while a `-profile spirv_1_3` `%_ptr_Function__ptr_Uniform_RWStructuredBuffer` slot is unfixable. Check "rejected approach" claims against validator source or spec, not Slang's legalizer, and check which storage class the profile emits ([VP/VPSB lift the rule only for StorageBuffer/Workgroup pointees](../learnings/1790784612373-spir-v-function-var-holding-a-logical-pointer-vpsb.md), [pre-1.4 Slang SSBOs are Uniform](../learnings/1790785526520-spir-v-variable-pointers-cover-only-storagebuffer-.md)).

**groupshared by reference.** Passing a `groupshared T arr[N]` parameter by reference (to fix D3D TGSM loss) creates a `Workgroup` pointer that cannot cross a SPIR-V function boundary without `VariablePointers`. Fix: the Khronos-gated `GLSLResourceReturnFunctionInliningPass::shouldInline` inlines callees with a groupshared-rate parameter, keyed on `as<IRGroupSharedRate>(param->getRate())`, not the value type ([groupshared by-reference param regresses Khronos SPIR-V; fix is Khronos-gated inlining keyed on param RATE](../learnings/1782237919713-groupshared-by-reference-param-regresses-khronos-s.md)).

## Atomics

A new `AddressSpace` case touches all four atomic gates: (1) front-end l-value check E30047, (2) IR validator `isValidAtomicDest` E41403, (3) emitter `isAtomicableAddressSpace` (AtomicLoad/Store/Exchange only; a miss silently falls back to non-atomic `emitLoad`/`emitStore`), (4) `emitMemorySemanticMask` (a miss gives `memoryClass=0` → VUID-10870). `AtomicAdd`/`Inc`/`Dec`/`CompareExchange` bypass gate 3 ([SPIR-V atomic emit has TWO address-space gates — a per-address-space fix must touch both](../learnings/1782322436550-spir-v-atomic-emit-has-two-address-space-gates-a-p.md), [Slang SPIR-V atomic emission has 4 cross-layer gates keyed on address space — check all when reviewing atomic/VUID fixes](../learnings/1782346122322-slang-spir-v-atomic-emission-has-4-cross-layer-gat.md)).

**Memory order (#13518/#13519).** `Atomic<T>`/`__atomic_*` take `MemoryOrder` as a plain enum that `emitMemorySemanticMask` maps 1:1 with no per-op check, so `load(Release)`, `store(Acquire)` and invalid CAS pairs emit invalid SPIR-V with exit 0. Only VUID-10866 (SeqCst) is Vulkan-gated; 10867/10868/10875/10876 fail under `--target-env spv1.5` too. The order must be a compile-time constant: a non-inlined `ld(MemoryOrder o){ return a.load(o); }` gives E99997 (`getIntVal`) on SPIR-V/Metal while HLSL/GLSL/CUDA/WGSL drop it; `(MemoryOrder)7` hits `SLANG_UNEXPECTED` on SPIR-V and becomes `seq_cst` on Metal. The natural check site, `validateAtomicOperations` (`slang-ir-validate.cpp`, E41403), has a non-SPIR-V call as a `SLANG_PASS` in `slang-emit.cpp` that grepping `validateAtomicOperations(` misses, and both call sites run before final folding/DCE, so a constness check there misfires (see [[wiki/concepts/slang-compiler-probe-discipline-and-type-naming.md]]). `AllMemoryBarrier` emits AcquireRelease (0x948), not SeqCst as the docs say ([MemoryOrder: no per-op validation; non-constant order ICEs; only 10866 is Vulkan-gated](../learnings/1791462408563-slang-atomic-memoryorder-no-per-op-validation-non-.md)).

**Float compare-exchange has no general SPIR-V lowering (#14408).** Bitcasting comparand, value and result through `uint` is not enough: `OpAtomicCompareExchange` needs pointee type == Result Type, so the pointer must become pointer-to-uint, and in Logical addressing spirv-val (`validate_logical_pointers.cpp`) rejects `OpBitcast` on a logical pointer ("Instruction may not have a logical pointer operand", per a `spirv_asm` `OpBitcast &buf[0]` probe). Only PhysicalStorageBuffer pointers and ByteAddressBuffer storage (via the uint view `__getEquivalentStructuredBuffer<uint>`) can be lowered; GLSL cannot reinterpret an lvalue, and Vulkan has no 16-bit integer atomics for half. The principled fix rejects float CAS destinations on Vulkan and keeps the BAB `*FloatBitwise` methods (as llvm/llvm-project#235837 does); PR #14412 (draft, 2026-11-08) reports E55204 for float/half/double CAS on SPIR-V/GLSL and moves the BAB `*FloatBitwise` CAS methods onto `uint` (review notes on [[wiki/concepts/slang-compiler-unsupported-shape-checks-and-emitter-use-checks.md]]) ([float CAS: logical pointers cannot be bitcast](../learnings/1794133299455-float-cas-on-spir-v-a-value-bitcast-is-not-enough-.md)).

## Optimization-Level Effects

**Default opt is O1, so `-g2` runs spirv-opt.** `OptimizationLevel::Default` (`slang-compiler-options.cpp`) is not `None`; `glslang_optimizeSPIRV` early-returns only on explicit `-O0` with no `-Xspirv-opt`. So the intermittent `SPVDB_DEBUGGER` failure (SPIRV-Tools `assert(unique_id_ != 0)`, `opt/instruction.h:251`, macOS-aarch64 Debug) is a slangc `-g2` debug-info emit/opt bug from #12896, not spvdb integration: `libspvdb` never links SPIRV-Tools, and the Step-1 compile is a fresh `UseExe` subprocess. It is real, with a flaky Debug-only trigger: cross-reference #13024 ([SPVDB_DEBUGGER failure is a slangc -g2 SPIR-V opt bug, not a spvdb-integration bug](../learnings/1789170739377-a-spvdb-debugger-debuginfo-slang-test-failure-is-a.md), [spvdb unique_id_ assertion is a real bug with a flaky trigger — tracked #13024](../learnings/1789179963682-spvdb-unique-id-assertion-on-macos-debug-aarch64-r.md)).

**Report static-const comparisons per opt level.** For a module-scope `static const` struct array (#13107), pre-fix master at `-O3` already emits a module-scope `OpConstantComposite` (spirv-opt folds the inlined `Record.$init`), so it looks like the fix; the per-invocation reconstruction shows only at default opt (`OpCompositeConstruct`) and `-O0` (`OpFunctionCall %Record__init`); text targets show it even at `-O3`. The `Function`-var copy for dynamic indexing happens on both builds and is not evidence ([SPIR-V -O3 hides the static-const struct-table localization](../learnings/1790874683100-slang-spir-v-o3-hides-the-static-const-struct-tabl.md)).
