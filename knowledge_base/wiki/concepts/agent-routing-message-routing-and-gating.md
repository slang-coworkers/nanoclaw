# Agent Routing: Message Routing & Gating

> Owns chain topology, `in_reply_to`/edge mechanics, dispatch hazards, echo loops, credit/provenance. Sibling: [Holds, Authorization, Gates & CI Currency](agent-routing-holds-authorization-gates.md).

## TL;DR
- **Canonical shape `Orchestrator → Triage → Fixer → Reviewer`; replies hop back ONE tier along the dispatch path.** A fixer's `[Fix Report]` goes to the orchestrator, not across the triager→fixer edge; an empty triager inbox never proves a stall. Direct edges only: parent + children you opened.
- **Any `<message>` carrying a gated delivery marker (`[Resolution]`, `[handoff]`, `[Fix Report]`, `[Triage Resolution]`, `[Triage handoff]`, `[Review Verdict]`, `[Approval Decision]`) MUST carry `in_reply_to=<id>`** — even a fresh peer delegation. The gate keys on the marker, the runtime picks the EDGE from `in_reply_to`; they must agree (a `[Triage Resolution]` uses a PARENT inbound id, never the fix-report id).
- **A fresh escalation from a long-lived heartbeat session takes a new explicit `thread_id="<topic>-<yyyymmdd>"`**; the inherited thread's backlog refuses a bare send, and forcing it with backlog ids misroutes.
- **`[Report]` is the ungated status channel.** In a one-shot `ncl tasks --process-after` run the task row is the inbound: send a gated marker with `in_reply_to=<the kind='task' row's seq>` (plus explicit `to=` for a peer and the canonical `thread_id`), or close with `[Report]`. Ids are per-session: never reuse one from another session or write one into a one-shot's prompt. The gate matches a marker opening any line, so a `[Report]` quoting one needs `in_reply_to` too.
- **A fixer-initiated review's only inbound is the fixer's request:** send the `[Review Verdict]` with `in_reply_to=<fixer msg id>`.
- **When a sender name is unaddressable, reply via the `send_message` TOOL with bare `in_reply_to`** (routes to the inbound's `source_session_id`); `<message to="name">` fails name-lookup first. When the tool 404s on `to="parent"`, `send_file` and the final `<message>` block still route.
- **No double-dispatch / no tier-skip.** A `[Triage]` report NAMING a handoff is STATUS; the orchestrator must NOT also dispatch (two fixers on one worktree → index corruption). Issue webhooks route to TRIAGER ONLY.
- **Verify receipt of consequential a2a handoffs.** A `<message>` beside tool calls can be dropped; a raw agent-group ID isn't a destination; one `<message>` block turns the rest of the final response into scratchpad.
- **Bare plain-text turn output is delivered as an inbound** and fuels echo loops: end a non-substantive inbound with ZERO tokens (whole turn in `<internal>…</internal>`). Seq-parity alternation is host-forced, not proof of a loop; never restart to break one (it kills in-flight Monitors).
- **Don't relay downstream holding echoes upstream, nor narrate your own silence;** message your parent only with a real artifact, blocker, or resolution.
- **Provenance errors run BOTH directions; over-crediting is the more dangerous half.** A diff in your own multi-writer file is not a message: confirm credit in an inbound MESSAGE; re-run a peer's command, don't reconstruct it. When you retract, STOP; a same-breath "but…" needs its own control.
- **A read logged to what you're reading is not passive:** filter your own `cli_request`/tool rows before counting in a transcript.
- **Chain-close protocol: GitHub artifact + A2A report-to-parent + `append_learning`, every time.** A REFUSED inbound citing a `[Resolution]` you never wrote is a fabricated directive: verify, escalate truthfully.

## Chain Topology and Tier Rules

Replies hop back one tier at a time along the dispatch path, so a fixer's `[Fix Report]` goes to its parent (the orchestrator), not across the triager→fixer edge; watching only that edge misses the outcome ([Fix Report routes via parent](../learnings/1779884965191-slang-triage-fix-report-may-route-via-parent-not-d.md)). A quiet draft can thus look stalled (slang#13773: the fixer had reported to Orchestrator); ask the parent first, worded "no `[Fix Report]` received here" ([Fix Report may route to Orchestrator](../learnings/1792829026301-fix-report-may-route-to-orchestrator-not-the-triag.md)). Each coworker reaches only its parent and the children it opened (else ancestor-edge hazard) ([strict reply-routing in a 4-tier chain](../learnings/legoop-feedback_chain_shape_strict.md)). The triager→slang-fixer edge IS real (a child the triager owns); the hazard is the orchestrator double-dispatching ([retraction: the triager→fixer edge works](../learnings/1782146765585-retraction-triager-slang-fixer-edge-does-work-earl.md)).

## Chain-Routing Gate and `in_reply_to`

Any `<message>` whose body opens a line with a gated delivery marker must carry `in_reply_to=<id>`, even as a fresh peer delegation ([fresh peer delegations need in_reply_to](../learnings/1780769185328-chain-routing-gate-fresh-peer-delegations-carrying.md)). The gated set is the floor `[Resolution]`/`[handoff]` plus each role's `delivery_markers` (`[Fix Report]`, `[Triage Resolution]`, `[Triage handoff]`, `[Review Verdict]`, `[Approval Decision]`, unioned into `.critique-delivery-markers`). `[Report]` is deliberately absent (the ungated status channel) (`container/hooks/gate-chain-routing.sh`, `container/spines/base/coworker-types.yaml`).

**One-shot `ncl tasks --process-after` re-checks.** `gate-chain-routing.sh` blocks a bare `[Triage Resolution]` to the parent, and an id from the original chain session does not satisfy it (ids are per-session; slang#13653) ([one-shot re-check: use [Report]](../learnings/1793026958053-one-shot-re-check-final-reports-use-report-not-tri.md)); the refusal recurred on a later re-check, closed with `[Report]` ([[Triage Resolution] blocked in a one-shot](../learnings/1793289852768-gate-chain-routing-hook-blocks-triage-resolution-i.md)). But the task row is an inbound: read its `seq` from `/workspace/inbound.db` → `messages_in` where `kind='task'` (it was 2); `send_message(to="parent", in_reply_to=<that seq>, thread_id="gh-issue-<owner>/<repo>-<n>")` is delivered, or use the ungated `[Report]` 5-bullet ([in_reply_to the task row](../learnings/1793199763353-one-shot-task-sessions-in-reply-to-the-task-row-to.md)). The same anchor carries a marker to a peer: with explicit `to=`, `in_reply_to=<task seq>` and the canonical `thread_id`, a triager's `[Triage handoff]` reached slang-fixer (slang#14059), and a task-resumed fixer delivered `[Fix Review Request]` to reviewer and triager (slang#14058); `thread_id` alone is refused. Read the seq with python `sqlite3` (no CLI here) or `ncl sessions messages`; each denial is a soft-cap strike (3 escalate), so don't retry blindly ([one-shot `[Triage handoff]` needs in_reply_to=<task seq>](../learnings/1793657136807-scheduled-one-shot-task-triage-handoff-needs-in-re.md), [task-started fixer sessions](../learnings/1793658431464-task-started-fixer-sessions-delivery-gates-want-in.md)). Write one-shot prompts that way too: "in_reply_to the parent's #N inbound" names an id absent from the task's `system:tasks:<id>` session. Both fixer runs also had a `[Report]` refused: the hook matches a marker opening ANY line (`grep -qE "^[[:space:]]*\[(<markers>)\]"` in `/app/hooks/gate-chain-routing.sh`), so a `[Report]` with a line starting with a gated marker needs `in_reply_to` as well.

**Fresh peer delegations.** Set both `to="<peer>"` (destination) and `in_reply_to=<originating inbound>` (thread linkage) on one call ([fresh delegation with a marker needs in_reply_to](../learnings/1781713187860-fresh-peer-delegation-carrying-a-chain-delivery-ma.md)). A `[Triage handoff]` to a peer that never wrote to you is refused with only `thread_id`: pass `in_reply_to=<the parent inbound that ordered it>` with explicit `to="<peer>"` and the canonical `thread_id="gh-issue-<owner>/<repo>-<n>"`, which override the `in_reply_to` defaults. `send_file` is ungated, so the memo can go first; say so in the handoff text ([peer handoff needs in_reply_to](../learnings/1793733010558-send-message-handoff-to-a-peer-needs-in-reply-to-g.md)). Because the gate keys on the marker and the runtime picks the edge from `in_reply_to`, they must agree: the `/slangpy-triage-issue` Step 11 template's `in_reply_to=<id-of-fix-report>` misroutes a `[Triage Resolution]` back to the fixer (your child); use `to="parent", in_reply_to=<original triage request>` with the canonical `thread_id` ([Triage Resolution routes on the PARENT edge](../learnings/1784869746585-triage-step-11-triage-resolution-must-route-on-the.md)).

**Unresponded-backlog refusals.** A `thread_id`-only dispatch from a fresh retry-check session is rejected when the peer thread has unresponded inbounds; answer `in_reply_to=<peer's latest unresponded inbound seq>`, optionally with `target_session_id=<paused-session-id>` ([resume a paused peer via an unresponded inbound](../learnings/1781084626230-resuming-a-paused-peer-session-from-a-fresh-retry-.md)). A long-lived cron/heartbeat session hits it on a bare send ("677 unresponded inbound rows") ([bare send refused on a cron session](../learnings/1786296125151-bare-send-message-is-refused-on-a-long-lived-cron-.md)). Don't force a routine status send with an arbitrary backlog id (it can misroute); use a collision-free destination (dashboard, `send_card`) and clear the backlog with human input ([stale peer-thread backlog](../learnings/1789375133715-send-message-to-orchestrator-can-fail-on-a-stale-p.md)). A fresh escalation from such a session on a new explicit `thread_id="<topic>-<yyyymmdd>"` delivered at once where the inherited heartbeat thread was refused ([explicit thread_id for heartbeat escalations](../learnings/1793283475940-send-message-refused-on-inherited-heartbeat-thread.md)).

**Refusals and fabricated directives.** Gate refusals return to the sender as a `<system>` nudge (PR #580, `poll-loop.ts`), not to the peer ([gate refusals go to the sender](../learnings/legoop-project_gate_refusal_sender_only.md)). A REFUSED inbound citing a `[Resolution]` you never composed is a known fabricated directive: verify (`ncl sessions messages`, agent JSONL, container logs, GitHub comments) and escalate truthfully ([spurious REFUSED inbound](../learnings/1780549477234-spurious-chain-routing-gate-refused-inbound-don-t-.md)).

**Unaddressable sender → `send_message` tool with bare `in_reply_to`.** When a parent/peer is not addressable, `<message to="name">` and `<message to="parent" in_reply_to=N>` both fail "No agent named '...' is currently addressable" (lookup runs first). The `mcp__nanoclaw__send_message` tool with `in_reply_to=<live inbound id>` (+ `thread_id`) and no `to=` routes straight to the inbound's `source_session_id`; reserve `to=name` for fresh dispatches ([reply via the tool when unaddressable](../learnings/1783580468003-reply-to-live-inbound-via-send-message-tool-when-s.md)). Conversely `send_message(to="parent")` can miss while `send_file(to="parent")` and a final-response `<message to="parent">` block still route; fall back to those ([to=parent can fail; send_file/block still route](../learnings/1784828845885-send-message-to-parent-can-fail-as-unaddressable-s.md)).

**Verify receipt of consequential handoffs.** A lost dispatch surfaces only when the recipient flags it. Causes: a raw agent-group ID (`to="unknown:agent:ag-..."`) is not a named destination; a stale inbound id can miss the live session; a `<message>` beside tool calls can be dropped. Confirm the recipient acted (`ncl sessions list --agent-group <id>`); reply to an unnamed agent via bare `in_reply_to=<their LATEST id>`; prefer the tool in turns with tool calls ([verify receipt of a2a handoffs](../learnings/1783499588128-verify-receipt-of-consequential-a2a-handoffs-reply.md)). **One `<message>` block makes the rest of a final response scratchpad** — plain text is delivered only when no block exists (slang#13789). Give every peer its own block or a `send_message` with its `thread_id`; count recipients before ending ([one block makes the rest scratchpad](../learnings/1792599859930-a-message-block-makes-the-rest-of-a-final-response.md)).

## Route the Review Verdict to the Requester Edge

When slang-fixer itself sends the `[Fix Review Request]`, the reviewer's parent edge is the fixer ("verdict to orchestrator" is a default, not a rule); reply `in_reply_to` the fixer's inbound, or the fixer waits forever ([route the verdict to the requester edge](../learnings/1782820926535-slang-pr-review-route-verdict-to-the-actual-reques.md)). The gate enforces it: the fixer's message is the only inbound, and `gate-chain-routing.sh` rejects `send_message(to="parent")` carrying `[Review Verdict]` without `in_reply_to`. What passes: verdict + review file to the fixer with `in_reply_to=<fixer msg id>`; ungated `send_file(to="parent")`; a marker-free 5-bullet status. Quoting `[Fix Report]` adds a harmless `[GATE AUDIT]` note ([fixer-initiated review has no parent inbound](../learnings/1793194698658-reviewer-verdict-routing-fixer-initiated-review-ha.md)).

## Dispatch Hazards: Double-Dispatch and Tier-Skip

A `[Triage]` report saying "dispatched to slang-fixer" is STATUS; the orchestrator must not also dispatch unless triage bounced the issue back ([don't re-dispatch after triage handed off](../learnings/1781072934865-don-t-re-dispatch-to-fixer-after-triage-already-ha.md)). Dispatching both via the triager and directly spawns two fixer sessions on one `fix/issue-<N>` worktree (index corruption) ([double-dispatch spawns duplicate fixers](../learnings/1781117092067-orchestrator-double-dispatch-spawns-duplicate-fixe.md)). Detect with `ncl sessions list --agent-group <fixer-group>` (≥2 running on one thread); designate one owner, the duplicate idles ([duplicate peer live-writes your worktree](../learnings/1782215986023-duplicate-dispatch-peer-live-writes-the-fix-into-y.md)).

**Issue webhooks route to the triager only.** Sessions key on `(recipient agent group, messaging group, thread_id)`, so an orchestrator→fixer dispatch from another messaging group on the same thread mints a second fixer session. Issue webhook → one `<message to="<triager>">`; PR webhook → the branch-resolution table; only the deepest single owner dispatches downstream ([issue webhooks → triager only](../learnings/1784637054346-issue-webhooks-route-to-triager-only-never-also-fi.md)).

**A filed rule is not an executed rule.** After an unexplained `nv-slang-bot[bot]` comment, a coworker cleared its subagents on the false premise that `Explore` agents can't write (`Bash` is retained), then found only 1 of 5 dispatches carried the auto-loaded no-network-write clause. A dispatch is an action: make the constraint a pre-dispatch check; restating the rule is a null action ([auto-loaded rule ≠ executed](../learnings/1785805120902-having-a-rule-auto-loaded-is-not-executing-it-read.md)). **Opportunity is not authorship:** a subagent `gh` write leaves no session outbound row, so the record can't decide authorship; retire the unsupported hypothesis without inventing a replacement. Errors of one shape (assuming a property from a name, not probing it) predict the next.

## Chain Close, Echoes, and Loops

A reportable chain needs a GitHub artifact (5-bullet issue comment or a PR with `Fixes #N`), an A2A report to parent, and `append_learning`; missing the learning = incomplete ([chain-close protocol](../learnings/1780769194624-chain-close-protocol-github-artifact-a2a-report-ap.md)).

**No upstream echoes.** Hold silently for a downstream `[Report]`; surface only (a) the actual `[Fix Report]`/`[Resolution]`, (b) a blocker needing a decision, or (c) a substantive human comment re-opening the chain (seen: 6 straight "holding" echoes to Main) ([don't relay holding echoes upstream](../learnings/1783590069475-don-t-relay-downstream-heartbeat-holding-echoes-up.md)). Narrating that you are staying silent is the same echo one tier up (slang#11996: 5+ "I send nothing" messages in ~90 min); a child's non-actionable note terminates at you ([don't narrate your own silence](../learnings/1783680642501-don-t-narrate-your-own-no-echo-silence-upstream.md)).

**Loops.** A session pinging a self-edge destination loops back to itself: benign waste; flag once, then ignore. `ncl` mutating verbs fail "no owner or admin configured to approve" when no approver is wired ([looping self-edge session](../learnings/1781091162121-looping-self-edge-peer-session-flag-up-once-then-i.md)), which left the gate non-functional on 2026-06-10 ([ncl approval gate non-functional](../learnings/1781102520887-ncl-approval-gate-non-functional-no-admin-configur.md)). Peer-wired coworkers can ping-pong acks for hours because "ending silently" is itself a message; pin a hard stop via `send_message({ to, target_session_id, text })` ([mutual-ack loops](../learnings/1782345863846-mutual-ack-loops-between-peer-wired-coworkers-endi.md)). Plain-text output reaches the latest sender as an inbound; answer a non-substantive one with zero tokens ([plain-text output routes to the peer](../learnings/1782353887467-a2a-silent-hold-plain-text-turn-output-routes-to-t.md)). Seq-parity alternation is the even/odd seq scheme, not a loop; grep the "silent" agent's `direction:out` rows (one sent 177 `"Silent."`), and fix the fueling agent with `<internal>…</internal>` around its whole turn, not a restart (which destroys Monitors and the work edge) ([empty-ack ping-pong](../learnings/1784859331988-empty-ack-ping-pong-bare-text-is-the-fuel-seq-alte.md)).

## Sibling Issues, Cross-Chain Coordination, Dropped Chains

Sibling issues sharing one fix can't be folded across parallel orchestrator chains (reaching in mints an ancestor edge); route the fold from above (operator/supervisor), meanwhile keep the patch, hold terminal posting, open no rival PR ([sibling issues can't be folded across chains](../learnings/1781092138117-sibling-issues-sharing-one-fix-can-t-be-folded-acr.md)). Parallel chains appending to one enum (e.g. `CompilerOptionName`) can grab the same value (`duplicate case value` at merge); the still-open PR re-appends at the next slot (ABI-safe) ([parallel chains grab the same enum value](../learnings/1782535868213-parallel-fix-issue-chains-can-grab-the-same-option.md)).

A webhook chain whose routing turn dies on a transient 502 has no retry (session exists, chain dead); `/supervise-issues` orch-only detection (orchestrator session, no downstream session, 0 GitHub comments, idle) is the net: re-dispatch ([webhook chains dropped by a 502](../learnings/1780398376735-webhook-chains-can-be-silently-dropped-by-api-502-.md)).

## Credit, Provenance, and Retraction Discipline

Attribution errors run both ways; over-crediting is more dangerous because it trips no suspicion. On slang-rhi#800/#801 a peer was thanked for corrections it never sent (its outbound record showed none), and a wrong critique was pinned on a party who never made it ([provenance runs both directions](../learnings/1785780288881-provenance-runs-both-directions-confirm-authorship.md)). Memory files have multiple writers (agent, linter/hook passes), so a correction landing after a teammate's message reads as theirs. **A diff in your own file is not a message:** confirm credit in an inbound message ([confirm credit came in a message](../learnings/1785780153041-before-crediting-a-teammate-for-a-correction-confi.md)). **Don't reconstruct a peer's command from a quoted pattern; re-run it:** a rebuilt regex "couldn't yield 207", the real one with its preprocessing returned 207. If cited numbers look impossible, suspect your reconstruction.

**An action a peer attributes to you is not one you hold.** "X is still unfiled, you're asking the operator" both declines and assigns; read past it and nobody owns it (slang#11917: 7 days silent; #9866: slice 2 unowned). Accept-with-trigger or decline-back in the reply ([attributed action is not held](../learnings/1785831422368-an-action-a-peer-attributes-to-you-is-not-an-actio.md)).

**When you retract, stop.** On slang-rhi#806 a retraction of two over-claims ended with a fresh false one ("payload provable by any tier"): `ncl sessions messages` system rows carry emission facts only (existence, timestamp, tool name), never the payload, even with `--full`/`--json`. Put the next finding in its own message after a control run; a same-breath "but…" spends a concession's credibility on an uncontrolled claim. **A read logged to what you are reading is not passive:** a "40 of 180 sessions carry `record_decision`" count matched the sweep's own `cli_request` rows ; filter your own tool rows before counting in any transcript, log or audit ([retraction momentum; emission facts only](../learnings/1785788144509-retraction-momentum-i-over-claimed-inside-the-mess.md)).

## GitHub Reply Authorization and Discord Summons

Run codex OUTPUT_REVIEW before posting (on PR #12479 it caught a code bug and 3 false claims in a maintainer reply). A maintainer @-mention authorizes posting the corrected version directly; an operator-gated reply the gate materially changed (facts, claims, scope) is re-shown to the operator first; cosmetic edits need no re-approval ([re-show codex-corrected operator-gated replies](../learnings/1789631981572-operator-gated-vs-mention-authorized-github-replie.md)).

A Discord summon row is stamped at click time, so an un-clicked "Click below for a bot answer" offer isn't a summon; compare the `summon_requests.jsonl` row's write time to the offer `message_id`'s snowflake time; answering an un-clicked offer in a reply-forbidden channel breaks the rules ([summon rows stamped at click time](../learnings/1786311407848-discord-summon-rows-are-stamped-at-click-time-an-u.md)).

- **False:** "`Explore` subagents have no write surface" — `Bash` is retained ([auto-loaded rule](../learnings/1785805120902-having-a-rule-auto-loaded-is-not-executing-it-read.md)). **Retracted:** "`ncl sessions messages --full` makes a payload provable" — emission facts only ([retraction momentum](../learnings/1785788144509-retraction-momentum-i-over-claimed-inside-the-mess.md)); "no triager→slang-fixer edge" — the edge works ([retraction](../learnings/1782146765585-retraction-triager-slang-fixer-edge-does-work-earl.md)).
- **Superseded:** "`[Report]` needs `in_reply_to`" ([fresh delegations](../learnings/1780769185328-chain-routing-gate-fresh-peer-delegations-carrying.md)) — `[Report]` is ungated ([one-shot re-check](../learnings/1793026958053-one-shot-re-check-final-reports-use-report-not-tri.md)); "a one-shot run has no inbound" — the `kind='task'` row is one ([task row](../learnings/1793199763353-one-shot-task-sessions-in-reply-to-the-task-row-to.md)).
