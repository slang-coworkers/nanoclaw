# Build Tooling: Testing a PR's Effect Locally, Shared-Clone Hazards, and Detaching Long Builds

## TL;DR

- **Test a PR's effect by extracting its merge-base delta, not by building its branch.** `git diff master..pr` on an old branch is polluted with the commits master gained since; use `git diff $(git merge-base master pr)..pr`. Then `git apply` the source-only delta onto an already-built master and bracket **apply → build → measure → revert**: one variable, one recompiled TU, instead of a whole branch (which also hits unpopulated submodules).
- **A build failure in a shared clone is not evidence about your patch.** Read the undefined symbol, find which file *generates* it, and check whether your diff touches that file. Run `git status --porcelain | grep -v '^??'` before AND after any build in a shared checkout; a sibling session mid-flight looks like your own breakage. Preserve foreign changes; **never `git checkout --` / `reset --hard`** a shared clone.
- **A long build launched inside an `Agent` subagent dies when the subagent's turn ends** (`ninja: build stopped: interrupted by user` is SIGINT from process-group teardown, not an operator). Detach with `setsid nohup ... &` and watch via `Monitor`. Discriminator: `grep -c "^FAILED:" build.log` == 0 plus "interrupted" = teardown.
- **A green test suite is not coverage.** A fix PR's green CI is *silent* about a slice its tests do not construct; measure the slice, don't infer it from the predicate.
- **Guards that make a local measurement worth anything:** a positive control that the PR's fix is LIVE in your binary; a must-fail pre-guard; a must-differ post-guard after revert; and `BUILD_EXIT` in the log as the only completion signal (a background wrapper reports exit 0 while still linking; compare binary mtime vs the recompiled object's).
- **Warnings-as-errors is per job.** Windows builds with MSVC `/WX`; macOS clang aarch64 and `static-unit-test-*-aarch64` build with `-Werror`; linux gcc builds do not. Repro one TU from `compile_commands.json` with `-fsyntax-only -Werror` (or `-Wshadow` for MSVC C4456), but use a real `-c -o /tmp/x.o` compile for middle-end warnings such as GCC `-Wunused-function`. GCC-only warnings reach an error only in the weekly `cmake-options.yml`.
- **A warning only GCC 14+ emits is invisible to CI** (x86-64 GCC 11.4, aarch64 13.3). Reproduce it on the Compiler Explorer API with an amalgamated TU (quoted includes inlined, PCH prepended, `#line` markers, flags from `compile_commands.json`) across many GCC ids, counting hits by script. Test at -O2/-O3; Debug and `-Os` often don't warn. A `-Wstringop-overflow` FP in `List::reserve` is silenced by a single-conjunct `SLANG_ASSERT` (release `SLANG_ASSERT` is `SLANG_ASSUME`). For a real local GCC 14, micromamba installs conda-forge `gxx_linux-64=14` in user space (`--ssl-verify "$SSL_CERT_FILE"` behind the OneCLI proxy).
- **VS2019 (MSVC 19.29) has no CI job but is still a documented preset.** It ICEs (C1001) on `constexpr std::to_array<const char*>` over string literals; probe MSVC versions on Compiler Explorer (`vcpp_v19_29_VS16_11_x64`), deduping `#ifndef`-guarded headers except the X-macro `slang-image-format-defs.h`.
- **GCC TSan can't RUN in this container** (high-entropy ASLR vs `libtsan.so.2`; the process dies before `main()`, every mitigation is EPERM / read-only), but you can BUILD with TSan by importing non-instrumented generators via `SLANG_GENERATORS_PATH`, and verify a `SKIP_SANITIZERS` boundary with `nm -D <lib>.so | grep __tsan_` + `ldd`. An uninstrumented library costs TSan false *negatives*, not positives. For a `source/core` mutex bug, link a tiny repro against `libcore.a` and read glibc mutex internals.
- **Slang CI runs a Debug slang-test**, so a plain `tests/` regression guards a `_DEBUG`-only assert; no release-level assert is needed.

## Extract the merge-base delta; don't build the branch

For "does open PR #N change this behaviour?", building the PR branch is often the expensive wrong move, and the obvious diff is the wrong diff. Two traps on slang #12386 vs PR #12304 ([test a PR's effect by extracting its merge-base delta](../learnings/1786000108097-test-a-pr-s-effect-by-extracting-its-merge-base-de.md)):

1. **A fresh `git worktree` has UNPOPULATED submodules**: configure died on a missing `SPIRV-Headers` target and wanted to clone+build DXC (~500 MB). Discriminator: `ls external/spirv-headers | wc -l` → 0 in the worktree, 16 in the main clone. The log was one line because `configure && build` short-circuited, so **`BUILD_EXIT=1` was a CONFIGURE failure**; read which stage failed before diagnosing.
2. **`git diff master..pr-branch` is NOT the PR's contribution**: on a 6-day-old branch it also held the 35 commits master gained since (134 KB of churn). `git diff $(git merge-base master pr)..pr` showed PR #12304's whole source contribution was one 4-line removal.

The cheaper method: extract the source-only delta, `git apply --check` it against current master, then bracket **apply → build → measure → revert** on the already-built clone. Non-negotiable guards: a **positive control that the fix is LIVE** in your binary (master emitted `struct Empty_0` count 1, patched 0; without it a null result is indistinguishable from an unpatched binary); a **must-fail pre-guard** (master still reproduces the bug); a **must-differ post-guard** after revert; and **`BUILD_EXIT` in the log as the only completion signal** (twice "completed" appeared with `slangc` older than the object it should have relinked). Shared-clone hazard: `ps` could not see another container's build (0 matches) but the artifact count could (objects 604 → 658 in 20 s); sample twice, snapshot binaries with a PROVENANCE file before measuring, and never mutate a worktree you didn't create. Payoff: the PR turned out to *widen* the bug (a shape that compiles today aborts with it applied), a land-order dependency a diff reading would have missed.

## A green suite is not coverage — measure the slice

On slang #12384 the fix for a sibling issue was in flight as PR #12304, CI green 27/0 ([a green CI on a fix PR is silent about a slice its tests do not construct](../learnings/1786000256187-a-green-ci-on-a-fix-pr-is-silent-about-a-slice-its.md)). **"Does the in-flight fix close my issue?" is a build, not a code read.** Building PR #12304's head against a pristine baseline showed it fixes the reported repro but leaves a residual **byte-identical**: `public __extern_cpp struct Empty {}` still mismatches, because `kIROp_ExternCppDecoration` is a separate case label from `kIROp_PublicDecoration` in the same switch and the PR removes only the `PublicDecoration` producer; a maintainer decides close-vs-keep-open on that measurement. **A green suite is not coverage**: all five of the PR's regression shapes were `ParameterBlock`/function-boundary, none an entry-point uniform parameter, the path the new issue reports. Enumerate the tests' shapes and state which axis none exercises.

The control that makes the rest trustworthy is a matrix cell whose expected result is AGREEMENT (a non-empty inner struct, reflection 8 / PTX 8); without it every MISMATCH is indistinguishable from a stuck instrument. Two cells were not constructible (`E30604`) and were reported as void: an inconclusive control means the construction can't test the claim, not that the claim is false. Run any proposed fix against the cells that currently *agree* (unconditional size-1 reflection for `Empty` would create a new mismatch on the passing no-`public` shape), and read closed PRs first (the reflection-side fix was tried and rejected in PR #8257).

## Warnings-as-errors differs by CI job: reproduce `/WX` and aarch64 `-Werror` locally

Windows CI compiles with `/WX`, so an MSVC warning is a hard failure that the Linux Debug preset (no `-Wshadow -Werror`) does not flag. The classic case is **C4456**: a new function-scope local whose name already exists as a local in a nested block later in the same function. On PR #12412, adding `astBuilder` at `validateEntryPoint` function scope collided with five later `astBuilder` locals, 5× C4456, while Linux Debug was green. Confine the new declaration to a local `{ }` block. Catch it without MSVC by recompiling that TU with `-Wshadow` from `build/compile_commands.json`: `CMD=$(jq -r '.[]|select(.file|endswith("myfile.cpp"))|.command' build/compile_commands.json | head -1); (cd build && eval "$CMD -Wshadow")`, and prove the detector live on the pre-fix version (expect the CI count) ([MSVC /WX C4456 shadow: Linux Debug can't catch it](../learnings/1789493968162-msvc-wx-c4456-shadow-linux-debug-build-can-t-catch.md)).

In `ci.yml` the linux gcc x86_64/aarch64 *build* jobs pass `warnings-as-errors: false`, but the macOS clang aarch64 builds and both `static-unit-test-*-aarch64` jobs keep the default `true` (`CMAKE_COMPILE_WARNING_AS_ERROR=ON`), so a PR green on every Linux and Windows test can fail 5 aarch64 jobs on a clang warning. On #12749 that went unnoticed for a month: `-Winconsistent-missing-override` (one sibling marked `override`, `shouldInline` not) and `-Wmissing-field-initializers` (aggregate init omitting a `HashSet` member). Fast repro: swap `-c` for `-fsyntax-only -Werror` in the TU's command; for clang also use `clang++` and add `-Wno-unknown-warning-option`, since the gcc-only flags error first. Clang 14 also reports two pre-existing `missing 'typename'` errors in core headers that CI's newer clang accepts; ignore those. Fix the code: add `override`, spell the initializer `{ref, {}}` ([x86/Windows green does not mean -Werror clean](../learnings/1792247797393-slang-pr-ci-x86-windows-green-does-not-mean-werror.md)). A GCC-only warning is the remaining hole: no PR or merge-queue job errors on it, and only the weekly `cmake-options.yml` catches it (see [CI Flake — Sweep Mechanics & Routing](ci-flake-sweep-mechanics-and-routing.md)).

**`-fsyntax-only` misses middle-end warnings.** GCC issues `-Wunused-function` during cgraph analysis, which `-fsyntax-only` skips, so it gives a false "no warning" for "does removing X leave an unused static?" (#13976). To answer it for one edited file without rebuilding an in-use worktree, take the TU's command, drop `-o`, `-c`, `-MD`, `-MF` and `-MT`, add `-iquote <worktree>/source/slang` so relative includes resolve from the `/tmp` copy, and compile with `-c -o /tmp/x.o` (a Release `slang-check-decl.cpp` takes 1–2 minutes). Slang's GCC flags have `-Wall -Wextra` but not `-Werror`, so an unused static is a warning there ([-fsyntax-only hides -Wunused-function](../learnings/1793209364198-tu-only-compile-drill-for-slang-fsyntax-only-hides.md)). `-Wshadow` and the clang warnings above do fire under `-fsyntax-only`.

## GCC- and MSVC-version-only problems: Compiler Explorer and micromamba

CI's GCC is old (2026-10 merge-queue logs: x86-64 11.4.0, aarch64 13.3.0), so a GCC 14+-only warning is invisible to every job. On slang#13770, GCC ≥ 14.1 (x86-64 and aarch64; not 11.4/12.2/13.x, not `-Os`) warns `__builtin_memcpy writing 1024 bytes into a region of size 256 [-Wstringop-overflow=]` at `List<T>::reserve`'s copy loop (`slang-list.h:387`) when many inlined `add()`s meet it (`unit-test-string.cpp:284-285`). It is a false positive: GCC cannot see `m_count <= m_capacity`. `SLANG_ASSERT(m_count <= m_capacity);` before `_allocate` silences it on 14.1–16.2 at -O2/-O3 because a release `SLANG_ASSERT` is `SLANG_ASSUME` (as `setCount` was fixed in #13754); the two-conjunct `SLANG_ASSERT(m_count >= 0 && m_count <= m_capacity)` still warns on 14.2/15.3, and a `values.reserve(N)` in the test does not help ([GCC 14+ -Wstringop-overflow FP in List::reserve](../learnings/1792503064030-gcc-14-wstringop-overflow-fp-in-slang-list-reserve.md)).

The container has only GCC 12, but the Compiler Explorer REST API accepts unauthenticated requests, so a fixer and a reviewer each verified base vs head without installing GCC ([reproduce via the Compiler Explorer API](../learnings/1792513384473-reproduce-a-gcc-version-only-warning-via-the-compi.md)). (1) Amalgamate the TU in Python: inline every quoted `#include "..."` (resolving against `source/`, `include/`, `tools/`, `source/slang/`), drop `#pragma once`, prepend the PCH (`cmake_pch.hxx` only includes `source/core/slang-basic.h`), inline `<ankerl/unordered_dense.h>` from `external/unordered_dense/include`, remove `#include "TargetConditionals.h"`, leave other system includes, and insert `#line` markers. Do not send `g++ -E` output, because glibc's preprocessed `_Float128` typedefs break GCC 14; the result is 640–720 KB. (2) Take flags from `build/compile_commands.json` (RelWithDebInfo = `-O2 -g -DNDEBUG -Wall …`), minus `-I`/`-include`. (3) POST to `https://godbolt.org/api/compiler/<id>/compile` (ids `g141` … `g162`, `arm64g1410`) with `{"source":…, "options":{"userArguments": flags + " -c", "compilerOptions":{"skipAsm":true}}}` and `Accept: application/json`. (4) Strip ANSI escapes from `stderr[].text`, write each result to its own file, and count `Wstringop-overflow` hits with awk, never by eye (a hand tally of 15 was really 14). 60 compiles take a few minutes on 4 threads. This reproduced the warning byte-for-byte on 14 of 19 configs before the fix and 0 after; Debug (`-Og -D_DEBUG`) and `-Os` often do not warn, so a clean result there says nothing. Scripts: `/workspace/agent/reports/pr-13770/{amalg.py,ce.py,matrix.sh}` (slang-fixer), `/workspace/agent/review-13782/ce.py` (reviewer). Side note: `/app/skills/slang-pr-review-runner/scripts/wait-run.sh` lost its exec bit in the read-only skills dir; call it as `bash …/wait-run.sh`.

**The same method answers MSVC-version questions, and VS2019 has no CI.** On slang#14069 (CE, 2026-10-29), `constexpr auto x = std::to_array<const char*>({"a", "bc"});` in a function body crashes cl 19.29 (VS 16.11, toolset 14.29.30133) with ICE C1001 at the closing `});`, at /Od and /O2; 19.30 (VS2022 17.0) and later compile it, so the boundary is 19.30, not 19.38. `std::to_array<StructWithConstCharPtrMember>({...})`, `constexpr const char* x[] = {...};` and CTAD `constexpr std::array x{...};` are fine on 19.29, and VS 16.10 rejects `/std:c++20` and lacks `std::to_array`. CI dropped VS2019 (`cmake-options.yml:96-97`, windows-2019 runner retired) while CMakePresets keeps `vs2019` and `docs/building.md` shows it, so VS2019-only breaks reach users unseen. For an MSVC amalgamation, treat `#ifndef X / #define X` guarded headers as once-only (Slang core headers use guards, not `#pragma once`; without dedup `unit-test-string.cpp` grew to 17 MB as `slang.h` was inlined 59 times; with it ~640 KB), but never dedupe `include/slang-image-format-defs.h`, an unguarded X-macro header. MSVC ids look like `vcpp_v19_29_VS16_11_x64`, and CE can execute MSVC builds (`filters.execute=true`, `compilerOptions.executorRequest=true`) ([MSVC 19.29 ICE C1001 on constexpr std::to_array](../learnings/1793318072513-msvc-19-29-vs2019-16-11-ice-c1001-on-constexpr-std.md)).

**A real GCC 14+ locally: micromamba in user space.** `curl -sSL https://micro.mamba.pm/api/micromamba/linux-64/latest | tar -xj -C /tmp/mm bin/micromamba`, then `MAMBA_ROOT_PREFIX=/tmp/mmroot /tmp/mm/bin/micromamba create -y -p /tmp/gcc14 -c conda-forge --ssl-verify "$SSL_CERT_FILE" gxx_linux-64=14`; the `--ssl-verify` flag is required because the OneCLI proxy's CA otherwise fails the repodata download. A full Slang build works with `-DCMAKE_C_COMPILER=/tmp/gcc14/bin/x86_64-conda-linux-gnu-gcc -DCMAKE_CXX_COMPILER=/tmp/gcc14/bin/x86_64-conda-linux-gnu-g++` (Ninja, RelWithDebInfo), tests with `LD_LIBRARY_PATH=/tmp/gcc14/lib`. An out-of-tree build dir fakes two `slang-unit-test-tool/` results: `optixMultipleDefinition` fails because OptiX headers are looked up three directories above the binary at `<root>/external/optix-dev` (`slang-nvrtc-compiler.cpp:858`), and `CapabilityGeneratorFailsOnError` is ignored because it needs `<build>/generators/<cfg>/bin`; copy `<build>/RelWithDebInfo` and `<build>/generators` under `<root>/build/` for a like-for-like run ([real GCC 14+ via micromamba](../learnings/1792602621339-get-a-real-gcc-14-in-a-slang-coworker-container-vi.md)).

## A build failure in a shared clone is not evidence about your patch

Setting up a guilty control on slang (patch one line of `hlsl.meta.slang`, rebuild, confirm the compiler rejects it), the build failed, and the reading "the patch breaks the build" was wrong and would have shipped a false public claim. The link error was `undefined reference to Slang::Diagnostics::EntryPointCannotThrow::getInfo()`, a symbol generated from `slang-diagnostics.lua`, which the patch never touched; `git status --porcelain` showed a sibling session mid-flight in the same clone had added a diagnostic, and the build swept in its unregenerated work ([a build failure in a shared clone is not evidence about your patch](../learnings/1786041592085-a-build-failure-in-a-shared-clone-is-not-evidence-.md)).

Rules: **read the undefined symbol, find which file declares or generates it, and check whether your diff touches that file**; a generated symbol (from a `.lua`, a fiddle template, a codegen step) failing to link usually means someone edited the generator. Run `git status --porcelain | grep -v '^??'` before AND after any build in a shared clone. **Preserve, never `git checkout --`**: copy foreign files plus a `git diff` patch to a scratch dir, revert only the file you edited, and `cmp`-verify theirs stayed byte-identical (a `checkout -- .` would have destroyed an in-flight change with a new diagnostic and two tests). When a control can't be completed, soften the claim and name the unobserved step (the verdict said a native arm "would not compile" is *inferred* from two measured things). A *different* link failure in the same tree (`getSearchDirectories()`) was a stale-link race: the defining object was newer than the link step, and re-running the identical build succeeded. Check that, and re-run once, before believing a link error.

## A long build in a subagent dies with the turn — detach it

Delegating a 20–40 min slang build to an `Agent` subagent has a failure mode: **when the subagent's turn ends, its child processes are reaped**, and the log ends `ninja: build stopped: interrupted by user.`, which reads like an operator cancel but is SIGINT from process-group teardown ([a long build inside an Agent subagent dies when its turn ends](../learnings/1786040718661-a-long-build-launched-inside-an-agent-subagent-die.md)). `grep -c "^FAILED:" build.log` == 0 plus `interrupted by user` = teardown, not a compile error (a real error prints `FAILED: <target>` plus diagnostics). Detach from the process group:

```bash
cd /path/to/worktree
setsid nohup cmake --build --preset debug >> build.log 2>&1 < /dev/null &
```

Confirm it took hold (`pgrep -x ninja`) and watch with a `Monitor`. **`run_in_background: true` alone is not sufficient**; the process still belongs to the turn's group. A relaunch is cheap: ninja is incremental, and slang's expensive stage-1 (`generate_core_module_headers`) completes early (check for `Compiling core module took N seconds` in the log). "Delegate builds to a subagent, it blocks until completion" holds for short commands; prefer `setsid` + `Monitor` for anything over ~10 min. Converse trap: `setsid bash script.sh` under `Bash(run_in_background)` forks, so the tool reports "completed" at once while the child runs; wait on the child's pid with a `kill -0 <pid>` loop ([setsid under run_in_background reports completed immediately](../learnings/1790721272121-check-that-a-fixer-s-promised-diagnostic-landed-gi.md)).

Two neighbouring traps from shader-slang/slang#13305: a background `codex exec` without `< /dev/null` prints "Reading additional input from stdin..." and hangs until the timeout, and CLI codex rounds are not recorded by the critique delivery gate (only `mcp__codex__codex` calls count). Rebuilding `slangc` (libslang.so) while `slang-test -use-test-server` runs kills the test servers mid-run, leaving no summary line, so finish every edit first and run the full suite once ([codex exec needs </dev/null; don't rebuild during slang-test runs](../learnings/1790645515788-ops-cla-breaks-with-git-c-user-name-c-user-email-c.md)).

## Sanitizer builds: TSan can't RUN in the container, but you can build and verify the boundary

Validating a `-DSLANG_ENABLE_TSAN=ON` change (slang#12707, GCC 12 / `libtsan.so.2`): **no GCC-TSan process can start here.** Any `-fsanitize=thread` binary, even a 10-line smoke test, dies before `main()` with `FATAL: ThreadSanitizer: unexpected memory mapping`, because the container's high-entropy ASLR (`vm.mmap_rnd_bits`) is incompatible with GCC 12's libtsan, and every mitigation is blocked (`sysctl -w vm.mmap_rnd_bits=28` → EPERM; `/proc/sys/kernel/randomize_va_space` read-only; `setarch -R` → `personality()` EPERM under seccomp; `unshare -Ur` → EPERM; newer gcc≥13 / clang≥16 runtimes need `install_packages`). TSan runtime testing needs a host with `--privileged` / `seccomp=unconfined`, a lower `vm.mmap_rnd_bits`, or `setarch -R`. **Building with TSan works** once the instrumented generators stop crashing at prelude generation: configure a `build-gen` tree with `-DSLANG_ENABLE_TSAN=OFF ... --target all-generators`, then the real tree with `-DSLANG_GENERATORS_PATH=$PWD/build-gen/generators/Release/bin`, so every generator is IMPORTED and uninstrumented ([GCC TSan builds cannot RUN in the container; use SLANG_GENERATORS_PATH](../learnings/1789544786329-gcc-tsan-builds-cannot-run-in-the-coworker-contain.md)).

**When the race can't be run, verify the instrumentation boundary** ([verifying a SKIP_SANITIZERS boundary + TSan false-positive reasoning](../learnings/1789546126437-verifying-a-skip-sanitizers-boundary-tsan-false-po.md)): `nm -D <lib>.so | grep -c __tsan_` and `ldd <lib>.so | grep tsan` showed `libslang.so` with 23 `__tsan_` symbols linking libtsan while `libslang-glslang*.so` had zero, proving the `SKIP_SANITIZERS` exclusion does what it claims (a legitimate, reportable partial result). The worry that excluding `slang-glslang` causes *false positives* is usually backwards: TSan's `pthread`/mutex interceptors are process-wide, independent of compile-time instrumentation, so an uninstrumented library's locking still forms happens-before edges; uninstrumented code costs false *negatives*. The only real false-positive window is non-interposed synchronization (lock-free handoff through uninstrumented raw atomics), which a boundary passing only per-call disjoint buffers closes; so prefer a targeted suppressions file over narrowing a skip to "ASan-only", which *increases* the false-positive surface.

**A concurrency bug in `source/core` can be shown without TSan or a rebuild.** clang-14 in the container also lacks `libclang_rt.tsan`. For slang#13786 (mutex misuse in `slang-writer.cpp`), a tiny `main.cpp` linked against `build/Debug/lib/libcore.a` sufficed: copy the `.cpp`'s `-I`/`-D`/`-isystem` flags from `build/compile_commands.json` (a plain `-I source -I include` fails on `ankerl/unordered_dense.h`) and link with `-lpthread -ldl`. To show an unlock of an unowned `std::mutex`, subclass it to reach `native_handle()` and read glibc's `pthread_mutex_t.__data.__nusers`, which underflows to `0xFFFFFFFF`; a `PTHREAD_MUTEX_ERRORCHECK` mutex returns `EPERM` for the same unlock. Run a deadlock repro in a detached `std::thread` under a timed `main` so it reports instead of hanging ([repro core-writer mutex bugs against libcore.a](../learnings/1792517123202-repro-core-writer-mutex-bugs-standalone-against-li.md)).

## Slang CI runs a Debug slang-test, so a plain `tests/` regression guards a `_DEBUG`-only invariant

For a `_DEBUG`-only assert (e.g. `checkIRDuplicate`'s "duplicate global instruction" abort in `slang-ir-link.cpp`), a normal `.slang` regression test under `tests/` **does** guard it in CI; no release-level `SLANG_RELEASE_ASSERT` or diagnostic is needed. `ci.yml` has Debug test jobs (`test-linux-debug-gcc-x86_64`, its `-rhi` twin, `test-macos-debug-clang-aarch64`) that run `slang-test` with the `slang-tests-…-debug` artifact, so the buggy compiler aborts there; Release silently tolerates the duplicate (verified at master `6eb89786ca` fixing #13257). To pin a `_DEBUG` abort's culprit without a rebuild, given a Debug `slangc`/`libslang.so`: run gdb with `set pagination off`, `start` (so `libslang.so` loads; a pending `break`/`commands` block does not bind reliably in batch), `break <fn>`, `ignore <bp> <n>` to reach the throwing call, then `bt`. gdb `printf` does not support `%.*s` (print an `UnownedStringSlice` via `%s` on `.m_begin`, null-terminated for mangled names) and does not apply C++ default arguments ([CI runs Debug slang-test, so `_DEBUG`-only invariants are guarded](../learnings/1790275762971-slang-ci-runs-debug-slang-test-so-debug-only-invar.md)).

## Checking 32-bit layout `static_assert`s without 32-bit libc headers

The container has no 32-bit libc headers, so a header including `<cstdint>` cannot be compiled for i386. A standalone mimic of the header wrapper that avoids `<cstdint>` (using `long long` and friends) still verifies 32-bit layout `static_assert`s with `clang++ -target i386-linux-gnu -fsyntax-only` ([i386 -fsyntax-only layout check](../learnings/1791828331890-track-critique-attested-parser-rejects-backtick-wr.md)).
