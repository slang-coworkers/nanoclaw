# Slang Code-Review Lenses

Concrete review lenses for the Slang compiler — the reusable "look here" heuristics that surface real bugs (and expose confident false positives) on refactor, null-invariant, and codegen PRs, the FileCheck-test nuances that decide whether a regression test actually pins the regression, and the redistribution / third-party-license-notice compliance lens for packaging PRs.

## TL;DR
- **Pure-matcher unit tests are not integration coverage.** A unit test proves the extracted helper is correct but says nothing about call-site wiring, ordering, or precedence. For slang-test, a `-dry-run` black-box check (assert the subtest is absent from dry-run stdout) exercises the real scheduling path without running tests.
- **Normalize-before-match blind spot.** When one side of a string comparison is canonicalized (e.g. via `Path::simplify`) and the other is assembled raw, matching silently fails on the platform where normalization isn't a no-op — Windows `kPathDelimiter` is `\`, so a name built with `/` won't match. For any "match a user string against an internal string" feature, check whether one side is normalized and whether the author only tested where normalization is a no-op.
- **When a fix adds a null-possible invariant + safe-access helper, audit ALL structurally-identical sites.** Grep the whole file for `<member>->` and confirm each remaining raw dereference is unreachable under the new condition or asserts/uses the helper. A missed sibling is a latent crash of the exact class just fixed; two reviewers flagging the same untouched site is strong convergence.
- **A reviewer-traced path can be foreclosed upstream by the front-end.** Before adding a regression test for a traced "gap" — and *especially* before treating a 🔴 crash / infinite-recursion / spurious-diagnostic finding as blocking — construct the triggering input and compile it against a built `slangc`. An earlier fatal diagnostic (E30702, E39997, E39999, E41001, E30820) can make the gap unreachable; a confident code trace is not proof the input is reachable, because automated reviewers reason from source and miss earlier rejections.
- **Don't add a recursion/cycle/depth guard for input an earlier fatal diagnostic already rejects** — it is dead code under correct input, which CLAUDE.md forbids (along with changes that have no failing test). Document the termination invariant at the function instead.
- **Trust codex's CONTENT verdict over the PostToolUse hook's stage-verdict parse** when they disagree.
- **FileCheck:** per-entry-point errors → split into separate entry points with per-entry prefixes; module-wide errors → ordered (non-DAG) `CHECK:` lines each pinning a distinct expected/got. Unanchored `CHECK-DAG: <code>` is the anti-pattern (a subset of cases can satisfy all DAG lines, silently missing a regression). A comment containing a literal `CHECK:`/`CHECK-DAG:` token is parsed as a real directive — reword it.
- **Third-party-license-notice PRs have plural edit sites and near-zero PR-CI coverage.** Redistribution notices land via a CPack `metadata`/`EXCLUDE_FROM_ALL` install component (platform ZIP/TGZ) AND the hand-assembled WASM packages in `release.yml` that `cp` files and bypass CPack — check both; and those install rules are exercised only at release-time `cpack`, not by any PR job. "BSD/MIT" includes MIT — audit statically-linked MIT deps (mimalloc, miniz), not just BSD/CPack. Ship each dep's OWN `LICENSE`/`COPYING` (with its specific copyright line), never a bare `LICENSES/*.txt` SPDX template; `reuse lint` checks out WITHOUT submodules so it neither catches missing submodule notices nor validates install-only files.

## Reviewer A's Lens: Extracted Matchers and Normalize-Before-Match

Two reviewer lenses that frequently surface on refactor PRs [PR-review lenses: extracted-matcher integration gap + normalize-before-match blind spot](../learnings/1780323605226-pr-review-lenses-extracted-matcher-integration-gap.md):

**Pure-matcher unit tests are not integration coverage.** Unit tests prove the extracted helper is correct but say nothing about the call-site wiring, ordering, or precedence. For slang-test specifically, a `-dry-run` black-box check (asserting the subtest is absent from dry-run stdout) exercises the real scheduling path without running tests.

**Normalize-before-match blind spot.** When CLI entries are canonicalized before storage (e.g. via `Path::simplify`) but the matcher compares by exact string against an assembled display name, the normalization round-trip is a silent gap. On Windows `kPathDelimiter` is `\`; strings assembled with `/` from a source `filePath` can fail to match. Any "match a user-supplied string against an internal string" feature — check whether one side is normalized and the other isn't, and whether the author only tested on the platform where normalization is a no-op.

## Null-Possible Invariant Audits

When a PR establishes a new null-possible invariant for a member (e.g. "`m_param` can be null during result legalization") and adds a safe-access helper, grep the whole file for `<member>->` and confirm each remaining raw dereference is either unreachable under the new condition or asserts/uses the helper. Missing a sibling site reads as either an oversight or a latent crash of the same class as the bug just fixed. Both Reviewer A and C flagging the same untouched sibling site is a strong convergence signal [PR-review heuristic: when a fix adds a null-possible invariant + helper, audit ALL structurally-identical sites](../learnings/1781792411472-pr-review-heuristic-when-a-fix-adds-a-null-possibl.md).

The audit sharpens when a fix *bundles* several guards at once and claims to "close the whole reachable class": the highest-value correctness check is to grep the deref pattern (`X->`) for **every site reachable from the entry point**, not to trust the PR's own enumeration. On slang#13020 (null `Parser::currentModule` on the module-less reflection path `findTypeByName`→`getTypeFromString`), the PR guarded 5 sites and added a null-tolerant `getCurrentLanguageVersion()` accessor, but `Parser::ParseStruct()` still read `currentModule->languageVersion` **unguarded** on the *identical* path (`_parseSimpleTypeSpec` calls `ParseStruct()` two lines above a guard the PR did add) — a raw segfault that escapes the `try/catch` the issue claimed to close. The structural signal (clarity C001 raised it independently): a consumer-guard approach **enforces nothing** — nothing stops a new `SLANG_LANGUAGE_VERSION_*` gate from routing through a raw `currentModule->` deref again — so recommend the PR document the invariant ("bare-deref sites are module-path-only") and ship the grep-audit itself. As with #11873 above, Devin (anonymous scrape) reported "low risk" and echoed the PR description here too: treat it as corroborating, never gating; the local correctness pipeline caught the real bug [Bundle null-guard fixes: grep-audit the whole reachable class, not the sites the PR lists](../learnings/1789161922124-bundle-null-guard-fixes-grep-audit-the-whole-reach.md).

## Reviewer-Traced Unreachable Paths

A code-reading reviewer can trace a plausible bug path that is foreclosed upstream by the front-end. Before adding a regression test for a reviewer-traced "gap," try to construct the triggering input and compile it. If it's rejected upstream (e.g. E30702 for `SV_DepthGreaterEqual` as input), the gap is unreachable — say so with the diagnostic code as evidence, and don't ship a test that can't compile [Depth SV semantics are output-only (E30702) — a reviewer-traced 'inout duplicate' gap can be unreachable](../learnings/1782175276058-depth-sv-semantics-are-output-only-e30702-a-review.md).

This applies with full force to **🔴 crash / infinite-recursion / spurious-diagnostic findings**, which read as blocking. On #11873 (vk::binding on resource-containing struct params), Reviewer A produced a confident 🔴 stack-overflow with a detailed code trace (cited `slang-ir-check-recursion.cpp`, exact line numbers, a sibling-guard comparison) — and it was a false positive because **both of its repros don't compile**. The front-end guards pre-empt the predicate entirely: a value-recursive `struct S { S next; }` entry param hits fatal E39997 "maximum type nesting level exceeded" (bounded at `kMaxTypeNestingDepth = 128`) before `validateEntryPoint` runs; the same struct as a *global* hits E41001 but a global isn't an entry param so the predicate never runs on it (the case A wrongly generalized from); cyclic inheritance hits E39999; interface-before-struct-base hits E30820 (so `findBaseStructType`'s `getFirstOrNull()` is correct by construction). Rule: for any reviewer crash/recursion/spurious-diagnostic claim, **compile the exact repro against a built slangc before treating it as blocking**. Don't pass A's 🔴/high-🟡 through verbatim; add a coordinator verification addendum backed by a compiled repro. (Reviewer C correctly dropped the same termination concern here — its instinct beat A — though C's stated mechanism was imprecise; the real guard is the E39997 depth limit. Reviewer B echoed the PR body: weak signal.) ([Reviewer A (nv-slang-bot) can emit confident false-positive crash bugs whose repros do not compile — always compile the repro](../learnings/1782885111139-reviewer-a-nv-slang-bot-can-emit-confident-false-p.md))

Corollary decision (same #11873 / PR): when a reviewer flags a new recursive walk for "missing a cycle/depth guard that sibling functions carry," do NOT reflexively add the guard — first check whether the divergent input is rejected by an EARLIER fatal front-end diagnostic before your code runs (here E39997/E39999 reject value-recursive/cyclic types before `validateEntryPoint`, so a visited-set would be dead code under correct input). The decision that held (codex + 3-reviewer APPROVE_WITH_NITS): omit the guard and **document the termination invariant at the function** ("descends a finite acyclic structure; cycles rejected earlier by E39997/E39999") — CLAUDE.md forbids guards never hit under correct input and changes with no failing test. Also reinforced: **trust codex's CONTENT verdict over the PostToolUse hook's stage-verdict parse** — the hook parsed the stages as "approve" while codex's content verdict was request-changes for a real, harness-verified item (an unnecessary `non-exhaustive` on a DIAGNOSTIC_TEST, which `slang-test` reports as a failure); a DIAGNOSTIC_TEST should use plain `diag=CHECK` unless you deliberately leave diagnostics unmatched ([Don't add a recursion guard for input an earlier fatal diagnostic already rejects](../learnings/1782886466163-don-t-add-a-recursion-guard-for-input-an-earlier-f.md)).

Two 2026-09 rounds sharpen this into a **finding-vs-remedy** rule and its mirror-image **reachability** rule, both about verifying a reviewer's higher-confidence output empirically before acting. First, when a correctness reviewer's finding ships a "Suggested fix," treat the *finding* as the high-value output and the *remedy* as a lower-confidence hypothesis — a plausible fix can be actively wrong, so verify it at source or label it "reviewer's suggestion, unverified." On slang#13086 round 6 Reviewer A correctly found that a direct-resource combined-sampler diagnostic under `spvBindlessTextureNV+spvDescriptorHeapEXT` misdirects the user, but BOTH of A's proposed fixes were wrong at source: "route it through the EXT-heap helper" is a **silent miscompile** (`__makeCombinedTextureSamplerFromHandle` consumes the whole `uint2` — both the resource *and* sampler lanes — while the single-index branches use `handle.x`, so a `uint2(index,0)`-built handle silently zeroes the sampler index) and "add `static_assert(!usesNativeSpirvDescriptorHandle<This>())`" is a **regression** (that predicate is true for every NV-encodable type, so it also rejects the currently-working plain `Texture2D t = ResourceDescriptorHeap[i]`). The durable descriptor-handle fact: a `CombinedTextureSampler` genuinely needs BOTH `uint2` lanes, so a single-index path cannot construct one — the *rejection* is correct and only the misdirecting message is the bug, whose right fix is a maintainer message/workflow call, not a speculative patch that trades a loud-but-wrong diagnostic for a silent miscompile ([a bot reviewer's proposed FIX is lower-confidence than its FINDING — verify suggested remedies at source](../learnings/1789652286088-a-bot-reviewer-s-proposed-fix-is-lower-confidence-.md)). Second — the exact mirror of the E39997/E41001 pre-emption above, and of the #13033 "errors ≠ unreachable" lesson — a reviewer's "SIGSEGV on valid input" inferred from an O(depth) native-stack recursion is THEORETICAL until an input is shown to reach that recursion at depth *past* upstream guards. On slang#12563 Gap 1 a flagged eager `processFunction` re-entry (slang-ir-specialize-address-space.cpp:537/:561) is real recursion, but a 3000-deep pointer-forwarding-chain repro exited 255 with a clean fatal E39997 at ~128 — the invoke-lowering guard `kMaxIRInvokeLoweringRecursionDepth = 128` (slang-lower-to-ir.cpp:5513, verified in-source) pre-empts the overflow — so it is a latent O(depth) coupling to *track*, not a crash to disclose. BOTH directions of a reachability claim (reachable-crash and unreachable-dead-code) need an empirical demo, never static inference: before disclosing a "crash on valid input" (1) confirm an input reaches the recursion at depth, (2) check for upstream caps that pre-empt it, (3) if capped, reframe-and-track as a low-priority robustness follow-up (better than dropping the real recursion or posting a false scare) — and verify a recant against its anchoring code fact (the `=128` constant) exactly as you would the original claim ([reviewer-flagged 'crash on valid input': verify reachability empirically past upstream guards](../learnings/1789689508202-reviewer-flagged-crash-on-valid-input-verify-reach.md)).

## New-Interface-Requirement Completeness and Many-to-One Enum Collisions

When a Slang PR adds an associated-constant requirement (e.g. `static const bool isBindlessTextureNVEncodable;`) to a widely-implemented interface like `IOpaqueDescriptor` **with no default value**, it is a *hard* requirement: every conformer must supply it or the core module fails to type-check. So the reviewer question "did any conformer get missed / inherit a wrong default?" is answered definitively by (1) confirming from the diff that the requirement has **no default** — a defaulted `= false` is the dangerous case, because an odd conformer can then silently inherit the wrong value — and (2) a green core-module build; you do NOT need to hand-enumerate every conformer to prove completeness. What still needs a positive per-kind test is *value* correctness for the conformers where the coarse enum diverges from the IR type class: `DescriptorKind` collides many-to-one, so SubpassInput (kind=Texture but `IRSubpassInputType` → must be false) and TextureBuffer (kind=UniformTexelBuffer but `IRTextureBufferType` → must be false) differ from plain textures/samplers (true). Route the predicate on the SAME classifier the consumer uses (here the C++ `isBindlessTextureNVEncodableResourceType = as<IRTextureType> || as<IRSamplerStateTypeBase>`), and require a per-kind test that actually reaches that consumer. Corollary caught in the same review (slang#13086): a `static_assert` placed inside a `case spvBindlessTextureNV:` arm fires under plain-NV AND NV+EXT (a `static_assert` is checked post-specialization on the surviving case), so a diagnostic whose suggested remedy only works when a *second* capability is also enabled can misdirect the user toward a path that silently miscompiles in the single-capability config — flag both the possible `pr: breaking` implication (previously-compiling code now hard-errors) and the misdirecting remedy ([reviewing a new interface requirement with no default — build-green answers 'any conformer missed?'](../learnings/1789560871840-reviewing-a-new-interface-requirement-with-no-defa.md)).

## FileCheck Test Nuances

Several review-time FileCheck lessons apply across the review pipeline [slang-pr-review: scope a re-run to focused verification when the re-push is test-only](../learnings/1782594329649-slang-pr-review-scope-a-re-run-to-focused-verifica.md):

- For a per-entry-point availability error, split into separate entry points with per-entry filecheck prefixes to isolate each case.
- For a module-wide semantic error, use ordered (non-DAG) `CHECK:` lines, each pinning a distinct `expected/got` pair. Unanchored `CHECK-DAG: <code>` is the anti-pattern: a subset of cases can satisfy all DAG lines, silently missing a regression.
- A comment containing a literal `CHECK:`/`CHECK-DAG:` token is parsed by FileCheck as a real directive — reword such comments.

## License / Redistribution-Notice Review

Reviewing a third-party-license-notice / redistribution-compliance PR (the class that arose from slang#12302 → PR #13021, follow-up #13023 → #13040) has its own reusable checklist, and it is easy to under-cover. **The edit sites are plural.** An `install(... COMPONENT metadata)` rule in the top-level `CMakeLists.txt` only reaches the platform ZIP/TGZ archives through CPack; the **WASM release packages are hand-assembled in `.github/workflows/release.yml`** (both `${base}` and `${base_libs}` do `cp -R`, exiting before `cpack`) and bypass CPack entirely, so a notice added only as a CPack rule never lands in the WASM zips — always check `release.yml`'s manual staging, guarding each `cp`/`install` on the vendored-source flags (`SLANG_OVERRIDE_*_PATH`, `SLANG_USE_SYSTEM_*`) so notices ship only when the submodule is the actual build source. **"BSD/MIT" means MIT too:** MIT's "include the copyright notice in all copies" is the same binary-redistribution obligation as BSD, so audit statically-linked MIT deps (`mimalloc` links into `core` for the default Windows MSVC shared release; `miniz` is the same class), and watch that a guard variable like `SLANG_BUILD_MIMALLOC` is `set()` in `external/CMakeLists.txt` without `PARENT_SCOPE` (invisible where the install rules live — duplicate its boolean inline and comment why). **Ship the dep's OWN `LICENSE`/`COPYING` file** (renamed to disambiguate, e.g. `cmark-COPYING`), never a bare `LICENSES/BSD-2-Clause.txt` template — BSD/MIT require the *specific* copyright-holder line the SPDX template lacks, and cmark's `COPYING` is itself multi-license. **`reuse lint` is not the safety net:** the `reuse-compliance` job checks out WITHOUT submodules, so it never sees submodule notices; and dropping a bare `LICENSES/BSD-2-Clause.txt` REDS it as an *unused* license — but that unused-license argument is **BSD-specific** (`LICENSES/MIT.txt` and `Apache-2.0.txt` already exist and are used, so for the MIT/Apache class the correct reuse-green reasoning is simply "adds nothing to `LICENSES/`; notices ship via the `metadata` component"). **Per-license obligation differs, state it precisely:** MIT = reproduce the dep's actual copyright lines; Apache-2.0 §4(a) = give a copy of the license, and §4(d) NOTICE-carry triggers **only if the upstream Work ships a NOTICE file** (spirv-tools has none → LICENSE-only is correct — verify with `ls external/<dep>/NOTICE`). **Header-only ≠ "no compiled code in the binary":** `fast_float`'s `from_chars` is compiled into the lexer, and `spirv-headers`' grammar JSON is transformed at build time into generated C++ (`slang-lookup-tables`) that links into the shipped `slang` — so an INTERFACE dep can still put derived content in the binary via codegen. Finally, **`COMPONENT metadata` + `EXCLUDE_FROM_ALL` install rules have essentially zero PR/merge-CI coverage** (materialized only by release-time `cpack`; `ci-slang-build.yml` installs `--component generators`, `cmake-options-build.yml` installs with no component), so a path typo or bad `RENAME` passes every PR and fails only at a release tag — a cheap guard is a GPU-free step running `cmake --install build --component metadata --prefix X` and asserting the files land. On sequencing: a follow-up notice PR that edits the same CPack block must land AFTER its precedent PR (merge-conflict + adopt the same per-dep-vs-aggregated form), and any `.github/workflows/*` half is blocked by the bot's missing App `workflows` scope, so deliver it as a maintainer-applied `git apply` patch ([license-notice PRs: check MIT deps + install-component CI coverage, not just BSD/CPack](../learnings/1789164645783-slang-license-notice-prs-check-mit-deps-install-co.md); [ship the dep's own file, not a bare SPDX template](../learnings/1789218594018-slang-third-party-bsd-mit-license-notice-complianc.md); [MIT/Apache reuse-lint reasoning differs from BSD; spirv-headers ships codegen](../learnings/1789248098319-slang-third-party-notices-mit-apache-reuse-lint-re.md); [Apache §4(d) NOTICE precondition + sequence behind the precedent PR + bot workflows-permission wall](../learnings/1789167340037-third-party-license-notice-follow-ups-apache-4-d-n.md)).
