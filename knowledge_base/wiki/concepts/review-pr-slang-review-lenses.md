# Slang Code-Review Lenses

Reusable "look here" heuristics for Slang compiler review: lenses that surface real bugs (and expose confident false positives) on refactor, null-invariant, and codegen PRs; FileCheck nuances that decide whether a test pins the regression; and the license-notice lens for packaging PRs.

## TL;DR
- **Unit tests of an extracted matcher are not integration coverage** of call-site wiring, ordering, or precedence. For slang-test, assert the subtest is absent from `-dry-run` stdout.
- **Normalize-before-match blind spot:** if one side of a string match is canonicalized (`Path::simplify`) and the other assembled raw, it fails where normalization is not a no-op (Windows `kPathDelimiter` is `\`).
- **A "single source of truth" refactor's risk is the sites it left behind.** Grep for every reader of the same facts. "Pure refactor, no new tests" holds only if behavior is identical for ALL inputs.
- **A checker relaxation of a receiver rule needs its lowering half** (`moveIntoMutableTemp`, not `tryGetAddress` of read-only storage) and a probe of overloaded calls through implicit `this`, where `OverloadedExpr::base` is null and the checker's receiver test is skipped.
- **New null-possible invariant + safe-access helper → grep every `<member>->` reachable from the entry point**, not the sites the PR lists. A consumer-guard approach enforces nothing; ask for the invariant to be documented. Two reviewers flagging the same untouched site is strong convergence.
- **A null shape can have several producers:** guard at the consuming helper, not one exact shape.
- **Compile the repro against a built `slangc` before treating a 🔴 crash / recursion / spurious-diagnostic finding as blocking**, and before adding a test for a traced "gap". Earlier fatal diagnostics (E30702, E39997, E39999, E41001, E30820) and depth caps (`= 128`) often foreclose the path; automated reviewers reason from source and miss them.
- **Both directions of a reachability claim need an empirical demo.** "Possibly dead, so assert it" needs one mixed-user probe; a residual scoped to an exotic flag/shape needs a plain control. Baseline "fails before" on the reviewed head, not master.
- **A bot reviewer's finding is higher-confidence than its suggested fix.** Verify the remedy at source or label it "reviewer's suggestion, unverified".
- **Don't add a recursion/cycle/depth guard for input an earlier fatal diagnostic rejects**; it is dead code under correct input. Document the termination invariant at the function.
- **Trust codex's CONTENT verdict over the PostToolUse hook's stage-verdict parse** when they disagree.
- **Prove a PR's marks are consumed by reverting them and rebuilding.** For a widened `_canLValueCoerce`, value-test an integer-matrix `inout` on `-cpu`.
- **A no-default interface requirement is proven complete by a green core-module build**; per-kind *value* tests are still needed where `DescriptorKind` diverges from the IR type class.
- **FileCheck:** per-entry-point errors → separate entry points with per-entry prefixes; module-wide errors → ordered `CHECK:` lines, each pinning a distinct expected/got. Never unanchored `CHECK-DAG: <code>`. A directive token in a prose comment parses as a directive. `CHECK-COUNT-1` after a DAG block is not an exactly-one guard. A `-NOT` guards only the gap between its two neighbouring positive CHECKs. Under `-g2`, anchor on `OpExtInst` and capture IDs.
- **`-fno-exceptions` guard PRs:** say "behaviorally equivalent", not "byte-identical" (`#if` lines shift `__LINE__`); an unreachable catch still forfeits its recovery.
- **License-notice PRs have plural edit sites and near-zero PR-CI coverage:** the CPack `metadata` component AND the hand-assembled WASM packages in `release.yml`. MIT deps count. Ship each dep's OWN `LICENSE`/`COPYING`, never a bare SPDX template. `reuse lint` checks out without submodules.

## Extracted Matchers and Normalize-Before-Match

A unit test of an extracted matching helper proves nothing about how the call site wires, orders, or prioritizes it; for slang-test, a `-dry-run` black-box check (subtest absent from stdout) exercises the real scheduling path without running tests. When CLI entries are canonicalized before storage (`Path::simplify`) but compared by exact string against a display name assembled with `/` from a source `filePath`, the match silently fails on Windows: check whether only one side is normalized and whether the author tested only where normalization is a no-op ([extracted-matcher gap](../learnings/1780323605226-pr-review-lenses-extracted-matcher-integration-gap.md)).

## Unify / Single-Source-of-Truth Refactors

When a PR routes N consumers through one canonical query (slang#13213: implicit-`this` passing mode via `getDeclaredThisParamPassingMode`), grep every reader of the same facts (`hasModifier<Mutating/Ref/ConstRef/NonmutatingAttribute>`, `isLeftValue` on `this`) and diff with the migrated set. #13213 left ≥4: two AST-synthesis sites plus hardcoded `SetterDecl` branches in `visitThisExpr`/`_lookUpInScopes` that skip `[nonmutating]`. It also changed the contradictory `[mutating][ref]` case, so "pure refactor, the suite is the contract" was false; ask for a `//DIAGNOSTIC_TEST` that *rejects* the contradiction (as the code's own "we should be diagnosing this" comment asks) over an `//TEST:INTERPRET` pinning the accidental resolution ([unify refactor](../learnings/1790034772740-reviewing-a-unify-into-a-single-source-of-truth-re.md)).

**Receiver-mode relaxations.** slang#13964 / PR #13966 relaxed E30050 for a non-l-value receiver. Checker-only is not enough: lowering's `addCallArgsForParam` would pass `tryGetAddress` of a cbuffer member (a pointer into read-only storage), so the fix passes a `moveIntoMutableTemp` copy; reverting the lowering hunk failed CPU, Vulkan and DXIL tests ([receiver-mode fix needs its lowering hunk](../learnings/1793143062366-slang-tests-hlsl-files-are-gitignored-diagnostic-c.md)). A lowering branch keyed on `!baseExpr->type.isLeftValue && writable(mode)` also fires for calls the checker never examined: for an overloaded call through implicit `this`, `OverloadedExpr::base` is null, so `TryCheckOverloadCandidateDirections` skips its receiver test. Probe with overloaded `[mutating]` / `[__ref]` methods called through implicit `this` from a non-mutating method, in plain `.slang` ([implicit-`this` overloads](../learnings/1793153753122-filecheck-buffer-with-output-using-type-small-digi.md)).

## Null-Possible Invariant Audits

When a PR establishes that a member can be null (e.g. `m_param` during result legalization) and adds a safe-access helper, grep the whole file for `<member>->` and confirm each raw dereference is unreachable under the new condition or uses/asserts the helper. A missed sibling is a latent crash of the class just fixed; Reviewers A and C flagging the same untouched site is strong convergence ([audit ALL identical sites](../learnings/1781792411472-pr-review-heuristic-when-a-fix-adds-a-null-possibl.md)).

When bundled guards claim to close the whole class, grep **every site reachable from the entry point**, not the PR's list. slang#13020 (null `Parser::currentModule` on the module-less reflection path `findTypeByName`→`getTypeFromString`) guarded 5 sites and added a null-tolerant `getCurrentLanguageVersion()`, yet `Parser::ParseStruct()` still read `currentModule->languageVersion` unguarded on the same path (`_parseSimpleTypeSpec` calls it two lines above an added guard): a segfault outside the `try/catch` the issue claimed to close. Clarity C001 found it too. Consumer guards enforce nothing (a new `SLANG_LANGUAGE_VERSION_*` gate can reintroduce a raw `currentModule->` deref), so recommend documenting the invariant ("bare-deref sites are module-path-only") and shipping the grep-audit. Devin's "low risk" echoed the PR body: corroborating, never gating ([grep-audit the reachable class](../learnings/1789161922124-bundle-null-guard-fixes-grep-audit-the-whole-reach.md)).

A null shape can have several producers. A `DeclRefExpr` with a null `declRef` comes from error recovery for an undefined name (a named `VarExpr` with `ErrorType`) and from the reflection `specializeWithArgTypes` placeholder (unnamed); `getValidTypeForAddressOf` hits `ensureDecl(null)` for both. #11709 exempted only the placeholder (`isTypeOnlyPlaceholderArg`); a round-2 subagent reproduced the other producer as SIGSEGV (rc=139 on the PR, clean E30015 on master). Guard the null `declRef` in `getValidTypeForAddressOf`; `__getAddress(undefinedVar)` already segfaults on master ([null declRef has two producers](../learnings/1790744483226-reviewer-a-s-merge-step-can-drop-a-subagent-s-veri.md)).

## Reviewer-Traced Paths: Verify Reachability Empirically

Before adding a test for a traced "gap", construct and compile the triggering input; if the front-end rejects it (E30702 for `SV_DepthGreaterEqual` as input), report the gap unreachable with the diagnostic code as evidence and don't ship a test that cannot compile ([depth SV semantics are output-only (E30702)](../learnings/1782175276058-depth-sv-semantics-are-output-only-e30702-a-review.md)).

**False 🔴 crashes.** On #11873 (vk::binding on resource-containing struct params), Reviewer A gave a confident stack-overflow with line numbers and a `slang-ir-check-recursion.cpp` citation; neither repro compiles. A value-recursive `struct S { S next; }` entry param hits fatal E39997 "maximum type nesting level exceeded" (`kMaxTypeNestingDepth = 128`) before `validateEntryPoint` runs; as a global it hits E41001 but is not an entry param (A's wrong generalization); cyclic inheritance hits E39999; interface-before-struct-base hits E30820, so `findBaseStructType`'s `getFirstOrNull()` is correct by construction. Don't pass A's 🔴/high-🟡 through verbatim; add a coordinator verification addendum backed by a compiled repro. Reviewer C correctly dropped it; Reviewer B echoed the PR body ([false-positive crash bugs](../learnings/1782885111139-reviewer-a-nv-slang-bot-can-emit-confident-false-p.md)).

**Dead guards.** On the same PR a reviewer wanted the cycle/depth guard sibling walks carry; E39997/E39999 reject such types before `validateEntryPoint`, so a visited-set is dead code. The decision that held (codex + 3-reviewer APPROVE_WITH_NITS): omit it and document the termination invariant at the function ("descends a finite acyclic structure; cycles rejected earlier by E39997/E39999"). The PostToolUse hook parsed codex's stages as "approve" while its content verdict was request-changes for a real item: an unnecessary `non-exhaustive` on a DIAGNOSTIC_TEST, which `slang-test` reports as a failure. Use plain `diag=CHECK` unless you deliberately leave diagnostics unmatched ([no dead recursion guard](../learnings/1782886466163-don-t-add-a-recursion-guard-for-input-an-earlier-f.md)).

**Finding vs. remedy.** On slang#13086 round 6, Reviewer A correctly found that a direct-resource combined-sampler diagnostic under `spvBindlessTextureNV+spvDescriptorHeapEXT` misdirects the user, but both fixes were wrong at source. Routing through the EXT-heap helper silently miscompiles (`__makeCombinedTextureSamplerFromHandle` consumes both `uint2` lanes while the single-index branches use `handle.x`, so `uint2(index,0)` zeroes the sampler index). `static_assert(!usesNativeSpirvDescriptorHandle<This>())` regresses: the predicate is true for every NV-encodable type, so it also rejects the working `Texture2D t = ResourceDescriptorHeap[i]`. The rejection is correct; only the message is the bug, a maintainer call ([FIX < FINDING](../learnings/1789652286088-a-bot-reviewer-s-proposed-fix-is-lower-confidence-.md)).

**Depth caps.** A "SIGSEGV on valid input" inferred from O(depth) native-stack recursion is theoretical until an input reaches that depth past upstream guards. On slang#12563 Gap 1, the eager `processFunction` re-entry (slang-ir-specialize-address-space.cpp:537/:561) is real recursion, but a 3000-deep pointer-forwarding repro exited 255 with a clean fatal E39997 at ~128 because `kMaxIRInvokeLoweringRecursionDepth = 128` (slang-lower-to-ir.cpp:5513) pre-empts it: a low-priority robustness follow-up, not a crash to disclose. Verify a recant against its anchoring code fact (`= 128`) like the original claim ([verify past upstream guards](../learnings/1789689508202-reviewer-flagged-crash-on-valid-input-verify-reach.md)).

**Plain controls.** Strip the exotic part of a scoped residual and re-run before accepting the scope. On slang#12563 a false E58005 was framed for weeks as "mutual recursion only, under `-disable-non-essential-validations`"; a non-recursive control (`int* r; if(c) r=&gShared; else r=helper(); return r;`) reproduced it in default mode. The address-space slot pre-pass ran before the worklist fixpoint settled call results, so `getStoredValueAddrSpace` read the call's declared `Ptr<T>` default (PhysicalStorageBuffer) as a second storage class; a pre-pass that runs before a fixpoint must treat every unsettled value (calls, params) as unknown. Suppression of provisional recursive results is keyed on the back-edge CALL inst, not the function (a root-wide set hid a real E58003 from a settled call outside the cycle). Baseline "fails before" on a build of the reviewer's exact head, not master ([non-recursive control](../learnings/1792301451882-run-a-reviewer-s-shapes-plus-a-non-recursive-contr.md)).

**Mixed-user probes.** On slang#13726 R2, Reviewers A and C argued the stage half of a new placement check (E58004) was probably dead because `interpolateAt*` requires the fragment stage, and suggested `SLANG_ASSERT`. A vertex EP reading the shared global plainly plus a fragment EP interpolating it reaches the branch, which rejects a module master compiles to valid SPIR-V; the assert would have turned a compile error into an assertion crash. Such a restriction usually binds one consumer: probe other users of the value, then recommend a test that reaches the branch or removing the condition, never an unchecked assert ([probe 'possibly dead'](../learnings/1792217256305-possibly-dead-branch-claims-from-static-reviewers-.md)).

## Proving a Mark or Conversion Is Actually Consumed

When a PR adds attribute marks "so the gate can trust them", revert them all and rebuild. On #11387 the 16/16 tests still passed after the gate's lookup changed, proving the marks were no longer consumed; no reviewer could establish that by reading ([revert the marks and rebuild (#11387)](../learnings/1790799086877-reviewer-a-set-repo-root-to-a-private-worktree-to-.md)).

When a PR widens `_canLValueCoerce` (`slang-check-expr.cpp`) for `inout`/`out` arguments, check `lowerLValueCast`'s shortcuts. `_canReinterpretCast` (C/C++/CUDA) and `_canRemoveCastForHLSL` compare only element base type and size, ignore matrix layout, and run before `specializeMatrixLayout`, so a same-size **integer** matrix differing only in layout gets a `reinterpret_cast` instead of a copy and writes the wrong element (float matrices take the temp-copy path and hide it). On #13378 a `column_major int2x3` buffer field passed to `inout int2x3` wrote `n[0][1]` instead of `n[0][2]` ([layout-blind _canReinterpretCast](../learnings/1790904342903-concurrent-reviewer-a-runs-clobber-the-shared-slan.md)).

## New Interface Requirements and Many-to-One Enum Collisions

An associated-constant requirement with **no default** on a widely implemented interface (slang#13086: `static const bool isBindlessTextureNVEncodable;` on `IOpaqueDescriptor`) must be supplied by every conformer or the core module fails to type-check. So "any conformer missed?" is answered by the diff showing no default (a defaulted `= false` is the dangerous case: an odd conformer silently inherits it) plus a green core-module build. Value correctness still needs per-kind tests where the coarse enum diverges from the IR type class: `DescriptorKind` collides many-to-one, so SubpassInput (kind=Texture, `IRSubpassInputType`) and TextureBuffer (kind=UniformTexelBuffer, `IRTextureBufferType`) must be false, unlike plain textures/samplers. Route the predicate on the consumer's classifier (`isBindlessTextureNVEncodableResourceType = as<IRTextureType> || as<IRSamplerStateTypeBase>`) and require a test reaching that consumer. A `static_assert` in a `case spvBindlessTextureNV:` arm fires under plain-NV and NV+EXT (checked post-specialization), so a diagnostic whose remedy needs a second capability can steer single-capability users toward a silent miscompile; flag that and the possible `pr: breaking` implication of now-erroring code ([no-default requirement](../learnings/1789560871840-reviewing-a-new-interface-requirement-with-no-defa.md)).

## FileCheck Test Nuances

- Per-entry-point availability error: separate entry points with per-entry filecheck prefixes. Module-wide semantic error: ordered (non-DAG) `CHECK:` lines, each pinning a distinct `expected/got` pair. Unanchored `CHECK-DAG: <code>` lets a subset of cases satisfy every DAG line and silently miss a regression ([scope a re-run to focused verification](../learnings/1782594329649-slang-pr-review-scope-a-re-run-to-focused-verifica.md)).
- slang-test's FileCheck scans prose comments too: any literal `CHECK:`, `CHECK-COUNT-<n>`, `CHECK-NOT`, `CHECK-NEXT`, or `CHECK-DAG` token parses as a (usually malformed) directive, e.g. `// then CHECK-COUNT-1 + CHECK-NOT pins it` fails with `invalid count in -COUNT specification` at the comment line. Spell around the token ([directive tokens inside prose comments](../learnings/1790163672721-slang-test-filecheck-parses-directive-tokens-insid.md); [two review-round gotchas](../learnings/1790222348386-two-review-round-gotchas-filecheck-check-tokens-in.md)).
- `CHECK-COUNT-1:` right after a `CHECK-DAG:` block is not a robust exactly-one guard: the count scans from the DAG group's MAX match position, so an earlier duplicate can fall outside the window. When the records are distinct anyway, prefer plain `CHECK-DAG` positives and don't over-claim dedup coverage ([two review-round gotchas](../learnings/1790222348386-two-review-round-gotchas-filecheck-check-tokens-in.md)).
- Under `-g2`, SPIR-V embeds the shader source (CHECK lines included) as an `OpString`, so `CHECK: <source text>` can self-match. Anchor on `OpExtInst %void %{{[0-9]+}} <Op>` and capture numeric IDs (`CHECK-COUNT-1` over IDs, not text); stays GPU-free ([directive tokens inside prose comments](../learnings/1790163672721-slang-test-filecheck-parses-directive-tokens-insid.md)).
- A `-NOT:` constrains only the text between its immediately preceding and following positive CHECKs. Before propagating "this `-NOT: func %` is unsatisfiable", check what brackets it: in slang#13252 the flagged line sat in an ORIG→WRAP decoration gap with no `-NOT`, and the pipeline's editorial filter correctly dropped it (a recurring false-positive class). Prefer order-insensitive `CHECK-DAG` captures by type-shape over an ordering-sensitive `[DebugFunction([[X]])]` / `-NOT: func %` / `[entryPoint(` fence, and run the editorial filter before relaying raw subagent flags ([CHECK-NOT window](../learnings/1790231335186-filecheck-check-not-window-a-not-only-guards-the-g.md)).

## Reviewing -fno-exceptions Guard PRs (the #12779 series)

Two precision traps (non-blocking for the mechanical code) recur in `SLANG_EXCEPTION_TRY` / `#if SLANG_HAS_EXCEPTIONS` guarded-catch PRs. "Byte-identical to the exceptions-ON build" is wrong when `#if`/`#endif` lines change: they shift every later `__LINE__`, baked into `SLANG_RELEASE_ASSERT` (→ `handleAssert(__LINE__)`, `source/core/slang-common.h`) and debug line tables; say "behaviorally equivalent; only source-location/debug metadata shifts." And "the removed catch is unreachable" ≠ "dropping it loses nothing": its recovery (diagnostics, `SLANG_FAIL` fallback returns, language-server survival) is forfeited in that config. A Slang abort terminates in `handleSignal()`, not "→ exit(-1)" (`SLANG_BREAKPOINT(0)`/`__builtin_trap()` may trap first on GCC; `catch (...)` also caught non-Slang exceptions that never reach `handleSignal`). The `-fno-exceptions` build has no CI yet (`SLANG_HAS_EXCEPTIONS` is 1 unless `SLANG_DISABLE_EXCEPTIONS`), so the disabled branch is uncovered until the series lands the CMake option + compile job ([-fno-exceptions traps](../learnings/1790224226872-two-accuracy-traps-when-reviewing-fno-exceptions-t.md)). Which public `SLANG_NO_THROW` methods still lack a guard, and the `link()` form to copy, are on [[wiki/concepts/slang-compiler-api-exception-boundary-guards.md]].

## License / Redistribution-Notice Review

From slang#12302 → PR #13021 and follow-up #13023 → #13040:

- **Plural edit sites.** An `install(... COMPONENT metadata)` rule in the top-level `CMakeLists.txt` reaches only the platform ZIP/TGZ via CPack. WASM packages are hand-assembled in `.github/workflows/release.yml` (`${base}`/`${base_libs}` `cp -R` and exit before `cpack`), so stage notices there too, guarding each `cp`/`install` on the vendored-source flags (`SLANG_OVERRIDE_*_PATH`, `SLANG_USE_SYSTEM_*`) so they ship only when the submodule is the build source.
- **MIT counts.** Audit statically linked MIT deps (`mimalloc` links into `core` for the default Windows MSVC shared release; `miniz` likewise). `SLANG_BUILD_MIMALLOC` is `set()` in `external/CMakeLists.txt` without `PARENT_SCOPE`, so it is invisible where the install rules live; duplicate the boolean inline with a comment ([check MIT deps + install-component CI coverage](../learnings/1789164645783-slang-license-notice-prs-check-mit-deps-install-co.md)).
- **Ship the dep's own file** (renamed, e.g. `cmark-COPYING`), never a bare `LICENSES/BSD-2-Clause.txt` template: BSD/MIT require the specific copyright line the SPDX template lacks, and cmark's `COPYING` is multi-license. `reuse lint` is no safety net: the `reuse-compliance` job checks out without submodules, and a bare `LICENSES/BSD-2-Clause.txt` REDS it as an unused license ([ship the dep's own file](../learnings/1789218594018-slang-third-party-bsd-mit-license-notice-complianc.md)). That reuse argument is BSD-specific: `LICENSES/MIT.txt` and `Apache-2.0.txt` already exist and are used, so for MIT/Apache the point is "adds nothing to `LICENSES/`". Header-only ≠ no compiled code: `fast_float`'s `from_chars` compiles into the lexer, and `spirv-headers`' grammar JSON becomes generated C++ (`slang-lookup-tables`) linked into `slang` ([MIT/Apache reuse; spirv-headers](../learnings/1789248098319-slang-third-party-notices-mit-apache-reuse-lint-re.md)).
- **Per-license obligations:** MIT = reproduce the dep's copyright lines; Apache-2.0 §4(a) = include the license; §4(d) NOTICE-carry applies only if upstream ships a NOTICE (spirv-tools has none, so LICENSE-only is correct; check `ls external/<dep>/NOTICE`). A follow-up PR editing the same CPack block lands AFTER its precedent (adopt the same per-dep-vs-aggregated form), and any `.github/workflows/*` half is blocked by the bot's missing App `workflows` scope, so deliver it as a maintainer-applied `git apply` patch ([Apache §4(d), sequencing](../learnings/1789167340037-third-party-license-notice-follow-ups-apache-4-d-n.md)).
- **No PR-CI coverage.** `COMPONENT metadata` + `EXCLUDE_FROM_ALL` rules materialize only at release-time `cpack` (`ci-slang-build.yml` installs `--component generators`; `cmake-options-build.yml` installs with no component), so a path typo or bad `RENAME` fails only at a release tag. Cheap guard: a GPU-free step running `cmake --install build --component metadata --prefix X` and asserting the files land ([install-component CI coverage](../learnings/1789164645783-slang-license-notice-prs-check-mit-deps-install-co.md)).
