# slang-test GPU lanes on the shared L40S: run suites serially, orphaned test-servers, "ignored" that is contention, and what the GPU confirms

Every coworker container shares one NVIDIA L40S (46 GB). Since passthrough returned on 2026-10-16 (after the 09-28→10-16 outage), most false GPU failures have one cause: two GPU jobs, or other tenants, on one device at once. This page covers how those failures look and how to tell them from a regression, what the GPU confirms, how to get a Vulkan validation layer, and how to set up a push-constant repro. GPU presence is on [Container resources](agent-b-host-facts-and-critique-gate.md); WGSL through Dawn is on [Running WGSL on the real GPU](slang-backends-wgsl-on-gpu-execution.md); general false greens are on [slang-test False Greens](slang-test-false-greens-and-verification-traps.md).

## TL;DR

- **Run GPU slang-test jobs one at a time on the L40S.** Two concurrent `-vk`/`-cuda` suites produce hundreds of spurious failures (`CUDA_ERROR_LAUNCH_FAILED`, `waitForResult` retries, dead dispatch connections). Rerun differing files serially before calling anything a regression.
- **Never report a high-`-server-count` full-suite failure count as a regression.** One suite oversubscribes the shared GPU by itself (785 spurious failures at 16 servers, 397 at 48). Use about 4–8 servers, re-run the failed files at 2–4, then baseline the survivors on a build with only your fix reverted.
- **A lane that says `ignored` while a GPU is present can be contention, not a missing device.** Concurrent runs wedge in D state (`wchan os_acquire_rwlock_read`); check `ps -o stat,wchan` first. Other tenants filling the VRAM turn CUDA rows `ignored` ("Unable to create renderer [CUDA]" under `-v`), so trust CUDA coverage only after `nvidia-smi --query-gpu=memory.used,memory.total` shows headroom; `--query-compute-apps` lists only this container's PIDs.
- **If `(vk)` rows suddenly fail with empty output (`result code = 1`), check VRAM before the code.** An orphaned background `slang-test` and its servers can hold ~44 of 46 GB. Kill only your own parent `slang-test` (the servers' `-parent-pid` names it) and its servers, never another session's.
- **Keep CUDA dispatches small on the shared GPU**: 256 groups × 1024 threads failed at launch with `out of memory` while other tenants held 42/46 GB.
- **groupshared write→read races are deterministic on the L40S** (vk and cuda). A plain 64-thread COMPARE_COMPUTE catches a missing workgroup barrier.
- **Re-run every "also fails on master" note from the no-GPU window on the GPU.** `gfx-smoke.slang` passes now; the three `cooperative-matrix/fp8-cuda*` failures reproduce (`CUDA_ERROR_INVALID_PTX` on this driver and CUDA 12.6: environment baseline). The suite grows from ~8k to ~11k tests with the GPU, so attribute a new failure only after re-running it on a detached master worktree build (~20 min), which doubles as the negative control.
- **render-test rejects a bare `-DNAME=...` on a COMPARE_COMPUTE line**; pass `-Xslang -DNAME=...`.
- **Run a scratch GPU test from outside the checkout with a relative `-test-dir` and filter** (an absolute filter runs nothing). A `passed (vk)` line hides the values; a probe copy with an unmatchable CHECK exposes them in `.actual.txt`.
- **Classify a CUDA timeout as a kernel hang only if a `launched` marker printed.** On the busy GPU about half of runs hung in context creation; use ≥40 s timeouts and ≥8 runs per case.
- **A cross-group visibility repro must not spin on a non-atomic read of a `Coherent` buffer:** `Coherent` is not `volatile`, so the NVIDIA Vulkan driver and NVCC hoist the load and the loop hangs on every target. Prime the reader's L1 with one read, poll an atomic flag, then re-read.
- **The container has no Vulkan validation manifest, so `enable_debug_layers=True` prints nothing.** Write one pointing at `/usr/lib/chromium/libVkLayer_khronos_validation.so` under `/workspace/agent` (`/tmp` is wiped on restart) and set `VK_ADD_LAYER_PATH=<dir>`. slang-test's `-enable-debug-layers` takes a value (`true`); render-test's takes none. Debug builds enable layers by default; Release builds do not.
- **A green `-vk` run on the NVIDIA driver is not evidence of a correct binding or valid SPIR-V** (it accepted a wrong-type descriptor write, slang-rhi#959). Rerun under the Khronos layer (chromium copy or the Debian 1.3.239 `.deb`) before adding a GPU test or claiming a runtime fix. A teardown core dump with a written `-o` file is not a failure.
- **Count VUIDs with `grep -c '^error: .*VUID-'`, per run** (a plain grep counts each twice, slang-test's retry doubles it again). Use core validation only: GPU-AV adds a spurious acceleration-structure VUID from render-test itself.
- **Rebuild `render-test` before a push-constant repro**: a binary from before slang-rhi#848 aborts with `Unsupported binding type: 14`.
- **Reflection cannot place push constants for a global push-constant block plus entry-point uniforms**: the PUSH_CONSTANT_BUFFER index is a program-wide counter with no byte meaning, and `isParameterLocationUsed` says every index is unused (#5685). Entry-point uniform bindings also come from one program-wide pool; the guide's push/pop claim is not implemented (#13203).
- **A render-test SIGSEGV gets a backtrace in-process:** `LD_PRELOAD` a SIGSEGV `backtrace()` shim and run slang-test without `-use-test-server`; the frames name the layer (driver, render-test, slang-rhi, emit). Crash repros use your own test server, never a shared one.

## Concurrency on one GPU: the failure shapes

Each shape cleared when the same tests ran serially or at a low server count:

| Setup | Symptom | Serial / low-count result |
|---|---|---|
| Two `-server-count 16` suites (head + base) | `cuCtxSynchronize CUDA_ERROR_LAUNCH_FAILED` (slang-rhi `cuda-command.cpp:940`) until abort | barrier/groupshared subset 68/68 ([two suites concurrently](../learnings/1792140794509-don-t-run-two-gpu-slang-test-suites-concurrently-o.md)) |
| Two COMPARE_COMPUTE `-vk`/`-cuda` at once | both in D state on the driver lock; one cuda lane `ignored` | vk+cuda 2/2 in ~100 s ([run serially](../learnings/1792140793972-run-gpu-slang-test-jobs-serially-concurrent-vk-cud.md)) |
| Two `-server-count 24` suites in parallel | ~200 spurious CUDA/VK failures per side | all cleared ([corpus A/B emit-diff](../learnings/1792102021857-slang-corpus-a-b-emit-diff-control-for-bindir-path.md)) |
| One `-server-count 16` run under contention | ~100 "test server did not answer in waitForResult" retries | ([dawn.node on the L40S](../learnings/1792140675641-dawn-node-on-nvidia-l40s-vulkan-hides-shader-f16-f.md)) |
| Two full suites (16 + 12 servers, 2026-10-28) | 7 "dispatch failure(s) -- a connection died", 16 spurious cuda FAILs | 76/76 ([concurrent-suite rider](../learnings/1793218043049-git-checkout-rev-file-stages-the-file-so-a-revert-.md)) |

**One full suite oversubscribes the GPU on its own.** A debug `-server-count 16` suite gave 785 GPU-runtime failures (CUDA `out of memory`, `CUDA_ERROR_LAUNCH_FAILED`, some Vulkan); the failed files at `-server-count 2` passed 2223/2226, and the three survivors, baselined with only the fix reverted (92ef2caae), were `tests/cooperative-matrix/fp8-cuda{,-e5m2,-half-acc}.slang` (`CUDA_ERROR_INVALID_PTX` in the PTX JIT) — no regression from the slang-13260 change ([16-server suite oversubscribes](../learnings/1792166018117-slang-full-suite-at-16-test-servers-oversubscribes.md)). A Release suite at 48 servers with ~15 GB held by others gave 397 vk/cuda FAILs (`result code = 1`, empty output); at 4 servers 393 passed, the rest fp8-cuda. Extract the failed set with `grep '^FAILED test' log | sed -E "s/^FAILED test: '([^ ']+).*/\1/" | sed -E 's/\.slang\.[0-9]+$/.slang/' | sort -u` (plus `gfx-unit-test-tool/...`). Don't rebuild under a running suite on the same `build/`, and stop background jobs with TaskStop: `pkill -f <worktree path>` can match the calling shell (exit 144) ([48-server suite](../learnings/1792691640286-slang-test-full-suite-at-high-server-count-on-the-.md)).

**The A/B rule:** run the two suites one after the other (or on a targeted subset) at about 4–8 servers; serially rerun every differing file at 2–4, then baseline survivors on a build with only your fix reverted.

## Orphaned test-servers and other tenants hold the VRAM

A background `-server-count 16` slang-test that hit the Bash timeout kept running with ~44 of 46 GB, and a later run failed 22 previously-passing `(vk)` subgroup rows with empty output. List holders with `nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv`, kill only your own `-parent-pid` tree, re-run in the foreground ([orphaned test-servers](../learnings/1792140853317-orphaned-slang-test-test-servers-hog-gpu-vram-and-.md)). A 256 × 1024 CUDA dispatch failed with `cblCudaReconfigureLocalMemory ... out of memory` while others held 42/46 GB ([groupshared races deterministic](../learnings/1792138991574-groupshared-write-read-races-are-deterministic-on-.md)).

Other containers' memory turns CUDA rows `ignored` rather than red: on 2026-10-22 `syn (cuda)` rows came back ignored at 44/46 GB (`-v`: "Unable to create renderer [CUDA]") and passed ~15 minutes later. `--query-compute-apps` cannot see other tenants, so read `--query-gpu=memory.used,memory.total` before trusting CUDA coverage; a slang-test also went into D state then, so don't wait on one in the foreground ([CUDA rows flip to ignored](../learnings/1792697343358-slang-test-cuda-rows-flip-to-ignored-when-the-shar.md)).

## What the GPU confirms that a GPU-less container could not

**Missing-barrier races reproduce every time.** For slang#13631 (`workgroupUniformLoad` with no barrier off WGSL), "thread 0 writes groupshared, all read with no barrier" read stale on every thread but the writer, every run (Vulkan 261888/262144, CUDA 32736/32768), so a 64-thread COMPARE_COMPUTE (`-vk`/`-cuda`, 1×1×1) is a reliable regression test ([groupshared races deterministic](../learnings/1792138991574-groupshared-write-read-races-are-deterministic-on-.md)). On #13659 the functional test failed on master under `-vk`/`-cuda` 3/3 and passed with the fix [two suites concurrently](../learnings/1792140794509-don-t-run-two-gpu-slang-test-suites-concurrently-o.md).

**"Also fails on master" from the outage window is an environment artifact until re-run.** `tests/cpu-program/gfx-smoke.slang` (`Failed to load DLL "gfx"` then) passes on the L40S; the three `fp8-cuda*` failures reproduce on master (`CUDA_ERROR_INVALID_PTX`), so they are baseline ([revert baseline](../learnings/1792166018117-slang-full-suite-at-16-test-servers-oversubscribes.md)). With the GPU the suite grows ~8k→~11k tests; re-run only the failing tests on a detached master worktree (~20 min), which is also the PR tests' negative control. Read PR metadata with slang-mcp `github_get_pull_request` or `git fetch` + `git show`; the critique gate blocks `gh api .../pulls/<n>` ([critique delivery gates](agent-routing-f0909b0-critique-delivery-gates.md)) ([check on a master build](../learnings/1792662201433-check-new-full-suite-failures-on-a-master-build-wh.md)). The GPU also confirmed GLSL `uint64_t(uvec2)` keeping only the low word: `bit_cast<uint4>` of a struct with a `DescriptorHandle` under `-emit-spirv-via-glsl` returns a 0 high word on Vulkan; direct SPIR-V is correct (#13695). render-test needs `-Xslang -DNAME=...`, not bare `-D` ([re-run on the GPU](../learnings/1792140798870-slang-re-run-also-fails-on-master-failures-on-the-.md)).

## Getting a Khronos validation layer, and why a green NVIDIA run needs one

**The NVIDIA driver accepts some invalid API usage and SPIR-V and still produces the expected result.** On slang#14013 / PR #14023 a `-vk` repro read the expected 1234 three times after the fix; under the Khronos layer slang-rhi's `bindAsRoot` wrote a UNIFORM_BUFFER into a STORAGE_BUFFER binding (`VUID-VkWriteDescriptorSet-descriptorType-00319`) and never wrote the real UBO (`VUID-vkCmdDispatch-None-02699`, `-08114` in newer layers), and the validated run read 0 (slang-rhi#959; mechanism on [[wiki/concepts/slang-rhi-shader-object-binding-and-root-layout.md]]). Never add a GPU test or claim a binding/runtime fix from an unvalidated NVIDIA pass [NVIDIA tolerates mismatched-type writes](../learnings/1793285936432-nvidia-vulkan-drivers-tolerate-mismatched-type-des.md), [runtime pass is not evidence](../learnings/1793289426474-a-vulkan-runtime-pass-on-nvidia-without-validation.md), [green render-test can be UB](../learnings/1793294735619-a-green-vulkan-render-test-run-can-be-undefined-be.md). The driver also runs modules spirv-val rejects (`OpConvertPtrToU` with a signed result; see [[wiki/concepts/slang-backends-spirv-validation-testing-and-environment.md]]).

**No Khronos manifest is installed** (`/usr/share/vulkan/explicit_layer.d` has only INTEL_nullhw and MESA_overlay), so `spy.Device(enable_debug_layers=True)` prints nothing. Two sources need no admin approval:

- **Chromium's copy** (`/usr/lib/chromium/libVkLayer_khronos_validation.so`). Write a manifest under `/workspace/agent` (e.g. `/workspace/agent/tools/vklayer/VkLayer_khronos_validation.json`; `/tmp` is wiped on restart, [SlangPy local commit](../learnings/1792536990284-running-slangpy-against-a-local-slang-commit-isola.md)): `{"file_format_version":"1.2.0","layer":{"name":"VK_LAYER_KHRONOS_validation","type":"GLOBAL","library_path":"/usr/lib/chromium/libVkLayer_khronos_validation.so","api_version":"1.3.0","implementation_version":"1","description":"chromium VVL"}}` (`api_version` 1.3.0/1.3.239/1.3.250/1.3.290 all load). A teardown segfault with this layer, on base and head alike, does not matter [green render-test can be UB](../learnings/1793294735619-a-green-vulkan-render-test-run-can-be-undefined-be.md).
- **The Debian package.** `curl -LO https://deb.debian.org/debian/pool/main/v/vulkan-validationlayers/vulkan-validationlayers_1.3.239.0-2_amd64.deb`, `dpkg-deb -x <deb> <root>`, copy `usr/share/vulkan/explicit_layer.d/VkLayer_khronos_validation.json` into a layer dir with an absolute `library_path` (LunarG's SDK URL timed out). It uses older VUID names (`layout-00703` vs newer `layout-07988`), and `UNASSIGNED-CoreValidation-Shader-InconsistentSpirv … Invalid source language operand: 11` is noise (unknown Slang SourceLanguage) [NVIDIA tolerates mismatched-type writes](../learnings/1793285936432-nvidia-vulkan-drivers-tolerate-mismatched-type-des.md), [runtime pass is not evidence](../learnings/1793289426474-a-vulkan-runtime-pass-on-nvidia-without-validation.md).

**Loading it.** Either `VK_LAYER_PATH=<dir> VK_INSTANCE_LAYERS=VK_LAYER_KHRONOS_validation` (slang-test prints a `debug layer = {` block, fullest under `-v`) or `VK_ADD_LAYER_PATH=<dir>` + `VK_LOADER_LAYERS_ENABLE='*validation'` (slang-rhi logs `[rhi] driver: error`) ([validation layer + push-constant matrix](../learnings/1792172122995-vulkan-validation-layer-in-coworker-containers-sla.md), [push-constant repro](../learnings/1792167218740-vulkan-push-constant-gpu-repro-rebuild-render-test.md)). For render-test VUIDs: `VK_ADD_LAYER_PATH=<dir> XDG_RUNTIME_DIR=/tmp ./build/Release/bin/slang-test -enable-debug-layers true <test>`; `VK_LOADER_DEBUG=layer` confirms the load. That reproduced slang#13824 (read-only `Texture2D.Handle` bound as a storage image, `VUID-VkWriteDescriptorSet-descriptorType-00339`; cause on [descriptor-handle reflection](slang-language-core-descriptor-handle-capabilities-and-reflection.md)) ([chromium .so](../learnings/1792613432297-khronos-vulkan-validation-layer-in-the-coworker-co.md), [own manifest](../learnings/1792617340264-vulkan-validation-layer-in-coworker-containers-chr.md), [manifest trick](../learnings/1792608693780-render-test-descriptorhandle-access-is-none-on-uin.md)). slang-test's `-enable-debug-layers` takes a value (`tools/slang-test/options.cpp` ~647; a bare flag swallows the test path); render-test's takes none. Debug slang-test enables layers by default, Release does not. **Counting:** `grep -o 'VUID-…'` double-counts (the "Vulkan spec states" line) and the retry doubles again, so use `grep -c '^error: .*VUID-'` per run. Core validation only: GPU-AV (`VK_LAYER_ENABLES=VK_VALIDATION_FEATURE_ENABLE_GPU_ASSISTED_EXT`) adds a spurious VUID-vkCmdBuildAccelerationStructuresKHR-pInfos-12281 from render-test's own AS build ([own manifest](../learnings/1792617340264-vulkan-validation-layer-in-coworker-containers-chr.md)).

With validation errors render-test fails the test [runtime pass is not evidence](../learnings/1793289426474-a-vulkan-runtime-pass-on-nvidia-without-validation.md); render-test is a module slang-test loads (no binary in `build/Release/bin`) [green render-test can be UB](../learnings/1793294735619-a-green-vulkan-render-test-run-can-be-undefined-be.md). Even without a layer, `-vk` runs can dump core at teardown with a correct result (#14061, passing fp32 control), so check the `-o` file before reading a crash as a failure [fp64 GLSL.std.450 ops](../learnings/1793312363687-slang-spir-v-fp64-math-which-glsl-std-450-ops-are-.md).

## Vulkan push-constant repros: a fresh render-test and what reflection cannot tell the host

For a SlangPy module-scope `[[vk::push_constant]]` block on Vulkan (slangpy#1232; slang#13713, slang-rhi#915), a render-test built before slang-rhi#848 aborts with `Assertion failed: Unsupported binding type: 14` (`vk-shader-object.cpp`). Rebuild with `cmake --build --preset debug --target render-test slang-test` (not `render-test-tool`); `//TEST_INPUT:set push.a = {...}` binds a global block by name ([push-constant repro](../learnings/1792167218740-vulkan-push-constant-gpu-repro-rebuild-render-test.md)).

**What works and what breaks** (SlangPy, Slang 2026.19, validation on): resource-only kernels, plain `uniform` globals and `ConstantBuffer` globals beside the push constant are correct with 0 VUIDs. Kernels with entry-point uniforms fail VUID-VkPipelineLayoutCreateInfo-pPushConstantRanges-00292 and layout-10069 and return garbage; a global `ParameterBlock` fails VUID-...-layout-07988 when the push constant would be alone in set 0, shifting the ParameterBlock (slang#12349; phantom-set mechanism on [[wiki/concepts/slang-a-diagnostics-reflection-spec.md]]) ([push-constant matrix](../learnings/1792172122995-vulkan-validation-layer-in-coworker-containers-sla.md)).

**Why reflection alone cannot fix the entry-point-uniform case.** Reflection gives the global PUSH_CONSTANT_BUFFER index 0 and the EP parameters index 1, a program-wide counter with no byte meaning (each SPIR-V block starts at Offset 0), and `IMetadata::isParameterLocationUsed(PUSH_CONSTANT_BUFFER, …)` returns false for every index (#5685). The host cannot place the ranges, and slang-rhi's offset-by-sum (`addAllPushConstantRangesRec`) puts EP data at +16 ([what reflection reports](../learnings/1792167218740-vulkan-push-constant-gpu-repro-rebuild-render-test.md)).

**Descriptor bindings follow the same program-wide rule.** The user guide (`docs/user-guide/02-conventional-features.md:872-873` on 60a7c8c8; older notes cite 945-947; docs PR #3459) says compute EP `uniform` parameters are "pushed"/"popped" so the next EP reuses slots. Not implemented: `slang-parameter-binding.cpp` allocates every EP from one pool (`visitEntryPoint` :3984, `completeBindingsForParameterImpl` :1612/:1802), and `removePerEntryPointParameterKinds` (:3334) resets only varying, ShaderRecord, HitAttributes and existential kinds. A C++ harness (module + EP1 + EP2) measured EP2's `getVarLayout()->getOffset(DescriptorTableSlot)` as 3 on Vulkan, 1 per register class on HLSL (v2026.5, v2026.19); `slangc -target spirv-asm` with no `-entry` shows it, one `-entry` per compile hides it. No option controls it (#13203; proposals #13210/#13211) ([push/pop not implemented](../learnings/1792158083909-user-guide-s-compute-entry-point-uniform-push-pop-.md)). Unchanged on v2026.20 (SPIR-V 0/1/2 then 3/4/5; HLSL b0/t0/u0 then b1/t1/u1). `-reflection-json` prints only relative indices, so read `EntryPointReflection::getVarLayout()->getOffset(category)` via the API; `SamplerState()` can't be default-constructed (E39999), TextureCube `Load` takes `int4` ([still on v2026.20](../learnings/1792307527386-13203-entry-point-binding-growth-still-on-v2026-20.md)).

**Reflection-consumer traps in sgl.** `TypeReflection.ParameterCategory` stopped at 19, but a Vulkan ParameterBlock reports 20 (`sub_element_register_space`), so nanobind raised `ValueError`; use `categories` (`getCategoryCount`/`getCategoryByIndex`), since a push-constant struct holding a resource reports `mixed` ([sgl ParameterCategory](../learnings/1792172122995-vulkan-validation-layer-in-coworker-containers-sla.md)). `slangc -reflection-json /dev/null` fails with E00004; write a real file (gate on [[wiki/concepts/slang-tooling-f0909b0-slangc-cli-behavior.md]]) ([push-constant repro](../learnings/1792167218740-vulkan-push-constant-gpu-repro-rebuild-render-test.md)).

## Running a throwaway GPU test, proving what it produced, and telling a hang from a slow context

**Scratch tests from outside the read-only checkout.** Put a file in `/tmp/x/gputests/foo.slang`, `cd /tmp/x`, run `/workspace/agent/slang/build/Release/bin/slang-test -bindir /workspace/agent/slang/build/Release/bin/ -test-dir gputests/ -v gputests/` (relative `-test-dir` + filter; an absolute filter gives "no tests run"; `.actual.txt` lands beside the test). render-test: `slang-test -bindir <bin> render-test <file> -vk -compute -shaderobj -output-using-type -o out.txt`. `vulkaninfo --summary` hangs while slang-test Vulkan works; the device probe takes ~1 min, 2 files × (vk + cuda) ~3.5 min ([tests via -test-dir](../learnings/1793278419722-run-slang-test-gpu-vk-cuda-tests-from-outside-the-.md)). `-cuda` rows need `PATH=/usr/local/cuda/bin:$PATH cmake --preset default -DSLANG_ENABLE_CUDA=ON`.

**A `passed test: '…(cuda)'` line hides the values.** Copy the test to `tests/<dir>/zz-probe.slang` with an unmatchable CHECK, read each API's `<file>.actual.txt`, then delete the probe and outputs; that showed identical CUDA and Vulkan `Gather*` values on a `content=gradient` 4x4 texture ([proving a GPU run](../learnings/1793323215178-slang-worktree-submodules-proving-a-slang-test-gpu.md)).

**A render-test SIGSEGV: backtrace it in-process to name the layer.** The containers have no gdb, lldb or `libSegFault.so` (glibc 2.36). A 10-line C shim whose constructor installs a SIGSEGV/SIGBUS `sigaction` handler that calls `backtrace()` + `backtrace_symbols_fd(…, 2)` and re-raises, built with `gcc -shared -fPIC -o /tmp/segv/libsegv.so segv.c`, runs as `LD_PRELOAD=/tmp/segv/libsegv.so slang-test tests/x.slang -v` with NO `-use-test-server`, so render-test runs in-process and the trace reaches stderr. On #14208 the frames were in `libnvidia-glvkspirv.so` under `rhi::vk::DeviceImpl::createComputePipeline2`: an NVIDIA driver crash at pipeline creation. Confirm with the bad code in a branch that never runs; a crash that persists is compile/pipeline-time, not execution. Use your own `-use-test-server -server-count 1` (or in-process) for crash repros, never a shared server ([backtrace a slang-test/test-server SIGSEGV without gdb](../learnings/1793657696451-get-a-backtrace-for-a-slang-test-test-server-sigse.md)). Shim details and symbolization are on [[wiki/concepts/misc-f0909b3-slang-compiler-crash-triage.md]].

**A "hang" can be CUDA context creation.** At a busy time (2026-10-29) about half the runs of an nvcc deadlock harness hung before launch (first `cudaMalloc`/`cudaMemcpyToSymbol`), mimicking a deadlock. Print unbuffered stderr progress (`start`, `pre-launch`, `launched`, `sync: <err>`), count a timeout as a kernel hang only if `launched` printed, use ≥40 s timeouts and ≥8 runs; then master asym2/brk2 (#14016) hung 8/8 in the kernel and PR #14025 passed 8/8 ([context vs kernel hangs](../learnings/1793299898427-gpu-hang-tests-on-the-shared-l40s-separate-context.md)).

**A cross-group visibility repro needs a primed re-read, not a spin on a coherent load.** `Coherent` is not `volatile`, so the NVIDIA Vulkan driver and NVCC hoist a non-atomic spin and it hangs everywhere. Shape: group 1 reads `shared[0]` once (into L1), polls `InterlockedAdd(flag, 0)`, re-reads; group 0 delays ~200k atomic adds, writes `shared[0] = 42`, `DeviceMemoryBarrier()`, `InterlockedExchange` on the flag. On the L40S (6815ed82d) vk with `globallycoherent` gives `0 42`, without `0 0`, CUDA `0 0` because it drops the qualifier (slang#14140). It lacks a reader acquire (codex's objection), so present it as an illustration backed by a PTX/CUDA diff with and without the qualifier.
