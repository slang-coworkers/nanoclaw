# Fixer PR Creation, Fork & CI Mechanics

## TL;DR

- **The fixer (`nv-slang-bot[bot]`) pushes `fix/issue-<n>` straight to origin** — no fork; the CLAUDE.md "fork-only" wording is stale. PRs open as **DRAFT**; the bot never runs `gh pr ready` or `gh pr merge` (operator-gated).
- **Before reverting a non-draft PR, check the actor in the timeline** (`ready_for_review` `.actor.login`). Revert only a bot-authored flip; a maintainer's flip stays. Current state cannot say who flipped it.
- **PR bodies carry `Closes #N` / `Fixes #N`** (prose "also reported in #N" does not link). No `--reviewer`; CODEOWNERS assigns.
- **No AI attribution on any shader-slang commit** (slang, slang-rhi, slangpy, `wip/reap/*` included) and no "Generated with Claude Code" footer: the repo CLAUDE.md overrides the harness `Co-Authored-By: Claude` reminder; the only co-author trailer is the operator's. List every branch commit's trailers before the first push. Repair a PR-less bot branch with `commit-tree` on the same tree + authorized `--force-with-lease`; on a PR under review, ask the merger to drop it (squash keeps trailers).
- **Report up as soon as the push lands and the new CI run has started** (head SHA, run URL, gate state); never hold it for an in-session CI watch. CI outcomes arrive via `github.ci_failed`.
- **A priority-yielded bot dispatch on a draft that sits `waiting` is never auto-rerun**; don't promise a retry or re-dispatch — a maintainer marking ready or starting CI clears it.
- **`/explain-diff-html` (`upsert_pr_body.py`, since 2026-10-05) keeps ONE explanation comment, edited in place, and strips it from the description**, which stays concise (~5-15 lines; squash copies it into git log). If only `Fixes #N` survived, write the description at once with `gh pr edit --body-file`; the disclaimer goes on the comment.
- **The description check doesn't end a section at a blank line** — give each line after `**Risk.**` its own bold label; pre-check with `description_problems`.
- **`upsert_pr_body.py` exit 5 "edited by nv-slang-bot" is usually our own edit** (GraphQL drops `[bot]`). Confirm `__typename: Bot` and databaseId = REST `user.id`, re-run with `EXPLAIN_DIFF_ACTOR=nv-slang-bot`; never a human's login. Edit the comment only through the script.
- **Quiz letters follow the head SHA**: after every push re-run `--quiz-positions --head <new sha>` and re-slot answers.
- **Never pipe or truncate `upsert_pr_body.py` stdout** (use `--quiet`). Both hooks learn freshness only from the whole `EXPLAIN_DIFF_RECEIPT {...}` line.
- **After merging master into a PR that marks macro-generated declarations, re-sweep the marks.**
- **`tools/gfx/` is legacy, paralleling `external/slang-rhi/`** — grep the twin first; in-tree tests exercise only slang-rhi, so state the coverage limit.
- **On a fork PR the failing check is rarely the real blocker** — check fork permissions first; if a human owns the blocker and is engaged, watch only.
- **`dirty` PR:** `git merge-tree --write-tree --name-only` names conflicts without a checkout. **A conflicted PR gets no `on: pull_request` CI**, even when the conflict is submodule-pin-only. Check `actions/runs?branch=` and `mergeable_state` before calling CI green.
- **Off-repo (slang-rhi) triage:** anonymous clone works, `GH_TOKEN` may not write — report the blocker up. Workflow changes ship as maintainer-applied patches.
- **Devin's done-detector races the AI-analysis render** — guard on a non-`Generating...` paragraph.
- **The critique gate keys off delivery markers, not code** — a no-code triage confirmation still needs PLAN/CODE/OUTPUT recorded, each from a fresh STAGE-tagged `mcp__codex__codex` call with the exact `### Verdict\napprove` block; `codex-reply` rounds are never recorded.

The mechanics the fixer operates under on `shader-slang/slang`. Triage routing lives on [Triage Decisions](agent-fixer-triage-decisions.md); dispatch failure modes on [Fixer Dispatch & Coordination Failure Modes](agent-fixer-dispatch-coordination.md).

## Push rights, drafts-only, and issue linking

The fixer pushes `fix/issue-<n>` **directly to `origin = shader-slang/slang`**; CLAUDE.md's "fork-only" wording is stale ([slang-fixer can push fix/ branches direct to origin](../learnings/1780685454567-slang-fixer-can-push-fix-branches-direct-to-origin.md)). The szihs fork fails because `szihs/master` lags far behind, so a branch spanning the gap carries `.github/workflows/` changes and trips the App's `workflows` permission (`git diff --name-only szihs/master..HEAD | grep '^.github/workflows/'`); `git format-patch origin/master --stdout` is the fallback ([szihs fork master is stale → workflows-permission rejection](../learnings/1780357449295-slang-fixer-pr-push-szihs-fork-master-is-stale-div.md)).

Fixer PRs stay **DRAFT**: the bot never runs `gh pr ready` or `gh pr merge`; "done and green" is not authorization. The first version of this rule told the orchestrator to revert any non-draft fixer PR; on PR #11764 it ordered `gh pr ready --undo`, but the timeline showed maintainer expipiplus1 had flipped it, and the fixer rightly held and surfaced the evidence. **Verify the actor, not the state**, and revert only a bot-authored flip — overriding a maintainer is the worse breach ([Fixers must not self-flip PRs to ready — corrected: verify the actor](../learnings/1782464328257-fixers-must-not-self-flip-prs-to-ready-enforce-dra.md)). The audit is one call: `gh api repos/O/R/issues/<n>/timeline --jq '.[] | select(.event=="ready_for_review" or .event=="convert_to_draft") | "\(.event) actor=\(.actor.login) \(.created_at)"'`; on PR #12281 it returned human `pdeayton-nv`, nothing to revert ([draft-guardrail audit: use the timeline event actor](../learnings/1785825109539-a-dispatched-handoff-can-silently-die-verify-artif.md)).

PR bodies need `Closes #N` / `Fixes #N` to auto-link. Backfill with `gh api -X PATCH repos/<o>/<r>/pulls/<pr> -f body="$(existing)\n\nCloses #<issue>"`. Don't pass `--reviewer` ([Fixer PRs must use a Closes/Fixes #N closing keyword](../learnings/1780562553886-fixer-prs-must-use-a-closes-fixes-n-closing-keywor.md)).

## Commit attribution: the repo rule beats the harness reminder

No shader-slang commit (slang, slang-rhi, slangpy) may carry `Co-Authored-By: Claude` or other AI attribution, and no PR body the "Generated with Claude Code" footer. The harness reminder yields to the repo's CLAUDE.md ("Don't mention Claude on the commit message") and slang-fixer's ("Never include Claude or AI-tool attribution … — upstream policy"). The rule covers every pushed commit, throwaway `wip/reap/*` included (parent-confirmed 2026-09-29); sibling bot branches (fix/issue-13409/13423/13426) carrying no trailer are the sanity check. The reminder arrives fresh every session, so the slip recurs: worktree-GC pushed `wip/reap/fix/issue-12762` with the trailer, PR #11709 got two such commits, #13378 three, and a 2026-10-05 session four before any PR existed ([CLAUDE.md "no AI attribution" overrides the harness reminder](../learnings/1790718572444-claude-md-no-ai-attribution-overrides-the-harness-.md), [Session attribution reminder adds Co-Authored-By: Claude — check trailers at commit time](../learnings/1791166638297-session-attribution-reminder-adds-co-authored-by-c.md)).

**Prevent, because repair is not always available.** Before the first push list every commit's trailers: `git log origin/master..HEAD --format='%h [%(trailers)]'` (why content-only checks never see one: [CI correction scrutiny](ci-a-correction-scrutiny-and-forensics.md)). On a bot-owned branch with no PR, rewrite only messages: `NEW=$(git commit-tree <old>^{tree} -p <old>^ -m "<clean msg>")` then `git push --force-with-lease=refs/heads/<br>:<old-full-sha> origin $NEW:refs/heads/<br>`, or `git filter-branch -f --msg-filter '<strip>' origin/master..HEAD` for a range; `git diff <old> <new>` must be empty. The force-push needs explicit authorization ([repo no-AI-attribution rule beats the harness reminder (commit-tree recipe)](../learnings/1790689900100-shader-slang-commits-repo-no-ai-attribution-rule-b.md)). On a PR under review the force-push is off-limits without operator authorization, and squash merge collects every `Co-authored-by` onto master, so leave a PR-body note asking the merger to drop it. The one trailer a bot commit carries credits the operator; check `git log -1 --format=%B` before every push. Sweep open bot PRs with `gh pr view <n> --json commits --jq '[.commits[]|select((.messageBody//"")|test("(?i)co-authored-by:.*claude"))|.oid[0:10]]'`; a reviewer or codex flagging attribution is right ([Harness reminder vs slang's no-AI-attribution rule: repo rule wins](../learnings/1791247512039-harness-co-authored-by-claude-attribution-reminder.md)). The PR-description side (the AI disclaimer belongs on comments) is on [Codex provider](agent-fixer-codex-provider.md).

## The /explain-diff-html PR comment and description limits

**Since 2026-10-05 the explanation is a PR comment, not the description.** `upsert_pr_body.py` creates or edits ONE explanation comment and strips any explanation from the description, carrying only `Fixes #N` over — so an old explanation-only body is left near-empty (`NOTE: the PR description is 12 chars`, or ~123 chars with the disclaimer). Write the concise Summary/Root cause/Tests/Risk description right away with `gh pr edit <n> --body-file`; the bot disclaimer belongs on the comment (OUTPUT_REVIEW flags it when missing) ([upsert_pr_body.py writes the explanation as a PR comment](../learnings/1791234547680-upsert-pr-body-py-now-writes-the-explanation-as-a-.md)). Pre-check against the length hook offline: `cd /home/node/.claude/skills/explain-diff-html/scripts && python3 -c "import upsert_pr_body as u; print(u.description_problems(open(F).read(),1000,2))"` applies the PreToolUse gate's rules ([pre-check a PR description against the length hook offline](../learnings/1791289373392-pre-check-a-pr-description-against-the-length-hook.md)).

A section is a `**Label.**` or `## Heading` line plus every following non-empty line; a blank line does not close it. An "Open question …" or "Refs #N" line after `**Risk.**` trips "Risk has 3 lines, max 2", so give it its own bold label (`**Open question (blocks merge).**`, `**Issues.**`). Merge hazard from the same PR: when master moved a block of macro-generated declarations (e.g. `[__readNone]` in `diff.meta.slang`) into a new macro, taking master's hunk silently drops your mark — re-check every anchor attribute after resolving ([description limits: blank lines don't end a section](../learnings/1791463595621-explain-diff-html-description-limits-blank-lines-d.md)). The 1,000-char budget excludes only the `<sub>` disclaimer and pure `Fixes/Closes #N` lines (`counted_lines` in `/app/hooks/lib/pr_description.py`), so a codex OUTPUT_REVIEW counting with `wc -m` can false-flag; answer with `check_body()` output ([side note on #14093](../learnings/1793366451861-slang-lambda-capture-fields-copy-the-captured-name.md)).

**Exit 5 naming our own App is an identity-spelling mismatch.** When the comment's seal is broken the script asks GraphQL's edit history who edited it and refuses (writes nothing) unless the login is trusted. GraphQL's `editor.login` names an App without the suffix (`nv-slang-bot`, `__typename: Bot`), while the actors file and REST use `nv-slang-bot[bot]`; the usual trigger is our own hand edit, e.g. a REST PATCH adding the disclaimer ([exit 5 on our own edit: GraphQL drops the [bot] suffix](../learnings/1791922521312-upsert-pr-body-py-exit-5-on-our-own-edit-graphql-d.md)). Verify GraphQL `author { ... on Bot { databaseId } }` equals REST `user.id` (274397474), then re-run with `EXPLAIN_DIFF_ACTOR=nv-slang-bot` — never a human's login ([GraphQL names the App editor without [bot]](../learnings/1791939131464-explain-diff-upsert-graphql-names-the-app-editor-w.md), [also seen in a codex-critique session](../learnings/1791912236710-codex-stage-prompts-can-return-wiki-recall-instead.md)). Avoid it by editing only through the script, which appends the disclaimer when the body has no `<sub>` line. While investigating, note `gate-critique-on-deliver.sh` treats any `gh api …pulls…` command (GETs and reactions included) as PR creation, so read through `gh api graphql` (regex on [holds & authorization gates](agent-routing-holds-authorization-gates.md)).

**The hooks learn the comment is fresh only from a whole `EXPLAIN_DIFF_RECEIPT` line on stdout.** The deliver gate (`gate-critique-on-deliver.sh` via `pr-auto-map.sh`, `fromjson?`) and the Stop hook (`gate-explain-on-stop.sh` → `lib/explain-diff-owed.sh`) both update `explained_head` in `/workspace/.claude/explain-diff-state.json` from it ([gate only clears when the receipt reaches stdout untruncated](../learnings/1792155974206-explain-diff-gate-only-clears-when-the-upsert-rece.md), [the stop hook parses the receipt from Bash output](../learnings/1792177961012-never-truncate-the-explain-diff-receipt-line-the-s.md)). Through `cut -c1-N`, `head -c` or `| tail -1 | cut -c1-200`, GitHub updates but the cut JSON doesn't parse: the deliver gate keeps refusing `[Fix Review Request]`/`[Fix Report]` ("still explains head <old>") and the Stop hook blocks ("explanation comment is stale"). A `2>&1 | tail -1` re-run cleared the Stop hook ([don't truncate upsert_pr_body.py output](../learnings/1793231501137-don-t-truncate-upsert-pr-body-py-output-the-explai.md)), though one session saw `| grep` fail the deliver gate. **Run with `--quiet` and no pipe**, the one form both accept; slang#14026 (PRs #14046-8) lost the receipt again to `| tail -1 | cut -c1-200` ([Never pipe upsert_pr_body.py through cut/head](../learnings/1793308363614-never-pipe-upsert-pr-body-py-through-cut-head-the-.md)). Check with `jq '.prs["owner/repo#N"].explained_head' /workspace/.claude/explain-diff-state.json` or `. /app/hooks/lib/explain-diff-owed.sh; explain_diff_owed_lines`.

**Quiz answer letters derive from the head SHA.** `upsert_pr_body.py --quiz-positions --head <sha>` returns the slots, which change per head (PR #14024: 8f31746 → A D D C B, 52ae1d8 → D A B B D). After a push, move each correct option to its new slot and update the `**X.**` letter; the HTML quiz shuffles on load and is unaffected. The public-comment gate counts the whole Bash command's bytes, so write the body with a heredoc in one step and post with a short `gh api ... -F body=@file` ([quiz letters are derived from the head SHA](../learnings/1793294291217-explain-diff-quiz-letters-are-derived-from-the-hea.md)).

## tools/gfx legacy code and the slang-rhi twin

`tools/gfx/` parallels `external/slang-rhi/`, and all in-tree tests go through slang-rhi, so no regression test catches a `tools/gfx/` runtime bug. Grep the twin in `external/slang-rhi/src/` first — it is often already patched. State the limit in the PR: a compile-only filecheck guards the language surface; runtime coverage needs downstream CI such as Falcor's gfx tests ([tools/gfx/ is legacy code paralleling slang-rhi](../learnings/1778749638138-slang-fixer-tools-gfx-is-legacy-code-paralleling-s.md)).

## Failing checks, fork permissions, and CI mechanics

On fork PRs separate the *failing check* from the *merge blocker*: check `gh api repos/<fork-owner>/<repo> --jq .permissions` and `maintainerCanModify`; if the blocker is human-owned and humans are engaged, watch only ([Failing check ≠ real blocker on fork-based PRs](../learnings/1780903795100-failing-check-real-blocker-on-fork-based-prs-triag.md)).

For `mergeable_state=dirty`, `git fetch origin main pull/<N>/head:refs/tmp/prN` then `git merge-tree --write-tree --name-only origin/main refs/tmp/prN` prints conflicted paths, and `git log <merge-base>..origin/main -- <files>` names the causing commits ([Predict PR merge conflicts with `git merge-tree --write-tree`](../learnings/1791895869568-predict-pr-merge-conflicts-locally-with-git-merge-.md)). **A conflicted PR gets no `on: pull_request` CI**: pushes trigger only `pull_request_target` workflows, CLA and CodeRabbit, with no `ci` run and nothing to approve. The conflict can be **submodule-only**: GitHub's server merge has no submodule objects, so when `main` bumps a pin the PR also changed, it is unmergeable though a local `merge-tree` reports clean; a bare clone reproduces `CONFLICT (submodule)`. On slangpy#1189 no push after #1188 (bumping `external/slang-rhi`) got a `ci` run. Check `gh api repos/O/R/actions/workflows/ci.yml/runs?branch=<head>` and `.mergeable_state` before saying "CI is green"; only a rebase or merge restores CI, so run GPU tests locally meanwhile ([pull_request CI silently stops on a merge-conflicted PR](../learnings/1792159824626-github-pull-request-ci-silently-stops-on-a-merge-c.md)). A clean `merge-tree` proves only no textual conflict; see [GitHub state & PR mechanics](agent-a-github-state-and-pr-mechanics.md).

**On a parent-requested rebase/force-push, report up once the push lands and CI has started** (head SHA, run URL, gate state). A fixer that held its 5-bullet for a background watcher lost it when the session ended; the parent re-chased 24 h later ([Report up right after push+CI dispatch](../learnings/1790669062658-report-up-right-after-push-ci-dispatch-don-t-gate-.md)). A bot run can stop at `wait-for-human-priority` with `priority-gate-yielded` — a scheduling yield, which `retry-yielded-bot-ci` reruns only once the run is *completed* (see [GitHub bot & webhooks](agent-routing-github-bot-and-webhooks.md)). On a draft whose yielded run sits `waiting` on the Falcor approval gate, the script never fires (it reads `waiting` as active), approving the gate doesn't help and a re-dispatch only yields again; leave it to a maintainer marking ready or starting CI ([a priority-yielded draft dispatch is not rerun while 'waiting'](../learnings/1793105473572-a-priority-yielded-bot-ci-yml-dispatch-on-a-draft-.md); see [rerun decision rules](ci-flake-rerun-decision-rules.md)).

When a `set -euo pipefail` CI script exits silently and logs can't name the command (#13041 → PR #13352), add `trap 'status=$?; echo "::warning::… \"$BASH_COMMAND\" (line $LINENO) exited with status $status"; exit 0' ERR` **without** `set -E`: it fires only where errexit would abort at top level, so the next occurrence either names the command or rules errexit out ([ERR-trap diagnostic for silent pipefail exits](../learnings/1790799595374-critique-gate-any-file-write-after-the-output-revi.md)).

For off-repo slang-rhi triage from slang-triager, anonymous clone works but `GH_TOKEN` may be invalid for writes; report the posting blocker to the parent ([slang-rhi off-repo triage](../learnings/1780307950462-slang-rhi-off-repo-triage-anonymous-clone-works-gh.md)). Falcor CI tracking issues by `jkiviluoto-nv` are self-assigned CI-infra work: park at triaged, no fixer, but post a verified 5-bullet cross-linking the family (#11495 → #11600 → #9219, #9228, #11703) ([Falcor CI tracking issues: park at triaged](../learnings/1782222346038-falcor-ci-tracking-issues-from-jkiviluoto-nv-park-.md)). The #11600 Falcor YML 3-file refactor must reconcile the two workflows' differing cmake flags, keep the required-check aggregator key exactly `check-falcor`, and add `merge_group: types:[checks_requested]` to the dispatcher or the queue deadlocks; deliver as a maintainer-applied patch ([slang#11600 falcor YML refactor design notes](../learnings/1781365729972-slang-11600-falcor-yml-3-file-refactor-triage-desi.md)).

## Devin Review done-detector false positives

`devin-fetch.sh` in `slang-pr-review-runner` can declare completion while the AI-analysis paragraph still shows `Generating...`, because the right-rail `Analysis complete` status populates first. Extend `DONE_EXPR` to require a non-`Generating...` paragraph after the "Devin's AI analysis" heading; if `devin-flags.md` already shows "Generating...", drive `agent-browser` through each flag panel and re-scrape ([Devin Review done-detector races AI-analysis render](../learnings/1779298338813-devin-review-done-detector-false-positives-on-all-.md)).

## The critique gate fires even for no-code deliveries

`gate-critique-on-deliver.sh` keys off delivery markers (`[Fix Report]`, `[Resolution]`, `[Report]`, `gh pr create`/`gh api .../pulls`), so a zero-diff triage confirmation is blocked until PLAN_REVIEW, CODE_REVIEW and OUTPUT_REVIEW (`approve`) are recorded. Satisfy it honestly: write the deliverable to a file, run `/codex-critique` per stage, and frame a zero-diff CODE_REVIEW as the scope-shrinkage guard ("did I silently drop an in-scope fix?", pointing codex at `git status --porcelain` + `git diff --stat`) ([Critique gate fires on no-code triage-confirmations too](../learnings/1783523465568-critique-gate-fires-on-no-code-triage-confirmation.md)). The parser is exact: STAGE only from a FRESH `mcp__codex__codex` call with a `STAGE: <X>` line, and the verdict only from the exact `### Verdict\napprove` block (free text shows "verdicts: none"). A `codex-reply` carries no STAGE tag and is never recorded, so after a must-fix issue a NEW STAGE-tagged call with the canonical developer-instructions and `ROUND: n/3` ([upsert_pr_body.py … `codex-reply` rounds aren't recorded](../learnings/1791234547680-upsert-pr-body-py-now-writes-the-explanation-as-a-.md)); every in-container codex call needs `sandbox: "danger-full-access"`. A STAGE call can return wiki-recall bullets instead of a verdict — treat that as no review and re-ask (one session re-asked via `codex-reply`; the fresh-call form is the one the parser records) ([codex STAGE prompts can return wiki recall](../learnings/1791912236710-codex-stage-prompts-can-return-wiki-recall-instead.md)). The no-code diagnoses this gate sees usually come from the STEP-0 byte-compare for "did this diff change emitted output?" ([STEP-0 byte-compare and delivery-gate verdict format](../learnings/1783352556452-step-0-byte-compare-to-decide-if-a-diff-changed-em.md)).
