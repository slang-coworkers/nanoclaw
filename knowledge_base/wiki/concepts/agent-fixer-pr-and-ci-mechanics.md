# Fixer PR Creation, Fork & CI Mechanics

## TL;DR

- **The fixer (`nv-slang-bot[bot]`) pushes `fix/issue-<n>` straight to origin** — no fork; the CLAUDE.md "fork-only" wording is stale. PRs open as **DRAFT**; the bot never runs `gh pr ready` or `gh pr merge` (operator-gated).
- **Before reverting a non-draft PR, check the actor in the timeline** (`ready_for_review` event `.actor.login`). Revert only a bot-authored flip; a maintainer's deliberate flip stays. Current draft state cannot answer who flipped it.
- **PR bodies carry `Closes #N` / `Fixes #N`** to auto-link (prose "also reported in #N" does not). No `--reviewer`; CODEOWNERS assigns.
- **No AI attribution on any shader-slang commit** (slang, slang-rhi, slangpy, `wip/reap/*` included) and no "Generated with Claude Code" footer: the repo CLAUDE.md overrides the harness `Co-Authored-By: Claude` reminder; the only co-author trailer is the operator's. List every branch commit's trailers (`git log origin/master..HEAD --format='%h [%(trailers)]'`) before the first push. Repair a PR-less bot branch with `commit-tree` on the same tree + authorized `--force-with-lease`; on a PR under review, ask the merger to drop it (squash merge keeps trailers).
- **Report up as soon as the push lands and the new CI run has started** (head SHA, run URL, gate state). Never hold the report for an in-session CI watch — the session can end mid-watch. CI outcomes arrive later via `github.ci_failed`.
- **A priority-yielded bot dispatch on a draft that sits `waiting` is never auto-rerun**; don't promise the retry or re-dispatch — a maintainer marking ready or starting CI clears it.
- **`/explain-diff-html` (`upsert_pr_body.py`, since 2026-10-05) writes ONE explanation comment, edited in place, and strips it from the description**, which stays concise (~5-15 lines; squash merge copies it into git log). If only `Fixes #N` survived, write the description at once with `gh pr edit <n> --body-file`; the disclaimer goes on the comment.
- **The description length check doesn't end a section at a blank line** — every non-empty line after `**Risk.**` counts toward Risk, so give each trailing line its own bold label; pre-check with `description_problems` before `gh pr edit`.
- **`upsert_pr_body.py` exit 5 "edited by nv-slang-bot" is usually our own edit:** GraphQL names the App without `[bot]`. Confirm `__typename: Bot` and databaseId = REST `user.id`, then re-run with `EXPLAIN_DIFF_ACTOR=nv-slang-bot`; never a human's login. Edit the comment only through the script.
- **Explanation-comment quiz letters follow the head SHA**: after every push re-run `upsert_pr_body.py --quiz-positions --head <new sha>` and re-slot each correct option and its `**X.**` letter.
- **Never pipe or truncate `upsert_pr_body.py` stdout** (run it with `--quiet`). The deliver gate and the Stop hook learn the comment is fresh only from the whole `EXPLAIN_DIFF_RECEIPT {...}` line; check `explain-diff-state.json` or `explain_diff_owed_lines`.
- **After merging master into a PR that marks macro-generated declarations, re-sweep the marks** — taking master's hunk for a block moved into a new macro drops your mark.
- **`tools/gfx/` is legacy code paralleling `external/slang-rhi/`** — grep the twin first; in-tree tests exercise only slang-rhi, so state the coverage limit in the PR.
- **On a fork PR the failing check is rarely the real merge blocker** — check fork permissions (`.permissions`, `maintainerCanModify`) first; if a human owns the blocker and humans are engaged, watch only.
- **`dirty` PR:** `git merge-tree --write-tree --name-only origin/<base> <pull/N/head>` names the conflicting files without a checkout. **A merge-conflicted PR gets no `on: pull_request` CI at all**, and the conflict can be submodule-pin-only (a local merge-tree with submodule objects calls it clean). Check `actions/runs?branch=<head_ref>` and `mergeable_state` before calling CI green; only a rebase/merge restores CI.
- **Off-repo (slang-rhi) triage:** anonymous clone works, but `GH_TOKEN` may not write — report the posting blocker up. The bot cannot push `.github/workflows/*`; deliver a maintainer-applied patch.
- **Devin's done-detector races the AI-analysis render** — guard on a non-`Generating...` paragraph.
- **The critique gate keys off delivery markers, not off whether you wrote code** — even a no-code triage confirmation needs PLAN/CODE/OUTPUT recorded. STAGE is recorded only from a fresh STAGE-tagged `mcp__codex__codex` call and the verdict only from the exact `### Verdict\napprove` block; a `codex-reply` round is never recorded, so run each fix round as a fresh call with the canonical developer-instructions and `ROUND: n/3`.


The mechanics the `nv-slang-bot[bot]` fixer coworker operates under on `shader-slang/slang`: push rights and PR-state hygiene, commit attribution, the explain-diff PR comment, the `tools/gfx`↔`slang-rhi` twin, fork-PR CI blockers, the Devin done-detector race, and the codex critique gate. Triage classification/routing lives on [Triage Decisions](agent-fixer-triage-decisions.md); dispatch/coordination failure modes on [Fixer Dispatch & Coordination Failure Modes](agent-fixer-dispatch-coordination.md).

## Push Rights, Drafts-Only, and Issue Linking

The fixer authenticated as `nv-slang-bot[bot]` pushes `fix/issue-<n>` branches **directly to `origin = shader-slang/slang`**; the older CLAUDE.md "fork-only" wording is stale ([slang-fixer can push fix/ branches direct to origin (fork-only rule does not apply)](../learnings/1780685454567-slang-fixer-can-push-fix-branches-direct-to-origin.md)). The szihs fork fails because `szihs/master` lags far behind, so a branch spanning the gap carries `.github/workflows/` changes and trips the App `workflows` permission (check `git diff --name-only szihs/master..HEAD | grep '^.github/workflows/'`); `git format-patch origin/master --stdout` is the fallback for a real rejection ([slang fixer PR push: szihs fork master is stale/divergent (lacks docs/generated framework) → GitHub-App 'workflows permission' rejection; jkwak fork auth fails](../learnings/1780357449295-slang-fixer-pr-push-szihs-fork-master-is-stale-div.md)).

Fixer PRs open as **DRAFT** and stay draft: the bot never self-flips to ready (`gh pr ready`) or merges — those are operator/maintainer-gated ([Fixers must not self-flip PRs to ready — enforce drafts-only](../learnings/1782464090006-fixers-must-not-self-flip-prs-to-ready-enforce-dra.md)). That first framing ("see non-draft → direct a revert") was corrected: on PR #11764 the orchestrator saw `draft: false` and ordered a revert, but the timeline showed a human maintainer had flipped it, and the fixer rightly held and surfaced the evidence. So **verify the actor, not the state**, before directing any revert, and revert only a **bot-authored** flip; reversing a maintainer's deliberate decision is a worse breach than the one it guards against ([Fixers must not self-flip PRs to ready — enforce drafts-only](../learnings/1782464328257-fixers-must-not-self-flip-prs-to-ready-enforce-dra.md)). The audit is one call: `gh api repos/O/R/issues/<n>/timeline --jq '.[] | select(.event=="ready_for_review" or .event=="convert_to_draft") | "\(.event) actor=\(.actor.login) \(.created_at)"'`. On PR #12281 the actor came back `pdeayton-nv` — a human, guardrail intact, nothing to revert ([draft-guardrail audit: use the timeline event actor, not current state](../learnings/1785825109539-a-dispatched-handoff-can-silently-die-verify-artif.md)).

PR bodies need an explicit `Closes #N` / `Fixes #N` keyword to auto-link the issue; prose like "also reported in #N" does not link. Backfill with `gh api -X PATCH repos/<o>/<r>/pulls/<pr> -f body="$(existing)\n\nCloses #<issue>"`. Don't pass `--reviewer` to `gh pr create`; CODEOWNERS assigns ([Fixer PRs must use a Closes/Fixes #N closing keyword, not a prose issue reference](../learnings/1780562553886-fixer-prs-must-use-a-closes-fixes-n-closing-keywor.md)).

## Commit Attribution: the Repo Rule Beats the Harness Reminder

In shader-slang repos (slang, slang-rhi, slangpy) no commit may carry `Co-Authored-By: Claude` or other AI attribution, and no PR body the "Generated with Claude Code" footer. The harness system-reminder asks for both, but it yields to the user's or repo's own CLAUDE.md, and both the slang repo CLAUDE.md ("Don't mention Claude on the commit message") and slang-fixer's CLAUDE.md ("Never include Claude or AI-tool attribution in commit messages or PR bodies — upstream policy") forbid them. The rule covers every pushed commit, throwaway `wip/reap/*` branches included (parent-confirmed 2026-09-29); sibling bot branches (fix/issue-13409/13423/13426) carry no trailer, which is the quick sanity check. Because the reminder arrives fresh each session, the slip recurs: worktree-GC pushed `wip/reap/fix/issue-12762` @ 3390dc16f9 with the trailer, PR #11709 got two such commits, PR #13378 three (a reviewer caught it), and a 2026-10-05 session pushed four before any PR existed [No AI attribution in shader-slang commits; the repo rule overrides the harness reminder](../learnings/1790689864476-no-ai-attribution-in-shader-slang-commits-the-repo.md) [CLAUDE.md "no AI attribution" overrides the harness Co-Authored-By reminder](../learnings/1790718572444-claude-md-no-ai-attribution-overrides-the-harness-.md) [Session attribution reminder adds Co-Authored-By: Claude — check trailers at commit time](../learnings/1791166638297-session-attribution-reminder-adds-co-authored-by-c.md).

**Prevent rather than repair, because repair is not always available.** Before the first push, list every branch commit's trailers, not just the last: `git log origin/master..HEAD --format='%h [%(trailers)]'` (why content-only checks never see a trailer is on [CI correction scrutiny](ci-a-correction-scrutiny-and-forensics.md)). If the bot owns the branch and there is no PR, rewrite only the messages: `NEW=$(git commit-tree <old>^{tree} -p <old>^ -m "<clean msg>")` then `git push --force-with-lease=refs/heads/<br>:<old-full-sha> origin $NEW:refs/heads/<br>` for one commit, or `git filter-branch -f --msg-filter '<strip line>' origin/master..HEAD` for a range; then `git diff <old> <new>` must be empty (or `HEAD^{tree}` must equal the old head's tree). The force-push needs explicit authorization [shader-slang commits: repo no-AI-attribution rule beats the harness Co-Authored-By reminder (commit-tree repair recipe)](../learnings/1790689900100-shader-slang-commits-repo-no-ai-attribution-rule-b.md). On a PR under review the force-push is off-limits without operator authorization, and squash merge collects every `Co-authored-by` trailer into the squash commit, so leave a PR-body note asking the merger to drop it. The one co-author trailer a bot commit carries credits the operator at the verified address; check `git log -1 --format=%B` before every push. Orchestrator sweep over open bot PRs: `gh pr view <n> --json commits --jq '[.commits[]|select((.messageBody//"")|test("(?i)co-authored-by:.*claude"))|.oid[0:10]]'`. A reviewer or codex flagging attribution is right [Harness Co-Authored-By reminder vs slang's no-AI-attribution rule: repo rule wins](../learnings/1791247512039-harness-co-authored-by-claude-attribution-reminder.md). The PR-description side (the AI-transparency disclaimer belongs on comments, never in the body or a commit) is on [Codex provider](agent-fixer-codex-provider.md).

## The /explain-diff-html PR Comment and Description Limits

**Since 2026-10-05 the explanation lives in a PR comment, not the description.** `upsert_pr_body.py` creates or edits in place ONE explanation comment and strips any explanation from the description, which must stay concise (~5-15 lines, because squash merge copies it into git log). It carries `Fixes #N` over, so a PR whose old body held the explanation is left near-empty (`NOTE: the PR description is 12 chars`); write the concise description yourself with `gh pr edit <n> --body-file`. The bot disclaimer belongs on the explanation comment (OUTPUT_REVIEW flags it when missing). The old whole-body replacement (with `Fixes #N` and the disclaimer re-appended, duplicated on #13353) no longer applies ([upsert_pr_body.py now writes the explanation as a PR comment and strips it from the description](../learnings/1791234547680-upsert-pr-body-py-now-writes-the-explanation-as-a-.md)). A body that held only an `explain-diff-html:start…end` block comes out at ~123 characters (Fixes and disclaimer lines), so write the Summary/Root cause/Tests/Risk description right after the upsert. Check it against the length hook offline first — `cd /home/node/.claude/skills/explain-diff-html/scripts && python3 -c "import upsert_pr_body as u; print(u.description_problems(open(F).read(),1000,2))"` applies the PreToolUse gate's rules, so a refused edit and its full-context retry are avoided ([pre-check a PR description against the length hook offline](../learnings/1791289373392-pre-check-a-pr-description-against-the-length-hook.md)).

`description_problems` treats a section as a `**Label.**` or `## Heading` line plus every following non-empty line; a blank line does not close it. An "Open question …" or "Refs #N / Part of #M" line after `**Risk.**` therefore trips "Risk has 3 lines, max 2" — give each trailing line its own bold label (`**Open question (blocks merge).** …`, `**Issues.** Refs #…`). The 1,000-char budget excludes only the `<sub>` disclaimer and pure `Fixes #N`/`Closes #N` lines. The same PR exposed a merge hazard: when you merge master into a PR that marks macro-generated declarations (e.g. `[__readNone]` in `diff.meta.slang`) and master moved a block into a new macro, taking master's hunk silently drops your mark, so after resolving, check that each anchor attribute still carries its mark ([description limits: blank lines don't end a section; label trailer lines](../learnings/1791463595621-explain-diff-html-description-limits-blank-lines-d.md)).

**An exit 5 naming our own App as editor is an identity-spelling mismatch, not a human edit.** Before overwriting the comment the script checks its seal; if broken, it asks GraphQL's edit history who edited it and refuses (exit 5, writes nothing) unless the login is trusted. GraphQL's `editor.login` names a GitHub App without the suffix (`nv-slang-bot`, `__typename: Bot`) while the actors file and REST use `nv-slang-bot[bot]`, so our own edit reads as foreign. The usual trigger is a hand edit of our own comment, such as a REST PATCH adding the disclaimer ([upsert_pr_body.py exit 5 on our own edit: GraphQL drops the [bot] suffix](../learnings/1791922521312-upsert-pr-body-py-exit-5-on-our-own-edit-graphql-d.md)). Verify before adopting: GraphQL `author { ... on Bot { databaseId } }` must equal our App's REST `user.id` (274397474 for nv-slang-bot); then re-run with `EXPLAIN_DIFF_ACTOR=nv-slang-bot`, the coworker's own identity and what the refusal text allows — never a human's login ([explain-diff upsert: GraphQL names the App editor without [bot]](../learnings/1791939131464-explain-diff-upsert-graphql-names-the-app-editor-w.md), [also seen in a codex-critique session](../learnings/1791912236710-codex-stage-prompts-can-return-wiki-recall-instead.md)). Avoid it by editing the comment only through the script, which appends the disclaimer itself when the body has no `<sub>` line. While investigating, note that `gate-critique-on-deliver.sh` treats any `gh api …pulls…` command (GETs and reactions on pull comments included) as PR creation, so do those reads through `gh api graphql` (the regex is on [holds & authorization gates](agent-routing-holds-authorization-gates.md)).

**The hooks learn the comment was refreshed only from a whole `EXPLAIN_DIFF_RECEIPT` line on stdout.** The deliver gate (`gate-critique-on-deliver.sh`, via `pr-auto-map.sh` parsing stdout with `fromjson?`) and the Stop hook (`gate-explain-on-stop.sh` → `lib/explain-diff-owed.sh`, parsing the Bash tool output) both update `explained_head` in `/workspace/.claude/explain-diff-state.json` from that line. Through `| tail -1 | cut -c1-200`, `cut -c1-N` or `head -c`, GitHub is updated but the cut-short JSON does not parse, so the deliver gate keeps refusing `[Fix Review Request]`/`[Fix Report]` ("explanation comment still explains head <old>") and the Stop hook blocks ("explanation comment is stale"). Re-runs with a whole-line filter (`| grep RECEIPT`; `2>&1 | tail -1`) cleared the Stop hook, though one session listed `| grep` among forms that failed the deliver gate; every failure cut the line itself. **Run the script with `--quiet` (it already prints only the receipt) and no pipe on stdout**, the one form both hooks accept; slang#14026 (PRs #14046-8, 2026-10-29) lost the receipt again to `| tail -1 | cut -c1-200` [Never pipe upsert_pr_body.py through cut/head — the truncated EXPLAIN_DIFF_RECEIPT is never recorded and the deliver gate refuses [Fix Report]](../learnings/1793308363614-never-pipe-upsert-pr-body-py-through-cut-head-the-.md). Check with `jq '.prs["owner/repo#N"].explained_head' /workspace/.claude/explain-diff-state.json` or `. /app/hooks/lib/explain-diff-owed.sh; explain_diff_owed_lines` ([explain-diff gate only clears when the upsert receipt line reaches stdout untruncated](../learnings/1792155974206-explain-diff-gate-only-clears-when-the-upsert-rece.md), [never truncate the EXPLAIN_DIFF_RECEIPT line: the stop hook parses it from Bash output](../learnings/1792177961012-never-truncate-the-explain-diff-receipt-line-the-s.md), [don't truncate upsert_pr_body.py output; the stop gate reads its receipt](../learnings/1793231501137-don-t-truncate-upsert-pr-body-py-output-the-explai.md)).

**The comment's quiz answer letters are derived from the head SHA.** `upsert_pr_body.py --quiz-positions --head <sha>` returns the correct-answer slots, and they change with the head (PR #14024: 8f31746 → A D D C B, 52ae1d8 → D A B B D, 99c736d → D B C B A). After pushing review follow-ups, re-run it for the new head, move each question's correct option into its new slot and update the `**X.**` answer letter, or the comment's answers sit at stale positions; the HTML quiz is unaffected because it shuffles on load and uses `data-correct`. The public-comment gate counts the whole Bash command's bytes, so the body file is written with a heredoc in one step and posted with a short `gh api ... -F body=@file` in another [explain-diff quiz letters are derived from the head SHA — re-slot after every amend/push](../learnings/1793294291217-explain-diff-quiz-letters-are-derived-from-the-hea.md).

## tools/gfx Legacy Code and the slang-rhi Twin

`tools/gfx/` is legacy code paralleling `external/slang-rhi/`, and all in-tree tests go through slang-rhi, so a regression test cannot catch a `tools/gfx/` runtime bug. Before fixing a `tools/gfx/` symbol, grep its twin in `external/slang-rhi/src/` — slang-rhi is often already patched and `tools/gfx/` just lags. State the coverage limit in the PR: a compile-only filecheck guards the language surface; runtime coverage needs downstream CI such as Falcor's gfx tests ([slang-fixer: tools/gfx/ is legacy code paralleling slang-rhi — fixes need to land in both, but in-tree tests only exercise slang-rhi](../learnings/1778749638138-slang-fixer-tools-gfx-is-legacy-code-paralleling-s.md)).

## Failing Checks, Fork Permissions, and CI Mechanics

On fork-based PRs, separate the *failing check* from the *actual merge blocker*: check fork permissions first (`gh api repos/<fork-owner>/<repo> --jq .permissions`, `maintainerCanModify`), and if the binding blocker is human-owned and humans are engaged, default to watch-only ([Failing check ≠ real blocker on fork-based PRs (triage to watch-only)](../learnings/1780903795100-failing-check-real-blocker-on-fork-based-prs-triag.md)).

For a `mergeable_state=dirty` PR, name the conflicting files without a checkout: `git fetch origin main pull/<N>/head:refs/tmp/prN`, then `git merge-tree --write-tree --name-only origin/main refs/tmp/prN` prints the conflicted paths and `CONFLICT (content)` lines, and `git log <merge-base>..origin/main -- <conflicted files>` names the causing commits — enough to tell a maintainer where a rebase will hurt ([Predict PR merge conflicts locally with `git merge-tree --write-tree`](../learnings/1791895869568-predict-pr-merge-conflicts-locally-with-git-merge-.md)). **A merge-conflicted PR gets no `on: pull_request` CI at all:** each push triggers only `pull_request_target` workflows (slangpy "PR Maintenance"/board-sync), CLA and CodeRabbit, with no `ci` run, no `action_required`, nothing to approve ("Workflows will not run on `pull_request` activity if the pull request has a merge conflict"). The conflict can be **submodule-only**: GitHub's server-side merge has no submodule objects, so when `main` bumps a pin the PR also changed, the PR is unmergeable even though a local `merge-tree` with submodule objects reports a clean fast-forward; a bare clone without them reproduces the server's `CONFLICT (submodule)`. On slangpy#1189 no push after #1188 (bumping `external/slang-rhi`) merged got a `ci` run (an earlier reading blamed fork pushes). Check `gh api repos/O/R/actions/workflows/ci.yml/runs?branch=<head-branch>` and `pulls/N --jq .mergeable_state` before saying "CI is green"; only a rebase or merge restores CI, so meanwhile run the GPU tests locally for evidence ([GitHub pull_request CI silently stops on a merge-conflicted PR, incl. submodule-pin conflicts](../learnings/1792159824626-github-pull-request-ci-silently-stops-on-a-merge-c.md)). A clean `merge-tree` proves only that there is no textual conflict; its limits and the guilty control are on [GitHub state & PR mechanics](agent-a-github-state-and-pr-mechanics.md).

**On a parent-requested rebase/force-push, report up the moment the push lands and the new CI run has started** — head SHA, run URL, current gate state. A fixer that held its 5-bullet for a background CI watcher lost it when the session ended mid-watch; the parent re-chased 24 h later. CI outcomes arrive as a `github.ci_failed` webhook, so waiting in-session buys nothing [Report up right after push+CI dispatch; don't gate the report on a long CI watch](../learnings/1790669062658-report-up-right-after-push-ci-dispatch-don-t-gate-.md). A bot run can stop at `wait-for-human-priority` with `priority-gate-yielded`, failing `check-ci` with no real job run — a scheduling yield, not a code failure, which `retry-yielded-bot-ci` reruns only once the run is *completed* (see [GitHub bot & webhooks](agent-routing-github-bot-and-webhooks.md)). On a draft whose yielded run still sits `waiting` on the Falcor build approval gate, the script never fires (it treats `waiting` as active CI), approving the gate does not help, and a re-dispatch only yields again; say so and leave it to a maintainer marking the PR ready or starting CI ([a priority-yielded draft dispatch is not rerun while it sits 'waiting'](../learnings/1793105473572-a-priority-yielded-bot-ci-yml-dispatch-on-a-draft-.md); rules on [rerun decision rules](ci-flake-rerun-decision-rules.md)).

When a `set -euo pipefail` CI script exits non-zero with no output and the logs cannot name the command (#13041 → PR #13352), add `trap 'status=$?; echo "::warning::… \"$BASH_COMMAND\" (line $LINENO) exited with status $status"; exit 0' ERR` **without** `set -E`. It fires only where errexit would abort at top level, not on expected no-matches inside `$(...)`, so the next occurrence is falsifiable: a warning names the command, or a still-silent exit rules errexit out ([ERR-trap diagnostic for silent pipefail exits](../learnings/1790799595374-critique-gate-any-file-write-after-the-output-revi.md)).

For off-repo slang-rhi triage from the slang-triager container, anonymous clone works (public repo) but `GH_TOKEN` may be invalid for writes; report the posting blocker to the parent rather than writing with a broken token ([slang-rhi off-repo triage: anonymous clone works, GH_TOKEN invalid, no GPU](../learnings/1780307950462-slang-rhi-off-repo-triage-anonymous-clone-works-gh.md)).

Falcor CI tracking issues opened by `jkiviluoto-nv` are self-assigned CI-infrastructure work, not compiler bugs: park at triaged, don't forward to slang-fixer, but still post a verified 5-bullet whose value is cross-linking the family (#11495 → #11600 → #9219, #9228, #11703) ([Falcor CI tracking issues from jkiviluoto-nv: park at triaged, cross-link the family](../learnings/1782222346038-falcor-ci-tracking-issues-from-jkiviluoto-nv-park-.md)). The Falcor YML 3-file refactor (#11600) must reconcile build flags, since the two existing falcor workflows produce different cmake-flag artifacts; the required-check aggregator job key must be exactly `check-falcor`, and the dispatcher must add `merge_group: types:[checks_requested]` or the merge queue deadlocks. The bot cannot push `.github/workflows/*`, so deliver it as a maintainer-applied patch ([slang#11600 falcor YML 3-file refactor — triage design notes](../learnings/1781365729972-slang-11600-falcor-yml-3-file-refactor-triage-desi.md)).

`slang-pr-review-runner`'s `devin-fetch.sh` can declare completion while the middle-pane AI-analysis paragraph still shows `Generating...`, because the right-rail `Analysis complete` status and flag toggle populate before the paragraph hydrates. ## The Critique Gate Fires Even for No-Code Deliveries

`gate-critique-on-deliver.sh` keys off delivery markers (`[Fix Report]`, `[Resolution]`, `[Report]`, `gh pr create`/`gh api .../pulls`), not off whether you wrote code, so even a no-code triage confirmation with zero diff is blocked until PLAN_REVIEW, CODE_REVIEW and OUTPUT_REVIEW (`approve`) are recorded. Satisfy it honestly: write the deliverable to a file, run `/codex-critique` per stage, and frame a zero-diff CODE_REVIEW as the scope-shrinkage guard ("confirm zero-diff is correct/complete — did I silently drop an in-scope fix?", pointing codex at `git status --porcelain` + `git diff --stat`) ([Critique gate fires on no-code triage-confirmations too](../learnings/1783523465568-critique-gate-fires-on-no-code-triage-confirmation.md)). The parser is exact: it records STAGE only from a FRESH `mcp__codex__codex` call whose prompt has a `STAGE: <X>` line, and the verdict only from the skill's exact `### Verdict\napprove` block (free-text "VERDICT: approve" shows "verdicts: none"). A `codex-reply` continuation carries no STAGE tag and is never recorded, so after a must-fix, fix and issue a NEW STAGE-tagged call with the canonical developer-instructions and `ROUND: n/3` ([upsert_pr_body.py now writes the explanation as a PR comment](../learnings/1791234547680-upsert-pr-body-py-now-writes-the-explanation-as-a-.md)); every in-container codex call needs `sandbox: "danger-full-access"`. The no-code diagnoses this gate sees usually come from the STEP-0 byte-compare method for "did this diff change the emitted/serialized output?"
