# Slang Reflection API

The `spReflection*` C API and C++ wrappers: identity, layout, serialization and ABI constraints.

## TL;DR

- **`TypeReflection*` identity differs across `ProgramLayout` vs module reflection** (separate `ASTBuilder`s); key on `getFullName()`. Objects are live session pointers: persist via `-reflection-json` or a serialized module.
- **`import` (vs `#include`) loses reflection/bindings until `IComponentType::link()`** (slangc always links). A module's own layout omits `import`-only modules' globals — run "scan module globals" checks on the linked program.
- **`-reflection-json` with `-target` SIGSEGVs on EVERY failed compile** (never gated; P2). Without `-target`: E52009.
- **`//TEST:REFLECTION:` drives `slang-reflection-test` (`-no-codegen`), not `slangc -reflection-json`.** Test CLI bugs with `SIMPLE`, layout against emitted SPIR-V.
- **`-reflection-json` drops the `$Globals` CB binding** (#12307) and dedups pointee layout by `TypeReflection*` (#13190; the guard also stops self-recursion). Output-shape changes → maintainer PARK.
- **Cache-key widening:** if a memoized value starts depending on X, every cache of it keys on X in the SAME PR (#13020).
- **Layout has TWO independent engines**, AST (reflection) and IR (emit); a layout change touches both — verify with `spirv-asm` greps, pin IR bugs via `-dump-ir` FileCheck.
- **Existential `StructuredBuffer<Interface>` size diverges by phase order** (reflection 32, emit infers later); a big-enough `[anyValueSize(N)]` aligns them (root fix → PARK). In a CB, `anyValueSize` < 16 shifts later fields on vk/cuda.
- **D3D StructuredBuffer reflection does not round a nested struct's size; DXC does** (#14311); other targets match emit. Compare `-target dxil-asm` vs `-pass-through dxc`.
- **Reflection reads the AST, so it reports facts codegen ignores** (entry-point param defaults #14228, prototype-only `[numthreads]` #14230): say "ignored by codegen", not "dropped".
- **Offsets are parent-scope-relative; cumulative offset belongs to an ACCESS PATH** (public helper → PARK). `isParameterLocationUsed` needs the absolute; combined multi-entry-point emit DOES accumulate bindings (#13203).
- **`"used"` = presence in final IR after DCE**: resource-only `ParameterBlock` → `used:0` (#12349); a split CB's stale layout marks a DCE'd resource used (#13789).
- **`getElementVarLayout()` is non-null ONLY for `ParameterGroupTypeLayout`** (SSBO → null). Binding type/access come from the TYPE: a GLSL `readonly` SSBO reflects READ_WRITE (a real UAV on D3D, so fixes must be target-aware).
- **On HLSL/CPU/CUDA a spec-constant reflects as `Uniform`**; find it via `findAttributeByName(gs, "SpecializationConstant")` / `"vk_constant_id"`.
- **`include/slang-deprecated.h` holds the ACTIVE `spReflection*` C-API**; new accessors are append-only C-ABI, pinned by a `slang-unit-test`.
- **A return-value change matching `slang.h` docs can still break**: grep slangpy/slang-rhi for the OLD value as a sentinel; label `pr: breaking change`.

## Identity, lifetime, and linking

`slang::TypeReflection*` is an internal `Type*` deduplicated only within one `ASTBuilder`. A module's `getModuleReflection()` tree and the linked program's `getLayout()->findTypeByName()` can use different builders (linking and specialization build fresh nodes), so one type may have two pointers; compare `getFullName()` ([TypeReflection* identity differs across builders](../learnings/1780993688372-slang-reflection-typereflection-pointer-identity-i.md)).

Reflection objects point into live session memory. To persist, parse `-reflection-json` (programmatic: `spReflection_ToJson(SlangReflection*, SlangCompileRequest*, ISlangBlob**)`) into POD structs, or serialize the module and reflect it at runtime ([serialize via -reflection-json or a loaded module](../learnings/1782323528074-serializing-slang-reflection-use-reflection-json-o.md)).

A `[[vk::binding(n,set)]]` global reflects via `#include` but not via `import` when the host calls `getLayout()`/`getEntryPointCode()` on an unlinked composite: imported globals are *requirements*, filled only by `ComponentType::link()`'s `fillRequirements` ([import-vs-include loss = missing link()](../learnings/1782215579233-import-vs-include-reflection-binding-loss-missing-.md)). SlangPy hits the same split: `SlangModule.layout.parameters` (and composed `Module.device_module`) omits `import`-only modules' globals that `session.link_program(...).layout.parameters` lists, so a "scan module globals" check (`[[vk::push_constant]]`/`ParameterBlock`, slangpy#1235) must also run on the linked layout or `import pcmod;` slips past. Khronos validation on the L40S: Chromium's `libVkLayer_khronos_validation.so` plus a manifest (`VK_LAYER_PATH`, `enable_debug_layers=True`; no manifest = silent no-op); recipe on [[wiki/concepts/slang-test-gpu-lanes-on-shared-l40s.md]] [module layout omits import-only globals](../learnings/1792173909038-slang-module-layout-omits-globals-of-import-only-m.md).

## `-reflection-json`: crash, test directive, output-shape gaps

**Crash on failed compile (#11683).** On a front-end error `EndToEndCompileRequest::executeActionsInner` returns early (`slang-end-to-end-request.cpp:188`), leaving `m_specializedGlobalAndEntryPointsComponentType` null, but the emission block in `compile()` (`:1845-1865`) never checks the result. It SIGSEGVs on every error class, target and output mode; the trigger is exactly (failed compile) AND (`-target`), else the `if(!reflection)` guard yields `E52009`. The block (#7890, 2025-07) never had a gate: not a regression; P2, as it fires after the correct diagnostic. Three CLI discriminators localized it (repro; no `-target`; valid shader + `-target`) ([localizing the crash + REFLECTION directive](../learnings/1782146682704-localizing-slangc-reflection-json-crash-on-failed-.md), [#11683 broad scope, NOT a regression](../learnings/1782203064448-slang-11683-reflection-json-crash-is-broad-scope-a.md)).

**Test directive.** `tests/reflection/*.slang` `//TEST:REFLECTION:` drives `tools/slang-reflection-test/`, NOT `slangc -reflection-json`; a CLI regression test must invoke slangc via `SIMPLE`/`DIAGNOSTIC_TEST:SIMPLE` ([same](../learnings/1782146682704-localizing-slangc-reflection-json-crash-on-failed-.md)).

**Dropped `$Globals` scope (#12307).** `emitReflectionJSON`/`emitReflectionEntryPointJSON` iterate the flat `getParameterByIndex()` lists and never call `getGlobalParamsVarLayout()`/`EntryPointReflection::getVarLayout()`, so loose uniforms print as bare `{"kind":"uniform","offset":0}` with no containing buffer and CB slot 0 is a hole. The container emitter fires only when a *parameter's type* is a CB/PB; the reference is `examples/reflection-api/main.cpp`'s `printScope` over the global and each entry-point scope. An output-shape proposal with open trade-offs PARKs for a maintainer; DeepWiki's "JSON includes the CB binding" conflated API with JSON ([JSON drops the $Globals CB binding](../learnings/1785536267099-slang-json-reflection-drops-the-globals-cb-scope-b.md)).

**Pointee layout dedup (#13189/#13190).** `ReflectionTracker` (`slang-reflection-json.cpp:63-74`) is an add-only visited set on `TypeReflection*`; repeats emit only the type name. Once #13189 made the pointee honor the pointer's data-layout marker, sibling `Ptr<Vertex,…,ScalarDataLayout>` and `Ptr<Vertex,…,Std430DataLayout>` collapse onto the first layout (JSON-only; the C++ API returns distinct layouts). Re-keying on `TypeLayoutReflection*` is the direction, but the guard also terminates recursion on `struct Node { Ptr<Node> next; }`, so that PR needs self-referential coverage ([dedup by type, not type-layout](../learnings/1789944879524-reflection-json-dedups-pointee-layout-by-type-not-.md)). A "sibling `layoutMap` collision" hypothesis was wrong (each field lays out through a copied `fieldLayoutContext`) ([dedup by TypeReflection*](../learnings/1789943171658-reflection-json-dedups-pointee-layout-by-typerefle.md)).

## Cache-key widening: a new input joins every cache key

**If a diff makes a memoized value newly depend on state X, grep every cache of it and put X in its key, in the same PR.** Pin with a fail-before/pass-after test changing only X.

- **JSON dedup and the AST layout cache (#13189).** When a pointee's layout depends on the marker, audit both the JSON `ReflectionTracker` and the AST `layoutMap` (`Type*`-keyed, rule-blind, `slang-type-layout.h`). The AST cache cannot key on the `TypeLayoutReflection` it produces (circular); its key must cover all layout-affecting inputs ([same](../learnings/1789943171658-reflection-json-dedups-pointee-layout-by-typerefle.md)).
- **Language version in reflection lookup (#13015/#13020).** The null-`currentModule` crash fix threaded `getLanguageVersion()` into term parsing, but `ComponentType::m_types` (`findTypeByName`) and `m_decls` (`findDeclFromString`) key on the string alone (`slang-linkable.cpp:832`); after a supported mid-session `-std 2026` on one linkage, `findTypeByName("(int, float)")` returns a stale `float` (comma expr) instead of null. Fix: key both on `(string, languageVersion)` via `SLANG_COMPONENTWISE_HASHABLE_2`, one version source for get and put. Probe "version-independent" siblings with a generic argument (`findFunctionByName("pick<(int, float)>")`); test on one linkage via `spProcessCommandLineArguments` (separate reflection objects have separate caches) ([new dependency must extend the cache key](../learnings/1789172524588-threading-a-new-dependency-into-a-cached-parse-loo.md)).

## Two independent layout engines (AST reflection vs IR codegen)

1. **AST / program-layout engine**: `slang-type-layout.cpp` (`LayoutRulesImpl`, `EndStructLayout`, `GLSLLayoutRulesFamilyImpl::get*Rules`) feeds the reflection API, `-reflection-json` and `//TEST:REFLECTION`; `_lowerTypeLayoutCommon` lowers it into reflection `IRTypeLayout` (`IRTypeSizeAttr`; PR #11135 adds `IRTypeAlignmentAttr`).
2. **IR / codegen engine**: `slang-ir-layout.cpp` + `slang-ir-lower-buffer-element-type.cpp` compute size AND alignment on demand from the IR type plus a rules object, cached on `IRSizeAndAlignmentDecoration`; SPIR-V `Offset`/`ArrayStride` come from here.

They share no code: a change only in engine 1 moves reflection while SPIR-V is unchanged (hosts laying out buffers from reflection corrupt data); a reflection alignment attr does not change emission ([TWO type-alignment systems](../learnings/1785528040007-slang-has-two-type-alignment-systems-reflection-ir.md)). IR-engine traps: `IRTypeLayoutRuleName::Scalar` aliases `Natural`, and `NaturalLayoutRules::alignCompositeElement` doesn't round aggregate size up, so a real scalar-layout change needs a distinct IR rule threaded through `getTypeLayoutRuleNameForBuffer`, `IRTypeLayoutRules::get()`, `getOpFromTypeLayoutRuleName` and the `==Natural` special cases; `-emit-spirv-via-glsl` computes no offsets (glslang `layout(scalar)` does) ([a layout flag must touch both engines](../learnings/1789151128965-slang-layout-has-two-independent-engines-reflectio.md)).

**Verify per target, measuring both sides.** `RWStructuredBuffer<{int2;float4}, ScalarDataLayout>` emitted `ArrayStride 24`; `-reflection-json` said 32. Check `slangc -target spirv-asm … | grep -E 'MemberDecorate.*Offset|ArrayStride'` (flag on vs off), not a REFLECTION test. Pin with `git worktree add` (peers reset the shared checkout mid-task) ([measure emitted AND reflection](../learnings/1782325331597-verifying-slang-per-target-buffer-layout-measure-e.md)).

**Testing IR-layout internals.** An IR-layout representation bug (attr operand ordering, `getSizeAttrs()` contiguity) passes any REFLECTION test on good and buggy binaries alike, since reflection reads the AST `TypeLayout`. Pin it with `//TEST:SIMPLE(filecheck=...):-dump-ir` (prints layout attrs like `size(8 : Int, 32 : Int)`) using ID-agnostic variable capture and CHECK-DAG on the attr-def lines, and run the revert drill ([reflection cannot test IR-layout bugs](../learnings/1785539323116-slang-reflection-api-json-is-ast-based-cannot-test.md), [same](../learnings/1785528040007-slang-has-two-type-alignment-systems-reflection-ir.md)).

**D3D StructuredBuffer reflection vs DXC (#14311).** For `struct Inner { uint64_t key; uint value; }; struct Outer { Inner item; uint tail; };` in a `StructuredBuffer<Outer>` (master 3da6f63c0e), hlsl/dxil reflection reports `Inner` size 12, `tail` at 12, `Outer` 16; DXC puts `tail` at 16, size 24 (DXIL `; Buffer Definitions`, `rawBufferLoad` offset). `HLSLStructuredBufferLayoutRulesImpl` (`slang-type-layout.cpp:997-1008`) inherits the non-rounding `DefaultLayoutRulesImpl::EndStructLayout`; HLSL emit prints only the struct, so DXC decides the layout and reflection is wrong. Other targets' SB reflection matches their emit (SPIR-V std430 16/24, scalar 12/16, via-GLSL 16/24, CUDA base+16). `ByteAddressBuffer.Load<T>` is natural layout (byte 12) on EVERY target unless `-fvk-use-gl-layout` (`slang-ir-byte-address-legalize.cpp:610-631`), so raw-vs-structured disagreement is not D3D-only. Differential: `-target dxil-asm` vs `-pass-through dxc` (Release ships `libdxcompiler.so`). Note `getTypeLayout(type, LayoutRules::Default)` on HLSL uses CONSTANT-BUFFER rules; only `DefaultStructuredBuffer` and entry-point SB parameters get SB rules (`getInitialLayoutContextForTarget`, `slang-type-layout.cpp:3036-3080`) ([D3D SB reflection never rounds nested struct size](../learnings/1793815057187-d3d-structuredbuffer-reflection-never-rounds-neste.md)).

**Existential size (#12092).** For `StructuredBuffer<Interface>` without `[anyValueSize(N)]`, reflection and emit disagree by phase order. Reflection: `_createTypeLayout` (`slang-type-layout.cpp:5982`) defaults `fixedExistentialValueSize = 16` (only `AnyValueSizeAttribute` overrides) + a 16-byte RTTI/witness header → 32. Emit: `inferAnyValueSizeWhereNecessary` (`slang-ir-any-value-inference.cpp`, later) takes max conformer size + header, so a `float4x4` conformer gives ArrayStride 80. A large-enough `[anyValueSize(N)]` makes both agree (too small: `TypeDoesNotFitAnyValueSize`). Reproduce: `spirv-asm | grep ArrayStride` vs C++ `getSize()`. Tracking the inferred size vs keeping 16 as ABI default is a maintainer call → PARK ([existential 32 vs ArrayStride 80](../learnings/1784022520457-slang-reflection-existential-size-32-vs-emitted-ar.md)).

**Existential in a CB with `anyValueSize` < 16 (#14181).** Reflection sizes an interface-typed field `{uint2 rtti, uint2 witness, AnyValueN}` as 16+N. Emitted std140 (SPIR-V/GLSL/WGSL) wraps the payload in a 16-rounded struct (32 bytes total); CUDA rounds 16+N to a multiple of 8. Later fields sit where reflection doesn't say: on `-vk` with N in {4, 8, 12} the payload and following fields read 0, on `-cuda` (N in {4, 12}) the following field; `-cpu` and N ≥ 16 work. If a dynamic-dispatch CB test reads zeros on vk, check `anyValueSize` first; compare `spirv-asm` `OpMemberDecorate %Params_std140 1 Offset` with `-reflection-json` ([existential in a CB, anyValueSize < 16](../learnings/1793622876556-existential-in-a-constant-buffer-with-anyvaluesize.md)).

**Reflection reads AST facts that codegen ignores (#14228, #14230).** An entry-point parameter default (`uniform uint scale = 4`, `= nullptr`) is accepted undiagnosed and ignored by codegen (CUDA `K(uint* counts_0, uint scale_0)`; JSON shows none), yet `getDefaultValueBlob` returns 4 for `scale` and an empty non-null blob for `nullptr`: `spReflectionVariable_HasDefaultValue` checks `VarDeclBase::initExpr`, and `ParamDecl` is a `VarDeclBase`. Likewise `[shader("compute")][numthreads(4,1,1)]` on the prototype only makes an entry point with SPIR-V `LocalSize 1 1 1` while reflection reports `[4,1,1]`; a prototype `[ForceInline]` is ignored; prototype `[numthreads]` + definition `[shader]` lists two same-named entry points. Each redeclaration lowers to one mangled name (hypothesis: the prototype's decorations are lost when the definition wins). DXC honours prototype attributes (`-pass-through dxc`, `grep -a` for `!{i32 4, i32 1, i32 1}`). Say "ignored by codegen", not "dropped"; probe the API with ~30 lines of C++ (compose, getLayout, loop `getDefaultValueBlob`) ([param defaults codegen ignores](../learnings/1793676617873-the-slang-reflection-api-reports-default-values-on.md), [prototype attributes read only by reflection](../learnings/1793680339435-slang-ignores-attributes-on-a-function-prototype-i.md)).

## Offsets, bindings, and usage

**Relative offsets; cumulative offset is a path property (#12183).** `getOffset(category)`/`getBindingSpace(category)` are parent-scope-relative by design (containers transform layout units); cumulative-offset logic exists only in the reflection-api example. One `VariableLayoutReflection` reused in two places has two cumulative offsets, so `varLayout->getCumulativeOffset()` cannot work; the example threads an `AccessPath` with `deepestConstantBuffer`/`deepestParameterBlock`. Appending to the opaque-handle wrappers is ABI-safe, but how callers supply the path is a public-API call → PARK. For "promote helper X from the example", grep source/include and check whether X needs context the node lacks ([cumulative offset is a path property](../learnings/1784676089970-reflection-cumulative-offset-is-a-path-property-no.md)).

**Entry-point scopes (#13203).** `collectEntryPointParameters` builds a fresh `SimpleScopeLayoutBuilder` per entry point (`slang-parameter-binding.cpp:3358`), so leaf offsets are entry-point-relative. `spIsParameterLocationUsed` takes the ABSOLUTE location = leaf + every enclosing scope incl. `EntryPointReflection::getVarLayout()->getOffset(category)`; EP1's scope offset is 0 (masking the bug), EP2's isn't. Prefer `getOffset(category)` over `getBindingIndex()`. **Correction of an earlier "no bloat" reading:** one `slangc` run over several entry points DOES accumulate bindings in emitted code (SPIR-V EP2 → 3/4/5; HLSL → b1/t1/u1); only per-entry-point emit resets. Verify on the whole file with no `-entry`; the reset policy is design-gated ([multi-EP binding bloat IS real](../learnings/1790016065362-correction-entry-point-uniform-binding-bloat-acros.md)).

**`"used"` is presence in final IR (#12349, #13789).** JSON `used` (entry-point `bindings` only) comes from `spIsParameterLocationUsed` → `getUsedBindingRanges().containsBinding(...)`, built by `collectMetadata` (`slang-ir-metadata.cpp`), which runs LAST, after DCE. A `ParameterBlock`'s `SubElementRegisterSpace` is recorded only in the container-var-layout branch, which needs a surviving `IRGlobalParam` with an `IRParameterGroupTypeLayout`; a resource-only block legalizes into top-level globals, so the space reports `used:0` though used (one uniform field flips it to `used:1`). A metadata gap; there is no per-field `used` ([used:0 on a ParameterBlock space](../learnings/1786583259247-reflection-used-0-on-a-parameterblock-subelementre.md)). The branch also errs the other way: when a CB-style group mixes data and resources, legalization moves the resources to their own `global_param`s but the data-only remainder keeps the ORIGINAL `parameterGroupTypeLayout` (`size(9 /*DescriptorTableSlot*/, 2)` covers both resources); `collectMetadataFromInst` (`slang-ir-metadata.cpp:219-235`) inserts that whole range, so a DCE'd resource reports used (not pass ordering: `unusedBuf` is already gone). Affected (SPIR-V/WGSL/HLSL/GLSL): entry-point `uniform float4` plus resources, `uniform P p`, global `ConstantBuffer<P>`; not `ParameterBlock<P>`. Check the data-only global_param's `[layout]` "AFTER collectMetadata" in `-dump-ir` ([split CB keeps stale resource size attrs](../learnings/1792522133573-isparameterlocationused-false-positive-split-const.md)). Both are metadata reading a container layout that no longer matches the legalized params; fix that layout's producer, not `isParameterLocationUsed`.

**`getElementVarLayout()` and buffer kinds.** Non-null only for a `ParameterGroupTypeLayout`: `ConstantBuffer`/`TextureBuffer`/`ParameterBlock` derive from `UniformParameterGroupType : ParameterGroupType` (`slang-ast-type.h`); sibling `GLSLShaderStorageBufferType : PointerLikeType` → null, so null-check. HLSL `(RW)StructuredBuffer<T>` reflects as `Kind::Resource`; only `GLSLShaderStorageBuffer<T, Std430DataLayout>` gives `Kind::ShaderStorageBuffer`. PR #12715's `reflection::Cursor::navigateToContent()` crashed dereferencing that null for SSBO ([getElementVarLayout null outside ParameterGroup](../learnings/1787658477648-slang-reflection-getelementvarlayout-is-null-for-n.md)).

**Binding type and access come from the TYPE, so a GLSL `readonly` buffer reflects writable (#13972).** `_calcResourceBindingType` and `spReflectionType_GetResourceAccess` (`slang-reflection-api.cpp`) read the type; `readonly`/`writeonly` lives only on the VarDecl (`MemoryQualifierSetModifier`), so every GLSL `buffer` block reflects MUTABLE_RAW_BUFFER / READ_WRITE, and `SlangModifierID` has no readonly. A decl-aware fix is reachable (`BindingRangePathLink::var` carries the `VarLayout`), but access is target-dependent: off Khronos every SSBO becomes a `RWStructuredBuffer`, so on D3D a readonly SSBO really is a UAV and one global answer breaks D3D12 hosts. What breaks is slang-rhi's wgpu backend: MutableRaw→Storage from `getDescriptorSetDescriptorRangeType` (`wgpu-shader-object-layout.cpp` ~:279) plus VERTEX visibility, which WebGPU rejects. JSON and slang-reflection-test print no SSBO access; probe in C++ (`enableGLSL=true`) ([readonly SSBO reflection is type-only](../learnings/1793207233447-glsl-readonly-ssbo-reflection-is-type-only-slang-r.md)).

**`findFieldIndexByName`.** Returns the first match (a same-named global from another module is unreachable by bare name); `matchName` already handles `Module.var`/`Module::var` (last segment vs name, qualifiers via `getParentDecl`), and both are reachable via `getFieldCount`/`getFieldByIndex` ([findFieldIndexByName supports module.var](../learnings/1782456046812-slang-reflection-findfieldindexbyname-already-supp.md)).

**Specialization constants on uniform-layout targets (slang-rhi#943).** On HLSL/CPU/CUDA a `[SpecializationConstant]`/`[vk::constant_id]` global is an ordinary uniform: category `Uniform` (8), not `SpecializationConstant` (10), no `SlangModifierID`. `findAttributeByName(gs, "SpecializationConstant")` or `"vk_constant_id"` finds it everywhere (the parser renames `vk::constant_id`; that spelling returns null). `getDefaultValueBlob` bytes are target-independent (`bool` gives 4 though CPU/CUDA size is 1; a non-literal initializer gives none). slang-rhi cannot set spec-constant values; on Vulkan/WGPU `ShaderCursor["k"].setData()` returns SLANG_OK and does nothing (`ShaderObject::setData` clamps to `m_data`). slang-rhi tests skip CPU on Linux (`tests/testing.cpp:900-904`); use `-select-devices=cpu,cuda,vulkan`, configure with `-DSLANG_RHI_BUILD_TESTS_WITH_GLFW=OFF -DSLANG_RHI_BUILD_EXAMPLES=OFF` ([spec constants on uniform-layout targets](../learnings/1792933241509-slang-spec-constants-on-uniform-layout-targets-d3d.md)).

## The C-API surface and adding accessors

`include/slang-deprecated.h` is NOT purely deprecated: PR #5301 (2024-10) moved the whole `sp*` C interface there from `slang.h` (which includes it); its `spReflection*` family (~168 functions) backs the C++ wrappers, and only the `ICompileRequest` workflow (`spCreateSession`, `spCompile`, …) is legacy ([slang-deprecated.h holds the ACTIVE C-API](../learnings/1782754805883-slang-include-slang-deprecated-h-holds-the-active-.md)).

**Adding an accessor (`getContentVarLayout`, #12776).** All SB layout creation funnels through `createStructuredBufferTypeLayout` (`slang-type-layout.cpp:4402`), so a per-SB layout stored there has stable identity. SBs have no array layer (`GetElementStride` 0); a content array view is an `ArrayTypeLayout` over `getArrayType(elementType, nullptr)` with the element's array stride (`Kind::Array`). `spReflectionTypeLayout_*` are free `SLANG_API` functions, so a new accessor is append-only and non-breaking (prototype in `slang-deprecated.h`, wrapper in `slang.h`). Test via a C++ `slang-unit-test` (model `unit-test-atomic-reflection.cpp`, no GPU), not `//TEST:REFLECTION`: a new JSON field churns ~180 `.expected` baselines and is an output-format decision. When a maintainer must sign off on the name, the artifact is a draft PR with build-verified code and a semantics-pinning test ([getContentVarLayout producer-side](../learnings/1787777108008-reflection-getcontentvarlayout-producer-side-conte.md)).

**Changing what an accessor returns (PR #13535).** `TypeReflection::getElementCount()` for unsized `T[]` changed 0 → `SLANG_UNBOUNDED_SIZE`, as `slang.h` documented. Downstream uses 0 as a marker: slangpy's `is_generic()` (`num_elements()==0`), `any_generic_dims`, `builtin/array.py`, `tensorcommon.py` treat 0 as "generic/unsized" and store `int(element_count())` (`float[] a` now reads -1); slang-rhi Metal's `collectPointerFields` (`if(count==0) return; for(i<count)`) loops effectively forever. When a reflection value changes, grep slangpy and slang-rhi for the old value as a sentinel (`== 0`, `> 0`, casts), not only the accessor, and label `pr: breaking change`. `CI SlangPy Trigger Test` SKIPS bot-authored PRs; dispatch it (`workflow_dispatch pr_number=N`) ([return-value fixes matching slang.h can still break](../learnings/1791504997222-reflection-return-value-fixes-that-match-slang-h-d.md)).
