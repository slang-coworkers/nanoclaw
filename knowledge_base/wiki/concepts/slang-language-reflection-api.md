# Slang Reflection API

The C reflection API (`spReflection*`) and C++ wrappers (`TypeReflection`, `ProgramLayout`, …): non-obvious identity, layout, serialization and ABI constraints.

## TL;DR

- **`TypeReflection*` pointer identity is not safe across `ProgramLayout` vs module reflection** (different `ASTBuilder`s). Key on `getFullName()`.
- **Reflection objects are live session pointers — not serializable.** Use `-reflection-json` → POD structs, or serialize the module and reflect at runtime.
- **`import` (vs `#include`) loses reflection/bindings until `IComponentType::link()`**; `slangc` always links, so the CLI never reproduces it.
- **A module's own layout lists only its own and `link=` modules' globals, not those of modules it merely `import`s;** the linked program's layout does. Run any "scan module globals" check on the linked program too.
- **The CLI flag is `-reflection-json`.** With `-target` it SIGSEGVs on EVERY failed compile (no result gate since 2025-07; not a regression; P2). Without `-target`: E52009.
- **`//TEST:REFLECTION:` drives `slang-reflection-test`, not `slangc -reflection-json`, and runs `-no-codegen`.** Test a CLI bug with `SIMPLE`/`DIAGNOSTIC_TEST:SIMPLE`; test a layout change against emitted SPIR-V.
- **`-reflection-json` drops the implicit `$Globals` CB binding** (#12307). Output-shape changes are a maintainer design call → PARK.
- **`-reflection-json` dedups a pointee's layout by `TypeReflection*`**, wrong once the layout is context-dependent (#13190); the same guard stops self-referential recursion.
- **Cache-key widening:** if a memoized per-type/per-string value starts depending on state X, every cache of it must key on X in the SAME PR (#13020; JSON dedup + layout marker).
- **Layout has TWO independent engines** — AST (reflection) and IR (emitted SPIR-V), sharing no code. A layout change must touch both; verify with `spirv-asm` greps. IR-internal bugs are invisible to reflection tests (pin via `-dump-ir` FileCheck).
- **Existential (`StructuredBuffer<Interface>`) size diverges by phase order:** reflection reads the AST `[anyValueSize]` (default 32), emit the later inference pass. An explicit large-enough `[anyValueSize(N)]` makes both agree; root fix → PARK.
- **Offsets are relative to the immediate parent scope by design; cumulative offset is a property of an ACCESS PATH** — a public helper is an ABI design call → PARK.
- **Entry-point uniform offsets are scope-relative**; `isParameterLocationUsed` needs the absolute. Combined multi-entry-point emit DOES accumulate binding indices (#13203, real bug).
- **`"used"` = presence in final IR after DCE** — a resource-only `ParameterBlock` reports `used:0` (#12349); a mixed data+resource ConstantBuffer's data-only remainder keeps the old layout, so a DCE'd resource reports used (#13789).
- **`getElementVarLayout()` is non-null ONLY for `ParameterGroupTypeLayout`**; `GLSLShaderStorageBuffer` gives null; HLSL `StructuredBuffer` reflects as `Kind::Resource`.
- **Binding type and resource access come from the TYPE only**, so a GLSL `readonly` SSBO reflects MUTABLE_RAW/READ_WRITE; on D3D it really is a UAV, so a fix must be target-aware.
- **On HLSL/CPU/CUDA a spec-constant global reflects as an ordinary `Uniform`.** Find it with `findAttributeByName(gs, "SpecializationConstant")` or `"vk_constant_id"`; `getDefaultValueBlob` sizes are target-independent.
- **`include/slang-deprecated.h` holds the ACTIVE `spReflection*` C-API**; a new accessor there is append-only C-ABI — pin with a `slang-unit-test`, not `-reflection-json`.
- **Changing a reflection return value is potentially breaking even when it matches `slang.h` docs** — grep slangpy and slang-rhi for the OLD value as a sentinel, label `pr: breaking change`, and dispatch `CI SlangPy Trigger Test` manually on bot PRs.

## Identity, lifetime, and linking of reflection objects

`slang::TypeReflection*` is an internal `Type*` deduplicated only within one `ASTBuilder`. A module's `getModuleReflection()` decl tree and the linked program's `getLayout()->findTypeByName()` can use different builders (linking and generic specialization build fresh nodes), so one logical type may have two pointers — compare by `getFullName()` ([TypeReflection* pointer identity is not safe across ProgramLayout vs module reflection](../learnings/1780993688372-slang-reflection-typereflection-pointer-identity-i.md)).

Reflection objects point into live session memory. Two persistence strategies: (1) `-reflection-json` (programmatic: `spReflection_ToJson(SlangReflection*, SlangCompileRequest*, ISlangBlob**)`) parsed into POD structs; (2) serialize the compiled module and reflect it at runtime in a live session ([Serializing Slang reflection: -reflection-json or a loaded module](../learnings/1782323528074-serializing-slang-reflection-use-reflection-json-o.md)).

A global with `[[vk::binding(n,set)]]` reflects via `#include` but returns nothing via `import` when the host calls `getLayout()`/`getEntryPointCode()` on a composite without `IComponentType::link()`: imported module globals are *requirements*, and `fillRequirements` runs only from `ComponentType::link()` ([import-vs-include reflection/binding loss = missing link()](../learnings/1782215579233-import-vs-include-reflection-binding-loss-missing-.md)). SlangPy hits the same split: `SlangModule.layout.parameters` (including the composed `Module.device_module`) lists only the module's own and `link=` modules' globals, not those of `import`-only modules, while `session.link_program(...).layout.parameters` lists them even if unused. So a "scan the module globals" check (a `[[vk::push_constant]]` block or `ParameterBlock`, slangpy#1235) must also run on the linked layout, or `import pcmod;` slips past. Repro: module `pcimp` declares `[[vk::push_constant]] uniform PC push;` and the main module does `import pcimp;` — composed globals `[]`, linked program `['push']`. Khronos validation on the coworker L40S works via Chromium's `/usr/lib/chromium/libVkLayer_khronos_validation.so` plus a manifest (`VK_LAYER_PATH=/tmp/vklayer`, `spy.Device(..., enable_debug_layers=True)`; without the manifest `enable_debug_layers` silently does nothing). Recipe: [[wiki/concepts/slang-test-gpu-lanes-on-shared-l40s.md]] [module layout omits globals of import-only modules](../learnings/1792173909038-slang-module-layout-omits-globals-of-import-only-m.md).

## `-reflection-json`: crash, test directive, and output-shape gaps

**Crash on failed compile (#11683).** On a front-end error `EndToEndCompileRequest::executeActionsInner` returns early (`slang-end-to-end-request.cpp:188`), leaving `m_specializedGlobalAndEntryPointsComponentType` null, but the emission block in `compile()` (`:1845-1865`) runs without checking the result. It SIGSEGVs on every error class, target and output mode; the trigger is exactly (failed compile) AND (`-target`) — otherwise the `if(!reflection)` guard yields `E52009`. The block (#7890, 2025-07) never had a gate: not a regression, and P2 since it fires after the correct diagnostic. Three CLI discriminators localized it (repro; drop `-target`; valid shader + `-target`) ([Localizing the -reflection-json crash (#11683) + REFLECTION directive](../learnings/1782146682704-localizing-slangc-reflection-json-crash-on-failed-.md), [#11683 crash is broad scope and NOT a regression](../learnings/1782203064448-slang-11683-reflection-json-crash-is-broad-scope-a.md)).

**Test directive.** `tests/reflection/*.slang` `//TEST:REFLECTION:` drives `tools/slang-reflection-test/`, NOT `slangc -reflection-json`; a CLI regression test must invoke slangc via `SIMPLE`/`DIAGNOSTIC_TEST:SIMPLE` ([Localizing the -reflection-json crash (#11683) + REFLECTION directive](../learnings/1782146682704-localizing-slangc-reflection-json-crash-on-failed-.md)).

**Dropped `$Globals` scope (#12307).** `emitReflectionJSON`/`emitReflectionEntryPointJSON` iterate the flat `getParameterByIndex()` lists and never call `getGlobalParamsVarLayout()` / `EntryPointReflection::getVarLayout()`, so loose uniforms print as bare `{"kind":"uniform","offset":0}` with no containing buffer, and the CB's slot 0 appears as an unexplained hole. The container+element emitter (`emitReflectionParameterGroupTypeLayoutInfoJSON`) fires only when a *parameter's type* is a CB/PB; the clean reference is `examples/reflection-api/main.cpp`'s `printScope`, applied to the global scope and each entry point. An output-shape proposal with open trade-offs PARKs for a maintainer. DeepWiki's claim that the JSON "includes" the CB binding conflated API with JSON output; check against source ([JSON reflection drops the $Globals CB scope binding (#12307)](../learnings/1785536267099-slang-json-reflection-drops-the-globals-cb-scope-b.md)).

**Pointee layout dedup (#13189/#13190).** `ReflectionTracker` (`slang-reflection-json.cpp:63-74`; pointer case `:912-931`) is an add-only visited set keyed on `TypeReflection*`; after the first expansion it emits only the type name. Once #13189 made the pointee honor the pointer's data-layout marker, sibling `Ptr<Vertex,…,ScalarDataLayout>` and `Ptr<Vertex,…,Std430DataLayout>` collapse onto the first layout — JSON-only; the C++ API returns two distinct `getElementTypeLayout()`. Re-keying on `TypeLayoutReflection*` is the direction, but the guard also terminates recursion on `struct Node { Ptr<Node> next; }`, so that PR needs self-referential coverage ([reflection-JSON dedups pointee layout by type, not type-layout](../learnings/1789944879524-reflection-json-dedups-pointee-layout-by-type-not-.md)). A "sibling `layoutMap` collision" hypothesis was WRONG — each field lays out through a COPIED `fieldLayoutContext` — so the divergence is only in the JSON dedup ([reflection-json dedups pointee layout by TypeReflection*](../learnings/1789943171658-reflection-json-dedups-pointee-layout-by-typerefle.md)).

## Cache-key widening: a new input must join every cache key

**Rule: if a diff makes a previously input-independent memoized value depend on state X, grep for every cache of that value and put X in its key — in the same PR.** Pin with a fail-before/pass-after test that changes only X.

- **JSON dedup and the AST layout cache (#13189).** When a pointee's layout depends on the layout marker, audit both the JSON `ReflectionTracker` and the AST `layoutMap` (`Type*`-keyed, rule-blind, `slang-type-layout.h`). The AST cache cannot key on the `TypeLayoutReflection` it produces (circular); its key must cover all layout-affecting inputs ([reflection-json dedups pointee layout by TypeReflection*](../learnings/1789943171658-reflection-json-dedups-pointee-layout-by-typerefle.md)).
- **Language version in reflection lookup (#13015/#13020).** Fixing the null-`currentModule` crash threaded `getLanguageVersion()` into `parseTermFromSourceFile`/`parseTermString`, but `ComponentType::m_types` (`getTypeFromString`/`findTypeByName`) and `m_decls` (`findDeclFromString`) key on the string alone and return before consulting the version (`slang-linkable.cpp:832`, key `:860`). A mid-session `-std` change on one linkage is supported and tested (`reflectionRefreshesChangedLanguageVersion`), so `findTypeByName("(int, float)")` returns a stale `float` (comma expr) after `-std 2026` (tuple → null). Fix: key both on `(string, languageVersion)` via `SLANG_COMPONENTWISE_HASHABLE_2`/`EQUALITY_2`, one version source for get and put. Probe a "version-independent" sibling with a generic argument: `findFunctionByName("pick<(int, float)>")` smuggles version-dependent grammar into `m_decls`. Test on one linkage via `spProcessCommandLineArguments` (separate reflection objects have separate caches) ([a new dependency in a cached parse/lookup must extend the cache key](../learnings/1789172524588-threading-a-new-dependency-into-a-cached-parse-loo.md)).

## Two independent layout engines (AST reflection vs IR codegen)

Slang computes buffer layout twice, with no shared code:

1. **AST / program-layout engine** — `slang-type-layout.cpp` (`LayoutRulesImpl`, `EndStructLayout`, `GLSLLayoutRulesFamilyImpl::get*Rules`). Feeds the reflection API, `-reflection-json` and `//TEST:REFLECTION`. Lowered into reflection `IRTypeLayout` by `_lowerTypeLayoutCommon` (historically only `IRTypeSizeAttr`; PR #11135 adds `IRTypeAlignmentAttr`).
2. **IR / codegen engine** — `slang-ir-layout.cpp` + `slang-ir-lower-buffer-element-type.cpp`. Computes size AND alignment on demand from the IR type plus a rules object, cached on `IRSizeAndAlignmentDecoration`; SPIR-V `Offset`/`ArrayStride` come from here.

A change made only in engine 1 moves reflection while SPIR-V is unchanged (a host laying out buffers from reflection then corrupts data), and adding an alignment attr to reflection layouts does not change emission ("SPIR-V divines alignment" is wrong) ([Slang has TWO type-alignment systems](../learnings/1785528040007-slang-has-two-type-alignment-systems-reflection-ir.md), [layout has two independent engines — a flag must touch both](../learnings/1789151128965-slang-layout-has-two-independent-engines-reflectio.md)). IR-engine traps: `IRTypeLayoutRuleName::Scalar` is a literal alias of `Natural`, and `NaturalLayoutRules::alignCompositeElement` does not round aggregate size up, so a real scalar-layout change needs a distinct IR rule threaded through `getTypeLayoutRuleNameForBuffer`, `IRTypeLayoutRules::get()`, `getOpFromTypeLayoutRuleName` and the `==Natural` special cases; `-emit-spirv-via-glsl` computes no offsets (defers to glslang `layout(scalar)`), so padding there means synthesized members ([layout has two independent engines — a flag must touch both](../learnings/1789151128965-slang-layout-has-two-independent-engines-reflectio.md)).

**Verify per target, measuring both sides.** `RWStructuredBuffer<{int2;float4}, ScalarDataLayout>` emitted `ArrayStride 24` while `-reflection-json` reported 32. Check `slangc -target spirv-asm … | grep -E 'MemberDecorate.*Offset|ArrayStride'` (flag on vs off), not a REFLECTION test. A `--target slangc`-only build cannot emit SPIR-V, and peers reset the shared checkout mid-task — pin with `git worktree add` ([Verifying per-target buffer layout: measure emitted AND reflection](../learnings/1782325331597-verifying-slang-per-target-buffer-layout-measure-e.md)).

**Testing IR-layout internals.** Reflection reads the AST `TypeLayout`, so an IR-layout representation bug (attr operand ordering, `getSizeAttrs()` contiguity) passes any REFLECTION test under good and buggy binaries alike. Pin it with `//TEST:SIMPLE(filecheck=...):-dump-ir` (which prints layout attrs like `size(8 : Int, 32 : Int)`, `structTypeLayout(...)`) using ID-agnostic variable capture and CHECK-DAG on the attr-def lines, and run the revert drill ([reflection API/JSON is AST-based — cannot test IR-layout bugs](../learnings/1785539323116-slang-reflection-api-json-is-ast-based-cannot-test.md), [Slang has TWO type-alignment systems](../learnings/1785528040007-slang-has-two-type-alignment-systems-reflection-ir.md)).

**Existential size (#12092).** For `StructuredBuffer<Interface>` without `[anyValueSize(N)]`, reflection and emit disagree by phase order. Reflection: `_createTypeLayout` (`slang-type-layout.cpp:5982`) defaults `fixedExistentialValueSize = 16`, overrides it only from `AnyValueSizeAttribute`, and adds a 16-byte RTTI/witness header → 32. Emit: `inferAnyValueSizeWhereNecessary` (`slang-ir-any-value-inference.cpp`, scheduled at `slang-emit.cpp:1500`, after reflection) takes the max conformer size + header → a `float4x4` conformer gives ArrayStride 80. A large-enough explicit `[anyValueSize(N)]` makes both agree; too-small diagnoses `TypeDoesNotFitAnyValueSize`. Reproduce with `spirv-asm | grep ArrayStride` vs C++ `getSize()` (the JSON omits it). Whether reflection should track the inferred size or keep 16 as an ABI default is a maintainer call → PARK ([existential size 32 vs emitted ArrayStride 80 (#12092)](../learnings/1784022520457-slang-reflection-existential-size-32-vs-emitted-ar.md)).

## Offsets, bindings, and usage

**Relative offsets; cumulative offset is a path property (#12183).** `getOffset(category)`/`getBindingSpace(category)` are relative to the immediate parent scope by design, and containers hide/transform layout units. Cumulative-offset logic exists only in the reflection-api example (zero hits in `source/`/`include/`). One `VariableLayoutReflection` reused in two places has different cumulative offsets per context, so `varLayout->getCumulativeOffset()` cannot work; the example threads an `AccessPath` with `deepestConstantBuffer`/`deepestParameterBlock`. Appending to the thin opaque-handle wrappers is ABI-safe, but how callers supply the path is a public-API design call → PARK. Triage rule for "promote helper X from the example": grep source/include for the gap, and check whether X needs context the node lacks ([cumulative offset is a path property, not a node property (#12183)](../learnings/1784676089970-reflection-cumulative-offset-is-a-path-property-no.md)).

**Entry-point scopes (#13203).** `collectEntryPointParameters` builds a fresh `SimpleScopeLayoutBuilder` per entry point (`slang-parameter-binding.cpp:3358/3482`), so leaf offsets are entry-point-relative and two entry points can report the same values. `spIsParameterLocationUsed` (`slang-reflection-api.cpp:5138`) takes the ABSOLUTE location = leaf + every enclosing scope, including `EntryPointReflection::getVarLayout()->getOffset(category)` (the `calculateCumulativeOffset` recipe); EP1's scope offset is 0 (masks the bug), EP2's is not. Prefer `getOffset(category)` over `getBindingIndex()`. **Correction to an earlier "no bloat" reading:** one `slangc` run over multiple entry points DOES accumulate absolute bindings in emitted code (SPIR-V EP2 → 3/4/5; HLSL → b1/t1/u1), O(N·k) vs expected O(k); only separate per-entry-point emit resets. Verify on the whole file with no `-entry`; it is a real bug whose reset policy is design-gated ([CORRECTION: multi-entry-point binding bloat IS real (#13203)](../learnings/1790016065362-correction-entry-point-uniform-binding-bloat-acros.md)).

**`"used"` is presence in final IR (#12349).** The JSON emits `used` only in the entry-point `bindings` array, via `spIsParameterLocationUsed` → `getUsedBindingRanges().containsBinding(...)`, built by `collectMetadata` (`slang-ir-metadata.cpp`), which runs LAST, after DCE. A `ParameterBlock`'s `SubElementRegisterSpace` is recorded only in the container-var-layout branch, which needs a surviving `IRGlobalParam` with an `IRParameterGroupTypeLayout`; a resource-only block is legalized into top-level globals, so the space reports `used:0` though its resource is used. Adding one uniform field keeps the block and flips it to `used:1`. A metadata gap, not container semantics; there is no per-field `used` ([used:0 on a ParameterBlock subElementRegisterSpace is a metadata gap](../learnings/1786583259247-reflection-used-0-on-a-parameterblock-subelementre.md)).

The same branch also errs the other way (#13789, at master 7251cc60b). When a ConstantBuffer-style group mixes data and resources, type legalization moves the resources into their own `global_param`s, but the data-only `entryPointParams`/`gP` remainder keeps the ORIGINAL `parameterGroupTypeLayout`, whose `size(9 /*DescriptorTableSlot*/, 2)` still covers both resource fields. `collectMetadataFromInst` (`slang-ir-metadata.cpp:219-235`) inserts that whole range, so a DCE'd resource reports used. Not pass ordering: `unusedBuf` is already gone when `collectMetadata` runs. Affected on SPIR-V/WGSL/HLSL/GLSL: entry-point `uniform float4` plus resources, entry-point `uniform P p`, global `ConstantBuffer<P>`; not `ParameterBlock<P>` or data-free groups. Fast check: `slangc x.slang -target spirv -dump-ir -o x.spv`, read the data-only global_param's `[layout]` in "AFTER collectMetadata" ([isParameterLocationUsed false positive: split ConstantBuffer keeps stale resource size attrs](../learnings/1792522133573-isparameterlocationused-false-positive-split-const.md)). Both #12349 and #13789 are metadata reading a container layout that no longer matches the legalized params; the fix belongs at that layout's producer, not in `isParameterLocationUsed`.

**`getElementVarLayout()` and buffer kinds.** Non-null only for a `ParameterGroupTypeLayout`: `ConstantBuffer`/`TextureBuffer`/`ParameterBlock` derive from `UniformParameterGroupType : ParameterGroupType` (`slang-ast-type.h`); `GLSLShaderStorageBufferType : PointerLikeType` is a sibling → null, so null-check. Test trap: HLSL `(RW)StructuredBuffer<T>` reflects as `Kind::Resource`; only `GLSLShaderStorageBuffer<T, Std430DataLayout>` gives `Kind::ShaderStorageBuffer`. PR #12715's `reflection::Cursor::navigateToContent()` crashed dereferencing that null for SSBO ([getElementVarLayout is null for non-ParameterGroup buffers](../learnings/1787658477648-slang-reflection-getelementvarlayout-is-null-for-n.md)).

**Binding type and access come from the TYPE only, so a GLSL `readonly` buffer reflects as writable (#13972).** `_calcResourceBindingType` (`slang-reflection-api.cpp` ~:1921) and `spReflectionType_GetResourceAccess` (~:955) read the type, while `readonly`/`writeonly` lives only on the VarDecl (`MemoryQualifierSetModifier` → `IRMemoryQualifierSetDecoration`). Every GLSL `buffer` block therefore reflects as MUTABLE_RAW_BUFFER / READ_WRITE on every target, and `SlangModifierID` has no readonly value. A decl-aware fix is reachable (the binding-range path carries the `VarLayout`, `BindingRangePathLink::var`), but effective access is target-dependent: on non-Khronos targets `lowerGLSLShaderStorageBufferObjectsToStructuredBuffers` makes every SSBO a `RWStructuredBuffer`, so on D3D a readonly SSBO really is a UAV, and one global read-only answer would break D3D12 hosts (slang-rhi D3D12 maps RawBuffer→SRV, MutableRawBuffer→UAV). The consumer that breaks is slang-rhi's wgpu backend: it builds explicit bind group layouts from `getDescriptorSetDescriptorRangeType` (`wgpu-shader-object-layout.cpp` ~:279-286, MutableRaw→Storage) and ORs VERTEX into visibility, so a mutable-reflected buffer in a vertex shader gives `storage`+VERTEX, which WebGPU rejects. The JSON and slang-reflection-test print no SSBO access, so probe with a C++ program (`slang_createGlobalSession2`, `enableGLSL=true`) ([GLSL readonly SSBO reflection is type-only](../learnings/1793207233447-glsl-readonly-ssbo-reflection-is-type-only-slang-r.md)).

**`findFieldIndexByName`.** Returns the first match, so a second same-named global from another module is unreachable by bare name; its `matchName` already handles `Module.var`/`Module::var` (last segment vs name, qualifiers via `getParentDecl`), and both are reachable via `getFieldCount`/`getFieldByIndex` ([findFieldIndexByName already supports qualified module.var](../learnings/1782456046812-slang-reflection-findfieldindexbyname-already-supp.md)).

**Specialization constants on uniform-layout targets (slang-rhi#943).** On HLSL/CPU/CUDA a `[SpecializationConstant]` / `[vk::constant_id]` global is an ordinary uniform: category `Uniform` (8), not `SpecializationConstant` (10), and no `SlangModifierID` marks it. `VariableReflection::findAttributeByName(globalSession, "SpecializationConstant")` and `findAttributeByName(gs, "vk_constant_id")` find it on every target; the parser renames `vk::constant_id` to `vk_constant_id`, so `"vk::constant_id"` returns null. `getDefaultValueBlob` returns target-independent bytes: `bool` gives 4 though the CPU/CUDA layout size is 1, a non-literal initializer (`const int k = 3 * 4 + 1;`) gives no blob, and int/uint/float/half/double match the layout size. slang-rhi has no API to set specialization-constant values on any backend; on Vulkan/WGPU `ShaderCursor["k"].setData()` returns SLANG_OK and does nothing, because `ShaderObject::setData` clamps the write to `m_data`'s size (`src/shader-object.cpp:84-96`). Testing in slang-rhi: tests skip the CPU device on Linux (`tests/testing.cpp:900-904`; disable that `#if`), use `-select-devices=cpu,cuda,vulkan` (`-check-devices` >4 min), and configure with `-DSLANG_RHI_BUILD_TESTS_WITH_GLFW=OFF -DSLANG_RHI_BUILD_EXAMPLES=OFF` without Xinerama headers ([spec constants on uniform-layout targets: reflection facts + slang-rhi harness](../learnings/1792933241509-slang-spec-constants-on-uniform-layout-targets-d3d.md)).

## The C-API surface and adding accessors

`include/slang-deprecated.h` is NOT purely deprecated: PR #5301 (2024-10) moved the whole `sp*` C interface out of `slang.h` and included it just before the `namespace slang` wrapper block. Its `spReflection*` family (~168 functions) and `spGetReflection` back the C++ wrappers; only the `ICompileRequest` workflow (`spCreateSession`, `spCompile`, …) is legacy ([slang-deprecated.h holds the ACTIVE reflection C-API](../learnings/1782754805883-slang-include-slang-deprecated-h-holds-the-active-.md)).

**Adding an accessor (`getContentVarLayout`, #12776).** All structured-buffer layout creation funnels through `createStructuredBufferTypeLayout` (`slang-type-layout.cpp:4402`), so attaching a stored per-SB layout there gives stable pointer identity. SBs have no array layer (`GetElementTypeLayout` returns `T`, `GetElementStride` 0); a content array view is an `ArrayTypeLayout` over `getArrayType(elementType, nullptr)` with stride from the element's own `rules->GetArrayLayout(...).elementStride`, reporting `Kind::Array`. `spReflectionTypeLayout_*` are free `SLANG_API` functions with opaque-handle wrappers, so a new accessor is append-only (prototype in `slang-deprecated.h`, wrapper in `slang.h`), non-breaking. Test via a C++ `slang-unit-test` (model: `unit-test-atomic-reflection.cpp`, `loadModuleFromSourceString` + `getLayout`, no GPU), not `//TEST:REFLECTION`: the JSON emitter prints only named accessors, and adding one churns ~180 `.expected` baselines and is an output-format decision. When a maintainer must sign off on the name, a draft PR with build-verified code and a semantics-pinning test is the artifact ([getContentVarLayout: producer-side content layout (#12776)](../learnings/1787777108008-reflection-getcontentvarlayout-producer-side-conte.md)).

**Changing what an accessor returns (PR #13535).** `TypeReflection::getElementCount()` for an unsized `T[]` changed from 0 to `SLANG_UNBOUNDED_SIZE`, as `slang.h` always documented — on paper a doc-conformance fix. Downstream uses 0 as a marker: slangpy's `is_generic(){ return num_elements()==0; }` (`src/sgl/refl/type.h:231`), `any_generic_dims` (`type.cpp:625`), `slangpy/builtin/array.py:85` and `tensorcommon.py:285` treat 0 as "generic/unsized" and store `int(element_count())`, so `float[] a` now reads -1; slang-rhi Metal's `collectPointerFields` (`metal-shader-object-layout.cpp:22`) does `if(count==0) return; for(i<count)`, an effectively infinite loop. When a reflection value changes, grep slangpy and slang-rhi for the old value as a sentinel (`== 0`, `> 0`, `narrow_cast`, uint32 casts), not only the accessor, and label `pr: breaking change`. `CI SlangPy Trigger Test` is SKIPPED on bot-authored PRs; dispatch it (`workflow_dispatch pr_number=N`). Show the change with a C++ probe against `libslang-compiler.so` on master and the PR (`findFunctionByName(...)->getParameterByIndex(0)->getType()->getElementCount()`) ([reflection return-value fixes matching slang.h can still be breaking](../learnings/1791504997222-reflection-return-value-fixes-that-match-slang-h-d.md)).
