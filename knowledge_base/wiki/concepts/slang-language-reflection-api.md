# Slang Reflection API

Slang exposes a C reflection API (`spReflection*`) and C++ wrappers (`TypeReflection`, `ProgramLayout`, `DeclReflection`, …) for querying layout, bindings, and type structure of compiled shaders. This page holds the non-obvious identity, layout, serialization, and ABI constraints.

## TL;DR

- **`TypeReflection*` pointer identity is not safe across `ProgramLayout` vs module reflection** (different `ASTBuilder`s). Key on `getFullName()`.
- **Reflection objects are live session pointers — not serializable.** Use `-reflection-json` → POD structs, or serialize the module and reflect at runtime.
- **`import` (vs `#include`) loses reflection/bindings until `IComponentType::link()`** — imported globals are requirements folded in only by `link()`; `slangc` always links, so the CLI never reproduces it.
- **The CLI flag is `-reflection-json`** (not `-emit-reflection-json`). With `-target` it SIGSEGVs on EVERY failed compile (no compile-result gate since 2025-07; not a regression; P2). Dropping `-target` yields E52009.
- **`//TEST:REFLECTION:` drives `slang-reflection-test`, not `slangc -reflection-json`, and runs `-no-codegen`.** Test a CLI bug with `SIMPLE`/`DIAGNOSTIC_TEST:SIMPLE`; test a layout change against emitted SPIR-V.
- **`-reflection-json` drops the implicit `$Globals` CB binding** (flat `getParameterByIndex`, #12307). Output-shape changes are a maintainer design call → PARK.
- **`-reflection-json` dedups a pointee's layout by `TypeReflection*`**, which breaks once a pointee's layout is context-dependent (#13190); the same guard stops self-referential-struct recursion, so a re-key needs recursion coverage.
- **Cache-key widening:** if a change makes a memoized per-type/per-string value depend on new state X, every cache of that value must key on X — in the SAME PR (`m_types`/`m_decls` + language version, #13020; JSON dedup + layout marker).
- **Layout has TWO independent engines** — AST (`slang-type-layout.cpp`, feeds reflection) and IR (`slang-ir-layout.cpp`, feeds emitted SPIR-V), sharing no code. A layout change must touch both; verify with `spirv-asm` `Offset`/`ArrayStride` greps, measured separately from reflection.
- **IR-layout-internal bugs are invisible to reflection tests** — pin with `-dump-ir` FileCheck + a revert drill.
- **Existential (`StructuredBuffer<Interface>`) size diverges by phase order:** reflection reads the AST `[anyValueSize]` (default 16+16=32), emit reads the later `inferAnyValueSizeWhereNecessary` pass. A large-enough explicit `[anyValueSize(N)]` makes both agree; root fix is design-gated → PARK.
- **Offsets are relative to the immediate parent scope by design; cumulative offset is a property of an ACCESS PATH**, not a node — a public helper is an ABI design call → PARK.
- **Entry-point uniform offsets are scope-relative**; `isParameterLocationUsed` needs the absolute (+ `EntryPointReflection::getVarLayout()->getOffset`). Combined multi-entry-point emit DOES accumulate binding indices (#13203, real bug).
- **`"used"` = presence in final IR after DCE, not per-access liveness** — a resource-only `ParameterBlock` is legalized away, so its `subElementRegisterSpace` misreports `used:0` (#12349).
- **`getElementVarLayout()` is non-null ONLY for `ParameterGroupTypeLayout`** (CB/PB/TextureBuffer); `GLSLShaderStorageBuffer` is a pointer-like sibling (null); HLSL `StructuredBuffer` reflects as `Kind::Resource`.
- **`findFieldIndexByName` returns the first match** but already supports qualified `Module.var`/`Module::var`; all duplicates are reachable by index.
- **`include/slang-deprecated.h` holds the ACTIVE `spReflection*` C-API** (~168 functions) behind the C++ wrappers; only its `ICompileRequest` workflow is legacy.
- **A new `spReflectionTypeLayout_*` accessor is append-only C-ABI** (free functions, no vtable), but it won't appear in `-reflection-json` without editing the emitter — pin it with a `slang-unit-test`; a draft PR is the artifact while the API name awaits sign-off.
- **Changing a reflection return value is potentially breaking even when it matches the `slang.h` docs** — grep slangpy and slang-rhi for the OLD value used as a sentinel (`== 0`, `> 0`, narrowing casts), not just for the accessor, and label `pr: breaking change`. `CI SlangPy Trigger Test` is skipped on bot-authored PRs; dispatch it manually.

## Identity, lifetime, and linking of reflection objects

`slang::TypeReflection*` is an internal `Type*` deduplicated only within one `ASTBuilder`. A module's `getModuleReflection()` decl tree and the linked program's `getLayout()->findTypeByName()` can be backed by different builders (linking and generic specialization build fresh nodes), so one logical type may have two pointers — compare by `getFullName()` ([TypeReflection* pointer identity is not safe across ProgramLayout vs module reflection](../learnings/1780993688372-slang-reflection-typereflection-pointer-identity-i.md)).

Reflection objects point into live session memory. The two supported persistence strategies: (1) `-reflection-json` (programmatic: `spReflection_ToJson(SlangReflection*, SlangCompileRequest*, ISlangBlob**)`) parsed into custom POD structs; (2) serialize the compiled module and reflect it at runtime in a live session ([Serializing Slang reflection: -reflection-json or a loaded module](../learnings/1782323528074-serializing-slang-reflection-use-reflection-json-o.md)).

A global with `[[vk::binding(n,set)]]` reflects via `#include` but returns nothing via `import` when the host calls `getLayout()`/`getEntryPointCode()` on a composite without `IComponentType::link()`: imported module globals are *requirements*, and `fillRequirements` runs only from `ComponentType::link()` ([import-vs-include reflection/binding loss = missing link()](../learnings/1782215579233-import-vs-include-reflection-binding-loss-missing-.md)).

## `-reflection-json`: crash, test directive, and output-shape gaps

**Crash on failed compile (#11683).** On a front-end error `EndToEndCompileRequest::executeActionsInner` returns early (`slang-end-to-end-request.cpp:188`), leaving `m_specializedGlobalAndEntryPointsComponentType` null, but the emission block in `compile()` (`:1845-1865`) runs without checking the result. It SIGSEGVs (exit 139) on every error class (E20001, E30015, E30019, …), every target, and both file and stdout output; the trigger is exactly (failed compile) AND (`-target`) — without `-target` the `if(!reflection)` guard yields `E52009`. The block dates from 2025-07-24 (#7890) and never had a gate, so it is not a regression, and since it fires only after the correct diagnostic it is P2, not P0. It was localized without a debugger by three CLI discriminators (repro; drop `-target`; valid shader + `-target`) ([Localizing the -reflection-json crash (#11683) + REFLECTION directive](../learnings/1782146682704-localizing-slangc-reflection-json-crash-on-failed-.md), [#11683 crash is broad scope and NOT a regression](../learnings/1782203064448-slang-11683-reflection-json-crash-is-broad-scope-a.md)).

**Test directive.** `tests/reflection/*.slang` `//TEST:REFLECTION:` drives `tools/slang-reflection-test/`, NOT the `slangc -reflection-json` path — a regression test for a CLI bug must invoke slangc via `SIMPLE`/`DIAGNOSTIC_TEST:SIMPLE` ([Localizing the -reflection-json crash (#11683) + REFLECTION directive](../learnings/1782146682704-localizing-slangc-reflection-json-crash-on-failed-.md)).

**Dropped `$Globals` scope (#12307).** `emitReflectionJSON`/`emitReflectionEntryPointJSON` iterate the flat `getParameterByIndex()` lists and never call `getGlobalParamsVarLayout()` / `EntryPointReflection::getVarLayout()`, so loose uniforms print as bare `{"kind":"uniform","offset":0}` with no containing buffer, and the CB's slot 0 appears as an unexplained hole. The container+element emitter (`emitReflectionParameterGroupTypeLayoutInfoJSON`) already exists but fires only when a *parameter's type* is a CB/PB; the clean reference is `examples/reflection-api/main.cpp`'s `printScope`, applied uniformly to the global scope and each entry point. An output-shape proposal with open trade-offs PARKs for a maintainer, not a guessed-shape PR. DeepWiki claimed the JSON "includes" the CB binding — conflating API capability with JSON output; confirm "does the JSON emit Y" against source ([JSON reflection drops the $Globals CB scope binding (#12307)](../learnings/1785536267099-slang-json-reflection-drops-the-globals-cb-scope-b.md)).

**Pointee layout dedup (#13189/#13190).** `ReflectionTracker` (`slang-reflection-json.cpp:63-74`; pointer case `:912-931`) is an add-only visited set keyed on `TypeReflection*`; after the first expansion it emits only the bare type name. Once #13189 made the pointee honor the pointer's data-layout marker, sibling `Ptr<Vertex,…,ScalarDataLayout>` and `Ptr<Vertex,…,Std430DataLayout>` collapse onto the first layout — JSON-only; the C++ API returns two distinct `getElementTypeLayout()`. Re-keying on `TypeLayoutReflection*` is the direction, but the by-type guard also terminates recursion on `struct Node { Ptr<Node> next; }`, so it is its own PR with self-referential coverage ([reflection-JSON dedups pointee layout by type, not type-layout](../learnings/1789944879524-reflection-json-dedups-pointee-layout-by-type-not-.md)). An initial "sibling `layoutMap` collision" hypothesis was WRONG — each field lays out through a COPIED `fieldLayoutContext` — so the divergence lives only in the JSON dedup ([reflection-json dedups pointee layout by TypeReflection*](../learnings/1789943171658-reflection-json-dedups-pointee-layout-by-typerefle.md)).

## Cache-key widening: a new input must join every cache key

**Rule: if a diff makes a previously input-independent memoized value depend on state X, grep for every cache of that value and put X in its key — in the same PR.** Pin with a fail-before/pass-after test that changes only X.

- **JSON dedup and the AST layout cache (#13189).** When a pointee's layout starts depending on the layout marker, audit both the JSON `ReflectionTracker` and the AST `layoutMap` (`Type*`-keyed, rule-blind, `slang-type-layout.h`). The AST cache can NOT key on the `TypeLayoutReflection` it produces (circular); its key must cover all layout-affecting inputs ([reflection-json dedups pointee layout by TypeReflection*](../learnings/1789943171658-reflection-json-dedups-pointee-layout-by-typerefle.md)).
- **Language version in reflection lookup (#13015/#13020).** Fixing the module-less null-`currentModule` crash threaded `m_optionSet.getLanguageVersion()` into `parseTermFromSourceFile`/`parseTermString`, but `ComponentType::m_types` (`getTypeFromString`/`findTypeByName`) and `m_decls` (`findDeclFromString`) key on the string alone and return before consulting the version (`slang-linkable.cpp:832`, key `:860`). A mid-session `-std` change on one linkage is supported and tested (`reflectionRefreshesChangedLanguageVersion`, `unit-test-function-reflection.cpp:328`), so `findTypeByName("(int, float)")` returns a stale `float` (comma expr) after `-std 2026` (tuple → null). Fix: key both on `(string, languageVersion)` via `SLANG_COMPONENTWISE_HASHABLE_2`/`EQUALITY_2`, same version source for get and put. Probe a "version-independent" sibling with a generic argument before excluding it: `findFunctionByName("pick<(int, float)>")` smuggles version-differential grammar into `m_decls`. Test on one linkage via `spProcessCommandLineArguments` (separate reflection objects have separate caches), and don't call the scenario "unusual usage" when an existing test exercises it ([a new dependency in a cached parse/lookup must extend the cache key](../learnings/1789172524588-threading-a-new-dependency-into-a-cached-parse-loo.md)).

## Two independent layout engines (AST reflection vs IR codegen)

Slang computes buffer layout (offsets, sizes, strides, alignment) twice, with no shared code:

1. **AST / program-layout engine** — `slang-type-layout.cpp` (`LayoutRulesImpl`, `EndStructLayout`, `GLSLLayoutRulesFamilyImpl::get*Rules`). Feeds the reflection API, `-reflection-json`, and `//TEST:REFLECTION`. Lowered into reflection `IRTypeLayout` by `_lowerTypeLayoutCommon`, historically carrying only `IRTypeSizeAttr` (PR #11135 adds `IRTypeAlignmentAttr`), read by ~18 `getSizeAttrs` consumers.
2. **IR / codegen engine** — `slang-ir-layout.cpp` + `slang-ir-lower-buffer-element-type.cpp`. Computes size AND alignment on demand from the raw IR type plus an explicit rules object, cached on `IRSizeAndAlignmentDecoration`; SPIR-V `OpMemberDecorate Offset`/`ArrayStride` come from here.

A change made only in engine 1 moves reflection while the emitted SPIR-V is unchanged — a host that lays out its buffer from reflection then corrupts data — and adding an alignment attr to reflection layouts does not change emission ("SPIR-V divines alignment" is wrong) ([Slang has TWO type-alignment systems](../learnings/1785528040007-slang-has-two-type-alignment-systems-reflection-ir.md), [layout has two independent engines — a flag must touch both](../learnings/1789151128965-slang-layout-has-two-independent-engines-reflectio.md)). IR-engine traps: `IRTypeLayoutRuleName::Scalar` is a literal alias of `Natural`, and `NaturalLayoutRules::alignCompositeElement` does not round aggregate size up to alignment, so a real scalar-layout change needs a distinct IR rule threaded through `getTypeLayoutRuleNameForBuffer`, `IRTypeLayoutRules::get()`, `getOpFromTypeLayoutRuleName` (`slang-ir-layout.cpp:1063`) and the `==Natural` special cases; `-emit-spirv-via-glsl` computes no offsets (defers to glslang via `layout(scalar)`), so padding there means synthesized members ([layout has two independent engines — a flag must touch both](../learnings/1789151128965-slang-layout-has-two-independent-engines-reflectio.md)).

**Verify per target, measuring both sides.** `RWStructuredBuffer<{int2;float4}, ScalarDataLayout>` emitted `ArrayStride 24` while `-reflection-json` reported 32. Check `slangc -target spirv-asm … | grep -E 'MemberDecorate.*Offset|ArrayStride'` (flag on vs off), not a REFLECTION test. A `--target slangc`-only build cannot emit SPIR-V (the `slang-glslang`/`spirv-opt` libs come only from a full build), and peer sessions reset the shared checkout mid-task — pin the commit with `git worktree add` ([Verifying per-target buffer layout: measure emitted AND reflection](../learnings/1782325331597-verifying-slang-per-target-buffer-layout-measure-e.md)).

**Testing IR-layout internals.** The reflection API and JSON read the AST `TypeLayout`, so an IR-layout representation bug (attr operand ordering, `getSizeAttrs()` contiguity) passes any REFLECTION test under good and buggy binaries alike. Pin it with `//TEST:SIMPLE(filecheck=...):-dump-ir` — `-dump-ir` prints reflection layout attrs (`size(8 : Int, 32 : Int)`, `structTypeLayout(...)`) — using ID-agnostic FileCheck variable capture with CHECK-DAG on the attr-def lines, and run the revert drill to see it go RED ([reflection API/JSON is AST-based — cannot test IR-layout bugs](../learnings/1785539323116-slang-reflection-api-json-is-ast-based-cannot-test.md), [Slang has TWO type-alignment systems](../learnings/1785528040007-slang-has-two-type-alignment-systems-reflection-ir.md)).

**Existential size (#12092).** For `StructuredBuffer<Interface>` with no `[anyValueSize(N)]`, reflection and emit disagree by phase order. Reflection is AST-side: `_createTypeLayout` (`slang-type-layout.cpp:5982`) defaults `fixedExistentialValueSize = 16`, overrides it only from `AnyValueSizeAttribute`, and adds a 16-byte RTTI/witness header → 32 via `spReflectionTypeLayout_GetSize`. Emit uses `inferAnyValueSizeWhereNecessary` (`slang-ir-any-value-inference.cpp`, scheduled at `slang-emit.cpp:1500`, after reflection): max natural size over conformers + header → a `float4x4` conformer gives ArrayStride 80. A large-enough explicit `[anyValueSize(N)]` makes both agree (the user workaround); too-small already diagnoses `TypeDoesNotFitAnyValueSize`. Reproduce with `spirv-asm | grep ArrayStride` vs the C++ `getSize()` — `-reflection-json` does not surface existential size. Whether reflection should track the inferred size or 16 is a deliberate ABI default is a maintainer call → PARK ([existential size 32 vs emitted ArrayStride 80 (#12092)](../learnings/1784022520457-slang-reflection-existential-size-32-vs-emitted-ar.md)).

## Offsets, bindings, and usage

**Relative offsets; cumulative offset is a path property (#12183).** `getOffset(category)`/`getBindingSpace(category)` are relative to the immediate parent scope by design, and containers hide/transform layout units. The cumulative-offset logic exists only in the reflection-api example (zero hits in `source/`/`include/`). The same `VariableLayoutReflection` (a struct reused in two places) has different cumulative offsets per context, so `varLayout->getCumulativeOffset()` cannot work — the example threads an `AccessPath` with `deepestConstantBuffer`/`deepestParameterBlock`. Wrappers are thin opaque handles (not COM), so appending is ABI-safe, but how the caller supplies the path is a public-API design call → PARK, don't PR. Triage rule for "promote helper X from the example": grep source/include for the gap, and check whether X needs context the node doesn't carry ([cumulative offset is a path property, not a node property (#12183)](../learnings/1784676089970-reflection-cumulative-offset-is-a-path-property-no.md)).

**Entry-point scopes (#13203).** `collectEntryPointParameters` builds a fresh `SimpleScopeLayoutBuilder` per entry point (`slang-parameter-binding.cpp:3358/3482`), so leaf offsets are relative to that entry point and two entry points can report the same values. `spIsParameterLocationUsed` (`slang-reflection-api.cpp:5138`) takes the ABSOLUTE location = leaf + every enclosing scope, including `EntryPointReflection::getVarLayout()->getOffset(category)` (the `calculateCumulativeOffset` recipe); EP1's scope offset is 0 (masks the bug), EP2's is not. Prefer category-qualified `getOffset(category)` over `getBindingIndex()`. **Correction to an earlier "no bloat" reading:** a single `slangc` run over multiple entry points DOES accumulate absolute bindings in emitted code (SPIR-V EP2 → 3/4/5; HLSL → b1/t1/u1), O(N·k) vs an expected O(k); only per-entry-point separate emit resets. Verify on the whole file with no `-entry`; treat it as a real bug whose reset policy is design-gated ([CORRECTION: multi-entry-point binding bloat IS real (#13203)](../learnings/1790016065362-correction-entry-point-uniform-binding-bloat-acros.md)).

**`"used"` is presence in final IR (#12349).** The JSON emits `used` only in the entry-point `bindings` array, via `spIsParameterLocationUsed` → `getUsedBindingRanges().containsBinding(...)`, built by `collectMetadata` (`slang-ir-metadata.cpp`) which runs LAST, after DCE. A `ParameterBlock`'s `SubElementRegisterSpace` is recorded only in the container-var-layout branch, which needs a surviving `IRGlobalParam` with an `IRParameterGroupTypeLayout`; a resource-only block is legalized into top-level globals, so the space reports `used:0` even though its resource is used and its own `DescriptorTableSlot` is recorded. Discriminator: adding one uniform field (`uint bias`) keeps the block and flips it to `used:1`. A metadata gap, not container semantics; there is no per-field `used` ([used:0 on a ParameterBlock subElementRegisterSpace is a metadata gap](../learnings/1786583259247-reflection-used-0-on-a-parameterblock-subelementre.md)).

**`getElementVarLayout()` and buffer kinds.** Non-null only for a `ParameterGroupTypeLayout`: `ConstantBuffer`/`TextureBuffer`/`ParameterBlock` derive from `UniformParameterGroupType : ParameterGroupType` (`slang-ast-type.h`); `GLSLShaderStorageBufferType : PointerLikeType` is a sibling → null, so null-check. Test trap: HLSL `(RW)StructuredBuffer<T>` reflects as `Kind::Resource`; only `GLSLShaderStorageBuffer<T, Std430DataLayout>` gives `Kind::ShaderStorageBuffer`, so SSBO paths need the GLSL type. PR #12715's `reflection::Cursor::navigateToContent()` crashed dereferencing that null for SSBO ([getElementVarLayout is null for non-ParameterGroup buffers](../learnings/1787658477648-slang-reflection-getelementvarlayout-is-null-for-n.md)).

**`findFieldIndexByName`.** Returns the first match, so a second same-named global from another module is unreachable by bare name; its `matchName` already handles `Module.var`/`Module::var` (last segment vs name, qualifiers via `getParentDecl`), and both are reachable via `getFieldCount`/`getFieldByIndex` ([findFieldIndexByName already supports qualified module.var](../learnings/1782456046812-slang-reflection-findfieldindexbyname-already-supp.md)).

## The C-API surface and adding accessors

`include/slang-deprecated.h` is NOT purely deprecated: PR #5301 (2024-10) moved the whole `sp*` C interface out of `slang.h` and included it just before the `namespace slang` wrapper block. Its `spReflection*` family (~168 functions) and `spGetReflection` are the active backing for the C++ wrappers; only the `ICompileRequest` workflow (`spCreateSession`, `spCompile`, …) is legacy ([slang-deprecated.h holds the ACTIVE reflection C-API](../learnings/1782754805883-slang-include-slang-deprecated-h-holds-the-active-.md)).

**Adding an accessor (`getContentVarLayout`, #12776).** All structured-buffer layout creation funnels through `createStructuredBufferTypeLayout` (`slang-type-layout.cpp:4402`), so attaching a stored per-SB layout there once gives stable pointer identity (`counterVarLayout` is the precedent). SBs have no array layer (`GetElementTypeLayout` returns `T`, `GetElementStride` returns 0); a content array view is an `ArrayTypeLayout` over `getArrayType(elementType, nullptr)` (unbounded) with stride from the element's own `rules->GetArrayLayout(...).elementStride` — principled, not hand-rolled — and reports `Kind::Array`. `spReflectionTypeLayout_*` are free `SLANG_API` functions with opaque-handle wrappers, so a new accessor is append-only (prototype in `slang-deprecated.h`, wrapper in `slang.h`), non-breaking. Test via a C++ `slang-unit-test` (model: `unit-test-atomic-reflection.cpp`, `loadModuleFromSourceString` + `getLayout`, no GPU), not `//TEST:REFLECTION`: the JSON emitter prints only named accessors, and adding one there churns ~180 `.expected` baselines and is itself an output-format decision. When a maintainer must sign off on the API name first, a draft PR with build-verified code and a semantics-pinning test is the right artifact ([getContentVarLayout: producer-side content layout (#12776)](../learnings/1787777108008-reflection-getcontentvarlayout-producer-side-conte.md)).

**Changing what an accessor returns (PR #13535).** `TypeReflection::getElementCount()` for an unsized `T[]` changed from 0 to `SLANG_UNBOUNDED_SIZE`, which is what `slang.h` always documented, so on paper it was a doc-conformance fix. Downstream consumers use 0 as a marker, though. slangpy's `is_generic(){ return num_elements()==0; }` (`src/sgl/refl/type.h:231`), `any_generic_dims` (`type.cpp:625`), `slangpy/builtin/array.py:85` and `tensorcommon.py:285` treat 0 as "generic/unsized dimension" and store `int(element_count())`, so a function parameter like `float[] a` now reads -1. slang-rhi Metal's `collectPointerFields` (`metal-shader-object-layout.cpp:22`) does `if(count==0) return; for(i<count)`, which becomes an effectively infinite loop. When a reflection value changes, grep slangpy and slang-rhi for the old value used as a sentinel (`== 0`, `> 0`, `narrow_cast`, uint32 casts), not only for the accessor, and label the PR `pr: breaking change`. `CI SlangPy Trigger Test` is SKIPPED on bot-authored PRs, so dispatch it manually (`workflow_dispatch pr_number=N`). The fastest way to show the value change is a small C++ probe linked against `build/Release/lib/libslang-compiler.so`, run on master and on the PR: `m->getLayout()->findFunctionByName(...)->getParameterByIndex(0)->getType()->getElementCount()` ([reflection return-value fixes matching slang.h can still be breaking](../learnings/1791504997222-reflection-return-value-fixes-that-match-slang-h-d.md)).
