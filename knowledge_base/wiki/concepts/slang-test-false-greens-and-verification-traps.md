# slang-test False Greens and Verification Discipline

Running slang-test is one thing; **trusting its result** is another. This page covers the ways a green run can carry zero information (test-server false greens, stale binaries, vacuous DIAGNOSTIC and FileCheck tests, SPIR-V lanes that never validate) and the discipline (positive and negative controls, discriminating tests, load-bearing counts) that keeps a PASS meaningful. Harness internals (`-v` verbosity plumbing, replay-folder collisions under parallel test-servers, unit-testing harness and compiler internals) live on [slang-test Harness Internals and In-Process Unit Tests](slang-test-harness-internals-and-unit-tests.md).

## TL;DR

- **Run `slang-test` from the repo root** (`-use-test-server -server-count 8`; `slang-test tests/x.slang`; `slang-test slang-unit-test-tool/`). **Never use `$?` as pass/fail** (exit 0 was seen on a FAILED test); parse `FAILED test:` / `% of tests passed`.
- **Before PR #11753 a unit test that crashed the test server was reported PASSED**, so a test that "starts failing after #11753" is crashing the server. **The retry path also reported failures as passes (#11911)**: a green merge-queue or per-PR gate does not certify C++ unit-test health.
- **Device caching defeats per-invocation debug-callback bridges** (false greens). A GPU-free test of real RHI device code uses a real CPU-backend device in a `gfx-unit-test` `SLANG_UNIT_TEST`.
- **An in-container `slang-test` startup crash is not a compiler failure** if direct `slangc` works. Suspect RPC timeout or workload sizing before redesigning concurrency for a flaky test.
- **`-wgpu` rows DO run on the L40S in a build tree configured FRESH with `-DSLANG_EXCLUDE_DAWN=OFF`** (plus `XDG_RUNTIME_DIR=/tmp`). The default preset reports them `ignored`; a tree configured ON and then flipped to OFF reports `Not Supported`.
- **When a related PR merged after a PR's base, re-run the drills on PR head + `origin/master`.** The merge can leave another PR's regression test green with its fix reverted.
- **Prove the relink: require `test_binary_mtime > build_start`.** A build exiting 0 can rebuild nothing, and a stale binary passes. Ask: would this be green if my change were not compiled in?
- **Re-run pass-counts and subagent reproducers yourself; grep IR by TYPE** (`kIROp_PseudoPtr`), never by a substring that can match a mangled name. A subagent's capability claim read off a mechanism one layer below is the tell; run the tool.
- **Negative-control every branch-coverage claim**: neuter the branch, rebuild, re-run; still green means drop the test.
- **One positive control per HAZARD, not per fix**: sabotage the specific new guard (`if (owned)` → `if (true)`) and give the test something to trip on.
- **Count assertion-bearing tests, not files, and name the discriminating one.** If the fallback path gives the fix's answer in your configuration, the test cannot tell fixed from broken.
- **Probe each branch of a new pass at each parent kind** (function, global init, module-scope `static const`) via a whole-value use; a lowering moved later needs a `-target glsl` value run.
- **Bound a shared-resolver change by byte-comparing head vs master `slangc` over every SPIR-V test** (normalize `-g2` worktree paths) and logging every input where old and new logic disagree.
- **A worktree-cleanliness-guard trip can be a crashed test**: grep the same run's log for `FAILED test:` first.
- **`diag=CHECK` is not FileCheck**: only `//CHECK:` is parsed (`CHECK-NOT`/`CHECK-DAG` are silently dropped), matching is exhaustive by default and by substring, and one diagnostic is often two rows. Break one annotation to prove the test live.
- **`//CHECK:` is 8 chars**, so single-line carets start at column 9; a separate `// ^^^` line checks nothing; use `/*CHECK: … */` for low columns. Match by error CODE.
- **Drill every new diagnostic test per ROW on master**: a row master already rejects the same way pins nothing, and a revert drill that stays green means that leg is untested.
- **`diag=CHECK` catches crash→diagnostic via empty stderr only if crash and diagnostic are mutually exclusive**; otherwise add a `SIMPLE` `result code = N` test. Positive-compilation cases go in a separate file.
- **SIMPLE lanes never run spirv-val, and failed modules still disassemble with `internal error 99999:`**, so `CHECK-NOT: error:` / `X-NOT: VUID` are vacuous. Assert the buggy artifact is absent or pin emitted ops; run against the pre-fix binary.
- **slang-test injects `-O0` unless told otherwise** (pass `-O1`) and reports compile-only SPIR-V tests IGNORED without Vulkan; verify with `slangc` + `SLANG_RUN_SPIRV_VALIDATION=1`, and check the validator's version.
- **Backend-codegen compile time is measurable** (`-report-perf-benchmark` + `tools/compile-perf`). Quote the `.mailmap`-mapped name `git blame` shows.

## Harness False Greens: Test-Server Crashes and Retries

Before PR #11753 a unit test that crashed the test server was reported **PASSED**: an RPC or connection death leaves `ExecuteResult` at its default `resultCode=0`, which maps to Pass ([crash reported PASSED (#11751)](../learnings/1782398466162-slang-test-false-green-a-unit-test-that-crashes-th.md)). PR #11753 records RPC failures as Fail and changes only reporting, so a test that "starts failing after #11753" is crashing the server ([#11753: 'fails after the fix' ⇒ crash](../learnings/1782397269166-slang-test-rpc-failure-reporting-11753-fails-after.md)).

The unit-test retry path in test-server mode also reports failed tests as passing (#11911) ([retry false-green (#11911)](../learnings/1783009679066-slang-test-test-server-retry-false-green-11911-gh-.md)). We verify these fixes behaviorally, not by reading code, because the Defect-A registry-drain repro is platform-dependent ([verify behaviorally](../learnings/1783013967417-slang-test-harness-false-green-fixes-verify-behavi.md)). That applies to the reporting flow only; struct-driven harness internals can carry a `slang-unit-test` ([Harness Internals](slang-test-harness-internals-and-unit-tests.md)). So a green merge-queue or per-PR gate does **not** guarantee C++ unit-test health until the #11911 fixes land (fix PR #11913 open as of 07-05) ([merge-queue green ≠ unit-test health](../learnings/1783239972308-slang-merge-queue-green-c-unit-test-health-test-se.md)).

## Environment Traps: Startup Crash, Device Cache, GPU-Free Devices, Flaky Workloads

`slang-test` can crash at startup in-container while direct `slangc` runs fine; that is not a compiler failure. Beware also a codex "revert-without-rebuild" false positive, where the old binary is still on disk ([startup crash; revert-without-rebuild](../learnings/1782819445679-slang-verify-gotchas-slang-test-crashes-at-startup.md)). Device caching silently defeats per-invocation debug-callback bridges: a cached device reuses the prior callback wiring, so a per-invocation regression goes green (regression from PR #11785) ([device caching false greens](../learnings/1782862613084-device-caching-silently-defeats-per-invocation-deb.md)). For a GPU-free regression test that must exercise **real** RHI device code rather than a mock, create a real CPU-backend device inside a `gfx-unit-test` `SLANG_UNIT_TEST` ([real CPU device in gfx-unit-test](../learnings/1782871389928-gpu-free-render-test-regression-via-a-real-cpu-dev.md)).

Issue #11759 (flaky `parallelGenericEntryPointCompile`) was over-diagnosed as a deep concurrency race; the maintainer's fix, PR #11761, was a 4-line workload reduction. Suspect RPC timeout and workload sizing first ([postmortem #11759/#11761](../learnings/1782519024579-postmortem-slang-11759-superseded-by-pr-11761-stre.md)).

**`-wgpu` rows run locally only in a tree configured fresh with Dawn.** In a default-preset build (`SLANG_EXCLUDE_DAWN=ON`) every `-wgpu` row reads `ignored`. A fresh build tree configured with `cmake --preset default -DSLANG_EXCLUDE_DAWN=OFF`, run with `XDG_RUNTIME_DIR=/tmp`, prints `Check wgpu,webgpu: Supported` on the L40S container and gives real Tint + GPU runs of the rows. A tree first configured with Dawn excluded and then reconfigured to OFF still reports `Not Supported`. That stale-cache state is the source of an earlier note (2026-10-23) that local wgpu rows never run and must be proxied through dawn.node; it is corrected. For a WGSL PR, configure a fresh worktree with Dawn ON. Other runtime needs of a local Dawn run are on [WGSL on-GPU execution](slang-backends-wgsl-on-gpu-execution.md) ([correction: -wgpu rows DO run on a fresh Dawn-ON configure](../learnings/1792790967029-correction-slang-test-wgpu-rows-do-run-locally-on-.md)).

## Stale Binaries and Per-Hazard Positive Controls

**A stale test binary can pass the very test you are validating.** Capture a timestamp before the build and require `test_binary_mtime > build_start`; refuse to report numbers otherwise, because a build can exit 0 having rebuilt nothing. On slangpy#1073 a 10-day-old `sgl_tests` binary still passed the cross-thread profiler test meant to validate a concurrency fix; the build subagent caught the mtime. The stale result is plausible (same test name, same numbers), so for a nondeterministic timing fix you have zero signal while believing you have positive signal. The test *if my change had not been compiled in, would this still be green?* applies to every derived artifact you measure: binaries, generated docs, emitted assembly, lockfiles ([stale binary passes](../learnings/1785772374507-a-stale-test-binary-can-pass-the-very-test-you-re-.md)).

**One positive control per HAZARD, not per fix.** Also on slangpy#1073, the fix for a reference leak in `Profiler::end_zone` released on every zone-stack mismatch, so one reference could be released twice; `release_zone_from_global_frame` asserts `count > 0`, so release builds underflow a packed counter and corrupt shared state. Two controls were needed: remove the release stanza (the test still catches the leak) and weaken the new ownership guard to `true` (it catches the double-release), and the test had to be extended to re-present the rejected token so control 2 had something to trip on. Enumerate hazards (leak, double-release, underflow, deadlock, stall), sabotage the specific guard rather than the feature, and watch for a fix that turns failure mode A into B, common in reference counting, ring buffers and completion gates ([one control per hazard](../learnings/1785773520364-one-positive-control-per-hazard-when-a-fix-introdu.md)).

## Reproducer, Coverage and Count Discipline

**Negative-control a branch-coverage claim.** A test meant to cover one branch may pass through another always-present trigger. Neuter the branch (e.g. `continue` instead of `return true`), rebuild and re-run; if it stays green, it does not isolate the branch. On PR #12281 a generic-empty-type test passed with the `IRGeneric` branch of `hasEmptyTypeLegalizationWork` neutered (any named empty struct is hoisted to module scope and fires the struct-root scan anyway), so it was dropped ([negative control](../learnings/1785548777549-verify-a-test-isolates-its-target-branch-with-a-ne.md)).

**Drill on the merge, not only on the base.** When a PR's base predates a related PR that has since merged to master, build a local merge (PR head + `origin/master`) and re-run the drills there. On #13897 the shadow globals that #13897 hoists made #13883's regression test pass even with #13883's fix reverted, so #13883 lost its test pin on master; a fragment-stage row, whose shadow is not hoisted, restores it. When a WGSL change removes a validation error, also probe multi-entry modules compiled without `-entry`: with several entry points (#13687), hoisting a shadow into a by-value/struct context turns a Tint rejection into a silently wrong value, because the second entry point's context is never written and reads 0 ([review against base + master merges; probe multi-entry modules](../learnings/1792790967029-correction-slang-test-wgpu-rows-do-run-locally-on-.md)).

**Re-run a subagent's reproducer and grep IR by TYPE.** A subagent reported a PseudoPtr reproducer it never ran: the source failed in the front end with E41019, and its "PseudoPtr count" came from `grep -i pseudo` matching the mangled function name `test_pseudo_ptr`. Anchor IR-type greps (`= *pseudo_ptr\(`, `kIROp_PseudoPtr`) so they cannot match symbol names ([run the reproducer; grep the TYPE](../learnings/1785548791828-verify-a-subagent-s-reproducer-by-running-it-grep-.md)). Pass counts in a PR body are load-bearing too: a subagent reported `defer/` as 39/39, and a fresh run was 38/38 with 13 dx11 variants ignored ([re-run pass-counts](../learnings/1785349753826-verify-slang-test-suite-pass-counts-from-a-fresh-r.md)). The population is whatever the path arguments match, and slang-test matches them by string prefix, not at directory boundaries: `slang-test tests/autodiff` also runs `tests/autodiff-dstdlib/` (86 of 1165 test lines in one #13976 run, a narrower claim that codex OUTPUT_REVIEW flagged). Before reporting "suite X passed N/N", pass a trailing slash (`tests/autodiff/`) or count what ran with `grep -oE 'tests/[a-z-]+/' <log> | sort | uniq -c` ([slang-test path arguments are prefixes](../learnings/1793207631255-slang-test-path-arguments-are-prefixes-not-directo.md)).

**Probe every branch of a pass at every parent kind, through whole-value uses.** On #13378 R2, `lowerArrayBuiltinCasts` unrolled casts of up to 16 elements and looped otherwise. The loop branch asserted an enclosing block, assuming module-scope casts have literal length, but its condition was `!literal || count > 16`. So `static const row_major float4x4 src[17]; static const float4x4 dst[17] = src;` with `dst` passed to a function hit release assert E99997 on every target, while element reads (`dst[i]`) missed it because a `getElement(cast)` peephole folds the cast away. When a PR moves a lowering past `deferBufferLoad`, build its value test with `-target glsl`, where revived whole-buffer loads emit `copyLogical` and hit E99999 (#13379) ([late-lowered pass: arrays above the unroll limit](../learnings/1790933910032-late-lowered-ir-pass-test-literal-length-arrays-un.md)).

**Count assertion-bearing tests, not files, and name the discriminating one.** "6 tests committed" was 3 assertion-bearing tests plus 3 support inputs (an `__include`d file, an `#include`d helper, a second top-level file); fixtures are inputs, not coverage. Two of the three real tests passed with the feature broken: PR #10907 (for #10906) scoped a SPIR-V `DebugFunction` to its owning `DebugCompilationUnit`, and on a lookup miss emission falls back to a module-global scope pinned to the entry-point CU, so in a single-CU unit the broken fallback coincides with the expected answer. Only the two-CU test discriminates; say so in the PR body and in a test comment so nobody prunes it. Whenever a feature has a fallback, build the case where fallback and fix differ, and confirm each test fails for the reason you intend ([count assertion-bearing tests](../learnings/1785824059809-count-assertion-bearing-tests-not-test-files-and-n.md)).

**A worktree-cleanliness-guard failure can mask a real test failure.** A `slang-test left generated or modified files in the worktree` trip can be the symptom of a test that crashed mid-run. On PR #12182 a leftover `moduleG6276.slang` was first classified as hygiene, but a fresh run showed `optixMultipleDefinition.internal` failing deterministically on linux-debug/release and windows. Grep the same run's test-slang log for `FAILED test:` / `COMPILE ERROR` / crash first ([cleanliness guard masks a failure](../learnings/1785535887677-worktree-cleanliness-guard-can-mask-a-real-test-fa.md)).

## Bounding a Shared-Resolver Change: Byte-Compare Head vs Master

A small edit to a resolver many paths share (PR #13610, `getGlobalParamAddressSpace` in `slang-ir-spirv-legalize.cpp`) cannot be bounded by reading the diff, but it can be measured. Build Release at head and reuse a Release build at the same base as master. Parse every `//TEST:SIMPLE...:` line that targets SPIR-V, run both `slangc` binaries with identical arguments (cwd = head worktree, `-o` into a scratch dir), and compare stdout plus stderr; also compile every Vulkan compute test with `-target spirv-asm -stage compute`, plain and with `-fvk-t-shift 100 0 -fvk-s-shift 200 0 -fvk-u-shift 300 0`. **Normalize worktree paths first**: `-g2` embeds the `-I <bin dir>` `OpString` and source hashes, and 100+ apparent diffs vanished once worktree names were replaced. Separately, log under a `getenv` gate every input where old and new logic disagree, and run the full suite with it set.

On #13610 this found an **undisclosed second fix**: a ParameterBlock in space ≥ 1 under `-fvk-u-shift`/`-fvk-t-shift` threw E99997 on master because the old loop was order-dependent (`[UA, RegisterSpace]` threw, `[RegisterSpace, UA]` did not), with no issue and no test. The other ~226 changed reconciliations were overridden downstream, so output was byte-identical. Cross-check newly accepted output against the `Binding`/`DescriptorSet` decorations from master's `-emit-spirv-via-glsl`, which never ICEd. A new `git worktree add` tree has no submodules; copy `external/` from a worktree at the same base with `tar` (no rsync) ([byte-compare head vs master](../learnings/1791924730900-review-technique-byte-compare-head-vs-master-slang.md)), or run `git -c protocol.file.allow=always submodule update --init --recursive`. A plain update fails because the submodule URLs are local paths, and cmake configure then fails with many `add_subdirectory` errors ([worktree submodule init needs protocol.file.allow](../learnings/1792745836053-diagnostic-test-check-not-is-inert-but-passes-lint.md)).

## DIAGNOSTIC_TEST (`diag=CHECK`) Authoring

**The matcher is not LLVM FileCheck.** `checkAnnotations` in `tools/slang-test/diagnostic-annotation-util.cpp`, driven by `_diagnosticAnnotationTest` in `slang-test-main.cpp`, matches annotations against machine-readable diagnostics (slang-test adds `-enable-machine-readable-diagnostics`: one tab-separated row of code, severity, location, message, no source echo) and runs even where FileCheck is not installed. Only the exact prefix `//CHECK:` is recognized; `//CHECK-NOT:` and `//CHECK-DAG:` are **silently dropped** (they work only under `filecheck=CHECK`), so a `non-exhaustive` test whose only annotations are those passes vacuously. Prove a test live by breaking one annotation and watching it FAIL. Negative guarantees come from **exhaustive matching, the default** (`exhaustive = !isNonExhaustiveDiagTest()`): every emitted row must match and vice versa, so an unexpected `E99997` ICE or a duplicate diagnostic fails "Exhaustive check failed", and to prove a case does not warn you leave it unannotated. Annotations match by substring against message, severity, code or "severity code", each consuming one row. One diagnostic is often two rows (primary + span, deduplicated only when the span text equals the primary), so annotate both facets (`//CHECK: E29000` + `//CHECK: snippet`). No-location diagnostics (Line 0/Col 0) still work if every row is annotated by text in emission order. Add `non-exhaustive` only for a deliberately unannotated secondary diagnostic; the harness rejects an unnecessary one ([CHECK-DAG ignored; non-exhaustive vacuous](../learnings/1789680163713-slang-test-diag-check-check-dag-is-ignored-and-non.md); [exhaustive; ignores CHECK-NOT](../learnings/1789718875570-slang-diag-check-diagnostic-test-is-exhaustive-and.md)). Design corollary from the first atom: when two passes diagnose the same IR shape, hand off at one point (establish the winning diagnostic exactly where you suppress the other), because the passes can differ in reachability.

**Caret columns.** `//CHECK:` is exactly 8 chars, so `//CHECK:^^^ E41000` puts the first caret at column 9, while `//CHECK: ^^^` shifts every caret and fails "Column position(s) don't match". Use the "Suggested annotations you can copy" block slang-test prints on mismatch as ground truth, and match by error CODE (`E41000`), not free text. The same atom's provenance trap: `git blame`/`%aN` render the current name via `.mailmap` (shader-slang maps `Tim Foley` → `Theresa Foley`), so quote the name blame shows, not raw `%an`; find a comment's origin PR with `git log -1 <sha>` or `git log -S '<text>' --reverse` ([caret columns + .mailmap (#12236/#12245)](../learnings/1785230187967-diagnostic-test-caret-alignment-git-blame-mailmap-.md)).

**Two caret forms check nothing or cannot reach.** A `//CHECK:` line followed by `//   ^^^^ message` is not parsed as a check: on PR #13659 a `DIAGNOSTIC_TEST(diag=CHECK,non-exhaustive)` written that way passed on master, where the diagnostic does not exist, and on a head with the cause removed. The single-line form cannot point below column 10. The block form works, carets aligned to the previous non-annotation line:
```
uint loadWithTargetOnly()
/*CHECK:
     ^^^^^^^^^^^^^^^^^^ 'loadWithTargetOnly' uses undeclared capability 'spirv_1_0'
*/
```
Every new diagnostic test must FAIL on master or with the cause removed ([separate caret line checks nothing](../learnings/1792102157772-diagnostic-test-caret-annotations-a-separate-check.md)).

**Drill per row, not per file.** On shader-slang/slang#13718 (local types cannot see enclosing locals), this row passed on head:
```
cbuffer CB { int c; };
struct L { int get() { return c; } };
```
Master gave the same `E30015 undefined identifier 'c'` at the same column, so the row guarded nothing and the fix's breadcrumb leg (`_refersToFunctionCallValue`) was untested: with it disabled all 13 rows stayed green, and `fprintf` instrumentation over all 5,329 files under `tests/` gave it 0 hits. It was reachable only through a lambda, `let f = () => { struct L { int get() { return c; } }; ... }`, where master emits a silent `return _S1;` and the SPIR-V emitter ICEs. A row that already errors on master needs a shape only the fix changes ([row pins nothing on master](../learnings/1792181706579-a-diagnostic-test-row-can-pin-nothing-when-master-.md)).

**Crash→diagnostic regressions.** `_diagnosticAnnotationTest` ignores the process result code, yet it catches a crash regression: the buggy compiler segfaults with empty stderr, so the expected diagnostic (e.g. `E30015`) is unmatched. That holds only when diagnostic and crash are mutually exclusive, true for a front-end error because `executeActionsInner` returns before `generateIR()` on a non-zero error count. If the crash is downstream of the diagnostic, add a `SIMPLE` `.expected` test asserting `result code = N`. A fatal diagnostic suppresses codegen, so positive-compilation cases live in a separate file ([crash via empty stderr](../learnings/1785349746955-diagnostic-diag-check-catches-a-crash-regression-v.md)).

## SPIR-V Test Verification

**FileCheck vacuity.** A `//TEST:SIMPLE(filecheck=CHECK): -target spirv` test asserting a positive shape line plus `//CHECK-NOT: error:` can pass with or without the fix (#12592). Rejected SPIR-V is still disassembled (`slang-emit.cpp` calls `disassemble(...)` regardless, and SIMPLE FileCheck does not gate on the result code), so `OpTypePointer StorageBuffer` matches the failed output; and a validation failure prints `internal error 99999:`, with no `error:` substring. A positive `OpTypePointer StorageBuffer` also matches buggy and fixed modules alike when only a slot's pointee is wrong. Assert the buggy artifact is ABSENT (`//CHECK-NOT: PhysicalStorageBuffer`) or that `OpVariable`/`OpStore` operand types agree, and run every new SPIR-V test against the pre-fix binary ([`internal error` defeats `CHECK-NOT: error:`](../learnings/1789244351461-slang-spir-v-test-vacuity-a-validation-failure-dis.md)).

**A SIMPLE lane does not run SPIR-V validation.** A control fragment shader calling `GroupMemoryBarrierWithGroupSync()` (VUID-04682 under slangc with `SLANG_RUN_SPIRV_VALIDATION=1`) PASSED a `//TEST:SIMPLE(filecheck=X): -target spirv -stage fragment` lane with `X-NOT: VUID`, and the "standard error = {" block in `-target spirv` output also matches a naive `-NOT: error`. Pin the construct with `-target spirv-asm` (`CHECK: OpEntryPoint Fragment`, `CHECK-NOT: OpControlBarrier`), run validation separately with slangc for PR evidence, and test any "no error" detector against a known-bad control (#13631 / PR #13659) ([SIMPLE lanes skip validation](../learnings/1792090114561-slang-test-simple-lanes-do-not-run-spir-v-validati.md)).

**Local verification traps** on a GPU- or Vulkan-less machine:

1. slang-test tags spirv/spirv-asm tests with a Vulkan render-API requirement and reports them **IGNORED (0/0)** when no Vulkan device can be created (slang-test-main.cpp ~5980-6009), even known-good tests like `coverage-counter-width-*-spirv.slang` and `atomic-64bit.slang`. SPIR-V emit is compile-time, so verify with direct `slangc` plus `SLANG_RUN_SPIRV_VALIDATION=1` (off by default; CI exports it). That variable validates Slang's **pre-optimizer** module, and spirv-asm shows a constant's value but not its word count, so FileCheck on `OpConstant %long 0` cannot catch a 32-bit-under-64-bit pointer-sized constant; only validation can ([render-API tagged → IGNORED](../learnings/1790009629117-spir-v-compile-only-tests-are-render-api-tagged-ve.md)).
2. slang-test injects `-O0` when a directive gives no opt level (confirmed via `slang-test -v`), so a `CHECK-NOT: OpCompositeConstruct` never exercises spirv-opt: at `-O0` the #13206 repro is still invalid but emits `OpCompositeExtract` instead, a false green. Pass `-O1` on SIMPLE and `-Xslang -O1` on COMPARE_COMPUTE ([slang-test injects -O0](../learnings/1790037466327-slang-test-injects-o0-verifying-spir-v-logical-poi.md)).
3. The in-tree validator is **v2026.4.rc2** (not the recalled v2024.2) and does reject logical-pointer Function vars, so a validation-backed test, or validation plus a spirv-asm `CHECK-NOT` on `OpCompositeConstruct`/`OpCompositeExtract` of a `%_ptr_Workgroup_*` type, beats text matching alone. Check the version; don't recall it ([spirv-val v2026.4.rc2](../learnings/1790785645539-slang-in-tree-spirv-val-v2026-4-rc2-does-catch-log.md)).

## Subagent Bottom Lines: Backend-Codegen Timing Is Measurable

"Is this slow compile front-end or backend?" needs no compiler change: `slangc -report-perf-benchmark` prints per-phase timers as `[*] <phase> <count> <ms>`, and `tools/compile-perf/breakdown.py:56` lists **`emitEntryPointsSourceFromIR`** (the `SLANG_PROFILE` at `source/slang/slang-emit.cpp:2747`) as a named bucket under `generateOutput`. An `Explore` subagent reported the opposite bottom line at a line it cited itself: it read `SLANG_PROFILE` as a flat RAII timer and concluded the tooling cannot attribute, missing that `breakdown.py` reconstructs nesting downstream. The tell is a CAPABILITY claim derived from a MECHANISM one layer below; the check is to run the tool or open the file the capability lives in. Caveat: the profiler is flat, so a parent's time exceeds its named children and `breakdown.py` shows the gap as `<parent> (self)`; an unnamed hotspot needs that residual ([codegen timing is measurable](../learnings/1785838127386-backend-codegen-compile-time-is-separately-measura.md)).

## The Through-Line

Skipped test, stale binary, vacuous assertion, inert `CHECK-NOT`, a row master already rejects: one bug in different disguises, **present but not exercising**. Name the defect, name the assertion that fails when only that defect is reintroduced, and control both directions (flip each positive to a nonexistent name and expect RED; restore it and confirm green).
