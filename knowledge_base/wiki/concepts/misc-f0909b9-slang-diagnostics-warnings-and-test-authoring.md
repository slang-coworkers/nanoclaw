## TL;DR

**Slang's warning mechanism (wiki "disable-only" is STALE).** Slang has a full
opt-in / default-off warning ladder: `WarningLevel{Default, All, Extra, Pedantic}`;
`Default` + `Extra` are ON, `All` and `Pedantic` are OFF by default. CLI `-W<name>`
force-enables per-warning, `-Wno-<id>` disables, `-Wall`/`-Wextra`/`-Wpedantic` are
group toggles. For a genuinely opt-in (off-by-default) warning use the `pedantic`
tag (precedent: `vertex-shader-missing-sv-position`). Diagnostics are Lua-driven
(`slang-diagnostics.lua`); pick a FREE code; severity is baked per definition. Any
warning that fires inside the core module aborts `slang-bootstrap`, so prototype a
new or widened warning against the core module first.

**Lossy int→float warning family (#12929–#12933, #12979).** `IntegerLiteralExpr` folds
unary `-`/`+`/`~` un-truncated (reduce to source width, peel `ParenExpr`); the AST
folder evaluates 64-bit without per-op wrapping (gate to bare literals);
`getMaximumTypeBitSize` returns **64 for IntPtr/UIntPtr** and **0 for half**; the
E30082 float-literal exemption is scalar-only; exact representability = odd-part
significant-bit count (half: round-trip test). Never raise conversion costs.

**DIAGNOSTIC_TEST mechanics.** `//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK)` is **exhaustive
substring matching**, not FileCheck: every emitted record must be annotated, so an
un-annotated line asserts NO diagnostic there. `//CHECK-NOT:` is an inert comment that
still passes the `docs/generated` lint — a no-diagnostic pin needs a one-token control
that still warns. A rich diagnostic emits TWO records (code row + span message row);
legacy lexer diagnostics emit one. Each annotation is a literal substring of ONE field
(message, severity, code, or `severity code`; no `{{.*}}`; never the rendered
`error[E…]:` header), so a message-only annotation ignores severity — bind it with
`^^^ warning E30204` on the primary row (codes are always `E<code>`). An unlocated
`E99997` (`0:0`) cannot be caret-anchored. Use SIMPLE_EX for `-lang glsl`;
`.glsl`/`.hlsl` under `tests/` are gitignored (`git add -f`).

**Real FileCheck.** A bare `CHECK-NOT` guards only the gap between neighbouring positive
matches — use a `CHECK-DAG`/`CHECK-NOT`/`CHECK-DAG` barrier or a `-NOT`-only run, and
run the revert drill on every negative.

**Harness/build facts.** `-warnings-disable` works on SIMPLE but not COMPARE_COMPUTE
(forward via `-xslang -Wno-<code>`); slang-rhi's CPU backend is harness-skipped on
Linux; internal (non-`SLANG_API`) symbols are testable in `slang-static-unit-test` —
but verify that target exists at the PR's head commit, not master.

## Slang's warning mechanism is opt-in-capable

The shared-wiki claim that per-warning control is "disable-only" is STALE. `DiagnosticInfo` carries a `WarningLevel level`; `DiagnosticSink::getEffectiveMessageSeverity` disables any warning whose level is not in `m_enabledWarningLevels`. `Default` + `Extra` are on by default; **`All` and `Pedantic` are OFF** (so `-Wextra` is effectively always on). CLI: `-W<id-or-name>` force-enables, `-Wno-<id>` disables, `-Wall`/`-Wextra`/`-Wpedantic` toggle groups. A GCC-style opt-in `-W<foo>` needs no new plumbing — an off-by-default `warning(...)` def tagged `pedantic` plus the emit site (precedent `vertex-shader-missing-sv-position`, E38052). Implicit-conversion warnings live in `SemanticsVisitor::_coerce` (`slang-check-conversion.cpp`); signedness cost buckets sit below `kConversionCost_Default`, so a sign-change warning needs its own branch (`isSigned(to) != isSigned(from)`) ([Slang HAS opt-in default-off warnings — wiki "disable-only" is stale](../learnings/1788789285754-slang-has-opt-in-default-off-warnings-warninglevel.md)). Lossy int→float is likewise an independent `if` (int→float cost 400 < 500 never reaches the `cost >= kConversionCost_Default` band); do NOT raise the conversion cost, which perturbs overload resolution language-wide ([lossy int→float warning: annotation mechanics + unsigned-literal & warning-group pitfalls](../learnings/1788797863864-slang-lossy-int-float-warning-diagnostic-test-anno.md)).

**Severity is bound per definition.** Rich (Lua-defined, `~name:Type`) diagnostics take severity from the baked `getInfo()->severity`; the positional `diagnose(pos, DiagnosticInfo copy, …)` overload only substitutes `$0..$9`, so it renders a rich diagnostic's literal `~name:Type`, and `overrideDiagnosticSeverity` is a global per-id remap for `-Wno-`/`-Werror`. To show an error reason as a note on another error, add a `standalone_note(...)` companion in `slang-diagnostics.lua` (precedent: note E40018 restates error E30019). For overload-candidate note dedup use `HashSet<DeclRef<Decl>>`, not `Decl*` or the rendered signature (#12965/#12969) ([diagnostic severity is per-definition; diag=CHECK is exhaustive](../learnings/1788902941686-slang-diagnostic-severity-is-per-definition-diag-c.md)).

**A new or widened warning that fires inside the core module breaks the build.** `Session::addBuiltinSource` (`slang-global-session.cpp:~1248`) calls `SLANG_UNEXPECTED("Compiling the core module should not yield any warnings")` on any sink output, so `slang-bootstrap` aborts on the first hit in `core.meta`/`hlsl.meta`/`diff.meta`. Prototype a widened diagnostic against the core module first; to count every hit in one run, comment out that `SLANG_UNEXPECTED` in a throwaway worktree. Example: widening E30515 (generic-param-shadows-outer) to value params (`isGenericParam`) hits exactly `core.meta.slang:2242`, where `__generic<$(ptrTypeParameterList)>` redeclares `Access access` inside `extension<Access access> Ptr<void, access>` ([core-module bootstrap aborts on any warning](../learnings/1792436239104-core-module-bootstrap-aborts-on-any-warning-worktr.md)).

## The lossy int→float literal-checking traps

**Literal folding is un-truncated.** The parser folds unary `-`/`+`/`~` INTO `IntegerLiteralExpr`, keeping the un-truncated 64-bit payload until IR lowering, so `-0xffffffff` (a `uint`) reaches the checker as −4294967295 though its value is `1u`. Reduce the payload to the source width (sound for a literal: negation/bitwise-not commute with truncation mod 2^width), peel `ParenExpr`, and use two's-complement *magnitude* for negatives. `tryFoldIntegerConstantExpression` evaluates in 64 bits WITHOUT per-op wrapping, so a folded *binary* expression can differ from runtime (`(uint(0xffffffff)+2)/3` folds to 1431655765, runtime `0u`) — gate representability checks to bare literals ([IntegerLiteralExpr folds unary ops (un-truncated); folder is un-wrapped](../learnings/1788812664549-integerliteralexpr-folds-unary-ops-un-truncated-fo.md)).

**`getMaximumTypeBitSize` returns 64 for IntPtr/UIntPtr** — the *maximum* width, not the target's pointer width — and literals can be pointer-typed (`z`/`uz`), so on a 32-bit-pointer target a literal lossy at 64 but exact at 32 warns spuriously. Handle per branch, not by blanket exclusion (which drops provably-lossy cases): a literal source warns only if lossy at BOTH 32 and 64; a non-constant source uses the conservative 32-bit minimum ([width-based int→float diagnostics: getMaximumTypeBitSize IntPtr trap](../learnings/1788814344464-width-based-int-float-diagnostics-getmaximumtypebi.md), [getMaximumTypeBitSize returns 64 for IntPtr/UIntPtr — the MAX, not the target width](../learnings/1788817928259-getmaximumtypebitsize-returns-64-for-intptr-uintpt.md)). Exact float representability = odd-part significant-bit count (strip trailing zeros first, so 2^28 stays exact), NOT `getIntValueBitSize(v) <= mantissaBits`.

**E30082's float-literal exemption is scalar-only.** `!as<FloatingPointLiteralExpr>(fromExpr)` exempts `takeDoubleScalar(1.0f)` but not `takeDoubleVector(float4(1.0f,…))`, whose fromExpr is an `InvokeExpr` — decide intent and pin the branch with positive/negative tests (to extend, look through literal-constructor `InvokeExpr`s). The new `cost < kConversionCost_Explicit` gate is correct but non-local: ≥Explicit conversions are already rejected as TypeMismatch earlier ([E30082 float-literal exemption is scalar-only (asymmetry with vector/matrix constructors)](../learnings/1788801482957-e30082-float-literal-exemption-is-scalar-only-asym.md)).

**int→half (#12979) needs round-trip exactness, not a range.** Same E30081 `UnrecommendedImplicitConversion` path (`_coerce`, `slang-check-conversion.cpp:2861-2881`); the decision is `isIntValueInRangeOfType`'s `Half` arm (`slang-check-decl.cpp:12114`), which suppressed only the contiguous `[-2048, 2048]`. With 11 significant bits, exact integers above 2048 are non-contiguous (evens to 4096, multiples of 4 to 8192, … to max finite **65504**), so no range expresses "4096 ok / 4097 not". Use `slang-math.h`'s `(double)HalfToFloat(FloatToHalf((float)value)) == (double)value`, comparing in floating point (casting inf/nan half to int64 is UB; idiom at `slang-ir.cpp:2566`), in a named `isIntExactlyRepresentableInHalf`. Diagnostic-only; don't touch `ConversionCost` buckets. A shared "exactly representable in float type T" predicate would serve #12929, #12930 and #12979 ([int→half E30081: use round-trip exactness, not a fixed `[-2048,2048]` range](../learnings/1788945215723-slang-int-half-e30081-warning-use-round-trip-exact.md)). Routing: `getMaximumTypeBitSize()` returns **0** for `BaseType::Half` (`default:` arm), so the `maxBitSize > 0`-guarded `IntegerConstantOverflow` branch is skipped and **every** int→half literal, overflowing `131072` included, is diagnosed via E30081. In a `diag=CHECK` test the caret width includes a `u` suffix (`65505u` → 6 carets) ([int→half E30081 routes through `_coerce` because `getMaximumTypeBitSize`=0 for half](../learnings/1788947867563-half-int-literal-conversion-warning-e30081-getmaxi.md)).

## DIAGNOSTIC_TEST and FileCheck authoring

`//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK)` is **exhaustive substring matching**, NOT FileCheck: each `//CHECK:` matches a substring of one still-unmatched record, order-independent, and every emitted record must be annotated or the test fails ("Found N diagnostic(s) without annotations") — so to prove a case does NOT warn, leave it unannotated; to test a dedup fix, invoke the construct twice. A rich diagnostic with a differently worded span emits TWO records (header + span message), both needing annotations. Match by code (`E39999`) or message text, never the rendered `error[E39999]:` header (that FAILS). Easiest authoring: run with no annotations and copy the "Suggested annotations" block; add `,non-exhaustive` only for a genuinely unannotated secondary diagnostic (the harness errors on an unnecessary one). Front-end diagnostics need no target/entrypoint; unused locals don't warn ([DIAGNOSTIC_TEST diag=CHECK is exhaustive; short+span records; no CHECK-NOT](../learnings/1789718875570-slang-diag-check-diagnostic-test-is-exhaustive-and.md), [diagnostic severity is per-definition; diag=CHECK is exhaustive](../learnings/1788902941686-slang-diagnostic-severity-is-per-definition-diag-c.md)). Pin `warning E<code>` on at least one assertion to verify the severity — never `warning 30082` (no `E`, vacuous); a comment-line echo of a bare code can self-match, so prefer message-text carets. Boundary tests use an ODD value (`16777217`): powers of two strip to one significant bit and never exercise the `significantBits <= mantissaBits` compare ([IntegerLiteralExpr folds unary ops](../learnings/1788812664549-integerliteralexpr-folds-unary-ops-un-truncated-fo.md)).

**Pinning "no diagnostic here" needs a live control.** The parser reads only `//CHECK:` and `/*CHECK:` lines (`tools/slang-test/diagnostic-annotation-util.cpp:83-89`), so `//CHECK-NOT: W30051` is a plain comment — including those in `tests/diagnostics/aliased-out-inout-parameter.slang` ([CHECK-NOT is inert; exhaustive mode + one-token control](../learnings/1792744742040-diagnostic-test-check-not-is-inert-assert-no-warni.md)). It still satisfies the `docs/generated/tests` lint (`_meta/regenerate.py` ~2620-2700 needs only `CHECK[^:]*:…\b[EWNI]\d+\b`), and a zero-annotation file passes whenever the compiler emits nothing, even if the warning is deleted. Robust pin: leave the negative call unannotated, and add a one-token-different control that still warns, with caret CHECKs from "Suggested annotations". `non-exhaustive` on such a file fails "Unnecessary 'non-exhaustive'", so the pin can't be switched off silently. Precedent `aliased-out-inout-parameter.slang:117-119`; PR #13887 used it for the in+out alias fixture after #13406 ([CHECK-NOT is inert but passes lint; a no-diagnostic pin needs a live control](../learnings/1792745836053-diagnostic-test-check-not-is-inert-but-passes-lint.md)).

**Matching is a literal substring of ONE field** (message, severity, code, or `severity code`): `{{.*}}` is not interpreted and code and message are never concatenated, so `CHECK: E99997{{.*}}non-simple operand` fails while `CHECK: E99997` passes (#12875). **`E99997` (an internal `SLANG_UNEXPECTED` abort) is unlocated** (`0:0`), so no caret can pin it; if a maintainer wants the location tested the compiler must first emit a real located diagnostic — a scope question to ask first. **Prove the anchor is load-bearing**: move the caret one column, then to another line (both must fail), and revert-drill the compiler (`false &&` the new branch). Same PR: a user `bit_cast<Word>(Empty{})` never reaches `lowerBitCast`'s located E41202, since empty-type legalization removes `Empty` first and `legalizeBitCast` reports `NotEqualBitCastSize`; `sourceLoc.isValid()` is not evidence a cast was user-authored (lower-to-ir and inlining locate compiler casts too) — enumerate the `BitCast` producers ([DIAGNOSTIC_TEST: annotate every record; unlocated internal errors cannot be caret-anchored](../learnings/1791296982463-slang-diagnostic-test-annotate-every-record-unloca.md)). A located error's error row (code + title) and span row (message) each need an annotation at the same caret (`//CHECK: ^ E41202`, `//CHECK: ^ <message substring>`); the combined `error E45002: <text>` matches neither — to pin a decl/module name, use a substring of the main message plus one line for the span. A span with an invalid loc (e.g. a decl from a precompiled `.slang-module`) lists at "Line 0"; column-1 carets need a block comment (`/*X:\n^^^^^^ ...\n*/`) ([a span message is a separate entry that needs its own annotation](../learnings/1793366191649-slang-diagnostic-test-a-diagnostic-s-span-message-.md)).

**A message-substring annotation does not check severity.** `checkAnnotations` (~465) accepts any field match. When error E30200 ("conflicting declaration") became version-gated warning E30204, the old message annotations still passed, missing the severity flip (PR #13880); conversely, when a 202c error's text is the warning text plus a suffix ("… which is not allowed in Slang 202c and later"), the pre-202c warning test passed 1/1 under `-std 202c` (PR #14093). **Replace** the primary-row message annotation with the `severity code` form (`//CHECK: ^^^ warning E30204`, `//CHECK: ^^^ error E30200`; the code is `E<code>` for warnings too) and keep the span-message annotation; adding a second line at the same caret fails "(already matched)", since each annotation binds one row. `-std 2018` aliases `legacy,default` (`slang-type-text-util.cpp:120`), so pairing it with a no-`-std` run tests one mode twice and never 2025 ([a warning test passes under the error mode when the error text extends the warning text](../learnings/1793371682024-diagnostic-test-a-warning-test-passes-under-the-er.md)). Two `diag=` prefixes cannot stack annotation blocks under one source line (the other block counts as a source line for caret alignment), so per-version expectations go in separate files ([DIAGNOSTIC_TEST annotations are substring matches — tag severity](../learnings/1793094492688-slang-diagnostic-test-annotations-are-substring-ma.md)). For a method-call diagnostic (E30050/E30068) the caret goes on the call's `(` — in `makeCounter().increment();` the LAST `(`; copy the printed suggestions rather than counting columns ([.hlsl tests gitignored; method-call carets at the call paren](../learnings/1793143062366-slang-tests-hlsl-files-are-gitignored-diagnostic-c.md)).

**Annotation count follows record count.** Rich diagnostics (E41407, E15501) need a code line plus `//CHECK: ^ <message substring>` at the same column (or `non-exhaustive`); a lone `^ E41407` still leaves an unannotated record. A CAS-style op reporting both order operands at one `sourceLoc` can emit two identical diagnostics (`(MemoryOrder)7`) — dedupe and pin with a test row ([exhaustive DIAGNOSTIC_TEST: annotate code AND message](../learnings/1791550646372-slang-exhaustive-diagnostic-test-annotate-code-and.md)). Lexer diagnostics (`slang-lexer-diagnostic-defs.h`: 10002 octal, 10003 invalid digit) print legacy-format (`error 10003: …`) with no span row, so exactly ONE annotation each; a second fails "(already matched)". Pin with `//CHECK: ^ error E10003`, which matches via `severity errorCode` with the `E` even though output prints `10003` (an `E10004` control fails). Octal 10002 on `07_9` spans the whole token (`^^^^`). Checker-legacy diagnostics such as E30047 differ — their span row needs a second line (on [[wiki/concepts/slang-b-test-harness.md]]) — so copy the runner's suggestions rather than a rule ([legacy lexer diagnostics: one annotation per diag](../learnings/1791572293591-slang-legacy-lexer-diagnostics-one-annotation-per-.md)).

**Choosing the source language.** slang-test appends directive options AFTER the file path and `-lang` affects only later files, so `SIMPLE(diag=CHECK):-lang glsl ...` still parses Slang. `#version 450` in a `.slang` file switches language but adds two diagnostics ("source-language directive selects glsl and overrides…"), breaking exhaustive mode. Use `//DIAGNOSTIC_TEST:SIMPLE_EX(diag=CHECK): -lang glsl tests/<path>/<file>.slang -target spirv -stage vertex -entry main` with no `#version` (precedent `tests/glsl-intrinsic/compute-derivative/*.slang`); an HLSL-only option such as `-Gec` works as `-lang hlsl -Gec` in plain SIMPLE ([GLSL diagnostic tests: -lang glsl must precede the file (use SIMPLE_EX)](../learnings/1792703656968-slang-test-glsl-diagnostic-tests-lang-glsl-must-pr.md)). Keep the file `.slang`: `.gitignore` ignores `/tests/**/*.glsl` and `*.hlsl` as generated outputs, so such a test passes locally but stays out of `git status` and plain `git add` fails "paths are ignored"; in-tree ones were `git add -f`'d (`tests/bugs/13306/*.hlsl`, `tests/hlsl/*.hlsl`) [.hlsl tests are gitignored](../learnings/1793143062366-slang-tests-hlsl-files-are-gitignored-diagnostic-c.md).

**Real FileCheck** (e.g. SPIR-V absence): a bare leading/trailing `CHECK-NOT` guards only a bounded region and misses forbidden text mid-output, passing vacuously. Use a `CHECK-DAG`(early) / `CHECK-NOT` / `CHECK-DAG`(late) barrier around the target section — it guards only the gap *between* the DAG groups, not text interleaved among one group's matches — and a separate `-NOT`-only run for whole-output absence ([FileCheck CHECK-NOT regions](slang-test-filecheck-authoring-and-opt-levels.md)). `-g2` embeds the whole `.slang` source as one `OpString` with escaped quotes, so bare-word checks self-match directives — anchor on real instruction forms with bare quotes; prove each negative has teeth by asserting absence of something that DOES exist ([FileCheck: assert "X never appears" robustly with a CHECK-DAG/CHECK-NOT/CHECK-DAG barrier](../learnings/1788754022134-filecheck-assert-x-never-appears-robustly-with-a-c.md)). The gap rule holds for plain `CHECK` sequences too: interleave a `-NOT` between every pair of positive lines, add a whole-output `-NOT`-only row, and drill each by emitting the forbidden string inside its gap ([community-PR dedup + FileCheck `-NOT` gaps, #13650](../learnings/1792079739619-search-for-a-community-pr-on-the-issue-before-open.md)).

## Harness / target / build facts

**`-warnings-disable` placement depends on the directive.** On `//TEST:SIMPLE` trailing args go straight to `slangc`, so `-warnings-disable 40021` works; on `//TEST:COMPARE_COMPUTE` (and other render/compute directives) the render harness parses them and aborts with `error 1004` — forward with `-xslang -Wno-40021`. Any directive whose args go through the test/render harness needs `-xslang`/`-Xslang` for compiler flags; exhaustive `DIAGNOSTIC_TEST` cannot suppress at all ([-warnings-disable works on SIMPLE but NOT COMPARE_COMPUTE — forward via -xslang -Wno-N](../learnings/1788460645612-slang-test-warnings-disable-works-on-simple-but-no.md)).

**LANG_SERVER completion tests.** `//COMPLETE:line,col` is 1-based (a coord on the `//COMPLETE` line itself returns an EMPTY list — a *vacuous* pass). The server runs in-process in slang-test (no `slangd`; build only slang-test). To assert exactly one entry `X` of kind `K`: `CHECK-NOT {{^}}X:` / `CHECK: {{^}}X: K` / `CHECK-NOT {{^}}X:`. `collectMembers` already dedups by label (HashSet), so dedup in `collectAttributes` restores an existing idiom ([LANG_SERVER completion tests: COMPLETE coords, output format, "exactly one of kind K" FileCheck](../learnings/1788395364245-lang-server-completion-tests-complete-coords-outpu.md)).

**slang-rhi CPU backend is harness-skipped on Linux.** `tests/testing.cpp` marks the CPU device unavailable on Linux, so a `GPU_TEST_CASE(…, CPU)`'s `.cpu` variant is SKIPPED (runs only on Windows/macOS CI), and doctest counts a SKIP as "passed" — isolate the `.cpu` variant to confirm. Verify a deterministic CPU fix by source inspection plus the GPU backends that run locally; scope the test to `CPU`, not `ALL` (an `ALL` dispatch-limit assertion over-asserts for D3D11 9_1–9_3). slang-rhi's base branch is `main`; clang-format is pinned v20.1.7 (not slang's 17) ([slang-rhi CPU backend is harness-skipped on Linux — CPU-scoped rhi tests can't run locally there](../learnings/1788475957247-slang-rhi-cpu-backend-is-harness-skipped-on-linux-.md)).

**Internal-symbol unit tests go in `slang-static-unit-test`.** To call a non-`SLANG_API` `source/slang` entry point (`readSerializedModuleSerializationVersion`, IR/AST builders), don't conclude "needs a SLANG_API shim + sign-off": `slang-unit-test` is a shared library reaching only exported symbols, while `slang-static-unit-test` links the compiler statically for exactly this — no ABI change (precedent `unit-test-ir-dce.cpp`), and its typed fossil accessor dissolves the "brittle byte-poke" objection ([slang-static-unit-test is the module for testing non-exported source/slang symbols](../learnings/1788679074455-slang-static-unit-test-is-the-module-for-testing-n.md)). That target landed recently, so a PR forked before it lacks it — confirm at the PR ref (`gh api .../contents/tools/slang-static-unit-test?ref=<pr-head>`); any claim that a target, file or helper is *present* must be checked at the exact reviewed ref ([verify recommended test-infra exists on the PR branch, not just master/your local checkout](../learnings/1788679995187-verify-recommended-test-infra-exists-on-the-pr-bra.md)).
