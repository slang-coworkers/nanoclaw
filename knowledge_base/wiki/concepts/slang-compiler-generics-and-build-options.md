# Slang Compiler: Generics Memoization & Build Options

Nested-generic compile cost, the default `-g` level's blast radius, module-serialization dead weight, platform-macro and cache-key bugs, and the four `CompilerOptionSet` levels that option hashing and `DownstreamArgs` composition depend on.

## TL;DR
- Fix the producer, not the consumer; assert out-of-contract shapes. `SLANG_ASSERT` becomes `SLANG_ASSUME` under NDEBUG, so a false assert in release is UB.
- Read internals at a named ref before citing them — DeepWiki was wrong on hashing and on DownstreamArgs concatenation.
- Nested generic calls `wrap(wrap(...wrap(x0)...))` grow compile time EXPONENTIALLY: nothing memoizes per-level substitution/conformance work (interning keys on operand POINTER identity; the subtype-witness cache is GENERATION-GATED).
- The memo fix makes exponential → linear only on a SHARED DAG; on a shallow TREE `SubstitutionCache` is 100% miss → flat ~10-15% regression. Gating the cache is always correctness-safe.
- Split a "confounded" perf regression by CODE PATH: check each workload's invocation mode (`mode="module"` vs `IEntryPoint::specialize`).
- Default `-g` None→Minimal changes TEXTUAL codegen (side-effecting `IRDebugLine` blocks folding) and exposes a masked `== None` strip gap → 19 VM crashes + ~32 golden diffs. A default enum value can mask a code-vs-comment gap for years; a `SLANG_UNIMPLEMENTED` default arm crashes on any newly-surviving inst.
- Debug insts can MASK a dead-store miscompile: repro with `-g0`, add a `-g2` lane.
- `loadSerializedModuleContents`'s per-dep content load is DEAD WEIGHT — only dep PATHS are used and the staleness check digests the serialized chunk itself. `moduleChunk->getFileDependencies()` ≠ `module->getFileDependencies()`.
- `slang.h` derives endianness AND pointer size from one arch whitelist; endianness `#error`s on an unlisted arch but pointer size silently becomes 32-bit → public-ABI corruption.
- Four `CompilerOptionSet` levels: session (`Linkage`), target, component, `TargetProgram` (component overrides, target inherits). The request's `getOptionSet()` is the session set; front-end checks read only it, so `linkWithOptions` options never reach them; codegen reads `TargetProgram`.
- Session options reach an API target per option: since #13945 a default TargetDesc fp/line-directive/scalar-layout field keeps the session value, but `addTarget` always overwrites the profile. Check each such claim at the option's final consumer.
- slangc gives a declared target a version-only profile; the full raw set arrives only at output binding. A stage-bearing session-target profile fails multi-stage modules (E36107) — strip the stage.
- Cache keys must hash every codegen input (`buildHash` dropped `intValue2`; `getEntryPointHash` skipped a linked component's own set). Test on a target AND option values that really change codegen.
- `DownstreamArgs` do NOT compose across levels (`add()` matches tool name), and `(tool, args)` dedup is wrong — clients add one entry per token. Fix by provenance: compose once, concatenate, never dedup; probe with a split-token repeated flag.

## Exponential Compile Time With Generic Nesting Depth (#12100/#12103/#12139)

Nested `wrap(wrap(...wrap(x0)...))` (`Wrapper<T> wrap<T:IModel>(T v)`, `struct Wrapper<T:IModel>:IModel`) grows exponentially (@3eeda847c debug: depth 8≈3.1s, 14≈72s, 16 timeout; same for `typealias Pair` and `T.Next.Next...` chains). Root cause (code trace, not profiled): each call (`ResolveInvoke` slang-check-overload.cpp:3375 → `inferGenericArguments` :2866 → `trySolveGenericArguments` slang-check-constraint.cpp:3406 → `buildSubstDeclRef` :2777) re-substitutes the whole `Wrapper<Wrapper<...>>` tree; neither `DeclRefType::_substituteImplOverride` (slang-ast-type.cpp:152-213) nor `GenericAppDeclRef::_substituteImplOverride` (slang-ast-decl-ref.cpp:482) memoizes; `ASTBuilder::getOrCreate` interns on operand pointer identity, so equal types at different levels miss; `SharedSemanticsContext::m_mapTypePairToSubtypeWitness` (slang-check-inheritance.cpp:95-137) caches only when both inheritance-info generations are non-zero. Separately, non-generic `f(f(...f(x)...))` ~200 deep hits `E39997 maximum type nesting level exceeded` — `kMaxTypeNestingDepth=128` (slang-check.h:21) guards type STRUCTURE, not call depth. The >80x v2026.5→v2026.8 regression's prime suspect (in-window per `git merge-base --is-ancestor`) is #9808 auto-diff refactor (`45ccce9a3`); decide by bisecting `45ccce9a3^` vs `45ccce9a3` on the depth-16 repro. The reporter (jvepsalainen-nv) self-assigned and authors PR #12086 (depth-axis perf suite) → HOLD-for-assignee. File perf bugs with the native **Performance** Issue Type (`IT_kwDOAb2kZs4BlAhg`); when a bot's REST write 403s, GraphQL `updateIssue`/`addLabelsToLabelable`/`addComment` work (label IDs inline in the query string) ([#12100 missing substitution/conformance memo; >80x regression from #9808](../learnings/1784054268864-slang-12100-exponential-generic-nesting-compile-ti.md)).

Follow-up #12103 (depth-axis workloads) is also self-assigned and merge-blocked on open PR #12086 (same `tools/compile-perf/lib/manifest.py`, `lib/workloads.py`). When you shouldn't fix, validate the design against the live schema: `WorkloadSpec` (`manifest.py:28-78`) requires `default_size` in `sweep_sizes` (:539-541) and all 5 proposed workloads pass — a green light, not a bare park. Confirm merge order with `gh pr view <n> --json files --jq '.files[].path'`; `generic_nesting`/`generic_nesting_eval`/`interface_depth` exist only on the open PR ([#12103 hold for owner, merge-blocked on #12086](../learnings/1784056143534-slang-12103-compile-perf-depth-workload-follow-up-.md)).

The fix, PR #12106 ("Memoize shared Val and type DAG traversals", c8d02ae59), caused a flat ~10-15% shallow-generic regression (#12139). `SubstitutionCache` (`slang-ast-substitution.h:16-60`) is a `Dictionary<Key,Result>` heap-constructed per top-level substitution op, with `tryGet` + on-miss `add` (two hashes) per node: on a tree it is 100% miss, pure overhead; only on a shared DAG (inner type recurring as generic arg and witness) does it make exponential linear. Gating the semantics-preserving memo is safe: an inline buffer promoted to a Dictionary, a pooled cache, or a *work*-based guard (a static-depth guard can re-introduce #12100 on a shallow but heavily shared DAG). The `interface_depth` +40% outlier looked inseparable from co-window PR #12052 (`-specialize` conformance visibility), but `tools/compile-perf/lib/manifest.py` shows `interface_depth`/`generic_nesting`/`generic_nesting_eval` use `mode="module"` while only `rt_renderer_specialize`/`api_specialize` call `IEntryPoint::specialize`, the sole path #12052 touches — so #12052 is exonerated ([#12139 split a perf confound by workload trigger path](../learnings/1784270455318-slang-12139-resolving-a-two-commit-perf-confound-b.md)).

## Flipping the Default `-g` Level: Textual-Codegen Fallout + a Masked Strip Gap

slang#11682 flips the default debug level `None`→`Minimal`. **(1) Textual codegen changes, not just SPIR-V.** At Minimal+, `maybeEmitDebugLine` emits `IRDebugLine` in function bodies; `kIROp_DebugLine.mightHaveSideEffects()` is true, so `shouldFoldInstIntoUseSites` won't fold across it and HLSL/GLSL/CUDA/Metal output gains temporaries. Sweep non-SPIR-V goldens too ([-g level changes TEXTUAL codegen](../learnings/1784443119965-slang-debug-g-level-silently-changes-textual-codeg.md)). **(2) A masked strip gap.** `slang-emit.cpp` strips debug info only when the level `== None`, though its comment claims two conditions (incapable target OR `-g0`); while `None` was the default every compile hit the strip. With Minimal, `IRDebugLine` reaches targets that can't consume it → 19 VM/bytecode hard crashes (`slang-emit-vm.cpp` default arm is `SLANG_UNIMPLEMENTED`) plus ~32 textual golden diffs. The right predicate is `!isSPIRV && !isCPUTargetViaLLVM` — a bare `!isSPIRV` wrongly strips DWARF ([default -g flip exposes a masked strip gap](../learnings/1784443743816-slang-flipping-default-g-exposes-a-masked-strip-co.md)).

Debug insts can also MASK a miscompile: in #13466 DSE drops a store before a pure callee that reads it through a pointer — gone with no `-g`/`-g0`, but at `-g2` `*q_0 = 1U` returns in `-target cpp`. Put `-g0` on a COMPARE_COMPUTE directive reproducing a DSE miscompile, and add a `-g2` lane to tell "fixed" from "masked". To show such a bug is independent of an open draft PR, apply only that PR's source diff (`git diff $(git merge-base HEAD pr) pr -- <file>`) to a clean master worktree, rebuild, re-run, then `git checkout -- <file>` ([dead-store bugs hide under debug info](../learnings/1791318495821-slang-dead-store-bugs-can-hide-under-default-debug.md)).

## loadSerializedModuleContents Dep-Loop Content Is Dead Weight (#9400)

At 6a244fee2, `Linkage::loadSerializedModuleContents` (`slang-session.cpp:2248`) eagerly `loadSourceFile`s every dep of a loaded `.slang-module`, but that content is unused on the load path (a module compiles to GLSL with its `.slang` deleted). Only dependency PATHS are used: the load-path digest is chunk-copied, and the `UseUpToDateBinaryModule` check `isBinaryModuleUpToDate` runs its own loadSourceFile+digest loop over the serialized RIFF chunk, so removing the loop would not break staleness checks. `moduleChunk->getFileDependencies()` (serialized chunk, always present) ≠ `module->getFileDependencies()` (in-memory list from the loop) — a subagent conflated them; verify load-bearing subagent claims at both call sites. Missing snippets from precompiled modules (`error 36107` prints `(0)`) are separate: deserialized SourceViews come from empty-content SourceFiles. Maintainer tangent-vector wants the path/source-loc subsystem redesigned ("rotten to its core") → parked for jkwak-work ([#9400 dep-loop content is dead weight](../learnings/1784654116315-slang-9400-loadserializedmodulecontents-dep-loop-c.md)).

## slang#12069: Endianness Fails Loudly, Pointer Size Fails Silently

`include/slang.h` derives both from one arch whitelist (`SLANG_PROCESSOR_X86_64|ARM_64|POWER_PC_64`). Endianness has a guard (`#if ((SLANG_BIG_ENDIAN | SLANG_LITTLE_ENDIAN) == 0) #error`); pointer size has none — `SLANG_PTR_IS_32 = (SLANG_PTR_IS_64 ^ 1)`, so on an unlisted 64-bit arch (rv64, LoongArch64, s390x, MIPS64) `SlangInt`/`SlangUInt` silently become 32-bit → public-ABI/struct-layout corruption. That silent miscompile, not the "use compiler macros" ask, is the bug. gcc & clang predefine `__BYTE_ORDER__`, `__SIZEOF_POINTER__`, `__LP64__`; `__POINTER_WIDTH__` is clang-only; MSVC has none (use `_WIN64`). The block is the single source of truth (copied into generated C++/CUDA host preludes; read by core.meta.slang/nvrtc/slang-llvm), so keep the whitelist, augment the derivation, add the symmetric pointer-size `#error`. Triage Bug/low/P3; hybrid fix (guards, then compiler-macro-primary + whitelist fallback + `sizeof(void*)` cross-check), draft held for maintainer sign-off ([#12069 pointer size fails silently](../learnings/1783835875827-slang-12069-endian-ptr-whitelist-pointer-size-fail.md)).

Related C-ABI pitfall, appending fields to a versioned struct chain by inheritance (`struct Req_1_3 : public Req_1_2 { newFields; }`, PR #12206): a class with a public base AND own data members is not standard-layout, so `offsetof(Req_1_3, field)` is conditionally-supported and fails under `-Werror` (`-Winvalid-offsetof`). Downgrade by base-slicing (`static_cast<const Base&>(derived)`), never `offsetof` or raw reads of the base prefix (base-at-offset-0 is a toolchain property, not a C++ guarantee). The class is still a C++17 aggregate and trivially copyable without user special members; assert `std::is_base_of<B,D>` + `std::is_trivially_copyable_v<D>` — `sizeof(D) > sizeof(B)` does not prove B is a byte-prefix of D ([versioned-struct inheritance: base-slicing, not offsetof](../learnings/1784851897134-c-versioned-struct-inheritance-non-standard-layout.md)).

## The Four CompilerOptionSet Levels (#13847)

Which `getOptionSet()` a caller reads decides everything below. At 135570a76a (#13847):

1. **Session:** `Linkage::m_optionSet`. Linkage has no accessor; `EndToEndCompileRequest::getOptionSet()` (`slang-end-to-end-request.h:391`) only returns `m_linkage->m_optionSet`.
2. **Target:** `TargetRequest::getOptionSet()`. Its constructor copies the session set (`slang-target.cpp:49`), then `Linkage::addTarget(TargetDesc)` applies the TargetDesc fields (fp/line-directive/scalar-layout only when non-default since #13945, the profile always) and calls `overrideWith(TargetDesc::compilerOptionEntries)` (`slang-session.cpp:187-201`). `getTargetOptionSet()` returns this set.
3. **Component:** `ComponentType::getOptionSet()`. `linkWithOptions` loads its entries here (`slang-linkable.cpp:588`). A Module is seeded with a copy of the session set (`slang-module.cpp:27`), a SpecializedComponentType copies its base's, a composite starts empty.
4. **TargetProgram:** `overrideWith(component)` then `inheritFrom(target)` (`slang-target-program.cpp:19-21`). Codegen reads this set.

Front-end checks such as E36107 in `validateEntryPoint` read level 1, so `linkWithOptions` options never reach them; the precedent for an option the front end needs is `createSession` lifting the highest target DebugInformation level into the session set (`slang-global-session.cpp:878-886`). `EndToEndCompileRequest::TargetInfo::targetOptions` is dead, and `m_optionSetForDefaultTarget` holds slangc options given with no `-target`. DeepWiki's "LinkedComponentType" does not exist; `link()` returns `fillRequirements(this)`, the same object when there are no requirements [four CompilerOptionSet levels](../learnings/1792787652921-slang-has-four-compileroptionset-levels-endtoendco.md).

**TargetDesc defaults and default-target state reach a target per option (#13945, #14103).** Before `79fa796e` (#13945, after v2026.20), `addTarget` always copied `floatingPointMode`, `lineDirectiveMode` and `forceGLSLScalarBufferLayout`, so a default field reset the session value. Now a default field keeps the session value, a non-default one wins, `compilerOptionEntries` override both, and a `*_DEFAULT` entry forces the compiler default on one target; on v2026.20 or older set these per target. #13945 added 17 lines near `slang.h:4446`, so later `slang.h` citations shift by +17 [default TargetDesc no longer resets session options](../learnings/1793348689215-slang-13945-a-default-targetdesc-no-longer-resets-.md). The profile is still set unconditionally (`slang-session.cpp:201`): a session `-profile spirv_1_6` that `IGlobalSession::parseCommandLineArguments` serialized from `m_optionSetForDefaultTarget` (`slang-global-session.cpp:1177`) is overwritten by a `SLANG_PROFILE_UNKNOWN` `TargetDesc` (SPIR-V version word stays `0x00010500`), while a session fp mode survives. The deprecated `ICompileRequest` path keeps both (`_completeTargetRequest` → `inheritFrom(m_optionSetForDefaultTarget)`); `-profile a -profile b` with no target is caught only by E00042, as the conflict loop visits only `m_rawTargets` [session -profile never reaches API targets](../learnings/1793405396040-session-level-profile-from-parsecommandlineargumen.md). So in PR #14111 gating E00042 and E00044 (`…IgnoredBecauseNoTargets`) on `m_isCommandLineCompile` ("API callers keep default-target state") was right for fp mode, wrong for the profile, and hid conflicting profiles and a profile implying no target; slang-reviewer caught it (B1) via the SPIR-V version and E00042 stayed ungated. Before relaxing an "option ignored" diagnostic for a path, name each option's consumer, quote the line that keeps or overwrites it, and check observable output (a 30-line `libslang.so` probe: parse → `createSession` → `getEntryPointCode` → SPIR-V word 1) [trace each option's API consumer](../learnings/1793406411725-trace-each-option-s-api-consumer-before-gating-sib.md).

**slangc gives a declared target only a version-only profile; the full raw option set arrives with output binding (#14111 R3).** In `OptionsParser::_parse` a declared target gets a subset of its raw options: the profile's *version* only (`Profile(getProfileVersion())`), capabilities, fp mode, layouts, whole-program, embed-downstream-IR. The full `rawTarget.optionSet` (stage-bearing profile, `-emit-*-via-*`) is copied only in `_bindOutputsToTargets`, so a target with no `-o` lets each entry point supply its stage. Moving the full transfer to declaration is not an equivalence refactor: `tests/reflection/multi-file.hlsl` (`-entry mainVS -profile vs_4_0 -target hlsl ... -entry mainFS -profile ps_4_0`) then fails E36107. On the API side a session `TargetDesc::profile` of `findProfile("ps_5_0")` (0x30005, not 0x30000) makes `loadModule` of a VS+PS+CS module fail E36107 with E36112 warnings, and `cs_6_0` (0x50006) loads but warns E36112 per other-stage entry point. So any `overrideWith(rawTarget.optionSet)` into a session or API target must strip the stage (`parseCommandLineArguments` skips output binding and applies the full transfer only for the session description). Test by loading a VS+PS+CS module through a session the parse produced (PR #14111's `createSession`-only test missed this) ([target options reach linkage targets only via output binding](../learnings/1793603016896-slang-options-parser-target-options-reach-linkage-.md), [a stage-bearing TargetDesc::profile blocks multi-stage modules](../learnings/1793606998775-a-stage-bearing-profile-in-targetdesc-profile-bloc.md)). `-whole-program` is invisible in simple SPIR-V; an HLSL `lib_6_6` target emits `export` only under it, making a test observable ([same](../learnings/1793603016896-slang-options-parser-target-options-reach-linkage-.md)).

**Option-parser facts (`slang-options.cpp`, fix/issue-14103).** A bare `-` is not stdin (`findOptionByName` → E00017); use `-- -`. Target options (stored on `getCurrentTarget()`) are `-profile`, `-capability`, `-fp-mode`, `-whole-program`, `-embed-downstream-ir`, `-fvk-use-{scalar,dx,c}-layout`, `-emit-spirv-*` and `-emit-cpu-*`; every other option is a session option wherever it appears (`-target spirv -I foo` still calls `addSearchPath`). Global-session mutations not rolled back on a failed parse: `-load-core-module` (in the arg loop), `-compile-core-module`/`-save-core-module`/`-save-*-bin-source` (after it), `-spirv-core-grammar`, `-default-downstream-compiler`, `-<compiler>-path`. An adjacent `-target X -target X` is silently accepted; only a repeat after a different `-target` gives E00050. `CompilerOptionSet::options` is an `OrderedDictionary`, so `serialize()` emits insertion order, and targets inherit every linkage option except the level-local DownstreamArgs (`-X...`). `-module-name`, `-depfile` and `-pass-through` set only `EndToEndCompileRequest` state, so `IGlobalSession::parseCommandLineArguments` drops them ([slangc option-parser facts](../learnings/1793608426918-slangc-option-parser-facts-verified-while-document.md)).

## Cache Keys Must Hash Every Codegen Input (#12270, #13197)

**`buildHash` drops the second integer (#12270).** `CompilerOptionSet::buildHash`'s `Int` branch appends only `v.intValue`, never `v.intValue2` — unlike the `String` branch, which appends both. Four codegen-changing options pack a second int there (`-fvk-bind-globals <index> <set>`, `VulkanBindShift`/`BindShiftAll`, `-trace-coverage-binding <index> <space>`), so they collide on the key for BOTH the shader cache and `.slang-module` freshness. Fix: `builder.append(v.intValue2)`; test in slang-unit-test (`buildHash` is API-path only) ([#12270 buildHash drops intValue2](../learnings/1785350469856-buildhash-int-branch-drops-intvalue2-multi-integer.md)).

**`getEntryPointHash` omits a linked component's own option set (#13197 / PR #13215).** It returned one hash for `linkWithOptions` with different `-Xnvrtc --gpu-architecture=` args, so a cache could serve another target's code. `linkWithOptions` deposits `DownstreamArgs` into the linked component's own `m_optionSet` (`slang-linkable.cpp:557`), which drives codegen (`TargetProgram` ctor `overrideWith` → `getDownstreamArgs`), but `ComponentType::getEntryPointHash` (one non-virtual impl) never hashed it — only `Module::buildHash` hashes its own set; `CompositeComponentType`/`SpecializedComponentType::buildHash` only recurse, and `EntryPoint`/`RenamedEntryPointComponentType` hash nothing. Fix: `getOptionSet().buildHash(builder);` in `getEntryPointHash` (`slang-linkable.cpp:315`). DeepWiki wrongly claimed they were hashed — check the actual `buildHash` overrides ([getEntryPointHash omits a component's own option set](../learnings/1790001366182-getentrypointhash-omits-a-component-s-own-link-tim.md)). PR #13215 review: `CompilerOptionSet::buildHash` DOES hash `DownstreamArgs` (string path, no intValue2 bug); the added line is a no-op only for an empty-set composite and re-hashes a plain `Module`'s bytes — harmless, misses only, never a false hit; a nested `linkWithOptions` inside a further composite still contributes nothing (a `// TODO`, consistent since codegen reads only `this`'s set) ([PR #13215 review: Module re-hash is harmless](../learnings/1790048442419-getentrypointhash-link-time-downstreamargs-fix-con.md)).

**Test on a target and option values that really change codegen.** `-Xnvrtc …` on `SLANG_SPIRV` never reaches nvrtc, so asserting distinct hashes locks in a spurious miss (cf. `..DoesNotAffectCompilerOptionHash` tests); use `SLANG_PTX`. Tests are GPU-free, API-path, in `tools/slang-unit-test/unit-test-stdin-compile.cpp`, reusing `_getOptionEntryPointHash`/`_blobContentEquals` ([test with the target the option affects](../learnings/1790049157547-test-a-getentrypointhash-shader-cache-key-change-w.md)). The target alone is not enough: any differing string changes the digest, so the toggled option must (a) pass to the downstream tool unmodified and (b) really change codegen for the fixture. On #13197 nvrtc `--gpu-architecture=compute_75` vs `compute_120` clashes with the `-arch=compute_*` Slang injects (`slang-nvrtc-compiler.cpp`, DownstreamArgs appended after), and dxc `-Od` vs `-O3` collapses because Slang appends `-O1` last and DXC honors the last opt flag. Good pairs: nvrtc `--fmad=false`/`true` with a FLOAT multiply-add in the fixture; dxc `-Gfa`/`-Gfp` with a data-dependent branch (`-Gfa` on SM 5.1+ also needs `-all_resources_bound`). A `DownstreamArgs` argline splits on newline (`CommandLineArgs::deserialize` → `StringUtil::split(content, '\n')`), so two dxc args are `"-Gfa\n-all_resources_bound"`. Use a dedicated fixture and have codex compile both arg sets to confirm output differs ([avoid spurious-miss args](../learnings/1790100487907-testing-that-link-time-downstream-args-affect-gete.md)).

## DownstreamArgs Don't Compose Across Levels — Never Dedup by Value (#13436)

`CompilerOptionSet::add(name, List, replaceDuplicate)` (`slang-compiler-options.h:140-173`) matches "already present" on `stringValue` — for `DownstreamArgs` the TOOL NAME — so any two entries for one tool match: `overrideWith` (replace=true) overwrites the first entry once per incoming entry (last wins), `inheritFrom` (replace=false) skips. Only a destination with no `DownstreamArgs` gets the list verbatim, so one level composes (#12861/#12900) but session/target/link do not (`Linkage::addTarget`; `TargetProgram` ctor); DeepWiki wrongly says they concatenate [tool-name match blocks composition](../learnings/1791192233228-downstreamargs-never-compose-across-option-set-lev.md). The tempting fix — concatenate and elide exact `(tool, args)` duplicates, as the session set re-arrives (copied by the `TargetRequest` ctor at `slang-target.cpp:32` and a Module at `slang-module.cpp:27`, then `inheritFrom(session)` again at `slang-session.cpp:188` / `end-to-end-request.cpp:170,1328`) and NVRTC 12.6 rejects a repeated `--fmad`/`--gpu-architecture` — is WRONG: an entry is not an argument. SlangPy adds one entry per token (`shader.cpp` ~383-386 session, ~1635-1638 link), so `[-D, FOO=1, -D, BAR=2]` dedups to `-D FOO=1 BAR=2` and NVRTC fails "unrecognized option BAR=2"; slangc's trailing-`\n`-per-arg serialization (`CommandLineArgs::serialize`) vs the API's raw storage also makes `stringValue2` equality miss equivalent entries [value dedup breaks SlangPy](../learnings/1791207821835-value-based-dedup-of-downstreamargs-breaks-slangpy.md). No value rule can tell "same level arrived twice via a copy" from "user repeated an arg", so **the fix is provenance: each level stores only its own args, compose ONCE at the consumption point, concatenate, no dedup.** Every merge-rule probe matrix needs a split-token repeated flag (`-D x -D y` as separate entries) beside joined `--flag=value` cases — the triage prototype passed every joined probe and broke on this [never dedup by (tool, args); compose once](../learnings/1791208289552-slang-downstreamargs-never-dedup-entries-by-tool-a.md). GPU-free NVRTC probe: `--fmad=false` at one level, an arch flag at another; compile `o[0]=o[1]*o[2]+o[3]` to PTX and check `fma.rn` and `.target sm_NN`.
