# Slang Compiler: Generics Memoization & Build Options

Compile-time cost of nested generics (missing memoization and its shallow-generic trade-off), the blast radius of flipping the default `-g` level, dead weight in module-serialization dependency loading, two platform/build-option bugs (endianness-vs-pointer-size asymmetry, a hash that drops an operand), and the four `CompilerOptionSet` levels that option hashing and `DownstreamArgs` composition depend on.

## TL;DR
- Discipline unchanged: fix the producer, not the consumer; assert out-of-contract shapes rather than guard them. `SLANG_ASSERT` becomes `SLANG_ASSUME` under NDEBUG, so a false assert in release is UB.
- Before citing an internals behaviour, read it at a named ref — several entries here started from a false premise (DeepWiki was wrong on hashing and on DownstreamArgs concatenation).
- Nested generic calls `wrap(wrap(...wrap(x0)...))` grow compile time EXPONENTIALLY in depth: nothing memoizes the substitution/conformance work each level redoes — interning keys on operand POINTER identity and the subtype-witness cache is GENERATION-GATED, so `Wrapper<T>:IModel` is re-proven per level.
- The memoization fix turns exponential → linear only on a SHARED DAG; on a shallow TREE the `SubstitutionCache` is 100% miss → a flat ~10-15% regression. Gating/shrinking the cache is always correctness-safe — a pure speed/space trade.
- A perf confound that "can't be separated from the aggregate data" is often separable by CODE-PATH analysis: check a workload's invocation MODE (`mode="module"` vs `IEntryPoint::specialize`), not just its name.
- Flipping the DEFAULT `-g` None→Minimal changes TEXTUAL codegen (side-effecting `IRDebugLine` suppresses folding) and exposes a masked strip-condition gap (`== None` only) → 19 VM crashes + ~32 golden diffs. A default enum value can mask a code-vs-comment gap for years; a `SLANG_UNIMPLEMENTED` default arm turns any newly-surviving inst into a crash.
- Debug insts can also MASK a dead-store miscompile: repro with `-g0`, add a `-g2` lane.
- `loadSerializedModuleContents`'s eager per-dep content load is DEAD WEIGHT — only dependency PATHS feed consumers, and the staleness check runs its OWN digest loop over the serialized chunk. Disambiguate `moduleChunk->getFileDependencies()` from `module->getFileDependencies()`.
- `include/slang.h` derives endianness AND pointer size from one arch whitelist, but endianness `#error`s on an unlisted arch while pointer size silently becomes 32-bit → public-ABI corruption on rv64/LoongArch64/s390x/MIPS64.
- Four `CompilerOptionSet` levels: session (`Linkage`), target, component, `TargetProgram` (component overrides, then target inherits). `EndToEndCompileRequest::getOptionSet()` is the session set; front-end checks read only it, so `linkWithOptions` options never reach them; codegen reads `TargetProgram`.
- Session/default-target options reach an API target per option: since #13945 a default TargetDesc fp/line-directive/scalar-layout field keeps the session value, but `addTarget` always overwrites the profile. Check each "kept for later targets" claim at that option's final consumer.
- Cache keys must include every codegen input: `buildHash`'s Int branch drops `intValue2` (four options collide), and `getEntryPointHash` omitted a linked component's own option set. Test hash changes on a target AND option values that really change codegen.
- `DownstreamArgs` do NOT compose across session/target/link levels (multi-value `add()` matches on tool name), yet value/`(tool, args)` dedup is wrong — clients add one entry per token. Fix by provenance: each level stores its own args, compose once, concatenate, never dedup; always probe with a split-token repeated flag.

## Exponential Compile Time With Generic Nesting Depth (#12100/#12103/#12139)

Nested `wrap(wrap(...wrap(x0)...))` (`Wrapper<T> wrap<T:IModel>(T v)`, `struct Wrapper<T:IModel>:IModel`) grows exponentially (ToT @3eeda847c debug slangc: depth 8≈3.1s, 12≈11.7s, 14≈72s, 16 timeout; same class for `typealias Pair` chains and `T.Next.Next...` associated-type chains). Root cause (code trace + DeepWiki, not profiled): each call (`ResolveInvoke` slang-check-overload.cpp:3375 → `inferGenericArguments` :2866 → `trySolveGenericArguments` slang-check-constraint.cpp:3406 → `buildSubstDeclRef` :2777) re-substitutes the whole `Wrapper<Wrapper<...>>` tree. `DeclRefType::_substituteImplOverride` (slang-ast-type.cpp:152-213) and `GenericAppDeclRef::_substituteImplOverride` (slang-ast-decl-ref.cpp:482) don't memoize; `ASTBuilder::getOrCreate` interns on operand pointer identity, so identical types at different levels miss; `SharedSemanticsContext::m_mapTypePairToSubtypeWitness` (slang-check-inheritance.cpp:95-137) caches only when both inheritance-info generations are non-zero. A distinct facet: non-generic `f(f(...f(x)...))` at ~200 deep hits `E39997 maximum type nesting level exceeded` — `kMaxTypeNestingDepth=128` (slang-check.h:21) guards type STRUCTURE, not call depth. The >80x v2026.5→v2026.8 regression's primary suspect (in-window via `git merge-base --is-ancestor`, not profiled) is #9808 "Refactor auto-diff implementation" (`45ccce9a3`); decide with a first-parent bisect `45ccce9a3^` vs `45ccce9a3` on the depth-16 repro. The reporter (jvepsalainen-nv) self-assigned and authors PR #12086 (compile-perf depth-axis suite), so the chain parked HOLD-for-assignee. File perf bugs with the native **Performance** Issue Type (`IT_kwDOAb2kZs4BlAhg`); GraphQL `updateIssue`/`addLabelsToLabelable`/`addComment` work when a bot's REST write 403s, but `addLabelsToLabelable` needs label IDs inline in the query string ([slang#12100 exponential generic-nesting compile time: missing substitution/conformance memoization; >80x regression from #9808](../learnings/1784054268864-slang-12100-exponential-generic-nesting-compile-ti.md)).

Follow-up #12103 (depth-axis workloads) is not for a fixer either: self-filed and self-assigned, and merge-blocked on open PR #12086, which edits the same `tools/compile-perf/lib/manifest.py` and `lib/workloads.py`. When you shouldn't fix, validate the design against the live schema: `WorkloadSpec` (`manifest.py:28-78`) requires `default_size` in `sweep_sizes` (:539-541) and all 5 proposed workloads pass — a green light, not a bare park. Confirm merge order with `gh pr view <n> --json files --jq '.files[].path'`; `generic_nesting`/`generic_nesting_eval`/`interface_depth` exist only on the open PR ([slang#12103 compile-perf depth-workload follow-up — hold for self-assigned owner, merge-blocked on #12086](../learnings/1784056143534-slang-12103-compile-perf-depth-workload-follow-up-.md)).

The fix, PR #12106 ("Memoize shared Val and type DAG traversals", c8d02ae59), caused a flat ~10-15% shallow-generic regression (#12139). `SubstitutionCache` (`slang-ast-substitution.h:16-60`) is a `Dictionary<Key,Result>` heap-constructed per top-level substitution op, with `tryGet` + on-miss `add` (two hashes) per node: on a tree it is 100% miss, pure overhead; only on a shared DAG (inner type recurring as generic arg and witness) does it convert exponential to linear. The memo is semantics-preserving, so gating it is safe; directions are an inline-buffer cache promoted to a Dictionary, pooling the cache across ops, or a *work*-based guard (a static-depth guard can re-introduce #12100 on a shallow-looking but heavily shared DAG). Methodology: the `interface_depth` +40% outlier looked inseparable from co-window PR #12052 (`-specialize` conformance visibility), but `tools/compile-perf/lib/manifest.py` shows `interface_depth`/`generic_nesting`/`generic_nesting_eval` use `mode="module"` while only `rt_renderer_specialize`/`api_specialize` call `IEntryPoint::specialize`, the sole path #12052 touches — so #12052 is exonerated ([slang#12139 — resolving a two-commit perf confound by workload trigger-path (#12106 memo vs #12052 -specialize)](../learnings/1784270455318-slang-12139-resolving-a-two-commit-perf-confound-b.md)).

## Flipping the Default `-g` Level: Textual-Codegen Fallout + a Masked Strip Gap

slang#11682 flips the default debug level `None`→`Minimal`. **(1) Textual codegen changes, not just SPIR-V.** At Minimal+, `maybeEmitDebugLine` emits `IRDebugLine` through function bodies; `kIROp_DebugLine.mightHaveSideEffects()` is true, so `shouldFoldInstIntoUseSites` won't fold across it and the C-like emitter materializes temporaries in HLSL/GLSL/CUDA/Metal. Sweep the non-SPIR-V goldens too ([slang debug -g level silently changes TEXTUAL codegen (folding)](../learnings/1784443119965-slang-debug-g-level-silently-changes-textual-codeg.md)). **(2) A masked strip gap.** `slang-emit.cpp` strips debug info only when the level `== None`, though its comment claims two conditions (incapable target OR `-g0`); while `None` was the default every compile hit the strip. With Minimal, `IRDebugLine` reaches targets that can't consume it → 19 VM/bytecode hard crashes (`slang-emit-vm.cpp` default arm is `SLANG_UNIMPLEMENTED`) plus ~32 textual golden diffs. The right predicate is `!isSPIRV && !isCPUTargetViaLLVM` — a bare `!isSPIRV` wrongly strips DWARF ([flipping default -g exposes a masked strip-condition gap → VM crashes + codegen churn](../learnings/1784443743816-slang-flipping-default-g-exposes-a-masked-strip-co.md)).

Side-effecting debug insts can also MASK an optimizer miscompile. In #13466 dead-store removal drops a store before a pure callee that reads it through a pointer: with no `-g` or `-g0` the store is gone; at `-g2` `*q_0 = 1U` returns in `-target cpp`. Put `-g0` on a COMPARE_COMPUTE directive reproducing a DSE miscompile, and add a `-g2` lane to tell "fixed" from "masked". To show such a bug is independent of an open draft PR, apply only that PR's source diff (`git diff $(git merge-base HEAD pr) pr -- <file>`) to a clean master worktree, rebuild, re-run, then `git checkout -- <file>` ([dead-store bugs can hide under debug info; repro with -g0 and check -g2](../learnings/1791318495821-slang-dead-store-bugs-can-hide-under-default-debug.md)).

## loadSerializedModuleContents Dep-Loop Content Is Dead Weight (#9400)

At 6a244fee2, `Linkage::loadSerializedModuleContents` (`slang-session.cpp:2248`) eagerly `loadSourceFile`s every dep of a loaded `.slang-module`, but that content is unused on the load path (verified: a module compiles to GLSL with its `.slang` deleted). Only dependency PATHS feed consumers: the load-path digest is chunk-copied, and the `UseUpToDateBinaryModule` check `isBinaryModuleUpToDate` runs its own loadSourceFile+digest loop over the serialized RIFF chunk, not the in-memory list, so removing the loop would not break staleness checks. `moduleChunk->getFileDependencies()` (serialized chunk, always present) ≠ `module->getFileDependencies()` (in-memory list from the loop) — a code-reader subagent conflated them; verify load-bearing subagent claims at both call sites. Missing snippets from precompiled modules (`error 36107` prints `(0)`) are a separate mechanism: deserialized SourceViews come from empty-content SourceFiles. Maintainer tangent-vector called the path/source-loc subsystem "rotten to its core" and wants a redesign → parked for jkwak-work, no auto-fixer ([slang#9400: loadSerializedModuleContents dep-loop content is dead weight; up-to-date check is independent](../learnings/1784654116315-slang-9400-loadserializedmodulecontents-dep-loop-c.md)).

## slang#12069: Endianness Fails Loudly, Pointer Size Fails Silently

`include/slang.h` derives both from an arch whitelist (`SLANG_PROCESSOR_X86_64|ARM_64|POWER_PC_64`). Endianness has a guard (`#if ((SLANG_BIG_ENDIAN | SLANG_LITTLE_ENDIAN) == 0) #error`); pointer size has none — `SLANG_PTR_IS_32 = (SLANG_PTR_IS_64 ^ 1)`, so on an unlisted 64-bit arch (rv64, LoongArch64, s390x, MIPS64) `SlangInt`/`SlangUInt` silently become 32-bit → public-ABI/struct-layout corruption. That silent miscompile is the real bug, not the "use compiler macros" ask. gcc & clang predefine `__BYTE_ORDER__`, `__SIZEOF_POINTER__`, `__LP64__`; `__POINTER_WIDTH__` is clang-only; MSVC has none (use `_WIN64`). The block is the single source of truth — copied verbatim into generated C++/CUDA host preludes and consumed by core.meta.slang/nvrtc/slang-llvm — so keep the whitelist, augment the derivation, and add the symmetric pointer-size `#error`. Triage Bug/low/P3 (latent); hybrid fix (guards first, then compiler-macro-primary + whitelist fallback + `sizeof(void*)` cross-check), draft held for maintainer sign-off on the public header ([slang#12069 endian/ptr whitelist — pointer-size fails silently, endianness fails loudly](../learnings/1783835875827-slang-12069-endian-ptr-whitelist-pointer-size-fail.md)).

A related C-ABI pitfall when appending a field to a versioned struct chain by inheritance (`struct Req_1_3 : public Req_1_2 { newFields; }`, PR #12206): a class with a public base AND its own data members is not standard-layout, so `offsetof(Req_1_3, field)` is only conditionally-supported and fails under `-Werror` (`-Winvalid-offsetof`). Downgrade by base-slicing (`static_cast<const Base&>(derived)`), never `offsetof` or raw reads of the base prefix (base-at-offset-0 is a toolchain property, not a C++ guarantee). The class is still a C++17 aggregate and trivially copyable without user special members; assert `std::is_base_of<B,D>` + `std::is_trivially_copyable_v<D>` — `sizeof(D) > sizeof(B)` does not prove B is a byte-prefix of D ([C++ versioned-struct inheritance: non-standard-layout ≠ non-aggregate; use base-slicing not offsetof](../learnings/1784851897134-c-versioned-struct-inheritance-non-standard-layout.md)).

## The Four CompilerOptionSet Levels (#13847)

Every option-set section below depends on which `getOptionSet()` a caller reads. At 135570a76a (#13847, cmt 6374183569):

1. **Session:** `Linkage::m_optionSet`. Linkage has no accessor; `EndToEndCompileRequest::getOptionSet()` (`slang-end-to-end-request.h:391`) only returns `m_linkage->m_optionSet`.
2. **Target:** `TargetRequest::getOptionSet()`. Its constructor copies the session set (`slang-target.cpp:49`), then `Linkage::addTarget(TargetDesc)` applies the TargetDesc fields (fp/line-directive/scalar-layout only when non-default since #13945, the profile always) and calls `overrideWith(TargetDesc::compilerOptionEntries)` (`slang-session.cpp:187-201`). `getTargetOptionSet()` returns this set.
3. **Component:** `ComponentType::getOptionSet()`. `linkWithOptions` loads its entries here (`slang-linkable.cpp:588`). A Module is seeded with a copy of the session set (`slang-module.cpp:27`), a SpecializedComponentType copies its base's, a composite starts empty.
4. **TargetProgram:** `overrideWith(component)` then `inheritFrom(target)` (`slang-target-program.cpp:19-21`). Codegen reads this set.

Front-end checks such as E36107 in `validateEntryPoint` read level 1, so `linkWithOptions` options never reach them; the precedent for an option the front end needs is `createSession` lifting the highest target DebugInformation level into the session set (`slang-global-session.cpp:878-886`). `EndToEndCompileRequest::TargetInfo::targetOptions` is dead, and `m_optionSetForDefaultTarget` holds slangc options given with no `-target`. DeepWiki's "LinkedComponentType" does not exist; `link()` returns `fillRequirements(this)`, the same object when there are no requirements [four CompilerOptionSet levels; getOptionSet() on the request is the session set](../learnings/1792787652921-slang-has-four-compileroptionset-levels-endtoendco.md).

**TargetDesc defaults and default-target state reach a target per option (#13945, #14103).** Before master `79fa796e` (#13945, after v2026.20), `addTarget` always copied `floatingPointMode`, `lineDirectiveMode` and `forceGLSLScalarBufferLayout`, so a default field reset the session value (render-test's `-Xslang -floating-point-mode -Xslang precise` did nothing). Now a default field keeps the session value, a non-default one wins, the target's `compilerOptionEntries` override both, and a `*_DEFAULT` entry forces the compiler default on one target; users on v2026.20 or older should set these per target. #13945 added 17 lines near `slang.h:4446`, so later `slang.h` citations shift by +17 [a default TargetDesc no longer resets session options](../learnings/1793348689215-slang-13945-a-default-targetdesc-no-longer-resets-.md). The profile is still set unconditionally (`optionSet.setProfile(Profile(desc.profile))`, `slang-session.cpp:201`): a session-level `-profile spirv_1_6`, serialized by `IGlobalSession::parseCommandLineArguments` from `m_optionSetForDefaultTarget` (`slang-global-session.cpp:1177`), is overwritten by a `TargetDesc` with `SLANG_PROFILE_UNKNOWN` and the SPIR-V version word stays `0x00010500`, while a session fp mode survives. The deprecated `ICompileRequest` path keeps both via `_completeTargetRequest` → `inheritFrom(m_optionSetForDefaultTarget)`, and `-profile a -profile b` with no target is caught only by E00042, because the conflict loop visits only `m_rawTargets` [session-level -profile never reaches API targets](../learnings/1793405396040-session-level-profile-from-parsecommandlineargumen.md). That split decided PR #14111: gating both E00042 and E00044 (`…IgnoredBecauseNoTargets`) on `m_isCommandLineCompile` because "API callers keep default-target state" was right for fp mode and wrong for the profile, and hid conflicting profiles (last wins) and a profile implying no target. slang-reviewer caught it (B1) by probing the emitted SPIR-V version; E00042 stayed ungated. Before relaxing an "option ignored" diagnostic for a path, name each option's consumer on it, quote the line that keeps or overwrites it, and check the observable output; a 30-line probe against `libslang.so` (parse → `createSession` → `getEntryPointCode` → SPIR-V word 1) settles one option [trace each option's API consumer](../learnings/1793406411725-trace-each-option-s-api-consumer-before-gating-sib.md).

## CompilerOptionSet::buildHash Drops the Second Integer Operand (#12270)

`CompilerOptionSet::buildHash`'s `Int` branch appends only `v.intValue`, never `v.intValue2` — unlike the `String` branch, which appends both. Four options pack a second int into `intValue2` (`-fvk-bind-globals <index> <set>`, `VulkanBindShift`/`BindShiftAll`, `-trace-coverage-binding <index> <space>`) and all change emitted code, so they collide on the key feeding BOTH the shader cache and `.slang-module` freshness. One-line generic fix (`builder.append(v.intValue2)`); the regression lives in slang-unit-test because `buildHash` is API-path only ([buildHash Int branch drops intValue2 — multi-integer options collide on cache key](../learnings/1785350469856-buildhash-int-branch-drops-intvalue2-multi-integer.md)).

## getEntryPointHash Omits a Linked Component's Own Option Set (#13197 / PR #13215)

Same class as #12270. `IComponentType::getEntryPointHash()` returned the same hash after `linkWithOptions` with different `-Xnvrtc --gpu-architecture=` args, so a shader cache could serve code for another target. `linkWithOptions` deposits `DownstreamArgs` into the linked component's own `m_optionSet` (`slang-linkable.cpp:557`), which drives codegen (`TargetProgram` ctor `overrideWith` → `getDownstreamArgs`), but `ComponentType::getEntryPointHash` (one non-virtual impl) never hashed it: only `Module::buildHash` hashes its own option set; `CompositeComponentType`/`SpecializedComponentType::buildHash` only recurse, and `EntryPoint`/`RenamedEntryPointComponentType` hash nothing. Fix: `getOptionSet().buildHash(builder);` in `getEntryPointHash` (`slang-linkable.cpp:315`). DeepWiki wrongly claimed the args were already hashed — verify against the actual `buildHash` overrides ([getEntryPointHash omits a component's own link-time option set — only Module::buildHash hashes its options](../learnings/1790001366182-getentrypointhash-omits-a-component-s-own-link-tim.md)). Review of PR #13215 confirmed: `CompilerOptionSet::buildHash` DOES hash `DownstreamArgs` (string path, not subject to the intValue2 bug); the added line is a strict no-op only for an empty-set composite, and for a plain `Module` it re-hashes already-hashed bytes — harmless, it can only add misses, never a false hit; a nested `linkWithOptions` inside a further composite still contributes nothing (a `// TODO`, consistent because codegen also reads only `this`'s set) ([PR #13215 review confirms buildHash captures DownstreamArgs; Module re-hash is harmless](../learnings/1790048442419-getentrypointhash-link-time-downstreamargs-fix-con.md)).

**Test on a target the option affects.** A first draft used `SLANG_SPIRV` with `-Xnvrtc …`, which SPIR-V never routes to nvrtc, so asserting distinct hashes would lock in a spurious miss (cf. the `..DoesNotAffectCompilerOptionHash` tests); `SLANG_PTX` makes the arg a real codegen input. Tests are GPU-free and API-path only, in `tools/slang-unit-test/unit-test-stdin-compile.cpp`, reusing `_getOptionEntryPointHash`/`_blobContentEquals` ([test a getEntryPointHash/cache-key change with the target the option actually affects (PTX for nvrtc, not SPIRV)](../learnings/1790049157547-test-a-getentrypointhash-shader-cache-key-change-w.md)). The right target is not sufficient: `getEntryPointHash` only builds a digest, so any differing option string changes the hash, and the toggled option must (a) pass to the downstream tool unmodified and (b) really change codegen for the fixture. On #13197 nvrtc `--gpu-architecture=compute_75` vs `compute_120` clashes with the `-arch=compute_*` Slang injects (`slang-nvrtc-compiler.cpp`, DownstreamArgs appended after), and dxc `-Od` vs `-O3` collapses because Slang appends `-O1` last and DXC honors the last opt flag. Good pairs: nvrtc `--fmad=false`/`true` with a FLOAT multiply-add in the fixture; dxc `-Gfa`/`-Gfp` with a data-dependent branch (`-Gfa` on SM 5.1+ also needs `-all_resources_bound`). A `DownstreamArgs` argline splits on newline (`CommandLineArgs::deserialize` → `StringUtil::split(content, '\n')`), so two dxc args are `"-Gfa\n-all_resources_bound"`. Give such a test a dedicated fixture and have codex compile both arg sets to confirm the output differs ([testing that link-time downstream args affect getEntryPointHash — avoid spurious-miss args](../learnings/1790100487907-testing-that-link-time-downstream-args-affect-gete.md)).

## DownstreamArgs Don't Compose Across Option-Set Levels — and Must Never Be Deduped by Value (#13436)

`CompilerOptionSet::add(name, List, replaceDuplicate)` (`slang-compiler-options.h:140-173`) decides "already present" by `stringValue`, which for `DownstreamArgs` is the TOOL NAME, so any two entries for one tool match: `overrideWith` (replace=true) overwrites the first entry once per incoming entry (last wins), `inheritFrom` (replace=false) skips. Only a destination with no `DownstreamArgs` gets the list verbatim — why one level composes (#12861/#12900) but session/target/link do not (`Linkage::addTarget` session→target; `TargetProgram` ctor link→target). DeepWiki wrongly says they concatenate [tool-name match blocks composition](../learnings/1791192233228-downstreamargs-never-compose-across-option-set-lev.md). The tempting fix — concatenate and elide exact `(tool, args)` duplicates, since the session set re-arrives (`TargetRequest` ctor copies `linkage->m_optionSet` at `slang-target.cpp:32`, a Module at `slang-module.cpp:27`, then `addTarget`/slangc `inheritFrom(session)` again at `slang-session.cpp:188` / `end-to-end-request.cpp:170,1328`) and NVRTC 12.6 rejects a repeated `--fmad`/`--gpu-architecture` — is WRONG, because an entry is not an argument. SlangPy adds one entry per token (`shader.cpp` ~383-386 session, ~1635-1638 link), so `[-D, FOO=1, -D, BAR=2]` dedups to `-D FOO=1 BAR=2` and NVRTC fails "unrecognized option BAR=2" [value dedup breaks SlangPy](../learnings/1791207821835-value-based-dedup-of-downstreamargs-breaks-slangpy.md). No value rule can tell "same level arrived twice via a copy" from "user repeated an arg", and slangc's trailing-`\n`-per-arg serialization (`CommandLineArgs::serialize`) vs the API's raw storage makes `stringValue2` equality miss equivalent entries anyway [no value rule separates copy from repeat](../learnings/1791208144324-slang-downstreamargs-never-dedup-by-value-across-o.md). **Principled fix: provenance — each level stores only its own args, compose ONCE at the consumption point, concatenate with no dedup.** Every probe matrix for a merge rule must include a split-token repeated flag (`-D x -D y` as separate entries) beside joined `--flag=value` cases — the triage prototype passed every joined probe and broke on this [never dedup by (tool, args)](../learnings/1791208289552-slang-downstreamargs-never-dedup-entries-by-tool-a.md). A GPU-free NVRTC probe: `--fmad=false` at one level, an arch flag at another, compile `o[0]=o[1]*o[2]+o[3]` to PTX, check for `fma.rn` and the `.target sm_NN` line.
