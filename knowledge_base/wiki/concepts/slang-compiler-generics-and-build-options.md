# Slang Compiler: Generics Memoization & Build Options

This page covers compile-time performance of nested generics (missing substitution/conformance memoization and its own shallow-generic trade-off), the blast radius of flipping the default `-g` debug level, dead weight in module-serialization dependency loading, and two platform/build-option correctness bugs (endianness-vs-pointer-size asymmetry and a hash that drops an operand).

## TL;DR
- Discipline unchanged: fix the producer, not the consumer; assert out-of-contract shapes rather than guard them. `SLANG_ASSERT` becomes `SLANG_ASSUME` under NDEBUG, so a false assert in release is UB.
- Before citing an internals behaviour, read it at a named ref — several entries here started from a premise that was false.
- Nested generic calls `wrap(wrap(...wrap(x0)...))` grow compile time EXPONENTIALLY in nesting depth. Root cause: NO memoization of the substitution/conformance work each level redoes — interning keys on operand POINTER identity (so structurally-identical substituted types at different levels miss the cache) and the subtype-witness cache is GENERATION-GATED (so mid-computation substituted types bypass it and re-prove `Wrapper<T>:IModel` per level → multiplicative blowup).
- The memoization fix converts exponential → linear only on a SHARED DAG; on a shallow TREE (each Val visited once) the `SubstitutionCache` is 100% miss → pure per-op overhead (Dictionary alloc + double-hash), a flat ~10-15% shallow-generic regression. Gating/shrinking the cache is always correctness-safe — a pure speed/space trade.
- A perf confound that "can't be separated from the aggregate data" is often separable by CODE-PATH analysis: check a workload's invocation MODE (`mode="module"` vs `IEntryPoint::specialize`), not just its name.
- Flipping the DEFAULT `-g` None→Minimal has a blast radius far beyond "adds SPIR-V debug names": it silently changes TEXTUAL codegen (side-effecting `IRDebugLine` suppresses folding → multi-temp HLSL/GLSL/CUDA/Metal) and exposes a masked strip-condition gap (`== None` only) → 19 VM hard crashes + ~32 golden diffs. A default enum value can mask a code-vs-comment gap for years; a hard `SLANG_UNIMPLEMENTED` default arm weaponizes any newly-surviving inst class into a crash.
- `loadSerializedModuleContents`'s eager per-dep content load is DEAD WEIGHT on the load path — only dependency PATHS feed real consumers, and the staleness check runs its OWN digest loop over the serialized RIFF chunk. Always disambiguate `moduleChunk->getFileDependencies()` (serialized chunk) from `module->getFileDependencies()` (in-memory list from the loop).
- `include/slang.h` derives endianness AND pointer size from one arch whitelist, but the failure modes are ASYMMETRIC: endianness `#error`s on an unlisted arch, pointer size silently evaluates 32-bit → public-ABI corruption with no error on rv64/LoongArch64/s390x/MIPS64.
- `CompilerOptionSet::buildHash`'s Int branch drops `intValue2`, so four multi-integer options collide on the cache key feeding BOTH the shader cache and `.slang-module` freshness.

## Exponential Compile Time With Generic Nesting Depth — Missing Substitution/Conformance Memoization (#12100/#12103/#12139)

Nested generic calls `wrap(wrap(...wrap(x0)...))` (where `Wrapper<T> wrap<T:IModel>(T v)` and `struct Wrapper<T:IModel>:IModel`) grow compile time *exponentially* in nesting depth (REPRODUCED on ToT @3eeda847c debug slangc: depth 8≈3.1s → 12≈11.7s → 14≈72s → 16 timeout; same class for `typealias Pair` chains and associated-type `T.Next.Next...` chains). Root cause (hypothesis — code trace + DeepWiki, NOT profiled): NO memoization of the substitution/conformance work each level redoes for all inner levels. The type-check flow per call (`ResolveInvoke` slang-check-overload.cpp:3375 → `inferGenericArguments` :2866 → `trySolveGenericArguments` slang-check-constraint.cpp:3406 → `buildSubstDeclRef` :2777) re-descends and re-substitutes the whole `Wrapper<Wrapper<...>>` tree at every layer: `DeclRefType::_substituteImplOverride` (slang-ast-type.cpp:152-213) and `GenericAppDeclRef::_substituteImplOverride` (slang-ast-decl-ref.cpp:482) do not memoize; `GenericAppDeclRef` IS interned via `ASTBuilder::getOrCreate` but the `ValKey` keys on operand POINTER identity, so structurally-identical substituted types at different levels are pointer-distinct and miss the cache; and the subtype-witness cache (`SharedSemanticsContext::m_mapTypePairToSubtypeWitness`, slang-check-inheritance.cpp:95-137) is GENERATION-GATED (only caches when both endpoints' inheritance-info generations are non-zero) so mid-computation substituted types bypass it and `Wrapper<T>:IModel` is re-proven per level → multiplicative blowup. **Distinct** secondary facet: plain non-generic `f(f(...f(x)...))` at ~200 deep hits `E39997 maximum type nesting level exceeded` — that is `kMaxTypeNestingDepth=128` (slang-check.h:21), a type-STRUCTURE traversal guard (not a call-depth counter), fine at 128. The >80x v2026.5→v2026.8 regression (constant-factor ~7x jump at depth 16) primary suspect (in-window VERIFIED via `git merge-base --is-ancestor`, NOT profiled): **#9808 "Refactor auto-diff implementation"** (`45ccce9a3`) — the largest front-end change in the 111-commit range, touching every per-level hot-path file; decisive proof step is a first-parent bisect `45ccce9a3^` vs `45ccce9a3` on the depth-16 repro. Disposition: reporter jvepsalainen-nv (NVIDIA contributor) self-assigned and authors PR #12086 (the compile-perf depth-axis benchmark suite this feeds), so parent parked HOLD-for-assignee, no fixer dispatch (high-blast-radius core-substitution refactor + unprofiled regressor + owner-driven workstream; same pattern as #12096). Repo has a native **Performance** Issue Type (`IT_kwDOAb2kZs4BlAhg`) — use it for compile-time/runtime perf bugs; GraphQL `updateIssue`/`addLabelsToLabelable`/`addComment` mutations work even when a bot's REST write 403s, but `addLabelsToLabelable` needs the label IDs INLINE in the query string ([slang#12100 exponential generic-nesting compile time: missing substitution/conformance memoization; >80x regression from #9808](../learnings/1784054268864-slang-12100-exponential-generic-nesting-compile-ti.md)). The follow-up guard-workloads issue #12103 (adds depth-axis workloads to the compile-perf tracker to guard #12100's regressions) is doubly not-for-a-fixer: (1) self-filed AND self-assigned by the same owner, (2) a hard merge-order block — it stacks on the still-OPEN PR #12086 and edits the SAME files (`tools/compile-perf/lib/manifest.py` + `lib/workloads.py`), so it must land AFTER #12086 or conflict. Triage value-add when you can't/shouldn't fix: validate the proposed design against the live schema — the compile-perf workload schema (`manifest.py:28-78`, `WorkloadSpec`) has the invariant `default_size` MUST be in `sweep_sizes` (manifest.py:539-541); all 5 proposed workloads pass, turning a bare park into an actionable green light. Confirm a merge-order dependency concretely with `gh pr view <n> --json files --jq '.files[].path'` rather than asserting it, and don't assume a referenced workload is in-tree — the three #12086 workloads (`generic_nesting`/`generic_nesting_eval`/`interface_depth`) are ABSENT on master, only added by the open PR ([slang#12103 compile-perf depth-workload follow-up — hold for self-assigned owner, merge-blocked on #12086](../learnings/1784056143534-slang-12103-compile-perf-depth-workload-follow-up-.md)).

The #12100 memoization fix (PR #12106, "Memoize shared Val and type DAG traversals", commit c8d02ae59) that killed the exponential deep-generic blowup then produced its own ~10-15% flat SHALLOW-generic regression (#12139). The mechanism explains the trade-off directly: `SubstitutionCache` (`slang-ast-substitution.h:16-60`) is a `Dictionary<Key,Result>` heap-constructed fresh per top-level substitution op, with a `tryGet` + on-miss `add` (two hashes) per node. On a TREE (each Val visited once) it is 100% miss → pure overhead (per-op Dictionary alloc + double-hash + wasted insert); only on a SHARED DAG (the #12100 shape, inner type recurring as both generic-arg and conformance-witness) does it convert exponential to linear. Reviewer audits confirmed the memo is semantics-preserving, so gating/shrinking the cache is always correctness-safe — a pure speed/space trade (fix directions: inline-buffer-cache-with-Dictionary-promotion, pool/reuse the cache across ops, or a *work*-based — not static-depth — guard; static depth risks re-introducing #12100 on a shallow-looking heavily-shared DAG). The reusable methodology lesson: a perf confound that "can't be separated from the aggregate data" is often separable by CODE-PATH analysis — the reporter worried #12139's `interface_depth` +40% outlier was inseparable from co-window PR #12052 (`-specialize` conformance visibility), but reading `tools/compile-perf/lib/manifest.py` shows `interface_depth`/`generic_nesting`/`generic_nesting_eval` all use `mode="module"` while only `rt_renderer_specialize`/`api_specialize` invoke `IEntryPoint::specialize` — the SOLE path #12052 touches. A commit gated behind a rarely-used entry point cannot tax workloads that never hit it, so #12052 is exonerated and the outlier is #12106's territory: check the workload's invocation MODE, not just its name ([slang#12139 — resolving a two-commit perf confound by workload trigger-path (#12106 memo vs #12052 -specialize)](../learnings/1784270455318-slang-12139-resolving-a-two-commit-perf-confound-b.md)).

## Flipping the Default `-g` Level: Textual-Codegen Fallout + a Masked Strip Gap

slang#11682 flips the DEFAULT debug level `None`→`Minimal`, and the blast radius is far wider than "adds SPIR-V debug names." **(1) It silently changes TEXTUAL codegen (folding), not just SPIR-V.** At Minimal+, `maybeEmitDebugLine` emits `IRDebugLine` insts through function bodies; `kIROp_DebugLine.mightHaveSideEffects()` returns true, so `shouldFoldInstIntoUseSites` refuses to fold across it and the C-like emitter materializes temporaries — folded chains become multi-temp assignments across HLSL/GLSL/CUDA/Metal. Sweep the non-SPIR-V goldens too ([slang debug -g level silently changes TEXTUAL codegen (folding)](../learnings/1784443119965-slang-debug-g-level-silently-changes-textual-codeg.md)). **(2) It exposes a masked strip-condition gap.** `slang-emit.cpp` strips debug info only when the level `== None`, though its comment claims two conditions (incapable target OR `-g0`); while the default *was* `None` every compile hit the strip, hiding the missing "debug-incapable target" arm. Once Minimal is the default, `IRDebugLine` survives into targets that can't consume it, producing 19 VM/bytecode HARD crashes (`slang-emit-vm.cpp` default arm is `SLANG_UNIMPLEMENTED`) plus ~32 textual golden diffs. The right predicate is `!isSPIRV && !isCPUTargetViaLLVM` (both SPIR-V and CPU/LLVM genuinely express debug info — a bare `!isSPIRV` wrongly strips DWARF). Meta-lessons: a default enum value can mask a code-vs-comment gap for years, and a hard `SLANG_UNIMPLEMENTED` default arm weaponizes any newly-surviving inst class into a crash ([flipping default -g exposes a masked strip-condition gap → VM crashes + codegen churn](../learnings/1784443743816-slang-flipping-default-g-exposes-a-masked-strip-co.md)).

## loadSerializedModuleContents Dep-Loop Content Is Dead Weight; Up-to-Date Check Is Independent (#9400)

Triaging slang#9400 (module serialization / file-dependency tracking) @HEAD 6a244fee2: the dependency-loading loop in `Linkage::loadSerializedModuleContents` (`slang-session.cpp:2248`) eagerly `loadSourceFile`s (materializes full text) every dep of a loaded `.slang-module`, but on the load path that content is DEAD WEIGHT — verified empirically (a module compiles to GLSL fine with the original `.slang` source deleted). Only dependency PATHS feed real consumers: the load-path digest is chunk-copied not recomputed, and the `UseUpToDateBinaryModule` staleness check `isBinaryModuleUpToDate` does its OWN loadSourceFile+digest loop reading the serialized RIFF chunk — it does NOT read the in-memory list the loop populates, so removing the loop would NOT break up-to-date checking. CRITICAL DISTINCTION a code-reader subagent got wrong: `moduleChunk->getFileDependencies()` (serialized RIFF chunk, always present) ≠ `module->getFileDependencies()` (in-memory list from the loop) — always disambiguate `moduleChunk->` vs `module->`, and verify load-bearing subagent claims by reading the two call sites yourself. (Missing-snippet from precompiled modules — `error 36107` prints `(0)` — is a SEPARATE mechanism: deserialized SourceViews are built from empty-content SourceFiles, so the loaded content never reaches diagnostics.) Maintainer tangent-vector called this whole path/source-loc subsystem "rotten to its core" and wants a first-principles redesign → parked for jkwak-work, no auto-fixer ([slang#9400: loadSerializedModuleContents dep-loop content is dead weight; up-to-date check is independent](../learnings/1784654116315-slang-9400-loadserializedmodulecontents-dep-loop-c.md)).

## slang#12069: Endianness Fails Loudly, Pointer Size Fails Silently

In `include/slang.h`, endianness and pointer size are both derived from an architecture whitelist (`SLANG_PROCESSOR_X86_64|ARM_64|POWER_PC_64`), but their failure modes are ASYMMETRIC. Endianness has a guard (`#if ((SLANG_BIG_ENDIAN | SLANG_LITTLE_ENDIAN) == 0) #error`) so an unlisted arch fails the build loudly; pointer size has NO such guard — `SLANG_PTR_IS_32 = (SLANG_PTR_IS_64 ^ 1)`, so on any 64-bit arch NOT whitelisted (RISC-V rv64, LoongArch64, s390x, MIPS64), `SLANG_PTR_IS_32` silently evaluates to 1 → `SlangInt`/`SlangUInt` become 32-bit on a 64-bit target → public-ABI/struct-layout corruption with no error. That silent miscompile is the load-bearing bug, not the cosmetic "use compiler macros" ask. Verified: gcc & clang predefine `__BYTE_ORDER__`, `__SIZEOF_POINTER__`, `__LP64__`; `__POINTER_WIDTH__` is clang-only; MSVC provides none (use `_WIN64`). The detection block is the single source of truth — copied verbatim into generated C++/CUDA host preludes and consumed by core.meta.slang/nvrtc/slang-llvm — so don't remove the whitelist, only augment the derivation and add the symmetric pointer-size `#error`. Triage: Bug / low / P3 (latent — no supported target affected); hybrid fix (guards first, then compiler-macro-primary + whitelist fallback + `sizeof(void*)` cross-check), draft held for maintainer sign-off on the public ABI header ([slang#12069 endian/ptr whitelist — pointer-size fails silently, endianness fails loudly](../learnings/1783835875827-slang-12069-endian-ptr-whitelist-pointer-size-fail.md)). A related C-ABI-layout pitfall when appending a field to a *versioned* struct chain via inheritance (e.g. `struct Req_1_3 : public Req_1_2 { newFields; }`, as in PR #12206): a class with a public base AND its own data members is **not standard-layout**, so `offsetof(Req_1_3, field)` is only conditionally-supported and FAILS under `-Werror` (`-Winvalid-offsetof`) — do cross-version downgrades by base-slicing (`static_cast<const Base&>(derived)`), never `offsetof` or raw byte reads of the base prefix (base-at-offset-0 is a real-toolchain ABI property, not a C++ guarantee). Such a class IS still an aggregate in C++17 (public base allowed) and stays trivially copyable if no user special members are added, so assert the relationship with `std::is_base_of<B,D>` + `std::is_trivially_copyable_v<D>` — `is_trivially_copyable` + `sizeof(D) > sizeof(B)` do NOT prove B is a byte-prefix of D ([C++ versioned-struct inheritance: non-standard-layout ≠ non-aggregate; use base-slicing not offsetof](../learnings/1784851897134-c-versioned-struct-inheritance-non-standard-layout.md)).

## CompilerOptionSet::buildHash Drops the Second Integer Operand (#12270)

**`buildHash` drops the second integer operand (#12270).** `CompilerOptionSet::buildHash`'s `Int` branch appends only `v.intValue`, never `v.intValue2` — asymmetric with the `String` branch (which appends both). Four options pack a second int into `intValue2` (`-fvk-bind-globals <index> <set>`, `VulkanBindShift`/`BindShiftAll`, `-trace-coverage-binding <index> <space>`) and all change emitted code, so they collide on the cache key that feeds BOTH the shader cache and `.slang-module` freshness. One-line generic fix (`builder.append(v.intValue2)`); regression lives in slang-unit-test (`buildHash` is API-path, not `.slang`-reachable) ([buildHash Int branch drops intValue2 — multi-integer options collide on cache key](../learnings/1785350469856-buildhash-int-branch-drops-intvalue2-multi-integer.md)).
