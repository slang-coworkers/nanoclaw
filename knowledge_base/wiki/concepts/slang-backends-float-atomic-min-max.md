# Slang float atomic min/max across targets

`InterlockedMin`/`InterlockedMax` (and `Atomic<T>.reduceMin/Max`) accept any `T : IArithmeticAtomicable`, including `float`, `half` and `double`, and the front end lowers all of them to the same `kIROp_AtomicMin`/`kIROp_AtomicMax`. Each target then handles the float case on its own, and several did not. This page records the per-target state found while triaging #14026, the semantics a correct implementation has to match, and what the CUDA prelude implementation (PR #14048) learned about correctness and speed. Float atomic-add capability gating on SPIR-V is on [[wiki/concepts/slang-backends-f0909b0-spirv-capabilities.md]].

## TL;DR

- **Float min/max reach each emitter as plain `kIROp_AtomicMin/Max`**, so every target needs its own float handling. Direct SPIR-V is correct (`OpAtomicFMinEXT`/`OpAtomicFMaxEXT`); Metal reports E55204 (`diagnoseFloatAtomic`).
- **GLSL requests the wrong extension:** `requireAtomicExtIfNeeded` asks for `GL_EXT_shader_atomic_float` without looking at the op; min/max need `GL_EXT_shader_atomic_float2`, whose mapping already exists in `glsl.meta.slang`.
- **HLSL diagnoses too little:** `diagnoseFloatAtommic` covers only Add/Sub, and only `kIROp_FloatType`.
- **CUDA has no `atomicMin(float*)`**, and before #14048 the prelude's `__slang_atomic_reduce_min/max` were integer-only, so `Atomic<float>.reduceMin` failed as well.
- **The semantics to match are `OpAtomicFMinEXT`'s:** a NaN operand is ignored, a stored NaN is replaced, and either sign of zero may win (`-0.0 < +0.0` in integer order is allowed).
- **A CAS loop must decide by comparison and write the operand's own bits.** `replace = isnan(stored) ? !isnan(val) : (isMin ? val < stored : val > stored)`; never CAS in the bits of `fminf(old, val)`, which under `--use_fast_math`/FTZ returns a flushed 0 for a subnormal stored value and overwrites a value that should have won.
- **The early exit is what makes a CAS loop fast:** load, and return without writing if the stored value already wins. Most reduction updates lose, so most threads never issue an atomic.
- **A sign-split integer atomic tests the sign BIT** (`__float_as_int(v) >= 0`), not `v >= 0`; with `v >= 0`, `-0.0` takes the signed-min path as `INT_MIN` and overwrites stored negatives. Positive values use signed `atomicMin`, negative values unsigned `atomicMax` (mirrored for max).
- **A sign-split atomic without an early exit is SLOWER than the early-exit CAS loop** (2-10x) when its return value is used. Only when the result is unused does ptxas turn it into `RED` + `REDUX` warp aggregation, which is 5-14x faster.
- **A naive sign-split is not exact:** it keeps a stored +NaN under max and a stored -NaN under min, which `OpAtomicFMinEXT` requires replacing. The best exact form is: load, ignore a NaN operand, CAS-replace a stored NaN, early exit, one sign-split atomic, then check the returned original for a NaN stored concurrently and retry via CAS. It is about 2x faster than the CAS loop.
- **Half has no 16-bit integer `atomicMin/Max` in CUDA**, so it needs the CAS loop on 16-bit `atomicCAS`. Guard those overloads with `!defined(__CUDA_ARCH__) || __CUDA_ARCH__ >= 700` (CUDA's own `sm_70_rt.h` form) so nvcc's host pass still sees them.
- **NVRTC 12.8+ uses `compute_75` as its arch floor**, so CI (CUDA 13.0.1) cannot observe a `requireSMVersion(7.0)` raise, and a PTX FileCheck on `.target sm_70` breaks there. Check the instruction (`atom.*cas.b16`) instead, and disclose that an SM-raise pin only works on older NVRTC.
- **Repro per target without a GPU:** `slangc -target ptx` (NVRTC), `-target spirv -emit-spirv-via-glsl` (glslang), `-target dxil -profile cs_6_6` (DXC). Read the CUDA result in SASS with `cuobjdump -sass -fun <mangled> | grep -E 'REDUX|RED|ATOMG'`.

## Per-target lowering and emitter gaps (#14026)

At 9b3ac252d, `InterlockedMin/Max<T:IArithmeticAtomicable>` lowers float, half and double straight to `kIROp_AtomicMin/Max`, and the backends diverge from there. Direct SPIR-V emits `OpAtomicFMinEXT` and is correct. Metal rejects the op with E55204 from `diagnoseFloatAtomic`. GLSL's `requireAtomicExtIfNeeded` (`slang-emit-glsl.cpp:3053`) requests `GL_EXT_shader_atomic_float` without looking at the op, although min/max need `GL_EXT_shader_atomic_float2`; the correct mapping is already in `glsl.meta.slang:9414` (`typeRequireChecks_atomic_using_float2_tier`). HLSL's `diagnoseFloatAtommic` (`slang-emit-hlsl.cpp:742`) checks only Add/Sub and only `kIROp_FloatType`, so other float atomics pass undiagnosed. CUDA has no `atomicMin(float*)` overload, and the prelude's `__slang_atomic_reduce_min/max` were integer-only, so `Atomic<float>.reduceMin` failed too. Each target can be checked without a GPU: `-target ptx` runs NVRTC, `-target spirv -emit-spirv-via-glsl` runs glslang, and `-target dxil -profile cs_6_6` runs DXC [Float atomic min/max per target in Slang: emitter gaps and the sign-split -0.0 trap](../learnings/1793291639995-float-atomic-min-max-per-target-in-slang-emitter-g.md).

## Correct CUDA semantics: compare, then write the operand's bits

PR #14048 implements float min/max in the prelude as `__slang_atomic_min_max<T,Bits>`. In its CAS loop the decision is a comparison, `replace = isnan(stored) ? !isnan(val) : (isMin ? val < stored : val > stored)`, and the loop CASes in `val`'s own bits. That form matches `OpAtomicFMinEXT`: a quiet-NaN operand is ignored, a stored NaN is replaced, and either zero may win. It also exits without a write when the stored value already wins. The tempting alternative, CASing in the bits of `fminf(old, val)`, is wrong under `--use_fast_math` or flush-to-zero: `fminf` returns a flushed 0 for a subnormal stored value, so the loop overwrites the value that should have won (verified with nvcc 12.6: a stored `0x00000100` became 0) [CUDA float atomic CAS loop: write the operand's own bits, not fminf's result; guard 16-bit atomicCAS with !defined(__CUDA_ARCH__) || >= 700](../learnings/1793302322805-cuda-float-atomic-cas-loop-write-the-operand-s-own.md).

The integer "sign-split" trick maps float order onto integer atomics: non-negative floats order like signed integers and negative floats order in reverse like unsigned integers, so min uses signed `atomicMin` for non-negative values and unsigned `atomicMax` for negative ones (mirrored for max). The branch must test the sign bit, `__float_as_int(v) >= 0`, not `v >= 0`: `-0.0 >= 0` is true, so `-0.0` takes the signed path as `INT_MIN` and overwrites stored negative values [Float atomic min/max per target in Slang: emitter gaps and the sign-split -0.0 trap](../learnings/1793291639995-float-atomic-min-max-per-target-in-slang-emitter-g.md). A naive sign-split also keeps a stored +NaN under max and a stored -NaN under min, which `OpAtomicFMinEXT` requires replacing, so an exact version needs NaN repair around the integer atomic [CUDA float atomic min/max: early-exit + sign-split integer atomic beats a CAS loop ~2x; a sign-split without early exit is SLOWER; void form becomes red+REDUX](../learnings/1793323309178-cuda-float-atomic-min-max-early-exit-sign-split-in.md).

## Performance: the early exit matters more than the atomic

Measured on the L40S (nvcc 12.6, sm_89, 64K-256K threads updating 6 shared words) for #14048: a CAS loop with an early exit (load, return if the stored value already wins) is fast because most reduction updates lose. A sign-split integer atomic that always issues the atomic and uses its return value is 2-10x slower than that CAS loop. If its result is unused, ptxas turns it into `RED` + `REDUX` (warp aggregation) and it is 5-14x faster than the CAS loop, but an exact implementation must read the return value. The best exact form found is: load, ignore a NaN operand, `atomicCAS`-replace a stored NaN, early exit, one sign-split atomic, then check the returned original for a NaN that another thread stored concurrently and the integer atomic kept, and retry that case via CAS. It is 1.7-2.1x faster than the CAS loop for float and 1.6-2.0x for double, and equal on all-equal data; because the post-check reads the return value, the `RED`/`REDUX` path (another 2-3x) is lost. Read the generated code with `cuobjdump -sass -fun <mangled> | grep -E 'REDUX|RED|ATOMG'` [CUDA float atomic min/max: early-exit + sign-split integer atomic beats a CAS loop ~2x; a sign-split without early exit is SLOWER; void form becomes red+REDUX](../learnings/1793323309178-cuda-float-atomic-min-max-early-exit-sign-split-in.md).

## Half: CAS loop only, and SM gating that CI cannot see

CUDA has no 16-bit integer `atomicMin/Max`, so half min/max needs the CAS loop over 16-bit `atomicCAS`, which exists only on sm_70 and later. Guard those overloads with `!defined(__CUDA_ARCH__) || __CUDA_ARCH__ >= 700`, the condition CUDA's own `sm_70_rt.h` uses. The stricter `defined(__CUDA_ARCH__) && ...` form, which the existing prelude vector-half `atomicAdd` guard (~line 912) uses, hides the overloads from nvcc's host pass, so offline nvcc builds fail with "no instance of overloaded function" [CUDA float atomic CAS loop: write the operand's own bits, not fminf's result; guard 16-bit atomicCAS with !defined(__CUDA_ARCH__) || >= 700](../learnings/1793302322805-cuda-float-atomic-cas-loop-write-the-operand-s-own.md), [CUDA float atomic min/max: early-exit + sign-split integer atomic beats a CAS loop ~2x; a sign-split without early exit is SLOWER; void form becomes red+REDUX](../learnings/1793323309178-cuda-float-atomic-min-max-early-exit-sign-split-in.md).

The emitter's matching `requireSMVersion(SemanticVersion(7,0))` cannot be pinned by a test on CI. NVRTC 12.8 and later use `compute_75` as the arch floor, `requireSMVersion` only ever raises the arch, and the GPU CI image is CUDA 13.0.1, so a test of the raise passes with or without it there; only a local NVRTC 12.6 catches a missing raise. A PTX FileCheck on `.target sm_70` breaks outright on NVRTC 12.8+, so check the instruction (`atom.*cas.b16`) instead, and say in the test comment and the PR description that the SM pin only works on older NVRTC [CUDA float atomic CAS loop: write the operand's own bits, not fminf's result; guard 16-bit atomicCAS with !defined(__CUDA_ARCH__) || >= 700](../learnings/1793302322805-cuda-float-atomic-cas-loop-write-the-operand-s-own.md), [NVRTC ≥12.8 defaults to compute_75, so CUDA SM-raise tests below sm_75 are not observable on CI](../learnings/1793305652591-nvrtc-12-8-defaults-to-compute-75-so-cuda-sm-raise.md). The per-version floors and the general arch-selection rules are on [[wiki/concepts/slang-backends-cuda-cpp.md]].
