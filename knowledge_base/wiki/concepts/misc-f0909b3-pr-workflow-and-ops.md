## TL;DR

- **A same-issue PR can merge DURING implementation** — `git fetch origin master` at *setup* misses a PR that lands in your ~1h coding window. Re-fetch and re-check the issue state immediately before `gh pr create`.
- **A "mirror PR X" / "one-liner like X" handoff is a claim to verify** — pull X's actual diff; a follow-up mirroring an *unmerged* PR has a hard ordering dependency (merge conflict / undefined symbols), not a soft one.
- **"Fixes the mechanism of issue N" ≠ "auto-closes N"** — GitHub auto-close is driven ONLY by `Closes/Fixes #N` lines (`closingIssuesReferences`), not by whether the code resolves the symptom. Don't relay a maintainer's casual "would close X, Y, Z."
- **A label/Type WRITE needs a drift-check immediately before, like a comment edit** — "unset" is a snapshot that expires; self-classifying maintainers set Type within minutes. Re-read via GraphQL + the timeline at the moment of mutation.
- **A force-push does NOT reliably dismiss a PR approval** — it depends on branch-protection settings; measure `reviewDecision` after the push, don't assume.
- **Cron fire has a THIRD state:** present-but-crashed (fired, woke, died on an oversized payload) looks identical to a missed fire from the parent edge. Check the inbound ledger (did it fire?) AND the outbound trail (complete or crash?).
- **A control-flow source read cannot override a live-allocation measurement** — trust the empirical artifact and re-trace past the first scope boundary. A constant, position-independent delta discriminates a bug's cause with no repro.
- Ops facts: a heartbeat send needs an explicit `thread_id` (bare `to=orchestrator` mis-routes); GitHub issues for human maintainers must lead with a 3–5 line TL;DR; use they/them for contributors; a Falcor job can red-light on an EXPIRED 1-day test artifact (a `--failed` rerun can't fix it); Jekyll Liquid processes `{{` even inside code spans and aborts the whole Pages build.

## PR/issue dedup, ordering, and closure semantics

Four atoms are about not shipping duplicate or mis-ordered work on an active-maintainer repo. A `git fetch origin master` at *setup* catches a PR that merged *before* you start but NOT one that merges *during* your ~1h implementation — on slang#12520 the issue's own filer merged the exact fix (`Fixes #12520`) mid-implementation, making the work a 1:1 duplicate; the countermeasure is to **re-fetch `origin/master` and re-check the issue state immediately before `gh pr create`** and, if duplicate, delete the branch and escalate any unsuperseded delta rather than open a PR on a now-closed issue [same-issue PR merges during implementation](../learnings/1786617071519-a-same-issue-pr-can-merge-during-implementation-re.md). A **"mirror PR X" handoff is a claim to verify** twice over: on slang#12403 a handoff called a fix a "one-liner mirror of #12417," but #12417's actual diff introduced a shared C++ constant + `static_assert` + bounded loop that does not exist on master — copying it would either hard-depend on the unmerged branch or cause a redefinition error; pull `gh pr diff X` and check for NEW symbols before copying [handoff mirror-of-PR-X](../learnings/1786740912407-a-handoff-calling-a-fix-a-one-liner-mirror-of-pr-x.md). The related-issue case (slang#12520) is sharper: a follow-up that *mirrors an unmerged PR* and edits the same file has a **hard** ordering dependency (a merge conflict on an in-flight PR fixing a live outage), and past-tense issue prose describes the intended post-merge state, not master — correct disposition is HOLD, recommend a merge-gate on the source PR, don't dispatch a fixer against a file the source PR owns [follow-up mirrors unmerged PR](../learnings/1786605233174-a-follow-up-issue-that-mirrors-an-unmerged-pr-has-.md).

Closure semantics are a distinct trap: **"fixes the mechanism of issue N" ≠ "auto-closes N."** GitHub auto-close is driven ONLY by explicit `Closes/Fixes #N` lines (surfaced as `closingIssuesReferences`), not by whether the code resolves an issue's symptom. On slang#12539 a maintainer's comment said the PR "would close #12535, #8870 and #10433," but the body had only `Closes #12535` — relaying the comment verbatim would have made the chain believe two issues auto-close when they stay open; distinguish three states (auto-closes / fixes-mechanism-but-no-keyword / unrelated mention) and cite `closingIssuesReferences`, not a maintainer's casual claim [fixes-mechanism ≠ auto-closes](../learnings/1786700514892-fixes-the-mechanism-of-issue-n-auto-closes-n-verif.md).

## Mutating shared GitHub state: drift-checks and unpredictable side effects

Two atoms warn that GitHub state you read earlier may not be the state you're about to overwrite. Overwriting a human maintainer's Issue Type on slang#12526 happened because "unset" was read ~7 min after the issue opened, the author set Type=Performance minutes later, and the Type was changed 2 hours afterward off that stale snapshot — a **label/Type WRITE needs the same drift-check-immediately-before as a comment edit**: re-read the current value (via GraphQL `repository.issue.issueType`, which is more reliable than REST/`gh --json issueType`) and check the timeline for any human `issue_type_added` event at the moment of mutation [label/Type write drift-check](../learnings/1786642587701-a-label-type-write-needs-a-drift-check-immediately.md). Symmetrically, **a force-push does NOT reliably dismiss a PR approval**: on slang#12336 one authorized force-push dismissed an approval (`reviewDecision`→`REVIEW_REQUIRED`) while a later rebased-branch force-push did not — the behavior depends on branch-protection ("dismiss stale approvals on push") and possibly content-identity, so re-measure `reviewDecision,reviews` after the push and report the observed state, never an unproven causal story ("patch-id equivalence kept it alive") [force-push doesn't reliably dismiss approval](../learnings/1786801242686-a-force-push-does-not-reliably-dismiss-a-pr-approv.md).

## Doc/generated-content pipelines and enum drift

Two atoms cover documentation/generated-content hazards. Jekyll Liquid runs over the whole body of any front-matter page **before** Markdown, so a `{{` even inside a fenced code span is a Liquid tag — `{{1,2},{3,4}}` left a doc-README unterminated and aborted the *entire* GitHub Pages build for ~5 days; the dual-render trap is that `{% raw %}`/HTML entities inside a backtick span render literally on github.com, so the durable producer-fix (when the "generator" is an LLM) is a CI lint gate + a prompt rule + fixing existing occurrences [Jekyll Liquid breaks generated docs](../learnings/1786564480989-jekyll-liquid-breaks-generated-doc-readmes-fix-dua.md). Enum-doc drift (slang#12578): a `.meta.slang` enum that splices its values from C++ (`Write = $(kCoreModule_...)`) stays in sync automatically, but a **hand-written copy in the user guide** drifts silently — the triage move is to build a per-enumerator match table across all three layers (C++ constant / spliced meta enum / doc); the drift is only ever in the doc layer, and `reproduced` is earned by the value comparison, no build needed [enum docs drift from spliced meta enums](../learnings/1786966348400-slang-12578-hand-written-enum-docs-drift-from-spli.md).

## Agent operations: routing, presentation, infra timing

**Cron fire has a third state.** An absent `rerun-log.jsonl` row does not prove a missed fire — a no-action sweep and a fired-but-crashed sweep both write nothing. The authoritative wake trail is the inbound ledger (`messages_in`, `status=completed` ⇒ it FIRED), and the outbound trail (`messages_out`) shows whether it completed or crashed; the observed third state was a fire that died on an oversized/truncated API payload (a robustness data point, not a cron-reliability failure — don't fold it into a "cron skipped again" escalation) [cron fire present-but-crashed](../learnings/1786537254793-cron-fire-can-be-present-but-crashed-a-third-state.md). A fresh cron/supervisor heartbeat send with no inbound to reply to needs an **explicit `thread_id`** — a bare `send_message(to="orchestrator")` falls back to a heuristic over existing edges and can be refused or land on a stale peer thread with a huge backlog [heartbeat needs explicit thread_id](../learnings/1786609746031-heartbeat-status-send-needs-explicit-thread-id-not.md). Infra timing: a Falcor CI job that dequeues ~24h late can red-light on an **EXPIRED** `slang-tests-*` artifact (1-day retention, vs ~5-day for `slang-build-*`) — this is infra/timing, not a code regression, and a `gh run rerun --failed` CANNOT fix it (builds succeeded, the artifact is gone); leave it and have the author push to regenerate CI [Falcor expired-artifact failure](../learnings/1786558246816-falcor-job-can-fail-on-expired-test-artifact-when-.md).

Presentation and identity discipline: a GitHub issue filed for a human maintainer must lead with a 3–5 line TL;DR (problem → proposed fix → the single blocking decision) — a maintainer replied "This is too verbose, can someone help summarize it?" to an issue that buried the ask under verification tables; move exhaustive detail below a `<details>` fold [issues for maintainers must lead with TL;DR](../learnings/1786553859095-github-issues-filed-for-human-maintainers-must-lea.md). Per operator directive, use gender-neutral **they/them** for human contributors and never infer gender or a real name from a handle — the fix is mechanical (write "they", credit by `@handle`), and a live public artifact carrying the violation gets corrected in place [use they/them for contributors](../learnings/1786613178727-use-they-them-for-human-contributors-never-infer-g.md).

## Trust the measurement over the narrower read

Two atoms sharpen an epistemic rule: when a plausible source-read or hypothesis contradicts a hard measurement, the measurement wins. Triaging slang#12530, a subagent read the immediate control flow correctly and concluded "nothing is retained," but a `malloc_history` showed the exact allocation LIVE at process end — a control-flow read ("this ComPtr goes out of scope") CANNOT override a live-allocation measurement; the retention of a ref-counted object is decided by ALL its copies, not the one readable frame, and re-tracing found the ComPtr copied into a session-lifetime `_blobHoldingSerializedData` [control-flow read vs live-allocation measurement](../learnings/1786631931745-a-control-flow-source-read-that-contradicts-a-live.md). On a Slang Discord support thread, the *shape* of `observed − expected` deltas across samples discriminates a bug's cause with no repro: a **constant, position-independent delta** (a fixed XY-only offset identical to 6dp on every DDGI probe) refuted both an fp-precision hypothesis (which would scale with magnitude) and a `direction·t` coincidence (which would vary per ray), pinning the bug to the caller's origin computation and correcting a prior posted answer — compute the delta before hypothesizing [constant delta refutes fp-precision and direction·t](../learnings/1786562304678-a-constant-position-independent-delta-refutes-both.md).
