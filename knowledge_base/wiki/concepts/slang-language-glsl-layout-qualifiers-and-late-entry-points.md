# Slang GLSL `layout(...) in;` qualifiers and late entry points

GLSL source declares stage properties as standalone layout qualifiers (`layout(local_size_x = 16) in;`), not as attributes on the entry function. Slang turns them into function attributes or implicit declarations during checking. That works on the front-end path (`slangc -entry`, or `[shader]`), where the front end knows the entry point before lowering. It breaks on the module-API path (`loadModuleFromSourceString` then `IModule::findAndCheckEntryPoint`, which render-test uses), where an entry point without `[shader]` is validated only after the module has been lowered to IR. This page also covers the implicit workgroup-size spec constants that `local_size_*_id` creates. General link-time entry-point facts are on [[wiki/concepts/slang-compiler-linker-entry-point-checks.md]], and other checker-made declarations on [[wiki/concepts/slang-language-synthesized-declarations-and-double-visits.md]].

## TL;DR

- **On the module-API path, a GLSL entry point without `[shader]` is validated after lowering.** Attributes that `validateEntryPoint` lifts onto the FuncDecl (`local_size_*` to `NumThreadsAttribute`, `early_fragment_tests` to `EarlyDepthStencilAttribute`) are missing from the module IR. Reflection still sees them, because it reads the AST.
- **Lifted attributes reach the linked IR only through the per-program layout IR and the linker's `cloneExtraDecorationsFromInst` allowlist** (PR #14275 added `NumThreadsDecoration` and `EarlyDepthStencilDecoration`). A future lift in `validateEntryPoint` needs the same allowlist entry.
- **Symptom: a GLSL-source Vulkan compute test runs one thread per group (`LocalSize 1 1 1`) while reflection says N.** Tests that write only `data[0]` hide it, so write lanes beyond 0.
- **`derivative_group_{quads,linear}NV` is not lifted at all**, because `visitEmptyDecl` decorates only insts that already carry `IREntryPointDecoration`. Gate a new lift on "the module was already lowered" so the front-end path, and E31211's pinned location, stay unchanged.
- **`slangc -entry` takes the front-end path and cannot reproduce late-entry-point bugs.** Use a small C++ program against libslang with `enableGLSL = true`.
- **A GLSL `local_size_x_id` defaults to the `local_size_x` value of the same axis**, in either statement order (glslang). Slang's implicit spec constant got 0 on master, and the via-GLSL emitter writes only `local_size_x_id`, so glslang uses 1 for the unspecialized size.
- **Give every unnamed checker-synthesized global a unique name.** Unnamed siblings of one type share a mangled name, and the IR linker merges them silently. A `$` prefix cannot collide with user identifiers.
- **A sibling-modifier lookup at `ModifiersChecked` misses later siblings**; `ensureDecl` each one first.
- **Never fold an expression through a temporary `DiagnosticSink` if it will be checked again.** The first check caches the error result in the node, and the real check reports nothing.
- **`checkGLSLLayoutAttribute` keeps attributes that failed validation**, unlike `checkAttribute`, so a consumer that re-folds `args[0]` can see null.
- **Exhaustive DIAGNOSTIC_TEST on GLSL source: no `#version` line in a `.slang` file** (it emits E00120); use `SIMPLE_EX(diag=X): -lang glsl`.

## Lifted attributes reach the IR only through the layout IR (#14256, PR #14275)

Consider a GLSL compute shader with `layout(local_size_x = 16) in;` and `void main()`, loaded with `loadModuleFromSourceString` and then `IModule::findAndCheckEntryPoint("main")`, as render-test does. The entry point has no `[shader]`, so it is validated after the module is lowered. `validateEntryPoint` then lifts the layout qualifier onto the function as a `NumThreadsAttribute` (and `early_fragment_tests` as an `EarlyDepthStencilAttribute`), but the module IR was built before that and lacks the decoration. Reflection still reports 16, because it reads the AST. The per-program layout IR (`TargetProgram::createIRModuleForLayout`) lowers an import declaration of the entry function after validation, and the modifier loop runs for declarations too, so that copy does carry the decorations. The linker keeps a decoration from a non-best copy only if its opcode is on the `cloneExtraDecorationsFromInst` allowlist (`slang-ir-link.cpp`). The fix for slang#14256 (PR #14275) adds `kIROp_NumThreadsDecoration` and `kIROp_EarlyDepthStencilDecoration` to that list; any future lift in `validateEntryPoint` needs the same treatment [late entry-point AST attributes reach IR only via the layout IR + linker allowlist](../learnings/1793747942677-late-entry-point-ast-attributes-reach-ir-only-via-.md).

On Vulkan the symptom is a compute test that runs one thread per workgroup while reflection says N. While fixing slang#14250 (master 7f4efc7ce, L40S), a `COMPARE_COMPUTE ... -vk -source-language glsl` test with `layout(local_size_x = 16) in;` left lanes 1..15 unwritten, and `-compute-dispatch 16,1,1` gave 16 groups of one thread, while CUDA ran all 16 and `slangc -lang glsl` emitted `LocalSize 16`. Every existing GLSL-source Vulkan test wrote only `data[0]`, so nothing caught it. The workaround at the time was to write the test as Slang source with `[numthreads(N,1,1)]` and `import glsl;` to reach the GLSL builtins [only the first __intrinsic_asm is emitted; GLSL-source VK COMPARE_COMPUTE runs 1 thread/group](../learnings/1793740104470-slang-only-the-first-intrinsic-asm-in-a-core-modul.md).

## Three `layout(...) in;` qualifiers, three mechanisms

The three GLSL stage qualifiers take three different routes to a late entry point. `local_size_*` and `early_fragment_tests` are lifted onto the FuncDecl in `validateEntryPoint` and need the allowlist above. `derivative_group_{quads,linear}NV` is not lifted at all: `visitEmptyDecl` (slang-lower-to-ir.cpp) attaches the decoration only to insts that already carry `IREntryPointDecoration` at lowering, so a late entry point never gets it. On master this showed up as a spurious E31211, because LocalSize collapsed to 1x1x1 and `inferDerivativeGroupMode` chose Linear. Once the size is fixed, the mode is inferred from Y, so an explicit mode is silently overridden (linear 4x4 becomes Quads). An ungated lift moves E31211's location from the layout line to the function name, and `derivative-mode-wrong-multiple-linear.slang` pins that location. Gating the lift on `entryPoint->getModule()->getIRModule()` (the module was already lowered) keeps the front-end path unchanged.

`slangc -entry` takes the front-end path and cannot reproduce late-entry-point bugs. The probe harness is a ~100-line C++ program against `build/Release/lib/libslang.so`, linked with `-Wl,-rpath`. It needs `SlangGlobalSessionDesc.enableGLSL = true`; otherwise it fails with E38201 "'glsl' module not available". The script is `/workspace/agent/runs/probe-14275/probe.cpp` in the slang-reviewer group [late entry points: three GLSL layout qualifiers, three mechanisms](../learnings/1793751877547-slang-late-entry-points-three-glsl-layout-in-quali.md).

## Workgroup-size spec constants: `local_size_x_id` (#14277, PR #14284)

GL_KHR_vulkan_glsl declares sizes and ids independently. For `layout(local_size_x = 32) in; layout(local_size_x_id = 18) in;`, glslang makes SpecId 18 with a default of **32**, in either statement order. Slang's implicit constant, made in `checkModifier` for `GLSLLayoutLocalSizeAttribute`, got 0 on master e73d26897 and 1 in #14284 R1. The via-GLSL path has a related gap. The GLSL emitter (`slang-emit-glsl.cpp:1551`) writes `local_size_x_id = N` but not `local_size_x = <default>`, so glslang uses 1 for the unspecialized size while `gl_WorkGroupSize` still reads the constant's default: a silent mismatch for declared constants. Fixing the emitter breaks `tests/spirv/spec-constant-*numthreads`. A third trap is that `checkGLSLLayoutAttribute` ignores the return value of `validateAttribute`, so a `VkConstantIdAttribute` whose id does not fold survives, whereas `checkAttribute` (the HLSL `[vk::constant_id]` path) drops it. Any consumer that re-folds `args[0]` can then hit a null result, which was the #14284 segfault. To get reference SPIR-V without glslangValidator, dlopen `libslang-glslang-*.so` and call `glslang_compile_1_3` (header `source/slang-glslang/slang-glslang.h`; driver `runs/probe-14284/glslref.cpp` in slang-reviewer) [GLSL local_size_x_id default comes from local_size_x; temp-sink folding poisons AST exprs](../learnings/1793757488047-glsl-local-size-x-id-default-comes-from-local-size.md).

The implicit spec constant for an undeclared `local_size_*_id` is a module-level `VarDecl` that the checker synthesizes with no name. It gets the same mangled export name as any other unnamed sibling of the same type (`_SV3<module>0`), and the IR linker merges them into one symbol without any diagnostic: the implicit constants for ids 5 and 6 became one `OpSpecConstant` with only `SpecId 6`, used for both `LocalSizeId` axes. The #14284 fix gives each synthesized decl a unique name with a `$` prefix (`$local_size_id_5`), which cannot collide with user identifiers; the GLSL emitter scrubs `$` to `x24`. A lookup over sibling modifiers has its own ordering trap. The checker visits declarations at `DeclCheckState::ModifiersChecked` in source order, so a lookup done at that phase misses LATER siblings, which still hold `Unchecked*Attribute`. Call `ensureDecl(member, ModifiersChecked)` on each sibling first, iterating by index because members can be appended mid-scan [unnamed checker-synthesized globals get merged by the IR linker](../learnings/1793754626265-slang-unnamed-checker-synthesized-globals-get-merg.md).

## Checking and testing notes

- **Fold with the visitor's own sink.** Folding an AST expression through a sub-visitor with a temporary `DiagnosticSink` stores the error result in the node, so the later real check emits nothing. In #14284, `layout(local_size_x = undefinedSize)` compiled with no E30015. With the visitor's own sink the error is reported once [temp-sink folding poisons AST exprs](../learnings/1793757488047-glsl-local-size-x-id-default-comes-from-local-size.md).
- **Exhaustive DIAGNOSTIC_TEST on GLSL source.** A `.slang` file that contains `#version` emits warning E00120. Use `SIMPLE_EX(diag=X): -lang glsl tests/...` with no `#version` line [same](../learnings/1793757488047-glsl-local-size-x-id-default-comes-from-local-size.md).
- **render-test and API unit tests.** render-test prints buffers as UPPERCASE hex (`6A`). GLSL `atomicAdd` is rejected on CUDA (E36107). In API unit tests, a `.glsl` module path selects GLSL with no deprecation warning. Keep the `ISession` alive while you call `getLayout()` on the linked program, or it segfaults [late entry-point attributes](../learnings/1793747942677-late-entry-point-ast-attributes-reach-ir-only-via-.md).
- **Worktrees.** A new git worktree needs `git submodule update --init --recursive` before `cmake --preset default`, or configure fails on SPIRV-Headers [GLSL-source VK tests run 1 thread/group](../learnings/1793740104470-slang-only-the-first-intrinsic-asm-in-a-core-modul.md).
