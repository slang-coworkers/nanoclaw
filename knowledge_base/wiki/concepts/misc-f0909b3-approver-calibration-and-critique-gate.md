## TL;DR

- **Merged byte-identical at the decided head = the disputed change was NOT required** — the cheapest falsification of a critique-gate/challenger must-fix. Squash-only ⇒ compare head SHAs, not ancestry.
- **A merge join grades your gap only if a human SAW it.** A shadow-mode finding that never posts + a fast self-merge against a clean-looking head is *never-adjudicated*, not human-disagreement — don't flip the abstain to "I was over-cautious." A human CHANGES_REQUESTED at your head CONFIRMS an abstain, but a clarity-focused human can still miss the correctness defect the challenger caught.
- **"Inability to complete the check ⇒ ABSTAIN" is literal.** A concurrency/race/leak fix's own not-yet-completed sanitizer leg, a draft flag, or author-declared WIP scaffolding is a standalone abstain signal — clean code + passing clauses do not upgrade an unverified harness. Read the SKILL's decision criteria VERBATIM before recording, not from memory.
- **A critique must-fix on the PR author's SOURCE (comment style, prose) is structurally unresolvable by a read-only approver** → `ABSTAIN_POLICY:ESCALATED` after the 3-round soft-cap, NOT WOULD_APPROVE and NOT endless re-litigation.
- **The ABSTAIN delivery fast-path is a dumb word-boundary grep** — the literal tokens `WOULD_APPROVE`/`BLOCK` anywhere in an abstain report (even "→ not BLOCK") re-engage the full gate. Paraphrase them.
- **`tier_eligible` reads the 300-truncated `compare` array** (correct only while `max_files < 300`) and fires on raw diff *size* — a docs/test-only mega-PR from a trusted MEMBER trips it but is low-risk; check the path-confinement predicate.
- **Non-compiler content repos (website / blog / docs / `shader-slang/spec` proposals) are `ABSTAIN_POLICY:OUT_OF_SCOPE`** — clean clauses + empty Devin + prior human approval never round up.
- Tier facts: harvest **exit 20 on a bot-authored `dev/slang-fixer/` branch is the EXPECTED production-skip** (Devin-only tier, not NO_REVIEW_SIGNAL); a Devin timeout on a Devin-sole PR is an infra abstain, not a code concern; `record_human_verdict` is host-stamped from the merge webhook, not a callable tool.

## Reading the merge join: what a merge does and does not prove

The strongest calibration signal is a **merge byte-identical at the decided head with zero interval commits** — it refutes whatever a gate or challenger flagged as a merge blocker. On slang#12453 this confirmed a *gate-induced false-abstain*: an `ABSTAIN_POLICY:ESCALATED` whose only blocker was a critique must-fix on the PR author's comment style merged unchanged, with the disputed comments unrevised, proving they were never merge blockers [ESCALATED join confirms false-abstain](../learnings/1786537095703-approver-human-disagreement-escalated-join-confirm.md). Two "confirmed-safe" joins reinforce that a WOULD_APPROVE decided on a Devin-only tier and merged unchanged is a genuine agreement, not a silent-pre-merge-fix: the VM-emit BoolLit missing-constant fix (#11398) [BoolLit fix merged unchanged](../learnings/1786609551671-approver-confirmed-safe-vm-emit-boollit-missing-co.md) and the unorm/snorm float-opcode fix (#12468), where an earlier revision's `NO_REVIEW_SIGNAL` abstain (Devin timed out) was proven a pure infra gap by the later clean merge [WOULD_APPROVE joined to merge](../learnings/1786613025265-approver-human-agreement-would-approve-joined-to-a.md).

But a merge grades your gap **only if a human saw it**. On slangpy#1106 the author self-merged an OPEN_GAP head 11 minutes after open with the finding surfaced *nowhere a decision-maker would see it* (shadow-mode + a bot flag only on the superseded commit) — this is `never-adjudicated`, and the correct posture is to split the join: the *diff* is confirmed safe by the ship, but the *gap* is NOT graded, so do not flip the abstain to "over-cautious" [fast self-merge is not adjudication](../learnings/1786634978735-approver-human-disagreement-fast-maintainer-self-m.md). The converse: on slang#12421 a human posted CHANGES_REQUESTED at the exact decided head — CONFIRMING the abstain — yet the human's clarity pass MISSED the correctness defect the challenger caught (a missed `findSourceView` conversion dropping source context); a confirmed abstain is not evidence every issue is covered, so still surface the specific challenger-verified defect to whoever owns the fix [ABSTAIN confirmed by CHANGES_REQUESTED](../learnings/1786798250062-approver-human-disagreement-abstain-confirmed-by-a.md).

**Weight OPEN_GAP severity by artifact class, and read the size clause skeptically.** Two joins on slangpy#1107 and slang#12531 show reachable gaps confined to opt-in/nightly *infrastructure* are routinely shipped-then-followed-up by trusted MEMBERs — a reachable gap in nightly-only CI is real but has confined blast radius, so state the artifact class explicitly and set confidence accordingly rather than abstaining at full confidence [reachable gaps in nightly infra](../learnings/1786711986942-approver-human-disagreement-reachable-gaps-confine.md). The `tier_eligible` size clause is a recurring source of correct-but-noisy abstains: on slang#12531 (2,003 files, all under `docs/`) the clause fired on raw diff size and routed to a human who approved unchanged — a very large PR whose *entire diff is confined to docs/test/generated trees* from a trusted MEMBER is low-risk regardless of file count, so check the path-confinement predicate before treating a size abstain as a "human must scrutinize" signal [tier_eligible ABSTAIN on docs mega-PR](../learnings/1786697791975-approver-human-disagreement-tier-eligible-abstain-.md). The clause also has a latent bug: it derives BOTH size caps from GitHub's `compare` endpoint, which **truncates its `files` array at 300 and returns HTTP 200** — sound only while `max_files < 300`; derive counts from the exact `pulls/N` scalars instead [tier_eligible reads 300-truncated array](../learnings/1786632821260-approver-clause-gap-tier-eligible-reads-the-300-tr.md).

## Repo-class determination comes first

Clauses carry no repo-class predicate, so a PR on `shader-slang/spec` (formal spec / feature proposals) sails through all six clauses, `collect-reviews.sh` returns exit 20, and Devin comes back clean — a fingerprint byte-identical to `NO_REVIEW_SIGNAL` that also tempts WOULD_APPROVE. Do **class determination FIRST**: a non-compiler content repo (website / blog / docs / spec-proposals) is `ABSTAIN_POLICY:OUT_OF_SCOPE:<class>`, NOT ABSTAIN_INFRA (the pipeline didn't fail — the PR is out of domain), and never rounds up even with clean clauses + empty Devin + a prior human approval, because a proposal's merit is a maintainer language-design call [spec repo is OUT_OF_SCOPE](../learnings/1786741789835-approver-clause-gap-shader-slang-spec-feature-prop.md).

## "Inability to complete the check ⇒ ABSTAIN" and the sanitizer-PR class

A cluster of calibration atoms sharpens the literal ABSTAIN bar for PRs whose verification harness hasn't finished. A concurrency/data-race fix makes a claim only its own sanitizer run can verify — byte-identical codegen and a green non-sanitizer build cannot see a race — so on slang-rhi#839 the TSan legs the PR *adds* were the sole positive control and were still `in_progress`, an ABSTAIN independent of what the `ci_green_on_sha` clause said [TSan fix positive control is its own sanitizer leg](../learnings/1786621474608-approver-calibration-a-tsan-data-race-fix-s-positi.md). slang-rhi#711 (ASAN) adds three co-signals: verified UB in a stack trace is only a BLOCK if the faulting file is *in the diff* (pre-existing code exposed ≠ change-defect); a previously-green leg going red can be red *progress* (a sanitizer made to fail loudly is working); and author-declared WIP scaffolding ("remove before merge") in the diff is a CI-independent standalone abstain [sanitizer-validation PR = ABSTAIN not BLOCK](../learnings/1786569292882-approver-calibration-sanitizer-validation-pr-its-o.md). The most explicit statement is slang#12125 R6, where a merged+human-approved outcome pulled toward approve but two checks were genuinely incomplete: reading the SKILL's decision criteria VERBATIM (rather than a self-serving gloss) refuted the narrow reading — "Inability to complete the check ⇒ ABSTAIN" is its own independent trigger, and a merged+approved outcome is a post-hoc scoring signal, never a decision input [inability to complete the check is literal](../learnings/1786714850143-approver-critique-mustfix-inability-to-complete-th.md).

The **un-masking** calibration is the inverse: a VM-emit missing-constant fix (#11398) can legitimately bundle an "unrelated-looking" test-assertion change — the missing constant made a test pass *for the wrong reason* (garbage-truthy), and adding the arm forces the assertion to its real value; don't dismiss it as scope creep, but DO verify the NEW value against core-module source, not against the test's own new pass/fail state [un-masking test-assertion change](../learnings/1786546050952-approver-challenger-calibration-vm-emit-missing-co.md).

## Critique-gate mechanics: scope, deadlock, and delivery hygiene

Several atoms are about the critique gate itself, not the code. A must-fix that is (a) about the PR's own source and (b) something a read-only approver cannot change is **structurally unresolvable** → the terminal state is `ABSTAIN_POLICY:ESCALATED` after the 3-round soft-cap, asserting "the pipeline couldn't pass the gate," NOT "the code is unsafe"; state that explicitly, don't round up, and don't fake a critique round [source-comment must-fix → ESCALATED](../learnings/1786707838048-approver-critique-mustfix-source-comment-must-fix-.md). Conversely, the gate legitimately catches over-clears: on slang#12479 three critique rounds each caught a RIGOR defect in the approver's *own derivation* (an over-claimed "sole path," a non-isolating two-arbitrary-binaries control, an `rc=0` read from the end of a pipe) — the countermeasures are mechanical (build patched-head-vs-only-diff-reverted; capture `rc` without a pipe; read the whole diagnostic), and 3 rounds = soft-cap → escalate, never silently retry, even when the substance is sound [attributing a behavior change needs an isolating control](../learnings/1786541394634-approver-critique-mustfix-attributing-a-behavior-c.md). On slangpy#1107 the gate correctly caught two clearing fallacies ("pre-existing line" ≠ "pre-existing gap" — a PR can make an old line newly reachable; "nightly / not merge-gating" ≠ "no trigger") [pre-existing line / no trigger are not clears](../learnings/1786711285634-approver-critique-mustfix-pre-existing-line-and-no.md), and slang PR #12507's gate flagged a committed `.pr-body-*.md` working-log at the repo root — a documented-rule violation that persists to master, so `WOULD_APPROVE` is internally inconsistent (it asserts mergeable-as-is), yielding `ABSTAIN_POLICY:CHALLENGER_CONCERN` even with perfect code [committed working-log file is abstain-worthy](../learnings/1786971731131-approver-challenger-concern-committed-working-log-.md).

Two atoms document the same **delivery-gate word-boundary trap** and are mutually reinforcing: the ABSTAIN fast-path in `gate-critique-on-deliver.sh` fires only if the message contains an abstain token AND does NOT contain a standalone `\bWOULD_APPROVE\b`/`\bBLOCK\b` — so explanatory prose like "the honest state is ABSTAIN, not WOULD_APPROVE" [ABSTAIN report tripped by literal token](../learnings/1786560145563-approver-critique-mustfix-abstain-report-tripped-b.md) or "→ not BLOCK", "hard block", "not rounded up to BLOCK" [fast-path defeated by BLOCK/WOULD_APPROVE words](../learnings/1786969684328-approver-critique-mustfix-abstain-fast-path-is-def.md) re-engages the full gate even though the ledger append already succeeded. The fix is message hygiene: grep your own draft for standalone uppercase tokens and paraphrase (lowercase "hard-block", or "merge-stopping verdict") — and send abstain decisions via the `mcp__nanoclaw__send_message` TOOL (the fast-path is gated on that tool path), not only a trailing `<message>` block; do NOT run a ceremonial `/codex-critique` to satisfy the gate (abstains are not critique-gated).
