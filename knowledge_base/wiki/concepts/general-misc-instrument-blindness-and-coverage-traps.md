# Instrument Blindness and Coverage Traps

## TL;DR
- Cross-domain instrument traps: polymorphic nulls, truncated read-backs, retyped commands.
- Executed ≠ observed — know which arm of a compatibility guard actually carries the risk.
- An #elif-blind grep inverts the dead/live verdict.
- A harness's shape is an invisible coverage boundary; a zero-hit coverage check must survive a synonym retry.
- A fidelity gate firing on a corrupted reference produces a demand that looks exactly like diligence.

## Cross-Domain Instrument Traps: Polymorphic Nulls, Truncated Read-Backs, Retyped Commands

Three cross-domain instrument traps that also govern GitHub CI work. **A null from a polymorphic field is your accessor's error, not the API's absence** — on a User-vs-Team field, `.reviewer.login` returns `null` for a Team object that carries `name`/`slug` instead, indistinguishable from "unset"; the two readings imply opposite asks ("misconfigured, assign an owner" vs "a named team hasn't acted"). Print `sorted(obj.keys())` and check the `type` discriminator before concluding absence, and scrutinize a null *more* when it makes your finding scarier ([a null from a polymorphic field is your accessor's error](../learnings/1786270804019-a-null-from-a-polymorphic-field-is-your-accessor-s.md)). **`ncl tasks list --json` truncates `prompt` to 120 chars** — a successful large-prompt write reads back as failed; read with `ncl tasks get <series> --json`, and generally: when a write reports success and your read-back contradicts it, suspect the READ first, before "repairing" ([ncl tasks list truncates prompt to 120 chars](../learnings/1786266947337-ncl-tasks-list-truncates-prompt-to-120-chars-a-suc.md)). **Copy a command from their text — never retype it from their description** — testing your reconstruction tests nothing; a four-way refutation of a peer's `echo "exit=$?"` mechanism was entirely correct and entirely about a command nobody ran (the real defect, a `| head`, was verbatim one scroll up) ([copy the command from their text — never retype it from their description](../learnings/1786268741453-copy-the-command-from-their-text-never-retype-it-f.md)).


## Executed ≠ observed — which arm of a compatibility guard carries the risk

**A code path can run in an environment where its effect is invisible.** A guard's false arm *did* execute locally (`SGL_HAS_NVAPI: OFF` ⇒ predicate always false) but against a Slang pin where the diagnostic under test was unreachable, so it ran without being able to discriminate patched from unpatched. That also fixes **which arm owes verification**: when a fix narrows an unconditional action behind a predicate, the true arm restores the pre-patch path verbatim and is *inert by construction*, so "the `P == true` path is unverified" points at the arm needing no verification — the real question is whether anything on the newly-skipped path depended on the side effect that no longer happens; and "can't test configuration X" is usually too coarse (a diagnostic keyed on the *target* is testable with no D3D12 device at all) ([which arm of a compatibility guard carries the risk](../learnings/1785750665244-which-arm-of-a-compatibility-guard-carries-the-ris.md)). **A pin-independent fix's risk baseline is the pinned dependency, not the unreleased upstream change that motivated it** — fetch the dependency at the pinned ref (`gh api …/contents/<path>?ref=<tag>`) and ask which configurations behave differently *under the pin*; a green CI matrix lacking the exposed configuration cannot see the flip, and a two-clause predicate can invert a grep (`hasOption(Profile)` was unconditionally true because *upstream* session code calls `setProfile()`, so grepping the downstream repo "confirms" no profile — exactly backwards) ([a pin-independent fix's risk baseline is the pinned dependency](../learnings/1785751904901-a-pin-independent-fix-s-risk-baseline-is-the-pinne.md)). **Never ship a hedge for an environment failure you did not personally hit** — relaying another tier's `E00100` link failure would launder its failure under our bot identity and destroy the best evidence, *because if you believe you can't compile, you don't try*; with a working compiler a code comment's own premise ("valid programs cannot have by-value struct cycles") was testable and didn't carry, and watch for **DCE faking a pass** (a 200-deep type "compiled" only because the value was never stored — compare artifact sizes against a trivial baseline) ([never ship a hedge for an environment failure you didn't personally hit — prove the premise, hedge the inference](../learnings/1785748057767-never-ship-a-hedge-for-an-environment-failure-you-.md)). Two Slang-specific proxies: in slang-rhi's Vulkan backend, `areDefined()` excludes `VK_API_DEVICE_OPT_PROCS` and `addFeatureExtension` does not clear the feature bool it rejects, so `if (!api.m_extendedFeatures.X.y) bypass;` **tests a stale feature bit and never the proc pointer** — gate on the proc pointer ([optional Vulkan proc pointers are loaded unchecked and feature bits survive a rejected extension](../learnings/1785774873723-slang-rhi-vulkan-optional-proc-pointers-are-loaded.md)); but that clean mechanism was *refuted by call ordering* — **a null function pointer faults at the FIRST call site**, and the reported fault was the *second* call, so reaching it proves the pointer was non-null, no matter how well the rest fits; don't invoke "optimized builds are imprecise" as a blanket licence to move a fault to where your hypothesis needs it ([a null function pointer faults at the FIRST call site](../learnings/1785775592426-a-null-function-pointer-faults-at-the-first-call-s.md)). Finally, **breadth-of-mechanism is the author's job and no gate will do it**: rejecting a whole approach after one failed spelling (`set(... CACHE STRING "" FORCE)`) led to a more complex detection-based fix that every codex gate passed — because gates validate *the shape you chose*, not whether a simpler mechanism existed; and endorsing the superseding fix by **repeating its PR body** rather than running it was the same error sign-flipped (env `CXXFLAGS='-O0 -g3'` still yields `-Og` winning). A PR body is a claim, not evidence ([review gates validate the shape you chose, not whether a better mechanism exists](../learnings/1785769682134-review-gates-validate-the-shape-you-chose-not-whet.md)).


## An #elif-blind grep inverts the dead/live verdict

`grep -n '^#if\|^#else\|^#endif'` used to resolve which preprocessor arm ships **cannot match `#elif`**, so a three-armed chain silently reports as two-armed and `#else` *looks* live when it is dead. Ground truth at `d9353c090`: in `slang-glslang.cpp` the `#elif 1` arm at `:344` is what ships as `-O1`; the `#else` at `:384` is dead. Match every arm-introducing directive (`#elif`/`#elifdef`/`#elifndef`), print the whole chain with nesting depth, count *inside* the arm you cite, and prefer `cc -E`/`cc -E -P` over inference — the failure is self-consistent in both directions (identical surrounding comment text supports "rotted into `#if 0`" and "won and shipped"), so a correcting reviewer reached the opposite-but-also-wrong answer with the same blind pattern, and **a correction built on the same broken instrument reproduces the error with more confidence** ([an `#if 0` chain can have an `#elif` — an `#elif`-blind grep inverts the dead/live verdict](../learnings/1785781716720-correction-an-if-0-chain-can-have-an-elif-a-grep-t.md)).


## A harness's shape is an invisible coverage boundary

A test suite reports truthfully about what it measured and says **nothing** about what its own format could not carry — the harness's *shape* is an invisible coverage boundary. Three distinct mechanisms observed while two agents built one guard: a `while IFS= read -r` loop split a multi-line case on newlines so it never reached the subject intact, reporting a FAIL for input the subject actually handled (nearly widening a pattern that was already right); a one-line-per-case TSV had no representation for newline-separated or trailing-backslash commands, so they weren't passing — they were **absent**, and the green count was silent about them; and in a TSV a tab-separated command is the one shape the format structurally cannot test, because the field delimiter and the input under test are the same character ([a harness's shape is an invisible coverage boundary — three distinct ways, and "absent from the suite" is not "passing the suite"](../learnings/1786227099882-a-harness-s-shape-is-an-invisible-coverage-boundar.md)). A harness that mangles or cannot carry an input is indistinguishable from a subject that handles it; the remedy is to **drive the subject directly for every shape the format can't express** and record it beside the suite count ("31/31 suite + 4 direct-drive" is honest; "31/31" alone is not). A sharper corollary appears when the subject is a guard: its test suite contains the forbidden string in executable position *by definition*, so no stripping rule can exempt it — one agent's suite was blocked by its own guard, another's survived only *incidentally* (single-quoted cases removed by quote-stripping; an unquoted case is blocked), failing in the reassuring direction that looks like a tooling glitch rather than zero coverage. And the coverage decision itself must be measured, not assumed: counting the wrapper frequency (`eval "…"` 25×, `bash -c "…"` 60×) over 7453 commands would have justified widening the guard, but the *hazard* frequency (a wrapper actually carrying the payload) was 2, both the audit's own tests, 0 organic — so the fix was declined and documented inline with the measurement, so a later reader sees a decision rather than an oversight.


## A zero-hit coverage check must survive a synonym retry

A distinct coverage-boundary trap lives in the *query*, not the harness: a **zero-hit coverage check run with the wrong vocabulary is a false zero**, and a false zero in the delete direction is silent data loss. A `slang-pr-approver` compaction pass ran the right check — "before shortening a pointer, verify the full text exists in the child" — but grepped the *index's* compressed, capitalized, mnemonic phrasing against a child that stores the same facts in explanatory prose, producing **5 false zeros in one pass** (`ASYMMETRIC SKEPTICISM` → 0 hits / `Asymmetric skepticism` → 1; `MOUNT not a capability` → 0 / `mount` → 4; `INDEPENDENT CREATOR` → 0 / `universal` → 14) ([a zero-hit coverage check must survive a synonym retry](../learnings/1785839829126-a-zero-hit-coverage-check-must-survive-a-synonym-r.md)). The class is systematic, not occasional: a summary is *supposed* to reword its source, so the parent's own phrasing is close to the worst possible query for locating its expansion — the same shape as the known "`INDEX.md` is generated and titles are normalized, so exact-symbol greps false-negative as 'no prior art'," now recurring inside one agent's own memory. Rule: **a zero-hit coverage check is not evidence of absence until it survives a synonym retry** — retry case-insensitively (`grep -i`), then on the *concept's* distinctive mechanism nouns (`mount`, `specializ`) rather than the mnemonic label, preferring a distinctive substring over a full phrase (summaries reword connectives and drop qualifiers). This is one more instance of the page's spine — a verification step can itself need a control — so of any zero ask *what would this command return if the thing were present?*; if you can't answer, you don't have a result yet.


## A fidelity gate firing on a corrupted reference produces a demand that looks exactly like diligence

The most insidious "well-formed answer to a slightly different question" is a **fidelity gate firing on a reference that is itself corrupted** — because the resulting demand is indistinguishable from diligence. On slang#11917 batch-2 (PR #12336) an operator gave a requirement marked *verbatim*; transcribing it into an independent reviewer's prompt, the author re-rendered a bold lowercase `because` as uppercase `BECAUSE`, and the reviewer correctly returned **must-fix: restore the capitalization** — enforcing verbatim against the text *it had been given*, which was already corrupted ([a fidelity gate firing on a corrupted reference produces a demand that looks exactly like diligence](../learnings/1785840123164-a-fidelity-gate-firing-on-a-corrupted-reference-pr.md)). Complying would have made the published artifact *less* faithful to the source instruction while looking precisely like compliance — the finding was locally correct (artifact ≠ supplied reference) and globally wrong (the reference, not the artifact, was corrupt), and ordinary review discipline pushes *toward* the error. Two-sided remedy: **as the reviewed party, a fidelity complaint is a claim about two artifacts — the deliverable and the reference — so check both before complying**, declining with the source quoted when the reference is the corrupt one; as the delegator, hand over the source quote fenced or quoted, never a retyped rendering, because emphasis markup (bold, caps-for-emphasis) does not survive transcription and *your paraphrase becomes the de-facto spec*. This sat alongside a whole batch of instruments returning well-formed answers to slightly-different questions (`slang-test` "100% (264/264)" computed over survivors after discarding 265 failures; `grep -c` counting matching *lines* not occurrences, turning ~42 sites into "16"; a probe grepping `BEFORE <pass>` when only the *after* hook was installed) — in each the tool worked and the reference was wrong, so **the defence is not care but a comparison that generates its own baseline**: a two-sided drill (neuter → run → restore → run) never needs the correct absolute total, only that the two arms differ, which is why it survived every one of these defects while single-reading checks did not. A corollary on bounds: scope a claim *at the sentence that makes it*, not in a qualifier three paragraphs later — a reader who stops at the sentence should get the bounded version, and restatements in headings/tables/summary lines outrank body prose because they are what gets read instead of it.
