# Slang Test Harness — Test Directives and Authoring

> Siblings: [Harness Internals and In-Process Unit Tests](slang-test-harness-internals-and-unit-tests.md) · [Output Assertions and Truncated Runs](slang-test-output-assertions-and-truncated-runs.md).

This part covers **which directive to write and how**: the `//TEST:` grammar, golden regeneration, subtest naming, test-vehicle choice, DIAGNOSTIC_TEST annotations, downstream-compiler gating, and render-test arguments. Running the harness and its false-green traps are in [False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md); FileCheck mechanics are in [FileCheck Authoring and Opt-Levels](slang-test-filecheck-authoring-and-opt-levels.md).

## TL;DR

- **Tests live under `tests/` as `.slang` files; a file with no `//TEST:` directive never runs** (its `.expected` is orphaned). `//TEST_IGNORE_FILE` on line 1 skips the file.
- **The grammar is `//TEST[(<category>)]:<COMMAND>`** — test discovery must tolerate the optional `(<category>)`, or it silently misses `//TEST(64-bit):…` / `//TEST(smoke):…`.
- **For GPU-free coverage use `//TEST:COMPARE_COMPUTE(filecheck-buffer=CHECK):-cpu -output-using-type`** — no GPU, no slangi.
- **`//TEST:INTERPRET` tests are silently skipped without slangi**, so a green run is not coverage. With slangi, prefer INTERPRET over `SIMPLE` for a front-end fix: it proves the value binds, and SIMPLE fails on stray stderr.
- **`//TEST:LANG_SERVER` never publishes diagnostics** (`//DIAGNOSTICS` deadlocks) and the workspace API is unexported, so LSP diagnostic bugs are verified by an A/B probe of real slangd.
- **`//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK):` uses the built-in matcher, not FileCheck, and is exhaustive by default**: every emitted diagnostic needs an annotation.
- **Annotations take NO space after `//`** — `// CHECK_ERR:` is silently a plain comment.
- **`//CHECK:` is 8 characters, so carets start at column 9**; copy the harness's "Suggested annotations you can copy" block and match by error CODE (`E41000`), not free text.
- **Each diagnostic emits one or two `E<code>` rows** (title, plus span when the text differs): E31202 and E55202 need two annotations, E30702 exactly one ("(already matched)" on a second).
- **`//CHECK-NOT:` is inert under DIAGNOSTIC_TEST**; negatives hold only via exhaustiveness. **Under `filecheck=` the inverse holds**: FileCheck reads its prefix on every line, prose included — write `//<prefix>:` in prose.
- **`<file>.slang.N` is the (N+1)th `//TEST:` directive, not a retry counter.** It is deterministic; read the directive before calling a recurring `.N` failure flaky.
- **Skip a crashing synthesized subtest with `-exclude-prefix` / `-skip-list`** (pre-expansion); expected-failure lists run the test first. Matching one expanded variant needs exact equality on the full `testName` with ` syn` / ` (<api>)` suffixes.
- **A flake's identity is the (subtest index, target, failure mode) tuple**, not the test name.
- **A harness-scheduling PR needs no `.slang` test** — use a `slang-unit-test` over extracted pure helpers, with `-dry-run` as acceptance.
- **Recommend a test shape against the BUILD graph**: a symbol inside a tool's `main.cpp` is unlinkable, so a subprocess test (which also tests the exit code) is the only option.
- **Delete `*.slang.actual.txt` before `git add`.** `.expected` is globally gitignored, so a NEW golden needs `git add -f`; `.32` goldens are never run in CI and drift stale.
- **`//TEST:REFLECTION(filecheck=CHECK):` inlines its expectations; only bare `//TEST:REFLECTION:` uses a golden that must be regenerated.** A deterministic cross-platform `test-slang` failure right after a golden change means incomplete regeneration.
- **No category gates a downstream compiler's VERSION**: a `-target metallib -capability metallib_4_0` test RUNS and FAILS on lanes with a pre-4.0 `metal`. Assert the Slang-side decision with an emit-only `-target metal` FileCheck test.
- **A `-target metallib` directive is only a macOS acceptance smoke test**; the `-target metal` text check must self-discriminate (e.g. `// METAL-COUNT-<n>:`).
- **An empty-output FileCheck failure in a `-dx12` `COMPARE_COMPUTE` lane is usually an arg-parse failure (error 1004)**, not codegen — `-use-dxil` is not a slang-test flag (DXIL is the dx12 default); read the ACTUAL block.
- **slang-test FRONT-inserts `-O0` into any directive lacking `-OX`** — a standalone `slangc` repro needs `-O0` explicitly; a fold-dependent CHECK needs `-O1`.
- **render-test `-X<compiler>` support is two fixes, accept and forward**; `DownstreamArgs(cmdLineContext)` omits `slang`, and migrations keep Slang's own options inside `-Xslang...`.
- **A "no downstream-compiler path" unit test uses a concrete pass-through (`GCC`/`CLANG`/`VISUAL_STUDIO`), never `GENERIC_C_CPP`**, which can resolve to prebuilt `slang-llvm` → `SLANG_OK`.

## Directive Grammar, Golden Files, and Artifacts

The directive grammar is `//TEST[(<category>)]:<COMMAND>`, so any discovery pattern must allow the optional category. On #12225 (a field added to every reflection-JSON layout), the narrow `//[[:space:]]*TEST:(CPU_)?REFLECTION` found 60 files and `//[[:space:]]*TEST(\([^)]*\))?:(CPU_)?REFLECTION` found 68; the PR passed "99/99 local" and then failed `test-slang` cross-platform on the 8 un-regenerated category-suffixed tests. Reflection tests run via `slang-test <files>`, whose `.actual` on mismatch is the bless source. `.expected` is globally gitignored (`*.expected`), so a NEW golden needs `git add -f`. `.32`/`.64` CPU_REFLECTION variants are selected by `SLANG_PTR_IS_32` and no CI job runs 32-bit, so `.32` goldens drift stale unvalidated ([golden discovery must tolerate the TEST(category): suffix](../learnings/1785070091132-slang-test-reflection-golden-test-discovery-must-t.md)).

Only bare `//TEST:REFLECTION:...` tests have a whole-output `foo.slang.expected` that must be regenerated; `//TEST:REFLECTION(filecheck=CHECK):...` inlines `//CHECK:` lines (2026-08: ~43 of ~68 reflection files golden, ~25 filecheck-only). `emitReflectionJSON` emits the top-level version/globalScope keys for every target, so a top-level key touches every JSON golden. An un-regenerated `.32.expected` is benign (already stale for cpp-resource-reflection). A comment-only or rename-only C++ change produces byte-identical output and needs no regen ([reflection .expected: filecheck vs golden, and the .32 CI-blind spot](../learnings/1785548558845-reflection-expected-baseline-filecheck-vs-golden-a.md)).

`slang-test` writes `*.slang.actual.txt` beside each test; delete them before `git add`. New test directories show in `git status`, not `git diff master`, until added ([slang-test leaves .actual.txt artifacts](../learnings/1781088712827-slang-test-leaves-slang-actual-txt-artifacts-in-th.md)).

## Subtest Naming, Selection, and Flake Identity

slang-test names the first `//TEST:` directive `foo.slang` and the rest `foo.slang.1`, `foo.slang.2`, … in file order: a deterministic directive index, not a retry counter. In `slang-test-main.cpp`, `runTestsOnFile` (:5099-5122) appends `subTestIndex` (into the parsed `testList.tests`) when non-zero; `insertSubtestIndex` (:4926) documents `foo.slang.0 (vk)`. On slang#11595 the fixer twice dismissed `gh-9931.slang.1` as a GPU flake, but directive `.1` is the deterministic `computeMainNV` spirv-asm `CHECK_NV` check: the PR's new E41303 alignment contract made its `Store<DescriptorHandle>(4, h, 8)` (`4 % 8 ≠ 0`) a hard error, so empty output failed every time. Only `COMPARE_COMPUTE`/`-vk`/`-cuda` runtime subtests can be GPU-nondeterministic; SIMPLE/spirv-asm/DIAGNOSTIC ones cannot. Before calling a `.N` failure flaky, read the (N+1)th directive's entrypoint, target and CHECK prefix, and ask whether your change reaches it. Reproduce on the right entrypoint (grepping the passing `computeMain` masked the `computeMainNV` failure), and trust a local `FAILED test:` over a hand grep ([.slang.N maps to the Nth TEST directive](../learnings/1784249706016-slang-test-slang-n-suffix-maps-to-nth-test-directi.md), [.slang.N is the (N+1)th directive, not a flaky-run index](../learnings/1784269637732-slang-test-slang-n-is-the-n-1-th-test-directive-no.md)).

To skip a crashing synthesized variant (e.g. LLVM JIT), use `-exclude-prefix`/`-skip-list`, which filter on source path before expansion; expected-failure lists run the test first ([synthesized subtest skip needs pre-run exclusion](../learnings/1780314391657-slang-test-synthesized-subtest-skip-needs-pre-run-.md)). Matching one expanded variant needs exact equality on the full assembled `testName`, including ` syn` and ` (<api>)`; `getSubtestIndex` and `-test-prefix` match only the index-level stem ([matching an expanded subtest name needs exact testName equality](../learnings/1780318208555-slang-test-matching-an-expanded-subtest-name-needs.md)).

A flake's identity is the (subtest index, target, failure mode) tuple, not the test name. `static-const-matrix-array.slang` has two unrelated signatures: **Sig-A** `.slang.1 (vk)`, a Vulkan GPU numeric/crash flake surviving harness retry (a 14-PR burst on 2026-06-23/24, then none); and **Sig-B** `.slang.3 syn (llvm)`, a test-server `JSON RPC failure: waitForResult()/hasMessage()` drop (first 2026-07-03, #11922, run 28642587133). Cite run-ids and PRs per tuple ([static-const-matrix-array: two distinct flake signatures](../learnings/1783066436944-static-const-matrix-array-two-distinct-flake-signa.md)). #11951 (Sig-B) was closed 2026-07-15 as fixed by #12056 (AVX-512 JIT workaround), but merge_group run 29390282163 evicted the unrelated approved PR #12064 with `SLANG_DISABLE_AVX512=1` active: a genuine `FAILED` on `.slang.3 syn (llvm)` plus a `gh-5900.slang.1 syn (llvm)` drop on `test-windows-RELEASE-cl-x86_64-gpu`. So the export does not rule Sig-B out, and it spans debug and release GPU tiers; with no SIGILL in the log, claim "fix-gap real", not "residual AVX-512". A fix-gap receipt needs export active + genuine FAILED + an unrelated PR; the contaminated #12105 (mimalloc, failing its own tests) left the hypothesis unproven, not disproved; jkwak owns the reopen ([#11951 Sig-B fix-gap confirmed post-#12056](../learnings/1784103591814-11951-sig-b-fix-gap-confirmed-post-12056-avx-512-n.md)).

## Choosing the Test Vehicle

**Harness changes.** A slang-test scheduling PR (selection, exclusion matching, subtest expansion) needs no `.slang` test, since no directive can assert which subtests run; `-dry-run` is valid acceptance. The vehicle is a `slang-unit-test`, usually after extracting the file-local `static` helpers in `slang-test-main.cpp` into a linkable library (precedent: `unit-test-test-tool-util.cpp`) ([harness changes: slang-unit-test is the right vehicle](../learnings/1780320008141-slang-test-harness-changes-slang-test-rule-n-a-but.md)).

**Check the BUILD graph, not just the call graph.** On #12212 triage recommended an in-process `slang-unit-test` of `CapabilityDefParser::parseDefs() → SLANG_FAIL`, but the parser lives only in `tools/slang-capability-generator/capability-generator-main.cpp` (no header) and `tools/CMakeLists.txt:80` builds it with `generator(slang-capability-generator LINK_WITH_PRIVATE compiler-core)`, an executable with no library target. The shipped fix (PR #12217, merged `f282bdf9c0`) used a subprocess test, `tools/slang-unit-test/unit-test-capability-generator.cpp`, asserting the diagnostic, a nonzero exit, and no output files. That was better coverage: the bug was the tool exiting 0 after an error, and when a *tool* misbehaves (exit code, files, stdout) the process is the unit under test. Before recommending a shape, `git grep -l '<Symbol>'` (header or one `.cpp`?) and check its CMake target (library or executable?). For this generator, a bare `def _foo : stage;` fails with error 20003 (undefined identifier), an already-nonzero path, so the repro must declare `abstract stage;` first to reach the intended 20007 (`missingExternalInternalAtomPair`); always grep stderr for the intended code. The generator lives in `build/generators/<config>/bin/`, so a spawning test walks from `UnitTestContext::executableDirectory` via `../../generators/<config>/bin/` and `SLANG_IGNORE_TEST`s when absent (`SLANG_GENERATORS_PATH` layouts). Model on `unit-test-depfile.cpp` (`ProcessUtil::execute(cmdLine, ExecuteResult&)`); unit-test `.cpp` files auto-glob into `slang-unit-test` ([recommend a test shape against the BUILD graph](../learnings/1785840768185-correction-recommend-a-test-shape-against-the-buil.md), [check the BUILD graph before recommending a test shape](../learnings/1785840805944-check-the-build-graph-not-just-the-call-graph-befo.md)).

**INTERPRET / slangi.** INTERPRET tests are silently skipped when slangi is not built, so for reliable GPU-free regression use `COMPARE_COMPUTE` with `-cpu` ([INTERPRET silently skipped without slangi](../learnings/1781222721953-slang-test-ignores-interpret-slangi-tests-when-sla.md)). When slangi is built, `//TEST:INTERPRET(filecheck=CHECK):` beats `//TEST:SIMPLE:` for a front-end parse/check fix whose repro needs a GPU path (e.g. a buffer-device-address pointer): swap to a local pointer. `struct Foo { int Bar<int N>(){return N;} }; void main(){ Foo f; Foo* foo=&f; printf("%d\n", foo->Bar<42>()); } //CHECK: 42` proves the generic argument binds to the right value (slangi supports `&f`, `->`, generic member calls, `printf`) and avoids SIMPLE's empty-stderr brittleness. `foo->Bar<42>()` still errors 30101 on master, so it is a real guard (#9810 / PR #12892). Before writing "how to add a test" guidance on a contributor's PR, fetch its current files (`gh pr view <n> -R <repo> --json files,commits,headRefOid`); the contributor may already have committed a test ([front-end pointer/generic fixes: test via INTERPRET, check PR state first](../learnings/1788396349246-front-end-pointer-generic-fixes-regression-test-gp.md)).

**LANG_SERVER cannot observe diagnostics.** `//TEST:LANG_SERVER` drives hover/completion/signature, but slang-test runs slangd with `-periodic-diagnostic-update false` and `didOpen`/`didChange`/`didClose` call `resetDiagnosticUpdateTime()` just before `publishDiagnostics()`, whose 1000 ms throttle then returns early; nothing is published, so `//DIAGNOSTICS` (used by zero tests) deadlocks ([LANG_SERVER harness cannot observe diagnostics](../learnings/1781083469573-CONSOLIDATED-langserver-harness-cannot-observe-diagnostics.md)). `Slang::Workspace`/`getOrLoadModule` are also unexported from the DLL, so no unit test can drive the workspace. PR notes say "manual-probe-confirmed, no automated regression possible"; a clean `slangc` compile does not guard the LS fragment-open path ([LS diagnostics cannot be auto-tested](../learnings/1781086523456-slang-ls-diagnostics-cannot-be-auto-tested-lang-se.md)). Verify an LSP diagnostics bug (#11531/#11532) by A/B of real slangd's published set (control 4 → narrowed #11534 fix 4 → broadened 0). They share the `checkModule` ordering root cause, but #11532's extension is file-scope, so the fix drives every module-level `NamespaceDecl` to ScopesWired before the extension-first pass ([CORRECTION: LANG_SERVER can't observe diagnostics (re #11532)](../learnings/1781116005493-correction-test-lang-server-harness-can-t-observe-.md)).

**Downstream-compiler "no path" unit tests.** A test that expects `IGlobalSession::getDownstreamCompilerPath` → `SLANG_E_NOT_AVAILABLE` must not use `SLANG_PASS_THROUGH_GENERIC_C_CPP`: `Session::getOrLoadDownstreamCompiler(GenericCCpp)` (slang-check.cpp) loads Clang/Gcc/VisualStudio and LLVM, then picks `getDefaultCompiler(CPP)`, which can be the prebuilt `slang-llvm` (a shared library with a path) → flaky `SLANG_OK`. Loop over `GCC`/`CLANG`/`VISUAL_STUDIO`, gated on `checkPassThroughSupport`; each yields a `CommandLineDownstreamCompiler` with no `getPath` override, deterministic and GPU-free. To prove an out-param is untouched on failure, seed a non-null sentinel raw pointer and assert it survives (a null `ComPtr` cannot tell "untouched" from "cleared"). To prove a returned path is the loadable library, reload it (`SharedLibrary::loadWithPlatformPath`) and `findSymbolAddressByName` an entry point (NVRTC `nvrtcVersion`; glslang any of `glslang_compile`/`_1_1`/`_1_2`/`_1_3`) (#12838 / PR #12841; [testing "no path": avoid GENERIC_C_CPP](../learnings/1788246202939-testing-downstream-compiler-no-path-slang-e-not-av.md)).

## DIAGNOSTIC_TEST(diag=CHECK) Authoring

`//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK):` uses Slang's built-in annotation matcher, so it runs locally even without FileCheck. It is exhaustive by default: an unannotated diagnostic fails with "Exhaustive check failed"; `(diag=CHECK,non-exhaustive)` opts out. Carets must sit under the reported column (`//CHECK:` is 8 characters and starts at column 1 even when the source is indented); copy the harness's "Suggested annotations you can copy" line rather than hand-computing. A repro needing a module-wide diagnostic (recursion rejected by E55201 unless `-disable-non-essential-validations`) goes in its own file ([DIAGNOSTIC_TEST(diag=CHECK) authoring](../learnings/1781787235055-slang-diagnostic-test-diag-check-authoring-exhaust.md)).

**Row counting.** Each diagnostic emits a title row and a primary-span row, both prefixed `E<code>` (`diagnostic-annotation-util.cpp:266`); the span row is dropped only when code, file, begin/end location and message all match the title (`isDuplicatePrimarySpan`, :299-317). A standard `err("name", CODE, "TITLE", span{message=...})` thus yields two rows (an alternating "unannotated" suggestion is the tell); on PR #11883, two DuplicateModifier diagnostics → four `E31202` rows. A bare `//CHECK: E31202` is a substring match on the code alone; pair it with a caret span (`//CHECK: ^^^ message`) to also pin location and message ([E-code row count = 2× diagnostics](../learnings/1782910333196-diagnostic-test-simple-diag-check-e-code-row-count.md)). The count is per diagnostic and over-annotating fails too: on #13619 E55202 needed two carets (`^^^ error E55202` plus span text), while E30702 writes one row, so a second caret or a combined `error E30702: <message>` fails "(already matched)". A legalizer diagnostic on a struct field reports at the struct's NAME (use a `/*PREFIX:` block under `struct X`); on a legalized global varying, at Line 0 (use a caret-less substring) ([E30702 needs one annotation, E55202 two](../learnings/1791972892553-slang-diagnostic-test-e30702-needs-one-caret-annot.md)).

**No space after `//`.** `diagnostic-annotation-util.cpp:85` builds the marker as `"//" + prefix + ":"` and line 181 tests `trimmedLine.startsWith(lineMarker)`, so `// CHECK_ERR:` is silently dropped; the block form `/*CHECK_ERR:` is matched after trim. FileCheck tolerates `// CHECK:`, so converting a `filecheck=` test to `diag=` (PR #12138) turns spaced lines dead. If a block annotation still asserts the message, a dropped line is a test-quality gap, not a nullified test (with unrun CI, an OPEN_GAP abstain) ([diag= annotations need NO space after //](../learnings/1784223037335-approver-challenger-miss-averted-slang-diag-check-.md)).

**CHECK tokens: inert in DIAGNOSTIC_TEST, live under `filecheck=`.** The DIAGNOSTIC_TEST parser accepts only lines starting exactly `//CHECK:`, so `//CHECK-NOT:` is a plain comment and a "must not warn" negative holds only because the matcher is exhaustive ([//CHECK-NOT: is inert](../learnings/1782900106845-slang-diagnostic-test-check-not-is-inert-negatives.md)). LLVM FileCheck scans the whole file for its prefix whatever the context, so prose that writes `` `CHECK: OpEntryPoint` `` becomes a live directive and fails; use `//<prefix>:` in prose ([filecheck= runner parses CHECK: tokens in prose](../learnings/1782908183110-slang-test-filecheck-runner-parses-check-tokens-in.md)). Without FileCheck, `grep -nE 'CHECK(-[A-Z]+)?:' file` lists what would be read as directives; check each intended one against real `slangc -target spirv-asm` output.

## Downstream-Compiler Version Gating (metal4.0)

slang-test categories (`slang-test-main.cpp`) gate on OS (`windows`/`unix`), render API (`(mtl)`/`(vk)`) and backend availability, never on the downstream compiler's VERSION. A `//TEST:SIMPLE(filecheck=...): -target metallib -capability metallib_4_0` case therefore RUNS and FAILS (`result code = -1`) wherever a pre-4.0 `metal` is on PATH: the Windows-GPU runners (`C:\Program Files\Metal Developer Tools\metal\macos\bin`) and macos-15; only macos-26 (`macos-latest`) is metal4.0-capable. (On PR #12009 a sibling case at the default 3.1 passed on the same runner.) Assert the Slang-side decision with an emit-only `-target metal -capability metallib_X_Y` FileCheck test (no downstream compiler, runs everywhere); cover downstream behavior with an end-to-end test on `macos-latest`, and say so in the PR ([no category gates a downstream-compiler VERSION](../learnings/1784061153981-slang-test-has-no-category-to-gate-a-downstream-co.md)). A `-target metallib` directive is only a macOS acceptance smoke test (`// METALLIB: define {{.*}} @<entry>` asserts only that the entry compiled), so it does not fix a non-discriminating `-target metal` check. When one call site lowers to N identical tokens (`float2x2` via MATRIX_MAP_UNARY), pin it with `// METAL-COUNT-<n>:` or anchor to the destination, since off macOS the METAL text check is the only guard ([metallib directive ≠ FileCheck discrimination](../learnings/1784816898155-metallib-test-directive-filecheck-discrimination-b.md)).

## render-test Arguments and the `-O0` Default

To reproduce a `COMPARE_COMPUTE(_EX)` compile-time abort, run a clean `slangc <file> -target spirv -entry <name> -stage <stage>`; slangc rejects harness flags like `-vk`, `-render-features`, `-output-using-type` (#11766). PR #11805's `-O0` default (`slang-test-optimization-options.h`) applies only on the slang-test path, so bare slangc still optimizes and can still abort (fp8 constants trip spirv-opt `folding_rules.cpp:156`: exit 134 at -O2, 0 at -O0). `-expected-failure-list` (`test-reporter.cpp:168`) only turns Fail into ExpectedFail, never Pass into Fail, so a stale entry silently masks regressions; verify without the list ([reproducing render-test aborts with standalone slangc](../learnings/1783043861186-reproducing-slang-test-render-test-aborts-with-sta.md)). The harness FRONT-inserts the level (`-O0`; `-Xslang -O0` render; `-Xslang -O1` Metal) when none is present, so removing an explicit `-O0` is output-neutral; `-O1`–`-O3` are real (#11919, PR #11923). In bulk edits touch only lines starting `//[A-Za-z_:]*TEST`, remove the token with its own whitespace only (`git diff --check` misses internal double spaces), and drop `-Xslang -O0` pairs before bare `-O0` ([removing explicit -O0 from directives](../learnings/1783047481430-removing-explicit-o0-from-slang-test-test-directiv.md)).

render-test rejected `-Xdxc -Vd` until slang#12121 (PR #12128, merge `814ab6dda9`), so tests tunneled `-Xslang... -Xdxc -Vd -X.`. The fix has two parts; the first alone is a false-pass trap. **Accept:** construct `Options`' `DownstreamArgs` with the `CommandLineContext` from `Options::parse`, whose ctor auto-registers every `SLANG_PASS_THROUGH_*` name plus "downstream"/"linker" — then re-add `"slang"`, which is not a pass-through enum value, or every `getArgsByName("slang")` asserts ([DownstreamArgs auto-register ctor excludes "slang"](../learnings/1784149707201-render-test-downstreamargs-auto-register-ctor-excl.md)). **Forward:** render-test reads only the "slang" bucket (`_compileProgramImpl` in slang-support.cpp and the render-test-main.cpp matrix-layout scan), so `_compileProgramImpl` re-emits each other bucket as single-option `-X<name> <value>` pairs into `parseCommandLineArguments`. A green run does not prove forwarding; a bogus `-Xnvrtc`/`-Xgcc` through a `-cpu`/NVRTC test discriminates ([accept AND forward are two separate fixes](../learnings/1784173490784-render-test-x-compiler-args-accept-and-forward-are.md)). In the ~55-directive migration review, check each `-X<name>`: only downstream-compiler args (`-Xdxc`, `-Xnvrtc`) may be de-tunneled, while Slang's own options inside the wrapper (`-Xslang... -fvk-use-dx-layout -X.` in `tests/hlsl/cbuffer-float3-offsets-aligned.slang`) must stay. Mis-migration fails loudly, since render-test rejects unknown flags ([verify -X<compiler> migrations by slang-bucket vs downstream-bucket](../learnings/1784156876047-approver-challenger-win-verify-render-test-x-compi.md)).
