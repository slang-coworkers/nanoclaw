# Slang Test Harness — Test Directives and Authoring

> Siblings: [Harness Internals and In-Process Unit Tests](slang-test-harness-internals-and-unit-tests.md) · [Output Assertions and Truncated Runs](slang-test-output-assertions-and-truncated-runs.md).

This part covers **which directive to write and how**. Running the harness and its false-green traps are in [False Greens and Verification Discipline](slang-test-false-greens-and-verification-traps.md); FileCheck mechanics are in [FileCheck Authoring and Opt-Levels](slang-test-filecheck-authoring-and-opt-levels.md); silently inert misspelled directives are in [Inert Directives and Vacuous Tests](slang-a-test-harness.md); the `-dx12` empty-output trap (`-use-dxil` is not a slang-test flag, error 1004) is in [Runtime Shims and DX12 Lanes](slang-test-runtime-shims-and-vm.md).

## TL;DR

- **`//TEST_IGNORE_FILE` on line 1 skips the whole file**, so its `.expected` is never exercised.
- **The grammar is `//TEST[(<category>)]:<COMMAND>`** — discovery that ignores the optional category silently misses `//TEST(smoke):…`.
- **`//TEST:INTERPRET` is silently skipped without slangi**, so GPU-free coverage uses `//TEST:COMPARE_COMPUTE(filecheck-buffer=CHECK):-cpu -output-using-type`; with slangi, INTERPRET beats `SIMPLE` for a front-end fix.
- **`//TEST:LANG_SERVER` never publishes diagnostics** and the workspace API is unexported: verify LSP diagnostic bugs by an A/B probe of real slangd.
- **`//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK):` uses the built-in matcher, not FileCheck, and is exhaustive by default.**
- **Annotations take NO space after `//`** — `// CHECK_ERR:` is silently a plain comment.
- **`//CHECK:` is 8 characters, so carets start at column 9**; copy the harness's suggested annotations and match by error code.
- **Each diagnostic emits one or two `E<code>` rows**: E31202 and E55202 need two annotations, E30702 exactly one.
- **`//CHECK-NOT:` is inert under DIAGNOSTIC_TEST; under `filecheck=` every `CHECK:` token is live, prose included.**
- **`<file>.slang.N` is the (N+1)th `//TEST:` directive, not a retry counter**, and a flake's identity is the (subtest index, target, failure mode) tuple.
- **Skip a crashing synthesized subtest pre-expansion with `-exclude-prefix`/`-skip-list`**; matching one expanded variant needs the full `testName`.
- **Skip-list entries also match unit tests by case-sensitive name prefix**; list the matches with `-v` and read each body before describing the set.
- **slang-test synthesizes CUDA (and D3D/Metal/WGPU) rows by default**, so "no `-cuda` line" is not "no CUDA coverage"; check `slang-test <file> -v | grep syn`.
- **A harness-scheduling PR needs no `.slang` test** — use a `slang-unit-test` over extracted helpers, with `-dry-run` as acceptance.
- **Recommend a test shape against the BUILD graph**: a symbol inside a tool's `main.cpp` is unlinkable, so a subprocess test (which also tests the exit code) is the only option.
- **A "no downstream-compiler path" unit test uses a concrete pass-through (`GCC`/`CLANG`/`VISUAL_STUDIO`), never `GENERIC_C_CPP`.**
- **Delete `*.slang.actual.txt` before `git add`; a NEW `.expected` needs `git add -f`; `.32` goldens never run in CI.** Only bare `//TEST:REFLECTION:` uses a golden.
- **No category gates a downstream compiler's VERSION**: assert the Slang-side decision with an emit-only, self-discriminating `-target metal` FileCheck test; `-target metallib` is only a macOS smoke test.
- **slang-test FRONT-inserts `-O0` into any directive lacking `-OX`**, so a standalone `slangc` repro needs `-O0` explicitly.
- **render-test compiles with debug info ON unless the directive says `-g0`**; a test that depends on dead-code removal needs `-g0`.
- **render-test `-X<compiler>` support is two fixes, accept and forward**; migrations keep Slang's own options inside `-Xslang...`.

## Directive Grammar, Golden Files, and Artifacts

The directive grammar is `//TEST[(<category>)]:<COMMAND>`, so a discovery pattern must allow the optional category. On #12225 (a field added to every reflection-JSON layout) `//[[:space:]]*TEST:(CPU_)?REFLECTION` found 60 files where `//[[:space:]]*TEST(\([^)]*\))?:(CPU_)?REFLECTION` found 68, so the PR passed "99/99 local" and failed `test-slang` cross-platform on the 8 missed tests: a deterministic cross-platform failure right after a golden change means incomplete regeneration, not a compiler bug. Reflection tests run via `slang-test <files>`, whose `.actual` on mismatch is the bless source. `.expected` matches a global gitignore (`*.expected`), so a NEW golden needs `git add -f` ([golden discovery must tolerate the TEST(category): suffix](../learnings/1785070091132-slang-test-reflection-golden-test-discovery-must-t.md)).

Only bare `//TEST:REFLECTION:...` tests have a whole-output `foo.slang.expected` to regenerate; `//TEST:REFLECTION(filecheck=CHECK):...` inlines `//CHECK:` lines (~43 of ~68 reflection files are golden). A top-level key (emitted by `emitReflectionJSON` for every target) touches every JSON golden; a comment- or rename-only C++ change needs no regen. `.32`/`.64` CPU_REFLECTION variants are selected at compile time by `SLANG_PTR_IS_32` and no CI job runs 32-bit, so a `.32.expected` drifts stale unvalidated; leaving one un-regenerated is benign (cpp-resource-reflection's already was). `//TEST_IGNORE_FILE` on line 1 clears the test list (`slang-test-main.cpp:664`), so that file's `.expected` is never exercised ([reflection .expected: filecheck vs golden, and the .32 CI-blind spot](../learnings/1785548558845-reflection-expected-baseline-filecheck-vs-golden-a.md)).

`slang-test` writes `*.slang.actual.txt` beside each test; delete them before `git add`. New test directories show in `git status`, not `git diff master`, until added ([slang-test leaves .actual.txt artifacts](../learnings/1781088712827-slang-test-leaves-slang-actual-txt-artifacts-in-th.md)).

## Subtest Naming, Selection, and Flake Identity

slang-test names the first `//TEST:` directive `foo.slang` and the rest `foo.slang.1`, `foo.slang.2`, … in file order: a deterministic directive index, not a retry counter (`runTestsOnFile`, `slang-test-main.cpp:5099-5122`; `insertSubtestIndex` :4926). Only `COMPARE_COMPUTE`/`-vk`/`-cuda` runtime subtests can be GPU-nondeterministic; SIMPLE/spirv-asm/DIAGNOSTIC ones cannot. On slang#11595 the fixer twice dismissed `gh-9931.slang.1` as a GPU flake, but directive `.1` is the deterministic `computeMainNV` spirv-asm `CHECK_NV` check, which the PR's new E41303 alignment contract broke on every run (`Store<DescriptorHandle>(4, h, 8)`, `4 % 8 ≠ 0`, became a hard error → empty output). Before calling a `.N` failure flaky, read the (N+1)th directive's entrypoint, target and CHECK prefix and ask whether your change reaches it; reproduce on that entrypoint (grepping the passing `computeMain` masked the failure) and trust a local `FAILED test:` over a hand grep ([.slang.N maps to the Nth TEST directive](../learnings/1784249706016-slang-test-slang-n-suffix-maps-to-nth-test-directi.md), [.slang.N is the (N+1)th directive, not a flaky-run index](../learnings/1784269637732-slang-test-slang-n-is-the-n-1-th-test-directive-no.md)).

To skip a crashing synthesized variant (e.g. LLVM JIT), use `-exclude-prefix`/`-skip-list`, which filter on source path before expansion; expected-failure lists run the test first ([synthesized subtest skip needs pre-run exclusion](../learnings/1780314391657-slang-test-synthesized-subtest-skip-needs-pre-run-.md)). Matching one expanded variant needs exact equality on the full assembled `testName`, including ` syn` and ` (<api>)`; `getSubtestIndex` and `-test-prefix` match only the index-level stem ([matching an expanded subtest name needs exact testName equality](../learnings/1780318208555-slang-test-matching-an-expanded-subtest-name-needs.md)).

**Skip lists reach unit tests too, by case-sensitive name prefix.** A unit test's key is `slang-unit-test-tool/<TestName>.internal` (`makeUnitTestKey`, `test-reporter.cpp:16`), checked by the same `shouldRunTest` `String::startsWith` loop against each `tests/skip-list-*.txt` entry: `slang-unit-test-tool/testServer` matches the seven `testServerLoss*`/`testServerProtocolError*` tests but not `TestServerParentMonitor*`. `tests/skip-list-debug.txt` is added by every `config: debug` CI job and by no Release job ([skip lists target unit tests by name prefix](../learnings/1792574620099-slang-test-skip-lists-can-target-unit-tests-by-nam.md)). A prefix selects by name, not by the property the PR claims: on PR #13812 three prefixes matched 12 tests offered as "slow process-spawning", but `testServerLossConsolidatesAcrossReporters` is an in-process check and `testServerLossReportsTheKillingSignal` is `SLANG_IGNORE_TEST` outside `SLANG_UNIX_FAMILY`, so "Release jobs on all 3 OSes still run all 12" was false for Windows. List the matches with `slang-test -v -skip-list <file> <prefixes>` and open each matched `SLANG_UNIT_TEST` body before writing a collective claim. (The CMake target is `slang-unit-test`; `slang-unit-test-tool` is only the `.so` name, and a fresh `git worktree` needs `git submodule update --init --recursive` before configuring) ([skip-list prefixes match names, not cost](../learnings/1792577135861-skip-list-prefixes-match-test-names-not-cost-check.md)).

**A `-cpu` row can add a synthesized CUDA row that no directive names.** `tools/slang-test/options.h:128` defaults `synthesizedTestApis = AllOf & ~(Vulkan | CPU)`, so CUDA (and D3D/Metal/WGPU where available) is synthesized unless a directive covers it; the "CUDA is disabled by default" comment above it is stale. `_calcSynthesizedTests` builds the `<test>.N syn (cuda)` row (`render-test … -cuda`, same buffers and filecheck) from a source row whose explicit API is CPU, when no directive in the file names `-cuda` (details on [misc-f0909b3-slang-test-verification](misc-f0909b3-slang-test-verification.md)). Reviewers on #13815 and #13874 flagged "CUDA coverage absent" although the `syn (cuda)` variants ran and passed. The #13874 review also misflagged a `{{OpFDiv|OpFMul}}` alternation as dead: Slang folds `b /= 2.0` to `OpFMul %b %float_0_5` by default and emits `OpFDiv` only at `-O0`, so a CHECK that must hold at both levels needs it ([slang-test synthesizes CUDA rows by default](../learnings/1792694250314-slang-test-synthesizes-cuda-rows-by-default-no-cud.md)).

A flake's identity is the (subtest index, target, failure mode) tuple, not the test name. `static-const-matrix-array.slang` has two unrelated signatures: **Sig-A** `.slang.1 (vk)`, a Vulkan GPU numeric/crash flake surviving harness retry, and **Sig-B** `.slang.3 syn (llvm)`, a test-server `JSON RPC failure: waitForResult()/hasMessage()` drop (first on #11922, run 28642587133). Cite run-ids per tuple ([static-const-matrix-array: two distinct flake signatures](../learnings/1783066436944-static-const-matrix-array-two-distinct-flake-signa.md)). #11951 (Sig-B) was closed as fixed by #12056 (AVX-512 JIT workaround), yet merge_group run 29390282163 evicted the unrelated PR #12064 with `SLANG_DISABLE_AVX512=1` active, on a genuine `FAILED` `.slang.3 syn (llvm)` (plus a `gh-5900.slang.1 syn (llvm)` drop) on a Windows release GPU lane. So the export does not rule Sig-B out (it spans debug and release GPU tiers); with no SIGILL in the log, claim "fix-gap real", not "residual AVX-512". A fix-gap receipt needs the export active, a genuine FAILED and an unrelated PR; a contaminated run (#12105, failing its own tests) leaves the hypothesis unproven, not disproved ([#11951 Sig-B fix-gap confirmed post-#12056](../learnings/1784103591814-11951-sig-b-fix-gap-confirmed-post-12056-avx-512-n.md)).

## Choosing the Test Vehicle

**Harness changes.** A slang-test scheduling PR (selection, exclusion, subtest expansion) needs no `.slang` test, since no directive can assert which subtests run; `-dry-run` is valid acceptance. The vehicle is a `slang-unit-test`, usually after extracting the file-local `static` helpers in `slang-test-main.cpp` into a linkable library (precedent: `unit-test-test-tool-util.cpp`) ([harness changes: slang-unit-test is the right vehicle](../learnings/1780320008141-slang-test-harness-changes-slang-test-rule-n-a-but.md)).

**Check the BUILD graph, not just the call graph.** On #12212 triage recommended an in-process `slang-unit-test` of `CapabilityDefParser::parseDefs() → SLANG_FAIL`, but the parser lives only in `tools/slang-capability-generator/capability-generator-main.cpp`, which `tools/CMakeLists.txt:80` builds as an executable with no library target. The shipped fix (PR #12217) used a subprocess test (`unit-test-capability-generator.cpp`) asserting the diagnostic, a nonzero exit and no output files. That was better coverage: the bug was the tool exiting 0 after an error, and when a *tool* misbehaves the process is the unit under test. Before recommending a shape, `git grep -l '<Symbol>'` and check its CMake target. A "tool fails" test must fail through the diagnostic under test: a bare `def _foo : stage;` fails with 20003 (undefined identifier), an already-nonzero path, so the repro declares `abstract stage;` first to reach 20007 and greps stderr for it. The generator lives in `build/generators/<config>/bin/`, so the test walks from `UnitTestContext::executableDirectory` via `../../generators/<config>/bin/` and `SLANG_IGNORE_TEST`s when absent; model it on `unit-test-depfile.cpp`; unit-test `.cpp` files auto-glob into `slang-unit-test` ([check the BUILD graph before recommending a test shape](../learnings/1785840805944-check-the-build-graph-not-just-the-call-graph-befo.md)).

**INTERPRET / slangi.** INTERPRET tests are silently skipped when slangi is not built, so reliable GPU-free regression uses `COMPARE_COMPUTE` with `-cpu` ([INTERPRET silently skipped without slangi](../learnings/1781222721953-slang-test-ignores-interpret-slangi-tests-when-sla.md)). With slangi, `//TEST:INTERPRET(filecheck=CHECK):` beats `//TEST:SIMPLE:` for a front-end fix whose repro needs a GPU path (e.g. a buffer-device-address pointer): swap in a local pointer. `struct Foo { int Bar<int N>(){return N;} }; void main(){ Foo f; Foo* foo=&f; printf("%d\n", foo->Bar<42>()); } //CHECK: 42` proves the generic argument binds to the right value and avoids SIMPLE's empty-stderr brittleness; it still errors 30101 on master, so it is a real guard (#9810 / PR #12892). Before writing "how to add a test" guidance on a contributor's PR, fetch its current files (`gh pr view <n> --json files,commits,headRefOid`), since a test may already be committed ([front-end pointer/generic fixes: test via INTERPRET, check PR state first](../learnings/1788396349246-front-end-pointer-generic-fixes-regression-test-gp.md)).

**LANG_SERVER cannot observe diagnostics.** `//TEST:LANG_SERVER` drives hover/completion/signature, but slang-test runs slangd with `-periodic-diagnostic-update false`, and `didOpen`/`didChange`/`didClose` call `resetDiagnosticUpdateTime()` just before `publishDiagnostics()`, whose 1000 ms throttle then returns early; nothing is published, so `//DIAGNOSTICS` (used by zero tests) deadlocks ([LANG_SERVER harness cannot observe diagnostics](../learnings/1781083469573-CONSOLIDATED-langserver-harness-cannot-observe-diagnostics.md)). `Slang::Workspace`/`getOrLoadModule` are unexported from the DLL, so no unit test can drive the workspace either; PR notes say "manual-probe-confirmed, no automated regression possible" (a clean `slangc` compile does not guard the LS path) ([LS diagnostics cannot be auto-tested](../learnings/1781086523456-slang-ls-diagnostics-cannot-be-auto-tested-lang-se.md)). Verify an LSP diagnostics bug by A/B of real slangd's published set: #11531/#11532 went control 4 → narrowed #11534 fix 4 → broadened 0, because #11532's extension is file-scope and the fix must drive every module-level `NamespaceDecl` to ScopesWired before the extension-first pass ([CORRECTION: LANG_SERVER can't observe diagnostics (re #11532)](../learnings/1781116005493-correction-test-lang-server-harness-can-t-observe-.md)).

**Downstream-compiler "no path" unit tests.** A test expecting `IGlobalSession::getDownstreamCompilerPath` → `SLANG_E_NOT_AVAILABLE` must not use `SLANG_PASS_THROUGH_GENERIC_C_CPP`: `Session::getOrLoadDownstreamCompiler(GenericCCpp)` loads Clang/Gcc/VisualStudio and LLVM and then picks `getDefaultCompiler(CPP)`, which can be the prebuilt `slang-llvm` → flaky `SLANG_OK`. Loop over `GCC`/`CLANG`/`VISUAL_STUDIO`, gated on `checkPassThroughSupport`; each yields a `CommandLineDownstreamCompiler` with no `getPath` override. To prove an out-param is untouched on failure, seed a non-null sentinel raw pointer (a null `ComPtr` cannot tell "untouched" from "cleared"). To prove a returned path is the loadable library, reload it and `findSymbolAddressByName` an entry point (NVRTC `nvrtcVersion`, glslang `glslang_compile*`) (#12838 / PR #12841; [testing "no path": avoid GENERIC_C_CPP](../learnings/1788246202939-testing-downstream-compiler-no-path-slang-e-not-av.md)).

## DIAGNOSTIC_TEST(diag=CHECK) Authoring

`//DIAGNOSTIC_TEST:SIMPLE(diag=CHECK):` uses Slang's built-in annotation matcher, so it runs locally even without FileCheck. It is exhaustive by default (an unannotated diagnostic fails "Exhaustive check failed"; `(diag=CHECK,non-exhaustive)` opts out). Carets sit under the reported column, and `//CHECK:` is 8 characters starting at column 1 even in indented source, so copy the harness's "Suggested annotations you can copy" line rather than hand-computing. Because the caret column counts the prefix, renaming a prefix (e.g. `//MERGED:` → `//SHARED_TYPE:`) shifts every caret by the length difference ([Slang: removeUnusedGenericParam merges types whose witnesses differ; FileCheck -NEXT fails on slang-test HLSL](../learnings/1792845935161-slang-removeunusedgenericparam-merges-types-whose-.md)). A repro needing a module-wide diagnostic (recursion rejected by E55201 unless `-disable-non-essential-validations`) goes in its own file ([DIAGNOSTIC_TEST(diag=CHECK) authoring](../learnings/1781787235055-slang-diagnostic-test-diag-check-authoring-exhaust.md)).

**Row counting.** Each diagnostic emits a title row and a primary-span row, both prefixed `E<code>` (`diagnostic-annotation-util.cpp:266`); the span row is dropped only when code, file, location and message all match the title (`isDuplicatePrimarySpan`, :299-317). A standard `err("name", CODE, "TITLE", span{message=...})` thus yields two rows, and an alternating "unannotated" suggestion is the tell (PR #11883: two DuplicateModifier diagnostics → four `E31202` rows). A bare `//CHECK: E31202` matches the code alone; pair it with a caret span (`//CHECK: ^^^ message`) to pin location and message ([E-code row count = 2× diagnostics](../learnings/1782910333196-diagnostic-test-simple-diag-check-e-code-row-count.md)). Over-annotating fails too: on #13619 E55202 needed two carets, while E30702 writes one row, so a second caret or a combined `error E30702: <message>` fails "(already matched)". A legalizer diagnostic on a struct field reports at the struct's NAME (use a `/*PREFIX:` block under `struct X`); on a legalized global varying, at Line 0 (use a caret-less substring) ([E30702 needs one annotation, E55202 two](../learnings/1791972892553-slang-diagnostic-test-e30702-needs-one-caret-annot.md)).

**No space after `//`.** `diagnostic-annotation-util.cpp:85` builds the marker as `"//" + prefix + ":"` and line 181 tests `trimmedLine.startsWith(lineMarker)`, so `// CHECK_ERR:` is silently dropped; the block form `/*CHECK_ERR:` is matched after trim. FileCheck tolerates `// CHECK:`, so converting a `filecheck=` test to `diag=` (PR #12138) turns spaced lines dead. If a block annotation still asserts the message, a dropped line is a test-quality gap, not a nullified test (with unrun CI, an OPEN_GAP abstain) ([diag= annotations need NO space after //](../learnings/1784223037335-approver-challenger-miss-averted-slang-diag-check-.md)).

**CHECK tokens: inert in DIAGNOSTIC_TEST, live under `filecheck=`.** The DIAGNOSTIC_TEST parser accepts only lines starting exactly `//CHECK:`, so `//CHECK-NOT:` is a plain comment and a "must not warn" negative holds only because the matcher is exhaustive ([//CHECK-NOT: is inert](../learnings/1782900106845-slang-diagnostic-test-check-not-is-inert-negatives.md)). LLVM FileCheck scans the whole file for its prefix, so prose that writes `` `CHECK: OpEntryPoint` `` becomes a live directive; use `//<prefix>:` in prose, and without FileCheck run `grep -nE 'CHECK(-[A-Z]+)?:' file` to list what would be read as directives ([filecheck= runner parses CHECK: tokens in prose](../learnings/1782908183110-slang-test-filecheck-runner-parses-check-tokens-in.md)). In SIMPLE HLSL output, `CHECK-NEXT` fails across the blank and `#line` lines slang-test's output contains; to stay inside one function body, use `CHECK-NOT: }` followed by a plain `CHECK:` ([Slang: removeUnusedGenericParam merges types whose witnesses differ; FileCheck -NEXT fails on slang-test HLSL](../learnings/1792845935161-slang-removeunusedgenericparam-merges-types-whose-.md)).

## Downstream-Compiler Version Gating (metal4.0)

slang-test categories (`slang-test-main.cpp`) gate on OS, render API (`(mtl)`/`(vk)`) and backend availability, never on the downstream compiler's VERSION. A `//TEST:SIMPLE(filecheck=...): -target metallib -capability metallib_4_0` case therefore RUNS and FAILS wherever a pre-4.0 `metal` is on PATH — the Windows-GPU runners and macos-15 — and only macos-26 (`macos-latest`) is metal4.0-capable (PR #12009). Assert the Slang-side decision with an emit-only `-target metal -capability metallib_X_Y` FileCheck test that runs everywhere, and cover downstream behavior end-to-end on `macos-latest` ([no category gates a downstream-compiler VERSION](../learnings/1784061153981-slang-test-has-no-category-to-gate-a-downstream-co.md)). A `-target metallib` directive is only a macOS acceptance smoke test (`// METALLIB: define {{.*}} @<entry>` asserts only that the entry compiled), so it does not fix a non-discriminating `-target metal` check: when one call site lowers to N identical tokens (`float2x2` via MATRIX_MAP_UNARY), pin it with `// METAL-COUNT-<n>:` or anchor to the destination, because off macOS the METAL text check is the only guard ([metallib directive ≠ FileCheck discrimination](../learnings/1784816898155-metallib-test-directive-filecheck-discrimination-b.md)).

## render-test Arguments and the `-O0` Default

To reproduce a `COMPARE_COMPUTE(_EX)` compile-time abort, run a clean `slangc <file> -target spirv -entry <name> -stage <stage>`, since slangc rejects harness flags like `-vk`, `-render-features`, `-output-using-type` (#11766). PR #11805's `-O0` default applies only on the slang-test path, so bare slangc still optimizes and can still abort (fp8 constants trip spirv-opt `folding_rules.cpp:156`: exit 134 at -O2, 0 at -O0). `-expected-failure-list` (`test-reporter.cpp:168`) only turns Fail into ExpectedFail, never Pass into Fail, so a stale entry silently masks regressions; verify without the list ([reproducing render-test aborts with standalone slangc](../learnings/1783043861186-reproducing-slang-test-render-test-aborts-with-sta.md)). The harness FRONT-inserts the level (`-O0`; `-Xslang -O0` for render; `-Xslang -O1` for Metal) when none is present, so removing an explicit `-O0` is output-neutral, while `-O1`–`-O3` are real (PR #11923). In bulk edits, touch only lines starting `//[A-Za-z_:]*TEST`, remove the token with its own whitespace (`git diff --check` misses internal double spaces), and drop `-Xslang -O0` pairs before bare `-O0` ([removing explicit -O0 from directives](../learnings/1783047481430-removing-explicit-o0-from-slang-test-test-directiv.md)).

**render-test also turns debug info ON by default.** When `generateSPIRVDirectly` is set (the default), `_compileProgramImpl` adds `DebugInformation = STANDARD` unless the directive passes `-g0` (`tools/render-test/slang-support.cpp:276`, `options.cpp:293`). Debug info keeps unused entry-point `uniform` params alive, so a `COMPARE_COMPUTE` lane can diverge from plain `slangc`: since slang#13724, E39033 (more than one push-constant block per entry point) fires under render-test for an entry point that never reads its `uniform` param, while plain slangc accepts it (documented in `tests/diagnostics/multiple-push-constant-blocks-debug-info.slang`). A test that depends on dead-code removal adds `-g0` ([render-test compiles with debug info by default; use -g0](../learnings/1792599051218-render-test-compiles-with-debug-info-by-default-us.md), slang-rhi#915).

render-test rejected `-Xdxc -Vd` until slang#12121 (PR #12128), so tests tunneled `-Xslang... -Xdxc -Vd -X.`; the fix has two parts, and the first alone is a false-pass trap. **Accept:** construct `Options`' `DownstreamArgs` with the `CommandLineContext` from `Options::parse`, whose ctor auto-registers every `SLANG_PASS_THROUGH_*` name plus "downstream"/"linker", then re-add `"slang"` (not a pass-through enum value), or every `getArgsByName("slang")` asserts ([DownstreamArgs auto-register ctor excludes "slang"](../learnings/1784149707201-render-test-downstreamargs-auto-register-ctor-excl.md)). **Forward:** render-test reads only the "slang" bucket, so `_compileProgramImpl` re-emits each other bucket as single-option `-X<name> <value>` pairs into `parseCommandLineArguments`. A green run does not prove forwarding; a bogus `-Xnvrtc`/`-Xgcc` through a `-cpu`/NVRTC test discriminates ([accept AND forward are two separate fixes](../learnings/1784173490784-render-test-x-compiler-args-accept-and-forward-are.md)). In a migration review, only downstream-compiler args (`-Xdxc`, `-Xnvrtc`) may be de-tunneled; Slang's own options inside the wrapper (`-Xslang... -fvk-use-dx-layout -X.`) must stay, and mis-migration fails loudly because render-test rejects unknown flags ([verify -X<compiler> migrations by slang-bucket vs downstream-bucket](../learnings/1784156876047-approver-challenger-win-verify-render-test-x-compi.md)).
