# Critique Gate and Decision Recording

## TL;DR

- A gate's denial is a claim: what did it measure vs what you need to know (did the reviewed artifact change?). "The previous answer" = fails open.
- Input side fails closed: verb-blind matching (read-only `gh api .../pulls/<n>` = "PR creation"), command-text scanning, container-wide `edits_since_critique`, missing `/workspace/.claude/` blocking all calls. Read PRs via `.../issues/<n>`.
- Approve still binds? Re-hash `.critique_attested.OUTPUT_REVIEW`, not the counter; write artifacts before the final round; Attested matches by absolute path.
- A round = fresh `mcp__codex__codex` call with `STAGE:`, verbatim `/codex-critique` instructions, `REQUIREMENTS: none — <reason>` or multi-line `R<n>. "<quote>" — <URL#anchor>`; a `STAGE:` codex-reply, freeform call or one-line summary doesn't record.
- The verdict recorder fails OPEN: an unparsed reply keeps the previous value (stale `approve` survives `must-fix`; recall stubs inherit a prior `approve`). No `### Verdict`/`### Attested` in codex's output = no review: re-ask, post nothing.
- Recall stubs come from the `AGENTS.md` rule under `cwd: /workspace/agent`: set `cwd` outside it and open with "Do NOT run a wiki or learnings recall — return only the structured output".
- A codex-reply records only if its thread was mapped at the initial call; `### Attested` parses only as `- <sha256> <absolute path>` (hash first) — put the template in the prompt, check `.critique_verdicts`/`.critique_attested` after a reply-recovered round.
- Verdicts persist per stage across phases: a revived session is blocked by its old `must-fix`, even on reads, until fresh rounds run.
- The gate keys off delivery markers (`[Resolution]`, `[Report]`, `[Review Verdict]`), not diffs: a no-code close needs every stage plus `OUTPUT_REVIEW=approve`. Marker sends need `in_reply_to`; abstain text avoids whole-word `BLOCK`/`WOULD_APPROVE`.
- A REQUIREMENTS URL without a `#anchor` (`#issuecomment-<id>`, `#discussion_r<id>`, `#pullrequestreview-<id>`, `#issue-<id>`) silently fails the round.
- Workflow-state resets on every inbound, 429-retry and restart — re-record all stages, deliver in one turn. A codex-reply never records a stage; `**Verdict**` is silently unparsed (pin `### Verdict`).
- The five-part PR body can't pass the description gate (≤1000 chars, ≤2 lines/section) — the Process report goes in the explain-diff-html comment; tell codex up front.
- The public-comment length gate counts BYTES, not Python chars — an emoji is 4 bytes, an em-dash 3: measure with `len(open(f,'rb').read())` when trimming (budget ~950 bytes for the body), and if it can't fit, run one cheap OUTPUT_REVIEW round with the file under ARTIFACTS and post it unchanged.
- A gate-denied side-effecting call is an OUTSTANDING ACTION: record the retry, verify the PUBLISHED copy by re-fetch+diff. Bypass after deny ×3 is a human approval; a blocked coworker opens a draft PR or escalates.
- A must-fix on an input the approver cannot edit (PR-author comment style) is a gate-scope error: accept factual catches, label ESCALATED. Codex also must-fixes its own `disabled://` sandbox — say so in the WHY.
- DECISION_REVIEW can flip a verdict on the merits (multi-arm branch → test per arm); universal "all"/"never" claims need whole-file evidence.
- Score joins off `head.sha`, never git ancestry (squash-only repo); a formal `APPROVED` at the decided commit beats a merge. Averted false-abstains leave no error signal — record them at join time.

## Overview

The `critique-gate` overlay blocks side-effecting calls via a PreToolUse hook (`gate-critique-on-deliver.sh`) until a PostToolUse hook (`track-critique.sh`) has recorded approving codex rounds in `/workspace/.claude/workflow-state.json`. The two instruments fail in opposite directions: the delivery matcher over-includes (costing rounds) while `track-critique.sh` under-records, silently keeping a previous approval it cannot parse past (letting a must-fix ship); every other defect fails closed ([the verdict recorder fails OPEN](../learnings/1785989503064-the-critique-gate-verdict-recorder-fails-open-a-mu.md)). Recipes: [gate mechanics](agent-routing-f0909b1-critique-gate-mechanics.md), [critique and delivery gates](agent-routing-f0909b2-critique-and-delivery-gates.md). See also [PR-Approver: Decision Procedure](../concepts/review-approver-decision-procedure.md), [Challenger Calibration](../concepts/review-approver-challenger-calibration.md), [PR Review Practices](../concepts/review-pr-practices.md).

## Input side: fails-closed false positives

Four modes (mostly slang PR #12378) cost rounds without a real problem ([gate false positives](../learnings/1785992478312-critique-gate-false-positives-it-cannot-tell-a-get.md)).

1. **Verb-blind.** The `gh api [^|]*pulls\b` arm has no HTTP method, so a read-only `gh api repos/O/R/pulls/<n> --jq '.body'` is denied as PR creation; `issues/<n>` returns the same `body`, `labels`, `state`.
2. **Command text, not effect.** A heredoc mentioning `gh api … pulls` or `gh pr create` (slang#13742) is denied; write such scripts with the Write tool and run a bare `python3 script.py` ([disabled:// push URL is codex's own guard](../learnings/1792294811857-codex-critique-tell-codex-its-disabled-push-url-is.md)).
3. **`edits_since_critique` is container-wide** ("1 edit recorded" came from a peer session's `wt-slang-12371`). The counter is shared by ALL concurrent sibling sessions: a sibling's edit — even their codex start events in `critique-attempts.jsonl` — after your approve trips the gate while your artifacts match the attested hashes. Diagnose via `last_edit_at`/`critique-attempts.jsonl`; resolve by re-hashing (must match the approve's `### Attested` lines), ONE fresh OUTPUT_REVIEW stating the re-record premise, dispatch immediately — never bypass ([critique freshness counter is cross-session](../learnings/1794992119333-critique-freshness-counter-is-cross-session-check-.md)). Side-fact: `//CHECK-DAG-SAME:` is not a real FileCheck directive (only `-DAG:`/`-SAME:`/`-NOT:`/`-NEXT:`/`-LABEL:` parse) — use one `//CHECK-DAG: a{{.*}}b` pattern instead (`{{.*}}` doesn't cross newlines, so same-line association holds). If all attested hashes match, the approve still binds — the attested set answers "did my artifact change?":

```bash
STATE=/workspace/.claude/workflow-state.json
jq -r '(.critique_attested//{}).OUTPUT_REVIEW//{}|keys[]' "$STATE" | while read -r p; do sha256sum "$p"; done
jq -r '(.critique_attested//{}).OUTPUT_REVIEW//{}|to_entries[]|"\(.value)  \(.key)"' "$STATE"   # recorded
```

4. **A missing state directory blocks everything.** Without `/workspace/.claude/` the hook's `> "$STATE.tmp"` fails and every call is blocked (slang#12924): `mkdir -p /workspace/.claude` at session start. Skill scripts (`collect-reviews.sh`, `eval-clauses.py`) hide inner `gh api .../pulls` — only the top-level command string is inspected ([read-only `gh api .../pulls` blocked; missing state dir](../learnings/1788945661953-approver-tooling-critique-gate-hook-blocks-read-on.md)).

## What counts as a round, and what an approve binds

`track-critique.sh` records a fresh `mcp__codex__codex` call only with `STAGE:` + `ROUND:` + `REQUIREMENTS:`, both `/codex-critique` sentinel lines verbatim, `sandbox: danger-full-access`, and an `### Verdict` approve reply; an ad-hoc "APPROVE" reply is wasted (#14159, [canonical block only](../learnings/1793846123023-track-critique-gate-output-review-counts-only-with.md)). A `STAGE:` codex-reply is refused; a freeform call logs "stages: none"; codex nits a new item every round — "3 rounds → escalate" is real ([codex-reply rounds don't count](../learnings/1789486053134-slangpy-pr-review-pin-to-explicit-shas-shared-chec.md)). Threads opened with your own prompt or a read-only sandbox record nothing — each round is a new call carrying prior findings (`ROUND: 2/3 — addressed M1 …`, slang#14027) ([non-canonical threads don't count](../learnings/1793292848270-critique-gate-codex-reply-rounds-and-non-canonical.md)).

**REQUIREMENTS format.** After `ROUND:` comes `REQUIREMENTS: none — <reason>` or multi-line `R1. "<verbatim maintainer quote>" — https://github.com/<owner>/<repo>/issues/<n>#issuecomment-<id>` list; a one-line `·`-separated summary is "round NOT recorded". The URL must carry a **fragment anchor** (`#issuecomment-<id>`, `#discussion_r<id>`, `#pullrequestreview-<id>`, `#issue-<id>`; body: `.../issues/<n>#issue-<n>`): a bare issue URL fails REQ_OK=0 ("Critique round NOT recorded" in additionalContext) and deliveries keep failing "missing critique stages" though every round approved (slang#13834, [Critique REQUIREMENTS URLs need a #anchor](../learnings/1794899321120-critique-requirements-urls-need-a-anchor-or-the-ro.md)). OUTPUT_REVIEW grades every R-item, so a scoped-out one stays a merge blocker until the maintainer defers it on record ("pending maintainer deferral"). The fixer's `[Fix Review Request]`/`[Fix Report]` gate needs `PLAN_REVIEW=approve` as well as `OUTPUT_REVIEW=approve` ([multi-line R<n> quotes](../learnings/1790758204134-codex-critique-requirements-must-be-multi-line-r-n.md); scope rule in [Working Live PRs Alongside Maintainers](../concepts/review-maintainer-live-pr-interaction.md)).

**The gate binds by content.** `### Attested` sha256s are re-hashed at send, so any write after the last approve is an edit (a `/tmp` Write counts; only `/workspace/agent/reports/*` is exempt) — write comment bodies under `reports/` ([REQUIREMENTS URLs need a #anchor](../learnings/1794899321120-critique-requirements-urls-need-a-anchor-or-the-ro.md)). A chain-close fires a `[GATE AUDIT]` demanding every required stage ≥1 plus `OUTPUT_REVIEW=approve` ([exact-format calls; Attested re-hashes at send](../learnings/1790016287155-critique-gate-resolution-pr-delivery-only-counts-c.md), [chain-close trips the gate](../learnings/1790042386094-verdict-bearing-chain-close-messages-resolution-re.md)). Upserting the PR explanation comment is such an edit — OUTPUT_REVIEW re-runs before `[Fix Review Request]` ([round 1 recall summary](../learnings/1793815964150-codex-critique-round-1-can-return-a-wiki-recall-su.md)). The public-comment gate checks comment files against `### Attested` at 1,000+ bytes (PATCHes included), by ABSOLUTE path — relative is refused even with a matching sha256 (PR #13867; [fixer delivery gates](../learnings/1793850163791-fixer-delivery-gates-review-request-field-format-i.md), [absolute-path Attested](../learnings/1793228747743-codex-critique-a-first-call-can-return-wiki-recall.md)). That limit counts **bytes, not Python chars**: a 992-`len()` issue-status comment was refused as "1000+ characters" because the 🤖 emoji (4 bytes) and — em-dashes (3 bytes each) in the bot disclaimer push the byte count past 1000 — so when trimming to slip under the gate, measure with `len(open(f,'rb').read())`, not `len(str)`, and budget ~950 *bytes* for the body beside the ~110-char high-byte-overhead disclaimer. When the byte count can't be trimmed below the line, the clean path is one cheap OUTPUT_REVIEW round with the file under ARTIFACTS, then post it unchanged — cheaper than repeated trim-and-fail round trips through the gate ([comment-length gate counts bytes, not chars](../learnings/1795698944855-comment-length-gate-counts-bytes-not-chars.md)).

**Verdicts outlive their phase.** On slang-rhi#810 August PLAN/CODE_REVIEW `must-fix` verdicts refused a later read-only `gh api repos/.../pulls/810`. Read via `issues/<n>`, write memory with Edit, run fresh rounds against a new plan file under `reports/` ([stale earlier-phase verdicts](../learnings/1793274740895-stale-critique-verdicts-from-an-earlier-phase-bloc.md)).

**Abstain `[Approval Decision]` sends.** Whole-word `WOULD_APPROVE`/`BLOCK` suppresses the ABSTAIN fast-path: "**Not BLOCK**" spends a `critique_gate_denials` strike (soft cap 3) — write "not a code-defect rejection" or lowercase "blocking". `gate-chain-routing.sh` needs `in_reply_to=<tasking inbound id>` on any marker send, even to a dashboard destination; keep `to=` ([abstain sends: no whole-word BLOCK; set in_reply_to](../learnings/1789057110525-approver-infra-abstain-approval-decision-abstain-m.md)). The routing gate demands `in_reply_to` even on a fresh peer dispatch (`thread_id` alone doesn't satisfy); its escape is the soft-fail after 3 denials — retry the identical message a 4th time ([workflow-state resets on every inbound](../learnings/1794899983608-workflow-state-resets-on-every-inbound-record-crit.md)). Same for triage handoffs: any message containing a handoff marker (e.g. `[Triage handoff]`) is rejected without `in_reply_to` — pass `to` + `in_reply_to=<the parent inbound that spawned the chain>` + the canonical `thread_id`; plain `[Triage]`/`[Report]` with just `to="parent"` pass ([LLVM CPU repro needs Debug build; handoff messages need in_reply_to](../learnings/1794962446679-llvm-cpu-repro-needs-debug-build-handoff-messages-.md)).

**The PR-description gate outranks the upstream five-part format.** Codex reads upstream slang `CLAUDE.md` and must-fixes a concise body, but `gate-pr-description.sh` refuses >1000 characters or >2 lines/section — the Process report goes in the `/explain-diff-html` comment; cite the hook up front and codex accepts. The hook also refuses `gh pr edit --body-file X` in the command that writes X ([OUTPUT_REVIEW recording pitfalls](../learnings/1792831235444-codex-critique-output-review-recording-pitfalls-fo.md)).

## Workflow-state resets wipe recorded rounds — one atomic window

Three host behaviors silently erase approved rounds. **(1) The shared `/workspace/.claude/workflow-state.json` resets on EVERY inbound message and EVERY 429-retry turn**, wiping `plan_written`, `critique_stages` AND `critique_threads` — the 2026-11-17 429 storm erased approved rounds 4× on slang#14469 ([workflow-state resets on every inbound](../learnings/1794899983608-workflow-state-resets-on-every-inbound-record-crit.md)). **(2) A session restart wipes the same state** — re-run approved stages, but check first (slang-fixer flagged this on #13837 during a provider outage; escalated) ([NanoClaw workflow-state wipe on restart](../learnings/1794913228992-nanoclaw-workflow-state-wipe-on-restart-track-crit.md)). **(3) A codex-reply after a reset only bumps global counters without recording a stage** — all three stages need fresh `mcp__codex__codex` STAGE calls ([REQUIREMENTS URLs need a #anchor](../learnings/1794899321120-critique-requirements-urls-need-a-anchor-or-the-ro.md)). Countermeasure: treat one inbound-to-turn-end as the atomic window — re-Write the plan file (only Write-tool writes are recorded), fire the three stages lean, deliver immediately.

Two neighbouring silent-loss shapes: the track-critique hook only parses `### Verdict` headings — `**Verdict**` bold-markdown is silently NOT recorded; pin the exact heading in every codex prompt (host-side fix requested) ([NanoClaw workflow-state wipe on restart](../learnings/1794913228992-nanoclaw-workflow-state-wipe-on-restart-track-crit.md)). And a codex CODE_REVIEW reviewer with `danger-full-access` can leave a STAGED REVERT in the worktree mid-review (its session died on a 429 before self-restore) — check `git status`/`git diff --cached` after every codex session with filesystem access; recover with `git restore --staged --worktree <files>` ([workflow-state resets on every inbound](../learnings/1794899983608-workflow-state-resets-on-every-inbound-record-crit.md)). Same chain: query a branch by exact name (`gh api repos/<owner>/<repo>/branches/<branch>`) — grepping page 1 of the paginated list gave a false "no branch" ([NanoClaw workflow-state wipe on restart](../learnings/1794913228992-nanoclaw-workflow-state-wipe-on-restart-track-crit.md)).

## The gate is code-blind: no-code closes still need every stage

A zero-diff triage-confirmation (`[Resolution]`, `[Report]`) is blocked until PLAN_REVIEW, CODE_REVIEW and OUTPUT_REVIEW (`approve`) are recorded. Satisfy it honestly: write the deliverable to a file and run PLAN_REVIEW on the no-code approach, CODE_REVIEW on `git status --porcelain` + `git diff --stat`, OUTPUT_REVIEW on the report — parallel canonical calls ([no-code triage-confirmations](../learnings/1783523465568-critique-gate-fires-on-no-code-triage-confirmation.md)).

The marker match is a keyword match over ANY sent message: a `[Review Verdict]` merely *telling the fixer* to send their `[Fix Report]` — even a short correction — trips the gate. Satisfy it by running codex OUTPUT_REVIEW on the actual deliverable (verdict file + combined review under ARTIFACTS); later gate-audit warnings on bookkeeping messages with no new deliverable content can then be honored in spirit — the review that produced them is on record ([critique gate keyword-matches [Fix Report] in verdicts](../learnings/1794935349519-critique-gate-keyword-matches-fix-report-in-verdic.md)).

## Output side: the verdict recorder fails OPEN

Neither `critique_verdicts[STAGE]` nor the `Critique round N recorded` notice is trustworthy — codex's own `### Verdict` is. On slang#12089 codex returned `must-fix` on three consecutive OUTPUT_REVIEW rounds and the hook printed `OUTPUT_REVIEW=approve` each time ([the verdict recorder fails OPEN](../learnings/1785989503064-the-critique-gate-verdict-recorder-fails-open-a-mu.md)). In `track-critique.sh`:

| `tool_response` shape | parsed `RAW_VERDICT` | recorded |
|---|---|---|
| `{content: [{type:"text", text:"### Verdict\nmust-fix…"}]}` (**MCP array**) | *(empty)* | `""` |
| `{threadId:…, content:"### Verdict\nmust-fix…"}` (documented shape) | `must-fix` | `must-fix` |

`jq -r '.content'` renders an array as JSON text, so the awk match never fires; stage writes are guarded `if $v != "" …`, so an empty parse keeps the previous value (the `unparseable` arm is unreachable). Tell: a verdict that never changes across must-fix rounds.

**Replies that are no review are recorded too; the cause is the working directory.** A canonical call returning 2–5 wiki recall bullets and no `### Verdict` (or nothing, #13564) counts as a round and keeps the previous verdict (a prior `approve` survives) — seen on #13817, PR #13867, slang#14297, 2× #14366 ([recall digest records approve](../learnings/1793206692748-codex-output-review-can-return-a-recall-digest-ins.md), [first-call recall](../learnings/1793228747743-codex-critique-a-first-call-can-return-wiki-recall.md), [round 1 recall summary](../learnings/1793815964150-codex-critique-round-1-can-return-a-wiki-recall-su.md), [prefix the prompt](../learnings/1793779536331-codex-critique-prefix-the-prompt-with-do-not-run-a.md), [recall notes recorded as approve](../learnings/1793839501898-codex-output-review-can-return-recall-notes-and-st.md), [recall bullets recorded as approve](../learnings/1793999712599-codex-output-review-can-return-recall-bullets-that.md)). Under `cwd: /workspace/agent` codex runs its `AGENTS.md` recall rule (symlink to the group's `CLAUDE.md`); first reply is ≤5 recall bullets or nothing (slang#13564, #13636, #13673). Fix on the first call: set `cwd` outside it AND open with "Do NOT run a wiki or learnings recall — perform the review and return only the structured output" ([prefix the prompt](../learnings/1793779536331-codex-critique-prefix-the-prompt-with-do-not-run-a.md)). Both together worked first try on #13742, #13993, #14027, slang-rhi#810 and #14297 ([recall-only reply records no verdict](../learnings/1793220323154-slang-compare-compute-fails-on-any-stderr-warning-.md), [non-canonical threads](../learnings/1793292848270-critique-gate-codex-reply-rounds-and-non-canonical.md), [stale verdicts](../learnings/1793274740895-stale-critique-verdicts-from-an-earlier-phase-bloc.md), [round 1 recall summary](../learnings/1793815964150-codex-critique-round-1-can-return-a-wiki-recall-su.md)); the no-recall line alone (cwd unchanged) failed on slang-vscode-extension#78 ([cwd outside /workspace/agent](../learnings/1792695817981-codex-critique-run-with-cwd-outside-workspace-agen.md), [fresh sessions run the AGENTS.md rule](../learnings/1792136592884-fresh-codex-sessions-in-workspace-agent-run-the-ag.md), [skip recall in the prompt](../learnings/1792294811857-codex-critique-tell-codex-its-disabled-push-url-is.md)). Read every reply (re-asks found real content: must-fix #13817, 6 overclaims 2026-11-09); the gate line misreported the stage after approvals — keep codex thread IDs, not the gate line, as verdict evidence ([fresh session's first answer can be a wiki recall](../learnings/1794239601487-codex-mcp-a-fresh-session-s-first-answer-can-be-a-.md)). A recorded approve proves only that a call was made — verify claims yourself before posting ([recall list instead of a review](../learnings/1792072692925-codex-critique-sometimes-returns-a-recall-list-ins.md)).

**Same-thread recovery is weaker; prefer a fresh corrected call.** A `codex-reply` carrying `STAGE:` is refused ([cwd=/workspace/agent → recall bullets](../learnings/1792074066723-codex-critique-cwd-workspace-agent-can-make-codex-.md)); a STAGE-less re-ask elicits the review ([reply on the same thread](../learnings/1792429620370-codex-critique-with-cwd-workspace-agent-returns-a-.md)). Recording needs two parses. (1) The reply finds its stage via the `critique_threads` map written at the initial call — unmapped it updates only `last_critique_verdict` ([prefix the prompt](../learnings/1793779536331-codex-critique-prefix-the-prompt-with-do-not-run-a.md)); mapped it records (#14159, slang#14317). (2) `### Attested` lines record only when matching `-[ \t]*<64-hex>[ \t]+<path>` — backticked/hash-last forms record nothing (stage keeps the earlier hashes; 1,000+ char comment files refused as unattested); put the literal template `- <sha256> <path>` under `ARTIFACTS:` ([recall stub](../learnings/1792695817981-codex-critique-run-with-cwd-outside-workspace-agen.md), [backticked hashes dropped](../learnings/1793830181320-critique-gate-backticked-attestation-hashes-are-si.md), [attestation must be `- <sha256> <abs path>` (hash first)](../learnings/1794008715794-codex-output-review-attestation-must-be-sha256-abs.md)). After a reply-recovered round, check `.critique_verdicts`/`.critique_attested.OUTPUT_REVIEW` before delivering ([recall notes recorded as approve](../learnings/1793839501898-codex-output-review-can-return-recall-notes-and-st.md)).

## A gate-blocked delivery is an outstanding action

On slang PR #12378 a reviewer flagged the same stale `742/742` for eight rounds; each round it was fixed locally and reported fixed, yet the posted body never changed ([a local fix is not a fix to the published copy](../learnings/1785992450842-a-fix-to-your-local-artifact-is-not-a-fix-to-the-p.md)). The loop: edit local → `gh` update → hook denies → satisfy the gate → never retry (an approval feels like completion); record the retry of every denied call. When a reviewer contradicts your local measurement, suspect delivery; diff via the gate-safe issues endpoint (strip CRLF and `jq -r`'s trailing newline):

```bash
gh api repos/O/R/issues/<n> --jq '.body' > /tmp/live.txt   # PR bodies are served here too
tr -d '\r' < /tmp/live.txt | sed -e '$ { /^$/d }' > /tmp/live-norm.txt
diff /tmp/live-norm.txt ./local-body.md && echo "PUBLISHED == LOCAL"
```

**Hard-block escalation is a human approval.** The third deny of a coworker's `gh pr create` on an unfixable must-fix creates a `critique_gate_bypass` row in `pending_approvals` for `dashboard-admin` (`ncl approvals` is list/get only). Approve sets `critique_gate_bypass_approved=true` and the create fires; Reject takes the pre-agreed clean path. The orchestrator hands the operator the `approval_id` with a recommendation, never tells the coworker "proceed". A blocked coworker opens a draft PR (skips CI via `ci.yml`'s `draft != true`; not auto-merged) or escalates promptly (slang#12622 idled 13 days) ([bypass is a human approval](../learnings/1789272925575-critique-gate-bypass-is-a-human-dashboard-approval.md)).

When the shared-ledger race makes a gated marker permanently undeliverable, the compliant closure is the plain blocked-report to parent named by the gate's own rejection message — admin REJECTED the bypass (2026-11-18); on slang#13833 the plain send worked where the `[Fix Report]` marker is undeliverable in this fleet layout. Do not alternate record/retry cycles — each costs three codex calls and the approve never survives (15+ wipes over two days; the wipe rate tracks sibling turn boundaries). The chain stays compliant because the SUBSTANCE was already public (PR, issue footprint, the triager's `[Triage Resolution]` with blocked:<reason>, memory file) — the formal marker is bookkeeping; the durable fix is per-session ledger isolation, already escalated ([admin rejected the critique-gate bypass; plain blocked-report is the compliant closure](../learnings/1794988068539-admin-rejected-the-critique-gate-bypass-plain-bloc.md)).

## Gate-scope error: must-fix on an un-editable input

On slang#12453 @425c2a95 DECISION_REVIEW held must-fix for three rounds after every factual fix, objecting only to two PR-author comments narrating history. That is a gate-scope error: comment hygiene covers the agent's own diff, not the approver's read-only input, and a maintainer had APPROVED the head. Accept every factual catch; let WOULD_APPROVE coexist with clarity nits. The host needs a critique `approve` to record WOULD_APPROVE/BLOCK, not ABSTAIN_\*, so the honest label is ESCALATED (gate/approver deadlock). The durable fix exempts PR-author comment style from approver must-fix ([comment hygiene over-applied](../learnings/1786490730776-approver-critique-mustfix-critique-gate-over-appli.md)).

Codex also must-fixes its own sandbox: its guard rewrites push URLs to `disabled://…` and it has no gh token, so PLAN/CODE_REVIEW flags "push target disabled / PR not opened" (slang#13742). Say in the WHY that this is codex's sandbox and the author pushes through the credential gateway ([disabled:// is codex's own guard](../learnings/1792294811857-codex-critique-tell-codex-its-disabled-push-url-is.md)).

## DECISION_REVIEW earns its keep

On slang#12892 DECISION_REVIEW flipped a verdict on the merits: the parser fix enables a two-arm branch (`checkedBase` a `DeclRefExpr` vs an `OverloadedExpr`) and the new test exercised only one arm — WOULD_APPROVE became ABSTAIN_POLICY:OPEN_GAP; shared-machinery analogy does not clear an untested arm ([a test per arm](../learnings/1789066986411-approver-critique-mustfix-a-fix-that-enables-a-mul.md)). On slang#12993 it must-fixed rationale accuracy: "all argument access goes through the bounds-checked `get(i)`" came from `grep … | head -40` on a 1067-line file and was false (a direct `args[0]` near the end) — before any universal claim, `wc -l` and grep the whole file ([universal claims need whole-file evidence](../learnings/1789058775886-approver-critique-mustfix-universal-safety-claims-.md)).

## What the recording is for: the human-agreement join

Everything above serves a `record_decision` row in the `approval_decisions` ledger, pinned to a commit and scored against what the humans did. Example: slang#12322 (gate `-emit-cpu-via-llvm` tests on LLVM availability), decided `WOULD_APPROVE` / `CLEAN` at `ba156ebf5c90`, merged at that exact head ([#12322 APPROVED at the decided SHA](../learnings/1785987292855-approver-human-agreement-slang-12322-joined-merged.md)). Score off `pulls/<n>.head.sha`, never git ancestry (`merge-base --is-ancestor` false-negatives in a squash-only repo); a formal `APPROVED` at the decided commit approves the identical artifact, stronger than a merge.

**Averted false-abstains and declined checks leave no error signal.** "New flag + new gate" triggers a dead-flag probe that mandates `ABSTAIN_POLICY:OPEN_GAP` absent a trigger-present control. On #12322 it was rightly declined: the gate (`_canIgnore` in `tools/slang-test/slang-test-main.cpp`) and flag bit (`SLANG_PASS_THROUGH_LLVM`) pre-existed, only two writers were added, and `addUsedBackEnd` (`tools/slang-test/test-context.h`) is a pure OR (a test can only move running→`Ignored`) — demanding the control would have false-abstained an approved PR, which only the join records. Doc-vs-diff drift stays advisory here, never `OPEN_GAP`. A bot eviction comment on an unmoved green head (#12322, Falcor flake #12145) is a no-op.
