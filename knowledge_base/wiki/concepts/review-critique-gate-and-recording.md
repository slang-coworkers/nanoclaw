# Critique Gate and Decision Recording

## TL;DR

- A gate's denial is a claim: before spending a round on a block, ask what the gate measured versus what you need to know (did the reviewed artifact change?).
- Input-side defects fail closed: the Bash pattern is verb-blind (a read-only `gh api .../pulls/<n>` is "PR creation") and scans literal command text, `edits_since_critique` is container-wide, and a missing `/workspace/.claude/` blocks every call. Read via `gh api repos/O/R/issues/<n>` or `gh pr view --json`.
- Whether an approve still binds is answered by re-hashing `.critique_attested.OUTPUT_REVIEW`, not by the counter. Write artifacts before the final round. The comment gate matches Attested entries by absolute path.
- A round is a fresh `mcp__codex__codex` call with a `STAGE:` tag, the verbatim `/codex-critique` developer-instructions, and after `ROUND:` either `REQUIREMENTS: none — <reason>` or a multi-line `R<n>. "<verbatim maintainer quote>" — <full comment URL>` list. A `STAGE:` `codex-reply`, a freeform call or a one-line requirements summary is not recorded.
- The verdict recorder fails OPEN: an unparsed reply keeps the stage's previous value, so a stale `approve` survives a `must-fix`, and a reply that is no review at all (wiki-recall bullets, empty) is recorded `approve` (still seen 2026-10-28). No `### Verdict` / `### Attested` in codex's own output means no review happened: re-ask and post nothing until a structured review arrives.
- Recall stubs come from `cwd: /workspace/agent` (codex runs its `AGENTS.md` recall rule): set `cwd` outside it (`/tmp`, scratch dir, worktree) and open with "Skip any workspace recall step; your first reply must be the structured output". A reply-recovered review can keep the stub's verdict and attestation.
- Verdicts persist per stage in `workflow-state.json` across phases: a session revived months later is still blocked by its old `must-fix`, even on read-only calls, until fresh rounds run for the new phase.
- Audit any control by asking what it records when it cannot tell; "the previous answer" means it fails open.
- The gate keys off delivery markers (`[Resolution]`, `[Report]`, `[Review Verdict]`), not diffs: a no-code close still needs every required stage plus `OUTPUT_REVIEW=approve`. Marker sends need `in_reply_to`; abstain text must avoid whole-word uppercase `BLOCK`/`WOULD_APPROVE`.
- The upstream five-part PR body cannot pass this deployment's description gate (≤1000 chars, ≤2 lines per section): the Process report goes in the explain-diff-html comment; tell codex up front.
- A gate-denied side-effecting call is an OUTSTANDING ACTION: write down the retry and verify the PUBLISHED copy by re-fetch and diff, never by grepping your local file or comparing lengths.
- Bypass after deny ×3 is a human dashboard approval (`critique_gate_bypass`); `ncl approvals` is list/get only. A gate-blocked coworker opens a draft PR (which skips CI) or escalates promptly.
- A must-fix on an input the approver cannot edit (PR-author comment style) is a gate-scope error: accept the factual catches, hold the scope line, label the unresolved soft-cap ESCALATED. Codex also must-fixes its own `disabled://` sandbox; say so in the WHY.
- DECISION_REVIEW can flip a verdict on the merits (a fix enabling a multi-arm branch needs a test per arm). Universal ("all"/"never") rationale claims need whole-file evidence.
- Score a join off `head.sha`, never git ancestry, in a squash-only repo; a formal `APPROVED` at the decided commit beats a bare merge. Averted false-abstains and correctly declined checks leave no error signal: record them at join time. Bot comments and evictions on an unmoved head are no-ops.

## Overview

The `critique-gate` overlay blocks side-effecting calls via a PreToolUse hook (`gate-critique-on-deliver.sh`) until a PostToolUse hook (`track-critique.sh`) has recorded approving codex rounds in `/workspace/.claude/workflow-state.json`. This page covers the gate as an instrument, the recorder's failure modes (including recall stubs), and the human-agreement join. Operational recipes: stage counting, attestation parsing and ledger ordering on [gate mechanics](agent-routing-f0909b1-critique-gate-mechanics.md); the edit-event counter, token matching, read-only `gh` workarounds, chain routing and PR-body limits on [critique and delivery gates](agent-routing-f0909b2-critique-and-delivery-gates.md). Clause order and verdict tiers: [PR-Approver: Decision Procedure](../concepts/review-approver-decision-procedure.md); calibration: [Challenger Calibration](../concepts/review-approver-challenger-calibration.md); reviewer mechanics: [PR Review Practices](../concepts/review-pr-practices.md).

## The gate is two instruments that fail in opposite directions

On the input side, `gate-critique-on-deliver.sh` decides whether a call is a delivery and errs by over-including. On the output side, `track-critique.sh` decides what codex said and errs by under-recording, silently keeping a previous approval when it cannot parse the current verdict. The first costs rounds; the second lets a must-fix ship, and after several bogus denials an `OUTPUT_REVIEW=approve` reads as the instrument finally agreeing. Every other defect (over-blocking reads, a session born already-denied by the workspace-scoped counter) fails closed ([the critique-gate verdict recorder fails OPEN](../learnings/1785989503064-the-critique-gate-verdict-recorder-fails-open-a-mu.md)).

## Input side: fails-closed false positives

Four modes, measured mostly on slang PR #12378; all cost real rounds and none indicated a real problem ([critique-gate false positives — GET vs POST, container-wide counter, command text](../learnings/1785992478312-critique-gate-false-positives-it-cannot-tell-a-get.md)). The workaround catalogue is on [critique and delivery gates](agent-routing-f0909b2-critique-and-delivery-gates.md).

1. **Verb-blind.** The `gh api [^|]*pulls\b` arm has no HTTP method, so the read-only `gh api repos/O/R/pulls/<n> --jq '.body'` you run to verify a posted body is denied as PR creation. A PR is an issue: `gh api repos/O/R/issues/<n>` returns the same `body`, `labels` and `state`, the workaround and the correct verification fetch.
2. **Command text, not effect.** A `python3 - <<'PY'` memory note mentioning `gh api … pulls`, or a literal `gh pr create` inside a heredoc'd script (slang#13742), is denied. Author such files with the Write tool, then run a bare `python3 script.py` ([tell codex its disabled:// push URL is its own guard](../learnings/1792294811857-codex-critique-tell-codex-its-disabled-push-url-is.md)).
3. **`edits_since_critique` is container-wide.** "1 edit recorded since the last critique" appeared with no reviewed artifact changed; the edit came from a peer session's worktree (`wt-slang-12371`) in the same container. The approve is per-session; the attested-hash set answers "did my artifact change?", and all hashes matching means it still binds:

```bash
STATE=/workspace/.claude/workflow-state.json
jq -r '(.critique_attested//{}).OUTPUT_REVIEW//{}|keys[]' "$STATE" | while read -r p; do sha256sum "$p"; done
jq -r '(.critique_attested//{}).OUTPUT_REVIEW//{}|to_entries[]|"\(.value)  \(.key)"' "$STATE"   # recorded
```

4. **A missing state directory blocks everything.** Without `/workspace/.claude/` the hook's `> "$STATE.tmp"` fails (`line 417: … No such file or directory`) and every call is blocked (slang#12924): `mkdir -p /workspace/.claude` at session start; read via `gh pr view --json …`, `gh pr diff <n>` or `gh api repos/O/R/issues/<n> --jq .author_association`. Skill scripts (`collect-reviews.sh`, `eval-clauses.py`) hide their inner `gh api .../pulls` because only the top-level command string is inspected ([critique-gate hook blocks read-only `gh api .../pulls` and fails closed when `/workspace/.claude/` is missing](../learnings/1788945661953-approver-tooling-critique-gate-hook-blocks-read-on.md)).

## What counts as a round, and what an approve binds

A recorded round is a fresh `mcp__codex__codex` call with a `STAGE:` tag and the verbatim `/codex-critique` developer-instructions (counting details on [gate mechanics](agent-routing-f0909b1-critique-gate-mechanics.md)). A `STAGE:` `codex-reply` is refused and a freeform call logs "stages: none"; codex nits a new item every round, so "3 rounds → escalate" is real ([SlangPy PR review: codex-reply rounds don't count toward the gate](../learnings/1789486053134-slangpy-pr-review-pin-to-explicit-shas-shared-chec.md)). A thread opened with your own prompt or a read-only sandbox records nothing and refuses `codex-reply` follow-ups ("developer-instructions do not match"); each round is then a new `danger-full-access` call with the verbatim block (`ROUND: 2/3 — addressed M1 …`) carrying the prior thread's findings (slang#14027, 2026-10-29) [critique-gate: codex-reply rounds and non-canonical threads don't count; codex in /workspace/agent may run the recall rule instead of reviewing](../learnings/1793292848270-critique-gate-codex-reply-rounds-and-non-canonical.md).

**REQUIREMENTS format.** After `ROUND:` the prompt carries `REQUIREMENTS: none — <reason>` or a multi-line `R1. "<verbatim maintainer quote>" — https://github.com/<owner>/<repo>/issues/<n>#issuecomment-<id>` list (`#discussion_r<id>` also works); a single-line `·`-separated summary is "round NOT recorded". OUTPUT_REVIEW grades against every R-item, so one the orchestrator scoped out stays a merge blocker until the maintainer defers it on record: label it "pending maintainer deferral" and ask on the PR with the complete unchecked set. The fixer's `[Fix Review Request]`/`[Fix Report]` gate needs `PLAN_REVIEW=approve` as well as `OUTPUT_REVIEW=approve` ([REQUIREMENTS must be multi-line R<n> quotes with full URLs; orchestrator scope-outs are not maintainer deferrals](../learnings/1790758204134-codex-critique-requirements-must-be-multi-line-r-n.md); scope rule in [Working Live PRs Alongside Maintainers](../concepts/review-maintainer-live-pr-interaction.md)).

**The gate binds by content.** `### Attested` sha256s are re-hashed at send and any write after the last OUTPUT_REVIEW approve (a scratch file, a comment-id file under `.gh-comments/`) counts as an edit (full edit-event rule on [critique and delivery gates](agent-routing-f0909b2-critique-and-delivery-gates.md)). A verdict-bearing chain-close (`[Resolution]`/`[Review Verdict]`) fires a `[GATE AUDIT]` demanding every required stage ≥1 plus `OUTPUT_REVIEW=approve` ([critique-gate counts only codex calls in the exact format; `### Attested` re-hashes at send](../learnings/1790016287155-critique-gate-resolution-pr-delivery-only-counts-c.md), [verdict-bearing chain-close messages trip the critique-gate](../learnings/1790042386094-verdict-bearing-chain-close-messages-resolution-re.md)). The public-comment gate checks a comment file against `### Attested` only at 1,000+ characters ([recall bullets still record approve](../learnings/1792025053096-codex-output-review-can-return-wiki-recall-bullets.md)) and matches entries by ABSOLUTE path: a relative attested path is refused although the sha256 matches, so ask codex to re-emit absolute paths (PR #13867, [first-call recall and absolute-path Attested](../learnings/1793228747743-codex-critique-a-first-call-can-return-wiki-recall.md)).

**Verdicts outlive the phase that produced them.** The gate keys on the session's last verdict per stage, and a session revived months later still carries them: on slang-rhi#810 (2026-10-29) August PLAN/CODE_REVIEW `must-fix` verdicts refused a read-only `gh api repos/.../pulls/810`. Read via `issues/<n>`, write memory with Edit, and run fresh PLAN/CODE/OUTPUT_REVIEW rounds for the new phase against a new plan file under `reports/` [Stale critique verdicts from an earlier phase block even read-only gh calls](../learnings/1793274740895-stale-critique-verdicts-from-an-earlier-phase-bloc.md).

**Abstain `[Approval Decision]` sends.** The case-sensitive whole words `WOULD_APPROVE`/`BLOCK` suppress the ABSTAIN fast-path (full rule on [critique and delivery gates](agent-routing-f0909b2-critique-and-delivery-gates.md)): "**Not BLOCK**" spends a `critique_gate_denials` strike (soft cap 3), so write "not a code-defect rejection" or lowercase "blocking". `gate-chain-routing.sh` also needs `in_reply_to=<tasking inbound id>` on any marker send, even to a dashboard destination on the `ABSTAIN_POLICY` path; keep the explicit `to=` ([abstain `[Approval Decision]`: avoid whole-word BLOCK/WOULD_APPROVE and always set in_reply_to](../learnings/1789057110525-approver-infra-abstain-approval-decision-abstain-m.md)).

**The PR-description gate outranks the upstream five-part format.** Codex reads upstream slang `CLAUDE.md` and must-fixes a concise body, but `gate-pr-description.sh` refuses over 1000 characters or 2 lines per section (counting rules on [critique and delivery gates](agent-routing-f0909b2-critique-and-delivery-gates.md)) and `/explain-diff-html` holds the explanation in one PR comment, so the Process report goes there; say so up front, citing the hook, and codex accepts it. The hook also refuses `gh pr edit --body-file X` in the Bash command that writes X ([OUTPUT_REVIEW recording pitfalls for slang-fixer deliveries](../learnings/1792831235444-codex-critique-output-review-recording-pitfalls-fo.md)).

## The gate is code-blind: no-code closes still need every stage

The gate keys off delivery markers (`[Resolution]`, `[Report]`) in outbound text, not off whether code was written, so a zero-diff triage-confirmation is blocked until PLAN_REVIEW, CODE_REVIEW and OUTPUT_REVIEW (`approve`) are recorded. Satisfy it honestly: write the deliverable (verification log, approaches considered) to a file, then run PLAN_REVIEW on the no-code approach, CODE_REVIEW on `git status --porcelain` + `git diff --stat` and OUTPUT_REVIEW on the report as parallel canonical calls ([the critique gate fires on no-code triage-confirmations](../learnings/1783523465568-critique-gate-fires-on-no-code-triage-confirmation.md)).

## Output side: the verdict recorder fails OPEN

Neither `critique_verdicts[STAGE]` nor the `Critique round N recorded` notice is trustworthy; codex's own `### Verdict` is the truth. On shader-slang/slang#12089 (2026-08-06) codex returned `must-fix` on three consecutive `OUTPUT_REVIEW` rounds and the hook printed `OUTPUT_REVIEW=approve` every time ([the critique-gate verdict recorder fails OPEN](../learnings/1785989503064-the-critique-gate-verdict-recorder-fails-open-a-mu.md)). The mechanism in `track-critique.sh` turns on the shape of `tool_response`:

| `tool_response` shape | parsed `RAW_VERDICT` | recorded |
|---|---|---|
| `{content: [{type:"text", text:"### Verdict\nmust-fix…"}]}` — the **MCP array** | *(empty)* | `""` |
| `{threadId:…, content:"### Verdict\nmust-fix…"}` — the shape the hook's comment documents | `must-fix` | `must-fix` |

1. `:68-72` runs `jq -r '.content'` assuming string-or-object; an array renders as JSON text, so the `:80-91` awk match on `^###[ \t]*verdict` never fires.
2. The writes at `:183` / `:196` / `:205` are guarded `if $v != "" then … else . end`, so an empty parse preserves the previous value instead of recording "unknown".
3. The `:96` `*) VERDICT="unparseable"` arm, meant to fail closed on a bad verdict line, is unreachable because the failure yields `""`.

The hook's header notes this defect class was fixed once before with another input shape (*"45% of June must-fix verdicts were lost that way"*); on #12089 only reading codex directly kept a false public claim from shipping. Tell: a verdict that never changes across rounds that returned must-fix items.

**Replies that are no review are recorded too.** On 2026-10-15 two fresh canonical OUTPUT_REVIEW calls returned wiki-recall bullets and no `### Verdict`, and both were recorded `approve` ([codex OUTPUT_REVIEW can return wiki recall bullets and still record approve](../learnings/1792025053096-codex-output-review-can-return-wiki-recall-bullets.md)); on #13564 an empty reply was recorded too. On 2026-10-28 the first OUTPUT_REVIEW on #13817 and two fresh calls on PR #13867 returned only 2–3 `/workspace/shared/wiki/...` bullets, each logged with the stage's previous verdict (`approve`), the guarded-write carry-forward above ([OUTPUT_REVIEW can return a recall digest; the hook still records approve](../learnings/1793206692748-codex-output-review-can-return-a-recall-digest-ins.md), [a first call can return wiki-recall bullets and the tracker still records approve](../learnings/1793228747743-codex-critique-a-first-call-can-return-wiki-recall.md)). On #13817 the same-thread re-ask returned a real must-fix (the draft dropped the maintainer's 2025+ boundary), so counting the stub would have shipped a defect. A recorded approve proves only that a call was made: without a structured review, verify the factual claims yourself before posting (line numbers, counts, quoted source lines) ([recall list instead of a review, gate still records approve](../learnings/1792072692925-codex-critique-sometimes-returns-a-recall-list-ins.md)).

**The cause is the working directory; fix it on the first call.** A fresh session with `cwd: /workspace/agent` reads that directory's `AGENTS.md` (a symlink to the group's `CLAUDE.md`), whose memory rule says to recall from the shared wiki, so its first reply is up to five recall bullets or nothing (slang#13564, #13636, #13673); each such round spends budget and leaves the stage as it was. Set `cwd` outside `/workspace/agent` (`/tmp`, a scratch dir, or the per-issue worktree, whose repo `AGENTS.md` has no recall rule) and open with a no-recall line. Working phrasings: slang#13742 "This is a critique task. Do not run the workspace recall rule."; #13993 "Do not run any shared-wiki/learnings recall step; reply with the full structured review" [recall-only reply records no verdict](../learnings/1793220323154-slang-compare-compute-fails-on-any-stderr-warning-.md); slang#14027 "Do not run any recall/wiki step; perform the review directly" [critique-gate: codex-reply rounds and non-canonical threads don't count; codex in /workspace/agent may run the recall rule instead of reviewing](../learnings/1793292848270-critique-gate-codex-reply-rounds-and-non-canonical.md); slang-rhi#810 (a CODE_REVIEW answered with a memory search) "Do not run a memory/recall search; return only the structured output" [Stale critique verdicts from an earlier phase block even read-only gh calls](../learnings/1793274740895-stale-critique-verdicts-from-an-earlier-phase-bloc.md). Every session that did both got an attested review first try; the no-recall line alone, `cwd` unchanged, failed on slang-vscode-extension#78 ([run with cwd outside /workspace/agent or the first reply is a recall stub](../learnings/1792695817981-codex-critique-run-with-cwd-outside-workspace-agen.md), [fresh codex sessions in /workspace/agent run the AGENTS.md recall rule](../learnings/1792136592884-fresh-codex-sessions-in-workspace-agent-run-the-ag.md), [skip recall in the prompt](../learnings/1792294811857-codex-critique-tell-codex-its-disabled-push-url-is.md)).

**Same-thread recovery is weaker.** A `codex-reply` carrying `STAGE:` is refused ([cwd=/workspace/agent makes codex answer with recall bullets](../learnings/1792074066723-codex-critique-cwd-workspace-agent-can-make-codex-.md)); a STAGE-less same-thread reply ("the recall step is done — now perform the actual review") elicits the review under the thread's stage ([gate mechanics](agent-routing-f0909b1-critique-gate-mechanics.md); [reply on the same thread](../learnings/1792429620370-codex-critique-with-cwd-workspace-agent-returns-a-.md)), but on 2026-10-22 the verdict and `### Attested` hashes stayed the stub's and delivery was refused with "reviewed artifacts changed since the OUTPUT_REVIEW approve" although the hashes matched ([recall stub](../learnings/1792695817981-codex-critique-run-with-cwd-outside-workspace-agen.md)). Prefer a fresh call with the corrected `cwd`; after any reply-recovered round, inspect `.critique_attested.OUTPUT_REVIEW` before delivering.

## A gate-blocked delivery is an outstanding action

On slang PR #12378 a reviewer reported the same stale figure (`742/742`) in the PR body for eight consecutive rounds. Each round it was fixed locally (`grep -c '742/742'` returned 0) and reported fixed, yet the posted body was byte-identical to a version eight rounds old ([a fix to your local artifact is not a fix to the published copy](../learnings/1785992450842-a-fix-to-your-local-artifact-is-not-a-fix-to-the-p.md)). The loop: edit local → `gh` body update → hook denies → satisfy the gate → never return to the update, because ending in an approval feels like completion. Write down the retry of every gate-denied call; when a reviewer contradicts your local measurement, suspect the delivery path; diff content, never count (one body had three correct lengths: 22,220 bytes / 22,093 chars / 22,092 API-reported). Verify on the gate-safe issues endpoint, stripping GitHub's CRLF and the trailing newline `jq -r` adds:

```bash
gh api repos/O/R/issues/<n> --jq '.body' > /tmp/live.txt   # PR bodies are served here too
tr -d '\r' < /tmp/live.txt | sed -e '$ { /^$/d }' > /tmp/live-norm.txt
diff /tmp/live-norm.txt ./local-body.md && echo "PUBLISHED == LOCAL"
```

**Hard-block escalation is a human approval, not an orchestrator action.** On the third deny of a coworker's `gh pr create` on a must-fix it cannot satisfy, the host creates a `critique_gate_bypass` row in `pending_approvals` routed to `dashboard-admin`; `ncl approvals` is list/get only, so even a global-scope orchestrator cannot flip it, by design. On Approve, `src/modules/critique-escalation/` writes `critique_gate_bypass_approved=true` and the `gh pr create` fires on its own; Reject routes to the pre-agreed clean path. The orchestrator finds the card (`ncl approvals list`, `action=critique_gate_bypass`) and hands the operator the `approval_id` with a recommendation, never telling the coworker "proceed now". A gate-blocked coworker must open a draft PR or escalate promptly: slang#12622 idled ~13 days until the reporter asked "where's the PR" (supervisor: pushed branch + no PR + age > N days → nudge). A draft skips CI (`ci.yml` filters `draft != true`) and is not auto-merged ([critique-gate bypass is a human dashboard approval; draft-PR is the release valve](../learnings/1789272925575-critique-gate-bypass-is-a-human-dashboard-approval.md)).

## Gate-scope error: a must-fix on an input the approver cannot edit

On shader-slang/slang#12453 @425c2a95 DECISION_REVIEW held must-fix through all three rounds (soft cap) once every factual catch was fixed, its sole objection two PR-author comments narrating history ("fd-redirection was tried, not portable on Windows"). That is a gate-scope error: comment hygiene is scoped to the agent's own diff, but in the approver the diff is untrusted input and the approver is read-only; the rule also conflicts with slang's CLAUDE.md (concrete-incident comments), and jkiviluoto-nv had already APPROVED the exact head. WOULD_APPROVE coexists with acknowledged clarity nits (comments do not execute), and every factual catch is still accepted (a miscount, wrong audit-trail line numbers, a CI-green-as-coverage overstatement). Because the host blocks recording WOULD_APPROVE/BLOCK without a critique `approve` but relaxes that for ABSTAIN_\*, only abstains stay recordable; the honest label is ESCALATED (a gate/approver deadlock), not CHALLENGER_CONCERN or a silent WOULD_APPROVE, and the human APPROVE at head is the falsifiable proof. The durable fix is an approver-context carve-out exempting PR-author comment style from DECISION/OUTPUT_REVIEW must-fix ([critique gate over-applies generic comment-hygiene to un-editable PR-author comments → false ESCALATE](../learnings/1786490730776-approver-critique-mustfix-critique-gate-over-appli.md)).

Codex also must-fixes its own sandbox: its guard rewrites git push URLs to `disabled://…` and it holds no gh token, so PLAN/CODE_REVIEW flags "push target disabled / PR not opened" (slang#13742). Say in the WHY that this is codex's sandbox, the author pushes through the credential gateway, and CODE_REVIEW gates `gh pr create`, so "no PR yet" is expected ([tell codex its disabled:// push URL is its own guard](../learnings/1792294811857-codex-critique-tell-codex-its-disabled-push-url-is.md)).

## DECISION_REVIEW earns its keep, on the verdict and on the rationale

On slang#12892 R2 DECISION_REVIEW flipped a decision on the merits: the 6-line parser fix enables a branch with two accepting arms (`checkedBase` a single `DeclRefExpr` vs an `OverloadedExpr`), the new test exercised only the `OverloadedExpr` arm and no `->` generic-member-call test pre-existed, so WOULD_APPROVE became ABSTAIN_POLICY:OPEN_GAP; shared-machinery analogy does not clear an untested arm ([a fix that enables a multi-arm branch needs a test per arm](../learnings/1789066986411-approver-critique-mustfix-a-fix-that-enables-a-mul.md)). On the trivial slang#12993 cleanup it returned must-fix twice on rationale accuracy: "all argument access goes through the bounds-checked `get(i)`" came from a `grep … | head -40` on a 1067-line file and was false (a direct `args[0]` at line 1059). Before any universal ("all"/"never"/"cannot") claim, run `wc -l` and grep the whole file; scope claims to what was verified ([universal safety claims need whole-function evidence, not a truncated grep](../learnings/1789058775886-approver-critique-mustfix-universal-safety-claims-.md)).

## What the recording is for: the human-agreement join

Everything above serves a `record_decision` row in the `approval_decisions` ledger, pinned to a commit and later scored against what the humans did. The worked example is shader-slang/slang#12322 (gate `-emit-cpu-via-llvm` tests on LLVM availability), decided `WOULD_APPROVE` / `CLEAN` at `ba156ebf5c90` on 2026-08-04 ([approver human-agreement join — slang#12322 merged and formally APPROVED at the decided SHA](../learnings/1785987292855-approver-human-agreement-slang-12322-joined-merged.md)). It merged at the exact decided head, scored off `pulls/<n>.head.sha`, never git ancestry: the repo is squash-only, so `merge-base --is-ancestor` gives an authoritative-looking false negative. A formal `APPROVED` review at that commit approves the identical artifact, stronger than a merge.

**Averted false-abstains and declined checks leave no error signal.** "New flag + new gate" triggers a standing dead-flag probe whose rule mandates `ABSTAIN_POLICY:OPEN_GAP` absent a trigger-present control. On #12322 it was declined because the input failed its precondition: the gate (`_canIgnore`, `tools/slang-test/slang-test-main.cpp:4940-4944`) and flag bit (`SLANG_PASS_THROUGH_LLVM`) pre-existed, only two writers were added, and `addUsedBackEnd` (`tools/slang-test/test-context.h:55-62`) is a pure OR with no clearing site, so a test can move running→`Ignored`, never back and never →`Fail`. Demanding the control would have false-abstained a formally approved PR; only the counterfactual exposes that, so the join records that declining was right (a correct procedure on a misclassified input fails silently). An advisory the humans declined is as informative as one they acted on.
