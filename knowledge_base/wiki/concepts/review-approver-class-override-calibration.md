# PR-Approver: Repo-Class Override of INFRA, Devin-Timeout NO_REVIEW_SIGNAL & #12322/#12246 Calibration

This page covers how the approver classifies a PR *before* it reads the mechanical review-signal symptoms — the repo-class / change-class predicate that fires FIRST and overrides a co-occurring INFRA-looking signal into `ABSTAIN_POLICY:OUT_OF_SCOPE` — when a Devin timeout on a bot-authored PR is the correct `ABSTAIN_INFRA:NO_REVIEW_SIGNAL` rather than a license to round up from your own code read, the Step-1 clause-fail short-circuits (fork-head, `tier_eligible`), and the reusable diligence rules calibrated on two same-day decisions: shader-slang/slang#12322 (gate-a-flag) and #12246 (breaking narrowing).

Sibling page: [Devin retry & adequacy](review-approver-devin-retry-and-adequacy.md) — Devin artifact races and artifact-watching, bounded retry, late-primary refresh, the ABSTAIN-token critique-gate trap, and adequacy-as-Step-3.

## TL;DR

- The repo-class / change-class predicate fires FIRST and overrides the mechanical "review-signal missing → INFRA" mapping. A website-content or non-compiler infra/docs PR that shows a harvest exit-20 and/or an `unevaluable commit_match` is `ABSTAIN_POLICY:OUT_OF_SCOPE`, never `ABSTAIN_INFRA` — those symptoms are structural out-of-domain properties, not pipeline failures.
- Class determination fires before the eligibility clauses even matter: a non-compiler PR can pass all six clauses (6/6) and still be OUT_OF_SCOPE. A bot self-merge is not a human verdict.
- On the Devin-only tier, a Devin timeout + exit-20 harvest on a bot-authored PR = the one fragile signal failing = `ABSTAIN_INFRA:NO_REVIEW_SIGNAL`, even with fully green CI. This is the dominant infra-abstain driver for bot-authored PRs. Never substitute your own code read for the missing review verdict; whether trivially-safe bot PRs should keep abstaining is a human policy question.
- Some Step-1 clause failures short-circuit before the challenger and cannot be upgraded by it: a fork (cross-repo) head fails `head_provenance` independently of author trust under `allow_fork_head=false` (check `isCrossRepository` early); a >2000-line churn fails `tier_eligible` even when purely test-only (no change-class carve-out). Recognize the benign expected abstain and don't burn a challenger pass.
- Classify a gate PR by its FAILURE DIRECTION, not by resemblance. A new WRITER on an existing gate is monotone — it cannot create a dead flag or skip a needed pass — so the dead-flag probe does not apply. Route by what the change can *break*.
- "Untested" splits by direction: an untested *benefit* with a proven-safe *harm* direction is a different risk than an untested harm direction. Name which direction is untested before scoring the gap.
- A bot finding that a named human maintainer already overruled ON THIS PR is not an OPEN_GAP; two bots agreeing measures shared priors, not correctness. Read the human review thread first. But lead with the technical grounds — a maintainer's preference is supporting context, never the primary basis.
- A narrowing predicate's blast radius = the shapes that DIDN'T already error. Find the pre-existing rejection path before scoring an over-rejection flag; scope the flag to the delta.
- A relayed sweep conclusion is still an enumeration claim; an inherited `file:line` must cover the BEHAVIOR you cite, not just the line.
- When a multi-lens review result says incomplete (`reviewers_complete: false`), read the DOMAIN sections directly — a partial run makes synthesis and domain diverge. The clarity lens can carry the highest-severity finding; don't treat it as an optional third wheel.
- Structural support (covers untested inputs) makes a safety claim gateable; empirical support (a floor over the probed corpus) does not. DeepWiki can hallucinate API symbols — grep the real header before citing, and keep the proxy env intact (those vars carry the injected credential).

## Repo-Class Predicate Overrides Co-Occurring INFRA Symptoms

**Two independent INFRA-looking signals on a website-content PR still resolve to ABSTAIN_POLICY, not INFRA.** On shader-slang.github.io#209 both `collect-reviews.sh` exit 20 (`{found:false}` — no bot review to harvest) and `commit_match` unevaluable (because `eval-clauses.py` was run before `review-doc.md` was synthesized) co-occurred and could double-mislead toward ABSTAIN_INFRA. Both are structural out-of-domain symptoms of the website repo, not pipeline failures: production `claude-pr-review.yml` never runs on the Jekyll site (→ harvest-20), and `commit_match` parses the synthesized doc, not `harvest.json` (→ unevaluable purely because the doc isn't written yet). The **repo-class predicate fires FIRST and overrides the mechanical review-signal → INFRA mapping** — verify the diff is content-only (no `_config`/CI/build code) and record `ABSTAIN_POLICY:OUT_OF_SCOPE:website-content`, never ABSTAIN_INFRA. Re-running `eval-clauses.py` after synthesizing the doc with the pinned `commit_id` flips `commit_match` to a clean 6/6-pass whose abstain rests purely on the class predicate ([website-content PR shows BOTH harvest-20 and commit_match-unevaluable — both out-of-domain, still ABSTAIN_POLICY not INFRA](../learnings/1784618140917-approver-clause-gap-website-content-pr-shows-both-.md)).

The same ordering holds for a non-compiler infra/docs PR: **class determination fires FIRST**, so a `slang-coworkers/nanoclaw` changelog PR sails through all six eligibility clauses as PASS and its harvest-20 mimics the INFRA trigger, but the correct verdict is `ABSTAIN_POLICY:OUT_OF_SCOPE`, never WOULD_APPROVE or ABSTAIN_INFRA — and a bot self-merge is not a human verdict ([nanoclaw changelog docs PR: 6/6 clauses pass, still OUT_OF_SCOPE not INFRA](../learnings/1784745354331-approver-clause-gap-nanoclaw-changelog-docs-pr-6of.md)).

## Devin-Timeout on Bot PRs = NO_REVIEW_SIGNAL — Never Round Up From Your Own Investigation

**On the Devin-only tier, a Devin timeout + exit-20 harvest = the one fragile signal failing = `ABSTAIN_INFRA:NO_REVIEW_SIGNAL` — never round up from your own investigation.** slangpy#1071 (bot-authored rebased takeover, tiny diff, fully green CI) abstained because production `claude-pr-review.yml`/claude-code-action genuinely SKIPS bot-authored branches (exit-20, expected for this class) AND `devin-fetch.sh` hung past the URL-rewrite step for >12 min with no `devin-flags.md`. Exit-20 alone is not an abstain (the Devin-only tier decides); exit-20 AND a Devin failure is the `reviewers_complete=false` harness-integrity case. This is the dominant infra-abstain driver for bot-authored PRs — the fix is devin-fetch fail-fast (a ~5-min internal cap), and whether trivially-safe bot test-only PRs should keep abstaining is a human policy question, never a license to substitute the approver's own code read for the missing review verdict ([Devin timeout + bot-authored PR = NO_REVIEW_SIGNAL despite clean CI](../learnings/1784695299892-approver-infra-abstain-devin-timeout-bot-authored-.md)). The confirming shape for infra-abstain is a repeatedly-safe class you must still not round up from: a bot-authored rebased-takeover that is test-only, cites a CLOSED blocker, and whose target CI job actually *runs* the enabled tests ([merge confirms bot-authored test-only device-enablement takeover is a repeatedly-safe shape](../learnings/1784726873588-approver-infra-abstain-merge-confirms-bot-authored.md)).

**Human-agreement calibration on bot-authored / dependency PRs.** When Devin *does* return on such a PR, an isolated blast radius clears the missing-CI caveat: a dependabot Go-module bump under `extras/scaler` on the Devin-only tier, whose "no Go CI" caveat is cleared by the isolated blast radius, WOULD_APPROVE ([dependabot Go-module bump in extras/scaler: Devin-only tier, no-Go-CI caveat clears on isolated blast radius](../learnings/1784301449667-approver-clause-gap-dependabot-go-module-bump-in-e.md)) — a call vindicated when the human merged at a byte-identical head ([dependabot Go-module bump WOULD_APPROVE vindicated by merge](../learnings/1784321894518-approver-human-agreement-dependabot-go-module-bump.md)). The same "0 bugs / doc-nits" WOULD_APPROVE calibration was vindicated on a larger change: the mimalloc allocator-centralization PR MERGED at the exact decided head with its advisory nits shipped ([mimalloc allocator-centralization PR MERGED at exact head with advisory nits shipped; WOULD_APPROVE on "0 bugs / doc-nits" vindicated](../learnings/1784334832215-approver-human-agreement-mimalloc-allocator-centra.md)).

## Step-1 Clause-Fail Short-Circuits: fork-head and tier_eligible

Two class/clause interactions short-circuit before the challenger with no carve-out for change *class*, so recognizing them saves a wasted challenger pass. First, `head_provenance` fails any cross-repo (fork) head under `allow_fork_head=false` **independently of author trust**, so a clean member PR from a personal fork is a foregone `ABSTAIN_POLICY:CLAUSE_FAIL` — check `isCrossRepository` early and don't burn a challenger pass ([fork-head PRs from trusted MEMBERs abstain on head_provenance under v0-shadow](../learnings/1784735771677-approver-clause-gap-fork-head-prs-from-trusted-mem.md)). Second, the `tier_eligible` size cap is another Step-1 FAIL with no carve-out for change class — a purely test-only consolidation PR (slangpy#1085, 24 files all under `tests/`, +3141/−59 ≈ 3200 lines, zero runtime/binding/build changes) resolves to `ABSTAIN_POLICY:CLAUSE_FAIL:tier_eligible` (3200 > 2000-line cap) even though it touches no shipped code, because `eval-clauses.py` computes eligibility from raw `additions+deletions` churn. When a PR is test-only AND the only failing clause is `tier_eligible`, recognize the benign expected abstain, don't spend challenger effort (the challenger cannot upgrade a Step-1 FAIL), and note that the only lever that would change the outcome is a policy tier scaling `max_total_lines` by change class — not a challenger override ([Large test-only consolidation PRs abstain on tier_eligible size cap](../learnings/1785510473677-approver-clause-gap-large-test-only-consolidation-.md)).

## #12322 (gate-a-flag): Calibration and Challenger Diligence

**shader-slang/slang#12322** ("gate `-emit-cpu-via-llvm` tests on LLVM backend availability", 1 file, +17 −2, WOULD_APPROVE) generated four reusable diligence rules:

- **Classify a gate PR by its FAILURE DIRECTION, not by resemblance.** The PR *looks* exactly like the change class the standing dead-flag probe exists for (flag tested, requirement set, gated thing runs-or-doesn't), which would have demanded a trigger-present control and, absent one, produced `ABSTAIN_POLICY:OPEN_GAP` — a **false abstain**. But a **new WRITER on an existing gate is monotone**: it cannot create a dead flag and cannot skip a needed pass, so the dead-flag probe does not apply. Route by what the change can *break*, not what it resembles ([classify a gate PR by its failure direction — a new writer on an existing gate is monotone](../learnings/1785835891561-approver-calibration-classify-a-gate-pr-by-its-fai.md)).
- **"Untested" splits by DIRECTION.** A true statement about #12322: no CI leg exercises the code path the fix exists to fix (the fix makes LLVM-requiring tests report `Ignored` instead of `Failed` on a runner lacking `slang-llvm`, and no CI leg lacks it). But an **untested benefit with a proven-safe harm direction** is not the same risk as an untested harm direction — name which direction is untested before scoring the gap ([untested splits by direction — an untested benefit with a proven-safe harm direction is a different risk](../learnings/1785835946540-approver-clause-gap-untested-splits-by-direction-a.md)).
- **A bot finding that a named human maintainer already overruled ON THIS PR is not an OPEN_GAP** — and two bots agreeing measures shared priors, not correctness. Devin's only finding and CodeRabbit's 🟠 Major both flagged the same duplicated predicate the maintainer had already accepted; read the human review thread before scoring a structure/maintainability gap ([a bot finding a named human already overruled is not an OPEN_GAP](../learnings/1785835918863-approver-calibration-a-bot-finding-that-a-named-hu.md)). **Self-correction to the emphasis (not the verdict):** a maintainer's preference is *supporting* context for clearing a repo-guideline finding, never the primary basis — **lead with the technical grounds** ([correction: a maintainer's preference is supporting context, not the primary basis](../learnings/1785836205956-approver-critique-mustfix-correction-to-my-own-123.md)).
- **A relayed sweep conclusion is still an enumeration claim, and an inherited `file:line` must cover the BEHAVIOR you cite.** Both errors were in claims handed upstream as reusable facts (verdict unaffected), caught by independent OUTPUT_REVIEW — narrow the claim to what you actually enumerated, and re-verify an inherited citation covers the behavior, not just the line ([narrowing two of my own #12322 claims — a relayed sweep conclusion is still an enumeration claim](../learnings/1785836917776-approver-critique-mustfix-narrowing-two-of-my-own-.md)).

Repo property confirmed while deciding it: **"plugin absent" and "target genuinely unsupported" emit the SAME diagnostic (E00028)** — `Diagnostics::UnableToGenerateCodeForTarget` fires both when `getOrLoadSlangLLVM()` returns null and when the target is genuinely rejected; the same absence-vs-rejection conflation as the SPIR-V validator path, a standing still-open property, not a defect of this PR ([Slang LLVM backend: absent and rejected emit the same E00028](../learnings/1785835977515-slang-llvm-backend-plugin-absent-and-target-genuin.md)).

## #12246 (breaking narrowing): Blast Radius = the Delta

**shader-slang/slang#12246** (`pr: breaking change` — reject a non-integer `switch` condition). **A narrowing predicate's blast radius = the shapes that DIDN'T already error — find the pre-existing rejection path before scoring an over-rejection flag.** Devin flagged a plausible over-rejection ("switch over a bare generic type param would now be rejected", `slang-check-stmt.cpp:410-417`); the mechanism was real by reading, but the shapes it names were *already* rejected by an existing path, so the true blast radius is only shapes that previously slipped through — scope the flag to the delta ([a narrowing predicate's blast radius = shapes that didn't already error](../learnings/1785837275081-approver-challenger-miss-a-narrowing-predicate-s-b.md)).

## Cross-PR Review Diligence: Partial Multi-Lens Reads, Clarity Lens, Support-Strength, DeepWiki

**Reading a partial multi-lens review: check DOMAIN sections against the synthesis, not through it.** On #11917 batch-2 (PR #12336) a combined review came back `APPROVE_WITH_NITS, 0 bugs, 4 gaps` — but reading the 79KB report, the domain-reviewer sections **contradicted the synthesis twice**, both against code just written from the summary. The correctness lens had died at its $40 budget cap producing a 0-byte `final-review.md`; two of its four domain reviewers completed, their raw output survived, but the merged synthesis never ran (`reviewers_complete: false`). **A partial run makes synthesis and domain diverge** — read the domain sections directly when the result JSON says incomplete ([reading a partial multi-lens review — check domain sections against the synthesis, not through it](../learnings/1785836257411-reading-a-partial-multi-lens-review-check-domain-s.md)). Companion: **the clarity lens can find the highest-severity bug** — on the same pass the highest-value finding came from clarity (a comment claiming `lowerTaggedUnionTypes` synthesizes three families when it emits **five**, an under-counting comment that is a miscompile invitation), not correctness (which had died at its cap). Don't treat clarity as the optional third wheel ([the clarity lens can find the highest-severity bug](../learnings/1785833275733-the-clarity-lens-can-find-the-highest-severity-bug.md)).

**Structural vs empirical support for a safety claim are not equally strong:** a redundant `result.tagType = true` was defended two ways — empirical (the control matrix never showed `tagOps=1, tagType=0`) is only a *floor* over the corpus probed, while structural (all four tag ops are typed `SetTagType`, which is hoistable) *covers untested inputs*. Structural support is what makes it safe to ship ([structural vs empirical support for a safety claim — which discriminator decides gateability](../learnings/1785836586307-structural-vs-empirical-support-for-a-safety-claim.md)).

**DeepWiki can hallucinate API symbols — grep the real header before citing.** DeepWiki's answers about an API can name symbols that do not exist; verify against the actual header. (⛔ **Recipe caveat corrected 2026-08-05:** the original recipe opened with `unset HTTP_PROXY HTTPS_PROXY …`, but those vars carry the OneCLI-injected credential — stripping them *discards authentication* (measured 100× throttle: 6000→60 rate limit), it does not bypass a proxy. Keep the proxy env intact; `curl` including `raw.githubusercontent.com` works with it.) ([DeepWiki can hallucinate API symbols — grep the real header before citing](../learnings/1785836147443-deepwiki-can-hallucinate-api-symbols-grep-the-real.md)).
