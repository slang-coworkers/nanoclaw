# PR-Approver: Harvest Endpoints — slang-rhi Fallback Tier & Inline-Findings Discards

Two harness-level harvest defects, each a false-clean generator. On slang-rhi a clean CodeRabbit pass lands as a summary-comment EDIT and our own `collect-reviews.sh` discards a signal it already matched; separately, the harvest reads the wrong endpoint for inline findings, and the fix shipped with a best-effort fallback on a required input. Sibling pages: [decision procedure](review-approver-decision-procedure.md), [endpoint-split signal & clauses](review-approver-signal-endpoint-and-clauses.md), [Devin tier & critique-gate](review-approver-devin-tier-and-critique-gate.md), [OUTPUT_REVIEW evidence discipline](review-approver-output-review-evidence.md).

## TL;DR

- `collect-reviews.sh` exit 20 with `{found:false}` does NOT mean "no bot review exists". When CodeRabbit has no actionable comments it EDITS its existing summary issue-comment in place (`No actionable comments were generated… 🎉`, `updated` ~90s after the push, commit span at head) — key head-currency off the ABSENCE of the rate-limit marker plus the commit span, never the presence of a review row.
- The exit-20 miss is a DISCARD, not a blindness: the script captures `cr_summary` at :161 then `finish(20)` writes `{found:false}` without ever consulting it. The fix is "fall back to `cr_summary`", not "add summary matching". When an instrument reports absence, check whether the value was never acquired or acquired and thrown away — same symptom, different repair.
- slang-rhi is PERMANENTLY fallback-tier (`Claude Code Assistant` = completed/skipped; no production claude-code-action pipeline). Decisions there are CodeRabbit-primary + Devin, and a Devin timeout is the norm. Discriminate `completed/skipped` (never coming ⇒ proceed) from `pending` (imminent ⇒ wait); reading both as "no signal" fabricates ABSTAIN_INFRA:NO_REVIEW_SIGNAL on every PR and corrupts the abstain rate.
- A poll window expiring is not a negative result. "It hasn't returned yet" ≠ "it timed out" — the latter requires observing the process exit. A signal that settles before you RECORD supersedes the timeout ⇒ re-harvest immediately before `record_decision` whenever the prior harvest was non-zero (stale/pending/timeout). Never discount the slow best-effort tier — its absence is the most convenient to assume.
- Inline review findings live on `pulls/N/comments`, NOT `pulls/N/reviews` (near-boilerplate envelopes) or `issues/N/comments`. A clean exit-0 head-current harvest can leave both 🟠 Major findings invisible. `original_commit_id` (not `commit_id`) is the only usable SHA attribution.
- A best-effort fallback on a REQUIRED input is a false-clean generator: `try: inline=[...] except: inline=[]` silently yields an empty finding set and a clean synthesized review — the same false-negative shape the fix targeted. A required fetch must fail loud (propagate the error, force ABSTAIN_INFRA); "best-effort" is correct only for genuinely optional enrichment.

## The harvest tier on slang-rhi: a clean CodeRabbit pass is a comment EDIT, and the discard is in our own script

`scripts/collect-reviews.sh` returning **exit 20** with `harvest.json {found:false}` does **not** mean "no bot review exists". When CodeRabbit has no actionable comments it does not post a review row at all — it **edits its existing summary comment in place** (`issues/<pr>/comments`, body `No actionable comments were generated in the recent review. 🎉`, `created` months earlier but `updated` ~90 s after the push, with a `📥 Commits` header spanning the pinned head). Two confirmed instances (slang-rhi#811-R2, #598), so treat it as the expected shape, not an anomaly: key head-currency off the **absence of the rate-limit marker** plus the commit span, never off the presence of a review row ([harvest exit 20 is NOT NO_REVIEW_SIGNAL — a clean CodeRabbit pass lands as a summary-comment EDIT](../learnings/1786347975646-approver-infra-abstain-harvest-exit-20-is-not-no-r.md)).

The mechanism inside our script matters because it changes the fix, and the first diagnosis of it was wrong. The script is **not** structurally blind to the edit: at `:153-160` it paginates `issues/<pr>/comments`, filters to the CodeRabbit login and matches `summarize by coderabbit` / `Actionable comments posted`; at `:161` it **captures the signal** into `cr_summary` (last-wins, so the newest summary survives — on #598 that was 5,737 chars naming `cuda-device.cpp`). The defect is downstream: `:195` builds `cand` from **review ROWS only**, and `:206` calls `finish(20)` writing `{"found": false}` **without ever consulting `cr_summary`**. So it is a **discard, not a blindness** — a matched-then-dropped signal. The fix is therefore "make the exit-20 path fall back to `cr_summary`", not "add summary-comment matching". Generalizing: when an instrument reports absence, check whether the value was never acquired or acquired and thrown away, because those have different repairs and the symptom is identical ([CORRECTION: collect-reviews.sh DISCARDS the summary it already matched](../learnings/1786351911521-approver-infra-abstain-correction-to-my-earlier-at.md)).

**slang-rhi is permanently fallback-tier — that is not an infra defect to burn down.** Its `Claude Code Assistant` check-run reports `completed/skipped`: this repo does not run the production claude-code-action pipeline that shader-slang/slang runs, so there is no primary review to wait for at *any* head, ever. Decisions there are CodeRabbit-primary + Devin, and Devin timing out is the norm. The discrimination that carries the whole tier decision is `completed/skipped` (never coming ⇒ proceed on the fallback tier) versus `pending` (imminent ⇒ wait, and note that CodeRabbit legitimately re-reviews on every push, so a fresh `synchronize` yields exit 10 / stale `commit_id` / `pending` status as a **timing race**, not a skip). Reading both as "no signal" manufactures `ABSTAIN_INFRA:NO_REVIEW_SIGNAL` on every PR in the repo and corrupts the abstain rate the code is meant to protect ([slang-rhi has NO production review bot — permanently fallback-tier](../learnings/1786350851182-approver-infra-abstain-slang-rhi-has-no-production.md)).

**A poll window expiring is not a negative result, and a signal that settles before you RECORD supersedes the timeout.** On slang-rhi#770 Devin took ~17 min against ~4- then ~15-min windows, and twice a terminal negative was written into the decision artifacts (`DEVIN_SKIPPED: timeout — no result within the decision window`, *"Devin never returned… I have no head-current independent reviewer signal"*) **while the process was still running** — false at the moment of typing. "It hasn't returned yet" and "it timed out" are different claims; only the second is a finding, and it requires observing the process exit. The same shape with the opposite timing on #820-R2: the `pending_bot` window (12 polls @30 s) expired, permitting the Devin tier, and then ~7 min later — while the decision was still being assembled — CodeRabbit settled to `success` with a **head-current** review carrying two 🟠 Majors that had not been found. The artifact that matters is what is observable **at the moment the ledger row is written**, because the row is the claim; an `ABSTAIN_INFRA` there names a pipeline defect that had ceased to be true and hides real code findings behind an infra excuse. ⇒ **Re-harvest immediately before `record_decision` whenever the prior harvest was non-zero (stale/pending/timeout).** Never discount the slow best-effort tier — it is precisely the one whose absence is most convenient to assume ([a timeout is not a verdict](../learnings/1786350741917-approver-clause-gap-a-timeout-is-not-a-verdict-and.md), [a settling bot signal that arrives before you RECORD supersedes the timeout](../learnings/1786350789671-approver-challenger-a-settling-bot-signal-that-arr.md)).

## The harvest reads the wrong endpoint for inline findings — and a best-effort fallback on a required input is a false-clean generator

The harvest defect above has a companion at a different endpoint. On slang-rhi#817 three endpoints carried three different things, and the one the harvest read was the least informative: `pulls/817/reviews` held 3 CodeRabbit review *envelopes* (near-boilerplate, 699/699/1695 chars); `issues/817/comments` held a board-sync notice + a summary; and **`pulls/817/comments` held the 3 real findings** at `vk-surface.cpp:146/:148/:394` (2627/1882/7061 chars). `collect-reviews.sh` returned exit 0, `found:true`, `stale:false` — a clean, head-current harvest — while both of CodeRabbit's 🟠 Major findings were invisible, because the harvest never read `pulls/N/comments` where inline review findings live. Deciding from the synthesized doc alone, on a PR with 6/6 clauses and green CI, would have produced a **false WOULD_APPROVE**. `original_commit_id` (not `commit_id`) is the only usable SHA attribution for these inline comments ([pr-approver harvest misses pulls/N/comments where inline findings live](../learnings/1786277284242-pr-approver-harvest-misses-pulls-n-comments-where-.md), [FIXED: the harvest scripts never read pulls/N/comments; original_commit_id is the only usable SHA attribution](../learnings/1786279491535-approver-infra-abstain-fixed-the-approver-s-harves.md)).

**But the fix shipped with the exact bug it was written to close.** The patch wrapped the new `pulls/N/comments` fetch in `try: inline=[...] except: inline=[]` with the comment "best-effort: never turn a review we DID fetch into a failure." That makes a **required** input best-effort: a transient error on the endpoint that carries the findings silently yields an empty finding set and a *clean* synthesized review — a false-clean generator, the same false-negative shape the fix targeted. A required fetch must fail loud (propagate the error, force an `ABSTAIN_INFRA`), never swallow to empty; "best-effort" is correct only for genuinely optional enrichment, never for the input the decision rests on ([my own harness fix shipped with the exact bug it was written to close — a best-effort fallback on a required input](../learnings/1786280119038-approver-critique-mustfix-my-own-harness-fix-shipp.md)).
