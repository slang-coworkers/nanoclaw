# Slang SPIR-V DescriptorHandle, bindless, and descriptor-heap emission

How `DescriptorHandle<T>` lowers on SPIR-V under the default heap path, `spvBindlessTextureNV` and `spvDescriptorHeapEXT`: descriptor-load coalescing, `NonUniformResourceIndex` propagation, capability-dependent handle width, and heap `ConstantBuffer`/acceleration-structure ABI. Heap specialization allowlists, stride and atomics are on [[wiki/concepts/slang-backends-spirv.md]].

## TL;DR

- The per-use descriptor `OpLoad` (#12051) is emit strategy, not a SPIR-V rule (`pinDescriptor()`/`OpCopyObject` proves one load suffices); `legalizeIRForSPIRV` + the emit walk add it after the last `-dump-ir` snapshot. Coalescing a dominating read-only `UniformConstant` load is safe even for a divergent index: per-lane divergence is not per-iteration variance (PR #12111).
- `-dump-ir` is blind at both ends: disassemble and check the specific operand, not a whole-dump grep. Inlined and `[noinline]` shapes differ; label SPIR-V operands from `OpTypeFunction`, never by source position.
- The NonUniform mark is lost through the DescriptorHandle Cast round-trip and through arithmetic into a callee (`findNonuniformIndexInst`); keep one propagating-op predicate and a worklist + visited set. glslang propagates `nonuniformEXT` only from the final index position and never decorates `OpSampledImage`; check `OpDecorate` target ids.
- `DescriptorHandle<T>` is `uint2` on plain spirv/glsl, scalar `uint64` under `spvBindlessTextureNV`/cuda; a new width discriminator means auditing every width consumer (module-scope `OpBitcast` is invalid).
- An emitter's accept-set and a guard mirroring it share ONE predicate; when a second consumer guard still misses a case, fix the producer (#12186: kind-ungated read-back conversions in `hlsl.meta.slang`).
- SPV_NV_bindless_texture accepts `uint2` OR `uint64` under addressing mode 64 (public retraction on #12186): read the primary spec; compile a reviewer's alternative before agreeing.
- A module-scope `static const` repro must consume the constant or DCE hides the bug. Test explicit `sizeof`/`alignof(T, LayoutRule)` directly; struct offsets can coincide.
- Heap `DescriptorHandle<RaytracingAccelerationStructure>` works from v2026.11; the EXT heap is driver-managed (write the descriptor, don't memcpy). Slot 0 works, slot ≥1 crashes ⇒ AS stride mismatch.
- std140 `float4[2]` == row-major `float2x4`; matrix-layout mode never touches arrays. With a heap, suspect #11483 (fixed by #11647).
- The heap `ConstantBuffer` StorageBuffer flip (#11647) was deliberate: descriptor KIND ≠ buffer-pointer addressing class, and the `OpTypeBufferEXT`/`OpBufferPointerEXT` storage classes are independent per spec. PR #12256 (#12226) keeps a Uniform descriptor with an untyped Uniform data pointer.
- The L40S driver exposes VK_EXT_descriptor_heap, so heap shaders run in the prod container. A heap `ConstantBuffer` `float4x4` is right on v2026.11, zeros on v2026.13/14 and DEVICE_LOST on v2026.20 (untyped matrix load); use `float4 rows[4]` or `StructuredBuffer<T>`.
- `-capability spvDescriptorHeapEXT` changes only `DescriptorHandle<T>` lowering; `ParameterBlock<T>` keeps set/binding. Use `ConstantBuffer<T>.Handle` (needs `UntypedPointersKHR`), a `T*` BDA param, or `[vk::push_constant]`.
- VUID-...-flags-11312 on `__slang_resource_heap` (set 1, binding 1) = built without `spvDescriptorHeapEXT`; on the API use a Capability option entry, not a `+` profile.
- A static emit-crash hypothesis needs debug-build confirmation; an orphan inst at emit points at a clone/specialize pass.
- `RWTexture2D<uint>.Handle` atomics still emit format `Unknown` (v2026.20, master); closed #11130's fix was reverted before release, so point users at OPEN #10024. A closed issue is not a shipped fix: check the fixing PR for a revert.

## Descriptor-load coalescing (#12051, PR #12111)

**Reload is an emit artifact.** With `Texture2D tex = texH;` sampled 3×, HLSL loads once but SPIR-V emits 3 `OpLoad` from one `OpAccessChain`; `pinDescriptor()` (`OpCopyObject`) collapses them to 1. With a bare Debug build, `-target spirv-asm` needs a RELEASE `libslang-glslang-*.so` on `LD_LIBRARY_PATH` ([reload is an emit-time artifact](../learnings/1783759451138-slang-12051-spir-v-descriptor-reload-is-an-emit-ti.md)). The IR holds one shared `getElement(__slang_resource_heap, index)`; the per-use loads come from `legalizeIRForSPIRV` + the emit walk, not `shouldDuplicateInstAtUseSite`, so fix it there: materialize one load when its def dominates the uses ([CORRECTION: emit-time OpLoad-per-use](../learnings/1784075115135-correction-slang-12051-spir-v-descriptor-reload-is.md)). The redundancy pass misses it not because of ordering (`legalizeSPIRV` inserts the loads, then `simplifyIRForSpirvLegalization` → `removeRedundancyInFunc`) but because `isMovableInst`'s `kIROp_Load` case accepts only CB/ParameterBlock pointers; `CastDescriptorHandleToResource` (`spvBindlessTextureNV`-only) is not movable, `CastDynamicResource` is ([legalize pass ordering](../learnings/1784269362740-slang-12111-spir-v-legalize-pass-ordering-removere.md)).

**The NonUniform guard was unnecessary.** At `insertLoadAtLatestLocation` uniform and divergent IR are identical: the heap index carries neither `NonUniformResourceIndex` nor `IRSPIRVNonUniformResourceDecoration` (the `isNonUniform` at `:690` is the plain resource-array path; a plain `Texture2D t[16]` keeps its decorations) ([NonUniform marker stripped before legalize](../learnings/1784081063099-slang-12051-descriptorhandle-divergent-nonuniform-.md)). Coalescing is still correct (`spvDescriptorHeapEXT` already emits 2 loads with 0 NonUniform and validates; the missing hint is a documented gap, `desc-heap-nonuniform.slang:8-12`), so Option A drops the guard and NonUniform preservation is follow-up #12110. Before calling a guard mandatory, verify its signal exists at the fix site ([option-a: guard over-specified](../learnings/1784081353064-slang-12051-option-a-the-invariance-guard-was-over.md)). The mark exists early (`%34 = nonUniformResourceIndex(%33)`); `makeVector` → `CastUInt2ToDescriptorHandle` → `CastDescriptorHandleToUInt2` → `swizzle` re-extracts the index unmarked, and a whole-dump `grep -c` is inflated by the capability-atom name ([CORRECTION: Cast round-trip drops the mark](../learnings/1784083614756-slang-12051-correction-descriptorhandle-nonuniform.md)). `-dump-ir`'s first snapshot (`AFTER validateAndRemoveAssumeAddress`) is already past early lowering ([REFINEMENT: -dump-ir starts too late](../learnings/1784083913871-refinement-slang-12051-the-nonuniform-marker-exist.md)).

**Safe shape for SPIR-V-legalize CSE/coalesce PRs:** the shared load dominates by construction (`setInsertAfter(subAddr)`), the change is decoration-neutral, and scope follows the read-only `UniformConstant` invariant, not a builtin-name gate ([safe shape](../learnings/1784126649253-approver-confirmed-spir-v-uniformconstant-load-coa.md)).

**`[noinline]`, #12027, and #12004.** With `[noinline]`, a resource passed as a loaded descriptor is loaded caller-side, and #12111 coalesces those loads N→1. #12027 passes an IMAGE across a call as a `%uint` bindless index and a SAMPLER as a real descriptor; a change regresses it only if the image parameter flips from `%uint` to `OpTypeImage` ([coalescing vs [noinline] + #12027](../learnings/1784128384354-slang-12051-12111-descriptorhandle-load-coalescing.md)). After two mislabeled public answers: resolve operand roles from the raw `OpTypeFunction` / `OpFunctionParameter` / type-def lines ([image as uint INDEX, sampler as descriptor](../learnings/1784128407283-slang-bindless-noinline-image-passes-as-uint-index.md)). The asymmetry (#12004) is `isIllegalSPIRVParameterType`: it always specializes textures but samplers only when they are *arrays* (a legacy compile-time-blowup guard, #3546), so a scalar `SamplerState` param stays by-value `OpTypeSampler` while the texture is passed by index and reloaded in the callee. Emission is symmetric (the specialize step decides), so don't chase it in the emitter; such fixes MUST pass `spirv-val`, not just FileCheck ([#12004 isArray gate](../learnings/1783527024741-slang-12004-sampler-vs-texture-noinline-spir-v-par.md)).

## NonUniformResourceIndex propagation

**DescriptorHandle round-trip (PR #12116, #12161).** The float pass (`slang-ir-float-non-uniform-resource-index.cpp`) adds SPIR-V-gated `kIROp_CastUInt2ToDescriptorHandle` and `kIROp_MakeVector` cases that float the wrapper to the heap index, fixing VUID-RuntimeSpirv-None-10148 on the default heap path. The `if (floatMode != SPIRV) break;` asymmetry follows the file-header contract (textual = hint; SPIR-V `OpDecorate NonUniform` is position-specific): APPROVE_WITH_NITS ([#12116 asymmetry is a nit](../learnings/1784536684181-slang-12116-nonuniform-float-pass-guard-asymmetry-.md)). On HLSL/GLSL the mark lands nested in `uint2(...).x`; #12161 checked it without a GPU via `-emit-spirv-via-glsl` (2026-10-07). For the nested `heap[uvec2(nonuniformEXT(i),0U).x]` (emitted before #12263) glslang decorates only the `OpCopyObject %uint` of the index; canonical `heap[nonuniformEXT(i)]` gets index, `OpAccessChain` and `OpLoad` decorated; DXC sets `createHandleFromHeap`'s nonUniformIndex flag for both. glslang never decorates the `OpSampledImage` from `sampler2D(tex[nonuniformEXT(i)], s[nonuniformEXT(j)])`, even for plain `Texture2D[]` (v2026.12, master); Slang's direct path does. List the ids `OpDecorate ... NonUniform` targets; raw `grep -c NonUniform` also counts `OpCapability ShaderNonUniform` and `; NonUniform` comments ([textual: nested in uint2(...).x](../learnings/1784539603707-nonuniform-on-descriptorhandle-round-trip-lands-ne.md), [glslang: final index position only](../learnings/1791406267340-glslang-propagates-nonuniformext-only-from-the-fin.md)).

**Through arithmetic (#13072).** `buffers[NUR(i)*i][0]` / `.Load(...)` lowers to a CALL: the float pass floats the mark through `mul`, but it dead-ends at the call argument. The gate is `findNonuniformIndexInst` (`slang-ir-specialize-function-call.cpp`), which walked only `IntCast`; the float pass's arithmetic path covers only same-function access (`arr[NUR(i)*i][0] = v`). Dump IR to find the layer; use a worklist + visited set (naive recursion took >10 s on a 29-node `v=v+v` chain); re-insert the mark with `newParam->getFullType()`; keep one `isNonUniformIndexArithmeticOp` predicate ([fix is in the specializer](../learnings/1789465468604-nonuniformresourceindex-through-arithmetic-fix-is-.md)).

## spvBindlessTextureNV and DescriptorHandle width (#12185, #12186)

**Over-broad producer (#12185).** A non-image/sampler `DescriptorHandle<T>` under `-capability spvBindlessTextureNV` aborts with `Unsupported result type for CastDescriptorHandleToResource` (E99997): the `case spvBindlessTextureNV:` arm in `hlsl.meta.slang` forwards every kind to `__castDescriptorHandleToResource<T>` (sibling arms switch on `T.kind`), while the `slang-emit-spirv.cpp` switch handles only texture/sampler. Fix the producer; make the emit `default` a diagnostic ([producer over-broadcasts](../learnings/1784687930584-slang-12185-spvbindlesstexturenv-descriptorhandle-.md)). The follow-up guard hand-mirrored the accept-set and omitted `kIROp_SamplerComparisonStateType` (encodable via `OpConvertUToSamplerNV`), turning an abort into a wrong diagnostic; one `isBindlessTextureNVEncodableResourceType(IRType*)` (`kIROp_TextureType || as<IRSamplerStateTypeBase>` on unwrapped types) now serves both sites ([ONE predicate](../learnings/1784697407327-emit-switch-accept-set-a-legalization-guard-that-m.md)).

**Representation is capability-dependent.** The handle is a scalar `%ulong` under `spvBindlessTextureNV`/cuda, so the AS cast is `RaytracingAccelerationStructure((uint64_t)handle)`; a maintainer's `__asuint64((uint2)handle)` failed spirv-val once compiled, which is how to settle such suggestions ([uint64-native under spvBindlessTextureNV](../learnings/1784762549887-descriptorhandle-is-uint64-native-under-spvbindles.md)). Kind-dependent width touched 8 consumers: type emit, default-construct legalization, both byte-address cast selectors, IR layout, the sizeof/alignof peephole, AST layout, reflection. Grep every `implies(CapabilityAtom::X)`/`getUInt64Type`; keep one IR predicate plus a mirrored AST one. In a block a `uint2`↔`uint64` cast is a real `OpBitcast`; at module scope `OpBitcast` is invalid ("must appear in a block"), so materialize the constant from its bits and compare in the native representation ([audit ALL width consumers](../learnings/1784859574140-kind-dependent-spir-v-representation-change-audit-.md)).

**Four consumer guards ⇒ one producer hole.** Four emit-time guards each caught a different subset (the fourth walked the operand graph to recover width). The root cause is the handle read-back conversions in `hlsl.meta.slang` (`extension uint2 { __init<T>(DescriptorHandle<T>) }` and the `uint64_t` sibling): capability-gated, not kind-gated. The hole surfaced at module scope (`OpIAdd %ulong` on `%v2uint`), in a function-scope cast, and in descriptor-heap lowering (a scalar `OpCompositeExtract` tripping spirv-opt `const_folding_rules.cpp:129`). Escalate the public `.meta.slang` fix rather than add a fifth guard; both integer constructors are public, so use a diagnostic, not an assert. Spec lesson: SPV_NV_bindless_texture accepts `uint2` OR `uint64` at `OpSamplerImageAddressingModeNV 64`; a caveated DeepWiki answer said otherwise and cost a public retraction. Read the primary spec; spirv-val silence is not evidence ([cite the spec](../learnings/1785776557998-cite-the-spec-not-a-summarizer-spv-nv-bindless-tex.md)).

**#12186 option-A review (pdeayton).** Q1 "does the width conversion assert?": a module-scope `static const` handle from a float/`bit_cast` source aborts at `emitGlobalInst` ("Unhandled global inst"), but the same `castFloatToInt` abort reproduces on master with no capability and no handle (A/B control ⇒ **pre-existing** global-emit gap). The PR's own edge is the width-mismatch path hitting `tryGetConstantDescriptorHandleBits`'s missing cast case → `SLANG_RELEASE_ASSERT`. The principled layer is **SCCP** (`isEvaluableOpCode`, `slang-ir-sccp.cpp`), which runs at global scope before emit and folds BitCast/CastFloatToInt but not MakeVector or the DescriptorHandle casts; teaching it those retires both the bespoke walker and the assert ([pre-existing global-emit gap; fix layer SCCP](../learnings/1784912194039-slang-12186-option-a-layout-change-restores-cap-co.md)). Such a repro must *observably consume* the constant (store it to a `RWStructuredBuffer` from the entry point), or DCE drops the global and a green compile falsely reads as "bug unreal"; symbols from an *unmerged draft PR* (`tryGetConstantDescriptorHandleBits`) aren't actionable until grepped on master ([consume the constant or DCE masks it](../learnings/1784915301574-module-scope-static-const-repros-need-the-constant.md)). Q2 "uint2 scalar layout — latent bug?" was first wrongly cleared by matching std430 struct offsets, but `uint2` and `uint64` both align to 8 there. The explicit `alignof(T, Std430DataLayout)` fails on the PR (handle 4, `uint2` 8): the AlignOf/SizeOf **peephole** (`slang-ir-peephole.cpp`) resolves `layoutRules` but calls `getNaturalSizeAndAlignment`, hardcoded to natural rules (invisible for uint64, where natural == std430). Test the explicit query, and run a reviewer's exact minimal `static_assert` before writing an elaborate test ([Q2: explicit alignof diverges; struct tests mask it](../learnings/1784915310738-slang-12186-q2-update-explicit-alignof-t-std430dat.md)).

## Descriptor heap: acceleration structures and ConstantBuffer storage class

**AS through `spvDescriptorHeapEXT`.** Supported and regression-tested from v2026.11 (`tests/spirv/descriptor-heap-acceleration-structure*.slang`). The handle `uint2` (`.x` = heap index) is not the slot contents (an 8-byte device address). Diagnose: (1) grep `-target spirv-asm` for `OpConvertUToAccelerationStructureKHR` (missing = old build); (2) VK GPU-assisted validation; (3) slot 0 works, slot ≥1 crashes ⇒ AS stride mismatch (`-spirv-resource-heap-stride`, #11231/#11494) ([heap AS crash diagnosis](../learnings/1785051051163-diagnosing-descriptorhandle-lt-raytracingaccelerat.md)). The EXT `ResourceHeapEXT` is driver-managed (slang-rhi uses `VK_DESCRIPTOR_TYPE_MUTABLE_EXT`): fill the AS slot with `vkUpdateDescriptorSets` + `VkWriteDescriptorSetAccelerationStructureKHR`; the raw-uint64 model holds only for an app buffer (`RaytracingAccelerationStructure(myBuffer[i])`). AS failing at index 0 with a correct `.x` while textures work ⇒ the host is memcpy'ing. Escape hatch: override `getDescriptorFromHandle` ([AS heap is driver-managed](../learnings/1785056296611-spvdescriptorheapext-as-heap-is-driver-managed-des.md)).

**"`float4[N]` reads garbage, `float2x4` works."** In std140 `float4[2]` (32 B) is byte-identical to a row-major `float2x4` (column-major is 64 B); matrix-layout mode changes only matrices. Without a heap, suspect host packing: `spirv-dis | grep -E "Offset|ArrayStride|MatrixStride"` ([std140: float2x4 == float4[2]](../learnings/1785073305394-std140-row-major-float2x4-and-float4-2-are-byte-id.md)). With a heap it is #11483: a heap `ConstantBuffer<T>` became a `Uniform` `OpBufferPointerEXT`, for which `getPointerArrayStrideValue` emits no stride; #11647 fixed it by retyping to StorageBuffer (update forward; workaround: `StructuredBuffer<T>`), which later caused #12226 ([float4[N] + heap = #11483](../learnings/1785073991889-discord-float4-n-in-struct-reads-garbage-matrix-wo.md)).

**Heap ConstantBuffer: descriptor kind vs addressing class (#12226, PR #12256).** A struct-typed `ConstantBuffer<T>` from `ResourceDescriptorHeap[]` emitted an `OpTypeBufferEXT` **StorageBuffer** descriptor (16 B on the reporter's driver) instead of **Uniform** (8 B) → 8 bytes of garbage. Flipping back to Uniform regresses #11483: `processConstantBufferDescriptorHeapLoad` *deliberately* retypes struct/array heap CB loads to StorageBuffer (PR #11647, szihs) for the pointer `ArrayStride`. The defect conflates the descriptor *kind* (an ABI fact that also sets the heap index stride via `OpConstantSizeOfEXT`) with the buffer-pointer *addressing class* ([#11647 flip is deliberate](../learnings/1784939222858-descriptor-heap-constantbuffer-storagebuffer-flip-.md)). The published `SPV_EXT_descriptor_heap` spec gives `OpTypeBufferEXT` and the `OpBufferPointerEXT` result *separate* storage-class operands with **no matching rule** (only a worked example coincides; `NonWritable` contemplates a non-StorageBuffer result), so DeepWiki's "must match" was wrong; only a device-ABI check (`SLANG_RUN_SPIRV_VALIDATION=1`) remains ([storage classes are independent](../learnings/1784939925118-spv-ext-descriptor-heap-optypebufferext-and-opbuff.md)). Slang's `emitDescriptorHeapLoad` returns a TYPED `IRPtrType` (`OpAccessChain`), and a typed pointer to an array element needs a pointer `ArrayStride` (StorageBuffer/PhysicalStorageBuffer only); glslang uses an untyped Uniform pointer + `OpUntypedAccessChainKHR`. Scalar/vector/matrix elements were already valid, so flipping EVERY struct was over-broad. `-spirv-unified-descriptor-heap-stride` fixes the stride, not the kind; the untyped path meant ~5-8 new untyped-aware consumers ([typed vs untyped OpBufferPointerEXT](../learnings/1785256702253-slang-descriptor-heap-constantbuffer-typed-vs-unty.md)). PR #12256 (merged 2026-07-29, closes #12226; in v2026.20) took it: the descriptor stays `OpTypeBufferEXT Uniform`, and the data pointer is a new `SPIRVUntypedPtrType` IR flavor (`OpTypeUntypedPointerKHR Uniform` + `OpUntypedAccessChainKHR`). Container tip: if `slangc -target spirv-asm` fails on the missing `slang-glslang` library, use `-O0 -target spirv -skip-spirv-validation` and the in-tree `build/external/spirv-tools/.../spirv-dis`.

**Heap shaders run on the prod L40S, and a heap `ConstantBuffer` matrix regressed across releases.** The L40S ICD (driver 595.91.07, Vulkan 1.4.329) exposes VK_EXT_descriptor_heap and VK_KHR_shader_untyped_pointers. A raw heap host builds with g++ against Vulkan-Headers main (`git clone --depth 1 https://github.com/KhronosGroup/Vulkan-Headers`), and the old system loader (1.3.239) passes the device functions through `vkGetDeviceProcAddr`; the working host is `/workspace/agent/reports/tmp1028/discord/h7/gpu/heaprun.cpp` (`heaprun <spv> [ubo|ssbo]`, with `VK_ICD_FILENAMES=/etc/vulkan/icd.d/nvidia_icd.json`). On this driver a UBO descriptor is 8 B and an SSBO descriptor 16 B. Measured on 2026-10-28 with a Discord repro: a `float4x4` in a heap `DescriptorHandle<ConstantBuffer<T>>` under `-capability spvDescriptorHeapEXT` is correct on v2026.11 (typed Uniform pointer), reads zeros with a UBO descriptor on v2026.13/14 (#11647's StorageBuffer descriptor), and gives VK_ERROR_DEVICE_LOST on v2026.20 (#12256's untyped Uniform pointer + `OpUntypedAccessChainKHR` + `OpLoad` of a matrix, whose element reads also come back transposed). spirv-val passes and SPV_KHR_untyped_pointers rev 4 seems to allow it, so it may be a driver bug, but it is a Slang regression from v2026.11. Verified workarounds: `float4 rows[4]`, or `StructuredBuffer<T>` with an SSBO descriptor. On a blobless clone `git grep` fetches every blob and hangs; use `git show rev:path` ([VK_EXT_descriptor_heap on the L40S; heap ConstantBuffer matrix regression](../learnings/1793176601479-prod-container-can-run-vk-ext-descriptor-heap-shad.md)).

**`-capability spvDescriptorHeapEXT` changes only `DescriptorHandle<T>` lowering.** On release v2026.20 a plain `uniform ParameterBlock<T>` entry-point param still gets `DescriptorSet 0`/`Binding 0` and no DescriptorHeapEXT capability, so Vulkan validation asks for `VkShaderDescriptorSetAndBindingMappingInfoEXT`. The native heap route, `uniform ConstantBuffer<T>.Handle h` (deref `*h`), emits a `uint2` PushConstant handle, `OpTypeBufferEXT Uniform`, `OpBufferPointerEXT`, `OpUntypedAccessChainKHR` and no set/binding, but needs `OpCapability UntypedPointersKHR` (SPV_KHR_untyped_pointers); `ParameterBlock<T>.Handle` is rejected (E30027). Without untyped pointers, a `T*` buffer-device-address param needs only `PhysicalStorageBufferAddresses` and `[vk::push_constant] ConstantBuffer<T>` only `OpCapability Shader`. The VK_EXT_descriptor_heap proposal (final spec unchecked) lists VK_KHR_shader_untyped_pointers as a dependency; docs.vulkan.org/registry.khronos.org 403 to WebFetch, but `raw.githubusercontent.com/KhronosGroup/Vulkan-Docs/main/proposals/VK_EXT_descriptor_heap.adoc` works ([capability leaves ParameterBlock set/binding](../learnings/1792525428195-spvdescriptorheapext-does-not-remove-set-binding-f.md)).

**VUID-VkGraphicsPipelineCreateInfo-flags-11312 on `__slang_resource_heap` (Set 1, Binding 1) = compiled without `spvDescriptorHeapEXT`.** That variable is Slang's legacy bindless array; with the capability, a `DescriptorHandle<Sampler2D>` fragment shader (v2026.20) emits SPV_EXT_descriptor_heap and keeps only the `globalParams` set/binding. Via the API, `findProfile("spirv_1_5+...+spvDescriptorHeapEXT")` returns 0 and drops the capability (as does a plain profile); a Capability `CompilerOptionEntry` on `TargetDesc` or `SessionDesc` applies it ([[wiki/concepts/slangc-target-coverage-and-capabilities.md]]). `-bindless-space-index N` moves only the set. Grep the asm for SPV_EXT_descriptor_heap, then look for a second session, a hardware-dependent branch, or a leftover `+` profile string ([VUID-11312 = capability missing](../learnings/1793006419948-vuid-11312-no-mapping-for-slang-resource-heap-spir.md)).

## Texture atomics through a handle: format Unknown (#10024; closed #11130)

For `InterlockedOr(h[p], 1)` on `RWTexture2D<uint>.Handle h`, a plain global would get `R32ui`, but the handle's `OpTypeImage` stays `Unknown` on v2026.20 and fails spirv-val (VUID-04658 without `spvDescriptorHeapEXT`, VUID-11416 with it). `[format]`/`[vk::image_format]` do not help on the handle, a local, or `= ResourceDescriptorHeap[i]`; the workaround is a buffer handle (`RWStructuredBuffer<uint>.Handle`), which validates. The E41403 validator gap on the same shape (#11506) is separate, on [[wiki/concepts/slang-backends-spirv.md]]. #11130 was closed 2026-10-14 as fixed by #13537, but #13712 reverted #13537 on 10-16, before v2026.20 was tagged on 10-17. A closed issue is not a shipped fix: check the fixing PR for a revert (commits touching its test file) and compare dates against the release tag ([#11130 closed, not fixed in any release](../learnings/1792612858405-slang-11130-handle-texture-atomics-format-unknown-.md)). Still unchanged at master 653bfdeef4 (2026-10-22); the OPEN tracker is #10024 ("[[format]] not propagated through DescriptorHandle", csyonghe, milestone Q1 2027, "requires a big refactoring"). Likely root cause: format inference runs only when the variable type unwraps to `TextureTypeBase`, in `maybeApplyLayoutModifier` (`slang-check-decl.cpp:2585-2600`) and in `slang-ir-resolve-texture-format.cpp:134-154` (global texture and texture-array insts only), so a handle never gets a format ([open tracker #10024](../learnings/1792658643801-slang-descriptorhandle-textures-get-no-image-forma.md)).

## Emit crashes on the heap path

**SIGSEGV from an orphan `IRParam` (#11496).** A `DescriptorHandle<Texture2D>` passed into a `[noinline]` callee with a buffer-pointer array argument, then sampled, crashed SPIR-V emit under `-capability spvDescriptorHeapEXT`. Static triage blamed an unguarded `getFormatInst()` (no `hasFormat()`), but a debug build with that guard still crashed: the operand was an orphan `IRParam` (no parent function, null `getFullType()`) left by `specializeFuncsForBufferLoadArgs` and the post-clone `simplifyFunc`/`replaceImageElementType` path. Root cause tracked in #11498; partial fix #11499 turns the crash into E99997. Confirm a static emit-crash hypothesis with a debug build, and tell "operand list too short" apart from "the value is orphaned": an orphan reaching emit points at a clone/specialize pass ([#11496 orphan IRParam](../learnings/1780768927407-slang-11496-spir-v-sigsegv-static-getformatinst-tr.md)). The allowlist side of this cluster is on [[wiki/concepts/slang-backends-spirv.md]].
