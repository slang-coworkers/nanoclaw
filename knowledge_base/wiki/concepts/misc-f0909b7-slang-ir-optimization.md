## TL;DR

Firsthand findings from triaging/planning Slang IR-pass work. Themes:

- **Read-only ≠ value-stable.** An SRV `StructuredBuffer` can be aliased by a `RWStructuredBuffer` bound to the same memory (a documented spec guarantee), so dominance + structural equality alone cannot CSE its loads/calls across an intervening write. Slang's `removeRedundancy`/`DeduplicateContext` is a *pure structural GVN* with NO memory-dependence analysis — there is no memory-aware GVN / MemorySSA / available-expressions pass in Slang today.
- **The sound cross-block CSE recipe already exists:** reuse `isMemoryLocationUnmodifiedBetweenLoadAndUser` + the `[__noSideEffect]` classifier (which already excludes execution-mask ops), not a new `[__readOnlyAccess]` effect tier.
- **A bare `globallycoherent`/`volatile` LOAD is per-access visibility, not an acquire fence** — it does not order *subsequent unrelated* accesses, so a `mightHaveSideEffects()` between-walk already handles it (barriers/atomics are side-effecting; a plain coherent load is not). Gate reuse **positively** (`isPointerToImmutableLocation` + write-focused walk); never enumerate "non-reusable" qualifiers — that is unsound-by-default and non-convergent (provenance hides behind chains/loaded-handles/phis).
- **The coherent/volatile-read CSE miscompile fixes at the `readNone` INFERENCE**, not `isPureFunctionalCall` and not `removeRedundancy` (the `[noinline]` wrapper closes over the coherent global, so only the inference can see the qualifier). `getRootAddr`'s field-key pre-peel is *branch-dependent*: live on the resource-load branch, bypassed on the plain-Load branch (fix there: pass the raw `getPtr()`).
- **Variadic-pack (`expand`/`each`) bugs use unflattened operand counts** and reproduce ONLY on whole-module compiles (no `-entry`); detect a still-symbolic pack leaf by *op*, not data type.
- **Fix producers, not consumers.** An empty mangled name / null requirement value on an inst that is *supposed* to carry one is a producer bug — don't teach the linker/emit to tolerate it. `git blame` the strip site.
- **Classify triage correctly:** "latent/dormant" (branch unreachable on master) is distinct from `reproduced`/`regression`; a "diagnosed, not fixed" report is a strong start but confirm the mechanism from the IR before relaying the reporter's owner claim; a missed-optimization is not a defect (don't apply `reproduced`).
- **Codegen-quality reports: first find which optimizer owns the op.** At `-O1` and above `slangc -target spirv` output is post-spirv-opt, and DXC runs its own DCE, so compare `-target hlsl` and `spirv-asm -O0` before crediting or blaming Slang. Core-module `__intrinsic_asm` calls survive Slang DCE unless marked `[__NoSideEffect]`/`[__readNone]` (never inferred for target intrinsics), and RayQuery getters stay at source placement because Slang has no sinking/GCM pass.
- **Dynamic-dispatch shape is fixed by construction:** the seq-ID→tag mapping never folds to identity (its `default` arm), and a caller-side merge after dispatch is never tail-duplicated. The static generic callback is the supported way to get per-type code.
- **Additive vs breaking:** a mangling/representation change is `pr: non-breaking` if the only affected inputs are programs that *don't compile today* — ask "whose currently-compiling symbol changes?"

## CSE, aliasing, and the memory-clobber walk (a correction chain)

The initial framing — add a third "read-only access" effect tier and wire it into call CSE — is **UNSOUND** as an unconditional dominance-preserving CSE, and this page's chain records the correction. `removeRedundancy`'s `DeduplicateContext::deduplicate` is a `Dictionary<IRInstKey,IRInst*>` keyed on op+type+operand-identity, seeding each dominated child's dedup map verbatim from its dominator's — with NO store/atomic/barrier analysis; the spec's "Memory Aliasing via Binding" makes SRV/UAV to the same memory aliased, so structural dedup collapsing a load across a UAV write is a miscompile [read-only StructuredBuffer is NOT value-stable](../learnings/1787811803955-read-only-structuredbuffer-is-not-value-stable-dom.md), [CSE-eligibility is NOT just an effect tier — DeduplicateContext has no memory-dependence analysis](../learnings/1787816069555-cse-eligibility-for-resource-load-calls-is-not-jus.md). The sound design **reuses existing machinery**: the `[__noSideEffect]` classifier already excludes wave/quad/derivative ops (they observe the active-lane mask — a `[noinline]` wrapper around `WaveActiveSum(buf[i])` is not DCE'd while a plain-load wrapper is), so it automatically blocks the mask-dependent CSE the reporter's divergent-`if` repro would miscompile; pair it with a *strict* between-instruction walk where ANY store/atomic/barrier/side-effecting/unknown inst blocks the CSE — no per-address aliasing exemption [NoSideEffect classifier already excludes execution-mask ops](../learnings/1787825603005-nosideeffect-classifier-already-excludes-execution.md). The canonical cross-block primitive to reuse (do not reinvent) is `isMemoryLocationUnmodifiedBetweenLoadAndUser` (`slang-ir-defer-buffer-load.h:35`), a dominance-bounded predecessor walk over `canAddressesPotentiallyAlias` for stores and `mightHaveSideEffects()` for everything else — but harden it, since its callers short-circuit via `isPointerToImmutableLocation` and its `Store` arm trusts the distinct-buffer-root non-aliasing rule the spec contradicts [reusable cross-block memory-clobber walk](../learnings/1787824688560-slang-has-a-reusable-cross-block-memory-clobber-wa.md). Any new effect decoration must also be stripped at `specialize-function-call.cpp` / `glsl-legalize.cpp` (both strip `ReadNone`/`NoSideEffect`) and needs an IR-module version bump.

Why the gate must be *positive*, and why a coherent load in between is not a blocker: enumerating "non-reusable" qualifiers (reuse unless volatile/`globallycoherent`/ROV/memory-scoped) is unsound-by-default and does NOT converge — the disqualifier lives on the resource (global param, buffer-block field key, or the resource TYPE for ROVs) and its provenance at the access site can be obscured through a pre-built element pointer, a handle `load`ed from a struct/`ParameterBlock` field, or a phi/select merging two qualified handles (codex found 4 successive shapes: direct global → field-address chain → loaded handle → prebuilt-elem-ptr / phi-merged). The convergent design reuses only when it can POSITIVELY prove immutable-reusable memory (a directly-resolvable read-only SRV/`ConstantBuffer`/`ParameterBlock`/read-only texture with no coherent/volatile qualifier, or SSA-local/param/constant), treating unprovable provenance as non-reusable [sound-by-default beats "detect non-reusable"](../learnings/1789420875085-slang-cse-of-read-only-load-calls-detect-non-reusa.md). This is sound because a bare `globallycoherent`/`volatile` (HLSL) or `coherent`/`volatile` (GLSL) LOAD is per-access **visibility**, not an acquire fence: it does not establish happens-before over *subsequent unrelated* accesses, so it does not force a re-read of an unrelated (even aliased) location and does not by itself block CSE/reuse/reordering. SPIR-V separates the two mechanisms — a coherent load carries only the per-instruction memory operand `MakePointerVisible|NonPrivatePointer` on the `OpLoad` (a *visibility* op scoped to that reference), whereas cross-invocation happens-before requires `Acquire`/`Release` *memory semantics* on an `OpMemoryBarrier`/`OpAtomic*`, which is side-effecting and therefore already caught by a `mightHaveSideEffects()` between-walk (Slang's emit puts the operand on the `OpLoad` with no standalone barrier, `slang-emit-spirv.cpp:8890,8945`; the repo spec establishes happens-before only via release/acquire atomics or barriers). So the sound gate is (a) a positive immutable-read gate + (b) a write-focused between-walk — never a "cancel on any coherent/volatile access" gate (non-convergent AND over-conservative); a `volatile buffer` lowering to `GLSLShaderStorageBuffer` is mutable and excluded by the positive gate anyway [bare coherent/volatile load is per-access visibility, not a fence](../learnings/1789422527100-a-bare-globallycoherent-volatile-load-is-per-acces.md).

When the miscompile actually fired (#13082: a `globallycoherent`/`volatile` `ByteAddressBuffer.Load` CSE'd across a store → silent `a+a`), the fix layer is the **`readNone` inference**, not `isPureFunctionalCall` and not `removeRedundancy`. The read-only `.Load` methods are `[__readNone]` unconditionally — the qualifier lives on the buffer *variable* (`IRMemoryQualifierSetDecoration`), invisible to the method decl — so a `[noinline]` wrapper whose only callee is `.Load` is inferred `readNone` transitively before `.Load` is force-inlined, and `removeRedundancy` then commons the two `call wrapper` insts as pure. Because the wrapper *closes over the coherent global* (the buffer is not a call argument), the outer `isPureFunctionalCall` can't see coherence; only the inference — which looks inside at `call .Load(inData,…)` — can. Fix: in the inference's Call branch, deny `readNone` when a call arg reads a coherent/volatile resource (`resourceAccessTouchesCoherentOrVolatile`, a bounded cycle-protected backward slice over load/field-address/element-ptr + phi via `getPhiArgs`). It terminates because the front end confines coherent/volatile to *global* resource decls, so provenance always bottoms out at a global (a parameter can't carry the qualifier). Residual soundness bug (the true enabler): a plain copy `ByteAddressBuffer x = inA;` or `x = inA;` SILENTLY DROPS the qualifier — no diagnostic; only the ternary/argument-binding path diagnoses (E30048) — so a memory-routed handle carries no coherence in the IR and no IR-layer analysis can recover it; that fix belongs at the semantic checker, tracked separately [coherent/volatile load CSE miscompile — fix at readNone inference, plus the front-end qualifier drop](../learnings/1789440874211-coherent-volatile-resource-load-cse-miscompile-fix.md).

Refinement on the `getRootAddr` pre-peel that gates the read-only-load CSE (#13081/#12785): the per-field-key `globallycoherent`/`volatile` check inside `isRepeatableReadLocation` is **branch-dependent**, not uniformly dead code. `getRootAddr` (slang-ir-util.cpp ~936-953) peels `FieldAddress`/`GetElementPtr`/`NodeOutputRecordGetElementPtr` but NOT `kIROp_Load`. On the **resource-load branch** the check IS LIVE: for `structuredBufferLoad(load(fieldAddr(gp, memberKey)), i)`, `getRootAddr(operand0)` stops at the `Load` (Load isn't peeled), so the chain survives and `isRepeatableReadLocation`'s own peel walks `Load → FieldAddress` and inspects the member key — empirically a `globallycoherent` ConstantBuffer member is NOT commoned while its plain sibling IS. On the **plain-Load branch** the check is BYPASSED: a scalar member read `return cb.x;` lowers to a bare `kIROp_Load` whose `getPtr()` is `fieldAddr(cb, xKey)` directly, and passing `getRootAddr(getPtr())` peels the FieldAddress away so the field-key qualifier check never runs (a latent soundness asymmetry). Fix is local to the plain-Load branch — drop the redundant `getRootAddr` and pass the raw `getPtr()` so the predicate's own peel (which starts at `isPointerToImmutableLocation` and handles FieldAddress/GetElementPtr/Load) does the work; do NOT un-peel at the *top-level* eligibility gate as a blanket fix, because on CPU/CUDA a `Ptr(StructuredBuffer)` field pointer into `GlobalParams` is not `isPointerToImmutableLocation`-true and un-peeling there would reject legitimate global reads [getRootAddr + field-key check is branch-dependent, not dead code](../learnings/1789445655724-correction-getrootaddr-field-key-check-is-branch-d.md).

## Missing optimization passes and reusable machinery

When this was first triaged Slang had **no jump-threading / predecessor-constant switch-threading pass**; `threadSwitchOnConstantPhi` (#12795) has since landed but threads `switch` only, not `IfElse` ([caller-side merge after dispatch is never tail-duplicated](../learnings/1790318679657-slang-dynamic-dispatch-caller-side-merge-after-dis.md)). The original finding: SCCP folds a switch only on a *global* constant (a phi carrying a different constant per edge collapses to `Any`), and simplifyCFG is shape-based not value-based. The reusable per-predecessor-edge walk already exists in `slang-ir-constexpr.cpp`; the insertion window is after SCCP+DCE, before the post-inline `simplifyIR`. You can confirm a missed-*optimization* shape GPU-free (`-target spirv-asm -O3` + `grep -c OpSwitch`) — but a missed-opt is NOT a defect, so don't apply the `reproduced` label [Slang has no jump-threading pass](../learnings/1787819801464-slang-has-no-jump-threading-pass-predecessor-const.md). For narrow SROA (promoting small non-escaping local arrays), two firsthand findings shrink the work: the scalarization tail is already free (peephole folds `UpdateElement`-over-`MakeArray` to scalars), and the non-escaping analysis already exists inlined in `isPromotableVar` — a bespoke SROA pass would reinvent both [narrow-SROA — the scalarization tail and escape analysis already exist](../learnings/1787809324437-slang-narrow-sroa-12787-the-scalarization-tail-and.md).

## Codegen-quality triage: which optimizer owns the op

A batch of 2026-09-25 reports asked why an op survives, or disappears, on one target. The first question is always which optimizer acted.

**Removal is usually downstream.** When a report says "CUDA keeps a dead call but DXIL/SPIR-V remove it", check `-target hlsl` (the call is still there, so DXC did the DCE) and `-target spirv-asm -O0` or `-dump-ir` at -O1 (the dead OpLoad/SPIRVAsm survives, so spirv-opt did it). In #13262 (WorldToObject3x4) Slang removed the call on no target. Core-module `__intrinsic_asm` functions lower to a bare GenericAsm; `isNoSideEffectCallee` (slang-ir-util.cpp:3502) keeps the call unless the callee has `[__NoSideEffect]` or `[__readNone]`; and `propagateFuncProperties` skips TargetIntrinsic functions, so neither attribute can be inferred. None of the pipeline RT system-value getters carry either (RayQuery getters use `[__NoSideEffect]`, GetTransformListSize uses `[__readNone]`). CUDA cannot clean up downstream because OptiX's transform-list walk is `asm volatile` optixLdg. To prove a fix without rebuilding the core module, copy the intrinsic into user code with `[__NoSideEffect]`; the call then disappears on every target, even SPIR-V at -O0. Never put `[__readNone]` on RayTCurrent, because an accepted ReportHit changes it within an intersection invocation ([DXIL/SPIR-V 'eliminating' a dead intrinsic call is usually DXC/spirv-opt, not Slang](../learnings/1790318755944-dxil-spir-v-eliminating-a-dead-intrinsic-call-is-u.md)).

**The SPIR-V you read at -O1 and above is spirv-opt's.** `needsOptimization` (slang-emit.cpp:3555-3563) runs the bundled spirv-opt from `-O1`, and the -O2/-O3 preset (slang-glslang.cpp:460-520) includes InlineExhaustive, so single-OpFunction output is not Slang inlining; compile at `-O0` to see Slang-only SPIR-V. Slang's peephole folds `swizzle(makeVector(...))` only when makeVector has one scalar operand per lane (it bails at slang-ir-peephole.cpp:1751, so `uint3(u2, 0).xy` survives; the GetElement(MakeVector) fold at :904-947 is the model for a fix), and spirv-opt does not fold OpVectorShuffle(OpCompositeConstruct) either. Vector asuint/asfloat on SPIR-V are opaque `spirv_asm { OpBitcast }` blocks rather than `kIROp_BitCast`, so an IR BitCast fold will not fire on them. A local whose field address escapes to a non-inlined call stays a memory var even after inlining, which blocks value-level peepholes (#13263) ([-O3 SPIR-V is post-spirv-opt; swizzle(makeVector(vec,s)) is folded by neither Slang nor spirv-opt](../learnings/1790319181328-slang-o3-spir-v-output-is-post-spirv-opt-swizzle-m.md)).

**Nothing moves a RayQuery getter.** The getters are `[__NoSideEffect]` `spirv_asm OpRayQueryGet*KHR &this` with a BorrowIn `this`, so before inlining the call fails `areCallArgumentsSideEffectFree`, and after inlining the IRSPIRVAsm hits `mightHaveSideEffects`'s default of true. They are never DCE'd, CSE'd or moved, and SPIR-V placement equals source placement. Slang IR has no sinking/GCM/remat pass (LICM is off outside autodiff), and spirv-tools' CodeSinkingPass moves only OpLoad/OpAccessChain. To keep reads local to each switch case without a callback, call a caller-side generic `intersect_case<G : IGeometry>(inout RayQuery<F> q, …)` per case; it emits SPIR-V identical to hand-duplicated reads (#13268). The 4x3 transform getters' `[__readNone]` is too strong and must be fixed before any movement pass keys on readNone ([RayQuery getters are pinned at source placement; per-case reads use a generic caller-side helper](../learnings/1790318756067-slang-pins-rayquery-getters-at-source-placement-pe.md)).

**CUDA struct returns.** NVRTC can give smaller SASS when a tagged-union result is built as a common exit with separate field writes. `simplifyForEmit`'s `processMakeStruct` splits only `store(ptr, MakeStruct)`, never `return(MakeStruct)` (early returns emit a brace-init temp), while phi elimination stores each predecessor's value into the struct-param temp. So a single local `result` assigned in every branch, each a visible MakeStruct, plus one `return` is the source-level route to per-field writes. Nothing on the CUDA path merges returns; `convertFuncToSingleReturnForm` is the natural hook if a maintainer wants that canonicalization. To tell NVVM from ptxas, diff the PTX between variants; the local CUDA 12.6 toolkit has no sm_120, so label sm_75/89/90 results as unqualified (#13266) ([CUDA struct/interface returns: Slang emits per-field writes only for store(MakeStruct), never for return](../learnings/1790318832645-cuda-struct-interface-returns-slang-emits-per-fiel.md)).

**Dynamic-dispatch shape.** `createDynamicObject<I>(runtimeId, 0)` always calls an integer-mapping function (`lowerGetTagFromSequentialID` → `createIntegerMappingFunc`), even when the `-conformance` IDs equal the internal tags, because its `default` arm maps unknown IDs to a registered tag. Making tag == seq-ID therefore also needs an invalid-ID contract (#13220), not just renumbering. A static interface forwarder folds nested-existential layers into one dispatch arm, which isolates the AnyValue box round-trip cost from the remap cost ([the seq-ID→tag remap switch survives even when public IDs equal the internal tags](../learnings/1790318450614-slang-dynamic-dispatch-the-seq-id-tag-remap-switch.md)). A caller-side merge after dispatch (`if (obj.f(ctx, out c)) accept(c);`) keeps exactly one accept site: Slang has no tail duplication, `threadSwitchOnConstantPhi` threads switch only, and there is no heuristic inliner. Neither `[ForceInline]` on the impls nor `[ForceUnroll]` over constant IDs helps, since the mapping function is not inlined; the static generic callback (a default method `f_and_accept<H>`) is the supported form. The same limit applies to a generic helper `f<G:IFoo>(G g, ...)` called with a `createDynamicObject<IFoo>` value: it is specialized once for the conformer set (a tag parameter, `specializeGenericWithSetArgs` in slang-ir-specialize.cpp), with a dispatch switch at each witness-method call inside, and code before or after the interface call is not per-arm. Per-conformer bodies exist only for interface requirements and default methods. To get a whole caller body per arm without editing `IFoo`, declare `interface ICase { static void run(...); }` plus a blanket `extension<G : IFoo> G : ICase { static void run(...) {...} }` in an imported module, dispatch `createDynamicObject<ICase>(id,0).run(...)`, and register `-conformance T:ICase=N` per type with the same IDs; DXIL then has the same shape as a default-method callback (#13268). If the blanket extension sits in the primary slangc TU, `-conformance T:ICase` fails E00073, because `createTypeConformanceComponentType` sees extensions only from `loadedModulesList` (the #12049 class); `import core;` collides with the built-in module, and `extension IFoo {}` is rejected E30852 ([per-conformer specialization of a caller under dynamic dispatch: a traversal-owned interface + blanket extension](../learnings/1790404968818-per-conformer-specialization-of-a-caller-under-dyn.md)). PR #12924 (v2026.18.2) force-inlines `s_dispatch_*` and the witness wrappers, which changed DXC's input and the DXIL phi count (16→18 on #13267) without changing the commit count, so diff `-target hlsl` first when comparing releases. Official release tarballs plus `-dxc-path` give same-DXC cross-version comparisons without a rebuild, and dxil-asm output contains a NUL byte, so use `grep -a` ([caller-side merge after dispatch is never tail-duplicated; #12924 changed the DXC phi shape](../learnings/1790318679657-slang-dynamic-dispatch-caller-side-merge-after-dis.md)).

## Variadic packs: unflattened counts and whole-module-only repros

The `expand`/`each` unroll count comes from `getCapture(0)->getOperandCount()`, which for a *concatenation* `makeValuePack(scalar, nestedPack)` is the raw operand count (2), disagreeing with the flattened `getTupleElement` domain (1 when the nested pack is empty) → out-of-range `getTupleElement` → segfault. The `flattenPackOperand` helper exists but the count sites don't call it [expand/each unroll count uses unflattened operand count](../learnings/1787853893292-expand-each-unroll-count-uses-unflattened-operand-.md). This class of bug reproduces ONLY on whole-module compiles (no `-entry`): with `-entry` the generic specializes eagerly and the concatenation is flattened before the expand unrolls, so `slang-test`'s `-entry`-driven tests never hit it — the reliable regression is a whole-module `//TEST:SIMPLE:-target spirv-asm` [expand pack-arity bugs only reproduce whole-module](../learnings/1787868222506-expand-pack-arity-bugs-only-reproduce-whole-module.md). When guarding a pack-count computation, detect a still-symbolic leaf by *op* not data type — a symbolic *type* pack leaf (`each T`) is an `IRParam` of `IRTypeParameterPackKind`, not an `IRTypePack`, so a type-only check misclassifies it as a scalar; use the op set `hasNestedShapePackOperand`/`getPackBranchCardinality` already treats as unknown-cardinality [detect an unresolved IR pack leaf by op, not by data type](../learnings/1787868230656-detect-an-unresolved-ir-pack-leaf-by-op-not-by-dat.md).

## Producer-side root causes and additive-vs-breaking analysis

Two producer bugs. An interface with ≥2 associated-type *equality* constraints crashes `linkIR` with a duplicate-key assert because both constraint keys have empty mangled names — the tempting linker fix (eager-clone any empty-name entry) MASKS a producer violation; the real root is `removeLinkageDecorations` (added by #7764 for method-requirement *values*) wrongly stripping the KEY's linkage on an equality constraint whose canonical entry is `(named key, null value)`. An empty/absent canonical identifier on an inst *supposed* to carry one is a producer bug — check whether that inst class is *intentionally* anonymous (like `IRBuiltinRequirementKey`) or *accidentally* stripped [equality-constraint key has no mangled name = producer bug, not a linker bug](../learnings/1787938004557-slang-12817-equality-constraint-key-has-no-mangled.md). **Apply the test, don't apply the conclusion:** not every `slang-ir-link.cpp` dedup/`checkIRDuplicate` fix is the #12817 "fix-the-producer" anti-pattern. The discriminator is **is the dedup KEY well-formed?** #12817's key was *malformed* (empty mangled name), so teaching the consumer to tolerate it would mask the producer bug → producer fix. But PR #13258's prelink `checkIRDuplicate` abort had a **validly-keyed** `[Import]`-origin linkage clone (real, non-empty mangled name); the bug was pure asymmetry in `IRPrelinkContext::maybeCloneValue::completeClonedInst` — `shared->symbols` registered `[Export]`-origin clones but not `[Import]`-origin ones, so an overlapping import closure re-cloned the same name. Registering the `[Import]` clone (key derived from an `[Import]` decoration when no `[Export]` is present) completes the *consumer's* dedup-registration symmetry, and that is the correct layer because the input shape is canonical, not malformed. Rule: **malformed/absent key → producer bug (fix upstream); valid key the consumer simply failed to record in its own dedup table → consumer fix is right** ([not every slang-ir-link.cpp dedup fix is the #12817 fix-the-producer anti-pattern — test whether the KEY is well-formed](../learnings/1790305347451-not-every-slang-ir-link-cpp-dedup-fix-is-the-12817.md)). And a latent null-deref exposed by a sibling PR teaches two triage classifications: "latent/dormant" (the `getModule()` deref branch is unreachable on master because the decoration is serialized) is neither `reproduced` nor `regression`; and a null `getModule()` on a dummy entry point is the *intended representation* with an established tolerate-it invariant — so "tolerate the null" IS the principled fix, not a work-around [a latent null-deref exposed by a sibling PR + when a WAR is the principled fix](../learnings/1787777363163-a-latent-null-deref-exposed-by-a-sibling-pr-when-a.md).

On labeling a mangling change: implied-constraint synthesis (infer `where T:IFoo` from a constrained generic application) *is* part of the mangle, but it fires ONLY where an unconstrained param is used in a constrained application — exactly the programs that error today. So it never changes the mangle of any program that compiles now and strictly enlarges the accepted set ⇒ additive/monotonic ⇒ argue `pr: non-breaking`; the plumbing (adding a synthesized `GenericTypeConstraintDecl` member) propagates with zero extra wiring [implied-constraint synthesis is additive, not ABI-breaking](../learnings/1787955885624-implied-constraint-synthesis-is-additive-not-abi-b.md).
