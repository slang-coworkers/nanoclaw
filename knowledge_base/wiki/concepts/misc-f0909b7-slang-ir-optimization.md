## TL;DR

Firsthand findings from triaging and planning Slang IR-pass work.

- **Read-only is not value-stable.** An SRV `StructuredBuffer` can alias a `RWStructuredBuffer` bound to the same memory (a spec guarantee). Dominance plus structural equality cannot CSE its loads across a write. `removeRedundancy`/`DeduplicateContext` is pure structural GVN with no memory-dependence analysis; Slang has no MemorySSA or available-expressions pass.
- **Sound cross-block CSE reuses existing machinery:** `isMemoryLocationUnmodifiedBetweenLoadAndUser` plus the `[__noSideEffect]` classifier, which already excludes execution-mask ops. Do not add a `[__readOnlyAccess]` effect tier.
- **Gate reuse positively.** Prove the memory is immutable (`isPointerToImmutableLocation`), then walk the instructions in between for writes. Never enumerate "non-reusable" qualifiers: provenance hides behind chains, loaded handles and phis. A bare `globallycoherent`/`volatile` load is per-access visibility, not an acquire fence, so it does not block reuse.
- **The coherent/volatile-load CSE miscompile is fixed at the `readNone` inference**, because the `[noinline]` wrapper closes over the coherent global. `getRootAddr`'s field-key pre-peel is live on the resource-load branch and bypassed on the plain-Load branch; pass the raw `getPtr()` there.
- **`canInstHaveSideEffectAtAddress`'s Call arm is unsound three ways:** escaping function-child roots (including pointers inside by-value struct args), pointer-valued roots, and a pure-callee exemption that lets DSE drop a store before a `[noSideEffect]` reader.
- **Regression lanes:** CPU lanes need `-g0`; the KernelContext argument masks some alias bugs on CPU, so use CUDA/HLSL FileCheck; spirv-opt `-O` makes "store survives a call" SPIR-V checks meaningless.
- **Codegen-quality reports: first find which optimizer owns the op.** At `-O1` and above SPIR-V is post-spirv-opt, and DXC runs its own DCE; compare `-target hlsl` and `spirv-asm -O0`. Target `__intrinsic_asm` calls survive Slang DCE unless marked `[__NoSideEffect]`/`[__readNone]`, which is never inferred. Slang has no sinking/GCM pass.
- **Dynamic-dispatch shape is fixed by construction:** the seq-ID→tag mapping never folds to identity, and a caller-side merge after dispatch is never tail-duplicated. A static generic callback is the supported way to get per-type code.
- **Variadic-pack bugs** use unflattened operand counts and reproduce only on whole-module compiles (no `-entry`). Detect a symbolic pack leaf by op, not by data type.
- **Fix the producer when the key is malformed.** An empty mangled name on an inst that should carry one is a producer bug. A valid key that the consumer failed to record is a consumer fix.
- **Triage labels:** latent/dormant is neither `reproduced` nor `regression`; a missed optimization is not a defect.
- **Additive vs breaking:** a mangling change is `pr: non-breaking` if the only affected programs do not compile today.

## CSE, aliasing, and the memory-clobber walk

The first plan, a third "read-only access" effect tier wired into call CSE, is unsound as unconditional dominance-based CSE. `DeduplicateContext::deduplicate` keys a `Dictionary<IRInstKey,IRInst*>` on op, type and operand identity, and seeds each dominated child's map from its dominator's, with no store, atomic or barrier analysis. The spec's "Memory Aliasing via Binding" makes SRV and UAV views of the same memory aliased, so collapsing a load across a UAV write is a miscompile ([read-only StructuredBuffer is NOT value-stable](../learnings/1787811803955-read-only-structuredbuffer-is-not-value-stable-dom.md), [DeduplicateContext has no memory-dependence analysis](../learnings/1787816069555-cse-eligibility-for-resource-load-calls-is-not-jus.md)). The sound design reuses existing machinery. The `[__noSideEffect]` classifier already excludes wave, quad and derivative ops, which observe the active-lane mask, so it blocks the mask-dependent CSE that the reporter's divergent-`if` repro would miscompile. Pair it with a strict between-instruction walk in which any store, atomic, barrier, side-effecting or unknown inst blocks the CSE, with no per-address aliasing exemption ([NoSideEffect classifier already excludes execution-mask ops](../learnings/1787825603005-nosideeffect-classifier-already-excludes-execution.md)). The cross-block primitive to reuse is `isMemoryLocationUnmodifiedBetweenLoadAndUser` (`slang-ir-defer-buffer-load.h:35`), a dominance-bounded predecessor walk that uses `canAddressesPotentiallyAlias` for stores and `mightHaveSideEffects()` for everything else. Harden it first: its callers short-circuit on `isPointerToImmutableLocation`, and its `Store` arm trusts a distinct-buffer-root non-aliasing rule that the spec contradicts ([reusable cross-block memory-clobber walk](../learnings/1787824688560-slang-has-a-reusable-cross-block-memory-clobber-wa.md)). A new effect decoration must also be stripped in `specialize-function-call.cpp` and `glsl-legalize.cpp` (both strip `ReadNone`/`NoSideEffect`), and it needs an IR-module version bump.

The gate must be positive. A negative gate ("reuse unless volatile, `globallycoherent`, ROV or memory-scoped") is unsound by default and does not converge. The disqualifier lives on the resource (global param, buffer-block field key, or the ROV type), and its provenance at the access site can hide behind a pre-built element pointer, a handle loaded from a struct or `ParameterBlock` field, or a phi/select of two handles. Reuse only when the memory is provably immutable: a directly resolvable read-only SRV, `ConstantBuffer`, `ParameterBlock` or read-only texture with no coherent/volatile qualifier, or SSA-local, param or constant memory. Unprovable provenance is non-reusable ([sound-by-default beats "detect non-reusable"](../learnings/1789420875085-slang-cse-of-read-only-load-calls-detect-non-reusa.md)). A coherent load between two reads does not block this. A bare `globallycoherent`/`volatile` (HLSL) or `coherent`/`volatile` (GLSL) load is per-access visibility and creates no happens-before over later unrelated accesses. In SPIR-V it carries only the `MakePointerVisible|NonPrivatePointer` operand on its `OpLoad` (Slang emits no standalone barrier, `slang-emit-spirv.cpp:8890,8945`). Happens-before needs `Acquire`/`Release` semantics on `OpMemoryBarrier`/`OpAtomic*`, which are side-effecting and already stop a `mightHaveSideEffects()` walk. So the gate is (a) a positive immutable-read check plus (b) a write-focused between-walk, never "cancel on any coherent access". A `volatile buffer` lowers to a mutable `GLSLShaderStorageBuffer` and fails the positive gate anyway ([bare coherent/volatile load is per-access visibility, not a fence](../learnings/1789422527100-a-bare-globallycoherent-volatile-load-is-per-acces.md)).

#13082 (a `globallycoherent`/`volatile` `ByteAddressBuffer.Load` CSE'd across a store, giving a silent `a+a`) is fixed at the `readNone` inference, not in `isPureFunctionalCall` or `removeRedundancy`. The `.Load` methods are `[__readNone]` unconditionally, because the qualifier lives on the buffer variable (`IRMemoryQualifierSetDecoration`). A `[noinline]` wrapper that calls `.Load` is inferred `readNone` before `.Load` is force-inlined, and `removeRedundancy` then commons the two wrapper calls. The wrapper closes over the global, so only the inference, which sees `call .Load(inData,…)`, can see the qualifier. The fix denies `readNone` in the inference's Call branch when an argument reads a coherent/volatile resource: `resourceAccessTouchesCoherentOrVolatile`, a bounded, cycle-protected backward slice over load, field-address, element-ptr and phi (via `getPhiArgs`). It terminates because the front end allows the qualifiers only on global resource decls. The remaining enabler is a front-end bug: a plain copy `ByteAddressBuffer x = inA;` silently drops the qualifier (only the ternary/argument path diagnoses, E30048), so no IR analysis can recover it. That fix belongs in the semantic checker and is tracked separately ([fix at readNone inference, plus the front-end qualifier drop](../learnings/1789440874211-coherent-volatile-resource-load-cse-miscompile-fix.md)).

The field-key check in `isRepeatableReadLocation` (#13081/#12785) is branch-dependent, not dead code. `getRootAddr` (slang-ir-util.cpp ~936-953) peels `FieldAddress`, `GetElementPtr` and `NodeOutputRecordGetElementPtr`, but not `Load`. On the resource-load branch, `structuredBufferLoad(load(fieldAddr(gp, key)), i)` stops at the `Load`, so the predicate's own peel reaches the member key: a `globallycoherent` `ConstantBuffer` member is not commoned and its plain sibling is. On the plain-Load branch, `return cb.x;` is a bare `Load` of `fieldAddr(cb, xKey)`; `getRootAddr(getPtr())` peels the FieldAddress away, so the check never runs. The fix is local: pass the raw `getPtr()` on that branch. Do not un-peel at the top-level eligibility gate: on CPU/CUDA a `Ptr(StructuredBuffer)` field pointer into `GlobalParams` is not `isPointerToImmutableLocation`-true, so legitimate global reads would be rejected ([getRootAddr + field-key check is branch-dependent](../learnings/1789445655724-correction-getrootaddr-field-key-check-is-branch-d.md)).

`canInstHaveSideEffectAtAddress` (`slang-ir-util.cpp` ~:1442 at 6ba151dcf) is the call-clobber predicate behind store-to-load forwarding (`tryRemoveRedundantLoad`) and DSE (`tryRemoveRedundantStore`). Its `kIROp_Call` arm has three unsound exemptions:

1. It treats any root that is a child of `func` as unreachable by the callee. The sound rule is "a thread-private local that does not escape". Metal/CPU `groupshared` is one victim (see [Metal backend](../concepts/slang-backends-f0909b0-metal.md)). Escape is another: in `uint x = 1; S s; s.p = &x; w(s); out = x;` the load is still forwarded on master (CUDA `out = 1U`), because the argument loop alias-checks only pointer-like arguments and `isValueType(StructType)` is true. `*cb.pp = &x; w();` escapes the same way through global memory.
2. Pointer-valued roots (#13412): `uint* q = cb.p; *q = 1; w(); outb = *q` gives 1 on every target. A fix must also handle escape, cheaply, because the predicate runs inside the O(n²) redundancy scan ([an escaped local var is also forwarded across calls](../learnings/1791143981459-caninsthavesideeffectataddress-an-escaped-local-va.md)).
3. The pure-callee exemption. When `doesCalleeHaveSideEffect` is false, the arm skips its conservative `return true` for non-private roots, but `tryRemoveRedundantStore` uses the predicate as "may read or write". So `*q = 1; r = rd(); *q = 2;` drops `*q = 1` when `rd() { return *cb.p; }` is inferred `[noSideEffect]` (`slang-ir-propagate-func-properties.cpp`); the CPU result is 0, not 1. An escaped local fails the same way (2 instead of 12). It reproduces at master 6ba151dcf and at #13431 head a227aa0, so neither #13421 nor #13431 fixes it. Once #13431's `isCallerPrivateRoot` lands, #13421's comment that "tryRemoveRedundantStore never asks about a non-local root" is false ([the pure-callee exemption lets DSE drop a store before a [noSideEffect] reader](../learnings/1791168347129-caninsthavesideeffectataddress-the-pure-callee-exe.md)).

Regression lanes for these bugs have three traps. First, render-test builds CPU `COMPARE_COMPUTE` lanes with debug info on (`tools/render-test/slang-support.cpp:276-280`), which keeps the loads that forwarding would remove: the same shader emits `return 1U;` at `-g0` and `return *q_0;` at `-g2`. Put `-g0` on the TEST line and show that the lane fails on an unfixed binary ([CPU COMPARE_COMPUTE tests hide IR optimisation bugs unless -g0](../learnings/1790982231204-slang-cpu-compare-compute-tests-can-hide-ir-optimi.md)). Second, on CPU every call also receives the KernelContext pointer, which the argument loop treats as possibly aliasing, so some alias bugs never show on CPU even at `-g0`; check those with CUDA/HLSL FileCheck. Third, spirv-opt at default `-O` removes a Function-storage `OpStore` before an `OpFunctionCall` even when the address escaped to PSB memory, so SPIR-V checks for "the store must survive a reading call" are not meaningful. Also, `SLANG_ASSERT` expands to `SLANG_ASSUME` in release builds, so replacing a reachable guard with an assert makes out-of-contract input UB ([SLANG_ASSERT is an optimizer assumption; CPU lanes need -g0](../learnings/1791173083128-slang-assert-is-an-optimizer-assumption-in-release.md)).

## Missing optimization passes and reusable machinery

When first triaged, Slang had no jump-threading pass. `threadSwitchOnConstantPhi` (#12795) has since landed, but it threads `switch` only, not `IfElse` ([caller-side merge after dispatch is never tail-duplicated](../learnings/1790318679657-slang-dynamic-dispatch-caller-side-merge-after-dis.md)). SCCP folds a switch only on a global constant (a phi with a different constant per edge becomes `Any`), and simplifyCFG is shape-based, not value-based. The per-predecessor-edge walk already exists in `slang-ir-constexpr.cpp`; the insertion point is after SCCP+DCE and before the post-inline `simplifyIR`. A missed-optimization shape can be confirmed GPU-free (`-target spirv-asm -O3` + `grep -c OpSwitch`), but it is not a defect, so do not apply `reproduced` ([Slang has no jump-threading pass](../learnings/1787819801464-slang-has-no-jump-threading-pass-predecessor-const.md)). For narrow SROA of small non-escaping local arrays, both halves exist: peephole already folds `UpdateElement`-over-`MakeArray` to scalars, and `isPromotableVar` already contains the escape analysis. ([narrow-SROA: the scalarization tail and escape analysis already exist](../learnings/1787809324437-slang-narrow-sroa-12787-the-scalarization-tail-and.md)).

## Codegen-quality triage: which optimizer owns the op

A 2026-09-25 batch of reports asked why an op survives or disappears on one target. First ask which optimizer acted.

**Removal is usually downstream.** When "CUDA keeps a dead call but DXIL/SPIR-V remove it", check `-target hlsl` (the call is still there, so DXC removed it) and `-target spirv-asm -O0` or `-dump-ir` (the dead op survives, so spirv-opt removed it). In #13262 (WorldToObject3x4) Slang removed the call on no target. Core-module `__intrinsic_asm` functions lower to a bare GenericAsm. `isNoSideEffectCallee` (slang-ir-util.cpp:3502) keeps the call unless the callee has `[__NoSideEffect]` or `[__readNone]`, and `propagateFuncProperties` skips TargetIntrinsic functions, so neither can be inferred. CUDA cannot clean up downstream, because OptiX's transform-list walk is `asm volatile` optixLdg. To prove a fix without rebuilding the core module, copy the intrinsic into user code with `[__NoSideEffect]`; the call then disappears on every target. Never mark RayTCurrent `[__readNone]`, because an accepted ReportHit changes it ([dead intrinsic call removal on DXIL/SPIR-V is DXC/spirv-opt, not Slang](../learnings/1790318755944-dxil-spir-v-eliminating-a-dead-intrinsic-call-is-u.md)).

**SPIR-V at -O1 and above is spirv-opt's.** `needsOptimization` (slang-emit.cpp:3555-3563) runs the bundled spirv-opt from `-O1`, and the -O2/-O3 preset (slang-glslang.cpp:460-520) includes InlineExhaustive, so single-OpFunction output is not Slang inlining. Compile at `-O0` to see Slang-only SPIR-V. Slang's peephole folds `swizzle(makeVector(...))` only when makeVector has one scalar per lane (it bails at slang-ir-peephole.cpp:1751, so `uint3(u2, 0).xy` survives; the GetElement(MakeVector) fold at :904-947 is the model for a fix). spirv-opt does not fold OpVectorShuffle(OpCompositeConstruct) either. Vector asuint/asfloat on SPIR-V are opaque `spirv_asm { OpBitcast }` blocks, not `kIROp_BitCast`. A local whose field address escapes to a non-inlined call stays a memory var after inlining, which blocks value-level peepholes (#13263) ([-O1+ SPIR-V is post-spirv-opt; swizzle(makeVector(vec,s)) folded by neither](../learnings/1790319181328-slang-o3-spir-v-output-is-post-spirv-opt-swizzle-m.md)).

**Nothing moves a RayQuery getter.** The getters are `[__NoSideEffect]` `spirv_asm OpRayQueryGet*KHR &this` with a BorrowIn `this`. Before inlining, the call fails `areCallArgumentsSideEffectFree`; after inlining, the IRSPIRVAsm hits the default `true` of `mightHaveSideEffects`. They are never DCE'd, CSE'd or moved. Slang IR has no sinking/GCM/remat pass (LICM is off outside autodiff), and spirv-tools' CodeSinkingPass moves only OpLoad/OpAccessChain. To keep reads local to each switch case, call a caller-side generic `intersect_case<G : IGeometry>(inout RayQuery<F> q, …)` per case; its SPIR-V is identical to hand-duplicated reads (#13268). The `[__readNone]` on the 4x3 transform getters is too strong and must be fixed before any movement pass keys on readNone ([RayQuery getters are pinned at source placement](../learnings/1790318756067-slang-pins-rayquery-getters-at-source-placement-pe.md)).

**CUDA struct returns.** NVRTC can give smaller SASS when a tagged-union result is built with separate field writes at a common exit. `simplifyForEmit`'s `processMakeStruct` splits only `store(ptr, MakeStruct)`, never `return(MakeStruct)`, while phi elimination stores each predecessor's value into the struct-param temp. So one local `result`, assigned a visible MakeStruct in every branch, plus one `return`, is the source-level route to per-field writes. Nothing on the CUDA path merges returns; `convertFuncToSingleReturnForm` is the natural hook. Diff the PTX between variants to tell NVVM from ptxas. The local CUDA 12.6 toolkit has no sm_120, so label sm_75/89/90 results as unqualified (#13266) ([CUDA struct returns get per-field writes only via store(MakeStruct)](../learnings/1790318832645-cuda-struct-interface-returns-slang-emits-per-fiel.md)).

**Dynamic-dispatch shape.** `createDynamicObject<I>(runtimeId, 0)` always calls an integer-mapping function (`lowerGetTagFromSequentialID` → `createIntegerMappingFunc`), even when the `-conformance` IDs equal the internal tags, because its `default` arm maps unknown IDs to a registered tag. Making tag == seq-ID therefore also needs an invalid-ID contract (#13220). A static interface forwarder folds nested-existential layers into one dispatch arm, which separates the AnyValue box round-trip cost from the remap cost ([the seq-ID→tag remap switch survives even when IDs equal tags](../learnings/1790318450614-slang-dynamic-dispatch-the-seq-id-tag-remap-switch.md)).

A caller-side merge after dispatch (`if (obj.f(ctx, out c)) accept(c);`) keeps exactly one accept site. Slang has no tail duplication and no heuristic inliner, and `threadSwitchOnConstantPhi` threads switch only. `[ForceInline]` on the impls and `[ForceUnroll]` over constant IDs do not help, because the mapping function is not inlined. The supported form is a static generic callback (a default method `f_and_accept<H>`). A generic helper `f<G:IFoo>(G g, ...)` called with a `createDynamicObject<IFoo>` value has the same limit: it is specialized once for the conformer set (a tag parameter, `specializeGenericWithSetArgs` in slang-ir-specialize.cpp), with a dispatch switch at each witness-method call, so code around the interface call is not per-arm. Per-conformer bodies exist only for interface requirements and default methods. To get a whole caller body per arm without editing `IFoo`, declare `interface ICase { static void run(...); }` and a blanket `extension<G : IFoo> G : ICase { static void run(...) {...} }` in an imported module. Dispatch `createDynamicObject<ICase>(id,0).run(...)` and register `-conformance T:ICase=N` per type with the same IDs; DXIL then has the shape of a default-method callback (#13268). If the blanket extension is in the primary slangc TU, `-conformance T:ICase` fails E00073, because `createTypeConformanceComponentType` sees extensions only from `loadedModulesList` (the #12049 class). `import core;` collides with the built-in module, and `extension IFoo {}` is rejected E30852 ([per-conformer caller specialization under dynamic dispatch](../learnings/1790404968818-per-conformer-specialization-of-a-caller-under-dyn.md)). PR #12924 (v2026.18.2) force-inlines `s_dispatch_*` and the witness wrappers. That changed the DXIL phi count (16→18 on #13267), so diff `-target hlsl` first when comparing releases. Official release tarballs plus `-dxc-path` give same-DXC cross-version comparisons. dxil-asm output contains a NUL byte, so use `grep -a` ([#12924 changed the DXC phi shape](../learnings/1790318679657-slang-dynamic-dispatch-caller-side-merge-after-dis.md)).

## Variadic packs: unflattened counts and whole-module-only repros

The `expand`/`each` unroll count comes from `getCapture(0)->getOperandCount()`. For a concatenation `makeValuePack(scalar, nestedPack)` that is the raw count (2), while the flattened `getTupleElement` domain is 1 when the nested pack is empty, so `getTupleElement` goes out of range and segfaults. `flattenPackOperand` exists, but the count sites do not call it ([expand/each unroll count uses unflattened operand count](../learnings/1787853893292-expand-each-unroll-count-uses-unflattened-operand-.md)). This class of bug reproduces only on whole-module compiles (no `-entry`). With `-entry` the generic specializes eagerly and the concatenation is flattened before the expand unrolls, so `-entry`-driven slang-test tests never hit it. The reliable regression is a whole-module `//TEST:SIMPLE:-target spirv-asm` ([expand pack-arity bugs only reproduce whole-module](../learnings/1787868222506-expand-pack-arity-bugs-only-reproduce-whole-module.md)). When guarding a pack-count computation, detect a still-symbolic leaf by op, not by data type. A symbolic type-pack leaf (`each T`) is an `IRParam` of `IRTypeParameterPackKind`, not an `IRTypePack`, so a type-only check treats it as a scalar. Use the op set that `hasNestedShapePackOperand`/`getPackBranchCardinality` already treats as unknown cardinality ([detect an unresolved IR pack leaf by op, not by data type](../learnings/1787868230656-detect-an-unresolved-ir-pack-leaf-by-op-not-by-dat.md)).

## Producer-side root causes and additive-vs-breaking analysis

An interface with two or more associated-type equality constraints crashes `linkIR` with a duplicate-key assert, because both constraint keys have empty mangled names (#12817). A linker fix (eager-clone any empty-name entry) would mask a producer bug. The root is `removeLinkageDecorations` (added by #7764 for method-requirement values), which strips the key's linkage on an equality constraint whose canonical entry is `(named key, null value)`. An absent canonical identifier on an inst that should carry one is a producer bug. First check whether the inst class is intentionally anonymous (like `IRBuiltinRequirementKey`), then `git blame` the strip site ([equality-constraint key has no mangled name = producer bug](../learnings/1787938004557-slang-12817-equality-constraint-key-has-no-mangled.md)).

Apply the test, not the conclusion: not every `slang-ir-link.cpp` dedup fix is the #12817 anti-pattern. The discriminator is whether the dedup key is well-formed. PR #13258's prelink `checkIRDuplicate` abort had a validly keyed `[Import]`-origin linkage clone. `IRPrelinkContext::maybeCloneValue::completeClonedInst` registered `[Export]`-origin clones in `shared->symbols` but not `[Import]`-origin ones, so an overlapping import closure re-cloned the same name. Registering the `[Import]` clone completes the consumer's own dedup symmetry. That is the right layer, because the input shape is canonical. Malformed or absent key: fix the producer. Valid key the consumer failed to record: fix the consumer ([not every slang-ir-link.cpp dedup fix is the #12817 anti-pattern](../learnings/1790305347451-not-every-slang-ir-link-cpp-dedup-fix-is-the-12817.md)).

A latent null-deref exposed by a sibling PR gives two triage rules. "Latent/dormant" (the `getModule()` deref branch is unreachable on master because the decoration is serialized) is neither `reproduced` nor `regression`. And a null `getModule()` on a dummy entry point is the intended representation, with an established tolerate-it invariant, so tolerating the null is the principled fix ([a latent null-deref exposed by a sibling PR + when a WAR is the principled fix](../learnings/1787777363163-a-latent-null-deref-exposed-by-a-sibling-pr-when-a.md)).

Implied-constraint synthesis (inferring `where T:IFoo` from a constrained generic application) is part of the mangle. It fires only where an unconstrained param is used in a constrained application, which is exactly the set of programs that error today. No currently compiling program's mangle changes, and the accepted set only grows, so argue `pr: non-breaking`. The synthesized `GenericTypeConstraintDecl` member propagates with no extra wiring ([implied-constraint synthesis is additive, not ABI-breaking](../learnings/1787955885624-implied-constraint-synthesis-is-additive-not-abi-b.md)).
