# slang-pr-review: REST review-body edit 404s under App token; use GraphQL updatePullRequestReview

When posting a nv-slang-bot COMMENT-state PR review via `post-review.sh`, the review body is created fine (REST `POST /pulls/N/reviews`), but editing that body afterward via REST `PUT /pulls/N/reviews/{id}` returns **404 Not Found** — the App installation token can create but not edit reviews through that REST path. This bites when you need to append the required bot-transparency disclaimer (`🤖 Generated by an automated Slang coworker…`) after the fact, since `final-review.md` from the runner doesn't include it.

**Fix:** use the GraphQL mutation instead — fetch `.node_id` of the review and call:
```
gh api graphql -F rid="$NODE_ID" -F body=@newbody.md -f query='mutation($rid:ID!,$body:String!){updatePullRequestReview(input:{pullRequestReviewId:$rid,body:$body}){pullRequestReview{id state}}}'
```
This preserves the COMMENTED state (verified) and edits the body successfully. Better still: append the disclaimer to `final-review.md` **before** calling post-back.sh so no edit is needed.

**Second surprise (same run):** the pr-review-runner `transcripts/` dir is shared across all concurrent PR-review sessions and gets clobbered fast — a run dir from ~40 min earlier (`pr-20260710T...Z`) and its `final-review.md` were gone, and `slang/tmp/context.json` had been overwritten by another PR's review (12036). **Always copy `final-review.md` / `clarity-review.md` / `tool-uses.jsonl` into your own `/workspace/agent/review-<pr>/` dir immediately on job completion**, and re-derive the reviewed HEAD from the captured `context.json`/`pr-diff.reference` at capture time, not later.

**Third:** agent-browser (Reviewer B / Devin) cannot launch Chrome in this container (`Failed to connect to the bus … /run/dbus/system_bus_socket`, no DevToolsActivePort). This is deterministic, not a transient/auth-wall/timeout — treat Reviewer B as reliably skipped here and don't burn a retry; A+C still give a complete verdict.
