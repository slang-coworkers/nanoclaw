# Triaging an &quot;add a SPIR-V capability bit&quot; request — vendored-operand check + inert-atom scoping

For Slang issues asking to "add a capability bit" for a SPIR-V extension (e.g. #11538, `SPV_EXT_shader_64bit_indexing`):

**1. Check whether the `SpvCapability*` operand is already vendored before assuming a submodule bump.** Grep `external/spirv-headers/include/spirv/unified1/spirv.h` for the capability name (e.g. `64BitIndexing`). If present (`SpvCapabilityShader64BitIndexingEXT = 5426` was already there at submodule aaffbc5), there is **no SPIRV-Headers bump** — the backend `requireSPIRVCapability(...)` path compiles. Even if absent, the `spirv_asm` string-literal path (`OpCapability "..."`) avoids the compile-time enum dependency. Don't reflexively scope in a submodule update.

**2. A capdef atom alone is INERT — flag the scoping question.** Adding `def SPV_EXT_xxx : _spirv_1_0;` + `def spvXxxEXT : SPV_EXT_xxx;` to `source/slang/slang-capabilities.capdef` (each needs `///` doc + `/// [EXT]` tag; regenerated by `slang-capability-generator`, never hand-edit generated headers) only makes the capability *referenceable*. It emits no `OpExtension`/`OpCapability` until a consumer references it (intrinsic gated `[require(spvXxxEXT)]` whose body is `spirv_asm`, or C++ emit keyed on an IR op). So "add a capability bit" is genuinely ambiguous: bare referenceable atom (small, ~2 lines) vs. functional language surface (net-new design if the stdlib has zero existing surface for the feature). Surface this to the author rather than guessing.

**3. ABI:** adding a capdef atom is **non-breaking** — `CapabilityName`/`CapabilityAtom` is a generated/internal enum, not ABI-stable public surface (`include/slang.h:1008` only references it in a doc comment). Label PR `pr: non-breaking`.

**4. Gating pitfall (recurring):** never gate lowering on `targetCaps.implies(SPV_EXT_...)` for a fresh extension atom — target cap sets are minimal and extension atoms are added on-demand at emit, so the implies-check silently elides. Gate on target family (`isSPIRV(...)`).
