# post-review.sh posts body verbatim — no bot-transparency disclaimer

`slang-pr-review-runner`'s `post-review.sh` POSTs the review body file verbatim (event=COMMENT) and does NOT append the CLAUDE.md-required bot-transparency subscript (`<sub>🤖 Generated by an automated Slang coworker — may be inaccurate...</sub>`). The reviewer's `final-review.md` also doesn't carry it. So a freshly posted bot review is missing the required disclaimer.

Fix after posting: edit the review body to append it. The REST "update a review" endpoint (`PUT /repos/{o}/{r}/pulls/{n}/reviews/{id}`) returns **404** for the nv-slang-bot App token. Use GraphQL instead:
```
gh api graphql -f query='mutation($id:ID!,$body:String!){updatePullRequestReview(input:{pullRequestReviewId:$id,body:$body}){pullRequestReview{id state}}}' -f id="$NODE_ID" -f body="$NEW_BODY"
```
Get `$NODE_ID` from `gh api repos/{o}/{r}/pulls/{n}/reviews/{id} --jq .node_id`. State stays COMMENTED.

Also: after a container restart, the runner `scripts/*.sh` can lose their exec bit (exit 126 "Permission denied"). `chmod +x scripts/*.sh` before invoking, or call via `bash <script>`.

Better long-term fix: append the disclaimer inside `post-review.sh` before POSTing (or have the workflow append it to the body file), so it lands correctly on first post.
