# [approver/gating-safety] Lazy autodiff-module load (slang#12136) crashes on IDifferentiable-CONSTRAINED types with no trigger — gap#1 is real (SIGSEGV), not advisory

**PR:** slang#12136 "Load autodiff builtins on demand" (jvepsalainen-nv, issue-12113). Splits diff.meta.slang into a lazily-loaded `BuiltinModuleName::Autodiff` supplement. Two — and only two — load triggers: (1) `checkDifferentiableCallableCommon` when `_callableHasDifferentiabilityHeaderModifier` (`[Differentiable]`/`[MaybeDifferentiable]`) is true (slang-check-decl.cpp:14952); (2) `_checkHigherOrderInvokeExpr` on `DifferentiateExpr`/`PrimalSubstituteExpr` (slang-check-expr.cpp:5965). No catch-all — verified grep of entire diff: no torch/CUDA-target, `[CUDAKernel]`/`[AutoPyBindCUDA]`/`[TorchEntryPoint]`, `no_diff`, or name-lookup load path.

**The production review's gap #1 (load triggers miss name-refs to supplement types + IDifferentiable conformance of Array/Optional/Tuple) is REAL and REACHABLE — and worse than "wrong result": it CRASHES.** Confirmed by RED CI at the PR head: deterministic SIGSEGV across ALL 7 `test-slang` jobs at `tools/slang-unit-test/unit-test-function-reflection.cpp:383` (`module->getLayout()->findTypeByName("MyStruct<float>")` → `findFunctionByNameInType`). The reproducing shader (the unit test's own source, PRE-EXISTING, not modified by the PR) uses `IDifferentiable` ONLY as a generic constraint — `interface IScalarActivation<float:IDifferentiable>`, `struct MyStruct<float:IDifferentiable>: IScalarActivation<float>`, extensions constrained on `float:IDifferentiable` — with NO `[Differentiable]` callable and NO fwd_diff/bwd_diff. So neither trigger fires, the supplement never loads, and reflecting/checking the IDifferentiable-constrained type SIGSEGVs. Second failing test: `tests/language-feature/interfaces/assoctype-param.slang` (`IFloat`-constrained; `IFloat : IArithmetic, IDifferentiable` at core.meta.slang:304, so IFloat pulls in IDifferentiable). `IDifferentiable` interface itself IS `[KnownBuiltin]` in base core.meta.slang:646 and resolves — the crash is downstream machinery assuming the supplement's shape.

**Why the struct-ctor `no_diff`-mis-stamp path is NOT the bug (ordering saves it):** `SemanticsDeclAttributesVisitor::visitStructDecl` synthesizes memberwise ctors and stamps `no_diff` on members where `isTypeDifferentiable(memberType)` is false (slang-check-decl.cpp:19922) — runs for EVERY struct, ungated. BUT `checkModule` is breadth-first over `DeclCheckState` (slang-ast-support-types.h:474): `ReadyForLookup`(523, where trigger#1 fires in SemanticsDeclHeaderVisitor) completes for ALL decls BEFORE any decl reaches `AttributesChecked`(541, ctor synthesis). So in any module with a `[Differentiable]` callable, the supplement loads before ctor synthesis queries conformance → no mis-stamp. Also the negative subtype-witness cache is generation-guarded (`tryGetSubtypeWitnessFromCache` evicts on inheritance-generation mismatch, slang-check-inheritance.cpp:107), and the PR's new `addLoadedCoreModule` calls `bumpDeclExtensionEpoch(typeDecl)` for each extended-type decl (Array/Optional/Tuple/TensorView are the keys in the supplement's `mapDeclToCandidateExtensions`) → cached null witnesses self-heal after a trigger. The author clearly understood the cache hazard. The UNHANDLED hole is the pure constraint/reflection path that NEVER fires a trigger.

**Decision consequence:** This is a BLOCK-class red-CI, PR-caused regression (not ABSTAIN/OPEN_GAP-advisory) — reproduced deterministically on unmodified pre-existing tests. Distinct from the earlier #12136 CHALLENGER_CONCERN null-deref learning (that was `translateFwdDerivativeAttributeToAD2` context-owned-module deref, unproven-reachability → ABSTAIN). Here reachability is PROVEN by CI. Challenger probe for any lazy-builtin-load PR: does an interface used only as a GENERIC CONSTRAINT (`<T:IDifferentiable>`, `<T:IFloat>`), or REFLECTION of such a type, fire a load trigger? If not, and the supplement's shape is assumed downstream → crash. Also: `check-cmdline-ref` red is trivial (new -save-autodiff-module* CLI opts, needs doc regen) — not correctness.
