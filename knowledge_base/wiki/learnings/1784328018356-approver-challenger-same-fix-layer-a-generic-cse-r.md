# [approver/challenger] Same-fix Layer-A (generic CSE) revision needs a fresh CI probe — broader blast radius than the Layer-B head you approved

**Symptom:** PR #12111 R1 @4e78df9c (Layer B — coalesce in the SPIR-V legalizer `insertLoadAtLatestLocation`, dominance-by-construction, descriptor-heap `getElement` loads only) → WOULD_APPROVE, clean. On `synchronize` the author re-implemented the SAME fix as Layer A: one guarded branch in the generic `isMovableInst` (slang-ir.cpp) making any `AddressSpace::UniformConstant` load movable, so the existing `removeRedundancyInFunc` CSE collapses the redundant loads. Reviewer csyonghe explicitly directed this ("add the opcode to the switch in `isMovableInst`"); jkwak confirmed. Devin parsed 0-bug/APPROVE. **BUT the new head regressed `tests/glsl-intrinsic/intrinsic-texture.slang.6/.7/.8` (the `-target spirv -O3` directives of an UNMODIFIED test) on 8 test-slang legs — green on master, not expected-failure → BLOCK (RED_BUG).**

**Root cause (the transferable class):** A "move the same fix to a more generic/earlier layer" revision is NOT a re-sync — it is a materially different change with a **different blast radius**, and must get a full fresh challenger, not a rubber-stamp of the prior verdict. Two distinct axes to check, do not conflate them:
1. **Cross-TARGET leakage** (the axis the orchestrator worried about): often resolvable *by construction*. Here: exhaustive `grep -rn AddressSpace::UniformConstant source/` showed it is *assigned* at exactly ONE site (`slang-ir-spirv-legalize.cpp:518`, a SPIR-V-only pass) and the CSE consumer `removeRedundancyInFunc(func,false)` is called only from `simplifyIRForSpirvLegalization` (SPIR-V-only). ⇒ the new `isMovableInst` branch is dead code on HLSL/Metal/CUDA/GLSL/WGSL. Cross-target leakage was structurally impossible. This axis cleared.
2. **Broader reach WITHIN the same target** (the axis that actually bit): a generic predicate keyed on a storage class fires on ALL loads of that class, not just the narrow shape the layer-B fix touched. Layer B only touched descriptor-heap `getElement` loads; Layer A's predicate ALSO makes plain combined-sampler globals (`uniform sampler3D`) movable, so CSE reordered/merged their loads and broke a golden's `[[LOAD]] … OpImageQueryLod{{.*}}[[LOAD]]` capture-adjacency. **A widening from a construction-scoped fix to a predicate-scoped fix always widens the set of affected IR — enumerate what else matches the predicate.**

**How to catch it:** On any revision that moves a fix from a narrow/legalizer layer to a generic predicate (`isMovableInst`, `isMovableInst`-like, CSE/GVN/duplication predicates): (a) grep every OTHER shape that satisfies the new predicate on the same target (here: every UniformConstant load, incl. plain textures/samplers via `isSpirvUniformConstantType` which covers `IRTextureTypeBase`/`IRSamplerStateTypeBase`/arrays); (b) **pull the live CI test-slang legs and diff failures against master** — a PR-caused break of an UNMODIFIED, previously-green, not-expected-failure test is a verified 🔴 ⇒ BLOCK even when the review doc is clean and the policy doesn't require CI green. Devin does NOT build/run tests (recurring: [[pr-12122-decided]], [[pr-12141-decided]]), so a Devin-only 0-bug verdict is BLIND to codegen-golden regressions — the CI probe is mandatory on any emit/CSE change.

**Fix (decision):** BLOCK, flagged the within-SPIR-V blast radius for triager. The PR's own new test (desc-handle-load-reuse) PASSED under spirv-val, so the motivating case is correct — the defect is un-updated collateral SPIR-V goldens the wider predicate disturbs; author must regenerate goldens or narrow the predicate. Contrast [[pr-12130-decided]] (target emit change broke unmodified test → BLOCK-VINDICATED) — same shape. Related priors: the #12051 wiki investigation recorded that Layer B's safety is dominance-by-construction and NON-transferable to a generic predicate, and that `isMovableInst` feeds the all-target redundancy pass — exactly this.
