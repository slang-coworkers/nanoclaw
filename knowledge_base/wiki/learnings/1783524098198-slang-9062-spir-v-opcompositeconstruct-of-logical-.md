# slang#9062 SPIR-V OpCompositeConstruct of logical-pointer array escapes resource legalization (struct-field blindness)

**Symptom:** SPIR-V validation `error: Instruction may not have a logical pointer operand` on `%N = OpCompositeConstruct %_arr__ptr_StorageBuffer_... %buf %buf`. Slang emitted an `OpCompositeConstruct` building an array (or struct) whose element/field type is a *logical* (StorageBuffer/Uniform/Workgroup) pointer — e.g. an array of `RWStructuredBuffer` resource-pointers. SPIR-V logical addressing forbids logical pointers as operands to `OpCompositeConstruct`/`OpCompositeExtract` (only load/store/access-chain/function-call/select/phi). Reproduced statically, NO GPU: `SLANG_RUN_SPIRV_VALIDATION=1 slangc test.slang -target spirv -stage compute -entry main`. (Need slang-glslang on LD_LIBRARY_PATH; a Debug build often omits it — point at `build/slang-<ver>-linux-x86_64/lib`.)

**Root cause / the non-obvious bit:** The passes that normally eliminate arrays-of-resources for Vulkan/SPIR-V only inspect the array's **direct element type** — they `unwrapArray()` (recurse through *nested arrays*) and check whether the unwrapped type is DIRECTLY a resource (`IRHLSLStructuredBufferTypeBase`, texture, param-group, ...). They do **NOT recurse into struct fields**. So a `struct MyPtr { RWStructuredBuffer buf; uint off; }` used as `MyPtr[2]` is invisible to them — `MyPtr` isn't a resource type, it merely *contains* one — while a bare `RWStructuredBuffer[2]` param IS caught. Key predicates (shader-slang/slang @bfe6a7f14): `isIllegalGLSLParameterType`/`isIllegalSPIRVParameterType` (slang-ir-specialize-resources.cpp:1324/1364), `TypeInliningPass::doesTypeRequireInline` (slang-ir-inline.cpp:1050-1107, only fires for Ref/BorrowIn/BorrowInOut wrapper param types), `IRResourceTypeLegalizationContext::isSpecialType` (slang-ir-legalize-types.cpp:3981). Pass ordering (slang-emit.cpp): specialize/translate(1347) → finalizeAutoDiffPass(1358) → performTypeInlining(1523) → legalizeResourceTypes(1776) → specializeResourceUsage(1840) — so resource legalization runs AFTER autodiff; the escape is structural blindness, NOT a timing/gating gap. Don't chase "autodiff runs too late" — it doesn't.

**Autodiff angle:** `Array<T,N> : IDifferentiablePtrType` (diff.meta.slang:1385-1389) makes `MyPtr[2]` itself a differentiable-ptr type, so autodiff wraps the WHOLE array as one `DifferentialPtrPair<MyPtr[2]>` (core.meta.slang:869-897), and `processPairTypes` (finalizeAutoDiffPass, slang-ir-autodiff.cpp:1186) lowers that pair to a struct — reliably materializing the array-of-resource-pointers as a first-class composite. Non-autodiff code seemingly never forms this shape (gets inlined/scalarized first), which is why the maintainer couldn't repro without autodiff.

**Fix direction:** Preferred = SPIR-V-target legalization near `processConstructor` (slang-ir-spirv-legalize.cpp:1780) that rewrites a MakeArray/MakeStruct with logical-pointer element/field into a Function-storage var + per-element OpStore/OpAccessChain (target-scoped, keeps emit simple per repo methodology). Alt = teach the resource-legalization predicates to recurse through struct fields (more thorough, wider blast radius — must target-gate since HLSL/CUDA allow struct-of-resource params). `VariablePointers` capability does NOT help — it never legalizes OpCompositeConstruct operands. Related closed: #5805 (ptr params to diff fns crash), #9801 (OpCompositeExtract from pointers).
