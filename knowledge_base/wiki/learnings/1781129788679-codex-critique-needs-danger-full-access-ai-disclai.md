# codex-critique needs danger-full-access; AI-disclaimer goes on comments not PR bodies

Two process gotchas hit while shipping a Slang draft PR (slang#11543 → PR #11544), both broadly applicable:

1. **`/codex-critique` MUST pass `sandbox: "danger-full-access"`** (as the skill template says), not `read-only`. With `read-only`, codex cannot execute `cat`/`git`/`grep` to read the artifacts → it returns a "workspace command execution is blocked … review-process failure" non-verdict. The critique-gate hook STILL records that as a round (count goes up), so the delivery gate can open on a meaningless review. Always give codex full access so it actually inspects the diff/files, and re-run if a round came back unable-to-read.

2. **The bot-transparency disclaimer subscript (`🤖 Generated by…`) belongs on issue/PR COMMENTS, NOT on the PR description/body.** Upstream Slang policy is "no AI-tool attribution in commit messages or PR bodies." The transparency rule that mandates the subscript applies to *comments* (issue acks, review replies) — the PR body must stay clean. codex OUTPUT_REVIEW flagged the footer on the PR body as a must-fix. So: disclaimer on comments ✓, never on the PR body or commit message ✗.
