# [approver/infra-abstain] Policy mount can vanish across container re-creation → eval-clauses silently uses bundled v0-shadow (wrong); restore v0-shadow-wide before deciding

**Symptom.** On a revision re-run of shader-slang/slang#12503 (2026-09-01, after the container was re-created), `eval-clauses.py` printed `(policy v0-shadow)` and FAILed `author_trust` for a CONTRIBUTOR author + marked `commit_match` unevaluable — a completely different clause outcome than the same PR's R1 run (2026-08-17), which used `(policy v0-shadow-wide)` and passed all clauses.

**Root cause.** The group policy-of-record mount `/workspace/extra/approver-policy/APPROVAL_POLICY.json` — and the sibling `/workspace/agent/policy/APPROVAL_POLICY.json` — were **empty** this session. Both dirs existed but were re-created as empty root-owned dirs (container re-creation didn't re-populate the mount). `eval-clauses.py` policy precedence is: `--policy` → `<ws>/policy/APPROVAL_POLICY.json` → `/workspace/extra/approver-policy/APPROVAL_POLICY.json` → **bundled DEFAULT (`scripts/APPROVAL_POLICY.json` = `v0-shadow`)**. With the mount gone it silently fell to the bundled `v0-shadow`, which is the deliberately-conservative default the org EXPLICITLY widened away from: `v0-shadow` trusts only [OWNER, MEMBER, COLLABORATOR] (so CONTRIBUTOR/NONE/FIRST_TIMER FAIL author_trust), `require_ci_green:true`, protected `.github/**`+CMake+yaml+external, caps 400/30. The policy of record `v0-shadow-wide` (human-signed haaggarwal 2026-08-04) trusts CONTRIBUTOR/NONE/etc., `require_ci_green:false`, protected only `**/slang-tag-version.h`, caps 8000/150.

**Why it matters (silent, not loud).** The fallback is by-design ("if none mounted, use bundled v0") so nothing errors — but it flips the effective policy. Under bundled `v0-shadow`, EVERY CONTRIBUTOR/NONE-authored PR gets a spurious `author_trust` FAIL → ABSTAIN_POLICY:CLAUSE_FAIL:author_trust, and the recorded `policy_version` becomes `v0-shadow` instead of `v0-shadow-wide` — corrupting the agreement measurement the wide policy exists to preserve. A single decision looks plausible; the damage is systematic across the session.

**How to catch it.** eval-clauses prints the policy_version it loaded — if it says `v0-shadow` (not your mounted `v0-shadow-wide`), the mount is missing. Also: an `author_trust` FAIL on a CONTRIBUTOR, or clause outcomes that differ from a prior run on the same PR, are the tells. `ls -la /workspace/extra/approver-policy/` — empty dir = broken mount.

**Fix.** Do NOT record under the bundled default when the mount is merely missing (the policy of record didn't change; the mount broke). Restore the authoritative policy into the per-PR policy slot `<ws>/policy/APPROVAL_POLICY.json` (precedence #2) — its content is recoverable verbatim from any prior decision row's `clauses.policy_note` or a prior session's read — then re-run eval-clauses (it will report `v0-shadow-wide`). Record with `policy_version=v0-shadow-wide` and a `clauses.policy_note` documenting the missing mount. **Escalate to the operator to re-populate `/workspace/extra/approver-policy/`** so subsequent sessions don't silently run under the wrong policy. (The canonical v0-shadow-wide: trusted=[OWNER,MEMBER,COLLABORATOR,CONTRIBUTOR,FIRST_TIME_CONTRIBUTOR,FIRST_TIMER,NONE], allow_fork_head=true, require_ci_green=false, protected_paths=["**/slang-tag-version.h"], max_total_lines=8000, max_files=150.)
