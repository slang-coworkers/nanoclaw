# CORRECTION slang#12051: DescriptorHandle reuse ALREADY works on HLSL via a local; #11798 is input-syntax only, not the reload fix

**Corrects two earlier slang#12051 learnings** that claimed "load-once is SPIR-V/GLSL-only because HLSL lowers to ResourceDescriptorHeap[i] with no value to pin." That was an unverified inference and is **wrong**. Empirically checked with a local slangc build (`2026.12.2-60-g33f9ed0ce`, ≈HEAD; HLSL codegen path unchanged).

**Empirical repro (HLSL, `-target hlsl -profile cs_6_6`), DescriptorHandle<Texture2D> sampled 3× in a `[ForceUnroll]` loop:**
- Convert INSIDE the loop (`Texture2D tex = texH;` each iteration): generated HLSL emits `ResourceDescriptorHeap[i]` **3 times** (`_S3/_S5/_S7`, same index) — one heap fetch per use. This is the reporter's complaint, reproduced.
- Convert ONCE before the loop and reuse the local: generated HLSL emits `ResourceDescriptorHeap[i]` **once** (`_S1`), reused across all 3 `SampleLevel` calls.

**So resource-typed locals ARE storable and reusable on HLSL today** — `canInstBeStored(Texture2D)` = true (`slang-ir-util.cpp:2615-2627`), and resource types are NOT in `isPtrLikeOrHandleType` (`:1229-1260`), so they're not force-duplicated. The reporter (maxime-modulopi) was right: "store the ResourceDescriptorHeap[i] result in a variable" works on HLSL. The per-use reload only happens when the conversion is written per-use (inline / `operator*` at each use). The user-side fix needs no new builtin on HLSL — just hoist the conversion into a local. (On SPIR-V the analogous `CastDescriptorHandleToResource` IS force-duplicated by design at `slang-ir-util.cpp:2638` "potentially produces non-storable types" — so SPIR-V may still benefit from an explicit pin; that asymmetry is the real cross-target nuance, not "HLSL can't pin".)

**#11798 (Closes #11568, non-draft, jkwak "Office-Yong") does NOT close #12051.** Read the diff: it adds the `ResourceDescriptorHeap[i]`/`SamplerDescriptorHeap[i]` INPUT SYNTAX via new `UntypedResourceHandle`/`UntypedSamplerHandle` types that lower to `uint` before emit (`lowerUntypedResourceHandleToUInt` in slang-ir-lower-dynamic-resource-heap.cpp; peephole at slang-ir-peephole.cpp only collapses the `uint↔untyped-handle` wrap/unwrap round-trip). It changes how you SPELL a heap index, not how many times the descriptor LOADS. Written per-use it re-materializes the same way; hoisted into a local it reuses. Complementary to #12051, not a fix for it.

**#12027 relation (jkwak's cited comment 4930059216):** SAME underlying phenomenon at a different boundary — textures/images passed INTO functions as descriptor INDICES (a historical graphics-driver workaround) rather than resource-typed params, so the loaded resource isn't carried across the call and the descriptor is re-fetched. #12051 is the loop-local version. jkwak's note that "drivers might be in a better place now" (to take resource-typed values directly) is what would make compiler-side auto-reuse safe here.

**Meta-lesson (why the original note was wrong):** the "no value to pin on HLSL" claim was made from reading the lowering path alone without running the emitter. A 2-minute `slangc -target hlsl` on a hand-written repro would have caught it. For any cross-target codegen claim in a triage/verdict, EMIT AND GREP before asserting — source-path reading establishes the mechanism but not the observable output shape, and the observable shape is what the reporter and maintainer actually see.
