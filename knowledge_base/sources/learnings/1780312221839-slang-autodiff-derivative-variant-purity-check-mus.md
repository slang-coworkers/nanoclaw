# Slang autodiff: derivative-variant purity check must accept [PreferRecompute], not just [__readNone]

## Context
Fixing shader-slang/slang#11374 (follow-up to #11286): extend the `isInstCarryingOverDiff` readNone carry-gate in `source/slang/slang-ir-check-differentiability.cpp` so a `[__readNone]` primary's call is only treated as carry-elidable when its **associated derivative variants** are also side-effect free. Walk `AnnotationKind::{ForwardDerivative, BackwardDerivativeApply, BackwardDerivativePropagate}` via `ctx.tryGetAssociationOfKind(callee, kind)`.

## The non-obvious trap
The naive implementation — require each derivative to satisfy `isReadNoneCallee` (i.e. explicit `[__readNone]`) — produces **false-positive E41031** on built-in math (`sqrt`, `max`, `dot`, `operator/`). Why: those derivatives are generated by macros in `source/slang/diff.meta.slang` (e.g. `UNARY_DERIVATIVE_IMPL`) that annotate with **`[PreferRecompute]`**, NOT `[__readNone]`. And `checkAutoDiffUsages` runs at `slang-lower-to-ir.cpp:~15002`, **before** `propagateFuncProperties` (which lives in `simplifyIR`, much later), so those derivatives are not yet marked readNone at check time.

## What works
In the derivative-purity helper, accept BOTH signals: `isReadNoneCallee(deriv)` OR the underlying `IRFunc` carries `IRPreferRecomputeDecoration`. Two gotchas:
1. **Exclude `SideEffectBehavior.Allow`.** `[PreferRecompute]`'s operand 0 is `SideEffectBehavior` (`Warn=0`, `Allow=1`; see `core.meta.slang` ~4747). `Allow` explicitly permits side effects, so only the default `Warn` form is a purity signal. (Codex flagged this as a must-fix.)
2. **Recurse, don't iterate, through the wrappers.** A derivative association can be `IRSpecialize<IRTranslateBase<IRSpecialize<IRGeneric>>>` — e.g. `BackwardPropagateFromLegacyBwdDiffFunc` wrapping a specialized generic. Mirror `isReadNoneCallee`'s structure: handle `IRTranslateBase` ops (recurse into operand 0, or operand 1 for `BackwardPropagateFromLegacyBwdDiffFunc`), then `IRSpecialize`→operand0, then `IRGeneric`→`findGenericReturnVal`, then check the `IRFunc`.

## Rejected alternatives
- Running `propagateFuncProperties` early (before checkAutoDiffUsages): it auto-marks pure user functions readNone, which breaks the `no-diff-carry-readnone-only-positive.slang` regression guard (that test relies on a non-`[__readNone]` primary falling back to "always carries").
- Adding `[__readNone]` to ~63 macro sites in diff.meta.slang: too invasive.
- Modifying `isReadNoneCallee` in slang-ir-util.cpp: it has 3 other callers that want narrow primary-only semantics.

The fix stays file-local in slang-ir-check-differentiability.cpp.
