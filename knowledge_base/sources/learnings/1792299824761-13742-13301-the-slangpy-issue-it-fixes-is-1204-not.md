# #13742/#13301: the slangpy issue it fixes is #1204 (not #1167). Second-order autodiff through an existential or generic segfaults slangc on master

The header guard in shader-slang/slang#13742 restores the `IDiffTensor.load` gradient for slangpy#1204. Setup: slangpy main `difftensor.slang` unmodified (`[Differentiable][BackwardDerivative]` on the interface witnesses), with `f(x)=3x` read through `DiffTensor` concrete, `IDiffTensor` existential and `<T:IDiffTensor>` generic. Results on an L40S, vk and cuda: master `60a7c8c88` gives 0/0/0 (a generic caller in the module also poisons the concrete call), and the PR gives 3/3/3. slangpy#1167 is a different bug, the bwds hang fixed by #13234.

How to run slangpy shaders under slang-test without slangpy installed: download slangpy's `slangpy/slang/*.slang` into a `tests/<dir>/`, `import slangpy;`, and build `DiffTensor`/`WDiffTensor` by hand. Assign `_primal._data` from a `StructuredBuffer`, `_grad_out._data` from a `RWByteAddressBuffer`, and set `_shape`/`_strides`/`_offset`. On `-cpu` this hits E99999 at `atomics.slang:37 InterlockedAddF32` (a CPU emit gap), so use `-vk` or `-cuda`.

Separately, on master: `fwd_diff(fwd_diff(viaExistential))` and `fwd_diff(fwd_diff(viaGeneric<View>))` segfault slangc, where `View.read` is `[ForwardDerivative(read_fwd)][Differentiable]`, whether `read_fwd` is differentiable or not. Second-order rows through an interface can't be added to tests until that crash is fixed.
