# Operation doc comments are one line of responsibility; extra parser scopes break deferred-body capture

tangent-vector's doc-comment philosophy, stated with force on slang PR #14627 (2026-11-19): a doc comment on an OPERATION states its responsibility, full stop — "Parse a condition clause." / "Check a condition clause in place." — never the per-case walkthrough of how subclasses are handled, never the implementation mechanics, never rationale essays. His test: the comment on `Val* evalExpr(Expr*)` would be "evaluate an expression and return the resulting value", NOT "if the expression is a variable reference then...; if it's a subscript then...". Rationale/justification prose in a doc comment is a signal the abstraction is wrong ("Most of the comment is you trying to justify why the ugly code you wrote is valid"). Invariants and non-obvious *why* still belong as SHORT inline notes at the load-bearing line, and type-level doc comments may still describe the type + how a client uses it — but operation docs = one line of responsibility. I burned five review rounds learning this; write every new operation doc comment this way from the first commit.

Also from the same rounds: (a) pushing a fresh parser scope around every `if`/`while`/`do`-`while` condition (statement-owned unconditional scopes, a maintainer design suggestion) BREAKS the core module build — deferred-body parsing (UnparsedStmt::currentScope capture + parseUnparsedStmt re-parse) ends up with contaminated scope chains: lookups in hlsl.meta.slang bodies (e.g. VECTOR_MAP_UNARY at :8088) resolve against a *sibling function's* scope objects and names become undefined identifiers. Repro: `slang-bootstrap -compile-core-module`. Disabling only the if-condition push made the build green; while/do-while pushes alone did not reproduce it. Debug technique that nailed it in three probes: (1) toggle one push site off and rebuild the slang-bootstrap target (~4 min), (2) minimize by editing hlsl.meta.slang locally + `cmake -E touch` + relink, (3) a temporary fprintf in the undefined-identifier diagnose path dumping the expr's scope chain (names + astNodeType of each containerDecl) — the chain rooting at a different function was the smoking gun. Remove the probe afterward.
