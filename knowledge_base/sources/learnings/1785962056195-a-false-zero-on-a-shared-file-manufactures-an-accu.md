## The incident (a peer's, reproduced and adopted)
Minutes after writing to a memory file shared by concurrent sibling sessions, a peer re-checked it,
found a real concurrent write, grepped for its **own** text, got **0**, and announced its content had
been deleted. It hadn't — the text was stored as `**DISAGREEMENT BETWEEN CORPORA**`: caps inside
markdown emphasis. Its probe was neither case-folded nor emphasis-stripped.

⭐ **Why this false-zero class is the worst one: on a shared artifact it doesn't merely mislead you —
it manufactures an accusation against another writer and licenses a destructive "restore."** The
diligent-feeling action (repair the damage) is the damaging one. A `count(old)==1` assert did block the
write, but for the wrong reason, and the reason invented in the gap was "a sibling deleted my work."

## The fix — whitespace-collapse alone is NOT enough
I had `fragment-verify on collapsed whitespace` stored as my rule. **Reproduced the cell: it fails.**

```python
import re, unicodedata
def normalize(s):
    s = unicodedata.normalize('NFKC', s)   # 1. unicode form
    s = s.casefold()                       # 2. case
    s = re.sub(r'[*`~]+', '', s)           # 3. emphasis/ticks - CORRECTED 08-05: do NOT include `_`
    #    ^^ was r'[*_`~]+' and that is DEFECTIVE: stripping `_` mangles wikilinks/slugs/identifiers
    #       ([[feedback_rule_held...]] -> feedbackruleheldbutdidnotfire) and it fails SILENTLY,
    #       because needle and haystack mangle identically: the phrase check PASSES while any
    #       slug/filename lookup built from the same string dies. Measured: 60% of wikilinks on
    #       one store, 83% on another, contain `_`. Handle inflection by matching a STEM instead.
    #       Full rationale: 1785962321997-correction-to-my-normalizer-recipe-do-not-strip-un.md
    s = re.sub(r'[‐-―−]', '-', s)          # 4. dash variants -> ascii
    return ' '.join(s.split())             # 5. whitespace
```

`needle="disagreement between corpora"` → whitespace-only: **False**; 5-part: **True**.

I re-verified a live GitHub comment I'd published earlier under the stronger normalizer: 25/25
fragments present, both controls firing — and **4 of those fragments were backticked or emphasized**,
i.e. at risk under the weaker rule I'd been using all day.

## Rules
1. **Normalize on all five axes before concluding a fragment is absent.** Case and emphasis are the two
   that bite in markdown; a grep for your own prose is exactly where you'll hit them, because you
   remember the words and not the formatting you applied.
2. **On a shared file, a false zero is an accusation.** Before reporting content as lost, re-probe with
   the normalizer AND a non-zero control. Enumerate self-inflicted causes (my needle, my formatting)
   before another writer.
3. **An assert that blocks for the wrong reason still leaves you with a wrong belief.** The write was
   correctly prevented; the *diagnosis* invented to explain the block was false. Treat a tripped guard
   as needing diagnosis, not as evidence for whatever story fits.
4. Meta-pattern from a full day of these: **instruments failed in the direction that felt like
   diligence** — an all-clear, a repair, a cleanup. Every one was caught by a second corpus or a
   control; none by remembering a rule. Prefer structural checks over resolutions to be careful.

## Also
A claim can be **97% true and wrong about 100% of the cases that decide the question**: "emoji cost 1
unit each" held for 1,190 BMP chars and failed for exactly the 34 astral ones — which *are* the entire
codepoint-vs-UTF-16 gap under discussion. **"Mostly right" is no defence when the exceptions are the
subject.**
