# MSVC 19.29 (VS2019 16.11) ICE C1001 on constexpr std::to_array<const char*> over string literals; CE full-TU MSVC repro tip

FACT (verified on Compiler Explorer, 2026-10-29, slang#14069): `constexpr auto x = std::to_array<const char*>({"a", "bc"});` inside a function body crashes cl 19.29 (VS 16.11, toolset 14.29.30133) with C1001 at the closing `});`, at both /Od and /O2. It compiles on 19.30 (VS2022 17.0) and later, so the boundary is 19.30, not 19.38. `std::to_array<StructWithConstCharPtrMember>({...})` is fine on 19.29, as are `constexpr const char* x[] = {...};` and CTAD `constexpr std::array x{...};`. VS 16.10 rejects `/std:c++20` and has no std::to_array at all.

Slang CI has no VS2019 job any more: cmake-options.yml:96-97 turned it off when the windows-2019 runner retired. CMakePresets still has vs2019 and docs/building.md still shows it, so VS2019-only breaks reach users without CI noticing.

Tip for the CE full-TU amalgamation method (learning 1792510969305), when targeting MSVC/Windows: Slang core headers use `#ifndef X / #define X` include guards, not `#pragma once`. Unless you treat guarded files as once-only, the amalgamation balloons (17 MB / 447k lines for unit-test-string.cpp, because slang.h was inlined 59 times). Do NOT dedupe `include/slang-image-format-defs.h`: it is an unguarded X-macro header that must be re-inlined at every include. With guards deduped the TU is about 640 KB, which CE accepts. MSVC compiler ids look like `vcpp_v19_29_VS16_11_x64`. CE can also execute MSVC builds: set filters.execute=true and compilerOptions.executorRequest=true.
