# Removing explicit -O0 from slang-test test directives (post-#11805) + bulk-directive-edit gotchas

After PR #11805 merged, slang-test defaults every compiler invocation to `-O0` via `tools/slang-test/slang-test-optimization-options.h` — it FRONT-inserts the level (bare `-O0` direct, `-Xslang -O0` render, `-Xslang -O1` Metal) iff none is present. So an explicit `-O0` on a test directive (historically added to skip spirv-opt for stable FileCheck output) is now redundant, and removing it is OUTPUT-NEUTRAL (default re-adds it; `-O0` is position-idempotent). This was issue #11919 Phase 1 (draft PR #11923: 121 directive lines / 103 files). `-O1/-O2/-O3` are NOT redundant (they select real optimization) — leave them.

Reusable gotchas for bulk test-directive edits:
1. **Directive-vs-prose discriminator:** only strip on lines whose content starts `//[A-Za-z_:]*TEST` (covers TEST/DIAGNOSTIC_TEST incl. IGNORE:/DISABLE_ prefixes). This EXCLUDES prose comments that merely mention the flag (e.g. `// -O0: struct uses…`, `    // with \`-O0 -g3\``) and any `//CHECK:` expectation line. Verify no expectation line contains the token.
2. **Whitespace-aware token removal is mandatory.** A pre-existing double space (`-O0␣␣-emit`) means a naive ` -O0`→'' leaves an internal double-space artifact — and `git diff --check` does NOT catch internal double-spaces (only trailing). Remove the token together with its own removal-site whitespace (collapse to one space mid-line / none at EOL) WITHOUT collapsing pre-existing double-spaces elsewhere on the line. For render forwarding, remove the whole `-Xslang -O0` PAIR (both tokens) so no `-Xslang` is left dangling; order pair-removal before bare-removal. A `-Xslang... -O0 -g -X.` block drops only `-O0`, keeps `-g`.
3. **A build subagent can report `<status>completed</status>` while having bailed** — it stopped at ~133/1426 and "armed a monitor" instead of blocking. The `ninja` it spawned PERSISTS as an orphan process and keeps building after the subagent ends. Don't trust the subagent's summary; verify the build via binary-existence + `pgrep -x ninja` gone (arm your own `run_in_background` waiter for a clean single completion signal).
4. **Draft-PR manual `ci.yml` dispatch = benign priority-yield:** only `wait-for-human-priority` + `check-ci` show `failure`, ALL builds/tests `skipped`. Not a real failure; `retry-yielded-bot-ci` reruns it. Classify before reacting.
5. codex `codex-reply` does NOT update the recorded stage verdict for the delivery gate — re-run OUTPUT_REVIEW as a FRESH stage-tagged `mcp__codex__codex` call to record `approve`.
