# Append the mandatory bot-disclaimer to the PR body BEFORE running OUTPUT_REVIEW

**Gotcha (measured 2026-08-17, slang#12488 / PR #12576):** the codex-critique OUTPUT_REVIEW `### Attested` block binds the approve to a sha256 of the reviewed artifact (the PR-body file), and the delivery gate re-hashes at send time. If you run OUTPUT_REVIEW on the PR body, get `approve`, and THEN append the required `🤖 Generated by an automated Slang coworker…` transparency subscript to that same body file (or `gh pr create` a linter normalizes it), the hash no longer matches → the very next marker-bearing `send_message` ([Fix Report]/[Fix Review Request]) is blocked with "1 edit(s) recorded since the last critique round — the OUTPUT_REVIEW approve no longer covers the current state." You then have to burn a whole fresh OUTPUT_REVIEW round to re-approve the disclaimer-appended body.

**Fix / ordering:** finalize the PR body COMPLETELY — including the mandatory bot-transparency disclaimer footer — BEFORE you run the OUTPUT_REVIEW stage, so the approve covers the final bytes. The disclaimer is a non-factual footer, so codex re-approves trivially, but it's a wasted round + a blocked send if you append it after.

**Also confirmed same task:** (1) the critique gate records a stage's verdict ONLY from a fresh `mcp__codex__codex` call carrying a literal `STAGE: <NAME>` line + the verbatim developer-instructions block (sentinel-checked); a `codex-reply` re-verify does NOT flip the recorded verdict. Required stages here were PLAN_REVIEW + CODE_REVIEW + OUTPUT_REVIEW; only OUTPUT_REVIEW must be `approve` (others need count≥1, any verdict). (2) `.slang`/`.meta.slang` files are NOT processed by `extras/formatting.sh` — it only globs `*.cpp/.hpp/.c/.h/.yaml/.yml/.json/.md/.sh/.cmake` + CMakeLists — so a pure core-module/test change is a genuine formatting no-op even when the C++ formatters are absent from the edge.
