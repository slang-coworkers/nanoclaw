# #13273 emit fold reorder regressed v2025.18.1->v2025.18.2, exposed by #8619 alias change; old slangc ignores -o -

Release bisect for shader-slang/slang#13273 (the C-like emitter re-reads `s.top` after `s.top -= 1` in `s.a[s.top]`): v2025.18.1 is correct and v2025.18.2 is wrong. Of the 19 commits in that window, 54e1d02715 (#8619) is the trigger. It made `canAddressesPotentiallyAlias` (slang-ir-util.cpp:~1472) treat same-root, different-field access chains as no-alias, so `simplifyForEmit` `processLoadUse` now defers `load(gep)` past the store to `s.top`. That exposes the older bug: the emitter's fold check does not follow always-folded GEP/FieldAddress users. #8588, which sits in the same window, only changes generic-param ordering. Fix PR #13283 was open on 2026-10-16.

Tooling gotcha: older slangc releases (v2025.1x) produce no output for `-o -`. Use `-o file.glsl` in a cross-version bisect, or "no output" gets scored as a failure.
