# [approver/infra-abstain] record_decision returns a success STRING while the host denies the write (APPROVAL_LEDGER_WRITERS unset) — 4th+ occurrence

## Symptom

On slang-rhi#825 R2 (`426b62d6778a`), `mcp__nanoclaw__record_decision` returned:

> `Decision recorded: shader-slang/slang-rhi#825@426b62d6778a = ABSTAIN_POLICY`

…and then, as a separate asynchronous host notification ~1 minute later:

> `record_decision denied: no approval-ledger writers are configured (set APPROVAL_LEDGER_WRITERS)`

So the tool result asserted success for a write that never landed. This is now at least the
**fourth** occurrence (previously on #819, #823 ×2, #824) — it is install-wide and permanent
until an operator sets the env var, not a transient flake.

## Root cause

The MCP tool's return string is generated by the **tool wrapper on the call path**, not by the
host component that performs the ledger append. The host enforces the
`APPROVAL_LEDGER_WRITERS` capability *after* the wrapper has already replied, and reports the
denial on a **different channel** (a system notification into the session) with different timing.
Two channels, and the optimistic one answers first.

## How to catch it

- **Never treat the `record_decision` success string as proof of the append.** It is a claim about
  a state you did not open — the same class as any other unverified past-tense claim about your own
  work.
- The denial arrives as an out-of-band `<system-notification>`, possibly *after* you have moved on
  and even after you have already sent your report upstream. Do not close a decision turn assuming
  silence means success.
- Whatever you do, the durable artifacts you control are `work/<pr>-<sha12>/decision.md` and your
  memory row. Those outrank the ledger for reconstruction.

## Fix (the standing workaround)

**State the full verdict INLINE in the upstream report**, every time: decision + reason_code +
the exact commit SHA + the evidence basis. Never emit a report whose content is "recorded in the
ledger, see there" — on this install that sentence points at nothing. Also write the local
`decision.md` before calling the tool, so the record exists independently of the append.

Backfill debt to date (all still unwritten): #819, #823 ×2, #824, #825 R2.

## Transferable rule

**When a tool's reply and the system's enforcement travel on different channels, the reply is
advertising, not evidence.** A capability-gated write needs confirmation from the *enforcing*
side — or an inline copy of the payload that survives the denial. If you cannot get either,
say plainly that the write is unconfirmed rather than repeating the tool's optimistic string.
