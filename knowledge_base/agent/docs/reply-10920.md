@jkwak-work Good question — I checked the SPIR-V grammar (`spirv.core.grammar.json` in SPIRV-Headers) directly.

**Short answer: there is no equivalent in `SPV_NV_shader_invocation_reorder`.** No opcode in that extension returns the hit triangle's vertex positions. The only SPIR-V opcode that does this is `OpHitObjectGetIntersectionTriangleVertexPositionsEXT`, which belongs to `SPV_EXT_shader_invocation_reorder` (capability `ShaderInvocationReorderEXT`) and requires an `OpTypeHitObjectEXT` operand plus `SPV_KHR_ray_tracing_position_fetch`.

The complete set of `OpHitObjectGet*` opcodes gated on the NV capability (`ShaderInvocationReorderNV`) is: `WorldToObjectNV`, `ObjectToWorldNV`, `ObjectRayDirectionNV`, `ObjectRayOriginNV`, `WorldRayDirectionNV`, `WorldRayOriginNV`, `RayTMinNV`, `RayTMaxNV`, `CurrentTimeNV`, `HitKindNV`, `PrimitiveIndexNV`, `GeometryIndexNV`, `InstanceIdNV`, `InstanceCustomIndexNV`, `AttributesNV`, `ShaderBindingTableRecordIndexNV`, `ShaderRecordBufferHandleNV`. None of these returns vertex positions.

The closest you can do with the NV extension is read `OpHitObjectGetPrimitiveIndexNV` / `GetGeometryIndexNV` / `GetInstanceIdNV` (plus the object↔world matrices) and *manually* fetch and transform the vertices from your own vertex/index buffers — a workaround, not an equivalent.

(For completeness: the only NV `HitObject` opcodes that return positions at all are `OpHitObjectGetSpherePositionNV` and `OpHitObjectGetLSSPositionsNV`, but those are for sphere / linear-swept-sphere geometry — gated on `RayTracingSpheresGeometryNV` / `RayTracingLinearSweptSpheresGeometryNV` — and live in different NV extensions, not `SPV_NV_shader_invocation_reorder`.)

**So the PR's "EXT-only" framing is correct and doesn't need revising.** An NV-capability build emits the hit object as `OpTypeHitObjectNV` (`slang-emit-spirv.cpp:2738`), while the EXT triangle-vertex-position op requires an `OpTypeHitObjectEXT` operand; mixing them would produce invalid SPIR-V, which is exactly why the code rejects the NV path at compile time via `static_assert`.
