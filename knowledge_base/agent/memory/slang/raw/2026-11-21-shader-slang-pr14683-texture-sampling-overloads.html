Background

Deep background (skippable)

Slang compiles texture calls like tex.SampleGrad(s, loc, gx, gy, clamp) through declaration, not through C++ built-ins: the methods are generic extension members of _Texture<T, Shape, isArray, …> in source/slang/hlsl.meta.slang. Each overload resolves a call by its parameter list, then lowers through a __target_switch with one body per backend. SPIR-V lowering is declarative: a spirv_asm block names its operands (Grad|MinLod, OpImageSparse…, OpStore of the resident code) and the emitter writes exactly that. Availability is gated by [require] capability attributes; shape rules by static_assert on the Shape type parameter, which produces a clear diagnostic at the call site. Because there is no legalization pass after the fact, an overload that compiles emits precisely what its block says — wrong shape rules mean silently invalid code.

The HLSL authority for the overload table is DXC's gen_intrin_main.txt: cube and cube-array textures have no texel-offset overload on any method; the six implicit-LOD methods instead take (clamp) / (clamp, status); the explicit-LOD methods take status-only (status); noncube textures take (offset) / (offset, clamp) / (offset, clamp, status), and comparison sampling has no 3D form at all. SPIR-V agrees mechanically: ConstOffset on a cube image is invalid; MinLod corresponds to Vulkan's shaderResourceMinLod feature; sparse residency is a separate capability.

The narrow facts this change needs: Slang's cube overloads did have offset forms (a fictional int3 for SampleGrad, int2 elsewhere), did not have the cube clamp forms, and the GL_ARB_sparse_texture_clamp capability alias mapped its SPIR-V alternative to spvSparseResidency — a different feature from the spvMinLod a clamp actually needs.

Intuition

Consider the issue's motivating example:

TextureCube<float4> testCube;
SamplerState testSampler;
return testCube.SampleGrad(testSampler, dir, gx, gy, minLod);  // minLod is a minimum-LOD clamp

Before the fix, cube SampleGrad had no clamp overload, so the fifth argument resolved to the offset overload: an implicit float → vector<int,3> conversion warning, then E40012 ("expected a compile-time constant") because a clamp is not a constant offset. Passing a constant offset instead compiled silently and emitted Lod|ConstOffset on a cube image — invalid SPIR-V. The fix makes the declaration surface equal the HLSL table: assert the shapes a form can never take, add the forms that are missing, and name the capabilities the lowerings actually use.

Cube / CubeArray (per DXC)

  • implicit-LOD: (), (clamp), (clamp, status)
  • explicit-LOD: (), (status)
  • any offset parameter → static_assert diagnostic

1D / 2D / 3D / arrays

  • (), (offset)
  • (offset, clamp), (offset, clamp, status)
  • SampleLevel family: (offset, status)

Code walkthrough

1 · The failing repro

tests/hlsl-intrinsic/texture/sample-grad-cube-minlod.slang — the exact call above, checking for OpImageSampleExplicitLod … Grad|MinLod with CHECK-NOT: ConstOffset. It failed with E40012 on master; it passes on this branch.

2 · Reject invalid shapes

The existing cube-exclusion precedent on SampleCmpGrad/SampleCmpBias is extended to every offset overload of Sample, SampleBias, SampleLevel, SampleGrad, SampleCmp, SampleCmpLevel, SampleCmpLevelZero, and to the eight __texture_gather_[Cmp_]offset[s] helpers — plain and combined samplers. Comparison sampling gains static_assert(!(Shape is __Shape3D)) (no DXC SampleCmp* on Texture3D, invalid OpImage*Dref* on 3D images). The always-true WGSL offset check becomes the intended 2D-or-3D restriction (rejecting 1D too). Two quiet bugs go with them: the combined Sample(location, offset) GLSL case called textureOffsetClampARB with no clamp argument plus a stray OpCapability MinLod, and SampleGrad offsets used Shape.dimensions (fictional int3 on cube) instead of Shape.planeDimensions.

3 · The missing forms

Cube (clamp)/(clamp, status) on the six implicit-LOD methods; cube status-only (status) on the three explicit-LOD methods; noncube (offset, clamp) on SampleBias/SampleCmp/SampleCmpBias/SampleCmpGrad and (offset, clamp, status) on the last two — each with a real per-target body: HLSL positional passthrough, GLSL textureClampARB-family intrinsics under GL_ARB_sparse_texture_clamp, Metal bodies for the documented cube gradient/bias clamp, and SPIR-V blocks emitting MinLod (and OpImageSparse* plus the resident-code OpStore for status forms). The combined SampleBias (offset, clamp, status) SPIR-V body, which dropped the clamp entirely, now emits Bias|ConstOffset|MinLod … $clamp. The two short (offset, status) comparison forms become spirv-only: the HLSL emitter passed them through positionally where DXC reads the last argument as the clamp — targets silently disagreed; HLSL callers now get a clean overload error and the table's (offset, clamp, status).

4 · Capability wiring

GL_ARB_sparse_texture_clamp's SPIR-V alternative becomes spvMinLod (the feature a clamp needs), not spvSparseResidency. The two plain (offset, clamp) forms require the clamp atom like their combined twins. Every residency form splits [require(hlsl_spirv, sm_5_0)] into an hlsl clause and a spirv clause adding spvSparseResidency; the fallback-style Sample (offset, clamp, status) forms gain stacked availability+spirv clauses (new cpp_glsl_hlsl_metal compound alias). SampleCmpLevel's SM 6.7 requirement is branch-local __requireCapability(sm_6_7) inside the HLSL cases — a declared clause propagates into the GLSL-module wrappers that call it and would raise their minimum GLSL version to 4.60 (the build fails exactly that way before the branch-local choice).

5 · The matrix

Positive coverage across 1D/2D/3D/cube/array for the clamp forms (separate and combined samplers), shape diagnostics for cube offsets, 3D comparison and WGSL 1D/cube offsets, the SM 6.7 upgrade-warning behavior, and the migrated sparse comparison tests. tests/hlsl-intrinsic/: 744/744; full suite green except three pre-existing fp8-cuda PTX-JIT environment failures.

Open questions for the maintainer

E41012 policy. The issue complained that Slang "emits SampleCmpLevel for an HLSL SM 6.6 profile, even though DXC requires SM 6.7." After this change an sm_6_6 request gets warning[E41012]: profile implicitly upgraded (lib_6_6 → sm_6_7) and a coherent upgraded module — warn-and-upgrade is Slang's standing __requireCapability behavior, not a new policy. A hard error for SM-family requirements would be a capability-policy decision (#9210); deliberately not made unilaterally.

Cube-array SampleCmpGrad. The SM 6.8 proposal excludes it; DXC main declares it. This branch keeps Slang's existing exclusion — two asserts to remove if you prefer DXC parity.

Short (offset, status) comparison forms. Now spirv-only (they lowered to sparse residency on SPIR-V but to a misread clamp on HLSL). If downstream Slang code relied on them for HLSL, it was getting silently divergent code; alternative migrations (explicit diagnostic, different spelling) are on the table.
