Other findings (Linux, so Metal is checked at text level only):

1. **A `case` label is a hard error, not only a warning.** `emitSwitchCaseSelectorsImpl` (`slang-emit-c-like.cpp:3697`) prints the selector through the same literal path. So `case -9223372036854775807LL - 1:` becomes `case -9223372036854775808LL:`:
   - nvrtc 12.6 (`-target ptx`): `invalid narrowing conversion from "unsigned long long" to "long long"`.
   - dxc 1.9 (`-target dxil`): `case value is not a constant expression`.
   - LLVM (`-target host-callable`): `case value ... cannot be narrowed to type 'long'`.

   The `(-9223372036854775807LL - 1LL)` spelling compiles without errors under nvcc, clang and dxc. A test lane with a switch case would cover this.
2. **`BaseType::IntPtr`** (`slang-emit-c-like.cpp:1394-1409`, 64-bit pointer branch) writes `int64_t(-9223372036854775808)` with no suffix. This is the same out-of-range literal (clang: `-Wimplicitly-unsigned-literal`). A fix to the `Int64` case only does not cover it.
3. **GLSL** has its own override (`slang-emit-glsl.cpp:1415-1422`, shared by `Int64` and `IntPtr`) that writes `-9223372036854775808L`. glslang rejects it as a case label (`'case' : scalar integer expression required`). The equivalent spelling there is `(-9223372036854775807L - 1L)`. I could not check it with glslang here.

Repro for the case label:
```slang
RWStructuredBuffer<int64_t> outputBuffer;
[numthreads(1, 1, 1)]
void computeMain()
{
    switch (outputBuffer[1])
    {
    case -9223372036854775807LL - 1: outputBuffer[0] = 1; break;
    default: outputBuffer[0] = 2; break;
    }
}
```
`slangc sw.slang -target ptx -entry computeMain -stage compute` fails with the nvrtc error above. The same happens with `-target dxil -profile cs_6_0` and with `-target spirv -emit-spirv-via-glsl`.
