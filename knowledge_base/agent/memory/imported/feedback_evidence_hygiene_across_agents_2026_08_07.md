# Cross-agent evidence hygiene — 2026-08-07

Second spill from [[feedback_optimized_lane_can_be_inert_for_the_fix]] → [[feedback_an_assertion_that_cannot_fail_2026_08_07]] (the sibling holds the test-instrument entries; this holds the cross-agent ones). Reconciled to the durable rules; the per-instance forensic tables were pruned as the chains are closed.

### Hand over a PROBE, not a VERDICT

Same `slang-reviewer`, one night, opposite value. **Asserting an unmeasured conclusion:** #12419 `[CudaHost]` — *"four probes produced zero bytes of `__host__`"* → told the fixer not to add a check. **Refuted:** the fixer measured `__host__ int hostHelper(...)` on plain `-target cuda` with a positive control (drop `[CudaHost]` → `__device__`); the reviewer's probe binary was 49 commits stale and failed that control. **Handing over the probe instead:** on the #12417 signed-zero item it declined to assert and supplied the experiment, which produced a materially better position.

⇒ **A reviewer's verdict inherits its author's instrument; a reviewer's probe inherits the recipient's** — so an experiment transfers the finding to whoever has the *current* tree. Brief reviewers to supply probes for anything unmeasured; treat "I probed it, N times" as unverified until the probe's own control is named. **A negative with no control cannot outrank a positive with one**, and the count makes it *look* stronger ("five reviewers agreeing" is one observation, via a shared method, counted five times). A better-evidenced position is not a resolved one — which of ±0.0 is correct stayed a maintainer's semantic call.

### The unaudited reading is the one that costs nothing to leave standing

Three instances, three actors, none flattering its author: a fixer's stale `9/10` that understated its own result; a CI-babysitter's three defects all biased toward *not* escalating (an error that suppresses action produces no incident to investigate); my own stale *"correlation, not causation"* hedge left standing ~20 min after I'd verified the mechanism.

⇒ **The unaudited class is not "self-serving" and not merely "expected" — it is any reading whose direction costs nothing to leave standing, including one against your own interest.** A self-serving error invites challenge from others; a self-diminishing one invites challenge from nobody, which makes it more durable. **A stale hedge is a defect, not humility** — when you strengthen a finding, sweep for your own earlier qualifiers (the enumerate-don't-recall rule of [[feedback_correction_unapplied_until_every_restatement_fixed]], applied to hedges). ✅ Cheap pre-claim test: *"who is harmed if this stays wrong?"* — if "only me" or "nobody," it will not be caught, so audit it now. And **name the system a status lives in** ("approved" needs "approved in *what*") — that catches, in advance, substituting a peer's verdict for GitHub review state, a local body for the published one, a working tree for `git show HEAD:`, or a merged inbox for a peer session's transcript.

### "No longer applies" and "cannot be reached" are the same claim

n=2, roles reversed, one PR pair (#12419): the reviewer's *"`[CudaHost]` is unreachable — four probes found zero `__host__`"* (refuted by a controlled compile; probe was 49 commits stale) and the fixer's *"that wording was replaced before your review"* (refuted by grepping every commit — it was present at three, absent only at one, i.e. it was the replacement, not the replaced).

⇒ **Both are assertions about an artifact's STATE, both are refuted by opening the artifact, and both function to CLOSE an investigation** ("unreachable" closes a code path; "stale" closes a finding). Neither is an argument on the merits, and each is one `git grep` / one compile away — accept neither without the artifact. **The honest repair is the same both directions: keep the disposition, fix the REASON** (the reviewer kept "don't add the check" but on NVRTC rejecting `__host__` in JIT mode, not on unreachability; the fixer kept its declination but on scope, not staleness). ⚠️ Related trap: platform-scoped instruction sections (slang CLAUDE.md's `.exe`/"WSL on Windows" guidance) get applied **unscoped** by reviewers on Linux hosts — pre-empt it in the dispatch rather than re-arguing per review.

### A debug line table is content-addressed provenance

For *"is this object built from post-fix source?"* three instruments of increasing strength: `.ninja_log` output mtime (temporal — a link refreshes mtime without recompiling); `ninja -n` → 0 work (bookkeeping, asserts up-to-date not provenance); and **`readelf --debug-dump=decodedline` on the `.o`** showing executable code at lines 6398–6399, where the base revision has a *comment* (and a comment emits no code).

⇒ **To prove an object came from a given source revision, find a line whose CODE-EMITTING status differs between the two revisions and query the debug line table.** It is content-addressed, so no mtime, log ordering, or link freshness can lie to it — every other trap this store recorded (`cp -p`, append-only logs, `filter=all` carry-over) attacks *bookkeeping about* the artifact; this reads the artifact. A comment↔statement flip at a known line is the cleanest discriminator, and `strings` cannot substitute (comments are not string literals). It also makes the install-drill bidirectional: code-at-6398 `== 0` after installing the base proves the base rebuild happened.

### A rule that must be RECALLED will be bypassed; only a changed DEFAULT holds

Five instances of a recorded rule bypassed at the moment of use across two agents (a "the gate is loud" note contradicted 30 min later; my role-split "keeper" bypassed ~50 min later; a "2 of 3" retraction surviving in the same doc's summary; a promised operator flag never sent; an announced memory write never written). Peer's diagnosis: *"the failure isn't absent knowledge, it's that nothing forces the lookup — a rule only helps if it's what I type by default, not one I recall after a discrepancy."*

⇒ **Convert rules into defaults, or expect them to fail at the moment of use** — a note is consulted *after* a discrepancy, a default runs *before* one exists. Make the positional log the command you type (`tail -n +<last-interrupt>`), make the role-split the first step of any attribution reply. This is ANCHOR E's terminal form: "build the tell in the turn you design it" is necessary but insufficient — it must also become the path of least resistance (see [[feedback_a_pending_tell_does_not_catch_the_error_it_was_designed_for]]).

### A number converging is not a number arriving — audit the SET, not the count

One claim ("`hlsl.meta.slang` already splices C++ constants, so adding one follows precedent"), four figures in ~25 min, each strictly better and all wrong: 872 (`grep -c` counts lines not occurrences) → 982 (right count, ~765 are generator loop vars) → 217/130 distinct (122 are `kIROp_`, a *generated* enum, a different mechanism) → the real population, **7** (`kCoreModule_`/`kConversionCost_`, from 18 `const int k…=` at `slang-type-system-shared.h:99-118`).

⇒ **Monotone improvement manufactures false confidence in arrival — "strictly better than the last" is not "correct."** The invariant error: *"I checked the COUNT three times and never the SET."* ✅ Before publishing any aggregate, **state the population in words and ask whether a reviewer grepping it would find members that don't belong** (122 generated enum values would have been found instantly). **7 is sufficient** — the argument never needed a big number, just the right one; one verifiable example + one `file:line` beats an aggregate that doesn't survive being checked. And the loop closed only because the reviewer *checked* my figure rather than adopting it (it had been about to ship 130 on my recommendation).

### A retraction is the least-audited claim — enumerate, a cluster is not a unit

`slang-reviewer` disclaimed all five things I credited it with; **four were verbatim in its own message from that same session** (only `[CudaHost]` was genuinely cross-session). Its own diagnosis: *"one confirmed misattribution, generalized to the whole cluster without enumerating; I never read my own outbound rows before writing 'I did not do these.'"*

⇒ **A retraction is self-critical, costs the author credit, so it reads as rigour — nobody challenges "I did less than you think."** Over-retraction and over-claim put equally false statements in the record, but this direction is worse: the finding is destroyed and the destruction looks virtuous (had I accepted it, the night's sharpest shared-clone hazard would have been erased by the party who found it). ✅ Discriminator, **per-item never per-cluster:** `ncl sessions messages <session>` → match `source_session_id` + direction=out + timestamp; one confirmed misattribution licenses re-checking the others, not disclaiming them. ⇒ **The field that answers a provenance question usually already exists in the artifact** (frontmatter `originSessionId`, inbound `source_session_id`) — both agents reasoned from *content* while a stamped field sat unread. Ask which FIELD records authorship before reasoning about it; a provenance *feeling* is never evidence. A peer's correction is itself a claim and inherits the burden of proof, even when you already believe it.

### A bounded probe reported as the whole file — the citations are the broken probe's output

My own instance (04:14Z): I challenged a peer's include-chain citation (`slang-ir.h` → `slang-type-system-shared.h`), reporting *"`slang-ir.h`'s first includes are `:9-14`… no such include."* Both its citations were exact — the `#include` block runs to `:22`, and `slang-type-system-shared.h` is at `:16`, **two lines past where my `enumerate(lines[:14])` slice stopped.** A `[:14]` slice can never print line 16 — the same defect as a monitor pinned to `^\[[0-9]+/1453\]` that can never print `/1232`.

⇒ **An include-chain claim FEELS VERIFIED because you read a file, when what you read was a PREFIX of it** — *"I looked at the includes"* is not a check; enumerate to the end of the block, or `grep -n` the whole file. **"WHAT COULD THIS NEVER PRINT?"** catches it in one second. Peer's sharpening: refusing my challenge was **cheap** (one `grep -n`, three revisions, zero cost); what made it *feel* expensive was that my challenge was specific and confident — **specificity is what makes a wrong correction persuasive, and the line numbers are precisely what came out of the broken probe.** So the citations are the *least* trustworthy part of a wrong correction, not the most; when challenged with a citation, spend the one command over the whole file at >1 revision — the alternative is over-retracting a correct premise. ⇒ **Split files for SIZE, never for taxonomy** — a new heading per instance rebuilds the trap list the drill was meant to replace (splitting for the Read/budget bound is the one legitimate reason). And **say which failure modes you designed for vs merely happen to cover** — a claim of complete coverage that is partly accidental breaks when one row is later edited.
