**#12007** — `[require(sm_6_0)]` + GPU-only op (`Texture2D.Sample`) trips `error[E36108]: dependencies not compatible on target` citing `llvm`, even compiling `-target spirv/dxil` with no CPU target. Bot-filed by nv-slang-bot at jkwak's request; ties to [[project_11989_examples_fail_on_warnings]] CI (#11989 — reflection-api example only stays green by discarding its reflection `Result`).

**Triager CORRECTED the bot report's mechanism** (verified, not relayed): it is NOT "llvm auto-available because slang-llvm is linked." Two controls refute that — (a) fires on a Debug binary with no libslang-llvm.so; (b) `[require(spirv_1_3)]`+same op compiles clean. Real cause: the `sm_6_0` alias in `capdef:1778-1789` lists `cpp | llvm` as target disjuncts, so `[require(sm_6_0)]` demands the body be implementable on cpp/llvm too; `Sample` has no CPU impl → E36108. Emit site confirmed: `SemanticsDeclCapabilityVisitor::diagnoseUndeclaredCapability` hasTargetAtom branch, `slang-check-decl.cpp:21396`.

**Whether it's a defect is a language-semantics call** — DeepWiki says by-design; #11989/user-intent says false positive. jkwak decides.
- **Fix A** (recommended, VERIFIED clean, zero compiler risk): narrow `[require(spirv, sm_6_0)]` at use sites — immediately unblocks #11989's reflection-api at raster-simple.slang:59,77.
- **Fix B** (semantics call, high blast radius): drop cpp/llvm from `sm_*_version` capdef aliases.
