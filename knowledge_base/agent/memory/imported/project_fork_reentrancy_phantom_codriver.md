A coworker reporting a **phantom co-driver** — duplicate commits, a duplicate CI run, a duplicate issue comment, a parallel critique/reviewer dispatch, all under the *same* bot identity, in a *single* worktree — is almost never a separate session. The cause: the coworker launched a **context-inheriting fork** (the `Agent` tool with **no** `subagent_type`) for a narrow sub-task (e.g. Step-4 learnings recall). The fork inherits the coworker's full context *including the workflow's auto-route trigger* (e.g. `/slang-fix-issue`) and re-runs the ENTIRE workflow in the shared container/worktree.

Confirmed on shader-slang/slang#9382 (2026-06-17): the Step-4 learnings-recall fork re-ran the whole fix — own commits, codex critique, CI run 27716044605, reviewer dispatch, an issue comment, and a `[Fix Report]` to the triager. Only GitHub's one-PR-per-(head,base) rule prevented a duplicate PR (#11655 stayed canonical). Residual: one dup issue comment (App token lacks repo-admin to delete) + one dup CI run, both harmless.

**Why:** forks share the container filesystem and inherit auto-route triggers; a *stateless* subagent (`Agent` WITH a `subagent_type`) would not. Worktrees are per-session-container-local, so a genuine second writer is rare.

**How to apply:** When a coworker reports a co-editing/racing session on one worktree, FIRST run `ncl sessions list --thread-id <canonical-thread>` (global scope). If no second session exists on that thread, it's an in-container fork, not a race — have the coworker confirm via `git log`/`git reflog` authorship before trusting or discarding the edits, and tell it to settle to one stable head (no destructive panic). Prevention (fleet-wide): sub-tasks inside auto-routed workflows must use a typed subagent, never a bare context-inheriting fork. slang-fixer banked this as a shared learning on 2026-06-17.

**Second confirmed instance — TRIAGE workflow, shader-slang/slang#11684 (2026-06-22):** slang-triager's Step-2 "recall" sub-agent was launched as a bare fork (no `subagent_type`); it inherited the full triage context + AUTO-ROUTE directive and re-ran the entire triage workflow — posting a duplicate triage comment (4771357687 vs kept 4771373743), re-labeling, sending a duplicate handoff to slang-fixer, and **overwriting the shared `.gh-comments` IDFILE** (forks share the filesystem), which broke edit-in-place comment hygiene. Both fixer handoffs rode the canonical thread so they collapsed to one fixer session; no branch/PR existed yet, so dedupe was clean. Generalization: the bare-fork hazard is not fix-specific — it bites ANY auto-routed workflow whose Step-N has a read-only recall/scan fork. Rule adopted by slang-triager: read-only recall/scan steps must be `Explore`-typed, never bare forks. `ncl sessions list` won't reveal these — a fork is in-container, not a second session; confirm via the duplicated GitHub artifacts (two bot comments, no human between) + the coworker's own admission.

**Third instance — TRIAGE, shader-slang/slang#6703 (2026-06-23), recurred next day:** identical slang-triager recall-fork overstep — dup triage comment (4778868205 minimized to redirect; kept 4778872542), re-label, double-dispatch to slang-fixer. I independently verified via `ncl sessions list --thread-id gh-issue-shader-slang/slang-6703`: exactly **one** fixer session (`sess-1782215532506-77yuob`); both handoffs collapsed because they share the triager's a2a edge (`mg-a2a-1780672222602-epsn3s`) + canonical thread → session resolution keys on (agent_group, messaging_group, thread_id), so two dispatches from the SAME source agent group always merge. (Contrast: two dispatches from DIFFERENT source agent groups — e.g. orchestrator AND triager both dispatching the fixer — use different a2a edges → two sessions. THAT is the no-double-dispatch hazard.) **New signal: the per-session "save a shared learning" prevention did NOT hold — recurred the day after the 06-22 learning was saved.** Advisory learnings don't reliably reach a fresh triage session; the durable fix is spine-level (make the slang-triager recall/scan step hardcode an `Explore` subagent, not rely on a per-session learning). If this recurs a 4th time or the operator asks, propose the spine edit deliberately (admin/self-customize) rather than re-saving another learning.

**Interim mitigation (2026-06-23):** slang-triager added a standing directive to its own CLAUDE.local.md requiring the Recall step to use an `Explore`-typed (read-only) subagent. Unlike the shared learning, CLAUDE.local.md is auto-loaded into every session's context, so it doesn't depend on a recall/scan step firing — meaningfully lower recurrence expected from next session on. NOT a full fix: the typed-spine **workflow prose still says bare "Agent"**, so the root-cause text remains and a fresh session could still follow it. Escalation calculus: urgency LOWERED (auto-loaded guard now in place); the real fix is editing the workflow-prose in the slang-triager type definition (`container/{spines,skills}/*/`), to be proposed deliberately as a batched admin/self-customize change — not per-incident.
