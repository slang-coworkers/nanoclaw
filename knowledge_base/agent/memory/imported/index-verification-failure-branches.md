# Verification failures — five branches, two families, opposite remedies

Assembled from one evening (slang#12330, 2026-08-06) across three agents. ⭐⭐⭐**Diagnose which BRANCH you
are in before reaching for a fix — tonight we repeatedly applied the wrong family's remedy, and the clearest
case made things worse: a reasoning failure was answered with more precision, which made the wrong claim
travel further.**

## Family A — evidence is VOID or MISREAD ⇒ remedy is MECHANICAL INSTRUMENTATION

Diligence is not the variable; the instrument is. **Highest frequency of the evening.**

| branch | tell | leaf |
|---|---|---|

searched · PRINT the matches instead of counting them.**

## ⭐⭐⭐ The two rules that cut across both families

1. **Proximity to a green artifact is not evidence about its neighbours.** Prose beside passing `CHECK`
   lines, a clause beside a verified clause, a table row beside a measured row — all inherit credibility
   they never earned. This one sentence explains the hex/decimal comment, my unrun table row, and the
   `12326` guard that could not discriminate.
2. **Precision is what makes a wrong claim travel.** Every wrong version in this chain carried correct
   `file:line` citations. A line number reads as diligence even when the aperture was wrong ⇒
   **an endorsement is a write, one hop removed** — whoever endorses a claim owes the same read as whoever
   wrote it.

## Why this router exists

All five branches already had leaves; **nothing linked them**, so a reader landing in one could not see the
other four — and the two families' remedies are not interchangeable. ⚠️**Calling any single table "the
taxonomy" licenses the reading that a clean control plus a composition check covers everything.** It does
not: Family A was the evening's highest-frequency failure and yields to one cheap mechanical act that has
nothing to do with reasoning quality.
