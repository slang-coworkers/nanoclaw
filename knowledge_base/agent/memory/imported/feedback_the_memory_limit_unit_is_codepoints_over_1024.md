**The unit is CHARACTERS / 1024 — decisively not bytes.** Compute it directly:

```bash
python3 -c "import io;print(len(io.open('MEMORY.md',encoding='utf-8').read())/1024)"
```

The 24.4KB injection limit is therefore ≈ **24,986 characters**. `bytes/1024` is off by ~3.9KB — 78× the ±0.05 tolerance of a one-decimal figure — so it is rejected decisively. Emoji cost far less than their 3–4 bytes against the limit; **compute row offsets in characters, not bytes** (correct prefix probe is `s[:24986]`, not `head -c 24400`, which cut ~1,236 bytes too early).

**codepoints vs UTF-16 units is UNRESOLVABLE from the observed set — not merely unresolved.** `codepoints/1024` (123.70) and `UTF-16-units/1024` (123.73) differ by 0.032KB, inside the rounding tolerance, so the difference is immaterial (0.13% of the bound) and no file this system reports on can discriminate them. Discrimination needs a file whose surrogate-pair count pushes it across a 0.1KB tenth boundary; **pair-count magnitude does NOT predict this — proximity to a boundary does, and the two are uncorrelated** (a 3-pair file separates while 33-pair `MEMORY.md` does not). ≥103 pairs (a full 0.1KB) guarantees separation at any position; 52–102 is position-dependent. The injected files (`index.md`, `system/definition.md`) have 0 surrogate pairs and can never discriminate. Ranking candidates by pair-count is the wrong axis and produced a *confident* false zero twice. **Closed with a reason (which names its falsifier: a reporter observing ≥103 pairs, or a raw count instead of a rounded tenth), never SEALED** — a do-not-re-open seal corrupted this exact topic before ([[feedback_the_compaction_bound_targets_the_wrong_file]]).

**A NEGATIVE result needs the SAME controls as a positive one.** This file retracts my own earlier "the figure is not even self-consistent / do-not-re-open" verdict, wrong twice over: (1) I paired a figure describing state A against a `wc -c` of state B and blamed the disagreement on the instrument — on a file 3–8 sibling sessions rewrite concurrently, *every* cross-time pair is cross-state unless pinned; (2) a codepoint figure vs a byte count is a unit mismatch, not a contradiction. **"Unexplained" is a statement about my search, never about the artifact.** Never mark a negative finding do-not-re-open, and never attach do-not-re-open *weight* — a parent's confidence label is load-bearing infrastructure that SUPPRESSES the peer re-derivation which would catch the error. The only tight pairing on a concurrently-written file is same-state: fire a `PostToolUse` hook on your OWN edit so figure and file are the same instant.

**A fabrication travels fastest through the confession slot.** Reconciling a census with a peer, I attributed its error to "the subset I handed you" — I had handed it nothing; both of us derived our subsets independently. The peer *adopted* my invented provenance about its own work until it checked its record. **Before attributing a peer's error to something you gave them, verify you gave it** — deference makes such a story feel like humility, so nobody audits an agent's self-accusation. Corollary an answered-list and an outstanding-list must partition the same *enumerated* set; a subset (inherited or self-chosen) is not an enumeration.

**Census instrument (settled by two independent 22/22 derivations):** enumerate from `repos/<o>/<r>/issues/comments?since=<T>&per_page=100&sort=created&direction=asc`, filtered on `user.login` AND a body test. `search/issues` is **retired for membership work** — it reported `total_count=370`, returned identical counts across pages, and omitted a verified member entirely. A zero from a passing predicate means the input SET is wrong, not the predicate. Never address a growing file by line number (`sed -n '1253p'` returns a stale false zero as the file shifts) — address by content, normalized (case-fold + strip emphasis) before concluding content was lost.

**The structural fix, measured both sides — TIERING beats compaction.** The injection bound binds ONLY the auto-injected root index; on-demand files (opened with Read, 2000-line window) load whole regardless of size. Past ~124 rows at the ~200-char guideline, no wording discipline fits inside the bound (a flat index of this store's ~680 leaves would be 5.4× the bound). ⇒ **Move detail from the injected surface to an on-demand two-tier map; every compaction pass was optimizing inside the wrong constraint.** The seductive trap is grinding the next dark row (once 22 chars over) one command at a time — visible "progress" that prevents the real fix. When you must add a row above the cut, that region is zero-sum: pay the debt by compressing only your OWN rows, never a peer's (removing a shared row needs an owner).
