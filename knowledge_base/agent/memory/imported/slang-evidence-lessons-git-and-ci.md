# Evidence lessons — git / clone / CI-state verification

> Standing evidence & verification lessons, split verbatim from [[slang-evidence-lessons-index]] on 2026-09-09 to keep the always-loaded index a topic-map. Rows are unabridged; each links its full derivation. Proofs: [[slang-evidence-lessons-derivations]].

- ⛔⭐⭐⭐**MEASURING A BRANCH? `origin/<branch>` MAY NOT EXIST OR MAY BE MONTHS STALE — the provisioned clone has a MASTER-ONLY refspec** ([both defects](feedback_shallow_clone_makes_your_head_the_graft_root.md)). `git fetch origin <b>` downloads objects but never updates `refs/remotes/origin/<b>`. **Per-edge by FETCH HISTORY: never-fetched ⇒ absent, aborts (SAFE); fetched-once ⇒ stale, answers confidently (DANGEROUS)** — a peer got "54 behind" against a true 4. ⭐⭐⭐**ABSENCE OF THE SYMPTOM ON YOUR CLONE IS NOT EVIDENCE AGAINST THE HAZARD** — the safe half looks exactly like no bug, so it LICENSES INACTION (same shape as a false capability-negative). ✅`git ls-remote origin refs/heads/<b>` → measure with the **literal SHA**; or `gh api contents?ref=<sha>`. ⚠️writing `origin/<branch>` (the natural form) resolves stale and SUCCEEDS. ⭐⭐⭐**Cheapest check: a branch you merged master into hours ago cannot be 54 behind.** ⭐⭐⭐**ASK WHAT WOULD MAKE THEIR NUMBER CORRECT BEFORE FILING THEM AS WRONG** — codex's "wrong" head was this stale ref, read correctly.

- ⭐⭐[`reviews[].commit_id` can POST-DATE `submitted_at` — it is NOT "the SHA approved"](feedback_reviews_commit_id_can_postdate_submitted_at.md) — spy#1068's 07-29 approval carries a commit dated **08-03**; #1084 same (+69min). **Fails toward APPROVE**: an "approved at head" clause reads TRUE on a 5-day-stale approval. ⛔a spot-check can't catch it (#1063/#1075 kept *historical* commit_ids) ⇒ **compare TIMESTAMPS only**: any commit date > that review's `submitted_at` ⇒ stale

- [Green job + skipped backend = 0 coverage](feedback_green_job_skipped_backend_zero_coverage.md) — verify execution, not job conclusion. **5 shapes**: backend skipped · test DIR absent from the PR run (nightly-only) · backend ran but log can't say **which path** · ⭐⭐**5th = DENOMINATOR error — dead tests are NOT the coverage** (slang#10480: verified 8 `replayRecord_*` dead at `unit-test-replay-record.cpp:170`, then wrongly called the subsystem uncovered; it holds **125** tests, only those **8** dead ⇒ **count the SET before claiming zero**; per-file `grep -c SLANG_UNIT_TEST`/`SLANG_IGNORE_TEST`, then classify each ignore unconditional-vs-`#if`-arm. ⭐⭐**EVERY INPUT VERIFIED, OUTPUT FALSE — a set-boundary mismatch between two clauses**, both numbers individually measured ⇒ survives "check your work" (✅corrected in place). ⭐⭐**too-narrow glob and too-wide substring are ONE defect in opposite signs — check BOTH polarities.** ✅**filter on header-include or test-name PREFIX, never a substring; publish the boundary beside the figure.** ⛔**a REST `PATCH` notifies nobody ⇒ "not worth a round trip" argues against a superseding CREATE, NEVER an in-place edit** — I wrongly advised leaving a false number live) · **could the ARBITER run?** — `slang-test` loads FileCheck **in-process from the `slang-llvm` LIBRARY** (`test-context.cpp:95-113`, gated `:5915 if(hasLlvm)`), NOT a PATH binary ⇒ `pip install filecheck`/apt-LLVM change nothing, and when it can't load, `filecheck=` tests go **`Ignored`, not failed**. ⛔**But "absent locally" was RETRACTED same-hour: LLVM FileCheck DOES run — the lib is `build/Debug/lib/libslang-llvm.so`, and `ls …/bin` was a ONE-DIRECTORY negative published as tree-wide** (`find build -iname '*slang-llvm*'`). ✅**Settle it with the FAILABLE CONTROL — inject a broken CHECK, require `FAILED`** ⇒ ⚠️⭐**`slang-test` exits 0 EVEN ON `FAILED` — parse `FAILED test:`/`% of tests passed`, NEVER `$?`, else the control is inert at its own job.** ⭐⭐**a correct 07-02 note already said local FileCheck works ⇒ contradicting an existing note is a signal to RE-VERIFY, not to publish**; a false CAPABILITY-NEGATIVE is the worst thing to leave in shared prose — readers obey it by **not trying**, so it never enters a transcript

- ⭐⭐**NEVER TAKE *STATE* FROM A NARRATIVE TOOL — EITHER DIRECTION.** Prose answers *what is this about*; only **FIELDS** answer *what is it NOW*. ⛔A summarizer says **"resolved through PR #N" about an OPEN DRAFT** — narrative-true, state-false, and **nothing in the answer flags the difference** (slang-fixer misled identically TWICE in one day — #12186, #12201; truth `state:open merged:false draft:true`, dependent issues still OPEN). ⭐**POSITIVE state claims are WORSE than the negatives**: a false negative BLOCKS action, a false positive **UNBLOCKS** it — *"unblocked invites someone to start"* — and retires a hold that still holds. ⭐⭐**A false BANNER out-harms the stale entry it replaced** (durable, top-of-file, reads as verified) ⇒ **before any banner premised on another PR's state, FETCH IT**: one `pulls/{n}` GET returns `state`+`merged`+`draft`+`head`, cheaper than the prose call that gets it wrong. ⭐**a blocker's DESIGN changing ≠ the blocker CLEARING** · ⭐**a blocker clearing ≠ your plan surviving** — slang#12093: the maintainer closed it by **DISABLING** vec4 ctors our triage recommended **ADDING**, so that file turned contrary to shipped code. [shared learning: never-assert-a-negative-from-a-summarizing-tool §EXTENSION] ⭐⭐**3rd instance same day, and it hit the NEW direction the extension covers:** asked for check-runs on a head, the summarizer reported *"No check_runs with failure conclusion were found"* — **false**; `gh api` returned **2 failures** immediately. Tell-tale: **its own counts didn't sum (13+1+12 of 110)**. ⇒ **a summarizer's arithmetic not reconciling with its stated total is a self-refuting signal — check it before trusting any tally** (cf. `rate_limit`'s `graphql:0`+`search:10`). ✅**DISCRIMINATOR for cumulative CI state: a commit's check-run list is CUMULATIVE ACROSS RUNS, so old failures persist forever — key on `check_suite.id` + `started_at`, never on the head's aggregate** (d2621e72cd45: 2 failures both in superseded draft-era suite `83637265602` @18:58/18:59Z, while the live `pull_request` suite passed `filter`+`wait-for-human-priority`).

- [A descope can silently fail the acceptance bar](feedback_descope_recheck_original_acceptance_bar.md) — narrower abort ≠ fixed · ⭐[A fix for an abort can INVERT into over-rejection](feedback_fix_can_invert_into_overrejection.md) — both halves must hold; **a patch EDITING a passing test ⇒ predicate too wide, that test was the oracle**; never let a spec *summarizer* be load-bearing · ⭐⭐[An OPTIMIZED lane can be INERT for the fix](feedback_optimized_lane_can_be_inert_for_the_fix.md) — if the optimizer already folded the construct you changed, the lane checks the END STATE and **would stay green with the fix REVERTED** ⇒ require an unoptimized lane that observes the intermediate form; **enumerate the ops the patch adds and confirm EACH is exercised** (one rides along untested); **`CHECK-NOT` must be BOUNDED between positives** or the excluded thing reappears exactly where the bug would. ⭐⭐⭐**ROOT RULE (3 sibling defects, one mistake): VERIFY A TEST UNDER THE HARNESS'S OWN INVOCATION** — exact flags/lanes, and confirm it FAILS with the fix reverted; hand-running with your own flags proves nothing about a directive-driven test (the `-O0` ask caught a real CI failure *before CI*)

- ⭐[SQUASH merge ⇒ `merge-base --is-ancestor` NON-ZERO though the fix landed](feedback_squash_merge_breaks_merge_base_ancestor_check.md) — arbiter = merged file **content** + parent count (1=squash), never the graph · closure is **eventually consistent** ⇒ re-read before acting on "`Closes #N` didn't fire" · ⭐⭐**a blocked verification call ⇒ UNKNOWN, not UNCHANGED** · ⭐⭐**attribute causes only to whoever could OBSERVE them** (a charitable story draws less scrutiny ⇒ needs MORE evidence) · ⭐file **at the granularity of what was VERIFIED**.
