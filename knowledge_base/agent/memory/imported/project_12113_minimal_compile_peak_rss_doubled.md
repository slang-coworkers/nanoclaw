⛔**RETRACTED 2026-08-10 — the `~20×` bridging factor in our own verdict comment `4977530963` is WRONG.** That comment (author `nv-slang-bot` = us, 07-15) says *"deserialized IR is ~20× its packed form, so +4.6 MiB serialized → ~+90 MiB RSS"*. jvepsalainen-nv measured the real expansion at **3.10x** (#12447 body: *"not ~20x as quoted in #12113"*; 430,369 insts × 155 B = 63.6 MiB ÷ 20.5 MiB serialized = 3.10, self-consistent). Ours was an **inferred bridging factor published as a measured ratio, with no stated denominator** — the ×1.96 blob ratio and the ×1.93 RSS ratio were both real measurements, but the ~20× glue between them was not. **✅ Retraction posted on BOTH surfaces (verified 08-10): #12447 cmt `5237740624` and #12113 cmt `5237924529`** (08:46:17Z, 3503 cp, `nv-slang-bot[bot]`). **Stacked, not edited** — verdict `4977530963` verified untouched (`created == updated == 2026-07-15T06:22:43Z`, len 2656), correct because the author's `4988512896` is newer and an in-place patch would hide the correction from anyone who read past it. Ceiling on core IR is ~64 MiB, not ~90 MiB.

**Per-claim evidence classes after the retraction (from cmt `5237924529`, my own verification of the text):** RSS ×1.93 **stands** (direct) · blob ×1.96 **stands** (direct) · localization to the eager core-module deserialize **stands** (direct) · "compiled core module produces more IR" = the surviving **inference**, not a measurement (#12447 rests on the same premise) · `nm --size-sort` next-action probe **unaffected** (blob-size measurement, never used the factor) · ⛔**"the two ratios track ⇒ blob growth proportionally accounts for RSS growth" — CAUSAL READING WITHDRAWN, demoted to an observation.** That last one is the non-obvious consequence: *when a factor is withdrawn, the inference leaning on it dies too, even though both its inputs were measured.*

⛔**Do NOT compute "then only ~14 MiB of the ~90 MiB is explained."** `4.56 × 3.10 = 14.1` is valid multiplication and a false prediction: `3.10x` is a whole-module **average** and `+4.56 MiB` is a **marginal** delta, so the product assumes uniform expansion across IR content, which nobody measured. How much of the `+90.4 MiB` is blob-proportional is **OPEN**. Full rule: [[feedback_an_average_ratio_applied_to_a_marginal_delta_needs_a_uniformity_proof]]. See also [[project_12447_on_demand_ir_loading_builtin_modules]].

**Root cause (localized, FACT — the ×1.96 blob measurement stands, only the ~20× glue is retracted):** `createGlobalSession()` eagerly deserializes the embedded core module; its serialized blob (`.rodata` symbol `g_coreModule` in libslang.so) nearly doubled 4.73→9.29 MiB (×1.96), tracking the RSS ratio. Source text flat, no serialization-format change → compiler produces more core-module IR. Leading (unproven-in-isolation) contributor: autodiff refactor **#9808**; smaller: CoopVec/CoopMat SM6.10, Conditional-intrinsic, late-cap-checks. Cheapest next probe (no full build): `nm --size-sort` g_coreModule across in-window commits starting 45ccce9a3.

**Solution space:** (A) reduce what core module serializes, (B) lazier core-module deserialization (also helps #9817), (C) accept as WAI if #9808 knowingly traded footprint.
