## Follow-up scope facts (carry into #12375)

- ✅ **`IDownstreamCompiler` lives in `source/compiler-core/`, NOT `include/`** ⇒ it is an **internal** header, so the public-ABI rules (never reorder/insert/remove a virtual) **do not apply** — changing the default body carries no vtable or source-compat cost. **The cheap fix and the correct fix are the same fix**; state this in the PR description to pre-empt a reviewer's ABI instinct. Verified reach: only `slang-glslang-compiler.cpp:57` overrides `link`, so one interface-default fix reaches every other implementor.
- ⛔⛔ **LLVM implements `IDownstreamCompiler` DIRECTLY** (`slang-llvm.cpp:116` `class LLVMDownstreamCompiler : public ComBaseObject, public IDownstreamCompiler`), bypassing `DownstreamCompilerBase` — so **jkwak's own "all sibling functions whose return type is `SlangResult`" phrasing is base-class framing and provably cannot reach it** (all four of us missed it in R2 by enumerating subclasses instead of implementors). LLVM's own stubs (bare `SLANG_FAIL`): `validate :139` · `disassemble :146` · `disassembleWithResult :152`. It **also** inherits the defective `link` default (`slang-downstream-compiler.h:374-385` returns `0` = `SLANG_OK`, `outArtifact` untouched) — fix that **once at the interface**, add NO LLVM override (an override would duplicate policy and leave metal/nvrtc/tint/dxc/fxc still defective). LLVM is the only direct implementor tree-wide.
- ⭐⭐⭐ **Every earlier pass missed `link` because the enumeration filtered on methods spelled `SlangResult`, and `link` is spelled `int`** (`SlangResult` is `typedef int32_t`, so same type — but a type-filtered search partitions the search space). **A "cosmetic" inconsistency that any enumeration FILTERS ON is not cosmetic.** I had filed it as readability-only and told the fixer not to escalate it — correct about ABI, wrong about consequence.
- ⚠️ **#12355 (null deref) MUST stay separate, and the ordering is load-bearing.** The base-default `return 0` → caller `slang-emit.cpp:3413` checks `!= SLANG_OK` (passes) → `linkedArtifact->loadBlob(...)` on a never-written `ComPtr`. Land the **producer-side deref fix FIRST**: a result code cannot express "succeeded but wrote nothing", so no spelling of the guard catches it, and `SLANG_FAILED(0)` is a **byte-identical no-op** at `slang-emit.cpp:3419`. A caller-side null check alone would MASK a broken contract (methodology forbids masking). If the sweep tidies the result codes first, the deref survives behind a green diff and a closed issue.
- ⭐⭐ **`compiler-core` habitually defines out-of-line** — the declaration-vs-definition conflation hit **three times** on this chain (DXC header is 20 lines / body in `.cpp:240`; LLVM `getVersionString` declared `:136` defined `:522`; base `convert` declared `:406` defined `slang-downstream-compiler.cpp:25`). Any declaration-site search over this surface is wrong by construction ⇒ **enumerate declarations and definitions as TWO lists and reconcile.**

**Scope provenance:** jkwak sanctioned only *"another PR that makes the unavailability return"* — he enumerated no implementations and no exclusions.
