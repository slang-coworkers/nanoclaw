**TWO any-value sizes exist, and they are DIFFERENT BY DESIGN:** (1) the **"external API contract" size** — computable purely from AST info, from the `interface` decl + its `[anyValueSize]` attr; for `IFoo` that is **16** (payload) ⇒ 32 total. ⇒ ⛔**REFLECTION IS CORRECT AND THE BACK-END IS THE BUG — the opposite of what our chain published.** Verbatim: *"The reflection API should use the external API contract size when reporting size information (**and luckily, it already does**)"* · *"Whenever a value of existential type is explicitly stored in memory or a buffer/resource, it should use a layout that is based only on the external API contract size. The reflection API gets this right for the example in this issue, while the code generation back-end currently gets this **wrong** — it uses the de facto size in place of the external API contract size."* Applies to `StructuredBuffer<IFoo>`, `ConstantBuffer<IFoo>`, `IFoo*`, etc. **Temporaries** (locals, params, results) correctly use the **de facto** size — and can be sized per-value (he points at @saipraveenb25's recent work). ⇒ **The emitted `ArrayStride 80` is the defect; 32 was right.**
