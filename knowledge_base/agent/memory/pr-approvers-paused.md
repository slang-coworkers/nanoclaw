**Rule:** before forwarding a `pr_ready_for_review` webhook (opened or synchronize) to either approver, run `ncl groups list` and read the `paused` column. A paused group does not wake; the message sits unread in its session, so each extra synchronize forward only queues a dispatch naming a head that will be stale by the time it is read (slangpy#1199 had 4 synchronizes in a day). If paused: don't forward; add the PR, its approver session id and its live head to the queue file; tell the operator in one line, on the FIRST event only (later events for the same PR get nothing more than the check — the queue tells the follow-up to read the live head with `gh` at dispatch time). Run the check on the very first event of every PR, not only once a PR repeats. Signs the target is paused: the approver session shows only `in` rows, and `ncl cost-cap status --session` reports "no cost_cap row yet" (the container never started). Act on the index line itself; a truncated search (`head_limit` cut hiding this file) is not a negative.

**Bounce-turn recipe (learned 11-16 after ~15 wasted calls).** Woken by an approver failureNotice: (1) `ncl groups list` → still `paused=1`? (2) grep [[pr-approvers-paused-bounce-log.md]] for the PR number — every wave instance siblings dispositioned is there, and "dispositioned" means no re-send, no reply into the paused group, no dashboard row; (3) grep `data/approver-pause-queue.md` for the PR; (4) check the dashboard's last ~15 rows for the aggregate report. If all four are covered: disposition anything genuinely new, then **end the turn cleanly with NO reply** — the reply route points at the paused group, so a plain reply delivers there, fails, and re-queues another bounce. An unattributed fallback (`sender="Unknown"`) leaves no inbound row in any dispatching session and the `<message id>` numbers map to neither session seqs nor dashboard rows — per-PR disposition of an unattributable bounce is impossible; don't forensically hunt "which dead handoff is mine". Useful ncl facts measured 11-16: `ncl sessions list --agent-group-id <gid> --status active --limit 500` DOES list another group's sessions (they don't appear in the default 2000-row list); `ncl sessions get/messages <sid>` works cross-group by id; `--last-active <date>` as a filter returns `[]` (format mismatch — don't conclude absence from it); verify PR state with `curl --noproxy '*'` / webfetch of the public PR page when `gh` and the API are 401-degraded.
