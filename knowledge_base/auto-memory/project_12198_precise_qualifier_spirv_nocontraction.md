**shader-slang/slang#12198** (author mediawaffle, external/NONE) — per-variable `precise` qualifier has NO effect on `-target spirv` in DEFAULT fp mode: 0 `NoContraction` decorations + spirv-opt algebraically reassociates the qualified expr (`dx*dy+dy*dz+dz*dx` → `dy*(dx+dz)+dz*dx`). DXIL keeps source order → SPIR-V-only divergence, breaks bit-exact GPU/CPU parity (SAH BVH builder, ~0.1% node cost flips). Workaround = TU-wide `-fp-mode precise`.

**Triaged 07-23** (slang-triager, REPRODUCED @HEAD 56eb1aa08, `reproduced` label, Issue Type=Bug): bug/medium/target-emit/**P2**. Verified 5-bullet posted → issue comment **5054888278**.

**Root cause (source-verified):** `slang-emit-spirv.cpp:10303` `emitArithmetic` gates NoContraction on `isFloatingPointModePrecise(inst)` = GLOBAL -fp-mode only; never reads the inst's own `IRPreciseDecoration` (IS lowered at `slang-lower-to-ir.cpp:3181`, survives to emit). Two symptoms = one cause: `-O0` preserves order (reassociation is 100% spirv-opt); `-fp-mode precise` (16 NoContraction, order preserved) proves NoContraction is the lever.

**Recommended fix = Approach A:** backward-propagate precise-ness through FP def-use fan-in, then reuse existing `maybeEmitNoContraction` choke (scoped so fast-math survives elsewhere). Nuance: precise decoration sits only on directly-qualified insts; compiler-gen intermediates undecorated; NO propagation pass exists — naive per-inst gate (Approach B) is incomplete.
