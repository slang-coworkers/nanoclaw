**slangpy#1059** — `float3` loop arithmetic runs ~2.9x slower on the **CUDA backend** than identical `float4`/scalar code; Vulkan shows no penalty. Root cause **upstream in shader-slang/slang**. SlangPy transparent to vector types (no code lever) → Track C (slangpy-layer rewrite) ruled out.

**⚠️ ROOT CAUSE CORRECTED (slang-triager, GPU-free codegen evidence @ HEAD 8f0c3515d):** NOT float3 layout/alignment (that + Metal PR #10031 packed-vec3 precedent are a *different, unrelated* buffer-stride concern). Real mechanism = **swizzle-base duplication**: a multi-component `.rgb`/`.xyz` READ is emitted by the C-family emitter (`slang-emit-cpp.cpp:1642-1719`, inherited by CUDA via `slang-emit-cuda.h:44`) as `float3{base.x, base.y, base.z}`, **re-evaluating the base once per component**. When base is a folded texture/buffer load, the fetch emits 3×. Proof: hot-loop `tex2Dfetch` count f4_all=**1**, f3_loop=**3** (≈2.87×), f3_epi=**1**. SPIR-V=single `OpVectorShuffle`, HLSL=native `.xyz` → the backend asymmetry. Affects **CUDA AND CPU/C++**. Explains reporter's uncharacterized trigger boundary: base=cheap local → fast; base=expensive helper expr → slow. Original slangpy-triager float3-layout diagnosis SUPERSEDED. Fix path: A (emit-side: bind base to temp once for elementCount>1 when base folded/non-trivial) or B (IR-side use-aware materialization). Severity medium/P2. slang-triager memo: `/workspace/agent/memory/triage-slangpy-1059-cuda-swizzle.md`.
