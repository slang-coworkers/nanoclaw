**Fix dimensions to flag (NOT fully my design — for the fixer):** (1) gate the `SPV_EXT_shader_atomic_float_add` push on the actual `shaderBufferFloat32AtomicAdd` bit, not `shaderBufferFloat32Atomics`; (2) **SIBLING INSTANCE, likely same defect** — `:832-840` gates `SPV_EXT_shader_atomic_float16_add` + `float_min_max` on `shaderBufferFloat16Atomics` (base bit), same conflation shape; check both; (3) the SPIR-V `SPV_EXT_shader_atomic_float_add` capability covers buffer AND shared, float32 AND float64 — device reports separate bits for each (their vulkaninfo: ALL `*AtomicAdd`=false, all base `*Atomics`=true) — advertising one coarse capability off one bit is lossy; consider Slang capability-atom granularity; (4) **D3D12 arm (`[0,0,0,0]`) is SEPARATE and NOT covered by this vk-device.cpp finding** — needs its own analysis (swoods-nv scoped their finding to "at least the Vulkan side").
