**shader-slang/slang#12092** (RefuX, non-bot contributor) — reflection reports the fixed default existential element size (16 payload + 16 RTTI/witness = **32**) for an interface with an *inferred* `[anyValueSize]`, disagreeing with the emitted `StructuredBuffer<Interface>` element `ArrayStride` (**80** in repro: 16 + float4x4=64). A tool sizing CPU-side buffer packing from reflection packs at the wrong stride, corrupting every element past the first.

**Status (2026-07-14):** REPRODUCED on ToT `65a98e333` (code-proven + reporter-measured). Triager posted verdict to GitHub (issue comment 4967702700), applied `reproduced` label, set Type=Bug. Forwarded to **slang-triager → slang-fixer** over triager's peer wire (I did NOT double-dispatch). Classification: bug / medium / reflection-layout (existential types) / P2.

**Root cause (verified — phase-ordering split):** Reflection layout (front-end `_createTypeLayout`, slang-type-layout.cpp:5982) reads ONLY the AST `[anyValueSize]` attr → default 32. Emit stride comes from a LATER IR pass `inferAnyValueSizeWhereNecessary` (slang-ir-any-value-inference.cpp:419-511 @ slang-emit.cpp:1500) that grows the payload to the largest conformer and writes `IRAnyValueSizeDecoration`; reflection never consults that IR decoration. ⛔⭐⭐⭐**DIRECTION REVERSED 2026-08-07 by tangent-vector (Tim Foley, core architect) — issue comment 5221466013. READ THIS BEFORE THE csyonghe SECTION BELOW; it supersedes the fix direction, and our own public comment was WRONG in the load-bearing claim.**

**TWO any-value sizes exist, and they are DIFFERENT BY DESIGN:** (1) the **"external API contract" size** — computable purely from AST info, from the `interface` decl + its `[anyValueSize]` attr; for `IFoo` that is **16** (payload) ⇒ 32 total. (2) the **"de facto" size** — computable only from Slang IR at codegen time, from the conformances actually in scope; here **64** (because `Big` is boxed into `IFoo`) ⇒ 80 total. *"In principle, this size could be larger or smaller."*

⇒ ⛔**REFLECTION IS CORRECT AND THE BACK-END IS THE BUG — the opposite of what our chain published.** Verbatim: *"The reflection API should use the external API contract size when reporting size information (**and luckily, it already does**)"* · *"Whenever a value of existential type is explicitly stored in memory or a buffer/resource, it should use a layout that is based only on the external API contract size. The reflection API gets this right for the example in this issue, while the code generation back-end currently gets this **wrong** — it uses the de facto size in place of the external API contract size."* Applies to `StructuredBuffer<IFoo>`, `ConstantBuffer<IFoo>`, `IFoo*`, etc. **Temporaries** (locals, params, results) correctly use the **de facto** size — and can be sized per-value (he points at @saipraveenb25's recent work). ⇒ **The emitted `ArrayStride 80` is the defect; 32 was right.**

⇒ ⛔**THE POST-EMIT-METADATA PATH IS SUPERSEDED — do NOT build it.** csyonghe's *"not fixable in the reflection API"* remains TRUE but is now **beside the point**: nobody needs to change reflection or add a metadata surface. The fix is **back-end**: respect the external-API-contract size for existential values stored into buffers/resources/memory that can cross a binary interface boundary. The `IBindlessResourceMetadata` draft-PR plan is **withdrawn, unbuilt**.

⭐**He affirms it IS a real bug** — *"this is a genuine bug and in my opinion merits a fix at some point.
