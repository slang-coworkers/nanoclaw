# slangpy#1079 — Arrays of tensor params: Metal wrong results, D3D12 device removal

Follow-up tracking issue filed by nv-slang-bot while carrying #996 → **#1078**. #1078 added array-of-tensor + tensor-in-struct-vectorize tests, **skipped on Metal & D3D12** (ref this issue); pass on Vulkan/CUDA. **Two INDEPENDENT defects** (root-caused from source; no Metal/D3D12 HW at triager — fixer confirms on-device):

1. **D3D12 device removal — root cause PINNED (high conf).** `Tensor.zeros(usage=shader_resource)` → `tensor_zeros()` calls `tensor->clear()` **unconditionally at creation** (`src/slangpy_ext/func/tensor.cpp:442`), ignoring usage flag. D3D12 `clear_buffer` needs a UAV → `ClearUnorderedAccessViewUint` on shader_resource-only buffer fails → `RemoveDevice`, poisons whole worker. VK/CUDA clear via transfer ops → pass. Root is **creation**, not dispatch (contra issue narrative). slang-rhi ref `external/slang-rhi/src/d3d12/d3d12-command.cpp:437-445`.
   - **APPROVED fix (plan reviewed+re-verified by triager @HEAD, msgs 16/22):** Approach **A** = zero non-UAV buffers via `BufferDesc.data` init-upload (NO UAV added). Chokepoint = `Tensor::clear()` (zeros/zeros_like/with_grads all route through it; zeros_like forwards usage → difftensors_read grad path trips too).
   - **Approach C caveats (msg 22):** `SlangPyError` does NOT exist in the codebase (only in AGENTS.md) — use existing error types. Approach C is already structurally satisfied by the `TypeError` at `tensorcommon.py:140-143`; the ask-#2 regression test must exercise the **array**-of-read-only→`RWTensor[4]` mismatch (not just scalar) and assert device-survival — let the test decide whether a separate `resolve_dimensionality` guard is even needed.
   - **⚠️ Load-bearing constraint:** read-only tensor *arrays* legitimately need shader_resource-only; **adding a UAV renames the element type → breaks array resolution on ALL backends** (array.py compares element types by `full_name` string). So the fix must zero the buffer another way, NOT add UAV.
   - **Guard location CORRECTED** by the plan: belongs in `tensorcommon.resolve_dimensionality:353-370`, **not** `tensor.py:184` (triager's original triage pointer was wrong; correction confirmed).
2. **Metal wrong results — subsystem call PENDING (UNCONFIRMED).** Same kernel correct on VK+CUDA, wrong on Metal → hypothesis = upstream **Slang Metal codegen** (echoes CLOSED slang#7606). Tensor-in-struct subset (`[1,5,1,1]`) may be slangpy marshalling-offset; **open PR #1045** targets that path — check first.
