**shader-slang/slang#11983** — imported `DebugFunction` records reference an imported module's `DebugSource` but wrongly use the entry-point file's `DebugCompilationUnit` as parent scope. bug / low / target-emit SPIR-V debug-info / P3 (valid SPIR-V, runs fine; debugger/tooling correctness only).

**Root cause (triager blame-confirmed):** `slang-emit-spirv.cpp` resolves every DebugFunction's parent scope through ONE module-global slot (`findDebugScope`); a post-pass added by #10907 (fixed #10906) unconditionally pins that slot to the entry-point CU → mis-scopes imported funcs. Each DebugFunction already carries the correct source via `getFile()`; only the derived scope operand is wrong.

**Approach A rejected (reporter caught the hole, triager VERIFIED @5c30d437f):** A = key scope by `DebugSource→CU` map, resolve by `getFile()` in `emitDebugFunction`. But `emitDebugSource` runs per-file (slang-lower-to-ir.cpp:15407) while `emitDebugCompilationUnit` is gated `!isIncludedFile()` (:15418) → an `#include`'d file gets a DebugSource but NO CU, so `cuForSource[getFile()]` misses for include-defined functions. Nuance: `import` ≠ `#include` (`setIncludedFile` only on preprocessor path) so A would still fix the *reported* import symptom but leave the include case unscoped.
**Conceded Approach B** = explicit scope/CU operand on `IRDebugFunction` at IR-gen — sounder, matches repo's store-canonical-at-producer methodology.
