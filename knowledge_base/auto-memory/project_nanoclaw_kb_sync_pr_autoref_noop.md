⛔**#1148 (2026-08-09) IS THE FIRST INSTANCE WHERE `sum(per-file .additions) == reported additions` ACTUALLY FIRED — and it was RIGHT.** 14,746 vs reported 14,921 (Δ175), deletions 1,203 vs 1,205 (Δ2). Cause: **GitHub omitted BOTH the patch AND the per-file stats for 3 files, reporting them as `+0/−0` with `patch == null`** — and one of those carried `status: added`. ⭐⭐⭐**`status: added` with `+0/−0` is ARITHMETICALLY IMPOSSIBLE and is the cheapest tell that per-file stats are missing, not zero.** Fetching all 4 patchless files whole at the merge sha resolved it exactly: `13,933 patch-added + 173 + 1 + 1 + 813 = 14,921` ✅ and `673 + 530 + 1 + 1 = 1,205` ✅. The two `+0/−0` *modified* files were genuine 1-line edits (a `(shared: …)` id appended to a `[[link]]`), verified by diffing each against the base sha — **not** by trusting the stats. ⇒ **Keep asserting the sum; when it mismatches, the gap is a FETCH gap, not a data gap — go get the whole files.**

⛔**#1148 INSTRUMENT BUG — DO NOT SUBTRACT `^+++`/`^---` FROM GitHub's PER-FILE `.patch`.** That subtraction is correct for a *unified diff* but the `.patch` field **contains no file headers** (measured: `grep -c '^+++'` → 0, `grep -c '^--- '` → 0). Meanwhile **4 prose lines legitimately begin with `---`** (`----`, `---limit 500 → 500 …`), so the habitual `minus_lines - grep -c '^---'` **silently over-subtracted 4**, giving `patch_deleted=669` instead of 673 — a Δ that would have made the correct reconciliation *look* broken and sent me hunting a phantom. ✅**Guard: assert the header count is 0 before subtracting anything; if it is 0, use the raw `^+`/`^-` counts.**

A `github.pr_ready_for_review` webhook for these arrives with the generic task "route to the *-pr-approver". **Do not route it.** Reasons:
- It is already `state: closed` / `merged` by the time the webhook lands (bot self-merge).
- The nanoclaw repo has **no `*-pr-approver` coworker** in Main's destinations — only `slang-pr-approver` / `slangpy-pr-approver` exist, scoped to their repos (see [[project_nanoclaw_pr874_webhook_route_approver]]).
- It is a data-only snapshot, not code.

Action: **no-op** (already-merged automated data snapshot, no applicable reviewer). Verify state first — if a future kb-sync PR ever lands *unmerged*, re-evaluate. Related: [[feedback_webhook_dispatch_by_event]].
