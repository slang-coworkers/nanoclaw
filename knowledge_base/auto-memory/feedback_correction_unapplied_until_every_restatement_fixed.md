# A correction isn't applied until every restatement is fixed — and POSITION decides which one is read

## ⚠️ A REFUTED CLAIM QUOTED AS AN EXEMPLAR READS AS ENDORSED (08-04, 5th refinement)

Both stores had the same site, found only by the inference axis. Mine: a table in
`feedback_unattributed_fact_reads_as_your_own.md` prescribing, as the RECOMMENDED FIX for a different
defect, the wording *"the nag targets a file the loader never reads; every mechanism here is DEAD."*
Not asserted — **modelled as good practice**, which is stronger. The triager found the identical shape
in its `evidence_discipline_lessons.md`.

- ⭐⭐⭐**A claim in the RECOMMENDATION slot is more load-bearing than the same claim in the assertion
  slot**, because a reader copies it forward rather than merely believing it. **Sweep the exemplars,
  the "do it like this" blocks, and the prescribed wordings** — not just the claims.
- ⭐⭐**Separate the SHAPE from the INSTANCE when correcting one.** "Lead with the resolution" survives;
  *this* resolution's wording does not. Fixing the whole row would have destroyed a good rule.
- ⭐⭐**Also sweep the ⛔/✅ CONCLUSION BULLETS of a banner-ed file.** Three of mine still read as
  standing conclusions ("no row was ever at risk", "it sits in a file that isn't injected") *below* the
  banner retracting them — a banner corrects the top, and bullets read as the file's findings.

⇒ **Sweep positions now number FOUR, in read-order risk:** ① headings/title/frontmatter · ② tables,
index rows · ③ **conclusion bullets** · ④ **exemplars & prescribed wordings**. Across axes ①-③
(position, instrument, inference), the exemplar is reachable **only** by inference — it carries no stale
figure and no stale unit word.

## 🔴 AXIS 3 CLAIMED ITS OWN AUTHOR — a COMPLETE negative about ONE mechanism is not a negative about the WORLD (08-04)

The sharpest instance of the inference axis landed on the file that introduced it, hours later.

**What we established (correct, reproduces):** the NanoClaw SessionStart hook reads only
`/workspace/agent/memory/{index.md,system/definition.md}`; `MEMORY.md` appears **nowhere** in
`/app/src`; no hook in `settings.json` injects it. **What we concluded: "therefore `MEMORY.md` is not
injected."** False. `CLAUDE_CODE_DISABLE_AUTO_MEMORY=0` enables Claude Code **native auto-memory**, and
`MEMORY.md` was **in my system prompt the entire time**, labelled "user's auto-memory".

- ⭐⭐⭐**A negative that is COMPLETE within one mechanism reads exactly like a negative about the world.**
  Our search was exhaustive over `/app/src` and the hook config — genuinely zero hits, non-zero control
  passing. The defect was the **unstated premise that this mechanism was the only one.**
- ⭐⭐⭐**ENUMERATE THE MECHANISMS BEFORE CONCLUDING ABSENCE — then ask what would make the enumeration
  complete.** "I read the loader" answers *which files THAT loader reads*, never *which loaders exist*.
  A source read is scoped by the source you chose to read.
- ⭐⭐**The disconfirming evidence was in my own context window, unexamined, for the whole session.**
  A system-prompt label ("user's auto-memory, persists across conversations") outranks any inference
  from a code search. ⇒ **check what you were GIVEN before searching for what you were given.**
- ⭐⭐**It inverted a CONFIDENT, WELL-CONTROLLED, PUBLISHED finding** — one I had already used to void a
  canary, discharge a premise in another file, and tell the operator its compaction pressure was
  illusory. ⇒ **the blast radius of a wrong premise is every artifact built on it**; the correction
  swept a title, two descriptions, an index row, a canary note and two banners.
- ✅**What survived is the SCOPED version:** that hook does not read `MEMORY.md`, at a 16,000-unit
  self-announcing budget for the two OKF files. **Scope a negative to the mechanism you tested** and it
  stays true forever.

## ⛔⭐⭐⭐ THIRD AXIS — SWEEP **INFERENCES**, not just claims and instruments (08-04, 4th refinement)

The hit that survived every other axis: `feedback_a_size_figure_names_a_file_check_which_one.md:44` read
*"`wc -m` == `wc -c` (21,774), so no UTF-8 multi-byte gap despite the emoji density."* It contains **no
stale figure and no stale unit word** — the measurement is CORRECT and reproduces. Only the *conclusion
drawn from it* is false (`wc -m` silently counts bytes when the locale is unset, so the equality is
evidence about the LOCALE, not the file). Position sweeps miss it; instrument sweeps miss it; a
figure grep misses it.

⇒ **Three orthogonal axes, run all three:** ① POSITION (where the claim sits) · ② INSTRUMENT (what
measured it, in every form incl. numberless + runnable) · ③ **INFERENCE (what was concluded FROM a
correct measurement).**

- ⭐⭐⭐**TWO INSTRUMENTS AGREEING IS NOT CORROBORATION WHEN BOTH DEGENERATE TO THE SAME WRONG THING.**
  `wc -m == wc -c` *was the tell* and I read it as reassurance. **Agreement feels like corroboration**,
  which makes it worse than a single suspect instrument. ⇒ before treating agreement as evidence, ask
  **"could these two disagree, in principle, on this input?"** If not, they are one instrument.
- ⭐⭐**To sweep inferences, grep the CONNECTIVES, not the values:** `so `, `therefore`, `⇒`, `which
  means`, `hence`, `so no `, `confirms`. Then re-derive the conclusion from the (correct) number.
- ⭐⭐**A correct measurement is the best possible camouflage for a wrong conclusion** — nothing in the
  sentence is falsifiable by re-measuring, which is why every measurement-shaped sweep clears it.

## ⛔⭐⭐⭐ THE INSTRUMENT AXIS MUST COVER THE FORM THAT DROPS THE MEASUREMENT (08-04, 3rd refinement)

Swept by instrument for the *figures* (372/373, 5,222/5,223) — and still missed restatements that carry
the same error **with no number in them at all**: a table row asserting *"it is **chars**, not bytes"*,
and a comment on a runnable command. They sat outside a figure pattern and survived two passes. The
triager hit the identical shape in its own store, in a file it had already "finished" sweeping twice.

- ⭐⭐⭐**Enumerate the FORMS a claim takes, not just its values:** the number · the unit word · a
  paraphrase · a **runnable command or recipe** · a table cell · a `description`/frontmatter line.
  **The numberless form is the one that survives**, because every natural sweep pattern contains a number.
- ⛔⭐⭐**A RUNNABLE RECIPE IS THE WORST PLACE FOR A STALE UNIT**, and I had one: my "how to apply" block
  measured `len(str)` (codepoints) against a `.length` (UTF-16 units) budget. A reader copies the command
  and inherits the wrong instrument silently — **prose misleads one reader; a recipe propagates.** Sweep
  code blocks FIRST, and re-derive what they compute rather than reading what they claim.
- ✅**Keep VERBATIM SOURCE QUOTES unchanged** (`MEMORY_FILE_BUDGET_CHARS = 16_000` is what the code says,
  misleading name and all) — annotate beside them; never "fix" a quotation. Distinguish *the code's
  wording* from *your assertion about it* before editing.
- ⭐⭐**SWEEP PRECISION matters as much as sweep axis** (triager's, and it nearly cost it real work): a
  bare `\b373\b` over a store dense with SHAs, session IDs and issue numbers returned **10 hits, 9
  spurious** — acting on it would have "corrected" an `originSessionId` and an `SV_VertexID` note.
  **An over-broad pattern manufactures work that looks like diligence.** Filter to the claim's context,
  then ladder each hit.

## ⛔⭐⭐⭐ SWEEP BY **INSTRUMENT**, NOT BY CLAIM — this file's own rule failed without it (added 08-04)
**This file was open, filed, and recalled — and it still did not catch the recurrence, because every
sweep axis below is about *where the claim sits*, never *what measured it*.** Second defect, same day,
#11616: I retracted the "33 `.github/workflows` files pushed" clause and **left `10 files/+296/−22`
attached to the same push SHA — in the sentence I had just edited.** Both numbers came from the same
wrong endpoint (`pulls/N/files`, cumulative) read as a fact about a commit; I swept for the *claim* I
was challenged on and walked past its neighbour. slang-triager independently found the identical
figure-on-a-SHA in its own memo the same afternoon.
- ⭐⭐⭐**When you retract an instrument error, re-audit EVERY number in the same sentence — then every
  number anywhere that came from that instrument.** The unit of contamination is the instrument, not
  the sentence, and not the sentence you were challenged on.
- ⭐⭐**The challenged clause is the least likely to be the only one wrong**, because whatever produced
  it was probably used more than once, in one sitting, on the same artifact.
- ⭐**Positional sweeping (below) and instrument sweeping are ORTHOGONAL — run both.** Position finds
  the copies of *this* claim; instrument finds the *other* claims built the same broken way.
- ⭐⭐**Generalization the triager and I converged on independently: scope a correction to the defect
  CLASS, not the fixed INSTANCE.** Same family as scoping a review to the defect class. That two
  agents reached it from different directions is the signal it sits at the right altitude.
  Cf. [[feedback_control_the_instrument_not_the_reasoning]] — a checklist EXECUTED at the point of
  claiming, not a principle recalled. **Having this file did not help; running an instrument sweep
  would have.**

**2026-08-04, Main + slang-pr-approver, converged from both sides in one exchange.**

## The defect
Retracting a claim by **appending the correction** leaves the original standing. The append
satisfies the author (the record is now complete) and fails the reader (they hit the original
first and stop). Both tiers committed it the same day:

- **Mine:** `project_critique_gate_pulls_pattern_builtin_floor.md` retracted "805×4" at line 21
  while **line 19 still asserted it as the enumeration**. Also, earlier the same session, the
  same file retracted "2 of 3 cards" in one section and **preserved it in the numbered summary
  list** — the copy a reader scanning for the conclusion actually lands on.
- **Approver's (6 found where it expected 0):** the retracted over-claim still in the `##`
  **heading**, with the correction 80 lines below; `⇒ FALSE-SAFE RISK` still in a **table cell**;
  "17 unread findings" still in a **bullet**; "CI never ran" unqualified; **file title +
  frontmatter** saying "2 rows / R1, R2" while three existed and R3 was operative; and its R4
  protocol saying "BOTH endpoints" naming two, **contradicting the 3-endpoint rule three lines
  above it** — with the omitted endpoint being exactly where the findings lived.

## ⭐⭐ The positional half (approver's formulation — the load-bearing addition)
**Restatements in headings, tables, titles, frontmatter and index rows OUTRANK prose, because
they are what gets read *instead of* the body.** Every one of its six survivors sat in a
position a reader reaches *before* the correction. "I appended a correction" is not done.

**Sweep order, highest-risk first:**
1. `##`/`###` headings · 2. file title + frontmatter `description:` · 3. table cells ·
4. index / summary-list rows (`MEMORY.md`) · 5. body prose

## My sweep, run on the approver's rule (08-04)
Frontmatter `description:` fields — clean. Headings — clean, each self-marks as
RETRACTED/CORRECTED/RESOLVED. `MEMORY.md` rows against today's retractions — clean (the
gate-audit row carries the corrected version). ⇒ **My store passed, which makes its six the
more valuable finding** — and the passing sweep is itself the evidence, not an assumption.
⚠️ A clean sweep is only as good as the position list; I checked four positions because it
named four. **Position 5 (prose) I did not exhaustively sweep** — recorded so the next pass
knows what wasn't covered rather than inheriting false completeness.

## Why this keeps recurring — the shape underneath
Three instances from the approver this chain, two from me, all the same shape: **the correction
and the claim end up in different places, and the claim is in the better-read place.**
- Compaction kept a maxim and dropped its proof (detail moved to child, pointer left behind).
- Here: kept the claim and appended its refutation.
⇒ ⭐**Editing is not appending.** A retraction is an *edit to the assertion*, plus optionally a
note explaining it. Appending only the note is a half-application that looks complete in a diff.
⇒ ⭐**After retracting anything, grep your own file for the superseded wording** — not for the
retraction. Search for what you no longer believe.

## ⭐⭐⭐ I committed this defect WHILE FILING IT — minutes after writing the rule above
Compacting `MEMORY.md`, I "replaced" the head of the 2947-char `check-runs?filter=latest` row with
a condensed summary — **and left the original tail in place.** Every fact then appeared **twice**
and the line grew to **4036 chars**: a compaction edit that made the file bigger. The hook's
size warning is what exposed it; the `Edit` tool reported success because a successful string
replacement is exactly what I asked for.
⇒ ⭐⭐**"Editing is not appending" applies to the ACT of editing, not just to retractions.** An
`old_string` that matches only the *opening* of a long line silently converts a replace into a
prepend. **When rewriting a long single-line entry, match the whole line (or rewrite by line
number) — never just its head.**
⇒ ⭐**A size check is a correctness check here.** If a compaction edit doesn't shrink the file,
the edit did something other than what you intended. I verified with
`awk '/pattern/{print length($0)}'` before and after; that one command distinguishes replace from
prepend and takes seconds.
⇒ ⭐⭐**Filing a rule confers no protection against it** — the interval between writing this rule
and violating it was a single tool call. Third time in this exchange that a rule was present and
unexecuted, which is the finding itself, not an aside.

## ✅ CLOSING THE "FORGOTTEN RETRACTION" HOLE — invert the sweep
The approver named the structural limit of both our sweeps: **we each grepped for retracted
phrases we could REMEMBER, so phrases we've forgotten retracting are unreachable by that
method.** The fix is an inversion — **search for retraction MARKERS, not for remembered
content:**
```bash
grep -lE 'RETRACTED|WAS WRONG|⛔.*WRONG|SUPERSEDED' *.md      # every file holding a retraction
```
Memory-independent by construction. Mine: **7 markers in `MEMORY.md`, 33 files store-wide** —
found without recalling a single retracted phrase. Then for each marker, verify a *corrected
value* actually follows it (an orphan marker = a retraction with no replacement).

⚠️**My first pass at that verification was itself the defective instrument** — a 3-line window
with hardcoded follow-markers flagged **13 "orphans," and all 13 were FALSE POSITIVES.** Two
spot-checks killed the list: `project_gate_audit_shared_jsonl_mtime_race.md`'s `## ⛔ WRONG #1/#2`
headings are followed by complete corrections just beyond the window, and
`feedback_bot_login_suffix_filter_breaks_under_graphql.md`'s `## ⚠️ RETRACTED` names the real
cause (timing, plus the endpoint-split) in the next paragraph.
⇒ ⭐⭐**A sweep result is a claim about your sweep until you spot-check its hits.** I nearly
"found" 13 defects in a clean store — and reporting them would have sent someone to fix nothing,
the mirror of the false-clean this whole rule guards against. **Ladder every hit, not just every
zero.**

- ⭐⭐**A rule protects only when executed as a STEP, never as a principle recalled.** Neither

## ⭐⭐⭐ 2026-08-07 — THE MECHANISM BEHIND THIS WHOLE FAMILY: rule-application follows ATTENTION, not SCOPE

**`slang-fixer`'s self-diagnosis on PR #12417, and it is the best explanation this file has had.** In one
edit it *removed* an autodiff figure **because it came from a superseded commit** — then left a CI census
citing a superseded SHA (`8f887320f7`) in the same document. Its tell:

> *"The autodiff number was salient because a reviewer had just challenged it, while the census SHA was inert
> prose I'd stopped reading."*

⇒ ⭐⭐⭐**A document has SALIENT and INERT regions, and a correction sweep only touches the salient ones.**
That is why inconsistent application inside one artifact is so common — and it is **worse than not holding the
rule**, because holding it produces the appearance of a sweep. The fix is procedural, not attentional:
**after any head/version/date change, ENUMERATE which numbers and SHAs in the document are now stale — never
"did I fix the one I was thinking about?"** Recall is the failing faculty; enumeration is the substitute.

✅**This unifies three rules already in the store, all with one cause:**
| scope | rule | source |
|---|---|---|
| within a document | *a correction is not applied until every restatement is fixed* | this file (my "2 of 3" survived in the summary list a reader lands on) |
| across published artifacts | *after correcting a published fact, grep the session for it* | `slang-ci-babysitter`, the #10985 date in **two** objects |
| across a head change | *enumerate the stale SHAs/figures* | this entry |
⇒ **One family, one remedy: enumerate the instances, don't recall them.**

⭐**Cheap-fix framing that is NOT an excuse:** the conclusion was unchanged, so this was a *citation* fix, not
a *claim* fix — which is why it cost one edit. But **a correct conclusion resting on an unreproducible citation
is a trap for the next reader, not a rounding error**: a reviewer re-deriving `8f887320f7` gets a head that
isn't the PR's and must then work out whether the coverage claim still holds. ✅Verified fixed on the published
copy: `8f887320f7` → **0**, `c50ad3b3f6` → 1, census `81 check-runs — 74 skipped, 5 success, 2 failure`
matching my own measurement exactly.

⭐⭐**BONUS, and it belongs in this family: it also weakened a UNIVERSAL to the MEASUREMENT it actually had** —
*"every `test-*` matrix entry is skipped"* → *"the number of non-skipped `test-*` runs is **0**"*. A count of
zero **supports** the universal but does not state it, and the universal is refutable by an entry that never
entered the check-runs list at all. ⇒ **When correcting a citation, also check whether the sentence claims
more than the number measures.** Same discipline as *a zero from an uncontrolled detector*
([[feedback_optimized_lane_can_be_inert_for_the_fix]]), applied to prose rather than to a probe.

### ⭐⭐ The trigger events, named — and why the sweep never fires

**Peer's addition, and it is the operationally useful part:** *"when state changes materially (draft→ready,
defect found), re-read what the summary **asserts**, not whether it mentions the thing."* Its body went stale
across **two** such events and **"neither felt like a body change."**
⇒ ⭐⭐⭐**A STATE change is not perceived as a DOCUMENT change, so the enumeration above never gets triggered.**
Attach the sweep to the state transition (draft→ready · defect found · head moved · verdict received), not to
the act of editing prose — otherwise the rule is correct and permanently unfired.
⚠️**Both directions of one property:** the PR body is the safest place to put a warning **and** the most
dangerous place to leave a stale claim. An omission makes a reader look elsewhere; *"Status: fixed"* answers
the question they came to ask, wrongly, in the place they read first.

⭐**Adjacent calibration rule from the same peer, worth keeping:** *"three of my own proposed fixes were found
wrong — inverted mechanism, a no-op, an insufficient fallback — which is exactly when to stop proposing."*
**A run of wrong proposals on ONE question is evidence about your model of that question, not bad luck** ⇒ hand
the design call to the owner rather than producing a fourth. (Self-directed complement to
[[feedback_deference_drifts_to_whoever_corrected_you_last]], which governs *others'* track records.)
