**#12096** (shader-slang/slang) — Metal 4 capability inferred from OS version fails MSL compile on `macos-26` CI images (toolchain lacks metal4.0). Author **jvepsalainen-nv** (NVIDIA, CONTRIBUTOR, **SELF-ASSIGNED**). Category bug/regression/CI, P2, medium.

**What:** On `macos-26` runners, 4 Metal gfx unit tests fail at `createComputePipeline` — Slang emits `[[required_threads_per_threadgroup(...)]]` (needs metal4.0) but the image's `metal` CLI (32023.883, Xcode-16 era stub) rejects it. Failing: neuralSlangNetworkConverterMetal, pointerInBufferDoublePtrRoundtripMetal, pointerInBufferRoundtripMetal, pointerInParamBlockRoundtripMetal (all `.internal`). Passes on `macos-15`.

**Root cause = slang-rhi, NOT slang core.** `external/slang-rhi/src/metal/metal-device.cpp:266` adds `metallib_4_0` from `osVersion.majorVersion >= 26` — OS version, not the offline MSL compiler/language version. Introduced by **slang-rhi#795** (Simon Kallweit, MERGED 07-06, merge commit `29dc332e55` == slang's current submodule pin; bumped into slang via ef06ca406 07-07 ~1h before first failing nightly). slang-emit-metal.cpp:213-229 emitter is REACTIVE (emits iff getTargetCaps implies metallib_4_0) — correct given inputs; **no core change warranted**.

**Recommended fix: Approach A** — probe actual Metal language/compiler version at device init (MTLCompileOptions.languageVersion / 4.0 construct), replace OS inference at metal-device.cpp:266. Lands in slang-rhi → submodule-bump. Reject C (GPU-family ≠ toolchain) and D (env-var stopgap).
