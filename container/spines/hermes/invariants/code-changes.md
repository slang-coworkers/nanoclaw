### Code-change rules (Hermes)

Apply when writing or reviewing Hermes code (builder, reviewer; readers can ignore). A reviewer must-changes any violation below.

- **Surface:** `plugins/**`, `website/docs/**`, `tests/**` only, unless the ADR carries a `CORE-CHANGE` section citing the blocking release `file:line` (see plugin-first). No unrelated refactors riding along.
- **One logical change per PR;** Conventional Commits `<type>(<scope>): <description>` with `fix | feat | docs | test | refactor | chore` (`CONTRIBUTING.md:944-969`); branch `plugin/<name>` or `fix/ | feat/ | docs/ | test/ | refactor/` (`CONTRIBUTING.md:919-927`). Draft PR to the fork only — never upstream.
- **Work from a current checkout:** `git fetch` and read the file at its present state before editing or asserting anything about it; claims drafted against a remembered version are the most common avoidable error.
- **Tests are contract:** every plugin ships tests under `tests/plugins/` or `tests/hermes_cli/` that load it through real discovery from an isolated `HERMES_HOME` with `HERMES_BUNDLED_PLUGINS` pointed at an empty dir. Behavior contracts only — no change-detector tests, no source-reading tests, no bare `skipif` for OS (use `@pytest.mark.linux_only` etc.), no `assert not _wait_until(...)` negative-timing races; wall-clock bounds ≥ 2 s. JS/TS assertions live in vitest. Never delete or silence a failing test without evidence it was wrong.
- **Hermetic:** tests and plugin code never write `~/.hermes`; paths via `get_hermes_home()` / `display_hermes_home()`; plugin state via `plugins.plugin_storage.plugin_data_dir` / `plugin_db`. `HERMES_DISABLE_LAZY_INSTALLS=1` is set by conftest — a test that needs a lazy install is wrong.
- **Config:** no new `HERMES_*` env vars for non-secret config — settings go in `config.yaml` (`ctx.get_config`, `plugins.entries.<id>.settings`, or `config_schema` in a v2 manifest); `.env` is for secrets only.
- **Deps:** exact pins in core, `>=floor,<next_major` for extras/new deps, never unbounded; `python_dependencies` in a manifest is declare-only; run `uv lock` after touching `pyproject.toml` and commit `uv.lock`.
- **Lint:** `ruff check .` is a blocking CI job — `PLW1514` explicit `encoding=` (`plugins/**` exempt) and `ASYNC210/220/221/251` no blocking HTTP / subprocess / sleep inside `async def` (applies to `plugins/**` in full; platform adapters run on the gateway loop) (`pyproject.toml:650-660`). Run `scripts/check-windows-footguns.py` before the PR: `psutil.pid_exists` not `os.kill(pid, 0)`, `shutil.which` before shelling out, `pathlib`, guarded `os.setsid` / `fork` / POSIX signals (`CONTRIBUTING.md:676-846`).
- **Contracts in code:** hook callbacks accept `**kwargs`; tool handlers `def h(args: dict, **kwargs) -> str` return a JSON string and never raise; `provides_hooks` / `provides_tools` match what `register()` actually registers (doctor drift warning = fix it); catch specific exceptions, `logger.warning|error(..., exc_info=True)`; `shlex.quote()` user input in shell strings; `os.path.realpath()` before path checks; never log secrets (`CONTRIBUTING.md:849-873`).
- **Prompt caching is sacred:** nothing in a plugin mutates past context, swaps toolsets, or rebuilds the system prompt mid-conversation; slash commands that change prompt state default to deferred invalidation (`AGENTS.md:19-23, 1345-1357`).
- **Verified before shipped:** `hermes plugins doctor <dir> --ci` exit 0, the acceptance test green, the relevant `scripts/run_tests.sh` chunks green (a `FLAKY` line is a defect, not a pass), and a manual `hermes` smoke run against `HERMES_HOME=/workspace/agent/.hermes-testbed` recorded in the PR body (`CONTRIBUTING.md:929-942`).
