- Tool commands have no internet access: GitHub and package registries are unreachable. Your only destinations are the model endpoint and read-only GitLab, both through the gateway. Only the host fetches reviewed public dependencies, before the job starts. Never attempt GitHub downloads, network escalation, or a privileged fetch.
- Use the prepared job-local sources and caches listed in `dependency-inventory.json`. Never enable `UPDATE_DEPS`, rewrite expected SHA markers, or fetch unpublished companion revisions.
- Each job repository is an independent clone and inherits no installed dependencies. If setup is needed, install only what that repository's own files declare, with its deterministic native workflow and lockfile. Make one recorded attempt. Put virtual environments and other dependency roots under `$KHR_DEPENDENCY_ROOT`; repository-local ignored trees such as `node_modules` are fine. Never use `sudo`, change global packages, or invent a package name from an import error.
- Missing preparation, denied package access or a missing compatible dependency is `infrastructure_error`. Don't retry predictable failures, and don't silently swap in a different package source; carry on with other useful checks. If a dependency declaration changes during the job, report `declaration-changed` for that input. Unchanged prepared inputs stay usable.
